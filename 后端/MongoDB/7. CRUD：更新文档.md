## CRUD：更新文档

### 更新方法与样例数据

#### 样例集合 users

**样例集合 users**：是后续全部更新示例共同操作的数据底座，三条文档包含字符串、数字、数组三类字段，便于演示各类更新操作符的效果。

```js
db.users.insertMany([
  { _id: 1, name: "赵雷", age: 28, city: "北京", tags: ["vip", "active"], score: 82 },
  { _id: 2, name: "钱芳", age: 35, city: "上海", tags: ["active"], score: 65 },
  { _id: 3, name: "孙杰", age: 22, city: "广州", tags: [], score: 90 }
])
```

```text
{ acknowledged: true, insertedCount: 3, insertedIds: { '0': 1, '1': 2, '2': 3 } }
```

> 后续所有示例都从这份初始数据出发、按文中出现顺序依次执行，每条语句的 text 输出与命令一一对应。整套示例重新执行前，先删掉集合并重建。



#### updateOne、updateMany 与 replaceOne

**三种更新方法**：是按「匹配范围」与「写入方式」划分的三个顶层更新入口，前两者按操作符改字段，后者用新文档整体替换。

- **updateOne(filter, update)**：只更新匹配到的第一篇文档。
- **updateMany(filter, update)**：更新全部匹配文档。
- **replaceOne(filter, doc)**：用新文档整体替换匹配到的第一篇文档，_id 保持不变。

```js
db.users.updateOne({ _id: 2 }, { $set: { city: "杭州" } })
db.users.updateMany({ age: { $gte: 28 } }, { $set: { level: "A" } })
db.users.replaceOne({ _id: 3 }, { name: "孙杰", age: 23, city: "广州" })
```

```text
{ acknowledged: true, insertedId: null, matchedCount: 1, modifiedCount: 1 }
{ acknowledged: true, insertedId: null, matchedCount: 2, modifiedCount: 2 }
{ acknowledged: true, insertedId: null, matchedCount: 1, modifiedCount: 1 }
```

- **matchedCount**：查询条件命中的文档数。
- **modifiedCount**：实际被改写的文档数，值与写入内容完全相同的不计入。
- **三者的写入语法**：updateOne 与 updateMany 的第二个参数完全一致，差别只在匹配范围；replaceOne 的第二个参数是不带操作符的完整新文档。

> 选型口诀：改字段用 updateOne 或 updateMany，整体换内容才用 replaceOne。updateOne 只改第一条匹配文档，写条件前先用 find 确认匹配顺序，避免改错对象。



### 字段级更新操作符

#### $set 与 $unset

**$set 与 $unset**：是一对增改与删除字段的基础操作符，$set 改值或建字段，$unset 按字段名删除字段。

```js
db.users.updateOne({ _id: 1 }, { $set: { city: "深圳", level: "B" } })
db.users.updateOne({ _id: 1 }, { $unset: { level: "" } })
```

```text
{ acknowledged: true, insertedId: null, matchedCount: 1, modifiedCount: 1 }
{ acknowledged: true, insertedId: null, matchedCount: 1, modifiedCount: 1 }
```

- **$set**：字段存在则改值，不存在则新增，一条语句可以同时改多个字段。
- **$unset**：按字段名删除，值写空字符串只是固定写法，写任何值效果相同，删除依据的是键名。
- **类型自由**：$set 可以把字段从数字改成字符串、数组等任意类型，MongoDB 不做类型约束。

> 一条 update 文档里多个字段写在同一个 $set 中即可，不必为每个字段单写一个 $set。$unset 删的是嵌套文档中的指定路径时，用点路径定位，如 config.debug。



#### 数值操作符 $inc、$mul、$min、$max

**数值操作符**：是围绕数值字段做加减乘与条件比较的四个操作符，全部在服务端原子执行。

```js
db.users.updateOne({ _id: 2 }, { $inc: { score: 5 } })
db.users.updateOne({ _id: 2 }, { $mul: { score: 2 } })
db.users.updateOne({ _id: 2 }, { $min: { score: 100 } })
db.users.updateOne({ _id: 2 }, { $max: { score: 200 } })
```

```text
{ acknowledged: true, insertedId: null, matchedCount: 1, modifiedCount: 1 }
{ acknowledged: true, insertedId: null, matchedCount: 1, modifiedCount: 1 }
{ acknowledged: true, insertedId: null, matchedCount: 1, modifiedCount: 0 }
{ acknowledged: true, insertedId: null, matchedCount: 1, modifiedCount: 1 }
```

- **$inc**：对字段原子加减，负数即减法，score 从 65 加 5 变 70。
- **$mul**：对字段原子相乘，score 从 70 乘 2 变 140。
- **$min**：新值比现值更小才更新，140 比 100 大故 modifiedCount 为 0。
- **$max**：新值比现值更大才更新，140 比 200 小故更新为 200。

> [!CAUTION]
> **注意内容**：$min 与 $max 是「取更小、取更大」的条件更新，不是截断或限幅；$inc 作用于不存在的字段时先按 0 计再加减，作用在非数值字段上会直接报错。



#### $rename

**$rename**：是把字段改名的操作符，值为「旧字段名到新字段名」的映射，一条语句可以同时改多个字段。

```js
db.users.updateMany({}, { $rename: { tags: "labels" } })
```

```text
{ acknowledged: true, insertedId: null, matchedCount: 3, modifiedCount: 3 }
```

- **映射方向**：键为旧名、值为新名，方向写反会把不存在的字段当来源而静默跳过。
- **嵌套字段**：新旧名都支持点路径，可把字段挪进或挪出嵌套文档。
- **字段不存在**：来源字段不存在的文档不报错，modifiedCount 只统计实际改动的文档。

> [!TIP]
> **建议内容**：批量改字段名属于结构迁移，执行前先用 updateMany 的 filter 匹配一遍并 countDocument 确认范围，生产集合上先在副本演练再上量。



### 数组更新操作符

#### $push 与 $each、$slice、$sort

**$push**：是向数组尾部追加元素的操作符，配合 $each、$slice、$sort 三个修饰符可实现批量追加后的裁剪与排序。

```js
db.users.updateOne({ _id: 3 }, { $push: { tags: "new" } })
db.users.updateOne(
  { _id: 3 },
  { $push: { tags: { $each: ["beta", "alpha", "vip"], $sort: 1, $slice: 3 } } }
)
```

```text
{ acknowledged: true, insertedId: null, matchedCount: 1, modifiedCount: 1 }
{ acknowledged: true, insertedId: null, matchedCount: 1, modifiedCount: 1 }
```

- **$push**：单个追加时值为字段名到元素，数组字段不存在时先创建再追加。
- **$each**：批量追加的元素列表，追加后 tags 为 ["new", "beta", "alpha", "vip"]。
- **$sort**：追加后按值排序，1 升序 -1 降序，得到 ["alpha", "beta", "new", "vip"]。
- **$slice**：排序后裁剪，正数保留前 n 个、负数保留后 n 个，3 表示只留前三个。

```js
db.users.find({ _id: 3 }, { tags: 1 })
```

```text
[ { _id: 3, tags: [ 'alpha', 'beta', 'new' ] } ]
```

> [!CAUTION]
> **注意内容**：$slice 与 $sort 必须伴随 $each 使用，单独出现在 $push 里会报错；三者按「追加、排序、裁剪」的固定顺序生效，$slice 作用在 $sort 之后的数组上。



#### $pull、$pullAll 与 $pop

**$pull、$pullAll、$pop**：是三个删除数组元素的操作符，差别在删除条件——$pull 按查询条件删，$pullAll 按列出的具体值删，$pop 只按位置删头尾。

```js
db.users.updateOne({ _id: 1 }, { $pull: { tags: "vip" } })
db.users.updateOne({ _id: 1 }, { $pullAll: { tags: ["active"] } })
db.users.updateOne({ _id: 1 }, { $pop: { tags: 1 } })
```

```text
{ acknowledged: true, insertedId: null, matchedCount: 1, modifiedCount: 1 }
{ acknowledged: true, insertedId: null, matchedCount: 1, modifiedCount: 1 }
{ acknowledged: true, insertedId: null, matchedCount: 1, modifiedCount: 0 }
```

- **$pull**：删除所有满足条件的元素，条件可以是等值也可以是 $gte 这类查询操作符，tags 从 ["vip", "active"] 删成 ["active"]。
- **$pullAll**：只删除与列出值完全相等的元素，不支持查询操作符，tags 变成空数组。
- **$pop**：值为 1 删尾部、-1 删头部，空数组上执行不报错也不修改，故第三次 modifiedCount 为 0。

> 删一类元素用 $pull，删指定的几个值用 $pullAll，只关心头尾用 $pop。三个操作符都不改变其余元素的顺序。



#### $addToSet

**$addToSet**：是去重追加操作符，元素已存在于数组中则不追加，配合 $each 可批量去重。

```js
db.users.updateOne({ _id: 2 }, { $addToSet: { tags: "active" } })
db.users.updateOne({ _id: 2 }, { $addToSet: { tags: { $each: ["new", "active"] } } })
```

```text
{ acknowledged: true, insertedId: null, matchedCount: 1, modifiedCount: 0 }
{ acknowledged: true, insertedId: null, matchedCount: 1, modifiedCount: 1 }
```

- **整值比较**：以整个元素为单位比对是否相等，active 已存在故第一条 modifiedCount 为 0。
- **$each 批量**：列表中已存在的跳过、不存在的追加，tags 追加 new 后为 ["active", "new"]。
- **不排序不裁剪**：与 $push 的修饰符不同，$addToSet 不提供 $sort 与 $slice，追加位置也不确定。

> $addToSet 保证「不重复」，不保证顺序；需要有序去重列表时，用 $push 配 $each、$sort、$slice 组合自行维护。



### 位置操作符与 upsert

#### 位置操作符 $ 与 $[]

**位置操作符**：是写在字段路径里定位数组元素的占位符，$ 指向第一个匹配查询条件的元素，$[] 指向数组全部元素。

先给 _id 为 2 的文档补一个订单数组作为操作对象。

```js
db.users.updateOne(
  { _id: 2 },
  { $set: { orders: [
    { item: "键盘", qty: 2, paid: false },
    { item: "鼠标", qty: 1, paid: true }
  ] } }
)
db.users.updateOne(
  { _id: 2, "orders.item": "键盘" },
  { $set: { "orders.$.paid": true } }
)
db.users.updateOne({ _id: 2 }, { $set: { "orders.$[].qty": 0 } })
```

```text
{ acknowledged: true, insertedId: null, matchedCount: 1, modifiedCount: 1 }
{ acknowledged: true, insertedId: null, matchedCount: 1, modifiedCount: 1 }
{ acknowledged: true, insertedId: null, matchedCount: 1, modifiedCount: 1 }
```

- **$**：指向第一个匹配元素，查询条件里必须包含对数组字段的匹配，此处 orders.item 等于键盘的那一项被置为已支付。
- **$[]**：无差别指向全部元素，此处所有订单的数量被清零。
- **书写位置**：两个占位符都写在字段路径中间，如 orders.$.paid，不是写在更新值里。

> $ 只更新第一个匹配元素，要更新所有满足条件的元素需改用 $[identifier] 配 arrayFilters。查询条件漏掉数组匹配条件时，$ 会报错。



#### $[identifier] 与 arrayFilters

**$[identifier] 与 arrayFilters**：是按自定义条件筛出数组元素再更新的组合，identifier 出现在更新路径中，条件写在第三个参数 arrayFilters 里。

```js
db.users.updateOne(
  { _id: 2 },
  { $set: { "orders.$[o].paid": true } },
  { arrayFilters: [{ "o.paid": false }] }
)
```

```text
{ acknowledged: true, insertedId: null, matchedCount: 1, modifiedCount: 1 }
```

- **identifier 命名**：任意合法标识符，与路径中的 $[名字] 和 arrayFilters 里的条件键一一对应。
- **条件写法**：arrayFilters 是条件数组，键名以 identifier 开头，如 o.paid 筛出未支付订单。
- **多标识符**：嵌套数组场景可同时用多个 identifier，arrayFilters 中为每个 identifier 各给一条条件。

> [!TIP]
> **建议内容**：需要「更新所有满足条件的元素」时一律用这套组合，$ 只覆盖第一条，容易留下漏改的尾巴。



#### upsert 行为

**upsert**：是「匹配不到就插入」的行为，通过第三个参数 upsert 设为 true 开启，updateOne、updateMany、replaceOne 都支持。

```js
db.users.updateOne(
  { name: "周琪" },
  { $set: { age: 30, city: "成都" } },
  { upsert: true }
)
```

```text
{
  acknowledged: true,
  insertedId: ObjectId('652f0a1b2c3d4e5f6a7b8c9d0'),
  matchedCount: 0,
  modifiedCount: 0,
  upsertedCount: 1
}
```

- **双态执行**：匹配到文档按更新走，返回 matchedCount 与 modifiedCount；匹配不到按插入走，返回 upsertedCount 与新文档的 insertedId。
- **新文档合成**：查询条件中的等值字段与更新操作符的内容合并成新文档，此处 name 取自查询，age 与 city 取自 $set。
- **范围差异**：updateMany 开 upsert 也只插入一篇，replaceOne 开 upsert 时插入的是第二个参数的完整文档。

> [!IMPORTANT]
> **重要内容**：upsert 是「存在则更新、不存在则建」类需求的标准写法，常用于计数器、配置项初始化。它把查询与插入合并成一次原子操作，避免了先查后插之间的并发空窗。



#### 无操作符整篇替换的陷阱

**无操作符更新**：更新文档中一个 $ 操作符都不带时，写入语义从「改字段」变成「整篇替换」，这是更新操作里最容易踩的静默陷阱。

```js
db.users.updateOne({ _id: 1 }, { age: 29 })
db.users.find({ _id: 1 })
```

```text
{ acknowledged: true, insertedId: null, matchedCount: 1, modifiedCount: 1 }
[ { _id: 1, age: 29 } ]
```

- **替换语义**：除 _id 外原字段全部丢弃，name、city、tags、score 全没了，只剩新写的 age。
- **判断分界**：第二个参数含至少一个 $ 操作符就是字段更新，一个都不带就是替换，与写的是 updateOne 还是 replaceOne 无关。
- **无报错**：语句正常执行并返回 modifiedCount 1，错误不体现在返回结果里，事后难以察觉。

> [!CAUTION]
> **注意内容**：为 updateOne 写第二个参数时漏掉 $set，结果不是报错而是整篇文档被替换成孤零零一个字段。有意的替换交给 replaceOne，字段更新必须逐字确认操作符存在。
