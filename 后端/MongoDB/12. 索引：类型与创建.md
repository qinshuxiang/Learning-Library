## 索引：类型与创建

### 索引基础与创建语法

#### 索引的价值与代价

**索引（Index）**：是**按指定字段的值排序存储的附加数据结构**，查询从全集合扫描降为沿树定位，MongoDB 索引采用 B 树结构。

- **收益**：等值与范围查询、排序、前置 $match 的聚合都能借助索引，把扫描量从全集合降到命中条目。
- **代价一写入放大**：每次插入、更新、删除都要同步维护所有相关索引，索引越多写入越慢。
- **代价二空间占用**：每个索引独立占存储与内存，工作集装不下索引时性能反噬。

后续示例统一使用 members 集合，先写入三名会员：

```js
db.members.insertMany([
  { _id: 1, name: "张三", email: "zhang@example.com", age: 28, joinedAt: ISODate("2026-01-05T00:00:00Z") },
  { _id: 2, name: "李四", email: "li@example.com", age: 34, joinedAt: ISODate("2026-02-11T00:00:00Z") },
  { _id: 3, name: "王五", email: "wang@example.com", age: 25, joinedAt: ISODate("2026-03-02T00:00:00Z") }
]);
```

> 索引不是越多越好：为每个查询各建一个索引会让写入与存储双重受损，正确做法是用少量复合索引覆盖主要查询模式。索引是否真的被命中，用执行计划验证，详见第 13 篇。



#### createIndex 语法与常用选项

**createIndex**：是**为集合创建索引**的方法，签名为 db.collection.createIndex(keys, options)，keys 声明字段与方向，options 声明索引属性。

- **keys 写法**：单字段写 age 配方向 1，复合写 name 与 joinedAt 各带方向，1 升序、-1 降序。
- **常用选项**：unique 唯一约束、expireAfterSeconds TTL 过期秒数、partialFilterExpression 部分过滤、name 自定义索引名。
- **幂等创建**：对已存在的同结构索引再次执行 createIndex 不会重复创建，直接返回索引名。

创建一个单字段索引与一个带自定义名字的复合索引：

```js
db.members.createIndex({ age: 1 });
db.members.createIndex({ name: 1, joinedAt: -1 }, { name: "name_joined" });
```

```text
age_1
name_joined
```

> 默认索引名是字段与方向的拼接，字段多时可读性差，复合索引建议显式传 name 选项。方向在单字段等值查询里无关紧要，主要影响排序类查询能否直接按索引序读取。



#### getIndexes 与 dropIndex

**getIndexes 与 dropIndex**：分别是**查看集合全部索引**与**删除指定索引**的方法，删除时可传索引名或键模式。

- **getIndexes 输出**：v 是索引版本，key 是键模式，name 是索引名，_id 索引永远排在首位。
- **dropIndex 两种传参**：传索引名（如 age_1）或键模式皆可，一个索引两种写法等价。
- **dropIndexes 清场**：不传参数删除除 _id 外的全部索引，属于高危操作。

```js
db.members.getIndexes();
```

```text
[
  { v: 2, key: { _id: 1 }, name: '_id' },
  { v: 2, key: { name: 1, joinedAt: -1 }, name: 'name_joined' },
  { v: 2, key: { age: 1 }, name: 'age_1' }
]
```

```js
db.members.dropIndex("age_1");
db.members.dropIndex({ name: 1, joinedAt: -1 });
```

```text
{ nIndexesWas: 3, ok: 1 }
{ nIndexesWas: 2, ok: 1 }
```

尝试删除 _id 索引会被服务器拒绝：

```js
db.members.dropIndex("_id_");
```

```text
MongoServerError: cannot drop _id index
```

> [!CAUTION]
> **注意内容**：_id 索引是集合创建时自动生成的主键索引，全部文档靠它保证唯一标识，任何手段都无法删除。删除生产环境的索引前先确认没有查询依赖它，误删会让相关查询瞬间退化为全集合扫描，恢复只能等待重建完成。



### 查询友好的复合索引设计

#### 单字段与复合索引

**单字段与复合索引**：索引键只含一个字段是单字段索引，含多个字段是复合索引；复合索引支持最左前缀——查询条件覆盖索引前缀字段时即可命中。

- **前缀规则**：索引 name 加 joinedAt 可服务 name 等值、name 与 joinedAt 组合两类查询，不能服务只有 joinedAt 的查询。
- **方向的意义**：joinedAt 取 -1 让按加入时间倒序的排序直接走索引序，免去内存排序。
- **避免冗余**：已被复合索引前缀覆盖的单字段索引是重复建设，应清理。

```js
db.members.find({ joinedAt: { $gte: ISODate("2026-01-01T00:00:00Z") } }).sort({ joinedAt: -1 });
```

```text
[
  {
    _id: 3,
    name: '王五',
    email: 'wang@example.com',
    age: 25,
    joinedAt: ISODate('2026-03-02T00:00:00Z')
  },
  {
    _id: 2,
    name: '李四',
    email: 'li@example.com',
    age: 34,
    joinedAt: ISODate('2026-02-11T00:00:00Z')
  },
  {
    _id: 1,
    name: '张三',
    email: 'zhang@example.com',
    age: 28,
    joinedAt: ISODate('2026-01-05T00:00:00Z')
  }
]
```

> 这条查询只有 joinedAt 一个条件，前缀是 name 的复合索引帮不上忙。{ name: 1, joinedAt: -1 } 与 { joinedAt: -1, name: 1 } 是两个不同的索引，前缀不同、能服务的查询族不同，设计时把最常做等值条件的字段放前面。



#### ESR 原则：等值、排序与范围

**ESR 原则**：是**复合索引字段顺序的设计法则——等值（Equality）字段排最前，排序（Sort）字段居中，范围（Range）字段最后**。

- **E 等值在前**：等值条件先把候选集缩到最小，索引在这一段内逐项精确对应。
- **S 排序居中**：等值段确定后，索引天然按排序字段有序，排序免内存、免额外扫描。
- **R 范围最后**：范围条件放在排序字段之后，取出的连续区间仍保持排序字段有序。

以「查指定用户、按加入时间倒序、年龄在某区间」的查询为例，按 ESR 得出理想索引：

```js
db.members.createIndex({ name: 1, joinedAt: -1, age: 1 });
db.members.find({ name: "张三", age: { $gte: 18 } }).sort({ joinedAt: -1 });
```

```text
[
  {
    _id: 1,
    name: '张三',
    email: 'zhang@example.com',
    age: 28,
    joinedAt: ISODate('2026-01-05T00:00:00Z')
  }
]
```

> 违反 ESR 的典型后果：范围字段排在排序字段之前时，索引进入范围段之后顺序被打乱，排序退化为内存排序。ESR 是经验法则而非硬约束，个别场景打破它能换来更少索引，取舍以实际执行计划为准。



#### 多键索引：数组字段的自动展开

**多键索引（Multikey Index）**：是**索引字段为数组时自动启用**的索引形态，无需任何选项，数组每个元素都会生成一个索引项。

- **自动生效**：对数组字段执行 createIndex 即生成多键索引，getIndexes 里没有特殊标记。
- **单数组优先**：复合索引里多个字段都是数组时，索引边界会交叉，查询难以精确裁剪，尽量只让一个字段成为数组。
- **唯一约束语义**：数组字段的唯一索引按「每个元素跨文档不重复」约束，同一数组内部的重复元素不触发冲突。

```js
db.books.insertMany([
  { _id: 1, title: "MongoDB 实战", topics: ["数据库", "后端"] },
  { _id: 2, title: "JavaScript 权威指南", topics: ["前端"] }
]);
db.books.createIndex({ topics: 1 });
db.books.find({ topics: "数据库" });
```

```text
[ { _id: 1, title: 'MongoDB 实战', topics: [ '数据库', '后端' ] } ]
```

> 判断某个索引是否为多键，可在执行计划输出里看 isMultiKey 标记。数组长、更新频繁的字段建多键索引要谨慎，索引条目数随数组长度膨胀，重排一个元素也要维护多个索引项，超大数组建议拆到独立子集合。



### 约束与特殊用途的索引

#### TTL 索引：自动过期删除

**TTL 索引**：是**通过 expireAfterSeconds 选项让文档到期自动删除**的单字段索引，目标字段必须是 BSON 日期类型。

- **到期判定**：字段值加 expireAfterSeconds 秒早于当前时间即到期，样例中的会话在最后活跃 24 小时后删除。
- **删除节奏**：后台任务约每 60 秒扫描一轮，删除有延迟且受负载影响，不能当精确定时器。
- **形态限制**：只支持单字段日期索引，字段值不是日期的文档不会被删除，一个集合可建多个 TTL 索引。

```js
db.sessions.insertMany([
  { _id: 1, user: "张三", token: "a1b2", lastActive: ISODate("2026-09-20T08:00:00Z") },
  { _id: 2, user: "李四", token: "c3d4", lastActive: ISODate("2026-09-22T12:30:00Z") }
]);
db.sessions.createIndex({ lastActive: 1 }, { expireAfterSeconds: 86400 });
```

```text
lastActive_1
```

> [!CAUTION]
> **注意内容**：TTL 删除是异步后台行为，实际删除时间可能比到期时间晚数十秒甚至更久，业务上不要把「刚过期的数据一定查不到」当作前提。字段类型写错为非日期时文档永不过期且不报错，配置后应用 getIndexes 复核索引确实建在了日期字段上。



#### 唯一索引

**唯一索引（Unique Index）**：是**通过 unique 选项保证索引键值在集合内不重复**的约束型索引，兼具加速与约束双重身份。

- **复合唯一**：复合索引加 unique 时约束的是组合值不重复，单个字段重复仍合法。
- **重复键错误**：违反约束的写入报 E11000，批量写入中一条冲突默认中断整批。
- **对脏数据建索引**：集合里已存在重复值时 createIndex 直接失败，需先清洗再建。

给邮箱建唯一索引后，插入重复邮箱被拒绝：

```js
db.members.createIndex({ email: 1 }, { unique: true });
db.members.insertOne({ _id: 4, name: "赵六", email: "zhang@example.com", age: 30, joinedAt: ISODate("2026-04-01T00:00:00Z") });
```

```text
MongoServerError: E11000 duplicate key error collection: test.members index: email_1 dup key: { email: "zhang@example.com" }
```

复合唯一索引约束的是组合值，先看创建，两条新文档只要组合不重复即可共存：

```js
db.members.createIndex({ name: 1, age: 1 }, { unique: true });
db.members.insertOne({ _id: 5, name: "赵六", email: "zhao@example.com", age: 28, joinedAt: ISODate("2026-05-01T00:00:00Z") });
```

> 邮箱、手机号这类业务主键应一律建唯一索引，把重复拦截在数据库层而不是应用层。unique 与 sparse 或 partialFilterExpression 组合可以放行缺失字段或部分文档，两种组合的差异在下文展开。



#### 稀疏索引与部分索引

**稀疏索引与部分索引**：都是**只索引集合中一部分文档**的过滤型索引——稀疏按「字段是否存在」过滤，部分按自定义条件过滤。

- **稀疏索引**：字段缺失（或数组字段为空）的文档不进索引，配合 unique 时缺失字段的文档可多条并存。
- **部分索引**：partialFilterExpression 支持 $exists、$eq、$gt、$gte、$lt、$lte、$type 等条件，可只索引成年用户这类子集。
- **与 unique 组合**：稀疏或部分加唯一索引，只对进索引的文档强制唯一。
- **取舍**：部分索引条件更灵活，新项目优先用部分索引；稀疏是历史形态，语义仅覆盖存在与否。

```js
db.members.createIndex({ email: 1 }, { unique: true, sparse: true });
db.members.createIndex(
  { joinedAt: -1 },
  { partialFilterExpression: { age: { $gte: 18 } } }
);
```

> 部分索引有使用门槛：查询条件必须蕴含 partialFilterExpression 的条件，索引才会被优化器选中——只索引成年用户的索引，服务不筛选年龄的查询时不会被使用。排查「建了索引却没走」时，先检查过滤条件与查询条件是否相容。



#### 文本、地理与哈希索引

**文本、地理与哈希索引**：分别**面向全文检索、位置查询与哈希取模**三类特殊场景，创建时在 keys 里写特殊值而非 1 或 -1。

- **文本索引**：对字段值分词建倒排，配合 $text 与 $search 做词项检索，一个集合最多一个文本索引。
- **地理索引**：2dsphere 服务 GeoJSON 球面查询，2d 服务传统平面坐标，配合 $near 与 $geoWithin 使用。
- **哈希索引**：对字段值取哈希，只支持等值匹配，不支持范围，主要用作分片键。

```js
db.articles.createIndex({ title: "text", body: "text" });
db.places.createIndex({ location: "2dsphere" });
db.members.createIndex({ email: "hashed" });
```

文本索引建好后，用 $text 与 $search 做词项检索：

```js
db.articles.insertMany([
  { _id: 1, title: "聚合管道入门", body: "聚合管道是 MongoDB 的数据分析利器" },
  { _id: 2, title: "索引详解", body: "索引让查询更快" }
]);
db.articles.find({ $text: { $search: "管道" } });
```

```text
[
  {
    _id: 1,
    title: '聚合管道入门',
    body: '聚合管道是 MongoDB 的数据分析利器'
  }
]
```

> 三类特殊索引各配专属查询语法，写普通条件不会触发对应索引。文本索引的分词对中文支持有限，严肃的中文全文检索建议交给 Elasticsearch 等专用引擎，MongoDB 文本索引适合轻量的英文场景。
