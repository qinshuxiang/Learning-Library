## Node 中使用 MongoDB：驱动与 Mongoose

### 官方驱动 mongodb

#### 连接与连接池

**连接池（Connection Pool）**：是**驱动在进程内维护的一组可复用 TCP 连接**，请求从池里取连接、用完归还，避免每次操作都重新握手。

- **maxPoolSize**：每个服务节点的最大连接数，默认 100，需与应用实例数、服务端 maxIncomingConnections 一起折算，防止两边总和超限。
- **minPoolSize**：预热连接数，默认 0；业务高峰前保持少量热连接，可避免冷启动时的建连尖峰。
- **maxIdleTimeMS**：空闲连接的回收时间，默认 0 表示不回收，生产环境常设 30000 到 60000 毫秒。
- **按主机建池**：连接池按服务节点维度建立，副本集场景下每个成员各有一个池，上述参数作用于每个成员。

```js
const { MongoClient } = require("mongodb");

// 连接串格式：协议://地址:端口
const uri = "mongodb://127.0.0.1:27017";
const client = new MongoClient(uri, {
  maxPoolSize: 20,
  minPoolSize: 5,
  maxIdleTimeMS: 30000,
});

async function main() {
  await client.connect();
  const db = client.db("shop");
  const users = db.collection("users");
  const count = await users.countDocuments({});
  console.log("用户总数:", count);
  await client.close();
}
main();
```

```text
用户总数: 3800
```

连接串还承载鉴权与选项信息，完整形态是 mongodb://用户名:密码@主机:端口/库名?authSource=admin&maxPoolSize=20，库写在路径里、参数写在查询串里。

> [!CAUTION]
> **注意内容**：一个进程只建一个 MongoClient 单例并全程复用，不要为每个请求 new 一个客户端。反复建连不仅慢，还会迅速吃满服务端的连接数上限，这是 Node 接 MongoDB 最常见的误用。



#### 原生驱动 CRUD

**原生驱动 CRUD**：是直接用 mongodb 包提供的集合方法完成增删改查，方法名与语义与 mongosh 中的集合操作一一对应。

- **插入**：insertOne 插一篇，insertMany 插一批，返回值里带 insertedId 或 insertedIds。
- **查询**：findOne 取第一条，find 返回游标，链式 sort、limit、skip 后用 toArray 收数。
- **更新**：updateOne 与 updateMany 配合 $set 等更新操作符，findOneAndUpdate 可顺带拿回改前或改后的文档。
- **删除**：deleteOne 与 deleteMany，同样配合过滤器使用。

```js
const { MongoClient } = require("mongodb");
const client = new MongoClient("mongodb://127.0.0.1:27017");
const db = client.db("shop");
const users = db.collection("users");

async function run() {
  await client.connect();

  // 插入
  const insertResult = await users.insertOne({ username: "lin", age: 20 });
  console.log("插入的 _id:", insertResult.insertedId);

  // 查询
  const doc = await users.findOne({ username: "lin" });
  console.log("查询到的年龄:", doc.age);

  // 更新
  const updateResult = await users.updateOne(
    { username: "lin" },
    { $set: { age: 21 } }
  );
  console.log("更新条数:", updateResult.modifiedCount);

  // 删除
  const deleteResult = await users.deleteOne({ username: "lin" });
  console.log("删除条数:", deleteResult.deletedCount);

  await client.close();
}
run();
```

```text
插入的 _id: 6650e1a2f1c9b3a4d5e6f708
查询到的年龄: 20
更新条数: 1
删除条数: 1
```

两个容易踩的差别：查询条件直接写普通对象时是精确匹配，范围与逻辑匹配要写 $gt 这类操作符；更新必须带更新操作符，直接传普通对象会把整篇文档替换掉。

> 原生驱动的 API 是对服务器协议的薄封装：会用 mongosh 写查询，几乎就等于会用驱动写查询。它没有结构约束，字段拼写错误不会报错，只是安静地查不到数据——这正是后面 Mongoose 出场的理由。



### Mongoose 的模型层

#### Schema 与 Model

**Schema 与 Model**：是 Mongoose 模型层的两个基础对象——Schema 定义集合内文档的字段结构、类型与约束，Model 是由 Schema 编译出的构造函数，一个 Model 绑定一个集合。

- **Schema**：用 JS 对象描述字段，每个字段写类型与约束，如 required、default、min。
- **Model**：由 mongoose.model 编译 Schema 得到，持有 CRUD 方法，实例化后得到文档对象。
- **集合命名**：model 的首参是单数名词，Mongoose 默认转成小写复数作为集合名，User 对应 users 集合。

```js
const mongoose = require("mongoose");
const { Schema, model } = mongoose;

const userSchema = new Schema({
  username: { type: String, required: true },
  email: { type: String, required: true },
  age: { type: Number },
  createdAt: { type: Date },
});

const User = model("User", userSchema);

async function run() {
  await mongoose.connect("mongodb://127.0.0.1:27017/shop");

  const user = new User({ username: "lin", email: "lin@example.com", age: 20 });
  await user.save();
  console.log("集合名:", User.collection.name);

  const found = await User.findOne({ username: "lin" });
  console.log("是否文档实例:", found instanceof User);

  await mongoose.disconnect();
}
run();
```

```text
集合名: users
是否文档实例: true
```

> Schema 定义结构、Model 提供行为、Document 承载数据，三者构成 Mongoose 的三层骨架。原生驱动的文档只是普通对象，Mongoose 的文档是带方法与状态跟踪的实例，知道哪些字段被改过，保存时只发送变更部分。



#### 字段校验与默认值

**字段校验与默认值**：是 Schema 上声明的数据质量规则——校验在保存时拦截非法数据，默认值在字段缺省时自动补齐，二者都在 Mongoose 层生效而非服务端生效。

- **required**：必填校验，值可写成布尔或返回布尔的函数。
- **min／max**：数值边界，minlength／maxlength 用于字符串。
- **enum**：枚举白名单，取值只能来自给定数组。
- **match**：正则校验，常用于邮箱、手机号这类格式。
- **validate**：自定义校验器，接收字段值并返回布尔或抛出错误。
- **default**：默认值，可直接给常量，也可给函数在创建时求值。

```js
const mongoose = require("mongoose");
const { Schema, model } = mongoose;

const userSchema = new Schema({
  username: { type: String, required: [true, "用户名必填"], trim: true },
  email: { type: String, required: true, match: /.+@.+\..+/ },
  role: { type: String, enum: ["user", "admin"], default: "user" },
  age: { type: Number, min: 0, max: 130 },
  createdAt: { type: Date, default: Date.now },
});
const User = model("User", userSchema);

async function createUser() {
  await mongoose.connect("mongodb://127.0.0.1:27017/shop");

  // 只传必填字段，role 与 createdAt 由默认值补齐
  const user = new User({ username: "lin", email: "lin@example.com" });
  const saved = await user.save();
  console.log("默认角色:", saved.role);
  console.log("默认时间是 Date:", saved.createdAt instanceof Date);

  await mongoose.disconnect();
}
createUser();
```

```text
默认角色: user
默认时间是 Date: true
```

> [!CAUTION]
> **注意内容**：updateOne 与 findOneAndUpdate 这类更新方法默认不触发校验，需要显式传 runValidators: true 才会按 Schema 校验更新值；另外校验只发生在 Mongoose 层，绕开 Mongoose 直接连库写入的数据不受任何约束，服务端的 schema 校验（validator）是另一道可选防线。



#### 中间件 pre 与 save

**中间件（Middleware）**：是 Mongoose 在文档生命周期的固定节点自动执行的钩子函数，pre 在节点前执行，post 在节点后执行，save、validate、deleteOne 等都注册有钩子。

- **pre("save")**：保存前执行，最常用的落点是密码加密、更新时间戳这类写入前加工。
- **isModified**：文档实例方法，判断某个字段本次是否被修改，密码加密只在密码变化时执行。
- **执行顺序**：同一节点的中间件按注册顺序执行，必须调用 next() 或返回 Promise 放行，漏放行会导致保存挂起。

```js
const crypto = require("crypto");
const mongoose = require("mongoose");
const { Schema, model } = mongoose;

const userSchema = new Schema({
  username: String,
  password: { type: String, required: true },
  updatedAt: Date,
});

// 保存前：密码变化时先做哈希，并刷新更新时间
userSchema.pre("save", function (next) {
  if (this.isModified("password")) {
    this.password = crypto
      .createHash("sha256")
      .update(this.password)
      .digest("hex");
  }
  this.updatedAt = new Date();
  next();
});

const User = model("User", userSchema);

async function register() {
  await mongoose.connect("mongodb://127.0.0.1:27017/shop");

  const user = await User.create({ username: "lin", password: "raw-pass" });
  console.log("库里存的密码前 12 位:", user.password.slice(0, 12));

  await mongoose.disconnect();
}
register();
```

```text
库里存的密码前 12 位: a4c4d0f4b1c2
```

> [!TIP]
> **建议内容**：pre("save") 只在使用 save 与 create 写入时触发，updateOne、findOneAndUpdate 走的是查询中间件，钩子函数名不同。需要在所有写路径生效的逻辑，要么两边都注册，要么把写入口收拢成只走 save 的统一方法。



### 关联查询与选型

#### populate 关联查询

**populate（关联填充）**：是 Mongoose 把 ObjectId 引用字段替换为目标集合真实文档的查询能力，相当于关系库的关联查询，引用字段在 Schema 里用 ref 声明目标模型。

- **单引用**：字段类型为 Schema.Types.ObjectId 且带 ref，populate 后得到单篇文档。
- **多引用**：字段类型为 ObjectId 数组，populate 后得到文档数组。
- **字段筛选**：populate 的第二参写返回的字段列表，避免把目标文档整个拉回。

```js
const mongoose = require("mongoose");
const { Schema, model } = mongoose;

const userSchema = new Schema({ username: String });
const postSchema = new Schema({
  title: String,
  author: { type: Schema.Types.ObjectId, ref: "User" },
});

const User = model("User", userSchema);
const Post = model("Post", postSchema);

async function run() {
  await mongoose.connect("mongodb://127.0.0.1:27017/shop");

  const author = await User.create({ username: "lin" });
  const post = await Post.create({ title: "MongoDB 入门", author: author._id });

  // 不填充：author 只是 ObjectId，看不到 username
  const raw = await Post.findById(post._id);
  console.log("未填充的 author:", raw.author.constructor.name);
  console.log("未填充有无 username:", raw.author.username === undefined);

  // 填充：author 变成 User 文档，且只带 username
  const found = await Post.findById(post._id).populate("author", "username");
  console.log("标题:", found.title);
  console.log("作者:", found.author.username);

  await mongoose.disconnect();
}
run();
```

```text
未填充的 author: ObjectId
未填充有无 username: true
标题: MongoDB 入门
作者: lin
```

> populate 本质是「先查主集合，再拿引用值查一遍目标集合」的两次查询，由 Mongoose 自动完成，并非服务端的原生关联。列表页批量填充时注意控制条数与填充深度，嵌套 populate 层数越多，发起的查询次数越多。



#### Mongoose 与原生驱动的取舍

**Mongoose 与原生驱动的取舍**：本质是「要不要在驱动之上加一层模型抽象」——Mongoose 用一层封装换来结构约束与开发效率，原生驱动用零抽象换来轻量与跟随服务端特性的速度。

- **Mongoose 的收益**：模式约束、保存时校验、默认值、生命周期中间件、populate、字段变更跟踪，适合模型复杂、多人协作的业务应用。
- **Mongoose 的代价**：多一层依赖与抽象，学习成本集中在 Schema 选项与中间件时序上；服务端新特性要等 Mongoose 跟进。
- **原生驱动的收益**：贴着协议走，服务端新命令可用得最早，无额外抽象层，适合脚本、工具、轻量服务与性能敏感路径。
- **折中做法**：核心业务用 Mongoose 管模型，数据导入导出、迁移与运维脚本用原生驱动直连，两层可以共存于同一项目。

> [!IMPORTANT]
> **重要内容**：选型判据看模型复杂度而不是项目大小：文档结构稳定、校验与关联需求多的业务系统，Mongoose 的约束收益远大于抽象成本；结构灵活多变、以读为主或以脚本为主的场景，原生驱动更直接。同一个项目里两者按用途分工也是常见且合理的形态。
