## MongoDB 简介与安装配置

### 文档数据库的定位

#### MongoDB 是什么

**MongoDB**：是一款以文档为基本存储单元的**开源文档型 NoSQL 数据库**，由 C++ 编写，数据以类 JSON 的 BSON 格式保存，当前主线版本为 8.0。

- **存储单元**：一条数据是一个 BSON 文档，结构类似 JSON 对象，字段名与字段值成对出现，可自由嵌套。
- **模式灵活**：同一集合内的文档可以拥有不同的字段，新增字段不需要预先修改表结构，也不需要执行变更脚本。
- **原生分布式**：内置副本集（Replica Set）提供高可用，分片（Sharding）提供水平扩展，两者都是产品内建能力。
- **典型场景**：内容管理、商品目录、用户画像、消息与事件流等结构多变、写入量大的业务。

```json
{
  "name": "林晓",
  "age": 28,
  "tags": ["backend", "mongodb"],
  "address": { "city": "杭州", "district": "西湖区" }
}
```

> 这条文档展示了 MongoDB 的核心气质：字段可以随意增减，值可以是数组与嵌套对象，一条文档即可表达传统数据库里需要多张表连接才能拼出的结构。是否需要拆分，由应用层按读写模式决定，而不是由表结构预先框死。



#### 库集合文档与库表行的概念对照

**概念对照**：MongoDB 的三层组织结构与关系数据库一一对应，只是名称不同、约束更松。

- **数据库对数据库**：最外层容器都叫 database，一个 MongoDB 实例可承载多个相互隔离的库。
- **集合对表**：集合（Collection）对应关系数据库的表（Table），是不要求成员结构一致的文档容器。
- **文档对行**：文档（Document）对应关系数据库的行（Row），是一条完整的 BSON 记录，天然支持嵌套。
- **字段对列**：字段（Field）对应关系数据库的列（Column），但没有全局列定义，字段属于每条文档自身。
- **_id 对主键**：每个文档必须拥有唯一的 _id 字段，作用等同主键，写入时未指定则自动生成 ObjectId。

```text
关系数据库：数据库 → 表 → 行 → 列
MongoDB：  数据库 → 集合 → 文档 → 字段
```

> 对照记忆时抓住一个根本差别：关系数据库的表结构是「先定义后写入」，写入前必须建好表和列；MongoDB 的集合是「先写入后形成结构」，模式约束从数据库转移到应用层。灵活换来的代价是数据库不再帮忙拦截结构错误。



#### 什么时候选 MongoDB

**选型判断**：文档模型适合结构多变、以聚合读写为主的场景，事务密集与强关系建模仍是关系数据库的主场。

- **适合的场景**：一个业务对象字段经常增减、整体读写（一次取整条文档）、数据量增长需要水平拆分的业务，如商品详情、内容系统、埋点事件。
- **不适合的场景**：跨多实体的复杂事务、大量多表连接式关联查询、财务级强一致记账，这些用关系数据库更直接。
- **折中的做法**：两者并存——核心交易放关系数据库，内容与行为数据放 MongoDB，是常见组合而非取舍。

> 选型口诀是「整体读、结构活、量增长」三占其一再考虑 MongoDB；仅仅因为「不想建表」而选它，省下的建表时间会在查询与一致性上加倍还回来。



### macOS 平台安装

#### 使用 Homebrew 安装

**Homebrew 安装**：是 macOS 上最省事的安装方式，官方提供 mongodb/brew 仓库，社区版安装后可直接用 brew services 托管进程。

```bash
# 添加 MongoDB 官方仓库并安装 8.0 社区版
brew tap mongodb/brew
brew install mongodb-community@8.0

# 作为后台服务启动，并注册开机自启
brew services start mongodb-community@8.0

# 或以前台进程方式手动启动，日志直接打印到终端
mongod --config /opt/homebrew/etc/mongod.conf
```

- **安装内容**：包含 mongod 服务进程、mongos 路由进程与 mongosh 交互外壳。
- **数据目录**：Apple Silicon 机型默认为 /opt/homebrew/var/mongodb，Intel 机型前缀是 /usr/local。
- **配置文件**：默认位于 /opt/homebrew/etc/mongod.conf，用 brew services 启动时自动读取。
- **停止与卸载**：brew services stop mongodb-community@8.0 停止服务，brew uninstall 移除软件本体，数据目录需另行删除。
- **查看状态**：brew services list 列出全部托管服务的启停状态，MongoDB 行显示 started 即在运行。

> [!TIP]
> **建议内容**：macOS 优先选择 Homebrew 方式，服务托管、日志目录、配置文件路径都由安装包安排妥当；官方手动 tgz 包目前仅提供 x86_64 版本，Apple Silicon 机型更应走 brew 安装。



#### 手动下载 tgz 安装

**tgz 手动安装**：从官网下载压缩包解压即用，适合不想依赖 brew 或需要多版本并存的场景。

```bash
# 下载社区版压缩包并解压
curl -LO https://fastdl.mongodb.org/osx/mongodb-macos-x86_64-8.0.0.tgz
tar -zxvf mongodb-macos-x86_64-8.0.0.tgz

# 把可执行文件复制进 PATH 覆盖的目录
sudo cp mongodb-macos-x86_64-8.0.0/bin/* /usr/local/bin/

# 手动创建数据与日志目录
sudo mkdir -p /usr/local/var/mongodb
sudo mkdir -p /usr/local/var/log/mongodb

# 后台启动，手动指定数据与日志路径
mongod --dbpath /usr/local/var/mongodb \
  --logpath /usr/local/var/log/mongodb/mongo.log --fork
```

- **--dbpath**：指定数据文件存放目录，目录必须已存在且对当前用户可写。
- **--logpath**：指定日志文件路径，配合 --fork 表示后台运行并把日志写入该文件。
- **--fork**：以守护进程方式运行，进程脱离当前终端，必须与 --logpath 同时使用。
- **--port**：指定监听端口，默认 27017，端口被占用时用它与默认实例并存。

> [!CAUTION]
> **注意内容**：手动安装不含 mongosh，需要单独下载安装；数据目录权限是最常见的启动失败原因，报错包含 permission denied 时优先检查 --dbpath 指向目录的属主与可写性。



### Linux 平台安装

#### 以 Ubuntu 为例的 apt 安装

**apt 安装**：Ubuntu 等基于 Debian 的发行版通过添加 MongoDB 官方 apt 源安装，官方源的版本比系统自带源更新且维护期更长。

```bash
# 导入 MongoDB 官方 GPG 公钥
sudo apt-get install gnupg curl
curl -fsSL https://www.mongodb.org/static/pgp/server-8.0.asc | \
  sudo gpg -o /usr/share/keyrings/mongodb-server-8.0.gpg --dearmor

# 添加 apt 源（以 Ubuntu 22.04 jammy 为例）
echo "deb [ arch=amd64,arm64 signed-by=/usr/share/keyrings/mongodb-server-8.0.gpg ] https://repo.mongodb.org/apt/ubuntu jammy/mongodb-org/8.0 multiverse" | \
  sudo tee /etc/apt/sources.list.d/mongodb-org-8.0.list

# 刷新索引并安装最新社区版
sudo apt-get update
sudo apt-get install -y mongodb-org
```

- **安装内容**：mongodb-org 元包会连带安装 mongod、mongos、mongosh 与数据库工具集。
- **版本锁定**：官方包安装后默认被 apt-mark hold 锁定，防止系统升级把数据库升到不兼容的大版本。
- **固定路径**：配置文件 /etc/mongod.conf，数据目录 /var/lib/mongodb，日志目录 /var/log/mongodb。

> [!CAUTION]
> **注意内容**：源地址里的 jammy 与 mongodb-org/8.0 两处随系统版本与目标版本变化，照抄前先核对，写错会导致 apt-get update 报 404；RHEL 系发行版改用 yum 或 dnf 配置官方 rpm 源，流程类似但地址不同。



#### 服务管理与开机自启

**systemd 服务**：apt 安装完成后会注册 mongod 服务，用 systemctl 统一管理启停与自启。

```bash
# 启动服务并查看运行状态
sudo systemctl start mongod
sudo systemctl status mongod

# 设置开机自启
sudo systemctl enable mongod

# 重启与停止
sudo systemctl restart mongod
sudo systemctl stop mongod
```

```text
● mongod.service - MongoDB Database Server
     Loaded: loaded (/usr/lib/systemd/system/mongod.service; disabled; vendor preset: enabled)
     Active: active (running) since Wed 2026-09-23 10:12:45 CST; 5s ago
   Main PID: 4821 (mongod)
      Tasks: 8 (limit: 4519)
     Memory: 96.5M
        CPU: 1.204s
```

- **status 判读**：Active 显示 active (running) 即服务正常；显示 failed 时用 journalctl -u mongod 查看完整日志定位原因。
- **enable 与 start 相互独立**：enable 只管开机自启，start 只管当下启停，装完只 enable 不 start 服务并不会运行。
- **重启时机**：修改 /etc/mongod.conf 后必须 restart 才生效，mongod 不会热加载配置文件。

> 首次启动失败多为 /var/lib/mongodb 目录权限问题：安装包通常已建好属主为 mongodb 用户的目录，若把数据目录挪过位置，必须用 chown 把属主改回 mongodb，否则 mongod 拒绝写入直接退出。



### 启动与连接验证

#### mongod 启动与配置文件常用项

**mongod 与配置文件**：mongod 是数据库服务主进程，参数可通过命令行传入，生产与日常使用推荐统一写在 YAML 格式的配置文件里管理。

```bash
# 读取默认位置的配置文件启动
mongod --config /etc/mongod.conf

# 不用配置文件时，用命令行参数最小化启动
mongod --dbpath /data/db --port 27017
```

常用配置项：

- **storage.dbPath**：数据文件目录，与命令行 --dbpath 等价。
- **net.port**：监听端口，默认 27017。
- **net.bindIp**：监听地址，默认 127.0.0.1，只接受本机连接。
- **systemLog.destination 与 systemLog.path**：日志输出方式设为 file 时，日志写入 path 指定的文件。
- **systemLog.logAppend**：设为 true 时重启后日志追加而非覆盖。
- **processManagement.fork**：设为 true 时以守护进程方式后台运行。
- **replication.replSetName**：副本集名称，搭建副本集时必填。
- **security.authorization**：设为 enabled 时开启访问控制，连接必须提供账号凭据。
- **storage.wiredTiger.engineConfig.cacheSizeGB**：WiredTiger 缓存上限，默认约为可用内存的一半，与其他服务混部时按需下调。

```bash
# 最小可用的配置文件示例
sudo tee /etc/mongod.conf << 'EOF'
storage:
  dbPath: /var/lib/mongodb
net:
  port: 27017
  bindIp: 127.0.0.1
systemLog:
  destination: file
  path: /var/log/mongodb/mongod.log
  logAppend: true
processManagement:
  fork: true
EOF
```

> [!CAUTION]
> **注意内容**：bindIp 保持 127.0.0.1 最安全，改成 0.0.0.0 而又未开启 authorization，等于把数据库完全暴露给外网，是云上数据库被勒索删库的最常见根源；开放远程访问之前必须先建账号并开启鉴权。



#### 使用 mongosh 连接验证

**连接验证**：mongosh 是官方交互式 JavaScript 外壳，连接成功并能执行命令，才证明服务真正可用。

```bash
# 连接本机默认端口
mongosh
```

```text
Current Mongosh Log ID: 68f1a2b3c4d5e6f7a8b9c0d1
Connecting to:      mongodb://127.0.0.1:27017/?directConnection=true&serverSelectionTimeoutMS=2000&appName=mongosh+2.5.0
Using MongoDB:      8.0.0
Using Mongosh:      2.5.0

For mongosh info see: https://www.mongodb.com/docs/mongodb-shell/

test>
```

进入外壳后执行验证命令：

```js
db.version()
show dbs
```

```text
test> db.version()
8.0.0
test> show dbs
admin   132.00 KiB
config   84.00 KiB
local    72.00 KiB
test>
```

- **连接串语义**：不带参数的 mongosh 等价于连接 mongodb://127.0.0.1:27017；连远程实例写成 mongosh "mongodb://用户名:密码@主机:端口"。
- **三个系统库**：admin 存放账号与角色，config 存放分片元数据，local 存放副本集内部数据，均由系统维护，不要拿来做业务库。
- **默认上下文**：未 use 任何库时提示符为 test，test 只是一个空的默认命名空间，不写入数据就不会真正落盘。
- **退出方式**：输入 exit 或按 Ctrl+C 断开连接，返回系统 shell。

> [!IMPORTANT]
> **重要内容**：验证成功的完整判据有两条——连接横幅正常显示，且 db.version() 返回版本号、show dbs 列出 admin、config、local 三个系统库；只看到横幅不代表命令通道可用，网络防火墙中断等场景下命令仍会超时报错。



#### 常见启动失败与排查

**启动失败排查**：mongod 启动失败时日志会给出明确原因，按日志定位比盲目重装有效。

- **端口被占用**：日志出现 Address already in use，用 lsof -i :27017 找到占用进程，换端口或停掉旧进程。
- **数据目录不可写**：日志出现 permission denied，检查 dbPath 目录是否存在、属主是否为运行 mongod 的用户。
- **异常退出后锁文件残留**：非正常关机后可能出现 mongod.lock 残留，确认无进程运行后删除该文件再启动。
- **配置文件缩进错误**：YAML 对缩进敏感，报错提示 YAML 相关信息时逐行检查空格，配置文件不允许使用 Tab 缩进。
- **数据目录版本不匹配**：用高版本 mongod 直接打开过旧的低版本数据目录，日志会提示版本不兼容，先走官方升级路径再启动。

```bash
# 查看服务端日志末尾，定位启动失败原因
tail -n 50 /var/log/mongodb/mongod.log

# 检查默认端口是否被占用
lsof -i :27017
```

```text
mongod  4821 qinshuxiang   11u  IPv6 0x9f3c2a1b8d6e4f70      0t0  TCP *:27017 (LISTEN)
```

> 排查顺序固定为「先日志、后权限、再端口」：绝大多数启动失败都能在日志末尾几行找到直接原因；未开鉴权且绑定本机时，日志还会提示 Access control is not enabled 的安全告警，属于提醒而非故障。
