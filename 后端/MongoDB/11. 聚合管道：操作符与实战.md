## 聚合管道：操作符与实战

### 分组累加器

#### $sum 与 $avg

**$sum 与 $avg**：是**组内求和与求平均**的累加器，用在 $group 内做统计，计数只需让 $sum 接常量 1。

- **$sum 累加**：对表达式结果逐条累加，表达式常用字段引用或 $multiply 这类算术组合。
- **$avg 平均**：对组内数值求算术平均，非数值与缺失值自动跳过，空组返回 null。
- **计数惯用形**：$sum 接常量 1 得到组内文档条数，是聚合中出现频率最高的写法。

示例沿用第 10 篇的 orders 集合，先完整重建样例数据：

```js
db.orders.insertMany([
  { _id: 1, user: "张三", item: "键盘", price: 299, qty: 2, tags: ["电子", "外设"], status: "paid", createdAt: ISODate("2026-01-12T08:30:00Z") },
  { _id: 2, user: "李四", item: "鼠标", price: 129, qty: 1, tags: ["电子"], status: "paid", createdAt: ISODate("2026-01-20T14:05:00Z") },
  { _id: 3, user: "张三", item: "显示器", price: 1599, qty: 1, tags: ["电子", "屏幕"], status: "shipped", createdAt: ISODate("2026-02-08T10:00:00Z") },
  { _id: 4, user: "王五", item: "键帽", price: 89, qty: 3, tags: ["外设"], status: "cancelled", createdAt: ISODate("2026-02-15T19:40:00Z") },
  { _id: 5, user: "李四", item: "鼠标垫", price: 39, qty: 2, tags: [], status: "paid", createdAt: ISODate("2026-03-01T09:15:00Z") },
  { _id: 6, user: "王五", item: "显示器支架", price: 249, qty: 1, tags: ["外设", "屏幕"], status: "paid", createdAt: ISODate("2026-03-18T16:20:00Z") }
]);
```

按用户统计已支付订单的消费总额与单价均值：

```js
db.orders.aggregate([
  { $match: { status: "paid" } },
  { $group: {
      _id: "$user",
      totalAmount: { $sum: { $multiply: ["$price", "$qty"] } },
      avgPrice: { $avg: "$price" }
  } },
  { $sort: { totalAmount: -1 } }
]);
```

```text
[
  { _id: '张三', totalAmount: 598, avgPrice: 299 },
  { _id: '王五', totalAmount: 249, avgPrice: 249 },
  { _id: '李四', totalAmount: 207, avgPrice: 84 }
]
```

> 张三只有一笔已支付订单，均值就是单价本身；李四两笔单价的均值是 84。累加器只对数值生效，字段混入字符串时该条被静默跳过，统计口径存疑时要先检查字段类型是否干净。



#### $min 与 $max

**$min 与 $max**：是**取组内最小值与最大值**的累加器，按 BSON 类型顺序比较，数值与日期同样适用。

- **数值极值**：最常用于价格、金额的最高最低。
- **时间极值**：对日期字段取 $max，直接得到最近一次行为的发生时间。
- **跨类型比较**：比较遵循 BSON 类型排序，字段类型混杂时结果可能不符合直觉，先保证类型一致。

按状态统计价格的最低与最高：

```js
db.orders.aggregate([
  { $group: { _id: "$status", minPrice: { $min: "$price" }, maxPrice: { $max: "$price" } } },
  { $sort: { _id: 1 } }
]);
```

```text
[
  { _id: 'cancelled', minPrice: 89, maxPrice: 89 },
  { _id: 'paid', minPrice: 39, maxPrice: 299 },
  { _id: 'shipped', minPrice: 1599, maxPrice: 1599 }
]
```

> 单元素组的 min 与 max 相等，如 shipped 组都是 1599，属正常现象而非错误。想要「最贵的那条完整文档」而不是单个值，用 $first 配合 $sort 更合适，这正是下一考点的用武之地。



#### $push 与 $addToSet

**$push 与 $addToSet**：是**组内收集值的两个累加器**——$push 把每个值按顺序追加进数组、保留重复，$addToSet 收集去重、顺序不保证。

- **$push 收集明细**：把组内每条文档的某字段汇成数组，常用于导出订单明细、标签列表。
- **$addToSet 去重**：同一用户买过多次同一商品时只记一次，代价是无法依赖输出顺序。
- **数组字段整体入组**：$push 引用数组字段时会把整个数组作为一个元素追加，需要拼接数组内容用 $concatArrays。

按用户汇总买过的商品与出现过的订单状态：

```js
db.orders.aggregate([
  { $group: { _id: "$user", allItems: { $push: "$item" }, distinctStatus: { $addToSet: "$status" } } },
  { $sort: { _id: 1 } }
]);
```

```text
[
  { _id: '张三', allItems: [ '键盘', '显示器' ], distinctStatus: [ 'paid', 'shipped' ] },
  { _id: '李四', allItems: [ '鼠标', '鼠标垫' ], distinctStatus: [ 'paid' ] },
  { _id: '王五', allItems: [ '键帽', '显示器支架' ], distinctStatus: [ 'cancelled', 'paid' ] }
]
```

> 需要稳定顺序时用 $push 再在下游去重，不要依赖 $addToSet 的元素顺序做展示。组内数组膨胀是性能隐患，收集前先用 $match 缩小范围，或对数组做截断。



#### $first 与 $last

**$first 与 $last**：是**取组内排序后第一条与最后一条文档的字段值**的累加器，语义完全依赖上游的 $sort 结果。

- **前置 $sort 是前提**：没有排序时组内顺序不确定，$first 与 $last 的结果不可预期。
- **典型场景**：按时间排序后取每个用户的首次与最近一次消费商品，即留存分析里的首购与最近购买。
- **与 $min/$max 的区别**：$min 取的是最小值本身，$first 取的是排序后第一条文档上的任意字段，两者取的东西不同。

按下单时间排序后，取全库首笔与最近一笔订单的商品：

```js
db.orders.aggregate([
  { $sort: { createdAt: 1 } },
  { $group: { _id: null, firstItem: { $first: "$item" }, lastItem: { $last: "$item" } } }
]);
```

```text
[ { _id: null, firstItem: '键盘', lastItem: '显示器支架' } ]
```

> 把 $first 与 $last 理解成「排序后的头尾取样」，就能安全使用；脱离 $sort 单独用，输出会随内部实现波动。分组键换成 "$user"，同一管道立刻变成每用户的首末消费统计，只改一处表达式。



### 字符串、日期与条件操作符

#### 字符串操作符 $concat 与 $toUpper

**$concat 与 $toUpper**：是管道内最常用的两个字符串操作符——$concat 拼接多个字符串表达式为一个字符串，$toUpper 把字符串转为大写，配套的 $toLower 转小写。

- **$concat 拼接**：参数是表达式数组，常量与字段引用混写即可生成展示用文案。
- **$toUpper 大小写**：只对拉丁字母生效，中文字符原样返回。
- **空值传染**：$concat 的任一参数为 null 或字段缺失时，结果整体为 null。

拼接订单文案并转大写状态标记：

```js
db.orders.aggregate([
  { $project: {
      _id: 0,
      label: { $concat: ["$user", " 购买了 ", "$item"] },
      statusUpper: { $toUpper: "$status" }
  } },
  { $limit: 2 }
]);
```

```text
[
  { label: '张三 购买了 键盘', statusUpper: 'PAID' },
  { label: '李四 购买了 鼠标', statusUpper: 'PAID' }
]
```

> $concat 的空值传染在脏数据场景下最伤：用户名缺失时整条文案变 null，下游再拼它就层层失效。稳妥做法是先套 $ifNull 给缺省值再拼接，空值处理的细节在条件操作符中展开。



#### 日期操作符 $year、$month 与 $dateToString

**$year、$month 与 $dateToString**：是从日期取分量与做格式化的日期操作符——$year 与 $month 返回数字，$dateToString 按模板返回字符串。

- **取分量**：$year、$month、$dayOfMonth、$hour 等各自返回对应分量，参数是日期字段。
- **格式化**：$dateToString 用 format 模板输出字符串，%Y 是四位年份，%m 是两位月份，%d 是两位日。
- **时区参数**：默认按 UTC 取值，传 timezone 可切换时区，如东八区。

把下单时间拆成年、月与格式化日期：

```js
db.orders.aggregate([
  { $project: {
      _id: 0,
      year: { $year: "$createdAt" },
      month: { $month: "$createdAt" },
      dateLabel: { $dateToString: { format: "%Y-%m-%d", date: "$createdAt" } }
  } },
  { $limit: 2 }
]);
```

```text
[
  { year: 2026, month: 1, dateLabel: '2026-01-12' },
  { year: 2026, month: 1, dateLabel: '2026-01-20' }
]
```

> 日期操作符默认按 UTC 计算分量，东八区晚八点之后的订单会被算到次日，跨月订单直接落进下一个月。做日报、月报统计时给日期操作符统一带上 timezone 参数，或在入库前统一存本地时间，二选一，不能混用。



#### 条件操作符 $cond、$switch 与 $ifNull

**$cond、$switch 与 $ifNull**：是管道内的三个条件分支操作符——$cond 做二选一，$switch 做多分支，$ifNull 给空值兜底。

- **$cond 三元**：if 是条件表达式，then 与 else 给两个分支的返回值，适合二元判断，也支持数组简写形式。
- **$switch 多分支**：branches 数组按顺序匹配 case，命中即返回对应 then，全不中走 default。
- **$ifNull 兜底**：从左到右取第一个非空值，字段为 null 或缺失都算空，适合给缺省值。

一个投影里同时演示三个操作符，金额分层用 $switch，取消单标记用 $cond，标签兜底用 $ifNull：

```js
db.orders.aggregate([
  { $project: {
      _id: 0,
      item: 1,
      level: {
        $switch: {
          branches: [
            { case: { $gte: [{ $multiply: ["$price", "$qty"] }, 1000] }, then: "大额" },
            { case: { $gte: [{ $multiply: ["$price", "$qty"] }, 200] }, then: "普通" }
          ],
          default: "小额"
        }
      },
      settlement: {
        $cond: [{ $eq: ["$status", "cancelled"] }, "不结算", { $multiply: ["$price", "$qty"] }]
      },
      tagsSafe: { $ifNull: ["$tags", "无标签"] }
  } },
  { $limit: 3 }
]);
```

```text
[
  { item: '键盘', level: '普通', settlement: 598, tagsSafe: [ '电子', '外设' ] },
  { item: '鼠标', level: '小额', settlement: 129, tagsSafe: [ '电子' ] },
  { item: '显示器', level: '大额', settlement: 1599, tagsSafe: [ '电子', '屏幕' ] }
]
```

> 分支超过两个时坚持用 $switch，嵌套 $cond 的可读性会急速崩塌。$ifNull 的兜底值类型要与原字段保持一致，数值字段兜成字符串会让下游的算术操作符报类型错误。



### 连接与多分支

#### $lookup 左外连接

**$lookup**：是**在聚合中实现对另一集合的左外连接**的阶段，把匹配到的关联文档整组放进输出文档的一个数组字段。

- **四要素**：from 指目标集合，localField 是本集合的连接字段，foreignField 是目标集合的连接字段，as 是输出数组字段名。
- **左外语义**：主文档总是保留，没有匹配时 as 字段是空数组，而不是主文档被丢弃。
- **性能前提**：每条主文档都要去目标集合查一次，foreignField 上必须有索引。

先准备一个用户集合，注意王五没有注册：

```js
db.users.insertMany([
  { _id: 101, name: "张三", vip: true },
  { _id: 102, name: "李四", vip: false }
]);
```

把订单关联出用户信息，王五的订单将得到空数组：

```js
db.orders.aggregate([
  { $match: { _id: { $in: [1, 4] } } },
  { $lookup: { from: "users", localField: "user", foreignField: "name", as: "userInfo" } },
  { $project: { _id: 1, user: 1, item: 1, userInfo: 1 } }
]);
```

```text
[
  {
    _id: 1,
    user: '张三',
    item: '键盘',
    userInfo: [ { _id: 101, name: '张三', vip: true } ]
  },
  {
    _id: 4,
    user: '王五',
    item: '键帽',
    userInfo: []
  }
]
```

> 订单 4 的用户王五不在 users 集合里，输出中 userInfo 是空数组而订单本身保留，这正是左外连接区别于内连接的地方。$lookup 还有传入 pipeline 的管道形式，适合关联条件带运算、或需要先筛选目标集合再连接的场景。



#### $facet 多分支报表

**$facet**：是**把同一批输入文档并行送入多个子管道、一次扫描产出多份报表**的阶段，每个子管道互不影响。

- **结构**：每个分支是 $facet 里的一个字段，字段值为该分支自己的阶段数组，输出是一份包含全部分支结果的文档。
- **典型用法**：一次 aggregate 同时给出总量汇总、状态分布、价格 TOP 榜等多份口径不同的统计。
- **限制**：$facet 内部不允许再嵌套 $facet，分支内可用的阶段以只读统计类为主。

一份管道同时产出总览、状态分布与最贵商品榜：

```js
db.orders.aggregate([
  { $facet: {
      overview: [
        { $group: { _id: null, total: { $sum: 1 }, revenue: { $sum: { $multiply: ["$price", "$qty"] } } } }
      ],
      byStatus: [
        { $group: { _id: "$status", count: { $sum: 1 } } },
        { $sort: { count: -1 } }
      ],
      topPrice: [
        { $sort: { price: -1 } },
        { $limit: 2 },
        { $project: { _id: 0, item: 1, price: 1 } }
      ]
  } }
]);
```

```text
[
  {
    overview: [ { _id: null, total: 6, revenue: 2920 } ],
    byStatus: [
      { _id: 'paid', count: 4 },
      { _id: 'shipped', count: 1 },
      { _id: 'cancelled', count: 1 }
    ],
    topPrice: [ { item: '显示器', price: 1599 }, { item: '键盘', price: 299 } ]
  }
]
```

> $facet 的价值在于把多次独立 aggregate 合成一次集合扫描，输入相同而口径不同时优先考虑它。各分支拿到的输入完全一致，分支内加 $match 只影响该分支自身的输出，分支之间无法传递中间结果。



### 实战：订单按月统计

#### 需求拆解与阶段选型

**订单按月统计**：是**把已支付订单按下单月份归组，输出每月订单数、销售额与下单人数**的典型报表需求，一条五阶段管道即可完成。

- **$match 定口径**：只统计 paid 状态，放在最前，既减少流入数据又能用索引。
- **$group 定维度**：分组键用 $dateToString 把 createdAt 格式化成年月字符串，统计用 $sum 计数与求和，用 $addToSet 收集下单人。
- **$sort 与 $project 定呈现**：按月份升序排列，再把 _id 改名为 month 并用 $size 算出下单人数。

> 阶段选型的顺序透露了聚合的设计骨架：先定口径、再定维度、最后定呈现，绝大多数报表管道都遵循这个次序，差异只在分组键与累加器的选择上。



#### 完整管道与输出

**完整管道与输出**：是**把需求拆解中的五个阶段拼成一条可复制管道并给出实跑结果**的交付环节，$match 与 $sort 决定数据范围和顺序，$group 完成归组，$project 负责最终交付的字段形状。

```js
db.orders.aggregate([
  { $match: { status: "paid" } },
  { $group: {
      _id: { $dateToString: { format: "%Y-%m", date: "$createdAt" } },
      orderCount: { $sum: 1 },
      revenue: { $sum: { $multiply: ["$price", "$qty"] } },
      buyers: { $addToSet: "$user" }
  } },
  { $sort: { _id: 1 } },
  { $project: { _id: 0, month: "$_id", orderCount: 1, revenue: 1, buyerCount: { $size: "$buyers" } } }
]);
```

```text
[
  { month: '2026-01', orderCount: 2, revenue: 727, buyerCount: 2 },
  { month: '2026-03', orderCount: 2, revenue: 327, buyerCount: 2 }
]
```

> 二月没有出现：样例数据中二月唯一一笔订单状态是 shipped，被 $match 过滤，属于数据本来的口径而非管道出错。报表缺一块时先区分这两种情况——把管道截断到 $group 之前逐阶段核对数据流，是定位此类问题的标准动作。



#### 易错点与优化建议

**月度统计的易错点**：这类报表最常见的三个错误集中在时区、顺序与口径上，写管道前逐项对照。

- **时区偏移**：$dateToString 默认按 UTC 取年月，东八区晚八点后的订单会归入次月，需在表达式内传 timezone 为 +08:00。
- **忘记排序**：$group 的输出顺序不保证，报表管道结尾没有 $sort 时月份顺序会随机。
- **状态口径含糊**：统计前先明确是否含退款与取消，$match 的条件就是报表口径本身，口径变更要同步改管道。

> [!IMPORTANT]
> **重要内容**：聚合报表的可信度取决于 $match 的口径与日期取值的时区，两者都必须显式声明而不是依赖默认值。上线前用已知数据人工核对一两个月的数字，对不上时逐阶段截断管道排查，这两步能拦下绝大多数报表事故。
