## mongosh 基础与数据库操作

### 连接与帮助体系

#### mongosh 的连接方式

**mongosh 连接**：通过标准 MongoDB 连接串或命令行参数指定目标实例，不带参数时默认连接本机 27017 端口。

```bash
# 连接本机默认端口，进入 test 库上下文
mongosh

# 用连接串连接远程实例并直接进入指定库
mongosh "mongodb://shopUser:secret@192.168.1.20:27017/shop"

# 用参数形式连接本机
mongosh --host 127.0.0.1 --port 27017
```

- **连接串结构**：mongodb://用户名:密码@主机:端口/库名，库名决定进入外壳后的默认上下文，省略时为 test。
- **额外选项**：连接串尾部可接问号参数，如 replicaSet=rs0 指定副本集、authSource=admin 指定鉴权库。
- **断开方式**：交互界面输入 exit 或按 Ctrl+C 退出，连接串里的明文密码在共享命令记录前要清理。

> [!CAUTION]
> **注意内容**：连接串里的用户名密码是明文，出现在 shell 历史与日志里就等于泄露；生产环境用 --password 交互输入或配置文件传入凭据，避免把带密码的完整命令贴进文档与聊天记录。



#### 帮助命令体系

**帮助命令**：mongosh 内置三层帮助——外壳级 help、库级 db.help、集合级 db.集合名.help，忘了命令用法时直接输入帮助命令查看。

```js
help
```

```text
  db.help()                    help on db methods
  db.mycoll.help()             help on collection methods
  sh.help()                    sharding helpers
  rs.help()                    replica set helpers
  help administrative          administrative help
  help connect                 connecting to a db help
  help keys                    key shortcuts
  help misc                    misc things to know

  show dbs                     display the names of available databases
  show collections             print the collection names of current db
  show users                   print the users of current db
  show roles                   print the roles of current db
  show profile                 print system.profile information
  show log <name>              log out the last portion of 'log' file
  use <db_name>                set current db to <db_name>
  exit                         quit the mongo shell
```

```js
db.help()
```

```text
Database Class:

  getCollection                Get a collection
  getCollectionNames           Get all collection names
  getCollectionInfos           Get information about the collections
  createCollection             Create a collection
  runCommand                   Run a database command
  adminCommand                 Run an admin command against the admin database
  getSiblingDB                 Get another database on the same server connection
  stats                        Report statistics of the database
```

- **三层结构**：help 管外壳命令，db.help 管 database 对象的方法，db.goods.help 管集合的增删改查方法，一层比一层具体。
- **交互细节**：支持 Tab 补全方法名，方向键翻历史，输入方法名不带括号回车会直接打印方法的源码签名。

> 记不住命令不是问题，「db.help 先看一眼再写」是正确习惯；show 系列是外壳快捷命令，不是 db 对象的方法，写成 db.showDbs 会直接报错。



### 库级操作

#### use 与库的隐式创建

**use 切换与隐式建库**：use 命令把当前上下文切到指定库，库不存在时也直接切换成功，但空库不落盘——写入第一份数据后库才真正创建。

```js
use shop
db.goods.insertOne({ name: "鼠标", price: 79.9 })
```

```text
switched to db shop
{
  acknowledged: true,
  insertedId: ObjectId('6ab31680a1b2c3d4e5f60721')
}
```

- **db 变量**：use 之后，外壳里的全局变量 db 就指向当前库，db.goods 表示当前库下的 goods 集合。
- **隐式创建语义**：use 只改变上下文不创建任何对象，insertOne、createCollection 这类写入动作才是创建的触发点。
- **误写库名的代价**：use shops 与 use shop 是两个库，往拼错的库里写完数据才发现，属于最常见的脏数据来源。

> [!CAUTION]
> **注意内容**：MongoDB 没有先建库再使用的仪式，拼错库名不会报错而是静默创建一个新库；写完第一条数据后立刻 show dbs 核对库名，比事后修数据便宜得多。



#### show dbs 与可见范围

**show dbs 的可见范围**：命令只列出至少含有一份数据的库，刚 use 过但没写入的库不会出现。

```js
use temp
show dbs
```

```text
switched to db temp
admin   132.00 KiB
config   84.00 KiB
local    72.00 KiB
shop     40.00 KiB
```

- **temp 未出现**：上下文已在 temp，但没有写入任何数据，列表里没有它，证明空库不落盘。
- **admin 与 config 与 local**：三个系统库始终存在，分别承担鉴权数据、分片元数据与副本集内部数据。
- **体积列的含义**：数值是数据文件占用的大致体积，供快速判断，精确统计用 db.stats()。

> 判断「库到底存不存在」不能用 show dbs，要用 db.getName() 或看提示符；show dbs 回答的是「哪些库有数据」，两者语义不同。



#### dropDatabase 删除当前库

**dropDatabase**：删除当前上下文的库及其全部分 collection，命令没有任何确认步骤，删除立即生效。

```js
use temp
db.dropDatabase()
```

```text
switched to db temp
{ ok: 1 }
```

- **作用对象是 db 变量**：命令删的是当前库，执行前先看提示符确认上下文，在 shop 里执行就是删 shop。
- **无法撤销**：删除后数据不可恢复，除非有最近的备份或副本集里还有未同步的节点。
- **执行环境差异**：分片集群上 dropDatabase 还涉及元数据清理，主从之间短暂不一致时可能看到库「复活」，需在主节点确认。

> [!WARNING]
> **警告内容**：dropDatabase 是即时生效且不可回滚的破坏性操作，生产库上执行前必须先确认提示符的库名与连接串指向的环境，把「use 正确的库」作为敲下回车前的最后一步检查。



### 集合级操作

#### 集合的隐式创建

**隐式创建**：直接向不存在的集合写入数据，服务端自动创建集合，这是 MongoDB 默认的建集合方式。

```js
db.goods.insertMany([
  { name: "键盘", price: 199 },
  { name: "显示器", price: 999 }
])
```

```text
{
  acknowledged: true,
  insertedIds: {
    '0': ObjectId('6ab31680a1b2c3d4e5f60722'),
    '1': ObjectId('6ab31680a1b2c3d4e5f60723')
  }
}
```

- **零 DDL**：goods 集合此前不存在，写入即创建，配合文档模式灵活，业务迭代不需要改表脚本。
- **代价**：集合名拼错同样静默建出新集合，shop 库里可能同时存在 goods 与 good 两个集合。
- **适用判断**：普通文档集合隐式创建即可；固定集合与视图必须显式创建。

> 隐式创建把「建集合」融进写入路径，灵活的另一面是没有拼名校验；代码里把集合名抽成常量统一引用，是抵御拼错的最简单手段。



#### show collections 与显式创建

**查看与显式创建**：show collections 列出当前库的全部集合，db.createCollection 方法在写入前预建集合，供需要特殊属性的场合使用。

```js
show collections
db.createCollection("logs")
show collections
```

```text
goods
{ ok: 1 }
goods
logs
```

- **输出顺序**：第一次 show collections 只有 goods，createCollection 返回 ok 为 1 后再查，logs 出现在列表末尾。
- **显式创建的场景**：建固定集合（capped，指定上限自动淘汰旧文档）、建视图（viewOn 加 pipeline）、需要在分片集群预分配。
- **等价路径**：普通集合用隐式创建即可，显式创建不带来额外性能收益。

> 记住一条分界线：需要「集合本身有属性」时才用 createCollection，只为存数据时直接 insert；用 show collections 验证建没建成功，比靠记忆可靠。



#### 删除集合

**删除集合**：用集合对象的 drop 方法删除集合与其中全部文档，返回布尔值表示是否删除了已存在的集合。

```js
db.logs.drop()
db.logs.drop()
```

```text
true
false
```

- **返回值语义**：第一次 drop 集合存在返回 true，第二次集合已不存在返回 false，不会报错。
- **与 dropDatabase 的差别**：drop 只删一个集合，库与其他集合不受影响，破坏半径小得多。
- **索引一并删除**：集合上的索引随集合一起消失，重建集合后索引需要重新创建。

> 批量清理测试集合时，drop 返回 false 可当作「集合本来就不存在」的信号写入脚本逻辑；生产环境删集合前先 countDocuments 留个记录，出问题时至少知道删了多少数据。



### mongosh 的 JavaScript 环境

#### 与 Node.js 同源的运行时

**运行时本质**：mongosh 是基于 Node.js 的交互式 REPL，JavaScript 的语法、标准库与异步模型全部可用，db 对象是注入的全局变量。

- **全局变量 db**：指向当前库，getSiblingDB 可在不退出会话的情况下跨库操作，如 db.getSiblingDB("admin")。
- **标准 JS 可用**：const 与 let 声明、数组 map 与 filter、JSON.stringify、Math 对象都能直接使用。
- **会话内持久**：变量在整个会话期间存活，切换库不影响已赋值的变量，退出会话即清空。

```js
const doc = db.goods.findOne({ name: "鼠标" })
console.log(doc.name, doc.price)
```

```text
鼠标 79.9
```

> [!TIP]
> **建议内容**：把 mongosh 当「带数据库连接的 Node.js 终端」理解，查询结果就是普通 JS 对象，可以在外壳里直接加工——取字段、算合计、格式化输出都不需要导出到别的工具。



#### 异步命令与自动结果解析

**异步语义**：数据库命令本质是异步调用，mongosh 自动等待 Promise 完成并把结果以 JS 对象形式直接打印，多数场合不需要手写 await。

```js
db.goods.find({ price: { $gt: 500 } })
```

```text
[
  {
    _id: ObjectId('6ab31680a1b2c3d4e5f60723'),
    name: '显示器',
    price: 999
  }
]
```

- **自动解析**：find 返回的游标、insertOne 返回的确认对象都会被外壳自动 await 后打印，等价于每次都写了 await。
- **游标的惰性**：find 不加遍历时不会立即拉全数据，第一次访问结果才触发查询，配合 it 迭代下一批。
- **显式 await**：在脚本模式或需要严格控制顺序时写 await db.command(...)，语义与自动解析一致。

> 写惯 Node.js 的人容易在这里「多此一举」，外壳里直接写命令即可；但在 load 加载的脚本里混合多条写入时，保持显式 await 的习惯可避免顺序依赖问题。



#### 脚本加载与批处理

**脚本化**：mongosh 可执行 JS 脚本文件，交互外壳里用 load 加载，命令行用 --file 批量执行，是初始化数据与定时任务的常用通道。

```js
// seed.js：批量写入初始化数据
const brands = ["西子", "苏堤", "断桥"];
for (let i = 0; i < brands.length; i++) {
  db.goods.insertOne({ name: brands[i] + "鼠标垫", price: NumberDecimal("9.90") });
}
print("初始化完成");
```

```bash
# 命令行直接执行脚本文件
mongosh "mongodb://127.0.0.1:27017/shop" --file seed.js

# 单条命令即时执行，不进入交互界面
mongosh shop --eval "db.goods.countDocuments()"
```

```text
初始化完成
3
```

- **--file 与 --eval 的分工**：--file 跑整段脚本，--eval 跑单条表达式，都不进入交互界面，执行完即退出。
- **连接串决定 db**：脚本里的 db 指向连接串中指定的库，脚本文件里不需要也不应该写 use。
- **print 与 console.log**：脚本模式下的输出都走标准输出，print 是外壳传统写法，两者等效。

> [!TIP]
> **建议内容**：重复执行的初始化、数据订正、巡检统计都值得沉淀成脚本文件，用 --file 跑比在交互界面里粘代码更可追溯；脚本开头打印目标库名与时间戳，留下执行痕迹。
