## OIDC 与 JWT 深入

本篇聚焦 OIDC 与 JWT 的理论：ID Token 的认证语义、JWT 的结构验签与作废难题。JWT 的签发、验证、刷新令牌以及 Cookie、Session 在 Node/Express 的落地实现（jsonwebtoken、cookie-parser、express-session），见 Node 主题第 31 篇 身份认证：Cookie、Session 与 JWT。

### OIDC：在 OAuth 2.0 上补「认证」

#### ID Token 与认证语义

**OpenID Connect（OIDC）**：构建在 OAuth 2.0 之上的**认证**层——授权服务器在发令牌时额外签发 ID Token，向客户端声明「这个用户是谁」。

- OAuth 2.0 的 access_token 是**资源方的通行证**，格式不透明、对客户端无语义，拿它判断「用户是谁」没有标准依据。
- OIDC 增加 **ID Token**：一个签名的 JWT，内含 `sub`（用户唯一标识）、`iss`（签发者）、`aud`（受众）、`exp`（过期时间）等标准声明，客户端**验签后直接得到身份**。
- 配套标准端点：`/authorize`（授权）、`/token`（发令牌）、`/userinfo`（取用户信息）、`/.well-known/openid-configuration`（元数据发现）。

> 「用 OAuth 2.0 做登录」的完整表述是「用 OIDC 做登录」：**授权码流程发令牌是 OAuth 2.0 的事，ID Token 声明身份是 OIDC 的事**。接入微信、Google、GitHub 登录时对接的就是它们的 OIDC 端点。

**速记**：OIDC＝**OAuth 2.0＋ID Token**，access_token 访资源、ID Token 声身份。



### JWT

#### 结构与验签

**JWT（JSON Web Token，RFC 7519）**：三段 Base64URL 编码用点连接——头部（算法）、载荷（声明）、签名，签名保证内容不可篡改。

```text
eyJhbGciOiJIUzI1NiJ9   .   eyJzdWIiOiIxMDAxIn0   .   SflKxwRJ...
        头部（HS256）            载荷（sub:1001）         签名

验签：服务端用密钥对「头部.载荷」重新计算签名，与第三段比对
```

- **只防篡改、不加密**：载荷 Base64 解码即可读，**严禁放入密码、身份证号等敏感明文**。
- **验证清单**：签名、`exp`（过期）、`iss`（签发者）、`aud`（受众为本服务）、`nbf`（生效时间）——只验签名不验声明，等于白验。
- **HS256 与 RS256**：对称密钥（HS256）签发与验证同钥，适合单体；非对称（RS256）私钥签、公钥验，**资源服务器无需持有签发能力**，微服务与第三方接入的标准选择，公钥经 JWKS 端点分发。

> JWT 的「自包含可信」来自签名数学，不来自保密——载荷里写的任何内容都应当作「公开可见但不可伪造」来设计。权限声明（如角色列表）放进去可以，但要有「声明过期后重新签发」的机制，否则改了角色旧声明还管用。

**速记**：JWT **防篡改不加密**，验签＋五声明（exp/iss/aud/nbf/签名）一个不能少，跨服务用 RS256。



#### JWT 的作废难题

**无状态的反面**：签名有效期内 JWT 无法单方面失效，退出登录、封号、改密都碰不到已签发的令牌。

- **短有效期＋Refresh 轮换**（第 1 章）：把危害窗口压到分钟级，是所有方案的基座。
- **黑名单**：注销或封号时把 Token 标识（`jti` 声明）存入 Redis，验证时查表——回归有状态，但只需存「被作废的少数」而非全部会话。
- **版本号校验**：用户记录里存 `tokenVersion`，密码修改时加一，JWT 载荷中的版本对不上即拒绝——一次改密作废该用户全部旧令牌。

> 三个手段不互斥：**短有效期是底线，版本号管「全量作废」类事件（改密、封号），黑名单管「单个令牌」类事件（登出单设备）**。全都要的做法成本也低——两个整数字段加一个 Redis 查询。

**速记**：作废三件套 **短有效期、版本号管全量、黑名单管单个**。

**警告内容**：JWT 验证代码中**必须显式限定允许的算法**。历史上大量库在攻击者把头部算法改为 `none`（无签名）时会直接放行——验签形同虚设。调用验证库时固定 `algorithms: ["RS256"]` 或 `["HS256"]`，绝不接受来自令牌头部的算法提示，这一行配置决定整个体系的存在意义。
