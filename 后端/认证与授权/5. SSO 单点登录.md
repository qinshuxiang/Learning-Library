## SSO 单点登录

### 同域与跨域

#### 问题的两种形态

**SSO（单点登录）**：一次登录，访问多个相互信任的系统。方案取决于各系统是否共享主域名。

- **同主域**（`oa.example.com` 与 `git.example.com`）：Cookie 可设 `Domain=.example.com` 共享，中心认证域 `sso.example.com` 验证登录后，各子系统自建会话——方案简单，一套 Session 存储即可。
- **跨主域**（`oa.company-a.com` 与 `git.company-b.com`）：Cookie 隔离，共享会话的通道不存在，必须走**中心认证服务＋重定向协议**（CAS 流程或 OIDC，第 3 章）。
- 判断标准一句话：**浏览器愿不愿意把 Cookie 带过去**——愿意就同域方案，不愿意就走协议。

> 同域共享 Cookie 看似省事，但把所有子系统的登录态绑在同一个 Cookie 上：一处 XSS 拿到 Cookie 即全域沦陷。安全要求高的系统即使同域，也推荐走标准协议方案——**方案的一致性比省一个重定向更值钱**。

**速记**：同主域 **Cookie 共享**、跨主域 **协议跳转**，安全要求高时统一走协议。



### 跨域 SSO 流程

#### CAS 式重定向与 OIDC 落地

**中心认证流程**：所有子系统不自己验密码，未登录的请求统一被重定向到认证中心，认证完成后再带着凭证回来。

```text
1. 用户访问子系统 A → A 无本地会话 → 302 到认证中心（带回 returnUrl）
2. 认证中心已有全局会话（Cookie 在认证中心域下）→ 直接发凭证
   若无全局会话 → 展示登录页 → 登录成功后建全局会话
3. 回到子系统 A 并附上票据（CAS 的 ticket / OIDC 的 code）
4. A 用票据在服务端向认证中心换取身份 → 建立 A 自己的会话
5. 用户再访问子系统 B → 跳到认证中心 → 全局会话已在 → 免登录返回
```

- **两层会话是机制核心**：认证中心持有**全局会话**（决定「要不要再输密码」），各子系统持有**本地会话**（决定「能不能直接访问」）。第一次登录两层都建，之后访问新系统只建本地层，用户无感。
- **OIDC 就是这套流程的标准化**：第 2 章的授权码流程里，步骤 4 换的是 code 换令牌，凭证换成 ID Token。接入自建认证中心或第三方（微信、企业微信、Google）是同一套代码结构。
- **统一登出**：子系统登出需通知认证中心销毁全局会话，并广播其他子系统销毁本地会话（OIDC 的 `front-channel/back-channel logout`）——登出同步是最常被遗漏、也最常被审计点名的环节。

> 子系统的本地会话有效期**必须短于认证中心的全局会话**：全局会话决定了「多久重新认证一次」，本地会话只决定「多久回认证中心确认一次」。两者倒置会导致认证中心已销毁会话、子系统还在放行的窗口。

**速记**：SSO＝**中心全局会话＋子系统本地会话**，OIDC 是流程的标准封装，登出同步别漏。

**警告内容**：SSO 让认证中心成为**全局单点**：它宕机，所有子系统新登录全部失效。高可用设计（多实例＋共享存储）之外，本地会话在认证中心不可用时的宽限策略（已认证会话短期内允许继续、新登录拒绝）要提前设计——「认证中心一抖、全公司无法办公」是 SSO 上线后最常见的故障报告。
