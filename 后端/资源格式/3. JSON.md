## JSON

### JSON 的定义与语法

#### 什么是 JSON

**JSON（JavaScript Object Notation）**：一种基于键值对的**轻量级文本数据交换格式**，源自 JavaScript 的对象字面量语法，现行标准是 RFC 8259。

- 顶层只能是一个**对象**（花括号包住）或一个**数组**（方括号包住）。
- 对象是无序的键值对集合：键必须是双引号字符串，键值之间用冒号。
- 数组是有序的值集合，值之间用逗号，元素类型可以混搭。
- 相比 CSV，JSON 能表达**嵌套层级**：对象里套数组、数组里套对象，理论深度无限。

```json
{
  "案号": "A2026-001",
  "状态": "在办",
  "当事人": ["张三", "李四"],
  "期限": { "受理日": "2026-09-01", "办结期限": "2026-11-01" }
}
```

> [!IMPORTANT]
> **重要内容**：JSON 与 Excel 表格的**结构鸿沟**在于嵌套：表格是规整的行与列，JSON 的当事人字段是一个数组、期限字段是一个子对象——铺平成表格必然遇到“一格多值”与“列不齐”的问题。理解嵌套，才能理解导入时为什么要“展开记录”“展开列表”。



#### 六种值类型

**JSON 的值只有六种类型**，没有日期、没有二进制、没有注释：

- **string**：双引号字符串，转义序列包括 \"、\\、\/、\b、\f、\n、\r、\t 与 \uXXXX。
- **number**：十进制数字，不支持前导零（01 非法）、不支持十六进制、不支持 NaN 与 Infinity。
- **boolean**：true 或 false，全小写。
- **null**：表示空值，全小写。
- **object**：花括号键值对。
- **array**：方括号值列表。

```json
{
  "编号": "001",
  "件数": 12,
  "已办结": false,
  "协办人": null
}
```

> [!WARNING]
> **警告内容**：JSON 语法四条红线：**字符串必须双引号**（单引号非法）；**最后一个成员后面不能有逗号**（尾逗号非法）；**不支持注释**（// 与 /* */ 都非法）；**键必须加双引号**（裸键非法）。手工编辑 JSON 后解析报错，先按这四条排。



### Excel 与 JSON 的互转

#### 导入：Power Query 逐层展开

**Excel 导入 JSON 的唯一正路是 Power Query**：路径为数据 → 获取数据 → 从文件 → 从 JSON。

- 加载后进入查询编辑器，顶层显示为一条 Record（对象）或一列 List（数组）。
- Record 点击**展开按钮**变成若干行；数组点击**转到列表**再逐层处理。
- 每层嵌套都要手动点一次展开：嵌套几层就展开几轮，字段多时勾选“选择列”。
- 展开完成后关闭并上载至工作表，后续刷新时自动重跑整个流程。

```json
[
  { "姓名": "张三", "电话": "13800138000", "住址": { "区县": "临县", "详址": "南塔社区" } },
  { "姓名": "李四", "电话": "13900139000", "住址": { "区县": "临县", "详址": "凤凰社区" } }
]
```

> 这段数据的导入路径：顶层是数组 → 转换为表 → 值列展开 Record → 出现姓名、电话、住址三列 → 住址列再展开一层 Record → 区县、详址成为独立列。**嵌套几层就展开几轮**，展开顺序决定列名前缀（如 住址.区县）。



#### 导出与生成

**Excel 没有内置的“另存为 JSON”**，常规做法有三种：

- **Power Query 反向生成**：把表格转成 JSON 输出，适合固定格式的报送数据。
- **程序转换**：用 VBA、Python（pandas 的 to_json）或在线工具把导出的 CSV、XLSX 转成 JSON。
- **手工编写**：数据量小、结构简单时直接按目标系统的字段要求手写，配合校验工具确认。

> [!TIP]
> **建议内容**：给对接系统**报送 JSON 前，先用校验工具（如 JSON 校验网站或编辑器插件）验一遍语法**，再核对字段名的大小写与拼写——系统接口对字段名是精确匹配的，companyName 与 company_name 差一个字母就是整批退回。



### 编码与常见坑

#### UTF-8 与转义

**JSON 标准要求 UTF-8 编码**，中文有两种合法写法：

- 直接写 UTF-8 中文字符（现代主流，文件可读）。
- 写 \uXXXX 转义序列（如 “\u5f20\u4e09” 即 “张三”），部分老系统导出会用。

```json
{
  "姓名": "\u5f20\u4e09",
  "备注": "第一行\n第二行"
}
```

- 两种写法**等价**，解析结果相同；文件乱码时确认编码是否为 UTF-8（无 BOM）。
- 字符串内的换行必须写 \n 转义，**不能直接回车**；反斜杠本身写 \\。
- BOM 问题：部分老解析器不接受带 BOM 的 UTF-8 JSON 文件，报错“非法字符”时先去 BOM。

> [!CAUTION]
> **注意内容**：手工编辑 JSON 的三类高频事故是**中文引号、尾逗号与真换行**：从 Word 或网页复制来的内容常带全角引号“”，字符串里直接敲回车会破坏结构。编辑 JSON 用代码编辑器（语法着色即时暴露错误），不要用记事本与 Word。



#### JSON 与 CSV 的选型

选型取决于数据形状与对方要求，二维台账用 CSV，层级结构用 JSON。

- **结构规整、列数固定**的台账数据：CSV，Excel 打开即用。
- **字段嵌套、一对多关系**（一个案件多个当事人）：JSON，结构保真。
- **对方系统指定**：接口给什么收什么，没有选型余地。
- 两者互转有损：JSON 铺平成 CSV 会把嵌套压成重复行或拼接文本，CSV 转 JSON 则需要人为指定哪些列是键哪些列是值。

> [!IMPORTANT]
> **重要内容**：**格式跟随数据形状**：二维表格选 CSV，层级结构选 JSON，打印遗留选 PRN。强行用 CSV 装嵌套数据（如把数组写成“张三；李四；王五”塞进一格），等于放弃格式自描述能力，下游每个环节都要重新约定拆分规则。
