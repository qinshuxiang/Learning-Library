## 变量、游标与流程控制

### 四类变量

#### 变量体系总览

**MySQL 有四类变量**：作用域与生命周期是区分它们的三把尺。

- 系统变量：服务器配置，@@ 前缀，分 GLOBAL 与 SESSION 两级
- 状态变量：只读的性能计数，@@GLOBAL.status 或 SHOW STATUS
- 用户变量：会话级自定义，@ 前缀，会话内存活
- 局部变量：过程体内 DECLARE，块级作用域

> 四类变量混用的根源是前缀可省略：SET x = 1 在过程体内会先找局部变量再找用户变量。显式写 @ 或 DECLARE 清楚，别让阅读者猜作用域。

**速记**：**系统 @@ 管配置，用户 @ 存会话，局部 DECLARE 在块内**。



#### 系统变量的查看与设置

**系统变量是服务器的配置面**：GLOBAL 管全局，SESSION 管当前会话。

- 查看：SELECT @@session.autocommit 或 SHOW VARIABLES LIKE 'innodb%'
- 会话级设置：SET SESSION 变量 = 值，只影响当前连接
- 全局级设置：SET GLOBAL 变量 = 值，影响之后的新连接
- 持久化：SET PERSIST（8.0）写入配置，重启不丢

> 改 GLOBAL 不影响已存在的连接，是新手高频困惑：改了 long_query_time 自己的会话还是老值。要么重连，要么同时改 SESSION。多数变量改 GLOBAL 前先评估是否需要重启生效。

**速记**：**SESSION 只管自己，GLOBAL 管新连接，PERSIST 才扛重启**。

```sql
SHOW VARIABLES LIKE 'long_query_time';
SET SESSION long_query_time = 0.5;
SET PERSIST max_connections = 500;
```



#### 用户变量与局部变量

**用户变量跨语句存活于会话，局部变量只在块内**：选型看生命周期需求。

- 用户变量：SET @total = 100，或 SELECT 列 INTO @v
- 用户变量无需声明类型，赋什么是什么
- 局部变量：DECLARE v INT DEFAULT 0，类型明确，速度快
- 局部变量只能出现在过程、函数、触发器体内

> 用户变量在普通 SQL 会话里做临时计算很顺手（编号、累计），但它削弱语句的可重入性：语句结果依赖变量初值。工程查询慎用，探索性分析随意。

**速记**：**@ 临时顺手，DECLARE 类型严谨，跨语句才用 @**。

```sql
SET @rank = 0;
SELECT id, @rank := @rank + 1 AS rn FROM scores ORDER BY score DESC;
-- 窗口函数时代，此类需求优先 ROW_NUMBER()
```



### 游标

#### 游标四步曲

**游标把结果集变成逐行可遍历**：声明、打开、取值、关闭四步缺一不可。

- DECLARE 游标名 CURSOR FOR 查询语句
- OPEN 游标名：执行查询，游标指向首行前
- FETCH 游标名 INTO 变量：取当前行并前进
- CLOSE 游标名：释放资源
- 取完后再 FETCH 触发 NOT FOUND，靠句柄捕获

> 游标是逐行处理的最后手段，「能集合不逐行」的铁律见篇末专节；逐行 FETCH 的开销在千万行级是灾难，在几十行的维护脚本里无所谓。

**速记**：**声明开取关，逐行爬集合能干就别爬**。

```sql
DECLARE cur CURSOR FOR SELECT id, name FROM tmp_users;
OPEN cur;
read_loop: LOOP
    FETCH cur INTO v_id, v_name;
    IF v_done = 1 THEN LEAVE read_loop; END IF;
    -- 逐行处理
END LOOP;
CLOSE cur;
```



#### 声明顺序与 NOT FOUND 句柄

**DECLARE 的顺序是语法强制**：变量、游标、句柄必须依次排列。

- 普通变量声明在前，游标居中，HANDLER 收尾
- 顺序错乱直接报错，不是警告
- DECLARE CONTINUE HANDLER FOR NOT FOUND SET v_done = 1 是标准套路
- HANDLER 在 ANY 游标 FETCH 失败时触发，多游标需自行区分

> 标准循环骨架的完整模板见综合运用一节；这里注意多游标场景：一个 NOT FOUND 句柄会让所有游标共享标志，需要用 RESET 或改用 EXIT HANDLER 分块。

**速记**：**变量游标句柄排三段，NOT FOUND 置标志跳出**。



### 流程控制

#### IF 与 CASE 语句

**IF 与 CASE 是块内的分支语句**：与同名表达式的区别在位置与形态。

- IF 条件 THEN ... ELSEIF ... ELSE ... END IF
- CASE 表达式形态：CASE v WHEN 1 THEN ... END CASE，做等值分发
- CASE 搜索形态：CASE WHEN 条件 THEN ... END CASE
- 都是语句（要 END IF 或 END CASE），不是表达式

> 过程体内的 IF 用于控制流，SELECT 里的 CASE 用于取值；两者长得像但生活场景不同。写混的直接报语法错，编译器会替你把关。

**速记**：**IF 条件链，CASE 值分发，END 不能省**。

```sql
IF v_score >= 90 THEN
    SET v_grade = 'A';
ELSEIF v_score >= 60 THEN
    SET v_grade = 'B';
ELSE
    SET v_grade = 'C';
END IF;
```



#### 三种循环与跳出

**LOOP、WHILE、REPEAT 覆盖三种循环语义**：跳出与继续用 LEAVE、ITERATE。

- LOOP：无条件循环，必须配 LEAVE，否则死循环
- WHILE 条件 DO ... END WHILE：先判后做，可能零次
- REPEAT ... UNTIL 条件 END REPEAT：先做后判，至少一次
- LEAVE 标签跳出循环，ITERATE 跳过本轮继续下一轮

> 循环体必须能收敛：更新条件变量或 FETCH 推进游标，二者必居其一。给循环起标签是好习惯，LEAVE 跳多层嵌套时全靠它。

**速记**：**LOOP 配 LEAVE，WHILE 先判 REPEAT 后判，ITERATE 跳本轮**。

```sql
blk: LOOP
    SET v_i = v_i + 1;
    IF v_i > 100 THEN LEAVE blk; END IF;
    IF v_i MOD 2 = 0 THEN ITERATE blk; END IF;
    -- 只处理奇数
END LOOP blk;
```



### 综合运用

#### 逐行处理的完整模板

**变量、游标、句柄、循环拼成过程体的标准骨架**：可直接套用改写。

- 声明区：变量、游标、NOT FOUND 句柄按序排
- 循环体：FETCH 判退出，处理逻辑，继续下一轮
- 收尾：CLOSE 游标，返回统计
- 整个逻辑包在事务里，失败回滚

> 模板的价值在于让维护者一眼看清结构；在此基础上加业务逻辑，而不要发明新的控制流花样。超过两百行的过程体，优先考虑拆成多个过程。

**速记**：**三段声明一循环，事务包底，超长就拆**。

```sql
CREATE PROCEDURE sp_regrade()
BEGIN
    DECLARE v_done INT DEFAULT 0;
    DECLARE v_id BIGINT;
    DECLARE v_score INT;
    DECLARE cur CURSOR FOR SELECT id, score FROM students WHERE graded = 0;
    DECLARE CONTINUE HANDLER FOR NOT FOUND SET v_done = 1;

    OPEN cur;
    scan: LOOP
        FETCH cur INTO v_id, v_score;
        IF v_done = 1 THEN LEAVE scan; END IF;
        UPDATE students SET grade = CASE WHEN v_score >= 60 THEN 'P' ELSE 'F' END
        WHERE id = v_id;
    END LOOP scan;
    CLOSE cur;
END;
```



#### 能集合不逐行的铁律

**游标是性能下策，集合操作是首选**：动手前先问一句。

- 逐行 UPDATE 能改成一条 UPDATE 加 JOIN 吗？
- 逐行判断能改成 CASE 表达式或窗口函数吗？
- 复杂计算能先落临时表再集合更新吗？
- 只有依赖外部调用、状态机跳转等真逐行需求才用游标

> 一条 UPDATE 语句的行处理在引擎内完成，游标则把每一行都拉到 SQL 层往返一次，差距是数量级的。写游标前先尝试三次集合化改写，失败再用游标，不算浪费。

**速记**：**三试集合，败者才游标，差一个数量级**。
