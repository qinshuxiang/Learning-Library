## MyCat 管理与监控

### 管理端入口

#### 9066 是什么

**9066 是 MyCat 自己的管理端口**：不是 MySQL，只是一套伪装成 MySQL 协议的运维接口。

- 用 mysql 客户端连，账号密码取自 server.xml 的 user
- 命令以 `show @@` 开头，与 SQL 语法无关
- `reload` 系列命令支持不重启加载配置
- 生产上只对内网开放，公网暴露等于把路由配置交出去

```bash
mysql -h127.0.0.1 -P9066 -uroot -p123456
```

```sql
show @@help;          -- 全部可用命令
show @@version;       -- MyCat 版本
show @@database;      -- 逻辑库列表
show @@datanode;      -- 数据节点与所属主机
show @@datasource;    -- 真实库连接状态
```

> 9066 的命令没有事务、没有权限分级，能连上就是全权限。安全基线里这一条常被漏掉：8066 加了防火墙，9066 却监听在 0.0.0.0。

**速记**：**管理端只有 show @@，全权限无分级，只许内网连**。

#### 启停与配置重载

**改配置的正确姿势是 reload**：重启会断掉所有业务连接。

- `mycat start|stop|restart|status|console`，console 前台启动便于看日志
- `reload @@config` 重载 schema.xml 与 rule.xml，不断连接
- `reload @@config_all` 连 server.xml 一起重载，会重建连接池
- 新增或删除 dataNode 必须用 `config_all`，只 reload 不生效

```bash
/usr/local/mycat/bin/mycat restart
```

```sql
reload @@config;        -- 表结构、分片规则
reload @@config_all;    -- 含数据源，重建连接池
```

> reload 不是热更新的万能药：它会清空 SQL 缓存与部分统计，正在跑的长查询可能受影响。变更窗口选低峰，改完立刻用真实 SQL 验证落点。

**速记**：**改表改规则用 config，加节点用 config_all，验证落点别省**。

### 运行态观测

#### 节点与心跳

**节点状态看两处**：dataNode 是逻辑视图，heartbeat 是物理探活。

- `show @@datanode` 给出节点名、所属主机、当前连接数与负载
- `show @@heartbeat` 显示每个 writeHost/readHost 的存活与延迟
- 心跳语句来自 schema.xml 的 `heartbeat` 标签，通常是 `select user()`
- 从库心跳失败时，读请求会被降级到主库或直接报错，取决于 `switchType`

```sql
show @@datanode;
show @@heartbeat;
show @@datasource;
```

> 心跳失败但库是好的，多半是账号权限或网络 ACL 的问题：心跳用小账号跑，别用业务账号，否则业务改密会连带把心跳打挂。

**速记**：**节点看负载，心跳看存活，失败先查账号与网络**。

#### 连接与 SQL 统计

**连接与 SQL 是排障的两把尺**：一个看堵在哪，一个看慢在哪。

- `show @@connection` 看当前前端连接、所属用户、执行的 SQL 与耗时
- `show @@sql` 看最近执行的 SQL 列表与耗时
- `show @@sql.sum` 汇总按表的读写次数、返回行数
- `show @@sql.slow` 看超过阈值的慢 SQL，需开启 `useSqlStat`

```sql
show @@connection;
show @@sql;
show @@sql.sum;
show @@sql.slow;
```

> 统计功能默认关闭，`useSqlStat` 打开后有可观的内存与 CPU 开销。生产上按需开、限时开，别常态开着当监控用。

**速记**：**连接看现状，SQL 看历史，统计开关有成本**。

### 日志

#### 三类日志的分工

**MyCat 的日志分三层**：启动、运行、SQL。

- `logs/wrapper.log`：JVM 启停、启动异常，排查「起不来」的第一现场
- `logs/mycat.log`：运行日志与 SQL 执行记录，级别由 `log4j2.xml` 控制
- `logs/mycat.pid`：进程号，脚本靠它判活
- SQL 日志按天滚动，量大时注意磁盘水位

```xml
<!-- conf/log4j2.xml 里调整级别与滚动策略 -->
<Logger name="io.mycat" level="info" additivity="false">
    <AppenderRef ref="Console"/>
</Logger>
```

> 打开 debug 级别的 SQL 日志能让问题瞬间清晰，也能让磁盘瞬间满。排障时开、排完关，是基本纪律。

**速记**：**wrapper 管启动，mycat 管运行，debug 只开一时**。

#### 慢 SQL 与执行下推

**MyCat 的慢不一定是它自己的慢**：可能是下推的 SQL 在库里慢。

- 开启 `useSqlStat` 后 `show @@sql.slow` 给出超阈值语句
- 同一条逻辑 SQL 在 MyCat 侧可能被拆成多条，逐条看真实下推语句
- 慢点分布在单库时，去那个库的慢查询日志里找同一条（36 篇）
- 跨片聚合类查询慢，往往是广播到所有片再合并

```sql
-- MyCat 侧
show @@sql.slow;

-- 真实库侧，对照同一时间窗
SELECT * FROM mysql.slow_log ORDER BY start_time DESC LIMIT 10;
```

> 两层慢日志要对齐时间戳看：MyCat 记的是端到端耗时，库里记的是单条执行耗时。差值大说明时间花在网络与合并上，而不是 SQL 本身。

**速记**：**两端日志对时间，差值即中间件开销**。

### 监控平台

#### MyCat-eye 的定位

**MyCat-eye 是官方配套的监控台**：把 9066 的指标变成图表。

- 独立 Web 应用，依赖 ZooKeeper 做注册与配置
- 主要面板：SQL 监控、慢查询、连接池、JVM、物理库状态
- 部署成本不低：ZK 加 Web 容器，适合长期运维而非临时排障
- 轻量替代是自建采集：定时抓 9066 的输出落到时序库

```bash
# MyCat-eye 默认监听 8082，启动前先起 ZK
sh start.sh 8082
```

> 中间件监控容易做成摆设：图表很好看，但没人看。真正有效的是「连接池水位」与「慢 SQL 数」两个告警项，其余可以只看大盘。

**速记**：**eye 靠 ZK，重点看水位与慢 SQL，别堆指标**。

### 综合运用

#### 巡检与调优清单

**巡检抓五项，调优抓三项**：MyCat 的问题高度集中。

- 巡检：进程存活、8066/9066 端口、心跳全部正常、连接池水位、慢 SQL 数量
- 调优一：`maxCon` 与真实库 `max_connections` 的总和匹配，超配会把库打满
- 调优二：`balance` 决定读请求分配，从库延迟大时不能盲目分流
- 调优三：`switchType` 决定主库故障时的行为，默认自动切，需与运维流程对齐

```xml
<dataHost name="host1" maxCon="1000" minCon="10" balance="1"
          writeType="0" dbType="mysql" dbDriver="native" switchType="1">
```

> 连接池是最隐蔽的故障源：MyCat 侧 `maxCon=1000`，后端库 `max_connections=500`，两主两从加起来轻松超过上限，表现是偶发的「连接超时」而非稳定报错。

**速记**：**池子总和别超库上限，读分流看延迟，切换行为要对流程**。
