## MySQL 管理与常用工具

### 四个系统库

#### mysql 库

**mysql 库存账号与权限**：整个实例的访问控制都在这。

- `user`：账号、密码哈希、全局权限、连接数限制、SSL 要求
- `db`：库级权限；`tables_priv`、`columns_priv`：表级与列级权限
- `proxies_priv`：代理权限；`role_edges`：角色关系（8.0）
- 权限表改动后 `FLUSH PRIVILEGES` 才生效——用 GRANT 语句改则自动生效
- 还有时区表 `time_zone*`、字符集与排序规则表

```sql
SELECT user, host, plugin, account_locked FROM mysql.user;
SELECT * FROM mysql.db WHERE Db = 'shop'\G
```

> 直接 `UPDATE mysql.user` 改权限是事故高发动作：8.0 的账号管理走 `CREATE USER`/`GRANT`/`ALTER USER`，绕过语句改表容易漏字段（如 `plugin`、`password_expired`）。

**速记**：**user 管全局，db 管库，priv 表管表列**。

#### information_schema

**information_schema 是元数据字典**：所有对象的结构都能查。

- `TABLES`：表名、引擎、行数估算、数据与索引长度
- `COLUMNS`：列类型、是否可空、默认值、字符集
- `STATISTICS`：索引信息，含基数 `CARDINALITY`（判断区分度的依据）
- `PROCESSLIST`：当前连接，等价 `SHOW PROCESSLIST`
- `INNODB_TRX`：当前运行的事务；锁信息 8.0 已移到 performance_schema

```sql
SELECT TABLE_NAME, ENGINE, TABLE_ROWS,
       ROUND(DATA_LENGTH/1024/1024, 2) AS data_mb
  FROM information_schema.TABLES
 WHERE TABLE_SCHEMA = 'shop'
 ORDER BY DATA_LENGTH DESC;

SELECT INDEX_NAME, COLUMN_NAME, CARDINALITY
  FROM information_schema.STATISTICS
 WHERE TABLE_SCHEMA = 'shop' AND TABLE_NAME = 'tb_order';
```

> `TABLE_ROWS` 是估算值，InnoDB 上误差可达 30% 到 50%。要精确行数只能 `COUNT(*)`，要容量判断看 `DATA_LENGTH` 更靠谱。

**速记**：**TABLES 看体量，STATISTICS 看基数，行数是估算别当真**。

#### performance_schema

**performance_schema 是可观测性的底座**：等待、语句、锁全在这里。

- `events_statements_summary_by_digest`：按 SQL 模板聚合（48 篇）
- `data_locks` / `data_lock_waits`：8.0 的锁与等待关系（34 篇）
- `events_waits_summary_global_by_event_name`：全局等待事件，找 IO 与锁瓶颈
- `replication_*`：复制状态；`memory_summary_*`：内存分配画像
- 采集有开销，可通过 `setup_consumers` 关掉不需要的消费者

```sql
SELECT * FROM performance_schema.data_lock_waits\G
SELECT EVENT_NAME, COUNT_STAR, SUM_TIMER_WAIT/1e12 AS sec
  FROM performance_schema.events_waits_summary_global_by_event_name
 ORDER BY SUM_TIMER_WAIT DESC LIMIT 10;
```

> 8.0 把锁信息从 information_schema 搬到 performance_schema 是一次重要迁移：`INNODB_LOCKS`、`INNODB_LOCK_WAITS` 已移除，老脚本直接报错。迁移监控脚本时先改这两张表。

**速记**：**语句摘要看慢，data_locks 看锁，等待事件看瓶颈**。

#### sys 库

**sys 是人话版的 performance_schema**：视图封装，直接给结论。

- `sys.schema_unused_indexes`：从未被使用的索引（29 篇治理用）
- `sys.statement_analysis`：语句耗时排行
- `sys.innodb_buffer_stats_by_table`：各表占用缓冲池的比例
- `sys.session`、`sys.processlist`：连接与执行的增强视图
- 视图底层依赖 performance_schema，关闭 P_S 时 sys 大部失效

```sql
SELECT * FROM sys.schema_unused_indexes;
SELECT * FROM sys.statement_analysis LIMIT 10;
SELECT * FROM sys.innodb_buffer_stats_by_table LIMIT 10;
```

> 排障时优先用 sys，读得懂再下钻到 performance_schema。反过来做，往往在几十张原始表里迷路。

**速记**：**sys 是结论层，先看它再下钻**。

### 客户端与运维工具

#### mysql 客户端

**mysql 客户端不只是执行 SQL**：它还负责导入与批处理。

- `source file.sql` 在会话内执行脚本，比命令行重定向更灵活
- `\G` 竖排输出，宽表可读性远好于默认表格
- `--tee=file` 把会话输出同时写文件，排障留证
- `-e "SQL"` 直接执行并退出，适合脚本与定时任务
- `--local-infile=1` 才能用 `LOAD DATA LOCAL`

```bash
mysql -h127.0.0.1 -P3306 -uroot -p -e "SHOW STATUS LIKE 'Threads_connected'"
mysql -uroot -p shop --tee=/tmp/session.log
```

```sql
SOURCE /tmp/backup.sql;
SHOW CREATE TABLE tb_order\G
```

> `source` 遇错默认继续执行，脚本跑完看着成功但实际有失败语句。批量导入前加 `--force` 的反面——用 `mysql --batch --verbose` 或检查退出码确认。

**速记**：**source 跑脚本，\G 看宽表，tee 留现场**。

#### mysqladmin

**mysqladmin 管实例状态与生命周期**：不登客户端也能查。

- `status`：版本、线程数、查询数、慢查询数、运行时长
- `ping`：存活探测，脚本探活用它
- `variables` / `extended-status`：等价 `SHOW VARIABLES` / `SHOW STATUS`
- `processlist`：当前连接
- `shutdown`：干净关库，比 kill 进程安全

```bash
mysqladmin -uroot -p status
mysqladmin -uroot -p ping
mysqladmin -uroot -p extended-status | grep -i com_select
mysqladmin -uroot -p shutdown
```

```text
Uptime: 86400  Threads: 12  Questions: 1842301
Slow queries: 37  Opens: 1024  Flush tables: 3
Open tables: 128  Queries per second avg: 21.32
```

> 监控脚本用 `mysqladmin ping` 比 `SELECT 1` 更轻，但要注意：`ping` 只证明进程能握手，不代表库可读写。真实可用性探测仍需一条穿透存储层的语句。

**速记**：**status 看概览，ping 探活，shutdown 别 kill**。

#### mysqlbinlog 与 mysqlimport

**两个专用工具**：一个读日志，一个灌文件。

- `mysqlbinlog` 解析 binlog 为可读 SQL，支持按时间与位点截取
- `--start-datetime`/`--stop-datetime` 定位时间窗，`--start-position`/`--stop-position` 定位位点
- `mysqlimport` 是 `LOAD DATA` 的命令行封装，文件名需与表名一致
- 误删恢复的标准动作：全量备份 + binlog 回放到误操作前一刻（37 篇）

```bash
mysqlbinlog --start-datetime="2026-10-20 10:00:00" \
            --stop-datetime="2026-10-20 10:30:00" \
            /var/lib/mysql/mysql-bin.000003 > /tmp/inc.sql

mysqlimport -uroot -p --local shop /tmp/tb_order.txt
```

> `mysqlbinlog` 输出的是伪 SQL，含 `SET TIMESTAMP` 与 `BEGIN/COMMIT`，不能直接当普通脚本改。要过滤表或改写入库，加 `--verbose` 看注释或用 `--rewrite-db` 做库名映射。

**速记**：**binlog 按时间位点截，import 按表名灌文件**。

### 综合运用

#### 运维命令速查

**五类命令覆盖日常九成场景**：贴墙即可。

| 场景 | 命令 |
|---|---|
| 看连接与执行 | `SHOW PROCESSLIST`；`sys.session` |
| 看容量 | `information_schema.TABLES` |
| 看索引健康 | `sys.schema_unused_indexes`；`STATISTICS.CARDINALITY` |
| 看锁与等待 | `performance_schema.data_lock_waits` |
| 看复制 | `SHOW REPLICA STATUS` |
| 看日志 | `mysqlbinlog`；慢日志 + `mysqldumpslow` |

> 这张表的价值在于替代「翻收藏夹」：每条命令背后是一类问题。新人接手实例时，按表走一遍就能画出这个库的体检报告。

**速记**：**连接容量索引锁复制，五类齐了就是体检表**。
