## Linux 下的安装与初始化

### 三种装法

#### 选哪条路

**Linux 装 MySQL 有三条路**：包管理、官方仓库、二进制包。

- **发行版自带仓库**：版本旧（EL7 常见 5.7 甚至 MariaDB），不推荐上生产
- **官方仓库**：`yum` 或 `apt` 接入 MySQL 官方源，版本新、升级方便
- **通用二进制包**：`tar.gz` 解压即用，可控性最强，适合标准化部署
- 三条路的差别主要在「升级与依赖管理」，运行时行为一致

```bash
# 先确认系统与已装版本
cat /etc/os-release
rpm -qa | grep -i -E "mysql|mariadb"
```

> 先查 MariaDB：EL 系默认预装 `mariadb-libs`，与 MySQL 的 `mysql-community-libs` 冲突，不先卸载装不上。这个坑在每一台新机器上都会重演。

**速记**：**自带源太旧，官方源省心，二进制最可控**。

#### 官方仓库安装

**仓库安装的关键是换源与选版本**：

- EL 系：装 `mysql80-community-release-el7-*.rpm` 后 `yum install mysql-community-server`
- Debian 系：下载 `mysql-apt-config_*.deb` 交互选版本，再 `apt update && apt install mysql-server`
- 安装完成后服务名为 `mysqld`（EL）或 `mysql`（Debian）
- 首次启动自动初始化 datadir，root 临时密码写入错误日志

```bash
# EL7
rpm -ivh mysql80-community-release-el7-7.noarch.rpm
yum install -y mysql-community-server
systemctl enable --now mysqld

# Ubuntu
dpkg -i mysql-apt-config_0.8.29-1_all.deb
apt update && apt install -y mysql-server
```

> Debian 系安装时会用 `auth_socket` 做 root 认证，本地 `sudo mysql` 直接进，不需要密码。这与其他发行版行为不同，照抄别处的改密脚本会一头雾水。

**速记**：**EL 换 rpm 源，Debian 走 apt-config，服务名不同**。

### 二进制安装

#### 解压与用户

**二进制包的四步**：解压、建用户、建目录、初始化。

- 解压到 `/usr/local`，软链为 `/usr/local/mysql`
- 建不可登录的 `mysql` 用户与组，`datadir` 归它所有
- `datadir` 建议独立挂盘，权限 `750`
- 把 `bin` 加进 `PATH`，或用绝对路径调用

```bash
tar -xvf mysql-8.0.36-linux-glibc2.28-x86_64.tar.xz -C /usr/local/
ln -s /usr/local/mysql-8.0.36-linux-glibc2.28-x86_64 /usr/local/mysql

groupadd mysql
useradd -r -g mysql -s /bin/false mysql

mkdir -p /data/mysql && chown -R mysql:mysql /data/mysql
chmod 750 /data/mysql

echo 'export PATH=/usr/local/mysql/bin:$PATH' >> /etc/profile
```

> `useradd -s /bin/false` 是关键：数据库运行账号不应能登录系统。很多加固检查项就卡在这一条，事后改还要停库。

**速记**：**解压软链，建不可登录用户，数据目录独立挂盘**。

#### 初始化

**初始化只做一次**：生成系统表空间与临时密码。

- `mysqld --initialize --user=mysql`：生成随机 root 密码，写入错误日志
- `mysqld --initialize-insecure`：root 空密码，仅限内网学习环境
- 初始化前 `datadir` 必须为空，否则报错退出
- 初始化耗时与磁盘性能相关，几分钟到十几分钟

```bash
/usr/local/mysql/bin/mysqld --initialize --user=mysql \
  --basedir=/usr/local/mysql --datadir=/data/mysql

# 取临时密码
grep 'temporary password' /data/mysql/*.err
```

```text
2026-10-20T02:11:03.512 [Note] A temporary password is generated for root@localhost: kQ8!vT2mZx#p
```

> 临时密码里的特殊字符容易在复制粘贴时出错，尤其是 `#` 与 `!` 在 shell 中有含义。用单引号包住，或改用 `--initialize-insecure` 后立刻设强密码。

**速记**：**目录必须空，密码在 err 里，insecure 只给学习用**。

### 配置文件

#### my.cnf 的分层

**MySQL 配置有固定查找顺序**：后面的覆盖前面的。

- `/etc/my.cnf` → `/etc/mysql/my.cnf` → `$MYSQL_HOME/my.cnf` → `~/.my.cnf`
- 用 `--defaults-file` 可指定唯一配置文件，忽略其他
- 用 `mysqld --verbose --help | grep -A1 "Default options"` 查实际加载顺序
- `[mysqld]`、`[client]`、`[mysql]` 分组，客户端与服务端分开配

```ini
[mysqld]
basedir = /usr/local/mysql
datadir = /data/mysql
port = 3306
socket = /tmp/mysql.sock
pid-file = /data/mysql/mysql.pid
log-error = /var/log/mysql/error.log

character-set-server = utf8mb4
collation-server = utf8mb4_0900_ai_ci
default-storage-engine = InnoDB

max_connections = 500
innodb_buffer_pool_size = 4G
```

> 配置项写错不会报错只会被忽略：`innodb_buffer_pool_sise` 这种拼写错误，MySQL 启动时只给一条 Warning。改完必须 `SHOW VARIABLES` 逐项确认生效。

**速记**：**顺序覆盖，defaults-file 唯一，改完必查变量**。

#### 最小可用参数

**先配六项，再谈调优**：

- `datadir` 与 `basedir`：路径必须正确，否则起不来
- `socket`：本地连接用，路径要与客户端一致
- `character-set-server=utf8mb4`：避免中文乱码（6 篇）
- `log-error`：错误日志独立路径，纳入监控
- `innodb_buffer_pool_size`：单实例最重要的性能参数
- `max_connections`：与中间件、应用连接池的总和匹配

```sql
SHOW VARIABLES WHERE Variable_name IN
 ('datadir','socket','character_set_server',
  'innodb_buffer_pool_size','max_connections');
```

> 参数不是越多越好：网上抄来的几十行配置往往互相冲突，且没人知道为什么这么写。从六项最小集开始，每次改动都有明确目的与验证方法。

**速记**：**路径字符集日志，池子连接数，六项打底**。

### 启动与首次配置

#### systemd 托管

**二进制安装需要自己提供 unit 文件**：否则没有 `systemctl` 可用。

- 官方包里带 `support-files/mysql.server`，可复制到 `/etc/init.d/`
- 更推荐自写 `mysqld.service`，用 systemd 管理生命周期与日志
- `Type=notify` 让 systemd 等到服务真正就绪
- `LimitNOFILE` 要调大，否则高并发下报 too many open files

```ini
# /usr/lib/systemd/system/mysqld.service
[Unit]
Description=MySQL Server
After=network.target

[Service]
User=mysql
Group=mysql
Type=notify
ExecStart=/usr/local/mysql/bin/mysqld --defaults-file=/etc/my.cnf
LimitNOFILE=65535
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload
systemctl enable --now mysqld
systemctl status mysqld
```

> `LimitNOFILE` 是常被漏掉的一行：默认 1024，连接数一上来就报错，而错误日志里只写「Can't open file」，看不出是文件描述符不够。

**速记**：**unit 托管，notify 等就绪，文件描述符要放大**。

#### 安全初始化

**装完立刻做五件事**：这是公网暴露前的最低要求。

- 改 root 密码，`ALTER USER 'root'@'localhost' IDENTIFIED BY '强密码'`
- 删除匿名账号与测试库 `test`
- 限制 root 只从 localhost 登录
- 按业务建专用账号，只给必要权限（37 篇）
- 防火墙只放行应用服务器网段到 3306

```sql
ALTER USER 'root'@'localhost' IDENTIFIED BY 'Str0ng#Pass';
DROP DATABASE IF EXISTS test;
DELETE FROM mysql.user WHERE User = '';

CREATE USER 'app'@'10.0.1.%' IDENTIFIED BY 'App#Pass2026';
GRANT SELECT, INSERT, UPDATE, DELETE ON shop.* TO 'app'@'10.0.1.%';
FLUSH PRIVILEGES;
```

```bash
firewall-cmd --permanent --add-rich-rule='rule family=ipv4 source address=10.0.1.0/24 port port=3306 protocol=tcp accept'
firewall-cmd --reload
```

> `mysql_secure_installation` 能一次做完大部分步骤，但它不处理网段限制与专用账号。安全基线要落到脚本里，而不是靠每次装完记得手动跑一遍。

**速记**：**改密删匿名限来源，建专用号，防火墙按网段放行**。

### 综合运用

#### 安装验收清单

**装完不等于装好**：八项逐条验。

- `systemctl status mysqld` 为 active，且 `enable` 已设置
- 错误日志无 ERROR，临时密码已替换
- `SHOW VARIABLES` 确认关键参数生效
- 字符集为 utf8mb4，写入中文无乱码
- 远程连接测试通过，且只从允许的网段
- 数据目录在独立分区，磁盘水位有监控
- 备份任务已配置并跑通一次恢复（37 篇）
- 时区正确，`SELECT NOW()` 与系统时间一致

```sql
SELECT @@version, @@character_set_server, @@time_zone, NOW();
```

> 时区是最容易漏的一项：容器与云主机默认 UTC，业务写入的时间差 8 小时，事后修数据极痛苦。装完就设 `default-time-zone='+08:00'` 并验证。

**速记**：**服务参数字符集，远程磁盘备份时区，八项过完再上线**。
