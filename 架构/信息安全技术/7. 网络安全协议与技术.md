## 网络安全协议与技术

> **全章主脉**：**网络安全协议是信息安全属性在网络通信中的落地手段，它把加密、认证与完整性保护嵌入协议栈的不同层次**。全章先讲安全协议在**链路层、网络层、传输层、应用层**的落点与取舍规律，再展开**网络层的 IP 安全协议族**与**传输层的 TLS**，继而讨论**应用层安全协议与虚拟专用网**，然后落到**边界防护、检测响应与可用性保障**，最后归结到**无线安全、网络隔离、持续监测与零信任架构**。**密码算法与密钥管理见第 2 至第 5 篇，身份认证与访问控制见第 6 篇**；网络分层与报文传输原理见 计算机网络 主题，工程部署配置见 后端/Nginx 主题。

### 安全协议在网络分层中的落点

#### 各层安全机制与代表性协议

**安全协议的层次落点**是指**某一安全机制工作在网络体系结构的哪一层，从而保护该层及其以上各层的数据**；层越低，单次部署覆盖的流量越广。

- **链路层**：保护单段链路的点到点通信，代表机制是链路加密，无线侧则是 802.1X 接入认证与 Wi-Fi 保护接入各代。
- **网络层**：保护主机与网段之间的 IP 数据报，代表协议是**IP 安全协议族**（Internet Protocol Security，IPSec）。
- **传输层**：保护进程之间的连接，代表协议是**传输层安全**（Transport Layer Security，TLS）。
- **应用层**：针对具体应用协议加固，代表有**安全外壳**（Secure Shell，SSH）、**安全多用途互联网邮件扩展**（Secure/Multipurpose Internet Mail Extensions，S/MIME）与超文本传输安全协议（HTTPS）。

```text
应用层   SSH、S/MIME、HTTPS、安全电子交易（SET）   面向单个应用
传输层   TLS（历史名 SSL）                         面向进程间连接
网络层   IPSec：AH 与 ESP，IKE 协商密钥             面向主机与网段
链路层   链路加密、802.1X、Wi-Fi 保护接入各代       面向单段链路
```

> **辨析**：**层次即范围**——判断某协议能否保护某数据有两步：先定该协议所在层次，再看数据是否落在其保护范围之内；**下层协议天然保护上层，上层协议不保护下层**。

> **速记**：自下而上记「**链路管一段、网络管全程、传输管连接、应用管服务**」。



#### 下层保护的取舍规律

**下层保护的取舍规律**是指**在越下层保护，透明性越好、控制粒度越粗**——机制越靠近协议栈底部，对上层应用越透明，但越难区分具体应用、用户与字段。

- **透明性**：下层保护无需改造应用，浏览器、邮件与数据库客户端自动被覆盖；上层保护须逐个应用适配。
- **控制粒度**：网络层按地址与端口放行，粒度粗；应用层能识别用户、资源与字段，可做到最小权限。
- **可见性代价**：下层加密形成**加密管道**，中间设备看不到内容，检测类设备随之失效。

> [!WARNING]
> **警告内容**：**加密提升机密性的同时，必然降低网络侧的检测可见性**。全流量加密后，防火墙与入侵检测只能看到连接元数据；攻击者正把恶意内容藏进加密流量规避检查，故下层加密必须与端点检测配合。

> **速记**：取舍规律记「**越往下越透明、越往上越精细**」；选型先问「覆盖全部流量，还是只保护某个应用」。



### 网络层与传输层安全协议

#### 网络层安全：IP 安全协议族的组成

**IP 安全协议族**（Internet Protocol Security，IPSec）是工作在网络层、为 IP 数据报提供认证、完整性与机密性的一组协议，由**认证头**、**封装安全载荷**与**密钥交换**三部分构成。

- **认证头**（Authentication Header，AH）：只提供**数据源认证与完整性校验**，不加密。
- **封装安全载荷**（Encapsulating Security Payload，ESP）：同时提供**机密性、认证与完整性**，是部署中最常用的一员。
- **密钥交换**（Internet Key Exchange，IKE）：负责**协商安全参数、生成与更新会话密钥**，本身不保护数据。

> **辨析**：**AH 只认证不加密，ESP 既加密又认证**。只要求完整性且需保护 IP 首部时才单独用 AH；因 AH 与网络地址转换不兼容，现实中多以 ESP 承担保护。

> **速记**：**AH 管「真不真」、ESP 管「看不看得懂加真不真」、IKE 管「钥匙怎么给」**。



#### 传输模式与隧道模式

**传输模式**（Transport Mode）是**只对原 IP 数据报的载荷施加保护、保留原 IP 首部**的封装方式，**隧道模式**（Tunnel Mode）是**把整个原 IP 数据报封装进新数据报、由新 IP 首部承担路由**的方式。

- **传输模式**：保护范围是端到端，适合主机直连，开销小，但原 IP 地址对中间网络仍可见。
- **隧道模式**：保护范围是网关到网关，原报文连同原 IP 首部被整体保护，适合**站点间虚拟专用网**。
- **封装开销**：隧道模式新增一层 IP 首部与安全载荷首部，报文变长，对最大传输单元更敏感。

```text
隧道模式： [ 新 IP 首部 | ESP 首部 | 被保护的原报文 | ESP 尾与认证数据 ]
传输模式： [ 原 IP 首部 | ESP 首部 | 被保护的载荷 | ESP 尾与认证数据 ]
```

> [!WARNING]
> **警告内容**：**两种模式的差别不在加密算法，而在被保护的对象**。传输模式保护载荷、原 IP 首部裸露；隧道模式保护整个原报文、原 IP 首部被隐藏。问「哪种模式适合站点间 VPN」或「哪种模式隐藏内网地址」，都答隧道模式。

> **速记**：**传输模式保载荷、隧道模式套整包**；主机直连用传输，网关互联用隧道。



#### 传输层安全：TLS 的两层结构与握手

**传输层安全**（Transport Layer Security，TLS）是工作在传输层之上、为面向连接的应用提供机密性与完整性的协议，它分为**握手层**与**记录层**两层，前者建立安全参数，后者用参数保护数据。

- **握手层**：完成**算法协商、服务器认证与会话密钥协商**，是 TLS 的建路阶段。
- **记录层**：对上层数据做**分片、加密与完整性保护**，是 TLS 的运货阶段。
- **会话恢复**：为免每次重做完整握手，用会话标识或票据复用已协商参数，代价是恢复凭据泄露后攻击面扩大。
- **历史关系**：SSL 是早期名称，其后续标准更名为 TLS；**现代表述一律用 TLS，SSL 只作历史名**，版本与套件以最新发布为准。

```text
客户端 → 服务器   问候报文：支持的版本、套件、随机数
服务器 → 客户端   问候回应：选定版本与套件、随机数
服务器 → 客户端   证书报文：服务器证书，供客户端验证身份
客户端 → 服务器   密钥交换报文：客户端的密钥交换参数
双方     ←→        切换加密规格、握手完成：启用加密并校验握手
```

> [!CAUTION]
> **注意内容**：**证书验证与密钥交换是握手的两件不同的事**——证书解决「你在和谁说话」，密钥交换解决「怎么算出共同的密钥」。只换密钥不验证书，中间人可各自换一把密钥实现窃听。

> **速记**：握手三步记「**谈算法、验身份、换密钥**」；TLS 总记「**握手谈参数、记录运数据**」。



### 应用层安全协议与虚拟专用网

#### 应用层安全协议族

**应用层安全协议**是**针对具体应用协议逐一定制安全机制**的一类协议，它以贴合应用语义、控制粒度最细为特征，不以覆盖全部流量为目标。

- **安全外壳**（Secure Shell，SSH）：为**远程登录与文件传输**提供加密通道，替代明文远程登录协议。
- **安全多用途互联网邮件扩展**（Secure/Multipurpose Internet Mail Extensions，S/MIME）：为**电子邮件**提供签名与加密，解决邮件机密性与发件人认证。
- **安全电子交易**（Secure Electronic Transaction，SET）：面向**银行卡在线支付**的历史方案，已被现代支付标准取代，只作历史定位。

> **辨析**：**应用层安全协议是「一应用一方案」**，网络层与传输层则给出「一揽子方案」。问「为电子邮件提供机密性」答 S/MIME，问「为远程管理加密」答 SSH，问「为网页加密」答 HTTPS。

> **速记**：应用层三代表记「**SSH 管登录、S/MIME 管邮件、SET 管支付（历史）**」。



#### HTTPS 的实质与常见误解

**HTTPS 的实质是「HTTP over TLS」**，即在超文本传输协议与传输层之间插入 TLS，使网页请求与响应在加密通道中传输，并借服务器证书确认所访问站点的身份。

- **保护内容与范围**：保护传输途中的请求与响应不被窃听与篡改、验证站点身份；加密在客户端与服务器之间建立，中间设备只能看到连接元数据。
- **不做的事**：**不保护服务端存储的数据、不校验业务逻辑、不阻止注入类攻击**，也不保证站点本身可信。

> [!IMPORTANT]
> **重要内容**：**HTTPS 只保护传输，不保护服务端数据**。挂上证书的钓鱼站同样是 HTTPS；服务端被拖库、注入漏洞被利用，HTTPS 一概拦不住。看到加密标志只能推断「这条链路是加密的」，不能推断「这个站点是可信的」。

> **速记**：HTTPS 记「**加密在途、验证站点**」；逆向两句——**挡不了服务端漏洞，也挡不了恶意站点本身**。



#### 虚拟专用网的分类与隧道协议

**虚拟专用网**（Virtual Private Network，VPN）是**在公用网络上通过隧道与加密技术构建的逻辑专用网络**，按使用方式分**远程接入**与**站点到站点**两类，按隧道所在层次分网络层与传输层两类。

- **远程接入**：单个用户从外部接入内网，常见实现是承载于 TLS 之上的方案。
- **站点到站点**：两个固定网络之间的网关互联，常见实现是网络层的 IPSec 隧道模式。
- **隧道层次**：**网络层隧道**以 IPSec 为代表，保护全部 IP 流量、对应用透明；**传输层隧道**以承载于 TLS 之上的方案为代表，部署简单、可按应用粒度授权。
- **封装代价**：隧道首部使报文变长、**有效最大传输单元减小**，加解密另有时延与吞吐开销。

> [!WARNING]
> **警告内容**：**传统 VPN 隐含「进入内网即信任」的假设，这一假设已被放弃**。VPN 只解决通道加密与身份准入，接入后权限往往过宽，失陷终端可横向移动。**零信任网络访问**（Zero Trust Network Access，ZTNA）改为每次访问都按身份与策略逐项授权。

> **速记**：VPN 记「**远程接入按人、站点到站点按网**」；隧道记「**网络层管全流量、传输层管便捷接入**」。



### 边界防护、检测与可用性保障

#### 防火墙的三代技术与固有局限

**防火墙**（Firewall）是**部署在不同信任级别网络之间、按预设策略检查并过滤进出流量的安全设备**，按技术演进分**包过滤**、**状态检测**与**应用层网关**三代。

- **包过滤**：工作在网络层与传输层，按地址、端口与协议逐包放行，速度快，但只看首部不看内容。
- **状态检测**：跟踪连接状态，只放行属于已建立合法连接的报文，能拦截伪造回包，是当前主流。
- **应用层网关与下一代防火墙**：前者工作在应用层，代理并解析协议内容，安全最强、开销最大；后者把状态检测、应用识别、入侵防御与威胁情报整合到一台设备。
- **固有局限**：**不能防内部越权**（横向移动绕开边界）；**不能防加密流量内部的攻击**（看不到载荷）。

> **辨析**：**防火墙的能力边界由「它检查到哪一层次」决定**。包过滤查首部、状态检测查连接、应用层网关查内容，**层次越深越慢也越严**；凡「流量已放行、载荷不可见」的场景都是盲区。

> **速记**：三代记「**包过滤查头、状态检测查连接、应用网关查内容**」；盲区记「**管边不管里、管明不管暗**」。



#### 入侵检测与入侵防御

**入侵检测系统**（Intrusion Detection System，IDS）是**旁路监听并在发现攻击迹象后告警**的系统，**入侵防御系统**（Intrusion Prevention System，IPS）是**串联部署并在发现攻击时直接阻断**的系统，差别在于是否在链路中执行阻断动作。

- **特征检测**：匹配已知攻击指纹，**准确率高但查不出未知攻击**，依赖规则库更新。
- **异常检测**：先建立正常行为基线，偏离即告警，**能发现未知威胁但误报率较高**。
- **误报与漏报取舍**：阈值放宽则漏报多，收紧则误报多；串联阻断要求**极低误报**，否则拦断正常业务。
- **部署位置**：**网络型**看整体流量但看不到加密载荷；**主机型**看单机日志、文件与进程，最细但需逐台部署。

> [!IMPORTANT]
> **重要内容**：**检测与阻断是两件事**。IDS 是只看不拦的摄像头，IPS 是看了就拦的闸机。IPS 串接在网络路径上，误杀正常业务的可用性损失可能超过攻击本身，因此 **IPS 的规则通常比 IDS 更保守**。

> **速记**：**IDS 只看、IPS 又看又拦**；原理记「**特征查已知、异常查未知**」；部署记「**网络型看全局、主机型看细节**」。



#### 拒绝服务与常见攻击的防御方向

**拒绝服务攻击**（Denial of Service，DoS）是**以耗尽带宽、连接或计算资源为目的、破坏可用性**的攻击，由大量被控主机同时发起时称**分布式拒绝服务**（Distributed Denial of Service，DDoS），其防御遵循**「无法完全避免，只能降低影响」**的口径。

- **流量清洗**：把可疑流量牵引到清洗中心过滤后再回注，主要应对带宽型攻击。
- **限速与连接数控制**：限制单源速率、并发连接与半连接数量，缓解连接耗尽型攻击。
- **任播与就近吸收**：把同一地址在多地发布，让流量就近分散吸收，摊薄单点压力。
- **应用层慢速攻击**：以极慢速度发送合法请求长期占用连接，**特征上与正常慢用户无异，识别难度高**。
- **常见攻击定位**：嗅探与中间人靠加密与证书校验；ARP 欺骗靠静态绑定与动态 ARP 检测；DNS 劫持与投毒靠加密查询与解析验签；会话劫持靠传输加密与令牌绑定；跨站脚本与跨站请求伪造靠输出转义、内容安全策略与请求令牌；注入类攻击靠参数化查询与最小权限；供应链攻击靠来源可信与软件物料清单。

> [!CAUTION]
> **注意内容**：**拒绝服务攻击无法被彻底消除**。攻击方只需控制足够多的主机与带宽，防守方资源始终有限；正确目标不是挡住全部，而是**保证关键业务在攻击期间仍可用**并缩短恢复时间。

> **速记**：防御四招记「**洗、限、播、辨**」；口径记「**降影响，不承诺零中断**」。



### 无线安全、持续监测与零信任

#### 无线网络安全与网络隔离

**无线网络安全**的核心是**接入认证与空中接口加密**两件事，**网络隔离**是**通过物理或逻辑手段切断网络之间的直接连通**。

- **有线等价保密协议**（Wired Equivalent Privacy，WEP）：早期无线加密方案，因密钥与初始化向量缺陷**已被证明可被快速破解**，只作历史教训。
- **Wi-Fi 保护接入二代与三代**（Wi-Fi Protected Access 2、3，WPA2、WPA3）：**WPA2** 引入更强的加密与完整性机制，**WPA3** 进一步强化握手认证与抗离线猜测能力。
- **企业级与个人级认证**：**企业级**基于 802.1X 与证书，为每个用户分配独立凭据、可吊销；**个人级**用预共享密钥，一人泄露即全体失守。
- **物理隔离与逻辑隔离**：**物理隔离**指无任何物理连接，**逻辑隔离**用虚拟局域网与访问控制限制可达性；**网闸**与**单向导入**用于隔离环境间受控的有限方向数据交换。

> [!WARNING]
> **警告内容**：**隔离环境下的数据交换是风险最集中的环节**。只要允许数据跨域流动，就要面对**格式伪装、内容夹带与协议漏洞**三类风险。把隔离理解为绝对安全是常见误判——隔离的含义是「没有直接连接」，而非「不需要检查」。

> **速记**：无线记「**认证加加密**」，代际记「**WEP 已破、WPA2 主流、WPA3 更强**」；隔离记「**物理断连接、逻辑控可达**」。



#### 安全运营中心与威胁情报

**安全运营中心**（Security Operations Center，SOC）是**以持续监测、分析与响应为核心职能的安全组织与平台**，其技术支撑是**安全信息与事件管理系统**（Security Information and Event Management，SIEM）与**威胁情报**。

- **安全运营中心**：集中人员、流程与工具，负责全天候监视告警、研判事件、处置与复盘。
- **安全信息与事件管理系统**：汇集多源日志并做关联分析与告警，解决设备各自告警、无人串联的问题。
- **威胁情报**：提供攻击者、攻击手法与失陷指标等外部知识，使检测从「见过才防」前移到「未见过也能推断」。

> **辨析**：**从被动防御转向持续监测与响应，是安全体系成熟度的分水岭**。设备能防住已知威胁，却防不住未知威胁与已失陷状态；只有把日志集中、关联、研判并联动处置，才能缩短「发现到处置」的窗口。

> **速记**：记「**SOC 是人与流程、SIEM 是日志与关联、威胁情报是外部知识**」；定位记「**从买设备转向持续运营**」。



#### 零信任架构

**零信任架构**（Zero Trust Architecture）是**不以网络位置判定信任、对每次访问都重新验证的网络安全理念**，核心原则是**永不信任、持续验证、最小权限、假设已被攻破**。

- **永不信任、持续验证与最小权限**：默认任何主体都不可信、内网与公网一视同仁；每次访问都依据身份、设备状态与环境风险重新评估，且只授予完成当前任务所必需的权限。
- **假设已被攻破**：以攻击者已在内部为前提做设计，强调微隔离、全链路加密与审计。
- **与传统边界模型的差别**：传统模型是**边界防护加内网默认可信**，零信任是**无边界加逐次授权**。
- **落地关键组件**：**策略决策点与策略执行点分离**，决策点按策略判定、执行点执行放行与阻断；**身份是新的控制平面**。

> **辨析**：**零信任不是一件产品，而是一套设计原则**。它不否定防火墙与加密，而是改变信任的判定方式——**从「在哪里」改为「你是谁、设备是否可信、这次访问是否必要」**。

> **速记**：四原则记「**不信、验、最小、被攻破**」；对照记「**旧模型信内网、零信任信证据**」。



#### 软考常见问法

软考对本篇的考查集中在**层次判断、模式比较、机制选型与盲区识别**四类。

- **判断协议所在层次**：**IPSec 在网络层、TLS 在传输层、SSH 与 HTTPS 在应用层**，防火墙与入侵检测按处理深度分层。
- **比较传输模式与隧道模式**：**传输模式保载荷、用于主机直连；隧道模式套整包、用于站点间 VPN**。
- **按场景选择安全机制**：远程登录选 SSH，网页加密选 HTTPS，邮件机密性选 S/MIME，站点互联选 IPSec 隧道，异地办公选承载于 TLS 的 VPN。
- **指出防火墙方案的防护盲区**：凡涉及**内部越权、加密载荷内部攻击、合法协议夹带恶意内容**，都超出防火墙能力范围。
- **判断可用性防护口径**：拒绝服务攻击**无法完全避免**，答题应落在流量清洗、限速、任播分散与业务连续性上。

> **要点**：解题动作是**先定位层次、再定保护对象、后比能力边界**。**层次判错，后面的机制与设备都会跟着错**。

> **速记**：层次题先问「它保护谁」，模式题先问「它包住什么」，选型题先问「要保护哪个应用」，盲区题先问「它能看到哪一层」。
