## 语法分析：自上而下

> **本块定位**：本块对应官方考纲的语法分析自上而下方法，回答三个问题——自上而下分析如何从开始符号出发推出输入串、消除回溯需要把文法改造成什么样子、LL(1) 分析法如何借助 FIRST 与 FOLLOW 集合实现无回溯的确定性分析。FIRST 与 FOLLOW 的求解、左递归与左公因子的消除、预测分析表与分析过程的推演是本篇四个稳定的计算点，LL(1) 文法的判定条件则是概念辨析的常客。字符到记号的那一层已在本主题第 4 篇 词法分析与有限自动机讲完，本块直接以记号串为输入；自下而上分析作为对照，见本主题第 7 篇 语法分析：自下而上。

### 自上而下分析的基本思想

自上而下分析从文法开始符号出发，试图为输入串构造一棵语法树。本模块交代它的分析方向、推导过程的表示方式，以及非确定分析必须解决的三类问题。

#### 自上而下分析的任务与推导方向

**自上而下分析（Top-Down Parsing）**是从文法开始符号出发，反复使用产生式展开非终结符，试图推出与输入串完全匹配的终结符序列的分析方法。

- 输入：词法分析输出的记号串，末尾附加结束符。
- 输出：该串的语法树，或一条语法错误的位置报告。
- 起点：文法开始符号，看作语法树的根。
- 终点：全部叶子按从左到右恰好组成输入串，且非终结符已全部展开。
- 推导方向：从开始符号到句子，与推导的方向一致。
- 与语法树的对应：分析过程等价于自根向叶逐步构造语法树，先建根后建枝。

**考察形式**：综合知识选择题，考查自上而下分析的分析方向与推导的对应关系。



#### 输入指针与推导过程的表示

自上而下分析在执行过程中同时维护输入指针与当前推导出的符号串，两者共同刻画出分析的每一步状态。

- 输入指针：指向当前待匹配的记号，匹配成功即右移一位。
- 当前句型：记录已展开的部分，其中保留尚未展开的非终结符。
- 匹配动作：当前串最左终结符与输入指针所指记号相同时，推进指针。
- 展开动作：当前串最左符号为非终结符时，选一条产生式把它替换掉。
- 成功判定：输入指针到达结束符且当前串只剩下已匹配的终结符。
- 失败判定：无法匹配又无可用的产生式时报告语法错误。

**考察形式**：综合知识选择题，考查分析过程中输入指针与当前句型两个状态的推进方式。



#### 带回溯的分析及其代价

**带回溯的分析（Backtracking Parsing）**是当一个非终结符有多条候选产生式时，逐条试探、失败后回退到原状态再试下一条的分析方法，又称不确定的自上而下分析。

- 试探次序：按产生式书写的先后逐条尝试，不成功则回退。
- 回退内容：输入指针与当前句型都要恢复，因此必须保存现场。
- 时间开销：最坏情况下同一条输入被反复扫描多次，效率急剧下降。
- 空间开销：需要保存回退点，分析栈与现场记录同时增长。
- 语义动作的麻烦：回退时已执行的语义动作难以撤销。
- 工程结论：带回溯的方法只适合手工演示，编译程序不采用。
- 改造方向：要从文法侧消除三类不确定因素，即左递归、回溯与匹配失败。

**考察形式**：综合知识选择题，考查回溯分析的代价与需要消除的三类不确定因素。

> **辨析提示**：三类问题的指向不同，左递归是「循环」问题，回溯与匹配失败是「选错」问题；解决次序固定为先消除左递归、再提取左公因子、最后按 FIRST 与 FOLLOW 集合构造分析表。题目把三者混列时，按这个分界判断即可。



### 左递归的消除与文法改造

左递归会使自上而下分析陷入无限循环，因此必须先改写成等价的无左递归文法。本模块给出左递归的两种形式与消除公式，并交代提取左公因子的做法。

#### 左递归的定义与两种形式

**左递归（Left Recursion）**指文法中存在经过若干步推导后重新回到同一非终结符、且推导过程中该非终结符始终处于最左位置的情形；它分为直接左递归与间接左递归两种形式。

- 直接左递归：某产生式的右部以该产生式左部的非终结符打头，形如 A → A α。
- 间接左递归：一组产生式的推导链回到出发的非终结符，形如 A 推出 B 开头的串，B 又推出 A 开头的串。
- 危害：分析时展开 A 得到 A α，再展开又得到 A α α，最左符号永不变化，推导无法结束。
- 判别：画出非终结符之间的最左依赖关系，若存在环即含左递归。
- 常见来源：左结合的二义表达式文法，如 E → E + T | T。

```text
直接左递归：E → E + T | T                       最左符号就是自己
间接左递归：A → B c | …，B → A d | …             A 与 B 的最左依赖成环
无左递归：  E → T E'，E' → + T E' | ε            改写成右递归形式
```

**考察形式**：综合知识选择题，考查直接与间接左递归的判别与左递归的循环成因。



#### 直接左递归的消除

含直接左递归的产生式按固定公式改写为右递归形式，改写后生成的语言完全不变，且分析过程不再循环。

```text
待改写形式：A → A α1 | A α2 | β1 | β2
改写后的两条产生式：
  A  → β1 A' | β2 A'
  A' → α1 A' | α2 A' | ε
其中 A' 是新引入的非终结符，不出现在原文法中
```

- 改写要点：把左递归的部分挪到新非终结符中，并用 ε 作为出口。
- 语言不变：改写前后的文法生成同一语言，只是推导的形状变了。
- 多个候选式：右部有多条 A α 时，全部移入新非终结符的候选式。
- 出口保证：新非终结符必须带一条产生空串的产生式，否则推导无法收束。
- 改写后形态：递归方向由左变右，因此称为右递归文法。

```text
原文法：E → E + T | T                          直接左递归
改写为：E → T E'，E' → + T E' | ε               出口为 ε，递归改到右侧
验证：E ⇒ T E' ⇒ T + T E' ⇒ T + T + T E' …      可推出任意多个加项
```

**考察形式**：综合知识选择题或案例分析题，考查直接左递归消除公式的应用。



#### 间接左递归的消除步骤

间接左递归不能直接套用公式，需先按固定次序代入展开，把间接形式转化为直接形式后再消除。

- 第一步：给全部非终结符排定一个固定次序，如 A1、A2、A3。
- 第二步：按该次序逐个代入，把右部中出现的次序在前的非终结符替换为它的候选式，消掉前面的非终结符。
- 第三步：代入完成后，形如 Ai → Ai α 的产生式即为直接左递归，套用公式消除。
- 第四步：若代入过程又产生了新的间接左递归，按同一次序再扫一遍，直到所有非终结符都不含前向依赖。
- 第五步：删除不再可达的多余非终结符，把没有产生式被用到的符号清理掉。

```text
原文法：A → B c | d，B → A e | f          间接左递归：A ⇒ B c ⇒ A e c
按次序 A 先 B 后，把 A 的右部代入 B：
  B → B c e | d e | f                      化为直接左递归，套用公式
  B  → d e B' | f B'
  B' → c e B' | ε
再回代：A → ( d e B' | f B' ) c | d
```

> **说明**：不同教材设定代入次序的方式略有差别，考试中只要按题目指定的次序逐步代入即可，结论不受影响。

**考察形式**：综合知识选择题或案例分析题，考查间接左递归消除的代入次序与步骤。



#### 提取左公因子

**提取左公因子（Left Factoring）**是把同一非终结符的若干候选式中相同的公共前缀提取出来、改由新非终结符承担后续选择的手段，用于消除候选式首符号冲突导致的回溯。

```text
待改造形式：A → α β1 | α β2
提取后的两条产生式：
  A  → α A'
  A' → β1 | β2
其中 A' 为新引入的非终结符
```

- 改造目的：让同一非终结符的各候选式首符号互不相同，从而能按下一个记号直接选定。
- 提取对象：只提取公共前缀，不提取首符号之外的相同部分。
- 多级提取：公共前缀被提取后新非终结符仍可能冲突，须递归地继续提取。
- 与回溯的关系：左公因子是回溯的根源之一，提取后分析可以一次选定不再回退。
- 语言不变：提取左公因子同样只改变文法形状，不改变它生成的语言。
- 改造的代价：新引入的非终结符不带语义，文法可读性下降，语义动作的挂载点也需重排。
- 改造的边界：改造只能消除不确定因素，不能把非 LL(1) 文法变成 LL(1) 文法；确属非 LL(1) 时改用 LR 一族分析法，见本主题第 7 篇 语法分析：自下而上。

> **辨析提示**：悬挂 else 问题正是这一改写方式的经典来源。原文法 S → i E t S | i E t S e S | a 中两条候选式共有前缀 i E t S，提取后 else 固定与最近的 if 配对，文法不再二义，与多数语言的语义约定一致。

**考察形式**：综合知识选择题或案例分析题，考查左公因子的提取与悬挂 else 的文法改写。



### FIRST 集合与 FOLLOW 集合

FIRST 与 FOLLOW 两个集合是构造预测分析表的全部依据，也是本篇最主要的计算点。本模块给出两个集合的定义、计算规则与完整示例。

#### FIRST 集合的定义

**FIRST 集合**是某文法符号串所能推导出的全部首终结符的集合；若该串能推导出空串，则空串也属于该集合。

- 记号：串 α 的 FIRST 集合记作 FIRST(α)。
- 元素的来源：只收集推导结果中最左侧的那个终结符。
- 空串的归属：只有当 α 能推出空串时，ε 才属于 FIRST(α)。
- 终结符的特例：单个终结符 a 的 FIRST 集合就是它本身。
- 用途：判断某个候选式能否以当前输入记号开头。
- 与 FOLLOW 的分工：FIRST 判断「能否用这条产生式展开」，FOLLOW 判断「能否用空串产生式跳过」。

```text
FIRST(a…) = {a}                               以终结符打头的串，首符确定
FIRST(A B) = FIRST(A) 再去掉 ε 后并入 FIRST(B)    A 可空时需继续向后取
FIRST(ε) = {ε}                                 空串首符集为 {ε}
```

**考察形式**：综合知识选择题，考查 FIRST 集合的定义与集合元素的可能来源。



#### FIRST 集合的计算规则

FIRST 集合按产生式逐条收集，遇到右部可空的非终结符时向后继续扫描，直到遇到终结符或右部扫描完毕。

- 规则一：右部以终结符 a 开头，把 a 加入 FIRST 集合，扫描结束。
- 规则二：右部以非终结符 X 开头，把 FIRST(X) 中除空串外的元素全部并入。
- 规则三：若 X 可推出空串，则继续扫描右部的下一个符号，重复规则一与规则二。
- 规则四：若右部所有符号都能推出空串，则把空串并入该非终结符的 FIRST 集合。
- 规则五：重复扫描直到所有 FIRST 集合不再增大，集合的求解是迭代到不动点的过程。

```text
文法：
  E  → T E'
  E' → + T E' | ε
  T  → F T'
  T' → * F T' | ε
  F  → ( E ) | i

依次求得：
  FIRST(F)  = { ( , i }                          两条候选式各以终结符打头
  FIRST(T') = { * , ε }                          含空串产生式，故并入 ε
  FIRST(T)  = FIRST(F) = { ( , i }               F 不可空，直接取 FIRST(F)
  FIRST(E') = { + , ε }
  FIRST(E)  = FIRST(T) = { ( , i }
```

**考察形式**：综合知识选择题或案例分析题，考查按规则逐条计算 FIRST 集合。



#### FOLLOW 集合的定义

**FOLLOW 集合**是某非终结符在文法的所有句型中所能紧跟其后的全部终结符的集合，用于判断该非终结符何时可以用空串产生式收束。

- 记号：非终结符 A 的 FOLLOW 集合记作 FOLLOW(A)。
- 元素的来源：查找所有形如 … A β 的位置，A 后面的部分所能推出的首终结符。
- 开始符号的特殊处理：开始符号的 FOLLOW 集合一定含结束符。
- 不回填空串：FOLLOW 集合只含终结符与结束符，不含空串。
- 用途：非终结符可空时，看当前输入记号是否落在它的 FOLLOW 集合里。
- 与 FIRST 的区别：FIRST 从某个符号向后看，FOLLOW 从别的符号向后看它。

```text
形如 … A β 的位置：
  若 FIRST(β) 非空，把 FIRST(β) 中除 ε 外的元素并入 FOLLOW(A)
  若 β 可空或 β 不存在，把 FOLLOW(左部非终结符) 并入 FOLLOW(A)
开始符号 S：结束符 # 一定并入 FOLLOW(S)
```

**考察形式**：综合知识选择题，考查 FOLLOW 集合的定义与开始符号的特殊处理。



#### FOLLOW 集合的计算规则

FOLLOW 集合按产生式逐条形如右部的相邻关系收集，遇到右部末尾或可空后缀时把左部的 FOLLOW 集合回传。

- 规则一：对形如 A → α B β 的产生式，把 FIRST(β) 中除空串外的元素并入 FOLLOW(B)。
- 规则二：若 β 可推出空串，或 B 后无符号，则把 FOLLOW(A) 并入 FOLLOW(B)。
- 规则三：开始符号的 FOLLOW 集合先放入结束符。
- 规则四：所有右部扫描一遍后集合若仍增大，再扫第二遍，直到不再变化。
- 规则五：求 FOLLOW 集合必须先用 FIRST 集合的结果，不能跳过顺序。
- 求解次序：先 FIRST 后 FOLLOW，书写时把集合元素完整列出，只写元素个数不给分。
- 结果复核：任何非终结符的 FOLLOW 集合都不含空串；开始符号的 FOLLOW 集合一定含结束符；位于右部末尾的非终结符，其 FOLLOW 集合应含左部非终结符的 FOLLOW 集合。

```text
在上例文法上依次求得：
  FOLLOW(E)  = { # , ) }                        开始符号，且出现在 ( E ) 中
  FOLLOW(E') = FOLLOW(E) = { # , ) }            E' 恒位于 E 的右部末尾
  FOLLOW(T)  = FIRST(E') 去掉 ε 后并上 FOLLOW(E)
             = { + } ∪ { # , ) } = { + , # , ) }
  FOLLOW(T') = FOLLOW(T) = { + , # , ) }
  FOLLOW(F)  = FIRST(T') 去掉 ε 后并上 FOLLOW(T)
             = { * } ∪ { + , # , ) } = { * , + , # , ) }
```

**考察形式**：综合知识选择题或案例分析题，考查 FOLLOW 集合按规则传递与回传的计算。



### LL(1) 文法与预测分析表

有了两个集合就可以构造预测分析表，并据此判断文法是否属于 LL(1)。本模块给出 LL(1) 的定义、分析表的构造规则与完整示例。

#### LL(1) 文法的定义与条件

**LL(1) 文法**是可以用预测分析法进行确定性分析的文法，其名称取自从左到右扫描输入、产生最左推导、只需向前看一个记号三项特征。

- 第一个 L：从左到右扫描输入串。
- 第二个 L：构造最左推导。
- 括号中的 1：分析每步只需向前看一个输入记号。
- 实质条件：同一非终结符的各候选式的 FIRST 集合两两不相交。
- 补充条件：若某候选式可推出空串，则其余候选式的 FIRST 集合不得与它的 FOLLOW 集合相交。
- 结论：同时满足两条条件的文法称为 LL(1) 文法，可构造无冲突的预测分析表。

**考察形式**：综合知识选择题，考查 LL(1) 名称三个字母的含义与 LL(1) 文法的两个条件。



#### 预测分析表的构造规则

**预测分析表（Predictive Parsing Table）**是一张以非终结符为行、以输入记号与结束符为列的二维表，表中每个格子存放该状态下应选用的产生式。

- 表的结构：行为全部非终结符，列为全部终结符再加上结束符。
- 首条规则：对产生式 A → α，把 FIRST(α) 中的每个终结符所在列填为该产生式。
- 第二条规则：若 α 可推出空串，则把 FOLLOW(A) 中的每个终结符所在列也填为该产生式。
- 空格子的含义：该格子为空表示当前状态下无合法动作，遇到输入记号落在此格即报语法错误。
- 冲突的含义：同一格子被填入两条不同产生式即为冲突，该文法不是 LL(1) 文法。
- 结束符的处理：结束符只出现在 FOLLOW 集合参与填表的那些列。

```text
填表口诀：
  产生式 A → α 填 FIRST(α) 各列
  α 可空时再填 FOLLOW(A) 各列
  同格两条产生式 = 冲突 = 文法不是 LL(1)
```

**考察形式**：综合知识选择题或案例分析题，考查预测分析表两条填表规则与冲突判定。



#### 预测分析表构造完整示例

下面对前述表达式文法构造完整的预测分析表，表内用产生式编号代替产生式本身，便于查表。

```text
产生式编号：(1) E → T E'   (2) E' → + T E'   (3) E' → ε   (4) T → F T'
            (5) T' → * F T'  (6) T' → ε       (7) F → ( E )  (8) F → i

预测分析表（列 = 输入记号，行为非终结符，短横表示该格无动作）：
         (      )      +      *      i      #
  E      (1)    -      -      -     (1)     -
  E'     -     (3)    (2)     -      -     (3)
  T      (4)    -      -      -     (4)     -
  T'     -     (6)    (6)    (5)     -     (6)
  F      (7)    -      -      -     (8)     -

查表依据：非空候选式按 FIRST 集合填列，空串候选式按 FOLLOW 集合填列
  故 E' 行 + 列取 (2)、) 与 # 列取 (3)；T' 行 * 列取 (5)、+ 与 ) 与 # 列取 (6)
```

- 无冲突核对：每个格子只填了一条产生式，故该文法是 LL(1) 文法。
- 空格位置：E 行的 ) 列即空格，输入中出现多余的右括号时在此报错。
- 表的规模：行数等于非终结符个数，列数等于终结符个数加一。
- 表的存储：实际程序用二维数组或哈希表表示，行列为编号后的整数下标。
- 与工具的关系：语法分析生成器由文法自动完成这一套填表工作，说明见本主题第 3 篇 编译过程与阶段划分。

**考察形式**：案例分析题，考查由 FIRST 与 FOLLOW 集合填出完整预测分析表并核对无冲突。



#### LL(1) 性的判定步骤

判断一个文法是否为 LL(1) 文法有一套固定步骤，考试按步骤书写即可避免遗漏。

- 第一步：检查文法是否含左递归，含则先消除，否则直接进入下一步。
- 第二步：检查同一非终结符的各候选式是否含公共前缀，含则提取左公因子。
- 第三步：求全部 FIRST 集合。
- 第四步：求全部 FOLLOW 集合。
- 第五步：逐条核对同一非终结符的候选式，判断 FIRST 集合是否两两不相交。
- 第六步：对可空的候选式，核对其余候选式的 FIRST 集合与它的 FOLLOW 集合是否相交。
- 第七步：两条条件都满足则为 LL(1) 文法，否则给出冲突所在的位置。

```text
判定链条：
  左递归？──是──→ 先消除，再往下
  公共前缀？──是──→ 提取左公因子，再往下
  各候选式 FIRST 两两不相交？──否──→ 不是 LL(1)
  可空候选式：其余 FIRST 与本题 FOLLOW 相交？──是──→ 不是 LL(1)
  全部通过 ──→ 是 LL(1) 文法
```

**考察形式**：案例分析题，考查按固定步骤判定文法是否为 LL(1) 并指出冲突位置。



#### 非 LL(1) 文法的常见成因

多数自然写出的表达式文法都不是 LL(1)，成因集中在少数几种结构，识别它们有助于快速判断。

- 左递归：原文法直接含左递归，如 E → E + T | T，未消除前必然不是 LL(1)。
- 公共前缀：候选式以相同符号开头，必须提取左公因子。
- 悬挂 else：else 与 if 的配对未定，提取左公因子后可消除。
- 空串候选式冲突：某候选式可空，其余候选式的 FIRST 与它的 FOLLOW 相交。
- 表达式结合性：左结合的运算符用左递归描述最自然，改为右递归后需在语义阶段修正结合性。
- 处理结论：确属非 LL(1) 且不可改造时，改用 LR 一族分析法，见本主题第 7 篇 语法分析：自下而上。

> **辨析提示**：左递归与公共前缀是「可以改造好」的一类，空串候选式与 FOLLOW 相交通常「改不动」。题目问「下列文法是否为 LL(1)」时，先把前两类排除再判断第三条。

**考察形式**：综合知识选择题，考查非 LL(1) 文法的常见成因与可否改造的判断。



### 递归下降分析法

递归下降是把 LL(1) 分析表直接写成程序结构的一种实现方式，它把每个非终结符对应成一个函数。本模块交代它的组织形式与优缺点。

#### 递归下降分析器的结构

**递归下降分析法（Recursive Descent Parsing）**是为文法的每个非终结符编写一个识别函数、函数之间按产生式相互调用的一种自上而下分析方法。

- 组织方式：一个非终结符对应一个函数，函数的任务是识别该非终结符。
- 函数签名：函数接收分析器状态对象，返回识别成功或失败的标志。
- 状态对象：保存输入记号序列、当前下标与错误位置。
- 调用关系：函数内部按产生式依次调用右部各符号对应的函数。
- 终结符处理：遇到终结符时与当前输入记号比较，相同则推进下标。
- 终结符比较的失败：不匹配即返回失败，由调用者决定是否报告错误。
- 函数与产生式的关系：非终结符个数等于函数个数，候选式多于一条时函数内用条件分支逐条判断。
- 分支判定依据：当前记号落在某候选式的 FIRST 集合中即选该条，落在 FOLLOW 集合中则选可空的那条候选式且不推进输入。

```text
对每个非终结符编写函数，以标识符为例：
  matchIdentifier()      终结符处理：比对当前记号后推进下标
  matchExpression()      按 E → T E' 依次调用 matchTerm、matchExpressionTail
  matchExpressionTail()  以当前记号是否落在 FIRST / FOLLOW 中决定走哪条候选式
要点：函数与产生式的对应关系是这套方法的核心
```

**考察形式**：综合知识选择题，考查递归下降分析器中函数与非终结符的对应关系。



#### 递归下降与预测分析的等价关系

递归下降与表驱动的预测分析是同一种分析方法的不同实现，两者选用的产生式序列完全一致。

- 分析能力等价：两者适用的文法集合相同，都是 LL(1) 文法。
- 决策依据相同：都用 FIRST 与 FOLLOW 集合决定下一步动作，结论一致。
- 差别在实现：递归下降把选择逻辑编码进程序的分支结构，表驱动把选择逻辑外化为数据。
- 改动的代价：文法变化时递归下降需要改代码并重新编译，表驱动只需重新生成分析表。
- 函数调用开销：递归下降的分析栈即程序的调用栈，深层嵌套时有栈溢出风险。
- 调试便利：递归下降的调用层次与语法结构一一对应，定位问题比查表更直观。

**考察形式**：综合知识选择题，考查递归下降与预测分析表在能力与决策依据上的一致性。



#### 递归下降分析法的优点与局限

递归下降分析法在工程上广泛用于手写分析器，但它的适用面受文法形态限制。

- 优点一：结构直观，函数层次与语法结构一一对应，可读性强。
- 优点二：在函数中直接插入语义动作方便，属性计算随识别同步完成。
- 优点三：错误信息可以按上下文给出，定位精度高于查表法。
- 局限一：只适用于 LL(1) 文法，含左递归或公共前缀的文法必须先改造。
- 局限二：深层嵌套时递归层次过深，可能出现栈溢出。
- 局限三：同一非终结符对应多条候选式时，逐一判断的开销高于一次查表。

> **说明**：实际编译程序常在递归下降的基础上加入向前看多个记号、回溯缓存等扩展，但方法的基本形态与本文一致。语义动作与属性计算的细节见本主题第 8 篇 语义分析与语法制导翻译。

**考察形式**：综合知识选择题，考查递归下降分析法的适用范围与主要局限。



### 表驱动预测分析器的实现

表驱动预测分析器把分析表与运行逻辑分开，是 LL(1) 分析的标准工程形态。本模块交代它的组成部分与运行过程。

#### 分析器的三个组成部分

**表驱动预测分析器**由分析栈、预测分析表与输入缓冲三个部分构成，运行逻辑是一个不断查表动作的主循环。

- 分析栈：存放当前句型的待展开部分，初始时只放开始符号与结束符。
- 预测分析表：由文法预先算出，行为非终结符，列为输入记号。
- 输入缓冲：存放待分析的记号串，末尾附加结束符，分析指针指向当前记号。
- 栈顶动作：栈顶是非终结符则查表选产生式，是终结符则与输入记号比较。
- 表格驱动的优势：改文法只需重算分析表，主循环代码不变。
- 终止条件：栈底与输入同时只剩结束符时分析成功。

```text
初始状态：分析栈 [ # , E ]（左端为栈顶），输入缓冲 [ i , + , i , * , i , # ]
主循环分支：
  栈顶为终结符 → 与当前输入记号比较，相同则同时弹出并推进输入
  栈顶为非终结符 → 查表取产生式，弹出栈顶并把产生式右部逆序压栈
  两侧只剩 # → 检查是否同时结束，是则分析成功
```

**考察形式**：综合知识选择题，考查预测分析器三个组成部分与主循环的分支逻辑。



#### 分析过程的完整示例

下面以输入串 i + i * i 为例，逐行走完整个分析过程，这一推演形式是案例分析题的固定要求。

```text
文法（同上）：FIRST / FOLLOW 与分析表见本模块前文
输入串：i + i * i #

步骤  分析栈              剩余输入        动作
  1   # E                 i + i * i #     E 查表 i 列：E → T E'
  2   # E' T              i + i * i #     T 查表 i 列：T → F T'
  3   # E' T' F           i + i * i #     F 查表 i 列：F → i
  4   # E' T' i           i + i * i #     终结符 i 与输入匹配，弹出并推进
  5   # E' T'             + i * i #       T' 查表 + 列：T' → ε
  6   # E' T +            + i * i #       E' 查表 + 列：E' → + T E'
  7   # E' T              i * i #         终结符 + 与输入匹配，弹出并推进
  8   # E' T' F *         * i #           T 与 T' 依次展开为 T → F T'、T' → * F T'
  9   # E' T' F           i #             终结符 * 与输入匹配，弹出并推进
 10   # E' T' i           i #             F 查表 i 列：F → i
 11   # E' T'             #               终结符 i 与输入匹配，弹出并推进
 12   # E'                #               T' 与 E' 依次取空串候选式，栈与输入同为 #，成功

结论：输入串 i + i * i 是该文法的合法句子，其语法树与最右推导的逆序一致
```

- 步骤 6 与 18、19：三处空串产生式不推进输入，只弹出栈顶。
- 步骤 8：分析栈顶部压入的是产生式右部的逆序，故 + 在 T 之前被处理。
- 步骤 20：两侧同时只剩结束符是成功的唯一判据。
- 记录要求：案例题作答时须把分析栈、剩余输入、所用产生式三列写全，缺列会扣分。
- 与最右推导的关系：自下而上分析中该树按最右推导的逆序归约，见本主题第 7 篇 语法分析：自下而上。

**考察形式**：案例分析题，考查预测分析完整过程的逐步填写与结论判定。

> [!WARNING]
> **警告内容**：空串候选式不推进输入，是最常见的失分点。步骤中出现 T' → ε 或 E' → ε 时，分析栈弹出栈顶而剩余输入保持不变；若顺手推进了输入指针，后续所有步骤都会错位，最终得到错误的结论。



#### 语法错误的检测与恢复

预测分析表里的空格位置就是错误检测点，分析器遇到空格即报错，随后按既定策略恢复以继续分析。

- 检测时机：栈顶为非终结符而查表得到空格时立即报错。
- 检测时机之二：栈顶终结符与当前输入记号不一致时报错。
- 错误定位：以当前输入记号的序号作为错误位置上报。
- 恢复策略之一：恐慌模式，跳过输入记号直到落在当前非终结符的 FOLLOW 集合中。
- 恢复策略之二：短语层恢复，把栈顶符号弹出直到能与输入记号衔接。
- 恢复策略之三：错误产生式，为常见错误形式专门增设产生式以便继续分析。
- 报告要求：一次编译应尽量报出多个错误，报完即停会让使用者反复重编。

**考察形式**：综合知识选择题，考查错误检测点的位置与三种错误恢复策略的取舍。

> [!IMPORTANT]
> **重要内容**：一次编译应尽量报出多个错误。发现错误后立即终止分析会让使用者反复重编，因此恢复策略是分析器的必备部分而不是可选优化，实际实现中恐慌模式与短语层恢复常配合使用。



#### LL(1) 分析的适用范围与取舍

LL(1) 分析在能力、效率与实现成本三者之间取得了一种平衡，但它并非所有场合的最优解。

- 能力范围：只能处理 LL(1) 文法，对自然写出的表达式文法往往需要先改造。
- 时间效率：分析过程线性于输入长度，主循环每步只做一次查表。
- 手工实现的友好度：递归下降形态极适合手写，复杂语言的前端常见这种组合。
- 与 LR 的对比：LR 一族能处理更大的文法类且不需消除左递归，但也更复杂，见本主题第 7 篇 语法分析：自下而上。
- 工具生态：语法分析生成器更常生成自下而上分析器，手写场景更常用递归下降。
- 结论：判断题目给出的是哪一类分析器，看它是否需要消除左递归即可区分。

```text
三类方法的能力与代价对照（越大越强 / 越繁琐）：
  LL(1)          处理文法类最小，实现最简单，须消除左递归与左公因子
  LR(0) 与 SLR(1) 处理文法类居中，实现较繁琐，不必消除左递归
  LALR(1)        处理文法类更大而分析表规模与 SLR(1) 相当，工程上最常用
  LR(1)          处理文法类最大，分析表规模也最大
```

> **说明**：本模块只给出三类分析法的能力排序，LR 一族分析表的构造与冲突消解属于下一篇的内容，见本主题第 7 篇 语法分析：自下而上。判断考试题属于哪一篇，看题目是否要求消除左递归即可。

**考察形式**：综合知识选择题或论文写作的方法选型论述，考查 LL(1) 分析的适用范围与三类分析法的取舍。
