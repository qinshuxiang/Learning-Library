## 语义分析与语法制导翻译

> **本块定位**：本块对应官方考纲的语义分析与语法制导翻译，回答三个问题——语义分析在编译过程中检查什么、属性文法如何把语义规则挂到语法树上、中间代码与符号表如何承载翻译结果。四元式与逆波兰式的书写次序、翻译模式中属性求值顺序是本篇的计算点，S 属性与 L 属性的判定以及符号表组织方式的选择是概念辨析的常考点。词法与语法的分析算法见本主题第 4 篇 词法分析与有限自动机、第 6 篇 语法分析：自上而下与第 7 篇 语法分析：自下而上，本块不重讲。

### 语义分析的任务与范围

语义分析在语法结构合法的前提下检查含义是否成立，并为后续的中间代码生成准备信息。本模块界定其任务、检查内容与阶段位置。

#### 语义分析的任务

**语义分析（Semantic Analysis）**是对语法分析输出的语法树做静态检查、并计算与语义相关信息以使程序含义明确的一类工作，它不产生可执行代码。

- 输入：语法分析产生的语法树，或记号流直接驱动的一次遍历。
- 输出：带语义标注的语法树、填好的符号表与其它语义信息。
- 检查范围：凡能在编译期静态判定的语言约束都归它负责。
- 计算范围：为表达式确定类型与运算符含义，为名字绑定符号表入口。
- 分界：数组下标越界、除零等只能运行期确定的问题不在静态语义检查范围。

**考察形式**：综合知识选择题，考查语义分析的输入输出形式与静态检查的范围边界。



#### 静态语义检查的内容

静态语义检查覆盖类型、声明与作用域三类约束，其共同点是不依赖运行时数据即可判定。

- 类型一致性：赋值、运算与调用实参的类型是否相容，必要时插入隐式类型转换。
- 声明检查：变量、函数、标号与类型名在使用前是否已声明。
- 作用域检查：名字的引用是否落在其声明的作用域内、是否存在重复声明。
- 控制流检查：break 与 continue 是否出现在循环或分支的合法位置。
- 唯一性检查：同一作用域内是否出现重名、同一分支标号是否重复。

**考察形式**：综合知识选择题，考查类型检查、声明检查与作用域检查各自覆盖的约束。



#### 语义错误的类型与处理

**语义错误**是程序语法合法但含义不成立的情形，按处理时机分为静态语义错误与动态语义错误。

- 静态语义错误：类型不匹配、未声明标识符、重复声明、参数个数不符，编译期报错。
- 动态语义错误：数组下标越界、空指针引用、除数为零，运行期检测。
- 报告方式：给出出错位置、错误类别与期望类型，并尽量继续分析以便一次报出多个错误。
- 错误恢复：可对错误表达式给出默认类型后继续检查，避免连锁报错。
- 与语法错误的分界：括号不配对属于语法错误，括号内表达式类型不符属于语义错误。

> **辨析提示**：题目问「下列错误在哪一阶段发现」时，先判断是不是语法结构问题。类型不匹配、未声明就使用都属语义分析阶段，不是语法分析阶段。

**考察形式**：综合知识选择题，考查静态语义错误与动态语义错误的归类以及错误恢复的常用做法。



#### 语义分析与前后阶段的关系

语义分析夹在语法分析与中间代码生成之间，三者常在一个遍中交错完成。

- 上游依赖：以语法树为输入，需要语法分析提供正确的结构信息。
- 下游输出：把类型与符号表信息交付中间代码生成使用。
- 遍的合并：语法制导翻译把语义分析与中间代码生成合并到同一遍完成。
- 与符号表的耦合：语义分析在声明处写入符号表、在引用处读取符号表。
- 与优化的关系：类型与常量信息是后续常量折叠与强度削弱的前提。

**考察形式**：综合知识选择题，考查语义分析在编译阶段中的位置以及它与符号表、优化的衔接关系。



### 属性文法（综合属性与继承属性）

属性文法把语义规则形式化地挂在文法产生式上，使语义计算可以随语法分析同步进行。本模块给出属性文法、两类属性、依赖关系与两类受限文法的定义。

#### 属性文法的定义

**属性文法（Attribute Grammar）**是在上下文无关文法基础上，为每个文法符号关联一组属性、为每条产生式关联一组语义规则的文法。

- 文法基础：底层的上下文无关文法描述结构，属性与规则描述含义。
- 属性：与文法符号相关联的语义量，可取类型、值、地址、字符串等。
- 语义规则：形如把某属性定义为其它属性的函数，如 E.val 由 E1.val 与 T.val 相加得到。
- 产生式关联：规则写在产生式旁，随该产生式的使用而触发。
- 别名：属性文法与语法制导定义同义，教材两种叫法并存。

**考察形式**：综合知识选择题，考查属性文法的组成以及属性与语义规则的对应关系。



#### 综合属性

**综合属性（Synthesized Attribute）**是由其所在结点自身及子结点的属性计算得到的属性，信息在语法树中自下而上流动。

- 计算来源：只能来自子结点属性与结点自身的固有信息，不含父结点或兄弟结点的属性。
- 典型例子：表达式的值、子表达式的类型，均由子结点汇总而来。
- 计算时机：自下而上分析时可以在归约时立即求值。
- 流向示意：叶子结点的属性经产生式规则逐层向上汇总到根。
- 使用范围：语法树根的综合属性就是整个程序的语义结果。

**考察形式**：综合知识选择题，考查综合属性的计算来源与它在语法树中的流动方向。



#### 继承属性

**继承属性（Inherited Attribute）**是由其父结点、兄弟结点或结点自身的属性计算得到的属性，信息在语法树中自上而下或横向流动。

- 计算来源：可以来自父结点属性、左兄弟属性或结点自身。
- 典型例子：标识符的声明类型、符号表指针、表达式所需的期望类型。
- 计算时机：需要父结点信息已知后才能求值，不能简单在归约时立即算。
- 流向示意：根或上层结点的属性向下传递，使叶子获得上下文信息。
- 必要性：类型声明与作用域相关的信息只能靠继承属性向下传递。

```text
声明语句 D -> T L 的属性依赖（T 为类型，L 为标识符表）
T.type 是综合属性          由类型子串汇总得到
L.inh 是继承属性           由 D 把 T.type 沿 L 向下传递
L.syn 是综合属性           收集本声明定义的标识符名表
语义规则：L.inh 取 T.type  把类型信息向下继承
         addType(L.inh, L.syn)   把类型写入符号表中各标识符条目
```

**考察形式**：综合知识选择题，考查继承属性的计算来源以及它与综合属性在流动方向上的差别。



#### 属性依赖图与求值顺序

**属性依赖图**是以属性为结点、以属性之间的依赖关系为有向边的图，它决定语义规则的可求值顺序。

- 结点与边：每个属性对应一个结点，若属性 b 依赖属性 c 则画一条 c 到 b 的边。
- 求值顺序：按依赖图的拓扑序求值，保证求某属性时其依赖已经算好。
- 冲突情形：依赖图中出现环时无法确定求值顺序，该属性文法不适于直接求值。
- 遍历对应：全为综合属性时后序遍历即可，含继承属性时常需前序与后序结合。
- 实际做法：为便于实现，通常改写文法使依赖关系与遍历顺序一致。

**考察形式**：综合知识选择题，考查属性依赖图的构造方式与拓扑求值顺序的确定。



#### S 属性文法与 L 属性文法

按属性依赖的方向把属性文法分为两类受限文法，它们分别适配自下而上与自顶向下的分析方式。

- **S 属性文法（S-Attributed Grammar）**：只含综合属性的属性文法，可用自下而上方式在归约时求值。
- **L 属性文法（L-Attributed Grammar）**：每个产生式右部符号的继承属性只依赖其左边符号的属性与本符号自身的属性，可按深度优先从左到右求值。
- 包含关系：S 属性文法是 L 属性文法的特例，L 属性文法不一定只含综合属性。
- 实现对应：S 属性文法适配 LR 分析，L 属性文法适配递归下降与 LL 分析。
- 受限理由：允许任意依赖会使求值顺序无法与单遍遍历对应，实现成本骤增。

> [!IMPORTANT]
> **重要内容**：判断一个属性文法属于 S 属性还是 L 属性，只看每条产生式中继承属性的依赖来源。右部某符号的继承属性若依赖其右侧符号的属性，就不满足 L 属性条件；只要出现继承属性，就不是 S 属性文法。

**考察形式**：综合知识选择题，考查综合属性与继承属性的判别、S 属性与 L 属性的包含关系及各自适配的分析方式。



### 语法制导翻译与翻译模式

语法制导翻译把属性文法落到分析过程上，翻译模式进一步规定语义动作在产生式右部的插入位置，使求值顺序显式化。

#### 语法制导定义与语法制导翻译

**语法制导定义（Syntax-Directed Definition，SDD）**是为每条产生式关联语义规则、为每个文法符号关联属性的形式化定义；**语法制导翻译（Syntax-Directed Translation，SDT）**是按语法制导定义在语法分析过程中同步完成语义计算与代码生成的实现方式。

- 定义层面：语法制导定义只说明算什么，不规定何时算。
- 实现层面：语法制导翻译规定何时算，是定义的实现方案。
- 遍历方式：可基于语法树事后遍历，也可在分析过程中随归约或随展开同步完成。
- 单遍实现：把语义动作插入分析过程，可省去显式建树的开销。
- 用途：类型检查、符号表填写、中间代码生成与目标代码生成都可用它组织。

**考察形式**：综合知识选择题，考查语法制导定义与语法制导翻译在说明层面与实现层面的分工。



#### 翻译模式

**翻译模式（Translation Scheme）**是把语义动作用花括号括起、插入产生式右部适当位置的写法，动作在其左侧符号全部处理完后执行。

- 写法形式：产生式右部中夹杂用花括号括起的语义动作，动作位置决定执行时机。
- 执行时机：自下而上分析中，动作在其左边的符号全部识别完毕时执行。
- 与语法制导定义的差别：定义中的规则隐式依附在产生式末尾，翻译模式把顺序显式写出来。
- 终结符处理：动作插在终结符之后表示该终结符已被读入。
- 可读性：翻译模式更便于手工实现与代码生成，是构造编译程序的常用写法。

**考察形式**：综合知识选择题，考查翻译模式中语义动作的位置与执行时机以及它与语法制导定义的差别。



#### 自下而上与自顶向下的翻译实现

两种分析方式对属性的求值能力不同，决定了翻译模式的写法差异。

- 自下而上实现：在归约时执行动作，天然支持 S 属性文法，属性值放在与分析栈平行的语义栈中。
- 自顶向下实现：在展开产生式时执行动作，可处理 L 属性文法，继承属性以参数形式向下传递。
- 语义栈：自下而上翻译时为栈中每个符号配一个值域，归约时按右部长度弹出并压入结果。
- 参数传递：自顶向下翻译时把继承属性作为函数参数、综合属性作为返回值。
- 选择依据：属性依赖方向决定实现方式，强行逆用会引入额外遍次。

**考察形式**：综合知识选择题，考查语义栈的工作方式与继承属性、综合属性在两种实现中的传递形式。



#### 消除左递归后的翻译模式改写

自顶向下翻译要求文法无左递归，改写文法时必须同步改写语义规则，否则属性值会丢失或重复计算。

- 问题所在：形如 E -> E + T 与 E -> T 的直接左递归使递归下降无法终止。
- 改写形式：E -> T E'，E' -> + T E' 与 E' -> 空串。
- 属性约定：T 的值作为继承属性向下传给 E'，E' 的结果作为综合属性向上返回。
- 规则改写：E' 的递归产生式中把左边累加值作为继承属性传入。
- 一致性检查：改写前后对同一输入的语义结果必须完全一致。

```text
左递归文法的翻译模式改写（计算表达式值）
原文法规则：E -> E1 + T   动作把 E.val 置为 E1.val + T.val
改写后规则：E  -> T E'          E'.inh 取 T.val，E.val 取 E'.syn
            E' -> + T E'1       E'1.inh 取 E'.inh + T.val，E'.syn 取 E'1.syn
            E' -> 空串          E'.syn 取 E'.inh
输入 3 + 4 求值：E'.inh = 3，读 + 与 T 后 E'1.inh = 3 + 4 = 7，最终 E.val = 7
```

**考察形式**：综合知识选择题与案例分析，考查左递归改写后继承属性与综合属性的传递路径以及求值结果的一致性。



#### 语法制导翻译示例

以带类型转换的表达式翻译为例，说明属性文法如何同时完成类型检查与生成中间代码。

- 文法：E -> E1 + T 与 E -> T 与 T -> i。
- 属性：E.type 与 T.type 表示表达式的类型，E.code 与 T.code 表示生成的中间代码序列。
- 规则：若两侧类型相同则直接相加，否则插入隐式转换后再相加。
- 代码拼接：子表达式的代码片段按左、右、本体三段的顺序拼接成父表达式的代码。
- 输出：根结点的 code 属性即整个表达式对应的中间代码序列。

```text
输入表达式 a + b * c 的翻译结果（.code 为四元式序列）
b * c 按 T -> T * F 归约，生成 t1 = b * c
a 与 t1 相加，生成 t2 = a + t1
组合后的中间代码序列为两条四元式：先 t1 = b * c，再 t2 = a + t1
```

**考察形式**：综合知识选择题，考查按给定属性规则推导表达式的类型与中间代码序列。



### 中间代码的形式（四元式、三元式、逆波兰式、树）

中间代码是与具体机器无关、介于源程序与目标代码之间的表示形式，它便于优化与跨平台移植。本模块给出四种常见形式及其生成方法。

#### 中间代码的作用与形式分类

**中间代码（Intermediate Code）**是编译程序在语义分析与优化阶段使用的、结构清晰且与源语言和目标机器都无关的中间表示。

- 作用一：把源语言与目标机器解耦，前端与后端可独立更换。
- 作用二：结构规整，便于实施与机器无关的优化。
- 分类依据：按表示形态分，常见有逆波兰式、四元式、三元式与树形表示。
- 层次差别：逆波兰式最接近栈式机器，四元式与三元式接近三地址码，树形表示最接近语法树。
- 选择取舍：以便于优化与便于生成目标代码为准则，教材例题多用四元式。

**考察形式**：综合知识选择题，考查中间代码的作用与四种常见表示形态的分类依据。



#### 逆波兰式

**逆波兰式（Reverse Polish Notation，RPN）**又称后缀表示，是把运算符写在两个运算对象之后的表达式表示形式，无需括号即可唯一确定运算次序。

- 定义：中缀表达式 a + b 的后缀形式为 a b +。
- 转换规则：遇运算对象直接输出，遇运算符比较优先级决定入栈或弹出。
- 求值方式：从左到右扫描，遇到运算符就对栈顶元素做运算并把结果压栈。
- 优点：无括号、无优先级表，适合栈式计算机执行。
- 局限：不适合表达控制流与复杂数据结构，常只用于表达式。

```text
中缀表达式 a + b * c 转逆波兰式的过程（维护一个运算符栈）
读 a      输出 a                       后缀串：a
读 +      运算符入栈                    后缀串：a
读 b      输出 b                       后缀串：a b
读 *      * 优先级高于 +，入栈           后缀串：a b
读 c      输出 c                       后缀串：a b c
读完       弹出栈中的 * 与 +            后缀串：a b c * +
求值：先算 b * c 得 t1，再算 a + t1，与中缀的运算次序一致
```

**考察形式**：综合知识选择题，考查给定中缀表达式转逆波兰式的过程与逆波兰式的求值顺序。



#### 四元式

**四元式（Quadruple）**是含四个域的中间代码表示，四个域依次为运算符、第一运算对象、第二运算对象与结果。

- 域的含义：运算符或指示动作、第一运算对象、第二运算对象、存放结果的域。
- 临时变量：为每个中间结果引入临时变量 t1、t2 等。
- 优点：结果域显式给出，便于优化时重排与回填。
- 控制流表示：无条件转移用运算符为 jump、结果为目标标号的四元式表示。
- 常见写法：赋值用等号形式的四元式，缺省运算对象用下划线占位。

```text
表达式 a = b * c + d 的四元式序列
1  *  b   c   t1        t1 取 b * c
2  +  t1  d   t2        t2 取 t1 + d
3  =  t2  _   a         a 取 t2
条件转移示例：if a < b then goto L 的四元式序列
1  <  a   b   t1        t1 取 a < b
2  jnz t1 _   L         t1 为真时转向标号 L
```

**考察形式**：综合知识选择题，考查给定表达式写成四元式序列的写法与临时变量的使用。



#### 三元式

**三元式（Triple）**是含三个域的中间代码表示，三个域依次为运算符、第一运算对象与第二运算对象，运算结果不显式命名而用该三元式的序号引用。

- 引用方式：后续三元式用序号引用前面三元式的结果。
- 优点：省去结果域与临时变量，表示更紧凑。
- 缺点：重排三元式会改变序号，使所有引用失效，不利于优化。
- 间接三元式：另设一张指示器表按顺序存放三元式序号，重排只改指示器表。
- 与四元式的关系：两者表达能力相当，四元式便于优化，三元式节省空间。

> **辨析提示**：选择四元式还是三元式，看是否需要频繁重排。四元式的结果域显式，重排不会破坏引用；三元式紧凑，但重排后序号失效，必须借助间接三元式。

```text
表达式 a = b * c + d 的三元式序列
1  *  b   c            结果记作 (1)
2  +  (1) d            结果记作 (2)
3  =  a   (2)          把 (2) 赋给 a
间接三元式的指示器表初始为 1、2、3；若把第 1 条移到第 2 位，只改指示器表为 2、1、3
```

**考察形式**：综合知识选择题，考查三元式的序号引用方式与间接三元式解决重排问题的原理。



#### 树形表示与有向无环图

**中间代码的树形表示**是以运算符为内部结点、以运算对象为叶子结点的语法结构表示；**有向无环图（Directed Acyclic Graph，DAG）**是在树形表示上合并公共子表达式后的表示。

- 树形表示：每个子表达式对应一棵子树，结构与语法树一致但已去掉无关语法成分。
- DAG 的定义：同一子表达式只保留一个结点，多个父结点共享该结点。
- 生成方式：自下而上合并键相同的结点，键由运算符与子结点编号组成。
- 优化价值：DAG 天然体现公共子表达式，是局部优化的基础数据结构。
- 与四元式的对应：DAG 每个内部结点可对应一条四元式，公共结点只需生成一次代码。

**考察形式**：综合知识选择题，考查树形表示与有向无环图的构造方式以及在优化中的作用。



### 符号表的作用与组织

符号表把程序中的名字与其属性集中管理，是编译各阶段共享的信息中心。本模块给出它的作用、组织方式、表项内容与作用域管理方法。

#### 符号表的作用

**符号表（Symbol Table）**是以名字为索引、存放该名字各项属性的数据结构，它把名字的声明信息与使用信息连接起来。

- 核心作用：登记声明、支持引用时查表、为后续阶段提供名字的属性。
- 属性内容：种类、类型、作用域、存储位置与其它附加信息。
- 共享范围：词法分析登记标识符，语义分析写类型，代码生成读地址。
- 一致性保证：同一名字在声明与引用处取到同一入口，才能正确绑定。
- 性能要求：查表与插表在编译过程中频繁发生，其效率直接影响编译速度。

**考察形式**：综合知识选择题，考查符号表在编译各阶段中的作用与它所承载的信息内容。



#### 符号表的组织方式

符号表的实现以查找效率与插入便利为取舍核心，常见三种组织方式。

- 线性表：按出现顺序顺序存放，插表快，查表需顺序比较，适合小规模程序。
- 有序表：表项按名字排序，可用折半查找，插表需保持有序，适合查多插少。
- 散列表：用散列函数把名字映射到桶，平均查找接近常数时间，是主流实现。
- 冲突处理：散列冲突用链地址法或开放地址法解决，链地址法更常用。
- 选择依据：以名字数量、查插比例与内存开销为准则，普遍优先散列表。

**考察形式**：综合知识选择题与案例分析，考查三种组织方式的查找与插入代价对比与选用依据。



#### 符号表表项的内容

符号表表项随名字种类不同而异，但都包含名字、种类与作用域三项基本内容。

- 名字：标识符的字符序列，是查表的键。
- 种类：常量、变量、类型、函数、标号或形参，决定其余字段的解释方式。
- 类型：数据类型，供类型检查与存储分配使用。
- 存储信息：静态分配的地址或运行时的偏移量，供代码生成使用。
- 函数附加信息：形参个数与类型、返回类型、入口地址。

**考察形式**：综合知识选择题，考查符号表表项的字段构成以及各字段服务的编译阶段。



#### 作用域与符号表的栈式管理

**作用域（Scope）**是名字有效的程序范围，符号表按作用域的进入与退出动态管理表项，形成栈式结构。

- 单表加栈式组织：用一张全局符号表，进入作用域时记录当前表尾位置，退出时回退到该位置。
- 分表组织：每个作用域一张子表，用外层指针串成链，查表时沿链向外查找。
- 进入处理：进入新作用域时压入作用域标记，登记本层声明的名字。
- 退出处理：退出时删除本层名字的表项或把表尾回退到进入前的位置。
- 可见性规则：内层同名声明遮蔽外层声明，查表从最内层开始向外。

> [!NOTE]
> **提醒内容**：同名标识符可在不同作用域并存，查表必须从最内层作用域开始。若散列表只按名字存一个全局入口，内层声明会覆盖外层，退出作用域时又无法恢复，必须配合作用域栈或子表链来保存各层表项。

**考察形式**：综合知识选择题，考查作用域嵌套下符号表的进入、退出与可见性判定规则；运行时的存储组织详见本主题第 10 篇 运行时环境与存储组织。
