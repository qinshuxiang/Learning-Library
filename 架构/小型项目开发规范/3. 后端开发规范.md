## 后端开发规范

> **全章主脉**：**小项目后端用 Express 保持两层结构：路由层接 HTTP，服务函数管业务，全局中间件只留必要的几个**。本篇给出工程骨架、路由与错误处理的直接可用代码、配置与日志的最低要求，依赖与升级取舍一并收口。

### 核心原则

- **两层结构**：路由层只做参数接收、校验与调用服务函数，业务逻辑全在服务函数里，不在路由回调里堆逻辑。
- **中间件最小集**：全局中间件固定为访问日志、跨域、JSON 解析、路由挂载、错误处理五个，顺序固定不增不减。
- **配置进环境变量**：端口、数据库连接、密钥一律从环境变量读，代码里不出现任何环境相关字面量。



### 推荐做法

**工程初始化**与本地启动：

```bash
npm init -y
npm install express mysql2 dotenv cors dayjs
node --watch app.js
```

**目录结构**固定如下：

```text
project/
  app.js            入口，只做装配
  config.js         环境变量集中读取
  db.js             MySQL 连接池
  lib/              工具函数（时间等）
  constants/        常量（状态、错误码）
  routes/           路由层，一个资源一个文件
  services/         服务层，业务逻辑
  middleware/       自定义中间件
  migrations/       数据库迁移脚本
  client/           前端工程（前后端同仓库时）
```

**配置集中读取**，全项目只在此一处碰环境变量：

```js
// config.js
require('dotenv').config()

module.exports = {
  port: Number(process.env.PORT || 3000),
  corsOrigin: process.env.CORS_ORIGIN.split(','),
  db: {
    host: process.env.DB_HOST,
    user: process.env.DB_USER,
    password: process.env.DB_PASSWORD,
    database: process.env.DB_NAME,
  },
  jwtSecret: process.env.JWT_SECRET,
}
```

**入口只做装配**，五类中间件按固定顺序挂：

```js
// app.js
const config = require('./config')
const express = require('express')
const cors = require('cors')
const { logger } = require('./middleware/logger')
const { errorHandler } = require('./middleware/error')
const userRouter = require('./routes/user')

const app = express()

app.use(logger)
app.use(cors({ origin: config.corsOrigin }))
app.use(express.json())
app.use('/api/users', userRouter)
app.get('/healthz', (req, res) => res.json({ ok: true }))
app.use(errorHandler)

app.listen(config.port, () => {
  console.log(`listening on ${config.port}`)
})
```

**路由层一个资源一个文件**，回调里只做三件事：接参数、调服务、回响应：

```js
// routes/user.js
const express = require('express')
const userService = require('../services/user')

const router = express.Router()

router.get('/', async (req, res, next) => {
  try {
    const list = await userService.list(req.query)
    res.json({ code: 0, data: list })
  } catch (err) {
    next(err)
  }
})

router.post('/', async (req, res, next) => {
  try {
    const user = await userService.create(req.body)
    res.status(201).json({ code: 0, data: user })
  } catch (err) {
    next(err)
  }
})

module.exports = router
```

**统一响应结构**，全接口一致，前端只判一个字段：

- **成功**：code 为 0，data 放数据。
- **失败**：code 非 0，message 放可读描述，HTTP 状态码仍如实给——4xx 参数错，5xx 服务错。

**错误处理收敛到一个中间件**，服务函数只管抛错，不打日志不拼响应：

```js
// middleware/error.js
const dayjs = require('dayjs')

function errorHandler(err, req, res, next) {
  console.error(`[${dayjs().format('YYYY-MM-DD HH:mm:ss')}] ${req.method} ${req.url}`, err)
  const status = err.status || 500
  res.status(status).json({
    code: status,
    message: status === 500 ? '服务器内部错误' : err.message,
  })
}

module.exports = { errorHandler }
```

**访问日志用一个函数起步**，格式统一带时间、请求标识与耗时，日志量级上来之前不引日志库：

```js
// middleware/logger.js
const crypto = require('crypto')
const dayjs = require('dayjs')

function logger(req, res, next) {
  req.id = crypto.randomUUID()
  res.setHeader('X-Request-Id', req.id)
  const start = Date.now()
  res.on('finish', () => {
    console.log(
      `${dayjs().format('YYYY-MM-DD HH:mm:ss')} ${req.id} ${req.method} ${req.url} ${res.statusCode} ${Date.now() - start}ms`
    )
  })
  next()
}

module.exports = { logger }
```

**日志要能定位到人与单**，三条最低要求：

- **每条请求有标识**：logger 里生成的请求标识同时写进日志与响应头 X-Request-Id，用户报障时让前端把响应头里的标识带上，一条标识串起全链路日志。
- **关键业务单独打日志**：下单、支付、改权限这类操作在服务函数里补一行业务日志，用户 ID 与业务单号必在其中，访问日志的 URL 参数替代不了它。
- **时间格式与全库一致**：时间戳取自时间工具的东八区格式，不用 toISOString 的 UTC 串，写法见 时间与时区统一 篇。

**依赖与升级策略**与前端同一纪律：锁文件提交、npm ci 还原、安全补丁即升、大版本按需；生产依赖控制在十来个以内，Express 中间件按需单装，不引全家桶框架。



### 注意事项

- **不引 ORM**：mysql2 参数化查询已经够安全够直白，SQL 能力不因 ORM 而退化；连接池与查询封装见 数据库规范 篇。
- **不上 TypeScript**：小项目引入 TS 的构建与类型维护成本高于收益，关键函数用 JSDoc 注释补类型说明即可。
- **异步错误必须转给 next**：Express 4 的路由回调不自动捕获 Promise 异常，漏写 try 加 catch 异步报错会让请求挂起；Express 5 起才自动转发，升级前统一手写。
- **接口路径用复数资源名**：/api/users 而非 /api/getUserList，动作交给 HTTP 方法表达。
