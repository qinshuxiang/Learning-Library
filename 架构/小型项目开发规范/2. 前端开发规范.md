## 前端开发规范

> **全章主脉**：**小项目前端的要害是把技术栈收敛成一条固定路径，让每个页面长一个样**。本篇基于 Vue3 与 Vite 给出工程初始化、目录结构、组件写法、请求封装与依赖管理的直接可用做法，依赖引入与升级的取舍一并收在本篇。

### 核心原则

- **一条技术路径**：全项目只用 Vue3 组合式 API 加 script setup 写法，不混用选项式 API；每个新页面照抄既有页面的结构再改内容。
- **服务端状态就近管理**：数据在哪个组件用就写在哪个组件里，先容忍重复再谈抽象，同类逻辑第三次出现时才抽组合式函数。
- **基建一次选定**：请求用 axios、组件用 shadcn-ui、样式用 SCSS，三件既定基建不再中途更换；基建之外的依赖能不加就不加，每加一个都在支付升级与安全的长期成本。



### 推荐做法

**工程初始化**固定用 Vite 脚手架，一条命令生成基座：

```bash
npm create vite@latest my-app -- --template vue
cd my-app && npm install
```

**目录结构**固定如下，新文件只进既有目录，不随意新开目录：

```text
src/
  api/          请求封装与接口函数
  components/   可复用组件（含 shadcn-vue 复制进来的组件）
  composables/  组合式函数
  router/       路由定义
  views/        页面级组件
  styles/       全局样式、SCSS 变量与 mixin
  assets/       静态资源
  App.vue
  main.js
```

**组件一律用 script setup 单文件写法**，模板、逻辑、样式同文件：

```html
<script setup>
import { ref, onMounted } from 'vue'
import { fetchUserList } from '../api/user'

const list = ref([])
const loading = ref(true)

onMounted(async () => {
  try {
    list.value = await fetchUserList()
  } finally {
    loading.value = false
  }
})
</script>

<template>
  <ul v-if="!loading">
    <li v-for="user in list" :key="user.id">{{ user.name }}</li>
  </ul>
  <p v-else>加载中……</p>
</template>
```

**请求用 axios 统一封装**，基础路径、超时、令牌注入、401 处理、统一响应拆包收敛到一处，业务组件不直接用 axios：

```js
// src/api/request.js
import axios from 'axios'

const instance = axios.create({
  baseURL: import.meta.env.VITE_API_BASE,
  timeout: 10000,
})

instance.interceptors.request.use((config) => {
  const token = localStorage.getItem('app_access_token')
  if (token) {
    config.headers.Authorization = `Bearer ${token}`
  }
  return config
})

instance.interceptors.response.use(
  (res) => {
    if (res.data.code !== 0) {
      return Promise.reject(new Error(res.data.message || '请求失败'))
    }
    return res.data.data
  },
  (err) => {
    if (err.response?.status === 401) {
      localStorage.removeItem('app_access_token')
      localStorage.removeItem('app_refresh_token')
      location.href = '/login'
    }
    return Promise.reject(err)
  }
)

export default instance
```

**拆包约定与后端统一响应结构对应**：code 为 0 时拦截器直接返回 data，业务组件拿到的就是数据本身；401 由拦截器统一踢回登录页，令牌的自动续期同样加在响应拦截里，见 登录的实现 篇。

**接口函数按资源分文件**，一个资源一个文件，组件只调函数不拼路径：

```js
// src/api/user.js
import request from './request'

export function fetchUserList(params) {
  return request.get('/api/users', { params })
}

export function createUser(data) {
  return request.post('/api/users', data)
}
```

**路由用懒加载**，页面组件按需加载控制首屏体积：

```js
// src/router/index.js
import { createRouter, createWebHistory } from 'vue-router'

export const router = createRouter({
  history: createWebHistory(),
  routes: [
    { path: '/users', component: () => import('../views/UserList.vue') },
    { path: '/login', component: () => import('../views/Login.vue') },
  ],
})
```

**锁文件必须提交**，安装一律按锁文件还原，保证任何人任何机器装出的依赖树一致：

```bash
npm ci
```

**依赖引入与升级节奏**：

- **引入判据**：新依赖先问原生 API 与既有依赖能否覆盖；确定要引入时选周下载量大、近一年有维护的包。
- **安全补丁即升**：npm audit 报出有修复版本的漏洞当周处理，多数跑一次 npm audit fix 即可。
- **大版本按需**：框架与主力库的大版本升级只在需要新特性或旧版本停止维护时做，升级前开分支单独验证。



### 注意事项

- **Pinia 的引入时机**：跨路由共享且需要响应式的状态（登录用户、全局配置）出现之前不引状态管理库；到了引入时机只装 pinia，不引旧版 Vuex。
- **UI 组件层用 shadcn-ui**：Vue 生态用 shadcn-vue，组件源码经 CLI 复制进仓库、可自由改造，样式基于 Tailwind（引入 shadcn-vue 时一并接入 Tailwind）；不整库安装组件，用几个加几个。
- **自定义样式用 SCSS**：全局变量与 mixin 收敛在 src/styles，组件内用 scoped 加 lang 写样式；选择器嵌套不超过三层，能靠组件库样式变量解决的不另写样式。
- **不做过早组件抽象**：核心原则中「同类逻辑第三次出现才抽」的门槛同样适用于 UI 组件，先容忍复制粘贴再谈抽象。
