## 测试与质量保障

> **全章主脉**：**小项目的质量下限靠静态检查兜底、靠核心路径测试守护，不追求覆盖率数字**。本篇给出 ESLint 配置、零依赖后端测试与前端组件测试的直接可用写法，以及提交前检查的落地方式。

### 核心原则

- **静态检查优先于测试**：ESLint 拦住的低级错误成本最低，先配好检查再谈测试。
- **只测核心业务路径**：登录、下单、支付回调这类错了赔钱赔数据的链路必须有测试，纯展示页面不写测试。
- **测试不碰外部环境**：单元测试不连真实数据库、不发真实请求，靠模块替换隔离外部依赖。



### 推荐做法

**ESLint 用扁平配置**，前后端同一份规则：

```js
// eslint.config.js
const js = require('@eslint/js')

module.exports = [
  js.configs.recommended,
  {
    rules: {
      'no-unused-vars': 'error',
      eqeqeq: 'error',
    },
  },
]
```

**检查与测试收敛到 package.json 脚本**：

```json
{
  "scripts": {
    "lint": "eslint .",
    "test": "node --test tests/*.test.js"
  }
}
```

**后端测试用 Node 内置 test runner**，零依赖起步：

```js
// tests/slug.test.js
const test = require('node:test')
const assert = require('node:assert')
const { slugify } = require('../services/slug')

test('slugify 转小写并以连字符连接', () => {
  assert.equal(slugify('Hello World'), 'hello-world')
})

test('slugify 去除首尾连字符', () => {
  assert.equal(slugify('--hello--'), 'hello')
})
```

**测试命令与实跑输出**分开给，输出逐行对应测试文件的断言顺序：

```bash
node --test tests/*.test.js
```

**前端测试用 Vitest**，测组合式函数与纯逻辑模块：

```bash
npm install -D vitest
```

```js
// src/composables/useCounter.test.js
import { describe, it, expect } from 'vitest'
import { useCounter } from './useCounter'

describe('useCounter', () => {
  it('increment 后计数加一', () => {
    const { count, increment } = useCounter()
    increment()
    expect(count.value).toBe(1)
  })
})
```

**提交前用 git hook 跑检查与测试**，脚本放 .git/hooks/pre-commit：

```bash
#!/bin/sh
npm run lint || exit 1
npm test || exit 1
```

```bash
chmod +x .git/hooks/pre-commit
```



### 注意事项

- **测试命令带文件模式**：Node 22 的 --test 传裸目录名会按模块解析报 MODULE_NOT_FOUND，须写成 tests 加通配符的文件模式或列出具体文件。
- **不追覆盖率数字**：理由是为凑数写的测试比没有测试更糟，数字达标不等于核心路径受保护。
- **接口未就绪用 mock 路由**：前端依赖的后端接口没开发完时，写一个返回固定数据的 mock 路由顶上，不在组件里写死假数据。
- **测试库与开发库分开**：需要连库的集成测试连测试库，用完即清，绝不指向生产库。

> [!CAUTION]
> **注意内容**：**集成测试的连接配置若误指向生产库，清库操作就是删生产数据**。测试库连接串写进独立环境变量并做库名隔离，每次改动配置当场验证一次连接目标。
