## 安全基础

> **全章主脉**：**小项目安全的底线是加密、认证、限流、参数化四件事全用成熟方案，密钥与代码物理隔离**。本篇给出 Express 侧可直接落地的防护组合与密钥管理规则。

### 核心原则

- **不自研认证与加密**：密码哈希用 bcrypt，令牌用 jsonwebtoken，安全件自研等于给攻击者留门。
- **默认拒绝**：跨域白名单、接口权限、上传类型，一切默认关闭再按需打开。
- **密钥不入仓库**：密钥只存在于环境变量与密钥管理渠道，仓库里出现过的密钥一律视为已泄漏。



### 推荐做法

**防护中间件组合**，入口一次挂齐：

```bash
npm install helmet express-rate-limit
```

```js
const helmet = require('helmet')
const rateLimit = require('express-rate-limit')

app.use(helmet())
app.use(
  rateLimit({
    windowMs: 15 * 60 * 1000,
    limit: 300,
  })
)
```

**登录用 bcrypt 加 JWT**，校验失败返回统一错误结构：

```bash
npm install bcrypt jsonwebtoken
```

```js
// services/auth.js
const bcrypt = require('bcrypt')
const jwt = require('jsonwebtoken')
const config = require('../config')
const pool = require('../db')

async function login(name, password) {
  const [rows] = await pool.query('SELECT id, password_hash FROM user WHERE name = ?', [name])
  const user = rows[0]
  if (!user || !(await bcrypt.compare(password, user.password_hash))) {
    const err = new Error('用户名或密码错误')
    err.status = 401
    throw err
  }
  return jwt.sign({ uid: user.id }, config.jwtSecret, { expiresIn: '7d' })
}

function authRequired(req, res, next) {
  const token = (req.headers.authorization || '').replace('Bearer ', '')
  try {
    req.uid = jwt.verify(token, config.jwtSecret).uid
    next()
  } catch {
    res.status(401).json({ code: 401, message: '未登录或登录已过期' })
  }
}

module.exports = { login, authRequired }
```

**注册时哈希入库**，任何环节不存明文：

```js
// services/user.js
const bcrypt = require('bcrypt')
const pool = require('../db')

async function createUser(name, password) {
  const passwordHash = await bcrypt.hash(password, 10)
  const [result] = await pool.query(
    'INSERT INTO user (name, password_hash) VALUES (?, ?)',
    [name, passwordHash]
  )
  return result.insertId
}
```

**敏感文件提交前隔离**，.gitignore 给全基线：

```text
node_modules/
dist/
.env
*.log
```

**依赖漏洞定期巡检**，安全补丁当周处理：

```bash
npm audit
npm audit fix
```

**注入类攻击的默认防御**：

- **SQL 注入**：一律占位符传参，见 数据库规范 篇。
- **XSS**：Vue 模板插值默认转义；确需渲染 HTML 时，先用 DOMPurify 清洗再进 v-html，且只允许可信来源。
- **路径穿越**：文件下载与读取接口校验拼接后的真实路径在预期目录内。



### 注意事项

- **JWT 签发后无法主动作废**：给令牌用短有效期；需要强制下线时，在负载里带令牌版本号并在服务端比对，改密码即加版本。
- **上传接口单独设防**：校验扩展名与类型、限制大小、随机重命名落盘，上传目录不给执行权限。
- **错误信息不外泄内部细节**：500 统一返回「服务器内部错误」，堆栈只进日志，见 后端开发规范 篇错误中间件。

> [!CAUTION]
> **注意内容**：**密钥一旦进了代码、聊天记录或日志就视为已泄漏**，处置方式是立即轮换新密钥并作废旧密钥；事后删除文件消除不了已泄漏的事实。
