## 数据库规范

> **全章主脉**：**小项目数据库的要害是让每一次结构变更可追溯、可重放，让每一条查询都参数化**。本篇基于 MySQL 给出建库建表模板、连接池、迁移脚本与备份的直接可用做法。

### 核心原则

- **一切结构变更走迁移脚本**：表结构只由 migrations 目录下的 SQL 文件定义，禁止在库里手工改表后不补脚本。
- **参数化查询是铁律**：任何拼进 SQL 的值必须走占位符，字符串拼接 SQL 一律视为缺陷。
- **字符集统一 utf8mb4**：建库即指定，避免生产环境遇到生僻字与表情符号存储报错。



### 推荐做法

**建库模板**：

```sql
CREATE DATABASE app_db DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

**建表模板**，主键、时间戳、必要索引一次给全：

```sql
CREATE TABLE user (
  id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(64) NOT NULL,
  password_hash CHAR(60) NOT NULL,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  KEY idx_name (name)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4;
```

**连接池全局一个**，进程启动时建好，全项目共用：

```js
// db.js
const mysql = require('mysql2/promise')
const config = require('./config')

const pool = mysql.createPool({
  ...config.db,
  waitForConnections: true,
  connectionLimit: 10,
})

module.exports = pool
```

**查询一律占位符传参**，值交给驱动转义：

```js
const pool = require('./db')

async function getUserById(id) {
  const [rows] = await pool.query('SELECT id, name FROM user WHERE id = ?', [id])
  return rows[0] || null
}
```

**迁移目录按序号命名**，一个文件一次结构变更：

```text
migrations/
  001_create_user.sql
  002_add_user_status.sql
```

**迁移应用脚本**先建记录表，再逐个执行未应用过的文件：

```js
// migrate.js
const mysql = require('mysql2/promise')
const fs = require('fs')
const path = require('path')
const config = require('./config')

async function migrate() {
  const conn = await mysql.createConnection({
    ...config.db,
    multipleStatements: true,
  })
  await conn.query(`CREATE TABLE IF NOT EXISTS migration (
    name VARCHAR(128) PRIMARY KEY,
    applied_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
  )`)
  const applied = new Set(
    (await conn.query('SELECT name FROM migration'))[0].map((row) => row.name)
  )
  const dir = path.join(__dirname, 'migrations')
  for (const file of fs.readdirSync(dir).sort()) {
    if (applied.has(file)) continue
    const sql = fs.readFileSync(path.join(dir, file), 'utf8')
    await conn.query(sql)
    await conn.query('INSERT INTO migration (name) VALUES (?)', [file])
    console.log(`applied: ${file}`)
  }
  await conn.end()
}

migrate()
```

**备份用 mysqldump 定时跑**，备份文件带日期落盘并压缩：

```bash
mysqldump -u backup -p"$DB_PASSWORD" --single-transaction app_db | gzip > "/backup/app_db_$(date +%F).sql.gz"
```

**定时备份挂 crontab**，每天凌晨一次：

```bash
0 3 * * * /opt/app/bin/backup.sh >> /var/log/app_backup.log 2>&1
```



### 注意事项

- **外键约束保留**：小项目数据量级下外键的性能开销可忽略，它能兜住应用层漏网的不一致，建议保留。
- **不用存储过程与触发器**：业务逻辑进应用层，SQL 里藏逻辑会让迁移与排错变难。
- **种子数据不进迁移脚本**：迁移只放结构变更，测试数据单独用 seed 脚本管理，避免脏数据混进生产库。
- **应用账号最小权限**：为应用单建数据库账号，只授业务库的增删改查权限，禁用 root 直连。

> [!WARNING]
> **警告内容**：**备份必须验证可恢复**。定期挑一份备份文件在测试库执行恢复走一遍，没有恢复过的备份不叫备份。
