## 登录的实现

> **全章主脉**：**登录分两段——凭证校验（证明你是你）与会话保持（服务端记住这个证明）**。本篇把注册、签发、校验、续期、登出、强制下线的完整闭环用 Express 加 JWT 说清并给全代码；范围只覆盖单体应用自己的登录，单点登录与第三方 OAuth 登录不在本篇范围，小项目也用不上。

### 核心原则

- **两段式结构**：密码校验只发生在登录那一刻，之后的每次请求靠会话凭证自证身份；两段的代码与职责必须分开。
- **凭证不可伪造、服务端可裁决**：客户端持有的凭证必须带签名（防篡改），服务端必须保留一手否决权（版本号比对），签发了就不能管是伪命题。
- **密码只存哈希**：bcrypt 加盐哈希入库，任何环节不落明文、不打日志，写法与安全判据见 安全基础 篇。
- **会话方案默认 JWT**：前后端分离结构（client 加 api）下默认 JWT 加请求头；全栈同域的页面型应用才考虑 session 加 cookie。



### 推荐做法

**用户表补两个登录相关字段**，会话否决权靠 token_version 实现：

```sql
ALTER TABLE user ADD COLUMN token_version INT UNSIGNED NOT NULL DEFAULT 0;
```

**双令牌是标准形态**：访问令牌短命（两小时，泄露后损失有限），刷新令牌长命（七天，只用来换新访问令牌）：

```js
// services/auth.js
const bcrypt = require('bcrypt')
const jwt = require('jsonwebtoken')
const config = require('../config')
const pool = require('../db')

function issueTokens(user) {
  const base = { uid: user.id, ver: user.token_version }
  return {
    accessToken: jwt.sign(base, config.jwtSecret, { expiresIn: '2h' }),
    refreshToken: jwt.sign({ ...base, typ: 'refresh' }, config.jwtSecret, {
      expiresIn: '7d',
    }),
  }
}

async function login(name, password) {
  const [rows] = await pool.query(
    'SELECT id, password_hash, token_version FROM user WHERE name = ?',
    [name]
  )
  const user = rows[0]
  const ok = user && (await bcrypt.compare(password, user.password_hash))
  if (!ok) {
    const err = new Error('用户名或密码错误')
    err.status = 401
    throw err
  }
  return issueTokens(user)
}

module.exports = { issueTokens, login }
```

失败提示统一为「用户名或密码错误」，不区分哪种错，防用户名枚举；bcrypt.compare 内部做恒定时间比较，不要把哈希查出来自己对比。

**校验中间件每请求查一次版本号**，这是服务端的否决权，也是踢人下线的开关：

```js
// middleware/auth.js
const jwt = require('jsonwebtoken')
const config = require('../config')
const pool = require('../db')

async function authRequired(req, res, next) {
  const token = (req.headers.authorization || '').replace('Bearer ', '')
  let payload
  try {
    payload = jwt.verify(token, config.jwtSecret)
  } catch {
    return res.status(401).json({ code: 401, message: '未登录或登录已过期' })
  }
  const [rows] = await pool.query('SELECT token_version FROM user WHERE id = ?', [
    payload.uid,
  ])
  if (!rows[0] || rows[0].token_version !== payload.ver) {
    return res.status(401).json({ code: 401, message: '登录已失效，请重新登录' })
  }
  req.uid = payload.uid
  next()
}

module.exports = { authRequired }
```

每次请求多一次主键查询，小项目量级下可忽略；将来量级上来把版本号挪进缓存即可，接口不变。

**刷新与登出路由**，登出走版本号加一，全部设备立即失效：

```js
// routes/auth.js
const express = require('express')
const rateLimit = require('express-rate-limit')
const jwt = require('jsonwebtoken')
const config = require('../config')
const pool = require('../db')
const { issueTokens, login } = require('../services/auth')

const router = express.Router()

const loginLimiter = rateLimit({
  windowMs: 15 * 60 * 1000,
  limit: 10,
  message: { code: 429, message: '尝试次数过多，请稍后再试' },
})

router.post('/login', loginLimiter, async (req, res, next) => {
  try {
    const tokens = await login(req.body.name, req.body.password)
    res.json({ code: 0, data: tokens })
  } catch (err) {
    next(err)
  }
})

router.post('/refresh', async (req, res, next) => {
  try {
    const payload = jwt.verify(req.body.refreshToken, config.jwtSecret)
    if (payload.typ !== 'refresh') {
      return res.status(401).json({ code: 401, message: '令牌类型错误' })
    }
    const [rows] = await pool.query('SELECT id, token_version FROM user WHERE id = ?', [
      payload.uid,
    ])
    if (!rows[0] || rows[0].token_version !== payload.ver) {
      return res.status(401).json({ code: 401, message: '登录已失效，请重新登录' })
    }
    res.json({ code: 0, data: issueTokens(rows[0]) })
  } catch {
    res.status(401).json({ code: 401, message: '刷新失败，请重新登录' })
  }
})

router.post('/logout', async (req, res, next) => {
  try {
    await pool.query('UPDATE user SET token_version = token_version + 1 WHERE id = ?', [
      req.uid,
    ])
    res.json({ code: 0, data: null })
  } catch (err) {
    next(err)
  }
})

module.exports = router
```

**登录接口单独限流**是防爆破的主力，上面的 loginLimiter 十五分钟十次；配合原文 安全基础 篇的全局限流组合使用。

**前端只做一件事：存令牌**。令牌注入与 401 踢回登录页已由 前端开发规范 篇的 axios 拦截器统一处理，登录成功后把双令牌落进本地：

```js
// 登录成功后
localStorage.setItem('app_access_token', tokens.accessToken)
localStorage.setItem('app_refresh_token', tokens.refreshToken)
```

自动续期放在 axios 响应拦截里：收到 401 先调 refresh 接口换新令牌并重放原请求，刷新失败才清令牌跳登录；并发请求同时 401 时只在第一个触发刷新，其余等新令牌，避免刷新接口被打穿。

**会话方案的选型判据**，两句定案：

- **JWT 加请求头（默认）**：前后端分离、API 跨域、移动端复用接口，都天然适配；代价是每次请求多一次版本号查询。
- **session 加 cookie**：全栈同域的页面型应用、需要服务端即时精确控制会话时选它；cookie 加 HttpOnly 加 SameSite 属性防脚本偷取与跨站携带，express-session 默认存内存，进程重启会话全丢，要持久化接存储。



### 注意事项

- **JWT 的 payload 只是编码不是加密**：base64 可被任何人解码，里面只放 uid 与版本号，不放手机号、角色权限明细这类敏感内容。
- **过期时间与东八区策略不冲突**：JWT 标准用 UTC 时间戳算过期，库内业务时间用东八区墙上时间，两套各管各的，互不换算，见 时间与时区统一 篇。
- **令牌存 localStorage 有 XSS 代价**：脚本可读是事实，防线是把 XSS 挡在外面（模板默认转义、清洗 HTML，见 安全基础 篇）；要彻底免 XSS 偷取就改 cookie 加 HttpOnly，两种存放各有代价，选一种并知道代价。
- **refresh 接口也要限流**：它等价于第二次登录，不加限制就是绕过登录限流的后门。
- **改密码必须升版本号**：调用与登出相同的版本号加一逻辑，旧令牌全部立即失效，这是「密码改了别人还在线」的唯一堵法。

> [!WARNING]
> **警告内容**：**自己发明令牌格式、自己写签名与校验，是登录实现里唯一不可接受的错误**。签发、校验、续期全部走 jsonwebtoken 一类的成熟库，自研的部分只允许是「查版本号、拼响应」这类业务胶水。
