## 部署与运维规范

> **全章主脉**：**小项目部署的标准形态是一台服务器，nginx 托管前端静态产物并反代后端，PM2 守护 Node 进程，整条链路一条脚本可重放**。本篇给出服务器布局、部署与回滚脚本、nginx 配置与健康检查的直接可用内容。

### 核心原则

- **部署一条命令可重放**：从拉代码到服务恢复全程脚本化，手工在服务器上敲过的命令都应沉淀进脚本。
- **两套环境够用**：开发与生产两套即可，没有专职运维的前提下预发环境是负担。
- **永远记得上一版本**：发版前记录当前提交号，出问题两步切回。



### 推荐做法

**服务器目录布局**，仓库工作副本即运行目录，配置与代码物理隔离：

```text
/var/www/app/            仓库工作副本（.env 放这里，不入库）
  client/                前端工程，构建产物在 client/dist
  app.js                 后端入口
  ecosystem.config.js    PM2 配置
  prev_commit            部署脚本写入的回滚点
```

**PM2 管进程**，配置文件随仓库走：

```js
// ecosystem.config.js
module.exports = {
  apps: [
    {
      name: 'app-api',
      cwd: '/var/www/app',
      script: 'app.js',
      instances: 2,
      max_memory_restart: '512M',
      env: {
        NODE_ENV: 'production',
      },
    },
  ],
}
```

**部署脚本**全流程固定，发版即跑：

```bash
#!/bin/bash
set -e

cd /var/www/app
git fetch origin main
git rev-parse HEAD > prev_commit
git reset --hard origin/main
npm ci --omit=dev
cd client && npm ci && npm run build
cd ..
pm2 reload ecosystem.config.js --update-env
```

**回滚脚本**两步切回上一版本：

```bash
#!/bin/bash
set -e

cd /var/www/app
git checkout "$(cat prev_commit)"
npm ci --omit=dev
(cd client && npm ci && npm run build)
pm2 reload ecosystem.config.js --update-env
```

**nginx 配置**，静态托管前端构建产物并把接口反代给后端：

```nginx
server {
    listen 80;
    server_name example.com;

    root /var/www/app/client/dist;
    index index.html;

    location /api/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

**HTTPS 用 certbot 签发与自动续期**：

```bash
sudo certbot --nginx -d example.com
```

**健康检查**复用后端的 /healthz 接口，挂在 crontab 或外部拨测服务上，失败即告警：

```bash
curl -fsS --max-time 5 https://example.com/healthz
```

**变更顺序固定**，一次发版按四步走，顺序不可调换：

- **第一步**：执行数据库迁移脚本，让库结构先就位（向后兼容的迁移写法见 数据库规范 篇）。
- **第二步**：执行数据回填脚本并记录。
- **第三步**：发布新代码并重启服务。
- **第四步**：跑健康检查与核心接口抽样验证。

**回填脚本进仓库并留痕**，一次性数据修写成带编号的脚本提交，执行结果记录，禁止在生产库手工粘贴执行无痕 SQL：

```text
scripts/
  migrate.js           迁移执行器
  backfill/
    001_backfill_user_nickname.js
```

**配置漂移防线**：服务器的任何手工改动（临时改文件、改 nginx 不进仓库）视为未发生——下次部署即被覆盖；要改就改仓库再部署。配置唯一来源是仓库模板加环境文件，见 后端开发规范 篇 config.js。



### 注意事项

- **环境变量文件不进仓库**：.env 只存在于服务器与开发者本机，换机器时手工同步。
- **前端构建产物不进仓库**：dist 在部署机构建生成，构建一次产物一次，gitignore 掉。
- **数据库变更先于代码发版**：迁移脚本先执行，保证新代码跑在已迁移的库上；详见 数据库规范 篇。
- **回滚先于回填**：发版后发现问题需要回滚代码时，已执行的回填数据要评估是否反向修回，回滚脚本与回填脚本是成对出现的预案。

> [!IMPORTANT]
> **重要内容**：**部署脚本本身要进代码仓库并随项目演进**。运维知识只存在某台服务器的命令历史里，等于把项目命脉押在一个人记得住多少条命令上。
