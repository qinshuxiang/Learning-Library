## 关系代数与关系演算

> **全章主脉**：**关系代数（Relational Algebra）以关系为运算对象、以关系为运算结果，是 SQL 的理论基础与查询优化的形式化依据**。全章沿两条主线展开：一条是**运算体系**，由并、差、笛卡尔积、选择、投影五种基本运算出发，导出交、连接、除等组合运算；另一条是**表达能力**，用元组关系演算与域关系演算描述要什么，再由**安全表达式**与**关系完备性**把两类语言统一起来。两条线最终汇合于**查询优化**——用等价变换把表达式改小，再交由物理执行。SQL 的具体语法留待第 4 篇，关系模式的规范化留待第 5 篇。

### 关系代数的定位与基本运算

#### 关系代数的定位

**关系代数**（Relational Algebra）：以关系为运算对象、以关系为运算结果的形式化查询语言，是结构化查询语言（Structured Query Language，SQL）的理论基础，也是查询优化的形式化依据。

- **运算对象与结果**：输入是关系，输出仍是关系，因此运算可层层嵌套、任意组合。
- **非过程化表达**：表达式只说明取什么，不规定怎么取，存取路径与执行算法交由优化器决定。
- **SQL 的理论基础**：FROM 子句对应笛卡尔积，WHERE 子句对应选择，SELECT 子句对应投影。
- **查询优化的依据**：优化器以等价变换为工具，把逻辑计划改写成中间结果更小的等价计划。

> **易混辨析**：关系代数是**抽象查询语言**，不是某个数据库产品的具体语法。SQL 是它在工程上的实现外壳，二者在能表达什么上大体一致，在怎么写上完全不同。

> **速记**：关系代数记三句——**关系进、关系出、可嵌套**。

**考察形式**：综合知识选择题。



#### 五种基本运算

**基本运算**：不可由其他运算导出、构成关系代数最小完备集的五种运算，即**并**（Union）、**差**（Difference）、**笛卡尔积**（Cartesian Product）、**选择**（Selection）与**投影**（Projection）。

- **并**：把两个关系的元组合并，重复元组只保留一份。
- **差**：从第一个关系中剔除那些也出现在第二个关系中的元组。
- **笛卡尔积**：把两个关系的元组两两首尾拼接，结果属性数为两者属性数之和。
- **选择**：按条件筛出满足条件的元组，是挑行的运算。
- **投影**：按指定属性列取出各元组的分量，是挑列的运算。
- **导出运算**：**交**、**连接**、**除**都可由上述五种组合表达，故只算导出运算。

```text
五种基本运算的写法（R、S 为关系）

并       R ∪ S           元组属于 R 或属于 S
差       R − S           元组属于 R 且不属于 S
笛卡尔积 R × S           R 的元组与 S 的元组两两拼接
选择     σ 条件 ( R )     取 R 中满足条件的元组（挑行）
投影     π 属性列 ( R )   取指定属性列并消去重复（挑列）
```

> **易混辨析**：**基本运算与导出运算是生成元与派生结果的关系**，不是按难度分层。判断某运算是否基本，只需问它能否只用其余基本运算表达——能表达的即导出运算。

> **速记**：**并、差、笛卡尔积是集合运算，选择、投影是一元运算**。

**考察形式**：综合知识选择题。



#### 并运算与差运算的相容性

**相容性**（Union Compatibility）：并、差、交运算的适用条件，要求参与运算的两个关系属性个数相同，且对应属性的取值域相同。

- **同元数**：两个关系的属性个数必须一致。
- **同域**：按位置对应的属性必须取自同一个域，比较才有意义。
- **结果属性名**：并、差的结果沿用第一个关系的属性名。
- **不受此限的运算**：笛卡尔积、选择、投影、连接均无相容性要求。

> [!WARNING]
> **警告内容**：**属性个数相同不等于相容**——两个关系都是三个属性，但对应位置上一个取自学号域、一个取自成绩域，就不满足同域要求，不能直接做并或差。反过来，属性名不同而域相同是相容的，因为比较按位置进行而非按名字进行。

> **速记**：相容两条——**同元数、对应属性同域**；属性名不参与判断。

**考察形式**：综合知识选择题。



#### 选择与投影的分工

**选择**（Selection）与**投影**（Projection）：一对一元运算，分别完成行筛选与列筛选，选择按条件留下满足条件的元组，投影按属性列表留下指定的列。

- **选择的表达**：条件由**比较运算**（等于、不等于、大于、小于等）与**逻辑连接词**（与、或、非）组合而成，作用在单个元组上。
- **投影的表达**：只列出需要的属性名或属性序号，其余列一律丢弃。
- **投影的去重**：**关系是集合，集合不允许重复元素，因此投影结果要消去重复元组**。
- **次序影响**：先选择后投影与先投影后选择结果可能不同，能否交换取决于投影是否保留了选择条件用到的属性。

```text
示例关系 S（学生）
学号  姓名  年龄  系别
S01   张三  20    计算机
S02   李四  21    软件工程
S03   王五  19    计算机

选择 σ 年龄 < 20 ( S )   得一行：S03 王五 19 计算机
投影 π 系别 ( S )        得两行：计算机、软件工程（重复已消去）
```

> [!WARNING]
> **警告内容**：**投影会自动消去重复元组**，这是关系是集合这一前提的直接后果。两个学生的系别相同时，投影到系别只保留一行。答题时若投影结果出现重复行，即为错误。

> **速记**：**选择管行、投影管列；选择加条件、投影列属性；投影必去重**。

**考察形式**：综合知识选择题。



### 组合运算与连接运算族

#### 交运算及其与差的换算

**交**（Intersection）：由同时属于两个关系的元组构成的关系，同样要求相容性，并且可由**差**运算表达出来。

- **语义**：交的结果是既在第一个关系里、又在第二个关系里的元组集合。
- **换算关系**：两个关系的交，等于第一个关系减去（第一个关系减去第二个关系）所得的差。
- **导出方向**：差不能被交与并表示，因此差列基本运算、交列导出运算。
- **使用场合**：求两个查询结果的公共部分，如既选了数据库又选了操作系统的学生。

> **易混辨析**：**并、交、差都要求相容性**，常有人只记得并、差而漏掉交。同时注意可导出方向是单向的——**交可由差导出，差不可由交导出**。

> **速记**：**交是导出的，差是基本的；交可由差表示，反之不成立**。

**考察形式**：综合知识选择题。



#### 连接运算的分类与等值连接

**连接**（Join）：从两个关系的笛卡尔积中按给定条件筛选出满足条件的元组，因此本质上是**笛卡尔积加选择**的组合。

- **等值连接**（Equi-Join）：连接条件全部由等号构成，比较两关系的某些属性是否相等。
- **非等值连接**（Theta Join）：连接条件中含有大于、小于、不等于等非等值比较，通说认为也包含多个条件混合的情形。
- **连接的度**：等值连接与非等值连接的属性数等于两关系属性数之和。

> [!NOTE]
> **提醒内容**：连接不是基本运算，而是**笛卡尔积加选择的简写**；自然连接更特殊，它在笛卡尔积加选择之后再叠加一次投影，用来消去重复的同名列。看清这三层叠加，就看清了连接族的全部形态。

> **速记**：连接等于**积加选**，自然连接等于**积加选再加投影**。

**考察形式**：综合知识选择题。



#### 自然连接、自身连接与非等值连接

**自然连接**（Natural Join）：等值连接的特例，要求按同名属性相等来匹配，并在结果中去掉重复的属性列；**自然连接**与**等值连接**的差别集中在条件来源与重复列处理两处。

- **条件来源**：自然连接自动以全部同名属性作为等值条件；等值连接由使用者显式指定哪两个属性相等。
- **重复列处理**：自然连接只保留一份同名列，等值连接保留两个关系的全部属性、同名列出现两次。
- **自身连接**（Self Join）：一个关系与其自身做连接，要先取两个别名再当作两个关系使用，用于表内层级或比较，如找出每个员工的上级姓名。
- **非等值连接的用途**：用于区间匹配与排名类问题，如找出成绩高于某学生全部课程成绩的学生。

> [!WARNING]
> **警告内容**：**自然连接与等值连接不是同一件事**——若两个关系没有同名属性，自然连接退化为笛卡尔积；若属性名相同而域不同，自然连接可能做出毫无意义的匹配。使用自然连接前必须确认同名属性的语义一致。

> **速记**：**等值连接显式给条件、保留全部列；自然连接隐式按同名列、只留一列；自身连接靠别名**。

**考察形式**：综合知识选择题。



### 除运算与关系演算

#### 除运算的语义与等价改写

**除**（Division）：求解包含全部类问题的运算，商的结果由那些与第二个关系中每一个元组都匹配的元组分量组成。

- **适用条件**：第二个关系的属性集合必须是第一个关系属性集合的子集，商关系的属性等于前者减去后者后的剩余属性。
- **语义**：商中的每个元组与第二个关系的每个元组拼接后，都能在第一个关系中找到对应元组。
- **典型问题**：查询选修了全部课程的学生、找出供货覆盖全部零件的供应商。
- **等价改写**：商可用先求所有组合、再减去实际缺失的组合、最后投影的方式，用差与投影表达出来。

```text
示例关系 SC（选课）与 C（课程）

SC（学号 课程号 成绩）          C（课程号 课程名）
S01  C01  90                    C01  数据库
S01  C02  85                    C02  操作系统
S01  C03  78                    C03  计算机网络
S02  C01  88
S03  C01  92
S03  C03  80

查询：π 学号, 课程号 ( SC ) ÷ π 课程号 ( C )   结果为 S01
改写：全部学生乘全部课程，减去 SC 中已有的组合得到空缺，
      再从全部学生中减去空缺学生，即得结果。
```

> [!NOTE]
> **提醒内容**：除运算在标准 SQL 中没有直接对应的关键字，通常用不存在没选某课程的学生这类双重否定写法等价表达。除运算的真正价值在于**为全部这一语义提供代数写法**，而不在于是否直接可用。

> **速记**：**除管全部；商记满足全部条件的那个分量**。

**考察形式**：综合知识选择题。



#### 关系演算的两类与谓词表达式

**元组关系演算**（Tuple Relational Calculus，TRC）：以元组变量为基本单位、用谓词公式描述查询结果的形式化语言；**域关系演算**（Domain Relational Calculus，DRC）：以域变量为基本单位的形式化语言，域变量取自某个属性的取值域。

- **两种变量**：元组变量直接代表关系中的一行，取值范围是某个关系；域变量对应结果元组的一个分量，取值范围是该属性所在的域。
- **谓词表达式**：由**原子公式**（Atom）经逻辑连接词与量词组合而成，是两类演算共同的语言内核；原子公式形如某元组属于某关系、或某两个变量满足某种比较关系。
- **量词与变量**：存在量词表示存在某个元组使谓词成立，全称量词表示对所有元组谓词都成立；**自由变量**（Free Variable）不受量词约束、构成结果分量，**约束变量**（Bound Variable）落在量词作用域内、只起内部匹配作用。
- **共同点**：二者都只给出谓词条件，不规定存取路径，与关系代数一样是非过程化的，且可互相改写。

> **易混辨析**：两类演算的差别只在**变量的粒度**——元组演算的变量是一个元组、一行，域演算的变量是一个值、一个分量；粒度变了，写法繁琐程度不同，表达能力却不变。此外，同一名字是否自由取决于它是否处在量词作用域内，与名字本身无关。

> **速记**：**元组演算的变量是一行，域演算的变量是一个值；原子公式是最小判断，量词管约束变量，自由变量出结果**。

**考察形式**：综合知识选择题。



#### 安全表达式与关系完备性

**安全表达式**（Safe Expression）：结果中每个元组都取自某个有限集合、不会因量词产生无限关系的演算表达式，其作用是保证关系的有限性；**关系完备性**（Relational Completeness）：一种查询语言的表达能力不弱于关系代数。

- **安全问题**：谓词若写成取所有不满足某条件的元组，变量可能遍历无穷多个不存在于任何关系中的值。
- **安全条件**：结果元组的每个分量都必须能在某个已知关系的域或常量集中找到，通说认为只接受安全表达式。
- **三者等价**：关系代数、元组关系演算、域关系演算可互相改写，能表达的查询集合一致。
- **与图灵完备的区别**：关系完备不要求语言具备循环与递归能力，递归查询属于超出关系代数的扩展。

> [!IMPORTANT]
> **重要内容**：**安全性不是语法问题，而是语义前提**——关系是有限集合，若不加限制，演算可以写出结果无限或含义不明的表达式，与关系模型的前提直接冲突；因此教材一律在安全表达式范围内讨论关系演算的等价性。

> **速记**：**安全表达式的唯一标准是取值同有限域；关系代数、元组演算、域演算三者等价**。

**考察形式**：综合知识选择题。



### 查询优化与实际用途

#### 查询的等价变换规则

**等价变换规则**：保证变换前后表达式结果相同、用于把逻辑计划改小的一组改写法则，核心思想是尽早缩小中间结果。

- **选择下推**：把选择运算尽可能移向表达式树的叶端，先过滤元组再做连接或笛卡尔积。
- **投影下推**：把投影尽可能提前，只保留后续运算真正用到的属性，减小元组宽度。
- **次序调整**：调整连接与笛卡尔积的先后顺序使中间结果最小，连接满足交换律与结合律。
- **同类合并**：同一关系上的一串选择可合并成一个合取条件，一串投影可合并为一次投影。

```text
原始表达式（先连接后选择，中间结果大）
  π 姓名 ( σ 系别 = 计算机 ( S ⋈ SC ) )

选择下推后（先把 S 过滤成小关系，再连接）
  π 姓名 ( σ 系别 = 计算机 ( S ) ⋈ SC )
```

> [!TIP]
> **建议内容**：四条规则的意义可用一句话统摄——**让中间结果变小**。代价主要由中间结果规模决定，先筛后连、先少列再运算几乎总能带来收益。需要注意适用条件：投影下推时必须保证后续条件引用的属性没有被提前丢弃。

> **速记**：**选择下推、投影下推、次序重排、同类合并**，四招都为缩小中间结果。

**考察形式**：综合知识选择题。



#### 代数优化与物理优化

**查询优化**（Query Optimization）：分为依据等价变换改写表达式形式的**代数优化**（Algebraic Optimization）与依据代价估算选择存取路径和执行算法的**物理优化**（Physical Optimization）。

- **代数优化**：与具体数据库、硬件无关，只改运算的次序与组合方式，减少中间结果。
- **物理优化**：在给定逻辑计划上选择索引扫描还是全表扫描，选择嵌套循环、排序归并还是散列连接。
- **启发式规则**：把选择尽早、投影尽早、连接优先于笛卡尔积等经验法则作为改写方向，先做代数优化再做物理优化。
- **代价估算**：物理优化依赖统计信息估计中间结果大小与输入输出代价，统计信息失真会导致选错计划。

> [!CAUTION]
> **注意内容**：**启发式规则不是万能的**。选择下推通常有益，但当谓词求值代价极高或选择性极差时，早筛未必优于晚筛；把笛卡尔积改写成连接也只是形式上的改进，真正决定代价的是连接算法是否与数据分布匹配。规则给方向，代价模型做取舍。

> **速记**：**代数优化管形状，物理优化管算法**；启发式给方向，代价模型做取舍。

**考察形式**：综合知识选择题。



#### 实际用途与常见问法

**关系代数的实际用途**：把 SQL 映射为可分析的表达式，从而理解执行过程、阅读执行计划、判断查询能否改写。

- **理解执行过程**：把一条查询逐步翻译为投影、笛卡尔积与选择的组合，即可看清它实际做了什么。
- **阅读执行计划**：执行计划中的扫描、连接、排序节点，对应关系代数中一个个具体运算，据此判断瓶颈所在。
- **判断可改写性**：两个表达式是否等价，用等价变换规则即可推导，从而判断某条查询能否安全重写。
- **软考常见问法**：给出关系与查询要求写出关系代数表达式；判断两个表达式是否等价；说明某条优化规则为什么能减少代价。

> **易混辨析**：软考中写出关系代数表达式与写出 SQL 语句是两类不同的题。前者要求给出运算树的形状，后者要求给出符合语法的语句。**SQL 的具体语法归第 4 篇，关系模式的规范化归第 5 篇**，本篇只负责运算体系与优化的原理层面。

> **速记**：**关系代数是用来看计划、判等价、做优化的，不是用来写业务 SQL 的**。

**考察形式**：综合知识选择题。
