## 函数依赖与规范化理论

> **全章主脉**：**函数依赖**（Functional Dependency，FD）是属性之间取值约束的形式化表达，也是判断关系模式优劣的唯一标尺。全章链条为：由函数依赖区分**部分依赖与传递依赖**，用**属性闭包**求**候选码**，用 **Armstrong 公理**推理并求得**最小依赖集**，再逐级判定 **1NF 至 BCNF**，最后在**无损连接**与**保持函数依赖**约束下完成模式分解。软考四种高频问法是**求候选码、判第几范式、判分解是否无损、选满足指定范式的分解方案**。

### 函数依赖的基本概念

#### 函数依赖的定义与形式化

**函数依赖**（Functional Dependency，FD）指：设关系模式 R(U)，X 与 Y 都是 U 的子集，若 R 的**任意两个元组**在 X 上取值相同，则它们在 Y 上取值也必然相同，此时称 X 函数决定 Y，记作 X 决定 Y。

- **形式化表述**：对任意元组 t1、t2，若 t1 在 X 上的分量等于 t2 在 X 上的分量，则它们在 Y 上的分量也相等。
- **两个角色**：X 是**决定因素**（Determinant），Y 是**被决定因素**；依赖有方向，X 决定 Y 不蕴含 Y 决定 X。
- **来源与范围**：依赖由**现实语义**决定，不能由某一时刻的数据反推；它约束**整个关系**，存在一对可能元组违反即不成立。
- **平凡与非平凡**：右部被左部完全包含的称**平凡函数依赖**（如（学号，课程号）决定 学号），恒真而无信息量；右部不被左部包含的称**非平凡函数依赖**（如 学号 决定 姓名），是设计、判定与分解真正使用的依赖。

> [!IMPORTANT]
> **重要内容**：判定问的是**「任意两行」而不是「现有某两行」**。表中所有行的 X 值互不相同，不能据此断言 X 决定 Y；语义上只要存在两行 X 相同而 Y 不同的可能，依赖即不成立。

> **速记线索**：三要素是**左属性集、右属性集、方向**；**右被左包是平凡，右不被左包才算数**。



#### 完全、部分与传递依赖的判定

**完全函数依赖**指 X 决定 Y 且 X 的任何真子集都不能决定 Y；**部分函数依赖**指存在 X 的真子集也能决定 Y；**传递函数依赖**指 X 决定 Y、Y 决定 Z，且 Y 不决定 X、Z 不属于 Y。

三步判定法如下，三步相互独立。

- **判完全与部分**：逐个去掉左部属性，若剩余部分仍能决定右部则为部分依赖，否则为完全依赖。
- **判传递**：寻找链式关系 X 决定 Y 与 Y 决定 Z，确认 Y 不决定 X 且 Z 不在 Y 中。
- **定归属**：完全依赖是范式欢迎的形态，部分依赖破坏 2NF，传递依赖破坏 3NF。

```text
R(学号, 姓名, 系名, 系主任, 课程号, 成绩)
F = { 学号→姓名, 学号→系名, 系名→系主任, (学号,课程号)→成绩 }，候选码 = (学号, 课程号)
部分依赖：学号→姓名、学号→系名 由左部真子集「学号」即可决定右部
完全依赖：成绩 去掉「学号」或去掉「课程号」都不能被决定；传递依赖：学号→系名、系名→系主任 构成链
结论：同时存在部分依赖与传递依赖，仅满足 1NF
```

> [!WARNING]
> **警告内容**：判部分依赖最常见的错误是**拿单属性候选码去套**。候选码只含一个属性时其真子集为空集，部分依赖不可能出现，该模式必然至少满足 2NF。

> **速记线索**：**去掉一个还成立就是部分，链子中间夹着一环就是传递**。



### 码与属性闭包的计算

#### 候选码、主属性与非主属性

**候选码**（Candidate Key）指能唯一确定每个元组、且任何真子集都不能唯一确定元组的最小属性集；从候选码中选定一个作为**主码**，出现在任一候选码中的属性称**主属性**，其余属性称**非主属性**。

- **两个条件**：能决定全部属性（属于超键），且**极小性**成立，即去掉任一属性后不再能决定全部属性。
- **主码与全码**：主码是人为选定、用于唯一标识元组的那一个，一个关系只有一个；唯一候选码即全部属性组成集合时称全码（All Key）。
- **主属性的判定**：只要属性出现在**任何一个候选码**中即为主属性，未出现在任何候选码中的属性才是非主属性。

> **辨析要点**：主属性**不等于主码中的属性**。判断标准是「有没有出现在某个候选码里」；多候选码情形应取全部候选码的并集，并集中的属性才是全部主属性。

> **速记线索**：**超键要能定全体，候选码还要极小，主码只是选出来的那一个**。



#### 属性闭包的计算与候选码求解

**属性闭包**指由属性集 X 出发能函数决定出来的全部属性的集合，记作 X 的闭包；求闭包就是把依赖反复展开直到集合不再增长。

算法与用途如下。

- **算法**：结果集初始为 X；反复查找左部已被结果集包含的依赖并并入其右部，直到不再增大，结果集即 X 的闭包。
- **判蕴含与等价**：X 决定 Y 被 F 蕴含，当且仅当 Y 包含在 X 的闭包中；F 与 G 等价，当且仅当逐条比对属性闭包结果一致。
- **筛起点**：从未出现在任何依赖右部的属性必入每个候选码，只出现在右部的属性不进任何候选码。

```text
R(A, B, C, D)，F = { (A,B)→C, C→D, D→A }，右部出现 C、D、A，B 从未出现在右部
(A,B) 闭包：含 C，C→D 得 D，D→A 得 A，得 ABCD，等于全集，是候选码
(B,C) 闭包：C→D 得 D，D→A 得 A，得 ABCD，等于全集，是候选码
(B,D) 闭包：D→A 得 A，A 与 B 齐备触发 (A,B)→C 得 C，得 ABCD，是候选码
(C,D) 闭包：得 ACD，缺 B，不等于全集，不是候选码；结论：候选码为 (A,B)、(B,C)、(B,D)，全部属性均为主属性
```

> [!TIP]
> **建议内容**：手算闭包**只朝一个方向走**，按轮次列写到集合稳定为止；求候选码先用「左部专有属性必进码」缩小范围，再逐个试算。

> **速记线索**：**左部在集合里，右部搬进来，搬到搬不动为止**。



### 公理系统与依赖集的等价

#### Armstrong 公理与依赖集的闭包

**Armstrong 公理**是函数依赖推理的公理系统，由**自反律、增广律、传递律**三条组成，其**可靠性与完备性**保证「公理推导」与「闭包验证」结果一致；**函数依赖集的闭包**是由依赖集 F 按公理能推出的全部依赖组成的集合。

- **自反律**（Reflexivity）：Y 是 X 的子集，则 X 决定 Y；只能推出平凡依赖，是推理起点。
- **增广律**（Augmentation）：X 决定 Y，则对任意属性集 Z，X 与 Z 的并集决定 Y 与 Z 的并集。
- **传递律**（Transitivity）：X 决定 Y 与 Y 决定 Z 均成立，则 X 决定 Z 成立。
- **四条推论**：合并律、分解律、伪传递律、伪增广律，均由三律导出，其中合并律用于合并同左部依赖，分解律用于把右部拆成单属性。
- **闭包与等价**：闭包把 F 隐含的依赖全部显式化，其规模随属性数急剧膨胀，故实际判定**改用属性闭包**；F 与 G 等价，当且仅当 F 的每条依赖能由 G 推出且 G 的每条依赖能由 F 推出。

> **辨析要点**：**依赖集闭包与属性闭包不是一回事**。前者是「一堆依赖的集合」，规模指数级；后者是「某属性集能决定的属性集合」，规模不超过属性全集，判蕴含、判候选码、判等价只用后者。

> **速记线索**：**自反包含恒成立，增广两边同加集，传递首尾接成链；依赖集闭包看全集，属性闭包看单点**。



#### 最小依赖集及其求解

**最小依赖集**（Minimal Cover，又称最小覆盖）指与给定依赖集 F 等价、且满足三个条件的依赖集，它删净了冗余，是范式分解的直接依据。

三个条件与求解顺序如下。

- **右部单属性**：每条依赖的右部只含一个属性。
- **左部无冗余属性**：每条依赖的左部去掉任一属性后都不再成立。
- **无冗余依赖**：删去任一依赖后所得集合与原集不等价；求解按化右部、去左部冗余、去冗余依赖、闭包复核四步执行。

```text
R(学号, 课程号, 姓名, 系名, 成绩)
F = { (学号,课程号)→成绩, 学号→姓名, 学号→系名, (学号,课程号)→姓名 }
化右部：右部均为单属性，集合不变
去左部冗余：(学号,课程号)→姓名 去掉「课程号」后 学号→姓名 成立，故化简为 学号→姓名
去冗余依赖：三条逐条试删，剩余集均推不出被删依赖，全部保留
结论：F_min = { (学号,课程号)→成绩, 学号→姓名, 学号→系名 }
```

> **辨析要点**：最小依赖集的**求解顺序会影响最终形态**，去属性先后不同可能得到不同的最小依赖集，但它们的闭包相同，因此都算正确答案，只需满足三个条件并与原集等价。

> **速记线索**：**右部拆单、左部去冗余、整体删多余、闭包验等价**。



### 范式及其判定

#### 第一范式与第二范式

**第一范式**（First Normal Form，1NF）要求每个属性都是**不可再分的原子值**；**第二范式**（Second Normal Form，2NF）在 1NF 基础上要求**每个非主属性都完全函数依赖于候选码**，不允许部分函数依赖。

- **1NF 的判定口径**：不允许属性值可再分，也不允许表中有表，违反者连关系的最低要求都不满足。
- **2NF 的判定口径**：不允许非主属性对候选码的部分函数依赖，即非主属性必须依赖整个候选码。
- **单属性候选码的推论**：候选码只含一个属性时真子集为空集，部分依赖不可能出现，必然满足 2NF。

> **辨析要点**：判 2NF 时**只检查非主属性**。主属性对候选码的部分依赖不属于 2NF 的范围，要到 3NF 与 BCNF 才管，把它纳入 2NF 检查会得出相反结论。

> **速记线索**：**1NF 看是否原子，2NF 看是否整码**。



#### 第三范式与 BC 范式

**第三范式**（Third Normal Form，3NF）在 2NF 基础上要求**非主属性不传递依赖于候选码**；**BC 范式**（Boyce-Codd Normal Form，BCNF）要求**每个非平凡依赖的左部都是超键**。

- **3NF 的判定口径**：对每个非平凡依赖 X 决定 Y，**X 是超键或者 Y 是主属性**，满足其一即可。
- **BCNF 的判定口径**：对每个非平凡依赖 X 决定 Y，**X 必须是超键**，不允许非超键属性成为决定因素。
- **次序与分歧点**：先 1NF、再 2NF、再 3NF、再 BCNF 逐级判定，不得跳级；两者只在**主属性作决定因素**时不同，3NF 容忍而 BCNF 不容忍。

```text
R(学生, 课程, 教师)，F = { (学生,课程)→教师, 教师→课程 }
候选码：(学生,课程) 闭包 = 全集；教师 决定 课程，故 (学生,教师) 闭包也为全集
3NF：(学生,课程)→教师 左部是候选码，合规；教师→课程 左部非超键但右部 课程 是主属性，允许
BCNF：教师→课程 的左部 教师 不是超键（教师 闭包 = { 教师, 课程 }），违反「决定因素必含候选码」
结论：满足 3NF，不满足 BCNF
```

> [!IMPORTANT]
> **重要内容**：**BCNF 与 3NF 的唯一分歧点是主属性作决定因素**。只要存在一个非平凡依赖，其左部不是超键而右部是主属性，模式就停在 3NF 而进不了 BCNF；若所有左部都是超键，则 3NF 与 BCNF 同时成立。

> **速记线索**：**3NF 管住非主属性，BCNF 管住所有左部，左部不是超键就出局**。



#### 各级范式的递进、反例与第四范式

四个范式的约束强度**逐级递增**，满足高一级必然满足低级，反之不成立；**多值依赖**（Multivalued Dependency，MVD）是 BCNF 之后的新问题。

- **包含关系**：1NF 包含 2NF，2NF 包含 3NF，3NF 包含 BCNF，BCNF 包含 4NF，逐级收紧。
- **违反与范式的对应**：部分依赖破坏 2NF，传递依赖破坏 3NF，非超键决定因素破坏 BCNF，非平凡多值依赖破坏 4NF。
- **多值依赖与第四范式**：多值依赖 X 多值决定 Y 描述**两组互相独立的多值取值**；**第四范式**（Fourth Normal Form，4NF）要求每个非平凡多值依赖的决定因素都包含候选码，用于消除独立多值属性并列造成的冗余，软考只要求知其存在与作用。

```text
反例一（满足 2NF 不满足 3NF）：R(学号, 姓名, 系名, 系主任)，F = { 学号→姓名, 学号→系名, 系名→系主任 }
  候选码 = 学号；单属性候选码不存在部分依赖，满足 2NF；存在传递链 学号→系名→系主任，不满足 3NF
反例二（满足 3NF 不满足 BCNF）：R(学生, 课程, 教师)，F = { (学生,课程)→教师, 教师→课程 }
  候选码 = (学生,课程) 与 (学生,教师)，全部属性均为主属性；教师→课程 的右部 课程 是主属性，满足 3NF
  但 教师 不是超键，不满足 BCNF
```

> **辨析要点**：两个反例用途不同——**「学号、姓名、系名、系主任」是 2NF 反例，「学生、课程、教师」是 3NF 反例**；题干结构与之同形时直接引用结论，再用一句依赖链说明理由。

> **速记线索**：**包含关系像同心圆，外圈松、内圈紧；2NF 卡部分，3NF 卡传递，BCNF 卡左部**。



### 模式分解与规范化设计

#### 无损连接性与无损分解的判定

**无损连接性**（Lossless Join）指关系模式 R 分解为若干子模式后，用自然连接重新组装得到的元组集合**与原关系完全一致**，不多也不少。

- **两分法判定**：R 分解为子模式 R1 与 R2 时，若**交集决定差集**（公共属性集决定其中一个子模式的独有属性集），则该分解是无损的。
- **直观依据**：公共属性必须是至少一个子模式的**候选码或超键**，连接时才不会产生虚假元组。
- **多子模式判定**：分解为三个及以上子模式时改用**表格法**（Chase 算法）逐列追赶，能追出一整行全为标记即为无损。

> [!WARNING]
> **警告内容**：无损连接**不等于「属性没丢」，而是「连接结果与原关系严格相等」**。公共属性既不是候选码也不能决定差集时，连接会凭空多出虚假元组，这就是有损分解，也是考试中最易判错的一步。

> **速记线索**：把 R(学号, 姓名, 系名, 系主任) 分解为 R1(学号, 姓名, 系名) 与 R2(系名, 系主任)，交集 系名 决定 R2 的差集 系主任，经验算即为无损；**交集决定差集即可，交集是候选码最保险**。



#### 保持函数依赖性与两个性质的兼顾

**保持函数依赖性**指分解后各子模式上成立的依赖并集，能够**逻辑蕴含原模式的全部依赖**；两项性质能否同时满足，取决于分解所达到的范式等级。

- **保持依赖的判定**：对原依赖集 F 中每条依赖 X 决定 Y，检查是否存在某个子模式**同时包含 X 与 Y**，每条都被承接即为保持依赖。
- **3NF 的结论**：**总可以找到同时满足无损连接与保持函数依赖的分解**，用合成法即可构造。
- **BCNF 的结论与取舍次序**：**总可以找到无损连接的分解，但不一定能同时保持函数依赖**；工程上优先保证无损连接，其次争取保持依赖，二者不可兼得时退回 3NF。

> [!IMPORTANT]
> **重要内容**：两项性质的**可保证边界**必须记准——**3NF 分解可以同时做到无损连接与保持函数依赖，BCNF 分解只保证无损连接、不保证保持函数依赖**。判据是依赖 X 决定 Y 的两个属性是否同时落在某个子模式内，未同时出现即该依赖未被保持。

> **速记线索**：**无损恒可保，依赖看范式；两全选 3NF，纯无损可上 BCNF**。



#### 范式到 3NF 的分解思路与范式取舍

把关系分解到 3NF 并同时满足无损连接与保持函数依赖，通行做法是**合成法**：求最小依赖集、按左部归并、必要时补候选码关系；而范式并非越高越好，须与读写负载匹配。

合成法步骤、范式取舍与软考套路如下。

- **求最小依赖集**：按四步化简原依赖集 F，得到 F_min。
- **按左部归并**：把 F_min 中左部相同的依赖合成一组，每组构成一个子模式，属性为该左部及其决定的全部右部。
- **补候选码关系**：若所得的每个子模式都不含原模式的候选码，则增加一个由候选码构成的子模式，以保证无损连接。
- **范式取舍与实务边界**：范式越高，表越多、连接越多，查询性能可能下降而更新一致性更好；**反规范化**（Denormalization）为提高查询性能有意引入冗余，读多写少、连接成为瓶颈时适用，写多且频繁变更时慎用；**宽表**以查询为中心聚合多实体属性，**维度建模**用事实表加维度表按分析口径组织，范式则是**联机事务处理**（On-Line Transactional Processing，OLTP）的默认基准，分析场景可偏离，但须以明确的性能收益与可接受的维护成本为前提。
- **软考四种问法**：求候选码看属性闭包；判第几范式按 1NF 至 BCNF 逐级用「部分依赖、传递依赖、非超键决定因素」三把尺子定位；判分解是否无损用两分法看交集是否决定差集、多子模式用 Chase 表；选分解方案先求最小依赖集再按左部归并，并同时检查无损与保持依赖。

```text
合成法演示：R(学号, 课程号, 姓名, 系名, 系主任, 成绩)
F = { (学号,课程号)→成绩, 学号→姓名, 学号→系名, 系名→系主任 }，候选码 = (学号, 课程号)
按左部归并：(学号,课程号) 组 → (学号, 课程号, 成绩)；学号 组 → (学号, 姓名, 系名)；系名 组 → (系名, 系主任)
补候选码：子模式 (学号, 课程号, 成绩) 已含候选码，无需补充
验性质：先并前两者、交集 学号 是后者候选码，再并第三者、交集 系名 是后者候选码，逐步无损，依赖全部落在子模式内
结论：得到无损连接、保持函数依赖的三子模式分解
```

> [!CAUTION]
> **注意内容**：**反规范化是有代价的取舍，不是设计缺陷，也不能滥用**。它把一致性维护成本从查询侧转移到更新侧，若引入冗余却缺乏约束与同步机制，就会产生更新异常与数据不一致。

> **速记线索**：**OLTP 走范式，分析走宽表；求码看闭包、判式看依赖、验解看交集、选解靠合成**。
