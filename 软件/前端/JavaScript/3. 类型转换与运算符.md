## 类型转换与运算符

### 数据类型转换

#### 类型转换的理解

**类型转换**：是指把一个值从一种数据类型**转换**为另一种数据类型的过程。JavaScript 作为动态类型语言，类型转换无处不在——显式调用转换函数，或在运算中由引擎**隐式**完成。

类型转换分为两大类：

- **显式转换（Explicit）**：开发者主动调用 `String()`、`Number()`、`Boolean()` 等函数或 `parseInt()` 等方法完成。
- **隐式转换（Implicit）**：引擎在特定运算符（`+`、`==`、`-`、`if` 条件等）中自动触发，无需开发者干预。

```js
// 显式转换
const num = Number("123");   // 123
const str = String(123);     // "123"

// 隐式转换
const result = "3" - 1;      // 2（"3" 被隐式转为数字）
const concat = "3" + 1;      // "31"（1 被隐式转为字符串）
```

> 隐式转换是 JavaScript 最常被诟病的特性之一：它让代码更简洁，却也制造了大量"看起来违背直觉"的结果。理解转换规则，是写出可靠代码、看懂面试题的前提。



#### ToPrimitive 与对象转原始值

**ToPrimitive**：是 ECMAScript 规范定义的一个**抽象操作**，用于把任意值（尤其是对象）转换为**原始值**。当对象参与运算或比较时，引擎都会先调用它。

ToPrimitive 的转换顺序（对普通对象）：

1. 若存在 `Symbol.toPrimitive` 方法，则**优先调用**它，直接返回结果。
2. 否则，若提示类型（hint）为 `"string"`，先调 `toString()`，不行再调 `valueOf()`。
3. 否则（hint 为 `"number"` 或 `"default"`），先调 `valueOf()`，不行再调 `toString()`。

```js
const obj = {
  [Symbol.toPrimitive](hint) {
    if (hint === "string") return "这是字符串";
    if (hint === "number") return 42;
    return "默认值";
  }
};

console.log(`${obj}`);        // "这是字符串"（string 提示）
console.log(+obj);            // 42（number 提示）
console.log(obj + "");        // "默认值"（default 提示）
```

> hint 的取值由**运算场景**决定：`+` 二元运算用 `"default"`，`Number()`、算术运算用 `"number"`，`String()`、模板字符串用 `"string"`。理解 hint 是预测对象转换结果的关键。



#### 转换为 String

将值转换为字符串有三种主要方式，结果存在细微差异。

- **`String(value)`**：通用的显式转换，规则清晰。
- **`value.toString()`**：对象方法，但 `null` 和 `undefined` 没有此方法，会报错。
- **`value + ""`**：借助隐式转换，与 `String()` 结果一致。

各类型的转换结果：

- `null` → `"null"`，`undefined` → `"undefined"`。
- `true` / `false` → `"true"` / `"false"`。
- 数字 → 对应的数字字符串，`NaN` → `"NaN"`，`Infinity` → `"Infinity"`。
- 对象 → 先走 ToPrimitive 再转字符串。

```js
console.log(String(null));       // "null"
console.log(String(undefined));  // "undefined"
console.log(String(true));       // "true"
console.log(String(123));        // "123"
console.log(String([1, 2, 3]));  // "1,2,3"（数组转字符串）
```

各类型的转换结果有一处反直觉：**`Symbol`** 不会出现在上表中，因为 Symbol 是唯一**无法被隐式转换**的类型。`String(symbol)` 能安全返回 `"Symbol(描述)"`，但字符串拼接 `"" + sym`、模板字符串 `` `${sym}` ``、`"".concat(sym)` 全部抛出 `TypeError`。这是 ECMAScript 规范中 `ToString` 抽象操作对 Symbol 的专门限制——防止 Symbol 在日志、界面中被意外"泄底"，强制开发者显式 `String()`。理解"显式可转、隐式必抛"这条规则，是 Symbol 转换的核心要点。

> `String()` 与 `toString()` 的差别在于对 `null`、`undefined` 的处理：前者安全（返回字符串），后者直接抛错。因此对"可能为空"的值，优先用 `String()`。



#### 转换为 Number

转换为数字的规则更为复杂，因为字符串、布尔、`null`、`undefined`、数组各有不同表现。

- **`Number(value)`**：严格转换，能转则转，否则得 `NaN`。
- **`parseInt(str, radix)` / `parseFloat(str)`**：从字符串**开头**尽量解析出数字，更宽松。
- **一元加号 `+value`**：等价于 `Number(value)`，是简洁的隐式写法。

各类型的转换结果：

- `null` → `0`，`undefined` → `NaN`。
- `true` → `1`，`false` → `0`。
- `""`（空字符串）→ `0`，非空纯数字字符串 → 对应数字，含非数字 → `NaN`。
- 数组：空数组 `[]` → `0`，单元素数组转该元素，多元素 → `NaN`。

```js
console.log(Number(null));       // 0
console.log(Number(undefined));  // NaN
console.log(Number(""));         // 0
console.log(Number("123"));      // 123
console.log(Number("123abc"));   // NaN
console.log(Number([1]));        // 1
console.log(Number([]));         // 0

console.log(parseInt("123abc")); // 123（宽松解析）
console.log(parseInt("abc"));    // NaN
```

> `Number()` 与 `parseInt()` 的核心区别：前者要求**整个字符串**都能转数字，后者只要**开头**是数字就尽量解析。`parseInt` 的第二个参数 `radix` 指定进制，应始终显式传入以避免 `"0x"` 之类的歧义。



#### 转换为 Boolean

转换为布尔值的规则最简单，只需记住"**六个假值**"即可，其余一切都是 `true`。

六个假值（转为 `false`）：

- `false`
- `0`、`-0`、`0n`（BigInt 零）
- `""`（空字符串）
- `null`
- `undefined`
- `NaN`

```js
console.log(Boolean(0));        // false
console.log(Boolean(""));       // false
console.log(Boolean(NaN));      // false
console.log(Boolean("0"));      // true
console.log(Boolean("false"));  // true（非空字符串都是真值）
console.log(Boolean({}));       // true
console.log(Boolean([]));       // true
```

> 两个最易错的陷阱：一是 `"false"` 字符串是**真值**（只有空字符串是假值）；二是 `{}` 和 `[]` 都是**真值**。在 `if`、`while` 等条件里，引擎会自动调用这套规则，掌握假值清单即可预判所有行为。



### 运算符的概念

#### 运算符与运算元

**运算符（Operator）**：是用于对数据进行运算的符号，如 `+`、`-`、`*`、`/`、`>`。**运算元（Operand）**：是运算符作用的对象，如 `1 + 2` 中的 `1` 和 `2`。

根据运算元的数量，运算符分为三类：

- **一元运算符**：只作用于一个运算元，如 `-x`（取负）、`!x`（取反）、`++x`。
- **二元运算符**：作用于两个运算元，如 `a + b`、`a * b`、`a > b`。
- **三元运算符**：作用于三个运算元，全语言只有**一个**——条件运算符 `a ? b : c`。

```js
const negative = -5;      // 一元：取负
const sum = 3 + 4;        // 二元：加法
const max = a > b ? a : b; // 三元：条件运算
```

> 同一个符号在不同位置可扮演不同角色：`-` 作为一元是"取负"，作为二元是"减法"。这种"运算符重载"需要结合上下文判断。



#### 逗号运算符与 void

有两个易被忽略的运算符，虽不常用，却是理解边界行为的关键。

- **逗号运算符（`,`）**：依次求值多个表达式，**返回最后一个表达式的值**。
- **`void` 运算符**：对表达式求值，但**始终返回 `undefined`**，常用于阻止跳转。

```js
// 逗号运算符：返回最后一个表达式的值
const result = (1, 2, 3);
console.log(result); // 3

let a = 0;
const b = (a++, a + 1); // 先 a 自增为 1，再返回 a + 1
console.log(b); // 2

// void：阻止默认跳转行为
<a href="javascript:void(0)">点我不跳转</a>
```

> 逗号运算符常出现在 `for` 循环的表达式部分，或 `(a++, b)` 这类"先执行副作用再取结果"的场景；`void 0` 则是获取 `undefined` 的经典写法，比直接用 `undefined` 更安全（后者可被当作变量名覆盖）。



### 算术与赋值运算符

#### 算术运算符

算术运算符用于数值计算，包括 `+`、`-`、`*`、`/`、`%`（取余）、`**`（幂）。

- **`+` 加法**：数字相加；但任一运算元是字符串时，触发**字符串拼接**。
- **`-` 减法**、**`*` 乘法**、**`/` 除法**：都会把运算元隐式转为数字再运算。
- **`%` 取余**：返回除法的余数，符号与被除数一致。
- **`**` 幂运算**：ES2016 引入，等价于 `Math.pow()`。

```js
console.log(5 + 2);      // 7
console.log("5" + 2);    // "52"（字符串拼接）
console.log(5 - "2");    // 3（"2" 转为数字）
console.log(5 * "3");    // 15
console.log(10 / 3);     // 3.3333333333333335
console.log(10 % 3);     // 1（取余）
console.log(-10 % 3);    // -1（符号随被除数）
console.log(2 ** 3);     // 8（2 的 3 次方）
```

> `+` 是唯一"既能加又能拼接"的运算符，其行为取决于**是否有字符串参与**。这是隐式类型转换最典型的案例：`"5" + 2` 得 `"52"`，而 `"5" - 2` 得 `3`——因为 `-` 没有拼接语义，只能转数字。



#### 赋值与链式赋值

**赋值运算符（`=`）**：把右侧的值赋给左侧的变量，其**返回值是被赋的值**，这使它支持链式赋值。

- 赋值运算**从右向左**结合。
- 赋值表达式的值，允许"边赋值边使用"。

```js
let a, b, c;
// 链式赋值：从右向左，把 10 依次赋给 c、b、a
a = b = c = 10;
console.log(a, b, c); // 10 10 10

// 赋值表达式有返回值
let x;
console.log(x = 5);   // 5（赋值表达式返回 5）
```

> 链式赋值虽然简洁，但可读性差、易埋坑（尤其在混合声明时）。团队规范通常**禁止**在 `if` 条件里写赋值（`if (x = 5)`），因为它极易与 `===` 混淆。



#### 原地修改

**原地修改（In-place modification）**：是指复合赋值运算符（`+=`、`-=`、`*=` 等）在**修改变量自身**的同时，也作为一个整体返回新值。它们本质是"运算 + 赋值"的简写。

```js
let n = 10;
n += 5;   // 等价于 n = n + 5
console.log(n); // 15
n *= 2;   // 等价于 n = n * 2
console.log(n); // 30
```

> 复合赋值运算符与普通赋值遵循相同的**从右向左**结合与优先级规则，`n += 5` 先算 `n + 5` 再赋回。这类运算符让累加、累乘等常见操作更简洁，是循环计数最常用的写法。



#### 自增与自减

**自增（`++`）** 与 **自减（`--`）**：是让变量加 1 或减 1 的一元运算符，分**前置**与**后置**两种形式，关键区别在于**返回值**。

- **前置 `++n`**：先加 1，**返回加之后的值**。
- **后置 `n++`**：先返回原值，**再加 1**。

```js
let a = 1;
const b = ++a;   // 前置：a 先变为 2，再赋给 b
console.log(a, b); // 2 2

let c = 1;
const d = c++;   // 后置：先把原值 1 赋给 d，c 再变为 2
console.log(c, d); // 2 1
```

> 无论前置后置，变量最终都会加 1，差别只在**表达式的返回值**。`let x = 1; console.log(x++)` 输出 `1` 而 `console.log(++x)` 输出 `2`，这是经典面试陷阱。



### 位运算符

#### 按位与、或、异或与非

**位运算符**：直接对数字的**二进制位**进行操作。JavaScript 中位运算会把数字先转为 **32 位有符号整数**，逐位运算后再转回。

- **`&` 按位与**：两位都为 1 结果才为 1。
- **`|` 按位或**：任一位为 1 结果即为 1。
- **`^` 按位异或**：两位不同结果为 1，相同为 0。
- **`~` 按位非**：每一位取反，等价于 `-(n + 1)`。

```js
const a = 5;   // 0101
const b = 3;   // 0011

console.log(a & b);  // 1（0001）
console.log(a | b);  // 7（0111）
console.log(a ^ b);  // 6（0110）
console.log(~5);     // -6（按位取反）
```

> 位运算速度极快但可读性差，日常业务代码中较少使用，多出现在**权限控制、状态标记、算法优化、图形/底层处理**等场景。理解其二进制本质即可，不必死记每种组合。



#### 左移与右移

移位运算符把二进制位整体向左或向右移动。

- **`<<` 左移**：所有位向左移动，右侧补 0，等价于乘以 2 的 n 次方。
- **`>>` 有符号右移**：向右移动，左侧补**符号位**（保持正负），等价于除以 2 的 n 次方并向下取整。
- **`>>>` 无符号右移**：向右移动，左侧**始终补 0**，结果恒为非负数。

```js
console.log(1 << 3);   // 8（1 左移 3 位 = 1 * 2^3）
console.log(8 >> 2);   // 2（8 右移 2 位 = 8 / 2^2）
console.log(-8 >> 1);  // -4（有符号右移，保留符号）
console.log(-1 >>> 1); // 2147483647（无符号右移，补 0）
```

> `<<` 和 `>>` 常用于**快速乘除 2 的幂**，`>>>` 则用于处理无符号整数。注意右移的两种形式在负数上的差异：`>>` 补符号位（负数仍为负），`>>>` 补 0（结果为正的大数）。



#### 位运算的应用

位运算虽冷门，但有若干经典应用，体现了"用位状态表达布尔集合"的思想。

- **奇偶判断**：`n & 1` 为 1 是奇数，为 0 是偶数。
- **交换两个数**（不用临时变量）：利用异或的自反性。
- **权限标志**：用整数的每一位表示一个开关，如 Linux 权限 `rwx`。

```js
// 判断奇偶
console.log(7 & 1);  // 1（奇数）
console.log(8 & 1);  // 0（偶数）

// 异或交换
let x = 5, y = 9;
x ^= y; y ^= x; x ^= y;
console.log(x, y); // 9 5

// 权限：读=1 写=2 执行=4
const READ = 1, WRITE = 2, EXECUTE = 4;
const permission = READ | WRITE;        // 3（可读可写）
console.log(permission & EXECUTE);      // 0（无执行权限）
```

> 权限标志是位运算最实用的场景：用**一个整数**存储多个布尔状态，既省内存又便于判断。`|` 用于**设置**权限，`&` 用于**检查**权限，`^` 或 `& ~` 用于**取消**权限。



### 比较运算符

#### 比较运算符的使用

比较运算符用于比较两个值，返回布尔结果。包括 `>`、`<`、`>=`、`<=`、`==`、`!=`、`===`、`!==`。

- 大小比较（`>`、`<` 等）在**不同类型**间比较时，会先做隐式转换。
- 字符串之间按**字典序**（逐字符比较 Unicode 码点）比较。
- `NaN` 与任何值（包括自己）比较都返回 `false`。

```js
console.log(5 > 3);          // true
console.log("5" > 3);        // true（"5" 转为数字）
console.log("apple" < "banana"); // true（字典序）
console.log("10" < "9");     // true（字符串比较，"1" < "9"）
console.log(NaN > 0);        // false
console.log(NaN === NaN);    // false
```

> 大小比较的隐式转换比相等比较更"激进"：`"10" < "9"` 是 `true`（按字符串），而 `10 < 9` 是 `false`（按数字）。混用类型参与比较是 bug 高发区，务必先统一类型。



#### == 与 === 的区别

**`==`（宽松相等）** 与 **`===`（严格相等）** 是相等判断的两种方式，核心区别在于**是否做类型转换**。

- **`===` 严格相等**：类型不同直接返回 `false`，**不做转换**，是最推荐、最安全的形式。
- **`==` 宽松相等**：类型不同时先**隐式转换**再比较，规则复杂、易出意外。

```js
console.log(1 === 1);        // true
console.log("1" === 1);      // false（类型不同）
console.log("1" == 1);       // true（宽松：字符串转数字）
console.log(null == undefined); // true（特例：二者宽松相等）
console.log(null === undefined); // false
console.log("" == 0);        // true（空字符串转 0）
```

> 业界共识：**一律使用 `===` 和 `!==`**，除非有明确理由。`==` 的转换规则（见下一节）有大量反直觉特例，是无数 bug 的源头，ESLint 的 `eqeqeq` 规则默认强制使用严格相等。



#### 抽象比较的 ECMA 规范

宽松相等 `==` 的转换规则由 ECMAScript 规范的 **Abstract Equality Comparison**（抽象相等比较）算法定义，理解它需要记住几条核心转换。

关键规则（`x == y`）：

- 类型相同 → 直接用 `===` 判断。
- `null == undefined` → `true`（唯一配对）。
- 数字与字符串 → 字符串转数字再比。
- 布尔与其他 → 布尔先转数字（`true` → `1`，`false` → `0`）再比。
- 对象与原始值 → 对象走 ToPrimitive 转原始值再比。

```js
// 布尔转数字：true == 1
console.log(true == 1);      // true
// 对象转原始值：[1] 转 "1"，再转 1
console.log([1] == 1);       // true
// 经典怪例：[] 转 ""，"" 转 0，false 转 0
console.log([] == false);    // true
console.log([] == 0);        // true
```

> `[] == false` 为 `true` 是宽松相等最著名的怪例，其推演链是：`[]` 经 ToPrimitive 得 `""`，`""` 转数字得 `0`，`false` 转数字得 `0`，最终 `0 == 0`。这种"绕圈转换"正是 `==` 被诟病的根源。



### 逻辑运算符

#### 逻辑运算符的使用

逻辑运算符用于组合布尔条件，包括 `&&`（与）、`||`（或）、`!`（非），返回结果**不一定是布尔值**。

- **`&&` 逻辑与**：两个都为真才为真。
- **`||` 逻辑或**：任一为真即为真。
- **`!` 逻辑非**：取反，始终返回布尔值。

```js
const hasAge = true;
const hasName = true;
if (hasAge && hasName) {
  console.log("信息完整");
}
if (hasAge || hasName) {
  console.log("至少有一项");
}
console.log(!true);  // false
console.log(!0);     // true（0 是假值）
```

> 逻辑运算遵循**短路求值**：`&&` 遇到假值立即停止并返回该假值，`||` 遇到真值立即停止并返回该真值。这一特性被广泛用于**默认值**和**条件执行**，下一节详述。



#### 逻辑或的本质

**逻辑或 `||` 的本质**：不是返回布尔值，而是**返回第一个为真的操作数**；若都为假，则返回最后一个操作数。它常用于**设置默认值**。

```js
// 返回第一个真值
console.log(0 || "default");   // "default"（0 是假值）
console.log("hello" || "world"); // "hello"（第一个就是真值）
console.log(null || undefined || "x"); // "x"

// 用于默认值
const name = userName || "匿名";
```

> `||` 设默认值的局限：当合法值本身就是假值（如 `0`、`""`、`false`）时会被误替换。例如 `count || 10`，若 `count` 为 `0` 会错误地取 `10`。这正是 ES2020 引入**空值合并运算符 `??`** 的原因——它只在值为 `null`/`undefined` 时兜底。



#### 逻辑与的本质

**逻辑与 `&&` 的本质**：**返回第一个为假的操作数**；若都为真，则返回最后一个操作数。它常用于**条件执行**（存在性检查）。

```js
// 返回第一个假值
console.log(1 && 0);          // 0
console.log(1 && 2 && 3);     // 3（都为真，返回最后一个）
console.log(null && "hello"); // null

// 用于条件执行：obj 存在时才访问其属性
obj && obj.method();
```

> `&&` 的"条件执行"写法在现代 JavaScript 中逐渐被**可选链 `?.`** 取代：`obj && obj.method()` 可简写为 `obj?.method()`，语义更清晰、也更安全（能正确处理 `0`、`""` 等假值）。



#### 逻辑非

**逻辑非 `!`**：对操作数取反，与 `&&`、`||` 不同，它**始终返回布尔值**。连续两次取反 `!!value` 是**转布尔值**的惯用技巧。

```js
console.log(!true);    // false
console.log(!0);       // true
console.log(!"hello"); // false
console.log(!null);    // true

// 双重取反：将任意值转为布尔
console.log(!!1);      // true
console.log(!!0);      // false
console.log(!!"text"); // true
```

> `!!value` 本质等价于 `Boolean(value)`，是代码中最常见的"转布尔"简写。理解 `!` 的两步走：先按假值规则把操作数转布尔，再取反。



### 运算符的优先级

**运算符优先级**：决定在包含多个运算符的表达式中，**哪些运算先进行**。优先级高的运算符先被求值，同优先级则按**结合性**（从左或从右）决定顺序。

JavaScript 运算符优先级从高到低的关键层级（节选）：

- **最高**：成员访问 `.`、`[]`、`()` 调用、`new`。
- **一元**：`!`、`+`、`-`、`++`、`--`、`typeof`、`void`、`delete`。
- **算术**：`**` > `*` `/` `%` > `+` `-`。
- **移位**：`<<` `>>` `>>>`。
- **比较**：`<` `<=` `>` `>=` `in` `instanceof`。
- **相等**：`==` `!=` `===` `!==`。
- **按位**：`&` > `^` > `|`。
- **逻辑**：`&&` > `||`。
- **条件**：`?:`（三元）。
- **最低**：赋值 `=` 及复合赋值、逗号 `,`。

```js
// 算术优先于比较
console.log(1 + 2 * 3);      // 7（先 2*3）
// && 优先于 ||
console.log(false || true && false); // false（先 true && false）
// 赋值优先级最低
const result = 1 + 2 === 3;  // 先算 1+2，再比较
console.log(result);         // true
```

> 两条实用原则：一是**记不住优先级就加括号**，`(1 + 2) * 3` 比死记优先级更清晰可靠；二是 `&&` 高于 `||`、`===` 高于 `&&`、`?:` 高于 `=` 这几个最常见关系要心中有数。
