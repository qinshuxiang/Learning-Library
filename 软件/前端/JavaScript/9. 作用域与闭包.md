## 作用域与闭包

### 作用域的概念

**作用域**是一个变量或函数的作用范围，在**函数定义时**就已确定，决定了代码中变量和资源的可见性。其目的是提高程序可靠性、减少命名冲突。

ES5 中有两种作用域：

- **全局作用域**：作用于整个 script 标签或独立 JS 文件。
- **函数作用域**（局部作用域）：作用于函数内部。

在全局作用域中，用 `var` 声明的变量和函数会作为 `window` 对象的属性和方法保存。

### 作用域的访问关系

内层作用域可以访问外层作用域的变量，外层作用域无法访问内层作用域的变量。查找变量时采用**就近原则**：先在自身作用域找，找不到就向上级找，直到全局；全局仍找不到则报 `ReferenceError`。

### 变量提升

浏览器解析 JS 代码前会进行**预处理（预解析）**，把所有 `var` 变量声明和函数声明放到代码最前面，这称为声明提前（变量提升）。

- 用 `var` 声明的变量会被提前声明（但不赋值），值为 `undefined`。
- **函数声明**（`function foo(){}`）会整个提前，可在定义前调用。
- **函数表达式**（`var foo = function(){}`）不会提前（只提升变量名，不提升函数体）。

> 函数内省略 `var` 直接赋值的变量会成为全局变量，但不会声明提前，且需先调用函数才可用。

### 块级作用域（ES6）

ES6 新增了块级作用域，通过 `let` 和 `const` 声明。块级作用域在函数内部或代码块（花括号）内部被创建，其特点：

- 声明变量不会提升到代码块顶部（存在暂时性死区）。
- 禁止重复声明。

`var`、`let`、`const` 的区别：

- `var`：函数作用域，可跨块访问，不能跨函数；会提升；允许重复声明。
- `let`、`const`：块级作用域，不能跨块也不能跨函数；不提升（TDZ）；不允许重复声明。
- `const` 还必须初始化，且不能重新赋值（但可修改引用类型的属性）。

> `const` 保证的是变量指向的**内存地址**不变，不是值不变：`const obj = {}` 后可以 `obj.name = 'x'`，但不能 `obj = {}`。

### 词法作用域与动态作用域

- **词法作用域（静态作用域）**：作用域在**函数定义的位置**就确定，与调用位置无关。
- **动态作用域**：作用域在**调用时**确定，取决于调用链。

JavaScript 采用的是**词法作用域**。

### 执行上下文与执行栈

作用域是「静态规则」，而**执行上下文**是「运行时环境」。执行上下文分为三类：全局执行上下文、函数执行上下文、Eval 执行上下文。

**执行栈（调用栈）**管理这些上下文，遵循**后进先出**。每调用一次函数就创建一个新的、相互独立的上下文；函数执行完，其上下文出栈销毁。

> VO/AO 是 ES3 的说法，ES5 之后规范改用「词法环境 + 变量环境」描述同一件事：`var` 和 `function` 声明进变量环境（会提升为 undefined），`let`/`const`/`class` 进词法环境（有 TDZ）。

### 暂时性死区（TDZ）

**暂时性死区**：从进入当前作用域开始，到 `let`/`const` 声明语句执行完成为止，该变量不可访问。

- TDZ 内连 `typeof` 也会报错（与完全未声明的变量表现不同）。
- `var` 没有 TDZ，会提升为 `undefined`。
- `let`/`const` 其实也提升了，只是没初始化，所以在声明前访问会报 `ReferenceError`。

### 闭包的本质

**闭包**是能够访问另一个函数作用域中变量的函数。底层机制是：每个函数在定义时都会保存一个对外层词法环境的引用（内部属性 `[[Environment]]`），只要内层函数还活着，它引用的外层环境就不会被垃圾回收，即使外层函数早已执行完毕。

```js
function makeCounter() {
  let count = 0;
  return function () {
    return ++count;
  };
}
const counter = makeCounter();
console.log(counter()); // 1
console.log(counter()); // 2
```

每一次调用 `makeCounter()` 都会创建全新的、互相独立的词法环境。

### 闭包的经典陷阱：循环里的 var

```js
for (var i = 0; i < 3; i++) {
  setTimeout(function () {
    console.log(i);
  }, 100);
}
// 打印结果：3 3 3
```

因为 `var i` 在整个作用域中只有一份绑定，循环结束后 `i` 已是 3，三个回调共享同一个 `i`。三种解法：

- 改用 `let`（最推荐）：每次迭代创建新的块级绑定，各回调捕获不同的值。
- IIFE 立即执行函数：用形参把每轮的 `i` 拷贝一份。
- 利用 `setTimeout` 的第三个参数传参。

### 闭包的典型应用

- **数据私有化与模块化**：用闭包隐藏内部变量，只暴露接口（IIFE 模块模式）。
- **函数柯里化**：把一个多参函数转换成一系列单参函数。
- **防抖（debounce）**：触发后等待 delay 再执行，期间再触发则重新计时。
- **节流（throttle）**：无论触发多频繁，delay 内只执行一次。
- **缓存/记忆化（memoize）**：闭包持有缓存，避免重复计算。

防抖与节流的区别一句话：防抖是「等你停下来了，我再做」，节流是「不管你多急，我按自己的节奏来」。

### 闭包的代价：内存泄漏

闭包让本该销毁的变量继续存活，是一把双刃剑。典型泄漏场景是：闭包引用大对象，且该闭包长期存活（挂在全局、DOM、定时器上）。规避手段：不再需要时解除引用、移除 DOM 节点前先解绑、把大对象放到闭包之外或用完置空。

### 作用域链与原型链的区别

两者查找目标完全不同，别混淆：

- **作用域链**查找的是**变量/函数标识符**，在函数**定义时**确定（词法作用域），找不到时抛 `ReferenceError`。
- **原型链**查找的是**对象的属性/方法**，在对象**创建时**确定，找不到时返回 `undefined`（不报错）。
