## JavaScript 简介与编写方式

### 编程语言与计算机语言

#### 前端的三大核心

前端开发由三大技术支柱构成，三者各司其职、缺一不可：**HTML**（结构）负责"有什么"，**CSS**（表现）负责"长什么样"，**JavaScript**（行为）负责"能做什么"。HTML 与 CSS 属于**声明式**语言——开发者描述"结果是什么"；而 JavaScript 是**命令式**（同时也支持声明式范式）语言——开发者描述"一步步怎么做"。

- **HTML（HyperText Markup Language，超文本标记语言）**：描述网页的**结构与内容**，用标签把文字、图片、链接等组织成文档树。
- **CSS（Cascading Style Sheets，层叠样式表）**：描述网页的**样式与布局**，控制颜色、字体、间距、定位等视觉表现。
- **JavaScript**：描述网页的**交互与逻辑**，响应用户操作、处理数据、调用浏览器能力。

> 三者关系可类比盖房子：HTML 是**骨架**，CSS 是**装修**，JavaScript 是**水电与智能设备**——让房子"活"起来。没有 JavaScript 的页面也能看，但无法与用户"对话"。



#### 计算机语言与编程语言的定义

**计算机语言**：是人与计算机之间沟通的**形式化语言**，由一套明确的语法（规则）和语义（含义）构成，用于让计算机执行特定的计算或操作。它分为**低级语言**与**高级语言**两类。

**编程语言**：是计算机语言的一种，指**用于编写程序（指令序列）的高级语言**，具备更强的可读性和抽象能力，离自然语言更近、离机器指令更远。

- **机器语言**：由 `0` 和 `1` 组成的二进制指令，是 CPU 唯一能直接执行的代码，但人几乎无法直接编写和阅读。
- **汇编语言**：用助记符（如 `MOV`、`ADD`）代替二进制，与机器指令一一对应，需经**汇编器**翻译，可读性略高但仍是低级语言。
- **高级语言**：如 JavaScript、Python、C++，抽象了硬件细节，靠**编译器**或**解释器**翻译后运行。

> 判断一门语言是高级还是低级，标准是**抽象程度与可移植性**，而不是"难度"。汇编语言直接操作寄存器和内存地址，换一台 CPU 就可能无法运行；高级语言则屏蔽了这些差异。



#### 编程语言的发展历程

编程语言的发展是一个**不断抽象、不断靠近人类思维**的过程，大致经历四个阶段。

- **第一代：机器语言**——纯二进制，人类直接写 `0110` 之类的指令，极易出错、不可维护。
- **第二代：汇编语言**——用助记符替代二进制，但仍是"面向机器"的思维。
- **第三代：高级语言**——C、C++、Java 等，用接近自然语言的语法描述算法，面向"过程"或"对象"。
- **第四代：更高级的脚本与领域语言**——JavaScript、Python、SQL 等，追求快速开发和易读性。

> 从机器语言到 JavaScript，本质是**人机接口**的进化：把"人迁就机器"逐步变成"机器迁就人"。抽象每上升一层，开发效率提升一档，但运行效率往往下降一档——高级语言需要更多的翻译与运行时开销。



### JavaScript 的起源与发展历史

#### JavaScript 的诞生历史

JavaScript 诞生于 1995 年，由网景公司（Netscape）的程序员**Brendan Eich** 创造，最初目的只有一个：让网页"动起来"，即在浏览器里做一些轻量的表单校验和交互，而无需刷新页面或与服务器通信。

##### 十天设计与三次命名

JavaScript 的核心设计**只用了十天**完成（1995 年 5 月），如此仓促的诞生为这门语言埋下了诸多"历史遗留"的设计缺陷（如隐式类型转换、`==` 的诡异行为），但也正因如此，它保持了极高的灵活性和上手速度。

这门语言经历了**三次命名**：

1. **Mocha（摩卡）**：网景公司内部的原始代号。
2. **LiveScript**：发布前改名，强调其"活"的交互能力。
3. **JavaScript**：1995 年 12 月，网景与 Sun 公司合作后最终定名，借用了当时正火的 Java 的知名度。

> 三次改名反映了一段经典的"营销绑架"：JavaScript 与 Java **没有实质关系**，命名只是为了蹭 Java 的热度，却导致此后近三十年无数人误以为两者同源。



##### 浏览器大战与 JScript

1995 年前后正值**第一次浏览器大战**：网景 Navigator 与微软 Internet Explorer（IE）争夺市场。微软不甘落后，于 1996 年推出了自己的脚本语言 **JScript**。

- **JScript** 是微软对 JavaScript 的**逆向实现**，语法高度相似但实现细节有差异。
- 两家浏览器各自为政，导致**同一段脚本在不同浏览器下表现不一致**，开发者被迫写大量兼容代码。
- 这种混乱局面最终催生了标准化诉求——如果放任不管，JavaScript 将分裂成互不兼容的方言。

> 浏览器大战是 JavaScript 历史上最重要的"危机"，也是"转机"：正因为兼容性之痛，网景才在 1996 年 11 月向 ECMA 国际提交标准，最终诞生了 ECMAScript。



#### JavaScript 的组成

JavaScript 是一个**由三部分组成的复合体**，日常说的"JavaScript"其实覆盖了不同标准的拼盘，理解这一点是区分语言与运行环境的关键。

- **ECMAScript（核心语言）**：由 ECMA-262 标准定义，规定语法、类型、语句、关键字、对象等语言本身的内容，与运行环境无关。
- **DOM（Document Object Model，文档对象模型）**：由 W3C 维护，提供操作网页文档（元素、属性、文本）的接口，如 `document.querySelector()`。
- **BOM（Browser Object Model，浏览器对象模型）**：浏览器自行提供的、未标准化的对象集合，如 `window`、`location`、`history`、`navigator`。

> 三者分工清晰：**ECMAScript 决定语言"怎么写"，DOM 决定"怎么改网页"，BOM 决定"怎么控制浏览器"**。Node.js 里没有 DOM 和 BOM，只有 ECMAScript 加 Node 自带的模块，这正说明 ECMAScript 才是语言本体。



#### JavaScript 的学习路线

学习 JavaScript 应遵循一条由内而外、由语言到平台的路径，各阶段环环相扣。

1. **语言核心（ECMAScript）**：变量、类型、运算符、流程控制、函数、对象、原型、闭包、this、异步等——这是地基，决定你写出的代码对不对。
2. **浏览器平台（DOM 与 BOM）**：操作网页、处理事件、发起网络请求、存储数据——这是主战场，决定你能不能让页面动起来。
3. **工程化与生态**：模块化、打包工具（如 webpack、Vite）、框架（如 Vue、React）、TypeScript、Node.js 等——这是进阶，决定你能不能高效协作、构建大型应用。

> 初学者最容易犯的错误是**跳过语言核心直接学框架**：框架语法更新换代极快，而语言核心相对稳定，把地基打牢，框架只是"换汤不换药"的封装。



#### ECMAScript 的标准化与版本演进

**ECMAScript** 是 JavaScript 的**语言标准**，由 **ECMA 国际**下属的 **TC39** 技术委员会负责制定和维护。自 1996 年网景提交标准以来，它经历了从"长期停滞"到"每年发布"的转变。

- **ES3（1999）**：第一版被广泛实现的标准，奠定了语言的基本形态，统治了 Web 近十年。
- **ES5（2009）**：引入严格模式、`JSON`、数组新方法（`forEach`、`map` 等），修复了大量 ES3 的缺陷。
- **ES6 / ES2015（2015）**：有史以来最大的一次更新，引入 `let`、`const`、箭头函数、`class`、`Promise`、模块、解构等，是"现代 JavaScript"的起点。
- **ES2016 起**：改为**每年发布一个小版本**，用年份命名（ES2017、ES2018……），特性增量式添加。

> 命名上有两个体系并存：ES6 = ES2015，ES7 = ES2016，以此类推。业界常说的"ES6+"泛指 ES2015 及之后的所有现代特性。



#### JavaScript 与 Java 的区别

JavaScript 与 Java 除了名字相似，**在语言设计上几乎毫无关系**，把它们相提并论是长期以来的误解。

- **类型系统**：Java 是**静态强类型**语言，编译时确定类型；JavaScript 是**动态弱类型**语言，运行时才确定类型，变量可随时改类型。
- **编译方式**：Java 是**编译型**语言，先编译成字节码再在 JVM 上运行；JavaScript 传统上是**解释型**语言（现代引擎则采用 JIT 即时编译，见后文引擎部分）。
- **运行环境**：Java 主要用于服务端、桌面与 Android；JavaScript 最初只跑在浏览器里，如今经 Node.js 也能跑在服务端。
- **面向对象模型**：Java 基于**类**的继承；JavaScript 基于**原型**的继承（ES6 的 `class` 只是原型链的语法糖）。

> 一句话记牢：**Java 之于 JavaScript，如同"雷锋"之于"雷峰塔"**——名字沾边，本质无关。二者被绑定纯属当年的营销决策。



### JavaScript 的运行引擎

#### JavaScript 引擎的理解

**JavaScript 引擎**：是**解析并执行 JavaScript 代码的程序**，可以理解为"把源码翻译成机器指令并运行"的翻译官与执行器。任何想运行 JavaScript 的环境——浏览器、Node.js、甚至是嵌入式设备——都必须内置一个引擎。

- 引擎的核心任务：**词法分析 → 语法分析 → 生成字节码/机器码 → 执行**。
- 现代引擎普遍采用 **JIT（Just-In-Time，即时编译）** 技术：不再逐行解释，而是把热点代码编译成机器码，大幅提升性能。
- 引擎只是"执行器"，语言标准（ECMAScript）才是"法律"——各引擎都要遵循同一标准，保证代码跨环境一致。

> 引擎的存在让 JavaScript 摆脱了"纯解释型语言慢"的刻板印象。现代引擎配合 JIT，其性能已接近甚至追平部分静态语言。



#### V8 引擎

**V8 引擎**：是 Google 用 C++ 开发的高性能 JavaScript 与 WebAssembly 引擎，2008 年随 Chrome 发布，是目前最著名、使用最广的 JavaScript 引擎之一。

- **核心亮点**：首次大规模应用 **JIT 即时编译**，将 JavaScript 直接编译为机器码执行，性能远超当时的解释器，直接带动了整个 Web 的性能革命。
- **关键组件**：包含**解析器**（Ignition，生成字节码）与**优化编译器**（TurboFan，编译热点函数）、**垃圾回收器**（分代回收）等。
- **影响力**：V8 的成功催生了 **Node.js**——2009 年 Ryan Dahl 把 V8 从浏览器中"抠"出来，让 JavaScript 第一次跑在服务端，开启了全栈时代。

> 各浏览器引擎各不相同：Chrome / Edge 用 **V8**，Firefox 用 **SpiderMonkey**（JS 引擎的鼻祖），Safari 用 **JavaScriptCore（JSC）**。引擎多样但语言统一，这正是标准化的意义所在。



### JavaScript 的应用场景

#### JavaScript 的重要性

JavaScript 是**当今唯一一门能够同时运行在浏览器、服务端、桌面、移动端的通用语言**，其重要性由事实而非观点支撑。

- **浏览器端**：JavaScript 是 Web 平台**唯一**原生支持的编程语言，所有网页交互都离不开它。
- **全栈开发**：Node.js 让 JavaScript 从"只能在浏览器里跑"变成"前后端通吃"，一套语言打通全链路。
- **生态规模**：npm 是全球最大的软件包仓库，拥有数百万个包；Vue、React、Angular 等框架统治了前端领域。
- **跨端能力**：React Native、Electron、小程序等让 JavaScript 能开发 App、桌面软件乃至小程序。

> 主流编程语言排名（如 TIOBE、GitHub Octoverse）中，JavaScript 长期稳居前列。对前端开发者而言，它不是"可选项"，而是"唯一答案"。



#### 常见的应用场景

JavaScript 的应用早已超出"网页特效"的范畴，覆盖了软件开发的方方面面。

- **网页交互**：表单校验、轮播图、下拉菜单、懒加载、动画等——JavaScript 的本职工作。
- **单页应用（SPA）**：配合 Vue、React 等框架构建体验流畅、无需整页刷新的应用。
- **服务端开发**：用 Node.js 编写 API 服务、中间件、构建工具（如 webpack、Vite）。
- **移动端与桌面端**：React Native / Uni-app 开发 App，Electron 开发桌面软件（如 VS Code、Slack）。
- **小程序**：微信、支付宝等小程序均使用 JavaScript 生态（或类 JS 语言）开发。
- **数据可视化**：借助 ECharts、D3.js 等库绘制图表与可视化大屏。

> 一个广为人知的说法："**任何能够用 JavaScript 实现的应用，最终都会被用 JavaScript 实现**"（Atwood 定律）。虽有夸张，却精准概括了这门语言的渗透力。



### JavaScript 的编写方式

#### 三种编写方式

JavaScript 有三种引入网页的方式，按**推荐程度**由高到低排列。

1. **外部文件（推荐）**：将代码写入独立的 `.js` 文件，通过 `<script src="path/to/file.js"></script>` 引入。
2. **内联脚本**：在 HTML 中直接写 `<script>` 标签，把代码放在标签内部。
3. **行内脚本**：把代码写在 HTML 元素的**事件属性**里，如 `<button onclick="alert('hi')">`。

外部文件方式的示例：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <title>引入 JavaScript</title>
</head>
<body>
  <!-- 通过 src 引入外部脚本 -->
  <script src="./js/main.js"></script>
</body>
</html>
```

> 三种方式的取舍是**维护性与性能**的博弈：外部文件可被浏览器**缓存**、实现**结构与行为分离**、便于多人协作，是唯一推荐的生产级做法；内联脚本仅适合极小的演示；行内脚本把逻辑耦合进 HTML，既难维护又容易引发 CSP（内容安全策略）问题，应尽量避免。



#### noscript 元素

`<noscript>` 元素用于**在浏览器不支持或禁用了 JavaScript 时，向用户展示替代内容**。它是一种优雅降级的兜底手段。

```html
<script>
  document.write("欢迎使用本网站");
</script>
<noscript>
  <p>您的浏览器未启用 JavaScript，部分功能无法使用。</p>
</noscript>
```

- 当 JavaScript 可用时，浏览器会**忽略** `<noscript>` 里的内容。
- 当 JavaScript 被禁用或浏览器不支持时，浏览器会**渲染** `<noscript>` 里的内容作为提示。

> `<noscript>` 体现的是"渐进增强"思想：核心内容不依赖脚本也能被看到，脚本只是增强体验。这与"整站靠脚本渲染、禁了 JS 就白屏"的现代 SPA 形成了鲜明对照。



#### 编写的注意事项

编写 JavaScript 时，几个基础但关键的细节需要牢记。

- **`<script>` 会阻塞 HTML 解析**：浏览器遇到 `<script>` 时，默认会暂停后续 HTML 的解析，先去下载并执行脚本，导致页面渲染变慢。这正是常把脚本放在 `</body>` 前、或使用 `defer` / `async` 属性的原因。
- **`src` 与内联不可兼得**：一个 `<script>` 标签若写了 `src`，其标签内的代码会被忽略，不会执行。
- **JS 大小写敏感**：`var name` 与 `var Name` 是两个不同变量，关键字、变量名、函数名都必须区分大小写。
- **编码统一**：HTML、JS 文件都应统一为 UTF-8 编码，避免中文乱码。

> `defer` 与 `async` 的区别是高频考点：`defer` 让脚本在 HTML 解析完成后、`DOMContentLoaded` 事件前**按顺序**执行；`async` 让脚本**下载完就立即执行**，不保证顺序，适用于无依赖的独立脚本。



### 基础语法与规范

#### 语句与分号

**语句**：是 JavaScript 的基本执行单位，由表达式、关键字和运算符组成，通常以**分号（`;`）结尾**。

```js
// 每条语句以分号结尾
const greeting = "Hello";
console.log(greeting);
```

- 分号用于**分隔**语句，明确告诉引擎"这条语句到这里结束"。
- 语句可以写在同一行，也可以跨行书写，但**一行多条语句**时必须用分号分隔。
- 虽然 JavaScript 允许**省略分号**（靠 ASI 自动补全），但显式书写分号是更稳妥、争议更少的做法。



##### 自动分号插入（ASI）

**ASI（Automatic Semicolon Insertion，自动分号插入）**：是 JavaScript 引擎在解析时，**自动在"需要分号却没有写"的位置补上分号**的机制。它让省略分号在大多数情况下"看起来能用"，但也埋下了隐蔽的坑。

```js
// 看似没问题，实际 return 后会被自动插入分号，导致返回 undefined
function getValue() {
  return
  {
    name: "foo"
  }
}
console.log(getValue()); // undefined
```

- ASI 只在**换行**处、且不补分号会导致语法错误时才会触发。
- 最经典的陷阱是 `return`、`break`、`continue` 等关键字后**紧跟换行**：ASI 会在此处插入分号，使后面的值或语句"脱节"。
- 以 `(`、`[`、`+` 等开头的行，若前一行的末尾省略分号，也可能被错误合并。

> 规避 ASI 陷阱的最佳实践：**始终显式写分号**，并让 `return` 的返回值紧跟其后（不要换行）。团队规范（如 ESLint 的 `semi` 规则）通常强制统一，避免风格混用。



#### 三种注释

注释是写给**人**看的说明，JavaScript 引擎会忽略注释内容。JavaScript 支持三种注释。

1. **单行注释**：以 `//` 开头，直到行尾。
2. **多行注释**：以 `/*` 开头、`*/` 结尾，可跨行。
3. **文档注释**：以 `/** ... */` 开头，常用于描述函数、生成 API 文档（JSDoc 规范）。

```js
// 这是单行注释

/*
  这是多行注释
  可以跨越多行
*/

/**
 * 计算两个数的和
 * @param {number} a 第一个加数
 * @param {number} b 第二个加数
 * @returns {number} 两数之和
 */
function add(a, b) {
  return a + b;
}
```

> 注释不是越多越好：好的注释解释**"为什么"**（设计意图、坑），而不是复述**"是什么"**（代码本身已表达的）。命名清晰的代码应尽量自解释，注释用于补足无法从代码中读出的信息。



#### 代码规范

代码规范是**团队协作的契约**，其核心目标不是"哪个写法更好"，而是"**让所有人的代码看起来像同一个人写的**"，从而降低阅读与维护成本。

- **命名规范**：变量和函数用**小驼峰**（`userName`、`getUserById`），类与构造函数用**大驼峰**（`Person`、`HttpClient`），常量可用全大写加下划线（`MAX_COUNT`）。
- **缩进与空白**：统一用空格缩进（常见 2 或 4 空格），运算符、逗号后留空格，提升可读性。
- **引号与分号**：统一单引号或双引号（模板字符串用反引号），统一是否加分号。
- **风格一致**：一个项目内只允许一种风格，禁止混用。

> 规范的价值在于**一致性**而非"正确性"：`2 空格`和`4 空格`本身没有对错，但混用就会造成灾难。这也是 ESLint 这类工具存在的意义——把"人遵守的约定"变成"机器强制执行的规则"。



#### 编程风格与 ESLint

**ESLint**：是目前最主流的 JavaScript **静态代码检查工具**，它通过**可配置的规则**在编码阶段就发现潜在错误与风格问题，是"代码规范落地"的工业标准。

- **静态分析**：不运行代码，仅靠解析源码找出问题（如未使用变量、可能的分号遗漏、拼写错误）。
- **可配置**：通过 `.eslintrc` 或 `eslint.config.js` 配置文件开启 / 关闭规则，也可直接继承社区预设（如 `eslint:recommended`、`airbnb` 风格）。
- **可自动修复**：`eslint --fix` 能自动修正大量风格类问题（缩进、引号、分号等）。

```js
// 例：eslint.config.js 中的一段配置（示意）
export default [
  {
    rules: {
      "no-unused-vars": "error",   // 未使用变量报错
      "semi": ["error", "always"], // 强制分号
      "indent": ["error", 2]       // 强制 2 空格缩进
    }
  }
];
```

> 常见的主流风格规范有 **Airbnb、Standard、Google** 等，各有取舍。新项目不必从零造轮子，直接继承一套成熟预设即可——**规范的一致性比规范的"个性"重要得多**。



#### VSCode 插件与配置

VSCode 是前端开发最主流的编辑器，配合若干插件能显著提升编码体验与规范遵从度。

- **ESLint**：在编辑器里实时标出违反规则的代码，配合"保存时自动修复"可近乎无感地保持规范。
- **Prettier**：专注于**代码格式化**（缩进、换行、引号、逗号等），与 ESLint 互补——ESLint 管"逻辑与规范"，Prettier 管"排版与格式"。
- **其他实用插件**：如 **Live Server**（本地起服务、热更新）、**Path Intellisense**（路径补全）、**GitLens**（增强 Git 体验）。

> ESLint 与 Prettier 的分工是高频考点：二者存在**规则重叠**，实践中通常让 Prettier 负责格式化、并在 ESLint 中**关闭冲突的格式类规则**（如 `eslint-config-prettier`），避免"改来改去打架"。



#### 交互方式与调试工具

##### 常见的交互方式

JavaScript 在浏览器中通过几种**同步、阻塞式**的交互函数与用户对话，它们都挂在 `window` 对象上，可直接调用。

- **`alert(message)`**：弹出带"确定"按钮的提示框，仅用于展示信息，返回 `undefined`。
- **`confirm(message)`**：弹出带"确定 / 取消"的确认框，返回布尔值——用户点确定返回 `true`，取消返回 `false`。
- **`prompt(message, default)`**：弹出带输入框的对话框，返回用户输入的字符串；用户取消返回 `null`。

```js
alert("欢迎来到我的网站");

const isSure = confirm("确定要删除这条记录吗？");
console.log(isSure); // true 或 false

const userName = prompt("请输入你的名字", "访客");
console.log(userName); // 用户输入的内容，取消则为 null
```

> 这三者都会**阻塞脚本执行**，直到用户操作完毕，且界面样式由浏览器决定、不可定制。现代项目中它们已很少用于真实交互，更多见于教学演示或调试；正式交互应由 DOM 元素与事件完成。



##### Chrome 的 debug 调试

**Debug 调试**：是指在代码执行过程中，通过**断点**让程序暂停，逐步查看变量值与调用栈，从而定位 bug 的过程。Chrome 开发者工具提供了完整的调试能力。

- **断点（Breakpoint）**：在 Sources 面板中点击代码行号，程序运行到该行会暂停。
- **单步执行**：暂停后可"逐行执行"（Step over）、"进入函数"（Step into）、"跳出函数"（Step out）。
- **调用栈（Call Stack）**：查看当前函数的调用链，定位"谁调用了谁"。
- **监听与监视（Watch）**：暂停时实时查看、修改局部变量的值。

```js
function calculateTotal(price, count) {
  const total = price * count; // 在此行打断点，暂停后查看 price、count 的值
  return total;
}

calculateTotal(19.9, 3);
```

> 调试的核心是**缩小范围、验证假设**：不要靠"猜"来改 bug，而是用断点确认"变量此时到底是什么值"。`debugger` 语句也可在源码中手动触发断点，效果等同于在 DevTools 里点断点。



##### console 对象与控制台

**`console` 对象**：是浏览器（和 Node.js）提供的内置全局对象，用于向控制台输出信息，是 JavaScript 最常用、最基础的调试手段。

- **`console.log(value)`**：普通日志输出，最常用。
- **`console.warn(value)` / `console.error(value)`**：输出警告 / 错误，在控制台中有醒目的黄色 / 红色标记。
- **`console.table(data)`**：以**表格**形式输出数组或对象，便于查看结构化数据。
- **`console.time(label)` / `console.timeEnd(label)`**：成对使用，统计两段调用之间的**耗时**，用于性能分析。
- **`console.dir(obj)`**：以可展开的树状结构输出对象，比 `log` 更适合查看 DOM 元素或复杂对象。

```js
const users = [
  { name: "张三", age: 20 },
  { name: "李四", age: 25 }
];

console.log("普通日志");
console.warn("这是一条警告");
console.error("这是一条错误");
console.table(users); // 以表格形式输出 users

console.time("loop");
for (let i = 0; i < 100000; i++) {}
console.timeEnd("loop"); // 输出循环耗时
```

> 调试结束后应**清理临时的 `console.log`**，避免污染生产代码与造成信息泄露。现代工程里常通过构建工具或 ESLint 规则（如 `no-console`）在发布前自动移除或告警。
