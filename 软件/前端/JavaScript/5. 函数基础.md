## 函数基础

### 函数的认识

#### 函数的声明与调用

**函数**：是**一段可重复调用的代码块**，它接收输入（参数）、执行逻辑、返回输出（返回值），是 JavaScript 最核心的抽象单元。函数的意义在于**一次定义、多次复用**，避免代码重复。

函数的两个基本动作：

- **声明**：用 `function` 关键字定义函数，此时函数体不会执行。
- **调用**：用函数名加圆括号 `()` 触发执行，可传入参数。

```js
// 声明
function greet(name) {
  console.log("你好，" + name);
}

// 调用
greet("coderwhy"); // 你好，coderwhy
greet("张三");     // 你好，张三
```

> 函数的核心思想是"**封装与复用**"：把一段逻辑装进一个命名的盒子，之后只需通过名字调用，无需重复编写。声明时只定义"做什么"，调用时才真正"去做"。



#### 函数的参数

**参数（Parameter）**：是函数声明时定义的**占位变量**，用于接收调用时传入的值。调用时实际传入的值叫**实参（Argument）**。

- 参数让函数变得**通用**——同一函数可处理不同的输入。
- 形参与实参**按位置一一对应**，实参多于形参时多余的被忽略，少于形参时对应形参为 `undefined`。

```js
// a、b 是形参
function add(a, b) {
  return a + b;
}

console.log(add(1, 2));    // 3（1、2 是实参）
console.log(add(10));      // NaN（b 为 undefined，10 + undefined）
console.log(add(1, 2, 3)); // 3（多余的 3 被忽略）
```

> 参数让函数从"处理固定数据"升级为"处理任意数据"。理解**形参与实参的按位对应**，以及"实参不足时为 `undefined`"这一默认行为，是理解默认参数、剩余参数等进阶特性的基础。



#### 参数默认值

**参数默认值（Default Parameters）**：是在声明形参时直接给 `=` 设定兜底值，当调用时**实参缺省或显式传入 `undefined`**，形参即取用默认值，是 ES6 引入的语法。

```js
function greet(name, greeting = "你好") {
  console.log(`${greeting}，${name}`);
}

greet("coderwhy");           // 你好，coderwhy（greeting 用默认值）
greet("coderwhy", "嗨");     // 嗨，coderwhy
greet("coderwhy", undefined);// 你好，coderwhy（undefined 也触发默认值）
greet("coderwhy", null);     // null，coderwhy（null 不触发默认值）
```

- **触发时机**：只有实参为 `undefined`（或缺省）才用默认值；`null`、`0`、`""` 等**其他假值不会触发**默认值，会原样传入。这是与 `||` 设默认值（任何假值都兜底）的本质区别。
- **默认值可为表达式**：`function log(x = new Date()) {}` 中默认值在**每次调用时**才求值，而非定义时。
- **默认参数的位置**：带默认值的参数一般放**末尾**，否则调用时难以跳过（需显式传 `undefined` 才能"跳过"它）。

> 默认参数是"函数参数"这一知识点的自然延伸，与后续 `arguments`、剩余参数同属"如何处理不确定实参"的家族。相比旧式的 `arg = arg || 默认值`，默认参数更准确——它只在缺省时兜底，不会误吞 `0`、`""`、`false` 这些合法值。



#### 函数的返回值

**返回值（Return Value）**：是函数执行后**交还给调用方的结果**，通过 `return` 语句指定。没有 `return` 的函数默认返回 `undefined`。

- `return` 语句会**立即终止函数**，其后的代码不再执行。
- `return` 可以返回**任意类型**的值，包括另一个函数。

```js
function add(a, b) {
  return a + b;      // 返回计算结果
  console.log("不会执行"); // return 之后，不会执行
}

const result = add(2, 3);
console.log(result); // 5

function noReturn() {}
console.log(noReturn()); // undefined
```

> 返回值让函数成为"**可参与运算的表达式**"：`add(2, 3) * 2` 中，`add(2, 3)` 先求值为 `5` 再参与乘法。理解"函数调用即值"这一思想，是理解函数组合、高阶函数等一切进阶概念的钥匙。



#### 函数的题目练习

通过练习巩固函数的声明、参数与返回值，体会"用函数解决重复问题"。

```js
// 1. 判断一个数是否为偶数
function isEven(num) {
  return num % 2 === 0;
}
console.log(isEven(4)); // true
console.log(isEven(7)); // false

// 2. 求两个数的最大值
function getMax(a, b) {
  return a > b ? a : b;
}
console.log(getMax(10, 20)); // 20

// 3. 将数字格式化为带千分位的字符串
function formatNumber(num) {
  return num.toString().replace(/\B(?=(\d{3})+(?!\d))/g, ",");
}
console.log(formatNumber(1234567)); // "1,234,567"
```

> 练习题的核心是训练"**抽象出通用逻辑**"：从具体问题中提炼出"输入什么、输出什么"，再用函数封装。判断、求值、格式化是函数最典型的三种形态。



#### 变量使用的注意事项

函数中变量的使用有几个关键注意点，涉及作用域与命名。

- **参数名与函数内变量**：函数内的局部变量与参数只在函数内部有效，函数外无法访问。
- **避免与全局变量重名**：局部变量会**遮蔽**同名的全局变量，易造成困惑。
- **参数是局部变量**：修改参数不会影响函数外的变量（基本类型按值传递）。

```js
let count = 10; // 全局变量

function show() {
  const count = 99; // 局部变量，遮蔽全局
  console.log(count); // 99
}

show();
console.log(count); // 10（全局变量未被修改）
```

> 函数内部优先使用**局部变量**，避免依赖或污染全局状态。局部变量遮蔽全局变量虽合法，但会降低可读性，命名时应尽量避免重名。



### 函数封装练习

#### 数字格式化工具函数

函数封装的最佳实践是把常见逻辑沉淀为**工具函数**。以数字格式化为案例，逐步完善一个实用函数。

```js
// 将数字转为千分位格式：1234567 -> "1,234,567"
function formatNumber(num) {
  return num.toString().replace(/\B(?=(\d{3})+(?!\d))/g, ",");
}

console.log(formatNumber(1234567));   // "1,234,567"
console.log(formatNumber(1000));      // "1,000"
console.log(formatNumber(999));       // "999"
```

> 这个案例展示了"**先用语言能力拼出解法，再封装成函数复用**"的过程。正则 `\B(?=(\d{3})+(?!\d))` 匹配"非单词边界且后面跟着 3 的倍数个数字"的位置，实现千分位插入，是正则的经典应用。



#### 数字格式化工具的补充

工具函数还应考虑**健壮性**，对非法输入做兜底处理，并支持更细粒度的需求。

```js
function formatNumber(num, digits = 2) {
  // 非数字输入兜底
  if (typeof num !== "number" || Number.isNaN(num)) {
    return "0";
  }
  // 保留指定位数小数并格式化千分位
  const fixed = num.toFixed(digits);
  return fixed.replace(/\B(?=(\d{3})+(?!\d))/g, ",");
}

console.log(formatNumber(1234567.891)); // "1,234,567.89"
console.log(formatNumber("abc"));       // "0"（非法输入兜底）
console.log(formatNumber(3.14159, 3));  // "3.142"
```

> 健壮的工具函数会**先校验输入、再处理逻辑**，并为常见需求预留**可配置项**（如小数位数 `digits`）。`toFixed(digits)` 用于保留小数，但它返回字符串且可能四舍五入，需注意其"返回字符串"这一特性。



### arguments

#### arguments 变量的使用

**`arguments`**：是普通函数（非箭头函数）内部自动拥有的**类数组对象**，包含调用时传入的**所有实参**，即使函数没有声明形参也能访问。

- 通过索引访问：`arguments[0]`、`arguments[1]`……
- 有 `length` 属性表示实参个数。
- 是**类数组对象**，有 `length` 但没有数组方法（`map`、`forEach` 等）。

```js
function sum() {
  let total = 0;
  for (let i = 0; i < arguments.length; i++) {
    total += arguments[i];
  }
  return total;
}

console.log(sum(1, 2, 3, 4, 5)); // 15（未声明形参也能接收任意数量实参）
```

> `arguments` 让函数可以处理**不确定个数**的参数，是 ES6 剩余参数（`...rest`）出现之前的唯一方案。但它是类数组而非真数组，使用不便，现代代码中已被**剩余参数**取代，理解它主要是为了读懂旧代码。



#### 类数组对象

**类数组对象（Array-like）**：是**具有数字索引和 `length` 属性、但并非真正数组**的对象。它看起来像数组，却缺少数组的方法。

常见的类数组对象：

- 函数的 `arguments`。
- 字符串（有 `length` 和索引）。
- DOM 的 `NodeList`、`HTMLCollection`。

```js
function demo() {
  console.log(typeof arguments);          // "object"
  console.log(Array.isArray(arguments));  // false
  console.log(arguments.length);          // 实参个数
  // arguments.map(...) // 报错：类数组没有 map 方法

  // 转为真数组
  const realArray = Array.from(arguments);
  console.log(realArray.map((x) => x * 2));
}

demo(1, 2, 3);
```

> 类数组转真数组的几种方式：`Array.from(arrLike)`（推荐）、`[...arrLike]`（展开语法）、`Array.prototype.slice.call(arrLike)`（旧式）。理解"长得像但方法不同"是避免"某某不是函数"报错的关键。



### 递归

#### 递归的理解

**递归（Recursion）**：是函数**直接或间接调用自身**的编程技巧，用于把一个大问题分解为结构相同的更小问题，直到满足**终止条件**。

一个递归函数必须包含两部分：

- **终止条件（Base case）**：不再递归、直接返回的兜底，防止无限递归。
- **递归调用（Recursive case）**：把问题缩小后再次调用自身。

```js
// 计算阶乘 n! = n * (n-1)!
function factorial(n) {
  if (n <= 1) return 1;      // 终止条件
  return n * factorial(n - 1); // 递归调用
}

console.log(factorial(5)); // 120
```

> 递归的精髓是"**自己调用自己 + 必须能停下来**"。缺失或写错终止条件会导致**栈溢出（Stack Overflow）**。递归代码往往比循环更简洁、更贴近问题本身，但通常也更耗内存（每次调用都压栈）。



#### 递归的案例

通过几个案例体会递归"分解问题"的威力。

```js
// 1. 计算 1 到 n 的和
function sumTo(n) {
  if (n <= 1) return n;
  return n + sumTo(n - 1);
}
console.log(sumTo(100)); // 5050

// 2. 倒序打印数字
function printReverse(n) {
  if (n <= 0) return;
  console.log(n);
  printReverse(n - 1);
}
printReverse(5); // 5 4 3 2 1
```

> 递归的通用思考模式是"**假设子问题已解决**"：算 `sumTo(n)` 时，先假设 `sumTo(n-1)` 已经能算出来，那么 `sumTo(n) = n + sumTo(n-1)`。这种"信任递归"的思维方式，是掌握递归的核心心法。



#### 斐波那契数列

**斐波那契数列**：是递归的经典案例，数列从 0 和 1 开始，后续每项是前两项之和：`0, 1, 1, 2, 3, 5, 8, 13, ...`。

```js
function fibonacci(n) {
  if (n === 0) return 0;     // 终止条件 1
  if (n === 1) return 1;     // 终止条件 2
  return fibonacci(n - 1) + fibonacci(n - 2); // 递归
}

console.log(fibonacci(10)); // 55
```

> 斐波那契的递归实现**简洁但低效**：`fibonacci(n)` 会重复计算大量相同子问题，时间复杂度高达 O(2^n)，`n=50` 时几乎无法完成。这正是引出**记忆化（memoization）**与动态规划优化的经典引子——用缓存避免重复计算，可把复杂度降到 O(n)。



### 函数的作用域

#### 块级作用域与函数作用域

**作用域（Scope）**：是变量**可被访问的范围**，决定"在哪里能用这个变量"。JavaScript 的作用域主要有两种。

- **函数作用域**：`var` 声明的变量，其作用范围是整个函数。
- **块级作用域**：`let` / `const` 声明的变量，其作用范围是最近的 `{}` 块（ES6 引入）。

```js
function demo() {
  var a = 1;        // 函数作用域
  let b = 2;        // 块级作用域（此处块 = 函数体）

  if (true) {
    var c = 3;      // 函数作用域，块外可访问
    let d = 4;      // 块级作用域，块外不可访问
  }
  console.log(c);   // 3
  // console.log(d); // 报错：d 在块外不可访问
}
```

> `var` 与 `let` 作用域差异是高频考点：`var` 没有块级作用域，会"漏出"`if`、`for` 的块，造成污染与困惑；`let`/`const` 严格遵循块级作用域，行为更符合直觉，是现代的默认选择。



#### 全局、局部与外部变量

按作用范围，变量可分为三类，它们之间遵循"**内层可访问外层，外层不可访问内层**"的规则。

- **全局变量**：在最外层声明，整个程序都可访问。
- **局部变量**：在函数（或块）内声明，仅在其作用域内可访问。
- **外部变量**：从函数内部看，定义在函数外的变量都是"外部变量"，函数内**可读**，但通过 `var`/`let` 声明同名变量会遮蔽。

```js
const globalVar = "全局"; // 全局变量

function demo() {
  const localVar = "局部"; // 局部变量
  console.log(globalVar);  // 可访问外部变量
  // 外层无法访问 localVar
}
demo();
// console.log(localVar); // 报错
```

> 作用域的访问规则是"**由内向外查找**"：函数内找变量时，先找自己的局部作用域，找不到再一层层向外找全局。但**从外向内是访问不到的**——局部变量对外层"隐身"。



#### 变量的查询顺序

当代码引用一个变量时，JavaScript 按**作用域链**由内向外逐层查找，找到即停止，查不到则报错。

查找顺序（以三层嵌套为例）：

1. 当前函数/块的作用域。
2. 外层函数的作用域。
3. 全局作用域。
4. 都没有 → `ReferenceError`。

```js
const name = "全局";

function outer() {
  const name = "外层";
  function inner() {
    const name = "内层";
    console.log(name); // "内层"（最近优先）
  }
  inner();
}

outer();
console.log(name); // "全局"
```

> 变量查找遵循"**就近原则**"：内层同名变量会遮蔽外层。理解作用域链的查找顺序，是理解闭包、this 指向、变量提升等一切进阶概念的地基。



### 函数的其他定义方式

#### 函数表达式

**函数表达式**：是把函数**当作值**赋给变量或常量的定义方式。与函数声明不同，它把函数当"一等公民"对待。

- 函数表达式**没有函数提升**，只能在定义之后调用。
- 匿名函数常以函数表达式形式出现。

```js
// 函数声明
function declared() {
  console.log("声明式");
}

// 函数表达式（匿名函数赋给变量）
const expressed = function () {
  console.log("表达式");
};

expressed(); // 表达式
```

> 函数声明与函数表达式的核心区别在于**提升**：函数声明会被整体提升，可在声明前调用；函数表达式仅提升变量名（`var`）或完全不提升（`let`/`const`），调用必须先于定义。这一差异是诸多面试题的考点。



#### 头等公民与函数式编程

**头等公民（First-class Citizen）**：指函数与其他数据类型（数字、字符串）**地位相同**——可以被赋值给变量、作为参数传递、作为返回值返回。

函数的"一等公民"能力：

- **赋给变量**：`const fn = function () {}`。
- **作为参数**：回调函数 `[1,2,3].map(fn)`。
- **作为返回值**：返回另一个函数（高阶函数）。

```js
// 函数作为返回值（高阶函数）
function createMultiplier(factor) {
  return function (num) {
    return num * factor;
  };
}

const double = createMultiplier(2);
console.log(double(5)); // 10
```

> 函数是头等公民，是**函数式编程**的基石。正因为函数能像值一样传来传去，才有了回调、高阶函数、柯里化、闭包等强大特性。可以说，JavaScript 的灵活性一半来自动态类型，另一半来自"函数是一等公民"。



#### 回调函数与匿名函数

**回调函数（Callback）**：是**作为参数传给另一个函数、并在适当时机被调用**的函数。它让"执行时机"与"逻辑定义"解耦。

**匿名函数（Anonymous Function）**：是没有名字的函数，常以回调或表达式形式出现。

```js
// 匿名函数作为回调
const numbers = [1, 2, 3, 4];
numbers.forEach(function (item) {
  console.log(item);
});

// 事件回调也是回调函数
document.addEventListener("click", function () {
  console.log("被点击了");
});
```

> 回调函数是异步编程的起点：把"点击后要做什么"定义成一个函数，交给系统在点击发生时调用。现代代码中，匿名回调常用**箭头函数**简写，但"回调函数"这一概念本身，是理解事件、异步、Promise 的必经之路。



### 立即执行函数

#### 立即执行函数的使用过程

**立即执行函数（IIFE，Immediately Invoked Function Expression）**：是**定义后立即调用**的函数，写法是 `(function () { ... })()`。它创建了一个**独立的函数作用域**，避免污染全局。

```js
(function () {
  const message = "我是立即执行函数";
  console.log(message); // 我是立即执行函数
})();

// 变量 message 不会泄漏到全局
// console.log(message); // 报错
```

> IIFE 的核心价值在于**用函数作用域隔离变量**：在 ES6 模块与块级作用域出现之前，它是实现"私有作用域"的主要手段。虽然现代代码已多用 `let`/`const` 和模块替代，但理解 IIFE 是读懂大量历史代码的前提。



#### 立即执行函数的使用场景

立即执行函数有两大典型场景：**隔离作用域**与**数据私有化**。

##### 使用场景一

**隔离作用域**：把一段临时代码包裹起来，避免其内部变量污染全局命名空间。

```js
// 两个 IIFE 之间互不干扰
(function () {
  const version = "A";
  console.log(version);
})();

(function () {
  const version = "B";
  console.log(version);
})();
// 两个 version 各自独立，互不冲突
```

> 在大型项目中，若没有模块化，不同脚本容易因同名全局变量互相覆盖。用 IIFE 把每段代码装进独立作用域，是从根上避免这类冲突的经典方案。



##### 使用场景二

**数据私有化**：利用闭包，让 IIFE 返回一个对象，对象内部可以访问"私有变量"，外部只能通过暴露的方法操作。

```js
const counter = (function () {
  let count = 0; // 私有变量，外部无法直接访问

  return {
    increment() {
      count++;
    },
    getCount() {
      return count;
    }
  };
})();

counter.increment();
counter.increment();
console.log(counter.getCount()); // 2
// console.log(count); // 报错：count 是私有的
```

> 这个场景是**模块模式（Module Pattern）** 的雏形：用 IIFE 的闭包隐藏内部状态，只暴露有限的接口。它直接启发了后来的 CommonJS、ESModule 等模块化方案，理解它有助于理解"封装"与"私有"的本质。



#### 立即执行函数的其他写法

立即执行函数有多种等价写法，核心都是"**让函数变成表达式，再立即调用**"。

常见写法：

- **`(function () { ... })()`**：最经典、最常见。
- **`(function () { ... }())`**：把括号放在内部。
- **`!function () { ... }()`**：用 `!`、`+`、`~` 等一元运算符把函数声明转为表达式。
- 箭头函数版本：**`(() => { ... })()`**。

```js
// 写法一
(function () {
  console.log("写法一");
})();

// 写法二
(function () {
  console.log("写法二");
}());

// 箭头函数写法
(() => {
  console.log("箭头函数 IIFE");
})();
```

> 为什么需要括号？因为 `function () {}` 开头会被解析为**函数声明**（需要名字），而函数声明不能直接加 `()` 调用。用 `()` 或一元运算符把它转成**表达式**后，才能立即调用。这是"声明"与"表达式"语法差异的又一个体现。
