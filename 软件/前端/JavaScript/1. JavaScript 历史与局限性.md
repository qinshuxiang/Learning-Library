## JavaScript 历史与局限性

### 编程语言与计算机语言

**编程语言**（Programming Language）是人与计算机之间传递信息、规定计算过程的形式语言，用于编写程序，被翻译成机器指令后由计算机执行。

- **编程语言**：面向**人**书写代码的符号体系，强调可读性与表达力（如 JavaScript、Python）。
- **计算机语言**：人机交流的总称，包括编程语言与机器可读的指令体系。

**编程语言与计算机语言的区别**在于范围与立足点：

- **计算机语言**是上位概念，泛指一切人与计算机交互的语言，既包括给机器直接执行的**机器语言**，也包括给人书写的**高级语言**。
- **编程语言**是计算机语言的子集，专指能"编写程序"的语言；不是所有计算机语言都能写程序，例如仅用于数据描述、不表达控制逻辑的语言就不算通用编程语言。

> 通俗理解：**计算机语言**是总称，**编程语言**是其中用来写程序的那一部分；机器语言、汇编语言、高级语言都属于计算机语言，也都是编程语言。



### 编程语言的特点

一门语言是否称得上"编程语言"，要看它能否表达对数据的组织与对执行流程的控制。编程语言普遍具备四类特征：

#### 数据结构

**数据结构**是编程语言组织与存放数据的方式，语言通过提供基础数据类型与复合结构，让数据得以被程序使用。

- **基础数据类型**：数字、字符串、布尔等单一值。
- **复合结构**：数组、对象、列表、树、图等，将多个值组合起来。
- 不同语言内建的数据结构不同，决定其擅长的领域（如 JavaScript 以对象为核心，C 以数组与指针为核心）。



#### 流程控制

**流程控制**是编程语言表达程序执行顺序的机制，决定语句按何种路径运行。

- **顺序**：语句从上到下依次执行。
- **分支**：按条件选择执行路径，如 `if`、`switch`。
- **循环**：重复执行某段代码，如 `for`、`while`。



#### 引用机制

**引用机制**是语言中"传值还是传引用"的规则，决定变量之间的复制与函数参数传递到底复制数据本身，还是复制指向数据的地址。

- **传值**（by value）：复制数据的**副本**，改动副本不影响原数据。
- **传引用**（by reference）：传递数据的**引用（地址）**，通过引用改动会影响原数据。
- JavaScript 中基本类型传值、引用类型（对象、数组、函数）传引用，是理解其赋值与参数行为的关键。

> 例如 `let b = a` 后，若 `a` 是基本类型，`b` 是独立副本；若 `a` 是对象，`b` 与 `a` 指向同一对象，改动 `b.x` 会反映到 `a` 上。



#### 设计哲学

**设计哲学**是语言作者在设计时所依据的核心理念，决定语言的语法风格、约束方式与应用取向。

- **简单性 vs 强大性**：如 Python 强调简洁易读，C++ 强调灵活强大。
- **静态 vs 动态**：类型在编译期检查还是运行期检查。
- **严格 vs 宽松**：是否强约束（如 JavaScript 类型宽松、隐式转换多）。
- JavaScript 的设计哲学偏"**宽容、动态、基于对象**"——上手容易，但也因此埋下若干历史局限。



### 编程语言的历史

编程语言随硬件的发展而演变，大体经历由"贴近机器"到"贴近人"的三个阶段。

#### 机器语言

**机器语言**是第一代编程语言，由二进制指令（0 和 1）直接构成，计算机硬件能直接识别并执行，无需任何翻译。

- 优点：执行速度最快，直接操作硬件。
- 缺点：**可读性极差**，难以记忆、编写与调试，依赖具体机器型号，不同 CPU 指令互不通用。



#### 汇编语言

**汇编语言**是第二代编程语言，用**助记符**（如 `MOV`、`ADD`）代替二进制指令，是机器语言的符号化形式。

- 优点：比机器语言易读易写，仍能精细控制硬件。
- 缺点：仍是**低级语言**，贴近具体机器、移植性差，编写复杂程序依然繁琐。
- 汇编代码仍需**汇编器**翻译成机器语言才能执行。



#### 高级语言

**高级语言**是第三代及以后的编程语言，用接近自然语言的语法书写，屏蔽了机器细节，可读性与可移植性大幅提高。

- **面向过程**：以函数/过程组织程序，如 C、Fortran。
- **面向对象**：以对象和类组织程序，如 Java、C++、Python。
- **脚本语言**：解释执行、用于自动化特定任务，如 JavaScript、Python、Ruby。
- 高级语言不能直接被机器执行，需经**编译器**（整体翻译成机器码）或**解释器**（边翻译边执行）处理。

> 演进主线：**机器语言 → 汇编语言 → 高级语言**，本质是不断把机器细节下移、把表达上移，让人用更接近人类思维的方式编程。JavaScript 属于**高级语言**中的**脚本语言**。



### JavaScript 的定义

**JavaScript**（简称 JS）是一种**解释型的、动态的、基于原型的、多范式的客户端脚本语言**，最初设计用于在浏览器中为网页增加交互行为，现已成为应用最广的编程语言之一。

维基百科将其定位概括为：JavaScript 是一种**高级的、解释执行的编程语言**，遵循 **ECMAScript 语言规范**，也被用于**服务器端**（如 Node.js）与**非浏览器环境**。

- **脚本语言**：代码由解释器执行，不需要预先编译成独立可执行文件。
- **动态类型**：变量的数据类型在运行时确定，可随时改变。
- **基于原型**：通过原型链实现继承，而非传统的"类"继承。
- **多范式**：同时支持命令式、函数式、面向对象等编程方式。
- **事件驱动**：浏览器环境下以事件为驱动核心，通过回调响应交互。



### JavaScript 的诞生历史

JavaScript 的诞生源于网景公司想在浏览器中引入可交互脚本，发展过程中历经更名与标准化，其仓促诞生也直接造成了今日的诸多局限。

#### 网景公司

**网景公司**（Netscape Communications）是 1994 年成立的一家美国软件公司，其推出的 **Netscape Navigator** 是 1990 年代占据统治地位的浏览器。

- 当时网页纯静态，只能展示文本与图片，无法与用户动态交互（如表单校验、局部刷新）。
- 为在浏览器端运行脚本、增强网页活力，网景决定为其浏览器开发一种脚本语言。



#### 布兰登·艾奇

**布兰登·艾奇**（Brendan Eich）是 JavaScript 的创造者，1995 年受聘于网景公司时被要求在极短时间内设计出浏览器脚本语言。

- 1995 年 5 月，艾奇仅用 **10 天**就完成了 JavaScript 的第一个版本（最初命名 **Mocha**）。
- 艾奇原本倾向基于 **Scheme**（函数式语言）的设计，但因要与 Java 语法靠拢、便于市场推广，最终语言在语法上模仿了 Java 与 C。
- 语言随后更名为 **LiveScript**，最终为借 Java 的热度定名为 **JavaScript**。

> 注意：**JavaScript 与 Java 没有任何血缘关系**，二者仅在语法层面有相似之处。JavaScript 的名字纯粹是网景的商业营销行为，与 Java 的制造商 Sun 公司并无开发协作（仅达成商标许可协议）。



#### JavaScript 的局限性

JavaScript 由艾奇在 10 天内仓促设计，加上当时未预见到它会成为全球最流行语言，因此从诞生起就遗留了若干**设计局限**（history 层面的"坑"），这些既是缺陷也推动了后来 ECMAScript 的持续演进。

- **`var` 声明的函数作用域与变量提升**：易造成变量污染与不可预期的访问结果（后续 `let`/`const` 才引入块级作用域）。
- **隐式类型转换**：如 `"1" + 1` 得 `"11"`、`"5" - 3` 得 `2`，行为不够直观，`==` 宽松相等常引发误判。
- **全局作用域污染**：早期无模块化机制，顶层声明的变量/函数都会挂到 `window` 上。
- **`this` 指向的动态绑定**：`this` 随调用方式变化，初学者极易踩坑。
- **`typeof null === "object"`** 的历史 bug，源自早期实现中 null 的位标记，无法修复、沿用至今。
- **数字全部采用 IEEE 754 双精度浮点**，如 `0.1 + 0.2 !== 0.3`，且无原生 `BigInt`（直到 ES2020）。
- **回调地狱**：早期异步只能靠回调嵌套，可读性差（后由 Promise、async/await 缓解）。

> **局限是历史包袱，而非语言"错了"**。JavaScript 靠后端的持续打补丁（ES6 起的各版本）不断修正上述问题，但为兼容历史代码，早期缺陷大多无法根治，只能通过新增语法规避。



### JavaScript 的组成

通常所说的"JavaScript"实际是三部分的合称，运行在浏览器中时需要这三者协同。

#### ECMAScript（核心）

**ECMAScript**（简称 ES）是 JavaScript 的**语言规范**，规定了语法、类型、语句、关键字、内置对象等核心内容，由 **ECMA 国际**（European Computer Manufacturers Association，欧洲计算机制造商协会）的下属委员会 **TC39** 负责维护与制定版本。

- JavaScript 是 ECMAScript 规范的**一种实现**；规范统一了各厂商实现的语言行为，避免"各家各写一套"。
- 版本以年份命名：**ES5**（2009）、**ES6 / ES2015**（2015，里程碑式大版本）、ES2016~ES2023 逐年迭代。
- 语言层面的能力（语法、`let`、`Promise`、`class` 等）都属于 ECMAScript。



#### DOM

**DOM**（Document Object Model，文档对象模型）是浏览器提供的一组**操作网页内容**的标准接口，把 HTML 文档结构化为对象树，让脚本能读取和修改页面。

- 不属 ECMAScript 规范，而由 **W3C**（万维网联盟）等组织制定。
- 提供 `document.getElementById()`、`document.createElement()` 等 API 来增删改查页面元素。



#### BOM

**BOM**（Browser Object Model，浏览器对象模型）是浏览器提供的一组**操作浏览器本身**的标准接口，如控制窗口、导航、历史记录等。

- 核心对象是 **`window`**，其下挂载 `location`（地址）、`history`（历史）、`navigator`（浏览器信息）、`screen`（屏幕）等对象。
- 没有统一标准，不同浏览器实现存在差异（相较 DOM 规范程度低）。

> **组成关系**：**JavaScript = ECMAScript（核心语法）+ DOM（操作文档）+ BOM（操作浏览器）**。纯语言本身只能算 ECMAScript，只有配合 DOM 与 BOM 才能真正操控网页。



### JavaScript 的运行引擎

JavaScript 不能直接运行，需要**引擎**（Engine，也叫解释器）把源码翻译成机器码执行。不同环境内置不同引擎，但设计思路相通。

- **引擎**：读取 JS 源码 → 解析为语法树 → 编译/解释成字节码或机器码 → 执行并回收内存。
- **JIT**（Just-In-Time，即时编译）：现代引擎普遍在运行时把热点代码编译为机器码以提升速度。



#### V8 引擎

**V8** 是 Google 开发的高性能 JavaScript 引擎，用 C++ 编写，最先用于 Chrome 浏览器，后被 Node.js 采纳成为服务端 JS 的事实标准运行时。

- 采用**即时编译（JIT）**，把 JS 直接编译为机器码而非逐行解释，性能远超早期纯解释引擎。
- 附带高效**垃圾回收**与**内联缓存**优化。
- 支撑了 Node.js、Deno 等运行时与大量桌面/移动应用（如 Electron 桌面应用、React Native 的部分实现）。



#### 浏览器的 JS 引擎

浏览器的核心是**渲染引擎**，其中负责解析并执行 JavaScript 的那部分即"浏览器的 JS 引擎"，各主流浏览器引擎各不相同，但都遵循 ECMAScript 规范。

- **V8**：Chrome、Edge（新版）、Opera 使用。
- **SpiderMonkey**：Firefox 使用，是**最早**的 JS 引擎（源自网景）。
- **JavaScriptCore**（Nitro）：Safari 使用。

> **浏览器主引擎**渲染页面（HTML/CSS），**JS 引擎**执行脚本，二者通过浏览器提供的 Web API（DOM/BOM）衔接，合起来构成完整的浏览器运行时。



### 阿特伍德定律

**阿特伍德定律**（Atwood's Law）由编程问答网站 Stack Overflow 的联合创始人 **Jeff Atwood**（杰夫·阿特伍德）在 2007 年提出，其内容是：**任何能够用 JavaScript 实现的应用，最终都会用 JavaScript 实现。**

- 核心观点：JavaScript 的生态与影响力会不断扩张，凡是能在浏览器/JS 生态里做的事，社区最终都会用 JS 去做一遍。
- 该定律伴随 Node.js 的出现而加速兑现——JS 从只能写网页脚本，扩张到服务端、桌面端、移动端、命令行工具、IoT 等领域。
- 它不是严谨预言，而是对 JS 普及趋势的经验概括，常被用来调侃"万物皆可 JS"。

> 佐证实例：Atom/VS Code（桌面编辑器，Electron）、React Native/小程序（移动端）、Node.js（服务端）、TypeScript（JS 的超集）。"**一切终将 JavaScript 化**"。



### JavaScript 的应用场景

凭借跨平台能力与庞大的生态，JavaScript 早已超出"网页脚本"的原始定位，覆盖从前端到后端、从桌面到移动的全栈领域。

- **浏览器前端**：网页交互、表单校验、动画特效、SPA 应用（配合 React、Vue、Angular 等框架）。
- **服务器端**：通过 **Node.js** 编写后端服务、API 接口，实现前后端同用一门语言。
- **桌面应用**：借助 **Electron**（如 VS Code、Slack）、**Tauri** 构建跨平台桌面软件。
- **移动 / 跨端开发**：React Native、Flutter(部分)、uni-app 等实现一套代码多端运行。
- **全栈 / 构建工具**：Webpack、Vite、Babel 等前端工程化工具链均由 JS/TS 编写。
- **数据处理与机器学习**：浏览器端可运行轻量 ML 模型（如 TensorFlow.js）。
- **非浏览器嵌入式**：Node.js 在 IoT、CLI 工具、自动化脚本（Electron、Playwright 测试）中广泛应用。

> **JavaScript 今日角色**：不仅是"浏览器的脚本语言"，更是被 Node.js 带向全栈的通用语言，这正是阿特伍德定律在现实中的印证。
