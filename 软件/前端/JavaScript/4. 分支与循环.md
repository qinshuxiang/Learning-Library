## 分支与循环

### 代码块与分支结构

#### 代码执行方式与代码块

JavaScript 代码默认按照**从上到下、从左到右**的顺序逐行执行，这是**顺序执行**。但真实程序需要"按条件走不同路径"，于是引入了**代码块**与**分支结构**。

**代码块（Block）**：是用一对花括号 `{}` 包裹的一组语句，作为一个整体执行，可用于聚合多条语句。它是否构成作用域，取决于被声明的内容：`var` 与**非严格模式下的函数声明**会穿透块提升到外层；`let`、`const`、`class` 与**严格模式下的函数声明**则被限制在该块内。

```js
// 顺序执行
console.log("第一行");
console.log("第二行");

// 代码块
{
  var leaked = "var 会穿透块";
  const message = "块内的变量";
  console.log(message);
}
console.log(leaked); // "var 会穿透块"
// console.log(message); // 报错：const 是块级作用域
```

> 代码块最常见的用途是与 `if`、`for`、`while` 等搭配，作为"受控语句体"。单条语句可省略花括号，但**始终写花括号**是更安全、更规范的实践——它同时规避了"后续加语句却漏加括号"与 ASI（自动分号插入）带来的隐蔽错误。



#### 分支结构

**分支结构**：是指程序根据**条件的真假**，选择执行不同代码路径的结构。它是程序从"一条道走到黑"走向"智能决策"的关键。

JavaScript 提供了三类分支语句：

- **`if` / `if-else` / `if-else if-else`**：最基础、最通用的条件判断，条件可以是任意表达式。
- **三元运算符 `?:`**：`if-else` 的表达式级简写，有返回值。
- **`switch`**：多分支的等值判断，结构更清晰。

```js
// if-else if-else 多分支
const score = 85;
if (score >= 90) {
  console.log("优秀");
} else if (score >= 60) {
  console.log("及格");
} else {
  console.log("不及格");
}
```

> 选择哪种分支结构要看场景：**两个分支**用 `if-else` 或三元；**多个互斥的等值条件**用 `switch`；**范围判断**只能用 `if-else if` 或 `switch(true)` 惯用法（`switch` 本身只做等值匹配）。



#### 真值与假值

分支判断的本质是把条件表达式转成布尔值，因此必须先明确哪些值会被判为假。

**假值（Falsy）**：是在布尔上下文中被转换为 `false` 的值。JavaScript 的假值是一个**封闭的、只有八个**的集合；除此之外的一切值都是**真值（Truthy）**。

- **`false`**：布尔假。
- **`0`** 与 **`-0`**：数字零与负零。
- **`0n`**：`BigInt` 零。
- **`""`**：空字符串（空模板字符串同理）。
- **`null`**：空值。
- **`undefined`**：未定义。
- **`NaN`**：非数字。

```js
const falsyList = [false, 0, -0, 0n, "", null, undefined, NaN];
console.log(falsyList.map((item) => Boolean(item))); // 全部为 false

// 这些"看起来假"的值其实都是真值
console.log(Boolean("0"));     // true（非空字符串）
console.log(Boolean("false")); // true
console.log(Boolean([]));      // true（空数组也是对象）
console.log(Boolean({}));      // true（空对象）
console.log(Boolean(-1));      // true（只有 0 和 -0 是假）
```

> `if (value)` 判断的是"**是否为真值**"，而不是"**是否存在**"。`0`、`""`、`NaN` 都是合法的业务数据却会被判为假，因此校验数量应写 `count >= 0`、校验字符串应写 `text !== ""`、校验数字应写 `Number.isNaN(value) === false`，比依赖真值判断更精确。

> 速记：假值只有八个——`false`、`0`、`-0`、`0n`、`""`、`null`、`undefined`、`NaN`。除浏览器里 `document.all` 这一历史遗留特例（它是对象却被判定为假值）之外，**所有对象一律为真值**。



### if 分支语句

#### if 语句

**`if` 语句**：是最基础的条件语句，**当条件为真时执行代码块**，条件为假则跳过。它是所有分支逻辑的起点。

- 条件表达式会先被隐式转换为布尔值（按假值规则）。
- 条件为真才执行花括号内的语句。

```js
const age = 20;
if (age >= 18) {
  console.log("已成年，可以进入");
}
// 输出：已成年，可以进入

// 条件里可以是任意表达式，会自动转布尔
const userName = "";
if (userName) {
  console.log("用户名存在");
} else {
  console.log("用户名为空"); // 走这一支
}
```

> `if` 的条件里写"空字符串、0、null"等假值会被视为 `false`，这一隐式转换让"存在性判断"变得简洁，但也需注意 `0` 等合法假值被误判的边界情况。



#### if-else 语句

**`if-else` 语句**：在 `if` 基础上增加**否则分支**，条件为真走 `if` 块，为假走 `else` 块，二者**必走其一**。

```js
const isLogin = false;
if (isLogin) {
  console.log("欢迎回来");
} else {
  console.log("请先登录");
}
// 输出：请先登录
```

> `if-else` 表达的是"非此即彼"的**互斥关系**，两个分支恰好覆盖所有情况，不会有"无路可走"的空窗。这是它与单个 `if` 的本质区别。



#### if-else if-else 语句

**`if-else if-else` 语句**：用于**多个互斥条件**的判断，从上到下依次检查，命中第一个为真的分支后**立即停止**，不再判断后续分支。

```js
const hour = 14;
if (hour < 12) {
  console.log("上午好");
} else if (hour < 18) {
  console.log("下午好");
} else {
  console.log("晚上好");
}
// 输出：下午好
```

> 关键点在于"**命中即停**"：一旦某个分支条件为真，后面的 `else if` 都不会再被判断。因此**条件的书写顺序**很重要——范围应从小到大（或从大到小）单向排列，避免"前面的条件把后面的覆盖掉"。



#### 条件书写的顺序与陷阱

`if` 系列语句的易错点集中在**顺序、比较运算符与嵌套深度**三处。

- **顺序**：范围判断要单向收缩，先写**最特例**，最后写**兜底**。
- **比较运算符**：优先用严格相等 `===` 与 `!==`，避免 `==` 的隐式类型转换（`"" == 0` 为 `true`）。
- **嵌套深度**：多层嵌套会迅速吃掉可读性，应改用**卫语句（Guard Clause）**提前返回。

```js
// 卫语句：先排除非法与边界情况，主流程留在最后一层
function getDiscount(price, isVip) {
  if (typeof price !== "number" || Number.isNaN(price)) {
    return 0;
  }
  if (price <= 0) {
    return 0;
  }
  return isVip ? price * 0.2 : price * 0.1;
}

console.log(getDiscount(100, true)); // 20
console.log(getDiscount(-5, true));  // 0
```

> 卫语句的处理顺序是"**先特例、后一般**"：把最严格、最不可能的条件放在前面并立即 `return`，主流程就被自然地"平铺"到最后，避免了层层缩进。这一写法在校验函数与工具函数中几乎是标准做法。



### 三元运算符

**三元运算符（条件运算符）`?:`**：是 `if-else` 的**表达式形式**，语法为 `条件 ? 表达式1 : 表达式2`，条件为真返回 `表达式1`，否则返回 `表达式2`。它是 JavaScript 唯一的**三元**运算符。

```js
const age = 20;
const status = age >= 18 ? "成年" : "未成年";
console.log(status); // "成年"

// 等价于 if-else
let result;
if (age >= 18) {
  result = "成年";
} else {
  result = "未成年";
}
```

- 三元是**表达式**，有返回值，可以直接用于赋值、`return`、参数等位置；`if-else` 是**语句**，没有返回值。
- 三元运算符**右结合**，因此 `a ? x : b ? y : z` 等价于 `a ? x : (b ? y : z)`。
- 三元运算符支持**嵌套**，但过度嵌套会严重损害可读性。

```js
// 嵌套三元（可读性差，慎用）
const level = score >= 90 ? "A" : score >= 60 ? "B" : "C";
```

> 使用原则：三元适合**简单、单一**的二选一赋值；一旦需要嵌套或多个动作，就应改用 `if-else`。可读性永远优先于"看起来高级"。



### switch 语句

#### switch 的基本用法

**`switch` 语句**：用于**多个等值分支**的判断，把某个表达式的值与多个 `case` 依次进行**严格相等（`===`）**比较，命中后执行对应代码。

- 每个 `case` 末尾通常要写 **`break`**，否则会发生**穿透（fall-through）**，继续执行后续分支。
- 所有 `case` 都不匹配时，执行 **`default`** 分支（可选）。
- `default` **不必写在最后**，但按惯例放在末尾；一个 `switch` 只能有一个 `default`，写多个会抛 `SyntaxError`。

```js
const day = 3;
switch (day) {
  case 1:
    console.log("星期一");
    break;
  case 2:
    console.log("星期二");
    break;
  case 3:
    console.log("星期三");
    break;
  default:
    console.log("未知星期");
}
// 输出：星期三
```

> `switch` 的比较是**严格相等**（`===`），不会做类型转换；`if-else if` 则可以用任意比较（`>`、`<` 等）。因此**等值判断**用 `switch` 更清晰，**范围判断**要用 `if-else if` 或 `switch(true)`。漏写 `break` 导致的"穿透"是 `switch` 最常见也最隐蔽的 bug。



#### 穿透的双面性

**穿透（Fall-through）**：是指某个 `case` 末尾没有 `break`，控制流继续**无条件**执行下一个 `case`（乃至 `default`）的语句，而不再检查其表达式是否匹配。

穿透既是陷阱，也是有价值的特性——多个 `case` **共享同一段逻辑**时，反向利用穿透可以写出极简洁的分组。

```js
// 陷阱：忘记 break，多个分支被连续执行
const level = "A";
switch (level) {
  case "A":
    console.log("优秀");
    // 漏写 break
  case "B":
    console.log("良好");
    break;
}
// 输出：优秀、良好（"B" 的分支被穿透执行）

// 正用：多个 case 共享一段逻辑
function getMonthDays(month) {
  let days;
  switch (month) {
    case 1: case 3: case 5: case 7:
    case 8: case 10: case 12:
      days = 31;
      break;
    case 4: case 6: case 9: case 11:
      days = 30;
      break;
    case 2:
      days = 28;
      break;
    default:
      days = 0;
  }
  return days;
}
console.log(getMonthDays(1), getMonthDays(4), getMonthDays(2)); // 31 30 28
```

> `switch` 在函数中执行时，`return` 同样能结束整个 `switch`（因为函数已结束）；在循环体中的 `switch` 里写 `continue`，会结束 `switch` 并跳到循环的下一次迭代。这三者都算"跳出 `switch`"的合法手段。

> 穿透是**双刃剑**：漏写 `break` 是 bug，故意省略 `break` 做分组是技巧。二者的区别只在于**是否有注释说明**——共享逻辑的 `case` 分组应显式写注释或空一行对齐，让"故意穿透"一目了然。



#### 以 true 作为判别式的写法

`switch` 的判别式不限于变量，写成 `switch (true)` 后，每个 `case` 就变成一个**布尔表达式**，`switch` 退化为"按顺序求值的 `if-else if` 链"。

```js
function getGrade(score) {
  let grade;
  switch (true) {
    case score >= 90:
      grade = "A";
      break;
    case score >= 80:
      grade = "B";
      break;
    case score >= 60:
      grade = "C";
      break;
    default:
      grade = "D";
  }
  return grade;
}

console.log(getGrade(95), getGrade(85), getGrade(70), getGrade(30)); // A B C D
```

> `switch(true)` 与 `if-else if` 在能力上等价，差异只在**可读性**与**穿透能力**：条件简短且希望借助穿透时，`switch(true)` 的竖排结构更整齐；条件复杂时 `if-else if` 更自然。团队规范通常二者取一，不混用。

> 注意 `switch(true)` 依旧是 `===` 匹配：只有 `case` 表达式的值**恰好等于布尔 `true`** 才算命中。写成 `case score:`（`score` 是数字）永远匹配不上。



#### case 子句中的变量声明

`case` 与 `default` 子句类似于**标签**——它们只标记控制流的落点，**不创建词法作用域**。整个 `switch` 语句体是**一个**块作用域。

```js
const command = "start";
switch (command) {
  case "start":
    const message = "启动中"; // 声明在整个 switch 块中，而非本 case
    console.log(message);
    break;
  case "stop":
    // const message = "停止中"; // 报错：Identifier 'message' has already been declared
    console.log(message); // 能访问到上一 case 的 message
    break;
}
```

修复方式是给每个 `case` 补一对花括号，人为造出块级作用域。

```js
const command = "start";
switch (command) {
  case "start": {
    const message = "启动中"; // 只在本花括号内有效
    console.log(message);
    break;
  }
  case "stop": {
    const message = "停止中"; // 与上一 case 同名也不冲突
    console.log(message);
    break;
  }
}
```

> 结论：**在 `case` 中使用 `let`、`const`、`class` 时，必须给它套一层花括号**。这既是规避重复声明报错的手段，也避免了变量在穿透时被后续 `case` 意外读到。



### 循环语句

#### 循环的认识

**循环（Loop）**：是指**重复执行同一段代码**的结构。循环让程序能够以几行代码处理成千上万条数据，是"自动化"的核心手段。

JavaScript 的循环语句主要有四种：

- **`while`**：先判断条件，再执行循环体。
- **`do-while`**：先执行一次循环体，再判断条件。
- **`for`**：初始化、条件、迭代三者集中书写，最常用。
- **`for-in`** / **`for-of`**：分别用于遍历对象的可枚举属性名、可迭代对象的值。

一个循环通常包含三要素：**初始化变量**、**循环条件**、**迭代更新**，缺一容易造成死循环或逻辑错误。

```js
// 打印 0 到 4
let i = 0;          // 初始化
while (i < 5) {     // 条件
  console.log(i);
  i++;              // 更新
}
```

> 所有循环本质上都是这三要素的组合。写循环时首要警惕**死循环**：确保"迭代更新"能让"条件"最终变为假，否则程序将卡死。



#### while 循环

**`while` 循环**：**先判断条件，再执行循环体**。条件为真则执行，为假则退出。当循环次数**事先未知**时尤其适用。

```js
let i = 0;
while (i < 5) {
  console.log(i);
  i++;
}
// 输出：0 1 2 3 4
```

> `while` 是"入口判断"循环：若条件一开始就为假，循环体**一次都不会执行**。它适合"不知道要循环几次、只知道何时该停"的场景，如读取数据直到结束。



#### while 循环的练习

通过几个练习巩固 `while` 循环的写法与边界。

```js
// 1. 计算 1 到 100 的和
let sum = 0;
let n = 1;
while (n <= 100) {
  sum += n;
  n++;
}
console.log(sum); // 5050

// 2. 打印 1 到 100 中能被 7 整除的数
let num = 1;
while (num <= 100) {
  if (num % 7 === 0) {
    console.log(num);
  }
  num++;
}
```

> 累加与筛选是 `while` 的两类经典题。共同要点：**变量在循环外初始化**、**循环内必须更新**、**条件要能走到假**。任何一条疏忽都可能导致结果错误或死循环。



#### do-while 循环

**`do-while` 循环**：**先执行一次循环体，再判断条件**。与 `while` 的区别在于：无论条件真假，循环体**至少执行一次**。

```js
let i = 10;
do {
  console.log("至少执行一次");
  i++;
} while (i < 5);
// 输出：至少执行一次（尽管条件 i<5 一开始就为假）
```

> `do-while` 是"出口判断"循环，适合"无论如何都要先做一次、再决定是否继续"的场景，如"至少尝试读取一次输入"。日常使用频率低于 `while` 和 `for`，但理解其"至少一次"的语义很重要。



#### for 循环

**`for` 循环**：把**初始化、条件、迭代**三要素集中写在一行，是**最常用**的循环形式，尤其适合**次数已知**的循环。

```js
// 语法：for (初始化; 条件; 迭代) { 循环体 }
for (let i = 0; i < 5; i++) {
  console.log(i);
}
// 输出：0 1 2 3 4
```

- **初始化** `let i = 0`：只在循环开始前执行一次。
- **条件** `i < 5`：每次循环前判断，为假则退出。
- **迭代** `i++`：每次循环体执行完后执行。

> 三个表达式都可省略（如 `for (;;)` 是死循环），但省略条件须格外小心。用 `let` 声明循环变量能形成块级作用域，避免 `var` 带来的变量提升与污染。



#### for 循环的练习

`for` 循环是最常用的循环，通过练习掌握典型模式。

```js
// 1. 累加：计算 1 到 100 的和
let sum = 0;
for (let i = 1; i <= 100; i++) {
  sum += i;
}
console.log(sum); // 5050

// 2. 遍历数组
const fruits = ["苹果", "香蕉", "橙子"];
for (let i = 0; i < fruits.length; i++) {
  console.log(fruits[i]);
}

// 3. 打印偶数（步长为 2）
for (let i = 0; i <= 10; i += 2) {
  console.log(i); // 0 2 4 6 8 10
}
```

> 遍历数组是 `for` 最高频的用途，核心是**用 `i < arr.length` 控制边界、用 `arr[i]` 取元素**。现代 JavaScript 中，纯粹取值时更推荐用 `for-of`；但在需要**索引、步长、倒序或部分区间**时，索引式 `for` 仍是最底层、最灵活的方式。



#### 循环变量用 let 与 var 的差异

用 `var` 声明的循环变量**只有一份**，被整段循环共享；用 `let` 声明时，每次迭代都会**新建一个绑定**，循环结束后变量销毁。这一差异在异步回调与闭包中被放大。

```js
const varCallbacks = [];
for (var i = 0; i < 3; i++) {
  varCallbacks.push(function () {
    return i;
  });
}
console.log(varCallbacks.map(function (get) { return get(); })); // [3, 3, 3]

const letCallbacks = [];
for (let j = 0; j < 3; j++) {
  letCallbacks.push(function () {
    return j;
  });
}
console.log(letCallbacks.map(function (get) { return get(); })); // [0, 1, 2]
```

> `var` 版本里三个回调共享同一个 `i`，循环结束后 `i` 已是 `3`，于是全部返回 `3`；`let` 版本每轮迭代各有一个独立的 `j`，回调"记住"了各自的那一轮。这是 ES6 引入块级作用域后最直观的收益之一，**循环变量一律用 `let`**。



#### 循环的嵌套

**循环嵌套**：是在一个循环体内**再写一个循环**，外层每循环一次，内层完整循环一遍。常用于处理**二维结构**（如矩阵、表格）。

```js
// 外层控制行，内层控制列
for (let i = 1; i <= 3; i++) {
  for (let j = 1; j <= 3; j++) {
    console.log(`i=${i}, j=${j}`);
  }
}
// 输出 9 行：i 每变一次，j 从 1 到 3 走一遍
```

##### 嵌套的理解与案例练习

理解嵌套的关键是**分清内外层各自的职责**，用具体案例体会。

```js
// 打印一个 3 行 4 列的星号矩阵
for (let row = 0; row < 3; row++) {
  let line = "";
  for (let col = 0; col < 4; col++) {
    line += "* ";
  }
  console.log(line);
}
// 输出：
// * * * *
// * * * *
// * * * *
```

> 内层循环的**循环变量名**应区别于外层（如 `row`/`col`、`i`/`j`），避免混淆。嵌套的总执行次数是**内外层次数的乘积**（3×4 = 12 次），理解这一点有助于估算复杂度。



##### 嵌套案例练习二

继续用嵌套解决更有层次的图形问题，体会内外层变量的关系。

```js
// 打印三角形：第 i 行有 i 个星号
for (let i = 1; i <= 5; i++) {
  let line = "";
  for (let j = 1; j <= i; j++) {
    line += "*";
  }
  console.log(line);
}
// 输出：
// *
// **
// ***
// ****
// *****
```

> 这个案例的精髓在于**内层循环的次数依赖于外层变量 `i`**（`j <= i`），从而打印出逐行递增的三角形。这种"内层依赖外层"的模式是嵌套循环处理复杂图形的基础。



##### 九九乘法表练习

九九乘法表是嵌套循环的经典综合题，同时涉及**格式化输出**与**内层依赖外层**两个要点。

```js
for (let i = 1; i <= 9; i++) {
  let line = "";
  for (let j = 1; j <= i; j++) {
    line += `${j} × ${i} = ${i * j}\t`;
  }
  console.log(line);
}
// 输出：
// 1 × 1 = 1
// 1 × 2 = 2	2 × 2 = 4
// ...（共 9 行，第 i 行有 i 个算式）
```

> 乘法表用**外层 `i` 控制行（乘数）、内层 `j` 控制列（被乘数）**，内层上界 `j <= i` 形成下三角。模板字符串 `` `${j} × ${i} = ${i * j}` `` 与制表符 `\t` 让输出对齐，是格式化输出的常用技巧。



#### 循环的中断

##### break 与 continue

**`break`** 与 **`continue`** 是两个改变循环流程的关键字。

- **`break`**：**立即终止整个循环**，跳出循环体，执行循环后的代码。
- **`continue`**：**跳过本次循环的剩余代码**，直接进入下一次迭代。

```js
// break：找到目标就退出
for (let i = 1; i <= 10; i++) {
  if (i === 5) {
    break;          // i 到 5 就终止
  }
  console.log(i);
}
// 输出：1 2 3 4

// continue：跳过偶数
for (let i = 1; i <= 5; i++) {
  if (i % 2 === 0) {
    continue;       // 跳过本次，不打印偶数
  }
  console.log(i);
}
// 输出：1 3 5
```

> `break` 只跳出**最近的一层**循环，不跳出外层；`continue` 只跳过**本次迭代**，不影响后续。在嵌套循环中，`break`/`continue` 默认作用于最内层，若需影响外层则要配合**标签（label）**。

> `break` 与 `continue` 都**不能跨越函数边界**：在某个函数内部写 `break` 试图跳出外层的循环，是语法错误。循环中的判断逻辑若被抽成函数，应让函数返回布尔值，再由循环层决定中断。



##### 标签语句

**标签（Label）**：是给语句起的**标识符前缀**，形如 `labelName: statement`。配合 `break labelName` 或 `continue labelName`，可以从内层直接操作外层循环。

- **`break labelName`**：终止标签所指的**任意语句**（循环或块）。
- **`continue labelName`**：只能用于标签所指的**循环**，跳过该循环的当前迭代、进入下一次。
- 引用标签的 `break`/`continue` **必须位于标签所标记的语句内部**。

```js
const matrix = [
  [1, 2, 3],
  [4, 5, 6],
  [7, 8, 9]
];

let position = null;
rowScan: for (let row = 0; row < matrix.length; row++) {
  for (let col = 0; col < matrix[row].length; col++) {
    if (matrix[row][col] === 5) {
      position = { row, col };
      break rowScan; // 一次性跳出两层循环
    }
  }
}
console.log(position); // { row: 1, col: 1 }
```

`continue` 配合标签，可以"跳过整个分组"：

```js
const groups = [
  ["a", "b"],
  ["c", ""],
  ["d", "e"]
];

const collected = [];
groupScan: for (const group of groups) {
  for (const item of group) {
    if (item === "") {
      continue groupScan; // 放弃整个分组，直接进入下一个分组
    }
    collected.push(item);
  }
  collected.push("|"); // 被 continue 跳过时，这一行不会执行
}
console.log(collected); // ["a", "b", "|", "d", "e", "|"]
```

> JavaScript **没有 `goto`**，标签只能与 `break`/`continue` 配合使用。标签最典型的用途是"**在二维结构中搜索、命中即整体退出**"——不用标签就得引入布尔标志位，代码反而更啰嗦。但标签会打断阅读的线性流，非必要不使用。



##### try finally 中的中断

把 `break` 或 `continue` 写在 `try` 块里时，控制流**离开 `try` 之前一定会先执行 `finally`**；而如果 `finally` 自己包含 `return`、`break` 或 `continue`，它会**覆盖**原来那个中断动作。

```js
function findFirstEven(numbers) {
  let found = null;
  for (const num of numbers) {
    try {
      if (num % 2 === 0) {
        found = num;
        break; // 跳出前，finally 依然会执行
      }
    } finally {
      console.log("本轮收尾，当前数字：", num);
    }
  }
  return found;
}

console.log(findFirstEven([1, 3, 4, 6]));
// 本轮收尾，当前数字： 1
// 本轮收尾，当前数字： 3
// 本轮收尾，当前数字： 4
// 4
```

```js
// finally 中的 return 会吞掉 break
function breakIsSwallowed() {
  for (let i = 0; i < 3; i++) {
    try {
      if (i === 1) {
        break;
      }
    } finally {
      if (i === 1) {
        return "在 finally 中返回，break 失效";
      }
    }
  }
  return "循环正常结束";
}

console.log(breakIsSwallowed()); // "在 finally 中返回，break 失效"
```

> 结论：**`finally` 一定执行，且 `finally` 里的控制流语句优先级最高**。它同样会吞掉 `throw`（异常被丢弃）与 `return` 的原返回值。因此 `finally` 里只应放**资源清理**（关闭连接、恢复状态），绝不写 `return`。



#### 遍历方式的选择

##### for-in 与 for-of

这两个循环名字相似，遍历的目标却完全不同。

**`for-in`**：遍历对象的**可枚举字符串属性名**（键），会**沿原型链向上**查找，且 `Symbol` 键不参与。

**`for-of`**：遍历**可迭代对象**产出的**值**，依赖 `Symbol.iterator`，不触碰属性与原型链。

```js
const colors = ["红", "绿", "蓝"];
colors.extra = "附加属性";

// for-in：拿到的是字符串键，还会带上非索引属性与继承属性
for (const key in colors) {
  console.log("for-in 键：", key, typeof key);
}
// "0" string、"1" string、"2" string、"extra" string

// for-of：只拿值，干净
for (const value of colors) {
  console.log("for-of 值：", value);
}
// "红"、"绿"、"蓝"
```

遍历对象自身属性的正确做法是转成数组，而不是用 `for-in`：

```js
const user = { name: "张三", age: 20 };

for (const key of Object.keys(user)) {
  console.log(key, user[key]); // "name" "张三"、"age" 20
}

for (const [key, value] of Object.entries(user)) {
  console.log(key, value); // "name" "张三"、"age" 20
}
```

> `for-in` 遍历数组有三大坑：**键是字符串**（`"0" + 1` 会拼成 `"01"`）、**会带上非索引属性与原型链上的可枚举属性**、**遍历顺序虽然规范已定义但语义上仍属"属性枚举"**。数组遍历一律用 `for-of` 或 `forEach`；`for-in` 只适合调试时快速查看对象属性。

> 稀疏数组（含空槽的数组）是二者的又一处分野：`for-in` **跳过**空槽，`for-of` 会把空槽当作 `undefined` 访问。`[1, , 3]` 用 `Object.keys()` 得到 `["0", "2"]`，用展开得到 `[1, undefined, 3]`。



##### 可迭代协议

**可迭代协议（Iterable Protocol）**：是对象对外声明"我能被逐个取值"的约定——实现名为 `Symbol.iterator` 的方法，该方法返回一个**迭代器**（带 `next()` 方法的对象），`next()` 每次返回 `{ value, done }`。

`for-of`、展开语法 `...`、解构赋值、`Array.from()` 都依赖这一协议。数组、字符串、`Map`、`Set`、`NodeList`、`arguments` 都已内置 `Symbol.iterator`；**普通对象没有**，因此不可被 `for-of` 遍历。

```js
const scoreRange = {
  from: 1,
  to: 3,
  // 实现可迭代协议：方法名必须是 Symbol.iterator，返回一个迭代器
  [Symbol.iterator]() {
    let current = this.from;
    const upper = this.to;
    return {
      next() {
        return current <= upper
          ? { value: current++, done: false }
          : { value: undefined, done: true };
      }
    };
  }
};

for (const value of scoreRange) {
  console.log(value); // 1、2、3
}

console.log(typeof [][Symbol.iterator]);    // "function"（数组可迭代）
console.log(typeof "abc"[Symbol.iterator]); // "function"（字符串可迭代）
console.log({}[Symbol.iterator]);           // undefined（普通对象不可迭代）
```

> `for-of` 提前 `break` 或抛错时，会调用迭代器的 `return()` 方法做清理——这也是生成器函数在循环中断后无法继续复用（已提前返回）的原因。判断一个对象能否被 `for-of`，只需看它有没有 `Symbol.iterator`。



##### for await...of

**`for await...of`**：是 `for-of` 的异步版本，用于遍历**异步可迭代对象**（实现 `Symbol.asyncIterator`）。它只能在 `async` 函数体内或**模块顶层**使用。

```js
// 串行地依次请求多个地址：每个 await 会等待上一个完成
async function loadAll(urls) {
  const responses = [];
  for await (const response of urls.map((url) => fetch(url))) {
    responses.push(response);
  }
  return responses;
}
```

- 它每次迭代都会 `await` 一次，因此是**串行**执行；需要并发时应改用 `Promise.all()`。
- 它也能遍历同步可迭代对象，只是每次取值多一层 `await`，白白变慢。
- 循环 `break` 或抛错时，同样会调用迭代器的 `return()` 并等待其完成。

> `for await...of` 与 `Promise.all()` 的选择是"**串行 vs 并发**"：`Promise.all()` 一次性发起全部请求、整体最快；`for await...of` 逐个等待、适合有依赖关系或需要限流的场景。异步生成器与 `for await...of` 的详细机制见「迭代器与生成器」一章。



##### 数组方法的中断技巧

`Array.prototype.forEach()` 遍历时**无法中断**：回调里的 `return` 只相当于 `continue`，`break` 更是语法错误。需要"找到就停"时，有三条路。

```js
const numbers = [1, 2, 3, 4, 5];

// forEach：return 只是跳过当前元素，循环照旧走完
numbers.forEach((item) => {
  if (item === 3) {
    return; // 等价于 continue，不是 break
  }
  console.log("forEach 处理：", item);
});
// 输出 1、2、4、5

// some：回调返回 true 立即停止，用于"查找命中"
numbers.some((item) => {
  console.log("some 访问：", item);
  return item === 3;
});
// 只访问 1、2、3

// every：回调返回 false 立即停止，用于"验证是否全部满足"
numbers.every((item) => {
  console.log("every 访问：", item);
  return item < 3;
});
// 只访问 1、2、3
```

> 三者的语义取舍：**取值就用 `for-of`**（能 `break`、能 `continue`、性能好），**纯副作用遍历用 `forEach`，**需要中途停止时借 `some`/`every` 表达**（但这是在"借用"语义，可读性不如 `for-of`，应加注释说明）。万不得已还可以抛异常中断 `forEach`，再在外部 `catch`——这是最不推荐的做法。

> 记住 `some` 与 `every` 的短路方向：**`some` 遇 `true` 停**（找到一个就够），**`every` 遇 `false` 停**（发现一个不合格就够了）。二者都只遍历到短路点为止，不做完整遍历。



#### 循环的性能

循环优化的常见说法需要区分**过时经验**与**真实瓶颈**。

```js
const scores = new Array(20000000).fill(1);

function timeIt(label, action) {
  const start = performance.now();
  const total = action();
  console.log(label, (performance.now() - start).toFixed(1) + "ms", total);
}

timeIt("每次读 length：", function () {
  let total = 0;
  for (let i = 0; i < scores.length; i++) {
    total += scores[i];
  }
  return total;
});

timeIt("缓存 length：", function () {
  let total = 0;
  for (let i = 0, len = scores.length; i < len; i++) {
    total += scores[i];
  }
  return total;
});

timeIt("while 倒序：", function () {
  let total = 0;
  let i = scores.length;
  while (i--) {
    total += scores[i];
  }
  return total;
});
```

- **缓存 `length` 已无意义**：现代引擎的 JIT 会把 `arr.length` 这类循环不变量**外提**，实测两千万元素的遍历中，缓存与不缓存的耗时几乎相同。
- **`while` 倒序不再更快**：倒序写法（`while (i--)`）在过去能省一次比较，如今引擎已能优化，收益同样可以忽略。
- **真正的开销在抽象层**：`for-of` 需要走迭代器协议、每次构造 `{ value, done }`；`forEach` 需要为每次迭代调用一次回调。二者在同等数据量下通常比索引式 `for` 慢数倍。
- **循环内的重复计算仍有价值**：把循环体内**不变**的表达式（如 `object.list.length`、正则字面量、DOM 查询结果）提到循环外，依旧是有效的优化。

> 结论：**优先写最易读的循环，不要为微观性能牺牲可读性**。只有确认循环位于热点路径（大数据量、高频执行）时，才考虑把 `for-of`/`forEach` 换成索引式 `for`；此时也应以 `console.time()` 实测为准，而不是凭"据说倒序更快"这类过时的经验。



#### 循环与递归的取舍

循环与递归可以互相改写，取舍的核心是**内存与可读性**的权衡。

```js
// 循环写法：始终只用一个执行上下文，内存固定
function sumByLoop(n) {
  let total = 0;
  for (let i = 1; i <= n; i++) {
    total += i;
  }
  return total;
}

// 递归写法：每层调用压一个执行上下文，内存与深度成正比
function sumByRecursion(n) {
  if (n <= 1) return n;
  return n + sumByRecursion(n - 1);
}

console.log(sumByLoop(100), sumByRecursion(100)); // 5050 5050
```

- **内存**：循环占用**固定**内存；递归每层调用都要压栈，深度为 `n` 时同时存在 `n` 个执行上下文。
- **可读性**：递归代码更短、更贴近数学定义；处理树、链表、嵌套结构时优势明显。
- **风险**：递归深度受引擎栈限制，深度不可控时（如遍历用户上传的嵌套数据）会抛 `RangeError: Maximum call stack size exceeded`。

> 判断标准：**深度可控且结构天然递归**（树、JSON、目录）用递归；**深度不可控或追求极致性能**用循环，必要时用**显式栈**（自己维护一个数组模拟调用栈）把递归改成迭代。递归的更多细节与尾调用优化现状见「函数基础」一章。



### 综合练习

#### 随机生成数字

随机数生成是游戏与抽奖等场景的基础，JavaScript 通过 `Math.random()` 实现。

- **`Math.random()`**：返回 `[0, 1)` 之间的伪随机浮点数（含 0，不含 1）。
- 通过乘法和取整，可以映射到任意区间。

```js
// 生成 [0, n) 的随机整数
function getRandomInt(max) {
  return Math.floor(Math.random() * max);
}

// 生成 [min, max] 的随机整数（闭区间）
function getRandomIntInRange(min, max) {
  return Math.floor(Math.random() * (max - min + 1)) + min;
}

console.log(getRandomInt(10));          // 0 ~ 9
console.log(getRandomIntInRange(1, 6)); // 1 ~ 6（模拟骰子）
```

> 区间映射的通用公式：`Math.floor(Math.random() * (max - min + 1)) + min` 得到 `[min, max]` 的随机整数。用 `Math.floor`（向下取整）而非 `Math.round`，能保证每个整数被抽中的概率**均匀**。



#### 猜数字游戏

猜数字游戏是循环、分支、随机数、交互函数的**综合应用**，也是入门阶段最有代表性的完整案例。

```js
// 生成 1~100 的随机数，让用户猜
const target = getRandomIntInRange(1, 100);
let guess = -1;
let count = 0;

while (guess !== target) {
  guess = Number(prompt("请输入你猜的数字（1~100）："));
  count++;
  if (guess > target) {
    alert("猜大了");
  } else if (guess < target) {
    alert("猜小了");
  }
}
alert(`恭喜猜中！你一共猜了 ${count} 次`);
```

- 用 `while` 循环直到猜中才退出（循环次数未知）。
- 用 `if-else if` 给出"大了/小了"的提示，逐步缩小范围。
- 用 `count` 统计次数，体验"状态累积"。

> 这个游戏完整串联了**变量、随机数、循环、分支、交互函数**五大知识点。思考一个改进方向：如何限制最大猜测次数？——只需把 `while` 的条件改为 `guess !== target && count < 上限` 即可，这正是"多条件退出"的典型写法。

> 再进一步：把 `while` 换成 `for (;;)` 加 `break`、或把判断逻辑抽成 `compareGuess(guess, target)` 并让循环根据返回值决定是否继续，都是很好的重构练习——前者练习"**用 `break` 表达中断**"，后者练习"**把判断与流程分离**"。
