## BOM 与浏览器对象

### BOM 的认识

#### BOM 与浏览器环境

**BOM（Browser Object Model，浏览器对象模型）**：是浏览器提供给 JavaScript 的、用于**操作浏览器本身**的一组对象，以 **`window`** 为顶层对象。

- BOM **没有统一标准**，各浏览器实现可能有差异（与有 W3C 标准的 DOM 不同）。
- BOM 对象覆盖：窗口、位置、导航、历史、屏幕、定时器等。

```js
// BOM 的核心对象都挂在 window 上
console.log(window.location);   // 地址对象
console.log(window.history);    // 历史对象
console.log(window.navigator);  // 浏览器信息
console.log(window.screen);     // 屏幕信息
```

> BOM 与 DOM 的分工：**DOM 操作网页内容，BOM 操作浏览器环境**。理解这一区分，能帮你判断一个 API（如 `location`、`history`）属于哪个体系，以及为什么 BOM 的兼容性不如 DOM 稳定。



### window 对象

#### 全局作用域与 window

**`window`** 是 BOM 的**顶层对象**，同时承担着**全局作用域**的角色——全局变量和全局函数都成为它的属性。

```js
var globalVar = "hello";
function globalFn() {}

console.log(window.globalVar);  // "hello"
console.log(window.globalFn);   // 函数
console.log(window === this);   // true（全局作用域下）
```

> 关键差异：`var` 声明的全局变量和函数声明会挂到 `window`，但 **`let`/`const` 声明的全局变量不会**（它们存在于独立的"全局词法环境"）。访问 `window` 属性时可省略 `window.` 前缀，如直接写 `location` 等价于 `window.location`。



#### 窗口的位置与大小

获取窗口与屏幕的尺寸、位置信息。

- **`window.innerWidth` / `innerHeight`**：视口（含滚动条）宽高。
- **`window.outerWidth` / `outerHeight`**：整个浏览器窗口宽高。
- **`window.screenX` / `screenY`**：窗口在屏幕上的位置。

```js
console.log(window.innerWidth);  // 视口宽度
console.log(window.innerHeight); // 视口高度
console.log(window.screenX);     // 窗口距屏幕左边距
```

> `innerWidth`/`innerHeight` 是**响应式布局、判断视口**最常用的尺寸；`outerWidth` 是**浏览器窗口整体**（含边框工具栏）的尺寸。二者之差大致是浏览器 UI 占用的空间。



#### window.open 与窗口交互

**`window.open(url, target, features)`**：打开新窗口（或标签页），返回新窗口的 `window` 引用。

```js
// 打开新窗口
const newWindow = window.open("https://example.com", "_blank");

// 关闭窗口（只能关闭自己打开的）
// newWindow.close();
```

- `target` 指定打开位置：`_blank`（新窗口）、`_self`（当前）等。
- 返回的 `window` 对象可用于跨窗口交互（受同源策略限制）。

> `window.open` 常用于"弹出登录窗""打开帮助页"等场景，但**易被浏览器拦截**（弹窗拦截器会拦截非用户直接触发的 `open`）。因此它应**直接放在用户点击事件**里调用，而非异步回调中。



#### alert、confirm 与 prompt

三个同步、阻塞式的对话框函数，已在第 1 章"交互方式"介绍，这里补充 BOM 视角。

- **`alert(message)`**：提示框，只有"确定"。
- **`confirm(message)`**：确认框，返回布尔。
- **`prompt(message, default)`**：输入框，返回字符串或 `null`。

```js
alert("提示信息");

const sure = confirm("确定删除？");
console.log(sure); // true / false

const name = prompt("你的名字？", "访客");
console.log(name); // 输入的字符串，取消为 null
```

> 三者的共同特点：**同步阻塞**（后续代码等待用户操作）、**样式不可定制**、**会阻塞事件循环**。现代项目已很少用于真实交互，多用于调试与演示；正式交互应由 DOM 元素与事件完成。



### navigator 与 screen

#### navigator 对象

**`navigator`**：提供**浏览器与系统**的相关信息。

- **`navigator.userAgent`**：用户代理字符串（浏览器标识）。
- **`navigator.language`**：浏览器语言。
- **`navigator.onLine`**：是否联网。
- **`navigator.platform`**：操作系统平台。

```js
console.log(navigator.userAgent); // "Mozilla/5.0 ..."
console.log(navigator.language);  // "zh-CN"
console.log(navigator.onLine);    // true
```

> `userAgent` 常被用于**判断浏览器类型/版本**，但它**可被伪造、且逐渐废弃**，现代更推荐用**特性检测**（检测某 API 是否存在）而非 UA 字符串判断。`language` 可用于国际化默认语言，`onLine` 用于判断网络状态。



#### screen 对象

**`screen`**：提供**用户屏幕**的物理信息。

- **`screen.width` / `height`**：屏幕分辨率。
- **`screen.availWidth` / `availHeight`**：可用宽高（扣除任务栏等）。

```js
console.log(screen.width);      // 屏幕分辨率宽度
console.log(screen.height);     // 屏幕分辨率高度
console.log(screen.availHeight); // 可用高度
```

> `screen` 描述的是**物理屏幕**，而非浏览器窗口。`width/height` 是屏幕完整分辨率，`availWidth/availHeight` 是扣除系统任务栏后的可用区域。它可用于做全屏判断、分辨率适配等。



### location 与 URL

#### location 的属性与方法

**`location`**：表示**当前页面的地址**，可读可写，是页面跳转的核心对象。

常用属性：

- **`href`**：完整 URL（可读写）。
- **`protocol`** / **`host`** / **`pathname`** / **`search`** / **`hash`**：URL 各部分。

常用方法：

- **`location.reload()`**：刷新页面。
- **`location.assign(url)`**：跳转到新地址。
- **`location.replace(url)`**：替换当前地址（不可后退）。

```js
console.log(location.href);     // 完整 URL
console.log(location.pathname); // 路径
console.log(location.search);   // 查询字符串 ?a=1
console.log(location.hash);     // 哈希 #section

location.assign("https://example.com"); // 跳转（可后退）
location.replace("https://example.com"); // 跳转（不可后退）
location.reload(); // 刷新
```

> `assign` 与 `replace` 的区别是考点：`assign` 跳转后**可后退**回原页，`replace` 是**替换**当前历史记录、**不可后退**。`hash` 的变化会触发 `hashchange` 事件，是哈希路由的基础。



#### URL 与 URLSearchParams

**`URL`** 与 **`URLSearchParams`** 是处理 URL 和查询字符串的现代 API。

- **`new URL(url)`**：解析 URL，提供各部分的访问。
- **`new URLSearchParams(query)`**：解析查询字符串，提供 `get`/`set` 等操作。

```js
const url = new URL("https://example.com/path?a=1&b=2");
console.log(url.host);        // "example.com"
console.log(url.searchParams.get("a")); // "1"

const params = new URLSearchParams("a=1&b=2");
params.set("c", "3");
console.log(params.toString()); // "a=1&b=2&c=3"
```

> `URLSearchParams` 提供了**规范的查询串操作**（`get`、`set`、`append`、`delete`、`has`），替代了手写 `split("&")` 的繁琐。处理带查询参数、构建请求 URL 时非常实用。



### history 与前端路由

#### history 的属性与方法

**`history`**：表示**浏览历史**，提供了前进后退与状态管理的能力。

- **`history.length`**：历史记录条数。
- **`history.back()`** / **`forward()`** / **`go(n)`**：后退/前进/跳转。

```js
console.log(history.length); // 历史条数
history.back();              // 后退一页
history.forward();           // 前进一页
history.go(-2);              // 后退两页
```

> `history` 的 `back`/`forward`/`go` 是**传统页面跳转**的基础。而真正让 `history` 成为**前端路由核心**的，是下一节的 `pushState` 与 `popstate`。



#### pushState 与 popstate

**`history.pushState(state, title, url)`** 与 **`popstate`** 事件，构成了 **HTML5 History 路由**的基础。

- **`pushState`**：改变 URL 并添加一条历史记录，但**不刷新页面**。
- **`replaceState`**：替换当前记录（不新增）。
- **`popstate`**：用户点击前进/后退时触发。

```js
// 改变 URL 但不刷新
history.pushState({ page: 1 }, "", "/page1");

// 监听前进后退
window.addEventListener("popstate", (e) => {
  console.log("回到：", e.state); // { page: 1 }
});
```

> `pushState` 的妙处在于"**改 URL 不刷新页面**"，这让 SPA（单页应用）能实现无刷新的路由切换、且 URL 可收藏可分享。`popstate` 在用户点后退时触发，SPA 据此同步渲染对应页面。



#### 哈希路由与前端路由

前端路由有**哈希路由**与**History 路由**两种主流实现。

- **哈希路由**：用 URL 的 `#hash` 部分表示路由，监听 `hashchange` 事件。
- **History 路由**：用 `pushState` 改路径，监听 `popstate` 事件。

```js
// 哈希路由
window.addEventListener("hashchange", () => {
  const route = location.hash.slice(1); // 去掉 #
  console.log("当前路由：", route);
});
```

> 两种路由的取舍：哈希路由**兼容性好、无需服务器配置**（`#` 后的变化不请求服务器），但 URL 不美观；History 路由**URL 干净**，但刷新时需要服务器**配置重定向**（否则 404）。Vue Router、React Router 都同时支持这两种模式。



### 定时器

#### setTimeout 与 setInterval

**定时器**用于**延迟或周期**执行代码，是异步编程的基础。

- **`setTimeout(fn, delay)`**：延迟 `delay` 毫秒后执行**一次**。
- **`setInterval(fn, delay)`**：每隔 `delay` 毫秒执行**一次**。

```js
// 延迟 1 秒执行一次
setTimeout(() => {
  console.log("1 秒后执行");
}, 1000);

// 每 1 秒执行一次
setInterval(() => {
  console.log("每秒执行");
}, 1000);
```

> 定时器是**异步**的：`setTimeout` 会在 `delay` 后**把回调放入任务队列**，而非立即执行。这意味着实际执行时间**可能晚于** `delay`（取决于事件循环的繁忙程度），理解这一点是理解异步执行顺序的前提。



#### clearTimeout 与 clearInterval

定时器会返回一个**标识（id）**，用 `clearTimeout` / `clearInterval` 可**取消**它，防止内存泄漏。

```js
const timeoutId = setTimeout(() => {
  console.log("不会执行");
}, 1000);
clearTimeout(timeoutId); // 取消

const intervalId = setInterval(() => {
  console.log("执行");
}, 1000);
clearInterval(intervalId); // 停止
```

> 定时器用完后应**及时清除**，否则持续占用资源、可能导致内存泄漏（尤其 `setInterval` 不清理会永远执行）。这是定时器使用中最重要、也最容易被忽略的规范。



#### 定时器的嵌套与最小间隔

定时器存在**最小间隔**与**嵌套限制**，是理解其行为的细节。

- **最小间隔**：浏览器对 `setTimeout` 的延迟有**最小限制**（约 4ms，嵌套更深时更长）。
- **嵌套定时器**：嵌套超过 5 层，最小间隔会被强制为 4ms 以上。

```js
// 即使写 0，实际也不是立即执行（受最小间隔与事件循环影响）
setTimeout(() => console.log("A"), 0);
console.log("B");
// 输出顺序：B → A（定时器回调是异步的）
```

> 两个关键认知：一是 `setTimeout(fn, 0)` **不是立即执行**，而是"尽快异步执行"，回调要等当前同步代码跑完；二是延迟值存在**最小间隔**，写 `0` 或 `1` 实际不会真的那么短。这些细节常出现在执行顺序的面试题里。



#### requestAnimationFrame

**`requestAnimationFrame(callback)`**：专门用于**动画**的定时机制，让回调在**浏览器下一次重绘前**执行，实现流畅动画。

- 回调在**每帧**（通常 60fps，约 16.7ms 一次）执行。
- 浏览器会自动**优化**（页面不可见时暂停），性能优于 `setInterval`。
- 常配合递归调用实现持续动画。

```js
function animate() {
  // 更新动画
  console.log("一帧");
  requestAnimationFrame(animate); // 递归调度下一帧
}
requestAnimationFrame(animate);
```

> `requestAnimationFrame` 相比 `setInterval` 做动画的优势：**与屏幕刷新率同步**（避免掉帧、撕裂）、**自动暂停后台标签页**（省资源）。做 JS 动画应优先用它，而非定时器。
