## 继承与 ES6 class

### 继承的概念

#### 父类、子类等概念

**继承（Inheritance）**：是子类**复用父类**的属性和方法的机制，是面向对象三大特性之一。

相关概念：

- **父类（基类 / 超类）**：被继承的类。
- **子类（派生类）**：继承父类的类，可**扩展**或**重写**父类成员。
- **实例**：类的具体对象。

```js
class Animal {
  constructor(name) {
    this.name = name;
  }
  eat() {
    console.log(this.name + " 在吃东西");
  }
}

class Dog extends Animal {
  bark() {
    console.log(this.name + " 在叫");
  }
}

const dog = new Dog("旺财");
dog.eat();  // 旺财 在吃东西（继承自 Animal）
dog.bark(); // 旺财 在叫（Dog 自己的方法）
```

> 继承的价值是**代码复用与结构分层**：`Dog` 无需重写 `eat`，直接继承 `Animal`，再添加自己的 `bark`。它表达了"**狗是一种动物**"（is-a）的关系，是面向对象组织类层级的核心手段。



### 继承方案的演进

#### 原型链实现继承

**原型链继承**：让子类的原型指向父类实例，从而复用父类方法。

```js
function Parent() {
  this.name = "parent";
}
Parent.prototype.getName = function () {
  return this.name;
};

function Child() {}

// 核心：Child 的原型指向 Parent 实例
Child.prototype = new Parent();

const child = new Child();
console.log(child.getName()); // "parent"
```

> 原型链继承的思路是"**把父类实例当作子类原型**"，这样子类实例能沿原型链访问父类的属性和方法。但它有**严重弊端**（见下一节），是继承方案演进中的"第一版"。



#### 原型继承方案的弊端

原型链继承存在几个关键问题。

- **引用类型共享**：父类的引用类型属性被**所有子类实例共享**，一个改、全部变。
- **无法传参**：创建子类实例时，无法向父类构造函数传参。
- **只能单继承**。

```js
function Parent() {
  this.colors = ["red", "blue"]; // 引用类型
}
function Child() {}
Child.prototype = new Parent();

const c1 = new Child();
const c2 = new Child();
c1.colors.push("green");
console.log(c2.colors); // ["red", "blue", "green"]（c2 也被改了！）
```

> 最致命的是**引用类型共享**：`colors` 是父类实例的属性，被所有子类实例通过原型共享，`c1` 修改 `colors` 会**污染** `c2`。这正是后续方案（借用构造函数）要解决的问题。



#### 借用构造函数

**借用构造函数**：在子类构造函数中**调用父类构造函数**，解决引用类型共享与传参问题。

```js
function Parent(name) {
  this.name = name;
  this.colors = ["red", "blue"]; // 每份独立
}

function Child(name) {
  Parent.call(this, name); // 借用父类构造函数，绑定到子类实例
}

const c1 = new Child("c1");
const c2 = new Child("c2");
c1.colors.push("green");
console.log(c2.colors); // ["red", "blue"]（互不影响）
console.log(c1.name, c2.name); // "c1" "c2"（能传参）
```

> 借用构造函数的思路是"**把父类构造函数借来，以子类实例为 `this` 执行**"，这样每个实例都有**独立**的属性。它解决了引用共享和传参，但**无法复用父类原型上的方法**（每次调用都重新创建）。



#### 借用的回顾与原型赋值的弊端

借用构造函数虽然解决了属性共享，但**方法复用**仍是问题。

- 借用构造函数：属性独立了，但**方法无法放原型共享**（方法若写构造函数里，每实例一份）。
- 直接 `Child.prototype = Parent.prototype`：虽共享方法，但**子类改原型会影响父类**。

```js
function Parent() {}
Parent.prototype.sayHi = function () {};

function Child() {}
// 错误：直接共用原型，子类改动会污染父类
Child.prototype = Parent.prototype;
```

> 两个极端都有缺陷：借用构造函数**丢了方法复用**，直接共用原型**丢了独立性**。理想的方案是"**属性独立 + 方法共享**"，这引出了更完善的组合方案（寄生组合式继承）。



#### 原型式继承

**原型式继承**：借助 `Object.create`，以**指定对象为原型**创建新对象，实现浅继承。

```js
const parent = {
  name: "parent",
  colors: ["red", "blue"]
};

// 以 parent 为原型创建新对象
const child = Object.create(parent);
console.log(child.name); // "parent"（继承自 parent）
```

> 原型式继承本质是 **`Object.create(proto)`**：新对象的原型指向 `proto`，从而"继承"其属性。它适合"**基于已有对象创建相似对象**"的场景，但和原型链继承一样有**引用类型共享**的问题。



#### 寄生式继承

**寄生式继承**：在原型式继承基础上**增强对象**——创建新对象后，再添加自己的方法。

```js
function createChild(parent) {
  const child = Object.create(parent); // 原型式继承
  child.sayHi = function () {          // 增强：添加方法
    console.log("Hi");
  };
  return child;
}

const parent = { name: "parent" };
const child = createChild(parent);
console.log(child.name); // "parent"
child.sayHi();           // "Hi"
```

> 寄生式继承 = "**原型式继承 + 增强**"：先用 `Object.create` 继承，再给新对象添方法。它的思路启发了"寄生组合式继承"（下一节），但单独使用时同样无法解决引用共享。



#### 寄生组合式继承

**寄生组合式继承**：是目前**最完善的继承方案**，结合了"借用构造函数（属性独立）"与"原型链（方法共享）"。

```js
function Parent(name) {
  this.name = name;
  this.colors = ["red", "blue"];
}
Parent.prototype.sayHi = function () {
  console.log("Hi, " + this.name);
};

function Child(name, age) {
  Parent.call(this, name); // 1. 借用构造函数，属性独立
  this.age = age;
}

// 2. 寄生：让 Child.prototype 继承 Parent.prototype，但不调用 Parent
Child.prototype = Object.create(Parent.prototype);
Child.prototype.constructor = Child; // 修复 constructor 指向

const child = new Child("why", 18);
child.sayHi(); // "Hi, why"（复用父类方法）
console.log(child.constructor === Child); // true
```

> 寄生组合式继承是**最优解**：`Parent.call` 保证**属性独立**，`Object.create(Parent.prototype)` 保证**方法共享**且不重复调用父类构造函数。它也是 ES6 `class extends` 的底层实现方式，是面试必考的核心。



### ES6 的 class

#### class 定义类与类的特性

**`class`**：是 ES6 引入的**类语法**，本质是**构造函数 + 原型的语法糖**，让面向对象写法更清晰。

```js
class Person {
  constructor(name, age) {
    this.name = name;
    this.age = age;
  }
  sayHi() {
    console.log("Hi, " + this.name);
  }
}

const p = new Person("why", 18);
p.sayHi(); // "Hi, why"
console.log(typeof Person); // "function"（本质仍是函数）
```

> `class` 的两个特性：一是它**本质是函数**（`typeof Person === "function"`），是原型的语法糖；二是它**必须用 `new` 调用**（不像普通函数可裸调用），且**没有变量提升**（先声明后使用）。



#### 类的构造方法

**`constructor`**：是类的构造方法，在 `new` 时自动调用，用于**初始化实例属性**。

- 一个类只能有一个 `constructor`。
- `new` 时自动执行，`this` 指向新实例。
- 省略时会有默认的空 `constructor`。

```js
class Person {
  constructor(name, age) {
    this.name = name; // 初始化实例属性
    this.age = age;
  }
}

const p = new Person("why", 18); // new 时执行 constructor
console.log(p.name); // "why"
```

> `constructor` 相当于 ES5 里的构造函数本体，负责**接收参数、设置实例属性**。它与普通函数不同：不能用 `Person()` 裸调用，只能 `new Person()`。



#### 类中定义方法

类中定义的方法会**自动挂到原型上**（而非实例），实现方法共享。

```js
class Person {
  constructor(name) {
    this.name = name;
  }
  // 定义在原型上，所有实例共享
  sayHi() {
    console.log("Hi, " + this.name);
  }
}

const p1 = new Person("why");
const p2 = new Person("tom");
console.log(p1.sayHi === p2.sayHi); // true（共享同一方法）
```

> 类中写的方法（非 `constructor`）会放在**类的 `prototype` 上**，因此所有实例**共享**同一份方法。这与"构造函数存属性、原型存方法"的组合方案完全一致，只是语法更清晰。



#### class 实现继承与逻辑复用

**`class extends`** 实现继承，用 **`super`** 调用父类。

```js
class Animal {
  constructor(name) {
    this.name = name;
  }
  eat() {
    console.log(this.name + " 吃东西");
  }
}

class Dog extends Animal {
  constructor(name, age) {
    super(name); // 调用父类 constructor
    this.age = age;
  }
  bark() {
    console.log(this.name + " 叫");
  }
  eat() {
    super.eat(); // 调用父类方法
    console.log("吃完了");
  }
}

const dog = new Dog("旺财", 3);
dog.bark(); // 旺财 叫
dog.eat();  // 旺财 吃东西 / 吃完了
```

> `class` 继承的要点：**`extends` 声明继承，`super` 调用父类**。子类 `constructor` 里**必须先调 `super()`** 才能用 `this`；`super.method()` 用于调用父类的同名方法，实现"扩展而非覆盖"。



#### 扩展继承内置类

`class` 可以继承**内置类**（如 `Array`、`Error`），扩展其功能。

```js
class MyArray extends Array {
  first() {
    return this[0];
  }
  last() {
    return this[this.length - 1];
  }
}

const arr = new MyArray(1, 2, 3);
console.log(arr.first()); // 1
console.log(arr.last());  // 3
console.log(arr instanceof Array); // true
```

> 继承内置类的价值：`MyArray` 拥有 `Array` 的全部能力，还能**添加自定义方法**。这在 ES5 中很难做到（无法正确继承 `Array` 的 `length` 行为），`class` 让"扩展内置类型"变得简单可靠。



#### 类的混入与 React 技巧

**混入（Mixin）**：把多个类的功能**组合**到一个类里，弥补 JS 单继承的局限。

```js
function mixin(Base, ...mixins) {
  return mixins.reduce((Class, mixinFn) => mixinFn(Class), Base);
}

// 混入函数：给类加方法
const canFly = (Base) => class extends Base {
  fly() { console.log("飞"); }
};
const canSwim = (Base) => class extends Base {
  swim() { console.log("游"); }
};

class Bird {}
const FlyingBird = mixin(Bird, canFly, canSwim);
const bird = new FlyingBird();
bird.fly();  // 飞
bird.swim(); // 游
```

> 混入解决的是"**多继承**"需求：JS 的 `class` 只能单继承，但通过混入可以把多个类的功能"**拼接**"到一个类上。React 早期的 `React.createClass` 混入、高阶组件（HOC）等都借鉴了这一思想。



#### 私有属性的实现方式

类中的**私有属性**有几种实现方式，`#` 是标准方案。

- **约定式**：用 `_` 前缀（只是约定，不强制）。
- **`Symbol`**：用 Symbol 键降低访问概率。
- **`#` 私有字段（ES2022）**：真正的私有，外部无法访问。

```js
class Person {
  #secret = "私有值"; // 私有字段

  getSecret() {
    return this.#secret; // 类内部可访问
  }
}

const p = new Person();
console.log(p.getSecret()); // "私有值"
// console.log(p.#secret);  // 语法错误：外部无法访问
```

> `#` 私有字段是**真正的私有**：只能在类内部访问，外部（包括子类）都无法直接读取。相比 `_` 约定（只是君子协定）和 `Symbol`（仍可通过反射获取），`#` 提供了语言级的封装保障。



#### class 转 ES5 源码阅读

理解 `class` 本质，最直接的方式是看它**转成 ES5** 后的样子。

```js
// ES6 class
class Person {
  constructor(name) {
    this.name = name;
  }
  sayHi() {
    console.log("Hi");
  }
}

// 转 ES5（核心等价逻辑）
function Person(name) {
  this.name = name;
}
Person.prototype.sayHi = function () {
  console.log("Hi");
};
```

> `class` 转 ES5 就是"**构造函数 + 原型方法**"：`constructor` 变成构造函数体，类方法变成 `prototype` 上的方法。这印证了"**class 是原型的语法糖**"，理解这个转换，才能真正理解 class 的本质。



#### ES6 的继承转 ES5 源码阅读

`class extends` 转 ES5，正是**寄生组合式继承**。

```js
// ES6
class Dog extends Animal {
  constructor(name) {
    super(name);
  }
}

// 转 ES5（核心逻辑）
function Dog(name) {
  Animal.call(this, name); // 借用构造函数
}
Dog.prototype = Object.create(Animal.prototype); // 原型链
Dog.prototype.constructor = Dog;
```

> `class extends` 转 ES5 就是**寄生组合式继承**：`Animal.call` 借属性、`Object.create` 借方法。这再次印证：ES6 的继承方案，本质上就是前面讲的"最完善继承方案"的语法糖。



#### 阅读源码的技巧与习惯

阅读框架/库源码是进阶的必经之路，需要一些方法与习惯。

- **从入口入手**：先找到 `main`/入口文件，理解整体结构。
- **抓大放小**：先理解**核心流程**，忽略边界细节。
- **善用搜索**：对关键函数/类名全局搜索，追踪调用链。
- **结合调试**：打断点、`console.log` 观察运行时行为。
- **看编译产物**：理解语法糖时，看 Babel 转译结果很直观。

```js
// 阅读技巧示例：看 Babel 转译理解语法糖
// class → 构造函数 + 原型；箭头函数 → 普通函数绑定 this
```

> 读源码的核心习惯是"**带着问题读、抓住主线**"：不必逐行读懂，而是理解"**数据如何流动、调用链如何走**"。配合调试工具与编译产物，能把复杂的源码拆解成可理解的结构。



### 多态

**多态（Polymorphism）**：是面向对象三大特性之一，指**同一方法在不同对象上表现出不同行为**。JS 中通过**方法重写**与**动态类型**天然支持。

```js
class Animal {
  makeSound() {
    console.log("动物叫");
  }
}

class Dog extends Animal {
  makeSound() {
    console.log("汪汪");
  }
}

class Cat extends Animal {
  makeSound() {
    console.log("喵喵");
  }
}

// 同一个 makeSound 方法，不同对象表现不同
const animals = [new Dog(), new Cat()];
animals.forEach((animal) => animal.makeSound());
// 汪汪 / 喵喵
```

> 多态的精髓是"**同一个接口，多种实现**"：调用 `makeSound()` 时，具体行为由**对象实际类型**决定。它让代码**面向抽象编程**（写 `Animal`，运行时按实际子类执行），是设计模式（如策略模式、依赖倒置）的基础。
