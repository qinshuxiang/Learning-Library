## 原型与原型链

### 面向对象的概念

#### 面向对象与 JS 创建对象的方式

**面向对象编程（OOP）**：是一种以**对象**为核心组织代码的编程范式，通过**封装、继承、多态**来组织和管理代码。

JavaScript 创建对象的方式经历了演进：

- **对象字面量**：`{ key: value }`，适合单个对象。
- **工厂函数**：返回对象，适合批量创建但无法识别类型。
- **构造函数 + `new`**：可识别类型。
- **`Object.create()`**：以指定对象为原型创建。
- **ES6 `class`**：语法糖，本质仍是原型。

```js
// 字面量
const obj1 = { name: "why" };

// 构造函数
function Person(name) {
  this.name = name;
}
const obj2 = new Person("why");

// Object.create
const proto = { greet() { return "hi"; } };
const obj3 = Object.create(proto);
console.log(obj3.greet()); // "hi"
```

> 理解"创建对象的多种方式"是理解**原型**的入口：`new`、`Object.create`、`class` 背后都依赖**原型机制**。JavaScript 的面向对象是**基于原型的**，而非传统的基于类。



#### JS 面向对象中的各种概念

JavaScript 面向对象中，几个核心概念需厘清。

- **对象（Object）**：属性与方法的集合。
- **类（Class）**：对象的模板（JS 中用构造函数或 `class` 表达）。
- **实例（Instance）**：类的具体对象。
- **原型（Prototype）**：对象之间共享属性的机制。

```js
function Person(name) {
  this.name = name;
}
Person.prototype.sayHi = function () {
  console.log("Hi, " + this.name);
};

const p = new Person("why"); // p 是 Person 的实例
p.sayHi(); // 通过原型共享 sayHi
```

> 关键认知：JS 中"类"（构造函数）与"实例"之间靠**原型**连接——实例通过原型链**共享**构造函数原型上的方法，从而实现"所有实例共用一份方法"的效果。



### 创建对象的方案

#### 工厂模式

**工厂模式（Factory Pattern）**：用函数**返回对象**来批量创建对象，但无法识别类型。

```js
function createPerson(name, age) {
  const obj = {};
  obj.name = name;
  obj.age = age;
  obj.sayHi = function () {
    console.log("Hi, " + this.name);
  };
  return obj;
}

const p1 = createPerson("why", 18);
const p2 = createPerson("tom", 20);
console.log(p1 instanceof createPerson); // false（无法识别类型）
```

> 工厂模式的**缺点**是"**无法识别类型**"：`p1` 和 `p2` 没有共同的类型标识，`instanceof` 无法判断。它的优点是简单，但不满足面向对象"识别类型"的需求，于是有了构造函数。



#### 构造函数

**构造函数**：用 `new` 调用的函数，`this` 指向新对象，可识别类型。

```js
function Person(name, age) {
  this.name = name;
  this.age = age;
  this.sayHi = function () {
    console.log("Hi, " + this.name);
  };
}

const p1 = new Person("why", 18);
const p2 = new Person("tom", 20);
console.log(p1 instanceof Person); // true（可识别类型）
```

> 构造函数解决了"**识别类型**"问题（`instanceof` 可用）。但它有新问题：**每个实例都创建了一份 `sayHi` 方法**，浪费内存——这引出了"把方法放原型"的优化（见后续"原型"章节）。



#### new 的模拟实现

手写 `new`，理解它到底做了什么。

```js
function myNew(constructor, ...args) {
  // 1. 创建新对象，其原型指向构造函数的 prototype
  const obj = Object.create(constructor.prototype);
  // 2. 以 obj 为 this 调用构造函数
  const result = constructor.apply(obj, args);
  // 3. 若构造函数返回对象则用返回值，否则用 obj
  return result instanceof Object ? result : obj;
}

function Person(name) {
  this.name = name;
}
const p = myNew(Person, "why");
console.log(p.name); // "why"
console.log(p instanceof Person); // true
```

> `new` 做了三件事：**创建对象并链接原型**（`Object.create(prototype)`）、**绑定 `this` 执行构造函数**、**返回对象**。手写 `new` 是理解"构造函数如何产出实例"的关键，也是面试高频题。



#### 构造函数的缺点

构造函数虽然好用，但存在一个**内存浪费**的缺点。

```js
function Person(name) {
  this.name = name;
  this.sayHi = function () {}; // 每个实例都有一份独立的方法
}

const p1 = new Person("why");
const p2 = new Person("tom");

console.log(p1.sayHi === p2.sayHi); // false（两份不同的函数）
```

> 缺点在于：**每次 `new` 都创建一份新的方法**，`p1.sayHi` 和 `p2.sayHi` 是**不同**的函数，浪费内存。理想的方案是"**方法只存一份、所有实例共享**"——这正是**原型（prototype）** 要解决的问题。



### 原型的理解

#### 对象的原型与作用

绝大多数对象都有一个**原型**（规范称内部槽位 `[[Prototype]]`，可通过 `__proto__` 或 `Object.getPrototypeOf()` 访问），对象可以**访问原型上的属性**，实现属性共享。

```js
function Person(name) {
  this.name = name;
}

// 把方法放到原型上
Person.prototype.sayHi = function () {
  console.log("Hi, " + this.name);
};

const p1 = new Person("why");
const p2 = new Person("tom");

p1.sayHi(); // "Hi, why"
p2.sayHi(); // "Hi, tom"
console.log(p1.sayHi === p2.sayHi); // true（共享同一方法）
```

> 原型的作用：**把共享的属性/方法放到原型上，让所有实例共用一份**。`sayHi` 只定义一次，`p1`、`p2` 都通过原型链访问到**同一个**函数，既省内存、又便于统一修改。

> 辨析：`__proto__` 并不是对象的自有属性，而是定义在 `Object.prototype` 上的**访问器属性**（getter/setter），MDN 已将其标注为**已弃用**的遗留特性，生产代码推荐用 `Object.getPrototypeOf(obj)` 读取原型。此外**并非每个对象都有原型**：`Object.create(null)` 创建的对象原型为 `null`，不继承任何方法（详见原型链章节的"空原型对象"）。



#### 构造函数创建对象的内存表现

从**内存**角度理解原型如何节省空间。

- 实例对象只存**自身属性**（如 `name`）。
- **共享的方法**存到构造函数的 `prototype` 上。
- 实例通过 `__proto__` 指向原型，**按需查找**方法。

```js
function Person(name) {
  this.name = name; // 实例自身属性，每份独立
}
Person.prototype.sayHi = function () {}; // 共享方法，只存一份

const p1 = new Person("why");
console.log(p1.__proto__ === Person.prototype); // true
```

> 内存表现：`name` 是**实例私有**（每份独立），`sayHi` 是**原型共享**（一份）。实例通过 `__proto__` 链到原型，访问 `sayHi` 时沿链查找。这种"**私有数据 + 共享方法**"的分工，是原型设计的内存动机。



#### 对构造函数原型的修改

原型是**动态**的，可以在创建实例后**继续修改**，实例能立即感知。

```js
function Person(name) {
  this.name = name;
}

const p = new Person("why");

// 创建实例后再给原型加方法
Person.prototype.sayHi = function () {
  console.log("Hi, " + this.name);
};

p.sayHi(); // "Hi, why"（实例立即能用新增的方法）
```

> 原型的**动态性**：因为实例通过 `__proto__` 指向原型对象（引用关系），所以**事后修改原型**，实例也能立刻访问到。但若**整体重写** `Person.prototype = {...}`，则**之前**创建的实例的 `__proto__` 仍指向旧原型，会"断开"。



#### 原型与构造函数组合方案

**原型 + 构造函数组合**：是创建对象的最佳实践——**构造函数存私有属性，原型存共享方法**。

```js
function Person(name, age) {
  this.name = name;   // 私有属性
  this.age = age;     // 私有属性
}

// 共享方法放原型
Person.prototype.sayHi = function () {
  console.log(`Hi, 我叫 ${this.name}`);
};
Person.prototype.eat = function () {
  console.log(`${this.name} 在吃饭`);
};

const p1 = new Person("why", 18);
const p2 = new Person("tom", 20);
p1.sayHi(); // Hi, 我叫 why
p2.eat();   // tom 在吃饭
```

> 组合方案是**最经典、最推荐**的写法：**属性私有（放构造函数）、方法共享（放原型）**。它兼顾了"数据独立"与"方法复用"，也是 ES6 `class` 底层做的事。



### 原型链

#### 原型链的理解

**原型链（Prototype Chain）**：是对象**逐层向上查找属性**的链路，由 `__proto__` 串联而成，是 JS 实现继承的机制。

```js
function Person(name) {
  this.name = name;
}
Person.prototype.sayHi = function () {};

const p = new Person("why");

// 查找 sayHi：p 自身没有 → p.__proto__（Person.prototype）有 → 找到
p.sayHi();

// 查找 toString：p → Person.prototype → Object.prototype → 找到
p.toString();

console.log(p.__proto__ === Person.prototype);        // true
console.log(Person.prototype.__proto__ === Object.prototype); // true
```

> 原型链的查找规则：**从自身开始，沿 `__proto__` 逐层向上，直到找到或到达 `null`**。`p.sayHi` 在 `Person.prototype` 找到，`p.toString` 则继续向上到 `Object.prototype` 才找到。这条链就是"继承"的底层实现。



#### 顶层原型 Object 的原型对象

**`Object.prototype`** 是原型链的**顶端**（再往上是 `null`），几乎所有对象最终都链到它。

- `Object.prototype` 提供 `toString`、`hasOwnProperty` 等通用方法。
- `Object.prototype.__proto__` 是 `null`（链的终点）。

```js
const obj = {};
console.log(obj.__proto__ === Object.prototype); // true
console.log(Object.prototype.__proto__);         // null（链的终点）

console.log(obj.toString()); // 从 Object.prototype 继承的方法
```

> `Object.prototype` 是**万物的祖先**：数组、函数、普通对象，原型链最终都指向它。它上面的方法（`toString`、`hasOwnProperty` 等）因此能被所有对象使用。`Object.prototype.__proto__ === null` 标志着原型链的**终点**。



#### Object.create 与空原型对象

**`Object.create(proto, propertiesObject)`**：创建一个新对象，并把 `proto` 设为该对象的原型；第二个参数可选，是属性描述符映射，用法与 `Object.defineProperties()` 一致。

```js
const proto = { greet() { return "hi"; } };

// 第二个参数：属性描述符映射（可选）
const obj = Object.create(proto, {
  name: {
    value: "why",
    writable: true,
    enumerable: true,
    configurable: true
  }
});

console.log(obj.greet());  // "hi"（来自原型）
console.log(obj.name);     // "why"（自有属性，由描述符定义）
console.log(obj.__proto__ === proto); // true
```

`Object.create(null)` 创建**空原型对象**：它的原型是 `null`，**不经过 `Object.prototype`**，因此没有 `toString`、`hasOwnProperty` 等任何继承方法。

```js
const dict = Object.create(null);

console.log(dict.__proto__);            // null
// dict.toString();                     // TypeError: dict.toString is not a function
// dict.hasOwnProperty("a");            // 同样报错（没有继承任何方法）

// 等价写法：对象字面量的 __proto__: null（这是标准语法，与已弃用的
// Object.prototype.__proto__ 访问器不同）
const dict2 = { __proto__: null };
```

- **字典对象**：用 `Object.create(null)` 做"纯键值容器"，查询时不会误命中继承属性（如 `"toString" in {}` 为 `true`，而 `"toString" in dict` 为 `false`）。
- **防原型污染**：普通对象会受 `Object.prototype` 被恶意扩展的影响，空原型对象免疫这类攻击。
- **内置产出**：`Object.groupBy()` 的返回值、`import.meta`、模块命名空间对象等内置 API 都使用空原型对象。

> 辨析：`Object.create(null)` 与 `{}` 的差别在于**是否挂在 `Object.prototype` 链上**。空原型对象失去了 `hasOwnProperty`、`toString` 等方法，调试时 `console.log` 可能直接报错（无法转原始值）；需要回到普通对象可用 `Object.setPrototypeOf(dict, Object.prototype)`。依据：MDN `Object` 文档"null 原型对象"一节。



#### Person 原型对象指向顶层对象

自定义构造函数的原型对象，其 `__proto__` 也指向 `Object.prototype`，形成完整链条。

```js
function Person(name) {
  this.name = name;
}

// Person.prototype 是个普通对象，它的原型是 Object.prototype
console.log(Person.prototype.__proto__ === Object.prototype); // true

// 完整原型链：p → Person.prototype → Object.prototype → null
const p = new Person("why");
console.log(p.__proto__.__proto__.__proto__); // null
```

> 这揭示了原型链的**层级**：`p`（实例）→ `Person.prototype` → `Object.prototype` → `null`。每一层"原型"本身也是对象，也有自己的原型，层层链接直到 `null`。理解这条完整链条，就理解了 JS 的继承本质。



#### 原型的判断方法

判断原型关系有多个方法，各有用途。

##### instanceof

**`instanceof`**：判断对象是否是某构造函数的实例，原理是**沿原型链查找** `prototype`。

```js
function Person() {}
const p = new Person();

console.log(p instanceof Person); // true
console.log(p instanceof Object); // true（原型链顶端是 Object.prototype）
console.log(p instanceof Array);  // false
```

> `instanceof` 判断的是"**构造函数的 prototype 是否在对象的原型链上**"。`p instanceof Object` 为 `true` 是因为 `Person.prototype` 的原型是 `Object.prototype`。



##### isPrototypeOf()

**`obj.isPrototypeOf(target)`**：判断 `obj` 是否在 `target` 的**原型链上**。

```js
function Person() {}
const p = new Person();

console.log(Person.prototype.isPrototypeOf(p));     // true
console.log(Object.prototype.isPrototypeOf(p));     // true
```

> `isPrototypeOf` 与 `instanceof` 方向相反：`A instanceof B` 问"`A` 是 `B` 的实例吗"，`B.prototype.isPrototypeOf(A)` 问"`B` 的原型在 `A` 的链上吗"。二者本质等价，视角不同。



##### hasOwnProperty()

**`obj.hasOwnProperty(key)`**：判断属性是否是对象**自身**的属性（而非继承自原型）。

```js
function Person() {
  this.name = "why"; // 自身属性
}
Person.prototype.sayHi = function () {}; // 原型属性

const p = new Person();
console.log(p.hasOwnProperty("name"));   // true（自身）
console.log(p.hasOwnProperty("sayHi"));  // false（继承自原型）
```

> `hasOwnProperty` 用于区分"**自身属性 vs 继承属性**"：`name` 是实例自己的，`sayHi` 是原型的。遍历对象时常用它过滤掉原型上的属性，只处理自身属性。



##### in 操作符

**`in` 操作符**：判断属性是否**可访问**（无论自身还是原型链上）。

```js
function Person() {
  this.name = "why";
}
Person.prototype.sayHi = function () {};

const p = new Person();

console.log("name" in p);   // true（自身属性）
console.log("sayHi" in p);  // true（原型属性）
console.log("xxx" in p);    // false
```

> `in` 与 `hasOwnProperty` 的区别：`in` **只要属性在原型链上任何位置**就返回 `true`，`hasOwnProperty` **只认自身属性**。判断"属性是否存在（含继承）"用 `in`，判断"是否是自身属性"用 `hasOwnProperty`。



#### 对象、函数与原型之间的关系

对象、函数、原型三者构成了 JS 的**核心关系网**，需理清。

- **函数**是对象，有 `prototype` 属性（普通对象没有）。
- **对象**有 `__proto__` 指向其原型。
- **`prototype` 对象**的 `constructor` 指回构造函数。

```js
function Person() {}

// 函数 → prototype → constructor 指回函数
console.log(Person.prototype.constructor === Person); // true

// 实例 → __proto__ → 构造函数的 prototype
const p = new Person();
console.log(p.__proto__ === Person.prototype); // true

// 函数本身也是对象，其 __proto__ 指向 Function.prototype
console.log(Person.__proto__ === Function.prototype); // true
```

> 三者的关系是 JS 最"绕"也最重要的知识点：**`prototype` 是函数独有的（供实例共享），`__proto__` 是对象独有的（指向原型），`constructor` 指回构造函数**。理清这三条线，原型就通了。



#### 原型链的重要性与应用场景

原型链是 JS 的**核心机制**，其重要性体现在多个方面。

- **继承**：子类复用父类的方法（`class extends` 的底层）。
- **方法共享**：所有实例共享原型方法，节省内存。
- **扩展内置对象**：给 `Array.prototype`、`String.prototype` 加方法。
- **理解框架**：Vue、React 等框架内部大量使用原型。

```js
// 扩展内置对象（慎用）
Array.prototype.first = function () {
  return this[0];
};
console.log([1, 2, 3].first()); // 1
```

> 原型链的重要性：它是**继承**的底层（ES6 `class` 只是其语法糖）、是**方法共享**的机制、是**理解一切框架源码**的钥匙。掌握原型链，才算真正"入门" JavaScript 的面向对象。扩展内置原型需**谨慎**（可能冲突、污染全局）。
