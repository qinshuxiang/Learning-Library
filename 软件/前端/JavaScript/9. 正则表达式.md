## 正则表达式

### 正则表达式的定义与作用

**正则表达式（Regular Expression，简称 RegExp）**：是用于**匹配字符串中字符组合的模式**，本质是一种"模式描述语言"。它用一套紧凑的语法，描述"要匹配什么样的文本"。

正则的核心作用：

- **验证**：判断字符串是否符合格式（手机号、邮箱、密码强度）。
- **搜索**：在文本中查找匹配的内容。
- **替换**：批量替换文本中的特定模式。
- **提取**：从字符串中抽取所需部分。

```js
const email = "user@example.com";
const emailReg = /^\w+@\w+\.\w+$/;
console.log(emailReg.test(email)); // true（验证格式）
```

> 正则的价值在于"**用声明式的模式代替繁琐的字符串判断**"。一个手机号校验，用手写 `if` 可能几十行，用正则一行搞定。它难在"语法紧凑、不直观"，但一旦掌握，处理文本的效率会成倍提升。



### 创建正则表达式对象

#### 方式一：构造函数

用 `new RegExp(pattern, flags)` 创建正则，**`pattern` 是字符串**，适用于**模式动态生成**的场景。

```js
// 用构造函数，pattern 是字符串，注意转义
const reg = new RegExp("hello", "i");
console.log(reg.test("Hello World")); // true（i 忽略大小写）

// 动态生成模式
const keyword = "abc";
const dynamicReg = new RegExp(keyword, "g");
console.log(dynamicReg.test("abcabc")); // true
```

> 构造函数创建时，`pattern` 是**字符串**，因此字符串中的反斜杠需要额外转义（如 `\d` 要写成 `"\\d"`）。当正则需要**根据变量动态拼接**时，只能用它。



#### 方式二：字面量

用 `/pattern/flags` 直接书写，**`pattern` 是字面量**，是最简洁、最常用的方式，性能也更好。

```js
const reg = /hello/i;
console.log(reg.test("Hello")); // true

// 修饰符写在最后一个斜杠之后
const globalReg = /a/g;  // g：全局匹配
const multiReg = /^a/m;  // m：多行模式
```

> 字面量与构造函数的区别：字面量在**解析时**编译一次（性能好）、模式固定；构造函数在**运行时**编译、模式可动态。模式不变时优先用字面量，模式需动态生成时才用构造函数。



### 匹配模式

正则的**修饰符（flags）**控制匹配行为，常见的几个需牢记。

- **`g`（global）**：全局匹配，找出所有匹配，而非只匹配第一个。
- **`i`（ignoreCase）**：忽略大小写。
- **`m`（multiline）**：多行模式，让 `^` 和 `$` 匹配每行的开头结尾。
- **`s`（dotAll）**：让 `.` 也能匹配换行符。
- **`u`（unicode）**：启用 Unicode 支持（正确处理 emoji、代理对）。
- **`y`（sticky）**：粘性匹配，从 `lastIndex` 位置开始精确匹配。

```js
console.log(/a/g.test("aaa")); // true
console.log(/a/i.test("A"));   // true
console.log(/^b/m.test("a\nb")); // true（m 模式匹配每行开头）
console.log(/a.b/s.test("a\nb")); // true（s 模式 . 匹配换行）
```

> 修饰符可**组合使用**，如 `/abc/gi` 表示全局 + 忽略大小写。最常用的是 `g` 和 `i`，`u` 在处理含 emoji、中文等 Unicode 字符时很重要，`s` 在跨行匹配时不可或缺。



### test 方法

**`reg.test(str)`**：测试字符串是否**包含**匹配项，返回布尔值。是验证场景最常用的方法。

```js
const reg = /hello/i;
console.log(reg.test("Hello World")); // true
console.log(reg.test("world"));       // false
```

> `test` 返回布尔，用于"是否匹配"的判断（如表单验证）。注意：当正则带 `g` 标志时，`test` 会从 `lastIndex` 位置开始匹配，多次调用可能得到交替结果，这是经典的 `lastIndex` 陷阱。



### 正则表达式的简单语法

#### 字符类

**字符类**用于匹配某类字符，是正则的基础语法。

- **`\d`**：数字（0-9），`\D` 非数字。
- **`\w`**：单词字符（字母、数字、下划线），`\W` 非单词字符。
- **`\s`**：空白字符（空格、制表符、换行），`\S` 非空白。
- **`.`**：任意单个字符（除换行）。
- **`[abc]`**：方括号内任选一个，`[a-z]` 范围，`[^abc]` 取反。

```js
console.log(/\d/.test("abc123"));   // true
console.log(/\d{3}/.test("abc123")); // true（连续 3 个数字）
console.log(/[aeiou]/.test("hello")); // true
console.log(/[^0-9]/.test("123"));   // false（全数字，无非数字）
```

> 大写形式（`\D`、`\W`、`\S`）是**小写的取反**。方括号 `[]` 表示"字符集合"，可写范围（`[a-z]`、`[0-9]`）或用 `^` 取反（`[^...]`）。



#### 量词

**量词**指定匹配的次数，紧跟在被修饰的字符之后。

- **`*`**：0 次或多次。
- **`+`**：1 次或多次。
- **`?`**：0 次或 1 次。
- **`{n}`**：恰好 n 次。
- **`{n,}`**：至少 n 次。
- **`{n,m}`**：n 到 m 次。

```js
console.log(/a*/.test("bbb"));   // true（0 次也算匹配）
console.log(/a+/.test("bbb"));   // false（至少 1 次）
console.log(/colou?r/.test("color")); // true（u 可有可无）
console.log(/\d{2,4}/.test("123"));   // true（2 到 4 个数字）
```

> 量词的**贪婪性**：默认尽可能多地匹配（贪婪），加 `?` 变为**非贪婪**（`*?`、`+?`、`{n,m}?`）尽可能少地匹配。理解贪婪与非贪婪是写出精确正则的关键。



#### 边界

**边界**用于匹配位置而非字符，锚定匹配的范围。

- **`^`**：字符串（或行，配合 `m`）开头。
- **`$`**：字符串（或行）结尾。
- **`\b`**：单词边界（单词与非单词字符之间）。
- **`\B`**：非单词边界。

```js
console.log(/^abc/.test("abcdef"));  // true（以 abc 开头）
console.log(/abc$/.test("xyzabc"));  // true（以 abc 结尾）
console.log(/\bcat\b/.test("a cat")); // true（独立的 cat 单词）
console.log(/\bcat\b/.test("category")); // false（cat 不是独立单词）
```

> `^` 和 `$` 常用于**全串匹配**（如邮箱校验 `/^\w+@\w+\.\w+$/`）。`\b` 用于匹配**完整单词**，避免把 `cat` 匹配到 `category` 里。边界匹配"位置"而非"字符"，不消耗字符。



#### 断言：先行与后行

**断言（Assertion）**：匹配某个**位置**需满足的条件，但**不消耗字符**，分先行和后行。

- **`x(?=y)` 先行断言**：x 后面必须是 y。
- **`x(?!y)` 先行否定断言**：x 后面不能是 y。
- **`(?<=y)x` 后行断言**：x 前面必须是 y。
- **`(?<!y)x` 后行否定断言**：x 前面不能是 y。

```js
console.log(/\d+(?=元)/.exec("价格 100元"));  // 100（后面是"元"）
console.log(/\d+(?!元)/.exec("数量 100件"));  // 100（后面不是"元"）
console.log(/(?<=￥)\d+/.exec("￥99"));       // 99（前面是 ￥）
console.log(/(?<!￥)\d+/.exec("$99"));        // 99（前面不是 ￥）
```

> 断言的精髓是**"只检查、不消费"**：`(?=元)` 检查后面是"元"但不把它算进匹配结果。后行断言（`(?<=...)`）是 ES2018 引入的新特性，之前 JS 只支持先行断言。



#### 分组与或

**分组 `()`** 和 **或 `|`** 用于组合与选择。

- **`(...)` 分组**：把多个字符当作一个整体，可配合量词、捕获结果。
- **`(?:...)` 非捕获分组**：分组但不捕获，只用于组合。
- **`a|b` 或**：匹配 a 或 b。

```js
console.log(/(ab)+/.test("ababab"));   // true（ab 作为整体重复）
console.log(/cat|dog/.test("dog"));    // true（匹配 cat 或 dog）
console.log(/gr(a|e)y/.test("grey"));  // true（gray 或 grey）

const match = /(\d{4})-(\d{2})/.exec("2024-01");
console.log(match[1], match[2]); // "2024" "01"（捕获分组）
```

> 分组有两大作用：**组合**（把多字符当整体加量词）和**捕获**（用括号提取匹配子串）。`?:` 表示"只组合不捕获"，用于不需要提取结果的场景，能略微提升性能。



### 支持正则的 String 方法

#### split

**`str.split(separator)`**：用正则作为分隔符把字符串拆成数组。

```js
const str = "apple,banana;orange";
console.log(str.split(/[,;]/)); // ["apple", "banana", "orange"]
```

> `split` 配合正则能按**多种分隔符**拆分，比只传字符串灵活得多。如按任意空白拆分：`"a b\tc".split(/\s+/)`。



#### search

**`str.search(regexp)`**：返回**第一个匹配的位置**，找不到返回 `-1`。与 `indexOf` 类似，但接受正则。

```js
const str = "Hello World";
console.log(str.search(/World/)); // 6
console.log(str.search(/xyz/));   // -1
```

> `search` 只返回**位置**、忽略 `g` 标志（始终找第一个）。它与 `indexOf` 的区别是能接受正则，适合"找模式位置"而非"找字面量位置"。



#### match

**`str.match(regexp)`**：返回匹配结果，返回**数组**或 `null`。

- 不带 `g`：返回第一个匹配及其**捕获分组**。
- 带 `g`：返回**所有匹配**的数组（不含分组细节）。

```js
const str = "2024-01-15";

console.log(str.match(/\d+/));   // ["2024"]（第一个匹配）
console.log(str.match(/\d+/g));  // ["2024", "01", "15"]（全部匹配）

const m = str.match(/(\d{4})-(\d{2})/);
console.log(m[1], m[2]); // "2024" "01"（捕获分组）
```

> `match` 带 `g` 时只返回匹配的**完整串**（不含分组），不带 `g` 时返回**第一个匹配 + 分组**。需要"所有匹配 + 分组细节"时，用 ES2020 的 `matchAll`（见本章末尾）。



#### replace

**`str.replace(regexp, replacement)`**：用正则匹配并替换，是正则最强大的应用场景。

- `replacement` 可用字符串，其中 `$1`、`$2` 引用捕获分组。
- `replacement` 也可以是**函数**，动态生成替换内容。

```js
const str = "2024-01-15";
console.log(str.replace(/-/g, "/")); // "2024/01/15"

// 用 $1、$2 引用分组：交换顺序
console.log(str.replace(/(\d{4})-(\d{2})/, "$2/$1")); // "01/2024"

// 用函数：动态替换
console.log(str.replace(/\d+/g, (m) => Number(m) * 2));
// "4048-02-30"
```

> `replace` 配合 `g` 标志才能替换**全部**匹配（否则只替换第一个）。`$1`、`$2` 引用捕获分组、函数形式的回调（参数依次是完整匹配、各分组、位置、原串）是实现**高级替换**的两大利器。



### 常见正则举例

#### 手机号

手机号校验是正则最典型的应用，需结合国内号段规则。

```js
// 国内手机号：1 开头，第二位 3-9，共 11 位
const phoneReg = /^1[3-9]\d{9}$/;

console.log(phoneReg.test("13812345678")); // true
console.log(phoneReg.test("12812345678")); // false（第二位 2 不合法）
console.log(phoneReg.test("1381234567"));  // false（不足 11 位）
```

> 手机号正则拆解：`^` 开头、`1` 固定首位、`[3-9]` 第二位、`\d{9}` 剩余 9 位数字、`$` 结尾。用 `^...$` 做**全串匹配**是关键，否则 `13812345678abc` 也会通过 `test`（因为 `test` 是包含匹配）。



#### 去掉首尾空格

去除首尾空格可用正则配合 `replace`，也可直接使用 `trim` 方法。

```js
const str = "  hello world  ";

// 正则实现
console.log(str.replace(/^\s+|\s+$/g, "")); // "hello world"

// 原生方法（推荐）
console.log(str.trim()); // "hello world"
```

> 虽然 `trim()` 已原生支持去首尾空格，但理解 `/^\s+|\s+$/g` 的写法很有价值：`^\s+` 匹配开头空白、`\s+$` 匹配结尾空白、`|` 表示"或"、`g` 全局匹配。这种"开头或结尾"的模式在清洗数据时常见。



#### 邮箱

邮箱格式校验是经典正则，需覆盖常见的用户名@域名.后缀结构。

```js
// 简化版邮箱正则
const emailReg = /^[\w.-]+@[\w-]+\.[\w.]+$/;

console.log(emailReg.test("user@example.com"));  // true
console.log(emailReg.test("a.b-c@sub.domain.cn")); // true
console.log(emailReg.test("user@example"));      // false（缺后缀）
console.log(emailReg.test("@example.com"));      // false（缺用户名）
```

> 邮箱正则拆解：`[\w.-]+` 用户名（字母数字下划线点横线）、`@` 固定、`[\w-]+` 域名、`\.` 转义的点、`[\w.]+` 后缀。需注意：**完整的 RFC 邮箱规则极复杂**，这个正则只是实用简化版，生产环境应配合真实邮件发送验证。



### 正则的扩展

#### u 修饰符与 Unicode 属性转义

**`u` 修饰符**：启用完整的 Unicode 支持，正确处理代理对（如 emoji）和 Unicode 属性转义 `\p{...}`。

```js
// 无 u：把 emoji 拆成两个代理对
console.log(/^.$/.test("😀"));  // false（emoji 是两个码元）
console.log(/^.$/u.test("😀")); // true（u 按码点匹配）

// Unicode 属性转义：\p{...}
console.log(/\p{Emoji}/u.test("😀"));   // true（是 emoji）
console.log(/\p{Script=Han}/u.test("中")); // true（是汉字）
```

> `u` 修饰符让 `.`、量词、字符类都**按码点而非码元**处理，是处理 emoji、生僻字等代理对字符的必备。`\p{...}` 属性转义能按 `Emoji`、`Script=Han`（汉字）等类别匹配，功能强大。



#### y 修饰符与 sticky 模式

**`y` 修饰符（sticky，粘性模式）**：要求匹配**必须从 `lastIndex` 指定的位置开始**，不能跳过。

```js
const reg = /a/y;
reg.lastIndex = 1;
console.log(reg.exec("ba")); // ["a"]（从位置 1 精确匹配）

reg.lastIndex = 0;
console.log(reg.exec("ba")); // null（位置 0 是 "b"，不匹配）
```

> `y` 与 `g` 的区别：`g` 会**向后搜索**到下一个匹配，`y` 要求**就在当前位置**匹配、否则失败。`y` 模式适合做**精确的增量解析**（如逐段 tokenize 文本）。



#### s 修饰符与 dotAll

**`s` 修饰符（dotAll）**：让 `.` 也能匹配**换行符**。

```js
console.log(/a.b/.test("a\nb"));  // false（. 默认不匹配换行）
console.log(/a.b/s.test("a\nb")); // true（s 模式 . 匹配换行）
```

> 默认情况下 `.` 匹配除换行外的任意字符。开启 `s` 后，`.` 能匹配**包括换行在内的一切**，适合匹配跨多行的内容，替代旧的 `[\s\S]` 写法。



#### d 修饰符与匹配索引

**`d` 修饰符**：让匹配结果携带**起止索引**，便于定位匹配在原文中的位置。

```js
const match = /ab/d.exec("xxabxx");
console.log(match.index);       // 2（匹配的起始位置）
console.log(match.indices);     // [[2, 4]]（起止索引数组）
```

> `d` 修饰符（ES2022）为每个匹配（含捕获分组）附加 `indices` 属性，记录精确的起止位置。它在做**高亮定位、语法分析、文本替换**等需要"知道匹配在哪"的场景非常有用。



#### v 修饰符与集合表示法

**`v` 修饰符**：是 `u` 的增强版，支持**集合运算**与**字符串属性**，是较新的特性（ES2024）。

```js
// 集合差集：匹配字母但排除 a、e
const reg = /[\p{Letter}--[ae]]/v;
console.log(reg.test("b")); // true
console.log(reg.test("a")); // false（a 被排除）
```

> `v` 修饰符支持 `--`（差集）、`&&`（交集）等**集合运算**，让字符类表达更强大。它是较前沿的特性，兼容性还在完善中，学习了解即可。



#### 后行断言

**后行断言 `(?<=...)`**：断言某个位置**之前**的内容，是 ES2018 引入的（先行断言早已支持）。

```js
// 匹配"￥"后面的数字
console.log(/(?<=￥)\d+/.exec("￥99"));   // 99

// 后行否定：前面不是 ￥ 的数字
console.log(/(?<!￥)\d+/.exec("$88"));   // 88
```

> 后行断言与先行断言对称：先行 `x(?=y)` 看后面，后行 `(?<=y)x` 看前面。它们都**只断言不消费**，常用于"提取特定前缀/后缀的内容"。



#### 具名捕获分组

**具名捕获分组 `(?<name>...)`**：给捕获分组起名字，通过 `match.groups.name` 访问，比数字索引更可读。

```js
const reg = /(?<year>\d{4})-(?<month>\d{2})-(?<day>\d{2})/;
const match = reg.exec("2024-01-15");

console.log(match.groups.year);  // "2024"
console.log(match.groups.month); // "01"
console.log(match.groups.day);   // "15"
```

> 具名分组（ES2018）解决了数字分组"记不清第几个是什么"的痛点：`groups.year` 比 `match[1]` 直观得多。它还能在 `replace` 中通过 `$<name>` 引用，如 `str.replace(reg, "$<month>/$<year>")`。



#### matchAll 方法

**`str.matchAll(regexp)`**：返回一个**迭代器**，包含**所有**匹配及其捕获分组，弥补了 `match` 带 `g` 时丢失分组细节的缺陷。

```js
const str = "2024-01 2025-02";
const reg = /(\d{4})-(\d{2})/g;

for (const match of str.matchAll(reg)) {
  console.log(match[1], match[2]); // "2024" "01" 和 "2025" "02"
}
```

> `matchAll` 要求正则**必须带 `g`** 标志（否则报错），它返回迭代器，适合 `for-of` 遍历。相比 `match` 带 `g`（只返回完整串）、`exec` 循环（需手动维护 `lastIndex`），`matchAll` 是最优雅的"全量匹配 + 分组"方案。
