## 异步编程：Promise、async 与 EventLoop

### 回调地狱

多层回调函数相互嵌套就形成**回调地狱**，缺点是代码耦合性太强、难以维护、可读性变差。Promise 就是为了解决回调地狱而提出的异步编程方案。

### Promise

**Promise** 是异步编程的优雅解决方案，是一个**构造函数**，静态方法有 `all`、`race`、`resolve`、`reject` 等，原型上有 `then`、`catch`、`finally` 等方法。

#### Promise 的特点

- Promise 对象有**三种状态**：`pending`（进行中）、`fulfilled`（已成功）、`rejected`（已失败）。状态改变只有两种可能：从 `pending` 变为 `fulfilled`，或从 `pending` 变为 `rejected`。
- 状态一旦改变就不会再变，任何时候都能得到这个结果；改变发生后再添加回调，也会立即得到结果。
- 每个 `new Promise()` 得到的实例都能通过原型链访问 `.then()` 方法，用于指定成功和失败的回调。
- `new` 出来的 Promise 实例代表一个异步操作。

**Promise 创建后会立即执行**内部的代码（executor 是同步执行的）。因此一般把 Promise 包在函数里，需要时再调用：

```js
function test() {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      resolve('返回任意的数据');
    }, 2000);
  });
}
```

#### resolve 与 reject

- `resolve(value)` 是成功时的回调，把状态改为 `fulfilled`，其参数会传给 `then` 的成功回调。
- `reject(reason)` 是失败时的回调，把状态改为 `rejected`，其参数会传给失败回调。
- `then` 可以接收两个回调：第一个对应成功（resolve），第二个对应失败（reject）。

```js
test().then(
  (data) => console.log(data), // 成功
  (err) => console.log(err) // 失败
);
```

#### then 链式调用

`then` 的返回值可以是普通值，也可以是新的 Promise，从而支持链式调用：

```js
test()
  .then((data) => {
    console.log(data);
    return test(); // 返回 Promise 继续链式调用
  })
  .then((data) => {
    console.log(data);
  });
```

#### catch 与 then 第二个参数的区别

`.catch()` 除了处理失败结果，还能捕获**异常**（如语法错误），捕获后不会卡死，而是继续执行后面的代码。`then` 的第二个参数只能处理它**前面那个 Promise** 的失败，而 `catch` 能处理它之前**整条链**的失败。实际开发推荐统一用 `catch` 收尾。

#### Promise.all 与 race

- `Promise.all([p1, p2, ...])`：并行执行多个异步操作，全部成功才执行回调，返回一个数组，**数组中结果顺序与传入顺序一致**。
- `Promise.race([p1, p2, ...])`：谁先执行完成（无论成功还是失败）就先执行回调，其余不再进入任何回调。

> 易错点：传给 `all`/`race` 的必须是**调用后返回的 Promise 实例**，即 `this.test1()` 而不是 `this.test1`（后者传的是函数本身，会被当作普通值）。

### async/await

`async/await` 是 ES8（ECMAScript 2017）引入的语法，用来简化 Promise 异步操作，用同步的写法书写异步代码。

- 在 `function` 中使用了 `await`，则 `function` 必须用 `async` 修饰。
- `async` 函数的返回值永远是 Promise。
- `await` 后面可以跟 Promise 或普通值。
- `async` 函数里 `throw` 等价于 `reject`。
- 错误处理用 `try/catch`。
- `await` 只会等待，不会自动重试；一个 `await` 失败，后面的 `await` 都不会执行。

```js
async function get() {
  const r1 = await readFile('./a.txt');
  console.log(r1.toString());
}
```

> 性能陷阱：不要把可并行的操作写成串行。多个无依赖的 `await` 应用 `Promise.all` 并行执行，否则总耗时是累加而非取最大值。

### EventLoop 事件循环

JavaScript 是**单线程**语言，同一时间只能做一件事。为防止耗时任务导致程序假死，JS 把任务分为两类：

- **同步任务**：在主线程上排队执行的非耗时任务。
- **异步任务**：委托给宿主环境执行的耗时任务，执行完成后把回调放入任务队列等待执行。

异步任务又分为两类：

- **宏任务（macrotask）**：异步 Ajax 请求、`setTimeout`、`setInterval`、文件操作等。
- **微任务（microtask）**：`Promise.then`、`.catch`、`.finally`、`async/await` 中 `await` 之后的代码、`queueMicrotask()`、`MutationObserver`、`process.nextTick`（Node 环境，优先级更高）等。

事件循环的执行过程：

1. 任务依次进入执行栈，先执行全局上下文和主线程的同步任务。
2. 异步任务委托给宿主环境执行，完成的异步任务把回调放入任务队列。
3. 执行栈清空后，**先检查微任务队列**，一次性执行完所有微任务。
4. 再**取第一个宏任务**执行。
5. 重复上述过程，即 EventLoop。

> 宏任务与微任务都是运行在**同一个主线程**上的任务，与操作系统的进程/线程无关。二者的真实区别在于**调度时机**：一轮事件循环只取一个宏任务，执行完必须清空微任务队列才进入下一轮。可以类比为：宏任务是「一节课」，微任务是「这节课的随堂作业」。

```js
console.log(1);
setTimeout(() => {
  console.log(2);
  new Promise(function (resolve) {
    console.log(3);
    resolve();
  }).then(() => {
    console.log(4);
  });
});
new Promise((resolve) => {
  console.log(5);
  resolve();
}).then(() => {
  console.log(6);
});
setTimeout(() => {
  console.log(7);
  new Promise(function (resolve) {
    console.log(8);
    resolve();
  }).then(() => {
    console.log(9);
  });
});
// 打印结果：156234789
```
