## 客户端存储

### Web 存储的认识

**Web 存储**：是浏览器提供的、在**客户端保存数据**的一系列机制，让网页能在多次访问间记住信息。

客户端存储的主要方案：

- **`Cookie`**：随请求发送的小型文本，用于会话保持。
- **`localStorage`**：持久的键值存储。
- **`sessionStorage`**：会话级的键值存储。
- **`IndexedDB`**：强大的结构化数据库。

```js
// localStorage 示例
localStorage.setItem("username", "coderwhy");
console.log(localStorage.getItem("username")); // "coderwhy"
```

> 客户端存储解决了 HTTP **无状态**带来的"记不住"问题：登录状态、用户偏好、购物车等数据，都需要在客户端持久化。不同方案在**容量、有效期、作用域、是否随请求发送**上有显著差异，需按场景选型。



### Cookie

#### Cookie 的结构

**Cookie**：是服务器**设置、浏览器保存**的小型文本数据，会**随每次请求自动发送**给服务器。

一个 Cookie 由多个字段组成：

- **名称（Name）** 与 **值（Value）**：核心数据。
- **域（Domain）** 与 **路径（Path）**：作用范围。
- **有效期（Expires/Max-Age）**：过期时间。
- **标志**：`HttpOnly`、`Secure`、`SameSite` 等。

```js
// 通过 document.cookie 读写（字符串形式）
document.cookie = "username=coderwhy; path=/; max-age=3600";
console.log(document.cookie); // "username=coderwhy"
```

> Cookie 的特点是"**随请求自动携带**"，这让它天然适合**会话保持**（如登录态），但也带来了**性能开销**（每次请求都带上）和**容量限制**（约 4KB）。它由服务器通过 `Set-Cookie` 响应头设置。



#### Cookie 的属性

Cookie 的几个关键属性决定了它的行为与安全。

- **`Expires` / `Max-Age`**：过期时间；不设则为**会话 Cookie**（关闭浏览器即失效）。
- **`Domain` / `Path`**：限制 Cookie 的发送范围。
- **`HttpOnly`**：禁止 JavaScript 读取，防 XSS 窃取。
- **`Secure`**：仅 HTTPS 发送。
- **`SameSite`**：控制跨站请求是否携带（`Strict`/`Lax`/`None`）。

```js
document.cookie = "token=abc; Secure; HttpOnly; SameSite=Lax";
```

> 安全相关属性尤其重要：**`HttpOnly` 防 XSS**（脚本读不到）、**`Secure` 防明文传输**、**`SameSite` 防 CSRF**。`SameSite=Lax` 是现代浏览器推荐值，可有效缓解跨站请求伪造攻击。



#### Cookie 的封装与限制

直接操作 `document.cookie` 很繁琐，常需封装工具函数，且需了解其限制。

```js
// 封装：设置 Cookie
function setCookie(name, value, days) {
  const expires = new Date(Date.now() + days * 86400000).toUTCString();
  document.cookie = `${name}=${value}; expires=${expires}; path=/`;
}

// 封装：获取 Cookie
function getCookie(name) {
  const match = document.cookie.match(new RegExp(`(^| )${name}=([^;]+)`));
  return match ? decodeURIComponent(match[2]) : null;
}

setCookie("username", "coderwhy", 7);
console.log(getCookie("username")); // "coderwhy"
```

Cookie 的限制：

- **容量小**：每个约 4KB，总数有限。
- **每次请求都携带**：有性能开销。
- **操作繁琐**：`document.cookie` 是字符串，需手动解析。

> 由于这些限制，Cookie 应**只用于小而关键的数据**（如会话标识），不适合存大块数据。存储大数据应改用 `localStorage` 或 `IndexedDB`。



### localStorage 本地存储

**`localStorage`**：是**持久化**的键值存储，数据**永久保存**（除非手动清除），且**不随请求发送**。

- 存储为**字符串**键值对，需手动序列化对象。
- 容量约 **5MB**（各浏览器略有差异）。
- 作用域：**同源**共享。

```js
// 存字符串
localStorage.setItem("theme", "dark");

// 存对象（需序列化）
const user = { name: "why", age: 18 };
localStorage.setItem("user", JSON.stringify(user));

// 读
console.log(localStorage.getItem("theme")); // "dark"
const savedUser = JSON.parse(localStorage.getItem("user"));
console.log(savedUser.name); // "why"

// 删
localStorage.removeItem("theme");
localStorage.clear(); // 清空所有
```

> `localStorage` 适合存**长期、非敏感、容量适中**的数据（主题偏好、草稿、缓存）。注意两点：只能存**字符串**（对象要 `JSON.stringify`）；**不适合存敏感信息**（可被脚本读取，有 XSS 风险）。



### sessionStorage 会话存储

**`sessionStorage`**：与 `localStorage` 用法几乎相同，但数据**仅在当前标签页会话内有效**，关闭标签页即清除。

```js
// 用法与 localStorage 完全一致
sessionStorage.setItem("step", "2");
console.log(sessionStorage.getItem("step")); // "2"

// 刷新页面数据仍在，但关闭标签页后丢失
// 不同标签页之间相互独立，即使同源
```

> `sessionStorage` 与 `localStorage` 的唯一区别是**生命周期**：前者**标签页级**（关闭即失效、各标签页独立），后者**永久**（同源共享）。适合存"本次会话的临时状态"，如表单多步填写、临时 token。



### Web 存储的常用 API

`localStorage` 与 `sessionStorage` 共享同一套 API（都是 `Storage` 类型）。

- **`setItem(key, value)`**：写入。
- **`getItem(key)`**：读取。
- **`removeItem(key)`**：删除单个。
- **`clear()`**：清空所有。
- **`key(index)`**：按索引取键名。
- **`length`**：键值对数量。

```js
localStorage.setItem("a", "1");
localStorage.setItem("b", "2");

console.log(localStorage.length);   // 2
console.log(localStorage.key(0));   // 第一个键名
console.log(localStorage.getItem("a")); // "1"
```

> 还有一个**跨标签页通信**的实用特性：`storage` 事件。当**其他标签页**修改 `localStorage` 时，当前页面会触发 `storage` 事件，可用于多标签页同步状态。

```js
window.addEventListener("storage", (e) => {
  console.log(`${e.key} 被修改为 ${e.newValue}`);
});
```



### IndexedDB

#### 打开数据库与版本更新

**`IndexedDB`**：是浏览器内置的**非关系型数据库**，支持**大容量、结构化、异步**的数据存储，是 Web 端最强大的存储方案。

```js
const request = indexedDB.open("mydb", 1);

request.onupgradeneeded = (e) => {
  const db = e.target.result;
  // 创建对象仓库（类似表）
  db.createObjectStore("users", { keyPath: "id" });
};

request.onsuccess = (e) => {
  const db = e.target.result;
  console.log("数据库打开成功");
};
```

- `open(name, version)` 打开数据库，**版本号升级时**触发 `onupgradeneeded`。
- 在 `onupgradeneeded` 里创建对象仓库、索引。

> IndexedDB 相比 `localStorage` 的优势：**容量大**（数百 MB 起）、**支持复杂查询**（索引、事务）、**异步不阻塞**。适合存大量结构化数据（离线数据、缓存）。它基于**事件**而非 Promise（原生版），代码较繁琐。



#### 对象仓库与事务

IndexedDB 的**对象仓库（Object Store）** 类似数据库的表，所有读写都在**事务（Transaction）** 中进行。

```js
const db = /* 已打开的数据库 */;

// 开启事务
const transaction = db.transaction("users", "readwrite");
const store = transaction.objectStore("users");

// 添加数据
store.add({ id: 1, name: "coderwhy" });
store.put({ id: 2, name: "张三" });

// 通过主键获取
const getReq = store.get(1);
getReq.onsuccess = () => console.log(getReq.result);
```

> 事务保证了操作的**原子性与一致性**：要么全部成功，要么全部回滚。所有对对象仓库的操作（`add`、`put`、`get`、`delete`）都必须在事务内进行，这是 IndexedDB 与 `localStorage` 最本质的架构差异。



#### 索引与游标

**索引（Index）** 用于按非主键字段查询，**游标（Cursor）** 用于遍历多条记录。

```js
// 创建索引（在 onupgradeneeded 里）
store.createIndex("name_index", "name", { unique: false });

// 用索引查询
const index = store.index("name_index");
const req = index.get("coderwhy");
req.onsuccess = () => console.log(req.result);

// 用游标遍历所有记录
const cursorReq = store.openCursor();
cursorReq.onsuccess = (e) => {
  const cursor = e.target.result;
  if (cursor) {
    console.log(cursor.value);
    cursor.continue(); // 继续下一条
  }
};
```

> 索引让"按 name 查用户"成为可能（否则只能按主键 id 查）；游标则提供了**逐条遍历**的能力，是查询大量数据的标准方式。游标配合 `cursor.continue()` 迭代，配合范围（`IDBKeyRange`）可实现范围查询。



### Cookie、localStorage 与 sessionStorage 的区别

三者是 Web 存储的三大基础方案，理解其差异是选型的前提。

- **容量**：Cookie 约 4KB；`localStorage`/`sessionStorage` 约 5MB。
- **有效期**：Cookie 可设过期（或会话级）；`localStorage` 永久；`sessionStorage` 标签页会话级。
- **是否随请求发送**：Cookie **会**（每次自动携带）；后两者**不会**。
- **作用域**：三者均遵循同源，但 `sessionStorage` 还限**单个标签页**。
- **操作方式**：Cookie 是字符串、需手动解析；后两者是键值 API。
- **典型用途**：Cookie 存会话标识；`localStorage` 存长期偏好；`sessionStorage` 存临时状态。

```js
// 直观对比
document.cookie = "token=abc";      // 随请求发送，4KB
localStorage.setItem("theme", "dark");   // 永久，5MB
sessionStorage.setItem("step", "1");     // 会话级，5MB
```

> 选型口诀：**要随请求自动带上、存会话 → Cookie；要长期保存、稍大数据 → localStorage；只要本次会话、标签页隔离 → sessionStorage；要海量结构化数据 → IndexedDB**。敏感数据一律不建议存客户端（或需加密）。
