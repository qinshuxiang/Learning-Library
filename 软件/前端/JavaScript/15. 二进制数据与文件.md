## 二进制数据与文件

### ArrayBuffer

#### ArrayBuffer 与视图

**`ArrayBuffer`**：是一块**固定长度**的、连续的**二进制内存区域**，是 JavaScript 处理二进制数据的**底层载体**。

- `ArrayBuffer` 本身**不能直接读写**，只能分配内存。
- 必须通过**视图（View）** 来读写它：`TypedArray`（类型化数组）或 `DataView`。

```js
// 分配 16 字节的内存
const buffer = new ArrayBuffer(16);
console.log(buffer.byteLength); // 16

// 通过视图读写
const view = new Uint8Array(buffer);
view[0] = 255;
console.log(view[0]); // 255
```

> 类比理解：`ArrayBuffer` 是"**一块空地**"，视图是"**测量这块地的工具**"。同一块 `ArrayBuffer` 可以用不同的视图（8 位、16 位、32 位等）以不同方式解读，这是处理二进制（文件、网络数据、WebGL 等）的基础。



#### ArrayBuffer 的创建与切片

`ArrayBuffer` 支持创建与切片操作。

- **`new ArrayBuffer(length)`**：分配指定字节的内存。
- **`buffer.slice(start, end)`**：切片出一个**新** ArrayBuffer。
- **`buffer.byteLength`**：字节长度。

```js
const buffer = new ArrayBuffer(8);
console.log(buffer.byteLength); // 8

const sliced = buffer.slice(0, 4);
console.log(sliced.byteLength); // 4（新缓冲区，与原缓冲区独立）
```

> `slice` 返回的是**新的、独立的** ArrayBuffer，修改切片不影响原缓冲区。`ArrayBuffer` 的大小在创建时**固定**，之后无法改变（这与普通数组可动态扩容不同）。



### TypedArray

#### TypedArray 的种类

**TypedArray（类型化数组）**：是一组**视图**类型，用**固定类型**读写 `ArrayBuffer`，每个元素占固定字节数。

常见的 TypedArray 类型：

- **`Uint8Array`**：无符号 8 位整数（1 字节）。
- **`Int8Array`**：有符号 8 位整数。
- **`Uint16Array`** / **`Int16Array`**：16 位整数（2 字节）。
- **`Uint32Array`** / **`Int32Array`**：32 位整数（4 字节）。
- **`Float32Array`** / **`Float64Array`**：浮点数。

```js
const u8 = new Uint8Array([1, 2, 3]);
console.log(u8.length);   // 3
console.log(u8[0]);       // 1

const f32 = new Float32Array([1.5, 2.5]);
console.log(f32[0]);      // 1.5
```

> TypedArray 相比普通数组：**元素类型固定、内存连续、性能更高**，适合大量数值运算（图形、音频、科学计算）。命名规律是"类型 + 位数 + Array"，如 `Uint8Array` 是"无符号 8 位整数数组"。



#### TypedArray 的使用与字节序

TypedArray 支持数组式操作，但需理解**字节序（Endianness）**。

- 支持下标访问、`length`、迭代、部分数组方法（`map`、`forEach` 等）。
- **字节序**：多字节数值在内存中的存储顺序，分**大端（Big-Endian）** 与**小端（Little-Endian）**。

```js
const u8 = new Uint8Array([1, 2, 3, 4]);
console.log(u8.map((x) => x * 2)); // [2, 4, 6, 8]（有 map）

// 字节序：16 位整数 0x0102 在内存中的两种存储
const buf = new ArrayBuffer(2);
const view = new Uint16Array(buf);
view[0] = 0x0102;
// 小端（x86 常见）：低字节在前 → [0x02, 0x01]
// 大端：高字节在前 → [0x01, 0x02]
```

> 字节序是多字节数据的存储顺序问题：**小端**把低位字节放前面（x86 平台默认），**大端**把高位字节放前面。TypedArray 使用**平台默认字节序**，若需指定字节序，要用 `DataView`（见下一节）。



### DataView

#### DataView 的使用

**`DataView`**：是更灵活的视图，可以**指定字节序**地读写任意类型的数据，而不受平台字节序影响。

- **`new DataView(buffer)`**：在 `ArrayBuffer` 上创建。
- 通过 `setInt8`、`getUint16`、`setFloat32` 等方法读写，可指定 `littleEndian`。

```js
const buffer = new ArrayBuffer(8);
const view = new DataView(buffer);

view.setUint16(0, 0x0102, false); // 大端写入
console.log(view.getUint16(0, false)); // 0x0102（258）

view.setUint16(0, 0x0102, true);  // 小端写入
console.log(view.getUint16(0, true));  // 0x0102（258）
```

> `DataView` 与 TypedArray 的区别：TypedArray 使用**平台默认字节序**、适合**同类型连续数据**；`DataView` 可**显式指定字节序**、适合**混合类型的结构化二进制数据**（如解析文件头、网络协议）。



### Blob 与 File

#### Blob 对象

**`Blob`（Binary Large Object）**：表示**不可变的二进制数据块**，常用于处理文件、图片、下载等。

- **`new Blob(parts, options)`**：创建 Blob，`parts` 是数据源数组。
- **`blob.size`**：字节大小。
- **`blob.type`**：MIME 类型。

```js
const blob = new Blob(["Hello, world"], { type: "text/plain" });
console.log(blob.size); // 12
console.log(blob.type); // "text/plain"
```

> `Blob` 是处理**原始二进制**的通用对象，`File` 继承自 `Blob`。它常用于：生成下载文件、`URL.createObjectURL` 预览图片、`FormData` 上传等场景。



#### File 与 FileList

**`File`**：是 `Blob` 的子类，代表**用户选择的文件**，额外携带文件名等信息。**`FileList`**：是文件集合（如 `input` 的 `files`）。

```html
<input type="file" id="fileInput" multiple>
```

```js
const input = document.querySelector("#fileInput");

input.addEventListener("change", () => {
  const files = input.files;        // FileList
  console.log(files.length);        // 文件个数

  const file = files[0];            // File
  console.log(file.name);           // 文件名
  console.log(file.size);           // 文件大小
  console.log(file.type);           // MIME 类型
});
```

> `File` 相比 `Blob` 多了 **`name`（文件名）、`lastModified`（修改时间）** 等属性。`input.files` 返回的 `FileList` 是类数组，可用 `Array.from` 或索引访问，常用于文件上传、图片预览。



#### FileReader

**`FileReader`**：用于**异步读取** `Blob`/`File` 的内容，支持多种格式。

- **`readAsText(blob)`**：读取为文本。
- **`readAsDataURL(blob)`**：读取为 base64 DataURL（常用于图片预览）。
- **`readAsArrayBuffer(blob)`**：读取为 ArrayBuffer。

```js
const file = input.files[0];
const reader = new FileReader();

reader.onload = function (e) {
  console.log(e.target.result); // 读取结果
};

reader.readAsDataURL(file); // 读取为 DataURL，用于预览
```

> `FileReader` 是**异步**的（`onload` 回调接收结果）。`readAsDataURL` 把文件转成 base64 字符串，可直接赋给 `<img src>` 做**本地图片预览**，是最常用的图片预览方案。



#### Blob URL 与文件下载

**`URL.createObjectURL(blob)`**：为 `Blob`/`File` 创建一个**临时的 URL**，可用于预览或下载。

```js
// 图片预览
const blob = file; // File 也是 Blob
const url = URL.createObjectURL(blob);
img.src = url;

// 触发下载
function download(content, filename) {
  const blob = new Blob([content]);
  const url = URL.createObjectURL(blob);
  const a = document.createElement("a");
  a.href = url;
  a.download = filename;
  a.click();
  URL.revokeObjectURL(url); // 释放
}

download("文件内容", "example.txt");
```

> 两个要点：一是 `URL.createObjectURL` 创建的 URL 用完后应调用 **`URL.revokeObjectURL`** 释放内存；二是它生成的 URL 是 `blob:` 开头的临时地址，比 base64 DataURL **更省内存**，适合大文件。



#### Base64 编码与解码

**Base64**：是一种用 64 个字符表示二进制数据的**编码方式**，用于在文本中传输二进制。

- **`btoa(str)`**：字符串 → Base64 编码。
- **`atob(str)`**：Base64 → 字符串解码。

```js
const encoded = btoa("hello");
console.log(encoded); // "aGVsbG8="

const decoded = atob(encoded);
console.log(decoded); // "hello"
```

> `btoa`/`atob` 只能处理 **ASCII 字符**，处理中文需先转码：`btoa(unescape(encodeURIComponent("中文")))`。Base64 比二进制**体积大 1/3**，但能在纯文本环境（URL、JSON、HTML）中安全传输二进制，是 DataURL、图片内联的基础。
