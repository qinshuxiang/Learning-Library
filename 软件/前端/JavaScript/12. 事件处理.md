## 事件处理

### 事件的认识

#### 事件与事件处理程序

**事件（Event）**：是**用户在页面上发生的动作**（点击、输入、滚动等）或**系统触发的信号**。**事件处理程序（Event Handler）**：是响应这些事件而执行的函数，也叫监听器（listener）。

```js
const button = document.querySelector("button");

// 事件：点击；事件处理程序：箭头函数
button.addEventListener("click", function () {
  console.log("按钮被点击了");
});
```

- 常见事件类型：`click`（点击）、`input`（输入）、`keydown`（按键）、`scroll`（滚动）等。
- 事件处理程序在**事件发生时**由浏览器调用。

> 事件机制是 JavaScript **异步模型**的体现：代码先"注册"处理器，之后事件发生时浏览器才"回调"它。理解"注册与回调分离"，是理解事件、定时器、Promise 等一切异步概念的共同起点。



#### EventTarget 接口

**`EventTarget`**：是所有能接收事件的对象的**基类接口**，DOM 元素、`document`、`window` 都实现了它。它提供了事件的核心方法。

- **`addEventListener(type, listener)`**：注册事件监听。
- **`removeEventListener(type, listener)`**：移除事件监听。
- **`dispatchEvent(event)`**：手动派发事件。

```js
const button = document.querySelector("button");

function handleClick() {
  console.log("点击");
}
button.addEventListener("click", handleClick);
button.removeEventListener("click", handleClick);
```

> 正因为 `window`、`document`、元素都继承自 `EventTarget`，它们都能调用 `addEventListener`。这也解释了第 10 章 DOM 继承链里 `EventTarget` 为何是最顶层——它赋予所有节点"接收事件"的能力。



#### addEventListener 的使用

**`addEventListener(type, listener, options?)`**：注册事件监听的**标准方法**，支持多个监听器、精细控制。

- **`type`**：事件类型字符串（如 `"click"`）。
- **`listener`**：事件处理函数。
- **`options`**：可选配置，如 `{ once: true, capture: true }`。

```js
const button = document.querySelector("button");

// 同一元素可注册多个监听器
button.addEventListener("click", () => console.log("监听器一"));
button.addEventListener("click", () => console.log("监听器二"));

// 第三个参数传对象
button.addEventListener("click", handler, { once: true });
```

> `addEventListener` 相比旧的 `onclick` 属性有三大优势：**可注册多个监听器**、**可移除**、**可控制捕获/冒泡阶段**。因此它是现代事件处理的唯一推荐方式，`onclick` 仅剩"写法简短"的优势。



#### 事件监听的移除与 once 选项

移除监听器需注意**引用一致性**，或用 `once` 选项实现"只触发一次"。

- **移除**：`removeEventListener` 必须传入**同一个函数引用**，匿名函数无法移除。
- **`once: true`**：监听器触发一次后自动移除。

```js
function handleClick() {
  console.log("点击一次");
}

// 错误：匿名函数无法移除
button.addEventListener("click", () => {});
button.removeEventListener("click", () => {}); // 无效

// 正确：用命名函数
button.addEventListener("click", handleClick);
button.removeEventListener("click", handleClick);

// 或用 once：只触发一次
button.addEventListener("click", handleClick, { once: true });
```

> 移除监听器的关键是**函数引用要一致**：匿名函数每次都是新引用，无法移除；必须用**具名函数**或先保存引用。`once: true` 则天然解决了"只执行一次"的需求，免去手动移除。



#### DOMContentLoaded 与 load 事件

页面加载有两个关键事件，时机不同。

- **`DOMContentLoaded`**：HTML 解析完毕、**DOM 树构建完成**时触发（不等待图片、样式等资源）。
- **`load`**：页面**所有资源**（图片、样式、脚本等）加载完成时触发。

```js
document.addEventListener("DOMContentLoaded", () => {
  console.log("DOM 已就绪，可以操作元素了");
});

window.addEventListener("load", () => {
  console.log("所有资源加载完成");
});
```

> `DOMContentLoaded` 早于 `load`。脚本放在 `<head>` 时，需等 `DOMContentLoaded` 才能操作元素；脚本放在 `</body>` 前则无需等待（DOM 已就绪）。这也是"脚本放底部"与 `defer` 属性的意义所在。



### 事件模型

#### 事件传播的三个阶段

事件在 DOM 树中的传播经过**三个阶段**。

1. **捕获阶段（Capture）**：从 `window` 向下到目标元素的**祖先链**。
2. **目标阶段（Target）**：到达触发事件的**目标元素**本身。
3. **冒泡阶段（Bubble）**：从目标元素**向上**回到 `window`。

```js
// 第三个参数 capture: true 表示在捕获阶段触发
parent.addEventListener("click", () => console.log("捕获"), true);
child.addEventListener("click", () => console.log("目标"));
parent.addEventListener("click", () => console.log("冒泡"));
```

> 默认 `addEventListener` 的监听器在**冒泡阶段**触发，第三个参数传 `true` 才在**捕获阶段**触发。理解"先捕获、后目标、再冒泡"的顺序，是搞懂事件委托、阻止冒泡的前提。



#### 事件冒泡与捕获

**冒泡（Bubble）** 与 **捕获（Capture）** 是事件传播的两个方向。

- **冒泡**：事件从**目标元素**逐级向上传播到祖先（默认行为）。
- **捕获**：事件从**根**逐级向下传播到目标元素（需显式开启）。

```html
<div id="parent">
  <button id="child">按钮</button>
</div>
```

```js
const parent = document.querySelector("#parent");
const child = document.querySelector("#child");

// 点击 child，事件会冒泡到 parent
child.addEventListener("click", () => console.log("子元素"));
parent.addEventListener("click", () => console.log("父元素"));
// 输出：子元素 → 父元素（冒泡）
```

> 冒泡是**默认**、也是日常最常用的机制（配合事件委托）。捕获阶段通常用得少，但理解它有助于理解完整的事件流，以及 `stopPropagation` 应作用在哪一阶段。



#### 事件委托

**事件委托（Event Delegation）**：是把子元素的事件监听**委托给祖先元素**，利用**事件冒泡**，通过一个监听器处理多个子元素的事件。

```html
<ul id="list">
  <li>项目 1</li>
  <li>项目 2</li>
  <li>项目 3</li>
</ul>
```

```js
const list = document.querySelector("#list");

// 只监听父元素，通过 e.target 判断点击了哪个子元素
list.addEventListener("click", (e) => {
  if (e.target.tagName === "LI") {
    console.log("点击了：", e.target.textContent);
  }
});
```

> 事件委托的两大优势：一是**性能**——一个监听器替代 N 个，减少内存；二是**动态元素**——后添加的子元素**无需重新绑定**也能响应。它是列表渲染、动态内容场景的核心技巧。



#### 阻止冒泡与阻止默认行为

事件对象提供了两个"阻止"方法，作用不同。

- **`event.stopPropagation()`**：阻止事件**继续传播**（不再冒泡/捕获）。
- **`event.preventDefault()`**：阻止事件的**默认行为**（如链接跳转、表单提交）。

```js
// 阻止冒泡：点击子元素不触发父元素
child.addEventListener("click", (e) => {
  e.stopPropagation();
});

// 阻止默认行为：阻止链接跳转
link.addEventListener("click", (e) => {
  e.preventDefault();
});
```

> 二者常被混淆：`stopPropagation` 管"**传不传**"（是否冒泡），`preventDefault` 管"**做不做**"（是否执行默认动作）。阻止链接跳转用 `preventDefault`，阻止事件影响父元素用 `stopPropagation`。



### Event 对象

#### Event 的实例属性

事件处理函数会收到一个 **`Event` 对象**，携带事件的各种信息。

- **`type`**：事件类型（如 `"click"`）。
- **`target`**：**触发**事件的元素（最具体）。
- **`currentTarget`**：**当前**处理事件的元素（委托时是父元素）。
- **`eventPhase`**：事件所处的阶段。

```js
list.addEventListener("click", (e) => {
  console.log(e.type);          // "click"
  console.log(e.target);        // 实际点击的子元素
  console.log(e.currentTarget); // 绑定监听器的 list 元素
});
```

> `target` 与 `currentTarget` 的区别是高频考点：事件委托中，`target` 是**实际点击**的子元素，`currentTarget` 是**绑定监听器**的父元素。普通场景（不委托）二者相同。



#### Event 的实例方法

`Event` 对象提供的方法用于**控制事件行为**。

- **`preventDefault()`**：阻止默认行为。
- **`stopPropagation()`**：阻止冒泡/捕获。
- **`stopImmediatePropagation()`**：阻止传播，且**阻止同一元素上的其他监听器**执行。

```js
button.addEventListener("click", (e) => {
  e.stopImmediatePropagation(); // 后续监听器都不执行
});
button.addEventListener("click", () => console.log("不会执行"));
```

> `stopImmediatePropagation` 比 `stopPropagation` 更"狠"：它除了阻止传播，还**阻止当前元素上后续注册的监听器**执行。当多个监听器并存、想"一票否决"时用它。



#### 鼠标事件 MouseEvent

**鼠标事件**继承自 `MouseEvent`，携带鼠标位置、按键等信息。

- 常用类型：`click`、`dblclick`、`mousedown`、`mouseup`、`mousemove`、`mouseenter`、`mouseleave`。
- 关键属性：`clientX/clientY`（相对视口）、`pageX/pageY`（相对文档）、`button`（哪个键）。

```js
document.addEventListener("mousemove", (e) => {
  console.log(e.clientX, e.clientY); // 鼠标在视口中的坐标
});

button.addEventListener("click", (e) => {
  console.log(e.button); // 0 左键、1 中键、2 右键
});
```

> `mouseenter`/`mouseleave` 与 `mouseover`/`mouseout` 的区别：前两者**不冒泡**、进入子元素也不触发，后两者**冒泡**、会在子元素间反复触发。做"悬停高亮"通常用 `mouseenter`/`mouseleave` 更省心。



#### 键盘事件 KeyboardEvent

**键盘事件**继承自 `KeyboardEvent`，携带按键信息。

- 常用类型：`keydown`（按下）、`keyup`（松开）、`keypress`（已废弃）。
- 关键属性：`key`（按键值）、`code`（物理键位）、`ctrlKey`/`shiftKey` 等（修饰键）。

```js
document.addEventListener("keydown", (e) => {
  console.log(e.key);   // 如 "a"、"Enter"、"ArrowUp"
  console.log(e.code);  // 物理键位，如 "KeyA"

  // 组合键：Ctrl + S
  if (e.ctrlKey && e.key === "s") {
    e.preventDefault();
    console.log("保存");
  }
});
```

> `key` 与 `code` 的区别：`key` 是**实际字符**（受键盘布局影响，如中文输入法下不同），`code` 是**物理键位**（固定，如 `KeyA`）。做快捷键判断建议用 `code`（不受布局影响），做输入判断用 `key`。



#### 表单与焦点事件

表单元素有一组专用事件。

- **`input`**：输入框内容**变化时**触发（实时）。
- **`change`**：值**改变且失焦**时触发。
- **`submit`**：表单提交时触发。
- **`focus`** / **`blur`**：获得/失去焦点。

```js
const input = document.querySelector("input");
input.addEventListener("input", (e) => {
  console.log("输入中：", e.target.value);
});

const form = document.querySelector("form");
form.addEventListener("submit", (e) => {
  e.preventDefault(); // 阻止默认提交
  console.log("提交表单");
});
```

> `input` 与 `change` 的区别是高频考点：`input` **实时**触发（每输入一个字符都触发），`change` 在**失焦且值改变**时才触发。做"实时搜索"用 `input`，做"表单校验"用 `change` 或 `submit`。



#### 拖拉事件

**拖拽（Drag and Drop）** 通过一组事件实现，分**拖拽源**与**放置目标**两类。

- 拖拽源事件：`dragstart`、`drag`、`dragend`。
- 放置目标事件：`dragover`、`drop`。

```js
const draggable = document.querySelector(".drag");
const dropZone = document.querySelector(".drop");

draggable.addEventListener("dragstart", (e) => {
  e.dataTransfer.setData("text/plain", e.target.id);
});

dropZone.addEventListener("dragover", (e) => {
  e.preventDefault(); // 必须阻止默认，才能触发 drop
});

dropZone.addEventListener("drop", (e) => {
  e.preventDefault();
  const id = e.dataTransfer.getData("text/plain");
  console.log("放下了：", id);
});
```

> 拖拽的关键点：**`dragover` 必须 `preventDefault` 才能触发 `drop`**；数据通过 `dataTransfer` 在源与目标间传递。拖拽常用于文件上传、排序、看板等交互场景。



#### 进度事件

**进度事件**用于监听资源加载或上传下载的**进度**，常与 `XMLHttpRequest`、图片加载等配合。

- **`progress`**：传输进行中触发（携带 `loaded`/`total`）。
- **`load`**：加载完成。
- **`error`**：加载失败。

```js
const img = new Image();
img.addEventListener("load", () => console.log("图片加载完成"));
img.addEventListener("error", () => console.log("图片加载失败"));
img.src = "example.jpg";
```

> 进度事件是"**资源加载状态**"的通用模型：`load`/`error` 判断成败，`progress` 获取进度。它在文件上传（配合 XHR 或 fetch）、图片懒加载等场景有广泛应用，后续网络请求章节会再次用到。



### 自定义事件

#### CustomEvent 与 dispatchEvent

**自定义事件**：允许开发者**创建并派发**自己的事件，实现组件间的解耦通信。

- **`new CustomEvent(type, { detail })`**：创建自定义事件，`detail` 携带数据。
- **`element.dispatchEvent(event)`**：派发事件。

```js
const button = document.querySelector("button");

// 监听自定义事件
button.addEventListener("user-login", (e) => {
  console.log("登录用户：", e.detail.name);
});

// 创建并派发
const event = new CustomEvent("user-login", {
  detail: { name: "coderwhy" }
});
button.dispatchEvent(event);
```

> 自定义事件让**任意两个对象**通过事件解耦通信：发布方 `dispatchEvent`，订阅方 `addEventListener`，彼此无需直接引用。它是"发布-订阅模式"在浏览器中的原生实现。



#### 事件总线与发布订阅

**事件总线（Event Bus）**：是利用自定义事件或专用对象实现的**发布-订阅机制**，让不直接关联的组件互相通信。

```js
class EventBus {
  constructor() {
    this.listeners = {};
  }
  on(type, handler) {
    (this.listeners[type] ||= []).push(handler);
  }
  emit(type, payload) {
    (this.listeners[type] || []).forEach((handler) => handler(payload));
  }
  off(type, handler) {
    this.listeners[type] = (this.listeners[type] || []).filter((h) => h !== handler);
  }
}

const bus = new EventBus();
bus.on("login", (data) => console.log("登录", data));
bus.emit("login", { name: "why" });
```

> 事件总线是**发布-订阅模式**的典型实现：`on` 订阅、`emit` 发布、`off` 取消。它解耦了组件间的直接依赖，广泛用于跨组件通信（如 Vue2 的 `$bus`）。现代项目中，这类需求也可用全局状态管理（如 Pinia、Redux）替代。
