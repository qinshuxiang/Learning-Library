## Git 操作

### 日常提交流程

项目里改完代码，按顺序执行：

```text
1. git add <文件>     → 暂存本次改动相关文件，不裸 add 全目录
2. ocr review         → AI 评审工作区 diff（含已暂存、未暂存、未跟踪）
3. git commit         → type: 中文摘要（feat/fix/docs/refactor/chore）
```

- 评审发现 critical／high 问题必须先修再提；medium 以下自行判断。
- 功能分支合入前，对整个分支跑一次全量对比评审：`ocr review --from main --to feature`。
- 评审会话可续查：`ocr session list` 查看，`--resume <session-id>` 续跑被中断的评审。

### 自动提交与仓库检查

- 任务完成即视为到达提交点：AI 主动走完上面的提交流程，不等用户逐次指示。
- 动手前先确认当前目录是 Git 仓库（`git rev-parse --is-inside-work-tree`）；不是仓库时停下来提醒用户创建，不擅自 `git init`。
