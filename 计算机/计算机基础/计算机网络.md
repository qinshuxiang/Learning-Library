# 计算机网络学习笔记

> **发送数据的一生**：应用进程产生报文 → 传输层加端口封装成报文段/数据报（端到端可靠/流量/拥塞控制）→ 网络层加 IP 地址封装成数据报（路由、最长前缀匹配转发）→ 数据链路层加 MAC 地址封装成帧（成帧、差错控制、介质访问控制）→ 物理层编码调制为比特流/信号逐段传播；接收方逐层解封装，逆过程上交。
>
> **地址体系**：MAC 地址（链路内，永久）→ IP 地址（网络间，可变、逻辑定位）→ 端口号（进程定位）；**ARP** 打通 IP↔MAC，**DNS** 打通域名↔IP，**DHCP** 动态分配 IP，**NAT** 打通私网↔公网。
>
> **一句话记忆各层**：物理层——"传比特"；数据链路层——"传帧，管相邻节点"；网络层——"选路，管主机到主机"；传输层——"管进程到进程，保证可靠"；应用层——"为用户服务"。

## 一、计算机网络概述

### 1.1 什么是计算机网络

计算机网络技术是**通信技术与计算机技术相结合**的产物。

计算机网络是将不同地理位置的、具有独立功能的多个计算机系统，通过各种**通信设备和线路**连接起来，在**网络协议和软件的支持**下进行数据通信，实现**信息交换和资源共享**的系统。

> **日常场景**：我们每天都会使用计算机网络，使用不同类型的设备去连接计算机网络，比如手机、笔记本电脑或者台式机，现在还有智能手表、智能电视，这些都可以连接计算机网络。不同的设备，连接计算机网络的方式也各不相同：笔记本电脑可以通过 Wi-Fi 连接路由器从而接入计算机网络；台式机可以通过网线连接路由器从而接入网络；在户外使用手机，则是通过 5G 通信技术连接 5G 基站从而接入计算机网络。在这些设备中我们会安装一些方便易用的软件，比如说百度网盘或微信，可以用百度网盘去共享资源等——这些功能都离不开计算机网络的支撑。

从组成结构看，计算机网络由若干**结点**和连接这些结点的**链路**组成：

- **结点**：可以是计算机、集线器、交换机、路由器等。
- **链路**：可以是有线链路（网线、光纤）、无线链路（Wi-Fi、蜂窝网络）。

**互连网（internet）**：由路由器把两个或多个计算机网络连接起来的网络称为互连网。路由器也可以和路由器互连，互连网内部可以使用任意的协议通信。

**互联网（Internet）**：覆盖全世界范围的互连网，由 ISP（互联网服务提供商：移动、电信、联通等）和国际机构提供。**互联网必须使用 TCP/IP 协议通信**。

> 小结：互连网是"网络的网络"（通用概念），互联网是特指全球最大的那个互连网。日常口语中常把两者混用，但考试与文档中需要区分。

### 1.2 计算机网络的组成

计算机网络的组成可以根据不同的标准进行分类，主要包括：

#### 1.2.1 按组成部分

- **硬件**：包括主机、通信设备、通信链路。
  - **主机（端系统）**：接入网络的计算机等设备，包括电脑、手机、物联网设备。
  - **通信设备**：端系统接入计算机网络之后，需要通过通信设备以及通信链路才可以进行数据的传输，典型的通信设备就是路由器。
  - **通信链路**：连接网络的线路，如网线、光纤、同轴电缆。
- **软件**：实现网络功能的各种程序（操作系统网络组件、应用软件等）。
- **协议**：规定计算机网络中的通信规则，由硬件、软件共同实现。例如"网络适配器 + 软件"来实现网络通信协议。

#### 1.2.2 按工作方式

- **边缘部分**：直接为用户服务（数据通信、资源共享），由连接到互联网上的主机及其软件组成。
- **核心部分**：为边缘部分提供服务（**连通性、交换服务**），由大量网络与连接这些网络的路由器组成。

#### 1.2.3 按逻辑功能

- **资源子网**：向用户提供硬件、软件和信息资源的共享，主要由连接到互联网上的主机组成。
- **通信子网**：负责数据传输和交换。所有的通信设备和通信介质都属于通信子网，网络适配器这类硬件以及一些底层的网络协议，也是为了实现计算机之间的信息传输。

### 1.3 计算机网络的分类

#### 1.3.1 按覆盖范围

**局域网（LAN）**：覆盖小范围，如办公室、校园、单位、部门。

**广域网（WAN）**：覆盖大范围，如城市、国家或全球。

**城域网（MAN）**：介于局域网和广域网之间，覆盖城市区域。

| **特性** | **局域网（LAN）** | **广域网（WAN）** |
| --- | --- | --- |
| **覆盖范围** | 小范围，如家庭、办公室、校园 | 大范围，如城市、国家甚至全球 |
| **传输速度** | 高速（一般为 100 Mbps ~ 10 Gbps 及以上） | 较慢（一般为几十 Mbps 到 Gbps） |
| **延迟** | 低延迟，适合高实时性需求 | 高延迟，尤其在跨国通信中更明显 |
| **传输介质** | 双绞线、电缆、光纤、Wi-Fi 等 | 光纤、电缆、卫星通信、蜂窝网络等 |
| **网络结构** | 常为星形、总线、环形拓扑 | 采用路由器和交换机构建的复杂网络，通常使用网状拓扑 |
| **应用场景** | 办公楼、学校、家庭网络、数据中心等 | 互联网、跨国公司网络、云服务等 |
| **典型协议** | 以太网（Ethernet）、Wi-Fi | MPLS、PPP、BGP、IP |
| **安全性** | 较高，通常只限内部访问 | 安全性较低，需要 VPN 或防火墙保护 |
| **数据交换技术** | 共享广播 | 存储转发 |

#### 1.3.2 按拓扑结构

**总线拓扑（Bus Topology）**：所有设备共享一条主干线路，通过分支连接到主干上。布线简单、成本低，但**总线故障会导致整个网络失效**；设备增多时容易出现通信冲突，影响性能；负载能力有限、**实时性差**、存在**总线争用问题**，采用**广播式传输**。

**环形拓扑（Ring Topology）**：每个设备与相邻的两个设备连接，形成一个闭合的环路。数据以单一方向传输，减少冲突；但任意一个节点故障会导致整个网络中断，网络扩展不灵活。使用**令牌**解决总线争用问题——只有持有令牌者可以发送消息，采用**广播式传输**。

**星形拓扑（Star Topology）**：所有设备通过独立的线路连接到一个中央节点（如交换机或路由器）。单个设备故障不会影响整个网络；但**依赖中央节点**，若其故障则网络瘫痪；布线成本高，需要大量电缆；采用**点对点传输**。这是目前家庭和企业局域网最常用的拓扑。

**网状拓扑（Mesh Topology）**：每个设备与网络中的多个设备直接相连。即使某条连接失效，也不会影响通信；但布线复杂且成本高；采用**点对点传输**，**常见于广域网**。

> **树形拓扑（Tree Topology）**：由多个星形拓扑通过总线连接组成，形成类似树的层次结构。易于扩展，适合层级结构的网络（如学校、企业网络）；高层节点的故障可能影响下层所有节点；网络复杂性增加时维护难度加大。

#### 1.3.3 按传输媒介

1. **有线网络**：通过物理介质进行数据传输，常见的介质有：
   - **双绞线**：成本低，使用最广（网线）。
   - **同轴电缆**：抗干扰能力较好（有线电视网络）。
   - **光纤**：使用光信号传输，适用于高速、大规模数据传输。优点：**传输速度快、距离远、不受电磁干扰、难以窃听**。
2. **无线网络（Wireless Network）**：通过无线电波、红外线等媒介进行数据传输（Wi-Fi、蓝牙、蜂窝网络）。

#### 1.3.4 按功能

| 网络类型 | 定义 | 优缺点 |
| --- | --- | --- |
| 互联网 | 全球最大的公共网络，由多个异构网络互联而成 | 优点：全球互联、资源丰富、开放性高；缺点：安全性低，容易受到攻击 |
| 私有网络 | 由一个组织或机构独立构建和维护，仅供内部使用的网络 | 优点：控制权强、安全性高、性能稳定；缺点：需要专门人员维护，扩展和管理成本高 |

#### 1.3.5 按传输技术

| 网络类型 | 定义 | 优缺点 |
| --- | --- | --- |
| 广播式网络 | 所有节点共享同一条通信信道，数据包发送后会被所有设备接收，但只有目标节点处理 | 优点：网络结构简单，易于实现组播和广播通信；缺点：带宽共享，容易产生冲突和拥塞 |
| 点对点网络 | 每一对通信设备之间通过独立的通信链路进行数据传输，不共享传输介质 | 优点：通信效率高，适合远距离、高速传输；缺点：成本高，需要大量通信链路 |

### 1.4 性能指标

**信道**：表示向某一方向传送信息的通道。一条通信线路在逻辑上往往对应一条发送信道和一条接收信道（**信道 ≠ 通信线路**）。

#### 1.4.1 速率、带宽、吞吐量

| 性能指标 | 描述 |
| --- | --- |
| **速率** | 也称数据传输速率，表示每秒钟传输的比特数，单位为 **bps（bits per second）**。速率通常用于衡量链路的传输能力，如 100 Mbps、1 Gbps 等（**1 B = 8 b**） |
| **带宽** | 表示通信链路所能提供的**最高数据传输能力**，单位同样为 bps。带宽决定了链路理论上的最大传输速率。上行带宽指上传速率，下行带宽指下载速率 |
| **吞吐量** | 实际传输的数据量，通常受限于网络拥塞、协议开销和硬件性能，单位为 bps。吞吐量反映系统的实际性能 |

> 通俗理解：带宽是"高速公路的最高限速"，速率是"实际跑的速度"，吞吐量是"单位时间内真正运过去的货物量"。

#### 1.4.2 时延、时延带宽积、往返时延

| 性能指标 | 描述 |
| --- | --- |
| **时延** | 数据从发送端到达接收端所需的时间，单位为毫秒（ms），包括**发送时延、传播时延、处理时延、排队时延**四部分 |
| **时延带宽积** | 表示网络中同时存在的数据量，为 **带宽 × 时延**，用于衡量链路的"填充"程度 |
| **往返时延（RTT）** | 数据从发送端发送完，到接收端再返回发送端所需的时间，单位为 ms。**RTT 是 TCP 等协议中重要的性能指标** |

时延的四个组成部分：

- **发送时延（传输时延）**：节点把数据推向信道所花的时间，= 数据长度 ÷ 发送速率。
- **传播时延**：电磁波在信道中传播一定距离所花的时间，= 信道长度 ÷ 电磁波传播速率（铜线/光纤中约 2×10⁸ m/s，接近光速）。
- **处理时延**：被路由器处理所花的时间（如分析首部、查找转发表）。
- **排队时延**：数据排队进入、排队发出路由器所花的时间，随负载增大呈非线性急剧增长。

> **总时延 = 发送时延 + 传播时延 + 处理时延 + 排队时延**。注意：提高链路速率只能减小**发送时延**，不能减小**传播时延**——这也是"网络很快但跨洋访问依然卡"的原因之一。

#### 1.4.3 信道利用率

表示信道中实际用于传输数据的时间与总可用时间的比值。信道利用率越高，说明链路资源的使用越有效；但**过高的信道利用率可能导致网络拥塞和延迟增大**。
### 1.5 互联网的构成与接入网

#### 1.5.1 三大组成部分

- **网络边缘**：位于互联网边缘、与互联网相连的计算机和其他设备（端系统），如桌面计算机、移动设备、服务器、智能终端等。
- **网络核心**：由互联端系统的**分组交换设备**和**通信链路**构成的网状网络，包括路由器、链路层交换机，以及光纤、铜缆、无线电、卫星链路等。
- **接入网**：将主机连接到**边缘路由器**（端系统去往任何远程端系统路径上的第一台路由器）的物理链路，是异构网络接入互联网的桥梁。

#### 1.5.2 常见接入网方式（对照日常使用）

| 接入方式 | 原理 | 现状与场景 |
| --- | --- | --- |
| **光纤到户（FTTH）** | 从运营商端局直接铺设光纤到用户家中 | 速率高、抗干扰，是当前家庭宽带主流方式（即"光猫 + 光纤"） |
| **数字用户线（DSL/ADSL）** | 利用电话线上未被语音使用的频带传输数据，上下行速率不对称 | 早期的"电话线上网"，现基本被光纤取代 |
| **同轴电缆（HFC）** | 利用有线电视网络，上下行共享带宽 | 广电宽带使用 |
| **无线接入** | Wi-Fi（无线局域网）、4G/5G 蜂窝移动网络等 | 手机上网、公共场所 Wi-Fi |
| **企业与家庭网络** | 局域网 + 路由器 + NAT 共享接入 | 一台路由器让全家设备共用一个公网 IP |

### 1.6 三种数据交换方式

数据交换技术包括：**电路交换、报文交换与分组交换**。其中分组交换是现代互联网的基础。

#### 1.6.1 电路交换

电路交换是一种为通信双方建立**专有通信路径**的方式。这条路径会在通信开始时建立，并在通信结束后释放。**电话网络是典型的电路交换网络**（打电话时先拨号建立连接，通话期间独占线路）。

- **优点**：
  - **专用通信路径**：通信期间**保持独占的物理路径**，传输过程稳定且可靠。
  - **传输效率高**：没有其他数据干扰，确保**数据按顺序传输**，时延稳定。
- **缺点**：
  - **建立和释放路径开销大**：每次通信都需要进行路径建立和释放，带来额外延迟。
  - **线路独占导致资源浪费**：通话双方即使不说话，占用的路径也无法被别人使用。
  - **缺乏灵活性**：线路分配不灵活，**无法适应动态流量需求**。
  - **差错控制困难**：通信过程中**没有中间节点可以进行差错处理**。

#### 1.6.2 报文交换

报文交换采用**存储-转发技术**，每个报文在经过节点时会被暂时存储，直到找到合适的路径后再继续转发。**电报网络是典型的报文交换网络**。

- **优点**：
  - **无需独占物理线路**：网络资源共享，提高了通信可靠性。
  - **线路灵活分配**：路径根据网络负载情况动态调整。
  - **无需建立连接**：发送方不需要预先建立通信连接。
- **缺点**：
  - **传输延迟较大**：报文必须在节点存储和转发，容易产生延迟。
  - **不适合实时应用**：通信时延波动较大，难以满足实时通信需求。
  - **报文不定长**：不同长度的报文不利于统一存储和管理。

#### 1.6.3 分组交换

分组交换将数据拆分为多个小的数据包（分组），每个数据包独立传输，并在目的地重新组装成完整的数据。**现代计算机网络（如互联网）使用的正是这种技术**。

- **优点**：
  - **无需独占物理线路**：资源动态分配（统计复用），提升了可靠性。
  - **存储-转发技术**：灵活调度，提高了线路使用效率。
  - **无需建立连接**：可以直接发送数据包，提高了通信效率。
  - **支持差错控制**：中间节点可以检测错误。
  - **分组定长，方便存储与转发**：统一的分组长度有助于高效管理和调度。
  - **转发时间开销小**：分组交换比报文交换更快，适用于大规模网络。
- **缺点**：
  - **控制信息开销大**：每个分组都需要附加控制信息（如源地址、目的地址、分组号），占用部分带宽。
  - **可能存在时延**：传输过程中，某些分组可能需要排队等待转发。
  - **数据丢失与失序问题**：不同分组可能走不同路径，接收端需要处理失序和丢失的数据包（由传输层的 TCP 负责解决）。

> **分组交换中的报文结构**：
>
> - **首部**：包含控制信息，如源地址、目的地址、分组号，用于路由和转发。
> - **数据段**：承载具体的数据内容。
>
> 数据被拆分为若干定长的分组，每个分组 = 首部 + 数据段。

#### 1.6.4 三种交换方式对比

| 对比项 | 电路交换 | 报文交换 | 分组交换 |
| --- | --- | --- | --- |
| 是否建立连接 | 先建立专用物理路径（建立 → 通信 → 释放三阶段） | 不建立连接 | 不建立连接 |
| 资源占用 | 独占链路带宽（FDM/TDM 复用） | 存储转发，资源共享 | 存储转发，统计复用 |
| 时延特点 | 建立连接有开销，传输阶段时延稳定 | 报文不定长，时延大且波动 | 分组小，时延相对小 |
| 可靠性/灵活性 | 差（线路故障即中断），资源浪费 | 较好 | 好，灵活，健壮 |
| 典型应用 | 传统电话网络 | 电报系统 | 现代互联网 |

- **分组交换的缺点**：存在存储转发时延、排队时延，可能拥塞、丢包、失序、重复。
- **分组交换的优点**：设计简单、资源利用率高、适合突发流量，代价是"尽力而为（best-effort）"服务。
- **传输时延估算**：设报文总长 x bit、分组长度 p bit（含首部）、链路数（跳数）为 h、每段链路速率 R（忽略传播时延），分组交换总时延 ≈ x/R + (h−1)·p/R（首个分组沿途逐站存储转发，后续分组流水线并行）。

### 1.7 标准化工作及相关组织

计算机网络的发展离不开标准化工作，主要组织包括：

- **ISO（国际标准化组织）**：制定了 OSI 七层参考模型等标准。
- **IEEE（电气与电子工程师协会）**：制定局域网标准，如 IEEE 802.3（以太网）、802.11（Wi-Fi）、802.1Q（VLAN 标签）。
- **ITU（国际电信联盟）**：制定电信领域标准（如 X.25、帧中继、H.323）。
- **IETF（互联网工程任务组）**：负责 TCP/IP 协议族的标准制定，以 RFC 文档发布（如 RFC 793 定义 TCP）。
- **ICANN / IANA**：管理全球域名系统和 IP 地址分配。
- **W3C（万维网联盟）**：制定 Web 标准（HTML、CSS 等）。

## 二、计算机网络的体系结构

### 2.1 协议、接口与服务

网络的体系结构是计算机网络各层及其协议的集合，是计算机网络及其构件所应完成的功能的精确定义（**不涉及实现**）。实现是在遵循体系结构的前提下，用何种硬件或软件完成这些功能的问题。

> **体系结构是抽象的，而实现则是具体的。**
>
> 协议规定的是**水平**的关系（对等层之间），服务是**垂直**的关系（相邻层之间）。

**协议数据单元（PDU）**：对等层次之间传送的数据单位。

- **服务数据单元（SDU）**：为完成上一层实体所要求的功能而传送的数据。
- **协议控制信息（PCI）**：控制协议操作的信息。

协议由三部分组成：**语法、语义、同步**。

- **语法**：数据与控制信息的格式。
- **语义**：需要发出何种控制信息、完成何种动作及做出何种应答。例如，协议中需要明确规定：发送方发送完数据后，接收方是否需要"应答"，以及应答的种类有哪些。
- **同步**：执行各种操作的条件、时序关系等。例如，发送方发完数据后，接收方需要立即应答；如果发送方在 10 秒内未收到"传输成功"应答，则发送方会再次发送数据。

### 2.2 OSI 七层模型

OSI 全称**开放式系统互联参考模型**，自上而下分为应用层、表示层、会话层、传输层、网络层、数据链路层、物理层：

| 层次 | 功能 | 单位 | 协议 | 设备 |
| --- | --- | --- | --- | --- |
| 应用层 | 为应用程序提供网络服务 | — | **HTTP**、HTTPS、FTP、SMTP、DNS | — |
| 表示层 | **数据格式转换、加密解密** | — | SSL/TLS、JPEG、MPEG | — |
| 会话层 | **建立、管理和终止会话**、断点续传 | — | NetBIOS、RPC | — |
| 传输层 | **复用和分用**、端到端的差错控制、流量控制、连接的建立与释放、可靠传输管理（针对报文段） | 报文段 | **TCP**、**UDP** | — |
| 网络层 | **路由选择**、分组转发、拥塞控制、网际互联（针对数据报） | 数据报 | **IP**、ICMP、OSPF | **路由器** |
| 数据链路层 | **差错控制（针对帧）**、流量控制 | 帧 | Ethernet、PPP、HDLC | 网桥、**交换机** |
| 物理层 | 定义物理媒介接口的参数，**实现比特流传输** | 比特 | — | 网线、光纤、中继器、**集线器** |

> **常见误区修正**：HTTPS 是应用层协议（HTTP + TLS），不应列入传输层；SSL/TLS 实际工作在传输层之上、应用层之下，教材中常归入表示层或会话层。
>
> **记忆口诀**：自下而上"物、数、网、传、会、表、应"；自上而下"应、表、会、传、网、数、物"。

OSI **网络层**可向上层提供：有**连接可靠的服务（虚电路）**和**无连接不可靠的服务（数据报）**。

OSI **传输层仅可向上层提供有连接的可靠的服务**。

### 2.3 TCP/IP 模型

TCP/IP 模型是互联网的基础协议套件，它定义了数据如何在网络上打包、寻址、传输、路由和接收。相比 OSI 七层模型，TCP/IP 模型更加简化和实用（将 OSI 的会话层、表示层并入应用层，物理层与数据链路层合并为网络接口层）：

| 层次 | 对应 OSI 层 | 功能 | 主要协议 | 数据单位 |
| --- | --- | --- | --- | --- |
| 应用层 | 会话层、表示层、应用层 | 为应用程序提供网络服务；需要数据格式转换、会话管理时，由应用层的特定协议实现 | **HTTP**、HTTPS、FTP、SMTP、DNS、SSH、Telnet、POP3 | — |
| 传输层 | 传输层 | **复用和分用**、差错控制、流量控制、连接的建立与释放、可靠传输管理（**数据可靠性全部交给传输层**） | **TCP**、**UDP** | 报文段 |
| 网络互联层 | 网络层 | **路由选择**、分组转发、拥塞控制、网际互联（不负责差错控制、流量控制、可靠传输，全部下放给传输层） | **IP**、ICMP、IGMP | 数据报 |
| 网络接口层 | 物理层和数据链路层 | 实现相邻结点的数据传输 | Ethernet、PPP、ARP | 帧 |

TCP/IP 模型的**网络层**提供的是**无连接、不可靠**的数据报服务，差错控制、流量控制、连接的建立与释放、可靠传输管理都交给传输层完成。

TCP/IP **传输层**可向上层提供两种服务：有连接可靠的服务（TCP 协议）、无连接不可靠的服务（UDP 协议）。

> **网络层提供的两种服务**：
>
> 数据包在传输过程中可能出现误码，可能因路由器繁忙而被丢弃，还可能按序发送却不能按序到达。如果网络层对这些传输错误不采取任何措施，则提供的是**不可靠传输服务**；如果采取措施使接收方能正确收到数据，则提供的是**可靠传输服务**。
>
> 不同网络体系结构提供的服务可能不同：因特网使用的 TCP/IP 体系，其网际层提供**无连接、不可靠**的数据报服务；而 ATM、帧中继和 X.25 的网络层提供的都是**面向连接、可靠**的虚电路服务。

### 2.4 五层综合体系结构（教学模型）

为兼顾教学与实用，常采用五层模型（对应关系：应用层 = OSI 上三层；其余逐层对应）：

| 层次 | 核心任务 | PDU（协议数据单元） | 典型设备 |
| --- | --- | --- | --- |
| 应用层 | 通过应用协议提供网络服务 | 报文 | — |
| 传输层 | 进程到进程的端到端通信 | 报文段（TCP）/ 用户数据报（UDP） | — |
| 网络层 | 主机到主机，路由与转发 | IP 数据报 | 路由器 |
| 数据链路层 | 相邻节点间成帧传输 | 帧 | 交换机、网桥、网卡 |
| 物理层 | 比特流透明传输 | 比特 | 中继器、集线器、传输介质 |

## 三、物理层

物理层考虑的是如何在传输媒体上**传输数据比特流**，而不是传输媒体本身。它的目标是**屏蔽不同传输媒体和通信手段的差异**，为数据链路层提供透明的比特流传输服务。

### 3.1 数字信号与模拟信号

信源通过信道给信宿发送信号，信号是数据的载体。对于计算机网络来说，所谓的数据通常就是二进制数据。信号有两种类型：**数字信号**（值离散）与**模拟信号**（值连续）。

| **类型** | **描述** | **特点** | **示例** |
| --- | --- | --- | --- |
| **数字信号** | 以离散的二进制形式（0 和 1）表示的信息 | 抗干扰能力强，便于存储和处理 | 计算机数据、数字音频 |
| **模拟信号** | 以连续波形形式表示的信息，如正弦波 | 适合传递连续的变化，容易受到噪声干扰 | 传统电话语音信号 |

**编码与调制**：

- **编码**：把二进制数据转换成**数字信号**的过程（如曼彻斯特编码）。
- **解码**：把数字信号转换回二进制数据的过程。
- **调制**：把二进制数据转换成**模拟信号**（或光信号）的过程。
- **解调**：把模拟信号（或光信号）转换回二进制数据的过程。

**光猫（ONT/ONU，俗称"猫"）**：本质上是一种**调制解调器**，其主要功能是在**光纤信号**和**数字信号**之间进行转换。家庭宽带的"光猫"规范名称是光网络终端（ONT），运营商侧对应光线路终端（OLT）：

- **调制（Modulation）**：将**数字信号**（计算机、手机等设备的数据）转换为**光信号**，以便通过光纤传输。
- **解调（Demodulation）**：将光纤网络中的**光信号**转换回**数字信号**，使其可以被计算机或路由器识别处理。

### 3.2 编码与调制（基带与带通）

- **基带调制（编码）**：对数字信号进行变换，输出仍为数字信号。常用编码：
  - **不归零（NRZ）**：1 为高电平，0 为低电平；无法自同步，连续同值难以区分边界。
  - **曼彻斯特编码**：每个比特中间必有跳变，跳变方向表示 0/1（以太网使用），占用带宽是 NRZ 的两倍。
  - **差分曼彻斯特编码**：比特中间跳变仅作同步，比特开始处**有跳变为 0、无跳变为 1**（802.5 令牌环使用），抗干扰更好。
  - **4B/5B 编码**：每 4 位数据映射为 5 位码组，保证码组中至少有两个 1，解决连续 0 的同步问题，编码效率 80%。
- **带通调制**：把基带信号搬移到较高频段，使用**调幅（AM）、调频（FM）、调相（PM）**，可组合使用（**QAM 正交振幅调制** = 幅度 + 相位联合调制）。

### 3.3 奈奎斯特定理（无噪声信道）

- 理想低通信道下，为避免码间串扰，极限码元传输速率为 **2W Baud**（W 为信道带宽，单位 Hz）。
- 极限数据率：**C = 2W·log₂V**（V 为每个码元的离散电平数）。
- 含义：码元速率受信道带宽限制，但可以通过**多元制调制**（增大 V，即每个码元携带更多比特）来提高数据率。

### 3.4 香农定理（有噪声信道）

- 带宽受限、存在高斯白噪声时，无差错传输的极限数据率：**C = W·log₂(1 + S/N)**。
- 信噪比（dB）= 10·log₁₀(S/N)，如 30 dB 对应 S/N = 1000。
- 含义：**带宽或信噪比越大，极限速率越高**；只要传输速率低于信道容量，总存在一种编码方式实现无差错传输。
- 综合应用：实际中先由香农定理算出极限数据率 C，再结合奈奎斯特定理确定所需的码元电平数 V。

### 3.5 传输介质

网络传输介质是指在网络中传输信息的载体，分为**有线传输介质**和**无线传输介质**两大类。

**有线传输介质**是在两个通信设备之间实现物理连接的部分，将信号从一方传输到另一方，主要有双绞线、同轴电缆和光纤：

- 双绞线和同轴电缆传输**电信号**。
- **光纤传输光信号，是传输速度最快、距离最长、抗干扰能力最强的计算机网络传输介质**。

| 介质 | 特点 | 速率/距离 |
| --- | --- | --- |
| 双绞线 | 两根绝缘铜线绞合抗干扰；电话线 1 对，网线 4 对；5 类 100 Mbps~1 Gbps、6 类 10 Gbps | 单段约 100 m |
| 同轴电缆 | 两根同心铜导线，带宽高，抗干扰较好 | 约 200 m，带宽可达数百 Mbps |
| 光纤 | 光全反射传输；**单模光纤**（芯细、激光、长距离骨干）与**多模光纤**（芯粗、发光二极管、短距离）；速率 10~100 Gbps，对电磁噪声免疫，中继距离远 | 数十公里以上 |

**无线传输介质**指周围的自由空间，利用无线电波在自由空间的传播实现多种无线通信。按频谱可分为无线电波、微波、红外线、激光等，**信息被加载在电磁波上进行传输**：

- 地面微波：点对点通信，约 45 Mbps。
- 卫星通信：同步卫星高约 36000 km，往返时延约 280 ms；低轨卫星时延小，但需要大量卫星组网。
- 蓝牙、红外：短距离通信。
- 蜂窝移动网络（3G/4G/5G）：约 10 km 覆盖范围。

**介质选择**：不同的传输介质特性不同，对数据通信质量和通信速度影响较大。选择传输介质时必须考虑 5 种特性：**吞吐量和带宽、成本、尺寸和可扩展性、连接器以及抗噪性**。

> **有线传输介质的命名规则：速度 + Base + 介质信息**
>
> 速度的单位是 Mbps；Base 表示信号传输方式（**基带传输**）；介质信息若为数字，表示最大段长度（以百米计）；若为字母，表示传输介质类型——**T、TX 表示双绞线，F 表示光缆**。
>
> 举例：**10BASE-T** → 10 Mbps 基带传输，使用双绞线；**10BASE2** → 10 Mbps 基带传输，同轴电缆，最远传输距离约 200 米；**100BASE-FX** → 100 Mbps 基带传输，使用光缆。

### 3.6 信道复用技术

- **频分复用（FDM）**：所有用户在**同样的时间**占用**不同的频带**资源，适合模拟信号；频分多址（FDMA）是其接入形式。
- **时分复用（TDM）**：将时间划分为等长的 TDM 帧，每个用户在每帧中占用固定序号的时隙；**统计时分复用（STDM）**按需动态分配时隙，提高利用率。
- **波分复用（WDM）**：光的频分复用，一根光纤同时传输多个光载波（波长）信号；密集波分（DWDM）可达数十路。
- **码分复用（CDM/CDMA）**：各用户使用相互**正交的码片序列**，同一时间、同一频带并行通信互不干扰；接收方用发送方的码片序列做规格化内积即可分离信号（结果为 +1 / −1 / 0 分别表示发送比特 1 / 0 / 未发送）。

### 3.7 物理层接口的特性

物理层接口有四大特性：

- **机械特性**：接口形状、尺寸、引脚数目和排列。
- **电气特性**：电压范围、传输速率、距离限制。
- **功能特性**：某电平的电压表示何种意义（如 0/1）。
- **规程特性**：不同功能的各种事件的出现顺序。

### 3.8 物理层设备

#### 3.8.1 中继器

当电压信号或电流信号在电缆上传输时，会受电阻影响逐渐失真，传输距离越长失真越严重。要让网络覆盖更长的距离，就需要使用中继器：**当信号处于一个合理的波动范围内，中继器可以正确识别信号的含义，把信号整形再生，然后再发送到下一段链路上**，确保最终目的节点收到的信号失真不会太严重，至少能正确解读信号含义。

中继器仅支持**半双工通信**，有两个端口，**通过一个端口接收信号，将失真信号整形再生，并转发至另一端口**，这个过程会产生一些时延。它的两个端口对应两个"网段"，适用于总线型拓扑。

#### 3.8.2 集线器

**集线器本质上是多端口中继器**，将其中**一个端口接收到的信号整形再生后，转发到所有其他端口**。各端口连接的结点不可同时发送数据，仅支持**半双工通信**。

> 把四台电脑连接到同一个集线器上，就把多个节点连接了起来，组成了一个计算机网络。

其特点包括：

- **广播式发送消息**：所有连接的设备都能收到信息，信息可能被其他设备截获，存在安全隐患。
- **半双工**：不能同时向上和向下传输信息。
- **实时性差**：消息传递可能存在延迟。
- **总线型拓扑结构**：所有端口共享同一个冲突域。

> **链路聚合**：将**多条物理链路捆绑成一条逻辑链路**的技术，以提高网络的**带宽、冗余性**和**可靠性**。即使某条物理链路故障，其他链路仍能继续传输数据：
>
> 1. **带宽增加**：多条链路并行传输数据，提高总体带宽。
> 2. **冗余性**：即使一条或多条链路故障，其他链路仍能正常工作。
> 3. **负载均衡**：将流量分布在多条链路上，避免单链路拥塞。
> 4. **故障恢复**：当一条链路失效时，流量自动切换到剩余链路上，无需人工干预。
>
> **网络冗余设计**：避免网络组件单点失效造成应用中断。主路径比备用路径承担更多的网络负载；负载分担通过并行链路提供流量分担来提升性能，网络中存在备用链路时可以考虑加入负载分担设计。

## 四、数据链路层

数据链路层是计算机网络体系结构中的第二层，负责实现相邻节点之间的数据传输。它需要为网络层提供服务：将网络层的分组数据加上首部和尾部的控制信息**封装成帧**；同时依赖物理层提供的比特传输服务，将帧传输给下一个相邻节点。**数据链路层实体之间以帧为单位进行数据传输**。

### 4.1 数据链路层的功能

1. **封装成帧**：将网络层的数据封装成帧，包括**帧定界**和**透明传输**（透明传输即恢复原始的 SDU，使接收方的网络层感受不到封装成帧的过程）。
2. **差错控制**：发现并解决**帧中的位错误**，包括**检错编码**和**纠错编码**。
3. **可靠传输**：使用**滑动窗口机制、确认机制、重传机制**解决**帧丢失、帧重复和帧失序**的问题。
4. **流量控制**：控制发送方发送帧的速率，防止接收方来不及接收。
5. **介质访问控制**：实现广播信道的介质访问控制，防止多个节点争抢传输介质。

### 4.2 数据链路层的三类服务

| 服务类型 | 是否确认 | 是否连接 | 典型场景/实例 |
| --- | --- | --- | --- |
| 无确认无连接 | 否 | 否 | 误码率低的可靠信道、实时通信（以太网） |
| 有确认无连接 | 是 | 否 | 不可靠信道（802.11 无线） |
| 有确认有连接 | 是 | 是 | 长延迟不可靠信道（蓝牙） |

### 4.3 组帧（帧定界）的四种方法

1. **字符计数法**：帧首部给出帧长；缺点是计数一旦出错，后续全部错位。
2. **字节（字符）填充法**：用特殊字符（如 SOH、EOT）定界，数据部分出现定界字符时插入转义字符（PPP 使用 0x7E 定界、0x7D 转义）。
3. **比特填充法**：定界符 01111110（0x7E），发送方数据中每出现**连续 5 个 1 就插入 1 个 0**；接收方看到连续 5 个 1 时：后跟 0 则丢弃该 0（还原有效载荷），后跟 1 再跟 0 则识别为帧结束（HDLC、PPP 的零比特填充）。
4. **物理层编码违例法**：利用正常编码中不会出现的信号模式做定界，如曼彻斯特编码中持续高/低电平为违例码；4B/5B 中未使用的码组、以太网前导码也可作定界。

### 4.4 差错控制：检错与纠错编码

**基本策略**：

- **检错码**（奇偶校验、校验和、CRC）：只能发现错误，靠重传恢复，适合低误码信道（如光纤）。
- **纠错码**（汉明码、FEC 前向纠错）：能定位并纠正错误，适合高误码或实时场景（无线链路、实时流媒体）。
- 应对四种传输差错：**位翻转**（靠校验发现）、**帧丢失**（靠定时器/重传）、**乱序**（靠序号）、**重复**（靠序号去重）。

#### 4.4.1 奇偶校验码

奇偶校验码是一种简单的错误检测方式，用于检测数据传输过程中的单个比特错误。它通过在数据中添加一个附加位（校验位），根据数据中 1 的个数来确定该位的值，使整个数据的 1 的个数满足奇数或偶数的约定。例如**奇校验**：数据 1010111 中 1 的个数为 5（奇数），则校验位为 0，保证整体 1 的个数仍为奇数（`1 | 1010111`）。

奇偶校验码**只能检测出奇数位错误**，无法检测出偶数位错误，且**只能检错，不能纠错**。

#### 4.4.2 CRC 循环冗余校验

循环冗余校验（Cyclic Redundancy Check, CRC）是一种用于检测数据传输或存储过程中错误的校验技术。它将数据视为一个多项式，通过特定的**生成多项式**计算校验码；接收端重复计算过程，若结果不符，则说明数据在传输中出错。

计算步骤：

1. 设原始数据 D 为 k 位，选定 n+1 位生成多项式 G（最高位为 1），收发双方事先商定。
2. 在 D 后补 n 个 0（即 D × 2ⁿ），用 G 对其做**模 2 除法**（异或运算、不借位）。
3. 得到 n 位余数 R（不足 n 位高位补 0）即 CRC 校验码，实际发送 D 后接 R。
4. 接收方用同一个 G 除收到的 (k+n) 位数，余数为 0 则认为无错。

> 例：D = 1010001101，G = 110101（n = 5），计算得 R = 01110，实际传输 1010001101**01110**。以太网帧尾的 FCS（帧校验序列）就是 CRC-32。

#### 4.4.3 海明校验码（汉明码，可纠 1 位错）

**1. 确定数据和校验位的位置**：

- n 位数据需要 k 个校验位，满足 **2^k ≥ n + k + 1**。
- 校验位放在 1、2、4、8……这些 2 的幂位置上（P₁、P₂、P₄、P₈…）。
- 其余位置依次填入信息位。

**2. 求校验位**：

- 将信息位的位置序号用 k 位二进制数表示。
- 校验位 Pᵢ 与"位置序号二进制第 i 位为 1"的所有信息位构成一组，每组做偶校验（如 P₁ 负责位置 1、3、5、7…；P₂ 负责 2、3、6、7…；P₃ 负责 4、5、6、7…）。

**3. 纠错**：接收方对各个分组重新做异或（偶校验），得到 S₁S₂S₃…，其二进制值即为出错位的**位置号**；全 0 表示无错。

**示例：信息位 1010（n = 4，由 2³ ≥ 4 + 3 + 1 得 k = 3）**

| H7 | H6 | H5 | H4 | H3 | H2 | H1 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 0 | 1 | P3 | 0 | P2 | P1 |

各位置号转二进制：3 = 011，5 = 101，6 = 110，7 = 111。求校验位：

```
P1 = H3 ⊕ H5 ⊕ H7 = 1 ⊕ 1 ⊕ 0 = 0   （位置号第 1 位为 1：3、5、7）
P2 = H3 ⊕ H6 ⊕ H7 = 1 ⊕ 0 ⊕ 0 = 1   （位置号第 2 位为 1：3、6、7）
P3 = H5 ⊕ H6 ⊕ H7 = 1 ⊕ 0 ⊕ 1 = 0   （位置号第 4 位为 1：5、6、7）
```

填入校验位后发送的数据为：

| H7 | H6 | H5 | H4 | H3 | H2 | H1 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 0 | 1 | 0 | 0 | 1 | 0 |

即发送 **1010010**。

**接收端校验示例**：若接收到的数据是 1010000，重新对分组做偶校验：

```
S1 = H1 ⊕ H3 ⊕ H5 ⊕ H7 = 0 ⊕ 0 ⊕ 1 ⊕ 1 = 0
S2 = H2 ⊕ H3 ⊕ H6 ⊕ H7 = 0 ⊕ 0 ⊕ 0 ⊕ 1 = 1
S3 = H4 ⊕ H5 ⊕ H6 ⊕ H7 = 0 ⊕ 1 ⊕ 0 ⊕ 1 = 0
```

S₃S₂S₁ = 010（二进制 2），说明**第 2 位（H2）出错**，将其翻转后正确数据应为 1010010。

**区分 1 位错与 2 位错**：基于上述方案无法区分 1 位错还是 2 位错，可在最后面添加一位**全体校验位**，对整体做偶校验：

```
S1S2S3 = 000 且全体偶校验成功  → 无错误
S1S2S3 ≠ 000 且全体偶校验失败  → 有 1 位错，纠正即可
S1S2S3 ≠ 000 且全体偶校验成功  → 有 2 位错，需重传
```

### 4.5 流量控制与可靠传输机制

数据链路层负责在相邻节点之间传输数据帧。为了保证传输可靠且不发生拥塞，主要采用以下机制：

- **流量控制**：防止发送端发送速度超过接收端的处理能力。使用**滑动窗口机制**：发送端维护一个窗口，限制未确认的数据帧数量；接收端根据自身处理能力调整窗口大小。
- **可靠传输**：确保数据帧不丢失、不重复且按序到达，由**停止-等待、后退 N 帧、选择性重传**三种协议实现。

| 协议 | 发送窗口 | 接收窗口 | 信道利用率 | 重传策略 |
| --- | --- | --- | --- | --- |
| 停止-等待（S-W） | 1 | 1 | 最低（U = T_D / (T_D + RTT + T_A)） | 超时重传当前帧 |
| 后退 N 帧（GBN） | ≤ 2ⁿ − 1 | 1 | 较高 | 出错帧及其后**全部**重传 |
| 选择性重传（SR） | ≤ 2ⁿ⁻¹ | = 发送窗口 | 最高 | 只重传**丢失/出错**的帧 |

- **停止-等待协议**：每次发送一个数据帧，等待确认（ACK）后再发送下一个。实现简单但效率低、信道利用率低。
- **后退 N 帧协议（GBN）**：发送方可以连续发送多个帧，但必须按顺序接收确认。若某帧丢失或出错，则重发该帧及其后所有未确认的帧。
- **选择性重传协议（SR）**：发送方只重传丢失或出错的帧，而不是像 GBN 那样重发多个帧。
- n 为序号比特数；窗口序号范围必须在模 2ⁿ 空间内可区分新旧帧（SR 要求窗口之和 ≤ 2ⁿ）。
- **捎带确认（piggybacking）**：双向通信时把确认信息放在反向数据帧中，减少开销。
- **累积确认**：GBN 中确认号表示该帧及之前所有帧均已正确接收。

### 4.6 介质访问控制

广播信道的访问控制方法分为三类：

1. **信道划分**：频分多路复用（FDM）、时分多路复用（TDM）、波分多路复用（WDM）、码分多路复用（CDM），详见物理层复用技术。
2. **随机访问**：ALOHA 协议、CSMA 协议（CSMA/CD、CSMA/CA）。
3. **轮询访问（受控访问）**：令牌传递协议、位图协议、二进制倒计数。

#### 4.6.1 ALOHA 协议

- **纯 ALOHA**：想发就发，冲突随时可能发生，冲突帧全部损毁需随机退避后重传；最大吞吐率约 **18.4%**。
- **时隙（分槽）ALOHA**：时间划分为固定时隙（时长 = 一帧传输时间），只能在时隙起点发送，冲突只发生在时隙起点；最大吞吐率约 **36.8%**。

#### 4.6.2 CSMA 载波侦听多路访问（先听后发）

| 类型 | 侦听忙时的行为 | 特点 |
| --- | --- | --- |
| 1-持续式 | 持续侦听，一空闲**立即**发送 | 延迟小，但多个站等待时**必然冲突** |
| 非持续式 | 放弃侦听，等待一个**随机时间**后再侦听 | 冲突少，但空闲介质可能被浪费 |
| p-持续式 | 空闲时以概率 p 发送、以 1−p 推迟一个时间单元；忙则持续侦听 | 折中方案，用于时隙信道 |

#### 4.6.3 CSMA/CD（碰撞检测，有线以太网）

- 流程：**先听后发、边听边发、冲突停发、随机重发**。
- **争用期（冲突窗口）2τ**：端到端传播时延 τ 的两倍，经过 2τ 未检测到碰撞才能确定发送成功。
- **最小帧长 = 2τ × 数据率**。传统 10 Mbps 以太网争用期 51.2 μs，故最短有效帧长 **64 字节**（不足则填充）。
- **截断二进制指数退避算法**：冲突后第 i 次重传从 {0, 1, …, 2^min(i,10) − 1} 中随机选 k，等待 k·2τ 后重发；重传 16 次仍失败则放弃并报错。

#### 4.6.4 CSMA/CA（碰撞避免，802.11 无线）

- 无线环境下无法边发边听（信号衰减导致冲突检测不可行），故改为**碰撞避免**：帧间间隔（IFS）+ 随机退避计时器。
- 可选 **RTS/CTS 机制**（请求发送/允许发送）预约信道，解决**隐藏终端问题**。
- 配合链路层确认（ACK）+ 超时重传实现可靠传输。

#### 4.6.5 受控访问（轮询）协议

- **位图协议（预留协议）**：竞争期各站按序在属于自己的时槽中"举手"预留，传输期按序发送，无冲突。
- **令牌传递**：持有令牌者才有发送权；帧需由目的站或发送站负责从环上摘除以防无限循环；缺点是令牌维护有开销（令牌环、令牌总线）。
- **二进制倒计数协议**：各站点编号二进制位从高到低排队竞争，高序号站点优先。

#### 4.6.6 有限竞争协议

- **自适应树搜索协议**：冲突时将所有站点组织成完全二叉树，逐层一分为二递归竞争，冲突概率随站点密度自适应降低，结合了随机访问的低延迟与受控访问的无冲突。
### 4.7 局域网

IEEE 802 委员会在局域网技术的标准化和推广中起到了重要作用。局域网技术最初由科技公司发明，出于商业目的。IBM 公司的令牌环网技术和 FDDI 曾受到市场认可，但最终被以太网技术超越。

局域网的主要特点：

1. 覆盖较小的地理范围，内部节点间通信具有较低的时延和误码率。
2. 内部节点间通信带宽高、传输时延小。
3. 内部数据传输以帧为单位，支持**单播、广播和多播**模式。
4. 每个节点具有唯一的 MAC 地址，用于指明帧的发送目标。

> **内部局域网（企业内网）**：组织内部使用的封闭、私有网络系统，通常用于企业、政府机构或学校内部通信。相比互联网，内网安全性更高，大多不直接向公共网络暴露。其价值主要体现在：
>
> - **高安全性**：通过身份认证、加密等手段实施内部访问控制；数据不暴露在公共网络中，减少外部攻击风险；管理员可集中监控流量与设备状态，通过 DHCP 和 DNS 服务自动管理 IP 与域名解析。
> - **高性能低延迟**：数据传输速率高（如 1Gbps 或 10Gbps），适合视频会议、文件共享等实时或高频应用；通过冗余备份降低单点故障，提高可用性。
> - **可扩展灵活**：通过 **VLAN** 和子网划分细分为多个逻辑区域，适应不同部门需求；可按需扩展设备与服务而不影响现有网络稳定性。

#### 4.7.1 以太网（IEEE 802.3）

以太网（Ethernet）是使用最广泛的**局域网技术**，是一种**数据链路层和物理层**的网络协议，**遵循 IEEE 802.3 标准**，将有线局域网的数据分成帧传输。

- **MAC 帧（V2 格式）**：前导码(8B) + 目的MAC(6B) + 源MAC(6B) + 类型(2B，如 0x0800 表示上层为 IP) + 数据(46~1500B) + FCS(4B CRC)；帧长 64~1518 字节。
- **MAC 地址**：48 位物理地址，全球唯一，烧录于网卡（前三字节 OUI 标识厂商）；全 1 地址 FF-FF-FF-FF-FF-FF 为广播地址。
- **CSMA/CD**：有线以太网使用的介质访问控制方法（见 4.6.3）。
- **冲突域与广播域**：集线器的所有端口属于同一冲突域和同一广播域；交换机每个端口是一个独立冲突域，但默认所有端口同属一个广播域；路由器隔离冲突域和广播域。

#### 4.7.2 交换机与生成树协议

> 交换机可以把多个节点连接起来组成计算机网络，且不会发生数据冲突——两台电脑同时发送数据，数据不会"打架"，都可以成功发出。交换机还可以级联另一台交换机，所以构建校园网这类较大规模的内部网络时，会使用很多台交换机。

交换机是比集线器更智能的设备，能够记录设备的唯一标识——MAC 地址，其主要特点：

- **自学习**：交换机收到帧时将源 MAC 与进入端口记入 **MAC 地址表**（表项有老化时间）。
- **转发/过滤**：目的 MAC 在表中且端口不同于进入端口则转发；同端口则丢弃（过滤）；不在表中则向除进入端口外的所有端口**洪泛**。
- **点对点发送**：根据 MAC 地址直接转发。**交换机用于局域网，利用主机的 MAC 地址进行数据传输，不需要关心 IP 数据包中的 IP 地址**。
- **全双工模式**：允许同时进行双向信息传输。
- **桥接支持**：可以实现多个交换机之间的信息交换。
- **主要功能**：增加传输带宽、降低网络传输延迟、进行网络管理、选择网络传输线路。交换机工作在 OSI 参考模型的**数据链路层**。

然而，随着网络规模扩大，可能出现以下问题：

- **表溢出**：新 MAC 地址覆盖旧地址，导致信息无法正确发送。
- **冗余链路**：可能引发广播风暴和环路问题。

> **交换网环路**：在以太网交换网络中，存在多条路径连接同一组交换机，从而形成物理环路。环路会导致数据包无限循环，造成**广播风暴**、**MAC 地址表抖动**和**网络拥塞**。**生成树协议（STP）**通过交换 BPDU 计算无环生成树，逻辑阻塞冗余链路；链路故障时自动重新收敛，恢复备用路径。

#### 4.7.3 虚拟局域网（VLAN）

VLAN（虚拟局域网）技术用于将局域网划分为多个虚拟网络，每个虚拟网络具有独立的广播域。VLAN 的引入可以解决传统大型局域网面临的问题：

1. **广播风暴**：当局域网规模较大、节点数较多时，广播帧出现频率增加，导致网络数据传输和节点处理负载过高，可能引发广播风暴。
2. **安全性问题**：所有节点暴露在同一个广播域内，高敏感节点（如服务器、数据中心）容易受到攻击。

VLAN 的解决方案：

1. 将局域网内部的节点重新分组，划分为不同的**虚拟局域网**。
2. 每个 VLAN 是独立的广播域，**节点只能与同属一个 VLAN 的节点通信**。
3. 通过**将敏感节点划分到单独的 VLAN 中**提升安全性，限制其他节点的访问。

VLAN 的划分方式：

1. **基于接口划分**：管理员**配置 VID 与接口号的映射关系**，节点通过所连接的接口确定所属 VLAN。
2. **基于 MAC 地址划分**：管理员**配置 VID 与 MAC 地址的映射关系**，节点即使更换接口也属于同一个 VLAN。
3. **基于 IP 地址划分**：通过 **IP 地址与 VID 的映射关系**划分，可以跨越路由器，连接多个局域网的主机。

交换机与交换机之间的传输：

1. 使用 **802.1Q 帧格式**，在标准以太网帧中间插入 4 字节的 VLAN 标签。
2. VLAN 标签包含 VID 信息，用于标识帧所属的 VLAN。
3. 交换机通过检查 VLAN 标签确定帧的转发端口；帧到达 Access 端口时剥离标签。
4. **VLAN 间通信**必须借助路由器或**三层交换机**进行 VLAN 间路由。

#### 4.7.4 令牌环网（802.5，已基本淘汰）

令牌环网中，设备首尾相连形成闭合环路，采用**令牌传递**方式控制发送权：只有持有令牌的站点才能发送数据，数据沿环单向传递，由目的站接收并摘除。其优点是冲突少、信道利用率高且公平；缺点是任一节点故障会中断整个环，且令牌维护复杂。令牌环网和 FDDI 曾流行于早期企业网，**现已基本被以太网取代**。

#### 4.7.5 无线局域网（802.11/Wi-Fi）

- **基础架构模式（有 AP）**：站点 STA + 访问点 AP + 分布式系统 DS 组成基本服务集 BSS，多个 BSS 通过 DS 组成扩展服务集 ESS；站点间通信经 AP 转发；入网需**扫描、认证、关联**三步骤，支持漫游与节能（休眠模式）。
- **自组织模式（Ad hoc）**：无 AP，站点直接通信，构成独立基本服务集 IBSS。
- 使用的介质访问控制方法是 **CSMA/CA**（原因见 4.6.4）。
- 需解决的核心问题：有限频谱（信道划分与空间复用）、共享信道可靠性（冲突避免与安全）、移动性管理与节能。

### 4.8 广域网

#### 4.8.1 广域网的基本概念

广域网（WAN）覆盖范围大（城市、国家、全球），通常由电信运营商建设，通过租用线路或公共网络（互联网、MPLS 专线等）把多个局域网连接起来。广域网使用**存储转发**方式，核心设备是路由器。

#### 4.8.2 PPP 协议（点对点协议）

PPP 面向字节，用于**拨号/专线串行链路**（如家庭宽带拨号上网的历史场景、运营商接入链路）：

- 只检错不纠错、不可靠传输、不使用序号确认机制。
- 由**封装方法、LCP（链路控制协议：建立/测试/拆除链路）、NCP（网络控制协议，如 IPCP 协商 IP 地址）**三部分组成。
- 帧定界 0x7E，字节填充转义 0x7D（见 4.3 组帧方法）。

#### 4.8.3 HDLC 协议（高级数据链路控制）

HDLC 面向比特，帧定界 01111110 + 零比特填充（见 4.3 组帧方法），有确认与序号，支持正常响应/异步平衡等模式；与 PPP 相比开销更大、更复杂。历史上用于租用线路的可靠传输，现已较少直接使用（多被 PPP/以太网替代）。

### 4.9 数据链路层设备

#### 4.9.1 网桥

网桥类似于中继器，但网桥要**分析帧地址字段**，以决定是否把收到的帧转发到另一个网络段上。它工作在**数据链路层**。

#### 4.9.2 交换机

见 4.7.2（交换机是"多端口网桥"，比集线器智能，可隔离冲突域）。

#### 4.9.3 网络适配器（网卡）

网络适配器（Network Adapter）是用于将计算设备（如计算机、服务器、IoT 设备）连接到网络的硬件组件（或虚拟化软件组件），负责在设备与网络之间传输数据，实现有线或无线通信。工作在**数据链路层**。

- 网卡提供一个接口，使计算机能够通过有线或无线网络通信；网卡**将计算机内部的数据封装成适合在网络上传输的格式**（如以太网帧）。
- **每个网卡都有一个唯一的 MAC 地址，用于在局域网中标识设备**。
- 网卡接收来自计算机的数据，转换为网络可以理解的格式；接收到的数据通过网卡驱动程序送入计算机处理。

> 网卡工作在数据链路层，转发数据帧；连接的传输介质在物理层，所以网卡主要实现的功能横跨物理层与数据链路层。

## 五、网络层

网络层负责把数据报从源主机传送到目的主机，核心是**寻址与路由**。

### 5.1 网络层的功能

- **异构网络互联**：屏蔽不同物理网络（以太网、Wi-Fi、蜂窝、专线等）的差异，使它们可以协同工作。
- **路由与转发**：路由是**全局**操作（运行路由协议，确定从源到目标的路径，生成路由表）；转发是**本地**操作（把收到的分组从输入接口移动到正确的输出接口）。
- **拥塞控制**：网络层配合传输层缓解网络拥塞（详见 5.10）。
- 传统教材还提及差错控制、流量控制等，但在 TCP/IP 体系中这些功能主要由传输层负责。

### 5.2 数据报服务与虚电路服务

| 对比项 | 数据报服务（Internet） | 虚电路服务（X.25、ATM、帧中继） |
| --- | --- | --- |
| 建立连接 | 无需 | 通信前需建立虚电路 |
| 分组头 | 每个分组携带完整目的地址 | 仅携带虚电路号 VCID |
| 路由 | 每个分组独立选路，可失序到达 | 沿同一条虚电路按序到达 |
| 可靠性 | 网络层不保证可靠，由端系统负责（TCP/IP 方案） | 网络层提供可靠服务 |
| 故障影响 | 某节点故障，分组可绕行 | 虚电路经过故障节点则中断 |

> 互联网选择数据报服务，把可靠性交给端到端的 TCP 来实现——"网络尽力而为，端系统负责可靠"。

### 5.3 路由算法

#### 5.3.1 静态路由与动态路由

- **静态路由**：管理员手工配置路由表，简单、开销小，但不适应拓扑变化，适合小型稳定网络。
- **动态路由**：路由器运行路由协议自动学习、更新路由表，适应网络变化，开销较大。

#### 5.3.2 距离向量（DV）算法

- 每个节点周期性地向**邻居**发送自己到所有节点的距离向量；收到邻居的 DV 后用 **Bellman-Ford（B-F）方程**更新：Dx(y) ← minᵥ{ c(x,v) + Dᵥ(y) }。
- 特点：迭代式、分布式、异步；路由器只掌握邻居与链路费用（"部分道听途说"）。
- 缺陷：**计数到无穷**（好消息传播快、坏消息传播慢）；防环路手段：水平分割、毒性反转、触发更新、限制最大跳数。

#### 5.3.3 链路状态（LS）算法

- 每台路由器**泛洪链路状态分组（LSP）**到全网（LSP 含发送方标识、序列号、年龄、邻居及费用），掌握完整拓扑后用 **Dijkstra 算法**计算最短路径树。
- 度量可为带宽倒数（如 1 Gbps 链路代价 1，100 Mbps 代价 10）、时延（RTT 测量）等。
- 序列号用于识别新旧分组：新分组泛洪、重复分组丢弃、过时分组拒绝。
- 与 DV 对比：信息交换范围（邻居 ↔ 全网）、信息可靠性（间接获知 ↔ 自己测量）、收敛速度与报文开销各有优劣。

#### 5.3.4 层次路由（自治系统）

- 规模与管理自治需求 → 划分**自治系统（AS）**：一个管理机构控制下的网络，内部使用统一的路由协议与度量，拥有全球唯一 AS 号；AS 内可再划分区域。
- 由此路由协议分为：**域内（内部网关协议 IGP）**如 RIP、OSPF、IS-IS；**域间（外部网关协议 EGP）**即 BGP。

### 5.4 IP 地址

IP 地址由**网络部分**和**主机部分**组成。对于 IPv4 地址，通常表示为四个十进制数字（例如 192.168.1.1），每个数字范围在 0~255 之间。网络部分标识特定的网络，主机部分标识该网络内的具体设备；使用**子网掩码**可以进一步划分网络和主机部分。

#### 5.4.1 分类编址（早期方案）

| 类别 | 地址范围 | 说明 | 网络地址 | 网络号 | 主机号 | 默认子网掩码 |
| --- | --- | --- | --- | --- | --- | --- |
| A | 1.0.0.0 - 126.255.255.255 | 大型网络，首位为 0 | 1 - **126** | 7 | 24 | 255.0.0.0 |
| B | 128.0.0.0 - 191.255.255.255 | 中型网络，前两位为 10 | 128 - **191** | 14 | 16 | 255.255.0.0 |
| C | 192.0.0.0 - 223.255.255.255 | 小型网络，前三位为 110 | 192 - **223** | 21 | 8 | 255.255.255.0 |
| D | 224.0.0.0 - 239.255.255.255 | 多播地址 | — | — | — | — |
| E | 240.0.0.0 - 255.255.255.255 | 预留地址，用于科研 | — | — | — | — |

> C 类网络的网络号为 24 位，主机号为 8 位，理论上有 2⁸ = 256 个地址，但**主机号全为 0 表示"本主机"所连接的网络地址，主机号全为 1 表示该网络上的所有主机（广播地址）**，两种情况都不能分配给主机，所以每个网络最多可安装 254 台主机（2⁸ − 2）。

**特殊地址**：0.0.0.0（本网络本主机）、255.255.255.255（受限广播）、127.x.x.x（环回 loopback，用于本机自测）、主机号全 0（网络地址）、主机号全 1（定向广播）。

#### 5.4.2 私有地址与 NAT

**NAT（网络地址转换）**是一种将**私有网络 IP 地址**转换为**公共 IP 地址**的技术，用于在局域网和互联网之间传输数据。NAT 常用于缓解 IPv4 地址不足的问题，并提升网络安全性（家庭路由器默认开启）。

**私有网络预留了三个 IP 地址块**，这些地址不会在互联网上被分配：

- A 类：**10**.0.0.0 ~ 10.255.255.255
- B 类：**172.16**.0.0 ~ **172.31**.255.255
- C 类：**192.168**.0.0 ~ **192.168**.255.255

> 即：**10. 开头、172.16~172.31 之间、192.168 开头**的地址都是私有地址，只能在局域网内部使用。家里路由器分配的 192.168.x.x 就属于此类。

#### 5.4.3 子网掩码

子网掩码是一个 32 位的二进制数，其对应**网络地址的所有位置都为 1**，对应于**主机地址的所有位置都为 0**。

- A 类网络默认子网掩码 255.0.0.0，B 类默认 255.255.0.0，C 类默认 255.255.255.0。
- 将子网掩码和 IP 地址按位做逻辑"与"运算，得到该 IP 的网络地址，剩余部分即主机地址，从而区分任意 IP 中的网络部分和主机部分。

> **示例**：主机 1 的 IP 为 222.21.160.6、子网掩码 255.255.255.192；主机 2 的 IP 为 222.21.160.73、子网掩码 255.255.255.192。判断两主机是否在同一网段：
>
> ```
> 主机1 IP：       11011110.00010101.10100000.00000110
> 子网掩码：       11111111.11111111.11111111.11000000
> 按位与结果：     11011110.00010101.10100000.00000000  → 网络地址 222.21.160.0
>
> 主机2 IP：       11011110.00010101.10100000.01001001
> 子网掩码：       11111111.11111111.11111111.11000000
> 按位与结果：     11011110.00010101.10100000.01000000  → 网络地址 222.21.160.64
> ```
>
> 两台主机的网络地址不同（222.21.160.0 ≠ 222.21.160.64），**不在同一网段**，它们之间的通信需要通过路由器。
>
> ps：计算时，子网掩码全为 1 的部分只需要关注 IP 对应位为 1 的部分。

#### 5.4.4 子网划分

子网划分是**借用 IP 地址的若干主机位充当子网位**，从而将原网络划分为若干子网。借用的主机位越多，子网数目越多，而每个子网中的可用主机数越少。

以 C 类网络为例：原有 8 位主机位（2⁸ = 256 个地址），默认子网掩码 255.255.255.0。借用 1 位主机位 → 产生 2 个子网，每个子网 2⁷ − 2 = 126 个可用主机地址；借用 2 位 → 产生 4 个子网，每个子网 2⁶ − 2 = 62 个可用主机地址……每个子网中，**第一个 IP（主机部分全 0，网络地址）和最后一个 IP（主机部分全 1，广播地址）不能分配给主机**，所以每个子网的可用 IP 数 = 总地址数 − 2。

> **示例**：将 B 类网络 `135.41.0.0/16` 划分为 20 个能容纳 200 台主机的子网。
>
> **方式一：从主机数出发**
>
> 1. 每个子网需要容纳 200 台主机，加上网络地址和广播地址，共需 202 个地址。
> 2. 由 `2^n − 2 ≥ 202` 得 n = 8（2⁸ − 2 = 254 ≥ 202），即主机位需要 8 位。
> 3. 原掩码 /16，主机位占 8 位 → 网络前缀 = 32 − 8 = 24，新子网掩码为 **/24**（255.255.255.0），每个子网可容纳 254 台主机，满足需求。
>
> **方式二：从子网数量出发**
>
> 1. 需要 20 个子网。
> 2. `2⁴ = 16 < 20 ≤ 2⁵ = 32`，所以需要**借用 5 位主机位**作为子网位。
> 3. 新子网掩码为 /16 + 5 = **/21**，每个子网有 2¹¹ − 2 = 2046 台可用主机（满足 200 台的需求）。
>
> 两种方式都能满足需求，实际规划时取两者中更合理（不浪费地址）的方案。

#### 5.4.5 CIDR 无类域间路由

CIDR **抛弃分类编址**，采用**斜线记法 a.b.c.d/n**，n 为网络前缀位数；CIDR 把前缀相同的连续地址聚合为地址块，**路由聚合（构成超网）**大幅缩减路由表。

- 地址块内地址数 = 2^(32−n)，可用主机数 = 2^(32−n) − 2；地址块的网络地址主机位全 0，广播地址主机位全 1。
- **最长前缀匹配原则**：路由器将目的 IP 与路由表中各条目逐位比对（先用各条目掩码做与运算再比较），有多条匹配时选**前缀最长**（最具体）的条目。例如目的地址 192.168.1.5 同时匹配 192.168.0.0/16 与 192.168.1.0/24 时，选 /24 条目。

### 5.5 IPv4 数据报格式与分片

#### 5.5.1 IPv4 数据报格式（首部 20~60 字节）

| 字段 | 位数 | 说明 |
| --- | --- | --- |
| 版本 | 4 | IP 协议版本（IPv4 = 4） |
| 首部长度 | 4 | 单位为 4 字节，最大 60 B（1111） |
| 区分服务 | 8 | 一般不使用；现用作 DSCP/QoS 标记 |
| 总长度 | 16 | 首部 + 数据，最大 65535 B |
| 标识 | 16 | 计数器产生，同一数据报的所有分片标识相同 |
| 标志 | 3 | MF=1 表示后面还有分片；DF=1 表示不允许分片 |
| 片偏移 | 13 | 单位为 8 字节，表示本片数据在原分组中的相对位置 |
| 生存时间 TTL | 8 | 每经过一个路由器减 1，减到 0 丢弃（防止环路） |
| 协议 | 8 | 上层协议号（TCP=6、UDP=17、ICMP=1、OSPF=89） |
| 首部校验和 | 16 | 只校验首部，逐跳重新计算（数据部分不校验） |
| 源/目的地址 | 32+32 | 发送方与接收方 IP 地址 |
| 选项 + 填充 | 可变 | 安全、源路由、记录路由、时间戳等 |

#### 5.5.2 IP 分片

- 分片原因：数据报长度大于链路的 **MTU**（以太网 1500 B）；分片可在源端和中间路由器进行，但**只在目的端重组**（重组依据：标识 + 片偏移 + MF 标志）。
- 计算要点：**片偏移以 8 字节为单位**，除最后一片外每片数据长度必须是 8 的倍数；总长度指每片的首部 + 数据。
- 例：总长 3820 B（数据 3800 B）的数据报在 MTU = 1420 的链路上分片：每片数据最多 1400 B → 共 4 片，片偏移分别为 0、175、350、475（1400/8 = 175）。
- IPv6 不允许中间路由器分片，只能在源端进行（配合路径 MTU 发现）。
### 5.6 配套协议：ARP、DHCP、ICMP、NAT

#### 5.6.1 ARP（地址解析协议）

作用：已知同网段目的主机的 **IP 地址**，求其 **MAC 地址**，确保数据帧能够在局域网中正确传输。

流程：

1. 先查本机 **ARP 缓存**（IP ↔ MAC 映射表）。
2. 未命中则向本地网段**广播 ARP 请求**（含源 IP、源 MAC、目的 IP）。
3. 网络中所有主机收到请求后检查目的 IP 是否与自己一致：不一致则忽略；一致则把自己的 MAC 地址**单播**回送 ARP 响应，并顺带学习发送方的 IP-MAC 映射（已有则覆盖）。
4. 源主机收到响应后，把目的 IP-MAC 加入 ARP 缓存（有超时时间），开始传输数据。若一直收不到响应，说明 ARP 查询失败。

**跨网段通信**：先通过 ARP 获得**默认网关（路由器）的 MAC 地址**，把帧发给网关，由路由器逐跳转发。注意：**IP 地址始终是最终的源/目的地址，而 MAC 地址逐链路更换**。

#### 5.6.2 DHCP（动态主机配置协议）

DHCP（Dynamic Host Configuration Protocol）是一个**应用层协议**（基于 UDP，服务器 67 端口、客户机 68 端口）。当把客户主机的 IP 设置为"自动获取"时，DHCP 服务器会根据 DHCP 协议给客户端分配 IP，使客户机能够上网。**家庭路由器的"DHCP 服务器"功能就是给手机、电脑自动分配 192.168.x.x 地址**。

四步交互（DORA）：

1. **Discover**：客户端广播寻找 DHCP 服务器。
2. **Offer**：服务器广播（或单播）提供可用 IP。
3. **Request**：客户端广播选择某一服务器的地址。
4. **ACK**：被选服务器确认分配（含 IP 地址、子网掩码、默认网关、DNS 服务器、租期）。

> 新加入的主机通过 DHCP 可获得四类信息：**本机 IP、子网掩码、默认网关地址、DNS 服务器地址**。

#### 5.6.3 ICMP（互联网控制报文协议）

ICMP 是 TCP/IP 协议族的一个子协议，用于在 IP 主机、路由器之间传递**控制消息**——"网络通不通、主机是否可达、路由是否可用"等网络本身的消息。这些控制消息虽然不传输用户数据，但对用户数据的传递起着重要作用。ICMP 报文封装在 IP 数据报中（协议号 1）。

- **差错报告报文**：终点不可达（网络/主机/端口/协议不可达）、超时（TTL=0，**traceroute 即利用此机制**）、参数问题、改变路由（重定向）。
- **询问报文**：回送请求/回答（**ping 的原理**）、时间戳请求/回答。
- 报文前 4 字节统一为：类型、代码、校验和。

> **常见误区修正**：`ping` 命令使用的是 **ICMP 回送请求/回答报文**（封装在 IP 之上），**不是 UDP 数据包**。`ping` 通说明本机到目标主机的 IP 层路径可达。

#### 5.6.4 NAT / NAPT（网络地址转换）

- 出向数据报：用 NAT 路由器的**公网 IP + 新端口号**替换源私有 IP + 端口号，并记录到 NAT 转换表；入向数据报查表反向替换。
- 依靠 16 位端口号，一个公网地址可支持约 60000 个并行连接（NAPT 端口级复用）。
- 优点：缓解 IPv4 短缺、隐藏内网结构提升私密性；缺点：破坏端到端原则，外部无法主动访问内网（需要端口映射/UPnP/打洞等技术）。

> **RARP（反向地址解析协议）**：根据 MAC 地址查找 IP 地址（与 ARP 相反），历史上用于获取无盘工作站的 IP。**该协议已被 BOOTP/DHCP 取代，现已淘汰**，了解即可。

#### 5.6.5 IPSec（网络层安全协议）

**隧道协议中工作在网络层的是 IPSec**，用于在 IP 层提供认证（AH）与加密（ESP）服务，是 VPN 的重要实现技术（详见 5.11）。

### 5.7 IPv6

为了扩大地址空间，IPv6 重新定义了地址空间：**IPv4 采用 32 位地址长度，IPv6 采用 128 位地址长度**，几乎可以不受限制地提供地址（约 3.4×10³⁸ 个）。

IPv6 的主要优势：

1. **更大的地址空间**：128 位地址，彻底解决 IPv4 地址枯竭问题。
2. **更小的路由表**：地址分配一开始就遵循聚类原则，路由器能用一条记录表示一片子网，大大减小路由表长度，提高转发速度。
3. **增强的组播与流控制**：支持组播（Multicast）与流标签（Flow Label），为服务质量（QoS）控制提供了良好平台，有利于多媒体应用。
4. **自动配置（SLAAC）**：无状态地址自动配置，是对 DHCP 的改进和扩展，使网络（尤其是局域网）管理更方便快捷。
5. **更高的安全性**：内置对网络层数据的加密与鉴别（IPSec），极大增强了网络安全性。
6. **基本首部固定 40 字节**：取消首部校验和（减轻逐跳处理负担），选项功能移入**扩展首部**（逐跳、路由、分片、认证 AH、封装安全载荷 ESP 等）。
7. **不允许中间路由器分片**：只允许源端分片（配合路径 MTU 发现）。

**地址表示**：冒号十六进制，8 组 16 位。

> **IPv6 省略写法**：
>
> 1. **去除前导零**：每个 16 位组中前导的零可以省略。例如 `2001:0db8:0000:0000:0000:0000:0000:0001` 可简化为 `2001:db8:0:0:0:0:0:1`。
> 2. **双冒号 ::**：用 `::` 代替**连续的零组**，但整个地址中只能使用一次。例如 `2001:0db8:0000:0000:0000:0000:0000:0001` 可简化为 `2001:db8::1`。

**地址类型**：**单播**（含链路本地 fe80::/10、全球单播 2000::/3）、**多播**（ff00::/8，取代广播）、**任播**（anycast，发给组内"最近"成员）。

**过渡技术**：**双栈**（节点同时运行 IPv4/IPv6）、**隧道**（IPv6 分组封装在 IPv4 中穿越 IPv4 网络）、**翻译**（NAT64/DNS64 地址族转换）。

### 5.8 路由协议：RIP、OSPF、BGP

#### 5.8.1 RIP（基于距离向量，域内）

- 以**跳数**为度量，每经过一个路由器跳数加 1；最大跳数 **15**，16 即不可达（限制了网络规模 ≤ 15 跳）。
- 仅与**相邻路由器**交换**完整路由表**，周期 **30 秒**；触发更新加快收敛。
- 特点：实现简单、收敛慢、交换信息量大，适合**中小型网络**。

#### 5.8.2 OSPF（基于链路状态，域内）

- 每台路由器泛洪 **LSA（链路状态通告）**，全网维护一致的链路状态数据库，用 **Dijkstra** 算法计算最短路径；度量可为带宽、时延等（默认代价与带宽相关）。
- **划分区域**：主干区域 Area 0 + 其他区域，区域间路由经区域边界路由器（ABR）汇总，抑制泛洪范围、缩小路由表。
- 链路状态数据库同步后只更新变化部分（增量化），**收敛快、无环、支持验证与 VLSM/CIDR**。
- 五种分组类型：Hello（发现/维持邻居）、DD（数据库描述）、LSR（链路状态请求）、LSU（链路状态更新）、LSAck。
- 广播网络上选举 **DR（指定路由器）/BDR**，减少邻接关系数量。
- 直接封装在 IP 上（协议号 89）；与 RIP 对比：收敛快、适合大型网络、协议更复杂、资源开销更大。

#### 5.8.3 BGP（路径向量，域间）

- 目前互联网**唯一在用的 AS 间路由协议**；基于**策略**而非单纯最优度量（商业合同、安全考虑）。
- **eBGP**：从相邻 AS 获取网络可达信息；**iBGP**：把可达信息传播到 AS 内部路由器；基于可达信息与策略选择"最优"路径。
- BGP 会话建立在 **TCP 连接（179 端口）**之上；通告内容是到达各网络前缀的 **AS 路径**（如 AS2, AS3, X），收到通告的 AS 检查自身是否已在路径中以防环（路径中含自身则拒绝）。
- 路由器可能学到多条路径，由**本地策略**选择并向内/外通告。

### 5.9 路由器：组成与工作原理

> 通过路由器可以把两个或多个计算机网络互相连接起来，形成更大规模的计算机网络（互连网）。**家用路由器 = 路由器 + 交换机 + NAT + DHCP 等其他功能的一体化设备**。

路由器处在**网络层**，是连接因特网中各局域网、广域网的设备，**会根据路由表选择最佳路径，按顺序转发数据包**。

路由器通过 IP 数据包中 IP 地址的**网络号**识别网络，所以为保证数据包路由正确，**每个网络都必须有唯一的网络号**。路由器使用 IP 地址区分不同设备，最终通信还需要 MAC 地址（通过 ARP 解析）。

- **路由表**：记录 IP 地址与端口的映射关系，指导数据包的转发。
- **IP 地址管理**：随着 IPv4 地址的耗尽，路由器的管理与分配（配合 NAT）显得尤为重要。

> 路由器与广域网连接的端口称为 **WAN 端口**（接光猫/运营商线路），与局域网连接的端口称为 **LAN 口**（接电脑/交换机）。家用路由器上标注 WAN/LAN 的网口就是这个区别。

#### 5.9.1 路由表与转发的完整流程

- **控制平面**：运行路由协议（RIP/OSPF/BGP），结合静态路由、直连路由，按**路由优先级**（数值越小优先级越高）选出最佳路由构成核心路由表，并下发为**转发表（FIB）**。
- **数据平面**转发流程：
  1. 链路层解封装，校验 IP 首部；
  2. 提取目的 IP，按**最长前缀匹配**查找转发表；未命中则丢弃；
  3. TTL 减 1、重算首部校验和；
  4. 重新链路层封装（新 MAC：下一跳 MAC / 目的 MAC），从输出接口发送。
- 转发过程中路由器**不查看传输层及以上内容**。
- **路由器内部结构**：输入端口（线路端、数据平面查找）、**交换结构**（内存交换、总线交换、纵横制 crossbar 互联网络三种典型结构）、输出端口（排队与调度、封装发送）；输入/输出排队过大产生拥塞甚至丢包。
- **路由表 vs 转发表**：路由表由路由协议生成（控制面），转发表由路由表派生（数据面），面向硬件优化。

### 5.10 拥塞控制与 QoS

#### 5.10.1 拥塞控制

- 拥塞：网络中分组过多导致时延增大、丢包、吞吐量下降；是**全局性**问题（对比：流量控制是端到端的局部问题）。
- **开环控制**（预防式）：事先协商参数，运行期不变，不考虑当前网络状态。
- **闭环控制**（反馈式）：监测（丢包率、排队时延）→ 反馈 → 调整，分为**显式反馈**与**隐式反馈**（端系统推断，如 TCP 拥塞控制）。
- **抑制包**：路由器向拥塞分组的源主机回送告警，源降低发送速率；**逐跳抑制包**在沿途每个路由器都起作用，见效快但要求上游路由器有更大缓冲区。
- **显式拥塞通告（ECN）**：IP 首部 DSCP 中的 2 位 ECN 域（00 不支持；01/10 支持；11 经历拥塞），由接收方在 ACK 中回传给发送方。
- **随机早期检测（RED）**：维护平均队列长度，与最小门限、最大门限比较：小于最小门限则入队；大于最大门限则丢弃；介于两者之间按概率丢弃，防止队列满后"全局同步"式的尾部丢弃。

#### 5.10.2 QoS 服务质量

- 可量化指标：**带宽、时延、抖动、丢包率**；互联网只提供尽力而为服务，实时业务需要额外保障。
- **流量整形**：
  - **漏桶算法**：恒定速率 r 输出、桶容量 b，平滑突发，输出严格受限（不允许突发）。
  - **令牌桶算法**：以速率 r 生成令牌（桶满则丢弃令牌），报文需消耗相应数量的令牌才能发送；**允许累积令牌应对短时突发**，更友好。
- **分组调度算法**：先进先出 FIFO（FCFS）、公平队列 FQ（各流轮流）、**加权公平队列 WFQ**（按权重分配带宽）、优先级调度（高优先级队列优先，可能饿死低优先级）。

### 5.11 三层交换、组播、移动 IP 与 VPN

- **三层交换**：利用 IP 层信息加强二层交换，交换芯片"一次路由、多次交换"（路由一次、交换其后），融合 VLAN 间路由，解决传统路由器转发瓶颈，简化网络拓扑。
- **IP 组播**：一对多通信只发送一份数据，沿途路由器按需复制；使用 **D 类地址 224.0.0.0~239.255.255.255**（前缀 1110）；组播 MAC 地址由 IP 低 23 位映射到 01-00-5E-xx-xx-xx；主机用 **IGMP 协议**告知本地路由器加入/退出组播组，路由器间运行组播路由协议（PIM 等）构建组播分发树。
- **移动 IP**：移动主机跨网段移动时保持 IP 不变的通信技术；核心实体：**本地代理（HA）、外部代理（FA）、转交地址（COA）**；通信对端发往归属地址，HA 通过**隧道**把分组转发到 COA，再交给移动节点；反向直接发送（存在三角路由问题）。
- **VPN**：利用**隧道技术**在公共网络上模拟点到点逻辑专线，结合加密与验证实现专用网络的经济可靠延伸；网络层隧道协议为 **IPSec**（AH 认证 / ESP 加密）；SSL/TLS VPN 则工作在传输层之上。典型场景：企业员工在外通过 VPN 接入公司内网。

## 六、传输层

传输层是**进程到进程（端口到端口）**的端到端逻辑通信层——网络层只把分组送达主机，传输层才把数据交付给主机上正确的应用程序。

### 6.1 传输层的功能与端口

- **复用**：发送方多个应用进程共用同一个传输层协议；**分用**：接收方根据**端口号**把数据交付给正确的进程。
- 端口号 16 位（0~65535）：
  - **熟知端口 0~1023**：FTP 20/21、SSH 22、Telnet 23、SMTP 25、DNS 53、HTTP 80、POP3 110、HTTPS 443。
  - **登记端口 1024~49151**：供应用程序注册使用。
  - **短暂端口 49152~65535**：客户端临时使用（发起连接时的源端口）。
- **套接字 Socket = (源 IP : 源端口, 目的 IP : 目的端口)**，唯一标识一条连接。

### 6.2 UDP 协议

UDP 提供的是一种**非面向连接、不可靠**的数据传输服务，主要适用于需要**更快速传输**、对丢包不敏感的应用（实时音视频、DNS 查询等）。

UDP 的特点：

- **无连接**：传输数据前源端和目的端不建立连接，想传就传，尽可能快地把数据"扔"到网络上。发送速度只受应用程序生成数据的速度、计算机能力和传输带宽限制；接收端把每个消息段放入队列，应用程序每次从队列中读一个消息段。
- **开销小**：不需要维护连接状态，一台服务器可同时向多个客户端传输相同消息；**UDP 首部只有 8 字节**，而 TCP 首部至少 20 字节。
- **无拥塞控制**：吞吐量不受拥塞控制算法调节，只受应用生成数据的速率、传输带宽和主机性能限制。
- **尽最大努力交付**：不保证可靠交付，主机不需要维持复杂的连接状态表。
- **面向报文**：发送方的 UDP 对应用程序交下来的报文，添加首部后直接向下交付给 IP 层，**既不拆分也不合并**，保留报文边界，因此应用程序需要选择合适的报文大小。

**UDP 首部结构**：源端口(16 位) + 目的端口(16 位) + 长度(16 位) + 校验和(16 位)。

**UDP 校验**：计算时增加 12 字节**伪首部**（源 IP、目的 IP、0、17、UDP 长度），伪首部只参与计算、不参与传输，用于校验 IP 地址是否正确；UDP 校验和是可选的。

**典型应用**：DNS、DHCP、RIP、SNMP、实时音视频（VoIP、视频会议）、TFTP 等。

> **TCP 与 UDP 的区别**：
>
> 1. TCP 基于连接，UDP 无连接。
> 2. 对系统资源的要求：TCP 较多，UDP 较少。
> 3. UDP 程序结构较简单。
> 4. TCP 是流模式，UDP 是数据报模式。
> 5. TCP 保证数据正确性与顺序，UDP 可能丢包、不保证顺序。
>
> 浏览网页使用 HTTP（搭载在 TCP 之上）；Telnet/SSH 是 TCP/IP 协议族中的远程登录协议；**VoIP**（IP 电话）指在 IP 网络上以数据包方式传输语音，使用 UDP 协议。
>
> **常见误区修正**：`ping` 命令使用的是 **ICMP** 协议（封装在 IP 之上），既不是 UDP 也不是 TCP。

### 6.3 TCP 协议

TCP 向下屏蔽 IP 协议的不可靠传输特性，向上提供一种**面向连接的、可靠的点到点数据传输**服务。TCP 在可靠性和安全性上更有保证。

> TCP 是面向连接的协议：在收发数据前，必须和对方建立可靠的连接。一个 TCP 连接必须经过**三次"对话"**才能建立。简单描述：
>
> - 第一次对话：主机 A 向主机 B 发出连接请求数据包——"我想给你发数据，可以吗？"
> - 第二次对话：主机 B 向主机 A 发送同意连接和要求同步的数据包——"可以，你什么时候发？"（同步就是两台主机一个在发送、一个在接收，协调工作）
> - 第三次对话：主机 A 再发出一个数据包确认主机 B 的要求——"我现在就发，你接着吧！"
>
> 三次对话的目的是使数据包的发送和接收同步。经过三次对话之后，主机 A 才向主机 B 正式发送数据。此外，**TCP 要求接收方确认；如果在某个时限内没有收到确认，TCP 将重新发送数据包**。

#### 6.3.1 TCP 报文段格式（首部 20~60 字节）

| 字段 | 位数 | 说明 |
| --- | --- | --- |
| 源端口 / 目的端口 | 16+16 | 标识应用进程 |
| **序号 seq** | 32 | 本报文段数据第一个字节的编号（字节流编号） |
| **确认号 ack** | 32 | 期望收到对方的下一个字节编号（= 最后一个正确字节 + 1），隐含累积确认 |
| 数据偏移 | 4 | 即首部长度，单位 4 字节 |
| 标志位 | 6 | **URG**（紧急指针有效）、**ACK**（确认号有效，连接建立后恒为 1）、**PSH**（尽快上交应用）、**RST**（复位连接）、**SYN**（请求建立连接）、**FIN**（请求释放连接） |
| 窗口 | 16 | 接收窗口 rwnd，流量控制依据 |
| 校验和 | 16 | 含伪首部（协议号为 6），检验首部 + 数据，强制使用 |
| 紧急指针 | 16 | URG=1 时有效，指出紧急数据末尾 |
| 选项 | 可变 | 如 MSS（最大报文段长度，典型值 = MTU − 40 = 1460 B）、窗口扩大、时间戳、SACK |

TCP 面向**字节流**（不保留报文边界，可能出现"粘包"，需要应用层自己划分消息边界）；全双工、点对点（不支持多播/广播）。

#### 6.3.2 TCP 连接管理：三次握手

1. **第一次**：客户端发送 **SYN=1, seq=x** 的连接请求报文段（消耗一个序号），进入 SYN-SENT 状态。
2. **第二次**：服务器回复 **SYN=1, ACK=1, seq=y, ack=x+1**（SYN+ACK），进入 SYN-RCVD 状态。
3. **第三次**：客户端发送 **ACK=1, seq=x+1, ack=y+1**（可携带数据），双方进入 ESTABLISHED 状态。

**为什么必须三次握手**：

- 防止**失效的历史连接请求**突然到达服务器造成资源浪费与错误连接（若只有两次握手，服务器会直接建立连接并等待数据）。
- 双方都需要确认"自己的发送和接收能力都正常"，并同步彼此的初始序号（ISN）。

**SYN 洪泛攻击与防御**：攻击者伪造源地址大量发送 SYN 报文占满半连接队列。防御手段：SYN Cookie（不保存半连接状态，把状态编码进 SYN-ACK 的序号中）、缩短超时、增大半连接队列等。

#### 6.3.3 TCP 连接释放：四次挥手

1. **第一次**：客户端发送 **FIN=1, seq=u**，请求关闭（进入 FIN-WAIT-1）。
2. **第二次**：服务器回复 **ACK=1, ack=u+1**（半关闭：客户端→服务器方向关闭，服务器仍可发数据），服务器进入 CLOSE-WAIT，客户端进入 FIN-WAIT-2。
3. **第三次**：服务器数据发完后发送 **FIN=1, ACK=1, seq=w, ack=u+1**（进入 LAST-ACK）。
4. **第四次**：客户端回复 **ACK=1, ack=w+1**，进入 **TIME-WAIT**，等待 **2MSL**（报文段最大生存时间的两倍）后关闭；服务器收到 ACK 即关闭。

**为什么四次而非三次**：TCP 全双工，两个方向要分别关闭；中间的 ACK 与 FIN 通常分开发送（服务器可能还有数据要发）。

**TIME-WAIT 等待 2MSL 的原因**：① 保证最后一个 ACK 能到达对方（若 ACK 丢失，对方会重传 FIN，可以再次确认）；② 让本连接的所有报文在网络中消逝，避免污染新建的相同四元组连接。

> **排障提示**：`netstat` 看到大量 **CLOSE_WAIT** 通常意味着应用程序未调用 `close()`（代码缺陷）；大量 **TIME_WAIT** 是主动关闭方频繁创建短连接所致，可通过长连接/连接复用缓解。

#### 6.3.4 TCP 可靠传输机制

- **序号与确认**：字节级编号 + 累积确认，保证按序、不重、不丢。
- **超时重传**：发送后启动定时器，超时未确认则重传。超时时间 RTO 基于 RTT 自适应估计：RTO = RTTᵤ + 4·RTT_D（加权平均偏差），其中 RTTᵤ = (1−α)·RTTᵤ + α·SampleRTT（RFC 6298，推荐 α = 1/8）。
- **快速重传**：接收方失序时**重复确认**最后按序到达的字节；发送方收到 **3 个冗余 ACK** 即立即重传缺失报文段，无需等待超时（配合快恢复使用）。
- **校验**：首部 + 数据 + 伪首部校验和，发现差错直接丢弃（静默丢弃，靠重传恢复）。

#### 6.3.5 TCP 流量控制

- 目的：**匹配发送方速率与接收方处理速率**，防止接收缓存溢出（点对点问题，与拥塞控制不同）。
- 机制：接收方在每个 ACK 中用**窗口字段 rwnd** 通告接收缓存剩余量；发送方保证"已发送未确认"的字节数 ≤ rwnd（**滑动窗口**）。
- **零窗口与坚持定时器**：rwnd=0 时发送方暂停发送，但周期性发送**零窗口探测报文**，防止接收方恢复窗口的通告丢失导致双方互相死等。
- **糊涂窗口综合症**：为避免每次只通告/发送几个字节的低效情况，接收方可等缓存增至 MSS/2 再通告，发送方可采用 **Nagle 算法**攒够 MSS 再发。

#### 6.3.6 TCP 拥塞控制（发送窗口 = min(rwnd, cwnd)）

- **慢启动（Slow Start）**：连接建立初期 cwnd = 1 MSS，每收到一个 ACK 则 cwnd 加 1（**每个 RTT 翻倍**，指数增长），直到达到阈值 ssthresh。
- **拥塞避免（Congestion Avoidance）**：cwnd ≥ ssthresh 后，每个 RTT 内 cwnd **线性加 1**（加法增大，AIMD 的"AI"）。
- **超时事件**（重度拥塞）：ssthresh = cwnd/2，cwnd 重置为 **1 MSS** 重新慢启动（乘法减小，"MD"）。
- **快速重传 + 快速恢复**（收到 3 个冗余 ACK，轻度拥塞）：立即重传丢失报文；ssthresh = cwnd/2，**cwnd = 新 ssthresh**（不回到 1），进入拥塞避免线性增长。
- 目标：拥塞窗口始终围绕理想带宽附近波动；AIMD 保证公平性与效率。
- **现代算法演进**：**CUBIC**（三次函数窗口增长，Linux 默认）、**BBR**（基于带宽与 RTT 建模而非丢包信号，Google 提出，减少缓冲膨胀）。

### 6.4 TCP 与 UDP 全面对比

| 对比项 | TCP | UDP |
| --- | --- | --- |
| 连接 | 面向连接（三次握手） | 无连接 |
| 可靠性 | 可靠交付、按序、不丢不重 | 尽最大努力交付 |
| 传输单位 | 面向字节流 | 面向报文（保留边界） |
| 拥塞/流量控制 | 有（cwnd / rwnd） | 无 |
| 首部开销 | 20~60 字节 | 8 字节 |
| 通信方式 | 一对一 | 一对一、一对多、多对一、多对多 |
| 典型应用 | HTTP/HTTPS、FTP、SMTP、SSH | DNS、DHCP、VoIP、视频直播、游戏、QUIC |

## 七、应用层

应用层是体系结构的最高层，直接面向用户，为应用程序提供网络服务。

### 7.1 网络应用模型

- **客户/服务器（C/S）模型**：服务器常驻、拥有固定地址、可扩展为服务器集群；客户端主动发起、间歇接入。易管理，但服务器易成性能瓶颈与攻击目标。
- **P2P 对等模型**：节点对等，既是客户端又是服务器（对等方）；自扩展性强（每个新节点既消耗也贡献资源）、成本低、去中心化；管理难，存在版权与安全挑战。
- **混合模型**：如即时通信（中心服务器管理在线状态，用户间直接传消息）。

### 7.2 DNS 域名系统

DNS（Domain Name System）是**域名与 IP 地址相互映射**的**分布式、层次化数据库**系统。每一个域名都对应一个唯一的 IP 地址，DNS 负责完成解析，让用户通过友好的名称访问计算机和服务，是互联网的核心服务。使用 **UDP 53 端口**（区域传送用 TCP）。

> 只要是通过权威部门授权的服务商，都可以把域名绑定解析到他们的 DNS 上。

#### 7.2.1 层次域名空间

以 `www.cs.tsinghua.edu.cn` 为例，从右向左依次为：根 → 顶级域 cn（国家/通用顶级域 com、org、net、edu 等）→ 二级域 edu.cn → … → 主机名 www。

#### 7.2.2 域名服务器层次

- **根域名服务器**：知道所有顶级域服务器的地址（全球 13 个逻辑编号，经 Anycast 镜像扩展）。
- **顶级域名（TLD）服务器**：管理 .com/.cn 等下的权威服务器。
- **权威域名服务器**：拥有某区域内域名的最终解析记录。
- **本地域名服务器（递归解析器）**：主机的"代理"，由 ISP 或公共 DNS（114.114.114.114、8.8.8.8）提供。

#### 7.2.3 域名解析过程（以查询 www.example.com 为例）

1. 检查**浏览器缓存** → **操作系统 hosts 文件**与本地 DNS 缓存 → 命中直接返回。
2. 向**本地域名服务器**发起查询：
   - **递归查询**（主机 → 本地服务器）：本地服务器必须给出最终答案；
   - **迭代查询**（本地服务器 → 各级服务器）：本地服务器依次问根 → 根返回 TLD 地址 → 问 TLD → 返回权威地址 → 问权威 → 得到最终 IP。
3. 结果沿原路返回并在各级缓存（TTL 控制），向主机回送。

#### 7.2.4 资源记录（RR）

`(Name, Value, Type, TTL)`；类型：**A**（域名→IPv4）、**AAAA**（域名→IPv6）、**CNAME**（别名→规范名）、**NS**（域的权威服务器）、**MX**（邮件服务器）、**PTR**（IP→域名，反向解析）。

> **安全补充**：DNS 劫持/污染是常见安全问题；**DoH（DNS over HTTPS）/ DoT（DNS over TLS）**通过加密 DNS 查询防止窃听与篡改（现代浏览器、公共 DNS 均已支持）。

### 7.3 WWW 与 HTTP

#### 7.3.1 WWW 的概念与组成

WWW（万维网）三要素：**URL（统一资源定位符）**（协议://主机:端口/路径）、**HTML**（超文本标记语言）、**HTTP**（超文本传输协议）；浏览器向服务器发起请求并渲染响应。

#### 7.3.2 HTTP 协议

HTTP 是互联网上应用最广泛的应用层协议，是客户端和服务器之间请求和应答的标准（基于 TCP），用于从 WWW 服务器传输超文本到本地浏览器。

**HTTP 报文**：

- 请求报文：请求行（方法 + URL + 版本）、首部字段（Host、User-Agent、Cookie、Content-Type 等）、空行、请求体。
- 响应报文：状态行（版本 + 状态码 + 短语）、首部、空行、响应体。

**常见方法**：**GET**（获取资源，幂等）、**POST**（提交数据，非幂等）、PUT（替换资源）、DELETE（删除）、HEAD（只要首部）、OPTIONS。

**状态码分类**：**1xx 信息**、**2xx 成功**（200 OK、204 无内容）、**3xx 重定向**（301 永久、302 临时、304 缓存有效）、**4xx 客户端错误**（400、401、403、**404 Not Found**）、**5xx 服务器错误**（500、502、503）。

**无状态与 Cookie/Session**：HTTP 本身无状态；**Cookie**（服务器通过 Set-Cookie 下发，浏览器每次请求自动携带）实现会话跟踪（登录态、购物车）；**Session** 把状态存在服务器端，靠 Cookie 中的 SessionID 关联。Cookie 涉及隐私问题（第三方 Cookie 追踪，现代浏览器已逐步禁用）。

**HTTP 版本演进（对照当前使用）**：

- **HTTP/1.0**：每次请求新建 TCP 连接。
- **HTTP/1.1**：默认**持久连接（keep-alive）**+ 流水线（pipelining）；存在**队头阻塞**（同一连接上响应必须按序返回）。目前仍是大量网站的默认协议。
- **HTTP/2**：**二进制分帧 + 多路复用**（一条连接并行多个流，解决应用层队头阻塞）、**首部压缩（HPACK）**、服务器推送；但 TCP 层丢包仍会阻塞所有流（TCP 队头阻塞）。主流网站普遍支持。
- **HTTP/3**：放弃 TCP，基于 **QUIC**（UDP 上实现的可靠传输 + TLS 1.3 内置加密）：0-RTT 快速建连、连接迁移（Connection ID 适配网络切换，如 Wi-Fi→5G）、彻底解决传输层队头阻塞。Google、Meta 等大型服务已大规模部署。

### 7.4 HTTPS 与 TLS

HTTPS = HTTP + **TLS**（传输层与应用层之间的安全层），默认端口 443，需要 CA 机构颁发的证书。

**安全目标**：**机密性**（对称加密，如 AES）、**完整性**（哈希/MAC）、**身份认证**（证书 + 数字签名）、**防篡改防窃听**。

**TLS 握手简化过程**：客户端 Hello（支持的密码套件、随机数）→ 服务器返回**证书**（含服务器公钥）+ 随机数 → 客户端验证证书链后用服务器公钥加密预主密钥（或 ECDHE 密钥交换）发送 → 双方基于随机数与预主密钥派生**会话密钥** → 之后所有应用数据用会话密钥对称加密。

即"**非对称加密交换密钥，对称加密传输数据**"，兼顾安全与性能。

**HTTP 与 HTTPS 对比**：

- HTTP 是明文传输，HTTPS 是加密传输（对数据加密并建立信息安全通道）。
- HTTP 标准端口 80，HTTPS 标准端口 443。
- 在 OSI 模型中，HTTP 工作于应用层，HTTPS 的安全传输机制工作在传输层之上。
- HTTP 无需证书，HTTPS 需要 CA 颁发的 SSL/TLS 证书，并对服务器进行**真实身份认证**。
- HTTPS 更安全，对**搜索引擎更友好（利于 SEO）**；浏览器对 HTTPS 站点显示绿色安全锁。

### 7.5 FTP 文件传输协议

FTP 是文件传输协议，基于 TCP；**控制连接（21 端口，全程保持）与数据连接（按需建立）分离**，控制信息带外传送。FTP 有两种工作方式：

- **PORT（主动）方式**：客户端向服务器的 FTP 端口（默认 21）发送连接请求，建立命令链路。需要传送数据时，**客户端在命令链路上用 PORT 命令告诉服务器**"我打开了 XXXX 端口，你过来连接我"，于是服务器从 20 端口主动连接客户端的 XXXX 端口，建立数据链路。
- **PASV（被动）方式**：客户端先建立命令链路。需要传送数据时，**服务器在命令链路上用 PASV 命令告诉客户端**"我打开了 XXXX 端口，你过来连接我"，于是客户端主动连接服务器的 XXXX 端口建立数据链路。

> **使用场景**：客户端处于 NAT/防火墙之后（无法被服务器主动连接）时，应使用 **PASV 被动模式**——这也是浏览器/下载工具默认被动模式的原因。匿名 FTP 使用用户名 anonymous。

### 7.6 电子邮件系统

电子邮件系统组成：**用户代理 UA**（Outlook、Foxmail 等，撰写/读取邮件）、**邮件服务器**（含用户邮箱与报文队列）、**协议**（发送用 SMTP，收取用 POP3/IMAP，Webmail 走 HTTP）。

- **SMTP（25 端口，TCP 推协议）**：用户代理 → 发送服务器、服务器间转发都靠"推"；只能传输 ASCII 文本，因此需要 **MIME（多用途互联网邮件扩展）**把二进制/多媒体编码为 ASCII 再传输（Base64 等）。
- **POP3（110 端口，拉协议）**：适用于 **C/S 结构的脱机模型**——允许用户把服务器上的邮件下载到本地主机，同时可删除服务器上的邮件，支持离线阅读，是因特网电子邮件最早的离线标准。**电子邮件传输建立的是可靠连接，所以采用 TCP 连接**。
- **IMAP（143 端口）**：邮件保留在服务器，支持多设备同步、文件夹管理、部分收取；Webmail（163、Gmail 网页版）实质走 HTTPS/HTTP。
- 依赖 DNS 的 **MX 记录**定位收件方邮件服务器；垃圾邮件治理：SPF/DKIM/DMARC。

> **现代使用提示**：SMTP 发送邮件到邮件服务器时，提交端口通常使用 **587（提交 Submission）**，465 为 SMTPS（SSL 加密）；25 端口主要用于服务器之间的中继转发。

### 7.7 流媒体与内容分发网络（CDN）

- **流媒体存储与播放**：音视频经压缩编码（如 H.264/H.265、AAC）分块存储，客户端**边下边播**（应用层缓冲几秒以平滑网络抖动）。
- **DASH（基于 HTTP 的动态自适应流）**：同一视频编码为多档码率，服务器提供 manifest（MPD）清单，客户端实时测量带宽，动态请求合适码率的分块——**客户端自适应**（client-driven）。
- 辅助协议：**RTP**（实时传输，承载媒体数据，常跑在 UDP 上）、**RTCP**（质量反馈，配合 RTP）、**RTSP**（流控制"遥控器"，PLAY/PAUSE）。
- **CDN 工作原理**：
  - 在网络边缘部署大量缓存服务器，把内容复制到离用户最近的地方，缓解源站压力、降低时延、抗拥塞。
  - **内容分发方式**：enter-deep（深入 ISP 接入网，近但维护难）与 bring-home（少量关键位置集群部署）；内容注入：pull（用户访问触发回源缓存）与 push（提前主动分发热点内容）。
  - **调度（重定向）机制**：**DNS 调度**（权威 DNS 按发起查询的本地 DNS 位置返回最近的边缘节点 IP）、**Anycast**（同一 IP 多地广播，BGP 自动路由到拓扑最近节点）、302 HTTP 重定向调度。
  - CDN 也是 HTTP/2、HTTP/3（QUIC）等新协议落地的关键推动者，边缘节点终结协议就近加速。

### 7.8 P2P 应用

- **文件分发**：以 **BitTorrent** 为代表——文件切分为块（chunk），节点加入洪流（torrent）后从跟踪服务器（Tracker / DHT）获取对等方列表，通过"最稀有优先"策略请求块，并向给自己供块最多的邻居优先回馈（tit-for-tat 激励），各节点同时上下载使总分发能力随用户数增长。
- 结构化 P2P（DHT 分布式哈希表，如 Chord、Kademlia）用于 key 定位；非结构化 P2P 依靠泛洪/随机漫步查询。
- 应用延伸：区块链、去中心化存储。

### 7.9 套接字编程简介

- **TCP 套接字**：服务器端 `socket() → bind() → listen() → accept() → recv/send → close()`；客户端 `socket() → connect() → send/recv → close()`。
- **UDP 套接字**：无需连接，`socket() → sendto()/recvfrom()`，服务器只需 bind。

### 8.2 协议分层汇总（TCP/IP 体系）

- **应用层协议**：HTTP、HTTPS、FTP、SMTP、POP3、IMAP、DNS、SSH、Telnet、DHCP（基于 UDP）；RIP、BGP 虽属于路由协议，但分别基于 UDP 520 / TCP 179，运行在应用层。
- **传输层协议**：TCP（传输控制协议）、UDP（用户数据报协议）。
- **网络层协议**：IP、ICMP、IGMP、OSPF（直接封装于 IP，协议号 89）、IPSec（AH/ESP）。
- **数据链路层协议**：以太网（Ethernet）、PPP、HDLC、ARP（地址解析协议，工作在链路层与网络层之间，负责 IP→MAC 映射）。
- **物理层**：线路、无线电、光纤等传输介质及接口标准。

> **易混淆点**：P2P 不是协议而是**应用模型**；ICMP 属于网络层（封装在 IP 中），不是"传输层与网络层之间"的协议。

## 九、网络管理

根据国际标准化组织（ISO）定义，网络管理有**五大功能：故障管理、配置管理、性能管理、安全管理、计费管理**。

- **故障管理**：包括**故障检测、隔离和纠正**三方面——维护并检查错误日志、接受错误检测报告并作出响应、跟踪和辨认错误、执行诊断测试、纠正错误。
- **计费管理**：记录网络资源的使用，目的是控制和监测网络操作的费用和代价。
- **配置管理**：初始化网络并配置网络，以使其提供网络服务，目的是实现某个特定功能或使网络性能达到最优。
- **性能管理**：估价系统资源的运行状况及通信效率等系统性能。
- **安全管理**：安全性是网络的薄弱环节之一，而用户对网络安全的要求又相当高，因此网络安全管理非常重要。

> 按管理软件产品功能，又可细分为：网络故障管理软件、网络配置管理软件、网络性能管理软件、网络服务/安全管理软件、网络计费管理软件。目前主要的发展方向有：网管系统（NMS）、应用性能管理（APM）、桌面管理（DMI）、员工行为管理（EAM）、安全管理。
>
> **网络入侵检测系统（IDS）**的主要实现手段是监视和分析网络流量及异常行为，包括对网络协议的监视、对数据包结构的分析以及对网络行为的监控。通过实时监测和分析，IDS 能发现异常行为模式并发出警报，以便管理员采取适当措施。

### 9.1 常用网络命令（含跨平台对照）

| 命令 | 用法示例 | 作用 | Windows | macOS / Linux |
| --- | --- | --- | --- | --- |
| ping | `ping [hostname/IP]` | 测试主机与目标 IP 的连通性，发送 ICMP 回显请求 | `ping` | `ping`（macOS 需加 `-c` 限制次数，如 `ping -c 4 baidu.com`） |

| telnet | `telnet [hostname] [port]` | 与远程主机建立 TCP 连接，常用于**测试某个端口是否开放**（如 `telnet 192.168.1.1 443`） | 需在"启用或关闭 Windows 功能"中开启 | 需安装（`brew install telnet`） |
| ipconfig / ifconfig | `ipconfig`（全部配置）、`ipconfig /all`（详细） | 查看网络配置（IP 地址、子网掩码、网关） | `ipconfig` | `ifconfig`、`ip addr`（Linux） |
| tracert / traceroute | `tracert [hostname/IP]` | 跟踪数据包到达目标主机的路径，显示经过的路由器（利用 ICMP TTL 超时） | `tracert` | `traceroute`（macOS 需 `sudo` 才能看到完整路径） |

## 十、网络安全与网络新技术

### 10.1 网络安全基础

- **安全目标（CIA 三要素）**：**机密性**（Confidentiality）、**完整性**（Integrity）、**可用性**（Availability）；延伸目标：认证、不可否认。
- **密码学基础**：
  - **对称加密**：加解密使用同一密钥，效率高（DES、3DES、**AES**）；密钥分发是难点。
  - **非对称加密**：公钥加密、私钥解密（**RSA**、ECC）；解决密钥分发与数字签名问题，但速度慢。
  - **哈希函数**：单向、定长输出（MD5、**SHA-256**），用于完整性校验与口令存储。
  - **数字签名**：发送方用私钥对摘要签名，接收方用公钥验证；实现认证 + 不可否认。
  - **证书与 PKI**：**CA** 用自己的私钥签署"实体身份 ↔ 公钥"的证书，形成信任链。

### 10.2 典型攻击与防御

- **攻击**：**DDoS 分布式拒绝服务**（耗尽带宽/连接/计算资源，可用 CDN、流量清洗缓解）；**ARP 欺骗**（伪造 ARP 应答冒充网关实施中间人攻击，防御：静态 ARP、DAI）；**DNS 劫持/污染**（防御：DoH/DoT）；钓鱼、SQL 注入、XSS、**中间人攻击**（防御：TLS 证书校验）；嗅探（Sniffer）与欺骗（Spoofing）。
- **防御**：**防火墙**（分组过滤、状态检测、应用网关，隔离信任域）、**IDS 入侵检测**（监测告警）/ **IPS 入侵防御**（串联阻断）、**VPN**（IPSec 网络层 / SSL-VPN）、蜜罐、纵深防御 + **零信任架构**（ZTNA，"永不信任、持续验证"）。

### 10.3 网络新技术趋势

- **SDN 软件定义网络**：**控制平面与数据平面分离**，集中式 SDN 控制器通过**南向接口（OpenFlow）**下发流表到交换机，通过北向 API 供网络应用编程；灵活可编程，便于流量工程与网络创新。
- **NFV 网络功能虚拟化**：路由器、防火墙、负载均衡等网络功能从专用硬件迁移到通用服务器上的虚拟机/容器。
- **QUIC 与 HTTP/3**：传输层革新（见应用层），连接迁移与 0-RTT 显著改善移动体验。
- **IPv6 规模部署**：我国已进入 IPv6 主导阶段（活跃用户与流量占比持续提升），配合 SRv6 等源路由技术在骨干网落地。
- **5G 网络切片**：在同一物理网络上虚拟出多张端到端逻辑网络（eMBB 大带宽 / URLLC 低时延高可靠 / mMTC 海量连接），边缘计算（MEC）将算力下沉到网络边缘。
