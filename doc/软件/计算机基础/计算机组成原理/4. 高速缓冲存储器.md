## 高速缓冲存储器

> **全章主脉**：CPU 远比主存快，直连会造成 CPU 空等。Cache 放在两者之间，靠**局部性原理**把主存中近期要用的数据块先搬进来，让 CPU 大多数时候命中 Cache。本章依次讲 Cache 工作原理、三种地址映射、替换算法与写策略。**映射**解决"主存块能放 Cache 的哪些位置"，**命中率**是 Cache 效率的晴雨表。
>
> **一句话记映射**：直接映射"一个块位唯一、需换即换"、全相联"随意放、查全 Cache"、组相联"分组建、组内任意"——组相联是直接与全相联的折中，现代 Cache 最常用。

### Cache 的工作原理

#### 局部性原理

**局部性原理**指程序在一段时间内往往集中访问主存中某一小部分区域的现象，是 Cache 能够生效的根基。

局部性有两类：

- **时间局部性**：刚被访问的单元很可能在不久后再次被访问（如循环体中的指令与变量）。
- **空间局部性**：刚被访问单元附近的单元很可能随后被访问（如数组的顺序扫描、连续存放的指令）。

> [!IMPORTANT]
> 重要内容：正因为局部性，CPU 可以只把主存中被频繁访问的**字块**提前调入小容量 Cache。命中率高时，CPU 大多访问 Cache，访问主存的平均时间大幅下降。若程序局部性差（如频繁跳转、随机访问大数据），Cache 命中率低，加速效果大打折扣。



#### 命中与失效

**命中**指 CPU 要访问的字已在 Cache 中，可直接访问 Cache；**失效（未命中）**指所需字不在 Cache，须先把该字所在的整个主存块调入 Cache。

- **命中率**：CPU 访问 Cache 命中的次数占总访问次数的比例，是衡量 Cache 效率的核心指标。
- **Cache 与主存按块交换**：CPU 与 Cache 之间以字为单位传送；Cache 与主存之间以字块为单位传送（块内若干字）。
- **块**：Cache 与主存之间数据交换的基本单位，主存与 Cache 的块大小相同，块内地址是相对块起始的偏移。

**失效率**等于 1 减命中率。当块命中但内部字访问时，先按块号找 Cache，再用块内偏移取字。

> [!NOTE]
> 提醒内容：判断命中/失效看"该字所在的块是否已调入 Cache"。Cache 容量有限、块内字数与块数都影响命中率；块太小局部性用不足，块太大又浪费、替换频繁，故块大小需折中选取。



#### Cache 的读写过程

**Cache 的读操作**：CPU 发出主存地址 → 地址变换机构判断命中/失效 → 命中则直接从 Cache 取字；失效则按映射规则把主存块调入 Cache 再取字（同时可直送 CPU）。

**Cache 的写操作**比读复杂，因写会改动 Cache 与主存两处副本是否一致的问题，需配合写策略处理（详见本章"写策略"）。

**Cache 平均访问时间**可由命中率、Cache 访问时间与失效时访主存的时间加权估算：平均访问时间 ≈ 命中率 × Cache 访问时间 + 失效率 ×（主存访问时间 + Cache 访问时间）。

> [!TIP]
> 建议内容：读命中是常态优化目标；写操作要额外处理一致性与是否延迟写。分析题常给命中率与两级访问时间，用加权公式求平均访问时间，务必把"失效时既要访主存又要写回 Cache"的代价算进去。



### Cache 主存地址映射

**Cache-主存地址映射**规定主存中的每个块可以装入 Cache 中哪些位置，是 Cache 设计的核心。三种映射方式可由"主存地址如何分割成块号与块内地址、Cache 内对应关系"刻画。

#### 直接映射

**直接映射**规定每个主存块只能装入 Cache 中唯一的一个固定位置，映射关系由主存块号对 Cache 块数取模决定。

- **位置唯一**：主存第 j 块只能放入 Cache 第 (j mod Cache 块数) 块。
- **地址结构**：主存地址 = 主存标记（块号的高位）+ Cache 块号（定位 Cache 行）+ 块内地址。比较标记即可判断是否命中。
- **优点**：硬件简单、判断快，无需在全 Cache 中查找。
- **缺点**：位置冲突剧烈，两个映射到同一 Cache 块的主存块会互相挤掉（抖动），命中率相对较低。

> [!NOTE]
> 提醒内容：直接映射若块内地址占低 b 位、Cache 行号占 c 位，则主存标记 = 总地址位 - c - b。命中比较只需把主存地址高位的"标记"与 Cache 行中存的标记比对，相等且有效位为 1 即命中。



#### 全相联映射

**全相联映射**允许每个主存块装入 Cache 中任意一个空闲位置，映射最灵活。

- **位置任意**：主存块可放入 Cache 的任何位置。
- **地址结构**：主存地址 = 主存标记 + 块内地址；因块可任意放，Cache 中不再用"行号"作地址位。
- **命中查找**：命中时须把主存标记与 Cache 全部行的标记并行比较（相联比较），找出哪一行存有该块。
- **优点**：冲突最少、命中率最高。
- **缺点**：需全相联比较，硬件复杂、造价高、查寻速度受限，Cache 容量难以做大。

> [!WARNING]
> 警告内容：全相联用"标记并行比较"定位，硬件开销随 Cache 行数增加而快速上升，故实际 Cache 很少做成全相联，多用组相联折中。命中率高低与硬件复杂度之间存在此消彼长的取舍。



#### 组相联映射

**组相联映射**是直接映射与全相联的折中：把 Cache 分成若干组，主存块只能装入**指定组**，但组内可放任意一行。

- **组间直接、组内相联**：主存第 j 块装入第 (j mod 组数) 组，组内任意一行都可放。
- **相联度 r**：每组含 r 行，称 r 路组相联。直接映射是每组 1 行的特例，全相联是所有块同属一组的特例。
- **地址结构**：主存地址 = 主存标记 + 组号 + 块内地址。
- **命中查找**：先用组号定位到唯一一组，再把标记与该组内各行的标记比较。
- **优点**：兼具直接映射"查寻快"与全相联"冲突少"的优点，现代 Cache 普遍采用（如 8 路、16 路组相联）。

> [!IMPORTANT]
> 重要内容：组相联"先组内直接定位、再组内比较"，把全相联的全局比较降为组内少量行的比较，硬件可行且命中率接近全相联。**路数越高冲突越少但电路越复杂**，设计时按命中率与成本权衡。组相联是对"空间换命中、复杂度换性能"的典型体现。



### 替换算法

#### 随机、先进先出与 LRU

当新调入的块要占用的位置已满时，需按某种策略淘汰一个旧块，这种策略即**替换算法**。

常用替换算法：

- **随机算法（RAND）**：随机选取一个 Cache 行替换。实现最简单，但不考虑访问历史，命中率不稳。
- **先进先出（FIFO）**：替换最早调入 Cache 的那一行。实现简单，但可能把正在频繁使用、只是较早调入的块换出。
- **LRU（近期最少使用）**：替换**最长时间未被使用**的那一行。依据时间局部性，性能好，是实际最常用的算法，但需记录每行的使用历史，硬件开销较大。

> [!NOTE]
> 提醒内容：LRU 判断"哪个最久没被用"而不只是"哪个最早来"，故能避免 FIFO 把常用块误换出。替换算法的选择通常是在命中率与硬件可实现性之间权衡；Cache 命中率的分析题常配给定替换策略按访问序列推演块替换过程。

> [!TIP]
> 建议内容：分析替换过程时，画出"按访问序列逐次填充 Cache 行"的表，逐块判断命中或替换，是求命中率最稳妥的方法。注意初始 Cache 为空时前几块必失效（冷启动失效），不算在算法缺陷内。



### Cache 的写入策略

写操作的特殊性在于：Cache 与主存各有副本，改写 Cache 后是否立即同步主存、以及失效时是否把主存块先调入，决定了写策略的分类。

#### 写直达与写回法

**写直达（写通过）**：每次写 Cache 的同时，把该字也写入主存，Cache 与主存始终一致。

- 优点：一致性简单，失效时无需把整块写回。
- 缺点：每次写都要访主存，写操作慢，主存流量大。

**写回法（写回）**：写 Cache 时只更新 Cache，并置"脏位"标记；仅当该行被替换出 Cache 时才一次性写回主存。

- 优点：减少访主存次数，写操作快。
- 缺点：需脏位记录，替换时要写回，实现稍复杂；若写后未写回系统就断电，会丢失更新。

> [!IMPORTANT]
> 重要内容：**写直达把 Cache 与主存一致性负担放在每次写**，**写回法则把负担推迟到替换时一次性结算**。写回常与"按写分配"配合、写直达可与"写不分配"配合。脏位（dirty bit）是写回法的标志性硬件。



#### 写分配与写不分配

**写分配**与**写不分配**决定"写失效（要写的字不在 Cache）时是否先把主存块调入 Cache"。

- **写分配（写时取）**：写失效时先把该块从主存调入 Cache，再在 Cache 中改写。通常与写回法配合——既然以后要整块写回，干脆先调入统一管理。
- **写不分配（写时直写）**：写失效时**不调入**该块，直接写主存。通常与写直达法配合——写直达反正每次都要写主存，没必要先调入 Cache。

> [!NOTE]
> 提醒内容：两对策略的常见组合是"写直达 + 写不分配"与"写回 + 写分配"。读写命中与否、失效时先调入还是直接访主存、命中时同步主存还是延迟写回，组合起来决定了 Cache 一致性行为的完整刻画，命题常要求据组合判断命中/失效的动作。
