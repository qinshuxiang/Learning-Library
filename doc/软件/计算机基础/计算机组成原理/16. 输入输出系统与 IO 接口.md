## 输入输出系统与 IO 接口

> **全章主脉**：CPU 要与外设交换数据，中间隔着速度慢、种类多、时序各异的设备。IO 系统由**设备、接口、总线与控制逻辑**构成，用接口做"缓冲与匹配"。本章先讲 IO 系统概况、设备与主机如何联系，再讲**IO 接口**的功能与组成，最后总览四种**IO 控制方式**——程序查询、程序中断、DMA 与通道，它们的差异在于"谁主管传输、CPU 介入多少"。
>
> **一句话记 IO 控制**：程序查询靠 CPU 轮询、慢；中断让设备"叫"CPU、省 CPU；DMA 让专用控制器直接搬数据、绕过 CPU 快；通道本身就是专门管 IO 的小处理器。**从查询到通道，CPU 干预越来越少、数据传输越来越高效**。

### 输入输出系统概述

#### IO 系统的发展概况

**输入输出系统**是计算机与外界交换信息、完成输入输出功能的部分，其发展围绕"减少 CPU 干预、提高 IO 与 CPU 并行度"展开。

IO 系统的发展大致经历几个阶段：

- **早期分散连接**：每个设备与 CPU 单独相连，CPU 直接参与每个数据的传送，效率低。
- **总线连接与接口**：设备经接口挂到总线上，接口承担缓冲与协调，引入中断与 DMA 提高并行。
- **通道与 IO 处理器**：引入通道或 IO 处理机，让专门的硬件分担 IO 管理，CPU 只需发一次 IO 命令即可。
- **现代智能化**：DMA、通道、中断控制器与多级缓存配合，设备与 CPU 高度并行、对软件屏蔽底层差异。

**发展趋势**：从"CPU 逐字节经手"走向"CPU 只发命令、数据由专用通道/DMA 直传"，从而把 CPU 从缓慢的 IO 中解放出来。

> [!NOTE]
> 提醒内容：IO 系统演进的主线是"逐步把 CPU 从数据搬运中解放"——查询时代 CPU 全程盯着，中断时代设备主动通知、DMA 时代专用控制器直接搬数、通道时代由通道统一调度多个设备。理解这条主线能串起四种控制方式。



#### IO 系统的组成

**IO 系统**由完成输入输出所需的硬件与软件组成，主要包括 IO 设备、IO 接口（接口电路）、总线及相应的驱动与中断控制逻辑。

IO 系统的组成层次：

- **IO 设备**：实际完成输入输出的装置（键盘、显示器、磁盘、网卡等），可含设备控制器（在设备端，管理设备的机械与电气操作）。
- **IO 接口（IO 控制器）**：位于主机总线与设备之间，起连接、缓冲、时序协调与信号转换作用（本章重点）。
- **总线**：主机与接口、设备之间传送数据、地址、控制信号的通路。
- **IO 软件**：设备驱动程序与上层 IO 软件，把设备细节对应用隐藏（详见操作系统课程）。

> [!NOTE]
> 提醒内容：这里把"接口"（主机侧、贴近 CPU/总线）与"设备控制器"（设备侧）区分看；组成原理侧重主机侧接口与总线，操作系统侧重驱动与 IO 软件层次。IO 系统把千差万别的设备规整成统一接口，供 CPU 与内存按统一方式访问。



#### IO 设备与主机的联系方式

**IO 设备与主机的联系**包括物理上的连线方式与逻辑上的寻址、时序与数据传送关系。

联系方式的要点：

- **设备编址**：为每个设备（或其端口）分配地址。常用两种编址——统一编址（设备与主存共用地址空间、用访存指令访问设备）与独立编址（设备有单独地址空间、用专门 IO 指令访问）。
- **传送方式**：并行/串行，直接与 CPU 交换或经 DMA 与主存直传。
- **联络与时序**：设备与主机之间常需"就绪/应答"握手信号，以匹配速度差异。
- **控制方式**：数据传输由谁主导（查询、中断、DMA、通道），决定 CPU 的介入程度。

**统一编址与独立编址的比较**：

- 统一编址：设备与内存统一寻址，访存指令即可访问设备、无需专门 IO 指令，但占用主存地址空间。
- 独立编址：设备独立编址，用专门 IO 指令，不占主存空间、译码简单，但需增设 IO 指令。

> [!IMPORTANT]
> 重要内容：设备编址直接决定 CPU 如何找到并访问一个外设端口。**统一编址用访存指令访设备（省指令但占地址空间），独立编址用专门 IO 指令（不占主存空间但要多一套指令）**。判断某种机器是哪种编址，看它访问外设端口时用的是访存指令还是专用 IO 指令。



### IO 接口的功能与组成

#### 接口的功能

**IO 接口**是主机与 IO 设备之间的连接部件，负责把设备接入系统总线并协调二者工作，是数据传送的"中转站"。

IO 接口的主要功能：

- **数据缓冲**：用数据寄存器缓冲，使高速 CPU 与低速设备在数据传送时能暂存，避免数据丢失。
- **状态寄存**：记录设备状态（忙、就绪、出错等），供 CPU/设备查询。
- **地址识别**：识别总线上发来的、属于本设备的地址，决定是否响应。
- **信号转换与时序协调**：把总线的信号与时序转换成设备所需的格式，匹配速度。
- **中断管理**：对中断请求进行登记、屏蔽与向 CPU 提交（配合中断系统）。
- **控制与传送**：接收 CPU 命令控制设备动作，并完成数据、地址、控制三类信息的传送。

> [!NOTE]
> 提醒内容：接口是"缓冲 + 状态 + 译码 + 转换 + 中断"的综合体。它一端连主机总线、一端连设备，让千差万别的设备以统一的端口集合（数据、状态、命令寄存器）呈现给 CPU。



#### 接口的类型与数据缓冲

**IO 接口**可按并行性、可编程性与数据宽度等多种方式分类，其内部通常含若干可访问的寄存器。

接口的常见分类：

- **并行接口与串行接口**：并行接口一次传送多位、速度快、线多；串行接口一位位传送、线少、适合长距离（并需并串转换）。
- **可编程接口与不可编程接口**：可编程接口可用命令字设置工作方式，灵活通用；不可编程接口功能固定。
- **按设备类型**：磁盘接口、显示接口、网络接口等。

**接口内的寄存器（端口）**：

- **数据寄存器**：暂存输入/输出的数据，起缓冲作用。
- **状态寄存器**：保存设备与接口状态（就绪、忙、错误），供查询。
- **命令寄存器**：CPU 写入命令，控制设备/接口工作方式。

**数据缓冲的作用**：当 CPU 与设备速度差异大时，数据寄存器先存入待传数据或暂存读入数据，使高速侧不必死等低速侧，从而平滑传输并减少 CPU 等待。

> [!TIP]
> 建议内容：理解接口可把它想象成"设备的小窗口"——CPU 通过读写接口里的命令、状态、数据三个端口来指挥与交换。程序查询/中断/DMA 都能见到接口里状态与数据寄存器的身影，它们是各类控制方式工作的硬件落脚点。



### IO 设备与主机信息传送的控制方式

#### 程序查询、中断、DMA 与通道

**IO 控制方式**指数据在主机与设备之间如何组织传送、由谁主导。四种方式按 CPU 介入程度从强到弱排列：

**程序查询方式**：CPU 反复查询设备状态，忙则等待、就绪才传一个数据。最简单，但 CPU 要空转等待设备，效率最低（详见第 17 章）。

**程序中断方式**：CPU 发命令后不再等待，设备就绪时向 CPU 发中断请求，CPU 响应后转去执行中断服务程序完成数据传送。免除 CPU 空等、提高并行，但每传一个数据仍要 CPU 介入中断处理。

**DMA（直接存储器访问）方式**：用专门的 DMA 控制器在主存与设备之间直接成块传送数据，CPU 只需在开始与结束时介入，传送期间不占用 CPU（详见第 18 章）。

**通道方式**：通道是一种专管 IO 的处理器，可执行通道程序、独立控制多台设备的数据传送，CPU 只需发一条 IO 命令由通道去执行。控制能力最强，但实现复杂、需专门的通道硬件。

**四种方式的对比主线**：从程序查询到通道，CPU 对数据传送的参与越来越少——查询要 CPU 盯每个数据，中断要 CPU 处理每批数据，DMA 由控制器搬整块、CPU 只负责启停，通道则连搬数据的指令都自行执行。

> [!IMPORTANT]
> 重要内容：四种控制方式的本质差异是"**数据传送由谁执行、CPU 介入多少**"——程序查询 CPU 全程轮询最慢；中断按数据逐个让 CPU 响应处理；DMA 由专用控制器整块直传主存与设备、CPU 几乎不碰数据；通道本身是能执行通道程序的 IO 处理机。效率与 CPU 解脱程度依次提高，硬件复杂度也依次上升，命题常要求按"CPU 介入由多到少"排序。
