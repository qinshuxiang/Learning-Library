## DMA 方式

> **全章主脉**：中断方式虽然免除 CPU 空等，但每传一个数据仍要 CPU 响应并执行中断服务，成块高速数据（如磁盘读写）吃不消。**DMA（直接存储器访问）**让 DMA 控制器直接在主存与设备之间成块搬数据，传送期间不占用 CPU，只在开始与结束时各打扰 CPU 一次。本章讲 DMA 的特点、DMA 接口的组成、工作过程与三种传送方式。
>
> **一句话记 DMA**：DMA 让专用控制器"接管总线、自己搬整块数据"——CPU 初始化后让出总线，数据在主存与设备间直传，传完由控制器交还总线并中断通知 CPU。CPU 只忙两头、中间完全解脱。

### DMA 方式的特点

#### DMA 与中断方式的区别

**DMA（直接存储器访问）方式**用 DMA 控制器接管数据传送，使主存与 IO 设备之间可以直接成块交换数据，CPU 只在传送开始前与结束后介入。

DMA 与程序中断方式的本质区别在于"数据传送由谁执行、CPU 介入几次"：

- **程序中断方式**：每传一个数据，CPU 都要响应中断、执行中断服务程序把数据读入/写出，成块数据需 CPU 反复介入。
- **DMA 方式**：整块数据由 DMA 控制器在硬件控制下直传，CPU 只在传送前做初始化、传送结束后响应一次"传送完成"中断，块内传送不占 CPU。

**DMA 的相对优势**：

- 成块数据传送高效，CPU 不逐字参与，利用率高。
- 适合高速设备与大量数据（如磁盘、网卡、高速外设）。

**DMA 的代价**：需要专门的 DMA 控制器，且传送时 DMA 要占用总线（与 CPU 争总线，见传送方式），故适合大块数据，小块数据未必划算。

> [!IMPORTANT]
> 重要内容：一句话分清——**中断方式每个数据都经 CPU"过手"（逐数据中断处理），DMA 整块数据由 DMA 控制器直传主存与设备，CPU 只管头尾**。因此 DMA 适合大批量、高速的数据交换；中断则适合数据量小、需 CPU 处理的场合。判"何时用 DMA"看是否要成块、高速、大量传输。



### DMA 接口的功能与组成

**DMA 接口（DMA 控制器）**是 DMA 方式的核心，负责在主存与设备间组织并执行成块数据的直接传送。

**DMA 控制器的功能**：

- 向 CPU 申请总线，获得总线使用权后接管传送。
- 管理数据传送：按约定的源/目的地址与字节数，控制主存与设备之间的数据流。
- 计数与控制：统计已传字节、判断是否传完。
- 传送结束通知：传送完成后向 CPU 发中断请求，交还总线。

**DMA 接口中的寄存器（组成）**：

- **内存地址寄存器（AR）**：存放本次传送的源或目的主存地址，每传一个数据自动修改。
- **数据寄存器（DR）**：暂存主存与设备间周转的数据，起缓冲。
- **字计数寄存器（WC）**：记录还需传送多少数据，每传一个递减，减到 0 表示完成。
- **设备地址寄存器**：指向被传送数据的设备（或其端口）。
- **控制/状态寄存器**：保存控制命令与状态、启动与结束标志。

**DMA 的三种传输方向**（据设备与主存相对位置）：

- 设备读入主存（输入，设备 → 主存）。
- 主存读出到设备（输出，主存 → 设备）。
- 也支持主存到主存（或经 DMA 的两块主存间搬移）。

> [!NOTE]
> 提醒内容：DMA 控制器的寄存器——AR 管主存地址、DR 管缓冲、WC 管传多少个（计数）。它的存在使 CPU 只做"设初值、看结果"，块内每个数据的搬移由这些寄存器与硬件自动推进。理解这三类寄存器即可把握 DMA 的传送骨架。



### DMA 的工作过程

**DMA 的工作过程**分三个阶段：传送前预处理、成块传送、传送后处理。

**预处理（CPU 完成）**：

- CPU 对 DMA 控制器设置主存起始地址、设备地址、传送数据个数与方向。
- 启动设备，之后 CPU 可去做别的事（DMA 独立传送）。

**数据传送（DMA 控制器完成，不占 CPU）**：

- DMA 控制器申请并取得总线控制权。
- 按内存地址寄存器与计数寄存器，在主存与设备之间成块搬数据。
- 每搬一个数据更新地址与计数，直到计数为 0。

**后处理（CPU 完成）**：

- DMA 控制器向 CPU 发"传送完成"中断。
- CPU 响应，进行结果处理（校验、善后），交还总线继续原工作。

**DMA 期间 CPU 的去向**：传送期间 CPU 可继续执行与传送无关的指令；仅在传送需占用总线时与 DMA 存在总线使用权冲突，由传送方式协调。

#### DMA 传送的三种方式

**DMA 传送方式**解决"DMA 与 CPU 争用总线"时如何安排两者使用总线。主要有三种：

- **停止 CPU 访存（成块传送）**：DMA 取得总线后，暂停 CPU 访存直到整块传完，CPU 在传送期间被停。实现简单，但 CPU 被长期占用、不能访存（只可做寄存器内的事），浪费 CPU。
- **周期挪用（周期窃取）**：DMA 每次只占用 CPU 的一个或几个访存周期来传数据，传完一个周期就交还总线给 CPU，两者交替访存。CPU 只被"偶尔挪用"周期、停顿小，是较常用方式。
- **DMA 与 CPU 交替访问（透明传送）**：把 CPU 的访存周期划分，DMA 只在 CPU 不访存的那些时间片内传送，因而不打断 CPU（对 CPU 透明），但需更复杂时序安排。

> [!WARNING]
> 警告内容：周期挪用会偶尔让 CPU 停顿一个访存周期；停止 CPU 访存则让 CPU 长时间不能访存但可执行寄存器内操作（并非完全停机）；透明传送不打断 CPU 但对时序要求高。三种方式的取舍在"DMA 速率需求 vs CPU 停顿"之间，判题时看它让 CPU 停多久、传送多久一次。

> [!NOTE]
> 提醒内容：DMA 结束时以"中断"通知 CPU，这里的"完成中断"只在整块传完后发一次，与程序中断方式"逐数据中断"不同——DMA 用一次中断通知"整批完成"，体现其"CPU 只管头尾"的特点。
