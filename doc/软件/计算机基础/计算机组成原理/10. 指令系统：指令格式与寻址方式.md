## 指令系统：指令格式与寻址方式

> **全章主脉**：指令系统是软硬件的界面，CPU 只认自己的指令。一条指令 = **操作码**（做什么）+ **地址码**（到哪找操作数/结果）。本章讲指令怎么编排（定长/变长、扩展操作码）、有哪些操作数与操作类型、最关键的是**寻址方式**——它决定地址码如何演变成真正的操作数地址，直接影响指令的灵活性与长度。
>
> **一句话记寻址**：指令给出的是"到哪儿找数据"的线索：立即数直接把数带上、直接/间接寻址地址先给地址再取数、寄存器寻址最快、变址/基址靠寄存器加偏移定位。**寻址方式越直接越快，越间接越灵活但越慢**。

### 机器指令的格式

#### 操作码与地址码

**机器指令**是 CPU 能直接识别并执行的二进制代码，一般由**操作码**与**地址码**两部分组成。

- **操作码**：指出该指令要执行什么操作（如加、减、传送、转移、停机），是区分指令类型的依据。
- **地址码**：指出操作数所在位置或下一条指令的地址，可能有一个或多个。

**地址码的数量**不同，指令分为多种地址制：

- **零地址指令**：无操作数（如停机）或操作数隐含在栈顶。
- **一地址指令**：一个操作数地址，另一个操作数可隐含（如累加器）。
- **二地址指令**：给出两个操作数地址，如 A 加 B 结果存某处，最常见。
- **三地址指令**：两个源操作数加一个目的地址。

**指令的作用范围**：指令中可显式给出或隐含约定操作数来自寄存器、主存单元或立即数等，寻址方式决定地址码如何解释。

> [!NOTE]
> 提醒内容：操作码位数决定指令条数上限（n 位操作码最多 2 的 n 次方种），地址码个数与位数决定访存与指令长度。指令设计要在"能表示的指令数、可寻址空间、指令长度、执行速度"间权衡。



#### 指令字长与扩展操作码

**指令字长**指一条指令所含的二进制位数。按字长是否固定分定长指令与变长指令两类。

- **定长指令**：所有指令字长相同，取指简单、译码快，但指令不紧凑，浪费存储。
- **变长指令**：指令字长不同（按需取 1 至多个字节），节省空间，但取指与译码复杂。

**扩展操作码**是一种让操作码位数可变的编码技术：短操作码用于高频指令，把空闲码点扩展出更长操作码以表示更多指令。

**扩展操作码的设计要点**：

- 短操作码留出若干码点不用，作为"扩展到更长操作码"的标志。
- 当操作码取短码点时，剩余地址位增加，可表示更多操作数；取长码点时地址位减少。
- 要求所有指令的操作码前缀互不冲突，能在译码时唯一区分。

> [!IMPORTANT]
> 重要内容：**扩展操作码通过"留白"牺牲部分短码，换取更多的长指令**。设计时先按指令使用频度分配短码，短码剩余的码点再扩展成更长的操作码。判定一组合法性要看是否存在歧义——即任一编码前缀能否被唯一译成某条指令。



### 操作数类型与操作类型

**操作数类型**指指令处理的数据种类，不同数据在机器中如何存放与表示决定操作数编码。

常见操作数类型：

- **地址**：作为操作数，用于转移与访存。
- **数值数据**：定点数、浮点数、十进制数、字符与字符串等。
- **逻辑数据**：仅按位处理、无数值意义的数据。
- **其他**：如控制类标志、状态等。

**数据在存储器的存放**要遵循地址对齐与字节序等约定：

- **字节序**：多字节数据在存储器中的排列——小端（低字节在低地址）与大端（高字节在低地址）。
- **对齐**：字/半字数据按地址对齐存放可提高访问效率。

**操作类型**指指令所执行的操作种类，大致可分几类：

- **数据传输**：寄存器间、寄存器与主存间、主存与 IO 间的传送。
- **算术逻辑运算**：定点/浮点加减乘除、与或非、移位。
- **移位操作**：算术移位、逻辑移位、循环移位。
- **转移操作**：无条件转移、条件转移、调用与返回。
- **输入输出**：CPU 与 IO 设备间传送数据（单独 IO 指令或映射为访存）。

> [!NOTE]
> 提醒内容：操作数类型关注"数据长什么样、怎么存"，操作类型关注"指令做什么"。字节序与对齐是数据存放的常见考点，小端低字节在低地址、大端反之，写多字节示例时应先明确字节序再排地址。



### 寻址方式

#### 指令寻址

**指令寻址**解决"下一条要执行的指令在哪个地址"，主要分顺序寻址与跳跃寻址两种。

- **顺序寻址**：指令在主存中顺序存放，执行完当前指令后 PC 自动加指令长度，指向下一条（顺序执行）。
- **跳跃寻址**：遇到转移指令且条件成立时，把转移目标地址装入 PC，下一条从目标地址开始执行（非顺序）。

**指令寻址的实现**：程序计数器 PC 始终指向"下一条要取出的指令地址"，顺序执行靠 PC 自增、转移执行靠把目标写入 PC。

> [!NOTE]
> 提醒内容：指令寻址只回答"指令从哪来"，一般不把"转移目标怎么算出来"算作指令寻址，而称数据寻址或专门讨论。顺序（PC+1）与跳跃（PC=目标）是最基础的两种，后文寻址重点在操作数的"数据寻址"。



#### 数据寻址：立即、直接、间接、寄存器、变址与基址寻址

**数据寻址**规定如何根据指令中的地址码找到真正的操作数（有效地址），是决定指令灵活性与速度的关键。

各主要寻址方式的要点：

- **立即寻址**：操作数直接写在指令中（立即数），取指即得数、不需访存，速度快，但操作数是常数、不灵活。
- **直接寻址**：地址码直接给出操作数在主存的地址，取指后再访存一次取操作数；简单但地址字段长。
- **间接寻址**：地址码给出的是"存放操作数地址"的单元地址，须访存一次取出真正地址、再访存取数，可多次间接；灵活、可访问大空间，但慢。
- **寄存器寻址**：地址码指出寄存器编号，操作数就在该寄存器中；不需访存、速度最快，但寄存器数量有限。
- **寄存器间接寻址**：地址码指出寄存器，寄存器内存放操作数的主存地址，先取寄存器内地址再访存；灵活且指令短。
- **变址寻址**：有效地址 = 指令中变址寄存器内容 + 形式地址（指令内偏移），常配合循环处理数组，变址寄存器内容可变。
- **基址寻址**：有效地址 = 基址寄存器内容 + 形式地址，用于程序定位（重定位），基址由系统设定、多用于多道程序。
- **相对寻址**：有效地址 = PC 当前值 + 形式地址，用于转移，程序可整体搬移不失效。

**变址与基址的区别**：变址主要面向**用户遍历数组**（偏移在指令、变址量在变址寄存器）；基址主要面向**系统管理存储**（基址由系统给、用于重定位）。二者都做"寄存器 + 形式地址"，但用途与寄存器归属不同。

> [!WARNING]
> 警告内容：变址与基址最易混——同是"寄存器内容加形式地址"，**变址强调下标变化遍历数组、基址强调定位程序基地址**。相对寻址加的是 PC。判断"访存几次"要看寻址链：直接寻址 1 次取数、间接寻址至少 2 次、寄存器寻址 0 次访存，别把"取指"那次也算进"取操作数"的次数。



### 指令格式设计

**指令格式设计**是在给定机器字长、指令条数与寻址方式等条件下，合理划分操作码与地址码字段，使指令既能覆盖所需功能又尽量短、译码简单。

**设计应考虑的因素**：

- **指令条数**：决定操作码位数下限。
- **操作数个数与类型**：决定地址码个数与每个地址的长度。
- **寻址方式**：决定地址码是直接给出地址还是寄存器号等。
- **字长与对齐**：定长或变长、按字节还是按字取指。

**设计目标与权衡**：

- 地址码短则指令短、取指快，但单指令可寻址空间小、需间接/寄存器辅助。
- 操作码与地址码在有限字长内此消彼长，常用**扩展操作码**在二者间平衡。
- 尽量让常用指令短、高频操作寻址方式简单，提高整体执行效率。

> [!TIP]
> 建议内容：做指令格式设计题时，先由"指令条数"定操作码位数，再由"寻址方式种类"为每条指令留寻址方式字段，最后核算总字长并考虑用扩展操作码压缩。关键校验是"字段位数是否够装下所需指令数/寄存器数/形式地址范围"，并把每条指令的编码翻译成确切的取数流程。




### 程序的机器级代码表示

**机器级代码表示**研究的是：高级语言里的一条语句（if、循环、函数调用）最终如何被翻译成一串机器指令，从而揭示"程序是怎么真正跑起来的"。这层是 408 的重要考点，常以一段 C 代码配合汇编让你分析寄存器、内存与跳转关系。理解机器级表示，须先掌握一套简化指令集的基本用法。

#### 常用指令与条件码

**机器级指令**按功能可分数据传送、算术逻辑、转移、调用返回几类。理解每类指令"改了什么"是读汇编的基础。

- **数据传送（mov/lea 类）**：在寄存器、主存、立即数间搬运数据。mov 把源复制到目的，lea 常用来算地址或一次做"基址加变址乘比例"的地址计算。
- **算术与逻辑（add、sub、imul、and、or、xor、shl、sar 等）**：对操作数做运算并把结果写回目的。结果是否为零、正负、有无进位会被记录到状态寄存器里的**条件码**。
- **比较（cmp）与测试（test）**：cmp 做减法但不写回，只影响条件码（用来比较两数）；test 做按位与但不写回（用来测某位是否为零）。
- **跳转（jmp、jz/jnz、jl、jg 等）**：jmp 无条件转移；以 j 开头的条件跳转指令根据条件码跳转，如 je（相等则跳）、jne、jl（小于）、jg（大于）等。
- **调用与返回（call、ret）**：call 把返回地址压栈并跳转到函数入口，ret 从栈弹出返回地址跳回调用点。

> [!NOTE]
> 提醒内容：判断一段汇编对应的控制流，先找影响条件码的指令（cmp/test/算术）再找紧跟的条件跳转。**条件码由前一条改变它的指令产生，条件跳转再据它决定是否跳**——两者常配对出现。

#### 选择语句的机器级表示

**if-else 语句**翻译时，先把条件表达式算出来并影响条件码，再用与条件相反的条件跳转跳过 then 分支（或跳到 else 分支）。

例如"若 a 大于 b 则执行块1 否则执行块2"，典型翻译是：先 cmp 比较 a、b，再用 jle（不大于即小于等于则跳）跳到 else 对应的块2 处，顺序执行块1，最后跳转到整个 if 后；else 分支的块2 排在块1 之后。

**关键点**：
- 条件跳转的方向通常与高级语义"相反"——if 条件成立走 then，汇编里往往是"条件不成立就跳走"。
- 无 else 的 if：不成立时跳过 then 块直接到 if 之后。
- 多个条件（与、或）会拆成多个 cmp 与跳转组合。

#### 循环语句的机器级表示

**循环（for、while、do-while）**翻译时，用条件跳转在"循环体"与"循环判断"之间构成回边（向后跳转），并用条件跳转在条件不再成立时跳出循环。

- 典型的 while 结构：判断处先测条件，不成立则跳到循环外；成立则顺序执行循环体，执行到末尾**无条件跳回判断处**（形成回边）。
- do-while 先执行一次循环体再判断，翻译时判断在循环体之后，首次无需先测。
- 编译器会把 for 的初始化、条件、步进拆到循环体前/内/尾，其中步进通常在每次循环体末尾执行后跳回判断。

> [!WARNING]
> 警告内容：读循环汇编时，找两处跳转——**循环体尾部的无条件回跳（决定"再来一次"）与判断处的条件跳出（决定"何时停"）**。do-while 因为先执行后判断，判断处的条件跳转方向与 while 往往相反，是常见易错点。

#### 过程调用的机器级表示：调用栈

**函数（过程）调用**的核心机制是**调用栈**：每个正在执行的函数在栈中占一段连续的**栈帧**，存放其返回地址、局部变量、被保存的寄存器与被调用者的参数等。栈由 CPU 的栈指针（如 rsp）管理，向低地址增长。

**一次调用的动作**：
- 调用方先按约定把实参放到参数寄存器或压栈，执行 call 指令。
- call 把**返回地址**（call 下一条指令的地址）压栈，并把 PC 设为被调函数入口。
- 被调函数**建立栈帧**：把栈指针下移为自己分配局部变量空间，必要时把调用方要用到的寄存器值压栈保存。
- 函数体执行期间，局部变量通过栈指针加偏移访问；return 值通常放到约定的寄存器。
- 函数返回时**撤销栈帧**、恢复被保存寄存器，执行 ret 从栈弹出返回地址跳回调用点。

**递归**正是调用栈价值的体现：每层递归调用都建立新的栈帧，保存本层参数与局部变量，逐层返回时各栈帧依次释放，因此递归深度受栈空间限制、过深会栈溢出。

> [!IMPORTANT]
> 重要内容：**过程调用用 call/ret + 栈实现，栈帧是理解递归与函数链的关键**。一条 call 至少隐含"压返回地址"一次写栈，ret 隐含"弹返回地址"一次读栈。区分三类机器级控制：if 用"条件跳转跳过"、循环用"回跳+条件跳出"、函数用"call 压栈 + ret 弹栈"，是本章最需贯通的一条主线。
