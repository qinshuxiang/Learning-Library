## 网络管理

### 网络管理概述

#### 网络管理的定义与对象

**网络管理（network management）**：指对网络的**运行状态进行监测、控制和协调**，以保证网络高效、可靠、安全地运行，并合理利用网络资源、降低运行成本。

- 管理对象：路由器、交换机、服务器、防火墙、链路带宽、IP 地址资源以及运行其上的服务与应用。
- 管理的本质是"**监视 + 控制**"：先采集设备与流量状态（监视），再按策略调整配置或流量（控制）。
- 学习主线：ISO 定义的**五大管理功能**（故障、计费、配置、性能、安全）、管理系统的实现技术（代理、MIB、协议），以及运维中使用的**常用命令与排障方法**。

> 一句话：**网络管理管的是"网络健不健康、资源贵不贵、配置对不对、跑得快不快、安不安全"**——五大功能正好各回答一个问题。



#### 网络管理的基本模型

**网络管理模式**通常由三部分组成：**管理站（manager）**、被管设备上的**管理代理（agent）**、以及两者之间的**管理协议与数据库**。

- **管理站**：运行网管软件的主机，是管理员操作的入口，负责下发指令与汇总展示。
- **管理代理**：运行在被管设备（路由器、交换机等）上的进程，响应管理站的查询与设置，并在异常时主动上报。
- **管理信息库（MIB，Management Information Base）**：被管对象（设备状态、接口流量、计数器）在代理侧的结构化数据库，管理协议读写的正是 MIB 变量。
- **管理协议**：管理站与代理之间的通信规则，TCP/IP 网络中最典型的是 **SNMP**（Simple Network Management Protocol，简单网络管理协议）。

SNMP 相关要点：

- 传输在 **UDP** 之上：管理站轮询用 161 端口，代理主动发**陷阱（trap）**上报异常用 162 端口。
- 操作类型：**Get/GetNext**（读 MIB）、**Set**（写配置）、**Trap/Inform**（事件上报），代理被动的"查询应答"为主、主动上报为辅。
- 版本：SNMPv1/v2c 使用团体名（community）做弱认证；**SNMPv3** 引入用户认证与加密，安全性显著提升。

> 记忆：**"管理站轮询、代理应答、出事发 trap、MIB 是字典、UDP 161/162 是通道"**。网络管理的技术骨架就是这句话。



### ISO 五大管理功能

#### 五大功能的总体框架

**ISO（International Organization for Standardization，国际标准化组织）**在 OSI 管理框架中把网络管理划分为**五大功能：故障管理、计费管理、配置管理、性能管理、安全管理**，取英文首字母常称 **FCAPS**。

- **故障管理（Fault）**：发现并修复网络故障，保可用性。
- **计费管理（Configuration 之外的 Accounting）**：统计资源使用与费用（注意首字母对应顺序）。
- **配置管理（Configuration）**：管理设备配置，保运行与变更可预期。
- **性能管理（Performance）**：评估资源与服务质量。
- **安全管理（Security）**：保障网络与数据的安全。
- 五大功能不是孤立的：故障往往与性能恶化相关，性能数据帮助定位故障，配置变更又可能引入性能或安全问题。

> 记忆口诀：**"坏、账、配、速、安"——故障要先修、计费要算清、配置要管好、性能要盯紧、安全要兜底**。考题直接问"ISO 五大功能有哪些"，按此顺序默写。



#### 故障管理

**故障管理（fault management）**：负责网络的**故障检测、故障隔离与故障纠正**，目标是把故障对服务的影响降到最低，是网络管理中最常被强调的功能。

故障管理的具体工作：

- **故障检测**：维护并检查错误日志、接收错误检测报告并作出响应，利用轮询与告警及时发现异常。
- **故障隔离**：通过诊断与测试**跟踪、辨认错误**，确定故障发生在哪台设备、哪条链路（如用分层排查与路径跟踪）。
- **故障纠正**：执行诊断测试、修复或替换故障部件，并尽快恢复服务；事后记录故障原因与处理过程，形成经验库。

> 记忆：故障管理三段式是**"先发现、再定位、后修复"**。运维排障（见本章末）本质就是故障管理的实操版。



#### 计费管理

**计费管理（accounting management）**：**记录网络资源的使用情况**，目的是**控制和监测网络操作的费用与代价**，并向用户合理收取费用或分配配额。

- 计费的对象：流量用量、连接时长、存储空间、专用带宽、服务调用次数等可量化的资源。
- 作用：对**收费网络**（ISP、云服务）形成账单依据；对**企业网络**则是"成本归集 + 预算控制"，防止资源被滥用。
- 支撑技术：SNMP 计数器、NetFlow/sFlow 流量统计、Radius 认证计费（AAA 中的 Accounting）。

> 一句话：**计费管理回答"谁用了多少、该花多少钱"**。它把网络从"黑盒免费"变成"可计量、可分摊、可审计"的资源。



#### 配置管理

**配置管理（configuration management）**：负责**初始化网络并对网络进行配置**，以使其提供网络服务，目的是实现某个特定功能或使网络性能达到最优。

配置管理的具体工作：

- **初始配置**：新设备上线时的基础设置（IP、路由协议、VLAN、安全策略）。
- **配置档案管理**：集中保存各设备的配置版本，保证**变更可回溯**——出问题时可对比前后差异、快速回滚。
- **配置变更控制**：按流程审批与执行变更，避免"随手改配置导致全网故障"。
- **拓扑与资源管理**：维护网络拓扑视图与 IP 地址、VLAN 等资源台账。

> 记忆：**配置管理是"让网络按设计意图工作，并让每次改动留痕可回滚"**。实践中大量故障源于未受控的配置变更，配置管理因此是运维规范化的基石。



#### 性能管理

**性能管理（performance management）**：**估价系统资源的运行状况及通信效率**等系统性能，目标是保证网络以可接受的服务质量持续运行，并为扩容提供依据。

性能管理的典型指标：

- **利用率**：链路带宽、CPU、内存的占用比例。
- **吞吐量**：单位时间实际传输的数据量。
- **时延与抖动**：端到端时延及其波动，直接反映用户体验。
- **丢包率与错误率**：传输质量的直接度量。
- **可用性**：设备与服务的在线时间占比。

性能管理的闭环：持续**采集指标** → 与**基线/阈值**比较 → 超限**告警** → 分析与**优化**（调整参数、扩容、优化路由）→ 更新基线。性能数据也能反过来帮助故障管理定位瓶颈。

> 记忆：**性能管理管"快不快、满不满、稳不稳"**。它与故障管理的区别：性能关注"趋势与容量"，故障关注"有没有坏"。



#### 安全管理

**安全管理（security management）**：负责网络的**安全策略制定、访问控制、安全事件监测与响应**。网络是安全薄弱环节，而用户对安全要求高，安全管理因此非常关键。

安全管理的具体工作：

- 制定并下发安全策略（防火墙规则、访问控制列表、认证与授权方案）。
- 管理密钥与证书（PKI 的日常运维，见第 23 章）。
- 通过日志审计、IDS/IPS 等**监测安全事件**，发现入侵迹象并告警。
- 应急响应与恢复：处置攻击、隔离失陷主机、恢复被破坏的服务与数据。

> 定位：**安全管理是"策略 + 监测 + 处置"**，与第 23 章的安全技术互为表里——那里讲"用什么技术防"，这里讲"如何在管理体系中落地"。



### 网络管理系统与网管软件

#### 网管系统 NMS 与网管软件产品

**NMS（Network Management System，网络管理系统）**：是运行管理协议、提供管理功能的软件平台，把五大功能落到可操作的界面与流程上。

- 典型的网管软件功能分为：**网络故障管理软件、网络配置管理软件、网络性能管理软件、网络服务/安全管理软件、网络计费管理软件**，与五大功能一一对应。
- 当前主要发展方向：**网管系统（NMS）**走向集中化与自动化；**应用性能管理（APM）**关注应用层体验；**桌面管理（DMI）**管理终端；**员工行为管理（EAM）**审计上网行为；**安全管理**与态势感知平台融合。
- 网管系统的基础能力：自动发现拓扑、设备状态监控、阈值告警、配置备份与报表、北向接口对接上层平台。

> 记忆：**管理软件是五大功能的"产品化"**——故障、配置、性能、安全、计费软件正好一一承接五大功能，NMS 是它们的集成平台。



#### 入侵检测系统 IDS 在网络管理中的角色

**网络入侵检测系统（IDS）**在网管体系中承担"安全监测"角色，其主要实现手段是**监视和分析网络流量及异常行为**，包括对**网络协议的监视、数据包结构的分析**以及对**网络行为的监控**。

- 通过实时监测与分析，IDS 能发现**异常行为模式并发出警报**，供管理员采取适当措施（阻断、隔离、加固）。
- 分类与部署详见第 23 章安全防御部分，此处要点是它在网管框架中的位置：IDS 的告警应汇入安全管理的**事件与审计**流程，与防火墙、日志系统联动形成"检测—响应"闭环。
- 从"管理"而非"技术"角度，IDS 的价值是把安全事件**量化与可视化**——让管理员知道"网络正在被怎样试探、攻击到了哪一步"。

> 一句话：**IDS 是安全管理功能在技术层的"哨兵"**——网络管理的五大功能是框架，IDS/防火墙等是落实框架的技术手段。



### 常用网络命令与跨平台对照

#### 命令总览

网络排障与验证离不开命令行工具，以下命令覆盖"连通性、远程管理、地址与解析、路径与路由、连接与端口"五类需求，且存在 Windows 与 macOS/Linux 的平台差异。

- **连通性测试**：ping
- **远程管理**：ssh、telnet
- **本机网络配置**：ipconfig（Windows）、ifconfig/ip（macOS/Linux）
- **路径跟踪**：tracert（Windows）、traceroute（macOS/Linux）
- **地址解析与路由**：arp、route
- **域名查询**：nslookup（另推荐 dig）
- **连接与端口**：netstat、ss、lsof
- **Windows 网络管理**：net

> 用法约定：下文用"**平台标注**：Windows / macOS / Linux"区分差异；命令行示例统一放在以 text 为语言标注的代码块中给出，可直接复制运行。



#### ping：连通性测试

**ping**：向目标主机发送 **ICMP 回显请求（echo request）**，等待回显应答，用于测试本机与目标之间的**连通性与往返时延**。

- **用途示例**：测试能否到达网关、公网主机与域名解析后的服务器。

```text
ping -c 4 baidu.com   # macOS/Linux：ping 4 次后停止
ping 192.168.1.1      # Windows/macOS/Linux 通用；Windows 默认连续 ping 可用 -n 限次数
ping -n 4 baidu.com   # Windows：ping 4 次
```

- **平台对照**：Windows 与 macOS/Linux 都自带 ping；macOS/Linux 若不限次数会一直 ping（Ctrl+C 结束），常用 -c 指定次数，Windows 用 -n。
- **结果判读**：通——看到回显与 RTT；不通——Request timed out/Destination Host Unreachable/100% packet loss；RTT 大且抖动——链路拥塞或质量差。

> 排障口诀：**先 ping 通不通、再看时延长不长**。ping 通代表"IP 层可达"，但不代表"端口服务可用"——服务可用性要靠端口测试。



#### ssh：安全远程登录

**ssh**：使用 SSH 协议**加密远程登录**并管理远程主机，是替代明文 telnet 的标准远程管理手段（默认端口 22）。

- **用途示例**：登录远程服务器执行管理命令、端口转发与隧道、安全传输文件（scp）。

```text
ssh 用户名@主机           # 常规登录，如 ssh root@192.168.1.10
ssh -p 2222 用户@主机     # 指定非默认端口
scp 文件 用户@主机:路径    # 基于 SSH 的加密拷贝
```

- **平台对照**：Windows 10 起自带 OpenSSH 客户端；macOS/Linux 系统自带。
- **常见问题**：首次连接需确认主机指纹；密码或密钥认证失败时检查用户名、权限（私钥须 chmod 600）；连接超时排查网络与端口。

> 排障要点：**ssh 能通说明"端口 22 可达且认证通过"**；频繁失败可能是防火墙拦截、sshd 未启动或密钥权限错误。



#### telnet：端口连通性测试

**telnet**：传统远程登录协议（明文，不安全），现代主要用于**测试某个 TCP 端口是否开放**——能连上说明端口通，连不上说明端口被拦或服务未开。

- **用途示例**：

```text
telnet 192.168.1.1 443    # 测试目标 443 端口是否开放
telnet baidu.com 80       # 连上后可手动输入 HTTP 请求行测试
```

- **平台对照**：Windows 需在"启用或关闭 Windows 功能"里勾选 Telnet 客户端；macOS 需安装（brew install telnet）；Linux 装 telnet 包。
- **替代工具**：nc（netcat）功能更强（如 nc -vz host port 快速探测端口）。

> 排障要点：**"端口通不通"是区分"网络可达但服务没起"与"防火墙拦截"的关键一步**。telnet 能连上 80 而浏览器打不开，问题多半在 HTTP 层而非网络层。



#### ipconfig 与 ifconfig：查看本机网络配置

**ipconfig（Windows）/ifconfig（macOS/Linux）**：查看本机的**IP 地址、子网掩码、默认网关、DNS** 等网络配置，是排障第一步"先看本机有没有配好地址"。

- **用途示例**：

```text
ipconfig            # Windows：显示各网卡简要配置
ipconfig /all       # Windows：完整信息（含 MAC、DNS、DHCP）
ifconfig            # macOS/Linux：显示接口配置（含 MAC）
ifconfig en0        # macOS：只看 en0 接口
ip addr             # Linux：现代推荐写法（iproute2）
```

- **平台对照**：Windows 用 ipconfig；macOS/Linux 用 ifconfig、Linux 常用 ip addr（ip 命令正在取代 ifconfig）。
- **Windows 补充操作**：ipconfig /release 与 ipconfig /renew（DHCP 重新获取）、ipconfig /flushdns（清 DNS 缓存）。

> 排障要点：**先确认本机拿到的是不是预期网段的 IP**——IP 为 169.254.x.x（Windows）说明 DHCP 失败；网关地址配错则"能发不能收"。



#### tracert 与 traceroute：跟踪路径

**tracert（Windows）/traceroute（macOS/Linux）**：跟踪数据包到达目标所经过的**每一跳路由器**，利用 IP 首部 TTL 逐跳递减、超时返回 ICMP 差错报文的原理实现，用于**定位故障在哪一跳**。

- **用途示例**：

```text
tracert baidu.com        # Windows
traceroute baidu.com     # macOS/Linux（macOS 需 sudo 才能看到完整路径）
traceroute -I baidu.com  # Linux：用 ICMP 方式穿越禁 UDP 的中间设备
```

- **平台对照**：Windows 为 tracert；macOS/Linux 为 traceroute。
- **结果判读**：某跳 * * * 超时——该节点不响应探测（可能禁 ICMP）或确有问题；能继续到达目标且后续正常则多为中间设备不回显；卡在某跳且后续全超时——故障点很可能在这一跳附近。

> 排障要点：**tracert 回答"路通到哪儿断了"**——配合 ping 网关、ping 公网 IP，可把故障范围从"链路、路由、防火墙"中逐层剥离。



#### arp：查看与操作 ARP 缓存

**arp**：查看与操作本机的 **ARP 缓存**，即 **IP 地址与 MAC 地址的映射表**，用于排查"二层邻居可达性"与 ARP 欺骗等异常。

- **用途示例**：

```text
arp -a              # 查看全部 ARP 表项（Windows/macOS/Linux 通用）
arp -d IP地址        # 删除某个缓存项（Windows/Linux），macOS 用 arp -d IP
```

- **平台对照**：arp -a 三平台通用；Windows 还有 arp -s IP MAC 静态绑定（需管理员）。
- **结果判读**：网关表项的 MAC 是否正常——若网关 IP 对应的 MAC 与预期不符或频繁变化，可能存在 **ARP 欺骗**（见第 23 章）；incomplete 表项表示解析失败（对方不存在或链路异常）。

> 排障要点：**ping 通但上网异常时，先 arp -a 看网关 MAC**——MAC 被篡改是内网中间人攻击的典型信号。



#### route：查看与修改路由表

**route**：查看与修改本机的**路由表**，判断数据包按哪条路径转发，必要时增删路由。

- **用途示例**：

```text
route print          # Windows：打印路由表
route -n             # macOS/Linux：以数字形式显示（不反查域名）
ip route             # Linux：现代推荐写法
route add 目标 网关   # 添加路由（各平台语法有差异，需管理员）
```

- **平台对照**：Windows 用 route print；macOS/Linux 用 route -n 或 ip route。
- **结果判读**：默认路由（0.0.0.0/0 或 default）是否存在、指向哪台网关——默认路由丢失会导致"能上内网不能上外网"。

> 排障要点：**"不通"先查默认路由**——默认路由缺失、错误或指向不可达网关，是"内网通、外网断"的最常见原因之一。



#### nslookup：查询 DNS 记录

**nslookup**：查询 DNS，获取**域名与 IP 的映射**及其它资源记录，也可**指定 DNS 服务器**进行对比测试。

- **用途示例**：

```text
nslookup baidu.com            # 用本机配置的 DNS 解析
nslookup baidu.com 8.8.8.8    # 指定用 8.8.8.8 解析（对比是否被污染）
nslookup -type=MX qq.com      # 查询 MX 记录（Windows/macOS 支持）
dig qq.com MX                 # macOS/Linux：功能更强的 dig
```

- **平台对照**：Windows、macOS、Linux 均支持 nslookup；macOS/Linux 额外推荐 dig（信息更全）。
- **结果判读**：返回 IP 正常——解析没问题；Non-authoritative answer 为缓存结果；server can't find 表示域名不存在或服务器异常；同一域名用不同 DNS 结果不同——可能存在 DNS 污染或配置不一致。

> 排障要点：**解析不出时，分别用默认 DNS 与公共 DNS（8.8.8.8/114.114.114.114）对比**——默认 DNS 失败而公共 DNS 成功，问题在本机 DNS 配置或本地 DNS 服务；反之可能被污染。



#### netstat：查看连接与端口

**netstat**：显示**网络连接、端口监听、路由表与接口统计**，用于查看"哪些端口在监听、连接处于什么状态、谁占用了端口"。

- **用途示例**：

```text
netstat -ano        # Windows：所有连接与端口，-o 显示占用进程 PID
netstat -an         # macOS/Linux：所有连接（数字显示）
netstat -antp       # Linux：显示 TCP 连接与进程（需 sudo 看全部）
ss -tlnp            # Linux：现代替代 netstat 的 ss
lsof -i :8080       # macOS/Linux：查看占用 8080 端口的进程
```

- **平台对照**：Windows 用 netstat -ano（配合任务管理器按 PID 查进程）；macOS/Linux 用 netstat -an，也可用 ss、lsof、nstat 等。
- **状态判读**：LISTEN 表示服务在监听；ESTABLISHED 是正常连接；大量 TIME_WAIT/CLOSE_WAIT/SYN_RCVD 的含义见第 20 章连接释放排障。

> 排障要点：**"服务起没起"看 LISTEN，"连接正不正常"看 ESTABLISHED 与异常堆积状态，"端口被谁占"看 PID 与进程**。netstat 是本地排障使用率最高的命令。



#### net：Windows 网络管理命令

**net**：Windows 内置的**网络服务管理命令**，可管理网络共享、用户账户、网络服务与映射网络驱动器等。

- **用途示例**：

```text
net use \\server\share           # 连接网络共享
net use Z: \\server\share        # 把共享映射为本地盘符 Z
net share                        # 查看本机共享
net user                          # 查看/管理用户（net user 用户名）
net start/stop 服务名            # 启动/停止 Windows 服务（需管理员）
```

- **平台对照**：net 主要面向 Windows；macOS/Linux 无对应命令，相关操作由 mount、smbutil、systemctl 等承担。

> 提示：net 系列命令把 Windows 的资源共享、用户与服务管理收拢到命令行，适合批量脚本化；考试与跨平台对照中记住它是"Windows 专属"即可。



### 排障思路

#### 分层排障法

**分层排障法**：按照 TCP/IP 层次**自底向上**（物理→链路→网络→传输→应用）逐层验证，先排除低层问题再排查高层，是最通用的排障框架。

- **物理/链路层**：网线、无线是否连接，接口 up/down，本机能否 ping 通网关（二层内邻居）。
- **网络层**：ping 通网关后 ping 公网 IP——判断三层路由是否可达、默认路由是否正确。
- **传输与安全层**：用 telnet/nc 测目标端口——判断服务是否监听、防火墙是否放行。
- **应用层**：用 nslookup 验证解析，再用浏览器/curl 测试服务本身（配置、权限、后端）。

> 口诀：**"先通后断、由近及远、从底到顶"**——每一层验证通过才进入上一层，卡在哪一层，故障范围就圈定在哪一层。



#### 通用排查链路

一套"拿来即用"的标准排查顺序，覆盖八成常见故障：

```text
1. ping 网关 192.168.1.1       → 本机与局域网是否连通
2. ping 公网 IP（如 223.5.5.5）→ 外网连通性（跳过 DNS 干扰）
3. nslookup baidu.com          → DNS 解析是否正常
4. ping baidu.com              → 域名可达性（解析 + 路由综合）
5. telnet 目标 端口            → 目标服务端口是否开放
6. tracert 目标               → 定位故障在哪一跳
7. netstat / lsof             → 检查本机端口监听与连接状态
```

- 第 2 步用 IP 而非域名，是为了**把 DNS 因素先隔离出去**：IP 通而域名不通，问题基本在解析；IP 不通则继续往上追路由。
- 中间任何一步失败，结合"分层排障"回到该层细查（配置、防火墙、设备状态）。

> 核心思想：**用"隔离变量"的方式做二分定位**——把 DNS、路由、端口、服务逐项从怀疑列表里排除，剩下的就是根因所在。



#### 常见故障现象速查

按现象归纳最常出现的判断路径：

- **完全上不了网，内网也 ping 不通网关**：物理链路、网卡驱动或 IP 配置问题——查接口状态、ipconfig、网线/无线。
- **内网通、外网不通**：默认路由缺失/错误、公网出口防火墙或运营商故障——查 route print、ping 公网 IP。
- **IP 能通、域名不通**：DNS 配置错误、DNS 服务器故障或污染——换公共 DNS 对比，清本地缓存。
- **域名能解析、网页打不开**：目标端口被防火墙拦截或服务异常——telnet 目标 80/443 验证端口。
- **能上 QQ 打不开网页（旧式判断）**：网页依赖 DNS 与 HTTP 端口，QQ 仅需可达 UDP/TCP 部分端口——多为 DNS 或 HTTP 代理问题（现代 App 加密后此判断已不精确）。
- **慢而不通（时延大、丢包高）**：链路拥塞、无线干扰、MTU 问题——ping -c 100 观察丢包率，tracert 看在哪跳劣化，必要时测 MTU。
- **某些端口反复异常堆积状态**：应用层问题——查 netstat 中 CLOSE_WAIT（代码没关连接）与 TIME_WAIT（短连接过多）等。

> 兜底建议：**三层循环"测连通→查解析→探端口"后仍无头绪，启用抓包**（Wireshark/tcpdump）看报文实际走到哪一步、有没有被重置——抓包是排障的最终裁判。



#### 抓包与验证：排障的最后手段

**抓包（packet capture）**：捕获并分析网卡进出的真实报文，直接观察协议交互过程，是定位疑难问题与验证学习结论的利器。

- 工具：**Wireshark**（图形化）、**tcpdump**（命令行，服务器排障首选）。
- 典型场景：
  - 验证 TCP 三次握手/四次挥手：访问一个 HTTPS 站点，过滤 tcp.port == 443 观察 SYN/SYN-ACK/ACK 与 FIN 序列。
  - 分析 HTTP 慢：过滤 HTTP 请求，看 TCP 重传率与 RTT 波动。
  - 排查"连不上"：看是 TCP RST（被拒/被防火墙拦）还是超时无响应（丢包）。
- 学习建议：抓一次本机 ping（看 ICMP）、一次网页访问（看 DNS + TCP + TLS + HTTP 全链路），协议的学习效果远胜背书。

> 收束：**命令是"听诊器"，分层法则是"问诊流程"，抓包是"透视检查"**。熟练组合三者，排障就从"猜"变成了"验证"。
