## ARP、DHCP、ICMP 与 NAT

### ARP 地址解析协议

#### ARP 的作用与工作流程

**ARP（Address Resolution Protocol，地址解析协议）**：在已知同一网段内某主机的 IP 地址时，通过广播查询来获取其 MAC 地址的协议，用于把“逻辑的 IP”解析为“链路层通信必需的 MAC”。

ARP 的一次完整解析分四步：

1. 发送方先查本机 **ARP 缓存**（IP 与 MAC 的映射表），命中则直接使用，无需广播。
2. 缓存未命中，则向本网段**广播 ARP 请求报文**，内容为“谁的 IP 是 192.168.1.8？请把 MAC 告诉我”，请求中携带自己的 IP 与 MAC。
3. 网段内所有主机都收到该广播，检查目的 IP 是否与自身一致：不一致则丢弃；**一致的主机把自己的 MAC 地址以单播回送 ARP 响应**，并顺带学习发送方的 IP-MAC 映射（已有则刷新）。
4. 发送方收到响应后把映射写入 ARP 缓存（带超时时间），随后开始传输数据；若多次重试仍无响应，则 ARP 解析失败、通信无法建立。

> 关键特征：**请求是广播，响应是单播**。另外请求中的“目标 MAC”字段为空（以太网广播地址为 FF-FF-FF-FF-FF-FF），靠“广播帧内点名 IP”来定位目标。

#### ARP 报文格式

**ARP 报文直接封装在链路层帧中传输，不经过 IP 层**，以太网帧中的类型字段为 0x0806。报文共 28 字节，字段如下：

- **硬件类型**（2 字节）：链路层类型，以太网取 1。
- **协议类型**（2 字节）：要解析的网络层协议，IPv4 取 0x0800。
- **硬件地址长度**（1 字节）：MAC 地址长度，取 6。
- **协议地址长度**（1 字节）：IPv4 地址长度，取 4。
- **操作码**（2 字节）：区分报文类型，1 为请求、2 为响应。
- **发送方 MAC 地址**（6 字节）：请求/响应方自己的 MAC。
- **发送方 IP 地址**（4 字节）：请求/响应方自己的 IP。
- **目标 MAC 地址**（6 字节）：请求时填 0（未知），响应时填对方 MAC。
- **目标 IP 地址**（4 字节）：请求时填待解析的 IP，响应时填对方 IP。

> ARP 报文并不封装在 IP 数据报中，因此常说“**ARP 工作在网络层与链路层之间**”：它解析的是 IP，走的却是链路层的广播。这使 ARP 在本机尚未配好 IP 时（如 DHCP 阶段）也能使用。

#### ARP 缓存、免费 ARP 与安全性

**ARP 缓存**：保存近期解析得到的 IP-MAC 映射，条目设有超时时间（典型值为几分钟），过期自动删除，避免映射失效后长期占用。

- **免费 ARP（Gratuitous ARP）**：主机开机或更改 IP 后主动广播一条“我的 IP 是 X、MAC 是 Y”的请求，作用有两个——**向网内宣告自己的地址映射，以及探测是否有别的机器正在使用同一 IP**（若收到回应说明地址冲突）。
- **静态 ARP**：管理员手工把关键主机（如网关）的 IP 与 MAC 绑定，防止被伪造的应答篡改。

> 安全性考点：**ARP 欺骗**通过伪造 ARP 请求/应答，把受害者的 IP 指向攻击者 MAC，污染缓存后截获流量。防御手段包括静态绑定、端口安全以及交换机上的动态 ARP 检测（DAI）。

#### 跨网段通信：解析网关的 MAC

**当源与目的不在同一网段时，源主机不解析目的主机的 MAC，而是先解析默认网关（路由器）的 MAC**，把数据帧发给网关，由路由器逐跳转发。

- 主机先用子网掩码判断目的 IP 是否属于本网络：属于则直接 ARP 目的主机；不属于则把帧交给默认网关。
- 路由器每转发一跳，都重新用 ARP 解析“下一跳路由器或最终目的主机”的 MAC，并把帧头中的源 MAC、目的 MAC 改写。
- **源 IP 与目的 IP 在整个传输过程中始终不变，MAC 地址则随链路逐段更换**——这正是“IP 负责端到端定位、MAC 负责逐链路投递”的分工。

> [!WARNING]
> **理解误区**：跨网段通信“ARP 找不到目的主机”很正常——**ARP 永远只解析“同一条链路上能直接到达的邻居”（含网关）**，无法也不应解析跨网段的设备。解析到网关 MAC 后，剩下的事由路由器接力完成。

### DHCP 动态主机配置协议

#### DHCP 的定位与封装

**DHCP（Dynamic Host Configuration Protocol，动态主机配置协议）**：是让主机在启动时自动获得网络配置的应用层协议，主机把 IP 设为“自动获取”时即通过它得到可用的 IP 地址，无需手工配置。

- DHCP 基于 UDP 工作：**服务器监听 67 号端口，客户机使用 68 号端口**。
- 客户机尚未取得 IP，发送广播时用 **0.0.0.0 作源地址、255.255.255.255 作目的地址**。
- DHCP 由更早的 BOOTP 发展而来，能动态分配、回收地址并支持租期。
- 家用路由器内置的“DHCP 服务器”功能，就是给手机、电脑自动分配 192.168.x.x 之类的私有地址。

> DHCP 报文本身是应用层报文，但它的存在是为了配置网络层：客户机在“没有 IP”的前提下用广播与服务器通信，属于“先有鸡还是先有蛋”问题的标准解法——通过链路层广播完成首次配置。

#### DORA 四步交互

**DHCP 分配地址的过程缩写为 DORA，共四步**：发现、提供、请求、确认。

1. **Discover（发现）**：客户机以广播（源 0.0.0.0:68，目的 255.255.255.255:67）寻找网内的 DHCP 服务器。
2. **Offer（提供）**：收到发现的服务器广播（或单播）一个“候选 IP”及配置参数，供客户机挑选。
3. **Request（请求）**：客户机广播 Request 报文，声明“我选择某个服务器给出的地址”——以广播方式发出，既让被选中的服务器确认，也让其它未选中的服务器回收自己提供的地址。
4. **ACK（确认）**：被选中的服务器广播（或单播）确认报文，正式把地址及配套参数租给客户机，客户机即可使用该 IP 上网。

> 只有 Discover 与 Request 一定是广播；Offer 与 ACK 视网络环境可广播也可单播。客户机在 Request 阶段广播，是为了**同时告诉多个 Offer 服务器“我选了谁”**，未中选者即可把候选地址释放。

#### 客户机获得的四类信息与租期

**一个通过 DHCP 入网的新主机可获得四类关键信息：本机 IP 地址、子网掩码、默认网关地址、DNS 服务器地址。**

- 除四类信息外，ACK 还携带**租期（lease time）**，主机只能在该期限内使用地址。
- 租期过半时客户机会单播请求续租（延长租期），续租失败则到期释放地址。
- 相比手工静态配置，DHCP 免去逐台配置、避免地址冲突、提高地址复用率，适用于主机数量多且经常变动的网络。

> 经典问法：新主机插上网线后“什么都不知道”却能上网，靠的就是 DHCP 先分到 IP、再向默认网关与 DNS 发起后续通信。DHCP 分配的地址通常是私有地址，上网还需 NAT（见本文件后文）。

### ICMP 互联网控制报文协议

#### ICMP 的定位

**ICMP（Internet Control Message Protocol，互联网控制报文协议）**：是 IP 层的配套协议，用于在主机与路由器之间传递**差错报告与网络询问**等控制消息，回答“网络通不通、主机可达不可达、路由是否可用”之类的问题。

- ICMP 报文封装在 IP 数据报的数据部分传输，IP 首部中的协议号字段取 1。
- ICMP 不传输用户数据，只辅助 IP 工作，本身不保证可靠交付（差错报告也可能丢失）。
- 每个 ICMP 报文的前 4 字节统一为：**类型（1 字节）、代码（1 字节）、校验和（2 字节）**，类型与代码共同决定报文含义。

> ICMP 虽然“坐在 IP 里”，但被普遍视为**网络层的组成部分**——它由 IP 主机/路由器产生和处理，不是独立的传输服务，也不为应用进程提供“端口”。

#### 差错报告报文

**ICMP 差错报告报文**用于报告数据报在传输中遇到的问题，由检测到差错的路由器或目的主机产生。主要类型如下：

- **终点不可达**：网络不可达、主机不可达、协议不可达、端口不可达等（用代码细分），例如路由器找不到去往目的网络的路由时回送。
- **时间超过**：数据报的 TTL 减为 0 被丢弃时，路由器回送超时报文——**traceroute 正是利用这一点**。
- **参数问题**：IP 首部字段值错误或缺少必需选项时回送。
- **改变路由（重定向）**：路由器发现“有更优的下一跳”，通知源主机把去往该目的的分组改从更近的路由器发出。

> [!IMPORTANT]
> **铁律**：**① 对 ICMP 差错报文不再产生新的差错报文**（防止递归风暴）；**② 对 IP 分片的非首片不回送差错报文**（重组完成前无法定位源）；③ 差错报文需携带触发它的 IP 数据报首部及其前 8 字节数据（含端口号），供上层识别是哪个应用进程。早期的**源点抑制（Source Quench）**报文曾用于拥塞告警，现已废弃，见《拥塞控制与 QoS》章。

#### 询问报文

**ICMP 询问报文**用于主动探测网络状态，由请求方发出、被询问方回答，常见的两类是：

- **回送请求与回送回答（echo request / echo reply）**：目的主机收到请求后原样回送回答，用于测试连通性与往返时延。
- **时间戳请求与时间戳回答**：用于获取对方时钟与估算网络时延。

> 询问报文与差错报文的区别：**差错报告“被动发生”，询问报文“主动发出”**。ping 是询问报文最典型的使用场景。

#### ping 与 traceroute 的原理

**ping 命令利用 ICMP 回送请求与回送回答报文测试连通性**：向目的地址发回送请求，收到回送回答即表明本机到目的主机的 IP 层路径可达，并可从时间差估算往返时延 RTT。

**traceroute（Windows 下为 tracert）命令利用 ICMP 超时差错报文逐跳探测路径**：源主机依次把数据报的 TTL 设为 1、2、3……每份数据报到达第 n 跳路由器时 TTL 减为 0，该路由器丢弃它并回送 ICMP 时间超过报文，源主机由此知道第 n 跳路由器的地址与往返时延。

- 探测报文逐跳递增 TTL，直到抵达目的主机为止。
- 经典实现里探测报文用**目的端口不可达的 UDP 数据报**：到达目的主机时因端口不存在而回送 ICMP 端口不可达报文，源据此确认已走完全程；Windows 的 tracert 则默认发 ICMP 回送请求，靠最终的回送回答确认到达。

> [!WARNING]
> **常见误区修正**：ping 用的是 ICMP 回送报文（封装于 IP 之上），**不是 UDP，也不是 TCP**。“ping 不通”只说明 ICMP 层面不通，不必然代表应用层服务不可用。同理，“traceroute 中间某跳无响应”可能只是该路由器不回应超时报文（如防火墙丢弃），不能断定路径中断。

### NAT 与 NAPT

#### NAT 的转换过程与转换表

**NAT（Network Address Translation，网络地址转换）**：是在连接内网与外网的设备（如家用路由器）上，把数据报的 IP 地址在私有地址与公网地址之间改写，使众多私有地址主机共享少量公网地址访问互联网。

NAT 对数据报的处理：

1. **出向**：内网主机发出的数据报到达 NAT 设备时，源地址（私有 IP + 端口）被改写为 NAT 设备的公网 IP 与一个新的端口号，同时把这一映射关系记入 **NAT 转换表**。
2. **入向**：外网返回的数据报到达 NAT 设备时，根据转换表查得真正的内网主机，把目的地址改回私有 IP + 原端口后转发入内网。
3. 转换表中每条表项记录“内网 IP + 端口”与“公网 IP + 端口”的对应关系，并设有超时时间。

> [!NOTE]
> **注意**：NAT 改写的位置——家用场景中改动的是**源地址**（出向）；当内网自建服务器时，也可用**端口映射**把公网特定端口定向转发给内网固定主机（目的地址改写）。NAT 是一个“状态型”设备，必须维护转换表才能把回应报文送回正确的内网主机。

#### NAPT：端口级复用

**NAPT（Network Address Port Translation，网络地址端口转换）**：在转换 IP 的同时转换端口号，使**一个公网 IP 的不同端口对应不同内网主机**，是家用路由器实际采用的“多对一”转换形式。

- 不同内网主机发起连接时，被分配同一个公网 IP 下的不同端口，靠端口区分内网对象。
- 传输层端口号为 16 位，除去系统保留端口，**一个公网地址大约可同时支持 60000 个并行的内外连接**（理论值 65536，扣保留后约 6 万），实际受设备性能与表项容量限制。
- 严格意义的 NAT 只改 IP 不改端口（多对多或一对一共用不充分），NAPT 才是缓解 IPv4 短缺的关键。

#### NAT 的利弊与端口映射

**NAT 的益处与代价并存**，考试常要求两面论述：

- **益处**：缓解 IPv4 地址枯竭；隐藏内网拓扑与主机，外部难以直接定位内网设备，带来一定安全性；网络变更时只需调整边界设备，内网可自由使用私有地址。
- **代价**：**破坏端到端原则**——因特网设计上任何主机应能主动与另一主机通信，NAT 使外部无法主动发起对内网主机的连接；增加设备转发开销；转换表有状态，对部分应用（如 FTP 数据连接、IPSec）不友好，需要额外 ALG（应用层网关）配合。

**端口映射（port forwarding）**：在 NAT 设备上把“公网 IP 的某端口”预先指向“内网某主机的某端口”，使外部能够主动访问内网的服务器等服务。

> 家用场景速记：打游戏连不上、自建网站外网访问不到，多半是 NAT 的端口映射没配好；P2P 软件则常用 UPnP 自动打洞或 NAT 穿透技术绕过“NAT 不允许外部主动接入”的限制。

### RARP 与 IPSec

#### RARP（已淘汰）

**RARP（Reverse Address Resolution Protocol，反向地址解析协议）**：与 ARP 方向相反，根据已知的 MAC 地址反向查找 IP 地址，历史上用于无盘工作站启动时从服务器获取自己的 IP。

- 无盘工作站只有 MAC 没有 IP，开机后广播 RARP 请求，RARP 服务器查表后单播回送对应 IP。
- RARP 只能返回 IP 一个信息，且需逐网段部署服务器、不支持动态分配。
- RARP 已被 **BOOTP 进而被 DHCP 取代，现已淘汰**，了解其“MAC 反查 IP”的思想即可。

> 对比记忆：**ARP 是“已知 IP 求 MAC”，RARP 是“已知 MAC 求 IP”**；前者至今活跃在每条以太网链路上，后者只在网络原理与历史考题中出现。

#### IPSec 提供网络层安全

**IPSec（Internet Protocol Security，互联网协议安全）**：是工作在网络层的安全协议族，在 IP 层直接为数据报提供完整性认证与加密保密，是构建 VPN 的主要技术之一。

- **认证首部 AH（Authentication Header）**：对数据报做来源认证与完整性校验，不加密内容。
- **封装安全载荷 ESP（Encapsulating Security Payload）**：既加密数据又提供认证，是实际最常用的选择。
- 使用场景：两台主机之间、两个网关之间或主机与网关之间的安全通信；因特网密钥交换（IKE）协议负责协商密钥与安全参数。
- IPSec 支持两种封装模式：**传输模式**只保护上层数据（端到端），**隧道模式**把整个 IP 数据报再包一层新 IP 头（网关间常用）。

> 隧道协议按层次记忆：**网络层是 IPSec，链路层有 L2TP/PPTP 一类二层隧道，传输层之上还有 SSL/TLS VPN**。层层隧道技术在实现上共享“封装-穿越-解封装”的思路，只是把隧道建在哪一层不同。
