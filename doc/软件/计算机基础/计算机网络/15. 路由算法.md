## 路由算法

### 路由选择的基本概念

#### 路由与转发

**路由（routing）**：是确定从源主机到目的主机端到端路径的过程，路由器运行路由协议、依据网络拓扑计算出路径并生成路由表，属于“全局决策”。

**转发（forwarding）**：是路由器把收到的分组从输入端口移动到正确输出端口的动作，只查本地转发表、逐分组完成，属于“本地执行”。

- 路由决定“路怎么选”：事先或动态计算，变化较慢，对应**控制平面**。
- 转发决定“包往哪送”：每个分组到达都要立刻完成，对应**数据平面**，追求线速（详见《路由器组成与转发》章）。
- 路由表是转发决策的依据来源：路由算法算出路径后，路由器按“目的网络 → 下一跳/输出端口”组织转发表项。

> 一个形象的区分：路由好比“出行前规划走哪条高速”，转发好比“在每一个路口按路牌打方向盘”。规划可以慢慢想，打方向盘必须一刹那完成。



#### 路由选择的度量

**路由算法需要回答“哪条路径更优”，度量（metric）就是给路径打分的标准**，不同协议选用的度量不同。

- **跳数（hop count）**：经过的路由器个数，RIP 使用，简单但无视链路快慢。
- **带宽（bandwidth）**：OSPF 等常用带宽倒数作代价——链路越宽、代价越低。
- **时延（delay）**：可由往返时间（RTT）实测得到，适合时延敏感业务。
- **费用与可靠性**：运营商会叠加线路租费、可靠性等策略因素。

> 度量不同导致同一网络可能选出不同路径：**按跳数最短的路未必是最快的路**——一个经过 3 跳千兆链路的路由可能优于 2 跳拨号链路。这是 RIP 的固有缺陷，也是 OSPF 引入带宽代价的动机。



#### 路由算法的信息基础与分类

**路由算法主要按“路由器掌握全网信息还是只掌握邻居信息”与“是否随网络动态变化”两个维度划分**。

- 掌握信息范围：**全局式**（如链路状态算法，每台路由器都有全网拓扑）对**分布式**（如距离向量算法，只与邻居交换信息）。
- 是否动态适应：**静态路由**（人工配置）对**动态路由**（协议自动更新）。
- 其它划分角度：单路径对多路径、平面路由对层次路由等。

> 互联网路由协议几乎都是**动态 + 分布式**的：网络规模太大，不可能靠一台设备维护全网状态；拓扑随时变化，人工静态维护不现实。差异只在“邻居间传什么、怎么算”——这引出了 DV 与 LS 两大算法族。



### 静态路由与动态路由

#### 静态路由

**静态路由**：由网络管理员手工把“目的网络 → 下一跳”写入路由器的路由条目，网络拓扑变化时不会自动更新。

- 优点：实现简单、不占用链路带宽与路由器计算资源、路径可控可预期、安全性好。
- 缺点：不能自动适应拓扑变化，链路或节点故障后不会自动绕行，需人工修改。
- 适用场景：网络规模小、拓扑长期稳定，或作为企业出口的**默认路由**，以及配合动态协议做策略性引流。

> 静态路由与动态路由并不互斥：静态路由在路由表中优先级通常更高（管理距离数值更小），动态协议学到的路由与之冲突时以静态为准。如“特定网段走专线（静态）、其余流量走互联网（默认路由）”是常见组合。



#### 动态路由

**动态路由**：路由器运行路由协议（RIP、OSPF、BGP 等），自动学习网络拓扑、定期或触发式交换路由信息，自动更新路由表。

- 优点：能自动适应拓扑变化，链路故障后自动收敛到新路径，适合中大型、变化频繁的网络。
- 缺点：协议本身占用链路带宽与路由器资源，配置与排错更复杂，收敛期间可能出现短暂环路或丢包。

> 静态与动态的对比记忆：**静态“手工、稳定、省资源、不灵活”，动态“自动、灵活、费资源、有收敛期”**。题目问“某小型稳定网络选什么”，优先静态；问“大型网络自动适应故障”，选动态。



### 距离向量 DV 算法

#### DV 的基本思想与 Bellman-Ford 方程

**距离向量算法（Distance-Vector，DV）**：每个节点只掌握“自己到各直连邻居的费用”与“邻居通告的距离向量”，周期性地把自己维护的“到所有目的节点的距离表（距离向量）”发给**邻居**，再依据收到的邻居向量更新自己的表。

- 节点最终会收敛到正确距离，但每个节点对全网拓扑的了解是“邻居转述的”，即**间接获知、道听途说**。
- DV 更新依据 **Bellman-Ford（B-F）方程**：

```text
Dx(y) = min_v { c(x, v) + Dv(y) }

Dx(y)：节点 x 到目的 y 的最短距离
c(x, v)：x 到直连邻居 v 的链路费用
Dv(y)：邻居 v 通告的“v 到 y 的距离”
min_v：遍历所有直连邻居 v 取最小
```

- 算法特征：**分布式**（各节点独立计算）、**迭代**（不断交换更新）、**异步**（无需全局同步）、且在网络稳定时**自终止**（无变化即停止通告）。

用一个三角形拓扑说明：节点 X 与 Y 直连费用 2，X 与 Z 直连费用 7，Y 与 Z 直连费用 1。

1. 初始：X 只知道直连路径，认为到 Z 是 7。
2. Y 通告自己的向量（Y→Z 为 1）后，X 用 B-F 方程计算：到 Z 取 min(7, 2 + 1) = 3。
3. X 更新到 Z 的距离为 3，下一跳改为 Y，并把新向量再通告给邻居。

> B-F 方程揭示了 DV 的本质：**“到远方的最优路径 = 先走到某个邻居 + 邻居声称的最优后续”**。X 从未直接测量过 X-Z 链路，却借 Y 的转述得出了更优路径——这就是“间接信息”的力量，也是“坏消息传播慢”的根源。



#### 好消息传播快、坏消息传播慢

**DV 收敛的不对称性**：链路状态变好（出现捷径）时，好消息一跳一跳传遍全网，收敛很快；链路断开等坏消息却可能因“路由环路”被拖延，甚至陷入**计数到无穷（count to infinity）**。

坏消息传播慢的原因：

1. 链路断开后，两端节点立即知道自己无法直连，但邻居的路由表里还保存着“经对方可达”的旧条目。
2. 双方交换向量时互相“借鉴”，各自以为对方那里还有路，距离值每轮加 1、来回上涨，而不是直接归为无穷。
3. 若没有上限，这个循环会永远进行下去；即使设了上限（如 16），也需要很多轮才能“数到顶”。

```text
A 通过 B 到达 C（B 通告 C 距离 2，A 记为 3）
A—B 链路断开，A 不再直达 B，但 B 仍通告“C 距我 2，经 A”……
A、B 相互把对方当下一跳，到 C 的距离每轮 +1：3、4、5、6……
直到超过“无穷”上限（RIP 中为 16）才宣告不可达
```

> 总结成一句话：**“好消息是跑得快的信使，坏消息是绕圈的坏消息”**——捷径一经发现迅速全网皆知，断路却要经过漫长的“逐轮 +1”才被认清。



#### 防止环路的措施

**DV 需要专门的防环机制来抑制计数到无穷**，常用手段如下：

- **水平分割（split horizon）**：从某邻居学到的路由，**不再通告回该邻居**，切断“我告诉你的又被你告诉我”的回路。
- **毒性反转（poisoned reverse）**：比水平分割更进一步，把“从某邻居学到的路由”**以距离无穷大的形式**通告给该邻居，明确告诉它“这条路不能经我走”。
- **触发更新（triggered update）**：拓扑发生变化时立即发送更新，而不是等固定周期，缩短坏消息的传播时延。
- **定义无穷大**：给距离设上限（RIP 定为 16，即最大跳数 15），坏消息最坏只需“数到 16”即判不可达，从时间上封顶。

> [!IMPORTANT]
> **必须强调的局限**：**水平分割与毒性反转只能防止“两人互指”的直接环路，无法根治更复杂拓扑下的计数到无穷**，还需要触发更新与“无穷”上限配合兜底。考试问“RIP 如何防环”，按上述四点作答，其中“16 即无穷”是最高频的考点。



### 链路状态 LS 算法

#### LS 的基本思想

**链路状态算法（Link-State，LS）**：每台路由器亲自测量自己到直连邻居的链路费用，把结果封装成**链路状态分组（LSP）**向全网**泛洪**，使每台路由器都掌握全网拓扑与费用，再独立用 **Dijkstra 算法**计算以自己为根的最短路径树（SPT），进而导出路由表。

- 信息来源可靠：所有链路费用都是**自己实测或邻居直接宣告**的，不存在 DV 那种“转述再转述”。
- 计算集中：各路由器拿到一致的拓扑数据库后各自独立计算，结果天然无环。
- 泛洪是代价：每个 LSP 要传遍全网，报文数量与网络规模成正比。

> DV 与 LS 的信息哲学对比：**DV 是“只跟邻居说悄悄话，路况靠听来的”，LS 是“把自己的家门口情况广播给全世界，然后自己拼地图”**。前者省通信但易被骗，后者通信量大但所见即真实。



#### LSP 的内容与新旧判定

**链路状态分组（Link State Packet，LSP）**：是 LS 算法中承载“节点与其直连邻居的链路状态”的报文，泛洪到全网。

LSP 携带的信息：

- **发送方标识**：产生该 LSP 的路由器。
- **序列号**：标识 LSP 的新旧程度。
- **年龄（age）**：随时间递减，减到 0 视为过期并删除，防止失效 LSP 在网络中无限滞留。
- **邻居列表及链路费用**：发送方到各直连邻居的费用（与邻居可达性信息）。

**新旧判定规则**：收到 LSP 后，路由器先比较序列号——**比本地存的更新则接收并继续泛洪，相同则丢弃重复，更旧则拒绝**，从而保证全网的链路状态数据库最终一致。

> 可靠性设计：单靠一次泛洪可能丢包，LS 协议通常**周期性重发 LSP**，配合“年龄”超时清理；序列号用尽后回绕，是比较新旧时需处理的边界问题。这些机制保证“全网一致地掌握拓扑”这一前提成立。



#### Dijkstra 算法

**Dijkstra 算法**：是 LS 算法中集中式计算最短路径的经典算法，从源节点出发，每轮在“尚未确定最短路径的节点”中挑一个距离最短者加入已确定集合，并用它松弛其邻居的距离，直至所有节点确定。

计算过程（节点集合 N' 表示“已确定最短路径的节点”）：

1. 初始化：N' 只含源节点，源到各邻居的距离取其直连费用，其余记为无穷。
2. 重复执行：在 N' 之外的节点中，选“经 N' 内某节点可达、且当前距离最小”的节点 w 加入 N'。
3. 松弛：对 w 的每个不在 N' 中的邻居 v，若“源到 w 的距离 + w 到 v 的费用”更小，则更新 v 的距离并记录前驱。
4. 直到所有节点都加入 N'，算法结束，得到以源为根的最短路径树。

以节点 u 为源的 6 节点网络为例（直连费用：u-v 为 2、u-w 为 5、u-x 为 1，v-x 为 2、v-w 为 3，w-x 为 3、w-y 为 1、w-z 为 5，x-y 为 1，y-z 为 2）：

```text
初始：N' = {u}
      d(v) = 2   d(w) = 5   d(x) = 1   d(y) = ∞   d(z) = ∞

第 1 轮：选 x（距离 1）
      经 x 松弛：d(w) = min(5, 1+3) = 4，d(y) = 1+1 = 2
第 2 轮：选 v（距离 2）
      经 v 松弛：d(w) = min(4, 2+3) = 4（不变），y、z 经 v 不可达
第 3 轮：选 y（距离 2）
      经 y 松弛：d(w) = min(4, 2+1) = 3，d(z) = 2+2 = 4
第 4 轮：选 w（距离 3）
      经 w 松弛：d(z) = min(4, 3+5) = 4（不变）
第 5 轮：选 z（距离 4），全部节点确定
```

- 由最短路径树可得 u 的路由表：到 v 下一跳为 v，到 w 下一跳为 x（u→x→y→w），到 z 下一跳为 x（u→x→y→z）。
- 算法要求链路费用非负，复杂度约为 O(n^2)（n 为节点数），可用优先队列优化。

> 与 B-F 方程的区别：**B-F 方程是“分布式地、逐跳套公式”更新，Dijkstra 是“集中式地、拿到全图后一次算完”**。两者都能求出最短路径，但前者靠节点间迭代逼近，后者靠完整的拓扑一次性确定。



### 距离向量与链路状态的对比

**DV 与 LS 是两类完全不同的路由算法设计，从信息基础到故障表现处处对照**：

- **信息交换范围**：DV 只与邻居交换／LS 向全网泛洪链路状态。
- **交换内容**：DV 交换“到各目的的距离估计”（间接信息）／LS 交换“直连链路的费用”（实测信息）。
- **掌握的拓扑**：DV 只知道邻居及距离，不知道全网结构／LS 每台路由器都有全网一致的拓扑数据库。
- **收敛速度**：DV 慢，坏消息可能计数到无穷／LS 快，全网同步后一次算清。
- **环路风险**：DV 收敛期间可能产生瞬时环路／LS 以自己为根算出的路径天然无环。
- **健壮性**：DV 中某个节点广播错误距离会污染全网（“一步错、步步错”）／LS 中节点算错或 LSP 有误只影响以它为根的计算，影响面小、易排查。
- **报文开销**：DV 报文体积与网络规模成正比且周期发送／LS 泛洪报文数量与网络规模成正比，各有适用场景。

> 一句话对照速记：**DV 靠“邻居口口相传、逐跳逼近”（信息少、通信省、收敛慢、易成环），LS 靠“全网广播、自己算图”（信息全、通信多、收敛快、无环）**。RIP 是 DV 的代表，OSPF 是 LS 的代表，两者之争的细节见《路由协议：RIP、OSPF 与 BGP》章。



### 层次路由

#### 自治系统与两层路由

**自治系统（Autonomous System，AS）**：在单一管理机构控制之下、内部使用统一路由策略的一组网络，是路由管理的“管理域”边界。互联网规模与跨组织管理需求催生了按 AS 划分的层次路由。

- 每个 AS 拥有全球唯一的 **AS 号**，AS 之间通过运营商互联。
- 层次路由把全网路由分成两层：**AS 内部**的路由选择与 **AS 之间**的路由选择。
- 分类对应关系：AS 内部运行的协议称**域内路由协议**（或称内部网关协议 IGP），AS 之间运行的称**域间路由协议**（或称外部网关协议 EGP）。

> 为什么要分层：若把全互联网当作一张图用 LS 算法全网泛洪，报文量与计算量完全不可承受；且不同机构互不信任，也不可能共享内部拓扑。**层次路由把“能自治的归内部、讲策略的归边界”，用两层路由换取可扩展性与管理可行性**。



#### IGP 与 EGP

**IGP（Interior Gateway Protocol，内部网关协议）**：运行在 AS 内部的路由协议，追求“域内最短路径”，典型有 RIP、OSPF、IS-IS。

**EGP（Exterior Gateway Protocol，外部网关协议）**：运行在 AS 之间的路由协议，关心的不是“最短”，而是“可达性与策略”（商业合同、安全过滤、流量工程），目前实际使用的只有 BGP。

- IGP 内部可以放心追求最优度量，因为同属一个管理域、拓扑相对小且可控。
- EGP 面对的是互相独立甚至互相竞争的 AS：各 AS 不愿暴露内部拓扑，只对外通告“我可达哪些前缀、经哪些 AS 到达”，用**策略**决定放行与选路。
- 由此路由协议形成了清晰的谱系：RIP、OSPF、IS-IS 解决“AS 内怎么走最快”，BGP 解决“AS 间让不让走、走哪家”。

> 易混点澄清：**IGP 与 EGP 是按"运行范围"分类，距离向量与链路状态是按"算法思想"分类**——RIP 是"域内 + 距离向量"，OSPF 是"域内 + 链路状态"，BGP 是"域间 + 路径向量"，三个标签分别回答"在哪用、怎么算、传什么"。BGP 的具体机制详见《路由协议：RIP、OSPF 与 BGP》章。



### 路由表更新与代价的典型计算

路由算法最常考的是"距离向量算法的路由表更新"与"迪杰斯特拉/链路状态求最短路径"两类计算。

**距离向量更新示例**：设路由 X 从邻居 Y 收到 Y 的路由表，Y 到目的 N 的距离为 d(Y,N)，X 到 Y 的距离为 d(X,Y)。若 N 不是 X 的直连或 X 到 N 的现路由并不经过 Y，则更新规则为：

- 若 d(X,Y) + d(Y,N) < 当前 d(X,N)：用 X 经 Y 到 N 的新路径，下一跳改为 Y，距离取两者之和。
- 若 X 现有的到 N 的路径恰好经过 Y：无论新距离大小都更新为 d(X,Y) + d(Y,N)（因 Y 的距离可能已变化）。

**数值示例**：X 到 Y 为 2，Y 通告"到 N 距离为 5"。

- X 到 N 现为 8（经 Z），8 > 2 + 5 = 7，故更新为经 Y、距离 7。
- 若 X 到 N 现为 6 但正是经 Y，6 虽小于 7 仍须更新为 7（Y 自己到 N 变了）。

> [!WARNING]
> 警告内容：距离向量更新的经典误区——**"我当前路径若经过该邻居，则必须无条件用新通告的距离"**，这是为了防止"好消息快传、坏消息慢传"导致的无穷计数。若当前路径不经过该邻居，才按"更小才更新"的原则。做表更新题时先判断"现路径下一跳是不是这个邻居"，再决定无条件更新还是比大小更新。

**链路状态（迪杰斯特拉）示例**：求源 A 到各点的最短路径，逐步把"已确定最短距离"的结点加入集合，并松弛其邻接点的候选距离，重复直到覆盖全部结点。每一步记录"到哪个点、距离多少、经谁"，据此得到最短路径树与转发表。

> **常考角度**：给定各邻居的距离向量做"逐表更新判断下一跳与距离"；或给一个带权拓扑手推最短路径树并填转发表；判断"坏消息传播慢（无穷计数）"是距离向量的固有缺点，链路状态用洪泛全网拓扑规避之。
