## 线性表

> **全章主脉**：线性表是**由 n 个相同类型数据元素构成的有限序列**，是最基本、最常用的一类数据结构。本章讲清线性表的**逻辑结构、顺序表（顺序存储）与链表（链式存储）**两大实现，以及循环链表、双向链表、静态链表。核心是**顺序表"随机存取但插入删除要移元素"、链表"插入删除快但不能随机"**的对比，以及单链表指针操作。

### 线性表的定义与基本操作

#### 线性表的逻辑结构

**线性表**是**由 n（n 大于等于 0）个相同类型数据元素构成的有限序列**。n 为线性表的长度，n 等于 0 时为空表。除第一个元素外，每个元素都有且仅有一个**直接前驱**；除最后一个元素外，每个元素都有且仅有一个**直接后继**——元素之间存在**一对一**的线性关系。

**线性表的特点**：

- 元素**个数有限**、元素类型相同。
- 元素之间有**先后次序**，是**序列**（有序），位置即逻辑次序。
- 表中每个元素（非首非尾）有**唯一直接前驱与直接后继**。

**基本操作**：在表尾插入、在表头/表中插入、删除指定位置元素、按值/按位查找、求表长、判空等。

> [!NOTE]
> 提醒内容：线性表的"线性"指元素之间的**逻辑关系是一对一的先后序列**，与存储方式无关——它既可用顺序表也可用链表实现。区分"线性表（逻辑结构）"与"顺序表/链表（存储实现）"。

#### 顺序存储与链式存储的比较

**顺序存储（顺序表）**把元素存放在**地址连续**的存储单元中；**链式存储（链表）**用指针把元素串起来、物理上可不相邻。两者在存取、插入删除与空间利用上各有优劣。

- **随机存取**：顺序表可**按位 O(1)** 直接访问（下标算地址）；链表必须**从头遍历 O(n)**，不能随机。
- **插入删除**：顺序表插入/删除要**移动大量元素** O(n)；链表只需**改指针** O(1)（若已知位置）。
- **空间**：顺序表需**预分配连续空间**、容量固定易浪费或溢出；链表**动态分配**、按需占空间但每结点**多存一个指针**、空间开销大。
- **适用**：查找/按位访问多、元素少变动用顺序表；频繁插入删除、表长不定用链表。

> [!IMPORTANT]
> 重要内容：核心对比一句话——**顺序表"以移动换随机存取"，链表"以指针换插入删除"**。判断选型看操作特征：常按下标访问（如读第 i 个）选顺序；常增删（如合并两表、逆置）选链表。复杂度上顺序表查找 O(1)、链表查找 O(n)；但已知位置插入删除则顺序表 O(n)、链表 O(1)。

### 顺序表

#### 顺序表的存储与基本操作

**顺序表**是**用一组地址连续的存储单元依次存放线性表元素**的存储结构，逻辑上相邻的元素物理位置也相邻。通常用一维数组实现，另设一个变量记录当前表长（已用元素个数）。

**顺序表的关键点**：

- **随机存取**：第 i 个元素地址等于 基址 加 (i 减 1) 乘 元素大小，可 O(1) 访问任意元素。
- **表长与容量**：表长是实际元素个数，容量是数组能容纳的最大个数；表长小于等于容量，表长达到容量时再插入需扩容。
- **基本操作**：按位/按值查找 O(n) 最坏、在表尾插入 O(1)、在表中插入与删除需移动元素 O(n)。

> [!NOTE]
> 提醒内容：顺序表用数组实现，**下标从 0 或 1 起**要注意（教材常从 1 起讨论逻辑位序，实际数组从 0）。随机存取指"给定位置直接算出地址"，这是顺序表相对链表最大的优势。

#### 插入与删除的移动元素次数分析

**顺序表插入**在位置 i 插入一个元素时，需**把原位置 i 及之后的所有元素依次后移一位**腾出空位；**删除位置 i 的元素时，需把其后所有元素依次前移一位**。移动元素的平均次数与插入/删除位置有关，均为 O(n)。

- **插入到表尾**：不需移动，O(1)。
- **插入到表头/位置 1**：移动 n 个元素，最坏 O(n)。
- **平均移动次数**：在 n 个元素的顺序表中等概率插入到任意位置（含表尾共 n 加 1 个可能位置），平均移动 n/2 个元素；删除平均移动 (n 减 1)/2 个元素。
- **时间复杂度**：插入与删除平均与最坏都是 **O(n)**（除表尾特殊）。

> [!WARNING]
> 警告内容：顺序表插入/删除的**平均移动次数约 n/2（插入）、(n−1)/2（删除）**，是常考填空题。插入有 n 加 1 个位置可选（表尾也算），删除只有 n 个位置（表尾删后无元素后移）。求平均移动次数别把"表尾插入移动 0 个"漏算。复杂度整体判 O(n)。

### 单链表

#### 头指针与头结点

**单链表**用**一组地址任意（可不相邻）的存储单元存放线性表元素**，每个结点由**数据域（存元素）与指针域（存下一结点地址）**组成。单链表的存取只能从头开始，靠指针域逐个向后"链"。

**头指针**是指向**链表第一个结点**的指针，是链表的**必要标识**（判空、遍历都靠它）。**头结点**是在第一个元素结点之前**额外附加的一个结点**，其指针域指向首元素结点。

- **带头结点**：头指针指向头结点，头结点后才是首元素；判空看头结点指针域是否为空，插入/删除首结点不需特殊处理头指针。
- **不带头结点**：头指针直接指向首元素结点；对首结点操作时需改动头指针，代码要单独处理。

> [!TIP]
> 建议内容：**头指针必须有（标识链表），头结点可选（统一操作、简化首结点处理）**。考试默认常带头结点。带头结点好处：插入/删除第一个元素与其它位置代码统一，不必单独改头指针。头结点数据域通常闲置或存表长。

#### 单链表的建立、查找、插入与删除

**单链表的基本操作**建立在指针操作之上，核心是**修改 next 指针建立结点间联系**。

- **建立**：**头插法**（新结点插到头结点之后，得到的表与输入顺序相反）与**尾插法**（新结点接到表尾，顺序一致），时间均为 O(n)。
- **按序号/按值查找**：须从首结点**逐个沿 next 遍历**，最坏 O(n)；链表的查找**不能随机**。
- **插入（在 p 结点后插入 s）**：先令 s 的 next 指向 p 的 next，再令 p 的 next 指向 s（**顺序不能反**，否则丢失后继）；已知 p 时插入 O(1)。
- **删除 p 的后继 q**：令 p 的 next 指向 q 的 next，再释放 q；已知 p 时删除 O(1)。

> [!WARNING]
> 警告内容：**插入操作必须先改新结点 s 的 next 再改 p 的 next**（先 s→next = p→next，再 p→next = s），若先改 p 的 next 会丢失原后继。删除则用"p 的 next 指向 p→next→next"一步跳过被删结点。这类指针顺序错误是链表题最易错点。已知前驱结点时链表插入删除是 O(1)，只有**先找前驱**才是 O(n)。

#### 单链表的合并

**单链表的合并**指把两条有序单链表**合并成一条新的有序链表**，是链表应用的经典操作。做法：用尾插法，每次**比较两表当前结点的值，把较小者接到结果链表尾部**，一表取尽后把另一表剩余部分直接接上。

```text
合并两个递增有序单链表 A、B 为 C：
  用指针 pa、pb 分别指向 A、B 当前结点，pc 指向 C 的表尾
  while pa 与 pb 都非空：
    若 pa 的数据 小于等于 pb 的数据：把 pa 接上，pa 后移
    否则：把 pb 接上，pb 后移
 若 pa 非空：把 A 剩余段接上
 若 pb 非空：把 B 剩余段接上
```

**复杂度**：两表各遍历一次，时间 **O(m 加 n)**（m、n 为两表长），空间 O(1)（可复用原结点、不需新建）。合并需改变两表结点的链接，故采用**尾插**依次重构。

> [!NOTE]
> 提醒内容：有序表合并在顺序表与链表上均可做——顺序表合并为 O(m 加 n) 需新开 O(m 加 n) 空间，链表合并可原地 O(1) 空间（改指针）。链式合并后不要忘把结果表尾的 next 置空。

### 循环链表

**循环链表**是**把单链表的最后一个结点的指针域指向头结点（或首结点）**，使整个链表构成一个环，从而可以从任一结点出发遍历到整条表。循环链表分**单向循环链表**与**双向循环链表**。

**循环链表的特点**：

- **判空**：判断尾结点指针是否指向头结点（单向循环）——而非指针域是否为空。
- **遍历不越界**：从任一结点出发都能绕一圈访问所有结点，无需头指针也能访问全表。
- **常设尾指针**：很多操作（在表尾插入、合并两个循环链表、找表尾）用**指向表尾的尾指针**更高效（O(1) 找到头尾）。
- **双向循环链表**：双向链表首尾相连，头结点的前驱指向尾结点、尾结点的后继指向头结点，使找前驱/后继都 O(1)。

> [!IMPORTANT]
> 重要内容：**循环链表把"表尾"和"表头"连成环**——好处是能从任意结点访问全表、找表尾快（设尾指针则 O(1)），代价是判空/判尾方式变化（靠指针是否指回头结点）。双向循环链表结合了双向"找前驱 O(1)"与循环"绕圈遍历"，是最灵活但结构最复杂的链表。

### 双向链表

#### 双向链表的结点结构

**双向链表**的每个结点含**数据域、前驱指针（prior，指向前一结点）与后继指针（next，指向后一结点）**三个部分，从而可以**从任一结点向前或向后**遍历，弥补单链表"只能向后、找前驱要重头扫"的不足。

**双向链表的特点**：

- 每个结点有 **prior 与 next** 两个指针，分别指向直接前驱与直接后继。
- 找某结点的前驱**不必从头遍历**，prior 直接可得（O(1)）。
- **代价**：每个结点比单链表多一个指针域，**空间开销更大**；插入删除操作需同时维护 prior 与 next，**步骤更多、更易错**。

> [!NOTE]
> 提醒内容：双向链表的"双向"解决了单链表**前驱查找 O(n)** 的问题，换来更大的空间与更复杂的插入删除。判断场景：需频繁向前遍历或删除"当前结点"（不需前驱）时，双向链表优势明显。

#### 插入与删除操作

**双向链表的插入与删除**需**同时修改前后两个方向的指针**，比单链表步骤多，关键是别漏改 prior。

**在 p 结点后插入 s 结点**：依次完成 s 的 next 指向 p 的 next、s 的 prior 指向 p、p 的 next 的 prior 指向 s、p 的 next 指向 s 四步，使 s 正确嵌入 p 与其原后继之间。

**删除 p 的后继 q**：令 p 的 next 指向 q 的 next，再令 q 的 next 的 prior 指向 p，最后释放 q。若删除的是 p 本身，则需同时改其前驱的 next 与后继的 prior。

> [!WARNING]
> 警告内容：双向链表插入时**四步指针操作不能漏**——尤其"p 的 next 的 prior 指向 s"这一步若漏改，新结点就断了反向链。删除时同理要把被删结点前驱的 next 与后继的 prior 都改到位。写双向链表操作务必"成对更新 prior 与 next"并注意指针被覆盖前先取值。

### 静态链表

**静态链表**是用**数组**实现的链表：数组的每个分量代表一个结点，含**数据域与游标（cur，存放下一结点在数组中的下标）**，用整数游标代替指针把结点"链"起来。静态链表**既保有了链表"插入删除不需移动元素"的优点，又不需动态分配内存**（用预先分配的数组）。

**静态链表的特点**：

- 结点用数组元素充当，next 用**整型下标（游标）**代替真指针，靠游标实现逻辑上的链接。
- 优点：插入/删除只改游标、不移动元素，适合**无指针/不支持动态内存**的语言（如早期 Pascal、部分嵌入式）或数据量已知的场景。
- 缺点：**容量固定**（数组定长）、不能随机存取、仍需遍历才能查找，且数组空间要事先分配可能浪费。

> [!NOTE]
> 提醒内容：静态链表"**用数组 + 游标模拟链表**"，兼有链式"插入删除不改地址"与静态"不需动态分配"的特点，但牺牲了"动态伸缩"。它常用于文件系统空闲空间管理（游离链表）等。识别静态链表：结点里存的是整数下标而非地址指针。

### 线性表应用

**线性表的应用**广泛，很多复杂数据结构与算法以线性表为基。典型应用包括**多项式的表示与运算、稀疏向量的表示、约瑟夫环问题、表的合并/拆分/逆置**等。

- **多项式**：用顺序表或链表按指数存储系数，链表更利于指数不同时的合并运算。
- **约瑟夫环**：n 人围圈报数出列，可用循环链表模拟，每次移除报数到 k 者，最后剩者为胜。
- **逆置/去重/合并**：常见于顺序表与链表的算法题，考查指针操作与移动元素分析。
- **选型**：问题以"随机访问/按位置读"为主用顺序表，以"动态增删/循环报数出队"为主用链表。

> [!TIP]
> 建议内容：线性表应用题的通用思路——**先定"用什么结构能支持核心操作"**（约瑟夫环频繁删人用循环链表，逆置看能否 O(1) 改指针或用辅助栈），再算复杂度。链表的头插法天然实现"逆置"，是常用技巧。
