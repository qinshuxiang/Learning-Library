## 散列查找

> **全章主脉**：散列（Hash）查找**不用比较**，而是**根据关键字直接计算存储地址**，理想下 O(1) 查找。本章讲散列表与散列函数、散列函数的构造方法（重点**除留余数法**）、冲突处理（**开放定址与拉链法**），以及装填因子与**平均查找长度**。核心是冲突处理方法与散列 ASL 的计算。

### 散列的概念

#### 散列表与散列函数

**散列表（哈希表）**是**根据关键字直接计算存储地址的数据结构**：通过**散列函数 H(key)** 把关键字 key 映射到一个地址，把记录存到该地址，查找时同样由 H(key) 直接定位，无需比较即可（理想下 O(1)）找到。

**散列函数**应使**关键字均匀分布**到地址空间、计算简单、尽量减少**冲突**。**冲突（碰撞）**是不同关键字经散列函数得到**同一地址**的现象，需用冲突处理方法解决。

> [!NOTE]
> 提醒内容：散列的理想是"**一次算地址、直接存取**"。但冲突不可避免（地址空间通常小于关键字空间），故散列表 = 散列函数 + 冲突处理。散列**不按关键字有序**，不支持范围/顺序查找，只支持"按键精确查"。查找键与存时用同一散列函数。

### 散列函数的构造

#### 除留余数法

**除留余数法**是最常用、最简便的散列函数构造法：**取关键字 key 被某个不大于散列表长 m 的数 p 除后的余数**作为散列地址，即 **H(key) 等于 key 对 p 取余**。取 p 为**不大于 m 的质数（或最接近 m 的质数/不含小因子的数）**能减少冲突。

- **优点**：计算简单、实现容易，适用范围广。
- **p 的选择**：p 应为不大于表长 m 的**质数或尽量不含 2、5 等小因子**，以减少取模导致的地址聚集。
- **作用**：常与其他方法结合（如再散列、平方取中后取余）。

> [!WARNING]
> 警告内容：除留余数法**关键是选好模数 p**——p 取质数且尽量接近但不超过表长，能显著减少冲突。若 p 选得不好（如取 2 的幂、或能被关键字中的规律整除），会产生大量冲突。做题给散列函数与表长，要会正确计算各关键字地址。

#### 直接定址法与数字分析法

**直接定址法**取**关键字的某个线性函数**作为散列地址，即 H(key) 等于 a 乘 key 加 b。它**无冲突、最简单**，但只适用于**关键字集合较小且分布连续**、能预先知道关键字范围的情况，否则地址空间可能过大浪费。

**数字分析法**（数字选择法）分析**各关键字的各位数字分布**，**选取分布较均匀的若干位**作为散列地址。适合关键字是**多位数字**（如学号、身份证号）且已知关键字集合、能预分析各位分布的场景。

- **直接定址**：H(key)=a·key+b，无冲突但需关键字范围小且连续。
- **数字分析**：挑各位分布均匀的位段作地址，适合等长数字关键字。

> [!TIP]
> 建议内容：**直接定址法适合关键字分布均匀连续的已知集合**（几乎一一对应、无冲突），**数字分析法适合事先能统计各位分布的等长数字关键字**（挑均匀的位）。除留余数法则最通用。散列函数目标：分布均匀 + 计算快。

### 冲突处理

#### 开放定址法

**开放定址法**解决冲突的方式是：发生冲突时，**在散列表的空闲位置中再找一个位置**存放，地址序列通过**再探测**得到。常用探测方法有**线性探测、平方（二次）探测与再散列（双散列）**。

- **线性探测法**：冲突时**依次探测下一个地址**（加 1、加 2……），直到有空位。简单但**易造成聚集**（堆积）——冲突元素连成一片，后续查找慢。
- **平方探测法（二次探测）**：探测序列为加 1 方、减 1 方、加 2 方、减 2 方……缓解线性聚集，但表长须为 4k 加 3 的质数等才能探测完所有位置。
- **再散列法（双散列）**：用**第二个散列函数**计算探测步长，分散效果更好。
- 删除需**特殊处理**（标记删除），否则会破坏探测链。

> [!WARNING]
> 警告内容：**开放定址把冲突记录放到表内其它空位，靠"探测"找**。**线性探测易聚集**（一旦连片，后续查找大幅增加），平方探测缓解聚集但限制表长，双散列效果最好。开放定址**删除不能直接清空**（会断探测链，须用"删除标记"）。会手推线性探测与平方探测的散列过程并算 ASL。

#### 拉链法

**拉链法（链地址法）**把散列到**同一地址的所有记录链成一个单链表**，散列表每个地址存一个**链表头**。冲突时直接把记录**挂到对应地址的链尾/链头**即可，**无聚集问题、删除方便**。

- **实现**：数组每个单元是一个链表的头指针，同地址元素链成一条链表。
- **优点**：冲突时只需加链表结点，**无聚集**；删除简单（链表删结点）；**装填因子可大于 1**（表不必很大）。
- **查找**：先算地址得链表，再在链表中顺序找；链表越长越慢。

> [!NOTE]
> 提醒内容：**拉链法让每个"槽"存一条链表**，同地址元素链起来。优点是无堆积、易删除、表可小些；缺点是需链表结点指针空间。与开放定址对比——开放定址把记录塞进表内空位（可能聚集、删除麻烦），拉链法挂在链上（灵活）。会画给定序列的拉链散列表并算 ASL。



### 集合与字典的 JavaScript 实现

**集合**是**元素互不重复的无序容器**，**字典**是**键值对（key 到 value）的映射**，二者都是"按内容直接定位"的抽象结构，其最典型的实现就是**散列表**。先用对象手写这两个结构，再实现散列表本身，可看清从抽象到落地的完整链条。

#### 集合的 JavaScript 实现

- **底层容器**：本例用对象保存元素，元素同时作为键与值。
- **判重 add**：先判断元素是否已存在，存在则返回 false，不存在才加入。
- **集合运算**：并集、交集、差集、子集判断，均基于遍历元素与 has 判定组合而成。

```js
class MySet {
  constructor() {
    this.items = {};
  }

  has(value) {
    return Object.prototype.hasOwnProperty.call(this.items, value);
  }

  add(value) {
    if (this.has(value)) return false;
    this.items[value] = value;
    return true;
  }

  remove(value) {
    if (!this.has(value)) return false;
    delete this.items[value];
    return true;
  }

  clear() {
    this.items = {};
  }

  size() {
    return Object.keys(this.items).length;
  }

  values() {
    return Object.keys(this.items);
  }

  // 并集
  union(otherSet) {
    const unionSet = new MySet();
    for (const value of this.values()) unionSet.add(value);
    for (const value of otherSet.values()) unionSet.add(value);
    return unionSet;
  }

  // 交集
  intersection(otherSet) {
    const intersectionSet = new MySet();
    for (const value of this.values()) {
      if (otherSet.has(value)) intersectionSet.add(value);
    }
    return intersectionSet;
  }

  // 差集
  difference(otherSet) {
    const differenceSet = new MySet();
    for (const value of this.values()) {
      if (!otherSet.has(value)) differenceSet.add(value);
    }
    return differenceSet;
  }

  // 子集判断
  isSubsetOf(otherSet) {
    return this.values().every((value) => otherSet.has(value));
  }
}

const setA = new MySet();
[1, 2, 3].forEach((v) => setA.add(v));
const setB = new MySet();
[2, 3, 4].forEach((v) => setB.add(v));

console.log(setA.union(setB).values()); // 1,2,3,4
console.log(setA.intersection(setB).values()); // 2,3
console.log(setA.difference(setB).values()); // 1
console.log(setA.isSubsetOf(setA)); // true
```



#### 字典的 JavaScript 实现

- **底层容器**：对象或 Map；对象方案的键会被自动转成字符串，Map 支持任意类型的键。
- **核心操作**：set 存、get 取、has 判、remove 删、keys 与 values 取全部键与值、size 取长度、clear 清空。

```js
class Dictionary {
  constructor() {
    this.items = {};
  }

  set(key, value) {
    this.items[key] = value;
    return true;
  }

  has(key) {
    return Object.prototype.hasOwnProperty.call(this.items, key);
  }

  remove(key) {
    if (!this.has(key)) return false;
    delete this.items[key];
    return true;
  }

  get(key) {
    return this.has(key) ? this.items[key] : undefined;
  }

  keys() {
    return Object.keys(this.items);
  }

  values() {
    return Object.values(this.items);
  }

  size() {
    return this.keys().length;
  }

  clear() {
    this.items = {};
  }
}

const dict = new Dictionary();
dict.set("age", 18);
dict.set("name", "Coderwhy");
dict.set("height", 1.88);

console.log(dict.keys()); // age,name,height
console.log(dict.values()); // 18,Coderwhy,1.88
console.log(dict.size(), dict.get("name")); // 3 Coderwhy

dict.remove("height");
console.log(dict.keys()); // age,name
```

> [!CAUTION]
> 注意内容：用**普通对象**当底层容器时，键会被**强制转成字符串**，数字 1 与字符串 "1" 会互相覆盖；同时对象键还可能与原型上的属性名（如 constructor、toString）冲突。工程实现请直接使用 ES6 原生的 **Map 与 Set**，或至少用 Object.create(null) 创建无原型对象并配合 hasOwnProperty 判定。



### 散列表的 JavaScript 实现

散列表把**散列函数、冲突处理、扩容**三件事组合起来：先由散列函数把键映射到数组下标，再用**拉链法**（每个数组槽位挂一个桶数组）解决冲突，最后按**装填因子**自动扩容或缩容以维持效率。

- **散列函数 hashFunc**：采用**霍纳法则**，依次累加"37 乘上一步结果加字符编码值"，最后对表长取模。
- **冲突处理**：拉链法——每个桶内的每一项形如 [键, 值]，同桶内线性查找。
- **扩容 resize**：装填因子超过 0.75 时扩容到不小于两倍表长的最小**质数**；低于 0.25 时缩容到不大于半表长的最大质数附近。
- **质数表长**：取质数作模数可让键分布更均匀，减轻聚集。

```js
class HashTable {
  constructor(limit = 8) {
    this.storage = []; // 桶数组
    this.count = 0; // 元素个数
    this.limit = limit; // 表长
  }

  // 散列函数：霍纳法则 + 取模
  hashFunc(key, max) {
    let hashCode = 0;
    const str = String(key);
    for (let i = 0; i < str.length; i++) {
      hashCode = 37 * hashCode + str.charCodeAt(i);
    }
    return hashCode % max;
  }

  // 判断质数
  isPrime(num) {
    if (num <= 1) return false;
    const temp = parseInt(Math.sqrt(num), 10);
    for (let i = 2; i <= temp; i++) {
      if (num % i === 0) return false;
    }
    return true;
  }

  // 获取不小于 num 的最小质数
  getPrime(num) {
    while (!this.isPrime(num)) {
      num += 1;
    }
    return num;
  }

  // 存入或修改
  put(key, value) {
    const index = this.hashFunc(key, this.limit);
    let bucket = this.storage[index];

    if (bucket === undefined) {
      bucket = [];
      this.storage[index] = bucket;
    }

    // 已存在则覆盖
    for (const tuple of bucket) {
      if (tuple[0] === key) {
        tuple[1] = value;
        return true;
      }
    }

    // 新增
    bucket.push([key, value]);
    this.count += 1;

    // 装填因子超过 0.75 则扩容
    if (this.count > this.limit * 0.75) {
      this.resize(this.getPrime(this.limit * 2));
    }
    return true;
  }

  // 取值
  get(key) {
    const index = this.hashFunc(key, this.limit);
    const bucket = this.storage[index];
    if (bucket === undefined) return null;
    for (const tuple of bucket) {
      if (tuple[0] === key) return tuple[1];
    }
    return null;
  }

  // 删除
  remove(key) {
    const index = this.hashFunc(key, this.limit);
    const bucket = this.storage[index];
    if (bucket === undefined) return null;

    for (let i = 0; i < bucket.length; i++) {
      if (bucket[i][0] === key) {
        const value = bucket[i][1];
        bucket.splice(i, 1);
        this.count -= 1;

        // 装填因子低于 0.25 则缩容
        if (this.limit > 7 && this.count < this.limit * 0.25) {
          this.resize(this.getPrime(Math.floor(this.limit / 2)));
        }
        return value;
      }
    }
    return null;
  }

  // 扩容或缩容：重建桶数组并重新散列
  resize(newLimit) {
    const oldStorage = this.storage;
    this.limit = newLimit;
    this.count = 0;
    this.storage = [];

    for (const bucket of oldStorage) {
      if (bucket === undefined) continue;
      for (const tuple of bucket) {
        this.put(tuple[0], tuple[1]);
      }
    }
  }

  isEmpty() {
    return this.count === 0;
  }

  size() {
    return this.count;
  }
}

const ht = new HashTable();
ht.put("abc", "123");
ht.put("cba", "321");
ht.put("nba", "521");
ht.put("mba", "520");

console.log(ht.get("abc")); // 123
ht.put("abc", "111");
console.log(ht.get("abc")); // 111（同一键被覆盖）
console.log(ht.remove("abc")); // 111
console.log(ht.get("abc")); // null
console.log(ht.size()); // 3
```

> [!WARNING]
> 警告内容：**扩容必须重新散列，不能直接搬移**。表长变化后同一个键的取模结果随之改变，若不逐个重新 put，查询就会找不到数据。resize 里要先把旧数组存下来、清空计数，再遍历旧桶逐个插入。

> [!IMPORTANT]
> 重要内容：**装填因子是散列表的效率开关**。装填因子等于元素个数除以表长，拉链法下它直接等于桶的平均链长；控制在 0.75 以内，查找才能稳定接近 O(1)。扩容取**质数表长**可让取模结果分布更均匀，减轻聚集。

> [!TIP]
> 建议内容：**散列表速记**——"函数定址、拉链解冲、装填扩容"三步走。散列函数用霍纳法则（37 倍累加字符编码），冲突用桶数组线性查找，扩容取不小于两倍表长的最小质数。



### 散列表查找分析

#### 装填因子

**装填因子 α** 等于 **表中已存记录数 n 除以散列表长度 m**，即 α 等于 n/m。它反映散列表的**装满程度**，**α 越大冲突越多、查找越慢**。

- **装填因子 α = 已存元素 / 表长**。
- α 越小，空闲位越多、冲突概率越低、查找越快，但浪费空间。
- **散列表查找的 ASL 不直接依赖元素个数 n，而依赖装填因子 α**——这是散列区别于其它查找的关键特点。

> [!NOTE]
> 提醒内容：散列的性能用**装填因子 α**衡量——**α 大则冲突多、ASL 大；α 小则省查找时间费空间**。控制 α（如 0.7~0.8）可在时空间取得平衡。题目常给表长与元素数求 α，或用拉链法时 α 可大于 1。

#### 平均查找长度

**散列表的平均查找长度（ASL）**分成功与失败，取决于散列函数、冲突处理方法与装填因子 α。散列的 ASL **与 n 无关、只与 α 及处理法有关**。

- **查找成功 ASL**：Σ（各关键字被找到所需的比较次数）/n。**比较次数**要看该关键字是否一次命中或经历几次冲突探测。
- **查找失败 ASL**：对每个散列地址，从该地址开始**按探测规则走到空位（判定失败）所需的比较次数**，再取平均（按地址数 m 平均）。
- **估算公式（近似）**：线性探测成功约 1/2(1+1/(1−α))，失败约 1/2(1+1/(1−α)²)；拉链法成功约 1+α/2。可作验证参考。

> [!WARNING]
> 警告内容：**成功 ASL 只统计能查到的关键字，失败 ASL 统计到"判定失败的空位"为止**。手算散列 ASL 必须：①成功——对每个关键字沿探测/链表数比较次数后取平均（除 n）；②失败——按每个地址做探测直到遇空，统计探测次数取平均（**除表长 m 而非 n**）。失败 ASL 的除数最易错，开放定址按地址总数 m 平均、拉链法也需逐地址（含空链表算 1 次）统计。
