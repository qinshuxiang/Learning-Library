## 安装与初始配置

### 安装 Git

Git 在 Linux、macOS 与 Windows 上都有成熟的安装途径，安装完成后统一用版本号命令验证。

#### Linux 下安装

Linux 上优先使用系统自带的包管理器安装。

```bash
# Debian / Ubuntu
sudo apt-get install git

# Fedora / CentOS（新版 Fedora 用 dnf）
sudo yum install git
```

安装前可先执行 git --version 确认是否已经内置；多数发行版如今预装 Git，缺的只是较新版本。



#### macOS 下安装

macOS 有两条常见途径，任选其一。

```bash
# 途径一：随 Xcode Command Line Tools 附带
xcode-select --install

# 途径二：Homebrew 安装（版本更新、可控）
brew install git
```

- **Xcode Command Line Tools**：执行命令后按提示安装，附带系统自带的 Git，版本略旧但够用。
- **Homebrew**：macOS 常用的包管理器，便于随时升级到最新版本。



#### Windows 下安装

Windows 使用 **Git for Windows** 官方安装包，从 Git 官网下载后按向导安装，保持默认选项即可覆盖绝大多数场景。

- 安装包自带 **Git Bash**：一个模拟 Linux 终端的环境，让 bash 命令、SSH 等工具在 Windows 上可用，是 Windows 上使用 Git 的推荐入口。
- 安装包同时提供图形化界面与资源管理器右键菜单集成，可按需勾选。



#### 验证安装

安装完成后，打开终端执行验证命令：

```bash
git --version
# 输出示例：git version 2.46.0
```

版本号能正常输出即安装成功；不同时间安装得到的版本号不同，属正常现象。



### 三级配置与配置文件

**配置级别**：Git 的所有配置按作用范围从大到小分为三级：**系统级**（--system）、**全局级**（--global）与**仓库级**（--local）。

- **系统级（--system）**：对本机**所有用户**生效，配置文件为 /etc/gitconfig。
- **全局级（--global）**：对当前用户的**所有仓库**生效，配置文件为用户主目录下的 .gitconfig。
- **仓库级（--local）**：仅对**当前仓库**生效，配置文件位于仓库内 .git 目录的 config 文件中。
- **优先级**：仓库级覆盖全局级，全局级覆盖系统级——范围越小，优先级越高。

```bash
# 三个级别的写入语法，差别只在级别选项
git config --system core.editor vim
git config --global user.name "Zhang San"
git config --local user.email "zhangsan@company.com"
```

> 不写级别选项时，git config 默认按仓库级读写；查看各级配置可用 git config --system --list、git config --global --list、git config --local --list。



### 必要的身份配置

安装 Git 后首先要配置 **user.name**（用户名）与 **user.email**（邮箱），它们的作用只有一个：**标识每一次提交的作者**。

- 每次提交都会把这两个信息永久写入提交记录，历史上的每笔改动因此可追溯到人。
- 它们**与远程账号认证无关**：向代码托管平台推送时的身份验证依靠凭据（如访问令牌）或 SSH 密钥，user.name 与 user.email 不参与认证。
- user.name 建议写真实姓名或常用昵称，user.email 建议与代码托管平台账号的邮箱一致，便于平台把提交关联到头像与贡献统计。

```bash
git config --global user.name "Zhang San"
git config --global user.email "zhangsan@example.com"

# 查看全部已生效的配置
git config --list
```

> git config --list 按优先级从低到高列出各来源的配置，同名项以后出现的为准；git config --list --show-origin 可额外显示每条配置来自哪个文件。



### 默认编辑器与常用配置

Git 在需要输入多行说明或进行交互确认时会启动一个文本编辑器，默认编辑器等行为可通过配置统一。常用的三项如下。

- **core.editor**：Git 默认启动的编辑器。不设置时回退到 VISUAL 或 EDITOR 环境变量，通常为 vim；可改为任何编辑器，改用 VS Code 时需带 --wait 参数，让 Git 等待编辑器关闭后再继续。
- **init.defaultBranch**：git init 创建新仓库时的初始分支名。历史默认为 master，2020 年前后社区出于包容性考虑普遍改用 main，主流代码托管平台也已把 main 作为新仓库的默认分支名。
- **pull.rebase**：git pull 拉取远端更新时采用合并（merge）还是变基（rebase）策略；设为 true 即拉取时变基，让提交历史更接近一条直线。

```bash
git config --global core.editor "code --wait"
git config --global init.defaultBranch main
git config --global pull.rebase true
```

> merge 与 rebase 的取舍属于分支进阶话题，此处只需记住：三项配置都在全局级设定一次、对所有仓库生效，无需每个仓库重复设置。



### 配置别名

**别名**（alias）：为常用命令创建的简写，写法是 git config --global alias.别名 加 原命令。别名只存在于配置文件中，等价于把长命令映射成短命令。

```bash
git config --global alias.ci commit
git config --global alias.st status
# 带参数的别名，整体用引号包起来
git config --global alias.lg "log --oneline --graph --decorate --all"
```

配置后的效果：

- git ci 等价于 git commit，git st 等价于 git status。
- git lg 以一行一条、带分支图形与装饰信息的方式展示全部提交历史，是高频使用的查看命令。

> 若别名以感叹号开头，例如 alias.history 后接 !git log，则执行的是外部 shell 命令而非 Git 子命令，可用于串联多条命令，此类用法了解即可。



### 获取帮助

Git 的帮助体系有两条入口，按查阅深度选择。

- **git help 命令**（等价于 git 命令 --help）：打开该命令的完整手册，内容详尽，本地即可阅读，无需联网。
- **git 命令 -h**：在终端直接输出该命令的选项摘要，一屏列完，适合快速确认某个参数的写法。

```bash
# 完整手册：config 命令的全部说明
git help config

# 快速摘要：config 命令的选项一览
git config -h
```

> 记忆口诀：help 求详解，-h 求速查。日常开发中 -h 的使用频率更高，完整手册适合系统了解某条命令的全部能力。
