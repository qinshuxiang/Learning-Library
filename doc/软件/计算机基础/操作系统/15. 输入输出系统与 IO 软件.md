## 输入输出系统与 IO 软件

> **全章主脉**：IO 系统管理 CPU 与外部设备之间的数据交换。本章从**IO 硬件**讲起，理清**设备、设备控制器、IO 通道**，再讲**四种 IO 控制方式**（程序直接控制、中断驱动、DMA、通道）的演进，最后给出**IO 软件的层次结构**（中断处理、设备驱动、设备无关层、用户层）。核心是**各种控制方式下 CPU 的参与程度与数据流向**。

### IO 系统的功能、模型与接口

#### IO 硬件

**IO 硬件**主要包括**IO 设备、设备控制器与设备接口**。IO 设备负责数据的具体输入输出，设备控制器（IO 控制器/适配器）介于 CPU/主存与设备之间，负责解析 CPU 的 IO 指令并控制设备动作，两者通过**接口（端口）**相连，设备控制器再通过总线或 IO 通道与主机相连。

**IO 系统的组成**：

- **IO 设备**：输入设备（键盘、鼠标）、输出设备（显示器、打印机）、存储设备（磁盘）等，种类繁多。
- **设备控制器**：接收并解释 CPU 的命令、控制设备、管理设备状态、进行数据缓冲与格式转换，其上有**控制寄存器、状态寄存器、数据缓冲寄存器**等。
- **设备接口**：连接设备与控制器；设备往往通过**寄存器端口**与 CPU/主存交互。

> [!NOTE]
> 提醒内容：CPU 不直接面对五花八门的设备，而通过**统一的设备控制器接口**发命令——控制器是"设备的翻译官与管家"。理解 IO 系统，把目光集中在"CPU—控制器—设备"三层以及数据如何经控制器在主存与设备间流动。

#### IO 系统的层次结构

**IO 系统的层次结构**把 IO 功能自下而上分层，屏蔽设备差异、逐层提供抽象。常见层次为：**IO 硬件 → 中断处理程序 → 设备驱动程序 → 与设备无关的 IO 软件 → 用户层 IO 软件**。

- **中断处理程序**：处理 IO 完成等中断，位于内核最底层。
- **设备驱动程序**：直接与设备控制器打交道，**把上层统一的 IO 请求转换成具体设备的操作**，每类设备一个驱动。
- **与设备无关的 IO 软件**：实现**设备命名、缓冲、分配、错误处理**等不依赖具体设备的通用功能。
- **用户层 IO 软件**：库函数与系统调用接口，向用户程序提供统一 IO。

> [!IMPORTANT]
> 重要内容：IO 层次由低到高是**硬件 → 中断处理 → 设备驱动 → 设备无关层 → 用户层**。**设备驱动程序是唯一与具体设备硬件直接打交道的软件**，它向上提供统一接口、把上层抽象请求翻译成控制器命令——因此换设备只换驱动、上层不用改，这正是分层的好处。

### IO 设备与设备控制器

#### 设备类型

**IO 设备**可按多种标准分类，常见分类如下。

- **按信息交换单位**：**块设备**（以块为单位传输、可寻址、如磁盘，可随机存取）与**字符设备**（以字节/字符为单位、不可寻址、如键盘打印机，只能顺序传输）。
- **按使用特性**：独占设备（同一时间只能一个进程用，如打印机）、共享设备（可多个进程同时用，如磁盘）、虚拟设备（用 SPOOLing 把独占设备虚拟成多个逻辑设备）。
- **按传输速率/交互性**：低速（键盘）、中速（打印机）、高速（磁盘、网络）设备。

> [!NOTE]
> 提醒内容：**块设备可随机存取、以块为单位**（磁盘、SSD），**字符设备按字节流顺序传输**（键盘、打印机）。区分块/字符设备是 IO 基础考点。独占 vs 共享决定是否需要"设备分配 + SPOOLing 虚拟化"。

#### 设备控制器的功能与组成

**设备控制器（IO 控制器）**是**介于 CPU（主存）与设备之间、控制设备完成数据交换的部件**。它的功能包括**接收并识别 CPU 命令、向 CPU 报告设备状态、进行数据交换与缓冲、以及地址识别**（区分设备与寄存器）。

**控制器的组成**：控制器内有**若干寄存器**与**接口逻辑**。

- **控制寄存器**：存放 CPU 下发的控制命令（启动、停止、读、写等）。
- **状态寄存器**：反映设备/控制器状态（忙、就绪、错误等），CPU 轮询它判断 IO 是否完成。
- **数据缓冲寄存器/数据寄存器**：暂存主机与设备之间传输的数据，起**缓冲**作用。
- **I/O 端口与译码逻辑**：为各寄存器分配端口地址，CPU 通过端口访问。

> [!TIP]
> 建议内容：控制器像"设备端的微型处理器"——**CPU 把命令写进控制寄存器、轮询/中断读状态寄存器、经数据寄存器交换数据**。三类寄存器（控制、状态、数据）是理解"程序直接控制（轮询状态）""中断驱动（状态变化发中断）"的基础。

#### 内存映像 IO 与 IO 通道

**内存映像 IO**是把**设备控制器的寄存器端口映射到主存地址空间**，使 CPU 访问设备寄存器就像访问普通主存单元（用访存指令读写），简化了 IO 指令设计。与之相对的是**独立编址（专用 IO 指令）**——用独立于内存的 IO 指令访问端口。

- **内存映像 IO**：端口占一段主存地址，用访存指令访问，无需专用 IO 指令；端口地址可多、便于灵活编址。
- **独立编址**：用专门 IN/OUT 指令与端口号访问，指令专一、但不便扩展大量端口。

**IO 通道**是**专门负责 IO 控制的处理器/机构**：它能在没有 CPU 干预的情况下，**独立执行通道程序**，控制多台设备与主存之间成批传送数据，进一步把 CPU 从 IO 中解放出来（通道可看作 DMA 的进一步发展、能控制多设备）。

> [!NOTE]
> 提醒内容：内存映像 IO 回答"**CPU 怎么访问设备寄存器**"——映射到主存用访存指令；独立编址则用专用 IO 指令。**通道则是把"IO 控制"做成独立处理器**，能自主管理多设备大批量传输，比 DMA 控制能力更强、CPU 更省。

### IO 控制方式

#### 程序直接控制

**程序直接控制方式**是**最原始**的 IO 控制方式：CPU 通过**不断轮询设备状态寄存器**，等待设备就绪后执行一次数据传送。设备忙/未就绪时 CPU 只能循环等待（忙等）。

- **工作过程**：CPU 发命令启动设备 → **反复读状态寄存器**，设备未就绪就一直轮询 → 设备就绪后 CPU 从数据寄存器取数/写数 → 重复直到数据传完。
- **缺点**：CPU 与设备串行，**轮询期间 CPU 被占用空转、无法做别的事**，效率极低。
- **特点**：实现简单，但 CPU 利用率极低——**每传一个数据 CPU 都要等待设备并亲自搬一次**。

> [!WARNING]
> 警告内容：程序直接控制的最大问题是**忙等轮询、CPU 空耗**——设备慢、CPU 快，CPU 花大量时间"干等设备就绪"，没做有用功。判断标志：CPU 主动反复查状态寄存器直到设备就绪。因效率太低，实际很少单独使用。

#### 中断驱动方式

**中断驱动方式**改进程序直接控制：CPU 发出 IO 启动命令后**不再轮询等待**，而是**转去做其他工作**；当设备完成一次数据传送（就绪/完成）时，**向 CPU 发中断**，CPU 响应中断后处理该次传送，再继续原工作。

- **工作过程**：CPU 发命令启动 IO → CPU 去执行别的程序 → 设备完成传送后**发中断** → CPU 响应、进入中断处理程序搬一次数据 → 返回原程序，等待下一次中断。
- **优点**：CPU 在设备工作期间**可执行其他程序**，提高了 CPU 利用率。
- **缺点**：**每传送一个字/字节都要一次中断**，中断次数随数据量激增，中断开销大；高速设备（磁盘）下中断过频拖慢系统。

> [!NOTE]
> 提醒内容：中断驱动方式让 **CPU 与设备并行**（设备忙时 CPU 干别的），每完成一次小量传送就中断一次。它消除了忙等，但**"一次中断只搬一点数据"**对高速大批量传输不利，于是引出能一次搬一大批的 **DMA**。

#### DMA 方式

**直接存储器存取（DMA）方式**让**数据直接在设备与主存之间传输，不经 CPU 逐字节搬运**：由 **DMA 控制器**接管数据传输，CPU 只需在开始设置传输参数、结束时响应一次中断。**一个数据块只中断一次**，大大减少中断次数。

- **DMA 控制器**：含**内存地址寄存器（MAR）、数据寄存器、命令/状态寄存器与传送字节计数器**，自主控制传输。
- **工作过程**：CPU 设置 DMA 控制器（源/目的地址、字节数、命令）并启动 → DMA 控制器**在设备与主存间成块搬运**（每传一字占用一个总线周期，称周期挪用），CPU 可并行执行别的指令 → 传完由 DMA 控制器**发一次中断**通知 CPU。
- **优点**：成块传输、只中断一次、CPU 干预少，适用于磁盘等高速大批量设备。

> [!IMPORTANT]
> 重要内容：DMA 让数据**不经 CPU 直通主存**，**传送一个数据块只需一次中断**（区别于中断驱动"每个字中断一次"）。传送期间 DMA 与 CPU 以**周期挪用**方式共享总线。判断采用 DMA 的场合：**高速、大批量、块设备**（磁盘）。DMA 仍需占用总线、且在传送中与 CPU 争用主存。

#### 通道方式

**通道方式**是 DMA 的进一步发展：**IO 通道是一台能执行通道程序的、专门管理 IO 的处理器**。通道通过执行**通道程序**（一组描述 IO 操作的指令）来控制一台或多台设备的 IO，实现**设备与主存间成组数据传送而几乎不需 CPU 干预**。

- **通道程序**：由通道指令组成，描述"读/写、传送地址、字节数"等，通道自主执行。
- **工作过程**：CPU 组织好通道程序并"启动通道"→ 通道独立执行通道程序、管理 IO → **一组 IO 操作完成或出错时**才向 CPU 发一次中断。
- **优点**：进一步把 CPU 从 IO 中解放，可同时管理多台设备、支持更复杂 IO；代价是**通道硬件较复杂、成本高**。
- **与 DMA 关系**：DMA 适合单一设备成块传输，通道能控制多设备、执行程序化 IO，控制能力更强。

> [!TIP]
> 建议内容：四种控制方式的演进口诀——**程序直接控制"CPU 忙等每字亲搬"、中断驱动"每字一中断"、DMA"成块传输只中断一次"、通道"独立处理器执行通道程序"**。CPU 参与度从高到低、设备智能化从低到高。判断用哪种方式，看设备速度与数据量：慢速零星（中断/直接）、高速成块（DMA/通道）。

### IO 软件层次

#### 设备驱动程序

**设备驱动程序**是**与设备硬件直接交互、把上层通用 IO 请求转换成具体设备命令的底层软件**，每类（甚至每种）设备对应一个驱动程序。它运行在内核态，负责初始化设备、启动 IO、处理设备中断、维护设备状态与队列。

- **功能**：向上提供统一接口（open、read、write、ioctl 等）给设备无关层；向下把请求翻译为对控制寄存器的读写操作。
- **与硬件关系**：驱动直接操作设备控制器的寄存器、处理设备特性（磁盘驱动要知道磁盘的磁道扇区等细节），故**换设备须换驱动**。
- **中断处理**：设备中断到达时，由中断处理部分（驱动内或独立）读取设备状态、完成相应处理并唤醒等待进程。

> [!NOTE]
> 提醒内容：**设备驱动程序是"软件与硬件的桥"**——它把设备无关层发来的统一请求变成某台设备控制器听得懂的命令序列。每种设备一个驱动，所以新设备要装驱动。驱动在中断发生时也被调用来服务设备。

#### 与设备无关的 IO 软件

**与设备无关的 IO 软件**指**不针对某具体设备、对所有设备通用**的那部分 IO 软件，它运行在设备驱动之上，向用户层提供统一的设备视图。其核心功能是**缓冲管理、设备命名与映射、设备分配与回收、以及统一的错误处理**。

- **设备命名与映射**：把用户的逻辑设备名映射到具体物理设备与驱动（如把"打印机"映射到某台物理打印机及其驱动）。
- **缓冲管理**：为数据传送分配与管理系统缓冲，缓解速度不匹配。
- **设备分配与回收**：管理独占/共享设备的分配，用设备表记录设备占用状态。
- **错误处理**：统一处理设备错误（重试、上报等），不让设备差异漏到上层。
- **提供统一接口**：向用户层暴露一致的读写等系统调用。

> [!TIP]
> 建议内容：设备无关层的价值是"**让上层只面对统一设备接口，不必关心具体硬件**"——缓冲、分配、命名、错误处理都与具体设备无关，故放这一层统一实现，避免每个驱动重复造轮子。它是分层的"公共设施层"。

#### 用户层 IO 软件

**用户层 IO 软件**是 IO 软件的最高层，包括**用户程序调用到的库函数与 IO 系统调用接口**。用户程序通过标准库函数（如 printf、read、write）间接或直接发起系统调用，最终到达内核的设备无关层、设备驱动与硬件。

**用户层 IO 软件的要点**：

- 用户程序通过**系统调用接口**请求内核执行 IO（open、read、write、close 等），库函数对系统调用进行封装与格式化（如 printf 格式化后写）。
- **假脱机（SPOOLing）**等也常借助用户/系统层软件把独占设备变成可共享的逻辑设备。
- 用户层不直接操作设备寄存器，全部 IO 都**经由内核的系统调用**完成（受保护），保证系统安全。

> [!WARNING]
> 警告内容：**用户层 IO 软件不直接碰硬件**——一切设备访问都须经**系统调用进入内核**，由设备无关层、设备驱动层层处理。库函数（printf）在用户态做格式化，真正写设备由内核中的系统调用完成。判断某 IO 属于哪层：能直接操作控制寄存器的是驱动层，做格式化/接口的是用户层。
