## 处理机调度

> **全章主脉**：处理机调度回答"**哪个就绪进程/作业、何时、占用 CPU 多久**"。本章按"层次—准则—算法—实时"展开：先讲高级/中级/低级三级调度，再给出评价准则（周转时间、等待时间、响应时间等公式），随后是六类典型调度算法（FCFS、SJF、HRRN、RR、优先级、多级反馈队列），最后是实时调度。计算题的核心是**会按算法画出甘特图并套公式算周转时间**。

### 处理机调度的层次

#### 高级、中级与低级调度

**处理机调度**按抽象层次分**高级调度（作业调度/长程调度）、中级调度（内存调度/中程调度）与低级调度（进程调度/短程调度）**三级。它们分别决定"作业能否进入内存""进程能否占用内存""进程能否占用 CPU"。

- **高级调度（作业调度）**：把**外存**上处于后备队列的作业，按一定算法**调入内存、为之建立进程**。发生频率最低（以"作业"为单位、分钟级）。
- **中级调度（内存调度）**：把**暂时不能运行的进程调到外存（挂起）、必要时再调回内存**，目的是提高内存利用率与系统吞吐量，对应挂起状态。
- **低级调度（进程调度）**：从**内存中处于就绪状态的进程**中选出进程分配 CPU，发生频率最高（毫秒级），是最基本、最核心的调度。

> [!NOTE]
> 提醒内容：三级调度口诀——**高级"进门"（外存作业进内存）、中级"换入换出"（挂起/激活）、低级"用 CPU"（就绪变运行）**。发生频率从高到低是 低级 > 中级 > 高级。作业调度与进程调度的对象不同：作业调度对象是作业、进程调度对象是进程。

#### 调度队列模型

**调度队列模型**刻画进程/作业在各级调度下排队等待的流程，典型模型含**就绪队列、阻塞（等待）队列与设备/资源队列**。

- **就绪队列**：存放已就绪、等待分配 CPU 的进程，由**进程调度**从队中选进程。
- **阻塞队列**：存放等待某事件（I/O、信号等）的进程，事件发生后转为就绪进就绪队列。
- **设备队列**：等待某台设备的进程队列（如打印队列），本质上属阻塞队列的细分。

一个典型流程：作业经**高级调度**入内存建进程 → 进程进**就绪队列** → 进程调度选中占用 CPU → 若请求 I/O 进**阻塞队列**，I/O 完成回就绪队列 → 不断循环直至终止。中级调度可在阻塞/就绪进程过多时将其挂起到外存。

> [!TIP]
> 建议内容：画调度队列模型时抓住"**CPU 就绪队列是中心**"——所有可运行进程都在就绪队列排队等 CPU；被中断/时间片到回就绪队列，请求 I/O 则去阻塞队列。就绪队列与阻塞队列是必画的两类，设备队列可并入阻塞理解。

### 调度算法评价准则

#### CPU 利用率

**CPU 利用率**指**CPU 处于忙碌（执行程序）的时间占总时间的比例**，是衡量系统处理能力的重要指标，公式为 CPU 利用率等于 CPU 忙碌时间除以总时间。在并发与多道环境下，提高 CPU 利用率意味着减少 CPU 空闲等待。

**计算要点**：

- 总时间包含 CPU 忙碌时间与等待/空闲时间（如等待 I/O、进程切换开销）。
- CPU 利用率越高，说明 CPU 被充分利用、系统吞吐能力越强。
- 进程切换、中断处理本身也占用 CPU，属"忙碌"但属开销，会降低有效利用率。

> [!NOTE]
> 提醒内容：给定一段含 CPU 计算与 I/O 交替的作业运行时间，求 CPU 利用率要**把多个作业的时间轴叠加**看 CPU 何时空闲。多道并发能提高 CPU 利用率，正是因为它让一个作业等 I/O 时 CPU 去执行另一作业。

#### 周转时间、等待时间与响应时间

**周转时间**指**作业从提交到完成所经历的时间**，包含作业在外存等待（调度）、内存等待 CPU、执行与等待 I/O 的全部时间。**带权周转时间**是周转时间除以实际运行时间，用于消除作业长短差异、衡量调度对长短作业的公平性。

- **周转时间**等于 作业完成时间 减 作业提交时间。
- **带权周转时间**等于 周转时间 除以 作业实际运行时间，恒大于等于 1，越接近 1 越好。
- **平均周转时间**与**平均带权周转时间**：对多个作业求相应平均值，是评价调度算法的重要指标。

**等待时间**指**进程处于等待处理机状态的时间之和**（对交互进程也含等待输入输出），越短越好。**响应时间**指**从提交请求到产生首次响应所经历的时间**，对分时系统关键——用户只关心"我的命令何时有反应"，而非整个任务何时完成。

> [!IMPORTANT]
> 重要内容：**周转时间面向"整个作业从来到走"，带权周转消除作业长短差异，响应时间面向"首次响应的快慢"**。调度算法题目基本都要求"先排甘特图、再算完成时间与周转时间、最后算平均周转与带权"。等待时间常与周转时间混淆——周转包含执行时间，等待不含执行时间。

### 典型调度算法

#### 先来先服务

**先来先服务（FCFS）**是一种**非抢占式**调度算法：按进程**到达就绪队列的先后顺序**分配 CPU，先到先运行，直到运行完或阻塞才让出 CPU。算法简单、公平（不饿死），但**对短作业不利、平均等待时间长**。

- **特点**：实现简单、无饥饿；但**只考虑等待时间、不考虑运行时间长短**，一个长作业先到会阻塞后面所有短作业，导致平均周转与带权周转偏大。
- **适用**：常与时间片轮转或优先级结合，或用于对时间要求不高的批处理。

> [!NOTE]
> 提醒内容：FCFS 的毛病是"**先来者若很长，后来者即便很短也得干等**"——它不照顾短作业。属于非抢占，不会因更高优先级打断当前进程。

#### 短作业优先

**短作业优先（SJF）**调度时**优先选择估计运行时间最短的作业/进程**运行。**最短剩余时间优先（SRTN）**是其抢占版本：每当新进程到达，比较当前进程剩余时间与新进程所需时间，短者优先（可抢占）。SJF 的平均周转时间与平均等待时间**最短**，是理论最优的非抢占调度之一。

- **优点**：平均等待/周转时间最短，能提高系统吞吐量。
- **缺点**：**对长作业不利、可能饿死长作业**；且需预知作业运行时间，实际中难以精确估计。

> [!WARNING]
> 警告内容：**SJF 追求平均周转最短，却可能饿死长作业**（短作业源源不断时，长作业永排不上）。抢占版 SRTN 关注"**剩余**时间"而非"总运行时间"——做题区分：SJF 排定后不可抢占，SRTN 可因更短剩余时间而抢占当前进程。

#### 高响应比优先

**高响应比优先（HRRN）**是一种**非抢占式、动态优先级**调度：每作业的优先级由其**响应比**决定，响应比等于（等待时间 加 要求服务时间）除以 要求服务时间，即 1 加 等待时间除以服务时间。**谁先到、等待时间累积越多，谁优先**。

- **特性**：兼顾 FCFS 与 SJF——**长作业等待久了响应比上升会被调度**，避免饿死；而短作业因服务时间短、初始响应比即高，通常较快被调度。
- **动态性**：作业的响应比随等待时间增长而**动态增大**，需在每次调度时重新计算各作业当前响应比。

> [!NOTE]
> 提醒内容：HRRN 的响应比公式要记住——**响应比等于（等待时间加服务时间）除以服务时间**。等待时间相同时短作业优先（趋近 SJF），服务时间相同时先来者（等待久）优先（趋近 FCFS）。它是非抢占的，每次调度时重算全部作业响应比选最大者。

#### 时间片轮转

**时间片轮转（RR）**是一种**抢占式、基于时间片**的调度：把 CPU 时间划分成固定大小的时间片，就绪队列中的进程**轮流**各运行一个时间片，时间片用完仍未完成则**被剥夺 CPU、回到就绪队列队尾**，换下一进程。

- **时间片大小**：时间片过大则退化为 FCFS；过小则**进程切换过于频繁、系统开销大**。应使时间片略大于一次典型交互所需的处理时间。
- **特性**：公平（不饿死）、响应快、适合分时系统；但时间片切换有开销，且**平均周转时间不一定最优**（含较多切换等待）。

> [!TIP]
> 建议内容：RR 做题要点——**按到达顺序排就绪队列，每个进程最多跑一个时间片**；时间片到被剥夺排到队尾。时间片的选择是"切换开销"与"响应及时性"的权衡：太小切换浪费 CPU，太大失去轮转意义。

#### 优先级调度

**优先级调度**按进程的**优先级**决定运行顺序，又分**非抢占式**（当前进程运行完/阻塞才换更高优先级进程）与**抢占式**（有更高优先级进程到达立即抢占）。优先级可由系统静态设定，也可动态调整。

- **静态优先级**：创建时确定、运行中不变，简单但可能饿死低优先级进程。
- **动态优先级**：运行中可调整（如随等待时间增长而提高优先级），能避免饿死。
- **抢占 vs 非抢占**：实时/分时常用抢占式以保证关键进程及时运行。

> [!WARNING]
> 警告内容：优先级调度最大的问题是**低优先级进程可能饿死**（高优先级源源不断抢占）。解决靠**动态提升等待进程优先级**。区分抢占与非抢占看"更高优先级到达时是否立刻抢走 CPU"。

#### 多级反馈队列

**多级反馈队列调度**设置**多个优先级递减的就绪队列**，每个队列内用时间片轮转，时间片长度从高优先级队列向下递增。进程**先进入最高优先级队列**，在一个时间片内未完成则**降到下一级队列**；同时，高优先级队列空时才调度低优先级队列（可设抢占：新到高优先级进程抢占低队列进程）。

- **高优先级队列**：时间片短，适合短作业与交互作业（能快速响应与完成）。
- **低优先级队列**：时间片长，适合长作业；长作业在低队列长时间运行减少切换开销。
- **灵活与自适应**：兼顾短作业响应快（先在高队列）与长作业不饿死（有更低队列承载），是最常用的综合调度算法之一。

> [!IMPORTANT]
> 重要内容：多级反馈队列的规则串记——"**新进程先进最高队列、跑完时间片未成则降级、高队列空才服务低队列、高队列新到可抢占低队列运行**"。它同时兼顾短作业（快速完成）、交互（响应快）与长作业（最终在低队列跑完且不被饿死），是多种算法优点综合的典型。

### 实时调度

#### 最早截止时间优先

**最早截止时间优先（EDF）**是实时调度算法，**谁的截止时间（deadline）最早谁先运行**。它既可用于抢占式也可非抢占式，能动态根据任务的截止期限调整运行顺序，是**动态优先级**实时调度的一种。

- **抢占式 EDF**：每当新任务到达，若其截止时间早于当前运行任务的截止时间，则抢占当前任务先执行新任务。
- **特性**：理论上只要系统总负载不超过其调度能力，抢占式 EDF 能保证所有任务在其截止时间内完成。

> [!NOTE]
> 提醒内容：EDF 的本质是"**越紧急越先做**"——以剩余时间最少即截止时间最近者为最高优先级。它是动态的，任务到达即需重新评估优先级。

#### 最低松弛度优先

**最低松弛度优先（LLF）**选择**松弛度最小的任务**先执行。**松弛度**指任务"还能拖延多久而不误截止时间"，公式为松弛度等于（任务截止时间 减 当前时间）减 还需运行时间。松弛度越小说明越紧迫，越应先运行。

- **计算**：松弛度（L）等于 截止时间（D）减 当前时刻（t）减 剩余处理时间（C）。
- **抢占式 LLF**：某任务松弛度减到比当前运行任务小时，抢占运行。
- **适用**：多任务实时系统中，配合抢占调度保证紧急任务及时完成。

> [!TIP]
> 建议内容：LLF 做题要**会算每个时刻各任务的松弛度**，选最小者运行，并注意任务运行中松弛度随时间递减、需动态比较是否触发抢占。EDF 看"截止时间远近"，LLF 看"还能拖多久（含剩余时间）"，二者都是动态实时调度，LLF 更精细地考虑了剩余处理时间。
