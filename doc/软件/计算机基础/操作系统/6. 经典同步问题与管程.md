## 经典同步问题与管程

> **全章主脉**：本章把上一章的信号量用于四个经典同步问题（生产者—消费者、读者—写者、哲学家进餐、理发师），再用**管程**这一更高级的抽象重新解决同步。掌握经典问题的**信号量设置与 P/V 摆放**是 408 大题常考点，关键在分清每个信号量管"互斥"还是管"同步"、以及 P/V 的先后。

### 生产者消费者问题

**生产者—消费者问题**描述一组**生产者进程**与一组**消费者进程**共享一个有界缓冲区：生产者向缓冲区投放产品，消费者从缓冲区取走产品。要求满足两个同步约束——**缓冲区满时生产者必须等待（不能覆盖未取的产品）**，**缓冲区空时消费者必须等待（无产品可取）**；同时**对缓冲区的访问互斥**。

**信号量设置**：设互斥信号量 mutex（初值 1，保护缓冲区）、同步信号量 empty（初值 n，n 为缓冲容量，表示空槽数）、同步信号量 full（初值 0，表示已满产品数）。

```text
生产者进程：
  P(empty)              # 申请一个空槽，空槽不足则阻塞
  P(mutex)              # 进入临界区，互斥访问缓冲区
  往缓冲区写入产品
  V(mutex)
  V(full)               # 增加一个满槽，可能唤醒等待的消费者

消费者进程：
  P(full)               # 申请一个产品，无产品则阻塞
  P(mutex)
  从缓冲区取出产品
  V(mutex)
  V(empty)              # 增加一个空槽，可能唤醒等待的生产者
```

> [!WARNING]
> 警告内容：**必须先 P 同步信号量（empty/full）再 P 互斥信号量（mutex），绝不能颠倒**——若先 P（mutex）再 P（empty），当缓冲区满时生产者占着 mutex 又去等 empty 空槽，而消费者要取产品需先 P（mutex）却被堵住，就会互相等待形成**死锁**。规律：同步 P 在外、互斥 P 在内。

### 读者写者问题

**读者—写者问题**描述一组**读者**与一组**写者**共享一个数据对象，约束为：**多个读者可同时读**（读读允许）、**写者与任何读者/写者互斥**（写写、读写都不允许同时）。写者优先问题中还要求**一旦有写者等待，后续读者不得抢先**（防止写者饿死）。

**读者优先解法**：设读计数变量 readCount（当前读者数）、互斥信号量 rmutex（保护 readCount）、互斥信号量 wmutex（控制写者与读者的互斥）。**第一个读者**进入时 P（wmutex）把写者挡住，最后一个读者离开时 V（wmutex）放开写者；readCount 的增减由 rmutex 保护。

```text
写者进程：
  P(wmutex)
  写数据
  V(wmutex)

读者进程：
  P(rmutex)
  readCount = readCount + 1
  if readCount == 1: P(wmutex)   # 第一个读者占住写锁
  V(rmutex)
  读数据
  P(rmutex)
  readCount = readCount - 1
  if readCount == 0: V(wmutex)   # 最后一个读者释放写锁
  V(rmutex)
```

> [!IMPORTANT]
> 重要内容：**读者优先解法的钥匙是"第一个读者抢 wmutex、最后一个读者放 wmutex"**，中间读者既不抢也不放，从而多读者可同读、写者被第一个读者挡住。readCount 必须用 rmutex 保护（它是共享变量）。要防写者饿死，可在读者进入处加"写者优先"的互斥信号量，保证有写者在等时新读者等待。

### 哲学家进餐问题

**哲学家进餐问题**描述五位哲学家围坐圆桌，桌中央一碗米饭，每位哲学家左右各一根筷子。哲学家需**同时拿到左右两根筷子才能进餐**，用毕放下。它**用来说明如何避免死锁**——若每位哲学家都先拿左手筷再拿右手筷，可能五人各持一筷、互等对方放手而死锁。

**避免死锁的几种策略**：

- **至多允许 4 位哲学家同时拿起筷子**（设信号量 room 初值 4），保证至少一人能拿到两根。
- **规定奇数号哲学家先拿左手、偶数号先拿右手**，打破循环等待。
- **仅当哲学家左右两根筷子都空闲时才同时拿起**（用互斥信号量保护"检查并拿"的原子性），进餐完再同时放下。

```text
每根筷子是一个信号量（初值 1）。第 i 位哲学家用互斥信号量保证检查+拿起是原子的：
  P(mutex)
  检查并拿起左右两根筷子（若其中一根被占用则等待）
  V(mutex)
  进餐
  放下左右两根筷子
```

> [!WARNING]
> 警告内容：哲学家进餐警示的是**死锁的产生（循环等待）**，比生产者—消费者问题更高一层——单纯每人都"先左后右"会在极端情况下死锁。三种改法本质是：**限制并发人数、打破循环（奇偶反向）、原子化拿筷**。考试常让你指出"为何会死锁、如何避免"。

### 理发师问题

**理发师问题**描述一间理发店：一名理发师、若干等候椅。若店内有顾客，理发师给一位理发，其余顾客在等候椅上等待；若**无顾客，理发师休息**；顾客来时若理发师正忙但有空椅则坐下等待，若**椅子也满则离开**。该问题用于演示"**理发师休息与顾客离开**"这类需用信号量同时协调"服务方与被服务方"的同步。

**信号量设置**：设互斥信号量 mutex 保护顾客计数，同步信号量 barber（初值 0，理发师空闲/被占用状态）、同步信号量 customer（初值 0，等待的顾客数）；waiting 记录等待人数。

```text
理发师进程：
  循环：
    P(customer)        # 无顾客则休息，有顾客被唤醒
    P(mutex)           # 进入，把 waiting 减 1
    waiting = waiting - 1
    V(mutex)
    V(barber)          # 告诉顾客"可以开始理发"
    理发

顾客进程：
  P(mutex)
  if waiting < 椅子数:
    waiting = waiting + 1
    V(customer)        # 通知理发师有顾客
    V(mutex)
    P(barber)          # 等理发师就绪后接受理发
  理发
  else:
    V(mutex)           # 椅子满，离开
```

> [!NOTE]
> 提醒内容：理发师问题比前几个多一层"**双边同步**"——理发师等顾客（P customer）、顾客等理发师（P barber），两条同步信号量构成你来我往。抓住 waiting 计数与"椅子满离开"的分支即可。它是信号量解决"服务队列"类问题的代表。

### 管程机制

#### 管程的定义与组成

**管程（Monitor）**是一种**把共享数据结构及其上的操作（过程）封装在一起、并对并发访问自动互斥**的同步机制。它由**局部于管程的共享数据结构、对该数据结构的操作过程、以及对数据结构初始化**的语句组成。管程把"共享数据 + 对该数据的同步操作"捆绑，进程只有通过管程提供的入口过程才能访问共享数据。

**管程的核心特性**：

- **互斥性**：任一时刻**只允许一个进程**在管程内执行，进程进入管程即自动互斥，无需像信号量那样显式 P/V 互斥。
- **封装性**：共享数据对外不可见，只能通过管程内的过程访问，把对数据的保护集中起来。
- **同步由条件变量实现**：进程在管程内需要等待某条件时，用**条件变量**阻塞自己。

> [!NOTE]
> 提醒内容：**管程把"互斥"内建**（同一时刻只有一个进程在管程中），程序员不再手工写 P/V 护互斥；但仍需**条件变量**来处理同步（何时等待、何时唤醒）。管程由语言/操作系统提供支持，比裸信号量更不易出错。

#### 条件变量

**条件变量**是管程内用于**进程同步等待与唤醒**的变量，每个条件变量对应一种"进程要等待的条件"。进程在管程内执行到需要等待某条件时，对条件变量执行 **wait（x）** 把自己阻塞并**释放管程**（让其他进程能进入）；当条件满足时，另一进程执行 **signal（x）** 唤醒一个在该条件变量上等待的进程。

**要点**：

- **wait（x）**：阻塞进程并把其放入 x 的等待队列，同时**释放管程使用权**——否则别的进程进不来、条件永远不满足会死锁。
- **signal（x）**：唤醒 x 队列上的一个等待进程（若有），被唤醒进程从 wait 处继续。
- 条件变量**不保存计数**，只代表"队列"本身；signal 若无进程等待则空操作，不像信号量 V 会累计。

> [!WARNING]
> 警告内容：**条件变量与信号量不同**——条件变量无"计数"、signal 无等待者就白白丢弃；而信号量 V 总会把值加 1 保留下来。且**条件变量上的 wait 必须释放管程**，这与信号量 P 阻塞但不自动释放它保护的临界区不同。区分"管程条件变量 vs 信号量"是常见辨析点。

#### 用管程解决同步问题

**用管程解决同步问题**的思路：把共享缓冲区及生产者/消费者对它的操作封装进一个管程，在管程内的过程里用**条件变量**实现"缓冲区满则生产者等待、缓冲区空则消费者等待"的同步。

以管程实现生产者—消费者：管程内设缓冲区、变量 count（当前产品数）与两个条件变量 notfull（缓冲区不满）、notempty（缓冲区不空）。

```text
管程 boundedbuffer:
  过程 insert(item)：       # 生产者调用
    if count == N: wait(notfull)     # 缓冲区满则等待
    写入 item；count = count + 1
    signal(notempty)                 # 通知可能等待的消费者

  过程 remove()：           # 消费者调用
    if count == 0: wait(notempty)    # 缓冲区空则等待
    取出 item；count = count - 1
    signal(notfull)                  # 通知可能等待的生产者
```

**优点**：因为管程本身保证互斥，生产者、消费者调用 insert/remove 不必再写互斥 P/V；条件变量负责协调满/空两种同步，逻辑清晰、不易出错。调用者只是按语义调用对应过程即可。

> [!TIP]
> 建议内容：对比两种解法——**信号量方案要程序员自己摆对 P/V 并小心死锁；管程方案把互斥内建、同步交给条件变量，代码更结构化**。408 若让你写解法，信号量方案更常被要求手写；管程则重在理解其"互斥内建 + 条件变量同步"的机制与条件变量的 wait 须释放管程这一关键。
