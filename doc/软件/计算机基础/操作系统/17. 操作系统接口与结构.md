## 操作系统接口与结构

> **全章主脉**：用户/程序怎样"指挥"操作系统、系统又是怎样"开机启动"的，是本章主题。前半讲**用户接口**（命令接口与图形界面）与**系统调用**（用户程序进入内核的通道，含类型与典型例子）；后半讲**系统启动与引导**（开机后操作系统如何被加载运行）。核心是把"接口=系统对外的门"与"引导=系统如何启动"讲清。

### 用户接口

#### 联机命令接口与图形用户接口

**用户接口**是**操作系统向用户提供的使用计算机的界面**，按形式可分为**命令接口**与**程序（系统调用）接口**；命令接口又分**联机命令接口**与**脱机命令接口**，此外还有**图形用户接口（GUI）**。

- **联机命令接口**：用户**通过终端交互式地**输入命令，系统即时响应，如 shell 命令行——用户敲入命令、系统执行并反馈，**一条命令一个响应**。
- **脱机命令接口（批处理命令接口）**：用户把命令**写进作业说明书（批命令文件）**，一次提交给系统批量执行，不逐条交互。
- **图形用户接口（GUI）**：用**窗口、图标、菜单、鼠标点击**等图形化方式操作，用户不必记忆命令，本质上仍是把用户的图形操作转换成系统调用/命令执行。
- **程序接口（系统调用）**：供**应用程序**通过编程方式请求内核服务，是用户程序访问系统功能的唯一正规途径。

> [!NOTE]
> 提醒内容：**命令接口面向"人"**（shell 命令、批处理、GUI），**系统调用面向"程序"**。联机命令逐条交互、脱机命令成批提交、GUI 用图形替代命令。无论哪种用户接口，最终都要调用内核的功能来实现。

### 系统调用

#### 系统调用的类型与实现

**系统调用**是**操作系统为应用程序提供的、请求内核服务的编程接口**，本质是一条**陷入（trap）指令**触发、进入内核态执行相应的系统服务。它是**用户态与内核态之间的接口**，也是实现资源管理、保护系统安全的关键——应用程序不能直接执行特权操作，只能通过系统调用请内核代办。

**系统调用的类型**（按功能分）：**进程控制**（创建/终止进程）、**文件管理**（打开/读/写/关闭文件）、**设备管理**（申请/释放设备、读设备）、**信息维护**（获取系统时间、进程信息）、**通信**（进程间通信、网络）等。

**系统调用的实现步骤**：

1. 应用程序把**系统调用号**与参数放入寄存器（或压栈）。
2. 执行**陷入指令**（如 trap/syscall），**CPU 从用户态切换到内核态**。
3. 根据系统调用号**查系统调用表**，转入对应的内核处理程序。
4. 内核完成服务后返回，**CPU 切回用户态**，把结果返回给应用程序。

> [!IMPORTANT]
> 重要内容：**系统调用是"用户态进入内核态的通道"**——通过陷入指令把 CPU 从用户态切到内核态，才能执行受保护的特权操作。与普通函数调用不同：系统调用**要切换 CPU 状态、进入内核**，开销大，故应减少不必要调用。库函数（如 printf）内部常会触发系统调用（write），但库函数本身运行在用户态。

#### 典型系统调用举例

**典型系统调用**覆盖进程、文件、设备与信息维护等，举例如下。

- **进程控制**：fork（创建子进程）、exec（装入并执行新程序）、exit（终止进程）、wait（等待子进程结束）。
- **文件管理**：open（打开）、read、write、close、lseek（定位读写指针）、create（创建）、unlink/delete（删除）、stat（取文件属性）。
- **设备管理**：ioctl（控制设备）、read/write（对设备读写，与文件统一）。
- **信息维护**：getpid（取进程号）、time（取时间）、gettimeofday 等。
- **进程通信**：pipe（建管道）、socket、send/recv（网络收发）、共享内存/消息队列系统调用。

> [!TIP]
> 建议内容：记典型系统调用按"**进程（fork/exec/exit/wait）、文件（open/read/write/close）、设备（ioctl）、时间、通信**"归类。考试判断某功能"是否需系统调用"——只要涉及**特权操作、访问共享资源、创建进程/文件**等，就必须系统调用；纯用户态计算则不需要。fork 与 exec 之分：fork 复制本进程、exec 换上新程序镜像。

### 系统启动与引导

#### 引导过程

**系统启动（引导）**指**从开机加电到操作系统内核接管计算机**的过程。硬件无法自带操作系统，需一段**引导程序**把操作系统从磁盘装入内存运行。典型的引导流程是**加电 → 固件（BIOS/UEFI）自检 → 加载引导程序 → 引导程序装载内核**。

**引导过程的各步**：

1. **加电自检（POST）**：CPU 复位后从固定地址执行固件（ROM/BIOS/UEFI）代码，检测内存、CPU、基本设备是否正常。
2. **定位启动设备与引导扇区**：固件按设置找到启动盘（磁盘），读取其**引导扇区/引导程序**（如磁盘主引导记录 MBR 或 UEFI 引导项）。
3. **引导程序把内核载入内存**：引导程序（如 GRUB）把**操作系统内核映像**从磁盘读到内存指定位置。
4. **跳转执行内核**：CPU 跳转到内核入口，内核开始初始化。

> [!NOTE]
> 提醒内容：**引导是"从无到有把内核调入内存"**——先由固件做最小初始化，再由引导程序把真正的操作系统内核读进内存并交权。理解链条"**固件 → 引导程序 → 内核**"即可把握启动主线。引导程序一般放在磁盘引导扇区等固定位置，便于固件找到。

#### 操作系统内核的加载

**操作系统内核的加载**指引导程序把**内核映像载入内存后，内核完成自身初始化、接管系统**的过程。内核加载后要做一系列初始化才能提供完整服务。

**内核初始化工作**：

- **初始化核心数据结构**：建立进程表、内存管理、设备表等内核数据结构（常驻内存）。
- **建立初始进程/任务**：创建并调度第一个内核进程或 init 进程，后续用户进程由它派生。
- **初始化设备驱动与中断**：为各设备安装驱动、建立中断向量与处理程序。
- **建立文件系统与系统调用**：挂载根文件系统、建立系统调用入口表。
- **切换运行**：完成初始化后，内核进入多道运行状态，等待调度用户进程。

> [!WARNING]
> 警告内容：内核加载与引导程序的区别——**引导程序负责"把内核放进内存"（loader 的活），内核加载后负责"自我初始化、接管系统"**。二者常被混淆。内核初始化要先建立**最核心的进程与中断、内存管理**，再逐步扩展到文件系统与设备。判断某动作发生在"引导时"还是"内核初始化时"，看它是否在内核接管之后。
