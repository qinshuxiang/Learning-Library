## 操作系统引论

> **全章主脉**：操作系统是**管理计算机硬件与软件资源、为用户和应用程序提供服务的系统软件**。理解操作系统的钥匙是它的四大基本特性——**并发、共享、虚拟、异步**，其中并发与共享互为条件，是操作系统的核心。本章讲清操作系统是什么、怎么来的、有什么特性、管哪些资源、运行在怎样的环境下，以及本身如何组织。

### 操作系统的概念与目标

#### 操作系统的目标

**操作系统的目标**主要有四个：方便性（为用户提供良好的使用环境与接口）、有效性（提高资源利用率、提高系统吞吐量）、可扩充性（便于增加新功能）与开放性（遵循国际标准，便于互联互通）。不同用户对目标侧重不同，但从根本上看，**有效性**追求的是让有限的硬件资源发挥更高效率，**方便性**则让计算机更易用。

- **方便性**：提供命令接口与图形界面，用户不必了解硬件细节即可使用。
- **有效性**：一方面提高系统资源利用率，另一方面提高系统吞吐量。
- **可扩充性**：操作系统结构便于增加新模块与新功能而不需推倒重来。
- **开放性**：采用标准接口与协议，使不同厂商的软硬件能协同工作。

> [!NOTE]
> 提醒内容：操作系统作为**最接近硬件的系统软件**，其目标始终在"方便用户"与"提高资源利用率"之间取得平衡。解题时若问设计出发点，优先答"管理资源、提高利用率、方便用户"。

#### 操作系统的定义

**操作系统**是配置在计算机硬件上的第一层软件，是**对硬件资源进行管理、对软件资源进行分配与回收，并向用户提供接口的系统软件**。它介于用户/应用程序与计算机硬件之间，是所有系统软件中最基础的软件，其他软件都建立在操作系统之上。

从管理者角度，操作系统管理**处理机、存储器、设备与文件**四类资源；从用户角度，操作系统是**用户与计算机硬件之间的接口**；从资源分配角度，操作系统是**各种系统资源的管理者**。

> [!TIP]
> 建议内容：把握操作系统定义的三重身份——对上是**接口**（接用户）、对下是**管理者**（管硬件）、自处是**系统软件**（本质）。一句话串记：操作系统是管理资源、向上提供接口的最底层系统软件。

### 操作系统的发展过程

#### 批处理系统

**批处理系统**是最早成型的一类操作系统，其特点是作业成批输入、由操作系统自动调度执行、用户不干预运行过程，目标在于**提高资源利用率与吞吐量**。它经历了从无操作系统的**单道批处理**到引入多道程序技术的**多道批处理**两个阶段。

- **单道批处理**：内存中同时只驻留一道作业，CPU 与 IO 串行，作业成批后由监督程序自动调入，解决人机矛盾但仍存在大量 CPU 空闲。
- **多道批处理**：内存中同时驻留多道作业，作业在宏观上并行运行、微观上轮流占用 CPU，靠多道程序技术提高 CPU 与设备的利用率。

> [!NOTE]
> 提醒内容：多道批处理实现了**并发执行**，但缺少交互性——用户无法在作业运行中干预，调试困难。这是它后来被分时系统取代的重要动因。

#### 分时系统与实时系统

**分时系统**把 CPU 的时间划分成很短的时间片，轮流分配给各个终端用户，使多个用户通过终端同时与系统交互。其关键技术是**时间片轮转**，核心特征是**同时性、交互性、独立性、及时性**。分时系统解决了批处理缺少交互的问题，使每个用户都感觉独占一台计算机。

**实时系统**则要求系统在**规定的时间限制内**完成对事件的处理并作出响应，强调**及时性**与**可靠性**。它分为**硬实时系统**（必须在规定时刻前完成，如飞行控制）与**软实时系统**（允许偶尔超时，如视频点播）两类。

**对比分时与实时**：**追求目标**：分时为交互性与响应及时，实时为及时性与可靠性。**时间约束**：分时靠时间片轮转尽量及时，实时必须在时限内完成。**典型场景**：分时面向通用分时终端，实时面向工业控制、嵌入式与音视频。

> [!IMPORTANT]
> 重要内容：分时与实时都强调"快"，但本质不同——**分时的及时性是"尽量快、用户可容忍"，实时的及时性是"必须在限期内完成"**。实时系统通常**不强调强交互、不追求高资源利用率**，而把可靠性放在首位。

#### 现代操作系统的发展

**现代操作系统**的发展体现在多个方向：引入**多核与多处理机支持**（多个 CPU/核协同工作）、**线程概念**（进程内细粒度并行）、**微内核与可扩展结构**、以及面向网络的**分布式与云计算支持**等。

典型方向包括：

- **多处理机与并行**：支持对称多处理、多核调度，提升并行能力。
- **网络与分布式**：提供网络协议支持，使多台计算机协作完成计算。
- **虚拟化**：通过虚拟机技术让一台物理机运行多个操作系统，实现资源隔离与整合。
- **嵌入式与移动**：面向专用硬件的高效精简系统（如嵌入式实时操作系统）。

### 操作系统的基本特性

#### 并发与共享

**并发**是指**多个事件在同一时间间隔内发生**（宏观并行、微观上交替进行）。它是操作系统区别于顺序执行的关键特性，靠多道程序技术实现——多个进程在内存中同时存在，CPU 在它们之间快速切换，造成"同时运行"的假象。

**共享**是指**系统中的资源可供内存中多个并发执行的进程共同使用**。共享分**互斥共享**（同一时间仅一个进程能使用，如打印机、临界区内的共享变量）与**同时共享**（多个进程可同时访问，如可重入代码、磁盘这类宏观同时读写的设备）两种。

**并发与共享互为存在条件**：资源的共享以程序并发为前提，若程序不能并发执行，自然无需共享；而若系统不能有效管理共享，程序的并发也难以顺畅进行。因此二者常被并列为操作系统最基本的两个特性。

> [!IMPORTANT]
> 重要内容：**并发强调"多程序交替推进"，共享强调"资源被多程序共用"**，二者互为条件、不可分割。判断是否属于并发，看"是否在同一个时间间隔内都有执行"而非同一瞬间；多核下才存在真正的"同一瞬间并行"。

#### 虚拟与异步

**虚拟**是指**把一个物理实体映射为多个逻辑上的对应物**。操作系统的虚拟技术让用户感觉资源比实际更多、更强：如分时系统用一台物理 CPU 虚拟出多个"逻辑 CPU"给每个用户，虚拟存储器把外存虚拟成内存，SPOOLing 技术把一台物理打印机虚拟成多台逻辑打印机。

**异步**是指**进程以不可预知的速度向前推进**，进程何时运行、运行多久、是否被中断都无法事先确定。由于进程共享资源且并发执行，每个进程的执行顺序与速度由调度决定，具有不确定性。

> [!WARNING]
> 警告内容：虚拟与异步都源于多道程序环境——**虚拟靠"分时复用"或"空分复用"一个物理资源来造出多个逻辑资源；异步则强调并发进程的推进速度不可预知**。注意异步并不等于执行结果不确定，只要同步与互斥处理正确，结果仍是确定的。

### 操作系统的主要功能

#### 处理机管理

**处理机管理**的任务是**合理分配与调度 CPU，使多个进程高效、有序地运行**。其核心内容包括**进程管理**与**处理机调度**两大块，涉及进程的创建、撤销、状态转换以及 CPU 的分配策略。

- **进程管理**：负责进程的创建与终止、进程的状态转换、进程同步与互斥、进程通信。
- **处理机调度**：从就绪队列中按一定算法选出进程分配 CPU，涉及作业调度、进程调度与线程调度。

> [!NOTE]
> 提醒内容：处理机管理的对象本质是**进程与线程**，它回答"哪个进程、什么时候、占用 CPU 多久"。现代操作系统以线程为 CPU 调度单位、以进程为资源分配单位。

#### 存储器管理

**存储器管理**负责**对内存进行分配、回收、保护与扩充**，为用户程序提供可用的内存空间。它要解决的核心问题是**多道程序如何共享有限内存、如何保证彼此不越界干扰、如何提高内存利用率**。

- **内存分配与回收**：为进程分配所需内存、进程结束时回收，含连续分配与分页/分段等离散分配。
- **内存保护**：防止各进程越界访问或破坏其他进程与系统区。
- **地址映射**：把程序中的逻辑地址转换为物理地址（重定位）。
- **内存扩充**：通过虚拟存储器技术，逻辑上扩充内存容量，使大程序能在小内存上运行。

#### 设备管理与文件管理

**设备管理**负责**对计算机的输入输出设备进行分配、驱动与调度**，使用户方便、高效地使用设备。其任务包括设备分配与回收、设备驱动、缓冲管理以及磁盘等块设备的调度。

**文件管理**负责**对系统中的软件资源（文件）进行管理**，包括文件的存储、检索、共享与保护。操作系统以文件为基本单位管理外存上的信息，用户通过文件名即可访问数据，不必关心其在磁盘上的物理位置。

> [!NOTE]
> 提醒内容：四类管理可简记为"**管 CPU、管内存、管设备、管文件**"。设备管理面向硬件 I/O，文件管理面向外存上的数据集合，二者都涉及"分配—使用—回收"的资源管理闭环。

### 操作系统的运行环境

#### 操作系统的运行机制

**操作系统的运行机制**指操作系统与用户程序在 CPU 上交替执行时遵循的状态规则。CPU 的状态分为**内核态（核心态/管态）**与**用户态（目态）**两种，操作系统运行在内核态、用户程序运行在用户态，二者通过**程序状态字（PSW）**中的状态位标识。

- **内核态**：CPU 可执行**特权指令**（如修改 PSW、设置中断屏蔽、启停设备、清内存、切换进程），能访问全部内存与硬件。
- **用户态**：CPU 只能执行**非特权指令**（如普通运算、访存），不能直接访问关键资源与硬件。

> [!NOTE]
> 提醒内容：**区分内核态与用户态的本质，是能否执行特权指令**。只有操作系统内核运行在内核态，用户程序必须通过系统调用请求内核代为完成特权操作，从而保证系统安全。

#### 中断与异常

**中断**是CPU**在执行用户程序过程中被内部或外部事件打断、转去执行相应处理程序、处理完再返回原程序继续执行**的机制。中断是操作系统**由用户态进入内核态的唯一途径**，也是实现并发与多道的关键支撑。中断分为**外中断（中断）**与**内中断（异常）**两类。

- **外中断（中断）**：来自 CPU 外部的事件，如 I/O 完成、时钟中断、硬件故障，与当前指令无直接关系，也称**异步中断**。
- **内中断（异常）**：来自 CPU 内部的事件，由当前正在执行的指令引起，如缺页、除零、非法指令、溢出，也称**同步中断**。
- 此外**陷入（trap）**特指由**系统调用/陷入指令**主动引发的中断，用于请求内核服务，属内中断的一类。

> [!IMPORTANT]
> 重要内容：**中断响应过程**一般含关中断（保存现场、防止打断）、识别中断源、保护断点与现场（PC 与寄存器入栈）、转入中断处理程序、恢复现场并开中断返回。其中**通过陷入指令执行系统调用**是用户态请求内核服务的典型途径——用户态不能直接执行特权操作，只能触发陷入转内核态。

#### 系统调用与内核态用户态

**系统调用**是**操作系统提供给应用程序调用内核功能的一类接口**，本质是一条**陷入（trap）指令**。应用程序在用户态通过系统调用请求内核代为完成需要特权支持的操作，如进程创建、文件读写、设备操作、内存申请等。系统调用是**用户态进入内核态的手段**，也是内核态与用户态切换的典型场景。

- **用户态到内核态的切换**：应用程序执行陷入指令 → CPU 状态位置为内核态 → 转入内核中对应的系统调用处理程序。
- **内核态到用户态的返回**：系统调用处理完毕，恢复现场、状态位改回用户态，返回用户程序继续执行。
- **传递参数**：系统调用号与参数通过寄存器或堆栈传递给内核，内核据调用号分发到对应服务例程。

> [!CAUTION]
> 注意内容：**库函数调用与系统调用不同**——库函数在用户态执行（如 C 的 printf 内部才可能触发系统调用 write），而系统调用会切换到内核态。解题时区分"陷入指令产生的是内中断/异常"，"外部设备发的是外中断"，别把二者混为一谈。

### 操作系统结构设计

#### 整体式结构

**整体式结构**也称**模块接口法或无结构**，把操作系统设计成一组过程（模块）的集合，模块之间通过**直接相互调用**协作，没有清晰的层次。早期操作系统多用此法，结构简单、效率高，但模块间耦合紧密、可维护性与可移植性差。

- **优点**：模块间直接调用、开销小、系统效率高。
- **缺点**：模块关系复杂、接口不清晰、一旦出错难定位、不易扩充与维护。

> [!NOTE]
> 提醒内容：整体式结构把整个内核当作一个大的可执行体，所有功能在一个地址空间内。它追求"快"，却牺牲了"清晰"。

#### 模块化结构

**模块化结构**把操作系统**按功能划分为若干相对独立的模块**，每个模块实现一个功能块，模块之间有清晰的接口，可独立开发、测试与替换。相比整体式，它改善了可读性与可维护性，但模块间仍可能通过函数调用产生较强耦合。

- **特点**：按功能分模块、每个模块含若干功能、模块接口清晰。
- **优点**：提高系统设计正确性、可理解性与可维护性；模块可独立扩充。
- **不足**：模块划分与接口设计难度大，调用关系复杂时仍易耦合。

#### 分层与微内核结构

**分层结构**把操作系统**按功能划分为若干层次，每层建立在相邻下层之上、只能调用下层接口**。层次单向依赖使系统结构清晰、易于调试与验证（自底向上逐层验证），但也可能因层间调用带来性能损失。

**微内核结构**把操作系统的核心功能（如进程调度、内存基本管理、进程通信）放进一个很小的**内核（微内核）**，把文件系统、设备驱动、网络协议等**传统内核功能移到用户态作为独立服务进程**，各服务通过**消息传递**与微内核及其他服务通信。代表如 L4、MACH、Minix。

- **微内核的优点**：内核小、可扩展性好、可靠性高（驱动与服务故障不易拖垮内核）、便于移植与分布式。
- **微内核的不足**：用户态与内核态频繁切换、消息传递开销大，导致性能下降。

> [!TIP]
> 建议内容：结构演进口诀——整体式"大而杂"、模块化"按功能分"、分层式"单向依赖"、微内核"内核小、服务外移"。性能上整体式最高、微内核因频繁切换消息传递通常较低；健壮性可维护性上则相反。
