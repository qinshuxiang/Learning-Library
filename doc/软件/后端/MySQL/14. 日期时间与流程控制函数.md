## 日期时间与流程控制函数

### 日期时间函数

#### 当前时间三兄弟

**NOW、CURDATE、CURTIME 给出会话视角的当前时间**：取值发生在语句开始执行时。

- NOW() 返回完整的日期时间，如 2026-09-07 21:30:00
- CURDATE() 只到日期，CURTIME() 只到时间
- NOW() 在同一条语句内多次调用返回同一值，取的是语句开始时刻
- SYSDATE() 则取真实调用时刻，同语句内会继续走表

> NOW 的“语句级冻结”特性让时间戳列在同一事务里保持一致，正好适合审计字段；除非明确需要墙钟语义，一律用 NOW 而非 SYSDATE，避免同批数据时间漂移。

**速记**：**NOW 冻结在语句开头，SYSDATE 跟着墙钟走**。

```sql
SELECT NOW(), CURDATE(), CURTIME();
-- 结果：2026-09-07 21:30:00, 2026-09-07, 21:30:00
```



#### DATE_FORMAT 与 STR_TO_DATE

**格式化与解析互为逆运算**：DATE_FORMAT 出串，STR_TO_DATE 入库。

- DATE_FORMAT(dt, 模板) 按占位符输出字符串
- 常用占位符：百分号 Y 四位年、百分号 m 月、百分号 d 日、百分号 H 时、百分号 i 分、百分号 s 秒
- STR_TO_DATE(字符串, 模板) 按模板解析成日期时间
- 模板与实际格式不匹配时返回 NULL 或部分解析结果

> GROUP BY 按天统计的惯用式是 DATE_FORMAT(create_time, '百分号Y-百分号m-百分号d')；但该函数套在列上会让索引失效，数据量大时改为对常量侧做边界计算的范围查询。

**速记**：**FORMAT 出串 STR_TO_DATE 回，模板对齐才不吐 NULL**。

```sql
SELECT DATE_FORMAT(NOW(), '%Y-%m-%d %H:%i:%s') AS ts;
-- 结果：2026-09-07 21:30:00
```



#### 加减与差值

**日期加减用 DATE_ADD 配 INTERVAL**：单位词直接写进语句。

- DATE_ADD(dt, INTERVAL n DAY)：n 可正可负，负数即往前推
- DATE_SUB(dt, INTERVAL n HOUR) 与加负数等价
- DATEDIFF(d1, d2) 返回相差天数，只看日期不看时分秒
- TIMESTAMPDIFF(单位, d1, d2) 支持月、小时等精细单位

> 统计“最近 7 天”的边界写法是 create_time 大于等于 NOW 减 INTERVAL 7 DAY 且小于 NOW；直接用 DATE_FORMAT 截断到天会丢掉今天没过完的部分还是包含它，得先跟业务确认口径。

**速记**：**INTERVAL 写单位，DATEDIFF 数天，TIMESTAMPDIFF 精细到月**。

```sql
SELECT DATE_ADD(NOW(), INTERVAL -7 DAY) AS week_ago,
       TIMESTAMPDIFF(HOUR, '2026-09-07 09:00:00', NOW()) AS hours_passed;
```



#### 抽取与时间戳互转

**EXTRACT 拆字段，UNIX 时间戳做跨系统通信**：一个向内拆，一个向外换。

- EXTRACT(YEAR FROM dt)、EXTRACT(HOUR FROM dt) 等按单位抽取
- YEAR(dt)、MONTH(dt)、DAY(dt) 是等价的便捷写法
- UNIX_TIMESTAMP(dt) 转秒级时间戳，FROM_UNIXTIME(n) 反向转换
- 时间戳是无时区歧义的整数，适合接口传输与排序比较

> 抽取函数套在列上同样索引失效，与 13 篇的结论一致；时间戳互转受时区设置影响，跨时区系统统一存 UTC 时间戳是省心的底线方案。

**速记**：**EXTRACT 拆零件，时间戳整数通四海**。



### 流程控制函数

#### IF、IFNULL 与 NULLIF

**三个 IF 系函数处理分支与空值兜底**：短小，适合表达式位置。

- IF(条件, 真值, 假值)：条件为真取前者，否则取后者
- IFNULL(x, 兜底)：x 为 NULL 返回兜底，否则返回 x 本身
- NULLIF(a, b)：a 与 b 相等返回 NULL，否则返回 a
- COALESCE(a, b, c, ...) 返回第一个非 NULL 的参数，是通用兜底

> IFNULL 是 COALESCE 的两参特例，多来源兜底直接用 COALESCE；NULLIF 的妙用是“除零防护”：除数用 NULLIF(x, 0) 包一层，x 为零时整式得 NULL 而不是报错。

**速记**：**IF 二选一，IFNULL 兜空，NULLIF 凑等化空**。

```sql
SELECT IF(1 > 0, 'yes', 'no'), IFNULL(NULL, 'fallback'), NULLIF(3, 3);
-- 结果：yes, fallback, NULL
```



#### CASE WHEN 两种语法

**CASE 表达式在 SQL 里实现分支**：简单 CASE 与搜索 CASE 两种形态。

- 简单 CASE：CASE col WHEN 值1 THEN 结果1 ... ELSE 默认 END，做等值分发
- 搜索 CASE：CASE WHEN 条件 THEN 结果 ... END，条件任意组合
- 从上到下取第一个命中的分支，都不中走 ELSE，无 ELSE 返回 NULL
- CASE 是表达式不是语句，可用于 SELECT、WHERE、ORDER BY、聚合内部

> 行转列透视是 CASE 的招牌应用：按类型字段分组，每个类型一个 SUM(CASE WHEN) 列。分支里忘记写 ELSE 是常见漏洞，缺口处静默产出 NULL。

**速记**：**等值简单 CASE，条件搜索 CASE，命中即走漏网为 NULL**。

```sql
SELECT name,
       CASE WHEN score >= 90 THEN 'A'
            WHEN score >= 60 THEN 'B'
            ELSE 'C' END AS grade
FROM students;
```



#### 流程函数的工程位置

**能写进一条 SQL 的分支就不必拉回应用层**：但要守住边界。

- 简单映射、兜底、透视适合放 SQL，减少数据往返
- 复杂业务规则留在应用层，SQL 里的长 CASE 链是维护灾难
- CASE 套函数再套 CASE 的嵌套，先想想能否拆成多列或派生表
- 分支条件里能走索引的写法优先（常量侧转换）

> SQL 与应用层的职责分界没有铁律，可操作的判据是：这条规则会不会单独变化、要不要单测覆盖。要的，就挪回应用层。

**速记**：**SQL 管映射兜底，业务规则回家写**。



### 综合运用

#### 按时间维度统计的标准姿势

**时间维度统计 = 边界计算加分组**：模板固定，套用即可。

- 先用 INTERVAL 算出区间边界，写成对常量的范围条件
- 再用 DATE_FORMAT 或派生列做分组键
- 排序按分组键，必要时补齐空缺时段（应用层或日历表）
- 大数据量下为分组列建索引或用预聚合表

> 模板示例：统计近七天每日订单量。WHERE created_at 大于等于 CURDATE() 减 INTERVAL 7 DAY，GROUP BY DATE_FORMAT(created_at, '百分号Y-百分号m-百分号d')。记住边界含不含今天，要与业务口径核对。

**速记**：**边界算常量，分组截日期，空档莫忘补**。

```sql
SELECT DATE_FORMAT(created_at, '%Y-%m-%d') AS day,
       COUNT(*) AS cnt
FROM orders
WHERE created_at >= CURDATE() - INTERVAL 7 DAY
GROUP BY day
ORDER BY day;
```



#### 空值与缺省的表达策略

**流程函数是查询层兜底，不是设计层借口**：列设计仍是第一道关。

- 高频兜底说明该列的 NULL 语义混乱，回设计层重审
- 展示兜底用 COALESCE(nickname, name, '匿名用户') 链式兜底
- 统计场景先决定 NULL 是否计入：AVG 忽略 NULL，COUNT(列) 亦然
- 兜底值本身要有业务含义，别拿 0 或空串糊弄

> 查询里到处 IFNULL 的表，往往列定义时就没想清楚“空”表达的是未知、不适用还是尚未填写。三种语义混在一列里，任何函数都救不回来。

**速记**：**兜底在查询，治理在设计，NULL 语义先分家**。
