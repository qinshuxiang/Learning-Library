## MySQL 简介与安装配置

### MySQL 的认识

#### 什么是数据库

**数据库**：是**按一定数据结构组织、存储和管理数据**的软件系统，目的是让数据能够持久保存、高效检索并支持多用户共享。

数据库解决的问题可拆为四类：

- **持久化**：数据写入磁盘，程序重启、断电后依然保留。
- **结构化**：以表、行、列等结构描述数据，并施加类型与约束。
- **统一接口**：通过查询语言（如 SQL）读写，上层不必关心底层文件格式。
- **并发与安全**：多用户同时访问，由系统保证一致性与访问权限。

```sql
-- 用一条最简单的语句感受结构化查询
SELECT 1 + 1 AS result;
```

> 数据库与普通文件的本质差异，在于它维护**数据的结构与约束**（主键、外键、字段类型等），而不只是把字节落盘。零散配置、日志适合文件；需要关联查询与一致性的业务数据适合数据库。

> 速记：**落盘、有结构、能查询、可并发**。这四点就是数据库区别于普通文件夹的核心。



#### 什么是关系型数据库

**关系型数据库**：是**以二维表（关系）为数据模型**的数据库，表与表之间通过主键、外键建立关联，并使用 SQL 作为操作语言。

关系型数据库的核心特征：

- **表结构**：数据存放在行与列的二维表中，每列有固定类型。
- **关系建模**：表之间通过外键表达一对多、多对多等关联。
- **SQL 语言**：用声明式语言做增删改查，屏蔽存储细节。
- **事务与约束**：通过事务（ACID）与约束（唯一、非空、外键）保证正确。

```sql
-- 建两张有关系的表
CREATE TABLE department (
    id   INT PRIMARY KEY,
    name VARCHAR(50) NOT NULL
);

CREATE TABLE employee (
    id       INT PRIMARY KEY,
    name     VARCHAR(50) NOT NULL,
    dept_id  INT,
    FOREIGN KEY (dept_id) REFERENCES department(id)
);
```

> 关系型数据库的"关系"一词来自数学上的关系代数，并非指表之间的"人际关系"。它强调用**集合与代数运算**描述数据，而非层级或文档嵌套。非关系型数据库（NoSQL）则用文档、键值、图等模型，二者选型取决于数据形态。

> 速记：**表、键、SQL、事务**四件套。凡是二维表加外键加 SQL 的，就是关系型数据库。



#### MySQL 的历史与归属

**MySQL**：是**由瑞典 MySQL AB 公司创始、现归属 Oracle 公司**的关系型数据库，采用 GPL 双许可模式，并提供社区版与企业版两条产品线。

其归属与发展脉络：

- **起源**：1995 年由 Michael Widenius（Monty）等人创立，名字来自其女儿 My。
- **收购链**：2008 年 MySQL AB 被 Sun 收购，2010 年 Sun 被 Oracle 收购，MySQL 自此归属 Oracle。
- **双许可**：以 GPL 协议开源，同时提供商业许可供闭源集成。
- **两个版本**：**社区版（Community）** 免费开源；**企业版（Enterprise）** 含收费插件与官方支持。

```bash
# 查看当前 MySQL 的版本与发行信息
mysql --version
# 输出形如：mysql  Ver 8.0.36 for macos14 on arm64 (Homebrew)
```

> MySQL 的开源建立在 GPL 之上：基于其源码修改并分发的衍生作品，通常也需以 GPL 开源。这也正是 Oracle 收购后，社区担忧闭源化、从而催生 MariaDB 分支的背景之一，详见后续版本与分支一节。

> 速记：**瑞典起步、Oracle 收编、GPL 开源、社区免费企业收费**。



### MySQL 的版本与分支

#### 5.7 与 8.0 的差异要点

**MySQL 8.0**：是**当前主流大版本**，相比 5.7 在 SQL 能力、默认字符集与内部架构上有显著增强，是新建项目的首选版本。

二者关键差异：

- **默认字符集**：5.7 默认 latin1；8.0 默认 **utf8mb4**，原生支持表情与四字节字符。
- **窗口函数与 CTE**：8.0 新增 **窗口函数**（OVER）与 **公用表表达式**（WITH），5.7 不支持。
- **索引增强**：8.0 支持**不可见索引、降序索引、函数索引**。
- **原子 DDL**：8.0 的 CREATE、DROP 等元数据操作为原子操作，失败可回滚。
- **角色与权限**：8.0 引入**角色（ROLE）** 管理，权限分配更清晰。
- **查询缓存**：5.7 仍有查询缓存，8.0 **已移除**（详见第二讲）。

```sql
-- 8.0 才支持的窗口函数：按部门分组计算累计工资
SELECT
    dept_id,
    name,
    SUM(salary) OVER (PARTITION BY dept_id ORDER BY id) AS running_total
FROM employee;
```

> 升级到 8.0 时最常被忽视的是**字符集差异**：5.7 库若默认 latin1，迁移到 8.0 的 utf8mb4 需要显式转换，否则可能出现乱码。此外 8.0 默认认证插件改为 caching_sha2_password，旧驱动可能连不上，需要升级驱动或改回 mysql_native_password。

> 速记：**8.0 强在字符集、窗口函数、索引与原子 DDL；5.7 仍有查询缓存**。新项目直接上 8.0。

> [!TIP]
> **建议内容**：老 5.7 项目升级到 8.0 前，务必先在测试库跑通全部核心 SQL 与驱动兼容性，重点验证字符集、认证插件与窗口函数相关语法，避免直接上生产踩坑。



#### MariaDB

**MariaDB**：是**MySQL 创始人 Monty 主导 fork 的开源分支**，目标是保持 GPL 完全开源、避免 Oracle 收购后的不确定性，二者在协议层高度兼容。

MariaDB 的特点：

- **同源分流**：初始以 MySQL 5.5 为基准，代码逐步分化。
- **完全 GPL**：不提供商业闭源版本，社区驱动。
- **引擎多样**：除 InnoDB 外，还发展 Aria、ColumnStore 等自有引擎。
- **兼容优先**：命令行、SQL 语法与 MySQL 高度一致，便于迁移。

```bash
# 在 macOS 上用 Homebrew 安装 MariaDB
brew install mariadb
brew services start mariadb
```

> MariaDB 与 MySQL 的**兼容性并非永久保证**：随各自演进，部分新特性（如 MySQL 8.0 的窗口函数实现细节、某些系统表结构）已出现差异。生产环境若计划从 MySQL 切换到 MariaDB，需实测关键 SQL 与驱动兼容性，不能假设完全一样。

> 速记：**MariaDB：同宗、全开源、防闭源风险**，迁移前先测兼容性。



#### Percona Server

**Percona Server**：是**Percona 公司基于 MySQL 源码构建的增强分支**，面向高性能与可观测性，完全兼容 MySQL 协议与生态。

其主要增强：

- **XtraDB 引擎**：以 InnoDB 为基础的性能增强存储引擎（历史版本）。
- **线程池**：在高并发下通过线程池降低上下文切换开销。
- **可观测性**：内置更丰富的状态变量与慢查询诊断能力。
- **备份工具**：配套 Percona XtraBackup，支持不锁表的热备份。

```bash
# 使用 Percona XtraBackup 做物理热备（示意）
xtrabackup --backup --target-dir=/backups/full
```

> Percona Server 与官方 MySQL 的最大价值在于**性能诊断与备份生态**，而非改换 SQL 语义。它与 MySQL 二进制兼容，应用层通常无需改动即可切换，因此常用于对稳定性与备份要求极高的场景。

> 速记：**Percona：MySQL 的性能与运维增强版，协议全兼容**。



### MySQL 在 macOS 下的安装

#### Homebrew 安装

**Homebrew 安装**：是**macOS 上最简洁的 MySQL 安装方式**，通过包管理器一键安装并可用 brew services 管理开机自启，适合开发环境。

安装步骤：

- **更新与安装**：用 brew install mysql 拉取社区版 8.0。
- **启停服务**：用 brew services start mysql 后台启动。
- **临时运行**：mysql.server start 仅当前会话生效。
- **验证**：mysql --version 确认版本。

```bash
# 安装 MySQL 社区版
brew install mysql

# 设置为登录后自动启动并立即启动
brew services start mysql

# 查看运行状态
brew services list
```

> Homebrew 安装的 MySQL 默认数据目录、配置文件路径与官方 DMG 不同（通常位于 /opt/homebrew/var/mysql 或 /usr/local/var/mysql，因芯片架构而异）。卸载时除 brew uninstall 外，还需手动清理数据目录，否则重装会残留旧数据。

> 速记：**开发机首选 brew：install 装、services 管、list 查**。



#### 官方 DMG 安装包

**官方 DMG 安装包**：是**从 MySQL 官网下载的图形化安装镜像**，安装向导会引导设置初始密码并把 MySQL 加入系统偏好设置面板，适合希望使用官方原版的用户。

安装要点：

- **下载渠道**：前往 dev.mysql.com 下载对应 macOS 架构（arm64 或 x86_64）的 DMG。
- **安装向导**：双击挂载后运行 pkg，按提示完成。
- **初始密码**：8.0 会在安装结束界面给出 **root 临时密码**，务必记录。
- **系统面板**：安装后在系统偏好设置中出现 MySQL 图标，可启停。

```bash
# 通过官方 DMG 安装后，命令行工具通常位于
/usr/local/mysql/bin/mysql --version

# 将其加入 PATH（写入 shell 配置文件）
echo 'export PATH="/usr/local/mysql/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc
```

> DMG 安装的 MySQL 默认装在 /usr/local/mysql，命令不在默认 PATH 中，直接敲 mysql 会报命令未找到。务必把 /usr/local/mysql/bin 加入 PATH，或始终使用绝对路径调用。

> 速记：**DMG 装原版、记临时密码、别忘加 PATH**。



#### 安装后的初始化与 root 密码设置

**初始化与密码设置**：是**安装后让 MySQL 可用、安全的第一步**，8.0 不再允许 root 空密码，必须设置或重置后才能正常连接。

关键操作：

- **安全初始化**：运行 mysql_secure_installation 设密码、禁远程 root、删匿名用户。
- **首次登录**：用安装时给的临时密码登录后必须改密。
- **修改密码**：通过 ALTER USER 语句重置。
- **校验**：登录后执行 SELECT 验证。

```bash
# 交互式安全设置（设置 root 密码、移除匿名用户等）
mysql_secure_installation
```

```sql
-- 登录后修改 root 密码（MySQL 8.0 语法）
ALTER USER 'root'@'localhost' IDENTIFIED BY 'NewStrongPass!2024';

-- 验证当前用户与版本
SELECT CURRENT_USER();
SELECT VERSION();
```

> 8.0 的密码管理有两点易错：**认证插件**默认为 caching_sha2_password，旧版客户端（如某些老 JDBC）需升级；mysql_secure_installation 中途若选了密码强度校验，密码需满足策略（长度、大小写、特殊字符），否则 ALTER USER 会失败。不同发行版下初始密码的获取方式略有差异（DMG 显示在界面，brew 常为空需自行设）。

> 速记：**先 secure、再 ALTER、记牢密码、查版本**。



### 服务的启动、停止与自启动

#### brew services

**brew services**：是**Homebrew 提供的服务管理器**，把 MySQL 注册为登录项，实现开机自启与持久后台运行，是 brew 安装后的标准启停方式。

常用命令：

- **启动并自启**：brew services start mysql。
- **停止并取消自启**：brew services stop mysql。
- **重启**：brew services restart mysql。
- **状态列表**：brew services list。

```bash
# 启动并设置登录自启
brew services start mysql

# 停止（同时移除自启）
brew services stop mysql

# 查看所有 brew 托管服务的状态
brew services list
```

> brew services start 与 mysql.server start 都能启动 MySQL，区别在于**前者常驻并自启、后者仅当前会话运行**。若用 brew 安装却直接 mysql.server start，重启电脑后服务不会自动恢复，需重新手动启动。

> 速记：**brew services 管开机自启，mysql.server 管临时运行**。



#### mysql.server

**mysql.server**：是**MySQL 自带的 Shell 启停脚本**，基于系统的 SysV 风格接口，适合手动、一次性地启动或停止服务。

常用操作：

- **启动**：mysql.server start。
- **停止**：mysql.server stop。
- **重启**：mysql.server restart。
- **状态**：mysql.server status。

```bash
# 用自带脚本启动（当前会话有效）
sudo mysql.server start

# 停止服务
sudo mysql.server stop
```

> 官方 DMG 安装包通常把 mysql.server 放在 /usr/local/mysql/support-files/ 下。直接 mysql.server 报命令未找到时，要么进入该目录执行，要么把它加入 PATH。以 sudo 运行是因为要写入数据目录与占用端口，普通用户可能权限不足。

> 速记：**mysql.server 是手工开关，关电脑就停**。



#### systemctl

**systemctl**：是**Linux 系统的 systemd 服务管理命令**，在 Linux 服务器上（如 CentOS、Ubuntu 较新版本）用于管理 mysqld 的开机自启与运行。

常用命令：

- **启动**：systemctl start mysqld。
- **开机自启**：systemctl enable mysqld。
- **状态**：systemctl status mysqld。
- **停止**：systemctl stop mysqld。

```bash
# 在 Linux 服务器上启动并设置自启
sudo systemctl start mysqld
sudo systemctl enable mysqld
sudo systemctl status mysqld
```

> macOS 没有 systemctl，这条命令仅适用于 **Linux 服务器环境**；在 Mac 上使用会报 command not found。本地开发用 brew services 或 mysql.server，生产服务器（Linux）才用 systemctl，二者不要混淆。

> 速记：**本地用 brew/server，服务器用 systemctl**。



### 连接与断开服务

#### mysql 客户端命令行工具

**mysql 客户端**：是**MySQL 自带的命令行连接工具**，通过它可以向服务器发送 SQL、查看结果，是学习与排障最基础的手段。

其基本形态：

- **交互模式**：直接敲 mysql 进入，逐条输入 SQL。
- **连接对象**：默认连本机、端口 3306 的 mysqld。
- **输出形式**：结果以表格化文本展示，便于阅读。
- **脚本能力**：可配合 -e 或重定向执行批量 SQL。

```bash
# 进入交互式客户端
mysql -u root -p
```

> mysql 客户端本身**不是数据库**，它只是一个传话的人，真正存数据的是背后的 **mysqld 服务器进程**。客户端断开不影响服务器运行，其他客户端仍可继续连接。

> 速记：**mysql 是话机，mysqld 是总机**。



#### 常用连接参数

**连接参数**：是**mysql 客户端用于定位服务器与身份的参数**，常用组合即可覆盖绝大多数本地与远程连接场景。

高频参数：

- **-u（--user）**：指定登录用户名，如 root。
- **-p（--password）**：提示输入密码，建议不要在命令行明文写密码。
- **-h（--host）**：指定服务器地址，本地默认 localhost。
- **-P（--port）**：指定端口，默认 3306。
- **-D（--database）**：连接后直接选中某库。

```bash
# 连接本地 3306 的 MySQL，用户 root，并直接进入 test 库
mysql -u root -p -h 127.0.0.1 -P 3306 -D test

# 连接远程服务器（示例）
mysql -u appuser -p -h 192.168.1.10 -P 3306
```

> 注意 **-p 与 -P 的大小写区别**：小写 -p 是密码，大写 -P 是端口，写反会导致连不上或密码错。另外 -h localhost 在 Unix 系默认走 **Unix 域套接字**而非 TCP，若要强制走 TCP 需写 -h 127.0.0.1。不同版本/发行版下默认值略有差异。

> 速记：**-u 用户、-p 密码、-h 主机、-P 端口、-D 库；小 p 密码大 P 端口**。

> [!CAUTION]
> **注意内容**：不要在 -p 后直接写明文密码（如 -p123456），密码会出现在进程列表与 shell 历史中，存在泄露风险；应只用 -p 让系统交互提示输入，或用配置文件托管凭据。



#### exit 与 quit

**exit 与 quit**：是**mysql 交互模式中退出客户端的等效命令**，输入任一并回车即可断开当前连接、回到系统 shell。

使用方式：

- **exit**：输入后回车退出。
- **quit**：与 exit 完全等价。
- **快捷键**：Ctrl + D 同样可退出。
- **效果**：仅关闭当前客户端会话，不停止服务器。

```sql
-- 在 mysql 交互提示符下
exit
-- 或
quit
```

> exit、quit 只关闭**当前这条客户端连接**，服务器进程 mysqld 不会被关闭，其他连接照常工作。这与停止服务是两回事：停止服务要回到系统层用 brew services stop 或 systemctl stop，而不是在客户端里敲 exit。

> 速记：**exit/quit 退客户端、不动服务器**。



### MySQL 的配置文件

#### my.cnf 的查找顺序

**my.cnf**：是**MySQL 的主配置文件**，服务器启动时会按固定顺序读取多个可能的位置，靠后的文件中的同名配置项会覆盖靠前的。

典型查找顺序（由先到后）：

- **/etc/my.cnf**：系统级全局配置。
- **/etc/mysql/my.cnf**：部分发行版使用的路径。
- **basedir/my.cnf**：MySQL 安装目录下的配置。
- **~/.my.cnf**：当前用户的个人配置。

```bash
# 查看 mysqld 实际读取配置文件的顺序
mysqld --verbose --help | grep -A 1 "Default options"

# macOS 上 brew 安装的默认配置位置示例
ls /opt/homebrew/etc/my.cnf 2>/dev/null
```

> 配置文件的**读取顺序是后者覆盖前者**，而非合并叠加。当某项配置改了不生效时，多半是被更靠后（如 ~/.my.cnf）的同名项覆盖了。排查时优先用 mysqld --verbose --help 打印的实际顺序，不同版本/发行版下路径略有差异。

> 速记：**后者覆盖前者，改不生效先查加载顺序**。



#### 常用配置项

**常用配置项**：是**my.cnf 中高频调整的参数**，覆盖端口、字符集、数据目录、连接数与包大小，直接决定实例的可用性与性能。

关键配置项：

- **port**：监听端口，默认 **3306**。
- **character-set-server**：服务端字符集，8.0 默认 **utf8mb4**。
- **datadir**：数据文件存放目录。
- **max_connections**：最大并发连接数，默认 151。
- **max_allowed_packet**：单条 SQL 或包的最大字节，默认约 64MB。

```ini
[mysqld]
port = 3306
character-set-server = utf8mb4
datadir = /opt/homebrew/var/mysql
max_connections = 200
max_allowed_packet = 128M
```

> 修改配置后必须**重启 MySQL 才能生效**，仅改文件不会热加载（少数动态变量除外，可用 SET GLOBAL 即时改）。另外 max_connections 设得过大可能撑爆内存：每个连接都占用线程与缓冲，需结合服务器内存权衡，并非越大越好。

> 速记：**端口 3306、字符集 utf8mb4、连接数看内存、改完要重启**。



### 图形化工具与初体验

#### MySQL Workbench

**MySQL Workbench**：是**Oracle 官方推出的免费图形化管理工具**，集连接管理、ER 建模、SQL 编辑与服务器状态监控于一体，是官方首选的 GUI。

主要功能：

- **连接管理**：可视化配置多个数据库连接。
- **SQL 开发**：带语法高亮、自动补全的编辑器。
- **建模**：正向/反向工程生成 ER 图。
- **运维**：查看状态、用户与权限、导出导入。

```bash
# macOS 上可用 brew 安装 Workbench（cask）
brew install --cask mysqlworkbench
```

> Workbench 对 **MySQL 官方版本** 支持最完整；连接到 MariaDB 或 Percona 时，部分监控面板可能因系统表差异而显示不全，但基础 SQL 与连接不受影响。它偏重，仅做简单查询时略显笨拙。

> 速记：**官方免费、重建模、全功能**。



#### DataGrip

**DataGrip**：是**JetBrains 出品的跨数据库商业 IDE**，支持 MySQL、PostgreSQL、Oracle 等多种数据库，以强大的智能提示与重构能力著称，适合多数据库开发者。

特点：

- **多库统一**：一套界面管理多种数据库类型。
- **智能提示**：基于上下文的字段、表名补全。
- **版本控制**：SQL 文件纳入 Git 管理。
- **收费**：需订阅，提供试用。

> DataGrip 的优势在**跨数据库与代码智能**，而非某一种库的特殊功能。若团队只用 MySQL，免费的 Workbench 已够用；若同时维护多种数据库，DataGrip 的投入更划算。

> 速记：**多库通吃、智能补全、商业收费**。



#### Navicat

**Navicat**：是**老牌商业数据库管理工具**，以易用的界面、强大的数据同步与导入导出著称，在国内使用广泛。

特点：

- **易上手**：向导式操作，新手友好。
- **数据迁移**：库间结构/数据同步方便。
- **定时任务**：可作备份与调度。
- **收费**：需授权。

> Navicat 的强项在**数据迁移与可视化操作**（如拖拽建表、导入 Excel），但重度依赖它的点点点可能弱化对 SQL 本身的掌握。学习阶段建议搭配命令行，知其然也知其所以然。

> 速记：**界面友好、迁移强、商业授权**。



#### mysql -e 非交互模式

**mysql -e 非交互模式**：是**不进入交互提示符、直接执行一条 SQL 并退出的方式**，常用于脚本、定时任务与自动化运维。

用法要点：

- **-e（--execute）**：后接要执行的 SQL 字符串。
- **结合 -u/-p**：照常提供身份参数。
- **输出定向**：结果可重定向到文件或管道。
- **批处理**：与 shell 脚本配合做定时统计。

```bash
# 非交互地查看版本与当前库列表
mysql -u root -p -e "SELECT VERSION(); SHOW DATABASES;"

# 把查询结果导出到文件
mysql -u root -p -e "SELECT * FROM test.user" > users.txt
```

> 非交互模式把 MySQL 变成命令行过滤器，特别适合 **cron 定时任务、监控脚本、CI 流水线**。注意 -e 后 SQL 用引号包裹，含特殊字符时注意 shell 转义；不要在命令里明文写密码，建议用 -p 交互输入或配置文件托管凭据。

> 速记：**-e 一句话执行、退可进脚本、密码别明文**。
