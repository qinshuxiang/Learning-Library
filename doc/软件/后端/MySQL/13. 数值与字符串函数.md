## 数值与字符串函数

### 数值函数

#### 取整与截断四兄弟

**取整函数按方向各司其职**：四舍五入、向上、向下、直接截断。

- ROUND(x, d)：四舍五入到 d 位小数，d 缺省为 0
- CEIL(x)：向上取整，CEILING 是同义写法
- FLOOR(x)：向下取整
- TRUNCATE(x, d)：直接砍掉 d 位之后的小数，不进位

> ROUND 与 TRUNCATE 在金额上会产生一分的差异：四舍五入有进位，截断没有。财务场景必须与业务方确认口径，全链路统一，不能一处 ROUND 一处 TRUNCATE。

**速记**：**ROUND 进 CEIL 顶 FLOOR 压 TRUNCATE 砍**。

```sql
SELECT ROUND(3.567, 2), CEIL(3.1), FLOOR(3.9), TRUNCATE(3.567, 2);
-- 结果：3.57, 4, 3, 3.56
```



#### 取模、绝对值与随机数

**MOD、ABS、RAND 覆盖基础数值需求**：用法简单，陷阱在随机性。

- MOD(x, y) 与 x MOD y、x % y 三写法等价
- ABS(x) 返回绝对值，负数变正
- RAND() 返回 0 到 1 之间的随机小数，每次调用都不同
- RAND(n) 带种子时同一种子产生同一序列，可复现

> ORDER BY RAND() 是著名的大表毒药：为每一行算随机数再排序，代价是全表扫描加 filesort。随机抽样的正确姿势是先随机主键区间再取行，或应用层预生成随机池。

**速记**：**MOD 求余 ABS 归正，RAND 别进大表 ORDER BY**。



#### FORMAT 千分位格式化

**FORMAT 负责人读的数字格式**：千分位加指定小数位。

- FORMAT(1234567.891, 2) 返回 1,234,567.89，带千分位逗号
- 第二参数是保留小数位，四舍五入进位
- 返回结果是字符串，不能再参与数值运算
- 千分位分隔符与小数点字符受区域设置影响

> FORMAT 的输出只适合展示层直接消费；接口返回给前端的数字应保持数值类型，格式化交给前端或模板层，避免字符串数字在链路中传染。

**速记**：FORMAT **管展示不管计算，逗号一加就成串**。



### 字符串函数

#### 长度两兄弟：字符与字节

**CHAR_LENGTH 数字符，LENGTH 数字节**：utf8mb4 下两者差得远。

- CHAR_LENGTH('数据库') 返回 3，按字符计
- LENGTH('数据库') 在 utf8mb4 下返回 12，每个汉字 4 字节
- VARCHAR(n) 的 n 是字符数而非字节数，索引 key_len 计算才涉及字节
- 判断输入长度限制（如手机号 11 位）用 CHAR_LENGTH

> 校验用户名、验证码等长度时用错函数，中文用户会被莫名其妙地拒绝：LENGTH 把一个汉字当四个字节。记住口诀：给人看的长度用字符，存储引擎的账用字节。

**速记**：**CHAR_LENGTH 按字，LENGTH 按字节，中文差四倍**。



#### 拼接与分隔

**CONCAT 与 CONCAT_WS 负责拼串**：对 NULL 的态度是两者的分水岭。

- CONCAT(a, b, c) 依次拼接，任一参数为 NULL 整体即 NULL
- CONCAT_WS(分隔符, a, b) 用分隔符连接，自动跳过 NULL
- 拼接数字与日期会先隐式转为字符串
- 常用于生成展示文本、构造日志键、拼接字典值

> 地址、姓名拼接首选 CONCAT_WS：字段里有 NULL 也不会把整个地址变成 NULL。CONCAT 的 NULL 传染性让它只适合保证非空的场景。

**速记**：**CONCAT 遇 NULL 全灭，CONCAT_WS 跳空续拼**。

```sql
SELECT CONCAT('a', NULL, 'b'), CONCAT_WS('-', 'a', NULL, 'b');
-- 结果：NULL, a-b
```



#### 截取三件套

**SUBSTRING、LEFT、RIGHT 负责取子串**：下标从 1 开始是 MySQL 的约定。

- SUBSTRING(str, pos, len)：从 pos 起取 len 个字符，pos 从 1 数
- pos 为负表示从尾部倒数，如 SUBSTRING(str, -4) 取末 4 字符
- LEFT(str, n) 取最左 n 字符，RIGHT(str, n) 取最右 n 字符
- len 省略时取到字符串末尾

> 从 1 开始而非 0，是 SQL 世界的通用约定，与多数编程语言的 0 起点相反；写惯了应用代码再来写 SQL，这是最容易串台的一处。

**速记**：**下标从 1 起，负数从尾数，左右各取 n**。

```sql
SELECT SUBSTRING('20260907-report', 1, 8), SUBSTRING('20260907-report', -6);
-- 结果：20260907, report
```



#### 清理与替换

**TRIM、REPLACE 负责清理脏字符**：入库前与展示前各用一次。

- TRIM(str) 去两端空格；LTRIM、RTRIM 只去一侧
- TRIM(LEADING/TRAILING/BOTH 'x' FROM str) 可去指定字符
- REPLACE(str, from, to) 全文替换所有出现的 from
- UPPER 与 LOWER 转大小写，对中文无效果

> 用户输入入库前 TRIM 是标准动作，能消灭一大类“看起来一样却查不到”的脏数据；REPLACE 要注意它替换所有出现位置，想做“只替换第一个”得绕路组合函数。

**速记**：**TRIM 去边角，REPLACE 全换，大小写只管拉丁**。



#### 定位与补位

**LOCATE 找位置，LPAD/RPAD 补位**：一查一补，配合出花样。

- LOCATE(sub, str) 返回子串首次出现位置，从 1 起数，找不到返回 0
- INSTR(str, sub) 参数顺序相反，功能相同
- LPAD(str, n, pad) 从左侧补 pad 到总长 n，超长则从左截断
- 订单号补零：LPAD(id, 8, '0') 把 42 变成 00000042

> LPAD 超长截断的特性既是便利也是坑：想补位却把关键内容截掉了。对定长编号生成，先确认源长度上限，或干脆在应用层生成编号。

**速记**：**LOCATE 找得到返回位置找不到归零，LPAD 补零也截长**。

```sql
SELECT LOCATE('bar', 'foobar'), LPAD(42, 8, '0');
-- 结果：4, 00000042
```



### 函数与索引

#### 列上套函数的代价

**对索引列套函数会让索引失效**：函数的结果没有索引可查。

- WHERE YEAR(create_time) = 2026 触发全表扫描
- 改写为范围条件可救：create_time 大于等于年初且小于次年年初
- UPPER(col) = 'ABC' 同理，改用与排序规则匹配的直接比较
- EXPLAIN 的 type 退化为 ALL 即中招（27 篇）

> 口诀是“函数上列，索引离别”：要转换就转换常量侧，或把表达式结果落成生成列再加索引。逐行执行函数的 CPU 成本只是小头，丢索引的全表扫描才是大头。

**速记**：**函数套列索引丢，改写范围或转常量**。

```sql
-- 失效写法与等价改写
-- WHERE YEAR(created_at) = 2026
SELECT * FROM orders
WHERE created_at >= '2026-01-01' AND created_at < '2027-01-01';
```



#### 函数选型的工程判断

**能用简单比较就不用函数**：函数链越长，优化空间越小。

- 简单等值与范围比较优先，函数只在表达语义必需时出现
- 展示型格式化尽量挪到应用层，数据库专心存取
- 计算列高频使用时考虑生成列加索引，而不是每次现算
- 同一表达式在 WHERE、SELECT、ORDER BY 反复出现是坏味道

> 数据库函数是把双刃剑：就近计算省网络，但也把负载钉死在数据库上。判断标准是可下推、可索引、低频使用；否则上移到应用层。

**速记**：**函数就近便利贵，能索引才留库**。
