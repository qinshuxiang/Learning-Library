## 运算符

### 算术与比较

#### 算术运算符

**算术运算符做数值计算**：加减乘除之外还有整除与取模两个专用符号。

- 加减乘除：+、-、*、/
- DIV 整除取商，MOD 或百分号取余，两者等价
- 除法结果是小数，除零返回 NULL 而不报错
- 参与运算的操作元会被隐式转为数字

> 除零与溢出在默认模式下静默返回 NULL，在严格模式下部分场景报错；对金额、库存等关键计算，应先在应用层校验除数与范围，别指望数据库替你兜底。

**速记**：**DIV 商 MOD 余，除零得 NULL 不炸**。

```sql
SELECT 7 DIV 2, 7 MOD 2, 7 / 2, 7 / 0;
-- 结果：3, 1, 3.5000, NULL
```



#### 比较运算符

**比较运算符产出布尔结果**：真、假，或三值逻辑中的 NULL。

- 等号与两种不等写法：=、<>、!=，标准写法是不等用 <>
- 大小比较：大于、小于、大于等于、小于等于
- BETWEEN、IN、IS、LIKE、REGEXP 也是比较运算符家族成员
- 任一侧为 NULL，比较结果即为 NULL

> 比较的输入类型不一致时发生隐式转换（本篇末节详述），转换规则决定了 '10' 与 10 相等、'abc' 与 0 相等这类反直觉结果。

**速记**：**比较出真假冒牌 NULL，类型不齐先转换**。



#### 安全等于

**安全等于可以正确处理 NULL**：NULL 与 NULL 判等返回 1。

- 写法是等号前加感叹号，即 <=> 操作符
- 两操作元相等或都为 NULL 时返回 1，否则返回 0
- 结果集里不会出现 NULL，适合用在连接条件与计算表达式
- IS NULL 与 IS NOT NULL 仍然是判空的首选读法

> 安全等于解决了“NULL 判等失灵”，但也让代码读者多一次停顿；WHERE 判空优先用 IS NULL，只在连接键可能为 NULL 的场景才请出 <=>。

**速记**：<=> **认 NULL 为同类，判空首选仍是 IS**。

```sql
SELECT 1 <=> 1, NULL <=> NULL, NULL = NULL;
-- 结果：1, 1, NULL
```



### 逻辑运算

#### AND、OR、NOT 与三值逻辑

**逻辑运算在三值逻辑下运行**：真、假之外还有 UNKNOWN。

- AND：任一为假即假，遇 NULL 未定则结果可能为 NULL
- OR：任一为真即真，全 NULL 才是 NULL
- NOT 对 NULL 取反仍是 NULL
- WHERE 只保留条件为真的行，NULL 与假同等落选

> NOT IN (子查询) 在子查询返回 NULL 时的空结果灾难，根源正是三值逻辑：x NOT IN (1, NULL) 对任何 x 都无法证明为真。

**速记**：**三值逻辑，NULL 传染，WHERE 只收真**。

```sql
-- NOT IN 遇 NULL 的经典陷阱
SELECT 2 NOT IN (1, NULL);   -- 结果：NULL
SELECT 2 NOT IN (1, 3);      -- 结果：0（假，2 在列表中）
```



#### XOR 异或

**XOR 是“二者恰好其一为真”**：同为真或同为假时结果为假。

- 真 XOR 假得真，真 XOR 真得假，NULL 参与 XOR 结果为 NULL
- 语义等价于两者不相等的布尔判断
- 使用频率远低于 AND 与 OR，多见于校验类条件
- 可用不等价的条件组合改写，可读性往往更好

> 业务上出现 XOR 时先想想是不是两个互斥条件；用 (a AND NOT b) OR (b AND NOT a) 改写虽然冗长，但语义对所有人显式。

**速记**：XOR **恰好一真才真，NULL 一掺就懵**。



### 位运算

#### 位运算符概览

**位运算直接操作二进制位**：在状态标记场景偶有登场。

- 按位与、或、异或、取反；左移与右移
- 典型用途：用一个整数的每个二进制位表示一个开关状态
- 判断某位是否开启：flags 与掩码按位与后是否非零
- 设置与清除某位：按位或上掩码、按位与上取反掩码

> 位标记省列但难懂：查不出某标志位为真的行走不了普通索引，可读性与可维护性都差。新表设计慎用，存量数据迁移时再评估。

**速记**：位运算 **一数多态省列费解，查标志难走索引**。

```sql
-- flags 第 2 位（值为 4）是否开启
SELECT * FROM tasks WHERE flags & 4;
```



### 隐式类型转换

#### 转换的基本规则

**类型不一致时 MySQL 自动转换**：规则记不住，结果就会骗你。

- 字符串与数字比较：字符串整体转数字，开头非数字部分丢弃
- '10' = 10 为真；'abc' = 0 也为真（转不成数字即 0）
- 布尔上下文里非零为真：'1'、'-2' 都是真
- 日期与字符串比较时字符串会尝试转日期

> 'abc' = 0 为真是面试与事故双高发点：整串无法解析成数字就按 0 处理，比较于是为真。凡涉及用户输入与数字列的比较，先在应用层定型。

**速记**：**字符碰数字先变数，变不动就按零算**。

```sql
SELECT '10' = 10, 'abc' = 0, '3abc' = 3;
-- 结果：1, 1, 1
```



#### 隐式转换与索引失效

**隐式转换能悄悄废掉索引**：这是它最贵的一面。

- 数字列传字符串：列被套上转换函数，索引失效，全表扫描
- 字符串列传数字：字符串常量转数字，索引仍可用
- 方向记忆法：转换发生在列上就失效，发生在常量上无妨
- EXPLAIN 里表现为 type 退化到 ALL、key 为空

> user_id 是 BIGINT 而代码传了字符串 '123'，在数据量小的测试环境毫无感知，上了生产就是全表扫描事故。ORM 参数类型、DTO 类型校验是第一道防线。

**速记**：**列被转换索引死，常量转换无大碍**。



### 优先级与工程习惯

#### 运算符优先级要点

**优先级决定表达式如何分组**：记不住就把括号写上。

- 大致次序：算术高于比较，比较高于 NOT，NOT 高于 AND，AND 高于 OR
- 位运算夹在算术与比较之间，容易被误读
- 同级运算从左到右结合
- 括号最高，任何拿不准的场合直接加括号

> 依赖优先级的语句是在给未来的读者出题：加括号不改变语义时零成本，改变了语义时那就是救命。SQL 评审中裸奔的混合逻辑一律打回。

**速记**：**算术比较再逻辑，拿不准就上括号**。



#### 显式转换函数

**CAST 与 CONVERT 做显式转换**：把转换从暗处搬到明处。

- CAST(表达式 AS 类型) 是标准写法，CONVERT 是 MySQL 方言
- 常用目标类型：SIGNED、UNSIGNED、CHAR、DECIMAL、DATE
- 显式转换让意图可见，也避免了依赖隐式规则的赌博
- 转换失败的行为同样遵循严格模式设置

> 在查询边界把外部输入先 CAST 成正确类型，既明确语义又能保住索引方向：把常量侧转成列的类型，转换就落在常量上。

**速记**：**CAST 挑明意图，转换常量保索引**。

```sql
-- 把字符串显式转为整数后再比较
SELECT * FROM orders
WHERE user_id = CAST('123' AS SIGNED);
```
