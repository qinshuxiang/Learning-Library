## 数据操作：INSERT、UPDATE、DELETE

### INSERT：写入数据

#### INSERT 的基本形式

**INSERT 向表中插入行**：指定列清单再给出对应值，是标准且推荐的写法。

- 完整形式：INSERT INTO 表名 (列1, 列2) VALUES (值1, 值2)
- 指定列清单后，未列出的列取默认值或 NULL
- 不写列清单则必须按建表顺序给全所有列，列顺序一变就出错
- 一条语句可插入多行：VALUES 后跟多组括号，逗号分隔

> 批量插入比逐条插入快得多：减少语句解析与网络往返。但单语句行数过大时会超出 max_allowed_packet，实践中每批几百到几千行为宜。

**速记**：**列清单加 VALUES，批量括号逗号隔**。



#### 自增主键与默认值

**自增列与默认值列可以省略**：让数据库自己生成。

- 自增主键不写即自动取当前最大值加一，或写 NULL 或 DEFAULT 触发生成
- 有默认值的列省略后填默认值，显式写 DEFAULT 同效
- 时间列常配 DEFAULT CURRENT_TIMESTAMP 自动记创建时间
- 插入后用 LAST_INSERT_ID() 取本次生成的自增值

> 自增值只保证单调递增不保证连续：事务回滚、批量插入冲突都会留下空洞。业务上不要依赖自增值连续。

**速记**：**自增留空让它长，回滚留洞莫依赖**。



#### INSERT ... SELECT 批量搬数

**INSERT ... SELECT 把查询结果直接插入另一表**：不需要中间落盘。

- 语法：INSERT INTO 目标表 (列...) SELECT 列... FROM 源表 WHERE 条件
- 两边列数与类型需对应，列名不必相同
- 适合数据迁移、汇总表生成、报表快照
- 源表与目标表是同一张表时，MySQL 会先物化结果再插入

> 大表之间搬数会是一条大事务：注意分批（配合 LIMIT 与主键游标），否则 undo 膨胀、主从延迟同时爆发。

**速记**：**SELECT 直插不过手，大表分批防长事务**。



#### 主键冲突的三种处理

**插入撞主键有三种出路**：报错、跳过、改写，按业务语义选择。

- 默认行为：报 Duplicate entry 错误，语句终止
- INSERT IGNORE：冲突时降为警告并跳过该行
- ON DUPLICATE KEY UPDATE：冲突时把插入改为对旧行的更新
- REPLACE INTO：冲突时先删旧行再插新行

> 三种非默认行为语义差别极大：IGNORE 可能静默丢数据，REPLACE 会删除再插入（触发删除联动、自增 id 变化）。幂等写入首选 ON DUPLICATE KEY UPDATE，明确表达“存在则更新”。

**速记**：**撞键三选一，幂等首选 ON DUPLICATE KEY UPDATE**。



#### REPLACE INTO 的语义陷阱

**REPLACE 是删除加插入而非更新**：名字有误导性，代价要心里有数。

- 冲突时旧行被真正 DELETE，新行以新的自增 id 插入
- 未指定的列不会保留旧值，而是填默认值或 NULL
- 删除动作会触发删除触发器与外键级联
- 受影响行数统计为 2（删一插一）时说明发生了替换

> 需要“存在则更新且保留未提及列”时应改用 INSERT ... ON DUPLICATE KEY UPDATE，它做的是原地 UPDATE。

**速记**：REPLACE **先删后插换身份，保留旧值它做不到**。



### UPDATE：修改数据

#### UPDATE 的基本形式与 WHERE

**UPDATE 按 WHERE 定位目标行再改列**：不带 WHERE 是全表覆盖。

- 语法：UPDATE 表名 SET 列1 = 值1, 列2 = 值2 WHERE 条件
- SET 支持表达式与函数，如 UPDATE accounts SET balance = balance - 100
- 多列在一条 UPDATE 中一次改完，比逐列执行高效
- 改动结果同样写入 undo 与 redo，可随事务回滚

> 执行 UPDATE 前先用相同 WHERE 跑一遍 SELECT 确认命中行数，是防止误改的标准动作；高危变更放事务里验证后再 COMMIT。

**速记**：**SET 列赋值，WHERE 圈范围，改前先查后执行**。



#### 多表 UPDATE

**多表 UPDATE 用连接关系跨表改数**：一张表的数据决定另一张表的更新。

- 语法：UPDATE 表1 JOIN 表2 ON 条件 SET 表1.列 = 表2.列
- 也支持逗号连接的旧式写法，但可读性差，推荐显式 JOIN
- 常用于以字典表回填编码、以汇总表同步状态
- 驱动顺序影响性能，连接列上应有索引

> 多表 UPDATE 无法像单表那样轻松估算影响范围，务必在事务内先以相同连接跑 SELECT 核对要改的行。

**速记**：**JOIN 定关系，SET 改一端，事务里先核对**。



#### 安全更新模式

**sql_safe_updates 是防误操作的保险丝**：拦截无定位条件的写语句。

- 开启后，不带 WHERE 的 UPDATE 与 DELETE 直接被拒绝
- 带 WHERE 但不走索引（全表扫描）的写语句同样被拒
- 会话级开启：SET SESSION sql_safe_updates = 1
- 确需全表更新时，显式加 LIMIT 或走索引条件绕开

> 生产环境建议默认开启；个别批量任务确需全表写时，由脚本临时会话关闭并用完即恢复，不长期裸奔。

**速记**：**无 WHERE 不放行，保险丝常开**。



### DELETE：删除数据

#### DELETE 的基本形式

**DELETE 按 WHERE 逐行删除并记日志**：可回滚、触发触发器。

- 语法：DELETE FROM 表名 WHERE 条件
- 不带 WHERE 清空全表且逐行记 binlog，大表上既慢又撑日志
- 删除行数用 ROW_COUNT() 或返回的 affected rows 确认
- 业务上多用软删除（is_deleted 标记）而非物理删除

> DELETE 走索引才能精确锁定删除范围；条件列无索引时全表扫描加锁，极易引发锁扩散与死锁。

**速记**：**DELETE 逐行记日志，范围靠 WHERE 走索引**。



#### TRUNCATE 与 DELETE 的区别

**TRUNCATE 是重建表而非逐行删**：快，但代价是失去行级安全。

- TRUNCATE 属 DDL：隐式提交、不能回滚、不触发行级触发器
- 自增值归零重新计数；DELETE 不重置自增
- TRUNCATE 不逐行记 binlog（语句级记录），速度远快于全表 DELETE
- 权限要求不同：TRUNCATE 需要 DROP 权限

> TRUNCATE 之后数据只能靠备份恢复，操作前必须二次确认。清空大表用 TRUNCATE，清空后要立刻回滚的那就绝不能用。

**速记**：**TRUNCATE 重建快但狠，自增归零不可回滚**。



#### 分批删除大表

**大表删除必须分批**：控制事务大小、锁持有时间与主从延迟。

- 按主键范围循环删除，每批数千行后 COMMIT
- 配合 SLEEP 间隔让从库与缓冲池喘息
- 每批之间检查主从延迟指标再继续
- 应用层用任务队列调度，失败可从断点续删

> 一次性 DELETE 千万级行是长事务灾难：undo 膨胀、MDL 阻塞 DDL、主从延迟数小时。分批是把大事化小的唯一正解。

**速记**：**大删分批加睡眠，主从延迟是节拍器**。



### 外键级联行为

#### ON DELETE 与 ON UPDATE 级联

**外键可定义父行变化时子行如何联动**：四种动作覆盖不同业务语义。

- CASCADE：父行删除或更新，子行跟着删或改
- SET NULL：父行变化，子行外键列置 NULL（该列须允许 NULL）
- RESTRICT 与 NO ACTION：有子行时拒绝父行操作
- 不定义则默认 RESTRICT 语义

> CASCADE 用起来省心但危险：删除一行引发整链级联删除，影响范围难以预估。核心业务表多在应用层管理关联，数据库只设 RESTRICT 防孤儿数据。

**速记**：**级联 CASCADE 连坐，RESTRICT 拦截，SET NULL 断链留行**。



#### 外键的性能与选型

**外键是约束也是负担**：互联网高并发场景常在应用层替代。

- 优点：数据库层面杜绝孤儿数据，语义可靠
- 代价：每次写入多一次父表校验；级联在深处放大锁竞争
- 需要外键时确保子表外键列有索引，否则父表更新会锁全子表
- 不用外键的团队必须用应用层事务保证一致性

> 外键不是原罪，没能力在应用层正确维护一致性就别硬拆；拆了外键又不管一致性的系统，脏数据只是时间问题。

**速记**：**外键保一致但要交税，拆与不拆都要有人管一致性**。
