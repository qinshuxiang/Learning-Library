## 数据库与表的创建管理

### 标识符命名规则

#### 长度限制

**标识符**：是数据库、表、列、索引等对象的名称，长度上限由具体对象类型决定。

- 数据库名、表名、列名、索引名、别名等最长 **64 个字符**（按字符数计，非字节数）。
- 约束名最长 **64 个字符**。
- 触发器名最长 **64 个字符**。
- 存储过程与函数名最长 **64 个字符**。
- 表空间名最长 **64 个字符**。
- 单条 SQL 语句的长度上限由 max_allowed_packet 控制，默认 64MB，可调整。

> 字符与字节是两个概念：在 utf8mb4 字符集下，一个汉字占 4 字节，但标识符的 64 限制按**字符数**计，不是字节数。超长会直接报错 Identifier name is too long。

> 速记：**64 字符**是大多数标识符的统一上限，唯独单条语句长度由 max_allowed_packet 决定，二者不可混淆。



#### 允许的字符

**标识符**：可包含的字符范围，以及需要引用才能使用的特殊字符。

- 允许字符：字母、数字、下划线、美元符号（$）、以及取决于字符集配置的 Unicode 字符。
- 名称可含空格及其他特殊字符，但必须用**标识符引用符**包裹，实践中不推荐。
- 名称不得以纯数字开头（强制含数字开头时必须用引用符包裹）。
- 完全由数字组成的名称不允许作为标识符。

```sql
CREATE TABLE `order` (
  id INT UNSIGNED NOT NULL,
  PRIMARY KEY (id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

> 标识符引用符用于引用包含特殊字符或保留字的名称，例如 order 这种保留字做表名时必须用引用符包裹。正文中为避免行内引用符，这类写法统一放进代码块展示。引用符虽灵活，但会让语句与 ORM 映射变复杂，命名时尽量避开特殊字符更省心。

> 口诀：**字母数字下划线美元，特殊字符要引用，数字开头不可用**。



#### 大小写敏感性（lower_case_table_names 参数的影响）

**lower_case_table_names**：是控制数据库名与表名在磁盘存储及比较时是否区分大小写的系统参数。

- 取值 0（类 Unix 默认）：表名与数据库名按**创建时的大小写原样存储并区分比较**。
- 取值 1（Windows 默认）：名称统一转为**小写**存储，比较不区分大小写。
- 取值 2（macOS 默认）：按原样存储，但比较时统一转小写。

```sql
SHOW VARIABLES LIKE 'lower_case_table_names';
```

> 大小写敏感性与操作系统文件系统相关：Linux 文件系统区分大小写，故默认 0；Windows 不区分，故默认 1。该参数**只能在服务器初始化前设置**，运行中修改并要求已有数据一致极易导致表找不到。

> 速记：**建库之前定 lower_case_table_names**，三取值对应 原样区分、全转小写、原样存储比小写；跨平台迁移库务必统一，避免 Linux 上找不到表。



#### 避免使用保留字

**保留字**：是 MySQL 语法中已具有关键字含义的词，用作标识符会破坏语句解析。

- 关键字分为**保留字**与**非保留字**，保留字冲突更严格。
- 强制用作标识符时，必须用**标识符引用符**包裹。
- 常见高危保留字：order、group、select、user、rank、desc、key、primary。

```sql
CREATE TABLE `user` (
  `rank` INT UNSIGNED NOT NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

> 不能完全依赖记忆判断某词是否保留字；官方文档维护完整保留字清单，且随版本增加（如 8.0 新增 rank、window 等）。命名时加业务前缀（如 tbl_order、user_rank）可彻底规避冲突。

> 口诀：**保留字不碰，要碰就引用，最好加前缀**。



### 数据库的管理

#### CREATE DATABASE 的完整语法

**CREATE DATABASE**：是新建数据库对象的语句，可附带不存在判断、字符集与排序规则。

```sql
CREATE DATABASE IF NOT EXISTS school
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_0900_ai_ci;
```

- IF NOT EXISTS：数据库已存在时**不报错**，仅产生警告，适合幂等建库脚本。
- CHARACTER SET：指定默认字符集，未指定时沿用服务器默认（8.0 起为 utf8mb4）。
- COLLATE：指定默认排序规则，需与所选字符集兼容。
- 二者皆省略时，新建库继承服务器 character_set_server 与 collation_server。

> 建库语句本身只创建目录与元信息，不占大量空间；真正的存储开销来自其下各表的数据与索引文件。字符集一旦选定，后续建表默认继承，故建库时定好 utf8mb4 是良好实践。

> 速记：**IF NOT EXISTS 防重复，CHARACTER SET 定编码，COLLATE 定排序**；建库即定字符集，省去逐表指定。



#### 查看数据库

**SHOW DATABASES**：是列出服务器上所有数据库的命令；**SHOW CREATE DATABASE** 展示建库语句。

```sql
SHOW DATABASES;

SHOW DATABASES LIKE 'school%';

SHOW CREATE DATABASE school;
```

- SHOW DATABASES 可配合 LIKE 或 WHERE 做模式筛选。
- SHOW CREATE DATABASE 回显建库时的完整定义，含字符集与排序规则。
- information_schema.SCHEMATA 也可查询，字段更结构化、便于程序读取。

> 普通用户执行 SHOW DATABASES 只能看到自身有权限的数据库，受权限体系控制，并非总是返回全部库。排查"看不到某库"时，先确认账号是否有该库的任意权限。



#### 选择数据库

**USE**：是把某个数据库设为当前默认库的语句，后续省略库名前缀即作用于该库。

```sql
USE school;

SELECT DATABASE();
```

- USE 后未限定库名的表操作都落到当前库。
- DATABASE() 函数返回当前所在库名，无选中时返回 NULL。
- 完全可以不 USE，而永久以 库名.表名 的限定写法操作。

> 当前库的概念只是"默认命名空间"，不改变权限；跨库查询始终可用 库名.表名 显式限定，生产脚本更推荐显式限定以避免误写到错库。



#### 删除数据库

**DROP DATABASE**：是删除整个数据库及其全部表的语句，操作不可逆。

```sql
DROP DATABASE school;

DROP DATABASE IF EXISTS school;
```

- DROP DATABASE 会删除库下所有表、视图、触发器，并移除磁盘目录。
- IF EXISTS 在库不存在时不报错，仅警告。
- 该操作**不能回滚**（DDL 隐含提交），删除后数据只能靠备份恢复。

> [!CAUTION]
> **注意内容**：DROP DATABASE 是破坏性最高的语句之一，执行前务必确认当前库、确认有可用备份、确认不在生产高峰。它不受事务回滚保护，误删后只能依赖备份或 binlog 恢复，代价极高。



#### 修改数据库

**ALTER DATABASE**：是修改数据库级字符集与排序规则的语句，不能改库名（需重建）。

```sql
ALTER DATABASE school
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_0900_ai_ci;
```

- ALTER DATABASE 主要改字符集、排序规则、读锁等属性。
- MySQL 不支持直接重命名数据库，改名需**新建库并迁移数据**。
- 仅修改"默认"，已存在表的字符集不受影响，需另行 ALTER TABLE 转换。

> 修改库默认字符集不会自动转换已有表的字符集，老表仍用旧字符集，易引发隐式转换与乱码。真正统一需逐个 ALTER TABLE 转换表与列，必要时用 ALTER TABLE ... CONVERT TO CHARACTER SET 一并转换列数据。



### 表的创建

#### CREATE TABLE 的完整语法

**CREATE TABLE**：是新建表的核心语句，可指定临时、存在判断、引擎、字符集、注释等选项。

```sql
CREATE TABLE IF NOT EXISTS student (
  id INT UNSIGNED NOT NULL AUTO_INCREMENT,
  name VARCHAR(50) NOT NULL COMMENT '姓名',
  age TINYINT UNSIGNED,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id)
) ENGINE=InnoDB
  DEFAULT CHARSET=utf8mb4
  COLLATE=utf8mb4_0900_ai_ci
  COMMENT='学生表';
```

- TEMPORARY：建为**会话级临时表**，仅当前连接可见，断开自动消失。
- IF NOT EXISTS：表已存在时不报错，适合幂等脚本。
- ENGINE：指定存储引擎，推荐 **InnoDB**（支持事务与外键）。
- DEFAULT CHARSET / COLLATE：表级字符集与排序规则，列可再覆盖。
- COMMENT：表与列均可加注释，便于维护。

> TEMPORARY 临时表与普通表同名时，当前会话的引用优先指向临时表，且临时表互不跨连接可见。它常用于复杂查询的中间结果暂存，避免污染正式数据；注意临时表无法跨连接共享，分布式场景不适用。

> 速记：**TEMPORARY 会话内，ENGINE 选 InnoDB，CHARSET 定 utf8mb4，COMMENT 写说明，IF NOT EXISTS 防重复**。



#### 完整可运行建表示例

**可运行建表示例**：是贴近真实管理系统的表结构，可直接在 MySQL 8.0 执行。

```sql
CREATE DATABASE IF NOT EXISTS school_mgmt
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_0900_ai_ci;

USE school_mgmt;

CREATE TABLE IF NOT EXISTS department (
  dept_id INT UNSIGNED NOT NULL AUTO_INCREMENT,
  dept_name VARCHAR(50) NOT NULL,
  PRIMARY KEY (dept_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='院系表';

CREATE TABLE IF NOT EXISTS student (
  stu_id INT UNSIGNED NOT NULL AUTO_INCREMENT,
  stu_name VARCHAR(50) NOT NULL,
  gender CHAR(1) NOT NULL DEFAULT 'M',
  dept_id INT UNSIGNED NOT NULL,
  enroll_date DATE NOT NULL,
  PRIMARY KEY (stu_id),
  KEY idx_dept (dept_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='学生表';
```

- 字段类型遵循"够用即可"原则，如主键用 INT UNSIGNED 而非无谓的 BIGINT。
- KEY idx_dept 为常用查询列建索引，提升按院系检索速度。
- 整段脚本可重复执行（依赖 IF NOT EXISTS），适合库初始化。

> 示例刻意保留自增、NOT NULL、DEFAULT 等要素，是为后续约束章节铺垫；实际建表还应视业务补充外键或唯一约束。KEY 子句等价于建表后执行 CREATE INDEX，写在表定义内更紧凑。



### 查看表结构

#### SHOW CREATE TABLE 与 DESC

**SHOW CREATE TABLE**：回显完整建表语句；**DESC**（或 DESCRIBE）显示列的概要信息。

```sql
SHOW CREATE TABLE student;

DESC student;

DESCRIBE student;
```

- SHOW CREATE TABLE 展示列定义、引擎、字符集、约束、注释全貌，便于复制重建。
- DESC 输出列名、类型、是否可空、键、默认值、额外信息六列概要。
- DESCRIBE 与 DESC 完全等价，是快捷别名。

> DESC 适合快速看列类型与是否可空；要看完整的索引、字符集、引擎细节，必须用 SHOW CREATE TABLE。二者互补，日常常先用 DESC 扫一眼，再用 SHOW CREATE TABLE 拿精确定义。



#### information_schema 查询

**information_schema**：是只读系统库，以表的形式暴露所有对象的元数据，可程序化查询。

```sql
SELECT COLUMN_NAME, COLUMN_TYPE, IS_NULLABLE, COLUMN_DEFAULT, COLUMN_COMMENT
FROM information_schema.COLUMNS
WHERE TABLE_SCHEMA = 'school_mgmt'
  AND TABLE_NAME = 'student';

SELECT TABLE_NAME, ENGINE, TABLE_COMMENT
FROM information_schema.TABLES
WHERE TABLE_SCHEMA = 'school_mgmt';
```

- COLUMNS 表存列级元数据：类型、可空、默认值、注释等。
- TABLES 表存表级元数据：引擎、行格式、注释、数据长度等。
- 适合在脚本中批量探查结构，比 DESC 更灵活。

> information_schema 是标准 SQL 信息架构，跨数据库通用（字段名可能略有差异）；它的查询不锁表，但大批量反射可能消耗资源，不宜放在高频路径。MySQL 8.0 还提供 performance_schema 与 data dictionary 视图，元数据的底层来源已统一到数据字典。



### 查看当前库有哪些表

#### SHOW TABLES 的用法与筛选

**SHOW TABLES**：是列出当前数据库所有表（及视图）的命令。

```sql
USE school_mgmt;
SHOW TABLES;

SHOW TABLES LIKE 'stu%';

SHOW FULL TABLES;
```

- SHOW TABLES 仅列出当前库对象名。
- LIKE 子句按模式筛选表名。
- SHOW FULL TABLES 额外显示每行是 BASE TABLE 还是 VIEW，区分表与视图。

> 未执行 USE 选定当前库时，SHOW TABLES 会作用于上次选定的库或报错；脚本中推荐用 库名.表名 或显式 USE 后再查，避免拿到错误库的表清单。SHOW FULL TABLES 比单纯的 SHOW TABLES 多一列 Table_type，排查视图时用得上。



### 基于查询结果创建表

#### CREATE TABLE ... AS SELECT

**CTAS**：是"查询结果建表"的缩写，用一条 SELECT 的结果集直接生成新表并写入数据。

```sql
CREATE TABLE student_archive
AS
SELECT * FROM student WHERE enroll_date < '2020-01-01';
```

- 新表结构由 SELECT 的输出列决定，含列名与类型推断。
- 数据**会**被写入，是原表满足条件的快照副本。
- 原表的约束、索引、默认值、自增属性**不会**被复制。

> [!WARNING]
> **警告内容**：CTAS 生成的表是"结构加数据的副本"，但丢失主键、外键、索引、默认值、注释等所有约束与属性，仅保留列名与推断类型。它适合做快照、归档、宽表落地，不适合作为正式表结构的来源；需要带约束的副本应改用 CREATE TABLE ... LIKE 配合 INSERT ... SELECT。

> 速记：**CTAS 搬数据也搬列，约束索引全丢光；要原样结构用 LIKE**。



### 基于已有表创建表

#### CREATE TABLE ... LIKE

**CREATE TABLE ... LIKE**：是按源表的完整结构克隆一张空表，复制定义但不复制数据。

```sql
CREATE TABLE student_bak LIKE student;

INSERT INTO student_bak SELECT * FROM student;
```

- 新表获得与源表**一致的结构**：列、索引、主键、自增、字符集、注释全部复制。
- 数据**不**复制，得到的是空表。
- 常与 INSERT ... SELECT 配合完成"结构一致的数据备份"。

> LIKE 与 CTAS 的核心差异在于是否复制约束与是否复制数据：LIKE 复制全部结构、不复制数据；CTAS 复制列与数据、不复制约束。二者不可混用，选错会导致备份表缺少索引或主键值。LIKE 还支持跨库克隆，写成 CREATE TABLE 新库.新表 LIKE 旧库.旧表 即可。

> 口诀：**LIKE 克隆结构空，CTAS 复制数据松；要结构用 LIKE，要数据用 AS SELECT**。



### 修改表名

#### RENAME TABLE 与 ALTER TABLE RENAME

**重命名**：是把已存在的表改名为新名的操作，有两种等价写法。

```sql
RENAME TABLE student TO student_info;

ALTER TABLE student_info RENAME TO student;

ALTER TABLE student RENAME student_new;
```

- RENAME TABLE 可在一条语句里重命名多个表，原子完成。
- ALTER TABLE ... RENAME TO 是单表写法，语义等价。
- 重命名是元数据操作，8.0 下对 InnoDB 表通常很快。

> 重命名不会自动更新视图、存储过程中对该表的写死引用，需手工同步。此外 RENAME 期间表会被加锁，大并发时短暂影响访问；RENAME TABLE 一条语句同时改多张表时，要么全成功要么全失败，具备原子性。



### 删除表

#### DROP TABLE 与批量删除

**DROP TABLE**：是删除整张表的语句，连同结构、数据、索引一并清除。

```sql
DROP TABLE student_bak;

DROP TABLE IF EXISTS student_bak;

DROP TABLE dept_backup, student_backup;
```

- DROP TABLE 删除表结构与全部数据，且**不可回滚**（DDL 隐含提交）。
- IF EXISTS 在表不存在时不报错，仅警告，适合清理脚本。
- 可在一条语句中逗号分隔批量删除多张表。

> [!CAUTION]
> **注意内容**：DROP TABLE 与 DROP DATABASE 同属不可逆 DDL，执行即丢失结构与数据，无法用事务回滚。删除前先确认对象存在、确认有备份、确认无其他对象依赖（外键、视图、存储过程），误操作只能依赖备份或 binlog 恢复。

> 速记：**DROP TABLE 删结构加数据，IF EXISTS 防报错，批量用逗号分隔，慎之又慎**。



### 清空表

#### DELETE 与 TRUNCATE 的对比

**清空表**：是把表中所有行删除的操作，有两种常用手段，语义与代价差异显著。

```sql
DELETE FROM student;

TRUNCATE TABLE student;
```

- **DELETE FROM** 是 DML，逐行删除，**可带 WHERE**、**可回滚**、触发 **DELETE 触发器**、自增计数**不重置**。
- **TRUNCATE TABLE** 是 DDL，重建表结构，**不可回滚**、**不触发触发器**、速度更快、自增计数**重置**为首值。

> DELETE 与 TRUNCATE 的核心分野：**DELETE 是逐行、可回滚、保自增、能带条件**；**TRUNCATE 是整表重建、不可回滚、重置自增、最快**。TRUNCATE 在有外键引用本表时会被拒绝，而 DELETE 仍可逐行删（受外键约束限制）。对大表而言，TRUNCATE 远快于无条件的 DELETE，因为它不记录逐行删除日志。

> 口诀：**清数据，DELETE 温柔可回滚，TRUNCATE 暴力快重置；带条件只能 DELETE，有关联外键慎用 TRUNCATE**。



### 数据库的整体层面推荐

#### 整体层面推荐

**整体推荐**：是从库、表、字符集、引擎等层面给出的一致实践建议。

- **统一字符集**：全链路使用 utf8mb4 与 utf8mb4_0900_ai_ci，避免乱码与隐式转换。
- **统一引擎**：生产表一律 InnoDB，获得事务、崩溃恢复、外键支持。
- **命名规范**：库、表、列用小写蛇形（snake_case），加业务前缀规避保留字。
- **幂等脚本**：建库建表加 IF NOT EXISTS，便于重复执行与自动化。
- **注释充分**：表与关键列写 COMMENT，沉淀业务语义。
- **审慎 DDL**：DROP、TRUNCATE 等不可逆操作须双人确认与备份。

> 这些建议服务于"可重复、可维护、可恢复"的工程目标：幂等脚本让环境搭建可自动化，统一字符集与引擎消除最常见的两类线上故障，审慎 DDL 则把不可逆风险压到最低。字符集的统一尤其关键，混用字符集会在连接、比较、排序时触发隐式转换，拖慢查询并产生乱码。

> 速记：**字符集 utf8mb4，引擎 InnoDB，命名 snake_case，脚本幂等化，DDL 要谨慎**。
