## 基础查询与 WHERE 条件

### SELECT：查什么

#### SELECT 选列与 FROM

**SELECT 定义输出列，FROM 指明数据来源**：两者合起来是最小完整的查询。

- 指定列：SELECT name, price FROM products，只取需要的列
- 星号：SELECT * FROM products，取全部列
- 输出列顺序与书写顺序一致，可重复、可计算（SELECT 1 + 1）
- 无 FROM 的 SELECT 合法，如 SELECT NOW() 直接求值

> 生产代码禁用星号：多取的列浪费网络与内存，更致命的是破坏覆盖索引的可能性，且表结构变更后星号查询的列序会静默变化。

**速记**：SELECT 定输出，**列名写全莫贪星**。

```sql
-- 指定列与计算列
SELECT name, price, price * 0.9 AS discounted FROM products;
```



#### 列别名与输出控制

**列别名给输出列改名**：让结果集自解释，也让后续子句可引用。

- 语法：SELECT 列 AS 别名 或省略 AS 直接空格
- 别名含空格或保留字时需引号包裹：AS "总 金额"
- ORDER BY 与 GROUP BY 可引用别名，WHERE 不可
- 别名不必与列名不同，但重名没有意义

> WHERE 不能用别名的根因是执行顺序：WHERE 在 SELECT 求值之前运行，别名尚不存在。需要在 WHERE 里用的表达式，就把表达式原样写出或放进派生表。

**速记**：**AS 改名，WHERE 用不上，排序分组没问题**。



#### DISTINCT 去重

**DISTINCT 对输出行整行去重**：重复的行只保留一行。

- 单列：SELECT DISTINCT city FROM users，列出不相重的城市
- 多列：DISTINCT 作用于列的组合，两列都相同才算重复
- 与聚合合用：COUNT(DISTINCT city) 统计不重复城市数
- DISTINCT 写在所有输出列之前，不能只对其中一列生效

> 想对某一列去重却保留其他列的最大值，DISTINCT 做不到，那是分组聚合（15 篇）或窗口函数的活。硬把 DISTINCT 套在多列上过滤重复，常是语义误解。

**速记**：**DISTINCT 整行判重，多列合起来算**。



### WHERE：挑哪些行

#### 比较与逻辑条件

**WHERE 逐行求值布尔条件**：为真的行进入结果。

- 比较运算：=、<> 或 !=、大于小于、BETWEEN 含两端
- 逻辑连接：AND、OR、NOT，AND 优先级高于 OR
- 混用 AND 与 OR 时显式加括号，不依赖优先级记忆
- 括号是零成本的表达，能彻底消除歧义

> WHERE price > 100 OR category = 3 AND stock > 0 因 AND 先算，语义与直觉相反；加上括号写明白，比让人猜优先级划算。

**速记**：**AND 先于 OR，混用必加括号**。

```sql
-- 括号明确逻辑分组
SELECT * FROM products
WHERE (price > 100 AND stock > 0)
   OR category = 3;
```



#### IN 与 BETWEEN

**IN 与 BETWEEN 是区间与枚举的简写**：语义清晰且利于优化。

- IN (1, 2, 3) 等价于一串 OR 等值比较
- BETWEEN 5 AND 10 双闭区间，含 5 与 10 本身
- NOT IN 与 NOT BETWEEN 取反，注意 NULL 陷阱（12 篇展开）
- IN 的列表也可来自子查询，但性能要单独评估

> IN 的等值列表对索引友好，多个等值区间可合并扫描；BETWEEN 走 range 扫描也是索引友好的形态。两者都是执行计划里的优等生。

**速记**：**IN 枚举 BETWEEN 区间，都含边界都亲索引**。



#### IS NULL 判空

**判断 NULL 只能用 IS NULL**：等号与 NULL 比较永远得 NULL 而非真假。

- IS NULL 找空值行，IS NOT NULL 找非空行
- WHERE col = NULL 不报错但永远查不到东西，是经典错误
- 三值逻辑下 NULL 参与任何比较结果都是 UNKNOWN
- 与 NOT IN 组合时子查询含 NULL 会导致整体空结果

> 想把 NULL 当普通值参与比较，用安全等于操作符（12 篇）；但更要紧的是设计期决策：列允不允许 NULL、NULL 表达什么业务含义，想在查询层兜底已经晚了一步。

**速记**：**判空用 IS，等号碰 NULL 全落空**。



#### LIKE 模糊匹配

**LIKE 用通配符做模式匹配**：百分号匹配任意串，下划线匹配单字符。

- 前缀匹配 LIKE 'abc%' 可走索引
- 中缀或后缀匹配 LIKE '%abc' 无法走 B+ 树索引
- 下划线严格匹配一个字符，'a_c' 匹配 abc 但不匹配 abbc
- 匹配本身是转义敏感的：要匹配字面百分号需用 ESCAPE 声明转义符

> 后缀搜索是 LIKE 的硬伤：数据量大时改用全文索引、倒排索引或搜索引擎，而不是放任全表扫描。前缀匹配也有索引列字符集函数隐式转换的失效陷阱（26 篇）。

**速记**：**百分号任意下划线一，前缀走索引，中缀全表爬**。

```sql
-- 转义字面百分号
SELECT * FROM logs
WHERE message LIKE '100\%%' ESCAPE '\\';
```



#### REGEXP 正则匹配

**REGEXP 用正则表达式匹配**：能力比 LIKE 强，代价也更高。

- 默认不区分大小写（与排序规则相关），加 BINARY 可强制区分
- 常用记号：点号任意字符、星号重复、方括号字符集、尖号与美元符定首尾
- 匹配语义是“包含”而非“全等”，需要全等时自行加首尾锚点
- 正则无法利用普通索引，只能逐行计算

> REGEXP 适合低频的探索性查询与数据清洗；线上高频路径用它是把 CPU 消耗转嫁到数据库，应把模式匹配挪到应用层或专用的检索设施。

**速记**：REGEXP **能力全开索引全关，探索可用高频莫上**。



### LIMIT 与查询常数

#### LIMIT 初识

**LIMIT 限制返回行数**：保护结果集与网络的基本手段。

- LIMIT 10 返回前 10 行，LIMIT 5, 10 跳过 5 行取 10 行
- 不带 ORDER BY 的 LIMIT 结果不确定，先排序再限制才有稳定语义
- 大偏移量代价高：跳过的行也要真实扫描
- 深分页优化在 16 篇专门展开

> 探索大表时随手加 LIMIT 是好习惯，防止误把千万行拖到客户端；但注意 LIMIT 不减少服务端的扫描量，只截断返回。

**速记**：LIMIT **管返回不管扫描，排序后再限才稳定**。



#### 查询常数与无表查询

**SELECT 可以不依赖任何表**：数据库兼作表达式计算器。

- SELECT 1、SELECT NOW()、SELECT 1 + 1 都合法
- 常用于探测连接可用性：SELECT 1 是最轻的心跳语句
- 联表时补常数列做标记：SELECT 'x', col FROM t
- Oracle 需要 FROM dual，MySQL 里 dual 可写可不写

> 连接池与监控大量使用 SELECT 1 做活性探测；若配置了更复杂的探测语句，注意它自身的开销与权限要求。

**速记**：**无表可查，SELECT 1 当心跳**。



### 查询的设计意识

#### 先想清楚再写语句

**查询语句的第一性问题不是语法而是语义**：要什么行、什么列、什么顺序。

- 动笔前列出：筛选条件、输出列、去重需求、排序分页
- 用主键或明确索引条件缩小范围，避免裸查大表
- 交互探索加 LIMIT，代码里杜绝裸 SELECT 星号
- 语句写完先 EXPLAIN 看一眼（27 篇），再交付

> 多数慢查询不是优化出来的而是写出来的：无 WHERE 的全表拉取、星号带回全部大字段、忘写 LIMIT 的报表查询。写时多想一秒，胜过事后优化一小时。

**速记**：**语义先行，范围收窄，交付前 EXPLAIN**。
