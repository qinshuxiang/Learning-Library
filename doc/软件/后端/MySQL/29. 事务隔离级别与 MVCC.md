## 事务隔离级别与 MVCC

### 隔离级别

#### 四级阶梯

**隔离级别是“并发正确性换并发性能”的四档旋钮**：从宽松到严格。

- READ UNCOMMITTED：什么都可能发生，脏读都放行
- READ COMMITTED（RC）：只读已提交，杜绝脏读，仍有不可重复读与幻读
- REPEATABLE READ（RR）：同事务内读值稳定，默认级别
- SERIALIZABLE：完全串行化语义，并发代价最高
- 查看与设置：SELECT @@transaction_isolation；SET SESSION TRANSACTION ISOLATION LEVEL ...

> 级别选择没有标准答案：互联网业务多用默认 RR 或降级 RC 换并发，金融核对类任务会临时升到 SERIALIZABLE。默认是 RR，而 SQL 标准默认是 SERIALIZABLE——InnoDB 有自己的主意。

**速记**：**RC 挡脏读 RR 保重复，串行化全防代价高**。



#### 三病灶在各级别的表现

**级别矩阵就是“容忍哪些病灶”的声明**：一张表背下全部组合。

- 脏读：只有 READ UNCOMMITTED 存在
- 不可重复读：RC 存在，RR 起消失
- 幻读：RC 与 RR 都存在（RR 靠 MVCC 与锁大幅缓解，见后文）
- SERIALIZABLE 全部免疫，因为读也加锁

> 级别与病灶的对应关系不是玄学而是实现的结果：RR 靠快照读稳定了值，靠间隙锁封堵了当前读的幻影。理解实现，矩阵自然记住。

**速记**：**级别即容忍度，矩阵背后是快照与锁的实现**。



### MVCC 实现

#### 版本链

**MVCC 让每行保留多个历史版本**：读旧写新互不打扰。

- 每行隐藏列 DB_TRX_ID 记录最后修改它的事务
- 每次更新都把旧版本写入 undo log
- 回滚指针 DB_ROLL_PTR 把各版本串成链，头是最新版
- 读操作沿链回溯，找到对自己可见的版本

> 版本链是“读不阻塞写、写不阻塞读”的物质基础：写方在链头追加新版本，读方按自己的可见性沿链找旧版本。undo log 因此有双重身份——回滚用，MVCC 也用。

**速记**：**更新留旧版，指针串成链，读方按需回溯**。



#### ReadView 与可见性判断

**ReadView 是一次读操作拍下的“活跃事务快照”**：可见性由它裁定。

- 四个字段：m_ids（生成时刻活跃事务列表）、min_trx_id、max_trx_id、creator_trx_id
- 判断规则：版本的 trx_id 是自己则可见；小于 min 可见；大于等于 max 不可见；在两者之间则看是否在 m_ids 里
- 不可见就沿回滚指针往链尾找，直到找到可见版本
- 整个判断是纯内存运算，不产生锁

> ReadView 是 MVCC 的裁判规则手册：同样是 RR，两个事务各自 ReadView 不同，看到的“当下”就不同。把四字段与判断顺序推演两遍，所有 MVCC 面试题都能自己推导。

**速记**：**四字段定可见，不可见沿链走，全程不加锁**。



#### RC 与 RR 的分水岭

**两者的 MVCC 实现只差一处：ReadView 的生成时机**。

- RC：每次快照读都生成新的 ReadView，总能看到最新已提交
- RR：只在事务第一次快照读时生成一次，之后沿用
- 于是 RC 下两次读可能不同（不可重复读），RR 下恒定
- 级别切换影响的就是这一个时点，别想复杂

> “一图胜千言”的场景：同一事务内两次 SELECT，RC 拍两张快照，RR 只拍一张。把这句话讲清楚，隔离级别的差异就讲清楚了。

**速记**：**RC 每读每拍，RR 一事务一拍，分水岭仅此一处**。



### 快照读与当前读

#### 两种读的区分

**快照读走 MVCC，当前读写的是最新版**：语句类型决定读法。

- 快照读：普通 SELECT，不加锁，读可见版本
- 当前读：SELECT ... FOR UPDATE、SELECT ... LOCK IN SHARE MODE、UPDATE、DELETE、INSERT
- 当前读读最新已提交版本，并加相应锁
- 同一事务内两种读混用，是幻读残余的根源

> 当前读的锁语义在 30 篇展开；这里只需记住分界线：带锁子句与 DML 都是当前读，裸 SELECT 是快照读。

**速记**：**裸 SELECT 看快照，带锁与 DML 读当下**。



#### RR 下幻读的解决程度

**RR 把幻读压到很低，但没消灭**：两种读各堵一半，缝隙在混用处。

- 快照读侧：ReadView 固定，新插入的行对旧事务不可见，幻读不现
- 当前读侧：间隙锁与临键锁锁住范围，别人插不进来
- 缝隙：事务内先快照读、后当前读，两次读的成员可能不一致
- 彻底一致的做法：关键范围从一而终用 FOR UPDATE

> 面试高频点与工程真实点在这里重合：知道“RR 也有幻读窗口”的人，才会对“先查再写”的热点路径加 FOR UPDATE。理论缝隙直接对应生产锁策略。

**速记**：**快照堵一半锁堵另一半，混用留缝，关键路径一锁到底**。



### 综合运用

#### 隔离级别的工程决策

**选级别就是选病灶容忍度**：三步定夺。

- 列出业务对三类病灶的真实敏感度
- 大多数业务：默认 RR 已足够，不必折腾
- 高并发短事务、可接受不可重复读的场景：评估 RC 换并发
- 核对与结算类：事务内关键范围用当前读，而不是升级全库级别

> 级别是全局与会话可调的，但调整的影响面要按“所有跑在这个库上的业务”来评估；多数团队终其一生只该用默认级别加精准的当前读。

**速记**：**默认 RR 走天下，敏感路径当前读**。



#### MVCC 推演自查

**MVCC 的理解深度用三个问题自测**：答得出即过关。

- RC 与 RR 的实现差异是哪一行代码级别的区别？——ReadView 生成时机
- 版本链存在哪里？——undo log，由回滚指针串联
- 快照读会不会阻塞写？——不会，可见性判断纯内存
- 长事务为什么危险？——它的 ReadView 挡住 undo 清理，版本链越拖越长

> 四问全过，MVCC 不再是背诵题；任何一问答不上，回到对应小节重新推演，别停在名词层面。

**速记**：**时机、版本链、不阻塞、挡清理，四问答毕 MVCC 通**。
