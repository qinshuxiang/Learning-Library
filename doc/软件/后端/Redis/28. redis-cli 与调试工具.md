## redis-cli 与调试工具

**redis-cli 与调试工具**：是 Redis 官方命令行客户端与配套调试工具的总称——redis-cli 既是交互式的命令终端，又内置了统计、扫描、延迟检测、备份等多种运行模式，再加上 redis-benchmark、redis-check-rdb、redis-check-aof 等伴生程序，共同构成运维与排查 Redis 的第一线工具箱。

- 本章先讲连接参数与执行控制：-h、-p、-a、-n、-r、-i、-x 等选项与认证的安全姿势。
- 再讲交互模式与实时观测：HELP、CONFIG、SELECT、DBSIZE、RESET、CLIENT 命令族，以及 --stat、--bigkeys、--latency 等运行模式与 MONITOR 命令。
- 然后是压测与配置管理：redis-benchmark 的参数与结果解读、redis-server 启动参数与 CONFIG 动态调参。
- 接着讲观测命令：INFO 各分区精读，SLOWLOG 与 MEMORY 命令族。
- 最后讲检查修复工具、连接排查、DEBUG 调试命令与第三方图形客户端。
- 与相邻章节的分工：本章讲工具怎么用，第 29 章讲用这些工具做性能优化的方法论，交叉处均标注互见。

### redis-cli 连接参数与基础用法

#### 基础连接参数与密码认证

**redis-cli**：是 Redis 自带的官方命令行客户端，既可进入交互模式逐条执行命令，也可在命令后直接拼接命令实现单次执行后退出。

- -h 指定主机地址，默认 127.0.0.1；-p 指定端口，默认 6379。
- -a 指定密码，对应配置项 requirepass 的值；密码会以明文形式留在 shell 历史与进程列表中。
- --no-auth-warning 用于抑制使用 -a 时的安全警告，仅为让输出干净，不改变 -a 的明文风险。
- 更安全的做法是通过环境变量 REDISCLI_AUTH 传递密码，避开命令行明文；生产环境更推荐 ACL 账号与本机 socket 认证。
- -s 指定 Unix socket 路径连接本机套接字；-u 以 redis://user:password@host:port/db 的 URL 形式连接。
- -3 启用 RESP3 协议；--tls 启用 TLS 连接，证书参数与安全体系详见第 31 章。
- 命令行末尾直接跟命令即单次执行，如 ping、get 等，脚本化运维主要用这种形态。
- 多条命令可写入文本文件后管道喂入，redis-cli 会逐行执行并汇总输出，比多次建立连接高效。
- --pipe 子命令配合原生协议文件是批量导入的极致形态，普通场景用文件管道即可。

```bash
redis-cli -h 127.0.0.1 -p 6379 -a yourpassword --no-auth-warning ping
printf 'set k1 v1\nset k2 v2\nget k1\n' | redis-cli
export REDISCLI_AUTH=yourpassword
redis-cli -h 127.0.0.1 ping
```

> 辨析：-a 与 --no-auth-warning 只是抑制客户端告警，密码仍会出现在 history 与 ps 输出里；交互模式下执行 auth 命令时 Redis 会做掩码处理，命令行参数形态的 -a 无任何保护，安全加固详见第 31 章。

**速记**：连接四件套 -h、-p、-a、-n，密码明文是 -a 的原罪，环境变量最稳。



#### -n 选库与 -r -i -x 执行控制

**执行控制参数**：-n 用于登录时指定数据库编号，-r 与 -i 组合用于把一条命令按指定间隔重复执行指定次数，-x 则从标准输入读取命令的最后一个参数。

- -n 0 到 -n 15 指定逻辑数据库，默认 0；等于登录后执行 select 命令，最多库数由 databases 配置决定。
- -r count 让随后的命令重复执行 count 次，配合间隔可简化观测脚本，省去 shell 循环。
- -i seconds 指定重复执行的间隔秒数，支持小数如 0.1，必须与 -r 搭配才有意义。
- 组合形态适合做轻量探针：每秒读一次监控指标、每秒写入一次心跳等。
- 重复执行的命令里可嵌入 info、latency 等诊断命令，把输出直接重定向到文件留档。
- -x 让 redis-cli 把标准输入的内容当作命令的最后一个参数，常用于把文件或管道数据直接写入 value，如 redis-cli -x set key 后接输入重定向。

```bash
redis-cli -n 2 set db2:key hello
redis-cli -r 10 -i 1 info stats | grep instantaneous_ops_per_sec
redis-cli -x set net_services < /etc/services
```

```text
OK
instantaneous_ops_per_sec:1024
instantaneous_ops_per_sec:1031
instantaneous_ops_per_sec:998
```

> 辨析：Redis Cluster 模式下只有 db0，-n 传入非 0 编号会直接报错；多库隔离是单实例的能力，集群的隔离靠按业务拆分实例，集群选型详见第 22 章。

**速记**：-n 定库，-r 次数，-i 间隔，-x 从标准输入接值，合体当探针。



#### --csv 输出与 --scan 替代 KEYS

**--scan 与 --csv**：--scan 让 redis-cli 以 SCAN 游标方式遍历键空间并逐行输出键名，--csv 把命令输出转成 CSV 格式，两者常组合用于安全导出。

- --scan 本质是客户端封装的 SCAN 增量迭代，分批拉取不阻塞主线程，与 keys 命令的全量一次性遍历有本质区别。
- --scan 支持 --pattern 参数做匹配过滤，等价于 SCAN 命令的 MATCH 子句。
- --scan 输出的键名不保证一次遍历内有序，也不保证遍历期间的新增键一定被返回，重跑一次结果可能不同。
- --csv 将输出按 CSV 规则转义，方便导入表格工具或与其他管道程序对接。
- 危险的 keys 命令在生产应被 rename 或禁用，遍历键空间一律用 --scan。

```bash
redis-cli --scan --pattern "user:*" | head -n 20
redis-cli --scan --pattern "session:*" --csv > session_keys.csv
redis-cli --scan --pattern "tmp:*" | xargs -L 100 redis-cli unlink
```

```text
"user:1001"
"user:1002"
"user:1003"
```

> [!TIP]
> **建议内容**：批量删除键时用 redis-cli --scan --pattern 匹配后管道给 xargs 调 del 或 unlink，比 keys 加通配符再删安全得多；大 key 的进一步治理手段详见第 29 章。

**速记**：键空间遍历只认 --scan，keys 是生产禁词，--csv 管导出。



### redis-cli 交互模式与实时观测

#### 交互模式便利功能

**交互模式**：不带命令参数启动 redis-cli 即进入交互模式，具备补全、提示、帮助与输出截断等便利能力。

- Tab 键可补全命令名与部分参数，输入前缀后连续按两次 Tab 列出全部候选。
- 输入命令时行内实时提示参数签名与用法说明，照着提示补参数即可，无需背完整签名。
- help 命令查看任一命令的内嵌文档，help hgetall 会给出概要、复杂度、参数与示例。
- help 支持按命令组查看，help @string 列出字符串类全部命令，@hash、@list、@set 同理。
- 交互模式下超大字符串值默认截断显示，超出部分以省略提示替代，避免刷屏。
- clear 清屏，quit 或 exit 退出；connect host port 可在会话内切换服务器，select n 切换库。
- dbsize 返回当前库键总数，直接读计数器、开销为常数级，可放心高频使用；reset 自 Redis 6.2 起提供，把当前连接复位到初始状态——回到 0 号库、退出事务与订阅、关闭 monitor、清除连接名。
- 集群模式下 select 直接报错，只有 db0，多库隔离是单实例能力，集群的隔离靠业务键前缀，详见第 22 章。

```text
127.0.0.1:6379> help hgetall

  HGETALL key
  summary: Get all the fields and values in a hash
  complexity: O(N) where N is the size of the hash

127.0.0.1:6379> help @hash
  1) HDEL key field [field ...]
  2) HEXISTS key field
  3) HGET key field
```

```text
127.0.0.1:6379> get cache:page:index
"<!DOCTYPE html><html><head><title>Index</title>... (truncated) ..."
```

> 辨析：截断显示只影响人眼阅读，不影响返回数据的完整性，需要完整输出时退出交互用 --raw 重跑，或把结果重定向到文件；--no-raw 则相反，会将二进制安全的回复转成转义文本展示。

**速记**：Tab 补全、行内提示、help 加 @ 分组查文档，大值自动截断不刷屏。



#### --stat 与 --latency 实时观测

**--stat 与 --latency**：--stat 以滚动行实时打印实例总体吞吐与内存概览，--latency 持续测量客户端视角的命令延迟分布，两者都是无侵入的观测模式。

- --stat 每秒一行输出 keys、mem、clients、blocked、requests、connections 等列，适合肉眼盯趋势。
- --latency 以一秒为周期发送 ping，记录最差、平均延迟并实时刷新最大值，退出时打印汇总。
- --latency-history 与 --latency 类似，但默认每 15 秒开启一条新的统计线，便于观察延迟随时间的变化而非只看历史最差值。
- --latency-dist 以彩色频谱图展示延迟分布形态，参数为采样时长。
- --intrinsic-latency seconds 用于测量服务器所在机器的固有延迟，即系统调度、缺页等环境本身引入的抖动，必须在服务器本机运行才有意义。
- 客户端测得的延迟包含网络往返，与固有延迟之差才是网络与服务处理的真实开销。

```bash
redis-cli --stat
redis-cli --latency-history -h 10.0.0.5
redis-cli --latency-dist 120
redis-cli --intrinsic-latency 60
```

```text
Keys   Mem    Clients  Blocked  Requests
1200   2.10M  8        0        456789 (+0)
1200   2.10M  8        0        456901 (+112)

max latency: 3 ms / avg latency: 0.42 ms
```

- --stat 的 requests 列带括号增量、connections 列带历史累计，短时间观察即可发现请求突增与连接泄漏。

> 辨析：--intrinsic-latency 不连接 Redis 也不发送命令，它只是在本机空转采样，衡量操作系统环境的固有抖动；若客户端延迟高而固有延迟低，问题多半在网络或 Redis 处理本身，延迟治理详见第 29 章。

**速记**：--stat 看吞吐趋势，--latency 量客户端延迟，--intrinsic-latency 量机器本底抖动。



#### --bigkeys 与 --memkeys

**--bigkeys 与 --memkeys**：二者都是基于 SCAN 抽样的键空间体检工具，--bigkeys 找各类型中元素最多或字符串最长的键，--memkeys 找占内存最大的键。

- 工作原理是以空闲间隔执行 SCAN，对每个 key 按其类型调用相应的长度类命令：字符串取 strlen，列表取 llen，集合取 scard，哈希取 hlen，有序集合取 zcard，流取 xlen。
- 输出按类型分段给出最大值键与平均值，可作为大 key 排查的第一步。
- 默认每扫描 100 次休眠 0.1 秒，可用 -i 参数调节扫描速度，避免影响线上服务。
- --memkeys 需要 Redis 4.0 及以上版本支持，底层依赖 memory usage 命令逐键估算内存；--samples 可调整每种类型展示的样本数。
- 抽样统计存在误差：只统计 SCAN 路径上遇到的键，遍历不完整时结果偏差更大。
- 长度口径与内存口径并不等价，元素多不等于内存大，一个 100 万元素的 zset 与一个 1 MB 的字符串风险不同。
- 工具只报最大与均值，分布形态看不到，长尾大 key 需配合 --scan 加 memory usage 逐键确认。

```bash
redis-cli --bigkeys -i 0.01
redis-cli --memkeys --samples 5
redis-cli --hotkeys
```

```text
-------- summary -------
Sampled 120000 keys in the keyspace!
Total key length in bytes is 1800000 (avg len 15.00)

Biggest string found 'cache:page:index' has 102400 bytes
Biggest   hash found 'user:1001:profile' has 5000 fields

0 strings with 0 bytes (00.00% of keys, avg size 0.00)
120000 hashes with 300000 fields (100.00% of keys, avg size 2.50)
```

> 辨析：--bigkeys 的长度统计与真实内存占用不一致，精确到字节的排查应结合 memory usage 与 memory doctor；定位到的大 key 如何拆分与删除属于治理动作，详见第 29 章。

**速记**：--bigkeys 数长度、--memkeys 算内存、--hotkeys 找热点（须 LFU 策略），都是抽样体检，误差心中记。



#### --rdb 导出远程 RDB

**--rdb 模式**：让 redis-cli 以副本身份连接目标实例，借助复制初次同步机制把远端 RDB 文件拉取到本地，一条命令完成在线备份。

- 用法：redis-cli --rdb 备份文件名，文件名给 - 则写到标准输出，便于接管道直接压缩。
- 用途：低峰期在线备份、把生产数据拉到离线环境解析内存报告（详见第 29 章）；脚本中使用时应检查返回值，非零表示出错。

```bash
redis-cli -h 10.0.0.8 --rdb /backup/dump.rdb
redis-cli -h 10.0.0.8 --rdb - | gzip > dump.rdb.gz
```

> 全量同步会在主节点产生 fork 与传输开销，等价于一次 RDB 生成（详见第 17 章），备份应安排在低峰期执行；若已挂载多个从节点，还需留意复制积压缓冲区与带宽余量。

**速记**：--rdb 把 redis-cli 变成一次性的副本，拉全量 RDB 做备份与离线分析。



### MONITOR 命令

#### MONITOR 实时命令流

**MONITOR**：是调试用命令，执行后客户端进入实时流模式，服务器把随后处理的所有命令原样推送给该客户端打印。

- 输出格式为时间戳、数据库编号、客户端地址、命令名与完整参数，能看到所有客户端在做什么，包括来自其他机器的连接。
- 追加的 MONITOR 输出只进该客户端缓冲，不落盘不留痕，断开即停止，属于最轻量的观测入口。
- 典型用途：排查未知来源的写操作、验证应用实际下发的命令序列、复现协议与序列化问题。
- 交互或独立连接中执行 monitor 即开始，Ctrl C 退出。
- 官方明确说明：MONITOR 会把每条命令的完整文本回显给所有监控客户端，回显成本随命令流线性增长。

> [!WARNING]
> **警告内容**：MONITOR 会显著拖慢 Redis 性能，官方基准显示开启后吞吐可下降约五成，命令越大开销越大；生产高负载实例严禁长时间开启，只在低峰期、限定时间窗内做临时诊断，用完立刻断开。

```text
127.0.0.1:6379> monitor
OK
1717000000.123456 [0 127.0.0.1:54321] "SET" "user:1001:name" "alice"
1717000000.123789 [0 127.0.0.1:54322] "GET" "user:1001:name"
1717000000.124001 [2 127.0.0.1:54330] "ZADD" "rank" "99" "player:7"
```

> 辨析：MONITOR 输出的是全部命令明文，等于把数据内容也暴露给监控者，包含敏感数据的实例要评估泄露风险；只想统计命令频率与耗时分布时，应改用 info commandstats，它按命令聚合不吐明文。

**速记**：MONITOR 是全量命令直播，能看协议能验错，性能腰斩勿久开。



### redis-benchmark 压测工具

#### 压测参数详解与输出解读

**redis-benchmark**：是 Redis 自带的基准压测工具，通过对指定命令施加并发请求，测出每秒执行数与延迟分布。

- -c 并发连接数，默认 50；-n 总请求数，默认 100000。
- -q 只输出每秒请求数的简洁摘要，适合脚本对比。
- -t 指定要压测的命令集合，如 -t set,get,incr，省略则压默认命令集。
- -P 启用管道，单次网络往返发多条命令，能大幅抬高每秒请求数，用于评估管道收益。
- -d 指定 set 与 get 的 value 字节数，默认 3；-r keyspace 以传入范围为上限生成随机键后缀，模拟带随机 key 的负载。
- -k 1 或 0 控制是否 keepalive；--csv 输出 CSV 格式；-l 循环压测不停歇，适合长时段观察。
- 输出的延迟统计给出最小、最大、平均以及各分位延迟，判断长尾要看高分位而非平均值。
- 输出末尾的 cumulative distribution 按 50% 到 100% 分位列出延迟上限，99.9% 分位之后的跳变最值得关注。

```bash
redis-benchmark -h 127.0.0.1 -p 6379 -c 50 -n 100000 -t set,get -q
redis-benchmark -c 100 -n 1000000 -t set -P 16 -d 256 -q
redis-benchmark -c 50 -n 100000 -t set -r 1000000 -q
```

```text
SET: 98765.43 requests per second, p50=0.5ms
GET: 102040.82 requests per second, p50=0.5ms

====== SET ======
  1000000 requests completed in 6.20 seconds
  100 parallel clients
  256 bytes payload
Latency by percentile:
99.900% <= 2.1ms
```

> 辨析：-P 管道压出来的数字远高于真实业务的单命令模式，那是网络往返被摊薄后的极限值，不能直接当作容量规划依据；带 -r 的随机 key 压测更接近缓存穿透类真实负载，穿透与雪崩场景详见第 25 章。

**速记**：-c 并发、-n 总量、-t 选命令、-P 管道、-d 大小、-r 随机键，每秒请求数与分位延迟一起看。



#### 压测结果的参考性

**压测结果仅供参考**：redis-benchmark 的输出是理想化模型的极限数字，与业务真实负载存在系统性偏差，结论只能作横向对照。

- 压测命令是固定模式，真实业务是混合读写、多 key 与事务脚本，命令复杂度不同。
- 压测 value 默认极小，大 value 下每秒请求数会数量级下降，需用 -d 贴近真实大小。
- 压测客户端与服务器同机时网络路径失真，跨机压测才反映网络瓶颈。
- 开启持久化、主从复制、内存淘汰压力下的稳态性能远低于空载压测，需带生产同级配置重压。
- 短时压测反映的是峰值能力，容量规划应以小时级长压与爬坡压测的稳态值为准。
- 两次压测对比时须保持 -c、-n、-d、-P 全部一致，只改一个变量，否则数字不可比。

> [!CAUTION]
> **注意内容**：严禁直接对生产实例跑 redis-benchmark，压测会以洪峰写入与读取挤占带宽和 CPU，造成正常请求延迟飙升甚至触发主从切换；压测应在隔离的环境实例上进行，压测前清场确认。

**速记**：压测数字是天花板不是承诺，贴近 -d、带持久化、跨机压，才谈容量。



### redis-server 启动参数与配置管理

#### 常用启动参数与配置文件核心项

**redis-server 的启动形态**：不接参数即以默认配置启动，接配置文件路径即按文件启动，也可在文件之后追加覆盖项临时改单次启动行为。

```bash
redis-server
redis-server /etc/redis/redis.conf
redis-server /etc/redis/redis.conf --port 6380 --daemonize yes
```

- bind：指定监听的网卡地址，默认 127.0.0.1 只听本机，放开需显式列出内网地址。
- protected-mode：保护模式开关，无密码且未显式 bind 时拒绝远程访问，默认 yes。
- port：监听端口，默认 6379，单机多实例部署靠错开端口实现。
- requirepass：客户端认证密码，设置后所有连接需 auth 通过。
- maxmemory：最大内存上限，达到后按策略淘汰或拒绝写入。
- maxmemory-policy：内存淘汰策略，如 allkeys-lru、volatile-lru、noeviction，策略语义详见第 15 章。
- appendonly：AOF 持久化开关，yes 开启，持久化机制详见第 18 章。
- dir：工作目录，RDB 与 AOF 文件的落盘位置。
- daemonize：yes 时以守护进程后台运行，日志与进程号文件分别由 logfile 与 pidfile 指定。
- redis-server --version 与 redis-server --help 查看版本与参数清单，redis-cli -v 查看客户端版本。
- 单机多实例时每个实例独立指定 port、dir、logfile 与 pidfile，避免文件互踩。

> 辨析：命令行追加项只对本次进程生效，优先级高于配置文件但不落盘，重启即失效；需要永久生效必须写入配置文件或用 CONFIG REWRITE，安全相关配置的完整清单详见第 31 章。

**速记**：九大件 bind、protected-mode、port、requirepass、maxmemory、maxmemory-policy、appendonly、dir、daemonize，命令行参数只活一次。



#### CONFIG 动态改配置与落盘

**CONFIG 命令族**：CONFIG GET 与 CONFIG SET 支持运行中实例读写配置项，CONFIG REWRITE 把当前配置回写进启动配置文件，三者构成动态调参闭环。

- CONFIG GET pattern 按通配符读配置，返回键值交替的扁平数组。
- CONFIG SET parameter value 在线修改配置，多数项立即生效，无需重启。
- CONFIG REWRITE 将当前生效的配置改写回原配置文件，保留原有注释与结构，只改动被修改的项。
- CONFIG GET * 可列出全部配置项，排查实际生效值时优先用它而非翻配置文件；CONFIG GET maxmemory* 支持前缀过滤。
- 调参前用 CONFIG GET 存档原值，配合 CONFIG SET 回退，避免只改不记。
- 并非所有配置都支持动态修改，port、dir 等与进程生命周期绑定的项只能重启生效，改后报错即属此类。

```bash
redis-cli config get maxmemory
redis-cli config set maxmemory 4gb
redis-cli config set maxmemory-policy allkeys-lru
redis-cli config rewrite
```

```text
1) "maxmemory"
2) "0"
OK
OK
```

> [!IMPORTANT]
> **重要内容**：CONFIG SET 修改后若不执行 CONFIG REWRITE，重启即回滚为配置文件旧值，线上调参务必确认落盘；批量调参前先用 CONFIG GET 记录原值，留好回退路径。

**速记**：GET 看现状、SET 改运行值、REWRITE 才落盘，三步缺一不可。



### INFO 命令分段精读

#### INFO 分段结构与 keyspace 命中率

**INFO**：是实例状态的总出口，输出按段落组织的键值指标，info 段名 可只取一段，info everything 取全量。

- server 段：redis_version 版本、运行模式、操作系统与进程号，确认环境先看这里。
- clients 段：connected_clients 当前连接数、blocked_clients 被阻塞连接数，连接类故障先看这里。
- stats 段：total_commands_processed 累计处理命令数、instantaneous_ops_per_sec 每秒操作数、evicted_keys 因内存满被淘汰的键数。
- persistence 段：RDB 与 AOF 的运行状态——rdb_last_bgsave_status、aof_enabled、aof_last_write_status 等，持久化健康与否先看这里（机制详见第 17、18 章）。
- cpu 段：used_cpu_sys 与 used_cpu_user 为全部线程的 CPU 消耗，used_cpu_sys_children 与 used_cpu_user_children 为后台子进程的消耗，用于判断压力是否在持久化子进程上。
- 命中率由 stats 段的 keyspace_hits 与 keyspace_misses 计算：命中率等于 hits 除以 hits 加 misses。
- replication 段：role 显示主或从，connected_slaves 与 slave0 等行描述从库状态，主从偏移量用于判断同步延迟，复制细节详见第 20 章。
- keyspace 段：db0 到 db15 各库的键数、带过期键数与平均生存时间，格式为 keys=键数,expires=带过期键数,avg_ttl=平均生存毫秒数。

```bash
redis-cli info stats | grep -E "keyspace|evicted|ops"
redis-cli info replication | head -n 6
redis-cli info keyspace
```

```text
total_commands_processed:982341
instantaneous_ops_per_sec:1102
keyspace_hits:567890
keyspace_misses:67890
evicted_keys:0

# Replication
role:master
connected_slaves:2
```

> 辨析：命中率低不一定是坏事，misses 可能来自首次写入前的正常未命中或业务上的 TTL 自然过期；但命中率骤降叠加 evicted_keys 增长，几乎可以断定内存压力正在撕掉缓存，相关治理详见第 29 章。

**速记**：八段 server、clients、memory、persistence、stats、replication、cpu、keyspace，命中率 hits 除以 hits 加 misses，evicted_keys 是内存告警灯。



#### 内存段与内存碎片率

**memory 段**：是内存诊断的核心段，关键在区分分配器视角与操作系统视角的内存，以及由二者之比导出的碎片率。

- used_memory：Redis 分配器申请的总内存，即数据与内部结构实际占用，是与 maxmemory 对比的口径。
- used_memory_rss：操作系统视角的常驻内存，包含分配器未归还的碎片与页对齐损耗。
- mem_fragmentation_ratio：等于 used_memory_rss 除以 used_memory，正常略大于 1，健康区间约 1.0 到 1.5。
- 比率大于 1.5 说明碎片偏多，成因多为频繁变更大小的写入与删除，评估是否择机重启或开启主动碎片整理。
- 比率小于 1 说明 RSS 小于分配量，通常代表发生了 swap，性能会断崖式下跌，属于最高优先级告警。
- used_memory_peak 记录历史峰值用于容量回溯；used_memory_dataset 与 used_memory_overhead 拆分数据占用与运行开销。
- memory stats 给出更细的分项占比，memory doctor 直接给出碎片与峰值方面的诊断结论，是 info memory 的进阶入口。
- mem_allocator 字段标明底层分配器，常见为 jemalloc，DEBUG JMAP 的画像即基于它。

```bash
redis-cli info memory | grep -E "used_memory:|used_memory_rss:|mem_fragmentation_ratio"
```

```text
used_memory:2100000
used_memory_rss:2600000
mem_fragmentation_ratio:1.24
```

> [!CAUTION]
> **注意内容**：mem_fragmentation_ratio 低于 1 时实例大概率已在用 swap，磁盘换内存会让延迟放大几个数量级，应立即排查机器内存占用并考虑扩容或迁实例，而不是继续调参硬扛。

**速记**：used_memory 管账、used_memory_rss 管房，比值即碎片率，大于 1.5 碎片多、小于 1 在 swap。



### SLOWLOG 与 MEMORY 观测

#### SLOWLOG GET、LEN 与 RESET

**SLOWLOG 命令族**：操作慢查询日志的三个动作——GET 读取、LEN 看条数、RESET 清空，配合两个配置项构成慢命令定位的基础设施。

- 记录机制：执行耗时超过 slowlog-log-slower-than（单位微秒，默认 10000 即 10 毫秒）的命令进入内存中的先进先出队列，队列长度由 slowlog-max-len（默认 128）限制，只存内存、重启即清。
- SLOWLOG GET 可带数字只取最近若干条，每条含序号、时间戳、执行耗时微秒、完整命令与客户端地址；SLOWLOG LEN 长期非零说明存在稳定慢命令；SLOWLOG RESET 在排查前清出干净的观察窗口。
- 慢查询只记录服务端执行阶段，排队与网络时间不进日志，完整的排查方法论详见第 29 章。

```bash
redis-cli config set slowlog-log-slower-than 5000
redis-cli slowlog get 10
redis-cli slowlog len
redis-cli slowlog reset
```

**速记**：GET 取、LEN 数、RESET 清；阈值单位是微秒，队列先进先出。



#### MEMORY USAGE 与 MEMORY DOCTOR

**MEMORY 命令**：自 Redis 4.0 起引入的内存观测命令族，USAGE 估算单个键的内存占用字节数，DOCTOR 输出人类可读的内存健康诊断。

- MEMORY USAGE 键名 计入数据结构与元管理开销返回总字节数；集合类型按抽样推算，默认抽 5 个元素，加 SAMPLES 数量 提高精度，SAMPLES 0 为全量统计。
- MEMORY DOCTOR 汇总各维度指标给出诊断文本，指出碎片、副本与客户端缓冲等潜在异常；MEMORY PURGE 手动触发一次主动碎片整理，需主动碎片整理机制支持。
- 与 --bigkeys 的配合：先用它圈出元素最多的键，再用 MEMORY USAGE 逐键复核内存，两步构成大 key 排查的标准动作（详见第 29 章）。

```bash
redis-cli memory usage user:1001:profile
redis-cli memory usage big:zset samples 100
redis-cli memory doctor
```

> USAGE 是估算值而非精确值：元素大小分布不均时默认抽样的误差可能很大，关键大键应加大 SAMPLES；结果比 value 序列化后的字节数大，因为计入了内部结构与字典表等管理开销。

**速记**：USAGE 量单键（默认抽样 5）、DOCTOR 做体检、PURGE 清碎片，三招都是 4.0 起步。



### 检查修复、连接排查与调试命令

#### redis-check-rdb、redis-check-aof 与 redis-sentinel

**检查修复工具与哨兵入口**：redis-check-rdb 校验 RDB 文件完整性，redis-check-aof 校验并可修复 AOF 文件，redis-sentinel 是哨兵模式的启动入口，三者与 redis-server 共用同一套实现。

- redis-check-rdb 接 RDB 文件路径，输出校验和验证结果与文件统计，只能检查不能修复。
- redis-check-aof 接 AOF 文件路径，默认只检查，加 --fix 参数对发现的截断或不完整命令进行修复。
- 修复 AOF 会从第一个损坏命令处截断其后内容，可能丢数据，必须先备份原文件。
- Redis 7 起多部分 AOF 拆分为多个文件，redis-check-aof 会自动识别目录形态并合并检查。
- redis-sentinel 配置文件 以哨兵模式启动进程，等价于 redis-server 加 --sentinel 选项启动，哨兵机制详见第 21 章。
- 典型场景：磁盘写满导致 AOF 尾部截断、宕机后 RDB 校验失败、数据迁移前验证文件可用。
- 修复前用 cp 备份原文件再执行 --fix，截断后原文件不可复原，备份是唯一后悔药。

```bash
redis-check-rdb /var/lib/redis/dump.rdb
redis-check-aof /var/lib/redis/appendonly.aof
cp /var/lib/redis/appendonly.aof /tmp/appendonly.aof.bak
redis-check-aof --fix /var/lib/redis/appendonly.aof
redis-sentinel /etc/redis/sentinel.conf
redis-server /etc/redis/sentinel.conf --sentinel
```

```text
The RDB file is OK: 1200 keys loaded.

AOF analyzed: size=10485760, ok_up_to=10485300, diff=460
This will shrink the file from 10485760 to 10485300.
Continue? [y/N]: y
Successfully truncated AOF
```

> 辨析：修复是截断不是还原，丢的是损坏点之后的命令；若实例仍有完好的从库副本，优先用副本重建而不是修复残缺文件，RDB 与 AOF 机制本身详见第 17 章与第 18 章。

**速记**：RDB 只查不修，AOF 查加 --fix 可修（先备份），sentinel 入口即 redis-server 的哨兵形态。



#### CLIENT LIST 与 CLIENT KILL

**CLIENT 命令族**：CLIENT LIST 列出全部客户端连接的明细，CLIENT INFO 只返回当前连接自身信息，CLIENT KILL 按条件踢除指定连接，三者构成连接排查闭环。

- CLIENT LIST 每行一个连接，关键字段：id 连接唯一号、addr 来源地址端口、fd 文件描述符、age 已连接秒数、idle 空闲秒数。
- cmd 字段显示该连接最近执行的命令，db 显示所在库，name 显示 client setname 设置的连接名。
- 排查连接暴涨时按 addr 前缀聚合来源，配合 age 与 idle 判断是泄漏的空闲连接还是活跃洪峰。
- CLIENT KILL ADDR ip:port 按地址踢，CLIENT KILL ID n 按唯一号踢，新写法支持多条件组合过滤。
- CLIENT KILL TYPE normal 或 TYPE master 或 TYPE slave 可整类踢除，误用会切断主从复制。
- client setname order-svc 与 client getname 成对使用，给连接起名后 CLIENT LIST 的 name 列可直接定位到具体应用实例。
- CLIENT ID 返回当前连接的唯一自增号，单调递增不回收，是追踪单条连接生命周期的锚点。

```bash
redis-cli client list | head -n 3
redis-cli client kill id 42
redis-cli client kill addr 10.0.0.8:52100
```

```text
id=42 addr=10.0.0.8:52100 fd=8 name=order-svc age=3600 idle=2 cmd=get db=0
id=43 addr=10.0.0.9:52110 fd=9 name=pay-svc age=120 idle=0 cmd=set db=0
OK
```

> 辨析：踢连接是断腕操作，被踢的客户端是否自动重连取决于其连接池实现，踢错高活跃连接会造成瞬时错误率抬升；先用 CLIENT LIST 定位再用最小粒度的 ID 或 ADDR 踢，禁用 TYPE 类整批操作。

**速记**：LIST 看全家、INFO 看自己、KILL 按 ID 与 ADDR 精准踢，name 是定位应用的钥匙。



#### DEBUG 调试命令

**DEBUG 命令族**：是一组仅在开发与测试环境使用的内部命令，可人为制造延迟、查看对象内存布局与控制内部行为，生产实例必须禁用。

- DEBUG SLEEP seconds 让服务器阻塞指定秒数，用于模拟卡顿、验证客户端超时与重试逻辑。
- DEBUG JMAP 输出 jemalloc 分配器的内存画像，用于分析内存碎片构成，依赖编译时开启 jemalloc。
- DEBUG OBJECT key 输出对象的引用计数与编码方式，行为偏内部实现，日常用 memory usage 代替。
- DEBUG SET-ACTIVE-EXPIRE 0 可关闭主动过期，用于测试惰性过期路径，过期删除机制详见第 14 章。
- DEBUG COMPACT 与 DEBUG POPULATE 分别用于整理内存与批量灌入测试数据，均属测试专用。
- DEBUG POPULATE number prefix 常用于压测前快速造数，如 debug populate 100000 user: 批量生成字符串键。

```bash
redis-cli debug sleep 5
redis-cli debug jmap
```

```text
OK
(5.02s)
jemalloc zone sizes:
  8: 1024
  16: 2048
```

> [!WARNING]
> **警告内容**：DEBUG SLEEP 会直接阻塞 Redis 主线程，单线程模型下所有请求在阻塞期间全部排队，生产执行等同人为制造事故；且 DEBUG 命令默认对客户端开放，本身即安全漏洞，生产环境必须通过 rename-command 将其改名或置空禁用，安全加固详见第 31 章。

**速记**：DEBUG 全家桶只活在测试环境，SLEEP 一执行全站卡死，生产必禁。



### 第三方图形客户端

#### RESP.app 与 Another Redis Desktop Manager

**图形客户端**：第三方桌面管理工具，以树形界面浏览键空间、直接查看与编辑数据，适合开发调试阶段的直观排查。

- RESP.app：老牌跨平台图形客户端，前身是 RedisDesktopManager，支持 SSH 隧道、TLS、集群与 Sentinel 接入。
- Another Redis Desktop Manager：开源免费的轻量图形客户端，键浏览与多种格式预览等日常能力齐全，社区活跃。
- 定位差异：图形工具胜在直观，适合看数据、查结构；生产排查与自动化仍以命令行与监控为准，编程客户端生态详见第 30 章。

> 图形客户端连接生产实例务必走 SSH 隧道并使用只读账号，批量操作的误伤面大，账号权限收敛详见第 31 章。

**速记**：看数据用 RESP.app 或 Another Redis Desktop Manager，生产连接走隧道加只读。
