## 数据类型：Set

### Set 的基本认识

#### Set 是无序且不重复的字符串集合

**Set（集合）**：是**无序、成员唯一**的字符串成员容器，一个集合最多可存储 **2 的 32 次方减 1**（4294967295，约 42.9 亿）个成员。

- **无序**：成员没有先后位置，不存在下标，无法按位置取第 N 个成员。
- **不重复**：同一成员无论添加多少次，集合中只保留一份。
- **成员是字符串**：集合内不能嵌套集合或其它数据结构，这与整个键的类型无关。
- 支持**增删查、随机抽取、交并差运算**，其中集合运算能力是它与其它类型最大的差别。
- 键的类型标记为 set，TYPE 命令对其返回 set。

```bash
SADD languages "C" "Python" "Go"
SMEMBERS languages
```

```text
1) "Go"
2) "C"
3) "Python"
```

```bash
TYPE languages
```

```text
set
```

> 返回顺序与插入顺序无关，且多次执行同一命令的返回顺序也可能不同：任何依赖成员顺序的业务需求都不该用 Set 承载，有序场景详见第 7 章的 ZSet。

> [!NOTE]
> **提醒内容**：集合对重复的判定依据是**成员字符串的精确相等**，redis 与 Redis 是两个不同成员；需要大小写归一时应在写入前统一转换，而不是指望 Redis 替你处理。

**速记**：Set **无序、不重、纯字符串**，强项是**集合运算**。



### 基础命令：增删查与判存

#### SADD 与 SREM 的增删语义

**SADD**：向集合**添加一个或多个成员**，返回**实际新增**的成员个数；**SREM**：从集合**移除一个或多个成员**，返回**实际移除**的个数。

- SADD 语法为 SADD key member [member ...]，成员一次可写多个，空格分隔。
- 已存在的成员重复添加**只计一次**，返回值直接暴露去重结果；返回 0 表示传入的成员全部已存在。
- SREM 语法为 SREM key member [member ...]，不存在的成员**跳过且不报错**。
- 对不存在的键执行 SREM 返回 0；执行 SADD 则**先创建集合**再添加成员。
- 移除最后一个成员后，键会被**自动删除**，这一行为与所有容器类型一致。

```bash
SADD article:1001:tags "redis" "database" "redis" "nosql"
```

```text
(integer) 3
```

```bash
SREM article:1001:tags "database" "kafka"
```

```text
(integer) 1
```

> SADD 的返回值是**新增个数**而不是集合大小，借助这一点可以在写入侧直接发现重复写入的业务异常；SREM 删除不存在的成员不视为错误，返回 0 表示一个都没删掉。

**速记**：SADD **只数新面孔**，SREM **只数真删掉的**。



#### SMEMBERS 与 SCARD 的读取与计数

**SMEMBERS**：返回集合中的**全部成员**；**SCARD**：返回集合的**成员个数**，即基数。

- SMEMBERS 语法为 SMEMBERS key，时间复杂度 **O(N)**，N 为成员总数。
- SCARD 语法为 SCARD key，时间复杂度 **O(1)**，直接读取计数元数据，不遍历成员。
- SMEMBERS 对不存在的键返回**空列表**，不报错。
- 成员数很大时 SMEMBERS 会**一次性拉回全部数据**，应改用 SSCAN 分批游标遍历。

```bash
SADD course:redis "小明" "小红" "小刚"
SCARD course:redis
```

```text
(integer) 3
```

```bash
SMEMBERS course:redis
```

```text
1) "小刚"
2) "小明"
3) "小红"
```

> SCARD 与 SMEMBERS 的复杂度差距是常考点：**计数走 O(1) 元数据，取全量走 O(N) 遍历**。SSCAN 的游标语义与分批遍历写法详见第 2 章。

**速记**：数个数用 **SCARD**，拉全量才用 **SMEMBERS**。



#### SISMEMBER 与 SMISMEMBER 的成员判存

**SISMEMBER**：判断**单个成员**是否存在于集合，时间复杂度 **O(1)**；**SMISMEMBER**：一次判断**多个成员**，Redis 6.2 引入。

- SISMEMBER 语法为 SISMEMBER key member，存在返回 1，不存在返回 0。
- SMISMEMBER 语法为 SMISMEMBER key member [member ...]，按入参顺序返回由 0 与 1 组成的**列表**。
- 二者对不存在的键一律返回 0 或全 0 列表，**不报错**。
- 判存走哈希表定位，**与集合大小无关**，这是 Set 承担去重白名单角色的根基。
- 典型用法是接口幂等与防重放：把请求指纹 SADD 进集合，处理前先 SISMEMBER 判断是否已处理过。

```bash
SISMEMBER course:redis "小明"
```

```text
(integer) 1
```

```bash
SMISMEMBER course:redis "小明" "小赵"
```

```text
1) (integer) 1
2) (integer) 0
```

> 6.2 之前的版本没有 SMISMEMBER，批量判存只能多次调用 SISMEMBER 或退化为 SMEMBERS 后在应用层比对；网络往返是主要开销，能用 SMISMEMBER 就不要在客户端写循环逐个判。

**速记**：单个判存 **SISMEMBER**，批量判存 **SMISMEMBER**（6.2 起）。



#### SMOVE 的原子搬运

**SMOVE**：把**一个成员**从源集合**原子地**移动到目标集合。

- 语法为 SMOVE source destination member，成功返回 1，失败返回 0。
- 底层是**先删后加**两步，但整体**原子执行**，客户端不会观察到中间状态。
- 成员不在源集合时返回 0，此时目标集合**不做任何修改**。
- 目标集合不存在时**自动创建**；源集合移出最后一个成员后被**自动删除**。

```bash
SMOVE course:redis course:mysql "小明"
```

```text
(integer) 1
```

```bash
SMEMBERS course:redis
SMEMBERS course:mysql
```

```text
1) "小红"
2) "小刚"
```

```text
1) "小明"
```

> SMOVE 与先 SREM 再 SADD 的差别在**原子性**：两条命令之间进程崩溃或并发写入时，成员可能凭空消失，SMOVE 则保证不丢。它每次只能搬一个成员，批量搬运需要 Lua 脚本，详见第 23 章。

**速记**：SMOVE **一次一个、先删后加、整体原子**。



### 随机类命令：SRANDMEMBER 与 SPOP

#### SRANDMEMBER 的 count 三种语义

**SRANDMEMBER**：从集合**随机返回成员但不移除**，count 参数的正负与零决定返回个数与是否可重复。🎲

- 不带 count 或 count 为 0：只返回**一个随机成员**，集合为空时返回 nil。
- count 为**正数**：返回**至多 count 个互不重复**的成员，个数不超过集合基数。
- count 为**负数**：返回 **count 的绝对值个成员且允许重复**，即使绝对值大于基数也照常返回。
- 任何情况下 SRANDMEMBER 都**不修改集合本身**，是只读的随机抽样。

```bash
SRANDMEMBER lottery:pool 3
```

```text
1) "user:7"
2) "user:1024"
3) "user:66"
```

```bash
SRANDMEMBER lottery:pool -5
```

```text
1) "user:7"
2) "user:7"
3) "user:1024"
4) "user:7"
5) "user:66"
```

```bash
SRANDMEMBER lottery:pool
```

```text
"user:1024"
```

> 正数版不重复受基数封顶，负数版可重复不封顶：集合只有 3 人却想取 5 个样本时，写 SRANDMEMBER key 5 只会得到 3 个，写 SRANDMEMBER key -5 会得到 5 个但可能重复，两种语义按业务需要选择。

**速记**：**正不重、负可重、零单个**，一律**不移除**。



#### SPOP 的弹出移除与抽奖基础

**SPOP**：从集合**随机弹出成员并移除**，是抽过不放回类抽奖的原生命令。

- 语法为 SPOP key [count]，不带 count 弹出 1 个并直接返回该成员，带 count 返回成员列表。
- 弹出即**从集合删除**，同一成员不会被抽中第二次。
- 集合为空或键不存在时返回 nil 或空列表，**不报错**。
- 与 SRANDMEMBER 的本质差别：**SPOP 改变集合，SRANDMEMBER 只读**。

```bash
SADD lottery:pool "user:7" "user:66" "user:1024"
SPOP lottery:pool
```

```text
"user:1024"
```

```bash
SPOP lottery:pool 2
```

```text
1) "user:7"
2) "user:66"
```

```bash
SPOP lottery:pool 5
```

```text
1) "user:8"
2) "user:19"
```

> [!CAUTION]
> **注意内容**：SPOP 是**破坏性读取**，弹出的成员不可恢复。调试或演示时若只想随机看看成员，务必改用 SRANDMEMBER，误用 SPOP 会把奖池越抽越少。

**速记**：SPOP **抽一个少一个**，放回式抽样才用 **SRANDMEMBER**。



### 集合运算命令：交并差

#### SINTER 与 SUNION 的交集并集

**SINTER**：返回**同时存在于所有给定集合**的成员；**SUNION**：返回**所有给定集合去重合并**后的成员。

- SINTER 语法为 SINTER key [key ...]，至少给一个键，多个键从左到右求交。
- SUNION 语法为 SUNION key [key ...]，结果自动去重，原集合不受影响。
- 任一给定键不存在时，SINTER 直接返回**空列表**；SUNION 把不存在的键当作**空集合**，结果由其余集合决定。
- 二者都返回**全新列表**，属于纯读操作。

```bash
SADD tag:redis "user:1" "user:2" "user:3"
SADD tag:database "user:2" "user:3" "user:4"
SINTER tag:redis tag:database
```

```text
1) "user:2"
2) "user:3"
```

```bash
SINTER tag:redis tag:database tag:nosuchkey
```

```text
(empty array)
```

```bash
SUNION tag:redis tag:database
```

```text
1) "user:1"
2) "user:2"
3) "user:3"
4) "user:4"
```

> 交集的结果规模由**最小的集合**封顶，Redis 内部会优先遍历基数最小的集合求交；并集则天然承担合并多份标签、好友列表的去重工作，替代应用层的 distinct 逻辑。

**速记**：SINTER **人人都有**，SUNION **合并去重**。



#### SDIFF 与操作数顺序

**SDIFF**：返回**存在于第一个集合、且不存在于后续集合**的成员，操作数顺序直接决定结果。

- 语法为 SDIFF key [key ...]，语义是 A 减 B 减 C，以第一个键为主体。
- 只给一个键时返回该集合**自身的全部成员**。
- 交换两个操作数结果通常**不同**：SDIFF a b 是 a 独有的成员，SDIFF b a 是 b 独有的成员。
- 后续键不存在时**不影响结果**，空集合参与差集等于没有约束。

```bash
SADD follow:alice "bob" "carol" "dave"
SADD follow:bob "carol" "dave" "eve"
SDIFF follow:alice follow:bob
```

```text
1) "bob"
```

```bash
SDIFF follow:bob follow:alice
```

```text
1) "eve"
```

```bash
SDIFF follow:alice follow:bob follow:carol
```

```text
1) "bob"
2) "dave"
```

> 顺序写反是 SDIFF 最常见的翻车点：**前者是我有他没有，后者是他有我没有**，两者合起来才是双向差异；需要互相都关注的语义时应改用 SINTER。

**速记**：SDIFF **谁在前减谁后的**，结果即**前者独有**。



#### SINTERSTORE 系列落库变体

**SINTERSTORE、SUNIONSTORE、SDIFFSTORE**：把交、并、差运算的**结果写入目标集合**而不是直接返回。

- 语法形如 SINTERSTORE destination key [key ...]，运算逻辑与非 STORE 版本一致。
- 目标键已存在时**整体覆盖**；运算结果为空集时**删除目标键**。
- 返回值是**结果集合的成员个数**，不是 OK。
- 目标键可以与某个源键相同，实现**原地运算**，例如 SUNIONSTORE all all tmp。
- 典型用法是把计算结果**物化成集合**，供后续 SISMEMBER、SCARD 直接查询。

```bash
SINTERSTORE mutual:follow follow:alice follow:bob
SCARD mutual:follow
```

```text
(integer) 2
```

```bash
SDIFFSTORE only:alice follow:alice follow:bob
SMEMBERS only:alice
```

```text
(integer) 1
1) "bob"
```

> STORE 系列把每次请求实时算交集，变成写入时算一次、之后读结果，代价是**结果与源集合存在一致性的时间差**；对实时性要求高的场景要么实时算，要么在数据变更点同步维护 STORE 结果。

**速记**：**算好存起来**，三个命令**一一对应**交并差。



#### SINTERCARD 的计数与 LIMIT

**SINTERCARD**：只返回**交集的成员个数**而不返回成员本身，Redis 7.0 引入。

- 语法为 SINTERCARD numkeys key [key ...] [LIMIT limit]，numkeys 显式指明后面有几个键。
- 与 SINTER 的差别：不拉明细、只给计数，**大集合时省去传输与序列化开销**。
- LIMIT 指定**计数上限**，交集个数一旦达到上限立即停止计算并返回，默认 0 表示不限制。
- 返回值与 SINTER 的列表不同，它是**纯整数**，无法据此得到交集成员本身。
- LIMIT 0 与不写 LIMIT 等价；LIMIT 与成员个数无关，只与停止时机有关。

```bash
SADD vip:2026 "user:1" "user:2" "user:3"
SADD paid "user:2" "user:3" "user:9"
SINTERCARD 2 vip:2026 paid LIMIT 1
```

```text
(integer) 1
```

> [!TIP]
> **建议内容**：判断两个大集合是否有共同元素、共同好友是否超过 100 人这类**只关心数量**的需求，优先用 SINTERCARD 加 LIMIT，把最坏耗时限制在常数级，避免为一个大数字拉回整份明细。

**速记**：SINTERCARD **只要个数不要明细**，LIMIT **到数即停**。



### 典型应用场景

#### 标签体系与共同兴趣

**标签体系**：用 Set 承载**用户到标签**与**内容到标签**两组映射，靠交集运算支撑找共同兴趣类功能。

- user:1001:tags 存用户打过的标签，article:1001:tags 存内容挂着的标签。
- 一个标签下的全部用户也可以反向存为一个集合，本质是**倒排索引**。
- 找兴趣重合：SINTER user:1001:tags user:1002:tags 得到两人共同标签。
- 给内容圈人群：先把候选用户并入一个集合，再与内容标签的倒排集合求交。
- 标签变更时在正向、反向两个集合里同步 SADD 与 SREM，保证两边一致。

```bash
SADD user:1001:tags "redis" "backend" "database"
SADD user:1002:tags "redis" "frontend"
SINTER user:1001:tags user:1002:tags
```

```text
1) "redis"
```

> 标签数量通常可控，一个用户几个到几十个，内存开销可以忽略；真正需要防的是某个标签下挂百万用户的倒排集合，求交前先用 SINTERCARD 探规模，见上一考点。

**速记**：用户标签、内容标签**各一个 Set**，共同兴趣就是**一次 SINTER**。



#### 共同好友与可能认识的人

**共同好友**用**交集**实现，**可能认识的人**用**先并后差**实现，两者共用同一批关注集合。

- 每个用户的关注列表存为一个 Set，如 follow:alice、follow:bob。
- 共同关注：SINTER follow:alice follow:bob，直接支撑你们都关注了 X 的展示。
- 可能认识的人：把多个好友的关注列表 SUNION 成候选池，再与我自己的关注列表做差。
- 候选池与差集结果都可落为临时键，便于分步调试与复用。

```bash
SUNIONSTORE candidates follow:bob follow:carol
SDIFFSTORE suggest candidates follow:alice
SMEMBERS suggest
```

```text
1) "eve"
2) "frank"
```

> 可能认识只给出了**候选集**，真实产品还要叠加亲密度、活跃度等排序，纯 Set 拿不到权重，需要打分排序的场景应改用 ZSet（详见第 7 章）；被屏蔽用户的过滤则是在候选集上继续做差集。

**速记**：共同好友**求交**，可能认识**先并后差**，排序加权**另请 ZSet**。



#### 访问去重与精度选型

**访问去重**：用 SISMEMBER 判断**某个标识当天是否出现过**，实现精确的是否首次判断。

- 以天为粒度建键，如 uv:20260907，成员是用户 ID 或设备号。
- 写入前判存返回 0 即记为**新访客**，SADD 的返回值同样能当去重信号。
- 按天建的键应配合 EXPIRE 设置过期时间自动清理，过期删除机制详见第 14 章。
- 该方案**精确无误差**，还能回查、判存、导出名单，但内存与成员数线性相关，亿级标识下成本很高。
- 只需要**近似计数**（如每日 UV 总数）时应改用 HyperLogLog，固定约 12KB、误差约 0.81%，精度对比详见第 8 章。🎯

```bash
SISMEMBER uv:20260907 "device:88231"
```

```text
(integer) 0
```

```bash
SADD uv:20260907 "device:88231"
SISMEMBER uv:20260907 "device:88231"
```

```text
(integer) 1
```

> [!IMPORTANT]
> **重要内容**：精确去重与近似计数是两道不同的选择题：名单要回查、要判定是否见过就必须用 Set；只要一个总数且对精度宽容，HyperLogLog 以不到百分之一的误差换来内存数量级的节省，先明确需求再选类型。

**速记**：**要精确判存用 Set，只要计数用 HyperLogLog**。



### 内部编码与使用边界

#### 三种内部编码与转换条件

**Set 的内部编码**：按成员构成与规模在 **intset、listpack、hashtable** 三者之间自动切换。

- **intset（整数集合）**：全部成员都是**能表示为整数**、且个数不超过 set-max-intset-entries（默认 512）时使用。
- **listpack（紧凑列表）**：Redis 7.0 起新增，成员个数不超过 set-max-listpack-entries（默认 128）且单个成员长度不超过 set-max-listpack-value（默认 64 字节）时使用。
- **hashtable（哈希表）**：以上条件任一不满足时使用，判存从 O(N) 变为 O(1)。
- 当前编码用 OBJECT ENCODING key 查看，类型与编码的对应关系详见第 13 章。

```bash
SADD nums 1 2 3
OBJECT ENCODING nums
```

```text
"intset"
```

```bash
SADD nums "redis"
OBJECT ENCODING nums
```

```text
"hashtable"
```

```bash
SADD small "a" "b" "c"
OBJECT ENCODING small
```

```text
"listpack"
```

> [!IMPORTANT]
> **重要内容**：编码切换是**单向升级**，intset 或 listpack 一旦超出阈值转为 hashtable，即使随后删成员瘦身也**不会退回**紧凑编码；Redis 7.0 之前的小集合没有 listpack 可用，直接落在 hashtable 上。批量写入整数集合前先想清楚最终规模，避免无谓的编码跃迁。

**速记**：**全整数看 intset，小而短看 listpack，其余 hashtable**，升级**单向**。



#### 常见误用与规避

**Set 的典型误用**：把 O(N) 命令用在大集合上，或把它当作队列与有序结构。

- 用 SMEMBERS 拉取**百万级成员**：一次网络传输加全量遍历，容易阻塞主线程并撑爆客户端内存。
- 把 Set 当**队列**：Set 无序且不能从固定端进出，先进先出应使用 List（详见第 5 章），消息队列语义可评估 Stream（详见第 9 章与第 24 章）。
- 在**百万级大集合**上直接跑 SINTER、SUNION、SDIFF：运算耗时随成员数线性增长，应改用 SINTERCARD 先探规模。
- 依赖成员**顺序**：Set 的返回顺序不保证稳定，有序需求应使用 ZSet 或让成员自带序号。
- 大集合遍历一律改用 **SSCAN** 分批游标，线上排查慢命令的方法详见第 29 章。

```bash
SSCAN big:set 0 COUNT 1000
```

> **警告内容**：生产环境对百万级成员执行 SMEMBERS 可能造成**秒级阻塞**与内存陡增，属于高危操作；确需全量数据时改用 SSCAN 分批拉取或从只读副本读取，执行前先用 SCARD 评估规模。
