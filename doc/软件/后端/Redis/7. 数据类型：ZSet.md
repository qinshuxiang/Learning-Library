## 数据类型：ZSet

### ZSet 的认识

#### ZSet 的定义与核心特性

**有序集合（Sorted Set，简称 ZSet）**：是给每个成员关联一个 double 类型分数（score）、成员唯一且按分数自动排序的集合类型。

- ZSet 同时兼顾 **Set 的唯一性**与**排序能力**：成员不允许重复，分数允许重复。
- 排序由 Redis 在写入时自动维护，按 score 从小到大排列，读取时无需业务侧再排序。
- 分数是 64 位双精度浮点数，支持正负值与 +inf、-inf；成员是字符串，单个最大 512MB。
- 同一成员重复写入不会产生新元素，只会更新其分数。
- 与 Hash 对比：Hash 是字段到字符串值的映射、不排序，ZSet 是成员到分数的映射、按分数排序。
- 内部同时使用跳表与哈希表：跳表支撑按分数的范围访问，哈希表支撑成员到分数的 O(1) 查找（跳表结构详见第 12 章）。

```bash
ZADD board 90 alice 85 bob 95 carol
ZRANGE board 0 -1 WITHSCORES
```

```text
1) "bob"
2) "85"
3) "alice"
4) "90"
5) "carol"
6) "95"
```

> ZSet 与 List 都“有序”，但 List 的顺序由**插入顺序**决定，ZSet 的顺序由 **score** 决定；ZSet 与 Set 都“唯一”，但 Set 不排序。选型标准：只需去重选 Set，需按插入顺序选 List，需按某个权重排序选 ZSet。

**速记**：成员**唯一**、按 **score 排序**、**跳表管范围**、**哈希管点查**。



#### ZSet 的内部编码

**ZSet 的内部编码**：元素少且成员短时使用 listpack，元素个数或成员长度超过阈值后转换为 skiplist 编码。

- **listpack 编码**：成员与分数紧凑连续存放，节省内存，但范围操作需要线性扫描。
- **skiplist 编码**：zset 结构同时持有跳表与字典，范围查询与单点查询都高效。
- 转换阈值：元素个数不超过 128 且任一成员长度不超过 64 字节时用 listpack，任一条件被突破即转 skiplist，且只升不降。
- 阈值由配置 zset-max-listpack-entries 与 zset-max-listpack-value 控制；7.0 之前对应的紧凑编码叫 ziplist。
- 编码转换对命令完全透明，业务无需感知当前编码。

```bash
ZADD board 90 alice 85 bob 95 carol
OBJECT ENCODING board
```

```text
listpack
```

> [!NOTE]
> **提醒内容**：排查内存问题时可用 OBJECT ENCODING 查看实际编码，再对照阈值判断是否因编码转换产生了额外开销（OBJECT ENCODING 等通用命令详见第 2 章）。

**速记**：**少而短用 listpack，多则转 skiplist，只升不降**。



### 分数的写入与读取

#### ZADD 的完整选项

**ZADD**：向 ZSet 添加成员并设置分数，成员已存在时更新其分数，是 ZSet 的核心写入命令。

- 基本语法：ZADD key [NX|XX] [GT|LT] [CH] [INCR] score member [score member ...]，一次可写多个分数成员对。
- **NX**：只新增，已存在成员不更新；**XX**：只更新已存在成员，不新增。
- **GT**（6.2+）：仅当新分数大于当前分数才更新；**LT**（6.2+）：仅当新分数小于当前分数才更新；GT 与 LT 互斥，且都与 NX 互斥。
- **CH**：把返回值从“新增个数”改为“新增加更新”的变化总数，即被修改的成员个数。
- **INCR**：对分数做累加，此时只允许一个分数成员对，返回累加后的新分数而非个数；与 NX 或 XX 组合时若操作未执行则返回 nil。
- 不加任何选项时，返回值为**新增成员的个数**。
- 分数支持负数与 ±inf；同一批次内成员重复出现时以后一个分数为准。

```bash
ZADD board 90 alice 85 bob 95 carol
ZADD board XX 95 alice
ZADD board GT CH 99 alice
ZADD board NX 80 dave
ZADD board LT 10 alice
ZADD board INCR 5 bob
```

```text
(integer) 3
(integer) 0
(integer) 1
(integer) 0
(integer) 0
"90"
```

> 辨析：XX 更新已有成员但不加 CH 时返回 0，容易误判为失败——返回值默认只统计新增，加了 CH 才统计更新；GT 组合常用于“分数只许上涨、不许回落”的排行榜写入保护；INCR 模式下返回值变成了字符串形式的分数，与个数语义截然不同。

**速记**：**NX 只新增，XX 只更新，GT LT 比大小，CH 数变化，INCR 回分数**。



#### ZSCORE、ZMSCORE 与 ZINCRBY

**分数的读取与增减**：单个取分数用 ZSCORE，批量取分数用 ZMSCORE（6.2+），对分数做增减用 ZINCRBY。

- ZSCORE key member：返回成员当前分数，成员不存在返回 nil。
- ZMSCORE key member [member ...]（6.2+）：一次返回多个成员的分数，缺失的成员在结果中对应位置补 nil。
- ZINCRBY key increment member：把成员分数加上增量 increment 后返回新分数，成员不存在则先按 0 创建再加。
- ZINCRBY 的增量可为负数，用于扣减场景；等价于 ZADD key INCR 增量 成员。

```bash
# 此时 board：bob 85、alice 90、carol 95
ZSCORE board alice
ZMSCORE board alice dave bob
ZINCRBY board 10 bob
ZINCRBY board -5 bob
```

```text
"90"
1) "90"
2) (nil)
3) "85"
"95"
"90"
```

> 辨析：ZSCORE 与 ZMSCORE 返回的分数是字符串形式，整数也按字符串返回，客户端需自行转为数值；ZINCRBY 的操作对象是成员而非键，键不存在时 Redis 会先创建 ZSet，不会报错；批量场景优先用 ZMSCORE 一次往返，减少网络开销。

**速记**：**单个 ZSCORE，批量 ZMSCORE，加减 ZINCRBY，负数即扣减**。



#### ZRANK 与 ZREVRANK

**排名查询**：ZRANK 返回成员按分数从低到高的名次，ZREVRANK 返回从高到低的名次，名次一律从 0 开始。

- ZRANK key member：分数最低的成员排名为 0。
- ZREVRANK key member：分数最高的成员排名为 0，排行榜场景最常用。
- 排名随全体成员分数动态变化，任何写入都可能改变已有成员的排名。
- 成员不存在时返回 nil，与名次 0 含义完全不同，判空逻辑要分开处理。

```bash
# 此时 board：bob 90、carol 95、alice 99
ZRANK board alice
ZREVRANK board alice
ZREVRANK board dave
```

```text
(integer) 2
(integer) 0
(nil)
```

> 辨析：并列分数的成员按成员字符串的**字典序**排列，名次因此唯一；需要“同分先达成者靠前”时，应改用复合 score 设计（见本章排行榜实战），而不是依赖默认字典序；先判 nil 再用名次，否则会把“未上榜”误当成第 0 名。

**速记**：**ZRANK 正着数 0 起，ZREVRANK 倒着数 0 起，不存在回 nil**。



### 范围查询

#### ZRANGE 的 7.0 统一语法

**ZRANGE**：自 7.0 起统一的范围查询命令，通过可选参数覆盖按排名、按分数、按字典序三种方式，均可正序或逆序。

- 完整语法：ZRANGE key start stop [BYSCORE|BYLEX] [REV] [LIMIT offset count] [WITHSCORES]。
- 默认按**排名**查询：start 与 stop 是名次下标，0 与 -1 表示首尾，ZRANGE board 0 -1 返回全部成员。
- **REV**：逆序返回，此时 start 与 stop 的含义也随之反转，start 是“高分端”下标。
- **BYSCORE**：按分数区间查询；**BYLEX**：按字典序区间查询；二者互斥，一次只能指定一个。
- **LIMIT offset count**：对结果分页，仅在指定 BYSCORE 或 BYLEX 时可用，语义同 SQL 的 LIMIT。
- **WITHSCORES**：结果中成员与分数交替出现。
- 旧命令与新语法的对应关系：ZRANGEBYSCORE 等价于 ZRANGE 加 BYSCORE；ZREVRANGEBYSCORE 等价于 ZRANGE 调换区间加 BYSCORE 加 REV；ZRANGEBYLEX 等价于 ZRANGE 加 BYLEX；ZREVRANGE 等价于 ZRANGE 加 REV。

```bash
# 此时 board：bob 90、carol 95、alice 99
ZRANGE board 0 -1 WITHSCORES
ZRANGE board 0 1 REV
ZRANGE board (85 +inf BYSCORE
ZRANGE board +inf 85 BYSCORE REV LIMIT 0 2
```

```text
1) "bob"
2) "90"
3) "carol"
4) "95"
5) "alice"
6) "99"
1) "alice"
2) "carol"
1) "bob"
2) "90"
3) "carol"
4) "95"
5) "alice"
6) "99"
1) "alice"
2) "99"
3) "carol"
4) "95"
```

```bash
# 旧命令与等价新语法的对照演示，二者结果完全一致
ZRANGEBYSCORE board (85 +inf
ZRANGE board (85 +inf BYSCORE
```

```text
1) "bob"
2) "90"
3) "carol"
4) "95"
5) "alice"
6) "99"
1) "bob"
2) "90"
3) "carol"
4) "95"
5) "alice"
6) "99"
```

> [!TIP]
> **建议内容**：ZRANGEBYSCORE、ZREVRANGEBYSCORE、ZRANGEBYLEX、ZREVRANGE 等旧命令已被官方标记为废弃，新代码统一写 ZRANGE，避免新旧混用造成维护负担；排查他人代码时按上面的对应关系翻译，即可快速读懂旧写法。

**速记**：**ZRANGE 一个命令管三种查询**，默认按排名，**REV 反转**，**LIMIT 管分页**。



#### BYSCORE 的区间写法

**BYSCORE 区间**：min 与 max 默认为闭区间，在数值前加半角左括号表示开区间，另支持正负无穷。

- 默认包含端点：ZRANGE board 85 95 BYSCORE 同时包含 85 与 95 的成员。
- 半角左括号 ( 表示开区间：ZRANGE board (85 95 BYSCORE 包含 95、不含 85，两端可分别加 (。
- **+inf 与 -inf**：表示正无穷与负无穷，ZRANGE board -inf +inf BYSCORE 等价于按分数取全量；正无穷可省略正号写成 inf。
- 开闭区间与 LIMIT 组合可实现“从某一分数继续向后翻页”的游标式分页。
- 区间参数是字符串而非纯数字，程序拼接时要注意保留括号与 inf 原样。

```bash
# 此时 board：bob 90、carol 95、alice 99
ZRANGE board (85 +inf BYSCORE
ZRANGE board 85 (95 BYSCORE
ZRANGE board -inf +inf BYSCORE LIMIT 0 2
```

```text
1) "bob"
2) "90"
3) "carol"
4) "95"
5) "alice"
6) "99"
1) "bob"
2) "90"
1) "bob"
2) "90"
3) "carol"
4) "95"
```

> 辨析：开区间符号只有**半角左括号一种**，没有 [ 或 ) 的写法；-inf 与 +inf 前不加括号，(-inf 这种写法无意义，负无穷直接写 -inf；闭区间端点恰好等于某成员分数时该成员会被包含，做“翻页去重”时常用开区间跳过上一页的最后一个分数。

**速记**：默认**闭区间**，加 **( 变开**，无穷用 **±inf**，翻页靠 **LIMIT**。



#### BYLEX 的字典序查询

**BYLEX**：按成员的字典序（二进制比较）查询范围，仅适用于全部成员分数相同的 ZSet。

- 字典序区间的元素必须以 [ 或 ( 开头：[b 表示包含 b，(b 表示不含 b。
- 区间的首元素用半角减号 - 表示负无穷，末元素用半角加号 + 表示正无穷，二者本身不加括号。
- 典型场景：把全部成员的 score 统一写成 0，让字典序成为唯一排序依据，可做自动补全、有序标签表等。
- 逆序查询同样是 ZRANGE 加 REV 参数；取“某前缀之下一个元素”这类操作也依赖该语法。

```bash
ZADD words 0 apple 0 banana 0 cherry
ZRANGE words [b + BYLEX
ZRANGE words - (c BYLEX
```

```text
1) "banana"
2) "cherry"
1) "apple"
2) "banana"
```

> [!IMPORTANT]
> **重要内容**：成员分数不全相同时 BYLEX 的结果未定义，不可依赖；若需求是“同分再按名称排”，正确做法是把名称参与复合 score 设计（见本章排行榜实战），而不是对异分 ZSet 使用 BYLEX。

**速记**：**同分才用 BYLEX**，**[ 含 ( 不含**，首尾无穷写 **- 与 +**。



### 统计、删除与辅助命令

#### ZCARD 与 ZCOUNT

**统计命令**：ZCARD 返回成员总数，ZCOUNT 统计指定分数区间内的成员个数。

- ZCARD key：时间复杂度 O(1)，直接读取元素计数。
- ZCOUNT key min max：区间规则与 BYSCORE 完全一致，默认闭区间，可加 ( 表示开区间，也可用 ±inf。
- ZCOUNT 在 skiplist 编码下利用跳表按分数定位两端，效率远高于全量遍历。
- 需要按时间或数值维度计数时，把该维度编码进 score 即可直接用 ZCOUNT 统计。
- 二者常配合使用：先 ZCARD 判断规模，再决定是否分页读取。

```bash
# 此时 board：bob 90、carol 95、alice 99
ZCARD board
ZCOUNT board (85 95
ZCOUNT board -inf +inf
# score 存秒级时间戳时，统计未来一小时的到期数
ZCOUNT queue 1720000000 1720003600
```

```text
(integer) 3
(integer) 2
(integer) 3
(integer) 1
```

> 辨析：ZCOUNT 统计的是**分数区间**内的成员数，与名次区间无关；要统计“前 N 名”的人数应使用名次区间配合 ZRANGE 取回后计数；分数带小数时区间端点照常比较，不受取整影响。

**速记**：**ZCARD 数全体，ZCOUNT 数分数段**。



#### 三种删除命令

**删除操作**：按成员删用 ZREM，按名次区间删用 ZREMRANGEBYRANK，按分数区间删用 ZREMRANGEBYSCORE。

- ZREM key member [member ...]：按成员删除，可一次删多个，返回实际删除的个数。
- ZREMRANGEBYRANK key start stop：按名次区间删除，下标含端点，支持负数下标，常用于只保留前 N 名。
- ZREMRANGEBYSCORE key min max：按分数区间删除，区间规则同 BYSCORE，支持开区间与 ±inf。
- 三个命令的返回值都是**被删除成员的实际个数**，不存在的成员不计入。

```bash
# 此时 board：bob 90、carol 95、alice 99
ZREM board dave
ZREMRANGEBYSCORE board -inf 90
ZREMRANGEBYRANK board 0 0
```

```text
(integer) 0
(integer) 1
(integer) 1
```

```bash
# 只保留前 100 名：删除名次 100 到末尾的全部成员
ZREMRANGEBYRANK hot 100 -1
```

```text
(integer) 12
```

> 辨析：“保留前 100 名”的标准写法是 ZREMRANGEBYRANK key 100 -1——删出名次 100 到末尾的全部成员，方向是**删尾巴留头部**；ZREM 删除不存在的成员返回 0 而非报错，批量删除时不能以报错与否判断成员是否存在。

**速记**：**删成员用 ZREM，删名次用 BYRANK，删分数用 BYSCORE**。



#### ZRANDMEMBER 与 ZRANGESTORE

**两个辅助命令**：ZRANDMEMBER（6.2+）随机取样，ZRANGESTORE（6.2+）把范围查询结果直接存为新键。

- ZRANDMEMBER key [count] [WITHSCORES]：count 为正返回不重复的 count 个成员，为负返回可能重复的绝对值个成员；不带 count 默认返回 1 个。
- count 为正且大于成员总数时返回全部成员；count 为负时返回数量恰为 count 的绝对值。
- ZRANGESTORE dst src start stop [BYSCORE|BYLEX] [REV] [LIMIT offset count]：参数与 ZRANGE 完全一致，把结果写入 dst 并返回存储的元素个数。
- ZRANGESTORE 的 dst 若已存在会被整体覆盖，常用于把主榜单裁剪为子榜单。

```bash
ZADD board 90 alice 85 bob 95 carol
ZRANDMEMBER board 2 WITHSCORES
ZRANGESTORE top2 board 0 1 REV
ZRANGE top2 0 -1 WITHSCORES
```

```text
1) "carol"
2) "95"
3) "alice"
4) "90"
(integer) 2
1) "carol"
2) "95"
3) "alice"
4) "90"
```

> 辨析：ZRANDMEMBER 只读不删，取样后原集合不变，需要“随机弹出”语义时应取回后自行 ZREM；上面随机取样的输出仅为示意，实际结果每次不同；ZRANGESTORE 复制的是查询时刻的快照，源集合后续变化不会同步到目标键。

**速记**：**随机抽样 ZRANDMEMBER，查询结果落新键 ZRANGESTORE**。



### 弹出与阻塞弹出

#### ZPOPMIN 与 ZPOPMAX

**弹出命令**：ZPOPMIN 移除并返回分数最小的成员，ZPOPMAX 移除并返回分数最大的成员，均为原子操作。

- 语法：ZPOPMIN key [count]，ZPOPMAX key [count]；count 可选，默认弹出 1 个。
- 返回成员与分数交替的数组；弹出即删除，原集合随之缩小。
- 复杂度为 O(log N) 乘弹出个数，源于跳表头尾定位与删除。
- 典型用途：优先级队列、任务调度里“每次取最紧急任务”。

```bash
# 此时 board：bob 90、carol 95、alice 99
ZPOPMIN board
ZPOPMAX board 2
```

```text
1) "bob"
2) "90"
1) "alice"
2) "99"
3) "carol"
4) "95"
```

> 辨析：ZPOPMIN 与 ZRANDMEMBER 的区别在于**是否删除**——前者弹出即删，后者只读；需要“看一眼但不取走”时应使用 ZRANGE 0 0 或 ZRANGE 0 0 REV；弹出后集合可能变空，Redis 会自动删除空键，无需手动清理。

**速记**：**MIN 取最小，MAX 取最大，弹出即删除**。



#### 阻塞弹出 BZPOPMIN 与 ZMPOP 家族

**阻塞与多键弹出**：BZPOPMIN、BZPOPMAX 是阻塞版弹出，ZMPOP、BZMPOP（7.0+）支持一次从多个键弹出多个成员。

- BZPOPMIN key [key ...] timeout：集合为空时阻塞等待，timeout 为 0 表示无限阻塞；多个键按给定顺序检查，取第一个有数据的键。
- BZPOPMAX 语义相同，取分数最大者；返回值为键名、成员、分数三个元素组成的数组。
- ZMPOP numkeys key [key ...] MIN|MAX [COUNT count]（7.0+）：从 numkeys 个键中弹出 MIN 或 MAX 端的至多 count 个成员；全部为空时返回 nil。
- BZMPOP timeout numkeys key [key ...] MIN|MAX [COUNT count]（7.0+）：ZMPOP 的阻塞版，timeout 语义同 BZPOPMIN。
- BZPOPMIN 与 BZPOPMAX 弹出方向固定，ZMPOP 家族用 MIN、MAX 参数自由指定方向，且一次可弹多个。
- 多键阻塞是延迟队列、任务分发的基础原语，与 List 的 BLPOP 思路一致。

```bash
ZADD queue 1720000000000 task:1001
BZPOPMIN queue 0
```

```text
1) "queue"
2) "task:1001"
3) "1720000000000"
```

```bash
ZMPOP 2 queue:delay queue:retry MIN COUNT 3
```

```text
1) "queue:delay"
2) 1) "task:1001"
   2) "1720000000000"
```

> 辨析：BZPOPMIN 一次只弹一个成员且不能跨键批量；需要批量或按 MIN、MAX 方向任选时必须用 7.0 的 ZMPOP 家族；timeout 为 0 时连接会一直挂起，客户端要设置合理的 socket 超时避免假死；阻塞弹出只在集合为空时等待，集合非空时立即返回。

**速记**：**B 开头会阻塞，timeout 0 不超时；M 开头多键多弹出，7.0 才有**。



### 实战场景与避坑

#### 排行榜的复合 score 设计

**复合 score 设计**：把业务分数放在高位、时间信息放在低位拼成一个 score，使 ZSet 在按分数排名的同时自动实现“同分按达成时间排先后”。

- 拼接公式：score = 主分数 × 10^13 + (10^13 − 毫秒时间戳)，整数位是主分数，低位是时间补数。
- 时间补数用固定常数减时间戳：达成越早，补数越大，同分时排名越靠前；若业务要求后达成者靠前，直接放时间戳本身即可。
- 展示时从 ZSCORE 的结果反解：对 10^13 向下取整得主分数，余数反推时间戳。
- 写入侧用 ZADD GT 保证分数只涨不跌；读取侧用 ZREVRANGE 取前 N 名、ZREVRANK 查个人名次。
- 反解展示时用整数除法取主分数，务必在应用层做，不要把复合 score 直接透出给前端。
- Node 客户端的落地写法与连接管理详见第 30 章，批量写入可配合管道减少往返。

```bash
# 主分数 95，达成时间 1720000000000 毫秒
# 95 * 10^13 + (10^13 - 1720000000000) = 958280000000000
ZADD board GT 958280000000000 alice
ZSCORE board alice
ZREVRANGE board 0 9 WITHSCORES
ZREVRANK board alice
```

```text
"958280000000000"
```

> [!CAUTION]
> **注意内容**：double 只有 2^53 以内的整数才能精确表示，即约 9.007 乘 10 的 15 次方；复合 score 的总位数必须控制在此范围内，超限会发生**精度丢失**，导致排名错乱或时间位失真。主分数很大时可把时间戳降为秒级以压缩低位宽度，写入前先按最大主分数与最大时间戳估算总位数。🏆

**速记**：**高位放分数，低位放时间，同分按时间自然排序**。



#### 延迟队列实现

**ZSet 延迟队列**：以任务标识为 member、执行时间戳为 score 写入 ZSet，消费者轮询取出到期任务，实现按时间调度的队列。

- 生产者：ZADD queue 执行时间戳 任务标识，一次写入即完成登记。
- 消费者：用 ZRANGEBYSCORE queue -inf 当前时间戳 LIMIT 0 10 取出到期任务，按分数从早到晚消费。
- 取到任务后先执行再 ZREM 删除；多个消费者同时抢任务时，取出与删除必须原子化，通常用 Lua 脚本或分布式锁（详见第 23 章、第 27 章）。
- BZPOPMIN 可替代轮询实现“有到期任务才醒”的推送模式，但拿不到时间窗口内的一批任务，高吞吐场景仍以轮询为主。
- 需要失败重试时，把任务以新时间戳重新 ZADD 回队列即可，天然支持延迟重投。
- 与 Stream 消息队列的取舍见第 24 章：简单定时调度用 ZSet 足够，需要消费组与消息确认时选 Stream。

```bash
ZADD queue 1720000000000 task:1001
ZRANGEBYSCORE queue -inf 1720000000100 LIMIT 0 10
ZREM queue task:1001
```

```text
1) "task:1001"
```

```bash
# 游标式翻页：以上一批最后一个分数为开区间起点，继续向后取
ZRANGEBYSCORE queue (1720000000100 +inf LIMIT 0 10
```

```bash
# 任务执行失败，延迟 60 秒后重试
ZADD queue 1720000060000 task:1001
```

> [!WARNING]
> **警告内容**：多消费者环境下“先取出后删除”存在**重复消费**风险——两个消费者可能在同一毫秒各自读到同一条到期任务；务必用 Lua 脚本把取任务与删任务合并为原子操作，或对任务加分布式锁，否则会出现任务被重复执行的事故。⏰

**速记**：**score 存到期时间，轮询取到期，原子删除防重复**。



#### 常见误用与避坑

**ZSet 的常见误用**：集中在全量拉取、分数精度与返回值误判三类，生产事故多源于此。

- 误用 ZRANGE key 0 -1 全量拉取大 ZSet：百万级成员的单次全量读取会长时间占用主线程，阻塞其他命令（单线程模型详见第 16 章）；应按名次或分数分页，配合 LIMIT 逐批取（性能调优详见第 29 章）。
- 复合 score 超过 2^53：整数位与时间位拼接过宽，double 无法精确表示，出现排名抖动；写入前先估算总位数。
- ZADD 不带 GT 直接覆盖：重复写入会无条件覆盖旧分数，排行榜允许刷分；需要保底时必须加 GT 或 NX。
- WITHSCORES 结果结构误判：成员与分数在数组中**交替出现**，客户端解析时按两两一组处理，不要当成两个独立数组。
- BYLEX 用在异分集合上：结果未定义，排序需求一律回到 score 设计本身。
- 弹出与删除非原子：多消费者场景拆开写 ZRANGE 加 ZREM，存在竞态；用 Lua 或 ZMPOP 保证原子性。
- 忽视编码阈值：成员普遍超过 64 字节会让整个 ZSet 提前转为 skiplist，内存与遍历成本同步上升。

> 辨析：ZSet 的命令复杂度差异很大——ZSCORE、ZCARD 是 O(1)，ZADD、ZRANK 是 O(log N)，ZRANGE 全量与 ZREMRANGEBYSCORE 是 O(log N + M)；评估大集合操作时先看 M（返回或删除的元素个数）而非只看成员总数，这正是“禁全量拉取”的复杂度根源。

**速记**：**不全量拉取、不超 2^53、覆盖先想 GT、WITHSCORES 两两一组、多消费者必原子**。
