## 全局对象与模块基础

### global 全局对象

#### global 是 Node 的顶级对象

**global**：是 Node.js 运行时的**顶级对象**，相当于浏览器环境中的 window，所有全局可访问的成员都挂在它之下。

global 与浏览器 window 的对照：

- **浏览器**：顶层声明的变量、函数会成为 window 的属性。
- **Node**：顶层声明的变量、函数**不会**成为 global 的属性，原因见模块作用域相关章节。

```js
// 在任意模块顶层执行
console.log(global === globalThis); // true
console.log(typeof global.setTimeout); // "function"
```

> global 提供运行时基础设施（定时器、控制台、进程对象等）。理解 global 是理解 Node 模块系统边界的前提：离开 global，仍可使用语言内置对象（Object、Array、Promise 等），因为它们属于 ECMAScript 规范而非某一运行时。

**速记**：global 是**Node 的 window**。



#### 全局变量不会自动成为 global 属性

**全局变量**：在文件顶层用 var、let、const 声明的变量，是**模块作用域的局部变量**，不会自动挂到 global 之下。

验证方式：

- a.js 中写 const name = "why"，b.js 中无法通过 global.name 获取。
- 只有显式执行 global.name = "why"，才能跨模块共享。

```js
// a.js
const greeting = "hello";
global.greeting = "hello-from-global"; // 显式挂载

// b.js
console.log(typeof greeting); // "undefined"，未自动暴露
console.log(global.greeting); // "hello-from-global"
```

> 这一细节常被误解为"Node 顶层变量就是全局"。实际上模块系统先用函数包裹每个文件，所以顶层声明落在函数作用域内，不会污染 global。这是 Node 模块隔离的根基，也是与浏览器裸 script 的本质差异。

**速记**：**顶层声明只属模块，不进 global**。



#### globalThis 的统一

**globalThis**：是 ECMAScript 2020 引入的**跨环境统一全局对象引用**，在 Node 中指向 global，在浏览器中指向 window。

globalThis 的价值：

- **跨环境一致**：同一段库代码既能在 Node 又能在浏览器拿到真实全局对象。
- **语义清晰**：不再依赖 global 或 window 的字面名称。

```js
// 以下三者指向同一对象
console.log(globalThis === global); // true

function readGlobalFlag() {
  return globalThis.__flag; // 不关心运行环境
}
```

> 新代码应优先使用 globalThis 而非 global 或 window，以保证可移植性。在 Node 内部两者完全等价，选择 globalThis 只是让代码不被运行时绑定。



### Node 中的特殊变量

**速记**：globalThis 是**跨环境统一引用**。

#### __dirname 与 __filename 是局部变量

**__dirname 与 __filename**：是 Node 为每个模块注入的**局部变量**，表示当前模块所在目录与文件的绝对值，它们**不是** global 的属性。

验证方式：

- 在模块中打印 typeof global.__dirname 得到 "undefined"。
- 在 REPL 中直接使用 __dirname 会报错（REPL 没有模块包裹）。

```js
console.log(typeof __dirname); // "string"
console.log(typeof global.__dirname); // "undefined"
```

> 不要试图通过 global.__dirname 读取，它本就不存在。也不要用 var __dirname = ... 覆盖后再依赖它，因为 Node 注入的就是局部绑定，重名声明会遮蔽注入值。

**速记**：二者是**模块局部变量，非全局**。



#### __dirname 与 __filename 的取值含义

**__filename**：是当前被执行模块文件的**绝对路径**（含文件名与扩展名）。**__dirname**：是该文件所在目录的**绝对路径**（不含末尾分隔符）。

取值对照（假设文件位于 /project/src/app.js）：

- __filename 得到 /project/src/app.js。
- __dirname 得到 /project/src。

```js
// /project/src/app.js
console.log(__filename); // /project/src/app.js
console.log(__dirname); // /project/src
```

> 在 ES Module（.mjs 或开启 type:module 的 .js）中，__dirname 与 __filename **不可用**，需用 import.meta.url 配合 fileURLToPath 取得等价信息。这是 CommonJS 与 ESM 的显著差别，迁移时容易踩坑。

**速记**：**__filename 含文件名，__dirname 只到目录**。



#### 与 process.cwd 的区别

**process.cwd**：是 Node 进程的**当前工作目录**，由启动 Node 的命令行所在目录决定，与模块文件位置无关。

三者差异要点：

- **__dirname**：跟着**文件位置**走，固定不变。
- **process.cwd**：跟着**启动目录**走，会随命令行位置变化。
- **__filename**：文件绝对路径，同样固定。

```js
// 在 /project 目录执行 node src/app.js
console.log(__dirname); // /project/src （文件所在）
console.log(process.cwd()); // /project （启动目录）
```

> 读取**相对当前文件**的资源时务必用 __dirname 拼接路径，不要依赖 process.cwd；否则换一个启动目录运行程序，相对路径就会指向错误位置，引发文件找不到。



### 常见的全局函数与对象

**速记**：**__dirname 看文件位置，cwd 看启动位置**。

#### console 与 process

**console**：是标准输出对象，提供 log、info、warn、error 等方法，输出到 stdout 或 stderr。**process**：是当前 Node 进程对象，提供环境变量、命令行参数、退出控制等。

```js
// console 常用方法
console.log("普通日志");
console.warn("警告日志");
console.error(new Error("出错").message);

// process 常用成员
console.log(process.platform); // "darwin" / "linux" / "win32"
console.log(process.env.NODE_ENV); // 环境变量
console.log(process.argv); // [node路径, 脚本路径, ...用户参数]
```

> console 与 process 是调试与运维的第一手工具。process.argv 在编写命令行脚本时用于读取参数；process.env 用于注入配置（如数据库密码）。注意 process.exit(code) 会**立即终止**整个进程，调用需谨慎。

**速记**：**console 管输出，process 管进程**。



#### 定时器与 queueMicrotask

**queueMicrotask**：是把回调排入**微任务队列**的全局方法，执行时机早于所有宏任务（包括定时器）。

相关全局成员：

- **setTimeout**：延时执行一次的宏任务。
- **setInterval**：周期性执行的宏任务。
- **setImmediate**：在当前轮事件循环 check 阶段执行。

```js
setTimeout(() => console.log("timeout"), 0);
setImmediate(() => console.log("immediate"));
queueMicrotask(() => console.log("microtask"));

console.log("sync");
// 输出顺序：sync → microtask → timeout / immediate（先后随环境）
```

> 微任务（queueMicrotask、Promise.then）总是先于下一轮宏任务执行。因此 queueMicrotask 中的代码会在 setTimeout(...,0) 之前运行。理解这一优先级是排查"为什么先打印这个"类问题的关键。

**速记**：queueMicrotask **排在宏任务之前**。



#### URL、TextEncoder 与 AbortController

**URL**：是 WHATWG 标准的 URL 解析构造器，比旧版 url.parse 更规范，已是全局对象。**TextEncoder 与 TextDecoder**：是字符串与 Uint8Array 互转的全局工具。**AbortController**：是原生支持的取消信号源，用于中断 fetch、定时器监听等。

```js
const url = new URL("https://example.com/path?q=1");
console.log(url.hostname); // "example.com"

const encoder = new TextEncoder();
const bytes = encoder.encode("你好");
console.log(bytes.length); // 6（UTF-8 下每个汉字 3 字节）

const controller = new AbortController();
controller.signal.addEventListener("abort", () => console.log("已取消"));
controller.abort();
```

> URL、TextEncoder、AbortController 都源自 Web 标准并已被 Node 全局化，因而能用同一套代码同时服务前端与后端。优先使用 new URL 而非字符串拼接路径，可减少路径注入与编码错误。

**速记**：**URL 解析、编码转换、取消信号**三件套。



#### structuredClone 与 Buffer

**structuredClone**：是深拷贝全局函数，基于结构化克隆算法，能正确处理 Map、Set、Date、TypedArray 等。**Buffer**：是 Node 专有的二进制数据容器（Uint8Array 的子类），用于处理文件流、网络包。

```js
const original = { list: [1, 2], date: new Date() };
const copied = structuredClone(original);
copied.list.push(3);
console.log(original.list.length); // 2，互不影响

const buf = Buffer.from("你好", "utf8");
console.log(buf); // <Buffer e4 bd a0 ...>
console.log(buf.toString("utf8")); // "你好"
```

> structuredClone 不是 JSON.parse(JSON.stringify()) 的替代品——它能拷贝函数之外的几乎所有结构，且不会因循环引用而报错，但**不能克隆函数、DOM 节点、Error 的部分信息**。二进制数据务必用 Buffer 而非普通字符串处理，否则编码错位会导致乱码。



### 定时器家族

**速记**：**structuredClone 深拷贝，Buffer 管二进制**。

#### setTimeout 与 setInterval

**setTimeout**：在至少等待 delay 毫秒后，把回调推入**定时器阶段**执行一次。**setInterval**：每隔 delay 毫秒重复执行，直到被清除。

两者均返回一个 **Timeout 对象**（Node 内部类），可用它取消：

```js
const id = setTimeout(() => {
  console.log("1 秒后执行一次");
}, 1000);

const timer = setInterval(() => {
  console.log("每 500 毫秒执行");
}, 500);

clearInterval(timer); // 停止重复
```

> setTimeout 的 delay 是**最小值而非保证值**；当事件循环繁忙时，回调会延后。delay 传 0 并不会"立刻"执行，而是进入下一轮定时器阶段。此外 setInterval 可能因前一次回调耗时过长而"堆积"，必要时改用递归 setTimeout 以错开执行。

**速记**：**setTimeout 一次，setInterval 反复**。



#### setImmediate

**setImmediate**：把回调排到**当前事件循环轮次结束时的 check 阶段**执行，等价于 setTimeout(...,0) 但语义更明确——"立即在当前轮之后"。

对比场景：

- 在 I/O 回调内部，setImmediate 总是先于 setTimeout(...,0) 执行。
- 在模块顶层，二者顺序不确定。

```js
const fs = require("fs");

fs.readFile(__filename, () => {
  setTimeout(() => console.log("timeout"), 0);
  setImmediate(() => console.log("immediate"));
  // 输出：immediate → timeout
});
```

> setImmediate 的语义是"让出当前轮、下一阶段再执行"，适合在 I/O 完成后立即继续处理。它与 process.nextTick 不同：nextTick 队列在**任何阶段之前**清空，优先级更高。

**速记**：setImmediate 落在**check 阶段**。



#### process.nextTick

**process.nextTick**：把回调放入**微任务性质的 nextTick 队列**，在当前操作完成后、事件循环继续之前立即执行，优先级高于所有定时器。

```js
console.log("a");

process.nextTick(() => console.log("nextTick"));

Promise.resolve().then(() => console.log("promise"));
setTimeout(() => console.log("timeout"), 0);

console.log("b");
// 输出：a → b → nextTick → promise → timeout
```

> nextTick 队列会在每个阶段切换前被**完全清空**，若在其中无限递归调用 process.nextTick，会阻塞事件循环、饿死 I/O。因此它适合"在事件循环继续前必须完成的清理或通知"，切勿滥用。

**速记**：nextTick**插队最快，早于微任务**。



#### 清除定时器与 Timeout 对象

**清除定时器**：通过 clearTimeout、clearInterval、clearImmediate 分别取消对应的调度；它们都接收对应方法返回的调度标识。**Timeout 对象**：setTimeout 与 setInterval 返回的是 Timer 类的实例，携带 unref、ref、close 等方法。

```js
const timeout = setTimeout(() => console.log("不会执行"), 1000);
clearTimeout(timeout); // 取消

const immediate = setImmediate(() => {});
clearImmediate(immediate);
```

> 返回的标识在浏览器与 Node 中类型不同：浏览器是数字 id，Node 是 Timeout 对象。清除时必须用**对应的 clear 方法**——clearTimeout 也能清除 setInterval 返回的标识（底层同族），但语义上仍建议配对使用。

**速记**：**clear 配 set，成对使用**。



#### unref 与 ref

**unref**：使一个定时器**不再阻止事件循环退出**——若进程中没有其他活跃任务，即使定时器未触发，Node 也会退出。**ref**：恢复其阻止退出的能力（默认行为）。

```js
const timer = setInterval(() => console.log("心跳"), 1000);
timer.unref(); // 没有别的任务时，进程直接结束，不等待心跳

// 需要它阻止退出时
timer.ref();
```

> unref 常用于"后台保活型"任务（如日志上报、健康检查）：希望它们运行，但不希望它们**单独**把进程挂起。注意 unref 之后若想恢复阻止退出，必须调用 ref；一对 unref/ref 可多次切换。



### 模块的基本认识

**速记**：**unref 不挡退出，ref 恢复**。

#### 为什么需要模块

**模块化需求**：源于早期脚本把一切塞进全局，导致的命名冲突、依赖顺序脆弱、难以维护等问题。

无模块时期的问题：

- **全局污染**：不同文件的同名变量互相覆盖。
- **依赖混乱**：脚本必须按手写顺序加载，改一处牵动全身。
- **复用困难**：无法清晰"取出一部分功能"供别处使用。

```js
// 无模块时代：依赖加载顺序，易冲突
// <script src="a.js"></script> 定义了 name
// <script src="b.js"></script> 又定义了 name，覆盖前者
```

> 模块系统把"全局共享"改为"按需导入"，让每个文件自成一个封闭空间。CommonJS 是 Node 最早采用的方案，它用同步 require 解决了服务端本地文件依赖问题——浏览器因网络延迟不适合同步加载，因此另走 ESM 路线。

**速记**：模块化**解冲突、理依赖**。



#### 每个文件就是一个模块

**文件即模块**：在 Node（CommonJS）中，每创建一个 .js 文件，该文件就被自动视为一个独立模块，拥有专属的 module 与 exports。

示例：

- a.js 中定义的顶层 const 仅在 a.js 可见。
- 想被外部使用，必须挂到 exports 或 module.exports。

```js
// math.js
function add(a, b) {
  return a + b;
}
module.exports = { add };

// main.js
const { add } = require("./math");
console.log(add(1, 2)); // 3
```

> "一个文件一个模块"是 CommonJS 的核心约定。它意味着文件之间天然隔离，导入导出是**唯一**的通信通道，从物理上杜绝了全局串味。

**速记**：**一个文件即一个模块**。



#### 模块作用域

**模块作用域**：是 Node 给每个文件包裹出的独立词法作用域，文件顶层声明的变量不会泄漏到 global，也不会进入其他文件。

验证：

- 在 a.js 写 const x = 1，b.js 访问 x 会得到 ReferenceError。
- 顶层函数同样被封装，不会成为 global 的方法。

```js
// a.js
const secret = "only in a";
// b.js 中 secret 不存在
```

> 模块作用域由"模块包装"实现：Node 把文件内容包进一个函数体，顶层声明自然变成函数内的局部声明。这是 var 声明不会污染全局的根本原因，也是与浏览器裸 script 的最大区别。



### module 对象

**速记**：**文件顶层声明不外泄**。

#### 打印 module 结构

**module 对象打印**：在任意模块中直接 console.log(module) 即可观察其字段，是理解模块系统的直接手段。

```js
// demo.js
console.log(module);
```

> 运行 node demo.js 时控制台输出的结构形如：
> Module { id: ".", path: "/project", exports: {}, parent: null, filename: "/project/demo.js", loaded: false, children: [], paths: [ ... ] }

> 打印结果中的 loaded 在模块执行完毕前为 false，执行结束变为 true；children 是它 require 过的子模块列表。parent 为 null 表示它是入口模块（也可用 require.main === module 判断，详见 CommonJS 模块化一篇的相关章节）。

**速记**：**打印 module 即可看全貌**。



#### module 的字段含义

**module 字段**：是描述模块身份、位置、导出与依赖关系的一组属性，常用字段如下。

- **id**：模块的唯一标识；入口模块为 "."，其余为解析后的绝对路径。
- **filename**：模块文件的绝对路径。
- **loaded**：布尔值，表示模块是否已编译执行完成。
- **parent**：引用本模块的父模块对象，入口模块为 null。
- **children**：本模块通过 require 加载的子模块对象数组。
- **path**：模块所在目录的绝对路径（用于向上查找 node_modules）。
- **exports**：本模块对外暴露的对象，即 require 的返回值。

```js
console.log(module.id); // "."（入口）
console.log(module.filename); // /project/demo.js
console.log(module.parent); // null
console.log(Array.isArray(module.children)); // true
```

> exports 是 module 的一个属性，这一点至关重要——后续所有导出写法都围绕它展开。children 与 parent 构成模块依赖树，可用于分析加载关系，但日常开发极少直接操作。



### exports 与 module.exports

**速记**：module**记身份、位置、导出与依赖**。

#### 两者最初指向同一对象

**初始关系**：在模块被包裹执行时，Node 令 exports 与 module.exports **指向同一个空对象**，因此对 exports 增删属性等价于修改 module.exports。

```js
console.log(exports === module.exports); // true（初始时）

exports.foo = 1;
console.log(module.exports.foo); // 1，同一对象
```

> 正因两者同源，模块内用 exports.xxx = ... 与 module.exports.xxx = ... 在"挂载属性"时效果完全一致。理解"指向同一对象"是理解后续"赋值失效"现象的前提。

**速记**：二者**初始指向同一对象**。



#### require 拿的是 module.exports

**require 返回值**：无论用 exports 还是 module.exports 操作，外部 require 拿到的始终是 **module.exports** 这个引用，而非 exports。

```js
// lib.js
exports.a = 1;
// main.js
const lib = require("./lib");
console.log(lib.a); // 1（实际来自 module.exports）
```

> 关键结论：**exports 只是指向 module.exports 的快捷变量**。当 exports 与 module.exports 仍指向同一对象时一切正常；一旦 exports 被重新赋值，它就与 module.exports 脱钩，后续改动再也影响不到返回值。

**速记**：**require 只认 module.exports**。



#### 四种常见导出写法

**导出写法**：根据要暴露单个值、多个值、类或函数，有四种惯用形式。

第一种，挂载多个属性（module.exports.xxx）：

```js
// math.js
module.exports.add = (a, b) => a + b;
module.exports.sub = (a, b) => a - b;
```

第二种，逐个挂载（exports.xxx）：

```js
exports.add = (a, b) => a + b;
exports.sub = (a, b) => a - b;
```

第三种，导出单个对象：

```js
module.exports = {
  add: (a, b) => a + b,
  sub: (a, b) => a - b,
};
```

第四种，导出类（构造函数）：

```js
class Calculator {
  add(a, b) { return a + b; }
}
module.exports = Calculator;
```

> 前两种暴露"命名空间式"多成员；第三种适合一次性导出对象；第四种适合"模块本身就是一个类"的语义。选择依据是**使用者如何消费**：require 后是要 new 一个实例，还是直接调用若干方法。

**速记**：**单值、多值、类、函数**各有所适。



#### 直接给 exports 赋值会失效

**赋值失效**：当执行 exports = 某个值 时，exports 被改指向新对象，而 module.exports 不受影响，require 拿到的仍是原 module.exports（为空对象），导致导出"失踪"。

```js
// 错误写法
exports = { add: (a, b) => a + b }; // 只改了局部变量 exports
// 正确写法
module.exports = { add: (a, b) => a + b };
```

```js
// 验证
// lib.js
exports = { value: 1 }; // 失效
// main.js
console.log(require("./lib")); // {} 空对象
```

> 永远用 module.exports = ... 做"整体赋值"，用 exports.xxx = ... 做"属性挂载"。口诀：**整体导出找 module.exports，局部挂载用 exports 点属性**；一旦 exports 被等号改写，它就脱离了返回值。



### require 的导入

**速记**：**只改属性，别改指向**。

#### 核心模块、文件模块、第三方模块

**模块分类**：按来源把被加载模块分为三类，require 的查找策略各异。

- **核心模块**：Node 内置（如 fs、path、http），编译进二进制，加载最快，优先匹配。
- **文件模块**：以 ./、../ 或 / 开头的相对或绝对路径，指向具体文件或目录。
- **第三方模块**：非路径、非内置的裸名（如 lodash），从 node_modules 向上查找。

```js
const fs = require("fs"); // 核心模块
const myLib = require("./myLib"); // 文件模块
const lodash = require("lodash"); // 第三方模块
```

> 同名冲突时优先级为**核心模块 > 文件模块（路径明确）> 第三方模块**。核心模块不可被同名文件覆盖，这是出于安全与性能的设计。

**速记**：**核心、文件、第三方**查找各异。



#### 省略扩展名时的查找顺序

**扩展名查找**：require 对省略扩展名的文件模块，按固定顺序补全并尝试定位。

查找顺序为：

- 先当作**文件**查找：依次补 .js、.json、.node。
- 若均不存在，当作**目录**查找：加载其 package.json 的 main，否则 index.js。

```js
// require("./config") 实际可能解析为：
// 1. ./config （文件本身，极少）
// 2. ./config.js
// 3. ./config.json
// 4. ./config.node
// 5. ./config/index.js（目录）
```

> 省略扩展名是 Node 的便利特性，但要注意**性能与歧义**：每少写一个扩展名，Node 就要多做几次文件系统探测。生产代码建议写出 .js 以明确意图、减少探测。

**速记**：补全顺序**先 js、后 json、再 node**。



#### require 拿的是引用还是拷贝

**引用语义**：require 返回的是 module.exports 的**引用（同一对象）**，而非深拷贝；对导出对象属性的修改会在所有导入方之间共享。

```js
// store.js
module.exports = { count: 0 };
// a.js
const store = require("./store");
store.count += 1;
// b.js
const store2 = require("./store");
console.log(store2.count); // 1，同一份引用
```

> 这印证了模块缓存机制：同一模块只执行一次，导出对象在进程内唯一。若导出的是基本类型（如 module.exports = 42），require 拿到的是该值的拷贝式绑定；但对象、数组、类实例始终是共享引用。



### Node 对模块的包装

**速记**：require 拿到的是**引用而非拷贝**。

#### 模块被包裹进函数

**包裹执行**：Node 把模块源码套进形如 function (exports, require, module, __filename, __dirname) { ... } 的函数中，再调用它以运行你的代码。

伪代码示意：

```js
const wrapper = function (exports, require, module, __filename, __dirname) {
  // 你的文件内容被放在这里
};
```

> 包裹是"文件即模块、拥有独立作用域"的底层实现。正因为代码处在函数体内，顶层声明才是局部变量，而不是全局变量。

**速记**：模块**包在函数里执行**。



#### 五个参数的来源

**五个参数**：exports、require、module、__filename、__dirname 全部由 Node 在调用包裹函数时传入，不是语言关键字，也不是 global 成员。

参数含义：

- **exports**：初始指向 module.exports 的空对象。
- **require**：用于加载其他模块的函数。
- **module**：当前模块对象。
- **__filename**：当前文件绝对路径。
- **__dirname**：当前文件目录绝对路径。

```js
// 文件内可直接使用，因为它们是函数形参
console.log(typeof require); // "function"
console.log(typeof __dirname); // "string"
```

> 这五个参数"凭空可用"的谜底就是包裹函数：它们是形参，由 Node 在编译阶段注入实参。也正因为如此，在 REPL 或 eval 中它们不存在。

**速记**：**exports、require、module、__filename、__dirname** 五参注入。



#### var 声明不会成为全局变量

**var 隔离**：由于文件被函数包裹，顶层 var、let、const、function 声明都落在函数作用域，不会泄漏到 global。

```js
// demo.js
var name = "why";
function hello() {}
console.log(global.name); // undefined
console.log(global.hello); // undefined
```

> 对比浏览器中裸 script 的顶层 var 会变成 window 属性，Node 因模块包裹而天然隔离。这是 Node 不直接污染全局的关键，也使同名变量在不同文件间互不干扰。

**速记**：**被函数包裹，故不外泄**。
