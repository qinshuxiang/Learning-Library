## Node 简介与环境搭建

### Node 的认识

#### 官方定义与发布背景

**Node.js**：是 **Ryan Dahl** 于 **2009 年**发布的服务端 JavaScript 运行环境，官方定义强调它是"基于 Chrome V8 引擎的 JavaScript 运行时"。

- **发布者**：Ryan Dahl 在 2009 年 JSConf 首次公开 Node。
- **设计动机**：提供事件驱动、非阻塞 IO 的轻量服务端模型。
- **治理**：现由 OpenJS 基金会长期维护。

```bash

# Node.js is a JavaScript runtime built on Chrome's V8 JavaScript engine.

```

> **V8 引擎**来自 Chrome，Node 借用了它，但去掉 BOM、DOM，改接操作系统能力，所以"Node 用浏览器引擎，但不是浏览器"。



#### 运行时不是语言也不是框架

**运行时**：是**执行代码的环境**，既不是新语言，也不是开发框架。

- **语言（JavaScript）**：即 ECMAScript，Node 与浏览器都用同一套。
- **框架（如 Express）**：构建在运行时之上的代码库，需额外安装。
- **运行时（Node）**：让 JavaScript 跑起来的底层程序，框架依赖它存在。

```js
const sum = (a, b) => a + b;
console.log(sum(1, 2)); // 3
```

> **语言仍是 JavaScript**，Node 只是换宿主、多了系统 API；框架是 Node 之上的可选封装，并非必需。



#### Node 与浏览器 JavaScript 的分野

**Node 与浏览器 JavaScript**：共享同一套 **ECMAScript** 核心，差异只在**宿主能力**。

- **ECMAScript 核心**：变量、函数、Promise、数组方法，两者通用。
- **浏览器宿主 API**：window、document、BOM、DOM、fetch。
- **Node 宿主 API**：fs、net、http、process 等系统模块。

```js
// 浏览器可用、Node 没有：document.getElementById("app");
// Node 可用、浏览器没有：const fs = require("fs");
```

> 只用到语言核心的代码两端都能跑；一旦调用宿主 API，就只能在对应环境运行。



### Node 与 JavaScript 的关系

#### V8 执行 ECMAScript

**V8**：是 Google 开发的 **JavaScript 引擎**，把 **ECMAScript 代码**即时编译为机器码执行。

- **性能**：JIT 把热点代码优化为原生机器码。
- **标准**：完整实现 ECMAScript 规范。
- **边界**：只管"算"，不提供文件、网络等 IO。

```js
const list = [3, 1, 2].map((n) => n * 2).sort((a, b) => a - b);
console.log(list); // [2, 4, 6]
```

> V8 是"**只算不算 IO**"的引擎，Node 的 IO 来自 libuv 等底层库，而非 V8。



#### 浏览器提供 BOM、DOM，Node 提供 fs、net、http

**宿主 API**：是运行环境在 ECMAScript 之上额外提供的接口，浏览器与 Node 各自不同。

- **浏览器**：提供 **BOM**（window、location）、**DOM**（document、节点）。
- **Node**：提供 **fs**（文件系统）、**net**（网络）、**http**（服务）、**process**（进程）。

```js
const http = require("http");
console.log(typeof http.createServer); // "function"
```

> **浏览器面向界面**，**Node 面向操作系统**；"在 Node 操作 DOM"或"在浏览器用 fs"均不存在。



#### 同一份 ECMAScript，宿主 API 不同

**跨环境代码**：只使用 ECMAScript 核心、不依赖任一宿主 API 的代码，可在两端通用。

- **可移植**：纯计算、数据结构、Promise、正则、类。
- **不可移植**：浏览器专属 DOM 操作、Node 专属 fs 操作。
- **适配**：用 typeof window 等判断屏蔽宿主差异。

```js
function fibonacci(n) {
  let a = 0, b = 1;
  for (let i = 0; i < n; i++) [a, b] = [b, a + b];
  return a;
}
```

> 写**库**时尽量只用 ECMAScript 核心，可同时服务两端；写**应用**时再按宿主引入对应 API。



### Node 能做什么

#### 命令行工具与 Web 服务器

**命令行工具与 Web 服务器**：是 Node 最常见的两类用途，分别借 process 与 http 模块实现。

- **CLI 入口**：node xxx.js 启动，参数从 process.argv 获取。
- **服务器**：http.createServer 创建服务并 listen 端口。
- **异步非阻塞**：单线程即可应对大量并发连接。

```js
const http = require("http");
http.createServer((req, res) => {
  res.end("来自 Node 服务器的响应");
}).listen(3000, () => console.log("http://localhost:3000"));
```

> Node 原生即可做服务器，**无需框架**；生产常用 Express、Koa 简化路由与中间件。



#### 中间层 BFF 与桌面应用

**BFF**：是位于前端与后端之间的"**为前端服务的后端**"，Node 因与前端同语言而适合。

- **数据聚合**：合并多个后端接口，减少前端请求。
- **协议转换**：把内部 RPC 转为前端友好的 REST。
- **桌面应用**：Electron 把 Chromium 与 Node 包进原生窗口。

```js
async function getUserPage(userId) {
  const profile = await fetch(`/api/profile/${userId}`);
  const orders = await fetch(`/api/orders/${userId}`);
  return { ...profile, recentOrders: orders.slice(0, 5) };
}
```

> 选 Node 做 BFF 的最大优势是**前后端同构**，前端工程师用同一门 JavaScript 贯通界面与中间层。



#### 工程化、构建与脚本

**构建工具**：是用 Node 编写的、把源码转译为产物的程序，是现代前端工程化基石。

- **打包与转译**：webpack、babel、swc 处理模块与语法。
- **开发服务器**：vite 提供热更新与代理。
- **爬虫与脚本**：自动化抓网页、批处理文件。

```bash
npm create vite@latest my-app
cd my-app && npm install && npm run dev
```

> 前端工程化几乎**完全建立在 Node 之上**，即便只写浏览器代码也离不开它的包管理与构建链路。



### Node 的安装

#### macOS 用 Homebrew 安装

**Homebrew 安装**：是 macOS 上通过 brew 安装 Node 的标准做法，自动处理路径与依赖。

- **安装 Homebrew**：若未装，先执行其官方安装命令。
- **安装 Node**：brew install node。
- **验证**：node -v 查看版本。

```bash
brew install node       # 最新版
brew install node@20    # 指定大版本
```

> Homebrew 安装后，Node 位于 /opt/homebrew/bin（Apple 芯片）或 /usr/local/bin（Intel），已在 PATH 中。



#### 官方 pkg 安装包

**pkg 安装包**：是 Node 官网提供的图形化安装程序，双击按向导完成。

- **来源**：nodejs.org 下载对应 macOS 版本。
- **位置**：默认装入 /usr/local，node 与 npm 自动可用。
- **适用**：偏好图形界面的用户。

```bash
node -v
npm -v
```

> pkg 装到系统目录，**与版本管理器不冲突但路径不同**；若改用 nvm，注意 shell 配置中 PATH 先后。



#### node -v 与 npm -v 验证

**验证安装**：通过 node -v 与 npm -v 打印版本号，确认运行时与包管理器就绪。

- **node -v**：Node 运行时版本，证明 node 可用。
- **npm -v**：npm 版本，证明包管理器随 Node 一并安装。

```bash
node -v   # 例如 v20.11.0
npm -v    # 例如 10.2.4
```

> 若提示 **command not found**，多半 PATH 未含 Node 路径或安装失败；检查 .zshrc 的 PATH，或重开终端使其生效。



### 版本管理工具

#### nvm 的安装与常用命令

**nvm**：是 macOS 与 Linux 管理 Node 版本的事实标准，通过 shell 函数拦截 node 调用。

- **nvm install 版本号**：安装指定版本。
- **nvm use 版本号**：当前 shell 切换版本。
- **nvm ls**：列出已安装并标出当前项。
- **nvm alias default 版本号**：设定默认版本。

```bash
nvm install 20
nvm use 20
nvm alias default 20
```

> nvm **每 shell 生效**：nvm use 只影响当前终端，关闭即失效，故用 **nvm alias default** 固定默认版本很关键。



#### n 与 fnm

**n 与 fnm**：是 nvm 的两种替代，安装与使用哲学不同。

- **n**：npm install -g n 安装，交互式选版本，逻辑简单。
- **fnm**：独立二进制，启动快、跨平台，支持按目录自动切换。

```bash
npm install -g n && n 20
fnm install 20 && fnm use 20
```

> **n 依赖已存在的 Node**（它自己用 Node 跑），**fnm 不依赖 Node** 即可运行；无版本管理需求时直接 Homebrew 装单版本更简单。



#### .nvmrc 文件与 lts 代号

**.nvmrc**：是项目根目录的版本约定文件，写入期望的 Node 版本号，配合 nvm use 对齐。

- **内容**：可写具体版本（20.11.0）或代号（lts/*）。
- **lts 代号**：LTS 的元素名代号（如 Argon），用 lts/名称 引用。
- **自动切换**：配合 nvm 自动加载脚本，进目录即切换。

```bash
echo "20" > .nvmrc
nvm use   # 读取 .nvmrc 并使用对应版本
```

> 把 **.nvmrc** 提交进版本库，能让团队用上**一致**的 Node 版本，避免"在我机器上能跑"。



### Node 的版本策略

#### 偶数 LTS、奇数 Current

**LTS 与 Current**：是 Node 并行两条发布线——**LTS 求稳、Current 求新**。

- **LTS（偶数）**：每年十月发布，约 30 个月维护期，适合生产。
- **Current（奇数）**：含最新特性，但**不长期维护**，仅作试验。
- **升级路径**：奇数特性若稳定，会在下一偶数 LTS 沉淀。

> **偶数稳定、奇数尝鲜**是共识；把奇数用于生产等于主动承担"随时停止维护"的风险。



#### Active LTS 与 Maintenance LTS

**LTS 两阶段**：**Active LTS（活跃支持）** 与 **Maintenance LTS（维护支持）**，力度递减。

- **Active LTS**：积极修缺陷、合并非破坏性更新，约 18 个月。
- **Maintenance LTS**：仅修安全与严重缺陷，约 12 个月，直至终止。
- **终止（EOL）**：到终止日不再提供任何更新。

```bash

# Active LTS  → 功能与安全更新

# Maintenance → 仅安全与严重修复
```

> 优先选 **Active LTS**：既稳定又仍收功能更新；**Maintenance LTS** 只适合无法立即升级的遗留系统续命。



#### 生产环境该选哪个

**生产选型原则**：一律用 **Active 或 Maintenance LTS 中的偶数版本**，避开奇数 Current。

- **新项目**：选当前 **Active LTS** 偶数大版本。
- **老项目**：至少停留 **Maintenance LTS** 并规划升级。
- **禁止**：把奇数 Current 用于对外服务。

```bash
node -v   # 生产应形如 v20.x.x 或 v22.x.x（偶数）
```

> 速记：**生产用偶数 LTS，开发可试奇数 Current，绝不让奇数进生产**。



### 第一个 Node 程序

#### 命令行运行 node xxx.js

**node 命令**：是把某 JavaScript 文件交给 V8 执行的最简方式。

- **基本形式**：node 文件名（node app.js）。
- **内联执行**：node -e "代码" 直接跑一行。
- **退出**：脚本跑完自动退出，也可 process.exit() 主动退。

```js
const greet = (name) => `你好，${name}`;
console.log(greet("Node"));
// node app.js → 你好，Node
```

> 与浏览器不同，Node 的 **console.log 输出到终端**而非开发者工具；脚本跑完进程即结束。



#### 最小 HTTP 服务器

**最小 HTTP 服务器**：用 Node 原生 http 模块几行代码即可对外提供响应。

- **创建服务**：http.createServer 传入请求处理函数。
- **写入响应**：res.writeHead 设状态码与头，res.end 返回正文。
- **监听端口**：server.listen 指定端口并回调确认。

```js
const http = require("http");
http.createServer((req, res) => {
  res.writeHead(200, { "Content-Type": "text/plain; charset=utf-8" });
  res.end("这是我的第一个 Node 服务器");
}).listen(8080, () => console.log("http://localhost:8080"));
```

> 本质：**请求进来 → 回调处理 → 返回响应**；所有 Web 框架都建立在这个最简模型上。



### REPL 交互式环境

#### 进入与退出

**进入与退出 REPL**：开始或结束交互式调试的最基本操作。

- **进入**：终端输入 node（不带文件名）。
- **退出（命令）**：输入 .exit 回车。
- **退出（快捷键）**：Control + D。

```bash
$ node
> console.log("在 REPL 中")
在 REPL 中
> .exit
```

> 进入后提示符变 **大于号**，每输入一行立即求值；**REPL 持续等待输入，脚本一次跑完即退出**。



#### 常用命令与下划线变量

**REPL 点命令与下划线**：点命令管理会话，下划线保存上次结果。

- **.help / .save / .load / .exit**：查看帮助、存会话、载文件、退出。
- **下划线**：保存上一次表达式结果，仅 REPL 有效。
- **连续运算**：可基于下划线链式推导。

```bash
> 10 * 2
20
> _ + 5
25
```

> 下划线是 REPL 专属便利，**不属于 ECMAScript 标准**，不要写进需跨环境运行的脚本。



### Node 的优缺点与适用场景

#### 单线程异步的长处

**单线程异步**：是 Node 用**一个主线程 + 事件循环**支撑海量并发连接的设计，资源占用低、吞吐高。

- **高并发 IO**：单线程即可应对数万连接，无需每连接开线程。
- **低开销**：无线程切换与锁竞争成本。
- **模型统一**：以回调、Promise、async/await 表达异步。

```js
const urls = ["https://a.com", "https://b.com"];
Promise.all(urls.map((u) => fetch(u))).then(() => console.log("全部完成"));
```

> **单线程不等于低性能**：正因无线程切换开销，Node 在 IO 密集场景比"一连接一线程"更省资源。



#### CPU 密集型是短板

**CPU 密集短板**：大量同步计算会**长时间占用唯一主线程**，导致其他请求被阻塞。

- **阻塞事件循环**：超长循环让后续 IO 回调迟迟不执行。
- **无法并行**：单线程本身不能利用多核计算。
- **缓解**：重计算交 worker_threads 或子进程，或拆小任务。

```js
server.on("request", () => {
  // 跑 10 秒循环期间，整个进程无法响应其他请求
  heavyCompute();
});
```

> **IO 等待不阻塞，计算执行才阻塞**；Node 擅长"等"（网络、磁盘），怕"算"（加密、压缩、遍历）。



#### 适用与不适用场景清单

**场景清单**：判断"该不该用 Node"的速查表，按 IO 与 CPU 比重取舍。

- **适用**：Web API、网关、BFF、实时通信、前后端同构项目。
- **不适用**：大规模图像处理、科学计算、视频编码等 CPU 密集计算。
- **经验法则**：IO 多算少选 Node；算多 IO 少选 Go/Rust/Python。

```bash

# IO 多、计算少 → 选 Node

# 计算多、IO 少 → 选 Go / Rust / Python 等
```

> 速记：**多 IO、少计算，Node 上；多计算、少 IO，换语言**。场景匹配比语言优劣更决定成败。
