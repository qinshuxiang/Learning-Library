## fs 文件系统基础

### fs 模块的导入与三大 API 风格

#### fs 模块的导入方式

**fs 模块**：是 Node.js 内置的文件系统模块，封装了读写、查看、删除、重命名等磁盘操作，随运行时发布，无需 npm 安装，通过 require 直接引入即可使用。

- 完整引入写法为 const fs = require("fs")，得到的对象同时包含回调风格与同步风格方法。
- Promise 风格挂载在该对象的 promises 属性上，例如 fs.promises.readFile，也可独立用 const fsp = require("fs/promises") 取得。
- 两种 Promise 形式的接口完全等价，区别只在入口；其余 options、返回值语义一致。
- fs 与 path 同为运行时预置能力，文件操作为何常配 path 见第 10 篇路径模块。

```js
const fs = require("fs");
const fsp = require("fs/promises");

console.log(typeof fs.readFile);           // function（回调风格）
console.log(typeof fs.readFileSync);       // function（同步风格）
console.log(typeof fs.promises.readFile);  // function（Promise 风格）
```

> fs 的回调与同步方法同名、仅差 Sync 后缀；Promise 版本名字相同但不带 Sync，位于 promises 下。混用三种形式不会冲突，但同一处逻辑最好只用一种，避免风格交错难以维护。

**速记**：fs **直引内置**，Promise 在 **promises 或 fs/promises**。



#### 三大 API 风格对照

**三种风格**：fs 为同一能力提供回调、同步、Promise 三类接口，三者在返回方式、阻塞性与错误处理上各成一套模型。

- **回调风格**：以 callback 作为最后一个参数收尾，方法内部完成 IO 后用回调交付结果，例如 fs.readFile(path, options, callback)。
- **同步风格**：方法名以 Sync 结尾，直接 return 结果而非走回调，例如 readFileSync(path, options)。
- **Promise 风格**：挂在 fs.promises，返回 Promise，例如 fs.promises.readFile(path, options)，可用 await 取结果。

```js
const fs = require("fs");
const path = require("path");

// 目标文件：与脚本同目录的 note.txt
const file = path.join(__dirname, "note.txt");

// 回调风格
fs.readFile(file, "utf8", (err, data) => {
  if (err) throw err;
  console.log("回调风格读到：", data);
});

// 同步风格
const syncData = fs.readFileSync(file, "utf8");
console.log("同步风格读到：", syncData);

// Promise 风格
fs.promises.readFile(file, "utf8").then((data) => {
  console.log("Promise 风格读到：", data);
});
```

- 回调风格无阻塞但需层层嵌套；同步风格代码最直白却会卡住事件循环；Promise 风格既非阻塞又便于用 await 线性书写。
- 三者的编码、错误对象语义一致，差异只在"如何拿到结果"这一道环节。

> 选型上：库内部或简单脚本可用同步风格省事；对外服务、并发场景优先回调或 Promise 风格，避免阻塞主线程。三种风格不要在同一函数里混写，否则错误处理路径会分裂成两路。

**速记**：回调**嵌套不阻塞**、同步**直白会卡**、Promise **await 最清爽**。



#### 同步风格会阻塞事件循环

**同步阻塞**：以 Sync 结尾的方法在系统调用返回前不返回，期间主线程被独占，事件循环无法派发任何定时器、IO 或请求回调。

- 调用进入内核等待磁盘，函数栈一直挂着，后续 JavaScript 全部排队等待。
- 文件越大、磁盘越慢，阻塞时长越长，与第 8 篇所述 CPU 密集任务占用单线程同理。
- 仅适合启动配置加载、一次性脚本收尾等"无需并发响应"的场合。

> 同步方法并非"错误"，而是"不适用于并发现场"。在 HTTP 请求处理函数里写 readFileSync，等于让所有用户排队等这一次的磁盘读取，单线程优势被彻底抵消。

> [!WARNING]
> **警告内容**：在服务器请求处理、定时任务等并发路径上调用 readFileSync、writeFileSync 等同步方法，会令事件循环停滞，表现出来就是接口大面积超时。凡处在"可能被多个请求同时触发"的代码，务必改用回调或 Promise 风格。

**速记**：Sync **占主线程直到磁盘回**。



### 回调风格与错误优先约定

#### 错误优先回调 error-first callback

**错误优先回调**：是 Node 回调的约定签名，回调的第一个参数固定为 err，第二个及之后才是业务结果，成功时 err 为 null。

- 完整签名为 callback(err, result) 或更具体的 callback(err, data)，err 永远在第一位。
- 成功时第一参数为 null（或 undefined），失败时第一参数是 Error 实例，其余参数无意义。
- 这一约定让"先判错再取数"成为统一的异步消费姿势，被 fs、net、child_process 等广泛沿用。

```js
const fs = require("fs");

fs.readFile("/不存在的文件.txt", "utf8", (err, data) => {
  // err 在第一位：null 表示成功，Error 表示失败
  if (err) {
    console.log("出错：", err.message);
    return;
  }
  console.log("内容：", data);
});
```

> 不要想当然认为"回调的第二参才是重点"就忽略第一位。错误优先的精髓正是把 err 前置，调用方无论成功失败都先看到它，从而统一判错。漏判 err 会让异常在回调里静默吞掉。

**速记**：回调**第一位永远是 err**。



#### Node 风格签名与判 err 习惯

**判 err 习惯**：消费回调时必须在函数体开头检查 err，非 null 即视为失败并提前 return 或抛出，切勿在 err 存在时继续读取后续参数。

- 典型结构是先写 if (err) { 处理; return; }，再使用业务数据。
- 即使"确信不会出错"，也应判 err，否则生产环境偶发失败时程序会带着 undefined 数据继续跑。
- 判错后若需上报，应 return 或 throw，避免处理分支与成功分支都执行。

```js
const fs = require("fs");

fs.stat("/some/path", (err, stats) => {
  if (err) {
    console.error("获取信息失败：", err.code);
    return; // 失败即退出，不再使用 stats
  }
  console.log("大小：", stats.size);
});
```

> 回调风格里没有 try/catch 能兜住异步错误：错误通过 err 参数传递，而非抛出到同步栈。因此"判 err"是回调风格唯一正确的错误捕获方式，不能用同步的 try 包住异步回调体。

**速记**：回调**先 if(err) 再取数**。



### 文件读取 readFile

#### readFile 默认返回 Buffer

**默认返回 Buffer**：fs.readFile 在未指定编码时，回调的 data 参数是一个 Buffer（二进制字节序列），适合图片、压缩包等非文本文件。

- 完整签名为 fs.readFile(path, options, callback)，options 省略或不含 encoding 时返回 Buffer。
- Buffer 是 Node 表示原始字节的对象，可 toString 转文本、可写盘、可做二进制拼接。
- 文本与二进制都先以 Buffer 落地，指定编码只是额外做了一次解码。

```js
const fs = require("fs");
const path = require("path");

const file = path.join(__dirname, "image.png");

fs.readFile(file, (err, data) => {
  if (err) throw err;
  console.log(Buffer.isBuffer(data)); // true
  console.log(data.length);           // 字节数
});
```

> Buffer 不等同于字符串：直接拼接 Buffer 与字符串会得到意外结果，需先 toString 指定编码。读二进制文件时务必保留 Buffer，不要误加 utf8，否则内容会被错误解码成乱码。

**速记**：不指定编码 **拿到 Buffer 字节**。



#### 指定 utf8 编码返回字符串

**utf8 解码**：给 options 传入 "utf8"（或等价别称 "utf-8"），fs.readFile 会在内部把 Buffer 按 UTF-8 解码成 JavaScript 字符串，回调 data 即为文本。

- 完整写法为 fs.readFile(path, "utf8", callback)，编码字符串作为 options 的位置参数直接给出。
- 也可写成对象形式 fs.readFile(path, { encoding: "utf8" }, callback)，语义相同。
- 拿到的是普通字符串，可直接打印、正则、JSON.parse，无需再手动 toString。

```js
const fs = require("fs");
const path = require("path");

const file = path.join(__dirname, "note.txt");

fs.readFile(file, "utf8", (err, data) => {
  if (err) throw err;
  console.log(typeof data); // string
  console.log(data);
});

// 等价对象写法
fs.readFile(file, { encoding: "utf8" }, (err, data) => {
  if (err) throw err;
  console.log(data);
});
```

> 编码传错别称不会报错但会解码异常：始终用 "utf8" 这一标准写法，避免自造方言。若文件真实编码非 UTF-8（如 GBK），需用 iconv-lite 等库转换，fs 自身只认 UTF-8 家族。

**速记**：传 **utf8 即获字符串**。



#### 读取不存在文件报 ENOENT

**ENOENT 错误**：当 path 指向的文件不存在或无权限时，回调的 err 为非 null，其 code 字段为 ENOENT（Error NO ENTry），表示找不到该路径。

- 失败不会返回数据，data 为 undefined，必须先判 err 再使用。
- err.code 是字符串常量，可据其值区分"不存在"与"无权限"（EACCES）等情形。
- 该行为对 readFile、stat、unlink 等多数读类方法一致。

```js
const fs = require("fs");
const path = require("path");

const file = path.join(__dirname, "missing.txt");

fs.readFile(file, "utf8", (err, data) => {
  if (err) {
    console.log(err.code); // ENOENT
    return;
  }
  console.log(data);
});
```

> ENOENT 是"路径层面找不到"，与文件内容错误无关。若用相对路径却总报 ENOENT，多半是相对基准不是脚本目录（见本篇末段路径约定），而非文件真不存在。调试时先打印 resolve 后的绝对路径确认落点。

**速记**：文件不在 **err.code 是 ENOENT**。



### 文件写入 writeFile 与追加 appendFile

#### writeFile 默认覆盖行为

**默认覆盖**：fs.writeFile 在目标文件已存在时会清空原内容再写入，整体替换而非保留旧数据，与"追加"语义相反。

- 完整签名为 fs.writeFile(file, data, options, callback)，省略 options 即默认覆盖写。
- 若目标文件不存在，则自动创建新文件后再写入。
- 写入是"整文件替换"：原内容无论多长都会被新 data 顶替。

```js
const fs = require("fs");
const path = require("path");

const file = path.join(__dirname, "out.txt");

fs.writeFile(file, "第一行内容", (err) => {
  if (err) throw err;
  console.log("写入完成");
});

// 再次写入会覆盖上一行
fs.writeFile(file, "新内容", (err) => {
  if (err) throw err;
  console.log("已覆盖");
});
```

> 覆盖是 writeFile 的默认且最易误用之处：在循环或并发里反复 writeFile 同一文件，后写会吃掉先写。需要保留历史务必改用 a 标志或 appendFile（见本模块末段）。

**速记**：writeFile **默认整文件覆盖**。



#### flag 选项 w a wx

**flag 选项**：通过 options 的 flag 字段可切换写模式，w 表示覆盖写、a 表示追加写、wx 表示"存在则失败"，三者覆盖不同写入语义。

- **w**（默认）：打开用于写入，文件存在则截断（清空），不存在则创建。
- **a**：打开用于追加，每次写入都定位到文件末尾，原内容保留。
- **wx**：以 w 方式打开但要求文件不存在，若已存在则失败并报 EEXIST，用于防意外覆盖。
- flag 还可取 r、r+、ax 等，本篇仅列与写相关的基础三项。

```js
const fs = require("fs");
const path = require("path");

const file = path.join(__dirname, "log.txt");

// 覆盖（等同不写 flag）
fs.writeFile(file, "覆盖", { flag: "w" }, (err) => {
  if (err) throw err;
});

// 追加
fs.writeFile(file, "追加一行\n", { flag: "a" }, (err) => {
  if (err) throw err;
});

// 仅当文件不存在才创建写入，已存在则报 EEXIST
fs.writeFile(file, "排他写", { flag: "wx" }, (err) => {
  if (err) console.log(err.code); // EEXIST
});
```

> wx 是"排他创建"的防护：在需要先确认文件为新建的场景（如写临时锁文件）能避免覆盖他人数据。注意它只在"打开"这一刻判存在，打开成功后别的进程仍可能介入，属轻量防护而非强锁。

**速记**：flag **w 覆盖、a 追加、wx 排他**。



#### 写入对象需先序列化、目录必须已存在

**写入前置条件**：fs.writeFile 只接受字符串或 Buffer 作为 data，写入普通对象会报错；且目标所在目录必须已存在，方法不会自动建目录。

- data 为对象时须先 JSON.stringify 转成字符串，否则得到 [object Object] 或异常。
- 目标目录不存在会报 ENOENT，写文件前需确保父目录存在（建目录留待第 12 篇）。
- 写入数字、布尔等也会先被转字符串；二进制则用 Buffer。

```js
const fs = require("fs");
const path = require("path");

const file = path.join(__dirname, "data.json");

const obj = { name: "node", version: 20 };
// 必须先序列化
fs.writeFile(file, JSON.stringify(obj, null, 2), "utf8", (err) => {
  if (err) throw err;
  console.log("对象已写入");
});
```

> 写入"目录不存在"的报错与"文件不存在"同为 ENOENT，但含义相反：前者是父目录缺失，后者是文件缺失。若要把文件放进新建子目录，应先用 mkdir 准备目录（第 12 篇详解），writeFile 自身不负责建目录。

**速记**：写对象 **先 stringify**，目录 **须先存在**。



#### appendFile 与 writeFile 配 a 的等价

**追加等价**：fs.appendFile 本质是以 a 模式调用写入，与 fs.writeFile 配 flag 为 a 完全等价，都保证新内容接到文件末尾而不破坏旧内容。

- 完整签名为 fs.appendFile(path, data, options, callback)，语义等同 fs.writeFile(path, data, { flag: "a" }, callback)。
- 二者在目标不存在时都会创建文件，在存在时都追加到末尾。
- 选择上：语义清晰优先 appendFile，需在同一 options 里混合其它模式时可用 writeFile 配 flag。

```js
const fs = require("fs");
const path = require("path");

const file = path.join(__dirname, "log.txt");

// 两种写法效果一致：都追加到末尾
fs.appendFile(file, "来自 appendFile\n", "utf8", (err) => {
  if (err) throw err;
});

fs.writeFile(file, "来自 writeFile+a\n", { flag: "a" }, (err) => {
  if (err) throw err;
});
```

> appendFile 是 writeFile 在 a 模式下的"语法糖"，不存在性能或行为差异。不要同时用二者往同一文件高频交替写而期待顺序可控——并发追加的交错由操作系统决定，关键日志应加序号或加锁。

**速记**：appendFile **等于 writeFile 配 a**。



### 文件信息 stat 与 lstat

#### stats 常用字段 isFile isDirectory size mtime birthtime

**stats 对象**：fs.stat 回调的第二个参数是 fs.Stats 实例，携带文件类型、大小、时间等元信息，通过其方法字段判断属性，不直接读盘内容。

- **isFile 方法**：返回布尔，true 表示这是一个普通文件而非目录或设备。
- **isDirectory 方法**：返回布尔，true 表示这是一个目录。
- **size 字段**：文件字节数，目录的 size 不代表其内容总大小，仅表示目录项本身。
- **mtime 字段**：最近修改时间（Date 对象），内容变更会更新。
- **birthtime 字段**：创建时间（Date 对象），部分平台可能回退为修改时间。
- 另有 atime（访问时间）、ctime（状态变更时间）等，按需取用。

```js
const fs = require("fs");
const path = require("path");

const file = path.join(__dirname, "note.txt");

fs.stat(file, (err, stats) => {
  if (err) throw err;
  console.log(stats.isFile());      // true
  console.log(stats.isDirectory()); // false
  console.log(stats.size);          // 字节数
  console.log(stats.mtime);         // 最近修改时间
  console.log(stats.birthtime);     // 创建时间
});
```

> size 对目录无意义：它只反映目录项占用的元数据大小，不等于其下文件总和。要判断"是否为文件再读取"，务必先 isFile() 判型，别仅凭 size 是否为 0 推断内容，空文件 size 也为 0。

**速记**：stats **isFile/isDirectory/size/mtime/birthtime**。



#### stat 跟随符号链接而 lstat 不跟随

**跟随差异**：fs.stat 会解析路径上的符号链接、返回其指向目标的信息；fs.lstat 则停留在符号链接本身，返回链接自身的信息，二者仅在遇到符号链接时才不同。

- 完整签名 fs.stat(path, options, callback) 与 fs.lstat(path, options, callback)，参数一致。
- 对普通文件或目录，stat 与 lstat 返回内容相同，因为无链接可跟。
- 对符号链接，stat 暴露目标（如目标是文件则 isFile 为真），lstat 暴露链接（isSymbolicLink 为真）。
- 想知道"这是否就是个链接"时用 lstat，想知道"链接指向的东西"时用 stat。

```js
const fs = require("fs");
const path = require("path");

const link = path.join(__dirname, "note.link"); // 假设是指向 note.txt 的符号链接

fs.lstat(link, (err, lstats) => {
  if (err) throw err;
  console.log(lstats.isSymbolicLink()); // true：停留在链接本身
});

fs.stat(link, (err, stats) => {
  if (err) throw err;
  console.log(stats.isFile()); // true：跟随到目标 note.txt
});
```

> 误用 stat 去判链接类型会得到目标类型，从而"看不见"链接存在——若逻辑依赖区分链接与普通文件（如防循环遍历），必须用 lstat。本篇不展开目录遍历，符号链接的批量处理见第 12 篇进阶。

**速记**：stat **跟链接看目标**，lstat **停链接看自身**。



### 删除重命名、文件描述符与错误处理实践

#### fs.unlink 删除文件与删除不存在的错误

**unlink 删除**：fs.unlink 用于删除一个文件（非目录），成功后文件从磁盘移除，无"回收站"中转，删除即不可恢复。

- 完整签名为 fs.unlink(path, callback)，只删文件、不递归删目录。
- 目标不存在时报 ENOENT，与读取缺失文件同源。
- 删除目录需用 rmdir 或 rm（第 12 篇），unlink 对目录会报 EISDIR 或 EPERM。

```js
const fs = require("fs");
const path = require("path");

const file = path.join(__dirname, "to-delete.txt");

fs.unlink(file, (err) => {
  if (err) {
    console.log(err.code); // 不存在则为 ENOENT
    return;
  }
  console.log("已删除");
});
```

> unlink 名字源自 Unix 的"解除链接"语义：它解除文件名到 inode 的引用，引用归零才真正释放空间。因此对硬链接、正被打开的文件，删除行为涉及底层引用计数，本篇不深究，记住"它只删文件、删目录会报错"即可。

**速记**：unlink **删文件不删目录，不在则 ENOENT**。



#### fs.rename 重命名与移动

**rename 移动**：fs.rename 把 oldPath 改名为 newPath，当二者跨目录时即为"移动文件"，底层在原地改目录项而非整体拷贝。

- 完整签名为 fs.rename(oldPath, newPath, callback)，成功即完成改名或移动。
- 同一文件系统内移动接近瞬时（仅改目录项），跨设备则 Node 内部先拷贝再删源。
- newPath 已存在时会被覆盖，尤其在同目录改名需避免与现有文件撞名。

```js
const fs = require("fs");
const path = require("path");

const src = path.join(__dirname, "old.txt");
const dst = path.join(__dirname, "sub", "new.txt");

fs.rename(src, dst, (err) => {
  if (err) throw err;
  console.log("已重命名或移动");
});
```

> rename 的"移动"依赖目标目录已存在：newPath 所在的父目录不存在会报 ENOENT，与 writeFile 同理。把文件移动到新建子目录前，需先确保目录就位（建目录见第 12 篇）。

**速记**：rename **改名即移动，目标目录须存在**。



#### 文件描述符 fd 与 fs.open/close

**文件描述符**：是操作系统对"已打开文件"返回的一个小整数句柄 fd，后续读写都凭 fd 定位，而非每次重传路径；fs.open 取得 fd、fs.close 释放 fd。

- 完整签名为 fs.open(path, flags, mode, callback)，回调第二参即为 fd 数字。
- 完整签名为 fs.close(fd, callback)，关闭后该 fd 应不再用于 IO。
- 手动 open/close 属于底层用法，需自己管理缓冲与偏移，容易遗漏 close 造成句柄泄漏。

```js
const fs = require("fs");
const path = require("path");

const file = path.join(__dirname, "note.txt");

fs.open(file, "r", (err, fd) => {
  if (err) throw err;
  console.log("文件描述符：", fd); // 通常是个非负整数
  fs.close(fd, (closeErr) => {
    if (closeErr) throw closeErr;
  });
});
```

> 日常读写无需手动 open：readFile/writeFile 已在内部帮你 open、读写完再 close，既省心又避免漏关。只有当需要"按偏移多次读写同一文件""精细控制 flag 与权限"时，才直接用 open 拿 fd，深入用法留待流章节。

**速记**：fd **是数字句柄，日常用 readFile 替 open**。



#### 相对路径基于 process.cwd 而非脚本目录

**cwd 基准**：fs 中传入的相对路径以 process.cwd（进程启动目录）为基准解析，而不是以"脚本文件所在目录"解析，两者在换目录启动时会产生分歧。

- 例如 readFile("note.txt") 实际找的是"启动时所在目录下的 note.txt"，而非脚本旁边的 note.txt。
- __dirname 才是当前文件所在目录，固定不随启动位置变化（第 10 篇详述）。
- 稳定定位同伴资源应写成 path.join(__dirname, "note.txt")，而非裸相对名。

```js
const fs = require("fs");
const path = require("path");

// 不稳定：依赖从哪个目录启动 node
fs.readFile("note.txt", "utf8", (err, data) => {
  if (err) console.log(err.code); // 换目录启动极易 ENOENT
});

// 稳定：永远指向脚本旁边的 note.txt
const file = path.join(__dirname, "note.txt");
fs.readFile(file, "utf8", (err, data) => {
  if (err) throw err;
  console.log(data);
});
```

> 同一份脚本在 A 目录启动能读到、在 B 目录启动报 ENOENT，多半就是 cwd 与脚本目录不一致所致。凡资源与脚本绑定，一律用 __dirname 拼绝对路径，不要用相对文件名赌启动位置。

**速记**：相对路径 **看 cwd，不看脚本目录**。



#### 编码选项统一用 utf8

**编码统一**：文本读写时编码选项应统一写成 "utf8"，这是 Node 与 Web 通用的标准文本编码，避免 GBK、Latin1 等带来的乱码与跨平台差异。

- 读用 fs.readFile(path, "utf8", callback) 直接得字符串；写用 fs.writeFile(file, str, "utf8", callback)。
- 不写编码则读得 Buffer、写得需自管字节，文本场景易出错。
- 文件真实为非 UTF-8 编码时，fs 无法直接正确解码，需借 iconv-lite 等转换层。

```js
const fs = require("fs");
const path = require("path");

const file = path.join(__dirname, "note.txt");

fs.writeFile(file, "中文内容", "utf8", (err) => {
  if (err) throw err;
  fs.readFile(file, "utf8", (err2, data) => {
    if (err2) throw err2;
    console.log(data); // 中文内容（无乱码）
  });
});
```

> 写入与读取的编码必须一致：用 utf8 写却用默认 Buffer 读再随手按别编码 toString，会出现乱码。把 "utf8" 作为项目编码约定固定下来，比每次临时决定更稳。

**速记**：编码 **读写都写 utf8**。



#### 错误处理：try/catch 与勿用 existsSync

**错误处理分风格**：同步与 await（Promise）风格用 try/catch 捕获异常，回调风格必须判 err，三者不可相互替代，尤其不能用 try 兜异步回调里的错。

- **同步风格**：readFileSync 抛错，用 try { ... } catch (e) { ... } 包住即可。
- **Promise 风格**：await 抛错，同样用 try/catch 或在 .catch 中处理。
- **回调风格**：错误经 err 参数传递，try/catch 对其无效，必须 if (err) 判错。

```js
const fs = require("fs");
const path = require("path");

const file = path.join(__dirname, "note.txt");

// 同步 / await 用 try/catch
try {
  const data = fs.readFileSync(file, "utf8");
  console.log(data);
} catch (e) {
  console.log(e.code);
}

// 回调风格：判 err，而非 try/catch
fs.readFile(file, "utf8", (err, data) => {
  if (err) {
    console.log(err.code);
    return;
  }
  console.log(data);
});
```

> [!CAUTION]
> **注意内容**：不要用 fs.existsSync 先判断文件存在再读写（即 TOCTOU：检查与使用之间存在时间窗，期间文件可能被删或抢占）。应直接读写并在 err 里处理 ENOENT，把"判断"与"操作"合一，才是 Node 推荐的竞态安全写法。

**速记**：同步 await **try/catch**，回调 **判 err**。
