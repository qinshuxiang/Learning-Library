## MySQL2 与数据库操作

### 驱动选型：mysql、mysql2 与 ORM 方案

#### mysql 是老牌的回调风格驱动

**mysql 驱动**：是 Node 生态中最早流行的 MySQL 客户端，以**回调风格**编写，提供基础的连接与查询能力。

- 接口以回调函数为收尾，例如 connection.query(sql, callback) 的第二个参数是错误优先回调。
- 不支持原生 Promise，异步流程需自行包裹或借助 util.promisify。
- 长期未活跃维护，部分新特性与问题未被修复，新项目通常不再首选。

> mysql 适合阅读历史代码或维护老项目；新项目更推荐其升级版 mysql2，二者 API 高度兼容，迁移成本很低。

**速记**：mysql 是**回调老驱动**，新项目多换 mysql2。



#### mysql2 是兼容升级且性能更好的驱动

**mysql2 驱动**：是 mysql 的**兼容升级版**，在保持相似 API 的同时改进性能并补齐现代能力。

- 原生支持 **Promise 接口**，通过 mysql2/promise 入口即可 await 调用。
- 支持**预处理语句（Prepared Statements）**，服务端预编译、参数化，天然利于防注入。
- 修复了 mysql 的若干问题，并在协议层做了性能优化，解析更快。
- 本篇以 mysql2 为主，所有示例均基于该驱动。

> mysql2 刻意保持与 mysql 相近的调用形态，因此 mysql 代码只需少量改动即可迁移；关键差异在于 mysql2 强化了 Promise 与预处理能力。

**速记**：mysql2 **兼容升级、Promise 与预处理原生支持**。



#### ORM 方案的定位与取舍

**ORM（对象关系映射）**：是把数据库表映射为**代码对象**的中间层，典型有 Sequelize、Prisma、TypeORM。

- 优势：用对象方法代替手写 SQL，类型安全、迁移方便、与领域模型贴合。
- 代价：引入抽象层，复杂查询的**性能与可控性**不如原生 SQL，学习成本也更高。
- 定位：适合业务模型稳定、以 CRUD 为主的中后台；对性能与 SQL 精细控制要求高的场景，原生 mysql2 更直接。

> ORM 与 mysql2 并非二选一：很多项目用 mysql2 处理复杂查询，用 ORM 处理简单 CRUD。本篇只讲 mysql2 原生操作，SQL 语法细节请参考 MySQL 系列专题。

**速记**：ORM **重抽象省心，mysql2 重控制高效**。



### 安装与建立连接

#### 通过 npm 安装 mysql2

**安装方式**：mysql2 是 npm 上的第三方包，使用 npm install mysql2 即可加入项目依赖。

- 安装命令：npm install mysql2，包名就是 mysql2，不是 mysql。
- 项目若使用 TypeScript，可额外安装 @types/mysql2 获得类型提示。
- 安装后通过 require("mysql2") 拿到回调风格入口，通过 require("mysql2/promise") 拿到 Promise 风格入口。

```bash
npm install mysql2
```

> 若仅写回调风格，引入 mysql2 即可；若全程使用 await，直接引入 mysql2/promise，写法更统一，本篇示例均以后者为主。

**速记**：npm install **mysql2**，Promise 走 mysql2/promise。



#### mysql2/promise 提供 Promise 接口

**mysql2/promise 入口**：是对 mysql2 的封装，把回调式方法改造成**返回 Promise** 的形态，便于用 async/await 编写。

- 同一个 createConnection 方法，从 mysql2/promise 引入时返回的是 Promise 版连接对象。
- 查询方法返回 Promise，可用 await 直接取值，避免回调嵌套。
- 错误通过异常抛出，统一用 try/catch 捕获，逻辑更线性。

```js
const mysql = require("mysql2/promise");

async function showVersion() {
  const connection = await mysql.createConnection({
    host: "localhost",
    user: "root",
    password: "password",
  });
  const [rows] = await connection.query("SELECT VERSION() AS version");
  console.log(rows[0].version);
  await connection.end();
}
```

> mysql2/promise 与 mysql2 的方法名完全一致，区别只在返回值是否为 Promise；混用两套入口容易造成 await 拿到的是连接而非结果，需固定使用其一。

**速记**：mysql2/promise **把回调改成 Promise，可 await**。



#### createConnection 与 createPool 的区别

**两种建连方式**：createConnection 建立**单条长连接**，createPool 建立**连接池**按需分配连接。

- createConnection 方法（参数 connectionOptions 配置对象）：返回单一连接，所有查询共用这一条，并发时相互阻塞。
- createPool 方法（参数 poolOptions 配置对象）：维护一组连接，每次查询借用一条，用完归还，适合服务端并发。
- 开发期脚本、一次性任务可用 createConnection；长期运行的服务端程序应使用 createPool。

```js
const mysql = require("mysql2/promise");

// 单连接：整进程只有一条连接
const single = await mysql.createConnection({ host: "localhost", user: "root" });

// 连接池：内部维护多条连接
const pool = mysql.createPool({ host: "localhost", user: "root", connectionLimit: 10 });
```

> 单连接在高并发下会成为瓶颈，且一旦断开整进程不可用；连接池通过复用与排队缓解该问题，是服务端默认选择。

**速记**：createConnection **单连接**，createPool **池复用**。



#### 配置项与完整连接示例

**连接配置项**：传给 createConnection 或 createPool 的**配置对象**包含主机、账号与字符集等字段。

**host**（主机地址）：数据库所在机器，本地开发常填 localhost 或 127.0.0.1。
**port**（端口号）：MySQL 默认 3306，改过端口需显式指定。
**user**（用户名）：用于登录的数据库账号。
**password**（密码）：对应用户的口令，生产环境不应写死在代码里。
**database**（默认数据库）：连接后默认选中的库，省略则需在每个语句里带库名。
**charset**（字符集）：推荐 utf8mb4，可正确存储表情与四字节汉字，避免乱码。

```js
const mysql = require("mysql2/promise");

async function initDatabase() {
  const connection = await mysql.createConnection({
    host: "localhost",
    port: 3306,
    user: "root",
    password: "password",
    database: "test",
    charset: "utf8mb4",
  });
  console.log("连接成功");
  return connection;
}
```

> 字符集务必两端一致：数据库连接用 utf8mb4，建表也应用 utf8mb4，否则仍可能在存储环节出现乱码或插入报错。

**速记**：host、port、user、password、database、charset **六项最常用**。



### 连接池：并发控制与资源复用

#### 为什么需要连接池

**连接池的价值**：通过**复用已有连接**避免每次查询都新建与断开 TCP 连接的高昂开销。

- 建立数据库连接涉及 TCP 握手与认证，频繁建连会显著拖慢请求。
- 连接池预先维持若干空闲连接，查询到来时直接借用，结束即归还。
- 连接池能**限制并发连接总数**，防止瞬时流量打满数据库。

> 没有连接池时，每条请求各自建连，连接数随并发线性增长，数据库很快到达 max_connections 上限而拒绝服务。

**速记**：池**免去反复建连、并限流护库**。



#### createPool 的核心配置项

**连接池配置项**：createPool 的配置对象在连接项之外，还控制**池的大小与排队行为**。

**connectionLimit**（最大连接数）：池中同时保持的连接上限，默认 10，应按数据库承载能力设置。
**waitForConnections**（是否排队等待）：为 true 时连接被借光后请求排队，为 false 则立即报错。
**queueLimit**（排队上限）：最多排队的请求数，0 表示不限制；超出直接报错。
**idleTimeout**（空闲超时）：连接空闲超过该毫秒数后被回收，释放资源。

```js
const mysql = require("mysql2/promise");

const pool = mysql.createPool({
  host: "localhost",
  user: "root",
  password: "password",
  database: "test",
  waitForConnections: true,
  connectionLimit: 10,
  queueLimit: 0,
  idleTimeout: 60000,
});
```

> connectionLimit 并非越大越好：过大会压垮数据库，过小则请求排队变长。应结合数据库 max_connections 与业务峰值估算。

**速记**：connectionLimit 限总数、waitForConnections 决定排队、queueLimit 限排队、idleTimeout 收空闲。



#### 用 pool.execute 查询并自动归还

**pool 级查询**：通过池对象的 execute 或 query 方法查询时，mysql2 会**自动借还连接**，无需手动管理。

- pool.execute(sql, params) 内部从池中取一条空闲连接执行，结束后自动归还。
- 调用方只关心 SQL 与结果，不必调用 connection.release()，降低了连接泄漏风险。
- 适合无事务、彼此独立的单条查询；带事务的批量操作才需要手动取连接。

```js
const [rows] = await pool.execute("SELECT id, name FROM users WHERE age > ?", [18]);
console.log(rows);
```

> 自动归还只在调用 pool.execute / pool.query 时成立；一旦用 pool.getConnection() 手动取出连接，就必须显式 release，否则该连接永远不会回到池中。

**速记**：pool.execute **用毕自动归还，省心防泄漏**。



#### 用 pool.end 关闭连接池

**关闭连接池**：pool.end() 方法会**断开池内所有连接**并拒绝新请求，用于进程退出前的清理。

- pool.end() 返回 Promise，应在程序关闭钩子里 await 它，确保连接优雅释放。
- 调用后池不再接受查询，再次使用会报错，属于一次性的终态操作。
- 短时脚本也可不显式调用，进程退出时操作系统会回收，但服务端应优雅关闭。

```js
async function shutdown() {
  await pool.end();
  console.log("连接池已关闭");
}
```

> 不要在请求处理中途调用 pool.end()，那会切断所有正在进行的查询；它只应出现在进程关停逻辑里。

**速记**：pool.end **终态收池，仅用于关停**。



### 执行查询的两种方式：query 与 execute

#### query 直接拼接并执行语句

**query 方法**：pool.query(sql, params) 或 connection.query(sql, params) 直接把 SQL 发往数据库执行，参数可选。

- 不强制使用预处理，既能传参也能直接拼完整语句。
- 当不传参数时，语句原样提交，调用方需自行保证安全。
- 适合执行 DDL、多语句或那些不便参数化的管理类操作。

```js
const [rows] = await pool.query("SELECT * FROM users");
console.log(rows);
```

> query 在传参时也能做转义，但语义上它不强调预处理；对用户输入一律优先用 execute，把安全交给占位符机制。

**速记**：query **直发语句，参数可选不强制预处理**。



#### execute 使用预处理语句

**execute 方法**：pool.execute(sql, params) 使用**服务端预处理语句**，先预编译模板再绑定参数执行。

- 第一个参数是带问号占位符的 SQL 模板，第二个参数是与问号一一对应的参数数组。
- 预编译后的语句可被数据库复用，重复执行时省去再次解析。
- 参数与 SQL 文本分离传输，数据库按类型绑定，从根本上杜绝注入。

```js
const [rows] = await pool.execute(
  "SELECT id, name FROM users WHERE city = ? AND age > ?",
  ["Beijing", 18]
);
console.log(rows);
```

> execute 的占位符数量必须与参数数组长度一致，否则数据库报参数不匹配错误；这也是它比手写拼接更不容易出错的体现。

**速记**：execute **预处理、占位符、防注入可复用**。



#### 两者行为差异对照

**核心差异**：query 偏重灵活直接，execute 偏重安全与可复用，二者返回形态一致。

**预编译**：execute 走服务端预处理，query 默认不预编译。
**参数化**：execute 强制占位符传参，query 的传参是可选便利。
**注入防护**：execute 天然阻断注入，query 拼串仍有风险。
**复用性**：execute 的预处理句柄可复用，query 每次重新解析。
**返回结构**：二者都返回 [rows, fields] 双值，使用方式相同。

> 经验法则：凡涉及用户输入的查询一律 execute；仅当执行固定 DDL 或确定无外部输入时，才用 query 简化书写。

**速记**：用户输入 **execute，固定语句可 query**。



### 参数化查询与 SQL 注入防护

#### 用问号占位符传参

**占位符传参**：把 SQL 中的变量改写为**问号**，真实值通过参数数组单独传入，由驱动做安全绑定。

- 占位符位置用单个问号表示，参数按出现顺序填入数组。
- 驱动会把参数按字段类型正确编码，字符串中的特殊字符不再被当作 SQL 语法。
- 占位符既能用于 WHERE 条件，也能用于 INSERT/UPDATE 的赋值。

```js
const [rows] = await pool.execute(
  "SELECT * FROM users WHERE username = ? AND status = ?",
  [username, status]
);
```

> 占位符只能替换**值**，不能替换表名、列名或排序方向；这些结构类元素仍需白名单控制，详见本节的动态表名考点。

**速记**：值用 **问号占位，参数数组顺序对应**。



#### 预处理语句如何阻断注入

**阻断原理**：预处理把**代码结构**与**数据值**分两阶段传输，数据库先固化语法、再绑定数据。

- 第一阶段：数据库收到带问号的 SQL 模板并编译，确定语句结构。
- 第二阶段：参数作为纯数据传入，即使包含单引号或分号也不会改变已编译的结构。
- 因此攻击者输入 ' OR '1'='1 只会被当作某个字段的字符串值，无法逃逸成额外条件。

```sql
-- 模板先编译：SELECT * FROM users WHERE name = ?
-- 参数 "x' OR '1'='1" 作为纯数据绑定，不会变成 OR 条件
```

> [!WARNING]
> **警告内容**：SQL 注入会导致拖库、越权甚至删表。只要查询包含任何外部输入，就必须用问号占位符的 execute，绝不可把输入拼进 SQL 文本。

**速记**：预处理 **先固结构后绑值，注入无从逃逸**。



#### 拼接字符串的危险与正确写法

**危险写法**：用字符串拼接把用户输入直接嵌入 SQL，是注入的**主要来源**。

- 危险示例：把 username 变量用加号拼进 SELECT 语句，单引号被用户输入闭合后语句结构改变。
- 正确写法：改用 execute 的问号占位符，让驱动负责转义与绑定。
- 即便坚持拼串，也必须用 connection.escape 手工转义，但该方式易漏，远不如占位符可靠。

```js
// 危险：用户输入闭合引号后注入额外条件
const danger = "SELECT * FROM users WHERE name = '" + username + "'";

// 正确：占位符由驱动安全绑定
const safe = await pool.execute("SELECT * FROM users WHERE name = ?", [username]);
```

> 拼接危险不在于字符串本身，而在于把**不可信数据**当成了**代码文本**；占位符的本质是恢复数据与代码的边界。

**速记**：拼串 **数据与代码混同必危，占位符划界方安**。



#### 动态表名与排序字段不能参数化

**结构元素限制**：问号占位符只能替换**值**，无法替换表名、列名、排序方向与数量等结构元素。

- 表名如 users、orders 不能用问号传入，否则数据库报语法错误。
- 排序字段（ORDER BY 后的列名）与排序方向（ASC/DESC）同样不能参数化。
- 这类需求必须依靠**白名单**校验，只允许预设的安全取值通过。

```js
const allowedSort = new Map([
  ["name", "name"],
  ["created_at", "created_at"],
]);
const sortColumn = allowedSort.get(sortBy) || "created_at";
const sql = `SELECT id, name FROM users ORDER BY ${sortColumn} DESC`;
const [rows] = await pool.query(sql);
```

> [!CAUTION]
> **注意内容**：动态表名与排序字段若直接用用户输入拼 SQL，即便值本身走占位符也仍会注入；务必用白名单把输入收敛到已知安全集合，再拼入语句。

**速记**：结构元素 **不能占位，白名单收敛**。



### 增删改查实践

#### 查询：返回行对象数组

**查询返回形态**：SELECT 经 execute 后，解构得到的 rows 是**行对象的数组**，每个对象对应一条记录。

- 数组长度即命中行数，没有命中时为空数组而非 null。
- 每个行对象的**属性名与结果集列名一致**，可用点号访问字段。

```js
async function queryUsers(city) {
  const [rows] = await pool.execute(
    "SELECT id, name, city FROM users WHERE city = ?",
    [city]
  );
  return rows;
}
```

> 列别名会直接成为行对象的属性名，需要驼峰展示时应在 SQL 里用 AS 起别名，而非在 Node 侧臆造。

**速记**：查询返回 **行对象数组，键名对齐列名**。



#### 插入：通过 insertId 取回自增主键

**插入结果**：INSERT 的返回结果对象含 **insertId** 字段，即数据库生成的**自增主键值**。

- execute 的返回值解构为 [result, fields]，写操作取第一个元素即可。
- insertId 仅在表存在自增主键时有效，手动指定主键时它反映实际插入的 id。

```js
async function createUser(name, email) {
  const [result] = await pool.execute(
    "INSERT INTO users (name, email) VALUES (?, ?)",
    [name, email]
  );
  return result.insertId;
}
```

> insertId 属于 result 对象而非 rows；常见错误是用 [rows] 解构后去找 insertId 而拿不到，应解构为 [result]。

**速记**：插入取 **result.insertId 拿自增主键**。



#### 更新与删除：检查 affectedRows

**写操作影响行数**：UPDATE 与 DELETE 的结果对象含 **affectedRows**，表示**实际被改动或删除的行数**。

- affectedRows 为 0 说明条件未命中任何行，操作虽成功但无数据变化。
- 用它判断“是否真的改到了东西”，例如删除接口返回 404 还是 204。

```js
async function updateUser(id, name) {
  const [result] = await pool.execute(
    "UPDATE users SET name = ? WHERE id = ?",
    [name, id]
  );
  return result.affectedRows;
}
```

> 不要把 affectedRows 为 0 当成错误：它只代表“没匹配到”，可能是正常的业务空操作，应结合状态码语义处理。

**速记**：更新删除看 **affectedRows 知影响行数**。



#### 完整的增删改查函数示例

**CRUD 封装**：把四类操作各写成一个语义明确的函数，统一用 execute 与占位符，便于业务复用。

- 查询函数 queryUsers 返回行数组，供列表与详情复用。
- 插入函数 createUser 返回新主键，供后续跳转或回执。
- 更新函数 updateUser 与删除函数 deleteUser 返回 affectedRows，供结果判定。

```js
async function queryUsers(city) {
  const [rows] = await pool.execute(
    "SELECT id, name, city FROM users WHERE city = ?",
    [city]
  );
  return rows;
}

async function createUser(name, email) {
  const [result] = await pool.execute(
    "INSERT INTO users (name, email) VALUES (?, ?)",
    [name, email]
  );
  return result.insertId;
}

async function updateUser(id, name) {
  const [result] = await pool.execute(
    "UPDATE users SET name = ? WHERE id = ?",
    [name, id]
  );
  return result.affectedRows;
}

async function deleteUser(id) {
  const [result] = await pool.execute(
    "DELETE FROM users WHERE id = ?",
    [id]
  );
  return result.affectedRows;
}
```

> 以上函数都基于池对象调用，连接自动归还；真实项目还应加上错误捕获与参数校验，本例聚焦调用形态。

**速记**：CRUD **各一函数、统一 execute、占位符**。



### 结果集形态与数据类型处理

#### 行对象是普通对象且字段名对齐列名

**行对象结构**：结果集中的每一行是**普通 JavaScript 对象**，其键来自查询返回的列名。

- SELECT 列出的列决定对象有哪些键，未查询的列不会出现在对象里。
- 列名含下划线或大小写，对象键原样保留，不会自动转换命名风格。
- 多表连接出现同名列时，默认后者覆盖前者，应改用表别名加前缀区分。

```js
const [rows] = await pool.execute("SELECT id, user_name FROM users");
// rows[0] 形如 { id: 1, user_name: "alice" }
```

> 想让返回键是驼峰，应在 SQL 中用 AS 起别名（如 user_name AS userName），而不是在结果侧猜测字段名。

**速记**：行是**普通对象、键名即列名**。



#### rows 与 fields 双返回值及解构

**双返回值**：mysql2 的查询 Promise 解构为 **[rows, fields]** 两个元素，分别对应数据与元数据。

- rows 是行对象数组，承载实际查询结果，绝大多数场景只用它。
- fields 是字段描述数组，含列名、类型、表名等元信息，调试或动态处理时用。
- 用数组解构一次性接收，只关心数据时可写成 const [rows] = await ...。

```js
const [rows, fields] = await pool.execute("SELECT id, name FROM users");
console.log(rows);   // 行数据
console.log(fields); // 每列的名称与类型等元信息
```

> 常见笔误是把解构写成 const (rows, fields) 而漏掉方括号，结果是拿到两个独立 Promise 而非结果，务必用数组解构。

**速记**：解构 **[rows, fields]，数据在前元信息在后**。



#### 日期与大数类型的处理

**特殊类型**：DATE、DATETIME 默认转为 **JavaScript Date 对象**，BIGINT 与 DECIMAL 默认以**字符串**返回以保精度。

- 日期默认是 Date 对象，需要时区与格式化处理；想要字符串可开启 dateStrings 配置。
- BIGINT 超过 JS 安全整数范围，mysql2 默认返回字符串避免精度丢失，前端再按需转 BigInt。
- DECIMAL 同理返回字符串，参与金额计算应先转为精确类型再做运算。
- 更精细的控制可用 typeCast 配置项自定义每列的类型转换逻辑。

```js
const pool = mysql.createPool({
  host: "localhost",
  user: "root",
  database: "test",
  dateStrings: true, // 日期以 'YYYY-MM-DD HH:mm:ss' 字符串返回
});
```

> 金额与订单号等场景绝不能用 JS number 直接承接 BIGINT/DECIMAL，否则会出现尾数与精度错误，务必以字符串或 BigInt 处理。

**速记**：日期默认 **Date**，大数默认 **字符串保精度**。



### 事务处理

#### 事务的基本方法

**事务方法**：在单条连接上依次调用 **beginTransaction、commit、rollback** 三个方法控制事务边界。

- beginTransaction 方法（无参数）：开启事务，此后查询处于同一原子上下文。
- commit 方法（无参数）：提交事务，使期间所有改动永久生效。
- rollback 方法（无参数）：回滚事务，撤销期间所有未提交的改动。
- 三者都返回 Promise，需用 await 顺序执行，且必须作用在同一条连接上。

```js
const connection = await pool.getConnection();
await connection.beginTransaction();
try {
  // 一系列写操作
  await connection.commit();
} catch (err) {
  await connection.rollback();
  throw err;
}
```

> 只调用 beginTransaction 而不 commit，改动在连接关闭时会被数据库自动回滚；务必保证成功路径显式 commit。

**速记**：事务三件套 **begin、commit、rollback**。



#### 必须复用同一个连接

**同一连接约束**：事务内的所有语句必须跑在**同一条连接**上，从不同连接发起的查询不属于同一事务。

- 错误做法：事务中用 pool.execute，每次随机借到不同连接，begin 与后续写操作不在一处。
- 正确做法：用 pool.getConnection() 取出一条连接，全程用这条 connection 执行。
- 只有同连接才能保证隔离级别、锁与回滚范围覆盖全部操作。

```js
const connection = await pool.getConnection();
await connection.beginTransaction();
await connection.execute("UPDATE accounts SET balance = balance - ? WHERE id = ?", [100, 1]);
await connection.execute("UPDATE accounts SET balance = balance + ? WHERE id = ?", [100, 2]);
await connection.commit();
connection.release();
```

> 混用池级方法与连接级方法是事务最常见的坑：begin 在某条连接，execute 却从池里另借连接，导致事务完全失效。

**速记**：事务 **全程锁死同一条连接**。



#### 用 try/catch/finally 保证归还连接

**归还保证**：手动取出的连接必须在 **finally 中 release**，否则异常路径会泄漏连接、拖垮连接池。

- try 块里执行事务操作并 commit，catch 块里 rollback 并向上抛出。
- finally 块无论成功失败都调用 connection.release() 把连接还回池。
- 这样即使中途报错，连接也不会卡在占用状态，池才能继续服务其他请求。

```js
const connection = await pool.getConnection();
try {
  await connection.beginTransaction();
  // 业务写操作
  await connection.commit();
} catch (err) {
  await connection.rollback();
  throw err;
} finally {
  connection.release();
}
```

> 忘记在 finally 释放连接，会让该连接永远离开可用集合，连接池逐渐被耗尽而报等待超时，是高并发服务的高频故障。

**速记**：连接 **finally 必 release，防泄漏**。



#### 转账事务示例

**转账场景**：把扣款与加款放进同一事务，任一步失败整体回滚，保证**金额不丢不错**。

- 先 beginTransaction 开启事务，再在同一连接上执行扣款与加款两条更新。
- 两条都成功才 commit，任一条抛错则 rollback 撤销，避免只扣不加。
- 用受影响行数判断账户是否存在，最后在 finally 归还连接。

```js
async function transferMoney(fromId, toId, amount) {
  const connection = await pool.getConnection();
  try {
    await connection.beginTransaction();
    const [out] = await connection.execute(
      "UPDATE accounts SET balance = balance - ? WHERE id = ?",
      [amount, fromId]
    );
    const [in_] = await connection.execute(
      "UPDATE accounts SET balance = balance + ? WHERE id = ?",
      [amount, toId]
    );
    if (out.affectedRows === 0 || in_.affectedRows === 0) {
      throw new Error("账户不存在或余额不足");
    }
    await connection.commit();
    return true;
  } catch (err) {
    await connection.rollback();
    throw err;
  } finally {
    connection.release();
  }
}
```

> 该示例把 commit/rollback/release 都纳入 try/catch/finally，是事务模板的标准写法；任何一步缺失都会在异常时留下隐患。

**速记**：转账 **同连事务，失败回滚**。



### 错误处理与敏感配置管理

#### 常见错误码与 sqlMessage

**错误信息**：数据库错误对象上带有 **code** 与 **sqlMessage** 字段，用于区分错误种类。

**ECONNREFUSED**（连接被拒绝）：数据库未启动或 host/port 错误，网络层直接拒绝。
**ER_ACCESS_DENIED_ERROR**（访问被拒）：user 或 password 不正确，认证失败。
**ER_DUP_ENTRY**（重复键）：插入了唯一索引已存在的值，违反唯一约束。
**sqlMessage**（SQL 错误信息）：人类可读的失败原因，随错误对象一并返回。

```js
try {
  await pool.execute("INSERT INTO users (email) VALUES (?)", ["a@b.com"]);
} catch (err) {
  console.log(err.code);       // 如 ER_DUP_ENTRY
  console.log(err.sqlMessage); // 具体冲突说明
}
```

> code 是程序判断错误类型的依据（如捕获 ER_DUP_ENTRY 提示用户换邮箱），sqlMessage 用于日志排查，二者用途不同。

**速记**：错误看 **code 分类、sqlMessage 排查**。



#### 连接断开与重连策略

**断线处理**：数据库重启或网络抖动会让连接进入**断开状态**，需有重连或错误重试机制。

- 连接池本身会在借出时检测连接可用性，失效连接通常被剔除并新建。
- 单连接场景可监听连接的 error 与 end 事件，触发重连逻辑。
- 更稳妥的是在上层加**带退避的重试**，避免雪崩式频繁重连。

```js
pool.on("error", (err) => {
  if (err.code === "PROTOCOL_CONNECTION_LOST") {
    console.error("数据库连接丢失，等待后续请求自动重建");
  }
});
```

> 不要为每一次失败做无限立即重连，那会在数据库恢复期间形成重试风暴；指数退避与上限重试更稳健。

**速记**：断线 **池自剔除，重试加退避**。



#### 不要把数据库错误直接返回客户端

**错误暴露风险**：把原始 **sqlMessage 或 code** 直接回给前端，会泄露表结构、列名与数据库版本等敏感信息。

- 数据库错误属于内部实现细节，攻击者可用其推测表名与字段，辅助注入或越权。
- 服务端应先记录完整错误日志，再向客户端返回笼统的提示与统一错误码。
- 统一错误响应结构，既保护信息也利于前端稳定处理。

```js
try {
  await createUser(name, email);
} catch (err) {
  console.error("创建用户失败：", err); // 详细错误留给自己
  res.status(500).json({ code: "INTERNAL_ERROR", message: "服务异常，请稍后重试" });
}
```

> [!CAUTION]
> **注意内容**：原始数据库错误详情绝不可原样返回客户端，它会暴露数据库结构与版本，成为攻击者的侦察入口；对外只给统一抽象错误。

**速记**：错误 **详情留日志，对外给抽象**。



#### 用环境变量管理敏感配置

**配置外置**：把密码、主机等敏感项放进 **环境变量**，由代码读取而非写死，避免密钥入库。

- 用 process.env 读取配置，例如 process.env.DB_PASSWORD 取得数据库口令。
- dotenv 是社区维护的 npm 包，能把本地 .env 文件里的键值加载进 process.env，方便开发。
- .env 文件与含密码的配置文件**不应提交到版本库**，应加入 .gitignore。

```js
require("dotenv").config();
const mysql = require("mysql2/promise");

const pool = mysql.createPool({
  host: process.env.DB_HOST,
  user: process.env.DB_USER,
  password: process.env.DB_PASSWORD,
  database: process.env.DB_NAME,
});
```

> [!NOTE]
> **提醒内容**：dotenv 属于社区第三方包，并非 Node 内置模块；生产环境通常由平台直接注入环境变量，无需 .env 文件。

**速记**：配置 **进环境变量，不进代码库**。



### 与 Express 结合及性能优化

#### 在路由中调用数据库查询

**路由集成**：把连接池挂到 **应用实例或请求对象** 上，路由处理函数内即可 await 查询并响应。

- 在服务启动时创建 pool，通过 app.set("db", pool) 或模块导出共享给路由。
- 路由处理函数声明为 async，内部 await 查询结果后组装响应。
- 查询失败应进入错误处理中间件，而非在路由里散落 try/catch。

```js
const express = require("express");
const pool = require("./db"); // 导出已建好的连接池
const app = express();

app.get("/users", async (req, res) => {
  const [rows] = await pool.execute("SELECT id, name FROM users");
  res.json(rows);
});
```

> 连接池应在进程级创建一次并复用，不要在每次请求里新建 pool，那会迅速耗尽数据库连接资源。

**速记**：路由 **复用进程级 pool，async 内查询**。



#### 异步错误需向 Express 传递

**错误传递**：async 路由里抛出的异常不会自动进 Express 错误处理中间件，必须**显式 next 或交给包装器**。

- 直接 throw 时 Express 4 不会捕获 async 函数的拒绝，导致请求挂起。
- 用 try/catch 捕获后调用 next(err)，或在路由外包一层异步错误包装函数。
- 让错误统一流向错误处理中间件，返回规范的错误响应。

```js
const asyncHandler = (fn) => (req, res, next) =>
  Promise.resolve(fn(req, res, next)).catch(next);

app.get("/users/:id", asyncHandler(async (req, res) => {
  const [rows] = await pool.execute("SELECT * FROM users WHERE id = ?", [req.params.id]);
  if (rows.length === 0) return res.status(404).json({ message: "未找到" });
  res.json(rows[0]);
}));
```

> 遗漏异步错误传递，会使异常变成未处理 Promise 拒绝，请求既无响应也无日志，排障时极难定位，是 Express 接入数据库的高发问题。

**速记**：异步错误 **务必 next 或包装传递**。



#### 性能优化要点

**查询性能**：从 SQL 与调用方式两端入手，减少不必要的数据搬运与往返。

- 只查需要的列，用明确列名代替 SELECT *，减小结果体积。
- 为 WHERE、JOIN、ORDER BY 所用列**建索引**，让数据库走索引而非全表扫描（索引本身属数据库侧知识，见 MySQL 专题）。
- 分页用 LIMIT 与 OFFSET 控制返回量，避免一次拉取整表。
- 避免在循环里逐条查询，改为一次 IN 或批量语句，把 N 次往返降为 1 次。
- 关注慢查询日志，定位高频且耗时的语句再针对性优化。

```js
// 避免：循环里逐条查
for (const id of idList) {
  await pool.execute("SELECT * FROM users WHERE id = ?", [id]);
}
// 推荐：一次批量查
const [rows] = await pool.execute("SELECT * FROM users WHERE id IN (?)", [idList]);
```

> [!TIP]
> **建议内容**：把循环内的单条查询合并为批量查询，是提升接口性能最立竿见影的手段；往返次数往往比单条语句耗时更致命。

**速记**：优化 **列少、有索引、批量替循环**。



#### 常见坑总结

**高频陷阱**：多数数据库问题集中在**连接管理、异步与注入**三类，提前规避可省大量排障时间。

- 连接未归还导致池耗尽：手动 getConnection 后忘了 release，连接逐渐归零。
- 事务中混用池级方法：begin 在某连接、execute 另借连接，事务形同虚设。
- 忘记 await 导致拿到 Promise：把查询 Promise 当结果使用，取到的是对象而非数据。
- 连接对象全局共享：把单条连接存为全局变量并多请求共用，并发下相互干扰。
- 把用户输入拼进 SQL：舍占位符而用拼接，埋下注入隐患。

```js
// 错误：全局共享单连接，并发互相踩踏
const globalConn = await mysql.createConnection({ host: "localhost", user: "root" });

// 正确：用池，每次自动借还独立连接
const [rows] = await pool.execute("SELECT 1");
```

> [!CAUTION]
> **注意内容**：手动取出连接后务必配对 release，且不要在事务外把单连接当全局共享；这两者都会在高并发下引发连接耗尽与数据错乱。

**速记**：坑在 **连接必还、事务同连、await 别漏**。
