## events 与 EventEmitter

### 事件驱动与发布订阅模式

**事件驱动（Event-driven）**：是以**事件发生**为驱动力组织程序的范式，外部输入或状态变化都以事件形式通知监听者执行回调。

- Node 的流、网络、子进程等内建能力都建立在事件之上。

- 与主动轮询不同，事件驱动**被动等待通知**，资源消耗低、响应及时。

- 本篇聚焦 events 模块的 EventEmitter 类，它是 Node 事件驱动的统一载体。

#### 事件驱动是 Node 的核心范式

**事件驱动范式**：程序推进不靠主流程主动调用，而靠**事件被派发后回调被调用**来推进。

- 网络到达、文件读完、定时器到期都被转化为事件处理。

- 开发者只写监听与回调，把"何时发生"交给运行时。

- 事件循环负责"何时调度"，EventEmitter 负责"谁在监听什么"。

> 二者是配套两层：事件循环是机制，EventEmitter 是表达。理解 EventEmitter 即可看懂几乎所有 Node API 的回调组织。

**速记**：事件驱动是**被动等通知，而非主动轮询**。



#### 发布订阅模式解耦发送方与接收方

**发布订阅（Publish-Subscribe）**：是 EventEmitter 采用的消息模式，发送方只管**派发事件名**，接收方只管**监听事件名**，互不持有引用。

- 发送方不认识接收方，调用 emit 时无需知道谁在听，降低耦合。

- 接收方可动态增删，运行时随时订阅或退订。

- 一个事件可对应**多个订阅者**，事件被广播给全部监听器。

> 与"直接调用对方方法"相比，发布订阅去掉双向依赖：模块 A 只发布事件，B、C、D 各自订阅，A 完全不需要 import 它们。

**速记**：发布订阅让**发送方与接收方互不认识**。



#### EventEmitter 是事件驱动的载体

**EventEmitter 类**：是 events 模块导出的核心类，提供**注册监听、触发事件、移除监听**的完整能力。

- 它是 Node 事件驱动的**统一基类**，许多内建对象继承它。

- 开发者继承或组合它，即可给任意对象加上事件能力。

- 其方法名（on、emit、once）成为整个 Node 生态的通用词汇。

```js
const EventEmitter = require("events");
const emitter = new EventEmitter();
emitter.on("hello", () => console.log("收到 hello"));
emitter.emit("hello");
```

> EventEmitter 本身不产生业务事件，只是一套**事件调度机制**；触发什么、传什么参数由使用者决定。

**速记**：EventEmitter 是**事件调度的统一基类**。



### 基本用法：继承与注册触发

**基本用法**：拿到 EventEmitter 类后，用 **on 注册监听、emit 触发事件**，监听器按注册顺序同步执行。

- 获取：通过 require("events") 拿到 EventEmitter 类。

- 扩展：用 class 语法继承它，使自定义类具备事件能力。

- 触发：调用 emit 并传入事件名与参数。

#### 通过 require 拿到 EventEmitter 类

**引入方式**：EventEmitter 是 events 模块的导出成员，require("events") 即可取得该类。

- 解构写法 const { EventEmitter } = require("events") 直接取类。

- 整体写法 const EventEmitter = require("events") 在旧版本同样可用。

- 它是核心模块，无需安装，适合作为任意模块的事件底座。

```js
const { EventEmitter } = require("events");
console.log(typeof EventEmitter); // 输出：function
```

> 不要手写事件机制，复用内建类能保证行为一致、可被生态识别。

**速记**：require("events") 即拿到 **EventEmitter 类**。



#### 用 class 继承扩展事件能力

**继承扩展**：让自定义类 extends EventEmitter，实例便同时拥有业务方法与原生事件方法。

- 业务方法里调用 this.emit 把状态变化**广播**出去。

- 监听者通过 on 挂到实例，与业务方法**解耦**。

- 仅当"对象天然是事件源"才用继承。

```js
const { EventEmitter } = require("events");

class Timer extends EventEmitter {
  start() {
    this.emit("tick");
  }
}

const timer = new Timer();
timer.on("tick", () => console.log("tick 触发"));
timer.start();
```

> 只是想在别处复用事件能力，更轻量的做法是**组合一个 EventEmitter 实例**作成员，避免污染自身原型。

**速记**：extends EventEmitter 让**实例自带事件能力**。



#### on 注册监听、emit 触发

**on 方法**：签名为 on(eventName, listener)，为事件名注册一个持续监听的回调。

- 同一事件名可挂**多个监听器**，注册后可再注册。

- **emit 方法**：签名为 emit(eventName, ...args)，把后续参数原样传给监听器。

- 未监听的事件被 emit 不会报错，只是**无监听器执行**。

```js
const { EventEmitter } = require("events");
const emitter = new EventEmitter();

emitter.on("data", (value) => console.log("收到", value));
emitter.emit("data", 42);
emitter.emit("missing"); // 无监听，静默
```

> on 与 addListener 完全等价，社区更常用 on。

**速记**：on **挂监听**，emit **发事件**。



#### 监听器按注册顺序同步执行

**执行顺序**：同一事件名的多个监听器，按**注册先后依次执行**，先 on 的先被调用。

- 执行是**同步**的：emit 等当前所有监听器跑完才返回。

- 若某监听器**抛错**，emit 中断并向上抛出，后续监听器不再执行。

- 注册顺序形成稳定的**调用链**。

```js
const { EventEmitter } = require("events");
const emitter = new EventEmitter();
emitter.on("step", () => console.log("第一步"));
emitter.on("step", () => console.log("第二步"));
emitter.emit("step"); // 第一步 → 第二步
```

> 依赖"先 A 后 B"只需让 A 先注册，不必加锁或延时。

**速记**：监听器**先注册先执行，且同步**。



### 常用方法全解

**常用方法**：EventEmitter 提供成对互补的方法，覆盖**注册、一次性、移除、清空、查询**五类需求。

- 注册类：on（等于 addListener）持续监听。

- 一次性类：once 只响应首次触发。

- 移除类：off（等于 removeListener）移除单个、removeAllListeners 清空。

- 查询类：listenerCount 与 eventNames 读状态。

#### on 与 addListener 等价

**on 方法**：签名 on(eventName, listener)，为事件名注册持续监听的回调。

- listener 会被**反复调用**，每次该事件被 emit 都执行。

- 同一函数重复注册会**产生两个独立监听**，移除需各移各的。

**addListener 方法**：签名 addListener(eventName, listener)，与 on **行为完全一致**，仅名字不同。

```js
const { EventEmitter } = require("events");
const emitter = new EventEmitter();
const handler = () => console.log("监听");
emitter.on("a", handler);
emitter.addListener("a", handler);
console.log(emitter.listenerCount("a")); // 输出：2
```

> 二者等价是历史原因；团队内统一一种即可，混用无功能差异但影响可读性。

**速记**：on 即 addListener，**两名字一套行为**。



#### once 只执行一次

**once 方法**：签名 once(eventName, listener)，注册的监听器**仅在事件首次触发时执行一次**，之后自动移除。

- 适合"只关心第一次结果"的场景，如首包到达。

- 自动移除意味着**无需手动 off**，天然避免泄漏。

- 若事件始终不触发，该监听器会一直挂着，仍占引用。

```js
const { EventEmitter } = require("events");
const emitter = new EventEmitter();
emitter.once("ready", () => console.log("只打印一次"));
emitter.emit("ready");
emitter.emit("ready"); // 不再输出
```

> once 的自动移除发生在**监听器被调用之后**；混合 on 与 once 时，on 的监听不受影响。

**速记**：once 是**首触发后自移除的监听**。



#### off 与 removeListener 移除指定监听器

**off 方法**：签名 off(eventName, listener)，从事件名上**移除指定的那个监听器函数**。

- 必须传入**与注册时相同的函数引用**，匿名函数无法移除。

- 只移除**一个**匹配监听，同名事件上的其他监听不受影响。

**removeListener 方法**：签名 removeListener(eventName, listener)，与 off **完全等价**，仅名字不同。

```js
const { EventEmitter } = require("events");
const emitter = new EventEmitter();
const handler = () => console.log("监听");
emitter.on("a", handler);
emitter.off("a", handler);
console.log(emitter.listenerCount("a")); // 输出：0
```

> 移除失败最常见原因：传给 off 的是"另一个长得一样"的匿名函数。务必**保存监听器引用**。

**速记**：off 即 removeListener，**按引用移除单个**。



#### removeAllListeners 清空监听

**removeAllListeners 方法**：签名 removeAllListeners(eventName)，不传参时**移除全部事件的全部监听**，传事件名时只清空该事件。

- 批量收尾很有用，如对象销毁前一次性解绑防泄漏。

- 慎用无参形式：它会**连内部监听一起清掉**，可能破坏依赖该发射器的模块。

- 调用后返回发射器自身，支持链式书写。

```js
const { EventEmitter } = require("events");
const emitter = new EventEmitter();
emitter.on("a", () => {});
emitter.on("b", () => {});
emitter.removeAllListeners("a");
console.log(emitter.eventNames()); // 输出：[ 'b' ]
```

> 无参 removeAllListeners 是重型操作，会移除 newListener 等系统监听；优先**按事件名逐个移除**。

**速记**：removeAllListeners **按名清空，无参则全清**。



#### emit 返回是否有监听器被调用

**emit 方法**：签名 emit(eventName, ...args)，返回**布尔值**，表示本次是否存在**至少一个监听器**被调用。

- 返回 true：有监听器执行（不论内部做了什么）。

- 返回 false：**没有任何监听器**监听，事件被静默丢弃。

- 返回值只反映"有没有人听"，**不反映监听器是否抛错**。

```js
const { EventEmitter } = require("events");
const emitter = new EventEmitter();
console.log(emitter.emit("nobody")); // 输出：false
emitter.on("someone", () => {});
console.log(emitter.emit("someone")); // 输出：true
```

> 用返回值可判断事件是否有人订阅，常用于可选钩子：返回 false 说明无外部关心，可跳过昂贵附带逻辑。

**速记**：emit 返回 **true 有人听、false 无人听**。



#### listenerCount 与 eventNames 查询

**listenerCount 方法**：签名 listenerCount(eventName)，返回某事件名**当前监听器数量**。

- 可用于运行时检查是否**重复注册**或监听为空。

- 新版也提供模块级 events.listenerCount(emitter, name)。

**eventNames 方法**：签名 eventNames()，返回**当前所有已注册事件名的数组**（字符串或 Symbol）。

```js
const { EventEmitter } = require("events");
const emitter = new EventEmitter();
emitter.on("a", () => {});
emitter.on("a", () => {});
emitter.on("b", () => {});
console.log(emitter.listenerCount("a")); // 输出：2
console.log(emitter.eventNames());        // 输出：[ 'a', 'b' ]
```

> 二者常配合做自省：打印 eventNames 看对象在监听什么，用 listenerCount 确认是否被异常叠加。

**速记**：listenerCount **数个数**，eventNames **列清单**。



### 事件命名约定与特殊事件

**事件命名**：事件名可用**字符串或 Symbol**，其中 error、newListener 等具有特殊含义，命名须遵循约定避免误用。

- 普通业务事件用**语义化字符串**，见名知意。

- 需私有、防冲突的事件可用 **Symbol** 作名。

- 个别事件名被框架**保留为特殊行为**。

#### 事件名可用字符串或 Symbol

**字符串事件名**：最常用，用说明性文字标识事件，如 data、end、connection。

- 可读性好，eventNames 直接返回可读字符串，便于调试。

- 同名字面量即同一事件，**拼写错误会导致监听失效**且不易察觉。

**Symbol 事件名**：用 Symbol 作事件名，保证该事件**全局唯一、不会与字符串事件冲突**。

```js
const { EventEmitter } = require("events");
const internalEvent = Symbol("internal");
const emitter = new EventEmitter();
emitter.on(internalEvent, () => console.log("私有事件"));
emitter.emit(internalEvent);
```

> 用 Symbol 适合"内部事件不想被外部误触发"：外部拿不到该 Symbol 引用，就无法 emit 或 on 它。

**速记**：字符串**可读易拼错**，Symbol **唯一防冲突**。



#### error 与 newListener 是特殊事件

**error 事件**：被 emit 时若**没有监听器**，EventEmitter 会**抛错并使进程崩溃**（详见后续章节），是唯一"无监听即致命"的事件。

- 它不受 maxListeners 限制规则约束。

- 业务异常统一走 error 事件是 Node 的共识约定。

**newListener 与 removeListener 事件**：当**新增或移除监听器**时，发射器自行派发这两个事件，可用于监听变化。

```js
const { EventEmitter } = require("events");
const emitter = new EventEmitter();
emitter.on("newListener", (name) => console.log("新增监听", name));
emitter.on("data", () => {}); // 输出：新增监听 data
```

> newListener 的监听函数自身注册时也会触发 newListener，但 EventEmitter 会避免无限递归；二者用于调试审计，不建议承载核心逻辑。

**速记**：error **无人听就崩溃**，newListener **自动上报增删**。



#### 事件命名风格建议

**命名风格**：推荐用**小写连字符或驼峰**的动词性短语，让事件名同时表达"发生了什么"。

- 以"动作完成"命名：orderCreated、fileRead，比 read 更明确是已读完。

- 区分"进行中"与"已完成"：reading 表开始、read 表完成。

- 层级事件用冒号分隔命名空间：net:connect、db:query。

> 命名统一降低协作成本：约定"已完成态用过去式"，任何人看到 paid 即知"支付已落定"，不会误当"准备支付"。

**速记**：事件名用**动词过去式表已完成**。



### 传参与 this 指向

**传参与 this**：emit 可携带**任意个参数**传给监听器；监听器内 this 的指向取决于它是**普通函数还是箭头函数**。

- 参数通过 emit(eventName, ...args) 原样传递，监听器按位接收。

- 普通函数做监听器时，**this 指向发射器实例**。

- 箭头函数做监听器时，this 取**词法外层**，不指向发射器。

#### emit 可携带任意个参数给监听器

**参数传递**：emit 触发事件时，事件名之后的所有实参都会**依次传给监听器**。

- 监听器按形参位置接收，多传忽略、少传为 undefined。

- 参数可为任意类型，对象、数组、错误均可。

- 建议把多个字段**打包成一个对象**传递，后续增删字段不破坏参数顺序。

```js
const { EventEmitter } = require("events");
const emitter = new EventEmitter();
emitter.on("user", (name, age) => console.log(name, age));
emitter.emit("user", "小明", 18); // 输出：小明 18
```

> 多字段场景用 emit("user", { name, age })，比按位传参更稳健。

**速记**：emit 后参数**原样按位传给监听**。



#### 箭头函数做监听器时 this 不指向发射器

**箭头函数 this**：箭头函数**没有自己的 this**，继承定义处的外层 this，故监听器里 this **不等于发射器**。

- 想用 this 访问发射器属性会失败。

- 适合只依赖**闭包变量**、不依赖 this 的纯逻辑。

- 类里用箭头函数注册，this 指向**类实例**，有时正合需求。

```js
const { EventEmitter } = require("events");
const emitter = new EventEmitter();
emitter.on("check", () => console.log(this === emitter)); // 输出：false
emitter.emit("check");
```

> 用箭头函数却写 this.emit 是常见坑：此时 this 非发射器，会报 this.emit is not a function。

**速记**：箭头函数 this **取词法外层，非发射器**。



#### 普通函数 this 指向发射器

**普通函数 this**：用普通 function 声明的监听器，被 emit 调用时 **this 默认绑定到发射器实例**，可反身触发新事件。

- 与 DOM 事件不同，EventEmitter **不会**把 this 改成事件对象。

- 监听器内可直接写 this.emit("next") 串联后续事件。

- 需拿到外层 this 时用**箭头函数或 bind** 固定。

```js
const { EventEmitter } = require("events");
const emitter = new EventEmitter();
emitter.on("first", function () {
  console.log(this === emitter); // 输出：true
  this.emit("second");
});
emitter.on("second", () => console.log("second 触发"));
emitter.emit("first");
```

> 需要"监听器里再触发本发射器事件"时，普通函数最省事。

**速记**：普通函数 this **绑定到发射器**。



### 监听器数量限制

**数量限制**：单个事件名默认最多挂 **10 个监听器**，超出时打印警告（不抛错），提示可能的**内存泄漏**。

- 阈值由 maxListeners 控制，可用 setMaxListeners 调整。

- 设 0 表示**不限制数量**，不再告警。

- 告警不影响功能，但忽略它往往意味着监听器在异常堆积。

#### 默认单个事件最多 10 个监听器告警

**默认上限**：默认 maxListeners 为 **10**，某事件名监听器数超过 10 时打印警告到 stderr。

- 警告形如 MaxListenersExceededWarning: Possible EventEmitter memory leak detected。

- 超过后才告警，**第 11 个仍能正常注册并执行**。

- 限制**按事件名分别计数**，不同事件互不影响。

```js
const { EventEmitter } = require("events");
const emitter = new EventEmitter();
for (let i = 0; i < 11; i++) emitter.on("bulk", () => {}); // 第 11 个告警
```

> 警告是提示非错误；出现它几乎总是监听器被**重复注册未移除**，应优先排查泄漏而非调高上限。

**速记**：默认 **10 个封顶，超了只告警**。



#### setMaxListeners 调整上限、0 表示无限制

**setMaxListeners 方法**：签名 setMaxListeners(n)，为发射器设置单个事件的监听器数量上限。

- 传正整数 n：超过 n 才告警，可按业务放宽。

- 传 0：**关闭数量限制**，既不告警也不拦截。

- 读取当前值用 getMaxListeners 方法。

```js
const { EventEmitter } = require("events");
const emitter = new EventEmitter();
emitter.setMaxListeners(50);
console.log(emitter.getMaxListeners()); // 输出：50
```

> 调高上限是治标，真正该治的是"为何需要这么多监听"。确认是合理设计（如广播给众多订阅者）再调高。

**速记**：setMaxListeners **调阈值，0 即无限**。



#### 告警提示潜在内存泄漏

**告警含义**：监听器数量告警本质是**内存泄漏预警**——监听器持有闭包与对象引用，长期不移除会让对象无法被回收。

- 每多一个长期监听，发射器就多持一份引用，阻止相关对象 GC。

- 在长生命周期对象（服务器、连接池）上泄漏，会随运行时间**持续涨内存**。

- 看到告警应先查"监听器是否在该移除时移除"。

> [!CAUTION]
> **注意内容**：把 maxListeners 调成 0 只会**消除告警，不解决泄漏**。真实泄漏仍在，内存照样上涨；调 0 仅适用确认无误的设计，调试阶段务必保留告警暴露问题。

**速记**：告警是**内存泄漏的探雷针**。



### error 事件的特殊性

**error 事件**：是 EventEmitter 中**唯一无监听即致命**的事件，emit("error") 时若无监听器，会**抛错并使进程退出**。

- 它不受 maxListeners 限制，也不走普通事件的静默逻辑。

- 任何可能 emit error 的发射器都**必须**提前注册 error 监听器。

- 它与进程级 uncaughtException 相关但不等同。

#### emit error 无人监听会抛错并崩溃

**崩溃机制**：调用 emit("error") 且**没有任何监听器**时，EventEmitter 抛出 Error，若无人捕获则**终止整个进程**。

- 与普通事件"无监听就静默"截然相反，是 error 的特殊性所在。

- 抛出的错误沿调用栈向上，直到被 try/catch 或进程级处理器接住。

- 凡是会 emit error 的路径，必须保证有兜底监听。

```js
const { EventEmitter } = require("events");
const emitter = new EventEmitter();
emitter.emit("error", new Error("出错了")); // 无监听：进程退出
```

> error 的特殊处理是刻意设计：让错误"不被监听就暴露"，避免被静默吞掉导致后续在错误状态继续运行。

**速记**：error **无人听即崩溃**。



#### 必须注册 error 监听器

**兜底监听**：对会 emit error 的发射器，应**始终先注册 error 监听器**，把错误转化为可控处理而非进程退出。

- 监听器内通常做**记录日志、清理资源、通知上游**，而非再抛一次。

- 继承 EventEmitter 的类中，建议在**构造函数里预置** error 监听。

- 若 error 监听自身又抛错且无其他监听，仍会崩溃。

```js
const { EventEmitter } = require("events");
const emitter = new EventEmitter();
emitter.on("error", (err) => console.error("捕获错误：", err.message));
emitter.emit("error", new Error("可恢复错误")); // 不再崩溃
```

> 不要在 error 监听里无条件**再 emit("error")**，会造成无限递归，最终仍崩溃；错误处理应是终点而非转发。

**速记**：error 必配**兜底监听防崩溃**。



#### 与 uncaughtException 的关系

**进程级兜底**：当 error 无人监听而抛错时，该错误成为**未捕获异常**，可被 process 的 uncaughtException 事件接住。

- uncaughtException 是**最后防线**：捕获后可记录并优雅退出，不应当常规错误处理。

- 二者层级不同：error 监听是**对象级**，uncaughtException 是**进程级**。

- 官方建议用**退出并重启**应对未捕获异常，而非在处理器里强行续命。

```js
const { EventEmitter } = require("events");
const emitter = new EventEmitter();
process.on("uncaughtException", (err) => {
  console.error("进程级兜底：", err.message);
  process.exit(1);
});
emitter.emit("error", new Error("没人听的错"));
```

> uncaughtException 能救一次，但进程状态可能已不一致；正确做法是**每个发射器都注册 error 监听**，让错误在对象级消化。

**速记**：error 无人听才**落到 uncaughtException**。



### 同步派发与异步顺序

**同步派发**：emit 调用是**同步**的，立即按顺序执行全部监听器后才返回；监听器内写异步代码不会改变 emit 本身的同步返回。

- emit 不等监听器里的 setTimeout、Promise 等异步逻辑。

- 若要在 emit 之后处理，需理解**同步已完成、异步稍后到**。

- 需真正异步派发时，显式借助 setImmediate 或 Promise。

#### emit 同步调用所有监听器

**同步执行**：emit 触发事件时，**逐一、同步**调用该事件全部监听器，全部跑完才返回。

- 监听器里的同步代码在 emit 返回前**已执行完毕**。

- 若某监听器抛错，emit 在该处中断，其余监听器**不再执行**。

- 返回值在全部同步监听结束后才产生。

```js
const { EventEmitter } = require("events");
const emitter = new EventEmitter();
emitter.on("go", () => console.log("同步 A"));
emitter.on("go", () => console.log("同步 B"));
emitter.emit("go"); // 上面两行已先打印
console.log("emit 之后");
```

> "emit 之后"的打印一定晚于所有同步监听器；不要假设监听器会稍后跑。

**速记**：emit **同步跑完所有监听才返回**。



#### 监听器内的异步不改变 emit 的同步返回

**异步不阻断**：监听器中调用 setTimeout、Promise.then、异步 IO 等，只会把回调**推迟到事件循环后续阶段**，不会让 emit 等待。

- emit 在触发那一刻就返回，异步结果在**之后的 tick** 才落地。

- emit 返回后，监听器里的异步产物**尚未就绪**。

- 想等异步结果要回到 Promise/回调模型，而非依赖 emit 返回值。

```js
const { EventEmitter } = require("events");
const emitter = new EventEmitter();
emitter.on("async", () => setTimeout(() => console.log("异步完成"), 0));
emitter.emit("async");
console.log("emit 已返回"); // 先于"异步完成"
```

> 常见误判：以为 emit 会等监听器干完活。emit 只管同步派发，监听器里的异步属另一段时间线。

**速记**：监听器异步 **不改变 emit 已同步返回**。



#### 用 setImmediate 或 Promise 实现异步派发

**异步派发**：若希望"事件触发"发生在当前调用栈之外，可在监听器内用 **setImmediate** 把真正逻辑推迟到 check 阶段。

- setImmediate 让回调在**当前 IO 之后、下一轮之前**执行，实现稍后派发。

- 用 Promise 包装则可在触发侧 **await** 一次结果（见下章）。

- 常用于**让出事件循环**，避免长同步链阻塞。

```js
const { EventEmitter } = require("events");
const emitter = new EventEmitter();
emitter.on("later", () => setImmediate(() => console.log("下一阶段才执行")));
emitter.emit("later");
console.log("emit 已返回"); // 先打印，再打印上一行
```

> 需纯粹异步派发，setImmediate 是首选；要携带结果并支持等待，用 events.once 的 Promise 形式更自然。

**速记**：异步派发靠 **setImmediate 或 Promise**。



### 与 Promise 的配合

**Promise 配合**：events 模块提供 **events.once**，把"等待某事件触发"包装成 Promise，使异步等待可用 await 书写。

- events.once(emitter, name) 返回 Promise，事件触发时**以传参 resolve**。

- 若触发的是 error 事件，Promise 会 **reject**，便于 try/catch 处理。

- 适合"只等一次"的场景，比手动 on/once 更贴合现代异步写法。

#### events.once 返回 Promise

**events.once 方法**：模块级方法，签名 events.once(emitter, name)，返回**一个 Promise**，在事件 name 首次触发时 resolve。

- resolve 的值是**事件参数组成的数组**（事件可传多参）。

- 它是 once 语义的 Promise 版本，触发一次即结束。

- 需先取出：const { once } = require("events")。

```js
const { EventEmitter, once } = require("events");
const emitter = new EventEmitter();
setTimeout(() => emitter.emit("ready"), 100);
once(emitter, "ready").then(() => console.log("ready 已触发"));
```

> 必须**先调用 once 拿到 Promise** 再让事件触发，否则可能错过（早于 await 的 emit 不会被捕获）。

**速记**：events.once **把一次事件变 Promise**。



#### await 等待一次性事件

**await 等待**：用 const [arg] = await once(emitter, name) 即可**暂停当前异步函数**，直到该事件首次触发并取参。

- 多参数用数组解构：const [a, b] = await once(emitter, name)。

- 比手写 on + resolve 的回调更扁平、易读。

- 配合 try/catch 可直接捕获同名 error 事件的 reject。

```js
const { EventEmitter, once } = require("events");
async function waitForData() {
  const emitter = new EventEmitter();
  setTimeout(() => emitter.emit("data", 7), 50);
  const [value] = await once(emitter, "data");
  console.log("拿到", value); // 输出：拿到 7
}
waitForData();
```

> 用 once 等待时，务必把"会触发事件的代码"安排在 await 之前或并发启动，否则事件永不发生，await 会**永远挂起**。

**速记**：await once **暂停等一次事件**。



#### 适合一次性等待场景

**适用场景**：events.once 适合"启动后等首个信号""等一次握手完成"这种**只关心首次触发**的等待。

- 典型：等服务器 listen 完成、等首条消息到达、等子进程首次就绪。

- 不适合需反复响应的场景，那种仍应用 on 持续监听。

- 与 once 方法相比，Promise 版天然支持 **async/await 串联**多个等待。

> [!TIP]
> **建议内容**：当一段逻辑是"触发事件 → 等它完成 → 继续"，优先用 events.once 配合 await，而非嵌套 once 回调；前者把时序写成顺序代码，可读性与维护性更好。

**速记**：once 适合 **一次性、首信号等待**。



### 内存泄漏风险

**内存泄漏**：EventEmitter 最常见泄漏是**监听器只注册不移除**，使对象被长期引用、无法回收，内存随运行持续上涨。

- 监听器是闭包，持有定义时所在作用域的变量。

- 在长生命周期发射器上堆积监听器，是 Node 服务内存涨的根源之一。

- 用 once、及时 off、必要时 removeAllListeners 是主要防线。

#### 监听器未移除导致对象无法回收

**泄漏机理**：只要监听器还挂在发射器上，它引用的**外部对象就保持可达**，垃圾回收器不敢回收。

- 长生命周期发射器（全局对象、连接管理器）上不断 on，会越积越多。

- 旧监听器即便业务已不用也**仍占内存**。

- 表现：常驻内存随运行时间单调上升，重启后回落。

```js
const { EventEmitter } = require("events");
const emitter = new EventEmitter();
function onVisit() {
  const big = new Array(1e6).fill(1);
  emitter.on("tick", () => big.length); // 每次新增引用
}
for (let i = 0; i < 1000; i++) onVisit();
```

> 判断泄漏的简单办法：对比"注册次数"与"移除次数"，正常业务二者应大致平衡。

**速记**：只注册不移除 **对象永不可回收**。



#### 重复注册同一函数

**重复注册**：用**同一个函数引用**多次 on 同一事件，会挂上多个独立监听，移除时需**对应移除多次**。

- 每次 on 都新增一份，listenerCount 会累加。

- 只 off 一次，剩余副本仍在监听，泄漏继续。

- 常见于"每次进入函数就 on、退出却没成对 off"的反模式。

```js
const { EventEmitter } = require("events");
const emitter = new EventEmitter();
const handler = () => {};
emitter.on("a", handler);
emitter.on("a", handler);
emitter.off("a", handler);
console.log(emitter.listenerCount("a")); // 输出：1（还有一份）
```

> 避免重复注册的根本手段是"**谁注册谁负责移除**"，并保持注册/移除成对出现在同一生命周期。

**速记**：同函数重复 on **多份监听难一次清**。



#### once 与移除监听的最佳实践

**最佳实践**：优先用 **once** 处理一次性事件，它自动移除；持续监听则**显式保存引用并在结束时 off**。

- 一次性等待用 events.once 或 once 方法，省去手动清理。

- 持续监听把监听器存为**具名引用**，销毁或退订时调用 off。

- 批量收尾用 removeAllListeners(事件名)，避免无参形式误伤系统监听。

```js
const { EventEmitter } = require("events");
const emitter = new EventEmitter();
const onMessage = (msg) => console.log(msg);
emitter.on("message", onMessage);
emitter.off("message", onMessage); // 同一引用移除
```

> [!IMPORTANT]
> **重要内容**：注册与移除必须**成对且引用同一函数**。用匿名函数注册却想 off 移除不可能成功——移除前务必保留监听器引用，这是杜绝 EventEmitter 泄漏的铁律。

**速记**：once **自动清**，off **成对引用清**。



### 实战示例

**实战示例**：用 EventEmitter 实现两个真实场景——**订单事件发射器**与**日志总线**，体会事件如何解耦业务模块。

- 订单发射器：把下单、支付、发货建模为事件，让通知、库存等模块各自订阅。

- 日志总线：用单例发射器收集各处日志，让控制台、文件等输出器订阅同一来源。

- 二者都体现"**发送方不依赖接收方**"的发布订阅价值。

#### 自定义订单事件发射器 OrderEmitter

**OrderEmitter 类**：继承 EventEmitter，将订单生命周期的**关键节点**建模为事件，供外部模块订阅。

- 方法 place、pay、ship 分别触发 orderPlaced、orderPaid、orderShipped。

- 通知、库存模块**独立监听**，订单类本身不 import 它们。

- 用普通函数做监听器可在内部用 this 串联后续事件。

```js
const { EventEmitter } = require("events");

class OrderEmitter extends EventEmitter {
  place(orderId) {
    console.log(`订单 ${orderId} 已创建`);
    this.emit("orderPlaced", orderId);
  }
  pay(orderId) {
    console.log(`订单 ${orderId} 已支付`);
    this.emit("orderPaid", orderId);
  }
  ship(orderId) {
    console.log(`订单 ${orderId} 已发货`);
    this.emit("orderShipped", orderId);
  }
}

const orders = new OrderEmitter();
orders.on("orderPaid", (id) => console.log(`[通知] 订单 ${id} 支付成功`));
orders.on("orderShipped", (id) => console.log(`[通知] 订单 ${id} 已出库`));
orders.on("orderPlaced", (id) => console.log(`[库存] 锁定订单 ${id} 的库存`));

orders.place("A1001");
orders.pay("A1001");
orders.ship("A1001");
```

> 订单类**完全不知道**通知、库存模块存在；新增风控模块只需再 on 一个事件，不改订单类一行代码。

**速记**：OrderEmitter 让**业务节点变可订阅事件**。



#### 用 EventEmitter 实现日志总线 Logger

**Logger 类**：用单例 EventEmitter 作为日志总线，各处调用 log 时**只管 emit**，由订阅的输出器决定打印到哪。

- 产生方调用 logger.log(level, message)，不直接操作控制台或文件。

- 控制台输出器订阅 log 打印终端，文件输出器订阅后写磁盘。

- 切换输出方式**不改产生方代码**，符合单一职责与开闭原则。

```js
const { EventEmitter } = require("events");

class Logger extends EventEmitter {
  log(level, message) {
    this.emit("log", { level, message, time: new Date().toISOString() });
  }
}

const logger = new Logger(); // 单例总线
logger.on("log", ({ level, message, time }) => {
  console.log(`[${time}] ${level.toUpperCase()} ${message}`);
});
logger.on("log", ({ level, message }) => {
  // fs.appendFileSync("app.log", `${level} ${message}\n`);
  void level; void message;
});

logger.log("info", "服务启动");
logger.log("error", "数据库连接失败");
```

> 想加"错误上报监控平台"的输出器，只需再 on 一次 log 事件，原代码零改动。

**速记**：Logger 让**日志产生与输出解耦**。
