## Buffer 与二进制数据

### Buffer 的认识

#### Buffer 是处理二进制数据的类

**Buffer**：是 Node 中处理**二进制数据**的类，继承自 **Uint8Array**，每个元素是一个 **0 到 255 的字节**。

- 它操作**文件、网络、图片**等原生字节，字符串负责文本。
- 作为 Uint8Array 子类，它拥有 TypedArray 能力，并额外提供二进制专用方法。
- 每个元素占 **1 字节**，写入超过 255 的值会被**按 256 取模**截断。

```js
const buf = Buffer.from([0x48, 0x65, 0x6c]);
console.log(buf instanceof Uint8Array); // true
console.log(buf[0]); // 72
```

> Buffer 与字符串职责不同：文本走**字符串**，字节走 **Buffer**；它既是 TypedArray 的超集封装，又更懂字符编码与整数读写。

**速记**：Buffer 是 **Uint8Array 子类**，元素即**字节**。



#### 为什么需要 Buffer

**Buffer 存在的根本原因**：JavaScript 的**字符串不够用**，直接读写二进制会被字符编码破坏。

- 字符串按字符与 UTF-8 解释，图片字节被当字符串再写回会**错误解码**。
- 网络与文件传输的是**原始字节流**，字符串编码层会损坏数据。
- 固定大小、**连续内存**的字节视图，才能高效做底层 IO。

```js
const fs = require("fs");
const bytes = fs.readFileSync("demo.png"); // Buffer，原始字节
```

> 把图片读成字符串再写回往往损坏，因为某些字节在 UTF-8 下非法，会被替换为**替换字符**；Buffer 原样保存每个字节。

**速记**：字符串会**解码破坏**二进制，Buffer **原样保字节**。



### Buffer 的内存本质

#### Buffer 在堆外分配且以十六进制展示

**Buffer 的内存**：由 Node 的 **C++ 层在堆外申请**，不占 V8 堆；打印时以**十六进制**逐字节显示。

- 创建大 Buffer 时内存来自 **libuv 管理的堆外内存**，不受 V8 堆上限约束。
- 控制台形如 <Buffer 48 65 6c>，每组是一个字节的两位，便于观察原始值。
- 过长时会**截断显示**；十六进制只是展示方式，看文本应改用 toString。

```js
const buf = Buffer.alloc(1024 * 1024);
console.log(buf.length); // 1048576，不占 V8 堆上限
```

> 内存不在 V8 堆意味着单进程能处理很大二进制，但也需更留意**内存泄漏**；查看完整字节应改用 **toString("hex")**。

**速记**：Buffer 在**堆外**，打印显示**十六进制**。



### 创建 Buffer

#### Buffer.alloc 与 Buffer.allocUnsafe

**Buffer.alloc(size)**：创建并**清零**内存，最安全；**Buffer.allocUnsafe(size)**：创建但**不初始化**，速度快但有脏数据风险。

- alloc 返回**确定干净**的内存，不会残留旧数据（如密码、密钥）。
- allocUnsafe 跳过清零，直接返回**未清理**内存，可能含先前使用者数据。
- allocUnsafe 仅适合**立即写满**的场景，否则会读到不可预期脏数据。

```js
const a = Buffer.alloc(5);         // <Buffer 00 00 00 00 00>
const b = Buffer.allocUnsafe(5);   // 可能显示残留字节
```

> alloc 的安全来自**初始化清零**；allocUnsafe 快但拿到内存若未被完全覆盖就读取，会泄露或读到脏数据。

**速记**：alloc **清零安全**，allocUnsafe **快但不清**。



#### 三者对比：安全性、性能与优先 alloc

**alloc、allocUnsafe、allocUnsafeSlow 的差异**：核心在**是否清零**与**是否用内存池**，日常应优先 alloc。

- **安全性**：alloc 清零最安全；后两者不清零，有泄露旧数据风险。
- **性能**：allocUnsafe 最快；alloc 因清零略慢；allocUnsafeSlow 因绕池更慢。
- allocUnsafeSlow 直接堆外新分配，绕过内存池，仅属**性能调优**高级接口。

```js
const a = Buffer.alloc(4);
const b = Buffer.allocUnsafe(4);
const c = Buffer.allocUnsafeSlow(4);
```

> 选择原则：默认 **alloc**；确认立即写满且追求性能用 **allocUnsafe**；只有内存池成为瓶颈才考虑 allocUnsafeSlow。

**速记**：默认 **alloc**，性能用 **allocUnsafe**。



### Buffer.from 的各种入参

#### 从字符串创建并指定编码

**Buffer.from(str[, encoding])**：把字符串按指定**编码**转为字节，默认 **UTF-8**。

- 第二个参数 encoding 指定字符编码，常用 **utf8、base64、hex、latin1、ascii**。
- 字符串字符先被**编码为字节**再写入；"e4bda0" 在 hex 下是四个字节，在 utf8 下是四个字符。
- 编码参数决定"如何解读字符串"，务必明确指定，否则结果完全不同。

```js
const a = Buffer.from("你好");
const b = Buffer.from("e4bda0", "hex");
console.log(a); // <Buffer e4 bd a0 e6 9d a5>
```

> from 字符串必须**带编码**，缺省按 UTF-8 解释，错误编码会得到错误字节。

**速记**：from 字符串要**带编码**，默认 **utf8**。



#### 从数组创建

**Buffer.from(array)**：用一组 **0 到 255 的整数**构造 Buffer，每个数字对应一个字节。

- 数组元素被**逐个取低 8 位**写入，超范围按 256 取模。
- 结果是**一份拷贝**，与原数组互不干扰。
- 适合**手工构造字节序列**（如协议头）。

```js
const buf = Buffer.from([0x48, 0x65, 0x6c, 0x6c, 0x6f]);
console.log(buf.toString()); // "Hello"
```

> 数组里的数字被视为**原始字节值**而非字符编码，0x48 直接成为第一个字节，不再经 UTF-8 转换。

**速记**：from 数组即**直接填字节**。



#### 从已有 Buffer 创建

**Buffer.from(buffer)**：以另一个 Buffer 为数据源创建新 Buffer，内容是**拷贝**。

- 新 Buffer 持有**独立内存**，修改它不会影响原 Buffer。
- 常用于**复制一份**再加工，避免影响原始数据。
- 若想共享内存而非拷贝，应使用 slice 或 subarray。

```js
const src = Buffer.from("abc");
const copy = Buffer.from(src);
copy[0] = 0x41;
console.log(src.toString()); // "abc"，原数据未变
```

> **Buffer.from(otherBuffer) 是拷贝**，而 **buf.slice 是视图共享**；需要独立副本用 from。

**速记**：from Buffer **拷贝**，slice **共享**。



#### 从 ArrayBuffer 创建

**Buffer.from(arrayBuffer[, byteOffset[, length]])**：在已有 **ArrayBuffer** 之上创建 Buffer 视图，默认**共享**其内存。

- 可指定 byteOffset 与 length，只覆盖 ArrayBuffer 的**某一段**。
- 适合与 **TypedArray、Web 标准 API** 互操作。
- 修改会影响原 ArrayBuffer，**与 from(Buffer) 不同**。

```js
const ab = new ArrayBuffer(4);
const view = new Uint8Array(ab);
view[0] = 0x41;
const buf = Buffer.from(ab);
buf[1] = 0x42;
console.log(view[1]); // 66，证明共享内存
```

> from(ArrayBuffer) **共享内存**，from(Buffer) **独立拷贝**；共享与否取决于源类型，容易踩坑。

**速记**：from ArrayBuffer **共享**，from Buffer **拷贝**。



### Buffer 与字符串的转换

#### toString 默认 UTF-8 与支持的编码

**buf.toString([encoding[, start[, end]]])**：把字节按编码**解码为字符串**，默认 **UTF-8**，并支持多种编码。

- 默认从 **0 到 length** 全部解码，可用 start、end 限定区间；解码非 UTF-8 数据会得到乱码。
- **utf8** 最通用，**utf16le/ucs2** 为 UTF-16 小端，**latin1** 单字节透传，**ascii** 7 位。
- **base64 / hex** 把字节表示为可打印文本，便于传输存储。

```js
const buf = Buffer.from("A");
console.log(buf.toString("hex"));     // "41"
console.log(buf.toString("base64"));  // "QQ=="
```

> 文本用 **utf8**，二进制文本化用 **hex/base64**；latin1 因一一对应字节，常用于无损二进制到字符串的临时转换。

**速记**：文本用 **utf8**，二进制文本化用 **hex/base64**。



#### 中文在 UTF-8 下占 3 字节

**中文 UTF-8 编码**：常用汉字在 UTF-8 下占 **3 个字节**，因此 Buffer 长度约为字符数的 3 倍。

- 一个汉字经 UTF-8 编码产生 **3 字节**，计算"几个字"不能只看 Buffer 长度。
- 切分时要确保落在**字符边界**，否则截断多字节字符会乱码。
- 英文数字占 **1 字节**，表情符号常占 **4 字节**。

```js
const buf = Buffer.from("中");
console.log(buf.length);          // 3
console.log(buf.toString("hex")); // "e4b8ad"
```

> 混合文本的长度计算必须基于**字节而非字符**，否则切分与截断都会错位。

**速记**：中文 UTF-8 占 **3 字节**，长度按字节算。



### Buffer 的读写

#### 索引读写与 write 方法

**索引读写**：用**方括号加下标**访问单个字节，读写 0 到 255 的值，不做编码转换。

- buf[index] 读取第 index 个字节；buf[index] = value 写入，超出范围按 256 取模。
- 下标越界读取返回 **undefined**，写入**静默失败**。
- **buf.write(string[, offset[, length[, encoding]]])** 从指定位置把字符串编码写入，返回**实际字节数**。

```js
const buf = Buffer.alloc(10);
buf[0] = 0x41;
const written = buf.write("你好", 0, 6, "utf8"); // 6
```

> 写中文时 write 返回的**字节数常异于字符数**，容量应不小于 Buffer.byteLength 预估的字节长度。

**速记**：索引**直接读写字节**，write 返回**字节数**。



#### 读写整数系列方法

**整数读写方法**：按**符号、位数、字节序**组合提供全套函数，名字即含义。

- 读：readInt8、readUInt8、readInt16LE、readUInt16LE、readInt16BE 等，及 32 位与 64 位（BigInt）版本。
- 写：writeInt8、writeUInt8、writeInt16LE、writeUInt16BE 等对应系列。
- **Int 有符号、UInt 无符号、数字为位数、LE/BE 为字节序**。

```js
const buf = Buffer.alloc(4);
buf.writeInt16LE(258, 0);
console.log(buf.readInt16LE(0)); // 258
console.log(buf.readInt16BE(0)); // 513
```

> 位数决定范围：**8 位最大 255，16 位最大 65535，32 位最大约 42 亿**；64 位需用 BigInt 版本。

**速记**：名字四要素——**符号、位数、字节序、读写**。



#### 大小端 LE 与 BE 的意义

**字节序（Endianness）**：指**多字节整数在内存中的排列顺序**，分小端与大端。

- **LE（小端）**：低位字节存低地址，Intel 系常用。
- **BE（大端）**：高位字节存低地址，符合书写顺序，**网络协议常用**。
- 同样字节用 LE 与 BE 解读会得到**不同数值**，收发双方必须约定一致。

```js
const buf = Buffer.from([0x01, 0x02]);
console.log(buf.readInt16LE(0)); // 513（0x0201）
console.log(buf.readInt16BE(0)); // 258（0x0102）
```

> 字节序错配是二进制协议经典 bug：一端 BE 写、另一端 LE 读，数值全盘错位；处理网络包必须明确约定。

**速记**：LE **低地址存低位**，BE **低地址存高位**。



### Buffer 的常用实例方法

#### 长度与切片方法

**length、slice、subarray**：用于获取长度与**取出一段视图**。

- **length**：Buffer 的字节数（只读属性）。
- **slice(start, end)** 与 **subarray(start, end)** 等价，都返回**共享内存**的视图，不拷贝。
- 修改视图会影响原 Buffer，这与某些语言里 slice 返回拷贝不同。

```js
const buf = Buffer.from("hello");
console.log(buf.slice(0, 2).toString()); // "he"
```

> slice 与 subarray 在 Buffer 上**等价**，均返回共享底层内存的视图，是易错点。

**速记**：slice / subarray **共享视图**，非拷贝。



#### 查找、比较、填充与拼接

**indexOf、includes、equals、fill、copy、concat**：覆盖定位、比较与合并等常用操作。

- **indexOf / includes / equals**：定位子序列、判断是否包含、逐字节比较是否相同。
- **fill(value)**：用某值填满；**copy(target, ...)**：把片段复制到另一 Buffer。
- **Buffer.concat(list[, totalLength])**：把多个 Buffer **合并成新 Buffer**（返回拷贝）。

```js
const src = Buffer.from("XYZ");
const dst = Buffer.alloc(3);
src.copy(dst);
console.log(Buffer.concat([Buffer.from("ab"), Buffer.from("cd")]).toString()); // "abcd"
```

> concat 是**新建拼接**而非原地修改；copy 在已有目标 Buffer 上写入，需保证目标容量足够。

**速记**：indexOf 找位置，equals 比字节，concat 合并。



#### 调试展示方法

**inspect**：决定 Buffer 在 **console.log 与调试输出**中的呈现，通常无需手动调用。

- Node 打印 Buffer 时内部使用 **util.inspect**，以十六进制块展示。
- 长 Buffer 会被**截断显示**，可用 toString("hex") 看完整内容。
- 也可通过 **buf.inspect()** 拿到同样的字符串。

```js
const buf = Buffer.from("hello world, a long buffer for demo");
console.log(buf.toString("hex")); // 完整十六进制，无省略
```

> 调试若发现打印被省略（末尾出现省略号），说明 Buffer 过长，改用 **toString("hex")** 或 **toString("base64")**。

**速记**：打印被省略就改用 **toString("hex")**。



### Buffer.slice 与 Buffer.concat

#### slice 共享内存导致修改互串

**Buffer.slice**：返回的是**原 Buffer 的共享内存视图**，修改视图会**反向影响原数据**。

- slice 不分配新内存，视图与原 Buffer **指向同一段字节**。
- 通过视图改某字节，原 Buffer 对应位置**同步变化**。
- 这与"切片是独立副本"的直觉相反，是常见隐患。

```js
const buf = Buffer.from("abcdef");
const view = buf.slice(0, 3);
view[0] = 0x41;
console.log(buf.toString()); // "Abcdef"（原数据被改）
```

> [!CAUTION]
> **注意内容**：slice 返回的是**共享视图**而非拷贝，对它的写入会**污染原 Buffer**。在回调、并发、缓存复用场景，独立拷贝更安全。



#### concat 合并与需要独立拷贝

**Buffer.concat**：把多个 Buffer **按顺序拼接**成新 Buffer；需要独立数据时应改用 **Buffer.from**。

- concat 返回**新分配**的 Buffer，原列表均不被修改，totalLength 可省去内部重算。
- **Buffer.from(otherBuffer)** 复制一份新内存，后续修改互不干扰。
- 既要切片又要独立，可组合 **Buffer.from(buf.slice(...))**；或用 copy 写入目标 Buffer。

```js
const full = Buffer.concat([Buffer.from("Hello, "), Buffer.from("World")]);
const indep = Buffer.from(full.slice(0, 5));
```

> 选择依据：**要共享、要省内存**用 slice；**要独立、防串扰**用 Buffer.from 或 copy。concat 与 slice 内存语义相反。

**速记**：concat **建新内存**，独立用 **from/copy**。



### Buffer 与 ArrayBuffer、TypedArray 的关系

#### 继承关系与底层 ArrayBuffer

**Buffer 与 ArrayBuffer 的关系**：Buffer **继承自 Uint8Array**，并通过 **buf.buffer** 访问底层 ArrayBuffer。

- Buffer 实例拥有 Uint8Array 的**原型方法链**，可传给需要 TypedArray 的接口。
- **buf.buffer** 指向真正的原始内存，交给 Web 标准 API，多个视图可能**共享它**。
- 对 buf.buffer 的修改会**反映到所有共享它的视图**。

```js
const buf = Buffer.from("abcd");
const u8 = new Uint8Array(buf.buffer);
u8[0] = 0x5a;
console.log(buf[0].toString(16)); // "5a"，证明共享
```

> 访问 buf.buffer 拿到的是**整个底层 ArrayBuffer**，可能比 Buffer 本身更长（因内存池对齐）；精取区段需结合 byteOffset 与 byteLength。

**速记**：Buffer 是 **Uint8Array 子类**，buf.buffer 是**内存底**。



#### byteOffset 与多视图共享

**byteOffset**：表示当前 Buffer 视图在底层 **ArrayBuffer 中的起始字节偏移**；多个视图可共享同一段内存。

- 一个 Buffer 未必从 ArrayBuffer 的**第 0 字节**开始，可能存在偏移。
- slice 后得到的新视图，byteOffset 通常**不等于 0**，定位物理位置要用 **byteOffset + index**。
- 共享带来**零拷贝高性能**，也带来**并发串扰风险**。

```js
const base = Buffer.alloc(10);
const view = base.slice(4, 7);
console.log(view.byteOffset); // 4
```

> 共享内存是双刃剑：高频 IO、零拷贝场景它是性能关键；多模块协作场景易导致数据被意外改写，需隔离时用 **Buffer.from** 或 copy。

**速记**：byteOffset 是**视图起点**，共享即**零拷贝但防串扰**。



### Buffer 的实际应用

#### 读取文件的二进制与 Base64 编解码

**文件与 Base64**：fs 读文件默认返回 **Buffer（原始字节）**，并可自由与 **Base64 文本**互转。

- fs.readFile 不指定编码即得到**纯二进制**，读非文本文件必须拿 Buffer。
- 字节转 Base64：buf.toString("base64")；Base64 转字节：Buffer.from(str, "base64")。
- 常用于**图片内联、接口传文件**，把二进制塞进 JSON、HTML 或 URL。

```js
const fs = require("fs");
const img = fs.readFileSync("demo.png");
const restored = Buffer.from(img.toString("base64"), "base64");
fs.writeFileSync("restored.png", restored);
```

> Base64 把**每 3 字节编码成 4 字符**，体积约膨胀 33%，但转换可逆，是文本通道传输二进制的常用手段。

**速记**：读文件用 **fs 返回 Buffer**，转 Base64 即 **toString("base64")**。



#### 处理网络包与字符集转换

**网络包与转码**：TCP 流式数据以 **Buffer 分片**到达需拼接，字符集差异可用 Buffer 做字节级转码。

- net、http 的 data 事件回调拿到 **Buffer 片段**，需先 **concat 累积**再按协议解析。
- 整数字段用 **readInt16BE 等**按协议规定的字节序读取。
- 字符集转换先**按原始编码还原字符**，再**用目标编码重新编码为字节**。

```js
const fs = require("fs");
const raw = fs.readFileSync("legacy.txt"); // 默认 Buffer
fs.writeFileSync("utf8.txt", Buffer.from(raw.toString("latin1"), "utf8"));
```

> 流式传输中**一次 data 未必是一个完整包**，应**累积到满足协议长度再解析**；转码必须经由"字节到字符再到字节"的编码层。

**速记**：网络包**累积再按协议解析**，转码走**字节到字符再到字节**。
