## 模板引用与 DOM 交互

### 模板引用的基本概念

#### 模板引用是获取真实 DOM 元素的桥梁

**模板引用（Template Ref）**：是 Vue 提供的一种特殊 ref attribute，用于把模板中的**真实 DOM 元素或组件实例**与脚本里的一个 ref 变量关联起来。

- 在标签上写 ref attribute 并起一个名字，脚本中声明同名 ref 变量，挂载后变量里保存的就是该元素。
- 拿到的是**真实 DOM 对象**，不是虚拟节点，可以直接调用浏览器原生 API。
- 同样的写法放在组件标签上时，拿到的是**组件实例**而非元素。
- 它是 Vue 声明式体系里的**逃生通道**：状态驱动覆盖不到的场景，才借它直接触达原生节点。

```html
<input ref="username" placeholder="请输入用户名" />
```

```js
import { ref, onMounted } from "vue";

const username = ref(null);

onMounted(() => {
  username.value.focus(); // username.value 是真实的 input 元素
});
```

> 模板引用与 v-model 的分工：v-model 负责**数据与视图的双向绑定**，模板引用负责**拿到元素本身**。前者改值后由 Vue 去更新视图，后者是开发者亲手操作节点，二者作用层次不同，不可互相替代。

**速记**：ref attribute **一桥飞架**，真实元素进脚本。



#### ref 变量的声明与挂载期填充

**声明方式**：先在脚本中用 ref(null) 声明一个初始为空的变量，再让模板 ref attribute 与之**同名对应**，渲染器会在挂载期把元素填进来。

- 初始值约定写 null：表示尚未挂载、还没有元素。
- 填充时机：渲染器执行**挂载渲染**时，把元素实例赋给该变量的 value。
- 变量名与模板中的 ref 值必须**完全一致**，Vue 靠同名匹配建立关联。
- 挂载完成后随时可读：事件处理函数、侦听器、生命周期钩子里都能访问。

```js
import { ref, onMounted } from "vue";

const box = ref(null); // 1. 声明，初始为 null
// 模板：<div ref="box">容器</div>  2. 模板中同名标注

onMounted(() => {
  console.log(box.value); // 3. 挂载后已填充为该 div 元素
});
```

> 模板 ref 的填充由渲染器自动完成，无需手动赋值；同一变量名只对应一个元素，若模板中多个元素写了同一个 ref 名，后渲染者会覆盖前者。需要收集多个元素时，应改用 v-for 数组或函数 ref 方案，见后文。

**速记**：**ref(null) 起手，同名匹配，挂载期填充**。



#### v-if 与 v-show 场景下的可用性差异

**可用性差异**：v-if 控制的元素**未渲染时 ref 为 null**，v-show 控制的元素**始终存在于 DOM 中**，挂载后一直可访问。

- v-if 为假时元素**根本不在文档里**，对应的 ref 自然是 null，条件切真之后才填充。
- v-show 只是切换 display 样式，元素**始终在文档里**，挂载后任何时刻拿到都有值。
- 判断依据是**元素是否真实存在**，而不是视觉上可见与否。
- 依赖 v-if 元素的逻辑，应放在**元素确实渲染之后**执行，用 nextTick 或侦听器对齐时机。

```js
import { ref, nextTick } from "vue";

const showModal = ref(false);
const modalInput = ref(null);

async function openModal() {
  showModal.value = true;
  await nextTick();          // 等 v-if 的元素真正渲染出来
  modalInput.value.focus();  // 此刻才非空
}
```

> [!CAUTION]
> **注意内容**：对 v-if 元素的 ref **想当然地立刻访问**，是空指针报错的高发点——元素尚未渲染时 value 仍是 null，直接调用其方法会抛错。切换状态后务必等待渲染完成再使用。

**速记**：v-if **不渲染则 null**，v-show **藏而不删**。



#### 响应式依赖更新后 ref 的更新时机

**更新时机**：模板 ref 的填充发生在**DOM 更新完成之后**；响应式依赖变化导致元素被重建或替换时，ref 会随之指向新元素。

- ref 的赋值由渲染器在**挂载与更新阶段**完成，晚于状态变化的同步代码。
- 依赖变化引起元素重建时，ref 自动更新为**新元素**，无需手动维护。
- 想侦听模板 ref 本身的变化，watch 必须**加 flush: "post"**，否则回调执行时 ref 尚未更新，拿到的是旧值或 null。

```js
import { ref, watch } from "vue";

const tabPanel = ref(null);

// 侦听模板 ref 本身，必须在 DOM 更新之后执行回调
watch(
  tabPanel,
  (el) => {
    console.log("新面板元素", el);
  },
  { flush: "post" }
);
```

> 模板 ref 与普通响应式状态的方向相反：状态是**先改数据、后更新视图**，ref 是**视图更新完、才回填变量**。理解这一滞后性，就明白为什么要用 flush: "post" 或 nextTick 来对齐时机。

**速记**：ref 回填**晚于渲染**，watch 记得 **flush: "post"**。



### useTemplateRef 组合式函数

#### useTemplateRef 按名字字符串查找模板 ref

**useTemplateRef**：是 Vue 3.5 新增的组合式函数，传入模板中 ref attribute 的**名字字符串**，返回已绑定到对应元素的 ref。

- 用法：const inputEl = useTemplateRef("username")，字符串就是模板里 ref 的值。
- 脚本变量名**不必与模板名一致**，对应关系由传入的字符串显式表达。
- 返回值的类型根据元素**自动推导**，TypeScript 下无需手写元素类型。
- 挂载前为 null，挂载后为元素，时机与同名 ref 方式完全一致。

```html
<input ref="username" />
```

```js
import { useTemplateRef, onMounted } from "vue";

const inputEl = useTemplateRef("username"); // 按名字字符串查找

onMounted(() => {
  inputEl.value.focus(); // 类型自动推导为 input 元素
});
```

> [!NOTE]
> **提醒内容**：useTemplateRef 需要 **Vue 3.5 及以上版本**，低版本只能用同名 ref 方式。同一批 3.5 新增 API 中还有 useId，用于生成应用内唯一的 ID，二者同属 3.5 对开发体验的增强。

**速记**：useTemplateRef **传名字符串，直取模板元素**。



#### useTemplateRef 与同名 ref 方式的对比

**本质对比**：两种方式最终拿到同一个元素，差别在于**命名约束与类型推导的直观程度**。

- 同名 ref 方式：靠模板 ref 值与变量名**恰好一致**建立关联，属于隐式约定，重命名时容易单边改动导致断链。
- useTemplateRef 方式：对应关系**写在代码里**（传入名字符串），变量名可自由命名（如 usernameInput），关联一目了然。
- 类型推导：useTemplateRef 自动推导元素类型；同名 ref 方式在 TypeScript 下需要手写泛型。
- 官方立场：3.5 起推荐使用 useTemplateRef，意图表达更清晰。

```js
// 方式一：同名 ref（3.5 之前的唯一选择）
import { ref } from "vue";
const username = ref(null); // 变量名必须等于模板里的 ref 值

// 方式二：useTemplateRef（3.5 起）
import { useTemplateRef } from "vue";
const usernameInput = useTemplateRef("username"); // 变量名随意，名字字符串决定绑定
```

> 两个名字各司其职：模板里的 ref 值是**查找键**，脚本里的变量名是**使用名**。useTemplateRef 把二者解耦，这正是它比同名 ref 方式更直观、更不易出错的原因。

**速记**：同名 ref **靠巧合**，useTemplateRef **靠声明**。



### v-for 中的模板引用

#### ref 在 v-for 中收集为元素数组

**数组收集**：当 ref attribute 用在 v-for 内部时，同名 ref 变量填充的不是单个元素，而是**包含全部元素的数组**。

- 声明方式不变，仍可用 ref(null) 起手，挂载后自动变为元素数组。
- 数组按渲染结果收集，每个列表项对应一个元素。
- 列表项增删引起重新渲染时，数组内容随之自动更新。
- 适合对整组元素做统一操作，如批量测量、逐个聚焦。

```html
<ul>
  <li v-for="item in items" ref="itemEls">{{ item.text }}</li>
</ul>
```

```js
import { ref, onMounted } from "vue";

const itemEls = ref(null);

onMounted(() => {
  console.log(itemEls.value.length); // 列表项数量
  console.log(itemEls.value[0]);     // 第一个 li 元素
});
```

> 数组中保存的是元素本身；它对应的是**渲染结果**，与源数据数组 items 的下标对应关系需要额外保障，这正是下一个考点要辨析的顺序问题。

**速记**：v-for 内的 ref **收成数组**，一项一元素。



#### 3.5 之前的数组顺序问题

**顺序口径**：**3.5 起 ref 数组与源数组顺序保持一致**；3.5 之前填充顺序**不保证**与源数组一致，不能直接按下标对应数据项。

- 3.5 之前：数组顺序取决于元素收集的先后，可能出现乱序，官方文档明确不保证一致。
- 若此时写 itemEls.value[index] 去对应 items[index]，可能拿到错位的元素。
- 3.5 起：官方保证 ref 数组与源数组**同步对应**，可放心按下标使用。
- 跨版本兼容或需要更强的对应保障时，应改用**函数 ref 自行收集**，见下一节。

```js
// 3.5 之前：按下标对应数据项存在风险
const item = items.value[index];
const el = itemEls.value[index]; // 不保证与 item 对应
```

> [!WARNING]
> **警告内容**：在 3.5 之前的版本里，把 ref 数组下标当作源数组下标使用是**隐蔽的错误来源**——多数时候恰好正确，个别场景乱序出错且难复现。涉及下标对应关系的逻辑，一律改用函数 ref 按数据项显式记录。

**速记**：**3.5 起有序，3.5 前不保证**，对应关系靠函数 ref。



### 函数模板引用

#### 函数 ref 在挂载与卸载时被调用

**函数模板引用**：把 :ref 动态绑定为一个函数，元素**挂载时以元素实例为参数**调用该函数，元素**卸载时以 null 为参数**调用。

- 语法：:ref="函数名" 或 :ref="(el) => ..."，注意是 v-bind 动态绑定，值是函数而非字符串。
- 挂载阶段：参数 el 是新挂载的元素，正是登记元素的时机。
- 卸载阶段：参数 el 为 null，是清理过期引用的信号，处理前应判空。
- 写成**内联箭头函数**时，组件**每次更新都会重新执行**该函数；写成稳定的方法引用，则只在挂载与卸载时调用。

```js
import { ref } from "vue";

const boxEl = ref(null);

// 稳定的方法引用：仅在挂载、卸载时触发
function setBoxEl(el) {
  if (el) {
    boxEl.value = el;   // 挂载：登记元素
  } else {
    boxEl.value = null; // 卸载：清理引用
  }
}
```

```html
<div :ref="setBoxEl">内容</div>
```

> [!IMPORTANT]
> **重要内容**：卸载时以 null 调用是函数 ref 的**清理契约**——若只登记不清理，元素销毁后变量或集合里会残留失效引用。凡在函数 ref 里往集合中添加元素，必须同时写好对应的移除逻辑。

**速记**：函数 ref **挂载传元素，卸载传 null**。



#### 用函数 ref 自行管理数组收集

**自行收集方案**：需要**稳定的顺序**或自定义整理逻辑时，用函数 ref 配合数组手动收集元素，是 3.5 之前获得有序元素数组的标准做法。

- 以数据项的 index 作为存储位置，元素挂载时按 index 写入，天然与源数组对齐。
- 元素卸载时以 null 调用，把对应位置清掉，避免残留。
- 更新渲染前清空集合重新收集，可保证集合与最新渲染一致。

```html
<ul>
  <li v-for="(item, index) in items" :ref="(el) => setItemEl(el, index)">
    {{ item.text }}
  </li>
</ul>
```

```js
import { ref, onBeforeUpdate } from "vue";

const items = ref(["苹果", "香蕉", "橘子"]);
const itemEls = ref([]);

// 按下标登记，顺序与源数组严格一致
function setItemEl(el, index) {
  itemEls.value[index] = el;
}

// 每次更新前清空，等待重新收集
onBeforeUpdate(() => {
  itemEls.value = [];
});
```

> 内联箭头函数在每次更新时都会重新执行，配合 onBeforeUpdate 清空集合，恰好构成**先清空、再重收**的完整循环；这也解释了为什么函数 ref 方案天然适配动态列表。

**速记**：函数 ref **按 index 入位**，更新前先清空。



### 组件上的模板引用

#### 组件 ref 拿到的是组件实例

**组件模板引用**：ref 放在组件标签上时，变量填充的是**组件实例**而非 DOM 元素，可以访问实例上对外暴露的属性与方法。

- 选项式 API 组件的实例与组件内部的 this 等价，公开的 data、computed、methods 均可直接访问。
- script setup 组件拿到的是**封闭的实例**，须经 defineExpose 声明后才能访问，见下两节。
- 组件实例上没有原生 DOM API，需要元素时应由子组件内部自行拿 ref 再暴露，或访问实例的根元素。
- 典型用途是调用子组件的**命令式方法**，如打开弹层、触发子组件聚焦。

```html
<ChildView ref="childView" />
```

```js
import { useTemplateRef, onMounted } from "vue";

const childView = useTemplateRef("childView");

onMounted(() => {
  childView.value.open(); // 调用子组件暴露的方法
});
```

> [!TIP]
> **建议内容**：父子通信**优先走 props 与事件**，模板引用是备选手段。通过 ref 直取实例会让父组件依赖子组件的内部结构，形成反向耦合；只有无法用数据表达的命令式需求（聚焦、动画、播放控制）才值得动用它。

**速记**：组件 ref **取实例不取元素**，命令式需求才用它。



#### script setup 组件默认封闭

**默认封闭**：使用 script setup 语法的组件，其内部绑定**默认对外封闭**，父组件通过模板引用访问不到任何内部状态。

- 封闭的含义：setup 作用域里的变量与函数，不主动暴露给外部。
- 这是**刻意的封装设计**：组件内部实现属于私有细节，防止父组件随意伸手形成隐式依赖。
- 未经 defineExpose 时，父组件拿到的实例上几乎访问不到有效内容。
- 需要开放时，用 defineExpose 列出白名单，见下一节。

```js
// ChildView.vue —— script setup 组件
import { ref } from "vue";

const count = ref(0);

function increment() {
  count.value++;
}
// 未调用 defineExpose，父组件拿不到 count 与 increment
```

> 与选项式 API 对比：选项式组件的实例**默认全开放**，this 上有什么父组件就都能看到；script setup 把默认值反转为**全封闭**，把暴露什么的决定权交还给组件作者，粒度从全部收窄到白名单。

**速记**：script setup **默认关门**，开门靠 defineExpose。



#### defineExpose 声明暴露白名单

**defineExpose**：是 script setup 组件向父组件开放内部绑定的编译宏，传入的对象就是父组件经模板引用能访问到的**白名单**。

- 子组件内调用 defineExpose({ count, reset })，列出允许访问的属性与方法。
- 父组件经 childRef.value.count、childRef.value.reset() 访问，白名单之外一律不可见。
- 白名单是**显式契约**：改动暴露内容等于改动组件的公开接口，应审慎维护。
- 编译宏无需导入、在编译期处理，相关背景可衔接 13. 组合式 API 与 script setup。

```js
// ChildView.vue
import { ref } from "vue";

const count = ref(0);

function reset() {
  count.value = 0;
}

defineExpose({ count, reset }); // 仅开放这两项
```

```js
// 父组件
import { useTemplateRef, onMounted } from "vue";

const childView = useTemplateRef("childView");

onMounted(() => {
  console.log(childView.value.count); // 0，可读
  childView.value.reset();            // 可调用
});
```

> 暴露的是**引用而非快照**：count 暴露后父组件读到的是响应式数据，子组件内部变化对父组件实时可见；但父组件直接改写暴露的状态会绕过子组件自身的逻辑，除非有意为之，暴露方法比暴露裸状态更稳妥。

**速记**：defineExpose **列白名单，父凭 ref 访问**。



### 拿到原生 DOM 之后能做什么

#### 常用原生 DOM API 一览

**原生能力**：模板引用拿到元素后，即可使用**浏览器原生 DOM API**，Vue 不拦截也不替代这些能力。

- **addEventListener(事件名, 监听器函数, 选项)**：挂载事件监听，配合 **removeEventListener(事件名, 监听器函数)** 移除。
- **getBoundingClientRect()**：返回元素的位置与尺寸信息，是测量与定位的基础。
- **focus() 与 blur()**：控制聚焦与失焦。
- **querySelector(选择器)**：在该元素内部继续查找子元素，作用域限定在元素之内。
- **classList 与 style**：操作类名与内联样式。
- **scrollTop、scrollHeight、scrollIntoView()**：读取与控制滚动状态。

```js
const box = boxEl.value;

box.addEventListener("transitionend", handleTransitionEnd);
box.classList.add("is-active");
const rect = box.getBoundingClientRect();
console.log(rect.top, rect.height);
```

> 原生 DOM 的系统知识不在本篇展开，可对照 JavaScript 系列的 10. DOM 基础 与 11. DOM 元素操作 学习；那两篇里的查找、属性、样式、事件 API 在这里全部适用，只是获取元素的入口从 document 换成了模板引用。

**速记**：拿到元素，**原生 API 全解锁**。



#### 焦点管理与元素测量的典型示例

**典型实战**：模板引用最常见的两类用途是**焦点管理**与**几何测量**，二者都必须等真实元素就绪后进行。

- 焦点管理：进入页面自动聚焦搜索框、弹层打开后聚焦首个输入项、校验失败后聚焦出错字段。
- 几何测量与滚动：读取尺寸位置做定位计算，或在消息列表更新后滚动到底部。
- 涉及**状态变化之后再操作**的场景，记得用 nextTick 或侦听器对齐时机。

```js
import { useTemplateRef, nextTick, onMounted } from "vue";

const searchInput = useTemplateRef("searchInput");
const messageList = useTemplateRef("messageList");

onMounted(() => {
  searchInput.value.focus(); // 进入页面自动聚焦
});

async function sendMessage() {
  // ...发送逻辑，追加新消息后等待渲染
  await nextTick();
  const list = messageList.value;
  list.scrollTop = list.scrollHeight; // 滚动到底部
}
```

> 焦点与测量这类操作**依赖真实布局**，虚拟 DOM 层面无从得知，这正是它们无法被状态驱动取代的原因；而滚动位置何时读、何时设，取决于 DOM 何时更新完毕，nextTick 在这里就是时机的保险。

**速记**：焦点与测量，**元素就绪再加 nextTick**。



### 直接操作 DOM 的边界

#### 状态驱动为主、命令式操作为辅

**范式边界**：Vue 的默认范式是**状态驱动视图**——修改数据、模板自动更新；直接操作 DOM 属于**命令式补充**，只在声明式覆盖不到的场合使用。

- 状态驱动：数据是唯一事实来源，视图是数据的投影，更新路径可预测。
- 命令式操作绕过数据直接改视图，与虚拟 DOM 的下次渲染**可能互相覆盖**。
- 大量手动 DOM 操作会让视图为什么变成这样难以追踪，破坏可维护性。

> [!WARNING]
> **警告内容**：直接改写模板引用所及的样式、内容或结构，等于**在数据之外私设第二事实来源**——下一次渲染可能把改动冲掉，出现改了又被改回去的竞态。凡是能用响应式状态表达的视觉变化，一律回到状态驱动。

**速记**：**状态驱动是主路，命令式是应急车道**。



#### 适合直接操作 DOM 的典型场景

**判断标准**：一件事**无法通过状态变化表达**时，才动用模板引用直接操作 DOM；能声明式解决的，绝不命令式绕行。

- **第三方库集成**：图表、富文本编辑器、地图等库需要真实容器节点来初始化与销毁。
- **焦点管理**：自动聚焦、焦点转移、失焦校验，是 DOM 焦点 API 的专属领域。
- **几何测量与定位**：getBoundingClientRect 读尺寸、计算弹出层坐标。
- **canvas 绘制**：画布渲染本身就是命令式过程，必须持有真实 canvas 元素。
- **精细滚动控制**：读取与设置滚动位置、监听滚动事件做联动。

> 自查口诀：先问这个效果**能不能用数据加模板写出来**。能，就用响应式状态配合条件渲染、类名绑定完成；不能，才轮到模板引用出手，且操作范围应收敛在必要最小处。

**速记**：**声明式先问一遍，做不到再拿 ref**。
