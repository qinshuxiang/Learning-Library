## 组件事件与组件级 v-model

### 组件事件的触发与监听

#### defineEmits 声明组件自定义事件

**defineEmits**：是 script setup 中**声明组件自定义事件**的编译器宏，返回一个 emit 函数，专用于在组件内部触发事件。

- **数组式声明**：把事件名逐个写入字符串数组，只表达组件会发出哪些事件，如 defineEmits(['change', 'submit'])。
- **对象式声明**：以事件名为键、以 null 或校验函数为值，除声明外还能为每个事件单独挂校验逻辑。
- 声明过的名字被 Vue 视为**组件自定义事件**，触发走 emit 通道；未声明而父组件又绑定的写法，则落入原生事件透传逻辑。
- 宏无需导入：与 defineProps 一样由编译器直接识别，在 script setup 内直接调用即可。

```js
// 数组式：仅罗列事件名
const emit = defineEmits(['change', 'submit'])

// 对象式：键为事件名，值为 null 或校验函数
const emit = defineEmits({
  change: null,
  submit: (payload) => {
    if (payload && payload.id) {
      return true
    }
    console.warn('submit 事件缺少有效的 id 参数')
    return false
  },
})
```

> 选项式 API 中没有 defineEmits，对应写法是在组件的 emits 选项里声明事件名，再以 this.$emit('submit', payload) 触发；两种形态声明的是同一套机制，区别只在书写宿主。

**速记**：defineEmits 负责**声明**，返回的 emit 负责**触发**，数组求简、对象求校验。



#### emit 函数的调用方式

**触发规则**：script 逻辑中用 defineEmits 返回的 emit 函数触发，模板中用全局方法 $emit 触发，二者殊途同归。

- script 中：先写 const emit = defineEmits(['submit'])，再调用 emit('submit', payload)，第二个参数起为传给监听器的负载。
- 模板中：直接调用 $emit('submit', payload)，无需事先声明变量，常见于行内表达式。
- $emit 只在模板里可用：script setup 代码中拿不到 $emit，必须使用 emit 变量，这是两个环境最易混淆的边界。
- 参数个数不限：emit('move', x, y) 可以带多个参数，监听器函数按位置依次接收。

```html
<!-- 模板内直接触发 -->
<button @click="$emit('submit', { id: 1 })">提交</button>
```

```js
// script setup 内通过 emit 变量触发
const emit = defineEmits(['submit'])

function handleClick() {
  emit('submit', { id: 1 })
}
```

> 同一个事件在模板与脚本中触发效果完全一致，选哪种只看触发位置：写在模板行内用 $emit，写在函数逻辑里用 emit。

**速记**：脚本用 **emit**，模板用 **$emit**，触发的是同一个事件。



#### 父组件用 v-on 监听组件事件

**监听方式**：父组件用 v-on 指令（缩写 @）在子组件标签上监听自定义事件，处理器接收 emit 传来的负载。

- 监听写法：子组件标签上写 @submit 加处理器名，事件名对应子组件 emit 时传入的名字，大小写匹配规则见下节。
- 负载接收：监听器函数的第一个参数就是 emit 的第二个实参，emit('submit', { id: 1 }) 对应 function handleSubmit(payload)。
- 内联写法：@submit 可直接绑定表达式，也可用 @submit 加 $event 拿到首个负载。
- 对象语法：v-on 以对象形式一次绑定多个事件，键为事件名、值为处理器函数。

```html
<!-- 父组件模板 -->
<template>
  <ChildForm
    @submit="handleSubmit"
    @change="handleChange"
  />
</template>
```

> 子组件标签上写 @click 未必是监听原生点击，它监听的是名为 click 的事件：子组件声明过 click 则为自定义事件，未声明才会透传到根元素，详见本章声明原生事件一节。

**速记**：父组件 **@事件名** 监听，负载即 emit 的**第二个实参**。



### 事件校验与原生事件声明

#### 对象式 emits 的事件校验函数

**事件校验**：对象式 emits 允许为事件名配置一个校验函数，参数即本次触发时传入的负载，返回值表示负载是否合法。

- 校验函数在**每次触发时执行**，形如 submit 后挂 (payload) => payload.id !== undefined 这样的函数。
- 返回真值：校验通过，事件照常触发，无任何额外表现。
- 返回假值：Vue 只在控制台输出一条原生警告，事件**照常触发**，业务不受阻断。
- 无负载的事件用 null 占位即可，不必都写校验函数。

```js
const emit = defineEmits({
  // 无负载事件用 null 占位
  open: null,
  // 带负载事件挂校验
  submit: (payload) => {
    return payload && payload.id > 0
  },
})
```

> [!WARNING]
> **警告内容**：校验返回假值**只产生控制台警告、不拦截触发**，它属于开发期自检工具而非运行时防护。不要把校验当成业务守卫，关键数据的合法性仍须在监听处理器内自行判断。

**速记**：校验函数**只警告、不拦截**，假值仅留一条控制台提示。



#### 声明原生事件名会阻断透传

**原生事件声明**：在 emits 中声明 click、focus 等原生事件名后，父组件对该事件的监听不再透传到子组件根元素。

- 不声明时：父组件在子组件标签上写 @click，Vue 将其视为原生监听，自动挂到子组件**根元素**上，这是属性透传机制的一部分，机制细节详见 8. 组件基础与 props.md。
- 声明后：@click 被识别为**组件自定义事件**，只有子组件显式执行 emit('click') 才会触发，根元素不再自动接收。
- 该规则适用于 emits 中登记过的一切名字，无论这个名字同时是不是原生事件名。
- 典型用途：自定义按钮组件希望把点击语义完全收归自己控制，而不是放任父组件直接监听内部元素。

```js
// 子组件声明了 click
const emit = defineEmits(['click'])
```

```html
<!-- 父组件的 @click 不再落到子组件根元素 -->
<MyButton @click="handleClick" />
<!-- 只有子组件内部 emit('click') 时 handleClick 才执行 -->
```

> [!IMPORTANT]
> **重要内容**：声明原生事件名会**静默改变监听挂载位置**，从根元素透传切换为 emit 触发。若子组件忘记 emit，父组件的监听将永远不触发且无任何警告，排查时优先核对 emits 声明与 emit 调用是否成对。

**速记**：emits 里**登记即断透传**，触发权收归子组件。



### 事件名的命名规则

#### camelCase 与 kebab-case 的自动匹配

**自动匹配**：子组件用 camelCase 触发的事件，父组件用 kebab-case 监听同样生效，Vue 在两种写法之间自动转换。

- 触发侧：emit('someEvent')，以驼峰书写事件名。
- 监听侧：@some-event 加处理器，以短横线书写监听名，与驼峰触发指向同一事件。
- 匹配的实质是事件名归一化后再比对，而非字面全等，与 props 的大小写匹配机制同源。
- 设计目的：让模板书写符合 HTML 偏好短横线的习惯，不必强求两端风格一致。

```js
// 子组件：驼峰触发
const emit = defineEmits(['someEvent'])

function saveData() {
  emit('someEvent', { ok: true })
}
```

```html
<!-- 父组件：短横线监听，与驼峰触发自动匹配 -->
<ChildEditor @some-event="handleSomeEvent" />
```

> 匹配虽是自动的，但同一事件在声明、触发、监听三处应保持同一种风格，否则代码检索与重构时极易漏改。

**速记**：驼峰触发、**短横线监听**，Vue 自动牵线。



#### DOM 模板的大小写限制与 kebab 建议

**DOM 模板限制**：直接写在 HTML 里的模板（非单文件组件）会由浏览器把属性名全部转为小写，camelCase 形式的监听会失真。

- 在 DOM 模板中写 @someEvent，浏览器解析后实际变成 @someevent，与事件名 someEvent 无法匹配，监听静默失效。
- 单文件组件由编译器处理，模板保留原始大小写，不受此限制。
- 官方建议：监听一律使用 **kebab-case**，在 DOM 模板与单文件组件中都能安全工作，消除环境差异。

```html
<!-- DOM 模板中的陷阱：浏览器把属性名转为小写 -->
<child-editor @someEvent="handleSomeEvent" />
<!-- 实际等价于 @someevent，监听失效 -->
```

```html
<!-- 推荐写法：kebab-case 在任何模板环境下都正确 -->
<child-editor @some-event="handleSomeEvent" />
```

> [!NOTE]
> **提醒内容**：该限制只影响**直接写进 HTML 的 DOM 模板**；Vue 官方示例统一以 kebab-case 书写监听，跟随这一习惯可完全绕开大小写陷阱。

**速记**：DOM 模板**全变小写**，监听统一 **kebab-case** 最稳。



### 组件级 v-model 的原理

#### v-model 是 prop 加事件的语法糖

**组件级 v-model**：在组件上使用 v-model，等价于绑定一个名为 modelValue 的 prop，并监听一个名为 update:modelValue 的事件，本质仍是**单向数据流**的组合。

- 展开式：v-model="message" 完全等价于绑定 :model-value 为 message，再监听 @update:model-value 把新值赋回 message。
- 命名固定：无参数时 prop 名必须是 modelValue、事件名必须是 update:modelValue，二者由框架约定。
- 子组件从不直接改 prop，而是在交互时执行 emit('update:modelValue', 新值)，由父组件把新值写回自己的状态。
- 因此 v-model 看似双向，实际是**父传值、子报请、父写回**的自动闭环。

> [!IMPORTANT]
> **重要内容**：组件上的 v-model 与原生表单元素上的 v-model 是**两套机制**：原生元素由 Vue 直接同步输入值，组件上则完全依赖上述 prop 与事件约定。理解这一点，手写任何受控组件都不再神秘。

**速记**：组件 v-model 等于 **modelValue 的 prop 加 update:modelValue 的事件**。



#### 手写实现双向绑定

**手写路径**：不借助 defineModel 时，子组件声明 modelValue 的 prop、声明 update:modelValue 的事件，再把输入值通过事件报给父组件。

- 第一步：defineProps 接收 modelValue。
- 第二步：defineEmits 声明 update:modelValue。
- 第三步：内部元素把 modelValue 绑定为输入框的 value 属性，input 事件里以 $event.target.value 取新值并 emit。
- 父组件侧照常写 v-model 即可生效。

```js
// 子组件 script setup
defineProps(['modelValue'])
const emit = defineEmits(['update:modelValue'])
```

```html
<!-- 子组件模板 -->
<template>
  <input
    :value="modelValue"
    @input="$emit('update:modelValue', $event.target.value)"
  />
</template>
```

```html
<!-- 父组件：正常使用 v-model -->
<MyInput v-model="message" />
```

> 直接把 :modelValue 绑到 input 的 v-model 上，会造成子组件内自改 prop 的错误写法；正确姿势是 value 属性加 input 事件中转，让变更始终经由 emit 回到父组件。

**速记**：手写三件套：**modelValue prop、update 事件、value 属性加 input 中转**。



### defineModel 宏

#### defineModel 一行实现双向绑定

**defineModel**：是 Vue 3.4 起稳定的编译器宏，一个调用同时声明 modelValue 的 prop 与 update:modelValue 的事件，返回一个**可读可写的 ref**。

- 基本用法：写 const model = defineModel()，模板内直接以 v-model 绑定 model，脚本内通过 model.value 读写。
- 读写即同步：给 model.value 赋值时，宏内部自动触发 update:modelValue 事件，父组件状态随之更新。
- 模板中自动解包：模板里写 model 无需追加 .value，与普通 ref 的使用习惯一致。
- 带参数形式：defineModel('title') 对应父组件的 v-model:title，详见下节多参数绑定。

```js
// 子组件：一行声明
const model = defineModel()
```

```html
<!-- 子组件模板：像普通 ref 一样双向绑定 -->
<template>
  <input v-model="model" />
</template>
```

```html
<!-- 父组件 -->
<MyInput v-model="message" />
```

> defineModel 内部由 useModel 组合式函数支撑，把 prop 与事件打包：返回的 ref 被赋值时等价于 emit('update:modelValue', 值)，被读取时等价于读取父组件传入的 modelValue，手写一节的三件套被压缩进了一个调用。

**速记**：defineModel **一行顶三件套**，返回**可读写 ref**。



#### 父级未绑定时的行为

**未绑定行为**：父组件没有使用 v-model 时，defineModel 返回的 ref 退化为一个普通的本地 ref，可自由读写但不与任何外部状态同步。

- 本地可用：仍可照常对 model.value 赋值取值，组件内部功能不受影响。
- 不再回传：本地修改不会向父组件同步，因为父组件根本没有参与绑定。
- 默认值配置：defineModel 可传入配置对象，default 选项为未绑定时提供初始值；父级一旦传入，以父级为准。
- 适用场景：通用输入组件既支持 v-model 受控使用，也允许无绑定的自由模式。

```js
// 父级未绑定 v-model 时，model 是本地 ref
const model = defineModel({ default: '草稿内容' })

function resetDraft() {
  model.value = '' // 仅改本地，不会同步任何父级状态
}
```

> [!NOTE]
> **提醒内容**：判断组件当前是否受控，看父组件是否传了 modelValue；未传时组件对本地修改**完全自治**。这一特性让 defineModel 比手写 prop 加事件更适合做可选受控的通用组件。

**速记**：父级未绑定时 **ref 变本地**，改了也不外传。



### 多个 v-model 与修饰符

#### 同一组件上使用多个 v-model

**多个 v-model**：同一组件可同时绑定多个不同参数的 v-model，每个参数独立对应一对 prop 与事件。

- 参数语法：v-model:title 与 v-model:content 分别绑定两个互不相干的值。
- 子组件对应：defineModel('title') 与 defineModel('content') 各返回一个独立 ref。
- 手写对应：带参数时 prop 名直接取参数名 title，事件名为 update:title；无参数才是 modelValue 与 update:modelValue。
- 典型场景：表单类组件一次接收多个字段，姓名、邮箱各走各的 v-model。

```js
// 子组件：两个参数各声明一次
const title = defineModel('title')
const content = defineModel('content')
```

```html
<!-- 父组件：两个 v-model 并列 -->
<ArticleEditor
  v-model:title="title"
  v-model:content="content"
/>
```

> 无参数的 v-model 是参数缺省的特例：prop 固定叫 modelValue；一旦写了参数，prop 名就是参数本身，不再出现 modelValue 字样，核对 props 声明时不要混淆。

**速记**：参数即 prop 名，defineModel 的参数与 v-model 参数**一一对应**。



#### 内置修饰符在组件上的自动处理

**内置修饰符**：使用 defineModel 时，父组件加在 v-model 上的 .trim、.number、.lazy 由 Vue 自动处理，子组件无需任何额外代码。

- .trim：同步时自动去除首尾空白。
- .number：尝试把输入转为数字，转换失败则保留原字符串。
- .lazy：把逐字符同步换成 change 事件语义，失焦时才同步。
- 仅 defineModel 免手工：手写 prop 加事件的组件若要用这些修饰符，需在触发处自行实现对应转换，框架不会代劳。

```html
<!-- 父组件：内置修饰符直接加在 v-model 后 -->
<MyInput v-model.number="age" />
<MyInput v-model.trim="nickname" />
```

> [!TIP]
> **建议内容**：能用 defineModel 就不手写，内置修饰符**开箱即用**；只有在维护必须手写的旧组件时，才需要把 .trim、.number 的转换逻辑补进 emit 之前的赋值语句里。

**速记**：defineModel 下 **.trim、.number、.lazy 自动生效**。



#### modelModifiers 自定义修饰符

**自定义修饰符**：框架允许自定义修饰符（如 .capitalize），声明在名为 modelModifiers 的 prop 中，组件读取它来决定如何加工负载。

- 父组件写 v-model.capitalize 加绑定值后，子组件会收到一个 modelModifiers 的 prop，值为 { capitalize: true }。
- 手写实现：在 emit 之前检查该 prop 并加工值，加工逻辑由组件自己负责。
- defineModel 实现：以数组解构拿到 ref 与修饰符对象，并在 set 钩子里加工，逻辑更集中。
- 修饰符可叠加：.capitalize 与 .number 同时使用时，modelModifiers 中会同时出现两个键。

```js
// 手写实现：声明 modelModifiers，emit 前加工
const props = defineProps({
  modelValue: String,
  modelModifiers: {
    default: () => ({}),
  },
})
const emit = defineEmits(['update:modelValue'])

function emitValue(event) {
  let value = event.target.value
  if (props.modelModifiers.capitalize) {
    value = value.charAt(0).toUpperCase() + value.slice(1)
  }
  emit('update:modelValue', value)
}
```

```js
// defineModel 实现：解构出修饰符，set 钩子加工
const [model, modifiers] = defineModel({
  set(value) {
    if (modifiers.capitalize) {
      return value.charAt(0).toUpperCase() + value.slice(1)
    }
    return value
  },
})
```

> 修饰符的本质是**父组件传给子组件的配置开关**：Vue 只负责把开关递进来，加工算法永远由子组件实现，所以同一个 .capitalize 在不同组件里可以有不同精度。

**速记**：修饰符经 **modelModifiers 传入**，加工逻辑**子组件自写**。



### 双向绑定的边界与辨析

#### v-model 与 v-bind 单向传值的辨析

**边界结论**：v-bind 是纯**单向传值**，父到子一去不回头；v-model 是在单向数据流之上封装的**受控双向**，双向的表象由事件回传撑起。

- v-bind：只把父状态作为 prop 递下去，子组件内部改动 prop 属于违规操作，父状态毫不知情。
- v-model：在 prop 下发之外还监听回传事件，子组件每次想改值都通过事件请示，最终由父组件落笔。
- 受控语义：父组件始终是值的唯一权威来源，子组件展示的值永远来自父组件最近一次写回。
- 选用标准：只读展示用 v-bind；表单值、开关状态等需要子组件发起修改的场景用 v-model。

> [!CAUTION]
> **注意内容**：子组件直接修改 props 传入的值（如给 props.modelValue 赋值）会触发 Vue 警告，且修改结果不会同步回父组件；把 v-bind 误当 v-model 用、指望子组件改值自动生效，是新手最常见的数据流事故。

**速记**：v-bind **只进不出**，v-model **出必经事件**。



#### 子组件修改父状态的合规路径

**合规路径**：子组件影响父状态只有两条正路，显式 emit 事件由父组件处理器修改，或使用 defineModel 由宏代为 emit。

- 路径一（emit）：defineEmits 声明语义化事件名（如 remove-item、update:modelValue），父组件在监听器里改自己的状态，意图清晰、可追溯。
- 路径二（defineModel）：简单值的双向同步交给宏，子组件对 model.value 赋值即等价请示，父组件状态随之更新。
- 复杂逻辑选路径一：删除列表项、提交表单等业务动作，用动词化事件名表达意图，而不是塞进 v-model。
- 纯值同步选路径二：输入框、开关、滑块这类值语义明确的控件，defineModel 最省代码。

```js
// 业务动作：语义化事件加父组件处理器
const emit = defineEmits(['remove-item'])
emit('remove-item', itemId)
```

```js
// 纯值同步：defineModel 直接写
const model = defineModel()
model.value = 42
```

> 判断标准看**语义**：改的是值本身选 defineModel，改的是父组件的一块业务状态选语义化 emit；两条路的共同点是**父组件永远是落笔人**，子组件只有建议权。

**速记**：子改父只有两正路：**emit 请示**或 **defineModel 代笔**。
