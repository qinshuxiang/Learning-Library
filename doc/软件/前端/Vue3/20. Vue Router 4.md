## Vue Router 4

### 前端路由的认识

#### 前端路由是 URL 与视图的映射关系

**前端路由**：是单页应用（SPA）中管理 **URL 与视图映射** 的机制，在不重新向服务器请求页面的前提下完成视图切换。

- **SPA 单页应用**：整个应用只有一个 HTML 页面，页面内容的变化全部由 JavaScript 驱动。
- **传统服务端路由**：每次导航都向服务器发起请求，由服务器返回完整的新 HTML 页面，期间浏览器会白屏重载。
- **前端路由的工作方式**：拦截地址变化，由 JavaScript 根据新地址匹配对应组件并渲染，同时更新地址栏，全程不发页面请求。

> 前端路由与服务端路由的本质差别在于 **页面是谁渲染的**：服务端路由返回整页 HTML，前端路由只换视图不换页面。正因如此，SPA 切换页面时不会丢失前端状态，体验接近原生应用。

**速记**：前端路由 **只换视图不换页**，URL 与组件的映射由 JS 接管。



#### hash 模式基于锚点且无需服务器配置

**hash 模式**：URL 中以井号分隔路由地址的模式，通过 createWebHashHistory 创建，例如 https://example.com/#/users。

- 原理：井号后的部分是 **URL 的锚点（hash）**，其变化只触发 hashchange 事件，**不会向服务器发请求**。
- 优点：无需服务器任何配置，部署到任意静态服务器都能直接使用。
- 缺点：地址中始终带着井号，不够美观；且锚点语义会被路由占用，无法再用于页面内定位。

> hash 部分根本不会被发送到服务器，因此无论地址怎么变，服务器看到的始终是井号前的同一页面。这就是 hash 模式天然不需要 history fallback 配置的原因。

**速记**：hash 模式 **井号内变化不出网**，零配置可用。



#### history 模式依赖 History API 且需要服务器回退

**history 模式**：基于 HTML5 的 History API（pushState、replaceState 与 popstate 事件）实现的模式，通过 createWebHistory 创建，地址干净无井号。

- 原理：用 pushState 与 replaceState **改写地址栏但不发请求**，用 popstate 事件监听浏览器前进后退。
- 优点：URL 与传统服务端路由的地址形态一致，利于 SEO 与分享。
- 缺点：用户在深层路径上 **刷新或直接访问** 时，浏览器会把完整路径发给服务器，而服务器上并不存在该路径的资源，会返回 404。
- 解决方式：服务器需要配置 **history fallback**，把所有未匹配到的请求统一回退到 index.html，交给前端路由接管。

以 nginx 为例的回退配置：

```text
location / {
  try_files $uri $uri/ /index.html;
}
```

> [!WARNING]
> **警告内容**：history 模式部署时若遗漏 fallback 配置，用户从首页进入应用一切正常，但 **刷新或分享深层链接就会 404**。这是 history 模式最常见的线上事故，部署前务必确认服务器配置。

**速记**：history 模式 **地址干净但要配回退**。



### 安装与注册

#### 用 createRouter 创建实例并 app.use 注册

**注册流程**：Vue Router 4 通过 npm 安装，用 createRouter 创建路由实例，再通过 app.use 挂载到应用，核心是 **createRouter、history、routes 三要素**。

- 安装命令：npm install vue-router@4，Vue 3 必须搭配 Router 4，Router 3 仅支持 Vue 2。
- createRouter 接收配置对象，history 项决定路由模式，routes 项声明路由表。
- app.use(router) 完成注册后，任意组件内均可使用路由能力。

```js
import { createApp } from "vue";
import { createRouter, createWebHistory } from "vue-router";
import Home from "./views/Home.vue";
import Users from "./views/Users.vue";

const router = createRouter({
  history: createWebHistory(), // hash 模式改用 createWebHashHistory()
  routes: [
    { path: "/", component: Home },
    { path: "/users", component: Users },
  ],
});

const app = createApp(App);
app.use(router);
app.mount("#app");
```

> createRouter 是工厂函数而非构造函数，**不加 new**。routes 中每一项的最小结构是 path 加 component，路径以斜杠开头表示从根出发的绝对地址。

**速记**：createRouter 配 **history 与 routes**，app.use 完成注册。



#### router-view 是渲染出口而 router-link 是导航入口

**router-view 与 router-link**：是路由系统的两大内置组件，前者声明 **匹配组件的渲染出口**，后者提供 **声明式的导航入口**。

- router-view 是占位容器，URL 匹配到哪条路由，对应组件就渲染在它内部。
- router-link 最终渲染为 a 标签，并 **自动拦截点击的默认行为**，改由路由系统完成切换，页面不重载。
- router-link 具备激活状态 class：当前路径匹配时追加 router-link-active，完全匹配时追加 router-link-exact-active，可用于高亮导航样式。

```html
<template>
  <nav>
    <router-link to="/">首页</router-link>
    <router-link to="/users">用户列表</router-link>
  </nav>
  <router-view />
</template>
```

> 不要手写 a 标签做站内跳转：裸 a 标签会触发真实的页面请求，导致整页重载，SPA 的状态全部丢失。router-link 渲染出的 a 标签之所以不会重载，是因为路由系统接管了它的点击事件。

**速记**：router-view 管 **渲染出口**，router-link 管 **导航入口**。



#### to 支持对象写法与命名路由

**to 的两种写法**：router-link 的 to 属性既接受字符串路径，也接受对象形式，对象写法配合 **命名路由** 可以让跳转与具体路径解耦。

- 字符串写法：to="/users"，直接写目标路径。
- 对象写法按 name 跳转：to 为 { name: "user", params: { id: 1 } }，路由表须先给该路由声明 name 字段。
- 对象写法按 path 跳转：to 为 { path: "/users/1" }，此时 params 不生效，参数要手写进路径或放进 query。

路由表声明命名路由：

```js
{ path: "/users/:id", name: "user", component: User }
```

用命名路由跳转：

```html
<router-link :to="{ name: 'user', params: { id: 1 } }">用户详情</router-link>
```

> **按 name 跳转优先于按 path 跳转**：路径调整时只需改路由表，代码里按 name 的跳转不受影响；按 path 写死字符串的跳转则要在所有调用点同步修改。命名路由是大型项目的推荐做法。

**速记**：to 可传 **字符串或对象**，对象配 name 与路径解耦。



### 动态路由匹配

#### 路径参数通过冒号声明并由 params 读取

**动态路由**：用冒号声明 **路径参数** 的路由匹配方式，例如 /users/:id 能同时匹配 /users/1 与 /users/abc，参数值通过 route.params 读取。

- 路由表声明：{ path: "/users/:id", component: User }，冒号后是参数名。
- 组件内读取：useRoute 拿到当前路由对象，params.id 即路径中的实际值，类型是字符串。
- 支持多个参数：/users/:userId/posts/:postId，params 中同时携带 userId 与 postId。
- 支持可选参数：写成 /users/:id?，id 缺省时 params.id 为 undefined。

```vue
<script setup>
import { useRoute } from "vue-router";

const route = useRoute();
console.log(route.params.id); // 访问 /users/42 时输出 "42"
</script>
```

> params 的值 **永远是字符串**：地址栏里的内容没有类型信息，42 与 "42" 不必混淆，需要数字时自行转换。若参数值可能含斜杠等特殊字符，可使用自定义正则约束，如 /users/:id(\\d+) 只匹配数字。

**速记**：冒号声明 **路径参数**，params 读值且恒为字符串。



#### 参数变化时组件实例被复用

**组件复用问题**：从 /users/1 导航到 /users/2 时，由于匹配的是 **同一条路由**，组件实例会被复用，生命周期钩子不会重新执行，写在 onMounted 里的数据请求也就不会再次触发。

- 复用是性能优化：组件销毁重建成本高，路由系统默认复用同组件的实例。
- 副作用：依赖生命周期发请求的写法在参数变化时失灵，页面显示旧数据。
- 方案一：侦听路由对象，参数变化时重新拉取数据。
- 方案二：使用组件内守卫 onBeforeRouteUpdate，在导航确认前拿到新旧参数。

```js
import { watch } from "vue";
import { useRoute, onBeforeRouteUpdate } from "vue-router";

const route = useRoute();

// 方案一：watch 侦听参数
watch(
  () => route.params.id,
  (newId) => {
    fetchUser(newId);
  }
);

// 方案二：组件内更新守卫
onBeforeRouteUpdate((to, from) => {
  fetchUser(to.params.id);
});
```

> [!IMPORTANT]
> **重要内容**：参数变化触发的是 **复用而非重建**，onMounted 只会执行一次。判断用哪种方案：只需响应数据变化用 watch；需要在导航完成前拦截或取消（如校验新参数合法性）则用 onBeforeRouteUpdate。

**速记**：同组件换参数 **实例复用**，watch 或 onBeforeRouteUpdate 二选一。



### 路由传参

#### params 与 query 的区别

**params 与 query**：是导航传参的两种途径，params 是 **路径的一部分**，query 是 **路径之后的查询串**，二者在写法、形态与行为上均有差别。

- 写法差别：params 对应路径参数 /users/:id 中的 id；query 对应 /users?page=2 中问号后的键值对。
- 读取方式：params 从 route.params 读取，query 从 route.query 读取。
- URL 形态：params 拼进路径本体，query 以问号开头、多个键值对用与号连接，如 /users?page=2&size=10。
- 保留行为：两者都会体现在地址栏，刷新后均在；但 Router 4.1 起明确规定，目标路由未声明路径参数时 params 会被忽略，**params 不再支持脱离路径定义单独传参**。

```html
<router-link :to="{ name: 'users', query: { page: 2 } }">第二页</router-link>
```

> 选择标准看 **语义**：参数是定位资源的标识（用户 id、文章 id）用 params；参数只是修饰查询的可选项（页码、关键字、排序）用 query。query 还天然支持数组值，写成 { tags: ["vue", "router"] } 会序列化为多个同名键。

**速记**：params 是 **路径身份**，query 是 **查询修饰**。



#### props 模式实现参数与组件解耦

**props 模式**：让路由参数以 props 形式注入组件，组件不再依赖 route 对象取值，从而与路由系统 **解耦**，可在任意父组件中复用。

- 布尔模式：路由配置 props: true，把 params 中与组件 props 同名的项整体传入，最常用。
- 对象模式：props 是静态对象，传入固定值，多用于与参数无关的静态配置。
- 函数模式：props 接收 route 对象并返回对象，可自由组合 params 与 query，灵活性最高。

```js
// 布尔模式：params.id 注入同名 prop
{ path: "/users/:id", component: User, props: true }

// 函数模式：同时注入路径参数与查询参数
{
  path: "/search",
  component: Search,
  props: (route) => ({ keyword: route.query.keyword, page: route.query.page }),
}
```

组件侧不再触碰 route：

```vue
<script setup>
defineProps(["id"]);
// 直接使用 id，无需 useRoute
</script>
```

> props 模式的核心收益是 **组件脱离路由可独立测试**：组件只认 props，不关心数据来自路由还是父组件。函数模式注意保持纯函数，仅做取值映射，不要在其中发请求或写副作用。

**速记**：props 三模式 **布尔、对象、函数**，组件只认 props 不认路由。



### 嵌套路由与命名视图

#### children 声明子路由并由父级 router-view 渲染

**嵌套路由**：通过 children 数组在一条路由下声明子路由，子组件渲染在 **父组件模板内的 router-view** 中，形成多层视图结构。

- 路由表中父路由带 children 数组，子路由对象写在其中。
- 子路由的 path **不以斜杠开头** 时为相对路径，自动拼接父路径；以斜杠开头则为绝对路径。
- 父组件模板中必须再写一个 router-view 作为子路由的出口，否则子组件无处渲染。

```js
{
  path: "/user",
  component: UserLayout,
  children: [
    { path: "profile", component: UserProfile },   // 匹配 /user/profile
    { path: "settings", component: UserSettings }, // 匹配 /user/settings
  ],
}
```

```html
<!-- UserLayout.vue -->
<template>
  <h2>用户中心</h2>
  <nav>
    <router-link to="/user/profile">资料</router-link>
    <router-link to="/user/settings">设置</router-link>
  </nav>
  <router-view />
</template>
```

> URL 的层级与 router-view 的嵌套层级 **一一对应**：每多一层 children，视图结构就多一层出口。忘记在父组件写 router-view 是嵌套路由最典型的错误，表现为地址变了但子组件不出现。

**速记**：children 配 **父级 router-view**，路径层层拼接。



#### 默认子路由用空 path 声明

**默认子路由**：当用户只访问父路径、未指定子路径时呈现的内容，通过 **空字符串 path** 的子路由声明。

- 写法：在 children 中加一条 { path: "", component: UserHome }，访问 /user 时它直接渲染。
- 代替方案：父路由配置 redirect: "/user/home"，把父路径重定向到某个具名子路由，地址栏会显式变化。
- 空子路由与 redirect 的取舍：空子路由保持地址栏为 /user，redirect 则让地址栏落到子路径上。

```js
{
  path: "/user",
  component: UserLayout,
  children: [
    { path: "", component: UserHome }, // 访问 /user 时渲染
    { path: "profile", component: UserProfile },
  ],
}
```

> 空子路由匹配父路径本身，此时 **父级 router-view 里渲染的是空子路由的组件**，父路由自己的 component 依旧正常渲染。若父路由连 component 都没写，仅作路径组织之用，则直接渲染匹配到的子组件。

**速记**：空 path 子路由 **兜底父路径**，redirect 让地址显式跳转。



#### 命名视图用 components 渲染多个出口

**命名视图**：在同一路由层级用多个带 name 的 router-view 渲染多个组件，路由配置改用 **components 复数对象**，key 对应视图名，default 对应无名视图。

- 模板侧：router-view 不带 name 是默认出口，router-view name="sidebar" 是命名出口。
- 路由侧：components 写法为 { default: Main, sidebar: SideBar }。
- 典型场景：后台布局中主内容、侧边栏、顶栏同属一条路由，需要同时切换。

```js
{
  path: "/dashboard",
  components: {
    default: DashboardMain,
    sidebar: DashboardSidebar,
  },
}
```

```html
<template>
  <router-view name="sidebar" />
  <router-view />
</template>
```

> 命名视图与嵌套路由解决的问题不同：嵌套路由解决 **上下层级** 的视图结构，命名视图解决 **同层并列** 的多出口。components 忘写成 component 是命名视图的高频笔误，表现为侧边栏永远渲染不出来。

**速记**：命名视图 **components 配 name**，同层多出口并列渲染。



### 编程式导航

#### push、replace 与 go 的分工

**编程式导航**：在代码中调用路由实例的方法完成跳转，核心是 **router.push、router.replace、router.go 三个方法**。

- router.push(location)：跳转到新地址，**向历史栈压入一条记录**，浏览器可后退回原页面。
- router.replace(location)：跳转但 **替换当前历史记录**，不新增记录，后退会跳过当前页。
- router.go(n)：在历史栈中前进或后退 n 步，n 为负数后退，正数前进，栈中无对应记录时静默失败。
- push 与 replace 均返回 Promise，可链 then 或 catch 处理导航结果。

```js
import { useRouter } from "vue-router";

const router = useRouter();

router.push("/users/1");
router.push({ name: "user", params: { id: 1 } }); // 对象写法与 to 一致
router.replace("/login");                          // 登录后不留登录页历史
router.go(-1);                                     // 等价于点浏览器后退
```

> 选用标准看 **历史栈语义**：普通跳转用 push；跳转后不希望用户后退回当前页（如登录页、支付完成页）用 replace；实现返回按钮用 go(-1)。滥用 replace 会让用户丢失返回路径，慎用。

**速记**：push **进栈**，replace **顶替**，go **栈内移动**。



#### 编程式导航与 router-link 内部等价

**等价关系**：router-link 的本质就是一次 router.push，to 属性的值原样传给 push，因此两者能力完全一致，可按场景互换。

- router-link 适合模板中的静态导航入口，自动获得 a 标签语义与激活 class。
- 编程式导航适合逻辑触发的跳转：登录成功后跳首页、提交表单后跳详情、事件回调中带条件跳转。
- to 与 push 的对象写法完全相同：{ name, params }、{ path, query } 通用。

```js
// 点击后的两段代码等价
// <router-link :to="{ name: 'user', params: { id: 5 } }">详情</router-link>
router.push({ name: "user", params: { id: 5 } });
```

> router-link 渲染为 a 标签是 **可配置的**，custom 属性配合插槽可以自定义渲染内容，用于按钮样式的导航。反之，逻辑分支里的跳转不要硬塞 router-link，用 push 更直白。

**速记**：router-link 就是 **模板化的 push**，按声明式或命令式场景选用。



### 导航守卫体系

#### 全局守卫覆盖每一次导航

**全局守卫**：注册在路由实例上、对 **每一次导航** 都生效的钩子，按执行时机分为 beforeEach、beforeResolve、afterEach 三个。

- router.beforeEach(to, from)：导航被确认 **之前** 触发，是权限校验、登录拦截的主战场。
- router.beforeResolve(to, from)：在所有组件内守卫与异步路由组件解析完毕 **之后、导航确认之前** 触发，适合做依赖最终数据的检查。
- router.afterEach(to, from)：导航确认 **之后** 触发，无法取消导航，适合埋点上报、修改页面标题。
- to 是即将进入的目标路由对象，from 是正要离开的路由对象。

```js
router.beforeEach((to, from) => {
  // 返回 false 可取消导航
});

router.afterEach((to, from) => {
  document.title = to.meta.title ?? "默认标题";
});
```

> afterEach 里 **改不了导航结果**，此时导航已被确认、页面即将切换。需要拦截跳转的逻辑必须放在 beforeEach 或 beforeResolve，放错位置的拦截代码不会报错但完全失效，需警惕。

**速记**：beforeEach **拦在事前**，afterEach **收尾事后**，beforeResolve 兜底确认前。



#### 路由独享守卫与组件内守卫各管一段

**守卫的分级**：除全局守卫外，还有定义在路由配置上的 **路由独享守卫 beforeEnter** 与定义在组件内部的 **组件内守卫 onBeforeRouteUpdate、onBeforeRouteLeave**。

- beforeEnter：写在单条路由配置里，只在该路由进入时触发，参数与返回值规则同全局 beforeEach。
- onBeforeRouteUpdate：组件被复用、路由参数变化时触发，对应本章动态路由的复用问题。
- onBeforeRouteLeave：离开该组件对应的路由时触发，典型用途是拦截未保存的表单。

```js
// 路由配置中的独享守卫
{
  path: "/admin",
  component: Admin,
  beforeEnter: (to, from) => {
    return isAdmin() || false; // 非管理员取消导航
  },
}
```

```vue
<script setup>
import { onBeforeRouteLeave } from "vue-router";

onBeforeRouteLeave((to, from) => {
  if (hasUnsavedChanges() && !confirm("改动尚未保存，确定离开？")) {
    return false; // 阻止离开
  }
});
</script>
```

> 守卫作用域 **由小到大、由内到外** 依次执行：离开旧组件、全局 beforeEach、更新组件、独享 beforeEnter、解析完成 beforeResolve。作用域越小的守卫越后于全局守卫之前确认，按流程顺序记忆即可，完整顺序见下文解析流程。

**速记**：beforeEnter **独享单路由**，Update 管复用，Leave 管离开。



#### 现代返回值风格不再依赖 next

**现代返回值风格**：Vue Router 4 的守卫通过 **返回值** 决定导航走向，无需调用 next 参数，这是 Router 4 与 Router 3 在守卫写法上的核心差异。

- 返回 false：取消导航，停留原页面。
- 返回一个路由地址：发生重定向，导航转向该地址，可传路径字符串或对象。
- 返回 undefined 或 true：放行，继续正常流程。
- 守卫支持 async 函数：可先 await 校验接口，再按结果返回，异步逻辑天然顺畅。

```js
router.beforeEach(async (to, from) => {
  const hasToken = !!getToken();
  if (to.meta.requiresAuth && !hasToken) {
    return { name: "login", query: { redirect: to.fullPath } }; // 重定向
  }
  if (hasToken && to.name === "login") {
    return "/"; // 已登录访问登录页，直接回首页
  }
  // 不写返回值即放行
});
```

> [!IMPORTANT]
> **重要内容**：next 参数在 Router 4 中 **仍然可用但不推荐**，官方明确新代码一律采用返回值风格。二者混用时，一旦调用了 next 就 **必须调用且只调用一次**，否则守卫会陷入不确定状态；返回值风格从机制上杜绝了漏调与重调问题。

**速记**：返回 **false 取消、地址重定向、不写放行**，不再用 next。



#### 完整的导航解析流程有固定次序

**导航解析流程**：一次导航从触发到落地，守卫与渲染按 **固定次序** 执行，掌握顺序是排查跳转问题的基础。

完整次序如下：

1. 导航被触发，路由开始解析。
2. 失活组件内触发 onBeforeRouteLeave。
3. 触发全局 router.beforeEach。
4. 复用组件内触发 onBeforeRouteUpdate（参数变化时）。
5. 依次调用路由配置中的 beforeEnter。
6. 解析异步路由组件（懒加载的组件在此刻下载）。
7. 触发全局 router.beforeResolve。
8. 导航被确认，触发全局 router.afterEach。
9. 触发 DOM 更新，router-view 渲染新组件。

> 两条记忆主线：**守卫链在先、DOM 更新在后**；**离开的先走（Leave），进入的后走（Enter 类）**。懒加载组件的下载发生在 beforeEnter 之后、beforeResolve 之前，首屏慢可从这一环排查分块体积。

**速记**：**Leave、beforeEach、Update、beforeEnter、Resolve、afterEach、DOM**，一条链走完。



### 路由元信息与权限控制

#### meta 承载路由的附加数据

**路由元信息 meta**：路由配置上的自由字段，用于给路由 **附加业务数据**（标题、权限标记、是否缓存等），运行时通过 route.meta 读取。

- meta 的值是任意对象，如 { path: "/admin", component: Admin, meta: { requiresAuth: true, title: "后台" } }。
- Router 4 中 to.meta 是 **所有匹配路由的 meta 合并结果**：嵌套路由中子页能直接读到父路由的 meta，无需遍历 route.matched。
- meta 只是被路由系统透传的数据，字段名与结构完全由业务自定义。

```js
const routes = [
  {
    path: "/admin",
    component: AdminLayout,
    meta: { requiresAuth: true },
    children: [{ path: "stats", component: Stats }], // 子页 meta 合并后也有 requiresAuth
  },
];
```

> meta 合并是 Router 4 的行为升级，Router 3 中读取父级 meta 需要手动遍历 to.matched 逐层查找。但合并只做 **浅合并**，父子同名深字段并不会递归合并，结构复杂时仍需自查层级。

**速记**：meta 挂 **业务标记**，Router 4 自动沿匹配链合并。



#### beforeEach 校验 requiresAuth 是权限控制的标准范式

**requiresAuth 校验**：在全局 beforeEach 中检查目标路由 meta 的 requiresAuth 标记，未登录则重定向到登录页，是前端权限控制 **最经典的落地范式**。

- 步骤一：登录相关路由的 meta 标注 requiresAuth: true。
- 步骤二：beforeEach 中判断标记与登录态，未登录返回重定向到登录页。
- 步骤三：重定向时带上 redirect 参数记录原目标，登录成功后跳回，避免用户丢失操作路径。

```js
router.beforeEach((to) => {
  if (to.meta.requiresAuth && !getToken()) {
    return { name: "login", query: { redirect: to.fullPath } };
  }
});
```

```js
// 登录成功后回到原目标
const route = useRoute();
router.push(route.query.redirect ?? "/");
```

> [!CAUTION]
> **注意内容**：重定向目标本身若也带 requiresAuth 标记且未登录，会造成 **登录页与目标页之间的无限重定向**。防范方式是确保登录页路由不带 requiresAuth，或在守卫开头先判断 to.name === "login" 直接放行。

**速记**：meta 打标、beforeEach 校验、**未登录带 redirect 回跳**。



### 组合式 API

#### useRouter 与 useRoute 是 setup 中的替代

**useRouter 与 useRoute**：是组合式 API 下获取路由能力的一对函数，useRouter 返回 **路由实例**，useRoute 返回 **当前路由的响应式对象**，用于在 script setup 中替代选项式 API 的 this.$router 与 this.$route。

- useRouter()：拿到 router 实例，调用 push、replace、go 等编程式导航方法。
- useRoute()：拿到当前路由对象，读 params、query、meta、fullPath 等信息。
- 二者本质是 provide 与 inject 的封装，**只能在 setup 上下文中调用**，不能在组件外裸调用。

```vue
<script setup>
import { useRouter, useRoute } from "vue-router";

const router = useRouter();
const route = useRoute();

function goDetail() {
  router.push({ name: "user", params: { id: route.params.id } });
}
</script>
```

> **router 与 route 是两个对象**：前者是操作者（发号施令做跳转），后者是观测者（只读描述当前在哪）。选项式 API 中 this.$router 与 this.$route 的对应关系保持不变，只是获取方式换成了函数调用。

**速记**：useRouter **管跳转**，useRoute **管读参**，仅限 setup 内调用。



#### useRoute 的返回值不可解构使用

**响应性陷阱**：useRoute 返回的是当前路由的 **响应式代理对象**，对它做对象解构会让解构出的变量失去响应性，参数变化后视图不更新。

- 错误写法：const { id } = useRoute()，id 在路由变化后仍是旧值。
- 正确写法一：始终通过 route.params.id 访问。
- 正确写法二：需要局部变量时用 computed 包裹，如 computed(() => route.params.id)。
- 侦听参数同样基于函数式写法：watch(() => route.params.id, 回调)。

```js
const route = useRoute();

// 错误：失去响应性
// const { id } = useRoute();

// 正确：保持响应性
const userId = computed(() => route.params.id);
```

> [!CAUTION]
> **注意内容**：解构后不报错、不抛异常，只是 **静默失效**，属于难以排查的隐性 bug。这与 Vue 3 中解构 reactive 对象丢失响应性是同一原理，凡响应式对象都要先想清楚再解构。

**速记**：route **解构即失响应**，用 route.xxx 或 computed 包裹。



### 路由懒加载

#### 动态 import 让路由按需分块

**路由懒加载**：把路由的 component 写成动态 import 的函数，让该页面被打包工具 **拆成独立的 JS 分块**，只有真正导航到这条路由时才下载执行。

- 写法：component: () => import("./views/Users.vue")，返回 Promise 的工厂函数。
- 收益：页面代码不再全部打进首屏主包，首屏体积变小、加载变快，访问量低的页面尤其划算。
- 配合分包：构建工具会为每个动态 import 生成独立 chunk，可用注释定制分块名，如 import("./views/Users.vue") 前加 webpackChunkName 类注释（Vite 中用 rollup 原生分包策略）。

```js
const routes = [
  { path: "/", component: Home }, // 同步引入，进主包
  {
    path: "/users",
    component: () => import("./views/Users.vue"), // 懒加载，独立分块
  },
];
```

> 判断是否懒加载只看 **component 是组件对象还是函数**：写组件对象是同步引入，写返回 import 的箭头函数才是懒加载。懒加载组件在导航解析流程中于 beforeEnter 之后、beforeResolve 之前下载，守卫链会等待它就绪再继续。

**速记**：component 写成 **箭头函数包 import**，按路由分块、按需加载。



### 4.4+ 新特性

#### View Transitions API 简化页面切换过渡

**View Transitions 支持**：Vue Router 4.4 起原生接入浏览器的 View Transitions API，导航切换视图时可由浏览器生成 **平滑的过渡动画**，无需再依赖自定义过渡组件的完整配置。

- 启用方式：在支持该 API 的浏览器（Chromium 系）中，路由切换时通过 document.startViewTransition 包裹 DOM 更新，Router 提供了官方接入指引，按需在导航流程中包裹。
- 动画定义：为根或元素设置 view-transition-name，再在 CSS 中通过 view-transition-old 与 view-transition-new 伪元素定制时长与效果，例如把过渡时长定为 0.3 秒。
- 兼容行为：不支持的浏览器自动退化为 **无动画的普通切换**，不影响功能。

> View Transitions 的优势是 **动画由浏览器在合成层驱动**，比传统 CSS 过渡更流畅且实现更薄。它属于渐进增强：代码按标准 API 编写，老浏览器自动降级，不写兜底动画也不会报错。

**速记**：4.4 接入 **View Transitions**，浏览器驱动过渡，不支持则自动降级。



#### Data Loading API 提供路由级数据加载

**Data Loading API**：Vue Router 4.4 起提供的实验性数据加载方案，让路由组件通过 **data 选项与 loader 加载器** 在导航过程中预取数据，替代过去在 onMounted 里发请求的模式。

- 解决的问题：onMounted 的请求发生在组件渲染之后，容易先渲染空页面再闪一次加载态；路由级加载把请求提前到 **导航流程内**，数据与视图同步就绪。
- 组成部分：路由组件内用官方提供的 defineLoader 创建加载器，data 选项声明数据来源，配套组合式函数管理加载中、加载失败等状态。
- 定位：该 API 目前为 **实验性**，细节仍在演进，生产使用前以官方文档最新口径为准。

> 与传统守卫取数据的差别：beforeEach 等守卫适合做 **能否进入** 的判断，Data Loading API 专注于 **进入时取什么数据**，两者职责不同可并行使用。数据失败时的重试与错误页处理，加载器体系内置了对应机制。

**速记**：Data Loading 把请求 **提前进导航流程**，实验性特性留意官方更新。



#### 类型化路由让路由跳转获得编译期检查

**类型化路由（Typed Routes）**：Vue Router 4.4 起支持的实验性能力，为 to、push 的目标生成 **精确的类型定义**，路径拼错或参数缺失能在编译期直接报错。

- 工作方式：配合官方工具从路由表生成类型文件，在 tsconfig 中引入后，router-link 的 to 与 router.push 的字符串或对象参数都会被类型系统约束。
- 核心收益：命名路由拼错、params 漏传、路径写错等问题从 **运行期白屏** 提前到 **编辑期红线**，重构路由时能立即发现全部失效调用点。
- 适用前提：项目使用 TypeScript，并按官方指引接入类型生成流程。

> 类型化路由与 Data Loading 一样处于实验阶段，配置细节随版本演进。判断是否值得接入看项目规模：路由多、跳转分散的中大型项目收益明显，小型项目成本可能高于收益。

**速记**：类型化路由把 **写错的路径提前到编译期报错**，TS 项目重构利器。
