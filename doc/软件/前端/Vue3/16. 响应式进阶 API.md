## 响应式进阶 API

### 浅层响应式变体

#### shallowRef 只追踪 value 的整体替换

**shallowRef**：是 ref 的浅层版本，只对 .value 的整体赋值建立响应式追踪，其内部嵌套属性的变化不被追踪。

- 创建方式：调用 shallowRef(初始值)，返回一个只暴露 .value 这一层响应的引用。
- 响应边界：只有 state.value = 新对象 这类整体替换会触发依赖更新。
- 嵌套修改：state.value.count++ 这类深层属性修改不会触发任何更新，界面保持原样。
- 内部身份：.value 里存放的始终是原始对象，不会被转为 Proxy 代理。
- 适用场景：体量大的数据、第三方类实例、只需整体替换的不可变数据结构。

```js
import { shallowRef } from "vue";

const state = shallowRef({ count: 1 });

function increment() {
  state.value.count++;                            // 不触发更新：嵌套修改不被追踪
  state.value = { count: state.value.count + 1 }; // 触发更新：整体替换 .value
}
```

> [!NOTE]
> **提醒内容**：shallowRef 的价值在于省成本：深层 ref 会为整棵对象树的每一层建立代理，而 shallowRef 只处理 .value 一层。对 echarts 实例、地图实例这类第三方对象，或上万行的表格数据，用 shallowRef 包裹可避免代理化带来的性能损耗与内部逻辑干扰。

**速记**：shallowRef **只认整体替换**，嵌套修改不通知。



#### triggerRef 手动强制触发更新

**triggerRef**：强制触发与一个浅层 ref 关联的所有副作用，是为 shallowRef 补上手动通知能力的配套 API。

- 签名：triggerRef(目标 ref)，无返回值，传入需要强制通知的浅层引用即可。
- 典型配合：修改 shallowRef 的内部嵌套属性之后调用一次，让界面同步这次变化。
- 适用场景：数据体量太大不值得深层响应式，但偶有内部修改需求的位置。
- 边界说明：深层 ref 的内部修改本来就会自动触发更新，无需也无法从 triggerRef 获益。

```js
import { shallowRef, triggerRef } from "vue";

const bigList = shallowRef([
  /* 上万条数据 */
]);

function markFirstDone() {
  bigList.value[0].done = true; // 内部修改，不会自动触发更新
  triggerRef(bigList);          // 手动强制通知，界面同步刷新
}
```

> triggerRef 的意义是用一次手动通知换取省掉整棵树的成本：深层响应式对访问到的每层嵌套都建立代理，而 shallowRef 加 triggerRef 只在明确修改处通知一次，这正是官方文档推荐的、用于替换昂贵深层响应式的做法。

**速记**：改了内部属性，**调一次 triggerRef 补通知**。



#### shallowReactive 与 shallowReadonly 仅代理首层

**shallowReactive 与 shallowReadonly**：分别是 reactive 与 readonly 的浅层版本，只对对象的第一层属性建立代理或只读限制。

- shallowReactive：第一层属性的读写是响应式的；深层嵌套属性不代理、修改不触发更新。
- shallowReadonly：第一层属性只读，赋值会被拒绝；深层嵌套属性不受只读约束。
- 与 shallowRef 的分工：shallowRef 针对 .value 整体，shallowReactive 针对对象首层键值。
- 共同特征：深层嵌套对象始终保持原始对象身份，不被转为代理。

```js
import { shallowReactive, shallowReadonly } from "vue";

const state = shallowReactive({ foo: 1, nested: { bar: 2 } });
state.foo = 2;         // 响应式：第一层属性
state.nested.bar = 3;  // 非响应式：深层属性不代理、不通知

const frozen = shallowReadonly({ foo: 1, nested: { bar: 2 } });
// frozen.foo = 9       第一层只读，开发环境警告且赋值无效
frozen.nested.bar = 9; // 静默成功：深层不受只读约束
```

> [!WARNING]
> **警告内容**：shallowReadonly 只保护第一层，深层嵌套对象仍可被静默修改，不能用它替代 readonly 去保护共享状态；需要整棵树只读时必须使用深层的 readonly。

**速记**：浅层变体**只管首层**，深层裸奔不代理。



### 只读代理与原始对象

#### readonly 深层只读代理

**readonly**：接收一个对象或 ref，返回一个深层只读的代理，任何层级的属性修改都会被拒绝。

- 深层只读：嵌套对象在访问时同样被转为只读代理，整棵树不可写。
- 修改行为：任何赋值都会被忽略，开发环境在控制台发出警告，生产环境静默失败。
- 传入 ref：readonly(某个 ref) 返回的代理在 .value 层同样只读。
- 典型用途一：保护跨组件共享的全局状态，防止使用方意外改写。
- 典型用途二：props 的只读约定，组件不应在子组件内部修改传入的 props。

```js
import { readonly, reactive } from "vue";

const original = reactive({ count: 0, nested: { value: 1 } });
const copy = readonly(original);

// copy.count = 1     开发环境警告，修改无效
original.count = 1;   // 合法：仍可通过原始响应式对象修改
```

> readonly 与原对象共享同一份数据：通过原始对象修改后，只读代理读到的也是新值。readonly 是视图层的写保护，不是复制快照；需要独立快照时应先深拷贝再 readonly。

**速记**：readonly **整树只读、数据同源**，改原对象照常生效。



#### markRaw 标记对象永不转为代理

**markRaw**：给对象打上永不转为代理的标记，即使它此后被 reactive 或 readonly 包裹，也始终保持原始对象身份。

- 签名：markRaw(原始对象)，返回打上标记的原对象本身。
- 场景一：第三方类实例，如地图实例、图表实例、复杂的日期对象，代理化会破坏内部逻辑或徒增开销。
- 场景二：大型静态数据，如上万行且不会局部更新的表格数据，代理化成本远超收益。
- 行为要点：被标记的对象放进 reactive 返回的代理中时，该属性读出来就是原始对象。

```js
import { reactive, markRaw } from "vue";

class Stock {
  constructor(symbol) {
    this.symbol = symbol;
    this.price = 0;
  }
}

const state = reactive({
  stock: markRaw(new Stock("AAPL")),
  count: 0,
});

state.stock.price = 100; // 不触发更新：stock 属性未被代理
state.count = 1;         // 触发更新：count 是普通响应式属性
```

> [!IMPORTANT]
> **重要内容**：标记必须在对象首次进入响应式系统之前打好：已经被代理过的对象再补 markRaw 也无法撤销既有的代理行为。同时，markRaw 是永久标记，日后想让这份数据恢复响应式就得换新对象，不要对将来可能需要深层响应式的数据滥用此标记。

**速记**：markRaw **提前打标、永不代理**，第三方实例首选。



#### toRaw 拿到代理背后的原始对象

**toRaw**：返回 reactive 或 readonly 代理背后的原始对象，是面向只读操作与外部对接的转换工具。

- 签名：toRaw(代理对象)，传入的不是代理时原样返回。
- 用途一：读取原始对象做只读处理，避免经过代理的依赖追踪开销。
- 用途二：与第三方库对接时交出原始对象，防止库内部修改触发不可预期的更新。
- 关键辨析：通过原始对象修改数据不会触发任何更新，因为依赖建立在代理层而非原始对象上。
- 与 markRaw 的方向相反：markRaw 阻止对象将来被代理，toRaw 是从已代理对象找回原始对象。

```js
import { reactive, toRaw } from "vue";

const state = reactive({ count: 1 });
const raw = toRaw(state);

raw.count = 2;
console.log(state.count); // 2：数据同源，读取到新值
// 但这次赋值不经过代理，不会触发依赖更新，界面不刷新
```

> [!CAUTION]
> **注意内容**：通过 toRaw 拿到的原始对象写数据属于绕过响应式系统的危险操作，界面与数据会出现不同步；除非确认该修改不需要反映到视图（如序列化、与外部库比对），否则不要通过原始对象改状态。

**速记**：toRaw **取原身、不触发更新**，只读与对接用。



### customRef 自定义引用

#### customRef 显式声明追踪与触发

**customRef**：创建一个自定义 ref，显式声明依赖的追踪时机与更新的触发时机，签名接受一个工厂函数。

- 工厂函数：接收 track 与 trigger 两个函数作为参数，返回一个带 get 与 set 的普通对象。
- track：在 get 中调用，声明这次取值需要收集依赖，通常即时调用。
- trigger：在 set 中调用，声明值已变化、应当通知依赖；调用时机由开发者决定，可以延迟。
- 返回结构：get 负责取值并追踪，set 负责赋值并按自定义策略触发通知。

```js
import { customRef } from "vue";

function useUppercaseRef(initialValue) {
  return customRef((track, trigger) => ({
    get() {
      track();
      return initialValue.toUpperCase();
    },
    set(newValue) {
      initialValue = newValue;
      trigger();
    },
  }));
}
```

> customRef 暴露了深层 ref 内部隐藏的两个动作：追踪与触发。防抖、节流、异步校验等“赋值与更新不同步”的需求，本质都是在 set 里延迟调用 trigger。

**速记**：customRef **get 里 track、set 里 trigger**，时机自己定。



#### 防抖引用 useDebouncedRef

**防抖引用**：用 customRef 实现的 useDebouncedRef 组合式函数，让绑定值在停止输入一段时间后才真正触发更新。

- 实现要点：set 中把 trigger 放进 setTimeout 延迟执行，重复赋值先清除上一个定时器。
- 使用方式：const keyword = useDebouncedRef("", 500) 创建实例，模板里用 v-model 绑定输入框。
- 更新效果：输入过程中依赖方收不到中间值，停止输入 500 毫秒后通知才落地，适合搜索联想等场景。
- 时序衔接：定时器回调属于宏任务，trigger 在其中执行，异步顺序的推演方法见 JavaScript 系列的 《32. async、await 与事件循环.md》。

```js
import { customRef } from "vue";

function useDebouncedRef(initialValue, delay = 500) {
  let value = initialValue;
  let timerId = null;
  return customRef((track, trigger) => ({
    get() {
      track();
      return value;
    },
    set(newValue) {
      clearTimeout(timerId);
      timerId = setTimeout(() => {
        value = newValue;
        trigger(); // 延迟触发：停止输入 delay 毫秒后才通知依赖
      }, delay);
    },
  }));
}
```

> [!TIP]
> **建议内容**：value 的赋值要放在定时器回调内、紧贴 trigger 之前，保证依赖方被通知时读到的就是最新值；若先赋值再延迟通知，期间的读取会拿到已变化却未声明的数据，造成时序错觉。

**速记**：useDebouncedRef **set 里定时、到点再 trigger**。



### effectScope 副作用作用域

#### effectScope 与 scope.stop 的基本用法

**effectScope**：创建一个副作用作用域对象，把作用域存活期间创建的计算属性、侦听器等副作用收拢在一起，便于统一销毁。

- 签名：effectScope(detached)，参数可选，传 true 时脱离父作用域独立存在。
- scope.run(fn)：在作用域内执行工厂函数，fn 中同步创建的副作用全部归入该作用域。
- scope.stop()：一次性停止作用域内所有副作用，计算属性失效、侦听器解绑。
- 解决的问题：大型组件里大量需要手动清理的副作用，逐一保存停止函数既繁琐又容易遗漏。

```js
import { effectScope, ref, watch, watchEffect, computed } from "vue";

const scope = effectScope();

scope.run(() => {
  const count = ref(0);
  const doubled = computed(() => count.value * 2);
  watch(count, () => console.log("count 变化"));
  watchEffect(() => console.log("doubled:", doubled.value));
});

scope.stop(); // 一次调用，上面所有副作用全部停止
```

> [!NOTE]
> **提醒内容**：作用域的捕获发生在 scope.run 执行期间：同步创建的副作用才会归入作用域；在 run 之外，或 setTimeout 等异步回调里创建的侦听器不会被捕获，仍需自行保存停止函数手动清理。

**速记**：effectScope **run 时收编、stop 时清场**。



#### 组合式函数中的资源统一释放

**作用域化组合式函数**：在组合式函数内部创建 effectScope 并借助 onScopeDispose 停止，让内部资源随组件生命周期自动释放。

- 标准模式：函数内先建 scope，用 scope.run 包住所有侦听器创建，再注册 onScopeDispose 调用 scope.stop()。
- onScopeDispose：当前响应式作用域（通常对应组件实例）销毁时执行的回调，相当于作用域版的卸载钩子。
- 收益：调用方无需关心组合式函数内部建了多少侦听器，组件卸载时一切自动回收。
- detached 参数：嵌套作用域默认随父作用域一起停止；传 true 后可独立控制生命周期。

```js
import { effectScope, onScopeDispose, watch } from "vue";

function useAutoDisposeWatch(source, callback) {
  const scope = effectScope();
  scope.run(() => {
    watch(source, callback);
  });
  onScopeDispose(() => scope.stop());
}
```

> [!WARNING]
> **警告内容**：侦听器若既不在 effectScope 之内，也没有手动保存停止函数，组件卸载后仍会持有对响应式数据的引用，造成内存泄漏与无效回调；组合式函数内的副作用要么归入作用域，要么显式注册清理。

**速记**：组合式函数**副作用入 scope、卸载自动 stop**。



### 判断与转换 API 全家福

#### isRef 与 unref

**isRef 与 unref**：是处理 ref 的判断与解包工具，一个判断身份，一个统一取值。

- isRef(值)：判断传入值是否为 ref，返回布尔值；shallowRef、customRef 创建的引用同样返回 true。
- unref(值)：传入 ref 时返回其 .value，传入普通值时原样返回，是兼容两种入参的取值工具。
- 常见用途：组合式函数的参数允许传 ref 或普通值，内部用 unref 统一取值。
- 相关延伸：Vue 3.3 起提供 toValue，它在 unref 的基础上进一步支持函数入参，会调用函数取其返回值。

```js
import { isRef, unref, ref, shallowRef } from "vue";

const count = ref(1);
const state = shallowRef({ a: 1 });

isRef(count);  // true
isRef(state);  // true
unref(count);  // 1
unref(42);     // 42：普通值原样返回
```

> unref 是 isRef 判断加 .value 取值的语法糖：只需要取值时用 unref，需要在分支里区分类型时才用 isRef，二者常配合出现在兼容多种入参的组合式函数里。

**速记**：isRef **辨身份**，unref **统一取值**。



#### toRef 与 toRefs

**toRef 与 toRefs**：把响应式对象的属性转换为 ref 的两个转换工具，用于在保留响应式连接的前提下解耦结构。

- toRef(对象, 属性名)：为响应式对象的单个属性创建 ref，读写该 ref 等价于读写原属性。
- toRefs(对象)：批量版本，把响应式对象的所有第一层属性逐个转为 ref，返回一个普通对象。
- 核心价值：转换结果与源对象保持响应式连接，源属性变化会同步到 ref，反向赋值也写回源对象。
- 典型场景：组合式函数返回 reactive 对象前先 toRefs，让调用方解构而不丢失响应式。

```js
import { reactive, toRef, toRefs } from "vue";

const state = reactive({ count: 0, name: "Vue" });

const countRef = toRef(state, "count");
countRef.value++;              // state.count 同步变为 1

const refs = toRefs(state);
const { name } = refs;         // 解构拿到的是 ref，仍与 state 关联
```

> [!IMPORTANT]
> **重要内容**：toRefs 只对 reactive 返回的响应式对象有效，对普通对象调用得不到可用结果；它转换的只是第一层属性，深层嵌套需要逐层处理。直接解构 reactive 对象会丢失响应式，解构 toRefs 的结果则安全，这正是它的存在意义。

**速记**：toRef **单属性连线**，toRefs **批量转、解构不丢响应**。



#### isProxy isReactive 与 isReadonly

**isProxy、isReactive 与 isReadonly**：三个检查代理身份的判断 API，粒度从粗到细。

- isProxy(值)：值是 reactive 或 readonly 产生的代理时返回 true，涵盖下面两者。
- isReactive(值)：值由 reactive 或 shallowReactive 创建时返回 true；深层嵌套于响应式对象内的子对象也返回 true。
- isReadonly(值)：值由 readonly 或 shallowReadonly 创建时返回 true。
- 共同限制：只对代理对象成立；对原始对象、ref、markRaw 对象一律返回 false。

```js
import { reactive, readonly, isProxy, isReactive, isReadonly, markRaw } from "vue";

const state = reactive({ nested: { a: 1 } });
const frozen = readonly({ b: 2 });

isProxy(state);            // true
isProxy(frozen);           // true
isReactive(state.nested);  // true：深层子对象也属于响应式体系
isReadonly(frozen);        // true
isProxy(markRaw({ c: 3 })); // false：markRaw 对象不是代理
```

> [!CAUTION]
> **注意内容**：这三个判断主要服务于调试与库开发中的类型分支，不要写进业务条件逻辑去“区分数据来源”；ref 不归它们管，判断 ref 必须用 isRef，两套判断体系不可混用。

**速记**：isProxy 粗、**isReactive 与 isReadonly 细**，ref 另走 isRef。



### 响应式使用陷阱清单

#### reactive 解构失响应

**解构陷阱**：对 reactive 对象解构或把属性取出来赋给变量，会切断与代理的连接，得到失去响应性的普通值。

- 原理：响应式建立在代理的属性访问上，解构是一次性读取属性值，之后的变化不再关联。
- 基本类型属性：解构后得到完全断开的原始值，源变化不反映，反向赋值也不写回。
- 对象类型属性：解构拿到的是嵌套的响应式子代理，其内部变化仍能触发更新，但整体替换源属性时链接断裂。
- 正确做法：需要解构时先 toRefs 再解构，或保持 state.count 的属性访问形式书写。

```js
import { reactive, toRefs } from "vue";

const state = reactive({ count: 0 });

let { count } = state; // count 是普通数字，响应式已断开
state.count = 5;
console.log(count);    // 仍是 0：不随源变化

const { count: linkedCount } = toRefs(state); // 解构出 ref，响应式保留
```

> [!WARNING]
> **警告内容**：在 script setup 与组合式函数中直接解构 reactive 返回值是最常见的新手错误，表现为“数据变了页面不动”；排查思路是确认变量是否还与代理保持连线，断裂处用 toRefs 修复。

**速记**：解构 reactive **一刀切断**，先 toRefs 再解构。



#### 整体替换 reactive 对象失效

**替换陷阱**：reactive 的代理身份与创建它的那次调用绑定，把变量重新赋值为新对象后，旧代理仍在被引用、新对象脱离原有管理，状态会分裂。

- 现象：state = 新对象 之后，之前保存的旧引用（模板、侦听器、其他模块里持有的）仍指向旧代理，新旧读写互不相干。
- 原理：响应式连接依赖 Proxy 包装那一层，变量重赋值只改变量指向，不影响已建立的代理。
- 对比 ref：ref 为此而设计，对 .value 整体赋新对象会正常触发更新，适合整体替换型状态。
- 实践结论：会整体替换的状态用 ref 包裹；reactive 适合形态固定的对象。

```js
import { reactive, ref } from "vue";

const state = reactive({ list: [1, 2, 3] });
const savedProxy = state;            // 保存旧代理引用

state = reactive({ list: [4, 5] });  // 变量重指，旧代理不受影响
console.log(savedProxy.list);        // 仍是 [1, 2, 3]：状态分裂

const better = ref({ list: [1, 2, 3] });
better.value = { list: [4, 5] };     // 整体替换，正常触发更新
```

> [!CAUTION]
> **注意内容**：把 reactive 对象作为参数传入函数后，函数内对参数整体重赋值同样不会反映到调用方；要么修改参数的属性，要么从一开始就用 ref 传递。

**速记**：reactive **变量重指即分裂**，整体替换交给 ref。



#### ref 与 reactive 混用的心智负担

**混用负担**：ref 与 reactive 并存于同一代码库时，取值方式、解构行为、整体替换能力都不同，混用会显著抬升心智负担。

- 取值差异：ref 在脚本中需要 .value，在模板中自动解包；reactive 在脚本与模板中都直接访问属性。
- 解构差异：ref 解构天然安全，拿到的是引用本身；reactive 解构即失响应。
- 替换差异：ref 可整体替换 .value；reactive 不可整体替换。
- 官方态度：官方文档明确列出 reactive 的诸多限制，并建议在组合式函数返回值、整体替换等场景优先使用 ref。

```js
import { ref } from "vue";

// 统一用 ref 的写法：心智负担最低
const user = ref({ name: "Ada", tags: ["vue"] });
user.value.name = "Grace";    // 脚本里修改嵌套属性
user.value = { name: "Lin" }; // 整体替换也没问题
// 模板中写 user.name 即可，自动解包
```

> [!TIP]
> **建议内容**：团队约定比 API 选择更重要：新项目可全程只用 ref，一并规避解构与替换两类陷阱；有明确性能需求时才引入 shallowRef 与 shallowReactive，让浅层化成为显式的优化决策而非随意混搭。

**速记**：**能 ref 则 ref**，浅层化是显式优化手段。



#### 深层大数组的性能权衡

**性能权衡**：深层响应式会为数组访问到的每一层、每个嵌套元素建立代理，数据量大时创建与访问开销显著上升。

- 成本来源：深层代理按需为每个嵌套对象建立 Proxy，十万级元素的列表会放大这一开销。
- 方案一：用 shallowRef 包裹大数组，更新走整体替换，局部修改配合 triggerRef。
- 方案二：数据静态不变时用 markRaw 标记，或干脆不放入响应式系统，改用普通变量加手动刷新。
- 方案三：分页与虚拟滚动，从数据量本身压缩代理范围。

```js
import { shallowRef, triggerRef } from "vue";

const rows = shallowRef(loadHugeTableRows()); // 万行级数据不做深层代理

function toggleRow(rowIndex) {
  rows.value[rowIndex].done = !rows.value[rowIndex].done;
  triggerRef(rows); // 单次手动通知，替代整树深层代理
}
```

> [!IMPORTANT]
> **重要内容**：性能优化要在证据之上进行：先用 Vue 开发者工具或性能剖析确认响应式开销确为瓶颈，再对热点数据浅层化；几百条量级的业务列表，深层响应式的开销可以忽略，过早优化反而徒增代码复杂度。

**速记**：大数组 **shallowRef 加 triggerRef**，有证据再优化。
