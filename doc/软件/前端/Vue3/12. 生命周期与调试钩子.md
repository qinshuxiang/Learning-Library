## 生命周期与调试钩子

### 生命周期的定义与阶段划分

#### 生命周期是组件从创建到销毁的全过程

**生命周期（Lifecycle）**：指 Vue 组件从**创建、挂载、更新到卸载**的完整运行过程，框架会在过程中的关键节点自动调用开发者登记好的回调函数。

- 这些关键节点的回调函数统称**生命周期钩子（Lifecycle Hooks）**，开发者把对应阶段的逻辑写进钩子里。
- 钩子由 Vue **自动触发**，无需手动调用，开发者只负责注册回调。
- 生命周期的意义在于**提供可预测的时机**：DOM 何时可用、组件何时被移除、数据何时变化，都有确定的回调节点可依。
- 注册时机上有统一约束：钩子必须**同步注册在 setup 执行期间**，脱离同步上下文注册会失效。

> 类比理解：生命周期像**人的一生**——出生（创建）、落户（挂载）、成长变化（更新）、离世（卸载），每个节点都对应一次可以做特定事情的机会窗口。

**速记**：生命周期 = **组件一生 + 框架自动回调**。



#### 创建、挂载、更新、卸载四大阶段

**阶段划分**：Vue 3 把组件的一生划分为**创建、挂载、更新、卸载**四大阶段，每个阶段前后各有一对钩子把守。

- **创建阶段**：初始化组件实例、处理 props 与响应式状态（执行 setup），此时尚未生成任何真实 DOM。
- **挂载阶段**：把模板渲染为虚拟 DOM 并插入页面，完成后真实 DOM 就绪，组件正式出现在页面上。
- **更新阶段**：响应式数据变化后，重新渲染虚拟 DOM 并打补丁更新页面，此阶段会随数据变化**循环发生多次**。
- **卸载阶段**：组件从页面移除，执行清理与回收，避免定时器、监听器等资源泄漏。

```text
创建 ──▶ 挂载 ──▶ 更新（随数据变化循环多次）──▶ 卸载
setup    DOM可用    DOM与数据保持同步           清理资源
```

> before 类钩子（beforeMount、beforeUpdate、beforeUnmount）表示"**即将发生但尚未发生**"，后对钩子表示"**已经完成**"。理解"前后成对"的命名结构，即可推出全部钩子的名字与含义。

**速记**：**创建、挂载、更新、卸载**四阶段，每阶段**前后成对**有钩子。



### 组合式 API 生命周期钩子

#### 钩子注册时机限制与全家福

**组合式钩子全家福**：Vue 3 提供十余个以 on 开头的生命周期函数，需要**从 vue 导入并在 setup 同步段注册**，按所属阶段可分为六组。

- 挂载期：onBeforeMount、onMounted。
- 更新期：onBeforeUpdate、onUpdated。
- 卸载期：onBeforeUnmount、onUnmounted。
- 缓存期（配合 keep-alive）：onActivated、onDeactivated。
- 错误与调试：onErrorCaptured，以及仅开发环境生效的 onRenderTracked、onRenderTriggered。
- 服务端渲染：onServerPrefetch。

```js
import { onMounted, onUnmounted } from "vue";

export default {
  setup() {
    // 钩子必须在 setup 函数体内同步注册
    onMounted(() => {
      console.log("组件已挂载");
    });
    onUnmounted(() => {
      console.log("组件已卸载");
    });
  },
};
```

> [!IMPORTANT]
> **重要内容**：钩子必须**同步注册在 setup 执行期间**。若放在 setTimeout 回调、await 之后的异步代码里注册，Vue 已经找不到当前组件实例，钩子不会生效，控制台会给出没有活动组件实例的警告。

**速记**：**on 开头全家福，setup 同步段注册**，异步注册**无效**。



#### 挂载期钩子 onBeforeMount 与 onMounted

**挂载期一对钩子**：onBeforeMount 在**组件即将挂载、DOM 尚未生成**时调用，onMounted 在**真实 DOM 已插入页面**之后调用。

- onBeforeMount：模板已编译完成，但页面中还没有该组件的任何真实 DOM，此钩子内改不了页面，实际业务使用较少。
- onMounted：真实 DOM 已就绪，是**操作 DOM、初始化第三方 DOM 库**的标准入口。
- 二者都只在首次挂载时**触发一次**，组件后续更新不会再走挂载期钩子。

```js
import { ref, onBeforeMount, onMounted } from "vue";

const boxRef = ref(null); // 模板 ref

onBeforeMount(() => {
  // boxRef.value 此刻仍是 null，页面无 DOM
  console.log("即将挂载");
});

onMounted(() => {
  // DOM 已可用，可安全读取模板 ref
  console.log(boxRef.value.offsetHeight);
});
```

> 在 onMounted 里可以放心读取 boxRef.value——模板 ref 的赋值发生在挂载阶段；而 setup 同步段中读取到的还是 null。这一差别是判断"代码该放哪个钩子"的基本依据。

**速记**：onBeforeMount **页面还没有**，onMounted **DOM 已就绪**。



#### 更新期钩子 onBeforeUpdate 与 onUpdated

**更新期一对钩子**：onBeforeUpdate 在**数据已变化、DOM 尚未更新**时调用，onUpdated 在**DOM 更新完成**之后调用。

- onBeforeUpdate：此刻状态已是新值，页面仍是旧值，适合在渲染前**读取更新前的 DOM 状态**，例如记录滚动位置、元素尺寸。
- onUpdated：虚拟 DOM 重新渲染并打补丁完毕，页面与数据已经同步。
- 触发条件：组件内任何**被模板使用**的响应式数据发生变化并引发重新渲染。
- 层级关系：父组件更新会带动子组件更新，父组件的 onUpdated 在其子组件的 onUpdated **之后**触发。

```js
import { onBeforeUpdate, onUpdated } from "vue";

onBeforeUpdate(() => {
  console.log("数据已变，DOM 还是旧的");
});

onUpdated(() => {
  console.log("DOM 已同步为最新");
});
```

> 未被模板使用的响应式数据变化**不会引发渲染**，也就不会触发更新期钩子；需要观察"任意数据变化"时应使用侦听器而非更新钩子。

**速记**：onBeforeUpdate **DOM 未动**，onUpdated **页面已新**。



#### onUpdated 中不得再次修改组件状态

**递归更新风险**：onUpdated 的回调里**不应再次修改组件的响应式状态**，否则会再次触发更新，可能形成**无限循环更新**，开发环境会给出递归更新超限的警告。

- 风险链条：onUpdated 中改状态 → 触发重新渲染 → 渲染完成又调用 onUpdated → 再次改状态，循环往复。
- Vue 对此有保护机制：循环达到上限后停止更新并**在控制台警告**，但页面状态已不可靠。
- 正确归属：需要在"数据变化后"修正状态或发起副作用的逻辑，应写在**侦听器 watch** 或 onBeforeUpdate 中。
- 判断标准：凡是"改了数据再引发渲染"的逻辑，都不属于 onUpdated 的职责范围。

```js
import { ref, watch, onUpdated } from "vue";

const page = ref(1);
const list = ref([]);

// 反例：onUpdated 中修改状态
onUpdated(() => {
  // page.value++; // 禁止：会再次触发更新，可能无限循环
});

// 正例：状态派生与副作用交给侦听器
watch(page, (val) => {
  fetchPage(val).then((data) => {
    list.value = data;
  });
});

async function fetchPage(val) {
  const res = await fetch("/api/list?page=" + val);
  return res.json();
}
```

> [!WARNING]
> **警告内容**：在 onUpdated 中修改组件状态是官方文档明确不推荐的做法，极易造成**无限循环更新**。onUpdated 的定位是"观察 DOM 更新完成"，不是"处理数据变化"。

**速记**：updated 里**别改状态**，改状态的活交给**侦听器**。



### 卸载钩子与资源清理

#### 卸载期钩子 onBeforeUnmount 与 onUnmounted

**卸载期一对钩子**：onBeforeUnmount 在**组件卸载之前**调用，此时组件仍然完整可用；onUnmounted 在**组件已从页面移除**之后调用。

- onBeforeUnmount：DOM 还在、实例还活着，是**清理定时器、事件监听、订阅**的推荐时机，清理过程中仍能访问组件资源。
- onUnmounted：组件的 DOM 已被移除、在组件树中已不存在，适合做**最终上报、通知父级**等纯收尾动作。
- 常见触发场景：v-if 条件转为假、列表项被删除、路由切换导致页面组件销毁、父组件卸载带动子组件卸载。

```js
import { onBeforeUnmount, onUnmounted } from "vue";

onBeforeUnmount(() => {
  console.log("即将卸载，在这里做清理");
});

onUnmounted(() => {
  console.log("已卸载，在这里做收尾");
});
```

> 卸载期钩子在路由切换、条件渲染移除等场景都会触发，是 SPA 中**页面级资源回收**的标准位置；清理逻辑优先写 onBeforeUnmount，onUnmounted 只留不需要访问组件资源的收尾。

**速记**：onBeforeUnmount **还活着先打扫**，onUnmounted **已离场做收尾**。



#### 清理定时器、事件监听与订阅

**清理原则**：组件中创建的**一切非框架托管资源**——定时器、事件监听、消息订阅——都必须在卸载钩子中成对清理，否则会内存泄漏并在组件销毁后继续空跑。

- 定时器：setInterval、setTimeout 创建后，用 clearInterval、clearTimeout 对应清除，保存返回的 id。
- 事件监听：window、document 等全局对象上的 addEventListener，必须用**同一函数引用**调用 removeEventListener 移除，配对原则见 JavaScript 系列第 12 篇 事件处理.md。
- 订阅与观察器：WebSocket 订阅、EventSource、MutationObserver、第三方库实例（图表、编辑器）都提供 destroy 或 disconnect 类方法，卸载时逐个调用。
- 归属判断：框架托管的资源（组合式函数、在 setup 中同步创建的侦听器）会随组件**自动回收**，无需手动清理。

```js
import { ref, onMounted, onBeforeUnmount } from "vue";

const seconds = ref(0);
let timerId = null;

function handleResize() {
  console.log("窗口尺寸变化");
}

onMounted(() => {
  timerId = setInterval(() => seconds.value++, 1000);
  window.addEventListener("resize", handleResize);
});

onBeforeUnmount(() => {
  // 与创建动作一一配对清理
  clearInterval(timerId);
  window.removeEventListener("resize", handleResize);
});
```

> [!IMPORTANT]
> **重要内容**：清理的关键是**保存引用、成对销毁**。匿名函数监听器没有引用可移除，setInterval 的 id 丢失后无法清除，这类"创建时没留下痕迹"的资源是泄漏的主要来源。创建时多存一个变量，卸载时才能多删一份资源。

**速记**：**谁创建、谁清理**，创建留引用，卸载成对删。



### 选项式与组合式钩子的对照

#### beforeCreate 与 created 由 setup 本身取代

**对应关系**：选项式的 beforeCreate 与 created 两个钩子，在组合式 API 中**没有 on 前缀版本**，由 setup 函数体本身取代。

- beforeCreate：实例初始化之后、数据观测之前，此时 props 与响应式状态都不可用。
- created：数据观测完成、计算属性与方法就绪，但 DOM 尚未生成。
- setup 函数恰好在**这两个时机之间同步执行**，因此它天然覆盖了 beforeCreate 到 created 的全部职责。
- 组合式里"想在 created 阶段做的事"，直接写在 setup 的**同步代码段**即可，不需要任何钩子包裹。

```js
export default {
  setup() {
    // setup 同步段的执行时机等价于 created 阶段
    // 此时 props 已可用，DOM 尚未生成
    console.log("这里相当于 created");
  },
};
```

> 不存在官方的 onBeforeCreate 与 onCreated——setup 本身就运行在这两个时机之间，再提供同名钩子没有意义，这也是钩子全家福里唯独缺这两个名字的原因。

**速记**：**setup 同步段 = created**，beforeCreate 与 created **无 on 版本**。



#### 其余钩子加 on 前缀一一对应

**命名规律**：除 beforeCreate 与 created 之外，选项式生命周期钩子在组合式 API 中**统一加 on 前缀**，与原钩子一一对应。

- beforeMount 对应 onBeforeMount；mounted 对应 onMounted。
- beforeUpdate 对应 onBeforeUpdate；updated 对应 onUpdated。
- beforeUnmount 对应 onBeforeUnmount；unmounted 对应 onUnmounted。
- activated 对应 onActivated；deactivated 对应 onDeactivated。
- errorCaptured 对应 onErrorCaptured；serverPrefetch 对应 onServerPrefetch。
- renderTracked 对应 onRenderTracked；renderTriggered 对应 onRenderTriggered。
- 使用形态差异：选项式写法中钩子是**配置项**（mounted() { }），组合式中是**导入的函数**（onMounted(() => { })）。

```js
import { onMounted, onUnmounted } from "vue";

// 选项式：mounted() { ... } / unmounted() { ... }
// 组合式：等价写法如下
onMounted(() => {
  console.log("组合式注册挂载钩子");
});

onUnmounted(() => {
  console.log("组合式注册卸载钩子");
});
```

> [!NOTE]
> **提醒内容**：组合式 API 中**同一个钩子可以注册多次**，多个回调按注册顺序依次执行，这为组合式函数封装提供了基础；而选项式对象写法里同名键重复会被覆盖。迁移旧代码时需要留意这一行为差异。

**速记**：选项式**配置项**，组合式**导入函数**，除 created 双钩子外**一律加 on**。



### onMounted 与数据请求的时机

#### onMounted 中真实 DOM 已经可用

**DOM 可用性**：onMounted 是组合式 API 中**第一个能安全接触真实 DOM** 的钩子，页面中已存在该组件渲染出的元素。

- 获取模板 ref：挂载完成后模板 ref 已赋值，boxRef.value 指向真实元素，可读取或修改。
- 初始化第三方 DOM 库：图表、富文本编辑器、拖拽库等需要真实容器元素，应在 onMounted 中创建实例。
- 测量与布局：读取 offsetWidth、调用 getBoundingClientRect 等依赖布局的操作放在 onMounted 中执行。

```js
import { ref, onMounted } from "vue";

const chartRef = ref(null);

onMounted(() => {
  // 容器元素已存在，第三方图表库可以安全初始化
  const chart = createChart(chartRef.value);
  chart.render();
});

function createChart(container) {
  return { render: () => console.log("渲染图表到", container) };
}
```

> [!TIP]
> **建议内容**：需要等待**响应式数据变化后的最新 DOM** 时，不要依赖 onMounted——它只在首次挂载时执行一次。此时应使用 nextTick，或把侦听器的 flush 选项设为 post（用法见本系列第 4 篇 计算属性与侦听器.md）。

**速记**：onMounted **DOM 首次可用**，模板 ref **此刻已赋值**。



#### 数据请求放在 setup 同步段还是 onMounted

**请求时机辨析**：与 DOM 无关的异步请求**可以放在 setup 同步段发出**，不必等到 onMounted；只有依赖 DOM 或页面布局的请求才必须放 onMounted。

- setup 同步段等价于 created 时机，组件一初始化就能发请求，比挂载完成的 onMounted **更早**，能略微缩短首屏等待。
- 网络请求本身是异步副作用，**不依赖 DOM 的存在**，因此不受"DOM 是否就绪"的限制。
- 请求返回后的结果存入响应式状态，模板会自动渲染，无需手动操作 DOM。
- 服务端渲染差异：服务端只执行 setup 同步段（相当于 created），onMounted 等**挂载、更新钩子只在客户端执行**，因此 SSR 场景的数据获取必须写在 setup 中。

```js
import { ref, onMounted } from "vue";

const userList = ref([]);

// 写法一：setup 同步段发请求，时机最早，SSR 下也能执行
fetchUserList().then((data) => {
  userList.value = data;
});

// 写法二：onMounted 中发请求，仅客户端执行
onMounted(() => {
  fetchUserList().then((data) => {
    userList.value = data;
  });
});

async function fetchUserList() {
  const res = await fetch("/api/users");
  return res.json();
}
```

> [!IMPORTANT]
> **重要内容**：判断标准是**请求是否依赖 DOM**——不依赖就提前到 setup 同步段，依赖 DOM 才放 onMounted。官方文档口径：服务端渲染时只有 setup 同步段（对应 created 时机）会在服务端被调用，不要把需要服务端执行的逻辑放进 onMounted。

**速记**：**DOM 无关请求提前发**，SSR **只在 setup 拿数据**。



### 父子组件的生命周期执行顺序

#### 挂载顺序：父 beforeMount 先于子 mounted

**挂载顺序链**：嵌套组件挂载时，**父组件先开始、子组件先完成**——父 beforeMount 先于子 mounted，父 mounted 最后触发。

- 完整顺序链（父组件 P 包含子组件 C）：

```text
父 setup → 父 beforeMount
  → 子 setup → 子 beforeMount → 子 mounted
  → 父 mounted
```

- 原因一：父组件要先渲染模板才能确定子组件的存在与位置，所以父**先走到 beforeMount**。
- 原因二：渲染到子组件占位时开始一个完整的递归过程，子组件**一口气走完自己的挂载流程**，因此子 mounted 先于父 mounted。
- 推论口径：某组件的 mounted 触发时，它的**所有后代组件都已挂载完毕**。

> [!NOTE]
> **提醒内容**：面试常问父 mounted 与子 mounted 谁先——答案是**子先父后**。若父模板中有多个子组件，各子组件按模板中出现的顺序依次完成挂载，整体顺序依然可预测。

**速记**：挂载**父开头、子收尾**，父 mounted **最后触发**。



#### 卸载与更新顺序：before 父先跑，ed 子先完

**卸载顺序链**：卸载与挂载方向相反，**父组件先接到卸载指令、子组件先完成卸载**——父 beforeUnmount 最先触发，父 unmounted 最后触发。

```text
父 beforeUnmount → 子 beforeUnmount → 子 unmounted → 父 unmounted
```

- 卸载以父组件为起点：父先进入卸载流程，随后**递归卸载子组件**，全部后代清理完毕，父才算卸载完成。
- 更新顺序链：父 beforeUpdate → 子 beforeUpdate → 子 updated → 父 updated，同样是**子组件的更新先完成**，父的 updated 收尾。
- 统一规律：**before 类钩子父先执行，完成类钩子子先执行**，挂载、更新、卸载三个阶段都符合。

```js
// 在父子组件中分别注册卸载钩子即可验证顺序
onBeforeUnmount(() => console.log("父 beforeUnmount"));
onUnmounted(() => console.log("父 unmounted"));
// 子组件的 beforeUnmount 与 unmounted 输出夹在父组件两条输出之间
```

> 把三条顺序链放在一起记：**开始父先行，结束子先行**。无论是 mounted 之前还是 unmounted 之前，父组件都走在前面；所有"完成"节点，子组件都先落地。

**速记**：**before 父先跑，ed 子先完**，卸载链与挂载链**方向相反**。



### keep-alive 缓存钩子

#### onActivated 与 onDeactivated 的触发时机

**缓存钩子**：被 keep-alive 包裹的组件在**切入页面时触发 onActivated，切离页面时触发 onDeactivated**，对应"从缓存取出"与"放回缓存"两个动作。

- keep-alive 缓存的组件切离时**不会被销毁**，而是连同 DOM 与状态一起被缓存，因此不走 onBeforeUnmount 与 onUnmounted。
- 切回时**也不会重新挂载**，而是从缓存恢复，触发 onActivated。
- onActivated 每次切入都触发，**首次切入也不例外**：顺序为 mounted 之后紧跟 activated。
- onDeactivated 每次切离都触发，扮演了"被缓存而非被销毁"的中间态钩子。

```js
import { onActivated, onDeactivated } from "vue";

onActivated(() => {
  console.log("页面重新可见，可刷新数据或恢复轮询");
});

onDeactivated(() => {
  console.log("页面被缓存，可暂停耗时任务");
});
```

> [!IMPORTANT]
> **重要内容**：缓存组件的**首次切入会依次触发 mounted 与 activated**，之后的每次切入只触发 activated。若把"每次可见都要执行"的逻辑写在 onMounted，第二次切入不会执行——这类逻辑应写在 onActivated。

**速记**：切入 **activated**，切离 **deactivated**，缓存组件**不挂载不卸载**。



#### 缓存组件中钩子的替代关系

**替代关系**：keep-alive 场景中，onActivated 与 onDeactivated **部分替代**了 onMounted 与 onUnmounted 的职责，需按"一次性"与"每次"区分放置逻辑。

- onMounted 只执行一次：放**一次性初始化**，如创建播放器实例、绑定全局资源。
- onActivated 每次切入执行：放**每次可见都需要的刷新**，如拉取最新数据、恢复定时器与轮询。
- onDeactivated 每次切离执行：放**暂停类操作**，如暂停定时器、暂停动画、断开轮询。
- onUnmounted 仍会触发：缓存组件最终被销毁（超出缓存上限被淘汰、组件树整体卸载）时，卸载钩子照常执行，清理逻辑照常写在其中。

```js
import { onMounted, onUnmounted, onActivated, onDeactivated } from "vue";

let timerId = null;

onMounted(() => {
  startPolling(); // 首次挂载启动轮询
});

onActivated(() => {
  startPolling(); // 每次切入恢复轮询
});

onDeactivated(() => {
  stopPolling(); // 每次切离暂停轮询
});

onUnmounted(() => {
  stopPolling(); // 彻底销毁时清理
});

function startPolling() {
  if (timerId !== null) return; // 防止重复启动
  timerId = setInterval(() => console.log("轮询中"), 3000);
}

function stopPolling() {
  clearInterval(timerId);
  timerId = null;
}
```

> [!WARNING]
> **警告内容**：缓存组件中的定时器与轮询要**成对管理**——activated 启动、deactivated 暂停、unmounted 兜底清理。只写 onMounted 启动而不写 onDeactivated 暂停，组件被缓存后定时器仍在后台空转，造成无谓的资源消耗。

**速记**：一次性放 **mounted**，每次可见放 **activated**，切离暂停放 **deactivated**，卸载兜底放 **unmounted**。



### 错误捕获 onErrorCaptured

#### onErrorCaptured 的签名与传播规则

**错误捕获钩子**：onErrorCaptured 用于**捕获后代组件的错误**，回调签名包含错误对象、组件实例与错误来源信息三个参数。

- 完整签名：onErrorCaptured((err, instance, info) => { })，err 是错误对象，instance 是触发错误的组件实例，info 是描述错误来源的字符串。
- 捕获范围：**后代组件**的渲染函数错误、生命周期钩子错误、setup 执行错误、侦听器回调错误、自定义事件处理函数错误等。
- 传播规则：捕获后错误默认**继续向父级传播**，祖先链上的多个钩子可依次处理；回调返回 false 可**阻止继续向上传播**。
- 处理顺序：错误自出错组件**向上**逐级传播，最先执行的是离出错组件最近的钩子。

```js
import { onErrorCaptured } from "vue";

onErrorCaptured((err, instance, info) => {
  console.log("捕获后代错误：", err.message);
  console.log("出错组件：", instance, "来源：", info);
  // 返回 false 阻止错误继续向更上层传播
  return false;
});
```

> [!NOTE]
> **提醒内容**：onErrorCaptured 只捕获**后代组件**的错误，钩子所在组件自身的错误不会被自己捕获。覆盖全应用的兜底应另配应用级的 app.config.errorHandler。

**速记**：参数 **err、instance、info**，返回 false **截断传播**，只管**后代**。



#### 错误边界组件的思想

**错误边界（Error Boundary）**：指用 onErrorCaptured 构建的、**专门捕获并兜底展示后代错误**的容器组件，让局部出错不至于拖垮整个页面。

- 典型结构：边界组件捕获后代错误后，**渲染一份兜底 UI**（如出错了请重试）替代出错的子树。
- 局部隔离：错误被边界截住（返回 false），页面其他区域继续正常工作，体现**故障隔离**思想。
- 可封装：把 hasError 响应式状态与 onErrorCaptured 注册封装成组合式函数，在任意父组件中复用。
- 两级兜底：错误边界管局部区块，app.config.errorHandler 管全局兜底，共同构成完整的错误处理体系。

```js
import { ref, onErrorCaptured } from "vue";

// 通用错误边界组合式函数
function useErrorBoundary() {
  const hasError = ref(false);
  const errorMessage = ref("");

  onErrorCaptured((err) => {
    hasError.value = true;
    errorMessage.value = err.message;
    return false; // 截断传播，展示兜底 UI
  });

  function resetError() {
    hasError.value = false;
    errorMessage.value = "";
  }

  return { hasError, errorMessage, resetError };
}
```

> [!TIP]
> **建议内容**：错误边界宜放在**路由级或大区块级**，而不是每个小组件都包一层——边界粒度过细会让兜底 UI 与重试逻辑的维护成本上升，覆盖到大区块即可拦截绝大多数崩溃。

**速记**：错误边界 = **捕获后代错误 + 渲染兜底 UI + return false 隔离**。



### 调试钩子 onRenderTracked 与 onRenderTriggered

#### 两个调试钩子的定位与事件对象

**调试钩子定位**：onRenderTracked 与 onRenderTriggered 是**仅开发环境生效**的组件级调试钩子，用于观察渲染过程中**响应式依赖的收集与触发**。

- onRenderTracked：组件渲染过程中，**每收集到一个依赖**就调用一次，事件对象带 target、key、type 字段。
- onRenderTriggered：某个依赖**实际触发组件重新渲染**时调用，事件对象在 tracked 基础上多了 newValue 与 oldValue。
- 事件对象关键字段：key（变化的属性名）、target（所属响应式对象）、type（操作类型，如 set、add、delete）、newValue 与 oldValue（变化前后的值）。
- 生产环境两个钩子**不会被调用**，无需手动移除，但也不要在其中编写正式业务逻辑。

```js
import { onRenderTracked, onRenderTriggered } from "vue";

onRenderTracked((event) => {
  console.log("渲染收集了依赖：", event.key);
});

onRenderTriggered((event) => {
  console.log("该依赖触发了重渲染：", event.key);
  console.log("旧值 → 新值：", event.oldValue, "→", event.newValue);
  console.log("操作类型：", event.type);
});
```

> 二者分工：tracked 回答**收集了谁**，得到一份依赖清单；triggered 回答**谁变了**，锁定变化的元凶。一个看全量，一个看增量。

**速记**：tracked **记收集**，triggered **报变化**，**仅开发环境**。



#### 定位重渲染的触发来源

**调试用途**：当页面出现"不知道谁改了状态"或"没改数据却频繁重渲染"的问题时，onRenderTriggered 能**直接打印出触发重渲染的属性与新旧值**，是排查多余渲染的第一工具。

- 排查步骤一：在目标组件中注册 onRenderTriggered，观察触发频率与 key 字段。
- 排查步骤二：对频繁出现的 key，结合 target 字段定位是哪个响应式对象，再排查其**写入位置**。
- 排查步骤三：对比 newValue 与 oldValue，判断是真实变化还是**引用替换引发的误触发**（如整个对象被新对象覆盖）。
- 与侦听器互补：侦听器需要**预先声明监听目标**，调试钩子则**被动汇报一切触发**，适合问题原因不明的场景。

```js
import { reactive, onRenderTriggered } from "vue";

const state = reactive({ count: 0, list: [] });

onRenderTriggered((event) => {
  // 打印形如：key 为 count，type 为 set，oldValue 0 → newValue 1
  console.log(event.key, event.type, event.oldValue, "->", event.newValue);
});
```

> [!CAUTION]
> **注意内容**：调试钩子的回调在**每次渲染时都会执行**，在钩子里打印大对象或做复杂计算会明显拖慢开发环境的渲染速度。定位完成后应及时移除或注释掉调试钩子。

**速记**：重渲染**查元凶**，triggered 事件里看 **key 与新旧值**。
