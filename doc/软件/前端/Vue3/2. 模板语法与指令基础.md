## 模板语法与指令基础

### 文本插值

#### 双大括号是文本插值的标准语法

**文本插值**：使用双大括号包裹 JavaScript 表达式，把数据渲染成元素的文本内容，是 Vue 模板最基础的语法。

- 双大括号内的表达式会被替换为其求值结果，以纯文本形式呈现在标签之间。
- 表达式依赖的响应式数据变化时，插值**自动重新求值**，视图随之更新，全程无需手动操作 DOM。
- 双大括号只能写在元素的**文本内容**位置；attribute 值的位置不接受双大括号，动态属性必须交给 v-bind 指令处理。

```html
<template>
  <p>计数：{{ count }}</p>
</template>
```

> 双大括号外的普通文字与插值结果会原样拼接，上例渲染出 计数：0 这样的整行文本；插值也可以与普通文字混写在同一行内。

**速记**：双大括号包**表达式**，文本输出**自动更新**。



#### 插值内容按普通文本处理

**纯文本输出**：双大括号对求值结果只做文本替换，结果中的 HTML 标签不会被解析，而是原样显示为文字。

- 数据中即使包含形如标签的字符串，页面展示的也是尖括号原文，不会被浏览器当真渲染。
- 这是 Vue 刻意的安全默认值：不解析 HTML，就从源头挡住了绝大多数模板层面的注入。
- 需要真正渲染 HTML 的场景必须显式改用 v-html 指令，安全责任随之显式化。

```html
<template>
  <!-- rawHtml 的值为 <span style="color: red">红色</span> -->
  <p>{{ rawHtml }}</p>
  <!-- 页面显示的是标签原文，而不是红色的文字 -->
</template>
```

> 与之相对，v-html 会把值作为真正的 HTML 插入元素内部，标签与样式均被解析渲染；二者的差别正是纯文本与 HTML 的差别，安全细节见下文 XSS 相关考点。

**速记**：双大括号**只认文本**，标签原样显示。



#### 插值中可以书写 JavaScript 表达式

**表达式支持**：双大括号内支持完整的 JavaScript 表达式语法，可运算、可调用方法、可写三元表达式。

- 算术运算、字符串拼接、成员访问、方法调用链、三元表达式均可直接书写。
- 表达式可以访问组件暴露出来的数据与方法；在组合式 API 中即 script setup 顶层声明的绑定。
- 表达式只承担**展示层的轻量计算**，复杂逻辑应抽为计算属性，保持模板可读，详见 4. 计算属性与侦听器.md。

```html
<template>
  <p>{{ number + 1 }}</p>
  <p>{{ ok ? "是" : "否" }}</p>
  <p>{{ message.split("").reverse().join("") }}</p>
  <p>{{ formatDate(createTime) }}</p>
</template>
```

> 每个双大括号只能容纳**一个**表达式；需要同时输出多个值时分成多个插值，或合并为一个计算属性。

**速记**：插值即**表达式**，运算与方法皆可用。



### 表达式的限定与沙箱

#### 插值只能写表达式，不能写语句与流程控制

**表达式限定**：插值与指令值都只能是**单个表达式**，语句与流程控制一律不允许出现在模板中。

- 表达式是能求出一个值的代码片段；语句是执行动作、声明变量的代码单元，二者语法地位不同。
- if、for、var、const、function 等语句与声明不能写入插值；条件取舍用三元表达式，列表加工用数组方法。
- 一个插值里只能写一个表达式，也不能用分号拼接多个表达式。

```text
{{ if (ok) { return message } }}   错误：if 是语句，无法求值
{{ var a = 1 }}                    错误：变量声明是语句
{{ ok ? message : "暂无" }}        正确：三元表达式可以求值
{{ list.filter(isActive).length }} 正确：方法调用链可以求值
```

> 判断标准：这段代码能否原样作为实参传进一个函数调用。放进 Math.abs(此处) 仍合法的是表达式，不合法的是语句。

**速记**：只写**能求值**的表达式，不写 if、for 语句。



#### 模板表达式运行在全局白名单沙箱中

**模板沙箱**：模板表达式可以访问的全局对象被限定在一份**白名单**内，名单之外的全局变量一律不可用。

- 白名单覆盖常用内置对象，如 Math、Date、JSON、Number、String、Array、Object、Boolean、RegExp、Map、Set、console 等。
- 自定义的全局变量、挂到 window 上的属性在模板中不可直接访问，须先通过组件正常暴露。
- 白名单在编译期即生效，不在名单内的标识符在编译阶段就会报错。

```html
<template>
  <p>{{ Math.round(score) }}</p>
  <p>{{ Date.now() }}</p>
  <!-- window.myGlobal 不可用，须先在组件中暴露 -->
</template>
```

> 沙箱的意图是安全与可控：模板只描述视图，不承担访问全局环境的职责；外部数据应经由组件的响应式数据走正规渠道进入模板。

**速记**：模板沙箱**只认白名单**，Math、Date 可用，window 不可用。



### 原始 HTML 渲染

#### v-html 指令用于渲染原始 HTML

**v-html**：把元素的 innerHTML 更新为指令值中的 HTML 字符串，使模板能输出真正的富文本内容。

- 双大括号把数据当纯文本，v-html 把数据当 HTML 解析，标签、样式、事件属性都会生效。
- 典型场景是渲染后端返回的富文本，如文章正文、公告内容等自带格式的片段。
- v-html 会**整体替换**元素的 innerHTML，元素模板中原有的子内容全部丢弃，因此目标元素通常写成空标签。

```html
<template>
  <p>纯文本：{{ rawHtml }}</p>
  <p v-html="rawHtml"></p>
</template>
```

> 在单文件组件中，v-html 渲染出来的内容不受 scoped 样式约束：作用域标识只加在当前模板的元素上，动态插入的 DOM 并不在其中；确需样式时使用全局选择器或深度选择器处理。

**速记**：v-html 写入 **innerHTML**，富文本场景专用。



#### 双大括号不解析 HTML 是刻意的设计

**设计原因**：双大括号对内容只做文本替换、不解析 HTML，是 Vue 在易用与安全之间做出的明确取舍。

- 页面内容以文字为主，标签解析是少数富文本场景才需要的特例，默认不解析覆盖了绝大多数需求。
- 默认不解析 HTML 意味着数据中的特殊字符天然不会破坏页面结构，注入的攻击面被显著缩小。
- 把渲染 HTML 的能力收拢到 v-html 一个显式指令上，安全责任随语法显式化，代码审查时一眼可辨。

> 对比记忆：双大括号是**安全的默认**，v-html 是**显式的例外**；看到 v-html 就应当警觉数据来源，这正是设计的可审计性所在。

**速记**：默认**文本安全**，例外才用 **v-html**。



#### v-html 有 XSS 注入风险，只用于可信内容

**XSS 风险**：v-html 直接把字符串写入 innerHTML，内容中的恶意标签与脚本片段可能被浏览器执行，构成跨站脚本攻击（XSS）。

- 攻击者把形如 script 的标签或带事件属性的标签藏进数据，v-html 渲染后即在受害者浏览器中运行。
- 后果包括窃取登录态、伪造页面行为、向其他用户传播攻击载荷，属于 Web 安全的高危项。
- 防护原则：v-html 只用于**完全可信**的内容，例如站内编辑器产出的富文本；绝不能用 v-html 渲染用户输入，确需渲染时先经服务端或成熟净化库处理。

> [!WARNING]
> **警告内容**：绝不能用 v-html 渲染用户输入的内容，哪怕是看似无害的昵称与评论。用户可控字符串一旦进入 innerHTML，就可能携带恶意标签造成 XSS，窃取 Cookie 或冒充用户操作；自行用正则过滤不可靠，净化必须交给服务端或成熟的净化库完成。

**速记**：v-html **只吃可信内容**，用户输入先净化。



### 动态绑定属性 v-bind

#### v-bind 的完整写法与冒号简写

**v-bind**：把表达式的值响应式地绑定到元素的 attribute 上，数据变化时属性值随之更新。

- 完整写法为 v-bind:属性名=表达式，冒号后跟 attribute 名，引号内是 JavaScript 表达式。
- 简写为冒号加属性名，即 :属性名=表达式，与完整写法完全等价，工程中普遍使用简写。
- 绑定普通 attribute 时，非字符串值会转为字符串输出；值为 null 或 undefined 时，该 attribute 从渲染结果中移除。

```html
<template>
  <a v-bind:href="url">完整写法</a>
  <a :href="url">冒号简写</a>
  <img :src="coverUrl" :alt="title">
</template>
```

> 同一元素上写死的静态属性与 v-bind 绑定的动态属性可以混用：静态的照常渲染，动态的随数据更新，互不干扰。

**速记**：v-bind 绑属性，简写**一个冒号**。



#### 布尔 attribute 的特殊求值规则

**布尔 attribute**：在 HTML 中仅凭存在即表示真值的属性（如 disabled、checked、readonly、required），v-bind 对它们有专门的求值规则。

- 绑定值为 **null 或 undefined** 时，该 attribute 从渲染结果中**完全移除**。
- 绑定值为 **false** 时，同样不渲染该 attribute。
- 绑定值为**空字符串**时，attribute 保留并输出为空值形态，按 HTML 语义等价于 **true**。
- 绑定值为其他真值时，attribute 正常渲染。

```html
<template>
  <!-- isDisabled 为空字符串时输出 disabled=""，为 false、null、undefined 时属性不出现 -->
  <button :disabled="isDisabled">提交</button>
</template>
```

> 空字符串被视为 true 遵循的是 HTML 规范对布尔 attribute 的定义：只要属性存在即为真。这与 JavaScript 中空字符串为假值的直觉相反，是本考点最容易踩的坑。

**速记**：空串为**真**，false、null、undefined 移除。



#### Vue 3.4 起支持同名简写

**同名简写**：attribute 名与绑定的变量名相同时，可以省略绑定值，从 Vue 3.4 开始可用。

- :id 等价于 :id="id"，:src 等价于 :src="src"，仅适用于属性名与变量名同名的场合。
- 同名简写在向组件透传一组同名 props 时尤其实用，可少写一整遍重复的变量名。
- 这属于可读性层面的语法糖，不改变任何行为，团队可按规范统一取舍。

```html
<template>
  <img :src :alt>
  <!-- 等价于 :src="src" :alt="alt" -->
</template>
```

> 同名简写依赖新版模板编译器，Vue 3.4 之前的版本不支持该写法；跨版本维护的项目先确认基线版本再使用。

**速记**：**同名可省值**，3.4 起可用。



#### 无参数的 v-bind 可批量绑定对象

**批量绑定**：不带参数的 v-bind 可以绑定一个对象，对象的每个键值对都会展开为对应 attribute。

- 写法为 v-bind=对象表达式，键是属性名，值是属性值，适合一次性透传一组 props。
- 对象语法与单独绑定可混用于同一元素。
- 书写顺序决定同名的覆盖关系：**后写的覆盖先写的**。

```html
<template>
  <MyCard v-bind="cardProps" title="标题" />
  <!-- title 的固定值覆盖 cardProps 中的同名键 -->
</template>
```

> 若希望对象里的值覆盖单独绑定的固定值，把 v-bind=对象 写在单独绑定之后即可；覆盖关系完全由书写顺序决定，与写法种类无关。

**速记**：对象一绑**全展开**，同名后写覆盖先写。



### 动态参数

#### 方括号内表达式可作属性名或事件名

**动态参数**：把表达式放进方括号，让指令的参数本身动态化，既可用于属性名，也可用于事件名。

- 属性名动态化：v-bind:[attributeName]=url，最终绑定到哪个属性由 attributeName 的求值结果决定。
- 事件名动态化：v-on:[eventName]=handler，eventName 求值为 focus 时等价于监听 focus 事件。
- 动态参数的求值结果应为**字符串**；求值为 null 表示显式移除该绑定，其他非字符串值会触发警告。

```html
<template>
  <a v-bind:[attributeName]="url">链接</a>
  <button v-on:[eventName]="handleClick">按钮</button>
</template>
```

> 动态参数把配置化能力带进模板：属性名来自数据的场景（如按配置渲染表单控件的属性）由此成为可能；动态参数同样可以与修饰符连用，如 v-on:[eventName].prevent。

**速记**：方括号包**参数表达式**，属性事件皆可动态。



#### 动态参数的语法约束

**语法约束**：动态参数表达式内部不能包含空格与引号，且在 DOM 内模板中受 HTML 属性命名规则的额外限制。

- 表达式里不能出现空格与引号，复杂取值应改用计算属性，不能内联书写。
- DOM 内模板中，浏览器会把 attribute 名统一转成小写，大写变量名会因此失配；SFC 模板由 Vue 自己的编译器解析，不受此限。
- 实务建议：DOM 内模板中动态参数的取值本身采用小写或 kebab-case 命名，配合计算属性完成映射。

```html
<template>
  <!-- DOM 内模板中 dataAttr 会被浏览器转成小写 dataattr，导致失配 -->
  <a v-bind:[dataAttr]="url">链接</a>
</template>
```

> 判断模板类型的方法：写在 html 文件里、由浏览器直接解析的是 DOM 内模板，受全部约束；写在 vue 单文件组件里的模板由 Vue 编译器处理，大小写保留、约束解除，两类模板的完整对比见本篇末节。

**速记**：动态参数**忌空格引号**，DOM 模板忌大写。



### 事件绑定 v-on

#### v-on 与 at 简写

**v-on**：把事件监听器绑定到元素上，简写为 at 符号，是模板中承接用户交互的语法入口。

- 完整写法 v-on:click=handler，简写 @click=handler，二者完全等价。
- 处理器可以是方法名、内联语句或方法调用表达式，传参在内联写法中完成。
- v-on 同样支持动态事件名与修饰符；本篇只立语法入口，事件处理的完整体系（修饰符细节、传参差异、多处理器）详见 6. 事件处理.md。

```html
<template>
  <button v-on:click="handleClick">完整写法</button>
  <button @click="handleClick">at 简写</button>
</template>
```

> v-bind 与 v-on 是使用频率最高的两条指令，一个管属性进、一个管事件出；把这两条指令练到肌肉记忆，模板阅读速度会显著提升。

**速记**：v-on 绑事件，简写**一个 at**。



### 修饰符

#### 点后缀修饰符与常见修饰符一览

**修饰符**：以点开头、缀在指令参数之后的后缀，用声明式写法表达某类固定的细节处理。

- 事件修饰符：.prevent 阻止默认行为、.stop 阻止冒泡、.self 仅事件源自身触发、.capture 改为捕获阶段监听、.once 只触发一次、.passive 提升滚动性能。
- 按键修饰符：.enter、.tab、.delete、.esc、.space 等，把键盘事件精确到具体的键。
- 表单修饰符：.lazy 改为 change 事件后同步、.number 转为数字、.trim 去除首尾空白，配合 v-model 使用。
- v-bind 修饰符：.camel 把 kebab-case 属性名转为 camelCase、.prop 强制绑定为 DOM property。

```html
<template>
  <form @submit.prevent="handleSubmit">阻止默认提交</form>
  <button @click.stop="handleClick">阻止冒泡</button>
  <input v-model.lazy="keyword">
</template>
```

> 修饰符可以**链式连用**，且书写顺序影响语义，例如 @click.prevent.self 与 @click.self.prevent 的行为并不相同；常规场景按语义自然排列即可。表单修饰符与 v-model 的配合详见 7. 表单绑定 v-model.md。

**速记**：修饰符是**点后缀**，事件、按键、表单、属性四族。



#### 修饰符的设计意义

**设计意义**：修饰符把事件处理中高频的样板代码前移为声明式后缀，让处理器方法保持专注。

- 没有修饰符时，阻止默认行为、阻止冒泡要在处理器里手动调用 preventDefault 与 stopPropagation，方法体被机械代码污染。
- 有了修饰符，意图写在模板上，处理器只保留业务逻辑，方法职责单一。
- 修饰符由编译器展开为对应的原生调用，运行时行为与手写等价，没有额外开销。

```js
// 无修饰符时的典型处理器
function handleSubmit(event) {
  event.preventDefault(); // 机械样板代码
  doSubmit();
}
// 使用 @submit.prevent 后，处理器体内只剩 doSubmit()
```

> 修饰符体现 Vue 的分层哲学：模板负责“做什么”的声明，处理器负责“业务怎么做”的实现，机械细节不要渗进业务方法。

**速记**：修饰符**前移样板代码**，处理器只留业务。



### 指令的本质

#### 指令是带 v- 前缀的特殊 attribute

**指令**：带有 v- 前缀的特殊 attribute，是模板中承担逻辑职责的语法单元。

- 内置指令包括 v-html、v-bind、v-on、v-model、v-show、v-if、v-for、v-slot、v-pre、v-cloak、v-memo 等，各司其职。
- 指令的完整语法结构为：指令名:参数.修饰符=值；参数与修饰符均可省略，值按各指令规则可省略。
- 指令与普通 attribute 的本质区别：指令会在表达式的值变化时，**把声明的影响响应式地应用到 DOM 上**。

```text
v-on:submit.prevent="handleSubmit"
 │    │       │          └ 值：表达式
 │    │       └ 修饰符：prevent
 │    └ 参数：submit
 └ 指令名：v-on
```

> 简写符号服务于高频指令：冒号是 v-bind 的简写，at 是 v-on 的简写，井号是 v-slot 的简写；简写只是语法糖，编译结果与完整写法等价。

**速记**：指令的结构为 **指令名 加 参数 加 修饰符 加 表达式**，参数与修饰符可省略。



#### 指令值是单个表达式且响应式求值

**响应式求值**：指令值（少数特殊指令除外）是单个 JavaScript 表达式，Vue 在其依赖变化时重新求值并把结果应用回 DOM。

- 指令值与插值同受表达式限定：不能写语句与流程控制，同样运行在白名单沙箱中。
- 表达式的依赖被响应式系统追踪，依赖变化时指令重新执行，形成数据变、视图变的闭环；追踪原理详见 JavaScript 系列的 29. Proxy、Reflect 与响应式.md。
- 少数指令的值有专属语法：v-for 接收迭代语法，v-on 接收方法名或内联语句，v-slot 接收插槽作用域解构；这些由编译器统一处理。

```html
<template>
  <p v-if="count > 0">当前计数 {{ count }}</p>
  <!-- count 变化时 v-if 重新求值，元素的挂载与卸载随之切换 -->
</template>
```

> 响应式求值的前提是数据本身是响应式的：普通变量赋值的数据不触发任何更新，创建响应式数据的方法详见 3. 响应式基础：ref 与 reactive.md。

**速记**：指令值**响应式求值**，依赖变则 DOM 更。



### SFC 模板与 DOM 内模板

#### 大小写敏感差异

**大小写差异**：DOM 内模板会被浏览器统一转成小写，SFC 模板保留原样大小写，这是两类模板最常见的失配来源。

- DOM 内模板中 attribute 名被浏览器强制小写：camelCase 的 prop 写成 :maxLimit 会失配，应写 kebab-case 的 :max-limit。
- 组件标签同理：DOM 内模板只能使用 kebab-case 标签名，SFC 模板中 PascalCase 与 kebab-case 均可。
- SFC 模板由 Vue 自己的编译器解析，不经浏览器 HTML 解析器，大小写完全保留，无此约束。

```html
<!-- DOM 内模板：必须 kebab-case -->
<my-card max-limit="10"></my-card>
```

```html
<!-- SFC 模板：PascalCase 原样保留 -->
<MyCard :maxLimit="10" />
```

> 官方建议：SFC 中组件名用 PascalCase、prop 用 camelCase，需要兼容 DOM 内模板的场景统一退回 kebab-case。

**速记**：DOM 模板**一律小写**，SFC 保留原样。



#### 自闭合限制

**自闭合限制**：SFC 模板中任何标签都可自闭合，DOM 内模板中只有 HTML 规范的 void 元素允许自闭合。

- 浏览器遵循 HTML 规范，只有 br、img、input 等 void 元素允许不写结束标签，自定义组件标签在 DOM 内模板中必须显式闭合。
- SFC 模板走 Vue 编译器，允许组件标签以斜杠结尾的自闭合写法，且是官方推荐的书写风格。
- 除自闭合外，DOM 内模板还受 HTML 嵌套规则约束：部分元素只容纳特定子元素，组件标签放进去会被浏览器解析器挪出原位置，导致渲染异常。

```html
<!-- SFC 模板：自闭合合法 -->
<MyCard />
```

```html
<!-- DOM 内模板：必须显式闭合 -->
<my-card></my-card>
```

> 典型踩坑是把组件写进 ul、table、select 内部，浏览器会先移走非法子元素，Vue 拿到的模板已经变形；此类场景改用 SFC 模板即可彻底规避。

**速记**：自闭合 **SFC 随意**，DOM 模板仅限 void 元素。



#### 引号与属性值差异

**引号差异**：DOM 内模板的属性值必须用引号包裹，SFC 模板允许省略引号，但工程实践仍建议统一加引号。

- HTML 语法要求所有 attribute 值必须加引号，双引号单引号皆可，DOM 内模板无从例外。
- SFC 模板由 Vue 编译器解析，属性值不加引号也能正确解析，属于编译器宽容。
- 宽容不等于推荐：无引号写法可读性差、易与表达式中的空格混淆，团队规范应统一要求加引号。

```html
<!-- DOM 内模板：引号必须 -->
<my-card title="卡片标题"></my-card>
```

```html
<!-- SFC 模板：可不加引号，但不推荐 -->
<MyCard title=卡片标题 />
```

> 两类模板的取舍一句话概括：DOM 内模板适用于无构建工具的渐进增强场景，约束来自浏览器；SFC 适用于工程化项目，官方全量推荐，本系列后续篇章均以 SFC 为默认载体，SFC 的创建与结构详见 1. Vue3 简介与编写方式.md。

**速记**：DOM 模板**引号必须**，SFC 宽容但仍加引号。
