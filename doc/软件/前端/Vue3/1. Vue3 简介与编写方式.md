## Vue3 简介与编写方式

### 渐进式框架的定义与哲学

#### Vue 是用于构建用户界面的渐进式框架

**渐进式框架（Progressive Framework）**：是 Vue 官方给自身的定位，指一个**可以按需逐层采用**的前端框架，用多少功能就引入多少能力，不必一开始就接受整套技术栈。

- Vue 的核心只解决一件事：**把数据渲染到界面并保持同步**。
- 路由（Vue Router）、状态管理（Pinia）、构建工具链（Vite）都是**可插拔的外围层**。
- 项目规模变大时，再逐层引入对应生态，已有的代码**不需要推倒重写**。

> 渐进式的反面是 all in one：有些框架要求项目从第一天起就接受它的全部约定。Vue 的设计哲学恰好相反——**先用最轻的方式解决眼前问题，规模到了再升级**。

**速记**：Vue 是**能屈能伸**的框架，用一层学一层。



#### 渐进式体现在可以逐层采用

**渐进式的具体路径**：从给静态页面加一点交互，到完整单页应用，再到全栈方案，Vue 在每个阶段都有对应形态。

- **第一阶段（增强静态页）**：一个 script 标签引入 Vue，把数据绑到页面的局部区域，无需构建工具。
- **第二阶段（单页应用 SPA）**：引入组件系统、Vue Router、Pinia，用 create-vue 脚手架搭建工程。
- **第三阶段（全栈与同构）**：需要 SEO 与首屏性能时，采用 Nuxt 这类基于 Vue 的元框架做服务端渲染。

> [!NOTE]
> **提醒内容**：渐进式是采用方式的描述，不是三种不同产品。同一个 Vue 库，既可以只当模板引擎用，也可以撑起整个大型应用，**学习路径同样可以渐进**——本系列前几章只需 CDN 引入即可跟练。

**速记**：静态页加交互 → SPA → 全栈，**三步逐层上**。



### 声明式渲染与虚拟 DOM

#### 声明式渲染对比命令式 DOM 操作

**声明式渲染（Declarative Rendering）**：是 Vue 的核心工作方式，指开发者只**声明数据与界面的映射关系**，由框架自动把数据变化同步到视图。

- **命令式**（原生 DOM 操作）：一步步下达指令——查找元素、修改属性、拼接节点，每一步都亲手写。
- **声明式**（Vue）：只描述「界面上这一块长什么样、由哪些数据决定」，数据变了视图**自动更新**。
- 声明式屏蔽了 DOM 细节，代码量少且不易出现「忘了更新某处视图」的遗漏。

两种写法实现同一个计数器：

```html
<!-- 命令式：亲手操作 DOM -->
<div id="app">
  <p id="count">0</p>
  <button id="btn">加一</button>
</div>
<script>
  let count = 0;
  const btn = document.getElementById("btn");
  btn.addEventListener("click", () => {
    count++;
    document.getElementById("count").textContent = count; // 视图要自己同步
  });
</script>
```

```html
<!-- 声明式：只声明映射关系 -->
<div id="app">
  <p>{{ count }}</p>
  <button @click="count++">加一</button>
</div>
<script>
  Vue.createApp({
    data() {
      return { count: 0 };
    },
  }).mount("#app");
</script>
```

> 命令式的细节（查找元素、监听事件、改文本）在 JavaScript 系列的 10. DOM 基础.md 与 11. DOM 节点与 Web 存储.md 中已系统学过。对比可见：**命令式写的是过程，声明式写的是结果**。DOM 操作越复杂，声明式的省力越明显。

**速记**：命令式**亲手改 DOM**，声明式**只管数据**。



#### 声明式的底层是虚拟 DOM

**虚拟 DOM（Virtual DOM）**：是 Vue 实现声明式渲染的底层机制，指用 **JavaScript 对象来描述真实 DOM 树**的中间层。

- 状态变化时，Vue 先根据新状态生成**新的虚拟 DOM 树**。
- 新旧两棵树做**对比（diff）**，找出真正变化的最小部分。
- 只把变化的部分**应用到真实 DOM**，避免整棵树重排重绘。

```js
// 虚拟 DOM 节点的示意结构（并非实际源码）
const vnode = {
  type: "p",
  props: { class: "title" },
  children: "当前计数为 3",
};
```

> 直接操作真实 DOM 的代价高（触发重排重绘），虚拟 DOM 用**纯 JS 对象运算**代替大部分 DOM 操作，最后只做最小的真实更新。这套机制的深入拆解详见本系列 17. 响应式原理：Proxy 与依赖收集.md 与 19. 渲染机制与 render 函数.md。

**速记**：虚拟 DOM 是**描述界面的 JS 对象**，diff 后**最小化更新**。



### 选项式 API 与组合式 API

#### 选项式 API 以选项对象组织代码

**选项式 API（Options API）**：是 Vue 2 延续下来的组件写法，把组件逻辑按**用途分类**填进固定的选项对象，如 data、methods、computed、watch、生命周期钩子。

- 各选项的职责固定：data 放**响应式数据**，methods 放**方法**，computed 放**计算属性**。
- 选项式是**强约定**的组织方式，新人拿到代码能立刻知道去哪找数据、去哪找方法。
- 简单到中等复杂度的组件用它写起来**整齐直观**。

```js
Vue.createApp({
  data() {
    return { count: 0 };
  },
  methods: {
    increment() {
      this.count++;
    },
  },
  mounted() {
    console.log("组件已挂载，初始值为 " + this.count);
  },
}).mount("#app");
```

> 选项式 API 中 this 指向组件实例，data、methods 中的数据与方法都通过 this 访问。**this 的指向规则**是该风格的配套知识点，写错场景常考。

**速记**：选项式是**分格抽屉**——数据、方法、钩子各归各格。



#### 组合式 API 以函数作用域组织逻辑

**组合式 API（Composition API）**：是 Vue 3 推出的组件写法，在一个 **setup 函数（或 script setup）** 里用 import 进来的 ref、computed、watch、onMounted 等函数，**按逻辑功能而非选项类别**组织代码。

- 数据、方法、钩子不再分散，**同一功能的所有代码写在一起**。
- 逻辑复用靠**组合式函数（composables）**：把一段有状态的逻辑抽成普通函数供多处调用。
- 对 TypeScript 与代码折叠、摇树优化更友好，大型项目可维护性更高。

```js
import { ref, onMounted } from "vue";

export default {
  setup() {
    const count = ref(0);
    function increment() {
      count.value++;
    }
    onMounted(() => {
      console.log("组件已挂载，初始值为 " + count.value);
    });
    return { count, increment };
  },
};
```

> 组合式 API 里的 ref 数据没有 this 可用，**通过 .value 访问与修改**。ref 的响应式细节详见本系列 3. 响应式基础：ref 与 reactive.md，script setup 语法糖详见 13. 组合式 API 与 script setup.md。

**速记**：组合式是**按功能打包**——一个功能的数据、方法、钩子写在一起。



#### 同一计数器的双风格对照

**双风格同构**：选项式与组合式是**同一套运行时的两种外壳**，能力完全等价，写法对应关系固定。

- data 返回的数据 ↔ 组合式里用 **ref** 创建的数据。
- methods 里的方法 ↔ 组合式里的**普通函数**。
- computed、watch、mounted 等选项 ↔ **computed、watch、onMounted** 等同名函数。

```js
// 选项式：逻辑按类别分散在多个选项里
export default {
  data() {
    return { count: 0 };
  },
  methods: {
    increment() {
      this.count++;
    },
  },
  mounted() {
    console.log("mounted: " + this.count);
  },
};
```

```js
// 组合式：计数这一件事的所有代码相邻
import { ref, computed, onMounted } from "vue";

export default {
  setup() {
    const count = ref(0);
    const double = computed(() => count.value * 2);
    function increment() {
      count.value++;
    }
    onMounted(() => console.log("mounted: " + count.value));
    return { count, double, increment };
  },
};
```

> 同一个组件两种写法渲染结果完全一致，**运行时不知道也不区分**你用哪种风格。一个项目中两种风格**可以混用**，但同一组件内部建议保持统一。

**速记**：双风格**能力等价**，只是代码组织的维度不同。



#### 两种风格的选择与官方建议

**选型结论**：官方明确表示**两种风格都是官方支持的一等公民**，选择依据是项目规模与团队背景，而非优劣。

- **学习阶段**：官方教程以选项式开场，概念（数据、方法、钩子）更贴近直觉，**入门更平滑**。
- **中小项目与低复杂度组件**：选项式组织整齐，够用且易读。
- **大型项目、逻辑需要跨组件复用、使用 TypeScript**：组合式优势明显，组件库作者也倾向组合式，便于摇树优化与类型推导。

> [!IMPORTANT]
> **重要内容**：Vue 3 的新特性（如组合式函数、更细的响应式控制）**主要围绕组合式 API 展开**，长期看组合式是重点方向；但选项式并未被废弃，官方承诺持续维护。学习本系列时建议**先通选项式建立概念，再主攻组合式**。

**速记**：入门看**选项式**，深造与大型项目看**组合式**。



### CDN 引入与全局构建

#### 全量构建与 ESM 构建的选用

**CDN 引入**：是不依赖构建工具、用 script 标签直接加载 Vue 的编写方式，适合快速体验、小型页面增强与渐进式改造存量页面。

- **全量构建**（global 构建）：暴露全局变量 Vue，加载后直接用 Vue.createApp，**无需 import**。
- **ESM 构建**（esm-browser 构建）：以 ES 模块形式提供，需在 type 为 module 的 script 里 **import** 使用。
- 两者都是**完整包含编译器**的版本，浏览器内直接编译模板字符串，代价是体积更大。

```html
<!-- 方式一：全量构建，暴露全局变量 Vue，无需 import -->
<script src="https://unpkg.com/vue@3/dist/vue.global.js"></script>
<script>
  Vue.createApp({ /* ... */ }).mount("#app");
</script>

<!-- 方式二：ESM 构建，在 module 脚本中 import 使用 -->
<script type="module">
  import { createApp } from "https://unpkg.com/vue@3/dist/vue.esm-browser.js";
  createApp({ /* ... */ }).mount("#app");
</script>
```

> [!TIP]
> **建议内容**：体验与练习用全量构建最省事；正式的 CDN 页面建议锁定版本号（如 vue@3.5）并使用生产版（文件名带 prod），避免 unpkg 的重定向延迟与开发版的体积告警。

**速记**：CDN 引入**零构建可用**，全量走全局变量，ESM 走 import。



#### createApp 创建并挂载应用

**应用创建流程**：每个 Vue 应用都以 **createApp 函数**为起点，传入根组件得到应用实例，再用 **mount 方法**挂到某个容器元素上。

- createApp(根组件)：返回**应用实例**，参数是根组件的选项对象或组件定义。
- app.mount(容器选择器)：把应用渲染进容器，**返回根组件实例**，返回值可继续操作根组件状态。
- mount 会**清空容器的既有内容**，再把渲染结果填进去；容器内的 Vue 模板属性除外。

```html
<div id="app">
  <h1>{{ title }}</h1>
</div>
<script src="https://unpkg.com/vue@3/dist/vue.global.js"></script>
<script>
  const app = Vue.createApp({
    data() {
      return { title: "我的第一个 Vue 应用" };
    },
  });

  // 挂载前可做全局配置，挂载后配置不再生效
  app.mount("#app");
</script>
```

> 与 Vue 2 的 new Vue().$mount() 不同，Vue 3 一律用 **createApp 工厂函数**创建应用实例。每个应用实例有**独立的全局配置**，避免 Vue 2 中全局配置互相污染的问题。

**速记**：**createApp 出实例，mount 上容器**。



#### 应用的链式配置 app.component 与 app.use

**链式配置**：应用实例在 mount 之前，可以调用一组**注册类方法**完成全局配置，且多数方法**返回应用实例本身**，因此支持链式书写。

- **app.component(名称, 定义)**：注册全局组件，注册后任何组件的模板里都可直接使用。
- **app.use(插件)**：安装插件，如路由、状态管理或自定义插件。
- **app.directive(名称, 定义)**：注册全局自定义指令。
- **app.provide(键, 值)**：在应用层级提供数据，供所有后代组件注入。
- **app.config.globalProperties**：挂载全局属性，所有组件实例都能访问。

```js
const app = Vue.createApp(RootComponent);

app
  .component("my-badge", {
    props: ["text"],
    template: "<span>{{ text }}</span>",
  })
  .use(router)
  .use(pinia)
  .mount("#app");
```

> [!CAUTION]
> **注意内容**：所有 app.component、app.use 等配置必须写在 **mount 调用之前**，mount 之后再注册**不会生效**。全局组件与全局属性也要克制使用——注册越多，组件的依赖关系越隐蔽，不利于维护。

**速记**：链式配置**赶在 mount 之前**，一链到底。



### SFC 单文件组件

#### SFC 的三块结构

**单文件组件（Single-File Component，SFC）**：是把一个组件的**模板、逻辑、样式**封装在同一个 .vue 文件里的编写方式，是工程化 Vue 项目的标准形态。

- **template 块**：写组件的 HTML 模板，使用 Vue 模板语法。
- **script 块**：写组件逻辑；组合式 API 配合 **script setup** 写法时，顶层变量自动暴露给模板。
- **style 块**：写组件样式，默认全局生效，加 scoped 后限定在本组件。

```html
<template>
  <button class="counter" @click="count++">
    点击了 {{ count }} 次
  </button>
</template>

<script setup>
import { ref } from "vue";

const count = ref(0);
</script>

<style scoped>
.counter {
  color: #42b883;
}
</style>
```

> .vue 文件**浏览器无法直接执行**，必须经构建工具编译为标准的 JS 与 CSS，因此 SFC 与 CDN 引入是互斥的两条路线：**要 SFC 就要有工程**。

**速记**：SFC 一文件**三件套**——template、script、style。



#### scoped 样式与 lang 属性

**scoped 隔离**：给 style 块加上 **scoped 属性**后，样式只作用于本组件的元素，原理是编译时给本组件元素追加**唯一的 data 属性**并改写选择器。

- 父组件的 scoped 样式**影响不到子组件的内部结构**（子组件根节点除外）。
- 需要**深度选中**子组件内部元素时，使用 :deep() 伪类包裹选择器。
- **lang 属性**：声明块使用的语言，如 script 加 lang="ts" 写 TypeScript、style 加 lang="scss" 写 SCSS，需要对应依赖支持。

```html
<style scoped>
/* 编译后形如 .title[data-v-7ba5bd90]，天然隔离 */
.title {
  font-size: 20px;
}

/* 深度选择：命中子组件内部的元素 */
:deep(.inner-list) {
  margin: 0;
}
</style>
```

> [!WARNING]
> **警告内容**：scoped 是**选择器层面的隔离**而非 Shadow DOM，子组件根节点仍会被父组件样式命中，第三方组件库的内部元素也可能因选择器改写而打不中，需要 :deep() 配合。不要把 scoped 理解成绝对的样式沙箱。

**速记**：scoped 靠 **data 属性改写选择器**，lang 切换**预处理器**。



### create-vue 脚手架与 Vite

#### create-vue 脚手架创建项目

**create-vue**：是 Vue 官方的项目脚手架工具，一条命令交互式生成**基于 Vite 的标准工程**，命令为 npm create vue@3。

- 执行后依次询问：项目名、是否 TypeScript、是否 JSX、是否 Vue Router、是否 Pinia、是否单元测试等。
- 全部选否即得到**最小可用项目**，后续可再按需补配。
- 生成的项目自带开发服务器、生产构建与代码检查脚本，开箱即用。

```bash
# 创建一个新的 Vue3 项目（npm 7 及以上可用此简写）
npm create vue@3

# 交互完成后进入项目并启动开发服务器
cd 新项目目录
npm install
npm run dev
```

> [!NOTE]
> **提醒内容**：create-vue 是 Vue 3 时代替代 Vue CLI 的官方脚手架，Vue CLI 已进入维护模式，新项目不要再选。npm create vue@3 中的 3 表示拉取 create-vue 的第 3 大版本，与 Vue 3 配套。

**速记**：一条 **npm create vue@3**，问答式生成 Vite 工程。



#### Vite 为何快

**Vite 的快**：来自两个设计——开发环境**原生 ESM 按需编译**，以及依赖**预构建**，使启动与热更新速度远超传统打包方案。

- 传统打包器（如 webpack）启动时要**把整个应用打包完**才提供服务，项目越大启动越慢。
- Vite 开发时**不打包业务代码**：浏览器按 import 路径逐个请求源码模块，Vite **按需转换单个文件**再返回。
- 第三方依赖用 esbuild **预构建**成单文件缓存，esbuild 用 Go 编写，比 JS 编写的打包器快一个数量级。
- 热更新（HMR）只替换**被修改的那一个模块**，与项目总大小基本无关。

```text
webpack 开发模式：启动 → 全量打包全部模块 → 才能访问（大项目以分钟计）
Vite   开发模式：启动（秒级）→ 浏览器请求哪个模块，就只编译哪个模块
```

> 生产构建时 Vite 使用 Rollup 做打包，输出高度优化的静态资源；快的是**开发体验**，产物质量与成熟打包器同水平。

**速记**：Vite 快在**按需编译加预构建**，改哪编译哪。



#### 工程项目的目录结构概览

**标准结构**：create-vue 生成的项目有固定的目录约定，src 是业务代码的家，理解每一处职责才能顺利定位文件。

- **src/main.js**：应用入口，调用 createApp 并 mount 到 index.html 的容器。
- **src/App.vue**：根组件，组件树的顶层。
- **src/components**：可复用的业务组件。
- **src/assets**：静态资源（图片、字体），经构建工具处理。
- **src/router**：选装 Vue Router 后生成，放路由配置。
- **src/stores**：选装 Pinia 后生成，放状态仓库。
- **public**：不经构建直接原样拷贝的静态文件。
- **vite.config.js**：Vite 配置文件，可配置别名、代理、插件。

```text
my-vue-app/
├── public/              # 原样拷贝的静态文件
├── src/
│   ├── assets/          # 参与构建的静态资源
│   ├── components/      # 业务组件
│   ├── App.vue          # 根组件
│   └── main.js          # 入口：createApp + mount
├── index.html           # 挂载容器所在
└── vite.config.js       # Vite 配置
```

> 与 CDN 方式对照：CDN 写法里所有组件挤在一个 script 里，工程写法则**一个组件一个 .vue 文件**，入口文件只负责创建应用。后续章节的示例默认以该工程结构为背景。

**速记**：入口 **main.js** 创建应用，业务代码都住 **src**。



### Vue3 相对 Vue2 的核心变化

#### 响应式从 defineProperty 改为 Proxy

**响应式系统重构**：Vue 3 用 **Proxy 对象**替换 Vue 2 的 **Object.defineProperty** 实现数据侦测，这是最底层、影响最广的变化。

- Vue 2 的 defineProperty 只能**劫持已存在的属性**，新增、删除属性侦测不到，数组下标赋值也侦测不到，需要 $set 等补丁方法。
- Proxy 代理的是**整个对象**，属性的新增、删除、数组索引修改全部可侦测，无需任何补丁 API。
- Vue 3 中 data 返回的对象、ref 包裹的值都基于 Proxy，**直接改就是响应式**。
- 支持了 Map、Set 等集合类型的响应式，且嵌套对象**访问时才代理**（惰性），初始化开销更小。

```js
// Vue 2 的痛点：这些写法视图不更新，需要 $set
this.list[0] = newValue;
this.obj.newKey = value;

// Vue 3 的 Proxy：同样的写法天然响应式
this.list[0] = newValue; // 正常更新
this.obj.newKey = value; // 正常更新
```

> 原理层面的代理拦截、依赖收集与触发更新详见本系列 17. 响应式原理：Proxy 与依赖收集.md。此处在概览层面只需记住结论：**Vue 3 没有响应式的死角补丁，改值即更新**。

**速记**：defineProperty **有盲区**，Proxy **无死角**。



#### 组合式 API 的引入与逻辑复用改善

**组合式 API 登场**：Vue 3 新增的第二种组件风格，直接目的是解决 Vue 2 时代**逻辑复用与代码组织**的两大痛点。

- Vue 2 复用逻辑靠 **mixin**，但 mixin 存在命名冲突、来源不透明、属性难以追溯的问题。
- 组合式 API 把逻辑抽成**普通函数（组合式函数）**，来源清晰、可传参、可类型化。
- 相关逻辑可以**聚合书写**，不必在 data、methods、watch 之间来回跳转。

```js
// Vue 2 的复用方式：mixin，来源不可见
export default {
  mixins: [mousePositionMixin, themeMixin], // x、y 来自哪个 mixin？难以回答
};

// Vue 3 的复用方式：组合式函数，import 即见来源
import { useMousePosition } from "./useMousePosition";
import { useTheme } from "./useTheme";

const { x, y } = useMousePosition();
const { theme, toggleTheme } = useTheme();
```

> 组合式函数的写法与约定详见本系列 14. 组合式函数 composables.md。命名约定是 use 前缀（如 useMousePosition），与 React 的自定义 Hook 思想相通，但实现机制不同。

**速记**：mixin **隐晦易冲突**，组合式函数**显式可追踪**。



#### Fragment 多根节点模板

**Fragment（片段）**：指 Vue 3 组件的模板**允许有多个根节点**，不再强制单一根元素包裹。

- Vue 2 模板必须**只有一个根元素**，常被迫包一层无意义的 div。
- Vue 3 模板可以并列多个元素、注释、文本节点，减少无意义嵌套。
- 多根节点时，**透传属性（class、id 等）不会自动落到任何元素上**，需要显式声明处理或手动绑定。

```html
<!-- Vue 2：必须单根，包一层多余的 div -->
<template>
  <div>
    <header>头部</header>
    <main>内容</main>
  </div>
</template>
```

```html
<!-- Vue 3：多根合法，无多余包裹 -->
<template>
  <header>头部</header>
  <main>内容</main>
</template>
```

> [!IMPORTANT]
> **重要内容**：多根组件若被外部传入 class 或其他属性，运行时会**发出警告**提示无法自动继承。要么给组件包回单根节点，要么在组件内用 useAttrs 接管透传属性。单根组件的透传行为保持与 Vue 2 一致。

**速记**：Vue 3 模板**多根合法**，代价是**属性不自动透传**。



#### 被移除的特性：过滤器与事件总线

**特性清理**：Vue 3 删除了一批 Vue 2 的旧能力，最常见的两个是**过滤器（filter）**与**事件总线（Event Bus）**，迁移时必须改写。

- **过滤器**：模板中用管道符做文本格式化（{{ value | currency }}）。Vue 3 中改用**计算属性或方法**替代。
- **事件总线**：Vue 2 里常 new 一个 Vue 实例当全局事件中心做跨组件通信。Vue 3 中 createApp 不再提供 $on 与 $off，推荐改用 **Pinia** 或**外部 mitt 库**。
- 同时移除的还有 **$children**、内联模板 inline-template、键盘修饰符的数字键码写法等（按官方迁移指南逐项核对）。

```js
// Vue 2：过滤器格式化金额，模板写 {{ price | currency }}
filters: {
  currency(value) {
    return "¥" + value.toFixed(2);
  },
},
```

```js
// Vue 3：用计算属性替代
import { ref, computed } from "vue";

const price = ref(9.8);
const priceText = computed(() => "¥" + price.value.toFixed(2));
// 模板改写为：{{ priceText }}
```

> [!WARNING]
> **警告内容**：Vue 2 项目里大量出现的 EventBus.$emit 跨组件通信在 Vue 3 下**直接报错**。改造存量代码时优先把共享逻辑归入状态管理（Pinia），只剩纯事件通知场景再引入 mitt 之类的第三方库。

**速记**：过滤器**改成计算属性**，事件总线**交给 Pinia 或 mitt**。



#### 性能提升的来源

**性能提升**：Vue 3 相对 Vue 2 在渲染、更新与体积三个维度均有可观的改进，主要来自四项底层优化。

- **响应式改用 Proxy**：惰性代理嵌套对象，初始化开销更小（见前文）。
- **编译期优化**：模板编译器标记**静态节点（patchFlag 与 Block Tree）**，diff 时直接跳过静态内容，只比对其余动态部分。
- **事件缓存**：内联事件处理函数被缓存，避免每次渲染都生成新函数导致子组件无谓更新。
- **体积更小、摇树友好**：核心按 API 导出，未使用的 API 在打包时可被剔除，运行时体积比 Vue 2 更小。

> 性能优化是编译器与运行时**协同**的结果：正因为模板写法足够规约，编译器才能提前分析出哪些部分永远不变。这也是官方推荐模板优先于手写渲染函数的原因之一。

**速记**：静态**跳过**、事件**缓存**、依赖**摇树**，三招提速减重。



### 选型建议与迁移路径

#### 新项目直接采用 Vue3

**新项目结论**：一切新项目**直接采用 Vue 3 及其配套生态**，不要再基于 Vue 2 启动。

- Vue 2 已于官方公告的时间点停止维护，不再接收常规更新，新漏洞风险自担。
- 配套生态均为 Vue 3 版本：路由用 **Vue Router 4**，状态管理用 **Pinia**（Vuex 的继任者）。
- 工具链以 create-vue 加 Vite 为标准配置，与 Vue 3 的编译优化完全匹配。
- TypeScript 支持、性能、开发体验在 Vue 3 上全面占优，新项目没有留在 Vue 2 的理由。

> [!TIP]
> **建议内容**：新项目的默认组合记住一套即可——**Vue 3 加 create-vue 加 Vite 加 Vue Router 4 加 Pinia**。本系列后续章节全部基于这一组合展开。

**速记**：新项目**只选 Vue 3**，Router 4 配 Pinia。



#### Vue2 存量项目的迁移路径 @vue/compat

**迁移构建（@vue/compat）**：是官方提供的 **Vue 2 兼容层**，让存量 Vue 2 项目能在 Vue 3 运行时上以兼容模式逐步运行，最终摘掉兼容层完成迁移。

- 第一步：升级到 @vue/compat 构建并修复启动报错，此时大部分 Vue 2 写法仍可用。
- 第二步：按**编译器给出的运行时警告**逐个改写不兼容写法（过滤器、事件总线、全局 API 改为应用实例方法等）。
- 第三步：警告清零后，把依赖从 @vue/compat 换成纯 Vue 3，迁移完成。
- 配套改造：Vuex 视情况换 Pinia，Vue CLI 工程可同步迁到 Vite，也可保留构建工具只迁框架。

> [!CAUTION]
> **注意内容**：迁移的价值取决于项目要继续长期维护。若只是只读的老项目或生命周期临近尾声，保留 Vue 2 不动反而更稳妥；**先评估再迁移**，不要为了新版本而迁移。

**速记**：@vue/compat 当**过渡桥**，警告清零即上岸。



### 本章小结

#### 核心概念回顾

**一句话收束**：Vue 3 是一个渐进式、声明式的用户界面框架，提供选项式与组合式两种等价写法，支持 CDN、SFC 与完整工程三种落地形态，相对 Vue 2 完成了响应式与性能的底层重构。

- 渐进式声明式：按需逐层采用，只声明数据与视图的映射，虚拟 DOM 负责最小化更新。
- 双风格：选项式分格归档，组合式按功能聚合，能力等价。
- 三形态：CDN 零构建、SFC 单文件组件、create-vue 完整工程。
- 对比 Vue 2：Proxy 响应式、组合式 API、Fragment 多根、移除过滤器与事件总线、性能更强。

> 后续章节将以 create-vue 工程为背景、组合式 API 为主线展开；模板语法的细节从下一篇 2. 模板语法与指令基础.md 开始。

**速记**：**渐进声明两风格，CDN、SFC、工程三形态**。
