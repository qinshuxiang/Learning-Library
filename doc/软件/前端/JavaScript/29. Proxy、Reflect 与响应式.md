## Proxy、Reflect 与响应式

### 监听对象属性的操作

#### 监听方式一

要**监听对象属性的变化**，第一种方式是**手动封装** set/get 方法。

```js
const obj = {
  name: "why",
  setName(name) {
    console.log(`name 被修改为 ${name}`);
    this.name = name;
  },
  getName() {
    return this.name;
  }
};

obj.setName("tom"); // 触发日志
console.log(obj.getName()); // "tom"
```

> 这种方式的缺点是**繁琐、不通用**：每个属性都要手写 set/get，且破坏了"直接赋值"的自然语法（必须 obj.setName() 而非 obj.name = ...）。因此需要更优雅的监听方案。



#### 监听方式二

第二种方式是用 **Object.defineProperty 的 getter/setter** 拦截属性的读写。

```js
const obj = { _name: "why" };

Object.defineProperty(obj, "name", {
  get() {
    return this._name;
  },
  set(value) {
    console.log(`name 被修改为 ${value}`);
    this._name = value;
  }
});

obj.name = "tom"; // 触发 set，输出日志
console.log(obj.name); // "tom"
```

> Object.defineProperty 能**拦截单个属性**的读写，保留了 obj.name = ... 的自然语法。但它仍有局限：**只能拦截已知属性**（新增属性无法监听）、**需要遍历每个属性**、**无法监听数组索引变化**。这正是 Vue2 响应式的实现方式，也是它的局限所在。



### Proxy

#### Proxy 的基本使用

**Proxy**（ES6）：用于**拦截对象的所有操作**，创建一个"代理"来定制对象的行为，是监听对象的**终极方案**。

```js
const target = { name: "why" };

const proxy = new Proxy(target, {
  get(target, key) {
    console.log(`读取了 ${key}`);
    return target[key];
  },
  set(target, key, value) {
    console.log(`设置了 ${key} = ${value}`);
    target[key] = value;
    return true;
  }
});

proxy.name;        // 读取了 name
proxy.age = 18;    // 设置了 age = 18
console.log(proxy.age); // 18
```

> new Proxy(target, handler) 创建代理：target 是被代理对象，handler 是**捕获器（trap）**对象。相比 defineProperty，Proxy 能**拦截任意属性**（含新增、数组索引），能力全面得多，是 Vue3 响应式的底层。



#### Proxy 的其他 13 个捕获器

Proxy 提供了 **13 个捕获器**，分别拦截不同的操作。

##### get 与 set 捕获器

- **get(target, key, receiver)**：拦截**读取**。
- **set(target, key, value, receiver)**：拦截**写入**。

```js
const proxy = new Proxy({}, {
  get(target, key) {
    console.log("读取", key);
    return target[key];
  },
  set(target, key, value) {
    console.log("写入", key, value);
    target[key] = value;
    return true; // set 必须返回 true
  }
});
```

> [!CAUTION]
> **注意**：get/set 是最常用的捕获器，用于**数据拦截、校验、日志**。set 必须**返回 true**（表示设置成功），否则严格模式下会报错。



##### has 与 deleteProperty 捕获器

- **has(target, key)**：拦截 in 操作符。
- **deleteProperty(target, key)**：拦截 delete 操作。

```js
const proxy = new Proxy({ a: 1 }, {
  has(target, key) {
    console.log("判断", key);
    return key in target;
  },
  deleteProperty(target, key) {
    console.log("删除", key);
    delete target[key];
    return true;
  }
});

console.log("a" in proxy); // 判断 a → true
delete proxy.a;            // 删除 a
```

> has 拦截 in、deleteProperty 拦截 delete。它们让"成员判断"和"删除"也可被监听，是完整拦截对象操作的一部分。



##### 函数相关的 apply 与 construct 捕获器

- **apply(target, thisArg, args)**：拦截**函数调用**。
- **construct(target, args)**：拦截 new 调用。

```js
function greet(name) {
  return `Hello, ${name}`;
}

const proxy = new Proxy(greet, {
  apply(target, thisArg, args) {
    console.log("函数被调用，参数：", args);
    return target.apply(thisArg, args);
  },
  construct(target, args) {
    console.log("被 new 调用");
    return new target(...args);
  }
});

console.log(proxy("why")); // 函数被调用，参数：["why"] → "Hello, why"
```

> apply 拦截普通调用、construct 拦截 new 调用。它们让**函数**也能被代理，是 AOP（面向切面编程）的基础。



##### 其他捕获器

其余捕获器拦截各类操作。

- **getPrototypeOf / setPrototypeOf**：拦截原型操作。
- **isExtensible / preventExtensions**：拦截可扩展性操作。
- **getOwnPropertyDescriptor / defineProperty**：拦截属性描述符操作。
- **ownKeys**：拦截 Object.keys、for-in 等。
- **getOwnPropertyNames** 等。

```js
const proxy = new Proxy({}, {
  ownKeys(target) {
    console.log("枚举属性");
    return Reflect.ownKeys(target);
  }
});
```

> 这些捕获器覆盖了对象的**全部底层操作**，让 Proxy 成为"**完全透明**"的代理层。掌握常用的 get/set/has/deleteProperty 即可应对多数场景，其余按需查阅。



#### 可撤销的 Proxy

**Proxy.revocable(target, handler)**：创建**可撤销**的代理，撤销后代理失效。

```js
const { proxy, revoke } = Proxy.revocable({}, {
  get(target, key) {
    return target[key];
  }
});

proxy.a;   // 正常访问
revoke();  // 撤销代理
// proxy.a; // TypeError：代理已撤销
```

> revocable 返回 { proxy, revoke }，调用 revoke() 后代理**立即失效**。它适合"**只允许在特定阶段访问**"的场景（如安全控制、临时授权）。



### Reflect

#### Reflect 的作用与 Proxy 同时使用

**Reflect**：是一个内置对象，提供了一组**与对象操作对应的静态方法**，常与 Proxy 搭配使用。

- Reflect 的方法与 Proxy 的捕获器**一一对应**。
- 在 Proxy 捕获器里，用 Reflect 完成**默认行为**，避免手动实现。

```js
const proxy = new Proxy({}, {
  get(target, key, receiver) {
    console.log("读取", key);
    return Reflect.get(target, key, receiver); // 默认读取
  },
  set(target, key, value, receiver) {
    console.log("写入", key);
    return Reflect.set(target, key, value, receiver); // 默认写入
  }
});

proxy.name = "why";
console.log(proxy.name);
```

> Reflect 的定位是"**默认行为的标准化入口**"：在 Proxy 捕获器里先做自定义逻辑，再调用 Reflect.xxx 完成默认操作，代码更清晰、更规范（Reflect 返回布尔值，比 Object 的抛错更友好）。



#### Reflect 与 Proxy 中的 receiver

**receiver 参数**：是 get/set 捕获器的第三个参数，指向**实际调用者**，用于正确处理原型链上的 this。

```js
const parent = {
  get name() {
    return this._name;
  }
};

const proxy = new Proxy(parent, {
  get(target, key, receiver) {
    // receiver 指向 proxy 本身（而非 target）
    return Reflect.get(target, key, receiver);
  }
});

const child = Object.create(proxy);
child._name = "child";
console.log(child.name); // "child"（receiver 保证 this 指向 child）
```

> receiver 的价值在于**传递正确的 this**：当代理对象出现在原型链上时，receiver 指向**真正的调用者**，Reflect.get(target, key, receiver) 能把 this 正确绑定到调用者，避免 getter 里的 this 指向错误。



#### Reflect 的 construct 方法

**Reflect.construct(target, args, newTarget?)**：以 new 方式调用构造函数。

```js
function Person(name) {
  this.name = name;
}

// 等价于 new Person("why")
const p = Reflect.construct(Person, ["why"]);
console.log(p.name); // "why"
```

> Reflect.construct 是 new 的**函数式替代**，还能指定 newTarget（改变原型）。它比 new 更灵活，适合在函数式、动态构造的场景中使用。



### 响应式原理

#### 认识响应式

**响应式（Reactive）**：是指当**数据变化时，依赖它的 UI 自动更新**的机制，是现代前端框架（Vue、React）的核心。

```js
// 理想效果：修改数据，UI 自动更新
const state = { count: 0 };
// 修改 count 后，视图自动重新渲染
```

> 响应式的本质是"**数据与视图的自动同步**"：你只管改数据，框架自动更新界面。它把开发者从"手动操作 DOM"中解放出来，是 Vue、React 等框架的核心价值。



#### 响应式函数与依赖收集

实现响应式，需要**依赖收集**：记录"哪些函数依赖了哪些数据"。

```js
// 响应式函数：需要自动执行的函数
let activeEffect = null;

function watchEffect(fn) {
  activeEffect = fn;
  fn();               // 首次执行，触发依赖收集
  activeEffect = null;
}

// 数据变化时，重新执行依赖它的函数
function trigger() {
  // 找到依赖该数据的函数并执行
}
```

> 依赖收集的思路：**执行响应式函数时，记录它访问了哪些数据**（读数据时把函数登记到该数据的依赖列表），数据变化时**通知这些函数重新执行**。这就是 Vue3 响应式的雏形。



#### 用 Proxy 监听对象的变化

用 Proxy 实现数据的**读写拦截**，是响应式的第一步。

```js
function reactive(target) {
  return new Proxy(target, {
    get(target, key, receiver) {
      // 依赖收集：记录当前函数依赖了 key
      track(target, key);
      return Reflect.get(target, key, receiver);
    },
    set(target, key, value, receiver) {
      const result = Reflect.set(target, key, value, receiver);
      // 触发更新：通知依赖 key 的函数
      trigger(target, key);
      return result;
    }
  });
}

const state = reactive({ count: 0 });
state.count;      // 读取时收集依赖
state.count = 1;  // 修改时触发更新
```

> Proxy 的 get 里做**依赖收集**（track），set 里做**触发更新**（trigger）。相比 Vue2 的 defineProperty，Proxy 能拦截**新增属性、数组操作**，是更完善的响应式基础。



#### 依赖的保存结构

依赖需要一个**保存结构**，记录"哪个对象 → 哪个属性 → 哪些函数"。

```js
// 依赖结构：Map 套 Map 套 Set
// targetMap: Map<target, Map<key, Set<effect>>>
const targetMap = new WeakMap();

function track(target, key) {
  let depsMap = targetMap.get(target);
  if (!depsMap) {
    targetMap.set(target, (depsMap = new Map()));
  }
  let deps = depsMap.get(key);
  if (!deps) {
    depsMap.set(key, (deps = new Set()));
  }
  deps.add(activeEffect); // 记录依赖
}
```

> 依赖结构通常是**三层嵌套**，写法如下：
>
> ```ts
> WeakMap<target, Map<key, Set<effect>>>
> ```
>
> 外层 WeakMap 按对象存（弱引用），中层 Map 按属性存，内层 Set 存依赖函数（去重）。这种"三层嵌套"结构是 Vue3 响应式存储依赖的标准形态。



#### 正确收集依赖的过程

完整的依赖收集需在**函数执行时**追踪，函数结束时清理，避免**脏依赖**。

```js
let activeEffect = null;

function watchEffect(fn) {
  activeEffect = fn;
  fn();                    // 执行时，访问属性触发 track
  activeEffect = null;     // 执行完，清空
}

function trigger(target, key) {
  const depsMap = targetMap.get(target);
  if (!depsMap) return;
  const deps = depsMap.get(key);
  deps && deps.forEach((effect) => effect()); // 通知所有依赖函数
}
```

> 正确收集依赖的关键：**执行响应式函数时**设置 activeEffect，函数访问属性时把它登记为依赖，执行完清空。数据变化时 trigger 找到并**重新执行**依赖函数，实现"数据变了、函数自动跑"。



#### Depend 类的优化

把依赖收集逻辑封装成**类**，使代码更清晰、可复用。

```js
class Depend {
  constructor() {
    this.reactiveFns = new Set();
  }
  depend() {
    if (activeEffect) {
      this.reactiveFns.add(activeEffect);
    }
  }
  notify() {
    this.reactiveFns.forEach((fn) => fn());
  }
}
```

> 用 Depend 类封装"**依赖的收集与通知**"：depend() 收集、notify() 通知。这种封装让响应式逻辑更内聚，是 Vue3 内部 Dep 类的简化版。



#### Vue2 与 Vue3 的响应式实现

Vue2 与 Vue3 的响应式实现有本质区别。

- **Vue2**：用 Object.defineProperty 劫持属性 getter/setter。
  - 局限：**无法监听新增/删除属性**、**需遍历所有属性**、**数组需特殊处理**。
- **Vue3**：用 Proxy 代理整个对象。
  - 优势：**能监听新增/删除属性**、**能监听数组变化**、**无需遍历**、性能更好。

```js
// Vue2：defineProperty（需遍历、无法监听新增）
// Vue3：Proxy（代理整个对象，全面拦截）
const state = reactive({ count: 0 }); // Vue3 的 reactive 基于 Proxy
```

> Vue3 用 Proxy 彻底解决了 Vue2 defineProperty 的痛点（新增属性、数组索引无法监听），这是 Vue3 响应式最重要的升级。理解 Proxy，也就理解了 Vue3 响应式的核心。
