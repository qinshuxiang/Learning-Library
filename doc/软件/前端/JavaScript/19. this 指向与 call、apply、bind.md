## this 指向与 call、apply、bind

### this 的认识

#### 为什么需要 this

**this**：是函数内部的一个特殊关键字，指向**调用该函数的对象**。它的存在解决了"**方法如何引用自己所属对象**"的问题。

```js
const user = {
  name: "coderwhy",
  sayName() {
    console.log(this.name); // 用 this 引用 user 自己
  }
};

user.sayName(); // "coderwhy"
```

> 为什么不用 user.name 而用 this.name？因为 this 让方法**与具体对象解耦**——同一段 this.name 代码，可以被任意对象复用，this 指向谁就输出谁。这正是 this 存在的意义：**在方法内部动态引用"当前对象"**。



#### this 在全局环境下的指向

在全局作用域下，this 的指向因环境而异。

- **浏览器**：全局 this 指向 window。
- **Node.js**：全局 this 指向空对象 {}（模块环境）。
- **严格模式**：函数内的 this 为 undefined。

```js
// 浏览器全局
console.log(this === window); // true

// 严格模式下的函数
function strictFn() {
  "use strict";
  console.log(this); // undefined
}
```

> 全局 this 的指向是理解 this 的起点：浏览器中它就是 window。而严格模式改变了普通函数调用时 this 的默认行为（undefined 而非 window），这是"默认绑定"规则的重要细节。



#### 不同的执行方式与结果

同一个函数，**以不同方式调用**，this 指向不同——这正是 this 最核心的特性。

```js
const obj = {
  name: "obj",
  show() {
    console.log(this.name);
  }
};

obj.show();        // "obj"（作为方法调用，this 是 obj）

const fn = obj.show;
fn();              // undefined（作为普通函数调用，this 是 window）
```

> 关键结论：**this 不由函数定义位置决定，而由调用方式决定**。同样一个 show 函数，obj.show() 时 this 是 obj，赋值后 fn() 调用时 this 变成了全局。这一"动态绑定"是 this 区别于词法作用域的本质。



### this 的绑定规则

#### 默认绑定

**默认绑定**：是最基础的规则，适用于**独立函数调用**，此时 this 指向全局对象（严格模式下为 undefined）。

```js
function foo() {
  console.log(this); // window（非严格模式）
}

foo(); // 独立调用，默认绑定
```

> 默认绑定的判断标准是"**直接调用、没有对象前缀**"。foo() 这种裸调用就触发默认绑定。注意：严格模式下默认绑定的 this 是 undefined，而非 window。



#### 隐式绑定

**隐式绑定**：当函数**作为对象的方法调用**时，this 指向**调用它的那个对象**。

```js
const obj = {
  name: "obj",
  foo() {
    console.log(this.name);
  }
};

obj.foo(); // "obj"（通过 obj 调用，隐式绑定到 obj）
```

> [!CAUTION]
> **注意内容**：判断隐式绑定的关键是看"**调用点有没有对象前缀**"：obj.foo() 中 foo 前的 obj 就是 this 的绑定对象。但要注意：隐式绑定**容易丢失**（把方法赋值给变量再调用，就退化为默认绑定）。



#### 显式绑定

**显式绑定**：通过 call、apply、bind 方法**强制指定** this 的指向，优先级高于默认绑定。

##### call 方法

**fn.call(thisArg, arg1, arg2, ...)**：调用函数并指定 this，参数**逐个**传入。

```js
function greet(greeting, punctuation) {
  console.log(`${greeting}, ${this.name}${punctuation}`);
}

const person = { name: "coderwhy" };
greet.call(person, "Hello", "!"); // "Hello, coderwhy!"
```

> call 的第一个参数是 this 的绑定对象，后续参数是函数的实参（**逐个传入**）。它实现了"借方法"：让一个函数以指定对象为 this 执行。



##### apply 方法

**fn.apply(thisArg, [arg1, arg2, ...])**：与 call 唯一区别是参数以**数组**形式传入。

```js
function sum(a, b, c) {
  return a + b + c;
}

console.log(sum.apply(null, [1, 2, 3])); // 6（参数以数组传入）
console.log(sum.call(null, 1, 2, 3));    // 6（参数逐个传入）
```

> call 与 apply 的唯一区别是**参数传递形式**：call 逐个传，apply 传数组。记忆口诀：**"call 逗号分开，apply 数组打包"**。apply 常用于参数是现成数组的场景（如 Math.max.apply(null, arr)）。



##### bind 方法

**fn.bind(thisArg, ...)**：**返回一个新函数**，新函数的 this 被永久绑定为 thisArg，**不会立即执行**。

```js
function greet() {
  console.log(`Hello, ${this.name}`);
}

const person = { name: "coderwhy" };
const boundGreet = greet.bind(person); // 返回新函数
boundGreet(); // "Hello, coderwhy"
```

> bind 与 call/apply 的本质区别：**bind 不立即执行，而是返回绑定了 this 的新函数**。它常用于"**永久固定 this**"的场景（如事件回调、定时器回调中保持 this 指向）。



#### new 绑定

**new 绑定**：当函数作为**构造函数**用 new 调用时，this 指向**新创建的对象**。

```js
function Person(name) {
  this.name = name; // this 指向新对象
}

const p = new Person("coderwhy");
console.log(p.name); // "coderwhy"
```

> new 调用时，引擎会创建一个新对象，并把 this 绑定到它。因此构造函数里的 this.xxx = ... 是给**新实例**添加属性。new 绑定的优先级**高于**显式绑定和隐式绑定（见后续"优先级"小节）。



#### 从 ECMA 规范解读 this

从 ECMAScript 规范角度，this 的绑定在**执行上下文创建时**确定，遵循特定步骤。

核心理解：

- 函数调用时，引擎根据**调用方式**计算 this。
- 普通调用 → 绑定全局（或 undefined）。
- 方法调用 → 绑定调用对象。
- call/apply/bind → 绑定指定对象。
- new → 绑定新实例。

```js
// 规范视角：this 由 Call 操作的 thisMode 决定
// 严格模式（strict）：独立调用 this 为 undefined
// 非严格模式（sloppy）：独立调用 this 为全局对象
```

> 从规范层面理解，能破除"this 很玄学"的误解：**this 的绑定有一套明确、可预测的规则**（默认、隐式、显式、new 四种），只要按"调用方式"对号入座，就能准确判断。规范只是把这几条规则形式化了。



### 绑定规则的优先级

#### 多个绑定规则的优先级比较

当多个规则同时适用时，按**优先级从高到低**判断。

优先级顺序：

1. **new 绑定**（最高）。
2. **显式绑定**（call/apply/bind）。
3. **隐式绑定**（对象方法）。
4. **默认绑定**（最低）。

```js
function foo() {
  console.log(this.name);
}

const obj1 = { name: "obj1", foo };
const obj2 = { name: "obj2" };

obj1.foo();                 // "obj1"（隐式绑定）
obj1.foo.call(obj2);        // "obj2"（显式绑定优先于隐式）
```

> 记忆优先级：**"new > 显式 > 隐式 > 默认"**。上例中 obj1.foo.call(obj2) 同时有隐式（obj1）和显式（obj2），结果显式胜出，this 是 obj2。这套优先级是判断一切 this 指向的"万能钥匙"。



#### 忽略显式绑定与间接函数引用

显式绑定有**边界情况**需注意：传 null/undefined 会被**忽略**，间接引用会**丢失绑定**。

```js
function foo() {
  console.log(this);
}

// 传 null/undefined：显式绑定被忽略，退化为默认绑定
foo.call(null);      // window（非严格模式）
foo.call(undefined); // window

// 间接引用丢失绑定
const obj = { foo };
(obj.foo = obj.foo)(); // 赋值表达式的返回值是函数，独立调用 → 默认绑定
```

> [!CAUTION]
> **注意内容**：两个易错点：一是 call(null) 的 null 会被**忽略**，this 落到默认绑定；二是 (obj.foo = obj.foo)() 这种**间接引用**返回的是函数本身，调用时丢失了 obj 前缀，退化为默认绑定。



#### 系统 API 中 this 的指向

许多内置 API 的**回调函数**中，this 有特定指向，需了解。

- **forEach/map 等**：默认 this 为 undefined（严格模式），但可传第二个参数指定。
- **事件监听 addEventListener**：回调里的 this 指向**绑定事件的元素**。
- **定时器**：回调里的 this 指向全局对象。

```js
// forEach 的第二个参数可指定 this
const arr = [1, 2, 3];
arr.forEach(function (item) {
  console.log(this.name);
}, { name: "自定义 this" }); // "自定义 this"

// 事件监听：this 是绑定事件的元素
button.addEventListener("click", function () {
  console.log(this === button); // true
});
```

> 系统 API 的 this 各有约定：数组方法可通过**第二个参数**指定 this，事件回调的 this 是**当前元素**。这也是"回调里用箭头函数"常见的原因——箭头函数的 this 是词法的，不受这些 API 影响。



### 箭头函数与 this

#### 箭头函数的使用

**箭头函数（Arrow Function）**：是 ES6 引入的**更简洁**的函数写法。

语法特点：

- (参数) => { 函数体 }。
- 单参数可省略括号，单表达式可省略 return 和花括号。

```js
// 传统函数
const add1 = function (a, b) {
  return a + b;
};

// 箭头函数
const add2 = (a, b) => a + b;

// 单参数、单表达式
const square = x => x * x;
console.log(square(3)); // 9
```

> 箭头函数的简洁只是表象，它真正**关键的区别在于 this**（见下一节）：箭头函数**没有自己的 this**，其 this 由外层作用域**词法**决定。这一特性既带来便利，也带来限制。



#### 箭头函数中的 this

箭头函数**没有自己的 this**，它的 this 是**定义时**外层作用域的 this（词法继承）。

```js
const obj = {
  name: "coderwhy",
  // 普通函数：this 是调用对象
  normalFn() {
    console.log(this.name);
  },
  // 箭头函数：this 继承外层（此处是全局）
  arrowFn: () => {
    console.log(this.name); // undefined（外层是全局）
  }
};

obj.normalFn(); // "coderwhy"
obj.arrowFn();  // undefined
```

> 箭头函数与普通函数在 this 上的核心区别：**普通函数的 this 是动态的（调用时决定），箭头函数的 this 是静态的（定义时确定）**。正因如此，箭头函数**不能作为构造函数**、不能用 call/apply/bind 改变其 this。

```js
// 箭头函数的典型用途：回调里保持外层 this
const timer = {
  name: "timer",
  start() {
    setTimeout(() => {
      console.log(this.name); // "timer"（继承 start 的 this）
    }, 1000);
  }
};
timer.start();
```



### this 面试题

#### 面试题一

```js
var name = "window";

const obj = {
  name: "obj",
  getName() {
    return this.name;
  }
};

console.log(obj.getName());           // "obj"
const fn = obj.getName;
console.log(fn());                    // "window"
```

> 第一问 obj.getName() 是**隐式绑定** → "obj"；第二问 fn() 是**独立调用**，退化为默认绑定 → 全局 "window"。考点是"**隐式绑定丢失**"。



#### 面试题二

```js
const obj = {
  name: "obj",
  getName() {
    return function () {
      return this.name;
    };
  }
};

console.log(obj.getName()()); // "window"（或 undefined）
```

> obj.getName() 返回一个**匿名函数**，再 () 调用时是**独立调用**，this 是默认绑定（全局）。考点是"**返回的函数丢失了 this**"——若想保持 this，需用箭头函数或 bind。



#### 面试题三

```js
const obj = {
  name: "obj",
  getName() {
    return () => {
      return this.name;
    };
  }
};

console.log(obj.getName()()); // "obj"
```

> 与上一题对照：这里返回的是**箭头函数**，它的 this 词法继承自 getName（其 this 是 obj），所以输出 "obj"。考点是"**箭头函数保持外层 this**"。



#### 面试题四

```js
function Foo() {
  this.name = "foo";
  setTimeout(function () {
    console.log(this.name);
  }, 1000);
}

new Foo(); // undefined（定时器回调的 this 是 window）

function Bar() {
  this.name = "bar";
  setTimeout(() => {
    console.log(this.name);
  }, 1000);
}

new Bar(); // "bar"（箭头函数继承构造函数的 this）
```

> 普通函数作定时器回调，this 是全局 → undefined；箭头函数继承构造函数的 this（新实例）→ "bar"。这是"**箭头函数解决 this 丢失**"最经典的实战案例。



### call、apply 与 bind

#### 手写 call 方法

通过**手写实现** call，深入理解其原理。

```js
Function.prototype.myCall = function (thisArg, ...args) {
  // 1. 处理 thisArg（null/undefined 时用全局）
  thisArg = thisArg ?? globalThis;
  // 2. 把函数临时挂到 thisArg 上，作为方法调用实现绑定
  const fn = Symbol("fn");
  thisArg[fn] = this;
  // 3. 以方法形式调用，此时 this 指向 thisArg
  const result = thisArg[fn](...args);
  // 4. 删除临时属性
  delete thisArg[fn];
  return result;
};

const person = { name: "why" };
function greet() {
  return this.name;
}
console.log(greet.myCall(person)); // "why"
```

> 手写 call 的核心思路：**把函数临时设为 thisArg 的方法**，再以"对象方法"形式调用，天然实现 this 绑定，最后清理临时属性。用 Symbol 作键名避免与对象已有属性冲突。



#### 手写 apply 方法

apply 与 call 几乎相同，仅参数是**数组**。

```js
Function.prototype.myApply = function (thisArg, args = []) {
  thisArg = thisArg ?? globalThis;
  const fn = Symbol("fn");
  thisArg[fn] = this;
  const result = thisArg[fn](...args); // 展开数组
  delete thisArg[fn];
  return result;
};

function sum(a, b, c) {
  return a + b + c;
}
console.log(sum.myApply(null, [1, 2, 3])); // 6
```

> apply 与 call 的唯一区别是**参数形式**：call 用剩余参数 ...args，apply 接收数组后 ...args 展开。手写时只要把"逐个传"换成"展开数组"即可。



#### 手写 bind 方法

bind 的实现更复杂，因为它**返回新函数**，且需处理 new 的情况。

```js
Function.prototype.myBind = function (thisArg, ...boundArgs) {
  const fn = this; // 保存原函数
  return function (...args) {
    // 若用 new 调用，this 是新实例，应绑定到 this；否则绑定 thisArg
    const finalThis = this instanceof arguments.callee ? this : thisArg;
    return fn.apply(finalThis, [...boundArgs, ...args]);
  };
};

function greet(greeting, name) {
  return `${greeting}, ${name}`;
}
const sayHello = greet.myBind(null, "Hello");
console.log(sayHello("why")); // "Hello, why"
```

> 手写 bind 的两个要点：一是**返回新函数**（合并绑定参数与调用参数）；二是**兼容 new**——当用 new 调用时，this 是新实例，应优先绑定到 this 而非 thisArg（因为 new 优先级更高）。



#### 手写实现的补充说明

手写 call/apply/bind 的若干细节与注意事项。

- **thisArg 兜底**：null/undefined 时回退到全局对象（globalThis）。
- **临时属性冲突**：用 Symbol 作键名避免污染对象。
- **参数合并**：bind 要合并"预置参数 + 调用时参数"。
- **new 优先级**：bind 返回的函数被 new 调用时，this 以 new 为准。

```js

// 这里展示的是核心思想，实际规范更严格
```

> 手写这些方法的价值**不在于替代原生**，而在于**深刻理解 this 绑定机制**。面试常考，更重要的是——理解了"临时挂方法"这个 trick，就真正理解了 this 的绑定本质。



### arguments

#### arguments 转成 array

**arguments** 是普通函数内**类数组对象**（见第 5 章），转成真数组后才能使用数组方法。

转数组的几种方式：

- **Array.from(arguments)**：最推荐。
- **[...arguments]**：展开语法。
- **Array.prototype.slice.call(arguments)**：旧式写法。

```js
function sum() {
  // 转为真数组后，就能用 reduce 等数组方法
  const args = Array.from(arguments);
  return args.reduce((acc, cur) => acc + cur, 0);
}

console.log(sum(1, 2, 3, 4)); // 10
```

> arguments 是类数组（有 length、索引，但无数组方法），转数组后才能 map、reduce 等。现代代码中，更推荐用**剩余参数 ...args** 直接得到真数组，arguments 主要存在于旧代码。



#### 箭头函数中没有 arguments

箭头函数**没有自己的 arguments**，访问 arguments 会**沿作用域链**找到外层函数的 arguments。

```js
function outer() {
  const arrow = () => {
    console.log(arguments); // 这是 outer 的 arguments，而非 arrow 的
  };
  arrow(1, 2, 3);
}

outer("a", "b"); // 输出 outer 的参数 "a"、"b"

const standaloneArrow = () => {
  // console.log(arguments); // 报错：没有外层 arguments 时不可访问
};
```

> 箭头函数没有 arguments、也没有 this、不能作构造函数，这是它与普通函数的三大区别。箭头函数里访问 arguments 会**误拿到外层的**，需要"不确定参数个数"时应改用**剩余参数** (...args)。
