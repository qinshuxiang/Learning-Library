## 正则表达式

### 正则表达式的定义与作用

#### 什么是正则表达式

**正则表达式（Regular Expression，简称 RegExp）**：是用于**匹配字符串中字符组合的模式**，本质是一套描述文本规则的**模式语言**——用紧凑的符号回答"要匹配什么样的文本"这个问题。

- **验证**：判断字符串是否符合某种格式（手机号、邮箱、密码强度）。
- **搜索**：在文本中查找匹配的内容。
- **替换**：批量替换文本中的特定模式。
- **提取**：从字符串中抽取所需的片段。

```js
const email = "user@example.com";
const emailReg = /^\w+@\w+\.\w+$/;
console.log(emailReg.test(email)); // true
```

> 正则的价值在于**用声明式的模式代替繁琐的字符串判断**：一个手机号校验，手写 if 可能几十行，用正则一行完成。它难在语法紧凑、不直观，但掌握之后处理文本的效率会成倍提升。

#### 正则既是语法也是对象

在 JavaScript 中，正则不只是语法，还是**对象**：RegExp 实例持有 source（模式文本）、flags（标志串）、lastIndex（下一次匹配的起始位置）等状态，可作为值传递、可作为字符串方法的参数。

```js
const digitReg = /\d+/g;

console.log(digitReg.source);    // "\d+"（模式文本）
console.log(digitReg.flags);     // "g"
console.log(digitReg.global);    // true（对应 g 标志的只读布尔属性）
console.log(digitReg.lastIndex); // 0（下一次从哪个位置开始匹配）
```

> 理解"正则是对象"是理解 lastIndex 陷阱的前提：**状态挂在对象上，复用同一个对象就会复用它的状态**。标志一旦确定就无法更改，g、i、m、s、u、y、d、v 只能通过重新创建正则来改变。

### 创建正则表达式对象

#### 字面量创建

**字面量创建**：用一对斜杠 /pattern/flags 直接书写模式，是最常用、最简洁的方式。

```js
const wordReg = /hello/i;
console.log(wordReg.test("Hello World")); // true

// 修饰符写在最后一个斜杠之后，可组合
const globalReg = /a/g;   // g：全局匹配
const multiReg = /^a/m;   // m：多行模式
const allFlags = /a/gimsy;
```

> 字面量在**脚本加载（解析）时编译**，模式固定不变，可读性与性能都最好。模式写成常量时，一律用字面量。

#### 构造函数创建

**构造函数创建**：new RegExp(pattern, flags) 的第一个参数是**字符串**，适用于模式需要**动态拼接**的场景。

```js
const reg = new RegExp("hello", "i");
console.log(reg.test("Hello World")); // true

// 动态生成模式：从变量拼接
const keyword = "abc";
const dynamicReg = new RegExp(keyword, "g");
console.log(dynamicReg.test("abcabc")); // true

// ES6 起允许传入正则并覆盖标志
const clonedReg = new RegExp(/abc/, "gi");
console.log(clonedReg.flags); // "gi"
```

> 构造函数在**运行时编译**，且 pattern 是字符串，因此正则里的反斜杠要写两遍：/\d+/ 对应的构造函数写法是 new RegExp("\\d+")。这是构造函数最容易出错的地方。

#### 两种创建方式的选择

- **模式固定**：用**字面量**，编译早、无双重转义、可读性高。
- **模式动态**：用**构造函数**，可以从变量、用户输入、配置项拼出模式。
- **性能**：字面量在循环中不会被反复重新编译；而**每次求值正则字面量都会创建一个新的 RegExp 对象**（ES5 起），所以字面量不会在多次调用间共享 lastIndex。

```js
// 字面量之间的状态互不干扰：每次求值都是新对象
console.log(/a/g.test("aa"), /a/g.test("aa")); // true true

// 复用同一个对象，lastIndex 才会累积
const reusedReg = /a/g;
console.log(reusedReg.test("aa"), reusedReg.lastIndex); // true 1
console.log(reusedReg.test("aa"), reusedReg.lastIndex); // true 2
console.log(reusedReg.test("aa"), reusedReg.lastIndex); // false 0
```

> [!IMPORTANT]
> **重要内容**：两条铁律：**模式不变用字面量，模式动态用构造函数**；**需要在多次调用之间保持状态（如逐段解析）时，必须把正则存进变量**，否则每次都是新对象、状态无从谈起。

### 修饰符

#### 修饰符总览

**修饰符（flags，也称标志）**：是写在正则末尾、改变匹配行为的一组单字母开关。每个标志在 RegExp 对象上都有一个对应的只读布尔属性。

- **d（hasIndices）**：为匹配结果附加起止索引 indices，ES2022 引入。
- **g（global）**：全局匹配，一次匹配成功后把 lastIndex 推到匹配末尾，可继续向后查找。
- **i（ignoreCase）**：忽略大小写；配合 u 时启用 Unicode 大小写折叠。
- **m（multiline）**：让 ^ 和 $ 匹配**每一行**的开头与结尾。
- **s（dotAll）**：让 . 也能匹配行终止符。
- **u（unicode）**：按 **Unicode 码点**而非 UTF-16 码元处理，启用 \p{...} 与 \u{...}。
- **v（unicodeSets）**：u 的升级版，支持字符类的集合运算，ES2024 引入。
- **y（sticky）**：粘性匹配，**只在 lastIndex 位置**尝试，不向后搜索。

```js
console.log(/a/g.test("aaa"));     // true
console.log(/a/i.test("A"));       // true
console.log(/^b/m.test("a\nb"));   // true（m 让 ^ 匹配每行开头）
console.log(/a.b/s.test("a\nb"));  // true（s 让 . 匹配换行）
console.log(/^.$/u.test("𝄞"));      // true（u 让 . 按码点匹配，𝄞 是非 BMP 字符）
```

> 修饰符可任意组合、顺序不限，如 /abc/gi。其中 u 与 v **互斥**，同时使用会抛 SyntaxError；v 可以视为"u 的超集"，开启 v 后 RegExp.prototype.unicode 与 unicodeSets 同时为 true。

#### g 修饰符与 lastIndex 陷阱

**lastIndex**：是 RegExp 实例上的一个可写整数，表示**下一次匹配从字符串的哪个位置开始**。只有带 g 或 y 标志的正则才会用到它。

```js
const digitReg = /\d/g;

console.log(digitReg.test("a1")); // true，匹配到索引 1，lastIndex 变为 2
console.log(digitReg.test("a1")); // false，从索引 2 起无匹配，lastIndex 归零
console.log(digitReg.test("a1")); // true，lastIndex 已归零，重新从头匹配
```

把同一个带 g 的正则用在**不同的字符串**上，问题更隐蔽：

```js
const wordReg = /\w+/g;

console.log(wordReg.test("hello")); // true，lastIndex 停在 5
console.log(wordReg.test("world")); // false！从索引 5 开始，新串根本没有索引 5
```

> [!WARNING]
> **警告内容**：lastIndex 陷阱的两条规避原则：**做"是否存在"的验证时不要加 g**；**复用带 g/y 的正则前，显式把 lastIndex 重置为 0**。带 g 的 exec 循环结束时若匹配失败，lastIndex 会自动归零，但成功后不会，这正是坑的来源。

#### y 修饰符与粘性匹配

**y 修饰符（sticky，粘性模式）**：要求匹配**必须正好从 lastIndex 位置开始**，不允许向后搜索。

```js
const reg = /a/y;

reg.lastIndex = 1;
console.log(reg.exec("ba")); // ["a"]（位置 1 正好是 a）

reg.lastIndex = 0;
console.log(reg.exec("ba")); // null（位置 0 是 b，粘性匹配不放宽）
console.log(reg.lastIndex);  // 0（失败后自动归零）
```

> y 与 g 的分水岭在于**能不能往后找**：g 是"从 lastIndex 起向后找到第一个匹配"，y 是"就在 lastIndex 这个位置，成则成、不成则败"。y 适合写**词法分析器（tokenizer）**：一段一段地切，切不动就说明位置错了。

#### m 修饰符与多行锚点

**m 修饰符**：改变 ^ 与 $ 的含义，使其匹配**每一行的行首行尾**，而非只匹配整个字符串的开头结尾。

```js
const lines = "第一行\n第二行\n第三行";

console.log(lines.match(/^第/g));   // ["第"]（无 m，只匹配开头一次）
console.log(lines.match(/^第/gm));  // ["第", "第", "第"]（有 m，每行开头都算）

console.log(/行$/m.test(lines));    // true（最后一行以"行"结尾）
```

> ^ 与 $ 只匹配**位置**、不消耗字符，属于**锚点**。m 影响的只有这两个锚点，不影响 .，也不影响 \b。

#### s 修饰符与 dotAll

**s 修饰符（dotAll）**：让 . 也能匹配**行终止符**。

```js
console.log(/a.b/.test("a\nb"));  // false（. 默认不匹配换行）
console.log(/a.b/s.test("a\nb")); // true（s 模式下 . 匹配换行）

// 旧写法：用"任意空白 + 任意非空白"绕开限制
console.log(/a[\s\S]b/.test("a\nb")); // true
```

> 默认情况下 . 匹配除 \n、\r、\u2028、\u2029 之外的任意字符。开启 s 后 . 能匹配一切，/^[\s\S]*$/ 这类绕路写法就可以退休了。

#### u 修饰符与 Unicode 码点

**u 修饰符**：让正则按 **Unicode 码点**而非 UTF-16 码元工作，并启用 Unicode 属性转义 \p{...} 与码点转义 \u{...}。

```js
// 𝄞（U+1D11E，音乐符号）超出 BMP，由两个代理项码元组成
console.log("𝄞".length);      // 2
console.log(/^.$/.test("𝄞"));  // false（无 u：. 只匹配一个码元）
console.log(/^.$/u.test("𝄞")); // true（有 u：. 匹配一个完整码点）

console.log(/^\u{1D11E}$/u.test("𝄞")); // true（码点转义，必须配合 u）

// Unicode 属性转义 \p{...}
console.log(/\p{Script=Han}/u.test("中"));              // true（汉字）
console.log(/\p{Script_Extensions=Han}/u.test("中"));   // true（scx 别名写法）
console.log(/\p{Script=Greek}/u.test("α"));             // true（希腊字母）
```

> u 模式下，正则的"字符"概念从**码元**升级为**码点**：量词、字符类、. 全部按码点计数，emoji、生僻汉字不再被拦腰截断。凡是要处理中文、emoji、多语言文本，都应默认加上 u。

#### d 修饰符与匹配索引

**d 修饰符（hasIndices）**：给匹配结果附加 indices 属性，记录每个匹配（含捕获组）在原串中的**起止位置**。

```js
const dateReg = /(?<year>\d{4})-(\d{2})/d;
const match = dateReg.exec("今天是 2024-01-15");

console.log(match.index);          // 4
console.log(match.indices);        // [[4, 11], [4, 8], [9, 11]]
console.log(match.indices.groups.year); // [4, 8]（命名分组也有索引）
```

> indices 是一个二维数组，第 0 项是整个匹配的 [start, end]，其后依次是各捕获组；命名分组额外挂在 indices.groups 上。做**关键词高亮、代码定位、编辑器插件**这类"必须知道匹配落在哪"的场景时，d 是唯一省事的方案。注意 end 是**开区间**（不含该下标）。

#### v 修饰符与集合表示法

**v 修饰符（unicodeSets）**：是 u 的增强版，在字符类中引入**集合运算**与**多字符字符串**匹配，ES2024 引入。

```js
// 差集 --：所有字母，排除 a、e
console.log(/[\p{Letter}--[ae]]/v.test("b")); // true
console.log(/[\p{Letter}--[ae]]/v.test("a")); // false

// 交集 &&：既是希腊字母又是字母
console.log(/[\p{Script=Greek}&&\p{Letter}]/v.test("α")); // true

// 并集：直接并列书写
console.log(/[\p{Script=Han}\p{Script=Latn}]/v.test("中")); // true

// \q{} 匹配多字符字符串（字符类里可以放"串"而不只是"字符"）
console.log(/[\q{元|美元}]/v.test("100元")); // true
```

> v 让字符类从"字符的集合"升级为"字符串的集合"，语法上支持 --（差集）、&&（交集）与并列（并集）。代价是**字符类里的 -、(、)、[、]、{、}、/、| 等必须转义**，原本在 u 模式下能用的部分写法会直接报 SyntaxError。这是较新的特性，写业务代码前先确认目标运行环境与构建工具的转译能力。

### 正则的基本语法

#### 字符类

**字符类（Character Class）**：用于匹配"某一类字符"而非"某个具体字符"，是正则最基础的构件。

- **.**：任意单个字符（默认不含行终止符）。
- **\d**：数字 [0-9]；**\D**：非数字。
- **\w**：单词字符 [A-Za-z0-9_]；**\W**：非单词字符。
- **\s**：空白字符（空格、制表符、换行等）；**\S**：非空白字符。
- **[abc]**：方括号内任选其一；**[a-z]**：范围；**[^abc]**：取反。

```js
console.log(/\d/.test("abc123"));     // true
console.log(/\d{3}/.test("abc123"));  // true（连续 3 个数字）
console.log(/[aeiou]/.test("hello")); // true
console.log(/[^0-9]/.test("123"));    // false（全数字，无非数字字符）
console.log(/[\u4e00-\u9fa5]/.test("中")); // true（常用汉字区间）
```

> [!NOTE]
> **提醒内容**：大写形式（\D、\W、\S）一律是**小写形式的取反**。注意 \w **只认 ASCII**：它匹配不了中文，判断汉字请用 [\u4e00-\u9fa5] 或 /\p{Script=Han}/u。

#### 转义规则

**转义**：用反斜杠 \ 把一个元字符变成普通字符，或把一个普通字符变成有特殊含义的序列。

- **必须转义的元字符**：. * + ? ^ $ { } ( ) | [ ] \。
- **/** 只在**字面量**中需要转义（它界定正则边界），构造函数中不必。
- **字符类 [] 内部**：多数元字符失去特殊含义，但 ]、\、^（放首位时）、-（放中间表示范围）仍需处理。

```js
console.log(/\$100/.test("价格 $100")); // true（$ 是锚点，需转义成普通字符）
console.log(/[.$*]/.test("a.b"));       // true（字符类内部多数元字符无需转义）
console.log(/[a\-z]/.test("-"));        // true（- 在中间要转义，放首尾则不必）
console.log(/\//.test("a/b"));          // true（字面量中的 / 必须转义）
console.log(new RegExp("/").test("a/b")); // true（构造函数中不必）
```

> [!WARNING]
> **警告内容**：两条容易踩的坑：一是**不要在 {n,m} 的数字之间加空格**，/a{1, 3}/ 在非 u 模式下会被当成字面文本 "a{1, 3}"；二是**不要依赖"多余的反斜杠"**，非 u 模式下 /\a/ 等价于 /a/，但 u 模式下这是语法错误——u/v 模式会严格校验转义序列。

#### 量词

**量词（Quantifier）**：紧跟在某个**原子**（单个字符、字符类、分组）之后，指定它重复的次数。

- *****：0 次或多次。
- **+**：1 次或多次。
- **?**：0 次或 1 次。
- **{n}**：恰好 n 次。
- **{n,}**：至少 n 次。
- **{n,m}**：n 到 m 次。

```js
console.log(/a*/.test("bbb"));        // true（0 次也算匹配）
console.log(/a+/.test("bbb"));        // false（至少 1 次）
console.log(/colou?r/.test("color")); // true（u 可有可无）
console.log(/\d{2,4}/.test("123"));   // true（2 到 4 个数字）
```

> **量词只作用于紧邻它的那一个原子**，想让一整段重复就必须加分组：/(ab)+/ 是 ab 重复，/ab+/ 是 b 重复。另外**量词不能修饰断言**，/^*/ 会直接抛 SyntaxError。

#### 贪婪与惰性

**贪婪（greedy）**：量词默认行为，在能让整体匹配成功的前提下**尽可能多地吃字符**；**惰性（lazy）**：在量词后加 ?，改为**尽可能少地吃字符**。

```js
const html = "<p>标题</p><p>正文</p>";

console.log(html.match(/<p>.*<\/p>/)[0]);
// "<p>标题</p><p>正文</p>"（贪婪：一路吃到最后一个 </p>）

console.log(html.match(/<p>.*?<\/p>/)[0]);
// "<p>标题</p>"（惰性：遇到第一个 </p> 就收手）

console.log(html.match(/<p>[^<]*<\/p>/)[0]);
// "<p>标题</p>"（排除型字符类：既精准又无需回溯，推荐）
```

> 惰性不是"匹配更短"，而是"**先少拿、拿不动了再多加**"。/a*?/.exec("aaa") 得到的是空串而不是 "aaa"——因为它允许 0 次重复。真正的取舍口诀是：**能用排除型字符类 [^x]* 解决，就别用 .*?**，前者几乎不产生回溯。

#### 锚点与单词边界

**锚点（Anchor）**：匹配的是**位置**而不是字符，不消耗任何字符。

- **^**：字符串开头；配合 m 时为行首。
- **$**：字符串结尾；配合 m 时为行尾。
- **\b**：单词边界，即 \w 与非 \w 之间的位置。
- **\B**：非单词边界。

```js
console.log(/^abc/.test("abcdef"));   // true
console.log(/abc$/.test("xyzabc"));   // true
console.log(/\bcat\b/.test("a cat"));      // true（cat 是独立单词）
console.log(/\bcat\b/.test("category"));   // false（cat 嵌在单词里）
```

> [!WARNING]
> **警告内容**：三个高频误区：一是 ^...$ 才是**全串匹配**，只写一半会让 "13800138000abc" 通过 /\d{11}/.test()；二是 JavaScript 的 $ **不允许末尾换行前匹配**，/a$/.test("a\n") 是 false；三是 \b 依赖 \w，而 \w 只认 ASCII，/\b中文\b/.test("学中文") 是 false——中文没有单词边界可用。

### 分组与引用

#### 捕获组

**捕获组（Capturing Group）**：用圆括号 (...) 包裹的子模式。它有两个作用：**组合**（把多个字符当成一个整体加量词）与**捕获**（把匹配到的子串记下来供后续引用）。

```js
const dateReg = /(\d{4})-(\d{2})-(\d{2})/;
const result = dateReg.exec("今天是 2024-01-15");

console.log(result[0]);      // "2024-01-15"（第 0 项永远是完整匹配）
console.log(result[1]);      // "2024"
console.log(result[2]);      // "01"
console.log(result[3]);      // "15"
console.log(result.index);   // 4（完整匹配的起始下标）
console.log(result.input);   // "今天是 2024-01-15"（原串）
```

> 组的编号按**左括号出现的顺序**从 1 开始。带量词的捕获组只保留**最后一次**重复的结果：/(ab)+/.exec("ababab")[1] 是 "ab" 而不是 "ababab"。未参与匹配的组其值为 undefined。

#### 非捕获组

**非捕获组 (?:...)**：只起组合作用，不占用编号、不记录结果。

```js
const reg = /(?:ab)+/;
console.log(reg.test("ababab")); // true（ab 作为整体重复）
console.log(reg.exec("ababab")); // ["ababab", index: 0, ...]（没有 [1]，因为不捕获）

// 对比：捕获组会多出一项
console.log(/(ab)+/.exec("ababab")); // ["ababab", "ab", index: 0, ...]
```

> 凡是不需要把这段内容取出来的括号，一律写成 (?:...)：**语义更清晰**（明确表达"不关心这段"）、**避免编号错位**（后续 $1、$2 不会因插入一个分组而集体后移），也能省下记录结果的开销。

#### 命名捕获组

**命名捕获组 (?<name>...)**：给捕获组起名字，通过 match.groups.name 访问，ES2018 引入。

```js
const dateReg = /(?<year>\d{4})-(?<month>\d{2})-(?<day>\d{2})/;
const match = dateReg.exec("2024-01-15");

console.log(match.groups.year);  // "2024"
console.log(match.groups.month); // "01"
console.log(match.groups.day);   // "15"
console.log(match[1]);           // "2024"（数字索引依然可用）
```

> 命名分组解决了"记不清第几个括号是什么"的痛点，groups.year 比 match[1] 自解释得多。它在 replace 中通过 $<name> 引用，在正则内部通过 \k<name> 反向引用。

#### 反向引用

**反向引用**：在同一个正则里引用**前面已经匹配到的内容**，要求"后面出现的和前面完全一样"。

- **\n**：引用第 n 个捕获组（\1、\2……）。
- **\k<name>**：引用命名捕获组。
- **$n / $<name>**：用在 replace 的替换字符串中，含义相同但**书写位置不同**。

```js
// 匹配成对的标签
console.log(/<(\w+)>.*<\/\1>/.test("<div>文本</div>")); // true
console.log(/<(\w+)>.*<\/\1>/.test("<div>文本</p>"));   // false

// 找出叠字
console.log("高高兴兴".match(/(.)\1/g)); // ["高高", "兴兴"]

// 命名分组的反向引用
const quoteReg = /(?<quote>["']).*?\k<quote>/;
console.log(quoteReg.test(`"你好"`)); // true
console.log(quoteReg.test(`"你好'`)); // false
```

> 正则内（\1、\k<name>）与替换串（$1、$<name>）是**两套写法**，作用位置不同：前者出现在**模式**里表示"要和前面一样"，后者出现在**替换结果**里表示"把前面抓到的放这儿"。混用是最常见的语法错误之一。

#### 或运算与分组

**或 |**：表示"匹配左边或右边"，它的优先级**低于**量词与拼接，通常需要分组来限定范围。

```js
console.log(/cat|dog/.test("dog"));   // true
console.log(/gr(a|e)y/.test("grey")); // true（分组限定"或"的范围）

// 陷阱：没有分组时，"或"贯穿整个模式
console.log(/^ab|cd$/.test("abxx")); // true（等价于 /(^ab)|(cd$)/）
console.log(/^(ab|cd)$/.test("abxx")); // false（加了分组才受 ^ $ 约束）
```

> [!IMPORTANT]
> **重要内容**：| 的优先级是正则里**最低**的，/^ab|cd$/ 会被解析成 /(^ab)|(cd$)/ 而不是 /(^(ab|cd)$)/。凡是用"或"列举多种完整形态，务必用 (?:...) 把它们包起来再用锚点收口。

### 断言

#### 先行断言

**先行断言 x(?=y)**：要求 x 的**后面**必须紧跟着 y，但 y 不进入匹配结果。

```js
console.log(/\d+(?=元)/.exec("价格 100元")[0]); // "100"（"元"未被消费）

// 密码强度校验：至少包含一个数字
console.log(/(?=.*\d)/.test("abc1")); // true
console.log(/(?=.*\d)/.test("abcd")); // false
```

> /(?=.*\d)/ 这种写法叫"**条件叠加**"：把若干个先行断言并列，等价于对同一个位置施加多个"与"条件。密码强度规则（同时含数字、含小写、含大写、长度 ≥ 8）就是靠它一行写完的，例如 /^(?=.*\d)(?=.*[a-z])(?=.*[A-Z]).{8,}$/。

#### 先行否定断言

**先行否定断言 x(?!y)**：要求 x 的**后面**不能是 y。

```js
console.log(/\d+(?!元)/.exec("数量 100件")[0]); // "100"

// 匹配不是 .js 结尾的文件名
console.log(/^\w+\.(?!js$)\w+$/.test("main.ts")); // true
console.log(/^\w+\.(?!js$)\w+$/.test("main.js")); // false
```

> 否定断言的括号里同样"只检查、不消费"，所以 /(?!js$)/ 检查的是"从当前位置起不是 js 且紧接着结尾"，它不会把 ts 吃掉。

#### 后行断言

**后行断言 (?<=y)x**：要求 x 的**前面**必须是 y，ES2018 引入。

```js
console.log(/(?<=￥)\d+/.exec("￥99")[0]);    // "99"
console.log(/(?<=单价：)\d+/.exec("单价：88")[0]); // "88"
```

> 后行断言与先行断言完全对称：先行 x(?=y) 看**后面**，后行 (?<=y)x 看**前面**。它常用于"提取带特定前缀的内容"，替代过去必须先捕获前缀再取 [1] 的写法。

#### 后行否定断言

**后行否定断言 (?<!y)x**：要求 x 的**前面**不能是 y。

```js
console.log(/(?<!￥)\d+/.exec("$88")[0]); // "88"

// 不匹配 "foo" 内部的数字
console.log(/(?<!foo)\d+/.exec("bar 123")[0]); // "123"
```

> 需要注意：后行断言在部分旧引擎（如老版本 Safari）中不被支持，且**后行断言内的匹配是从右往左进行的**，过复杂的模式可能影响可读性。生产环境使用前请核对兼容性基线。

#### 断言的共性

- **零宽（zero-width）**：断言只检查条件，**不消耗字符**，匹配结果里不会出现断言的内容。
- **不可量化**：(?=a)* 这类写法在 u/v 模式下是语法错误。
- **可组合**：多个断言可以并列，形成"与"逻辑；^、$、\b 本质上也是断言。

```js
// 断言不消耗字符的证据：两个断言叠在同一位置
const password = "Abc12345";
const pwdReg = /^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)[A-Za-z\d]{8,}$/;
console.log(pwdReg.test(password)); // true
```

> 口诀：**"先行看后、后行看前；只查不拿、成对出现"**。四条断言的记忆方式是——括号里带 < 的看**前面**（< 像箭头指回左边），不带 < 的看**后面**；带 ! 的是**否定**，不带的是**肯定**。

### 正则相关的方法

#### test() 方法

**regExp.test(string)**：测试字符串**是否包含**匹配项，返回布尔值，是验证场景的首选。

```js
const reg = /hello/i;
console.log(reg.test("Hello World")); // true
console.log(reg.test("world"));       // false
```

> test 的语义是"**包含**"而非"等于"：/\d{11}/.test("a13800138000b") 也是 true。做格式校验必须加 ^ 与 $ 收口。此外，带 g/y 的正则会因 lastIndex 累积导致连续调用结果交替，见"g 修饰符与 lastIndex 陷阱"。

#### exec() 方法

**regExp.exec(string)**：执行一次匹配，成功返回**结果数组**（含 index、input、groups，带 d 时还有 indices），失败返回 null。带 g/y 时会推进 lastIndex，可循环取出全部匹配。

```js
const wordReg = /(\w+)@(\w+)/g;
let match = null;

while ((match = wordReg.exec("a@x 和 b@y")) !== null) {
  console.log(match[0], match[1], match[2], match.index);
}
// "a@x" "a" "x" 0
// "b@y" "b" "y" 6
```

> [!WARNING]
> **警告内容**：exec 是唯一能**逐个取出"所有匹配 + 分组详情 + 下标"**的传统手段，代价是要手动维护 lastIndex 并警惕**零长匹配导致死循环**：/(a*)/g 这类能匹配空串的正则必须在使用后手动推进 lastIndex，否则 while 永不结束。日常更推荐 matchAll。

#### match() 方法

**str.match(regexp)**：返回匹配结果，其行为**随 g 标志而分裂**。

- **不带 g**：等价于一次 exec，返回第一个匹配的数组（含 index、input、groups），无匹配返回 null。
- **带 g**：返回由**所有完整匹配字符串**组成的数组，**不含**分组、index、groups；无匹配返回 null。

```js
const str = "2024-01-15";

console.log(str.match(/\d+/));   // ["2024"]（仅第一个）
console.log(str.match(/\d+/g));  // ["2024", "01", "15"]（全部完整匹配）

const first = str.match(/(\d{4})-(\d{2})/);
console.log(first[1], first[2], first.index); // "2024" "01" 0
```

> match 带 g 时只给"完整串"，分组信息**全部丢失**——这是它最大的局限，也是 matchAll 存在的原因。另外 match 会在开始前把 lastIndex 归零，所以它不像 test/exec 那样受上一次调用的影响。注意：**无匹配时返回 null 而不是空数组**，直接 .length 会抛错。

#### matchAll() 方法

**str.matchAll(regexp)**：返回一个**迭代器**，逐项产出**所有匹配及其分组详情**，ES2020 引入。

```js
const str = "2024-01 2025-02";
const dateReg = /(\d{4})-(\d{2})/g;

for (const match of str.matchAll(dateReg)) {
  console.log(match[0], match[1], match[2], match.index);
}
// "2024-01" "2024" "01" 0
// "2025-02" "2025" "02" 8

// 需要数组时展开即可
const allMatches = [...str.matchAll(dateReg)];
console.log(allMatches.length); // 2
```

> [!IMPORTANT]
> **重要内容**：三条硬性规则：**正则必须带 g**，否则抛 TypeError；**返回的是迭代器而非数组**，要 for-of 遍历或用 [...] 展开；**内部会克隆一份正则**，因此不会污染原对象的 lastIndex。这是"全量匹配 + 分组详情"场景下的最优解。

#### search() 方法

**str.search(regexp)**：返回**第一个匹配的下标**，找不到返回 -1。

```js
const str = "Hello World";
console.log(str.search(/World/)); // 6
console.log(str.search(/xyz/));   // -1

// 即使正则带 g，也只找第一个
console.log(str.search(/o/g)); // 4
```

> search 与 indexOf 的区别是**接受正则**；与 match 的区别是**只返回下标、不要内容**。它会先把 lastIndex 设为 0 并在结束后还原，因此 g 标志对它**没有实际作用**——它永远从头找、永远只报第一个。

#### replace() 方法

**str.replace(searchValue, replaceValue)**：把匹配到的内容替换掉，返回**新字符串**，原串不变。searchValue 可以是字符串或正则，replaceValue 可以是字符串或函数。

替换字符串中的特殊记号：

- **$$**：字面量 $。
- **$&**：整个匹配。
- **$ 加反引号记号**：匹配**之前**的文本。
- **$'**：匹配**之后**的文本。
- **$n**：第 n 个捕获组。
- **$<name>**：命名捕获组。

```js
const str = "2024-01-15";

console.log(str.replace(/-/g, "/")); // "2024/01/15"（配合 g 才替换全部）
console.log(str.replace(/-/, "/"));  // "2024/01-15"（不带 g 只换第一个）

// 交换分组顺序
console.log(str.replace(/(\d{4})-(\d{2})/, "$2/$1")); // "01/2024-15"

// 命名分组与 $<name>
const dateReg = /(?<year>\d{4})-(?<month>\d{2})/;
console.log(str.replace(dateReg, "$<month>/$<year>")); // "01/2024-15"

// $& 引用整个匹配：给数字加方括号
console.log(str.replace(/\d+/g, "[$&]")); // "[2024]-[01]-[15]"

// 函数形式：动态生成替换内容
console.log(str.replace(/\d+/g, (matched) => String(Number(matched) * 2)));
// "4048-2-30"（"01" 转数字后是 1，乘 2 得 2）
```

> 函数形式的参数依次是 (match, p1, p2, ..., offset, string, groups)，返回值即替换文本。它是 replace 最灵活的地方：大小写转换、查表映射、按需格式化都能一步完成。**replace 不修改原串**，必须接收返回值。

#### replaceAll() 方法

**str.replaceAll(searchValue, replaceValue)**：替换**全部**匹配，返回新字符串，ES2021 引入。

```js
console.log("a-b-c".replaceAll("-", "/"));        // "a/b/c"（字符串直接全替换）
console.log("a-b-c".replaceAll(/-/g, "/"));      // "a/b/c"（正则必须带 g）
console.log("a-b-c".replaceAll(/-/, "/"));       // TypeError：正则缺 g 标志
console.log("2024-01".replace(/(\d+)/g, "$1年")); // "2024年-01年"
```

> replaceAll 对**字符串**参数等价于 split().join()，对**正则**参数则强制要求 g 标志——这是刻意的保护：既然方法名写了 All，就不该因为漏写 g 而静默只换一个。它比 replace(/x/g, ...) 的意图更明确，也更不容易漏掉 g。

#### split() 方法

**str.split(separator, limit)**：按分隔符把字符串拆成数组，separator 可以是字符串或正则，limit 限制返回的最大片段数。

```js
console.log("apple,banana;orange".split(/[,;]/)); // ["apple", "banana", "orange"]
console.log("a  b\tc".split(/\s+/));              // ["a", "b", "c"]
console.log("a,b;c".split(/[,;]/, 2));            // ["a", "b"]

// 带捕获组时，分隔符本身也会进入结果
console.log("a1b2c3".split(/(\d)/)); // ["a", "1", "b", "2", "c", "3", ""]
```

> 传字符串分隔符时 split 会先把它转成正则，所以 "a.b".split(".") 中的 . 会被当作正则元字符（虽然匹配结果通常一样）。**正则含捕获组是关键差异点**：捕获到的分隔符会一并塞进结果数组，利用这一点可以在拆分的同时保留分隔符。

#### 方法对照与选用

- **"有没有"**：test() 返回布尔；search() 返回下标或 -1。
- **"第一个匹配 + 详情"**：exec() 与不带 g 的 match()，二者等价。
- **"全部匹配、只要完整串"**：带 g 的 match()。
- **"全部匹配 + 分组 + 下标"**：matchAll()（必须带 g）。
- **"替换"**：replace()（带 g 则全部）或 replaceAll()（正则必须带 g）。
- **"拆分"**：split()。

```js
const text = "联系方式：138-0013-8000，备用：139-0013-9000";
const phoneReg = /(\d{3})-(\d{4})-(\d{4})/g;

// 只要号码：用 match
console.log(text.match(/\d{3}-\d{4}-\d{4}/g));
// ["138-0013-8000", "139-0013-9000"]

// 要分组：用 matchAll
for (const m of text.matchAll(phoneReg)) {
  console.log(`${m[1]}****${m[3]}`); // "138****8000"、"139****9000"
}
```

> 选中方法的判断顺序是：**先看要不要"全部"，再看要不要"分组"**。只要完整串用 match，要分组用 matchAll，只要真假用 test，只要位置用 search——exec 循环是前两者都不方便时的兜底。

### 正则的性能与安全

#### 回溯与灾难性回溯

**回溯（backtracking）**：正则引擎在某条匹配路径走不通时，**退回上一个可选分支**再试。它是惰性与贪婪、量词与分组能协同工作的基础，但也可能被滥用。

**灾难性回溯（Catastrophic Backtracking，也称 ReDoS）**：当模式里出现**嵌套量词**（如 (a+)+、(a*)*）且最终匹配失败时，引擎要枚举的组合数随输入长度**指数级增长**，导致脚本卡死。

```js
const riskyReg = /(a+)+$/; // 嵌套量词，危险

// 下面这行会让主线程长时间卡住：26 个 a 的每一种拆分都要试一遍
console.log(riskyReg.test(`${"a".repeat(26)}!`));
```

> ReDoS 的触发需要两个条件同时成立：**存在多种拆分方式的嵌套量词**，且**最终匹配失败**（失败才会穷举所有可能）。用于校验用户输入（尤其是用户名、URL、邮箱这类公开表单字段）的正则，必须专门排查这一点。

#### 常见优化建议

- **用排除型字符类替代 .***：/<p>[^<]*<\/p>/ 比 /<p>.*?<\/p>/ 快且不会回溯失控。
- **避免嵌套量词**：/(a+)+/、/(\s*\w+)*/ 这类写法要拆开重写。
- **锚点尽早失败**：把 ^、字面前缀放在最前面，让不匹配的字符串迅速被排除。
- **限制输入长度**：在校验前先用 str.length 卡一道，是最廉价的防护。
- **非捕获组优先**：不需要结果时用 (?:...)。
- **复杂文本用专用解析器**：HTML、URL、Markdown 都不该用正则硬啃，浏览器有 DOMParser 与 URL 可用。

```js
// 校验 URL：先用内置 API，别硬写正则
function isValidUrl(value) {
  try {
    new URL(value);
    return true;
  } catch {
    return false;
  }
}

console.log(isValidUrl("https://example.com/a?b=1")); // true
console.log(isValidUrl("不是网址"));                    // false
```

> 一句话准则：**正则适合"匹配模式"，不适合"解析结构"**。嵌套结构（HTML 标签、JSON、代码）在理论上就无法用正则正确解析，任何"看起来能用"的正则都只是特定输入的近似解。

### 常见正则举例

#### 手机号

国内手机号规则的**实用近似**是：1 开头、第二位 3~9、共 11 位数字。

```js
const phoneReg = /^1[3-9]\d{9}$/;

console.log(phoneReg.test("13812345678")); // true
console.log(phoneReg.test("12812345678")); // false（第二位 2 不合法）
console.log(phoneReg.test("1381234567"));  // false（不足 11 位）
```

> 拆解：^ 开头、1 固定首位、[3-9] 第二位、\d{9} 剩余 9 位、$ 结尾。注意**号段会随运营商放号而变化**，这个正则只保证"格式像手机号"，不保证号码真实存在；严格的号段校验需要维护一张号段表，而真实有效性只能靠短信验证码。

#### 邮箱

```js
const emailReg = /^[\w.+-]+@[\w-]+(\.[\w-]+)+$/;

console.log(emailReg.test("user@example.com"));    // true
console.log(emailReg.test("a.b-c@sub.domain.cn")); // true
console.log(emailReg.test("user@example"));        // false（缺顶级域）
console.log(emailReg.test("@example.com"));        // false（缺用户名）
```

> 拆解：[\w.+-]+ 用户名、@ 分隔、[\w-]+ 域名主体、(\.[\w-]+)+ 至少一个点分段。需要强调的是：**完整的 RFC 5322 邮箱规则极其复杂**（支持引号、注释、IP 字面量等），上面只是实用简化版；生产环境应以**发送验证邮件**作为最终有效性依据。

#### 身份证号

18 位居民身份证：前 6 位行政区划码、8 位出生日期、3 位顺序码、1 位校验位（数字或 X）。

```js
const idCardReg =
  /^[1-9]\d{5}(?:19|20)\d{2}(?:0[1-9]|1[0-2])(?:0[1-9]|[12]\d|3[01])\d{3}[\dXx]$/;

console.log(idCardReg.test("110101199003072316")); // true（示例号码）
console.log(idCardReg.test("010101199003072316")); // false（首位不能为 0）
console.log(idCardReg.test("110101199013072316")); // false（月份 13 非法）
```

> 这个正则只做**格式与日期合法性**校验，不校验行政区划码是否存在，也不校验最后一位的**校验码算法**（ISO 7064 MOD 11-2）。要做严格校验，应当在通过正则后再跑一遍加权求和；而"这个人是否存在"只能依赖公安系统的实名接口。

#### URL

```js
const urlReg = /^https?:\/\/[\w.-]+(?::\d+)?(?:\/[\w\-./?%&=#]*)?$/;

console.log(urlReg.test("https://example.com"));         // true
console.log(urlReg.test("http://example.com:8080/a/b")); // true
console.log(urlReg.test("ftp://example.com"));           // false（仅 http/https）
console.log(urlReg.test("example.com"));                 // false（缺协议）
```

> 正则校验 URL 的**局限很明显**：它处理不了 IPv6 主机、用户名字段、复杂查询串，也判断不了域名是否合法。浏览器内置的 new URL(value) 才是正确做法（见"常见优化建议"里的 isValidUrl），正则只适合做"必须以 http(s) 开头"这类粗筛。

#### 去掉首尾空格

```js
const str = "  hello world  ";

// 正则实现
console.log(str.replace(/^\s+|\s+$/g, "")); // "hello world"

// 原生方法（推荐）
console.log(str.trim());     // "hello world"
console.log(str.trimStart()); // "hello world  "
console.log(str.trimEnd());   // "  hello world"
```

> 生产代码一律用 trim() 系列，正则写法只作理解用：^\s+ 匹配开头空白、\s+$ 匹配结尾空白、| 表示"或"、g 保证两端都处理。这种"开头或结尾"的模式在数据清洗（如去掉首尾逗号、首尾引号）时很常见。

#### 千分位分隔

```js
function groupByThousands(value) {
  return String(value).replace(/\B(?=(\d{3})+(?!\d))/g, ",");
}

console.log(groupByThousands(1234567));  // "1,234,567"
console.log(groupByThousands(123));      // "123"
console.log(groupByThousands(1234.56));  // "1,234.56"（小数部分不参与）
```

> 这段模式拆解：\B 定位在**非单词边界**，(?=(\d{3})+(?!\d)) 断言"后面的数字个数正好是 3 的倍数"。它之所以正确，是因为**从右往左**每三位插入一个逗号，正是"后面剩余位数是 3 的倍数"的那些位置。现代代码也可以直接用 Number.prototype.toLocaleString() 或 Intl.NumberFormat。

#### 转义用户输入

把用户输入的字符串拼进正则时，其中的 .、*、(、[ 等元字符必须转义，否则轻则匹配异常，重则触发 ReDoS。

```js
// 传统手写转义
function escapeRegExp(text) {
  return text.replace(/[.*+?^${}()|[\]\\]/g, "\\$&");
}

const keyword = "a.b";
const safeReg = new RegExp(escapeRegExp(keyword), "g");
console.log(safeReg.test("xxa.bxx")); // true
console.log(safeReg.test("xxaxbxx")); // false（点已被当作普通字符）
```

> 现代标准提供了 **RegExp.escape(text)**，直接返回转义后的字符串（ES2025 特性，各浏览器正在铺开）。在它可用之前，上面的 escapeRegExp 是社区通行的等价实现；无论用哪种，**"用户输入进正则前必须转义"是安全红线**。

### 正则的调试与工具

#### 调试与验证

- **regex101.com**：在线解释器，能逐 token 解释模式、展示匹配步骤与回溯次数，是最常用的学习工具。
- **RegExp.prototype.toString()**：输出 /pattern/flags 形式的字符串，可用于打印检查。
- **console 实测**：不确定返回值时，直接在控制台跑一遍比记忆规则更可靠。

```js
const reg = /\d{3}/g;
console.log(reg.toString()); // "/\d{3}/g"
console.log(`${reg.source} | ${reg.flags}`); // "\d{3} | g"
```

> 调试正则的心法是**"缩小、二分、实测"**：把长正则拆成几段逐段验证，用具体字符串试探边界，再拼回去。正则出错往往不是"整条都错"，而是某一段多吃了或少吃了字符。
