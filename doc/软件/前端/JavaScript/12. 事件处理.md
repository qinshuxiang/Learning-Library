## 事件处理

### 事件的认识

#### 事件与事件处理程序

**事件（Event）**：是**用户或浏览器在页面上发生的动作**（点击、输入、滚动、资源加载完成等）的载体，由浏览器按 DOM 规范创建并派发。**事件处理程序（Event Handler）**：是**为响应某个事件而注册的函数**，也叫监听器（listener）。

- **事件类型**：一个**区分大小写**的字符串，如 click、keydown、DOMContentLoaded。
- **事件目标**：事件发生的对象，event.target 指向**最深层的那个元素**。
- **注册与回调分离**：代码先"注册"处理器，事件发生时浏览器才"回调"它。

```js
const button = document.querySelector("button");

// 注册：此刻函数并不执行
button.addEventListener("click", function handleClick(event) {
  // 回调：点击发生时由浏览器调用，并传入事件对象
  console.log("按钮被点击", event.type);
});
```

> [!WARNING]
> **警告内容**：事件机制是 JavaScript **异步模型**的体现：注册在前、执行在后，中间隔着不确定的时间。理解"注册与回调分离"，是理解定时器、Promise、网络请求等一切异步概念的共同起点。注意 addEventListener 的第二个参数必须是**函数引用或带 handleEvent() 方法的对象**，写成 handleClick()（带括号）等于先调用函数、再把返回值注册进去，是初学者最常见的错误。



#### EventTarget 接口

**EventTarget**：是所有能接收事件的对象的**基类接口**，window、document、元素、XMLHttpRequest、AbortController 都实现了它，因此它们都能调用下面三个方法。

- **addEventListener(type, listener, options)**：注册事件监听。
- **removeEventListener(type, listener, options)**：移除事件监听。
- **dispatchEvent(event)**：向该对象派发事件，返回布尔值——**有监听器调用过 preventDefault() 时返回 false**，否则返回 true。

```js
const button = document.querySelector("button");

// 监听器也可以是一个含 handleEvent 方法的对象
const clickHandler = {
  count: 0,
  handleEvent(event) {
    this.count += 1; // 对象作监听器时，this 指向该对象本身
    console.log(`第 ${this.count} 次点击`, event.type);
  }
};

button.addEventListener("click", clickHandler);
button.removeEventListener("click", clickHandler);
```

> 监听器中 **this 的指向有三种情况**：**普通函数**的 this 指向**绑定监听器的元素**（等价于 event.currentTarget）；**对象监听器**的 this 指向**该对象**；**箭头函数没有自己的 this**，沿用外层作用域，因此拿不到元素，需要使用元素时改写 event.currentTarget。



#### 事件的三种绑定方式

绑定事件有**三种方式**：HTML 事件属性、DOM 事件属性（onxxx）、addEventListener()。三者的可维护性与可控性依次增强。

- **HTML 事件属性**：写在标签里（如 onclick="..."），属性值是**字符串代码**，在浏览器隐式生成的函数中执行。
- **DOM 事件属性**：赋值给元素对象的 onclick 等属性，同一事件**只能有一个**处理器，后赋的覆盖先赋的。
- **addEventListener**：标准做法，可绑定**多个**、可精确移除、可指定阶段与选项。

```html
<!-- 方式一：HTML 属性，值是代码字符串，不推荐 -->
<button onclick="handleClick()">点击</button>
```

```js
const button = document.querySelector("button");

// 方式二：DOM 属性，同一事件只能有一个，后者覆盖前者
button.onclick = () => console.log("会被下面一行覆盖");
button.onclick = () => console.log("只有我生效");

// 方式三：addEventListener，多个并存且按注册顺序执行
button.addEventListener("click", () => console.log("监听器一"));
button.addEventListener("click", () => console.log("监听器二"));
```

```js
// IE8 及更早使用 attachEvent：事件名带 on 前缀、this 指向 window、执行顺序倒序
// element.attachEvent("onclick", handler);
// element.detachEvent("onclick", handler);
```

> addEventListener 相比 onxxx 属性的三大优势：**可注册多个监听器**、**可精确移除**、**可控制捕获/冒泡阶段**；onxxx 只余"写法简短"和"便于判断是否已绑定"两点便利。IE8 时代的 attachEvent 已彻底废弃，如今只会在考古代码里见到——它事件名要带 on 前缀、this 指向 window、多个监听器**倒序**执行、且只在冒泡阶段触发。另外，HTML 事件属性会把逻辑耦合进结构里，还会被 CSP（内容安全策略）挡下，应当避免。



#### addEventListener 的第三个参数

**addEventListener(type, listener, options)** 的第三个参数决定**何时触发**与**如何触发**，可以是一个布尔值，也可以是一个配置对象。

- **布尔值 useCapture**：true 表示在**捕获阶段**触发，默认 false（冒泡阶段）。
- **capture**：与 useCapture 等价的对象写法，默认 false。
- **once**：默认 false；为 true 时监听器**执行一次后自动移除**。
- **passive**：默认 false；为 true 时向浏览器**承诺不会调用 preventDefault()**。
- **signal**：传入一个 AbortSignal，调用对应 AbortController 的 abort() 即可移除监听器。

```js
const panel = document.querySelector(".panel");

// 布尔值：在捕获阶段触发
panel.addEventListener("click", () => console.log("捕获"), true);

// 配置对象：多个选项可组合
panel.addEventListener("click", () => console.log("只执行一次"), { once: true });

// passive：承诺不阻止默认行为，让滚动立即开始而不必等回调跑完
document.addEventListener("touchmove", () => {
  console.log("这里不调用 preventDefault，滚动更流畅");
}, { passive: true });
```

> passive 解决的是**滚动卡顿**：浏览器通常要等监听器跑完、确认它没调 preventDefault()，才敢执行默认滚动；声明 passive: true 后浏览器不必再等。两处细节要记：一是 removeEventListener 匹配时**只比对 capture**，once、passive 不参与匹配；二是 **passive 的默认值不总为 false**——在 window、document、document.body 上的 wheel、mousewheel、touchstart、touchmove 事件，现代浏览器默认即为 passive: true，此时 preventDefault() 无效并会在控制台告警，需要阻止必须显式写 { passive: false }。



#### 事件监听的移除与 AbortController

移除监听器要求**四要素一致**：同一目标、同一事件类型、**同一个函数引用**、**同一个捕获阶段**，缺一不可。

- **匿名函数无法移除**：每次字面量都会生成新的函数引用。
- **once: true**：让监听器执行一次后自动移除，免去手动清理。
- **signal 选项**：**批量解绑**的现代方案，一次 abort() 即可移除所有用该 AbortSignal 注册的监听器。

```js
const button = document.querySelector("button");

function handleClick() {
  console.log("点击一次");
}

// 具名函数：引用一致，可以移除
button.addEventListener("click", handleClick);
button.removeEventListener("click", handleClick);

// 匿名函数：removeEventListener 拿不到同一个引用，无效
button.addEventListener("click", () => console.log("移除不掉"));
button.removeEventListener("click", () => console.log("移除不掉"));

// 想移除箭头函数，必须先存进变量
const handleEnter = () => console.log("可以移除");
button.addEventListener("mouseenter", handleEnter);
button.removeEventListener("mouseenter", handleEnter);
```

```js
// 用 AbortController 批量解绑：一个 signal 管理一组监听器
const controller = new AbortController();

window.addEventListener("resize", () => console.log("尺寸变化"), { signal: controller.signal });
window.addEventListener("scroll", () => console.log("滚动"), { signal: controller.signal });

// 组件卸载、路由切换时统一解绑
controller.abort();
```

> 移除监听器的关键是**函数引用一致**：要么用具名函数，要么把箭头函数先存进变量。"只执行一次"用 once，"成组清理"用 signal——后者尤其适合 SPA 的组件卸载场景，避免逐个 removeEventListener 时漏掉某一个而内存泄漏。



#### 页面加载与生命周期事件

页面从加载到卸载有几个关键事件，触发时机各不相同。

- **DOMContentLoaded**：HTML 解析完毕、**DOM 树构建完成**时触发（不等待图片、样式等子资源）。
- **load**：页面**所有子资源**（图片、样式、iframe）加载完成时触发。
- **beforeunload**：页面即将卸载前触发，可用于挽留提示（需 preventDefault 或设置 returnValue）。
- **visibilitychange**：页面在**可见与隐藏**之间切换时触发（document.visibilityState 为 "visible" 或 "hidden"）。
- **readystatechange**：document.readyState 变化时触发，取值依次为 "loading"、"interactive"、"complete"。

```js
// readyState：loading → interactive（触发 DOMContentLoaded）→ complete（触发 load）
document.addEventListener("readystatechange", () => {
  console.log(document.readyState);
});

document.addEventListener("DOMContentLoaded", () => {
  console.log("DOM 就绪，可以安全操作元素");
});

window.addEventListener("load", () => {
  console.log("全部资源加载完成");
});

// 页面切到后台时暂停轮询/动画，切回再恢复
document.addEventListener("visibilitychange", () => {
  console.log(document.visibilityState, document.hidden);
});
```

> DOMContentLoaded 与 load 的顺序是 DOMContentLoaded 先、load 后，二者分别对应 readyState 的 interactive 与 complete。脚本放在 body 结束标签前或带 defer 属性时，代码执行时 DOM 已就绪，**不必再等 DOMContentLoaded**。注意移动端的 beforeunload、unload 并不可靠（切后台、杀进程时可能不触发），做"离场上报"应优先用 visibilitychange 配合 navigator.sendBeacon()。



### 事件模型

#### 事件传播的三个阶段

**事件流（Event Flow）**：事件从产生到结束，在 DOM 树中依次经过**捕获阶段（Capture）** → **目标阶段（Target）** → **冒泡阶段（Bubble）**，对应 event.eventPhase 的取值 1、2、3。

1. **捕获阶段**：从 window 沿祖先链**向下**，直到目标元素的父节点。
2. **目标阶段**：到达 event.target 本身。
3. **冒泡阶段**：从目标元素沿祖先链**向上**，回到 window。

```js
const outer = document.querySelector(".outer");
const inner = document.querySelector(".inner");

outer.addEventListener("click", (event) => console.log("捕获 outer", event.eventPhase), true);
inner.addEventListener("click", (event) => console.log("目标 inner", event.eventPhase));
outer.addEventListener("click", (event) => console.log("冒泡 outer", event.eventPhase));

// 点击 inner：捕获 outer(1) → 目标 inner(2) → 冒泡 outer(3)
```

> 目标阶段有一条易被忽略的规则：**eventPhase 为 2 时，捕获监听器与冒泡监听器都会触发，且按注册先后执行**——规范并不为"目标阶段"单独区分捕获与冒泡。因此 addEventListener 的 capture 选项只在**祖先链**上有意义，绑在目标元素本身时两种写法触发时机相同。



#### 事件冒泡与捕获

**冒泡（Bubble）** 与 **捕获（Capture）** 是事件传播的两个方向。

- **冒泡**：事件从**目标元素**逐级向上传播到祖先，是**默认**行为。
- **捕获**：事件从**根**逐级向下传播到目标元素，需显式开启 { capture: true }。

```html
<div id="parent">
  <button id="child">按钮</button>
</div>
```

```js
const parent = document.querySelector("#parent");
const child = document.querySelector("#child");

// 点击 child：先触发 child 的处理器，再冒泡到 parent
child.addEventListener("click", () => console.log("子元素"));
parent.addEventListener("click", () => console.log("父元素"));
// 输出：子元素 → 父元素
```

> 冒泡是日常最常用的机制，事件委托正建立在其上；捕获阶段用得少，但有两个典型用途：**在事件到达目标之前拦截**（权限校验、全局埋点），以及**让不冒泡的事件也能被祖先听到**——把监听器注册在捕获阶段即可，因为传播路径必定经过祖先。此外，若某个事件本身 **bubbles 为 false**，则只有捕获阶段能经过祖先，冒泡阶段完全不存在。



#### 事件委托

**事件委托（Event Delegation）**：把子元素的监听**注册在共同祖先上**，利用**事件冒泡**，用一个处理器服务一批元素。

```html
<ul id="list">
  <li data-id="1">项目 1</li>
  <li data-id="2">项目 2</li>
</ul>
```

```js
const list = document.querySelector("#list");

list.addEventListener("click", (event) => {
  // closest 从 event.target 向上找最近的匹配元素，兼容点中 li 内部节点的情况
  const item = event.target.closest("li");
  if (!item) return; // 点在 ul 的空白处，忽略
  console.log("点击了", item.dataset.id, item.textContent);
});
```

- **优势一（性能）**：一个监听器替代 N 个，内存占用与绑定开销大幅下降。
- **优势二（动态）**：后插入的子元素**无需重新绑定**即可响应。
- **写法要点**：用 event.target.closest(selector) 判断，而非直接比较 event.target.tagName，否则点到子元素的内部节点会失效。

> 事件委托的**前提是事件会冒泡**，因此它**不适用于 focus、blur、load、unload、mouseenter、mouseleave 等不冒泡的事件**。focus/blur 有两个替代方案：改用**会冒泡**的 focusin/focusout，或把监听器注册在**捕获阶段**。另外三个限制要留意：中间某层调用了 stopPropagation() 会让委托失效；事件目标与祖先之间若被 Shadow DOM 边界隔开，需事件 composed 为 true 才能穿透；mousemove 这类极高频事件委托到根节点时，回调里的判断逻辑要尽量轻。



#### 阻止传播、阻止默认行为与 passive

事件对象提供了三个"阻止"方法，作用范围层层收紧。

- **event.preventDefault()**：阻止事件的**默认行为**（链接跳转、表单提交、右键菜单、滚轮滚动），**不影响传播**。
- **event.stopPropagation()**：阻止事件**沿传播路径继续前进**（不再捕获或冒泡），**不影响同一元素上的其他监听器**。
- **event.stopImmediatePropagation()**：在 stopPropagation 的基础上，**额外阻止当前元素上尚未执行的其他监听器**。

```js
const link = document.querySelector("a");

// 阻止默认行为：链接不跳转，但事件照常冒泡
link.addEventListener("click", (event) => event.preventDefault());

const button = document.querySelector("button");
button.addEventListener("click", (event) => {
  console.log("先注册的先执行");
  event.stopImmediatePropagation();
});
button.addEventListener("click", () => console.log("永远不会执行"));
```

```js
// 只允许输入数字：拦截 keypress 的默认输入行为
const input = document.querySelector("input");

input.addEventListener("keypress", (event) => {
  if (!/\d/.test(event.key)) {
    event.preventDefault(); // 非数字字符不会被写进输入框
  }
});
```

- **event.defaultPrevented**：只读布尔值，表示**是否已有监听器调用过 preventDefault()**。
- **event.cancelable**：只读布尔值，表示**该事件的默认行为能否被取消**；为 false 时 preventDefault() 无效（如 scroll 事件）。

> 三者分工一句话记：**preventDefault 管"做不做"（默认动作），stopPropagation 管"传不传"（是否继续传播），stopImmediatePropagation 在"不传"之外还管"别人还做不做"**。三点补充：preventDefault 只在 cancelable 为 true 时有效，且必须在**同步**代码中调用（放进 setTimeout 就太晚了）；随意 stopPropagation 会制造"死区"，让上层的埋点、点击外部关闭弹窗等逻辑失效，非必要不使用；捕获阶段调用 stopPropagation 会**连冒泡一起掐断**。



#### 高频事件的节流与防抖

**节流（Throttle）**：让函数在**固定时间间隔内至多执行一次**，稀释执行频率。**防抖（Debounce）**：让函数在**最后一次触发后延迟一段时间才执行**，中途再次触发则重新计时。

- **节流**适用于：scroll、resize、mousemove 等需要"持续反馈但不必每次都算"的事件。
- **防抖**适用于：input 搜索联想、窗口 resize 结束后的重排、表单校验等只关心"最终那一次"的场景。

```js
// 节流：单位时间内至多执行一次
function throttle(func, wait) {
  let lastTime = 0;
  return function (...args) {
    const now = Date.now();
    if (now - lastTime >= wait) {
      lastTime = now;
      func.apply(this, args);
    }
  };
}

// 防抖：每次触发都重置计时器，停手后才执行
function debounce(func, wait) {
  let timerId = null;
  return function (...args) {
    clearTimeout(timerId);
    timerId = setTimeout(() => func.apply(this, args), wait);
  };
}

// 滚动：每 200 毫秒至多计算一次
window.addEventListener("scroll", throttle(() => {
  console.log("滚动位置", window.scrollY);
}, 200), { passive: true });

// 输入：停止输入 300 毫秒后才发请求
input.addEventListener("input", debounce(() => {
  console.log("发起搜索", input.value);
}, 300));
```

> 二者口诀：**节流是"按固定频率执行"（像水龙头滴水），防抖是"等安静下来再做"（像电梯关门）**。处理 scroll/resize 时还应配合 { passive: true }，并把真正的 DOM 读写放进 requestAnimationFrame 的下一帧，避免在一帧内反复读写布局属性造成**布局抖动（Layout Thrashing）**。



### Event 对象

#### Event 的实例属性

**Event 对象**：是浏览器在事件发生时**创建并传给监听器**的对象，携带类型、位置、按键等一切信息；MouseEvent、KeyboardEvent、ProgressEvent 等都是它的子类。

- **type**：事件类型字符串，如 "click"。
- **target**：**触发**事件的**最深**元素，在整条传播路径上**始终不变**。
- **currentTarget**：**当前正在执行监听器的那个元素**（即绑定者），等价于普通函数里的 this。
- **eventPhase**：当前阶段，1 捕获、2 目标、3 冒泡。
- **bubbles** / **cancelable**：该事件是否冒泡 / 默认行为是否可取消。
- **isTrusted**：true 表示事件由**用户真实操作**产生，false 表示由脚本 dispatchEvent 产生。
- **timeStamp**：事件创建的时刻（毫秒，相对 time origin）。

```js
const list = document.querySelector("#list");

list.addEventListener("click", function (event) {
  console.log(event.type);          // "click"
  console.log(event.target);        // 实际点击的后代元素
  console.log(event.currentTarget); // list 本身
  console.log(this === event.currentTarget); // true（换成箭头函数则为 false）
  console.log(event.bubbles, event.cancelable, event.isTrusted); // true true true
});
```

> target 与 currentTarget 是高频考点：**target 是"事发地"，传播途中始终不变；currentTarget 是"当前处理者"，随传播位置变化**。不委托时两者相同（都指向绑定元素），一旦委托就分道扬镳——委托中 target 是被点的子元素、currentTarget 是监听祖先。监听器执行完毕后 currentTarget 会被置为 null，若要在异步代码（如 setTimeout）里使用，需先存进变量。



#### Event 的实例方法

Event 对象的方法用于**控制事件行为**与**探查传播路径**。

- **preventDefault()**：取消默认行为。
- **stopPropagation()**：停止传播。
- **stopImmediatePropagation()**：停止传播，并阻止当前元素上的后续监听器。
- **composedPath()**：返回**事件传播路径**上的对象数组，包含 Shadow DOM 内部的节点。

```js
const button = document.querySelector("button");

button.addEventListener("click", (event) => {
  // 由内到外，最后一项通常是 window
  console.log(event.composedPath()); // [button, div, body, html, document, Window]
});
```

> composedPath() 是调试事件流最直观的工具：数组第 0 项就是 event.target，末项通常是 window。在 Shadow DOM 场景下，它能拿到被影子树边界隐藏的中间节点，而普通的 parentNode 链会在边界处断开。



#### 鼠标事件 MouseEvent

**MouseEvent**：是所有鼠标类事件的接口，继承 UIEvent 再继承 Event；WheelEvent、DragEvent、PointerEvent 都是它的子类。

- **常用类型**：click、dblclick、mousedown、mouseup、mousemove、mouseenter、mouseleave、mouseover、mouseout、contextmenu、wheel。
- **坐标属性**（难点在"相对谁"）：
  - **clientX / clientY**：相对**视口**左上角，不含滚动距离。
  - **pageX / pageY**：相对**文档**左上角，含滚动距离，即 pageX = clientX + window.scrollX。
  - **offsetX / offsetY**：相对**目标元素的内边距边**。
  - **screenX / screenY**：相对**屏幕**左上角。
  - **movementX / movementY**：相对**上一次 mousemove** 的位移。
- **按键与修饰键**：button（0 左键、1 中键、2 右键）、buttons（当前按住的按键位掩码）、ctrlKey、shiftKey、altKey、metaKey。
- **relatedTarget**：mouseover/mouseout 中"从哪来 / 到哪去"的那个元素。

```js
document.addEventListener("mousemove", (event) => {
  console.log("视口坐标", event.clientX, event.clientY);
  console.log("文档坐标", event.pageX, event.pageY);
});

document.addEventListener("click", (event) => {
  console.log("按下的键", event.button, "按住中的键", event.buttons);
});

// 自定义右键菜单：先阻止浏览器默认菜单
document.addEventListener("contextmenu", (event) => {
  event.preventDefault();
  console.log("在此显示自定义菜单", event.clientX, event.clientY);
});
```

> 两组高频辨析：一是 **mouseenter/mouseleave 与 mouseover/mouseout**——前者**不冒泡**、在父子元素之间移动**不重复触发**，后者**冒泡**、在子元素间移动会反复触发，做"悬停高亮"用前者省心；二是 **click 与 mousedown/mouseup**——click 要求**按下与抬起落在同一元素**才触发，因此"在 A 上按下、拖到 B 上抬起"不会产生 click。移动端还应注意 click 有约 300 毫秒的历史延迟，交互密集时可用 pointerdown 或 CSS 的 touch-action 规避。



#### 键盘事件 KeyboardEvent

**KeyboardEvent**：描述键盘交互，常用事件为 keydown（按下）与 keyup（松开）；keypress 已废弃，不应再使用。

- **key**：按键产生的**字符或键名**，受键盘布局、大小写与输入法影响（"a"、"A"、"Enter"、"ArrowUp"）。
- **code**：**物理键位**编码，与布局无关（KeyA、Digit1、Space、Enter）。
- **ctrlKey / shiftKey / altKey / metaKey**：修饰键是否按下。
- **repeat**：true 表示由**长按自动重复**产生。
- **isComposing**：true 表示按键正处于**输入法组字**过程中。

```js
document.addEventListener("keydown", (event) => {
  console.log(event.key, event.code, event.repeat);

  // 快捷键用 code：不受键盘布局与大写锁定影响
  if (event.ctrlKey && event.code === "KeyS") {
    event.preventDefault(); // 阻止浏览器自带的"保存网页"
    console.log("执行应用内保存");
  }

  // 判断输入内容用 key，但要先排除输入法组字阶段
  if (event.key === "Enter" && !event.isComposing) {
    console.log("回车提交");
  }
});
```

> [!CAUTION]
> **注意内容**：key 与 code 的取舍：**做游戏按键、快捷键判断用 code**（物理位置固定），**判断用户输入了什么字符用 key**。中文输入法组字期间会先触发 keydown，此时 isComposing 为 true、key 常常是 "Process"；若直接按 key === "Enter" 处理，会把"用回车选词"误判成提交，因此要加上 !event.isComposing 的判断。另外 keydown 支持长按重复（repeat），做"按住连发"要记得过滤。



#### 表单与焦点事件

表单元素有一组专用事件，核心差别在**触发时机**。

- **input**：值**每次变化**立即触发（键盘输入、粘贴、拖拽、语音输入都算）。
- **change**：值**已改变且已提交给元素**时触发——文本框在**失焦**时触发，select 元素、单复选框、文件选择则在**选中即触发**。
- **focus / blur**：获得 / 失去焦点，**不冒泡**；**focusin / focusout**：同义但**冒泡**。
- **submit**：表单提交时触发，绑在 form 元素上，**阻止默认行为即可接管提交**。
- **reset**：表单重置时触发。

```js
const input = document.querySelector("input");

input.addEventListener("input", (event) => {
  console.log("实时输入：", event.target.value); // 每敲一个字符都触发
});

input.addEventListener("change", (event) => {
  console.log("失焦后确认：", event.target.value);
});

// 委托处理焦点：必须用会冒泡的 focusin
document.querySelector("form").addEventListener("focusin", (event) => {
  console.log("获得焦点的字段：", event.target.name);
});
```

```html
<form id="loginForm">
  <input name="username" required minlength="3">
  <input name="password" type="password" required minlength="6">
  <button type="submit">登录</button>
</form>
```

```js
const form = document.querySelector("#loginForm");

form.addEventListener("submit", (event) => {
  event.preventDefault(); // 阻止默认的整页刷新式提交

  // 原生校验：checkValidity 返回布尔，reportValidity 还会弹出气泡提示
  if (!form.checkValidity()) {
    form.reportValidity();
    return;
  }

  const data = new FormData(form); // 自动收集所有带 name 的字段
  console.log(Object.fromEntries(data));
});
```

> input 与 change 的差别在**时机**而非内容：**input 是"每变一次就报"，change 是"尘埃落定再报"**。实时搜索与字数统计用 input；select 元素、日期、文件这类选择型控件只有 change 语义。表单提交有三个要点：preventDefault() 必须写在**同步**代码里；submit 事件要绑在 form 元素上而不是提交按钮的 click 上——后者会漏掉"在输入框里按回车"这种提交方式；原生校验靠 checkValidity() 与 reportValidity()，配合 required、minlength、pattern 等属性即可，无需自己写正则。



#### 拖拉事件

**拖拽（Drag and Drop）**：由**拖拽源**与**放置目标**两侧的事件协作完成，数据通过 event.dataTransfer 传递。

- **拖拽源**：dragstart（开始拖）、drag（拖动中）、dragend（拖拽结束）。
- **放置目标**：dragenter、dragover（悬停中，持续触发）、dragleave、drop（放下）。
- **dataTransfer.setData(format, data) / getData(format)**：写入 / 读取拖拽数据。
- **dataTransfer.files**：从操作系统拖入文件时，这里是 FileList。

```js
const draggable = document.querySelector(".drag");
const dropZone = document.querySelector(".drop");

draggable.addEventListener("dragstart", (event) => {
  event.dataTransfer.setData("text/plain", event.target.id);
  event.dataTransfer.effectAllowed = "move";
});

// 必须阻止 dragover 的默认行为，否则 drop 不会触发
dropZone.addEventListener("dragover", (event) => {
  event.preventDefault();
  event.dataTransfer.dropEffect = "move";
});

dropZone.addEventListener("drop", (event) => {
  event.preventDefault();
  const id = event.dataTransfer.getData("text/plain");
  console.log("放下了：", id);

  // 从桌面直接拖入文件
  const file = event.dataTransfer.files[0];
  if (file) console.log("拖入文件：", file.name, file.size);
});
```

> [!CAUTION]
> **注意内容**：拖拽最大的坑是 **dragover 必须 preventDefault()**——浏览器默认认为"此处不可放置"，不阻止就不会触发 drop。另外元素默认不可拖拽，需设置 draggable="true"（图片与链接除外，它们天生可拖）；若要做拖拽上传，把 dataTransfer.files 交给 FormData 即可，详见第 15 章。



#### 进度事件

**ProgressEvent**：描述**资源加载或数据传输**的进度，携带 loaded、total、lengthComputable 三个关键属性。

- **事件序列**：loadstart（开始）→ progress（进行中，可多次）→ load（成功）/ error（失败）/ abort（被取消）→ loadend（结束，无论成败）。
- **lengthComputable**：为 false 时 total 无意义（服务端未返回 Content-Length 或响应被压缩），此时**不能计算百分比**。

```js
const img = new Image();

img.addEventListener("progress", (event) => {
  if (!event.lengthComputable) return; // total 不可信时跳过
  console.log(`已加载 ${((event.loaded / event.total) * 100).toFixed(1)}%`);
});
img.addEventListener("load", () => console.log("图片加载完成"));
img.addEventListener("error", () => console.log("图片加载失败"));

img.src = "example.jpg";
```

> 进度事件是"**资源加载状态**"的通用模型，同时适用于图片、script 元素、XMLHttpRequest、FileReader。它也是文件上传进度条的基础：把监听器挂在 xhr.upload 上即可获得上传进度，详见第 14 章。



### 自定义事件

#### CustomEvent 与 dispatchEvent

**自定义事件**：由开发者**创建并派发**的事件，用于在同一 DOM 树内实现**解耦通信**。

- **new CustomEvent(type, options)**：options 支持 detail（自定义数据）、bubbles（是否冒泡，默认 false）、cancelable、composed。
- **new Event(type, options)**：不带 detail 的简单事件；需要携带数据就用 CustomEvent。
- **target.dispatchEvent(event)**：派发事件，返回布尔值——**被 preventDefault() 时返回 false**。

```js
const button = document.querySelector("button");

// 订阅方：监听自定义事件
document.addEventListener("user-login", (event) => {
  console.log("登录用户：", event.detail.name);
});

// 发布方：创建并派发，bubbles 让事件能一路冒到 document
const loginEvent = new CustomEvent("user-login", {
  detail: { name: "coderwhy", id: 1 },
  bubbles: true
});

button.dispatchEvent(loginEvent);
```

> [!CAUTION]
> **注意内容**：自定义事件是"**发布-订阅模式**"在浏览器中的原生实现：发布方只管 dispatchEvent，订阅方只管 addEventListener，双方互不引用。两个易错点：一是 **bubbles 默认 false**，想让祖先（如 document）收到就必须显式设为 true；二是**派发是同步的**——dispatchEvent 返回时所有监听器已执行完毕，这一点与 postMessage 的异步派发截然不同。



#### 事件总线与发布订阅

**事件总线（Event Bus）**：是一个**独立于 DOM 的发布-订阅容器**，让任意两个模块互相通信而无需引用彼此。

```js
class EventBus {
  constructor() {
    this.handlers = new Map();
  }

  // 订阅，返回用于取消订阅的函数
  on(type, handler) {
    const handlerSet = this.handlers.get(type) ?? new Set();
    handlerSet.add(handler);
    this.handlers.set(type, handlerSet);
    return () => this.off(type, handler);
  }

  // 取消订阅
  off(type, handler) {
    this.handlers.get(type)?.delete(handler);
  }

  // 发布，把数据依次传给所有订阅者
  emit(type, payload) {
    this.handlers.get(type)?.forEach((handler) => handler(payload));
  }
}

const bus = new EventBus();
const unsubscribe = bus.on("login", (user) => console.log("登录", user));

bus.emit("login", { name: "why" });
unsubscribe(); // 取消订阅，避免模块销毁后仍然被调用
```

> 用 Map 存类型、用 Set 存处理器有两个好处：**天然去重**（同一函数重复 on 只算一次）与**便于精确移除**。让 on 返回取消函数，调用方就不必自己保留函数引用。事件总线解耦了模块间的直接依赖，代价是**调用链变得隐晦、难以追踪**——大型项目里跨模块通信更推荐用全局状态管理（Pinia、Redux），总线更适合插件、埋点这类"谁都可以监听、但不强求有人监听"的场景。
