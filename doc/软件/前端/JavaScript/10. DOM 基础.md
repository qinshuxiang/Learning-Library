## DOM 基础

### DOM 与 BOM

#### DOM 的概念

**DOM（Document Object Model，文档对象模型）**：是浏览器把 HTML 文档解析后，生成的**树状对象模型**，让 JavaScript 能够**操作网页内容**。它是一套标准化的**编程接口**，规范现由 WHATWG 维护（DOM Living Standard，早期版本由 W3C 制定）。

- DOM 把每个标签、文本、属性都表示为**节点（Node）**。
- 通过 DOM 接口（如 document.querySelector()）可以增删改查网页元素。
- DOM 是**编程接口**，本身不是 JavaScript 语言的一部分。

```js
// 通过 DOM 获取并修改网页元素
const title = document.querySelector("h1");
title.textContent = "新的标题";
```

> DOM 的本质是**"网页的编程接口"**：HTML 是静态的文本，DOM 是浏览器把它变成的、可被脚本操作的对象树。JavaScript 之所以能"让页面动起来"，靠的就是 DOM。



#### BOM 的概念

**BOM（Browser Object Model，浏览器对象模型）**：是浏览器提供的、用于**操作浏览器本身**（而非网页内容）的一组对象，**没有统一标准**，由各浏览器自行实现。

BOM 的核心对象：

- **window**：浏览器窗口，是 BOM 的顶层对象。
- **location**：当前页面的 URL 信息。
- **history**：浏览历史。
- **navigator**：浏览器信息。
- **screen**：屏幕信息。

```js
console.log(window.location.href);  // 当前 URL
console.log(window.navigator.userAgent); // 浏览器标识
```

> DOM 与 BOM 的区别：**DOM 管"网页里有什么"，BOM 管"浏览器本身怎么样"**。DOM 有独立标准；BOM 长期无统一标准（HTML5 起才把 location、history、navigator 等核心对象收编进 HTML 标准），因此 BOM 对象在不同浏览器下可能存在差异。



#### DOM Tree

**DOM Tree（DOM 树）**：是浏览器把 HTML 文档按**层级结构**解析出的树状图。文档是根，标签是节点，层层嵌套。

一个 HTML 文档对应的 DOM 树结构：

```html
<!DOCTYPE html>
<html>
  <head>
    <title>标题</title>
  </head>
  <body>
    <h1>主标题</h1>
    <p>段落</p>
  </body>
</html>
```

- **document**：树的根节点。
- **html**：根元素，是 document 的子节点。
- **head、body**：html 的子节点，互为兄弟。
- **h1、p**：body 的子节点。

> DOM 树揭示了 HTML 的**层级关系**：父节点、子节点、兄弟节点。所有 DOM 操作（查找、遍历、增删）本质上都是在**这棵树上移动和修改**。理解树结构，才能理解各种导航 API。



### DOM 的架构与继承

#### DOM 架构的继承关系图

DOM 中的各类节点（元素、文本、注释）**不是孤立的对象**，而是遵循一套**继承体系**，理解它能掌握各种节点的共同能力。

继承关系（从抽象到具体）：

- **EventTarget**：最顶层，提供事件能力。
  - **Node**：所有节点的基类，提供树结构的导航能力。
    - **Element**：元素节点，提供属性、查找能力。
      - **HTMLElement**：HTML 元素，提供通用元素能力。
        - **具体元素**：如 HTMLDivElement、HTMLInputElement，提供特定标签的能力。
    - **Document**

```js
const div = document.createElement("div");

console.log(div instanceof EventTarget);    // true
console.log(div instanceof Node);           // true
console.log(div instanceof Element);        // true
console.log(div instanceof HTMLElement);    // true
console.log(div instanceof HTMLDivElement); // true
```

> 这个继承链解释了**能力的层层叠加**：EventTarget 让所有节点能监听事件，Node 让所有节点能导航（parentNode 等），Element 让元素能查找（querySelector 等）。越具体的类，能力越专有。



#### 类的继承概念

**继承（Inheritance）**：是面向对象的核心机制，指**子类拥有父类的属性和方法**，并可在此基础上扩展。DOM 架构正是继承的典型体现。

```js
// 用 ES6 class 模拟继承
class Node {
  constructor() { this.nodeType = 1; }
  getParent() { return this.parent; }
}

class Element extends Node {
  query(selector) { /* 查找 */ }
}

const el = new Element();
console.log(el.nodeType);  // 1（继承了 Node 的属性）
el.query("div");           // 拥有 Element 自己的方法
```

> 继承的价值是**代码复用与结构清晰**：通用的能力（导航、事件）定义在基类，各子类自动拥有，无需重复实现。DOM 用继承组织上百种节点类型，正是"用类的层级管理复杂系统"的典范。



### 节点之间的导航

#### document 对象与节点之间的导航

**document** 对象是 DOM 树的根，通过它可以访问整棵树的任何部分。节点导航通过 parentNode、childNodes 等属性在**节点之间**移动。

核心导航属性（节点层面）：

- **document.documentElement**：html 元素。
- **document.head** / **document.body**：head 元素与 body 元素。
- **node.parentNode**：父节点。
- **node.childNodes**：所有子节点（含文本、注释）。
- **node.firstChild** / **node.lastChild**：首/末子节点。
- **node.nextSibling** / **previousSibling**：相邻兄弟节点。

```js
console.log(document.documentElement); // <html>
console.log(document.body);            // <body>
console.log(document.body.firstChild); // body 的第一个子节点
```

> [!NOTE]
> **提醒内容**：注意"**节点**"与"**元素**"的区分：childNodes、nextSibling 等是**节点层面**的导航，会把**文本节点、注释节点**也包含进去；而 children、nextElementSibling 等是**元素层面**的，只包含元素。下一节详述。



#### 元素 element 之间的导航

**元素导航**只考虑**元素节点**，忽略文本和注释节点，是日常开发更常用的方式。

核心导航属性（元素层面）：

- **element.children**：所有子元素。
- **element.parentElement**：父元素。
- **element.firstElementChild** / **lastElementChild**：首/末子元素。
- **element.nextElementSibling** / **previousElementSibling**：相邻兄弟元素。

```html
<div id="container">
  <p>第一段</p>
  <p>第二段</p>
</div>
```

```js
const container = document.getElementById("container");
console.log(container.children);            // 两个 <p>（不含文本节点）
console.log(container.firstElementChild);   // 第一个 <p>
console.log(container.children[1].nextElementSibling); // null
```

> 元素导航与节点导航的对应关系：children（元素）对应 childNodes（节点），firstElementChild 对应 firstChild。**日常优先用元素导航**，因为文本/注释节点通常不是我们关心的目标。



#### document 对象的理解与前端开发模式

document 对象是前端开发的**核心入口**，几乎所有页面操作都从它开始。理解它有助于理解现代前端开发模式。

- **传统模式**：直接操作 document，通过 DOM API 增删改查真实节点。
- **现代框架模式**：Vue、React 等框架维护**虚拟 DOM**，开发者操作数据，框架负责把变化同步到真实 DOM。

```js
// 传统模式：手动操作 DOM
const ul = document.querySelector("ul");
const li = document.createElement("li");
li.textContent = "新项目";
ul.appendChild(li);
```

> 理解 document 与 DOM 操作，是理解**框架原理的基础**：框架的"响应式更新""虚拟 DOM diff"最终都会落到真实 DOM 操作上。掌握原生 DOM，才能理解框架在"替你做什么"，也才能应对脱离框架的场景。



#### table 与 form 的导航

table 和 form 元素有**专用的导航属性**，比通用导航更便捷。

table 相关：

- **table.rows**：所有 tr 行。
- **row.cells**：某行的所有 td 单元格。

form 相关：

- **form.elements**：表单内所有控件。
- **form.name**：通过 name 属性访问控件。

```js
const table = document.querySelector("table");
console.log(table.rows);        // 所有行
console.log(table.rows[0].cells); // 第一行的所有单元格

const form = document.querySelector("form");
console.log(form.elements);     // 表单内所有控件
console.log(form.elements["username"]); // name 为 username 的控件
```

> 这些专用属性让"操作表格/表单"变得直接：table.rows[0].cells[1] 就能定位到第一行第二列。相比用 querySelectorAll("tr") 层层筛选，专用属性语义更清晰、代码更简洁。



#### table 的导航案例练习

通过案例练习 table 的专用导航属性。

```js
// 遍历表格的每一行每一格
const table = document.querySelector("table");

for (const row of table.rows) {
  for (const cell of row.cells) {
    console.log(cell.textContent); // 输出每个单元格内容
  }
}

// 给表格隔行变色
for (let i = 0; i < table.rows.length; i++) {
  if (i % 2 === 1) {
    table.rows[i].style.backgroundColor = "#f0f0f0";
  }
}
```

> 表格导航的典型应用是**遍历与批量处理**：用 table.rows 拿到所有行，再对每行取 row.cells 处理单元格。隔行变色是经典需求，核心是"用索引判断奇偶行"。



#### ParentNode 与 ChildNode 接口

**ParentNode** 与 **ChildNode** 是两个**混入接口**，为元素/节点补充了一批便捷方法。

ParentNode 接口的方法（用于拥有子节点的对象）：

- **children**：子元素集合。
- **querySelector() / querySelectorAll()**：查找后代。
- **append() / prepend()**：末尾/开头添加节点。

ChildNode 接口的方法（用于可作为子节点的对象）：

- **remove()**：移除自身。
- **before() / after()**：在自身前后插入节点。
- **replaceWith()**：用新节点替换自身。

```js
const ul = document.querySelector("ul");

// ParentNode：append 添加
ul.append("新文本");

// ChildNode：remove 移除自身
const li = document.querySelector("li");
li.remove();
```

> 这些方法比传统的 appendChild、removeChild 更简洁：li.remove() 直接移除自身（无需找父节点），ul.append() 支持一次添加多个节点或文本。它们是现代 DOM 操作的首选。



### 获取元素

#### 获取任何元素的方法

获取 DOM 元素是操作的第一步，主要有两类方法。

- **document.querySelector(selector)**：返回**第一个**匹配的元素。
- **document.querySelectorAll(selector)**：返回**所有**匹配的元素（NodeList）。
- **document.getElementById(id)**：按 id 获取（快速）。
- **document.getElementsByClassName() / getElementsByTagName()**：旧式方法，返回动态集合。

```js
const first = document.querySelector(".item");       // 第一个 .item
const all = document.querySelectorAll(".item");      // 所有 .item
const byId = document.getElementById("app");          // id 为 app 的元素
const byClass = document.getElementsByClassName("item"); // 动态集合
```

> [!NOTE]
> **提醒内容**：现代开发**优先用 querySelector / querySelectorAll**，它们支持完整的 CSS 选择器，语法统一。getElementById 性能略优，getElementsByClassName 等返回**动态集合**（实时反映 DOM 变化），需注意与静态 NodeList 的区别。



#### nodeType 属性

**nodeType**：是节点的一个只读属性，用一个**数字**标识节点的类型，用于判断"这是哪种节点"。

常见的节点类型（nodeType 值）：

- **1**：元素节点（Element）。
- **3**：文本节点（Text）。
- **8**：注释节点（Comment）。
- **9**：文档节点（Document）。
- **11**：DocumentFragment 节点。

```js
const element = document.querySelector("div");
console.log(element.nodeType); // 1（元素节点）

const text = element.firstChild;
console.log(text.nodeType);    // 3（文本节点）

console.log(document.nodeType); // 9（文档节点）
```

> nodeType 是区分节点类型的**底层依据**。虽然日常多用 instanceof 或 tagName 判断，但 nodeType === 1 这种判断在遍历节点时仍很常见，尤其需要区分元素与文本节点时。



#### Node 节点获取内容的方式

获取节点内容有多个属性，语义各不相同。

- **textContent**：获取/设置节点的**纯文本**内容（含所有后代文本，不含标签）。
- **innerText**：类似 textContent，但受 CSS 影响（如 display:none 的元素取不到）。
- **innerHTML**：获取/设置节点的 **HTML 字符串**（含标签）。
- **nodeValue**：文本节点、注释节点才有的值，元素节点为 null。

```js
const div = document.querySelector("div");
console.log(div.textContent); // 纯文本内容
console.log(div.innerHTML);   // 含 HTML 标签的内容
console.log(div.nodeValue);   // null（元素节点无 nodeValue）
```

> [!WARNING]
> **警告内容**：三者区别是高频考点：textContent 返回**纯文本**（安全、性能好），innerHTML 返回**HTML 字符串**（可解析标签，但有 XSS 风险），innerText 受渲染影响。**设置文本用 textContent，插入 HTML 才用 innerHTML**。



#### NodeList 与 HTMLCollection

**NodeList** 和 **HTMLCollection** 都是**类数组对象**（有 length 和索引，但非真数组），用于表示节点集合，二者有细微差别。

- **NodeList**：querySelectorAll 返回，是**静态**的（不随 DOM 变化），可包含任意类型节点。
- **HTMLCollection**：getElementsByClassName、children 返回，是**动态**的（实时反映 DOM），只含元素。

```js
const staticList = document.querySelectorAll("li"); // NodeList，静态
const dynamicList = document.getElementsByTagName("li"); // HTMLCollection，动态

// 转成真数组再操作
const realArray = Array.from(staticList);
realArray.forEach((li) => console.log(li));
```

> 两者都是类数组，**没有 forEach/map 等方法**（NodeList 有 forEach 但无 map），需用 Array.from() 或展开语法 [...] 转真数组。理解"静态 vs 动态"能避免"遍历时集合变了导致 bug"的隐患。
