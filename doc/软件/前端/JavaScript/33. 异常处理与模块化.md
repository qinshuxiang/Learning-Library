## 异常处理与模块化

### 异常处理

#### 函数的错误处理方案

错误处理有几种方案，从被动到主动。

- **返回错误码**：函数返回特定值表示出错（如 -1、null）。
- **抛出异常**：用 throw 抛错，由调用方 try/catch 处理。

```js
// 方案一：返回错误码
function divide1(a, b) {
  if (b === 0) return null; // 用 null 表示出错
  return a / b;
}

// 方案二：抛出异常
function divide2(a, b) {
  if (b === 0) {
    throw new Error("除数不能为 0");
  }
  return a / b;
}

try {
  console.log(divide2(10, 0));
} catch (err) {
  console.log(err.message); // "除数不能为 0"
}
```

> 返回错误码的问题：**错误码易被忽略**、**与正常返回值混淆**。抛异常则**强制**调用方处理（否则程序中断），错误更不容易被遗漏。现代 JavaScript 更推荐抛异常 + try/catch 的方式。



#### 抛出异常的其他补充

throw 可以抛出**任意类型**的值，也可抛自定义错误。

```js
// 抛任意值（字符串、对象等）
throw "出错了";
throw { code: 500, message: "服务器错误" };

// 抛 Error 对象（推荐）
throw new Error("标准错误");
throw new TypeError("类型错误");
throw new RangeError("范围错误");
```

> 虽然 throw 能抛任意值，但**推荐抛 Error 对象**（或其子类），因为它携带**堆栈信息**、能被 instanceof 识别、便于调试。抛裸字符串或对象会丢失这些信息。



#### 处理异常的方法

处理异常用 **try/catch/finally** 结构。

- **try**：包裹可能出错的代码。
- **catch**：捕获并处理错误。
- **finally**：无论成败都执行。

```js
try {
  // 可能出错的代码
  riskyOperation();
} catch (err) {
  // 处理错误
  console.log("出错：", err.message);
} finally {
  // 无论成败都执行（清理资源）
  console.log("清理资源");
}
```

> [!CAUTION]
> **注意**：try/catch 只能捕获**同步**错误；异步错误（如 setTimeout 里的、Promise 里的）需用其它方式（Promise 的 .catch、async/await 配合 try/catch）。finally 常用于释放资源、关闭连接。



#### 内置错误类型

JavaScript 内置了多种错误类型，各有用途。

- **Error**：通用错误基类。
- **TypeError**：类型错误（如对非函数调用）。
- **RangeError**：范围错误（如数组长度越界）。
- **ReferenceError**：引用错误（如访问未声明变量）。
- **SyntaxError**：语法错误。

```js
try {
  // foo(); // TypeError: foo is not a function
  // console.log(undefinedVar); // ReferenceError
  new Array(-1); // RangeError
} catch (err) {
  console.log(err.name); // 错误类型名
  console.log(err instanceof TypeError); // 判断类型
}
```

> 每种错误类型对应**特定场景**，用 instanceof 可**区分处理**不同的错误。理解内置错误类型，能更精准地捕获和处理异常。



#### 自定义错误类型

可以**继承 Error** 自定义错误类型，携带业务信息。

```js
class BusinessError extends Error {
  constructor(message, code) {
    super(message);
    this.name = "BusinessError";
    this.code = code; // 自定义错误码
  }
}

try {
  throw new BusinessError("余额不足", 1001);
} catch (err) {
  console.log(err.name);   // "BusinessError"
  console.log(err.code);   // 1001
  console.log(err.message); // "余额不足"
}
```

> 自定义错误类型让错误**携带业务语义**（错误码、字段等），便于上层**精确处理**（如按错误码跳转不同提示）。它是大型项目错误处理的最佳实践。



### 模块化

#### JavaScript 模块化的历史

JavaScript 模块化经历了从无到有的演进。

- **早期（无模块）**：所有脚本全局共享，靠**全局变量**和**脚本顺序**协作，易冲突。
- **命名空间/IIFE**：用对象或立即执行函数隔离作用域。
- **CommonJS**：Node.js 的模块规范。
- **AMD / CMD**：浏览器端的模块规范（RequireJS、Sea.js）。
- **ESModule**：ES6 官方的模块标准。

```js
// 早期：全局变量，易冲突
var moduleA = { data: 1 };
// IIFE：隔离作用域
(function () {
  var privateData = 2;
})();
```

> 模块化的核心诉求是"**作用域隔离 + 依赖管理**"：把代码拆成独立模块，明确依赖关系，避免全局污染。理解这段历史，才能理解 ESModule 为什么要那样设计。



#### 自定义模块化规范

在官方规范出现前，人们**自定义**模块化方案（如 IIFE + 全局对象）。

```js
// 自定义模块：用对象导出
const myModule = (function () {
  const privateData = "私有";
  function getData() {
    return privateData;
  }
  return { getData }; // 只暴露 getData
})();

console.log(myModule.getData()); // "私有"
// 私有变量无法直接访问
```

> 自定义模块用 **IIFE + 闭包**实现"私有变量 + 暴露接口"，是现代模块化的**雏形**。它揭示了模块化的本质：**隐藏内部实现，只暴露必要接口**。



#### CommonJS 的基本使用

**CommonJS**：是 **Node.js** 采用的模块规范，用 require 引入、module.exports 导出。

```js
// 导出（math.js）
const add = (a, b) => a + b;
const PI = 3.14159;
module.exports = { add, PI };

// 引入（main.js）
const math = require("./math.js");
console.log(math.add(1, 2)); // 3
console.log(math.PI);        // 3.14159
```

> CommonJS 是**同步加载**的，适合**服务端**（文件在本地磁盘，同步加载无压力）。它是 Node.js 的默认模块系统，require 和 module.exports 是它的两个核心。



#### Node 实现 CommonJS 的原理

Node 实现 CommonJS，本质是**把模块包进一个函数**执行。

```js
// Node 内部大致将模块代码包裹为：
(function (exports, require, module, __filename, __dirname) {
  // 模块代码
  const add = (a, b) => a + b;
  module.exports = { add };
});
```

> Node 加载模块时，把模块代码**包裹进一个函数**，传入 exports、require、module 等参数。这解释了几个现象：模块内 require、module 可用、模块有**独立作用域**（变量不泄漏全局）、__filename/__dirname 可用。



#### exports 的作用和原理

exports 是 module.exports 的**引用**，二者关系易混淆。

```js
// exports 指向 module.exports
console.log(exports === module.exports); // true

// 正确：给 exports 加属性
exports.a = 1; // 等价于 module.exports.a = 1

// 错误：重新赋值 exports 会断开引用
// exports = { b: 2 }; // 无效，module.exports 没变
```

> [!WARNING]
> **警告**：exports 是 module.exports 的**引用**。**给 exports 加属性**是有效的（exports.a = 1）；但**重新赋值 exports** 会断开引用、失效。真正导出的是 module.exports，因此**始终用 module.exports** 最安全。



#### require 的细节

require 有几个关键细节。

- **缓存**：模块只加载一次，之后 require 返回**缓存**的 module.exports。
- **路径解析**：按文件路径、node_modules 等规则查找。
- **支持 JSON**：require 可加载 .json 文件。

```js
// 缓存：同一模块只执行一次
const m1 = require("./module.js");
const m2 = require("./module.js");
console.log(m1 === m2); // true（缓存，返回同一对象）

// 加载 JSON
const config = require("./config.json");
console.log(config);
```

> require 的**缓存机制**很关键：模块只加载执行一次，后续 require 返回缓存（因此模块是"单例"的）。这也意味着**循环依赖**时，可能拿到未完全初始化的模块。



#### 模块加载过程的细节

CommonJS 模块加载的完整过程。

1. **解析路径**：确定模块文件的绝对路径。
2. **加载**：读取文件内容。
3. **包裹**：把代码包进函数。
4. **执行**：执行函数，得到 module.exports。
5. **缓存**：把结果缓存起来。

```js
// 伪代码：require 的内部过程
function require(modulePath) {
  if (cache[modulePath]) return cache[modulePath]; // 缓存
  const module = { exports: {} };
  const wrapped = wrap(readFile(modulePath));
  wrapped(module.exports, require, module, ...); // 执行
  cache[modulePath] = module.exports; // 缓存
  return module.exports;
}
```

> 理解加载过程，能解释 CommonJS 的**同步性、缓存、作用域隔离**等特性。这个"解析 → 包裹 → 执行 → 缓存"的流程，是模块系统的核心骨架。



#### CommonJS 的缺点与 AMD、CMD

CommonJS 是**同步**加载，在浏览器端有缺陷，于是有了 AMD、CMD。

- **CommonJS 缺点**：同步加载，浏览器中会**阻塞**（网络请求慢）。
- **AMD**：**异步**加载，依赖前置（RequireJS）。
- **CMD**：**异步**加载，依赖就近（Sea.js）。

```js
// AMD（RequireJS）：依赖前置
define(["moduleA", "moduleB"], function (a, b) {
  return function () { /* 使用 a、b */ };
});

// CMD（Sea.js）：依赖就近
define(function (require) {
  const a = require("moduleA"); // 用到时才加载
});
```

> AMD 与 CMD 都是为**浏览器异步加载**设计的，区别在于**依赖声明时机**：AMD **前置声明**（定义时列全依赖），CMD **就近声明**（用到时再 require）。二者后来都被 ESModule 取代。



#### AMD 规范与 require 的实现

**AMD** 用 define 定义模块、require 异步加载，核心是**依赖前置 + 回调**。

```js
// 定义模块
define("moduleA", [], function () {
  return { value: "A" };
});

// 依赖 moduleA
define("moduleB", ["moduleA"], function (a) {
  return { value: "B", ref: a.value };
});

// 使用
require(["moduleB"], function (b) {
  console.log(b.value, b.ref); // "B" "A"
});
```

> AMD 的核心思想：**先声明所有依赖，异步加载完再执行工厂函数**。这解决了浏览器"同步加载阻塞"的问题，是 RequireJS 的实现范式。



#### CMD 规范与 sea.js 的实现

**CMD** 的 define 也支持依赖，但强调**就近 require**（用到才加载）。

```js
// CMD 定义模块
define(function (require, exports, module) {
  // 用到时才 require
  const a = require("moduleA");
  exports.value = "使用 " + a.value;
});
```

> CMD 与 AMD 的差异是**依赖解析时机**：CMD 在**执行时**才 require（就近），AMD 在**定义时**声明（前置）。CMD 更接近 CommonJS 的写法，曾是国内（Sea.js）流行的方案。



#### ESModule 的使用与注意事项

**ESModule（ESM）**：是 ES6 官方的模块标准，用 import/export。

```js
// 导出（math.js）
export const PI = 3.14159;
export function add(a, b) {
  return a + b;
}
const secret = "私有"; // 不导出即私有
export default function () { return "默认导出"; }

// 导入（main.js）
import defaultFn, { PI, add } from "./math.js";
console.log(PI, add(1, 2));
```

ESModule 的注意事项：

- **编译时确定依赖**（静态结构），可被**静态分析**（tree-shaking）。
- 默认**严格模式**。
- 在浏览器中需 <script type="module">。

> ESModule 是**官方标准**，有两大优势：一是**静态结构**（依赖在编译时就确定，支持 tree-shaking 摇树优化）；二是**浏览器原生支持**。它是现代前端（配合打包工具）的主流模块方案。



#### ESModule 的其他用法

ESModule 的其它语法。

- **重命名**：import { a as b }。
- **整体导入**：import * as ns from "./m.js"。
- **重新导出**：export { x } from "./m.js"。

```js
// 重命名
import { add as sum } from "./math.js";

// 整体导入（命名空间）
import * as math from "./math.js";
console.log(math.add(1, 2));

// 重新导出
export { PI } from "./math.js";
```

> 这些语法让 ESModule 更灵活：as 重命名避免冲突、* as 整体导入、export ... from 聚合再导出（常用于入口文件统一导出）。



#### ESModule 与 CommonJS 的结合使用

ESModule 与 CommonJS 是**两套体系**，互操作有规则。

- **CommonJS 导出的东西**，ESModule 可通过**默认导入**使用。
- **ESModule 的默认导出**，CommonJS 可通过 require().default 获取。

```js
// CommonJS 模块（cjs.js）
module.exports = { value: "CJS" };

// ESModule 导入 CommonJS
import cjs from "./cjs.js";
console.log(cjs.value); // "CJS"（默认导入整个 module.exports）
```

> 两套体系互操作是打包工具（webpack、Vite）要处理的复杂问题。核心区别：CommonJS **运行时**确定依赖、ESModule **编译时**确定。现代项目通常统一用 ESModule，打包工具负责兼容。



#### 动态 import() 与 import.meta

- **import() 动态导入**：**运行时**加载模块，返回 Promise，支持**按需加载**。
- **import.meta**：模块的**元信息**（如 import.meta.url）。

```js
// 动态导入：按需加载
button.addEventListener("click", async () => {
  const module = await import("./heavy-module.js");
  module.doSomething();
});

// import.meta
console.log(import.meta.url); // 当前模块的 URL
```

> 动态 import() 实现了**懒加载、代码分割**（配合打包工具按需加载模块）。import.meta 提供模块自身的元信息。二者是 ESModule 在工程化中的重要补充。



#### ESModule 的循环依赖

循环依赖（A 导入 B，B 导入 A）在 ESModule 中的表现。

```js
// a.js
import { b } from "./b.js";
export const a = "A";

// b.js
import { a } from "./a.js";
export const b = "B";
// 循环依赖时，可能拿到 undefined（未初始化完成）
```

> [!WARNING]
> **警告**：循环依赖是模块化的**经典难题**：ESModule 由于是**静态**的，循环依赖时可能拿到 undefined（模块未初始化完成）。避免循环依赖是**架构设计**问题——应重构代码、抽出公共部分，而非靠机制硬扛。



### Babel 与语法编译

#### Babel 与 AST

**Babel**：是把**新语法**转成**旧语法**（兼容老浏览器）的编译工具，核心基于 **AST（抽象语法树）**。

- **解析（Parse）**：源码 → AST。
- **转换（Transform）**：AST → 新 AST（应用插件）。
- **生成（Generate）**：新 AST → 目标代码。

```js
// Babel 把箭头函数转成普通函数
// 源码：const add = (a, b) => a + b;
// 转换后：var add = function(a, b) { return a + b; };
```

> Babel 的三步流程（解析 → 转换 → 生成）都围绕 **AST**——把代码解析成树结构，通过插件改写树，再生成新代码。理解 AST，是理解 Babel、ESLint、Prettier 等一切"代码处理工具"的基础。



#### Babel 编译 Class、Generator 与 Async

Babel 能把高级语法编译成低级等价物。

- **Class** → 构造函数 + 原型。
- **Generator** → 状态机（switch-case）。
- **Async/await** → Generator + Promise 的组合。

```js
// async/await 被 Babel 转成 Generator + 自动执行器
async function foo() {
  const r = await bar();
  return r;
}
// 大致转为：function* foo() { ... } 配合自动执行
```

> Babel 的编译揭示了一个深刻事实：**async/await 本质是 Generator + Promise 的语法糖**。看编译产物，能加深对语言特性的理解——很多"高级语法"底层都有朴素的实现。
