## Promise

### 异步请求的处理方案

异步操作的处理经历了从"回调"到"Promise"再到"async/await"的演进。

- **回调函数**：最原始，但会陷入**回调地狱**（层层嵌套）。
- **Promise**：把异步操作**链式化**，用 .then() 串联，解决回调地狱。
- **async/await**：Promise 的**语法糖**，用同步写法写异步代码。

```js
// 回调地狱（难以维护）
getData(function (a) {
  getMoreData(a, function (b) {
    getEvenMore(b, function (c) {
      console.log(c);
    });
  });
});

// Promise 链式（清晰）
getData()
  .then((a) => getMoreData(a))
  .then((b) => getEvenMore(b))
  .then((c) => console.log(c));
```

> 异步的核心矛盾是"**代码不按书写顺序执行**"。回调通过"传函数"解决，但嵌套会失控；Promise 通过"链式"把异步**扁平化**，是异步方案的重要里程碑。



### Promise 的基本使用

#### Promise 的三种状态

**Promise**：是表示**异步操作最终结果**的对象，有三种状态。

- **pending（进行中）**：初始状态，结果未定。
- **fulfilled（已成功）**：操作成功，有结果值。
- **rejected（已失败）**：操作失败，有原因。

```js
const promise = new Promise((resolve, reject) => {
  // 异步操作
  setTimeout(() => {
    resolve("成功"); // 状态 pending → fulfilled
    // reject("失败"); // 状态 pending → rejected
  }, 1000);
});

console.log(promise); // 初始是 pending
```

> Promise 状态的**三个关键特性**：状态只能**从 pending 转变一次**（要么 fulfilled、要么 rejected）、**不可逆转**、**结果不可改变**。一旦确定，就永远是那个结果。



#### resolve 方法的参数

resolve 可以接收**不同参数**，行为各异。

- **普通值**：直接作为结果。
- **另一个 Promise**：等待该 Promise 的结果（**状态跟随**）。
- **thenable 对象**（有 then 方法的对象）：调用其 then。

```js
// resolve 一个 Promise：状态跟随
const p1 = new Promise((resolve) => {
  setTimeout(() => resolve("内部结果"), 1000);
});

const p2 = new Promise((resolve) => resolve(p1));
// p2 会等待 p1，最终状态与 p1 一致
```

> resolve 传入 Promise 时，会**"展开"**它——外层 Promise 的状态跟随内层。这为"Promise 组合"（如 then 返回 Promise 时自动等待）奠定了基础。



### Promise 的对象方法

#### then 方法

**promise.then(onFulfilled, onRejected)**：注册成功/失败回调，**返回新 Promise**，实现链式调用。

```js
const promise = new Promise((resolve) => resolve(1));

promise
  .then((value) => {
    console.log(value); // 1
    return value * 2;   // 返回值传给下一个 then
  })
  .then((value) => {
    console.log(value); // 2
  });
```

> then 的**返回值决定链的走向**：返回普通值 → 下一个 then 拿到该值；返回 **Promise** → 等待它；**抛错** → 走 catch。理解"then 返回新 Promise + 返回值传递"，就理解了 Promise 链式的核心。



#### catch 方法

**promise.catch(onRejected)**：捕获链上**任何一处**的失败，是 then 失败回调的简写。

```js
new Promise((resolve, reject) => {
  reject("出错了");
})
  .then((v) => console.log(v))
  .catch((err) => {
    console.log("捕获错误：", err); // 捕获错误：出错了
  });
```

> catch 能捕获**链上任意位置**抛出的错误（包括 then 回调里抛的错），是 Promise 错误处理的核心。它等价于 .then(null, onRejected)，但语义更清晰。



#### finally 方法

**promise.finally(onFinally)**：无论成功失败都执行，用于**清理**逻辑。

```js
fetch("/api")
  .then((r) => r.json())
  .catch((err) => console.error(err))
  .finally(() => {
    console.log("无论成败，都会执行（如隐藏 loading）");
  });
```

> finally 不接收结果（成功失败都执行同一个回调），常用于**关闭加载动画、释放资源**等收尾工作。它返回的 Promise **透传**原结果。



#### 值穿透与错误处理实践

**值穿透（Value Penetration）**：指 .then() 若没有传入对应的回调参数，Promise 的**结果/拒绝原因会被"透传"到链的下一个 .then()/.catch()**，中间的空 then 只是"路过"。

```js
Promise.resolve("结果")
  .then()                          // 没有回调，值穿透到下一层
  .then((v) => console.log(v));    // "结果"（穿透成功值）

Promise.reject(new Error("原因"))
  .then(() => console.log("不会走这里")) // 跳过成功回调
  .catch((e) => console.log(e.message)); // "原因"（错误穿透）
```

> 值穿透的成因：then 内部会把**缺失的参数**替换为默认函数——成功回调默认 (v) => v（原样返回），失败回调默认 (err) => { throw err; }（继续抛出）。理解这一默认机制，就能明白为什么省略参数时错误不会"消失"，而是沿链向下传递直到被 catch。

两个易踩的实战陷阱：

- **错误吞掉（Swallowed Error）**：在 then 回调里 return promise2 而不是返回后 .catch，或在 catch 里忘记 throw/return Promise.reject，会导致**后续的 catch 接不到错误**（catch 返回的 Promise 是"已恢复"状态）。
- **未处理的拒绝（unhandledrejection）**：若一个 reject 的 Promise **从头到尾没有任何 .catch** 接住，会触发浏览器的 unhandledrejection 事件（Node 中是 unhandledRejection），该错误**不会默认抛到全局 window**，却可能让程序在 await 下崩溃，务必监听排查：

```js
window.addEventListener("unhandledrejection", (e) => {
  console.error("未被处理的 Promise 拒绝：", e.reason);
});
```

> [!IMPORTANT]
> **重要**：三条实践铁律——**链末必须收尾**（要么 catch 要么有兜底）；**catch 里若想"继续让外层失败"要重新 throw**；**不要无意义地 try/catch 包裹能靠链处理的 Promise**。错误一旦被 catch 接住而未重新抛出，就视为"已处理"，不会进入 unhandledrejection。



### Promise 的类方法

#### resolve 与 reject

- **Promise.resolve(value)**：创建**已成功**的 Promise。
- **Promise.reject(reason)**：创建**已失败**的 Promise。

```js
Promise.resolve(42).then((v) => console.log(v)); // 42
Promise.reject("err").catch((e) => console.log(e)); // "err"

// 常用于把值/函数统一包装成 Promise
function wrap(value) {
  return Promise.resolve(value);
}
```

> Promise.resolve/reject 常用于**把不确定的值包装成 Promise**、快速构造测试用的 Promise、统一同步/异步接口。



#### all 与 allSettled

- **Promise.all(iterable)**：**全部成功**才成功（任一失败则失败），返回结果数组。
- **Promise.allSettled(iterable)**：**等待全部结束**，返回每个的结果（无论成败）。

```js
const p1 = Promise.resolve(1);
const p2 = Promise.resolve(2);
const p3 = Promise.reject("失败");

Promise.all([p1, p2]).then((results) => {
  console.log(results); // [1, 2]（全部成功）
});
// Promise.all([p1, p3]) 会直接 reject（任一失败）

Promise.allSettled([p1, p3]).then((results) => {
  console.log(results);
  // [{ status: "fulfilled", value: 1 }, { status: "rejected", reason: "失败" }]
});
```

> all 是"**一票否决**"（一个失败全失败），适合"所有请求都必须成功"；allSettled 是"**全都要结果**"（不等失败），适合"收集所有请求结果，个别失败不影响整体"。



#### race 与 any

- **Promise.race(iterable)**：**第一个**结束的（无论成败）决定结果。
- **Promise.any(iterable)**：**第一个成功**的决定结果（全失败才 reject）。

```js
const slow = new Promise((r) => setTimeout(() => r("慢"), 1000));
const fast = new Promise((r) => setTimeout(() => r("快"), 100));

Promise.race([slow, fast]).then((v) => console.log(v)); // "快"（先结束的）
Promise.any([slow, fast]).then((v) => console.log(v));  // "快"（先成功的）
```

> race 是"**谁先结束听谁的**"（常用于**超时控制**），any 是"**谁先成功听谁的**"（忽略失败，全失败才 reject）。二者一字之差，语义不同。



### 手写 Promise

#### Promise 规范与整体设计

手写 Promise 前，需理解其**核心规范**（Promise/A+）。

核心要点：

- Promise 有三种状态，**状态只能转变一次**。
- then 返回**新 Promise**，实现链式。
- 回调是**异步**执行的（微任务）。
- 支持**链式传递**返回值。

```js
// 手写 Promise 的整体结构
class MyPromise {
  constructor(executor) { /* 状态、值、回调队列 */ }
  then(onFulfilled, onRejected) { /* 返回新 Promise */ }
  catch(onRejected) { /* 语法糖 */ }
}
```

> 手写 Promise 的目标是**理解其内部机制**（状态管理、回调队列、链式传递），而非生产替代。理解这些，才能真正驾驭异步、看懂框架源码。



#### 构造方法与 then 方法的实现

先实现**构造函数**（状态管理）与**基础 then**。

```js
class MyPromise {
  constructor(executor) {
    this.state = "pending";
    this.value = undefined;
    this.reason = undefined;
    this.onFulfilledCallbacks = [];
    this.onRejectedCallbacks = [];

    const resolve = (value) => {
      if (this.state === "pending") {
        this.state = "fulfilled";
        this.value = value;
        this.onFulfilledCallbacks.forEach((fn) => fn());
      }
    };
    const reject = (reason) => {
      if (this.state === "pending") {
        this.state = "rejected";
        this.reason = reason;
        this.onRejectedCallbacks.forEach((fn) => fn());
      }
    };

    executor(resolve, reject);
  }

  then(onFulfilled, onRejected) {
    if (this.state === "fulfilled") {
      onFulfilled(this.value);
    } else if (this.state === "rejected") {
      onRejected(this.reason);
    } else {
      // pending：把回调存起来，等状态改变时执行
      this.onFulfilledCallbacks.push(() => onFulfilled(this.value));
      this.onRejectedCallbacks.push(() => onRejected(this.reason));
    }
  }
}
```

> 基础版解决了**状态管理**与**回调队列**：resolve/reject 改变状态并执行队列中的回调，then 在 pending 时先把回调存起来。但还未实现**链式**（then 返回新 Promise）与**异步**。



#### then 方法的优化

对 then 进行优化，实现**链式**与**异步**。

##### then 方法的优化一

让 then **返回新 Promise**，实现链式传递。

```js
then(onFulfilled, onRejected) {
  return new MyPromise((resolve, reject) => {
    const handleFulfilled = () => {
      const result = onFulfilled(this.value);
      resolve(result); // 把返回值传给新 Promise
    };
    // ... 类似处理 rejected、pending
  });
}
```

> 链式的关键：then **返回新 Promise**，把回调的返回值 resolve 给新 Promise，这样下一个 then 就能拿到上一个的返回值。



##### then 方法的优化二

处理**返回值是 Promise**、**回调抛错**、**异步执行**等情况。

```js
function resolvePromise(promise, result, resolve, reject) {
  if (result instanceof MyPromise) {
    result.then(resolve, reject); // 返回 Promise 则等待
  } else {
    resolve(result); // 普通值直接 resolve
  }
}

// then 回调里 try/catch，抛错则 reject
// 用 queueMicrotask 或 setTimeout 实现异步执行
```

> 完整版需处理三个细节：**返回值是 Promise 时等待**、**回调抛错时 reject**、**回调异步执行**（放入微任务队列）。这些是 Promise 规范（A+）的核心要求。



#### catch 与 finally 的实现

catch 和 finally 都是 then 的**语法糖**。

```js
catch(onRejected) {
  return this.then(null, onRejected);
}

finally(onFinally) {
  return this.then(
    (value) => MyPromise.resolve(onFinally()).then(() => value),
    (reason) => MyPromise.resolve(onFinally()).then(() => { throw reason; })
  );
}
```

> catch 等价于 then(null, onRejected)；finally 是"**无论成败都执行 onFinally，然后透传原结果**"。理解它们是 then 的语法糖，就理解了它们的本质。



#### resolve 与 reject 的实现

静态方法 resolve/reject 用于快速创建 Promise。

```js
static resolve(value) {
  return new MyPromise((resolve) => resolve(value));
}

static reject(reason) {
  return new MyPromise((resolve, reject) => reject(reason));
}
```

> [!NOTE]
> **提醒**：Promise.resolve/reject 本质是"**构造一个立即 resolve/reject 的 Promise**"。resolve 传入 Promise 时需"展开"（返回原 Promise 本身）。



#### all、allSettled、race 与 any 的实现

实现四个静态组合方法，理解它们的不同语义。

```js
static all(promises) {
  return new MyPromise((resolve, reject) => {
    const results = [];
    let count = 0;
    promises.forEach((p, i) => {
      MyPromise.resolve(p).then((value) => {
        results[i] = value;
        if (++count === promises.length) resolve(results);
      }, reject); // 任一失败则 reject
    });
  });
}

static race(promises) {
  return new MyPromise((resolve, reject) => {
    promises.forEach((p) => MyPromise.resolve(p).then(resolve, reject));
  });
}
```

> all 用**计数器**统计完成数（全成功才 resolve）；race 让**第一个结束**的（无论成败）决定结果；allSettled 收集所有结果、any 找第一个成功。理解它们，能准确选用并手写。



#### 手写 Promise 的总结

手写 Promise 涉及的核心知识点总结。

- **状态机**：pending → fulfilled/rejected，只转变一次。
- **回调队列**：pending 时暂存回调，状态改变时执行。
- **链式**：then 返回新 Promise，返回值传递。
- **异步**：回调放入微任务执行。
- **静态方法**：all/race/allSettled/any 的组合逻辑。

> 手写 Promise 是**异步编程的综合大考**，串联了状态管理、回调、闭包、微任务等多个知识点。即使不逐字复现，理解"**状态 + 队列 + 链式**"这个骨架，就抓住了 Promise 的本质。
