## 网络请求与跨域

### 网络请求的认识

#### HTTP 请求的基本过程

**HTTP（HyperText Transfer Protocol，超文本传输协议）**：是浏览器与服务器之间**通信的协议**，浏览器向服务器发**请求（Request）**，服务器返回**响应（Response）**。

一次 HTTP 请求的基本过程：

1. **建立连接**：浏览器与服务器建立 TCP 连接。
2. **发送请求**：浏览器发送请求行、请求头、请求体。
3. **服务器处理**：服务器解析请求并生成响应。
4. **返回响应**：服务器返回状态行、响应头、响应体。
5. **断开/复用**：关闭连接或保持复用。

```js
// 请求方法、状态码等概念
// GET：获取数据；POST：提交数据
// 200：成功；404：未找到；500：服务器错误
```

> HTTP 是**无状态**协议（每次请求相互独立），这是 Cookie、Session、Token 等"状态保持"机制存在的根本原因。理解请求—响应的基本过程，是理解一切网络请求 API 的前提。



#### AJAX 与异步请求

**AJAX（Asynchronous JavaScript and XML）**：是一种**异步**地向服务器发请求、**不刷新页面**更新内容的技术，是现代 Web 应用的基石。

- **异步**：请求发出后不阻塞代码，响应到达时通过回调处理。
- **无刷新**：局部更新页面，体验流畅。

```js
// 异步请求的核心：发请求不阻塞，响应来了再处理
fetch("/api/data")
  .then((response) => response.json())
  .then((data) => console.log(data));

console.log("请求已发出，继续执行"); // 先于响应打印
```

> AJAX 名字里的 "XML" 已名不副实——现代数据格式主要是 **JSON**。AJAX 的核心思想是"**异步 + 无刷新**"：让网页像桌面应用一样流畅交互，而不必每次操作都整页刷新。



### XMLHttpRequest

#### XHR 的基本使用

**XMLHttpRequest（XHR）**：是 AJAX 的**早期实现**，通过事件监听处理异步响应，是理解 fetch 的前身。

```js
const xhr = new XMLHttpRequest();

xhr.open("GET", "/api/data");
xhr.onreadystatechange = function () {
  if (xhr.readyState === 4 && xhr.status === 200) {
    console.log(xhr.responseText);
  }
};
xhr.send();
```

- **open(method, url, async, user, password)**：配置请求，后三个参数可选，async 默认为 true。
- **setRequestHeader(name, value)**：设置请求头，须在 open 之后、send 之前调用。
- **send(body)**：发送请求，body 可为字符串、Blob、FormData 等。
- **onreadystatechange**：状态变化时的回调。
- **xhr.timeout 与 ontimeout**：设置超时毫秒数与超时回调。

> XHR 是**回调风格**的异步 API，代码较为繁琐（需手动判断 readyState 和 status）。但它仍是理解 fetch、以及看懂大量历史代码的必要知识。



#### readyState 与请求状态

**readyState**：表示请求所处的**阶段**，取值 0 到 4。

- **0**：未初始化（未调用 open）。
- **1**：已调用 open。
- **2**：已发送，收到响应头。
- **3**：正在接收响应体。
- **4**：请求完成。

```js
xhr.onreadystatechange = function () {
  console.log("当前状态：", xhr.readyState);
  if (xhr.readyState === 4) {
    console.log("请求完成，状态码：", xhr.status);
  }
};
```

> 关键判断是 **readyState === 4（完成）且 status === 200（成功）**。只判断 readyState === 4 还不够，因为完成不等于成功——服务器可能返回 404、500 等错误状态码。



#### 响应类型与 JSON 处理

XHR 支持多种响应类型，通过 responseType 指定。

- **responseText**：字符串响应（默认）。
- **responseType = "json"**：自动解析为 JSON 对象。
- **responseType = "blob"**：二进制数据。

```js
const xhr = new XMLHttpRequest();
xhr.open("GET", "/api/user");
xhr.responseType = "json";       // 指定 JSON
xhr.onload = function () {
  console.log(xhr.response.name); // 直接得到对象
};
xhr.send();
```

> 设置 responseType = "json" 后，xhr.response 直接是解析好的对象，免去手动 JSON.parse。onload 是 readyState === 4 时的简写事件，比 onreadystatechange 更简洁。



#### 上传与下载的进度事件

XHR 支持**下载进度**与**上传进度**的监听，用于进度条等场景。

- **下载进度**：xhr.onprogress（响应体接收中）。
- **上传进度**：xhr.upload.onprogress（请求体发送中）。

```js
const xhr = new XMLHttpRequest();

// 下载进度
xhr.onprogress = function (e) {
  if (e.lengthComputable) {
    const percent = (e.loaded / e.total) * 100;
    console.log(`下载进度：${percent}%`);
  }
};

// 上传进度
xhr.upload.onprogress = function (e) {
  const percent = (e.loaded / e.total) * 100;
  console.log(`上传进度：${percent}%`);
};
```

> 进度事件的关键是 **e.loaded（已传输）与 e.total（总量）**，二者相除得到百分比。上传进度监听在 xhr.upload 对象上（而非 xhr 本身），这是实现文件上传进度条的基础。



### Fetch

#### fetch() 的基本使用

**fetch()**：是现代、基于 **Promise** 的网络请求 API，语法更简洁，是 XHR 的替代方案。

```js
fetch("/api/data")
  .then((response) => response.json())
  .then((data) => console.log(data))
  .catch((error) => console.error("请求失败", error));
```

- fetch(url) 返回一个 **Promise**，resolve 出 Response 对象。
- 需调用 response.json() 等方法解析响应体。

> fetch 相比 XHR 的三大优势：**Promise 风格**（可链式、配合 async/await）、**语法简洁**、**更易理解**。它已成为现代网络请求的首选，但有一个重要"坑"（见"错误处理"一节）。



#### Request、Response 与 Headers

fetch 涉及三个核心对象。

- **Request**：请求对象，可配置方法、头、体。
- **Response**：响应对象，含状态、头、体。
- **Headers**：请求/响应头对象。

```js
const request = new Request("/api/data", {
  method: "POST",
  headers: new Headers({ "Content-Type": "application/json" }),
  body: JSON.stringify({ name: "why" })
});

fetch(request).then((response) => {
  console.log(response.status);         // 状态码
  console.log(response.headers.get("Content-Type"));
});
```

> fetch 的第二个参数是一个**配置对象**：method（方法）、headers（请求头）、body（请求体）。这三个对象让请求的构造更加结构化、可复用。



#### Response 的 body 读取

Response 提供了多种**读取响应体**的方法，需根据数据类型选择。

- **response.json()**：解析为 JSON 对象。
- **response.text()**：读取为文本。
- **response.blob()**：读取为二进制（如图片）。
- **response.arrayBuffer()**：读取为 ArrayBuffer。

```js
// JSON 响应
fetch("/api/user").then((r) => r.json()).then((data) => console.log(data));

// 文本响应
fetch("/api/text").then((r) => r.text()).then((text) => console.log(text));

// 二进制响应（如图片）
fetch("/img/avatar.png").then((r) => r.blob()).then((blob) => {
  const url = URL.createObjectURL(blob);
  console.log(url);
});
```

> 这些方法都返回 **Promise**，且**只能调用一次**（响应体只能读取一次）。根据后端返回的数据类型（JSON/文本/二进制）选择对应的方法，是最常用的写法。



#### fetch 的错误处理

fetch 的错误处理有一个**重要陷阱**：**只有网络错误**才会 reject，**HTTP 错误状态（404、500）不会 reject**。

```js
fetch("/api/not-found")
  .then((response) => {
    // 即使 404，也会走到这里
    if (!response.ok) {
      throw new Error(`请求失败：${response.status}`);
    }
    return response.json();
  })
  .then((data) => console.log(data))
  .catch((error) => console.error("出错：", error));
```

> [!IMPORTANT]
> **重要内容**：关键点：fetch 只有在**网络故障**（断网、DNS 失败等）时才 reject；**404、500 等 HTTP 错误会正常 resolve**。因此必须用 **response.ok**（或 status）手动判断成功与否，这是 fetch 与 XHR 最大的使用差异。



#### AbortController 与请求取消

**AbortController**：用于**取消** fetch 请求，配合 AbortSignal 使用。

```js
const controller = new AbortController();

fetch("/api/data", { signal: controller.signal })
  .then((r) => r.json())
  .then((data) => console.log(data))
  .catch((err) => {
    if (err.name === "AbortError") {
      console.log("请求已取消");
    }
  });

controller.abort(); // 取消请求
```

> 取消请求的典型场景：**搜索框防抖**（用户继续输入时取消上一个请求）、**超时控制**、**组件卸载**。AbortController 是原生取消机制，也是现代请求库（axios 等）底层能力的来源。



### 同源策略与跨域

#### 同源策略

**同源策略（Same-Origin Policy）**：是浏览器的**安全机制**，限制一个源（origin）的脚本**访问另一个源的资源**。它是浏览器最重要的安全基石之一。

**同源**需同时满足三个条件：

- **协议**相同（如都是 https）。
- **域名**相同（如都是 example.com）。
- **端口**相同（如都是 443）。

```js
// 同源：http://example.com:80/a 与 http://example.com:80/b
// 跨域：http://example.com 与 https://example.com（协议不同）
// 跨域：http://a.example.com 与 http://b.example.com（域名不同）
```

> 同源策略**限制的是"读取"**，而非"请求"：跨域请求能发出，但浏览器**阻止脚本读取响应**。它防止了恶意网站窃取用户在其他网站的数据（如 Cookie、银行信息），是 Web 安全的基石。



#### CORS 跨域资源共享

**CORS（Cross-Origin Resource Sharing，跨域资源共享）**：是**官方的跨域解决方案**，通过服务器设置响应头，**允许**特定源的跨域请求。

关键响应头：

- **Access-Control-Allow-Origin**：允许的源（* 或具体域名）。
- **Access-Control-Allow-Methods**：允许的 HTTP 方法。
- **Access-Control-Allow-Headers**：允许的请求头。

```js
// 服务器返回的响应头示例
// Access-Control-Allow-Origin: https://example.com
// Access-Control-Allow-Methods: GET, POST, PUT
```

> CORS 的原理是"**服务器主动声明允许谁跨域**"：浏览器发请求时带上 Origin，服务器通过 Access-Control-Allow-Origin 决定是否放行。它是**最标准、最推荐**的跨域方案，但需要**服务器配合**配置。



#### JSONP 与其他跨域方案

除了 CORS，还有若干跨域方案，各有适用场景。

- **JSONP**：利用 <script> 标签**不受同源策略限制**的特性，动态加载脚本获取数据（仅支持 GET）。
- **代理**：让同源服务器转发请求（开发环境常用 devServer 代理）。
- **postMessage**：跨窗口/iframe 通信。

```js
// JSONP：动态创建 script 标签
function jsonp(url, callbackName) {
  const script = document.createElement("script");
  script.src = `${url}?callback=${callbackName}`;
  document.body.appendChild(script);
}

// 服务器返回：callbackName({ data: ... })
```

> JSONP 的原理是"**<script> 标签可以跨域加载**"：服务器把数据包进一个函数调用里返回，脚本加载后自动执行。但它**只支持 GET、有安全隐患**，已逐渐被 CORS 取代；代理方案则常用于**开发环境**。



### FormData 与文件上传

#### FormData 的使用

**FormData**：用于**构造表单数据**，尤其适合**文件上传**，会自动设置 multipart/form-data 格式。

```js
const formData = new FormData();
formData.append("username", "coderwhy");
formData.append("avatar", fileInput.files[0]); // 文件

fetch("/api/upload", {
  method: "POST",
  body: formData
});
```

- **append(name, value)**：添加字段（字符串或文件）。
- 从表单构造：new FormData(formElement) 自动收集表单字段。

```js
const form = document.querySelector("form");
const data = new FormData(form); // 自动收集所有字段
```

> [!CAUTION]
> **注意内容**：FormData 的两大用途：**收集表单数据**（new FormData(form)）和**上传文件**（append("file", file)）。上传文件时**不要手动设置 Content-Type**，让浏览器自动添加 multipart/form-data 边界。



### WebSocket

#### WebSocket 的基本使用

**WebSocket**：是一种**全双工**的通信协议，在浏览器与服务器之间建立**持久连接**，实现**双向实时**通信。

```js
const ws = new WebSocket("ws://example.com/socket");

ws.onopen = () => console.log("连接已建立");
ws.onmessage = (e) => console.log("收到消息：", e.data);
ws.onerror = (e) => console.log("连接出错");
ws.onclose = () => console.log("连接已关闭");

ws.send("你好，服务器"); // 发送消息
```

- 连接建立后，**双方可随时互发消息**。
- 用 ws://（或加密的 wss://）协议。

> WebSocket 与普通 HTTP 的区别：HTTP 是**请求-响应**的单向模式，WebSocket 是**全双工持久连接**，服务器可主动推送。它适用于**聊天、实时通知、协作编辑、股票行情**等需要实时双向通信的场景。
