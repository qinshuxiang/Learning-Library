## 响应式设计与媒体查询

### 响应式设计

#### 响应式的概念与策略

**响应式设计（Responsive Web Design, RWD）**：让一套网页在不同设备（手机/平板/桌面）与不同视口宽度下**自动调整布局与样式**，核心思想是"**流动布局 + 弹性尺寸 + 断点重排**"。

- **流动布局**：用百分比、fr、minmax、auto 让块随容器伸缩，而不是写死像素。
- **弹性媒体**：图片/视频 max-width:100% 防溢出。
- **断点重排**：用媒体查询在某宽度临界点切换列数/布局。
- **视口 meta**：移动端必须设 <meta name="viewport">，否则按桌面宽度渲染（会横向缩放错乱）。

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0">
```

> 响应式的本质是"**不猜设备，而让布局对宽度敏感**"。策略上先做**移动优先（mobile-first）**——默认样式写小屏，再在断点处用 min-width 逐级增强为更宽布局，比桌面优先 + max-width 收缩更省心、性能更好。



#### 响应式的实现手段

- **流式网格**：容器/列用百分比或 fr，列数随宽度自动增（如 grid repeat(auto-fit, minmax(240px,1fr))）。
- **弹性图片**：img { max-width:100%; height:auto; } 避免横向溢出。
- **容器查询**：@container 让组件**按所在容器宽度**（而非视口）自适应，比只看视口的媒体查询更贴合"组件级复用"。
- **相对单位**：rem、vw、clamp() 让字号/间距随环境缩放。

```css
.gallery { display: grid; grid-template-columns: repeat(auto-fit, minmax(220px, 1fr)); }
img { max-width: 100%; height: auto; }
```

> 响应式的三根支柱：**网格弹性化**（几列自动）、**媒体自适应**（不溢出）、**按视口或容器切换布局**。现代偏好把"自适应组件"做成容器查询友好、再用视口媒体查询管整体骨架，二者分工：**容器查询管"卡片自己在窄处怎么排"，媒体查询管"整页断点怎么换"**。



### 媒体查询

#### @media 语法与媒体类型

**媒体查询（@media）**：基于**媒体特征**（宽度、方向、偏好等）条件式地应用样式，是响应式断点的载体。

```css
/* 类型：all(默认)|screen|print */
@media print { body { background: #fff; } }

/* 特征：宽度范围 */
@media (max-width: 600px) { /* 视口宽 ≤600px 时 */ }
@media (min-width: 601px) and (max-width: 1024px) { /* 平板区间 */ }
```

- **媒体类型**：all、screen（屏幕）、print（打印）。
- **宽度特征**：min-width/max-width 是最常用断点条件。
- **逻辑组合**：and、,（或）、not、only。
- **其它特征**：orientation（横竖屏）、(hover: hover)、(pointer: fine) 等。

> 媒体查询的判据是**当前视口/设备能力**，命中才应用。写断点时建议**约定一套断点值**（如 480/768/1024/1280），min-width 断点从小到大递增书写，逻辑最顺；避免散落一堆魔法数字。



#### 断点设计（移动优先）

**移动优先**：默认样式面向**最窄**（手机）书写，然后用 min-width 断点**逐级增强**为更宽布局。

```css
/* 默认：手机单列 */
.columns { display: block; }
/* ≥768px：平板两列 */
@media (min-width: 768px) {
  .columns { display: grid; grid-template-columns: repeat(2, 1fr); }
}
/* ≥1024px：桌面三列 */
@media (min-width: 1024px) {
  .columns { grid-template-columns: repeat(3, 1fr); }
}
```

> 移动优先的好处：默认代码最简、加载更小的基础样式；min-width 只在"变宽"时增量覆盖，逻辑单向清晰、不易互相打架。断点值应贴合**内容换行需求**而非死磕某机型——在"刚好换行难看"处设断点最科学。



#### prefers-* 功能查询

媒体查询不只管宽度，还能查询**用户与设备能力偏好**，用于无障碍与体验适配。

- **prefers-reduced-motion: reduce**：用户希望**减少动效**，应停/弱化动画（见动画章）。
- **prefers-color-scheme: dark**：系统处于**深色模式**，可切换深色主题。
- **prefers-contrast**、prefers-reduced-transparency：其它无障碍偏好。

```css
@media (prefers-color-scheme: dark) {
  body { background: #111; color: #eee; }
}
@media (prefers-reduced-motion: reduce) {
  * { animation-duration: 0.01ms !important; }
}
```

> 现代产品普遍通过 prefers-color-scheme 做**跟随系统深色模式**的主题（也可配合 JS 手动切换，存本地偏好并覆盖）。给动画加 prefers-reduced-motion 分支是无障碍刚需。学会"用媒体查询响应设备能力，而不只是宽度"，是进阶响应式的重要一步。
