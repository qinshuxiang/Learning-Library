## 浮动布局与清除浮动

### 文档流与浮动

#### 标准文档流

**标准文档流（Normal Flow）**：元素默认的排布规则——**块级元素从上到下、行内元素从左到右**依次排列，构成页面最基本的布局基础。理解流是理解"浮动/定位为何会脱离流"的前提。

- **块级元素**（block）：独占一行，从上到下堆叠，宽度默认撑满父容器。
- **行内元素**（inline）：从左到右在一行内排列，放不下才换行，不能设宽高与上下 margin。
- **行内块**（inline-block）：既能设宽高、又能在一行内排布。

> 现代布局（flex/grid）之所以"颠覆"传统，正是因为它们**重写了排列规则**、让开发者无需依赖"默认从上往下堆块"。但标准流仍是**文档的根本**——浮动/定位是"在流的基础上抽出来"的特殊行为。



#### 浮动的概念与作用

**浮动（float）**：让元素**脱离标准流**、向左或右靠，其后的行内内容会**环绕**它排布。旧时代浮动是实现"多列布局"的主力。

```css
img { float: left; margin-right: 12px; }  /* 图文环绕 */
.column { float: left; width: 33.33%; }   /* 老式三列布局 */
```

- float 取值：left/right/none。
- 浮动元素**脱离文档流**，不再参与父容器的高度撑起（这导致父塌陷，需清除浮动）。
- 浮动元素会**收缩宽度**（像行内块），一行放得下会**并排**，是旧式"横排布局"的原理。
- 后续的**块级兄弟会占据浮动元素空出的位置**（被浮动盖住），但文字等行内内容会绕开它。

> 一句话理解 float：**元素左/右飘，文字绕着飘走**。它曾承担"横排、多列、图文环绕"三大任务。如今**布局已由 flex/grid 接管**，float 主要退居"图文环绕"这一原生优势场景。



#### 浮动引发的"父塌陷"

**父塌陷（Collapse）**：由于浮动元素**脱离了文档流**、不再撑起父元素高度，父容器（若不设高度）会**塌成 0 或很矮**，这是浮动布局最经典的副作用。

```html
<div class="wrap"><!-- 高度塌陷：里面只有 float 子元素 -->
  <div class="item">内容</div>
</div>
```

```css
.wrap { border: 1px solid #000; }   /* 只包得住非浮动的部分 */
.item { float: left; height: 100px; }
```

> [!WARNING]
> **警告**：浮动的"脱离"有两个连带后果：**父高度塌陷**（浮动子不参与撑高）与**兄弟重叠**（后续块级元素被浮动盖住）。只要用浮动布局，就必须处理这两点，否则版式会乱。这也是"清除浮动"技法诞生的原因。



### 清除浮动

#### 清除浮动的原理

**清除浮动（Clearing）**：目的是**结束浮动对后续布局的影响**——让父容器正确包裹浮动的子元素，或让后面的元素不再被浮动盖住。

- **clear**：作用于某元素，left/right/both 表示"该元素前面不允许有浮动元素"，从而把它**推到浮动元素下方**（另起一行并让父容器把浮动也算进高度）。
- clear: both 最常用，兼顾左右两侧浮动。
- 清除只影响**设置了 clear 的那个元素之后**的布局，不改变已浮动元素本身。

```css
.clearfix::after {
  content: "";
  display: block;   /* 或 table */
  clear: both;      /* 把伪元素放到浮动下方，父容器因此被撑起 */
}
```

> 父塌陷的根治思路：让父容器内**存在一个处于标准流末尾的"清理者"**，它要求"前面不能有浮动"，于是被排到浮动元素下方，父容器的高度就被它撑起来了。现代实现最干净的是用 ::after 伪元素充当这个清理者（即 clearfix）。



#### clearfix 与 BFC

清除浮动有三大类实现，**BFC（块级格式化上下文）** 是最干净的方向，也是理解现代布局的钥匙。

- **clearfix（伪元素法）**：父加 ::after { clear: both }，兼容旧浏览器最广。
- **BFC 法**：让父容器**建立 BFC**（overflow: hidden、display: flow-root、float、绝对定位等），BFC 会把浮动子元素**算入高度**，从而包裹浮动——overflow: hidden 是最常用的老技巧。
- **现代推荐**：display: flow-root 专门为"触发 BFC 而不产生副作用"而生。

```css
/* clearfix：老而稳 */
.clearfix::after { content: ""; display: block; clear: both; }

/* overflow 触发 BFC：副作用是把溢出内容裁掉 */
.wrap { overflow: hidden; }

/* flow-root：为建 BFC 而生，无 overflow 的裁剪副作用 */
.wrap { display: flow-root; }
```

> 三者的取舍：clearfix 兼容最广但多一层伪元素；overflow:hidden 简单但有"裁掉溢出"的连带影响（可能切掉浮出盒外的内容）；display: flow-root 语义最纯粹、无副作用，是**现代首选**。理解 BFC 还顺带解释了很多布局现象（见层叠与 BFC 章）。



### 浮动布局的替代

#### 为什么被 flex/grid 取代

浮动最初不是为"布局"设计，用它拼列是"借力打力"，其局限在复杂布局中暴露无遗，最终被 flex/grid 取代。

- **等分与垂直对齐难**：浮动无法让列自动等高、无法垂直居中、需要手工算宽度与清除浮动。
- **顺序与换行僵硬**：列数变化、响应式重排靠 media query 重算 float 宽度，繁琐易错。
- **清除浮动负担**：每个父容器都要处理塌陷，样板代码多。
- **flex/grid 的优势**：自动分配空间、垂直/水平对齐内建、换行/顺序可控、无需清浮动。

> 一句话：**float 是"没有布局模型时代的权宜"，flex/grid 是"真正的布局模型"**。如今新代码基本不再用 float 做列布局，float 只保留给"图文环绕"这类它能胜任的原始场景。



#### 浮动的现代用途

float 在今天仍有少数**不可替代的原生价值**，主要是"文本环绕"。

```css
/* 图文环绕：插图靠左，文字环绕其右侧与下方 */
.news img { float: left; margin: 0 16px 8px 0; }

/* 首字下沉：首字母浮动放大 */
.dropcap::first-letter { float: left; font-size: 3em; line-height: 1; margin-right: 6px; }
```

- **图文环绕**：float 的招牌能力，文字会自然地环绕浮动图片，flex/grid 反而做不到"文字绕图"。
- **首字下沉 / 环绕块**：::first-letter + float 可做杂志风首字下沉。
- 少数工具场景：让某元素"靠右"且后续文本环绕，仍用 float。

> 何时仍该用 float：**需要文字/内联内容环绕某元素**（图片、引言块、首字）时，float 是无法被 flex/grid 替代的正解。除此之外的布局，一律优先考虑 flex/grid。
