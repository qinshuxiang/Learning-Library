## 层叠、继承与优先级

### 层叠的本质

#### 层叠（Cascade）的概念

**层叠（Cascade）**：是 CSS 的核心机制——当**多个来源的多个规则**都试图为**同一元素的同一属性**赋值时，CSS 依据一套优先级规则**裁决出最终生效的那个值**。样式表的名字"层叠样式表"正源于此。

- 被命中的规则不止一条，但**一个属性最终只有一个生效值**。
- 裁决顺序由**来源与重要性、选择器优先级、书写顺序**层层筛选。
- 层叠只解决"同一属性的冲突"，不决定"属性是否存在"——后者由初始值兜底。

> 一个比喻：层叠如同一场"谁能说了算"的官司，先比**身份地位**（作者/浏览器/用户 + !important），再比**精细程度**（选择器优先级），最后同分则**后到者胜**（书写顺序）。三关层层淘汰，剩者为王。



#### 层叠的决定因素

最终值的裁决按以下**优先级由高到低**依次判定，任一关分出胜负即停止。

1. **来源与重要性**：!important 的作者声明 > 普通作者声明 > 用户声明 > 浏览器默认。
2. **选择器优先级（特异性）**：来源相同时，比较命中该元素的选择器的权重。
3. **书写顺序**：来源与特异性都相同时，**后出现的声明覆盖先出现的**。

```css
/* 同来源、同特异性：后者覆盖前者 */
p { color: red; }
p { color: blue; }   /* 生效：blue */
```

> 记忆链：**作者 > 用户 > 浏览器**（!important 会把该声明整体抬到顶层，且**用户 !important 高于作者 !important**，因为用户样式要能压过作者以满足可访问性）。对开发者而言绝大多数冲突发生在"作者来源"内部，此时只比特异性和顺序两关。



### 特异性（Specificity）

#### 特异性权重的计算

**特异性（Specificity）**：量化"选择器有多具体"的权重，用 **(a, b, c)** 三元组表示，分别累计 **ID 选择器数、类/属性/伪类数、元素/伪元素数**，从高位到低位依次比较。

```css
/* 特异性计算示例 */
*          {}  /* (0,0,0) 通用选择器不计 */
li         {}  /* (0,0,1) 一个元素 */
li:first-line {} /* (0,0,2) 元素+伪元素 */
ul li      {}  /* (0,0,2) */
ul ol+li   {}  /* (0,0,3) */
h1 + *[rel=up] {} /* (0,1,1) 属性+元素 */
ul ol li.red {}  /* (0,1,3) */
li.red.level {}  /* (0,2,1) */
#x34y      {}  /* (1,0,0) 一个 ID */
```

- **比较规则**：先比 a，再比 b，再比 c，**逐位从左到右**，更高者胜；是"进位制"比较而非简单相加。
- **继承值**：不参与特异性比较，其来源"低于"任何普通声明。
- **!important**：改变"来源"层级的整体排序，但同是 !important 时仍按特异性与顺序比较。

> 特异性是一套**防"谁写得多谁赢"的精确规则**——不是加总谁大，而是逐位 PK：一个 ID（1,0,0）压过任意多个类（哪怕 (0,999,0)）依然更高位胜出。这也是"能用类就别用 ID"的结构性原因：ID 一旦介入，类就很难覆盖它。



#### 优先级记忆与常见误区

优先级在日常书写中有几条**直观排序**与常见误区需要牢记。

- **速记链**：!important > 行内样式 > ID > 类/属性/伪类 > 元素/伪元素 > 继承值。
- **行内样式**：在特异性三元组里视作**最高位再加一档**（比任何 ID 都高），只有 !important 能越过它。
- **伪类的特异性**：:hover、:nth-child()、:not() 本身按"类"计，但 :not() 的**参数**要各自计入其权重；:where() 参数不计。
- **通用选择器 ***：不计入特异性。
- **:nth-child 的括号内容**：不计权重（它属于伪类整体，按一个类计）。

> [!WARNING]
> **警告内容**：三个最易写错的坑：一是 :not(.a) 特异性 = :not 的类权重 + 参数 .a 的权重（并非只看 :not）；二是后代选择器 ul li 特异性是**相加**的 (0,0,2)，别以为深层数更多就绝对更"强"，它仍比不过一个类 (0,1,0)；三是**顺序只在特异性相同时才起作用**，低特异性写在后也赢不了高特异性写在前。



### 继承（Inheritance）

#### 继承的机制

**继承（Inheritance）**：某些属性在未显式设置时，会**从父元素继承计算值**给子元素，而非取初始值。继承让"设置一次、整片生效"成为可能。

- **可继承属性**：多为**文本外观类**，如 color、font-*、line-height、text-align、visibility、list-style、cursor 等。
- **不可继承属性**：多为**布局/几何类**，如 width、height、margin、padding、border、position、background、display 等——它们各自独立，默认取初始值。
- **层叠优先级**：继承值是**最低优先级**的样式来源，任何直接作用于元素的声明（含浏览器默认）都会覆盖继承值。

```css
body { color: #333; font-family: sans-serif; }
/* 未单独设色的段落自动继承 body 的颜色与字体 */
```

> 继承是一把双刃剑：设 body 的 color/font 能让全站统一，是**最省力的默认样式**；但想"不给某些子元素继承"时，需显式覆盖或用 all/inherit 控制。判断某属性是否可继承，最可靠是查文档标注的 **Inherited: yes/no**。



#### 控制继承的全局关键字

CSS 提供四个**全局关键字**显式控制某属性的取值来源，用于摆脱"必须手写整棵继承链"的困境。

- **inherit**：强制**取父元素的计算值**（即使是不可继承属性，也会被强制继承）。
- **initial**：强制取该属性的**初始值**（与父元素无关）。
- **unset**：若属性**可继承**则等同 inherit，否则等同 initial。
- **revert**：回退到**浏览器默认样式表**对该属性的设定（用户代理层）。

```css
input { color: inherit; }   /* 输入框文字跟父元素同色 */
button { font: inherit; }   /* 摆脱按钮默认字体，跟随父级 */
a { color: initial; }       /* 取消浏览器默认的链接色 */
```

> [!WARNING]
> **警告内容**：all: initial / all: unset 可一次性重置**所有属性**，常用于"无样式组件"或隔离场景，但要小心 all: initial 会同时把 display 等也重置成初始值（如 div 会变回 inline），需配合 display 另行指定。revert 最贴合"我不要作者样式、回到浏览器默认"的语义。



### 默认值、浏览器默认样式与 Reset

#### 浏览器默认样式表

**浏览器默认样式（User-Agent stylesheet）**：浏览器内置的一套默认规则，为每个元素定义基础外观（如 h1 加粗加大、body 有外边距、a 有下划线）。它是层叠里**最底层**的来源。

- 默认样式让"纯 HTML 不写 CSS"也能可读，但也带来**跨浏览器不一致**与"莫名间距"。
- 不同浏览器（Chrome/Firefox/Safari）的默认值存在差异，这正是需要 **Reset 或 Normalize** 的原因。

> "为什么我的页面边上有白边、标题和我预想的不同"——多半来自浏览器默认样式。它们属于"用户代理来源"，优先级极低，**任何作者声明都能覆盖**，所以不必害怕，只需用 Reset 先"清场"再自行定义。



#### Reset、Normalize 与盒模型统一

面对默认样式差异，业界有三种主流策略，取舍点在于"彻底清零"还是"保留有益默认"。

- **Reset（清零）**：把所有元素的 margin/padding 归零、去除列表符号等，追求**完全从零开始**（如 Eric Meyer Reset）。缺点是需重新定义大量本就合理的默认。
- **Normalize**：保留合理的默认值，只**统一跨浏览器的差异**（如 html 的默认行高、svg 的 overflow），不改动浏览器的合理外观（如 b 仍加粗）。
- **盒模型统一**：现代项目几乎必加 box-sizing: border-box，让 width/height 包含内边距与边框，避免尺寸反复换算。

```css
/* 精简 reset：统一盒模型 + 去内外边距（常配合 Normalize 使用） */
*,
*::before,
*::after {
  box-sizing: border-box;
  margin: 0;
  padding: 0;
}
```

> 两种方案可互补：**Normalize 提供一致性基础，再配少量自己的 Reset**（尤其 box-sizing: border-box）。Reset 追求"清空重画"，Normalize 追求"拉平差异"——多数现代工程已转向 Normalize + 盒模型统一，而非全盘清零。



#### 冲突的最终裁决示例

综合层叠三要素，看一个"谁生效"的完整例子。

```html
<div id="app">
  <p class="tip highlight">这是一段文字</p>
</div>
```

```css
p { color: gray; }                    /* (0,0,1) */
#app p { color: blue; }               /* (1,0,1) 最高，blue 胜 */
.tip { color: red; }                  /* (0,1,0) */
.highlight { color: green; }          /* (0,1,0)，与上一条同权 */
```

- 没有 !important、没有行内样式，先比来源（都是作者）→ 再比特异性 → #app p 的 (1,0,1) 最高，故最终 **blue**。
- 若去掉 #app p，则在 .tip 与 .highlight（同为 (0,1,0)）之间由**书写顺序**决定，后者 .highlight 生效（green）。
- 若给 .tip 的声明加 !important，则它压过 #app p 的普通声明，生效 red。

> 实战判断顺序口诀：**先看有没有 !important → 再看是否行内 → 再算特异性三元组 → 相同则比谁写在后面**。按此四步推理，任何冲突都能得出确定答案，不必靠"试"。
