## 语义化与文档大纲

### 语义化的意义

#### 语义化 HTML 的定义与价值

**语义化（Semantic HTML）**：用能表达内容含义的标签组织文档，让结构自解释，而非一律用 div 加样式模拟。

- 语义化让机器（浏览器、搜索引擎、屏幕阅读器）理解页面各部分的作用。
- 它提升可访问性、SEO、可维护性，是现代前端的基础素养。
- 反例是无语义的 div 嵌套（俗称 div 汤），机器无从判断内容角色。

> [!IMPORTANT]
> 重要内容：语义化不是给 div 起个名，而是选择真正表达内容角色的标签。用户能否用屏幕阅读器快速跳转到"导航、正文、页脚"，取决于这些区块是否用了对应语义元素。

#### 语义对可访问性、SEO 与维护的意义

- 可访问性：语义元素（nav、main、button 等）自动产生可被辅助技术识别的角色与导航点。
- SEO：搜索引擎依据标题层级、链接、结构化语义理解主题与权重。
- 维护：语义清晰的文档让后来的开发者秒懂结构意图。

> 一句话：语义化同时服务三拨"读者"——用屏幕阅读器的用户、搜索引擎的爬虫、以及半年后回来看代码的你。



### 分节与结构元素

#### 页面级结构：header、main、footer

现代 HTML5 提供描述页面骨架的分节语义元素。

- **header 元素**：区块的页眉，常含站点标题、logo、导航，可出现在页面与各 article/section 顶部。
- **main 元素**：页面主要内容，一个页面一般只有一个 main，不含侧边栏与站点级重复内容。
- **footer 元素**：区块的页脚，常含版权、联系方式、站点链接，可出现在页面与各区块底部。

```html
<body>
  <header>站点标题与导航</header>
  <main>页面主体内容</main>
  <footer>版权与联系信息</footer>
</body>
```

> [!IMPORTANT]
> 重要内容：main 每页仅一个，且不应嵌套在 article、aside、footer、header、nav 内部。它是文档的"主内容"标志，屏幕阅读器与浏览器可据此实现"跳到主内容"的功能。

#### 内容区块：article、section、nav、aside

四个分节元素用于组织文档内容区块，各自语义不同。

- **article 元素**：独立的、可单独分发或复用的内容（一篇文章、一条评论、一个组件）。
- **section 元素**：按主题划分的内容区块，通常含一个标题。
- **nav 元素**：主要导航链接的区块。
- **aside 元素**：与主体相关但相对独立的内容（侧栏、注释、广告、相关链接）。

```html
<article>
  <h2>一篇独立文章</h2>
  <p>文章正文…</p>
  <section>
    <h3>小节标题</h3>
    <p>小节内容…</p>
  </section>
</article>
<aside>
  侧栏：相关文章推荐
</aside>
```

> [!WARNING]
> 警告内容：不要为了"让元素更有语义"而滥用——一段普通文字硬塞进 article，或用 section 包没有主题的碎片，反而不如朴素的 div。article 强调独立完整、section 强调同主题分组、div 是纯无语义容器，三者按需选用。

#### section 与 div、article 的取舍

选择用哪个容器，核心看内容是否有语义归属。

- 内容成主题、结构上应进文档大纲 → section。
- 内容独立可复用 → article。
- 仅需包裹以加样式或脚本 → div。

> [!TIP]
> 建议内容：拿不准就先用无语义的 div，别为了语义而语义。section 一般要有标题才名副其实；纯粹为布局包裹而加 section 会稀释大纲，反成噪音。判断是否用 section：去掉标题后这个区块是否还有独立的主题含义。



### 标题与文档大纲

#### 正确使用 h1-h6

标题的正确使用是文档大纲健康的根本。

- 一页一个主标题（通常 h1），其余按层级 h2 到 h6。
- 标题嵌套应反映内容嵌套，不跳级。
- 不用标题来"设置字号"，字号是 CSS 的事。

> 大纲 = 标题的层级集合。搜索引擎与辅助技术常据 h1-h6 生成目录与跳转菜单，标题即"内容目录"。

#### 大纲算法与现代实践

早期的 HTML5 大纲算法（用 section 影响大纲）并未被浏览器与辅助技术采纳，现代实践回归以标题层级为主。

- 实际生效的是"h1-h6 层级 + 隐式/显式标题归属"。
- 不要指望把多个 h1 放进不同 section 就能构造多级大纲——主流辅助技术仍按 h1-h6 次序理解。
- 规范写法：全页一个 h1，后续按层级推进。

> [!NOTE]
> 提醒内容：别依赖"section 内可再用 h1"的旧想法。可靠做法是保持全文档 h1 唯一，标题层级随内容自然递进（h1→h2→h3），这既是 SEO 惯例也是辅助技术实际解析方式。



### 语义化综合实践

#### 典型页面的语义骨架

把结构元素与标题组合，可搭出一份语义清晰的页面骨架。

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <title>示例文章页</title>
</head>
<body>
  <header>
    <h1>我的博客</h1>
    <nav><a href="/">首页</a><a href="/about">关于</a></nav>
  </header>
  <main>
    <article>
      <h2>一文读懂语义化</h2>
      <p>正文…</p>
    </article>
    <aside>相关阅读</aside>
  </main>
  <footer>
    <small>© 2026</small>
  </footer>
</body>
</html>
```

> 这份骨架同时回答了"页面分几部分、每部分是什么、标题层级如何"三个问题，机器与人都能顺畅理解。

#### 语义化自查清单

写完一页可快速自查：

- 页面主体用 main 包裹，且全页唯一。
- 导航用 nav，正文用 article 或按主题的 section。
- 页眉页脚用 header/footer，侧栏用 aside。
- 标题层级连续、h1 唯一。
- 普通文字、行内强调各用对应语义（p、strong、em 等）。

> 自查通过即基本达标。后续可用 axe、Lighthouse 等工具量化可访问性与 SEO 分数，进一步校准。
