## 内容分类与嵌套规则

### 内容模型的概念

#### 为什么 HTML 有内容分类

HTML 规范并非允许任何元素随意嵌套任何元素，而是依据**内容模型（Content Model）**规定每种元素能容纳哪些内容。理解分类是写出合法文档的前提。

- 每种元素对其内部可放的子元素有约束，浏览器据此确定哪些写法合法。
- 非法嵌套浏览器未必报错（会容错），但会导致结构异常、样式失效、可访问性受损。
- HTML5 用一套分类体系（flow、phrasing 等）取代 HTML4 时代简单的"块级/行内"二分。

> [!NOTE]
> 提醒内容：内容模型是规范层面的"法律"，浏览器容错只是无奈兜底。写标签前想一下"这个元素里能放什么"，能避免大量隐性 bug。

#### HTML5 的七类内容分类

HTML5 把元素按可容纳关系归入若干内容分类，元素可同时属于多类。

- **元数据内容**：描述文档自身的元素，如 head 里的 link、meta、title、style。
- **流式内容（flow content）**：主体中最常见的元素集合，如 p、div、h1-h6、table、form、img 等。
- **标题内容（heading content）**：h1 到 h6、hgroup。
- **分节内容（sectioning content）**：可构成大纲独立区块的元素，如 article、aside、nav、section。
- **短语内容（phrasing content）**：构成段落的行内元素，如 a、span、strong、img、em 等。
- **嵌入内容（embedded content）**：引入外部资源，如 img、video、canvas、iframe、svg。
- **交互内容（interactive content）**：用户可交互的元素，如 a、button、input。

> 分类的意义：元素的"父级能放什么"由父级内容模型决定，"能当什么子级"由子元素所属分类决定。



### 流式与短语内容

#### 流式内容与短语内容的关系

**流式内容**大致对应"块级"，**短语内容**大致对应"行内"，但 HTML5 的定义更精确、允许更灵活。

- 大多数流式元素内部可再放流式内容（容器性质）。
- **短语内容**：文本及行内级元素。凡允许短语内容的位置通常也允许流式内容，但反之未必。
- 一个常见约束：**p 元素内只允许短语内容**，不能放 div、ul 等块级容器。

```html
<!-- 合法：p 内放行内短语内容 -->
<p>这是<strong>一段</strong>文本。</p>

<!-- 不合法：p 内套 div 块级 -->
<p>文字<div>这会破坏结构</div>结束</p>
```

> [!WARNING]
> 警告内容：p、h1-h6 等标题与段落元素内部只接受短语（行内）内容。把 div、section、ul 直接放进 p 或标题内是非法嵌套，浏览器会强制把内部块级元素"踢出" p，打乱文档结构。

#### 块级与行内概念的演进

HTML4 的"块级 block 与行内 inline"二分在现代 HTML5 已被内容分类取代，但旧概念仍常被口头沿用。

- 旧"块级"大致对应新流式/分节类，旧"行内"大致对应短语类。
- 显示上的块级/行内最终由 CSS 的 display 决定，与 HTML 语义分类不完全等同。

> 理解演进：不必再死记"某元素是块还是行内"，而应问"该元素属于哪类内容、允许放进什么父级"。CSS 负责显示排布，HTML 分类负责结构合法性。



### 常见元素的合法嵌套

#### 容器与列表的嵌套约束

容器类元素相对宽松，列表与表格有自己的严格子元素规则。

- div、main、section 等可容纳流式内容，包容性强。
- ul、ol 的直接子元素只能是 li（可含脚本模板元素）。
- dl 的直接子元素是 dt 与 dd 的组。
- table 的直接子元素为 caption、colgroup、thead、tbody、tfoot、tr 等表格结构元素，不能直接放任意块级。

```html
<ul>
  <li>合法</li>
</ul>

<table>
  <tr><td>合法：tr 直接作为 table 子级</td></tr>
</table>
```

> 表格与列表对直接子级要求严格（table 内不能直接放 p，ul 内不能直接放 div），违反时浏览器会插入隐式节点或移位，使预期结构失效。

#### a 元素可包裹内容的边界

HTML5 放宽了 a 的嵌套，允许其包裹较大范围内容，但仍有限制。

- a 内不能嵌套另一个 a。
- a 属于交互内容，通常只含短语内容；规范允许部分流式内容但要求其内无交互内容。

```html
<!-- 卡片式链接：a 包裹块级排版内容 -->
<a href="/article/1" class="card">
  <h3>文章标题</h3>
  <p>文章摘要内容…</p>
</a>
```

> [!WARNING]
> 警告内容：a 内不能再放 a（否则哪个链接生效产生歧义），也不能把 button、input 等本身可交互的元素塞进 a，会造成交互嵌套冲突。卡片链接若内部需放按钮/链接，应改为结构拆分加 JS 的点击处理。

#### 内联元素的限制

行内级（短语）元素通常不可包含块级元素，但可嵌套同属短语的元素。

- a、span、strong、em 等可互相嵌套（短语内容内允许短语内容）。
- 例外：个别短语元素（如 a、button）自身不能嵌套同为交互的元素。

> 规则口诀：行内元素套行内元素一般可以，行内元素套块级元素一般不行；交互元素彼此不能嵌套。把握这两点可避开绝大多数嵌套错误。



### 合法性与实践

#### 用工具校验 HTML

避免隐性结构错误的可靠办法是使用校验工具。

- W3C 官方 Markup Validation Service（validator.w3.org）可检查合法性。
- 打包构建工具（如 html-validate）与编辑器插件也能在开发期提示错误。
- 浏览器的 Elements 面板能看出浏览器容错后实际形成的结构。

> [!TIP]
> 建议内容：写复杂页面后用校验器过一遍，能发现肉眼难查的嵌套与闭合问题。把它纳入构建流程（CI），可防止结构错误流入线上。

#### 结构合法性的实践收益

坚持合法嵌套带来的回报是多方面的。

- 样式稳定：CSS 选择器与布局不会被意外打乱。
- 脚本可靠：document 遍历与查询结果符合预期。
- 可访问性：屏幕阅读器对结构语义的解析更准确。
- SEO：搜索引擎对清晰的语义结构更友好。

> 一句话：内容分类与合法嵌套不是束缚，而是让 HTML 文档"确定、可预期"的保证。先合法，再谈样式与交互。
