## 文档结构、head 与元信息

### 根元素与文档头部

#### html 根元素

**html 元素**：是 HTML 文档的最外层根元素，包裹整个文档，文档中所有其他元素都是其后代。

- html 元素有且仅有一个，位于 <!DOCTYPE html> 之后。
- 通常为 html 设置 lang 属性，声明页面主要语言，利于屏幕阅读器与搜索引擎理解内容。
- 现代 HTML5 中 head 与 body 元素可省略书写（浏览器会隐含补全），但显式写出更清晰。

```html
<!DOCTYPE html>
<html lang="zh-CN">
  <!-- head 与 body 是 html 的两大直接子元素 -->
</html>
```

> [!IMPORTANT]
> 重要内容：lang 属性直接决定浏览器拼写检查、屏幕阅读器发音与搜索引擎语言识别。中文页面应写 lang="zh-CN"，不要遗漏或误写为它语。

#### head 与 body 的分工

**head 元素**：承载文档元数据（metadata），即描述文档自身的信息，其内容默认不显示在页面主体。

**body 元素**：承载页面所有可见内容，是用户最终看到的全部界面。

- head 放在 body 之前，浏览器先读取元信息（字符集、视口、标题、样式表）再渲染主体。
- head 内不放可见内容；把文本直接写进 head 是不符合结构的做法，会被移出或忽略。

> [!NOTE]
> 提醒内容：判断一个元素该放 head 还是 body，就看它是否产生可见渲染——可见内容进 body，只影响解析与元信息的内容进 head。



### head 中的核心元素

#### title 文档标题

**title 元素**：定义文档标题，显示在浏览器标签页、收藏夹与搜索引擎结果标题中，是 head 中必备的核心元素。

```html
<head>
  <title>学习 HTML —— 前端入门笔记</title>
</head>
```

- 标题应简洁、准确地概括页面内容。
- 搜索引擎与社交分享都以 title 作为主要标题来源，具有 SEO 价值。

> [!TIP]
> 建议内容：title 宜控制在约 30 个中文字符内，把最重要的关键词前置。每个页面应有唯一且贴合内容的 title，不要全站共用同一句。

#### meta 元信息

**meta 元素**：以键值对形式描述文档的元数据，是 head 中最灵活、最常用的元素之一。常见用途如下。

- 字符集声明 charset 属性为 UTF-8 的 meta 元素：声明文档编码，避免中文乱码。
- 视口设置 name 属性为 viewport 的 meta 元素（content 写 width=device-width 与 initial-scale=1）：适配移动端。
- 描述 name 属性为 description 的 meta 元素：供搜索引擎在结果中显示摘要。
- 作者与关键词 name 属性为 author 的 meta 元素、name 属性为 keywords 的 meta 元素：keywords 已被搜索引擎普遍忽略。
- 主题色 name 属性为 theme-color 的 meta 元素：控制移动端浏览器地址栏颜色。

```html
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <meta name="description" content="系统学习 HTML 的笔记，覆盖结构、表单、语义化等">
  <meta name="theme-color" content="#3366cc">
  <title>学习 HTML</title>
</head>
```

> [!IMPORTANT]
> 重要内容：字符集声明必须位于 head 的最前部（HTML5 规范要求在文件开头 1024 字节内），且与文件实际编码一致（统一 UTF-8）。声明过晚或与保存编码不符都会导致乱码。

#### http-equiv 与 CSP

部分 meta 通过 http-equiv 模拟 HTTP 响应头，在无法修改服务器响应头时发挥作用。

- http-equiv 属性为 refresh 的 meta 元素（content 写秒数与跳转目标）：定时刷新或跳转（有滥用风险，慎用）。
- http-equiv 属性为 X-UA-Compatible 的 meta 元素：已过时，仅历史遗留。
- http-equiv 属性为 Content-Security-Policy 的 meta 元素：为页面设置内容安全策略（CSP）。

> [!WARNING]
> 警告内容：http-equiv 属性为 refresh 的 meta 元素，其自动跳转会影响可访问性与 SEO，且被用于恶意跳转，现代项目应避免，改用服务端响应头或脚本跳转。CSP 用 meta 生效晚于响应头，仅作补充。



#### link 关联外部资源

**link 元素**：在 head 中声明文档与外部资源的关系，最常见的是引入样式表与网站图标。

- rel 属性为 stylesheet 的 link 元素：引入 CSS 样式表。
- rel 属性为 icon 的 link 元素：设置网站图标。
- rel 属性为 canonical 的 link 元素：声明页面的权威地址，避免重复内容（详见 SEO 章）。
- rel 属性为 preload 的 link 元素（as 属性声明资源类型）：提前加载关键资源（详见性能章）。
- rel 属性为 preconnect 的 link 元素：提前与第三方源建立连接。

```html
<head>
  <link rel="stylesheet" href="./css/main.css">
  <link rel="icon" href="./favicon.svg" type="image/svg+xml">
</head>
```

> [!NOTE]
> 提醒内容：rel 的值决定 link 的用途，href 指向目标地址。一个页面可引入多个样式表，按书写顺序依次应用（层叠规则见 CSS 目录）。

#### style 内联样式

**style 元素**：在文档内直接书写 CSS 样式，用于小型页面或组件内样式。

```html
<head>
  <style>
    body { font-family: system-ui; }
    .highlight { color: #d00; }
  </style>
</head>
```

- 内联样式不利于缓存与复用，生产级项目更推荐外链样式表。
- 现代工程借助打包工具将组件样式编译后注入或外链。

> [!TIP]
> 建议内容：把样式拆到独立 .css 文件可被浏览器缓存、在多页复用；style 内联适合单页演示或首屏关键样式。工程化与样式组织详见 CSS 目录相关章节。

#### script 与 base

**script 元素**：在 head 或 body 中引入或内联 JavaScript（加载时序详见性能章）。

**base 元素**：为文档内所有相对 URL 设置基准地址，使用需谨慎。

```html
<head>
  <base href="https://example.com/docs/">
  <!-- 其后相对链接都相对该基准解析 -->
</head>
```

> [!WARNING]
> 警告内容：base 会改变整篇文档相对链接的解析基准，一处误设会让所有相对路径失效。除非确有必要，一般建议不用 base，而用完整的相对或绝对路径。



### 元数据对页面形态的影响

#### viewport 与移动适配

viewport 元信息控制页面在移动设备上的视口行为，是响应式网页的起点。

- width=device-width：让视口宽度等于设备屏幕宽度，而非默认的桌面宽度。
- initial-scale=1：初始缩放比例为 1，避免被放大。
- 不设 viewport 的页面在手机上会被按约 980px 宽的桌面视口缩小显示，需手动缩放。

> [!IMPORTANT]
> 重要内容：面向移动端的页面应始终在 head 中设置 viewport meta。viewport 需配合响应式 CSS（媒体查询等）才能实现真正的移动适配，二者共同作用。

#### 元信息与社交分享、SEO

head 中的 title 与各类 meta 共同决定页面在搜索引擎、社交平台的呈现。

- 搜索引擎：依据 title、description、语义化结构与链接等建立索引。
- 社交分享（Open Graph、Twitter Card）：通过专用 meta 控制链接被分享时的标题、摘要与预览图（详见 SEO 章）。

> 一份规范的 head 元信息，是页面在"机器视角"下是否专业的最直接体现，也是 SEO 与可访问性的根基。
