## 剪贴板、拖放与编辑

### 剪贴板 API

#### 读写剪贴板

**Clipboard API**：允许脚本读写系统剪贴板。现代接口为异步、基于 Promise，且受权限与用户手势约束。

```js
// 写入
await navigator.clipboard.writeText("要复制的内容");

// 读取
const text = await navigator.clipboard.readText();
```

- writeText(text) 写入纯文本；write() 可写入多类型数据。
- readText() / read() 读取剪贴板。
- 读取通常要求用户授权；写入多要求处于用户手势上下文（如点击事件里）。

> [!WARNING]
> 警告内容：剪贴板 API 的读取受严格权限控制——脚本不能在无用户手势与授权下静默读取剪贴板（防恶意窃取）。调用应在用户交互内进行，并捕获可能的权限错误。

#### 传统 document.execCommand 与 fallback

旧式复制依赖 document.execCommand("copy")，兼容旧浏览器但仍存留。

- 传统做法：创建一个临时 textarea，选中其文本，执行 execCommand 复制后移除。
- execCommand 已废弃，但仍在部分旧环境作为兜底。

> 优先级：优先异步 Clipboard API；需要更广兼容时可保留 execCommand 兜底。读取剪贴板权限较紧，非必要时不必实现读取。

#### 复制富内容与图片

除纯文本外，剪贴板还能复制多类型内容（HTML、图片等）。

- write() 接收 ClipboardItem 数组，每项含 MIME 类型到数据的映射。
- 复制富文本时同时提供 text/plain 与 text/html，粘贴端择优。
- 图片可用 fetch 拉取转 Blob 后写入。

```js
await navigator.clipboard.write([
  new ClipboardItem({
    "text/plain": new Blob(["示例文本"], { type: "text/plain" }),
    "text/html": new Blob(["<b>示例</b>"], { type: "text/html" })
  })
]);
```

> 复制到 Office/富文本编辑器时，同时提供 text/html 与 text/plain 可让格式与纯文本都有合适呈现。现代浏览器对 ClipboardItem 支持已较普遍。



### 拖放 API

#### 拖放事件流程

HTML5 拖放（Drag and Drop）允许拖拽元素/文件到放置区。流程由一系列事件驱动。

- 拖拽源侧：dragstart（开始）、drag、dragend（结束）。
- 放置目标侧：dragenter（进入）、dragover（悬停，需 preventDefault 以允许放置）、dragleave（离开）、drop（放置）。

```html
<div id="drop" style="min-height:80px;border:2px dashed #999">拖放到这里</div>
<script>
  const zone = document.getElementById("drop");
  zone.addEventListener("dragover", (e) => e.preventDefault());
  zone.addEventListener("drop", (e) => {
    e.preventDefault();
    console.log(e.dataTransfer.files);
  });
</script>
```

- 允许放置的关键：在 dragover 中调用 preventDefault。
- dataTransfer 承载被拖的数据与文件。

> [!IMPORTANT]
> 重要内容：放置区必须监听 dragover 并 preventDefault，否则 drop 事件不会触发（浏览器默认禁止放置）。drop 里同样要 preventDefault 阻止浏览器默认打开文件的跳转。

#### dataTransfer 与文件拖放

**dataTransfer 对象**：拖放过程中携带的数据容器。

- 设置：dragstart 中用 setData(type, data) 写入。
- 读取：drop 中用 getData(type) 读出。
- 文件：dataTransfer.files 提供被拖入的本地文件。

```js
// 拖拽源写入
document.getElementById("src").addEventListener("dragstart", (e) => {
  e.dataTransfer.setData("text/plain", "拖拽数据");
});
```

> 文件拖放上传常配合 dataTransfer.files 读取 FileList，再经 FormData 上传——与 input type="file" 的读取殊途同归。拖放是"无选择框"上传的常见交互。

#### 原生拖拽与 HTML5 拖放的取舍

HTML5 拖放（拖 DOM 元素排序）实现较繁琐；现代排序更多用指针事件与库。

- 拖文件进网页：HTML5 拖放 API 稳定实用。
- 拖 DOM 元素重排：HTML5 drag 事件交互感有限，常改用 Pointer Events 或排序库（SortableJS）。

> 建议：文件拖放用原生 API；列表拖拽排序用现代指针方案或成熟库，避免原生 drag 事件的粗糙体验与移动端兼容问题。



### 内容编辑

#### contenteditable 与富文本编辑

**contenteditable 属性**：让元素可被用户编辑，是富文本编辑器的基础。

```html
<div contenteditable="true">
  点击这段文字即可编辑。
</div>
```

- 可编辑区域的输入、光标、格式由浏览器原生处理。
- 用 document.execCommand 可执行加粗、斜体、插入链接等（已废弃但仍常用作底层）。
- 生产富文本编辑器通常基于 contenteditable，或用 contenteditable 加现代 API。

> [!NOTE]
> 提醒内容：contenteditable 编辑出的 HTML 往往包含浏览器注入的杂标签，且 execCommand 已废弃。生产环境请优先采用成熟编辑器库（Quill、TipTap/ProseMirror 等）封装，它们处理了光标、格式、粘贴清理等复杂细节。

#### 可编辑内容的获取与限制

对 contenteditable 区域，可用 contenteditable="plaintext-only" 限制为纯文本。

- 读取内容：innerText / textContent（纯文本）或 innerHTML（含格式）。
- 限制纯文本：contenteditable="plaintext-only" 可避免粘贴时带入富格式。
- 编辑结束时需清理内容、约束长度。

> 若只需"可编辑文本"而不要富格式，plaintext-only 或 textarea 更合适——真正需要富文本才用 contenteditable 加编辑器库。

#### execCommand 的现状与替代

**document.execCommand**：曾用于富文本格式命令的接口，已被标记废弃。

- 支持加粗、斜体、插入链接、撤销等命令。
- 行为跨浏览器不一致、难预测，规范已不推进。
- 现代替代：Clipboard API、Selection API、Contenteditable 规范化的编辑能力仍演进中，实践中以编辑器库为最稳妥选择。

> 新项目避免直接依赖 execCommand；维护旧代码时理解其命令可作过渡。富文本需求一律评估使用成熟编辑器库。



### 综合实践

#### 文本复制按钮的完整示例

综合复制到剪贴板并反馈，给出可运行示例。

```html
<button id="copy">复制链接</button>
<script>
  document.getElementById("copy").addEventListener("click", async () => {
    try {
      await navigator.clipboard.writeText("https://example.com");
      alert("已复制");
    } catch {
      alert("复制失败");
    }
  });
</script>
```

- 复制在点击事件（用户手势）内进行，权限与成功率高。
- 捕获异常给用户反馈，而非静默失败。

> 复制交互要点：用户手势内调用、成功/失败都给反馈。此模式可复用于邀请链接、订单号等复制按钮。

#### 无障碍与安全注意

剪贴板、拖放、编辑功能都有安全与无障碍考量。

- 复制操作对触屏与键盘用户都应可达（按钮即可，不需悬停）。
- 拖放不应是上传/移动的唯一途径，同时保留文件选择或按钮入口。
- 编辑区域需能被键盘操作与聚焦，与可访问性原则一致。

> 每条交互路径都应提供替代方式：拖放之外有选择框、编辑之外保持按钮式修改入口。这样既不排他，也提升可访问性与移动端体验。
