## HTML 的历史与标准演进

### HTML 的早期历史

#### 从 HTML 到 HTML4

HTML 起源于 1990 年代初的科学研究场景，随 Web 普及历经多次版本迭代。

- **HTML 1.0 / 2.0**：早期由 Tim Berners-Lee 提出，定义基本文本标记与超链接。
- **HTML 3.2（1997）**：W3C 推动标准化，加入表格、图片、表单等更丰富元素。
- **HTML 4.01（1999）**：成熟的经典版本，强调结构与表现分离，广泛使用，持续十余年。

> 这一时期的典型形态是"用 table 排版、内联大量样式"的早期网页。HTML 4 已开始引导用 CSS 代替表现性标签，但实践中仍有许多表现标签。

#### XHTML 与表观分裂

在 HTML4 之后，Web 标准化走过一段强调"严格 XML"的岔路。

- **XHTML 1.0（2000）**：把 HTML 用 XML 语法重写，要求严格闭合、小写、属性加引号。
- XHTML 严格约束未被主流采纳，XML 语法的严格性让开发者无所适从。
- 浏览器为兼容旧网页仍宽容解析，形成"书写与解析"的双轨。

> [!NOTE]
> 提醒内容：XHTML 的"严格化"尝试最终让位于更务实的 HTML5。理解这段历史有助于明白为何现代 HTML 语法宽松（浏览器容错），又为何仍需规范书写（避免依赖容错）。

#### 标准化分裂与 WHATWG 的诞生

2004 年前后，W3C 的方向（XHTML2）与浏览器厂商现实需求严重脱节，催生了新组织。

- 浏览器厂商不满 W3C 推进缓慢、脱离实际，另组 **WHATWG**（Web Hypertext Application Technology Working Group）。
- WHATWG 主张务实的"向后兼容的 HTML"，提出 Web Applications 1.0 等工作。
- 此间 HTML5 作为对 XHTML2 的替代方案逐渐成型。

> WHATWG 的成立是 Web 标准化史上关键转折：它把标准拉回"浏览器真实实现、向后兼容"的轨道，奠定了现代 HTML 的治理模式。



### HTML5 与标准治理

#### HTML5 的诞生与特性

**HTML5**：自 HTML4 之后的一次重大版本迭代，实质是 HTML 走向现代应用平台的分水岭。

- 新增大量语义元素：header、nav、main、article、section、aside、footer。
- 原生多媒体：video、audio、canvas、SVG 内联。
- 表单增强：新 input 类型、约束验证。
- 存储与通信：localStorage、WebSocket、history API 等（配合 JS）。
- 明确把 Web 从"文档"扩展为"应用平台"。

> [!IMPORTANT]
> 重要内容：HTML5 与其说是一次版本号更新，不如说是对"HTML 能做什么"的重新定义——从描述文档扩展到支撑富交互应用，语义元素、多媒体、离线与存储能力在此全面落地。

#### 从"版本"到 Living Standard

HTML 的治理从"分版本发布"转向"持续演进"，这是理解现代标准形态的关键。

- W3C 曾发布 HTML 5.0、5.1、5.2 等快照。
- 后 W3C 与 WHATWG 达成协议，HTML 以 **HTML Living Standard** 形式由 WHATWG 持续维护。
- 不再等"下一版大版本"，而是按需持续加入成熟特性。

> 现状：HTML 是一个"活的规范"，每月持续更新；现代浏览器不断跟进增量特性。开发者不必等"HTML6"，而应关注具体特性的浏览器支持。

#### WHATWG 与 W3C 的角色

今天的 HTML 标准治理是两大组织的分工。

- **WHATWG**：维护 HTML Living Standard（规范事实来源）。
- **W3C**：维护相关 Web 技术标准与建议书，与 WHATWG 协作。
- 其它模块（如 DOM、CSS、SVG）各有负责的标准组织。

> 查阅规范优先级：HTML 具体语义查 WHATWG 的 HTML Living Standard；CSS 查 CSSWG/WHATWG；DOM、Web API 各归其位。MDN 是对开发者最友好的权威文档入口。



### HTML 兼容性与演进特点

#### 宽容解析与怪异模式

浏览器对 HTML 的宽容解析既有历史成因，也是兼容性的保证。

- 早期网页不规范，浏览器为稳定渲染而自主纠错，形成"宽容解析"。
- <!DOCTYPE html> 触发标准模式；缺失时进入怪异模式（旧 IE 兼容行为）。
- 宽容是"允许错误网页可用"，但规范书写仍是正确之选。

> [!WARNING]
> 警告内容：怪异模式会沿用旧的非标准盒模型与布局规则，导致现代 CSS 表现异常。务必在文档首行写 <!DOCTYPE html> 以进入标准模式，这也是最基础却最常被忽视的"现代"开关。

#### 废弃元素与表现性标签

HTML5 起废弃了一批表现性元素，交由 CSS 承担视觉职责。

- 已废弃的表现元素：font（字体）、center（居中）、marquee（滚动）、strike（删除线）等。
- 部分元素虽保留但语义或用法变化（如 b、i 的重新定义）。
- 旧属性（align、bgcolor、border 于部分元素）同样移入 CSS 范畴。

> 遇到旧代码中的 font、center、marquee 等，应改写为语义元素加 CSS。保持"HTML 只管结构与语义、样式交给 CSS"是现代铁律。

#### 向后兼容与渐进增强

HTML 的发展始终坚持向后兼容，新特性以渐进方式普及。

- 旧特性不轻易移除，保证历史网页可访问。
- 新元素/特性按浏览器支持逐步采用。
- 渐进增强与优雅降级是面向不同浏览器的策略。

> 学习启示：写 HTML 应基于"现代浏览器默认支持"的成熟特性，必要时用特性检测与回退处理边缘浏览器，而非一味追新或用最高级特性不顾兼容。



### 历史对我们的启示

#### HTML 演进的规律

回望 HTML 历史，可提炼几条规律。

- 治理从"机构主导"转向"厂商与标准协作、持续演进"。
- 语法从宽松走向"宽容但规范"。
- 职责从"表现混排"走向"结构、表现、行为三层分离"。
- 平台从"文档"走向"应用"。

> 这几条规律解释了现代 HTML 为何如此设计，也是判断"某元素/写法是否该用"的方法论依据。

#### 面向未来：关注什么

展望 HTML 的持续演进，可关注稳定成形的方向。

- 原生交互组件（dialog、popover、自定义元素）继续补强平台能力。
- 各新特性以 Living Standard 形式渐进落地。
- 关注 caniuse 与 MDN 的浏览器支持表，评估采用时机。

> 一句话总结：HTML 早已不是"静态文档标记"，而是一个持续演进、支撑现代应用的原生平台。以 Living Standard 的视角学习，紧跟成熟特性，是最可持续的方式。更多延伸可看下一章参考资料。
