## 字符编码与实体

### 字符集与编码

#### 编码的概念与乱码成因

**字符编码**：把人类字符映射为计算机二进制数字的规则。HTML 文档在保存与传输时都依赖字符编码，编码不一致就会出现乱码。

- 字符（如汉字"中"）先被映射为码点（Unicode 编号），再被编码为字节序列。
- 浏览器需知道文档用什么编码，才能把收到的字节还原成字符。
- 编码声明与文件实际编码不符，是乱码的最常见原因。

> [!IMPORTANT]
> 重要内容：乱码的根源几乎都是"编码不一致"——文件用 A 编码保存，却告诉浏览器按 B 编码解读。现代实践统一使用 UTF-8 编码保存与声明，即可根治绝大多数乱码。

#### 常见编码与 UTF-8 的主导地位

历史上曾有多种编码，现今 UTF-8 已成事实标准。

- ASCII：最早的西文编码，仅 128 字符，不含中文。
- 各种本地编码：如西欧的 Latin-1、中文的 GBK/GB2312，各自覆盖特定语言，跨语言易乱码。
- **UTF-8**：对全 Unicode 字符的变长编码，ASCII 兼容，是 Web 的主流选择，也是规范默认。
- UTF-16：另一种 Unicode 编码，内部处理常见，但 Web 传输主流仍是 UTF-8。

> 结论：新文档一律用 UTF-8 保存并在 HTML 声明 charset="UTF-8"。这是兼容性最好、最不易乱码的方案，也是 HTML 规范推荐的默认。

#### 声明字符集的方式

浏览器通过多种途径得知文档编码，HTML 内的声明是关键之一。

- 在 head 最前写 <meta charset="UTF-8">（推荐且必须尽早出现）。
- HTTP 响应头可带 charset（如 Content-Type: text/html; charset=utf-8），优先级通常高于 meta。
- 通过 BOM（字节顺序标记）也可能推断编码。

```html
<head>
  <meta charset="UTF-8">
  <title>中文标题</title>
</head>
```

> [!WARNING]
> 警告内容：meta charset 应在文档前 1024 字节内出现（规范要求置于文件开头附近），否则浏览器可能先用错误的默认编码解析前段内容再回头修正，造成首屏局部乱码。HTTP 响应头指定的编码优先于 meta，二者应保持一致。



### 实体（字符引用）

#### 为什么需要实体

某些字符在 HTML 源码中有特殊含义，直接书写会被浏览器误解析，此时须用**实体（字符引用）**表示。

- 小于号 < 会被当成标签起始，直接写在正文中会破坏解析。
- 与号 & 是实体的起始符号，正文中孤立的 & 可能被误读为实体开头。
- 部分字符键盘不便输入或需明确指定，也可用实体表达。

> 三条铁律：正文要显示 < 写 &lt;，显示 > 写 &gt;，显示 & 写 &amp;。属性值中涉及引号时也可能需要对应实体。

#### 常用实体的写法

实体有两种形式：命名实体（易记）与数字实体（通用）。

- 命名实体：&lt; 小于、&gt; 大于、&amp; 与、&quot; 双引号、&apos; 单引号、&nbsp; 不间断空格、&copy; 版权号、&reg; 注册商标。
- 数字实体：&#数字;（十进制）或 &#x十六进制;（十六进制），如 &#169; 或 &#xA9; 表示版权号，可表示任意 Unicode 字符。
- 实体都以 & 开头、分号 ; 结尾。

```html
<p>使用 &lt;p&gt; 表示段落。</p>
<p>AT&amp;T 公司</p>
<p>版权符号 &copy; 也可写作 &#169;</p>
```

> [!NOTE]
> 提醒内容：现代中文页面真正需要实体的场景不多——除 <、>、& 等在正文中可能被误解析的字符外，版权号、不间断空格等可直接用命名实体或对应字符本身。为可读性，能用字面字符表达的优先字面字符。

#### 不间断空格与常见误区

部分实体（尤其 nbsp）常被误用，需注意其正确用途。

- &nbsp; 是不间断空格，其内的空格不会断行，用于避免词被行尾拆开。
- 反复用 &nbsp; 制造间距是错误做法——间距应交给 CSS。

> [!WARNING]
> 警告内容：&nbsp; 的正确用途是防止特定位置断行（如数字与单位、姓名与称谓），不是用来"排版留白"。堆叠 &nbsp; 撑间距会污染语义与布局，应改由 CSS（margin、text-indent、flex 间隙等）实现。



### 特殊字符与排版细节

#### 中文排版常用字符

中文正文中部分符号建议用对应全角形式或用实体表达，保证显示正确。

- 中文引号“ ” ‘ ’、书名号《 》在中文排版中直接以全角字符书写即可。
- 规范 W8 强调中文标点使用全角；源码中直接写入全角字符是最稳妥做法，无需实体。
- 非文本字符（如表意文字旁的符号）保持字面书写，交由浏览器与字体渲染。

> 经验：正文尽量直接写字面字符（全角中文标点），实体只用于确实有解析歧义或需特殊空白的少数情况。滥用实体反而降低源码可读性。

#### 浏览器解析的健壮性与内联脚本

HTML 解析对某些字符序列有特殊规则，涉及脚本时尤须注意。

- 脚本内出现 </ 序列（如正则、字符串拼接的收尾标签）可能被当成 HTML 结束标签，需转义（如写成 <\/）。
- 历史写法 CDATA 包裹已不必要；现代把脚本外链更省心。

> [!TIP]
> 建议内容：把复杂脚本放外链 .js 文件，可彻底避开"内联脚本里出现 </script>"这类解析陷阱。确需内联时，注意字符串里避免直接写 </script> 或用转义分隔。

#### 检查与避免乱码

开发中遇乱码可循此排查路径。

- 确认文件以 UTF-8 保存（编辑器右下角编码设置）。
- 确认 head 最前有 <meta charset="UTF-8">。
- 确认服务器响应头未强制指定冲突的编码。
- 查看浏览器实际所用编码（开发者工具的 Network/设置）。

> 按"保存编码、声明编码、传输编码三者一致"的原则排查，乱码基本可定位。此点在含中文的项目中是基础中的基础。
