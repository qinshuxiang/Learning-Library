## 嵌入内容与可编程图形

### iframe 内联框架

#### iframe 的用途与基本用法

**iframe 元素**：在页面内嵌入另一个独立 HTML 文档（页面、视频播放器、地图等），形成文档中的内联子文档。

```html
<iframe src="https://example.com/embed" width="600" height="400"
        title="嵌入式示例"></iframe>
```

- src 指定要嵌入的文档地址。
- iframe 内的内容是嵌套文档，与宿主页面有独立上下文，但共享 DOM 事件冒泡边界等特性。
- title 属性为 iframe 提供可访问名称，屏幕阅读器依赖它识别每个框架。

> [!IMPORTANT]
> 重要内容：给每个 iframe 写 title 描述其内容（如"天气预报小部件"），否则屏幕阅读器会把无数框架都读成"无标题"。这是 iframe 可访问性的基本要求。

#### 嵌入第三方与安全隔离

嵌入第三方内容（视频、地图、社交按钮）是 iframe 的主要场景，但需防范安全风险。

- 第三方 iframe 通常由平台提供专用嵌入 URL 与代码片段。
- 若第三方内容不可信，用 sandbox 属性限制其能力。
- referrerpolicy、allow 等属性进一步约束。

> [!WARNING]
> 警告内容：iframe 若嵌入不可信内容，可能引入点击劫持、恶意脚本等风险。对不可信 iframe 务必加 sandbox 属性（无值时最严格，几乎禁用一切能力，可按需用空格列出的值放开脚本、弹窗、表单等），并在关键页面用 X-Frame-Options 或 CSP frame-ancestors 防止被他人恶意嵌入。

#### sandbox 与 allow

**sandbox 属性**：为 iframe 内容建立隔离沙箱，限制脚本执行、表单提交、弹窗、同源访问等能力。

**allow 属性**：为 iframe 内的特性（如摄像头、麦克风、全屏、画中画）授权。

```html
<iframe src="widget.html" sandbox="allow-scripts allow-forms"
        allow="fullscreen; autoplay"></iframe>
```

- sandbox 空值即完全隔离；列出值则逐项放开，如 allow-scripts 允许脚本、allow-same-origin 允许同源。
- allow 基于 Permissions Policy，按需授权敏感能力。

> [!TIP]
> 建议内容：信任的第三方（自家站点的嵌入）可不加 sandbox；外部不可信内容坚持 sandbox 白名单。allow 遵循最小权限原则，只授给确实需要的能力。



### 通用嵌入与对象

#### object 与 embed

**object 元素**：可嵌入多种外部资源，历史上多用于嵌入插件内容（如 PDF、Flash、Applet），现代多被其他方案取代。

**embed 元素**：快速嵌入外部资源（如 PDF、插件内容）的简洁方式。

```html
<object data="doc.pdf" type="application/pdf" width="600" height="500">
  无法显示 PDF。
</object>

<embed src="map.svg" type="image/svg+xml" width="400" height="300">
```

- 两者都能在页内显示 PDF、SVG、图片等。
- 现代浏览器对 PDF 的支持方式趋于统一，object/embed 的插件时代已过。

> [!WARNING]
> 警告内容：object/embed 曾是 Flash 等插件的入口，如今插件已退出历史。现代页面嵌入 PDF 可考虑链接下载、iframe 或浏览器原生 PDF 查看，不必依赖 object/embed。是否在页内直接内嵌 PDF 也应权衡 UX 与兼容。



### Canvas 画布

#### canvas 元素与绘制原理

**canvas 元素**：提供一个可编程绘制的位图画布，通过 JavaScript 获取 2D 或 WebGL 上下文在上面绘制图形、图表、游戏画面。

```html
<canvas id="board" width="400" height="300">
  浏览器不支持 canvas。
</canvas>
<script>
  const board = document.getElementById("board");
  const ctx = board.getContext("2d");
  ctx.fillStyle = "#3a8";
  ctx.fillRect(20, 20, 120, 60);
</script>
```

- canvas 只是"空画布"，一切绘制由脚本完成，无脚本则画布空白。
- width、height 设定画布坐标尺寸（非 CSS 显示尺寸）。
- 通过 getContext("2d") 拿 2D 绘制上下文，或 getContext("webgl") 拿 3D 上下文。

> [!NOTE]
> 提醒内容：canvas 的 width/height 属性决定其内部坐标系与像素数；若只改 CSS 尺寸会拉伸失真。要响应式适配需按设备像素比（DPR）重设画布物理尺寸。canvas 是位图，内容对屏幕阅读器与搜索引擎默认不可读。

#### canvas 与 SVG 的选择

canvas 与 SVG 是两种可编程图形的不同路线，选型看使用场景。

- **canvas**：位图栅格，像素级绘制，适合大量动态重绘（游戏、粒子、图表密集刷新）；放大易糊，内容非 DOM、不可单独交互。
- **SVG**：矢量，基于 XML 的 DOM 结构，适合图标、可缩放图形、数量不多但需交互/事件/无障碍的内容。

> 判断要点：数据量小、需要事件与可访问性、要无限缩放 → SVG；海量动态绘制、逐帧动画 → canvas。也有图表库内部选择其一实现。



### 内联 SVG

#### SVG 基础与优点

**SVG（Scalable Vector Graphics，可缩放矢量图形）**：用 XML 描述图形的矢量格式，可内联进 HTML，作为 DOM 元素参与样式与脚本。

```html
<svg width="100" height="100" viewBox="0 0 100 100" role="img" aria-label="示例圆形">
  <circle cx="50" cy="50" r="40" fill="#4a90d9" />
</svg>
```

- SVG 图形由形状元素（circle、rect、path 等）构成，矢量可无损缩放。
- 内联 SVG 的元素是真实 DOM，可被 CSS 设样式、被 JS 操作、被事件绑定。
- viewBox 定义坐标系，width/height 定义显示尺寸。

> [!TIP]
> 建议内容：图标与徽标优先内联 SVG 而非字体图标或位图——它任意缩放不糊、可用 CSS 控制颜色、支持渐变与动画，且利于无障碍（配合 title、role 与 aria-label）。

#### SVG 的无障碍与可访问性

矢量图形同样需要考虑无障碍，与位图略有不同。

- 用 <title> 或 aria-label 提供图形名称。
- 图形复杂时应提供 role 与详细描述。
- 纯装饰 SVG 可加 aria-hidden="true" 让辅助技术忽略。

> 内联 SVG 因是文本与 DOM，天然比 canvas 更可访问；把图标文字信息用 aria 标注清楚，视觉图标即可服务视障用户。



### 脚本与样式嵌入的边界

#### 内联 script 与外部脚本位置

脚本与样式可内联或外链，位置影响加载性能（详加载章），此处厘清元素职责。

- script 元素：放 JavaScript，可内联（内容直接写）或外链（src）。
- style 元素：放 CSS，通常放 head。
- 内联脚本/样式与外部文件各有取舍。

> 边界原则：结构与内容（HTML）、样式（CSS）、行为（JS）尽量分离。脚本样式外链更利于缓存与维护；少量内联（如关键样式、页面专属小脚本）可作补充。
