## HTML 简介与基础结构

### HTML 是什么

#### HTML 的定义与作用

**HTML**（HyperText Markup Language，超文本标记语言）：是用于描述网页结构与内容的标记语言，用成对的标签把文字、图片、链接等组织成一棵文档树，浏览器据此渲染出可视页面。HTML 负责网页的结构层，即"有什么"。

- HTML 是**标记语言**而非编程语言：它没有变量、循环、函数，不描述计算逻辑，只负责标注内容是什么。
- HTML 是**声明式**语言：开发者只描述"结果长什么样"，由浏览器决定如何呈现，这与命令式的 JavaScript 形成对照。
- HTML 的产物是**文档树**：标签层层嵌套构成树形结构，浏览器据树渲染，脚本据树操作。

> [!NOTE]
> 提醒内容：HTML、CSS、JavaScript 是前端的三大支柱，各有分工——**HTML 负责结构（有什么）、CSS 负责表现（长什么样）、JavaScript 负责行为（能做什么）**。三者缺一不可，但 HTML 是一切的地基。

#### 超文本与标记的含义

理解 HTML 名称中的"超文本"与"标记"二词，能把握它的本质。

- **超文本（HyperText）**：指文本之间可通过链接相互跳转，不是线性阅读。网页与网页靠超链接组成一张网。
- **标记（Markup）**：指用特殊记号（标签）把一段内容标注为"标题、段落、链接"等含义，浏览器据此理解并渲染。

> 一句话：HTML 用标记给纯文本"贴标签"，再用超链接把它们串成可跳转的网络——前者解决"内容是什么"，后者解决"内容怎么串联"。

#### 文件扩展名与 MIME

HTML 文档以 .html 或 .htm 为扩展名，浏览器通过 HTTP 响应中的 MIME 类型 text/html 来识别并解析。

- 本地双击 .html 文件，浏览器以 file 协议直接打开并解析。
- 通过服务器访问时，服务器返回 Content-Type: text/html，浏览器按其解析渲染。

> [!NOTE]
> 提醒内容：文件扩展名只是约定，真正决定浏览器如何解析的是 HTTP 的 MIME 类型。开发时保持 .html 扩展名与 text/html 响应一致即可。



### 一个最小 HTML 文档

#### 文档的基本骨架

任何 HTML 文档都由固定骨架构成，包含文档类型声明、根元素、头部与主体四部分。

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <title>页面标题</title>
</head>
<body>
  <p>这里放页面的可见内容。</p>
</body>
</html>
```

- 文档类型声明 <!DOCTYPE html>：告诉浏览器按现代 HTML5 标准模式解析，必须写在最前。
- 根元素 html：整个文档的最外层容器，lang 属性声明页面主语言。
- 头部 head：放元信息，不显示在页面主体，内容供浏览器与搜索引擎读取。
- 主体 body：页面所有可见内容的容器。

> [!WARNING]
> 警告内容：<!DOCTYPE html> 不可省略且必须置于第一行。若缺失或书写错误，浏览器会进入怪异模式（Quirks Mode），导致盒模型、布局等按旧的、不统一的规则渲染，同一份代码在不同浏览器表现各异。

#### 标签、元素与属性

HTML 语法围绕标签、元素、属性三个核心概念展开。

- **标签（Tag）**：用尖括号括起的标记，分开始标签与结束标签两种，结束标签比开始标签在元素名前多一个斜杠。
- **元素（Element）**：由开始标签、内容、结束标签共同构成的一个完整结构单位，如以 p 为元素名的开始标签、内容、结束标签合起来就是一个 p 元素。
- **属性（Attribute）**：写在开始标签内、用于配置元素的附加信息，形如 属性名="属性值"。

```html
<!-- 元素：a；href 为属性，指向链接地址；"访问示例"是元素内容 -->
<a href="https://example.com">访问示例</a>
```

> [!IMPORTANT]
> 重要内容：标签与元素是两个概念——标签是写在源码里的记号，元素是标签包裹内容后形成的完整结构。日常口语常混用，但技术语境中区分二者有助准确沟通。

#### 空元素（void 元素）

大多数元素有成对的开始与结束标签；部分元素没有内容，也无需结束标签，称空元素或 void 元素。

- 常见空元素：br 换行、img 图像、input 输入、hr 分隔、meta 元数据、link 外链。
- 空元素写在开始位置即完成使命，不能嵌套子元素。

```html
<p>第一行<br>第二行</p>
<img src="logo.png" alt="网站标志">
```

> [!TIP]
> 建议内容：空元素结尾是否写斜杠（写作 br 还是带上结尾斜杠）在 HTML 中都可接受，HTML5 惯例不写；若沿用 XHTML 习惯写斜杠也合法。保持一种风格统一即可。



### 文档树与嵌套

#### 元素嵌套与父子关系

HTML 元素层层包裹形成树状结构，产生父子、兄弟、祖先后代等关系，文档树即由此而来。

- 元素之间必须正确嵌套：先开的后关（先进后出），不可交叉。
- 嵌套产生层级：外层称父元素，内层称子元素，同一父下的元素互为兄弟元素。

```html
<ul>
  <li>苹果</li>
  <li>香蕉</li>
</ul>
```

- 上例中 ul 元素是父元素，两个 li 元素是其子元素且互为兄弟。

> [!WARNING]
> 警告内容：标签交叉嵌套是常见错误，如先写 b 的开始标签、再写 i 的开始标签，却先关 b 再关 i，顺序颠倒，会导致浏览器自动纠错、文档结构错乱。正确写法应先进后出：先开 b 与 i，再按 i、b 的顺序关闭。

#### 浏览器对错误的容错

浏览器解析 HTML 时非常宽容，会自动修复许多书写错误（缺失结束标签、交叉嵌套、未闭合标签等）。

- 容错是历史遗留：早期网页编写随意，浏览器为稳定渲染而自主纠错。
- 容错虽让页面"能用"，但可能产生与预期不符的结构，影响样式与脚本。

> [!IMPORTANT]
> 重要内容：不要依赖浏览器的容错。标签尽量正确闭合、嵌套合理，否则文档树可能偏离预期，导致 CSS 选择器失效、JavaScript 取错元素、可访问性受损。



### HTML 的语言特性

#### 大小写与空白

HTML 在源码书写上有若干宽松约定，理解它们可避免踩坑。

- 标签与属性名**不区分大小写**：写作 P 与写作 p 等效，但 HTML 惯例统一使用小写。
- 连续空白字符（空格、换行、制表）在多数文本元素中被**折叠为一个空格**（pre 元素等除外）。
- 属性值建议加引号（双引号或单引号），HTML5 允许某些情况下省略引号，但易出错，不推荐。

```html
<!-- 大小写、引号、空白的实际效果：p 内多个空格与换行最终只渲染一个空格 -->
<P>第一段   中间有多个空格    结束</P>
```

> [!TIP]
> 建议内容：规范做法是标签属性一律小写、属性值一律用双引号、缩进清晰体现嵌套。让源码与渲染预期一致，便于维护与协作。

#### 注释

HTML 注释用于在源码中写说明，浏览器渲染时忽略其内容。

- 注释以 <!-- 开始、--> 结束，可跨行，不能嵌套。
- 注释不会显示在页面上，但会随源码可见，不要在其中存放敏感信息。

```html
<!-- 这是单行注释 -->
<!-- 这是
     多行注释 -->
<p>可见内容</p>
```

> [!NOTE]
> 提醒内容：注释内容对访问者是可见的（查看源码即得）。调试时临时注释掉的敏感信息，上线前应删除，避免信息泄露。

#### HTML 与 XHTML 的差异

XHTML 是对 HTML 的 XML 化重写，曾试图以更严格的 XML 语法约束 HTML，但未获主流采纳。

- XHTML 要求标签小写、属性加引号、所有元素闭合（含空元素）、严格嵌套。
- 现代 HTML5 采用更宽松的语法，取代了 XHTML 严格约束的路线。

> 一句话：HTML5 放弃了对 XHTML 严格性的追求，回归"宽容但规范"的路线，代价是需靠开发者自律保证文档质量。



### 查看网页源码与文档树

#### 查看源码与开发者工具

学习 HTML 最直接的方式是观察真实网页的结构，浏览器提供两套入口。

- 右键查看网页源代码：看到服务器返回的原始 HTML 文本。
- 开发者工具（F12）的 Elements 面板：显示浏览器实际解析后的文档树，可实时查看与修改样式。

> [!TIP]
> 建议内容：原始源码与开发者工具中的文档树可能不同——浏览器容错后自动修正的结构，只有在 Elements 面板才能看到。排查结构问题以开发者工具为准。

#### 文档大纲意识

阅读 HTML 时应保持"文档大纲"意识：用标题层级勾勒出页面内容的骨架。

- 合理使用 h1 到 h6 表达内容层级，避免为样式随意使用标题。
- 大纲清晰对 SEO 与屏幕阅读器导航都至关重要。

> 开发习惯建议：写完结构后，先在脑海里或借助大纲工具审视一遍"这篇文档的逻辑骨架是否通顺"，再进入样式与脚本阶段。
