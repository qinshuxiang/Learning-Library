## 源码细节：表达式求值与代码注入

### 表达式求值

#### 求值流水线

**mustacheReplacer 是表达式的心脏**：先函数、再路径、逐层替换。

- 主替换用双花括号正则，路径内嵌套部分先用单层方括号正则二次求值
- 形如 $func(参数) 的片段先被识别为函数调用（extractStrFunction）
- 参数本身也走一遍替换求值，函数与数据源可以任意嵌套
- 路径解析走 keyParser，按关键字与路径拆开取值

> 求值是递归下降的：表达式里套函数、函数参数里套数据访问、数据访问里再套函数，层层展开。这也解释了 6 篇的方括号规则——方括号就是进入下一层求值的入口。

**速记**：**双花括号主刀，方括号递归，函数路径皆可嵌**。



#### keyParser 的路径规则

**路径解析有四条归一化规则**：表格路径被智能补全。

- dataColumn 与 dataColumns 关键字被映射为 table（别名兼容）
- table 路径首段为 $last 时替换为最后一行下标
- table 路径只有列名时自动补 0（第一行）：{{table.title}} 等价于第一行
- loopData 路径自动插入 data 段：{{loopData.项目}} 实际取 loopData.id.data.项目

> 这些规则让“自然写法”大多能工作，但也意味着路径错误被静默修正：你以为在取第 0 行，其实规则替你补了行号。写精确路径（显式行号）可绕开隐式补全的歧义。

**速记**：**别名归 table，缺行补 0，$last 换下标**。



#### 求值失败的静默行为

**取不到值的表达式原样留在文本里**：这是最重要的调试线索。

- objectPath 取值为 undefined 时，返回原始的 {{...}} 文本而非空串
- 于是输出里残留的 {{table.9.name}} 就是路径错误的现场
- 与之相对，方括号求值链路里另有存在性检查模式（checkExistence），条件类场景返回布尔
- 感叹号前缀可强制序列化：{{!variables.obj}} 输出 JSON 字符串

> “未替换即错误”是快速排错法：结果字符串里出现没被展开的花括号，直接去检查对应路径。而对象被展开成 object Object 还是 JSON 文本，取决于是否加了感叹号前缀。

**速记**：**取不到原样留，感叹号强转 JSON**。



#### secrets 凭据的解密通道

**secrets 是表达式的一等数据源**：凭据按需解密。

- referenceData 中 secrets 字段承载加密的凭据数据
- 表达式取 secrets 时走 credentialUtil.decrypt 解密后返回
- 代码块的下发数据中 secrets 被显式置空：代码里拿不到凭据
- 凭据在扩展的凭据管理中维护，不进工作流 JSON

> 安全边界在源码里画得很清楚：表达式层可以取凭据，代码层一律拿不到。需要凭据的请求用表达式拼进 HTTP 块参数，而不是在代码块里引用变量——这不是缺陷是设计。

**速记**：**表达式可解密，代码块零凭据**。



### 代码注入

#### 内置函数的注入方式

**五个内置函数以源码字符串形式注入页面**：不是扩展 API，是动态生成的代码。

- getAutomaScript 拼出一段 JS：定义 automaRefData（findData 逐段取路径）、automaSetVariable、automaNextBlock、automaResetTimeout、automaFetch
- automaNextBlock 通过派发自定义事件 __automa-next-block__ 通知内容脚本
- automaFetch 通过 __automa-fetch__ 事件转后台请求，响应经 __automa-fetch-response-实例id__ 事件回传
- 响应类型合法值为 text、json 与 base64——比文档多一个 base64

> 事件驱动的桥接解释了两个行为：这些函数只在注入了 Automa 脚本的页面里存在；每次新标签模式下不注入完整脚本，函数自然缺席。base64 类型源码支持，可用于拉取二进制资源转码。

**速记**：**函数即注入脚本，事件即通信桥，类型多 base64**。



#### 超时与错误的精确语义

**超时是 resolve 不是中断，错误是抛出不是吞掉**：与直觉相反的两处。

- 用户代码被包进 Promise，超时到点调用 resolve（无值），工作流静默走下一块
- 代码内没有 automaNextBlock 调用时，自动补一行 automaNextBlock()
- 未捕获异常被 catch 后返回 $error 标记，块处理器据此抛错，块判定失败
- automaResetTimeout 重置的是内部 setTimeout 计时

> “超时静默、报错显性”的成对语义修正一个常见误解：代码抛异常不是被吞掉，而是块失败并走工作流的错误处理；被 try 住的异常才由代码自己兜底。漏写 automaNextBlock 不致命，引擎会替你补。

**速记**：**超时静默走，未捕获异常块失败，漏写 nextBlock 自动补**。



#### 注入的边界条件

**代码注入有三道门**：标签就绪、CSP 与沙箱。

- website 上下文先等标签页加载完成（默认超时 30000 毫秒可配）
- 严格 CSP 的页面可能拦住注入，引擎先做 CSP 检查并尝试 trustedTypes 策略降级
- background 上下文在 MV2 或弹窗场景转入沙箱 iframe 执行，Firefox 无沙箱
- 预加载脚本仅接受 http 与 https 地址，可设执行后移除

> CSP 检查解释了个别站点上代码块失效的现象：不是 Automa 的 bug，是站点安全策略拒绝注入。降级与绕过受限于浏览器安全模型，遇到 CSP 严格站点改用 background 上下文或 HTTP 块是更稳的路。

**速记**：**等加载、过 CSP、择沙箱，三道门定成败**。
