## HTTP 请求与 automaFetch

### 请求的两种路径

#### HTTP 请求块与代码块请求

**Automa 有两条发请求的路**：专用块与代码内函数。

- HTTP 请求块：可视化配置 URL、方法、头、体，响应存入表格或变量
- 代码块内 automaFetch：JS 写请求逻辑，灵活度更高
- 两者最终都从扩展后台发出，绕开页面 CORS 限制
- 选型：简单调用用块，需要逻辑（重试、多步组装、条件头）用代码

> 与本库 JavaScript 系列第 14 篇网络请求与跨域对读：那篇讲清了 CORS 为什么存在，本篇讲 Automa 怎么绕开它——扩展后台有更高权限，同源策略管不到它。

**速记**：**块管简单请求，代码管复杂请求，后台管跨域**。



### automaFetch 详解

#### 签名与响应类型

**automaFetch(type, resource) 两参定形**：响应类型与请求配置。

- type：响应解析方式，text 返回原始文本，json 自动反序列化；源码另支持 base64（拉取二进制资源转码，官方文档未列）
- resource：fetch 的标准配置对象，url、method、headers、body 全支持
- 返回 Promise：await 或 .then 接结果
- body 传对象时先 JSON.stringify，与原生 fetch 一致

```js
// GET
const data = await automaFetch('json', { url: 'https://api.example.com/list' });

// POST
const created = await automaFetch('json', {
  url: 'https://api.example.com/items',
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ title: 'Hello world' }),
});
```

> 参数心智模型就是原生 fetch（本库 JavaScript 系列第 14 篇）：唯一新增的是第一参告诉 Automa 怎么解析响应。选 json 免去手动 res.json()，选 text 处理非 JSON 载荷。

**速记**：**第一参定解析，第二参就是 fetch 配置**。



#### 请求结果的去向

**请求结果要交还给工作流才有用**：写变量或写表格两条出路。

- 写变量：automaSetVariable('apiResult', data)，下游表达式 {{variables.apiResult}} 引用
- 写表格：automaNextBlock(data) 直接入表，键对列名
- 组合链路：取数、变换、写回，一段代码一次完成
- 错误路径：try 包裹 await，失败时写错误标记变量再正常续流

```js
try {
  const data = await automaFetch('json', { url: 'https://api.example.com/list' });
  automaSetVariable('items', data.items);
  automaNextBlock({ count: data.items.length });
} catch (err) {
  automaSetVariable('apiError', String(err));
  automaNextBlock({ count: 0 }, false);
}
```

> 错误处理是请求代码块的必修课：网络抖动、限流、鉴权过期都走 catch。失败时也要 automaNextBlock 续流（可 insert 为 false 不写脏数据），让下游条件块基于错误标记分支——静默中断是最难排查的失败。

**速记**：**成功写数据，失败写标记，永远续流**。



### 实战模式

#### 分页拉取与限速

**API 分页拉取是 automaFetch 的高频用法**：循环翻页加限速。

- 页码循环：每次请求递增 page 参数，直到返回为空
- 限速：请求间 await 延时，尊重 API 的频率限制
- 结果累积：数组 concat 后统一写表，或每页写一次
- 退出条件必须可靠：空结果、最大页数、连续错误三层保险

```js
let page = 1;
const all = [];
while (page <= 50) {
  const res = await automaFetch('json', {
    url: 'https://api.example.com/list?page=' + page,
  });
  if (!res.items || res.items.length === 0) break;
  all.push(...res.items);
  page += 1;
  await new Promise((r) => setTimeout(r, 1500));
}
automaSetVariable('total', all.length);
automaNextBlock(all.map((it) => ({ title: it.title, url: it.url })));
```

> 这段骨架覆盖了拉取类需求的大半：页码循环、空页退出、限速等待、批量写表。403 与 429 状态码是限流信号，遇码加间隔重试比硬跑更持久。

**速记**：**页码循环、空页即停、限速垫底**。



#### 与页面流程的编排

**请求与页面操作交替编排是全能力形态**：API 取数、页面执行、结果回传。

- 前置取数：代码块从 API 拉清单存变量，循环块逐项驱动页面操作
- 中途回传：页面取到的数据写变量，后续代码块汇总后调 API 上报
- 身份复用：页面带登录态，代码块调需要鉴权的站点 API 时可直接借用
- 这类混合流里，每段职责单一：代码管数据，块管页面

> 混合编排是 Automa 的完全体：纯块流程被 API 能力放大，纯代码流程借页面登录态突破鉴权。编排时画清楚“数据在哪、动作在哪”，两套手段按段切换。

**速记**：**代码管数块管页，登录态是最贵资产**。
