## Automa 简介与安装

### Automa 是什么

#### 产品定位

**Automa 是以连接块的方式自动化浏览器的扩展**：填表、抓数据、定时任务，靠拖块完成。

- 低代码与无代码定位：主流操作不需要写代码，复杂逻辑可以写 JavaScript
- 以块为原子单位：点击、填表、取文本、发请求都是一个块
- 块连成工作流：工作流是自动化的完整单元，可保存、分享、定时执行
- 支持 Chrome 与 Firefox，代码开源于 GitHub（AutomaApp/automa，AGPL 协议）

> Automa 与影刀、UiPath 等桌面 RPA 的分界在“浏览器内”：它工作在扩展权限范围内，天然跨平台但管不了操作系统级动作。选型先问自动化发生在哪里。

**速记**：**连接块即自动化，浏览器是主场，开源可查**。



#### 能做什么

**典型场景集中在网页的重复操作**：四类需求覆盖大多数用法。

- 数据抓取：循环翻页、取文本、导出表格
- 表单自动化：自动填表、批量提交、签到打卡
- 流程编排：打开页面、等元素、点按钮、存结果串成一条流
- 定时任务：按时间或按间隔自动触发工作流

> 凡是“人在浏览器里重复做的事”，都值得先问一句能不能交给 Automa；反过来，需要操作浏览器之外的世界（本地文件系统、桌面应用）的，它不是合适工具。

**速记**：**抓取、填表、编排、定时，四类场景问出处**。



### 安装与界面

#### 安装方式

**两种安装渠道**：应用商店安装为主，开发者可本地加载。

- Chrome 用户：从 Chrome Web Store 安装（扩展名 Automa）
- Firefox 用户：从 Firefox Add-ons 安装
- 开发者：克隆 AutomaApp/automa 仓库，pnpm 安装依赖后 pnpm build，在 chrome://extensions 打开开发者模式加载 build 目录
- Firefox 本地调试走 about:debugging 临时加载 manifest.json

> 商店版自动更新，是绝大多数用户的正确选择；本地构建只在需要改源码或尝鲜未发布功能时使用，注意商店版与构建版的数据不互通。

**速记**：**商店装省心，源码构建为改造**。



#### 界面组成

**扩展界面围绕工作流展开**：五个入口各管一摊。

- 工作流列表：新建、导入、搜索与定时概览
- 编辑器画布：拖块、连线、配置参数的主战场
- 运行日志：查看每次执行的状态与输出
- 设置：全局配置、备份与凭据管理
- 市场（Marketplace）：分享与下载他人工作流

> 建议先在列表里跑通官方示例工作流，再进画布搭自己的第一个流；画布操作的学习成本集中在前两小时，拖动加双击配置，用过即会。

**速记**：**列表、画布、日志、设置、市场，五口入流**。



### 基本工作法

#### 第一个工作流

**最小可用工作流只有两个块**：触发器加一个动作。

- 新建工作流，画布默认带一个手动触发的触发块
- 拖入一个新建标签页块，填入目标网址
- 再拖一个获取文本块，选择页面上某个元素
- 点运行，观察日志输出

> 第一个流的价值不在功能而在闭环：建、配、跑、看日志，四步走通后，Automa 的全部复杂度都建立在这条路径上。

**速记**：**触发器起手，动作块收尾，日志里看结果**。



#### 学习路径

**学习 Automa 的正确顺序是先块后码**：无代码用尽再上 JavaScript。

- 第一阶段：熟悉常用块的参数，能搭出抓取与填表流
- 第二阶段：掌握变量、数据表与表达式，流开始有状态
- 第三阶段：进入 JavaScript 代码块，处理块覆盖不了的逻辑
- 第四阶段：工作流复用、定时任务与错误处理，走向稳定运行

> 本系列的编排正是这个顺序：块操作（2 至 4 篇）、数据与表达式（5 至 7 篇）、JavaScript 核心（8 至 11 篇）、生态与实战（12 至 13 篇）。JavaScript 部分与本库 JavaScript 系列深度对齐，遇语法细节可回查对应篇目。

**速记**：**先块后码，数据先行，JS 收顶**。
