## 页面操作：导航、选择器与元素交互

### 页面导航

#### 标签页与页面跳转

**导航类块负责“去哪里”**：新开、切换、跳转与刷新。

- 新建标签页块：打开指定 URL，支持表达式动态拼地址
- 切换标签页块：在已打开的标签页之间转移活动焦点
- 跳转页面块：在当前标签页内导航到新地址
- 刷新与前进后退块：复用浏览器原生导航行为

> 多标签页工作流必须显式管理焦点：每个作用于页面的块都以当前活动标签为上下文，切错标签后续块全部落空。涉及两个页面的流程，每个动作前先确认焦点在谁身上。

**速记**：**新开、切换、跳转、刷新，动作前先定焦点**。



#### 等待页面就绪

**页面加载是异步的**：导航后必须等待元素出现再操作。

- 导航块自带等待页面加载完成的选项
- 元素存在性判断块可当等待用：配合轮询条件
- 延迟块是兜底手段：固定毫秒数的粗粒度等待
- 网络慢的页面优先等元素而非等时间

> 固定延迟是脆弱方案：网络一抖就失效。正确姿势是“等元素出现”的事件驱动等待，延迟块只留给必须垫时间的场景（如动画完成）。

**速记**：**等元素不等秒数，延迟块是兜底不是首选**。



### 选择器

#### CSS 选择器基础

**Automa 定位元素以 CSS 选择器为主力**：与浏览器 DevTools 同一套语法。

- 标签、类、id、属性选择器：div.card、#submit、input[name=email]
- 层级与伪类：ul li:first-child、a[target=_blank]
- 本库 JavaScript 系列第 10 篇 DOM 基础对选择器语法有系统讲解，语法细节直接回查
- 选择器写在块的“元素选择器”参数里，多数页面操作块都带这一项

> 选择器能力来自浏览器原生的 querySelector 体系：你在控制台能用 document.querySelector 验证的选择器，Automa 里同样有效。调试选择器先开 DevTools 控制台试，再回填到块。

**速记**：**选择器即 querySelector，控制台验证再落块**。



#### 选择器策略

**稳定选择器的三条取法**：从“唯一”走向“语义”。

- 优先语义属性：data-testid、name、aria-label 这类为稳定而生的属性
- 次选 id 与唯一类名组合
- 慎用自动生成的类名：构建工具产出的哈希类名一次部署就失效
- DevTools 的复制选择器功能给出的路径冗长且脆，多作参考少作依赖

> 选择器的寿命决定工作流的寿命：页面改版后第一个坏的就是选择器。为关键流程维护一份选择器清单（哪个页面用哪些选择器），改版时批量检查。

**速记**：**语义属性最长寿，哈希类名是一次性的**。



#### XPath 补充

**XPath 是文本定位的补充手段**：CSS 挑不动的场景用它。

- 按文本定位：双斜杠加方括号，如 //button[contains(text(), '提交')]
- 按轴定位：父级、兄弟节点关系，CSS 表达不便时使用
- 本库 JavaScript 系列第 9 篇正则表达式篇对文本匹配思维的迁移有参考价值
- XPath 性能弱于 CSS，仅在必要场景使用

> 先 CSS 后 XPath：CSS 覆盖九成场景，XPath 主要赢在“按文本找元素”与复杂层级关系两点。

**速记**：**CSS 走九成，XPath 补文本与层级**。



### 元素交互

#### 点击与基础交互

**点击块模拟用户动作**：支持点击、悬停、滚动等。

- 点击块：选中元素后模拟点击，可配等待选项
- 悬停块：触发 mouseover 类事件，展开菜单必用
- 滚动块：页面滚动到元素或指定距离，懒加载页面必备
- 触发方式可选真实模拟或直接调事件，效果差异在个别站点会显现

> 懒加载列表的抓取套路是“滚一屏、等加载、再滚一屏”的循环：滚动块配循环块，循环次数封顶防死循环。

**速记**：**点击悬停滚动三件套，懒加载靠滚加等**。



#### 取文本与取属性

**读取元素数据是抓取流的核心动作**：文本、属性、多元素各一个块。

- 获取文本块：取元素文本内容，支持 CSS 选择器与 XPath
- 获取属性块：取 href、src 等属性值
- 元素列表类块可配多元素模式：一次取一组结果
- 取到的数据默认写入数据表，供后续导出或判断使用

> 批量抓取的效率关键在“一次取一组”而不是循环逐条取：能配多元素选择器的场景，一个块顶一个循环。取完的数据结构在数据表篇展开。

**速记**：**文本属性分开取，多元素模式省循环**。



#### 表单交互

**表单块覆盖输入类控件**：文本框、下拉、复选、文件。

- 表单块：按字段类型分别处理，一个块可配多个字段
- 文本框直接赋值；下拉框按值或按文本选中
- 复选框与单选框支持勾选状态设置
- 文件上传块单独处理 input[type=file] 场景

> 表单提交前先确认校验逻辑：页面用 JS 校验时，填完字段再点提交按钮，别跳过中间的失焦事件——很多校验在 blur 时才触发。

**速记**：**一表一流程：先填后触校验再提交**。
