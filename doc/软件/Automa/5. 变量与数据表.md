## 变量与数据表

### 变量

#### 变量的创建与读写

**变量是工作流的内存**：Set Variable 块与表达式是读写两扇门。

- 设置变量块：写入变量名与值，值可以是任意 JSON 类型
- 读变量用表达式：{{variables.变量名}}，任何块的输入框都可用
- JS 代码块内用 automaSetVariable 写、automaRefData('variables', 路径) 读
- 变量的值贯穿整个执行实例，执行结束即销毁

> 变量类型跟着 JS 走：字符串、数字、布尔、数组、对象都行。存对象与数组时，表达式路径可以直接点下去（6 篇），这让它比纯字符串变量灵活得多。

**速记**：**块里 Set，表达式读，JS 里两样都行**。



#### 变量的设计习惯

**变量命名的规范程度决定工作流的可读性**：三条习惯够用。

- 语义命名：totalCount 优于 a1，与 JS 命名规范同源（本库 JavaScript 系列第 2 篇）
- 一个变量一个职责：不把页码和结果混在一个对象里乱放
- 复杂结构先画形状：嵌套对象在表达式里一层层点，写前先想清结构

> 变量是流的隐形骨架：三个月后回看自己的工作流，变量名是最重要的路标。命名省下的三秒钟，调试时会加倍还回去。

**速记**：**语义命名、单一职责、结构先想后写**。



### 数据表

#### 数据表是什么

**数据表是工作流的行式数据容器**：抓取结果的默认归宿。

- 数据表按列组织：使用前先定义列名，如 title、price、url
- 各块的输出写入表格：取文本块的“写入数据表”选项、JS 的 automaNextBlock 都能插行
- 表格数据在循环中逐行累积，结束时一次性导出
- 表格与变量并存：临时计算放变量，收集结果放表格

> 数据表的列是 schema：JS 写入时对象键必须与已定义的列名匹配（见 9 篇 automaNextBlock 的说明），列名对不上数据就进不了表。先定义列，是抓取流的第一步。

**速记**：**列先定义后写入，行随循环累积**。



#### 表格的读取

**表格数据也能被读出来参与逻辑**：不只是只写不读。

- 表达式读表格：{{table.0.title}} 取第一行的 title 列
- 特殊路径：$last 指最后一行，配合循环索引可取任意行
- $getLength([table]) 取表格行数，用于判断是否为空
- 循环数据块可直接以表格为数据源逐行遍历

> “先抓后判”的模式靠读表格支撑：抓完第一页，读表格行数判断有没有数据，有则翻页循环、无则直接结束。表格读写的组合让纯块也能搭出有状态的流程。

**速记**：**行号点列名，$last 取末行，长度判空**。



### 数据的流向

#### 数据在块间怎么走

**块间数据传递有三条通道**：表格、变量与上一块输出。

- 表格：多块累积写入，适合结果集
- 变量：显式命名共享，适合配置与中间状态
- 上一块输出：prevBlockData 关键字直接引用，适合紧邻两块间传递
- 循环迭代数据：loopData 服务循环体内取当前项

> 三条通道的选择口诀：要汇总的进表格，要复用的进变量，相邻块顺手传的用上一块输出。通道选对了，工作流的连线图才干净。

**速记**：**表格汇总、变量共享、相邻直传**。



#### Global Data 与工作流入参

**Global Data 是执行前注入的数据**：一次运行的外部输入。

- 运行工作流时可传入 Global Data，作为本次执行的全局数据
- 表达式与 JS 里分别用 globalData 关键字与 automaRefData('globalData') 读取
- 典型用途：外部调度传入关键词、目标 URL、日期等参数
- 子工作流被调用时也可接收传入数据

> Global Data 让同一份工作流服务不同参数：抓取流写成模板，关键词从入参来，一份流跑 N 个词。参数化是工作流复用的第一步。

**速记**：**入参进 Global Data，一份流跑千般词**。
