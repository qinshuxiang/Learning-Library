## SQL 语言与数据库操作

> **全章主脉**：**SQL 是关系数据库的标准语言，以非过程化方式声明"要什么"而非"怎么做"**。它同时承担**数据定义、数据操纵、数据控制与事务控制**四类职责，考试既考语句结构，更考语义规则——尤其是查询的**执行顺序**、**分组前后两处筛选**的差异、**连接与子查询**的等价改写，以及**视图可更新性**的判断。本章按"定位与分类、单表查询与聚合、多表查询与集合运算、视图更新与索引、数据控制与工程化"五块展开。

### SQL 语言概览与语句分类

#### SQL 的定位与特点

**SQL**（Structured Query Language，结构化查询语言）：关系数据库的**标准数据语言**，以**非过程化**方式声明目标结果，由数据库管理系统自行决定存取路径与执行方式。

- **非过程化**：只写查什么，不写怎么查，执行计划由系统生成，这是它与过程式语言最根本的区别。
- **面向集合**：一次操作处理一个元组集合，即一张表，而不是逐条记录循环处理。
- **双重身份与两种用法**：SQL 既是**查询语言**，也是**数据定义与控制语言**；既可**交互式**在终端直接使用，也可**嵌入式**由程序调用，后者需处理宿主语言与 SQL 之间的数据交换。

> [!IMPORTANT]
> **重要内容**：SQL 虽以 Query 命名，却**绝不只用于查询**。判断一项能力是否为关系数据库必备，只需看它能否完成定义、操纵、控制、事务四件事。

> **速记线索**：非过程化、面向集合、一套语法两处使用、四种职责——四点合起来就是 SQL 的定位。



#### 语句的四大分类

**SQL 语句**：按功能分为**数据定义、数据操纵、数据控制、事务控制**四类，四类各有一组固定动词，动词与类别一一对应。

- **数据定义**（DDL）：定义与修改数据库对象的结构，包含**模式、表、视图、索引**的创建、修改与删除，即 CREATE、ALTER、DROP、TRUNCATE。
- **数据操纵**（DML）：对数据本身做**查询与更新**，即 SELECT、INSERT、UPDATE、DELETE。
- **数据控制**（DCL）：管理访问权限，即 GRANT 授权与 REVOKE 回收。
- **事务控制**（TCL）：界定事务边界，即 COMMIT 提交、ROLLBACK 回滚、SAVEPOINT 保存点。

> **辨析**：CREATE、ALTER、DROP 改的是**对象的骨架**，INSERT、UPDATE、DELETE 改的是**对象中的内容**；TRUNCATE 形似删除数据，语义上按数据定义处理，清空而不逐行记日志。

> **速记线索**：**定义管结构、操纵管内容、控制管权限、事务管边界**；四类动词互不交叉，归类题按动词定位即可。



#### 数据类型与完整性约束

**数据类型**：规定列可取的值域与存储形态；**完整性约束**：规定列或表上必须成立的条件，二者共同支撑域完整性、实体完整性与参照完整性。

- **字符类型族**：定长字符与变长字符之分，前者不足补空格，后者按实际长度存储，差别集中体现在尾部空格的比较行为上。
- **数值类型族**：精确数值与近似数值两类，金额等要求精确的场合用前者，科学计算可用后者，取舍标准是精度要求而非取值范围。
- **日期时间与大对象类型族**：日期、时间、时间戳分别刻画年月日、时分秒与二者组合，时间戳还可携带时区信息；字符大对象与二进制大对象用于超长文本与图形、音视频等非结构化数据，一般不参与排序与比较。
- **六类约束**：主键唯一标识一行且不允许空值；外键引用另一表的主键或候选键；唯一约束要求同列取值不重复；非空约束禁止空值；检查约束限定列值须满足的条件；默认值约束在插入未给值时提供缺省。

> [!WARNING]
> **警告内容**：**约束之间的冲突表现**须分清：唯一约束允许多个空值却拒绝重复值，与主键"非空且唯一"的语义完全不同；外键要求被引用值必须存在，父表删除被引用行而子表未做处理时，语句将被拒绝或触发级联，考试常在此设错。

> **速记线索**：约束可记成**一标识、二候选、三条件**——主键定标识，外键与唯一定候选，非空、检查、默认定取值条件。



### 单表查询与聚合分组

#### 查询的语义结构与执行顺序

**查询的语义结构**：由选择、投影、排序、去重、限制返回行数五种操作组成；其中**书写顺序与执行顺序不同**，是 SQL 最易失分的语义事实。

- **书写顺序**：SELECT、FROM、WHERE、GROUP BY、HAVING、ORDER BY，与人写句子的直觉一致。
- **逻辑执行顺序**：FROM、WHERE、GROUP BY、HAVING、SELECT、ORDER BY，先取数、再筛行、然后分组、筛组、投影、排序。
- **选择**：WHERE 子句按条件过滤行，条件由比较、逻辑与空值判断组合而成，空值参与比较的结果是未知而非真。
- **投影与去重**：SELECT 挑出需要的列并可做算术、函数与别名处理；DISTINCT 消除重复行，作用范围是**整行**而非某一列。
- **排序与限行**：ORDER BY 指定列与升降序，可控制空值排位；取前若干行由限行子句承担，标准口径用 FETCH。

```sql
SELECT 部门, COUNT(*) AS 人数
FROM 员工
WHERE 入职年份 >= 2020
GROUP BY 部门
HAVING COUNT(*) >= 3
ORDER BY 人数 DESC;
```

> [!TIP]
> **建议内容**：记住执行次序，很多易错题不攻自破——**WHERE 里写聚合函数必错**，因为该步尚未分组；**SELECT 的别名不能用于 WHERE**，因为别名尚未产生；**ORDER BY 却可以用别名**，因为它在 SELECT 之后。

> **速记线索**：执行次序记作 **FROM 取数、WHERE 筛行、GROUP BY 分组、HAVING 筛组、SELECT 投影、ORDER BY 排序**；一句话："先取再筛行，分组再筛组，最后投影和排序。"



#### 聚合函数与分组筛选

**聚合函数**：把一组行折叠为单个值；**分组**：按列值把表划成若干组，使聚合在组内分别进行。

- **五类聚合函数**：计数、求和、求平均、求最大值、求最小值，即 COUNT、SUM、AVG、MAX、MIN。
- **分组语义**：GROUP BY 之后的每一行代表一个组，SELECT 中只应出现分组列与聚合函数，写其他列在标准口径下并不合法。
- **分组后筛选**：HAVING 作用于组，可用聚合结果作为条件，用于筛出满足条件的组。
- **空值处理**：COUNT 星号统计行数并包含空值行；COUNT 列名、SUM、AVG、MAX、MIN 都**跳过空值**，其中 AVG 只对非空值求平均，故与"总和除以总行数"并不相等。

```sql
SELECT 部门, AVG(薪资) AS 平均薪资
FROM 员工
GROUP BY 部门
HAVING AVG(薪资) > 8000;
```

> [!IMPORTANT]
> **重要内容**：**分组前筛选与分组后筛选的差异是高频考点**。**WHERE** 在分组前逐行筛选，**不能**使用聚合函数，被筛掉的行不参与分组；**HAVING** 在分组后按组筛选，**必须**配合分组，可以使用聚合函数。二者的差异不在于能不能筛选，而在于筛选的**时点**与**对象**。

> **速记线索**：**行用 WHERE、组用 HAVING**；聚合函数只允许出现在 SELECT 与 HAVING 中，绝不会出现在 WHERE 中。



### 多表查询与集合运算

#### 连接查询

**连接查询**：按连接条件把两个表组合成一张结果表，对应关系代数中的连接运算，按是否保留未匹配行分为内连接与外连接。

- **内连接**：只保留连接条件成立的行，可写成 INNER JOIN 加 ON，也可写成 FROM 两表加 WHERE 条件的等价形式。
- **外连接**：保留匹配行的同时保留一侧或两侧不匹配的行，分左外、右外、全外三类，未匹配处补以空值。
- **交叉连接**：不带连接条件的两两组合，即笛卡尔积，结果行数为两表行数之积。
- **自然连接**：按同名同类型的列自动做等值连接并去掉重复列，可用内连接加等值条件加投影来等价表达。

```sql
SELECT 员工.姓名, 部门.部门名
FROM 员工 LEFT JOIN 部门 ON 员工.部门号 = 部门.部门号;
```

> [!CAUTION]
> **注意内容**：**外连接中的条件位置不可随意挪动**。对从表的过滤条件写在 ON 与写在 WHERE，结果可能完全不同——写在 WHERE 会把补空的行一并滤掉，使外连接退化为内连接，这是结果集判断题最常见的失分点。

> **速记线索**：**内连接取交集、外连接保一侧、交叉连接全组合、自然连接自动比**；四种写法中只有交叉连接不带连接条件，只有外连接会补空值。



#### 子查询

**子查询**：嵌套在另一条语句中的查询，按能否独立运行分为**不相关子查询**与**相关子查询**。

- **不相关子查询**：内层不引用外层的列，可先独立执行一次，再把结果交给外层使用。
- **相关子查询**：内层引用外层的列，须对外层每一行分别求值，语义上相当于逐行代入。
- **量词表达**：EXISTS 与 NOT EXISTS 表达存在与不存在，配合相关子查询可实现关系代数中的除法；全称量词没有直接写法，须改写为"不存在不满足条件的行"，即双重否定式。
- **常用谓词**：IN 用于集合成员判断；比较运算符配 ANY 或 ALL 用于按行参与比较，语义与 EXISTS 的取真方式并不相同。

```sql
SELECT 姓名
FROM 学生
WHERE NOT EXISTS (
  SELECT *
  FROM 选修
  WHERE 选修.学生号 = 学生.学生号
    AND 选修.成绩 < 60
);
```

> **辨析**：相关与不相关的判据只有一条——**内层是否引用外层的列**。引用即相关，外层每行都要跑一次内层；不引用即不相关，内层只算一次。做题时先划出内外层的引用关系，再判断执行次数与结果。

> **速记线索**：**存在用 EXISTS、全称靠"不存在反例"**；IN 与 ANY 偏成员判断，EXISTS 偏真值存在判断，二者在空值参与时结果可能不同。



#### 集合运算

**集合运算**：把两个查询结果按集合语义做并、交、差，要求两个结果的列数相同、对应列类型相容。

- **并运算**：UNION 合并两结果并去重；UNION ALL 合并但保留重复行，代价更低。
- **交与差运算**：INTERSECT 取同时出现在两个结果中的行；EXCEPT 取出现在第一个结果而不出现在第二个结果中的行。
- **去重规则**：三者的默认语义都是集合，**自动去重**；要保留重复行必须显式使用带 ALL 的写法。
- **替换关系**：并可用带 OR 的条件或对合并结果去重实现，交可用连接或 IN 子查询实现，差可用 NOT EXISTS 或 NOT IN 实现。

> **辨析**：集合运算要求结果列**按位置对应**而非按列名对应，列名取自第一个查询；若两列类型相容但意义不同，语句仍会执行却得到无意义的集合，这属于语义错误而非语法错误。

> **速记线索**：**并去重、交取同、差取独**；三者都能用子查询改写，考试常在同一题中给出多种写法让人判断结果是否等价。



### 视图、数据更新与索引

#### 视图的定义、作用与可更新性

**视图**：由一个查询定义的虚表，不实际存储数据，使用时按定义临时求值；其作用集中在简化查询、逻辑独立性与安全控制三方面。

- **简化查询**：把复杂连接与筛选封装成一个名字，外部只面对简单结构。
- **逻辑独立性**：底层表结构变化时，只要同步调整视图定义，使用视图的程序可以保持不变。
- **安全控制**：只把需要的行列暴露给使用者，隐藏其余数据，是权限控制的常用手段。
- **定义方式**：用 CREATE VIEW 加一个 SELECT 定义，可附列名清单，本质是把查询命名保存下来。
- **可更新条件**：视图的每一行须与底层表的行保持**一一对应**，含聚合函数、GROUP BY、HAVING、DISTINCT 或集合运算的定义都会把多行折为一行，因而不可更新。
- **物化视图**：把查询结果实际存储下来以换取查询性能，需在底层数据变化时刷新，属于以空间与一致性代价换查询速度的手段。

```sql
CREATE VIEW 高薪员工 AS
SELECT 姓名, 部门, 薪资
FROM 员工
WHERE 薪资 > 10000;
```

> [!NOTE]
> **提醒内容**：视图是**虚表**，定义时不产生数据、查询时才求值，本身不占数据空间；因此视图上的查询性能并不由视图决定，而由视图内部的查询决定。判断可更新性时，先看定义是否"保行"，再看是否附带写入条件限制。

> **速记线索**：视图三作用记作**简化、独立、安全**；可更新性记作**能保行才可更新**。工程建设方式与语法细节，工程实现详见 MySQL 主题。



#### 插入、修改与删除

**数据更新**：由插入、修改、删除三条语句完成，共同的语义核心是**影响行数**，即语句实际改动的记录数。

- **插入**：INSERT INTO 表名加列清单加 VALUES 逐行给值，也可用带子查询的插入把查询结果批量写入。
- **修改**：UPDATE 表名 SET 列等于值加 WHERE 条件；省略 WHERE 将更新全表，是实务中最危险的写法。
- **删除**：DELETE FROM 表名加 WHERE 条件；省略 WHERE 将删除全部行，但表结构与约束仍然保留。
- **带子查询的更新**：SET 或 WHERE 中可嵌入子查询，子查询的求值结果决定更新范围，相关子查询会对外层逐行求值。
- **级联行为的取舍**：外键可配置为级联删除或置空，级联能自动维持参照完整性，却可能引发大范围连锁改动，实务中倾向于显式控制而非隐式级联。

```sql
UPDATE 员工
SET 薪资 = 薪资 * 1.1
WHERE 部门号 IN (SELECT 部门号 FROM 部门 WHERE 城市 = '上海');
```

> **辨析**：删除与清空不同——DELETE 逐行删除、可带条件、可回滚，TRUNCATE 清空整表、不可带条件、按数据定义处理。级联删除与置空的选择取决于子表数据能否脱离父表而独立存在。

> **速记线索**：**插入靠列与值对应、修改靠 SET 与 WHERE 配合、删除靠 WHERE 划定范围**；三者共同的隐患都是**条件缺省**。



#### 索引的原理与取舍

**索引**：建立在表的列上的辅助存取结构，以额外的存储空间与维护开销换取定位速度。

- **作用**：把全表扫描降为按索引定位，减少为找到目标行而访问的数据量，在等值与范围条件、排序与连接时收益尤为明显。
- **代价**：索引本身占用空间；插入、修改、删除都要同步维护索引，写入越频繁维护成本越高；索引过多还会干扰优化器的选择。
- **聚簇与非聚簇**：**聚簇索引**决定数据行的物理存放顺序，一个表通常只能有一个；**非聚簇索引**是独立于存放顺序的辅助结构，一个表可有多个，命中后往往还需回表读取整行。
- **适合建索引的列**：经常出现在 WHERE 条件、连接条件与排序列上的列，以及区分度高、重复值少的列。
- **不适合建索引的列**：区分度很低的列、更新极频繁的列、很少被查询涉及的列，以及表本身很小、全表扫描已足够快的场合。

> [!CAUTION]
> **注意内容**：**索引不是越多越好**。每增加一个索引，写入就要多维护一份结构，空间与写性能同步下降；是否建索引的判据是"读的收益能否长期超过写的代价"，而不是"这一列看起来会用到"。

> **速记线索**：索引取舍一句话——**读多写少、区分度高、常用于条件与连接者宜建**；聚簇管顺序、非聚簇管定位。索引类型、创建语法与优化实践属工程细节，详见 MySQL 主题。



### 数据控制与工程化扩展

#### 授权与回收

**数据控制**：通过授权与回收管理用户对数据库对象的访问权限，核心语句为 GRANT 与 REVOKE。

- **授权语句**：GRANT 权限清单 ON 对象 TO 用户，可附 WITH GRANT OPTION，允许被授权者把权限再授予他人。
- **回收语句**：REVOKE 权限清单 ON 对象 FROM 用户，可连带回收其转授出去的权限，形成级联回收。
- **对象层次**：权限可作用于库、表、列等不同粒度，粒度越细管理越灵活也越繁琐。
- **角色组织**：把一组权限打包成角色，再把用户加入角色，避免逐人逐权限重复授予，是权限规模扩大后的标准做法。
- **视图作为权限手段**：只授权用户访问某个视图而不开放底层表，使被授权者只见其应见的数据，实现行与列粒度的访问控制。

```sql
GRANT SELECT, UPDATE ON 员工 TO 张三 WITH GRANT OPTION;

REVOKE UPDATE ON 员工 FROM 张三;
```

> **辨析**：撤回权限时必须考虑**转授链**——若被授权者曾用 WITH GRANT OPTION 把权限授予第三人，回收时可能一并失效。角色与视图解决的是两个不同问题：角色解决授权的**组织效率**，视图解决可见数据的**范围裁剪**。

> **速记线索**：**GRANT 给权限、REVOKE 收权限、WITH GRANT OPTION 管转授**；角色管打包，视图管范围。



#### 嵌入式 SQL 与存储过程、触发器

**嵌入式 SQL**：把 SQL 语句写进宿主语言程序中执行；**存储过程**与**触发器**：把过程逻辑存放在数据库端，由数据库自身调度执行。

- **宿主语言交互与游标**：嵌入式 SQL 以预编译方式识别 SQL 语句、用共享变量传递参数与结果；返回多行时须用游标逐行取出，形成声明、打开、取行、关闭的固定流程。
- **动态 SQL**：语句在运行时才拼装确定，适用于条件与表名不固定的场合，基本思路是先准备语句再执行。
- **存储过程**：把一段带流程控制的 SQL 存放在数据库端，按名调用，优点是减少网络往返、逻辑集中。
- **触发器**：由表上的插入、修改、删除事件自动触发，用于自动维护约束与审计，但触发链隐蔽、调试困难。

> **辨析**：存储过程与触发器的争议集中在**可维护性与可移植性**：逻辑下沉后业务规则分散在应用与数据库两处，版本管理更难；各产品过程语言方言差异大，迁移成本高。实务中倾向把复杂业务留在应用层，数据库只承担数据职责。

> **速记线索**：**嵌入式连宿主、游标取多行、动态拼语句、过程存逻辑、触发器随事件**；五者共同的定位是把 SQL 从交互式使用推向工程化使用。



#### 软考常见问法

**本章考查**：集中在按需求写语句与读语句求结果两类，题型固定、判据明确。

- **给出表结构写查询**：先列出涉及的表与列，再确定筛选条件、分组需求与排序要求，最后按书写顺序组织子句。
- **判断查询结果集**：重点核对 WHERE 与 HAVING 的位置、连接类型、去重与排序的影响，按执行顺序模拟比凭经验判断可靠。
- **说明分组与筛选的差异**：先答时点——分组前与分组后，再答对象——行与组，最后答可用性——能否使用聚合函数。
- **选出可更新视图**：逐条排查定义中是否含聚合、分组、去重、集合运算与多表连接，凡会把多行折为一行者即判不可更新。
- **多表查询的等价改写**：连接、子查询、集合运算三类写法常互为等价，需在结果等价的前提下比较可读性与执行代价。

> **辨析**：判断结果集时最容易忽略的是**空值参与比较**与**去重时机**——空值使条件取值为未知，该行不进入结果；DISTINCT 在投影之后生效，与在投影之前去重的结果并不相同。

> **速记线索**：四类题型对应四条判据——**写查询看子句归属、判结果看执行顺序、答差异看时点与对象、选可更新看是否保行**。
