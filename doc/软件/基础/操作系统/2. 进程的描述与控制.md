## 进程的描述与控制

> **全章主脉**：进程是**资源分配的基本单位**，也是操作系统并发执行的基本载体。本章从"程序如何变成进程"讲起——由**前趋图描述执行顺序、引入进程以刻画并发**，再讲清进程的**定义、状态与转换、控制块 PCB、以及创建/撤销等进程控制**，最后给出进程同步互斥的引论（临界区与准则），为后续章节铺路。

### 前趋图与程序的执行

#### 程序的顺序执行

**程序的顺序执行**指一个程序内部的各条指令（或一个作业中的各程序段）**严格按照书写顺序、一个接一个地执行**。其特征是**顺序性、封闭性与可再现性**：前一段执行完才执行后一段，程序独占全部资源（结果不受外界影响、是封闭的），且只要初值相同、重复执行结果一定相同（可再现）。

- **顺序性**：指令/程序段严格按先后次序执行。
- **封闭性**：程序运行期间独占资源，资源状态只由本程序决定。
- **可再现性**：初值相同则结果可复现，便于调试。

> [!NOTE]
> 提醒内容：顺序执行保证了结果确定性，但**资源利用率低**——CPU 等待 I/O 时空闲。这正是引入多道并发执行的动因。

#### 程序的并发执行

**程序的并发执行**指多个程序（或一个程序的多个程序段）**在同一时间间隔内同时执行**，宏观并行、微观上交替占用 CPU。并发执行突破了顺序执行的封闭性，引入了新的特征。

- **间断性**：程序因共享资源与互相制约而走走停停，不再一气呵成。
- **失去封闭性**：共享资源使程序的运行结果受其他程序影响，运行环境不再封闭。
- **不可再现性**：由于推进速度不定，同样的输入可能得到不同结果（若不加以同步控制）。

> [!WARNING]
> 警告内容：并发执行的**不可再现性**源于"多个程序共享资源且推进速度不定"——同一初值因调度顺序不同可能结果不同。为了让并发程序结果可再现，必须引入进程概念并用同步互斥机制协调，这正是进程管理要解决的核心问题。

### 进程的定义与特征

**进程**是**进程实体的运行过程，是系统进行资源分配和调度的一个独立单位**。进程实体（进程映像）由**程序段、相关数据段和进程控制块 PCB** 三部分组成。引入进程的目的是**更好地刻画程序的并发执行，使并发程序可再现地运行**。

**进程与程序的区别**：

- **动态与静态**：进程是程序的一次执行、是动态的（有创建、运行、消亡）；程序是静态的指令集合，可长期保存。
- **暂存与永久**：进程是暂时的（执行完即撤）；程序是永久的。
- **并发粒度**：进程可并发执行；程序本身不是执行单位、不能并发。
- **对应关系**：一个程序可对应多个进程（多次执行）；一个进程也可执行多个程序。

**进程的四个基本特征**：**动态性**（最基本，进程因创建而生、因调度而运行、因撤销而消亡）、**并发性**（多个进程可同存并发执行）、**独立性**（进程是独立获得资源与独立调度的基本单位）、**异步性**（进程按不可预知速度推进）。

> [!IMPORTANT]
> 重要内容：**进程是资源分配与调度的基本单位，线程是 CPU 调度的基本单位**。判断"进程 vs 程序"，抓住"动态/静态""临时/永久"即可。PCB 是进程存在的唯一标志——没有 PCB 就没有进程。

### 进程的状态与转换

#### 五种基本状态

**进程的基本状态**描述进程生命周期中的主要形态，共五种：**创建态、就绪态、运行态、阻塞态（等待态）、终止态**。它们刻画了进程从诞生到消亡的动态过程。

- **创建态**：进程正在被创建（正在分配资源、建立 PCB），尚未就绪。
- **就绪态**：进程已具备运行条件、只差 CPU，只要被调度即可运行。
- **运行态**：进程正占用 CPU 运行（单 CPU 下任意时刻最多一个进程处于运行态）。
- **阻塞态**：进程因等待某事件（如 I/O 完成）而暂时不能运行，即使给它 CPU 也无法推进。
- **终止态**：进程执行完毕或出错被撤销，系统正在回收其资源与 PCB。

> [!NOTE]
> 提醒内容：区分**就绪与阻塞**最见功力——就绪态是"万事俱备只欠 CPU"，阻塞态是"有了 CPU 也跑不了、在等某事件"。运行态进程只能**由运行转就绪**（时间片到）或**由运行转阻塞**（请求 I/O/等待资源），不能直接转创建或终止。

#### 挂起状态与状态转换图

**挂起状态**是进程**被暂时移出内存（或内存映像调到外存）而处于静止**的状态，引入挂起是为了提高内存利用率、平衡系统负载、便于调试。挂起分为**阻塞挂起**（进程在等待事件且被挂起）与**就绪挂起**（进程已就绪但被移出内存）。挂起与阻塞的区别在于：阻塞是等事件，挂起是**不占内存**，且挂起可由进程自身或系统主动发出。

**状态转换**（活跃部分）要点：

- **就绪 → 运行**：被调度选中分配 CPU（唯一进入运行态的通道）。
- **运行 → 就绪**：时间片用完或更高优先级进程抢占。
- **运行 → 阻塞**：请求资源/等待 I/O/等待信号而主动让出 CPU。
- **阻塞 → 就绪**：所等待的事件发生（如 I/O 完成、被唤醒）。

> [!WARNING]
> 警告内容：**阻塞只能由运行态主动进入，就绪可被唤醒**——阻塞进程不能自己回运行，必须等事件发生后转为就绪、再由调度选中。挂起态中"就绪挂起"与"阻塞挂起"的转换方向不同，做题画状态转换图时按"挂起/激活"两条边分别处理，别混淆。

### 进程控制块

#### PCB 的内容

**进程控制块（PCB）**是操作系统为了管理进程而设置的**专门数据结构，记录进程的全部信息，是进程存在的唯一标志**。系统依据 PCB 感知进程的存在、控制进程的运行。PCB 主要包含四类信息。

- **进程标识符**：内部标识（系统分配的唯一编号）与外部标识（创建者给的名称）。
- **处理机状态**：进程运行时 CPU 各寄存器值（PC、PSW、通用寄存器等），用于进程切换时保存与恢复现场。
- **进程调度信息**：进程状态、优先级、等待/就绪原因、队列指针、运行统计等。
- **进程控制信息**：程序与数据地址、进程同步与通信机制、资源清单、链接指针等。

> [!NOTE]
> 提醒内容：PCB 是**操作系统"描述进程"的数据结构**。进程切换时，系统先把运行进程的现场存入其 PCB、再从目标进程 PCB 恢复现场——PCB 是进程调度与切换的关键。

#### 进程的组织方式

**进程的组织方式**指操作系统如何把系统中众多的 PCB 组织起来，以便查询与管理，常见三种：**链接方式、索引方式与线性方式**。

- **链接方式**：按进程状态（就绪、阻塞等）分别把 PCB 链成队列，用指针链接，如就绪队列、阻塞队列。
- **索引方式**：按进程状态建索引表，表项指向对应 PCB 的首地址，如就绪索引表、阻塞索引表。
- **线性方式**：把所有 PCB 放在一张连续的线性表中，简单但表长固定、查找效率低、不易扩充。

> [!TIP]
> 建议内容：识别组织方式看"队列靠指针还是靠索引表"。**链接方式用指针串队列**（就绪队列、各阻塞队列），**索引方式先按状态分表再指向 PCB**，**线性方式就是一张大数组**。多数通用系统用链接方式。

### 进程控制

#### 进程的创建与终止

**进程控制**是系统通过**原语**对进程实施的创建、撤销、阻塞、唤醒等操作。**原语**是由若干条指令组成、**执行中不可被中断**的原子操作，用于保证进程控制的正确性。进程的创建与终止都由系统调用触发、经原语完成。

**创建进程**（原语 creat）步骤：申请空白 PCB → 为新进程分配所需资源（内存、设备等）→ 初始化 PCB（填标识、状态设为就绪、置初值）→ 插入就绪队列。创建常由**用户登录、作业调度、提供服务、应用进程请求**引发。

**终止进程**（原语 kill）步骤：根据标识找出 PCB → 读出进程状态，若正运行则立即剥夺 CPU → 若有子孙进程须先终止子孙 → 回收全部资源、撤消 PCB。终止由**正常结束、异常结束（越界、非法指令等）及外界干预（被 kill）**引发。

> [!NOTE]
> 提醒内容：**原语是原子操作**——创建或终止一旦开始就不可分割执行完，防止出现"PCB 建到一半进程就绪"的中间态。判断系统调用的功能，看清是"改状态"还是"建/撤 PCB"。

#### 进程的阻塞与唤醒

**进程的阻塞**是进程**因等待某事件（I/O、信号等）而主动从运行态转为阻塞态**的过程，由**阻塞原语 block** 实现。**进程的唤醒**是**使处于阻塞态的进程因所等待事件发生而转为就绪态**的过程，由**唤醒原语 wakeup** 实现。二者必须成对使用、由不同进程完成。

- **阻塞（block）**：调用者把自己投入阻塞队列，转由调度程序重新分配 CPU。
- **唤醒（wakeup）**：事件发生时，由**相关进程或系统**把对应阻塞进程从阻塞队列移入就绪队列。

> [!WARNING]
> 警告内容：**阻塞是进程自己主动调用，唤醒是被别的进程/中断事件唤醒**——一个进程不能唤醒自己。阻塞原语由被阻塞进程执行，唤醒原语由"促使事件发生的另一进程"执行，二者一一对应。阻塞与唤醒必须在成对出现的场合使用，否则进程会因无人唤醒而永久阻塞（饿死）。

### 进程同步与互斥引论

#### 临界资源与临界区

**临界资源**指**一次仅允许一个进程访问的资源**（如打印机、共享变量、某块内存缓冲）。**临界区**指**进程中访问临界资源的那段代码**。多进程并发执行时，对临界资源的访问必须互斥进行——即任一时刻至多一个进程处于临界区内。

**对临界区管理的四项要求（同步机制准则）**：**空闲让进**（无进程在临界区时，应允许一个请求者进入）、**忙则等待**（有进程在临界区时，其他进程必须等待）、**有限等待**（等待进程应在有限时间内获得进入权，避免饿死）、**让权等待**（不能进入时应立即释放 CPU，避免忙等）。

> [!IMPORTANT]
> 重要内容：**临界资源是"对象"（一次一人用），临界区是"代码"（访问该对象的那段）**。进程进入临界区须先"申请"、离开须"释放"，申请与释放之间的代码段不可被并发的另一进程同时进入——互斥即"谁先进、别人先别进"。

#### 同步机制应遵循的准则

**同步机制**用于协调并发进程的执行顺序，其设计应遵循四准则：**空闲让进、忙则等待、有限等待、让权等待**。前三条保证正确性与不饿死，第四条（让权等待）保证不浪费 CPU。

- **空闲让进**：临界资源空闲时，允许请求的进程进入。
- **忙则等待**：已有进程在临界区时，其他请求必须等待。
- **有限等待**：等待进程在有限时间内必能进入，防止无限期等待。
- **让权等待**：进不了临界区的进程应主动让出 CPU（放弃处理机），而不是空转忙等。

> [!NOTE]
> 提醒内容：**软件方法（如皮特森算法）能满足前三条但不一定让权（可能忙等）；硬件方法与信号量中的记录型信号量能让权等待**。判断某同步机制优劣，先看它违反了哪条准则——"忙则等待"与"让权等待"常成对考察。
