## 进程同步与互斥

> **全章主脉**：并发进程共享资源时会产生两类需要协调的问题——**互斥**（同一资源一次只给一个进程用）与**同步**（进程间按一定先后顺序推进）。本章沿"软件方法 → 硬件方法 → 信号量 → 用信号量解题"层层递进。核心要掌握**信号量机制**与 **P/V 操作**，并能用信号量写出互斥、同步的经典解法——这是操作系统的重中之重。

### 进程同步的基本概念

#### 临界区问题

**临界区问题**指如何**保证多个并发进程对临界资源（临界区）的访问互斥进行**，即任一时刻至多一个进程执行它的临界区代码。临界区是进程中访问临界资源的代码段，进入临界区前须申请、离开后须释放。

**临界区问题的解须满足三项要求**：**互斥**（任何时刻最多一个进程在临界区）、**前进/空闲让进**（无进程在临界区且有进程请求时，应让请求者之一进入）、**有限等待**（请求进入的进程应在有限时间内获准进入，避免饿死）。这与上一章介绍的同步机制四准则一致。

> [!NOTE]
> 提醒内容：临界区问题三要求与同步准则本质是一回事——**互斥、有空让进、有限等待**。能否进入临界区由一个进程"进入区"的申请与"退出区"的释放控制，这两段代码不能用普通代码实现，否则会再产生竞态。

#### 同步与互斥

**同步**与**互斥**都是并发进程间的约束关系，但语义不同。

- **同步（直接制约）**：进程间存在**先后依赖**——一个进程要等另一个进程完成某操作后才能继续。如生产者只有等消费者取走数据后才能覆盖缓冲区。同步是"**一方的推进以另一方的某种进展为条件**"。
- **互斥（间接制约）**：进程因**竞争同一独占资源**而相互排斥——一个进程用资源时其他进程必须等待。互斥是"**同一资源不能同时被多个进程用**"。

**区别**：同步强调"有序、等对方做到某步"，互斥强调"独占、你不能进来"。同步需要协调次序，互斥需要保证排他。二者常结合出现，都可用信号量解决。

> [!IMPORTANT]
> 重要内容：同步是"**等你到某点我再走**"（先后次序，直接制约），互斥是"**一个用别人就得等**"（资源独占，间接制约）。判断属于哪种，看进程间是"次序依赖"还是"资源竞争"。做题识别同步信号量与互斥信号量很关键：互斥信号量初值常为 1，同步信号量初值视条件而定。

### 实现临界区互斥的软件方法

#### 单标志法、双标志法与皮特森算法

**软件方法**用纯编程（轮流标志变量）实现互斥，不需硬件或操作系统支持，但各有缺陷。典型有**单标志法、双标志先检查法、双标志后检查法与皮特森算法**。

- **单标志法**：设一共享变量 turn 表示"允许谁进"，两个进程轮流用。**违背"空闲让进"**——若某进程不想进，另一进程也无法进入（被 turn 卡住），资源可能闲置。
- **双标志先检查法**：每个进程先检查对方标志再置自己标志。**违背"忙则等待"（互斥）**——两进程可能同时检查到对方未置标志而都进入临界区。
- **双标志后检查法**：先置自己标志再检查对方。**违背"空闲让进"**——两进程可能都置了标志又都检查到对方标志，结果谁都不进，可能死等。
- **皮特森算法**：结合标志与 turn，先置自己的标志（我要进）、再让 turn 给对方，然后检查"对方想进 且 turn 是对方"才等待。**正确实现互斥、有空让进、有限等待**，是经典软件解法。

> [!WARNING]
> 警告内容：软件方法的"坑"要能指出——**单标志违背空闲让进、先检查违背互斥、后检查违背空闲让进（可能死等）**。皮特森算法三者都满足，是软件解法的完备代表，但它是**忙等**（等待进程空转检查），不满足"让权等待"。掌握每种方法违背哪条准则，是高频考点。

### 硬件同步机制

#### 关中断

**关中断法**指**在进程进入临界区前关中断、离开后开中断**，使整个临界区执行期间不响应中断，从而保证临界区代码的原子执行、实现互斥。这是最简单直接的硬件同步方法。

- **优点**：实现简单，能保证互斥。
- **缺点**：关中断**权力过大**——把关键区对系统和其他进程的影响放大，若在临界区出现故障可能导致系统死机；同时**只适用于单处理器**（多处理器上一个 CPU 关中断不能阻止其他 CPU 访问共享资源）；把关中断的权限交给用户进程也**不安全**，只宜由内核使用。

> [!NOTE]
> 提醒内容：关中断通过"**禁掉时钟中断等一切中断**"让当前进程独占 CPU 到开中断为止，从而天然互斥。但它**只对单 CPU 有效**，且把系统安全寄托于用户进程不乱用关中断——所以关中断/开中断只应由内核（原语）执行。

#### TestAndSet 与 Swap 指令

**TestAndSet（TS 指令，也称 test-and-set）**是一条**原子**指令，它读出并返回某共享锁变量 lock 的原值，同时把 lock 置为 1。**Swap（交换指令）**原子地交换两个变量的值。二者都靠**原子性**实现互斥，不需关中断，可用于多处理器。

**用 TS 指令实现互斥**的思路：设共享布尔量 lock（初值 false 表示锁空）。每个要进临界区的进程循环执行 test-and-set（lock）：若返回原值为 false 说明锁空闲，则本进程取得锁进入临界区；若返回 true 说明已上锁，则循环自旋等待（忙等），直到临界区进程在退出区把 lock 置回 false。

**特性**：

- **优点**：实现简单、适用于多处理器（原子指令不受其他 CPU 干扰）。
- **缺点**：等待进程**忙等自旋、浪费 CPU**，不满足"让权等待"；可能出现进程饿死（多个等待者竞争，个别长期抢不到锁）。

> [!IMPORTANT]
> 重要内容：TS/Swap 用"**原子地读改写**"避免检查与置位之间被打断（这正是先检查后置标志软件法失败的根源）。只要 test-and-set 一条指令原子完成"读旧值并置 1"，就不会有两个进程同时取到 false。记住硬件同步的共同缺点是**忙等**，软件与硬件方法都没解决让权等待——让权要靠信号量。




### 互斥锁与自旋锁

**互斥锁（mutex lock）**是一把**只有上锁（lock/acquire）与解锁（unlock/release）两种状态的同步工具**，用于保护临界区：进程进入临界区前必须先取得锁（acquire），离开后释放锁（release）。互斥锁由一条**原子性的上锁操作**实现——若锁可用则取得并进入临界区，若锁已被占用则**阻塞或自旋等待**直到锁被释放。它是除信号量之外最常见的互斥实现。

**按等待方式分两类**：

- **自旋锁（spinlock）**：上锁失败时**不阻塞，而是原地循环"自旋"反复尝试获取锁（忙等）**，直到锁被释放。优点是无进程切换开销、适合**临界区极短**且**多处理器**场景；缺点是忙等浪费 CPU，不适合临界区长或单处理器下长时间占用。
- **无等待锁/阻塞型互斥锁**：上锁失败时**把进程阻塞（让权等待）**，锁被释放时唤醒等待者。不浪费 CPU，但上锁/解锁可能涉及进程切换、开销较大，适合临界区较长或多进程争用频繁的场合。

> [!NOTE]
> 提醒内容：互斥锁与 TS 指令、信号量的关系——**互斥锁常基于 test-and-set/compare-and-swap 等原子指令实现**；它本质是"只做互斥"的简易同步工具，一般**不能像计数信号量那样表示多个资源**（互斥锁只有 0/1 两种取值），也没有信号量的同步次序编排能力。判断用自旋锁还是阻塞锁，看**临界区长短**与**等待代价**：临界区短、多核忙等可接受则用自旋锁，否则用阻塞型锁。

### 信号量机制

#### 整型信号量与记录型信号量

**信号量（Semaphore）**是**用于进程同步与互斥的、由系统管理的数据结构**，含一个整数型变量 S 与对应的等待队列，只能通过**P、V 两个原子操作**访问，不能被进程随意读写。

- **整型信号量**：S 为整型，P 操作（wait）循环自旋检查 S 是否大于 0、大于 0 才减 1，否则**忙等**；V 操作（signal）把 S 加 1。整型信号量**不满足"让权等待"**（忙等）。
- **记录型信号量**：在整型基础上增加一个**等待队列**。P 操作若 S 大于 0 则 S 减 1 继续，否则**把进程投入 S 的等待队列并阻塞（让权）**；V 操作把 S 加 1，若仍有进程在 S 的等待队列则**唤醒队首进程**。记录型信号量**满足让权等待**，是广泛采用的形式。

> [!NOTE]
> 提醒内容：**整型信号量会忙等**（P 循环空转），**记录型信号量会阻塞让权**（P 时资源不足就把自己挂到等待队列）。现代操作系统与考试默认用记录型信号量。S 的物理含义常被解释为"可用的资源数"：大于 0 表示可用，等于 0 表示恰用完，小于 0 表示有等待者（其绝对值为等待进程数）。

#### P 操作与 V 操作

**P 操作（wait、proberen、申请）**与 **V 操作（signal、verhogen、释放）**是信号量上仅有的两个**原子操作**，P 用于申请资源、V 用于释放资源。

记录型信号量的 P、V 实现要点：

```text
P(S)：                  # 申请一个资源
  若 S 大于 0：S = S - 1
  否则：把当前进程阻塞，投入 S 的等待队列

V(S)：                  # 释放一个资源
  S = S + 1
  若 S 的等待队列不空：唤醒队首（或一个）等待进程
```

**要点解读**：

- P 操作先减后判断：S 减到不小于 0 表示申请到资源继续运行；S 减后小于 0 表示资源已被抢光，进程阻塞入队。
- V 操作先加后判断：加后若等待队列不空则唤醒一个，被唤醒进程可继续。
- P、V 必须**成对出现**（互斥场景一个 P 配一个 V；同步场景可多个），且 P、V 本身是原子操作、执行中不可被中断。

> [!WARNING]
> 警告内容：**P、V 是原子操作、只能由内核提供**。易错点：V 操作**不一定能唤醒成功**——只有当 S 加后仍有等待进程时才唤醒，否则只是把 S 加 1 供后续申请。P 的"先减"记法下 S 可能为负，|S| 表示阻塞等待的进程数。做题时把"S 值随每个 P/V 如何变化"逐步写出，能避免混乱。

### 用信号量实现互斥与同步

**用信号量实现互斥**：为每类临界资源设一个初值为 1 的互斥信号量 mutex，进程进入临界区前执行 P（mutex）、离开后执行 V（mutex）。因为 mutex 初值为 1，第一个 P 得 1 减为 0 进入，第二个进程 P 时 mutex 变负被阻塞，从而保证同时只有一个进程在临界区。

```text
互斥模式（mutex 初值为 1）：
P(mutex)
  临界区代码（访问共享资源）
V(mutex)
```

**用信号量实现同步**：在需要"先执行"的一方 V 一个同步信号量、在需要"等对方执行完"的一方 P 它。例如进程 A 要在进程 B 完成某操作后才能继续，则设同步信号量 S（初值 0），A 在等待处执行 P（S），B 在完成该操作后执行 V（S）——只有 B 执行了 V（S）使 S 从 0 变 1 后，A 的 P（S）才不阻塞。

**互斥与同步的搭配**：当一个进程既要互斥又要同步时，**同步 P/V 通常应放在互斥 P/V 之外（前后），避免死锁**。典型如生产者—消费者，需对缓冲区设互斥信号量、又用两个同步信号量（空槽数、满槽数）协调，实现"缓冲区有空才生产、有货才消费"。

> [!IMPORTANT]
> 重要内容：信号量解题口诀——**"P 申请、V 释放；互斥信号量初值 1、围着临界区；同步信号量协调先后、先做者 V、后做者 P"**。判断一个信号量的角色：初值反映可用资源数，P/V 位置反映等待/唤醒关系。分析死锁风险时，注意不要把"等同步"的 P 放进"等互斥"的临界区内。
