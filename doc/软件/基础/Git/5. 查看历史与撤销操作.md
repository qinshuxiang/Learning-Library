## 查看历史与撤销操作

### 查看提交历史

#### git log 的常用选项

**git log**：按时间倒序列出提交历史，每条包含完整哈希、作者、日期与提交消息；通过选项可以控制显示的详略、条数与过滤条件。

- **-p**：显示每次提交的具体改动（补丁），是最详尽的查看方式。
- **-n**：只显示最近 n 条，如 -3。
- **--stat**：显示每次提交的统计摘要，包括改动了哪些文件、增删多少行。
- **--oneline**：每条提交压缩为一行，只显示短哈希与提交主题。
- **--graph**：用字符画出分支与合并的拓扑图形。
- **--pretty**：自定义输出格式，如 --pretty=format:"%h - %an, %ar : %s"。
- **--author**：只显示指定作者的提交。
- **--since 与 --until**：按时间过滤，如 --since="2 weeks ago"。

```bash
# 图形化加单行，是最常用的历史概览组合
git log --graph --oneline
# * e2f1a9c (HEAD -> main) feat: 支持深色模式
# * b4c8d21 fix: 修复登录超时
# * 9a1e37f chore: 初始化项目
```

> 选项可以自由组合，如 git log --oneline --graph --all 一次展示所有分支的拓扑。选项无须逐一背诵，记住"oneline 看脉络、p 看细节、--author 与 --since 做过滤"即可覆盖绝大多数场景。



### 修改最后一次提交

#### commit --amend 的两种用途

**commit --amend**：用一次新提交**替换**最近一次提交，而不是在其后追加；两种典型用途是补文件与改消息。

- **补文件进上次提交**：漏 add 了某个文件时，先 add 再执行 commit --amend，该文件并入上一次提交。
- **改提交消息**：消息写错时直接执行 commit --amend，在编辑器中重写消息。
- amend 之后旧提交被新提交取代，提交哈希随之改变。

> [!CAUTION]
> **注意内容**：amend 会产生一个新提交去替换旧提交，本质是改写历史。提交一旦推送到远程，其他人可能已基于旧提交工作，此时不要 amend，应改用一次新的修正提交；amend 只适合尚未推送的本地提交。



### 取消暂存与撤销工作区修改

#### restore 的两种用法

**git restore --staged 文件名**：把文件从暂存区退回，取消暂存但保留修改；**git restore 文件名**：丢弃工作区中未暂存的修改，把文件恢复到暂存区或指定提交的状态。

- **restore --staged（取消暂存）**：改动从暂存区退回工作区，内容不丢失，是安全的操作。
- **restore（丢弃修改）**：工作区中被改坏的文件回到最近暂存或提交的状态，改动**直接销毁**。

> [!CAUTION]
> **注意内容**：不带 --staged 的 git restore 丢弃的修改**无法找回**：被覆盖的内容没有进入任何提交或暂存区，Git 没有保存它的副本。丢弃前用 git diff 确认要放弃的范围，不确定时先 add 或先建分支保存现场。



### git reset 三种模式

#### 三种模式的影响范围

**git reset**：移动当前分支的指针到指定提交，并按模式决定是否重置暂存区与工作区。三种模式的影响范围逐级扩大。

- **reset --soft**：只移动分支指针，暂存区与工作区都不动，改动完整保留在暂存区，等待重新提交。
- **reset --mixed**（默认）：移动指针并重置暂存区，改动保留在工作区，需要重新 add。
- **reset --hard**：移动指针并重置暂存区与工作区，改动**全部丢弃**，工作区回到目标提交的样子。

> 三种模式按"动了哪几层"记忆：soft 只动提交历史，mixed 再动暂存区，hard 连工作区一起动，力度递增。reset 的定位是**对未推送的本地提交做后退**，把分支指针挪回去重新整理提交。

> [!WARNING]
> **警告内容**：reset --hard 会**销毁未提交的修改**，且这些修改没有进入任何提交，被覆盖后无法找回。执行前务必确认工作区没有需要保留的内容；对已推送提交的后退不要用 reset --hard，应改用 revert。



### 安全的撤销

#### revert 与 reset 的对比

**git revert**：生成一个**反向提交**来抵消指定提交的改动，历史中多出一条抵消记录，原有提交全部保留。

- revert 不改写历史，任何已有提交的哈希都不变，因此适合**已推送**的提交。
- revert 可以指定任意一次历史提交，如 revert 提交哈希；revert HEAD 抵消最近一次提交。
- **revert 与 reset 的对比**：revert 是**保留历史**的反向提交，reset 是**改写历史**的指针回退；已共享的提交用 revert，本地未推送的提交用 reset。

> 已推送的提交若被 reset 改写，他人拉取会遇到历史分叉，往往需要强推才能同步，协作风险极高；revert 只新增提交，任何人直接 pull 即可对齐。公共分支上的撤销一律优先 revert。



### 检出旧版本

#### checkout 旧提交与分离 HEAD

**checkout 提交哈希**：把工作区切换到指定提交的状态以预览旧版本，此时处于**分离 HEAD（detached HEAD）**状态——HEAD 直接指向某个提交而非分支。

- 分离 HEAD 下可以浏览、编译、运行旧版本，做实验性修改，但此时的提交不属于任何分支，切换离开后可能被 Git 回收。
- 回到最新分支执行 checkout 分支名（如 checkout main）即可；临时的实验内容如需保留，应先在分离状态下新建分支。
- 一句话定位：checkout 提交哈希 是只读式回看，不影响任何分支指针。
