## 串与模式匹配

> **全章主脉**：串（字符串）是**字符的有限序列**，是线性表的字符特例。本章讲串的定义、存储、基本操作，重点掌握**模式匹配**——从**朴素（暴力）匹配 O(mn)** 到 **KMP 算法 O(m 加 n)**，核心是求模式串的 **next 数组**（与改进的 nextval），这是数据结构的高频考点。

### 串的定义与存储

#### 串与子串

**串**是**由零个或多个字符组成的有限序列**，一般记为 S 等于 a1 a2 … an（S 为串名、n 为串长）。**空串**是长度为 0 的串；**空格串**是只含空格的串（长度大于 0，与空串不同）。

**子串**是**串中任意个连续字符组成的子序列**；**主串**是包含子串的串。串中任一字符在串中的位置叫**字符位置**，子串在主串中的位置以子串**第一个字符在主串中的位置**表示。

- **子串**：主串中连续的一段，如 S 等于 abcd 的子串有 a、ab、abc、abcd 等。
- **空串 vs 空格串**：空串无字符（长度 0），空格串有空格字符（长度大于 0）。
- **相等**：两串长度相等且对应位置字符相同。

> [!NOTE]
> 提醒内容：串是**字符的线性序列**，很多教材把串归于线性表范畴（其逻辑结构是线性）。区分"串与子串"：子串必须**连续**，不能隔开取；空串是任何串的子串。

#### 定长顺序存储与堆分配存储

**串的存储结构**常用**定长顺序存储、堆分配存储与块链存储**。

- **定长顺序存储**：用**固定长度数组**存放串，若串长超过数组容量则需截断或用特殊标记（如存储串长）。实现简单但容量固定、难处理变长串。
- **堆分配存储**：用**动态分配的连续空间**存放串（长度由 malloc 分配），长度可变、更灵活，是多数高级语言字符串的实现。
- **块链存储**：用链表存串，每个结点存若干字符（块），便于插入删除，但查找需遍历、指针开销大。

> [!NOTE]
> 提醒内容：串的存储与线性表类似——**定长顺序（数组，快但容量定）、堆分配（动态、长度可变，最常用）、块链（链表，便于修改但慢）**。多数教材串的模式匹配基于顺序存储讨论，理解"串长与字符如何定位"是前提。

### 串的基本操作

**串的基本操作**主要包括求串长、串赋值、串连接、求子串、比较与**定位（模式匹配）**等。

- **StrLength（S）**：返回串 S 的长度。
- **Concat（T，S1，S2）**：把 S1、S2 连接成新串 T。
- **SubString（Sub，S，pos，len）**：求 S 中从位置 pos 起长为 len 的子串。
- **Index（S，T）**：定位——返回子串 T 在 S 中**第一次出现的位置**，无则返回 0。模式匹配是 Index 的实现。
- **比较**：按字典序逐字符比较两串。

> [!TIP]
> 建议内容：串的**模式匹配（定位子串）**是串操作的核心与重难点，单独成节。其余操作（连接、取子串、比较）较直观。掌握串的操作主要是为理解"如何高效找到子串在主串中的位置"服务。

### 简单模式匹配算法

**简单模式匹配（朴素/暴力匹配）**从主串的每个可能起始位置与模式串逐个字符比较：若某位置起完全匹配则成功，否则主串指针**回溯到下一个起始位置**重新与模式串比较。最坏时间为 **O(m 乘 n)**（m 为主串长、n 为模式串长）。

```text
朴素匹配思想：
  i 从主串第 1 位、j 从模式串第 1 位开始
  逐个比较主串[i] 与 模式串[j]
  若相等：i、j 都后移，继续
  若不等：i 回溯到 (i - j + 2)（本次起点的下一位），j 回到 1，重新比较
  若 j 超过模式串长：匹配成功，返回起始位置
```

**缺点**：主串指针**不断回溯**——即使前面已比较过的字符匹配，失败后仍要退回重比，造成大量重复比较，尤其在模式串有较多重复前缀时效率低。

> [!WARNING]
> 警告内容：朴素匹配**主串指针回溯**是低效根源——最坏情况（如主串全是 a、模式串前 n−1 个是 a 末位是 b）下每次都在最后一位失败并回溯，复杂度达 O(mn)。KMP 正是针对"避免主串指针回溯、利用已匹配信息"的改进。

### KMP 算法

#### 前缀函数与 next 数组

**KMP 算法**在匹配失败时**主串指针 i 不回退**，而是让模式串指针 j 依据 **next 数组**跳到合适位置继续比较，从而把时间复杂度降到 **O(m 加 n)**。其核心思想是：**利用模式串自身的重复前缀，匹配失败后直接对齐到可能匹配的位置，避免无谓回溯**。

**next 数组的定义**：next[j] 表示当模式串第 j 位字符匹配失败时，模式串应**回退到第 next[j] 位**继续与主串当前位比较。next[j] 等于**模式串前 j 个字符组成的子串中"最长相等前后缀"的长度加 1**（下标从 1 起）的常用记法；若用下标 0 起则相应约定。约定 next[1] 等于 0（表头，需 i、j 同移）。

**求 next 的关键**：求模式串每个前缀的**最长相等前后缀**——前缀是不含末字符的头部子串、后缀是不含首字符的尾部子串，取两者相等且最长者的长度。

```text
next[j] 的直观理解：
  模式串 前 j-1 位 匹配成功、第 j 位失败时，
  next[j] = 这前 j-1 位的最长相等前后缀长度 + 1（下标1起约定）
  例如模式串 "abaabc"，第4位'a'失败时回退到已匹配的 "aba" 中
  最长相等前后缀 "a"(长1)，故 next[4]=2
```

**匹配过程**：主串指针 i 不回退；当主串[i] 不等于 模式串[j] 时，令 j 等于 next[j]（若 next[j] 为 0 则 i、j 各加 1 重来）。整趟主串只扫描一遍，故 O(m 加 n)。

> [!IMPORTANT]
> 重要内容：**KMP 的核心是"主串不回溯、模式串按 next 跳"**，next 由模式串自身的最长相等前后缀决定。求 next 数组要会：对每个 j，考察模式串前 j 个字符，取**最长相等前后缀长度加 1**。与朴素匹配相比，KMP 消除重复比较，最坏仍 O(m 加 n)。下标从 0 还是 1 起的 next 记法不同，做题先看清约定。

#### 改进的 nextval 数组

**nextval 数组（next 的改进）**解决 next 数组可能产生的"**无意义回退**"：若回退后要比较的字符与失败时相同（模式串[j] 等于 模式串[next[j]]），则此次回退仍会失败，应继续按 next 链回退到更前的位置，把这种情况合并，得到 **nextval**。

**nextval 的求法**：先求 next，再检查：若 **模式串[j] 等于 模式串[next[j]]**，则 nextval[j] 等于 nextval[next[j]]；否则 nextval[j] 等于 next[j]。也就是把"回退后仍与失败字符相同"的跳转顺延到真正不同的位置，减少无谓比较。

```text
求 nextval：
  对每个 j：若 P[j] == P[ next[j] ] 则 nextval[j] = nextval[ next[j] ]
           否则                    nextval[j] = next[j]
  （P 为模式串；下标从 1 起约定）
```

**意义**：nextval 比 next 更"聪明"，能跳过必然失败的相同字符回退，进一步减少比较次数，尤其在模式串含大量重复字符时效果明显。

> [!WARNING]
> 警告内容：next 与 nextval 的区别在于——**next 只按"最长相等前后缀"跳，可能跳回去还要跟一个与失败字符相同的字符比（白比）；nextval 把这种必然失败的相同回退顺延到底**。求 nextval 需先会求 next。判断用哪个：一般题目让求 next 或 nextval 二者其一，会了 next 再看"若回退字符相同则套用 nextval 规则"即可。

### 字符串模式匹配的应用

**字符串模式匹配**的应用非常广泛，KMP 及模式匹配思想用于各类"在文本中查找/替换子串、检测重复"的场景。

- **文本编辑器**：查找与替换功能用模式匹配定位子串。
- **关键词过滤/检索**：在正文中查找给定模式（如搜索引擎、编辑器高亮）。
- **生物信息**：DNA/蛋白质序列中的模式查找。
- **正则表达式**：正则引擎内部结合类似自动机与回溯的匹配思想。
- **病毒特征/恶意代码检测**：在文件中查找特征串。

> [!TIP]
> 建议内容：理解模式匹配的应用价值在于"**在大文本中快速定位子串**"。KMP 保证线性时间，适合文本很长或需多次匹配的场合；朴素匹配在文本短或模式串无重复时也可用。掌握 KMP 的 next 求法在算法与字符串题中很常用。
