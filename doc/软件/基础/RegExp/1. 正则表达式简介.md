## 正则表达式简介

### 什么是正则表达式

#### 定义与作用

**正则表达式（Regular Expression，简称 RegExp）**：是用于**匹配字符串中字符组合的模式**，本质是一套描述文本规则的**模式语言**——用紧凑的符号回答“要匹配什么样的文本”这个问题。

- **验证**：判断字符串是否符合某种格式（手机号、邮箱、密码强度、身份证号）。
- **搜索**：在文本中查找匹配的内容（日志检索、关键词定位）。
- **替换**：批量替换文本中的特定模式（格式转换、脱敏处理）。
- **提取**：从字符串中抽取所需的片段（解析日期、抓取链接、提取参数）。
- **分割**：按模式把字符串拆成数组（混合分隔符、多余空白）。
- **词法分析**：把长文本切成一个个记号（模板引擎、简易解析器）。

```js
const email = "user@example.com";
const emailReg = /^\w+@\w+\.\w+$/;
console.log(emailReg.test(email)); // true
```

> 正则的价值在于**用声明式的模式代替繁琐的字符串判断**：一个手机号校验，手写 if 可能几十行，用正则一行完成。它难在语法紧凑、不直观，但掌握之后处理文本的效率会成倍提升。



#### 正则既是语法也是对象

在 JavaScript 中，正则不只是语法，还是**对象**：RegExp 实例持有 source（模式文本）、flags（标志串）、lastIndex（下一次匹配的起始位置）等状态，可作为值传递、可作为字符串方法的参数。

```js
const digitReg = /\d+/g;

console.log(digitReg.source);    // "\d+"（模式文本）
console.log(digitReg.flags);     // "g"
console.log(digitReg.global);    // true（对应 g 标志的只读布尔属性）
console.log(digitReg.lastIndex); // 0（下一次从哪个位置开始匹配）
```

> 理解“正则是对象”是理解 lastIndex 陷阱的前提：**状态挂在对象上，复用同一个对象就会复用它的状态**。标志一旦确定就无法更改，g、i、m、s、u、y、d、v 只能通过重新创建正则来改变。



#### 方法主体的归属

**方法主体口诀**：test 与 exec 是**正则对象**的方法，match、matchAll、replace、replaceAll、search、split 是**字符串对象**的方法。两者写反是最常见的入门错误。

```js
// 正确：主体与方法匹配
console.log(/\d+/.test("abc123"));      // true（正则对象调 test）
console.log("abc123".match(/\d+/)[0]);  // "123"（字符串对象调 match）

// 错误示范（运行即报错）：
// "abc123".test(/\d+/)   → TypeError: str.test is not a function
// /\d+/.match("abc123")  → TypeError: reg.match is not a function
```

> [!IMPORTANT]
> **重要内容**：口诀——**正则当家 test、exec；字符串当家 match、replace、search、split**。判断某段代码能否运行，先看点号左边是什么对象，再确认方法是否属于它。



### 创建正则表达式对象

#### 字面量创建

**字面量创建**：用一对斜杠 /pattern/flags 直接书写模式，是最常用、最简洁的方式。

```js
const wordReg = /hello/i;
console.log(wordReg.test("Hello World")); // true

// 修饰符写在最后一个斜杠之后，可组合
const globalReg = /a/g;   // g：全局匹配
const multiReg = /^a/m;   // m：多行模式
const allFlags = /a/gimsy;
```

> 字面量在**脚本加载（解析）时编译**，模式固定不变，可读性与性能都最好。模式写成常量时，一律用字面量。



#### 构造函数创建

**构造函数创建**：new RegExp(pattern, flags) 的第一个参数是**字符串**，适用于模式需要**动态拼接**的场景。

```js
const reg = new RegExp("hello", "i");
console.log(reg.test("Hello World")); // true

// 动态生成模式：从变量拼接
const keyword = "abc";
const dynamicReg = new RegExp(keyword, "g");
console.log(dynamicReg.test("abcabc")); // true

// ES6 起允许传入正则并覆盖标志
const clonedReg = new RegExp(/abc/, "gi");
console.log(clonedReg.flags); // "gi"
```

> 构造函数在**运行时编译**，且 pattern 是字符串，因此正则里的反斜杠要写两遍：/\d+/ 对应的构造函数写法是 new RegExp("\\\\d+")。这是构造函数最容易出错的地方——字符串字面量先消费一个反斜杠，正则引擎再消费一个，双重转义少写一遍，new RegExp("\\d+") 得到的实际模式是 d 加一个加号。



#### 两种创建方式的选择

- **模式固定**：用**字面量**，编译早、无双重转义、可读性高。
- **模式动态**：用**构造函数**，可以从变量、用户输入、配置项拼出模式。
- **性能**：字面量在循环中不会被反复重新编译；而**每次求值正则字面量都会创建一个新的 RegExp 对象**（ES5 起），所以字面量不会在多次调用间共享 lastIndex。

```js
// 字面量之间的状态互不干扰：每次求值都是新对象
console.log(/a/g.test("aa"), /a/g.test("aa")); // true true

// 复用同一个对象，lastIndex 才会累积
const reusedReg = /a/g;
console.log(reusedReg.test("aa"), reusedReg.lastIndex); // true 1
console.log(reusedReg.test("aa"), reusedReg.lastIndex); // true 2
console.log(reusedReg.test("aa"), reusedReg.lastIndex); // false 0
```

> [!IMPORTANT]
> **重要内容**：两条铁律：**模式不变用字面量，模式动态用构造函数**；**需要在多次调用之间保持状态（如逐段解析）时，必须把正则存进变量**，否则每次都是新对象、状态无从谈起。



### 何时不用正则

#### 用内置方法替代简单判断

**能用更简单手段解决的需求，不要上正则**：正则的语法成本与出错风险都高于直观的字符串方法，能用内置 API 一步到位的场景写正则属于自找麻烦。

- **包含判断**：String.prototype.includes(substring) 替代 /(关键词)/.test()。
- **前后缀判断**：startsWith(prefix)、endsWith(suffix) 替代 /(^前缀)/、/(后缀$)/。
- **URL 解析**：new URL(value) 提取协议、主机、查询参数，远比正则可靠。
- **数字格式化**：Intl.NumberFormat 与 toLocaleString() 替代千分位正则。
- **日期解析**：Date 对象与专用库（如 date-fns）替代用正则硬解析日期串。
- **复杂结构解析**：HTML 用 DOMParser，JSON 用 JSON.parse，表单校验可用 Zod 这类 schema 库的 regex 能力。

```js
// 简单判断：内置方法一目了然
console.log("hello world".includes("world")); // true
console.log("report.pdf".endsWith(".pdf"));   // true

// URL 解析：内置 API 完胜正则
const url = new URL("https://example.com:8080/path?name=张三");
console.log(url.hostname);          // "example.com"
console.log(url.searchParams.get("name")); // "张三"
```

> [!TIP]
> **建议内容**：选型次序是**内置方法优先、正则次之、专用解析器兜底**。判断标准看三点：需求是否只是固定的字面子串（用 includes）、是否需要模糊模式（用正则）、是否是结构化文本（用专用解析器）。



### 调试与学习资源概览

**调试工具与学习资源**在系列末篇《参考资料与延伸阅读》中完整介绍，日常最常用的三件是：

- **regex101.com**：在线解释器，逐 token 解释模式、展示匹配步骤与回溯步数。
- **regex-vis.com**：把正则渲染成可视化铁路图，长模式的辅助理解工具。
- **console 实测**：不确定返回值时直接在控制台跑一遍，比记忆规则可靠。

```js
const reg = /\d{3}/g;
console.log(reg.toString()); // "/\d{3}/g"
console.log(`${reg.source} | ${reg.flags}`); // "\d{3} | g"
```

> 调试正则的心法是**“缩小、二分、实测”**：把长正则拆成几段逐段验证，用具体字符串试探边界，再拼回去。正则出错往往不是“整条都错”，而是某一段多吃了或少吃了字符。
