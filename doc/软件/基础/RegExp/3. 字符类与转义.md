## 字符类与转义

### 字符类

#### 预定义字符类

**字符类（Character Class）**：用于匹配“某一类字符”而非“某个具体字符”，是正则最基础的构件。

- **.**：任意单个字符（默认不含行终止符）。
- **\d**：数字 [0-9]；**\D**：非数字。
- **\w**：单词字符 [A-Za-z0-9_]；**\W**：非单词字符。
- **\s**：空白字符（空格、制表符、换行等）；**\S**：非空白字符。
- **[abc]**：方括号内任选其一；**[a-z]**：范围；**[^abc]**：取反。

```js
console.log(/\d/.test("abc123"));     // true
console.log(/\d{3}/.test("abc123"));  // true（连续 3 个数字）
console.log(/[aeiou]/.test("hello")); // true
console.log(/[^0-9]/.test("123"));    // false（全数字，无非数字字符）
console.log(/[\u4e00-\u9fa5]/.test("中")); // true（常用汉字区间）
```

> [!NOTE]
> **提醒内容**：大写形式（\D、\W、\S）一律是**小写形式的取反**。注意 \w **只认 ASCII**：它匹配不了中文，也匹配不了 é 这类带变音符的字母，判断汉字请用 [\u4e00-\u9fa5] 或 /\p{Script=Han}/u。



#### 预定义字符类的 ASCII 边界

**\d、\w、\s 的“全”是有限的“全”**：三个简写各有自己的字符清单，其中 \s 覆盖最宽（含全角空格与 BOM），\d 与 \w 则严格限定在 ASCII 内。

- **\d 等价于 [0-9]**：只认 ASCII 数字，**不认全角数字 １ 与阿拉伯-印度数字 ٣**。
- **\w 等价于 [A-Za-z0-9_]**：只认 ASCII 字母与下划线，不认带变音符的字母，也不认中文。
- **\s 覆盖更宽**：除常规空白外，还包含不换行空格 \u00A0、全角空格 \u3000、字节序标记 \uFEFF、行分隔符 \u2028 等。
- **要匹配 Unicode 数字**：改用 \p{Nd}，它同时覆盖半角与全角数字、各语言的数字字符。

```js
// \d 的边界：全角数字与阿拉伯-印度数字都匹配不上
console.log(/\d/.test("１"));  // false（全角数字 1）
console.log(/\d/.test("٣"));  // false（阿拉伯-印度数字 3）

// 要覆盖各语言的数字，用属性转义
console.log(/\p{Nd}/u.test("１")); // true

// \s 反而很宽：全角空格、不换行空格、字节序标记都算空白
console.log(/\s/.test("\u3000"), /\s/.test("\u00A0"), /\s/.test("\uFEFF"));
// true true true

// \w 的边界：带变音符的字母不算单词字符
console.log(/\w/.test("é")); // false
```

> [!IMPORTANT]
> **重要内容**：**\d、\w、\s 三者的“国际化程度”并不一致**——\s 已按 Unicode 定义，\d 与 \w 仍是纯 ASCII。写国际化表单校验时，数字要用 \p{Nd}，字母要用 \p{Letter}，只有空白可以放心直接用 \s。



#### 方括号类的书写细节

**方括号类的内部规则**与正文不同：多数元字符在类内失去特殊含义，但几个字符的位置决定行为。

- **-** 表示范围：[a-z] 是小写字母；放在**类首或类尾**（[-a-z]、[a-z-]）则为字面短横线；放中间表示范围时需转义 [a\-z]。
- **^** 放在类首表示**取反**：[^abc] 是“abc 之外”；不在类首时是字面插入符。
- **] 与 \** 在类内永远需要转义，否则截断类或引出转义序列。
- **. 与 \*、+** 在类内是字面符号：[.] 只匹配点，[.*] 匹配点或星。

```js
console.log(/[a-z-]/.test("-"));  // true（- 在类尾是字面量）
console.log(/[a\-z]/.test("-"));  // true（转义写法等价）
console.log(/[^0-9]/.test("x"));  // true（^ 在类首是取反）
console.log(/[0-9^]/.test("^"));  // true（^ 不在类首是字面量）
console.log(/[.*+]/.test("."));   // true（类内 . 与 * 是字面量）
console.log(/[\]\\]/.test("\\")); // true（类内的 \ 需要转义）
```

> 类内类外是**两套规则**，同一个符号的含义可能完全不同：. 在类外是“任意字符”、在类内是“点”；^ 在类外是锚点、在类首是取反。读别人的模式时先分清符号在哪个区域。



#### 空字符类与全匹配类

**两队特殊写法要注意**：**[] 永远匹配失败**（一个字符都不允许，于是没有任何字符能进这个集合），** [^] 永远匹配成功**（“不是任何字符”的补集就是全部字符，换行也算）。

```js
// 空字符类：一个字符都装不下，恒不匹配
console.log(/[]/.test("a"));  // false
console.log(/[]/.test(""));   // false

// 取反空字符类：恒匹配任意一个字符，包含换行
console.log(/[^]/.test("a"));  // true
console.log(/[^]/.test("\n")); // true（[\s\S] 的老写法可以换成它）

// 二者的等价物对照
console.log(/[^]/.test("\n"), /[\s\S]/.test("\n"), /./s.test("\n")); // true true true
```

> [!CAUTION]
> **注意内容**：**[] 并不是“匹配空字符串”**，它是“什么都不匹配”，常被误当成“可选”。真要表达可选要用 ? 或 {0,1}；真要表达“任意字符且允许换行”，[^] 与 [\s\S] 等价，但 [\s\S] 的可读性更好，团队代码里优先用后者。



#### 字符类内部的组合与取反陷阱

**多个简写放进同一个方括号是“并集”**，但先取反再并集会互相抵消，写出恒真或恒假的类。

- **[abc\d]**：abc 三个字母与所有数字的并集，直接用。
- **[\D\d]**：非数字与数字的并集，等于**全部字符**，恒真——这是最隐蔽的死代码。
- **[\W\w]**、**[\S\s]**：同理都是全部字符，[\s\S] 之所以常被用作“任意字符”，正是利用了这一性质。
- **[^\D]**：对“非数字”取反，结果等价于 \d；套两层取反等于不取反。

```js
// 想写“数字或字母”，结果写成了恒真
const brokenReg = /^[\D\d]$/;
console.log(brokenReg.test("a"), brokenReg.test("7"), brokenReg.test("中")); // true true true

// 正确写法：明确列出两类字符
const letterOrDigitReg = /^[A-Za-z0-9]$/;
console.log(letterOrDigitReg.test("a"), letterOrDigitReg.test("7"), letterOrDigitReg.test("中"));
// true true false

// 双层取反等价于原类
console.log(/[^\D]/.test("7"), /[^\D]/.test("a")); // true false
```



#### 未转义元字符的典型故障

**漏写转义的后果是静默错配而非报错**：. 匹配任意字符，量词元字符未转义时模式直接变成另一个含义，这类故障不抛异常，只在数据上露出马脚。

```js
// 想匹配字面文本 "1.00"，漏转义后变成了另一个模式
console.log(/1\.00/.test("1.00")); // true（正确写法）
console.log(/1\.00/.test("1x00")); // false（. 已转义，x 不匹配）
console.log(/1\.00/.test("100"));  // false

// 对比：未转义的 . 会吞掉任意字符
console.log(/1.00/.test("1.00")); // true（碰巧对）
console.log(/1.00/.test("1a00")); // true！把 "1a00" 也当成了 1.00
console.log(/1.00/.test("100"));  // false

// 未转义的 + 让模式失去字面含义
console.log(/a\+b/.test("a+b")); // true（正确写法）
console.log(/a+b/.test("aaab")); // true！+ 被当成了量词
```

> [!WARNING]
> **警告内容**：**匹配元字符本身必须转义**：. * + ? ^ $ { } ( ) | [ ] \ 共十二个。故障的共同特征是“多匹配了不该匹配的”——功能测试若只测正确样本，永远发现不了。



### 转义规则

#### 需要转义的字符

**转义**：用反斜杠 \ 把一个元字符变成普通字符，或把一个普通字符变成有特殊含义的序列。

- **必须转义的元字符**：. * + ? ^ $ { } ( ) | [ ] \。
- **/** 只在**字面量**中需要转义（它界定正则边界），构造函数中不必。
- **字符类 [] 内部**：多数元字符失去特殊含义，但 ]、\、^（放首位时）、-（放中间表示范围）仍需处理。

```js
console.log(/\$100/.test("价格 $100")); // true（$ 是锚点，需转义成普通字符）
console.log(/[.$*]/.test("a.b"));       // true（字符类内部多数元字符无需转义）
console.log(/\//.test("a/b"));          // true（字面量中的 / 必须转义）
console.log(new RegExp("/").test("a/b")); // true（构造函数中不必）
```

> [!WARNING]
> **警告内容**：两条容易踩的坑：一是**不要在 {n,m} 的数字之间加空格**，/a{1, 3}/ 在非 u 模式下会被当成字面文本 "a{1, 3}"；二是**不要依赖“多余的反斜杠”**，非 u 模式下 /\a/ 等价于 /a/，但 u 模式下这是语法错误——u/v 模式会严格校验转义序列。

```js
// 带空格的量词：整段失去量词含义，变成字面文本
console.log(/a{1, 3}/.test("a"));        // false（没有量词效果）
console.log(/a{1, 3}/.test("a{1, 3}"));  // true（它在找字面文本）
console.log(/a{1,3}/.test("a"));         // true（无空格的正确写法）

// u 模式对转义序列做严格校验
console.log(/\a/.test("a"));             // true（非 u 模式：多余反斜杠被忽略）
// new RegExp("\\a", "u");               // SyntaxError: Invalid escape
```



#### 字面量与构造函数的转义差异

**双重转义**只发生在构造函数中：字符串字面量先消费一层反斜杠，正则引擎再消费一层。

```js
// 字面量：一层转义
console.log(/\d+/.test("123")); // true

// 构造函数：字符串里的 \d 要写成 \\d
console.log(new RegExp("\\d+").test("123")); // true
console.log(new RegExp("\\d+").source);      // "\d+"（引擎收到的模式）

// 典型事故：字符串字面量把 \d 先消费掉了，引擎收到的模式只剩 d+
console.log(new RegExp("\d+").source); // "d+"（不是 "\d+"）
console.log(new RegExp("\d+").test("123abc")); // false！它在找字面 d
```

> [!IMPORTANT]
> **重要内容**：用构造函数写模式时，**逐个数反斜杠**：引擎需要看到 \d，字符串就得写 \\d；引擎需要看到 \\（匹配字面反斜杠），字符串就得写 \\\\。写完打印 source 属性核对，是消除双重转义疑虑的最快办法。



#### 模板字符串与动态模式的转义

**从模板字符串拼模式，反斜杠的层数又多一层**：模板字符串本身也是一层字符串字面量，规则与单双引号一致，但容易因为写法花哨而数错。

```js
// 三条路径得到的 source 完全一致
const keyword = "d";
console.log(new RegExp("\\d").source);        // "\d"（普通字符串）
console.log(new RegExp("\\" + keyword).source); // "\d"（拼接）

// 纯字面反斜杠：引擎要看到 \\，字符串要写四个
console.log(new RegExp("\\\\").source);       // "\\"（匹配一个字面反斜杠）
console.log(/\\/.test("C:\\Windows"));        // true
console.log(/\\/.source);                     // "\\"

// 含引号与反斜杠的路径匹配：先转义再拼，绝不手写
function escapeRegExp(text) {
  return text.replace(/[.*+?^${}()|[\]\\]/g, "\\$&");
}
const pathReg = new RegExp("^C:\\\\" + escapeRegExp("Program Files") + "\\\\");
console.log(pathReg.test("C:\\Program Files\\App")); // true
```

> [!TIP]
> **建议内容**：**记住三条对应关系就不会数错**：引擎要 1 个反斜杠，字符串写 2 个；引擎要 2 个反斜杠，字符串写 4 个；凡是拼用户输入，一律先过转义函数再拼。拿不准时先打印 reg.source 观察，再决定加不加反斜杠。



### 控制字符与码点转义

#### 常用控制字符与不可见字符

**控制字符转义**：用反斜杠加一个字母表示键盘打不出来的不可见字符，它们在处理文件、日志、表格数据时高频出现。

- **\n**：换行符（U+000A）；**\r**：回车符（U+000D），Windows 文本的换行是 \r\n 两个字符连用。
- **\t**：制表符（U+0009）；**\f**：换页符（U+000C）；**\v**：垂直制表符（U+000B）。
- **\0**：空字符（U+0000）。
- **\b**：在**字符类内部**是退格符（U+0008）；在类外是单词边界锚点——同一个转义符号在两个区域含义完全不同，是转义规则里的经典陷阱。

```js
// 制表符分隔的数据行：用 \t 定位分隔位置
console.log(/^姓名\t.+$/.test("姓名\t张三")); // true

// Windows 换行是两个字符，逐行解析前先归一
console.log("a\r\nb".split(/\r?\n/)); // ["a", "b"]
console.log("a\r\nb".split(/\n/));    // ["a\r", "b"]（残留回车符）
```

> [!CAUTION]
> **注意内容**：\b 在**字符类内**匹配退格符、在**类外**是单词边界：/[\b]/ 匹配的是退格符而不是边界，/x\b/ 里写的是边界。排查“为什么 [\b] 匹配不上单词边界”这类问题时，第一步先确认符号写在了哪个区域。



#### 十六进制与码点转义

**码点转义**：用十六进制数直接指定字符的码点。三种写法的位数要求与所需修饰符各不相同，混用是码点转义出错的主要来源。

- **\xHH**：恰好两位十六进制，只能表示 U+0000 到 U+00FF，无需修饰符。
- **\uHHHH**：恰好四位十六进制，只能表示基本多文种平面（U+0000 到 U+FFFF），无需修饰符。
- **\u{n}**：一到六位十六进制，可表示任意码点，**必须配合 u 或 v 修饰符**。
- **\cX**：控制字符，\cI 与 \t 等价（Ctrl 加对应字母的编码）。

```js
console.log(/\x41/.test("A"));     // true（0x41 即字母 A）
console.log(/\u0041/.test("A"));   // true（与 \x41 等价）

console.log(/\u{41}/.test("A"));   // false！无 u 时被解析为字面 u 加 {41}
console.log(/\u{41}/u.test("A"));  // true（加 u 后按码点解析）

console.log(/^\u{1F600}$/u.test("😀")); // true（超出 BMP 只能用 \u{n}）
console.log(/\u{1F600}/.test("😀"));     // false（无 u 表达不了该码点）
```

> \x 与 \uHHHH 的“固定位数”是双刃剑：写 \x411 时引擎解析的是 \x41 加字面 1，而不是码点 U+0411；要表示 BMP 之外的字符（emoji、生僻汉字），只有 \u{n} 加 u 一条路。



#### 数字转义的歧义与严格校验

**数字转义 \1 有双重身份**：模式里存在第 1 个捕获组时，\1 是反向引用；**没有捕获组**时，非 u 模式下按历史规则退化为**八进制转义**（\1 即码点 U+0001），而 u/v 模式下直接抛 SyntaxError。

```js
// 有捕获组：\1 是反向引用
console.log(/(\w)\1/.test("aa")); // true（两个相同的字符）

// 无捕获组：非 u 模式下退化为八进制转义，匹配码点 U+0001
console.log(/\1/.test("\x01"));   // true（历史兼容行为）

// console.log(/\1/u);            // SyntaxError：u 模式禁止该写法
```

> u 与 v 模式对转义序列做**严格校验**：\a、无分组的 \1、不带 u 的 \u{n}，这些“非 u 模式宽容放行”的写法在严格模式下全部变成语法错误。新写正则时建议默认带上 u，让错误在书写阶段就暴露，而不是潜伏成静默错配。



### 不可见字符的排查方法

#### 用码点定位问题字符

**肉眼看不见的字符是数据清洗的头号敌人**：全角空格、不换行空格、字节序标记、零宽字符看起来与普通空白毫无差别，却会让“看起来相同”的两个字符串比对失败。

- **字节序标记 \uFEFF**：常见于 Excel 导出的 CSV 文件首部，会让首列字段名多出一个不可见字符。
- **零宽空格 \u200B、零宽连字 \u200D**：网页富文本复制粘贴时经常带入。
- **不换行空格 \u00A0**：从网页复制的文本里大量存在，它**不属于 \n，却属于 \s**。
- **软连字符 \u00AD**：排版连字遗迹，肉眼完全不可见。
- **全角空格 \u3000**：中文输入法下极易误打，属于 \s，trim() 能去掉。

```js
// 把字符串还原成码点序列，让不可见字符现形
function showCodePoints(text) {
  return [...text].map(
    (char) => "U+" + char.codePointAt(0).toString(16).toUpperCase().padStart(4, "0")
  );
}

console.log(showCodePoints("a\u00A0b\u200Bc"));
// ["U+0061", "U+00A0", "U+0062", "U+200B", "U+0063"]

// 对比：肉眼完全相同的两个字符串并不相等
console.log("a b" === "a\u00A0b"); // false（一个是普通空格，一个是不换行空格）
```

```js
// 批量清理：把各类“伪空白”统一成普通空格，再压缩
function normalizeWhitespace(text) {
  return text
    .replace(/[\u00A0\u2000-\u200A\u202F\u205F\u3000]/g, " ") // 各类空格归一
    .replace(/[\u200B-\u200D\uFEFF]/g, "")                    // 零宽字符删除
    .replace(/\s+/g, " ")                                     // 连续空白压缩
    .trim();
}

console.log(normalizeWhitespace("\uFEFF姓名\u00A0\u00A0张三\u3000"));
// "姓名 张三"
```

> [!WARNING]
> **警告内容**：排查“两个字符串看起来一样却不相等”的问题，**第一步打印码点，不要靠眼睛比对，也不要靠 length 猜**。经验取法是先跑一遍 normalizeWhitespace 看是否还相等：还相等说明差异在别的类别（大小写、变音符、全角半角），不相等说明问题就在不可见空白上。



### 常见错误排查

#### 字符层面的故障清单

**正则“不生效”大多出在字符层面**，排查顺序按出现频率排列如下：

- **元字符未转义**：. 匹配任意字符、+ 变量词，模式含义整个改变。
- **括号未闭合**：/(abc/ 直接抛 SyntaxError。
- **范围写反**：[z-a] 抛 SyntaxError；[A-z] 不报错但混入了 [、\、^ 等符号。
- **量词空格**：{1, 3} 带空格在非 u 模式下是字面文本。
- **大小写混淆**：\D 与 d 完全不同；模式整体还受 i 标志影响。
- **中文输入法符号**：把全角括号（）、全角句号。写进了模式。
- **取反叠加**：[\D\d] 这类“先取反再并集”的写法恒真，等于没写校验。
- **模式里混入不可见字符**：从网页复制的代码片段带入零宽空格。

```js
// 范围写反与“隐形混入”的对照
console.log(/[z-a]/);  // SyntaxError：范围顺序颠倒
console.log(/[A-z]/.test("^")); // true！A-z 混入了中间的六个符号

// 全角与半角的差异肉眼难辨
console.log(/（/.test("（")); // true（全角括号要按原字符匹配）
console.log(/\(/.test("（")); // false（半角转义匹配不了全角字符）
```

> [!TIP]
> **建议内容**：写完模式先做**三样测试**——一个应当匹配的正样本、一个长得像但不该匹配的负样本、一个边界样本。三类样本全部符合预期再上线，能拦下绝大多数字符层错误。测试矩阵的完整方法论见系列第 11 篇《参考资料与延伸阅读》。
