## 实战案例集

### 身份与联系方式

#### 手机号

国内手机号规则的**实用近似**是：1 开头、第二位 3~9、共 11 位数字。

```js
const phoneReg = /^1[3-9]\d{9}$/;

console.log(phoneReg.test("13812345678")); // true
console.log(phoneReg.test("12812345678")); // false（第二位 2 不合法）
console.log(phoneReg.test("1381234567"));  // false（不足 11 位）
```

> 拆解：^ 开头、1 固定首位、[3-9] 第二位、\d{9} 剩余 9 位、$ 结尾。注意**号段会随运营商放号而变化**，这个正则只保证“格式像手机号”，不保证号码真实存在；严格的号段校验需要维护一张号段表，而真实有效性只能靠短信验证码。

实际输入常带分隔符，先清洗再校验是更稳的顺序：

```js
function normalizePhone(value) {
  const cleaned = value.replace(/[\s-]/g, "");
  return /^1[3-9]\d{9}$/.test(cleaned) ? cleaned : null;
}

console.log(normalizePhone("138 0013-8000")); // "13800138000"
console.log(normalizePhone("1380013800"));    // null
```



#### 邮箱

```js
const emailReg = /^[\w.+-]+@[\w-]+(\.[\w-]+)+$/;

console.log(emailReg.test("user@example.com"));    // true
console.log(emailReg.test("a.b-c@sub.domain.cn")); // true
console.log(emailReg.test("user@example"));        // false（缺顶级域）
console.log(emailReg.test("@example.com"));        // false（缺用户名）
```

> 拆解：[\w.+-]+ 用户名、@ 分隔、[\w-]+ 域名主体、(\.[\w-]+)+ 至少一个点分段。需要强调的是：**完整的 RFC 5322 邮箱规则极其复杂**（支持引号、注释、IP 字面量等），上面只是实用简化版；生产环境应以**发送验证邮件**作为最终有效性依据。



#### 身份证号

18 位居民身份证：前 6 位行政区划码、8 位出生日期、3 位顺序码、1 位校验位（数字或 X）。

```js
const idCardReg =
  /^[1-9]\d{5}(?:19|20)\d{2}(?:0[1-9]|1[0-2])(?:0[1-9]|[12]\d|3[01])\d{3}[\dXx]$/;

console.log(idCardReg.test("110101199003072316")); // true（示例号码）
console.log(idCardReg.test("010101199003072316")); // false（首位不能为 0）
console.log(idCardReg.test("110101199013072316")); // false（月份 13 非法）
```

> 这个正则只做**格式与日期合法性**校验，不校验行政区划码是否存在，也不校验最后一位的**校验码算法**（ISO 7064 MOD 11-2）。要做严格校验，应当在通过正则后再跑一遍加权求和；而“这个人是否存在”只能依赖公安系统的实名接口。

用命名捕获组可以把**出生日期直接解析出来**，供后续按年龄分支使用：

```js
const idParseReg = /^(?<area>[1-9]\d{5})(?<year>\d{4})(?<month>\d{2})(?<day>\d{2})\d{3}[\dXx]$/;
const idMatch = idParseReg.exec("110101199003072316");

console.log(idMatch.groups.area);  // "110101"（行政区划码）
console.log(idMatch.groups.year);  // "1990"
console.log(idMatch.groups.month); // "03"
console.log(idMatch.groups.day);   // "07"
```



#### 中文姓名

中文姓名的校验要点是**汉字范围**与**少数民族姓名的间隔号**，写法详见系列第 8 篇《Unicode 与中文处理》。

```js
const chineseNameReg = /^[\p{Script=Han}·]{2,16}$/u;

console.log(chineseNameReg.test("张三"));           // true
console.log(chineseNameReg.test("阿依古丽·买买提")); // true（含间隔号）
console.log(chineseNameReg.test("𠮷水"));           // true（扩展区生僻字）
console.log(chineseNameReg.test("张 三"));          // false（含空格）
```

> 姓名类校验不用 [\u4e00-\u9fa5]——扩展区生僻字会被误判为非法。



### 车辆与证件格式

#### 车牌号

民用车牌的**实用近似**：省份简称 + 发牌机关代字字母 + 5 或 6 位序号（新能源多一位），序号不含字母 I 与 O。

```js
const plateReg = /^[京津冀晋蒙辽吉黑沪苏浙皖闽赣鲁豫鄂湘粤桂琼渝川贵云藏陕甘青宁新][A-HJ-NP-Z][A-HJ-NP-Z0-9挂学警]{5,6}$/;

console.log(plateReg.test("晋A12345"));  // true（常规牌 5 位序号）
console.log(plateReg.test("晋AD12345")); // true（新能源 6 位序号）
console.log(plateReg.test("晋AI2345"));  // false（序号不含 I 与 O）
console.log(plateReg.test("北京A12345")); // false（省份必须是单字简称）
```

> 拆解：第一段是 31 个省份简称的字符类，第二段 [A-HJ-NP-Z] 是发牌机关代字（跳过 I、O，防止与数字 1、0 混淆），第三段 {5,6} 兼容常规牌与新能源牌。挂学警等特殊车种后缀与警牌、军牌格式各有独立规则，此模式只覆盖民牌主干，属于实用近似。



#### 信用卡号格式

银行卡与信用卡的**格式粗筛**：13 到 19 位数字，常按 4 位分组、允许空格或短横线分隔。

```js
const cardReg = /^\d{4}[\s-]?\d{4}[\s-]?\d{4}[\s-]?\d{3,7}$/;

console.log(cardReg.test("4111 1111 1111 1111"));  // true（Visa 常见格式）
console.log(cardReg.test("4111-1111-1111-1111"));  // true
console.log(cardReg.test("4111111111111111"));     // true（连续写法）
console.log(cardReg.test("41111111111"));          // false（位数不足）
```

> 拆解：[\s-]? 允许每组之间有一个可选分隔符，末组 {3,7} 覆盖 13 到 19 位总长。这个模式只做**格式校验**；卡号的真实有效性要用 Luhn 算法校验位验证，业务上只能靠发卡接口。展示时配合 replace 做脱敏（见下文“敏感信息脱敏”）。



### 数字与金额

#### 金额格式校验

```js
const moneyReg = /^(?:0|[1-9]\d*)(?:\.\d{1,2})?$/;

console.log(moneyReg.test("0.50"));   // true（合法，允许 0 开头的小数）
console.log(moneyReg.test("123"));    // true（整数）
console.log(moneyReg.test("01.5"));   // false（前导 0 非法）
console.log(moneyReg.test("1.234"));  // false（最多两位小数）
console.log(moneyReg.test("-5"));     // false（负数需另加分支）
```

> 拆解：(?:0|[1-9]\d*) 保证整数部分要么是单个 0、要么不以 0 开头，(?:\.\d{1,2})? 允许一到两位小数且可省略。需要支持负数时把模式改为 /^-?(?:0|[1-9]\d*)(?:\.\d{1,2})?$/；“1,234.56” 这类千分位输入要先去掉逗号再校验。



#### 千分位分隔

```js
function groupByThousands(value) {
  return String(value).replace(/\B(?=(\d{3})+(?!\d))/g, ",");
}

console.log(groupByThousands(1234567));  // "1,234,567"
console.log(groupByThousands(123));      // "123"
console.log(groupByThousands(1234.56));  // "1,234.56"（小数部分不参与）
```

> 这段模式拆解：\B 定位在**非单词边界**，(?=(\d{3})+(?!\d)) 断言“后面的数字个数正好是 3 的倍数”。它之所以正确，是因为**从右往左**每三位插入一个逗号，正是“后面剩余位数是 3 的倍数”的那些位置。现代代码也可以直接用 Number.prototype.toLocaleString() 或 Intl.NumberFormat。



#### 密码强度校验

**条件叠加**是密码强度校验的核心技巧，断言原理详见系列第 6 篇《断言与锚点》。

```js
// 至少 8 位，且同时包含小写字母、大写字母与数字
const pwdReg = /^(?=.*[a-z])(?=.*[A-Z])(?=.*\d).{8,}$/;

console.log(pwdReg.test("abc12345"));  // false（缺大写字母）
console.log(pwdReg.test("Abc12345"));  // true
console.log(pwdReg.test("Ab1"));       // false（不足 8 位）
```

> 要再加“必须含特殊字符”，并列一个 (?=.*[^\w\s]) 即可，主干无需改动。



### 文本清洗

#### 去掉首尾空格

```js
const str = "  hello world  ";

// 正则实现
console.log(str.replace(/^\s+|\s+$/g, "")); // "hello world"

// 原生方法（推荐）
console.log(str.trim());      // "hello world"
console.log(str.trimStart()); // "hello world  "
console.log(str.trimEnd());   // "  hello world"
```

> 生产代码一律用 trim() 系列，正则写法只作理解用：^\s+ 匹配开头空白、\s+$ 匹配结尾空白、| 表示“或”、g 保证两端都处理。这种“开头或结尾”的模式在数据清洗（如去掉首尾逗号、首尾引号）时很常见。



#### 驼峰与短横线互转

CSS 属性名与 JavaScript 属性名之间的互转是 replace 加替换函数的经典应用。

```js
// background-color-image → backgroundColorImage
function camelize(text) {
  return text.replace(/-([a-z])/g, (match, letter) => letter.toUpperCase());
}

// backgroundColor → background-color
function hyphenate(text) {
  return text.replace(/[A-Z]/g, (letter) => "-" + letter.toLowerCase());
}

console.log(camelize("background-color-image")); // "backgroundColorImage"
console.log(hyphenate("backgroundColor"));       // "background-color"
```

> 拆解：camelize 用捕获组抓住短横线后的那个字母，替换函数里把它转成大写，短横线本身因为不在返回值里而被丢弃；hyphenate 没有捕获组，直接把每个大写字母替换为“短横线加小写”。两者的差别说明：**删掉什么就让它只出现在模式里，保留什么就写进替换结果**。



#### 提取文件扩展名

```js
function getFileExtension(filename) {
  const match = filename.match(/\.([^.\/]+)$/);
  return match ? match[1].toLowerCase() : "";
}

console.log(getFileExtension("报告.终稿.PDF"));   // "pdf"
console.log(getFileExtension("archive.tar.gz")); // "gz"（取最后一个）
console.log(getFileExtension("README"));         // ""（无扩展名）
```

> 拆解：排除型字符类 [^.\/]+ 表示“一串既不是点也不是斜杠的字符”，配合 $ 锚定结尾，天然定位到**最后一个点**之后。写 .\*\.(\w+)$ 也能得到同样结果，但排除型写法没有回溯隐患。



#### 删除代码注释

```js
function stripComments(code) {
  return code
    .replace(/\/\*[\s\S]*?\*\//g, "") // 块注释：惰性防止吞掉后面的代码
    .replace(/\/\/.*$/gm, "");        // 行注释：m 让每一行的 // 都生效
}

const source = "const a = 1; /* 说明 */\n// 备注行\nconst b = 2;";
console.log(stripComments(source));
// "const a = 1; \n\nconst b = 2;"（内容被删，换行骨架保留）
```

> 拆解：块注释用 [\s\S]*? 而不是 .*，因为 . 不匹配换行；惰性量词保证“遇到第一个 */ 就停”，贪婪会把后面所有代码都吞进注释。行注释用 .* 加 gm：m 让 $ 对每一行生效。字符串里恰好含 “//” 的代码会被误删——这正是“正则不解析结构”的又一例证。



#### 敏感信息脱敏

**脱敏**是警务与政务数据处理的高频需求：日志、报表里展示的证件号、手机号、卡号都应保留首尾、遮蔽中段。

```js
function maskSensitive(text) {
  return text
    .replace(/\b(\d{6})\d{8}(\d{3}[\dXx])\b/g, "$1********$2") // 身份证 18 位：留首 6 尾 4
    .replace(/\b(\d{4})\d{8,12}(\d{4})\b/g, "$1********$2")    // 银行卡 16~20 位：留首 4 尾 4
    .replace(/\b(\d{3})\d{4}(\d{4})\b/g, "$1****$2");           // 手机号 11 位：留首 3 尾 4
}

console.log(maskSensitive("身份 110101199003072316"));
// "身份 110101********2316"

console.log(maskSensitive("卡号 6222020200112233456 待核"));
// "卡号 6222********3456 待核"

console.log(maskSensitive("联系 13812345678"));
// "联系 138****5678"
```

> [!WARNING]
> **警告内容**：脱敏正则的替换顺序就是**污染风险顺序**：宽泛的模式会把更长的号码先改掉，导致后续模式匹配不上。身份证（18 位）先于银行卡（16~20 位）、银行卡先于手机号（11 位）正是这个原因，且每条模式都用 \b 定界防止部分命中；上线前用混合真实格式的样本串整体验证一遍，防止规则互相覆盖。



### 提取与解析

#### URL 与域名提取

```js
const urlReg = /^https?:\/\/[\w.-]+(?::\d+)?(?:\/[\w\-./?%&=#]*)?$/;

console.log(urlReg.test("https://example.com"));         // true
console.log(urlReg.test("http://example.com:8080/a/b")); // true
console.log(urlReg.test("ftp://example.com"));           // false（仅 http/https）
console.log(urlReg.test("example.com"));                 // false（缺协议）
```

> 正则校验 URL 的**局限很明显**：它处理不了 IPv6 主机、用户名字段、复杂查询串，也判断不了域名是否合法。浏览器内置的 new URL(value) 才是正确做法，正则只适合做“必须以 http(s) 开头”这类粗筛。

从文本里**抠出主机名**是正则更合适的场景：

```js
function extractDomain(url) {
  const match = url.match(/^https?:\/\/(?:www\.)?([^\/?#]+)/);
  return match ? match[1] : null;
}

console.log(extractDomain("https://www.example.com/path?q=1")); // "example.com"
console.log(extractDomain("http://api.service.cn:8080/v1"));    // "api.service.cn:8080"
console.log(extractDomain("不是网址"));                          // null
```

> 拆解：(?:www\.)? 用非捕获组吃掉可选的 www 前缀，([^\/?#]+) 捕获到第一个斜杠、问号或井号之前的整段主机。遇到只需主机、不要路径的需求，这个模式比完整 URL 校验短得多。



#### 日期校验与解析

日期的**格式**可以完全交给正则，日期的**真实性**（闰年、每月天数）需要代码二次确认。

```js
const dateReg = /^\d{4}-(?:0[1-9]|1[0-2])-(?:0[1-9]|[12]\d|3[01])$/;

console.log(dateReg.test("2024-02-29")); // true（格式合法）
console.log(dateReg.test("2023-02-29")); // true！格式对，但 2023 年没有 2 月 29 日
console.log(dateReg.test("2024-13-01")); // false（月份 13 非法）
console.log(dateReg.test("2024/01/15")); // false（分隔符不符）
```

```js
// 正则粗筛 + 代码精查的标准组合
function isValidDate(text) {
  if (!/^\d{4}-\d{2}-\d{2}$/.test(text)) return false;
  const [year, month, day] = text.split("-").map(Number);
  const date = new Date(text);
  return date.getFullYear() === year && date.getMonth() + 1 === month && date.getDate() === day;
}

console.log(isValidDate("2024-02-29")); // true（闰年成立）
console.log(isValidDate("2023-02-29")); // false（非闰年被代码拦下）
```

> 完整的闰年规则（四年一闰、百年不闰、四百年再闰）理论可以写进正则，但可读性会崩塌。**格式问题归正则，业务问题归代码**，这是日期校验的分工准则。



#### 结构化日志行解析

日志行是**命名捕获组**的最佳舞台：一条模式把时间、级别、正文拆成具名字段。

```js
const logLine = "2026-04-12 01:30:00 [ERROR] Connection refused on port 8080";
const logReg = /^(?<date>\d{4}-\d{2}-\d{2})\s+(?<time>\d{2}:\d{2}:\d{2})\s+\[(?<level>\w+)\]\s+(?<message>.+)$/;

const log = logReg.exec(logLine);
console.log(log.groups.date);    // "2026-04-12"
console.log(log.groups.level);   // "ERROR"
console.log(log.groups.message); // "Connection refused on port 8080"
```

> 拆解：\s+ 兼容不定长空白；级别一段先转义方括号圈定边界，再用命名捕获组 level 记录括号内的单词字符。把这条模式配合 matchAll 扫描整份日志文件，再按 level 分组统计，就是一个最小可用的日志分析器。



#### 提取超链接地址

```js
const html = '<a href="https://example.com">官网</a> <a href="/login">登录</a>';
const hrefReg = /<a\s[^>]*?href="([^"]+)"/g;

for (const match of html.matchAll(hrefReg)) {
  console.log(match[1]); // "https://example.com"、"/login"
}
```

> [!WARNING]
> **警告内容**：正则提取 HTML 属于**粗筛手段**：属性顺序、单双引号、多行属性、注释里的假标签都会让它失手。确定要解析 HTML 时，用 DOMParser 或 jsdom 这类专用解析器；正则只适合格式受控的模板文本。



#### 提取话题标签

```js
const text = "#js #regex #es2022 普通文字";
const tags = [...text.matchAll(/#(\w+)/g)].map((m) => m[1]);

console.log(tags); // ["js", "regex", "es2022"]
```

> 拆解：# 字面匹配，(\w+) 捕获标签正文，matchAll 一次取全。中文话题标签把 \w+ 换成 [\p{Script=Han}\w]+ 加 u 标志即可。这类“带前缀记号的提取”同构于 @提及、$股票代码等场景，换个前缀字符直接复用。



### 应用组合

#### 高亮关键词

关键词高亮 = **转义用户输入** + **替换函数包裹标记**，两者缺一不可。

```js
function highlightKeyword(text, keyword) {
  const safeReg = new RegExp(escapeRegExp(keyword), "gi");
  return text.replace(safeReg, (matched) => `<mark>${matched}</mark>`);
}

console.log(highlightKeyword("RegExp 很强，regexp 很难。", "regexp"));
// "<mark>RegExp</mark> 很强，<mark>regexp</mark> 很难。"

console.log(highlightKeyword("正则的点是特殊字符：a.b", "a.b"));
// "<mark>a.b</mark>"（点已被转义，不会匹配 axb）
```

> 拆解：escapeRegExp 保证关键词里的元字符按普通字符处理（定义见系列第 9 篇《性能与安全》）；gi 标志实现全量与忽略大小写；替换函数用 matched 而不是 $&，能原样保留每个匹配的**原有大小写**。若直接把关键词拼进正则，输入 ( 就会抛 SyntaxError，输入 (a+)+ 就可能触发 ReDoS。



#### 模板插值替换

简易模板引擎的插值就是一个 replace 加捕获组。

```js
function renderTemplate(template, data) {
  return template.replace(/\{\{(\w+)\}\}/g, (match, key) => data[key] ?? match);
}

console.log(renderTemplate("您好，{{name}}！案件 {{caseId}} 已办结。", { name: "张三", caseId: "A2024-017" }));
// "您好，张三！案件 A2024-017 已办结。"

console.log(renderTemplate("缺字段：{{missing}}", {}));
// "缺字段：{{missing}}"（键不存在时原样保留）
```

> 拆解：\{\{(\w+)\}\} 捕获花括号内的键名，替换函数按键查数据对象，查不到用 ?? 回退为原样 match。若键名允许点号与短横线，把 \w+ 换成 [\w.-]+ 即可。这一模式同样适用于把敏感字段（姓名、手机号）批量替换为掩码。
