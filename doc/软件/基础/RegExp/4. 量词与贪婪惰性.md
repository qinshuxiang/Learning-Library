## 量词与贪婪惰性

### 量词

#### 六种基础量词

**量词（Quantifier）**：紧跟在某个**原子**（单个字符、字符类、分组）之后，指定它重复的次数。

- *****：0 次或多次。
- **+**：1 次或多次。
- **?**：0 次或 1 次。
- **{n}**：恰好 n 次。
- **{n,}**：至少 n 次。
- **{n,m}**：n 到 m 次。

```js
console.log(/a*/.test("bbb"));        // true（0 次也算匹配）
console.log(/a+/.test("bbb"));        // false（至少 1 次）
console.log(/colou?r/.test("color")); // true（u 可有可无）
console.log(/\d{2,4}/.test("123"));   // true（2 到 4 个数字）
```

> **量词只作用于紧邻它的那一个原子**，想让一整段重复就必须加分组：/(ab)+/ 是 ab 重复，/ab+/ 是 b 重复。另外**量词不能修饰断言**，/^*/ 会直接抛 SyntaxError。



#### * 与 + 的零次陷阱

**星号量词允许零次**这一性质是若干“莫名其妙就匹配成功”的根源：模式里带 \* 的部分永远可以“什么都不匹配”，导致整个正则变成几乎永真。

```js
// /\d*/ 几乎对任何字符串都返回 true——0 个数字也算匹配
console.log(/\d*/.test("abc"));  // true！
console.log(/\d+/.test("abc"));  // false（+ 至少要求 1 个）

// 可选部分用 ? 或 {0,n} 写清楚下限，避免 * 的零次歧义
console.log(/^1\d{0,2}$/.test("1")); // true（明确允许 0 到 2 位）
```

> [!CAUTION]
> **注意内容**：写验证类正则时优先用 **+** 与 **{n,m}**，慎用 **\***：星号允许零次重复，校验 /\d*/.test(空串) 也是 true，“形同虚设”。确实允许为空时，用量词明示（\d{0,11}）比用 \* 更可读。



### 贪婪与惰性

#### 两种模式的定义

**贪婪（greedy）**：量词默认行为，在能让整体匹配成功的前提下**尽可能多地吃字符**；**惰性（lazy）**：在量词后加 ?，改为**尽可能少地吃字符**。

```js
const html = "<p>标题</p><p>正文</p>";

console.log(html.match(/<p>.*<\/p>/)[0]);
// "<p>标题</p><p>正文</p>"（贪婪：一路吃到最后一个 </p>）

console.log(html.match(/<p>.*?<\/p>/)[0]);
// "<p>标题</p>"（惰性：遇到第一个 </p> 就收手）

console.log(html.match(/<p>[^<]*<\/p>/)[0]);
// "<p>标题</p>"（排除型字符类：既精准又无需回溯，推荐）
```

> 惰性不是“匹配更短”，而是“**先少拿、拿不动了再多加**”。/a*?/.exec("aaa") 得到的是空串而不是 “aaa”——因为它允许 0 次重复。真正的取舍口诀是：**能用排除型字符类 [^x] 解决，就别用 .\*?**，前者几乎不产生回溯。



#### 引号配对的经典案例

**成对引号提取**是区分贪婪与惰性的教科书案例：贪婪会吞掉中间的多段文本，惰性或排除型写法才能正确切分。

```js
const text = 'a "witch" and her "broom" is one';

// 排除型：引号之间不允许再出现引号（首选）
console.log(text.match(/"[^"]+"/g));  // ["\"witch\"", "\"broom\""]

// 惰性：同样能切成两段
console.log(text.match(/".+?"/g));    // ["\"witch\"", "\"broom\""]

// 贪婪：从第一个引号一路吞到最后一个引号
console.log(text.match(/".+"/g));     // ["\"witch\" and her \"broom\""]
```

> 三种写法只有一种语义是错的，但三种都能通过“测试串里有一对引号”的粗检。**写多段提取的模式时，构造一个至少含两段目标的测试串**，一行输出就能暴露贪婪错误。



#### 贪婪惰性在分段提取中的表现

贪婪与惰性的差异在**多段提取**时最为直观：

```js
const config = "a=1;b=2;c=3;";

console.log(config.match(/\w=\d+;/g)); // ["a=1;", "b=2;", "c=3;"]

// 从“键=值”中逐段取出键与值
const pairReg = /(\w)=(\d+);/g;
for (const m of config.matchAll(pairReg)) {
  console.log(m[1], m[2]); // a 1、b 2、c 3
}

// 带量词的捕获组只记住最后一次重复，要用它包住整体时请改用非捕获组
console.log(/(\d)+/.exec("12345")[1]);   // "5"，不是 "12345"
console.log(/(?:\d)+/.exec("12345")[0]); // "12345"
```



### 回溯初探

#### 回溯的工作方式

**回溯（backtracking）**：正则引擎在某条匹配路径走不通时，**退回上一个可选分支**再试。贪婪与惰性能协同工作，全靠回溯机制托底；量词越多、分支越多，回溯的路径就越多。

```js
// 贪婪匹配 "aaa" 中 a+ 的过程：先吃满，再按需吐出
console.log(/a+a$/.exec("aaa")[0]); // "aaa"

// 引擎内部：a+ 先吃掉全部三个 a → a$ 失败 → 吐回一个 a → a$ 成功
```

> 日常使用不需要逐帧追踪回溯，但需要建立两个直觉：**回溯让正则“智能”却也埋着性能隐患**；在 regex101 的调试面板里能看到每一步的回溯过程，多看几次就能理解量词的真实行为。性能风险的完整展开见系列第 9 篇《性能与安全》。



#### 惰性量词并非银弹

**惰性只改变尝试顺序，不消灭回溯**：.\*? 在“找不到目标”的失败场景下同样会穷举位置，某些输入下甚至比贪婪更慢。

```js
// 惰性在成功场景下更省事
console.log("x123y".match(/x.*?y/)[0]); // "x123y"（最短匹配）

// 但失败场景下惰性一样要走到头
console.log(/x.*?z/.test("x123y")); // false（同样穷举后失败）
```

> [!IMPORTANT]
> **重要内容**：性能优化的首选不是“贪婪换惰性”，而是**用排除型字符类收缩搜索空间**：[^<]* 只能在非尖括号字符上尝试，位置数量天然有限，从根上减少回溯分支。**先精确，再惰性，最后才考虑贪婪**。
