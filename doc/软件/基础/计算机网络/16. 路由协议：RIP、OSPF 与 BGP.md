## 路由协议：RIP、OSPF 与 BGP

### RIP 路由信息协议

#### RIP 的定位与算法基础

**RIP（Routing Information Protocol，路由信息协议）**：是运行在自治系统（AS）内部的**距离向量**路由协议，以跳数为度量，实现简单，是 DV 算法的经典实现（算法思想见《路由算法》章）。

- **度量是跳数**：每经过一个路由器加 1，直连网络为 0 跳或 1 跳（实现约定不同）。
- **最大跳数 15，16 即无穷（不可达）**：超过 15 跳的网络一律视为不可达，这决定了 RIP 只能用于中小型网络。
- RIP 报文基于 UDP 传输，**使用 UDP 的 520 端口**——因此 RIP 在协议栈上位于应用层，实现的是网络层路由功能，是“用应用层报文做网络层的事”的典型例子。
- RIP 只与**相邻路由器**交换路由信息，交换的是**完整的路由表**。

> RIP 的三个“只”是高频考点：**只按跳数选路、只和邻居说话、只适合小网络**。跳数度量完全无视链路带宽——两条路一条 1 跳但走 56 Kbps 拨号，另一条 2 跳但全程千兆，RIP 会固执地选前者。

#### RIP 的工作过程

**RIP 让每个路由器维护一张“目的网络 → 下一跳 → 跳数”的路由表，靠周期通告与触发更新把全网的跳数信息逐步收敛**。

- **周期通告**：每个路由器每 **30 秒**把自己的完整路由表发给相邻路由器（RIPv2 用组播地址 224.0.0.9）。
- **更新规则**：收到邻居通告的路由条目时——若跳数更小则更新并记下该邻居为下一跳；若条目来自原来通告该路由的邻居（同一下一跳）则无条件刷新（即使跳数变大，也要跟从，因为源头信息可能已变化）。
- **触发更新**：路由表发生变化时立即发送更新，不必等满 30 秒，以加快收敛。
- **超时处理**：一条路由若 **180 秒**（约 6 个周期）没再收到刷新，判定邻居或链路失效，将该路由标为不可达（16），再过一段时间才从表中删除。

> 细节考点：RIP 的防环沿用 DV 的手段——水平分割、毒性反转、触发更新与“16 为无穷”（详见《路由算法》章）。考试若给一段“RIP 收敛过程”的题，本质是在考 DV 的更新方程，把“跳数 +1、取最小值”套进去即可。

#### RIP 的版本差异与适用场景

**RIP 有两个主要版本，区别在于是否携带子网掩码**，这直接决定了对 VLSM 与 CIDR 的支持。

- **RIPv1**：按分类编址发送，不携带子网掩码，不支持 VLSM 与 CIDR，更新用广播发送，无认证能力，现已很少使用。
- **RIPv2**：通告中携带掩码（前缀长度），支持 VLSM 与 CIDR；改用组播发送，支持明文与 MD5 认证。
- **RIPng**：面向 IPv6 的版本。

**适用场景与局限**：

- 适合网络直径不超过 15 跳的中小型网络，配置简单、占用资源少，常用于小型企业或教学实验网络。
- 局限明显：收敛慢（坏消息计数到无穷）、跳数上限使大网络用不了、选路不考虑带宽、每 30 秒全表广播浪费链路。

> 一句话定位：**RIP 是“够用的简单协议”**——规模不大时它轻量可靠；一旦网络变大、链路多样，收敛慢与度量粗糙的缺陷就不可接受，这时要换成 OSPF。

### OSPF 开放最短路径优先

#### OSPF 的定位与封装

**OSPF（Open Shortest Path First，开放最短路径优先）**：是运行在 AS 内部的**链路状态**路由协议，通过泛洪链路状态通告、全网同步拓扑后用 Dijkstra 算法计算最短路径，专为大中型网络设计（算法思想见《路由算法》章）。

- **直接封装在 IP 数据报中传输，IP 首部的协议号字段取 89**——不像 RIP 依赖 UDP。
- **度量是代价（cost）**，默认取与链路带宽相关的值：典型定义是 10^8 除以带宽（bps），即 100 Mbps 链路代价约 1、10 Mbps 链路代价约 10（实际实现会给最小代价设下限 1）。
- 每个区域内所有路由器维护**一致的链路状态数据库（LSDB）**，各自独立运行 Dijkstra，算出以自己为根的最短路径树，再生成路由表。
- 支持 **VLSM 与 CIDR**，属于无类路由协议。

> OSPF 与 RIP 的第一层对比：**RIP 按“跳数”这种粗糙度量走 DV，OSPF 按“带宽代价”走 LS**。前者邻居间传“我到哪都多远”，后者全网传“我直连邻居的状态”——信息基础完全不同，收敛速度与网络规模上限也天差地别。

#### OSPF 的工作过程

**OSPF 的工作可概括为“建邻居、同步数据库、独立算路”三步**：

1. 路由器通过 **Hello 报文**发现直连链路上的邻居，协商参数后建立**邻接关系**（Hello 周期默认 10 秒，40 秒未收到邻居 Hello 则判定邻居失效）。
2. 邻接建立后，双方交换链路状态通告 **LSA**，把各自知道的拓扑信息同步为一致的 LSDB。
3. 每台路由器以自己为根对 LSDB 运行 Dijkstra，得到最短路径树与路由表。

- LSA 由每台路由器描述“自己的直连邻居及链路费用”，通过可靠的泛洪在全区域内传播。
- 数据库同步完成后，**只发送变化部分（增量更新）**，链路稳定时网络开销很低。
- 可靠性保证：LSA 的扩散需要显式确认（LSAck），丢失会重传，保证全网数据库一致。

> 关键理解：OSPF 是“先让所有人拿到同一张图，再各算各的最短路”。路由器之间交换的是**拓扑事实**而不是“谁到谁有多远”的估计，因此不会出现 DV 的计数到无穷，收敛既快又无环。

#### OSPF 的五种分组

**OSPF 用五种分组完成邻居发现、数据库同步与更新扩散**，可用“H-D-S-U-A”记忆：

- **Hello**：发现与维持邻居关系、选举 DR/BDR。
- **DD（Database Description，数据库描述）**：向邻居描述自己 LSDB 的摘要，用于比对双方数据库差异。
- **LSR（Link State Request，链路状态请求）**：请求对方发送自己缺失或过期的 LSA。
- **LSU（Link State Update，链路状态更新）**：真正携带 LSA 的分组，用于应答请求或主动扩散新 LSA。
- **LSAck（Link State Acknowledgment，链路状态确认）**：对收到的 LSU/LSA 做确认，保证扩散可靠。

> 交互顺序速记：**Hello 相识 → DD 对账 → LSR 索要 → LSU 传送 → LSAck 确认**。考试给出分组名称问作用时，抓住“DD 是目录、LSR 是订单、LSU 是货、LSAck 是回执”就不容易混。

#### OSPF 的区域划分与 Area 0

**OSPF 把 AS 划分成若干区域（area），其中必须存在一个主干区域 Area 0（编号 0.0.0.0），其它区域都直接与 Area 0 相连**，区域之间不直接泛洪 LSA。

- **为什么分区域**：泛洪与 Dijkstra 都局限在区域内部，一个区域的路由变化不会波及全网，路由表也因“区域间只交换聚合后的汇总路由”而大幅缩小，网络规模由此可扩展。
- **区域边界路由器（ABR）**：连接 Area 0 与其它区域的边界路由器，负责把本区域内的路由汇总后通告进主干，再把其它区域的路由引入本区域。
- **AS 边界路由器（ASBR）**：连接其它 AS 的路由器，负责把 AS 外部路由引入 OSPF（如重分发进 BGP 学到的路由）。
- 非骨干区域的 LSA 泛洪被 ABR 挡住：区域内明细路由由 ABR 汇总后以“区域间路由”形式传播。

> 必背结构：**OSPF 的区域是“星形加骨干”**——Area 0 是中心，其它区域像辐条一样接在它上面；区域间通信必须经过 Area 0。若某区域无法直连 Area 0，可用虚链路（virtual link）逻辑上穿越一个区域接到主干。

#### DR 与 BDR 的选举

**在多路访问网络（如一条以太网上接多台路由器）中，OSPF 选举指定路由器 DR 与备份指定路由器 BDR**，其余路由器（DRother）只与 DR、BDR 建立邻接关系，DRother 之间互不建立邻接。

- 不选举会怎样：n 台路由器要两两建立邻接，共 n(n−1)/2 个邻接，LSA 泛洪量随节点数平方增长。
- 引入 DR 后：每台 DRother 只与 DR、BDR 建立邻接，邻接数量降为约 2n，DR 负责把网络拓扑代表性地通告出去，大幅减少邻接与泛洪。
- 选举规则：比较接口优先级（默认 1，0 表示不参与），优先值高者胜；相同则比路由器 ID（Router ID，可用最大环回地址或手工指定），大者胜。**DR 一经选定不会因新加入的路由器而抢占**（非抢占式），直到 DR 失效由 BDR 接替、再补选 BDR。
- 点到点链路（两台路由器直连）不需要 DR/BDR。

> 理解要点：**DR/BDR 是“广播型多路访问网络”的优化手段**，为的是少建邻接、少泛洪；DR 不是“领导”，只是一个替大家代言拓扑的“代表”。考试常问“为什么要 DR/BDR”——答案永远是“减少邻接数量、控制 LSA 泛洪”。

#### OSPF 的特点总结

**OSPF 以收敛快、无环、可扩展著称，代价是协议复杂度与资源开销明显高于 RIP**。

- **优点**：基于带宽的精确度量、收敛快、算法本身无环、支持 VLSM/CIDR、支持认证、分区域可扩展、增量更新省带宽。
- **代价**：配置与排错复杂，对设备内存与 CPU 要求高（要维护 LSDB 并反复跑 Dijkstra），泛洪初期仍有瞬时开销。
- **适用**：大中型企业网、校园网等需要快速收敛与精细选路的域内网络。

> 与 RIP 的经典对比：**RIP 简单够用但收敛慢、跳数封顶；OSPF 复杂但快、准、无环、能长大**。中型以上网络选 OSPF 是行业默认答案。

### BGP 边界网关协议

#### BGP 的定位与封装

**BGP（Border Gateway Protocol，边界网关协议）**：是互联网上目前唯一在使用的**自治系统间（域间）**路由协议，解决“AS 之间如何交换可达性与选路”的问题。

- BGP 属**路径向量（path vector）**算法：通告的不是“距离”，而是到达目的所经过的**完整 AS 路径**。
- 域间路由的本质是**策略**，不是最短路径：是否允许某 AS 的流量经过自己、与哪些 AS 签有商业合同，都由本地策略决定。
- BGP 会话建立在 **TCP 连接之上，使用 TCP 的 179 端口**——依靠 TCP 获得可靠的报文传输，因而 BGP 本身无需再设计确认与重传，路由更新可以按增量发送。
- 面向互联网规模的扩展性：只通告“前缀可达”而不暴露 AS 内部拓扑，互联网上有几十万个前缀，BGP 必须高度可扩展。

> 三个协议的封装对照是必考题：**RIP 走 UDP（520）、OSPF 走 IP（协议号 89）、BGP 走 TCP（179）**。为什么 BGP 敢用 TCP？因为域间路由更新量小、但绝不能丢，直接借 TCP 的可靠传输最省事。

#### eBGP 与 iBGP

**BGP 的会话按“连接双方是否同属一个 AS”分为两类**，解决“外部学进来、内部传出去”两个问题。

- **eBGP（外部 BGP）**：不同 AS 的路由器之间建立的 BGP 会话，用于**从相邻 AS 学习外部网络的可达信息**，并把自己的可达信息通告给邻居 AS。
- **iBGP（内部 BGP）**：同一 AS 内部路由器之间建立的 BGP 会话，用于**把从 eBGP 学到的外部路由在整个 AS 内传播**，使 AS 内的每台路由器都知道“去某外部前缀应从哪个出口走”。
- iBGP 的传递规则：从 eBGP 学到的路由可以通告给 iBGP 邻居，但从 iBGP 学到的路由**不再通告给其它 iBGP 邻居**，因此 iBGP 需要全网状连接或用路由反射器（route reflector）来保证信息传遍全 AS。
- eBGP 邻居通常是直连的两台边界路由器，iBGP 邻居可以跨越 AS 内部的多跳链路。

> 一句话区分：**eBGP 管“外面的路由怎么进来、我的路由怎么出去”，iBGP 管“进来的路由怎么在自家院子（AS）里传遍”**。一个 AS 内若只有边界路由器知道外部路由，内部路由器仍无法转发，所以 iBGP 必不可少。

#### BGP 的通告内容与路径向量防环

**BGP 通告的核心内容是“目的网络前缀 + 到达该前缀的 AS 路径（AS_PATH）”**，AS_PATH 就是防环的关键。

BGP 路由通告的主要属性：

- **NLRI（网络层可达信息）**：通告的目的前缀，如 203.0.113.0/24。
- **AS_PATH（AS 路径）**：到达该前缀依次经过的 AS 号列表，如“AS2 AS3 X”表示从当前 AS 出发经 AS2、AS3 到达 AS X。
- **NEXT_HOP（下一跳）**：去往该前缀的下一跳 IP（通常是通告者的某个接口）。
- **LOCAL_PREF（本地优先级）**：AS 内部自行设定的偏好，值越大越优先，用于本 AS 内统一选路口径。
- **MED（多出口区分度量）**：通告给邻居 AS 的“多出口优选”提示，值小者优先。

**防环原理**：当某 AS 收到一条 BGP 通告时，检查 AS_PATH——**若路径中已经包含自己的 AS 号，说明这条路由绕了一圈又回来了，直接拒绝**。

- 路径向量因此天然防环：路径只会越来越长，回环路径必被识别。
- 接收方在向自己的邻居转发前，会把**自己的 AS 号追加到 AS_PATH 末尾**，让路径信息逐跳累积。

> 与 DV、LS 的本质差异：DV 传“距离数字”所以会计数到无穷，LS 传“拓扑”所以要求全网一致；**BGP 干脆把“走过的路”（AS 路径）原样传给你，你自己看有没有绕圈**——路径向量用“路径本身”换来了策略灵活与防环。

#### BGP 的选路与策略本质

**BGP 不以“全网最短路径”为目标，而以本地策略为准绳**：一台路由器可能从多个邻居学到去同一前缀的多条路径，最终选择遵循一整套决策顺序。

选路决策的大致顺序（本地策略优先于技术指标）：

1. 优先选择 **LOCAL_PREF 最大**的路径（AS 内部策略，最优先）。
2. 次选 **AS 路径最短**的路径（经过的 AS 越少越优先）。
3. 再考虑 MED、路由来源（eBGP 学到的通常优于 iBGP 学到的）等。
4. 仍有并列时，用路由器 ID 等作最终裁决。

**为什么域间不能沿用 DV 或 LS**：

- 互联网的 AS 彼此独立甚至互为商业对手，**没有统一的度量标准**，一个 AS 不会为了“全网最优”而放弃自己的商业利益。
- LS 需要全网一致的拓扑数据库，而 AS 出于安全与商业原因**不愿暴露内部拓扑**。
- DV 的距离数字无策略含义，且坏消息收敛问题在互联网规模上不可接受。

> 商业本质透视：**BGP 是“互联网的路由即商务”**。运营商之间签的是对等（peer）、转接（transit）合同，BGP 策略就是这些合同的技术化表达——考试的“策略路由”考点，落到协议上就是 LOCAL_PREF、AS 路径长度这些决策规则。

### 三种路由协议的对比

**RIP、OSPF、BGP 三个协议在算法、范围、度量、传输与适用场景上全面不同，可逐项对照记忆**：

- **算法基础**：RIP 是距离向量／OSPF 是链路状态／BGP 是路径向量。
- **运行范围**：RIP 与 OSPF 是域内（IGP）／BGP 是域间（EGP，唯一的 EGP）。
- **度量标准**：RIP 是跳数（上限 15）／OSPF 是带宽相关的代价／BGP 是本地策略加 AS 路径长度。
- **报文承载**：RIP 封装于 UDP（520 端口）／OSPF 直接封装于 IP（协议号 89）／BGP 建立于 TCP（179 端口）。
- **交换内容**：RIP 每 30 秒交换完整路由表／OSPF 泛洪 LSA、同步后增量更新／BGP 按触发交换带 AS 路径的路由通告（增量）。
- **收敛表现**：RIP 慢（可能计数到无穷）／OSPF 快且无环／BGP 收敛依赖策略协商，拓扑变化后逐跳传播。
- **环路控制**：RIP 靠水平分割、毒性反转与 16 为无穷／OSPF 靠 LS 数据库天然无环／BGP 靠 AS_PATH 检出自环。
- **VLSM/CIDR**：RIPv1 不支持、RIPv2 支持／OSPF 支持／BGP 支持。
- **适用规模**：RIP 适合中小网络（≤15 跳）／OSPF 适合大中型域内网络／BGP 运行于全球互联网的 AS 之间。

> 最终速记：**“RIP 简单小网络、OSPF 快速大园区、BGP 策略连世界”**。若题目问“去某 ISP 网络应运行什么协议”，第一反应是 OSPF（域内）加 BGP（对接其它运营商），而不是拿 RIP 硬扛。



### 组播与移动 IP

#### IP 组播

**组播（多播，multicast）**：一对多的通信方式，发送方只发送一份数据，沿途路由器按需复制，把分组送交给多个目的主机，避免为每个接收方各发一份的单播浪费。

- 组播使用 **D 类地址 224.0.0.0 ~ 239.255.255.255**（前四位 1110），目的地址是一个**组播组地址**而非单台主机。
- **组播 MAC 地址**：由组播 IP 地址的低 23 位映射到以 01-00-5E 开头的 48 位 MAC 地址。
- **主机加入/离开组**：用 **IGMP（网际组管理协议）** 告知本地路由器加入或退出某组播组。
- **组播路由协议**：路由器之间用 PIM（协议无关组播）等构建**组播分发树**，决定如何在路由器间转发组播分组（每源树 / 共享树）。
- 应用：IP 电视、视频会议、在线直播、远程多媒体教学等一对多场景。

> 对比：**广播**发给同网段所有主机（本地）、**组播**发给订阅了某组的多个主机、**单播**发给特定一台。IPv6 用多播（ff00::/8）取代了 IPv4 的广播。



#### 移动 IP

**移动 IP**：让移动主机在不同网段之间移动时，仍能保持其**归属地址（home address）不变**地通信的技术，从而在移动过程中不被中断正在进行的连接。

- **核心实体**：**本地代理（HA，位于归属网络）**、**外部代理（FA，位于被访网络）**、**转交地址（COA）**（移动节点在被访网络中临时获得的地址）。
- **工作过程**：移动节点到达外地网络后，向本地代理注册其 COA；通信对端发往移动节点**归属地址**的分组，由 HA 通过**隧道**把分组封装转发到 COA，再交给移动节点；移动节点回程可直接发送给通信对端。
- **三角路由问题**：从通信对端发来的数据绕道 HA 再转到移动节点，路径不是最短（三角形），延迟较高；优化方案是让通信对端知道 COA 后直连。

> 移动 IP 解决的是**“保持地址不变下的网络层漫游”**；与应用层的会话保持、以及《无线局域网》中同一 AP 域内的链路层漫游是不同的层级问题。
