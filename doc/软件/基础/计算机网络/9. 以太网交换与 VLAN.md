## 以太网交换与 VLAN

### 以太网交换机的基本原理

#### 交换机的自学习与帧转发

**以太网交换机**：本质是"**多端口网桥**"，工作在**数据链路层**，按帧中的 **MAC 地址**决定把帧转发到哪个端口。它没有手工配置的转发表，而是通过**自学习**动态建立和维护一张 **MAC 地址表**（内容为"MAC 地址 → 端口号"的映射），实现即插即用。

自学习与转发的完整流程（以收到一个帧为例）：

1. **学习源地址**：把帧的**源 MAC 地址**与其**进入端口**记入 MAC 地址表；若表已存在该 MAC 但端口不同，则更新端口号。
2. **查表决定去向**：查 MAC 地址表找**目的 MAC 地址**，分三种情况处理：
   - **命中且端口不同**：把帧**只转发**到表项对应的端口（精确转发，不发到其他端口）。
   - **命中且端口相同**：目的站与源站在同一端口下，说明该帧**无需交换机中转**，**丢弃（过滤）**，不转发回原端口。
   - **未命中**：不知道目的站位于哪个端口，把帧**洪泛**到除进入端口以外的所有端口。
3. **老化表项**：MAC 地址表项有**老化时间**（典型值 300 秒），超过时间未再收到该源地址的帧就删除，以跟随站点位置的变化。

> 交换机的转发只依据**MAC 地址**：它工作在数据链路层，不解析、不关心帧里的 IP 地址。**局域网内靠 MAC 转发、跨网才由 IP 选路**，这是"交换机"与"路由器"职责分工的根本界线。



#### 交换机的三种帧转发方式

按"接收多少再转发"划分，交换机有三种转发方式，在时延与可靠性之间取舍。

- **【存储转发（store-and-forward）】**：把帧**完整接收**并校验 FCS 后再转发。能丢弃坏帧、不传播错误，可靠性最高；但整帧收完才开始转发，**时延最大**。
- **【直通式（cut-through）】**：只读到帧的**目的 MAC 地址**（6 字节）就立即开始转发，无需等完整帧。**时延最小**，但无法检错，可能把坏帧也转发出去。
- **【无碎片式（fragment-free）】**：读到帧的前 **64 字节**再转发。由于冲突残帧都短于 64 字节，此法能过滤掉大部分坏帧，时延介于前两者之间，是直通式的改进。

> 三种方式的取舍口诀：**"存储转发最稳最慢，直通最快但可能传错，无碎片折中"**。交换机选择哪种方式取决于对"低时延"与"低误传率"的侧重，现代高端交换机多采用存储转发以保证网络质量。



#### 交换机与集线器的区别

交换机与集线器外形相似（都是星形拓扑的中心设备），但工作层次与性能完全不同。

- **工作层次**：集线器在**物理层**，只再生比特、不理解帧；交换机在**数据链路层**，能识别帧与 MAC 地址。
- **冲突域**：集线器所有端口是**一个冲突域**；交换机**每个端口一个独立冲突域**。
- **带宽**：集线器端口**共享**带宽、半双工；交换机端口**独享**带宽、可全双工。
- **转发方式**：集线器把收到的比特向所有端口广播（站点自己过滤）；交换机按 MAC 表**定向转发**，只有目的端口收到帧。

> 结论速记：**集线器是"物理层共享总线"，交换机是"链路层并行交换"**。同一台 PC 从集线器换接到交换机，网卡仍使用相同的 MAC 帧——区别只在交换机能隔离冲突域、让多个端口同时通信。



### 冗余链路与生成树协议

#### 冗余链路与环路危害

**冗余链路**：是网络为**提高可靠性**而故意部署的多余路径——交换机之间用多条链路连接，单条链路故障时数据可走备用路径。但二层网络与三层不同，数据帧**没有 TTL（生存时间）**，一旦存在物理环路就会引发严重后果。

环路引发的三大问题：

- **广播风暴**：广播帧在环路上被反复洪泛、无限循环复制，数量指数增长，很快占满链路与交换机处理能力，导致网络瘫痪。
- **MAC 地址表抖动**：同一 MAC 地址的帧从环路的两个方向交替到达，交换机从不同端口反复学习到该地址，地址表项被来回改写，转发决策混乱。
- **多帧副本**：单播帧也可能沿环路产生多个副本到达目的站，造成接收混乱与带宽浪费。

> 可靠性与环路的矛盾：**冗余链路带来可靠性，也带来环路；二层帧无 TTL，环路不能靠"跳数衰减"自愈**。破解之道不是拆掉冗余链路，而是让交换机在逻辑上"剪掉"一条路径——这正是生成树协议的作用。



#### 生成树协议 STP 的工作原理

**生成树协议（STP，Spanning Tree Protocol）**：是 IEEE 802.1D 定义的无环化协议。它在物理上存在环路的交换网络中，让交换机互相交换信息，共同计算出一棵**逻辑上的无环树**，然后**阻塞**树外的冗余端口；链路故障时重新计算并恢复被阻塞的路径。

算法核心概念：

- **BPDU（网桥协议数据单元）**：交换机之间互发的配置消息，携带网桥 ID、路径开销等，是计算生成树的"选票"。
- **根桥（根交换机）**：网桥 ID（优先级＋MAC 地址）最小的交换机被选为**根桥**，整棵树的根。
- **根端口（RP）**：每个非根交换机上"到根桥路径开销最小"的端口，负责向根桥方向转发。
- **指定端口（DP）**：每条链路段上"到根桥开销最小"的端口（通常根桥侧端口即为指定端口），负责向该网段转发。
- **阻塞端口**：既不是根端口也不是指定端口的端口进入**阻塞状态**——不收发数据帧（仅接收 BPDU 用于侦听拓扑变化）。

端口状态变迁与收敛：

1. 交换机上电后各端口从**阻塞**开始，依次经过**监听、学习**状态，最终稳定为**转发**（树上的端口）或保持**阻塞**（树外的端口）。
2. 状态收敛需要计时器配合，经典 STP 收敛时间典型值为 **30～50 秒**级别。
3. 链路故障后，交换机重新交换 BPDU、**重新计算生成树**，把原阻塞的备用端口放开，完成拓扑恢复。

> 后续演进：**RSTP（快速生成树，802.1w）** 改进状态机与握手机制，收敛时间缩短到**秒级甚至亚秒级**；**MSTP（多生成树）** 则把多个 VLAN 映射到不同生成树实例，实现负载分担。三者一脉相承：都是"用阻塞冗余端口的代价，换取无环的二层网络"。



### 虚拟局域网 VLAN

#### VLAN 的概念与作用

**VLAN（Virtual Local Area Network，虚拟局域网）**：是在**一个物理局域网**上，通过交换机配置**逻辑划分**出的多个相互隔离的广播域。每个 VLAN 是一个独立的广播域，**同 VLAN 的成员二层互通，不同 VLAN 的成员二层隔离**，效果如同把一台交换机变成了多台互不相通的独立交换机。

VLAN 要解决的三大问题：

- **广播风暴**：传统大型局域网所有节点同处一个广播域，节点越多、广播帧越频繁，网络负载与处理开销越高，可能引发广播风暴。VLAN 把广播限制在每个 VLAN 内部，缩小广播域。
- **安全隐患**：所有节点暴露在同一广播域时，敏感节点（财务服务器、数据中心）易被任意主机探测攻击。把敏感节点划入独立 VLAN 可限制访问面。
- **管理不便**：按物理位置建网时，部门调整意味着重新布线。VLAN 让节点**逻辑分组不受物理位置约束**，成员关系由配置决定、随交换机端口调整即改。

> 关键点辨析：VLAN 的隔离是**二层（链路层）隔离**——不同 VLAN 的节点即使连在同一台交换机上，也不能直接二层通信；若需互访，必须经过**路由器或三层交换机**进行三层转发，即"不同 VLAN 形同不同子网"。



#### VLAN 的划分方式

VLAN 按"如何决定一个节点属于哪个 VLAN"分为三种典型划分方式。

- **【基于接口（端口）划分】**：管理员配置**端口与 VLAN 的映射**，节点连到哪个端口就属于哪个 VLAN。
  - 优点：配置简单直接，是最常用的方式。
  - 缺点：用户更换接入端口后 VLAN 会变，需重新配置。
- **【基于 MAC 地址划分】**：管理员配置**主机 MAC 地址与 VLAN 的映射**。
  - 优点：用户终端**更换端口仍属原 VLAN**，适合移动性强的场景（如笔记本在楼内各处接入）。
  - 缺点：要预先登记大量 MAC 地址，初装与维护开销大。
- **【基于 IP 地址划分】**：按节点的 **IP 地址（或上层协议）** 划分 VLAN，可跨越路由器关联多个局域网的主机。
  - 优点：逻辑性强、可跨三层设备组织。
  - 缺点：依赖 IP 配置，三层查表开销大，实际应用较少。

> 划分方式的取舍：**基于端口最普遍、基于 MAC 最灵活、基于 IP 最"跨界"**。考试常以"用户换了座位想保持 VLAN 不变"来考——应选基于 MAC 地址的划分。



#### 802.1Q 标签与 VLAN 帧

**802.1Q** 是定义 VLAN 标签的 IEEE 标准。当帧在交换机之间（Trunk 链路）传输时，交换机会在**标准以太网帧的源地址字段之后、类型字段之前**插入 **4 字节的 VLAN 标签**，使对端交换机能够识别该帧属于哪个 VLAN；帧到达 Access 端口时标签被剥离。

VLAN 标签（4 字节）的组成：

- **TPID（2 字节）**：标签协议标识符，固定为 0x8100，用于识别"这是一个带 802.1Q 标签的帧"。
- **TCI（2 字节）**：标签控制信息，内含：
  - **优先级（3 位）**：802.1p 优先级，用于 QoS（服务质量管理）。
  - **CFI/DEI（1 位）**：规范格式指示符，以太网中通常为 0。
  - **VID（12 位）**：VLAN 标识符，取值范围 0～4095，其中 0 与 4095 保留，**实际可用的 VLAN 号为 1～4094**。

插入标签后的帧变化：

- 插入位置在源地址与类型字段之间，因此对上层协议（类型字段及以后）透明。
- 标签参与 FCS 计算，插标签的交换机须**重新计算帧尾的 FCS**；带标签帧的总长上限由 1518 字节增至 **1522 字节**。

> 记忆要点：**802.1Q 标签插在"源 MAC 之后"，由 TPID＝0x8100 识别，VID 有 12 位、可用编号 1～4094**。带标签的帧只存在于交换机之间的链路上，普通主机收发的是无标签的标准以太网帧。



#### Access 端口与 Trunk 端口

交换机的端口按对 VLAN 标签的处理方式分为 **Access 端口**与 **Trunk 端口**两类（还有介于两者之间的 Hybrid 端口，此处从略）。

- **【Access 端口（接入端口）】**：用于连接**终端主机**（PC、服务器、打印机）。
  - 只属于**一个 VLAN**（其 PVID 即所在 VLAN）。
  - 收到主机的**无标签帧**时，打上该端口所属 VLAN 的标签后按 VLAN 转发。
  - 把帧发给主机前，**剥离 VLAN 标签**——普通主机不认识也不应收到带标签的帧。
- **【Trunk 端口（干道端口）】**：用于**交换机与交换机之间**（或交换机与路由器之间）的连接。
  - 可同时承载**多个 VLAN** 的流量，帧在 Trunk 上以**带 802.1Q 标签**的形式传输。
  - 对收到的**无标签帧**，按端口的 **PVID（缺省 VLAN，通常为 VLAN 1）** 处理；PVID 对应的"本征 VLAN"帧在 Trunk 上默认不打标签。
  - 两台交换机的 Trunk 端口配置必须一致，才能正确传递各 VLAN 的帧。

> Access 与 Trunk 的分工速记：**Access"对主机，一个 VLAN，进打标出撕标"；Trunk"对交换机，多 VLAN 跑，帧始终带标（本征 VLAN 除外）"**。判断一道帧转发题先看端口类型：Access 侧先剥标签、Trunk 侧靠标签找 VLAN，两侧的 VLAN 映射一致才能互通。



#### VLAN 间路由与三层交换

**VLAN 间路由**：不同 VLAN 之间是二层隔离的，互相通信必须经由三层设备转发。由于每个 VLAN 通常对应一个独立 IP 子网，VLAN 间路由在本质上就是**子网间路由**，常用两种实现。

- **路由器（单臂路由）**：用一条 Trunk 链路把交换机与路由器的**一个物理接口**相连，在该接口上配置多个**子接口**（每个子接口绑定一个 VLAN 的 IP 网关）。数据经子接口查路由表转发，实现 VLAN 互访。缺点是所有跨 VLAN 流量都挤在一条链路上，易成瓶颈。
- **三层交换机**：在交换机上启用路由功能，为每个 VLAN 配置**虚拟接口（VLANIF/SVI）**作为该 VLAN 的网关；VLAN 间流量在交换机内部直接路由，无需外接路由器。

**三层交换（三层转发）**：三层交换机对跨 VLAN 的第一个数据包，交由 CPU 完成传统路由并**建立硬件转发表项**；后续同流的包直接由硬件**线速转发**，即"**一次路由，多次交换**"。

- 第一包：走软件路由，逐跳查找路由表（慢但只发生一次）。
- 后续包：匹配已建立的硬件流表，在交换机内部快速转发（快且不经过 CPU）。
- 意义：兼顾"路由的灵活性"与"交换的速度"，是园区网三层架构的标准做法。

> [!IMPORTANT]
> **重要内容**：同 VLAN 靠二层交换直达，跨 VLAN 必须三层路由。规模小用单臂路由省钱但瓶颈明显，规模大用三层交换机做"一次路由多次交换"。路由协议的细节见网络层相关章节，本层只需理解"VLAN 是二层隔离、三层打通"这一框架。
