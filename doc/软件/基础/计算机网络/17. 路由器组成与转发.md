## 路由器组成与转发

### 路由器的地位与功能

#### 路由器的工作层次与基本功能

**路由器（router）**：工作在网络层的互连设备，负责连接两个或多个计算机网络，根据 IP 数据报中的目的地址查询路由，并把分组从合适的端口转发出去。

- **连接异构网络**：可以互联局域网与广域网、有线与无线、不同链路层技术的网络，因为路由器工作在 IP 层，与下层链路技术无关。
- **按网络号转发**：路由器依据目的 IP 中的**网络号**决定转发方向，因此要求互联网上**每个网络都有全网唯一的网络号**，否则分组无法被正确路由。
- **隔离广播域与冲突域**：广播不会穿过路由器，路由器两侧是相互独立的广播域。
- **选路与转发**：运行路由协议（RIP、OSPF、BGP）建立路由视图（选路），再按转发表逐分组执行转发（转发细节见本文件后文）。

> 路由器与交换机的工作层次差异：**交换机在数据链路层按 MAC 地址转帧，路由器在网络层按 IP 地址转发分组**。家用宽带里“光猫—路由器—交换机—电脑”的串法，正是两层设备各司其职的写照。

#### 家用路由器是一体化设备

**家用路由器 = 路由器 + 交换机 + 无线接入点 + NAT + DHCP 服务器等功能的一体化设备**，消费者买到的其实是多种网络功能的合体。

- **路由功能**：连接“内网”与“运营商外网”两个网络，执行 NAT 转发。
- **交换功能**：机身背面一排 **LAN 口**背后就是一台小型以太网交换机，多个 LAN 口设备可二层互通。
- **无线接入点功能**：Wi-Fi 本质是让无线终端以无线方式接入这台“交换机”。
- **NAT 与 DHCP**：对外做网络地址转换，对内自动分配 192.168.x.x 私有地址。
- **WAN 口与 LAN 口**：与广域网（运营商）连接的端口叫 **WAN 口**（通常接光猫/入户线），与局域网连接的端口叫 **LAN 口**（接电脑、交换机、打印机）。路由器依据“从哪个口进来、目的地址指向哪一侧”决定是否做 NAT 与路由。

> 记忆要点：**WAN 是“上联外网”、LAN 是“下联内网”**。台式机网线插到 LAN 口、宽带线插到 WAN 口，这是家用路由器最标准的接法；专业路由器端口不分 WAN/LAN，由配置决定角色。

### 路由表与路由来源

#### 路由表的来源

**路由表**：路由器维护的“目的网络 → 下一跳（或出接口）→ 度量”的映射表，是转发决策的依据。表中条目按来源可分为四类：

- **直连路由**：路由器接口配置好 IP 地址并启用后自动生成，目的网络是与接口直连的子网，无需任何协议参与。
- **静态路由**：管理员手工配置的“目的网络 → 下一跳”条目，不随拓扑变化而更新（见《路由算法》章）。
- **动态路由**：RIP、OSPF、BGP 等路由协议自动学习并维护的路由（见《路由协议：RIP、OSPF 与 BGP》章）。
- **默认路由**：目的为 0.0.0.0/0 的特殊条目，匹配一切未命中更具体条目的分组，常用于企业出口“其余流量全部走互联网”。

> 一个目的网段可能同时存在多种来源的路由，这时靠**路由优先级**裁决：数值越小优先级越高，路由器把优先级最高的来源（通常直连最高、其次静态、再动态）选为正式路由。**数值取何值由厂商定义，考试按题目给定值比较大小即可**。

### 控制平面与数据平面

#### 两大平面的划分

**路由器内部在逻辑上划分为控制平面与数据平面**，分别承担“决定怎么走”与“立刻送出去”两类工作，这是理解现代路由器与软件定义网络的关键。

- **控制平面（control plane）**：运行路由协议（RIP/OSPF/BGP），结合直连与静态路由，经过路由优先级比较选出最优路径，形成路由表并把转发信息下发到数据平面。它更新慢、可容忍时延，由 CPU 软件执行，又称“慢路径”。
- **数据平面（data plane）**：逐分组执行转发：查转发表、改 TTL、重封装、从正确端口发出。它要求每微秒级处理成千上万分组，通常由专用硬件（ASIC 芯片）执行，又称“快路径”。

> 平面视角的经典考点：**转发是“查本地表、立即执行”，路由是“全网协作、慢慢收敛”**。所以路由器升级路由协议不会影响正在转发的流量（控制面与数据面解耦），这也是现代路由器高可用的设计基础。

#### 软件定义网络 SDN

**SDN（Software-Defined Networking，软件定义网络）**：把网络的控制平面从各路由器中抽离出来，集中到一台逻辑上的远程控制器，路由器/交换机只保留数据平面，按控制器下发的**流表**转发。

- 控制平面集中：控制器掌握全网拓扑，统一计算转发路径，再通过南向接口（如 OpenFlow）把流表下发给每个转发设备。
- 数据平面通用化：转发设备退化为“按表项匹配 + 动作”的通用硬件，支持灵活编程。
- 好处：全网路径可集中优化与快速调整、策略下发即改全网行为、设备可白盒化降低成本；代价是控制器成为新的关键点，需高可用设计。

> 对应关系：传统路由器“控制平面在路由器里”（分布式），SDN“控制平面搬去远程控制器”（集中式）。**SDN 是控制平面与数据平面物理分离的极致形态**——题目若问“SDN 把什么和什么分开”，答案就是转发与控制分离。

### 转发的完整流程

#### 路由器转发一个分组的步骤

**路由器收到一帧到发出下一帧，经历“解封装、查表、更新首部、再封装”四个动作，全程只关心到网络层为止的信息**。

1. **链路层解封装**：去掉帧头帧尾取出 IP 数据报，校验 IP 首部（IPv4 首部校验和）是否正确。
2. **查转发表**：提取目的 IP 地址，按**最长前缀匹配**在转发表中查找对应条目；查不到则丢弃该分组（可能回送 ICMP 目的不可达）。
3. **更新 IP 首部**：把生存时间 TTL 减 1，若减为 0 则丢弃（并回送 ICMP 超时报文）；IPv4 还需重新计算首部校验和（因此逐跳都变）。
4. **重新封装**：根据下一跳信息构造新帧头——源 MAC 改为本路由器出接口的 MAC，目的 MAC 改为下一跳路由器（或最终目的主机）的 MAC，然后从对应输出端口发出。

- 输出链路的 MTU 小于数据报长度时：IPv4 路由器可分片后再发（各片在目的端重组）；IPv6 路由器不分片，直接丢弃并回送“分组过大”（详见《IPv6》章）。
- **转发过程中路由器不查看传输层及以上内容**：端口号、应用数据对转发透明，这符合“端到端原则”。

> 地址变化规律的必考点：**转发全程 IP 源/目的地址保持不变，MAC 地址每一跳都被改写**。帧在第 1 跳用的源 MAC 是发送方网卡、目的 MAC 是第 1 个路由器；到第 2 跳时源 MAC 变成第 1 个路由器的出口 MAC……MAC 逐段“接力”，IP 一以贯之。

> 与“不看上层”相对的例外：NAT 需要看端口（NAPT 改写端口号）、ACL 防火墙需要按端口过滤（详见《ARP、DHCP、ICMP 与 NAT》章）。日常转发走“不看上层”的快路径，安全功能在旁路叠加。

#### 最长前缀匹配与硬件查找

**路由器查转发表使用的是最长前缀匹配**：目的 IP 可能同时匹配多条带前缀的路由，选择前缀最长（范围最具体）的那条（规则见《子网划分与 CIDR》章）。

- 软件逐条比对速度慢，现代路由器的转发表查找由**三态内容寻址存储器（TCAM）**等专用硬件完成：把所有前缀放入 TCAM，一次并行比较即可在恒定时间内得到最长匹配结果，支撑线速转发。
- 转发表的表项为“前缀 + 动作”结构，比路由表更贴近硬件（详见本文件“路由表与转发表”部分）。

> 记忆锚点：**软件路由表跑控制面，TCAM 转发表跑数据面**。考试问“路由器如何做到快速转发”，答“硬件并行查表 + 只做 IP 层处理”即可。

### 路由器的内部结构

#### 输入端口

**输入端口**：是分组进入路由器的第一站，承担物理接收、链路层处理与转发查找三件事。

- **线路端**：接收并解码物理信号，完成链路层解封装与差错校验。
- **查找与决策**：提取目的 IP 查询转发表，决定把分组交换到哪个输出端口；这是输入端口最耗时的环节，所以用专用硬件完成。
- **排队等待**：若多个输入端口同时要送往同一输出端口，交换结构忙不过来，分组在输入端排队，**队列溢出即丢包**。

> 关键认识：查表在**输入端口**完成，而非等分组进入中央处理器后再查——这是路由器能线速转发的原因。若输入端排队过深，还可能出现**头端阻塞（HOL blocking）**：队头分组被占用的输出端口挡住，后面本可去其它端口的分组也只能等待。

#### 交换结构

**交换结构**：是路由器内部的“十字路口”，负责把分组从输入端口搬运到输出端口，典型实现有三种：

- **经内存交换**：最早期的做法，分组被拷贝进共享内存，由 CPU 处理后再拷贝到输出端口。实现简单，但每个分组要**两次经过内存总线**，速度受限于内存带宽，只适合低速路由器。
- **经总线交换**：所有输入输出共享一条总线，分组经总线一次传送到目标输出端口。**同一时刻只允许一个分组占用总线**，总线带宽决定转发上限，性能中等。
- **经互联网络交换（crossbar，纵横制）**：输入输出之间用纵横交错的线路构成网格，交叉点可同时导通多对输入输出，**多个分组可并行地从不同输入交换到不同输出**，吞吐与扩展性最好，现代高性能路由器普遍采用。

> 三种结构的速度排序是常考点：**内存交换 < 总线交换 < 互联网络（纵横制）**。总线是“共享的独木桥”，纵横制是“每对端口间都能架一座桥”，所以后者能并行。

#### 输出端口与排队

**输出端口**：是分组离开路由器的最后一站，负责排队、调度与链路层封装发送。

- **排队**：交换结构送来的分组到达输出端口后，若发送线路正忙则进入输出队列等待。
- **调度**：按既定的调度算法（FIFO、WFQ、优先级等，详见《拥塞控制与 QoS》章）从队列中选择下一个发送的分组。
- **封装发送**：为分组构造新帧头（写入新 MAC 地址）并交给链路层发送。

- **输入排队**发生在“多个入口抢同一个出口”时，**输出排队**发生在“交换结构比出口线路快”时（通常是主要瓶颈）；任一队列满时发生的丢弃，是路由器端拥塞的直接表现。

> 抽象一句话：**输入端口管“收和查”，交换结构管“搬”，输出端口管“排和发”**。三个环节都可能排队，排队溢出就是丢包，丢包率上升正是网络拥塞的信号——这为《拥塞控制与 QoS》章的 RED、队列调度埋下伏笔。

### 路由表与转发表的比较

#### 路由表与转发表的区别

**路由表（routing table）**：由控制平面（直连 + 静态 + 路由协议）生成的路由信息集合，记录“目的网络、下一跳、出接口、度量、来源”等逻辑信息，供选路与排错使用。

**转发表（forwarding table / FIB，转发信息库）**：从路由表中提炼并下发到数据平面的表项，记录“前缀、最长匹配动作、输出端口与封装信息”，按硬件查找优化。

- **生成方向**：路由表是“源”，转发表是“果”——控制平面先建好路由表，再把它转换成转发表下发给数据平面（或下发到 SDN 交换机的流表）。
- **更新频率**：路由表随拓扑与路由协议收敛而变化，转发表随路由表变化被动刷新；两者都要求快速同步，避免查表与选路不一致。
- **查找方式**：路由表可用软件逐条比较，转发表面对线速要求，用 TCAM 等硬件按最长前缀匹配并行查找。
- **内容侧重**：路由表偏“逻辑决策”（含下一跳、来源协议、优先级），转发表偏“物理执行”（含输出端口、新 MAC、封装动作）。

> 一句话区分：**路由表回答“去这个网络该往哪个方向走”（控制面逻辑），转发表回答“这个分组从哪个端口、用什么帧头发出去”（数据面动作）**。考题给一段“路由器如何转发”的叙述时，正确描述应为“查转发表”，写成“查路由表”也不至于全错——但严谨答案一定是转发表（FIB）。
