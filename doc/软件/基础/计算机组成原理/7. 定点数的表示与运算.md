## 定点数的表示与运算

> **全章主脉**：定点数把小数点的位置固定，运算比浮点简单，是 CPU 算术的基础。本章先讲定点小数与定点整数怎么摆放小数点、n 位能表示多大范围；再讲移位（算术移位相当乘除 2）、加减（补码统一）、乘除运算。重点掌握**补码加减如何算、如何判溢出**，以及乘法/除法用"移位 + 加/减"逐位累出的硬件思想。
>
> **一句话记运算**：加减看补码——连同符号位相加、正负得自动；判溢出看"符号位与最高数值位进位是否一致"；乘除靠"移位 + 部分积/商累加"，硬件用加法器反复做。

### 定点数的表示

#### 定点小数与定点整数

**定点数**约定小数点的位置固定不变，据此分为定点小数与定点整数两类。

- **定点小数**：小数点在符号位之后、最高数值位之前，表示绝对值小于 1 的数，用于浮点数的尾数。
- **定点整数**：小数点在最低数值位之后，表示整数。

**定点小数示意**（n 位含 1 位符号位）：符号位 S + (n−1) 位数值位，数值位为纯小数。

**定点整数示意**：符号位 S + (n−1) 位数值位，数值位为纯整数。

> [!NOTE]
> 提醒内容：定点数需程序员自己确定小数点的约定位置并管理量纲。表示范围有限是定点数的最大局限——太小/太大的数会下溢/上溢，故引入浮点数扩大动态范围。



#### 机器字长与数据范围

**数据范围**由机器字长（位数）与码制共同决定。n 位机器数（含 1 位符号位）在不同码制下表示范围不同。

各种码制的范围（n 位、含符号位）：

- **原码/反码**：−(2 的 (n−1) 次方 − 1) 至 (2 的 (n−1) 次方 − 1)。
- **补码**：−2 的 (n−1) 次方 至 (2 的 (n−1) 次方 − 1)。
- **无符号数**：0 至 2 的 n 次方 − 1。

**关键推论**：

- 补码因 0 唯一，能多表示一个最小负数 −2 的 (n−1) 次方（编码为 1 后跟 (n−1) 个 0）。
- 定点小数的补码范围是 −1 至 (1 − 2 的 −(n−1) 次方)，定点整数补码范围是 −2 的 (n−1) 次方 至 2 的 (n−1) 次方 − 1。

> [!TIP]
> 建议内容：定点小数补码的最小值 −1 很特殊——补码 1000…0 表示 −1，这是定点小数补码比原码多出的一个值。做范围计算先确认码制与是定点小数还是整数，再套对应上下界。



### 移位运算

#### 算术移位与逻辑移位

**移位运算**把二进制各位左移或右移，速度极快，是乘除 2 的快捷手段。

- **算术移位**：对有符号数按"移一位相当于乘/除 2"处理，要保证符号位不变、数值正确扩展。
  - 算术左移一位：最高数值位移入符号位会改变符号（可能溢出），低位补 0。
  - 算术右移一位：符号位保持不变（正数高位补 0、负数补 1 或按码制），移出的低位丢弃。
- **逻辑移位**：对无符号数或纯位串处理，不分符号，左移低位补 0、右移高位补 0。

> [!WARNING]
> 警告内容：算术右移必须保持符号，故负数右移高位补 1 才不改变符号意义；逻辑右移则一律补 0。做算术右移时判断"补 0 还是补 1"看符号位，而非简单补 0。



#### 补码移位规则

**补码移位**因补码数的符号位特殊，右移时高位补位与符号位一致，以保证移位后仍为正确的补码。

**补码的算术移位规则**：

- **补码左移一位**：低位补 0；若最高数值位与符号位不同，左移可能溢出（移位后符号被破坏），需判断。
- **补码右移一位**：高位补**符号位**（即补码右移是"符号扩展"），符号位保持，数值位依次右移；补码右移一位等价于除以 2 并保持符号。

**补码右移的本质**：因为负数补码的符号扩展不改变其数值大小方向，右移一位即除以 2（向负无穷取整），故补码右移高位总是补符号位。

> [!NOTE]
> 提醒内容：总结三种移位的高位补位——**逻辑右移补 0、算术右移补符号位（原码负数右移补 1、补码负数右移补符号位 1）**。补码左移若把符号位顶掉会改变符号即溢出，是判断左移溢出的要点。



### 加减运算

#### 补码加减运算

**补码加减**把带符号数都表示成补码后，减法规约为加"减数的补码"，硬件只需一个加法器。

**补码加法规则**：两个补码相加，连同符号位一起按二进制加法运算，舍去最高位产生的进位（按模 2 的 n 次方取模）。

- 例：4 位补码，+5（0101）加 +3（0011）得 +8？——0101+0011=1000，符号位变 1，实为 −8，说明发生正溢出。

**补码减法规则**：求 [A] − [B] = [A] + [−B]，即把减数取负（补码取反加 1）后做加法。

**运算步骤**：

- 两个数都以补码形式参与。
- 加法直接相加；减法把减数[B]变[−B]（每位取反加 1）再相加。
- 舍去最高进位，符号位自然给出结果正负。

> [!IMPORTANT]
> 重要内容：**补码做减法就是把减数变补（取反加 1）再相加**，符号位照常参与。这样 CPU 不需要独立的减法器，用加法器加补码即可实现全部加减，极大简化硬件。溢出判断另述。



#### 溢出判断

**溢出**指运算结果超出该码制能表示的范围，此时结果错误，必须判断并处理。

**判溢出的两种常用方法**：

- **双符号位法（变形补码）**：用两位符号位参加运算。若运算后两位符号位相同（00 或 11）则无溢出；不同（01 为正溢出、10 为负溢出）则溢出。
- **单符号位进位法**：比较最高数值位的进位与符号位的进位。二者不同则溢出（符号位进位与最高数值位进位不一致）。

**溢出的判别规则**：两正数相加得负、或两负数相加得正，必是溢出；一正一负相加不会溢出。

> [!WARNING]
> 警告内容：溢出与"进位"不是一回事——最高位有进位不代表溢出（如两负数相加最高进位是正常结果的高位），只有**符号位进位与数值最高位进位不一致**才是真溢出。用双符号位时看两位符号是否一致最直观。判断"结果对错"必须结合运算的是同号相加减。

> **判溢出示例**（4 位补码）：(+7) 的补码为 0111，(+1) 的补码为 0001，相加得 1000，符号位为 1、变成负数 −8，两正相加得负即正溢出；用单符号位进位法看，最高数值位无进位而符号位产生进位，二者不一致，判溢出。而 (5) + (−3)：0101 加 1101 得 0010（=2），结果正确，无溢出。溢出判定的本质是"结果的符号被破坏"，别把正常的高位进位误判成溢出。



### 乘法运算

#### 原码一位乘法

**原码一位乘法**按"符号位单独处理、数值位取绝对值相乘"进行，每位乘数对应一次"移位 + 加部分积"。

**基本思想**：积的符号 = 两数符号异或；积的数值 = 两数绝对值相乘。乘法通过反复"看乘数最低位：为 1 则加被乘数、为 0 则加 0，然后部分积右移一位"完成。

**原码一位乘的步骤**：

- 符号位单独异或得积符号。
- 绝对值部分做无符号乘法：被乘数与乘数用绝对值。
- 用一个双倍宽部分积寄存器，逐次判断乘数位，累加被乘数后右移，重复 n 次得 n 位积的绝对值。
- 拼上符号得最终原码乘积。

> [!TIP]
> 建议内容：原码乘法把符号与数值分离，数值部分按无符号数相乘，思路清晰、实现简单，缺点是符号位要单独处理。乘法是"部分积右移 + 条件加被乘数"的迭代，n 位乘需 n 次右移与至多 n 次加法。



#### 补码一位乘法

**补码一位乘法**（布斯算法）让符号位参与运算，得到可直接使用的补码乘积，且能处理负数，是实用的乘法实现。

**布斯算法要点**：

- 被乘数与乘数都用补码，符号位参加运算。
- 依据乘数末两位（当前位与前一位）决定操作：00 或 11 不加；01 加被乘数；10 减被乘数（加被乘数的相反数）。
- 每步做一次"条件加减 + 部分积右移（算术右移）"，重复 n 次后得补码乘积。

**优点**：补码乘法统一处理正负、可直接得补码结果，速度与硬件可并行优化。

> [!NOTE]
> 提醒内容：原码乘要单独处理符号、补码乘让符号参与——这是两者本质差别。布斯算法根据相邻两位决定加减，从而消除对符号的单独判断。理解"部分积与乘数连在一起右移、按末两位操作"即可，不要求死记每一位细节。



### 除法运算

#### 原码与补码除法

**除法运算**同样用"移位 + 加减"完成，其核心思想是恢复余数与加减交替两类。

**原码除法（恢复余数法 / 加减交替法）**：

- 商符号 = 两数符号异或，数值部分做无符号除法。
- 恢复余数法：每次用余数减除数，够减商 1、不够减恢复余数并商 0，然后余数左移。
- 加减交替法（不恢复余数法）：据上次结果直接加/减除数以决定商位，减少一次恢复操作，速度更快。

**补码除法**：让符号位参与，用加减交替法直接得到补码商与余数。

- 判断"够减与否"看余数与除数符号，决定商 1 还是商 0，并相应加减除数。

> [!NOTE]
> 提醒内容：除法比乘法复杂之处在于"判断够不够减"决定商位。恢复余数法实现直观但要恢复、多次操作；加减交替法通过续用余数符号决定下一步加减，省去恢复步骤，是实际采用较多的方法。命题多考原码加减交替的商位规则与余数左移的迭代次数，理解"移位减除看余数符号定商"即抓住要点。
