# 学习类 Markdown 文档编写规范

> 效力范围：仓库根 doc 目录下的所有学习类 Markdown 文档，包括本规范自身。凡属本规范约束的对象，均应同时满足“全文不使用反引号”与“允许并规范使用警告框”两条总则。

---

## 总则：两条贯穿全文的原则

> [!IMPORTANT]
> 重要内容 一：正文不使用行内代码反引号；代码块以反引号围栏呈现（唯一豁免）。
> 正文句、标题、列表、普通引用里不再使用行内代码反引号——代码、标识符、文件路径、方法签名等内容改用普通文字书写（必要时加粗）。可运行/可读的整段代码允许放进以三个反引号围成并带语言标注的代码块，代码块内部的反引号（如 JS 模板字符串）原样保留。此即全仓库反引号的唯一豁免，详见 2.7 的 T0。

> [!IMPORTANT]
> 重要内容 二：允许使用警告框强调信息。
> 仓库统一采用 Typora 1.8 及以上所支持的 Github 风格 Alert / Callout（即引用块警示语）来突出提示类信息。共五种类型，其语义与适用场景见“2.4 强调与标记符号”中的警示框一览表。

## 一、目录结构规范

### 1.1 标准三层结构

学习文档统一存放于 doc 目录之下，按下列层级组织：

- doc 目录：仓库根目录下的 doc 文件夹，为全部学习文档的存放根。
  - 领域层（一级）：知识领域，用 2 至 4 字中文名词命名，如 法律、软件、常识。
    - 主题层（二级）：学科、课程或一门课，一个主题一个子目录，目录名即学科名。
      - 目录索引文件：0. 主题名.md，固定编号为 0，是每个主题目录必有的索引。
      - 章节正文：1. 章节名.md 起连续编号。
      - 资源目录：assets，可选的图片等二进制资源，与正文文件同级。
  - 单篇文档：仅有一个文件的领域，正文直接置于领域层，不再建主题目录。
  - 规范文件：编写规范.md，与各领域平级存放于 doc 目录根。

### 1.2 结构规则

下表为目录结构方面的硬性规则，规则号以 S 开头：

| 规则号 | 规则 | 说明与依据 |
|---|---|---|
| S1 | 顶层按知识领域划分 | 现有 法律、软件、常识 三个领域。目录名用 2 至 4 字中文名词，不加 类、篇、笔记、资料 等后缀。 |
| S2 | 二级为主题（学科、课程） | 一个主题一个目录，目录名即学科名。 |
| S3 | 每个主题目录必有目录索引文件 | 以 0. 主题名.md 命名。0 是索引专用槽位，正文永不占用。 |
| S4 | 正文从 1 起连续编号 | 编号即学习顺序，也是考纲顺序。 |
| S5 | 文件名格式统一 | 格式为：编号 空格 名称点md，例如 1. 法的本体.md。编号与名称间用半角句点加一个空格分隔。 |
| S6 | 编号不补零 | 现有 10. 作用域与闭包.md、11. DOM 节点与 Web 存储.md 均未补零，保持一致。 |
| S7 | 是否建主题目录视章节数决定 | 预计章节数不少于 2 篇时才建主题目录并配索引；单篇直接放领域层。依据 常识/月天数计算.md。 |
| S8 | 图片统一存放 | 放在 主题名/assets 子目录。依据 软件/前端/JavaScript/assets。 |
| S9 | 不建空目录 | Git 不跟踪空目录，若干历史空目录已从仓库移除，避免再建。 |
| S10 | 文件名与文档标题、索引显示名一致 | 三者一致，避免跳转错位（详见 2.1 的 C5）。 |

### 1.3 目录索引文件的格式

目录索引文件的结构严格统一，以 法律/法理学/0. 法理学.md 为范本，可对照该文件逐字符核对。要点如下：

1. 首行写入 目录 一词作为二级标题，标题下方空一行。此标题使用二级，不使用一级。
2. 其后每个条目独占一行，条目格式为：文件显示名（形如 1. 法的本体.md）用半角方括号括起，紧接一对半角圆括号写入相对路径 ./1. 法的本体.md，路径须以点斜杠开头、只写文件名、不加目录前缀。整行前后各保留一个半角空格。
3. 条目与条目之间空一行。
4. 链接一律使用相对路径；文件名含空格时无需转义，只需按可链接的常规写法书写。
5. 条目顺序与正文编号一致；新增章节时，新条目追加到末尾并同步正文编号。
6. 索引文件只含标题与条目，除此之外不写任何内容——不写参考来源说明、不写导言、不做分类、不插入表格。

> [!NOTE]
> 提醒内容：凡含空格的相对路径链接，书写时保持路径原样即可，不要自行删除或改动文件名中的空格，也不要添加任何转义符，交给渲染端处理。

> [!CAUTION]
> 注意内容：一旦正文文件被改名、删除或移动，而索引条目与相对路径未同步更新，目录中的链接就会指向不存在的文件，导致整本资料无法从索引顺畅跳转。改完文件名后请立即回头核对索引第 5 点所述的一致性。

## 二、文档内容规范

### 2.1 标题层级

标题依靠井号的数量表达层级。正文各文件的层级约定如下表：

| 层级 | 井号数量 | 用途 | 实例（法理学） |
|---|---|---|---|
| 文档标题 | 二级（两个井号） | 章节主标题，等于文件名去掉编号与点md | 二级标题 法的本体 |
| 一级知识点 | 三级（三个井号） | 知识模块、考纲大块 | 三级标题 法的概念 |
| 二级知识点 | 四级（四个井号） | 具体考点、单一命题 | 四级标题 法概念的争议 |
| 三级知识点 | 五级（五个井号） | 仅当四级之下仍需细分时使用 | 技术类主题已启用，规则见 2.7 |

关于标题的硬性规则：

- C1：不使用一级标题。本仓库约定一篇正文等于一章，一级标题的语义层级留给整个学科，故正文一律从二级标题起。
- C2：一个文件有且只有一个二级标题，且位于文件第一行。
- C3：层级不跳级。二级到三级到四级逐级下降，不允许出现二级之下直接接四级的情况。
- C4：未完成的模块保留空标题占位。标题下方留空行，保证大纲完整、后续可定位。例如 法的价值、法的要素、法律关系 等三级标题目前即为空节。
- C5：二级标题须与文件名严格一致，见 S10。
- C6：标题不写编号。不写 1.2、一、（一） 等序号，层级一律靠井号数量表达。
- C7：同级标题不重名。同一父标题下的同级标题名称唯一，避免锚点冲突。
- C8：标题内出现的标识符与名称直接裸写，不添加任何包裹符号。例如写 实例化方法 与 return 方法 的含义，用普通文字表述，不使用行内代码包裹。

### 2.2 空行与留白

对 1. 法的本体.md 全文标题的实际测量结果如下，作为留白的基准：

| 位置 | 应留空行数 | 说明 |
|---|---|---|
| 二级标题之后 | 1 | |
| 三级标题之前 | 3 | 与上一节内容拉开，形成模块边界 |
| 三级标题之后 | 1 | 后接四级标题或正文段落时均为 1 |
| 四级标题之前 | 3 | 同一三级标题下的首个四级例外，为 1 |
| 四级标题之后 | 1 | |
| 五级标题之前 | 3 | 同一四级标题下的首个五级例外，为 1 |
| 五级标题之后 | 1 | 规则同四级 |
| 段落与段落之间 | 1 | |
| 引用块与前后段落之间 | 1 | |
| 文件末尾 | 保留单个换行 | 不额外堆叠空行 |

> [!WARNING]
> 警告内容：同级标题之间空 3 行，标题与紧邻内容空 1 行，这是全文最容易走样、也最影响阅读的地方，请务必照做。空行规则对任意层级通用；判断“首个标题”与否，只看上一个同级标题是否存在于当前父标题之下，与标题本身是三级、四级还是五级无关。

### 2.3 内容组织：考点的四段式结构

正文以四级标题承载每一个考点。每个考点按下列顺序展开，缺哪一段就跳过哪一段，但顺序不可颠倒：

1. 结论与定义先行。首句直接给出该考点的判断标准或定义，一句话说清。
2. 要素拆分或分类展开。用列表把要素、分类、情形逐项拆开，一项一行。
3. 辨析与例外。用引用块写易混点、例外、特殊情况、与相邻概念的差别。
4. 速记线索。用引用块或加粗给出记忆口诀、层级树、对照表。

> [!TIP]
> 建议内容：考点即命题。每一段文字都应为“答这道题”服务，先结论、后展开、再辨析、末速记，读者据此即可背默一个完整考点。

### 2.4 强调与标记符号

写作中用于强调与标记的符号约定如下：

| 用途 | 书写方式 | 效果实例 |
|---|---|---|
| 定义项、术语、判断关键词、对比双方 | 对目标词两侧各加一对星号（每侧两个），即加粗 | 某阵营 一词加粗后作为定义句主语 |
| 定义句式 | 术语加粗，紧跟全角冒号再写释义 | 加粗的术语 加全角冒号 加释义 |
| 考点标签 | 半角方括号括起标签文字，用于标注法律名、学说名、特征名 | 实然法、应然法、罪刑法定 |
| 并列的法定特征条目 | 标签内再加粗关键特征词 | 序号后接方括号内加粗的特征名再写完整表述 |
| 句内短注 | 半角方括号括起短词，紧跟被限定词之后 | 非意志、填补漏洞、法律不清楚也要判 |
| 有序列表 | 数字加点加空格开头 | 用于有法定顺序或穷举性质的清单，如从宪法到地方性法规的正式渊源 |
| 无序列表 | 短横线加空格开头 | 用于无顺序的要素、分类、特征，如法的规范作用 |
| 长清单分项小标题 | 中文数字加粗后接全角冒号 | 一、宪法： 二、法律： 等 |
| 书名与文件名 | 用书名号括起 | 民法典 第十条、立法法 第九十九条、文件 1. 法的本体.md |
| 需特别区分的称谓或引述 | 用直角引号括起 | 裁判依据 与 说理依据 对举 |

引用块作为普通提示与辨析的载体，常见用途为易混辨析、条文补充、例外情况、记忆口诀、理论同实务的分歧说明。凡需要强调“需要注意”“务必遵守”“后果严重”等更强语义时，改用警示框，而非普通引用块。

警示框一览表（对应 Typora 支持的 Github 风格五类）：

| 中文类型 | 渲染所用标记 | 语义与适用场景 |
|---|---|---|
| 提醒内容 | 标记为 NOTE | 提供读者应知的一般信息，即使快速浏览也应留意 |
| 建议内容 | 标记为 TIP | 提供帮助读者做得更好的可选建议或技巧 |
| 重要内容 | 标记为 IMPORTANT | 读者成功完成某事所必需的关键信息 |
| 警告内容 | 标记为 WARNING | 因潜在风险而要求读者立刻注意的关键内容 |
| 注意内容 | 标记为 CAUTION | 某个操作可能带来的负面影响或需要谨慎的后果 |

警示框书写法：在引用块首行书写 大于号、空格、半角方括号、感叹号、类型英文词、半角方括号，紧接一行后写正文。渲染端通过标记词识别类型并着色加图标；本仓库以中文语境组织，故正文首句通常以对应的中文类型词加粗引领，便于在未着色环境下仍能辨识语义。

> [!IMPORTANT]
> 重要内容：警示框务必“先类型后内容、一框一意”。引用警示语时，正文内容前用对应中文类型词加粗点题；不要在警示框里罗列多个无关要点，也不要嵌套警示框。

全仓库统一禁用的元素（不分领域，一律不用）：

- Markdown 表格。内容一律用列表表达层级；二维数据（字段表、端口表、位图）同样拆成“加粗定义项加冒号加释义”的列表项，不因表格看起来更整齐而破例。本规范作为说明性文件不在其列，故自身可使用表格做对照。
- 水平分隔线。用标题层级划分区块，不用一条或多条短横线、星号或下划线组成的分隔线。
- 图标、彩色文字等过度装饰。带圈数字属于序号而非图标，可以使用；不使用表情代替语义。
- Emoji 需适度，仅按 2.5 的 W10 用于点缀，禁止滥用。

> [!WARNING]
> 警告内容：正文句一律不使用行内代码反引号。若在正文某处想“把一个标识符圈出来”，请改为直接以普通文字书写，需要强调时加粗。整段可运行代码放进反引号围栏代码块（见 2.7 的 T0），围栏之外不再出现任何反引号。

### 2.5 写作风格

- W1：定义用判断句。以“某概念是什么”开头，一句话给全，不做铺垫。
- W2：对比成对出现。加粗的两方必须同时出现，缺一不可。
- W3：限定词紧跟被限定词并加粗。限定与被限定紧邻，避免误读。
- W4：结论性判断单独成段并整句加粗。
- W5：术语首次出现即给定义，不假设读者已知。
- W6：不使用 我们、大家、其实、简单来说 等口语衔接，不写与读者的互动语。
- W7：不臆造条文。引用规定须给出名称与条号；不确定的表述写明 通说认为 或 实务中，不绝对化。
- W8：使用中文标点。逗号、句号、冒号、括号用全角；并列项之间用顿号。
- W9：技术类术语首次出现即给完整签名。写到方法就带参数，例如完整写出数组对象的 splice 方法及其三个参数 index、deleteCount、items，而不是只写方法名。
- W10：技术类可少量使用 Emoji 点缀。同一文件不超过 3 至 5 处，且不重复堆砌，避免喧宾夺主。
- W11：自定义函数使用驼峰命名法，名称言简意赅、英文直译，不加人名、缩写等特殊前缀。示例中的占位函数同样须用有意义的名字（如 getRandomInt、makeCounter），不用 fun1、fn、Foo 之类无意义名；构造函数用大驼峰（如 Person）。

### 2.6 占位文件规范

尚未开始写的分册，只写一行与文件名一致的二级标题，不加空行、不加正文、不写注释标记。

例如 法律/法理学/5. 立法法.md 全文即为 立法法 的二级标题；6. 习近平法治思想.md 全文即为对应标题。

已建好但完全为空的文件应尽早补上二级标题，否则索引虽可跳转但页面无标题。

### 2.7 技术类主题的排版规则

本规则适用于软件 领域下的技术笔记（如 前端/JavaScript、前端/CSS、计算机基础 等）。它是对前述规则的额外补充，不是豁免——技术类同样禁止表格、分隔线、同样遵守 C1 至 C8。反引号的全局政策见下 T0，属仓库例外。

- T0（代码呈现·全局例外）：本仓库区分两类反引号——代码块与代码语法用 围栏包裹与缩进组织，行内代码用 普通文字 表达。
  - 代码块：允许以三个反引号围栏（可带语言标注，如 js、css）书写可运行/可读代码。围栏及代码块内部的任何反引号（如 JavaScript 模板字符串、字符串内反引号）一律原样保留、不得改动。这是全仓库唯一的反引号豁免。
  - 行内代码：正文句、标题、列表、普通引用里的行内代码反引号一律不使用——方法名、关键字、属性、文件名等去掉反引号写成普通文字；符号式且需突出时用加粗表达。
- T1：二维数据一律拆成列表，不保留 Markdown 表格。转换要点：三列的名、值、说明，写成 加粗名 加 括号内写值与单位 加 冒号说明；两列对照写成 加粗对比项 加 冒号加 A 方斜杠 B 方；逐位拆解的位图按顺序在一行内写出全部位值，并在冒号前用加粗标出位段。
- T2：五级标题仅在技术类使用，空行规则同四级（见 2.2）。依据是 3. JavaScript 内置对象.md，它包含大量五级标题，是全仓库唯一使用该层级的文件。
- T3：方法签名以普通文字完整写出（见 W9），必要时加粗方法名；不要把方法名/变量用行内代码反引号包起。
- T4：方法、语法点尽量给出可运行代码块示例；纯概念性知识点（如面向过程与面向对象之别）不强制。

> [!NOTE]
> 提醒内容：技术类正文以“代码块围栏 + 普通文字式行内引用”组织——代码示例放进带语言标注的围栏代码块；正文提及方法名/关键字时直接写普通文字（可加粗），不再使用行内代码反引号。改稿后请检索：正文句里不应再出现反引号，反引号只应出现在围栏代码块内。

## 三、模板

本仓库以若干真实文件为范本，正文各文件的组成与顺序如下说明。撰写新文件时，可直接打开对应范本逐字符对照。

### 3.1 目录索引文件模板

适用 主题/0. 主题.md。范本见 法律/法理学/0. 法理学.md。文件自顶向下依次为：

1. 一行二级标题，内容为 目录 一词，标题后空一行。
2. 若干条目行，每条对应一个章节正文，格式见 1.3 第 2 点：半角方括号括显示名，圆括号括相对路径，行首行尾各一个半角空格。
3. 条目之间空一行，条目按正文编号递增排列。

写完应自检：首行是二级标题、条目数与正文文件数一致、每条路径都能对应到真实文件。

### 3.2 正文文件模板

适用 主题/1. 章节名.md 等正文。范本见 法律/法理学/1. 法的本体.md。文件自顶向下依次为：

1. 文件第一行是二级标题，内容与文件名一致。
2. 其后为若干三级标题承载的一级知识点；三级标题之间空 3 行。
3. 每个一级知识点下再视内容展开四级标题承载的考点，四段式组织见 2.3。
4. 需要提示处按语义使用引用块或五类警示框（见 2.4）。
5. 文件以单个换行结尾，不堆空行。

整体节奏：同级标题空 3 行，标题与紧邻正文空 1 行，段间空 1 行（见 2.2）。

### 3.3 极简单页模板

适用内容量小、不会拆章的杂项知识点，直接置于领域层而不建目录。范本见 常识/月天数计算.md。其组成自顶向下为：

1. 三级标题承载知识点名。
2. 正文段落，一段一意，段间空一行。
3. 需要时以引用块或警示框写补充、例外或口诀，前后各空一行。

## 四、自检清单

新建或改写一篇学习文档后，逐项核对以下各项。

结构

- [ ] 主题目录已有 目录索引文件（0. 主题.md），新章节已追加进索引
- [ ] 索引文件只含标题与条目，未写参考来源说明、导言、分类或表格（见 1.3 第 6 点）
- [ ] 文件名符合 编号 空格 名称点md 的格式，编号不补零
- [ ] 文件名、文档二级标题、索引条目显示名三者一致
- [ ] 需要图片时已建 assets 子目录并放入，未散落在正文目录

标题

- [ ] 全文没有一级标题
- [ ] 二级标题只有一个，且在文件第一行
- [ ] 层级连续，无跳级
- [ ] 标题未写 1.2、一、（一） 等序号
- [ ] 同级标题不重名
- [ ] 未完成的模块保留了空标题占位

排版

- [ ] 同级标题之前空 3 行，同父标题下的首个例外为 1 行
- [ ] 标题与紧邻正文之间空 1 行
- [ ] 段落之间空 1 行；引用块前后各空 1 行
- [ ] 警示框前后各空 1 行，且一框一意、类型词与内容相符
- [ ] 文件末尾只有单个换行

内容

- [ ] 每个考点首句是定义或结论，不是背景铺垫
- [ ] 术语首次出现已给定义
- [ ] 对比项两方都加粗、成对出现
- [ ] 易混点、例外、条文补充均进入引用块或警示框，没有混在正文里
- [ ] 引用了条文且条号准确，或已标明 通说、实务 的分歧
- [ ] 未使用 Markdown 表格、水平分隔线
- [ ] Emoji 使用克制、未滥用

反引号与代码

- [ ] 正文句、标题、列表、普通引用里未出现任何反引号（反引号只允许出现在围栏代码块内）
- [ ] 行内代码已改为普通文字，方法名/关键字/属性等未用反引号包裹（需要时以加粗强调）
- [ ] 代码块以三个反引号围栏成对书写，围栏内部的反引号（如 JS 模板字符串）保留原样
- [ ] 代码块带语言标注，围栏成对闭合、未破坏标题与空行层级
- [ ] 二维数据已拆成列表，未出现 Markdown 表格
- [ ] 自定义函数用驼峰且有意义的英文名，占位函数不写 fun1、fn、Foo

警示框（若用到）

- [ ] 类型词书写正确：提醒用 NOTE、建议用 TIP、重要用 IMPORTANT、警告用 WARNING、注意用 CAUTION
- [ ] 每个警示框正文首句以对应中文类型词加粗点题
- [ ] 未将普通提示误升为 警告 或 注意，语义与类型匹配
