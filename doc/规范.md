# 学习类 Markdown 文档编写规范

> [!IMPORTANT]
> **重要内容**：本规范适用于 doc 目录下全部 Markdown 文档，包括本规范自身。本规范是元文档，标题体系自成一套：一级标题为文档名，其下以 一、二 分章、1.1 分节。故 2.1 的标题层级约定、2.2 的留白条款与分隔线禁用条款对其不适用；表格的例外见 2.4 禁用清单。除此之外，本规范自身一律遵守。

---

## 一、目录结构

### 1.1 标准三层结构

学习文档统一存放于 doc 目录之下，按下列层级组织：

- doc：全部学习文档的存放根，根下只放 目录.md 与 规范.md 两个元文件，不放正文。
  - 领域层（一级）：知识领域，目录名用 2 至 4 字中文名词，不加 类、篇、笔记、资料 等后缀；现有 临公、常识、法律、软件 四个领域。
    - 主题层（二级）：一门学科、课程或一门课，一个主题一个子目录，目录名即学科名。
      - 目录索引：0. 主题名.md，编号固定为 0，是每个主题目录必有的索引，0 为索引专用槽位。
      - 章节正文：1. 章节名.md 起连续编号，编号即学习顺序，也是考纲顺序。
      - 资源目录：assets，可选的图片等二进制资源，与正文文件同级。
  - 单篇文档：领域下只有一篇时直接置于领域层，不另建主题目录。

### 1.2 结构与命名规则

规则号以 S 开头：

| 规则号 | 规则 | 说明 |
|---|---|---|
| S1 | 顶层按知识领域划分 | 目录名 2 至 4 字中文名词，不加后缀。 |
| S2 | 二级为主题 | 一个主题一个目录，目录名即学科名。 |
| S3 | 每个主题目录必有索引 | 命名为 0. 主题名.md，0 是索引专用槽位。 |
| S4 | 正文从 1 起连续编号 | 编号即学习顺序与考纲顺序。 |
| S5 | 文件名格式统一 | 编号 空格 名称点md，编号与名称间为半角句点加一个空格。 |
| S6 | 编号不补零 | 两位编号直接书写，不加前导零。 |
| S7 | 章节数不少于 2 才建主题目录 | 单篇直接放领域层，不建目录也不配索引。 |
| S8 | 图片统一存放 | 放在 主题名/assets，不散落在正文目录。 |
| S9 | 不建空目录 | Git 不跟踪空目录。 |
| S10 | 文件名、二级标题、索引显示名三者一致 | 详见 C5，避免跳转错位。 |
| S11 | doc 根只放两个元文件 | 目录.md 与 规范.md，均受本规范约束。 |

### 1.3 索引文件格式

主题索引 0. 主题名.md 与全库总目录 doc/目录.md 共用同一格式，以 法律/法理学/0. 法理学.md 为范本，可逐字符核对：

1. 首行写入 目录 一词作为二级标题，标题下方空一行。此标题用二级，不用一级。
2. 其后每个条目独占一行：显示名用半角方括号括起，紧接一对半角圆括号写入相对路径 ./文件名.md，路径须以点斜杠开头、只写文件名、不加目录前缀；整行前后各保留一个半角空格。
3. 条目与条目之间空一行，顺序与正文编号一致；新增章节时新条目追加到末尾，并同步正文编号。
4. 索引文件只含标题与条目，不写参考来源说明、不写导言、不做分类、不插入表格。
5. 全库总目录另有两处不同：条目只列各主题的 0. 主题名.md，不列章节正文，也不列领域与分组目录；显示名取主题名、不带 0. 编号（该文件二级标题固定为 目录，本就不适用 S10）。条目顺序与学习库侧栏一致，即 临公、常识、法律、软件 依次排列。该文件由构建脚本重写，不要手工编辑——手写内容会在下次构建时被覆盖；脚本另会检查凡含正文的目录是否都配有索引，缺了就在构建输出里告警，不会静默漏收。

> [!NOTE]
> **提醒内容**：含空格的相对路径原样书写即可，不删空格、不改文件名、不加任何转义符，交给渲染端处理。

> [!CAUTION]
> **注意内容**：正文文件被改名、删除或移动而索引与相对路径未同步时，目录中的链接就会指向不存在的文件，整本资料无法从索引顺畅跳转。改完文件名后请立即回头核对第 3 点的一致性。

## 二、文档内容规范

### 2.1 标题层级

标题依靠井号的数量表达层级，正文各文件的层级约定如下：

| 层级 | 井号数量 | 用途 |
|---|---|---|
| 文档标题 | 二级 | 章节主标题，等于文件名去掉编号与点md，如 法的本体 |
| 一级知识点 | 三级 | 知识模块、考纲大块，如 法的概念 |
| 二级知识点 | 四级 | 具体考点、单一命题，如 法概念的争议 |
| 三级知识点 | 五级 | 仅当四级之下仍需细分时使用，规则见 2.7 |

关于标题的硬性规则：

- C1：不使用一级标题。一篇文章等于一章，一级标题的语义层级留给整个学科，正文一律从二级标题起。
- C2：有且只有一个二级标题，且位于文件第一行。
- C3：层级不跳级，二级到三级到四级逐级下降。
- C4：未完成的模块保留空标题占位，标题下方留空行，保证大纲完整、后续可定位。
- C5：二级标题须与文件名严格一致，见 S10。
- C6：标题不写 1.2、一、（一） 等序号，层级一律靠井号数量表达。
- C7：同一父标题下的同级标题不重名，避免锚点冲突。
- C8：标题内出现的标识符与名称直接裸写，不加任何包裹符号；需要强调时加粗，不用行内代码包裹。

### 2.2 空行与留白

留白基准来自对 1. 法的本体.md 全文标题的实测：

- 二级标题之后空 1 行。
- 同级标题之间空 3 行；同一父标题下的首个同级标题例外，其前空 1 行。三级、四级、五级一律适用。
- 标题之后空 1 行，段落之间空 1 行，引用块与警示框前后各空 1 行。
- 两条规则重叠时以标题为准：引用块、警示框或段落紧邻同级标题之前，一律空 3 行，不因「引用块前后空 1 行」降为 1 行。技术类主题普遍不以速记收尾，每节末尾恰好停在引用块上，此处按本条执行。
- 文件末尾保留单个换行，不堆叠空行。

> [!WARNING]
> **警告内容**：同级标题空 3 行、首个同级标题例外为 1 行，是全篇最容易走样、也最影响阅读之处。判断「是否首个」只看当前父标题之下此前有无同级标题，与层级是三级、四级还是五级无关。

### 2.3 内容组织：考点的四段式结构

正文以四级标题承载每一个考点，按下列顺序展开，缺哪一段就跳过哪一段，但顺序不可颠倒：

1. 结论与定义先行：首句直接给出该考点的判断标准或定义，一句话说清。
2. 要素拆分或分类展开：用列表把要素、分类、情形逐项拆开，一项一行。
3. 辨析与例外：用引用块写易混点、例外、特殊情况、与相邻概念的差别。
4. 速记线索：用引用块或加粗给出记忆口诀、层级树、对照表。

> [!TIP]
> **建议内容**：考点即命题。先结论、后展开、再辨析、末速记，每段文字都为「答这道题」服务，读者据此即可背默一个完整考点。

### 2.4 强调与标记符号

写作中的标记约定：

- 加粗：用于定义项、术语、判断关键词、对比双方；需突出的标识符也用加粗，不另加包裹符号。
- 定义句式：术语加粗，紧跟全角冒号再写释义。
- 半角方括号：用于考点标签（法律名、学说名、特征名）与句内短注；并列的法定特征条目在标签内再加粗关键特征词，后接完整表述。
- 列表：有法定顺序或穷举性质的清单用有序列表（数字加点加空格），无顺序的要素、分类、特征用无序列表（短横线加空格）；长清单的分项小标题用中文数字加粗后接全角冒号，如 一、宪法： 二、法律：。
- 书名号：用于书名、法规名与文件名，含条号时一并写出。
- 直角引号：用于需特别区分的称谓或引述，如 裁判依据 与 说理依据 对举。

引用块作为普通提示与辨析的载体，常见用途为易混辨析、条文补充、例外情况、记忆口诀、理论同实务的分歧说明。凡需要强调「需要注意」「务必遵守」「后果严重」等更强语义时，改用警示框，不用普通引用块。

警示框是仓库统一的提示强调方式，各领域文档均可使用。五类对应 Typora 支持的 Github 风格标记：提醒用 NOTE（读者应知、快览也应留意的一般信息）、建议用 TIP（可选的技巧或建议）、重要用 IMPORTANT（成功完成某事所必需的关键信息）、警告用 WARNING（因潜在风险要求立刻注意）、注意用 CAUTION（某操作可能带来的负面影响或需谨慎的后果）。

警示框书写法：在引用块首行书写 大于号、空格、半角方括号、感叹号、类型英文词、半角方括号，紧接一行后写正文。渲染端按标记词识别类型并着色加图标；本仓库以中文语境组织，故正文首句以对应的中文类型词加粗引领，便于未着色时仍可辨识语义。

> [!IMPORTANT]
> **重要内容**：警示框务必「先类型后内容、一框一意」。引用警示语时用对应的中文类型词加粗点题；不在一个框里罗列多个无关要点，也不嵌套警示框。

全仓库统一禁用的元素，不分领域一律不用：

- Markdown 表格。内容一律用列表表达层级；二维数据（字段表、端口表、位图）同样拆成加粗定义项加冒号加释义的列表项，不因表格看起来更整齐而破例。本规范作为说明性文件不在其列，故自身可用表格做对照。
- 水平分隔线。区块划分用标题层级，不用一条或多条短横线、星号、下划线组成的分隔线。
- 图标、彩色文字等过度装饰。带圈数字属序号而非图标，可以使用；不用表情代替语义。
- Emoji 滥用，仅按 2.5 的 W10 用于点缀。
- 正文中的裸 HTML 标签。尖括号括起的元素名（p、div、table、link 等）写进正文句、标题、列表、引用块或警示框时，渲染端会当作真实 HTML 解析，导致文字被拆成段落、标签被吞、排版错乱。表达元素一律写不带尖括号的普通文字（需要强调时加粗）；必须展示带尖括号的标签原文时，放入带 html 语言标注的围栏代码块，细则见 2.7 的 T5。
- 正文句中的行内代码反引号。想让标识符突出时改为普通文字书写，需要强调时加粗。反引号只允许出现在围栏代码块内，该唯一豁免的界定见 2.7 的 T0。

### 2.5 写作风格

- W1：定义用判断句，以「某概念是什么」开头，一句话给全，不做铺垫。
- W2：对比成对出现，加粗的两方必须同时出现，缺一不可。
- W3：限定词紧跟被限定词并加粗，避免误读。
- W4：结论性判断单独成段并整句加粗。
- W5：术语首次出现即给定义，不假设读者已知。
- W6：不使用 我们、大家、其实、简单来说 等口语衔接，不写与读者的互动语。
- W7：不臆造条文，引用规定须给出名称与条号；不确定的表述写明 通说认为 或 实务中，不绝对化。
- W8：使用中文标点，逗号、句号、冒号、括号用全角，并列项之间用顿号。标点处在标识符、方法签名、格式串、命令行或配置片段内部时（如参数分隔的逗号、键值对中的半角冒号），依技术惯例保留半角；落在中文行文之间的标点一律全角。
- W9：技术类术语首次出现即给完整签名，写到方法就带参数，例如写出数组 splice 方法的 index、deleteCount、items 三个参数，而不只写方法名（另见 T3）。
- W10：技术类可少量使用 Emoji 点缀，同一文件不超过 3 至 5 处，不重复堆砌，避免喧宾夺主。
- W11：自定义函数使用驼峰命名法，名称言简意赅、英文直译，不加人名、缩写等特殊前缀；示例中的占位函数同样须用有意义的名字（如 getRandomInt、makeCounter），不用 fun1、fn、Foo 之类，构造函数用大驼峰（如 Person）。

### 2.6 占位文件规范

尚未开始写的分册，只写一行与文件名一致的二级标题，不加空行、不加正文、不写注释标记。

已建好但完全为空的文件应尽早补上二级标题，否则索引虽可跳转但页面无标题。

### 2.7 技术类主题的排版规则

本规则适用于 软件 领域下的技术笔记（如 前端/JavaScript、前端/CSS、基础/Git 等）。它是对前述规则的额外补充，不是豁免——技术类同样禁止表格与分隔线，同样遵守 C1 至 C8。反引号的全局禁则见 2.4 末尾，T0 为其界定唯一的代码块豁免。

- T0（代码呈现·全局例外）：本仓库区分两类反引号。代码块允许以三个反引号围栏书写（可带 js、css 语言标注），围栏及代码块内部的任何反引号（如 JavaScript 模板字符串）一律原样保留、不得改动，这是全仓库唯一的反引号豁免。行内代码一律不用——方法名、关键字、属性、文件名等去掉反引号写成普通文字，需突出时用加粗表达。
- T1：二维数据一律拆成列表，不保留 Markdown 表格。三列的名、值、说明写成 加粗名 加 括号内写值与单位 加 冒号说明；两列对照写成 加粗对比项 加 冒号加 A 方斜杠 B 方；逐位拆解的位图按顺序在一行内写出全部位值，并在冒号前用加粗标出位段。
- T2：五级标题仅在技术类使用，空行规则同四级（见 2.2）。
- T3：方法签名以普通文字完整写出（见 W9），必要时加粗方法名；不用行内代码反引号包裹。
- T4：方法、语法点尽量给出可运行代码块示例；纯概念性知识点（如面向过程与面向对象之别）不强制。
- T5：HTML 标签的表述。正文句不写裸标签，表达某个元素时写不带尖括号的元素名（p、div、table），需要强调时加粗。需展示带尖括号的标签原文（如教学用 HTML 结构片段、带属性的标签写法）时，放入带 html 语言标注的围栏代码块，与 js、css 示例同等对待，块内标签保持原样书写，不用转义字符或实体替代。

改稿后请自检：正文句里不应再出现反引号，反引号只应出现在围栏代码块内。

## 三、模板

撰写新文件时打开对应范本逐字符对照即可，不必记文字描述。

- 目录索引：适用 主题/0. 主题.md，格式与自检要点见 1.3，范本为 法律/法理学/0. 法理学.md。
- 正文文件：适用 主题/1. 章节名.md，范本为 法律/法理学/1. 法的本体.md。自顶向下依次为：首行二级标题（内容与文件名一致）→ 三级标题承载的一级知识点，之间空 3 行 → 各知识点下视内容展开四级标题承载的考点，按 2.3 的四段式组织 → 需要提示处按语义用引用块或五类警示框（见 2.4）→ 单个换行结尾，不堆空行。
- 极简单页：适用内容量小、不会拆章的杂项，直接置于领域层而不建目录，以三级标题承载知识点名、正文一段一意、需要时以引用块或警示框写补充。当前仓库暂无实例。

## 四、自检清单

新建或改写一篇学习文档后，逐项核对以下高频易错项；未列出的细节以正文条款为准。

结构与命名

- [ ] 索引已同步：条目数与正文数一致、路径均可跳转、文件名与二级标题与索引显示名三者一致（见 S10、1.3）
- [ ] 新增、改名或删除主题后已跑一次构建，总目录 目录.md 随之刷新，构建输出无缺索引告警
- [ ] 需要图片时已建 assets 子目录，未散落在正文目录

标题与排版

- [ ] 全文没有一级标题；二级标题只有一个且在首行；层级无跳级
- [ ] 同级标题之前空 3 行（同父首个为 1 行）；标题与紧邻正文空 1 行；文件末尾只有单个换行
- [ ] 未完成的模块保留了空标题占位

内容

- [ ] 每个考点首句是定义或结论；术语首次出现已给定义；对比项两方都加粗、成对出现
- [ ] 易混点、例外、条文补充均进入引用块或警示框；引用条文有名称与条号，或已标明 通说、实务 的分歧
- [ ] 未使用 Markdown 表格与水平分隔线，二维数据已拆成列表；Emoji 使用克制
- [ ] 警示框一框一意，中文类型词与标记相符（提醒用 NOTE、建议用 TIP、重要用 IMPORTANT、警告用 WARNING、注意用 CAUTION）

代码相关

- [ ] 正文句、标题、列表、普通引用里无任何反引号，行内代码已改为普通文字；反引号只出现在围栏代码块内
- [ ] 代码块成对闭合、带语言标注；正文句无裸 HTML 标签，元素名已文字化，标签原文已入代码块
- [ ] 自定义函数用驼峰且有意义的英文名，占位函数不写 fun1、fn、Foo
