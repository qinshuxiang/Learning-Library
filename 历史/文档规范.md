# 文档规范

> [!WARNING]
> **警告内容**：本文档已退役（2026-09-25 库定位转向画像库），仅作历史留档，不再维护。现行写作口径见 `../写作风格.md`；与画像层文件冲突时以后者为准。

> [!IMPORTANT]
> **重要内容**：本规范是本库（`Learning-Library` 六领域 Markdown 库）全部正文与索引文档的统一写法契约。它规定七件事——适用范围与效力、文档类型与命名、标题层级、空行留白、正文写法、代码与示例、提示载体，外加主题体例族与全库禁用元素。编写或校改文档时按条款号逐条判定，条款号同时作为引用、派活、自查与脚本映射的凭据。

> [!NOTE]
> **提醒内容**：本文件与同目录的 `编程规范.md` 是本库的元文档。元文档的标题体系与排版自成一套（可用一级标题、多个二级标题、表格与水平分隔线），故豁免第三、四、八节的约束；除此之外的条款一律适用。元文档不参与 `.workbuddy/validate_doc.py` 的批量校验（校验时只传六个领域目录，不传仓库根）。

## 一、适用范围与效力

- A1：本规范约束本库全部 Markdown 文档，含六领域（前端／后端／工具／常识／架构／法律）下的主题正文、主题索引文件，以及仓库根的元文档（元文档的豁免范围见首节声明框）。

- A2：文档分三类，各有各的体例。
  - 索引文件：`0. 主题名.md`，与该主题目录同名，承载篇目清单，规则见 B2–B4。
  - 正文：`N. 篇名.md`，承载知识内容，规则见第三至八节与第九节的体例族。
  - 元文档：仓库根的 `文档规范.md` 与 `编程规范.md`，规则自定。

- A3：效力顺序为 用户显式指令 > 本规范 > `.workbuddy/` 下的脚本与项目记忆。按用户指令破例时，须在交付说明里写明破例点与理由，不得静默破例。

- A4：条款号是接口。条款号一经发布只增不改；确需改动时，必须按第十二节的同步清单逐处更新，不得只改本文件。

- A5：本规范与校验脚本是同一份契约的两端。新增或修改条款时，若该条可机器判定，须同步在 `.workbuddy/validate_doc.py` 增加检查项，并在第十二节的对照表里登记。



## 二、文档类型与文件命名

- B1：主题目录下的索引文件固定命名为 `0. 主题名.md`，与目录同名。凡含正文的目录都必须有索引，缺索引由构建脚本在构建期告警。

- B2：索引文件首行固定为 `## 目录`，正文自第二行起列条目。索引文件豁免 C3（二级标题与文件名一致），不适用 C3 的判定。

- B3：索引条目行的格式固定，条目行首尾各留一个半角空格，链接用相对路径：

```text
 [1. 篇名.md](./1. 篇名.md) 
```

- B4：索引条目与磁盘上同目录的正文文件一一对应，序号连续、不跳号、不重号。新增、删除、改名篇目后必须同步索引，用 `.workbuddy/check_index_sync.py <领域名>` 核验。

- B5：正文文件名形如 `N. 篇名.md`。N 是该主题内的递增整数，从 1 起；序号后为半角句点加一个半角空格。

- B6：篇名用陈述性短语，不写序号、不写书名号、不写日期、不写版本号。同一主题内的篇名去掉序号后不得重名。

- B7：图片统一放 `主题名/assets/` 子目录，正文以 `./assets/文件名` 引用。构建脚本在打包时把它转成内嵌数据；路径写错会在单文件浏览器里显示为裂图。

- B8：改名、合并、拆分、删除篇目后，必须回查跨主题引用并改篇号，然后跑 `.workbuddy/check_refs.py <目录>`。只改文件不改引用，等于把引用改坏。



## 三、标题层级

- C1：不使用一级标题。一篇正文等于一章，一级标题的语义层级留给领域，正文一律从二级标题起。元文档不在此限。

- C2：有且只有一个二级标题，且位于文件第一行。索引文件除外，见 B2。

- C3：二级标题的文字等于文件名去掉序号与扩展名。例如 `17. 闭包.md` 的二级标题是 `## 闭包`。

- C4：层级不跳级。H2 到 H3 到 H4 到 H5 逐级下降，相邻两级之间不得缺级。

- C5：各级承载的内容如下，判定以「这一段讲几件事」为准，不以标题长短为准。
  - H3：知识模块，一个模块讲一类事，如 事件模型。
  - H4：单一考点，一个考点只讲一个命题、一个机制或一个对象，如 事件冒泡与捕获。
  - H5：考点之下的具体对象，如具体方法、具体属性、具体分支情形。

- C6：H5 的使用判据：同一 H4 之下有两个及以上同类对象需要分别展开时，用 H5 分列；只有一个对象的并入 H4 正文的列表，不单独设 H5。H5 之下不再分级，需要继续细分说明改写列表或用新的 H4。

- C7：标题不写 1.2、一、（一）、星号等序号，层级一律靠井号数量表达。

- C8：标题内不出现行内反引号、不出现句末标点、不出现换行。

- C9：尚未写完的模块保留空标题占位，标题下方留一行空行，保证大纲完整、后续可定位。

- C10：同一父标题下的同级标题不得重名。



## 四、空行与留白

留白基准来自对库内正文的实测。空行数按下列规则判定：

- D1：二级标题之后空 1 行。

- D2：同一父标题下的首个同级标题，其前空 1 行。H3、H4、H5 一律适用。

- D3：同级标题之间空 3 行。H3、H4、H5 一律适用。

- D4：标题之后紧接正文时，标题与正文之间空 1 行。

- D5：段落之间空 1 行。

- D6：引用块与警示框前后各空 1 行。

- D7：引用块或警示框正好落在同级标题之前时，其前的空行按标题规则计——首个同级标题前 1 行，其余同级标题前 3 行，不因 D6 改变行数。

- D8：代码围栏前后各空 1 行，围栏与上一段落、下一段落之间不贴行。

- D9：文件末尾保留单个换行，不堆叠空行。



## 五、正文写法

- E1：概念首次出现即给定义，一句话给全，不假设读者已知，不做铺垫。

- E2：技术术语首次出现即给完整签名。写到方法就带参数，例如写出数组 splice 方法的 index、deleteCount、items 三个参数，而不只写方法名。

- E3：要点用无序列表承载，每条为「加粗小标题＋全角冒号＋一句说明」。不把多个要点挤进一个段落。

- E4：不使用 我们、大家、其实、简单来说、众所周知 等口语衔接，不写与读者的互动语，不写「让我们来看看」这类起兴句。

- E5：不写自指与空指代，如「本节」「如上所述」「详见下文」「前面提到过」。需要衔接时直接把对象名写出来。

- E6：不写会过期的硬数字。篇数、行数、文件数、章节数一律不写进正文；确需给出时改为「多个」「数十篇」这类量词，或在同篇内写明以脚本现查为准。

- E7：区分事实与推断。条文号、版本号、废止情况这类会变的结论必须先核实再写；无法核实的，在引用块里标注来源与核实状态，不凭记忆落笔。

- E8：中文语境用全角标点，引用他人原话或强调特定说法时用中文直角引号「」。半角标点只出现在代码围栏内与英文术语之间。



## 六、代码块与示例

- F1：围栏代码块必须带语言标注，写法是三个反引号紧接语言名。允许的语言名清单如下，清单以外的语言名不得使用。
  - 前端：js、ts、jsx、tsx、html、css、scss。
  - 后端与运维：bash、sql、json、nginx、http。
  - 纯文本输出：text。

- F2：一段代码一个围栏，一个围栏只讲一件事。围栏内不使用省略号省去代码，占位写法另起一段并写清写了什么。

- F3：示例代码整段可复制即用。依赖外部变量的，在同一篇的前文先给出该变量的定义，或在该围栏内一并给出。

- F4：正文引用运行结果时，结果必须是从围栏中抽出实跑得到的，逐行对应，放在 text 围栏里。不得凭印象手写输出。

- F5：自定义函数写完整形态，含函数名、参数、返回值。命名用驼峰、言简意赅、英文直译，不加人名与特殊前缀；示例中的占位函数同样用有意义的名字（如 getRandomInt、makeCounter），不用 fun1、fn、Foo 之类。

- F6：构造函数与类用大驼峰（如 Person）。常量用全大写下划线分隔。

- F7：命令与它的输出分成两个围栏，命令用 bash、输出用 text，不混排在一个围栏里。



## 七、提示载体：引用块与警示框

- G1：引用块是普通提示与辨析的载体。常见用途为易混辨析、条文补充、例外情况、记忆口诀、理论同实务的分歧说明、来源与核实状态标注。

- G2：需表达「需要注意」「务必遵守」「后果严重」等更强语义时，改用警示框。判据：一般提示、辨析、补充用引用块；强调、强制、后果提示用警示框。

- G3：警示框五类，按语义择一，不得混用。正文首句以对应的中文点题词加粗引领，点题词须与下表逐字一致。

| 类型 | 中文点题词 | 语义 |
| --- | --- | --- |
| NOTE | 提醒内容 | 读者应知、快览也应留意的一般信息 |
| TIP | 建议内容 | 可选的技巧或建议 |
| IMPORTANT | 重要内容 | 成功完成某事所必需的关键信息 |
| WARNING | 警告内容 | 因潜在风险要求立刻注意 |
| CAUTION | 注意内容 | 某操作可能带来的负面影响或需谨慎的后果 |

- G4：警示框的书写法固定为——首行写类型标记，紧接一行写以中文点题词加粗引领的正文：

```text
> [!WARNING]
> **警告内容**：正文……
```

- G5：一个警示框只讲一件事，不在一个框里罗列多个无关要点，不嵌套警示框。

- G6：WARNING 的点题词必须是「警告内容」，写「警告」会被校验脚本判错。

- G7：正文中描述警示框写法时用围栏代码块示例，不用自然语言逐字描述大于号、方括号这类符号。



## 八、主题体例族

同一主题内的篇目共用一套体例。体例族按主题归属确定，一经确定不得在主题内混用。

- T1：技术篇体例。适用于前端、后端、工具、架构四领域的技术主题，范本是 `前端/JavaScript`。特征如下。
  - H2＝篇名，H3＝知识模块，H4＝单一考点，H5＝考点下的具体对象。
  - 每个 H4 的首行是定调句，三种合法形态择一：定义型写「加粗术语：是……」，机制型写加粗判断句，列举型写一句导语。首行不得直接进列表或代码围栏，须是完整句子。
  - 节末收束：推荐在每个 H4 的末尾以引用块或警示框收尾，把该节的结论、取舍、易错点收在那里，不把结论混在正文段落里。库内范本主题（JavaScript）已全面执行，其他主题随改写逐步收敛，不作硬性要求。
  - 代码与实测输出配套出现，输出放在 text 围栏。
  - 速记与本主题的既定体例保持一致。库内范本主题（JavaScript）不写速记；同一主题内不得一部分篇写、一部分篇不写。
  - 篇首导语：可写可不写，同一主题内保持一致。库内范本主题（JavaScript）不写，二级标题之后直接进首个三级标题；架构侧软考类主题普遍写一段，交代本篇范围与线索。两种做法都合法，同一主题内不得一半写一半不写。

- T2：考纲条目体例。适用于软考考纲类主题（`架构/` 下按考纲组织的主题）。
  - H3＝大纲大块，H4＝单一考点，H4 之下不再分级。
  - 每个 H4 的末尾独立一行写「考察形式」，后接冒号与该考点的考法（综合知识选择题、案例分析、论文写作之一或多种）。
  - 不写速记。

- T3：法规条文体例。适用于 `法律/` 下以条文原貌为主的主题。
  - H3＝章，H4＝节或条文组，条文以引用块或列表呈现，条号写在条文之前。
  - 每个 H4 的末尾写一行「速记」，把该节要背的点收成一句。
  - 引用条号前必须核对现行有效版本，新旧对照写进引用块。

- T4：案例体例。适用于 `法律/法律案例库` 等以个案为单位的主题。
  - 每篇一个案件，H3＝案情、定性、处理、依据、评析一类的固定分段。
  - 事实与法律适用分开写，不把评价混进案情陈述。
  - 每篇末尾以引用块收束该案的要点。

- T5：函数合集篇体例。适用于以「一组可复用函数」为单位的篇目，范本是 `前端/JavaScript/33. 自定义函数`。
  - H3＝一组用途相同的函数，组名直述用途。二级标题之后、首个三级标题之前写一段篇首导语，交代本篇收录什么、按什么标准取舍、新函数往哪里加。
  - 组内函数按固定五段展开，段落名逐字为：完整函数、测试用例、测试结果、异常情况、注意情况。
  - 完整函数段：该组全部函数放同一个 js 围栏，整段可复制；函数说明写成「函数名：一句话」的条目，不铺陈原理。
  - 测试用例段：调用与打印放同一个 js 围栏。
  - 测试结果段：实跑输出放 text 围栏，逐行对应测试用例的打印顺序。
  - 异常情况段：先写一句「哪几类输入会给出错误结果且不报错」，再给复现用例与输出。
  - 注意情况段：写取舍与边界，说明哪些处理有意不做。
  - 收尾：完整函数、测试用例、测试结果、异常情况四段以代码围栏收尾，不套用 T1 的引用块收尾条款；注意情况段以引用块或警示框收尾。
  - 首行：实现类与示例类小节的标题之后可直接进代码围栏或列表，不套用 T1 的首行定调句条款；约定类小节仍写一句定调句。
  - 函数宁少不多，只给最基础形态；表头清洗、重名退让、判空、位置修正这类通用性处理一律不做，取舍写进注意情况。
  - 组内多个函数共用的逻辑抽成工具函数放在该组之前，并单独成 H4。

- T6：体例族只约束结构，不约束内容。跨主题引用只写「某主题第 N 篇」，不复制他篇正文；同一条知识只在一个主题里写全，其余主题衔接标注。

- T7：常识轻量体例。适用于「常识/」领域全部主题，按库内常识主题的现行写法定型。
  - H2＝篇名，H3＝知识模块，一篇通常两到四个模块；H4 一般不用，确需分列具体对象时按 C5 的判据使用。
  - 二级标题之后直接进首个三级标题，不写篇首导语；三级标题之后不要求定调句，直接以列表展开。
  - 要点用无序列表承载，每条一行，以提示语加全角冒号引出说明。
  - 换算与对照类内容可用 text 围栏给示例；除 text 外不设代码围栏，不写速记，不写考察形式。
  - 每篇至少以一个引用块或警示框收束，放在全篇末尾或相应模块末尾，把风险提示与例外情况收在那里。



## 九、全库统一禁用的元素

下列元素不分领域一律不用：

- X1：Markdown 表格。正文、索引、引用块与警示框内一律不出现表格。需要对照关系时改成无序列表，每条一行。元文档不在此限。

- X2：水平分隔线。三个及以上的连字符、星号或下划线独占一行时会被渲染成分隔线，破坏标题层级与留白判定。

- X3：围栏外的行内反引号。反引号只允许出现在代码围栏内。正文、标题、列表、引用块与警示框内需要指代符号时直接写符号本身，需要辨识度时加粗。

- X4：正文中的裸 HTML 标签。尖括号括起的元素名写进正文时会被渲染端当作真实 HTML 解析，导致文字被拆段、标签被吞。必须展示标签原文时放入带 html 语言标注的围栏。

- X5：彩色 Emoji 与 emoji 变体选择符（Unicode 的 U+1F000–U+1FAFF 区段与 U+FE0F，即靶心、闪电、彩色对勾这类图形表情）。正文、标题、列表、引用块与警示框内一律不用；技术讲解中必须指称某个字符时写码位（如 U+1F600），不把图形本体写进正文。箭头（→、↔）、判读符号（✓、✗、⚠）与项目符号不属此列，库内既有的流程链写法照常使用。



## 十、自查清单

提交前逐项确认，每项后括号内为对应条款号：

- 文件名符合 B5／B6；索引文件的文件名、首行与条目格式符合 B1–B4。（B）
- 一级标题不存在，二级标题唯一且在首行，文字与文件名一致。（C1–C3）
- 标题未跳级，各级承载与 H5 判据符合 C4–C6，标题内无序号、无反引号、无句末标点。（C4–C8）
- 未写完的模块保留空标题占位；同父标题下无重名同级标题。（C9／C10）
- 标题、段落、引用块、警示框、代码围栏之间的空行数符合 D1–D9；文件末尾为单个换行。（D）
- 概念首次出现即定义；技术术语带完整签名；要点用列表承载；无口语衔接、无自指、无硬数字。（E1–E6）
- 需核实的结论已核实或已标注来源；标点与引号符合 E8。（E7／E8）
- 围栏均带语言标注且在 F1 清单内；示例整段可复制；实跑输出放在 text 围栏。（F1–F4）
- 函数与类命名符合 F5／F6；命令与输出分栏。（F5–F7）
- 提示载体选择正确：一般提示、辨析、补充用引用块，更强语义用警示框；类型、点题词、一框一意均符合 G1–G7。（G）
- 本篇体例族已确定，且与同主题其他篇目一致。（T）
- 全文无表格、无水平分隔线、围栏外无反引号、无裸 HTML 标签、无 Emoji。（X1–X5）



## 十一、条款与校验脚本对照

可机器判定的条款已由 `.workbuddy/validate_doc.py` 覆盖，对应关系如下：

| 脚本检查项 | 条款 | 级别 |
| --- | --- | --- |
| 围栏不成对 | F1 | ERROR |
| 出现一级标题 | C1 | ERROR |
| 二级标题数不为 1 | C2 | ERROR |
| 二级标题与文件名不一致 | C3 | ERROR |
| 疑似表格行 | X1 | ERROR |
| 水平分隔线 | X2 | ERROR |
| 围栏外反引号 | X3 | ERROR |
| 末尾无换行或多余空行 | D9 | ERROR |
| 标题跳级 | C4 | ERROR |
| 标题前空行不符（首个 1 行、同级间 3 行） | D2／D3 | ERROR |
| 标题后未空行 | D4 | ERROR |
| 引用块前后空行不符 | D6／D7 | ERROR |

尚未机器判定、目前靠自查与人审的条款：B3／B4（索引条目格式与同步）、C5／C6（H5 判据）、D8（围栏前后空行）、E 全族、F1 的语言名清单、F2–F4、T 全族、X5。



## 十二、改动本规范时的同步清单

改动条款号、增删条款或调整体例时，下列位置必须一并核对，缺一处都会让库里两套口径并存：

- `build-docs.mjs`：构建期提示与注释里的条款号引用。
- `src/template/runtime.js`：运行时注释里的条款号与规范文件路径。
- `.workbuddy/validate_doc.py`：校验项清单与文件头的说明。
- `.workbuddy/check_series.py`、`.workbuddy/check_index_sync.py`、`.workbuddy/check_refs.py`：条款号引用。
- `~/.workbuddy/skills/learning-library-docs/SKILL.md`：条款体系描述、索引体例、两套体例族的说明。
- `.workbuddy/memory/MEMORY.md` 与 `~/.workbuddy/MEMORY.md`：条款号与体例描述。
- 仓库根的 `学习库.html`：改完跑构建重建，产物里嵌有模板注释。
