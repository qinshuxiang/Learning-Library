## 第一个测试：Node 内置测试运行器

**Node 内置测试运行器**：是随 Node.js 一同提供的测试工具，由 node:test 模块提供运行与组织能力、node:assert 模块提供断言能力，不安装任何第三方依赖即可写第一个用例。本篇讲清这两个模块的用法、命令行的关键选项与错误排查，配套的全部示例都可以直接运行。

### node:test 模块

本模块回答「用例怎么写、注册到哪里、套件与用例如何分层」。

#### node:test 是什么

**node:test 模块**：是 Node.js 内置的测试运行器模块，从 node:test 导入 test 函数即可注册用例，自 Node 18 起稳定可用。

- 零依赖：随 Node 提供，测试依赖不会进入依赖树与锁文件。
- 职责：负责用例注册、执行调度、结果汇总与退出码，不负责断言。
- 配套：断言能力由内置的 node:assert 模块提供。
- 版本：Node 20 起相关 API 趋于稳定，Node 22 之后新增报告器等能力。

```js
import { test } from "node:test";

test("addScore 在两个正数输入下应返回累加结果", () => {
  console.log("用例已注册，尚未写断言"); // 用例已注册，尚未写断言
});
```

**速记**：node:test 是内置运行器，从 node:test 导入 test 注册用例，无需安装。



#### test 函数的签名与参数

**test 函数**：是注册单条用例的入口，签名为 test(name, options, fn)，三个参数依次是用例名称、可选配置对象与用例体函数。

- name：字符串，用例标题，失败报告中用来定位问题。
- options：可选对象，常用字段有 timeout、skip、only、todo 与 concurrency。
- fn：用例体函数，接收一个 TestContext 参数，可以同步返回，也可以返回 Promise 表示异步用例。
- 返回值：返回一个 Promise，等待它可以获知该用例最终是成功还是失败。

```js
import { test } from "node:test";
import assert from "node:assert/strict";

test("calculateDiscount 在折扣率 0.2 下应返回 80", { timeout: 1000 }, () => {
  const actual = 100 * (1 - 0.2);
  assert.equal(actual, 80); // 断言通过
});

test("parsePort 在输入非法时应抛出错误", { skip: "待实现后再打开" }, () => {
  assert.ok(false); // 该用例被跳过，不会执行到这里
});
```

**速记**：test 的签名是 name、options、fn，返回 Promise，options 控制超时与跳过。



#### describe 与 it 的组织

**describe 函数**：是分组入口，签名为 describe(name, options, fn)，把一组相关用例归入同一个测试套件。**it 函数**：是 test 的别名，签名为 it(name, options, fn)，用于表达「某行为应某结果」。

- 分组：describe 内的用例在报告中归成一个套件，支持逐层嵌套。
- 命名：套件名与用例名拼接后构成用例的完整名称，是筛选时的匹配对象。
- 别名关系：it 与 test 完全等价，选择哪一个是可读性偏好。
- 约定：套件名写被测对象，用例名写输入与预期结果。

```js
import { describe, it } from "node:test";
import assert from "node:assert/strict";

describe("formatPriceInCents", () => {
  it("在整数分输入下应保留两位小数", () => {
    assert.equal(`¥${(1999 / 100).toFixed(2)}`, "¥19.99");
  });

  it("在零输入下应返回零元", () => {
    assert.equal(`¥${(0 / 100).toFixed(2)}`, "¥0.00");
  });
});
```

**速记**：describe 负责分组、it 是 test 的别名，套件名与用例名拼接后用于筛选。



#### 子测试与嵌套

**子测试（subtest）**：是在一条用例内部通过测试上下文再次注册的用例，签名为 t.test(name, options, fn)，其中 t 是用例体收到的 TestContext。

- 获取上下文：用例体的第一个参数即 TestContext，匿名箭头函数需显式写出该参数。
- 等待结果：必须 await t.test(...)，否则父用例可能在子测试报告之前就结束。
- 报告层级：子测试结果挂在父用例之下，报告中呈树形展开。
- 用途：把一段流程拆成多个可独立报告的检查点，同时共享父用例的准备结果。

```js
import { test } from "node:test";
import assert from "node:assert/strict";

test("购物车在逐步添加商品后应正确累计", async (t) => {
  const cart = { items: [] };

  await t.test("添加第一件商品后应有 1 条记录", () => {
    cart.items.push({ sku: "A-1", qty: 1 });
    assert.equal(cart.items.length, 1);
  });

  await t.test("添加第二件商品后应有 2 条记录", () => {
    cart.items.push({ sku: "B-2", qty: 3 });
    assert.equal(cart.items.length, 2);
  });
});
```

**速记**：子测试用 t.test 注册并必须 await，报告呈树形，适合拆分流程检查点。



### node:assert 断言模块

本模块回答「预期怎么写、失败信息怎么读」。

#### node:assert 是什么

**node:assert 模块**：是 Node.js 内置的断言库，通过函数式断言判断值与关系，断言不成立时抛出 AssertionError。

- 导入方式：默认导入 assert，再调用其上的方法。
- 失败行为：断言不成立即抛出异常，运行器捕获后把该用例标记为失败。
- 自定义消息：多数方法支持最后一个可选参数 message，用于补充失败上下文。
- 组合：与 node:test 同属内置，二者是默认搭配。

```js
import assert from "node:assert";

function addItemToCart(cart, item) {
  return { items: [...cart.items, item] };
}

const nextCart = addItemToCart({ items: [] }, { sku: "A-1", qty: 2 });
assert.equal(nextCart.items.length, 1, "加入一件商品后应只剩 1 条记录");
```

**速记**：node:assert 是内置断言库，失败抛 AssertionError，可传 message 补充上下文。



#### strict 模式

**strict 模式**：是 node:assert/strict 提供的断言集合，主要差别是 equal 系列采用严格相等语义，不做类型转换。

- 导入路径：从 node:assert/strict 导入。
- 语义差别：strict 下 assert.equal 等价于 assert.strictEqual，assert.deepEqual 等价于 assert.deepStrictEqual。
- 对照示例：数字 1 与字符串 “1” 在非严格模式下相等，在严格模式下不相等。
- 建议：新代码统一使用 strict 模式，避免隐式类型转换掩盖缺陷。

```js
import assert from "node:assert/strict";

assert.equal(1, 1);            // 通过
// assert.equal(1, "1");       // 报错：严格模式下 1 与字符串 "1" 不相等
assert.deepEqual({ a: 1 }, { a: 1 }); // 通过，逐层严格比较
```

**速记**：strict 模式让 equal 走严格相等，新代码应统一使用它。



#### 常用断言方法与签名

**常用断言方法**：是 node:assert 暴露的判断函数集合，签名统一为 method(actual, expected, message)，其中 message 可选。

- assert.ok(value, message)：判断 value 是否为真值。
- assert.strictEqual(actual, expected, message)：判断两个值严格相等。
- assert.deepStrictEqual(actual, expected, message)：逐层比较对象或数组的结构与值。
- assert.throws(fn, error, message)：判断 fn 是否抛出符合 error 描述的错误。
- assert.rejects(asyncFn, error, message)：判断异步函数返回的 Promise 是否以预期的错误拒绝。

```js
import assert from "node:assert/strict";
import { describe, it } from "node:test";

function parsePort(text) {
  const port = Number(text);
  if (!Number.isInteger(port) || port <= 0) {
    throw new RangeError("端口号必须是正整数");
  }
  return port;
}

describe("parsePort", () => {
  it("在数字字符串输入下应返回数字类型端口", () => {
    assert.strictEqual(parsePort("8080"), 8080);
  });

  it("在非法输入下应抛出范围错误", () => {
    assert.throws(() => parsePort("abc"), RangeError);
  });
});
```

**速记**：断言统一为 method(actual, expected, message)，判断值用 strictEqual，判异常用 throws。



#### 断言失败的信息

**断言失败信息**：是 AssertionError 携带的实际值、预期值、运算符与堆栈，用于定位失败原因。

- 三个字段：actual 是实际值，expected 是预期值，operator 是所用断言的名称。
- 自定义消息：传入 message 后，报告中会以该消息替换默认描述。
- 截断现象：超长对象在报告中会被截断，关键上下文应写进 message。
- 排查顺序：先确认 actual 是否为 undefined（多半是取值路径写错），再核对预期口径。

```bash
node --test

# ✖ formatPriceInCents 在整数分输入下应保留两位小数 (1.4ms)
#   AssertionError [ERR_ASSERTION]: 价格格式化结果不符
#       actual: '¥20.00',
#      expected: '¥19.99',
#      operator: 'strictEqual'
#   ℹ tests 1 | pass 0 | fail 1
```

**速记**：失败报告给出 actual、expected 与 operator，先看 actual 再核对预期口径。



### 运行命令与输出解读

本模块回答「命令怎么敲、报告怎么读、结果怎么交给流水线」。

#### node --test 的默认发现规则

**node --test 命令**：是启动内置运行器的入口，不接参数时按约定的命名规则自动发现测试文件。

- 目录约定：名为 test 的目录下的 JavaScript 文件会被扫描。
- 命名约定：文件名以 test- 开头，或以 .test.js、-test.js、_test.js、.spec.js 结尾的文件会被扫描。
- 指定范围：接文件或目录参数时只运行指定范围，如 node --test test/cart.test.js。
- 前提：需要 Node 18 及以上版本；使用 ESM 写法时在 package.json 中声明 type 为 module。

```bash
node --test
node --test test/
node --test test/cart.test.js
node --test "test/**/*.test.js"
```

**速记**：node --test 按 test 目录与 test、spec 命名约定自动发现用例，也可指定路径。



#### 输出格式与汇总行

**测试报告**：是运行结束后逐条列出的用例结果与末尾的汇总计数，默认报告器在非交互环境下输出 TAP 风格文本。

- 用例行：对号表示通过，叉号表示失败，减号表示跳过，行尾给出耗时。
- 嵌套展示：套件与子测试按层级缩进，便于定位失败所属的组。
- 汇总行：给出 tests、suites、pass、fail、cancelled、skipped、todo、duration 等计数。
- 失败详情：紧跟在失败用例之后，包含断言消息与实际值。

```bash
node --test

# ✔ formatPriceInCents 在整数分输入下应保留两位小数 (0.8ms)
# ✔ formatPriceInCents 在零输入下应返回零元 (0.2ms)
# ℹ tests 2
# ℹ suites 1
# ℹ pass 2
# ℹ fail 0
# ℹ duration_ms 42.5
```

**速记**：报告逐条给出用例结果，末尾汇总 pass 与 fail 计数，失败详情紧随其后。



#### 退出码与流水线接入

**退出码**：是进程结束时返回给调用方的整数，内置运行器以 0 表示全部通过、非 0 表示存在失败或错误。

- 通过：退出码 0，命令链继续执行。
- 失败：退出码非 0，配合命令连接符可让后续步骤中断。
- 用途：不解析文本输出即可判定结果，适合接入持续集成。
- 扩展：可通过 --test-reporter 指定报告格式，再用 --test-reporter-destination 指定输出文件。

```bash
node --test && echo "全部通过"
# ℹ pass 2
# 全部通过
# 退出码为 0
```

**速记**：通过返回 0、失败返回非 0，退出码是不解析文本即可判定的依据。



#### 常用命令行选项

**命令行选项**：是调整发现范围与执行行为的开关，与 node --test 组合使用。

- node --test --test-name-pattern=关键字：按正则筛选用例名称。
- node --test --test-only：只运行被标记为 only 的用例。
- node --test --test-concurrency=4：设置同时执行的用例数量上限。
- node --test --test-timeout=2000：设置单条用例的超时毫秒数。
- node --test --test-reporter=spec：指定报告器，常用的还有 dot 与 tap。

```bash
node --test --test-name-pattern="formatPriceInCents"
node --test --test-concurrency=4
node --test --test-timeout=2000 --test-reporter=spec
```

**速记**：筛选名称用 --test-name-pattern，限并发用 --test-concurrency，限时用 --test-timeout。



### 监视模式与用例筛选

本模块回答「本地开发期如何快速重跑，以及如何只跑关心的用例」。

#### 监视模式

**监视模式**：是 node --test --watch 启动的持续运行状态，被监听的文件发生变化后自动重新执行相关用例。

- 启动：node --test --watch。
- 交互：按回车立即重跑全部用例，输入字符可按名称过滤。
- 版本：监视模式下 Node 会分析用例对文件的引用关系，只重跑受影响的部分。
- 边界：监视模式用于本地开发，不用于流水线等一次性执行场景。

```bash
node --test --watch

# ▶ 回车重新运行，输入字符可过滤用例名称
# ℹ pass 2
# ℹ fail 0
```

**速记**：node --test --watch 持续监听文件变化并自动重跑，只用于本地开发。



#### --test-name-pattern 筛选用例

**--test-name-pattern 选项**：是按正则表达式筛选用例名称的开关，只有名称匹配的用例才会执行。

- 用法：node --test --test-name-pattern="优惠券"。
- 匹配对象：套件名与用例名拼接后的完整名称。
- 取值：值是正则表达式的源文本，包含元字符时需要转义。
- 组合：可与监视模式一起使用，开发中只重跑当前正在改的那组用例。

```bash
node --test --test-name-pattern="购物车"

# ✔ 购物车在逐步添加商品后应正确累计 (2.1ms)
# ℹ tests 1
# ℹ pass 1
# ℹ skipped 3
```

**速记**：--test-name-pattern 按正则匹配完整用例名，筛选后未命中的用例不执行。



#### 仅运行与跳过

**跳过（skip）与仅运行（only）**：是通过 options 对象控制用例是否参与本次执行的两个标记字段。

- skip：options.skip 设为 true 时不执行，设为字符串时报告里显示该原因。
- only：options.only 设为 true 时，只执行被标记的用例及其所在套件。
- 命令行：--test-only 与 only 配合，避免把标记提交到仓库。
- 类型：选项还可传 todo，表示该用例预期失败且不参与通过判定。

> [!CAUTION]
> **注意内容**：options.only 会遮蔽其他全部用例，若提交进仓库会导致流水线长期只跑少数用例。

**速记**：skip 跳过、only 只跑被标记的用例，only 必须在提交前移除。



#### 超时与并发控制

**超时（timeout）**：是单条用例允许执行的最长时间，超过即判为失败。**并发（concurrency）**：是同时处于执行中的用例数量上限。

- 用例级超时：在 options 中传 timeout，单位是毫秒，只作用于该用例。
- 全局超时：命令行 --test-timeout 设置默认值，未单独指定的用例都适用。
- 套件级并发：在 describe 的 options 中传 concurrency，控制该套件内的并行数量。
- 风险：共享可变状态的用例并行执行会互相干扰，产生间歇性失败。

```js
import { describe, it } from "node:test";
import assert from "node:assert/strict";

describe("库存扣减", { concurrency: 2 }, () => {
  it("在库存充足时应返回扣减后的数量", { timeout: 1000 }, () => {
    assert.equal(10 - 3, 7);
  });
});
```

**速记**：timeout 控制单条用例时限，concurrency 控制并发，共享状态不可并行。



### 最小可运行项目

本模块给出一个从零搭建、能跑通的最小项目，并列出常见失败与排查路径。

#### 目录结构与文件约定

**目录结构**：是内置运行器默认识别的最小目录与文件布局，用于让命令不接参数也能找到用例。

- 源码目录：src，存放被测函数。
- 测试目录：test，存放用例文件，文件以 .test.js 结尾。
- 发现规则：test 目录下的文件会被扫描，命名符合约定的文件也会被扫描。
- 配置：内置运行器不需要任何配置文件。

```bash
mkdir -p node-test-demo/src node-test-demo/test
cd node-test-demo
npm init -y
# 生成 package.json，随后声明 type 为 module 使用 ESM
```

**速记**：源码放 src、用例放 test 并以 .test.js 结尾，内置运行器无需配置文件。



#### package.json 脚本配置

**package.json 脚本**：是把运行命令固化到 scripts 字段的做法，便于团队用同一条命令执行测试。

- test：写 node --test，与 npm test 绑定。
- test:watch：写 node --test --watch，供本地开发使用。
- test:coverage：写 node --test --experimental-test-coverage，输出覆盖率统计。
- type：声明为 module，使 .js 文件按 ESM 解析。

```json
{
  "name": "node-test-demo",
  "type": "module",
  "scripts": {
    "test": "node --test",
    "test:watch": "node --test --watch",
    "test:coverage": "node --test --experimental-test-coverage"
  }
}
```

**速记**：scripts 里固化 test、test:watch 与覆盖率三条命令，type 声明为 module。



#### 编写第一个用例

**第一个用例**：是覆盖一个纯函数的最小测试，包含导入被测函数、注册用例与断言三步。

- 被测函数：写在 src 目录，导出为具名导出。
- 用例文件：写在 test 目录，导入被测函数并注册用例。
- 断言：用 node:assert/strict 判断返回值。
- 运行：在项目根执行 npm test 或 node --test。

```js
// src/format-price.js
export function formatPriceInCents(cents) {
  return `¥${(cents / 100).toFixed(2)}`;
}
```

```js
// test/format-price.test.js
import { test } from "node:test";
import assert from "node:assert/strict";
import { formatPriceInCents } from "../src/format-price.js";

test("formatPriceInCents 在整数分输入下应保留两位小数", () => {
  assert.equal(formatPriceInCents(1999), "¥19.99");
});
```

```bash
npm test

# ✔ formatPriceInCents 在整数分输入下应保留两位小数 (1.0ms)
# ℹ tests 1
# ℹ pass 1
# ℹ fail 0
```

**速记**：第一个用例等于导入被测函数、注册 test、用 assert 断言返回值为三步。



#### 运行与常见排查

**运行排查**：是按报告定位失败原因并确认修复的闭环过程。

- 第一检查点：汇总行的 fail 计数与退出码，先确认是否真的失败。
- 模块解析失败：核对导入路径是否带 .js 扩展名、是否遗漏 type 声明。
- 断言口径不符：核对 expected 的取值与类型，注意 0 与字符串 “0” 的差别。
- 异步未等待：用例体是异步的必须返回 Promise 或写成 async 函数，否则断言在完成前就结束。
- 用例未被发现：确认文件命名与目录是否符合默认约定。

> [!WARNING]
> **警告内容**：异步用例若忘记 await 内部操作，用例会在断言执行之前就结束并显示通过，从而掩盖真实缺陷。

**速记**：先看 fail 与退出码，再按解析、断言口径、异步等待、用例发现四条排查。
