## Vue 组件测试

### 组件测试的定位

**组件测试**：是以单个 Vue 组件为被测单元、在模拟 DOM 环境中挂载运行并验证其对外行为的测试。

本模块先划定组件测试的位置与边界，再交代所需环境与依赖，为挂载与交互的具体手段做铺垫。

#### 组件测试与其他层级的分工

**组件测试的分工**：是在单元测试与端到端测试之间取一个中间位置，覆盖模板渲染与事件联动，又不启动真实浏览器与后端服务。

- 单元测试：只测函数与工具模块，不渲染组件，运行最快（详见本主题第 1 篇 测试简介与测试体系）。
- 组件测试：挂载单个组件，验证 props 渲染、交互响应、条件分支与对外事件。
- 端到端测试：在真实浏览器中串联页面与接口，验证完整流程（详见本主题第 13 篇 端到端测试：Playwright）。
- 集成边界：需要验证父子组件联动时，挂载父组件观测子组件输出，仍不触碰真实网络。

```js
import { describe, it, expect } from "vitest"
import { mount } from "@vue/test-utils"
import CounterButton from "../src/components/CounterButton.vue"

describe("CounterButton", () => {
  it("在传入 label 与 count 时应渲染出合并文本", () => {
    const wrapper = mount(CounterButton, { props: { label: "投票", count: 2 } })
    expect(wrapper.text()).toContain("投票: 2")
  })
})
```

> 组件测试的性价比最高：它比端到端测试快得多，又能覆盖纯单元测试看不到的模板与事件逻辑。

**速记**：组件测试夹在单元与端到端之间，挂载单组件、不碰真实网络。



#### 组件测试测什么与不测什么

**被测范围**：是组件对外的可观察行为，包含渲染出的文本与结构、样式类名、属性值、对外触发的事件与接收的 props。

- 应测：给定 props 后的渲染结果；点击、输入等交互后的 DOM 变化；对外 emit 的事件与载荷；条件渲染与列表渲染的分支。
- 应测：插槽内容是否按预期渲染（插槽自身写法详见 前端/Vue3 主题第 10 篇 插槽 slot）。
- 不测：组件内部私有函数的调用过程、响应式系统的实现细节、第三方库自身的行为。
- 不测：真实网络请求与真实路由跳转，两者在组件测试中用替身替换（详见本主题第 7 篇 测试替身：mock、stub 与 spy）。

```js
it("在点击按钮时应向上发出 increment 事件", async () => {
  const wrapper = mount(CounterButton, { props: { label: "投票", count: 0 } })
  await wrapper.find("button").trigger("click")
  expect(wrapper.emitted("increment")).toHaveLength(1)
})
```

> 判定标准是「只改实现、不改对外行为时测试是否仍然通过」：通过说明测试绑定的是行为，失败说明测试绑定了实现细节。

**速记**：只测对外可观察的渲染与事件，不测内部实现步骤。



#### 测试环境与依赖清单

**测试环境**：是让组件能在 Node.js 中挂载的模拟浏览器环境，由 DOM 模拟库与测试运行器配置共同提供。

- DOM 模拟：jsdom 或 happy-dom 提供 document、window 等全局对象，通过运行器的 environment 选项启用。
- 组件工具：@vue/test-utils v2 提供 mount、shallowMount、flushPromises 等 API，与 Vue 3 配套。
- 编译插件：@vitejs/plugin-vue 让运行器能编译 .vue 单文件组件（运行器配置详见本主题第 5 篇 Vitest 简介与配置）。
- 断言扩展：@testing-library/jest-dom 可选，提供 toBeVisible、toHaveClass 等 DOM 专用匹配器（详见本主题第 11 篇 快照测试与 DOM 断言）。

```bash
npm install --save-dev vitest @vue/test-utils @vitejs/plugin-vue jsdom
```

```js
// vitest.config.js
import { defineConfig } from "vitest/config"
import vue from "@vitejs/plugin-vue"

export default defineConfig({
  plugins: [vue()],
  test: {
    environment: "jsdom",
    globals: true
  }
})
```

> 运行器默认环境是 node，组件测试必须显式切到 jsdom 或 happy-dom，否则挂载时会报 document is not defined。

> [!WARNING]
> **警告内容**：@vue/test-utils v1 面向 Vue 2、v2 面向 Vue 3，两者 API 不兼容；Vue 3 项目误装 v1 会在挂载时报参数结构错误。

**速记**：jsdom 加 @vue/test-utils 加 vue 插件，三者齐备才能挂载组件。



### 挂载组件与传入 props

**挂载**：是把组件实例创建并渲染到模拟 DOM 中的过程，挂载后的返回值是一个包裹器对象，查询、交互与断言都从它出发。

本模块讲清两个挂载入口、props 的传入与更新，以及全局依赖的注入方式。

#### mount 与首次渲染

**mount**：是完整挂载组件的函数，签名为 mount(component, options)，component 为组件定义，options 支持 props、slots、global、attachTo、data 等字段，返回 VueWrapper。

- 返回值：VueWrapper 提供 find、findAll、text、html、trigger、setProps、emitted、unmount 等方法。
- props 传入：通过 options.props 传入对象，键为 prop 名，值为对应数据。
- 挂载到真实节点：传入 attachTo 可挂到 document.body，用于依赖布局尺寸与焦点的场景。
- 卸载：测试结束可调用 wrapper.unmount() 清理挂载产生的副作用。

```js
import { mount } from "@vue/test-utils"
import UserCard from "../src/components/UserCard.vue"

const wrapper = mount(UserCard, {
  props: { name: "Ada Lovelace", role: "工程师" }
})

console.log(wrapper.text())              // "Ada Lovelace 工程师"
console.log(wrapper.find("h2").exists()) // true
```

> 每次挂载会独立创建组件实例，用例之间不会互相污染；仍需注意全局状态与定时器的清理。

**速记**：mount 完整挂载并返回 VueWrapper，props 经 options.props 传入。



#### shallowMount 与子组件隔离

**shallowMount**：是与 mount 同签名但会存根（stub）全部子组件的挂载函数，父组件模板照常渲染，子组件被替换为不渲染内部结构的占位节点。

- 适用：父组件只关心「是否把正确的 props 交给子组件」，子组件自身另有测试。
- 差异：mount 渲染整棵子树，shallowMount 只渲染当前组件一层，用例更快、失败定位更集中。
- 存根控制：可通过 options.global.stubs 指定哪些组件存根，或用自定实现替换。
- 取舍：需要整棵子树一起断言时用 mount，需要隔离被测组件时用 shallowMount。

```js
import { shallowMount } from "@vue/test-utils"
import TodoList from "../src/components/TodoList.vue"

const wrapper = shallowMount(TodoList, {
  props: { items: [{ id: 1, text: "写测试" }] }
})

console.log(wrapper.findAll("todo-item-stub").length) // 1
```

> shallowMount 的产物不包含子组件内部结构，用它做整树快照会得到一堆占位标签，价值有限。

**速记**：shallowMount 只渲染当前组件，子组件一律存根以隔离依赖。



#### props 的传入与更新

**props 的传入**：是在挂载时由 options.props 提供初始值。**props 的更新**：是在挂载后调用 setProps 改变父级传入的数据，验证组件对 props 变化的响应。

- setProps 签名：setProps(props, options) 传入新 props 对象，返回下次 DOM 更新完成的 Promise，必须 await。
- 更新语义：setProps 只覆盖传入的键，未传入的 props 保持原值。
- 校验观察：传入不符合声明的值会触发 Vue 的 prop 校验警告，可断言警告以验证契约。
- 反向验证：断言旧值已被替换，避免只断言新值出现而漏掉残留。

```js
const wrapper = mount(UserCard, { props: { name: "Ada Lovelace" } })
expect(wrapper.text()).toContain("Ada Lovelace")

await wrapper.setProps({ name: "Grace Hopper" })
expect(wrapper.text()).toContain("Grace Hopper")
expect(wrapper.text()).not.toContain("Ada Lovelace")
```

> 漏写 await 会让断言读到更新前的 DOM，表现为「断言偶发失败」，这类问题在本地可能被掩盖而在持续集成上暴露。

**速记**：setProps 返回更新 Promise，必须 await 后再断言新渲染。



#### 全局插件与配置注入

**全局配置注入**：是通过 options.global 为被测组件提供插件、组件、指令、provide 与模拟字段，避免在组件内部为测试写特例。

- global.plugins：注入路由、状态库、国际化等插件实例。
- global.stubs：把无关子组件替换为简单存根，减少无关结构带来的噪声。
- global.mocks：为实例上挂载的全局字段提供替身，如路由对象。
- global.provide：为组合式 API 的 inject 提供值（provide 与 inject 写法详见 前端/Vue3 主题第 11 篇 依赖注入 provide 与 inject）。

```js
import { mount } from "@vue/test-utils"
import { createI18n } from "vue-i18n"
import UserCard from "../src/components/UserCard.vue"

const i18n = createI18n({ locale: "zh", messages: { zh: { greeting: "你好" } } })

const wrapper = mount(UserCard, {
  global: {
    plugins: [i18n],
    stubs: { UserAvatar: true },
    provide: { theme: "light" }
  }
})

expect(wrapper.text()).toContain("你好")
```

> global.mocks 是过渡手段，长期方案是用插件或 provide 注入真实依赖，使组件与测试都不依赖挂载技巧。

**速记**：全局依赖统一走 options.global 注入，组件内部不为测试留分支。



### 触发交互与断言结果

**交互驱动**：是用查询定位节点、用 trigger 触发事件、再用断言读取结果的过程，它把「用户操作」翻译成测试中可复现的调用。

本模块讲查询、触发、表单输入与事件断言四件事。

#### 查询节点 find 与 findAll

**find**：是按选择器返回首个匹配包裹器的方法，签名为 find(selector)，selector 支持 CSS 选择器、组件定义或 ref 名。**findAll**：是返回全部匹配包裹器数组的方法，签名为 findAll(selector)。

- 未命中行为：find 命中不到时返回一个空的包裹器而非抛错，用 exists() 判断是否存在。
- get 的区别：get(selector) 在未命中时直接抛错，用于「断言此时必然存在」的场景。
- 选择器优先级：优先 data-testid 属性，其次语义标签，尽量少依赖样式类名。
- 数组长度：findAll 返回的数组有 length，可直接断言渲染条数。

```js
const wrapper = mount(TodoList, {
  props: { items: [{ id: 1, text: "写测试" }, { id: 2, text: "跑测试" }] }
})

console.log(wrapper.findAll("li").length)                  // 2
console.log(wrapper.get("[data-testid=todo-1]").text())    // "写测试"
console.log(wrapper.find("[data-testid=todo-9]").exists()) // false
```

> 选择器绑定 data-testid 而非样式类名，可以让样式重构不打断测试。

**速记**：find 未命中返回空包裹器，get 未命中直接抛错，选择器优先 data-testid。



#### 触发事件 trigger

**trigger**：是在找到的节点上派发事件的方法，签名为 trigger(eventString, options)，eventString 支持 click、input、keyup.enter 等写法，options 为事件初始化对象。

- 异步语义：trigger 返回下一次 DOM 更新完成的 Promise，涉及渲染变化的断言必须 await。
- 事件修饰：可用 keyup.enter、submit.prevent 等写法模拟带修饰的监听。
- 自定义参数：options 可携带 clientX、button 等字段，验证依赖事件对象的逻辑。
- 组合操作：需要连续交互时逐个 await，保证每次渲染都已完成。

```js
const wrapper = mount(CounterButton, { props: { label: "投票", count: 0 } })

await wrapper.find("button").trigger("click")
expect(wrapper.text()).toContain("投票: 1")

await wrapper.find("input").trigger("keyup.enter")
expect(wrapper.emitted("submit")).toHaveLength(1)
```

> trigger 只负责派发事件，不会自动聚焦或滚动；依赖焦点与布局的行为需要 attachTo 后另行准备。

**速记**：trigger 返回更新 Promise，先 await 再断言渲染与事件。



#### 表单输入 setValue 与 setChecked

**setValue**：是为输入类节点设置值并派发事件的方法，签名为 setValue(value)，适用于文本框、文本域与下拉选择。**setChecked**：是为复选框或单选框设置选中状态的方法，签名为 setChecked(checked)，checked 默认为 true。

- 文本输入：setValue 更新节点值并触发 input 事件，使 v-model 完成双向更新。
- 下拉选择：对 select 节点调用 setValue 传入选项值，触发 change 事件。
- 复选框：setChecked 传入布尔值切换 checked，触发 change 事件。
- 事件语义：三种操作派发的事件与真实用户操作一致，因此能驱动组件内的事件处理器。

```js
const wrapper = mount(LoginForm)

const email = wrapper.find("input[type=text]")
await email.setValue("ada@example.com")
expect(email.element.value).toBe("ada@example.com")

const remember = wrapper.find("input[type=checkbox]")
await remember.setChecked()
expect(remember.element.checked).toBe(true)
```

> 表单绑定本身的写法详见 前端/Vue3 主题第 7 篇 表单绑定 v-model，本篇只关注如何在测试中驱动它。

**速记**：文本用 setValue，勾选用 setChecked，两者都会派发对应事件。



#### 组件自定义事件的断言

**emitted**：是读取组件已发出事件的包裹器方法，签名为 emitted(eventName)，返回一个数组，数组每一项是该次触发时传入的参数列表；事件从未触发时返回 undefined。

- 次数断言：emitted 的 length 即触发次数，用 toHaveLength 断言。
- 载荷断言：emitted(name)[0] 是首次触发的参数数组，用 toEqual 比对完整载荷。
- 未触发断言：对不该发生的事件断言结果为 undefined。
- 组件级 v-model：子组件发出的 update:modelValue 事件同样按此方式断言（写法详见 前端/Vue3 主题第 9 篇 组件事件与组件级 v-model）。

```js
const wrapper = mount(LoginForm)

await wrapper.find("form").trigger("submit.prevent")

expect(wrapper.emitted("submit")).toHaveLength(1)
expect(wrapper.emitted("submit")[0]).toEqual([{ email: "ada@example.com" }])
expect(wrapper.emitted("cancel")).toBeUndefined()
```

> 断言 emitted 比断言父组件中的副作用更直接，它测的是组件的对外契约本身。

**速记**：emitted 返回参数数组的数组，未触发时为 undefined，据此断言次数与载荷。



### 异步更新与依赖替身

**异步边界**：是组件测试中最容易出错的地方。组件的渲染更新、数据加载与路由跳转都不在同一轮同步调用内完成，断言前必须先等待。

本模块讲清等待手段与两类常见依赖的处理。

#### 响应式更新与 nextTick

**nextTick**：是 Vue 提供的等待函数，返回一个在当前 DOM 更新队列刷新后兑现的 Promise，签名为 nextTick()。**实例上的 $nextTick**：是同一能力在组件实例上的入口。

- 更新时机：Vue 把同一次事件循环内的多次数据变更合并，在微任务中统一刷新 DOM。
- 断言前提：读取 text、html、classes 等渲染结果前，先 await nextTick 或 await trigger。
- 变更之后：通过实例修改组件状态后，同样需要 await nextTick 才能看到新 DOM。
- 优先用 await：等待 trigger 与 setProps 的返回值通常已足够，无需额外补 nextTick。

```js
const wrapper = mount(CounterButton, { props: { label: "投票", count: 0 } })

await wrapper.find("button").trigger("click")
await wrapper.vm.$nextTick()   // 通常已由 trigger 的返回值覆盖
expect(wrapper.text()).toContain("投票: 1")
```

> 断言失败时先怀疑「少了一次 await」，而不是怀疑组件逻辑，这是组件测试最高频的排查方向。

**速记**：Vue 合并更新并异步刷新 DOM，读渲染结果前必须等待。



#### flushPromises 与异步加载

**flushPromises**：是 @vue/test-utils 提供的清空微任务队列的函数，签名为 flushPromises()，返回在所有已排队微任务执行完毕后兑现的 Promise。

- 适用场景：组件在 onMounted 中发起请求，请求用替身立即兑现，需要等回调链跑完再断言。
- 与 nextTick 的分工：nextTick 只等一轮 DOM 更新，flushPromises 等整条 Promise 链，含多级 then。
- 组合用法：await flushPromises() 后再 await nextTick()，覆盖数据到位后再触发渲染的情形。
- 失败排查：断言拿到空字符串通常说明数据尚未落地，而非组件未渲染。

```js
import { flushPromises, mount } from "@vue/test-utils"
import UserCard from "../src/components/UserCard.vue"

const wrapper = mount(UserCard, { props: { userId: 7 } })
await flushPromises()
expect(wrapper.text()).toContain("Ada Lovelace")
```

> 与假定时器配合时，需要先推进时间再冲微任务（详见本主题第 9 篇 异步测试与定时器控制）。

**速记**：nextTick 等一轮 DOM，flushPromises 等整条 Promise 链。



#### 路由与状态库依赖的处理

**路由依赖**：是组件对当前路由与路由实例的读取与跳转，在组件测试中用内存历史构造的真实路由实例或直接替身替换。**状态库依赖**：是组件对状态库的读取，用测试专用插件让 store 可注入且可观测。

- 路由实例：用 createRouter 搭配 createMemoryHistory 构造内存路由，注入 global.plugins 后当前路由可直接读取。
- 跳转断言：调用 router.push 后 await router.isReady() 或 await flushPromises()，再断言组件渲染。
- 路由替身：只读参数时可用 global.mocks 提供路由参数，避免搭建完整路由表。
- 状态库：@pinia/testing 的 createTestingPinia 提供 initialState 预设数据与 createSpy 生成的行为替身。

```js
import { createRouter, createMemoryHistory } from "vue-router"
import { flushPromises, mount } from "@vue/test-utils"
import UserDetail from "../src/components/UserDetail.vue"

const router = createRouter({
  history: createMemoryHistory(),
  routes: [{ path: "/users/:id", component: UserDetail }]
})

router.push("/users/7")
await router.isReady()

const wrapper = mount(UserDetail, { global: { plugins: [router] } })
await flushPromises()
expect(wrapper.vm.$route.params.id).toBe("7")
```

```js
import { createTestingPinia } from "@pinia/testing"
import { mount } from "@vue/test-utils"
import { useUserStore } from "../src/stores/user"
import UserCard from "../src/components/UserCard.vue"

const wrapper = mount(UserCard, {
  global: {
    plugins: [
      createTestingPinia({
        createSpy: vi.fn,
        initialState: { user: { name: "Ada Lovelace" } }
      })
    ]
  }
})

const store = useUserStore()
expect(store.name).toBe("Ada Lovelace")
```

> 状态库接入的完整 API 与写法详见 前端/Vue3 主题第 21 篇 Pinia 状态管理，本篇只保留测试侧的接入方式。

**速记**：路由用内存历史或替身注入，状态库用 createTestingPinia 注入。



### 常见问题排查

**排查思路**：是沿着「环境、解析、等待」三个环节定位，多数组件测试失败都落在其中一环。

#### 挂载报错与选择器失效

挂载阶段的失败多集中在环境与解析两环，按报错文本逐条对照。

- document is not defined：environment 未设为 jsdom 或 happy-dom，组件根本没有 DOM 可用。
- 无法解析 .vue 文件：测试配置缺少 @vitejs/plugin-vue，或该插件版本与 Vue 版本不匹配。
- find 结果为空：选择器与模板不一致，或渲染尚未完成，先确认 exists 再补 await。
- props 校验警告：传入类型与声明不符，按警告文本核对 prop 名与类型。

```bash
npx vitest run --reporter=verbose
# 在输出中定位首个失败用例与环境报错
```

> 排查顺序为先看环境是否可用，再看组件是否渲染出来，最后才怀疑断言逻辑本身。

**速记**：先查环境再查解析，最后怀疑断言。



#### 事件与异步断言的常见误用

这几类误用都源于异步未等待与断言绑定实现细节，逐条核对即可规避。

- 忘记 await：trigger、setProps、setValue 的返回值未等待，断言读到旧 DOM。
- 事件名写错：emitted 传入的名称与组件 emit 的名称大小写或连字符不一致，得到 undefined。
- 断言实现而非行为：断言内部方法被调用次数，组件重构后测试无意义地失败。
- 依赖真实网络：未替换请求，用例受网络与后端数据影响而随机失败。

```js
// 错误：未等待更新，断言可能读到旧结果
// await wrapper.find("button").trigger("click")   // 漏掉 await
// expect(wrapper.text()).toContain("投票: 1")      // 断言不稳定
```

> [!CAUTION]
> **注意内容**：把未 await 的异步断言写进用例，会在本地偶然通过而在并发环境随机失败，排查成本极高。

**速记**：交互与更新一律 await，断言绑定对外行为，网络一律替换。
