## 断言与匹配器

### 断言的作用与失败信息

测试用例是否通过，最终由断言决定。本节说明断言是什么、失败时给出什么信号，以及断言与测试用例之间的关系。

#### 什么是断言

**断言（assertion）**：是测试代码中判断实际值是否符合预期的语句，成立则继续执行，不成立则抛出错误并中断当前用例。

- 判决动作：断言是测试脚本与普通脚本的分界，只执行不断言的用例不构成测试。
- 失败即中断：断言失败抛出的错误会终止当前用例，其后的语句不再执行。
- 表达完整：断言须写清考察对象与期望结果，失败时才能依据输出定位问题。

```js
// math.test.js
import assert from "node:assert/strict";

function addScore(current, delta) {
  return current + delta;
}

assert.strictEqual(addScore(1, 2), 3);   // 通过，无输出
// assert.strictEqual(addScore(1, 2), 4); // 抛出 AssertionError，用例失败
```

> 断言不同于日志：console.log 只留下运行痕迹，不影响用例结果，判断必须由断言表达。

**速记**：断言是测试的判决动作，成立即通过，不成立即抛错并中断用例。



#### 断言失败时的信号

**断言失败信号**：是断言不成立时运行器打印的错误对象与堆栈，其中实际值、期望值与失败位置三项构成排查的起点。

- 实际值与期望值：严格相等类断言同时打印 actual 与 expected，二者的差异直接指向问题。
- 失败位置：堆栈给出断言行所在的文件与行号，据此回溯产生该值的代码。
- 错误类型：Node 内置断言抛 AssertionError，Vitest 的 expect 抛同名错误，运行器按同一方式识别。

```bash
node --test math.test.js
# ✖ addScore 在 1 与 2 下应得 3
#   AssertionError [ERR_ASSERTION]: Expected values to be strictly equal:
#   + actual - expected
#   + 4
#   - 3
#     at TestContext.<anonymous> (file:///demo/math.test.js:9:8)
```

> [!TIP]
> **建议内容**：断言失败时先读 actual 与 expected 两行，再顺着堆栈回到产生该值的函数，不要靠修改期望值来消除报错。

**速记**：失败信号由实际值、期望值、失败位置三项组成，读它们即可定位。



#### 断言与测试用例的关系

**断言与测试用例的关系**：是用例为断言提供执行上下文，断言为用例给出通过与否的结论，一个用例至少包含一条断言。

- 上下文：用例负责准备数据与调用被测函数，断言只负责比较结果。
- 结论来源：用例不自行声明成败，运行器依据其中断言是否抛错来判定。
- 三段式结构：准备、执行、断言依次排列，断言位于末尾（详见本主题第 14 篇 测试质量与反模式）。

> 一条用例可以有多条断言，但任意一条失败都会使整条用例失败，因此同一用例内的断言应围绕同一个行为。

**速记**：用例准备上下文，断言给出结论，一个用例至少一条断言。



### Node assert 常用断言

Node.js 内置的 node:assert 模块提供零依赖的断言能力，适合脚本与轻量单元测试。本节按判定类型列出最常用的断言方法。

#### assert 与 assert.ok

**assert(value, message)**：是 node:assert 模块的默认导出，判断 value 是否为真值，为假时抛错。**assert.ok(value, message)**：是它的等价别名，语义更明确。

- value：任意值，按 JavaScript 真值规则判断，0、空字符串、null、undefined、NaN 均判为假。
- message：可选参数，自定义失败信息，省略时使用默认模板。
- 使用场景：判断布尔结果、对象非空、数组长度大于零等宽泛条件。

```js
import assert from "node:assert";

assert.ok(3 > 2);                           // 通过
assert.ok([1, 2, 3].length, "数组不应为空");  // 通过，长度 3 为真值
// assert.ok(0, "计数必须大于零");            // 抛出 AssertionError: 计数必须大于零
```

> assert.ok 只判断真值，不区分数值含义，需要精确比较时必须改用严格相等断言。

**速记**：assert.ok 判断真值，假值即抛错，message 用于自定义失败信息。



#### assert.strictEqual 与 assert.deepStrictEqual

**assert.strictEqual(actual, expected, message)**：判断两个值是否严格相等，比较规则为 Object.is，不做类型转换。**assert.deepStrictEqual(actual, expected, message)**：判断两个值的结构与内容是否递归相等。

- strictEqual：用于原始值，1 与 "1" 判为不等，NaN 与 NaN 判为相等。
- deepStrictEqual：用于对象与数组，逐层比较自有属性，原型不同也判为不等。
- 常见误用：用 strictEqual 比较两个对象，即使内容相同也会失败，因为比较的是引用。

```js
import assert from "node:assert/strict";

assert.strictEqual(1 + 1, 2);                   // 通过
// assert.strictEqual(1 + 1, "2");              // 抛出，number 与 string 不严格相等
assert.deepStrictEqual({ id: 1 }, { id: 1 });   // 通过，结构相等
// assert.strictEqual({ id: 1 }, { id: 1 });    // 抛出，两个字面量是不同引用
```

> [!CAUTION]
> **注意内容**：deepStrictEqual 会递归比较全部自有属性，对象变大后失败输出很长，应优先断言具体字段而不是整个对象。

**速记**：原始值用 strictEqual，对象与数组用 deepStrictEqual。



#### assert.throws 与 assert.rejects

**assert.throws(fn, error, message)**：断言同步函数 fn 抛出错误，未抛出则失败。**assert.rejects(asyncFn, error, message)**：断言异步函数 asyncFn 返回的 Promise 被拒绝。

- fn 与 asyncFn：被检查的函数本身，assert.throws 传入的函数会被立即调用，assert.rejects 传入的函数需返回 Promise。
- error：可选，可以是构造函数、正则表达式或校验对象，用于限定错误类型与信息。
- 反向断言：assert.doesNotThrow(fn) 与 assert.doesNotReject(asyncFn) 断言不抛错。

```js
import test from "node:test";
import assert from "node:assert/strict";

function parsePort(input) {
  const port = Number(input);
  if (!Number.isInteger(port) || port <= 0) {
    throw new RangeError("端口必须是正整数");
  }
  return port;
}

async function loadRemoteConfig() {
  throw new Error("请求超时");
}

test("parsePort 在非法输入下应抛出范围错误", () => {
  assert.throws(() => parsePort("abc"), RangeError);
  assert.throws(() => parsePort("abc"), /端口必须是正整数/);
});

test("loadRemoteConfig 在请求失败时应拒绝", async () => {
  await assert.rejects(loadRemoteConfig, /请求超时/);
});
```

> 传正则或构造函数给 error 参数是关键：只写 assert.throws(fn) 无法保证抛的是期望的那类错误。

**速记**：throws 查同步异常，rejects 查异步拒绝，error 参数用来限定类型。



#### assert.match 与 assert.fail

**assert.match(string, regexp, message)**：断言 string 匹配正则 regexp，不匹配则失败。**assert.fail(message)**：是无条件失败的断言，用于标记不应走到的分支。

- match：string 必须是字符串，regexp 必须是正则表达式，两者类型不符时抛 TypeError。
- fail：常放在 switch 的 default 分支或条件链末尾，表示该路径不应被执行。
- 组合用法：在 else 分支中调用 assert.fail，可把静默通过变成显式失败。

```js
import assert from "node:assert/strict";

function describeStatus(code) {
  if (code === 200) return "成功";
  if (code === 404) return "未找到";
  assert.fail(`未处理的响应码：${code}`);
}

assert.match(describeStatus(404), /未找到/); // 通过
// describeStatus(500);                     // 抛出 AssertionError: 未处理的响应码：500
```

> 分支中缺少 assert.fail 会让未覆盖的输入静默通过，掩盖实现缺陷，不可能分支应显式失败。

**速记**：match 用正则校验字符串，fail 把不该走到的分支变成显式失败。



### expect 风格断言

expect 风格断言把被测值与判定条件分开书写，链式调用可读性更好，是 Vitest 与 Jest 的默认风格。本节说明其调用形式与两个高频匹配器的差别。

#### expect 的调用形式

**expect(actual)**：是断言库的入口函数，把被测值 actual 包装成一个断言对象，再在其上链式调用匹配器完成判定。

- actual：任意值，可以是原始值、对象、函数或 Promise。
- 链式调用：expect(actual) 返回的对象暴露全部匹配器，每个匹配器返回自身以支持继续链式调用。
- 取反：加 not 得到相反判定，如 expect(actual).not.toBe(expected)。

```js
import { expect, it } from "vitest";
function formatUserName(firstName, lastName) {
  return `${firstName} ${lastName}`;
}

it("formatUserName 在给定姓名下应用空格拼接", () => {
  expect(formatUserName("Ada", "Lovelace")).toBe("Ada Lovelace");
});
```

> expect 是函数调用，匹配器是它的方法；与 node:assert 一次调用传入全部参数相比，链式写法把期望值留在最后。

**速记**：expect(actual) 包装被测值，匹配器链式判定，加 not 取反。



#### toBe 与 toEqual 的差别

**toBe(expected)**：判断两个值是否严格相等，底层为 Object.is，用于原始值。**toEqual(expected)**：判断两个值是否结构相等，递归比较可序列化的内容，用于对象与数组。

- toBe 比引用：两个内容相同的对象字面量用 toBe 比较必然失败。
- toEqual 比结构：忽略值为 undefined 的属性与稀疏数组的空位，但区分 0 与 -0。
- 选择依据：原始值一律 toBe，对象与数组一律 toEqual；需要最严格递归比较时用 toStrictEqual。

```js
import { expect, it } from "vitest";
function makeScoreRecord(id, score) {
  return { id, score };
}

it("makeScoreRecord 在给定字段下应生成结构相等的记录", () => {
  expect(2 + 2).toBe(4);
  expect(makeScoreRecord(1, 90)).toEqual({ id: 1, score: 90 });
  // expect(makeScoreRecord(1, 90)).toBe({ id: 1, score: 90 }); // 失败：引用不同
});
```

> [!IMPORTANT]
> **重要内容**：对象与数组一律使用 toEqual 或 toStrictEqual，误用 toBe 会让用例因为引用不同而失败，且失败信息难以理解。

**速记**：原始值用 toBe，对象与数组用 toEqual，比引用必失败。



#### 断言库与运行器的分工

**断言库与运行器的分工**：运行器负责收集用例、执行与汇报，断言库负责判定，两者通过抛错这一约定衔接。

- 运行器：如 Vitest、node:test，提供 describe 与 it 等结构，并在断言抛错时标记用例失败。
- 断言库：如 node:assert、Vitest 内置的 expect，只提供判定能力，不关心用例如何组织。
- 衔接点：断言库抛出的错误被运行器捕获，因此更换断言库不需要改写用例结构。

```bash
npm install --save-dev vitest
npx vitest --version
# 3.2.4
```

> 选型不要求两者同源：node:test 可以搭配第三方断言库，Vitest 也可以导入 node:assert（详见本主题第 2 篇 测试工具链与运行器选型）。

**速记**：运行器管用例与汇报，断言库管判定，二者用抛错约定衔接。



### 常用匹配器清单

匹配器是断言能力的原子单位，按判定对象分类记忆更高效。本节按判定对象分组列出常用匹配器，全部以要点列表给出。

#### 真值与相等匹配器

**真值与相等匹配器**：用于判断值的真假、空值与相等关系，是覆盖面最广的一组。

- toBeTruthy()：断言值为真值，等价于 Boolean(actual) 为 true。
- toBeFalsy()：断言值为假值，0、空字符串、null、undefined、NaN 均通过。
- toBeNull()：断言值严格等于 null，比 toBeFalsy 更精确。
- toBeUndefined()：断言值严格等于 undefined。
- toBeDefined()：断言值不是 undefined，常与属性存在性检查配合。
- toBeNaN()：断言值是 NaN，直接比较 NaN 恒为假，必须用该匹配器。
- toBe(expected)：断言与 expected 严格相等，对应 Object.is。
- toEqual(expected)：断言与 expected 结构相等，忽略 undefined 属性。
- toStrictEqual(expected)：断言结构与类型均相等，不忽略 undefined 属性。

```js
import { expect, it } from "vitest";
function findUser(users, id) {
  return users.find((user) => user.id === id);
}

it("findUser 在 id 不存在时应返回 undefined，Number 在非法字符串上应得 NaN", () => {
  expect(findUser([{ id: 1 }], 2)).toBeUndefined();
  expect(Number("abc")).toBeNaN();
});
```

> toBeFalsy 的通过范围很宽，判断精确取值时应改用 toBe；判断空值应明确写 toBeNull 或 toBeUndefined。

**速记**：真值类匹配器宽严不同，精确取值用 toBe，结构比较用 toEqual。



#### 数字与字符串匹配器

**数字与字符串匹配器**：用于判断数值大小、精度与文本内容。

- toBeGreaterThan(number)：断言大于给定数值。
- toBeGreaterThanOrEqual(number)：断言大于或等于给定数值。
- toBeLessThan(number)：断言小于给定数值。
- toBeLessThanOrEqual(number)：断言小于或等于给定数值。
- toBeCloseTo(number, numDigits)：断言浮点数在指定小数位内接近，用于规避精度误差。
- toHaveLength(number)：断言字符串或数组的长度。
- toContain(item)：断言数组或字符串包含某一项。
- toMatch(regexp)：断言字符串匹配正则表达式或包含某一子串。

```js
import { expect, it } from "vitest";
function average(scores) {
  return scores.reduce((sum, score) => sum + score, 0) / scores.length;
}

it("average 在给定分数下应得到指定精度的均值", () => {
  expect(average([80, 90, 100])).toBeCloseTo(90, 5);
  expect("Ada Lovelace").toMatch(/Lovelace/);
  expect([1, 2, 3]).toHaveLength(3);
});
```

> 浮点运算结果不要用 toBe 精确比较，0.1 加 0.2 的结果并不等于 0.3，应使用 toBeCloseTo。

**速记**：数值比大小、比精度，字符串用 toMatch，集合用 toContain 与 toHaveLength。



#### 集合与对象匹配器

**集合与对象匹配器**：用于判断数组元素、对象属性与整体结构。

- toContainEqual(item)：断言数组包含一个结构相等的元素，用于对象数组。
- toHaveProperty(path, value)：断言对象在指定路径上存在属性，可附带期望值。
- toMatchObject(object)：断言对象包含给定的子集，允许存在多余属性。
- expect.arrayContaining(array)：断言数组包含给定全部元素，顺序不限。
- expect.objectContaining(object)：断言对象包含给定属性，用于嵌套断言。
- expect.any(Constructor)：断言值为指定构造函数的实例或指定类型，用于忽略具体取值。
- expect.stringContaining(string)：断言字符串包含给定子串，可嵌入其他匹配器。

```js
import { expect, it } from "vitest";
function buildOrder(items) {
  return { id: "A-1", items, total: items.length };
}

it("buildOrder 在单件商品下应生成含商品清单的订单", () => {
  expect(buildOrder([{ sku: "P1" }])).toMatchObject({ id: "A-1" });
  expect(buildOrder([{ sku: "P1" }]).items).toContainEqual({ sku: "P1" });
  expect(buildOrder([{ sku: "P1" }])).toEqual({
    id: expect.any(String),
    items: expect.arrayContaining([{ sku: "P1" }]),
    total: 1,
  });
});
```

> toMatchObject 只校验给定字段，适合断言接口响应中的关注点；需要整体一致时改用 toEqual。

**速记**：子集用 toMatchObject，包含关系用 arrayContaining 与 objectContaining，占位用 expect.any。



#### 异常与类型匹配器

**异常与类型匹配器**：用于判断函数抛出错误、值的类型归属与实例关系。

- toThrow(error)：断言函数调用时抛出错误，error 可以是字符串、正则表达式或错误构造函数。
- toThrowError(error)：toThrow 的别名，语义更明确。
- toBeInstanceOf(Constructor)：断言值是 Constructor 的实例。
- toBeTypeOf(type)：断言 typeof 的结果等于给定字符串。

```js
import { expect, it } from "vitest";
function parsePort(input) {
  const port = Number(input);
  if (!Number.isInteger(port) || port <= 0) {
    throw new RangeError("端口必须是正整数");
  }
  return port;
}

it("parsePort 在非法输入下应抛出范围错误", () => {
  expect(() => parsePort("abc")).toThrow(RangeError);
  expect(() => parsePort("abc")).toThrow(/必须是正整数/);
});

it("parsePort 在合法输入下应返回数值", () => {
  expect(parsePort("8080")).toBeTypeOf("number");
});
```

> [!NOTE]
> **提醒内容**：toThrow 必须接收一个函数，直接写 expect(parsePort("abc")).toThrow() 会在断言执行之前就抛出错误，结果是测试报错而非失败。

**速记**：查异常用 toThrow 并传入函数，查类型用 toBeInstanceOf 与 toBeTypeOf。



#### 部分匹配与快照匹配器

**部分匹配与快照匹配器**：用于放宽精确比较，只断言关心的部分或与历史结果比对。

- expect.anything()：匹配除 null 与 undefined 之外的任意值，用于占位。
- expect.not.arrayContaining(array)：断言数组不包含给定全部元素，是包含断言的取反形式。
- toMatchInlineSnapshot(snapshot)：在源码内联写入期望字符串，首次运行时自动补全。
- toMatchSnapshot(snapshot)：与快照文件中的记录比对，不一致时需人工确认后更新。

```js
import { expect, it } from "vitest";

it("订单对象在占位断言下应只校验字段类型", () => {
  const order = { id: "A-1", createdAt: 1737000000000 };
  expect(order).toEqual({
    id: expect.any(String),
    createdAt: expect.any(Number),
  });
});
```

> 快照适合稳定的序列化输出，动态字段应先用 expect.any 或就地替换再快照（详见本主题第 11 篇 快照测试与 DOM 断言）。

**速记**：部分匹配放宽条件，快照匹配记录历史，动态字段先占位再快照。



### 否定断言与异步断言

断言并不总是判断成立，也需要判断不成立与异步结果。本节说明取反写法、Promise 断言与等待配合。

#### 取反 not

**not**：是匹配器链上的取反修饰符，把紧随其后的匹配器判定结果整体取反。

- 位置固定：not 必须写在匹配器之前，如 expect(actual).not.toBe(expected)。
- 语义完整：not 只取反判定，不改变匹配器的参数含义。
- 避免滥用：优先断言期望值本身，只有确认不应出现某结果时才用 not。

```js
import { expect, it } from "vitest";
function filterActive(users) {
  return users.filter((user) => user.active);
}

it("filterActive 在全为停用时不应保留任何用户", () => {
  const result = filterActive([{ id: 1, active: false }]);
  expect(result).toHaveLength(0);                               // 推荐：直接断言长度
  expect(result).not.toContainEqual({ id: 1, active: false });  // 通过
});
```

> 能写成正向断言时不要用 not，例如断言列表长度为零比断言不包含某元素更能表达意图。

**速记**：not 写在匹配器前取反判定，能用正向断言时优先正向。



#### 异步断言 resolves 与 rejects

**resolves**：是断言链上的修饰符，先等待被测 Promise 兑现，再用后续匹配器判定其兑现值。**rejects**：先等待 Promise 被拒绝，再判定其拒绝原因。

- 使用前提：被测值必须是 Promise，否则断言直接失败。
- 必须等待：异步断言返回 Promise，测试函数须标为 async 并 await，否则运行器不会等待判定。
- 参数一致：resolves 与 rejects 之后的匹配器与同步场景完全相同。

```js
import { expect, it } from "vitest";

async function fetchUserName(id) {
  if (id <= 0) throw new RangeError("id 必须为正数");
  return "Ada Lovelace";
}

it("fetchUserName 在合法 id 下应兑现用户名", async () => {
  await expect(fetchUserName(1)).resolves.toBe("Ada Lovelace");
});

it("fetchUserName 在非法 id 下应拒绝并抛出范围错误", async () => {
  await expect(fetchUserName(0)).rejects.toThrow(RangeError);
});
```

> [!WARNING]
> **警告内容**：忘记 await 会让异步断言脱离用例控制，即使断言失败用例也可能被判为通过，异步用例必须写 async 与 await。

**速记**：resolves 查兑现值，rejects 查拒绝原因，两者都必须 await。



#### 异步断言与等待配合

**异步断言与等待配合**：指断言前先等待异步状态稳定，避免读到中间态而得到偶然结果。

- 等待数据：先 await 请求，再断言其返回值，而不是断言尚未完成的 Promise 对象本身。
- 等待渲染：前端框架的更新是异步的，断言 DOM 前需等待一次更新周期（详见本主题第 10 篇 Vue 组件测试）。
- 轮询重试：Vitest 提供 expect.poll 与 vi.waitFor，按间隔重试直到条件满足或超时（详见本主题第 9 篇 异步测试与定时器控制）。

```js
import { expect, it } from "vitest";

async function loadConfig() {
  await new Promise((resolve) => setTimeout(resolve, 20));
  return { retries: 3 };
}

it("loadConfig 在延迟返回后应给出重试次数", async () => {
  const config = await loadConfig();
  expect(config.retries).toBeGreaterThan(0);
});
```

> 断言异步结果有两种写法：先 await 再同步断言，或直接 await expect(...).resolves，两种等价，同一文件内保持一致即可。

**速记**：先 await 再断言，或用 resolves 与 rejects，必要时用 expect.poll 轮询。
