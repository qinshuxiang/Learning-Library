## 分组与引用

### 分组

#### 捕获组

**捕获组（Capturing Group）**：用圆括号 (...) 包裹的子模式。它有两个作用：**组合**（把多个字符当成一个整体加量词）与**捕获**（把匹配到的子串记下来供后续引用）。

```js
const dateReg = /(\d{4})-(\d{2})-(\d{2})/;
const result = dateReg.exec("今天是 2024-01-15");

console.log(result[0]);      // "2024-01-15"（第 0 项永远是完整匹配）
console.log(result[1]);      // "2024"
console.log(result[2]);      // "01"
console.log(result[3]);      // "15"
console.log(result.index);   // 4（完整匹配的起始下标）
console.log(result.input);   // "今天是 2024-01-15"（原串）
```

> 组的编号按**左括号出现的顺序**从 1 开始。带量词的捕获组只保留**最后一次**重复的结果：/(ab)+/.exec("ababab")[1] 是 “ab” 而不是 “ababab”。未参与匹配的组其值为 undefined。



#### 可选捕获组的 undefined 陷阱

**可选组未参与匹配时值是 undefined**，把 undefined 直接拼进替换串或存入变量，会得到字面的字符串 undefined——这类脏数据往往在下游才暴露。

```js
const nameReg = /^(?<first>\w+)(?:\s(?<last>\w+))?$/;
const full = nameReg.exec("Zhang San");
const single = nameReg.exec("Cher");

console.log(full.groups.last);  // "San"
console.log(single.groups.last); // undefined（可选组没参与匹配）

// 直接插值会产出脏数据
console.log(`姓名：${single.groups.last}`); // "姓名：undefined"

// 正确做法：给兜底值
console.log(`姓名：${single.groups.last ?? "未填写"}`); // "姓名：未填写"
```

> [!WARNING]
> **警告内容**：凡是用 **?、{0,n}、\*** 标为可选的捕获组，取值前必须做存在性判断或用 **?? 兜底**。校验返回值是否为 null 之外，还要检查用到的每个组是否真的参与了匹配。



#### 非捕获组

**非捕获组 (?:...)**：只起组合作用，不占用编号、不记录结果。

```js
const reg = /(?:ab)+/;
console.log(reg.test("ababab")); // true（ab 作为整体重复）
console.log(reg.exec("ababab")); // ["ababab", index: 0, ...]（没有 [1]，因为不捕获）

// 对比：捕获组会多出一项
console.log(/(ab)+/.exec("ababab")); // ["ababab", "ab", index: 0, ...]
```

> 凡是不需要把这段内容取出来的括号，一律写成 (?:...)：**语义更清晰**（明确表达“不关心这段”）、**避免编号错位**（后续 $1、$2 不会因插入一个分组而集体后移），也能省下记录结果的开销。



#### 命名捕获组

**命名捕获组**：在捕获组内以问号加尖括号组名开头，给捕获组起名字，通过 match.groups.name 访问，ES2018 引入。

```js
const dateReg = /(?<year>\d{4})-(?<month>\d{2})-(?<day>\d{2})/;
const match = dateReg.exec("2024-01-15");

console.log(match.groups.year);  // "2024"
console.log(match.groups.month); // "01"
console.log(match.groups.day);   // "15"
console.log(match[1]);           // "2024"（数字索引依然可用）
```

> 命名分组解决了“记不清第几个括号是什么”的痛点，groups.year 比 match[1] 自解释得多。它在 replace 的替换串中通过美元符号加尖括号组名引用，在正则内部通过反斜杠 k 加尖括号组名反向引用。

```js
// 命名分组 + replace 的组合：把日期统一改成“年/月/日”
console.log("2024-01-15".replace(/(?<y>\d{4})-(?<m>\d{2})-(?<d>\d{2})/, "$<y>/$<m>/$<d>"));
// "2024/01/15"

// 用命名分组解析“时间 级别 正文”的日志行
const logReg = /^(?<time>\d{2}:\d{2}:\d{2})\s+(?<level>INFO|WARN|ERROR)\s+(?<msg>.+)$/;
const logMatch = logReg.exec("08:30:01 ERROR 系统盘空间不足");
console.log(logMatch.groups.level); // "ERROR"
console.log(logMatch.groups.msg);   // "系统盘空间不足"
```

> [!TIP]
> **建议内容**：捕获组**超过两个就改用命名分组**。数字下标在模式增删分组后会整体错位，命名分组的取值代码不随模式结构调整而失效，重构成本最低。



#### 命名分组的书写规则与限制

**组名是标识符，不是任意文本**：它要符合 JavaScript 标识符的命名规则，且**不能以数字开头**；引用与定义的位置也有约束，写错一律在编译期抛 SyntaxError。

- **组名规则**：由字母、数字、下划线、美元符号组成，**首字符不能是数字**；(?<1a>x) 直接抛 Invalid capture group name。
- **反向引用必须先存在**：\k 加尖括号引用一个**从未定义**的组名会抛 Invalid named capture referenced。
- **引用可以写在定义之前**：\k 加尖括号写在组之前**语法合法**，此时它引用的是“尚未参与匹配的组”，匹配结果为空串。
- **同名组只能分居不同分支**：/\d+ 或 [a-z]+ 两个分支各用一个名为 type 的组是允许的（ES2025 起），写在同一分支内仍然报 Duplicate capture group。

```js
// 组名不能以数字开头
// new RegExp("(?<1a>x)");        // SyntaxError: Invalid capture group name

// 引用不存在的组名
// new RegExp("(?<a>x)\\k<b>");   // SyntaxError: Invalid named capture referenced

// 引用写在定义之前：语法合法，匹配空串
console.log(/\k<a>(?<a>x)/.test("x")); // true（前面的引用匹配空）

// 同名组分居两个分支（需较新的运行时）
const typeReg = /(?<type>\d+)|(?<type>[a-z]+)/;
console.log(typeReg.exec("123").groups.type); // "123"
```

> [!NOTE]
> **提醒内容**：**不要靠“引用了不存在的组”来探测模式是否写对**——非 u 模式下，数字反向引用（\1）在找不到对应组时会静默退化为八进制转义；命名反向引用则直接报错。写新代码时统一带 u 标志，让这类问题在编译期暴露。



#### 嵌套分组的编号顺序

**编号只看左括号出现的先后，与嵌套深浅无关**：从左到右数左括号，数到第几个左括号，对应组号就是几。外层包裹内层时，外层编号反而更小。

```js
const nestedReg = /((a)(b(c)))/;
const result = nestedReg.exec("abc");

console.log(result[1]); // "abc"（第 1 个左括号：最外层）
console.log(result[2]); // "a"（第 2 个左括号）
console.log(result[3]); // "bc"（第 3 个左括号）
console.log(result[4]); // "c"（第 4 个左括号：嵌得最深，编号反而最大）
```

> 读取多层嵌套的匹配结果时，编号与“视觉上的层次”没有对应关系，全凭左括号计数。这类场景强烈建议改用命名分组，用组名代替心算编号；不需要取值的层次写成非捕获组 (?:...)，还能让后续组的编号整体前移一位。



#### 分组结果的结构化取用

**exec 与非全局 match 的返回值是“带额外属性的数组”**：它既是数组（可解构、可下标访问），又挂着 index、input、groups 三个属性，两种取法不要混淆。

```js
const dateMatch = /(\d{4})-(\d{2})-(\d{2})/.exec("今天是 2024-01-15");
const [, year, month, day] = dateMatch; // 解构时补一个逗号跳过第 0 项

console.log(year, month, day); // "2024" "01" "15"
console.log(dateMatch.index);  // 4（index 不在数组元素里，它是额外属性）
console.log(dateMatch.groups); // undefined（没用命名分组就没有该属性）
```

> 解构赋值是取分组的惯用法：开头补一个逗号跳过完整匹配，后面按组号顺序接住。注意**先判空再解构**：exec 无匹配返回 null，对 null 解构会直接抛 TypeError，标准的写法是 const match = reg.exec(str) 之后判断 if (match) 再解构。



### 引用

#### 反向引用

**反向引用**：在同一个正则里引用**前面已经匹配到的内容**，要求“后面出现的和前面完全一样”。

- **\n**：引用第 n 个捕获组（\1、\2……）。
- **反斜杠 k 加尖括号组名**：在正则内部引用命名捕获组。
- **美元符号加序号 / 美元符号加尖括号组名**：用在 replace 的替换字符串中，含义相同但**书写位置不同**。

```js
// 匹配成对的标签
console.log(/<(\w+)>.*<\/\1>/.test("<div>文本</div>")); // true
console.log(/<(\w+)>.*<\/\1>/.test("<div>文本</p>"));   // false

// 找出叠字
console.log("高高兴兴".match(/(.)\1/g)); // ["高高", "兴兴"]

// 命名分组的反向引用：引号必须前后一致
const quoteReg = /(?<quote>["']).*?\k<quote>/;
console.log(quoteReg.test(`"你好"`)); // true
console.log(quoteReg.test(`"你好'`)); // false
```

> 正则内（反斜杠加序号、反斜杠 k 加尖括号组名）与替换串（美元符号加序号、美元符号加尖括号组名）是**两套写法**，作用位置不同：前者出现在**模式**里表示“要和前面一样”，后者出现在**替换结果**里表示“把前面抓到的放这儿”。混用是最常见的语法错误之一。



#### 反向引用的清洗应用

反向引用在**文本清洗**里最实用——凡是“连续重复”都属于它的主场：

```js
// 去掉连续重复的空白与重复的标点
console.log("so    many".replace(/(\s)\1+/g, "$1"));      // "so many"
console.log("好！！！".replace(/([！？。，])\1+/g, "$1"));  // “好！”

// 检查是否含有连续四个以上相同字符（刷屏判断）
console.log(/(.)\1{3,}/.test("哈哈哈哈哈")); // true
console.log(/(.)\1{3,}/.test("正常内容"));   // false

// 域名去重："www.bai.bai.com" → "www.bai.com"
console.log("www.bai.bai.com".replace(/([a-z]+)\.\1/, "$1")); // "www.bai.com"
```

> 反向引用的通用模板是 **(某类字符) 后接 \1 重复**：捕获一个单元，再要求它重复若干次。“重复检测”与“重复压缩”共用同一模式，前者用于校验（刷屏、连续重复字符），后者用于 replace 清洗。



#### 反向引用的适用范围

**反向引用比较的是“字符序列”，不是“语义”**：它只认前面捕获到的那串字符本身，做不了“同义不同形”的判断，也受分组编号顺序约束。

- **逐字符比对**：\1 完全忽略大小写差异（除非模式带 i），"Ab" 与 "ab" 不算相同。
- **不跨模式分支**：捕获组在某个分支里未被匹配时，对应的反向引用匹配空串，而不是报错。
- **不能引用未来的组**：数字引用只能引用**编号更小**的组，引用不存在的编号会退化（非 u）或报错（u）。
- **后行断言里也能用**：(?<=(a))\1 形式合法，但可读性差，建议拆成两步处理。

```js
// 大小写敏感：Ab 与 ab 不算相同
console.log(/(\w)\1/.test("aA"));  // false
console.log(/(\w)\1/i.test("aA")); // true（加了 i 才等同）

// 分组未参与匹配时，反向引用匹配空串
console.log(/^(?:(\d)x)?\1$/.test("")); // true（组缺席，\1 变成空）

// 后行断言里的反向引用
console.log(/(?<=(a))\1/.test("aa")); // true
```



#### 替换串中引用未参与匹配的组

**替换串里的组引用有独立的兜底规则**：$n 或 $<name> 引用的组未参与匹配时，被替换成**空串**——不报错、不写 undefined；同样的组从结果数组里读出来却是 undefined。同一个“缺席”，两处行为不同。

```js
const nameReg = /^(?<first>\w+)(?:\s(?<last>\w+))?$/;

console.log("Zhang San".replace(nameReg, "$<last>, $<first>")); // "San, Zhang"
console.log("Cher".replace(nameReg, "$<last>, $<first>"));      // ", Cher"
// $<last> 缺席，被替换成空串，逗号前多出一个空位

// 对照：数组里读到的同一个组是 undefined
console.log(nameReg.exec("Cher").groups.last); // undefined
```

> [!WARNING]
> **警告内容**：用可选组的 $n 或 $<name> 做拼接时，缺席组会静默落成空串，产生多余的空格或空字段；替换串形式无法区分“空串”与“缺席”。组值需要参与逻辑判断时，改用 replace 的**函数形式**，在函数里对 undefined 做显式兜底。



#### 替换串的美元记号全表

**替换串里的美元符号永远有特殊含义**：想输出一个字面美元符号，必须写两个；想引用某段内容，得用下面对应的记号。这张表是查错时的第一站。

- **$$**：插入一个字面美元符号。
- **$&**：插入整个匹配到的子串。
- **$ 加反引号**：插入匹配**之前**的文本。
- **$'**：插入匹配**之后**的文本。
- **$n**：插入第 n 个捕获组，n 是一位数字时优先级最高。
- **$nn**：两位数字的组号，**前提是模式里真的有这么多组**。
- **$<组名>**：插入命名捕获组。
- **落空规则**：记号指向的组**不存在**时原样保留为字面文本（如 $1、$<x>）；组**存在但未参与匹配**时替换为空串。两种情况都不报错。

```js
const text = "价格 128 元";
const amountReg = /(\d+)/;

console.log(text.replace(amountReg, "[$&]"));      // "价格 [128] 元"
console.log(text.replace(amountReg, "$$$&"));      // "价格 $128 元"（$ 与 匹配 各一）
console.log(text.replace(amountReg, "$`"));        // "价格 价格  元"（匹配前文本被复制）
console.log(text.replace(amountReg, "$'"));        // "价格  元 元"（匹配后文本被复制）

// $n 与 $nn 的歧义：有足够多的组时按两位解析，否则回退为一位加字面数字
console.log("abcdefghij".replace(/(a)(b)(c)(d)(e)(f)(g)(h)(i)(j)/, "$10")); // "j"
console.log("ab".replace(/(a)/, "$10")); // "a0b"（只有 1 个组，$1 后接字面 0）
```

> [!CAUTION]
> **注意内容**：$n 与 $nn 的**歧义规则以“组是否存在”为准**——同一个 "$10" 在不同模式里含义不同（第 10 组，或第 1 组后接字符 0）。组号超过 9 时，一律改用命名捕获组加 $<组名>，把这类歧义彻底消除。



### 或运算与分组

#### 或的优先级

**或 |**：表示“匹配左边或右边”，它的优先级**低于**量词与拼接，通常需要分组来限定范围。

```js
console.log(/cat|dog/.test("dog"));   // true
console.log(/gr(a|e)y/.test("grey")); // true（分组限定“或”的范围）

// 陷阱：没有分组时，“或”贯穿整个模式
console.log(/^ab|cd$/.test("abxx")); // true（等价于 /(^ab)|(cd$)/）
console.log(/^(ab|cd)$/.test("abxx")); // false（加了分组才受 ^ $ 约束）
```

> [!IMPORTANT]
> **重要内容**：| 的优先级是正则里**最低**的，/^ab|cd$/ 会被解析成 /(^ab)|(cd$)/ 而不是 /(^(ab|cd)$)/。凡是用“或”列举多种完整形态，务必用 (?:...) 把它们包起来再用锚点收口。



#### 或的分支顺序

**或的分支从左到右尝试，先命中即停**：把更长的、更具体的分支放在前面，否则短分支会“截胡”。

```js
// “或”列举多种完整形态的规范写法：非捕获组 + 锚点收口
const idTypeReg = /^(?:\d{17}[\dXx]|\d{15})$/;   // 18 位或 15 位身份证的粗筛
console.log(idTypeReg.test("110101199003072316")); // true
console.log(idTypeReg.test("110101990030723"));    // true（15 位旧证）

// 分支顺序问题：短分支先命中，长分支永远轮不上
console.log("公告栏".match(/公告|公告栏/)[0]);  // "公告"（先命中短的）
console.log("公告栏".match(/公告栏|公告/)[0]);  // "公告栏"（长的放前面）
```

> 分支顺序只影响**匹配到哪一段**，不影响“能不能匹配”。在 replace 与 matchAll 等逐段处理的场景里，顺序错位会直接改变输出结果；纯 test 验证则无感。拿不准时，**永远把更长的分支写在左边**。



#### 或与量词、分组的组合

**“或”必须用括号圈定作用范围才能与量词配合**：不分组时量词只作用于分支的最后一个字符，结果与直觉完全不符。

- **量词加在整个“或”上**：/(?:ab|cd)+/ 表示 ab 或 cd 重复若干次。
- **量词只加在一个分支上**：/ab|cd+/ 里 + 只作用于 d，等价于 ab 或 cddd。
- **空分支要显式写**：(?:a|) 表示 a 或空串，等价于 a?。
- **公共前缀可提出**：/abc|abd/ 与 /ab(?:c|d)/ 等价，后者更容易看出共同部分。

```js
console.log(/(?:ab|cd)+/.exec("abcdab")[0]); // "abcdab"
console.log(/(?:ab|cd)+/.exec("abcdab")[1]); // undefined（非捕获组不记录）

// 量词位置决定语义：原模式里 + 只重复 d，包成非捕获组后才重复整个分支
console.log(/ab|cd+/.exec("cddd")[0]);     // "cddd"（+ 只作用于 d）
console.log(/(?:ab|cd)+/.exec("cdcd")[0]); // "cdcd"（整个分支重复两次）

// 空分支等价于可选
console.log(/^(?:v|)\d+$/.test("v2"), /^(?:v|)\d+$/.test("2")); // true true
```
