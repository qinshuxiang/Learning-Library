## 实战案例集

### 身份与联系方式

#### 手机号

国内手机号规则的**实用近似**是：1 开头、第二位 3~9、共 11 位数字。

```js
const phoneReg = /^1[3-9]\d{9}$/;

console.log(phoneReg.test("13812345678")); // true
console.log(phoneReg.test("12812345678")); // false（第二位 2 不合法）
console.log(phoneReg.test("1381234567"));  // false（不足 11 位）
```

> 拆解：^ 开头、1 固定首位、[3-9] 第二位、\d{9} 剩余 9 位、$ 结尾。注意**号段会随运营商放号而变化**，这个正则只保证“格式像手机号”，不保证号码真实存在；严格的号段校验需要维护一张号段表，而真实有效性只能靠短信验证码。

实际输入常带分隔符，先清洗再校验是更稳的顺序：

```js
function normalizePhone(value) {
  const cleaned = value.replace(/[\s-]/g, "");
  return /^1[3-9]\d{9}$/.test(cleaned) ? cleaned : null;
}

console.log(normalizePhone("138 0013-8000")); // "13800138000"
console.log(normalizePhone("1380013800"));    // null
```



#### 固定电话与分机号

固定电话的**实用近似**是：0 开头的区号加 7 到 8 位号码，可选分机号；区号与号码之间可以带短横线。

```js
const telReg = /^0\d{2,3}-?\d{7,8}(?:-\d{1,4})?$/;

console.log(telReg.test("0358-1234567"));     // true（区号加 7 位）
console.log(telReg.test("010-12345678"));     // true（三位区号加 8 位）
console.log(telReg.test("03581234567"));      // true（不带分隔符）
console.log(telReg.test("0358-1234567-123")); // true（带分机号）
console.log(telReg.test("0358-123456"));      // false（号码位数不足）
```

> 拆解：0\d{2,3} 覆盖二到四位区号，-? 让分隔符可选，\d{7,8} 是号码主体，(?:-\d{1,4})? 是可选的转接分机。**区号位数与号码位数是互补的**：三位区号配八位号码、四位区号配七位号码，本模式没有强制这一约束，属于宽松近似；需要严格校验时把首段拆成两个分支。



#### 邮箱

邮箱校验给出两版模式：日常实用简化版覆盖常见格式，严格版再约束域名分段长度。

```js
const emailReg = /^[\w.+-]+@[\w-]+(\.[\w-]+)+$/;

console.log(emailReg.test("user@example.com"));    // true
console.log(emailReg.test("a.b-c@sub.domain.cn")); // true
console.log(emailReg.test("user@example"));        // false（缺顶级域）
console.log(emailReg.test("@example.com"));        // false（缺用户名）
```

> 拆解：[\w.+-]+ 用户名、@ 分隔、[\w-]+ 域名主体、(\.[\w-]+)+ 至少一个点分段。需要强调的是：**完整的 RFC 5322 邮箱规则极其复杂**（支持引号、注释、IP 字面量等），上面只是实用简化版；生产环境应以**发送验证邮件**作为最终有效性依据。

如果要做“域名分段长度不超过 63 字符、首尾不能是短横线”这类更严的约束，改成显式分段更清晰：

```js
const strictEmailReg =
  /^[\w.!#$%&'*+/=?^`{|}~-]+@[A-Za-z0-9](?:[A-Za-z0-9-]{0,61}[A-Za-z0-9])?(?:\.[A-Za-z0-9](?:[A-Za-z0-9-]{0,61}[A-Za-z0-9])?)+$/;

console.log(strictEmailReg.test("user@example.com"));     // true
console.log(strictEmailReg.test("a.b-c@sub.domain.cn"));  // true
console.log(strictEmailReg.test("user@-bad.com"));        // false（分段不能以短横线开头）
console.log(strictEmailReg.test("user@example"));         // false（必须有点分隔的顶级域）
```

> 允许的顶级域是“至少两个点分段”，并不等于“顶级域必须是合法的国家或通用域”。真要做顶级域白名单，应当把域名部分单独取出来比对一份公开的顶级域清单，而不是把上千个后缀写进正则。



#### 身份证号

18 位居民身份证：前 6 位行政区划码、8 位出生日期、3 位顺序码、1 位校验位（数字或 X）。

```js
const idCardReg =
  /^[1-9]\d{5}(?:18|19|20)\d{2}(?:0[1-9]|1[0-2])(?:0[1-9]|[12]\d|3[01])\d{3}[\dXx]$/;

console.log(idCardReg.test("110101199003072316")); // true（示例号码）
console.log(idCardReg.test("010101199003072316")); // false（首位不能为 0）
console.log(idCardReg.test("110101199013072316")); // false（月份 13 非法）
```

> 这个正则只做**格式与日期合法性**校验，不校验行政区划码是否存在，也不校验最后一位的**校验码算法**（ISO 7064 MOD 11-2）。要做严格校验，应当在通过正则后再跑一遍加权求和；而“这个人是否存在”只能依赖公安系统的实名接口。

用命名捕获组可以把**出生日期直接解析出来**，供后续按年龄分支使用：

```js
const idParseReg = /^(?<area>[1-9]\d{5})(?<year>\d{4})(?<month>\d{2})(?<day>\d{2})\d{3}[\dXx]$/;
const idMatch = idParseReg.exec("110101199003072316");

console.log(idMatch.groups.area);  // "110101"（行政区划码）
console.log(idMatch.groups.year);  // "1990"
console.log(idMatch.groups.month); // "03"
console.log(idMatch.groups.day);   // "07"
```



#### 身份证校验码的完整校验

**第 18 位校验码按 ISO 7064 MOD 11-2 算法生成**：前 17 位分别乘以固定权重求和，和对 11 取余，按余数查表得出校验码。正则负责格式，算法负责校验位，两层配合才是完整校验。

```js
const ID_WEIGHTS = [7, 9, 10, 5, 8, 4, 2, 1, 6, 3, 7, 9, 10, 5, 8, 4, 2];
const ID_CHECK_CODES = ["1", "0", "X", "9", "8", "7", "6", "5", "4", "3", "2"];

function verifyIdCard(id) {
  // 第一关：格式与日期合法性，月份与日期都做了范围约束
  const formatReg =
    /^[1-9]\d{5}(?:18|19|20)\d{2}(?:0[1-9]|1[0-2])(?:0[1-9]|[12]\d|3[01])\d{3}[\dXx]$/;
  if (!formatReg.test(id)) return false;

  // 第二关：校验位加权比对
  let sum = 0;
  for (let i = 0; i < 17; i++) {
    sum += Number(id[i]) * ID_WEIGHTS[i];
  }
  return ID_CHECK_CODES[sum % 11] === id[17].toUpperCase();
}

console.log(verifyIdCard("110101199003072316")); // true（校验码正确）
console.log(verifyIdCard("110101199003072310")); // false（末位被改动）
console.log(verifyIdCard("110101199013072316")); // false（月份 13，格式关先拦下）
```

> 拆解：权重从首位起依次是 7、9、10、5、8、4、2、1、6、3、7、9、10、5、8、4、2；余数 0 到 10 对应的校验码依次是 1、0、X、9、8、7、6、5、4、3、2。比对前先把输入末位 toUpperCase()，否则小写 x 的合法号码会被误判为非法。校验码通过也只能证明“号码格式自洽”，人员真实性仍以实名核验接口为准。

> [!WARNING]
> **警告内容**：格式关与校验位关**必须分两层写、且顺序不能省**。只用 /^\d{17}[\dXx]$/ 当格式关时，“110101199013072316”这种月份为 13 的号码会闯过第一关，只能靠第二关的加权比对偶然拦下——而一旦校验位恰好对上，这个非法日期就会被放行。**日期范围校验交给正则，校验位交给算法**，两层各守一关。



#### 中文姓名

中文姓名的校验要点是**汉字范围**与**少数民族姓名的间隔号**，写法详见系列第 8 篇《Unicode 与中文处理》。

```js
const chineseNameReg = /^[\p{Script=Han}·]{2,16}$/u;

console.log(chineseNameReg.test("张三"));           // true
console.log(chineseNameReg.test("司马相如"));        // true（复姓同样是汉字）
console.log(chineseNameReg.test("阿依古丽·买买提")); // true（含间隔号）
console.log(chineseNameReg.test("𠮷水"));           // true（扩展区生僻字）
console.log(chineseNameReg.test("张 三"));          // false（含空格）
```

> 姓名类校验不用 [\u4e00-\u9fa5]——扩展区生僻字会被误判为非法。字符集从宽、长度从严，是这个字段最稳妥的边界。



#### 户籍地址

身份证住址的书写遵循公安部《办理公民户口和居民身份证件工作中住址项目填写规范》：行政区划名称按「省（自治区、直辖市）→ 市（地区、州、盟）→ 区（县、市、旗）→ 乡（镇、街道）→ 村（街、路、巷）→ 门牌详址」逐级展开。三种官方缺省例外——省会城市不冠省名、地级市所辖县级市略去市名、直辖市本无省级名称——决定了**前三段都可能缺位**，提取模式必须把每一段都写成可选。

```js
// 宽松校验：汉字开头，只含汉字、数字、括号、连字符、间隔号与空格
const addrCheckReg = /^[\p{Script=Han}][\p{Script=Han}0-9（）()\-—·\s]{3,60}$/u;

console.log(addrCheckReg.test("山西省吕梁市临县玉坪乡李家坡村1号")); // true
console.log(addrCheckReg.test("北京市朝阳区建国路1号"));             // true
console.log(addrCheckReg.test("abc123"));                            // false（不以汉字开头）
```

```js
// 命名捕获组拆出省、市、县区三段，乡（镇、街道）及以下全部归入 rest
const addrReg =
  /^(?<province>北京市|天津市|上海市|重庆市|[\p{Script=Han}]{2,7}?(?:省|自治区))?(?<city>[\p{Script=Han}]{1,6}(?:自治州|市|盟|地区))?(?<county>[\p{Script=Han}]{1,10}(?:县|区|旗|市))?(?<rest>[\p{Script=Han}0-9]*)$/u;

function parseAddr(text) {
  return addrReg.exec(text)?.groups;
}

console.log(parseAddr("山西省吕梁市临县玉坪乡李家坡村"));
// { province: "山西省", city: "吕梁市", county: "临县", rest: "玉坪乡李家坡村" }

console.log(parseAddr("北京市朝阳区建国路1号"));
// { province: "北京市", city: undefined, county: "朝阳区", rest: "建国路1号" }（直辖市无省级段）

console.log(parseAddr("南京市玄武区中山东路100号"));
// { province: undefined, city: "南京市", county: "玄武区", rest: "中山东路100号" }（省会不冠省名）

console.log(parseAddr("内蒙古自治区呼和浩特市新城区成吉思汗大街1号"));
// { province: "内蒙古自治区", city: "呼和浩特市", county: "新城区", rest: "成吉思汗大街1号" }
```

> 拆解：省段后缀是「省｜自治区」，直辖市四个名称单独列出；市段后缀按「自治州 → 市 → 盟 → 地区」排列并用贪婪量词回溯，让「杭州市」「大理白族自治州」整段落位，而不是被段内的「州」字截断。县级市的「市」会被贪婪地归入 city 段（如「江西省瑞金市」），这是写法规范允许的缺省，正则无从区分层级。**结构对不等于地址真**：行政区划名称是否存在必须比对 GB/T 2260 的行政区划代码表，与身份证前 6 位交叉核验同样要走码表，正则只负责把地址拆成结构化字段，供后续查表使用。



#### 邮政编码

我国邮政编码是**六位数字，首位 0 到 8**：前两位代表省（自治区、直辖市），第三位是邮区，第四位是县（市），末两位是投递局（所）。

```js
const postalReg = /^\d{6}$/;

console.log(postalReg.test("033200")); // true（山西临县——首位 0 完全合法）
console.log(postalReg.test("010000")); // true（内蒙古呼和浩特）
console.log(postalReg.test("100000")); // true（北京）
console.log(postalReg.test("33200"));  // false（不足六位）
console.log(postalReg.test("03320A")); // false（含字母）
```

> 拆解：模式本身简单，真正的坑在网上流传的 /^[1-9]\d{5}$/——那是照行政区划码「首位非 0」的惯性写的，会误杀 0 开头的华北邮编（内蒙古 01、山西 03、河北 05）。另要注意邮编与身份证前 6 位**同为六位数字但体系不同**：邮编是邮政投递分区，行政区划码按 GB/T 2260 管理，两者不能互相校验；格式通过也只说明「像邮编」，真实投递以邮政系统为准。



### 车辆与证件格式

#### 车牌号

民用车牌的**实用近似**：省份简称 + 发牌机关代字字母 + 5 或 6 位序号（新能源多一位），序号不含字母 I 与 O。

```js
const plateReg = /^[京津冀晋蒙辽吉黑沪苏浙皖闽赣鲁豫鄂湘粤桂琼渝川贵云藏陕甘青宁新][A-HJ-NP-Z][A-HJ-NP-Z0-9挂学警]{5,6}$/;

console.log(plateReg.test("晋A12345"));  // true（常规牌 5 位序号）
console.log(plateReg.test("晋AD12345")); // true（新能源 6 位序号）
console.log(plateReg.test("晋AI2345"));  // false（序号不含 I 与 O）
console.log(plateReg.test("北京A12345")); // false（省份必须是单字简称）
```

> 拆解：第一段是 31 个省份简称的字符类，第二段 [A-HJ-NP-Z] 是发牌机关代字（跳过 I、O，防止与数字 1、0 混淆），第三段 {5,6} 兼容常规牌与新能源牌。挂学警等特殊车种后缀与警牌、军牌格式各有独立规则，此模式只覆盖民牌主干，属于实用近似。



#### 车架号 VIN

**车架号（VIN）是 17 位、不含字母 I、O、Q 的大写字母数字串**：排除这三个字母是为了避免与数字 1、0 混淆。

```js
const vinReg = /^[A-HJ-NPR-Z0-9]{17}$/;

console.log(vinReg.test("LSVAM4185E2000001")); // true（17 位合格字符）
console.log(vinReg.test("LSVAM4185E2O00001")); // false（含字母 O，被排除）
console.log(vinReg.test("LSVAM4185E200001"));  // false（只有 16 位）
```

> 拆解：字符类 [A-HJ-NPR-Z0-9] 在字母区间里挖掉了 I、O、Q 三个洞，加上数字组成合法字符集，{17} 固定长度。VIN 只允许**大写**，所以不要加 i 标志；第 9 位是校验位（北美标准），欧洲标准的车架号不使用该算法，需要按市场区分后再决定是否进一步校验。



#### 银行卡号与 Luhn 校验

**卡号的合法性由 Luhn 算法（模 10 算法）保证**：从右往左，偶数位乘 2、超过 9 就减 9，全部相加能被 10 整除即为合法。正则只负责长度与字符，Luhn 负责数值。

```js
function luhnCheck(card) {
  const digits = card.replace(/\D/g, ""); // 先去掉空格与短横线
  if (!/^\d{12,19}$/.test(digits)) return false; // 长度关
  let sum = 0;
  for (let i = 0; i < digits.length; i++) {
    let value = Number(digits[digits.length - 1 - i]);
    if (i % 2 === 1) {
      value *= 2;
      if (value > 9) value -= 9;
    }
    sum += value;
  }
  return sum % 10 === 0;
}

console.log(luhnCheck("4111111111111111"));  // true（测试卡号）
console.log(luhnCheck("5500005555555559"));  // true（测试卡号）
console.log(luhnCheck("4111111111111112"));  // false（末位被改动）
console.log(luhnCheck("4111 1111 1111 1112")); // false（带分隔符也能先清洗再判）
```

> 拆解：第一行 replace(/\D/g, "") 把非数字字符全部剔除，这是**清洗在前、校验在后**的标准顺序；随后 /^\d{12,19}$/ 卡长度，最后逐位做加权求和。Luhn 只能证明“号码自洽”，卡是否存在、是否可用必须经由支付接口确认。



#### 信用卡号格式

银行卡与信用卡的**格式粗筛**：13 到 19 位数字，常按 4 位分组、允许空格或短横线分隔。

```js
const cardReg = /^\d{4}[\s-]?\d{4}[\s-]?\d{4}[\s-]?\d{3,7}$/;

console.log(cardReg.test("4111 1111 1111 1111"));  // true（Visa 常见格式）
console.log(cardReg.test("4111-1111-1111-1111"));  // true
console.log(cardReg.test("4111111111111111"));     // true（连续写法）
console.log(cardReg.test("41111111111"));          // false（位数不足）
```

> 拆解：[\s-]? 允许每组之间有一个可选分隔符，末组 {3,7} 覆盖 13 到 19 位总长。这个模式只做**格式校验**；卡号的真实有效性要用 Luhn 算法校验位验证，业务上只能靠发卡接口。展示时配合 replace 做脱敏（见下文“敏感信息脱敏”）。



#### 护照号与统一社会信用代码

两类**证件类编号**的实用近似：中国普通护照为字母 E 或 G 加 8 位数字，统一社会信用代码为 18 位、字符集排除 I、O、S、V、Z 五个易混字母。

```js
// 中国普通护照：电子护照 E 开头，旧版 G 开头，均为 8 位数字
const passportReg = /^[EG]\d{8}$/;
console.log(passportReg.test("E12345678")); // true
console.log(passportReg.test("G12345678")); // true（旧版护照）
console.log(passportReg.test("S12345678")); // false（前缀不符）

// 统一社会信用代码：18 位，字符集排除 I、O、S、V、Z
const usccReg = /^[0-9A-HJ-NPQRTUWXY]{2}\d{6}[0-9A-HJ-NPQRTUWXY]{10}$/;
console.log(usccReg.test("91110108551385082Q"));  // true
console.log(usccReg.test("9111010855138508IQ"));  // false（含被排除的 I）
```

> 拆解：护照号模式沿用“前缀字母 + 定长数字”的通用骨架，只覆盖普通护照两类前缀，公务与外交护照的前缀不同。统一社会信用代码按 GB 32100 的字符集定义写成：第 1 至 2 位是登记管理部门与机构类别，第 3 至 8 位是行政区划码，其余 10 位是主体标识与校验位；末尾一位同样有校验算法，格式通过后仍需按标准做进一步验证。



### 数字与金额

#### 金额格式校验

金额格式用一条模式约束整数部分前导零与小数位数，负数与千分位需另行处理。

```js
const moneyReg = /^(?:0|[1-9]\d*)(?:\.\d{1,2})?$/;

console.log(moneyReg.test("0.50"));   // true（合法，允许 0 开头的小数）
console.log(moneyReg.test("123"));    // true（整数）
console.log(moneyReg.test("01.5"));   // false（前导 0 非法）
console.log(moneyReg.test("1.234"));  // false（最多两位小数）
console.log(moneyReg.test("-5"));     // false（负数需另加分支）
```

> 拆解：(?:0|[1-9]\d*) 保证整数部分要么是单个 0、要么不以 0 开头，(?:\.\d{1,2})? 允许一到两位小数且可省略。需要支持负数时把模式改为 /^-?(?:0|[1-9]\d*)(?:\.\d{1,2})?$/；“1,234.56” 这类千分位输入要先去掉逗号再校验。



#### 千分位分隔

千分位分隔靠零宽断言从右往左每三位插入逗号，小数部分不受影响。

```js
function groupByThousands(value) {
  return String(value).replace(/\B(?=(\d{3})+(?!\d))/g, ",");
}

console.log(groupByThousands(1234567));  // "1,234,567"
console.log(groupByThousands(123));      // "123"
console.log(groupByThousands(1234.56));  // "1,234.56"（小数部分不参与）
```

> 这段模式拆解：\B 定位在**非单词边界**，(?=(\d{3})+(?!\d)) 断言“后面的数字个数正好是 3 的倍数”。它之所以正确，是因为**从右往左**每三位插入一个逗号，正是“后面剩余位数是 3 的倍数”的那些位置。现代代码也可以直接用 Number.prototype.toLocaleString() 或 Intl.NumberFormat。



#### 百分比与小数位

**百分比的取值范围是 0 到 100**，模式要把“100”与“小于 100 的数”分两支写，否则 101 会蒙混过关。

```js
const percentReg = /^(?:100(?:\.0{1,2})?|\d{1,2}(?:\.\d{1,2})?)$/;

console.log(percentReg.test("0"));      // true
console.log(percentReg.test("9.5"));    // true
console.log(percentReg.test("99.99"));  // true
console.log(percentReg.test("100"));    // true
console.log(percentReg.test("101"));    // false（超出上界）
console.log(percentReg.test("9.999"));  // false（超过两位小数）
```

> 拆解：第一支 100(?:\.0{1,2})? 专门接收上界（且小数只能是零），第二支 \d{1,2}(?:\.\d{1,2})? 接收一到两位整数加最多两位小数。**上界是分支写法的经典理由**：如果只写 \d{1,3}(?:\.\d{1,2})?，101 到 999 全都会通过。



#### 密码强度校验

**条件叠加**是密码强度校验的核心技巧，断言原理详见系列第 6 篇《断言与锚点》。

```js
// 至少 8 位，且同时包含小写字母、大写字母与数字
const pwdReg = /^(?=.*[a-z])(?=.*[A-Z])(?=.*\d).{8,}$/;

console.log(pwdReg.test("abc12345"));  // false（缺大写字母）
console.log(pwdReg.test("Abc12345"));  // true
console.log(pwdReg.test("Ab1"));       // false（不足 8 位）
```

> 要再加“必须含特殊字符”，并列一个 (?=.*[^\w\s]) 即可，主干无需改动。



#### IPv4 与端口号

**IPv4 的四段各有 0 到 255 的取值约束**，必须按 250~255、200~249、100~199、0~99 四档拆分，不能简单写成 \d{1,3}。

```js
const ipv4Reg =
  /^(?:(?:25[0-5]|2[0-4]\d|1\d{2}|[1-9]?\d)\.){3}(?:25[0-5]|2[0-4]\d|1\d{2}|[1-9]?\d)$/;

console.log(ipv4Reg.test("192.168.1.1"));      // true
console.log(ipv4Reg.test("255.255.255.255"));  // true
console.log(ipv4Reg.test("256.1.1.1"));        // false（超出 255）
console.log(ipv4Reg.test("1.2.3"));            // false（只有三段）
console.log(ipv4Reg.test("01.2.3.4"));         // false（不允许前导 0）

// 端口号：1 到 65535
const portReg = /^(?:6553[0-5]|655[0-2]\d|65[0-4]\d{2}|6[0-4]\d{3}|[1-5]\d{4}|[1-9]\d{0,3})$/;
console.log(portReg.test("80"), portReg.test("8080"), portReg.test("65535")); // true true true
console.log(portReg.test("0"), portReg.test("65536"));                        // false false
```

> 拆解：IP 分档的依据是**百位与十位的可能取值**——25 开头只能到 255、2 开头但第二位不是 5 时是 200~249、1 开头是 100~199、其余是 0~99（且不允许前导 0，所以写 [1-9]?\d 而不是 \d{1,2}）。端口号用同一思路分六档封顶到 65535。

> [!TIP]
> **建议内容**：IPv4 与端口这类**有明确数值上界**的字段，交给 Number.isInteger 与范围判断往往比正则更直观；只有当它们嵌在一段更长的文本里（如 “192.168.1.1:8080”）需要整体提取时，正则才是合适工具。IPv6 不建议手写正则，复杂度极高且极易出错。



### 文本清洗

#### 去掉首尾空格

去掉首尾空格有正则与原生两套写法，生产代码应优先调用 trim() 系列方法。

```js
const str = "  hello world  ";

// 正则实现
console.log(str.replace(/^\s+|\s+$/g, "")); // "hello world"

// 原生方法（推荐）
console.log(str.trim());      // "hello world"
console.log(str.trimStart()); // "hello world  "
console.log(str.trimEnd());   // "  hello world"
```

> 生产代码一律用 trim() 系列，正则写法只作理解用：^\s+ 匹配开头空白、\s+$ 匹配结尾空白、| 表示“或”、g 保证两端都处理。这种“开头或结尾”的模式在数据清洗（如去掉首尾逗号、首尾引号）时很常见。



#### 驼峰与短横线互转

CSS 属性名与 JavaScript 属性名之间的互转是 replace 加替换函数的经典应用。

```js
// background-color-image → backgroundColorImage
function camelize(text) {
  return text.replace(/-([a-z])/g, (match, letter) => letter.toUpperCase());
}

// backgroundColor → background-color
function hyphenate(text) {
  return text.replace(/[A-Z]/g, (letter) => "-" + letter.toLowerCase());
}

console.log(camelize("background-color-image")); // "backgroundColorImage"
console.log(hyphenate("backgroundColor"));       // "background-color"
```

> 拆解：camelize 用捕获组抓住短横线后的那个字母，替换函数里把它转成大写，短横线本身因为不在返回值里而被丢弃；hyphenate 没有捕获组，直接把每个大写字母替换为“短横线加小写”。两者的差别说明：**删掉什么就让它只出现在模式里，保留什么就写进替换结果**。



#### 提取文件扩展名

提取扩展名用排除型字符类配合结尾锚点，天然定位到最后一个点之后的片段。

```js
function getFileExtension(filename) {
  const match = filename.match(/\.([^.\/]+)$/);
  return match ? match[1].toLowerCase() : "";
}

console.log(getFileExtension("报告.终稿.PDF"));   // "pdf"
console.log(getFileExtension("archive.tar.gz")); // "gz"（取最后一个）
console.log(getFileExtension("README"));         // ""（无扩展名）
```

> 拆解：排除型字符类 [^.\/]+ 表示“一串既不是点也不是斜杠的字符”，配合 $ 锚定结尾，天然定位到**最后一个点**之后。写 .\*\.(\w+)$ 也能得到同样结果，但排除型写法没有回溯隐患。



#### 删除代码注释

删除注释要分别处理块注释与行注释，块注释靠惰性量词避免吞掉后续代码。

```js
function stripComments(code) {
  return code
    .replace(/\/\*[\s\S]*?\*\//g, "") // 块注释：惰性防止吞掉后面的代码
    .replace(/\/\/.*$/gm, "");        // 行注释：m 让每一行的 // 都生效
}

const source = "const a = 1; /* 说明 */\n// 备注行\nconst b = 2;";
console.log(stripComments(source));
// "const a = 1; \n\nconst b = 2;"（内容被删，换行骨架保留）
```

> 拆解：块注释用 [\s\S]*? 而不是 .*，因为 . 不匹配换行；惰性量词保证“遇到第一个 */ 就停”，贪婪会把后面所有代码都吞进注释。行注释用 .* 加 gm：m 让 $ 对每一行生效。字符串里恰好含 “//” 的代码会被误删——这正是“正则不解析结构”的又一例证。



#### 逗号分隔列表的清理与去重

**逗号分隔的标签串几乎不会长得规整**：多余空格、重复项、连续逗号、首尾逗号都会出现。清洗顺序是“拆分 → 逐项规整 → 去重 → 回填”。

```js
function normalizeList(text) {
  return [...new Set(
    text
      .split(/[,，]/)                  // 半角与全角逗号都当分隔符
      .map((item) => item.trim().replace(/\s+/g, " ")) // 去掉首尾空白并压缩内部空白
      .filter(Boolean)                 // 丢掉空项（连续逗号产生）
  )];
}

console.log(normalizeList("a, b ,a,,c, a"));
// ["a", "b", "c"]

console.log(normalizeList("张三， 李四,,张三"));
// ["张三", "李四"]
```

> 拆解：split(/[,，]/) 一次处理两种逗号，map 里的两级 replace 分别负责去首尾与压缩内部空白，filter(Boolean) 把空串与 undefined 一并滤掉，最后用 Set 去重。**去重用数据结构而不是正则**——正则擅长识别“重复出现”，但不擅长“保留第一次出现的那个”。



#### 敏感信息脱敏

**脱敏**是警务与政务数据处理的高频需求：日志、报表里展示的证件号、手机号、卡号都应保留首尾、遮蔽中段。

```js
function maskSensitive(text) {
  return text
    .replace(/\b(\d{6})\d{8}(\d{3}[\dXx])\b/g, "$1********$2") // 身份证 18 位：留首 6 尾 4
    .replace(/\b(\d{4})\d{8,12}(\d{4})\b/g, "$1********$2")    // 银行卡 16~20 位：留首 4 尾 4
    .replace(/\b(\d{3})\d{4}(\d{4})\b/g, "$1****$2");           // 手机号 11 位：留首 3 尾 4
}

console.log(maskSensitive("身份 110101199003072316"));
// "身份 110101********2316"

console.log(maskSensitive("卡号 6222020200112233456 待核"));
// "卡号 6222********3456 待核"

console.log(maskSensitive("联系 13812345678"));
// "联系 138****5678"
```

> [!WARNING]
> **警告内容**：脱敏正则的替换顺序就是**污染风险顺序**：宽泛的模式会把更长的号码先改掉，导致后续模式匹配不上。身份证（18 位）先于银行卡（16~20 位）、银行卡先于手机号（11 位）正是这个原因，且每条模式都用 \b 定界防止部分命中；上线前用混合真实格式的样本串整体验证一遍，防止规则互相覆盖。



### 提取与解析

#### URL 与域名提取

URL 校验与主机名提取分开处理：前者只能用正则粗筛，后者用捕获组抠出主机段。

```js
const urlReg = /^https?:\/\/[\w.-]+(?::\d+)?(?:\/[\w\-./?%&=#]*)?$/;

console.log(urlReg.test("https://example.com"));         // true
console.log(urlReg.test("http://example.com:8080/a/b")); // true
console.log(urlReg.test("ftp://example.com"));           // false（仅 http/https）
console.log(urlReg.test("example.com"));                 // false（缺协议）
```

> 正则校验 URL 的**局限很明显**：它处理不了 IPv6 主机、用户名字段、复杂查询串，也判断不了域名是否合法。浏览器内置的 new URL(value) 才是正确做法，正则只适合做“必须以 http(s) 开头”这类粗筛。

从文本里**抠出主机名**是正则更合适的场景：

```js
function extractDomain(url) {
  const match = url.match(/^https?:\/\/(?:www\.)?([^\/?#]+)/);
  return match ? match[1] : null;
}

console.log(extractDomain("https://www.example.com/path?q=1")); // "example.com"
console.log(extractDomain("http://api.service.cn:8080/v1"));    // "api.service.cn:8080"
console.log(extractDomain("不是网址"));                          // null
```

> 拆解：(?:www\.)? 用非捕获组吃掉可选的 www 前缀，([^\/?#]+) 捕获到第一个斜杠、问号或井号之前的整段主机。遇到只需主机、不要路径的需求，这个模式比完整 URL 校验短得多。



#### 日期校验与解析

日期的**格式**可以完全交给正则，日期的**真实性**（闰年、每月天数）需要代码二次确认。

```js
const dateReg = /^\d{4}-(?:0[1-9]|1[0-2])-(?:0[1-9]|[12]\d|3[01])$/;

console.log(dateReg.test("2024-02-29")); // true（格式合法）
console.log(dateReg.test("2023-02-29")); // true！格式对，但 2023 年没有 2 月 29 日
console.log(dateReg.test("2024-13-01")); // false（月份 13 非法）
console.log(dateReg.test("2024/01/15")); // false（分隔符不符）
```

```js
// 正则粗筛 + 代码精查的标准组合
function isValidDate(text) {
  if (!/^\d{4}-\d{2}-\d{2}$/.test(text)) return false;
  const [year, month, day] = text.split("-").map(Number);
  const date = new Date(text);
  return date.getFullYear() === year && date.getMonth() + 1 === month && date.getDate() === day;
}

console.log(isValidDate("2024-02-29")); // true（闰年成立）
console.log(isValidDate("2023-02-29")); // false（非闰年被代码拦下）
```

> 完整的闰年规则（四年一闰、百年不闰、四百年再闰）理论可以写进正则，但可读性会崩塌。**格式问题归正则，业务问题归代码**，这是日期校验的分工准则。



#### 时间与时长

**时间用 24 小时制按位限界**，时长则适合用一组可选的分组分别捕获，再交给代码换算。

```js
// 时间：HH:MM 或 HH:MM:SS，小时 00-23，分秒 00-59
const timeReg = /^(?:[01]\d|2[0-3]):[0-5]\d(?::[0-5]\d)?$/;

console.log(timeReg.test("09:30"));     // true
console.log(timeReg.test("23:59:59"));  // true
console.log(timeReg.test("24:00"));     // false（小时不超过 23）
console.log(timeReg.test("09:60"));     // false（分钟不超过 59）

// 时长：小时、分、秒三段都可选，按顺序出现
const durationReg = /^(?:(\d+)小时)?(?:(\d+)分)?(?:(\d+)秒)?$/;

function durationToSeconds(text) {
  const match = durationReg.exec(text);
  if (!match || text === "") return null;
  const [, hour, minute, second] = match;
  return Number(hour ?? 0) * 3600 + Number(minute ?? 0) * 60 + Number(second ?? 0);
}

console.log(durationToSeconds("1小时30分")); // 5400
console.log(durationToSeconds("45秒"));      // 45
console.log(durationToSeconds("1天"));       // null
```

> [!CAUTION]
> **注意内容**：时长模式里三段都是可选的，因此**空串也能匹配成功**（返回 null 的判断必须显式写上，不能只判 match）。这类“全可选组合”的模式要特别警惕：它的匹配集合包含空串，做校验时会变成永真。



#### 结构化日志行解析

日志行是**命名捕获组**的最佳舞台：一条模式把时间、级别、正文拆成具名字段。

```js
const logLine = "2026-04-12 01:30:00 [ERROR] Connection refused on port 8080";
const logReg = /^(?<date>\d{4}-\d{2}-\d{2})\s+(?<time>\d{2}:\d{2}:\d{2})\s+\[(?<level>\w+)\]\s+(?<message>.+)$/;

const log = logReg.exec(logLine);
console.log(log.groups.date);    // "2026-04-12"
console.log(log.groups.level);   // "ERROR"
console.log(log.groups.message); // "Connection refused on port 8080"
```

> 拆解：\s+ 兼容不定长空白；级别一段先转义方括号圈定边界，再用命名捕获组 level 记录括号内的单词字符。把这条模式配合 matchAll 扫描整份日志文件，再按 level 分组统计，就是一个最小可用的日志分析器。



#### 提取超链接地址

从 HTML 里抠链接靠捕获组取出 href 属性值，属于粗筛手段，受格式限制明显。

```js
const html = '<a href="https://example.com">官网</a> <a href="/login">登录</a>';
const hrefReg = /<a\s[^>]*?href="([^"]+)"/g;

for (const match of html.matchAll(hrefReg)) {
  console.log(match[1]); // "https://example.com"、"/login"
}
```

> [!WARNING]
> **警告内容**：正则提取 HTML 属于**粗筛手段**：属性顺序、单双引号、多行属性、注释里的假标签都会让它失手。确定要解析 HTML 时，用 DOMParser 或 jsdom 这类专用解析器；正则只适合格式受控的模板文本。



#### 提取话题标签与提及

带前缀记号的提取模式同构：话题标签与提及都靠捕获组取正文，并需排除邮箱误命中。

```js
const text = "#js #regex #es2022 普通文字";
const tags = [...text.matchAll(/#(\w+)/g)].map((m) => m[1]);

console.log(tags); // ["js", "regex", "es2022"]
```

> 拆解：# 字面匹配，(\w+) 捕获标签正文，matchAll 一次取全。中文话题标签把 \w+ 换成 [\p{Script=Han}\w]+ 加 u 标志即可。这类“带前缀记号的提取”同构于 @提及、$股票代码等场景，换个前缀字符直接复用。

```js
// @提及：中英文昵称都支持
const chat = "@张三 和 @admin 都收到了，邮箱是 a@b.com";
console.log([...chat.matchAll(/@([\w\p{Script=Han}]+)/gu)].map((m) => m[1]));
// ["张三", "admin"]

// 注意：账号里含 @ 的场景（邮箱）会误命中，需要用后行断言排除前置字符
console.log([...chat.matchAll(/(?<![\w.])@([\w\p{Script=Han}]+)/gu)].map((m) => m[1]));
// ["张三", "admin"]（a@b.com 被排除）
```

> [!NOTE]
> **提醒内容**：“带前缀记号”的提取模式**必须考虑前缀本身是正文一部分的情况**：@ 在邮箱里、# 在锚点链接里、$ 在价格里都会误命中。补一个后行否定断言 (?<![\w.]) 把前置字符排掉，是这类模式的通用加固手段。



#### UUID 与十六进制颜色

两类**定长字符集**的校验：UUID 是固定分段与版本号约束，颜色值是可选的简写长度。

```js
// UUID v1 到 v5：第 13 位是版本号，第 17 位是变体位
const uuidReg = /^[0-9a-f]{8}-[0-9a-f]{4}-[1-5][0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$/i;

console.log(uuidReg.test("123e4567-e89b-42d3-a456-426614174000")); // true（v4）
console.log(uuidReg.test("123e4567-e89b-42d3-c456-426614174000")); // false（变体位不合法）

// 十六进制颜色：三位简写、六位标准、八位带透明度
const colorReg = /^#(?:[0-9a-f]{3}|[0-9a-f]{6}|[0-9a-f]{8})$/i;

console.log(colorReg.test("#fff"), colorReg.test("#FF8800"), colorReg.test("#FF8800AA"));
// true true true
console.log(colorReg.test("#ffff"), colorReg.test("#GGG")); // false false
```

> 拆解：UUID 的第 3 段首位用 [1-5] 限定版本、第 4 段首位用 [89ab] 限定变体，这是“格式正确”之外的第二层约束；颜色值用三分支分别匹配三种长度，**分支之间不会互相误判**，因为长度不同、锚点已收口。



### 应用组合

#### 高亮关键词

关键词高亮 = **转义用户输入** + **替换函数包裹标记**，两者缺一不可。

```js
function highlightKeyword(text, keyword) {
  const safeReg = new RegExp(escapeRegExp(keyword), "gi");
  return text.replace(safeReg, (matched) => `<mark>${matched}</mark>`);
}

console.log(highlightKeyword("RegExp 很强，regexp 很难。", "regexp"));
// "<mark>RegExp</mark> 很强，<mark>regexp</mark> 很难。"

console.log(highlightKeyword("正则的点是特殊字符：a.b", "a.b"));
// "<mark>a.b</mark>"（点已被转义，不会匹配 axb）
```

> 拆解：escapeRegExp 保证关键词里的元字符按普通字符处理（定义见系列第 9 篇《性能与安全》）；gi 标志实现全量与忽略大小写；替换函数用 matched 而不是 $&，能原样保留每个匹配的**原有大小写**。若直接把关键词拼进正则，输入 ( 就会抛 SyntaxError，输入 (a+)+ 就可能触发 ReDoS。



#### 模板插值替换

简易模板引擎的插值就是一个 replace 加捕获组。

```js
function renderTemplate(template, data) {
  return template.replace(/\{\{(\w+)\}\}/g, (match, key) => data[key] ?? match);
}

console.log(renderTemplate("您好，{{name}}！案件 {{caseId}} 已办结。", { name: "张三", caseId: "A2024-017" }));
// "您好，张三！案件 A2024-017 已办结。"

console.log(renderTemplate("缺字段：{{missing}}", {}));
// "缺字段：{{missing}}"（键不存在时原样保留）
```

> 拆解：\{\{(\w+)\}\} 捕获花括号内的键名，替换函数按键查数据对象，查不到用 ?? 回退为原样 match。若键名允许点号与短横线，把 \w+ 换成 [\w.-]+ 即可。这一模式同样适用于把敏感字段（姓名、手机号）批量替换为掩码。



#### 换行统一与段落整理

**跨平台文本的换行符有三种形态**：Windows 的 \r\n、老式 Mac 的 \r、Unix 的 \n，混在一起会让按行切分与比对全部失准。

```js
function normalizeNewlines(text) {
  return text
    .replace(/\r\n?/g, "\n")   // \r\n 与单独的 \r 统一成 \n
    .replace(/[ \t]+$/gm, "")  // 行尾多余空白去掉
    .replace(/\n{3,}/g, "\n\n"); // 连续空行压缩为空一行
}

const messy = "标题  \r\n\r\n正文第一段\rc\n\n\n\n结尾  ";
console.log(JSON.stringify(normalizeNewlines(messy)));
// "标题\n\n正文第一段\nc\n\n结尾"
```

> [!TIP]
> **建议内容**：换行统一是**所有文本处理流水线的第一步**，且应当只做一次、放在最前面。顺序建议是：统一换行 → 去行尾空白 → 压缩空行 → 再进入业务正则。把这几步拆成独立的 replace 串起来，比塞进一条大模式更容易调试，也更容易复用。
