## CSS 简介与引入方式

### 前端三剑客中的 CSS

#### CSS 的概念

**CSS（Cascading Style Sheets，层叠样式表）**：是用于**描述网页样式与布局**的**声明式**语言，负责解决 HTML 内容"长什么样"的问题。HTML 管"有什么"，CSS 管"长什么样"，JavaScript 管"能做什么"。

- **HTML**：描述文档的**结构**，是一棵标签树。
- **CSS**：描述结构如何**呈现**——颜色、字体、间距、尺寸、位置、动画。
- **JavaScript**：描述网页的**行为**，让页面响应用户操作。

> 用盖房子的类比：HTML 是**骨架**，CSS 是**装修与布局**，JavaScript 是**水电与智能家居**。同一份 HTML 配不同的 CSS，可以呈现出天差地别的外观——这正是结构与表现分离的价值。



#### CSS 的声明式特性

**声明式（Declarative）**：指开发者**描述"最终要什么效果"**，而非"一步步怎么做"。CSS 的本质是给元素"下规则"，浏览器负责把这些规则应用到页面。

```css
/* 声明式：告诉浏览器标题应该是什么样，不关心它如何一步步绘制 */
h1 {
  color: red;
  font-size: 24px;
}
```

- **选择器**：h1 指明规则作用于哪些元素。
- **属性：值**：color: red 声明一个具体样式。
- **层叠**：多个规则作用于同一元素时，按优先级与来源决出最终值。

> 与命令式的 JavaScript 相对：CSS 只"描述结果"，遇到冲突由**层叠算法**仲裁；JavaScript 则"编写步骤"。这也决定了 CSS **没有变量、循环、条件**这些控制结构（其"逻辑"靠选择器与层叠模拟），直到 CSS 自定义属性出现才稍显灵活。



#### CSS 的版本演进

CSS 的标准化**不像 ECMAScript 那样按版本号大规模迭代**，而是拆分为**上百个独立模块**、各自独立定版（Level 1/2/3）。习惯上仍按大版本叙述。

- **CSS1（1996）**：首个正式标准，定义了字体、颜色、背景、文本、盒模型的基本样式。
- **CSS2 / CSS2.1（1998 / 2011）**：引入定位、浮动、选择器体系、@media 雏形、表格布局，是**经典 CSS 的集大成者**，也是"传统布局三件套（浮动/定位/标准流）"的出处。
- **CSS3（1999 起）**：不再是单一版本，而是**一大波独立模块**的代称，如圆角、阴影、渐变、过渡、动画、Flex、Grid、媒体查询、自定义属性等。
- **CSS4 争议**：官方已无"CSS4"整版，所谓"CSS4"指已进入 Level 4 的新模块（如选择器 Level 4、颜色 Level 4 的 oklch() 等）。

> 学习 CSS 的正确心态是**忘掉"CSS3 学完就毕业"**：CSS 是持续演进的模块集合。判断某特性能否使用，应查 **Can I Use**（caniuse.com），而非记"是 CSS3 还是 CSS4"。



### CSS 的引入方式

#### 三种引入方式

CSS 有三种引入网页的方式，按**推荐程度**由高到低排列。

1. **外部样式表（推荐）**：把 CSS 写入独立的 .css 文件，用 link 元素引入，实现**结构与样式彻底分离**，可被浏览器缓存。
2. **内嵌样式**：在 HTML 的 head 里用 style 元素包裹 CSS，仅适合单页小规模样式。
3. **行内样式**：在元素上用 style 属性直接写 CSS，优先级最高但完全无法复用。

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <title>CSS 引入方式</title>
  <!-- 方式一：外部样式表，rel 必须是 stylesheet -->
  <link rel="stylesheet" href="./css/style.css">
  <!-- 方式二：内嵌样式 -->
  <style>
    p { line-height: 1.6; }
  </style>
</head>
<body>
  <!-- 方式三：行内样式，会覆盖样式表里的同优先级规则 -->
  <h1 style="color: red;">标题</h1>
</body>
</html>
```

> 三种方式的取舍核心是**复用与维护**：外部文件唯一满足"一处改动、全站生效、多页共享、可缓存"，是生产首选；内嵌适合演示或首屏关键样式（避免额外请求）；行内样式因不可复用、优先级过高难覆盖、无法用 CSS 特性检测，只适合做动态的临时覆盖（常由 JS 写入）。



#### @import 与 link 的区别

除 link 元素外，CSS 内部也可用 @import 引入其它样式表，但二者机制差异显著。

```css
/* 必须写在样式表最顶部（其它规则之前） */
@import url("./theme.css");
@import "./reset.css";
```

- **link 元素**：HTML 层面引入，**可并行下载**（多张样式表可同时取），且不依赖外层样式表，是推荐方式。常规写法即 rel 属性为 stylesheet 的 link 元素，本身仍会**阻塞渲染**（需等 CSSOM 构建完成才首绘），只有 media 不匹配的样式表才不阻塞。
- **@import**：CSS 层面引入，**必须置于顶部**，**串行加载**（等外层样式表下载完才开始），会增加请求链深度、拖慢首屏，性能较差。
- **加载时序**：link 元素由浏览器在解析 head 时即发起下载；@import 要等当前样式表解析到该行才去取。

> 实践中**几乎总是用 link 元素**。@import 常见的合法用途极少（如在一个"入口样式表"里聚合多个分片），且主流打包工具都会把 @import 内联合并或转成 link 元素。避免在页面加载路径上使用 @import 是性能基线常识。



#### 行内样式与 !important

当三种方式作用于同一元素时，**优先级由层叠规则决定**，其中行内样式占有特殊地位。而 !important 是能推翻常规层叠的"最高命令"。

```css
p { color: blue !important; }
```

```html
<p style="color: red;">这段文字最终是蓝色</p>
```

- **常规层叠**：行内样式（内联 style）优先级**高于**选择器产生的任何"选择器优先级"（除非后者带 !important）。
- **!important**：声明后该条规则**压过所有普通声明**，包括行内样式的普通声明。
- **!important 之间**：仍按来源与选择器优先级比较——同是 !important，谁的来源更权威、选择器更具体谁生效。

> 优先级排序速记：**!important > 行内样式 > ID 选择器 > 类/属性/伪类 > 元素/伪元素 > 继承值**。!important 和行内样式都被视为"越过常规选择器权重"的特殊层，应尽量少用，否则会破坏层叠的可预测性（详见"层叠、继承与优先级"章）。



### CSS 语法基础

#### 规则的结构

一条 CSS **规则（rule）** 由**选择器**与**声明块**组成；声明块内是若干**属性: 值**声明，彼此用**分号**分隔。

```css
/* 选择器 { 声明块 } */
h1, .title {          /* 选择器列表：元素 h1 或类 .title */
  color: red;          /* 声明：属性: 值 */
  font-size: 24px;     /* 每个声明以分号结尾（末条可省） */
}
```

- **选择器列表**：用逗号把多个选择器合成一组，命中其中任一即应用规则。
- **注释**：CSS 只有 /* ... */ 一种注释，可单行可多行。
- **空白**：空格与换行不参与匹配，用于排版；冒号后、逗号后习惯留空格。

> [!WARNING]
> **警告内容**：两个易错点：CSS 注释**没有**类似 JS 的 // 单行注释（写了会被当作选择器的一部分）；声明块里的**大括号必须成对**，少一个 } 会吞掉其后的全部规则，这是最隐蔽的"样式整片失效"原因之一。



#### 属性与值的对应

CSS 中每个**属性**都有其**可接受的值的类型**（关键字、长度、颜色、函数、全局值等），写错类型的值会被**整条声明丢弃**（而非自动纠错）。

- **关键字值**：如 display: block、position: absolute。
- **长度值**：如 width: 100px、font-size: 2rem。
- **颜色值**：如 color: red、background: #fff、rgb(0,0,0)。
- **函数值**：如 transform: translate(10px)、width: calc(100% - 40px)。
- **全局关键字**：inherit（强制继承父值）、initial（取属性初始值）、unset（可继承则继承、否则取初始值）、revert（回退到浏览器默认样式）。

```css
.box {
  width: calc(100% - 40px);   /* 函数值 */
  color: #333;                /* 颜色值 */
  display: block;             /* 关键字值 */
  color: 问号垃圾值;          /* 非法值：整条 color 声明被丢弃，其它不受影响 */
}
```

> 一个值的"能写多宽"由该属性定义的**值语法**决定。非法值只会让**当前这一条声明失效**，不影响同一规则里的其它声明——这与 JS 的"报错中断"不同，CSS 采用"坏一条丢一条"的容错策略。



#### 浏览器与开发者工具

开发 CSS 最依赖的检查工具是**浏览器开发者工具（DevTools）**的 **Elements / Styles** 面板，它直接揭示层叠结果与来源。

- **Styles 面板**：列出命中当前元素的全部规则，**自上而下按来源排列**，靠后者优先；可即时勾选/取消声明、修改值实时预览。
- **Computed 面板**：展示所有属性经层叠、继承、计算后的**最终生效值**，是排查"为什么没生效"的最终依据。
- **覆盖来源标识**：被覆盖的声明会显示删除线，行内样式、!important、各样式表来源都有标记，便于定位是谁"赢了"。

> 排查 CSS 问题的黄金顺序：选中元素 → 看 **Computed** 确认最终值 → 看 **Styles** 谁覆盖了它 → 检查选择器是否命中、优先级是否不足、属性值是否合法。绝大多数"样式没生效"都逃不出这四个环节。



### CSS 的学习路线与认知

#### 从"调样式"到"算布局"

学习 CSS 最容易陷入"边查边试、玄学调参"，正确的进阶路径是**建立可计算的模型**——用规则而不是试错去推导结果。

1. **基础语法层**：选择器命中谁、层叠如何决出值、盒模型怎么算尺寸。
2. **布局层**：标准流 → 浮动 → 定位 → Flex → Grid，理解每种布局的**适用场景与局限**。
3. **视觉层**：颜色、字体、背景、渐变、滤镜、动画，负责表现与交互反馈。
4. **工程层**：变量、函数、模块化、预处理器、构建工具，负责规模化与可维护。

> 把 CSS 当"程序"来学：每种布局模式都有一组**决定因素**（如 Flex 的 flex-grow/shrink/basis），把它们当作输入，就能**算出**结果，而非靠反复刷新猜测。这才是从"会用"到"会算"的分水岭。



#### CSS 与 HTML、JavaScript 的关系

三个技术各司其职，最佳实践强调**关注点分离（Separation of Concerns）**。

- **结构（HTML）**：只表达内容与语义，不关心外观。
- **表现（CSS）**：只表达外观与布局，通过选择器附着到结构上。
- **行为（JavaScript）**：只表达交互与逻辑，一般不改样式（改的是 class 或 CSS 变量，让 CSS 来呈现）。

```css
/* 推荐：JS 只切换类，样式变化全交给 CSS 过渡/动画 */
.item.is-active {
  color: #f60;
  transform: scale(1.1);
  transition: all 0.3s;
}
```

```js
// JS 不直接改具体样式属性，而是切换类名，交给 CSS 去表现
element.classList.toggle("is-active");
```

> 关注点分离的收益：**可维护**（各层独立演进）、**可复用**（同一套样式用于多处）、**可换肤/响应式**（仅改 CSS 就改变外观）。直接由 JS 逐个改样式属性的写法会打散样式定义、难以统一管理，应视为反模式。
