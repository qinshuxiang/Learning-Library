## 显示与溢出、可见性

### display 体系

#### display 的核心取值

**display**：决定元素的**盒类型**与是否参与某种格式化上下文，是布局的"总开关"，取值很丰富。

- **块级**：block（独占一行、填满父宽）。
- **行内**：inline（同行排布，不能设宽高/上下 margin）。
- **行内块**：inline-block（能设宽高、又能同行排布）。
- **列表/表格**：list-item、table、table-cell 等。
- **布局容器**：flex、grid（给容器开布局模型）。
- **内容/隐藏**：none（不渲染）、contents（自身不渲染但子元素照常）。
- **其它**：flow-root（建 BFC）、inline-flex、inline-grid。

```css
.hide { display: none; }        /* 彻底移除，不占位 */
.flex { display: flex; }        /* 弹性容器 */
```

> display 决定"这个元素是块、行内，还是容器/网格"。块与行内的区别是布局的底层地基：inline 设宽高无效、上下 padding/margin 不推挤布局，block 独占一行、可设宽高。要"既有块的能力又能并排"用 inline-block。



#### display 的可视性对比

display 也常与 visibility、opacity 混淆——三者都能"让元素看不见"，但后果完全不同。

- **display: none**：元素**从文档流移除**，不占空间、不响应事件、子元素一并消失。
- **visibility: hidden**：元素**隐藏但仍占空间**，不响应事件，其子元素可单独 visibility: visible 恢复。
- **opacity: 0**：元素**透明但完全保留**，仍占空间、**仍可响应事件**（可点击不可见区域）。

```css
.a { display: none; }        /* 彻底消失，不留位置 */
.b { visibility: hidden; }   /* 隐形，占位 */
.c { opacity: 0; }           /* 透明，占位且可交互 */
```

> 三者取舍速记：**要彻底移除且不占位用 display:none**；**要隐藏但保布局（如撑住布局的占位）用 visibility**；**要透明但仍允许点击（或做淡入过渡）用 opacity**。其中只有 opacity 能平滑过渡——display:none 不可过渡，visibility 只能离散切换。



#### 隐藏与过渡的配合

"显示/隐藏 + 动画"是常见需求，但 display:none 无法被过渡，需要技巧组合。

```css
/* 先让 display 可用(如 block)，再对 opacity/visibility 过渡 */
.dropdown {
  opacity: 0;
  visibility: hidden;      /* 隐藏且不可交互 */
  transition: opacity 0.3s, visibility 0.3s;
}
.dropdown.open {
  opacity: 1;
  visibility: visible;
}
```

- 纯 display:none 切换无过渡 → 用 opacity + visibility 模拟淡入淡出并控制交互。
- visibility 的"延迟切换"配合 transition 可在动画结束后再真正隐藏。
- 现代也可用 transition-behavior: allow-discrete + @starting-style 让 display 也能参与进出场（较新）。

> 做下拉/浮层的进出场：**默认 opacity:0 + visibility:hidden，.open 时 opacity:1 + visibility:visible**，再配 transition 就能淡入，且隐藏时不挡点击。若必须在结束后移除空间，可再加 display:none（延迟到动画后切）。这个组合是"可过渡隐藏"的经典解法。



### 溢出控制

#### overflow 的取值与滚动

**overflow**：内容超出盒子尺寸时的处理，也用于控制**滚动容器**（详见盒模型章，此处补充滚动细节）。

```css
.scroll-y { overflow-y: auto; }   /* 垂直需要时滚动 */
.scroll { overflow: auto; }       /* 双轴需要时滚动 */
.no-scrollbar-x { overflow-x: hidden; }
```

- visible（默认，溢出可见）、hidden（裁剪）、auto/scroll（滚动）。
- **滚动容器**：设 overflow 非 visible 的元素会成为滚动容器，其内容可被 scrollTop 等控制。
- **移动端**：overflow 容器上可用 -webkit-overflow-scrolling: touch 提升惯性（旧浏览器）。

> 想"一块区域内容超了就滚、不超不显示滚动条"用 overflow:auto；"一定要能滚"用 scroll；"裁掉不要滚"用 hidden。注意 overflow:auto 会让元素变成滚动容器并建立 BFC，其内 position: fixed/sticky 的参考系可能变化（sticky 相对它）。



#### 文本与内容的溢出处理

内容溢出的另一类发生在**文本/单元素**层面（详见文本章与盒模型章，汇总如下）。

- **文本单行省略**：overflow:hidden + white-space:nowrap + text-overflow:ellipsis。
- **多行省略**：-webkit-line-clamp。
- **text-overflow**：文本溢出时的省略标记（ellipsis / clip）。
- **宽高限制**：max-width、min-width、overflow-wrap/word-break 控制折行。

```css
.ellipsis {
  overflow: hidden;
  white-space: nowrap;
  text-overflow: ellipsis;
}
.long-word { overflow-wrap: break-word; }  /* 长单词可折行 */
```

> 文本溢出的本质分两种：**空间超了不让折行**（用省略号收尾）与**长字符串硬挤破容器**（用 overflow-wrap/word-break 让它能断行）。做卡片标题、按钮文字时，"超长不破版"比"好看的截断"更基础——先保证 overflow-wrap 兜住长串，再做美观的省略号。



### visibility 与内容可见性

#### visibility 的继承与细节

visibility 是**可继承**属性，且子元素可反向恢复，这让它比 display:none 更灵活。

- **继承**：父设 visibility: hidden，子孙默认也隐藏（继承）。
- **反恢复**：某子元素可单独设 visibility: visible 重新显示（display:none 做不到这一点）。
- **对布局**：hidden 仍占空间（区别于 display:none）。

```css
.hidden-group { visibility: hidden; }
.hidden-group .keep { visibility: visible; }  /* 组隐藏但保留这个子元素可见 */
```

> 需要"父整体隐藏、个别子仍显示"时用 visibility（配 visible 反恢复）是唯一原生方案。若只是想整体消失不留位则 display:none。两种都**不可被 opacity 那样逐像素过渡**，动画靠搭配 opacity 完成。



#### content-visibility 性能优化

**content-visibility**：让浏览器**跳过屏外内容的渲染**（布局与绘制），显著提升长页/长列表性能，是较新的优化属性。

```css
article {
  content-visibility: auto;
  contain-intrinsic-size: 1px 600px;  /* 估算占位高，避免滚动跳动 */
}
```

- **content-visibility: auto**：内容滚入视口附近才渲染，滚出则跳过。
- **contain-intrinsic-size**：给未渲染内容一个**估算尺寸**作占位，防止滚动条跳动。
- **注意**：可能与依赖 "display 全量可交互" 的逻辑（如锚点定位、查找）冲突，需按场景评估。

> [!IMPORTANT]
> **重要内容**：content-visibility:auto 是"懒渲染"级优化：整页大量屏外 DOM 时（长博客、Feed、目录）收益明显。务必配 contain-intrinsic-size 提供占位高度，否则布局会在滚动时跳动。它在把"DOM 很多"变"实际渲染很少"，是现代长页性能利器，但要评估查找/打印等副作用。
