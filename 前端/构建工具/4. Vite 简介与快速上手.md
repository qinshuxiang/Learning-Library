## Vite 简介与快速上手

**Vite**：是面向现代浏览器的前端构建工具（build tool），由尤雨溪于 2020 年发布，开发期借助浏览器原生 ES Module 提供即时启动与热模块替换，构建期由 Rollup 生成生产产物。

本篇回答四件事：Vite 是什么、怎么安装、项目长什么样、第一次启动会发生什么。配置与插件从第 5 篇展开，开发服务器与环境变量从第 6 篇展开。

### Vite 是什么与设计取向

本节确立 Vite 的定位：它同时是一个开发服务器与一个打包器，两端的实现机制并不相同，理解这一点是后续所有用法的前提。

#### Vite 的定义与命名

**Vite**：是尤雨溪与社区共同维护的前端构建工具，单词取自法语，读音为 /vit/，意为「快」，命名直接对应其设计目标。

- 双重身份：Vite 既是开发服务器（dev server），也是打包器（bundler），两端实现机制不同。
- 开发期：直接让浏览器以原生 ES Module 加载源码，不做全量打包。
- 构建期：调用 Rollup 处理产物，产出可部署的静态文件。
- 定位：默认面向现代浏览器，需要兼容旧环境时用插件补足（详见本主题第 12 篇 Rollup、esbuild 与 SWC）。

```json
// package.json 中记录的工具版本
{
  "devDependencies": {
    "vite": "^7.0.0"
  }
}
```

> Vite 的名字与「快」同义，但速度优势主要来自架构选择，而不是单纯的代码优化。

**速记**：Vite 是开发服务器与打包器的合体，取名自法语「快」。



#### 开发期与构建期的两条主线

**两条主线**：是 Vite 的架构分工，开发期用原生 ES Module 按需加载，构建期用打包器整体产出，同一份源码走两条不同路径。

- 开发期：浏览器请求哪个模块就转换哪个模块，源码不经打包，启动耗时与项目规模基本无关。
- 构建期：由 Rollup 从入口出发构建依赖图，产出经过压缩与哈希命名的静态文件。
- 依赖与源码分开：第三方依赖由 esbuild 预构建，业务源码由浏览器按模块加载。
- 一致性：两条主线共用同一份配置文件与插件容器，避免开发与生产表现割裂。

```js
// 同一份源码在开发期被浏览器按模块请求，构建期被 Rollup 打包
// src/main.js
import { createApp } from "vue";
import App from "./App.vue";

createApp(App).mount("#app");
```

> [!IMPORTANT]
> **重要内容**：开发期不做全量打包，因此「开发服务器能跑」不等于「构建能过」；提交前必须至少执行一次构建命令验证产物。

**速记**：开发期按需转换，构建期整体打包，两条主线共用同一份配置。



#### 设计取向与适用边界

**设计取向**：是 Vite 在启动速度、开发体验与产物质量之间给出的取舍方案，核心是在开发期不做无用功。

- 延迟转换：模块只在被请求时才编译，冷启动不随项目规模线性增长。
- 约定优先：入口固定为项目根目录的 index.html，原样资源固定放 public，减少配置。
- 现代浏览器基线：默认输出 ES Module，不再默认提供旧浏览器垫片（polyfill）。
- 边界：必须兼容旧版浏览器时需引入降级插件，并接受启动与构建变慢的代价。

```js
// 只有交互发生时才请求详情模块，其余代码不影响首屏启动
const loadButton = document.querySelector("#load-detail");

loadButton.addEventListener("click", async () => {
  const { renderDetail } = await import("./detail.js");
  renderDetail();
});
```

> 设计取向决定了 Vite 的默认行为，遇到与默认预期不符的场景时，应先判断是配置问题还是取向本身的边界。

**速记**：延迟转换与约定优先换来启动速度，代价是浏览器基线与旧环境兼容。



### 安装与脚手架创建

本节解决项目的起点问题：确认运行时版本，选择脚手架或手动搭建，得到可启动的项目。

#### 环境要求与 Node 版本

**环境要求**：是运行 Vite 所依赖的运行时与包管理器条件，版本不满足会在安装或启动阶段直接报错。

- Node.js：Vite 6 支持 Node.js 18、20、22；Vite 7 要求 Node.js 20.19 或 22.12 及以上。
- 包管理器：npm、pnpm、yarn、bun 均可，命令有细微差别，详见 后端/Node 主题第 6 篇 npm 与包管理。
- 编辑器：推荐安装对应框架的语言支持插件，否则单文件组件与类型提示不可用。
- 检查命令：执行 node -v 与 npm -v 确认版本，再进入创建流程。

```bash
node -v
# v22.12.0
npm -v
# 10.9.0
```

> 用于长期项目时优先选择偶数号长期支持版（LTS）；奇数号版本生命周期短，升级节奏更频繁。

**速记**：Vite 7 需要 Node.js 20.19 及以上，动手前先用 node -v 确认。



#### create-vite 脚手架

**create-vite**：是 Vite 官方的脚手架（scaffold）工具，通过模板快速生成可直接启动的项目骨架。

- 交互式创建：执行 npm create vite@latest，按提示输入项目名并选择框架与变体。
- 指定模板：npm create vite@latest my-app -- --template vue-ts 可跳过交互。
- 常见模板：vanilla、vue、vue-ts、react、react-ts、svelte、solid、preact 等。
- Vue 专用脚手架：npm create vue@latest 基于 Vite 生成更完整的 Vue 工程，含路由与状态库选项。

```bash
npm create vite@latest my-app -- --template vue-ts
cd my-app
npm install
npm run dev
# VITE v7.0.0  ready in 312 ms
# Local:   http://localhost:5173/
```

> 模板只用于起步，生成的文件可以按项目需要增删，不必为保持模板原样而保留无用文件。

**速记**：npm create vite@latest 加 --template 可直接生成指定框架的骨架。



#### 手动搭建最小项目

**手动搭建**：是不依赖脚手架、只安装 vite 并自行编写入口文件的最小流程，适合理解各文件的职责。

- 初始化：执行 npm init -y 生成 package.json。
- 安装：执行 npm install --save-dev vite。
- 建文件：在项目根目录创建 index.html，入口脚本放在 src 目录。
- 启动：执行 npx vite，或写入 scripts 后用 npm run dev。

```bash
mkdir vite-minimal && cd vite-minimal
npm init -y
npm install --save-dev vite
```

```json
// package.json 追加脚本
{
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview"
  }
}
```

> 手动搭建时容易漏掉「index.html 必须位于项目根目录」这一约定；入口脚本可以放在子目录，但入口页面位置不可随意移动。

**速记**：只装 vite、根目录放 index.html，就能得到最小可运行项目。



### 目录结构与命令

本节把脚手架产物与命令行接口对齐，明确每个目录的职责与三个核心命令的用途。

#### 默认目录结构

**默认目录结构**：是脚手架生成项目的固定布局，理解各目录归属有助于判断文件放在哪里、是否参与构建。

- 根目录 index.html：入口页面，参与构建并处理其中的资源引用。
- src 目录：源码目录，入口脚本通常是 src/main.js 或 src/main.ts。
- public 目录：原样拷贝的静态资源，不经编译，通过绝对路径访问。
- vite.config.js：可选的配置文件，不创建时使用内置默认值（详见本主题第 5 篇 Vite 配置与插件）。
- dist 目录：构建产物输出目录，由构建命令生成，不应提交到版本库。

```html
<!-- 项目根目录的 index.html，入口脚本必须声明 module 类型 -->
<!doctype html>
<html lang="zh-CN">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>Vite 演示</title>
  </head>
  <body>
    <div id="app"></div>
    <script type="module" src="/src/main.js"></script>
  </body>
</html>
```

> index.html 放在项目根目录而不是 public 目录：它需要被 Vite 读取并改写其中的资源引用，public 中的文件则原样拷贝。

**速记**：入口页在根、源码在 src、原样资源在 public、产物在 dist。



#### 常用命令与参数

**常用命令**：是 Vite 命令行接口（CLI）提供的三个核心子命令与常用选项，覆盖开发、构建、预览三个阶段。

- 开发：vite 启动开发服务器，默认端口 5173，按需编译源码。
- 构建：vite build 产出生产文件到 dist，分包与压缩详见本主题第 7 篇 Vite 构建与产物优化。
- 预览：vite preview 在本地静态服务器上预览 dist 产物，默认端口 4173。
- 常用选项：--port 指定端口，--host 暴露到局域网，--open 自动打开浏览器，--force 强制重新预构建依赖。

```bash
npx vite --port 3000 --open
npx vite build
npx vite preview --port 4173
# Local:   http://localhost:4173/
```

```bash
# 指定模式启动，模式与环境变量的关系见本主题第 6 篇
npx vite --mode staging
```

> [!NOTE]
> **提醒内容**：vite preview 只用于本地检查构建产物，它不是生产服务器，不能直接用于线上部署。

**速记**：开发用 vite，产出用 vite build，验证产物用 vite preview。



#### package.json 脚本约定

**脚本约定**：是把命令写入 package.json 的 scripts 字段，用统一的 npm run 入口替代直接敲命令。

- dev：对应 vite，团队成员与持续集成都从同一入口启动。
- build：对应 vite build，可追加参数如 --mode production。
- preview：对应 vite preview，用于构建后自检。
- 参数透传：npm run dev -- --port 3000，双横线之后的参数原样传给命令。

```json
{
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview --port 4173"
  }
}
```

```bash
npm run dev -- --host
# 从 npm 传来 --host，等价于 npx vite --host
```

> scripts 中的命令在 node_modules/.bin 下查找，因此无需写成 npx vite 或完整路径。

**速记**：dev、build、preview 三条脚本是项目对外的最小命令面。



### 最小示例与首次启动

本节走完「写文件、启动、访问、改代码」的完整闭环，确认开发链路可用。

#### 入口 HTML 与入口脚本

**入口 HTML**：是 Vite 构建图的起点，Vite 以它为根解析出被引用的脚本与样式。

- 入口位置：默认读取项目根目录的 index.html，可改为其他文件。
- 模块脚本：入口脚本必须以 module 类型引入，才会被当作 ES Module 处理。
- 路径写法：以斜杠开头的路径按项目根解析，相对路径按当前文件解析。
- 静态引用：页面中的图片与样式引用同样被识别并纳入处理。

```html
<!-- index.html -->
<div id="app"></div>
<script type="module" src="/src/main.js"></script>
```

```js
// src/main.js
import "./style.css";

const appElement = document.querySelector("#app");

appElement.textContent = "Hello Vite";
```

> 入口脚本路径以斜杠开头时按项目根解析，这一规则同时适用于 HTML 中的引用与 JavaScript 中的导入。

**速记**：index.html 是构建图起点，入口脚本必须声明 module 类型。



#### 启动开发服务器

**启动开发服务器**：是执行 dev 命令后 Vite 建立本地服务并开始按需编译的过程，输出信息包含地址与耗时。

- 冷启动：不预打包全部源码，启动耗时通常在一秒以内。
- 本地地址：默认 http://localhost:5173/，端口被占用时自动递增到下一个可用端口。
- 网络地址：加 --host 后额外打印局域网地址，便于手机等设备访问。
- 依赖预构建：首次启动会先预构建第三方依赖，后续启动走缓存（详见本主题第 6 篇 Vite 开发服务器与环境变量）。

```bash
npm run dev
# VITE v7.0.0  ready in 298 ms
# Local:   http://localhost:5173/
# Network: use --host to expose
# press h + enter to show help
```

> [!WARNING]
> **警告内容**：使用 --host 或把 server.host 设为 true 后，开发服务器可被同网络的其他设备访问，共享网络环境下需先确认访问范围可控。

**速记**：开发服务器默认 5173 端口，启动秒级完成，端口冲突自动顺延。



#### 首次访问与热更新验证

**热更新验证**：是修改源码后观察页面局部刷新的过程，用于确认热模块替换（hot module replacement）是否按预期工作。

- 保存即更新：修改组件或样式后浏览器不整页刷新，只替换改动部分。
- 状态保留：模块级状态在热更新后尽量保留，表单内容与滚动位置不会丢失。
- 终端反馈：终端打印 hmr update 与文件路径，用于确认走了热更新通道。
- 失效情形：修改配置文件或环境变量文件会触发服务器重启，属整体重启而非热更新。

```bash
# 修改 src/main.js 后终端输出
# 3:12:04 PM [vite] (client) hmr update /src/main.js
```

> 热更新只保证开发期所见即所得，涉及全局副作用时仍需整页刷新验证真实行为。

**速记**：热更新按模块替换并尽量保留状态，改配置会触发整体重启。



### 与 webpack 方案的差异

本节只对比开发期路径与配置心智，webpack 的机制与配置见本主题第 8 至 10 篇。

#### 开发期机制的差异

**开发期机制**：是 Vite 与 webpack 在开发服务器实现上的根本分歧，前者按需转换，后者先打包再服务。

- 启动方式：webpack 需先把整个依赖图打包进内存再启动服务，项目越大启动越慢；Vite 启动时几乎不做转换。
- 更新粒度：webpack 的热更新需重新计算受影响的模块链；Vite 依托原生 ES Module 边界，通常只需重新转换单个模块。
- 缓存位置：webpack 依赖内存缓存，Vite 把依赖预构建结果写入文件系统缓存。
- 体验差距：项目规模越大，两者的冷启动与热更新耗时差距越明显。

```js
// 在 Vite 中，热更新边界由模块自身声明
if (import.meta.hot) {
  import.meta.hot.accept((updatedModule) => {
    renderCounter(updatedModule.default);
  });
}
```

> webpack 的完整机制与配置见本主题第 8 至 10 篇；此处只对比开发期路径，不做配置层面的展开。

**速记**：webpack 先打包后服务，Vite 按需转换，规模越大差距越大。



#### 配置风格与心智负担

**配置风格**：是两者在「需要写多少配置」上的差别，webpack 默认全手动，Vite 默认零配置可用。

- 默认值：Vite 内置入口、输出、转译等默认值，多数项目只需几十行配置；webpack 需显式声明 entry、output、loader 与 plugin。
- 转译：Vite 默认用 esbuild 处理 TypeScript 与 JSX；webpack 通常需自行组合 babel-loader 等规则。
- 扩展方式：Vite 插件接口兼容 Rollup 插件；webpack 使用自己的 loader 与 plugin 体系。
- 迁移成本：从 webpack 迁到 Vite 时，自定义 loader 链往往需要改写为插件或改为预处理器。

```js
// vite.config.js 的典型体量
import { defineConfig } from "vite";
import vue from "@vitejs/plugin-vue";

export default defineConfig({
  plugins: [vue()],
});
```

> [!IMPORTANT]
> **重要内容**：默认零配置不等于不需要配置，涉及路径别名、接口代理与环境变量时仍要写配置文件，见本主题第 5、6 篇。

**速记**：Vite 默认零配置，webpack 默认全显式，迁移成本集中在自定义规则。



#### 选型与迁移参考

**选型参考**：是判断项目该用 Vite 还是 webpack 的几条依据，核心变量是浏览器基线、存量配置与团队经验。

- 新建项目：默认选 Vite，除非目标环境明确要求旧浏览器支持。
- 存量项目：webpack 配置稳定且深度定制时不必为换而换，先评估迁移收益。
- 库打包：需要产出 ESM、CJS、UMD 等多格式产物时，Rollup 或 Vite 库模式更合适。
- 混合方案：先在开发期用 Vite 提升体验、构建期暂时保留 webpack，再逐步统一。

```bash
# 常见迁移顺序：先跑通开发服务器，再对齐构建配置，最后替换流水线
npm install --save-dev vite @vitejs/plugin-vue
npx vite
```

> [!CAUTION]
> **注意内容**：开发期能启动不代表构建产物正确，迁移后必须逐一比对页面行为、环境变量与资源路径，问题往往在构建期才暴露。

**速记**：新建项目优先 Vite，存量项目算清迁移收益再动手。
