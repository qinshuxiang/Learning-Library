## Gulp 实战：完整构建流水线

本篇把前几篇讲过的手段拼成一条可交付的流水线：定目录与目标、拆任务、装配开发与生产两条链路，收在产物清理、校验与发布前检查上。产物之后的服务端缓存头与部署配置见 后端/Nginx 与 后端/Docker 主题，测试与持续集成门禁见 前端/测试 主题，本篇都不涉及。

### 项目结构与目标

流水线的第一步不是写任务，而是把目录与目标定下来。本节确定源、中间、产物三个目录的边界，列出构建目标，并把路径与开关集中到一处。

#### 目录约定与源产物分离

**目录约定**：是把源文件、中间产物与发布产物分置于三个目录、任一方都不写入另两方的结构安排。

- 源目录：只读，包含样式、脚本、模板与静态资源。
- 中间目录：存放打包器等外部工具的输出，供后续步骤读取。
- 产物目录：最终发布内容，可以整体删除后重建。
- 分离收益：清理动作只需针对产物目录，不会误删源文件。
- 忽略清单：依赖目录、中间目录与产物目录一并写入忽略清单。

```text
project
  ├─ src          源文件，只读
  │   ├─ styles
  │   ├─ scripts
  │   ├─ templates
  │   └─ assets
  ├─ build        中间产物
  └─ dist         发布产物
```

> 三个目录的边界一旦固定，任务拆分就有了统一的输入输出口径，新增任务不必再讨论路径。

**速记**：源、中间、产物三目录分离，源目录只读，产物目录可整体重建。



#### 构建目标清单

**构建目标**：是本条流水线需要交付的能力集合，先写清单再拆任务，避免任务与目标脱节。

- 样式目标：源文件编译、前缀补全、压缩，并按约定组织目录。
- 脚本目标：模块打包与压缩，产物先写入中间目录，再并入发布目录。
- 页面目标：模板与数据合并渲染、压缩，并注入正确的资源引用。
- 资源目标：图片与字体压缩、按目录搬运，命名规范统一。
- 校验目标：产物清单比对、空文件检查与引用地址检查。

```text
构建目标
  1. 样式：编译 ──> 后处理 ──> 压缩 ──> 落盘
  2. 脚本：打包 ──> 压缩 ──> 并入发布目录
  3. 页面：渲染 ──> 压缩 ──> 注入资源引用
  4. 资源：压缩 ──> 搬运
  5. 校验：清单 ──> 空文件 ──> 引用地址
```

> 目标清单既是任务拆分的输入，也是验收的依据，新增任务都应对应清单中的一条。

**速记**：先写样式、脚本、页面、资源、校验五类目标，再按目标拆任务。



#### 配置常量集中管理

**配置常量**：是把路径、目录名与环境开关集中在一处声明、供所有任务引用的写法。

- 路径常量：源目录、中间目录与产物目录各声明一次，任务中不再写路径字面量。
- 环境开关：用运行时环境变量判定开发与生产，避免同一条流水线出现两套分支。
- 命名规则：输出文件名的模板集中声明，便于统一调整。
- 修改收益：目录调整只改一处，任务代码不受影响。
- 校验手段：任务里引用常量而非字面量，读代码时即可确认路径来源。

```js
import path from "node:path";

export const paths = {
  src: "src",
  build: "build",
  dist: "dist",
  styles: "src/styles",
  scripts: "src/scripts",
  templates: "src/templates",
  assets: "src/assets",
};

export const isProduction = process.env.NODE_ENV === "production";

export const distPath = (segment) => path.posix.join(paths.dist, segment);
```

> [!TIP]
> **建议内容**：把目录常量与环境开关放进单独的配置文件，gulpfile 只负责导入与编排，文件长度会明显下降。

**速记**：路径与开关集中声明，任务中不写路径字面量，目录调整只改一处。



### 任务拆分设计

任务拆分的目的是让每个任务只做一件事、且可以单独执行。本节按资源类型、处理阶段与组合方式三个维度切分。

#### 按资源类型拆分任务

**资源型任务**：是以一类文件为处理对象、输入输出都围绕该类型展开的任务划分方式。

- 划分粒度：样式、脚本、页面、资源各成一组，组内再按阶段细分。
- 命名方式：任务名以资源类型为前缀，便于按名筛选与组合。
- 复用方式：同类资源的多个子任务共享同一条管道函数。
- 独立性：任意一个资源组都可以单独执行，便于局部调试。
- 交叉点：资源组之间只通过产物目录交接，不互相调用函数。

```js
import gulp from "gulp";
import gulpIf from "gulp-if";
import terser from "gulp-terser";

export function styles() {
  return compileStyles()
    .pipe(cleanCss())
    .pipe(gulp.dest(distPath("styles")));
}

export function scripts() {
  return gulp
    .src(`${paths.build}/**/*.js`, { base: paths.build })
    .pipe(gulpIf(isProduction, terser()))
    .pipe(gulp.dest(distPath("scripts")));
}
```

> 资源型任务的组合顺序由产物依赖决定：脚本打包产物先存在，scripts 任务才有输入。

**速记**：按资源类型分组、组内按阶段细分，资源组之间只通过产物目录交接。



#### 按阶段拆分任务

**阶段型任务**：是把同一批资源在不同处理阶段上的动作分开，使编译、优化与产出各自独立的划分方式。

- 阶段划分：编译、优化、产出三类，开发期通常只跑到编译。
- 中间落盘：阶段之间用中间目录交接，便于单看某一阶段的输出。
- 开关接入：优化阶段的步骤按环境开关启用，开发期整体跳过。
- 调试收益：产物异常时可以只重跑某一阶段，快速缩小范围。
- 成本提醒：阶段越多中间文件越多，磁盘占用与清理成本同步上升。

```js
export const compile = gulp.series(compileStyles, compileTemplates);
export const optimize = gulp.parallel(minifyStyles, minifyMarkup);
export const produce = gulp.series(collectBundles, copyAssets);
```

> 串行与并行组合的语义与返回值约定见本主题第 52 篇 Gulp 任务编排与依赖，此处只做阶段划分。

**速记**：同一批资源按编译、优化、产出三段拆开，段间用中间目录交接，开发期只跑到编译。



#### 任务的串并行组合

**任务组合**：是用串行与并行两种组合函数把资源型与阶段型任务装配成完整链路的方式。

- 串行使用：存在产物依赖的步骤之间串行，前一步完成后才能开始。
- 并行使用：互不依赖的资源组并行，缩短整体构建时间。
- 组合嵌套：阶段内部可以再组合，形成「阶段串行、阶段内并行」的结构。
- 默认任务：默认任务指向完整构建，供命令行直接调用。
- 私有任务：内部编排函数不导出，避免出现在任务清单里。

```js
const buildAll = gulp.series(cleanDist, compile, gulp.parallel(optimize, produce));

export default buildAll;
```

> [!NOTE]
> **提醒内容**：只有被导出的函数才会注册为任务，编排用的内部函数留在模块作用域即可，不必导出。

**速记**：有依赖的串行、无依赖的并行，默认任务指向完整构建，编排函数不导出。



### 开发流水线

开发链路的诉求是改完立刻看到结果。本节组织本地服务、监听与开发期的错误容忍。

#### 本地服务与自动刷新

**本地服务**：是把产物目录作为站点根对外提供访问、并在文件变化后通知浏览器刷新的开发期能力。

- 服务根目录：指向发布产物目录，保证看到的就是构建结果。
- 刷新时机：在写出步骤完成后触发，避免刷新到半成品。
- 端口与代理：端口固定便于记忆，接口请求通过代理转发到后端服务。
- 与监听的关系：监听负责触发构建，服务只负责展示与刷新。
- 生产校验：开发服务器正常不代表发布产物可用，交付前仍需跑一次完整构建。

```js
import browserSync from "browser-sync";

const server = browserSync.create();

export function serve() {
  server.init({ server: paths.dist, port: 3000, open: false });
}

export function reload(done) {
  server.reload();
  done();
}
```

> [!IMPORTANT]
> **重要内容**：服务根目录必须指向发布产物目录，指向源目录会让开发期看到的页面与线上产物不是同一份。

**速记**：服务指向产物目录、写出完成后再刷新，端口与代理固定，交付前仍要跑完整构建。



#### 监听任务的组织

**监听组织**：是把源目录按资源类型分组监听、每组变化触发对应任务重跑的安排。

- 分组监听：样式变化只重跑样式链路，避免全量重建。
- 串联刷新：构建任务与刷新任务串行组合，保证刷新发生在写出之后。
- 触发合并：连续保存会触发多次构建，必要时加入延迟合并处理。
- 新增文件：监听通配符覆盖到目录层级，新增文件才能被捕获。
- 循环规避：监听范围不得包含产物目录，否则写出会再次触发构建。

```js
export function watchFiles() {
  gulp.watch(`${paths.styles}/**/*.scss`, gulp.series(styles, reload));
  gulp.watch(`${paths.templates}/**/*`, gulp.series(compileTemplates, reload));
  gulp.watch(`${paths.assets}/**/*`, gulp.series(copyAssets, reload));
}

export const dev = gulp.series(compile, gulp.parallel(watchFiles, serve));
```

> 监听与增量处理的完整写法见本主题第 50 篇 Gulp 的增量构建与监听，此处只做分组与刷新串联。

**速记**：按资源分组监听、构建与刷新串行，产物目录必须排除在监听范围之外。



#### 开发期的错误容忍

**错误容忍**：是开发期让报错不中断监听进程、只提示并等待下次改动的处理方式。

- 拦截位置：错误拦截步骤放在各管道起始处，覆盖其后的全部步骤。
- 提示方式：终端输出错误摘要并保留完整堆栈，必要时追加系统通知。
- 生产差异：生产构建不启用容忍，任何错误都应导致非零退出码。
- 刷新抑制：构建失败时不触发浏览器刷新，避免页面停在空白状态。
- 收敛写法：把错误处理抽成共用函数，各管道统一引用。

```js
import plumber from "gulp-plumber";

function guardStyles() {
  return plumber({
    errorHandler(error) {
      console.error(`样式处理失败：${error.message}`);
      this.emit("end");
    },
  });
}

export function stylesSafely() {
  return gulp
    .src(`${paths.styles}/**/*.scss`, { base: paths.styles })
    .pipe(guardStyles())
    .pipe(compileSass())
    .pipe(gulp.dest(distPath("styles")));
}
```

> 错误处理的完整策略见本主题第 51 篇 Gulp 的错误处理与任务健壮性，此处只落一条：开发容忍、生产不容忍。

**速记**：开发期拦截报错并抑制刷新，生产期不拦截，错误处理抽成共用函数。



### 生产流水线

生产链路的诉求是可复现、可缓存、可核对。本节组织清理、编译与优化的串联，以及指纹与引用改写。

#### 清理与全量构建

**全量构建**：是先清空产物目录、再从零执行全部步骤的构建方式，用于发布链路。

- 清理范围：产物目录整体删除后重建，保证不残留上一次的旧文件。
- 中间目录：是否一并删除按是否需要复用中间结果决定。
- 执行顺序：清理作为整条流水线的第一个任务，与其他任务串行。
- 缓存处理：发布构建不使用增量缓存，避免陈旧产物进入发布包。
- 可复现性：同一份源码在干净目录下重复构建，产物清单应完全一致。

```js
import { rm } from "node:fs/promises";

export async function cleanDist() {
  await rm(paths.dist, { recursive: true, force: true });
  await rm(paths.build, { recursive: true, force: true });
}
```

> 清理放在流水线最前，是保证产物可复现的最低成本手段，比事后比对文件清单更可靠。

**速记**：发布构建先整体清理产物与中间目录，不启用缓存，重复构建应得到相同清单。



#### 编译与优化串联

**生产串联**：是把编译、优化与产出三个阶段按依赖顺序串起来、并开启全部优化开关的链路。

- 顺序：清理、编译、优化、产出依次串行，产出依赖优化的结果。
- 开关：压缩、注释剥离与资源优化按环境开关统一启用。
- 映射：是否产出 source map 按排错需要决定，产出时注意源码暴露边界。
- 失败即停：任一步骤失败立即终止，不做部分产出。
- 中间校验：阶段之间可插入轻量检查，尽早暴露空文件等问题。

```js
export const production = gulp.series(
  cleanDist,
  gulp.parallel(styles, compileTemplates, collectBundles),
  gulp.parallel(minifyStyles, minifyMarkup, copyAssets),
  gulp.parallel(hashStaticAssets, rewritePageReferences)
);
```

> [!CAUTION]
> **注意内容**：把优化步骤与编译步骤并行，会让压缩作用于尚未编译完的文件，阶段之间只要有产物依赖就必须串行。

**速记**：清理、编译、优化、产出依次串行，优化开关按环境启用，任一步失败立即终止。



#### 指纹与产物引用改写

**指纹改写**：是给产物文件名加入内容哈希、并把页面中对它的引用同步替换的处理。

- 加哈希：只对需要长期缓存的脚本与样式加哈希，页面文件按需处理。
- 清单产出：加哈希时同时产出映射清单，记录原文件名与哈希文件名的对应关系。
- 引用替换：按清单替换页面中的引用地址，覆盖脚本与样式两类。
- 顺序约束：改写必须晚于加哈希与页面编译，两者都产出后才能执行。
- 核对方法：在产物页面中检索原始文件名，确认没有遗漏的旧引用。

```js
// 指纹与引用改写的任务顺序：先产出哈希文件与清单，再改写页面引用，收尾核对
export const fingerprintProduction = gulp.series(
  hashStaticAssets,
  rewritePageReferences,
  verifyFingerprints
);
```

> 指纹的价值在于让缓存失效由文件名承担，因此产物引用必须与文件名同时更新，缺一即出现取不到资源的问题。

**速记**：加哈希的同时产出映射清单，改写晚于加哈希与页面编译，收尾核对无旧引用。



### 清理、校验与发布

本节收在交付动作上：清理哪些目录、校验哪些结果、发布前逐条确认什么。

#### 产物清理与保留策略

**保留策略**：是明确哪些产物目录可以在每次构建前删除、哪些内容需要保留的约定。

- 可删目录：发布产物与中间产物，每次构建整体重建。
- 需保留项：手工维护的站点文件与第三方静态文件，不纳入自动清理。
- 清理时机：发布构建前清理一次，开发期不清理以免频繁重建。
- 白名单写法：保留项集中写成清单，清理任务按清单排除。
- 兜底检查：清理后确认保留项仍在，避免误删导致发布缺文件。

```js
import path from "node:path";
import { rm, mkdir, copyFile } from "node:fs/promises";

const keptFiles = ["robots.txt", "favicon.ico"];

export async function cleanDist() {
  await rm(paths.dist, { recursive: true, force: true });
  await mkdir(paths.dist, { recursive: true });
  await Promise.all(
    keptFiles.map((file) =>
      copyFile(path.join(paths.src, "public", file), path.join(paths.dist, file))
    )
  );
}
```

> [!NOTE]
> **提醒内容**：保留清单必须与清理任务写在同一处，分散在两处时容易在改动中脱节，导致发布缺文件。

**速记**：产物与中间目录整体重建，保留项写成清单并在清理后校验仍在。



#### 构建结果校验

**构建校验**：是用脚本核对产物清单、文件大小与页面引用是否与预期一致的一道收尾工序。

- 清单核对：按预期清单逐项确认文件存在，缺少即失败。
- 空文件检查：统计产物大小，零字节文件视为失败。
- 引用检查：在页面中检索引用地址，确认目标文件在产物中存在。
- 关键页检查：对首页与主要栏目页各抽查一次，确认关键资源引用完整。
- 失败处理：任一项不通过就让任务以非零退出码结束，阻断后续发布动作。

```js
import path from "node:path";
import { readdir, stat } from "node:fs/promises";

async function collectFiles(dir) {
  const entries = await readdir(dir, { withFileTypes: true });
  const nested = await Promise.all(
    entries.map((entry) => {
      const full = path.join(dir, entry.name);
      return entry.isDirectory() ? collectFiles(full) : [full];
    })
  );
  return nested.flat();
}

export async function verifyArtifacts() {
  const empties = [];
  for (const file of await collectFiles(paths.dist)) {
    const info = await stat(file);
    if (info.size === 0) empties.push(file);
  }
  if (empties.length > 0) throw new Error(`产物中存在空文件：${empties.join(", ")}`);
}
```

> 校验放在构建末尾而不是发布流程里，问题才能在离开本机之前被发现。

**速记**：校验清单、空文件与引用三项，任一项不通过就让任务以非零码退出。



#### 发布前检查清单

**发布检查**：是发布动作之前必须逐项确认的固定条目，覆盖产物、配置、文档与记录四个方面。

- 产物项：清单完整、无空文件、引用无旧地址，三项校验任务全部通过。
- 配置项：环境开关为生产值，浏览器范围与目标环境一致。
- 文档项：构建命令、产物目录与保留文件写进项目说明并已同步。
- 记录项：记录本次构建的产物清单与耗时，便于下次比对。
