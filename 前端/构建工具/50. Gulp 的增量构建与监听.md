## Gulp 的增量构建与监听

### watch 的用法

监听（watch）让构建在源文件变化后自动重跑，是开发期流水线的入口。本节说明监听的参数、事件绑定与任务引用方式。

#### 监听路径与任务

**监听（watch）**：是 Gulp 提供的文件系统监听接口，接收一组路径模式与一个处理函数，路径下的文件发生变化时自动执行该函数。

- 参数构成：第一个参数是路径模式或路径模式数组，第二个参数是变更后执行的任务函数。
- 返回值：返回监听器对象，可继续绑定事件，也可调用关闭方法停止监听。
- 路径范围：模式语法与 gulp.src 一致，通配符与排除写法都可直接复用。
- 处理函数：必须返回流（stream）或 Promise，否则 Gulp 无法判断处理何时结束。

```js
const { src, dest, watch } = require('gulp');
const compileSass = require('样式编译插件');

function watchStyle() {
  watch('src/styles/**/*.scss', function rebuildStyle() {
    return src('src/styles/**/*.scss')
      .pipe(compileSass())
      .pipe(dest('dist/styles'));
  });
}

exports.watchStyle = watchStyle;
```

> 监听任务本身不需要返回值，保持进程存活的是监听器，它与任务何时完成互不相关。

**速记**：监听接收路径模式与任务函数，任务函数用流或 Promise 表达处理结束。



#### 监听变更事件

**变更事件**：是监听器在文件新增、修改、删除时派发的通知，分别是 add、change 与 unlink 三类，可分别绑定处理逻辑。

- add 事件：路径匹配范围内出现新文件时派发。
- change 事件：已有文件的内容被改写时派发。
- unlink 事件：文件被删除时派发，此时文件已经不在磁盘上。
- 绑定方式：监听器对象的 on 方法接收事件名与处理函数，处理函数拿到被变更文件的路径。

```js
const { watch } = require('gulp');

function watchTemplate() {
  watch('src/pages/**/*.tpl')
    .on('add', function reportNewPage(filePath) {
      console.log('新增页面：' + filePath);
    })
    .on('unlink', function reportRemovedPage(filePath) {
      console.log('删除页面：' + filePath);
    });
}

exports.watchTemplate = watchTemplate;
```

> 不绑定事件时，传入的任务函数对三类事件都会执行；文件被删除时不能再去读取该文件。

**速记**：add、change、unlink 三类事件可分别绑定，默认任务函数对三类都执行。



#### 在监听中执行任务

**监听任务**：是把处理函数写成对已有任务的调用、让一次变更触发完整流水线的用法，处理函数既可以是单个任务，也可以是任务组合。

- 直接引用：把已导出的任务函数传给 watch，变更时执行该任务。
- 组合执行：多步处理时传入任务组合函数的结果，组合语义见本主题第 52 篇。
- 首次全量：注册监听不会执行任务，启动监听前应单独跑一次全量构建。
- 循环风险：监听范围包含写出目录时，写出动作会再次触发监听。

```js
const { src, dest, watch } = require('gulp');
const compileScript = require('脚本转译插件');

function rebuildScript() {
  return src('src/scripts/**/*.ts')
    .pipe(compileScript())
    .pipe(dest('dist/scripts'));
}

function watchScript() {
  watch('src/scripts/**/*.ts', rebuildScript);
}

exports.watchScript = watchScript;
```

> [!CAUTION]
> **注意内容**：监听路径指向源码目录时，写出目录必须落在监听范围之外，否则产物写入会再次触发任务并形成循环。

**速记**：变更触发的是被传入的任务函数，注册监听不会代替首次全量构建。



### 变更检测与过滤

一次变更往往只涉及少量文件，把处理范围收敛到真正变化的文件是监听场景下最直接的提速手段。

#### 只处理变更文件

**变更文件**：是本次触发中内容实际发生变化的文件，既可来自监听事件回调给出的路径，也可通过对读入的源文件加筛选条件得到。

- 事件来源：回调参数给出触发本次事件的文件路径，可只处理这一个文件。
- 流内筛选：以筛选条件读入文件，使后续管道只接收符合条件的文件。
- 收益：只处理变更文件能显著缩短监听场景下的单次响应时间。
- 风险：跳过未变更文件后，依赖这些文件的产物不会自动重建。

```js
const { src, dest } = require('gulp');
const compileSass = require('样式编译插件');

function compileOneStyle(filePath) {
  return src(filePath, { base: 'src/styles' })
    .pipe(compileSass())
    .pipe(dest('dist/styles'));
}

exports.compileOneStyle = compileOneStyle;
```

> 一次路径匹配会把结果合并成同一个流，无法区分具体是哪个文件变化，需要精确处理时改用事件回调的参数。

**速记**：用事件回调给出的路径精确处理单个文件，是最省时的变更收敛方式。



#### 按路径过滤

**路径过滤**：是在模式中用排除写法剔除不需要处理的目录与文件，使监听与读取都只覆盖目标范围。

- 排除写法：模式前加感叹号表示排除，可与其他模式并列成数组。
- 常见排除：依赖目录、构建输出目录、编辑器产生的临时文件。
- 目录尾斜杠：以斜杠结尾的模式只匹配目录，避免匹配到同名文件。
- 双重作用：同一组模式同时用于读取与监听，可保证两侧范围一致。

```js
const { src, dest } = require('gulp');
const compileScript = require('脚本转译插件');

const scriptPattern = ['src/scripts/**/*.ts', '!src/scripts/**/*.test.ts'];

function rebuildScript() {
  return src(scriptPattern)
    .pipe(compileScript())
    .pipe(dest('dist/scripts'));
}

exports.rebuildScript = rebuildScript;
```

> [!TIP]
> **建议内容**：把路径模式提取成常量并同时交给 gulp.src 与 gulp.watch，可避免两处写法不一致导致监听范围与读取范围不同。

**速记**：排除模式以感叹号开头、数组中顺序无关，模式常量在两处复用最稳妥。



#### 忽略目录与临时文件

**忽略规则**：是把不会影响产物的文件类型排除在监听之外的约定，典型对象是编辑器交换文件与版本控制元数据目录。

- 常见对象：编辑器临时文件、版本控制元数据目录、系统隐藏文件。
- 排除写法：按文件名前缀或后缀写模式，如以点开头的文件或带临时后缀的文件。
- 影响面：被忽略的文件发生变化时不触发任何任务，也不会出现在日志中。
- 配置位置：忽略规则通常集中在一处，临时去掉某条规则即可确认变更是否被过滤。

```js
const { watch } = require('gulp');

const ignorePattern = ['!**/.git/**', '!**/*.swp', '!**/*~'];

function watchSource() {
  watch(['src/**/*'].concat(ignorePattern), function reportChange(filePath) {
    console.log('源文件变化：' + filePath);
  });
}

exports.watchSource = watchSource;
```

> 忽略规则写错会让变更被静默丢弃，监听中出现的异常优先从监听范围开始核对。

**速记**：临时文件与版本控制目录一律排除，规则集中书写便于统一调整。



### 增量任务的实现

增量构建（incremental build）的核心是让任务只处理上一次运行之后发生变化的文件，Gulp 通过记录任务时间与流筛选两个手段实现。

#### 用 lastRun 记录上次时间

**lastRun**：是 Gulp 提供的接口，接收任务函数的引用并返回该任务上一次成功完成时的时间戳，作为筛选未变更文件的基准时刻。

- 语义：只在任务成功完成时推进，任务中途失败不会更新基准时间。
- 首次运行：此前没有记录时返回空值，筛选条件需容错为全量处理。
- 命名一致：名称必须与任务注册时一致，否则取不到对应的记录。
- 存储差异：记录默认保存在进程内存中，跨进程复用需改用落盘的缓存插件。

```js
const gulp = require('gulp');
const compileSass = require('样式编译插件');

function compileStyle() {
  return gulp.src('src/styles/**/*.scss', { since: gulp.lastRun(compileStyle) })
    .pipe(compileSass())
    .pipe(gulp.dest('dist/styles'));
}

exports.compileStyle = compileStyle;
```

> 不同 Gulp 主版本中该接口的引入方式略有差异，使用时以所在版本文档为准。

**速记**：lastRun 给出上次成功完成的时间戳，作为筛选条件的基准时刻。



#### 用 since 跳过未变文件

**since**：是 gulp.src 的选项，接收一个时间戳或返回时间戳的函数，只保留修改时间晚于该时刻的文件。

- 取值形式：直接传时间戳，或传入函数在创建流时求值，后者可延迟到任务执行时才取。
- 比较依据：按文件在磁盘上的修改时间比较，不比较内容摘要。
- 与写出的关系：被跳过的文件不会进入流，自然也不会被写出。
- 边界说明：通用缓存原理与优化清单见本主题第 15 篇，本节只讲筛选用法。

```js
const gulp = require('gulp');
const compileScript = require('脚本转译插件');

function buildScript() {
  return gulp.src('src/scripts/**/*.ts', { since: gulp.lastRun(buildScript) })
    .pipe(compileScript())
    .pipe(gulp.dest('dist/scripts'));
}

exports.buildScript = buildScript;
```

> [!WARNING]
> **警告内容**：被跳过的文件不会重新写入产物目录，删除产物目录后直接执行增量任务会得到不完整的产物。

**速记**：since 按修改时间筛选，跳过的文件既不进入流也不写出。



#### 内容比较与时间戳比较

**时间戳比较**：是依据文件修改时间判断是否需要重新处理的做法；**内容比较**：是依据文件内容摘要判断是否需要重新处理的做法，两者在准确性与开销上取舍不同。

- 时间戳优点：只需读取文件系统元数据，成本极低。
- 时间戳缺陷：检出代码、复制文件、切换分支都会刷新修改时间，导致误判为已变更。
- 内容比较取舍：不受元数据变化影响，判断更准确，但需要读取内容并计算摘要，文件多时开销不可忽略。
- 选择依据：本地开发用时间戳足够，产物需要严格可复现时改用内容比较。

```js
const crypto = require('crypto');
const fs = require('fs');

function readContentDigest(filePath) {
  const content = fs.readFileSync(filePath);
  return crypto.createHash('sha1').update(content).digest('hex');
}
```

> 时间戳比较追求快，内容比较追求准，同一项目里可以按资源类型分别选择。

**速记**：时间戳快但会被检出与复制动作干扰，内容比较准但要付出读取与计算的代价。



### 缓存与失效

缓存让重复构建省去未变更文件的处理，代价是一旦记录与真实状态不符，产物就会停留在旧版本。本节只讨论 Gulp 场景下的记录与失效。

#### 缓存的目的与位置

**任务缓存**：是把上一次运行处理过的文件信息保存下来、供后续运行判断是否可以跳过的机制，表现为记录文件与时间戳或内容摘要的对应关系。

- 目的：减少重复读取与编译，缩短监听场景下的单次响应时间。
- 位置：记录写入项目内的固定目录，或保存在进程内存中。
- 生命周期：落盘的记录与进程是否重启无关，内存记录则随进程结束而清空。
- 边界说明：通用缓存策略与优化清单见本主题第 15 篇，本节只讲 Gulp 侧的记录与失效。

```js
const gulp = require('gulp');
const buildCache = require('缓存插件');
const compileSass = require('样式编译插件');

function compileStyle() {
  return gulp.src('src/styles/**/*.scss', { since: buildCache.lastRun('compileStyle') })
    .pipe(compileSass())
    .pipe(gulp.dest('dist/styles'));
}

exports.compileStyle = compileStyle;
```

> 缓存本身不校验产物是否正确，它只回答「这个文件上次处理过没有」这一个问题。

**速记**：缓存记录文件的上次处理状态，作用是把未变更文件排除在本次处理之外。



#### 何时必须让缓存失效

**缓存失效**：是主动让记录不再被采用、使后续运行回到全量处理的动作，触发条件是产物结果会随配置而非文件内容改变。

- 配置变更：编译器选项、目标环境、压缩参数被修改时必须失效。
- 依赖变更：链路中被引用的公共文件被修改时必须失效。
- 记录损坏：记录与磁盘真实状态不一致时，继续跳过会产出缺失的产物。
- 常规做法：只删除记录目录并重跑，不动源码，代价是一次可接受的全量构建。

```bash
rm -rf .cache/build
# 删除缓存记录目录（实际路径以所用缓存插件的约定为准）
npm run build
# 重新执行构建，本次回到全量处理
```

> [!CAUTION]
> **注意内容**：缓存失效必须删除记录后再跑全量，只重跑增量任务无法补回此前被跳过的文件。

**速记**：配置、依赖、工具版本变化或记录损坏都必须先失效，再跑一次全量构建。



#### 失效后的全量重建

**全量重建**：是清空记录并从全部源文件重新生成产物的过程，用于在缓存失效后恢复产物与源码的一致状态。

- 触发时机：记录被删除、项目首次检出、产物目录被清理之后。
- 执行方式：去掉筛选条件或删除记录后执行同一任务即可。
- 顺序要求：全量重建应先清理输出目录再写入，避免旧文件残留。
- 校验方式：比对产物条目与源文件清单，确认没有缺失。

```js
const { src, dest } = require('gulp');
const compileSass = require('样式编译插件');

// 不传 since 选项即读取全部源文件，等价于一次全量重建
function rebuildAllStyle() {
  return src('src/styles/**/*.scss')
    .pipe(compileSass())
    .pipe(dest('dist/styles'));
}

exports.rebuildAllStyle = rebuildAllStyle;
```

> 全量重建比增量慢属于正常现象，判断本次是否走了全量，看耗时与文件数量是否同时上升即可。

**速记**：全量重建先去筛选条件再写产物，产物条目应与源文件清单一一对应。



### 监听场景的常见问题

监听长期运行，问题往往在启动数小时之后才暴露。本节列出新增文件不触发、频繁重复触发与写回循环三类高频现象。

#### 新增文件不触发

**新增文件不触发**：是新建文件没有引起任务执行的监听异常，成因通常是文件不在监听模式覆盖范围内或被忽略规则排除。

- 模式不匹配：新建文件所在目录或扩展名不在监听模式之中，单层通配符也匹配不到深层文件。
- 忽略规则：模式被排除项覆盖，变更被静默丢弃。
- 编辑器行为：部分编辑器先写临时文件再原子替换，事件会被识别成新增而非修改。
- 排查方式：把监听范围临时收窄到目标文件，确认事件是否派发。

```js
const { src, dest } = require('gulp');
const compileSass = require('样式编译插件');

function rebuildStyle() {
  return src(['src/styles/**/*.scss', '!src/styles/**/_*.scss'])
    .pipe(compileSass())
    .pipe(dest('dist/styles'));
}

exports.rebuildStyle = rebuildStyle;
```

> [!NOTE]
> **提醒内容**：新增文件只有在监听模式覆盖范围内才会触发，出现漏触发时先核对模式层级与忽略规则两处。

**速记**：新增不触发先查模式覆盖范围、忽略规则与通配符层级三处。



#### 监听风暴与重复触发

**监听风暴**：是短时间内大量变更事件连续触发任务、使任务重复执行并相互叠加的现象。

- 成因：一次操作改写大量文件，或任务自身写出的文件再次触发监听。
- 表现：任务被反复执行，控制台连续滚动，产物写入相互覆盖。
- 合并手段：为处理函数加去重与延迟，把短时间内的多次触发合并成一次。
- 排除手段：把输出目录排除在监听之外，从源头减少触发次数。

```js
const { src, dest, watch } = require('gulp');
const compileSass = require('样式编译插件');
let pendingTimer = null;

function rebuildStyle() {
  return src(['src/styles/**/*.scss', '!dist/**']).pipe(compileSass()).pipe(dest('dist/styles'));
}

function scheduleRebuild(done) {
  clearTimeout(pendingTimer);
  pendingTimer = setTimeout(rebuildStyle, 300);
  done();
}

watch('src/styles/**/*.scss', scheduleRebuild);
```

> [!WARNING]
> **警告内容**：监听范围包含输出目录会让每次写出都触发新一轮构建，短时间内反复叠加，最终拖慢整个开发环境。

**速记**：风暴的两个源头是大批量改写与输出目录被监听，合并触发并排除输出目录即可缓解。



#### 写回循环

**写回循环**：是任务写出的文件落在监听范围内、又被监听捕获并再次触发同一任务的现象，表现为构建永不停止。

- 判断特征：控制台日志持续输出，任务被反复触发却没有新的源码改动。
- 根本原因：监听模式与输出目录存在重叠。
- 处理方式：把输出目录加入排除模式，或把源码与产物分到不同父目录。
- 间接循环：任务在写出过程中读取了同目录下的产物文件，也会形成依赖回环。

```js
const { src, dest } = require('gulp');
const compileScript = require('脚本转译插件');

const scriptPattern = ['src/scripts/**/*.ts', '!dist/**/*'];

function rebuildScript() {
  return src(scriptPattern)
    .pipe(compileScript())
    .pipe(dest('dist/scripts'));
}

exports.rebuildScript = rebuildScript;
```

> 源码目录与产物目录分离是避免写回循环最直接的结构性手段，比逐条添加排除规则更可靠。

**速记**：写回循环源于监听范围与写出目录重叠，分离目录结构即可根治。
