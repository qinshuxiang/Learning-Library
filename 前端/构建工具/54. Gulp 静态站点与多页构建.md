## Gulp 静态站点与多页构建

静态站点与多页应用的构建是 Gulp 的主场：页面由模板与数据批量生成，资源按流水线加工，产物按目录发布。本篇讲模板与数据的合并、多页面与多语言的组织、构建期指纹与引用替换、页面处理，以及发布产物的组织；文件流的读写见本主题第 48 篇，任务编排见第 52 篇。

### 页面模板与数据注入

页面任务的输入是模板与数据两份材料，输出是完整的页面文件。本节说明模板如何在管道中编译、数据按哪几层组织，以及合并产物如何落到正确路径。

#### 模板引擎的接入方式

**模板引擎接入**：是在 Gulp 管道里增加一个转换步骤、把模板文件与数据合并编译成页面文本的做法。

- 数据传入：编译步骤内接收数据上下文，源模板只保留结构与占位标记。
- 输出改名：模板扩展名在写出前改为页面扩展名，源与产物扩展名分离。
- 布局支持：引擎支持布局或包含时，把公共部分抽成可复用片段。
- 失败处理：模板编译错误应让任务失败并指出模板路径，见本主题第 51 篇。

```js
const { Transform } = require("node:stream");

// renderPage 由所选模板引擎封装：接收模板文本与数据，返回页面文本
function compilePages(siteData) {
  return new Transform({
    objectMode: true,
    transform(file, encoding, callback) {
      if (file.isBuffer()) {
        const text = file.contents.toString();
        file.contents = Buffer.from(renderPage(text, siteData));
      }
      callback(null, file);
    },
  });
}
```

> 模板编译只应发生在一个转换步骤内，数据与模板的合并若散落在多个中转步骤里，排错时需要逐段还原上下文。

**速记**：模板在管道内的单个转换步骤里与数据合并成页面文本，源模板只保留结构与占位。



#### 数据源的组织

**站点数据**：是页面渲染所需的变量集合，按站点级、页面级与集合三个层次组织并在编译前统一加载。

- 站点级数据：站点名、域名、导航与版权等所有页面共用的字段。
- 页面级数据：标题、描述与结构化字段，写在页面的前言区或同名数据文件里。
- 集合数据：文章、产品这类列表由数据文件或目录扫描汇总得到。
- 加载时机：数据在任务启动时一次性读入，避免每个文件重复读盘。
- 观察范围：数据变化需要重新构建，开发期应把数据目录纳入监听。

```json
{
  "site": {
    "name": "示例站点",
    "nav": [
      { "label": "首页", "href": "/" }
    ]
  }
}
```

> 数据文件的改动不会改变模板文件的时间戳，开发期若只监听模板目录，改完数据页面不会更新。

**速记**：数据按站点级、页面级与集合三类组织，启动时一次性加载，开发期一并监听。



#### 模板与数据的合并产物

**合并产物**：是模板与数据编译后写出的完整页面文件，其产物路径由源模板路径推导而来。

- 路径推导：源模板的相对目录结构在产物中保持，扩展名替换为页面扩展名。
- 命名约定：目录首页使用固定文件名，使访问路径可以省略文件名。
- 内容完整：编译后的页面已是完整文本，不依赖运行时拼接。
- 后续步骤：压缩、引用替换与注入都在编译之后执行。
- 校验点：搜索产物中是否有未渲染的占位标记残留，确认数据全部注入。

```js
function buildPages() {
  return src("src/pages/**/*.njk")
    .pipe(rename({ extname: ".html" })) // 重命名能力由所选插件提供
    .pipe(compilePages(siteData))
    .pipe(dest("dist"));
}
```

> [!NOTE]
> **提醒内容**：扩展名替换放在编译之前还是之后，取决于模板引擎是否按扩展名选择语法，顺序写反会让模板被当作纯文本输出，产物中到处都是占位标记。

**速记**：源模板目录结构在产物中保持，扩展名替换为页面扩展名，压缩与替换排在其后。



### 多页面与多语言

页面数量上升后，逐页登记入口不再可行。本节说明如何用目录结构驱动生成、如何按语言维度组织，以及如何从产物反推出页面清单。

#### 按目录生成页面

**目录驱动生成**：是以源目录结构直接决定产物页面路径、不需要逐页登记入口的生成方式。

- 路径映射：目录层级原样映射到产物，页面之间的相对链接因此稳定。
- 索引约定：目录下的固定文件名对应目录首页，访问时可以不写文件名。
- 通配读取：用通配模式一次读入整棵目录，新增页面不需要改任务。
- 页面清单：生成后扫描产物目录得到清单，用于校验与站点地图。
- 冲突规则：同一目录出现同名模板时按扩展名优先级决定取舍，规则需固定。

```text
src/pages/index.njk        ->  dist/index.html
src/pages/about/index.njk  ->  dist/about/index.html
src/pages/docs/guide.njk   ->  dist/docs/guide.html
```

> 基准目录决定相对路径的起点，缺省时通配符之前的部分被当作基准，产物里会多出一层目录，见本主题第 48 篇。

**速记**：通配读取整棵源目录，目录结构原样映射为页面路径，新增页面不需要改任务。



#### 语言维度组织

**多语言组织**：是把同一页面在不同语言下的模板与数据分开存放、产物按语言分目录输出的组织方式。

- 目录方案：按语言代码划分源目录，各语言一个并列子树。
- 数据方案：站点数据按语言分文件，加载时与公共数据合并成各自上下文。
- 产物方案：每种语言产出一个子目录，共享资源统一放在公共资源目录。
- 复用方案：差异小的语言可用共享布局加语言覆盖数据，避免整份复制模板。

```js
const { src, dest, parallel } = require("gulp");
// makeLocaleTask 为每种语言产出一份页面任务，loadLocaleData 读取该语言的数据
function makeLocaleTask(locale) {
  const root = "src/locales/" + locale;
  return () =>
    src(root + "/**/*.njk", { base: root })
      .pipe(rename({ extname: ".html" }))
      .pipe(compilePages(loadLocaleData(locale)))
      .pipe(dest("dist/" + locale));
}

exports.buildPages = parallel(makeLocaleTask("zh"), makeLocaleTask("en"));
```

> 语言维度与目录维度不要混在同一个通配模式里，混用会让基准目录的推导结果难以预期。

**速记**：按语言分目录存模板与数据，产物按语言分目录输出，共享资源单独放公共目录。



#### 页面清单与站点地图

**页面清单**：是构建后收集全部产出页面路径的结果，用于生成站点地图、校验链接与判断增量上传。

- 收集方式：构建后遍历产物目录中的页面文件，记录相对路径与更新时间。
- 站点地图：由清单生成，包含站点地图格式所需的路径与时间字段。
- 链接校验：按清单检查页面内链接的目标是否存在，发现断链。
- 增量上传：以清单为基准与线上清单比对，只上传新增与变化的文件。
- 顺序要求：清单在页面全部写完之后生成，通常作为构建线的最后一个阶段。

```js
const { series, parallel } = require("gulp");

exports.build = series(
  cleanDist,
  parallel(buildZhPages, buildEnPages, buildStyles, copyAssets),
  buildPageIndex,
  hashAndRewrite,
  verifyOutput
);
```

> [!IMPORTANT]
> **重要内容**：站点地图与页面清单必须从构建产物生成而不是手工维护，手工清单会在页面增删后与产物不一致，搜索爬取与增量上传都会读到过期结果。

**速记**：构建后遍历产物收集页面清单，用它生成站点地图、校验链接与判断增量上传。



### 资源指纹与缓存控制

指纹解决的是「内容变了但文件名没变」的问题，构建期的全部工作集中在改名与改写引用两处。服务端的缓存头配置属于另一侧，见 后端/Nginx 主题。

#### 生成带哈希的文件名

**资源指纹（fingerprint）**：是把文件内容的摘要写入文件名、使内容变化必然引起文件名变化的做法。

- 摘要来源：对文件内容计算摘要并截取固定长度，同一内容得到同一名字。
- 命名位置：摘要放在扩展名之前，主文件名与扩展名之间以点连接。
- 长度取舍：摘要越长冲突概率越低，常规站点取八位左右足够。
- 覆盖范围：脚本、样式、图片与字体都应加指纹，页面本身通常不加。

```js
const { Transform } = require("node:stream");
const { createHash } = require("node:crypto");
const path = require("node:path");

function applyFingerprint() {
  return new Transform({
    objectMode: true,
    transform(file, encoding, callback) {
      if (file.isBuffer()) {
        const digest = createHash("sha256").update(file.contents).digest("hex").slice(0, 8);
        const parsed = path.parse(file.path);
        // 命名规则：主文件名.摘要.扩展名
        file.path = path.join(parsed.dir, parsed.name + "." + digest + parsed.ext);
      }
      callback(null, file);
    },
  });
}

// src 到 dest 的写入沿用第 48 篇的写法，此处省略
```

> 指纹只负责让用户拿到新文件，缓存有效期与缓存头的设置属于服务端配置，见 后端/Nginx 主题。

**速记**：按文件内容计算摘要并写进文件名，脚本样式图片字体都要加，页面不加。



#### 引用替换

**引用替换**：是把页面与样式里指向原始文件名的引用改成带指纹的新名，使引用与产物保持一致。

- 数据来源：重命名步骤同步写出原始名到新名的映射表。
- 页面替换：扫描页面中的样式与脚本引用，按映射表改写。
- 样式内替换：样式文件里的图片与字体引用同样需要替换。
- 顺序要求：替换必须在重命名完成之后，映射表此时才完整。
- 兜底检查：替换后搜索未命中的原始名，确认没有漏改的引用。

```js
const { src, dest } = require("gulp");
const { Transform } = require("node:stream");
const { readFileSync } = require("node:fs");

function replaceReferences(mapping) {
  return new Transform({
    objectMode: true,
    transform(file, encoding, callback) {
      if (file.isBuffer()) {
        let text = file.contents.toString();
        for (const name of Object.keys(mapping)) {
          text = text.split(name).join(mapping[name]);
        }
        file.contents = Buffer.from(text);
      }
      callback(null, file);
    },
  });
}

function rewriteReferences() {
  const mapping = JSON.parse(readFileSync("dist/assets/fingerprint-map.json", "utf8"));
  return src(["dist/**/*.html", "dist/assets/**/*.css"])
    .pipe(replaceReferences(mapping))
    .pipe(dest("dist"));
}
```

> 映射表由重命名步骤一次写出，比在两个步骤之间传递内存变量更可靠：重启构建后仍能从产物目录复原。

**速记**：重命名时写出映射表，再按映射表改写页面与样式中的引用，改完搜索查漏。



#### 与页面和样式的配合

**配合方式**：是让页面、样式与资源三者的改名与替换按固定次序衔接、避免出现指向旧名引用的安排。

- 页面不加指纹：页面名保持稳定，外部链接与书签才长期有效。
- 样式先处理：样式文件内部的资源引用先替换，再对样式文件本身加指纹。
- 页面最后替换：页面对样式与脚本的引用在两者都定名之后再替换。
- 次序固定：资源改名、样式内替换、样式改名、页面替换构成固定次序。
- 版本兜底：入口样式可另存一份不带指纹的固定名，供外部站点引用。

```text
1. 优化资源内容
2. 重命名资源并写出映射表
3. 替换样式文件内部的资源引用
4. 计算并重命名样式文件本身
5. 替换页面中的样式与脚本引用
```

> [!CAUTION]
> **注意内容**：先给样式文件加指纹、再替换样式内部的图片引用，会让图片引用指向已被改名的旧路径，页面能打开但图片全部 404，因此这个次序不可调换。

**速记**：资源先定名、样式内替换后样式再定名、页面最后替换，这个次序不可调换。



### HTML 压缩与处理

页面文本的处理集中在上线前的最后一步。本节说明压缩、标记清理与输出风格一致性三件事。

#### 页面压缩

**页面压缩**：是去掉页面中的空白、注释与冗余属性、缩小传输体积的处理。

- 压缩范围：去除空白与注释、折叠布尔属性、压缩内联样式与脚本。
- 保真要求：压缩不得改变渲染结果，内联内容按各自语法单独处理。
- 与调试的关系：压缩后的页面难以直接阅读，开发期不压缩。
- 校验方式：压缩前后比对关键文本与结构，确认没有内容被误删。

```js
const { src, dest } = require("gulp");

function minifyPages() {
  return src("dist/**/*.html")
    .pipe(minifyHtml({ collapseWhitespace: true, removeComments: true }))
    .pipe(dest("dist"));
}

exports.build = series(hashAndRewrite, minifyPages);
```

> 压缩只改变页面文本，不改变页面里引用的资源名，因此放在引用替换之后执行即可，次序上不与指纹冲突。

**速记**：压缩去掉空白、注释与冗余属性，开发期不压缩，生产线上排在引用替换之后。



#### 注释与冗余标记处理

**标记清理**：是按条件移除页面中仅供特定环境使用的注释与冗余属性，减小体积并收窄暴露面。

- 条件注释：按目标环境保留或移除外围注释，避免调试标记发到线上。
- 调试标记：开发期的占位标记与调试属性在生产构建中移除。
- 冗余属性：空属性与默认值属性可安全移除，但需确认不影响页面脚本读取。
- 内联注释：内联脚本与样式中的注释按各自语法处理，避免破坏语法。
- 保留清单：需要在线上保留的注释应显式列入白名单。

```js
function minifyPages() {
  return src("dist/**/*.html")
    .pipe(minifyHtml({ collapseWhitespace: true, removeComments: true, ignoreCustomComments: [/^!/] }))
    .pipe(dest("dist"));
}
```

> [!WARNING]
> **警告内容**：注释清理的规则一旦过宽，可能把内联脚本或样式中的片段当作注释删除，页面结构仍在而行为异常，规则调整后必须在真实页面上验证交互。

**速记**：按环境清理条件注释与调试标记，白名单保留许可声明，规则调整后要验交互。



#### 输出风格一致性

**输出风格**：是让所有页面的标签写法、属性顺序与缩进保持一致、减少产物差异与维护成本的约定。

- 统一来源：页面结构由统一的布局与片段产出，避免各页手写不同写法。
- 标签闭合：成对标签与自闭合标签的写法在全站统一。
- 编码与换行：统一字符编码与换行符，避免跨平台产物差异。
- 校验方式：对产物做一次全量比对，确认只有内容差异没有风格差异。

```html
<!DOCTYPE html>
<html lang="zh-CN">
  <head>
    <meta charset="utf-8" />
    <title>示例页面</title>
    <link rel="stylesheet" href="/assets/app.4b7e0c91.css" />
  </head>
  <body>
    <script src="/assets/app.8f3a1c2d.js"></script>
  </body>
</html>
```

> 风格一致性不是美观问题：产物差异变小之后，构建产物之间的比对与缓存判断才可靠。

**速记**：结构由统一布局产出，闭合写法、属性顺序、编码与换行全站统一。



### 站点发布的产物组织

发布环节决定线上目录长什么样。本节说明目录结构、清理与增量上传，以及上传前的校验。

#### 产物目录结构

**产物目录**：是构建输出的层级划分，按「谁引用谁」与「是否加指纹」两条线组织。

- 根级页面：页面文件放产物根目录，文件名与访问路径直接对应。
- 带指纹资源：脚本、样式、图片与字体放资源子目录，全部带指纹。
- 固定名文件：与外部有约定的文件放根目录且不加指纹。
- 语言与分站：多语言或分站按顶层子目录划分，共享资源放公共目录。

```text
dist/
  index.html
  robots.txt
  sitemap.xml
  zh/
    index.html
  en/
    index.html
  assets/
    app.8f3a1c2d.js
    app.4b7e0c91.css
    images/
    fonts/
```

> 页面不加指纹、资源加指纹的组合，使页面链接可以长期不变，同时资源可以获得长期缓存。

**速记**：页面放根目录且不加指纹，资源放子目录且全部加指纹，约定类文件放根目录。



#### 清理与增量上传

**清理策略**：是发布前清空产物目录、上传时按差异只传变化文件的两段式安排。

- 本地清理：每次构建前清空产物目录，产物只由本次构建决定。
- 远端增量：上传前比对本地清单与线上清单，只上传新增与变化的文件。
- 删除处理：线上存在而本地没有的文件需要显式删除，否则旧资源长期残留。
- 顺序要求：清理只作用于本地产物目录，任何远端删除都要经过确认。

```bash
npx gulp build
# 生成完整产物
npx gulp deploy --dry-run
# 先输出将要上传与删除的清单，确认后再实际执行
```

> [!CAUTION]
> **注意内容**：远端删除若直接按本地清单做差集，一次误删的源文件就会连带删除线上页面，删除动作应先输出清单并人工确认后再执行。

**速记**：本地每次清理重建，远端按清单增量上传，删除动作先列清单再确认。



#### 发布前校验

**发布前校验**：是在产物上传之前检查页面完整性、引用有效性与必需文件是否齐备的一组检查。

- 必需文件：站点地图、robots、图标与验证文件按清单逐项确认存在。
- 引用有效：页面中的脚本、样式与图片引用在产物中都有对应文件。
- 页面完整：页面数量与页面清单一致，没有因编译失败而缺页。
- 内容检查：关键占位标记已全部被替换，没有未渲染的变量残留。
- 失败处置：校验不通过即中止发布并输出差异清单，不进入上传阶段。

```js
exports.build = series(
  cleanDist,
  parallel(buildZhPages, buildEnPages, buildStyles, copyAssets),
  series(hashAndRewrite, minifyPages),
  buildPageIndex,
  verifyOutput
);
```

> 校验步骤的价值在于把问题留在构建期：上传之后再发现断链，回滚成本远高于重新构建一次。
