## Rollup 的代码分割与多入口

### 多入口配置

代码分割（code splitting）是把产物拆成多个文件、让运行方按需加载的行为，多入口与动态导入是触发它的两个来源。本节说明入口如何声明、产物如何命名与落位。

#### 对象式入口的写法

**多入口（multiple entry）**：是在一次构建中声明多个入口模块、各自产出一份产物并共享公共模块的配置方式。

- 入口形式：input 可取单个路径、路径数组，或键为入口名、值为路径的对象。
- 对象形式：键即出口名，能一路带到产物文件名与共享块命名上，多入口优先用对象。
- 目录输出：多入口必须用 output.dir 指定输出目录，不能用 output.file 指定单个文件。
- 共享分析：Rollup 先合并全部入口的模块图，再决定哪些模块被两个以上入口共用。
- 构建目标：一次构建覆盖多个页面、多套接口或主包加工作线程的组合。

```js
// 两份入口产物共享同一份工具代码
export default defineConfig({
  input: {
    index: "src/index.ts",
    admin: "src/admin.ts",
  },
  output: { dir: "dist", format: "es" },
});
```

> 路径数组形式的入口不便于给产物命名，对象形式的键可以把入口名一路带到产物与共享块上。

**速记**：多入口优先用键值对象式 input，配合 output.dir 输出目录，Rollup 自动提取共用模块。



#### 入口产物的命名规则

**入口命名**：是 output 里的 entryFileNames 模板，决定入口产物文件名，模板中可用入口名与内容哈希等占位符。

- entryFileNames：作用于入口产物，模板中可用入口名占位符。
- chunkFileNames：作用于共享块与动态导入产生的块。
- assetFileNames：作用于样式与资源文件，命名方式同理。
- 默认模板：不指定时按字段默认值生成，多入口场景下名字辨识度低。
- 内容哈希：文件名带哈希可配合长期缓存，内容变化时文件名随之改变。

```js
output: {
  dir: "dist",
  format: "es",
  entryFileNames: "[name].[hash].js",
  chunkFileNames: "chunks/[name].[hash].js",
  assetFileNames: "assets/[name].[hash][extname]",
}
```

> 占位符名称与可用范围以所用 Rollup 版本的文档为准，模板中的目录前缀同时决定产物的目录结构。

**速记**：三类产物各有命名模板，入口、共享块与资源分别控制，带哈希文件名便于长期缓存。



#### 入口键与产物落点

**产物落点**：是入口产物在输出目录中的位置，由入口键的写法与输出选项共同决定。

- 平铺默认：所有入口产物默认平铺在输出目录下，源码的目录层级被压平。
- 键带路径：把键写成 pages/home 这类相对路径，产物即落到对应子目录。
- 唯一性：键必须唯一，否则会出现同名产物相互覆盖。
- 目录依赖：落点控制依赖 output.dir，单文件模式没有可用的目录层级。
- 核对：构建后比对源码入口清单与产物文件清单，确认一一对应。

```js
export default defineConfig({
  input: {
    "pages/home": "src/pages/home.ts",
    "pages/about": "src/pages/about.ts",
  },
  output: { dir: "dist", format: "es", entryFileNames: "[name].js" },
});
```

> 入口键与源码路径是两套独立信息，键改了就换了落点，重构时要同步检查引用产物的路径。

**速记**：入口键既定产物名也定落点，唯一且带路径的键可在输出目录中还原目录层级。



### 动态导入与分包

动态导入（dynamic import）是把模块的加载推迟到运行时的语法，Rollup 会为它单独产出一个块。本节说明这种块的形态、加载路径与内联取舍。

#### 动态导入的产物形态

**动态导入**：是以 import 函数形式在运行时加载模块的语法，Rollup 识别后把它拆成独立块而不并入入口产物。

- 语法形态：import 后紧接括号与路径，返回一个 Promise。
- 产物形态：目标模块被拆成单独文件，入口产物中只保留一段引用该文件的加载逻辑。
- 格式限制：只有 ESM 与 CommonJS 输出支持拆分，浏览器直引格式不支持。
- 静态可分析：路径为字面量时按字面量拆分，路径为变量时需要额外的转换插件。
- 命名来源：拆出的块按模块名或目录名生成，命名规则由 chunkFileNames 控制。

```js
// 入口产物只保留这段加载逻辑，编辑器模块被拆成独立文件
async function openEditor() {
  const { Editor } = await import("./editor.js");
  return new Editor();
}
```

> [!WARNING]
> **警告内容**：动态导入的块是产物的一部分，部署时要把整个输出目录一起上传，只传入口文件会在触发按需加载时报模块找不到。

**速记**：动态导入被拆成独立块，入口只保留加载逻辑，仅 ESM 与 CommonJS 输出支持。



#### 块文件的加载路径

**加载路径**：是产物中引用其他块时使用的地址，由产物之间的相对位置与工具侧的路径前缀共同决定。

- 相对引用：块与块之间默认以相对路径互相引用，整套产物整体部署即可工作。
- 前缀需求：把产物托管到子目录或内容分发网络时，需要给引用地址加统一前缀。
- 前缀来源：路径前缀通常由上层工具提供，Rollup 自身的输出选项不含该字段。
- 目录跟随：chunkFileNames 里写了子目录，引用地址会自动跟随该层级变化。
- 核对：构建后在产物中搜索动态引用语句，确认地址与实际文件位置一致。

```bash
grep -n "import(" dist/index.js
# 查看入口产物中保留的动态引用地址
```

> 引用地址错的产物在本地整目录打开时正常，换到带前缀的部署环境才失效，交付前要在真实路径下验证。

**速记**：块之间默认相对引用，托管到子目录时靠上层工具加统一前缀，交付前核对引用地址。



#### 内联动态导入的取舍

**内联动态导入**：是通过输出选项把动态导入的块并回入口产物、不再产出独立文件的处理方式。

- 选项语义：开启后动态导入退化为静态导入，代码集中到一个文件。
- 适用场景：产物需要以单文件分发，或运行环境不支持按需加载。
- 代价一：失去按需加载能力，首次加载体积增大。
- 代价二：多个入口同时内联会各自包含一份相同代码。
- 前提：该选项只对单一入口生效，多入口配置下无法使用。

```js
output: {
  dir: "dist",
  format: "es",
  inlineDynamicImports: true,
}
```

> [!NOTE]
> **提醒内容**：内联动态导入与多入口在配置上互斥，同时出现会直接报错，需要按分发方式二选一。

**速记**：内联动态导入把块并回入口换取单文件分发，代价是失去按需加载且与多入口互斥。



### 手动分包策略

分包策略决定哪些代码合成一块、哪些保持独立。本节先从自动提取说起，再讲显式指定与粒度取舍。

#### 公共模块的自动提取

**公共模块提取**：是 Rollup 发现同一模块被两个以上入口或块引用时把它单独产出为一个共享块的默认行为。

- 触发条件：模块被多个入口或块同时引用，且没有被声明为外部依赖。
- 提取结果：该模块只保留一份，各引用方以导入语句指向共享块。
- 命名来源：共享块名默认取模块名或目录名，可用 chunkFileNames 统一整理。
- 副作用影响：被判定为有副作用的模块可能无法提取，只能在各入口各留一份。
- 核对：在产物清单中确认共用代码只出现一次。

```text
入口 A ─┐
        ├─> chunks/shared-utils.js
入口 B ─┘
```

> 自动提取只处理共享引用，判断依据是模块图的引用关系，与模块体积和变更频率无关。

**速记**：被多个入口引用的模块自动提取为共享块，有副作用的模块可能提不出来。



#### 用 manualChunks 指定归属

**manualChunks**：是 output 中的选项，用对象或函数显式声明某个模块应归入哪个块，覆盖默认的提取结果。

- 对象写法：键为块名，值为模块路径数组，命中的模块统一放入该块。
- 函数写法：接收模块标识并返回块名，适合按目录或包名归类。
- 空值回退：函数返回空值时该模块仍按默认规则处理。
- 优先级：显式声明的归属优先于自动提取的结果。
- 风险：把互不相关的模块塞进同一块，会让该块整体难以被下游摇掉。

```js
output: {
  dir: "dist",
  format: "es",
  manualChunks(moduleId) {
    if (moduleId.includes("node_modules")) {
      return "vendor";
    }
    return null;
  },
}
```

> 判定函数拿到的是模块的绝对路径，匹配时要用路径片段而不是包名，否则同名的本地目录也会被命中。

**速记**：manualChunks 用对象或函数指定模块归属，返回空值即回退默认规则，显式归属优先。



#### 拆分粒度的取舍

**拆分粒度**：是块的数量与单个块体积之间的权衡，粒度过粗与过细都会带来新的问题。

- 过粗：单块体积大，任一改动都让该块的哈希变化，缓存命中率下降。
- 过细：请求数量增多、加载链变长，小文件的传输开销被放大。
- 稳定块：把变更频率低的第三方依赖集中成少数块，让缓存长期有效。
- 业务块：业务代码变动频繁，按页面或路由边界拆分更合适。
- 判断依据：按实际访问路径观察请求数量与缓存命中情况再调整。

```js
manualChunks(moduleId) {
  if (moduleId.includes("node_modules")) {
    return "vendor";
  }
  if (moduleId.includes("/src/pages/")) {
    return "pages";
  }
  return null;
}
```

> [!TIP]
> **建议内容**：先按依赖与业务两类拆分并观察一段时间，出现缓存频繁失效或请求过多时再细分，不要一开始就按文件逐个拆块。

**速记**：过粗伤缓存、过细增请求，先按依赖与业务分离，再依据实际访问情况调整粒度。



### 保留模块结构

保留模块结构（preserve modules）是让产物按源码的模块粒度逐文件输出，而不是合并成少数几个文件。本节说明它的含义、与副作用的关系以及目录组织。

#### preserveModules 的含义

**保留模块结构**：是 output 中的 preserveModules 选项，让输出目录里每个源模块对应一个文件，目录层级与源码一致。

- 效果：产物的模块划分与源码一一对应，不再合并成少量块。
- 前提：必须使用 output.dir，单文件输出无法保留结构。
- 根目录：preserveModulesRoot 指定以哪个目录为基准截断路径，避免产物中带上多余层级。
- 产物性质：每个文件仍是标准 ESM，可被下游打包器逐文件按需消费。
- 适用场景：库需要支持逐文件引用，或希望下游的摇树粒度更细。

```js
output: {
  dir: "dist",
  format: "es",
  preserveModules: true,
  preserveModulesRoot: "src",
}
```

> 保留结构的收益体现在下游：模块边界被保留下来，下游打包器才有机会只取用其中的一部分。

**速记**：preserveModules 让每个源模块对应一个产物文件，配合根目录选项截断多余层级。



#### 保留结构与副作用标注的关系

**结构保留与副作用**：是两件独立的事，保留结构只改变产物的文件划分，模块能否被下游摇掉仍取决于副作用声明。

- 独立关系：preserveModules 不改变模块内容的副作用标记。
- 下游摇树：使用方按文件引用时，能否摇掉取决于该文件是否被判定为无副作用。
- 标注位置：副作用声明写在包的清单字段中，供下游打包器读取。
- 常见误解：以为保留结构就等于自动获得更好的摇树效果。
- 处理：与副作用标注配合使用，效果才符合预期。

```text
保留结构：产物按源模块拆成多文件   -> 影响产物的文件划分
副作用标注：声明哪些模块必须保留   -> 影响下游能摇掉多少
```

> 保留结构与副作用标注解决的是不同环节的问题，只做前者时下游依旧可能把整个目录打进产物。

**速记**：保留结构只决定产物文件划分，能否被摇掉取决于副作用标注，两者要配合使用。



#### 保留结构的目录组织

**目录组织**：是保留结构后输出目录的层级安排，由源码层级与根目录选项共同决定。

- 层级来源：输出目录结构直接复制源码的模块层级。
- 根目录截断：preserveModulesRoot 指向源码根，输出目录中不再重复出现该层。
- 文件名：入口与各模块的文件名仍遵循 entryFileNames 模板，扩展名按输出格式补全。
- 多余文件：未被任何入口引用的模块同样会被写出，需要在发布清单中过滤。
- 核对：逐层比对源码目录与输出目录，确认层级一致且无多余层级。

```bash
find dist -name "*.js" | sort | head -n 20
# 与源码模块清单逐条比对
```

> [!NOTE]
> **提醒内容**：保留结构会把未被任何入口引用的模块也写进输出目录，发布前需用发布清单过滤掉这类文件。

**速记**：保留结构的层级来自源码并可用根目录选项截断，未引用的模块也会产出，需在发布时过滤。



### 分包结果的核对

构建成功不等于分包正确。本节给出三种核对手段：读产物清单、找重复模块、验引用地址。

#### 产物清单的读取

**产物清单**：是构建结束后输出目录中的文件集合及各文件体积，是判断分包是否合理的第一手材料。

- 获取方式：构建日志会打印产物名与体积，也可直接列出输出目录。
- 关注项：块的数量、单个块的体积、入口产物的体积。
- 异常信号：体积与源码规模明显不符的块，或大量只有几十字节的空块。
- 对照基准：与上一次构建的清单对比，观察本次改动带来的增量。
- 记录方式：把清单按版本留存，便于定位体积变化的引入点。

```bash
npx rollup -c
# dist/index.js                 1.2 kB
# dist/chunks/vendor-3f9c1a.js 48.6 kB
# dist/chunks/editor-91b2de.js  6.4 kB
```

> 体积异常多来自依赖被整体打入或块划分过细，先看清单再改配置，比凭感觉调选项更快。

**速记**：先读产物清单看块数与体积，与上一版对比定位增量，再决定调整方向。



#### 重复模块的定位

**重复模块**：是同一份代码出现在多个产物文件中的现象，多由副作用标注或外部化配置不当引起。

- 成因一：模块被判定为有副作用，无法提取成共享块。
- 成因二：依赖未被外部化，同时被打进多个产物。
- 成因三：手动分包规则把同一模块同时匹配到两个块。
- 定位：在产物中搜索同一函数名或特征字符串的命中次数。
- 处理：先修外部化与分包规则，再处理副作用标注。

```bash
grep -l "formatCurrency" dist/*.js dist/chunks/*.js
# 命中多个文件说明该模块被重复打入
```

> 重复代码不会报错，只表现为产物体积偏大，因此需要在交付前按特征字符串主动搜索。

**速记**：重复模块来自副作用判定、外部化缺失或规则重叠，用特征字符串搜索定位后逐个修。



#### 引用路径与部署核对

**引用核对**：是检查产物之间的引用地址与实际文件位置是否一致，避免部署后出现模块找不到。

- 检查对象：入口产物对共享块的导入语句与动态导入的地址。
- 前缀一致性：所有引用使用同一种地址形式，不混用绝对与相对。
- 目录对应：产物中写到的子目录必须真实存在。
- 部署范围：整份输出目录一起发布，不能只挑入口文件。
- 验证：在部署环境的真实路径下加载产物，确认没有地址错误。

```bash
grep -rn "chunks/" dist/*.js | head -n 10
# 核对引用到的块是否都存在于输出目录
```

> [!WARNING]
> **警告内容**：只把入口产物上传到服务器而遗漏共享块目录，应用在触发按需加载时才会报模块找不到，构建阶段与静态检查都不会提示。

**速记**：核对产物清单、重复模块与引用地址，整份输出目录一起部署，按需加载的块不能漏传。
