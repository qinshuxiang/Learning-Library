## Vite 构建与产物优化

Vite 的开发期由原生 ESM 与依赖预构建支撑，进入生产环境后则交给 Rollup 完成打包。本篇只讨论构建期：产物长什么样、分包与压缩怎么配、部署路径怎么定、库模式与多入口怎么写。开发服务器与环境变量的用法详见本主题第 6 篇 Vite 开发服务器与环境变量。

### 生产构建与产物结构

生产构建把源码与静态资源编译成可部署文件，Vite 在这一阶段切换到 Rollup，输出按类型归档的产物目录。

#### vite build 命令

**vite build**：是 Vite 的生产构建命令，读取 vite.config.js 里的 build 字段，用 Rollup 打包并默认压缩产物。

- 默认模式：不带参数时 mode 取 production，加载 .env.production 并启用压缩。
- 指定模式：执行 vite build --mode staging 切换模式，读取 .env.staging（详见本主题第 6 篇 Vite 开发服务器与环境变量）。
- 覆盖基础路径：执行 vite build --base=/docs/ 可在命令行覆盖 base，优先级高于配置文件。
- 关闭压缩：临时排查产物时执行 vite build --minify false，保留可读代码。

```bash
npm run build
# vite v7.1.0 building for production...
# ✓ 32 modules transformed.
# dist/index.html                   0.46 kB │ gzip:  0.30 kB
# dist/assets/index-C3kV9m1a.js   142.31 kB │ gzip: 58.72 kB
# ✓ built in 1.28s
```

> 输出里的 gzip 一列是预估压缩后体积，用于估算网络传输成本，不等于服务器实际压缩结果。

**速记**：vite build 以 production 模式跑 Rollup，产物默认压缩并输出到 dist。



#### 产物目录与资源清单

**产物结构**：是构建输出在磁盘上的目录形态，Vite 默认把 HTML 放在 outDir 根目录，其余资源按类型归入 assets 子目录。

- 入口 HTML：项目根目录的 index.html 被复制到 dist/index.html，其中引用的脚本与样式被替换为带哈希的产物路径。
- JS 与 CSS：默认输出到 dist/assets，文件名带内容哈希，例如 index-C3kV9m1a.js。
- 其他资源：图片、字体等按扩展名归档到 dist/assets，可用 build.assetsDir 修改子目录名。
- 资源清单：把 build.manifest 设为 true 后输出 .vite/manifest.json，供后端模板按入口名查找真实文件名。

```json
{
  "index.html": {
    "file": "assets/index-C3kV9m1a.js",
    "src": "index.html",
    "isEntry": true,
    "css": ["assets/index-B7xq2p0d.css"]
  }
}
```

> dist 目录默认在构建前被清空，除非把 build.emptyOutDir 设为 false；把手工维护的文件放进 dist 需要格外留意。

**速记**：产物是根 HTML 加带哈希的 assets 目录，manifest 用入口名反查真实文件名。



#### 构建产物的本地预览

**vite preview**：是本地预览命令，启动一个静态服务器指向 outDir，用真实产物验证路由与资源路径。

- 端口：默认监听 4173，可用 vite preview --port 4173 显式指定。
- 一致性：预览服务器读取 build.outDir 并按其路径规则解析请求，与开发服务器的模块解析不同，能暴露只在构建期出现的问题。
- 限制：preview 不做热模块替换，改动源码需要重新构建。
- 校验重点：懒加载分包是否按需请求、静态资源路径是否正确、base 是否与实际部署前缀一致。

```bash
npm run build
# ✓ built in 1.28s
npx vite preview --port 4173
# ➜  Local:   http://localhost:4173/
```

> [!NOTE]
> **提醒内容**：vite preview 只服务构建产物，不模拟生产环境的反向代理、缓存头与压缩策略，预览通过不等于线上无问题。

**速记**：vite preview 默认 4173 端口，用真实产物验证路径与分包。



### Rollup 选项与分包配置

Vite 的 build 字段覆盖常见需求，超出封装范围的部分通过 build.rollupOptions 直接透传给 Rollup。

#### build.rollupOptions 的输出选项

**build.rollupOptions**：是 Vite 暴露给 Rollup 的配置入口，取值与 Rollup 的 input、output、external、plugins 等选项一致，用于补齐 Vite 未封装的打包能力。

- input：指定入口，缺省时由 Vite 从 index.html 推导。
- output：指定产物命名、分包与格式等细节，Vite 会在其基础上合并自己的默认值。
- external：声明不打入产物、交由使用方提供的依赖，库模式常用。
- plugins：追加只在构建期生效的 Rollup 插件。

```js
// vite.config.js
import { defineConfig } from "vite";

export default defineConfig({
  build: {
    rollupOptions: {
      output: {
        entryFileNames: "assets/js/[name]-[hash].js",
        chunkFileNames: "assets/js/[name]-[hash].js",
        assetFileNames: "assets/[ext]/[name]-[hash].[ext]",
      },
    },
  },
});
```

> [!CAUTION]
> **注意内容**：覆盖 output 命名时若丢掉 [hash] 占位符，浏览器缓存将无法按内容失效，发版后用户可能一直拿到旧文件。

**速记**：rollupOptions 是透传 Rollup 的出口，命名模板里的 [hash] 是缓存失效的依据。



#### manualChunks 手动分包

**build.rollupOptions.output.manualChunks**：是指定模块归属代码块的选项，取值为对象或函数，用于把体积稳定、更新频率低的依赖拆成独立文件。

- 对象形式：键为代码块名，值为模块标识数组，例如把 vue 与 vue-router 归入同一块。
- 函数形式：接收模块 id 字符串，返回代码块名或 undefined，适合按 node_modules 路径规则分流。
- 合并规则：同一依赖被多处声明时归入第一个命中的块，避免重复打入。
- 生效前提：已有两处以上独立引用时才能拆出独立请求，单入口的同步依赖仍会一起加载。

```js
// vite.config.js
export default defineConfig({
  build: {
    rollupOptions: {
      output: {
        manualChunks(id) {
          if (id.includes("node_modules")) {
            if (id.includes("vue")) return "vendor-vue";
            return "vendor";
          }
        },
      },
    },
  },
});
```

> manualChunks 决定的是产物切分，不等于按需加载；真正让代码延迟下载的是 import() 动态导入。

**速记**：manualChunks 用对象或函数把依赖归入命名代码块，函数形式按模块路径分流。



#### 代码块体积告警

**build.chunkSizeWarningLimit**：是单个代码块体积的告警阈值，单位为 kB，默认 500；压缩前体积超过阈值的代码块会在构建输出中逐条列出。

- 触发表现：构建结束打印超出阈值的代码块体积明细，不中断构建。
- 处理思路：优先用 manualChunks 拆分稳定依赖，其次用动态导入切走非首屏路由。
- 对比口径：阈值比较的是未压缩体积，与 gzip 后的传输体积不是同一口径。
- 常见误用：把阈值直接调大只是让提示消失，首屏体积问题仍然存在。

```bash
npm run build
# (!) Some chunks are larger than 500 kB after minification. Consider:
# - Using dynamic import() to code-split the application
# - Use build.rollupOptions.output.manualChunks to improve chunking
```

> [!WARNING]
> **警告内容**：把 chunkSizeWarningLimit 调到远大于默认值，会让体积回归失去唯一的自动提示，应优先拆包而不是关掉告警。

**速记**：单块超过 500 kB 会告警，正确处理是拆包而不是抬高阈值。



### 压缩与资源内联阈值

构建期的压缩决定传输体积，内联阈值决定小资源走独立请求还是编码进引用它的文件。

#### 压缩器的选择

**build.minify**：是压缩开关与压缩器选择项，取值为 esbuild、terser 或 false，默认使用 esbuild。

- esbuild：默认选项，压缩速度快，压缩率略低于 terser，部分压缩策略不支持。
- terser：需先安装 terser 依赖，压缩率更高，但速度明显更慢。
- false：关闭压缩，便于阅读产物或排查压缩引入的问题。
- 删除调试语句：esbuild 默认不删除 console，可用 build.esbuild 的 drop 选项去掉。

```bash
npm install --save-dev terser
```

```js
// vite.config.js
export default defineConfig({
  build: {
    minify: "terser",
    terserOptions: {
      compress: { drop_console: true, drop_debugger: true },
    },
    esbuild: {
      drop: ["console", "debugger"],
    },
  },
});
```

> build.esbuild 只在 minify 取 esbuild 时参与压缩，改选 terser 后该字段的 drop 不再生效。

**速记**：默认 esbuild 求速度，terser 求体积，drop 选项负责删除调试语句。



#### assetsInlineLimit 内联阈值

**build.assetsInlineLimit**：是资源内联阈值，单位为字节，默认 4096；小于该值的资源被编码为 base64 直接写进引用它的脚本或样式。

- 内联收益：省去一次小文件请求，减少往返，适合图标与小型字体。
- 内联代价：base64 编码使体积增大约三分之一，且无法被单独缓存。
- 关闭内联：设为 0 表示所有资源都输出为独立文件。
- 不适用对象：public 目录中的资源始终原样复制，不参与内联判断。

```js
// vite.config.js
export default defineConfig({
  build: {
    assetsInlineLimit: 1024,
  },
});
```

```bash
npm run build
# dist/assets/logo-9f2c1b4d.svg      0.42 kB │ gzip: 0.29 kB
# dist/assets/index-C3kV9m1a.js    142.31 kB │ gzip: 58.72 kB
```

> [!CAUTION]
> **注意内容**：把 assetsInlineLimit 调得过大，会让图片以 base64 形式重复内联进多个代码块，首屏体积反而增大。

**速记**：默认 4096 字节以下内联成 base64，调大阈值要付出体积与缓存代价。



#### CSS 的分割与压缩

**build.cssCodeSplit**：是 CSS 代码分割开关，默认 true，与 JS 代码块对应地生成 CSS 文件。

- 默认行为：每个异步代码块带出自己的 CSS，在模块加载时按需插入。
- 关闭分割：设为 false 时全部样式合并为单个样式文件，适合样式量小且首屏全用的项目。
- 压缩：build.cssMinify 默认跟随 build.minify，也可单独指定为 esbuild、lightningcss 或 false。
- 内联样式：关闭代码分割后配合插件，可把样式直接写入 HTML 的 style 标签。

```js
// vite.config.js
export default defineConfig({
  build: {
    cssCodeSplit: true,
    cssMinify: "esbuild",
  },
});
```

> CSS 分割与 JS 分割共用同一套代码块划分，manualChunks 调整后样式文件会随之重新分组。

**速记**：cssCodeSplit 默认开启并跟随代码块，cssMinify 可独立指定压缩器。



### base 与部署路径

base 决定产物中资源引用的前缀，是部署到子目录或 CDN 时最常出错的一项配置。

#### base 的取值形式

**base**：是公共基础路径，作为产物中所有绝对资源引用的前缀，默认值是一个斜杠。

- 绝对路径：取值为 /docs/ 时产物引用 /docs/assets/...，适合部署在站点的子目录。
- 完整 URL：取值为 https://cdn.example.com/assets/ 时资源从 CDN 加载，适合动静分离。
- 相对路径：取值为 ./ 时资源引用随 HTML 所在位置推算，适合路径不确定的静态托管。
- 命令行覆盖：vite build --base=/docs/ 优先于配置文件中的同名取值。

```js
// vite.config.js
export default defineConfig({
  base: "/docs/",
});
```

```html
<!-- 未设 base 时的产物引用 -->
<script type="module" src="/assets/index-C3kV9m1a.js"></script>
<!-- 设 base 为 /docs/ 后 -->
<script type="module" src="/docs/assets/index-C3kV9m1a.js"></script>
```

> [!IMPORTANT]
> **重要内容**：base 必须与产物的实际访问前缀一致，路径不匹配时页面白屏并伴随资源 404，这是子目录部署最常见的故障。

**速记**：base 是资源引用前缀，写错直接导致 404，子目录部署必须显式指定。



#### 按模式注入路径

**按模式注入路径**：指在配置文件中读取环境变量给 base 赋值，让同一份源码适配本地、预发与生产的不同部署前缀。

- 读取方式：用 loadEnv(mode, process.cwd(), "VITE_") 取出以 VITE_ 开头的变量。
- 缺省兜底：环境未提供变量时给默认值，避免把 undefined 拼进路径。
- 与模式解耦：base 取决于部署位置而非 mode 名称，二者不必然一一对应。
- 典型用法：预发部署在子目录、生产部署在根域名时，用两个 .env 文件分别声明。

```js
// vite.config.js
import { defineConfig, loadEnv } from "vite";

export default defineConfig(({ mode }) => {
  const env = loadEnv(mode, process.cwd(), "VITE_");
  return {
    base: env.VITE_BASE_PATH || "/",
  };
});
```

```bash
# .env.staging
VITE_BASE_PATH=/preview/
```

> 环境变量的读取规则与 .env 文件命名详见本主题第 6 篇 Vite 开发服务器与环境变量。

**速记**：base 用 loadEnv 按模式注入，缺省值兜底，避免把 undefined 拼进路径。



#### 静态资源的引用方式

**静态资源引用**：指源码中通过 import、new URL 或 public 目录三种方式引入资源时，base 对最终路径的不同影响。

- import 引入：资产被解析为产物 URL，自动带上 base 前缀并参与哈希与内联判断。
- new URL 写法：new URL("./logo.svg", import.meta.url) 同样经过处理，适合动态拼接。
- public 目录：其中的文件原样复制到产物根目录，必须按绝对路径引用，不参与哈希与内联。
- 避免硬编码：手写 /assets 前缀在 base 变化后失效，应交给构建工具替换。

```js
// 会被处理，产物路径自动带上 base
import logoUrl from "./assets/logo.svg";
console.log(logoUrl); // "/docs/assets/logo-9f2c1b4d.svg"

// public/robots.txt 原样复制，只能按绝对路径使用
const robotsPath = "/robots.txt";
console.log(robotsPath); // "/robots.txt"
```

> public 目录适合文件名必须稳定的资源，例如 robots.txt 与 favicon；其余资源优先走 import 以获得哈希与内联。

**速记**：import 与 new URL 会被改写并带 base，public 目录原样复制只能绝对路径引用。



### 库模式与多入口

当产物不是网页而是供他人引用的库，或一个项目要产出多个入口时，构建目标与输出格式都要另行配置。

#### build.lib 库模式

**build.lib**：是库模式配置入口，取值为对象，声明入口、库名与输出格式，Vite 随之按库的形态而不是网页的形态打包。

- entry：必需项，取值为模块路径字符串或对象。
- name：UMD 与 IIFE 格式下暴露到全局的变量名。
- fileName：输出文件名，取值为字符串或按格式返回文件名的函数。
- formats：输出格式数组，取值为 es、cjs、umd、iife。
- 输入差异：库模式跳过 HTML 处理，不再把 index.html 当作入口。

```js
// vite.config.js
import { defineConfig } from "vite";
import { fileURLToPath, URL } from "node:url";

export default defineConfig({
  build: {
    lib: {
      entry: fileURLToPath(new URL("./src/index.js", import.meta.url)),
      name: "DataFormat",
      fileName: (format) => `data-format.${format}.js`,
      formats: ["es", "umd"],
    },
  },
});
```

```bash
npm run build
# dist/data-format.es.js   18.42 kB │ gzip: 6.10 kB
# dist/data-format.umd.js  18.91 kB │ gzip: 6.28 kB
```

> 库模式产物默认仍被压缩；若希望保留可读实现便于上游调试，可把 build.minify 设为 false。

**速记**：build.lib 声明 entry、name、fileName 与 formats，产出的是库文件而非网页。



#### 依赖外置与全局变量映射

**external 与 globals**：是库模式配套的两项设置，分别声明哪些依赖不打进产物、以及这些依赖在 UMD 环境下对应的全局变量名。

- external：build.rollupOptions.external 列出依赖名，产物中以 import 或 require 保留引用。
- globals：build.rollupOptions.output.globals 给出外部依赖到全局变量名的映射，UMD 与 IIFE 格式需要。
- 同伴依赖：被外置的依赖通常写进 package.json 的 peerDependencies，由使用方安装。
- 遗漏后果：声明了 external 却没有 globals，UMD 产物在浏览器直接引用时找不到依赖。

```js
// vite.config.js
export default defineConfig({
  build: {
    lib: {
      entry: fileURLToPath(new URL("./src/index.js", import.meta.url)),
      name: "VueWidget",
      formats: ["es", "umd"],
    },
    rollupOptions: {
      external: ["vue"],
      output: {
        globals: { vue: "Vue" },
      },
    },
  },
});
```

> 把框架外置是库的通行做法：使用方已有同一份框架实例时，重复打包既浪费体积，也可能造成状态隔离问题。

**速记**：external 决定谁不打进来，globals 补上 UMD 的全局名映射，二者要成对出现。



#### 多入口构建

**多入口构建**：指一次构建产出多个彼此独立的入口，常见形态是多页面应用与网页加库的混合产物。

- HTML 多入口：在 build.rollupOptions.input 中以对象列出多个 index.html，键即入口名。
- 公共依赖：多个入口引用的同一依赖由 Rollup 自动提升为共享代码块。
- 库多入口：build.lib 的 entry 也可写成对象，每个键产出一组格式文件。
- 命名约束：入口名会进入产物文件名，需保证键名唯一且不含特殊字符。

```js
// vite.config.js
import { defineConfig } from "vite";
import { fileURLToPath, URL } from "node:url";

export default defineConfig({
  build: {
    rollupOptions: {
      input: {
        main: fileURLToPath(new URL("./index.html", import.meta.url)),
        admin: fileURLToPath(new URL("./admin/index.html", import.meta.url)),
      },
    },
  },
});
```

```bash
npm run build
# dist/index.html
# dist/admin/index.html
# dist/assets/admin-C9dq1f7k.js  12.05 kB │ gzip: 4.31 kB
```

> 多页面项目可直接用多入口替代路由工程，页面之间天然隔离，代价是页面切换会整页刷新。

**速记**：多入口用 input 对象声明，键名决定入口与产物名，公共依赖自动提升为共享块。
