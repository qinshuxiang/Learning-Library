## Vite 与框架生态集成

框架项目与 Vite 之间隔着插件：插件把框架自己的文件格式编译成标准模块，并负责开发期的刷新能力。插件机制与官方插件清单见本主题第 5 篇，本篇只讲接入侧的差异与配置：Vue 与 React 两条链路的形态差别、其它框架的接入方式、脚手架产出的模板差异，以及框架插件常见配置项的归类。Vue 与 React 的语言写法分别见 前端/Vue3、前端/React 主题，热更新机制见本主题第 6 篇。

### Vue 生态集成

Vue 项目对 Vite 的接入集中在单文件组件的编译与刷新，插件承担全部编译职责，框架侧库只提供运行时能力。

#### 官方 Vue 插件的接入

**Vue 接入插件**：是官方维护的 Vite 插件，接管 .vue 单文件组件的编译，并为组件注入开发期刷新所需的内容。

- 安装归属：插件本身装进开发依赖，框架与路由、状态管理库装进运行时依赖。
- 注册方式：在配置的 plugins 数组里调用插件工厂函数，按需要传入选项对象。
- 接手范围：把单文件组件拆成模板、脚本、样式三部分，分别交给对应处理链。
- 不接手范围：路由解析、状态管理、服务端渲染由框架侧库与其上层方案承担。
- 版本匹配：插件主版本需要与框架主版本、构建器主版本同时对齐，升级时按插件迁移说明执行。

```js
// vite.config.js
import { defineConfig } from "vite";
import vue from "@vitejs/plugin-vue";

export default defineConfig({
  plugins: [vue()],
});
```

> 插件是编译入口而不是运行时依赖，把它误装进运行时依赖会让使用方安装到用不到的编译代码。

**速记**：Vue 项目接入以官方插件为唯一入口，插件只负责编译与开发期刷新。



#### 单文件组件与编译宏

**单文件组件编译**：是插件按块拆分文件、把模板编译为渲染函数、把脚本与样式分别交给后续链路处理的过程。

- 块级分工：模板块进入模板编译器，脚本块进入脚本转换，样式块进入样式处理链路。
- 宏的处理：脚本块中的编译期宏由编译器在转换阶段展开，构建产物中不保留宏的调用形式。
- 作用域样式：样式块的作用域属性由编译器写入，构建后选择器会被加上额外属性，无需手工处理。
- 开发期刷新：插件为每个组件注入可接受更新的边界，使改动只替换对应组件。
- 错误定位：编译报错会带出所在文件与块的位置，定位问题优先看插件的报错行号。

```text
.vue 文件
  template 块  -> 模板编译器   -> 渲染函数
  script 块    -> 脚本转换     -> 宏在转换期展开
  style 块     -> 样式链路     -> 注入或提取为 CSS 文件
```

> [!NOTE]
> **提醒内容**：模板编译发生在构建期，运行时的模板字符串不会被编译，含运行时编译需求的写法在构建模式下无法生效。

**速记**：插件把单文件组件按块拆给三条链路，宏在转换期展开，样式作用域由编译器写入。



#### Vue 的 JSX 支持

**Vue JSX 插件**：是让 Vue 组件以 JSX 语法书写、并在构建期转译为框架渲染函数的插件，与单文件组件插件并存。

- 并存关系：两个插件各管一类文件，注册顺序不改变各自负责的扩展名。
- 转译目标：JSX 被转译为该框架的渲染函数调用，而不是另一框架的创建元素函数。
- 类型脚本：以 tsx 为扩展名的文件同样进入 JSX 转换链，类型检查由类型检查器负责。
- 选用场景：需要完全用表达式组织视图、或需要把既有 JSX 组件迁移进项目时使用。
- 成本判断：两种写法混用会让项目存在两条编译入口，团队内应约定主用其中一条。

```js
// vite.config.js 单文件组件与 JSX 同时接入
import { defineConfig } from "vite";
import vue from "@vitejs/plugin-vue";
import vueJsx from "@vitejs/plugin-vue-jsx";

export default defineConfig({
  plugins: [vue(), vueJsx()],
});
```

> 两个插件都对脚本转换阶段有要求，出现转换结果异常时，先确认文件是否落进了不该由它处理的插件。

**速记**：JSX 插件与单文件组件插件并存，各管一类文件，项目内应约定主用写法。



### React 生态集成

React 项目的接入插件提供两种实现，选择哪一种取决于是否需要自定义转译链。接入后的关键约定是模块导出形态。

#### 官方 React 插件的两种形态

**React 接入插件**：是官方维护的、负责 JSX 与 TypeScript 转译以及开发期刷新的插件，官方提供基于 Babel 与基于 SWC 的两种实现。

- 转译器差异：一种以 Babel 完成转换并支持传入自定义 Babel 插件，另一种以 SWC 完成转换、速度更快但扩展点较少。
- 互斥要求：两种实现只能注册一个，同时注册会对同一文件重复转换并可能得到不同结果。
- 选择依据：需要自定义转译插件时选 Babel 实现，追求编译速度且无自定义转译需求时选 SWC 实现。
- 依赖处理：开发期依赖的预构建由构建器自身完成，插件只处理项目源码。
- 安装归属：插件装进开发依赖，框架与其运行时类型装进运行时依赖。

```js
// vite.config.js 二选一，此例为 Babel 实现
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";

export default defineConfig({
  plugins: [react()],
});
```

> 两种实现的产物语义一致，差异集中在编译速度与可扩展性；切换实现属于构建配置变更，应单独验证一次产物。

**速记**：React 接入插件有 Babel 与 SWC 两种实现，只能二选一，按是否需要自定义转译插件来决定。



#### 开发期刷新与组件约定

**开发期刷新**：是框架插件在开发期提供的能力，改动组件后在不刷新整页的前提下替换模块，推送机制见本主题第 6 篇。

- 生效前提：模块只导出组件，编译器据此判断可替换的边界。
- 破坏约定：在组件文件中同时导出常量的模块会让刷新退化为整页刷新，状态随之丢失。
- 仅开发期：刷新相关代码只在开发期注入，生产构建中不包含该逻辑。
- 组件类型：函数组件与类组件在刷新行为上有差异，部分写法无法保留状态。
- 排查方式：观察终端输出是模块级更新还是整页重载，据此判断约定是否被破坏。

```js
// 反例：组件文件里混入其它导出，刷新会退化为整页重载
export const tableColumns = ["name", "size"];

export function FileTable({ rows }) {
  return rows;
}
```

> [!CAUTION]
> **注意内容**：把常量与工具函数放在组件文件里导出，会让开发期刷新频繁退化为整页刷新，长表单与滚动位置随之丢失，应把非组件导出移到独立模块。

**速记**：开发期刷新要求模块只导出组件，混入其它导出会让刷新退化为整页重载。



#### JSX 运行时与 Babel 选项

**JSX 运行时**：是 JSX 转译后创建元素的函数来源，分为从模块自动引入的运行时与依赖全局变量的经典运行时。

- 自动运行时：转译结果自动引入运行时模块，不再需要全局变量，是当前的主流选择。
- 经典运行时：转译结果依赖作用域内的全局变量，只在既有代码需要兼容时启用。
- 来源包选项：自动运行时下可指定提供运行时函数的包，用于自定义渲染环境。
- 自定义转译：Babel 实现可通过插件选项追加 Babel 插件，用于装饰器、宏一类转换。
- 冲突排查：同时配置构建器自身的 JSX 选项与框架插件的 JSX 选项时，以插件处理结果为准，不要重复配置。

```js
// vite.config.js 指定运行时来源与自定义 Babel 插件
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";

export default defineConfig({
  plugins: [
    react({
      jsxRuntime: "automatic",
      babel: {
        plugins: ["babel-plugin-macros"],
      },
    }),
  ],
});
```

> JSX 的类型检查不在构建期进行，编辑器与流水线中的类型校验由类型检查器按类型脚本配置完成。

**速记**：JSX 运行时默认自动引入，自定义转译由插件选项追加，构建器侧不要重复配置 JSX。



### 其他框架与通用插件

框架接入不是 Vue 与 React 的专利，同一套插件契约对其余框架同样适用。本节说明接入方式与通用能力的补充。

#### 非 Vue 与 React 框架的接入

**框架接入插件**：是按同一插件契约实现、通过转换与开发期钩子接管框架自有文件格式的第三方插件。

- 覆盖范围：编译型框架各有对应插件，Svelte 由官方维护接入插件，Solid 与 Preact 由框架团队维护。
- 免插件情形：不需要编译的框架只要用标准扩展名书写即可直接用构建器处理，仅在需要额外能力时才引入插件。
- 选型核对：确认插件声明的兼容构建器主版本、是否由框架官方仓库维护、最近一次发布时间。
- 单一原则：一个项目只注册一个框架插件，混合注册会让同一文件被两套转换链处理。
- 契约一致：无论哪个框架，插件都只是编译与开发期能力的载体，替换框架时配置形态基本不变。

```js
// vite.config.js 第三方框架插件按同一形态注册，包名以插件文档为准
import { defineConfig } from "vite";

export default defineConfig({
  plugins: [frameworkPlugin({ extensions: [".svelte"] })],
});
```

> 判断一个框架是否需要接入插件，看它是否有非标准文件格式或需要编译的模板语法，没有则不必引入。

**速记**：第三方框架插件按同一契约接入，一个项目只注册一个，选型先核对兼容版本与维护状态。



#### 通用能力插件

**通用能力插件**：是与框架无关、补齐降级、产物压缩、按需引入等能力的插件，注册方式与框架插件一致。

- 降级产物：为旧内核生成降级包与垫片，属官方插件之一，用法见本主题第 5 篇。
- 预压缩：在构建产物旁生成压缩文件，由部署层直接下发，省去服务端实时压缩的开销。
- 按需引入：为组件库提供自动导入能力，减少逐条手工注册的代码，配置需按插件的解析规则填写。
- 资源处理：矢量图转组件、图片压缩一类处理，接入前评估其对构建耗时的影响。
- 阶段限定：只在生产构建生效的插件用 apply 字段限定阶段，避免开发期承担无谓开销。

```js
// vite.config.js 仅在构建期生效的插件
export default {
  plugins: [
    {
      name: "compress-assets",
      apply: "build",
      generateBundle(_options, bundle) {
        // 遍历 bundle 生成预压缩文件
      },
    },
  ],
};
```

> [!TIP]
> **建议内容**：把只服务发布的插件用 apply 限定为构建期生效，可让开发启动与热更新不承担这些插件的开销。

**速记**：通用插件按同一方式注册，只服务发布的用 apply 限定为构建期生效。



#### 插件共存与冲突处理

**插件冲突**：是多个插件处理同一类文件或同一转换阶段而产生的相互干扰，表现为重复转换、产物异常或编译报错。

- 常见来源：同时注册两个框架插件，或两个插件都处理同一种扩展名。
- 转译重复：脚本转译与类型转译被两个插件各做一次，产物出现重复的辅助代码。
- 顺序影响：插件按数组顺序执行，可用 enforce 把插件提到核心流程之前或之后，语义见本主题第 5 篇。
- 定位方法：逐步减少注册的插件做二分定位，或借助构建日志观察插件耗时与执行顺序。
- 结构性约束：框架插件之间没有共存方案，需要同时支持多个框架时应拆成多个项目。

```js
// vite.config.js 用 enforce 明确插件的执行位置
export default {
  plugins: [
    { name: "prepare-source", enforce: "pre", transform: (code) => code },
    { name: "polish-output", enforce: "post", transform: (code) => code },
  ],
};
```

> 排查冲突时先确认「哪个插件动了这个文件」，再讨论顺序；只看最终产物很难判断是哪一步引入的差异。

**速记**：一个项目只注册一个框架插件，转换重复与顺序问题用二分与日志定位。



### 脚手架与模板差异

脚手架决定项目起点，也决定后续升级要跟随谁的节奏。本节对照通用脚手架、框架命令行工具与模板取舍。

#### 官方脚手架与模板清单

**脚手架**：是生成项目骨架并预置构建配置的命令行工具，官方提供通用脚手架，按模板名区分预置内容。

- 通用脚手架：按模板名生成最小可运行项目，可选模板覆盖无框架、Vue、React、Preact、Svelte、Solid、Lit 等。
- 模板名单：模板集合随工具版本增删，可用的模板名以工具当前版本的提示为准。
- 生成内容：配置文件、入口文件、页面模板与启动脚本，依赖按模板预置。
- 框架侧脚手架：Vue 另有官方脚手架命令，可在生成时按选项追加路由与状态管理等能力。
- 版本获取：脚手架命令按需拉取最新版本生成，生成后应立即安装依赖并提交锁文件。

```bash
npm create vite@latest my-app -- --template vue-ts
# 生成最小 Vue 加类型脚本项目
npm create vue@latest my-app
# 交互式选择是否包含路由与状态管理
```

> 模板只是起点，生成后的配置属于项目自身资产，升级构建器时不再依赖脚手架。

**速记**：通用脚手架按模板名生成最小项目，框架侧脚手架按选项追加框架能力。



#### 框架命令行工具生成的项目

**框架命令行工具**：是框架自己提供的初始化命令，生成的项目把构建配置封装在框架插件与约定目录之下。

- 配置形态：项目里的构建配置只暴露插件选项，打包细节由框架插件与预设给定。
- 目录约定：源码目录、静态资源目录、页面目录按框架约定组织，构建产物路径同样固定。
- 升级路径：构建器与插件的升级跟着框架的发布节奏走，不能单独升级其中一环。
- 能力预置：路由、状态管理、代码规范等能力在生成时按选项写入，项目内不再另行配置。
- 服务端渲染：带服务端渲染的框架另有一套入口与运行约定，属框架职责，详见 前端/SSR 与跨端 主题。

```text
框架命令行工具生成的项目
  vite.config  -> 只调用框架插件，选项有限
  src 目录     -> 按框架约定组织
  升级         -> 跟随框架版本与插件版本
```

> 封装程度越高，配置自由度越低；这类项目适合按框架给出的方式扩展，绕过插件直接改打包选项会让升级变得不可控。

**速记**：框架命令行工具把配置封装进插件，升级跟随框架节奏，不适合绕过插件改打包选项。



#### 模板的取舍与升级

**模板取舍**：是按项目需要的预置能力选择最小模板还是含框架全家桶的脚手架产物。

- 最小模板：依赖少、配置可见、构建链路清晰，代价是路由与规范工具需要自行补齐。
- 全家桶模板：开箱可用，代价是配置分散在插件与预设中，理解成本更高。
- 折中路线：以最小模板起步，按实际需要逐个添加插件，配置项始终处于可控范围。
- 团队约定：同类项目统一使用同一模板与同一插件集合，减少项目之间的配置差异。
- 升级注意：构建器主版本升级时同步核对框架插件与脚手架的兼容说明，三者不要各自升级。

```bash
npm create vite@latest my-app -- --template react-ts
npm install
npm run dev
```

> [!IMPORTANT]
> **重要内容**：模板生成后要提交锁文件并固定构建器与插件版本，否则不同机器会解析出不同版本，模板带来的确定性会在第一次安装时丢失。

**速记**：模板按需要选最小或全家桶，同类项目统一模板，升级时构建器与插件同步核对。



### 框架插件的常见配置项

框架插件的配置项按作用分为文件范围、编译选项与开发期开关三类。本节按这个归类说明，具体默认值以插件文档为准。

#### 文件匹配与包含排除

**文件匹配选项**：是框架插件判断哪些文件进入编译范围的选项，通常写作 include 与 exclude，取值为字符串、正则或数组。

- 默认范围：插件按框架约定的扩展名匹配文件，通常不需要显式声明。
- 追加范围：把自研文件格式纳入编译时，用 include 追加扩展名或路径规则。
- 排除范围：产物目录、依赖目录与测试夹具不应进入编译范围，避免重复处理与无谓耗时。
- 正则写法：正则取值为完整匹配，写相对路径模式时要考虑路径分隔符差异。
- 误配后果：范围过窄会让文件不被编译并直接报语法错误，范围过宽会拉长启动与构建时间。

```js
// vite.config.js 把额外扩展名纳入框架插件的编译范围
export default {
  plugins: [vue({ include: [/\.vue$/, /\.md$/], exclude: ["**/dist/**"] })],
};
```

> 修改匹配范围后应重启开发服务器并清理预构建缓存，否则旧结果可能仍在生效。

**速记**：默认扩展名之外的文件用 include 追加、用 exclude 排除产物与依赖目录，改完要重启。



#### 编译与模板选项

**编译选项**：是框架插件透传给框架编译器的配置，按框架分为模板侧与脚本侧两组，命名与默认值以插件文档为准。

- 模板侧：Vue 插件的模板编译选项可用于登记自定义元素白名单，避免把组件库标签当作组件解析。
- 脚本侧：Vue 插件可调整脚本编译行为，例如是否提升静态内容，具体选项按插件文档填写。
- 运行时选择：React 插件可指定 JSX 运行时与运行时来源包，对应上文的运行时话题。
- 转译扩展：React 插件可传入自定义 Babel 插件，用于宏、装饰器一类转换。
- 通用原则：编译选项影响的是语法转换结果，不要用它代替构建器的构建期选项。

```js
// vite.config.js 模板编译选项与运行时选项分别归属两个插件
export default {
  plugins: [
    vue({
      template: { compilerOptions: { isCustomElement: (tag) => tag.startsWith("x-") } },
    }),
  ],
};
```

> 编译选项写错通常不会中断构建，而是得到行为不符的产物，改动后应实际跑一次页面确认。

**速记**：模板选项与脚本选项分开配置，只影响语法转换结果，默认值以插件文档为准。



#### 刷新开关与版本匹配

**刷新开关**：是插件提供的开发期刷新控制选项，用于在特定场景下关闭刷新相关代码的注入。

- 关闭场景：刷新逻辑与自定义运行环境冲突，或需要确认某问题是否由刷新引起。
- 影响范围：开关只作用于开发期注入，关闭后生产产物的内容不变。
- 生产产物：开发期注入的刷新代码不会进入生产构建，无需在构建配置里另行剥离。
- 版本对齐：插件主版本、构建器主版本与框架主版本三者必须落在插件声明的兼容区间内。
- 升级顺序：按插件迁移说明执行，一般先升框架、再升插件、再升构建器，每一步单独验证。

```js
// vite.config.js 关闭刷新注入以排查问题
export default {
  plugins: [react({ fastRefresh: false })],
};
```

> [!WARNING]
> **警告内容**：插件与构建器的主版本错配会在启动阶段直接失败，错误信息常指向插件内部而非配置本身，升级前先查兼容区间可省去排查时间。

**速记**：刷新开关只影响开发期注入，插件与构建器、框架的主版本必须落在兼容区间内。
