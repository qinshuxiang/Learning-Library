## webpack 资源模块与静态资源处理

图片、字体、图标与媒体文件不属于 JavaScript，webpack 用资源模块（asset modules）统一处理它们：按类型决定输出独立文件还是内联进代码，再按模板命名落到产物目录。本篇讲四种资源类型的分工、图片与字体的策略、内联阈值的权衡、产物命名规则与 HTML 注入方式。loader 规则与匹配字段的写法见本主题第 9 篇 webpack loader 与 plugin，产物体积分析见第 10 篇，缓存与持久化缓存策略见第 15 篇。

### 资源模块的四种类型

资源模块不需要额外的 loader，type 字段声明后即生效。本节按类型逐一说明行为与适用对象。

#### asset/resource 输出独立文件

**asset/resource**：是资源模块的一种类型，把匹配到的文件原样输出到产物目录，并把导入结果替换为该文件的引用地址。

- 声明位置：写在 module.rules 的 type 字段上。
- 行为：每个文件产出一份独立文件，导入语句得到该文件的地址字符串。
- 默认命名：未配置 generator 时按默认模板命名并带摘要，产物集中在输出目录。
- 适用对象：体积较大、被多处复用、需要独立缓存的资源。
- 迁移关系：它取代了旧式文件搬运 loader 的职责，配置里不再需要额外 loader。

```js
// webpack.config.js 片段
module.exports = {
  module: {
    rules: [
      {
        test: /\.(png|jpe?g|gif|webp)$/i,
        type: "asset/resource",
        generator: {
          filename: "images/[name].[contenthash:8][ext]",
        },
      },
    ],
  },
};
```

> 资源模块由 webpack 内置提供，旧项目迁移时可逐条把搬运类 loader 的规则替换成 type 声明。

**速记**：asset/resource 把文件原样输出并返回引用地址，适合大文件与需要独立缓存的资源。



#### asset/inline 内联为数据地址

**asset/inline**：是资源模块的一种类型，把匹配到的文件内容编码成数据地址（data URI）内联进引用位置，不新增独立文件。

- 结果形态：导入结果是一段带编码前缀的字符串，直接写进最终代码。
- 体积代价：编码后体积约为原文件的三分之一以上增幅，字符串本身无法被单独缓存。
- 适用对象：极小图标、内联式矢量图标与避免额外请求的场景。
- 不适用：较大的图片与字体，会让入口脚本显著变大。
- 替代方式：asset 类型可按阈值自动在内联与输出之间选择。

```js
// webpack.config.js 片段
module.exports = {
  module: {
    rules: [
      {
        test: /\.svg$/i,
        type: "asset/inline",
      },
    ],
  },
};
```

> [!WARNING]
> **警告内容**：把中等体积的图片声明为内联，会把资源体积计入入口脚本并直接拖慢首屏，内联只应留给体积极小的文件。

**速记**：asset/inline 把内容编码进代码，减少一次请求但增大脚本体积且无法单独缓存。



#### asset/source 与 asset 自动选择

**asset/source**：是把文件内容以字符串形式导出、不经过任何转换的资源类型；**asset**：是按体积阈值在前两种行为之间自动选择的一种类型。

- source 行为：导入结果是文件原文，常见于把文本、着色器源码或模板拼进代码。
- asset 的判定：文件体积小于阈值时内联，否则输出独立文件。
- 阈值字段：由 generator.dataUrlCondition.maxSize 控制，单位是字节。
- 默认行为：未配置阈值时按资源默认上限判断，超过即输出独立文件。
- 选择建议：类型明确时直接写死类型，只有确实需要按体积分流时才用 asset。

```js
// webpack.config.js 片段
module.exports = {
  module: {
    rules: [
      {
        test: /\.(png|jpe?g)$/i,
        type: "asset",
        parser: {
          dataUrlCondition: { maxSize: 8 * 1024 },
        },
      },
      {
        test: /\.glsl$/i,
        type: "asset/source",
      },
    ],
  },
};
```

> asset/source 不做任何转义，把二进制文件声明为 source 会把乱码带进代码，它只应匹配文本类文件。

**速记**：asset/source 导出文件原文，asset 按体积阈值在内联与输出之间自动选择。



### 图片与字体的处理策略

同一套规则套用到所有资源是最常见的错误。本节按图片、字体与优化工具三段说明分流方式。

#### 图片按用途与格式分流

**图片分流**：是按图片的用途与格式分别声明资源类型与产物规则，让图标、插画与照片各自走到合适的处理路径。

- 小图标：体积很小，宜内联或合并成雪碧图，减少请求数。
- 内容插画：中等体积且复用少，宜输出独立文件并带内容摘要。
- 照片：体积大，宜交给压缩工具处理后输出，必要时转成新一代格式。
- 格式判断：新一代格式体积更小，但需要在构建期生成并保留回退格式。
- 规则顺序：多条规则都命中时只取第一条，范围窄的规则应写在前面。

```js
// webpack.config.js 片段
module.exports = {
  module: {
    rules: [
      { test: /\.svg$/i, type: "asset/inline" },
      { test: /\.(png|jpe?g)$/i, type: "asset" },
      { test: /\.(woff2?|ttf|otf)$/i, type: "asset/resource" },
    ],
  },
};
```

> 同一张图在构建期生成多种格式时产物里会出现多份文件，需要由模板或样式按需引用，避免全部加载。

**速记**：图标宜内联、插画与照片宜输出独立文件，多格式并存时由引用方按需选择。



#### 字体文件的处理要点

**字体处理**：是把字体文件交给资源模块输出、并保证样式中引用地址正确的一类配置。

- 类型选择：字体体积普遍较大，一律用 asset/resource，不做内联。
- 后缀覆盖：常见后缀包括 woff、woff2、ttf、otf、eot，规则里要写全。
- 目录组织：单独放字体目录，便于与图片分开配置缓存策略。
- 引用方式：样式里的地址与产物路径要对齐，避免字体请求失败后静默回退。
- 资源准备：字体授权与子集化属于资源准备阶段，构建只负责搬运与命名。

```js
// webpack.config.js 片段
module.exports = {
  module: {
    rules: [
      {
        test: /\.(woff2?|ttf|otf|eot)$/i,
        type: "asset/resource",
        generator: {
          filename: "fonts/[name].[contenthash:8][ext]",
        },
      },
    ],
  },
};
```

> [!CAUTION]
> **注意内容**：字体加载失败时浏览器会静默回退到系统字体，页面不报错但观感变化，字体路径必须在构建后实际访问确认。

**速记**：字体一律输出独立文件、规则写全后缀，路径错误只表现为字体静默回退。



#### 与压缩和子集化工具的衔接

**资源优化衔接**：是在资源模块之外接入压缩与子集化工具，构建只负责产物搬运与命名，优化在接入层完成。

- 图片压缩：在资源进入产物前接入压缩工具，按格式与质量参数处理。
- 格式转换：需要生成新一代图片格式时另接转换工具，与回退格式并存。
- 字体子集：按实际使用字符生成子集文件，显著减小字体体积。
- 顺序要求：压缩与转换必须发生在资源输出之前，否则处理结果不会进入产物。
- 配置位置：以上工具以 loader 形式接入规则链，具体选项按各自文档填写。

```text
源文件
  → 压缩与格式转换（接入层）
  → 资源模块按类型处理
  → 输出到产物目录
```

> 优化工具的收益差异很大，接入前先量化原文件体积，避免为体积占比极低的资源引入额外依赖。

**速记**：压缩、格式转换与子集化都在资源进入产物前完成，顺序错了处理结果不会进产物。



### 内联阈值与体积权衡

内联与否的判定依据是体积、复用次数与首屏必要性。本节讲两面性、分类型设阈值与调优方法。

#### 内联的正负两面

**内联权衡**：是减少一次请求与增大首屏脚本体积之间的取舍，判定依据是资源体积与使用频率。

- 正面：省掉一次网络往返，小图标内联后首屏可少发若干请求。
- 反面：编码后体积膨胀，且内联内容随脚本一起下载与解析，无法单独缓存更新。
- 更新代价：内联资源变化会让引用它的脚本内容变化，进而影响该脚本的缓存。
- 并发影响：请求数过多会占用连接，但现代传输协议下小文件的并发代价已明显下降。
- 判定顺序：先看体积，再看复用次数，最后看是否属于首屏必需资源。

```text
内联适用：体积很小、首屏必需、几乎不更新
外链适用：体积较大、多处复用、更新与页面发布不同步
```

> 请求数不是唯一指标，把大量小文件内联进入口脚本，节省的往返可能远小于增加的传输与解析成本。

**速记**：内联省请求、增体积、破坏独立缓存，判定先看体积再看复用与首屏必需性。



#### 按类型设置内联阈值

**内联阈值**：是 asset 类型判断是否内联的体积分界，由 generator.dataUrlCondition.maxSize 以字节为单位设置。

- 分类设置：图标、图片、字体分别用不同阈值，字体通常直接设为不内联。
- 图标类：阈值可以放宽，因为单个体积小且数量多。
- 图片类：阈值从严，只让极小图片进入内联。
- 字体类：阈值设为零或直接用 asset/resource 类型。
- 生效范围：阈值写在规则内，只对命中该规则的文件生效。

```js
// webpack.config.js 片段
module.exports = {
  module: {
    rules: [
      {
        test: /\.(png|jpe?g|webp)$/i,
        type: "asset",
        parser: {
          dataUrlCondition: { maxSize: 4 * 1024 },
        },
      },
    ],
  },
};
```

> 同一阈值套用到所有类型是常见的偷懒写法，字体一旦被判为内联，产物体积会出现难以解释的跳变。

**速记**：阈值按类型分别设置，图标可放宽、图片从严、字体不内联。



#### 阈值调优的判定方法

**阈值调优**：是依据真实产物体积与页面加载表现反复调整分界值的过程，而非一次设定后长期不变。

- 基线数据：先记录调整前的产物体积与首屏资源清单。
- 调整方式：一次只改一类资源的阈值，避免结果无法归因。
- 观察指标：入口脚本体积、请求数量与首屏关键资源总量。
- 核对产物：调整后检查产物目录，确认预期内联的文件不再单独输出。
- 回归成本：阈值变化会改变产物文件名与缓存命中，发布策略要同步考虑。

```text
调整前：入口脚本 180 KB，图片请求 12 个
阈值放宽后：入口脚本 260 KB，图片请求 5 个
结论：体积增幅过大时收回阈值
```

> [!TIP]
> **建议内容**：阈值调优应一次只动一个变量并记录前后数据，同时改阈值与压缩参数会让结论无法归因。

**速记**：先记基线，再单变量调整阈值，用入口体积与请求数共同判断是否收回。



### 产物目录与文件名规则

产物路径由目录与文件名两部分拼成。本节讲目录组织、命名模板与内容摘要的作用。

#### outputPath 与产物目录组织

**产物目录**：是资源文件在输出目录下的存放位置，由规则里的 generator.outputPath 决定，未配置时直接落在输出目录根。

- 分类存放：图片、字体与媒体分别放不同子目录，便于配置缓存与清理策略。
- 相对含义：该字段是相对整个输出目录的路径，不是相对源文件。
- 组合命名：目录与文件名模板共同决定最终路径与文件名。
- 覆盖写法：规则级配置优先于全局默认，可按类型分别设置。
- 目录数量：目录不宜过深，过深会让产物清单难以核对。

```js
// webpack.config.js 片段
module.exports = {
  module: {
    rules: [
      {
        test: /\.(png|jpe?g|webp)$/i,
        type: "asset/resource",
        generator: {
          outputPath: "assets/images/",
          filename: "[name].[contenthash:8][ext]",
        },
      },
    ],
  },
};
```

> 输出目录由 webpack 自动创建，不需要预先建目录，也不会因为目录不存在而报错。

**速记**：generator.outputPath 是相对输出目录的子目录，按资源类型分流便于缓存与清理。



#### generator 文件名模板

**文件名模板**：是 generator.filename 中使用的占位符组合，决定产物文件名如何由源文件信息与内容摘要生成。

- 常用占位符：name 取源文件名，ext 取含点的后缀，contenthash 取内容摘要，hash 取构建摘要。
- 摘要长度：用冒号加数字限定长度，兼顾可读性与唯一性。
- 唯一性：内容摘要随内容变化，内容不变则文件名不变，是长期缓存的前提。
- 冲突规避：同名不同内容的文件靠摘要区分，模板里必须包含摘要。
- 可读性：保留源文件名便于排查，纯摘要命名会牺牲可读性。

```js
// webpack.config.js 片段
module.exports = {
  output: {
    assetModuleFilename: "assets/[name].[contenthash:8][ext]",
  },
};
```

> 全局默认模板写在 output.assetModuleFilename，规则内的 generator.filename 会覆盖它，两者保留一处配置即可。

**速记**：模板用 name、ext 与内容摘要组合，摘要保证唯一性，源文件名保证可读性。



#### 内容哈希与缓存失效

**内容哈希（content hash）**：是由文件内容计算出的摘要占位符，内容变化摘要即变化，用于让缓存按文件粒度失效。

- 缓存原理：文件名变化即视为新资源，浏览器重新下载，未变化的文件继续命中缓存。
- 层级差别：内容摘要按单个文件内容计算，普通摘要按整体构建计算，前者更细。
- 引用一致性：引用资源的脚本同步变化，模板生成的引用地址随产物更新。
- 更新粒度：单个图片变化只影响该图片与其引用方，不会让全部资源失效。
- 取值稳定：内容不变时摘要稳定，构建之间的重命名不影响摘要取值。

```js
// webpack.config.js 片段
module.exports = {
  module: {
    rules: [
      {
        test: /\.(png|jpe?g)$/i,
        type: "asset/resource",
        generator: {
          filename: "images/[name].[contenthash:8][ext]",
        },
      },
    ],
  },
};
```

> [!IMPORTANT]
> **重要内容**：文件名不带内容摘要时，资源内容更新后访问者会继续命中旧缓存，线上表现为图片或样式长期不更新，必须清缓存才能恢复。

**速记**：内容摘要让缓存按文件粒度失效，文件名必须含摘要才能安全地长期缓存。



### 静态资源引用与 HTML 注入

资源文件被产出的同时，页面还要拿到正确地址。本节讲模板注入、地址前缀与路径形式的选择。

#### 从模板到产物的引用注入

**引用注入**：是把构建产出的脚本与样式地址写进 HTML 模板、使页面能加载到正确文件的过程。

- 注入方式：由 HTML 处理插件按构建产物自动写入，无需手写地址。
- 模板来源：模板文件只描述结构，资源地址留空由构建填充。
- 资源范围：默认注入入口相关的脚本与样式，按需加载的资源要显式声明。
- 多页面场景：每个页面各有入口时，插件按入口与页面建立对应关系。
- 核对方式：构建后打开产物 HTML，确认地址指向真实存在的文件。

```js
// webpack.config.js 片段
const path = require("node:path");
const HtmlWebpackPlugin = require("html-webpack-plugin");

module.exports = {
  entry: "./src/index.js",
  plugins: [
    new HtmlWebpackPlugin({
      template: path.resolve(__dirname, "public/index.html"),
      filename: "index.html",
    }),
  ],
};
```

> 模板内不要手写产物地址，手写地址在文件名带摘要后必然失效。

**速记**：模板只写结构，脚本与样式地址由构建按产物自动注入，切勿手写。



#### publicPath 的作用与取值

**publicPath**：是产物中引用其他资源时使用的地址前缀，决定运行时从哪里加载脚本、样式与资源文件。

- 默认取值：多为相对形式，产物放在站点根目录时通常无须额外配置。
- 子目录部署：站点部署在子路径下时必须显式设置前缀，否则资源请求会落到错误位置。
- 自动推断：部分取值会让运行时按当前脚本地址推断前缀，适合路径不确定的场景。
- 影响范围：它作用于运行时的地址拼接，不改变文件的物理输出位置。
- 资源模块：资源模块产出的引用地址同样受它影响。

```js
// webpack.config.js 片段
module.exports = {
  output: {
    filename: "[name].[contenthash:8].js",
    publicPath: "/static/",
  },
};
```

> [!NOTE]
> **提醒内容**：publicPath 写错不会中断构建，只会在浏览器里产生一批资源请求失败，部署路径变化时应优先核对它。

**速记**：publicPath 是运行时引用地址的前缀，子目录部署必须显式设置，它不改变物理输出位置。



#### 绝对路径与相对路径的选择

**路径形式选择**：是决定产物内的引用地址用绝对形式还是相对形式，取决于部署位置是否固定与页面是否可能被嵌套。

- 绝对形式：以斜杠开头，部署到固定子目录时最直观，路径变化需要改配置。
- 相对形式：以点开头，适合路径不确定或产物被放在任意层级访问的场景。
- 嵌套风险：相对形式下页面被路由嵌套时地址基准会变化，容易加载失败。
- 推断形式：让运行时按脚本自身位置拼接，兼顾不确定部署与资源定位。
- 判定依据：部署位置固定用绝对形式，任意层级访问用相对或推断形式。

```text
/static/js/main.a1b2c3d4.js    绝对形式：部署路径固定
./js/main.a1b2c3d4.js          相对形式：随页面位置变化
auto                           推断形式：按脚本位置拼接
```

> 单页应用通常把路由交给前端处理，深层路由下相对形式的基准会变化，这类项目更适合绝对形式或推断形式。

**速记**：部署路径固定用绝对形式，任意层级访问用相对或推断形式，深层路由慎用相对形式。
