## 模块化与打包原理

### 模块格式 ESM 与 CJS 与 UMD

打包器首先要认得的不是语法，而是模块格式：格式决定了依赖关系能否在构建期确定。本节从打包视角比较三种格式的写法与可分析程度。

#### ESM 的语法与特征

**ESM（ECMAScript Modules）**：是语言标准定义的模块格式，使用导入与导出语句声明依赖，依赖关系在解析阶段即可静态确定。

- 静态结构：导入导出语句必须位于顶层，依赖关系在代码执行前就可分析。
- 绑定特性：导出的是值的引用绑定，导出方更新后导入方看到的值同步变化。
- 严格模式：模块代码默认运行在严格模式下，顶层 this 为 undefined。
- 加载方式：浏览器与 Node.js 均可原生加载，浏览器需以模块方式引入脚本。
- 打包价值：静态可分析是摇树优化与代码分割能够成立的前提。

```js
// src/math.js
export const PI = 3.14159;
export function double(value) {
  return value * 2;
}
```

```js
// src/index.js
import { PI, double } from "./math.js";
console.log(double(PI)); // 6.28318
```

> 模块的加载规则、解析细节与包内入口字段详见 后端/Node 主题第 4 篇，此处只从打包视角讨论格式差异。

**速记**：ESM 静态可分析、导出为引用绑定、默认严格模式，是摇树与分割的前提。



#### CJS 的语法与特征

**CJS（CommonJS）**：是 Node.js 早期采用的模块格式，通过 require 同步加载模块、通过 module.exports 暴露接口。

- 动态加载：require 是函数调用，可以出现在条件分支里，依赖关系需运行时才能确定。
- 值拷贝：导出的对象属性在导出时刻取值，重新赋值导出变量不会同步给导入方。
- 同步执行：加载时同步读取并执行目标模块，不适合需要异步获取的浏览器环境。
- 生态存量：大量既有 npm 包以该格式发布，打包工具需要同时兼容两种格式。
- 分析上限：静态分析对 CJS 只能做有限推断，这是混合依赖下摇树失效的主要原因之一。

```js
// src/legacy.js
const os = require("os");
function describePlatform() {
  return os.platform();
}
module.exports = { describePlatform };
```

```js
// src/use-legacy.js
const { describePlatform } = require("./legacy.js");
console.log(describePlatform()); // "darwin"
```

> CJS 与 ESM 在同一个进程内混用有额外限制，导入前应确认目标环境与依赖的出口格式。

**速记**：CJS 动态加载、导出为值拷贝、同步执行，静态分析只能做有限推断。



#### UMD 与格式互操作

**UMD（Universal Module Definition）**：是一种同时兼容 CJS、AMD 与全局变量的包装写法，让同一个文件在多种加载环境中可用。

- 包装结构：先判断当前环境是否存在模块系统，再选择对应的导出方式。
- 使用场景：浏览器直接引入脚本、老式构建链与部分库产物仍会采用。
- 体积代价：包装代码增加了额外体积，也无法被静态分析识别为纯 ESM。
- 互操作方向：ESM 导入 CJS 相对容易，CJS 导入 ESM 在现代 Node.js 中受限制。
- 处理方式：打包器在遇到混合格式时插入互操作辅助代码，产物因此略大。

```js
(function (root, factory) {
  if (typeof module === "object" && module.exports) {
    module.exports = factory();
  } else {
    root.myLib = factory();
  }
})(typeof self !== "undefined" ? self : this, function () {
  return { version: "1.0.0" };
});
```

> [!NOTE]
> **提醒内容**：互操作只能在打包工具或运行时支持的范围内进行，跨格式导入前先确认目标环境与版本，不要假定两种格式可以任意混用。

**速记**：UMD 兼容多环境但体积更大，ESM 导入 CJS 容易，反向导入受运行环境限制。



### 依赖图与入口

打包的本质是沿引用关系走一遍图。本节说明这张图怎样建立、起点如何指定，以及节点用什么标识符定位。

#### 依赖图的构建过程

**依赖图（dependency graph）**：是由模块作为节点、导入关系作为有向边构成的图，打包器沿该图收集全部需要打包的模块。

- 起点：从入口文件开始解析导入语句，得到第一层直接依赖。
- 递归：对每个依赖继续解析其依赖，直到没有新的模块加入为止。
- 转换：每个模块在入图前先交给转译器处理，输出可拼接的代码。
- 去重：同一模块只保留一份节点，多处引用指向同一节点，避免重复执行。
- 收敛判定：当一轮解析不再产生新节点时，依赖图构建完成。

```js
// src/main.js        入口
import { createApp } from "./app.js";
import { formatDate } from "./utils/date.js";
```

```js
// src/app.js        被入口与页面共同引用，在图中只有一个节点
import { formatDate } from "./utils/date.js";
export function createApp(root) {
  root.textContent = formatDate(new Date());
}
```

> 依赖图是构建的核心中间产物，代码分割与摇树都在它之上做判断。

**速记**：依赖图从入口出发递归解析导入关系，同模块只保留一个节点，直至收敛。



#### 入口与多入口

**入口（entry）**：是打包器开始解析依赖图的起始模块，一个项目可以有多个入口以生成彼此独立的产物。

- 单入口：常规应用以一个脚本为入口，产物对应一个页面。
- 多入口：多页面应用为每个页面各配一个入口，公共依赖可提取为共享产物。
- 库入口：库产物常同时输出多种模块格式，并通过清单字段声明各自路径。
- 命名影响：入口名会影响输出文件名，需要与清单字段保持一致。
- 公共提取：多入口共享的依赖若不提取，会被复制进多个产物。

```json
{
  "name": "my-lib",
  "main": "./dist/index.cjs",
  "module": "./dist/index.js",
  "exports": {
    ".": {
      "import": "./dist/index.js",
      "require": "./dist/index.cjs"
    }
  }
}
```

> 入口数量与产物数量不是一一对应：启用公共提取或动态导入后，一个入口也可能产出多个代码块。

**速记**：入口决定图的起点，多入口各出产物，公共依赖需提取以免被重复复制。



#### 解析规则与模块标识符

**模块标识符**：是导入语句中写在来源位置、用于定位目标模块的字符串，分为相对路径、绝对路径与包名三类。

- 相对标识符：以点开头，相对当前文件解析路径，如 ./utils/date.js。
- 包名标识符：不以点开头，从依赖目录逐级向上查找，如 vue。
- 扩展名补全：多数打包器允许省略扩展名，按既定顺序尝试候选文件。
- 路径别名：通过别名把长路径映射为短前缀，减少相对路径的层级。
- 目录入口：指向目录时按该目录下的入口声明或默认文件名解析。

```js
// src/main.js
import { formatDate } from "./utils/date.js";   // 相对路径
import { createApp } from "vue";                // 包名
import { apiClient } from "@/api/client.js";    // 别名
```

> 解析失败的报错通常出在标识符这一层，排查时先确认它是相对路径、包名还是别名，再检查对应规则。

**速记**：标识符分相对路径、绝对路径与包名三类，别名与扩展名补全属于解析规则。



### 编译与打包与压缩的差别

三者常被统称为「构建」，但处理粒度与作用完全不同。本节按粒度从细到粗依次说明编译、打包与压缩。

#### 编译与转译

**编译（compile）**：是把源码按语法规则转换为目标代码的过程；在构建链中指语法降级与类型移除，通常以文件为单位进行。

- 处理粒度：以单个文件为单位，不关心文件之间的引用关系。
- 典型工具：类型检查器移除类型，转译器做语法降级，样式处理器转换样式语法。
- 输出形态：输入一个文件输出一个文件，文件结构保持不变。
- 与打包的关系：编译是打包的前置步骤，打包器在模块入图前调用编译环节。
- 独立性：编译可以脱离打包单独运行，用于类型检查或产物预览。

```bash
npx tsc --noEmit
# 只做类型检查，不产出文件
npx babel src --out-dir lib
# lib 目录与 src 目录结构一致，只是语法被改写
```

> 编译产物仍是「一文件对一文件」，所以它无法解决请求数与缓存问题，那些属于打包的职责。

**速记**：编译逐文件改写语法，结构不变，是打包的前置步骤，可独立运行。



#### 打包：模块链接与包裹

**打包（bundle）**：是把依赖图中所有模块按运行顺序组织进少量产物文件的过程，核心动作是模块链接与包裹。

- 模块链接：为每个模块分配标识，把导入语句替换为对模块表的读取。
- 包裹隔离：把模块代码放入函数包裹，使各自的局部作用域互不干扰。
- 引导代码：产物中保留一小段负责按需执行模块的运行时引导逻辑。
- 作用域提升：在条件允许时把多个模块合并进同一作用域，进一步减小体积。
- 产物形态：最终文件不再是原样的模块文件，而是模块表加引导代码。

```js
// 产物的简化结构示意
const modules = {
  "./src/math.js": (exports) => {
    exports.double = (value) => value * 2;
  },
  "./src/index.js": (exports, require) => {
    const math = require("./src/math.js");
    console.log(math.double(3)); // 6
  },
};
```

> 打包改变了代码的组织形态，调试线上产物时需要借助来源映射把位置还原到源码。

**速记**：打包把依赖图链接为模块表并附加引导代码，产物形态与源码结构不再对应。



#### 压缩与体积优化

**压缩（minify）**：是在不改变程序语义的前提下缩短代码体积的处理，包括删除空白与注释、缩短局部名与移除死代码。

- 空白与注释：直接删除，对执行结果没有影响。
- 标识符缩短：局部变量名替换为短名，减少字符数。
- 常量折叠：在构建期计算可确定的表达式，直接替换为结果。
- 死代码消除：移除条件恒假的分支与永不执行的语句。
- 传输压缩：gzip 或 brotli 在传输层再次压缩，与压缩工具叠加生效。

```bash
# 三种体积口径
# 未压缩   142.31 kB
# 压缩后    48.90 kB
# gzip 后   16.20 kB
```

> [!WARNING]
> **警告内容**：压缩后的产物无法直接阅读，定位线上问题必须依赖来源映射文件，且来源映射不应随产物公开发布。

**速记**：压缩做删除、缩短与折叠，传输压缩另算一层，线上定位依赖来源映射。



### 代码分割与按需加载

打包并非把所有代码塞进一个文件。本节说明为什么要拆、怎么拆，以及拆开之后如何控制加载时机。

#### 为什么需要代码分割

**代码分割（code splitting）**：是把产物拆成多个代码块、让浏览器按需加载其中一部分的处理，目的是避免首屏加载与当前页面无关的代码。

- 体积问题：所有代码打进一个文件，首屏必须下载并解析全部内容。
- 缓存问题：任一改动都会改变整个产物的哈希，导致缓存整体失效。
- 加载问题：无关模块占用带宽与解析时间，拖慢首屏可交互时间。
- 解决方向：按路由或功能边界切块，把非首屏代码移出主产物。
- 判断依据：合并所有代码块体积对比单产物体积，差值即被推迟的部分。

```bash
# 单产物与分割后的体积对照
# 单产物   index.js   820 kB
# 分割后   index.js   210 kB
#          vendor.js  480 kB
#          report.js  130 kB
```

> 分割的目标不是让产物变小，而是让首屏不必加载暂时用不到的代码。

**速记**：代码分割按路由或功能边界切块，让首屏只加载当下需要的部分。



#### 分割方式：入口分割与动态导入

**动态导入（dynamic import）**：是在代码执行到该语句时才加载目标模块的导入写法，通常返回一个 Promise。

- 入口分割：配置多个入口，各入口产物天然分离，适合多页面应用。
- 动态导入：在需要处调用导入表达式，打包器据此切出独立代码块。
- 共享提取：被多个代码块共用的模块提取为公共代码块，避免重复打包。
- 触发命名：可给切出的代码块指定名称，便于在产物目录中辨认。
- 路径约束：动态路径必须能在构建期推断出候选范围，否则切块会失败或错乱。

```js
// src/router.js
async function loadReportPage() {
  const module = await import("./pages/report.js");
  return module.renderReport();
}

loadReportPage().then((node) => console.log(node));
```

> 完全由变量拼出的动态路径会让打包器无法枚举候选模块，此时应改用固定前缀加可控后缀的写法。

**速记**：入口分割天然分离，动态导入按需切块，公共模块需提取以免重复打包。



#### 懒加载与预加载提示

**懒加载（lazy loading）**：是把代码块的请求推迟到真正需要时再发起的策略；**预加载（preload）**：是提前声明后续会用到、让浏览器在空闲时先行获取的提示。

- 懒加载：适合低频功能与体积较大的模块，如报表、编辑器、地图。
- 预加载：适合即将跳转的路由，提前拉取可减少切换时的等待。
- 预取：在浏览器空闲时以较低优先级获取，不占用关键加载时间。
- 预加载模块：模块脚本可用 modulepreload 声明，避免重复解析依赖。
- 代价控制：过度预加载会抢占带宽，抵消懒加载带来的收益。

```html
<link rel="modulepreload" href="/assets/report-3c9d0a.js">
<link rel="prefetch" href="/assets/editor-8f2c1d.js" as="script">
```

> [!TIP]
> **建议内容**：先用体积分析确认哪些代码块占比最大，再决定对它们懒加载还是预加载，不要对所有代码块统一处理。

**速记**：懒加载推迟请求，预加载提前获取，预取在空闲时进行，过度预加载会适得其反。



### 摇树优化的成立条件

摇树是打包器最有收益也最容易失效的优化。本节说明它的原理、成立条件与常见失效场景。

#### 摇树的原理

**摇树优化（tree shaking）**：是依据静态分析结果删除未被引用导出的处理，前提是打包器能确定模块的导入导出关系。

- 分析对象：模块声明的导出符号与消费方实际引用的符号。
- 删除依据：导出存在但没有任何消费方引用，且删除不影响副作用时移除。
- 标记方式：打包器在模块内部标记引用计数，计数为零的导出可安全删除。
- 优化效果：未被引用的导出既不出现在产物中，也不参与体积计算。

```js
// src/utils.js
export function usedHelper(value) {
  return value + 1;
}
export function unusedHelper(value) {
  return value - 1;
}
```

```js
// src/index.js：只引用其中一个导出
import { usedHelper } from "./utils.js";
console.log(usedHelper(41)); // 42
// 产物中 unusedHelper 被移除
```

> 导入导出关系无法确定时，打包器只能保守处理，保留整份代码。

**速记**：摇树按引用计数删除未被引用的导出，前提是依赖关系能被静态分析。



#### 生效条件

**副作用（side effect）**：是模块在被导入时除导出定义之外对外部产生的可观察影响，如修改全局对象、注入样式。

- 必须为 ESM：CJS 的导出是运行时对象，静态分析无法确定引用了哪些成员。
- 副作用声明：在清单中用 sideEffects 字段标明哪些文件有副作用，其余可安全删除。
- 包的粒度：依赖需提供 ESM 入口并正确声明副作用，否则摇树难以生效。
- 构建模式：开发期常保留完整代码以便调试，摇树效果应在构建期观察。

```json
{
  "name": "my-lib",
  "module": "./dist/index.js",
  "sideEffects": ["*.css", "./src/polyfill.js"]
}
```

> 声明 sideEffects 为 false 表示所有文件均无副作用；若实际存在样式注入等副作用，会被误删并导致功能缺失。

**速记**：摇树要求 ESM 格式与正确的副作用声明，具体成员引用比整体引入更利于分析。



#### 常见失效场景

**摇树失效**：是静态分析无法确定引用关系或误判副作用，导致无用代码未能被删除的情形。

- 格式不纯：依赖只提供 CJS 产物，分析只能退化为整体引入。
- 副作用误判：样式文件或补丁代码被标记为无副作用而被错误删除。
- 顶层副作用：模块在被导入时就执行初始化逻辑，无法安全删除。
- 包装写法：通过默认导出整体取属性，引用关系较难静态确定。
- 重复导出：同一符号经多层转发导出，增加了分析链路的长度。

```js
// 引用关系明确，便于摇树
import { double } from "./math.js";

// 通过默认导出整体取属性
import mathUtils from "./math.js";
console.log(mathUtils.double(3)); // 6
```

> [!IMPORTANT]
> **重要内容**：摇树效果取决于依赖包的产物格式与副作用声明，不能只靠应用侧的导入写法，接入前应先确认依赖是否提供 ESM 入口。

**速记**：格式不纯、副作用误判、顶层副作用与整体取属性都会让摇树失效。
