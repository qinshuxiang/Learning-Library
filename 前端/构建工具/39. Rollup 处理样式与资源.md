## Rollup 处理样式与资源

### 样式插件的接入

#### 样式插件的职责与形态

**样式处理插件**：是让 Rollup 能读取 CSS 与预处理器文件的插件，它在转换钩子（hook）中把样式内容改写成 JavaScript 模块，或登记为独立产物。

- 解决的问题：Rollup 核心只理解 JavaScript，导入样式文件会因无法解析而报错。
- 改写形态：把样式内容包成导出字符串的 JS 模块，或转成注入样式的副作用模块。
- 触发位置：多数插件挂载在 transform 钩子上，按文件扩展名过滤出样式文件。
- 返回结构：返回含 code 与 map 的对象，映射缺失会让样式相关报错定位不准。
- 附加能力：编译预处理器、补全浏览器前缀、压缩样式等，都由同一插件或其配套选项承担。

```js
// 最小样式插件：把 CSS 转成注入样式的 JS 模块
const inlineStylePlugin = () => ({
  name: "inline-style",
  transform(code, id) {
    if (!id.endsWith(".css")) return null;
    return {
      code: `const css = ${JSON.stringify(code)};
const el = document.createElement("style");
el.textContent = css;
document.head.append(el);
export default css;`,
      map: null,
    };
  },
});
```

> [!IMPORTANT]
> **重要内容**：没有样式插件时，任何 CSS 导入都会以无法解析的报错中断构建，样式必须经插件转成 JavaScript 或登记为产物才能进入模块图。

**速记**：样式插件把 CSS 改写成 JS 模块或独立产物，是样式进入模块图的唯一通道。



#### 与转换阶段的配合

**转换阶段的配合**：是样式插件与其他转换插件在同一 transform 钩子上的先后关系，样式模块一旦生成即进入后续转换链。

- 顺序要求：样式插件应排在会改写 JS 的转换之前，避免注入代码被当作普通业务代码处理。
- 过滤边界：样式插件只应处理样式文件，转换插件也只应处理 JS，两者用扩展名划清范围。
- 映射衔接：样式插件返回的映射要沿链路传递，压缩与后处理才能把位置还原到样式源文件。
- 依赖解析：样式文件中的相对引用由样式插件自行处理，不会触发 Rollup 的模块解析。
- 副作用声明：注入型样式模块带副作用，不能让后续树摇优化把它当作无用代码删除。

```js
import { defineConfig } from "rollup";

export default defineConfig({
  input: "src/index.js",
  output: { file: "dist/index.js", format: "es" },
  plugins: [
    inlineStylePlugin(),          // 样式先转成 JS 模块
    transpilePlugin(),            // 再对全部 JS 模块做语法转换
  ],
});
```

> 样式模块与业务模块在同一条转换链上，插件顺序错位通常不报错，只表现为注入代码被多余转换或映射偏移。

**速记**：样式插件排在 JS 转换之前，用扩展名划清处理范围，并保证映射沿链传递。



#### 预处理器与后处理的接入

**预处理器接入**：是在构建期把预处理器文件编译为 CSS、再交由样式插件统一处理的做法；**后处理接入**：是在 CSS 生成后追加前缀、降级新语法等处理的做法。

- 编译位置：预处理器编译发生在样式插件的转换之前，插件通过选项把编译参数透传出去。
- 配置来源：预处理器自身的配置文件仍按工具约定读取，构建配置只负责指向该文件。
- 后处理顺序：后处理接收的是编译后的 CSS，先编译后处理是固定次序。
- 选项透传：插件一般提供一组选项用于开启编译与后处理，取值按插件文档填写。
- 边界：预处理器的语法、变量与嵌套规则属于样式语言本身，不在构建配置的讨论范围内。

```js
export default {
  input: "src/index.js",
  output: { file: "dist/index.js", format: "es" },
  plugins: [
    stylePlugin({
      compile: { sourceMap: true },        // 预处理器编译，具体字段以插件文档为准
      postcss: { config: "./postcss.config.mjs" },
      extract: false,
    }),
  ],
};
```

> [!NOTE]
> **提醒内容**：预处理器的编译配置由样式工具自己读取一份配置文件，构建配置里的同名选项如果与之冲突，最终以插件文档说明的优先级为准。

**速记**：先编译预处理文件再统一后处理，选项经插件透传，语法细节归样式主题。



### CSS 提取与注入

#### 随 JS 注入的产出形态

**样式注入**：是样式插件生成一段在运行期创建样式标签的代码、使样式随 JS 一起加载的产出方式。

- 运行前提：注入代码依赖浏览器环境的文档对象，在服务端或非浏览器环境无法执行。
- 触发时机：模块被求值时立即注入，样式与加载该模块的时机绑定。
- 顺序来源：样式标签的先后取决于模块的求值顺序，即导入关系的展开顺序。
- 重复风险：同一份样式被多个入口模块导入时，每个入口都会各自注入一次。
- 适用场景：单入口应用、开发期调试以及不关心首屏渲染细节的内部工具。

```js
// 注入型产出：样式插件生成的模块等价于下面这段代码
const css = "body { margin: 0; }";
const el = document.createElement("style");
el.textContent = css;
document.head.append(el);
export default css;
```

```text
dist/
└── index.js        业务代码 + 注入样式的代码，无独立样式文件
```

> 注入方式省去一次样式请求，代价是样式在 JS 执行后才生效，首屏可能出现短暂的无样式状态。

**速记**：注入把样式写进 JS 并在运行期插入样式标签，依赖文档对象且样式随模块求值生效。



#### 提取为独立文件

**样式提取**：是样式插件把收集到的样式内容通过产物接口登记为独立资源文件、由页面以链接方式引用的产出方式。

- 登记方式：在产物生成钩子中调用产物接口，以资源类型发出样式文件。
- 内容合并：多个样式模块的内容按收集顺序拼接为一份或多份文件。
- 命名规则：文件名模板可带名称与内容哈希（content hash），哈希随内容变化而变化。
- 引用方式：Rollup 不生成 HTML，样式文件的链接标签由页面模板或上层工具补上。
- 适用场景：服务端渲染、对首屏样式有要求的应用以及只发布样式文件的组件库。

```js
// 提取型产出：收集样式并在产物生成阶段发出独立文件
const extractStylePlugin = () => {
  const styles = new Map();
  return {
    name: "extract-style",
    transform(code, id) {
      if (!id.endsWith(".css")) return null;
      styles.set(id, code);
      return { code: "export default undefined;", map: null };
    },
    generateBundle() {
      const source = [...styles.values()].join("\n");
      this.emitFile({ type: "asset", fileName: "index.css", source });
    },
  };
};
```

> [!WARNING]
> **警告内容**：提取出的样式文件不会自动出现在页面里，缺少链接标签时构建全程无报错，但页面完全无样式，产物核对时必须确认样式文件已被引用。

**速记**：提取把样式登记为独立资源并带内容哈希，链接标签需页面侧自行补上。



#### 两种方式的取舍

**注入与提取的取舍**：是按运行环境、样式体积与缓存诉求在选择产出方式时做的权衡，两者不是能力高低之别。

- 环境判定：存在服务端渲染或非浏览器运行场景时必须提取，注入代码会在服务端报错。
- 体积判定：样式体积较大时提取更利于浏览器并行加载与独立缓存。
- 缓存判定：提取文件可带内容哈希长期缓存，注入则随 JS 一起失效。
- 数量判定：样式较少且只有一个入口时，注入省去一次请求，实现也更简单。
- 混合策略：开发期注入便于热更新，生产构建切换为提取，是常见的双配置做法。

```js
const isProduction = process.env.NODE_ENV === "production";

export default {
  input: "src/index.js",
  output: { dir: "dist", format: "es", assetFileNames: "assets/[name]-[hash][extname]" },
  plugins: [stylePlugin({ extract: isProduction })],
};
```

> 产出方式应随构建环境切换，开发期与生产期用两套配置，而不是让同一种方式兼顾两种场景。

**速记**：服务端与大数据量选提取，单入口小样式可注入，按环境切换最稳妥。



### 资源文件处理

#### 图片与字体的导入方式

**资源导入**：是把图片、字体等非 JavaScript 文件转成可被模块引用的 URL 或内联数据的过程，Rollup 核心不识别这类扩展名。

- 扩展名过滤：资源插件按 .png、.svg、.woff2 这类扩展名识别文件，未识别即报解析失败。
- 读取方式：在加载钩子中按路径读取文件内容，再决定内联还是登记为产物。
- 引用产出：登记为产物后返回一个引用标识，由解析产物地址的钩子换成最终路径。
- 内联产出：体积较小的资源直接转成数据地址内联进代码，不再产生独立文件。
- 字体注意：字体文件往往较大且需要按格式分别提供，通常不做内联。

```js
import { readFileSync } from "node:fs";
import { basename, extname } from "node:path";

const MIME = { ".png": "image/png", ".svg": "image/svg+xml", ".woff2": "font/woff2" };

const assetPlugin = (limit = 4096) => ({
  name: "asset-files",
  load(id) {
    if (!/\.(png|svg|woff2?)$/.test(id)) return null;
    const bytes = readFileSync(id);
    if (bytes.byteLength <= limit) {
      const mime = MIME[extname(id)] ?? "application/octet-stream";
      return `export default "data:${mime};base64,${bytes.toString("base64")}";`;
    }
    const referenceId = this.emitFile({ type: "asset", name: basename(id), source: bytes });
    return `export default import.meta.ROLLUP_FILE_URL_${referenceId};`;
  },
});
```

> 引用标识由插件在加载阶段登记，最终地址在输出阶段才确定，因此插件必须返回引用占位而不是写死的相对路径。

**速记**：资源插件按扩展名识别文件，小体积转数据地址，大体积登记为产物并返回引用占位。



#### 产物目录与文件名规则

**资源文件名规则**：是输出配置中 assetFileNames 指定的命名模板，决定资源在产物目录中的位置与是否带内容哈希。

- 模板变量：名称、哈希与扩展名三类占位符组合出最终文件名。
- 目录前缀：在模板前加目录名即可把资源集中到独立子目录，便于部署时单独设置缓存。
- 哈希作用：同一名称内容变化时文件名随之变化，浏览器缓存随之失效，这是内容哈希的核心用途。
- 与脚本区分：脚本类产物由 chunkFileNames 与 entryFileNames 分别控制，互不影响。
- 清理策略：开启哈希后旧文件不会被自动清除，构建前需清空产物目录。

```js
export default {
  input: "src/index.js",
  output: {
    dir: "dist",
    format: "es",
    entryFileNames: "[name].js",
    chunkFileNames: "chunks/[name]-[hash].js",
    assetFileNames: "assets/[name]-[hash][extname]",
  },
};
```

```text
dist/
├── index.js
├── index.css
└── assets/
    ├── logo-1a2b3c4d.svg
    └── font-5e6f7a8b.woff2
```

> 内容哈希命名与产物清理必须配套，只加哈希不清目录会让每次构建都在旧文件之上叠加。

**速记**：assetFileNames 决定资源目录与哈希，配套构建前清理才不会堆积旧文件。



#### 资源路径与引用

**资源路径**：是产物中引用资源时使用的地址，其形式取决于产物被谁消费以及部署目录如何映射。

- 相对路径：产物内部互相引用用相对路径，适合整目录原样部署，但被消费方再打包时容易失效。
- 绝对路径：以站点根为起点书写，需要部署时保证目录映射与书写一致。
- 外部化引用：样式或脚本引用的第三方地址属于外部化（external）范畴，不参与产物路径计算。
- 消费方差异：供打包器消费的库产物应保持可解析的相对引用，供浏览器直引的产物通常用绝对路径。
- 核对方式：构建后按产物目录逐级检查资源是否存在，再确认引用路径能被目标环境解析到。

```text
引用形态对照
./assets/logo-1a2b3c4d.svg      相对，随目录整体搬迁
/assets/logo-1a2b3c4d.svg       绝对，要求部署在站点根
https://cdn.example.com/...     外部地址，不参与产物计算
```

> [!CAUTION]
> **注意内容**：库产物中使用绝对路径引用资源，会让使用方在其自身部署路径下取不到文件，库产物应优先保持相对引用。

**速记**：库产物用相对引用、浏览器直引用绝对路径，构建后必须按目录核对资源是否存在。



### 资源内联与体积

#### 内联的条件与阈值

**资源内联**：是把资源内容转成数据地址直接写进 JS 或 CSS 的产出方式，通常按字节数阈值决定是否内联。

- 阈值判断：常见做法是设置一个字节上限，未超过即内联，超过则登记为独立产物。
- 类型判断：矢量图与图标字体适合内联，位图与字体文件通常不内联。
- 引用次数：只被引用一次的小图适合内联，被多处引用时独立文件更省总量。
- 编码开销：内联会把二进制内容按基数 64 编码，体积约增大三分之一。
- 配置位置：阈值一般作为资源插件的选项传入，取值按插件文档与项目实测确定。

```js
export default {
  input: "src/index.js",
  output: { dir: "dist", format: "es" },
  plugins: [assetPlugin({ inlineLimit: 4096 })],   // 小于 4 KB 内联，其余独立成文件
};
```

> [!WARNING]
> **警告内容**：阈值设得过大，会把本应独立缓存的图片与字体塞进脚本，首屏体积与解析时间同步上升，阈值应按实际资源分布确定而不是照搬默认值。

**速记**：内联按字节阈值与类型判定，基数 64 编码约增大三分之一体积，阈值需按实测确定。



#### 内联对体积的影响

**内联的体积影响**：是多层叠加的，既包含编码膨胀，也包含无法复用带来的重复。

- 编码膨胀：同一份字节以文本形式表示，体积比原文件大约三分之一。
- 重复写入：同一资源被多个模块内联时，每个模块各持一份内容。
- 压缩无效：已编码的内容无法被压缩插件进一步压缩，压缩收益接近为零。
- 门限效应：阈值附近的资源内联与否可能让产物体积出现阶跃式变化。
- 核对方法：对比内联前后的产物体积与独立资源数量，确认阈值取值合理。

```text
原始图片      8.0 kB
内联后文本   ≈ 10.7 kB    基数 64 编码约放大三分之一
独立文件      8.0 kB      可独立缓存，且随资源哈希单独失效
```

> 判断是否内联不能只看单文件体积，还要乘上引用次数并计入编码膨胀，再与独立文件的总量比较。

**速记**：内联带来编码膨胀与重复写入，且压缩无法回收，核对时按引用次数合并计算。



#### 内联与缓存控制

**内联与缓存**：是相互制约的一对：内联减少请求但把资源绑进宿主文件，独立文件便于缓存但多一次请求。

- 缓存粒度：独立资源各自带内容哈希独立失效，内联资源只能随宿主文件整体失效。
- 命中效率：图标类资源极少变化，独立成文件后长期命中缓存，收益高于省下的一次请求。
- 更新代价：内联资源变化会连带宿主脚本的哈希变化，让整份脚本的缓存失效。
- 请求数量：内联省去的是请求往返，在长连接复用下收益有限，体积代价却持续存在。
- 判定顺序：先看资源是否稳定、是否多处引用，再决定内联还是独立，而不是只看体积小。

```js
// 稳定且多处引用的小图标独立成文件，随内容哈希长期缓存
export default {
  input: "src/index.js",
  output: { dir: "dist", format: "es", assetFileNames: "assets/[name]-[hash][extname]" },
  plugins: [assetPlugin({ inlineLimit: 0 })],
};
```

> 内联与独立文件的选择本质是缓存粒度之争，把稳定资源独立出去、让易变资源跟随宿主，是常见的划分方式。

**速记**：内联牺牲缓存粒度换请求数，稳定且多处引用的资源应独立并带内容哈希。



### 样式产物的常见问题

#### 样式引用丢失

**样式引用丢失**：是构建完成却查不到样式产出或样式未生效的现象，成因多在插件未登记产物或副作用被误判。

- 未登记产物：样式插件只在转换阶段改写内容，未在产物生成阶段发出文件。
- 副作用误判：包的副作用标记为无副作用时，仅导入样式的语句会被树摇优化移除。
- 入口遗漏：样式只被未参与本次构建的文件导入，模块图里根本不存在该样式模块。
- 定位方法：先确认产物目录中是否存在样式文件，再确认入口链路里是否存在样式导入。
- 修复方向：补齐产物登记，或在包配置中声明样式文件带副作用。

```json
{
  "name": "my-lib",
  "sideEffects": ["*.css", "*.scss", "dist/index.css"]
}
```

> [!IMPORTANT]
> **重要内容**：把仅导入样式的语句视为无用代码删除，会让样式在构建阶段静默消失且不产生任何警告，声明样式文件带副作用是避免该问题的标准做法。

**速记**：样式丢失先查产物再查入口链路，常见成因是未登记产物或副作用被误判。



#### 资源路径错误

**资源路径错误**：是产物内引用的样式或资源地址在目标环境下无法解析的现象，通常不报构建错误，只在运行时暴露。

- 基准不同：构建时按输出目录计算，部署后按页面地址计算，两者不一致即失效。
- 目录搬迁：产物目录被移动到其他层级时，相对路径的基准随之变化。
- 绝对路径前提：书写绝对路径要求部署在约定的站点根，部署到子目录即失效。
- 消费方再打包：库产物被消费方再次打包时，路径基准由消费方决定，不能写死。
- 核对方法：在目标部署路径下逐个打开产物引用的资源，确认全部可访问。

```text
构建输出：dist/assets/logo-1a2b3c4d.svg
代码引用：./assets/logo-1a2b3c4d.svg
部署后：  文件位于 /app/sub/assets/... ，页面位于 /app/sub/
```

> [!CAUTION]
> **注意内容**：资源路径错误不会在构建期暴露，只有在目标部署路径下实际访问才会失败，发布前应在接近生产的路径下验证一次。

**速记**：路径基准在构建与部署两处不同，库产物不写死路径，发布前按部署路径验证。



#### 顺序不确定与重复

**样式顺序与重复**：是样式在注入或合并后出现先后次序与预期不符、同一份样式出现多次的现象，根源在模块求值顺序与多入口。

- 顺序来源：注入顺序即模块求值顺序，合并顺序即样式收集顺序，两者都依赖导入关系。
- 不确定原因：模块图的遍历顺序在插件或配置变化后可能改变，样式先后随之变化。
- 重复来源：多个入口各自导入同一份样式，各自注入或各自提取一次。
- 覆盖风险：顺序变化会让同权重选择器的覆盖关系反转，表现为样式结果与预期不符。
- 处理方向：把基础样式与覆盖样式分开组织，并由显式导入顺序固定其先后。

```js
// 显式固定基础样式的导入顺序，覆盖样式紧随其后
import "./styles/base.css";
import "./styles/layout.css";
import "./styles/theme.css";
```

> 依赖遍历顺序来保证样式先后是脆弱的，把关键顺序写成显式导入语句，才不会因插件或配置变化而漂移。

**速记**：样式顺序取自模块求值与收集顺序，多入口易重复，关键顺序用显式导入固定。
