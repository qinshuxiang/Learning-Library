## 参考资料与延伸阅读

### 官方文档

#### Vite 官方文档

**Vite 官方文档**：是 Vite 配置项与插件 API 的权威出处，地址为 vite.dev。

- 配置参考按 server、build、resolve、optimizeDeps 等分组，逐项给出类型与默认值。
- 插件 API 页面说明各钩子的名称、调用时机与返回值约定。
- 迁移指南记录大版本之间的破坏性变更，升级前应先通读对应条目。

> 配置行为与文章描述不一致时，以官方配置参考的当前版本为准；中文文档可能滞后于英文原版。

**速记**：配置项与钩子以 vite.dev 为准，中文版滞后时对照英文。



#### webpack 官方文档

**webpack 官方文档**：是 loader、plugin 与优化配置的权威出处，地址为 webpack.js.org。

- Concepts 章节用最小示例讲清 entry、output、loader、plugin 四个核心概念。
- Configuration 章节逐项列出优化开关与默认值，是排查配置写法的第一入口。
- 官方博客发布大版本变更说明与迁移指引。

> webpack 各版本配置差异较大，查阅前先确认文档标注的版本与项目依赖版本一致。

**速记**：查 webpack 先对版本号，概念从 Concepts 章节入手。



#### esbuild 与 SWC 文档

**esbuild 与 SWC 文档**：指这两款转译与压缩工具的官方文档，用于核对构建选项与降级配置。

- esbuild：esbuild.github.io，以 API 页面列出构建选项与增量构建接口。
- SWC：swc.rs，覆盖转译与压缩配置，并提供与 Babel 配置项的对照说明。

> 两者都提供在线试验场，单条配置的产物变化可以直接观察，不必反复本地构建。

**速记**：esbuild 看构建选项，SWC 看与 Babel 的对照。



#### Rollup 官方文档

**Rollup 官方文档**：是插件钩子、输出格式与树摇行为的权威出处，地址为 rollupjs.org。

- 插件钩子页面按构建阶段与输出阶段分组列出钩子名、调用时机与返回值约定，是自研插件的第一依据。
- 配置参考逐项说明 input、output、external 与 treeshake 的类型与默认值。
- 教程章节给出打包一个库的最小完整示例，可直接作为库项目的起点。

> 钩子的调用时机与返回值约定以文档当前版本为准，不同大版本之间签名有过变更，升级前先读迁移说明（详见本主题第 37 篇 Rollup 插件机制与钩子）。

**速记**：Rollup 查钩子看插件页面，查产物看 output 参考，升级先读迁移说明。



#### 规范工具链文档

**规范工具链文档**：指 Babel、PostCSS、ESLint、Prettier 的官方文档，用于核对转译规则与检查规则的接入方式。

- Babel：babeljs.io，preset-env 与 browserslist 的配合方式在 preset 页面说明。
- PostCSS：postcss.org，插件机制与 autoprefixer 的配置项齐全。
- ESLint：eslint.org，含平面配置的迁移指南；Prettier：prettier.io，列出两者分工与冲突处理方式。

> 格式化与静态检查的规则冲突，应按官方文档给出的关闭规则清单处理，不要逐条试错。

**速记**：Babel 看 preset，ESLint 看平面配置迁移，冲突看官方清单。



#### Gulp 官方文档

**Gulp 官方文档**：是任务 API、gulpfile 写法与插件规范的出处，地址为 gulpjs.com。

- API 页面列出 src、dest、series、parallel 与 watch 的参数与返回值约定，是写任务的第一依据。
- 文档给出的示例 gulpfile 覆盖从读入到写出的完整任务链，可直接对照改造。
- 插件编写约定说明插件应遵守的流规范，对排查插件兼容问题有帮助。

> Gulp 插件多由社区维护，包名与维护状态需在安装前自行核对，官方文档只规定插件应遵守的流规范（详见本主题第 49 篇 Gulp 常用插件清单）。

**速记**：Gulp 查任务 API 以官方文档为准，插件质量自行核对。



### 规范与提案

#### ECMAScript 与 TC39 提案

**TC39 提案仓库与 ECMAScript 规范**：决定语言语法的可用性，规范文本在 tc39.es。

- 提案分五个阶段，进入阶段 4 才会纳入正式标准。
- 判断语法能否使用看两点：提案是否达到阶段 4，目标运行环境是否已实现。
- 模块相关提案（顶层 await、import 属性）的最新状态在此查询。

> 构建工具能降级语法，但不能凭空实现新语义；新语法落在旧运行时上仍需垫片（详见本主题第 11 篇 Babel 与 PostCSS：转译与语法降级）。

**速记**：语法可用性看提案阶段与运行环境，降级不创造新语义。



#### 模块格式与解析规范

**模块格式与解析规范**：指 ES Module 规范与 Node.js 模块解析文档，前者定义导入导出的静态绑定语义，后者定义解析算法与字段规则。

- Node.js 官方文档的 Packages 章节说明 type、exports、imports 字段的完整规则。
- package.json 的 exports 字段决定依赖对外暴露哪些子路径，是 ERR_PACKAGE_PATH_NOT_EXPORTED 的判据。
- 条件导出的匹配顺序有明确规定，顺序写错会命中错误分支。

> 双格式发布的包必须在 exports 中分别指向 ESM 与 CJS 产物，否则使用方只能按其中一种格式引用。

**速记**：模块解析看 Node 的 Packages 章节，exports 的条件顺序决定命中分支。



#### 依赖与版本规范

**依赖与版本规范**：指语义化版本规范与包管理器的依赖声明文档，用于判断版本范围与实际安装结果。

- semver.org 定义主版本、次版本、修订版的兼容含义，是范围符语义的依据。
- npm 文档的 package.json 章节说明各类依赖字段的差异（详见本主题第 2 篇 包管理与依赖治理）。
- 工作区协议与 pnpm 的工作区文档说明单仓多包内的引用写法（详见本主题第 14 篇 Monorepo 与工作区管理）。

> 范围符只约束版本区间，实际安装结果由锁文件决定；排查依赖问题时先看锁文件再改范围符。

**速记**：版本范围看 semver 规范，实际结果看锁文件。



#### 样式与资源相关规范

**样式与资源规范**：指 CSS 规范中关于导入与分层的规定，以及资源引用的相关标准。

- CSS 规范规定导入语句必须位于其他规则之前，顺序写错时整条语句被忽略。
- 层叠层（@layer）定义样式分层与优先级，是构建期合并样式时的参考。
- URL 与 MIME 类型相关标准决定资源在产物中的引用形式（详见本主题第 7 篇 Vite 构建与产物优化）。

> 样式在打包器中被当作模块处理，语法合法性仍以 CSS 规范为准，构建工具不会自动修正非法顺序。

**速记**：样式语法以 CSS 规范为准，导入语句必须在最前。



### 经典文章与书籍

#### 打包原理的经典文章

**打包原理文章**：指各打包器官方文档中的原理章节，用于建立对依赖图与产物的直觉。

- webpack 的 Concepts 与依赖图页面解释入口、依赖图与 chunk 三者的关系。
- Vite 的 Why Vite 页面说明开发期不打包、构建期打包的取舍。
- esbuild 的 FAQ 说明为何不采用 webpack 的 loader 模型。

> 阅读顺序建议先看 webpack 的依赖图，再看 Vite 与 esbuild 的设计取舍，两代工具链的差异由此清晰。

**速记**：先读依赖图原理，再对照两代工具链的设计取舍。



#### 模块格式演进类文章

**模块格式演进文章**：指介绍 CommonJS 与 ES Module 差异及互操作历史的文章，是排查互操作问题的背景材料。

- 关注三类知识点：导出语义差异、加载时机差异、条件导出规则。
- 包作者视角的双格式发布指南说明如何同时提供两种入口。

> 互操作主题的社区文章数量多且结论不一，判断依据应回到 Node 文档的 Packages 章节。

**速记**：互操作文章的结论回到 Node 文档验证。



#### 中文书籍与系统教程

**中文书籍与系统教程**：指系统讲解打包工具与前端工程化的中文出版物与在线教程。

- 居玉皓《Webpack 实战：入门、进阶与调优》：体系完整，loader 链、插件钩子与打包原理部分仍适用，配置示例基于 webpack 4，需要对照当前版本文档更新。
- 各前端社区的系统专栏可补足实践细节，优先选读近两年更新且标注版本的篇目。

> [!NOTE]
> **提醒内容**：构建工具演进很快，出版物的配置示例常落后一到两个大版本，阅读重点应放在原理与取舍上。

**速记**：旧书读机制，配置以当前版本官方文档为准。



#### 任务式构建的实践文章

**任务式构建的实践文章**：指介绍 Gulp 流水线组织与任务拆分的经验文章，用于借鉴目录约定与任务划分。

- 关注三类知识点：任务如何按资源类型拆分、串行与并行的选择依据、产物指纹与引用替换的落地方式。
- 文章多带特定项目背景，迁移前先确认其任务清单与目录约定是否适用。
- 需要完整流水线时，可直接以本主题第 57 篇的实战结构为骨架，再按项目增删任务。

> 任务式构建没有统一的目录约定，判断一篇文章是否可借鉴，看它的任务边界是否与你的资源类型一一对应。

**速记**：任务文章看拆分思路，结构以项目实际资源类型为准。



### 工具与在线调试

#### 产物体积分析工具

**产物体积分析工具**：是把构建产物的模块体积可视化的工具，用于定位体积异常的来源。

- webpack-bundle-analyzer：适配 webpack，输出可交互的矩形图。
- rollup-plugin-visualizer：适配 Rollup 与 Vite，可导出静态页面便于归档对比。
- source-map-explorer：依据 source map 还原模块占用，适合排查压缩后的体积分布。

> 分析前先关闭内联 source map 并统一压缩器，否则不同构建之间的对比没有意义。

**速记**：体积分析先统一构建条件，再比模块矩形图。



#### 在线打包与语法试验场

**在线试验场**：是在浏览器中直接查看转译与打包结果的工具，用于验证单条配置的效果。

- Babel REPL、TypeScript Playground、Prettier Playground 分别验证转译、类型与格式化结果。
- esbuild 与 SWC 的在线版本可查看语法降级与压缩后的产物。
- 配置改动先在试验场验证，再落地到项目，可减少无效构建次数。

> [!CAUTION]
> **注意内容**：在线工具会把输入内容上传到第三方服务器，公司内部代码与密钥不得粘贴进去。

**速记**：在线试验场只放公开代码，结论以本地构建复现为准。



#### 包体积与依赖查询

**包体积与依赖查询工具**：用于查询依赖体积与依赖树，服务于选型与体积预算。

- bundlephobia 与 bundlejs 查询包在未压缩与压缩后的体积。
- npmgraph 把依赖树渲染为可视图，便于发现重复依赖。
- npm 与 pnpm 的 why 命令在本地解释某个包为何被安装。

> 体积数据随版本变化，选型时以当前版本的查询结果为准，并优先确认该包是否支持摇树优化。

**速记**：选型看体积查询，排查重复依赖看依赖树。



#### 构建诊断与依赖检查

**构建诊断工具**：用于查看构建内部阶段与依赖健康度，定位慢与冗余。

- Vite 的调试选项打印插件与解析过程，性能分析选项输出各阶段耗时。
- webpack 的性能分析与 JSON 输出可生成结构化统计，交给分析器处理。
- madge 检测循环依赖，depcheck 与 knip 找出未被使用的依赖与文件。
- npm audit 与 socket.dev 检查依赖的安全与维护状态。

> 诊断先量化再优化：先拿到耗时或体积数据，再决定改配置还是换工具（详见本主题第 15 篇 构建性能优化与缓存策略）。

**速记**：诊断先量化，再决定改配置或换工具。



### 进阶方向

#### 构建性能与缓存

**构建性能与缓存方向**：以缩短构建时间为目标，涵盖依赖预构建、持久缓存与并行处理。

- 缓存命中率由缓存键决定，环境变量与依赖版本变化都会导致整块缓存失效。
- 增量构建与并行执行是流水线环境的主要收益点。
- 阅读入口：Vite 的依赖预构建与缓存目录文档、webpack 的 cache 配置。

> 优化前先建立耗时基线，否则无法判断改动是否有效（详见本主题第 15 篇 构建性能优化与缓存策略）。

**速记**：缓存收益看命中率，优化前先建耗时基线。



#### 产物优化与运行时性能

**产物优化方向**：以减小产物体积与改善运行时加载为目标，涵盖代码分割、懒加载与资源压缩。

- 分包粒度决定首屏加载量，过细增加请求数，过粗拖慢首屏。
- 压缩开关与资源内联阈值应按资源类型分别设置。
- 阅读入口：Vite 的 build 配置、webpack 的 splitChunks 与 performance 配置。

> 体积指标与运行时指标要一起看：体积变小但请求瀑布变长的方案不可取。

**速记**：分包粒度决定首屏成本，体积与运行时指标一起看。



#### 包作者与发布规范

**包作者方向**：以产出可被正确消费的包为目标，涵盖产物格式、类型声明与导出字段。

- 双格式发布要在 exports 中分别给出 import 与 require 条件，并保证类型声明同时可用。
- publint 与 arethetypeswrong 可检查 package.json 的导出与类型配置是否符合预期。
- 版本发布与变更记录规范决定使用方的升级成本。

> [!WARNING]
> **警告内容**：库产物的入口与类型配置错误不会在本地构建时暴露，只有使用方安装后才会显现，发布前必须用检查工具验证。

**速记**：库产物靠导出条件与类型检查工具把关，不能只在本地自测。



#### 自研插件与工具链内核

**工具链内核方向**：以扩展或替换构建内核为目标，涵盖插件协议、语法树转换与原生加速。

- 插件协议：Rollup 与 Vite 共用一套钩子模型，掌握后可迁移到两者。
- 语法树转换：Babel 与 SWC 提供语法树访问接口，自定义转译规则在此实现。
- 原生加速：esbuild 与 SWC 用原生语言实现解析与压缩，是当前性能优化的主流路径。

> 自研插件前先确认官方插件生态是否已有等价实现，重复实现的维护成本通常高于预期。

**速记**：插件先查官方生态，再做语法树与原生加速层面的扩展。
