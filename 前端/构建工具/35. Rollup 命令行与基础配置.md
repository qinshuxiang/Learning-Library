## Rollup 命令行与基础配置

### 安装与命令行用法

本节从安装讲起，再列出常用命令行参数与三类常见调用方式。

#### 安装方式与版本确认

**本地安装**：是把 Rollup 写入项目开发依赖、由项目自身脚本调用的安装方式，可保证团队与流水线使用同一版本。

- 安装命令：把 rollup 加入开发依赖，不依赖机器上的全局版本。
- 版本确认：调用版本查询参数查看当前可执行文件的版本。
- 调用方式：本地安装后用包运行器临时执行，或写进脚本字段。
- 全局安装：只适合临时试验，团队协作中不推荐。
- 版本锁定：本地安装配合锁文件，可让不同环境落到同一版本。

```bash
npm install --save-dev rollup
npx rollup --version
# rollup vN（以实际安装版本为准）
```

> 项目内本地安装是首选，全局安装的版本会随机器变化，容易造成构建结果不一致。

**速记**：Rollup 装进开发依赖，用包运行器调用，版本由锁文件统一。



#### 常用命令行参数

**命令行参数**：是不写配置文件、直接在命令中给出的构建选项，适合一次性构建与快速验证。

- 入口与输出：输入用 -i 指定，单文件用 -o，目录用 -d。
- 格式与名称：格式用 -f 指定，UMD 与 IIFE 需要 -n 给出全局变量名。
- 依赖外部化：用 -e 把依赖排除在产物外，可重复指定多个。
- 映射文件：用 -m 生成调试映射文件。
- 配置文件：用 -c 读取配置文件，用 -w 进入监听模式。
- 帮助与版本：-h 打印用法，-v 打印版本。

```bash
npx rollup -i src/index.js -o dist/index.mjs -f es -e lodash-es -m
```

```bash
npx rollup -c ./configs/rollup.build.mjs
# 读取非默认路径的配置文件
```

> 命令行参数与配置字段一一对应，能写进配置文件的选项不必长期留在命令行里。

**速记**：-i 入口、-o 单文件输出、-d 目录输出、-f 格式、-e 外部化、-m 映射。



#### 常见命令组合

**命令组合**：是把参数按构建目的拼成的常用调用形式，覆盖验证、发布与监听三类场景。

- 快速验证：只给入口与输出，产出单份 ESM 产物，用于确认依赖解析是否正常。
- 发布构建：读取配置文件，一次产出全部格式。
- 监听重建：配置文件加监听参数，源文件变更后重新构建。
- 环境区分：在命令前赋值环境变量，让配置读取后派生不同产物。
- 脚本封装：把上述命令写进脚本字段，避免每次手敲参数。

```json
{
  "scripts": {
    "build": "rollup -c",
    "dev": "rollup -c -w",
    "build:prod": "NODE_ENV=production rollup -c"
  }
}
```

> [!TIP]
> **建议内容**：把常用命令固化到脚本字段，团队与流水线共用同一入口，可减少参数写法差异带来的构建不一致。

**速记**：验证用临时参数、发布用配置文件、监听加 -w，日常命令固化进脚本字段。



### 基础配置结构

本节说明配置文件的形式、类型辅助方式与两类必填字段。

#### 配置文件的形式与命名

**配置文件**：是导出单个配置对象或配置对象数组的模块文件，Rollup 读取后据此完成构建。

- 默认文件名：rollup.config.mjs 为主，也支持 rollup.config.js。
- 导出形式：导出对象表示一次构建，导出数组表示在同一次调用中完成多次构建。
- 模块格式：以 ESM 写法组织配置，导入插件工厂函数并调用后放入插件列表。
- 路径基准：配置中的相对路径以配置文件所在目录为基准，而非命令执行目录。
- 自定义路径：用 -c 后接路径读取非默认位置的配置文件。

```js
// rollup.config.mjs
export default {
  input: "src/index.js",
  output: { file: "dist/index.mjs", format: "es" },
  plugins: [],
};
```

> 配置内的相对路径以配置文件位置为基准，配置文件被挪动后需同步检查入口与产物路径。

**速记**：配置导出对象或数组，默认名 rollup.config.mjs，相对路径以配置文件位置为基准。



#### defineConfig 的类型辅助

**defineConfig**：是 Rollup 导出的辅助函数，接收配置并原样返回，作用是在编辑器中获得配置字段的类型提示与校验。

- 类型提示：字段名与取值在编辑器内可补全，减少拼写错误。
- 返回原值：仅作类型包装，不影响运行时行为。
- 导出数组：辅助函数同样可包裹配置数组。
- 编辑器支持：类型提示依赖编辑器的语言服务，与构建本身无关。
- 可省略：不用该函数不影响构建结果，配置依然有效。

```js
import { defineConfig } from "rollup";

export default defineConfig({
  input: "src/index.ts",
  output: { file: "dist/index.mjs", format: "es", sourcemap: true },
});
```

```js
// 配置数组同样可以用类型辅助包裹
import { defineConfig } from "rollup";

export default defineConfig([
  { input: "src/index.ts", output: { file: "dist/index.mjs", format: "es" } },
  { input: "src/index.ts", output: { file: "dist/index.cjs", format: "cjs" } },
]);
```

> 类型辅助只改善编写体验，构建行为完全由配置内容决定。

**速记**：defineConfig 只提供类型提示并原样返回配置，不影响构建行为。



#### 输入与输出的必填项

**必填字段**：是构建能够成立的最小配置集合，缺入口无法建立依赖图，缺输出无法生成产物。

- 入口：input 指定依赖图起点，是必填项。
- 输出目标：output.file 或 output.dir 二选一，前者产出单文件，后者产出多文件。
- 输出格式：output.format 决定产物模块规范，缺省时构建会提示需要指定。
- 插件列表：plugins 不是必填项，但解析第三方依赖与转换语法时通常必备。
- 缺失后果：入口缺失报无法解析，输出缺失报未指定产物位置。

```js
export default {
  input: "src/index.js",
  output: {
    file: "dist/index.mjs",
    format: "es",
  },
};
```

> [!IMPORTANT]
> **重要内容**：output.file 与 output.dir 互斥，同时指定或都不指定都会让构建失败，多产物场景必须改用 dir。

**速记**：input 与 output.format 为必填，file 与 dir 二选一，二者互斥。



### 输入与输出选项

本节拆解 input 的三种写法、输出定位字段与常用输出字段。

#### input 的多种写法

**input**：是指定依赖图起点的字段，支持字符串、数组与对象三种写法，写法决定产物的命名来源。

- 字符串写法：单个入口，产物名取自入口文件的基本名。
- 数组写法：多个入口并列，产物的文件名与各自入口同名。
- 对象写法：键为产物名、值为入口路径，可把产物名与源文件名解耦。
- 命名结果：对象写法是控制多入口产物命名的主要手段。
- 基础目录：入口位于深层目录时，产物名默认保留相对路径。

```js
// 对象写法：键即产物中使用的入口名
export default {
  input: {
    index: "src/index.js",
    worker: "src/workers/encode.js",
  },
  output: { dir: "dist", format: "es" },
};
```

> 数组写法省事但命名受文件名约束，需要自定义产物名时改用对象写法。

**速记**：input 可写字符串、数组或对象，对象写法的键直接决定入口产物名。



#### output 的定位字段

**output 的定位字段**：指决定产物落点的 file 与 dir，前者面向单文件，后者面向多文件。

- file：产出单个文件，适合入口唯一且无代码分割的场景。
- dir：产出目录，适合多入口、动态导入与保留模块结构的场景。
- 互斥关系：同一次输出中只能选其一，不可并存。
- 结构保留：配合 preserveModules 等选项可保留源码的模块结构。
- 选择依据：产物只有一个文件选 file，否则选 dir。

```js
export default {
  input: "src/index.js",
  output: {
    dir: "dist",
    format: "es",
    preserveModules: true,
  },
};
```

> 动态导入会额外产生独立块，此时必须使用 dir，否则构建会因为无法确定产物数量而失败。

**速记**：单产物用 output.file、多产物用 output.dir，两者互斥不可并存。



#### output 的常用字段

**output 的常用字段**：是控制产物格式、命名与调试信息的选项集合，与输出目标一起声明。

- 格式：format 取 es、cjs、umd、iife 等值，决定产物使用的模块规范。
- 全局名：name 在 umd 与 iife 下必填，是产物挂到全局对象上的属性名。
- 依赖映射：globals 把外部依赖映射为全局变量名，供 umd 与 iife 使用。
- 导出形态：exports 在 cjs 输出下决定导出方式，named 表示具名导出。
- 映射文件：sourcemap 控制是否生成调试映射，可取布尔值或 hidden 等模式。
- 命名模板：entryFileNames、chunkFileNames、assetFileNames 控制各类产物的文件名。

```js
export default {
  input: "src/index.js",
  output: {
    file: "dist/index.umd.js",
    format: "umd",
    name: "DateKit",
    globals: { "date-fns": "dateFns" },
    exports: "named",
    sourcemap: true,
  },
};
```

> [!CAUTION]
> **注意内容**：umd 与 iife 下遗漏 name 会让产物挂到全局却没有固定属性名，使用方无法稳定引用，必须显式指定。

**速记**：format 定规范、name 与 globals 服务全局产物、exports 定导出形态、命名模板定文件名。



### 监听与增量构建

本节说明监听模式的启用方式、监听范围的控制字段与重建行为。

#### 监听模式的启用

**监听模式（watch）**：是在源文件发生变化时自动重新构建的运行方式，命令行与配置对象都能开启。

- 命令行开启：加 -w 或 --watch 参数，与配置文件一起使用时最方便。
- 配置开启：在配置对象中给出 watch 字段，写入监听相关选项。
- 运行表现：首次构建完成后进程常驻，等待文件变更再重建。
- 退出方式：手动中断进程结束监听。
- 适用场景：本地反复调试产物结构与导出内容。

```bash
npx rollup -c -w
# 首次构建完成后进入监听，源文件变更即重建
```

```js
export default {
  input: "src/index.js",
  output: { file: "dist/index.mjs", format: "es" },
  watch: {
    include: "src/**",
    exclude: "src/**/*.test.js",
  },
};
```

> 监听模式只负责重建产物，不提供开发服务器与页面刷新，页面调试需配合应用侧工具。

**速记**：加 -w 或在配置中写 watch 字段即可进入监听，进程常驻直到手动中断。



#### 监听范围与相关字段

**监听范围**：指 watch 字段中控制哪些文件参与触发重建的配置，范围过宽会带来无谓重建。

- 包含范围：include 限定参与监听的文件匹配范围。
- 排除范围：exclude 排除测试文件、临时文件等不影响产物的路径。
- 清屏行为：clearScreen 控制重建时是否清除终端输出。
- 写入控制：skipWrite 可在只校验产物内容的场景下跳过写盘。
- 延迟合并：buildDelay 把短时间内的多次变更合并为一次重建。
- 底层选项：chokidar 字段把参数透传给文件监听库，用于处理特殊文件系统。

```js
export default {
  input: "src/index.js",
  output: { dir: "dist", format: "es" },
  watch: {
    clearScreen: false,
    buildDelay: 200,
    chokidar: { usePolling: true },
  },
};
```

> 监听范围应收敛到参与产物的源码，把测试与文档目录排除可显著减少无效重建。

**速记**：include 与 exclude 划定范围，clearScreen、buildDelay、chokidar 调整行为。



#### 增量行为与缓存

**增量行为**：是监听模式下只重新构建受影响模块、复用其余分析结果的过程。

- 变更粒度：监听以模块为单位，未受影响的模块复用上次的分析结果。
- 传播范围：被改动模块的引用方会被重新分析与重新生成。
- 结构变化：新增或删除文件会改变依赖图，重建范围随之扩大。
- 缓存作用：进程内缓存只在本次监听会话内有效，重启后重新建立。
- 性能进一步优化：通用清单见本主题第 15 篇，本节只说明监听期的默认行为。

```bash
npx rollup -c -w
# 修改单个模块后，仅受影响部分被重新构建
```

> [!NOTE]
> **提醒内容**：监听期缓存随进程结束而失效，长时间运行后若产物表现异常，重启监听进程可排除缓存因素。

**速记**：监听期按模块增量重建，改动向上传播，进程内缓存随会话结束失效。



### 配置文件的组织

本节说明单文件多产物、按环境派生与配置片段复用三种组织方式。

#### 单文件多产物配置

**单文件多产物配置**：是在一个配置数组中并列多组输入输出、一次命令产出全部目标的组织方式。

- 数组导出：每个数组元素是一份独立配置，构建顺序按数组顺序执行。
- 按格式拆分：同一入口分别声明 ESM 与 CommonJS 两组输出。
- 共享字段：input 与 external 等公共字段在各元素中重复出现，需保持一致。
- 命名区分：产物扩展名与目录按格式区分，便于包入口字段指向。
- 命令简化：一条构建命令覆盖全部产物，减少脚本数量。

```js
export default [
  {
    input: "src/index.ts",
    external: ["vue"],
    output: { file: "dist/index.mjs", format: "es", sourcemap: true },
  },
  {
    input: "src/index.ts",
    external: ["vue"],
    output: { file: "dist/index.cjs", format: "cjs", exports: "named", sourcemap: true },
  },
];
```

> 数组写法的代价是公共字段重复，字段一多就容易出现两份配置不一致。

**速记**：导出配置数组即一次产出多个目标，代价是公共字段需要在各元素间手工保持一致。



#### 按环境派生配置

**按环境派生配置**：是把配置写成函数、依据环境变量返回不同配置对象的组织方式。

- 函数式导出：导出接收命令行参数与环境的函数，返回配置对象或数组。
- 环境读取：从 process 的环境对象中读取构建期注入的变量。
- 分支内容：产物是否压缩、是否生成映射、是否去掉调试代码按环境区分。
- 默认值处理：环境变量缺省时按开发环境处理，避免构建中断。
- 命令行配合：在命令前赋值环境变量，让同一条命令覆盖两种场景。

```js
export default () => {
  const isProduction = process.env.NODE_ENV === "production";
  return {
    input: "src/index.ts",
    output: {
      file: isProduction ? "dist/index.min.mjs" : "dist/index.mjs",
      format: "es",
      sourcemap: isProduction ? "hidden" : true,
    },
  };
};
```

> 函数式导出让同一份配置覆盖多种构建场景，环境判定入口收敛到一处。

**速记**：配置写成函数并按环境变量分支，同一份配置覆盖开发与生产两种产出。



#### 配置片段的拆分与复用

**配置片段复用**：是把公共字段抽成独立模块、由各配置导入合并的组织方式，用于消除数组写法中的重复。

- 抽出公共项：把 input、external 与插件列表抽成共享常量模块。
- 基础配置：导出基础配置对象，各产物在其上展开并覆盖差异字段。
- 函数封装：把按格式生成输出对象封装为函数，减少重复书写。
- 目录约定：配置目录与源码目录分离时，注意相对路径基准随之变化。
- 取舍标准：产物种类少时不必拆分，重复出现三处以上再抽公共片段。

```js
// configs/shared.mjs
export const sharedInput = "src/index.ts";
export const sharedExternal = ["vue"];

export function makeOutput(file, format) {
  return { file, format, sourcemap: true };
}
```

```js
// rollup.config.mjs
import { sharedInput, sharedExternal, makeOutput } from "./configs/shared.mjs";

export default [
  { input: sharedInput, external: sharedExternal, output: makeOutput("dist/index.mjs", "es") },
  { input: sharedInput, external: sharedExternal, output: makeOutput("dist/index.cjs", "cjs") },
];
```

> [!WARNING]
> **警告内容**：把配置拆到子目录后，配置内的相对路径基准仍是配置文件自身所在目录，入口路径需按新位置重写，否则构建直接解析失败。

**速记**：公共字段抽成模块并在基础配置上展开覆盖，重复三处以上才值得拆分。
