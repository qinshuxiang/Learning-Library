## Rollup 的 Tree Shaking 与副作用控制

### 树摇的前提

树摇优化（tree shaking）是打包器依据静态分析结果删除无用代码的优化，它成立与否取决于源码与依赖的形态。本节说明语法前提、静态可分析的含义与破坏它的写法。

#### ESM 的静态结构

**树摇优化（tree shaking）**：是打包器依据静态分析结果，把未被使用且无副作用的代码从产物中删除的优化。

- 前提语法：模块必须使用 ESM 的 import 与 export，导入导出关系写在语法层面。
- 静态结构：导入的绑定名与导出的名称都显式写出，不执行代码即可确定对应关系。
- 对比 CommonJS：require 与 module.exports 可出现在条件分支或在运行期拼装，无法静态确定。
- 发生时机：Rollup 在模块图构建与产物渲染两个阶段裁剪无用代码。
- 边界说明：模块化规范自身的差异见本主题第 3 篇，本篇只从摇树角度切入。

```js
// 命名导出与命名导入，静态可分析
export function formatDate(value) {}
export function formatTime(value) {}

import { formatDate } from "./utils/format.js";
console.log(formatDate(Date.now()));
// formatTime 未被引用且无副作用，会被删除
```

> 摇树的输入是模块的语法结构，语法结构越清晰可删除的范围越大，这与运行时的行为无关。

**速记**：树摇基于 ESM 的静态结构，导入导出在语法层面显式写出才可能被裁剪。



#### 静态可分析的意义

**静态可分析**：是模块的导出与被引用情况在不执行代码的前提下即可完全确定，分析结论与运行结果一致。

- 判断依据：导入导出只出现在模块顶层，路径与名称都是字面量。
- 直接收益：可删除的代码范围在构建期就能算出，无需运行期探测。
- 命名匹配：命名导入能精确到单个绑定，默认导入只能整体保留。
- 副作用前提：可删除的前提是这段代码被判定为无副作用。
- 与运行期判断的区别：运行期判断只能决定代码执行与否，静态分析才能决定能否删除。
- 传播能力：未被使用的模块，其独占依赖也会连带被删除。

```js
import { add } from "./math.js";
// 只保留 add 与其独占依赖，multiply 及其独占依赖一并删除
console.log(add(1, 2));
```

> 静态分析的结论只保证结构上未被引用，是否真的能删掉还要看副作用判定，两者缺一不可。

**速记**：静态可分析让「哪些代码没被用到」在构建期即可确定，命名导入的精度高于默认导入。



#### 破坏树摇的写法

**破坏树摇的写法**：是让导入导出关系无法在语法层面确定、迫使打包器整体保留模块的代码形式。

- 条件导出：把 export 写在条件分支里，语法上无法确定是否执行。
- 动态路径：导入路径由变量拼装，模块图在构建期无法确定。
- 整体使用：把命名空间对象整体传出或遍历，无法判断用到哪些成员。
- 外部改写：在模块之外给导入的命名空间赋值，迫使打包器保留全部成员。
- 通用模块转换：CommonJS 模块被转换后带上包装逻辑，静态结构随之削弱。

```js
// 反例：导出不能出现在条件分支中，这种写法在语法层面即非法
if (process.env.NODE_ENV === "production") {
  export const logger = createSilentLogger();
} else {
  export const logger = createVerboseLogger();
}
// 合法但同样削弱摇树的替代写法：在顶层判断后统一导出
const logger = process.env.NODE_ENV === "production" ? silentLogger : verboseLogger;
export { logger };
```

> [!WARNING]
> **警告内容**：条件导出在语法层面不合法会直接构建失败，常见替代写法是在模块顶层统一导出一个按环境取值的绑定，代价是该模块只能整体保留。

**速记**：条件导出、动态路径与整体使用命名空间都会破坏静态结构，使摇树退化为整体保留。



### 副作用与标注

副作用（side effect）是模块被加载时执行、效果不体现在导出值上的操作。本节说明副作用的定义、清单字段的标注与注释标注的用法。

#### 副作用的定义

**副作用（side effect）**：是模块被加载时执行、其效果不体现在导出值上的操作，例如改写全局对象、注册回调、注入样式。

- 典型形态：顶层调用函数、修改全局状态、注册事件监听、写文件或打日志。
- 判定影响：打包器不确定删除后是否改变行为时，只能保留整个模块。
- 保守原则：无法判定时保留，因此误判只会让产物体积变大，不会让程序出错。
- 与纯函数的区别：导出纯函数不代表模块无副作用，顶层语句同样计入判定。
- 控制手段：用清单字段与注释标注主动告知打包器哪些模块没有副作用。

```js
// 顶层调用让模块带上副作用，删除它会丢失初始化行为
import { registerPolyfill } from "./polyfill.js";

registerPolyfill();
export const featureFlags = {};
```

> 判定副作用的成本很高，因此打包器默认偏保守，开启摇树收益的前提是主动提供标注信息。

**速记**：副作用是加载时发生、不体现在导出值上的操作，顶层调用是判定中最常见的一类。



#### 清单字段的标注

**sideEffects 字段**：是包清单中声明本包哪些模块被加载时会产生副作用的字段，供打包器判断能否安全删除。

- 取值形式：布尔值表示全包有或全包无副作用，数组则按 glob 列出确有副作用的文件。
- 常见写法：数组列出样式文件与含顶层调用的模块，其余模块视为无副作用。
- 判定顺序：字段声明优先于打包器的保守推断，声明之后按声明执行。
- 与外部化的关系：声明为外部依赖的包不参与本包摇树，字段由该包自行声明。
- 风险点：声明与真实情况不符会删掉必需代码，字段必须与源码逐一核对。
- 生效范围：字段只约束本包被下游打包时如何判定，不影响本包构建时对依赖的判定。

```json
{
  "name": "date-kit",
  "version": "1.0.0",
  "sideEffects": ["./dist/styles.css", "./src/polyfill.js"]
}
```

> [!WARNING]
> **警告内容**：把副作用声明写得比真实情况更干净，会让含顶层初始化的模块被整体删除，问题只在运行到相关功能时暴露，字段必须与源码逐条核对。

**速记**：sideEffects 用布尔值或 glob 数组声明，声明优先于推断，写宽比写窄安全。



#### 注释标注与纯注解

**纯注解**：是写在函数调用前的注释标记，直接告诉压缩器该调用没有副作用、可以安全删除。

- 写法位置：紧邻被调用的函数调用之前，与被标注的表达式在同一语句内。
- 生效对象：主要对函数调用有意义，用于标记那些结果纯、可安全丢弃的调用。
- 使用场景：调用结果只用于生成常量，或初始化副作用可由其他方式保证时。
- 不适用情形：类声明、赋值语句与确有副作用的调用加注解不会生效。
- 核对：去掉注解后观察产物是否变大，可确认注解是否被识别。

```js
// 纯注解写在调用之前，声明该调用可安全删除
const config = /*#__PURE__*/ createConfig({ mode: "production" });
export const version = config.version;
```

> 注释标注作用于压缩阶段的删除判定，模块级的裁剪在打包阶段已经完成，两者解决的不是同一个问题。

**速记**：纯注解标在函数调用之前，供压缩阶段判断能否删除，模块级裁剪仍靠副作用标注。



### 声明与配置的影响

摇树选项决定分析的激进程度，声明写法决定单个模块能否被删。本节说明选项的作用、顶层声明的判定与导入语句的保留规则。

#### treeshake 选项的作用

**treeshake 选项**：是 Rollup 配置中的开关，用布尔值或选项对象控制摇树的开关与判定策略。

- 布尔形式：取假时完全关闭摇树，用于排查代码被误删一类问题。
- 对象形式：可分别配置模块副作用、属性读取与函数调用等判定策略。
- 保守档位：把模块副作用判定改为按需推断，可减少误删风险。
- 已知副作用：可显式列出被当作有副作用的模块或全局对象，避免误删。
- 使用建议：先保持默认，仅在确有问题时逐项调整，并在产物中验证结果。

```js
export default defineConfig({
  input: "src/index.js",
  output: { dir: "dist", format: "es" },
  treeshake: {
    moduleSideEffects: true,
    propertyReadSideEffects: false,
  },
});
```

> [!CAUTION]
> **注意内容**：把模块副作用判定整体关闭会让所有模块被当作无副作用，含顶层初始化代码的模块可能被删除，排查问题时先改回默认再逐项放开。

**速记**：treeshake 用布尔值开关、用选项对象调策略，默认档位足够，调整后要在产物中验证。



#### 顶层声明与类的处理

**顶层声明判定**：是打包器判断一个未被使用的顶层声明能否删除的规则，函数与类的判定条件强于普通变量。

- 函数声明：未被引用且函数体无副作用时可直接删除。
- 类声明：含静态初始化块、装饰器或继承自带副作用的基类时会被保留。
- 变量声明：初始化表达式被判定为纯时才可删除，否则保留初始化调用。
- 常量折叠：被折叠为字面量的绑定不再产生运行时代码，但声明仍可能保留。
- 观察方式：对照源码与产物，逐个确认未被使用的声明是否消失。

```js
export class Registry {
  static instance = createRegistry();
}
// 静态属性初始化被判定为有副作用，即使未被引用也会保留
```

> 类的静态初始化与继承链上的调用都计入副作用，这是类声明比函数声明更难被摇掉的主要原因。

**速记**：函数声明最容易被删，变量看初始化是否纯，类的静态初始化与继承会使其整体保留。



#### 导入语句的保留规则

**导入保留规则**：是 Rollup 对 import 语句本身的处理约定，被判定有副作用的导入即使绑定未被使用也会保留。

- 无副作用：导入的绑定未被使用时，整条导入语句连同其独占依赖一起删除。
- 有副作用：存在副作用时只删除未使用的绑定，导入语句保留为副作用导入。
- 仅副作用导入：只写路径不绑定任何名字，语义即加载它并保留副作用。
- 常见对象：样式文件与垫片依赖通常需要保留，可用副作用标注显式声明。
- 观察方式：在产物中搜索被删模块的特征代码，确认导入是否被去掉。

```js
import "./polyfill.js";          // 只加载，保留副作用
import { unused } from "./a.js"; // 未使用且无副作用，整条删除
```

> 只写路径的导入不会被摇掉，把「为副作用而加载」与「为使用而导入」区分开，判定才准确。

**速记**：无副作用的未使用导入整条删除，有副作用的只删绑定，仅副作用导入默认保留。



### 依赖包的树摇

第三方包往往是产物体积的主要来源。本节说明对依赖包摇树成立的条件、常见失效原因与转换环节的影响。

#### 对第三方包生效的条件

**依赖包摇树**：是把依赖目录中的包也纳入删除范围，前提是该包提供 ESM 形态且如实声明了副作用。

- 形态要求：包需提供 ESM 入口，只有 CommonJS 入口时无法被静态分析。
- 字段要求：包的清单中需要有副作用声明，否则打包器按保守策略整体保留。
- 入口选择：解析时命中 ESM 入口，命中 CommonJS 入口会让摇树失效。
- 外部化影响：声明为外部依赖的包在产物中保留导入语句，由下游继续处理。
- 本包源码：本包源码本身需为 ESM 形态，否则依赖形态再合格也无法生效。
- 收益来源：只用到包内少数函数时，条件满足才能显著缩小产物。

```bash
# 查看依赖包提供的入口字段与副作用声明
npm view lodash-es module main sideEffects
```

> 同一份源码在不同依赖形态下的产物体积可能相差数倍，选依赖时把是否提供 ESM 形态当作一项硬指标。

**速记**：依赖包可摇树需同时满足 ESM 入口、副作用声明与解析命中三件事，缺一项即整体保留。



#### 为何常常无效

**摇树失效**：是依赖包虽有 ESM 入口却仍被整体打入产物的现象，原因集中在形态、入口与写法三处。

- 原因一：包只提供 CommonJS 形态，或转换插件把它转成了带包装的形式。
- 原因二：解析时命中 CommonJS 入口，ESM 入口未被选中。
- 原因三：包未声明副作用，打包器保守保留全部模块。
- 原因四：默认导入后整体取用属性，无法定位到具体绑定。
- 处理顺序：先确认产物中的形态，再检查入口选择，最后核对副作用声明。

```js
// 默认导入后整体使用，只能整体保留
import formatKit from "./format-kit.js";
const value = formatKit.get(data, "a.b");

// 改为命名导入，未使用部分才有机会被删除
import { get } from "./format-kit.js";
const picked = get(data, "a.b");
```

> 导入写法是最容易改正的一项：从默认导入改为命名导入往往不需要改依赖，只改调用点即可。

**速记**：形态、入口与导入写法任一处不满足都会整体保留，先改写法再查依赖形态。



#### 转换环节的影响

**转换环节**：是 CommonJS 转 ESM、语法降级与代码注入等处理，它们在摇树之前改写模块结构。

- CommonJS 转换：转换后包上包装函数与条件判断，静态结构被削弱，可删范围缩小。
- 语法降级：目标版本过低时导出被改写成运行期赋值，绑定的静态对应关系丢失。
- 代码注入：注入的垫片与运行时助手引入新的副作用，使相关模块被整体保留。
- 执行顺序：转换在摇树之前，转换结果就是摇树的输入，链路上任何一环都会影响结果。
- 验证：分别关闭转换插件与降级配置，对比产物体积变化，判断影响来自哪一环。

```js
// 运行期助手会引入额外模块与副作用，助手策略需按需选择
babel({ babelHelpers: "bundled" })
```

> [!NOTE]
> **提醒内容**：转换插件的产出就是摇树的输入，插件改写得越多可静态分析的结构越少，排查体积问题时先看转换链路上挂了哪些插件。

**速记**：转换发生在摇树之前，包装、降级与注入都会削弱静态结构，排查体积先看转换链路。



### 效果核对方法

摇树是否生效要靠产物验证。本节给出三种核对手段：比体积、找残留、按序排查失效成因。

#### 产物体积对比

**体积对比**：是用改动前后的产物大小判断摇树是否生效，是最直接的验证手段。

- 对比对象：入口产物体积与产物总量，两者可能给出不同结论。
- 控制变量：每次只改动一个因素，例如只把默认导入改为命名导入。
- 参考基准：与源码中实际使用的代码量粗略比对，判断是否多出成倍体积。
- 压缩影响：压缩会缩小差距，比较时保持压缩设置一致。
- 记录方式：把每次对比结果留档，形成可回溯的体积变化记录。

```bash
npx rollup -c
wc -c dist/index.js
# 改动导入写法后再跑一次，比较两次字节数
wc -c dist/chunks/*.js | tail -n 1
# 共享块总量同样变化，说明摇树影响到了共用部分
```

> 体积对比只能说明有无异常，定位到具体模块还要结合产物搜索，两种手段配合使用。

**速记**：体积对比要控制变量并保持压缩设置一致，先发现异常再谈定位。



#### 未摇掉模块的定位

**未摇掉模块定位**：是在产物中找出本应被删除却仍然存在的代码，并回溯到其保留原因。

- 搜索特征：用源码中的独特字符串或函数名在产物里搜索命中位置。
- 看归属：确认该代码出现在入口产物还是共享块，据此判断由哪个入口带入。
- 查依赖：确认该模块是否被其他模块的顶层调用间接引用。
- 查形态：确认产物中是原始模块代码还是被转换后的包装代码。
- 查引用链：从入口出发沿导入语句逐层确认是哪一个引用让该模块无法被删。
- 处理：按副作用标注、入口选择、导入写法三条线索依次排查。

```bash
grep -n "formatTime" dist/index.js
# 若仍能命中，说明该函数未被摇掉，需回溯引用来源
```

> 搜索用的特征字符串要选源码中足够独特的一段，用通用名搜索会命中大量无关位置。

**速记**：用独特字符串在产物中定位残留代码，再按其归属与依赖关系回溯保留原因。



#### 摇树失败的常见成因

**摇树失败**：是分析链路中某一环阻断了静态结构，使删除范围退化为整体保留。

- 输入形态：源码或依赖以 CommonJS 形态进入模块图。
- 声明缺失：依赖或本包未声明副作用，判定退回保守策略。
- 写法问题：默认导入后整体使用、命名空间整体传出、导出写在条件分支。
- 转换干扰：降级目标过低或转换插件改写了导出结构。
- 顺序问题：改写模块结构的插件排在链路前段，其产出成为摇树的输入。

```text
排查顺序：
1. 模块是否以 ESM 形态进入模块图
2. 依赖与本包是否声明了副作用
3. 导入是否精确到单个绑定
4. 转换插件是否改写了导出结构
```

> [!NOTE]
> **提醒内容**：摇树结果为保留多数是保守判定的结果而非错误，按上述四步逐条排查即可缩小范围，不必直接调大摇树激进程度。

**速记**：按形态、声明、写法、转换四步排查摇树失效，先定位原因再调整配置。
