## Vite 插件开发与钩子机制

**插件（plugin）**：是至少带 name 字段并实现若干钩子方法的对象，Vite 在开发服务器与生产构建的固定阶段按约定签名调用这些方法，用于介入模块解析、源码转换与产物生成。

插件的接入方式与常用插件清单见本主题第 5 篇，本篇只处理插件的编写本身：钩子的参数与返回值、虚拟模块的实现方式、插件顺序的判定与调试手段。Rollup 侧的钩子定位见本主题第 12 篇，此处只写 Vite 语境下的用法。

### 插件的基本形态

本节确立插件对象的字段构成与导出形式，是后续所有钩子写法的基础。

#### 插件对象与必需字段

**插件对象**：是至少含 name 字段并实现若干钩子方法的普通对象，Vite 在生命周期的固定阶段按约定签名调用这些方法。

- name 字段：字符串，必填且应唯一，报错信息与调试日志都以它标识插件来源。
- 钩子方法：键为钩子名、值为函数，未使用的钩子直接省略，不需要写空函数占位。
- 上下文对象：钩子内的 this 是插件上下文，可用 this.resolve 解析模块、用 this.emitFile 产出额外文件。
- 异步支持：钩子可以是异步函数，Vite 会等待返回的 Promise 结束再进入下一阶段。
- 返回值约定：转换类钩子返回空值表示不介入，返回字符串或含 code 字段的对象表示替换结果。

```js
export function stampModule() {
  return {
    name: "stamp-module",
    transform(code, id) {
      if (!id.endsWith(".js")) return null;
      return { code: code + "\n// built by stamp-module", map: null };
    },
  };
}
```

> 未实现的钩子省略即可，写成返回 undefined 的空函数不会报错，但会让调用链多做一次无意义的判断。

**速记**：插件是 name 加钩子方法的对象，未用到的钩子省略不写。



#### 工厂函数与配置项

**插件工厂**：是接收配置项、返回插件对象的函数，用于让同一段插件逻辑按不同参数复用。

- 导出形式：包对外导出一个函数，调用后得到插件对象，使用方写成插件名加括号的形式。
- 闭包状态：工厂内的局部变量是插件的私有状态，两个插件实例之间互不影响。
- 副作用约束：工厂函数只做参数整理与状态初始化，不在其中读取配置或访问文件系统。
- 命名约定：函数名与 name 字段保持同一语义，便于在报错信息与源码之间对应。
- 返回内容：既可以返回一个对象，也可以返回对象数组，数组写法用于一个包导出多个插件。

```js
export function bannerPlugin(options = {}) {
  const text = options.text ?? "generated";
  return {
    name: "banner-plugin",
    apply: "build",
    renderChunk(code) {
      return `/* ${text} */\n${code}`;
    },
  };
}
```

> 需要跨钩子共享数据时把变量放在工厂作用域内，写到模块顶层会让多个实例互相污染。

**速记**：插件工厂收参数、返回对象，配置与状态都收在工厂作用域里。



#### 插件的生效范围与 apply 字段

**apply 字段**：是限定插件只在开发服务器或只在构建阶段生效的声明，取值为 serve、build 或接收配置与环境的判断函数。

- 字符串取值：写 serve 只在开发期加载，写 build 只在构建期加载。
- 函数取值：接收 config 与 env 两个参数，返回真值时插件参与本次运行。
- 典型用途：只服务构建的产物分析插件，只服务开发期的接口模拟插件。
- 与 enforce 的区别：apply 决定插件是否加载，enforce 决定加载后排到哪个位置。
- 排查价值：钩子没有触发时，先确认 apply 判定是否把当前命令排除在外。

```js
export function mockApiPlugin() {
  return {
    name: "mock-api",
    apply: "serve",
    configureServer(server) {
      server.middlewares.use((req, res, next) => {
        if (!req.url.startsWith("/api/")) return next();
        res.setHeader("Content-Type", "application/json");
        res.end(JSON.stringify({ ok: true }));
      });
    },
  };
}
```

> [!TIP]
> **建议内容**：把只在单一阶段使用的插件用 apply 明确限定，可减少另一阶段无谓的钩子调用与调试干扰。

**速记**：apply 决定插件是否加载，enforce 决定加载后的执行位置。



### Vite 专属钩子

Vite 在 Rollup 钩子之外补充了一组只在自身流程中触发的钩子，分别对应配置解析、开发服务器启动以及 HTML 与热更新处理。

#### config 与 configResolved

**config 钩子**：是在用户配置被解析成最终配置之前触发、用于追加或覆盖配置项的钩子；**configResolved 钩子**：是在全部配置合并完成后触发一次、参数为最终配置对象的钩子。

- 参数：config 接收原始配置与含 command、mode 的环境对象，configResolved 只接收最终配置。
- 返回合并：config 返回的部分配置会被深度合并进最终配置，越晚执行的插件覆盖越靠前的结果。
- 触发次数：config 在每次启动或构建时触发一次，configResolved 紧随其后触发一次。
- 使用边界：config 内拿不到其他插件追加的配置，configResolved 内不应再试图修改配置。
- 常见用途：config 注入全局常量与别名，configResolved 记录最终值并初始化插件状态。
- 冻结时点：configResolved 之后配置视为只读，后续钩子只读取其中字段。

```js
export function injectMode() {
  let isBuild = false;
  return {
    name: "inject-mode",
    config(config, env) {
      return {
        define: { __MODE__: JSON.stringify(env.mode) },
      };
    },
    configResolved(resolved) {
      isBuild = resolved.command === "build";
    },
  };
}
```

> [!IMPORTANT]
> **重要内容**：config 返回的对象深度合并进最终配置，多个插件可能覆盖同名字段，改动共享字段前必须确认插件的加载顺序。

**速记**：config 追加配置并参与合并，configResolved 只读最终配置并初始化状态。



#### configureServer 与中间件注入

**configureServer 钩子**：是在开发服务器内部中间件安装之前触发、用于挂载自定义请求处理逻辑的钩子。

- 参数：接收 server 对象，其中包含 middlewares、watcher、ws 等字段。
- 返回函数：返回函数时，该函数在 Vite 内部中间件安装完成之后执行，适合补充或覆盖内置行为。
- 中间件签名：middlewares.use 接收请求、响应与 next 三参数的函数，不处理时调用 next 放行。
- 顺序影响：在内部中间件之前挂载会先于静态资源与模块转换中间件处理请求。
- 常用场景：接口模拟、请求改写、额外静态目录、访问日志。
- 生效条件：该钩子只在开发服务器下触发，构建阶段不会执行。

```js
export function logRequestPlugin() {
  return {
    name: "log-request",
    apply: "serve",
    configureServer(server) {
      return () => {
        server.middlewares.use((req, res, next) => {
          if (req.url.endsWith(".css")) server.config.logger.info(req.url);
          next();
        });
      };
    },
  };
}
```

> 需要读取最终配置时可在钩子内访问服务器对象上的配置字段，而不是在模块顶层导入配置。

**速记**：configureServer 挂载中间件，返回的函数在内部中间件之后执行。



#### transformIndexHtml 与 handleHotUpdate

**transformIndexHtml 钩子**：是在 HTML 产出前后改写页面内容或注入标签的钩子；**handleHotUpdate 钩子**：是在文件变更后调整热更新模块集合的钩子。

- transformIndexHtml 参数：接收 HTML 字符串与上下文，上下文含页面路径、服务器对象与构建产物信息。
- 返回形式：可返回字符串、标签数组，或同时含 HTML 与标签的对象。
- 标签字段：标签项可声明标签名、属性、子内容与注入位置，注入位置决定插入到头部或体部的哪一端。
- 触发时机：开发期在每次请求页面时触发，构建期在写出 HTML 之前触发。
- handleHotUpdate 参数：上下文含变更文件、时间戳、受影响模块、读取方法与服务器对象。
- 返回数组：返回模块数组会替换默认的受影响集合，用于缩小或扩大刷新范围。

```js
export function injectRuntimePlugin() {
  return {
    name: "inject-runtime",
    transformIndexHtml(html) {
      const tags = [
        { tag: "script", attrs: { src: "/runtime-config.js" }, injectTo: "body" },
      ];
      return { html, tags };
    },
  };
}
```

> 热更新的默认行为按文件与模块依赖关系推断受影响模块，只在需要打破该推断时才使用 handleHotUpdate 的返回值。

**速记**：transformIndexHtml 改页面或注入标签，handleHotUpdate 调整热更新范围。



### 通用构建钩子

Rollup 提供的钩子在 Vite 中同样可用，它们分布在构建的解析、转换与产物三个阶段，是插件逻辑的主要落点。

#### 构建开始与结束类钩子

**生命周期钩子**：是标记构建各阶段起止的钩子，包括 options、buildStart、buildEnd 与 closeBundle，用于初始化与收尾。

- options：接收最终选项对象，可返回新选项，是钩子链的第一环。
- buildStart：构建开始时触发一次，适合初始化统计、读取外部数据。
- buildEnd：构建结束时触发，唯一参数是错误对象或空值。
- closeBundle：产物写入完成之后触发，适合释放资源与输出汇总日志。
- 触发差异：开发期的按需转换不经过完整构建流程，这些钩子的触发次数与构建期不同。
- 返回值：返回空值表示不介入，返回对象或字符串则替换对应结果。

```js
export function countTransformPlugin() {
  let transformed = 0;
  return {
    name: "count-transform",
    buildStart() {
      transformed = 0;
    },
    transform(code, id) {
      if (id.includes("node_modules")) return null;
      transformed += 1;
      return null;
    },
    buildEnd() {
      console.log(`transformed ${transformed} modules`);
    },
  };
}
```

> 依赖节点数量的统计只在构建期完整，开发期按需转换会得到偏小的数字。

**速记**：options 与 buildStart 管开头，buildEnd 与 closeBundle 管收尾，开发期不保证完整触发。



#### 模块解析与加载类钩子

**解析与加载钩子**：是决定模块标识如何确定、源码从哪里取得的钩子，包括 resolveId、load 与 transform。

- resolveId 签名：接收导入说明符、导入方标识与选项对象，返回字符串、含 id 字段的对象，或返回空值交给后续插件。
- load 签名：接收模块标识，返回源码字符串、含 code 与 map 的对象，或返回空值走默认读取。
- transform 签名：接收源码与模块标识，返回改写后的源码或空值，是语法处理的常用位置。
- moduleParsed：模块解析完成后触发，可读取该模块的导入导出结构。
- 责任划分：定位归 resolveId，取内容归 load，改内容归 transform，混用会让插件难以复用。
- 一致性：resolveId 返回的标识会原样传给 load，两处必须遵循同一套标识约定。

```js
export function resolveSharedPlugin() {
  return {
    name: "resolve-shared",
    resolveId(source) {
      if (!source.startsWith("#shared/")) return null;
      return source.replace("#shared/", "/src/shared/");
    },
  };
}
```

> 需要在插件中解析导入时使用插件上下文的解析方法，它会把别名与扩展名补全一并处理完再返回结果。

**速记**：resolveId 定标识、load 取源码、transform 改源码，三者职责分开。



#### 产物生成类钩子

**产物钩子**：是在输出阶段介入产物内容的钩子，包括 renderStart、renderChunk、generateBundle 与 writeBundle。

- renderStart：输出阶段开始时触发，可在所有产物首尾追加统一说明。
- renderChunk 签名：接收单个 chunk 的代码、chunk 信息与输出选项，返回改写后的代码。
- generateBundle：产物已生成尚未写入磁盘，参数为输出选项与产物集合，可增删改其中的文件对象。
- writeBundle：产物已写入磁盘，适合做体积统计与产物校验。
- 适用阶段：这些钩子只在构建期触发，开发期不产出文件，因此不会执行。
- 设计提醒：不要把功能只实现在产物钩子里，否则开发期与构建期行为不一致。

```js
export function reportBundlePlugin() {
  return {
    name: "report-bundle",
    apply: "build",
    generateBundle(options, bundle) {
      for (const [fileName, item] of Object.entries(bundle)) {
        console.log(`${fileName} ${item.type}`);
      }
    },
  };
}
```

> [!NOTE]
> **提醒内容**：产物集合中的文件对象按类型分为 chunk 与 asset 两类，遍历时先判断类型再读取代码字段。

**速记**：renderChunk 改单个 chunk，generateBundle 改产物集合，writeBundle 只做核对。



### 虚拟模块与资源解析

虚拟模块让插件在不落地文件的前提下向源码提供模块，是配置注入、数据生成与占位资源三类需求的通用实现方式。

#### 虚拟模块的标识约定

**虚拟模块（virtual module）**：是不对应磁盘文件、由插件在解析与加载阶段生成的模块。

- 可读前缀：约定用 virtual: 作为对外书写的导入前缀，便于在报错信息中识别来源。
- 内部标识：解析结果常以反斜杠零开头，表示这是虚拟模块，其他插件应跳过对它的处理。
- 成对实现：虚拟模块必须同时提供解析钩子与加载钩子，缺一项就在导入时直接报错。
- 命名唯一：内部标识要包含包名或插件名，避免不同插件生成同名标识。
- 热更新限制：虚拟模块没有对应的磁盘文件，改动插件实现后需要重启开发服务器。
- 常见误用：把真实文件路径当作虚拟标识，会让插件与默认读取流程互相抢占。

> 反斜杠零开头的标识在多数插件中被约定为内部模块，书写导入语句时仍使用可读前缀。

**速记**：虚拟模块用可读前缀对外、用内部标识对内，解析与加载两处都要实现。



#### resolveId 与 load 的配合

**虚拟模块的加载过程**：是解析钩子把导入说明符映射为内部标识、加载钩子再按内部标识返回源码的两步流程。

- 第一步：解析钩子匹配源码中书写的导入说明符，命中时返回内部标识，未命中返回空值。
- 第二步：加载钩子匹配内部标识，返回模块源码字符串。
- 返回对象：解析钩子可返回含标识与副作用标记的对象，加载钩子可返回含代码与映射的对象。
- 常量提取：两处使用的内部标识提取为模块级常量，避免手写两份字符串。
- 异步内容：加载钩子中可以读取文件或请求数据，把结果序列化为模块源码再返回。
- 缓存行为：转换结果被缓存，数据源变化时需要让标识或模块内容随之变化。

```js
const VIRTUAL_ID = "\0virtual:build-info";
const PUBLIC_ID = "virtual:build-info";

export function buildInfoPlugin() {
  return {
    name: "build-info",
    resolveId(id) {
      return id === PUBLIC_ID ? VIRTUAL_ID : null;
    },
    load(id) {
      if (id !== VIRTUAL_ID) return null;
      const payload = { builtAt: Date.now(), mode: process.env.NODE_ENV };
      return `export const buildInfo = ${JSON.stringify(payload)};\n`;
    },
  };
}
```

```js
// 业务代码中的用法，书写的是可读前缀
import { buildInfo } from "virtual:build-info";

console.log(buildInfo.mode);
```

> 加载钩子返回的源码必须是合法模块文本，直接返回对象会在解析阶段报错，需要先序列化。

**速记**：解析钩子认导入说明符、加载钩子认内部标识，标识提为常量最稳。



#### 虚拟模块的边界与更新

**模块边界**：是热更新判断一次变更影响哪些模块的依据，虚拟模块没有对应文件，边界信息随之缺失。

- 刷新退化：虚拟模块内容变化时无法定位到具体边界，通常退化为整页刷新。
- 依赖追踪：虚拟模块读取的外部数据文件不会被自动监听，内容变化不触发更新。
- 主动监听：可在配置钩子中把外部文件加入服务器监听列表，变更后触发热更新。
- 重启条件：改动解析钩子或加载钩子的实现属于插件自身变更，需要重启开发服务器。
- 两期一致：开发期与构建期共用同一份插件代码，保证模块内容在两期相同。

> [!CAUTION]
> **注意内容**：虚拟模块返回的内容若含时间戳或随机值，会让每次转换的产物都不同，破坏缓存并让本可复用的结果全部失效。

**速记**：虚拟模块没有模块边界，外部数据要显式监听，插件实现变更必须重启。



### 插件顺序与调试

多个插件同时介入同一批钩子时，执行顺序直接决定最终结果，顺序由配置数组位置与排序字段共同判定。

#### enforce 与排序位置

**插件排序**：是 Vite 把所有插件按类别与声明排成固定执行序列的过程，排序字段与数组位置都是输入。

- 完整次序：别名处理插件、用户配置中标记提前的插件、Vite 核心插件、用户配置中的普通插件、Vite 构建插件、用户配置中标记延后的插件、构建后的插件。
- 提前语义：标记提前的插件在核心插件之前执行，用于预处理源码，此时别名与依赖解析未必就绪。
- 延后语义：标记延后的插件在核心插件之后执行，用于产物后处理与结果收尾。
- 数组位置：未声明排序字段的插件按配置数组中的先后顺序执行。
- 钩子一致：排序对所有钩子生效，同一对插件在解析钩子与转换钩子中的先后一致。
- 与筛选取值区分：筛选取值决定插件是否被加载，排序字段决定加载后排到哪一段。

```text
别名处理插件
用户配置中标记提前的插件
Vite 核心插件
用户配置中的普通插件
Vite 构建插件
用户配置中标记延后的插件
构建后的插件
```

> 需要与核心插件抢先后时才使用排序字段，普通插件之间靠数组顺序表达先后即可。

**速记**：先按提前、普通、延后分段，段内再按数组位置排序。



#### 顺序对转换结果的影响

**转换链**：是把源码依次交给各插件的转换钩子处理、前一环的输出作为后一环输入的过程。

- 链式改写：转换钩子的返回值会成为下一个转换钩子的输入，顺序不同结果不同。
- 别名与解析：需要识别别名的插件应通过插件上下文的解析方法转交，不要自己拼路径。
- 语法与压缩：语法降级类插件排在读取源码的插件之后，压缩类插件排在最后。
- 冲突表现：两个插件改写同一段代码时结果取决于顺序，且往往只在构建期暴露。
- 定位方法：临时移除或调整可疑插件的位置，对比产物差异即可确认影响范围。
- 约定写法：需要较早执行就标记提前，需要较晚执行就标记延后，不要依赖数组位置碰运气。

> 插件顺序问题多出现在转换与产物两类钩子上，解析类钩子的顺序通常由首次命中的插件决定结果。

**速记**：转换钩子上游的输出就是下游的输入，顺序敏感的逻辑用排序字段明示。



#### 调试插件行为的方法

**插件调试**：是确认插件是否被加载、钩子是否触发、产物是否被正确改写的一组手段。

- 日志插桩：在钩子入口打印插件名与关键参数，唯一且可读的 name 让日志可以对应到源码。
- 调试开关：命令行加 --debug 输出内部调试日志，日志的命名空间划分随版本变化。
- 上下文查询：用插件上下文的解析方法确认某个导入最终解析到哪个文件。
- 产物核对：在产物钩子中打印文件名与体积，确认插件确实改动过产物。
- 最小复现：新建只安装该插件的空项目，排除其他插件干扰后再定位问题。
- 报错阅读：报错信息中的插件名取自 name 字段，规范的命名能显著缩短定位时间。

```bash
# 输出调试日志，观察插件加载与钩子触发情况
npx vite --debug
npx vite build --debug
```

> [!WARNING]
> **警告内容**：调试完成后残留的日志插桩会在每次构建时输出，既污染日志又拖慢构建，提交前必须清理干净。

**速记**：日志加插件名、上下文查解析、产物看结果，三步定位插件问题。
