## Vite 的 CSS 与预处理器

**样式处理链路**：是 Vite 把样式源码依次交给预处理器、PostCSS 与模块作用域处理后，在开发期注入页面、在构建期提取为独立文件的过程。

样式接入的概览写法见本主题第 5 篇，产物目录与资源内联阈值见第 7 篇，本篇只处理样式链路本身：注入与提取的差别、预处理器的接入方式、模块作用域、PostCSS 与降级，以及样式产物的拆分与体积。样式语言与预处理器语法见 前端/CSS 主题。

### 样式处理链路

样式在开发期与构建期的交付方式完全不同，这一差别是排查样式问题的起点。

#### 开发期的样式注入

**样式注入**：是开发期把样式内容转换为一段运行时脚本、由脚本把样式写入页面文档的处理方式。

- 处理方式：样式模块被转换为在运行时创建样式元素并插入页面的脚本。
- 插入结果：页面中出现的样式元素由脚本创建，不写入磁盘。
- 更新方式：样式改动通过热更新替换对应内容，不触发整页刷新。
- 顺序：插入顺序跟随模块引入顺序，引入先后会影响层叠结果。
- 调试：浏览器中可直接编辑插入的样式，刷新后改动丢失。
- 收集差异：需要拿到样式文本的场景不能依赖注入，要改用构建期的提取结果。

```js
// 开发期样式模块被转换后的等效逻辑
const styleElement = document.createElement("style");
styleElement.textContent = ".card { border-radius: 8px; }";
document.head.appendChild(styleElement);
```

> 开发期的样式注入依赖脚本执行，页面中看不到独立的样式文件，这是与构建期最直观的差别。

**速记**：开发期样式由脚本注入页面，改动走热更新，不落磁盘。



#### 构建期的样式提取

**样式提取**：是构建期把样式从脚本中分离、产出独立样式文件并自动接入页面的处理方式。

- 默认行为：构建时样式被提取为独立的样式文件，不再随脚本注入。
- 文件位置：输出目录下的资源目录，文件名默认带内容哈希。
- 页面关联：页面中自动插入指向该样式文件的引用。
- 分包行为：开启代码分割时，每个异步块对应的样式单独产出。
- 关闭拆分：把样式拆分开关置为假会让全部样式合并为单个文件。
- 加载差异：首屏样式在页面中直接引用，异步块的样式随块一并加载。

```text
dist/index.html                 引用首屏样式文件
dist/assets/index-8f3a.css      入口样式
dist/assets/detail-2b71.css     异步块样式
```

> 提取后的样式不再依赖脚本执行，页面可直接加载，对首屏渲染更有利。

**速记**：构建期样式被提取为独立文件并自动接入页面，异步块各有自己的样式文件。



#### 样式顺序与依赖关系

**样式顺序**：是提取后多个样式文件中规则生效的先后次序，由模块在依赖图中的引入顺序决定。

- 顺序来源：规则顺序由模块的引入顺序与分包结果共同决定。
- 重复引用：多个入口引用同一份样式时可能产出重复内容。
- 覆盖风险：引入顺序变化会让同优先级的选择器结果改变。
- 稳定手段：基础样式在入口最先引入，覆盖样式放在其后引入。
- 异步块顺序：异步块样式在块加载后才生效，可能晚于首屏样式。
- 核对方式：构建后检查样式文件中规则的先后是否与预期一致。

```js
// 入口文件中的引入顺序决定基础样式与覆盖样式的先后
import "./styles/base.css";
import "./styles/theme.css";
import "./styles/overrides.css";
```

> 样式顺序问题在开发期不易暴露，只在提取与并发加载时才显现，构建后核对是必要步骤。

**速记**：样式顺序由模块引入顺序与分包结果决定，基础样式先引入、覆盖样式后引入。



### 预处理器接入

Vite 通过依赖探测识别预处理器，接入工作集中在安装依赖与选项透传两处。

#### 安装与自动识别

**预处理器识别**：是按样式文件的扩展名自动选用对应编译器、无需编写转换配置的机制。

- 识别方式：安装对应依赖后，以对应扩展名结尾的文件自动交给该预处理器编译。
- 依赖对应：Sass 对应 sass，Less 对应 less，Stylus 对应 stylus。
- 安装位置：作为开发依赖安装，不进生产依赖。
- 零配置：不写任何配置即可导入该扩展名的样式文件。
- 缺失后果：未安装依赖时导入即报错，报错信息会指明缺少的包。
- 组合扩展名：模块化样式使用双扩展名写法，两种能力同时生效。

```bash
npm install --save-dev sass
npm install --save-dev less
# 按项目实际用到的语言安装，只用 Sass 时不必安装 Less
```

> 预处理器只在使用对应扩展名的文件时才被调用，未用到的语言不必安装依赖。

**速记**：装哪个依赖就自动支持哪种扩展名，模块化样式用双扩展名。



#### 预处理器选项透传

**预处理器选项透传**：是把样式配置中按语言分组的选项字段原样传给对应预处理器编译接口的做法。

- 配置位置：样式配置下按语言名分组的预处理器选项字段。
- 透传规则：分组内的字段原样传给对应预处理器的编译接口。
- 常用项：增加查找目录、静默依赖内告警、指定输出风格。
- 版本差异：不同预处理器的选项名不同，按各自文档填写。
- 类型差异：字段值类型随语言变化，配置的类型提示由语言名决定。
- 排查思路：编译报错提示某个选项未识别时，先核对该语言支持哪些字段。

```ts
import { defineConfig } from "vite";

export default defineConfig({
  css: {
    preprocessorOptions: {
      less: {
        paths: ["src/styles"],
        javascriptEnabled: true,
      },
    },
  },
});
```

> 透传意味着选项的合法性由预处理器自身判定，写错的字段不会在构建配置层被拦下。

**速记**：选项按语言名分组透传，字段合法性由预处理器判定。



#### 全局变量与公共样式注入

**追加内容注入**：是用预处理器选项在每个样式文件开头补一段公共内容的做法，用于免去逐文件书写引入语句。

- 注入手段：用追加内容选项在每个样式文件开头补一段文本。
- 典型内容：变量定义、混入定义、公共函数库的引入语句。
- 与引入语句的差别：注入发生在编译之前，不需要在每个文件里重复书写。
- 重复风险：被注入的文件若自己也引入同一份内容，会产生重复定义或告警。
- 抑制方式：配合静默依赖告警的选项，或只把变量与混入放进注入内容。
- 影响范围：注入对全部样式文件生效，包括依赖内的样式文件。

```ts
export default {
  css: {
    preprocessorOptions: {
      scss: {
        additionalData: '@use "@/styles/variables" as *;',
      },
    },
  },
};
```

> [!IMPORTANT]
> **重要内容**：注入内容会被添加到每个样式文件开头，若其中包含会产出规则的声明，产物中就会出现重复定义，注入内容应只放变量与混入。

**速记**：公共变量用追加内容注入一次，注入内容只放不产出规则的声明。



### CSS 模块与作用域

CSS 模块把类名限定在文件内部，是避免样式相互覆盖的主要手段。

#### 模块文件与导入结果

**CSS 模块（CSS Module）**：是让文件内类名默认局部生效的样式组织方式，Vite 对以 .module.css 结尾的文件自动启用。

- 启用条件：文件名以 .module.css 结尾时自动按 CSS 模块处理。
- 导入结果：默认导出是原始类名到实际类名的映射对象。
- 使用方式：通过映射对象取类名，不写原始类名字符串。
- 具名导出：也可按具名导出的方式取用，按项目约定统一即可。
- 构建差异：实际类名在开发期与构建期可能不同，业务代码不得依赖具体值。
- 类型提示：需要类型提示时按编辑器的模块声明方式补充，属类型系统范畴。

```css
/* src/components/Card.module.css */
.card {
  border: 1px solid #e5e7eb;
  border-radius: 8px;
}
```

```js
import styles from "./Card.module.css";

const cardElement = document.createElement("div");
cardElement.className = styles.card;
```

> [!NOTE]
> **提醒内容**：映射对象是转换阶段的产物，构建后类名会带哈希，业务代码里硬编码原始类名会在构建后失效。

**速记**：模块文件导入后得到类名映射对象，取类名一律走映射对象。



#### 作用域与命名规则

**作用域配置**：是控制局部与全局类名判定、以及实际类名生成规则的样式配置字段。

- 配置入口：样式配置下的模块对象控制作用域行为与类名生成规则。
- 局部与全局：模块文件内的类名默认局部，可用全局写法保留指定类名。
- 命名规则：生成规则可给字符串模板或函数，可用占位符随版本不同，以官方文档为准。
- 命名前缀：可加统一前缀，便于在浏览器中区分类名来源。
- 兼容映射：可把类名映射改为驼峰式，兼容既有代码的书写习惯。
- 作用域开关：可整体切换默认作用域行为，改动前需评估存量样式。

```ts
export default {
  css: {
    modules: {
      localsConvention: "camelCaseOnly",
      generateScopedName: "[name]__[local]__[hash:base64:5]",
    },
  },
};
```

> 命名规则只在需要与既有代码或调试工具配合时才调整，默认值已能满足多数项目。

**速记**：作用域与类名生成规则都在样式模块配置里改，改动前先评估存量样式。



#### 与预处理器并用

**组合处理**：是模块化样式文件同时经过预处理器编译与作用域改写两个阶段的过程。

- 组合命名：双扩展名写法同时满足模块与预处理器两个条件。
- 处理顺序：先按预处理器编译，再按 CSS 模块改写作用域。
- 变量使用：预处理器变量在编译期被替换，不参与模块映射。
- 嵌套写法：嵌套在编译后展开，只有最终类名参与作用域改写。
- 引用公共类名：模块文件中引用全局类名需要显式声明为全局。
- 常见问题：编译期报变量未定义时先确认注入内容对该文件是否生效。

```css
/* src/components/Panel.module.css 中的局部与全局混用 */
.root {
  padding: 12px;
}

.root .global-badge {
  margin-left: 4px;
}
```

> 作用域改写发生在预处理之后，因此预处理器生成的类名同样会被改写为局部类名。

**速记**：先编译后改写作用域，预处理器变量不进模块映射。



### PostCSS 与 CSS 新语法

PostCSS 承担预处理之后的第二段转换，与降级目标相关的配置都在这一层。

#### PostCSS 配置的加载入口

**PostCSS 配置**：是声明 PostCSS 插件及其选项的配置文件或内联配置对象，决定样式进入哪条插件链。

- 自动查找：项目根目录下符合约定命名的 PostCSS 配置文件会被自动加载。
- 内联配置：样式配置中的 PostCSS 字段可直接给出插件数组与选项。
- 互斥关系：给出内联配置后不再查找项目中的配置文件。
- 插件来源：插件需先从项目依赖中安装，再由配置引用。
- 链路位置：样式先经过预处理器编译，再进入 PostCSS 插件链。
- 排查入口：插件未生效时先确认加载的是哪一份配置。

```js
// postcss.config.js
export default {
  plugins: {
    "postcss-flexbugs-fixes": {},
  },
};
```

```ts
// 内联配置写法，给出后不再读取项目中的配置文件
export default {
  css: {
    postcss: {
      plugins: [],
    },
  },
};
```

> 内联配置与配置文件二者只能取其一，混用时按官方文档说明的优先顺序生效。

**速记**：PostCSS 插件链来自配置文件或内联配置，两者只能取其一。



#### 嵌套与新语法的降级

**语法降级**：是用 PostCSS 插件把嵌套写法与新语法转写为旧浏览器可执行的基础写法的过程。

- 需求来源：嵌套写法与新语法在旧浏览器中不被支持。
- 处理方式：用 PostCSS 插件把新语法转写为等价的基础写法。
- 嵌套插件：把嵌套选择器展开为平铺选择器。
- 预设插件：按目标浏览器批量启用需要降级的新语法。
- 接入前提：降级目标要与构建目标保持一致，避免两处配置互相矛盾。
- 核对方式：构建后检查产物中是否还存在未被处理的嵌套写法。

```js
// postcss.config.js
export default {
  plugins: {
    "postcss-nesting": {},
  },
};
```

> [!CAUTION]
> **注意内容**：降级目标与构建目标不一致时，会出现语法已降级却仍缺必要前缀、或降级过头两类问题，两处目标必须统一维护。

**速记**：新语法与嵌套靠 PostCSS 插件降级，降级目标必须与构建目标一致。



#### 浏览器前缀与目标控制

**浏览器前缀补全**：是按目标浏览器为需要前缀的声明自动追加前缀的能力，Vite 不内置该能力，需引入插件承担。

- 前缀来源：Vite 不自动补前缀，需要引入前缀补全插件。
- 目标来源：前缀补全插件按自身配置的目标浏览器决定补哪些前缀。
- 与构建目标的关系：构建目标控制语法降级，前缀由 PostCSS 侧控制。
- 配置写法：把目标写进前缀插件的配置，或使用共享的目标配置文件。
- 目标统一：用同一份目标配置同时供前缀插件与构建配置读取。
- 核对方式：构建后检查样式产物中是否出现预期的前缀。

```js
// postcss.config.js
export default {
  plugins: {
    autoprefixer: { overrideBrowserslist: ["defaults"] },
  },
};
```

> 前缀补全与语法降级是两条独立链路，只配其中一处不会得到完整的兼容结果。

**速记**：前缀靠插件补全，目标要与构建目标同源维护。



### 样式产物体积与拆分

样式产物的划分跟随脚本的划分，体积问题多半来自拆分方式而非写法。

#### 按入口与异步块拆分

**样式拆分**：是让样式产物随脚本分包一同划分、异步块各自带走自己样式的机制。

- 拆分开关：样式拆分开关控制是否随代码分包产出样式文件。
- 异步块：动态导入的模块对应样式会随该块单独产出。
- 加载时机：块被加载时样式随之加载，未进入的页面不下载该样式。
- 页面首屏：入口对应的样式仍随首屏加载。
- 合并取舍：关闭拆分可减少请求数，但会让首屏加载全部样式。
- 适用判断：页面数量少、样式总量小时合并更简单。

```js
// 动态导入使目标模块的脚本与样式一起成为异步块
const panelModule = await import("./panels/DetailPanel.js");
panelModule.render();
```

> [!NOTE]
> **提醒内容**：关闭样式拆分能减少请求数量，但首屏会加载到未使用页面的样式，是否关闭需按项目规模与样式总量权衡。

**速记**：样式随脚本分包走，异步块自带样式，关闭拆分会让首屏加载全部样式。



#### 重复样式的来源与消除

**重复样式**：是同一段规则出现在多个样式产物中的现象，主要来自分包划分而非源码重复书写。

- 来源一：多个入口引用同一份全局样式文件。
- 来源二：多个异步块共享同一组件的样式。
- 消除手段：把公共样式集中到入口引入，避免在各块内重复引用。
- 工具手段：通过手动分包配置把共享模块归入同一个 chunk。
- 核对方式：对比样式文件内容，确认同一段规则没有出现多次。
- 体积影响：重复规则既增加体积，也让同优先级规则的生效顺序更难预测。

```ts
export default {
  build: {
    rollupOptions: {
      output: {
        manualChunks: { shared: ["src/shared/styles/index.css"] },
      },
    },
  },
};
```

> 重复样式通常来自分包结果而非源码，先看产物的分包划分再看源码引用。

**速记**：重复样式来自分包划分，把共享样式归入公共 chunk 消除。



#### 与分包策略的关系

**分包联动**：是样式产物的文件划分与脚本 chunk 划分共用同一套依据的关系。

- 联动关系：样式产出的文件划分跟随脚本 chunk 的划分。
- 调整方式：改动手动分包配置会同时改变脚本与样式的产物结构。
- 共享样式：归入公共 chunk 的模块，其样式也归入对应的公共样式文件。
- 稳定做法：先定下分包策略，再核对样式产物是否符合预期。
- 压缩控制：样式压缩由构建配置单独控制，与脚本压缩分开。
- 体积核对：样式体积与脚本体积分别核对，避免只看总体积漏掉样式膨胀。

```ts
export default {
  build: {
    cssCodeSplit: true,
    cssMinify: true,
  },
};
```

> 样式拆分与脚本分包共用一个依据，调整分包时把样式产物一并纳入核对范围。

**速记**：样式与脚本共用分包依据，调整分包时同步核对样式产物。
