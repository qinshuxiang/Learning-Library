## Gulp 文件流与 glob 匹配

### src 与 dest

流水线的两端是读入与写出。本节说明 src 的读入行为、dest 的写出行为，以及写出时的目录还原规则。

#### src 的读入行为

**gulp.src**：是按通配模式读入文件、返回文件流的读入接口，签名为 gulp.src(globs, options)。

- 参数一：通配模式，可为字符串或字符串数组，数组表示多组模式。
- 参数二：可选配置，控制基准目录、是否读取内容等行为。
- 匹配方式：按模式在文件系统中查找文件，命中的文件进入流。
- 延迟读取：文件内容按需读取，避免一次性载入全部内容。
- 无匹配：没有文件命中时流为空，任务仍会正常结束。

```js
const { src, dest } = require('gulp');

// 读入一组样式文件
function readStyles() {
  return src('src/styles/*.css').pipe(dest('dist/styles'));
}

exports.readStyles = readStyles;
```

> src 只描述读入范围，不改变文件位置，路径的展开规则由基准目录决定。

**速记**：gulp.src 按通配模式读入文件并返回文件流，无匹配时流为空但任务不报错。



#### dest 的写出行为

**gulp.dest**：是把流中的文件按各自路径写入目标目录、并返回可继续串联的流的写出接口，签名为 gulp.dest(directory, options)。

- 参数一：目标目录，不存在时自动创建。
- 参数二：可选配置，控制是否覆盖已有文件、写入模式等。
- 返回值：写出后返回新流，可在其后继续追加处理步骤。
- 重复写出：同一管道可在不同位置多次调用 dest，产出多份结果。

```js
const { src, dest } = require('gulp');

// 同一份输入写出到两个目录
function writeBoth() {
  return src('src/text/*.txt').pipe(dest('dist/text')).pipe(dest('build/text'));
}

exports.writeBoth = writeBoth;
```

> [!NOTE]
> **提醒内容**：dest 会按文件的相对路径创建子目录，若只想要平铺结构，需要在写出前调整文件的相对路径。

**速记**：gulp.dest 按相对路径写出并自动建目录，返回新流可继续串联。



#### 写出目录的还原规则

**目录还原**：是 dest 依据文件的相对路径片段在目标目录下重建子目录、保持原有层级的行为。

- 还原来源：相对路径取自基准目录到文件之间的路径段落。
- 层级保持：中间目录会被原样重建，不压平。
- 结果形态：目标目录下出现与相对路径一致的结构。
- 常见意外：基准目录取到比预期更上层的位置时，目标目录会多出若干层。
- 控制方式：在 src 中显式指定基准目录，限定参与还原的路径段落。

```text
源文件：      src/scripts/app/index.js
基准目录：    src/scripts
相对路径：    app/index.js
写出结果：    dist/scripts/app/index.js
```

> 目录还原的效果完全由相对路径决定，路径多一层或少一层都源于基准目录的取值。

**速记**：dest 按相对路径重建子目录，层级是否正确取决于基准目录取在哪里。



### glob 语法

通配模式圈定读入范围。本节说明通配符、排除模式与多模式数组的求值顺序。

#### 通配符

**通配模式（glob）**：是用通配符描述一组文件路径的字符串，Gulp 用它圈定读入与监听的范围。

- 星号：匹配单层路径中的任意个字符，不跨目录分隔符。
- 双星号：匹配任意层目录，常用于递归取整个子树。
- 方括号：匹配括号内列出的任意一个字符或字符范围。
- 花括号扩展：用逗号分隔多个候选，展开为多条模式的并集。

```js
const { src, dest } = require('gulp');

// 各类通配写法
src('src/*.css');              // src 下第一层的全部样式文件
src('src/**/*.css');           // src 下任意层级的样式文件
src('src/img/icon-?.png');     // 单字符位置为通配
src('src/img/[ab]*.png');      // 以 a 或 b 开头
src('src/img/*.{png,jpg}');    // 两种扩展名
```

> 双星号跨目录、单星号不跨目录，这条差别是写错通配模式时最常见的来源。

**速记**：单星号不跨目录、双星号跨任意层，花括号展开为多条模式的并集。



#### 排除模式

**排除模式**：是以叹号开头的通配模式，用于从已匹配的集合中剔除满足条件的文件。

- 写法：在模式前加叹号，如排除测试目录下的文件。
- 作用范围：从当前已选集合中减去匹配的模式结果。
- 顺序影响：排除按书写顺序生效，先加入后排除。
- 常见用途：剔除测试文件、临时文件、编辑器的备份文件。
- 多模式配合：与正向模式写成数组，同时表达取入与剔除。

```js
const { src, dest } = require('gulp');

// 取入全部脚本，排除测试与临时文件
function buildScripts() {
  return src([
    'src/scripts/**/*.js',
    '!src/scripts/**/*.test.js',
    '!src/scripts/**/*.tmp.js'
  ]).pipe(dest('dist/scripts'));
}

exports.buildScripts = buildScripts;
```

> [!CAUTION]
> **注意内容**：排除模式写在正向模式之前不会生效，数组中的顺序就是匹配的执行顺序。

**速记**：叹号模式从集合中剔除文件，必须写在正向模式之后才生效。



#### 多模式数组

**多模式数组**：是把多条通配模式放入同一数组、按顺序依次求并集再求差的写法。

- 求值顺序：数组中自上而下处理，正向模式做并集，排除模式做差集。
- 合并读入：多组来源可一次读入，再统一处理。
- 结果形态：数组最终得到一个文件集合，与单条模式无差别。
- 注意点：重复匹配的文件只出现一次，不会重复进入流。

```js
const { src, dest } = require('gulp');

// 从两个来源读入页面，排除草稿
function buildPages() {
  return src([
    'src/pages/**/*.html',
    'src/templates/**/*.html',
    '!src/pages/drafts/**'
  ]).pipe(dest('dist'));
}

exports.buildPages = buildPages;
```

> 数组写法只影响匹配范围，不改变处理方式，最终仍是一个文件集合。

**速记**：数组按顺序并集再差集，重复命中只保留一份，最终仍是一个文件集合。



### 基准目录与路径还原

基准目录决定产物的目录层级。本节说明它的作用、路径被展开的原因，以及指定与调整的方式。

#### 基准目录的作用

**基准目录（base）**：是文件相对路径的计算起点，文件的相对路径等于其绝对路径去掉基准目录部分。

- 计算规则：相对路径由绝对路径减去基准目录得出。
- 决定对象：它决定 dest 写出时创建哪些子目录。
- 默认取值：未显式指定时按通配模式推导，取模式中通配符之前的字面路径。
- 影响范围：基准目录变化会整体改变产物的目录层级。
- 使用建议：路径层级有不确定时显式指定，避免依赖推导结果。

```js
const { src, dest } = require('gulp');

// 显式指定基准目录为 src，产物保留 pages 这一层
function buildPages() {
  return src('src/pages/**/*.html', { base: 'src' })
    .pipe(dest('dist'));
}

exports.buildPages = buildPages;
```

> 基准目录是路径还原的唯一依据，写不出预期层级时先确认它被推导成了什么。

**速记**：基准目录是相对路径的起点，直接决定 dest 重建出多少层子目录。



#### 路径被展开的原因

**路径展开**：是产物目录比预期多出若干层，根因是基准目录被推导到比预期更上层的位置。

- 触发条件：通配模式中通配符之前的路径段过多或过少。
- 典型表现：产物落在多出的目录前缀之下。
- 推导规则：默认基准目录取通配符之前的全部字面路径。
- 定位方法：对比源文件路径与产物路径，多出的前缀即基准目录取值。
- 修正方式：显式传入基准目录，或在读入后改写文件的相对路径。

```text
模式：src/pages/**/*.html
默认基准目录：src/pages
相对路径：index.html
产物：dist/index.html

模式：src/**/*.html
默认基准目录：src
相对路径：pages/index.html
产物：dist/pages/index.html
```

> [!IMPORTANT]
> **重要内容**：同一份源文件用不同通配模式读入会得到不同的产物层级，改模式前要连同基准目录一起确认。

**速记**：产物多出层级源于基准目录被推导到更上层，显式指定即可固定层级。



#### 指定与调整基准目录

**基准目录调整**：是通过读入配置或改写文件路径来固定相对路径、使产物层级符合预期的做法。

- 读入时指定：在 src 的配置项里传入基准目录，一次固定整批文件。
- 逐文件改写：在管道中修改文件对象的基准目录字段。
- 选择依据：同一批文件层级一致时用读入配置，需分别处理时逐文件改写。
- 风险：改写路径会影响后续 dest 的写出位置，须在写出前完成。
- 核对方式：先跑一次任务，比对产物目录层级是否符合预期。

```js
const { src, dest } = require('gulp');

// 读入时指定基准目录，产物只保留文件名
function flattenStyles() {
  return src('src/styles/themes/dark/*.css', { base: 'src/styles/themes/dark' }).pipe(dest('dist/themes/dark'));
}

exports.flattenStyles = flattenStyles;
```

> 基准目录的调整必须在 dest 写出之前完成，写出之后改动不会再影响已有产物。

**速记**：基准目录可在读入时统一指定或逐文件改写，调整要发生在写出之前。



### 读取与写回

流中的每个文件对象都携带路径与内容。本节说明文件对象的字段、内容的修改方式，以及流中增删文件的做法。

#### 文件对象的字段

**文件对象**：是流中流动的数据单元，携带路径、内容与读写标记等字段，遵循 vinyl 文件的字段约定。

- 绝对路径字段：记录文件在文件系统中的完整路径。
- 相对路径字段：记录去掉基准目录后的路径片段。
- 基准目录字段：记录相对路径的计算起点。
- 内容字段：保存文件内容，类型可为缓冲区或流。

```js
const { src, dest } = require('gulp');

// 打印每个文件对象的路径与基准目录
function inspectFiles() {
  return src('src/**/*.txt')
    .on('data', (file) => console.log(file.path, file.base, file.relative))
    .pipe(dest('dist'));
}

exports.inspectFiles = inspectFiles;
```

> 文件对象的三个路径字段互相推导，改动其中一个会影响 dest 的写出位置。

**速记**：文件对象携带绝对路径、相对路径、基准目录与内容，路径字段决定写出位置。



#### 修改文件内容

**内容修改**：是在管道中改写文件对象的内容字段、使中间步骤可以加工文本的做法。

- 读取内容：把内容字段转为字符串后加工。
- 写回内容：把加工结果转回缓冲区并赋回内容字段。
- 时机：修改发生在写出之前，dest 之后的内容不再参与处理。
- 适用场景：替换占位、插入标记、统一换行等文本级加工。
- 注意点：二进制文件不能按字符串处理，需按缓冲区分支判断。

```js
const { src, dest } = require('gulp');
const { Transform } = require('stream');

// 把源文件中的占位符替换为构建版本号
function replaceVersion(version) {
  return new Transform({
    objectMode: true,
    transform(file, encoding, done) {
      file.contents = Buffer.from(file.contents.toString().replace('__VERSION__', version));
      done(null, file);
    }
  });
}

function stampVersion() {
  return src('src/**/*.txt')
    .pipe(replaceVersion('1.0.0'))
    .pipe(dest('dist'));
}

exports.stampVersion = stampVersion;
```

> [!TIP]
> **建议内容**：文本加工统一在做完二进制判定之后进行，避免把图片等二进制文件按字符串误处理。

**速记**：内容修改在写出前完成，读字符串、改后转回缓冲区，二进制文件需另行判断。



#### 新增与删除文件

**流中增删**：是在管道中向流内加入新的文件对象，或把不需要的文件对象从流中移除。

- 新增方式：构造文件对象并推入流中，使其参与后续写出。
- 删除方式：判断不需要的文件后不向下传递即可。
- 判定依据：以文件对象的路径或内容作为筛选条件。
- 使用场景：生成补充文件、剔除不需要的产物。
- 注意点：新增对象的路径字段要与基准目录匹配，否则写出位置异常。

```js
const { src, dest } = require('gulp');
const { Transform } = require('stream');
const { File } = require('vinyl');

// 在流末尾追加一个站点说明文件
function appendNotice(notice) {
  return new Transform({
    objectMode: true,
    transform(file, encoding, done) {
      done(null, file);
    },
    flush(done) {
      this.push(new File({ path: 'notice.txt', contents: Buffer.from(notice) }));
      done();
    }
  });
}

function buildWithNotice() {
  return src('src/**/*.txt').pipe(appendNotice('built by gulp')).pipe(dest('dist'));
}

exports.buildWithNotice = buildWithNotice;
```

> 向流中推入的对象必须补齐路径与内容字段，缺少路径会导致写出阶段报错。

**速记**：流内可新增文件对象或过滤掉不需要的文件，新增对象必须补齐路径与内容。



### 文件流常见问题

文件流的问题集中在匹配与路径上。本节列出空流、路径错位与写回覆盖三类高频现象。

#### 空流

**空流**：是通配模式未命中任何文件、流中不含文件对象的状态，任务会正常结束但不产出结果。

- 成因：模式写错、目录不存在、扩展名不匹配。
- 表现：任务执行成功，产物目录没有变化或未被创建。
- 排查：单独执行匹配命令确认模式能否命中文件。
- 预防：目录与文件命名变化时同步更新通配模式。

```bash
ls src/pages/*.html
# zsh: no matches found
# 模式在实际文件系统上无命中，任务会得到空流
```

> 空流不是错误，Gulp 不会因为没有任何文件而中断任务，因此需要主动核对结果。

**速记**：空流来自模式未命中，任务仍成功结束，需主动核对产物是否存在。



#### 路径错位

**路径错位**：是产物目录结构或文件名与源文件不一致的现象，根因通常在基准目录或文件路径字段被改动。

- 表现：产物多出目录前缀，或文件名被意外改写。
- 成因一：基准目录的推导结果与预期不符。
- 成因二：管道中改写了文件对象的路径字段。
- 排查：打印每个文件对象的路径、相对路径与基准目录。
- 修正：在读入时固定基准目录，或在写出前还原路径。

```js
const { src, dest } = require('gulp');

// 打印路径三字段，定位产物层级偏差的来源
function tracePath() {
  return src('src/**/*.txt')
    .on('data', (file) => console.log('base:', file.base, '| relative:', file.relative))
    .pipe(dest('dist'));
}

exports.tracePath = tracePath;
```

> [!WARNING]
> **警告内容**：路径错位在文件数量多时不易察觉，产物分发到服务器后才暴露为资源 404，宜在构建阶段就核对目录层级。

**速记**：路径错位来自基准目录或被改写的路径字段，打印三字段即可定位。



#### 写回覆盖

**写回覆盖**：是把产物写回源目录、导致同一批文件被反复处理或源文件被替换的情形。

- 成因：源目录与产物目录相同，或产物目录落在通配模式范围内。
- 后果一：重复执行时把上一次的产物再次加工，结果不断叠加。
- 后果二：源文件被覆盖，无法从源头重新构建。
- 排查：核对 dest 的目标目录是否被 src 的模式覆盖。
- 规避：源与产物目录分开，产物目录加入忽略清单。

```js
const { src, dest } = require('gulp');

// 产物写入 dist，模式只覆盖 src，二者不交叉
function safeBuild() {
  return src('src/**/*.css').pipe(dest('dist'));
}

exports.safeBuild = safeBuild;
```

> [!CAUTION]
> **注意内容**：产物目录一旦落在源通配模式范围内，任务每次执行都会把结果再加工一遍，源文件也可能被不可逆地覆盖。

**速记**：源与产物目录必须分开，产物落进通配范围会导致结果叠加或源文件被覆盖。
