## Gulp 安装与首个任务

### 环境准备与安装

本节处理 Gulp 侧的运行前提与安装方式，只涉及 Gulp 自身的安装与调用，包管理器的通用命令归后端 Node 主题。

#### Node 版本要求

**Node 版本要求**：是 Gulp 可运行所依赖的运行时下限，需选择仍在维护期内的 Node LTS 版本，避免使用已停止维护的旧版本。

- 判断依据：以官方文档标注的支持范围为准，不凭经验估计。
- 选择建议：开发机与流水线使用同一大版本，减少环境差异。
- 检查方式：用 node 命令的版本参数确认当前运行时版本。
- 版本管理：多项目共存时用版本管理工具切换，不全局写死一个版本。
- 影响范围：版本过低会导致安装或运行失败，过高一般向后兼容但仍需回归一次构建。

```bash
node --version
# 输出当前运行时版本，需落在 Gulp 支持的范围内
```

> 运行时版本以项目声明的 engines 字段为约定，团队内保持一致比追新更重要。

**速记**：Gulp 依赖 Node 运行，选用仍在维护的 LTS 版本并保持开发与流水线一致。



#### 本地安装项目依赖

**本地安装**：是把 Gulp 作为项目依赖装入本地依赖目录、使构建能力随项目一起分发的方式。

- 安装目标：写入开发依赖字段，因为只在开发与构建阶段使用。
- 版本来源：安装命令解析出的版本记录在锁文件中，保证多机一致。
- 调用方式：通过包管理器的执行命令调用，或由项目的脚本字段转发。
- 目录位置：实现位于项目依赖目录，随项目一起检出与安装。
- 升级方式：升级时同时更新依赖字段与锁文件，并回归一次构建任务。

```bash
npm install --save-dev gulp
# 把 gulp 写入项目的开发依赖字段
npm ls gulp
# 确认项目内解析出的 gulp 版本
```

> 依赖字段与锁文件要一起提交，只提交其中一个会让不同机器解析出不同版本。

**速记**：Gulp 装入开发依赖，版本由锁文件固化，调用时用本地依赖目录里的实现。



#### 命令行工具的作用

**命令行工具**：是提供 gulp 命令的外层程序，负责定位并调用项目内安装的 Gulp 版本，自身不承担构建逻辑。

- 定位实现：在项目目录中查找本地安装的版本并加载。
- 版本无关：同一套命令行工具可服务多个项目，实际执行版本随项目而变。
- 全局提供：按官方文档全局安装后即可在任意项目目录使用该命令。
- 免装替代：用包管理器的执行命令直接调用本地版本，效果等价。
- 常见报错：命令找不到通常是没有命令行工具，任务无法加载通常是本地版本缺失。

```bash
npm install --global gulp-cli
# 提供 gulp 命令，实际执行的是各项目内的本地版本
gulp --version
# 同时显示命令行工具与本地 Gulp 的版本
```

> [!IMPORTANT]
> **重要内容**：命令行工具与本地版本是两层，全局装过命令行工具不等于项目里已装 Gulp，二者需同时满足才可运行。

**速记**：命令行工具只负责找本地版本并调用，实际构建能力来自项目内的安装。



### gulpfile 的基本结构

gulpfile 是命令行工具加载的入口，结构决定任务如何被识别。本节说明文件位置、导出方式与配置拆分。

#### 文件位置与命名

**gulpfile**：是放置任务定义、供命令行工具加载的入口文件，默认名为 gulpfile.js，放在项目根目录。

- 默认名：文件名为 gulpfile 加脚本后缀，命令行按此名自动识别。
- 位置：放在项目根目录，与依赖清单同层，便于定位。
- 目录约定：源目录、产物目录、临时目录在文件内以常量声明。
- 模块格式：文件遵循项目的模块格式约定，CommonJS 与 ESM 写法不同。
- 自定义入口：需要指定其他文件名时通过命令行参数传入。

```js
const { src, dest } = require('gulp');

const paths = {
  source: 'src',
  output: 'dist'
};

function copyHtml() {
  return src(paths.source + '/**/*.html').pipe(dest(paths.output));
}

exports.copyHtml = copyHtml;
```

> 把目录写成文件顶部的常量，任务要改路径时可集中修改，避免路径散落在各处。

**速记**：gulpfile.js 是任务入口，默认放项目根目录，路径以常量集中声明。



#### 模块导出方式

**导出方式**：是把任务函数暴露给命令行工具的机制，遵循脚本模块的导出规则，导出名即任务名。

- 具名导出：导出的属性名就是命令行可调用的任务名。
- 默认导出：作为默认任务，直接运行 gulp 命令时执行。
- 导出范围：不导出的函数仍可在文件内被其他任务调用。
- 命名约定：任务名用小驼峰且语义明确，与函数名不必一致。
- 模块格式：CommonJS 用导出对象赋值，ESM 用 export 关键字。

```js
const { src, dest } = require('gulp');

function copyScripts() {
  return src('src/scripts/*.js').pipe(dest('dist/scripts'));
}

// 导出后成为命令行任务 copyScripts
exports.copyScripts = copyScripts;
```

> [!TIP]
> **建议内容**：任务函数与导出名尽量同名，减少函数名与命令行任务名对不上时的排查成本。

**速记**：导出名即任务名，默认导出为默认任务，未导出的函数只能在文件内部调用。



#### 配置拆分与复用

**配置拆分**：是把路径常量、任务实现与导出入口分到不同文件、再集中汇入 gulpfile 的组织方式。

- 拆分动机：任务增多后单文件过长，查找与复用都变困难。
- 常见切分：路径常量、按资源类型的任务、导出入口各成一组。
- 汇入方式：gulpfile 只负责引入并导出，不承载具体实现。
- 复用价值：同一步骤可被多个任务引用，避免复制处理逻辑。
- 注意点：拆分后仍需保持只有一个入口文件，避免加载歧义。

```js
// gulpfile.js：只做引入与导出
const { copyHtml } = require('./tasks/html');
const { copyStyles } = require('./tasks/styles');

exports.copyHtml = copyHtml;
exports.copyStyles = copyStyles;
```

```js
// tasks/html.js：任务实现
const { src, dest } = require('gulp');

function copyHtml() {
  return src('src/**/*.html').pipe(dest('dist'));
}

module.exports = { copyHtml };
```

> 拆分的目标是让入口文件保持简短，而不是为每个函数单开一个文件。

**速记**：把路径、任务与导出拆开，gulpfile 只引入与导出，实现留在各模块内。



### 任务的定义与导出

任务是一个函数，导出动作即注册。本节说明函数式任务的完成信号、私有任务的边界与导出即注册的规则。

#### 函数式任务

**函数式任务**：是把构建动作写成一个函数、由 Gulp 在调用时执行的任务形式。

- 定义方式：函数名即任务内部标识，导出名决定命令行入口。
- 返回值：返回流、Promise 或使用回调三种方式之一，用于告知任务何时完成。
- 异步支持：函数可写成异步函数，用 await 等待后续步骤。
- 参数：任务函数本身不接收参数，配置通过闭包或外部常量传入。
- 可测试性：任务体是普通函数，可脱离命令行单独调用验证。

```js
const { src, dest } = require('gulp');

async function copyThenReport() {
  const stream = src('src/**/*.txt').pipe(dest('dist/text'));
  await new Promise((resolve, reject) => {
    stream.on('end', resolve);
    stream.on('error', reject);
  });
  console.log('copy finished');
}

exports.copyThenReport = copyThenReport;
```

> 没有返回完成信号的函数会被当作同步任务，Gulp 会在其返回后立刻认为任务已结束。

**速记**：任务就是一个函数，靠返回流、Promise 或使用回调之一告知完成时机。



#### 私有任务

**私有任务**：是未被导出、只能由文件内其他任务调用的任务函数。

- 可见性：不出现在命令行任务列表中，无法直接触发。
- 用途：存放只作为中间步骤的清理、准备等辅助动作。
- 复用：可被多个导出任务共同引用。
- 命名：仍按动词加名词命名，保持可读。
- 边界：私有与公开的区别只在导出与否，不改变函数本身的行为。

```js
const { src, dest } = require('gulp');

// 私有任务：仅作为内部步骤，不导出
function prepareOutput() {
  return src('src/placeholder.txt').pipe(dest('dist'));
}

function buildAll() {
  prepareOutput();
  return src('src/**/*.css').pipe(dest('dist'));
}

exports.buildAll = buildAll;
```

> [!CAUTION]
> **注意内容**：在任务中直接调用另一个任务函数而不返回其流，会让 Gulp 无法等待该步骤完成，后续步骤可能提前开始。

**速记**：私有任务不导出、只供内部调用，调用时要把流或 Promise 传递出去才算等待。



#### 导出即注册

**导出即注册**：是 Gulp 的任务登记方式，函数一旦被导出就自动成为命令行可调用的任务，无需单独注册。

- 注册时机：加载 gulpfile 时扫描导出项并建立任务表。
- 任务名：取导出属性名，与函数名无关。
- 默认任务：默认导出对应直接运行 gulp 命令时执行的任务。
- 重复名：同一文件内导出名不能重复，否则后者覆盖前者。
- 错误暴露：任务表在加载时确定，导出写错会在运行时立即报错。

```js
const { src, dest } = require('gulp');

function copyFonts() {
  return src('src/fonts/*').pipe(dest('dist/fonts'));
}

// 导出即注册为命令行任务
exports.copyFonts = copyFonts;
```

> 任务列表由导出项决定，排查任务不存在时先检查导出名是否写对。

**速记**：导出动作本身就是注册，导出名即命令行任务名，默认导出即默认任务。



### 命令行用法

命令行是任务的触发入口。本节说明按名调用、默认任务与常用参数的用法。

#### 按任务名调用

**按任务名调用**：是在项目目录执行 gulp 命令并附上任务名、只运行指定任务的方式。

- 基本形式：命令后接任务名，可一次列出多个任务。
- 执行顺序：一次列出多个任务时按书写顺序依次执行。
- 工作目录：命令需在 gulpfile 所在目录执行，否则找不到入口。
- 找不到任务：任务不存在会列出可用任务，便于核对导出名。
- 退出码：任务失败时命令以非零退出码结束，供流水线判定。

```bash
npx gulp copyHtml
# 只运行 copyHtml 任务
npx gulp copyHtml copyStyles
# 依次运行两个任务
```

> 命令列多个任务时是串行执行，需要并行应把关系写进任务组合中。

**速记**：gulp 加任务名只跑指定任务，多个任务按书写顺序串行执行。



#### 默认任务

**默认任务**：是不带任务名直接运行 gulp 命令时执行的任务，通常用于汇总常用构建动作。

- 声明方式：通过默认导出指定，导出名固定。
- 用途：把开发或构建的常用入口统一到一个任务。
- 完成信号：默认任务与普通任务无异，同样需要返回完成信号。
- 缺失表现：未声明默认任务时直接运行会提示可选任务列表。
- 约定：默认任务宜轻量，指向具体任务而不是塞入全部实现。

```js
const { src, dest } = require('gulp');

function buildAll() {
  return src('src/**/*.html').pipe(dest('dist'));
}

// 默认导出：直接运行 gulp 命令时执行
exports.default = buildAll;
```

> 默认任务是命令行的零参数入口，保持它只做转发能降低误触发的概率。

**速记**：默认导出即默认任务，直接运行 gulp 命令时执行，宜作转发入口。



#### 常用命令行参数

**命令行参数**：是附加在 gulp 命令后、用于调整入口文件、任务列表与日志输出的选项。

- 指定入口：用文件参数指向自定义 gulpfile，替代默认文件。
- 工作目录：用目录参数指定执行根目录，影响相对路径解析。
- 任务列表：用任务列表选项查看可用任务及其依赖关系。
- 版本信息：用版本选项同时查看命令行工具与本地版本。
- 日志控制：输出详略由参数或环境变量控制，便于排查。

```bash
npx gulp --tasks
# 列出当前 gulpfile 中的任务
npx gulp --gulpfile config/gulpfile.js
# 指定非默认的入口文件
npx gulp --version
# 查看命令行工具与本地 Gulp 版本
```

> [!NOTE]
> **提醒内容**：入口文件与工作目录都会影响相对路径的解析结果，流水线中显式指定可避免依赖执行位置。

**速记**：常用参数控制入口文件、执行目录、任务列表与版本输出，路径相关参数要显式指定。



### 首个可运行示例

把前面的概念合成一条最小通路。本节从准备目录开始，实现读入与写出，最后核对结果。

#### 目录与源文件准备

**目录准备**：是先建好源目录与产物目录、放入待处理文件，使最小流水线有确定输入输出的步骤。

- 源目录：存放待处理文件，按资源类型分子目录。
- 产物目录：构建输出位置，不手工存放源文件。
- 示例文件：放入少量文本或页面文件，便于核对结果。
- 忽略清单：把产物目录加入忽略清单，避免提交构建结果。
- 目录约定：在 gulpfile 中以常量声明，不写散落的字面路径。

```bash
mkdir -p src/pages dist
printf 'hello gulp\n' > src/pages/index.txt
# 准备一个待处理的源文件
```

> 目录结构先定下来，任务里的通配模式才有明确的对象，结果也便于核对。

**速记**：先建源目录与产物目录并放入示例文件，路径在 gulpfile 中集中声明。



#### 最小流水线实现

**最小流水线**：是只包含读入与写出两步、用于验证环境与命令通路是否可用的任务。

- 读入：用 src 取一组文件。
- 写出：用 dest 指定产物目录。
- 返回：把流返回给 Gulp，使任务有明确的完成信号。
- 命名：函数与导出名一致，便于按名调用。
- 验证价值：跑通后再逐步插入处理步骤，出错范围可控。

```js
const { src, dest } = require('gulp');

// 读取 src/pages 下的文件并输出到 dist/pages
function copyPages() {
  return src('src/pages/*.txt').pipe(dest('dist/pages'));
}

exports.copyPages = copyPages;
```

> 最小流水线只验证通路，确认无误后再逐步加入处理步骤，避免一次引入过多变量。

**速记**：最小流水线只有 src 与 dest 两步，跑通通路后再逐步插入处理步骤。



#### 运行与结果核对

**结果核对**：是执行任务后检查产物目录内容、确认文件数量与内容符合预期的步骤。

- 执行方式：在项目目录按任务名运行命令。
- 输出日志：命令会打印起止时间与任务耗时。
- 目录核对：检查产物目录是否按源目录层级生成文件。
- 内容核对：打开产物文件确认内容与源文件一致。
- 重复执行：再次运行应得到相同结果，验证任务可重复执行。

```bash
npx gulp copyPages
# [起止时间] Starting 'copyPages'...
# [起止时间] Finished 'copyPages'
ls dist/pages
# index.txt
```

> [!IMPORTANT]
> **重要内容**：任务跑通却看不到产物时，优先核对 src 的通配模式是否匹配到文件，以及 dest 的目录是否写对。

**速记**：运行任务后核对产物数量与内容，重复执行结果一致才说明流水线可用。
