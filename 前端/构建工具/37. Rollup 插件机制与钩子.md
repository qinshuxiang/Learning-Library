## Rollup 插件机制与钩子

### 插件的基本结构

#### 插件对象与钩子属性

**插件对象（plugin object）**：是至少带 name 属性、并按需挂载钩子方法的普通对象，Rollup 在构建的各时点按名称查找并调用对应钩子。

- 必要属性：name 是插件的唯一标识，报错、警告与耗时日志都以此为来源标签。
- 钩子属性：属性名必须与钩子名一致，值可以是函数，也可以是含 handler 与 order 的对象。
- 两类钩子：构建阶段钩子只在构建时触发一次，输出阶段钩子对每个产物分别触发。
- 返回约定：返回空值表示不干预，返回具体内容才接管或改写该环节的结果。

```js
const stripDebugPlugin = {
  name: "strip-debug",
  transform(code, id) {
    if (!id.endsWith(".js")) return null;
    return { code: code.replace(/\bdebugger;?/g, ""), map: null };
  },
};
```

> 插件不需要继承基类或实现接口，只要属性名与钩子名一致就会被调用，名字写错则钩子永不触发。

**速记**：插件是带 name 与钩子方法的普通对象，钩子按时机分成构建与输出两类。



#### 插件工厂与选项传递

**插件工厂（plugin factory）**：是接收选项对象、返回插件对象的函数，把可配置的插件做成一次编写多处传入的形态。

- 调用约定：配置里写工厂调用而非插件对象，选项在构建开始前完成闭合。
- 默认值：形参给出默认对象，调用方省略选项时仍能正常工作。
- 选项校验：在工厂体内校验取值，非法选项在构建开始时立刻抛出，而不是运行中途失败。
- 多次实例化：同一工厂可传入不同选项生成多个实例，彼此状态互不影响。

```js
export default function replaceTokenPlugin(options = {}) {
  if (typeof options.token !== "string") throw new TypeError("token 必须是字符串");
  const pattern = new RegExp(options.token, "g");
  return {
    name: "replace-token",
    transform(code) {
      return { code: code.replace(pattern, options.value ?? "local"), map: null };
    },
  };
}
```

> 工厂只负责组装插件对象，真正的构建逻辑仍写在钩子内，选项在工厂调用时求值一次，钩子内应避免重复读取配置文件。

**速记**：工厂把选项闭合进插件对象，默认值与校验都在工厂体内一次完成。



#### 插件命名与调试入口

**插件命名**：是以 name 属性区分插件来源的做法，命名唯一且带前缀，能在警告与耗时统计中直接定位到责任方。

- 唯一性：同一份配置里出现两个同名插件时，警告信息无法区分，排查成本立刻上升。
- 命名风格：用短横线连接的小写短语，必要时加组织前缀，避免与内置能力混淆。
- 条件禁用：用配置里的开关把插件从 plugins 数组中剔除，比在钩子里加判断更直接。
- 报错定位：钩子内抛出的错误会带上插件名，抛出自定义信息比静默返回更能说明原因。

```js
import { defineConfig } from "rollup";

export default defineConfig({
  input: "src/index.js",
  output: { file: "dist/index.js", format: "es" },
  plugins: [replaceTokenPlugin({ token: "__ENV__", value: "production" })],
  onwarn(warning, warn) {
    console.warn(`[rollup] ${warning.code}: ${warning.message}`);
    warn(warning);
  },
});
```

> [!WARNING]
> **警告内容**：忽略 onwarn 会让所有警告静默通过，未解析的导入与失效的指令都难以及时发现，排查时先恢复警告输出再定位问题。

**速记**：name 唯一且带前缀便于定位，调试靠阶段日志与 onwarn 输出。



### 构建阶段钩子

#### 解析类钩子 resolveId

**resolveId 钩子**：是把导入说明符翻译为实际模块标识的钩子，签名是 resolveId(source, importer, options)，返回标识字符串、对象或空值。

- 触发时机：每遇到一条静态导入或动态导入都会触发，入口文件同样会触发一次。
- 参数含义：source 是导入写法，importer 是发起导入的文件，入口的 importer 为空。
- 返回值：返回字符串即确认标识，返回含 id 与 external 的对象可把模块标记为外部依赖。
- 空值语义：返回空值表示本插件不处理，交给后续插件或交给 Rollup 默认逻辑。
- 虚拟模块：用约定前缀构造不存在的标识，再由 load 钩子提供内容，避免被当作路径解析。

```js
const virtualConfigPlugin = {
  name: "virtual-config",
  resolveId(source) {
    if (source === "virtual:app-config") return "\0virtual:app-config";
    return null;
  },
  load(id) {
    if (id !== "\0virtual:app-config") return null;
    return `export const appName = ${JSON.stringify(process.env.APP_NAME ?? "demo")};`;
  },
};
```

> 标识以反斜杠零开头是社区约定，用于告诉其他插件「这不是真实文件路径，请勿再解析」，沿用该约定可减少插件之间的相互干扰。

**速记**：resolveId 把说明符变成标识，空值放行、非空接管的规则是插件协作的基础。



#### 加载与转换钩子 load 与 transform

**load 钩子**：是按标识给出模块原始内容的钩子，签名是 load(id)；**transform 钩子**：是接收已加载内容并返回改写后内容的钩子，签名是 transform(code, id)。

- 分工：load 决定内容从哪来，transform 决定内容改成什么，两者返回空值都表示不处理。
- 执行对象：两个钩子对所有模块生效，包括依赖目录中的文件，需要自行用路径过滤排除。
- 返回结构：可返回字符串，也可返回含 code 与 map 的对象，返回对象才能控制映射衔接。
- 链式改写：多个插件的 transform 按插件顺序依次串行，前一个的输出即后一个的输入。

```js
export default function inlineVersionPlugin(version) {
  return {
    name: "inline-version",
    transform(code, id) {
      if (id.includes("/node_modules/")) return null;
      if (!code.includes("__VERSION__")) return null;
      return { code: code.replace(/__VERSION__/g, JSON.stringify(version)), map: null };
    },
  };
}
```

> [!CAUTION]
> **注意内容**：转换后返回空 map 会让该模块的映射整体错位，调试时断点会落到错误行，改动代码的转换插件必须显式给出映射或声明映射不可用。

**速记**：load 供内容、transform 改内容，两者都返回空值放行，多个 transform 按顺序串联。



#### 模块分析类钩子 moduleParsed

**moduleParsed 钩子**：是在单个模块解析完成后触发、用于读取其静态信息的钩子，签名是 moduleParsed(moduleInfo)，返回空值即可。

- 触发时机：模块完成解析且确定导入与导出后触发，一次构建中每个模块触发一次。
- 可读信息：moduleInfo 含 id、importedIds、dynamicallyImportedIds 与 isEntry 等字段。
- 典型用途：统计模块数量、检查入口是否被正确识别、为后续钩子建立模块索引。
- 缓存影响：命中缓存的模块不会重新解析，依赖该钩子的统计在增量构建时可能不完整。

```js
export default function reportGraphPlugin() {
  const entries = [];
  const dynamicIds = new Set();
  return {
    name: "report-graph",
    moduleParsed(info) {
      if (info.isEntry) entries.push(info.id);
      for (const id of info.dynamicallyImportedIds) dynamicIds.add(id);
    },
    buildEnd() {
      console.log(`入口 ${entries.length} 个，动态导入模块 ${dynamicIds.size} 个`);
    },
  };
}
```

> 需要跨模块汇总时，在 moduleParsed 中累积、在 buildEnd 中一次性输出，可避免每个模块各打印一次造成的日志噪声。

**速记**：moduleParsed 拿单个模块的导入导出信息，配 buildEnd 做整次构建的汇总。



### 输出阶段钩子

#### 渲染类钩子 renderChunk

**renderChunk 钩子**：是在单个产物块完成渲染后触发、可对其最终代码做最后改写的钩子，签名是 renderChunk(code, chunk, outputOptions)。

- 触发次数：每个产物块触发一次，多格式输出时同一块会按格式各触发一次。
- 可读信息：chunk 含 fileName、isEntry、imports 与 exports 等字段，可用于区分入口与分块。
- 返回结构：返回含 code 与 map 的对象才算改写成功，混用字符串会带来升级时的行为差异。
- 典型用途：追加许可头、替换构建期常量、对最终代码做轻量后处理。
- 边界：此处代码已完成打包，不宜再改写模块结构，结构层面的调整应前移到 transform。

```js
const bannerPlugin = {
  name: "entry-banner",
  renderChunk(code, chunk) {
    if (!chunk.isEntry) return null;
    return { code: `/* generated entry: ${chunk.fileName} */\n${code}`, map: null };
  },
};
```

> 需要内容哈希稳定时，不要在产物中写入时间戳或随机数，否则每次构建的哈希都会变化，缓存随之全部失效。

**速记**：renderChunk 在块渲染完成后做最后改写，按块触发、多格式各触发一次。



#### 产物生成钩子 generateBundle

**generateBundle 钩子**：是在产物写入磁盘之前触发、可直接增删改产物的钩子，签名是 generateBundle(options, bundle)。

- 触发时机：每个输出的全部块与资源已生成但尚未写入，此时修改 bundle 会落到最终结果。
- 可读结构：bundle 是以文件名为键、以块或资源对象为值的对象，键即产物路径。
- 增删改：改写对象的 code 或 source 即修改内容，删除对应键即阻止该产物写出。
- 追加资源：通过 this.emitFile 发出类型为 asset 的文件，用于产出清单、样式表等附加产物。

```js
const manifestPlugin = {
  name: "emit-manifest",
  generateBundle(options, bundle) {
    const manifest = Object.values(bundle).map((item) => ({
      fileName: item.fileName,
      type: item.type,
    }));
    this.emitFile({ type: "asset", fileName: "manifest.json", source: JSON.stringify(manifest) });
  },
};
```

> [!IMPORTANT]
> **重要内容**：需要新增或修改产物必须在 generateBundle 内完成，writeBundle 触发时文件已经落盘，在那里改动只会让磁盘与 bundle 对象不一致。

**速记**：generateBundle 在落盘前读写 bundle，用 emitFile 追加资源，是干预产物的最后时机。



#### 写入与收尾钩子 writeBundle 与 closeBundle

**writeBundle 钩子**：是产物写入磁盘后触发、用于校验与后置处理的钩子；**closeBundle 钩子**：是全部输出结束后触发一次的收尾钩子。

- 触发顺序：generateBundle 先于 writeBundle，closeBundle 在全部输出完成后触发。
- 观测性质：writeBundle 拿到的是已写入的产物，适合做体积统计、文件校验与外部命令调用。
- 多输出语义：一次构建有多个输出时 writeBundle 按输出各触发一次，closeBundle 只触发一次。
- 失败处理：在 writeBundle 中抛错会让构建以失败退出，适合承载产物体积这类硬性检查。
- 资源释放：closeBundle 用于关闭自建的文件句柄、子进程与定时器，避免监听期的资源泄漏。

```js
const sizeLimitPlugin = (limitBytes = 200 * 1024) => ({
  name: "size-limit",
  writeBundle(options, bundle) {
    const total = Object.values(bundle)
      .filter((item) => item.type === "chunk")
      .reduce((sum, item) => sum + Buffer.byteLength(item.code), 0);
    if (total > limitBytes) this.error(`产物体积 ${total} 字节，超过上限 ${limitBytes} 字节`);
  },
});
```

> 监听模式下每轮重建都会触发一次 writeBundle，日志与外部命令要控制频率，否则终端输出会被重复信息淹没。

**速记**：writeBundle 落盘后做校验，closeBundle 全局收尾一次，二者时机不可互换。



### 钩子的执行顺序

#### 顺序容器 order

**顺序容器（order）**：是把钩子写成含 handler 与 order 字段的对象、借 order 声明先于还是后于同类钩子的写法，取值为 pre 或 post。

- 写法：钩子值由函数改为对象，handler 放原函数，order 放 pre 或 post。
- 语义：pre 在所有常规同类钩子之前执行，post 在所有常规同类钩子之后执行。
- 适用范围：order 只调整同类钩子内部的相对次序，不改变构建阶段与输出阶段的先后。
- 局限：order 只表达相对位置，无法表达「必须等某个插件完成」这类数据依赖。

```js
export default function inlineEnvPlugin(env = {}) {
  return {
    name: "inline-env",
    transform: {
      order: "pre",
      handler(code) {
        return { code: code.replace(/__ENV_(\w+)__/g, (m, key) => JSON.stringify(env[key] ?? "")), map: null };
      },
    },
  };
}
```

> [!IMPORTANT]
> **重要内容**：order 只表达同阶段内同类钩子的先后，无法表达插件之间的数据依赖，靠 order 拼凑依赖关系在插件增减后极易失效。

**速记**：order 取 pre 或 post，只调同类钩子内部次序，不表达数据依赖。



#### 插件之间的执行顺序

**插件顺序**：是 plugins 数组中的排列次序，决定解析类钩子的命中优先级与转换类钩子的串联次序。

- 数组顺序：数组靠前的插件先执行，对首个非空返回值即生效的钩子，靠前者直接决定结果。
- 首命中钩子：resolveId 与 load 属于首个有效返回值生效的类型，靠前的插件优先接管。
- 串行钩子：transform 与 renderChunk 属于逐个串行的类型，数组顺序即内容改写顺序。
- 实践约束：把解析与别名类插件放在靠前位置，把压缩与统计类插件放在靠后位置。

```js
export default {
  input: "src/index.js",
  output: { file: "dist/index.js", format: "es" },
  plugins: [
    aliasPlugin({ entries: { "~utils": "./src/utils" } }),
    resolvePlugin(),
    transformPlugin(),
    sizeLimitPlugin(),
  ],
};
```

> 插件顺序是显式契约而非实现细节，配置里应按解析、转换、分析、压缩的先后成组排列，并在注释中标明不可调换的组合。

**速记**：数组顺序决定谁先接管、谁先改写，解析在前、压缩在后是不能颠倒的基本盘。



#### 钩子返回值的约定

**钩子返回值**：是插件向 Rollup 表达处理结果的方式，空值表示放行，非空值表示接管，不同类型的钩子对返回值的要求不同。

- 空值放行：返回空值或空对象表示本插件不处理，控制权交给后续插件或默认逻辑。
- 假值特例：解析类钩子返回 false 表示把该模块标记为外部依赖且不产生未解析警告。
- 对象结构：解析类返回含 id 与 external 的对象，加载与转换类返回含 code 与 map 的对象。
- 异步返回：钩子可以是异步函数，返回值以 Promise 解析后的结果为准。

```js
const cdnPlugin = {
  name: "cdn-modules",
  resolveId(source) {
    if (source.startsWith("node:")) return { id: source, external: true };
    if (source.startsWith("cdn:")) return false;
    return null;
  },
};
```

> 解析类钩子的 false 与含 external 的对象语义相近，区别只在是否抑制未解析警告，选择前先确认该依赖是否真的由运行环境提供。

**速记**：空值放行、非空接管、false 静默外部化，返回结构随钩子类型而异。



### 插件的封装与复用

#### 把项目配置抽成插件

**配置抽成插件**：是把散落在配置中的常量替换、产物改写等逻辑移入插件文件，使配置只保留组装职责的做法。

- 拆分依据：属性名即钩子名，一处逻辑只对应一个钩子，便于单独测试与替换。
- 目录约定：插件放在源码之外的独立目录，与构建配置分离，配置只引入插件工厂。
- 参数外置：把路径、阈值、开关做成工厂选项，同一插件可在多份输出配置中复用。
- 边界判断：只服务于单份配置且不含逻辑的常量，留在配置里比抽成插件更直观。

```js
export function bannerPlugin(text) {
  const banner = text.endsWith("\n") ? text : `${text}\n`;
  return {
    name: "prepend-banner",
    renderChunk(code, chunk) {
      return chunk.isEntry ? { code: banner + code, map: null } : null;
    },
  };
}
```

> 抽成插件的判断标准是「是否会被第二处使用」，只有一处使用的逻辑提前抽象，反而增加配置与实现之间的跳转成本。

**速记**：把可复用的改写逻辑移入插件目录，配置只做引入与组装，一处一钩子。



#### 插件内部的状态管理

**插件状态**：是插件在多个钩子之间共享的数据，通常存在闭包变量或插件对象属性中。

- 存储位置：闭包变量对同一插件实例可见，插件对象属性便于外部读取与调试。
- 生命周期：状态随插件实例存在，监听模式下实例不重建，状态会在多轮构建之间延续。
- 重置时机：在 buildStart 中清空上一轮累积的数据，保证每轮统计结果独立。
- 避免滥用：能由钩子参数推导的信息不必缓存，缓存反而带来失效问题。

```js
export default function countModulesPlugin() {
  let count = 0;
  return {
    name: "count-modules",
    buildStart() {
      count = 0;
    },
    moduleParsed() {
      count += 1;
    },
    buildEnd() {
      console.log(`本轮共解析 ${count} 个模块`);
    },
  };
}
```

> [!CAUTION]
> **注意内容**：监听模式下插件实例长期存活，未在 buildStart 重置的累积状态会让计数、缓存与去重结果逐轮膨胀，最终报出与事实不符的数据。

**速记**：状态存闭包或对象属性，监听模式下必须每轮在 buildStart 重置。



#### 插件的复用边界

**复用边界**：是判断一个插件该留在项目内、提取为独立包还是直接改用现成插件的分界，判据是通用性与维护成本。

- 项目内保留：与业务约定强耦合、只服务单个仓库的插件，留在仓库内最易随业务改动。
- 提取为包：多个仓库共用的插件才提取发布，并补上选项文档与最小示例。
- 优先复用：能力通用的解析、替换、压缩类需求先用成熟插件，自研只在现成方案不满足时启动。
- 淘汰机制：使用方归零的插件及时归档，留在仓库里会持续产生维护与审计成本。

```js
import { defineConfig } from "rollup";
import licensePlugin from "@my-scope/rollup-plugin-license";

export default defineConfig({
  input: "src/index.js",
  output: { file: "dist/index.js", format: "es" },
  plugins: [licensePlugin({ file: "LICENSE" })],
});
```
