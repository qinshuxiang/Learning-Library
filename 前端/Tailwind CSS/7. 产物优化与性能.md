## 产物优化与性能

### 产物体积

#### 按需生成的天然优势

**Tailwind 产物的体积逻辑**与组件库方案相反：只包含扫描到的工具类，**体积与项目使用的样式种类挂钩，与页面数量无关**。

- 典型中大型项目产物：10—30 KB（gzip 后 3—8 KB），且随迭代增长极其缓慢——新页面复用既有工具类，不产生新 CSS。
- **刻意触发产物膨胀的写法**只有一种：大量一次性任意值（`w-[137px]` 每个值都是一条新规则）与 safelist 滥用。控制它们就是控制体积。
- `safelist` 的正确定位：扫描不到的**极少数**动态类名白名单（如后端返回的主题枚举 `bg-success`），列出后无论是否出现都会生成——是兜底不是收纳盒。

> 原子化项目的 CSS 体积几乎不需要治理，这是机制自带的性质。对比传统方案「CSS 随业务线性增长、末年治理一整月」的成本曲线，是原子化在工程上最硬的论据。

**速记**：体积 **与样式种类挂钩、与页面无关**，管住任意值与 safelist 就没有体积问题。



### 开发与运行时性能

#### 构建速度与防闪烁

**性能关注点不在产物在过程**：构建速度、暗色模式防闪烁、与组件运行时的配合。

- **构建速度**：v4 引擎对全量编译做了重写，增量编译毫秒级；开发期若感觉慢，检查是否误用 v3 路径（`tailwind.config.js` 会被兼容加载，拖慢 v4）或扫描了 node_modules 大目录。
- **防闪烁（FOUC）**：暗色模式偏好存 localStorage 时，页面加载先按默认亮色渲染、JS 挂 `dark` 类后跳变——对策是在 `index.html` 内联一段阻塞脚本，渲染前读偏好挂好 class。
- **与运行时类名操作的配合**：JS 切换的类名（如 `document.body.classList.add("dark")`）必须是完整字符串写死在源码里（第 2 章的扫描纪律）；纯运行时计算的样式用 CSS 变量（`style.setProperty`）而不是拼工具类。

```html
<!-- index.html 的防闪烁内联脚本：先于渲染执行 -->
<script>
  const t = localStorage.theme || "system";
  if (t === "dark" || (t === "system" && matchMedia("(prefers-color-scheme: dark)").matches))
    document.documentElement.classList.add("dark");
</script>
```

> 运行时样式的分界线：**状态类切换用类名，数值型样式用 CSS 变量**——拖拽位置、进度百分比这类连续值拼不进工具类（值无限多），写 `style` 内联 CSS 变量才是正路。硬要拼类名的场景说明用错了层。

**速记**：产物不用管、**过程三件事**——v4 原生路径、防闪烁内联脚本、连续值走 CSS 变量。
