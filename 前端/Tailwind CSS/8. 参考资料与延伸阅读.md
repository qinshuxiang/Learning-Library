## 参考资料与延伸阅读

### 官方资源

#### Tailwind CSS 官方文档

**Tailwind CSS 官方文档**（tailwindcss.com/docs）：工具类的**权威字典**，也是本主题判定类名行为的最终依据。

- 「Utility-First」理念页与 Installing 页对应本主题第 1、2 章；每个工具类页面给出全部变体与示例。
- **Upgrade Guide** 是 v3→v4 迁移的必读页，配置载体与类名改名的权威清单都在这里。
- 官方博客（tailwindcss.com/blog）随版本发布讲解设计动机，v4 引擎重写的说明文章值得读。

> 工具类名不必背——记住命名规律（缩写＋刻度＋变体），具体类名查文档的速度比重背快。文档站的搜索就是为「查字典」式使用设计的。

**速记**：文档当 **字典查**，v3→v4 必读 Upgrade Guide。



### 配套工具

#### clsx、tailwind-merge 与 cva

**clsx**（github.com/lukeed/clsx）、**tailwind-merge**（github.com/dcastil/tailwind-merge）、**class-variance-authority**（github.com/joe-bell/cva）：组件变体三件套，对应本主题第 5 章。

- clsx 条件拼接类名，tailwind-merge 消解冲突工具类，cva 声明变体映射——三者组合是 shadcn 组件的写法基础。
- cva 的 README 给出与 React 的完整集成示例，配合 TypeScript 得到变体的类型推导。

> 三件套的分工要分清：**拼类名用 clsx，去冲突用 merge，管变体用 cva**。常见误用是拿 cva 做简单条件拼接——两个状态的简单切换，clsx 一行就够。

**速记**：clsx **拼**、merge **冲**、cva **变体**，简单拼接不必上 cva。



#### shadcn/ui

**shadcn/ui**（ui.shadcn.com）：基于 Tailwind 的组件方案，源码直接复制进项目，对应你既定的 UI 基建。

- 本库已有专主题（「shadcn 组件库」主题，14 篇），本主题第 3、5 章与其第 3、4、5 篇互为表里。
- shadcn 的主题体系（CSS 变量＋语义令牌）是学习「Tailwind 设计令牌实战」的最佳样本。

> 先读本主题理解 Tailwind 本体，再进 shadcn 主题看工程化形态，顺序适合已有 SCSS 基础的前端。

**速记**：Tailwind 本体看本主题，**工程化形态看 shadcn 主题**。



### 深入方向

#### Tailwind CSS 与 Atomic CSS 的设计讨论

- **John Polacek《CSS-Tricks: The Utility-First Workflow》**与 Adam Wathan（Tailwind 作者）的系列文章《CSS Utility Classes and Separation of Concerns》：原子化理念论战的两篇核心文本，对应第 1 章。
- **UnoCSS**（github.com/unocss/unocss）：原子化引擎的另一个实现，按需生成与 preset 机制更灵活，理解「原子化是一种思路、Tailwind 是一种实现」后可对照阅读。

> 理念文章读完的检验标准：能否用「样式的组织单位变了」一句话向同事讲清原子化与传统方案的区别。讲不清就再读，能用自己话讲出来再动手迁移（第 6 章）。

**速记**：理念读 Wathan 的 **Separation of Concerns** 一篇足矣，实现层可对照 UnoCSS。
