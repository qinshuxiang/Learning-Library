## 配置与主题定制

### @theme 与设计令牌

#### 刻度体系的定制入口

**`@theme`**：v4 的配置中心——在 CSS 里定义设计令牌（颜色、间距、字号、断点），每个令牌自动生成同名的工具类与 CSS 变量。

```css
@import "tailwindcss";

@theme {
  /* 生成 bg-brand-500、text-brand-500 等全套工具类 */
  --color-brand-500: oklch(0.65 0.18 255);
  --color-brand-700: oklch(0.45 0.16 255);

  /* 生成 p-card、gap-card 等间距类 */
  --spacing-card: 1.25rem;

  /* 生成 font-display 工具类 */
  --font-display: "Inter", "PingFang SC", sans-serif;

  /* 覆盖默认刻度：整个项目的间距圆角都收敛在体系内 */
  --radius-lg: 0.5rem;
}
```

- 令牌即 **设计系统数据源**：改一处 `--color-brand-500`，全站引用它的工具类同步更新，无需全局搜索替换。
- 生成的 CSS 变量（`var(--color-brand-500)`）在 JS 里也能读，主题切换（暗色模式）直接操作变量即可——shadcn 组件库主题第 3、4 篇的变量体系正是这样建立的。
- **删减默认令牌**：`--color-*: initial` 可清空默认色板，强制团队只用项目色板——约束越硬，一致性越稳。

> v3 的 `tailwind.config.js` 里 `theme.extend` 与这里的 `@theme` 是同构的：**JS 对象换成了 CSS 变量声明**。看 v3 教程时把配置结构平移过来即可，命名规律完全一致。

**速记**：`@theme` 定令牌、工具类与 CSS 变量 **双生**，改令牌即改全站。



### 暗色模式

#### class 策略与 CSS 变量

**暗色模式**：`dark:` 变体的生效策略默认跟随系统（`prefers-color-scheme`），手动切换用 class 策略。

```css
@custom-variant dark (&:where(.dark, .dark *));   /* v4 声明 class 策略 */
```

```html
<!-- class 策略：根元素挂 .dark 即全站切换 -->
<html class="dark">
  <body class="bg-white text-slate-900 dark:bg-slate-900 dark:text-slate-100">
```

- **推荐形态是「语义令牌＋双套变量值」**：组件里只用 `bg-background`、`text-foreground` 这类语义类，令牌在 `:root` 与 `.dark` 下各给一套值——组件代码完全不出现 `dark:`，切换逻辑收敛到根元素一个 class。
- 手动切换的三件事：偏好持久化（localStorage）、加载时防闪烁（读偏好后先挂 class 再渲染）、跟随系统作为默认值——完整实现见 shadcn 组件库主题第 4 篇。

> `dark:` 前缀写满模板的方案能用但**不宜推广**：每个组件都写两遍颜色，新增组件容易漏配暗色。语义令牌方案把「两遍」压缩到令牌定义处一次，组件层零感知——这也是 shadcn 全系组件的做法，与其保持一致维护成本最低。

**速记**：**语义令牌＋双套值**是正解，组件零 `dark:`；class 挂根元素即切换。
