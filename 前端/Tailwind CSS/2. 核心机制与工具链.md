## 核心机制与工具链

### 按需生成机制

#### 扫描与即时编译

**Tailwind 的核心机制**：扫描源码中的类名字符串，把「出现过的工具类」即时编译成 CSS——你只用到极小的子集，产物里也只有这个子集。

- **v4 引擎**：对源码做真正的文本级解析（不依赖配置文件声明路径），识别模板字符串拼接等动态写法的能力更强。
- **即时生成（JIT）**：开发时改类名立即出样式，无需全量编译；任意值语法（`w-[137px]`）在扫描到时按需生成。
- **前提纪律**：类名必须**以完整字符串形式出现在源码里**——`text-${size}` 这类运行时拼接扫描不到，产物里就没有对应样式（第 7 章的 safelist 是兜底而非出路）。

> 「扫描到什么生成什么」这一条决定了 Tailwind 全部的使用纪律：**类名字符串是源代码的一部分**。理解了这一点，safelist 滥用、动态拼接踩坑、CDN 版与构建版的差异，全都能自行推导。

**速记**：**扫描源码、按需生成**，类名必须是源码里的完整字符串。



### 工具链

#### v4 的 CSS 优先接入

**Tailwind v4 的接入以 CSS 为中心**：一行 `@import "tailwindcss"` 完成引入，配置写在 CSS 里（`@theme`，第 3 章），不再需要 `tailwind.config.js`。

```bash
# Vite 项目：官方插件一条命令接入（v4 推荐路径）
npm install tailwindcss @tailwindcss/vite
```

```js
// vite.config.js
import tailwindcss from "@tailwindcss/vite";
import { defineConfig } from "vite";

export default defineConfig({ plugins: [tailwindcss()] });
```

```css
/* src/index.css —— 引入即完成，无 @tailwind 三行指令（v3 的写法已废） */
@import "tailwindcss";
```

- **v3 与 v4 的关键差异**：v3 用 `tailwind.config.js`（JS 配置）＋`@tailwind base/components/utilities` 三指令；v4 全面转向 CSS 配置（`@theme`、`@utility`），构建速度大幅提升。
- **PostCSS 路径**：非 Vite 项目（webpack 等）用 `@tailwindcss/postcss` 插件接入，配置方式相同。
- **升级**：官方 upgrade 工具（`npx @tailwindcss/upgrade`）自动迁移 v3 配置，迁移前先通读 v4 升级指南，改动集中在配置载体与少量类名改名。

> 判断手头教程是 v3 还是 v4 的最快方法：**看到 `tailwind.config.js` 或 `@tailwind` 指令就是 v3 资料**。v4 已是当前默认，但社区存量教程仍以 v3 居多，概念大部分互通，配置载体不同而已。

**速记**：v4＝**一行 import＋CSS 内配置**，Vite 用官方插件，v3 资料认准 config 文件区分版本。

**警告内容**：浏览器 CDN 版（`cdn.tailwindcss.com`）仅用于原型演示——它在运行时扫描生成样式，体积大、性能差且无法定制。任何要提交的项目一律走构建链接入，CDN 链接忘删是评审时常见的「原型残留」。
