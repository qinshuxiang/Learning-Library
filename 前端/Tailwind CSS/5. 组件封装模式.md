## 组件封装模式

### 重复的归宿

#### 从复制类名串到组件提取

**原子化的配套纪律**：同一段类名串出现第二次，就该提取成组件——重复在组件层消灭，而不是在类名层消灭。

```jsx
// 反面：类名串复制粘贴，改一处漏一处
<button className="inline-flex items-center rounded-md bg-brand-500 px-4 py-2 text-sm text-white">保存</button>
<button className="inline-flex items-center rounded-md bg-brand-500 px-4 py-2 text-sm text-white">提交</button>

// 正面：变体收敛进组件 props
function Button({ variant = "primary", ...props }) {
  return <button className={buttonStyles({ variant })} {...props} />;
}
```

- 这一纪律把「样式复用」的战场从 CSS 文件搬到**组件层**：React/Vue 组件即样式单元，模板里的类名串是组件的实现细节，外部只见 props。
- 与传统写法相比，原子化项目的「CSS 架构」实际上就是**组件目录结构**——没有单独的样式架构层需要设计。

> 「原子化导致类名重复」的批评只在**不写组件**的项目里成立。组件化开发里，类名串的重复率天然被组件复用压到极低；见到大量复制类名串的项目，先问的是组件抽象能力，而不是工具选型。

**速记**：类名串出现两次即 **提取组件**，组件层是原子化项目的样式架构层。



### 变体管理

#### cva 与 shadcn 形态

**cva（class-variance-authority）**：把「变体 → 类名集合」的映射声明式管理，是 shadcn 组件的标准写法。

```js
const buttonStyles = cva(
  // 基础类名串
  "inline-flex items-center rounded-md text-sm font-medium",
  {
    variants: {
      variant: {
        primary: "bg-brand-500 text-white hover:bg-brand-600",
        outline: "border border-input bg-transparent hover:bg-accent",
        ghost: "hover:bg-accent",
      },
      size: {
        sm: "h-8 px-3",
        md: "h-10 px-4",
      },
    },
    defaultVariants: { variant: "primary", size: "md" },
  }
);

// 使用：类型安全地组合变体
<button className={buttonStyles({ variant: "outline", size: "sm" })} />
```

- cva 解决的问题：条件拼接类名（`className={primary ? "..." : "..."}`）在变体增多后不可维护；声明式映射＋TS 类型推导让变体组合可枚举、可校验。
- 配合 `tailwind-merge`（智能合并冲突类名：`clsx("px-4", props.className 里的 px-2)`）处理调用方覆盖，是组件允许外部定制类名的标准姿势。
- shadcn 组件库的每个组件都是「cva 变体定义＋组件骨架」的形态——完整实例直接看库内源码（shadcn 组件库主题第 5 篇的按钮变体即此模式）。

> cva＋tailwind-merge＋clsx 三件套是**原子化组件的变体基础设施**，值得沉淀为项目模板：新组件从模板复制开始，变体语义（primary/outline/ghost、尺寸）全项目保持同一套词汇。

**速记**：**cva 管变体映射、merge 管覆盖冲突**，三件套是 shadcn 形态的地基。
