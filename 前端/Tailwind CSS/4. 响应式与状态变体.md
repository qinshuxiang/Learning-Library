## 响应式与状态变体

### 响应式

#### 移动优先与断点变体

**响应式工具类**：断点前缀（`sm:`、`md:`、`lg:`）修饰任意工具类，含义是「达到该断点**及以上**生效」——体系是移动优先。

```html
<!-- 移动端单列，md 及以上双列，lg 及以上三列 -->
<div class="grid grid-cols-1 md:grid-cols-2 lg:grid-cols-3 gap-4">
```

- **移动优先的书写顺序**：无前缀写移动端默认值，断点前缀逐级覆盖——与 CSS 的 `min-width` 媒体查询语义一致，反着写（先桌面再缩小）会和体系对抗。
- 自定义断点在 `@theme` 里覆盖 `--breakpoint-*`；需要「某区间内生效」用 `md:max-lg:` 双前缀。
- 容器查询（`@container` 变体）按**组件自身宽度**而非视口响应，卡片类组件在栅格里自适应时比视口断点更准确，v4 已内置。

> 断点变体写多了模板会很吵，**响应式布局应尽量收敛在少数布局组件里**（栅格容器、页面骨架），业务组件少写断点、多做自适应（flex 弹性、`max-w` 约束）。断点满天飞的模板通常是布局没分层。

**速记**：**移动优先、前缀即以上生效**，断点收敛在布局层，组件内少写。



### 状态变体

#### 交互状态与关系变体

**状态变体**：`hover:`、`focus:`、`active:`、`disabled:` 直接在类名上表达伪类与状态，替代传统 CSS 的状态选择器。

```html
<button class="bg-brand-500 text-white hover:bg-brand-600 focus-visible:ring-2 disabled:opacity-50 disabled:cursor-not-allowed">
  提交
</button>
```

- **关系变体处理跨元素状态**：`group:`（父元素 hover/焦点时子元素响应）、`peer:`（兄弟元素状态影响后续元素）——下拉菜单「按钮 hover 展开菜单」用 `group-hover:` 一行解决，传统 CSS 要写后代选择器。
- `focus-visible:` 与 `focus:` 的区别：前者只在**键盘聚焦**时生效，鼠标点击不触发，交互态样式应优先用它（可访问性细节，见 shadcn 组件库主题第 14 篇）。
- 变体可叠加：`dark:hover:bg-slate-700`、`md:hover:...`，顺序即语义（在暗色下 hover、在 md 屏 hover）。

> 状态变体是原子化相对传统 CSS **表达力上升最明显**的地方：变体前缀让「元素在什么状态下长什么样」与元素本体写在同一处，不再需要在 CSS 文件里维护 `:hover`、`.parent:hover .child` 的映射关系。模板变长的代价换来的是状态的局部可读性。

**速记**：状态写在类名里，**group/peer 管跨元素**，键盘态用 `focus-visible:`。



### 任意值与兜底

#### 何时允许跳出刻度

**任意值语法**（`[...]`）：在刻度之外写出精确值，是体系外的逃生门而非日常通道。

```html
<div class="w-[137px] top-[calc(100vh-4rem)] bg-[#0f172a] before:content-['→']">
```

- **使用纪律**：设计稿标注的非刻度值（137px）、一次性特殊定位、与第三方设计稿对齐时用；同一个任意值出现两次以上，就该进 `@theme` 变成正式令牌。
- CSS 能写的任意值语法基本都能表达（伪元素 content、calc、CSS 函数），但它不享受刻度体系的一致性约束——**每多一个任意值，设计系统的约束就漏一分**。

> 任意值出现频率是项目健康度指标：偶尔出现说明体系覆盖良好，大面积出现说明令牌设计（第 3 章）缺刻度——该补的是 `@theme`，不是继续堆任意值。

**速记**：任意值是 **逃生门不是通道**，出现两次就该转正为令牌。
