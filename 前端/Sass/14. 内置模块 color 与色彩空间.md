## 内置模块 color 与色彩空间

### 色彩空间与颜色值

Sass 的颜色值与 CSS 一样，各自归属某个色彩空间。支持的空间共十六个：

```scss
// SCSS 中可直接书写的颜色字面量
@debug #f2ece4;                              // #f2ece4
@debug #b37399aa;                            // rgba(179, 115, 153, 0.6666666666666666)
@debug midnightblue;                         // midnightblue
@debug rgb(204 102 153);                     // rgb(204, 102, 153)
@debug lab(32.4% 38.4 -47.7 / 0.7);          // lab(32.4% 38.4 -47.7 / 0.7)
@debug color(display-p3 0.597 0.732 0.576);  // color(display-p3 0.597 0.732 0.576)
```

输出有两点需要留意：颜色值按书写时的空间原样打印，不会被压缩成简写（rgb(204 102 153) 不会变成 #c69，midnightblue 也不还原为 #191970）；带 alpha 的十六进制会被转换为其所在空间的小数形式。这与早期版本的表现不同，逐字节比对产物时要按当前版本为准。

空间清单按用途分为三组：

- 传统空间：rgb、hsl、hwb。它们是 CSS 早期仅有的三组颜色函数，也是 Sass 中的「旧式空间」。
- 标准与广色域 RGB 空间：srgb、srgb-linear、display-p3、display-p3-linear、a98-rgb、prophoto-rgb、rec2020、xyz、xyz-d50、xyz-d65。
- 感知均匀空间：lab、lch、oklab、oklch。

```scss
@use "sass:color";

@debug color.space(#ff6600);          // rgb
@debug color.is-legacy(#ff6600);      // true
@debug color.to-space(#ff6600, oklch);
// oklch(69.57934102753724% 0.2042590816060513 43.49103102933583deg)
@debug color.same(#ff6600, #f60);     // true
```

颜色函数有一个统一约定需要先记住：函数在原颜色的色彩空间内工作，返回的颜色也保持在原空间，除非显式调用 color.to-space($color, $space) 转换。因此对十六进制颜色做 oklch 空间的调整，结果仍是 rgb 空间的值。

> [!NOTE]
> **提醒内容**：色彩空间的通道范围各不相同。lab 的 a、b 通道取值范围是 -125 到 125，oklab 的 a、b 是 -0.4 到 0.4，oklch 的 chroma 是 0 到 0.4，lch 的 chroma 是 0 到 150。超出范围的值 Sass 能表示，但会落在该空间的标准色域之外。



### 调整与缩放

两个函数的区别在于计算基准：adjust 在现有值上加减，scale 按剩余空间按比例缩放。

```scss
@use "sass:color";

$brand: #ff6600;

@debug color.adjust($brand, $lightness: -10%);  // rgb(80%, 32%, 0%)
@debug color.scale($brand, $lightness: -20%);   // rgb(80%, 32%, 0%)
@debug color.adjust($brand, $red: -20);         // #eb6600
@debug color.adjust($brand, $hue: 40deg, $space: hsl);  // #eeff00
```

两者的实际差异在接近边界时才明显：adjust 直接做加减，值可能撞到通道边界被截断；scale 按「到上限或下限还有多少余量」的比例缩放，因此缩放 100% 会得到通道的极值，永远不会越界。做色阶生成时 scale 的间距更均匀。



### 替换通道与读取通道

```scss
@use "sass:color";

$brand: #ff6600;

@debug color.change($brand, $alpha: 0.5);                   // rgba(255, 102, 0, 0.5)
@debug color.change($brand, $lightness: 30%, $space: hsl);  // rgb(60%, 24%, 0%)
@debug color.channel($brand, "red", $space: rgb);           // 255
@debug color.channel($brand, "hue", $space: hsl);           // 24deg
@debug color.channel(oklch(60% 0.15 250deg), "chroma");     // 0.15
```

color.change($color, $args...) 把指定通道整体替换为新值，未指定的通道保持原样。color.channel($color, $channel, $space: null) 读取单个通道。

通道名必须写带引号的字符串，就像 "red"、"hue"；色彩空间名写成不带引号的标识符，就像 rgb、hsl、oklch。这个区分不是风格问题，而是解析需要：「red」不加引号会被当作颜色关键字，与通道名的含义冲突。



### 混合与特殊变换

```scss
@use "sass:color";

$brand: #ff6600;

@debug color.mix($brand, #0000ff, 50%);       // rgb(50%, 20%, 50%)
@debug color.complement($brand);              // #0099ff
@debug color.invert($brand);                  // #0099ff
@debug color.grayscale($brand);               // rgb(50%, 50%, 50%)
```

color.mix($color1, $color2, $weight: 50%, $method: null) 按权重混合两色，$weight 是第一个颜色的占比。$method 指定混合所在的色彩空间，做感知均匀的渐变过渡时传入 oklch 或 lab 能避免中间色发灰：

```scss
@use "sass:color";

.g {
  color: color.mix(#036, #d2e1dd, $method: oklch);
}
```

complement 按色相旋转 180 度求补色，invert 按通道求反色，两者在部分颜色上恰好一致（本例的 #ff6600 即是），但原理不同：改变色相会调整到另一个颜色，而反相保持饱和结构。grayscale 把颜色的饱和度置零。



### 缺失通道与色域判断

```scss
@use "sass:color";

@debug color.is-powerless(hsl(0deg 0% 50%), "hue", $space: hsl);  // true
@debug color.is-missing(hsl(none 0% 50%), "hue");                 // true
@debug color.is-in-gamut(oklch(70% 0.3 30deg));                   // true
@debug color.is-in-gamut(color(display-p3 1 0 0), $space: srgb);  // false
```

三个判断函数的语义需要分清：

- 缺失通道：写成 none 的通道，表示该通道值未知或不参与渲染，如 hsl(none 0% 50%) 中的色相。color.channel 对缺失通道返回 0，需要区分时应改用 color.is-missing。
- 无力通道：值不影响渲染结果的通道，如饱和度为零时的色相。转换到新空间时，CSS 规范要求把无力通道置为 none，Sass 在非旧式空间之间的转换中遵循此规则。
- 色域判断：color.is-in-gamut($color, $space: null) 判断颜色是否在指定空间的标准色域内。省略 $space 时用颜色自身的空间，因此 oklch 的 chroma 0.3 在其自身空间内是合法的；换算到 srgb 空间就可能越界。

需要把越界颜色压回目标色域时用 color.to-gamut($color, $method: local-minde)，它返回该色域内的近似颜色，是使用广色域配色再输出到 sRGB 场景的收尾步骤。



### 旧颜色函数与迁移方向

一批旧的全局颜色函数已进入弃用期，实测编译时的建议信息如下：

```shell
DEPRECATION WARNING [color-functions]: darken() is deprecated. Suggestions:

color.scale($color, $lightness: -20%)
color.adjust($color, $lightness: -10%)
```

按功能归类的对应关系：

- darken 与 lighten：改用 color.adjust 的 lightness 通道，或 color.scale 的 lightness 参数。
- saturate 与 desaturate：改用 color.adjust 的 saturation 通道。
- opacify 与 transparentize：改用 color.adjust 的 alpha 通道。
- fade-in 与 fade-out：同上，改用 alpha 通道加减。
- adjust-hue：改用 color.adjust 的 hue 通道。
- mix 与 invert 等已有同名模块函数：改用 color.mix 与 color.invert。
- 全局的 rgb、hsl、hwb 构造函数：属于 CSS 同名的特殊函数，仍有全局形式，但 hsl 与 rgb 的旧式逗号语法中带变量时会遇到斜杠解析问题，推荐改用逗号加 alpha 参数的形式。

> [!IMPORTANT]
> **重要内容**：新旧颜色函数的差异不只是改名。color.adjust 与 color.scale 默认在颜色自身的色彩空间工作，而 darken 与 lighten 固定按 HSL 处理。若原代码依赖 HSL 语义，迁移时必须显式传 $space: hsl，否则色值会变化且不留痕迹。
