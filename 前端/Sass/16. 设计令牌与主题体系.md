## 设计令牌与主题体系

### 三层令牌结构

设计令牌是把设计决策抽成命名变量的做法。工程上按抽象层级分为三层，每层职责单一：

- 原始层：不可再分的值与调色板，如 blue-500、space-4。它们描述「有什么」。
- 语义层：把原始值映射到用途，如 color-primary、color-danger、space-gutter。它们描述「用在哪」。
- 组件层：组件内部的局部变量，如 button-padding-x。它们描述「具体组件怎么用」。

```scss
// 原始层：调色板与刻度
$blue-500: #3366ff;
$blue-600: #2952cc;
$neutral-0: #ffffff;
$neutral-900: #1a1a1a;

$space-2: 8px;
$space-3: 12px;
$space-4: 16px;

// 语义层：把原始值映射到用途
$color-primary: $blue-500;
$color-primary-hover: $blue-600;
$color-surface: $neutral-0;
$color-text: $neutral-900;

$size-gutter: $space-4;
$size-control-padding: $space-3 $space-4;
```

分层的价值在换肤与改版时体现：改主色只需动语义层的 $color-primary 一行，所有引用它的组件同步变化；而原始层的调色板保持稳定，色阶生成脚本不必重算。

> [!IMPORTANT]
> **重要内容**：组件层不应直接引用原始层的值。写 color: $blue-500 会让该组件脱离主题体系——换主题时它不变。组件只允许引用语义层，这是令牌体系能否成立的分界线。



### 令牌表与循环派生

令牌数量增长后，逐个手写变量会失去一致性。改用映射集中定义，再用循环统一派生。

```scss
@use "sass:map";

$palette: (
  "blue-500": #3366ff,
  "blue-600": #2952cc,
  "green-500": #12a05c,
  "red-500": #d93a3a,
  "neutral-0": #ffffff,
  "neutral-900": #1a1a1a
);

$semantic: (
  "primary": "blue-500",
  "success": "green-500",
  "danger": "red-500",
  "surface": "neutral-0",
  "text": "neutral-900"
);

@function token($name) {
  $ref: map.get($semantic, $name);

  @if $ref == null {
    @error "未知语义令牌 #{$name}，可用令牌：#{map.keys($semantic)}";
  }

  @return map.get($palette, $ref);
}

@debug token("primary");   // #3366ff
@debug token("danger");    // #d93a3a
```

上例的关键点是令牌的取值通过引用名间接完成：语义层存的是原始层的键名而不是值本身，这样原始层改值、语义层改指向这两种操作彻底解耦。



### 派生 CSS 自定义属性

Sass 变量在编译期求值，产物里不留痕迹；要把令牌交给运行期使用，需派生一份自定义属性。

```scss
@use "sass:map";

$semantic: (
  "primary": #3366ff,
  "danger": #d93a3a,
  "surface": #ffffff,
  "text": #1a1a1a
);

:root {
  @each $name, $value in $semantic {
    --color-#{$name}: #{$value};
  }
}
```

```css
:root {
  --color-primary: #3366ff;
  --color-danger: #d93a3a;
  --color-surface: #ffffff;
  --color-text: #1a1a1a;
}
```

两份令牌的分工是明确的：Sass 变量在编译期用于运算与生成，自定义属性在运行期用于切换与覆盖。两侧同源，都由 $semantic 派生，不会出现两套令牌不同步的问题。



### 主题切换的三种方式

按生效时机区分，主题切换有三种实现路径：

- 编译期多产物：为每个主题各编译一份 CSS，运行期加载不同文件。产物完全静态、无额外变量开销，缺点是主题数乘以产物体积，且切换需要重新加载。
- 运行期类名覆盖：主题定义为一组自定义属性，挂在不同选择器上，切换时改元素上的类名或属性。切换零成本、无闪烁，是当前主流做法。
- 媒体查询跟随系统：用 prefers-color-scheme 自动选择主题，可与前两者叠加。

```scss
$themes: (
  "light": (
    "surface": #ffffff,
    "text": #1a1a1a,
    "primary": #3366ff
  ),
  "dark": (
    "surface": #1a1a1a,
    "text": #f5f5f5,
    "primary": #5c8aff
  )
);

@mixin emit-theme($tokens) {
  @each $name, $value in $tokens {
    --color-#{$name}: #{$value};
  }
}

@each $theme, $tokens in $themes {
  [data-theme="#{$theme}"] {
    @include emit-theme($tokens);
  }
}
```

```css
[data-theme=light] {
  --color-surface: #ffffff;
  --color-text: #1a1a1a;
  --color-primary: #3366ff;
}

[data-theme=dark] {
  --color-surface: #1a1a1a;
  --color-text: #f5f5f5;
  --color-primary: #5c8aff;
}
```

组件侧只引用自定义属性，不感知当前主题：

```scss
.card {
  background: var(--color-surface);
  color: var(--color-text);
  border: 1px solid color-mix(in oklab, var(--color-text) 12%, transparent);
}
```

> 自定义属性的一个限制需要提前设计规避：它们的值不能参与 Sass 的编译期运算。需要按主题计算派生色（如悬停态比基色深一档）时，应把派生色也在主题映射中显式列出，或者用 CSS 的 color-mix() 在运行期完成混合。



### 色阶生成

把基色扩展成完整色阶是令牌体系中最典型的编译期计算，适合用感知均匀空间做，避免明度不均。

```scss
@use "sass:color";

$steps: (100: 90%, 300: 70%, 500: 50%, 700: 30%, 900: 15%);
$brand: #3366ff;

@function scaleOf($base, $lightness) {
  @return color.change($base, $lightness: $lightness, $space: hsl);
}

@each $step, $lightness in $steps {
  .bg-brand-#{$step} {
    background: scaleOf($brand, $lightness);
  }
}
```

> [!TIP]
> **建议内容**：色阶生成建议固定在 oklch 或 lab 空间进行，用固定明度台阶、微调 chroma 的方式产出。直接对 HSL 的 lightness 分档会在黄绿与蓝紫区段产生明显的感知明度偏差，同一色阶中各档的「深浅感」看起来不一致。
