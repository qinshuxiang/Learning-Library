## 继承 @extend 与占位符选择器

### 基本用法

@extend 让一个选择器继承另一个选择器已经拥有的全部样式，写法是 @extend 加目标选择器。

```scss
.error {
  border: 1px solid #f00;
  background-color: #fdd;

  &--serious {
    @extend .error;
    border-width: 3px;
  }
}
```

```css
.error, .error--serious {
  border: 1px solid #f00;
  background-color: #fdd;
}
.error--serious {
  border-width: 3px;
}
```

产物形态与混合宏完全不同：混合宏把声明复制到调用处，@extend 把调用方选择器追回到被继承规则的选择器列表上。因此被继承的规则只保留一份声明，调用方出现在选择器组里。

这一特性使 @extend 特别适合「修饰符类」：BEM 里 error--serious 这类类名需要具备 error 的全部样式，用 @extend 后 HTML 只需写一个类名，不必再叠加第二个类。



### 占位符选择器

以百分号开头的选择器是占位符，它在产物中不出现，只能被 @extend 使用，用于承接纯粹的抽象样式。

```scss
%button-base {
  display: inline-block;
  padding: 6px 12px;
  border-radius: 4px;
}

.button { @extend %button-base; background: #f60; }
.button--ghost { @extend %button-base; background: transparent; }
```

```css
.button--ghost, .button {
  display: inline-block;
  padding: 6px 12px;
  border-radius: 4px;
}

.button {
  background: #f60;
}

.button--ghost {
  background: transparent;
}
```

若把 %button-base 换成 .button-base，即使无人继承它，该类也会进入产物，成为永远匹配不到元素的死代码。占位符正是为避免这份冗余而存在，写可复用的样式基座时应优先使用它。



### 编译展开原理

@extend 的展开在样式表其余部分编译完成之后进行，编译器会把被继承选择器在全文出现的位置全部追加上继承者。

```scss
.error {
  border: 1px solid #f00;
}

.error:hover {
  background: #fee;
}

.error--serious {
  @extend .error;
  border-width: 3px;
}
```

```css
.error, .error--serious {
  border: 1px solid #f00;
}

.error:hover, .error--serious:hover {
  background: #fee;
}

.error--serious {
  border-width: 3px;
}
```

选择器展开时执行的是选择器级的合并而非文本替换，编译器会做若干归一化：不生成 #main#footer 这类不可能匹配的元素组合；复杂选择器按交错展开以保证任意嵌套顺序下都生效；合并后削减冗余选择器；判断两个选择器的包含关系并合并同类项。这套处理即选择器文档中所说的智能统一。

优先级需特别留意：继承来的声明在层叠中的位置取决于被继承规则出现的位置，而不是 @extend 所在的位置。心智模型可以直接沿用 CSS 的等价写法——把被继承的类名加到 HTML 元素上，优先级就与那样书写的结果一致。



### 适用范围与限制

@extend 有四类明确限制，都会在编译期报错，需要在设计阶段就避开：

- 只能继承简单选择器。@extend .message.info 会报 compound selectors may no longer be extended，应改写为 @extend .message, .info。
- 不能跨媒体查询继承。在被 @media 包裹的规则内继承外部选择器会报 You may not @extend selectors across media queries，因为继承者只在该媒体条件下有效，无法安全地合并到外部规则。
- 目标必须存在。目标选择器未被使用时默认报错，报错信息会给出加 !optional 的提示；确认可缺席时用 @extend .nothing !optional 让它静默跳过。
- 作用范围限于上游模块。某文件中的 @extend 只影响它通过 @use 或 @forward 加载的那些模块中的规则，不会反向影响加载它的文件，这让继承的影响面可预测。

```shell
Error: compound selectors may no longer be extended.
Consider `@extend .message, .info` instead.

Error: You may not @extend selectors across media queries.

Error: The target selector was not found.
Use "@extend .nothing !optional" to avoid this error.
```



### 与混合宏的取舍

两者的选择依据是被复用的东西是「样式」还是「关系」：

- 复用的是关系：多个选择器共享同一组样式、且希望产物中声明不重复，用 @extend 加占位符。
- 复用的是样式：需要在任意位置插入一组声明、可能带参数或内容块，用 @mixin。
- 产物体积敏感：@extend 会拉长选择器组，选择器组过长时收益转为成本，此时用混合宏复制声明反而更小。

```scss
// 用占位符收敛公共样式，产物中声明只出现一次
%reset-list {
  margin: 0;
  padding: 0;
  list-style: none;
}

.menu { @extend %reset-list; }
.tags { @extend %reset-list; }

// 需要参数或内容块时改用混合宏
@mixin reset-list($gap: 0) {
  margin: 0;
  padding: 0;
  list-style: none;
  gap: $gap;
}

.actions { @include reset-list(8px); }
```

> [!IMPORTANT]
> **重要内容**：@extend 的常见误用是拿它当「组件复用」手段。当被继承的规则来自第三方库或跨越多层模块时，库的内部样式变更会顺着继承链影响调用方，且影响面在调用方文件里完全不可见。跨模块复用一律改用混合宏，@extend 只用于同一文件内、自己完全掌控的选择器。
