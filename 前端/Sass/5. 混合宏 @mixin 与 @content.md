## 混合宏 @mixin 与 @content

### 定义与调用

混合宏是一组可复用的声明块，用 @mixin 定义、@include 调用，编译时把声明原地展开。

```scss
@mixin flex-center {
  display: flex;
  align-items: center;
  justify-content: center;
}

.avatar {
  @include flex-center;
  border-radius: 50%;
}
```

```css
.avatar {
  display: flex;
  align-items: center;
  justify-content: center;
  border-radius: 50%;
}
```

与 @extend 的根本差别在产物形态：混合宏复制声明到调用处，@extend 复制选择器到被继承规则处。混合宏可以接受参数与内容块，因此承担了大部分抽象职责。



### 参数与默认值

参数在 @mixin 名后的括号内声明，带默认值的参数可以省略不传。

```scss
@mixin button($bg, $fg: #fff, $radius: 4px) {
  background: $bg;
  color: $fg;
  border-radius: $radius;
}

.a { @include button(#f60); }
.b { @include button($fg: #000, $bg: #eee); }
```

```css
.a {
  background: #f60;
  color: #fff;
  border-radius: 4px;
}

.b {
  background: #eee;
  color: #000;
  border-radius: 4px;
}
```

关键字参数可以乱序传入，如上例的 $fg 写在 $bg 之前。参数多且含义相近时，调用侧一律用关键字参数，避免位置错配。

参数默认为 null 时，该声明在输出中被整条剔除，规则若无其他声明则整个规则不输出：

```scss
@mixin optional($shadow: null) {
  box-shadow: $shadow;
}

.c { @include optional; }
.d { @include optional(0 1px 2px #0003); }
```

```css
.d {
  box-shadow: 0 1px 2px rgba(0, 0, 0, 0.2);
}
```

含 null 的值在拼接声明时会被跳过，这是「可选参数」最省事的实现方式，无需再写条件判断。



### 可变参数与动态声明

参数末尾加三个点表示可变参数，调用时传入的多个值在参数内部组成 arglist 类型。

```scss
@use "sass:meta";

@mixin props($map...) {
  @each $name, $value in meta.keywords($map) {
    #{$name}: $value;
  }
}

.e { @include props($color: red, $border: 1px solid); }
```

```css
.e {
  color: red;
  border: 1px solid;
}
```

上例中的三步值得记住：可变参数在内部的实际类型是 arglist；用 meta.keywords($args) 取出关键字参数部分，返回一个从参数名到值的映射；用插值语法 #{$name} 把变量当作属性名输出。这三点合起来实现了「按调用方传入的键值对动态产出声明」。

> meta.keywords($args) 只返回关键字形式传入的参数，位置形式传入的部分需用 meta.type-of 与列表函数处理。两种形式混用时，位置参数排在 arglist 前半部。



### @content 与内容块

@content 是调用方传给混合宏的声明块占位符，混合宏在展开时把它插到指定位置。

```scss
@mixin media($min) {
  @media (min-width: $min) {
    @content;
  }
}

.f {
  @include media(768px) {
    color: red;
  }
}
```

```css
@media (min-width: 768px) {
  .f {
    color: red;
  }
}
```

常见用途是把「外层包裹」类逻辑收敛一次：媒体查询、层叠层、伪元素容器、选择器前缀。

内容块可以带参数，混合宏用 @content($args) 传入实参，调用方用 using ($args) 接收：

```scss
@use "sass:math";

@mixin grid($cols) {
  @content($cols * 100%);
}

.g {
  @include grid(3) using ($w) {
    width: math.div($w, 3);
  }
}
```

```css
.g {
  width: 100%;
}
```

用 meta.content-exists() 可以在混合宏内部判断本次调用是否传入了内容块，从而让内容块变成可选：

```scss
@use "sass:meta";

@mixin optional-content {
  @if meta.content-exists() {
    @content;
  } @else {
    color: #000;
  }
}

.q { @include optional-content; }
```

```css
.q {
  color: #000;
}
```

若把 meta.content-exists() 写在混合宏之外调用，编译会直接报错：content-exists() may only be called within a mixin。这一限制源于内容块是调用关系的产物，在顶层不存在。



### 与函数的取舍

混合宏产出声明，函数产出一个值，两者的选择标准是产物形态而非复杂度：

- 需要输出若干条声明：用混合宏，靠 @content 承接变化部分。
- 需要一个值参与后续运算或判断：用函数，靠参数与 @return 传递。
- 既算值又输出声明：拆成函数加混合宏两个成员，先算后输出。

> 混合宏过度使用时会出现「看不见的层」：一处 @include 实际展开几十条声明，覆盖来源难以追溯。经验规则是单个混合宏的展开结果应在十行声明以内；超出后应拆分为更小的、职责单一的混合宏。
