## Sass 简介与语法形态

### Sass 是什么

Sass 是一门编译型样式语言，源码经编译器处理后输出标准 CSS，供浏览器直接使用。

Sass 在原生 CSS 之上补齐了原生长期缺失的编程能力：变量、嵌套、混合宏、函数、控制指令、模块化。它不引入新的运行时，编译产物就是普通 CSS 文件，浏览器与既有工具链无需任何改动。

Sass 源码文件有三种扩展名，含义各不相同：

- 扩展名 scss：使用 SCSS 语法，花括号分层、分号结尾，是 CSS 的超集。
- 扩展名 sass：使用缩进语法，靠换行与缩进分层，类似 Python。
- 扩展名 css：是普通 CSS，Sass 也允许用 @use 加载，但其中的 Sass 专有特性会直接报错。



### 两种语法形态

SCSS 与缩进语法是同一种语言的两套书写形式，能力完全对等，可以互相转换。区别只在分层方式：SCSS 用花括号与分号，缩进语法只用缩进与换行。

同一段样式在两种语法下的写法对照如下：

```scss
// SCSS 语法（.scss）
@use "sass:color";

$brand: #ff6600;

.card {
  color: $brand;
  padding: 8px;

  &:hover {
    color: color.scale($brand, $lightness: -20%);
  }
}
```

```sass
// 缩进语法（.sass）
@use "sass:color"

$brand: #ff6600

.card
  color: $brand
  padding: 8px

  &:hover
    color: color.scale($brand, $lightness: -20%)
```

缩进语法有两条易混淆的规则：一是不能用分号与花括号，多写了会报语法错误；二是 @use、@forward 的 URL 仍然必须加引号，缩进语法并不豁免引号。

```sass
// 缩进语法中 URL 依旧要引号
@use "sass:math"
```

工程实践上，SCSS 语法占绝对多数：它与 CSS 完全兼容，可以先把已有的 CSS 文件改名后增量改造，编辑器高亮、格式化、Lint 工具的支持也更完整。缩进语法更适合偏好简洁书写的个人项目。



### 官方实现与维护状态

Sass 官方仅维护一个实现，其余实现均已停止维护，选型时必须区分。

- Dart Sass：官方唯一在维护的实现，用 Dart 编写并编译为 JavaScript 分发，通过 npm 包 sass 使用。模块系统、色彩空间等新特性只在此实现上提供。
- LibSass：C++ 实现，其 Node.js 绑定即 node-sass。已于 2020 年 10 月停止维护，功能停留在旧语言层级，不支持 @use、@forward 与内置模块。
- Ruby Sass：最初的实现，已于 2019 年 3 月终止支持。

> [!WARNING]
> **警告内容**：新项目一律使用 Dart Sass，不要使用 node-sass 或 LibSass。旧实现不支持 @use 与 @forward，写出的模块化代码在上面会直接编译失败；同时它不会输出任何弃用警告，这些问题会一直潜伏到构建链升级时才集中爆发。

本文所有示例与输出均在 Dart Sass 1.104.1 上实测。绝大多数 API 自 1.23.0（模块系统）起可用，色彩空间相关函数需 1.78.0 以上，函数与常量页面会逐条标注版本基线。



### 编译方式

最直接的用法是命令行编译，输入一个文件并输出另一个文件：

```shell
sass input.scss output.css
```

命令行支持的常用选项如下：

- 输出样式：--style=compressed 输出压缩后的单行 CSS，默认为 expanded。
- 监听编译：--watch 常驻进程，源文件变化后自动重新编译，适合本地开发。
- 加载路径：--load-path=src/styles 追加模块查找目录，可重复传入。
- 源映射：--source-map 默认开启，输出 CSS 时同步生成同名的 map 文件。
- 编码声明：--charset 默认开启，产物含非 ASCII 字符时自动插入字符集声明。

```shell
sass --watch --style=compressed styles/main.scss dist/main.css
```

在构建工具中，Sass 以 loader 或插件的形式接入：webpack 用 sass-loader，Vite 直接安装 sass 依赖即可解析，Gulp 用 gulp-sass 配合 dart-sass。这些接入方式的配置细节属于构建工具范畴，接入点选择可参照前端构建工具相关篇章。



### 与原生 CSS 的关系

原生 CSS 近年补齐了自定义属性、原生嵌套、@layer 层叠层与 color-mix 等能力，与 Sass 的功能区间出现重叠，是否引入编译层需要按项目判断。

判断的分界线在于是否需要「编译期计算」：

- 只需变量与浅层嵌套时，原生 CSS 的自定义属性与原生嵌套已能覆盖，少一层编译更省事。
- 需要按列表循环生成类名、按条件分支产出声明、做颜色运算或单位换算时，这些工作必须发生在编译期，原生 CSS 无法替代。

```scss
@use "sass:map";
@use "sass:math";

$spacers: (1: 4px, 2: 8px, 3: 16px);

@each $level, $size in $spacers {
  .mt-#{$level} { margin-top: $size; }
  .mt-#{$level}-double { margin-top: $size * 2; }
}
```

> 上面的间距类由列表循环在编译期展开成六个具体类，写作时只维护一份数据源。这类「一份数据派生多条规则」的场景是 Sass 仍然不可替代的部分，而单纯的颜色变量与简单嵌套已可交给原生 CSS。二者并不互斥，同一项目里原生自定义属性常与 Sass 变量共存。
