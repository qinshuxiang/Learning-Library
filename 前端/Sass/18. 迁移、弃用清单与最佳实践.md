## 迁移、弃用清单与最佳实践

### 弃用机制的运作方式

Sass 的破坏性变更分两步走：先在某个小版本引入弃用警告，间隔至少三个月后在新的大版本中移除。因此旧写法不会立刻失效，但会在编译输出中持续告警。

命令行的三个开关控制这一过程：

```shell
# 把弃用视为错误，用于 CI 中阻止新增遗留写法
sass --fatal-deprecation=import,slash-div styles/main.scss dist/main.css

# 忽略指定弃用项，用于迁移过渡期
sass --silence-deprecation=color-functions styles/main.scss dist/main.css

# 提前启用尚未默认开启的变更，用于预演升级影响
sass --future-deprecation=import styles/main.scss dist/main.css
```



### 结构类弃用

@import 自 Dart Sass 1.80.0 起弃用，计划在 3.0.0 中移除。

```shell
DEPRECATION WARNING [import]: Sass @import rules are deprecated
and will be removed in Dart Sass 3.0.0.
More info and automated migrator: https://sass-lang.com/d/import
```

替代方案是 @use 与 @forward。两者的语义差异在迁移时必须逐处确认：@use 不把成员注入全局作用域，因此裸变量引用需补命名空间前缀。迁移步骤与常见错误见模块系统篇。



### 运算类弃用

斜杠除法自 1.33.0 起弃用，计划在 2.0.0 中移除。

```shell
DEPRECATION WARNING [slash-div]: Using / for division outside of calc()
is deprecated and will be removed in Dart Sass 2.0.0.

Recommendation: math.div(100px, 3) or calc(100px / 3)
```

需要区分两种情形：确实要做除法时改用 math.div($number1, $number2)；需要输出 CSS 原生斜杠语法时改用 calc，或把值放进 list.slash($elements...) 生成的斜杠列表中。

同一类别中还有两项收紧：

- 函数单位校验变严（1.32.0 起）：部分内置函数不再接受单位不兼容的输入，原先静默通过的值会报错。
- 严格一元运算符（1.55.0 起）：形如 a -b 的写法不再被解析为减法，需要显式写出空格 a - b。



### 颜色类弃用

两组与颜色相关的弃用同时存在：

- 旧颜色函数（1.79.0 起）：darken、lighten、saturate、desaturate、opacify、transparentize 等被 color.adjust 与 color.scale 取代。
- JS 颜色 API 的部分用法（1.79.0 起）：在 JavaScript 侧构造与读取颜色的部分接口被新接口替代，使用了自定义 JS 插件或 gulp 脚本时需一并检查。

```shell
DEPRECATION WARNING [color-functions]: darken() is deprecated. Suggestions:

color.scale($color, $lightness: -20%)
color.adjust($color, $lightness: -10%)
```

全局内置函数同样自 1.80.0 起弃用，警告类型为 global-builtin：

```shell
DEPRECATION WARNING [global-builtin]: Global built-in functions are deprecated
and will be removed in Dart Sass 3.0.0.
Use color.adjust instead.
```

> [!WARNING]
> **警告内容**：全局内置函数弃用后不会立即报错，IDE 与构建输出也常被折叠，容易漏改。旧项目可用 grep 检索未加命名空间的调用，例如查找列表相关函数时匹配 length、nth、join、append 等裸函数名，逐个确认是否应改为 list. 前缀的模块调用。



### 函数与语法类弃用

四项独立的小范围变更，影响面窄但容易在升级时集中暴露：

- meta.feature-exists（1.78.0 起）：不同实现的特性集已趋同，逐特性探测失去意义，需要区分行为时改由构建配置处理。
- 以两个连字符开头的函数与混合宏名（1.76.0 起）：与 CSS 自定义属性的命名空间冲突，改用普通名字。
- 给全局 abs() 传百分比（1.65.0 起）：百分号无法参与长度换算，改用 math.abs 或在计算前去掉单位。
- 旧式 if() 函数（1.95.0 起）：改向 CSS 原生的条件函数语法，实测编译时的提示如下。

```shell
DEPRECATION WARNING [if-function]: The Sass if() syntax is deprecated
in favor of the modern CSS syntax.

Suggestion: if(sass(true): 10px; else: 15px)
```

同一类别中还有一项行为变化而非弃用：type() 不再被解析为 Sass 内置函数。实测 type(10px) 会原样保留为纯 CSS 函数调用，输出 type(10px)，需要取类型时一律用 meta.type-of($value)。



### 输出行为变更：混合声明

自 1.77.7 起，样式规则中「声明与嵌套规则混排」的输出结构发生变化。实测以下代码：

```scss
.a {
  color: red;
  .b { color: blue; }
  background: green;
}
```

```css
.a {
  color: red;
}
.a .b {
  color: blue;
}
.a {
  background: green;
}
```

声明保持在书写位置，嵌套规则插在中间，外层规则因此被拆成两条。旧版本会把外层声明合并到同一条规则中，产物形态不同，依赖产物顺序的样式可能因此改变层叠结果。

规避方式统一为一条书写约定：把所有声明集中写在嵌套规则之前。

```scss
.a {
  color: red;
  background: green;

  .b { color: blue; }
}
```



### 选择器类变更：相邻复合选择器

Dart Sass 1.100.0 起，& 只能出现在复合选择器的开头。实测 && 会直接报错：

```text
Error: "&" may only used at the beginning of a compound selector.
   ╷
15 │   && { color: blue; }
   │    ^
   ╵
  c.scss 15:4  root stylesheet
```

旧写法中 && 与 .a& 用于提升特异性，替代方案是追加具体类名（&.is-active），或改用 @at-root 与选择器函数显式构造。

同一版本线上还有其他选择器相关收紧：无效组合器写法（1.54.0 起）与媒体查询 Level 4 语法（1.54.0 起）不再容忍旧式写法，例如 and、or 混排的媒体条件需要按新语法书写。



### 自动化迁移

官方提供 sass-migrator 处理机械性改写，覆盖最费时的三类工作：@import 转 @use 与 @forward、斜杠除法转 math.div、旧颜色函数转模块函数。

```shell
# 模块化迁移
npx sass-migrator module --migrate-deps styles/main.scss

# 除法迁移
npx sass-migrator division --migrate-deps styles/main.scss

# 颜色函数迁移
npx sass-migrator color --migrate-deps styles/main.scss
```

> [!CAUTION]
> **注意内容**：迁移工具处理的是语法，无法处理语义。三类问题必须人工复核：一是 @import 转为 @use 后原本依赖全局可见性的成员引用；二是颜色函数迁移时默认色彩空间从 HSL 变为颜色自身的空间，色值会变化；三是嵌套导入（@import 写在选择器内部）无法自动转换，需改写为混合宏调用或 meta.load-css。迁移前务必提交一次基线，迁移后逐页比对视觉结果。



### 升级策略

渐进升级比一次性全量重写可控，推荐顺序如下：

1. 先升级编译器版本，保留旧写法。此时只有弃用警告，产物不变，风险最低。
2. 在 CI 中开启 --fatal-deprecation，把新增的遗留写法挡在合并之前，避免边清边添。
3. 按类别分批迁移：先 @import，再除法，最后颜色函数。每批独立提交，便于回滚。
4. 每批迁移后比对产物：产物 diff 应只在预期位置变化，颜色类迁移需逐色核对。
5. 全量清除后，用 --silence-deprecation 的清单核对是否已全部清空。



### 可维护性检查清单

日常提交前的自查项，按投入产出排序：

- 无 @import、无斜杠除法、无无命名空间的全局函数调用。
- 声明集中写在嵌套规则之前，避免规则被拆分。
- @use 与 @forward 出现在文件顶部，@forward 写在同名的 @use 之前。
- 嵌套层级不超过两层，选择器权重可预测。
- 每个样式文件不超过 300 行，组件样式与页面样式分离。
- 颜色与间距全部来自令牌，无散落的十六进制字面量。
- 循环生成的规则总数有上限约定，产物体积在构建输出中可观测。
- 编译输出无弃用警告（可用 --fatal-deprecation 强制）。
