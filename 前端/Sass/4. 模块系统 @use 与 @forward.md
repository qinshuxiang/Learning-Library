## 模块系统 @use 与 @forward

### 为什么废弃 @import

旧的 @import 规则有三个结构性缺陷，模块系统正是为修正它们而设计。

第一是全局污染：@import 加载的文件中所有变量、函数、混合宏都进入同一个全局作用域，不同库之间无隔离，只能靠冗长的前缀名规避冲突。

第二是重复输出：同一文件被多次 @import 时，其中的样式会被重复编译进产物。实测两个 @import 指向同一文件，产物中出现两份相同规则：

```scss
@import "module";

@import "module";
```

```css
.padder {
  padding: 8px;
}
.padder {
  padding: 8px;
}
```

第三是来源不可追踪：读到 $radius 时无法判断它来自哪个文件。

```shell
DEPRECATION WARNING [import]: Sass @import rules are deprecated
and will be removed in Dart Sass 3.0.0.
More info and automated migrator: https://sass-lang.com/d/import
```

Dart Sass 1.80.0 起对 @import 输出弃用警告，并计划在 3.0.0 中移除。新代码一律使用 @use。

> [!IMPORTANT]
> **重要内容**：@import 与 @use 不能在同一处混用替代。@use 的成员默认不进入全局作用域，因此把 @import 机械替换成 @use 后，原有的裸变量引用会全部报未定义。迁移时需同步补上命名空间前缀，或对被加载文件改用 @forward 后再统一改造。官方提供了自动化迁移工具，命令见参考资料篇。



### @use 的加载与访问

@use 加载目标文件并生成命名空间，默认取 URL 的最后一段作为命名空间名。

```scss
// src/_corners.scss
$radius: 3px;

@mixin rounded {
  border-radius: $radius;
}

@function double($n) {
  @return $n * 2;
}
```

```scss
// style.scss
@use "src/corners";

.button {
  @include corners.rounded;
  padding: 5px + corners.$radius;
}
```

成员访问采用固定形式：变量写命名空间点变量名，函数写命名空间点函数名加参数，混合宏写 @include 命名空间点混合宏名。

@use 的加载有两条硬性约束：

- 位置：必须写在文件其他规则之前，仅 @charset 与 @forward 可以排在它前面。变量声明可以排在 @use 之前，用途是给 with 配置提供值。
- 作用域：只能写在顶层，不能嵌在样式规则内部，嵌入会报 This at-rule is not allowed here。

```scss
.a {
  @use "sass:math";   // 错误：@use 不能嵌套在样式规则内
}
```

```scss
Error: This at-rule is not allowed here.
  ╷
2 │   @use "sass:math";
  │   ^^^^^^^^^^^^^^^^
  ╵
  l.scss 2:3  root stylesheet
```

每个模块在整个编译中只被求值一次。样式也只输出一次，因此同一个基础样式文件被多个模块引用时不会产生重复 CSS。



### 命名空间与 as

命名空间可以自定义，写法是 @use 加 URL 加 as 加别名。

```scss
@use "src/corners" as c;

.button {
  @include c.rounded;
  padding: 5px + c.$radius;
}
```

不写命名空间用 as 加星号，成员的引用方式与旧 @import 相同，但只作用于当前文件。

```scss
@use "src/corners" as *;

.button {
  @include rounded;
  padding: 5px + $radius;
}
```

as 星号应只用于自己完全掌控的文件：一旦被加载文件新增同名成员，冲突会静默改变引用目标。

> 命名空间的另一收益是反向约束写法。有命名空间时变量可以叫 $radius、$width 这类短名而不会冲突，旧的 @import 时代只能写成 $mat-corner-radius 这样的长名前缀。



### 配置 with 与 !default

被加载文件用 !default 声明可配置变量，调用方用 with 传入覆盖值。

```scss
// src/_theme.scss
$text: black !default;
$bg: white !default;
```

```scss
// cfg.scss
@use "src/theme" with ($text: #222, $bg: #eee);

.t {
  color: theme.$text;
  background: theme.$bg;
}
```

```css
.t {
  color: #222;
  background: #eee;
}
```

配置有两条限制：一是每个模块只允许配置一次，即首次加载时；二是同时要改名与配置时，as 子句必须写在 with 之前。

```scss
// 顺序固定：先 as 后 with
@use "src/theme" as t with ($text: #222);
```

若模块已被其他文件先加载过，再配置就会直接报错：

```scss
Error: This module was already loaded, so it can't be configured using "with".
```

原因是模块只求值一次，配置必须在该次求值前提供。规避方式是把配置集中到入口文件，由入口统一 with 后再向外分发。



### 私有成员

变量、函数、混合宏的名字以连字符或下划线开头即为私有成员，只能在本文件内使用。

```scss
// src/_corners.scss
$-radius: 3px;

@mixin rounded {
  border-radius: $-radius;
}
```

外部文件引用 corners.$-radius 会报错。这条机制让库可以有内部实现细节，而公开的 API 面维持最小。



### @forward 与库入口

@forward 加载目标文件并把它的公开成员转出去，转出的成员对「加载本文件的人」可见，但对本文件自身不可见。它是构建库的统一入口的手段。

```scss
// src/_index.scss
@forward "corners";
@forward "theme";
@forward "components/button";
```

```scss
// entry.scss
@use "src" as lib;

@debug lib.$radius;   // 3px
@debug lib.double(21);// 42

.used { @include lib.rounded; }
```

@forward 支持三种修饰：

- 加前缀：@forward "src/list" as list-*，下游引用变为 list-reset 这类带前缀的名字，适合向外部暴露多个库时隔离命名。
- 只转发指定成员：@forward "src/list" show list-reset, $gap。
- 排除指定成员：@forward "src/list" hide list-reset, $gap。

@forward 的 with 子句额外允许带 !default，用于给上游设定中间层默认值，同时保留下游继续覆盖的能力：

```scss
// _opinionated.scss
@forward "library" with (
  $black: #222 !default,
  $border-radius: 0.1rem !default
);
```

> 同一文件同时对某模块写 @forward 与 @use 时，@forward 应写在前面。这样下游传来的配置会先作用于 @forward，随后的 @use 才拿到已配置好的版本。



### 索引文件与目录加载

目录下放置名为 _index.scss 的文件时，@use 该目录路径会直接加载这个索引文件。

```scss
// src/_index.scss
@forward "corners";
@forward "theme";
```

```scss
// 引用目录等价于引用 _index.scss
@use "src" as lib;
```

这条约定让库的对外入口稳定：内部文件如何增删重排，外部始终只引用目录名。



### 常见错误对照

实际迁移与使用中最常出现的几类失败，及其成因：

- 变量未定义：把 @import 换成 @use 后未补命名空间前缀，需改为 命名空间.$变量 形式。
- 无法配置：目标模块在此之前已被加载过，需把 with 提前到首次加载处。
- 成员不可见：@forward 只让成员对下游可见，本文件若要使用需额外写一条 @use。
- 私有成员被拒：成员名以连字符或下划线开头，外部不可引用。
- @use 位置报错：被写在了样式规则之后或嵌套在规则内，需移到文件顶部。
