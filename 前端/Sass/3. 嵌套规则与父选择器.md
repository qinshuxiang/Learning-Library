## 嵌套规则与父选择器

### 嵌套的基本形式

嵌套把后代关系写进层级，编译时展开为完整选择器，省去重复的父级前缀。

```scss
.card {
  color: #333;

  .title {
    font-weight: 700;
  }
}
```

```css
.card {
  color: #333;
}
.card .title {
  font-weight: 700;
}
```

嵌套可以写任意深度的组合器，子选择器、相邻兄弟选择器、后继选择器都按 CSS 语义展开：

```scss
.card {
  > .inner { padding: 4px; }
  + .sibling { margin-left: 8px; }
}
```

```css
.card > .inner {
  padding: 4px;
}
.card + .sibling {
  margin-left: 8px;
}
```



### 父选择器 &

& 指代当前外层选择器，可以拼接后缀、附加伪类，也可以把父级挪到后代的后面。

```scss
.card {
  &__title { font-weight: 700; }
  &--featured { border: 2px solid #f60; }
  &:hover, &:focus { outline: 1px solid; }
  &.is-open { display: block; }
  .parent & { color: #999; }
}
```

```css
.card__title {
  font-weight: 700;
}
.card--featured {
  border: 2px solid #f60;
}
.card:hover, .card:focus {
  outline: 1px solid;
}
.card.is-open {
  display: block;
}
.parent .card {
  color: #999;
}
```

其中 &__title 与 &--featured 是 BEM 命名的常用写法：类名结构与层级结构保持同构，改前缀时只需改父级一处。

& 在 SassScript 中的值是一个选择器列表，可用 meta.inspect(&) 观察：

```scss
@use "sass:meta";

.parent {
  @debug meta.inspect(&);   // (.parent,)
  &__child {
    @debug meta.inspect(&); // (.parent__child,)
  }
}
```

> [!WARNING]
> **警告内容**：& 只能出现在复合选择器的开头。写成 && 或 .a& 会直接报错：「&」may only used at the beginning of a compound selector。旧版本中 && 曾被用作提升特异性的技巧，在 Dart Sass 1.100.0 起不再合法，升级后需改为追加具体类名或提升选择器层级。



### 属性嵌套

属性名含相同前缀时，可以把前缀抽出来作为嵌套层级，冒号后可紧跟同名值。

```scss
.card {
  font: {
    family: sans-serif;
    size: 14px;
    weight: 700;
  }
  margin: auto {
    bottom: 10px;
  }
}
```

```css
.card {
  font-family: sans-serif;
  font-size: 14px;
  font-weight: 700;
  margin: auto;
  margin-bottom: 10px;
}
```

写法上：font 后必须带冒号才进入属性嵌套，漏掉冒号会被当作普通声明而报错；前缀本身有值时，把值写在冒号前，如上例的 margin: auto 会同时产出一条 margin 声明。



### 嵌套中的 @media

@media 可以写在样式规则内部，编译时会被提升到规则之外，并把外层选择器复制进去。

```scss
.card {
  padding: 8px;

  @media (min-width: 600px) {
    padding: 16px;
  }
}
```

```css
.card {
  padding: 8px;
}
@media (min-width: 600px) {
  .card {
    padding: 16px;
  }
}
```

与伪类嵌套的性质不同：&:hover 只影响选择器拼接，而 @media 会改变输出结构。媒体查询条件本身也支持变量与运算：

```scss
$breakpoint-tablet: 768px;
$breakpoint-scale: 1.5;

.responsive {
  @media (min-width: $breakpoint-tablet) and (max-width: $breakpoint-tablet * $breakpoint-scale) {
    display: flex;
  }
}
```



### @at-root

@at-root 把包含的规则挪到嵌套之外，输出到文档顶层或指定层级之外。

```scss
.wrapper {
  @at-root .rooted { color: red; }
}

.outer {
  @at-root {
    .a { color: 1; }
    .b { color: 2; }
  }
}

.list {
  @at-root #{&}-item { color: red; }
}
```

```css
.rooted {
  color: red;
}

.a {
  color: 1;
}

.b {
  color: 2;
}

.list-item {
  color: red;
}
```

三种形态的差异：单规则形态直接把该规则移出；块形态对块内多条规则统一生效；插值形态先取当前父选择器的文本再拼接，& 在此处退化为文本而非选择器引用。

> @at-root 常与「组件根样式写在组件块内」的组织方式配合使用，让作者在阅读时保持层级连贯，又不必让产物继承深层嵌套。



### 嵌套深度与陷阱

嵌套的展开是纯文本拼接，过度使用会同时放大三个问题：

- 选择器过长：三层以上的嵌套很容易产出权重过高、复用性差的选择器，后续覆盖只能继续叠加层级。
- 权重失控：嵌套深度直接决定特异性，深层规则会压过所有浅层规则，导致 !important 被当作常规手段。
- 可读性下降：产物中的选择器与源码不再一一对应，调试时定位困难。

主流做法是限制在两层以内：组件根选择器一层，状态与元素用 & 拼接的平铺类名承担，不做层级嵌套。这与 BEM 的前提一致——类名已经表达了结构，结构不应再由选择器层级重复表达。

> 判断标准可以简化为一句：如果嵌套是为了表达「谁在谁里面」，可以保留；如果只是为了少写一遍前缀，改用 & 拼接的平铺类名。
