## Next.js 入门

**Next.js**：是 Vercel 维护的 React 元框架（meta-framework），在 React 之上补齐文件系统路由、渲染模式选择、数据获取与构建部署等应用级能力，当前主线版本默认使用 App Router。

本篇只回答四件事：Next.js 是什么、项目结构与路由怎么写、布局与页面怎么组织、页面之间怎么导航。数据获取与缓存策略从第 8 篇展开，服务端组件与流式渲染从第 9 篇展开。

### Next.js 是什么

本节确立 Next.js 的定位与工程约定：它不是一门新的框架语言，而是把 React 的组件模型接入服务端与构建流程的一层应用框架。

#### 定位与核心能力

**Next.js**：是建立在 React 之上的应用级框架，把「组件树如何变成 HTML、由谁渲染、如何取数据、如何打包部署」这些问题用目录约定与内置能力统一解决。

- 渲染能力：同一套组件代码可在服务端按请求渲染为 HTML，也可在构建期预生成静态文件，模式由页面与数据决定。
- 路由能力：以目录结构表达路由，新增页面即新增文件夹，不需要单独维护一份路由表。
- 工程能力：内置打包、代码分割、图片与字体优化、开发服务器与生产构建。
- 部署能力：既可部署到托管平台，也可自托管在 Node.js 运行时（详见本主题第 10 篇 Next.js 工程实践与部署）。

```json
// package.json 中记录的核心依赖
{
  "dependencies": {
    "next": "^15.0.0",
    "react": "^19.0.0",
    "react-dom": "^19.0.0"
  }
}
```

Next.js 并不替代 React：组件的写法、Hooks 的用法与状态更新规则都来自 React，Next.js 决定的是这些组件在哪里执行、何时执行。

- 心智不变：组件、属性、状态、副作用的写法仍是 React 的那一套。
- 心智新增：需要判断一段代码属于服务端还是浏览器，这是框架层引入的新问题。
- 前提知识：组件与 Hooks 的基础归 前端/React 主题，本系列不重复展开。

> React 负责「组件是什么」，Next.js 负责「组件在哪里运行、怎样送达浏览器」，两者是分层关系而不是相互替代。

**速记**：Next.js 是 React 的元框架，用目录约定补上路由、渲染与部署能力。



#### App Router 与目录路由心智

**App Router**：是 Next.js 当前的路由体系，以 app 目录下的文件夹层级映射 URL 层级，并以服务端组件作为默认的组件形态。

- 默认服务端：app 目录下的组件默认在服务端渲染，需要浏览器能力时再显式声明为客户端组件（详见本主题第 9 篇 Next.js 进阶：服务端组件与流式渲染）。
- 约定优先：文件名承担语义，page 表示可访问页面，layout 表示共享外壳，route 表示接口端点。
- 嵌套组合：父级布局包裹子级页面，子级路由变化不会导致父级布局重新渲染。
- 替代关系：App Router 取代了早期的 pages 目录体系，新项目统一使用 app 目录。

```text
app/page.tsx                  → /
app/about/page.tsx            → /about
app/blog/page.tsx             → /blog
app/blog/[slug]/page.tsx      → /blog/任意标识
```

```tsx
// app/page.tsx
export default function HomePage() {
  return <h1>首页</h1>;
}
```

> [!NOTE]
> **提醒内容**：本系列所有 Next.js 示例统一使用 App Router，不再涉及 pages 目录的旧式数据获取函数。

**速记**：App Router 以 app 目录映射路由，默认服务端组件，页面与布局由文件名约定。



#### 创建项目与开发命令

**创建项目**：是用官方脚手架生成可运行骨架的过程，一条命令即得到目录结构、依赖与脚本。

- 脚手架：执行 npx create-next-app@latest 并按提示选择 TypeScript、App Router 等选项。
- 开发：执行 npm run dev 启动开发服务器，默认监听 3000 端口，改动即时热更新。
- 构建：执行 npm run build 产出生产产物，同时执行类型检查与静态分析。
- 预览：执行 npm run start 以生产产物启动本地服务，用于上线前的本地验证。

脚手架生成的结果包含可直接运行的首页、根布局与全局样式，删除示例内容即可开始写业务。

```bash
npx create-next-app@latest my-app
cd my-app
npm run dev
# Server running at http://localhost:3000
```

```json
// package.json 中的脚本约定
{
  "scripts": {
    "dev": "next dev",
    "build": "next build",
    "start": "next start"
  }
}
```

> 开发服务器的运行方式与生产不同：前者按请求即时编译，后者使用构建产物，因此开发期启动快并不代表构建能通过。

**速记**：create-next-app 生成骨架，dev 开发、build 构建、start 预览产物。



### 项目结构与文件路由

本节说明目录如何变成 URL：只要掌握文件夹与几个固定文件名，就掌握了一个站点的全部入口。

#### 顶层目录结构

**顶层目录结构**：是项目根目录下各文件夹的职责划分，路由代码集中在 app 目录，其余目录承担静态资源、公共组件与配置。

- app：路由与页面代码，文件夹层级即 URL 层级。
- public：原样对外提供的静态文件，按根路径直接访问。
- 公共代码目录：不参与路由的代码放在 app 之外，如 components、lib，命名无强制约定。
- 配置文件：next.config 与 tsconfig.json 位于根目录，控制构建与类型检查行为。

```text
my-app/
├── app/
│   ├── layout.tsx
│   └── page.tsx
├── public/
│   └── logo.svg
├── next.config.ts
├── package.json
└── tsconfig.json
```

文件与地址的对应关系可以反推：看到 /blog/hello 就能定位到 app/blog/[slug]/page.tsx，调试时无需在路由表中搜索。

> app 目录之外的文件不会被当作路由，只有 app 内的约定文件名才会生成可访问路径。

**速记**：app 存放路由代码，public 放静态资源，其余目录不参与路由映射。



#### 路由段与文件夹约定

**路由段（route segment）**：是 app 目录下的一个文件夹，其名称对应 URL 中的一段路径，多层嵌套组成完整地址。

- 映射规则：app/about/page.tsx 对应 /about，app/blog/post/page.tsx 对应 /blog/post。
- 页面文件：只有名为 page 的文件对外暴露路径，同目录其他文件不生成路由。
- 首页：app/page.tsx 对应根路径，也就是站点首页。
- 命名约定：文件夹名使用英文小写单词，URL 片段与目录名保持一致，便于对照排查。

```tsx
// app/about/page.tsx → 访问 /about
export default function AboutPage() {
  return <p>关于本页</p>;
}
```

- 大小写敏感：URL 与文件夹名逐字符对应，部署到大小写敏感的服务器时需保持一致。
- 层级即嵌套：目录每深入一层，URL 就多一段，不需要在代码中再声明父子关系。

> 只有 page 文件是可访问的页面入口，同目录下即使有的文件返回 JSX，也不会生成路由。

**速记**：文件夹即路由段，只有 page 文件生成可访问路径。



#### 动态路由与路由组

**动态路由（dynamic route）**：是用方括号包裹的文件夹名表示可变路径段，运行时把实际值作为参数交给页面组件。

- 单段动态：app/posts/[slug]/page.tsx 匹配 /posts/a 与 /posts/b，参数取自页面组件的 params。
- 多段捕获：app/docs/[...path]/page.tsx 捕获剩余的全部路径段，用于深层文档目录。
- 路由组：用括号包裹的文件夹名只用于组织代码，不进入 URL，如 app/(marketing)/about/page.tsx 仍对应 /about。
- 参数形态：较新版本中 params 以 Promise 形式传入页面，需用 async 组件读取后再使用。

```text
app/posts/[slug]/page.tsx        /posts/hello   → params.slug = "hello"
app/docs/[...path]/page.tsx      /docs/a/b/c    → params.path = ["a","b","c"]
app/(marketing)/about/page.tsx   /about
```

```tsx
// app/posts/[slug]/page.tsx → 访问 /posts/hello
export default async function PostPage({
  params,
}: {
  params: Promise<{ slug: string }>;
}) {
  const { slug } = await params;
  return <p>文章标识：{slug}</p>;
}
```

> [!TIP]
> **建议内容**：用路由组把「URL 层级相同但业务模块不同」的代码分开，例如 (shop) 与 (admin)，避免改动一个模块时牵连整棵布局。

**速记**：方括号表达动态段，括号包裹的文件夹只分组、不进入 URL。



### 布局与页面

本节说明一页内容由哪两层拼成：外层是不变的布局，内层是随路由切换的页面。

#### 根布局与嵌套布局

**布局（layout）**：是包裹一个路由段及其子段的外壳组件，同段内导航时不重新渲染，用于承载导航栏、页脚等共享结构。

- 根布局：app/layout.tsx 必须存在，负责输出 html 与 body 结构以及全局样式。
- 嵌套：每层文件夹可各写一个 layout，形成由外到内的包裹链。
- 不重建：同属一个 layout 覆盖范围的两个页面之间导航时，该布局的组件状态与滚动位置保持不变。
- 参数：layout 接收 children 属性，也就是被它包裹的子级内容。

```tsx
// app/layout.tsx
export default function RootLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <html lang="zh-CN">
      <body>
        <header>站点导航</header>
        {children}
      </body>
    </html>
  );
}
```

```tsx
// app/blog/layout.tsx：只包裹 /blog 及以下路径
export default function BlogLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <div className="blog-shell">
      <aside>文章分类</aside>
      <section>{children}</section>
    </div>
  );
}
```

> 布局承担的是「跨页面保持不变的结构」，把导航与页脚放在布局里，页面组件只需关心自己的内容。

**速记**：layout 包裹子段且跨页复用，根布局必须存在并输出 html 结构。



#### 页面组件与路由出口

**页面组件（page）**：是某个 URL 的最终内容出口，位于路由段文件夹内，文件名固定为 page。

- 唯一性：一个路由段最多有一个 page 文件，出现多个会造成路由冲突。
- 插入位置：page 的内容会插入到本段以及各级祖先 layout 的 children 位置上。
- 服务端默认：page 默认是服务端组件，可以直接声明为 async 并在渲染中取数。
- 与 layout 的区别：page 随路由切换而重建，layout 不随子路由切换重建。

```tsx
// app/blog/page.tsx
export default function BlogPage() {
  return (
    <main>
      <h1>博客列表</h1>
      <p>此处展示文章入口。</p>
    </main>
  );
}
```

一个页面组件不必关心导航栏与页脚，这些结构由祖先布局补齐；页面只负责本路由独有的内容区域。

> 布局负责「不变的外壳」，页面负责「会变的内容」，两者嵌套组合出最终文档结构。

**速记**：page 是路由的最终出口，随路由切换重建，嵌套在各级 layout 之内。



#### 特殊文件名与元数据

**特殊文件名**：是 app 目录中具有固定语义的文件名，除 page 与 layout 之外还有 loading、error、not-found 等，其中与流式渲染配合的部分详见第 9 篇。

- loading：同级页面加载期间展示的占位界面。
- error：同级页面渲染出错时展示的错误界面，必须是客户端组件。
- not-found：路径匹配不到内容时展示的界面。
- 元数据：通过导出 metadata 对象声明标题与描述，供搜索引擎与分享卡片使用（详见本主题第 6 篇 SEO 与首屏性能）。

```tsx
// app/blog/page.tsx
import type { Metadata } from "next";

export const metadata: Metadata = {
  title: "博客列表",
  description: "按时间排列的文章入口",
};

export default function BlogPage() {
  return <h1>博客列表</h1>;
}
```

```tsx
// app/blog/[slug]/not-found.tsx
export default function BlogNotFound() {
  return <p>该文章不存在或已删除。</p>;
}
```

> [!IMPORTANT]
> **重要内容**：只有 page 与 layout 这类约定文件名具有特殊语义，把业务组件命名为 page 会被当作路由入口，造成误判与冲突。

**速记**：loading、error 与 metadata 都由固定文件名约定，元数据承担 SEO 职责。



### 导航与预取

本节说明页面之间怎么跳：声明式与编程式两条路径，以及框架在点击之前替用户做的预取。

#### Link 组件与声明式导航

**Link 组件**：是 Next.js 提供的导航组件，通过 href 属性声明目标路径，点击时不触发整页刷新，只替换发生变化的部分。

- 用法：从 next/link 导入 Link，用 href 指定目标，子节点是可点击内容。
- 客户端导航：点击后只请求目标路由需要的片段，当前布局与组件状态得以保留。
- 语义保留：渲染结果是锚点元素，右键新开、复制链接等浏览器行为仍然可用。
- 参数形式：href 支持对象写法，用于携带查询参数与片段标识。

```tsx
// app/layout.tsx 中的导航条片段
import Link from "next/link";

export function SiteNav() {
  return (
    <nav>
      <Link href="/">首页</Link>
      <Link href="/blog">博客</Link>
      <Link href={{ pathname: "/posts", query: { page: 1 } }}>文章</Link>
    </nav>
  );
}
```

- 外部地址：指向其他站点的链接不产生客户端导航，会退回浏览器的正常跳转。
- 返回行为：客户端导航会记录历史，浏览器前进与后退按预期工作。

> Link 触发的是客户端导航，不会重新下载整份文档，只有目标路由需要的片段与数据会被请求。

**速记**：Link 用 href 声明目标，点击走客户端导航，保留布局与状态。



#### 编程式导航与路由钩子

**编程式导航**：是在事件回调或副作用中主动改变路由的方式，由 next/navigation 提供的钩子完成，适用于提交表单与登录跳转等场景。

- useRouter：返回 router 对象，提供 push、replace、back、forward、refresh 等方法。
- usePathname：返回当前路径字符串，常用于高亮当前菜单项。
- useSearchParams：返回只读的查询参数对象，用于读取筛选条件与分页位置。
- 客户端限制：这些钩子只能在客户端组件中使用，在服务端组件里调用会报错。

```tsx
"use client";

import { useRouter, usePathname } from "next/navigation";

export function SearchBox() {
  const router = useRouter();
  const pathname = usePathname();

  function goToResult(keyword: string) {
    router.push(pathname + "?q=" + keyword);
  }

  return <button onClick={() => goToResult("next")}>搜索</button>;
}
```

- push 与 replace：前者新增一条历史记录，后者替换当前记录，返回时会跳过被替换的页面。
- refresh：重新请求当前路由的服务端数据，适合写操作完成后刷新列表。

> 客户端组件的声明方式与边界规则详见本主题第 9 篇 Next.js 进阶：服务端组件与流式渲染。

**速记**：编程式导航由 useRouter 提供，路径与查询条件分别由 usePathname、useSearchParams 读取。



#### 预取机制与生效条件

**预取（prefetch）**：是 Link 在链接进入视口时提前请求目标路由资源的行为，让后续点击接近瞬时完成。

- 默认开启：生产环境下，出现在视口内的 Link 会自动预取目标路由。
- 预取范围：只覆盖目标路由所需的静态片段与共享布局，不包含按需渲染的动态内容。
- 关闭方式：给 Link 传入 prefetch 为 false，可单独关闭该链接的预取。
- 收益有限的情形：目标路由依赖动态数据且无法静态化时，预取能提前准备的内容较少（数据侧策略详见本主题第 8 篇 Next.js 数据获取与缓存）。

```tsx
import Link from "next/link";

export function Footer() {
  return (
    <Link href="/contact" prefetch={false}>
      联系我们
    </Link>
  );
}
```

预取的代价是额外的网络请求：页面里链接密集时，视口内所有目标都会被提前请求，需要按流量敏感度决定是否逐个关闭。

**速记**：Link 默认在视口内预取目标路由，可按链接关闭，动态路由收益有限。
