## uni-app 跨端开发

**uni-app**：是面向多端的跨端开发框架，用一套 Vue 语法源码经编译产出 Web、多个小程序平台与原生应用等多端产物。

本篇回答四件事：uni-app 是什么、项目结构与开发约定长什么样、条件编译如何处理平台差异、多端构建产出什么产物。跨端方案的总体选型详见本主题第 13 篇 跨端开发概览与方案选型，小程序的内置组件与基础 API 详见本主题第 15 篇 小程序开发：页面、组件与 API，本篇不重复。

### uni-app 是什么

本节确立 uni-app 的定位：它是一个以 Vue 单文件组件为编写单位、以编译为主要手段的跨端框架，理解这一点是后续所有约定的前提。

#### uni-app 的定位

**uni-app**：是以 Vue 单文件组件为基本编写单位、通过编译把同一份源码转换为多个目标端运行形态的跨端框架。

- 编写单位：模板、脚本与样式写在同一个单文件组件里，而不是分列三套文件。
- 编译产物：Web 端产出网页资源，小程序端产出代码包，原生应用端产出前端资源与原生工程。
- 统一命名：框架提供统一的组件名与接口名，调用方不必区分目标端。
- 差异隔离：确需分端的片段用条件编译标记，编译期只保留当前端的分支。

```vue
<script setup>
import { ref } from "vue";

const count = ref(0);
</script>

<template>
  <view class="counter">
    <text>{{ count }}</text>
    <button @click="count++">加一</button>
  </view>
</template>

<style scoped>
.counter {
  padding: 16px;
}
</style>
```

> 统一命名不等于统一行为：框架尽量抹平差异，但涉及平台专有能力的部分仍需逐端确认（详见本主题第 20 篇 多端适配：布局、样式与平台差异）。

**速记**：uni-app 用 Vue 单文件组件统一编写，靠编译产出多端产物。



#### 与原生小程序开发的差异

**原生小程序开发**：直接用平台提供的模板、样式与脚本三类文件编写；uni-app 改用 Vue 单文件组件编写，再编译为对应端代码。

- 编写单位：原生分列模板、样式与脚本；uni-app 合并为一个单文件组件。
- 逻辑组织：原生用页面实例对象承载逻辑；uni-app 用组合式 API 组织状态（详见 前端/Vue3 主题第 13 篇 组合式 API 与 script setup）。
- 代码复用：uni-app 的业务代码可在多端复用，仅平台差异处用条件编译隔离。
- 能力调用：uni-app 提供统一接口名，底层映射到各端原生能力。

```js
// uni-app 中调用统一接口，底层映射到目标平台实现
uni.request({
  url: "https://api.example.com/articles",
  success(res) {
    console.log(res.data);
  },
});
```

> 统一接口在各端由编译期或运行时映射到目标实现，名字一致不代表参数行为完全一致。

**速记**：原生分列三套文件，uni-app 用单文件组件统一编写再编译。



#### 编译期与运行时

**编译期**：是把 Vue 单文件组件转换为目标端代码的阶段。**运行时**：是产物在目标端执行时所依赖的支撑代码。

- 编译期职责：解析单文件组件，按目标端生成对应的模板、样式与逻辑文件。
- 运行时职责：提供跨端一致的组件层与接口层，填补平台差异。
- 平台判定：编译时通过条件编译剔除不属于当前端的代码，不进入产物。
- 产物可读：小程序端产物接近手写结构，便于与对应平台的开发者工具配合调试。

```bash
# 开发模式带监听，生产模式产出可上传的代码包
npm run dev:mp-weixin    # 微信小程序开发模式
npm run build:mp-weixin  # 微信小程序生产构建
```

> [!CAUTION]
> **注意内容**：开发模式能跑通不代表生产构建能过，条件编译误用与资源路径问题往往只在生产构建时暴露，发布前必须完整执行一次生产构建。

**速记**：编译期生成目标端代码，运行时提供跨端一致层，两端各有分工。



#### 版本与生态

**生态**：是围绕 uni-app 的插件市场、组件库与项目模板集合，用于补齐跨端开发中的通用能力。

- 插件市场：提供大量可选插件，覆盖界面组件、接口封装与业务模板。
- 官方组件：框架内置一批跨端组件，命名与各端原生能力对应。
- 项目模板：官方提供多套模板，按目标端组合选择初始化方式。
- 版本策略：不同版本对 Vue 语法与目标端的支持程度不同，迁移前先确认目标版本能力。

```text
# 引入外部能力前需要确认的三件事
1. 插件是否仍在维护
2. 是否覆盖项目需要全部目标端
3. 自身是否依赖浏览器专有对象
```

> 生态插件的质量参差，引入前应确认维护状态与目标端覆盖情况。

**速记**：插件市场与模板补足通用能力，引入前确认维护状态与端覆盖。



### 项目结构与开发约定

本节说明 uni-app 约定的目录组织与编写方式：页面、资源与配置各占固定位置，编译期据此收集入口。

#### 目录结构

**目录结构**：是 uni-app 约定的源码组织方式，页面、静态资源与配置各占固定位置，编译期据此确定入口。

- pages：页面目录，每个页面是一个单文件组件。
- static：静态资源目录，内容原样拷贝到各端产物。
- pages.json：全局配置，声明页面路径、窗口样式与导航表现。
- manifest.json：应用配置，声明各端特有的应用信息与权限。
- components：可复用的自定义组件目录，按需引入。

```text
project/
├─ pages/
│  ├─ index/index.vue
│  └─ detail/detail.vue
├─ components/
│  └─ ArticleCard.vue
├─ static/
├─ pages.json
├─ manifest.json
└─ package.json
```

> 只有 pages 目录下的页面会被编译为可导航页面，且页面路径必须同时出现在 pages.json 的登记列表里。

**速记**：页面在 pages，资源在 static，路由与窗口在 pages.json，应用信息在 manifest.json。



#### 页面与全局配置

**页面配置**：是在 pages.json 的 pages 数组中逐项声明页面路径与窗口表现的方式，编译期据此生成各端路由。

- 路径登记：数组首项为启动页，其余页面按需登记。
- 窗口样式：导航栏文字、背景色、是否允许下拉刷新等可按页面或全局设置。
- 分包：用分包字段把非首屏页面拆到独立代码包，控制主包体积。
- 条件覆盖：条件编译可针对特定端覆盖某些配置项。

```json
// pages.json：登记页面与全局窗口样式
{
  "pages": [
    { "path": "pages/index/index", "style": { "navigationBarTitleText": "首页" } },
    { "path": "pages/detail/detail", "style": { "navigationBarTitleText": "详情" } }
  ],
  "globalStyle": {
    "navigationBarTextStyle": "black"
  }
}
```

> [!WARNING]
> **警告内容**：页面组件存在但未写入 pages 数组时，该页面不会被注册为可导航页面，跳转将直接失败，新增页面必须同步登记。

**速记**：pages 数组决定可导航页面与启动页，窗口样式可全局也可逐页覆盖。



#### 单文件组件写法

**单文件组件**：是把模板、脚本与样式写在同一个文件里的编写单位，也是 uni-app 的基本组织方式。

- 模板段：用框架统一的组件名描述结构，编译到各端时映射为对应实现。
- 脚本段：用组合式 API 组织响应式状态，页面生命周期以组合式函数形式使用。
- 样式段：默认支持作用域隔离，可用单位与选择器受平台限制。
- 组件引入：自定义组件按需导入后在模板中使用。

```vue
<script setup>
import { ref, onMounted } from "vue";
import ArticleCard from "@/components/ArticleCard.vue";

const articles = ref([]);

onMounted(() => {
  uni.request({
    url: "https://api.example.com/articles",
    success(res) {
      articles.value = res.data;
    },
  });
});
</script>

<template>
  <view class="list">
    <ArticleCard v-for="item in articles" :key="item.id" :article="item" />
  </view>
</template>

<style scoped>
.list {
  padding: 12px;
}
</style>
```

> 页面级生命周期与组件级生命周期并存：页面级钩子由框架提供，组件级钩子沿用 Vue 的写法。

**速记**：一个单文件组件承载模板、脚本与样式，编译到各端后映射为对应实现。



#### 生命周期与页面通信

**页面生命周期**：是页面从加载、显示到卸载各阶段触发的回调。**页面通信**：是页面之间传递参数与回传结果的方式。

- 组合式钩子：加载、显示、隐藏等页面钩子以组合式函数形式调用。
- 传参：跳转时把参数拼进路径，目标页在加载钩子中读取。
- 回传：返回时可通过事件通道或全局状态回传结果（状态管理详见 前端/Vue3 主题第 21 篇 Pinia 状态管理）。
- 页面栈：栈内页面可能被保留而不卸载，隐藏与卸载需要区别对待。

```js
import { onLoad } from "@dcloudio/uni-app";

// 跳转时把参数拼进路径
uni.navigateTo({ url: "/pages/detail/detail?id=42" });

// 目标页读取参数
onLoad((query) => {
  console.log(query.id); // "42"
});
```

> 页面被隐藏时状态仍然保留，需要刷新数据的场景应把逻辑放在显示钩子而非加载钩子。

**速记**：页面钩子以组合式函数调用，传参走路径，回传走事件通道或全局状态。



### 条件编译与平台差异

本节回答同一份源码如何同时满足多个平台：答案是在编译期按端保留或剔除片段，而不是在运行时做判断。

#### 条件编译语法

**条件编译**：是在同一份源码中按目标平台保留或剔除片段的写法，编译期生效，被剔除的代码不进入产物。

- 注释式：用特定格式的注释标记包裹代码片段，其他端编译时整段剔除。
- 平台标识：标识符代表目标端，多个端可用竖线连接表示任一命中即保留。
- 配置式：pages.json 与 manifest.json 中同样可按端写不同配置。
- 样式式：样式文件中同样可用条件编译区分各端写法。

```js
// #ifdef MP-WEIXIN
console.log("仅在微信小程序端编译");
// #endif

// #ifndef H5
console.log("除 Web 端之外的所有端");
// #endif
```

```css
/* #ifdef APP-PLUS */
.safe-area {
  padding-bottom: env(safe-area-inset-bottom);
}
/* #endif */
```

> 条件编译在编译期完成，若误把运行时逻辑写进条件编译，其他端会因片段被剔除而缺失该逻辑。

**速记**：条件编译用注释标记包裹片段，编译期按端保留或剔除。



#### 平台常量与标识

**平台标识**：是代表各目标端的编译期符号，用于条件编译判断与分端配置。

- 常见标识：分别对应 Web 端、微信小程序端与原生应用端等。
- 多端组合：一个片段可同时适配多个端，用竖线连接多个标识。
- 命名对应：标识名与构建脚本中的端名保持一致，便于对照记忆。
- 运行时判断：部分场景也可在逻辑中运行时判断当前端，用于动态分支。

```js
// 用条件编译在编译期确定当前端
let currentPlatform = "unknown";

// #ifdef H5
currentPlatform = "web";
// #endif

// #ifdef MP-WEIXIN
currentPlatform = "mp-weixin";
// #endif

console.log(currentPlatform);
```

> 平台标识由编译期处理，写法与构建脚本中的端名对应，写错标识不会报错但分支会永远不生效。

**速记**：平台标识是编译期符号，可组合成多端片段，与构建脚本端名对应。



#### 平台差异的处理策略

**平台差异**：是同一功能在不同端表现或可用性不一致的现象，处理策略决定这些差异如何被隔离。

- 优先统一：能用统一接口完成的不写平台分支，减少分支数量。
- 兜底分支：确有差异处才用条件编译，并把分支集中到少数文件。
- 抽象封装：把平台特有实现封装成统一函数，调用方不感知平台。
- 降级处理：某端不支持的能力给出替代交互或明确提示。

```js
// 把平台差异封装在单个模块内，调用方无需关心当前端
export function saveToLocal(key, value) {
  // #ifdef MP-WEIXIN
  wx.setStorageSync(key, value);
  // #endif
  // #ifdef H5
  localStorage.setItem(key, JSON.stringify(value));
  // #endif
}
```

> [!TIP]
> **建议内容**：把平台分支集中到少数封装模块中，业务代码尽量只调用统一函数，可显著降低新增目标端时的改动面。

**速记**：能统一就不分支，分支集中封装，做不到的能力降级处理。



#### 组件与接口的平台覆盖差异

**平台覆盖差异**：是统一命名的组件与接口在部分端未实现或行为不同的现象。

- 组件覆盖：部分组件的属性与事件在个别端不支持，需条件编译给出替代写法。
- 接口覆盖：部分统一接口在个别端未实现，调用前应确认支持情况。
- 表现差异：即使同名同参数，各端的渲染结果与交互反馈也可能不同。
- 检测手段：以官方支持说明与真机验证为准，不以开发工具模拟为准。

```vue
<template>
  <view>
    <!-- #ifdef MP-WEIXIN -->
    <text>此分支仅微信小程序端编译</text>
    <!-- #endif -->
    <text>各端公共内容</text>
  </view>
</template>
```

> 同名接口的跨端一致性由框架尽量保证，涉及平台专有行为时仍需逐端验证。

**速记**：同名不等于同行为，支持情况以官方说明与真机验证为准。



### 多端构建与发布

本节只讲该框架的构建命令与产物形态，完整的流程、调试与排错统一归本主题第 21 篇 跨端工程化、调试与发布。

#### 构建命令与产物形态

**构建**：是把同一份源码按目标端编译为可运行产物的过程，由命令行脚本按端触发。

- 开发模式：带监听与热更新，产物供本地调试使用。
- 生产模式：经过压缩与优化的产物，用于上传或部署。
- 环境分离：构建时读取不同环境文件，区分开发与生产配置。
- 产物隔离：各端产物输出到独立目录，互不覆盖。

```bash
# 脚本名以官方模板为准，不同模板的命名可能略有差异
npm run dev:h5           # Web 端开发模式
npm run build:h5         # Web 端生产产物
npm run build:mp-weixin  # 微信小程序端生产代码包
npm run build:app        # 原生应用端前端资源
```

> [!IMPORTANT]
> **重要内容**：产物目录按端与模式区分，调试产物与生产产物不可混用；把开发模式产物提交上传会出现体积与调试信息问题。

**速记**：开发模式带监听，生产模式出压缩产物，各端产物输出到独立目录。



#### 各端产物差异

**产物差异**：是同一份源码在不同端编译后得到的文件形态差异，直接决定后续的上传或部署方式。

- 小程序端：产出对应平台的代码包结构，用该平台工具上传。
- Web 端：产出静态资源目录，可直接部署到静态托管服务。
- 应用端：先产出前端资源，再交由原生打包流程生成安装包。
- 调试配合：小程序端产物需与对应平台的开发者工具配合使用。

```text
dist/
├─ build/h5/            # Web 端静态资源
├─ build/mp-weixin/     # 微信小程序端代码包
└─ dev/mp-weixin/       # 微信小程序端开发产物
```

> 产物形态由目标端决定，构建命令只负责生成，上传与发布由各平台工具完成。

**速记**：小程序端出代码包，Web 端出静态资源，应用端出前端资源再走原生打包。



#### 环境变量与分端配置

**环境变量**：是构建时注入、用于区分运行环境的配置项，可在源码中按环境读取。

- 注入方式：构建命令读取环境文件，把变量注入到代码中。
- 命名约定：以固定前缀命名，避免与框架自带的变量冲突。
- 分端配置：应用标识、接口地址等在环境文件或应用配置中分别声明。
- 安全性：注入到客户端代码的变量对用户可见，不能放密钥。

```js
// 构建时注入的环境变量，在源码中直接读取
const apiBase = import.meta.env.VITE_API_BASE;
console.log(apiBase); // "https://api.example.com"
```

> [!WARNING]
> **警告内容**：注入到客户端代码的环境变量会随产物公开，密钥、令牌与数据库地址一律不得写进这类变量，只能留在服务端。

**速记**：环境变量构建时注入，按固定前缀命名，密钥绝不写进客户端可读变量。



#### 发布流程概览

**发布**：是各端产物分别提交到对应平台、经审核或部署后对外生效的过程。

- Web 端：把静态资源部署到托管服务，并配置域名与缓存策略。
- 小程序端：用平台工具上传代码包，提交审核通过后发布。
- 应用端：用原生打包流程生成安装包，提交应用市场审核。
- 版本对齐：多端共用同一份源码时，版本号与发布节奏需要统一管理。

```text
# 同一份源码的多端发布路径
源码 -> build:h5        -> 静态托管部署
     -> build:mp-weixin -> 平台工具上传 -> 审核 -> 发布
     -> build:app       -> 原生打包 -> 应用市场审核
```

> 构建、上传、审核、发布是四件独立的事，流程细节、调试手段与版本管理统一归本主题第 21 篇 跨端工程化、调试与发布。
