## Next.js 进阶：服务端组件与流式渲染

**服务端组件（React Server Component，RSC）**：是在服务端执行、渲染结果以特殊描述形式发送给浏览器的 React 组件，它本身的代码不进入客户端打包产物。

本篇只回答四件事：服务端组件是什么、服务端与客户端组件怎么划边界、Suspense 与流式渲染怎么用、Server Actions 怎么替代接口调用。数据在双端的共享与序列化详见本主题第 12 篇 SSR 应用的鉴权、状态与安全。

### 服务端组件是什么

本节确立组件模型的根本变化：组件不再只有「在哪里渲染」一个维度，而是分成两类、只在各自允许的位置执行。

#### 服务端组件的定义

**服务端组件**：是只在服务端求值的组件，其代码与依赖不进入浏览器包，输出的是可被客户端 React 还原的渲染描述。

- 运行位置：仅在服务端执行，可以访问数据库、文件系统与私有环境变量。
- 产物：不打包进客户端，因此对客户端包体积没有贡献。
- 声明方式：在 App Router 中组件默认即为服务端组件，不需要额外指令。
- 能力限制：不能使用 useState、useEffect，也不能访问 window 等浏览器 API。

```tsx
// app/posts/page.tsx：默认即为服务端组件
async function getPosts() {
  const res = await fetch("https://api.example.com/posts", { cache: "no-store" });
  return res.json();
}

export default async function PostsPage() {
  const posts = await getPosts();
  return (
    <ul>
      {posts.map((post: { id: number; title: string }) => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  );
}
```

服务端组件可以直接是 async 函数，await 的结果参与服务端渲染，不需要加载态分支，这一点在第 8 篇已经反复出现。

> 服务端组件不是「在服务端渲染的普通组件」：它的代码根本不发送给浏览器，这是它与同构组件最本质的差别。

**速记**：服务端组件只在服务端执行，代码不进客户端包，在 App Router 中默认即为该形态。



#### 与同构渲染的区别

**区别**：在于组件代码是否会被发送到浏览器并在浏览器中再次执行一遍。

- 同构渲染：同一份组件代码在服务端与浏览器各执行一次，浏览器侧靠水合接管（详见本主题第 4 篇 同构渲染原理与第 5 篇 水合机制与常见问题）。
- 服务端组件：只在服务端执行，浏览器收到的是渲染结果描述，不再执行其代码。
- 可组合：一棵组件树可以同时包含两类组件，边界由指令划分。
- 收益：服务端组件的依赖（如数据库驱动、内部工具库）不会泄露到客户端包。

```tsx
// 同一个页面里，服务端组件直接查库，客户端组件负责交互
import { LikeButton } from "@/components/LikeButton";

export default async function ArticlePage() {
  const article = { id: 1, title: "服务端组件", likes: 12 };
  return (
    <article>
      <h1>{article.title}</h1>
      <LikeButton initialLikes={article.likes} />
    </article>
  );
}
```

> [!NOTE]
> **提醒内容**：水合只发生在客户端组件及其边界内的 DOM 上，服务端组件不参与水合，因此也不会出现水合不匹配的问题。

**速记**：同构组件在两端各跑一次，服务端组件只跑服务端，二者可在同一棵树内组合。



#### 跨边界的传递规则

**传递规则**：指服务端组件向客户端组件传值时的约束，传递的值必须可被序列化，函数与类实例通常不可传。

- 可传：字符串、数字、布尔值、数组、普通对象、日期与 Promise。
- 不可传：普通函数、类实例、DOM 节点以及带方法的对象。
- 例外：以服务端指令声明的服务端函数可以作为属性传下去，它是引用而不是普通函数。
- 设计影响：组件接口按「可序列化数据」建模，避免在边界上传复杂对象。

```tsx
// 传普通数据可以，传函数会报错
import { LikeButton } from "@/components/LikeButton";

export default function ArticleCard() {
  return <LikeButton initialLikes={3} />;
  // <LikeButton onLike={() => console.log("liked")} /> // 报错：函数不可序列化
}
```

> [!WARNING]
> **警告内容**：把不可序列化的值当作属性跨边界传递会在运行时报错，边界两侧的数据结构需要在设计阶段就对齐。

**速记**：跨边界的属性必须可序列化，函数与类实例默认不可传。



### 服务端与客户端组件边界

本节说明两类组件如何分界、如何组合：边界划得好不好，直接决定客户端包的大小。

#### 客户端组件的声明

**客户端组件（Client Component）**：是需要在浏览器中执行、可以使用状态与副作用的组件，在文件顶部用双引号包裹的 use client 指令标记。

- 声明位置：文件第一行写指令，该文件导出的所有组件都成为客户端组件。
- 触发条件：需要状态、副作用、事件处理、浏览器 API 或仅支持浏览器的第三方库时使用。
- 代价：代码与依赖会进入客户端包，包体积随之增加。
- 粒度：指令作用于整个文件，宜把客户端逻辑收在叶子组件，不要写在根布局。

```tsx
"use client";

import { useState } from "react";

export function Counter({ initial }: { initial: number }) {
  const [count, setCount] = useState(initial);
  return <button onClick={() => setCount(count + 1)}>计数 {count}</button>;
}
```

指令必须位于文件顶部所有语句之前，写在其他导入之后会被当作普通字符串而失效。

> 一个文件不能既导出服务端组件又导出客户端组件，需要两类时拆成两个文件。

**速记**：use client 写在文件首行，需要状态、副作用与浏览器能力时使用，粒度收到叶子。



#### 边界与组合模式

**边界**：是服务端组件与客户端组件之间的分界线，跨过边界的属性要可序列化，边界内侧的组件继承外侧的运行位置。

- 向下继承：客户端组件引入的子组件也属于客户端组件，不需要重复声明。
- 向上组合：服务端组件可以把子组件作为 children 传给客户端组件，从而在客户端外壳内嵌套服务端内容。
- 位置选择：把边界尽量下移到需要交互的最小单元，减少进入客户端包的代码。
- 上下文限制：客户端上下文只能在客户端组件侧提供，服务端组件无法读取。

```tsx
"use client";

import { useState } from "react";

// 客户端组件通过 children 接收服务端内容，自身只负责交互外壳
export function Tabs({ children }: { children: React.ReactNode }) {
  const [activeTab, setActiveTab] = useState("latest");

  return (
    <section>
      <button onClick={() => setActiveTab("hot")}>热门</button>
      <p>当前：{activeTab}</p>
      {children}
    </section>
  );
}
```

```tsx
// 服务端组件把内容塞进客户端外壳，内容本身仍在服务端渲染
import { Tabs } from "@/components/Tabs";
import { PostTable } from "@/components/PostTable";

export default function PostPanel() {
  return (
    <Tabs>
      <PostTable />
    </Tabs>
  );
}
```

> children 是跨边界传递服务端内容的常用入口：客户端组件负责交互外壳，服务端组件负责内容填充。

**速记**：边界内侧继承运行位置，客户端可用 children 包裹服务端内容，边界宜下移。



#### 常见越界错误

**越界错误**：是把只能在某一侧使用的写法放到另一侧导致的报错，多发生在组件归属判断失误时。

- 服务端用了客户端能力：未声明指令的文件里调用 useState 或访问 window 会报错。
- 客户端读了服务端专属：客户端组件里导入服务端请求头工具或数据库驱动会报错。
- 传入函数：把事件处理函数从服务端传向客户端会因不可序列化而失败。
- 误判继承：以为某个子组件仍是服务端组件，实际已被父级的客户端边界纳入。

```text
// 典型报错：useState 只在客户端组件中可用
Error: useState only works in a Client Component.
Add the "use client" directive to the file that uses it.
```

排查顺序是先看报错指向的文件，再看它的父级链路上最近的一个客户端边界，据此决定是把该组件下移还是给它补上指令。

> [!CAUTION]
> **注意内容**：不要为了消除报错就给根布局加 use client，这会把整棵组件树拉进客户端包，直接失去服务端组件的收益。

**速记**：越界错误源于组件归属判断失误，按报错定位边界文件而不是全局加指令。



### Suspense 与流式渲染

本节说明「等待」如何被拆开：把整页等待换成按区域、按块到达，是服务端渲染在观感上的关键改进。

#### Suspense 与回退界面

**Suspense**：是 React 提供的边界组件，包裹可能延后的内容并在等待期间展示 fallback，等待结束后替换为真实内容。

- 属性：fallback 指定等待期间展示的界面，children 是被包裹的内容。
- 触发条件：子树中尚未完成的异步渲染会让该边界挂起。
- 颗粒度：多个边界并存时谁先完成谁先显示，互不阻塞。
- 可包裹内容：服务端组件与客户端组件都可以作为它的子节点。

```tsx
import { Suspense } from "react";
import { SlowStats } from "@/components/SlowStats";

export default function DashboardPage() {
  return (
    <main>
      <h1>数据概览</h1>
      <Suspense fallback={<p>统计加载中…</p>}>
        <SlowStats />
      </Suspense>
    </main>
  );
}
```

边界的划分依据是「数据可独立到达」：能各自完成的区域分成不同边界，串行依赖的内容放在同一个边界内。

> Suspense 把等待从整页级别下推到一个区域，页面骨架可以先到达，慢的部分随后补齐。

**速记**：Suspense 用 fallback 承接等待期，边界内挂起不影响边界外的内容。



#### 流式渲染的过程

**流式渲染（streaming rendering）**：是服务端把 HTML 分块持续发送给浏览器的方式，浏览器边接收边渲染，不必等整页生成完毕。

- 分块：已就绪的部分先发送，挂起的部分在其完成后继续补发。
- 顺序：文档顺序保持不变，晚到的片段插入到预留位置。
- 收益：首字节时间与可交互时间提前，慢数据不再拖住整页。
- 前提：需要配合 Suspense 边界与流式响应，框架在支持的运行时下默认启用。

```tsx
import { Suspense } from "react";
import { ArticleHeader } from "@/components/ArticleHeader";
import { CommentList } from "@/components/CommentList";

export default function ArticlePage() {
  return (
    <main>
      <ArticleHeader />
      <Suspense fallback={<p>评论加载中…</p>}>
        <CommentList />
      </Suspense>
    </main>
  );
}
```

- 文档头与前缀先到：浏览器可以提前解析样式与脚本，减少白屏时间。
- 片段插入：后到的 HTML 直接落到预留位置，不需要客户端重新渲染整页。

> 流式渲染把「整页等待」换成「分块到达」，它依赖 Suspense 划分边界，两者需要配合使用。

**速记**：流式渲染分块发送 HTML，未就绪片段由 Suspense 占位并随后补入。



#### 路由级流式与加载界面

**路由级流式**：是在路由切换时由约定文件提供等待界面，不必为每个页面手写 Suspense。

- loading 文件：在路由段放置 loading 文件，框架自动用它包裹该段页面作为回退。
- 作用范围：只影响该段及其下属路由，父级布局不受影响。
- 与 Suspense 的关系：loading 是框架基于 Suspense 提供的约定写法。
- 选择依据：整段路由一起等待用 loading 文件，页面内部局部慢用显式 Suspense。

```tsx
// app/blog/loading.tsx
export default function Loading() {
  return <p>博客列表加载中…</p>;
}
```

> [!TIP]
> **建议内容**：把加载界面的结构与真实内容的骨架对齐，可以减少内容到达时的布局跳动。

**速记**：loading 文件为路由段自动提供 Suspense 回退，局部等待仍用显式 Suspense。



### Server Actions

本节说明写操作的调用方式：从「先建接口再发请求」变成「直接调用服务端函数」。

#### Server Actions 是什么

**Server Actions**：是在服务端执行、可由客户端触发的函数，用服务端指令声明，用于替代为简单写操作额外搭建接口端点的做法。

- 声明方式：文件顶部写服务端指令时该文件导出的函数都是服务端函数，也可只标注单个函数。
- 调用方式：可以直接赋给表单的 action 属性，也可以在客户端组件的过渡中调用。
- 参数与返回值：传入的参数会被序列化后发给服务端，返回值同理（序列化规则详见本主题第 12 篇）。
- 安全前提：函数体内必须重新校验身份与输入，不能依赖客户端传来的判断结果。

```tsx
// app/actions.ts
"use server";

import { revalidatePath } from "next/cache";

export async function createTodo(formData: FormData) {
  const title = String(formData.get("title") ?? "");
  if (!title) return;
  await fetch("https://api.example.com/todos", {
    method: "POST",
    body: JSON.stringify({ title }),
  });
  revalidatePath("/todos");
}
```

服务端函数与普通接口端点的差别只在调用形式：前者由框架生成内部调用通道，鉴权与校验仍需自己写。

> Server Actions 省掉的是「为一次写操作新建接口」的样板代码，并不改变服务端仍需鉴权与校验的事实。

**速记**：Server Actions 用服务端指令声明，客户端可直接调用，省去写操作接口的样板。



#### 表单提交与状态处理

**表单提交**：是把 Server Action 挂到表单的 action 上，由框架接管提交过程，并用钩子读取结果状态。

- 基础用法：把服务端函数直接赋给表单的 action 属性。
- 提交状态：useFormStatus 在子组件中读取提交中状态，用于禁用按钮。
- 返回结果：useActionState 管理服务端函数返回的结果与错误信息。
- 渐进增强：表单在客户端脚本尚未加载时仍可提交，脚本到达后获得更顺滑的体验。

```tsx
"use client";

import { useActionState } from "react";
import { createTodo } from "@/app/actions";

export function TodoForm() {
  const [message, formAction] = useActionState(async (_prev: string, formData: FormData) => {
    await createTodo(formData);
    return "已提交";
  }, "");

  return (
    <form action={formAction}>
      <input name="title" />
      <button type="submit">新增</button>
      <p>{message}</p>
    </form>
  );
}
```

- 校验分层：浏览器侧只做即时反馈，真正的校验在服务端函数内重做一遍。
- 错误呈现：返回的提示信息由状态钩子带回界面，不需要额外的全局弹窗方案。

> [!IMPORTANT]
> **重要内容**：服务端函数与客户端组件之间的参数和返回值必须可序列化，复杂对象要在边界处先转成普通数据。

**速记**：action 直接挂到表单，useFormStatus 读提交状态，useActionState 管返回结果。



#### 写入后的数据刷新

**写入后的刷新**：是在 Server Action 修改数据后让相关缓存失效，使页面展示最新结果。

- 路径失效：调用 revalidatePath 让指定路径的缓存失效。
- 标签失效：调用 revalidateTag 让带同一标签的数据缓存失效。
- 主动刷新：在客户端调用 router.refresh 重新拉取当前路由的服务端数据。
- 顺序：先完成写入与失效，再让界面读取，避免新旧数据混在同一屏里。

```tsx
"use server";

import { revalidatePath } from "next/cache";

export async function deletePost(formData: FormData) {
  const id = String(formData.get("id"));
  await fetch("https://api.example.com/posts/" + id, { method: "DELETE" });
  revalidatePath("/posts");
}
```

```tsx
"use client";

import { useRouter } from "next/navigation";

export function RefreshButton() {
  const router = useRouter();
  return <button onClick={() => router.refresh()}>刷新数据</button>;
}
```

> 写操作与读缓存是一对：只写不失效，用户会误判为保存失败；只失效不写，界面则会不断回源。

**速记**：写入完成后立刻失效缓存，用 revalidatePath 或 revalidateTag，再让界面重新读取。
