## 小程序开发：页面、组件与 API

**小程序开发**：是在宿主给定的模板、样式、配置与逻辑四类文件之上，用宿主提供的组件描述界面、用宿主提供的接口调用能力的开发方式。本篇以微信小程序为具体例子，回答四件事：页面如何组织与配置、有哪些常用内置组件、常用接口如何调用、分包如何声明与按需加载。

本篇讲原生写法的页面、组件与接口调用；运行机制与双线程模型详见本主题第 14 篇 小程序基础：双线程模型与运行机制，登录、支付与开放能力详见本主题第 16 篇 小程序进阶：登录、支付与开放能力。

### 页面配置与结构

**页面**：是小程序的基本组成单位，由结构、样式、逻辑与配置四类文件共同描述，四类文件同名同目录。

#### 页面四件套文件

**页面四件套文件**：是描述一个页面所需的四类文件，分别承担结构、样式、逻辑与配置职责。

- 结构文件：扩展名为 wxml，用宿主模板语法描述界面骨架。
- 样式文件：扩展名为 wxss，写法接近 CSS，并补充了自适应单位。
- 逻辑文件：扩展名为 js，用页面配置对象注册数据与事件处理函数。
- 配置文件：扩展名为 json，声明该页面的窗口表现与所用组件。
- 组织约定：四类文件放在同名目录下且文件名一致，页面在全局配置中登记后才可访问。

```text
页面目录结构

pages/counter/
  counter.wxml    结构
  counter.wxss    样式
  counter.js      逻辑
  counter.json    页面配置
app.json          全局配置，登记页面路径
```

> 逻辑文件也可以用 TypeScript 编写，由开发工具在构建阶段转译，文件名与模板保持一致。

**速记**：一个页面等于结构、样式、逻辑、配置四件套，同名同目录并在全局登记。



#### 页面配置项与窗口表现

**页面配置项**：是写在页面配置文件中的键值对，用于覆盖全局窗口表现与该页面的组件引用。

- 标题与外观：可设置导航栏标题、背景色与下拉刷新开关。
- 组件引用：通过 usingComponents 声明该页面可用的自定义组件及其路径。
- 覆盖关系：页面级配置覆盖全局同名配置，未设置的项沿用全局值。
- 限制：部分全局配置如页面登记清单只在全局配置中生效，不能写在页面配置里。

```json
{
  "navigationBarTitleText": "计数器",
  "enablePullDownRefresh": true,
  "backgroundTextStyle": "dark",
  "usingComponents": {}
}
```

> 配置只写与全局不同的项即可，重复声明全部字段会让配置难以维护。

**速记**：页面配置覆盖全局窗口表现，并用 usingComponents 声明可用组件。



#### 数据绑定语法

**数据绑定**：是把逻辑层页面数据映射到模板中的写法，用双大括号把表达式嵌入结构文件。

- 文本绑定：把数据插入文本节点，数据变化时框架自动重渲染。
- 属性绑定：把数据写入组件属性，属性值为布尔或数字时可省略引号。
- 列表渲染：用 wx:for 遍历数组，配 wx:key 指定唯一标识以复用节点。
- 条件渲染：用 wx:if 与 wx:else 控制节点是否创建，wx:hidden 只控制显示。
- 表达式限制：模板内只支持简单表达式，不能调用自定义函数。

```html
<view class="page">
  <view class="title">{{title}}</view>
  <view class="count">当前计数：{{count}}</view>
  <view wx:if="{{count > 0}}">已开始计数</view>
  <view wx:for="{{records}}" wx:key="id">{{index}} - {{item.name}}</view>
  <button bindtap="onAdd">加一</button>
</view>
```

> 模板内的表达式保持简单：需要计算的内容应在逻辑层算好再放进页面数据。

**速记**：双大括号把页面数据映射到模板，列表与条件渲染由 wx:for、wx:if 控制。



#### 事件绑定与事件对象

**事件绑定**：是用以 bind 开头或 catch 开头的属性，把视图层的用户操作关联到逻辑层函数。

- bind 与 catch：bind 允许事件继续冒泡，catch 阻止冒泡。
- 事件对象：处理函数接收事件对象，包含事件类型、目标节点与附加数据。
- 附加数据：用 data 开头的属性写到节点上，在处理函数中从数据集里读取。
- 常见事件：点击、输入、滚动、触摸等，事件名由宿主定义，不能自定义事件类型。

```html
<view class="item" bindtap="onTapItem" data-id="{{item.id}}" data-index="{{index}}">
  点击查看详情
</view>
```

```js
Page({
  data: {
    list: [{ id: 1, name: "首条记录" }],
  },
  onTapItem(event) {
    // event.currentTarget.dataset 读取节点上 data 开头的属性
    const { id, index } = event.currentTarget.dataset;
    console.log(id, index);
  },
});
```

> [!NOTE]
> **提醒内容**：事件绑定的写法与 Web 不同，属性值写的是处理函数的名称字符串，不是函数调用，也不是内联表达式。

**速记**：事件用 bind 或 catch 绑定函数名，附加数据经数据集从事件对象读取。



### 常用内置组件

**内置组件**：是宿主提供的、可直接在结构文件中使用的组件集合，覆盖视图、表单、媒体与开放能力四类。

#### 视图容器与基础内容

**视图容器**：是承载布局与内容的容器类组件。**基础内容组件**：是展示文本与图片这类基础素材的组件。

- view：通用容器，相当于布局用的块级盒子，支持 flex 布局。
- text：文本节点，只有它能被长按选中，内部可嵌套文本片段。
- image：图片组件，通过 mode 属性决定裁剪与缩放方式。
- block：不被渲染的包装节点，只用于承载列表与条件指令。

```html
<view class="card">
  <text class="label">封面</text>
  <image class="cover" src="{{coverUrl}}" mode="aspectFill" />
</view>
```

> 组件不是 HTML 标签的别名，其属性与事件都由宿主定义，Web 上的属性名不能直接套用。

**速记**：view 负责布局、text 负责文本、image 负责图片，block 只承载指令。



#### 样式写法与自适应单位

**样式文件**：是用接近 CSS 的语法描述组件外观的文件。**自适应单位 rpx**：是按屏幕宽度等分计算的相对单位，与设备像素无关。

- 选择器：支持类选择器、元素选择器与部分组合写法，能力小于完整 CSS。
- 单位选择：与屏幕宽度相关且需要等比缩放的尺寸用 rpx，字号与固定像素用 px。
- 作用域：页面样式默认只作用于自身，组件样式需要显式声明是否受外部影响。
- 布局：flex 布局是主要排版手段，栅格与多列布局需要自行实现。

```css
.page {
  padding: 24rpx;
}

.title {
  font-size: 36rpx;
  font-weight: 600;
}

.cover {
  width: 100%;
  height: 320rpx;
}
```

> 单位选择与屏幕适配的完整方案详见 前端/CSS 主题与本主题第 20 篇 多端适配：布局、样式与平台差异。

**速记**：样式用类选择器组织，等比尺寸用 rpx，字号与固定间距用 px。



#### 表单组件与输入处理

**表单组件**：是采集用户输入的组件，输入值与交互结果通过事件回传到逻辑层。

- input：单行输入框，用 bindinput 获取每次输入的当前值。
- textarea：多行输入框，用于较长文本，支持字数限制。
- button：按钮组件，可用 type 与 open-type 控制样式与开放能力。
- picker：从列表或日期中选择，选择结果通过事件对象的结果字段回传。
- form：表单容器，可一次性收集内部带名字的输入组件取值。

```html
<view class="search">
  <input value="{{keyword}}" placeholder="输入关键字" bindinput="onInput" />
  <button type="primary" size="mini" bindtap="onSearch">搜索</button>
</view>

<picker mode="date" value="{{date}}" bindchange="onDateChange">
  <view>当前日期：{{date}}</view>
</picker>
```

> 输入类组件不受控：输入框内容默认由组件自身维护，回写页面数据时需要判断更新方向，避免光标跳动。

**速记**：输入用 bindinput 取值、选择用 picker 回传结果、批量收集用 form。



#### 列表与滚动容器

**滚动容器**：是自带滚动能力的组件，用于承载超过一屏的内容。**列表渲染**：是用 wx:for 把数组展开成节点序列的写法。

- scroll-view：可滚动的容器，需要给定尺寸，横向滚动需显式指定方向。
- 滚动事件：bindscroll、bindscrolltolower 用于监听滚动位置与触底。
- 长列表：节点数量过大时渲染开销明显，常用分页加载与虚拟列表控制节点数。
- 上拉加载：触底事件触发后追加下一页数据，配合加载状态避免重复请求。

```html
<scroll-view scroll-y class="list" bindscrolltolower="onReachBottom">
  <view class="item" wx:for="{{list}}" wx:key="id">{{item.name}}</view>
</scroll-view>
```

> [!CAUTION]
> **注意内容**：滚动容器必须在样式上给定确定高度，否则容器高度会随内容撑开，滚动不会生效。

**速记**：滚动容器要有确定高度，触底事件用于分页追加数据。



#### 媒体与开放能力组件

**媒体组件**：是播放音视频、展示轮播等与内容呈现相关的组件。**开放能力组件**：是把登录、分享、客服等宿主能力直接以组件形式暴露出来的组件。

- swiper：轮播容器，配合 swiper-item 使用，可设置自动播放与循环。
- video 与 audio：音视频播放，播放状态通过事件回传。
- open-type 能力：按钮等组件可通过 open-type 直接触发宿主能力，无需调用接口。
- 能力约束：开放能力组件触发的结果由宿主处理，回调中只能拿到宿主给出的结果对象。

```html
<swiper autoplay circular interval="3000" class="banner">
  <swiper-item wx:for="{{banners}}" wx:key="id">
    <image src="{{item.url}}" mode="widthFix" />
  </swiper-item>
</swiper>
```

> 涉及用户身份的开放能力会在第 16 篇展开，本篇只说明其以组件形式暴露这一形态。

**速记**：媒体组件负责内容呈现，开放能力组件把宿主能力直接挂到界面上。



### 常用 API 与能力调用

**宿主接口**：是挂在全局对象上、供逻辑层调用的函数集合，按能力分为路由、网络、存储、设备等类别。

#### API 的调用风格与回调约定

**宿主接口的调用风格**：是以配置对象为唯一入参，把成功、失败与完成三种结果分别交给对应回调的调用方式。

- 单一入参：接口接收一个配置对象，参数名写在对象里，不使用位置参数。
- 三类回调：success 处理成功结果，fail 处理失败，complete 无论成败都执行。
- 结果对象：成功回调收到结果对象，通常含状态码与数据字段。
- Promise 风格：较新基础库中，不传回调时部分接口返回 Promise，可用链式写法处理结果。
- 错误处理：失败回调中的信息以错误描述为主，业务错误要由状态码与数据自行判断。

```js
Page({
  data: {
    list: [],
  },
  fetchList() {
    wx.request({
      url: "https://api.example.com/articles",
      method: "GET",
      data: { page: 1 },
      success: (res) => {
        // res.statusCode 为状态码，res.data 为响应体
        this.setData({ list: res.data.list });
      },
      fail: (error) => {
        // 网络不可用、超时等失败
        console.log(error.errMsg);
      },
      complete: () => {
        // 加载状态复位
      },
    });
  },
});
```

> 三类回调的职责要分清：success 只处理成功，fail 只处理失败，收尾逻辑统一放 complete。

**速记**：接口以配置对象为唯一入参，结果分 success、fail、complete 三类回调。



#### 路由与界面交互

**路由接口**：是控制页面跳转与返回的接口集合，每个接口接收一个配置对象，含目标地址与跳转结果回调。

- 打开新页面：navigateTo 保留当前页面并压入新页面，页面栈有层数上限。
- 替换当前页面：redirectTo 关闭当前页面再打开新页面，不增加页面栈深度。
- 切换标签页：switchTab 只能跳到标签页，跳转后不保留原页面的返回关系。
- 返回：navigateBack 按层数回退，接收 delta 参数指定回退层数。
- 反馈类接口：提示、加载与确认弹窗用于交互反馈，均提供成功与失败回调。

```js
wx.navigateTo({
  url: "/pages/detail/detail?id=42",
  success: () => {
    // 成功压入新页面
  },
});

wx.navigateBack({ delta: 1 });

wx.showToast({ title: "已保存", icon: "success" });
```

> 路由参数写在地址的查询串里，由目标页面的加载回调读取；参数值需要自行做编码与解码。

**速记**：navigateTo 压栈、redirectTo 替换、switchTab 跳标签页、navigateBack 回退。



#### 网络请求

**网络请求接口**：是发起数据请求的接口，接收地址、方法、数据、请求头与响应类型等配置。

- 必填项：请求地址为必填，其余项有默认值，方法默认按 GET 处理。
- 请求参数：GET 参数经 data 字段传入并由框架拼接到地址，POST 参数按内容类型编码。
- 合法域名：请求地址必须在宿主平台登记过，否则在真机上会被拦截。
- 超时与并发：可设置超时时间，并发请求数量存在上限，需要控制批量请求规模。
- 上传与下载：文件上传与下载使用独立接口，支持进度事件。

```js
wx.request({
  url: "https://api.example.com/orders",
  method: "POST",
  header: { "content-type": "application/json" },
  data: { itemId: 7, count: 2 },
  timeout: 5000,
  success: (res) => {
    if (res.statusCode === 200) {
      // 业务成功
    }
  },
});
```

> [!IMPORTANT]
> **重要内容**：请求地址必须在宿主平台登记为合法域名，开发工具中可以临时关闭校验，但真机环境一定会拦截未登记的地址。

**速记**：请求接口以配置对象传参，地址必须先在宿主平台登记为合法域名。



#### 数据缓存与设备信息

**数据缓存接口**：是在本地持久化少量键值数据的接口，分同步与异步两套写法。**设备信息接口**：是读取窗口尺寸、安全区域与系统信息的接口。

- 同步写法：setStorageSync、getStorageSync、removeStorageSync 直接返回结果，写法最简。
- 异步写法：setStorage、getStorage 通过回调返回结果，适合对阻塞敏感的场合。
- 容量限制：本地缓存总量有上限，适合存会话标识与少量配置，不适合存大数据。
- 窗口信息：可获取窗口宽高与安全区域，用于适配刘海屏与底部操作区。
- 兼容提示：较新基础库把系统信息拆分为窗口、设备与应用信息等多个接口，旧接口逐步不再推荐使用。

```js
wx.setStorageSync("sessionKey", "session-token");
const sessionKey = wx.getStorageSync("sessionKey");
wx.removeStorageSync("sessionKey");

const windowInfo = wx.getSystemInfoSync();
// windowInfo.windowWidth、windowInfo.windowHeight、windowInfo.safeArea
```

> 缓存里不要放敏感凭据的明文副本，涉及会话标识的最小化存储与过期处理属于第 16 篇的范围。

**速记**：键值数据用同步或异步缓存接口存取，尺寸与安全区从设备信息接口读取。



### 分包与按需加载

**分包与按需加载**：是把代码按业务域拆成独立单元、只在需要时下载与注入的组织方式，用于控制启动开销与体积上限。

#### 分包的声明方式

**分包的声明方式**：是在全局配置中列出分包根目录与该分包包含的页面路径，页面路径相对于分包根目录书写。

- 声明位置：分包与预下载规则都写在全局配置里，页面配置中无法声明。
- 路径写法：配置里写相对分包根目录的路径，跳转时写包含根目录的完整路径。
- 标签页限制：标签页页面必须放在主包，不能放进分包。
- 独立分包：可声明为不依赖主包运行的分包，用于活动页等独立入口。

```json
{
  "pages": ["pages/index/index"],
  "subPackages": [
    {
      "root": "packageOrder",
      "pages": ["pages/list/list", "pages/detail/detail"]
    },
    {
      "root": "packageActivity",
      "pages": ["pages/index/index"],
      "independent": true
    }
  ]
}
```

> 分包的划分单位是业务域而不是技术层，把同一业务的页面、组件与资源放在同一分包内最利于维护。

**速记**：分包在全局配置里声明根目录与页面，跳转路径要带上根目录。



#### 主包与分包的引用规则

**主包与分包的引用规则**：是代码与资源在两个层级之间的依赖方向约定，方向是单向的。

- 允许：分包引用主包中的公共模块、组件与工具函数。
- 禁止：主包引用分包中的任何内容，主包在启动时无法保证分包已下载。
- 禁止：分包之间互相引用，不同分包按需下载，加载顺序不可预期。
- 处理方式：多个分包共用的代码抽到主包，或抽成一个独立的公共分包供各分包引用。
- 资源引用：样式与图片等静态资源同样受这条规则约束。

```text
依赖方向

主包  --禁止-->  分包
分包  --禁止-->  其他分包
分包  --允许-->  主包

共用代码的正确归处：主包，或独立的公共分包
```

> [!WARNING]
> **警告内容**：把公共组件放在某个分包里再让其他分包引用，在部分场景下可以编译通过，但运行时会出现模块缺失，必须按依赖方向重新组织。

**速记**：依赖只能由分包指向主包，分包之间与主包指向分包都被禁止。



#### 分包预下载

**分包预下载**：是在指定页面进入时提前下载后续可能用到的分包，把下载耗时提前到用户浏览期间。

- 触发时机：用户进入配置中指定的页面后即开始下载，可选择仅无线网络或任意网络。
- 配置内容：为某个页面指定需要预下载的分包列表。
- 收益：跳转到分包页面时无需再等待下载，跳转更顺畅。
- 代价：预下载占用网络与存储，配置过多会消耗用户流量。
- 取舍标准：跳转概率高、体积适中的分包才值得预下载。

```json
{
  "preloadRule": {
    "pages/index/index": {
      "network": "wifi",
      "packages": ["packageOrder"]
    }
  }
}
```

> 预下载解决的是跳转时的等待，不改变代码包体积，仍需先满足体积约束才能上传。

**速记**：预下载按页面配置，把分包下载提前到浏览期间，按跳转概率取舍。



#### 分包化改造的实践要点

**分包化改造**：是把已有小程序从单包结构迁移为分包结构的过程，主要工作是划分业务域与迁移公共代码。

- 先分类：把页面按业务域与访问频次分组，首屏必需页面留在主包。
- 再迁移：把非首屏页面连同其专属组件与资源整体移入分包。
- 后提公共：把跨组使用的组件与工具函数上移到主包。
- 改路径：跳转地址改为带根目录的完整路径，配置中的页面登记同步更新。
- 控体积：改造完成后重新核对主包体积，确认满足上传要求。

```text
改造顺序

分类页面  --> 迁移非首屏页面到分包
          --> 上移公共代码到主包
          --> 更新跳转路径与登记清单
          --> 校验主包体积
```

> 改造的风险集中在路径与公共代码两处，先在测试环境中完整走一遍跳转链路再发布。

**速记**：分包化改造按分类、迁移、提公共、改路径、控体积五步推进。
