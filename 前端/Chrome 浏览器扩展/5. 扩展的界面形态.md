## 扩展的界面形态

### 工具栏图标与 chrome.action

chrome.action 是统一的工具栏操作接口，它在 Manifest V3 中合并了 MV2 的 browserAction 与 pageAction，负责图标、悬停标题、徽章与弹出窗口四项内容。

使用它需要在清单中声明 action 键；即使不声明，扩展在工具栏里仍有一个图标可供用户访问扩展菜单。

```json
{
  "action": {
    "default_icon": {
      "16": "images/icon-16.png",
      "32": "images/icon-32.png"
    },
    "default_title": "点击查看面板",
    "default_popup": "popup.html"
  }
}
```

图标必须指定 path 或 imageData 之一，二者都是「尺寸到值」的字典或单个值；标题与徽章没有清单默认值，只能由代码设置。常用方法与属性的签名如下：

- chrome.action.setIcon(details)：details 接受 path 或 imageData，以及可选的 tabId。imageData 可来自 OffscreenCanvas 的像素数据，用于动态生成图标。
- chrome.action.setTitle(details)：details 含 title 与可选 tabId，标题显示在悬停提示中，也是屏幕阅读器朗读的无障碍文本。
- chrome.action.setBadgeText(details) 与 chrome.action.setBadgeBackgroundColor(details)：details 分别含 text 与 color，都接受可选 tabId。
- chrome.action.setBadgeTextColor(details)：Chrome 110 起可用，不设置时自动取与背景对比的颜色。
- chrome.action.setPopup(details)：details 含 popup 与可选 tabId，传空字符串即取消弹出窗口。
- chrome.action.openPopup(options)：Chrome 127 起对普通扩展开放，options 为 OpenPopupOptions，含可选 windowId；Chrome 118 到 126 之间仅对按政策安装的扩展可用。
- chrome.action.enable(tabId?) 与 chrome.action.disable(tabId?)：只影响是否派发点击事件与弹出窗口，不改变图标是否存在。
- chrome.action.getUserSettings()：Chrome 91 起返回 UserSettings 对象，其 isOnToolbar 属性表示用户是否把图标固定到了工具栏。

对应事件有两个：chrome.action.onClicked 在图标被点击时触发，回调收到 tabs.Tab 对象；chrome.action.onUserSettingsChanged 自 Chrome 130 起在 isOnToolbar 变化时触发。

```js
chrome.action.onUserSettingsChanged.addListener(async (change) => {
  if (!change.isOnToolbar) return;
  await chrome.action.openPopup();
});
```

> [!NOTE]
> **提醒内容**：Chrome 153 起对部分用户实验「扩展图标默认固定到工具栏」这一行为。判断某个用户是否真的固定了图标，应调用 chrome.action.getUserSettings 读 isOnToolbar，不要假定安装后图标一定可见。



### 图标、标题与徽章

徽章是叠加在图标上的一小段文字，用于展示计数或状态，由文本与背景色两部分组成。空间有限，官方建议文本不超过 4 个字符，传空字符串即清除徽章。

```js
await chrome.action.setBadgeBackgroundColor({ color: '#1a73e8' });
await chrome.action.setBadgeText({ text: '3' });
await chrome.action.setTitle({ title: '未读 3 条' });
```

背景色与文字色都可写成四个 0 到 255 整数组成的 RGBA 数组，写成 CSS 颜色值同样有效。徽章宽度随字符数变化，超过四个字符会被裁剪，不适合直接展示大数字，应先做量级压缩。

图标格式有限制：打包扩展可以用 Blink 能渲染的栅格格式，包括 PNG、JPEG、BMP、ICO，不支持 SVG；未打包扩展只能用 PNG。图标按要求应为 16 个逻辑像素见方，Chrome 会按设备像素密度挑选最接近的尺寸再缩放。

> [!CAUTION]
> **注意内容**：chrome.action.setIcon 面向静态图片，不要为图标使用动画图片。需要动态图标时用 OffscreenCanvas 逐次生成像素数据并重新设置，而不是靠动画帧驱动。



### 弹出窗口的声明与语义

弹出窗口是该操作被点击时显示的 HTML 页面，由清单的 default_popup 指定，也可由 setPopup 在运行时改写。

```html
<!DOCTYPE html>
<html lang="zh-CN">
  <head>
    <meta charset="utf-8" />
    <title>快速面板</title>
    <style>
      html { min-width: 18em; min-height: 8em; }
    </style>
  </head>
  <body>
    <p id="summary"></p>
    <button id="refresh">刷新</button>
    <script src="popup.js"></script>
  </body>
</html>
```

尺寸限制是 25 乘 25 像素到 800 乘 600 像素之间，页面会随内容自动调整大小，给出固定最小尺寸能避免内容抽动。

弹出窗口的生命周期是「打开即加载、关闭即销毁」：每次打开都重新执行页面脚本，关闭后页面上下文连同其中所有变量一起消失。由此推出三条约束：界面状态不能存在页面内存里，需要跨次打开保留的值放 chrome.storage 或 chrome.storage.session；输入到一半的数据若不落盘，关闭即丢失；不要用弹出窗口承载持续运行的任务，因为它的定时器与监听器会随窗口一并消失。



### 点击事件与逐标签页状态

当操作声明了弹出窗口时，点击图标只打开窗口，不派发 chrome.action.onClicked。只有未声明弹出窗口或把弹出窗口清空后，点击事件才会到达监听器。

```js
chrome.action.onClicked.addListener(async (tab) => {
  await chrome.scripting.executeScript({
    target: { tabId: tab.id },
    files: ['content.js']
  });
  const { unread = 0 } = await chrome.storage.local.get('unread');
  await chrome.action.setBadgeText({
    text: unread > 99 ? '99+' : String(unread),
    tabId: tab.id
  });
});
```

所有设置方法都接受可选的 tabId，语义是「只在该标签页上生效」。省略 tabId 表示全局设置，标签页专属设置优先于全局设置，标签页关闭时专属设置自动重置。

读取当前值同样按标签页区分：getBadgeText、getTitle、getPopup、getBadgeBackgroundColor、getBadgeTextColor 都接收含可选 tabId 的 TabDetails 对象，省略时返回非标签页专属的值。



### 选项页面的两种形态

选项页面承载扩展的配置项，有两种声明方式，区别只在打开位置：

- options_page 直接给页面路径，用户选择「选项」时在新标签页中打开整页。
- options_ui 用 page 给路径，再用 open_in_tab 决定形态：设为 false 时嵌入扩展管理页的扩展详情中，设为 true 时新标签页打开。

```json
{
  "options_ui": {
    "page": "options.html",
    "open_in_tab": false
  }
}
```

嵌入形态与整页形态有四处行为差异：嵌入页面不在标签页里，因此不能用 Tabs API，与后台交互要用 runtime.sendMessage 或 runtime.connect；从嵌入页面发出的消息，发送者对象里不设置标签页字段，只设置来源网址字段；嵌入框按内容自动定尺寸，对随窗口大小自适应布局的页面可能找不到合适高度，应给出固定尺寸下限；用户可通过右键点击工具栏图标选择「选项」，或在扩展管理页详情里点击选项链接，或用 chrome.runtime.openOptionsPage 以代码打开。



### 侧边栏的注册与配置

侧边栏在浏览器窗口一侧承载与主内容并排的持久界面，Chrome 114 起可用，需要 sidePanel 权限。静态的默认页面在清单里声明，全局生效：

```json
{
  "side_panel": { "default_path": "sidepanel.html" },
  "permissions": ["sidePanel"]
}
```

按标签页启用或换页由 chrome.sidePanel.setOptions(options) 完成，options 为 PanelOptions，含可选的 tabId、path 与 enabled，省略 tabId 时设置的是默认行为。让点击工具栏图标直接打开侧边栏，则用 setPanelBehavior 设置 openPanelOnActionClick：

```js
chrome.tabs.onUpdated.addListener(async (tabId, info, tab) => {
  if (!tab.url) return;
  const { origin } = new URL(tab.url);
  await chrome.sidePanel.setOptions({
    tabId,
    path: 'sidepanel.html',
    enabled: origin === 'https://example.com'
  });
});

await chrome.sidePanel.setPanelBehavior({ openPanelOnActionClick: true });
```

其余方法的签名与版本：chrome.sidePanel.open(options) 自 Chrome 116 起可用，options 为 OpenOptions，必须给出 tabId 或 windowId 之一，且只能在响应用户手势时调用，例如点击图标、按快捷键、点上下文菜单或页面内按钮；getOptions(options) 接收含可选 tabId 的 GetPanelOptions 并返回当前 PanelOptions；getPanelBehavior() 返回当前 PanelBehavior；close(options) 自 Chrome 141 起可用；getLayout() 自 Chrome 140 起返回面板所在侧；onOpened 自 Chrome 141 起、onClosed 自 Chrome 142 起触发。

侧边栏是扩展页面，因此能调用全部扩展 API。切换标签页时若该标签页也启用了面板，面板保持打开；切到未启用的标签页时面板隐藏，切回后自动恢复。

> [!IMPORTANT]
> **重要内容**：chrome.sidePanel.open 必须由用户手势触发，页面加载后自动调用会被拒绝。需要「进入某站点自动展开侧边栏」的效果时，只能先打开面板再切换标签页，或在用户首次交互时打开，不能靠代码静默弹出。



### 开发者工具页面

开发者工具页面让扩展往 DevTools 里加面板与侧边栏窗格，由清单的 devtools_page 键声明，值是指向 HTML 页面的相对路径，例如写 devtools.html。这个 HTML 只用来加载脚本，真正的工作在它引入的 devtools.js 中完成。

面板与窗格由两个方法创建：chrome.devtools.panels.create(title, iconPath, pagePath, callback) 创建面板，回调收到 ExtensionPanel 对象；chrome.devtools.panels.elements.createSidebarPane(title, callback) 创建侧边栏窗格，窗格内容用 setPage、setObject 或 setExpression 三种方式写入。

可用的 API 分四类：devtools.panels 管理面板与窗格并可互相嵌入；devtools.inspectedWindow 读写被检查页面，其 tabId 属性常用来配合 scripting.executeScript 注入脚本；devtools.network 读取网络请求信息；devtools.recorder 与 devtools.performance 扩展对应面板。

两条边界必须记住：chrome.devtools 的成员只在 DevTools 窗口打开期间对窗口内加载的页面可用，内容脚本与其他扩展页面没有访问权限；Chrome 152 之前，声明了 devtools_page 的扩展其 browser 命名空间会被整体关闭，原因是为了兼容依赖 polyfill 包装 devtools 回调式 API 的旧扩展，该限制随 devtools 原生支持 Promise 而解除。



### 覆盖 Chrome 内置页面

chrome_url_overrides 用扩展页面替换 Chrome 的三个内置页面之一：

```json
{
  "chrome_url_overrides": {
    "newtab": "newtab.html"
  }
}
```

三个可覆盖的键与对应页面是：newtab 对应 chrome://newtab，bookmarks 对应 chrome://bookmarks，history 对应 chrome://history。一个扩展只能覆盖其中一个页面，不能同时声明多个。

几条实践建议：页面要足够轻，用户期待内置页面立即打开，应避免同步访问数据库资源，网络请求优先用 fetch；务必在页面里写标题，否则标签页标题会退化成网址；新标签页的键盘焦点初始在地址栏，不要假定焦点落在页面上；自建页面与 Chrome 默认页的样式差异要大，避免用户分不清。无痕窗口下扩展无法覆盖新标签页，incognito 设为 split 时其余覆盖页面仍按无痕上下文独立运行。



### 界面形态的选择判据

六种形态各有明确适用面，选择依据是「用户与它的交互时长」与「它是否需要感知当前页面」：

- 单次动作的触发按钮：用工具栏图标加弹出窗口，用户点开、操作、关闭在一屏之内完成。
- 需要与网页并排长期驻留的辅助界面：用侧边栏，它在切换标签页时可以保持打开。
- 低频的配置项：用选项页面，嵌入形态适合只有几个开关的情况，整页形态适合配置项较多的情况。
- 轻量的状态提示：用徽章配合悬停标题，不要为了一行状态另开一个界面。
- 面向开发者的调试信息：用开发者工具页面，它只在 DevTools 打开时加载，不占用户的日常界面。
- 替换高频入口页：用 chrome_url_overrides，但只覆盖确实想长期替换的那一个页面。

界面之间的数据同步统一走 chrome.storage 的 onChanged 事件或消息通道，不要让两个界面各自维护一份状态。
