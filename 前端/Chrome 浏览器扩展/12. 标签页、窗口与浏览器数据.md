## 标签页、窗口与浏览器数据

标签页与窗口 API 是扩展操作浏览器界面的入口，浏览器数据 API 是扩展读写用户既有资料的入口：前者围绕 chrome.tabs、chrome.windows 与 chrome.tabGroups，后者覆盖书签、历史记录、下载与会话恢复。

两类接口的权限模型方向相反。标签页 API 的多数方法无需任何权限即可调用，权限只决定字段可见性；浏览器数据 API 必须先声明权限，声明后用户会在安装确认页看到明确告警。

### 标签页 API 的权限底座

chrome.tabs 的多数功能不需要权限，创建标签页、重新加载、跳转到其它网址都可以直接调用。权限在这里的作用不是「能否调用方法」，而是「能否读到字段」。chrome.tabs 只能由 Service Worker 与扩展页面调用，内容脚本用不了，内容脚本要操作标签页必须发消息给扩展侧代劳。

#### 敏感字段与两种授权

Tab 对象上有四个字段受额外管控：url、pendingUrl、title、favIconUrl。只有扩展拥有 tabs 权限，或拥有覆盖该标签页网址的 host 权限时，这四个字段才会被填充，两种授权需要在清单的 permissions 与 host_permissions 两个数组里分别声明。

两条路径的覆盖面不同：tabs 权限对所有标签页生效，无论网址是什么；host 权限只让匹配的标签页暴露字段，但额外带来直接与这些标签页交互的能力，包括 scripting.executeScript、scripting.insertCSS、scripting.removeCSS 与 tabs.captureVisibleTab。其余字段始终可见，例如 id、index、windowId、active、pinned、incognito、status、discarded、autoDiscardable、groupId 与 sessionId；陆续补充的有 mutedInfo（Chrome 46 起）、lastAccessed（Chrome 121 起）、frozen（Chrome 132 起）与 splitViewId（Chrome 140 起）。

> [!IMPORTANT]
> **重要内容**：tabs 权限并不授予 chrome.tabs 命名空间的访问权，它授予的是标签页元数据的可见性，外加按网址过滤查询的能力。缺少它时方法照样可以调用，只是读到 undefined，问题会以「数据莫名其妙为空」的形式出现，而不是抛出权限错误。



#### activeTab 的临时授权

activeTab 是临时主机权限，在用户通过手势激活扩展时生效，手势包括点击扩展操作图标、按下已绑定的快捷键、选择上下文菜单项。生效范围是被激活的那一个标签页，并且只覆盖当前源：标签页一旦导航到其它源，授权立即失效。它带来的字段可见性与 host 权限相同，但不产生任何安装期权限警告。

```js
chrome.action.onClicked.addListener(async (tab) => {
  const [result] = await chrome.scripting.executeScript({
    target: { tabId: tab.id },
    func: () => document.title,
  });
  console.log('当前标题：', result.result);
});
```

这段代码只需要 activeTab 与 scripting 两项权限，无需为每个目标站点声明 host 权限；代价是授权不能跨标签页复用，也不能在用户没有手势的情况下使用。



### 查询、操作与标签页事件

chrome.tabs.query(queryInfo) 返回满足全部条件的 Tab 数组，queryInfo 为空对象时返回所有标签页。可用过滤字段按语义分四组：

```text
窗口位置类  currentWindow、lastFocusedWindow、windowId、windowType
状态类      active、highlighted、pinned、muted、audible、discarded、frozen、status
分组布局类  index、groupId、splitViewId
内容匹配类  url、title
```

新版本加入的过滤字段有 audible 与 muted（Chrome 45 起）、autoDiscardable 与 discarded（Chrome 54 起）、groupId（Chrome 88 起）、frozen（Chrome 132 起）与 splitViewId（Chrome 140 起）。url 可以是一个匹配模式或一组匹配模式，title 做模式匹配；两者都要求扩展具备 tabs 权限或对应的 host 权限。

> [!CAUTION]
> **注意内容**：url 过滤有两条容易踩空的规则：网址中的片段标识符不参与匹配；扩展若既没有 tabs 权限也没有对应 host 权限，url 与 title 两个过滤条件会被直接忽略。忽略时不报错也不返回空数组，而是返回比预期更多的标签页，因此依赖查询结果做批量关闭的逻辑必须再校验一遍字段，不能把过滤条件当成安全边界。

创建与更新都只改动显式给出的字段：chrome.tabs.create(createProperties) 的 url 必须是含协议的完整网址，缺省则打开新标签页，active 默认为 true，pinned 默认为 false，index 指定插入位置，openerTabId 声明来源标签页；chrome.tabs.update(tabId, updateProperties) 可改 active、autoDiscardable、highlighted、muted、openerTabId、pinned 与 url，不接受 JavaScript 协议网址，脚本执行应改走 scripting 命名空间，省略 tabId 时作用于当前窗口的活动标签页。

```js
const [activeTab] = await chrome.tabs.query({ active: true, lastFocusedWindow: true });
const tab = await chrome.tabs.create({ url: 'https://example.com/report', active: false });
await chrome.tabs.update(tab.id, { active: true });
await chrome.tabs.reload(tab.id, { bypassCache: true });
await chrome.tabs.remove(tab.id);
```

- **move 与 moveProperties**：批量方法接收 id 数组；chrome.tabs.move 的 moveProperties 含 index 与 windowId，index 传 -1 表示移到末尾，且标签页只能在类型为 normal 的窗口之间移动。
- **其余常用方法**：goBack 与 goForward（Chrome 72 起）按历史记录前后跳转；duplicate 复制标签页；discard（Chrome 54 起）把内容从内存卸载但保留标签，省略 tabId 时浏览器自行挑选最不重要的一个；highlight 按索引突出显示若干标签页；captureVisibleTab 截取当前活动标签页的可见区域，需要全网址 host 权限或 activeTab，每秒最多调用 2 次，上限由常量 MAX_CAPTURE_VISIBLE_TAB_CALLS_PER_SECOND 给出。
- **常量约定**：常量值为 -1 时表示「没有」——TAB_ID_NONE 表示没有标签页 id，TAB_INDEX_NONE 表示没有索引，SPLIT_VIEW_ID_NONE 表示不在分屏中。

事件覆盖创建、更新、激活、关闭与移动五类动作。onUpdated 的 changeInfo 只带发生变化的字段，常用的是 status、title、favIconUrl、pinned、mutedInfo、audible、discarded、autoDiscardable、frozen、groupId 与 splitViewId，其中 status 取 unloaded、loading 与 complete。

```js
chrome.tabs.onUpdated.addListener((tabId, changeInfo, tab) => {
  if (changeInfo.status === 'complete' && tab.url) {
    console.log(`标签页 ${tabId} 加载完成：${tab.url}`);
  }
});

chrome.tabs.onRemoved.addListener((tabId, removeInfo) => {
  if (!removeInfo.isWindowClosing) console.log(`标签页 ${tabId} 被关闭`);
});
```

> [!NOTE]
> **提醒内容**：onActivated 触发时 url 可能尚未写入，onCreated 触发时 url 与分组信息同样可能尚未设置，两者都不能用来判断网址。事件回调里的 tab 对象是快照而不是实时视图，需要保证数据新鲜时应在回调里用 id 重新调用 chrome.tabs.get。onMoved 只在窗口内移动时触发，跨窗口移动改为派发 onDetached 与 onAttached；onReplaced 在标签页被预渲染或即时跳转替换时触发，收到新增与移除的两个 id。



### 窗口与标签页分组

chrome.windows 的基础调用不需要权限，只有当返回的 Window 对象要携带 tabs 数组、并且要读其中敏感字段时，才依赖 tabs 权限。

```js
const windows = await chrome.windows.getAll({ populate: true, windowTypes: ['normal'] });
const tabCount = windows.reduce((total, item) => total + (item.tabs?.length ?? 0), 0);
await chrome.windows.update(windows[0].id, { state: 'maximized' });
```

- **几何与形态**：create 接受 left、top、width、height 控制几何形状；state 指定 normal、minimized、maximized 或 fullscreen，其中后三种不能与位置尺寸同时指定；url 可以是单个网址或网址数组；type 取 normal 或 popup。
- **查询**：查询用 get、getCurrent 与 getLastFocused；getAll 的 QueryOptions 中 windowTypes 缺省为只含 normal 与 popup。
- **常量**：WINDOW_ID_NONE 值为 -1，表示当前没有任何浏览器窗口；WINDOW_ID_CURRENT 值为 -2，表示执行调用代码所在的窗口，对 Service Worker 而言它回退到上一个有效窗口。
- **事件**：onCreated、onRemoved、onFocusChanged（全部窗口失焦时给出 WINDOW_ID_NONE）与 onBoundsChanged（Chrome 86 起）。

chrome.tabGroups 管理分组本身，权限为 tabGroups，Chrome 89 起可用；把标签页加入分组仍由 chrome.tabs.group 完成，查询哪些标签页在组内也仍由 chrome.tabs 完成。TabGroup 对象的字段有 id、collapsed、color、title、windowId 与 shared（Chrome 137 起，表示是否为共享分组），color 取 grey、blue、red、yellow、green、pink、purple、cyan 与 orange。

```js
const groupId = await chrome.tabs.group({ tabIds: [firstTab.id, secondTab.id] });
await chrome.tabGroups.update(groupId, { title: '待读', color: 'cyan', collapsed: false });
```

常量 TAB_GROUP_ID_NONE 值为 -1，查询时可用来筛选未分组标签页。get、query、update 与 move 自 Chrome 90 起可用，move 与 tabs.move 遵守同一约束：只能在类型为 normal 的窗口之间移动。事件有 onCreated、onUpdated、onMoved 与 onRemoved，其中 onMoved 只在窗口内生效，跨窗口移动表现为一处移除加另一处创建。



### 书签、历史记录、下载与会话恢复

这四个 API 读写的是用户长期积累的数据。权限一旦声明就会在安装确认页上逐条告知用户，属于会被用户认真审视的权限。

chrome.bookmarks 的权限为 bookmarks，数据模型是一棵树，节点由 BookmarkTreeNode 表示，字段有 id、parentId、index、url、title、dateAdded、dateGroupModified 与 children；dateLastUsed 自 Chrome 114 起提供，只对书签条目设置；folderType 与 syncing 自 Chrome 134 起提供，用于区分浏览器自建文件夹与账号同步状态。读取用 get、getChildren、getSubTree、getRecent 与 getTree，Chrome 90 起全部返回 Promise；search 接受字符串或对象，对象形式可同时约束 query、title 与 url，其中 title 与 url 是精确匹配。

```js
const [tree] = await chrome.bookmarks.getTree();
const bar = tree.children.find((node) => node.folderType === 'bookmarks-bar');
const folder = await chrome.bookmarks.create({ parentId: bar.id, title: '稍后阅读' });
await chrome.bookmarks.create({ parentId: folder.id, title: '示例文档', url: 'https://example.com/doc' });
```

写入用 create、update、move、remove 与 removeTree，update 目前只支持 title 与 url。根文件夹不能增删条目，书签栏与其他书签两个特殊文件夹也不能改名、移动或删除。写入频率限制已取消，MAX_WRITE_OPERATIONS_PER_HOUR 与 MAX_SUSTAINED_WRITE_OPERATIONS_PER_MINUTE 均已弃用。事件有 onCreated、onRemoved、onChanged、onMoved、onChildrenReordered、onImportBegan 与 onImportEnded；批量导入期间浏览器会连续派发大量 onCreated，重量级观察者应在 onImportBegan 后暂停处理，等 onImportEnded 再统一执行。

chrome.history 的权限为 history。HistoryItem 含 id、url、title、lastVisitTime、visitCount 与 typedCount；VisitItem 描述单次访问，含 visitId、visitTime、referringVisitId、transition 与 isLocal（Chrome 115 起，区分本机访问与同步来的访问）。search 接受 text、startTime、endTime 与 maxResults 四个条件，maxResults 默认 100，startTime 缺省为最近 24 小时；全部方法自 Chrome 96 起返回 Promise。

```js
const items = await chrome.history.search({ text: '', maxResults: 50 });
for (const item of items) {
  const visits = await chrome.history.getVisits({ url: item.url });
  console.log(item.url, visits.length);
}
```

addUrl 以 link 过渡类型追加一条访问，deleteUrl 移除某网址的全部访问，deleteRange 按时间区间删除，deleteAll 清空整个历史记录。transition 取值包括 link、typed、auto_bookmark、auto_subframe、manual_subframe、generated、auto_toplevel、form_submit、reload、keyword 与 keyword_generated。事件有 onVisited（在页面加载之前触发）与 onVisitRemoved。

> [!WARNING]
> **警告内容**：deleteAll 与 deleteRange 不可撤销，历史记录没有回收站。任何暴露这两个方法的界面都应带二次确认，并在扩展说明里写清删除范围；把清除历史当作「清理缓存」的副作用执行，会让用户永久丢失数据。

chrome.downloads 的权限为 downloads，它同时管理下载任务与下载记录，两者相互独立：erase 只清记录不删文件，删除磁盘文件要调用 removeFile。download 的必填字段是 url，可选字段有 filename、conflictAction、saveAs、method、headers 与 body；filename 是相对于下载目录的路径，可以是子目录，绝对路径、空路径以及含上级目录跳转的路径都会报错，conflictAction 取 uniquify、overwrite 或 prompt。

```js
const downloadId = await chrome.downloads.download({
  url: 'https://example.com/export.json',
  filename: 'backup/export.json',
  conflictAction: 'uniquify',
});
const [item] = await chrome.downloads.search({ id: downloadId });
console.log(item.state, item.bytesReceived, item.totalBytes);
```

DownloadItem 的常用字段有 id、filename、url、finalUrl（Chrome 54 起）、state、paused、canResume、danger、error、bytesReceived、totalBytes、mime、startTime、endTime、incognito 与 exists。方法另有 pause、resume、cancel、erase、show、open、removeFile 与 showDefaultFolder；open 需要额外的 downloads.open 权限且只能在响应用户手势时调用，setUiOptions 需要额外的 downloads.ui 权限（Chrome 105 起）。事件有 onCreated、onChanged、onErased 与 onDeterminingFilename。

chrome.sessions 的权限为 sessions，常量 MAX_SESSION_RESULTS 值为 25。Session 对象的 lastModified 是关闭或修改时刻，单位为秒，它要么带 tab 要么带 window，不会同时出现。

```js
const sessions = await chrome.sessions.getRecentlyClosed({ maxResults: 10 });
const closedTab = sessions.find((session) => session.tab);
if (closedTab) await chrome.sessions.restore(closedTab.tab.sessionId);
```

restore 省略 sessionId 时恢复最近关闭的会话；getDevices 返回其它已同步设备的会话列表；onChanged 在最近关闭列表变化时触发，但不监听同步会话的变化。结果中的 Tab 与 Window 对象同样遵循字段可见性规则，读取 url、title 与 favIconUrl 需要 tabs 权限。



### 批量操作与隐私边界

这组 API 的能力范围从「改界面」延伸到「读用户的全部浏览历史」，权限选择比功能实现更值得先想清楚。批量操作有三条实践约束：先在内存里定好完整的目标集合再执行，避免边遍历边修改导致 id 失效；关闭、移动、丢弃这类方法要容忍单个元素失败，用逐个 await 或对结果做过滤，而不是让一个失效 id 中断整批；截图调用受每秒 2 次的限制，频繁抓图需要改为事件驱动。

隐私边界可按数据敏感度分三层：标签页的 id、索引、窗口归属属于界面元数据；标签页的网址与标题、历史记录、书签属于用户行为数据，读取即构成隐私接触；下载的文件路径与会话恢复的内容属于内容数据，风险最高。用户看到的权限告警与实际能力是对齐的：tabs 权限提示「读取您的浏览记录」，history 权限给出同样强度的文案，bookmarks 权限提示「读取和更改您的书签」。同时申请四项权限的扩展，在审核侧会被要求逐项解释用途，在用户侧会显著降低安装意愿。

> [!TIP]
> **建议内容**：能用 activeTab 加 scripting 完成的操作就不要申请 host 权限，能在用户手势当下处理完的就不要长期持有 tabs 权限。权限面越小，安装告警越少，审核中关于最小权限的问询也越少。
