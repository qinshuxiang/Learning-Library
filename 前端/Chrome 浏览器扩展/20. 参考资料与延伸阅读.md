## 参考资料与延伸阅读

本篇汇总 Chrome 扩展开发与发布所需的权威入口，并给出按问题类型检索的具体路径。扩展平台的文档分散在三处：开发者文档站负责技术细节，开发者信息中心负责发布与政策流程，邮件列表与 GitHub 仓库负责变更通知与示例代码。三者不能互相替代。

### 官方文档入口

技术文档的唯一权威来源是 Chrome for Developers，扩展部分按下列结构组织。本机访问 developer.chrome.com 可能失败时，把域名替换为 developer.chrome.google.cn 即可取到同一份内容的镜像。

- 扩展总览：https://developer.chrome.com/docs/extensions 是入口页，按「开始使用」「开发」「发布」三段组织后续链接。
- 入门教程：https://developer.chrome.com/docs/extensions/get-started 提供 Hello World、按标签页注入脚本、管理标签页、Service Worker 处理事件四条主线教程。
- 开发指南：https://developer.chrome.com/docs/extensions/develop 收录内容脚本、消息传递、Service Worker 生命周期、权限声明、界面形态等概念性章节。
- 调试教程：https://developer.chrome.com/docs/extensions/get-started/tutorial/debug 用一个刻意写坏的示例演示三类上下文各自的调试入口。
- 企业发布：https://developer.chrome.com/docs/webstore/cws-enterprise 汇总网域发布、集合、屏蔽名单与许可名单、强制安装等组织侧能力。



### API 参考与清单参考的检索方式

API 参考与清单参考是两套独立的目录，遇到签名疑问时应当先判断问题属于「调用哪一个方法」还是「清单里写哪一个键」。

- API 参考总目录：https://developer.chrome.com/docs/extensions/reference/api 按 API 名分组，单个 API 的地址形如该前缀拼接接口名。
- 清单参考总目录：https://developer.chrome.com/docs/extensions/reference/manifest 按清单键分组，单个键的地址形如该前缀拼接键名。
- 权限对应关系：每个 API 页面顶部都标注所需权限，清单键页面则标注该键与权限、主机权限的配合方式。
- 版本基线标注：API 页面对新增能力逐条标注「从 Chrome 某版本起」，判断兼容性时以页面标注为准。
- 匹配模式语法：https://developer.chrome.com/docs/extensions/develop/concepts/match-patterns 是主机权限与内容脚本匹配模式的权威说明。



### 版本与新特性查询

版本相关的三个问题分别是「我要用的能力从哪个版本可用了」「这个版本什么时候进入稳定版」「最近改了什么」，对应三个不同的页面。

- 新特性列表：https://developer.chrome.com/docs/extensions/whats-new 按时间倒序列出扩展、文档与政策的变化，是判断某项能力引入版本的首选入口。
- 发布日程：https://chromiumdash.appspot.com/schedule 列出稳定版与 Beta 版的发布日期，用于推算某个能力何时覆盖到目标用户群。
- 官方博客：https://developer.chrome.com/blog 发布功能说明与政策变更的详细解释，新特性列表中的条目多数指向对应博文。
- 版本号查询：在浏览器地址栏打开 chrome://version 可确认本机实际版本，避免按文档标注臆测。



### 官方示例代码

官方示例仓库既是可运行代码的来源，也是理解 API 组合方式的参考实现。

- 示例仓库：https://github.com/GoogleChrome/chrome-extensions-samples 顶层分 api-samples 与 functional-samples 两个目录，前者聚焦单个 API，后者是跨多个 API 的完整扩展。
- 归档目录：同一仓库的 _archive 下保留 Manifest V2 时期的资源与已废弃的 Chrome Apps 平台代码，只作对照阅读，不可作为新项目的起点。
- 使用方式：示例以未打包形式加载，克隆仓库后在扩展管理页选择对应子目录即可运行，具体步骤见仓库 README。
- 示例检索页：https://developer.chrome.com/docs/extensions/samples 支持按类型、权限与所用 API 反查示例，比在仓库里逐个目录翻找更快。
- 迁移参考：https://developer.chrome.com/docs/extensions/migrating 说明从 Manifest V2 迁移到 V3 的替换清单，读旧示例代码时用它确认等价写法。



### 政策与审核文档

商店侧的规则集中在开发者文档站的 Web Store 分区，与开发者信息中心里的表单字段一一对应。

- 开发者计划政策：https://developer.chrome.com/docs/webstore/program-policies 是政策索引页，按「安全」「隐私」「营销」「质量」「技术要求」「执法」分组。
- 政策单页版：https://developer.chrome.com/docs/webstore/program-policies/policies 把全部条款合并在一页，适合用浏览器内检索定位具体条文。
- 审核流程：https://developer.chrome.com/docs/webstore/review-process 说明审核时间的影响因素、四种违规处置与申诉入口。
- 注册与账号：https://developer.chrome.com/docs/webstore/register 与 https://developer.chrome.com/docs/webstore/set-up-account 覆盖注册费、邮箱验证与发布商设置。
- 上架与更新：https://developer.chrome.com/docs/webstore/publish 给出首次发布的完整步骤，更新流程见同分区的 update 一篇。
- 隐私字段与分发：https://developer.chrome.com/docs/webstore/cws-dashboard-privacy 与 https://developer.chrome.com/docs/webstore/cws-dashboard-distribution 说明各字段的填写要求。
- 编程接口：https://developer.chrome.com/docs/webstore/using-api 是 Publish API 的端点与鉴权说明，CI 自动上传以此为准。



### 跨浏览器扩展标准

Chrome 的扩展实现并非孤立标准，跨浏览器兼容与标准化工作在 W3C 社区组中推进，浏览器差异则以兼容性表为准。

- WebExtensions 社区组：https://github.com/w3c/webextensions 存放章程、会议纪要、提案与规范草案，跨浏览器的接口取舍在此讨论。
- 兼容性表：https://developer.mozilla.org/docs/Mozilla/Add-ons/WebExtensions 提供各接口在 Chrome、Firefox、Safari 上的支持情况对照。
- 命名空间差异：Chrome 148 起全部扩展 API 同时挂在 browser 命名空间下，作为 chrome 命名空间的跨浏览器别名，写可移植代码时可统一使用前者。
- 构建侧适配：https://wxt.dev 等多目标框架内置了不同浏览器的清单转换与权限裁剪，可以替代手工维护多份清单。



### 类型定义与构建工具链

类型定义解决编辑器补全与签名校验，构建工具解决多入口打包与开发期热重载，两者都应当固定版本并在 CI 中锁定。

- 官方类型包：https://www.npmjs.com/package/chrome-types 由 Chromium 源码自动生成，官方文档要求经常更新以匹配最新的 Chromium 版本。
- 社区类型包：https://www.npmjs.com/package/@types/chrome 由 DefinitelyTyped 维护，覆盖范围与更新节奏与官方包不同。
- Vite 与 CRXJS：https://crxjs.dev/vite-plugin 说明插件配置与热重载行为，包名为 @crxjs/vite-plugin。
- WXT：https://wxt.dev 提供从清单生成、入口约定到打包上传的完整工作流，命令与目录约定见其安装与项目结构两篇。
- 通用构建工具：https://vitejs.dev 与 https://webpack.js.org 的官方文档给出多入口配置、静态资源处理与环境变量注入的原始能力。
- 端到端测试：https://pptr.dev/guides/chrome-extensions 与 https://playwright.dev/docs/chrome-extensions 分别说明两套工具加载扩展的启动参数与取 Service Worker 引用的方式。



### 社区与邮件列表

扩展平台的变更通知通过邮件列表发布，问题排查则依赖议题跟踪器；这两处都不适合提出流程性咨询，流程问题应当走开发者支持表单。

- 官方邮件列表：https://groups.google.com/a/chromium.org/g/chromium-extensions 发布 API 变更、政策调整与安全公告，新特性列表中的多数条目在此有原始讨论帖。
- 议题跟踪器：https://issues.chromium.org 用于提交缺陷与查询已知问题，搜索时应带上扩展相关组件名以缩小范围。
- 开发者支持：商店政策、账号与审核类问题通过信息中心的一站式支持表单提交，不走邮件列表。
- 社区组的公开讨论：跨浏览器接口的提案与争议在新特性列表里常有链接指向社区组的相关议题，读变更动机时比读结论更有价值。



### 版本基线与核验方法

本系列的版本基线是本机 Chrome 稳定版 153.0.8010.36，凡文中写到「Chrome 多少起」的能力，均已对照官方文档核实，未以记忆或第三方转载为依据。

```text
核验顺序：
1. 打开 developer.chrome.com/docs/extensions/whats-new，按版本号定位条目
2. 打开对应 API 或清单键的参考页，读页面顶部的版本标注
3. 在 chrome://version 确认本机版本，判断该能力在基线上是否已可用
4. 涉及商店政策时以 program-policies 单页版为准，不以帮助论坛回答为准
```

> [!IMPORTANT]
> **重要内容**：Manifest V2 已彻底退场，文中出现 MV2 仅用于对照说明设计动因。本系列所有示例均为 Manifest V3；Manifest V2 的失败表现不应作为排查方向，遇到相关报错应直接确认清单是否被升级到了第 3 版。

> [!NOTE]
> **提醒内容**：官方文档站与镜像站内容一致，仅在域名上不同。本机访问 developer.chrome.com 失败时改用 developer.chrome.google.cn，路径部分完全不变；文档的更新时间以页面底部标注为准，涉及版本行为差异时以它判断该页是否已跟进。
