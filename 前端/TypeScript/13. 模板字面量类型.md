## 模板字面量类型

### 模板字面量类型基础

**模板字面量类型（template literal type）**：是用与 JavaScript 模板字符串相同的书写形式构造的字符串字面量类型，占位符以美元符号加大括号包围，括号内放入一个类型，整个类型表示各片段拼接后可能得到的所有字符串。

#### 与模板字符串对应的类型语法

书写形式与模板字符串一一对应：定界符相同、占位符写法相同，区别只在括号内放的是类型而不是值。

```ts
type Greeting = `hello ${string}`;
const greet: Greeting = "hello world";      // OK
// const wrong: Greeting = "hi world";      // 报错：不能赋给 `hello ${string}`

type Version = `v${number}`;
const version: Version = "v2";              // OK
```

- 占位符之外的部分是固定字面量，参与逐字符比对。
- 一个类型里可以有任意多个占位符，位置任意，包括开头与结尾。
- 该类型只描述字符串形状，编译后完全消失，不产生运行时代码。

**速记**：模板字面量类型与模板字符串写法一致，括号里放类型，占位符外是固定片段。



#### 占位符可填的类型范围

占位符内只能填能够表示为字符串片段的类型。

- 允许 string、number、bigint、boolean、null、undefined，以及它们的字面量类型与字面量联合。
- 不允许 object、symbol、函数类型、数组类型，填入即报错。
- boolean 在占位符内展开为 true 与 false 两个字面量。

```ts
type FromBoolean = `flag-${boolean}`;         // "flag-true" | "flag-false"
type FromUnion = `id-${number | "unknown"}`;  // `id-${number}` | "id-unknown"
```

> 占位符填入宽泛的 string 或 number 时，结果退化为模式类型，即某前缀开头的任意字符串，校验能力随之减弱；详见本节「与 string 的关系与字面量保持」。

**速记**：占位符只接受可转成字符串片段的类型，字面量给出精确成员，宽泛类型给出模式。



#### 与 string 的关系与字面量保持

模板字面量类型是 string 的**子类型**：可以赋给 string，反向赋值不成立。字符串字面量类型还**区分大小写**，因此拼接出的成员也区分大小写。

- 只含一个 string 占位符的模板字面量类型与 string 等价，含固定片段时是 string 的真子集。
- 把 string 赋给含固定片段的模板字面量类型一律报错，编译器无法证明形状匹配。
- 数组与对象里的值默认被**拓宽**成 string，拼接后得到宽泛模式；as const 阻止拓宽，保留字面量。

```ts
type AnyText = `${string}`;
const text: AnyText = "anything";             // OK

type Prefixed = `user-${string}`;
declare const some: string;
// const p: Prefixed = some;                  // 报错：string 不能赋给 `user-${string}`

const roles = ["admin", "editor"];            // string[]：已拓宽
const pinned = ["admin", "editor"] as const;  // readonly ["admin", "editor"]
type Wide = `on${Capitalize<typeof roles[number]>}`;   // `on${string}`：丢失校验
type Tight = `on${Capitalize<typeof pinned[number]>}`; // "onAdmin" | "onEditor"

// const c: CaseSensitive = "onclick";        // 报错：大小写不一致
type CaseSensitive = `onClick`;
```

> [!TIP]
> **建议内容**：只要模板字面量类型要消费数组或对象里的值，就在声明处加 as const，否则拼接结果退化成模式类型，白写一层类型。

**速记**：模板字面量类型是 string 的子类型且区分大小写；as const 阻止拓宽，是保留精确成员的前提。



### 联合类型展开

#### 占位符为联合类型时的展开与规模

**联合展开**：是占位符内为联合类型时，模板字面量类型按成员逐一取值并组合，得到所有拼接结果的机制。

- 每个占位符独立地取自己的联合成员，逐个配齐所有组合，结果仍是联合类型。
- 展开后的成员数是各占位符联合长度的**乘积**，两个占位符为平方，三个为立方。
- 这是模板字面量类型自身的展开规则，与分布式条件类型的集合语义相同但触发条件不同（条件类型机制详见本主题第 12 篇）。

```ts
type Axis = "x" | "y";
type Size = "small" | "large";
type ClassName = `${Size}-${Axis}`;           // "small-x" | "small-y" | "large-x" | "large-y"

type Env = "dev" | "stage" | "prod";          // 3
type Region = "cn" | "us" | "eu";             // 3
type Level = "info" | "warn" | "error";       // 3
type LogKey = `${Env}-${Region}-${Level}`;    // 3 × 3 × 3 = 27 个成员
```

> [!WARNING]
> **警告内容**：占位符个数与各级联合长度共同决定成员规模，二者同时增加时呈乘积级膨胀，四五个占位符即可达到数千个成员，拖慢编译并让报错信息失去可读性；发现类型运算变慢应立即拆分或放粗粒度。

**速记**：占位符是联合类型时按成员逐一组合，结果成员数等于各占位符联合长度的乘积。



#### 与 keyof 组合生成事件名与处理器名

keyof 的结果是属性名字面量联合，适合直接放进占位符，用来批量生成配套的命名。

- Capitalize 把首字母改为大写，是事件名成对出现时最常见的转换。
- keyof 结果可能含 number 或 symbol，放进占位符前用与 string 的交叉类型过滤更安全。
- 由事件名联合派生出监听器名联合后，即可进一步约束注册函数的参数。

```ts
interface UserEvents {
  save: (id: string) => void;
  remove: (id: string) => void;
}

type EventName = keyof UserEvents;                      // "save" | "remove"
type HandlerName = `on${Capitalize<EventName>}`;        // "onSave" | "onRemove"
```

**速记**：keyof 给出属性名联合，配合 Capitalize 即可批量生成 onXxx 这类配套命名。



#### 嵌套占位符

**嵌套占位符**：是占位符内再写模板字面量类型，即一个类型实参本身也是模板字面量类型的写法。

- 内层先按自己的联合展开，外层再把内层结果当作单个占位符参与组合，总成员数仍是各层联合长度的乘积。
- 嵌套不改变展开规则，但嵌套过深会明显降低可读性，超过两层建议拆成具名类型。

```ts
type Env = "dev" | "prod";
type Verb = "get" | "set";
type Inner = `${Env}-${Verb}`;                          // "dev-get" | "dev-set" | "prod-get" | "prod-set"
type Nested = `api:${Inner}`;                           // "api:dev-get" | "api:dev-set" | "api:prod-get" | "api:prod-set"
```

**速记**：占位符里再放模板字面量类型即嵌套，内层先展开、外层再组合，总规模仍为乘积。



### 内置字符串操作类型

#### 四个内置字符串操作类型

**Uppercase** 与 **Lowercase** 是把字符串字面量的全部字母转成大写或小写的工具类型；**Capitalize** 与 **Uncapitalize** 是只改首字符大小写的工具类型。

- Uppercase 与 Lowercase 只影响字母，数字、短横线、冒号等非字母字符保持不变。
- Capitalize 与 Uncapitalize 只处理首字符，其余字符大小写原样保留，首字符不是字母时结果与原串相同。
- 四者都是编译器内建实现，无法用普通条件类型复刻，机制原理归本主题第 12 篇。

```ts
type Shout = Uppercase<"hello world">;         // "HELLO WORLD"
type Whisper = Lowercase<"HELLO WORLD">;       // "hello world"
type Upper = Capitalize<"userName">;           // "UserName"
type Lower = Uncapitalize<"UserName">;         // "userName"

type Getter = `get${Capitalize<"name" | "age">}`;     // "getName" | "getAge"
```

> [!NOTE]
> **提醒内容**：Capitalize 与 Lowercase 不等价。Capitalize 只动首字符，Lowercase 会把整体转小写；把两者混用是常见错误。

**速记**：Uppercase 与 Lowercase 改写全部字母，Capitalize 与 Uncapitalize 只改首字符，非字母字符均保持原样。



#### 作用于联合类型时的分发

这四个内置类型内部由条件类型实现，遇到联合类型会**逐成员分发**，结果为逐个转换后的新联合。

- 分发是自动的，不需要显式循环，也不需要映射类型。
- 分发与模板字面量类型的展开可叠加，写出一个类型即得到全部转换结果。

```ts
type Modifier = "read" | "write" | "admin";
type Flag = `can${Capitalize<Modifier>}`;       // "canRead" | "canWrite" | "canAdmin"
type Underscore = `${Uppercase<Modifier>}_KEY`; // "READ_KEY" | "WRITE_KEY" | "ADMIN_KEY"
```

**速记**：内置字符串操作类型对联合逐成员分发，可与模板字面量类型的展开叠加使用。



#### 只对字面量类型生效的限制

这四个类型只改写**字面量类型**；输入不是字面量时结果退化为 string，不产生任何新信息。

- 输入 string 时四个类型都返回 string，没有校验能力。
- 输入带 string 占位符的模式类型时，只有固定片段参与改写，占位符部分仍是 string。
- 想得到精确结果，必须保证输入是字面量联合。

```ts
type OnString = Uppercase<string>;             // string：没有校验能力
type OnPattern = Uppercase<`user-${string}`>;  // 固定片段变大写，占位符仍为 string
type OnLiteral = Uppercase<"user-admin">;      // "USER-ADMIN"：精确结果
```

> [!CAUTION]
> **注意内容**：对 object、数组、函数类型调用这四个类型会直接报错，它们只接受 string 及其子类型；类型来自运行时数据时先用 as const 固定字面量。

**速记**：内置字符串操作类型只改写字面量，输入 string 或模式类型时结果退化，等于没写。



### 实战应用

#### 事件名与监听器映射表

需求：由事件名联合自动派生 onXxx 监听器类型，让注册函数对事件名与处理器签名同时做校验。

```ts
interface UserEvents {
  save: (id: string) => void;
  remove: (id: string) => void;
}

type EventName = keyof UserEvents;
type ListenerMap = {
  [K in EventName as `on${Capitalize<K>}`]: UserEvents[K];
};
// { onSave: (id: string) => void; onRemove: (id: string) => void }

function toEventKey<K extends EventName>(name: K): `on${Capitalize<K>}` {
  return `on${name[0].toUpperCase()}${name.slice(1)}` as `on${Capitalize<K>}`;
}

function on<K extends EventName>(name: K, handler: UserEvents[K]): void {
  document.addEventListener(toEventKey(name), handler as EventListener);
}
// on("sve", () => {});                        // 报错：不在事件名联合内
```

> 键重映射 as 属于映射类型机制，详见本主题第 11 篇；此处只借用它把事件名批量改写成监听器名。

**速记**：事件名联合经 Capitalize 加前缀，即可派生整张监听器映射表，键与处理器签名一一对应。



#### 路由路径的参数类型

需求：用模板字面量类型约束拼出的路径字符串，禁止拼出不存在的前缀或段数。

```ts
type RoutePath =
  | `/${string}`
  | `/users/${string}`
  | `/users/${string}/posts/${number}`
  | `/posts/${number}/${"edit" | "view"}`;

function toUserPath(userId: string): RoutePath {
  return `/users/${userId}`;
}

function toPostPath(postId: number, mode: "edit" | "view"): RoutePath {
  return `/posts/${postId}/${mode}`;
}

const edit: RoutePath = toPostPath(7, "edit");  // "/posts/7/edit"
// const bad: RoutePath = "/users/1/posts/x";   // 报错：最后一段必须是 number
```

- 每个成员最多放一个占位符，段数与固定片段由联合成员本身决定。
- 参数细节的自动提取留到「与 infer 组合」一节，那里能从单个路径模式反推参数名。

**速记**：用联合的模板字面量类型描述合法路径形状，占位符控制参数位置，固定片段控制段数。



#### CSS 单位与数值拼接

需求：把数值与单位拼成合法的 CSS 长度字符串，拒绝缺单位或非法单位。

```ts
type CssUnit = "px" | "rem" | "em" | "%" | "vh";
type CssLength = `${number}${CssUnit}`;

const gap: CssLength = "12px";                  // OK
// const noUnit: CssLength = "12";              // 报错：缺少单位
// const badUnit: CssLength = "12pt";           // 报错："pt" 不在单位联合内

function toCssLength(value: number, unit: CssUnit): CssLength {
  return `${value}${unit}`;
}
const width = toCssLength(1.5, "rem");          // "1.5rem"
```

> [!TIP]
> **建议内容**：数值部分用 number 占位符而不要用字面量联合，既覆盖任意数值，又保留对单位的约束。

**速记**：数值占位符加单位联合，一次同时约束数值形态与单位取值。



#### 对象键与表单字段名的批量派生

需求：对象键统一加前缀得到新类型；表单字段名派生出错误信息键，保证错误对象只允许出现与字段对应的键。

```ts
interface RawConfig {
  host: string;
  port: number;
  timeout: number;
}
type EnvConfig = {
  [K in keyof RawConfig as `APP_${Uppercase<K & string>}`]: RawConfig[K];
};
// { APP_HOST: string; APP_PORT: number; APP_TIMEOUT: number }

interface LoginForm {
  email: string;
  password: string;
}
type FieldName = keyof LoginForm & string;      // "email" | "password"
type ErrorKey = `${FieldName}Error`;            // "emailError" | "passwordError"
type FormErrors = Partial<Record<ErrorKey, string>>;
const errors: FormErrors = { emailError: "邮箱格式不正确" };  // OK
// const bad: FormErrors = { nameError: "x" };   // 报错：不在键联合内
```

- K 与 string 的交叉用于剔除 keyof 结果中可能混入的 number 与 symbol；映射类型与键重映射的完整规则详见本主题第 11 篇。

**速记**：映射类型的键重映射里拼接前缀或后缀即批量重命名对象键；字段名联合加后缀即得到配套的错误键联合。



### 与 infer 组合

条件类型与 infer 的语法、分布式行为归本主题第 12 篇；本节只复述在模板字面量类型中作模式匹配时的用法。

#### 用模式匹配提取字符串片段

**模式匹配**：是把模板字面量类型放在条件类型的 extends 左侧，用 infer 占住想提取的位置，从而拆解字符串形状的写法。

- 固定片段充当分隔点，infer 捕获分隔点之间或前后的片段，一次可用多个 infer。
- 捕获到的片段是字面量类型，可继续参与后续拼接与运算。
- 把上一步的 infer 结果再送入下一次匹配即形成嵌套匹配，链式推进；超过两步建议拆成具名类型。

```ts
type ExtractId<T extends string> = T extends `user-${infer Id}` ? Id : never;
type IdA = ExtractId<"user-42">;              // "42"
type IdB = ExtractId<"post-42">;              // never：前缀不匹配

type SplitPair<T extends string> = T extends `${infer Left}:${infer Right}`
  ? [Left, Right]
  : never;
type Pair = SplitPair<"host:localhost">;      // ["host", "localhost"]

type GetterName<T extends string> = T extends `get${infer Prop}` ? Uncapitalize<Prop> : never;
type PropName = GetterName<"getUserName">;    // "userName"
```

**速记**：模板字面量类型放条件类型左侧，infer 占住待提取位置；反复匹配即嵌套匹配，层数多时拆成具名类型。



#### 解析查询字符串

需求：把查询串的类型拆成键的联合，使返回对象只允许出现真正出现过的键。

```ts
type ParsePairs<T extends string> =
  T extends `${infer Head}&${infer Rest}`
    ? Head | ParsePairs<Rest>
    : T;
// ParsePairs<"page=1&size=10"> = "page=1" | "size=10"

type KeyOfPair<Pair extends string> =
  Pair extends `${infer Key}=${string}` ? Key : never;
type QueryKeys<T extends string> = KeyOfPair<ParsePairs<T>>;  // 逐成员分发得到键联合
type Q = QueryKeys<"page=1&size=10&sort=desc">;               // "page" | "size" | "sort"

function parseQuery<T extends string>(query: T): Record<QueryKeys<T>, string> {
  const result = {} as Record<QueryKeys<T>, string>;
  for (const pair of query.split("&")) {
    const [key, value] = pair.split("=");
    result[key as QueryKeys<T>] = value;
  }
  return result;
}
```

- ParsePairs 是递归条件类型，靠 Rest 逐段推进，最后一段没有与号时直接返回自身。
- KeyOfPair 的类型参数是裸类型参数，所以对联合自动分发，无需额外循环。

**速记**：先用递归拆出键值对，再用裸类型参数分发取出键名，查询串类型即可保留到返回对象。



#### 提取路径参数

需求：从单条路径模式反推参数名，生成参数对象类型，参数名与路径写法自动保持一致。

```ts
type PathParamNames<T extends string> =
  T extends `${string}:${infer Param}/${infer Rest}`
    ? Param | PathParamNames<`/${Rest}`>
    : T extends `${string}:${infer Param}`
      ? Param
      : never;

type RouteParams<T extends string> = {
  [K in PathParamNames<T>]: string;
};

type DetailParams = RouteParams<"/users/:userId/posts/:postId">;
// { userId: string; postId: string }

function toPath<T extends string>(pattern: T, params: RouteParams<T>): string {
  return pattern.replace(/:(\w+)/g, (_match, key: string) =>
    String((params as Record<string, string>)[key]));
}
```

> [!NOTE]
> **提醒内容**：该提取只做类型层面的形状推导，路径是否真实存在仍需由服务端路由表保证，类型无法替代运行时校验。

**速记**：以冒号加斜杠为分隔点递归匹配先取参数名，再用映射类型把参数名转成参数对象。



#### 匹配失败的处理与递归深度

匹配失败时若返回 never，输入信息被彻底丢掉；返回原串则保留信息，由调用处决定后续处理。

- 失败分支返回 T 适合「可选改写」场景，未匹配的输入原样透传。
- 失败分支返回 never 适合「必须匹配」场景，未匹配时立刻暴露为类型错误。
- 递归必须有收敛分支，每步向更短的方向推进，否则展开不会停止。

```ts
type LastSegment<T extends string> =
  T extends `${string}/${infer Rest}` ? LastSegment<Rest> : T;
type Last = LastSegment<"/users/u-1/posts">;    // "posts"

type RequirePrefix<T extends string> = T extends `api-${infer Rest}` ? Rest : never;
type R2 = RequirePrefix<"user">;                // never：调用处会得到类型错误
```

> [!WARNING]
> **警告内容**：递归模板字面量类型在失败分支仍把原串传回自身时会无限展开，编译器报「Type instantiation is excessively deep and possibly infinite」；每一层都必须实实在在缩短字符串。

> [!CAUTION]
> **注意内容**：非尾递归形式的条件类型在约五十层后即触发深度上限，长字符串解析需要改用尾递归写法或限制输入长度。

**速记**：失败分支返回原串保留信息、返回 never 暴露错误；递归必须收敛，否则触发深度上限报错。
