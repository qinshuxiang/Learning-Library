
## 接口与类型别名

### interface 的声明与使用

接口专门描述对象形状，是 TypeScript 中最常用的结构声明形式。

#### 声明对象形状

**接口（interface）**：TypeScript 中描述对象形状的声明，只存在于编译期，编译后不产生任何 JavaScript 代码。

```ts
interface UserProfile {
  id: number;
  nickname: string;
  isActive: boolean;
}

const user: UserProfile = { id: 1001, nickname: "lin", isActive: true };

console.log(user.nickname); // "lin"
// const missing: UserProfile = { id: 1001 }; // 报错：缺少 nickname、isActive
```

- 赋值是否成立只看结构，不要求两个对象来自同一个声明，这条规则称为结构化类型（structural typing）。
- 对象字面量赋值时额外做多余属性检查，多写字段直接报错，用来拦截拼写错误。
- 成员类型不符同样报错，例如 isActive 传字符串无法赋给 boolean。

**速记**：interface 只描述形状，不产生运行时值；赋值按结构化类型判断，对象字面量会做多余属性检查。



#### 方法成员

方法成员是在接口里声明可调用成员的两种等价写法：方法写法与函数类型属性写法。

```ts
interface Calculator {
  double(value: number): number;      // 方法成员
  triple: (value: number) => number;  // 属性加函数类型
}

const calculator: Calculator = { double: (value) => value * 2, triple: (value) => value * 3 };

console.log(calculator.double(4)); // 8
```

- 两种写法调用上等价，区别在参数检查：方法成员按双变处理，函数类型属性在开启 strictFunctionTypes 后按逆变检查。
- 需要严格校验回调参数时用函数类型属性写法。
- 方法成员不能加 readonly，函数类型属性可以。

**速记**：两种写法等价，差异只在参数的双变与逆变检查，以及能否加 readonly。



#### 继承与实现关系

**接口继承（extends）**：让新接口获得父接口的成员，可一次继承多个；**实现（implements）** 则让类声明自己满足某个接口。

```ts
interface Entity {
  id: string;
  createdAt: Date;
}

interface Timestamped {
  updatedAt: Date;
}

interface Article extends Entity, Timestamped {
  title: string;
}

const post: Article = { id: "a-1", createdAt: new Date(), updatedAt: new Date(), title: "TS" };
```

- 父接口的同名字段类型兼容时合并，冲突时整个接口报错。
- implements 是编译期的结构检查，不改变运行时行为，编译产物中没有痕迹。
- 类的成员修饰符、抽象类与 implements 的完整用法，见本主题第 14 篇。

**速记**：extends 可并列多接口、成员取并集，同名字段必须兼容；implements 只做编译期检查。



### 可选属性、只读属性与索引签名

修饰符与索引签名共同决定接口接受哪些键、哪些键的值可改。

#### 可选属性

**可选属性**：属性名后加问号，表示该键可以缺省，读取时类型自动包含 undefined。

```ts
interface SearchOptions {
  keyword: string;
  page?: number;
  pageSize?: number;
}

function getPageSize(options: SearchOptions): number {
  return options.pageSize ?? 10;
}

console.log(getPageSize({ keyword: "typescript" })); // 10
```

- 可选属性允许键整体不存在，显式写 undefined 的联合类型则要求键存在，开启 exactOptionalPropertyTypes 后差异更明显。
- 读取前需要先收窄或给默认值，空值合并运算符是常见做法，收窄手法见本主题第 8 篇。
- 函数类型成员也可以写成可选形式，例如 validate?: (input: string) => boolean。

**速记**：问号表示键可缺省，读取类型自动带上 undefined，使用前先收窄或给默认值。



#### 只读属性

**只读属性**：用 readonly 修饰的成员，只允许在创建时赋值，之后不能再改。

```ts
interface RuntimeConfig {
  readonly apiBase: string;
  readonly retries: number;
  timeout: number;
}

const config: RuntimeConfig = { apiBase: "https://api.example.com", retries: 3, timeout: 5000 };

config.timeout = 8000; // 合法：普通属性可改
// config.retries = 5; // 报错：readonly 属性不可重新赋值
```

- readonly 只约束编译期的赋值行为，编译后没有保护，运行时照样可以改。
- 只作用于当前这一层属性，嵌套对象里的字段仍可改；深层只读要用工具类型 Readonly，详见本主题第 11 篇。
- 只读数组与只读元组写成 readonly 修饰的数组类型，归本主题第 6 篇。

**速记**：readonly 是编译期的一次性约束，浅层有效、运行时不设防，深层只读要靠工具类型。



#### 索引签名与具名属性共存

**索引签名**：用方括号加键类型与值类型，描述一批未知属性名的统一取值类型。

```ts
interface HttpHeaders {
  [header: string]: string;  // 索引签名
  host: string;              // 具名属性必须能被索引签名容纳
}

const requestHeaders: HttpHeaders = { host: "example.com", "content-type": "application/json" };

console.log(requestHeaders["content-type"]); // "application/json"
// interface Broken { [key: string]: number; label: string; } // 报错：string 不能赋给 number
```

- 键类型只能是 string、number 或 symbol，模板字面量模式见本主题第 13 篇。
- 具名属性的类型必须可以赋给索引签名的值类型，否则整个接口报错。
- 同时写 string 与 number 索引时，number 索引的值类型必须可以赋给 string 索引的值类型。
- 索引签名放宽多余属性检查，适合字典结构，不适合字段固定的对象。

> 索引签名写字典类型比较啰嗦，内置工具类型 Record 用两个类型参数一次声明键与值，完整清单见本主题第 11 篇。

**速记**：索引签名给出统一取值类型，具名属性必须被它容纳，代价是失去多余属性检查。



### type 类型别名

类型别名既能给对象形状起名，也是命名组合类型的唯一手段。

#### 给任意类型起名

**类型别名（type alias）**：用 type 关键字给任意已存在的类型起一个新名字，新旧名字完全等价。

```ts
type UserId = string;
type Point = { x: number; y: number };
type EventLogger = (event: string) => void;
type MaybeName = string | undefined;

const id: UserId = "u-1001";
const logEvent: EventLogger = (event) => console.log(event);

logEvent("click"); // "click"
console.log(id);   // "u-1001"
```

- 只是起名，不创建新类型，UserId 与 string 可以互相赋值，不存在名义类型隔离。
- 可以给原始类型、对象、函数、联合、元组，乃至另一个别名起名。
- 编译后全部消失，无法在运行时判断某个值是否属于某个别名。

**速记**：type 给任意类型起名，新旧名字完全等价，不产生运行时值也不产生名义类型。



#### 联合、交叉与元组

联合、交叉与元组三种组合类型通常借类型别名命名，便于复用与集中修改。

```ts
type Status = "idle" | "loading" | "done";            // 联合类型
type Identity = { id: string } & { version: number };  // 交叉类型
type Coordinate = [number, number];                    // 元组类型

const status: Status = "loading";
const identity: Identity = { id: "i-1", version: 2 };
const startPoint: Coordinate = [0, 0];

console.log(status, identity.id, startPoint[0]); // "loading" "i-1" 0
```

- 联合用竖线连接候选类型，表示取值属于其中之一。
- 交叉用与号连接多个对象类型，表示同时满足全部成员。
- 元组是定长数组，逐位标注类型，比数组类型更能表达位数与位置。
- 三者的语义细节与可辨识联合见本主题第 5 篇。

**速记**：联合、交叉、元组都由 type 命名，语法分别是竖线、与号与方括号，语义细节见第 5 篇。



#### 嵌套引用与递归

类型别名之间可以互相引用，把复杂结构拆成若干可复用的小类型。

```ts
type OrderId = string;
type OrderStatus = "open" | "shipped" | "closed";

type OrderItem = { sku: string; quantity: number };

type Order = {
  id: OrderId;
  status: OrderStatus;
  items: OrderItem[];
};

const order: Order = { id: "o-2026-01", status: "open", items: [{ sku: "sku-1", quantity: 2 }] };

console.log(order.items.length); // 1
```

- 小类型独立命名后，改一处定义即可影响全部使用点，比内联书写更易维护。
- 别名可以递归引用自身，用来描述树形与链表等自相似结构。

```ts
type TreeNode = { value: number; children: TreeNode[] };
```

**速记**：别名可嵌套也可递归，用小类型拼出大类型是组织复杂结构的常规手段。



### interface 与 type 的差异与选择

两者在描述对象形状时几乎等价，差异集中在声明合并、表达能力与工程实践。

#### 声明合并

**声明合并（declaration merging）**：多个同名接口的成员自动合并成同一个类型，这是 interface 独有的能力。

```ts
interface RequestOptions { retries: number }
interface RequestOptions { timeout: number }
interface RequestOptions { method?: "GET" | "POST" }

const options: RequestOptions = { retries: 2, timeout: 3000, method: "GET" };

console.log(options.timeout); // 3000
```

- 名字相同、作用域相同即合并，全部成员的并集就是最终类型。
- 同名方法的签名按重载列表合并，后声明的接口中的签名排在前面。
- 类型别名不能重复声明，也不参与合并，因此无法给第三方类型追加成员。
- 模块扩充与全局类型增强依赖声明合并，见本主题第 16 篇。

> [!WARNING]
> 警告内容：声明合并会让类型的最终形状分散在多个声明里，排查时难以一眼看全，业务代码不应主动依赖它。

**速记**：声明合并是 interface 独有能力，别名在同一作用域只能声明一次，也因此缺席类型扩充。



#### 表达能力边界

interface 只能描述对象形状，类型别名可以命名任何类型，这是两者最本质的边界。

```ts
// 以下类型只能用 type 命名，interface 无法表达：
type Id = string | number;            // 联合类型
type Coordinates = [number, number];  // 元组类型
type PrimaryKey = string;             // 原始类型别名
```

- interface 能表达对象字面量形状、函数（调用签名）、构造函数（构造签名）、数组、类实例。
- 只有 type 能表达联合类型、交叉类型的命名、元组、原始类型别名，以及映射类型、条件类型、模板字面量类型。
- 映射类型归本主题第 11 篇，条件类型归第 12 篇，模板字面量类型归第 13 篇。

**速记**：interface 限于对象形状，type 覆盖全部类型；联合、元组与原始类型别名只能用 type。



#### 报错信息与工具性能

两者在报错可读性与编译器性能上存在差别，但只在大型类型定义下才明显。

- 报错信息：接口在提示里保留自己的名字；别名背后是联合、交叉或映射类型时，提示更容易被展开成一整段结构。
- 类型检查：复杂组合类型需要按需实例化，接口身份稳定，缓存与增量编译更容易命中。
- 编辑体验：日常规模的项目中，两者在补全与跳转上的差别可以忽略。

> [!NOTE]
> 提醒内容：报错与性能差异只在成千上万条类型实例的项目里可测量，普通项目不应据此选型。

**速记**：interface 报错保留名字更好读，type 深层组合后容易被展开；性能差异只在大规模类型下值得考虑。



#### 团队约定建议

团队约定优先于语言层面的细微差异，关键是同一职责只保留一种写法。

- 描述对象形状、需要被继承或被扩充时用 interface。
- 命名联合、元组、函数类型、原始类型别名时用 type。
- 对外暴露的组件 props 与函数参数对象建议用 interface，便于使用者继承。
- 不要为了将来可能合并而把别名改成接口，也不要两套写法混着描述同一个概念。
- 选定规则写进项目规范，避免同一份代码出现两种风格。

> [!TIP]
> 建议内容：团队没有既有偏好时，采用对象用 interface、其余用 type 这一条默认规则最省心，社区主流项目大多如此。

**速记**：对象形状用 interface，组合类型与别名用 type；规则写进规范并全项目统一。



### 函数签名与构造签名

接口不仅能描述属性，还能描述值可以被调用与被 new，分别称为调用签名与构造签名。

#### 调用签名

**调用签名（call signature）**：写在接口成员位置的参数列表与返回值，用来描述该值可以被调用。

```ts
interface LengthFormatter {
  (value: number, unit: string): string;
}

const formatLength: LengthFormatter = (value, unit) => value.toFixed(1) + unit;

console.log(formatLength(1.5, "cm")); // "1.5cm"
```

- 只写参数与返回值，不带函数名，参数名仅供阅读，位置与类型才是约束。
- 只含调用签名的接口与函数类型别名完全等价，两种写法可以互换。
- 调用签名可以与普通属性写在同一个接口里，描述既可以被调用、又带属性的值。

**速记**：调用签名用括号加返回值描述可调用值，与函数类型别名等价。



#### 构造签名

**构造签名（construct signature）**：在调用签名前加 new，描述该值可配合 new 运算符调用，返回值是实例类型。

```ts
interface PointLike {
  x: number;
  y: number;
}

interface PointConstructor {
  new (x: number, y: number): PointLike;
}

function makePoint(Ctor: PointConstructor, x: number, y: number): PointLike {
  return new Ctor(x, y);
}
```

- 只约束可以被 new，不要求实现方是 class，普通构造函数同样可以满足。
- 描述的是构造函数本身的类型，实例类型写在返回值位置，两者不要混淆。
- 同一接口可以同时写构造签名与调用签名，表示既能被 new 也能被直接调用。

**速记**：new 签名描述可被 new 调用的值，返回值即实例类型，实现方不必是 class。



#### 属性的可调用写法

描述一个可调用的东西有几种写法，选择取决于它是否作为对象的成员出现。

```ts
type Validator = (input: string) => boolean; // 类型别名

interface Form {
  validate: Validator;                     // 具名属性，类型为函数
  normalize?: (input: string) => boolean;  // 内联函数类型，可选
}

const form: Form = { validate: (input) => input.length > 0 };

console.log(form.validate("hello")); // true
```

- 一个值本身可调用时，用类型别名或带调用签名的接口。
- 对象的某个成员可调用时，用属性加函数类型，可选成员在名字后加问号。
- 内联函数类型适合只出现一次的成员，重复出现时抽成别名或接口。

**速记**：可调用的值用调用签名或别名，可调用的成员用属性加函数类型。



#### 接口中的重载签名

在同一个接口里并列多条调用签名，就构成函数重载的签名列表。

```ts
interface TextParser {
  (input: string): string[];
  (input: string, separator: string): string[];
}

const parseText: TextParser = (input: string, separator: string = ",") => input.split(separator);

console.log(parseText("a,b,c"));      // ["a", "b", "c"]
console.log(parseText("a|b|c", "|")); // ["a", "b", "c"]
```

- 多条调用签名即重载签名列表，调用时从上往下匹配第一个符合的签名。
- 接口里只写重载签名，不写实现签名；实现签名由赋值时的函数提供，必须兼容全部重载。
- 构造签名同样可以重载，写法是并列多条 new 签名。

> [!TIP]
> 建议内容：把参数最具体、最不容易被误匹配的签名放在最前面，否则后面的签名可能永远轮不到。

> 重载的实现规则、实现签名与重载签名的兼容要求，见本主题第 7 篇。
