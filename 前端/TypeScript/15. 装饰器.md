## 装饰器

### 装饰器的标准与演进

**装饰器（decorator）**：是写在类、类成员或参数声明之前、以 @ 开头的语法，在类定义求值时按函数调用执行，对目标做附加、包裹或替换。

#### legacy 装饰器与 stage 3 标准的差别

TypeScript 并存两套互不兼容的装饰器语义，分别来自两份不同的提案。

- legacy 装饰器：源自 TC39 的 stage 2 草案，TypeScript 1.5 起实现；按目标分为类、方法、访问器、属性、参数五类签名，参数为 target、propertyKey、descriptor。
- stage 3 标准装饰器：TC39 推进到 stage 3 的提案，TypeScript 5.0 起支持；签名统一为 value 与 context，不再包含参数装饰器。

```ts
// legacy：就地改写描述符
function logCall(target: Object, propertyKey: string, descriptor: PropertyDescriptor): void {
  const original = descriptor.value as (...args: unknown[]) => unknown;
  descriptor.value = function (this: unknown, ...args: unknown[]) {
    console.log(`调用 ${propertyKey}`); // "调用 run"
    return original.apply(this, args);
  };
}

// stage 3：返回新函数替换原方法，并可在 context 上注册初始化回调
function traceCall(value: Function, context: ClassMethodDecoratorContext): Function {
  return function (this: unknown, ...args: unknown[]) {
    return (value as (this: unknown, ...a: unknown[]) => unknown).apply(this, args);
  };
}
```

**速记**：legacy 是 stage 2 草案语义、五类签名、就地改描述符；stage 3 是标准语义、统一 value 与 context、靠返回值替换。



#### 编译开关与不兼容的后果

两个编译开关决定使用哪套语义、是否输出运行时元数据。

- experimentalDecorators：开启后按 legacy 语义检查与编译；关闭时按 stage 3 标准语义处理。
- emitDecoratorMetadata：额外写入 design:type、design:paramtypes、design:returntype 三类元数据，必须与 experimentalDecorators 同时开启。
- 混用不报语法错：标准写法在 legacy 下第二个参数实际是 propertyKey，context 为 undefined，静默产生错误行为。
- 依赖元数据的框架几乎都要求 legacy，因此这些框架仍需开启 experimentalDecorators。

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "experimentalDecorators": true,
    "emitDecoratorMetadata": true
  }
}
```

> [!WARNING]
> **警告内容**：开启 experimentalDecorators 即锁定 legacy 语义，同一编译单元内无法同时使用标准装饰器。

**速记**：experimentalDecorators 决定语义，emitDecoratorMetadata 依赖它输出元数据；两套语义混用会静默出错。



#### 装饰器能做什么与不能做什么

装饰器的能力边界由「只在类定义求值时执行」这一条决定。

- 能做：替换整个类、包裹或替换方法、改写访问器、修改属性描述符、写入元数据、以声明式语法表达横切关注点。
- 不能做：装饰普通函数声明、变量、interface、type 别名与枚举，写在非类位置上会直接报错。
- 不能做：产生新的静态类型；读取被类型擦除的泛型实参与 interface；在装饰阶段读取实例上的属性值。

> [!NOTE]
> **提醒内容**：装饰器改的是运行时结构而不是类型，实际对象与静态类型可能不一致，使用前需确认运行时的真实形态。

**速记**：装饰器只能改运行时结构；不产生类型、不还原擦除信息、不能装饰普通函数与类型声明。



### 类装饰器

**类装饰器**：是写在 class 声明之前的装饰器，接收类的构造函数，把整个类作为改写对象。

#### 类装饰器的签名与参数

legacy 类装饰器的签名是 (target: Function) => Function | void，target 为被装饰类的构造函数，在类定义求值时执行一次。

- 只收到一个参数，拿不到原型与属性名，要操作成员应改用成员装饰器。
- 泛型类传入后同样退化为 Function，无法读取类型参数。

```ts
function register(target: Function): void {
  console.log(`注册 ${target.name}`); // "注册 UserService"
}

@register
class UserService {
  findById(id: number): string { return `user-${id}`; }
}
```

**速记**：类装饰器签名是 (target: Function) => Function | void，只拿到构造函数，在类定义求值时执行一次。



#### 返回值替换构造函数与附加静态信息

返回值决定类的最终形态，挂静态属性则用于附加类级别的声明式信息。

- 返回 undefined 或不写 return：保留原类，装饰器内对 target 的修改仍然生效。
- 返回一个构造函数：替换原类声明；legacy 下静态类型不随之改变，实例类型仍是原声明。
- 静态信息：给 target 赋属性或用 Object.defineProperty 控制开关；这些成员不在静态类型里，读取需显式断言。

```ts
function entity(tableName: string) {
  return function (target: Function): void {
    Object.defineProperty(target, "tableName", { value: tableName });
  };
}

@entity("users")
class User { id = 0; }
const table = (User as unknown as { tableName: string }).tableName;
console.log(table); // "users"
```

**速记**：返回 undefined 保留原类，返回构造函数则替换且静态类型不变；附挂的静态信息不在类型里，读取要靠断言。



#### 类装饰器与继承的关系

类装饰器不是继承的成员，而是对某个类声明的一次性调用。

- 装饰器只作用于被装饰的类，子类不会自动获得同样的装饰行为。
- 装饰器对原型的改写会通过原型链被子类看到，除非子类覆写。
- 装饰器返回新类时，新的构造函数成为原类名的绑定值，子类 extends 的是替换后的结果。

**速记**：装饰器只作用于被装饰的类，子类不继承标记；对原型的改写会沿原型链对子类生效。



### 方法与访问器装饰器

**方法装饰器**：是写在类方法之前的装饰器，接收原型（静态方法为构造函数）、方法名与属性描述符。**访问器装饰器**：是写在 get 或 set 之前的装饰器，参数相同，改写对象是访问器描述符。

#### PropertyDescriptor 参数的作用

**属性描述符（PropertyDescriptor）**：是描述对象上某个属性行为的普通对象，方法装饰器拿到的是该方法在原型上的描述符。

- 数据描述符含 value、writable、enumerable、configurable，方法的 value 就是原函数。
- 访问器描述符含 get、set、enumerable、configurable，没有 value 与 writable。
- 描述符是引用传递，装饰器内对它的修改在装饰器返回后依然生效；因此改写 value 就等于替换方法实现。

**速记**：描述符描述属性行为；方法描述符的 value 是原函数，改写它即替换实现，修改立即生效。



#### 包裹原方法的通用写法

包裹是方法装饰器最常见的用法，套路固定为保存原函数、转发调用、写回描述符。

- 用 apply（或 call、Reflect.apply）转发 this，否则实例方法内部的 this 会丢失。
- 参数原样透传，返回值必须 return，否则调用方拿到 undefined。
- 包裹不改变静态类型：参数与返回类型仍由原方法声明决定，编译器不检查包装后的实际签名。

```ts
function logCall(target: Object, propertyKey: string, descriptor: PropertyDescriptor): void {
  const original = descriptor.value as (this: unknown, ...args: unknown[]) => unknown;
  descriptor.value = function (this: unknown, ...args: unknown[]) {
    console.log(`调用 ${propertyKey}`);
    return original.apply(this, args);
  };
}

class OrderService {
  @logCall
  pay(orderId: number): string { return `paid-${orderId}`; }
}

new OrderService().pay(7); // "调用 pay" 然后 "paid-7"
```

**速记**：保存原函数、用 apply 转发 this、透传参数并 return 返回值，是包裹方法的固定套路。



#### 访问器装饰器的限制与返回值规则

访问器装饰器有一条硬性限制，两类装饰器的返回值规则则完全相同。

- 同一属性的 get 与 set 不能各写一个装饰器，否则编译报错；装饰器收到的是同一个描述符，无法只针对读或只针对写。
- 返回 undefined 或不写 return：保留原描述符，装饰器内的修改继续生效。
- 返回描述符对象：整体替换，未包含在返回值里的修改会丢失，因此要先展开原描述符。

```ts
function readonlyField(target: Object, propertyKey: string, descriptor: PropertyDescriptor): void {
  const originalGet = descriptor.get;
  if (originalGet) {
    descriptor.get = function (this: unknown) {
      console.log(`读取 ${propertyKey}`);
      return originalGet.call(this);
    };
  }
}

class Config {
  private _port = 8080;
  @readonlyField
  get port(): number { return this._port; }
}

console.log(new Config().port); // "读取 port" 然后 8080
```

**速记**：访问器装饰器只能写 get 或 set 之一；返回 undefined 保留描述符，返回对象则整体替换。



### 属性与参数装饰器

**属性装饰器**：是写在类属性声明之前的装饰器，只接收原型（静态属性为构造函数）与属性名。**参数装饰器**：是写在构造函数或方法参数之前的装饰器，额外接收参数下标。

#### 属性装饰器读到的信息与限制

legacy 属性装饰器的签名是 (target: Object, propertyKey: string | symbol) => void。

- 实例属性：target 是类的 prototype；静态属性：target 是构造函数本身。
- 属性在原型上没有实体，实例字段在构造函数里才赋值，因此没有描述符可改，也读不到属性的值与运行时类型。
- 需要实例级行为时，改用访问器装饰器包裹 get 与 set，或把信息记录在原型上等实例化后再读。

```ts
function track(target: Object, propertyKey: string): void {
  console.log(`记录 ${target.constructor.name}.${propertyKey}`); // "记录 Article.title"
}

class Article {
  @track
  title = "";
}
```

> [!NOTE]
> **提醒内容**：开启 emitDecoratorMetadata 后，属性装饰器可借助 design:type 读到属性类型对应的构造函数，这是绕过「拿不到值」的常用办法。

**速记**：属性装饰器只有 target 与 propertyKey；实例字段在构造函数里才赋值，装饰阶段拿不到实例。



#### 参数装饰器的作用与出现位置

参数装饰器用于标记某个参数需要被框架特殊处理，签名是 (target: Object, propertyKey: string | symbol | undefined, parameterIndex: number) => void。

- 构造函数参数：target 是构造函数，propertyKey 为 undefined；方法参数：target 是原型（静态方法为构造函数），propertyKey 是方法名。
- 没有描述符，不能替换参数值，唯一的信息输出是 parameterIndex。
- 参数装饰器先于该成员自身的装饰器执行，是最先被调用的一类装饰器。

```ts
function inject(target: Object, propertyKey: string | symbol | undefined, parameterIndex: number): void {
  console.log(`第 ${parameterIndex} 个参数需要注入`); // "第 0 个参数需要注入"
}

class OrderService {
  constructor(@inject private readonly loggerName: string) {}
}
```

**速记**：参数装饰器只能拿到参数下标，用来标记需要特殊处理的参数，且仅存在于 legacy 语义。



#### 参数装饰器与依赖注入的关系

参数装饰器本身不做注入，只把「哪个参数要什么」变成框架可读的信息。

- 有元数据时，注入器读取 design:paramtypes 得到参数类型并递归解析依赖；类型被擦除时必须改用显式令牌标注。
- 依赖注入并不依赖装饰器语法：装饰器只是声明入口，手写装配代码同样能完成注入。

**速记**：参数装饰器只声明需求，注入器按元数据或显式令牌解析依赖；装饰器不是依赖注入的必要条件。



### 装饰器工厂与执行顺序

**装饰器工厂**：是返回装饰器函数的函数，用于在装饰时接收配置参数并生成定制化的装饰器。

#### 装饰器工厂的写法与多装饰器的调用顺序

需要参数（前缀、令牌、路径）时，把装饰器写成「接收配置、返回装饰器」的两层函数。

- 工厂在类定义求值时先被调用一次，返回的装饰器函数随后被调用一次。
- 同一声明叠加多个装饰器时，表达式自上而下求值（工厂从上到下执行），装饰器函数自下而上调用，离声明最近的先执行。

```ts
function logCall(prefix: string) {
  console.log(`求值 ${prefix}`);
  return function (target: Object, propertyKey: string, descriptor: PropertyDescriptor): void {
    console.log(`调用 ${prefix}`);
  };
}

class UserService {
  @logCall("first")
  @logCall("second")
  findById(id: number): string { return `user-${id}`; }
}
// 求值 first
// 求值 second
// 调用 second
// 调用 first
```

**速记**：装饰器工厂是「接收配置、返回装饰器」的两层写法；求值自上而下，调用自下而上。



#### 类成员装饰器的顺序自上而下

同一个类内部，不同位置的装饰器有确定的执行次序。

- 实例成员按声明顺序自上而下处理，每个成员内部先跑参数装饰器，成员装饰器再自下而上。
- 实例成员处理完再处理静态成员，然后是构造函数参数。
- 类装饰器最后执行，因此它能读到成员装饰器写入的全部信息，反之读不到。

```ts
function step(label: string) {
  return function (...args: unknown[]): void {
    console.log(label);
  };
}

@step("类装饰器")
class Pipeline {
  @step("实例方法")
  run(): void {}
  @step("静态属性")
  static version = "1";
}
// 实例方法
// 静态属性
// 类装饰器
```

**速记**：实例成员自下而上逐个处理，然后静态成员与构造函数参数，类装饰器最后执行。



#### 装饰器与初始化顺序

装饰器全部发生在类定义求值阶段，与实例字段初始化分属两个时刻。

- 装饰器在类定义完成前执行完毕，早于任何 new 调用，因此不能依赖实例状态。
- 实例字段初始化器在构造函数中按声明顺序执行，每次实例化都重跑一遍。
- 类装饰器返回替换构造函数时，new 的实际行为由替换后的构造函数决定。

```ts
function mark(label: string) {
  return function (): void {
    console.log(label);
  };
}

@mark("类装饰器")
class InitOrder {
  @mark("实例字段")
  count = 0;
}

console.log("类定义完成");
new InitOrder();
// 实例字段
// 类装饰器
// 类定义完成
```

**速记**：装饰器在类定义阶段执行一次，早于实例化；实例字段初始化每次 new 都按声明顺序重跑。



### 元数据与框架实践

**元数据（metadata）**：是附加在类或成员上、供运行时读取的结构化描述信息；装饰器负责写入，框架负责读取。

#### reflect-metadata 与 design:type 元数据的由来

元数据由 emitDecoratorMetadata 与运行时库配合产生，不是装饰器自动带来的。

- 编译器在装饰器调用前插入元数据写入，键为 design:type、design:paramtypes、design:returntype。
- 读取需要 reflect-metadata 提供 Reflect.getMetadata；未引入该库时写入静默失效，不报错。
- 映射是近似的：number 对应 Number、string 对应 String、void 对应 undefined、数组对应 Array。

```ts
import "reflect-metadata";

function showType(target: Object, propertyKey: string): void {
  const type = Reflect.getMetadata("design:type", target, propertyKey) as { name: string };
  console.log(`${propertyKey} 的类型是 ${type.name}`); // "createdAt 的类型是 Date"
}

class LogEntry {
  @showType
  createdAt = new Date();
}
```

**速记**：design 系列元数据由 emitDecoratorMetadata 写出、reflect-metadata 读出，映射值是静态类型的近似。



#### 依赖注入与路由注册的通用思路

框架读元数据的目的有两类：把依赖装配进对象，以及把方法挂到路由表上。

- 依赖注入：装饰器写入构造函数参数类型或显式令牌，容器启动时读取并递归解析依赖，实例按令牌缓存。
- 路由注册：类装饰器记录基础路径，方法装饰器记录请求方法与子路径，启动时扫描拼装成路由表。
- 共同点是「装饰阶段只登记，启动阶段再扫描」：类装饰器最后执行，装饰阶段拼不出完整信息。

```ts
function controller(basePath: string) {
  return function (target: Function): void {
    (target as { basePath?: string }).basePath = basePath; // 登记基础路径
  };
}

function get(path: string) {
  return function (target: Object, propertyKey: string): void {
    // 装饰阶段类装饰器尚未执行，只登记相对路径，启动时再拼 basePath
    console.log(`${target.constructor.name}.${propertyKey} -> ${path}`);
  };
}

@controller("/users")
class UserController {
  @get("/:id")
  findById(): string { return "user"; }
}
// "UserController.findById -> /:id"
```

**速记**：装饰器只登记信息，容器在启动时统一扫描；依赖按参数类型解析，路由按类路径与方法路径拼装。



#### 类型擦除的限制与装饰器的定位

**类型擦除（erasure）**：指类型注解在编译后全部消失，运行时只剩 JavaScript 值。

- design:type 是按静态类型写入的近似值，泛型实参、interface、type 别名与联合类型统一退化为 Object。
- 注入令牌不能只靠类型：同名 interface 跨模块会撞车，框架普遍要求显式令牌字符串。
- 定位：装饰器是声明式的装配入口，适合日志、权限、校验、路由与注入等横切关注点，不参与类型检查。
- 运行时改写的成员在静态类型中不可见，类型与实际可能不一致，必要时用断言或运行时校验补齐。

**速记**：类型擦除让泛型与 interface 在元数据里退化成 Object；装饰器是声明式装配入口，不改变类型系统。
