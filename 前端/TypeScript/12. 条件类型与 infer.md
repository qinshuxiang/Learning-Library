## 条件类型与 infer

### 条件类型语法

#### 三目形式的类型选择与可赋值判断

**条件类型（conditional type）**：是在类型层按可赋值关系二选一的类型运算符，写法为 T extends U ? X : Y，T 是待检查的类型，U 是参照类型，判断成立取 X，不成立取 Y。

```ts
type ValueKind<T> = T extends string ? "text" : "other";
type TextKind = ValueKind<string>;   // "text"
type NumberKind = ValueKind<number>; // "other"

type NarrowToWide = "draft" extends string ? true : false; // true
type WideToNarrow = string extends "draft" ? true : false; // false
```

- extends 读作「可赋值于」，不是继承：更具体的类型能赋给更宽的类型，反过来不成立；结构化类型（本主题第 4 篇）下只看成员兼容性，不看声明关系。
- 成员更少的对象类型反而更宽，{ id: number } 不能接收 { id: number; email: string }；两个分支可以是任意类型，包括 never 与另一个条件类型。

**速记**：T extends U ? X : Y 先做一次可赋值判断，再二选一。

  

#### 嵌套条件类型

**嵌套条件类型**：是在条件类型的分支位置再写条件类型，形成 if / else if / else 链的写法。

```ts
type TypeName<T> =
  T extends string ? "string" :
  T extends number ? "number" :
  T extends readonly unknown[] ? "array" :
  "object";

type NameOfArray = TypeName<number[]>;       // "array"
type NameOfObject = TypeName<{ id: number }>; // "object"
```

- 按书写顺序自上而下判断，第一个成立的分支胜出，因此更具体的条件要写在更宽的条件之前。
- 末尾的 "object" 是兜底分支，等价于 else；把兜底写成 never 就只保留匹配成功的成员。

**速记**：嵌套条件类型是一条自上而下的分支链，首个成立的判断胜出。

  

#### 条件类型与泛型配合

**延迟求值（deferred）**：当条件类型的被检查位置是尚未绑定的类型参数时，编译器无法立即判定，会把整个条件类型保留到类型实参确定后再求值。

```ts
type Boxed<T> = T extends string ? { text: T } : { value: T };
type TextBox = Boxed<string>;   // { text: string }
type NumberBox = Boxed<number>; // { value: number }

declare function wrap<T>(input: T): Boxed<T>;
const wrappedText = wrap("hello"); // { text: string }
const wrappedNumber = wrap(42);    // { value: number }
```

- Boxed 在 T 未绑定时不求值；wrap("hello") 把 "hello" 代入后才算出 { text: string }，泛型约束（本主题第 9 篇）则限定 T 的取值范围。
- 被检查位置必须直接是类型参数才享受分发（见下一节），套进其他结构就退化为整体判断。

**速记**：类型参数未绑定则条件类型待定，实参传入后才逐分支求值。

  

#### never 作为条件类型结果

真分支写 never 的写法用于从联合中剔除成员；never 出现在被检查位置时又被分发规则特殊处理。

```ts
type DropString<T> = T extends string ? never : T;
type Kept = DropString<"a" | "b" | 1>; // 1

type RawNever = never extends string ? true : false; // true，never 可赋给任何类型
type IsNever<T> = [T] extends [never] ? true : false;
type NeverCheck = IsNever<never>; // true
```

- 真分支返回 never 时，该成员在结果并集中被吸收，这就是「过滤」效果的来源。
- never 是底部类型，直接判断 never extends string 得到 true；但把 never 交给裸类型参数会被当成空并集，结果仍是 never，所以判断 never 必须写 [T] extends [never]。

**速记**：真分支写 never 用于剔除成员，判断 never 本身要写 [T] extends [never]。

  

### 分布式条件类型

#### 裸类型参数遇联合时分发

**分布式条件类型（distributive conditional type）**：是当条件类型的被检查位置是裸类型参数、传入实参为联合类型时，编译器把每个成员分别代入求值、再把各结果合并成新联合的规则。

```ts
type ToArray<T> = T extends unknown ? T[] : never;
type Distributed = ToArray<string | number>; // string[] | number[]

type KeepString<T> = T extends string ? T : never;
type Strings = KeepString<"a" | 1 | "b">; // "a" | "b"
```

- 触发需同时满足两点：被检查位置直接写类型参数（裸），且传入的是联合类型，缺一不可。
- 分发逐成员进行，等价于对每个成员单独求值再取并集，且只在最外层条件类型上进行，分支内部的联合不会二次分发。

**速记**：裸类型参数配联合会自动逐成员分发，结果是各分支结果的并集。

  

#### 用元组包裹关闭分发

**关闭分发**：是把类型参数放进单元素元组或其他结构，使它不再是裸类型参数，条件类型于是对整体做一次判断。

```ts
type ToArrayDistributive<T> = T extends unknown ? T[] : never;
type ToArrayWhole<T> = [T] extends [unknown] ? T[] : never;

type Distributed = ToArrayDistributive<string | number>; // string[] | number[]
type Whole = ToArrayWhole<string | number>;              // (string | number)[]
```

- [T] 仍是含类型参数的复合类型，被检查位置不再是裸参数，分发条件不再成立。
- 需要判断「联合整体是否满足某条件」时必须关闭分发，需要筛选成员则正相反；[T] extends [U] 是标准库与社区代码的通行写法。

**速记**：想整体判断就写 [T] extends [U]，元组包裹即关闭分发。

  

#### never 的分发特例

never 在裸类型参数位置被当作空并集，分发结果仍是 never，既不是真分支也不是假分支。

```ts
type IsString<T> = T extends string ? true : false;
type OnNever = IsString<never>;   // never，不是 true 也不是 false
type OnString = IsString<string>; // true

type IsNever<T> = [T] extends [never] ? true : false;
type NeverCheck = IsNever<never>; // true
```

- 若按可赋值判断，never 可赋给任何类型，应当得到真分支；分发规则优先级更高，空并集没有成员可代入，故得 never。
- 关闭分发后 [never] extends [never] 成立，IsNever 才能返回 true；封装类型在传入 never 时会静默失效，边界处要显式处理。

**速记**：never 被当作空并集，分发结果仍是 never；判断 never 必须关闭分发。

  

#### 分发带来的实际影响与误判

分发既是 Exclude 这类工具类型的实现基础，也是类型编程中最常见的误判来源。

```ts
type IsString<T> = T extends string ? true : false;
type Mixed = IsString<string | number>; // boolean，即 true | false

type ExactlyString<T> = [T] extends [string] ? true : false;
type Whole = ExactlyString<string | number>; // false

type OnAny = any extends string ? "yes" : "no"; // "yes" | "no"
```

- 逐成员判断后结果合并，IsString<string | number> 得到 true | false 也就是 boolean，容易被误读为「整个联合都是 string」。
- 想判断整体必须关闭分发，想筛选成员则要利用分发；any 参与时两个分支都会保留，any extends string ? X : Y 得到 X | Y。

**速记**：分发默认逐成员，判整体要包元组，判成员就不要包。

  

### infer 推断

#### infer 只能写在 extends 子句里

**infer**：是在条件类型的 extends 子句里声明一个待推断类型变量的语法，写作 infer 加变量名，该变量只在真分支内可用。

```ts
type UnwrapPromise<T> = T extends Promise<infer V> ? V : T;
type Resolved = UnwrapPromise<Promise<number>>; // number
type Plain = UnwrapPromise<string>;             // string
```

- infer 声明的位置由模式匹配决定：写在哪里，就从对应位置推断；写在 extends 子句之外会报错。
- 变量作用域仅限真分支，假分支引用会提示找不到名称；每个 infer 都是局部变量，与外层同名类型参数不冲突，但实际代码应取不同名字。

**速记**：infer 只能在 extends 子句里声明，且只在真分支可见。

  

#### 从函数类型推断参数与返回值

函数类型的参数列表与返回值位置都能放 infer，分别得到参数元组与返回类型。

```ts
type ReturnTypeOf<T> = T extends (...args: any[]) => infer R ? R : never;
type ParametersOf<T> = T extends (...args: infer A) => any ? A : never;

function parseNumber(text: string, radix: number): number {
  return Number.parseInt(text, radix);
}
type ParseArgs = ParametersOf<typeof parseNumber>;   // [text: string, radix: number]
type ParseReturn = ReturnTypeOf<typeof parseNumber>; // number
```

- 参数位置的 infer 得到元组类型，保留参数名与可选修饰；返回类型写在箭头右侧，用 infer R 抓取，重载函数（本主题第 7 篇）取最后一个重载签名。
- 匹配模式里的参数必须写 ...args: any[] 而非 unknown[]，因为函数参数位置逆变，unknown[] 会让具体签名的函数无法匹配。

**速记**：参数位 infer 得元组，返回位 infer 得返回类型，匹配模式用 any[] 避开逆变限制。

  

#### 从数组与 Promise 推断元素类型

把数组、只读数组与 Promise 写成待匹配的模式，即可在对应位置取出元素类型。

```ts
type ElementType<T> = T extends readonly (infer E)[] ? E : never;
type NumberElement = ElementType<number[]>;            // number
type ReadonlyElement = ElementType<readonly string[]>; // string
type TupleElement = ElementType<[number, string]>;     // number | string

type UnwrapPromise<T> = T extends Promise<infer V> ? V : T;
type Value = UnwrapPromise<Promise<string>>; // string
```

- readonly (infer E)[] 同时匹配可变数组与只读数组；写成 (infer E)[] 则只匹配可变数组，只读数组落到假分支。
- 元组也匹配数组模式，元素类型取各位置类型的并集；Promise 的推断取类型实参，联合传入时会先分发再合并。

**速记**：数组用 readonly (infer E)[] 取元素，Promise 用 Promise<infer V> 取实参。

  

#### 多个 infer 与位置对应

同一条件类型可以声明多个 infer，按出现顺序与结构位置一一对应。

```ts
type SwapPair<T> = T extends [infer First, infer Second] ? [Second, First] : never;
type Swapped = SwapPair<[string, number]>; // [number, string]

type Signature<T> = T extends (first: infer F, rest: infer R) => infer Ret
  ? { first: F; rest: R; returns: Ret }
  : never;
type Parsed = Signature<(id: string, flag: boolean) => number>;
// { first: string; rest: [flag: boolean]; returns: number }
```

- 位置决定推断来源，调整 infer 的出现顺序即可重排或重组结果；剩余参数位置的 infer 得到元组，所以 rest 推断为 [flag: boolean]。
- 同一个 infer 变量出现在多个协变位置时结果为各位置的并集；出现在多个逆变位置（函数参数）时取交叉。

**速记**：每个 infer 对应一个结构位置，协变取并、逆变取交。

  

#### infer 的约束写法

**infer 约束**：是给 infer 声明的变量加 extends 约束、写作 infer K extends string 的写法，推断结果不满足约束时该分支不匹配。

```ts
type FirstStringElement<T> = T extends [infer S extends string, ...unknown[]] ? S : never;
type Matched = FirstStringElement<["draft", 1]>;  // "draft"
type Rejected = FirstStringElement<[1, "draft"]>; // never

type RecordKeys<T> = T extends Record<infer K extends string, unknown> ? K : never;
type Keys = RecordKeys<{ id: number; name: string }>; // "id" | "name"
```

- 约束在推断的同时生效，推断值不满足约束时不走真分支，因此 Rejected 得到 never 而不是报错。
- 不加约束时 infer K 会把 number 键一并推断进来，后续用 K 参与运算就可能出错；该写法自 TypeScript 4.7 起支持，旧版本需在真分支里再加一层 K extends string ? K : never 过滤。

**速记**：infer K extends string 一边推断一边校验，不满足约束就走假分支。

  

### 内置条件类型的拆解

#### 手写 Exclude 与 Extract

Exclude 与 Extract 是分发规则最直接的两个应用：一个剔除命中的成员，一个保留命中的成员，差别只在真假分支的返回值。

```ts
type MyExclude<T, K> = T extends K ? never : T;
type MyExtract<T, K> = T extends K ? T : never;

type EventName = "click" | "submit" | "reset";
type NonClick = MyExclude<EventName, "click">;              // "submit" | "reset"
type ClickOrReset = MyExtract<EventName, "click" | "reset">; // "click" | "reset"
type OnlyNumber = MyExclude<string | number | boolean, string | boolean>; // number
```

- T 位于裸类型参数位置，遇到联合自动分发，逐成员判断是否可赋给 K，命中者按分支换成 never 或原样保留。
- never 在并集中被吸收，被命中的成员就此从结果里消失；K 若是联合，任一成员命中即命中。
- 两者都不能判断联合整体是否属于 K，那种需求要写 [T] extends [K]。

**速记**：Exclude 命中换成 never，Extract 命中返回 T，都靠分发逐成员进行。

  

#### 手写 NonNullable

NonNullable 把联合中的 null 与 undefined 剔除，正是一份把右侧固定为 null | undefined 的 Exclude。

```ts
type MyNonNullable<T> = T extends null | undefined ? never : T;

type MaybeName = string | null | undefined;
type Name = MyNonNullable<MaybeName>;      // string
type Flag = MyNonNullable<boolean | null>; // boolean
type DropAll = MyNonNullable<null>;        // never
```

- 与 MyExclude 的唯一区别是 K 固定为 null | undefined，其余完全一致；分发逐成员判断，只剔除空值成员。
- 该类型不递归：若 T 是 Promise<string | null>，null 不会被去掉，要先解开 Promise 再过滤。

**速记**：NonNullable 就是 Exclude<T, null | undefined>，只削掉空值成员。

  

#### 手写 ReturnType 与 Parameters

ReturnType 与 Parameters 是一对对称类型：都在类型参数上预先加函数约束，再分别从返回位置与参数位置推断。

```ts
type MyReturnType<T extends (...args: any[]) => any> =
  T extends (...args: any[]) => infer R ? R : never;
type MyParameters<T extends (...args: any[]) => any> =
  T extends (...args: infer A) => any ? A : never;

type LoadUser = (id: string) => Promise<{ name: string }>;
type LoadedUser = MyReturnType<LoadUser>;   // Promise<{ name: string }>
type LoadUserArgs = MyParameters<LoadUser>; // [id: string]
// type BadType = MyReturnType<number>; // 报错：number 不满足函数约束
```

- 约束保证 T 一定是函数类型，传错时在声明处就报错，而不是静默返回 never；两者都取最后一个重载签名。
- MyReturnType 的 infer R 位于协变位置，结果精确到具体类型；MyParameters 的 infer A 得到含参数名与可选标记的元组。

**速记**：函数约束加位置推断，返回位置取 R、参数位置取元组 A。

  

#### 手写 Awaited

Awaited 在解开 Promise 之后还要继续递归，直到结果不再是 Promise。

```ts
type MyAwaited<T> = T extends Promise<infer V> ? MyAwaited<V> : T;

type Level1 = MyAwaited<Promise<number>>;          // number
type Level2 = MyAwaited<Promise<Promise<string>>>; // string
type Plain = MyAwaited<boolean>;                   // boolean
```

- 真分支把推断出的 V 再次交给 MyAwaited，层层剥开到基础分支为止。
- 这个简化版只识别 Promise；标准库的 Awaited 还识别带 then 方法的 thenable，并保留 null 与 undefined 不向下递归，自 TypeScript 4.5 起内置。

**速记**：MyAwaited 在真分支递归调用自身，把多层 Promise 一次剥开。

  

### 递归条件类型与限制

#### 递归展开嵌套对象与数组

**递归条件类型**：是在自己的分支里再次引用自身、对嵌套结构逐层处理的类型，必须带一个能终止递归的基础分支。

```ts
type FlattenElementType<T> = T extends readonly (infer E)[] ? FlattenElementType<E> : T;
type Nested = FlattenElementType<number[][][]>; // number
type Flat = FlattenElementType<string[]>;       // string

type DeepUnwrap<T> = T extends Promise<infer V>
  ? DeepUnwrap<V>
  : T extends object
    ? { [K in keyof T]: DeepUnwrap<T[K]> }
    : T;
type Unwrapped = DeepUnwrap<{ id: Promise<number>; tags: Promise<string>[] }>;
// { id: number; tags: string[] }
```

- 基础分支（不是数组、不是 Promise、不是对象）直接返回 T，递归在此停止，没有基础分支会无限展开。
- DeepUnwrap 借映射类型（本主题第 11 篇）逐键重建对象，条件类型负责决定何时继续下钻；数组被同态映射类型处理后仍保持数组形状，所以 tags 得到 string[]。

**速记**：递归条件类型必须先写基础分支，再在分支里安全地向内一层。

  

#### 递归深度上限与编译性能

编译器对类型实例化层数设有上限，超过后抛出 TS2589；深度与分支数还会直接拉长编译时间，两者是同一个机制的两种后果。

```ts
type Nest<T, Depth extends readonly unknown[]> =
  Depth["length"] extends 5 ? T : Nest<{ value: T }, [...Depth, unknown]>;

type FiveLevel = Nest<string, []>;
// { value: { value: { value: { value: { value: string } } } } }

// type Infinite<T> = Infinite<T[]>; // 报错 TS2589：Type instantiation is excessively deep and possibly infinite.
```

- 默认实例化深度上限约为 100 层，不同版本略有差异；自引用且没有基础分支的类型必然触顶。
- TypeScript 4.5 起对尾递归形式的条件类型做尾递归消除，可用深度提高到约 1000 层，非尾递归写法仍会较早触顶。
- 联合类型过大时分发会把每个成员都跑一遍递归，复杂度按成员数放大；深层嵌套类型还会让编辑器在补全时反复实例化，表现为卡顿与提示延迟。

> [!CAUTION]
> **注意内容**：递归条件类型应只在少数关键接口上使用并设定明确的最大深度；放进每个公共组件的 props 会显著拖慢整个项目的类型检查。

**速记**：递归深度与联合规模共同决定实例化次数，是编译期变慢的主要来源。

  

#### 写成可维护形式的建议

把递归改写成尾递归形式、显式限制深度、并拆小单个类型，是让递归条件类型可控的三项措施。

```ts
type Reverse<T extends readonly unknown[], Acc extends readonly unknown[] = []> =
  T extends readonly [infer Head, ...infer Rest]
    ? Reverse<Rest, [Head, ...Acc]>
    : Acc;

type Reversed = Reverse<[1, 2, 3]>; // [3, 2, 1]
```

- 用第二个类型参数累计中间结果，使递归调用成为真分支的全部内容，即可享受尾递归消除。
- 给递归类型加深度计数参数，达到上限时返回兜底类型，避免异常输入导致失控展开。
- 把「提取」与「重排」拆成两个小类型，减少单个类型的实例化次数；命名表达用途，如 ElementType、UnwrapPromise、DeepUnwrap。

**速记**：尾递归、累积参数、明确深度上限，是递归条件类型可控的三件套。
