## 类型注解、类型推断与类型断言

### 类型注解与上下文类型

#### 类型注解的语法位置

**类型注解**（type annotation）：是以「冒号加类型」的形式显式写在标识符之后的类型标注，用来声明该位置允许出现的值。

- 变量与常量：写在标识符之后，如 userName: string。
- 函数参数：写在参数名之后，如 date: Date。
- 函数返回值：写在参数列表之后，如 (): string。
- 对象属性与类字段：写在属性名之后。

```ts
const userName: string = "ann";

function formatDate(date: Date, locale: string): string {
  return date.toLocaleDateString(locale);
}

const toUserId = (id: number): string => String(id);

console.log(formatDate(new Date("2026-09-13"), "zh-CN")); // "2026/9/13"
console.log(toUserId(42), userName); // "42" "ann"
```

> 注解是编译器唯一能收到的人工提示：凡是编译器无法从上下文推出的类型，都必须靠注解补齐。

**速记**：注解的位置＝标识符之后、冒号加类型；变量、参数、返回值、属性四处最常用。



#### 上下文类型

**上下文类型**（contextual typing）：是编译器根据表达式所在位置的期待类型，反向推断该表达式内部类型的机制。

- 回调参数：由形参类型推断，无需手写注解。
- 对象字面量：由目标类型推断属性类型。
- 箭头函数返回值：由期待类型推断。

```ts
type Comparator = (left: number, right: number) => number;

const sortNumbers = (numbers: number[], compare: Comparator): number[] => {
  return [...numbers].sort(compare);
};

sortNumbers([3, 1, 2], (left, right) => left - right); // left、right 推断为 number

const cities: string[] = ["beijing", "shanghai"];
cities.forEach((city) => console.log(city.toUpperCase())); // city 推断为 string
```

**速记**：上下文类型＝位置的期待类型反向喂给表达式；回调参数、对象字面量都靠它免注解。



#### 注解与推断的取舍

**注解与推断的取舍**：是决定「哪些类型手写、哪些交给编译器」的工程判断。

- 无默认值的函数参数必须注解，调用处无法提供上下文。
- 对外导出的函数建议注解返回值，避免实现变化无意改变契约。
- 初始化值能唯一确定类型时交给推断，减少样板。
- 空数组、null、undefined 初始化无法推断，需要注解。

> [!TIP]
> **建议内容**：开启 noImplicitAny，让漏写注解的参数直接报错，而不是静默退化为 any。

**速记**：边界与参数写注解，局部与初始化留给推断；空容器必须写元素类型。



### 类型推断

#### 变量的类型推断

**类型推断**（type inference）：是编译器在没有显式注解时，根据初始化值、赋值语句与控制流自行确定表达式类型的机制。

- const 声明：推断为字面量类型，且不再拓宽。
- let 声明：字面量被拓宽为基础类型。
- 声明与赋值分离时：按赋值语句推断，之后不再改变。

```ts
const appName = "learning-library"; // "learning-library"
let visitCount = 0;                 // number
const isReady = true;               // true
let tags = ["ts", "js"];            // string[]

// appName = "other";  // 报错：不能给 "learning-library" 赋值
visitCount = 10;

console.log(appName, visitCount, isReady, tags.length); // learning-library 10 true 2
```

> const 之所以保留字面量类型，是因为它不会再被赋值；let 随时可能被改写，因此必须拓宽。

**速记**：变量推断看初始化值；const 留字面量，let 拓宽为基础类型。



#### 函数返回值推断

**函数返回值推断**：是编译器根据所有 return 语句归纳函数返回类型的机制。

- 有多个 return：取各返回值类型的最佳公共类型。
- 没有 return：推断为 void。
- 提前 return 与分支 return：共同参与归纳。

```ts
function getGreeting(hour: number) {
  if (hour < 12) {
    return "good morning";
  }
  return "good afternoon";
} // 返回类型推断为 string

function logMessage(message: string) {
  console.log(message);
} // 返回类型推断为 void

console.log(getGreeting(9)); // "good morning"
```

> 内部函数依赖返回值推断可以减少噪音；对外导出的函数补上返回类型注解，等于把实现与契约分开。

**速记**：返回值推断＝所有 return 的公共类型；无 return 即 void；公共 API 建议显式注解。



#### 最佳公共类型

**最佳公共类型**（best common type）：是编译器面对多个候选类型时选取的、能同时容纳全部候选的类型；找不到合适候选时退回联合类型。

- 数组字面量：逐元素归纳候选。
- 候选存在共同基础类型：取该基础类型。
- 无共同类型：生成联合类型。

```ts
const counts = [1, 2, 3];             // number[]
const mixedValues = [1, "two", true]; // (string | number | boolean)[]
const nullableCounts = [1, null];     // (number | null)[]

console.log(counts.length, mixedValues.length, nullableCounts.length); // 3 3 2
```

**速记**：多候选先找公共类型，找不到就用联合；空数组别依赖推断。



#### 字面量拓宽

**字面量拓宽**（widening）：是把字面量类型放宽为基础类型的推断行为，只发生在可变位置。

- let 变量：拓宽，"pending" 变成 string。
- const 变量：不拓宽，保留 "pending"。
- 对象属性：属性可写，值被拓宽。

```ts
let requestStatus = "pending";   // string
const defaultStatus = "pending"; // "pending"

const httpConfig = { method: "GET", timeout: 3000 };
// httpConfig.method 的类型是 string，不是 "GET"

httpConfig.method = "POST"; // 允许，因为已拓宽

console.log(requestStatus, defaultStatus, httpConfig.method); // pending pending POST
```

> 若要在对象上保留字面量类型、阻止拓宽，使用 const 断言（as const）；const 断言的完整语义归本主题第 5 篇。

**速记**：可变位置会拓宽；const 变量与 as const 不拓宽。



### 类型断言

#### as 语法与尖括号写法

**类型断言**（type assertion）：是在编译期指定表达式类型的语法，写法为「表达式 as 类型」，旧式写法是把类型放进尖括号前置。

- 只影响编译器对该表达式类型的判断，不改动运行时值。
- 断言的类型必须与原类型存在充分重叠，否则报错。
- 尖括号写法在 .tsx 文件中会被解析成 JSX 元素，无法使用。
- 多数团队规范统一要求 as，避免文件类型变化导致语法失效。

```ts
const container = document.getElementById("app") as HTMLDivElement;
container.style.display = "none";

const pageTitle = <string>"typescript"; // .ts 中可用，.tsx 中会与 JSX 冲突
console.log(pageTitle.toUpperCase());   // TYPESCRIPT
```

> [!CAUTION]
> **注意内容**：在 .tsx 文件中尖括号断言会与 JSX 语法冲突导致解析失败，项目里统一使用 as 可以免去这层隐患。

**速记**：as 写法＝表达式 as 类型；尖括号只在 .ts 可用，.tsx 必须用 as。



#### 断言的本质是关闭检查而非转换

**类型断言不执行任何类型转换**：它只让编译器停止对表达式做类型校验，运行时的值保持原样。

- 断言后变量仍是原来的值，typeof 结果不变。
- 真实转换要用 Number、String、Boolean 等转换函数。
- 断言出错不抛异常，错误会推迟到使用该值的位置。

```ts
const rawValue: unknown = "42";
const numericValue = rawValue as number;

console.log(typeof numericValue); // "string"，断言没有转换
console.log(numericValue + 1);    // "421"，字符串拼接

const actualNumber = Number(rawValue);
console.log(actualNumber + 1);    // 43
```

> 把断言当成转换是最常见的误用：它只改类型标注，不改运行时行为。

**速记**：断言＝关检查，不是转换；要转换请用显式转换函数。



#### 双重断言与 unknown 中转

**双重断言**：是当两个类型缺乏重叠关系时，先断言为 unknown 再断言为目标类型、从而绕过检查的写法。

- 直接跨类型断言会报错，编译器认为这是笔误。
- unknown 中转可以打通任意两个类型，编译期不再阻拦。
- 代价是彻底放弃检查，运行时的错误只能靠测试发现。

```ts
const textValue = "hello" as number; // 报错：string 与 number 无充分重叠
const forcedNumber = "hello" as unknown as number;

const emailInput = document.querySelector("#email") as unknown as HTMLInputElement;

console.log(typeof forcedNumber); // "string"，值仍是字符串
console.log(emailInput?.tagName); // "INPUT"
```

> [!WARNING]
> **警告内容**：双重断言几乎总是关闭检查的信号，它不会让值变得可用，只会把运行时的类型错误推迟到更远的位置。

**速记**：跨类型断言需 unknown 中转，能用但基本等于放弃检查。



#### 断言与类型守卫的取舍

**类型守卫**（type predicate）：是在运行时检查值的类型、并让编译器跟随该检查收窄类型的机制，形式为返回类型写成「参数名 is 类型」的函数，完整收窄手段归本主题第 8 篇。

- 类型断言：编译期声明，零运行时成本，判断错了没有任何提示。
- 类型守卫：运行时校验，有少量成本，检查结果与实际一致。
- 数据来源可信用断言，数据来自网络或用户输入用守卫。

```ts
const unknownPayload: unknown = { name: "ann" };

const forcedPayload = unknownPayload as { name: string };
console.log(forcedPayload.name.toUpperCase()); // ANN

function isRecordWithName(value: unknown): value is { name: string } {
  return typeof value === "object" && value !== null && "name" in value;
}

if (isRecordWithName(unknownPayload)) {
  console.log(unknownPayload.name.toUpperCase()); // ANN
}
```

> 选择标准只有一条：这个类型是编译器推不出来、还是运行时才知道。前者用断言，后者用守卫。

**速记**：断言靠人担保，守卫靠代码检查；外部数据优先写守卫。



### 非空断言与确定赋值断言

#### 非空断言的后缀感叹号

**非空断言**（non-null assertion）：是在表达式后加感叹号、从类型中剔除 null 与 undefined 的语法。

- 写法为「表达式 !」，紧跟在表达式之后。
- 只影响类型，不做任何运行时判空。
- 值实际为 null 时，运行时仍会抛错。

```ts
function getFirstCharacter(text: string | null): string {
  return text!.charAt(0);
}

function findUserNameById(users: Map<number, string>, id: number): string {
  return users.get(id)!.toUpperCase();
}

const users = new Map<number, string>([[1, "ann"]]);

console.log(getFirstCharacter("typescript")); // "T"
console.log(findUserNameById(users, 1));      // "ANN"
// console.log(getFirstCharacter(null));       // 运行时抛错：Cannot read properties of null
```

> 后缀感叹号表达的是「已经确认这里不为空」的承诺，而不是「请把空值去掉」的操作。

**速记**：后缀感叹号＝从类型里删掉 null 与 undefined，运行时不检查。



#### 确定赋值断言

**确定赋值断言**（definite assignment assertion）：是在变量声明后加感叹号、告诉编译器「该变量会在使用前被赋值」的语法，用于跳过使用前赋值检查。

- 写法为「let 变量名 !: 类型」，感叹号在标识符与冒号之间。
- 最常用于类字段：初始化发生在构造函数之外。
- 不产生任何运行时代码，只跳过检查。

```ts
class PollingService {
  private timerId!: number;

  start(interval: number): void {
    this.timerId = setInterval(() => console.log("polling"), interval);
  }

  stop(): void {
    clearInterval(this.timerId);
  }
}
```

> 确定赋值断言让编译器跳过 strictPropertyInitialization 与「使用前赋值」检查，赋值责任完全落回写代码的人。

**速记**：声明后加感叹号＝承诺使用前已赋值，多用于类字段。



#### 它们掩盖的真实问题

**两种断言的共同代价**：它们都不改变运行时行为，只是让编译器不再报告「可能为 null」或「可能未赋值」，因此被掩盖的往往是真实缺陷。

- 「可能为 null」多指向控制流缺口：某条分支漏了赋值。
- 「可能未赋值」多指向初始化顺序问题：赋值被条件跳过。
- 运行时报错的位置常与断言位置相距很远，排查成本更高。

```ts
function getFirstCharacterSafe(text: string | null): string {
  if (text === null || text.length === 0) {
    return "";
  }
  return text.charAt(0); // 收窄后无需感叹号
}

console.log(getFirstCharacterSafe(null));         // ""
console.log(getFirstCharacterSafe("typescript")); // "t"
```

> [!IMPORTANT]
> **重要内容**：每使用一次感叹号，都应当能说清为什么该值不可能为空；把它当作消除报错的手段，等于把编译期错误换成了运行期错误。

**速记**：感叹号掩盖的是控制流缺口；能补默认值或提前收窄就别用它。



### satisfies 运算符

#### satisfies 与 as 的区别

**satisfies**：是用左侧表达式的推断类型去校验右侧目标类型、并保留表达式自身推断结果的操作符，写法为「表达式 satisfies 类型」。

- 类型注解：既校验又改变类型，变量类型变成注解的类型。
- as 断言：改变编译器认定的类型，只做兼容性检查。
- satisfies：做完整校验，但不改变推断结果。
- satisfies 需要 TypeScript 4.9 及以上版本。

```ts
type AppConfig = { port: number; host: string };

const configWithAnnotation: AppConfig = { port: 8080, host: "localhost" };
const configWithSatisfies = { port: 8080, host: "localhost" } satisfies AppConfig;

console.log(configWithAnnotation.port, configWithSatisfies.port); // 8080 8080
```

> 一句话区分：注解换类型，as 强改类型，satisfies 只校验、不动推断结果。

**速记**：注解换类型、as 改类型、satisfies 只校验不改类型。



#### 既校验又保留字面量类型

**保留字面量类型**：是 satisfies 在通过校验之后，仍让表达式保持窄推断的特性，键名、字面量与元组长度都不会被抹平。

- 对象键名保留：拼写错误能在编译期被拦下。
- 属性字面量保留：得到具体字面量而非基础类型。
- 元组长度保留：可以按位置访问。

```ts
type ThemeColorMap = Record<string, string>;

const themeColors = {
  primary: "#1d7af3",
  danger: "#e5484d"
} satisfies ThemeColorMap;

const annotatedColors: ThemeColorMap = { primary: "#1d7af3", danger: "#e5484d" };

console.log(themeColors.primary); // "#1d7af3"，键名被保留
// themeColors.primry;  // 报错：属性 primry 不存在，拼写错误被拦下

console.log(annotatedColors.primry); // 编译通过，运行时为 undefined
```

> 注解版本退化为字符串索引签名，任何键名都能通过检查；satisfies 版本记住具体键，拼写错误在编译期暴露。

**速记**：satisfies 校验完仍保留窄类型，键名与字面量都还在。



#### 配置对象的典型用法

**配置对象场景**：是 satisfies 最典型的落点，因为配置既需要结构校验，又需要在后续代码里保留具体键与具体类型。

- 路由表、事件处理器表：校验每个值都是正确签名。
- 主题、常量表：校验值符合允许的字面量集合。
- 值写错时报错信息直接指向该属性，无需额外断言。

```ts
type RouteHandler = (path: string) => string;
type RouteTable = Record<string, RouteHandler>;

const routes = {
  home: (path: string) => `home:${path}`,
  profile: (path: string) => `profile:${path}`
} satisfies RouteTable;

console.log(routes.home("/index"));  // "home:/index"
console.log(routes.profile("/ann")); // "profile:/ann"

// routes.setting;   // 报错：属性 setting 不存在
// const invalidRoutes = { home: "/index" } satisfies RouteTable;
// 报错：string 不能赋给 RouteHandler
```

**速记**：配置对象用 satisfies，既能查出值写错，又能保留键名做精确访问。
