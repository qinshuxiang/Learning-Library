## 函数类型、重载与 this

### 函数类型的写法

函数类型描述一个值接受哪些参数、返回什么结果，是回调与接口成员之间传递契约的基本单位。

#### 参数与返回值的标注

**函数类型注解**：在参数名后标参数类型、在参数列表右括号后标返回值类型，函数声明与箭头函数写法一致。

```ts
function formatPrice(amount: number, currency: string): string {
  return currency + amount.toFixed(2);
}
const double = (value: number): number => value * 2;
console.log(formatPrice(12.5, "$"), double(3)); // "$12.50" 6
```

- 参数类型不可省略，除非能从上下文推断；返回值类型可省略交由推断，对外暴露的 API 建议显式写出。
- 标注为 void 时不要求 return，标注为其他类型时每条返回路径都必须有返回值。

**速记**：参数逐个标注、返回值写在括号之后，声明与箭头函数共用同一套写法。



#### 函数类型表达式

**函数类型表达式**：用箭头语法单独描述一个可调用值的类型，形如参数列表加箭头再加返回值类型。

```ts
type OnFinished = (result: string) => void;
let convert: (value: number) => string = String;
console.log(convert(42)); // "42"
```

- 类型里的参数名只是占位，只写类型也合法，例如 (number) => string。
- 返回值位置写 void 表示调用方不关心返回值，函数体仍可返回任意值。

**速记**：单独描述可调用值用箭头语法，参数名可省，返回值位置必写。



#### 用接口或类型别名描述可调用对象

**可调用对象**：自身可以被调用的值。描述它可以用函数类型别名，也可以用只含调用签名的接口。

```ts
type Comparator = (left: number, right: number) => number;
interface StringPredicate { (input: string): boolean; }
const byAscending: Comparator = (left, right) => left - right;
const isNotEmpty: StringPredicate = (input) => input.length > 0;
console.log([3, 1, 2].sort(byAscending), isNotEmpty("ts")); // [1, 2, 3] true
```

- 类型别名与只含调用签名的接口完全等价，可以互相赋值。
- 需要在可调用的同时附带其他属性时，用接口把调用签名与普通成员写在一起。
- 调用签名与构造签名的完整语法归本主题第 4 篇。

**速记**：可调用对象用函数类型别名或带调用签名的接口描述，两者完全等价。



#### 属性的可调用成员

**可调用成员**：对象里类型为函数的属性，方法写法与函数类型属性写法都能描述它。

```ts
interface EventHandlers {
  onOpen(event: string): void;      // 方法写法
  onClose: (code: number) => void;  // 函数类型属性写法
}
const handlers: EventHandlers = { onOpen: (event) => console.log(event), onClose: () => {} };
handlers.onOpen("menu"); // "menu"
```

- 两种写法调用上等价，区别在参数兼容检查：方法成员按双变处理，函数类型属性在 strictFunctionTypes 下按逆变检查。
- 方法成员不能加 readonly，函数类型属性可以加。

**速记**：可调用成员用方法写法或函数类型属性写法，差异在参数检查与能否 readonly。



### 参数的可选、默认与剩余

参数列表的三种伸缩形式决定一个函数能接受几种调用形态，是重载之外最常用的表达手段。

#### 可选参数与位置约束

**可选参数**：参数名后加问号，调用时可以不传，读取时类型自动包含 undefined。

```ts
function greetUser(name: string, title?: string): string {
  return title ? title + " " + name : name;
}
console.log(greetUser("lin"), greetUser("lin", "Dr.")); // "lin" "Dr. lin"
// function broken(optional?: string, required: string) {} // 报错：可选参数不能在必选参数之前
```

- 可选参数必须排在全部必选参数之后，同一段末尾可以连续出现多个问号参数。
- 写成 string | undefined 的必选参数必须显式传值，不能像问号参数那样直接省略。

**速记**：问号表示可以省略、读取带 undefined，且只能出现在必选参数之后。



#### 默认参数与推断

**默认参数**：在参数位置赋初值，未传实参或传入 undefined 时使用默认值，该参数自动视为可选。

```ts
function createRetryPolicy(maxRetries = 3, delayMs = 500): { maxRetries: number; delayMs: number } {
  return { maxRetries, delayMs };
}
console.log(createRetryPolicy().delayMs); // 500
```

- 默认值能推断出类型时不必再写注解；无法推断时仍需显式标注。
- 同一个参数不能既写问号又写默认值，传 null 也不会触发默认值。

**速记**：默认值让参数自动可选并提供类型，undefined 触发默认值而 null 不会。



#### 剩余参数的类型

**剩余参数**：用三个点把任意数量的实参收集成数组，类型必须标注为数组类型。

```ts
function sumNumbers(...values: number[]): number {
  return values.reduce((total, value) => total + value, 0);
}
console.log(sumNumbers(1, 2, 3), sumNumbers()); // 6 0
```

- 一个函数最多一个剩余参数，且必须位于参数列表最后。
- 剩余参数可配元组类型表达固定前缀加不定后缀，元组细节归本主题第 6 篇。

**速记**：剩余参数把实参收集为数组，必须写成数组类型且只能有一个、只能放最后。



#### 参数解构的类型标注

**参数解构**：把对象或数组参数直接解构成局部变量，类型标在整个解构模式上。

```ts
function renderBadge({ label, count = 0 }: { label: string; count?: number }): string {
  return label + "(" + count + ")";
}
console.log(renderBadge({ label: "star" })); // "star(0)"
```

- 解构参数要标注整个对象的形状，不能只标注其中某个成员。
- 解构里写的默认值同时表达该成员可选；形状多处复用时先抽出接口或类型别名。

**速记**：解构参数标注整个对象形状，解构内的默认值同时表达可选。



### 回调与高阶函数的类型

回调的类型往往不由自身书写，而由接收它的 API 上下文给出，这一节说明推断与兼容规则。

#### 回调参数由上下文推断

**上下文类型（contextual typing）**：调用位置上的函数类型为传入的回调提供参数与返回值类型，回调不必重复标注。

```ts
const ids = ["aa", "b", "ccc"];
console.log(ids.map((id) => id.length)); // [2, 1, 3]
```

- map 的签名把回调参数定为 string、返回值定为任意类型，参数写 id 时已推断为 string。
- 回调用法与上下文冲突时报错；完全脱离上下文的回调参数在严格模式下按隐式 any 报错。

**速记**：回调的类型从调用位置的函数类型推断，不必手写参数与返回值。



#### 返回 void 的回调为何可接受有返回值的函数

**void 返回值回调**：声明为返回 void 的函数类型可以接受任何返回值的函数，此时返回值被调用方忽略。

```ts
type Notifier = (message: string) => void;
const toLength = (message: string) => message.length;

const notify: Notifier = toLength; // 合法：number 返回值被忽略
notify("typescript"); // 返回值丢弃，不报错
```

- 这是 void 返回类型的特殊规则，只作用于函数返回值位置。
- 反方向不成立：声明返回 number 的回调不能接收返回 void 的函数。

> [!TIP]
> 建议内容：不关心回调返回值时把参数类型写成返回 void，可以同时接受有返回值与无返回值的函数。

**速记**：返回 void 的函数类型接收任何返回值的函数，因为调用方不用返回值，反向不成立。



#### 函数参数的双变与逆变初识

**逆变（contravariance）**：函数参数按与返回值相反的方向兼容，参数类型更宽的函数可以赋给参数类型更窄的函数类型。**双变（bivariance）** 则两个方向都允许通过。

```ts
type Animal = { name: string };
type Dog = Animal & { bark: () => void };

const handleAnimal = (animal: Animal) => console.log(animal.name);
const handleDog: (dog: Dog) => void = handleAnimal; // 合法：参数更宽
// const handleAny: (animal: Animal) => void = (dog: Dog) => dog.bark(); // 报错：参数更窄
```

- 开启 strictFunctionTypes 后函数类型属性的参数按逆变检查，strict 模式默认包含该开关。
- 方法成员与构造函数参数仍按双变检查，这是为兼容既有类库刻意保留的设计。

> [!WARNING]
> 警告内容：把只接受更具体类型的函数当成通用回调使用，编译期不会报错，问题要到运行时传入不匹配的值才暴露。

**速记**：strictFunctionTypes 下函数类型属性的参数按逆变检查，方法成员仍按双变。



#### 函数类型作为参数的常见包装器

**高阶函数**：接收函数作为参数、或返回一个函数的函数，用来包装、延时或增强原函数行为。

```ts
function once(action: () => void): () => void {
  let called = false;
  return () => { if (!called) { called = true; action(); } };
}
const initOnce = once(() => console.log("init"));
initOnce(); // "init"
initOnce(); // 不再执行
```

- 参数位置写函数类型描述回调形状，避免使用不含参数信息的 Function 类型。
- 返回值位置写函数类型描述包装后的新函数，接收与返回都是函数即形成装饰链。
- 装饰器本质是一类特殊的高阶函数，完整机制见本主题第 15 篇。

**速记**：高阶函数在参数与返回值位置写函数类型，用 Function 类型会丢失全部检查。



### 函数重载

同一个名字在不同参数组合下返回不同类型时，用重载描述入参与返回值之间的对应关系。

#### 重载签名与实现签名

**重载签名（overload signature）**：只有参数与返回值、没有函数体的函数头；**实现签名（implementation signature）** 是最后带函数体的那一个，不直接对外可见。

```ts
function formatInput(value: string): string;
function formatInput(value: number): string;
function formatInput(value: string | number): string {
  return typeof value === "string" ? value.trim() : value.toFixed(2);
}
console.log(formatInput("  hi  "), formatInput(3.14159)); // "hi" "3.14"
```

- 重载签名至少写一条，实现签名恰好一条且位于所有重载签名之后。
- 实现签名的参数必须能覆盖全部重载签名，返回值也要与每条重载签名兼容。
- 实现签名不参与调用解析，只按实现签名传参同样报错。

**速记**：重载签名只声明不实现、实现签名最后且必须覆盖全部重载，对外不可见。



#### 调用解析按顺序匹配

**调用解析**：编译器从上到下用重载签名依次匹配实参，取第一个匹配成功的签名作为调用结果。

```ts
function pickValue(value: string): string;
function pickValue(value: number): number;
function pickValue(value: string | number): string | number {
  return value;
}
console.log(pickValue(10), pickValue("ten").length); // 10 3
```

- 匹配只看实参与参数列表，不比较或推断返回类型。
- 更具体的签名要写在前面，否则会被更宽的签名提前截获，后面的签名长期轮不到。
- 全部签名都不匹配时报错，错误信息会列出所有重载签名。

**速记**：调用解析自上而下取第一个匹配的重载签名，具体签名必须排在前面。



#### 重载与联合参数的取舍

**联合参数**：把多种参数类型合并成一个联合类型，用一个签名接收全部情况，与重载是两种表达手段。

```ts
function formatInput(value: string | number): string {
  return typeof value === "string" ? value.trim() : value.toFixed(2);
}
console.log(formatInput("  ts  ") + formatInput(3)); // "ts3.00"
```

- 各情况的返回类型相同，或返回类型与入参类型没有对应关系时，联合参数更简洁。
- 返回值随入参变化时重载才表达得出对应关系，例如 string 进 string 出、number 进 number 出。
- 改用联合参数会丢失入参类型到返回类型的精确对应，调用方需自行收窄。

**速记**：返回类型不随入参变化用联合参数，需要精确对应关系才用重载。



#### 重载在方法中的写法

类与接口中的重载写法与独立函数一致，重载签名与实现签名都写在同一个类体内。

```ts
class TextSearch {
  find(text: string, keyword: string): number;
  find(text: string, keyword: string, fromIndex: number): number;
  find(text: string, keyword: string, fromIndex = 0): number {
    return text.indexOf(keyword, fromIndex);
  }
}
console.log(new TextSearch().find("typescript", "script")); // 4
```

- 接口里的方法重载只写重载签名，不写实现，见本主题第 4 篇。
- 类中实现签名只写一次，位于所有重载签名之后。

**速记**：类与接口里的重载与独立函数同构，接口只写签名、类由实现签名收尾。



#### 常见误用与替代方案

重载容易被写成参数组合的穷举，滥用后签名列表难以维护，多数场景有更轻的替代写法。

```ts
// 反例：用可选参数拼出多种含义，返回值只能靠调用方猜
// function parseInput(input: string, mode?: "json" | "csv"): string | number[];

// 正解：入参是同一概念的不同取值，改用字面量联合
function parseInput(input: string, mode: "json" | "csv" = "json"): string | string[] {
  return mode === "json" ? input : input.split(",");
}
console.log(parseInput("a,b", "csv")); // ["a", "b"]
```

- 误用一：用可选参数或多个 any 硬凑签名，看似灵活实则不做检查。
- 误用二：把实现签名当作对外契约，按实现签名的联合参数调用会报错。
- 误用三：多条重载签名参数范围重叠，靠顺序互相遮挡，调用结果与直觉不符。
- 替代：参数是同一概念的不同取值时用字面量联合，收窄见本主题第 8 篇；需要按入参精确决定返回类型时用条件类型，见本主题第 12 篇。

> [!IMPORTANT]
> 重要内容：重载签名与实现签名不一致会直接报错，改动实现签名时必须同步核对每一条重载签名。

**速记**：重载只用于入参与返回值需要精确对应的场景，其余情况优先字面量联合或条件类型。



### this 参数与 this 类型

函数体里的 this 默认不受检查，显式 this 参数与 this 类型分别解决校验 this 形状与保留调用者类型两个问题。

#### 显式 this 参数的位置与作用

**this 参数**：写在参数列表最前面的伪参数，用来声明函数体内 this 的类型，不占实参位置，编译后消失。

```ts
function formatWithThis(this: { prefix: string }, value: number): string {
  return this.prefix + value.toFixed(1);
}
const formatter = { prefix: "$", format: formatWithThis };
console.log(formatter.format(12.345)); // "$12.3"
```

- this 参数必须是参数列表的第一项，调用时不需要也不能为它传实参。
- 只参与编译期检查，编译产物的参数列表里没有它。
- 把带 this 参数的函数赋给 this 形状不匹配的对象会立即报错。

**速记**：this 参数放在参数列表首位、不占实参、编译后消失，只做 this 形状检查。



#### noImplicitThis

**noImplicitThis**：tsconfig 中的严格性开关，开启后无法推断 this 类型的情景直接报错，而不是把它当作 any。

```ts
function describePlain(): string {
  // return this.title; // 报错：this 隐式为 any，类型无法推断
  return "no-this";
}
const counter = { value: 0, increase() { this.value += 1; return this.value; } };
console.log(counter.increase()); // 1
```

- 关闭时函数里的 this 一律当 any，成员名拼错也无法发现。
- 对象方法与类方法中的 this 有明确上下文，不受影响；箭头函数没有自己的 this，取的是外层值。

**速记**：noImplicitThis 让无法推断的 this 报错而非退回 any，strict 模式下默认开启。



#### this 类型在链式调用与建造者中的多态用法

**this 类型**：把返回位置写成关键字 this，表示调用者的实际类型，使子类调用后仍保留自身类型。

```ts
class QueryBuilder {
  protected clauses: string[] = [];
  where(condition: string): this {
    this.clauses.push(condition);
    return this;
  }
  build(): string { return this.clauses.join(" AND "); }
}
class PagedQueryBuilder extends QueryBuilder {
  limit(count: number): this { this.clauses.push("LIMIT " + count); return this; }
}
console.log(new PagedQueryBuilder().where("status = 1").limit(10).build()); // "status = 1 AND LIMIT 10"
```

- 返回类型写成 this 时 where 的结果是调用者的实际类型，因此后续能继续调用 limit。
- 返回类型若写成类名，子类调用 where 后类型退化为基类，子类专属方法会被隐藏。
- 同一手法适用于流式 API、建造者与静态工厂；接口中同样可以用 this 描述多态返回。

**速记**：返回位置写 this 让链式调用保留调用者的实际类型，写死类名会在子类处丢失类型。
