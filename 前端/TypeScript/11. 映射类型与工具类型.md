## 映射类型与工具类型

### 映射类型的语法

#### 遍历键联合的写法

**映射类型（mapped type）**：是遍历一个键联合、为每个键生成同名属性并指定属性类型，从而构造出新对象类型的类型运算符。

```ts
type User = { id: number; name: string; active: boolean };

type Stringify<T> = { [K in keyof T]: string };
type StringifiedUser = Stringify<User>; // { id: string; name: string; active: string }

type Direction = { [K in "asc" | "desc"]: boolean }; // { asc: boolean; desc: boolean }
```

- 骨架是 { [K in 键联合]: 值类型 }：K 逐键取值，keyof T 提供键联合，细节见本主题第 10 篇。
- 键来源也可直接写字面量联合；值类型里可引用 K 与 T[K]，让属性按自身类型变形。

**速记**：映射类型写成 { [K in 键联合]: 值类型 }，键联合通常来自 keyof T。



#### 用 readonly 与 ? 修饰符

readonly 写在键参数前、? 写在键参数后，为结果里的每个属性统一加上对应修饰；加号可省略，减号用于删除已有修饰符。

```ts
type Options = { readonly host: string; port?: number };

type LooseOptions = { [K in keyof Options]?: Options[K] };        // host?: string, port?: number
type FrozenOptions = { readonly [K in keyof Options]: Options[K] }; // readonly host, readonly port?
type MutableOptions = { -readonly [K in keyof Options]: Options[K] }; // host: string, port?: number
type CompleteOptions = { [K in keyof Options]-?: Options[K] };      // readonly host, port: number
```

- 两个修饰符写在键参数两侧，可单独使用也可同写，得到「可选且只读」的对象类型。
- -readonly 与 -? 删除修饰符，去掉本来不存在的修饰符不会报错；内置的 Required 与 Readonly 用的就是这套写法。

**速记**：减号删修饰符、加号加修饰符，同态映射下覆盖原属性的修饰状态。



#### 键重映射 as

**键重映射**：是在键参数后用 as 子句改写键名，写作 { [K in keyof T as 新键]: 值类型 }；新键计算为 never 时该属性被删除。

```ts
type LegacyRecord = { oldId: number; oldTitle: string };
type KeyAlias = { oldId: "id"; oldTitle: "title" };

type ModernRecord<T, Alias extends Record<keyof T, PropertyKey>> = { [K in keyof T as Alias[K]]: T[K] };
type Modern = ModernRecord<LegacyRecord, KeyAlias>; // { id: number; title: string }
```

- as 右侧是任意能求出键类型的表达式，常见形式是查表 Alias[K] 或条件判定。
- 新键为 never 表示删除该属性；新键仍限于 string、number、symbol 三个系列。

**速记**：as 子句决定结果里的键名，返回 never 就是删除该键。



#### 同态映射与非同态映射

**同态映射**：是形如 { [K in keyof T]: ... }、以 keyof T 为键来源的映射类型，编译器保留 T 原有的可选性与只读性并逐键对应。
**非同态映射**：是键来源不是 keyof T（手写字面量联合或 keyof 另一类型）的映射类型，结果不继承原属性的修饰符。

```ts
type Draft = { readonly id: number; title?: string };

type CopyByIdentity = { [K in keyof Draft]: Draft[K] };
// 同态：{ readonly id: number; title?: string }

type RebuiltByHand = { [K in "id" | "title"]: Draft[K] };
// 非同态：{ id: number; title: string | undefined }，修饰符丢失
```

- 同态映射原样复制键与修饰符，Partial、Readonly、Required 的行为都建立在这一特性上。
- 非同态映射适合由固定字段清单构造全新类型，但可选与只读必须自己补；判断标准只有键来源是否为 keyof T。

**速记**：同态保修饰符，非同态丢修饰符，看键来源是不是 keyof T。



#### 用 never 过滤键

映射类型没有专门的筛选语法，过滤键靠 as 子句把不需要的键重映射成 never，编译器随即删除该属性。

```ts
type FeatureFlags = { darkMode: boolean; betaBanner: boolean; maxItems: number; title: string };

type WithoutBooleans<T> = { [K in keyof T as T[K] extends boolean ? never : K]: T[K] };
type NumericAndText = WithoutBooleans<FeatureFlags>; // { maxItems: number; title: string }
```

- as 子句里成立分支写 K、不成立分支写 never 即「保留型过滤」，两支对调即「剔除型过滤」。
- 判定表达式是条件类型，语法与分配规则见本主题第 12 篇，本篇只把它当过滤开关使用。

**速记**：保留键写 K、丢弃键写 never，过滤即由 as 子句完成。



### 内置工具类型清单

**工具类型（utility type）**：是 TypeScript 标准库内置的一批泛型类型别名，用映射类型与条件类型封装了常见的类型变换。下面按作用对象分三类列出 13 个常用工具类型。

#### 属性修饰类：Partial 与 Required 与 Readonly 与 Record

**Partial<T>**：是把 T 的每个属性都变成可选的工具类型。
**Required<T>**：是把 T 的每个可选属性都变成必填的工具类型。
**Readonly<T>**：是把 T 的每个属性都变成只读的工具类型。
**Record<K, V>**：是构造键来自 K、值类型为 V 的对象类型的工具类型。

```ts
type Settings = { theme: string; fontSize: number };

type PartialSettings = Partial<Settings>;          // { theme?: string; fontSize?: number }
type RequiredSettings = Required<PartialSettings>; // { theme: string; fontSize: number }
type ReadonlySettings = Readonly<Settings>;        // { readonly theme: string; readonly fontSize: number }
type ThemeConfig = Record<"light" | "dark", string>; // { light: string; dark: string }
```

- 前三个作用于已有对象类型，改的是修饰符而不是值类型。
- Record 的键参数取 string、number、symbol 及其子集，值类型可任意。

**速记**：Partial 加可选、Required 去可选、Readonly 加只读、Record 造表。



#### 选取与过滤类：Pick 与 Omit 与 Exclude 与 Extract 与 NonNullable

**Pick<T, K>**：是从 T 中挑出键属于 K 的属性、组成新对象类型的工具类型。
**Omit<T, K>**：是从 T 中剔除键属于 K 的属性、保留其余属性的工具类型。
**Exclude<T, U>**：是从联合类型 T 中去掉可赋给 U 的成员的工具类型。
**Extract<T, U>**：是从联合类型 T 中保留可赋给 U 的成员的工具类型。
**NonNullable<T>**：是从 T 中去掉 null 与 undefined 的工具类型。

```ts
type Account = { id: number; email: string; password: string };
type PublicAccount = Pick<Account, "id" | "email">; // { id: number; email: string }
type AccountDraft = Omit<Account, "password">;       // { id: number; email: string }

type Status = "idle" | "loading" | "success" | "error";
type DoneStatus = Extract<Status, "success" | "error">;    // "success" | "error"
type PendingStatus = Exclude<Status, "success" | "error">; // "idle" | "loading"

type Name = NonNullable<string | null | undefined>; // string
```

- Pick 与 Omit 作用于对象类型，K 分别是 keyof T 与 keyof any 的子集。
- Exclude、Extract、NonNullable 作用于联合类型，对对象类型使用只会原样返回或得到 never。

**速记**：Exclude 减成员、Extract 留成员、NonNullable 去空值，都作用在联合上。



#### 函数与构造类：Parameters 与 ReturnType 与 InstanceType 与 Awaited

**Parameters<F>**：是取出函数类型 F 的参数、组成带标签元组的工具类型。
**ReturnType<F>**：是取出函数类型 F 的返回类型的工具类型。
**InstanceType<C>**：是取出构造签名类型 C 的实例类型的工具类型。
**Awaited<T>**：是递归解开 thenable 链、取出最终兑现值类型的工具类型。

```ts
function createUser(id: number, name: string): { id: number; name: string } {
  return { id, name };
}

type CreateUserArgs = Parameters<typeof createUser>; // [id: number, name: string]
type CreatedUser = ReturnType<typeof createUser>;    // { id: number; name: string }

declare class ApiClient { request(path: string): Promise<string>; }
type ClientInstance = InstanceType<typeof ApiClient>; // ApiClient

type Value = Awaited<Promise<Promise<number>>>; // number
```

- Parameters 与 ReturnType 的入参必须是函数类型；InstanceType 常与 typeof 类名组合，typeof 给构造签名、它取实例类型（见本主题第 10 篇）。
- Awaited 会递归处理嵌套 Promise 与自定义 thenable，非 Promise 类型原样返回。

**速记**：参数用 Parameters、返回用 ReturnType、实例用 InstanceType、异步结果用 Awaited。



### 手写实现

按映射类型把内置工具类型重写一遍，实现与标准库语义一致，命名加 My 前缀以示区分。

#### 手写 MyPartial 与 MyRequired 与 MyReadonly

三个属性修饰类工具类型都能用一行同态映射重写，分别控制可选性与只读性。

```ts
type MyPartial<T> = { [K in keyof T]?: T[K] };
type MyRequired<T> = { [K in keyof T]-?: T[K] };
type MyReadonly<T> = { readonly [K in keyof T]: T[K] };

type Sample = { id: number; note?: string };
type LooseSample = MyPartial<Sample>;   // { id?: number; note?: string }
type StrictSample = MyRequired<Sample>; // { id: number; note: string }
type FrozenSample = MyReadonly<Sample>; // { readonly id: number; readonly note?: string }
```

- MyPartial 用 ? 逐键加可选，MyRequired 用 -? 逐键删可选，MyReadonly 在键参数前加 readonly。
- 三者都是同态映射，对本来必填或本来必删的属性不会报错。

**速记**：Partial 加 ?、Required 减 ?、Readonly 加 readonly，各是一行同态映射。



#### 手写 MyPick 与 MyOmit

Pick 与 Omit 的差别在键来源，一个换成指定键联合，一个用 as 子句剔除键。

```ts
type MyPick<T, K extends keyof T> = { [P in K]: T[P] };
type MyOmit<T, K extends keyof T> = { [P in keyof T as P extends K ? never : P]: T[P] };

type Account = { id: number; email: string; password: string };
type AccountId = MyPick<Account, "id">;         // { id: number }
type AccountSafe = MyOmit<Account, "password">; // { id: number; email: string }
```

- MyPick 把键来源从 keyof T 换成 K，值类型写 T[P] 保证与原名对应。
- MyOmit 在键来源上写 as 判定，落在 K 里的键重映射为 never 从而被删除。
- K 约束为 keyof T 后，超出范围的键名在调用处即报错。

**速记**：Pick 换键来源为 K，Omit 在 as 里把要删的键判成 never。



#### 手写 MyRecord

手写 Record 只需一行映射，键约束为 keyof any，宽键时退化为索引签名。

```ts
type MyRecord<K extends keyof any, V> = { [P in K]: V };

type PermissionMap = MyRecord<"read" | "write" | "delete", boolean>;
// { read: boolean; write: boolean; delete: boolean }
type IndexedById = MyRecord<string, number>; // { [key: string]: number }
```

- K 约束为 keyof any，取值集合是 string、number、symbol，与内置 Record 一致。
- K 是字面量联合时逐键展开，K 是 string 这类宽类型时退化为索引签名；值类型 V 可任意。

**速记**：Record 就是「键来源为 K、值统一为 V」的映射。



#### 用 as 键重映射手写过滤

按值类型筛选键是可复用的过滤写法，把判定写进 as 子句，再用普通映射重建对象。

```ts
type KeysMatching<T, V> = { [K in keyof T as T[K] extends V ? K : never]: T[K] };

type Order = { id: number; note: string; paid: boolean; total: number };
type NumberKeys = KeysMatching<Order, number>; // "id" | "total"

type OnlyNumbers = { [K in NumberKeys]: Order[K] }; // { id: number; total: number }
```

- 第一层映射得到键联合，第二层映射按键联合重建对象类型，两步合起来即「按值类型筛选字段」。
- 判定成立与否由条件类型给出，语法与分配规则见本主题第 12 篇。

**速记**：KeysMatching 先筛出键联合，再用普通映射重建对象。



#### 条件类型实现的工具类型

Exclude、Extract、ReturnType、Parameters、NonNullable 内部不是映射类型，而是条件类型加 infer 完成的，本篇只交代用法，其实现拆解归本主题第 12 篇。

- 这一类工具类型不做逐键遍历，作用对象是联合类型或函数类型。
- 移除联合成员用 Exclude、反向保留用 Extract，从函数上取形参或返回类型用 Parameters 与 ReturnType。

**速记**：映射类型负责逐键改造，条件类型负责分支判定，两者分工见本主题第 12 篇。



### 使用误区

#### 工具类型只做浅层不递归

内置工具类型默认只作用于类型的最外层，嵌套对象不会自动跟着变换，这是最容易误判的一点。

```ts
type UserProfile = { id: number; contact: { email: string; phone: string } };
type PartialProfile = Partial<UserProfile>;
// { id?: number; contact?: { email: string; phone: string } }，contact 内层仍必填

type DeepPartial<T> = { [K in keyof T]?: T[K] extends object ? DeepPartial<T[K]> : T[K] };
type PartialUser = DeepPartial<UserProfile>;
// { id?: number; contact?: { email?: string; phone?: string } }
```

- Partial 只给顶层属性加 ?，contact 内部结构不变，const draft: PartialProfile = { contact: {} } 会报缺字段。
- 深递归要自己写映射类型并在值位置递归调用，还需终止条件与对数组、函数的特殊处理，实战见本主题第 18 篇。

**速记**：内置工具类型一律浅层，深变换必须自己写递归映射。



#### Omit 遇到索引签名的行为

Omit 在带字符串索引签名的类型上无法真正删掉属性，因为索引签名会把该属性重新放回来。

```ts
type Dictionary = { [key: string]: number; count: number };
type WithoutCount = Omit<Dictionary, "count">;
// keyof Dictionary 是 string | number，Exclude 后仍是 string | number
// 结果带索引签名，count 并未从可赋值的键里消失

const stats: WithoutCount = { count: 3 }; // 合法：索引签名放回了 count
```

- Omit 内部用 Exclude<keyof T, K> 求剩余键，「count」是 string 的子类型，从联合里删不掉。
- 结果仍是索引签名类型，取任意键都被标注为 number，键名检查同样失效。

> [!WARNING]
> **警告内容**：Omit 不能从带索引签名的类型里删除字段，删除后仍可赋入同名键；以索引签名承载配置表时，不要靠 Omit 做字段白名单。



#### Readonly 不等于深只读

Readonly 与手写只读映射都只冻结最外层属性，内层对象仍可修改，且这类限制只存在于编译期。

```ts
type AppState = { user: { name: string } };
const state: Readonly<AppState> = { user: { name: "why" } };
// state.user = { name: "tom" }; // 报错：user 为只读属性
state.user.name = "tom";          // 合法：内层对象没有只读修饰
```

- 只读是逐属性的浅层修饰，嵌套层级要靠递归映射或运行时冻结覆盖。
- 数组的只读要用 ReadonlyArray 或 as const，Readonly 只给元素位置加修饰。

> [!CAUTION]
> **注意内容**：Readonly 是编译期的浅层约束，既挡不住深层赋值，也挡不住运行时代码；它是接口契约而非运行时保护。



#### 工具类型嵌套过深导致报错难读

多层工具类型叠加后，编译器的错误信息会把每一层展开成完整结构，定位难度急剧上升。

```ts
type HandlerMap = { click: (event: { x: number }) => void; submit: (event: { form: string }) => void };
type SubmitOnly = Partial<Record<Exclude<keyof HandlerMap, "click">, ReturnType<HandlerMap["submit"]>>>;
// 报错时会展开成完整函数签名与可选属性列表，难以看出是哪一层出错
```

- 给每一层起一个中间类型别名把嵌套压平，错误信息会指向出问题的那个别名。
- 单行内叠加四层以上时先拆开逐层确认；类型别名只是命名，不产生运行时开销，也不影响推断。

**速记**：嵌套超过三层就用中间类型别名命名，错误信息才有落点。



#### 字段覆盖与声明合并

TypeScript 没有内置的 Override 工具类型，覆盖字段的通行做法是用 Omit 去掉旧字段再交叉类型补上，它与接口声明合并的规则并不相同。

```ts
type BaseOptions = { retry: number; timeout: number };
type CustomOptions = Omit<BaseOptions, "retry"> & { retry: number | "auto" }; // 覆盖成功

type Clash = { value: string } & { value: number }; // value 被求成 never，定义处不报错
// const broken: Clash = { value: "x" }; // 报错：string 不能赋给 never

interface CacheOptions { maxSize: number; }
// interface CacheOptions { maxSize: string; } // 报错：同名属性类型必须一致
```

- 交叉类型是叠加而非覆盖：两侧同名字段类型不兼容时被求成 never，错误延迟到赋值处才暴露。
- 只有 Omit 先删掉旧键，交叉才真正起覆盖作用，这是「Override 写法」的常规组合。
- 接口声明合并要求同名属性类型一致，类型不同直接在声明处报错，比交叉类型更早更明确。

**速记**：覆盖字段要 Omit 加交叉，纯交叉会把冲突字段求成 never。
