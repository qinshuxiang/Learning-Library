## 数组、元组与枚举

### 数组类型

**数组类型（array type）**：是表示同一种类型元素的变长序列的类型，长度不固定，每个位置的元素类型相同。

#### 两种写法 T[] 与 Array<T>

**T[]**：是把方括号写在元素类型之后形成的数组写法；**Array<T>**：是把元素类型作为类型实参传入 Array 的等价写法，两者描述同一个类型。

```ts
const names: string[] = ["Ada", "Linus"];
const scores: Array<number> = [90, 85];
// const mixed: number[] = [1, "2"]; // 报错：string 不能赋给 number
```

- 两种写法完全等价，string[] 与 Array<string> 可以互相赋值。
- 元素类型是联合或函数签名时 T[] 需要额外加括号，Array<T> 无需处理这件事。

```ts
type Status = "idle" | "busy";

let unionStates: ("idle" | "busy")[] = ["idle"]; // 元素为联合须加括号
let namedStates: Status[] = ["done"];            // 已命名类型无需括号
```

- 基础类型与已命名类型用 T[] 更简洁，元素类型是函数签名或多层嵌套时用 Array<T> 可读性更好。
- 只读写法只能写 readonly T[] 或 ReadonlyArray<T>，readonly Array<T> 不是合法写法。

> 方括号与尖括号都属于类型写法，泛型机制本身归本主题第 9 篇，此处只作为数组的两种书写形式使用。

**速记**：T[] 与 Array<T> 等价，元素类型为联合或函数时优先用 Array<T>，只读只能写 ReadonlyArray。

  

#### 只读数组 readonly T[] 与 ReadonlyArray

**只读数组（readonly array）**：是禁止一切改变长度或元素内容的操作的数组类型，写法为 readonly T[] 或 ReadonlyArray<T>。

```ts
const source: readonly string[] = ["a", "b"];
// source.push("c");  // 报错：readonly string[] 上不存在属性 push
// source[0] = "z";   // 报错：索引签名只允许读取
// source.length = 0; // 报错：length 是只读属性

const mutable: string[] = ["a"];
const readonlyView: readonly string[] = mutable; // 合法：可变赋给只读
// const backToMutable: string[] = readonlyView;  // 报错：只读不能赋给可变
```

- 只读数组上 push、pop、shift、splice、sort、reverse、fill 等全部变异方法都不存在。
- filter、map、slice、concat、includes 等读取方法照常可用，返回的仍是只读数组。
- readonly T[] 与 ReadonlyArray<T> 等价，选择哪一种与 T[] 和 Array<T> 的选择标准一致。

```ts
const keywords: readonly string[] = ["ts", "js"];
const upper = keywords.map((word) => word.toUpperCase()); // readonly string[]
```

> 只读数组的约束只存在于编译期，运行时的数组对象仍可被修改，编译期只读不等于运行时冻结。

**速记**：只读数组禁止一切变异操作，可变数组可赋给只读数组，反向赋值被拒绝。

  

#### 数组方法的类型推断

数组方法的参数与返回值类型由元素类型自动推断，调用 map(callback)、filter(callback)、reduce(callback, initialValue)、find(predicate) 时通常不需要手写类型实参。

```ts
const prices: number[] = [10, 20, 30];

const doubled = prices.map((price) => price * 2);            // number[]
const labels = prices.map((price) => `${price} 元`);          // string[]
const total = prices.reduce((sum, price) => sum + price, 0); // number
const found = prices.find((price) => price > 15);            // number | undefined

// const discounted = found * 0.8; // 报错：对象可能为 undefined
```

- map 的结果元素类型取回调返回值类型，回调参数类型自动取源数组元素类型。
- filter 与 slice 不改变元素类型，reduce 的返回类型取初始值类型或回调返回类型，初始值给错会连带影响推断。
- find 找不到时返回 undefined，结果类型带 undefined，直接参与运算前需要判空。
- 元素类型为联合时，回调参数也是该联合，使用前需要先收窄，收窄规则归本主题第 8 篇。

**速记**：数组方法从元素类型自动推断参数与返回值，find 的结果带 undefined。

  

#### 只读数组的限制

只读数组的限制不止于自身，还体现在作为参数传递与接收时的赋值方向。

- 只读数组不能传给形参为可变数组的函数，因为函数内部可能改写元素。
- 接收方若不需要修改，应把形参声明为 readonly T[]，这样可变数组与只读数组都能传入。
- 需要就地排序或反转时，先展开复制为可变数组再操作。

```ts
function sumAll(values: readonly number[]): number {
  return values.reduce((sum, value) => sum + value, 0);
}

function sortInPlace(values: number[]): number[] {
  return values.sort((a, b) => a - b);
}

const readOnlyNumbers: readonly number[] = [3, 1, 2];
// sortInPlace(readOnlyNumbers); // 报错：readonly number[] 不能赋给 number[]
console.log(sumAll([...readOnlyNumbers])); // 6
```

- 用 as const 推断出的数组是只读元组，传入可变数组形参同样报错。
- 函数签名写成 readonly T[] 是对调用方的承诺：函数不会修改传入的集合。

**速记**：只读数组不能传给可变数组形参，参数用 readonly 声明可同时接受两种数组。

  

### 元组类型

**元组类型（tuple type）**：是元素个数固定、每个位置的元素类型可分别声明的数组类型，长度与各位置类型同时受约束。

#### 定长与位置类型

元组用方括号按顺序列出各位置的类型，赋值时长度与每个位置的类型都要匹配。

```ts
let point: [number, number] = [10, 20];
let entry: [string, number] = ["age", 30];

// point = [1, 2, 3];   // 报错：长度为 2，元素过多
// point = [1];         // 报错：长度为 2，元素过少
// entry = [30, "age"]; // 报错：位置 0 需要 string
```

- 元素类型可以相同也可以不同，相同元素类型的定长元组与普通数组的区别只在长度约束。
- 可以为每个位置写标签，标签只提升可读性，不改变类型本身，位置仍是唯一的判别依据。

```ts
type Point3D = [x: number, y: number, z: number];
const origin: Point3D = [0, 0, 0];

const pair: [string, number] = ["age", 30];
// console.log(pair[2]); // 报错：长度为 2 的元组没有下标 2
```

- 用字面量下标越界访问会被编译期拒绝；用变量下标访问时类型为各位置类型的联合，越界风险仍在运行时。

> 长度检查只对字面量下标生效，变量下标无法在编译期确定，越界判定需要运行时完成。

**速记**：元组按位置声明类型，长度与位置类型双重约束，字面量下标越界会报错。

  

#### 可选元素与剩余元素

**可选元素**：是在元素类型后加问号、表示该位置可以缺省的元素，它必须排在所有必选元素之后。

```ts
type TimeRange = [start: number, end: number, step?: number];

const shortRange: TimeRange = [0, 100]; // 省略可选元素
// const wrongRange: TimeRange = [0, undefined, 5]; // 报错：undefined 不能赋给 number
```

- 省略可选元素时直接不写该位置，不能用 undefined 占位。
- 可选元素后面不能再出现必选元素，剩余元素也不能跟在可选元素之后。

**剩余元素**：是用 ...T[] 声明在末尾、表示该位置起为同类型不定长元素的元素，一个元组中只能出现一次。

```ts
type Command = [name: string, ...args: number[]];

const resetCommand: Command = ["reset"];          // 剩余部分为空
const scaleCommand: Command = ["scale", 1, 2, 3]; // 剩余部分任意多个
// const badCommand: Command = [1, "reset"];       // 报错：位置 0 需要 string
```

- 剩余元素本身已经覆盖零个或多个的情形，因此不需要再搭配可选元素。
- 剩余元素必须放在末尾，例如 [name: string, count?: number, ...args: number[]] 会被编译器拒绝。

**速记**：可选元素用问号且必须在必选元素之后，剩余元素用 ...T[] 放末尾，两者不能混排。

  

#### readonly 元组

**只读元组（readonly tuple）**：是加 readonly 修饰的元组类型，禁止修改任一位置的元素，也不能增删元素。

```ts
const rgb: readonly [number, number, number] = [255, 128, 0];

// rgb[0] = 1;     // 报错：索引签名只允许读取
// rgb.push(0);    // 报错：readonly 元组上不存在 push
// rgb.length = 2; // 报错：length 是只读属性
```

- 只读元组沿用相同的赋值方向：可变元组可以赋给只读元组，只读元组不能赋给可变元组。
- as const 是把数组字面量变成只读元组最常用的方式，同时会把每个元素类型收窄为字面量类型。

```ts
const palette = ["red", "green", "blue"] as const; // readonly ["red", "green", "blue"]
const themeColors: readonly [string, string] = ["light", "dark"];
```

- 只读元组常用来承载常量清单与固定结构，配合索引访问类型可以导出联合类型，写法见本主题第 10 篇。

> 只读元组的每个位置类型精确到字面量，这种结构固定且不可变的形态适合表达坐标、尺寸、键值对这类小结构。

**速记**：只读元组锁定每个位置的元素，as const 是生成只读元组最常用的方式。

  

#### 解构赋值与多返回值

**解构赋值（destructuring assignment）**：是按右值的结构提取并绑定变量的写法，元组解构按位置进行，解构出的变量类型取对应位置的元素类型。

```ts
function parseRange(text: string): [number, number] {
  const [rawStart, rawEnd] = text.split("-");
  return [Number(rawStart), Number(rawEnd)];
}
const [rangeStart, rangeEnd] = parseRange("10-20"); // number 与 number

function getSize(): [width: number, height: number, unit: string] {
  return [1920, 1080, "px"];
}
const [, height] = getSize();      // 跳过宽度
const [width, , unit] = getSize(); // 跳过高度
```

- 位置与变量一一对应，元素类型不同时每个变量拿到各自的精确类型，这是元组优于普通数组的地方。
- 只取部分元素时可用空位跳过，函数返回元组是「一次返回多个不同类型值」最直接的方式。
- 位置过多时可读性下降，超过三个位置建议改为返回带字段名的对象，例如 getViewportStats 返回 width、height、ratio。

**速记**：函数返回元组、调用处解构，是按位置传递多个不同类型值的最直接方式。

  

### 枚举

**枚举（enum）**：是给一组相关常量统一命名并集中声明的类型，成员在运行时是真实存在的具名取值。

#### 数字枚举与自动递增

**数字枚举**：是成员取值为数字的枚举，未显式赋值时从 0 开始自动递增。

```ts
enum Direction { Up, Down, Left }  // 0 1 2
enum FileMode { Read = 4, Write }  // 4 5

console.log(Direction.Left); // 2
console.log(FileMode.Write); // 5
```

- 只给首个成员赋值时，其后成员在该值基础上依次加一；部分赋值时，未赋值的成员接着上一个已知值递增。
- 数字枚举成员本身就是数字，可以直接参与运算与比较，这既是便利也是隐患。
- 成员值不要求唯一，两个成员取同一个数字是合法的，例如 Low = 1 与 Minor = 1 可以共存。

> 需要每个成员取值唯一时不要依赖数字枚举，编译器不检查唯一性，字符串枚举或字面量联合更合适。

**速记**：数字枚举默认从 0 递增，可整体偏移或逐个赋值，成员值不要求唯一。

  

#### 字符串枚举

**字符串枚举**：是成员取值必须显式赋为字符串字面量的枚举，不参与自动递增，每个成员都要写值。

```ts
enum LogLevel { Debug = "DEBUG", Info = "INFO", Warn = "WARN" }
// enum BadLogLevel { Debug = "DEBUG", Info } // 报错：字符串枚举成员必须有初始值

function logMessage(level: LogLevel, message: string): void {
  console.log(`${level}: ${message}`);
}
logMessage(LogLevel.Warn, "磁盘空间不足"); // "WARN: 磁盘空间不足"
// const level: LogLevel = "WARN"; // 报错：字符串字面量不能赋给 LogLevel
```

- 成员值在日志、接口与序列化结果中可读，值本身带有语义，便于排查问题。
- 不会生成反向映射，这是它与数字枚举最直观的运行期差别。
- 字符串枚举不接受裸字符串赋值，取值必须经由成员访问得到，因此拼写错误在编译期就能发现。
- 需要由字符串反查成员名时字符串枚举无能为力，得自己再建一张映射表。

> 面向外部协议、日志、状态码字符串时优先选字符串枚举，值本身就是契约的一部分。

**速记**：字符串枚举必须逐项显式赋值，可读性好且赋值严格，并且没有反向映射。

  

#### 常量枚举与反向映射

**常量枚举（const enum）**：是用 const enum 声明的枚举，编译期把成员引用就地替换为字面量，不生成运行时对象。

```ts
const enum Axis { X = "x", Y = "y" }

const activeAxis = Axis.X; // 编译后直接是 "x"，产物中不包含 Axis 对象
```

**反向映射（reverse mapping）**：是数字枚举在运行时额外生成的「值到成员名」的映射，使 Enum[值] 可以取回成员名。

```ts
enum Weekday { Monday, Tuesday }

console.log(Weekday[0]);           // "Monday"，反向映射
console.log(Object.keys(Weekday)); // ["0", "1", "Monday", "Tuesday"]
```

- 反向映射只对数字枚举生成，字符串枚举与常量枚举都没有。
- 反向映射使数字枚举对象同时含数字键与字符串键，用 Object.keys(obj) 统计成员数会偏多。
- 常量枚举没有运行时对象，因此不能遍历、不能取 Object.keys，也不能在运行时读取成员数量。

> [!WARNING]
> **警告内容**：常量枚举不生成运行时对象，一旦有代码需要在运行时遍历枚举成员，必须改用普通枚举或对象常量。

**速记**：常量枚举在编译期就地替换为字面量，反向映射只属于数字枚举。

  

#### 枚举作为类型使用

枚举名同时存在于值空间与类型空间：作为值可以访问成员，作为类型表示该枚举的全部成员取值。

```ts
enum TaskState { Pending, Running, Done }

let current: TaskState = TaskState.Pending; // 枚举名作类型

function enterRunning(state: TaskState.Running): TaskState { // 成员作类型
  return state;
}
// const invalidState: TaskState = 9; // 报错：9 不在 TaskState 的取值域内
```

- 枚举成员单独作类型时只接受该成员本身，可用于表达某个函数只能接收特定取值。
- 数字枚举对 number 类型比字符串枚举宽松，编译器无法保证运行时取值一定落在成员集合内；越界的数字字面量会被拒绝。

> 数字枚举与 number 的兼容性削弱了取值约束，这是它不如字符串枚举与字面量联合严格的主要原因。

**速记**：枚举名既可当值用也可当类型用，单个成员也能作类型，数字枚举对 number 较宽松。

  

### 枚举的取舍与替代

**取舍原则**：枚举提供运行时对象与集中声明，字面量联合与对象常量只提供类型约束，选择取决于是否需要运行时的成员集合。

#### 枚举与字面量联合的对比

**字面量联合**：是把若干字面量用竖线组合成的联合类型，与枚举表达同一组取值，但不在运行时产生任何对象。

```ts
enum Size { Small = "S", Medium = "M" }
type SizeUnion = "S" | "M";

const fromEnum: Size = Size.Medium; // 取值经由成员访问
const fromUnion: SizeUnion = "M";   // 取值直接写字面量
// const badUnion: SizeUnion = "XL"; // 报错："XL" 不能赋给 SizeUnion
```

- 运行时产物：枚举生成对象，字面量联合是纯类型，编译后完全消失。
- 可读性：字面量联合的值就是本身，日志与网络数据里一目了然；枚举多一层成员访问。
- 约束强度：字符串枚举拒绝裸字符串，字面量联合接受一切符合字面量的字符串，更容易与外部数据对齐。
- 穷尽检查：两者配合 switch 都能做穷尽检查，能力相当，检查手法归本主题第 8 篇。

> 选择原则：需要运行时遍历成员、需要单一维护点、或成员值与外部契约解耦时用枚举；只做编译期取值约束、值与外部数据一致时用字面量联合。

**速记**：枚举有运行时对象，字面量联合只有类型，纯编译期约束优先用字面量联合。

  

#### 异构枚举的问题

**异构枚举（heterogeneous enum）**：是成员取值同时包含数字与字符串的枚举，官方文档不推荐使用。

```ts
enum Mixed { No = 0, Yes = "YES" }

console.log(Mixed[0]); // "No"，数字成员仍有反向映射
console.log(Mixed[1]); // undefined，字符串成员没有反向映射
```

- 反向映射只覆盖数字成员，遍历结果里成员名与字符串值混杂，语义难以预期。
- 各成员的序列化与比较行为不一致，数字与字符串混用时的相等判断容易出错。
- 类型层面无法区分某个值是来自数字成员还是字符串成员，取值约束形同虚设。

> [!CAUTION]
> **注意内容**：异构枚举中数字成员与字符串成员行为不同，遍历与比较都会偏离直觉，需要两类取值时应拆成两个枚举或改用字面量联合。

**速记**：异构枚举混用数字与字符串成员，行为不一致，应当避免。

  

#### isolatedModules 与 const enum 的冲突

**isolatedModules**：是 tsconfig 中要求每个文件都能脱离其它文件单独转译的编译选项，开启后跨文件访问环境常量枚举会直接报错。

```ts
// globals.d.ts
declare const enum Axis { X = 1, Y = 2 }

// main.ts
console.log(Axis.X);
// 开启 isolatedModules 时报错：
// Cannot access ambient const enums when 'isolatedModules' is enabled.
```

- 报错原因是单文件转译时编译器看不到其它文件里的成员定义，无法把 Axis.X 内联成数字。
- 非环境声明的 const enum 不触发该报错，但 Babel、esbuild、swc 这类单文件转译器同样无法内联，产物可能与 tsc 不一致。
- isolatedModules 是 Vite、esbuild 等现代构建工具的默认前提，因此工程实践中应改用普通枚举或对象常量。

> [!WARNING]
> **警告内容**：在开启 isolatedModules 的工程里不要使用 const enum，跨文件访问要么直接报错，要么在单文件转译后失去内联保证。

**速记**：isolatedModules 下环境常量枚举直接报错，单文件转译也无法内联，工程中应避免使用。

  

#### 用 as const 对象替代枚举

**对象常量模式**：是用 as const 修饰的对象字面量承载一组取值，再用 typeof 与 keyof 导出对应的联合类型，兼具运行时对象与编译期约束。

```ts
const LogLevel = { Debug: "DEBUG", Info: "INFO", Warn: "WARN" } as const;

type LogLevel = (typeof LogLevel)[keyof typeof LogLevel]; // "DEBUG" | "INFO" | "WARN"

function logMessage(level: LogLevel, message: string): void {
  console.log(`${level}: ${message}`);
}
logMessage(LogLevel.Warn, "写入失败"); // 合法
// logMessage("FATAL", "写入失败");     // 报错："FATAL" 不能赋给 LogLevel

console.log(Object.values(LogLevel)); // ["DEBUG", "INFO", "WARN"]
```

- 与枚举相比：仍是真实对象，可用 Object.values 取全部值、可用 Object.keys 取全部名字，且不需要额外语法。
- 值本身就是字面量，与接口返回的字符串天然兼容，省去了枚举值到字符串的转换。
- 类型名与常量名可以同名，类型与值处于不同的命名空间，写法自然。
- 不支持反向映射，单个属性也不能像枚举成员那样直接当类型用，需要更精确的约束时应从联合类型里取字面量。

> 三种载体的分工：需要运行时枚举成员与反向映射用数字枚举，值与字符串契约一致用字符串枚举或字面量联合，需要集中维护又不想引入枚举语法用 as const 对象。

**速记**：as const 对象加 typeof 与 keyof 可以同时得到常量对象与联合类型，是枚举的常用替代。
