## 泛型

### 为什么需要泛型

**泛型（generic）**：是把类型本身作为参数传入、由调用处决定具体类型，从而在一份实现里保留类型关系的机制。

#### 重复实现与 any 化的两条死路

要让一个函数接受并返回多种类型又不使用泛型，只剩复制实现与退化成 any 两条路。

```ts
// 死路一：每个类型复制一份实现
function identityNumber(value: number): number { return value; }
function identityString(value: string): string { return value; }
function identityAny(value: any): any { return value; } // 死路二：类型关系丢失
const text = identityAny("hello"); // text 的类型是 any
text.toFixed(2); // 编译期不报错，运行时抛错
```

- 复制实现的成本在同步修改：逻辑改一处就要改所有副本，漏掉一份就行为不一致。
- any 丢掉返回值类型，也丢掉返回值与入参同类型的关系，并沿赋值链继续扩散。

**速记**：不用泛型只有两条路——复制实现，或退化成 any 丢掉类型关系。



#### 把类型当作参数传递

**类型参数（type parameter）**：是声明在函数、接口或类上的占位类型名，调用处提供具体类型后替换。**类型实参（type argument）**：是调用时为类型参数指定的具体类型。

- 类型参数写在函数名后的尖括号里，作用域覆盖整个签名与函数体；值参数由调用者传值，类型参数由调用者传类型，二者都在调用点确定。
- 泛型只参与编译期检查，运行时不存在类型参数，这一性质称为类型擦除（erasure）。

```ts
function identity<T>(value: T): T { return value; }
const text = identity("hello"); // string
const count = identity(42);     // number
```

**速记**：类型参数是占位类型名，调用点用类型实参替换；泛型被类型擦除，运行时不存在。



#### 泛型的收益与代价

收益与代价同在，是否使用泛型就是权衡这两端。

- 收益：类型关系被保留，实现只写一份，类型实参多数可由推断得出。
- 代价：签名变长、报错信息带类型参数、类型参数不建立关系时只是噪音。

> [!TIP]
> **建议内容**：两个及以上位置需要共享同一个类型时才用泛型，只出现一次的类型位置直接用具体类型或 unknown。

**速记**：泛型换来类型关系与复用，付出签名复杂度与报错可读性的代价。



### 泛型函数与调用推断

**泛型函数**：是声明了类型参数、把具体类型的决定推迟到调用点的函数。

#### 类型参数的声明位置

类型参数写在函数名与参数列表之间，用尖括号包住，位置固定。

```ts
function first<T>(items: T[]): T | undefined { return items[0]; }
const toPair = <T, U>(first: T, second: U): [T, U] => [first, second];
class Stack<T> {
  private items: T[] = [];
  push(item: T): void { this.items.push(item); }
}
```

- 函数声明、箭头函数、类方法、构造函数写法一致，都是标识符后跟尖括号。
- 类型参数不能声明在函数体内部，它属于签名而不是语句；箭头函数写法在 .tsx 文件中要写成带尾逗号或带约束的形式，否则会被解析成 JSX 标签。

**速记**：类型参数写在函数名后的尖括号里，作用域覆盖签名与函数体。



#### 调用时自动推断

调用泛型函数时不写类型实参，编译器从实参反推类型参数，这一步称为类型参数推断。

```ts
function identity<T>(value: T): T { return value; }
const fromString = identity("hello"); // T 推断为 string
const fromNumber = identity(42);      // T 推断为 number
function first<T>(items: T[]): T | undefined { return items[0]; }
const item = first(["a", "b"]); // string | undefined
```

- 推断来源是实参的静态类型，而不是运行时的值。
- 同一类型参数在多个位置出现时合并候选；空数组字面量等没有元素信息的情形，T 会退化为 never，需要显式传入类型实参。

**速记**：不写类型实参时，编译器从实参的静态类型反推类型参数。



#### 显式传入类型实参

在标识符后用尖括号写出类型实参，可以覆盖推断结果。

```ts
function first<T>(items: T[]): T | undefined { return items[0]; }
const empty = first<string>([]); // 显式指定 T 为 string
function createArray<T>(length: number, fill: T): T[] { return new Array<T>(length).fill(fill); }
const flags = createArray<boolean>(3, false); // boolean[]
```

- 需要显式的三类情形：无法推断、推断过宽、要求调用方明确表达意图。
- 显式实参优先于推断，写错时会在函数内部使用该类型的位置报错。

**速记**：无法推断或推断过宽时显式写类型实参，显式值优先于推断。



#### 多个类型参数

一个签名可以声明多个类型参数，用逗号分隔，各自由实参或推断确定。

```ts
function mapArray<T, U>(items: T[], transform: (item: T) => U): U[] { return items.map(transform); }
const lengths = mapArray(["a", "bb"], (item) => item.length); // number[]
function createRecord<K extends string, V>(key: K, value: V): Record<K, V> {
  return { [key]: value } as Record<K, V>;
}
```

- 每个类型参数都应有明确职责，职责说不清就说明参数可以合并或删除。
- 能由推断得出的参数不写，能用一个参数表达的不写两个。

**速记**：多个类型参数各自独立确定，数量以能表达清楚类型关系为准。



#### 类型参数与参数类型的依赖关系

靠后的类型参数可以用 extends 引用靠前的类型参数，形成依赖。

```ts
function pairWith<T, U extends T>(value: T, derived: U): [T, U] {
  return [value, derived];
}
const role = pairWith<string, "admin">("role", "admin"); // [string, "admin"]
function mapArray<T, U>(items: T[], toKey: (item: T) => U): U[] { return items.map(toKey); }
```

- U extends T 表示第二个类型参数必须是第一个的子类型，两个参数由此绑定，pairWith("role", 1) 会因 number 不满足 string 而报错。
- 读签名时从左往右即可判断哪些参数能单独确定，哪些依赖前面的参数。
- 返回值同时包含 T 与 U 时，调用结果就同时携带两者的信息。

**速记**：靠后的类型参数可 extends 靠前的类型参数，形成依赖并绑定两者。



### 泛型约束

**泛型约束（generic constraint）**：是用 extends 限定类型参数必须满足的形状，无约束的类型参数只能当任意类型使用。

#### extends 约束

约束让函数体可以安全访问约束上声明的成员。

```ts
function logLength<T extends { length: number }>(item: T): number {
  return item.length;
}
logLength("hello"); // 5
// logLength(42); // 报错：number 不满足 { length: number }
```

- 语法形如 T extends 约束类型，读作「T 必须可赋值给约束类型」。
- 约束不把 T 固定成约束类型：T 仍是调用处推断出的具体类型，只是被要求具备约束成员。
- 满足约束的实参不止一种，字符串、数组与带 length 的对象都可传入。

**速记**：T extends 约束 表示 T 必须满足约束形状，约束不放宽 T 的具体类型。



#### 约束与联合类型组合

约束本身可以是联合类型，用来把 T 限制在若干候选类型之内。

```ts
function stringifyId<T extends string | number>(id: T): string {
  return String(id);
}
stringifyId("u_1"); // "u_1"
// stringifyId(true); // 报错：boolean 不满足 string | number
```

- 约束为联合时，T 的取值必须落在联合内，但 T 本身仍是单一类型而不是联合。
- 约束越宽，函数体内能直接访问的成员越少：string | number 上既没有 toFixed 也没有 toUpperCase，需要先收窄（本主题第 8 篇）。

**速记**：约束可以是联合类型；能直接访问的成员由约束决定，越宽能用的越少。



#### 用类型参数当类型使用

类型参数可以出现在任何需要类型的位置，落点决定它能建立什么关系。

```ts
function toArray<T>(value: T): T[] { return [value]; }
function wrapInData<T>(value: T): { data: T } { return { data: value }; }
function applyTwice<T>(value: T, transform: (input: T) => T): T { return transform(transform(value)); }
applyTwice(3, (n) => n + 1); // 4
```

- 常见落点：数组元素、对象属性值、函数参数、函数返回值、另一个类型的类型实参。
- 只在返回值出现 T 就与入参无关，只在入参出现 T 就与返回值无关，关系由共同出现产生。
- 类型参数不能当值使用：运行时不存在 T，new T()、typeof T、T instanceof X 都不允许。

**速记**：类型参数可出现在任何类型位置，落点决定类型关系；它不能当值使用。



#### 约束中的 keyof

按键取值时，用 keyof 约束把键限制在对象真实拥有的属性上。

```ts
function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] { return obj[key]; }
const user = { name: "Ada", age: 36 };
const name = getProperty(user, "name"); // string
// getProperty(user, "email"); // 报错：email 不在 keyof typeof user 中
```

- K extends keyof T 把 key 限制为 T 的属性名联合，写错键名会在调用处直接报错。
- 返回类型 T[K] 是索引访问类型，随 K 变化：取 name 得 string，取 age 得 number。
- keyof 与索引访问类型详见本主题第 10 篇，本篇只作建立键与返回值关联的必要示例。

**速记**：K extends keyof T 把键限制在真实属性内，配合 T[K] 建立键与返回值的关联。



#### 多重约束

一个类型参数可以同时满足多个约束，用交叉类型连接。

```ts
interface HasId { id: string }
interface HasTimestamps { createdAt: string; updatedAt: string }
function newestOf<T extends HasId & HasTimestamps>(items: T[]): T {
  return items.reduce((left, right) => (left.createdAt > right.createdAt ? left : right));
}
```

- T extends A & B 表示 T 必须同时满足 A 与 B，可访问成员是两者并集。
- 约束之间是并列要求而不是继承，任一不满足都会在调用处报错。

> [!IMPORTANT]
> **重要内容**：类型参数上的 extends 是约束，与类的继承 extends 含义不同：前者要求结构兼容，后者建立继承关系（本主题第 14 篇）。

**速记**：多重约束用交叉类型连接，T 必须同时满足全部约束。



### 泛型接口、泛型类与默认类型参数

**泛型接口**：是声明了类型参数的接口，形状固定而成员类型可变；泛型类与泛型别名的思路相同。

#### 泛型接口描述容器与映射

泛型接口把容器的形状与装载的类型分开描述。

```ts
interface Box<T> { value: T }
interface ApiResponse<T> { code: number; message: string; data: T }
interface Mapper<T, U> { map(value: T): U }
const numberBox: Box<number> = { value: 1 };
const okResponse: ApiResponse<string[]> = { code: 0, message: "ok", data: ["a"] };
```

- Box 描述有 value 属性的容器，T 决定 value 的类型。
- ApiResponse 描述统一响应外壳，data 之外的部分对所有接口一致。
- Mapper 用两个类型参数表达映射方向：T 是输入，U 是输出，实现方必须满足该方向。

**速记**：泛型接口把结构固定、类型开放，适合容器、响应外壳与映射契约。



#### 泛型类与静态成员的注意点

泛型类在类名后声明类型参数，实例成员可自由引用，静态成员不可。

```ts
class Store<T> {
  private items: T[] = [];
  add(item: T): void { this.items.push(item); }
  getFirst(): T | undefined { return this.items[0]; }
  // static empty(): Store<T> {} // 报错：静态成员不能引用类的类型参数
}
const numberStore = new Store<number>(); // 实例确定自己的 T
```

- 每个实例在 new 时确定自己的类型实参，实例成员因此能安全使用 T。
- 静态成员在类层面只存在一份，没有实例的类型实参可用，故不能引用类的类型参数。
- 静态方法需要泛型时，在方法自身声明独立的类型参数，写法是 static 后跟方法名再接尖括号。

**速记**：泛型类的实例成员可用 T，静态成员不可；静态泛型方法需自带类型参数。



#### 默认类型参数的写法与用途

**默认类型参数**：是为类型参数提供默认类型实参，调用处未提供时生效。

```ts
interface ApiResponse<T = unknown> { code: number; data: T }
type ApiResult<T = string> = { ok: true; value: T } | { ok: false; error: string };
const plain: ApiResponse = { code: 0, data: null };      // T 取默认的 unknown
const typed: ApiResponse<number> = { code: 0, data: 1 }; // T 显式为 number
```

- 写法为尖括号内「类型参数 = 默认类型」，适用于接口、类型别名、类与函数。
- 默认值应取最常见的返回类型或最安全的顶层类型，unknown 比 any 更合适，且默认类型参数必须排在无默认值的类型参数之后。

> [!NOTE]
> **提醒内容**：默认类型只在调用处完全省略该位置的类型实参时生效，显式传入时直接覆盖默认值，不做合并。

**速记**：默认类型参数在缺省时生效，且必须排在无默认值的参数之后。



#### 泛型别名的组合

泛型类型别名可以互相嵌套，把复杂结构拆成若干可单独复用的层。

```ts
interface User { id: string; name: string }
type Result<T> = { ok: true; value: T } | { ok: false; error: string };
type Page<T> = { items: T[]; total: number };
type UserPageResult = Result<Page<User>>;
```

- 每层只负责一件事：Result 负责成败分支，Page 负责分页，User 是业务实体。
- 分层后任意组合都成立，Result<Page<User>> 与 Page<Result<User>> 各有明确含义，别名只表达类型不携带实现，映射类型等更深的组合见本主题第 11 篇。

**速记**：泛型别名互相嵌套形成分层，每层单独复用、按需组合。



### 常见误区

#### 无谓泛型

**坏味道（code smell）**：是提示设计问题的信号，不是语法错误。

判别方法：类型参数在签名里只出现一次，就没有在两个位置之间建立关系。

```ts
function logItem<T>(item: T): void { console.log(item); } // 坏味道：T 只出现一次
function logUnknown(item: unknown): void { console.log(item); } // 更清楚且等价
function parseJson<T>(text: string): T { return JSON.parse(text) as T; } // T 只出现一次
```

- 只出现一次的类型参数通常可换成具体类型或 unknown，调用处少一层理解成本。
- 例外是把显式类型实参当作断言入口的写法，如 parseJson 以放弃检查换取调用处简洁，需要谨慎。

> [!WARNING]
> **警告内容**：类型参数只在返回值出现时，函数内部必然要做一次断言或强转，类型安全由调用方承担，不由编译器保证。

**速记**：类型参数只出现一次就无关系可言，优先换成具体类型或 unknown。



#### 用 any 逃逸约束

写出约束后又用 any 绕过它，等于白写约束。

```ts
function mustFindBad<T extends { id: string }>(items: T[], id: string): T {
  return items.find((item) => item.id === id) as any; // 抹掉 undefined
}
function mustFind<T extends { id: string }>(items: T[], id: string): T {
  const found = items.find((item) => item.id === id);
  if (!found) { throw new Error("记录不存在: " + id); }
  return found;
}
```

- 一旦用 any 覆盖返回值，编译器不再校验这一处，约束名存实亡。
- 常见变体是把类型参数的默认值写成 any，省略类型实参的调用会全部退化成 any；需要一定有值时，用运行时检查加抛错表达。

**速记**：约束后接 any 或强转等于放弃检查，改回运行时校验并抛错。



#### 泛型嵌套过深

类型实参层层嵌套时，报错信息会展开整条链，定位成本陡增。

```ts
type DeepLoad = Promise<Result<ApiResponse<Page<User>>>>; // 四层嵌套
type UserPage = ApiResponse<Page<User>>;                  // 抽中间别名
type UserPageResult = Promise<Result<UserPage>>;
```

- 嵌套本身合法，问题在于报错信息把整条类型链原样打印，且每加一层都要重读一遍。
- 经验做法是嵌套不超过三层，超出就抽中间别名；同一实参在多处重复出现时，别名还能避免写错并统一修改点。

**速记**：类型嵌套控制在三层内，超出就抽中间别名换取可读性。



#### 泛型与联合类型混淆

两者都能让代码适配多种类型，但建立的关系完全不同。

```ts
function wrapUnion(value: string | number): string | number { return value; }
const fromUnion = wrapUnion("a"); // string | number，关系丢失
function wrapGeneric<T>(value: T): T { return value; }
const fromGeneric = wrapGeneric("a"); // string，关系保留
```

- 联合表达取值是其中之一，泛型表达同一个类型在签名内保持一致。
- 只关心能否接受多种类型时用联合，关心进出是不是同一类型时用泛型，T extends A | B 与 A | B 也不是同一件事，两者在条件类型下的差异见本主题第 12 篇。

**速记**：联合表达或，泛型表达同一个 T 贯穿签名，按需要保留的关系选择。



#### 把泛型当面向对象继承用

泛型是参数化，不是继承；约束也不是父类。

```ts
interface Animal { name: string }
interface Dog extends Animal { bark(): void }
interface Box<T> { value: T }
const dogBox: Box<Dog> = { value: { name: "Rex", bark() {} } };
const animalBox: Box<Animal> = dogBox; // 合法：value 结构兼容
```

- T extends Animal 的含义是 T 至少具备 Animal 的结构，与 class Dog extends Animal 的继承含义不同。
- TypeScript 是结构化类型（structural typing），能否赋值由成员结构决定，不由继承关系决定。
- 泛型不提供成员复用与运行时多态分派，需要这两项能力时用类与接口的继承（本主题第 14 篇）。

**速记**：泛型是参数化而非继承，可赋值性由结构决定，与继承无关。
