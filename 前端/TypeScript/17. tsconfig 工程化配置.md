## tsconfig 工程化配置

### 配置文件基础

**工程配置**：是用一份 JSON 文件描述项目边界与编译行为的做法，编译器据此决定纳入哪些文件、以什么目标编译、产物写到哪里。

#### tsconfig.json 的作用与查找顺序

**tsconfig.json**：是 TypeScript 项目的编译配置清单，声明编译范围、编译目标与产物位置；它所在目录同时被当作项目默认根目录。

- 命令行不指定路径时，从当前工作目录逐级向上查找最近的 tsconfig.json，找到即停止。
- 用 -p 或 --project 指定路径时跳过向上查找；--showConfig 打印继承展开后的完整生效配置。

> 向上查找只认 tsconfig.json 这个名字，tsconfig.base.json 之类共享配置必须被 extends 显式引用才会参与。

**速记**：tsconfig.json 兼作项目根标记且就近向上查找，排查生效值用 --showConfig。



#### extends 继承与多层覆盖

**extends**：让当前配置继承另一份配置的 compilerOptions 再局部覆盖，用于抽出多项目共享的基线。

```json
{
  "extends": "../../tsconfig.base.json",
  "compilerOptions": { "rootDir": "./src", "outDir": "./dist" }
}
```

- 取值为数组时按顺序合并，靠后的覆盖靠前的（TypeScript 5.0 起支持）；覆盖是浅合并，同一选项整体替换而非递归合并数组或对象内部字段，路径类选项中的相对路径以写出它的那份文件为基准解析。

**速记**：extends 浅合并、后者覆盖前者，相对路径以来源文件为基准。



#### include、exclude 与 files 三种圈定方式

三种字段决定哪些文件属于本项目：files 是显式白名单，include 是 glob 匹配，exclude 从 include 结果中剔除。

```json
{
  "files": ["src/global.d.ts"],
  "include": ["src/**/*.ts", "src/**/*.tsx"],
  "exclude": ["src/**/*.test.ts", "dist"]
}
```

- files 与 include 同时存在时取并集，exclude 只作用于 include 而对 files 无效；被纳入文件 import 到的其他文件会自动进入编译图，不写 files 与 include 时默认纳入配置目录下全部 .ts、.tsx、.d.ts，exclude 默认已排除 node_modules 与 outDir。

**速记**：files 点名、include 匹配、exclude 只减 include，被 import 的文件自动进图。



#### 项目引用 references 与 composite

**项目引用（references）**：把一个仓库拆成若干可独立编译的子项目，由上层配置按依赖引用，从而复用编译结果、避免整仓重编。**composite**：被引用项目必须打开的开关，强制生成声明文件与构建信息，并要求源文件都在 rootDir 范围内。

```json
{
  "files": [],
  "references": [{ "path": "./packages/shared" }, { "path": "./packages/web" }]
}
```

- 引用只能指向 composite 项目，普通配置被 references 指向会直接报错。
- 构建改用 tsc -b，它按依赖图排序、只重编过期项目，可加 --watch 持续监听；references 管构建边界，paths 管模块说明符到文件的映射，两者不能互相替代。

**速记**：references 拆构建边界且目标必须 composite，构建命令是 tsc -b。



### 编译目标与模块

#### target 与 lib 的配合

**target**：决定输出 JS 的 ECMAScript 版本，同时决定默认 lib 集合与语法降级程度。**lib**：编译期可见的标准库类型集合，决定哪些内置 API 有类型可用。

```json
{
  "compilerOptions": {
    "target": "ES2020",
    "lib": ["ES2020", "DOM", "DOM.Iterable"]
  }
}
```

- target 只降级语法（可选链、空值合并、类字段、async 等），不补 polyfill，也不改变内置 API 是否存在；显式写 lib 会整体替换默认集合而非叠加，前端项目漏写 DOM 会导致 document 找不到类型，target 高于实际运行环境时则会编译通过、运行时缺方法。

**速记**：target 管语法降级，lib 管类型可见性，lib 是替换而非叠加。



#### module 与 moduleResolution 的配套取值

**module**：决定产物里模块的书写格式；**moduleResolution**：决定编译器按哪套规则把 import 说明符解析到文件。解析算法见本主题第 16 篇，此处只列配套取值。

```json
{ "compilerOptions": { "module": "NodeNext", "moduleResolution": "NodeNext" } }
```

- module CommonJS 配 moduleResolution node（旧名 node10），产物是 require。
- module ES2015 或 ESNext 配 bundler（打包器项目）或 node（原生 ESM）。
- module NodeNext 必须配 NodeNext，且要求文件扩展名与 package.json 的 type 字段一致；module Preserve（TypeScript 5.4 起）配 bundler，import 与 require 原样保留。

**速记**：CommonJS 配 node，ESNext 配 bundler，NodeNext 必须自成一对。



#### moduleDetection 与 useDefineForClassFields

**moduleDetection**：决定不含 import 与 export 的文件被当作模块还是全局脚本，取值 auto、legacy、force。**useDefineForClassFields**：决定类字段用 defineProperty 语义还是赋值语义，target 为 ES2022 及以上时默认 true。

- auto（默认）：有 import 或 export 的文件视为模块，module 为 NodeNext 时全部按模块处理；force 则除声明文件外一律视为模块。
- useDefineForClassFields 为 true 时字段按自有属性定义，会遮蔽父类同名访问器；为 false 时按赋值处理，会触发父类 setter。
- 只想标注外部注入字段又不产生运行时字段时，用 declare 修饰符声明。

**速记**：moduleDetection 管文件是模块还是脚本，useDefineForClassFields 管类字段定义语义。



#### jsx 选项的取值

**jsx**：决定 .tsx 文件中 JSX 的转译方式，取值有 preserve、react、react-jsx、react-jsxdev、react-native。

```json
{ "compilerOptions": { "jsx": "react-jsx", "jsxImportSource": "react" } }
```

- preserve 保留 JSX 原样输出交给打包器；react 转成 React.createElement，需要文件内引入 React。
- react-jsx 转成自动运行时调用，无需手写 import React；react-jsxdev 是它的开发版本，带源码位置等调试信息；react-native 保留 JSX 且输出扩展名为 .js。
- jsxImportSource 指定自动运行时的包名，可换成 preact 或 @emotion/react；只有 .tsx 文件受 jsx 影响。

**速记**：新项目用 react-jsx，交给打包器就用 preserve。



### 严格性开关

#### strict 总开关与家族关系

**strict**：是一组严格检查的总开关，打开它等于同时打开家族内全部开关；要单独放宽某项时，把该项在配置中写为 false 覆盖。

```json
{
  "compilerOptions": {
    "strict": true,
    "strictPropertyInitialization": false
  }
}
```

- strict 聚合 strictNullChecks、noImplicitAny、strictFunctionTypes、strictBindCallApply、strictPropertyInitialization、noImplicitThis、useUnknownInCatchVariables 与 alwaysStrict。
- noUncheckedIndexedAccess、exactOptionalPropertyTypes、noImplicitOverride 不受 strict 管理，必须单独写；老项目迁移可保留 strict: true 并逐个放宽。

**速记**：strict 是八项开关的聚合，另有三项需单独启用。



#### strictNullChecks 与 noImplicitAny

**strictNullChecks**：把 null 与 undefined 当作独立类型，不再允许赋给任意类型。**noImplicitAny**：禁止推断失败时静默退化为 any，必须显式标注或修正调用方。

```ts
function formatName(name: string): string {
  return name.trim();
}
// formatName(null); // 报错：null 不能赋给 string

function parseNumber(input) { // 报错：参数隐式具有 any 类型
  return Number(input);
}
```

- strictNullChecks 影响面最大，strictPropertyInitialization 等检查以它为前提，迁移时优先打开。
- noImplicitAny 只挡推断失败产生的 any，显式写出的 any 仍放行；打开严格空值后宜先修数据入口与返回值。

**速记**：null 与 undefined 独立成类型靠 strictNullChecks，隐式 any 靠 noImplicitAny。



#### 函数与 this 相关开关

**strictFunctionTypes**：要求作为类型书写的函数参数按逆变检查。**strictBindCallApply**：让 bind、call、apply 的参数与返回类型参与检查。**noImplicitThis**：禁止 this 隐式为 any。**useUnknownInCatchVariables**：把 catch 捕获到的值从 any 改为 unknown。

```ts
type ClickHandler = (event: MouseEvent) => void;
// const handleKey: ClickHandler = (event: KeyboardEvent) => {}; // 报错：参数类型不兼容

try {
  JSON.parse("not json");
} catch (error) { // catch 绑定的类型为 unknown
  if (error instanceof Error) console.log(error.message); // 先收窄再访问
}
```

- strictFunctionTypes 不检查方法简写形式，只检查函数类型位置，这是为兼容既有继承写法留的口子。
- strictBindCallApply 能拦下 apply 传参个数与类型不符；useUnknownInCatchVariables 迫使在 catch 内先收窄再用，避免把任意抛出物当成 Error。

**速记**：参数逆变、bind 系列检查、this 必须有类型、catch 值按 unknown 处理。



#### noUncheckedIndexedAccess 与 exactOptionalPropertyTypes

**noUncheckedIndexedAccess**：让索引签名与数组下标读取的结果自动附带 undefined。**exactOptionalPropertyTypes**：区分属性不存在与属性值为 undefined，可选属性不再接受显式赋 undefined。

```ts
const counts: Record<string, number> = { alpha: 1 };
const missing = counts["beta"]; // 类型为 number | undefined
// console.log(missing.toFixed(2)); // 报错：对象可能为 undefined

interface RequestOptions { retries?: number; }
const options: RequestOptions = { retries: undefined }; // 报错：可选属性不接受显式 undefined
```

- 两项都不属于 strict，开启后改动量大，新项目或类型基础较好的项目收益最高。
- 数组循环访问会产生大量判空，确实不会越界的场景可先判长度；exactOptionalPropertyTypes 常与第三方声明冲突，开启前先跑一次全量编译。

**速记**：索引读取带 undefined、可选属性拒绝显式 undefined，两项按项目成熟度取舍。



### 产物与调试

#### outDir 与 rootDir

**outDir**：指定编译产物的输出目录，产物内部保持源码相对结构。**rootDir**：指定源码的公共根目录，决定产物目录结构的计算基准。

```json
{ "compilerOptions": { "rootDir": "./src", "outDir": "./dist" } }
```

- 不写 rootDir 时编译器取所有输入文件的最长公共路径作为根，混入根目录外的文件会让产物多出一层。
- 声明文件同样按 rootDir 结构落到 outDir；输入文件落在 rootDir 之外时编译器直接报错，这一报错正是约束目录结构的手段。

**速记**：outDir 定输出位置，rootDir 定结构基准。



#### declaration 与 declarationMap

**declaration**：为每个源码文件生成同名 .d.ts 声明文件。**declarationMap**：为声明文件生成映射，使编辑器从类型定义跳回原始源码。

```json
{
  "compilerOptions": {
    "declaration": true,
    "declarationMap": true,
    "declarationDir": "./types"
  }
}
```

- 作为库发布或供其他子项目引用时必须开 declaration，否则消费方拿不到类型信息。
- declarationMap 让「转到定义」落在 .ts 而非编译后的 .d.ts；declarationDir 把声明文件与 JS 产物分开，便于只发布类型包。

**速记**：对外提供类型就开 declaration，要跳回源码再加 declarationMap。



#### sourceMap

**sourceMap**：生成 .js.map 文件，把产物位置映射回源码，供浏览器与调试器定位断点。**inlineSourceMap**：把映射内联进 JS 产物。

- inlineSourceMap 把映射内联进 JS，省去额外文件但增大体积，与 sourceMap 互斥。
- 生产构建通常由打包器生成 sourcemap，打包器已负责时 tsc 侧重复生成会拖慢速度；源码不随产物部署时用 sourceRoot 或 inlineSources 修正路径。

**速记**：sourceMap 供调试定位且与 inlineSourceMap 二选一。



#### incremental 与 tsBuildInfoFile

**incremental**：把上次编译的文件与依赖信息写入构建信息文件，下次只重编变化部分。**tsBuildInfoFile**：指定该信息文件的存放路径。

```json
{
  "compilerOptions": {
    "incremental": true,
    "tsBuildInfoFile": "./node_modules/.cache/tsconfig.tsbuildinfo"
  }
}
```

- composite 项目自动开启 incremental，无需重复声明；用 tsc -b 构建时该文件由项目引用统一管理。
- 构建信息文件属于缓存，应加入忽略清单，不要提交到仓库。

**速记**：incremental 靠构建信息文件提速，该文件是缓存不提交。



#### noEmit 与打包器配合、removeComments

**noEmit**：只做类型检查、不写任何产物，转译完全交给打包器或运行器。**removeComments**：在输出中删除注释，默认 false。

```bash
npx tsc --noEmit
```

- Vite、webpack、esbuild 项目常用 noEmit 的配置专门做类型检查，产物由打包器负责。
- noEmit 与 emitDeclarationOnly 互斥，只想产出声明文件时用后者并保留 declaration 为 true；把 tsc --noEmit 固定为 CI 命令，可避免类型错误只停留在编辑器。

**速记**：打包器项目用 noEmit 做纯类型检查并在 CI 固定执行。



### 互操作与兼容

#### esModuleInterop 与 allowSyntheticDefaultImports

**esModuleInterop**：为 CommonJS 模块补齐默认导入与命名空间导入的互操作，并在产物中注入辅助代码。**allowSyntheticDefaultImports**：只放宽类型检查、允许对没有默认导出的模块写默认导入，不改变产物。

```json
{ "compilerOptions": { "esModuleInterop": true } }
```

- esModuleInterop 隐式打开 allowSyntheticDefaultImports，是绝大多数项目的推荐取值。
- 只开 allowSyntheticDefaultImports 时编译通过，但默认导入取到的是整个模块对象，运行时可能得到 undefined；关闭互操作后需改写为命名导入或显式取 .default。

**速记**：esModuleInterop 改产物且隐式带上 allowSyntheticDefaultImports。



#### isolatedModules 与 verbatimModuleSyntax

**isolatedModules**：要求每个文件都能被单独转译，禁止只有跨文件分析才能确定的写法。**verbatimModuleSyntax**：按书写形式原样保留 import 与 export，类型导入必须显式写成 import type。

```ts
export type { UserProfile } from "./userProfile"; // 转译后整行删除
// export { UserProfile } from "./userProfile";  // 报错：无法单独判断是否为类型

import type { UserProfile } from "./userProfile";
// import { UserProfile } from "./userProfile";   // 报错：类型必须用 import type 导入
```

- 使用 Vite、esbuild、swc 等逐文件转译工具时必须开 isolatedModules，否则跨文件信息缺失会转化为运行时错误。
- verbatimModuleSyntax 比 isolatedModules 更严格，开启后不再自动擦除「看起来像类型」的导入；被旧代码卡住时可先开前者，补齐 import type 后再开后者。

**速记**：逐文件转译必须开 isolatedModules，verbatimModuleSyntax 更严格且要求显式 import type。



#### skipLibCheck 与 forceConsistentCasingInFileNames

**skipLibCheck**：跳过对 .d.ts 声明文件的类型检查，只检查项目自身源码。**forceConsistentCasingInFileNames**：要求 import 路径的大小写与实际文件名完全一致。

```json
{
  "compilerOptions": {
    "skipLibCheck": true,
    "forceConsistentCasingInFileNames": true
  }
}
```

- skipLibCheck 能明显缩短编译时间，代价是第三方声明文件之间的类型冲突不再被报出，是多数项目的默认选择；forceConsistentCasingInFileNames 拦住 macOS 上开发正常、Linux 上构建失败的大小写问题，显式写出更稳。

**速记**：skipLibCheck 提速但放过第三方声明冲突，大小写一致性检查防止跨平台构建失败。



#### resolveJsonModule、allowJs 与 checkJs

**resolveJsonModule**：允许 import JSON 文件，并按文件内容推断出字面量类型。**allowJs**：允许把 .js 文件纳入编译范围。**checkJs**：在 allowJs 之上对 .js 文件做类型检查。

```json
{
  "compilerOptions": {
    "resolveJsonModule": true,
    "allowJs": true,
    "checkJs": false
  }
}
```

- JSON 默认导出与 isolatedModules 同用需要打包器配合，否则逐文件转译可能拿不到导出；迁移项目常用 allowJs: true 配合 checkJs: false，先把 JS 纳入范围，checkJs 打开后可用 ts-check 与 ts-nocheck 注释按文件开关。

**速记**：resolveJsonModule 让 JSON 可导入并带字面量类型，迁移项目先 allowJs 后 checkJs。



### 两套典型配置模板

两份模板都是可直接落地的完整配置，配置本身不放注释，取值理由在配置后分组说明。

#### 服务端项目的完整配置

这份配置面向长驻进程类服务端项目：源码集中在 src，产物输出到 dist，声明文件与源码映射一并产出，严格检查全开。运行环境所需的类型包归「后端/Node」主题，此处不列。

```json
{
  "compilerOptions": {
    "target": "ES2022", "lib": ["ES2022"],
    "module": "NodeNext", "moduleResolution": "NodeNext",
    "rootDir": "./src", "outDir": "./dist",
    "declaration": true, "declarationMap": true, "sourceMap": true,
    "strict": true, "noUncheckedIndexedAccess": true, "noImplicitOverride": true,
    "esModuleInterop": true, "forceConsistentCasingInFileNames": true,
    "skipLibCheck": true, "incremental": true,
    "tsBuildInfoFile": "./node_modules/.cache/tsconfig.tsbuildinfo"
  },
  "include": ["src/**/*.ts"],
  "exclude": ["src/**/*.test.ts", "dist"]
}
```

- 目标与模块：target 与 lib 都取 ES2022 与主流运行版本对齐；module 与 moduleResolution 成对写 NodeNext，保证产物格式与解析规则一致。
- 产物与调试：rootDir 与 outDir 明确目录基准；declaration 与 declarationMap 供其他包引用并支持跳转源码；sourceMap 供运行时定位堆栈。
- 严格性：strict 打开全部聚合开关，另加 noUncheckedIndexedAccess 收紧索引读取；noImplicitOverride 要求覆写父类成员时写 override，避免父类改名后子类方法静默变成新方法。
- 互操作与范围：esModuleInterop 让 CommonJS 依赖的默认导入可用；skipLibCheck 与 incremental 控制耗时；include 只收源码，exclude 排除测试与产物目录，避免测试代码混入发布产物。

> [!NOTE]
> **提醒内容**：使用 NodeNext 时相对导入需带文件扩展名，且产物格式受 package.json 的 type 字段影响。

**速记**：服务端配置的关键是 ES2022 目标、NodeNext 双写、全量严格加索引收紧、声明与映射齐出。



#### 前端打包项目的完整配置

这份配置面向由打包器负责转译的前端项目：tsc 只做类型检查不产出文件，模块解析交给打包器规则，严格性在服务端模板基础上再加一档。

```json
{
  "compilerOptions": {
    "target": "ES2020", "lib": ["ES2020", "DOM", "DOM.Iterable"],
    "module": "ESNext", "moduleResolution": "Bundler",
    "jsx": "react-jsx", "jsxImportSource": "react",
    "strict": true, "noUncheckedIndexedAccess": true, "exactOptionalPropertyTypes": true,
    "noEmit": true, "isolatedModules": true, "verbatimModuleSyntax": true,
    "esModuleInterop": true, "resolveJsonModule": true,
    "forceConsistentCasingInFileNames": true, "skipLibCheck": true,
    "incremental": true,
    "tsBuildInfoFile": "./node_modules/.cache/tsconfig.tsbuildinfo"
  },
  "include": ["src/**/*.ts", "src/**/*.tsx"],
  "exclude": ["src/**/*.test.ts", "src/**/*.test.tsx", "dist"]
}
```

- 目标与模块：target 取 ES2020 覆盖主流浏览器语法能力；lib 补 DOM 与 DOM.Iterable 以获得浏览器 API 类型；module 与 moduleResolution 用 ESNext 配 Bundler 并允许省略扩展名。
- JSX 与产物：jsx 用 react-jsx 走自动运行时，无需在每个文件引入 React；noEmit 表示只检查不产出，产物完全交给打包器。
- 严格性：在 strict 之上加 noUncheckedIndexedAccess 与 exactOptionalPropertyTypes，把数组下标与可选属性这两处最常见的空值来源收紧。
- 逐文件转译与兼容：isolatedModules 与 verbatimModuleSyntax 同时开启，确保逐文件转译结果与整体编译一致；esModuleInterop、resolveJsonModule、skipLibCheck、incremental 分别处理互操作、JSON 导入与检查耗时。

> [!TIP]
> **建议内容**：打包器的转译不检查类型，把 tsc --noEmit 挂在提交前与 CI 上，才能保证类型问题在合入前被发现。

**速记**：前端模板的核心是 Bundler 解析、react-jsx、noEmit 只检查、逐文件转译安全。
