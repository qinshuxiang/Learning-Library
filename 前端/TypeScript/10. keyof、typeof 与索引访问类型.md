## keyof、typeof 与索引访问类型

### keyof 运算符

#### 取出对象类型的键联合

**keyof 运算符**：是把对象类型的全部公开属性名取出来、组成一个字面量联合的类型运算符，写作 keyof T。

```ts
type Account = { id: number; email: string; active: boolean };
type AccountKey = keyof Account; // "id" | "email" | "active"
const key: AccountKey = "email";
// const badKey: AccountKey = "name"; // 报错：string 不能赋给 AccountKey
```

- 结果是属性名组成的联合类型，属性名在类型层表现为字符串字面量。
- 只取公开属性，私有与受保护成员不参与；无具名属性时得到 never。
- keyof any 得到 string | number | symbol，keyof unknown 与 keyof {} 都得到 never。

**速记**：keyof T 取 T 的公开属性名，得到一个字符串字面量联合。

  

#### 与索引签名配合得到 string 或 number

对象类型带索引签名时，keyof 不再给出具体属性名，而是给出索引签名的键类型。

```ts
type Dictionary = { [key: string]: number };
type NumericTable = { [index: number]: string };
type DictionaryKey = keyof Dictionary; // string | number
type NumericKey = keyof NumericTable;  // number
```

- 字符串索引签名得到 string | number，数字索引签名只得到 number。
- 字符串索引签名的键含 number，因为 JavaScript 访问属性时数字键会被转成字符串。
- 同时写具名属性与字符串索引签名时，键联合仍是 string | number，泛型约束随之变宽。

**速记**：string 索引签名的键是 string | number，number 索引签名的键只有 number。

  

#### 与泛型约束组合

把 keyof 放进泛型约束，可以让键参数与目标对象类型挂钩，键与返回类型同步推断。

```ts
function getProperty<T extends object, K extends keyof T>(target: T, key: K): T[K] {
  return target[key];
}
const profile = { name: "why", age: 18 };
const name = getProperty(profile, "name"); // string
// getProperty(profile, "email"); // 报错："email" 不属于 keyof T
```

- K extends keyof T 既限制键的合法取值，又让返回类型 T[K] 精确到目标字段的类型。
- 键名需由字面量推断；键参数若声明为 string，会因过宽而不满足约束。
- 有该约束后，函数体里 target[key] 的读取被证明安全，无需类型断言。

**速记**：K extends keyof T 是「按键取值」类函数的通用约束写法。

  

#### keyof 作用于联合类型的结果

keyof 作用于联合类型时取各成员键联合的交集，作用于交叉类型时取并集。

```ts
type Person = { name: string; age: number };
type Employee = { name: string; salary: number };
type PersonKeys = keyof (Person | Employee);   // "name"
type EmployeeKeys = keyof (Person & Employee); // "name" | "age" | "salary"
```

- 联合的值可能是任一成员，编译器只能保证公共属性存在，所以键取交集；交叉类型同时具备两侧成员，所以键取并集。
- 这与联合类型只能访问公共属性的规则一致（本主题第 5 篇），记法是联合取交集、交叉取并集。

**速记**：keyof (A | B) 是 (keyof A) & (keyof B)，keyof (A & B) 是两者之并。

  

### typeof 类型查询

#### 把值变成类型

**typeof 类型查询**：是在类型位置写 typeof 加标识符或标识符的点路径，把该值已有的类型原样取出，写作 type T = typeof value。

```ts
const defaultSettings = { theme: "light", fontSize: 14 };
type Settings = typeof defaultSettings; // { theme: string; fontSize: number }
```

- 类型查询只取类型，不产生运行时代码；typeof 在值位置是 JavaScript 运算符，在类型位置才是类型查询。
- 对象属性被推断为放宽后的 string 与 number，而不是字面量，因为属性可被重新赋值。
- 也可以只取某一个属性：type Theme = typeof defaultSettings.theme; // string

**速记**：typeof 值 把已有值的类型搬到类型层，避免重复声明。

  

#### 与 as const 组合保留字面量

**as const**：是常量断言，把字面量的类型收窄为字面量类型，并给对象与数组加上只读修饰。

```ts
const themeNames = ["light", "dark"] as const;
type Theme = (typeof themeNames)[number]; // "light" | "dark"
const statusMap = { draft: 0, published: 1 } as const;
type StatusKey = keyof typeof statusMap;          // "draft" | "published"
type StatusValue = (typeof statusMap)[StatusKey]; // 0 | 1
```

- 不加 as const 时数组推断为 string[]，(typeof themeNames)[number] 只能得到 string。
- 不加 as const 时对象属性推断为 number，(typeof statusMap)[keyof typeof statusMap] 只能得到 number。
- 数组在 as const 下变成只读元组，元素类型与长度同时被固定。

**速记**：as const 保住字面量与只读，typeof 再把这份精确类型取出来用。

  

#### typeof import 取模块类型

**typeof import** 是类型查询的模块形式，写作 typeof import("模块路径")，取整个模块命名空间的类型。

```ts
// config.ts 导出：export const apiBase = "https://api.example.com";
type ConfigModule = typeof import("./config");
type LoadConfig = ConfigModule["loadConfig"]; // () => string
type ApiBase = ConfigModule["apiBase"];       // string
```

- 只取类型、不引入运行时代码，适合描述模块整体形状，或在类型层判断某个导出是否存在。
- TypeScript 3.8 起普通 import 语句也能写 import type 只做类型导入，模块机制见本主题第 16 篇。
- 路径必须是字符串字面量，用变量拼接无法解析。

**速记**：typeof import("...") 拿到模块对象类型，再用索引访问取具体导出。

  

#### typeof 与公私有属性的限制

keyof 与 typeof 只暴露公开成员，类的 private 与 protected 成员不会出现在键联合里，typeof 类名得到的是构造签名类型而非实例类型。

```ts
class UserService {
  private cache = new Map<string, string>();
  protected version = 1;
  public name = "user-service";
  public findById(id: string): string | undefined { return this.cache.get(id); }
}
type ServiceKey = keyof UserService; // "name" | "findById"
// const cacheKey: ServiceKey = "cache"; // 报错：private 成员不进键联合
type ServiceInstance = InstanceType<typeof UserService>; // UserService
```

- 私有与受保护成员仍参与类型兼容性判断，使类带有名义类型色彩，只是不能被 keyof 取出。
- 想取实例类型要写 InstanceType<typeof 类名>，typeof 类名描述的是「可 new 的类型」，InstanceType 见本主题第 11 篇。
- 接口与类型别名的属性天然公开，限制只出现在类的私有与受保护成员上。

**速记**：public 才进类型运算；typeof 类名给构造签名，实例类型用 InstanceType 取。

  

### 索引访问类型

#### T[K] 取属性类型

**索引访问类型**：是用方括号按属性名取另一个类型中该属性类型的写法，写作 T[K]，K 必须是 keyof T 的子集。

```ts
type Order = { id: number; items: string[]; paid: boolean };
type OrderId = Order["id"];       // number
type OrderItems = Order["items"]; // string[]
// type Wrong = Order["total"];   // 报错："total" 不是 keyof Order
```

- K 可以是单个字面量、字面量联合、keyof T，或任何键类型的子集。
- T 与 K 都能是泛型参数，此时要保证 K extends keyof T，否则编译器无法确认键存在。
- 与点号访问不同，索引访问在类型位置工作，不会读取任何值。

**速记**：T[K] 按名字取类型成员，K 必须落在 keyof T 内。

  

#### 联合键的分配效果

键为联合时，索引访问把结果分配成每个键结果组成的联合；目标为联合时同样逐成员分配。

```ts
type Order = { id: number; paid: boolean; note: string };
type OrderField = Order["id" | "paid"]; // number | boolean
type AnyField = Order[keyof Order];     // number | boolean | string

type Shape = { kind: "circle"; radius: number } | { kind: "square"; side: number };
type ShapeKind = Shape["kind"]; // "circle" | "square"
// type ShapeRadius = Shape["radius"]; // 报错：square 上没有 radius
```

- Order[keyof Order] 是「取任意字段」的经典写法，结果是全部字段类型的联合。
- 目标为联合时，索引访问要求每个成员都有该键，缺一个就报错，这与联合只允许访问公共属性是同一规则。
- 键为 never 时结果是 never，因为没有任何成员可取。

**速记**：键联合逐键分配，目标联合逐成员分配；缺键即报错。

  

#### 与数组和元组的配合

数组与元组也支持索引访问，数组用 [number] 取元素类型，元组用数字字面量取某位置的类型。

```ts
type Names = string[];
type Name = Names[number]; // string

type Point = [x: number, y: number];
type First = Point[0];         // number
type Coord = Point[number];    // number
type Length = Point["length"]; // 2
```

- 数组没有固定位置，只有数字索引签名，所以 Names[0] 与 Names[number] 结果相同，都是元素类型。
- 元组的 length 属性被推断为长度字面量，可用索引访问直接取出。
- 元组的 keyof 会给出 "0"、"1"、"length" 与数组方法的混合结果，实际使用中很少整体展开。

**速记**：数组取 [number]，元组取位置字面量或 [number]，length 可当长度类型用。

  

#### 与可辨识联合的配合

**可辨识联合**：是各成员含同一个判别属性、且该属性为字面量类型的联合类型，用索引访问可以取出判别属性的字面量联合当作分支名集合。

```ts
type Shape =
  | { kind: "circle"; radius: number }
  | { kind: "square"; side: number }
  | { kind: "rect"; width: number; height: number };

type ShapeKind = Shape["kind"]; // "circle" | "square" | "rect"
// type ShapeRadius = Shape["radius"]; // 报错：并非所有成员都有 radius
```

- Shape["kind"] 得到的字面量联合可直接用于约束分支名、事件名或映射表的键。
- 判别属性之外的字段只在部分成员上存在，索引访问会报错，必须先收窄（见本主题第 8 篇）。
- 判别属性必须是字面量类型，声明成 string 会让联合失去可辨识性，分支无法穷尽。

**速记**：Shape["kind"] 取判别键的字面量联合，是分支与查表的键来源。

  

### 索引签名与映射的衔接

#### 索引签名的类型约束

**索引签名**：是在对象类型里用方括号声明任意键及其值类型的写法，键类型只能是 string、number 或 symbol。

```ts
interface StringMap { [key: string]: string; }
interface NumberMap { [index: number]: number; }
const headers: StringMap = { "content-type": "application/json" };
const scores: NumberMap = { 0: 90, 1: 85 };
```

- 键类型只能写这三种原始类型，不能写成某组字面量，模板字面量键的写法归本主题第 13 篇。
- string 与 number 索引签名可以同时存在，此时数字键同时满足两者，number 索引签名的值类型必须能被 string 索引签名接受。
- 值类型可以是任意类型，包括函数、联合与泛型参数。

**速记**：索引签名只允许 string、number、symbol 三种键类型。

  

#### 具名属性必须兼容索引签名

同一对象类型同时出现具名属性与索引签名时，每个具名属性的类型必须是索引签名值类型的子类型，否则报错。

```ts
interface UserRecord {
  [key: string]: string;
  name: string; // 合法：string 兼容 string
}
interface BadRecord {
  [key: string]: number;
  // name: string; // 报错：string 不能赋给 number
}
```

- 校验只要求单向兼容，即具名属性的类型要能赋给索引签名的值类型，反过来不受限制。
- 想让具名属性使用不同值类型，就把索引签名的值类型放宽为联合，或把该属性移出此类型。

**速记**：具名属性必须能赋给索引签名的值类型，方向是单向的。

  

#### 索引签名带来的类型宽松问题

索引签名会让编译器认为任意键都存在，从而关闭属性名检查，这是类型安全的主要代价。

```ts
interface Config { [key: string]: string; }
const config: Config = { mode: "dark" };
const missingValue = config.notExist; // string，运行时为 undefined
// const wrong: number = config.mode; // 报错：string 不能赋给 number
```

- 标注与运行时脱节：config.notExist 标注为 string，实际得到 undefined。
- 打开 noUncheckedIndexedAccess 后，索引访问与点号访问的结果都会加上 undefined，取值前必须判空。
- 打开 noPropertyAccessFromIndexSignature 后必须写成 config["notExist"]，以提示这里不是固定字段；两个开关都属严格性配置，见本主题第 17 篇。

> [!WARNING]
> **警告内容**：索引签名不等于「键一定存在」，它只是关闭了键名检查；配置对象与缓存表要么改用具名属性，要么打开 noUncheckedIndexedAccess 并在取值处判空。

**速记**：索引签名放宽键检查，代价是键名与缺值都逃过编译期。

  

#### 映射类型的一句话预告

**映射类型（mapped type）**：是遍历一个键联合、为每个键生成属性从而构造新对象类型的类型运算符。

- 它把本篇的 keyof 与索引访问串起来：先取键联合，再为每个键指定新的值类型。
- 语法与修饰符、键重映射、内置工具类型清单归本主题第 11 篇，本篇只做这一句预告。

**速记**：索引签名放宽键检查，映射类型负责成批生成键。

  

### 组合应用

#### 手写类型安全的 getProperty

用 keyof 约束键参数、用索引访问描述返回类型，可以让取值函数的键与结果类型自动对齐。

```ts
function getProperty<T extends object, K extends keyof T>(target: T, key: K): T[K] {
  return target[key];
}
const account = { id: 7, email: "why@example.com", active: true };
const accountId = getProperty(account, "id"); // number
// getProperty(account, "phone"); // 报错："phone" 不是 keyof typeof account
```

- 返回类型是 T[K]，调用点直接拿到该字段的精确类型，无需类型断言。
- 键参数必须是字面量或字面量联合，来自外部的 string 要先校验或收窄再传入。

**速记**：T extends object 配 K extends keyof T，返回 T[K]，取值即得精确类型。

  

#### 按字段名取值的表单场景

表单场景需要在读取与写入时都保证字段名与值类型成对，用 T[K] 同时约束两者即可。

```ts
type UserForm = { username: string; age: number };
function writeField<T extends object, K extends keyof T>(values: T, field: K, next: T[K]): void {
  values[field] = next;
}
function readField<T extends object, K extends keyof T>(values: T, field: K): T[K] {
  return values[field];
}
const form: UserForm = { username: "", age: 0 };
writeField(form, "age", 18);     // 合法
// writeField(form, "age", "18"); // 报错：string 不能赋给 number
// writeField(form, "phone", ""); // 报错："phone" 不是 keyof UserForm
const currentAge = readField(form, "age"); // number
```

- 参数 next 用 T[K] 描述，值类型跟着字段名走，写错字段类型在编译期即被拦住。
- values 声明为 T 而非只读类型，所以 writeField 内部允许直接赋值。
- 字段名来自配置或网络时，先用类型谓词（本主题第 8 篇）把 string 收窄成 keyof T 再传入。

**速记**：读用 T[K] 作返回、写用 T[K] 作参数，字段名与值类型同时被约束。

  

#### 键联合驱动的事件名常量与类型校验

把常量表用 as const 固定，再用 typeof 与索引访问取出联合，就能让同一份常量同时充当运行时列表与编译期类型。

```ts
const eventNames = ["click", "submit", "reset"] as const;
type EventName = (typeof eventNames)[number]; // "click" | "submit" | "reset"

const handlerTable = {
  click: () => console.log("处理点击"),
  submit: () => console.log("处理提交"),
  reset: () => console.log("处理重置"),
};
type HandlerName = keyof typeof handlerTable; // "click" | "submit" | "reset"
const selectedHandler: HandlerName = "reset"; // 合法
// const missingHandler: HandlerName = "blur"; // 报错：不在允许的事件名里
// const missingEvent: EventName = "blur";     // 报错：不在允许的事件名里
```

- eventNames 与 handlerTable 分别是数组常量与对象常量两种来源，前者用 [number]，后者用 keyof。
- 新增事件时只改常量，EventName 与 HandlerName 自动同步，遗漏注册会立刻暴露。
- 需要「每个事件名都必须有处理函数」这类完整性校验时，要借助映射类型，见本主题第 11 篇。

**速记**：数组常量用 (typeof names)[number]，对象常量用 keyof typeof，二者都得到键联合。
