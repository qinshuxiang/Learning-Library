## 类、抽象类与访问修饰符

### 类成员的类型标注

**类成员**：是类体内声明的属性、方法与构造函数，每个成员都要给出类型，实例的形状才可被编译器检查。

#### 属性的类型标注

**属性**：是挂在实例上的数据槽位，声明时写出属性名与类型，是否带初始值决定它是否参与初始化检查。

```ts
class UserService {
  name: string;      // 无初始值，由构造函数赋值
  retryCount = 3;    // 有初始值，推断为 number
  constructor(name: string) { this.name = name; }
}
const service = new UserService("userService");
console.log(service.name, service.retryCount); // "userService" 3
```

- 有初始值的属性可由推断得出类型，写不写注解等价；无初始值的属性必须写注解，否则严格模式下按隐式 any 报错。
- 属性类型只在编译期存在，编译产物里字段仍是普通 JS 属性，类型被擦除。

**速记**：有初始值的属性可省注解，无初始值的属性必须写注解。



#### 方法与构造函数

方法要写出参数类型与返回类型，构造函数只写参数列表，不能标返回类型。

```ts
class Temperature {
  private celsius: number;
  constructor(celsius: number) { this.celsius = celsius; }
  toFahrenheit(): number {
    return this.celsius * 9 / 5 + 32;
  }
}
console.log(new Temperature(25).toFahrenheit()); // 77
```

- 构造函数写成带返回类型会报错，它的结果类型由类名决定，不能手动指定。
- 方法可省略返回类型由推断得出，但公共方法建议显式写出，避免实现改动导致返回类型静默漂移。

**速记**：构造函数不写返回类型，其类型由类名决定；公共方法显式写返回类型更稳。



#### 可选成员与只读成员

**可选成员**：是名字后带问号的属性或方法，读取类型是原类型与 undefined 的联合。**只读成员**：是用 readonly 修饰的属性，只能在声明处或构造函数内赋值。

```ts
class Account {
  readonly id: string;
  nickname?: string;
  constructor(id: string) { this.id = id; }
  rename(nickname: string): void { this.nickname = nickname; }
}
const account = new Account("a-1");
account.rename("ada");
console.log(account.nickname); // "ada"
```

- readonly 只禁止对该属性重新赋值，不冻结它指向对象的内部状态；要挡内部修改就用 readonly 数组或对应的只读工具类型。
- 可选成员读取时类型里带着 undefined，使用前要收窄或给默认值。

**速记**：可选成员读取时带 undefined，readonly 只挡重新赋值、不挡内部修改。



#### 初始化检查与声明赋值分离

**strictPropertyInitialization**：是 strict 家族的一个开关，要求每个非可选、类型不含 undefined 的实例属性在构造函数结束时已确定赋值。

```ts
class Session {
  token: string;                // 构造函数内赋值，满足检查
  expiresAt?: Date;             // 可选属性，跳过检查
  store!: Map<string, string>;  // 确定赋值断言，由 init 完成赋值
  constructor(token: string) { this.token = token; }
  init(): void { this.store = new Map<string, string>(); }
}
console.log(new Session("t-1").token); // "t-1"
```

- 满足检查的途径：声明处初始化、构造函数内直接赋值、标成可选；在构造函数里调用别的方法给属性赋值，控制流分析不认这条路径，仍报未初始化。
- 感叹号是确定赋值断言，只作编译期承诺、不插入运行时检查，赋值路径漏掉时读到 undefined。

> [!WARNING]
> **警告内容**：确定赋值断言只在能保证赋值一定发生时使用，构造顺序不确定时改用可选成员或显式判空。

**速记**：属性要么声明即初始化、要么在构造函数内赋值、要么标可选，否则用感叹号断言并自担遗漏风险。



### 访问修饰符与私有字段

**访问修饰符**：是写在成员前、限定其可访问范围的修饰符，取值有 public、protected、private，省略时按 public 处理。

#### 三种修饰符与默认可见性

public 在类内、子类与外部都可访问，protected 只在类内与子类可访问，private 只在类内可访问。

```ts
class Order {
  private secret = "internal";
  protected total = 0;
  getSecret(): string { return this.secret; }  // 类内可访问 private
}
class DiscountOrder extends Order {
  apply(amount: number): void {
    this.total = amount;    // protected 可在子类访问
    // this.secret;         // 报错：private 仅 Order 内部可访问
  }
}
console.log(new Order().getSecret()); // "internal"
```

- 不写修饰符等价于 public，显式写只在强调意图时有价值。
- private 只给本类用，protected 给子类当扩展点；二者都只是编译期约束，编译后字段照常存在。

**速记**：不写修饰符就是 public，private 只给自己用，protected 给子类用。



#### 井号私有字段与 private 的差异

**井号私有字段**：是以 # 开头的字段，由 ECMAScript 提供真正的运行时私有，类外任何写法都无法访问；private 修饰符只在编译期拦截。

```ts
class Wallet {
  #balance = 0;
  private internalNote = "";
  deposit(amount: number): void { this.#balance += amount; }
  get balance(): number { return this.#balance; }
}
const wallet = new Wallet();
wallet.deposit(100);
console.log(wallet.balance);  // 100
// wallet.internalNote;       // 报错：编译期拦截，运行时该字段仍存在
```

- 井号字段的隐藏由 JS 引擎保证，编译到旧语法时需要 WeakMap 等降级方案；private 修饰符编译后无痕迹。
- 井号字段不能配合参数属性简写，也不能被子类以任何方式访问；需要运行时也必须私有就用井号。

**速记**：井号字段是真私有、有运行时成本，private 修饰符只是编译期约束。



#### 参数属性

**参数属性**：是在构造函数参数前加访问修饰符或 readonly，让编译器同时声明同名属性并完成赋值的简写。

```ts
class HttpClient {
  constructor(private readonly baseUrl: string, private timeout = 5000) {}
  buildUrl(path: string): string {
    return new URL(path, this.baseUrl).toString();
  }
}
console.log(new HttpClient("https://api.example.com").buildUrl("/users"));
// "https://api.example.com/users"
```

- 一个参数同时完成参数声明、属性声明与赋值三件事；修饰符顺序固定为访问修饰符在前、readonly 在后。
- 取舍在于属性声明散落到参数列表、可读性下降；需要先校验再赋值、属性名与参数名不同、或要用井号字段时，改回显式声明加构造函数赋值。

**速记**：参数属性把参数声明、属性声明与赋值合成一步，代价是声明位置分散。



### 抽象类与 implements

**抽象类**：是用 abstract 修饰、不能直接实例化、专门用于被继承的类，可只声明成员签名而不给实现。

#### 抽象方法与抽象属性

**抽象方法**：是只有签名、没有方法体、以分号结尾的方法。**抽象属性**：是只有类型、没有初始值的属性。

```ts
abstract class Shape {
  abstract area(): number;
  abstract readonly unit: string;
}
class Circle extends Shape {
  readonly unit = "米";
  constructor(private radius: number) { super(); }
  area(): number { return Math.PI * this.radius ** 2; }
}
console.log(new Circle(2).unit, new Circle(2).area()); // 米 12.566370614359172
```

- 子类必须实现全部抽象成员，漏掉一个就仍是抽象类，必须继续加 abstract 修饰。
- 抽象成员不能用 private 修饰，抽象属性不能带初始值。

**速记**：抽象成员只有签名没有实现，子类必须全部补齐，抽象成员不能是 private。



#### 抽象类不能实例化

抽象类禁止用 new 创建实例，但仍可以有构造函数供子类通过 super 调用。

- 直接 new 抽象类会报错，报错信息为 Cannot create an instance of an abstract class。
- 抽象类可以当作类型，用子类实例给它赋值，这是它最常见的用法。
- 抽象类会编译成真实的类，运行时存在；接口在编译后被擦除，这是二者在产物上的差别。

**速记**：抽象类不能 new，但可作类型并用子类实例赋值，运行时它仍是真实存在的类。



#### 抽象类与接口的分工

抽象类可带实现、实例状态与 protected 成员，一个类只能继承一个；接口只描述公共形状，一个类可以实现多个。

- 需要复用实现与状态用抽象类，需要描述能力契约并自由组合用接口。
- 常见组合是接口定契约、抽象类给骨架实现、具体类填空；抽象类也可以 implements 接口，把约束转成对子类的要求。

> [!TIP]
> **建议内容**：跨继承树共享行为或需要 protected 成员时用抽象类，只约束公共形状时用接口，两者可同时使用。

**速记**：抽象类表达是什么并提供实现，接口表达能做什么且可多重组合。



#### implements 与接口约束

**implements**：是让类接受一个或多个接口公共形状检查的语法，类必须实现接口声明的每个成员。

```ts
interface Named {
  readonly name: string;
}
interface Scored {
  score(): number;
}
class Player implements Named, Scored {
  constructor(public readonly name: string, private level: number) {}
  score(): number { return this.level * 10; }
}
console.log(new Player("ada", 3).score()); // 30
```

- 一个类可以 implements 多个接口，逗号分隔；只检查公共成员，private 与 protected 不参与，类多出成员不报错。
- implements 只做静态检查，不提供实现也不改变类的成员；接口成员默认必填，只有标问号才可选。

**速记**：implements 可一次接多个接口，只做公共形状检查，不提供任何实现。



### 类与结构化类型

**结构化类型（structural typing）**：是 TypeScript 的类型兼容规则，只要一个类型的成员覆盖目标类型要求的成员，二者就兼容，与是否声明继承无关。

#### 结构化类型在类上的表现

类的实例类型参与比较的是成员结构而不是类名，两个毫无继承关系的类只要形状一致就能互相赋值。

```ts
class Point {
  constructor(public x: number, public y: number) {}
}
class Vector {
  constructor(public x: number, public y: number) {}
}
const point: Point = new Vector(1, 2);   // 结构相同，允许
const shape: { x: number; y: number } = new Point(3, 4);
console.log(point.x, shape.y); // 1 4
```

- extends 只负责复用实现，不产生「只有本继承链上才能赋值」的独占关系，兼容性仍按结构判定。
- 源类型成员多于目标要求时可以赋值，缺少目标要求的成员则不兼容；方法参数按逆变、返回值与属性按协变比较。
- 子类实例总能赋给父类类型，因为子类结构包含父类全部成员，这是结构包含的结果而非继承特权。

**速记**：类按成员结构比较，与继承关系无关；子类能赋给父类是结构包含的结果。



#### 类与接口互相赋值

类实例可以赋给接口类型，接口类型也可以赋给类的实例类型，条件是双方成员结构互相覆盖。

```ts
interface Logger {
  log(message: string): void;
}
class ConsoleLogger {
  log(message: string): void { console.log(message); }
}
const logger: Logger = new ConsoleLogger(); // 类实例赋给接口
const same: ConsoleLogger = logger;         // 接口赋给类实例
logger.log("ready");                        // "ready"
```

- 类赋给接口：类的公共成员满足接口全部要求即可；接口赋给类：接口必须提供类的全部实例成员且类型一致。
- 一旦类带有 private 或 protected 成员，接口无法提供这些成员，双向赋值立即中断。

**速记**：类与接口只要结构互相覆盖就能双向赋值，私有成员会打断这条通路。



#### private 成员对兼容性的影响

private 与 protected 成员把结构比较变成来源比较，该成员必须来自同一处声明，两个类型才算兼容。

```ts
class NamingService {
  private cache = new Map<string, string>();
  format(value: string): string { return value.trim(); }
}
class TitleService {
  private cache = new Map<string, string>();
  format(value: string): string { return value.trim(); }
}
// const title: TitleService = new NamingService(); // 报错：private 来源不同
console.log(new NamingService().format("  ada  ")); // "ada"
```

- 两个类即使公共形状与私有成员名字都相同，只要各自声明就不是同一来源，仍然不兼容。
- 子类与父类兼容，因为私有成员出自同一处声明；没有私有成员的类则回到纯结构比较。

**速记**：private 与 protected 成员要求同一处声明，把结构化比较变成近似名义比较，用于保护内部不变量。



### 类的高级类型

#### this 类型与链式调用

**this 类型**：是类或接口中写为 this 的特殊类型，表示当前实例的具体类型，随调用方所在的子类而变。

```ts
class QueryBuilder {
  private conditions: string[] = [];
  where(condition: string): this {
    this.conditions.push(condition);
    return this;
  }
  toSql(): string { return `WHERE ${this.conditions.join(" AND ")}`; }
}
class PagedQueryBuilder extends QueryBuilder {
  limit(size: number): this { return this; }
}
const query = new PagedQueryBuilder().where("age > 18").limit(10);
console.log(query.toSql()); // "WHERE age > 18"
```

- 返回类型写 this 而不是类名，子类调用后仍保留子类类型，链式调用不会丢方法。
- this 类型也能出现在参数位置，用于约束两个对象必须同型。

**速记**：返回类型写 this 可让链式调用保留子类类型，写类名会在子类上丢失方法。



#### 类表达式与类作为类型

类名同时是值与类型：作值用时是构造函数，作类型用时是实例类型，位置决定取哪一个。

```ts
class Point {
  constructor(public x: number, public y: number) {}
}
const origin: Point = new Point(0, 0);      // Point 作实例类型
const pointFactory: typeof Point = Point;   // typeof Point 作构造函数类型
const NamedPoint = class extends Point {};  // 类表达式
console.log(origin.x, pointFactory.name, new NamedPoint(3, 4).y); // 0 "Point" 4
```

- 类表达式可以匿名，常用于导出匿名类、在表达式中继承或按条件构造类。
- 要描述构造函数本身用 typeof 类名，静态成员属于这一侧；typeof 类型查询详见本主题第 10 篇。

**速记**：类名作类型是实例类型，作值是构造函数，构造函数类型写作 typeof 类名。



#### 静态成员的类型

静态成员属于构造函数而不是实例，通过类名访问，实例类型里不含静态成员。

- 静态成员用类型注解声明，可以用访问修饰符与 readonly 修饰，规则与实例成员一致。
- 静态方法里的 this 指向构造函数，因此访问不到实例成员；实例类型里也没有静态成员。
- 静态侧面用 typeof 类名 描述，实例侧面用类名描述。

**速记**：静态成员挂在构造函数上，用类名访问，其类型写作 typeof 类名。



#### override 与 noImplicitOverride

**override**：是写在子类成员前、标明它覆盖基类成员的修饰符；noImplicitOverride 开启后，覆盖基类成员必须写 override，漏写就报错。

```ts
class Notifier {
  send(message: string): void { console.log(`默认：${message}`); }
}
class EmailNotifier extends Notifier {
  override send(message: string): void { console.log(`邮件：${message}`); }
}
const notifier: Notifier = new EmailNotifier();
notifier.send("上线完成"); // "邮件：上线完成"
```

- 写了 override 却找不到可覆盖的基类成员会报错，基类改名或删除成员时因此会立刻暴露。
- 构造函数不写 override，方法与属性都可以使用；override 只是编译期标记，运行时仍按原型链解析。

**速记**：override 标注覆盖关系，noImplicitOverride 强制覆盖必须标注，基类改名会立刻报错。



#### 成员声明合并与 declare 字段

同名的类与接口会合并，接口成员并入类的实例类型，用于给已有类补类型；declare 字段只声明类型、不生成初始化代码。

```ts
class UserService {
  constructor(public readonly id: string) {}
}
interface UserService { role: string; }   // 合并进实例类型
const service = new UserService("u1");
service.role = "admin";
console.log(service.role); // "admin"

class FormComponent {
  declare element: HTMLDivElement;   // 只声明类型，不生成字段
}
```

- 类与接口合并只补充类型，不产生实现，合并进来的成员必须在别处有运行时来源，否则读到 undefined。
- declare 字段不参与初始化检查，也不发出任何初始化语句，适合由外部或框架写入的字段。

**速记**：类与接口同名会合并类型、不产生实现；declare 字段只写类型，不生成初始化代码。
