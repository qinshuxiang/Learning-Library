## 联合类型、交叉类型与字面量类型

### 联合类型

**联合类型（union）**：是把两个及以上类型用竖线组合成的新类型，读作「或」，值属于其中任意一个成员类型即合法。

#### 或的语义

联合的语义是取值集合的并集，只要值落在任意一个成员内即可赋值。

```ts
type Identifier = string | number;
function printIdentifier(value: Identifier): void {
  console.log(value);
}
// printIdentifier(true); // 报错：boolean 不属于 string | number
```

- 成员可为原始类型、对象、字面量、函数，也可为另一个联合。
- 联合满足交换律与结合律，条件表达式两支类型不同时推断为联合，flag ? "enabled" : 0 得到 "enabled" | 0。
- 进入函数体后若要对具体成员做处理，就需要类型收窄，收窄规则归本主题第 8 篇。

**速记**：A | B 读作「或」，值是各成员取值集合的并集。

  
  
#### 公共属性访问限制

联合类型的变量只能访问所有成员共有的属性，访问仅部分成员拥有的属性会被拒绝。

```ts
type Employee = { name: string; salary: number };
type Contractor = { name: string; hourlyRate: number };
function greetStaff(person: Employee | Contractor): void {
  console.log(person.name); // 合法：公共属性
  // console.log(person.salary); // 报错：Contractor 上不存在 salary
}
```

- 可访问成员等于各成员属性的交集，这是编译期无法确认运行时成员时的安全策略。
- 要访问专有属性必须先缩小类型范围，报错信息形如「类型 Employee | Contractor 上不存在属性 salary」。

**速记**：联合只允许访问公共属性，专有属性需要先收窄。

  
  
#### 联合的成员化简

编译器在不改变语义的前提下化简联合：重复成员去重，较宽的类型吸收较窄的类型。

- A | A 化简为 A，A | never 化简为 A，A | any 化简为 any。
- A | unknown 化简为 unknown，unknown 是联合的顶类型，never 是单位元。
- 字面量类型被基础类型吸收，"draft" | string 化简为 string。

```ts
type Repeated = string | string;      // string
type Absorbed = "draft" | string;     // string
type WithNever = number | never;      // number
type WithUnknown = boolean | unknown; // unknown
```

**速记**：重复成员去重、窄类型被宽类型吸收，never 与 unknown 分别是联合的单位元与顶类型。

  
  
#### never 作为空联合

**never**：是不含任何成员的类型，等价于空联合，表示不存在合法取值。

- 没有任何值可以赋给 never，反过来说 never 可以赋给任何类型。
- never 出现在联合中会被直接消去：T | never 就是 T。
- 用于标注永不正常返回的函数，也是穷尽检查的基础（本主题第 8 篇）。
- never 与 void 不同：void 表示函数返回值为空但会正常返回，never 表示函数不会正常返回。

```ts
function fail(message: string): never {
  throw new Error(message);
}
// const value: never = 1; // 报错：number 不能赋给 never
```

**速记**：never 是空联合，无值可赋，出现在联合里会被消去。

  
  
### 交叉类型

**交叉类型（intersection）**：是用 & 把多个类型合并成的新类型，读作「且」，值必须同时满足所有成员类型。

#### 且的语义

交叉的语义是条件叠加，值必须同时属于每一个成员类型。

```ts
type HasName = { name: string };
type HasAge = { age: number };
type Person = HasName & HasAge;

// const bob: Person = { name: "Bob" }; // 报错：缺少 age 属性
```

- 交叉用于把多个独立的小类型片段组合成复合类型。
- 与联合方向相反：联合放宽要求，交叉收紧要求，A | B 接受满足任一边的值，A & B 只接受同时满足所有边的值。

**速记**：A & B 读作「且」，值必须同时满足全部成员。

  
  
#### 对象交叉的合并效果

当所有成员都是对象类型时，交叉表现为属性合并，结果类型拥有全部成员的全部属性。

```ts
type Timestamps = { createdAt: string; updatedAt: string };
type SoftDelete = { deletedAt: string | null };
type Article = { title: string } & Timestamps & SoftDelete;
// Article 同时拥有 title、createdAt、updatedAt、deletedAt 四个属性
```

- 同名且同类型的属性合并成一个，不报错，成员越多结果属性越全。
- 把时间戳这类通用字段抽成小类型片段再交叉拼装，比在每个类型里重复书写更易维护。

**速记**：对象交叉得到属性并集，同名同类型自动合并。

  
  
#### 同名属性类型冲突得到 never

若多个成员对同一属性声明了互不兼容的原始类型，该属性类型被推成交叉结果，最终化简为 never。

```ts
type WithStringId = { id: string };
type WithNumberId = { id: number };

type Broken = WithStringId & WithNumberId; // id 类型为 string & number，即 never
// const broken: Broken = { id: "a" };     // 报错：id 需要 never
```

- 冲突不在类型定义处报错，而在首次赋值时暴露。
- 两边都是对象类型时同名属性合并为交叉结构，不会立即变 never，但可能同样无法赋值。
- 需要二者其一的语义时应改用联合，而不是交叉。

> [!WARNING]
> **警告内容**：出现「不能将类型 X 赋给类型 never」的错误时，优先检查是否有交叉成员对同一属性声明了不兼容的类型。

**速记**：交叉同名且原始类型不兼容时，属性类型化简为 never。

  
  
#### 交叉与继承的差别

**interface 继承**：是声明式的类型扩展，子接口通过 extends 获得父接口成员；**交叉类型**：是在类型位置即时组合已有类型的运算。

- 同名冲突：继承在声明处直接报错，交叉延迟到赋值或访问时才暴露。
- 覆盖能力：继承允许子接口重新声明同名成员，交叉只能叠加不能覆盖。
- 结构关系：继承形成显式父子层级，交叉是扁平组合，没有层级概念。

```ts
interface BaseResource { id: string }
interface UserResource extends BaseResource { name: string }
type FlatUserResource = { id: string } & { name: string };
```

> 选择原则：表达「是一种」的层级契约与可扩展接口时用继承，把正交的能力片段自由拼装时用交叉。interface 与 type 的完整对比见本主题第 4 篇。

**速记**：继承有层级、冲突立即报错；交叉是扁平组合、冲突延迟暴露。

  
  
### 字面量类型与 const 断言

**字面量类型（literal type）**：是以具体字面量值作为类型、只接受该精确值的类型。

#### 字符串与数字与布尔字面量

字符串、数字、布尔值都可以作为字面量类型使用。

```ts
type Direction = "north" | "south" | "east" | "west";
type HttpStatus = 200 | 301 | 404 | 500;
type Toggle = true | false; // 等价于 boolean
let heading: Direction = "north";
// heading = "up"; // 报错："up" 不能赋给类型 Direction
```

- 布尔字面量只有 true 与 false，二者的联合即 boolean。
- 单独使用一两个字面量类型意义有限，与联合组合后才体现约束价值，模板字面量类型的延伸归本主题第 13 篇。字面量类型把取值约束提前到编译期，非法取值在写代码时就被拒绝。

**速记**：字面量类型以具体值作为类型，通常与联合搭配使用。

  
  
#### as const 对数组的收窄

**const 断言（const assertion）**：是在字面量表达式后写 as const，使推断取最窄的字面量类型，并把数组推断为只读元组。

```ts
const directions = ["north", "south", "east"];                // string[]
const frozenDirections = ["north", "south", "east"] as const; // readonly ["north", "south", "east"]
const firstDirection = frozenDirections[0]; // "north"
// frozenDirections.push("west"); // 报错：readonly 元组上不存在 push
```

- 不加 as const 时推断为可变数组，元素类型为 string；加了之后长度固定，每个位置的类型精确记录。
- 若要由此推导联合类型，需配合索引访问类型，写法见本主题第 10 篇。

> [!CAUTION]
> **注意内容**：as const 只影响类型，不产生运行时的冻结，数组在运行时仍可被修改，需要真正的不可变应使用 Object.freeze。

**速记**：as const 把数组收窄为只读元组，元素类型变为字面量类型。

  
  
#### as const 对对象的收窄

对对象使用 as const 时，所有属性递归地变为只读，且类型取最窄的字面量类型。

```ts
const config = { mode: "dark", retries: 3 };
// 推断为 { mode: string; retries: number }
const frozenConfig = { mode: "dark", retries: 3 } as const;
// 推断为 { readonly mode: "dark"; readonly retries: 3 }
```

- 嵌套的对象与数组会递归应用同样的规则，属性变为只读后赋值与删除都会报错。
- 配合 keyof 与 typeof 可反推属性名的字面量联合，用法见本主题第 10 篇：type Status = keyof typeof statusText。

**速记**：as const 作用于对象时递归加只读，并把属性类型收窄为字面量类型。

  
  
#### 字面量类型与基础类型的关系

**基础类型**：是其全部字面量类型的联合的超集；字面量类型是基础类型的子类型。

- 字面量类型可赋给对应的基础类型，反向赋值不允许。
- 联合中字面量被基础类型吸收，"draft" | string 化简为 string。
- 基础类型不会自动提升为字面量类型，除非使用 as const 或处于上下文类型位置。

```ts
let basic: string = "draft";     // 合法：字面量赋给基础类型
// let literal: "draft" = basic; // 报错：string 不能赋给 "draft"
let mutableValue = "draft";      // 推断为 string
const fixedValue = "draft";      // 推断为 "draft"
```

**速记**：字面量类型是基础类型的子类型，子可赋父、父不可赋子。

  
  
### 可辨识联合

**可辨识联合（discriminated union）**：是每个成员都带一个取字面量类型的公共属性、并以该属性区分成员的联合类型。

#### 判别属性的作用

**判别属性（discriminant）**：是各成员共有、取值互不重叠且类型为字面量的属性。

- 必须存在于每个成员上，否则无法整体判断。
- 类型必须是字面量类型，通常是字符串字面量，且取值互不重叠。
- 它是编译器区分当前成员的唯一依据，也是后续收窄的入口。

```ts
type SuccessResult = { status: "success"; data: string[] };
type ErrorResult = { status: "error"; message: string };
type LoadingResult = { status: "loading" };
type RequestResult = SuccessResult | ErrorResult | LoadingResult;
```

上面的 status 就是判别属性。

> [!IMPORTANT]
> **重要内容**：判别属性必须声明为字面量类型。若写成 string，各成员的该属性相互兼容，编译器无法区分成员，可辨识联合会退化为普通联合。

**速记**：判别属性是各成员共有、取值互不重叠的字面量类型属性。

  
  
#### switch 与 if 的典型写法

判别属性最常见的用法是在 switch 或 if 中判断它的取值，从而在分支内访问成员专有属性。

```ts
function renderResult(result: RequestResult): string {
  switch (result.status) {
    case "success": return result.data.join(", ");
    case "error": return `错误：${result.message}`;
    case "loading": return "加载中";
  }
}
```

- 每个 case 分支内编译器已把 result 确定为对应成员，可直接访问专有属性。
- 所有成员都被覆盖时无需书写 default 即可通过类型检查，成员较少时可改用 if 判断取值。

> 判断判别属性后类型被自动缩小的过程属于类型收窄，其完整规则、类型谓词与穷尽检查归本主题第 8 篇。

**速记**：switch 与 if 判断判别属性后，分支内类型自动收窄，可访问专有属性。

  
  
#### 状态机建模实例

用可辨识联合为订单状态建模：每个状态是一个成员，只携带该状态真正需要的字段。

```ts
type OrderState =
  | { status: "created"; orderId: string; createdAt: string }
  | { status: "paid"; orderId: string; paidAt: string; amount: number }
  | { status: "shipped"; orderId: string; trackingNo: string }
  | { status: "cancelled"; orderId: string; reason: string };

function payOrder(state: OrderState, amount: number): OrderState {
  if (state.status !== "created") throw new Error("只有待支付订单可以支付");
  return { status: "paid", orderId: state.orderId, paidAt: new Date().toISOString(), amount };
}
```

- 字段随状态归属，避免大量可选属性与运行时的空值判断。
- 状态转移函数可先用判别属性限定合法入口，非法转移在编译期与运行时各挡一层。

**速记**：状态机建模让每个状态只携带自己的字段，转移函数只接受合法的前置状态。

  
  
#### 请求结果建模实例

**请求结果建模**：用可辨识联合表达加载中、成功、失败三种互斥情形，是前端最常见的数据建模方式。

```ts
type UserListResponse =
  | { state: "loading" }
  | { state: "success"; users: string[] }
  | { state: "failure"; error: Error };

function renderUserList(response: UserListResponse): string {
  if (response.state === "loading") return "加载中…";
  if (response.state === "failure") return `请求失败：${response.error.message}`;
  return response.users.join(", ");
}
```

- 相比 data 加 isLoading 加 hasError 三字段并存的写法，互斥成员能表达「不可能同时加载中又有数据」。
- 消费端必须处理每个分支，遗漏分支会被穷尽检查发现；成功分支的 users 与失败分支的 error 都无需非空断言。
- 用互斥的状态成员替代多个可选标志字段，可以让非法状态在类型层面直接无法表示。

**速记**：请求结果用 loading、success、failure 三个互斥成员建模，非法组合无法表示。

  
  
### 常见陷阱与辨析

#### 联合属性访问报错

最常见的错误是把联合类型当作单个对象，直接访问只有部分成员拥有的属性。

```ts
type Cat = { name: string; meow: () => void };
type Dog = { name: string; bark: () => void };
function makeSound(pet: Cat | Dog): void {
  console.log(pet.name); // 合法：公共属性
  // pet.meow();          // 报错：Dog 上不存在 meow
}
```

- 报错信息里的类型通常是联合的全部成员拼接，读起来较长属正常现象。
- 正确顺序是先判断类别再访问专有属性，例如用 in 运算符判断属性是否存在于 pet 上，in 的具体规则归本主题第 8 篇。

**速记**：联合访问只认公共属性，专有属性要先收窄再访问。

  
  
#### 交叉同名属性变 never

把交叉理解为两边都要成立时，容易期待同名属性类型能自动兼容，实际会得到 never。

```ts
type WithStringId = { id: string };
type WithNumberId = { id: number };

type Broken = WithStringId & WithNumberId; // id 类型为 never
// const broken: Broken = { id: "a" };     // 报错：id 需要 never
```

- string 与 number 的交集为空，因此属性类型化简为 never。
- 对象类型之间的同名交叉保留为交叉结构，同样可能无法赋值。
- 需要字符串或数字的语义时应写成联合：{ id: string | number }。

> [!WARNING]
> **警告内容**：交叉不会在声明处提示同名冲突，只会在赋值处抛出 never 相关错误，排查时先核对各成员的同名属性类型。

**速记**：交叉同名且原始类型不兼容时属性变 never，需要二选一应改用联合。

  
  
#### as const 过度使用导致只读

对需要后续修改的数组或对象使用 as const，会让所有修改操作报错。

```ts
const queue = ["task-1", "task-2"] as const;
// queue.push("task-3"); // 报错：readonly 元组上不存在 push

const editableRoles: string[] = [...queue]; // 复制为可变数组
editableRoles.push("task-3"); // 合法
```

- as const 使数组变为只读元组、对象属性全部只读，这是编译期约束。
- 只对确定后不再变化的配置与常量清单使用，需要可变集合时保留普通推断。
- as const 与 Object.freeze 不同：前者只改变类型，后者只改变运行时行为。

**速记**：as const 只给不再变化的值使用，需要修改就复制成可变类型。

  
  
#### 联合与交叉的分配律预告

交叉对联合满足分配律：A & (B | C) 等价于 (A & B) | (A & C)。

```ts
type Base = { id: string };
type Mode = { kind: "read" } | { kind: "write" };
type Entry = Base & Mode;
// 按分配律展开，等价于：
type ExpandedEntry = (Base & { kind: "read" }) | (Base & { kind: "write" });
```

- 这解释了为什么用一个公共类型交叉一个联合会得到联合：公共字段被分配到每个成员。
- 分配的结果仍是可辨识联合，每个成员都带上了公共字段。
- 条件类型层面的同种分配行为称为分布式条件类型，归本主题第 12 篇。

> 辨析：联合对交叉不存在同样简洁的分配形式，处理联合成员的运算需要借助条件类型表达。

**速记**：A & (B | C) 等价于 (A & B) | (A & C)，交叉会分配到联合的每个成员。
