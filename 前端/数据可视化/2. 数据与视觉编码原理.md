## 数据与视觉编码原理

### 数据类型的划分

视觉编码的正确与否，首先取决于是否认清字段属于哪一类数据。本节给出定量、定序、定类与时序四类数据的判断依据，以及类型对可用运算与图形的约束。

#### 定量数据：连续与离散

**定量数据（quantitative data）**：是取值为数值、支持加减等算术运算并具有真实数量含义的数据，按取值能否细分又分为连续与离散两类。

- 连续定量：身高、温度、时长，任意两个取值之间仍可取得中间值。
- 离散定量：订单数、访问人次、故障次数，只能取整数。
- 关键性质：可比较大小、可做算术、差值本身有含义。
- 常见误判：编号、邮编、手机号是数字外观但只作标识，属于定类。
- 表达倾向：连续量适合位置与长度，离散量可与柱形或点阵配合。

```python
# 判断一列是否为定量：能否做有意义的算术
order_counts = [12, 8, 30, 5]        # 离散定量：计数
temperatures = [23.5, 24.1, 22.8]    # 连续定量：可细分
zip_codes = ["200120", "100084"]     # 数字外观，实为定类
```

> 数值外观不等于定量，判断依据是运算是否有意义：邮编相加没有含义，销量相加则有。

**速记**：定量数据支持算术运算，分连续与离散，数字外观的编号属于定类。



#### 定序数据与定类数据

**定序数据（ordinal data）**：是取值之间有明确顺序但相邻差距不可比的数据；**定类数据（nominal data）**：是取值之间只有区别、没有顺序的数据。

- 定序示例：满意度等级、尺码、学历层次，可排名但差值无意义。
- 定类示例：省份、渠道、产品线，只能区分与分组。
- 关键性质：定序支持大小比较，定类只支持相等判断。
- 常见误判：把定类取值按字典序排列，会读出并不存在的顺序。
- 表达倾向：定序用有序配色或有序位置，定类用分类配色或分组。

```json
{
  "satisfaction": ["非常满意", "满意", "一般", "不满意"],
  "channel": ["search", "social", "direct"]
}
```

> 只要取值集合能被自然排序，就更接近定序；排序规则来自业务含义而非字母顺序。

**速记**：定序有顺序但差值无意义，定类只分不排，排序依据必须来自业务含义。



#### 时序数据的特殊性

**时序数据（temporal data）**：是带时间戳、按时间先后排列的数据，兼具定量与定序特征，并额外要求时间轴按真实间隔等距排布。

- 时间粒度：秒、分、时、日、月、季、年，粒度决定可观察的模式。
- 等距要求：时间轴按真实间隔排布，不能把不同跨度的时间点等距摞在一列。
- 缺失时间点：无数据的时间点需显式补零或标记断点，不能直接跳过。
- 常见陷阱：把月度与日度数据混在同一轴上比较。
- 表达倾向：折线或面积用于趋势，柱形用于按周期的对比。

> 时间轴不等距会让斜率失真，趋势的陡缓看起来完全不同，绘制前必须先补齐时间点。

**速记**：时序数据要求时间轴按真实间隔等距排布，缺失时间点要补齐或标记断点。



#### 数据类型决定可用的运算与图形

**类型与运算的映射**：是依据数据类型确定允许的统计运算与可选图形范围的规则，它是选型的第一道约束。

- 定量：可求均值、中位数与相关系数，可用直方图、散点图与箱线图。
- 定序：可求中位数与分位数，可用堆积条与有序配色。
- 定类：只能计数与占比，可用柱状图、饼图与分组图。
- 时序：可做同比环比与趋势分解，可用折线、面积与日历热力图。
- 错误后果：对定类求均值会得出无意义结果，对定序做除法会放大误读。

```js
// 按类型限定可用的聚合方式
const aggregationsByType = {
  quantitative: ["mean", "median", "sum", "correlation"],
  ordinal: ["median", "quantile"],
  nominal: ["count", "share"],
  temporal: ["yoy", "mom", "trend"]
};
```

> 选型的第一步不是挑图形，而是确认字段属于哪一类，类型不对时再华丽的图形也无效。

**速记**：类型决定可用运算与图形范围，选型先定类型再挑图形。



### 视觉通道与感知精度

数据要变成图形，必须经过视觉通道这一层映射。不同通道被感知的精度差异很大，选错通道会让数据差异被放大或吞没。本节给出通道清单、精度排序与匹配规则。

#### 视觉通道清单

**视觉通道（visual channel）**：是图形标记上可承载数据差异的属性，包括位置、长度、面积、角度、颜色、形状与纹理。

- 位置：在坐标系中的横纵坐标，最精确也最易比较。
- 长度与高度：一维延伸量，适合表达定量差异。
- 面积与体积：二维与三维量，随数值快速膨胀，难以精确比较。
- 角度与斜率：受参考方向影响，比较精度低于长度。
- 颜色：色相用于区分类别，明度与饱和度可承载顺序或数量。
- 形状与纹理：区分能力有限，适合少量类别的辅助标识。

```js
// 通道与可承载的数据类型
const channelTypes = {
  position: ["quantitative", "ordinal", "nominal", "temporal"],
  length: ["quantitative"],
  area: ["quantitative"],
  hue: ["nominal"],
  lightness: ["quantitative", "ordinal"],
  shape: ["nominal"]
};
```

> 颜色在类别区分上有效，但要表达精确数量仍应回到位置或长度。

**速记**：视觉通道包括位置、长度、面积、角度、颜色、形状与纹理，各自承载能力不同。



#### 感知精度的排序

**感知精度**：是人对不同视觉通道判断差异时的准确程度，位置与长度最准确，面积与体积最不准确。

- 最精确：位置与长度，在同一轴上的比较误差最小。
- 次精确：角度与斜率，需要参照方向，误差随角度增大而上升。
- 较粗略：面积与体积，感知接近幂律压缩，容易低估大值、高估小值。
- 最粗略：颜色的明度与饱和度，通道容量有限，难分辨细微差异。
- 实践结论：承载精确比较的数据优先用位置与长度，颜色与面积只作辅助。

```js
// 幂律关系示意：感知面积是真实面积的高次压缩
function perceivedArea(actualArea, exponent = 0.7) {
  return Math.pow(actualArea, exponent);
}
// 真实面积放大 4 倍时，感知上远不到 4 倍，用面积表达数值会系统性低估差异
```

> 同一张图里若同时用面积和长度表达同一变量，阅读者会得到两套互相矛盾的印象。

**速记**：位置与长度最精确，角度次之，面积与体积最粗略，精确比较优先用位置与长度。



#### 通道与数据类型的匹配

**通道匹配**：是为每种数据类型选择表达能力相符的视觉通道，使差异既不丢失也不被夸大。

- 定量 × 位置或长度：表达精确差异的首选组合。
- 定类 × 位置或色相：分类之间区分清晰且无顺序暗示。
- 定序 × 明度或有序位置：顺序被自然读出。
- 时序 × 横向位置：时间只用一个方向承载，纵轴留给数值。
- 避免组合：定类 × 面积、定序 × 色相，都会产生错误暗示。

```js
// 一份映射配置的形状（不含具体色值）
const fieldMapping = {
  x: { field: "month", type: "temporal", channel: "position" },
  y: { field: "sales", type: "quantitative", channel: "length" },
  color: { field: "channel", type: "nominal", channel: "hue" }
};
```

> 匹配的核心是通道容量与数据结构一致：类别数多时不要用形状，数值差异小时不要用明度。

**速记**：定量配位置或长度，定类配位置或色相，定序配明度，时序占横向位置。



#### 冗余编码与通道组合

**冗余编码（redundant encoding）**：是用多个视觉通道同时表达同一个数据维度，以提升可读性或可访问性的手法。

- 冗余同一维度：位置加数值标注，读数更可靠。
- 互补分工：位置承载数值、色相承载类别，一次读出两组信息。
- 可访问性收益：颜色加形状或纹理后，色觉障碍者仍能区分。
- 风险：通道表达彼此矛盾，如长度与面积各代表不同数值，会造成误读。
- 上限：一屏承载的通道有限，超过三到四个维度后应改用分面或交互。

> [!TIP]
> **建议内容**：凡是用颜色区分类别的地方，都补一层形状或直接标注作为冗余，既提升可访问性也减少误读。

**速记**：冗余编码用多个通道表达同一维度，颜色配形状可兼顾可读性与可访问性。



### 图形语法与图表选型

选型是编码原理最直接的落点。本节先用图形语法说明图表的构件结构，再给出类型适用条件、判定顺序与多表达之间的取舍。

#### 图形语法的基本模型

**图形语法（grammar of graphics）**：是把图表描述为数据、映射、标记、比例尺、坐标系与分面一组可组合构件的模型，图形由构件组合而非逐个硬编码产生。

- 数据：整理为规范表格，一列一个变量、一行一条记录。
- 映射：把变量绑定到视觉通道，形成图形属性的取值规则。
- 标记：点、线、面等基本几何元素，决定图形的基本形态。
- 比例尺：把数据取值域映射到通道取值域，决定位置与大小。
- 坐标系与分面：决定空间排布方式以及按类别切分成子图的方式。

```js
// 图形语法的六层结构（示意，不含具体库接口）
const chartSpec = {
  data: "rows",
  mapping: { x: "month", y: "sales", color: "region" },
  mark: "line",
  scales: { y: { nice: true } },
  coord: "cartesian",
  facet: { by: "region", columns: 2 }
};
```

> 图形语法把「画什么」与「怎么画」分开，改一个映射就能从柱状图变为折线图。

**速记**：图形语法把图表拆成数据、映射、标记、比例尺、坐标系与分面六层构件。



#### 常见图表类型的适用条件

**图表类型**：是承载特定数据组合的图形形态，每种类型都有明确的适用条件与失效边界。

- 折线图：定量 × 时序，用于趋势与转折，类别多时容易缠线。
- 柱状图：定量 × 定类或定序，用于按项比较，类别过多时改横向或筛选。
- 散点图：定量 × 定量，用于相关与聚集，点数过密时需透明度或抽样。
- 饼图与环图：占比之和构成整体，扇区不宜超过五个且不用于精确比较。
- 箱线图与分布图：用于分布形态与离群点，前提是阅读者理解分位数。
- 热力图：两个定类维度的交叉值，用于观察矩阵中的高低格局。

```js
// 按变量组合查表选型
const chartByFields = {
  "temporal+quantitative": "line",
  "nominal+quantitative": "bar",
  "quantitative+quantitative": "scatter",
  "nominal+nominal+quantitative": "heatmap"
};
```

> 没有绝对正确的图形，只有与数据结构和阅读任务匹配的图形。

**速记**：折线对趋势、柱形对比较、散点对相关、热力图对交叉，类型须与变量组合匹配。



#### 选型的判定顺序

**判定顺序**：是依次回答变量数量与类型、是否含时间、是否要求精确读值、类别规模四个问题的固定流程。

- 第一步看字段：几个变量、各属哪类，确定可选图形集合。
- 第二步看时间：含时间维度时优先折线或面积。
- 第三步看任务：要精确读值用柱形加标注，要看关系用散点。
- 第四步看规模：类别超过一屏容量时改用横向排布、滚动或筛选。
- 最后检查：是否存在更能直接回答目标问题的替代图形。

```bash
# 选型四问
# 1 字段几维、各属哪类
# 2 是否含时间
# 3 任务是读值还是比较关系
# 4 类别数是否超出屏幕容量
```

> [!NOTE]
> **提醒内容**：先按数据与任务确定图形，再考虑装饰与交互，顺序颠倒会为了特效迁就不合适的图形。

**速记**：选型按字段、时间、任务、规模四步依次判定，最后再考虑装饰与交互。



#### 同一数据的多种表达与取舍

**表达取舍**：是同一份数据在多种合法图形之间做选择的过程，取舍依据是阅读任务、精度要求与版面约束。

- 趋势：折线与面积都可用，面积在强调累计量时更合适。
- 构成：堆积柱与饼图都可用，比较各期构成变化时用堆积柱。
- 分布：直方图看形状，箱线图看分位，蜂群图看个体。
- 比较：柱形看绝对量，条形看排名，点图看差异大小。
- 取舍准则：能直接回答目标问题的图形优先，其余作为补充视图。

> 多个视图并存时应明确主视图与辅助视图，避免阅读者在多张等价图之间反复切换。

**速记**：同数据多表达，取舍依据是任务与精度，主视图唯一、辅助视图从属。



### 失真的来源与规避

图表可以在不伪造数据的前提下误导读者。本节把常见失真来源逐一列出，并明确哪些是错误做法，不得作为技巧推荐。

#### 截断坐标轴的误导

**截断坐标轴**：是让数值型坐标轴不从零开始、或在中间省略一段区间的做法，它会放大柱形之间的高度差异，属于错误做法。

- 柱形图：柱高代表数值，基线不为零时柱高比例失真。
- 折线图：折线表示趋势，基线非零一般可接受，但必须显式标注范围。
- 面积图：面积代表累计量，基线非零会同时扭曲形状与总量。
- 判断方法：先看纵轴最小值，柱形的纵轴起点远离零则高度比较无效。
- 正确做法：柱形从零开始；确需放大局部时改用折线并标注轴范围。

```js
// 错误做法：柱状图纵轴截断，柱高差异被放大
// const badAxis = { type: "value", min: 95, max: 105 };
// 正确做法：数值轴从零开始
const safeAxis = { min: 0 };
```

> [!WARNING]
> **警告内容**：对柱形图截断纵轴会直接夸大差异，这是错误做法而非可调的风格选项，任何场景都不应使用。

**速记**：柱形图的数值轴必须从零开始，折线可非零但须标注，截断是错误做法。



#### 面积与体积的夸大

**面积夸大**：是用半径或边长按数值等比缩放来表达数值，导致面积按平方、体积按立方增长，属于错误做法。

- 圆形符号：半径按数值缩放时面积随半径平方增长，差异被平方级放大。
- 立体符号：三维图标随数值放大时体积按三次方增长，放大更严重。
- 感知叠加：人对面积的感知本就小于真实比例，平方放大与之叠加。
- 正确做法：让面积与数值成正比，即半径按数值的平方根缩放。
- 替代方案：改用长度或位置承载数值，符号大小只作辅助。

```js
// 正确做法：面积与数值成正比，半径取平方根
function radiusForValue(value, maxValue, maxRadius) {
  return Math.sqrt(value / maxValue) * maxRadius;
}
// 错误做法是把半径按 value / maxValue 线性缩放，会让面积被平方放大
```

> [!WARNING]
> **警告内容**：把半径或边长按数值等比缩放属于错误做法，会平方或立方级夸大面积，必须改为面积等比。

**速记**：面积按数值等比缩放，半径取平方根；半径线性缩放会平方级夸大，是错误做法。



#### 双轴与虚假相关

**双轴图**：是在同一坐标系中使用两套不同量纲的纵轴、把两条曲线并置的图形；两条轴的范围可被人为调整，从而制造出并不存在的相关，属于错误做法。

- 机制：改变任一轴的上下限，两条曲线的贴合与分离程度随之改变。
- 后果：阅读者会读出「同步上升」的结论，而真实相关性未经检验。
- 判定：看到双轴图先看两轴范围是否被刻意挑选。
- 正确做法：需要比较相关关系时改用散点图并给出相关系数。
- 替代：确需并置时把两图上下堆叠、共享横轴，各自保留独立纵轴。

```js
// 错误做法：调整双轴范围即可制造虚假同步
// const badDualAxis = [{ min: 0, max: 100 }, { min: 90, max: 100 }];
// 正确做法：相关关系用散点图表达
const relationView = { mark: "point", x: "metricA", y: "metricB" };
```

> 双轴图不是绝对不能出现，但用它下相关性结论属于错误做法，相关判断必须回到散点图。

**速记**：双轴范围可调即可能制造虚假相关，相关判断用散点图，双轴不宜作为结论依据。



#### 其他失真来源与自查

**其他失真**：是在坐标轴与图形比例之外，由取样、聚合与排序引入的偏差，同样会导致错误结论。

- 取样偏差：只选取有利时段或人群，忽略完整样本。
- 聚合粒度：平均值掩盖分布形态，需同时给出样本量与区间。
- 排序误导：按数值排序后截取前几项，让差异看起来更大。
- 对数轴未标注：对数刻度压缩大值差异，未标注时读者会按线性理解。
- 自查方式：核对轴范围、样本完整性、聚合方式与排序规则四件事。

> 对数坐标轴与聚合平均值都会压缩差异，必须显式标注刻度类型与样本量，否则读者会按线性与个体来理解。

**速记**：取样、聚合、排序与未标注的对数轴都会引入偏差，交付前核对四项。



### 数据准备与预处理

图形受制于输入数据。本节给出缺失值、异常值、排序分组与派生字段的基本处理方式，以及它们与图形表达的对应关系。

#### 缺失值处理

**缺失值**：是字段未采集到或采集失败的取值，处理方式取决于缺失机制以及该字段在图形中的含义。

- 区分类型：随机缺失与系统性缺失的处理方式不同。
- 数值字段：可用均值或中位数填充，但必须记录填充比例。
- 分类字段：可归入「未知」类别，保留缺失规模可见。
- 时间序列：中间缺失可插值，首尾缺失应明确断点。
- 图形对应：折线遇缺失应断开而非连线跨越，柱形应留空位。

```python
# 用 pandas 检出缺失并区分处理
import pandas as pd

frame = pd.read_csv("orders.csv")
missing_ratio = frame.isna().mean()             # 各字段缺失比例
frame["region"] = frame["region"].fillna("未知")
sales_filled = frame["sales"].interpolate()     # 时序中间缺失插值
print(missing_ratio[missing_ratio > 0])
```

> 填充会改变数据分布，必须在图注或数据说明中记录被填充的字段与比例。

**速记**：缺失值按机制分别处理，数值可填充、分类归入未知、时序断开而非跨越连线。



#### 异常值识别与聚合

**异常值**：是明显偏离主体分布的取值，它可能是真实极值，也可能是录入错误，处理前必须先判断来源。

- 来源判断：先回溯采集链路，确认是真实业务事件还是录入问题。
- 统计识别：用四分位距或三倍标准差标记候选异常，不直接删除。
- 真实极值：应保留并单独标注，删除会掩盖真实业务信号。
- 聚合：按合适粒度聚合可降低噪声，但会丢失个体信息。
- 双视图：图形同时给出聚合曲线与个体散点，兼顾趋势与细节。

```python
# 用四分位距标记候选异常值，不直接删除
q1, q3 = frame["sales"].quantile([0.25, 0.75])
upper = q3 + 1.5 * (q3 - q1)
candidates = frame[frame["sales"] > upper]
print(candidates[["order_id", "sales"]])
```

> 删除异常值是高风险操作，应先确认来源并在图注中说明被排除的记录范围。

**速记**：异常值先判来源再处理，真实极值保留标注，删除前必须回溯采集链路。



#### 排序、分组与派生字段

**派生字段**：是在原始字段基础上计算出的新字段，用于支撑排序、分组与聚合等图形需要。

- 排序：按数值或时间排序决定柱形与条形图的阅读顺序。
- 分组：按定类字段分组，为分组柱形或分面提供结构。
- 派生比例：占比、增长率、同比环比等由原始值计算得到。
- 分箱：把连续量切为区间，供直方图与分级着色使用。
- 注意单位：派生计算必须统一单位与时间口径后再进行。

```python
# 派生分组与比率字段
frame["month"] = pd.to_datetime(frame["date"]).dt.to_period("M")
frame["growth"] = frame.groupby("product")["sales"].pct_change()
frame["level"] = pd.cut(frame["sales"], bins=[0, 100, 500, 1000], labels=["低", "中", "高"])
```

> 派生字段会跟着图表一起被解读，口径错误的派生值比没有派生值更危险。

**速记**：派生字段支撑排序、分组、比例与分箱，计算前必须统一单位与时间口径。



#### 预处理与图形表达的对应

**预处理与表达的对应**：是让清洗、聚合与派生结果与目标图形的结构要求一一对齐的做法，避免在渲染阶段再做变形。

- 长表与宽表：多系列折线需要长表，分组柱形常从宽表整理成多列。
- 数值范围：比例尺对极端值敏感，预处理阶段先确认是否需要分箱或截尾。
- 类别顺序：定序字段的排序在数据阶段确定，而非依赖默认字典序。
- 时间补齐：缺失时间点在预处理阶段补零或标记，保证轴等距。
- 交付检查：图形阶段不再做业务口径转换，只做通道映射。

```js
// 渲染阶段只做映射，口径转换已在预处理完成
const seriesPoints = tidyRows.map((row) => ({
  x: row.month,
  y: row.sales,
  group: row.region
}));
```

> [!IMPORTANT]
> **重要内容**：把口径计算留在渲染阶段会让数据逻辑散落在视图代码里，难以复用与校对，预处理必须承担全部业务口径。

**速记**：预处理负责口径与结构，渲染只做通道映射，长表宽表与排序在数据阶段定妥。
