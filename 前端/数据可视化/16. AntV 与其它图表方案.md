## AntV 与其它图表方案

### AntV 体系概览

AntV 是蚂蚁集团的开源可视化体系，与 ECharts 这类成品图表库取向不同。本节说明体系构成、各产品定位，以及它与成品图表库的根本差异。

#### AntV 是什么与产品家族

**AntV**：是一套以图形语法为底层的可视化技术体系，按数据形态与使用场景拆成多个产品，彼此共享图形渲染与语法能力。

- G2：面向统计图表的图形语法库，用标记与通道的组合描述图形。
- G6：面向关系数据的图可视化库，处理节点与边的拓扑结构。
- L7：面向地理空间数据的可视化库，处理经纬度与地图层级。
- F2：面向移动端与小程序场景的轻量图表库。
- S2：面向多维交叉表的表格分析产品。
- X6：面向流程图与图编辑场景的图形编辑引擎。

```bash
npm install @antv/g2
npm install @antv/g6
# 各产品独立发布，按场景单独安装，不存在一个总包
```

**速记**：AntV 是以图形语法为底层的产品家族，G2 管统计图表、G6 管关系图、L7 管地理、F2 管移动端。



#### 各产品的定位与边界

**定位差异**：是各产品按数据形态与交互目标划定的分工，边界比成品图表库更细，选型时需要按数据形态而非图表名称判断。

- G2 处理表格型数据的统计图形，不负责图结构的拓扑布局。
- G6 处理节点与边的关系数据，不面向常规坐标轴图表。
- L7 处理带经纬度的空间数据，通用图表配置不属其范围。
- F2 与 S2 分别面向移动端与表格分析，与桌面端图表库不重叠。
- G2 之上还有一层开箱即用的图表组件封装，包名与维护状态以官方文档为准。

> 产品边界与数据形态对应：一组数值找 G2，一张图结构找 G6，一批经纬度找 L7，不要用一个产品覆盖所有形态。

**速记**：按数据形态选产品，G2 管表格、G6 管图结构、L7 管空间、F2 与 S2 管移动端与表格。



#### 与 ECharts 的取向差异

**取向差异**：是「声明图形语法」与「填写图表配置」两种使用模型的差别，前者描述图形的构成规则，后者选择并配置成品图表类型。

- 描述对象：ECharts 的 option 以图表类型为入口，G2 以数据与标记的组合为入口。
- 图形自由度：G2 可通过标记与通道组合出非标准图形，ECharts 需转到自定义系列。
- 交付速度：内置图表覆盖的范围内，ECharts 的配置量更少。
- 分层能力：G2 的图层与分面在同图内组合多种图形时更自然。
- 学习曲线：语法模型需要先理解标记与通道，配置模型只需记住字段名。

```js
// ECharts：以图表类型为入口
chart.setOption({ xAxis: { type: 'category' }, yAxis: { type: 'value' }, series: [{ type: 'bar', data: [120, 200] }] });
```

```js
// G2：以数据与标记的组合为入口
chart.interval().data([{ genre: '运动', sold: 275 }]).encode('x', 'genre').encode('y', 'sold');
```

**速记**：ECharts 选图表类型再填配置，G2 用数据加标记组合图形；前者交付快，后者图形自由度高。



### G2 图形语法

图形语法把图表的构成拆成数据、标记、比例尺与坐标系等要素。本节给出这套语法的骨架，不展开完整配置。

#### 图形语法的核心概念

**图形语法（grammar of graphics）**：是用一组可组合的要素描述图形的规则体系，其核心是把数据字段映射到视觉通道。

- 数据（data）：一组表格型记录，每列是一个字段。
- 标记（mark）：图形的基本单位，如 interval 柱、line 线、point 点、area 面、text 文本。
- 通道（encode）：把字段映射到位置、颜色、大小等视觉通道。
- 比例尺（scale）：定义字段值到视觉取值的换算方式。
- 坐标系（coordinate）：定义位置通道如何展开，如直角坐标、极坐标。
- 分面（facet）：把同一套图形语法在多个子区域重复，按字段拆分视图。

**速记**：图形语法的六要素是数据、标记、通道、比例尺、坐标系与分面。



#### Chart 的创建与渲染流程

**Chart**：是 G2 的图表实例，创建时指定容器与自适应等选项，随后依次声明标记与通道，最后调用渲染方法产出图形。

- 容器以元素 id 或元素对象指定，autoFit 控制是否随容器尺寸自适应。
- 标记由实例上的同名方法创建，如 interval()、line()、point()。
- 数据可在实例级声明，也可在标记级声明并覆盖。
- render() 触发实际渲染，changeData() 用于在已有结构上替换数据。
- destroy() 释放实例，组件卸载时应调用。

```js
import { Chart } from '@antv/g2';

const chart = new Chart({ container: 'chart-container', autoFit: true });

chart
  .interval()
  .data([
    { genre: '运动', sold: 275 },
    { genre: '策略', sold: 115 },
    { genre: '动作', sold: 120 }
  ])
  .encode('x', 'genre')
  .encode('y', 'sold')
  .encode('color', 'genre');

chart.render();
```

**速记**：创建实例、声明标记与通道、调用 render，数据替换用 changeData，卸载时 destroy。



#### mark、scale、coordinate 与 facet

**mark、scale、coordinate、facet**：是图形语法的四类可组合配置，分别控制图形种类、换算方式、位置展开方式与视图拆分方式。

- mark：同一张图可叠加多个标记，形成复合图形，叠加顺序即绘制顺序。
- scale：可为单个字段指定换算方式，常见类型有线性、序数、时间与对数。
- coordinate：切换位置通道的展开方式，极坐标把直角轴转换为角度与半径。
- facet：按字段把数据拆到多个子区域，各子区域复用同一套标记与通道。
- 四类配置都可下放到标记级，使不同标记使用不同的换算与坐标系。

```js
chart
  .interval()
  .data(salesRows)
  .encode('x', 'genre')
  .encode('y', 'sold')
  .scale('y', { nice: true });

chart.coordinate({ type: 'theta' });
chart.render();
```

> 不同主版本对标记方法的命名与分层位置做过调整，旧示例中的写法可能与当前版本不一致，迁移时先核对版本。

**速记**：标记定图形、比例尺定换算、坐标系定展开、分面定拆分，四类配置都可下放到标记级。



### G6 图可视化

关系数据的表达对象是节点与边，不是坐标轴上的数值。本节说明 G6 的数据模型、图实例的创建与布局配置，以及节点状态的用法。

#### G6 是什么与关系数据的表达

**G6**：是面向关系数据的图可视化库，输入是节点集合与边集合，输出是带布局算法的图结构视图。

- 节点：带唯一标识与自定义字段的实体，常见附加字段有标签、分类与权重。
- 边：由起点标识与终点标识构成的连接，可带方向与权重。
- 布局：决定节点在图中的位置，是图可视化的核心问题。
- 常用布局有 force 力导向、dagre 分层、circular 环形、grid 网格与 radial 辐射。
- 规模较大时应选择线性复杂度的布局，或对数据做聚合与采样。

**速记**：G6 的输入是节点与边，布局算法决定节点位置，规模大时优先线性复杂度布局。



#### Graph 的创建与 layout 配置

**Graph**：是 G6 的图实例，创建时通过配置对象声明容器、尺寸、布局、交互模式与默认样式。

- container 指定容器元素，width 与 height 指定画布尺寸。
- layout 以 type 指定布局算法，其余字段为该算法的参数。
- modes 声明启用的交互行为，如拖拽画布、缩放画布与拖拽节点。
- defaultNode 与 defaultEdge 定义节点与边的默认样式。
- data() 注入数据，render() 触发首次布局与绘制，destroy() 释放实例。

```js
import { Graph } from '@antv/g6';

const graph = new Graph({
  container: 'graph-container',
  width: 640,
  height: 480,
  layout: { type: 'force', preventOverlap: true },
  modes: { default: ['drag-canvas', 'zoom-canvas', 'drag-node'] },
  defaultNode: { size: 30, style: { fill: '#5b8ff9' } },
  defaultEdge: { style: { stroke: '#c2c8d5' } }
});

graph.data(graphData);
graph.render();
```

> 图的新主版本重构了节点与边的样式声明位置以及交互行为的配置字段，升级前需按对应版本的文档调整配置。

**速记**：Graph 创建时声明容器、布局与交互模式，注入数据后 render，卸载时 destroy。



#### 节点状态与交互

**节点状态（state）**：是节点或边在特定交互下切换的一组样式，nodeStateStyles 声明状态名与对应样式，运行时用 setItemState 切换。

- 状态适合表达悬停、选中、置灰与告警等临时外观。
- 事件以类别加动作命名，如 node:click、edge:mouseenter。
- 事件回调通过 item 取到图元素，再读取其数据模型。
- 状态样式与默认样式分离，避免在事件中直接改写元素属性。
- 图数据变化时可调用 changeData 增量更新，保留布局与当前视图。

```js
const graph = new Graph({
  container: 'graph-container',
  nodeStateStyles: {
    hover: { lineWidth: 3, stroke: '#f6bd16' },
    selected: { fill: '#5ad8a6' }
  }
});

graph.on('node:mouseenter', (event) => {
  graph.setItemState(event.item, 'hover', true);
});

graph.on('node:mouseleave', (event) => {
  graph.setItemState(event.item, 'hover', false);
});
```

**速记**：样式在 nodeStateStyles 里声明，事件回调中用 setItemState 切换，数据变化用 changeData。



### 轻量方案与其它库

除主流体系外，还有一批按场景或体积取胜的方案。本节按类别给出各自的能力边界，便于按需求筛选。

#### 轻量级图表库

**轻量级图表库**：是以体积与启动速度为主要目标的成品图表库，图表类型较聚焦，配置模型与 ECharts 接近。

- Chart.js：Canvas 绘制，内置响应式与动画，配置简洁，适合常规业务图表。
- ApexCharts：交互与图表类型较丰富，配置项以对象为主。
- Frappe Charts：以 SVG 绘制，体积极小，适合简单的单图场景。
- 共同边界：图形自定义能力有限，超大数据量与复杂联动不是强项。

```js
new Chart(canvasContext, {
  type: 'line',
  data: {
    labels: ['一月', '二月', '三月'],
    datasets: [{ label: '销量', data: [120, 200, 150] }]
  },
  options: { responsive: true, maintainAspectRatio: false }
});
```

**速记**：Chart.js、ApexCharts 与 Frappe Charts 以体积与上手速度取胜，复杂自定义与超大数据量是其短板。



#### 通用可视化与语法型库

**语法型库**：是提供图形描述语言或规格格式、由引擎负责渲染的库，强调图形的可组合与可复用。

- Vega 与 Vega-Lite：以 JSON 规格描述图形，规格可序列化、可复用、可跨语言生成。
- Observable Plot：在 D3 之上提供高阶语法，适合探索式分析。
- Plotly.js：面向科学计算与三维图表，与数据处理生态呼应。
- D3：提供选择集、比例尺与形状生成器等底层构件，图形需自行搭建。

```json
{
  "mark": "bar",
  "data": { "values": [{ "a": "A", "b": 28 }, { "a": "B", "b": 55 }] },
  "encoding": {
    "x": { "field": "a", "type": "nominal" },
    "y": { "field": "b", "type": "quantitative" }
  }
}
```

**速记**：语法型库用规格描述图形，Vega 与 Vega-Lite 便于序列化复用，D3 提供底层构件。



#### 场景专项库

**场景专项库**：是只服务单一场景、在该场景内做到极致的一类库，切换场景时需要替换技术栈。

- 金融行情：面向 K 线与分时图的库，以超大数据量与实时刷新为设计目标。
- 地理空间：GIS 类库与地图引擎，处理投影、瓦片与空间查询。
- 三维与体渲染：面向三维数据与体绘制的库，见本主题第 10 篇。
- 表格与交叉分析：面向多维表格的分析产品，与图表并列而非替代。
- 图编辑：面向流程图的图形编辑引擎，强调节点拖拽与连线交互。

```js
Highcharts.chart('container', {
  chart: { type: 'spline' },
  title: { text: '月度趋势' },
  series: [{ name: '销量', data: [120, 200, 150] }]
});
```

> [!IMPORTANT]
> **重要内容**：Highcharts 在商业场景使用需要购买授权，引入前必须确认许可范围与适用条款，避免合规风险。

**速记**：专项库在金融、地理、三维、表格与图编辑场景内做到极致，跨场景需替换技术栈。



### 选型对照与决策

选型的答案取决于需求维度而非库的知名度。本节用列表给出判定维度、按场景的对照结论，以及迁移与共存的做法。

#### 选型的判定维度

**判定维度**：是把需求拆成可比较的若干项，逐项打分后再定库，避免凭印象选择。

- 图表覆盖：目标图表是否内置，需要多少自定义工作量。
- 定制深度：能否接管图形绘制与层级，是否允许叠加自绘内容。
- 数据规模：最大数据量、刷新频率与增量更新能力。
- 交互能力：提示、缩放、刷选、跨图联动与外部控件协同。
- 生态与文档：中文文档完整度、社区活跃度与示例质量。
- 授权与合规：是否为商业授权，地图数据是否需要审核。
- 体积与依赖：是否支持按需引入，产物增量有多少。
- 框架契合：与 React、Vue 等框架的集成成本与封装难度。
- 维护与升级：主版本演进节奏与迁移成本。

**速记**：从图表覆盖、定制深度、数据规模、交互、生态、授权、体积、框架契合与维护九项逐条打分。



#### 按场景的对照结论

- 常规业务看板与后台图表：ECharts，图表类型齐全且中文生态完善。
- 需要图形语法与多标记组合的可视分析：G2、Vega-Lite 或 Observable Plot。
- 关系网络与拓扑：G6；需要可编辑流程图的场合：X6。
- 超大数据量时序与金融行情：面向行情的轻量库或 uPlot 类方案。
- 三维与科学图表：Plotly.js；场景三维另见本主题第 10 篇。
- React 深度集成与组件化优先：Recharts、nivo 或 visx。
- 需要完全自定义图形：D3 配合 SVG 或 Canvas，详见本主题第 12、13 篇。
- 商业授权与技术支持优先：Highcharts，先确认许可范围。
- 移动端与小程序：F2 或面向移动端优化的轻量库。
- 地理数据：L7 或地图引擎，注意地图数据的合规要求。

```js
function pickChartLibrary(requirement) {
  if (requirement.graphTopology) return 'G6';
  if (requirement.customGrammar) return 'G2';
  if (requirement.standardDashboard) return 'ECharts';
  if (requirement.fullControl) return 'D3';
  return 'ECharts';
}
```

**速记**：常规看板选 ECharts，图形语法选 G2 或 Vega-Lite，拓扑选 G6，完全自定义选 D3。



#### 迁移与共存策略

**迁移策略**：是把图表从一套库换到另一套库时的推进方式，核心是隔离渲染层，避免业务逻辑与库绑定。

- 先抽象数据层：把接口数据转成业务无关的中间结构，渲染层只消费该结构。
- 再抽象组件层：以统一的组件接口封装图表，替换库时只改组件实现。
- 增量替换：按页面或模块逐个迁移，不同库可在同一应用内共存。
- 共存代价：每个库都会带来体积与升级负担，应限定在确有不可替代能力的场景。
- 回归验证：迁移后需比对图形、交互与空数据态，确认行为一致。

> [!CAUTION]
> **注意内容**：不同主版本升级常伴随配置字段重命名或分层调整，跨版本照搬示例会静默失效，查阅资料前先核对版本号。

**速记**：先抽象数据层与组件层再换库，按模块增量迁移，多库共存需控制体积与升级负担。



### 框架集成注意

图表库与框架的结合点集中在实例生命周期与容器尺寸。本节只说明通用惯例与注意事项，框架自身的写法归各自主题。

#### 生命周期与实例管理

**生命周期对齐**：是把图表实例的创建与销毁绑定到组件的挂载与卸载时机，避免实例泄漏与重复初始化。

- 创建时机：容器挂载之后创建实例，不能在尚未挂载时初始化。
- 销毁时机：组件卸载时调用 destroy 或 dispose 释放实例与监听。
- 更新时机：数据变化时对已有实例更新数据，而不是重建实例。
- 重复初始化：同一容器重复创建实例会叠加画布，需先判定是否已存在实例。
- 依赖管理：初始化只依赖容器，不应依赖每次渲染都会变化的值。

```js
function mountChart(container, chartFactory) {
  const instance = chartFactory(container);

  return function unmountChart() {
    instance.destroy();
  };
}
```

**速记**：挂载后创建、卸载时销毁、更新时复用实例，同一容器不得重复初始化。



#### 封装组件的边界

**封装边界**：是图表组件对外暴露什么、向内隐藏什么的约定，目标是让业务方只关心数据与少数配置。

- 对外暴露：数据、必要的配置覆盖项与事件回调。
- 向内隐藏：实例创建、销毁、尺寸监听与默认样式。
- 配置合并：默认配置与外部覆盖项按字段深合并，避免整体替换丢样式。
- 数据转换：接口数据到图表数据的转换放在组件内或独立的数据层。
- 事件透传：把库事件转成业务语义的事件名再对外抛出，避免上层依赖库细节。
- 边界例外：需要深度定制时允许透出原始实例，但应在文档中标注为不受保护的用法。

**速记**：封装暴露数据、少量配置与事件，隐藏实例与生命周期，深度定制才透出原始实例。



#### 尺寸与样式隔离

**尺寸隔离**：是让图表尺寸只由容器决定、组件样式不穿透到图表内部的约束。

- 容器尺寸：为容器设定明确尺寸，图表的自适应才能正确计算。
- 尺寸监听：容器尺寸变化时触发重算，见本主题第 14 篇的 resize 用法。
- 样式隔离：图表内部元素由库生成，不要用全局选择器去改写其样式。
- 主题入口：需要统一外观时通过主题或库提供的样式配置，而不是覆盖内部类名。
- 隐藏与切换：容器被隐藏时尺寸为 0，重新显示后需要主动触发一次尺寸重算。

> [!NOTE]
> **提醒内容**：同一项目混用多个图表库会叠加体积与升级负担，只在图表库确有不可替代能力时才引入第二个。

**速记**：容器定尺寸、组件管监听、主题管外观，不用全局样式改写图表内部元素。
