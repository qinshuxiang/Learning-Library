## 可视化可访问性与工程化

### 可访问性要点

图表以图形承载信息，对屏幕阅读器与低视力使用者默认不可读，键盘使用者也无法像指针那样悬停取数。本节给出判断依据、颜色、键盘与语义四方面的落地写法。

#### 无障碍的目标与判断依据

**可访问性（accessibility）**：是让不同感知与操作能力的使用者都能获取图表所承载信息的设计要求，判断依据是一组公开的验收准则。

- 四项原则：内容需可感知、可操作、可理解、健壮，图表的整改点分别对应替代文本、键盘、文案与语义标记。
- 判断依据：Web 内容可访问性指南 WCAG 是通行的验收标准，成功准则按 A、AA、AAA 三级划分，多数组织以 AA 为验收线。
- 版本关系：WCAG 2.2 于 2023 年 10 月成为 W3C 推荐标准，与 2.0、2.1 向后兼容，满足 2.2 即满足更早版本。
- 图表落点：颜色不单独承载信息、提供等价文本、键盘可达、动效可关闭，是图表最常出现的四类缺陷。

> 可访问性不是额外的版本分支：满足准则的图表通常题注更清楚、单位更完整、灰度打印后仍可读，对所有使用者都是改进。

**速记**：以 WCAG 的四项原则与 A、AA、AAA 分级作为判断依据，图表重点在替代文本、键盘、文案与动效。



#### 颜色与对比度的可访问

**颜色可访问**：是不把颜色作为唯一的信息载体、并保证文字与图形在对比度上可辨认的做法。

- 不单独依赖颜色：分类用颜色配合形状、图案或直接标注共同区分。
- 文本对比度：正文文本与背景的对比度不低于 4.5 比 1，大字号不低于 3 比 1。
- 图形对比度：相邻图形与背景之间、图形边界与填充之间不低于 3 比 1。
- 系统偏好：响应系统的高对比度与强制颜色设置，不用自定义配色覆盖使用者的选择。

```css
@media (prefers-contrast: more) {
  .chart-label {
    color: #000000;
    font-weight: 600;
  }
}

@media (forced-colors: active) {
  .chart-series {
    forced-color-adjust: none;
  }
}
```

> 图表库通常提供图案叠加配置，使系列在去除颜色后仍能区分。ECharts 的 aria 配置项可自动生成图表描述，其 decal 字段为系列叠加图案（详见本主题第 14 篇 ECharts 快速上手与配置体系）。

**速记**：颜色不单独承载信息，文本对比度 4.5 比 1、大字与图形 3 比 1，并响应系统对比度与强制颜色设置。



#### 键盘可达与焦点顺序

**键盘可达**：是让不使用指针设备的使用者通过键盘完成浏览图表数据所需的全部操作。

- 可聚焦元素：需要交互的图元或数据点应可聚焦，焦点顺序与数据顺序一致。
- 焦点可见：聚焦状态必须有明显可见的轮廓，不能只靠填充色变化表达。
- 提示可达：提示框内容应能通过键盘触发，或以常驻文本的形式呈现，不能只由悬停触发。
- 快捷键避让：自定义快捷键不得覆盖浏览器与辅助技术的常用按键组合。

```html
<svg role="img" aria-labelledby="chartTitle" tabindex="0">
  <title id="chartTitle">2026 年上半年各区域销售额</title>
  <desc>柱状图，华东区域最高，西北区域最低。</desc>
</svg>
```

> 键盘使用者在图表上无法自由悬停，逐点浏览必须按固定顺序推进，顺序与视觉排列不一致会显著提高理解成本。

**速记**：交互图元要可聚焦且顺序一致、焦点可见、提示可键盘触发，自定义快捷键不得与辅助技术冲突。



#### 语义标记与屏幕阅读器

**语义标记**：是给图形元素附加角色与可读名称，使辅助技术在遍历页面时能说明这是哪一类图形、表达了什么。

- 根元素角色：把整幅图形标记为图像角色，并给出可读名称与描述。
- 名称与描述分工：名称给结论性的短句，描述补充单位、范围与趋势。
- 分组：把同一系列的元素标记为一组，避免逐个朗读无意义的图元。
- 图形专用角色：WAI-ARIA 图形模块为图形文档定义了一组专用角色，其规范成熟度以 W3C 最新发布状态为准。

```html
<figure>
  <svg role="img" aria-labelledby="revenueTitle" aria-describedby="revenueDesc">
    <title id="revenueTitle">各区域销售额对比</title>
    <desc id="revenueDesc">共六个区域，单位为万元，华东区域 1320 为最高值。</desc>
  </svg>
  <figcaption>数据来源：内部报表，统计至 2026 年 6 月。</figcaption>
</figure>
```

> 画布绘制的图表没有可供读取的内部结构，角色与名称只能挂在承载它的容器上，此时等价数据表的重要性更高。

**速记**：给图形根元素一个角色、名称与描述，名称给结论、描述给补充，同系列元素要分组。



### 数据表与替代形式

图形对辅助技术不透明，等价的数据表与文本替代是信息可达的基本手段。本节给出表格、摘要与静态替代三条路径。

#### 数据表的呈现与关联

**数据表**：是以行列结构承载原始数值、可与图形并列或按需展开的替代形式。

- 表头与范围：表头单元格要标明所属行或列，单位写在表头或表格说明里。
- 标题与说明：表格要有标题，并在说明中写明口径与更新时间。
- 显隐方式：数据量大时默认折叠并提供展开入口，不展示时用可被辅助技术忽略的方式隐藏，而不是从文档中删除。
- 数值同源：表中的数值与图形必须取自同一份数据，避免两处口径不一致。

```html
<figure>
  <figcaption>各区域销售额（万元，2026 年上半年）</figcaption>
  <table>
    <thead>
      <tr><th scope="col">区域</th><th scope="col">销售额</th></tr>
    </thead>
    <tbody>
      <tr><th scope="row">华东</th><td>1320</td></tr>
      <tr><th scope="row">西北</th><td>410</td></tr>
    </tbody>
  </table>
</figure>
```

> 对屏幕阅读器使用者而言，表格往往才是主要读取路径，图形只是视觉补充，两者的数值必须完全对应。

**速记**：等价数据表要有标题、明确表头与单位，可折叠但不删除，数值与图形同源。



#### 文本摘要与关键结论

**文本摘要**：是用一到三句话给出图形核心结论的替代文本，用于在图形不可见时也能获取要点。

- 结论优先：先给最重要的比较结果，再给范围与异常。
- 自动生成：由数据生成摘要时必须处理空数据与单点数据，不能输出无意义的极值表述。
- 更新同步：数据刷新后摘要同步更新，不能停留在旧结论。
- 与描述区分：摘要承载结论，图形的名称与描述说明结构与单位，两者不互相替代。

```js
function buildSummary(points, unit) {
  if (!points.length) return "暂无数据。";
  const sorted = [...points].sort((a, b) => b.value - a.value);
  const top = sorted[0];
  const bottom = sorted[sorted.length - 1];
  return `共 ${points.length} 项，最高 ${top.name} ${top.value}${unit}，最低 ${bottom.name} ${bottom.value}${unit}。`;
}

console.log(buildSummary([{ name: "华东", value: 1320 }], "万元"));
// 共 1 项，最高 华东 1320万元，最低 华东 1320万元。
```

> [!WARNING]
> **警告内容**：自动摘要若只取最大与最小值，在数据分布均匀时会给出误导性的「极端」表述。生成摘要前应先判断这批数据是否适合用极值概括。

**速记**：文本摘要先给结论并随数据同步更新，自动生成时要处理空数据与不适合用极值概括的情况。



#### 打印与静态替代

**静态替代**：是在无法交互的场景中仍能传达信息的呈现方式，覆盖打印、导出与脚本不可用三种情况。

- 打印样式：隐藏轮播与回到顶部等只对屏幕有意义的控件，保证图形与表格完整落纸。
- 灰度安全：颜色区分在灰度打印后仍可辨认，依靠明度差异与图案而非纯色相差。
- 无脚本降级：脚本不可用时至少输出数据表与摘要，图形缺省不显示也不影响信息获取。
- 静态快照：归档与汇报场景使用导出图片或固定数据文件，避免依赖实时接口。

```css
@media print {
  .screen-only {
    display: none;
  }

  .chart-panel {
    break-inside: avoid;
  }
}
```

> 打印与导出会丢失交互，凡是只能通过悬停获得的信息都必须在静态形态下另行给出。

**速记**：打印与静态替代要隐藏屏幕专用控件、保证灰度可辨，并在脚本不可用时回退到表格与摘要。



### 导出与分享

图表需要离开页面进入报告、邮件与归档，导出格式与状态还原决定这些场景能否复现。本节给出格式选择、实现要点与分享状态三方面做法。

#### 导出格式的选择

**导出格式**：是图表离开页面时的载体形式，按是否需要缩放、是否需要再次编辑与是否需要原始数据来区分。

- 矢量图：用于报告与印刷，缩放不失真，适合线条与文字清晰的图表。
- 位图：用于截图与即时通讯，兼容性最好，放大之后会模糊。
- 数据文件：用于二次分析，导出结构化数据而不是图片。
- 文档与打印：需要分页与页眉页脚时走打印路径，而不是把图片贴进文档。

```json
{
  "target": "report",
  "format": "svg",
  "pixelRatio": 2,
  "backgroundColor": "#ffffff"
}
```

> 格式选择的第一问是接收方拿到文件之后要做什么，而不是哪一种格式更清晰。

**速记**：矢量用于印刷、位图用于分享、数据文件用于二次分析，格式由接收方的用途决定。



#### 图片与数据导出的实现

**导出实现**：是调用绘图对象自带的导出方法或自行序列化图形得到文件的过程，需要处理背景、清晰度与样式内联。

- 画布导出：调用画布的转换方法得到二进制对象或数据地址，透明背景在多数接收端会显示为黑或白，应显式填底色。
- 清晰度：按设备像素比放大导出尺寸，避免小图在文档中被拉伸后模糊。
- 图表实例导出：图表实例通常自带取图方法，可指定格式、像素比与背景色（具体字段以所用版本文档为准）。
- 矢量导出：序列化 SVG 时外部样式表不会随之带走，需要把关键样式内联到元素上。

```js
function exportCanvas(canvas, fileName) {
  canvas.toBlob((blob) => {
    const url = URL.createObjectURL(blob);
    const link = document.createElement("a");
    link.href = url;
    link.download = fileName;
    link.click();
    URL.revokeObjectURL(url);
  }, "image/png");
}
```

```js
function serializeSvg(svgElement) {
  const clone = svgElement.cloneNode(true);
  clone.setAttribute("xmlns", "http://www.w3.org/2000/svg");
  return new XMLSerializer().serializeToString(clone);
}
```

```js
function buildCsv(rows, columns) {
  const escapeCell = (cell) => `"${String(cell).replace(/"/g, '""')}"`;
  const lines = [columns.join(",")];
  for (const row of rows) {
    lines.push(columns.map((key) => escapeCell(row[key])).join(","));
  }
  return lines.join("\n");
}

console.log(buildCsv([{ name: "华东", value: 1320 }], ["name", "value"]));
// name,value
// "华东","1320"
```

> [!CAUTION]
> **注意内容**：序列化 SVG 时外部样式表不会随之导出，直接保存会让导出文件丢失配色与字体。导出前必须把关键样式内联到元素上。

**速记**：导出要显式填背景、按像素比放大清晰度、内联样式，图表实例另有取图方法可指定这些参数。



#### 分享链接与状态还原

**状态还原**：是把筛选条件、时间范围与视图层级写入地址或存储，使链接打开后回到同一视图的做法。

- 可序列化状态：只把筛选、时间范围、排序与选中项写入地址，图表内部的临时状态不写入。
- 默认值省略：与默认值相同的项不写入地址，保持链接简短可读。
- 打开即还原：页面加载时先解析地址参数再请求数据，避免先请求默认数据再发起第二次请求。
- 敏感信息：地址会进入日志与转发链路，凭据与个人数据不得写入地址参数。

```js
function readChartState() {
  const params = new URLSearchParams(window.location.search);
  return {
    range: params.get("range") ?? "30d",
    region: params.get("region") ?? "all"
  };
}

console.log(readChartState()); // { range: "30d", region: "all" }
```

> 分享链接的价值在于复现同一视图，写入过多内部状态会让链接变脆，任何一次改版都可能让旧链接失效。

**速记**：只把筛选与时间范围写入地址、省略默认值、打开即还原，凭据与个人数据不得入地址。



### 工程结构与模块划分

图表代码容易在多个页面里复制粘贴成互不一致的副本。本节给出目录分层、配置集中与数据视图边界三方面的组织方式。

#### 目录分层与职责

**目录分层**：是按数据、比例尺与编码、视图、交互、配置把图表相关代码分到不同目录的组织方式。

- 数据层：请求、清洗与字段规范化，输出结构稳定的数据。
- 比例尺层：把数据值映射到位置、长度与颜色，只依赖输入输出，不依赖具体框架。
- 图表层：图表的创建、更新与销毁，只消费数据与配置。
- 交互层：筛选、下钻与联动，负责把用户动作转换成状态变化。

```ts
interface ChartSpec {
  type: string;
  data: unknown[];
  encoding: Record<string, string>;
  theme: string;
}

function createChartModule(spec: ChartSpec): { update(next: ChartSpec): void } {
  return { update: (next) => void next };
}
```

> 分层的目的不是形式整齐，而是让「更换数据源」与「更换图表库」两件事互不影响。

**速记**：按数据、比例尺、图表、交互分层，各层只依赖稳定的输入输出，换数据源与换库互不影响。



#### 配置与主题的集中管理

**配置集中**：是把尺寸、间距、色板与默认项收敛到少数模块，供各图表按标识取用。

- 单一来源：色板与字号只在一处定义，图表不得各自硬编码色值。
- 主题注册：主题以名称注册，图表按名称取用，切换主题时不必逐个改配置。
- 默认项：为常用图表类型准备默认配置，页面只覆盖有差异的字段。
- 变更边界：新增色值前先判断能否复用已有色板，避免色板无序扩张。

```js
const themeRegistry = new Map();

function registerTheme(name, tokens) {
  themeRegistry.set(name, tokens);
}

registerTheme("dark", { background: "#131a2e", text: "#e6ecff" });
registerTheme("light", { background: "#ffffff", text: "#1f2430" });

console.log([...themeRegistry.keys()]); // [ 'dark', 'light' ]
```

> 配置集中的反面是每个图表各带一份默认值，改一次全局风格要改几十处，最终无人敢改。

**速记**：色板与字号只在一处定义，主题按名称注册，默认配置只覆盖差异字段，避免各图表硬编码。



#### 数据层与视图层的边界

**数据视图边界**：是把取数与转换同渲染与交互分开，通过纯函数与显式参数连接的组织约定。

- 纯转换：排序、分组与汇总写成纯函数，输入输出明确，便于单独测试。
- 视图不取数：视图只接收已经就绪的数据，不在渲染过程中发起请求。
- 错误上抛：数据层把失败信息与陈旧状态一并返回，由视图决定如何呈现。
- 类型约束：两层的接口用类型描述，字段变更在编译期暴露。

```js
function aggregateByRegion(rows) {
  const totals = new Map();
  for (const row of rows) {
    totals.set(row.region, (totals.get(row.region) ?? 0) + row.value);
  }
  return [...totals].map(([region, value]) => ({ region, value }));
}

console.log(aggregateByRegion([{ region: "华东", value: 1320 }]));
// [ { region: '华东', value: 1320 } ]
```

> 边界清晰之后，数据源从接口换成静态文件、从轮询换成推送，都不需要触碰渲染代码。

**速记**：取数与转换放数据层并写成纯函数，视图只消费已就绪数据，失败与陈旧状态由视图决定呈现。



### 质量保障与视觉回归

图表测试的难点在于渲染结果难以逐像素断言，而配置错误往往不报错、只显示为空白。本节给出断言对象、视觉回归与基线治理三方面做法。

#### 图表场景的测试要点

**图表测试**：是以数据转换、比例尺映射与最终配置为断言对象，而不是以像素颜色为断言对象的测试方式。

- 分层断言：数据转换与比例尺用单元测试，配置生成用快照，渲染与交互用端到端测试。
- 断言数据：优先断言传给图表的配置与数据，失败时能定位是数据错还是渲染错。
- 运行环境：无浏览器环境缺少画布实现，涉及真实绘制的用例应在浏览器中运行。
- 交互用例：筛选、悬停与联动由端到端覆盖，断言可见文本而不是像素。
- 失败可读：断言信息里带上被判定的字段与期望值，避免只输出「不相等」。

```ts
function countSeries(option: { series: unknown[] }): number {
  return option.series.length;
}

const option = { series: [{ type: "bar" }, { type: "line" }] };
console.assert(countSeries(option) === 2, "系列数量应为 2");
```

> 断言配置而不是像素，可以让失败信息直接指向出错的字段，而不是只告知测试者颜色不同。

**速记**：断言数据与配置而非像素，转换与比例尺走单元测试、配置走快照、渲染与交互走端到端。



#### 视觉回归的实现

**视觉回归（visual regression）**：是把界面渲染结果与基线截图对比、用于发现样式与布局意外变化的测试方式。

- 固定环境：锁定视口尺寸、设备像素比、字体与浏览器版本，否则差异来自环境而非代码。
- 关闭动画：截图前停用入场动画与轮播，等待渲染稳定再取图。
- 忽略动态区：时间戳、随机数与实时数字用遮罩排除，避免每次都产生差异。
- 差异阈值：按差异像素比例设置容忍阈值，过严的阈值会因抗锯齿产生噪声。

```ts
import { test, expect } from "@playwright/test";

test("图表面板视觉稳定", async ({ page }) => {
  await page.goto("/dashboard?range=30d");
  await page.waitForSelector(".chart-panel canvas");
  await expect(page.locator(".chart-panel")).toHaveScreenshot({
    maxDiffPixelRatio: 0.01,
    animations: "disabled"
  });
});
```

> [!TIP]
> **建议内容**：视觉回归只覆盖关键面板与稳定组件。把整块大屏都纳入比对，会因轮播与实时数字产生大量噪声，最终退化为盲目更新基线。

**速记**：视觉回归要锁定环境、关闭动画、遮罩动态区并设置差异阈值，只覆盖关键面板。



#### 基线与噪声治理

**基线**：是被认定为正确的历史截图，后续比对以它为参照，基线的可信度决定视觉回归的价值。

- 评审后更新：差异必须人工确认是有意变更之后才能更新基线，不能默认接受。
- 缩小范围：基线数量越多维护成本越高，只保留关键面板与关键分辨率。
- 噪声归因：把噪声来源逐项排除，而不是靠提高阈值把噪声一起掩盖。
- 版本管理：基线随代码一起评审与回滚，避免出现无法解释的基线漂移。

```json
{
  "expect": {
    "toHaveScreenshot": {
      "maxDiffPixelRatio": 0.01,
      "animations": "disabled",
      "scale": "css"
    }
  }
}
```

> 基线一旦被随意更新，视觉回归就只剩下运行成本而没有发现问题的能力，治理比引入工具更重要。

**速记**：基线只在人工确认后更新，范围压到关键面板与分辨率，噪声要归因而不是靠抬高阈值掩盖。
