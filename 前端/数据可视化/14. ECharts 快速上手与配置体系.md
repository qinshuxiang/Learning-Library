## ECharts 快速上手与配置体系

### ECharts 是什么与适用场景

ECharts 面向的是「用一份配置描述整张图表」的场景。本节先给出定义，再说明它与底层绘图方案的分工，最后划定适用边界，为后续配置学习建立判断依据。

#### 定义与定位

**ECharts**：是 Apache 基金会旗下一款声明式图表库，调用方传入一份选项对象描述图表，库负责推导布局、绘制图形并挂载交互能力。

- 声明式：只描述要呈现的数据与图形类型，坐标范围、刻度与图例由库自行推导。
- 成品化：折线图、柱状图、饼图、散点图、地图与关系图等常用图表均为内置类型。
- 交互内置：提示框、图例开关、数据区域缩放与工具箱导出无需自行实现。
- 渲染可切换：同一份配置可由 Canvas 渲染器或 SVG 渲染器输出。
- 零框架依赖：可在原生页面与 React、Vue 等框架中直接使用。

```bash
npm install echarts
# 全量引入：import * as echarts from 'echarts'
# 按需引入：从 echarts/core 与 echarts/charts 中挑选模块后注册
```

> 声明式不等于不可控：需要接管单个图形的绘制过程时，自定义系列与图形组件允许直接操作渲染层。

**速记**：ECharts 是声明式成品图表库，一份配置描述图表，布局与交互由库完成。



#### 与 D3 和底层绘图方案的分工

**分层分工**：是把「数据到视觉的映射」与「图形的具体绘制」拆给不同工具承担，ECharts 接管前者并把后者封装为渲染器，底层方案则要求调用方自行衔接两层。

- 与 D3 的差别：D3 提供选择集、比例尺与形状生成器，图形结构与交互需自行搭建；ECharts 直接给出成品图表。
- 与 Canvas 手绘的差别：手绘需自行处理坐标换算、刻度计算与重绘时机；ECharts 由配置驱动并在数据变化时自动重绘。
- 与 SVG 手绘的差别：手绘需管理元素增删与层级顺序；ECharts 由渲染器统一维护这些细节。
- 复用关系：需要完全自定义的图形时，可在 ECharts 的自定义系列中调用底层绘制能力，两者并非互斥。
- 判断依据：图表类型落在库的支持范围内选 ECharts，需要原创图形语法或像素级控制时选底层方案。

**速记**：ECharts 管映射与交互，底层方案管绘制；常规图表用库，原创图形用底层。



#### 适用与不适用场景

**适用范围**：是图表类型在库支持范围内、需要快速交付且对交互完备度有要求的场合，典型如后台系统、运营看板与数据大屏。

- 业务看板：以标准折线图、柱状图、饼图为主，配置量小且交付快。
- 数据大屏：需要主题定制、动画与自适应布局，库提供现成能力。
- 交互密集型图表：需要提示框、联动、数据区域缩放与导出图片。
- 地图类展示：需要按行政区划分色或标注点位。

- 不适用原创视觉语法：图形映射规则需要重新定义时，库的抽象会成为阻碍。
- 不适用极小体积约束：对首屏体积极端敏感的小组件，应评估更轻量的库。
- 不适用非图表绘制：装饰性动画、粒子效果与图像处理不属于图表库职责。

> [!CAUTION]
> **注意内容**：把 ECharts 当作通用绘图引擎使用，会引入不必要的体积与抽象成本，原创图形需求应先评估底层绘图方案。

**速记**：常规业务图表用 ECharts，原创图形语法、极端体积约束与非图表绘制不适用。



### 安装、初始化与销毁

拿到图表实例是使用 ECharts 的第一步。本节说明引入方式、初始化所需的容器条件，以及实例销毁与复用的正确顺序。

#### 安装与引入方式

**全量引入**：是一次性引入库的全部图表与组件；**按需引入**：是只引入用到的图表类型、组件与渲染器，减小打包体积。

- 包管理器安装后从 echarts 主入口引入即可获得全部能力，适合原型与图表种类较多的项目。
- 按需引入从 echarts/core 取核心，再从 echarts/charts 与 echarts/components 分别取图表与组件。
- 按需引入必须调用 echarts.use 注册所取模块，未注册的图表类型不会出现在实例中。
- 渲染器也需注册，Canvas 渲染器与 SVG 渲染器来自 echarts/renderers。
- 需要通过脚本标签直接引入时，使用官方发布的构建产物并访问全局变量 echarts。

```js
import * as echarts from 'echarts/core';
import { LineChart, BarChart } from 'echarts/charts';
import { GridComponent, TooltipComponent, LegendComponent } from 'echarts/components';
import { CanvasRenderer } from 'echarts/renderers';

echarts.use([
  LineChart,
  BarChart,
  GridComponent,
  TooltipComponent,
  LegendComponent,
  CanvasRenderer
]);
```

**速记**：全量引入省事、按需引入省体积，按需引入必须用 echarts.use 注册图表、组件与渲染器。



#### 初始化与容器准备

**echarts.init(dom, theme, opts)**：是创建图表实例的方法，dom 为容器元素，theme 为主题名或主题对象，opts 为渲染器与尺寸等选项，返回图表实例。

- 容器条件：容器元素必须已经挂载到文档且具有可计算的宽度与高度。
- theme 参数：传入内置主题名或已注册的主题对象，不需要主题时传 null。
- opts 常用字段：renderer 指定渲染器，width 与 height 指定显式尺寸，devicePixelRatio 指定像素比。
- 单次初始化：同一容器重复调用 init 会得到新实例并丢失旧实例的引用。

```js
const chartDom = document.getElementById('sales-chart');
const chart = echarts.init(chartDom, null, { renderer: 'canvas' });

chart.setOption({
  xAxis: { type: 'category', data: ['一月', '二月', '三月'] },
  yAxis: { type: 'value' },
  series: [{ type: 'line', data: [120, 200, 150] }]
});
// 容器若无显式高度，图表高度为 0，页面上看不到任何图形
```

> [!WARNING]
> **警告内容**：容器元素没有可计算的宽度或高度时，初始化得到的是尺寸为 0 的图表，必须先用样式为容器设定尺寸再初始化。

**速记**：容器先有宽高再 init，theme 传主题名或对象，opts 控制渲染器、尺寸与像素比。



#### 销毁、实例复用与内存

**dispose()**：是销毁图表实例并释放画布、事件与内部缓存的方法；**getInstanceByDom(dom)**：是按容器元素取回已存在实例的静态方法。

- 框架卸载或路由切换时销毁实例，避免容器被移除后实例仍持有引用。
- 同一容器需要重新初始化前，先用 getInstanceByDom 判断是否已有实例。
- isDisposed() 可判断实例是否已销毁，销毁后不得再调用 setOption 与 resize。
- 多个容器对应多个实例，实例之间互不影响；需要联动时另见第 15 篇的 connect 用法。

```js
const chartDom = document.getElementById('sales-chart');
const existing = echarts.getInstanceByDom(chartDom);
const chart = existing || echarts.init(chartDom);

function disposeChart() {
  if (!chart.isDisposed()) {
    chart.dispose();
  }
}

window.addEventListener('beforeunload', disposeChart);
```

**速记**：用 getInstanceByDom 复用实例，卸载时 dispose 释放资源，销毁后不再调用实例方法。



### option 结构与核心组件

配置体系的核心是一份选项对象。本节拆开它的顶层结构，说明坐标系与系列的对应关系，以及通用组件各自负责的区域。

#### option 的顶层结构

**option**：是一份普通对象，顶层键分为全局组件与系列两类，setOption(option, notMerge, lazyUpdate) 把它合并进实例状态。

- 布局类组件：grid 定义绘图区域位置，title 定义标题，legend 定义图例。
- 坐标类组件：xAxis、yAxis、polar、angleAxis、radiusAxis、geo 定义坐标系。
- 辅助类组件：tooltip、toolbox、dataZoom、visualMap、brush 提供交互与视觉映射。
- 数据类键：series 是图表类型的载体，dataset 用于集中管理数据源。
- 参数语义：notMerge 为 true 时整体替换旧配置，lazyUpdate 为 true 时把更新推迟到下一帧。

```json
{
  "title": { "text": "月度销量" },
  "tooltip": { "trigger": "axis" },
  "legend": { "data": ["线上", "线下"] },
  "grid": { "left": 48, "right": 24, "bottom": 40 },
  "xAxis": { "type": "category", "data": ["一月", "二月", "三月"] },
  "yAxis": { "type": "value" },
  "series": [
    { "name": "线上", "type": "bar", "data": [120, 200, 150] },
    { "name": "线下", "type": "bar", "data": [90, 130, 110] }
  ]
}
```

> setOption 默认按字段合并，只覆盖本次传入的键；需要清空旧配置时把 notMerge 置为 true。

**速记**：option 顶层分组件与系列，setOption 默认合并且只覆盖传入的键。



#### 坐标系与系列

**坐标系（coordinate system）**：是决定图形位置如何由数值换算而来的参照系；**系列（series）**：是同一图表类型的一组数据与样式，series[i].type 决定图形类型。

- 直角坐标系：由 xAxis 与 yAxis 定义，绝大多数折线、柱状与散点系列使用它。
- 极坐标系：由 polar 与 angleAxis、radiusAxis 定义，用于角度与半径双维表达。
- 地理坐标系：由 geo 或地图系列提供，用于点位与区域着色。
- 雷达与日历坐标系：分别服务于多维对比与时间分布表达。
- 绑定规则：系列通过 coordinateSystem 字段声明所使用的坐标系，直角坐标系可省略。

```js
chart.setOption({
  polar: {},
  angleAxis: { type: 'category', data: ['A', 'B', 'C', 'D'] },
  radiusAxis: { type: 'value' },
  series: [{ type: 'bar', coordinateSystem: 'polar', data: [2, 3, 4, 3] }]
});
```

**速记**：先有坐标系再有系列，series[i].type 定图形，coordinateSystem 定参照系。



#### 通用组件的职责

**通用组件**：是不依赖具体图表类型、可与任意系列并用的配置块，它们把布局、交互与视觉映射从系列中分离出来。

- title：标题与副标题，支持位置与样式。
- grid：直角坐标系的绘图区域，left、right、top、bottom 控制四周边距。
- legend：图例，按系列名生成开关项，控制系列的显示与隐藏。
- tooltip：提示框，trigger 取 axis 时按坐标轴汇总，取 item 时按图形项触发。
- toolbox：工具框，提供导出图片、还原视图与数据视图等操作。
- dataZoom 与 visualMap：前者控制数据窗口，后者把数值映射为颜色或大小。

```js
chart.setOption({
  tooltip: { trigger: 'axis' },
  grid: { left: 48, right: 24, bottom: 48, containLabel: true },
  xAxis: { type: 'category', data: ['一月', '二月', '三月'] },
  yAxis: { type: 'value' },
  series: [{ name: '线上', type: 'line', data: [120, 200, 150] }]
});
```

> grid.containLabel 为 true 时会把坐标轴标签的宽度计入边距，避免长标签被裁切。

**速记**：title 管标题、grid 管绘图区、legend 管开关、tooltip 管提示、toolbox 管工具、dataZoom 管窗口。



### 常用图表配置

不同图表类型共享同一套 option 骨架，差异集中在 series 的 type 与对应字段。本节按常用程度给出可运行的配置片段。

#### 折线图与柱状图

**折线图（line）**：是以点与线的连接表达数值随时间或类别变化的系列类型；**柱状图（bar）**：是以矩形长度表达数值大小的系列类型，二者共用直角坐标系。

- smooth 控制折线是否平滑，平滑会改变视觉斜率，趋势判断仍以原始点为准。
- areaStyle 给折线下方填充面积，用于强调累积量或占比。
- stack 让多个系列在同一分类上堆叠，用于表达总量与构成。
- barWidth 与 barGap 控制柱宽与同组柱之间的间距。
- emphasis 定义悬停高亮时的样式，配合 tooltip 提示具体数值。

```js
chart.setOption({
  tooltip: { trigger: 'axis' },
  legend: { data: ['访问量', '下单量'] },
  xAxis: { type: 'category', data: ['周一', '周二', '周三', '周四'] },
  yAxis: { type: 'value' },
  series: [
    { name: '访问量', type: 'line', smooth: true, data: [820, 932, 901, 1290], areaStyle: {} },
    { name: '下单量', type: 'bar', barWidth: 20, data: [220, 282, 291, 334] }
  ]
});
```

**速记**：折线看趋势、柱状看对比，二者共用 xAxis 与 yAxis，靠 series 的 type 区分。



#### 饼图与散点图

**饼图（pie）**：是以扇形角度表达占比的系列类型，不使用直角坐标系；**散点图（scatter）**：是以点的位置表达两个定量维度关系的系列类型。

- radius 控制饼图的半径，写数组时形成空心环图；center 控制圆心位置。
- roseType 把扇形半径也纳入数值表达，形成南丁格尔玫瑰图，可读性弱于普通饼图。
- 散点图的 symbolSize 可写成函数，按数据值动态决定点的直径。
- 散点图数据量大时应开启大数据量模式，相关配置归第 15 篇。

```js
chart.setOption({
  tooltip: { trigger: 'item' },
  legend: { bottom: 0 },
  series: [
    {
      type: 'pie',
      radius: ['40%', '70%'],
      center: ['50%', '45%'],
      data: [
        { value: 1048, name: '搜索引擎' },
        { value: 735, name: '直接访问' },
        { value: 580, name: '邮件营销' },
        { value: 484, name: '联盟广告' }
      ]
    },
    {
      type: 'scatter',
      symbolSize: (value) => Math.sqrt(value[1]) * 3,
      data: [[10, 8], [20, 30], [35, 40], [48, 22]]
    }
  ]
});
```

**速记**：饼图靠角度表达占比且分类不宜多，散点图靠位置表达两个定量维度的关系。



#### 多系列与图表类型组合

**类型组合**：是在同一 option 的 series 数组中混放多种图表类型，只要它们绑定到同一坐标系即可共享绘图区域。

- 同一坐标系内可同时出现折线、柱状与散点系列，用 legend 统一控制显隐。
- 量纲差异较大时可用第二个 yAxis，并在系列上通过 yAxisIndex 指定所属轴。
- 系列顺序决定绘制层级，后绘制的系列覆盖先绘制的系列。
- 组合图的 tooltip 需按轴触发，才能在一次悬停中读出各系列的值。
- 类型切换只需改动 series[i].type，数据与坐标系字段可大部分复用。

```js
chart.setOption({
  tooltip: { trigger: 'axis' },
  legend: { data: ['销售额', '增长率'] },
  xAxis: { type: 'category', data: ['一月', '二月', '三月', '四月'] },
  yAxis: [{ type: 'value', name: '销售额' }, { type: 'value', name: '增长率', axisLabel: { formatter: '{value}%' } }],
  series: [
    { name: '销售额', type: 'bar', data: [120, 200, 150, 80] },
    { name: '增长率', type: 'line', yAxisIndex: 1, data: [12, 20, 15, 8] }
  ]
});
```

> [!WARNING]
> **警告内容**：把量纲不同且无明确比值关系的两组数据并置到双轴，会制造虚假的交叉与趋势对比，属于误导性做法，仅在量纲一致或存在明确换算关系时使用双轴。

**速记**：类型组合靠 series 数组混放，跨量纲用 yAxisIndex 指第二轴，双轴不可滥用。



### 主题与样式定制

默认样式适合快速验证，交付前需要统一视觉。本节说明主题的注册与使用、逐项样式的覆盖顺序，以及标签里的富文本写法。

#### 内置主题与自定义主题

**主题（theme）**：是一组预定义的全局样式，作用于调色盘、背景、文字与各类系列的默认外观；**registerTheme(name, theme)**：是注册自定义主题的静态方法。

- 内置主题：init 的 theme 参数传入内置主题名即可启用，深色主题适合大屏场景。
- 主题对象可写 color 调色盘、backgroundColor 背景与 textStyle 全局文字样式。
- 主题影响的是默认值，系列内的显式样式优先级高于主题。
- 主题在初始化时绑定，运行中需要换肤时应销毁后以新主题重建实例。

```js
echarts.registerTheme('report-dark', {
  color: ['#5b8ff9', '#5ad8a6', '#f6bd16', '#e8684a'],
  backgroundColor: '#1f2430',
  textStyle: { color: '#c9d1d9' }
});

const chart = echarts.init(chartDom, 'report-dark');
chart.setOption({
  xAxis: { type: 'category', data: ['一月', '二月', '三月'] },
  yAxis: { type: 'value' },
  series: [{ type: 'line', data: [120, 200, 150] }]
});
```

**速记**：主题管全局默认，registerTheme 注册后由 init 的 theme 参数启用，运行中换肤需重建实例。



#### 调色盘与逐项样式

**调色盘（color palette）**：是 option 顶层的 color 数组，系列按顺序循环取色；**逐项样式**：是写在系列内部的 itemStyle、lineStyle 与 areaStyle 等样式块。

- color 数组按系列顺序分配颜色，多系列图表由此获得一致的分类色。
- itemStyle 控制柱、点、扇形等图形块的填充、描边与圆角。
- lineStyle 控制折线的宽度、类型与端点样式。
- 渐变通过 echarts.graphic.LinearGradient 构造后赋给颜色字段。
- 逐项样式的优先级高于调色盘，写上具体色值后不再随主题变化。

```js
chart.setOption({
  color: ['#5b8ff9', '#5ad8a6', '#f6bd16'],
  series: [{
    type: 'line',
    data: [120, 200, 150, 80],
    lineStyle: { width: 3, type: 'dashed' },
    itemStyle: { color: '#5b8ff9' },
    areaStyle: {
      color: new echarts.graphic.LinearGradient(0, 0, 0, 1, [
        { offset: 0, color: 'rgba(91, 143, 249, 0.5)' },
        { offset: 1, color: 'rgba(91, 143, 249, 0)' }
      ])
    }
  }]
});
```

**速记**：调色盘在顶层按系列分配颜色，系列内的逐项样式优先级更高并会脱离主题换肤。



#### 标签、富文本与视觉映射

**标签（label）**：是绘制在图形上或旁边的文字；**富文本（rich text）**：是在一条标签内混排多种字号的写法；**视觉映射（visualMap）**：是把数值区间映射为颜色或图形尺寸的组件。

- label.show 控制标签显隐，position 控制相对图形的方位。
- formatter 支持模板变量，{c} 表示数值，{b} 表示名称。
- rich 定义若干命名样式片段，在 formatter 中用花括号加竖线引用。
- 标签过密时应减少显示数量，避免互相遮挡。
- visualMap 适合把连续数值映射为顺序色，与图例合用可读出数值范围。

```js
chart.setOption({
  visualMap: {
    min: 0,
    max: 200,
    calculable: true,
    inRange: { color: ['#e8f4ff', '#5b8ff9'] }
  },
  series: [{
    type: 'bar',
    data: [120, 200, 150, 80],
    label: {
      show: true,
      position: 'top',
      formatter: '{name|目标} {value|{c}}',
      rich: {
        name: { color: '#8c8c8c', fontSize: 12 },
        value: { color: '#1f1f1f', fontSize: 14, fontWeight: 'bold' }
      }
    }
  }]
});
```

**速记**：label 管图形上的文字，rich 在一条标签内混排字体，visualMap 把数值映射为颜色。



### 响应式与自适应

图表容器的尺寸在运行时可能变化。本节说明尺寸重算、按断点切换配置，以及渲染器与像素比的选择。

#### 容器尺寸变化与 resize

**resize(opts)**：是按容器当前尺寸重新计算布局与画布大小的方法，opts 可含 width、height 与 silent。

- 窗口缩放、侧边栏收合与栅格重排都会改变容器尺寸，图表不会自动跟随。
- 监听容器尺寸而非仅监听窗口，才能覆盖不改变窗口宽度的布局变化。
- resize 应在容器尺寸稳定后调用，频繁抖动时可做延迟合并。
- 组件卸载时同时断开尺寸监听，避免对已销毁实例调用 resize。
- 打印或导出前应先 resize，保证输出尺寸与目标一致。

```js
function bindResize(container, chart) {
  const observer = new ResizeObserver(() => chart.resize());
  observer.observe(container);
  return () => observer.disconnect();
}

const unbindResize = bindResize(chartDom, chart);
window.addEventListener('beforeunload', unbindResize);
```

**速记**：图表不自动跟随容器，必须监听容器尺寸并调用 resize，卸载时同步解除监听。



#### 断点式配置切换

**断点式配置**：是按容器宽度切换不同配置块的做法，ECharts 用 option 的 baseOption 与 media 两个键表达。

- baseOption 写默认配置，media 数组写各断点下的覆盖配置。
- 每条 media 项包含 query 与 option 两个键，query 支持 maxWidth、minWidth、maxHeight 与 minHeight。
- 窄屏下常见的调整是简化提示框触发方式、开启数据区域缩放、缩短标题。
- 使用 media 时，setOption 传入的对象只应包含 baseOption 与 media 两个键。
- 断点值应与容器实际宽度对应，而非固定按设备类型划分。

```js
chart.setOption({
  baseOption: {
    tooltip: { trigger: 'axis' },
    xAxis: { type: 'category', data: ['一月', '二月', '三月'] },
    yAxis: { type: 'value' },
    series: [{ type: 'line', data: [120, 200, 150] }]
  },
  media: [{
    query: { maxWidth: 480 },
    option: {
      tooltip: { trigger: 'item' },
      dataZoom: [{ type: 'inside' }],
      grid: { left: 32, right: 16, bottom: 32, containLabel: true }
    }
  }]
});
```

**速记**：断点配置写在 baseOption 与 media 中，query 按容器宽高匹配，窄屏优先简化交互与边距。



#### 高清屏与渲染器选择

**渲染器（renderer）**：是把图表绘制到页面上的后端实现，ECharts 提供 Canvas 与 SVG 两种；**devicePixelRatio**：是物理像素与逻辑像素的比值，用于控制高清屏下的绘制清晰度。

- Canvas 渲染器以位图绘制，图形数量多时表现更稳定，是默认选择。
- SVG 渲染器以矢量元素绘制，文字与线条在缩放与打印时更清晰。
- init 的 opts 中通过 renderer 字段选择渲染器，取值常见为 canvas 与 svg。
- devicePixelRatio 写入 opts 可控制位图的像素密度，取值过高会显著增加内存占用。
- 同一页面内不同实例可以选择不同渲染器，按图表类型分别权衡。

```js
const chart = echarts.init(chartDom, null, {
  renderer: 'svg',
  devicePixelRatio: window.devicePixelRatio
});
```

> [!NOTE]
> **提醒内容**：SVG 渲染器在图形元素数量很多时内存占用上升，大数据量图表仍以 Canvas 渲染器为主，清晰度问题应通过 devicePixelRatio 解决。

**速记**：Canvas 适合大数据量与图形密集场景，SVG 适合文字清晰度要求高的场景，像素比写入 init 的 opts。
