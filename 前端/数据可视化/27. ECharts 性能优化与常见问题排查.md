## ECharts 性能优化与常见问题排查

ECharts 自身的性能参数（large、渐进渲染、降采样）已在本主题第 15 篇讲过，跨渲染层的通用优化方法在第 18 篇，本篇不重复这两块，只做两件事：一是从组合使用角度给性能参数的实践配置与度量方法，二是给出一份按症状分类的排查清单——白屏、错位、标签重叠、事件失灵、更新无效、内存上涨，逐条给出成因与修法。

### 性能参数的组合使用

单个性能参数的作用第 15 篇已讲清，实战中它们往往要组合出现，且组合方式随数据形态变化。本节给三类典型形态的参考配置与度量化验证。



#### 按数据形态组合性能参数

**组合配置**：是把 large、progressive、sampling 等参数按数据形态搭配使用的方法，单一参数开到底不是最优解。

- 折线时序数据：开 sampling 取 lttb，配 showSymbol 为 false，数据点过万再叠 progressive。
- 海量散点：开 large 模式，配 progressive 与 progressiveRendering 阈值，symbol 用内置形状避免自定义回调。
- 大类目柱状图：bar 类不支持 large，走数据侧聚合或 dataZoom 分页，见本主题第 18 篇数据侧优化。
- 组合之后必须对比开关前后的图形精度，降采样与 large 都会改变呈现细节，取舍要过人眼。
- 参数组合写入团队统一的「大数据量模板」，新页面按数据量级套模板而不是逐个现场调。

```js
// 折线时序数据的参考组合
chart.setOption({
  xAxis: { type: 'time' },
  yAxis: { type: 'value' },
  series: [{
    type: 'line',
    showSymbol: false,
    sampling: 'lttb',
    progressive: 2000,
    progressiveThreshold: 10000,
    data: largeTimeSeries
  }]
});
```

**速记**：折线配降采样、散点配 large 与渐进，柱状大数据先聚合分页，组合结果必须过人眼验证。



#### 渲染层与实例层的选择

**渲染层选择**：是 Canvas 与 SVG 渲染器按场景取舍的决策，实例层选择是单页多图时的布局与数量控制。

- 结论与第 14 篇一致：常规与大数据量用 Canvas，文字清晰度与打印场景用 SVG，这里补工程侧的补充判断。
- 单页图表实例数量多时，每个实例独立画布与事件系统，实例数本身就是成本；同类小图优先考虑合并为一张多 grid 图。
- 常驻页面的图表（监控大屏）控制实例总量，切换视图时销毁非可见实例，缓存策略见本主题第 22 篇。
- 全屏动画与高频更新集中在一个实例上，避免多实例同时高频重绘抢主线程。
- 混合使用渲染器时，同一页面内不同实例按需选 renderer，互不影响。

```js
// 多块同类小图：合并为多 grid 单实例
chart.setOption({
  grid: [
    { left: 48, right: 16, top: 32, height: '28%' },
    { left: 48, right: 16, top: '44%', height: '28%' },
    { left: 48, right: 16, top: '60%', height: '28%' }
  ],
  // 三块 grid 各配一套轴与系列，事件、主题、实例管理只维护一份
});
```

> [!TIP]
> **建议内容**：页面图表实例超过十个时先想合并——多 grid 单实例、tab 懒加载、非可见销毁，都能把实例数量压下来；实例数量是单页图表性能的第一道闸门。

**速记**：渲染器按清晰度与数据量选，实例数量优先压：能合并的合并、非可见的销毁。



#### 优化效果的度量方法

**度量化验证**：是每次优化前后都采集同一组指标对比的方法，没有度量的优化是猜测。

- 首屏指标：从数据就绪到图表绘制完成的耗时，用 performance 标记包住 init 与 setOption。
- 交互指标：悬停与缩放期间的长任务（long task）次数与总耗时，用 PerformanceObserver 采集。
- 更新指标：单次 setOption 的同步耗时，在调用前后取时间戳做差，轮询场景按批次统计均值与峰值。
- 内存指标：长时间运行页面的堆内存趋势，用内存快照对比，重点关注实例与监听数量。
- 指标采集代码在开发与预发环境启用，生产环境采样开启，避免采集本身拖慢页面。

```js
performance.mark('chart-update-start');
chart.setOption(nextOption);
performance.mark('chart-update-end');
performance.measure('setOption', 'chart-update-start', 'chart-update-end');

new PerformanceObserver((list) => {
  list.getEntries().forEach((entry) => {
    if (entry.duration > 50) {
      reportSlowUpdate(entry.duration);
    }
  });
}).observe({ entryTypes: ['longtask'] });
```

**速记**：首屏、交互、更新、内存四类指标前后对比，长任务超五十毫秒上报，度量先于优化。



### 显示问题排查

显示类问题的症状明确：白屏、错位、重叠。成因大多在配置与容器，按症状逐条对号入座，本节给五条高频症状的排查路径。



#### 白屏与图形不显示

**白屏排查**：是图表区域一片空白时按序核对的流程，成因集中在容器、注册与时机三处。

- 第一步查容器：宽高是否为 0、是否处于 display: none，容器问题占白屏案例的大多数。
- 第二步查注册：按需引入时漏注册图表或组件类型，症状同样是空白，控制台通常有相关警告。
- 第三步查时机：init 时容器未挂载（React 中 ref 为 null、Vue 中未到 onMounted）直接抛错或无效。
- 第四步查数据：数据全为空或全非法时图可能是「空图」而非故障，画坐标轴区分配。
- 第五步查样式：图表容器被上层元素遮挡（zIndex）或透明度为 0，用开发者工具选中元素核对占位。

```text
白屏排查顺序：
1. 容器宽高与可见性
2. 按需引入的注册清单
3. init 的调用时机（DOM 就绪）
4. 数据是否为空
5. 层级遮挡与透明度
```

**速记**：白屏五连查——容器、注册、时机、数据、遮挡，八成案例停在第一步。



#### 尺寸错位与 resize 失效

**尺寸错位**：是图表尺寸与容器不一致的现象，表现为拉伸变形、留白过多或只有一部分图形可见。

- 图表不会自动跟随容器尺寸，缺 ResizeObserver 或 resize 未触发是最常见成因。
- display: none 到可见的切换不触发 ResizeObserver，需要在可见回调里手动 resize，见本主题第 22 篇初始化时机。
- resize 前容器尺寸尚未稳定（动画进行中）会按中间值布局，延迟到稳定帧再调用。
- chart.resize 传 width 与 height 参数可强制尺寸，与容器实际尺寸不符时反而制造错位，常规场景不传。
- 检查是否存在多个监听重复调用 resize 或监听绑在错误元素（绑窗口而非容器）上。

```js
// 正确的尺寸绑定：监听容器、防抖、解除同步
const observer = new ResizeObserver(
  debounce(() => chart.resize(), 100)
);
observer.observe(container);
```

**速记**：错位先查有没有监听容器尺寸，隐藏转可见手动补 resize，动画稳定后再调，resize 不传参。



#### 标签重叠与遮挡

**标签重叠**：是轴标签、图形标签与提示框互相叠压的现象，处理手段分疏解与减量两路。

- 轴标签：interval 抽稀、rotate 旋转、hideOverlap 自动隐藏，见本主题第 24 篇类目轴标签处理。
- 图形标签：labelLayout 的 hideOverlap 与 moveOverlap 疏解，饼图配 avoidLabelOverlap。
- 引导线标签：饼图标签过长时 alignTo 贴边、length 控制引导线长度。
- 减量是根本手段：类目多就抽稀数据，标签值能从轴读出的就不必逐柱标注。
- grid 边距不足会把标签挤出绘图区裁掉，开 containLabel 并核对四边距。

```js
chart.setOption({
  grid: { left: 24, right: 24, top: 32, bottom: 16, containLabel: true },
  xAxis: {
    type: 'category',
    data: longCategories,
    axisLabel: { hideOverlap: true, rotate: 30 }
  },
  yAxis: { type: 'value' },
  series: [{
    type: 'bar',
    label: { show: true, position: 'top' },
    labelLayout: { hideOverlap: true }
  }]
});
```

**速记**：重叠分轴标签、图形标签、引导线三处治，先疏解后减量，边距开 containLabel 兜底。



#### tooltip 不显示与错位

**tooltip 异常**：是提示框不出现、位置漂移或内容缺失的现象，成因在触发配置与定位计算两处。

- 不显示先查 trigger：item 触发在轴空白处不出现属正常，想按轴触发要写 trigger 为 axis。
- 容器或祖先元素设置 overflow 为 hidden 会裁掉溢出的提示框，confine 为 true 或调整容器溢出策略。
- position 回调返回错误坐标（如把相对坐标当绝对坐标用）会飞出可视区，回调参数的含义先核文档。
- 提示框被页面其它元素的更高层级盖住：tooltip 默认 z-index 较高仍可能被弹层压住，核对弹层层级。
- formatter 抛错会导致整个提示框失效且往往静默，回调里先做数据兜底再拼文案。

```js
chart.setOption({
  tooltip: {
    trigger: 'axis',
    confine: true,
    position: (point, params, dom, rect, size) => {
      // point 为鼠标位置，size 为提示框与容器尺寸，按空间左右翻转
      const x = point[0] + size.contentSize[0] < size.viewSize[0]
        ? point[0] + 12
        : point[0] - size.contentSize[0] - 12;
      return [x, point[1] - size.contentSize[1] / 2];
    },
    formatter: (params) => safeFormat(params)
  }
});
```

> [!WARNING]
> **警告内容**：formatter 回调内的异常不会把错误暴露在图表上，表现是提示框整体失效，这类静默失败常被误判为「tooltip 坏了」；回调第一行先做参数兜底，调试期在回调外层临时 try-catch 定位。

**速记**：不显示查 trigger 与裁切，错位查 position 坐标语义与层级，失效先怀疑 formatter 抛错。



### 交互与更新问题排查

事件不触发与更新不生效比显示问题更隐蔽，因为图表看起来一切正常。本节给两类问题的成因清单。



#### 事件不触发的原因

**事件失灵**：是绑定的事件回调不执行的现象，多数成因与实例身份和触发条件有关。

- 实例被重建后旧监听随实例销毁：组件里先 dispose 再重新 init 的路径，事件要重新绑定，封装层统一处理。
- 绑定在错误的实例上： getInstanceByDom 拿到的实例与业务代码持有的实例不是同一个，常见于重复 init 后引用未同步。
- mouseout 后立即重绑导致回调丢失：on 与 off 配对写错，off 用了不同函数引用等于没解绑。
- silent 模式的 setOption 不触发更新类事件；图表容器被上层透明元素挡住时鼠标事件根本到不了图表。
- 事件类型名写错不报错也不触发（如把 legendselectchanged 写成 legendselected 后期待切换时机），核对事件名拼写。

```js
// 解绑必须用同一函数引用
const onClick = (params) => handle(params);
chart.on('click', onClick);
chart.off('click', onClick);
```

**速记**：失灵查三处——实例身份是否换人、容器是否被挡、on 与 off 引用是否一致，事件名逐一核对。



#### 更新后图表未变化

**更新无效**：是调用了 setOption 但画面没有变化的现象，成因集中在合并语义与数据引用两处。

- 数据引用未变：传入与上次相同的对象，部分场景会被跳过；构造新数组或浅拷贝后再传。
- 合并语义误解：以为传短数组会清掉旧内容，实际按索引合并，动态增删要用 replaceMerge，见本主题第 26 篇。
- 更新传错了轴：改了 series 数据但类目轴 data 未同步，新数据被旧类目错位呈现或不可见。
- 同帧多次 setOption 相互覆盖，最后一次以外全部白调，需要合并时用 lazyUpdate 或先在内存拼好完整配置。
- 组件卸载后对已销毁实例调用 setOption 抛错被上层吞掉，画面停在最后一帧，检查实例存活性。

```js
// 引用未变的典型坑：push 后直接传同一数组
values.push(nextValue);
chart.setOption({ series: [{ data: values }] });        // 部分版本可能跳过
chart.setOption({ series: [{ data: values.slice() }] }); // 拷贝后再传
```

> [!NOTE]
> **提醒内容**：更新无效时在 setOption 前打印即将传入的对象做快照，与上一次对比；「传了但没生效」与「根本没传对」各占一半，快照对比能直接区分两种情况。

**速记**：更新无效查四条——引用是否新造、合并语义是否误解、轴数据是否同步、实例是否还活着。



### 内存与稳定性

长时间运行的图表页面（监控大屏、值班看板）对稳定性的要求高于一切。本节收束内存问题的排查方法与大屏场景的运行实践。



#### 内存问题的定位方法

**内存定位**：是用堆快照与计数曲线把「页面越跑越慢」落到具体对象上的方法，图表页的泄漏源高度集中。

- 泄漏源前三名：未 dispose 的实例、未 off 的事件回调、未 clear 的定时器，检查清单见本主题第 22 篇。
- 堆快照对比：切换十次视图后拍两次快照，对比 ECharts 实例与 DOM 节点的增量，数量只增不减即泄漏。
- 路由切换泄漏快于首页累积，用「进出同一页面十次」作为标准压测动作。
- 事件监听泄漏的间接信号：一次图例切换触发了多次联动回调，说明旧实例的监听还活着。
- 已确认泄漏但来源不明时，二分法逐段注释业务代码定位，成本高但收敛快。

```text
标准压测动作：进入页面 → 交互十次 → 离开 → 重复十轮
核对项：
1. 实例数量（getInstanceByDom 可达实例）应归零或恒定
2. 定时器数量应归零
3. 堆内存应回落到基线附近
```

**速记**：泄漏三源对照第 22 篇清单，进出页面十轮压测拍快照，联动回调重复执行是监听残留的信号。



#### 长时间运行页面的实践

**常驻页面实践**：是监控大屏这类 7 乘 24 运行页面的稳定性措施，目标是周级不重启。

- 定时自愈：按小时级周期重新 setOption 完整配置并 resize，清掉长期运行累积的渲染状态漂移。
- 数据窗口恒定：实时曲线只用固定窗口（见本主题第 26 篇窗口滚动），任何只增不减的数组都是定时炸弹。
- 动画降级：常驻页面把入场动画关掉、更新动画缩短，减少无信息量的绘制开销。
- 异常兜底：轮询与推送回调的异常全部捕获上报，避免一次接口异常中断整条更新链路。
- 工控机与浏览器内核偏旧时，功能按最低配置验收，不要按开发机表现上线。

```js
// 常驻页面的小时级自愈
setInterval(() => {
  if (document.hidden) return;
  chart.setOption(buildFullOption(latestData), { notMerge: true });
  chart.resize();
}, 60 * 60 * 1000);
```

> [!TIP]
> **建议内容**：大屏交付前做一次「过夜测试」：页面连续运行一晚后核对帧率、内存与数据时间戳，三项都健康再谈上线；过夜测试暴露的问题（内存缓涨、时间停摆、动画卡死）在短时验收里全部不可见。

**速记**：常驻页面靠恒定窗口、动画降级、异常兜底与周期自愈，交付前过夜测试是硬验收。



#### 版本升级的回归检查

**升级回归**：是 ECharts 大版本升级后的验证流程，配置字段与默认值的变化会静默改变线上图表。

- 升级前读官方升级指南，逐条核对项目用到的字段是否在变更列表里。
- 默认值变化不等价于配置迁移：默认主题、默认动画与默认配色在大版本间都会调整，图表视觉需整体过一遍。
- 回归用固定配置集驱动：把项目里出现过的图表形态配置沉淀为样例集，升级后批量渲染人工核对。
- 升级先在预发环境全量观察，重点核对第 27 篇排查清单里的显示与交互两类症状。
- 锁定版本号与锁文件，避免依赖声明漂移引入非计划的版本变化。

```text
升级回归清单：
1. 官方升级指南逐条对照项目配置
2. 固定样例集批量渲染，人工核对视觉
3. 显示问题与交互问题两类症状清单过一遍
4. 性能指标（首屏、单次更新耗时）前后对比
5. 预发全量观察后再进生产
```

**速记**：升级先读指南再过样例集，默认值变化与配置迁移分开核，性能指标前后对比，预发观察后再上。
