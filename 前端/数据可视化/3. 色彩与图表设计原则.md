## 色彩与图表设计原则

### 色彩属性与色彩空间

配色不是审美偏好，而是在给定色彩模型下做参数选择。本节先拆解色彩的三个属性，再比较常用色彩空间，说明各自适合的场合。

#### 色相、饱和度与明度

**色相（hue）**：是色彩在色环上的角度位置，决定它是红、黄还是蓝；**饱和度（saturation）**：是色彩的鲜艳程度；**明度（lightness）**：是色彩的明暗程度。

- 色相：取值通常为 0 至 360 度，首尾相接形成色环。
- 饱和度：取值通常为 0 至 100，为零时表现为灰度。
- 明度：取值通常为 0 至 100，为零时接近黑、为百时接近白。
- 三者的分工：色相用于区分类别，明度用于承载顺序，饱和度用于强调。
- 图表中的用法：同一系列的深浅常靠明度拉开，不同系列靠色相区分。

```css
/* 用 HSL 描述一组图表用色：色相区分系列，明度拉开层次 */
.series-a { color: hsl(210 60% 45%); }
.series-b { color: hsl(30 75% 50%); }
.series-c { color: hsl(140 40% 40%); }
.grid-line { color: hsl(210 10% 90%); }
```

> 明度是三个属性中区分能力最强的，把明度留给顺序、把色相留给类别，是配色最稳妥的分工。

**速记**：色相区分类别，明度承载顺序，饱和度用于强调，三者分工不可混用。



#### RGB 与 HSL 的差异

**RGB 色彩模型**：是以红、绿、蓝三个通道的加色叠加强度描述颜色；**HSL 色彩模型**：是以色相、饱和度、明度三个属性描述颜色，是 RGB 的柱面坐标变换。

- 直观程度：HSL 更贴近「调一个浅一点的蓝」这类操作意图。
- 计算方式：RGB 直接对应屏幕通道，HSL 需要经过变换才能得到通道值。
- 均匀程度：两者都不是感知均匀的，明度相同不代表看起来一样亮。
- 选型建议：手写主题色用 HSL 便于微调，参与计算与渲染时回落为 RGB。
- 注意事项：HSL 的明度是几何量，不是人眼感知的亮度。

> 同一个 HSL 明度值配上不同色相，实际观感亮度差别明显。

**速记**：RGB 面向通道、HSL 面向调色直觉，二者都不感知均匀。



#### 感知均匀的色彩空间

**感知均匀色彩空间**：是让数值距离与人眼感知差异近似成正比的色彩空间，代表为 CIE Lab、LCH 与较新的 OKLab、OKLCH。

- Lab 与 LCH：以亮度、色度、色相描述，色度轴在感知上更均匀。
- OKLab 与 OKLCH：在 Lab 基础上修正了蓝色区域的偏差，明度取值多为 0 至 1。
- 插值收益：在这类空间里做渐变，不会出现中间段发灰或发紫的问题。
- 顺序色收益：按其亮度轴取步长，相邻色阶的感知距离更接近。
- 现实限制：渲染与设计工具仍以 sRGB 为主，需要转换后使用。

> 在 sRGB 里对两端的颜色做线性插值，中间往往经过不期望的色相，改用感知均匀空间可直接规避。

**速记**：Lab、LCH 与 OKLCH 让数值距离接近感知差异，渐变与色阶应在其亮度轴上取步长。



#### 色彩空间的选择依据

**选择依据**：是按任务在直观调色、感知均匀与设备通道三种需求之间取舍，允许同一套主题混用不同空间。

- 调主题色：用 HSL 直观微调色相、饱和度与明度。
- 生成色阶：用 OKLCH 或 LCH 在亮度轴均匀取点。
- 计算对比度：用 sRGB 转换到相对亮度后按标准公式计算。
- 参与渲染：最终回落为 RGB 或十六进制值交给浏览器。
- 混用原则：同一套配色只在必要处转换，避免反复往返造成累积误差。

```js
// 色阶生成：在感知均匀空间的亮度轴上等距取点（示意流程）
function buildUniformSteps(baseHue, chroma, steps = 5) {
  return Array.from({ length: steps }, (_, index) => {
    const lightness = 0.9 - (index * 0.6) / (steps - 1); // OKLCH 亮度 0-1
    return `oklch(${lightness.toFixed(2)} ${chroma} ${baseHue})`;
  });
}
```

> 浏览器对较新色彩函数的支持仍在演进，用于生产前需确认目标环境，或转换为 sRGB 后输出。

**速记**：调色用 HSL、生成色阶用 OKLCH、算对比度用 sRGB，最终以 RGB 输出。



### 配色方案的类型与生成

配色方案按数据类型的顺序结构分为分类色、顺序色与发散色三类。本节说明每一类的构造约束与生成方法。

#### 分类色的构造

**分类色（categorical palette）**：是用于区分离散类别的颜色集合，要求各色在感知上彼此可辨且不暗示顺序。

- 色相分散：相邻类别的色相拉开足够距离，避免两组看起来同色。
- 明度接近：各类别的明度与饱和度保持接近。
- 数量上限：可稳定区分的类别数有限，通常控制在八到十以内。
- 超限处理：类别过多时改用分组、小倍数分面或交互筛选。
- 复用原则：同一类别在同一页面内始终使用同一颜色。

```js
// 分类色：色相分散、明度接近，不暗含顺序
const categoricalPalette = [
  "#4c78a8", "#f58518", "#54a24b",
  "#b279a2", "#e45756", "#72b7b2"
];
```

> 分类色一旦被排成由浅到深，就会被读出顺序，红色也常被误读为负向或警示，需要谨慎分配。

**速记**：分类色色相分散、明度接近、数量有限，同一类别在全站复用同一色。



#### 顺序色的构造

**顺序色（sequential palette）**：是用于表达有大小或强弱之分的连续量的单色渐变色阶，要求明度单调变化。

- 单调明度：从浅到深或从深到浅，明度必须单向变化。
- 单色相为主：以一个色相为主，可在暗端略微偏移色相增加层次。
- 步数选择：离散分级通常取五到七级，连续填充可取更多步。
- 零值处理：需要强调零值时，浅端应接近背景而非纯白。
- 常见误用：把顺序色用于无序分类，会暗示不存在的顺序。

```js
// 顺序色：固定色相与饱和度，按明度单调取步长
function buildSequentialRamp(hue, saturation, steps = 5) {
  return Array.from({ length: steps }, (_, index) => {
    const lightness = 90 - (index * 70) / (steps - 1);
    return `hsl(${hue} ${saturation}% ${lightness}%)`;
  });
}
```

> 顺序色的判断标准只有一条：明度是否单调，其余审美偏好都排在后面。

**速记**：顺序色以单色相为主、明度单调，五到七级便于区分，不可用于无序分类。



#### 发散色的构造

**发散色（diverging palette）**：是用于表达有明确中点、两端方向相反的数据的双向渐变色阶，要求中点为中性色且两翼对称。

- 中点语义：中点必须对应一个真实的中性值，如零、基准值或平均值。
- 两翼对称：两侧的明度变化与色相跨度应保持对称，避免一侧更醒目。
- 中间过渡：中点附近降低饱和度直至中性，形成清晰的视觉分界。
- 适用数据：同比增长率、温差、偏离基准的差值。
- 常见误用：给没有中点的占比数据套用发散色，会凭空制造基准。

```js
// 发散色：两端色相对称，中点为中性灰
function buildDivergingRamp(lowHue, highHue, steps = 7) {
  const middle = (steps - 1) / 2;
  return Array.from({ length: steps }, (_, index) => {
    const offset = index - middle;
    const hue = offset < 0 ? lowHue : highHue;
    const lightness = 92 - Math.abs(offset) * 9;
    const saturation = Math.abs(offset) * 14; // 中点为 0，得到中性灰
    return `hsl(${hue} ${saturation}% ${lightness}%)`;
  });
}
```

> [!TIP]
> **建议内容**：只有当数据存在明确中性基准时才使用发散色，否则改用两套独立的顺序色分别表达两端。

**速记**：发散色中点必须是中性色且对应真实基准，两翼对称，无中点不用发散色。



#### 调色板的生成方法

**调色板生成**：是从品牌色或基准色出发，按色彩空间与步长规则推导出一整套可用颜色的过程。

- 锚定基准：先确定品牌主色或一个稳定色相作为基准。
- 派生分类色：在色环上等距取若干色相，统一明度与饱和度。
- 派生顺序色：固定色相，在感知均匀空间的亮度轴上等距取点。
- 派生发散色：把两个互补色相分别放在中性点两侧，对称取点。
- 工具辅助：可用调色板工具与对比度检查工具产出初稿，再手工校正关键色。

> 机械生成的调色板只是初稿，仍需按对比度与色觉障碍模拟逐色复核后才能进入主题。

**速记**：调色板从基准色派生，分类等分色环、顺序走亮度轴、发散对称取两端。



### 配色实践与可访问性

配色最终要在真实屏幕上被读到。本节给出对比度阈值、色觉障碍对策与冗余编码方法，把可读性从主观判断变为可验证指标。

#### 对比度与可读性阈值

**对比度（contrast ratio）**：是两个颜色的相对亮度之比，按国际通行的无障碍准则取值，正文文本通常要求达到 4.5 比 1。

- 相对亮度：把每个通道转换到线性空间后按感知权重加权。
- 阈值：正文文本 4.5 比 1，大字文本与界面元素 3 比 1。
- 更高档：面向严格场景时正文可要求 7 比 1。
- 图表适用：轴标签、图例与数值标注都应按文本标准校验。
- 常见问题：浅灰网格文字、彩色底上的白字最容易不达标。

```js
function channelToLinear(value8bit) {
  const channel = value8bit / 255;
  return channel <= 0.03928 ? channel / 12.92 : Math.pow((channel + 0.055) / 1.055, 2.4);
}

function relativeLuminance([r, g, b]) {
  return 0.2126 * channelToLinear(r) + 0.7152 * channelToLinear(g) + 0.0722 * channelToLinear(b);
}

function contrastRatio(rgbA, rgbB) {
  const light = Math.max(relativeLuminance(rgbA), relativeLuminance(rgbB));
  const dark = Math.min(relativeLuminance(rgbA), relativeLuminance(rgbB));
  return (light + 0.05) / (dark + 0.05); // 4.5 以上满足正文要求
}
```

```bash
# 对比度自查输出（正文阈值 4.5，界面元素阈值 3）
# #1f1f1f on #ffffff  ->  16.48  pass
# #767676 on #ffffff  ->   4.54  pass
# #9a9a9a on #ffffff  ->   2.81  fail
```

> 对比度是可计算指标，配色评审时应给出实测值而非主观评价。

**速记**：正文对比度需 4.5 比 1、大字与界面元素需 3 比 1，配色评审要看实测值。



#### 色觉障碍与应对

**色觉障碍（color vision deficiency）**：是视网膜视锥细胞对特定波长敏感度下降导致的辨色差异，最常见的是红绿色觉障碍。

- 常见类型：红色型、绿色型与蓝黄色型，前两类合计占绝大多数。
- 人群比例：在男性中较为常见，女性比例显著更低。
- 影响：依赖色相区分的图例与热力图最容易被误读。
- 对策一：用明度差异替代部分色相差异，保证灰度下仍可区分。
- 对策二：同时提供形状、纹理或直接标注，形成冗余编码。

```js
// 为每个类别同时指定颜色与图案，色觉障碍下仍可区分
const seriesStyle = [
  { color: "#4c78a8", pattern: "solid" },
  { color: "#f58518", pattern: "diagonal" },
  { color: "#54a24b", pattern: "dots" }
];
```

> [!WARNING]
> **警告内容**：只靠颜色区分类别会让部分阅读者完全无法分辨系列，必须叠加明度、形状或直接标注中的至少一种。

**速记**：红绿色觉障碍最常见，类别区分不能只靠色相，需叠明度、形状或直接标注。



#### 冗余编码与图案辅助

**图案辅助**：是用实线、虚线、点阵与斜纹等填充纹理补充颜色差异的做法，使图形在没有颜色信息时依然可读。

- 线条：实线、虚线、点线用于区分折线系列。
- 填充：纯色、斜纹、点阵、网格用于区分面积与柱形。
- 标记：圆点、方块、三角用于区分散点类别。
- 灰度校验：把图表转为灰度后仍能区分，是冗余是否成立的检验方法。
- 成本：图案会降低填充的视觉纯度，类别数不宜过多。

```js
// 直接标注：把系列名写在末端，替代图例中的颜色检索
const directLabel = {
  show: true,
  position: "end",
  formatter: (series) => series.name
};
```

> [!IMPORTANT]
> **重要内容**：把图表转为灰度再做一次检查，是验证配色与冗余是否达标的最低成本方法，交付前必须执行。

**速记**：图案辅助用线型、填充与标记补充颜色，灰度检查通过才算冗余成立。



#### 深浅主题与上下文配色

**主题配色**：是配色的深色、浅色两套外观方案；**上下文配色**：是图表在所处容器与页面底色影响下的最终取色。

- 浅色主题：背景接近纯白，轴线用浅灰，文字用近黑。
- 深色主题：背景接近深灰而非纯黑，避免高对比刺眼，文字用近白。
- 反转注意：深浅切换时系列色需重新校验对比度，不能直接沿用。
- 容器影响：卡片底色、渐变背景与遮罩都会改变实际对比度。
- 一致性：同一页面内不要混用两套主题的同类元素。

```css
:root {
  --viz-color-text: #1f1f1f;
  --viz-color-muted: #767676;
  --viz-color-grid: #e6e6e6;
}

[data-theme="dark"] {
  --viz-color-text: #f5f5f5;
  --viz-color-muted: #b0b0b0;
  --viz-color-grid: #3a3a3a;
}
```

> 深色主题下的图表不是把浅色主题取反，而是一套需要在深底上重新校验的配色。

**速记**：深浅主题各需独立校验对比度，实际对比度受容器底色影响，不可直接取反。



### 版式与图表元素设计

色彩之外，图表的可读性还取决于文字、轴、图例与留白的组织。本节按元素的阅读顺序说明版式原则。

#### 标题、副标题与注释

**标题层级**：是按信息重要度组织图表文字的结构，通常由主标题、副标题与数据注释三级构成。

- 主标题：一句话说明图表回答的问题或结论，不重复轴与图例已有的信息。
- 副标题：补充口径、单位、时间范围与数据来源。
- 数据注释：直接标出关键拐点、异常值或阈值线。
- 位置：标题左对齐更利于快速定位，居中适合展示型场景。
- 常见问题：标题只写指标名，阅读者需要自行推断结论。

```js
// 图表文字层级的组织方式
const chartText = {
  title: "华东区营收连续三月回升",
  subtitle: "口径：含税收入，2026 年 1 月至 9 月",
  annotations: [{ at: "2026-06", text: "渠道调整上线" }]
};
```

> 主标题承担结论，副标题承担口径，注释承担细节，三者各司其职，不要互相替代。

**速记**：主标题写结论、副标题写口径、注释标关键点，左对齐更便于快速定位。



#### 坐标轴、刻度与网格线

**坐标轴**：是承载位置通道的参考基准；**网格线**：是帮助估读数值的辅助线，二者都应以克制为原则。

- 轴范围：数值轴从零开始，确需放大时明确标注。
- 刻度数量：控制在四到八个，避免密集刻度挤压标签。
- 刻度格式：大数用千分位或万、亿单位，比率标明百分比。
- 网格线：用浅色细线，只保留与刻度对齐的主网格。
- 轴与网格取舍：空间紧张时可去掉网格线，保留轴与标签。

```js
// 坐标轴的样式约束（示意字段名，具体以所用库为准）
const axisStyle = {
  axisLine: { show: true, color: "#d9d9d9" },
  splitLine: { show: true, color: "#f0f0f0" },
  splitNumber: 5,
  label: { color: "#595959", formatter: formatTick }
};

function formatTick(value) {
  return value >= 10000 ? `${value / 10000} 万` : String(value);
}
```

> 网格线是参照物而非主角，颜色重过数据线时说明视觉层级被颠倒。

**速记**：轴从零开始、刻度四到八个、标签带单位，网格线用浅色细线且不抢数据。



#### 图例与直接标注

**图例（legend）**：是把颜色或形状映射回类别名称的元素；**直接标注**：是把名称直接写在图形就近位置的做法。

- 图例位置：放在阅读动线的起点或终点，不遮挡数据。
- 直接标注：系列较少时优先直接标注，省去来回检索。
- 交互：图例可支持点击隐藏系列，但要提供恢复全部的方式。
- 顺序一致：图例顺序与堆叠顺序、类别排序保持统一。
- 冗余配合：图例中的色块可加形状或线型，与图形保持一致。

> 图例与直接标注不必二选一：关键系列直接标注，其余系列保留图例。

**速记**：少系列直接标注、多系列用图例，图例顺序与堆叠顺序保持一致。



#### 提示框、留白与整体节奏

**提示框（tooltip）**：是悬停或点击时显示单点详细数值的浮层；**留白**：是图表四周与元素之间的空白，用于区分层级与引导视线。

- 提示框内容：给出数值、单位与上下文，避免只显示裸数字。
- 提示框行为：靠近边缘时自动翻转，避免被容器裁切。
- 留白作用：区分标题区、绘图区与说明区，比例约为一比八比一。
- 密度控制：一屏图表数量与信息量要匹配，宁可分页不硬塞。
- 节奏：主图占据视觉重心，辅助图退居其后。

```js
// 提示框内容组织：数值加单位与上下文
const tooltipConfig = {
  show: true,
  formatter: (point) => `${point.seriesName}：${point.value} 万元`,
  confine: true // 防止浮层被容器裁切
};
```

> [!CAUTION]
> **注意内容**：把大量图表塞进一屏会稀释每张图的注意力，降低图表数量往往比增加图表更能提升信息传达效率。

**速记**：提示框给数值加单位、边缘自动翻转，留白区分层级，图表数量服从注意力预算。



### 设计规范落地

配色与版式只有固化为规范才能在多人协作中保持一致。本节给出令牌、主题封装与评审流程的落地方式。

#### 设计令牌与主题变量

**设计令牌（design token）**：是颜色、字号、间距等设计决策的具名变量，是设计与代码之间的共同契约。

- 命名分层：按用途命名而非按外观命名，如文本色、网格色、强调色。
- 语义映射：系列色、状态色、背景色各有独立令牌。
- 单一来源：同一取值只在一处定义，其余位置引用变量，改一处即可全站生效。
- 主题切换：深浅主题通过覆盖同一组变量的取值实现。

```css
:root {
  --viz-color-text: #1f1f1f;
  --viz-color-muted: #767676;
  --viz-color-series-1: #4c78a8;
  --viz-font-size-axis: 12px;
  --viz-gap: 8px;
  --viz-radius: 4px;
}
```

> 令牌按用途命名后，换一套配色只改变量取值，图形代码完全不用改动。

**速记**：设计令牌按用途命名、单一来源定义，主题切换靠覆盖同一组变量实现。



#### 图表主题的封装

**图表主题**：是把令牌组装成图表库可消费的配置对象，用于统一所有图表的默认外观。

- 组装内容：调色板、文字样式、轴线与网格样式、背景与提示框样式。
- 注册方式：多数图表库提供主题注册接口，具体签名以所用版本文档为准。
- 分级覆盖：提供全局主题加局部覆盖两层机制，应对特殊图表。
- 交付形态：主题以独立模块发布，避免与业务组件耦合。
- 版本管理：主题变更视同视觉规范变更，需要走评审。

```json
{
  "palette": { "categorical": ["#4c78a8", "#f58518", "#54a24b"] },
  "axis": { "lineColor": "#d9d9d9", "labelColor": "#595959" },
  "grid": { "color": "#f0f0f0" }
}
```

> 主题封装的边界是「默认值」：它统一外观，但不替业务决定用哪种图形。

**速记**：主题把令牌组装为库可消费的配置，提供全局加局部两级覆盖，独立于业务组件。



#### 一致性与审查清单

**一致性审查**：是按固定清单核对图表是否偏离设计规范的流程，把主观评审转化为可逐项勾选的检查。

- 颜色：是否全部取自令牌，是否存在硬编码色值。
- 对比度：文字与界面元素是否达到阈值，灰度下能否区分。
- 文字：标题、副标题与注释是否齐备，字号层级是否统一。
- 轴与网格：轴范围、刻度数量与标签格式是否合规。
- 交互：提示框、图例与直接标注是否互相冲突。
- 数据诚实：坐标轴是否从零开始，有无截断与双轴误导。

```bash
# 图表交付前的配色与版式自查
# 1 色值是否全部来自令牌
# 2 文本对比度是否达到 4.5
# 3 灰度下类别是否仍可区分
# 4 轴是否从零开始、刻度是否超标
# 5 提示框与图例是否冲突
```

> 清单的价值在于可重复执行，评审应逐条勾选而不是凭整体印象给结论。

**速记**：一致性审查按颜色、对比度、文字、轴网格、交互与数据诚实逐项勾选。



#### 交付与评审流程

**交付流程**：是把主题、图表与说明一起交给使用方的过程，强调可复现与可追溯。

- 交付物：主题模块、图表组件、示例页与设计说明。
- 示例页：覆盖常见图表类型，作为视觉回归的基准。
- 变更记录：记录主题版本与每次调整的原因。
- 评审环节：设计、前端与数据三方共同确认后再合入。
- 回归检查：主题升级后对示例页做视觉回归，防止意外改色。

> [!IMPORTANT]
> **重要内容**：主题是跨团队共享的视觉契约，任何改动都要同步示例页与变更记录，避免使用方在无感知的情况下被改色。

**速记**：交付含主题、组件、示例页与说明，变更需三方评审并做视觉回归。
