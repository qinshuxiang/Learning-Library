## WebGL 与 GPU 渲染基础

WebGL 把 GPU 的并行计算能力暴露给浏览器，代价是绘制全程的状态与数据都要自行组织。本篇先界定 WebGL 是什么与适用边界，再依次展开渲染管线、着色器语言、缓冲区与绘制调用、纹理与坐标映射，最后给出常见坑与降级方案。基于 Three.js 的高层用法详见本主题第 10 篇 Three.js 三维可视化入门。

### WebGL 是什么与适用边界

WebGL 面向的是「图元数量大、需要自定义计算」的绘制任务。本节给出定义与来路，说明它与 Canvas 2D 的根本差别，并划出适用范围。

#### WebGL 的定义与来路

**WebGL（Web Graphics Library，网页图形库）**：是浏览器基于 OpenGL ES 规范暴露的一套底层图形接口，通过 JavaScript 向 GPU 提交顶点数据、着色器程序与绘制指令，由 GPU 完成变换与着色后写入画布。

- 规范来源：以 OpenGL ES 2.0 为蓝本，裁剪桌面级特性以适配浏览器的沙箱与安全模型。
- 获取方式：在 canvas 元素上调用 getContext(contextType, options)，contextType 传 webgl 或 webgl2。
- 版本差异：WebGL 2 对应 OpenGL ES 3.0，着色器语法与纹理能力更强，可按目标浏览器选择。
- 能力定位：只提供绘制原语与 GPU 计算通道，不提供场景图、相机、材质等高层抽象。
- 调用代价：JavaScript 与 GPU 之间的每次交互都有开销，反复切换状态尤其昂贵。

```js
const canvas = document.getElementById("stage");
const gl = canvas.getContext("webgl2") || canvas.getContext("webgl");
if (!gl) {
  throw new Error("当前环境不支持 WebGL");
}
// gl 是后续所有绘制调用的入口对象
```

**速记**：WebGL 是浏览器调用 GPU 的底层接口，源于 OpenGL ES，只给原语不给场景抽象。



#### 与 Canvas 2D 的根本差别

**Canvas 2D 上下文**：是浏览器提供的立即模式绘图接口，每次调用就直接在当前画布上产生像素；WebGL 则把数据与状态先提交给 GPU，由 GPU 在绘制调用时统一处理整批图元。

- 执行位置：Canvas 2D 的绘制指令主要在 CPU 上逐条执行，WebGL 把顶点变换与像素着色交给 GPU 并行执行。
- 数据组织：Canvas 2D 每次绘制当场传入坐标，WebGL 先把顶点写入缓冲区再一次性提交。
- 状态模型：Canvas 2D 的状态是画笔属性，影响后续绘制；WebGL 的状态是全局开关，改错一处会波及之后的所有绘制。
- 绘制粒度：Canvas 2D 的调用次数即绘制次数，WebGL 的绘制次数由绘制调用决定，一次调用可以覆盖成千上万个三角形。
- 事件模型：Canvas 2D 可以按图元做命中检测，WebGL 画布是一个整体，命中检测需要在 JavaScript 侧自行计算。

```js
// Canvas 2D：一次调用绘制一个圆
ctx.beginPath();
ctx.arc(120, 80, 24, 0, Math.PI * 2);
ctx.fill();

// WebGL：先把成千上万个顶点写入缓冲区，再一次性绘制
gl.drawArrays(gl.POINTS, 0, pointCount);
```

> 两者不是新旧替代关系：图元少、需要与 DOM 事件紧密配合时，Canvas 2D 仍然是更省事的选择。

**速记**：Canvas 2D 逐条立即绘制，WebGL 批量提交给 GPU 并行处理，状态模型与事件模型都不同。



#### 适用边界与不适用场景

**适用边界**：是判断一项可视化需求该不该动用 WebGL 的取舍标准，核心在图元规模、是否需要三维投影、是否需要自定义像素计算三点。

- 适合：数万级以上的散点与折线、需要三维投影或透视、需要自定义光照与后处理、需要把图像处理搬到 GPU。
- 不适合：几十到几百个图元的普通图表，用 SVG 或 Canvas 2D 表达更清晰。
- 不适合：需要为每个图元单独绑定原生事件的交互，改在 JavaScript 侧做命中检测反而增加工作量。
- 成本：着色器、缓冲区、矩阵变换、上下文丢失都要自行处理，调试手段也少于普通网页。

```html
<canvas id="stage" width="800" height="600"></canvas>
```

> [!CAUTION]
> **注意内容**：把只有几十个点的图表改写成 WebGL，往往复杂度上升而性能收益接近于零，应先做规模估算再决定技术路线。

**速记**：图元规模大、要三维投影或自定义计算才用 WebGL，小规模图表用 SVG 或 Canvas 2D 更划算。



### 渲染管线

渲染管线是数据从 JavaScript 到屏幕像素所经过的固定流程。GPU 按自己的节奏执行这段流程，理解各阶段的分工是排查绘制异常的前提。

#### 渲染管线的阶段划分

**渲染管线（rendering pipeline）**：是 GPU 处理一次绘制任务的固定流程，输入是顶点数据与着色器程序，输出是画布上的像素颜色，中间依次经过顶点处理、图元装配、光栅化与片元处理。

- 顶点阶段：对每个顶点独立执行顶点着色器，完成坐标变换与属性传递。
- 装配阶段：把顶点按绘制模式组合成点、线或三角形等图元。
- 光栅化阶段：把图元覆盖到的区域离散成一个个片元，并插值顶点间变化的量。
- 片元阶段：对每个片元执行片元着色器，算出颜色与深度，再经过测试决定是否写入画布。
- 并行性：顶点之间、片元之间互不影响，GPU 用大量核心同时处理，这是相对 CPU 绘制的根本优势。

```js
// 一次绘制任务在 JavaScript 侧的准备顺序
const program = initShaderProgram(gl, vertexSource, fragmentSource);
createBuffer(gl, vertices);
gl.useProgram(program);
gl.drawArrays(gl.TRIANGLES, 0, vertices.length / 2);
// 之后由 GPU 按管线阶段自行推进
```

> 管线中只有顶点着色器与片元着色器可被替换，其余阶段由 GPU 固定实现，能干预的只有数据与这两个着色器。

**速记**：渲染管线是顶点处理、图元装配、光栅化、片元处理四段流程，仅两段着色器可由开发者替换。



#### 顶点处理与图元装配

**顶点着色器（vertex shader）**：是对每个顶点执行一次、负责计算最终位置与输出属性的程序；**图元装配**：是把处理后的顶点按绘制模式组合成基本图形。

- 输入：每个顶点的位置、颜色、纹理坐标等属性，由缓冲区提供。
- 职责：把模型坐标依次乘以模型矩阵、视图矩阵、投影矩阵，得到裁剪空间坐标。
- 输出：位置写入内置变量 gl_Position，其余需要传给片元的量写入 varying 变量。
- 装配模式：绘制模式决定顶点如何成组，常用 TRIANGLES、LINES、POINTS。
- 顶点数量：顶点着色器对每个顶点各执行一次，顶点数越多这一阶段的总工作量越大。

```glsl
attribute vec2 aPosition;
attribute float aValue;

uniform mat4 uProjection;
uniform float uMaxValue;

varying float vRatio;

void main() {
  vRatio = aValue / uMaxValue;
  gl_Position = uProjection * vec4(aPosition, 0.0, 1.0);
}
```

> [!IMPORTANT]
> **重要内容**：顶点着色器只输出位置与待插值的量，颜色计算应尽量交给片元着色器，避免在顶点阶段做逐顶点无法体现的细节。

**速记**：顶点着色器逐顶点算变换并输出 gl_Position，图元装配按绘制模式把顶点组合成基本图形。



#### 光栅化与片元处理

**光栅化（rasterization）**：是把连续的图元离散成与屏幕像素对应的片元，并在图元内部对 varying 变量做线性插值；**片元着色器（fragment shader）**：是对每个片元执行一次、决定该像素最终颜色的程序。

- 插值：顶点着色器输出的 varying 会在片元位置按重心坐标插值，得到逐像素变化的量。
- 计算：片元着色器据此算出颜色，可再叠加纹理采样与光照公式。
- 测试：片元要经过深度测试与模板测试，通过后才写入颜色缓冲区。
- 丢弃：片元着色器可以显式丢弃片元，用于实现镂空或自定义裁剪。
- 开销：片元数量与图元覆盖的像素面积成正比，大面积半透明重叠最容易拖慢帧率。

```glsl
precision mediump float;

uniform float uOpacity;
varying float vRatio;

void main() {
  // 取值越大越偏暖色，透明度由外部统一控制
  vec3 cold = vec3(0.20, 0.45, 0.85);
  vec3 warm = vec3(0.90, 0.35, 0.20);
  gl_FragColor = vec4(mix(cold, warm, vRatio), uOpacity);
}
```

> 逐顶点与逐像素的差别决定了图形细节：渐变、光照这类需要平滑变化的量放在片元着色器里效果更自然。

**速记**：光栅化把图元离散成片元并插值，片元着色器逐像素定色，再经深度测试决定是否写入。



### 着色器语言入门

着色器用 GLSL 编写，成对存在、编译链接后才可运行。本节给出语言的基本约定、数据类型与三类变量限定符。

#### 顶点着色器与片元着色器的配对

**GLSL（OpenGL Shading Language，着色器语言）**：是一种面向 GPU 的类 C 语言，顶点着色器与片元着色器各写一份，经过编译、链接成为可用的着色器程序。

- 成对存在：一个着色器程序至少包含一个顶点着色器与一个片元着色器。
- 编译流程：createShader(type) 创建对象，shaderSource(shader, source) 送入源码，compileShader(shader) 编译。
- 链接流程：createProgram() 建程序，attachShader(program, shader) 挂上着色器，linkProgram(program) 链接。
- 生效方式：调用 useProgram(program) 后，后续绘制才使用这套着色器。
- 报错排查：编译与链接都可能失败，必须读取信息日志才能定位到具体行。

```glsl
// 顶点着色器
attribute vec2 aPosition;

void main() {
  gl_Position = vec4(aPosition, 0.0, 1.0);
}
```

```glsl
// 片元着色器
precision mediump float;

void main() {
  gl_FragColor = vec4(0.20, 0.45, 0.85, 1.0);
}
```

```js
// 编译与链接成程序
const program = gl.createProgram();
gl.attachShader(program, vertexShader);
gl.attachShader(program, fragmentShader);
gl.linkProgram(program);
if (!gl.getProgramParameter(program, gl.LINK_STATUS)) {
  throw new Error(gl.getProgramInfoLog(program));
}
gl.useProgram(program);
```

> [!WARNING]
> **警告内容**：着色器编译失败不会抛异常，只是创建出无效对象，必须主动查询编译与链接状态并打印日志，否则表现为画面全黑而毫无报错。

**速记**：GLSL 着色器成对编译链接成程序，启用程序后绘制才生效，失败信息必须主动读取。



#### GLSL 的数据类型与精度限定符

**精度限定符**：是 GLSL 中声明浮点数最小精度与取值范围的修饰词，片元着色器必须显式声明浮点精度，否则编译报错。

- 基本类型：float、int、bool，向量有 vec2、vec3、vec4，矩阵有 mat2、mat3、mat4。
- 采样器：sampler2D 用于在片元着色器中读取二维纹理。
- 精度三档：lowp、mediump、highp 依次提高精度，同时增加计算开销。
- 声明位置：精度限定符写在类型之前，也可用 precision 语句为整个着色器设定默认值。
- 兼容性：桌面端 highp 通常可用，移动端需按设备能力判断，拿不准时用 mediump。

```glsl
precision mediump float;

uniform sampler2D uTexture;
varying vec2 vTexCoord;

void main() {
  vec4 color = texture2D(uTexture, vTexCoord);
  gl_FragColor = color;
}
```

> 精度不是越高越好：移动端把整体精度提到 highp 会明显增加耗电与发热，逐片元的开销尤其敏感。

**速记**：GLSL 用 float、vec、mat 与 sampler2D 表达数据，片元着色器必须声明浮点精度，精度越高越费。



#### attribute、uniform 与 varying 的分工

三类变量限定符决定数据从何而来、在管线中如何流动：attribute 逐顶点输入，uniform 全局常量，varying 从顶点阶段传向片元阶段。

- attribute：逐顶点不同，只在顶点着色器中使用，数据来自缓冲区。
- uniform：一次绘制内所有顶点与片元取同一值，顶点与片元着色器都可读取。
- varying：由顶点着色器写入、片元着色器读取，中间经过光栅化插值。
- 绑定位置：attribute 需用 getAttribLocation 取得索引，uniform 用 getUniformLocation 取得位置。
- 赋值接口：uniform 通过 uniform 系列方法写入，矩阵用 uniformMatrix4fv(location, transpose, value) 上传。

```js
const positionLocation = gl.getAttribLocation(program, "aPosition");
const projectionLocation = gl.getUniformLocation(program, "uProjection");

gl.vertexAttribPointer(positionLocation, 2, gl.FLOAT, false, 0, 0);
gl.enableVertexAttribArray(positionLocation);
gl.uniformMatrix4fv(projectionLocation, false, projectionMatrix);
```

> 命名约定：attribute 常以 a 开头，uniform 以 u 开头，varying 以 v 开头，便于在两种着色器之间对照数据流向。

**速记**：attribute 逐顶点自缓冲区进入，uniform 整批绘制共享，varying 经插值从顶点传向片元。



### 缓冲区与绘制调用

数据要从 JavaScript 进入 GPU，必须先放进缓冲区并绑定到顶点属性上。本节说明缓冲区的创建、数据上传、属性绑定与两类绘制调用。

#### 缓冲区对象与数据上传

**缓冲区对象（buffer object）**：是 GPU 侧的一段显存，用于存放顶点位置、颜色、纹理坐标等属性数据；数据上传后绘制时不再需要重复传输。

- 创建：createBuffer() 返回缓冲区对象。
- 绑定：bindBuffer(target, buffer) 把对象绑定到当前目标，target 常用 ARRAY_BUFFER。
- 上传：bufferData(target, data, usage) 把类型化数组写入显存，usage 描述读写频率。
- 频次提示：STATIC_DRAW 表示几乎不变，DYNAMIC_DRAW 表示会频繁改写。

```js
// 每个点两个坐标，共 pointCount 个点
const positions = new Float32Array(pointCount * 2);

const buffer = gl.createBuffer();
gl.bindBuffer(gl.ARRAY_BUFFER, buffer);
gl.bufferData(gl.ARRAY_BUFFER, positions, gl.STATIC_DRAW);
// 类型化数组一次性上传，之后绘制直接读取显存
```

> 上传是同步拷贝，数据量大时会有可观耗时；能一次传完就不要拆成多次，动态数据才考虑分块更新。

**速记**：缓冲区对象是 GPU 侧的显存片段，创建、绑定后用 bufferData 上传类型化数组。



#### 顶点属性指针与启用属性

**顶点属性指针**：是描述「缓冲区里的哪一段数据对应哪个顶点属性、其分量数与步长是多少」的描述符，由 vertexAttribPointer(index, size, type, normalized, stride, offset) 设置。

- index：属性索引，来自 getAttribLocation。
- size：每个顶点的分量数，位置通常为 2 或 3。
- type：分量类型，常用 gl.FLOAT。
- stride：相邻两个顶点起始位置之间的字节数，紧密排列时为 0。
- offset：该属性在本顶点数据内的字节偏移，交错存放时用于跳到对应字段。

```js
// 交错存放：每顶点 x、y、value 三个 float
const stride = 3 * Float32Array.BYTES_PER_ELEMENT;

gl.vertexAttribPointer(positionLocation, 2, gl.FLOAT, false, stride, 0);
gl.enableVertexAttribArray(positionLocation);

gl.vertexAttribPointer(valueLocation, 1, gl.FLOAT, false, stride, 2 * Float32Array.BYTES_PER_ELEMENT);
gl.enableVertexAttribArray(valueLocation);
```

> [!NOTE]
> **提醒内容**：vertexAttribPointer 生效的前提是该属性已通过 enableVertexAttribArray 启用，只设置不启用是空白画面的常见原因。

**速记**：顶点属性指针用索引、分量数、类型、步长与偏移描述取数方式，设置后必须启用对应属性。



#### 绘制调用的两种形式

**绘制调用**：是真正触发 GPU 执行管线的指令，分为按序读取的 drawArrays(mode, first, count) 与按索引读取的 drawElements(mode, count, type, offset) 两种。

- drawArrays：从缓冲区起始按顺序取顶点，顶点无复用，写法简单。
- drawElements：额外读取索引缓冲区，相同顶点可被多个图元复用，显存更省。
- 索引上传：索引需以 ELEMENT_ARRAY_BUFFER 为目标单独绑定与上传。
- 适用判断：共享顶点多时用 drawElements，点云这类顶点基本不共享时用 drawArrays。
- 绘制前设置：用 gl.viewport(x, y, width, height) 指定绘制区域，用 gl.clearColor(red, green, blue, alpha) 设定清除色后调用 clear 清空画布。

```js
// 无复用：按顺序绘制 pointCount 个点
gl.drawArrays(gl.POINTS, 0, pointCount);

// 有复用：用索引缓冲区绘制三角形
gl.bindBuffer(gl.ELEMENT_ARRAY_BUFFER, indexBuffer);
gl.drawElements(gl.TRIANGLES, indexCount, gl.UNSIGNED_SHORT, 0);
```

> 两种调用的差别只在取顶点的方式，绘制模式与后续管线阶段完全一致。

**速记**：drawArrays 顺序取顶点，drawElements 靠索引复用顶点，后者更省显存但需另建索引缓冲区。



### 纹理与坐标映射

纹理是把图像或数据当作二维表贴到图元上的手段，常用于底图、渐变与逐点符号。本节说明纹理的创建上传、坐标映射与参数设置。

#### 纹理的创建与上传

**纹理对象（texture object）**：是 GPU 侧存放图像数据及其他采样相关设置的对象，通过 texImage2D 把像素数据上传，采样时按纹理坐标取值。

- 创建与绑定：createTexture() 建对象，bindTexture(gl.TEXTURE_2D, texture) 绑定。
- 上传：texImage2D(target, level, internalFormat, format, type, source) 把图像或类型化数组写入纹理。
- 多纹理：activeTexture(gl.TEXTURE0) 选择纹理单元，再绑定不同纹理，着色器用不同采样器读取。
- 单元数量：可用单元数有上限，逐片元用到的纹理数不能超过设备限制。
- 数据来源：可以是图片元素、画布或直接构造的像素数组。

```js
const texture = gl.createTexture();
gl.bindTexture(gl.TEXTURE_2D, texture);
gl.texImage2D(gl.TEXTURE_2D, 0, gl.RGBA, gl.RGBA, gl.UNSIGNED_BYTE, image);

// 第二个纹理绑定到单元 1
gl.activeTexture(gl.TEXTURE1);
gl.bindTexture(gl.TEXTURE_2D, secondTexture);
```

> 纹理单元是采样入口而非存储本体，同一纹理可以绑定到不同单元，切换的是采样通道。

**速记**：纹理对象经 createTexture 创建、bindTexture 绑定、texImage2D 上传，activeTexture 选择采样单元。



#### 纹理坐标与采样

**纹理坐标**：是取值范围为 0 到 1 的二维坐标，用 (s, t) 表示，独立于纹理的像素尺寸，用于在图元表面定位采样位置。

- 原点位置：纹理坐标原点在纹理左下角，而图像行序通常自顶向下，首次使用常出现上下颠倒。
- 采样方式：片元着色器用 sampler2D 声明的变量配合 texture2D(sampler, coord) 取值。
- 传递方式：纹理坐标由 attribute 进入顶点着色器，作为 varying 传给片元着色器插值。
- 映射关系：坐标范围固定为 0 到 1，与纹理实际宽高无关，换图不必改坐标。
- 越界处理：超出 0 到 1 的坐标由纹理参数决定是重复还是钳制。

```glsl
attribute vec2 aTexCoord;

varying vec2 vTexCoord;

void main() {
  vTexCoord = aTexCoord;
  gl_Position = vec4(aPosition, 0.0, 1.0);
}
```

> 上传图片纹理时先把 UNPACK_FLIP_Y_WEBGL 设为 true，或把顶点里的纹理坐标上下翻转，可避免图像上下颠倒。

**速记**：纹理坐标取值 0 到 1、原点在左下角，经 varying 插值后在片元着色器里采样，换图不必改坐标。



#### 纹理参数与常见问题

**纹理参数**：是控制采样超出范围与缩放时取值的设置，通过 texParameteri(target, pname, param) 逐项指定。

- 环绕方式：TEXTURE_WRAP_S 与 TEXTURE_WRAP_T 设为 REPEAT 或 CLAMP_TO_EDGE，决定越界坐标的行为。
- 缩小过滤：纹理被缩小时用 TEXTURE_MIN_FILTER 指定取样方式。
- 放大过滤：纹理被放大时用 TEXTURE_MAG_FILTER 指定取样方式。
- 尺寸约束：非二次幂尺寸的纹理不能用重复环绕，也不能生成多级渐远纹理。
- 常见问题：图像翻转、纹理边缘渗色、纹理不显示，多数由环绕方式、过滤方式或坐标映射错误引起。

```js
gl.bindTexture(gl.TEXTURE_2D, texture);
gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_WRAP_S, gl.CLAMP_TO_EDGE);
gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_WRAP_T, gl.CLAMP_TO_EDGE);
gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_MIN_FILTER, gl.LINEAR);
```

> 纹理不显示时先确认三件事：纹理是否已上传数据、采样器是否指向正确的纹理单元、纹理坐标是否落在 0 到 1 内。

**速记**：纹理参数控制越界环绕与缩放过滤，非二次幂纹理只能钳制，边缘渗色与不显示多由参数与坐标引起。



### 常见坑与降级方案

WebGL 的错误常表现为画面全黑而不报错，排查依赖对上下文与状态的把握。本节给出上下文处理、状态与性能常见坑，以及降级策略。

#### 上下文获取与丢失处理

**WebGL 上下文（context）**：是承载全部显存对象与状态的环境，通过 canvas 的 getContext 取得，可能因资源紧张或系统切换而被浏览器回收。

- 获取失败：设备或浏览器不支持时 getContext 返回空值，必须先判断再使用。
- 上下文丢失：触发 webglcontextlost 事件后，所有缓冲区、纹理与程序都失效。
- 恢复流程：监听 webglcontextrestored，重新创建全部 GPU 资源并重绘。
- 释放资源：deleteBuffer、deleteTexture、deleteProgram 可主动回收，销毁组件时不可遗漏。
- 丢失开关：可在丢失事件中取消默认行为，浏览器才会尝试恢复上下文。

```js
canvas.addEventListener("webglcontextlost", (event) => {
  event.preventDefault();
  isContextLost = true;
});

canvas.addEventListener("webglcontextrestored", () => {
  initShaderProgram(gl, vertexSource, fragmentSource);
  createBuffer(gl, vertices);
  isContextLost = false;
  renderScene();
});
```

> [!WARNING]
> **警告内容**：上下文丢失后旧的缓冲区与纹理句柄全部失效，若不重建资源就继续绘制，画面会保持空白且不产生任何报错。

**速记**：上下文可能获取失败也可能被浏览器回收，丢失后必须重建全部 GPU 资源并重新绘制。



#### 状态管理与性能常见坑

**状态管理**：是控制 WebGL 全局开关的过程，包括当前程序、绑定缓冲区、启用属性与混合模式，状态残留是画面错乱的主要来源。

- 残留问题：上一个绘制遗留的绑定或启用会污染下一次绘制，尤其在同一画布上画多组数据时。
- 切换代价：频繁切换着色器程序、纹理与缓冲区会打断 GPU 的批处理，开销远高于一次绘制本身。
- 逐帧上传：每帧都重新 bufferData 上传大量静态数据最耗性能，静态数据应只传一次。
- 同步等待：readPixels 会把 GPU 结果读回 CPU 并造成同步等待，交互路径上应避免频繁调用。

```js
// 反例：每帧重新上传不变的静态数据
// gl.bufferData(gl.ARRAY_BUFFER, positions, gl.STATIC_DRAW); // 静态数据无需逐帧上传

// 正例：静态数据只上传一次，逐帧只改 uniform 与绘制参数
gl.uniform1f(timeLocation, elapsedSeconds);
gl.drawArrays(gl.POINTS, 0, pointCount);
```

> 优化顺序是先合并绘制与减少状态切换，再考虑减少逐帧上传，最后才调精度与细节，顺序颠倒往往收效甚微。

**速记**：状态残留会污染后续绘制，状态切换与逐帧上传是主要开销，静态数据只上传一次。



#### 特性检测与降级策略

**降级策略**：是在设备不支持 WebGL 或性能不足时改用其他渲染方案，保证内容始终可见，而不是直接报错或留白。

- 能力检测：先判断 getContext 返回值，再按需检测浮点纹理、最大纹理尺寸等扩展。
- 版本降级：优先取 webgl2，失败再取 webgl，两者都失败才进入后续方案。
- 渲染降级：改用 Canvas 2D 绘制降采样后的数据，或改用 SVG 只保留关键图元。
- 数据降级：按设备能力抽取一部分数据点绘制，并明确提示已做抽样。
- 提示兜底：无法绘制时给出文字说明与数据表，保证信息可达。

```js
function createRenderer(canvas) {
  const gl = canvas.getContext("webgl2") || canvas.getContext("webgl");
  if (gl) {
    return { kind: "webgl", context: gl };
  }
  const ctx = canvas.getContext("2d");
  if (ctx) {
    return { kind: "canvas2d", context: ctx };
  }
  return { kind: "none", context: null };
}
```

> 降级方案要与主方案共用同一份数据模型，切换渲染层时只替换绘制代码，不改数据结构。

**速记**：先检测能力再选渲染层，依次降级到 Canvas 2D、SVG 或抽样数据，最后用文字与数据表兜底。
