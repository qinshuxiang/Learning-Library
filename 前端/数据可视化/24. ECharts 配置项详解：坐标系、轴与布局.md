## ECharts 配置项详解：坐标系、轴与布局

第 14 篇拆过 option 的顶层结构，本篇往里走一层，把直角坐标系下最常被配置也最常出错的部分讲透：grid 决定图形画在哪，坐标轴决定数值怎么映射到位置，axisPointer 决定悬停时读数怎么对齐。这三层理解到位后，大多数「图形画歪了」「刻度不对」「提示框错位」的问题都能自行定位。

### 直角坐标系的网格布局 grid

grid 是直角坐标系的绘图区域，轴、图形与分割线都画在它划定的矩形之内。本节覆盖 grid 的定位方式、多 grid 布局与系列归属关系。



#### grid 的定位方式

**grid 定位**：是用 left、right、top、bottom 与 width、height 描述绘图区域位置与尺寸的配置方式，取值支持像素、百分比与方位关键字。

- 四边距写法最常用，left 与 bottom 给足标签空间，其余方向从紧。
- containLabel 为 true 时边距把轴标签的占位计算在内，是防止长标签被裁切的首选手段。
- 百分比写法相对容器尺寸，响应式布局下比固定像素更稳。
- width 与 height 显式给定尺寸后，对应方向的 left 与 top 决定起点位置，适合多 grid 精确排布。
- grid 默认不含边框，show 为 true 后可显示背景与边框，调试布局时可临时打开确认区域边界。

```js
chart.setOption({
  grid: {
    left: 24,
    right: 24,
    top: 56,
    bottom: 16,
    containLabel: true,
    show: true,
    borderColor: '#ccc'
  },
  xAxis: { type: 'category', data: ['一月', '二月', '三月', '四月'] },
  yAxis: { type: 'value' },
  series: [{ type: 'bar', data: [120, 200, 150, 80] }]
});
```

> containLabel 只解决标签占位，轴名（name）与图例不参与计算，顶部放轴名时 top 仍需自行留白。

**速记**：grid 用四边距定位，containLabel 吸收标签占位，调试期可开 show 看边界。



#### 多 grid 布局

**多 grid（multiple grids）**：是在一个实例里划出多个绘图区域、各自挂一套坐标轴的布局方式，grid 写成数组即可启用。

- 每个 grid 是数组的一项，按声明顺序得到索引 0、1、2。
- 轴通过 xAxisIndex 与 yAxisIndex 挂到指定 grid，每个 grid 至少要有一对轴。
- 典型场景是上下两块共享横轴：上面画价格折线、下面画成交量柱状，两块区域高度按需分配。
- 空间分配用 top 与 height（或百分比）显式写死，不依赖默认值，否则两块区域容易重叠。
- 大屏与联动分析页常用多 grid，交互联动配置见本篇 axisPointer 与第 15 篇 connect 的相关内容。

```js
chart.setOption({
  grid: [
    { left: 56, right: 24, top: 40, height: '55%' },
    { left: 56, right: 24, top: '72%', height: '20%' }
  ],
  xAxis: [
    { type: 'category', gridIndex: 0, data: ['周一', '周二', '周三', '周四', '周五'], axisLabel: { show: false } },
    { type: 'category', gridIndex: 1, data: ['周一', '周二', '周三', '周四', '周五'] }
  ],
  yAxis: [
    { type: 'value', gridIndex: 0, name: '价格' },
    { type: 'value', gridIndex: 1, name: '成交量' }
  ],
  series: [
    { type: 'line', xAxisIndex: 0, yAxisIndex: 0, data: [18, 19, 17, 21, 20] },
    { type: 'bar', xAxisIndex: 1, yAxisIndex: 1, data: [820, 932, 901, 1290, 1130] }
  ]
});
```

**速记**：grid 写数组即多布局，轴用 gridIndex 挂区域、系列用轴索引挂轴，空间显式分配防重叠。



#### 系列与坐标系的绑定关系

**绑定关系**：是系列通过索引字段确定自己使用哪个坐标系实例的规则，理解它可以解释大多数「图去哪儿了」的问题。

- 系列的 xAxisIndex 与 yAxisIndex 缺省为 0，单 grid 页面无需关心这两个字段。
- 多轴页面系列挂错轴的症状是图形消失或比例异常，先核对索引再查数据。
- 与直角坐标系并列的还有极坐标、地理坐标、日历坐标等，系列用 coordinateSystem 字段切换，缺省按类型推断。
- 多 grid 时 series 数组里的每个系列独立指定索引，同一个系列只能属于一个坐标系。
- 增删 grid 后要同步检查轴索引与系列索引，索引错位是合并更新场景下的高发问题。

```js
// 系列、轴、grid 的三层索引链
// series[i].xAxisIndex → xAxis[j].gridIndex → grid[j]
series: [
  { type: 'line', xAxisIndex: 0, yAxisIndex: 0, data: [1, 2, 3] },
  { type: 'bar', xAxisIndex: 1, yAxisIndex: 1, data: [4, 5, 6] }
]
```

> [!NOTE]
> **提醒内容**：用 setOption 增量更新增减 grid 与轴时，索引引用不会自动重排，整体替换（notMerge 为 true）比手工维护索引更不易出错。

**速记**：系列经轴索引挂到 grid，缺省全为 0，增删布局时核对整条索引链或整体替换。



### 类目轴与数值轴

坐标轴的 type 决定数据到位置的映射方式，选错 type 是刻度与图形异常的第一大原因。本节按类目轴、数值轴、时间轴与对数轴四类展开。



#### 类目轴的标签处理

**类目轴（category axis）**：是把离散类目均匀分布在轴上的坐标轴类型，每个类目占据等宽的一格。

- data 数组的顺序就是类目顺序，需要按数值排序时应先排数据再喂给轴。
- boundaryGap 为 true 时柱子落在格子中间（柱状图默认），为 false 时点落在刻度线上（折线图默认）。
- 类目多时 axisLabel.interval 取 auto 自动抽稀，或设为数值指定步长；interval 为 0 表示全显示。
- 长标签用 rotate 旋转、formatter 截断或改条形图，axisLabel.hideOverlap 可隐藏互相重叠的标签。
- 类目轴的刻度与数据一一对应，增删数据要同步更新轴的 data，合并更新时只传 series 数据不会改轴。

```js
chart.setOption({
  xAxis: {
    type: 'category',
    data: ['一月', '二月', '三月', '四月', '五月', '六月'],
    boundaryGap: true,
    axisLabel: {
      interval: 0,
      rotate: 30,
      hideOverlap: true,
      formatter: (value) => (value.length > 4 ? value.slice(0, 4) + '…' : value)
    }
  },
  yAxis: { type: 'value' },
  series: [{ type: 'bar', data: [120, 200, 150, 80, 170, 110] }]
});
```

**速记**：类目轴等分格位，标签靠 interval、rotate、hideOverlap 与 formatter 疏解，改数据要连轴 data 一起改。



#### 数值轴的范围控制

**数值轴（value axis）**：是把连续数值线性映射到轴上的坐标轴类型，范围默认由数据自动推导。

- 默认范围包含零且向外取整；scale 为 true 时轴不强制包含零，数据集中在高位时图形差异更明显。
- min 与 max 显式指定范围，业务有固定口径（如百分制 0 到 100）时必须写死而不是依赖自动推导。
- min 与 max 也接受回调，按数据动态计算范围，适合数据窗口变化的场景。
- splitNumber 建议分割段数，是参考值不是精确值，最终刻度由算法取整。
- 范围写得比数据最小值还大，图形会被裁掉，改范围后核对极值是否仍在轴内。

```js
chart.setOption({
  yAxis: {
    type: 'value',
    min: 0,
    max: 100,
    interval: 20,
    axisLabel: { formatter: '{value} 分' }
  },
  xAxis: { type: 'category', data: ['甲', '乙', '丙', '丁'] },
  series: [{ type: 'bar', data: [86, 72, 91, 65] }]
});
```

> [!WARNING]
> **警告内容**：数值轴不强制包含零（scale 为 true 或显式指定不含零的范围）会放大差异的视觉效果，柱状图这类以长度编码数值的图形尤其敏感；柱状图应当包含零起点，折线图在说明口径的前提下可以不包含。

**速记**：数值轴默认含零，scale 与显式范围能放大差异，柱状图必须含零，固定口径写死 min 与 max。



#### 时间轴与对数轴

**时间轴（time axis）**：是按时间连续分布数据点的坐标轴类型；**对数轴（log axis）**：是按对数刻度映射数值的坐标轴类型。

- 时间轴接受时间戳、日期字符串或 Date 对象，间隔不均的数据按真实时间定位，不会被均匀拉开。
- 时间轴的 axisLabel.formatter 按轴算法生成的刻度格式化，常用模板如 {yyyy}-{MM}-{dd}。
- 对数轴的基用 logBase 设置，常用 10；数据含零或负值时对数轴无定义，须先清洗数据。
- 对数轴适合数量级跨度大的数据（如多省份的确诊病例数），不适合普通对比场景。
- 两类轴都可与 dataZoom 组合使用，时间轴缩放按时间窗口取数，见本主题第 15 篇 dataZoom 相关内容。

```js
chart.setOption({
  xAxis: { type: 'time', axisLabel: { formatter: '{MM}-{dd}' } },
  yAxis: { type: 'log', logBase: 10 },
  series: [{
    type: 'line',
    data: [
      ['2026-09-01', 120], ['2026-09-08', 950],
      ['2026-09-15', 4300], ['2026-09-22', 21000]
    ]
  }]
});
```

**速记**：时间数据用时间轴按真实间隔定位，跨度大用对数轴，对数轴容不下零与负值。



### 轴的样式与格式化

轴的可读性由三件东西决定：线与刻度画不画、标签怎么格式化、轴名怎么标注。本节按这三件事展开，全部配置都在轴对象的子字段内。



#### 轴线、刻度与分割线

**轴线（axisLine）**：是坐标轴本体的线；**刻度（axisTick）**：是轴线上的短标记；**分割线（splitLine）**：是横穿绘图区、对齐刻度值的参考线。

- 类目轴的轴线与刻度通常保留，数值轴的轴线可去掉、只留分割线，画面更干净。
- splitLine 默认显示，颜色宜淡；alignWithLabel 让刻度对准标签中心。
- 多轴共用绘图区时只保留一套 splitLine，每根轴都画会叠加成网格噪声。
- 刻度数量由 splitNumber 或 interval 间接控制，密集的细刻度没有读数价值。
- 轴样式遵循「减法原则」：能去掉又不损失读数的元素一律去掉。

```js
chart.setOption({
  xAxis: {
    type: 'category',
    data: ['一月', '二月', '三月', '四月'],
    axisLine: { show: true, lineStyle: { color: '#999' } },
    axisTick: { alignWithLabel: true }
  },
  yAxis: {
    type: 'value',
    axisLine: { show: false },
    axisTick: { show: false },
    splitLine: { lineStyle: { color: '#eee' } }
  },
  series: [{ type: 'line', data: [120, 200, 150, 80] }]
});
```

**速记**：类目轴留线与刻度，数值轴去轴留分割线，多轴只留一套分割线。



#### axisLabel 的 formatter 体系

**axisLabel.formatter**：是把轴刻度值转换为显示文本的函数或模板，是轴上唯一该做「数据到文案换算」的地方。

- 模板字符串支持 {value} 占位；函数形式接收刻度值返回字符串，逻辑复杂时用函数。
- 单位写在轴名或轴标签里，不要在系列 tooltip 与轴标签两处用不同口径。
- 大数值缩写（如万、亿）在 formatter 内换算，并保证与 tooltip 的换算一致。
- 时间轴与类目轴的 formatter 入参不同：时间轴给的是时间值，类目轴给的是类目文本。
- 富文本 rich 可在轴标签内混排样式，写法见本主题第 14 篇 标签、富文本与视觉映射。

```js
yAxis: {
  type: 'value',
  axisLabel: {
    formatter: (value) => (value >= 10000 ? value / 10000 + '万' : value)
  }
}
```

> [!TIP]
> **建议内容**：轴标签与 tooltip 的数值换算逻辑应抽成同一个函数复用，两处口径不一致（如一处万、一处原值）是评审与对账时最常被抓到的问题。

**速记**：formatter 是轴上唯一的数据到文案换算点，复杂逻辑用函数，与 tooltip 共用同一套换算。



#### 轴名与单位标注

**轴名（name）**：是显示在轴端、说明轴含义或单位的文字，由 name、nameLocation 与 nameGap 控制。

- 轴名默认显示在轴端上方，nameLocation 取 middle 时居中显示在轴侧，适合放完整单位。
- 单位与量级写在轴名里（如「销售额（万元）」），轴标签只放数值。
- nameTextStyle 控制轴名字体，颜色比轴标签略淡以区分主次。
- 双轴图两根轴都要有轴名，缺轴名的双轴图无法判断折线读的是哪根轴。
- 轴名占位不参与 containLabel 计算，顶部与左侧放轴名时边距要手动留足。

```js
yAxis: {
  type: 'value',
  name: '销售额（万元）',
  nameLocation: 'middle',
  nameGap: 44,
  nameTextStyle: { color: '#666', fontSize: 12 }
}
```

**速记**：单位进轴名不放标签，双轴必须各有轴名，轴名占位自己留边距。



### axisPointer 与多轴联动读数

axisPointer 是悬停时的指示与读数组件，单独图表上它跟随 tooltip，多 grid 与多实例场景下它负责把多个图的读数对齐。本节覆盖它的类型、跨 grid 联动与常见错位排查。



#### axisPointer 的类型与配置

**axisPointer**：是悬停时显示在坐标轴上的指示器，type 取 line、shadow、cross 或 none，可配在全局、单轴或 tooltip 上。

- 全局 axisPointer 配置作为各轴的默认值，单轴可单独覆盖。
- line 画竖线、shadow 铺色块，柱状图配 shadow、折线图配 line 是常规搭配。
- cross 提供十字与坐标读数，适合散点图等需要精确读两个维度的场合。
- label 字段控制指示器上的数值标签，snap 为 true 时自动吸附到最近的数据点。
- tooltip 的 axisPointer 字段等价于单图层面的快捷配置，两处都写时以 tooltip 内的为准。

```js
chart.setOption({
  axisPointer: { snap: true, label: { backgroundColor: '#5b8ff9' } },
  tooltip: { trigger: 'axis', axisPointer: { type: 'shadow' } },
  xAxis: { type: 'category', data: ['一月', '二月', '三月', '四月'] },
  yAxis: { type: 'value' },
  series: [{ type: 'bar', data: [120, 200, 150, 80] }]
});
```

**速记**：柱配 shadow、线配 line、散点配 cross，全局配置做默认、tooltip 内的可覆盖。



#### 跨 grid 与跨实例联动

**联动读数**：是让多个绘图区域或多个图表实例的 axisPointer 同步移动的机制，多 grid 用 link，多实例用 connect。

- 全局 axisPointer.link 写轴引用数组，如 [{ xAxisIndex: 'all' }]，让多块 grid 的横轴指示同步。
- link 后悬停任一 grid，其余 grid 的指示器与数值标签同步显示，适合价格与成交量这类上下联读的布局。
- 多个独立实例的联动用 echarts.connect 接收实例数组或分组名，做法见本主题第 15 篇 connect 联动与 dataZoom、brush。
- 联动的轴类目必须对得上，横轴类目不一致时同步指示的读数没有意义。
- 联动只同步指示与缩放窗口，不合并各图的数据，数据口径仍由各系列自己负责。

```js
chart.setOption({
  axisPointer: { link: [{ xAxisIndex: 'all' }], label: { backgroundColor: '#777' } },
  grid: [
    { left: 56, right: 24, top: 40, height: '50%' },
    { left: 56, right: 24, top: '68%', height: '24%' }
  ],
  xAxis: [
    { type: 'category', gridIndex: 0, data: ['周一', '周二', '周三', '周四', '周五'] },
    { type: 'category', gridIndex: 1, data: ['周一', '周二', '周三', '周四', '周五'] }
  ],
  yAxis: [{ type: 'value', gridIndex: 0 }, { type: 'value', gridIndex: 1 }],
  series: [
    { type: 'line', xAxisIndex: 0, yAxisIndex: 0, data: [18, 19, 17, 21, 20] },
    { type: 'bar', xAxisIndex: 1, yAxisIndex: 1, data: [820, 932, 901, 1290, 1130] }
  ]
});
```

**速记**：多 grid 联动写 axisPointer.link，多实例联动用 connect，联动的轴类目必须一致。



#### 读数错位的排查

**读数错位**：是悬停指示与数值标签对不上数据点的现象，成因集中在轴配置与触发方式上。

- 指示器落在两刻度之间却不吸附：开 snap 或检查轴是否用了不匹配的 type。
- tooltip 触发方式写错：trigger 为 item 时按图形项触发，不会出现按轴汇总的指示，与 axis 轴触发表现混淆是常见原因。
- 多 grid 下 link 没写或写错索引，只有单块区域出现指示，属配置遗漏而非缺陷。
- 类目轴 data 与系列 data 长度不一致时，指示位置与数据点错开，先核对两侧长度。
- 合并更新后轴被重建而指示器状态残留，出现一次错位后自动恢复的，多为更新时机问题，见本主题第 26 篇合并语义。

```js
// 排查错位的最小核对清单
// 1. 轴 type 与数据类型匹配
// 2. 类目轴 data 与各系列 data 等长
// 3. tooltip trigger 为 axis
// 4. 多 grid 时 link 的轴索引正确
```

> [!NOTE]
> **提醒内容**：读数错位先核对配置四项，再怀疑数据；绝大多数错位来自轴 data 与系列 data 不等长，合并更新场景下这条尤其高发。

**速记**：错位先查四项——轴类型、数据等长、触发方式、联动索引，配置核对完再看数据。
