## Canvas 动画与交互

### 动画循环与时间控制

Canvas 没有内置动画，每一帧都要由脚本重新绘制。本节讲动画循环的驱动方式、基于时间差的运动，以及如何正确地启动与停止动画。

#### requestAnimationFrame 的基本用法

**动画帧回调**：是浏览器在下一帧绘制前调用的函数，requestAnimationFrame(callback) 注册回调并返回一个标识，callback 接收一个高精度时间戳参数，表示该帧的开始时间。

- 调用时机：回调在下一次重绘之前执行，浏览器会按显示器刷新率调度，通常在每秒 60 次上下。
- 返回值：每次调用返回一个唯一标识，可用于取消这次注册。
- 时间戳参数：单位是毫秒，表示从页面时间起点到本帧开始的时长，不用来取系统日期。
- 每帧重注册：回调只执行一次，动画要持续，必须在回调里再次调用 requestAnimationFrame。

```js
let frameId = 0;

function animate(timestamp) {
  drawFrame(timestamp);
  frameId = requestAnimationFrame(animate);
}

frameId = requestAnimationFrame(animate);

function drawFrame(timestamp) {
  console.log(timestamp); // 每帧递增的毫秒时间戳
}
```

> [!TIP]
> **建议内容**：持续动画一律用 requestAnimationFrame 串联，不要用 setInterval 或 setTimeout，前者会与浏览器刷新节奏对齐，后台标签页还会自动降频。

**速记**：requestAnimationFrame 在每帧绘制前回调并传入毫秒时间戳，回调只执行一次，要续帧必须重注册。



#### 基于时间差的运动

**时间差（delta time）**：是相邻两帧时间戳的间隔毫秒数，用它乘以速度得到本帧位移，可以让运动速度与帧率无关。

- 逐帧加常数的问题：帧率不同时同一段动画的快慢不一样，帧率越高跑得越快。
- 按时间差推进：位移等于速度乘时间差除以一千，帧率变化时总位移仍然一致。
- 首帧处理：第一帧没有上一帧时间戳，通常把时间差记为 0 或按固定值初始化。
- 时间差上限：标签页切回前台时时间差可能极大，应对其取值设上限避免物体瞬移。

```js
const state = { x: 0, speed: 120, lastTime: 0 }; // speed 单位：像素/秒

function step(timestamp) {
  const delta = state.lastTime === 0 ? 0 : Math.min(timestamp - state.lastTime, 64);
  state.lastTime = timestamp;
  state.x += (state.speed * delta) / 1000;

  ctx.clearRect(0, 0, 320, 240);
  ctx.fillStyle = "#0ea5e9";
  ctx.fillRect(state.x, 100, 40, 40);

  requestAnimationFrame(step);
}
requestAnimationFrame(step);
```

**速记**：以时间差乘速度推进位移，运动速度才与帧率无关，时间差进帧数前要设上限。



#### 启动与停止动画

**启动与停止**：是通过注册与取消动画帧回调控制循环生命周期的方式，cancelAnimationFrame(requestId) 用注册时返回的标识取消尚未执行的回调。

- 保存标识：把每次 requestAnimationFrame 的返回值存入变量，取消时才有据可依。
- 幂等启动：启动前先判断是否已在运行，避免同一动画被重复注册导致速度翻倍。
- 停止方式：在回调内部根据条件提前返回并不再注册，即可让循环自然结束。
- 与销毁配合：组件卸载或画布移除时务必取消动画，否则回调会持续执行并占用资源。

```js
let running = false;
let requestId = 0;

function startAnimation() {
  if (running) return;
  running = true;
  requestId = requestAnimationFrame(loop);
}

function stopAnimation() {
  running = false;
  cancelAnimationFrame(requestId);
}

function loop(timestamp) {
  if (!running) return;
  renderScene(timestamp);
  requestId = requestAnimationFrame(loop);
}

function renderScene(timestamp) {
  // 本帧的绘制逻辑
}
```

**速记**：注册时保存标识，取消用 cancelAnimationFrame，启动要幂等、销毁要取消。



### 缓动与补间

匀速直线运动在图表里显得生硬，数值跳变也需要过渡。本节讲缓动函数的形态与数值补间的实现。

#### 缓动函数的形态

**缓动函数（easing function）**：是把归一化进度映射为另一进度的函数，输入与输出都在 0 到 1 之间，用于改变运动的时间分布而不改变起止位置。

- 线性：easeLinear 直接返回输入进度，速度恒定。
- 缓入：easeInQuad 在起步阶段变化慢，适合物体从静止加速。
- 缓出：easeOutQuad 在收尾阶段变化慢，适合菜单展开与数值滚动。
- 缓入缓出：easeInOutQuad 两端慢、中间快，适合视角与视图切换。

```js
function easeLinear(t) {
  return t;
}

function easeOutQuad(t) {
  return 1 - (1 - t) * (1 - t);
}

console.log(easeOutQuad(0.5)); // 0.75，中点已走完四分之三
```

> 缓动只改变进度随时间的分布，起止值不变；需要超过终点的回弹效果时，改用带回弹的缓动函数即可。

**速记**：缓动函数把 0 到 1 的进度重新分布，缓入起步慢、缓出收尾慢，不改变起止位置。



#### 数值补间与状态推进

**补间（tween）**：是在起止值之间按缓动进度取值的过程，公式为结果等于起点加终点减起点乘以缓动后的进度；**状态推进**：是按时间差累加进度并判断动画是否结束。

- 启动记录：开始补间时记录起点值、终点值、起始时刻与持续时长。
- 进度归一：进度等于已过时长除以总时长，结果截断在 0 到 1 之间。
- 取值方式：用缓动后的进度对数值、点坐标或颜色分量分别插值。
- 结束处理：进度达到 1 时把结果吸附到终点值，避免浮点误差残留。

```js
function createTween(from, to, duration) {
  return { from, to, duration, elapsed: 0, value: from };
}

function advanceTween(tween, delta) {
  tween.elapsed += delta;
  const raw = Math.min(tween.elapsed / tween.duration, 1);
  const eased = easeOutQuad(raw);
  tween.value = tween.from + (tween.to - tween.from) * eased;
  return raw >= 1;
}
// 返回 true 表示补间结束，value 已停在终点
```

> [!NOTE]
> **提醒内容**：补间进度必须按时间差累加，直接按帧数加固定值会让动画时长随帧率漂移。

**速记**：补间记录起止值与时长，进度按时间差归一再用缓动取值，结束时吸附到终点。



#### 按进度驱动状态

**按进度驱动**：是把一个补间进度同时映射到多个属性的写法，适合让位置、透明度与颜色同步过渡。

- 属性分组：把同一进度用于位置、缩放与透明度，动画整体感更强。
- 进度复用：视图切换时常复用一个进度驱动坐标轴、数据点与标注。
- 反向播放：进度从 1 递减到 0 即可得到反向动画，无需另写一套逻辑。
- 中断处理：新动画开始时用当前值作为新起点，可以避免跳变。

```js
function renderTransition(progress) {
  const eased = easeInOutQuad(progress);
  ctx.save();
  ctx.globalAlpha = eased;
  ctx.translate(0, (1 - eased) * 24);
  ctx.drawImage(seriesLayer, 0, 0);
  ctx.restore();
}
// 数据层淡入并向上滑入
```

**速记**：一个进度驱动多个属性可让过渡整齐，反向播放与中断续接都靠复用同一进度实现。



### 命中检测

画布只有一个元素，图元的悬停与点击都要靠坐标计算判断。本节讲几何命中、路径命中与最近点拾取。

#### 矩形与圆形命中

**几何命中**：是用数学判断点是否落在图元范围内的方法，矩形判断点坐标是否同时落在左右上下边界内，圆形判断点到圆心的距离是否不超过半径。

- 矩形判断：分别比较横纵坐标与边界，四个条件同时成立才命中。
- 圆形判断：比较距离平方与半径平方，避免开方运算。
- 坐标来源：鼠标事件给出的是相对页面或视口的坐标，需要换算到画布位图坐标。
- 遍历策略：命中判断通常从后往前遍历，让上层图元优先被命中。

```js
function hitRect(point, rect) {
  return point.x >= rect.x && point.x <= rect.x + rect.width &&
    point.y >= rect.y && point.y <= rect.y + rect.height;
}

function hitCircle(point, circle) {
  const dx = point.x - circle.x;
  const dy = point.y - circle.y;
  return dx * dx + dy * dy <= circle.radius * circle.radius;
}
```

> [!IMPORTANT]
> **重要内容**：鼠标坐标必须先按画布的实际显示尺寸与位图尺寸之比换算，再用设备像素比之外的缩放修正，否则画布被拉伸时命中位置会整体偏移。

**速记**：矩形比边界、圆形比距离平方，命中前先把事件坐标换算到画布坐标系。



#### 路径命中 isPointInPath

**路径命中**：是复用已有路径做几何判断的接口，isPointInPath(x, y) 判断点是否落在当前路径的填充区域内，isPointInStroke(x, y) 判断点是否落在当前路径的描边上。

- 判定依据：前者按填充规则判断内部，后者按线宽判断描边覆盖范围。
- 路径来源：可用当前路径，也可传入 Path2D 对象作为第一个参数指定路径。
- 坐标系：传入的坐标以画布坐标表示，内部结合当前变换换算，判断前应明确当时的变换状态。
- 与填充无关：判断只看路径几何，与 fillStyle、strokeStyle 等外观设置无关。

```js
const region = new Path2D();
region.moveTo(60, 200);
region.lineTo(160, 60);
region.lineTo(260, 200);
region.closePath();

function isInsideTriangle(point) {
  return ctx.isPointInPath(region, point.x, point.y);
}
// 点在三角形内部时返回 true
```

**速记**：isPointInPath 判断内部、isPointInStroke 判断描边，可传入 Path2D 复用几何。



#### 拾取最近数据点

**最近点拾取**：是在全部数据点中找出距指针最近且不超过阈值的一个，用于密集散点与折线的悬停提示。

- 阈值限制：距离超过设定半径时不返回结果，避免指针在空白处也弹提示。
- 换算一致：比较前把指针坐标与数据点都换算到同一坐标系，常用屏幕坐标。
- 性能取舍：点数量很大时逐点比较会拖慢每帧，应先用空间索引或按横坐标二分缩小范围。
- 结果缓存：命中结果与上一帧相同就跳过重绘，减少提示框的更新次数。

```js
function pickNearestPoint(point, points, maxDistance) {
  let best = null;
  let bestDistance = maxDistance;

  for (const candidate of points) {
    const dx = candidate.x - point.x;
    const dy = candidate.y - point.y;
    const distance = Math.sqrt(dx * dx + dy * dy);
    if (distance <= bestDistance) {
      best = candidate;
      bestDistance = distance;
    }
  }
  return best;
}
```

> 拾取阈值应随缩放级别调整：放大视图后点间距离变大，固定阈值会让悬停变得不灵敏。

**速记**：最近点拾取按阈值过滤再取最小距离，点数多时用空间索引，阈值需随缩放调整。



### 视图平移与缩放

折线密集时用户需要拖拽与缩放查看细节，视图状态决定了绘制时的坐标映射。本节讲视图状态、坐标换算与锚点缩放。

#### 视图状态的维护

**视图状态**：是描述画布观察方式的一组值，最小集合为平移量 offsetX、offsetY 与缩放系数 scale，绘制前用它们构建坐标系。

- 状态对象：把三个值放在同一个对象里，便于统一更新与传递。
- 绘制映射：通常先平移到视图偏移，再按缩放系数缩放，之后按数据坐标绘制。
- 缩放范围：为 scale 设上下限，避免缩到不可见或放到失真。
- 状态与绘制分离：视图状态只描述观察参数，绘制函数据此重绘，两者不互相写值。

```js
const view = { offsetX: 0, offsetY: 0, scale: 1 };
const viewLimits = { minScale: 0.5, maxScale: 8 };

function applyView(ctx, view) {
  ctx.setTransform(1, 0, 0, 1, 0, 0);
  ctx.translate(view.offsetX, view.offsetY);
  ctx.scale(view.scale, view.scale);
}

function clampView(view) {
  view.scale = Math.min(Math.max(view.scale, viewLimits.minScale), viewLimits.maxScale);
}
```

**速记**：视图状态由平移量与缩放系数构成，绘制前先平移再缩放，系数必须设上下限。



#### 屏幕坐标与数据坐标换算

**坐标换算**：是在屏幕坐标与数据坐标之间互相转换的过程，换算基于视图状态而非画布尺寸。

- 屏幕转数据：先减去平移量再除以缩放系数，得到数据坐标。
- 数据转屏幕：先乘以缩放系数再加平移量，用于把数据点画到画布上。
- 指针事件：事件坐标先换算到画布位图坐标，再交给屏幕转数据步骤。
- 变换方向：绘制的映射与换算的公式互为逆运算，两者必须一致，否则指针位置与图元错位。

```js
function screenToData(view, canvasPoint) {
  return {
    x: (canvasPoint.x - view.offsetX) / view.scale,
    y: (canvasPoint.y - view.offsetY) / view.scale,
  };
}

function dataToScreen(view, dataPoint) {
  return {
    x: dataPoint.x * view.scale + view.offsetX,
    y: dataPoint.y * view.scale + view.offsetY,
  };
}
```

> [!WARNING]
> **警告内容**：绘制的变换顺序与坐标换算的公式必须完全对应，一旦一处改成先缩放再平移而另一处没改，就会出现指针与图元错位。

**速记**：屏幕转数据是减偏移再除缩放，数据转屏幕是乘缩放再加偏移，两者必须与绘制顺序一致。



#### 缩放锚点与边界约束

**缩放锚点**：是缩放过程中保持屏幕位置不变的那个点，常见做法取指针所在位置，使缩放围绕指针进行。

- 锚点原理：缩放前后让锚点对应的数据坐标不变，据此反解平移量的新值。
- 比例关系：新平移量等于锚点屏幕坐标减去锚点数据坐标与新缩放系数的乘积。
- 拖拽实现：按下时记录起点，移动时用位移量累加到平移量上。
- 边界约束：平移范围可限制在数据包围盒加余量之内，避免把内容拖出视野。

```js
function zoomAt(view, canvasPoint, factor) {
  const before = screenToData(view, canvasPoint);
  view.scale = clampScale(view.scale * factor);
  const after = screenToData(view, canvasPoint);
  view.offsetX += (after.x - before.x) * view.scale;
  view.offsetY += (after.y - before.y) * view.scale;
}

function clampScale(scale) {
  return Math.min(Math.max(scale, viewLimits.minScale), viewLimits.maxScale);
}
```

**速记**：以指针为锚点缩放即保持该点数据坐标不变，反解平移量，拖拽则把位移累加到平移量。



### 帧率与流畅度

动画的流畅度由每帧耗时与刷新节奏共同决定。本节讲帧率与丢帧的判断，以及大数据量下的刷新取舍。

#### 帧率与丢帧的判断

**帧率（frames per second，FPS）**：是每秒完成的绘制帧数，常见目标为 60，对应每帧约 16.7 毫秒的处理预算；**丢帧**：是某帧耗时超过预算导致画面更新被推迟的情况。

- 预算来源：帧率目标决定预算，目标 60 时每帧留给脚本的时间约为 16.7 毫秒。
- 时间差观察：相邻帧时间戳明显大于预算即说明有丢帧。
- 平滑显示：读数取一段时间的平均，避免瞬时值剧烈跳动。
- 与设备相关：刷新率更高的显示器允许更高帧率，测量应基于实际时间戳而非写死 60。

```js
function createFpsMeter() {
  return { frames: 0, elapsed: 0, value: 0 };
}

function updateFps(meter, delta) {
  meter.frames += 1;
  meter.elapsed += delta;
  if (meter.elapsed >= 500) {
    meter.value = Math.round((meter.frames * 1000) / meter.elapsed);
    meter.frames = 0;
    meter.elapsed = 0;
  }
  return meter.value;
}
// 每半秒刷新一次读数
```

> 把帧率读数叠加在画布角落观察即可，不必接入完整监控；先在真实数据量下确认是否掉帧，再决定优化方向。

**速记**：帧率由每帧预算决定，60 帧约合 16.7 毫秒，用相邻时间戳与滚动平均判断丢帧。



#### 分层与增量刷新

**分层刷新**：是按变化频率把画面拆分后分别重绘的策略，静态部分缓存成离屏画布，逐帧只重绘发生变化的部分。

- 静态层：网格、坐标轴与背景预渲染一次，每帧仅做一次合成。
- 动态层：数据点、游标与提示框每帧重绘，内容随交互变化。
- 脏矩形：已知只有局部变化时，只清理并重绘该矩形区域，减少填充量。
- 合成顺序：按背景到前景的顺序叠加，最后一帧提交，中间不展示。

```js
function renderAnimatedFrame(ctx, width, height, pointer) {
  ctx.clearRect(0, 0, width, height);
  ctx.drawImage(staticLayer, 0, 0);
  drawPoints(ctx, visiblePoints);
  drawCrosshair(ctx, pointer);
}
// 每帧只做一次清理、一次合成与两次绘制
```

**速记**：静态层缓存、动态层逐帧重绘，局部变化用脏矩形，合成按背景到前景叠加。



#### 大数据量下的取舍

**大数据量取舍**：是在绘制精度、交互帧率与内存之间取得平衡的做法，核心是减少每帧真正参与绘制的图元数量。

- 视口裁剪：只绘制落在当前视图范围内的数据点，视野外的直接跳过。
- 抽样降密：点数远超像素密度时按步长抽样或聚合，画面上看不出差异。
- 细节分级：缩放级别低时画聚合值，放大后再补充细节。
- 渲染降级：交互过程中用低精度版本保证跟手，停止交互后再绘制完整版本。

```js
function drawVisiblePoints(ctx, points, view, width, height) {
  const step = Math.max(1, Math.ceil(points.length / 4000));
  for (let i = 0; i < points.length; i += step) {
    const screen = dataToScreen(view, points[i]);
    if (screen.x < 0 || screen.x > width || screen.y < 0 || screen.y > height) continue;
    ctx.fillRect(screen.x, screen.y, 2, 2);
  }
}
// 先按步长降密，再剔除视口外的点
```

> [!CAUTION]
> **注意内容**：逐帧对全量数据做命中检测或重排序会直接吃满帧预算，交互期间应先用降密版本响应，空闲时再算精确结果。

**速记**：按视口裁剪、按步长降密、按缩放分级，交互期间用低精度版本保证帧率。
