## 大屏与仪表盘实战

### 大屏场景与约束

大屏与仪表盘都以在确定的显示区域长时间展示同一批指标为共同前提，差别在观看距离、交互方式与运行环境。本节先界定两类场景，再说明分辨率与运行环境带来的硬约束。

#### 大屏与仪表盘的场景差异

**数据大屏（large screen）**：是面向固定安装的显示设备、以远距离整体观感为优先的可视化页面；**仪表盘（dashboard）**：是面向桌面使用者的多指标聚合界面，强调逐项查看、筛选与下钻。

- 观看距离：大屏按数米外的可读性设计字号与信息密度，仪表盘按一臂距离设计。
- 交互方式：大屏以自动轮播与定时刷新为主，仪表盘以筛选、排序与联动为主。
- 布局自由度：大屏按固定设计稿整体缩放，仪表盘必须适应窗口尺寸的连续变化。
- 生命周期：大屏长时间不间断运行，仪表盘随使用者开合页面而启停。

```json
{
  "designWidth": 1920,
  "designHeight": 1080,
  "stage": "large-screen",
  "refreshInterval": 30000,
  "autoPlay": true
}
```

> 两类场景共用同一套图表实现，差异集中在布局策略与交互取舍，后续小节同时覆盖两种情况。

**速记**：大屏看远距离整体观感与自动刷新，仪表盘看近距离逐项交互，二者共用图表实现。



#### 分辨率与拼接屏的约束

**设计分辨率**：是设计稿中假定的横向与纵向像素数，页面按该尺寸排布再整体适配到实际显示设备；**拼接屏（video wall）**：是由多块独立面板拼合而成的显示阵列，面板边缘存在物理边框。

- 常用设计分辨率：1920×1080 与 3840×2160，设计时按现场设备确定并写进配置。
- 有效可视高度：全屏模式下没有地址栏与状态栏，窗口模式下要扣掉浏览器界面占用的高度。
- 拼接边框：面板之间的边框占用像素，跨屏内容会被边框切断，关键信息要避开拼缝。
- 等比保持：适配时横向与纵向比例必须一致，非等比拉伸会让圆形变椭圆、文字变形。

```css
.screen-stage {
  width: 1920px;
  height: 1080px;
}
```

> 拼接屏的输出分辨率不是各面板分辨率之和，还要扣除边框占用的像素，交付前应向现场确认拼接控制器的实际输出参数。

**速记**：设计分辨率写进配置，适配保持等比，关键信息避开拼缝与浏览器界面占用的高度。



#### 运行环境与浏览器限制

**运行环境**：是页面实际运行时所在的浏览器、操作系统与网络条件，大屏环境通常版本固定、无外网且无人值守。

- 版本可控但不一定新：现场机器可能长期不升级浏览器，使用新特性前要确认支持范围。
- 网络受限：内网或离线环境常无法访问外网，公共字体、图标与地图瓦片需本地化。
- 无鼠标交互：大屏不应依赖悬停才能看到的信息，提示内容应默认可见或自动轮播。
- 电池与休眠：现场机器需关闭系统休眠、屏保与自动更新，避免展示过程被系统中断。

> 环境差异是交付后问题的主要来源，本地开发机上的表现不能代表现场表现。

**速记**：现场浏览器版本、网络与交互方式都受限，资源必须本地化，机器必须关闭休眠与更新。



### 自适应布局方案

大屏的显示尺寸在交付前确定，仪表盘的窗口尺寸随时变化，两者需要不同的适配策略。本节给出整体缩放、栅格分栏与图表重绘三类方案。

#### 设计稿等比缩放

**等比缩放（scale to fit）**：是把按设计稿尺寸排布的内容整体缩放到实际视口大小的做法，缩放比例取宽高比例中的较小值，保证内容完整可见且不变形。

- 舞台容器固定为设计稿宽高，内部按普通流或定位排布。
- 缩放比例取视口宽与设计稿宽之比、视口高与设计稿高之比的较小值。
- 变换原点设在左上角，缩放后内容仍从左上角开始，不会偏移出视口。
- 缩放留下的空白用背景色填充，不通过拉伸内容去填满。

```js
function fitStage(stage, designWidth, designHeight) {
  const scale = Math.min(
    window.innerWidth / designWidth,
    window.innerHeight / designHeight
  );
  stage.style.transformOrigin = "left top";
  stage.style.transform = `scale(${scale})`;
  return scale; // 视口 1280×720 时返回 0.6667
}

window.addEventListener("resize", () => {
  fitStage(document.querySelector(".screen-stage"), 1920, 1080);
});
```

> [!CAUTION]
> **注意内容**：整体缩放会把文字一并缩放，缩小比例较大时小字号文本会发虚。核心数值应保留足够大的字号，不能依赖缩放后的小字承担阅读任务。

**速记**：等比缩放按宽高比的较小值整体缩小以保持不变形，代价是小字号会随缩放变虚。



#### 栅格与分栏自适应

**栅格布局（grid layout）**：是把页面横向划分为固定列数、由面板跨列占位的布局方式，缩放方案解决整体尺寸，栅格解决面板之间的相对比例。

- 列数固定：按 12 列或 24 列划分，面板用跨列数表达宽度比例。
- 行高弹性：用分数单位或最小最大函数让行高随可用高度伸缩。
- 间距统一：用栅格间距统一面板间隙，不为单个面板单独设外边距。
- 断点：仪表盘在窄窗口下降列数，大屏通常只有一个固定断点。

```css
.dashboard-grid {
  display: grid;
  grid-template-columns: repeat(24, minmax(0, 1fr));
  gap: 16px;
  height: 100vh;
}
```

> 栅格只决定位置与比例，面板内部的图形排布仍由各面板自行决定，两者不要互相渗透。

**速记**：栅格用固定列数与跨列表达比例，行高弹性、间距统一，大屏通常只需一个断点。



#### 图表容器的重绘时机

**重绘时机**：是图表所在容器尺寸变化后触发图表实例重新计算尺寸的时点，容器尺寸变化不会被图表库自动感知。

- 监听容器而非窗口：分栏拖拽与面板折叠只改变容器尺寸，不触发窗口尺寸事件。
- 合并到下一帧：一次拖拽会在同一帧内多次触发观察回调，用帧回调合并处理。
- 隐藏即零尺寸：折叠或切换标签页时容器宽高为零，恢复显示后必须补一次重绘。
- 重绘不取数：重绘只调整画布与内部布局，不重新请求数据。

```js
function observePanel(panel, chart) {
  let pending = false;
  const observer = new ResizeObserver(() => {
    if (pending) return;
    pending = true;
    requestAnimationFrame(() => {
      pending = false;
      if (panel.clientWidth > 0 && panel.clientHeight > 0) {
        chart.resize();
      }
    });
  });
  observer.observe(panel);
  return observer;
}
```

> [!IMPORTANT]
> **重要内容**：把图表重绘挂在窗口尺寸事件上，折叠面板、拖拽分栏与容器隐藏都不会触发，图表会停留在旧尺寸。重绘必须监听容器本身。

**速记**：容器尺寸变化要监听容器、合并到下一帧、零尺寸时跳过，重绘只调尺寸不取数据。



### 组件封装与数据流

大屏页面由大量结构相似的面板组成，逐个手写会造成取值、样式与刷新逻辑重复。本节给出面板组件的边界、数据获取方式与图表实例的生命周期安排。

#### 面板组件的职责边界

**面板组件**：是封装标题、边框、加载状态与内容区域的可复用单元，只负责外观与状态呈现，不负责数据来源与图表类型选择。

- 输入：标题、单位、数据、加载状态与错误信息。
- 输出：只暴露重试、下钻一类用户动作，不暴露内部图表实例。
- 不承担：请求地址、轮询周期与图表配置，这些由上层页面注入。
- 收益：更换图表类型时只改内容区域，布局与外壳代码不动。

```ts
interface PanelProps {
  title: string;
  unit?: string;
  loading: boolean;
  error?: string;
  onRetry: () => void;
}

function renderPanelTitle(props: PanelProps): string {
  return `${props.title}${props.unit ? `（${props.unit}）` : ""}`;
}
```

> 组件边界按「谁会变化」划分：外壳稳定、图表多变，切开之后两者可以独立替换。

**速记**：面板组件只管外壳与状态，数据与图表配置由上层注入，对外只暴露重试与下钻。



#### 数据获取与刷新策略

**刷新策略**：是页面按固定节奏或多路推送更新数据的安排，需要处理并发、失败重试与页面不可见时的暂停。

- 定时轮询：按固定周期发起请求，实现简单，数据无变化时会产生空请求。
- 长连接推送：由服务端在数据变化时下发，实时性好，需要断线重连。
- 失败处理：保留上一次数据并标注陈旧时间，不把面板清空成空白。
- 不可见即暂停：页面切到后台时暂停轮询，回到前台立即补一次。

```js
function startPolling(fetchData, intervalMs) {
  let timer = 0;
  const tick = async () => {
    try {
      const data = await fetchData();
      console.log("updated", data.updatedAt); // updated 2026-09-13T10:20:00Z
    } catch (error) {
      console.warn("keep last data", error);
    }
  };
  const start = () => {
    tick();
    timer = window.setInterval(tick, intervalMs);
  };
  const stop = () => window.clearInterval(timer);
  document.addEventListener("visibilitychange", () => {
    document.hidden ? stop() : start();
  });
  start();
  return stop;
}
```

> [!WARNING]
> **警告内容**：每个面板各自定时请求会把请求量放大到面板数量级，服务端压力成倍上升。应按页面统一调度刷新节奏，或把多个面板合并到同一个接口。

**速记**：轮询要处理失败、后台暂停与并发，多面板必须统一调度或合并接口，否则请求量成倍放大。



#### 图表实例的生命周期管理

**图表实例**：是初始化函数返回的图表对象，持有画布、事件与内部状态，必须在容器销毁时显式释放。

- 创建：容器挂载且尺寸确定之后初始化，不要在尺寸为零时创建。
- 更新：数据变化时只更新数据与配置，不重复初始化。
- 释放：卸载前调用释放方法并解绑事件，避免内存泄漏。
- 唯一：同一容器不要创建多个实例，重复初始化会叠加事件监听。

```js
function createChartController(dom) {
  let chart = null;
  return {
    init() {
      chart = echarts.init(dom, null, { renderer: "canvas" });
      return chart;
    },
    update(option) {
      if (chart) chart.setOption(option, { notMerge: false });
    },
    destroy() {
      if (chart) {
        chart.dispose();
        chart = null;
      }
    }
  };
}
```

> 图表实例的配置项与渲染器选择详见本主题第 14 篇 ECharts 快速上手与配置体系，此处只关心创建与释放的时机。

**速记**：实例在容器就绪后创建、数据变化时更新、卸载前释放，同一容器只保留一个实例。



### 视觉与主题

大屏多在昏暗环境中长时间观看，配色、字号与动效都需按远距离与低干扰原则调整。本节给出深色底、字号层级与动效节奏的做法。

#### 深色底与对比控制

**深色底**：是以低亮度背景配合高亮度数据色的配色基底，用于降低长时间观看的视觉疲劳并让数据从背景中浮出。

- 背景不用纯黑：接近黑或深蓝灰更能保留层次，也减少大面积高对比造成的拖影。
- 数据色提明度：同一色相在深底上要抬高明度，否则会显得浑浊。
- 网格线弱化：坐标网格与轴线压低对比，只保留必要的刻度。
- 面板描边：用低对比细线分隔面板，不用高亮实线切割画面。

```css
:root {
  --bg-panel: #131a2e;
  --text-primary: #e6ecff;
  --text-muted: #7f8bb0;
}
```

> 深色底的对比度要求与浅色底相同：正文文本与背景的对比度不低于 4.5 比 1，大字号数值不低于 3 比 1（详见本主题第 20 篇 可视化可访问性与工程化）。

**速记**：深色底用近黑或深蓝灰而非纯黑，数据色抬高明度，网格与描边压低对比。



#### 数字与指标的字号层级

**字号层级**：是按观看距离决定核心指标、次级指标与说明文字之间大小比例关系的外观约定。

- 核心数值最大：占据面板的视觉重心，字号按最远观看距离确定。
- 单位与副标题弱化：用较小字号与低对比文字，不与数值争夺注意力。
- 等宽数字：使用等宽字形或表格数字特性，避免刷新时数字宽度跳动。
- 中文与数字混排：统一基线，避免中西文并排时高低不齐。

```css
.metric-value {
  font-size: 48px;
  font-variant-numeric: tabular-nums;
}

.metric-unit {
  font-size: 16px;
  color: var(--text-muted);
}
```

> 字号确定之后不要再用缩放去补救：整体缩放会连带缩小字号，需要大字的场景应在设计稿里就放大。

**速记**：核心数值按最远观看距离定字号，单位与副标题弱化，数字用等宽特性避免宽度跳动。



#### 动效节奏与性能约束

**动效节奏**：是入场、刷新与轮播的时间与幅度安排，目标是提示变化而不是持续吸引注视。

- 入场动画只播一次：总时长控制在数百毫秒，不做无限循环的装饰动画。
- 数值变化短过渡：从旧值过渡到新值即可，不必每次刷新都做完整滚动。
- 轮播留停顿：切换前留出足够阅读时间，再进入下一屏。
- 与刷新解耦：动画调度与数据刷新各自独立，动画不得阻塞数据更新。

```js
function transitionNumber(node, from, to, durationMs) {
  const startTime = performance.now();
  function step(now) {
    const progress = Math.min((now - startTime) / durationMs, 1);
    const value = from + (to - from) * progress;
    node.textContent = Math.round(value).toLocaleString("zh-CN");
    if (progress < 1) requestAnimationFrame(step);
  }
  requestAnimationFrame(step);
}

transitionNumber(document.querySelector(".metric-value"), 1280, 1342, 600);
```

> [!TIP]
> **建议内容**：系统开启减弱动态效果时，应按媒体查询停用非必要动画，只保留数值直接更新的结果，避免给对动效敏感的使用者造成不适。

**速记**：动效只在提示变化，入场一次、数值短过渡、轮播留停顿，且与数据刷新互不阻塞。



### 交付与部署

大屏与仪表盘常部署在内网固定设备或客户现场，交付方式与常规 Web 应用不同。本节给出产物路径、静态服务与长时间运行三方面安排。

#### 构建产物与资源路径

**资源路径**：是产物中引用脚本、样式与静态资源时使用的基准地址，部署到子目录时必须与部署路径一致。

- 相对基准：以当前页面为基准解析资源地址，适合现场路径不固定时使用。
- 绝对基准：以域名根为基准，部署目录一变则全部引用失效。
- 内容哈希：静态资源文件名带内容哈希，内容不变则长期命中缓存。
- 大文件独立：字体、地图数据与视频单独放一个目录，便于现场替换而不重新构建。

```bash
npm run build
# dist/
#   index.html
#   assets/index-a1b2c3.js
#   assets/index-d4e5f6.css
#   data/geo/china-provinces.json
```

> 带哈希的文件名与相对基准配合使用，现场更换部署目录时无需重新构建。

**速记**：产物用相对基准与内容哈希，大文件放独立目录，现场换路径不必重新构建。



#### 静态服务与本地运行

**静态服务**：是把产物目录作为根目录对外提供文件访问的进程，现场常用独立机器或工控机承载。

- 单页回退：未匹配到文件的路径回退到入口页面，避免刷新时出现 404。
- 字符集：响应头声明字符集为 UTF-8，避免中文乱码。
- 全屏运行：浏览器全屏模式下没有地址栏与状态栏，展示区域更完整。
- 系统设置：关闭休眠、屏保与自动更新，避免展示过程被系统打断。

```bash
# 现场临时预览：以产物目录为根启动静态服务
python3 -m http.server 8080 --directory dist
# 浏览器按展示模式启动（以 Chromium 系为例）
chromium --kiosk --noerrdialogs --disable-infobars http://localhost:8080/
# Serving HTTP on 0.0.0.0 port 8080 ...
```

> 展示模式下没有浏览器界面，页面内的返回与关闭入口需要有替代手段，避免无法退出。

**速记**：静态服务要做单页回退与字符集声明，现场用全屏展示并关闭系统休眠与更新。



#### 数据接口与跨域

**跨域**：是页面与接口不属于同一来源时浏览器施加的访问限制，大屏现场常出现页面与接口分属不同机器的情况。

- 同源部署：页面与接口放在同一域名与端口，配置最简单。
- 反向代理：由静态服务把接口路径转发到后端，页面仍按同源访问。
- 服务端声明：由接口回应对跨域请求的许可，需要后端配合。
- 内网同样受限：内网不等于免受限，跨域规则与是否内网无关。

```bash
# 静态服务中把接口路径转发到后端（Nginx 片段）
# location /api/ {
#   proxy_pass http://10.0.0.12:9000/;
#   proxy_set_header Host $host;
# }
```

> [!CAUTION]
> **注意内容**：现场网络可能完全无法访问公网。页面若引用公共字体、图标库或在线地图瓦片，断网后这些资源会整体失效，交付前必须把它们下载到本地一并部署。

**速记**：跨域优先用同源部署或反向代理，内网同样受跨域限制，公网资源必须本地化。



#### 长时间运行的稳定性

**长时间运行**：是大屏连续开机数天甚至数周的工作状态，稳定性问题集中在内存、定时器与断网三处。

- 内存：及时释放图表实例与事件监听，避免节点与画布持续增长。
- 定时器：轮询与轮播的定时器统一登记，页面重载前统一清理。
- 断网：保留最后一次数据并显示陈旧时间，网络恢复后自动重连。
- 兜底自愈：设置定时整页重载作为最后手段，用于清理无法定位的泄漏。

```js
function guardLongRunning(reloadAfterMs) {
  const startedAt = Date.now();
  const timer = window.setInterval(() => {
    const aliveMs = Date.now() - startedAt;
    if (aliveMs > reloadAfterMs) {
      window.location.reload();
    }
  }, 60000);
  window.addEventListener("beforeunload", () => window.clearInterval(timer));
}

guardLongRunning(6 * 60 * 60 * 1000);
```

> 自愈重载只能掩盖问题，出现持续增长的内存曲线时仍应定位泄漏点，重载不是解决方案。

**速记**：长跑关注内存、定时器与断网三类问题，自愈重载只作兜底而不能替代定位泄漏。



### 上线自查清单

交付前的自查用于在离开开发机之前暴露适配、性能与数据三类问题。本节按这三类给出可逐项确认的检查点。

#### 适配与显示自查

**适配自查**：是在目标设备与实际分辨率下逐项确认画面是否完整、文字是否可读的检查过程。

- 在目标分辨率下整体截图核对，重点看边缘面板是否被裁切。
- 确认全屏模式下没有出现滚动条。
- 确认字体缺失时的回退效果，没有文字溢出容器。
- 确认缩放之后的小字号文本仍然可辨认。

```js
function reportViewport() {
  const { innerWidth, innerHeight, devicePixelRatio } = window;
  return { innerWidth, innerHeight, devicePixelRatio };
}

console.log(reportViewport()); // { innerWidth: 1920, innerHeight: 1080, devicePixelRatio: 1 }
```

> 自查记录应保留实际数值而不是只勾选「已检查」，出现问题时才能对照环境差异。

**速记**：适配自查在目标分辨率与全屏模式下核对裁切、滚动条、字体回退与最小字号。



#### 性能与稳定性自查

**性能自查**：是确认渲染帧率与内存占用在长时间运行下保持稳定的检查过程。

- 首屏渲染完成后统计帧率，确认动画期间没有明显掉帧。
- 连续运行观察内存占用曲线，确认没有持续上升趋势。
- 断开网络再恢复，确认数据能自行恢复而不是停留在错误态。
- 确认后台标签页不再发起不必要的请求。

> 帧率与内存要在真实设备上采集，开发机的性能通常明显优于现场工控机。

**速记**：性能自查采集帧率与内存曲线，并验证断网恢复与后台暂停两类边界行为。



#### 数据与文案自查

**数据自查**：是核对面板所展示数值的口径、单位与时间是否一致、是否存在歧义的检查过程。

- 核对各面板的数据口径、单位与更新时间是否一致。
- 检查空数据、极端值与负数是否有合理显示，而不是显示为空白或无穷。
- 检查指标名称是否存在歧义或口语化表述。
- 确认数据来源与统计口径说明在页面上可见。

> 数据口径的分歧应在交付前与业务方确认，页面文案只能体现已经确认的口径。

**速记**：数据自查核对口径、单位与时间的一致，并确认空值、极值与负数都有合理显示。
