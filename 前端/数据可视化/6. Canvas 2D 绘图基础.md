## Canvas 2D 绘图基础

### Canvas 是什么与与 SVG 的根本差别

Canvas 把绘制结果记录为像素而不是结构化的图形对象，这一取舍决定了它的能力边界。本节先给出定义与适用场景，再与 SVG 逐项对照，最后给出取舍判断。

#### Canvas 的定义与适用场景

**Canvas**：是 HTML 标准中的一个绘图元素，提供一块位图画布，脚本通过 2D 上下文把路径、文本与图像绘制成像素，绘制完成后不保留图形的结构信息。

- 绘制模型：脚本按顺序发出绘制指令，指令执行后立即作用于位图，光栅化由浏览器完成。
- 上下文类型：同一张画布可获取 2D 上下文或 WebGL 上下文，只能取其一，以另一类型再次获取返回 null。
- 适用场景：需要逐帧重绘、图元数量极大或需要像素级处理的场合，例如热力图、密集散点与实时波形。
- 不适用场景：需要单个图元响应事件、文本可被选中、缩放后依旧清晰时，改用 SVG 更合适。

```html
<canvas id="chart" width="800" height="400"></canvas>
```

```js
const canvas = document.getElementById("chart");
const ctx = canvas.getContext("2d");
ctx.fillStyle = "#3b82f6";
ctx.fillRect(40, 40, 120, 60);
// 画布左上区域出现一块 120×60 的蓝色矩形
```

> 画布元素的 width 与 height 描述的是位图尺寸而非显示尺寸，详细机制见下文「显示尺寸与位图尺寸」一节。

**速记**：Canvas 是位图画布，脚本发出绘制指令后只留下像素，不保留图形结构。



#### 与 SVG 的根本差别

**SVG（Scalable Vector Graphics，可缩放矢量图形）**：是基于 XML 的矢量图形格式，用元素描述图形并由浏览器保留成一棵可查询的节点树，属性变化会触发该节点与相关区域的重绘。

两者差别的根源在渲染模型：

- 保留模式与立即模式：SVG 保留图形对象，改属性即改图形；Canvas 只留像素，改图形必须重画整帧。
- 缩放表现：SVG 是矢量描述，放大不失真；Canvas 是位图，放大会暴露像素方块。
- 事件粒度：SVG 每个元素都是可命中对象，Canvas 只有一张画布，命中要靠坐标计算。
- 文档规模：几万个 SVG 节点会拖慢样式计算与布局，Canvas 用一条绘制循环即可画完。
- 可访问性：SVG 节点可被辅助技术读取，Canvas 内容对辅助技术不可见，需要另配替代形式。

```html
<svg width="200" height="100">
  <rect x="10" y="10" width="60" height="40" fill="#3b82f6"></rect>
</svg>
```

```js
// 同样的图形在 Canvas 上是一次性绘制，画完不再可寻址
ctx.fillStyle = "#3b82f6";
ctx.fillRect(10, 10, 60, 40);
```

**速记**：SVG 保留图形对象、可逐元素交互、缩放不失真；Canvas 只留像素、整体交互、放大失真。



#### 两种模型的取舍判断

**取舍判断**：是按图元数量、交互粒度与清晰度要求选择渲染模型的决策过程，判断顺序为交互需求、图元规模、缩放需求，任一硬约束成立即可直接定案。

- 图元数量过万：优先选 Canvas，DOM 节点数带来的布局与样式开销会先于绘制成为瓶颈。
- 需要逐图元悬停与点击：优先选 SVG，或改用 Canvas 加命中检测实现等价能力。
- 需要无损放大与打印：优先选 SVG，位图在高倍缩放与打印中会出现模糊。
- 需要像素级处理：只能选 Canvas，SVG 没有直接读写像素的接口。
- 两者混合：静态坐标轴与标注用 SVG，海量数据点用 Canvas 叠在同一区域。

```js
function shouldUseCanvas(pointCount, needPerMarkHitTest, needVectorZoom) {
  if (needVectorZoom) return "svg";
  if (needPerMarkHitTest && pointCount < 2000) return "svg";
  return pointCount > 5000 ? "canvas" : "svg";
}
console.log(shouldUseCanvas(12000, false, false)); // "canvas"
```

> 三种渲染模型的机制对照与迁移路径详见本主题第 11 篇 渲染技术选型：SVG、Canvas 与 WebGL。

**速记**：交互粒度、图元规模、缩放与像素需求依次决定取舍，规模大的数据点交给 Canvas。



### 上下文与绘制状态

绘制指令的效果取决于当前上下文的状态，理解状态与状态栈是避免样式串味的前提。本节先讲上下文的获取与类型区别，再讲状态的保存与恢复。

#### 获取绘制上下文

**绘制上下文**：是绑定到某张画布上的绘图接口对象，2D 上下文由 getContext(contextType, options) 返回，contextType 传 "2d" 时得到画布二维渲染上下文，失败或类型不符时返回 null。

- 类型取值：常见为 "2d"、"webgl" 与 "webgl2"，同一画布只能取其一，原因见本篇篇首「Canvas 的定义与适用场景」。
- 选项对象：2D 上下文可用 options 指定 alpha 是否支持透明、desynchronized 是否降低延迟等行为。
- 返回值判断：获取结果可能为 null，使用前应判空，避免在空对象上调用方法报错。
- 附加上下文属性：可读取 canvas 属性回指宿主元素，用于尺寸与坐标换算。

```js
const canvas = document.getElementById("chart");
const ctx = canvas.getContext("2d", { alpha: true });
if (!ctx) {
  throw new Error("当前环境不支持 2D 上下文");
}
console.log(ctx.canvas === canvas); // true
```

> [!NOTE]
> **提醒内容**：同一画布的上下文类型一经取得即锁定，切勿混取，详见篇首定义处的说明。

**速记**：2D 上下文由 getContext("2d", options) 获取，可能为 null，同一画布只能锁定一种上下文类型。



#### 绘制状态与 save/restore

**绘制状态**：是影响后续绘制结果的一组属性快照，包括填充与描边样式、线宽、线型、字体、文本对齐、透明度、合成模式、阴影、变换矩阵与裁剪区域；save() 把当前状态压入状态栈，restore() 弹出栈顶状态并恢复。

- 压栈内容：样式类属性与变换、裁剪区域都随状态一起保存与恢复。
- 不保存的内容：当前路径不属于绘制状态，restore() 不会清空已构建的路径。
- 栈的深度：状态栈可嵌套多层，超出实际需要会占用内存；配对使用是基本纪律。
- 空栈恢复：在空栈上调用 restore() 不报错也不产生效果，错误因此不易被发现。

```js
ctx.fillStyle = "#1f2937";
ctx.save();
ctx.fillStyle = "#ef4444";
ctx.fillRect(20, 20, 80, 40); // 红色矩形
ctx.restore();
ctx.fillRect(120, 20, 80, 40); // 回到 #1f2937
```

> [!TIP]
> **建议内容**：在绘制每个图元前 save()、绘制后 restore()，可以让图元之间互不影响，比手工回滚每个属性更可靠。

**速记**：save 压状态、restore 弹状态，样式与变换都受保护，路径不受影响。



### 路径与形状

路径是 Canvas 描述图形的核心手段，先声明几何再一次性填充或描边。本节依次讲路径的构建流程、矩形类形状与圆弧曲线。

#### 路径的构建流程

**路径**：是由若干子路径构成的几何描述，通过 beginPath() 开始新路径、moveTo(x, y) 起笔、lineTo(x, y) 连线，最后用 fill() 填充或 stroke() 描边；closePath() 把当前子路径的终点与起点闭合。

- beginPath()：清空上一条路径，忘记调用会让新旧路径被同一次填充合并。
- moveTo：开启新子路径，避免相邻两条线段被一条线连起来。
- 填充规则：fill(fillRule) 接受 "nonzero" 与 "evenodd"，决定重叠区域算不算内部。
- 描边细节：stroke() 沿路径中心线向两侧各画半个线宽，线宽为奇数时边界会落在半像素上。

```js
ctx.beginPath();
ctx.moveTo(40, 160);
ctx.lineTo(120, 80);
ctx.lineTo(200, 160);
ctx.closePath();
ctx.fillStyle = "rgba(59, 130, 246, 0.2)";
ctx.fill();
ctx.strokeStyle = "#2563eb";
ctx.lineWidth = 2;
ctx.stroke();
// 得到一个闭合三角形，内部半透明蓝、边界深蓝
```

**速记**：beginPath 开新路径、moveTo 起笔、lineTo 连线、closePath 闭合，内容靠 fill 与 stroke 落地。



#### 基本形状与矩形

**矩形方法**：是直接生成矩形子路径或直接落笔的便捷接口，rect(x, y, width, height) 把矩形加入当前路径，fillRect(x, y, width, height) 与 strokeRect(x, y, width, height) 立即填充或描边，clearRect(x, y, width, height) 把矩形区域清为透明。

- rect：只生成路径，可与其它子路径一起参与一次填充或裁剪。
- roundRect(x, y, width, height, radii)：生成圆角矩形路径，radii 可传数值或数组指定四角半径。
- fillRect 与 strokeRect：不进入路径，也不受当前路径影响，适合画背景与网格线。
- clearRect：把区域像素置为全透明，颜色与透明度一并清除，是重绘前的常用清理手段。

```js
ctx.fillStyle = "#f8fafc";
ctx.fillRect(0, 0, 320, 200);

ctx.strokeStyle = "#e2e8f0";
ctx.lineWidth = 1;
for (let x = 0; x <= 320; x += 40) {
  ctx.beginPath();
  ctx.moveTo(x + 0.5, 0);
  ctx.lineTo(x + 0.5, 200);
  ctx.stroke();
}
// 得到一张浅灰网格底，竖线落在半像素上更锐利
```

**速记**：rect 与 roundRect 生成路径，fillRect、strokeRect 直接落笔，clearRect 负责清空区域。



#### 圆弧与曲线

**圆弧与曲线方法**：是把非直线几何加入当前路径的接口，弧线用 arc(x, y, radius, startAngle, endAngle, counterclockwise) 与 arcTo(x1, y1, x2, y2, radius)，二次与三次贝塞尔曲线分别用 quadraticCurveTo(cpx, cpy, x, y) 与 bezierCurveTo(cp1x, cp1y, cp2x, cp2y, x, y)。

- 角度单位：startAngle 与 endAngle 用弧度，整圆为 2π，0 弧度指向正右方。
- 弧线起点：arc 会从当前点到弧线起点补一条直线，除非先 moveTo 到弧线起点。
- arcTo：按两条切线与半径生成圆角，适合把折线拐角磨圆。
- 椭圆：ellipse(x, y, radiusX, radiusY, rotation, startAngle, endAngle, counterclockwise) 允许两轴不等长。

```js
// 环形进度：从 -90° 起画到 120°
const centerX = 160;
const centerY = 160;
const start = -Math.PI / 2;
const end = start + (2 * Math.PI * 0.62);

ctx.beginPath();
ctx.arc(centerX, centerY, 70, start, end, false);
ctx.strokeStyle = "#10b981";
ctx.lineWidth = 14;
ctx.lineCap = "round";
ctx.stroke();
// 画出一段约六成圆周的绿色圆弧
```

> [!TIP]
> **建议内容**：绘制饼图与环形图时把起始角统一设为负二分之 π，让第一段从正上方开始，符合阅读习惯。

**速记**：arc 与 arcTo 生成圆弧，quadraticCurveTo 与 bezierCurveTo 生成曲线，角度一律用弧度。



### 样式、颜色与线型

路径只决定形状，最终外观由填充、描边与线型属性决定。本节讲纯色与线型、渐变与图案，以及虚线的设置方法。

#### 填充与描边样式

**填充样式与描边样式**：是决定形状内部与边界外观的属性集合，fillStyle 描述内部，strokeStyle 描述边界，两者都接受颜色字符串、渐变对象与图案对象。

- 颜色写法：用十六进制、rgb、rgba、hsl 与颜色关键字，半透明颜色用 rgba 或 hsla。
- lineWidth：为正数，描述描边总宽度，默认 1；设为 0 或负数不生效。
- lineCap：取 "butt"、"round" 与 "square"，控制线端形状，圆弧端点常配 "round"。
- lineJoin：取 "miter"、"round" 与 "bevel"，控制拐角形状，配合 miterLimit 限制尖角长度。

```js
ctx.strokeStyle = "rgba(37, 99, 235, 0.9)";
ctx.lineWidth = 4;
ctx.lineCap = "round";
ctx.lineJoin = "round";
ctx.beginPath();
ctx.moveTo(40, 200);
ctx.lineTo(120, 120);
ctx.lineTo(200, 200);
ctx.stroke();
// 折线端点是圆头、拐角是圆角
```

**速记**：fillStyle 管内部、strokeStyle 管边界，lineWidth 定粗细、lineCap 与 lineJoin 定端点和拐角。



#### 渐变与图案

**渐变对象**：是由两个以上颜色停靠点构成的填充或描边样式，线性渐变由 createLinearGradient(x0, y0, x1, y1) 创建，径向渐变由 createRadialGradient(x0, y0, r0, x1, y1, r1) 创建，两者都用 addColorStop(offset, color) 添加停靠点。

- 坐标语义：渐变坐标以画布坐标系表示，渐变不随形状移动，形状移动后需重建渐变。
- 停靠点：offset 取 0 到 1，必须至少两个停靠点才可见，超出范围的颜色值被忽略。
- 图案：createPattern(image, repetition) 把图像或另一张画布平铺为填充，repetition 取 "repeat"、"repeat-x"、"repeat-y" 与 "no-repeat"。
- 应用方式：把渐变或图案赋给 fillStyle 或 strokeStyle 即可生效。

```js
const gradient = ctx.createLinearGradient(0, 0, 0, 200);
gradient.addColorStop(0, "#93c5fd");
gradient.addColorStop(1, "#1d4ed8");
ctx.fillStyle = gradient;
ctx.fillRect(40, 40, 240, 120);
// 矩形从浅蓝渐变到深蓝
```

**速记**：渐变由创建函数加 addColorStop 构成，图案由 createPattern 平铺，二者都能赋给填充或描边样式。



#### 线型与虚线

**虚线**：是由 setLineDash(segments) 设置的线型，segments 是描述实线与空白交替长度的数组；getLineDash() 返回当前线型副本，lineDashOffset 用于让虚线流动。

- 数组语义：段长按数组顺序循环，元素个数为奇数时数组会被复制一份凑成偶数。
- 空数组：传空数组即恢复实线，这是清除虚线的标准写法。
- 偏移：lineDashOffset 为正值时虚线沿路径方向前移，改变它可做出流动边界效果。
- 作用范围：线型属于绘制状态，save 与 restore 能把它一并保存与恢复。

```js
ctx.beginPath();
ctx.moveTo(40, 200);
ctx.lineTo(280, 200);
ctx.lineWidth = 2;
ctx.setLineDash([8, 6]);
ctx.lineDashOffset = 0;
ctx.stroke();

console.log(ctx.getLineDash()); // [8, 6]
```

> [!CAUTION]
> **注意内容**：setLineDash 会持续作用于后续所有描边，忘记在不需要的图元前恢复，会让本应实线的坐标轴也变成虚线。

**速记**：setLineDash 用数组描述实虚交替，空数组恢复实线，lineDashOffset 控制虚线相位。



### 文本与图像绘制

图表离不开轴标签、数值标注与图例，也常需要在画布上叠加图片与纹理。本节讲文本的绘制与度量，以及图像的绘制方式。

#### 文本绘制与度量

**文本绘制**：是把字符串落到画布上的操作，fillText(text, x, y, maxWidth) 填充文字，strokeText(text, x, y, maxWidth) 描边文字，外观由 font、textAlign 与 textBaseline 控制。

- font：用一条字体声明描述字号与字族，写法与 CSS 的字体简写一致，如 14px sans-serif。
- textAlign：取 "start"、"end"、"center"、"left" 与 "right"，决定 x 在文字中的对齐位置。
- textBaseline：取 "top"、"middle"、"bottom"、"alphabetic" 与 "hanging" 等，决定 y 对应的基线位置。
- 度量：measureText(text) 返回 TextMetrics，用其 width 计算文字占宽，可据此做居中与截断。

```js
ctx.font = "14px sans-serif";
ctx.textAlign = "center";
ctx.textBaseline = "middle";
ctx.fillStyle = "#334155";
ctx.fillText("2026-09", 160, 90);

const metrics = ctx.measureText("2026-09");
console.log(metrics.width); // 约 52，随字体与字号变化
```

> 度量只在当前字体下有效：先设 font 再 measureText，顺序颠倒会得到上一字体的宽度。

**速记**：fillText 与 strokeText 负责落笔，textAlign 与 textBaseline 定锚点，measureText 提供宽度。



#### 图像绘制

**图像绘制**：是把位图资源画入画布的接口，drawImage(image, dx, dy) 按原始尺寸绘制，drawImage(image, dx, dy, dWidth, dHeight) 缩放绘制，drawImage(image, sx, sy, sWidth, sHeight, dx, dy, dWidth, dHeight) 裁剪并缩放绘制。

- 图像来源：图片元素、另一张画布、位图对象与视频帧都可作为 image 参数。
- 加载时机：图片必须已加载完成，未加载完成时绘制不会报错但看不到内容，应在加载完成后重绘。
- 裁剪参数：源矩形以图像左上角为原点，目标矩形以画布坐标系为原点。
- 跨域限制：绘制跨域图片会污染画布，之后调用导出接口会抛出安全错误。

```js
const logo = new Image();
logo.src = "/assets/logo.png";
logo.onload = () => {
  // 把源图左上 64×64 的区域放大到 96×96 画到 (40, 40)
  ctx.drawImage(logo, 0, 0, 64, 64, 40, 40, 96, 96);
};
```

**速记**：drawImage 有三档重载，分别对应原尺寸、缩放与裁剪缩放，绘制前必须确认图像已加载。



### 尺寸适配与高分屏

画布的位图尺寸与 CSS 尺寸分工不同，在设备像素比大于 1 的屏幕上不做适配就会出现模糊。本节讲两种尺寸的区别、适配方法与重绘时机。

#### 显示尺寸与位图尺寸

**位图尺寸**：是画布实际拥有的像素行列数，由 canvas 元素的 width 与 height 属性决定；**显示尺寸**：是画布在页面上占据的布局大小，由 CSS 决定，两者不一致时浏览器按显示尺寸缩放位图。

- 默认值：width 与 height 默认均为 300 与 150 像素。
- 缩放后果：位图小于显示尺寸时被拉伸而变模糊，位图大于显示尺寸时被压缩而浪费内存。
- 坐标系：所有绘制坐标都基于位图尺寸，而不是 CSS 尺寸。
- 属性与样式：改 width 属性的数值即改位图，改 CSS 的 width 即改显示，二者是不同层面。

```css
#chart {
  width: 100%;
  height: 360px;
  display: block;
}
```

```js
// 位图保持 800×400，布局上被拉伸到容器宽度
console.log(canvas.width, canvas.height); // 800 400
console.log(canvas.clientWidth, canvas.clientHeight); // 随容器变化
```

**速记**：width 与 height 属性是位图尺寸，CSS 尺寸是显示尺寸，绘制坐标始终按位图尺寸计算。



#### 设备像素比适配

**设备像素比（devicePixelRatio，DPR）**：是设备物理像素与 CSS 像素的比值，普通屏为 1，高分屏常为 2 或 3；适配做法是把位图尺寸放大到 CSS 尺寸乘以 DPR，再用一次缩放把绘制坐标系拉回 CSS 像素。

- 位图放大：把 width 设为 CSS 宽度乘 DPR，height 同理，让位图拥有足够物理像素。
- 坐标系还原：调用 scale(dpr, dpr) 或 setTransform，使一单位绘制坐标等于一个 CSS 像素。
- 重置陷阱：给 width 或 height 赋值会清空画布并重置全部状态，包括变换、样式与裁剪。
- 绘制顺序：先设尺寸，再设变换，最后绘制；顺序颠倒会被尺寸赋值清掉变换。

```js
function resizeCanvas(canvas, cssWidth, cssHeight) {
  const dpr = window.devicePixelRatio || 1;
  canvas.width = Math.round(cssWidth * dpr);
  canvas.height = Math.round(cssHeight * dpr);
  canvas.style.width = cssWidth + "px";
  canvas.style.height = cssHeight + "px";

  const ctx = canvas.getContext("2d");
  ctx.setTransform(dpr, 0, 0, dpr, 0, 0);
  return ctx;
}
// 之后即可按 CSS 像素坐标绘制，例如 ctx.fillRect(0, 0, 100, 100)
```

> [!WARNING]
> **警告内容**：给画布的 width 或 height 赋值会清空全部像素并重置绘制状态，任何在赋值前设置的变换、样式与裁剪都会失效，必须在赋值之后重新设置。

**速记**：高分屏适配把位图尺寸乘 DPR 再缩放坐标系，尺寸与变换的先后顺序不能颠倒。



#### 内容重绘的时机

**重绘**：是清空或覆盖旧内容后按新尺寸重新执行绘制的过程，画布不保留图形结构，任何尺寸、数据或视图变化都需要主动重绘。

- 尺寸变化：窗口尺寸或容器尺寸改变后重新算尺寸、重置变换并重绘。
- 初次绘制：字体或图片等异步资源加载完成后需要再绘一次，否则相关内容缺失。
- 清理方式：全量重绘用 clearRect 清空整个位图，或用不透明底色 fillRect 覆盖。
- 监听方式：容器尺寸变化可用 ResizeObserver 监听，避免只依赖窗口事件而漏掉局部布局变化。

```js
const observer = new ResizeObserver((entries) => {
  const box = entries[0].contentRect;
  const ctx = resizeCanvas(canvas, box.width, box.height);
  drawChart(ctx, box.width, box.height);
});
observer.observe(canvas.parentElement);

function drawChart(ctx, width, height) {
  ctx.clearRect(0, 0, width, height);
  // 在此按新的宽高重绘坐标轴与数据
}
```

> 画布重绘是显式动作，没有自动刷新；把「尺寸、变换、绘制」封装成同一个函数，可以避免三者不一致。

**速记**：尺寸与数据变化都必须显式重绘，用 ResizeObserver 监听容器并统一走重绘函数。
