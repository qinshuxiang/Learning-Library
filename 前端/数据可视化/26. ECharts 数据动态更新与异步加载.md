## ECharts 数据动态更新与异步加载

真实业务里图表的数据是活的：接口轮询、推送通道、用户筛选，都会在图表存活期间改写数据。第 15 篇讲过异步获取的时机、加载态与 appendData 的机制，本篇把更新这件事讲完整：setOption 的合并语义决定旧配置去哪儿了，更新通道决定数据什么时候来，数据质量处理决定脏数据会不会画坏图，最后按场景给出更新策略的选型。

### setOption 的合并语义

setOption 是唯一的配置入口，它的合并行为决定了更新时哪些字段被保留、哪些被清掉。理解合并语义是避免「更新后图表诡异」的前提，本节拆开三种合并模式。



#### 默认合并的行为

**默认合并（merge mode）**：是 setOption(option) 不带第二参数时的行为，本次传入的字段按结构合并进旧配置，未提及的字段原样保留。

- 对象字段逐键合并，数组按索引合并：series 只传一项时只更新第一项，其余系列不动。
- 未提及的字段保留意味着增量更新只需传变化的部分，这是轮询场景的常规写法。
- 副作用是旧字段不会自动消失：删掉的系列、移除的组件仍然留在实例里。
- 数组长度变化时超出旧长度的项按新增处理，缩短数组不会删除尾部旧项。
- 更新轴 data 与系列 data 要一起传，只传系列数据不改类目轴，见本主题第 24 篇类目轴的相关说明。

```js
// 首次配置两个系列
chart.setOption({
  xAxis: { type: 'category', data: ['一月', '二月', '三月'] },
  yAxis: { type: 'value' },
  series: [
    { name: '线上', type: 'bar', data: [120, 200, 150] },
    { name: '线下', type: 'bar', data: [90, 130, 110] }
  ]
});

// 只更新第一个系列的数据，第二个系列保持不变
chart.setOption({ series: [{ data: [130, 180, 160] }] });
```

> [!WARNING]
> **警告内容**：默认合并下数组按索引覆盖、只增不减，指望「传一个短数组就把旧内容清掉」是合并语义最常见的误解；需要删内容时改用 replaceMerge 或整体替换，见下两节。

**速记**：默认合并对象逐键、数组按索引，未提及的全保留，删不掉旧内容是特性不是故障。



#### replaceMerge 与失效内容清理

**replaceMerge**：是 setOption 第二参数 options.replaceMerge 指定字段数组，让这些顶层字段做整体替换而非合并的模式，取值如 ['series']、['xAxis']。

- replaceMerge: ['series'] 时，传入的 series 数组整体替换旧系列，未传入的旧系列被删除。
- 动态列报表（列数随查询条件变化）是最典型场景：切换条件后旧系列必须清掉，否则残留旧柱或旧线。
- 替换是按字段整体的，不能只替换 series 的某一项，粒度是整个数组。
- 与 notMerge 的区别：notMerge 替换整个 option（含主题外的一切配置），replaceMerge 只替换指定字段，其余仍合并。
- 组件字段同样支持，动态增删 dataZoom、visualMap 时可用 replaceMerge 清理。

```js
// 切换统计口径后，系列集合整体替换
chart.setOption(
  {
    xAxis: { data: newXCategories },
    series: buildSeriesByDimension(nextDimension)
  },
  { replaceMerge: ['series'] }
);
```

**速记**：replaceMerge 按顶层字段整体替换，动态增删系列用它，粒度是整个数组不是单项。



#### notMerge 与 lazyUpdate

**notMerge**：是 setOption 第二参数直接传布尔或 options.notMerge 为 true 时的整体替换模式；**lazyUpdate**：是推迟到下一帧再应用更新的开关。

- notMerge 为 true 时实例状态回到全新状态再套用新配置，图例选中、dataZoom 窗口等用户状态一并重置。
- 切换图表类型、切换整页口径用 notMerge；只改数据绝不要用，用户交互状态会丢。
- lazyUpdate 为 true 时更新合并到下一帧执行，同一帧内多次 setOption 只生效最后一次合并结果。
- 高频连续调用 setOption 的场景（如滑杆拖动联动多图）开 lazyUpdate 能减少中间态重绘。
- silent 参数与更新无直接关系，它控制更新是否触发事件，需要静默刷新时配合使用。

```js
// 整体替换：类型从柱切到饼，用户态重置
chart.setOption(pieOption, { notMerge: true });

// 同帧多次更新只算最后一帧
chart.setOption(partA, { lazyUpdate: true });
chart.setOption(partB, { lazyUpdate: true });
```

> [!NOTE]
> **提醒内容**：notMerge 会重置图例选中与缩放窗口这类用户交互状态，页面提示「用户选择丢失」的问题多半源于把 notMerge 写在了常规数据更新路径上。

**速记**：notMerge 整体替换连用户态一起重置，只换类型不换数据；lazyUpdate 合并同帧更新减少重绘。



### 更新通道：轮询与推送

数据通过定时请求或长连接到达图表，通道本身的问题（频率、节流、重连）会直接反映为图表的卡顿或停滞。本节给两类通道的标准接法。



#### 定时轮询的标准写法

**定时轮询（polling）**：是按固定间隔请求最新数据并更新图表的模式，实现简单、排查容易，是后台系统的默认选择。

- 用 setInterval 时回调必须容错：请求失败不该中断后续轮询，catch 后继续下一轮。
- 组件卸载必须 clearInterval，否则回调持续驱动已销毁实例，见本主题第 22 篇内存泄漏的三个来源。
- 请求耗时不可忽略时长间隔：轮询周期应大于请求耗时，或改用递归 setTimeout 避免请求堆积。
- 页面不可见时暂停轮询，恢复可见时立即拉一次，用 visibilitychange 事件驱动。
- 更新只传变化的数据列，走默认合并，动画与更新过渡的参数配置见本主题第 25 篇。

```js
let timer = null;

function startPolling(chart, interval = 5000) {
  const tick = async () => {
    try {
      const data = await fetchLatest();
      chart.setOption({ series: [{ data }] });
    } catch (error) {
      // 失败不中断轮询，记录后等下一轮
      console.warn('poll failed', error);
    }
    timer = setTimeout(tick, interval);
  };
  tick();
  return () => clearTimeout(timer);
}

document.addEventListener('visibilitychange', () => {
  if (document.hidden) {
    clearTimeout(timer);
  }
});
```

**速记**：轮询回调必须容错、卸载必清定时器，递归 setTimeout 防堆积，页面隐藏时暂停。



#### WebSocket 推送接入

**推送更新**：是通过 WebSocket 等长连接接收数据到达即更新的模式，延迟低但连接管理是额外成本。

- 连接断开要自动重连并带退避（指数增长的间隔），重连成功后先拉一次全量再续推送，补齐断线期间的数据空洞。
- 推送频率可能高于渲染合理频率，收到的数据先进缓冲，按固定节拍批量刷进图表。
- 消息要校验结构与时间戳，乱序到达的旧消息按时间戳丢弃。
- 图表更新与连接管理解耦：连接层只往数据缓冲写，渲染层只从缓冲读，两边互不阻塞。
- 页面卸载时关闭连接并解绑回调，与轮询的清理义务相同。

```js
const buffer = [];
let flushTimer = null;

ws.onmessage = (event) => {
  const msg = JSON.parse(event.data);
  if (msg.timestamp > lastTimestamp) {
    lastTimestamp = msg.timestamp;
    buffer.push(msg.value);
  }
};

// 固定节拍消费缓冲，推送再快图表也按稳定频率刷新
flushTimer = setInterval(() => {
  if (buffer.length === 0) return;
  const batch = buffer.splice(0);
  chart.setOption({ series: [{ data: mergeLatest(currentData, batch) }] });
}, 1000);
```

> [!TIP]
> **建议内容**：推送通道务必加缓冲节拍，直接一收一刷在行情与监控类高频数据下会拖垮渲染主线程；节拍频率与更新动画时长要匹配，见第 25 篇更新过渡的取值建议。

**速记**：推送要重连退避、断线补全量、时间戳去乱序，缓冲加固定节拍再进图表。



#### 数据窗口滚动

**窗口滚动**：是实时曲线上只保留最近 N 个点、新点进来旧点出去的画法，监控类页面的标准形态。

- 类目轴滚动用数组 shift 弹出旧类目、push 压入新类目，轴 data 与各系列 data 同步操作。
- 数值轴加时间轴的写法不需弹轴数据，窗口由 dataZoom 或 min 与 max 的回调控制。
- 滚动窗口配合默认合并更新即可，无需 notMerge；窗口尺寸不变时过渡动画平滑。
- 弹出的历史数据需要回看时，用 dataZoom 让用户向左平移，数据侧保留更长的缓冲队列。
- 窗口尺寸与刷新频率共同决定每秒重绘量，二者都不宜过大。

```js
function pushPoint(chart, categories, values, point) {
  categories.push(point.time);
  values.push(point.value);
  if (categories.length > 30) {
    categories.shift();
    values.shift();
  }
  chart.setOption({
    xAxis: { data: categories },
    series: [{ data: values }]
  });
}
```

**速记**：类目窗口 shift 加 push 成对操作，轴与系列数据同步滚动，历史回看交给 dataZoom。



### 数据质量与边界处理

接口来的数据不总是干净的：缺失、空值、类型错乱、极端值，任何一种都会把图表画坏。本节按缺失、脏数据与三态展示三段处理。



#### 空值与缺失点

**空值（null）**：是数据项缺少数值的表现，ECharts 对空值默认断线不画点，相关行为可用配置调整。

- series data 里的 null 表示该位置无数值，折线在此处断开；connectNulls 为 true 时跨过空值连成直线。
- 断线与连线表达的含义不同：断线忠实呈现「没有数据」，连线呈现「推断有数据」，按业务口径选择。
- undefined 与 null 行为一致，NaN 会被当无效值处理，均不参与绘制与求和。
- 提示框对空值默认显示为短横线，formatter 自定义时可单独判断空值给「无数据」文案。
- 大面积缺失时先在数据层补齐或标注缺失原因，图表层只是如实呈现缺失。

```js
chart.setOption({
  xAxis: { type: 'category', data: ['周一', '周二', '周三', '周四', '周五'] },
  yAxis: { type: 'value' },
  series: [{
    name: '上报量',
    type: 'line',
    connectNulls: false,
    data: [120, null, 150, null, 90]
  }]
});
```

> [!NOTE]
> **提醒内容**：connectNulls 默认为 false，看到折线「莫名断开」先检查数据里的空值；反过来，把空值悄悄连线会掩盖数据缺口，监控与考核类场景应保持断线并标注。

**速记**：null 断线是默认且应默认，connectNulls 连线是推断要谨慎，提示框给空值专门文案。



#### 脏数据与类型校验

**脏数据处理**：是在数据进图表前做结构校验与数值清洗的环节，图表层对脏数据的容错有限，清洗应前置。

- 校验最小集：字段存在、类型为数值、非 NaN、在业务合理区间内；任一不过按业务规则剔除或置空。
- 字符串数字（如 '120'）不报错但比较与求和会出错，进图表前统一转数值。
- 极端离群值不一定错，先核实再决定剔除或保留，保留时用本主题第 24 篇的对数轴或范围标注处理。
- 清洗逻辑与图表配置解耦成独立函数，同一数据喂表格与图表时口径一致。
- 清洗结果留痕（剔除条数与原因），页面上给出「已剔除 N 条异常数据」的提示，避免总数对不上引发质疑。

```js
function cleanSeries(rows) {
  return rows.map((row) => {
    const value = Number(row.count);
    return Number.isFinite(value) && value >= 0 ? value : null;
  });
}

chart.setOption({
  xAxis: { type: 'category', data: rows.map((row) => row.day) },
  yAxis: { type: 'value' },
  series: [{ type: 'bar', data: cleanSeries(rows) }]
});
```

**速记**：清洗前置成独立函数，字符串转数值、NaN 与负值按规则处置，剔除要留痕提示。



#### 空态、加载态与错误态

**三态展示**：是图表在无数据、加载中与请求失败三种状态下的页面表现，第 15 篇讲过 showLoading 的用法，这里补齐三态的完整闭环。

- 加载态用 chart.showLoading，默认是旋转动画，text 与 color 可定制文案与配色。
- 错误态不要静默白屏：保留上一份数据并叠加「更新失败」标记，或显示重试按钮。
- 空态区分「确实没有数据」与「加载失败」两种成因，文案要能区分，否则用户分不清该等还是该报修。
- 空态视觉可用 graphic 组件在绘图区中央放置提示文字，配合默认合并随时被数据更新覆盖。
- 三态切换由数据层状态机驱动，图表封装暴露 status 属性，见本主题第 22 篇框架封装的相关内容。

```js
function renderStatus(chart, status) {
  if (status === 'loading') {
    chart.showLoading({ text: '数据加载中…', color: '#5b8ff9' });
  } else {
    chart.hideLoading();
  }
  if (status === 'empty') {
    chart.setOption({
      graphic: [{ type: 'text', left: 'center', top: 'middle', style: { text: '暂无数据', fill: '#999' } }]
    });
  }
}
```

> [!WARNING]
> **警告内容**：接口失败后保持上一次数据继续展示而不做任何标记，会让读者把旧数据当成实时数据；监控与考核场景必须显式标注数据截止时间或失败状态。

**速记**：三态由状态机驱动，错误态不静默、空态分成因，旧数据续展示必须带截止标记。



### 更新策略选型

全量替换、增量追加与窗口滚动各有成本，选错策略的表现是越跑越慢或内存上涨。本节给一张选型依据与三个注意事项。



#### 三种更新路径的成本对比

**更新路径**：是数据到达后作用到实例的方式，全量 setOption、appendData 追加与自维护窗口滚动是三条主要路径。

- 全量 setOption：实现最简单，每次都重走布局与绘制，适合数据量中小、频率不高的场景。
- appendData：向大数据量系列增量追加，不重置已有绘制，适合流式增长的超大数据集，机制见本主题第 15 篇。
- 窗口滚动：数据侧只保留窗口内的点，更新量恒定，适合实时监控曲线，写法见本篇数据窗口滚动一节。
- appendData 只支持部分系列类型且只能追加不能改历史，需要回改历史的场景不适用。
- 三条路径可共存：主体用窗口滚动，缩放回看时按需请求历史数据再全量更新。

```text
选择顺序：
1. 数据窗口固定（监控曲线）        → 窗口滚动
2. 数据量持续增长且只增不改（日志流、轨迹）→ appendData
3. 数据量中小、需要改历史或换口径   → 全量 setOption（配合 replaceMerge 或默认合并）
```

**速记**：窗口滚动求稳、appendData 求吞吐、全量更新求简单，按数据形态选路径不按习惯选。



#### dataset 的动态替换

**dataset 动态替换**：是集中管理数据源时更新 dataset.source 的做法，绑定它的系列随数据源一起刷新。

- dataset.source 整体替换即可，encode 绑定不变时系列自动读到新数据。
- 列结构变化（列数或含义改变）时，encode 与维度定义要一起更新，否则绑定错列。
- dataset 适合多系列共享同一数据源的场景，单系列小数据用 series.data 更直接。
- 与 series.data 混用时注意更新路径二选一：同一系列同时被 dataset 与 data 喂过，行为以最后一次为准且难以排查。
- 数据源替换后的更新动画与 series.data 路径一致，过渡参数沿用本主题第 25 篇的结论。

```js
chart.setOption({
  dataset: {
    dimensions: ['月份', '线上', '线下'],
    source: [
      ['一月', 320, 280],
      ['二月', 380, 260],
      ['三月', 350, 300]
    ]
  },
  xAxis: { type: 'category' },
  yAxis: { type: 'value' },
  series: [
    { type: 'bar', encode: { x: '月份', y: '线上' } },
    { type: 'bar', encode: { x: '月份', y: '线下' } }
  ]
});

// 之后只需替换 source
chart.setOption({ dataset: { source: nextSource } });
```

**速记**：dataset 只换 source，列结构变了连 encode 一起改，dataset 与 series.data 不要混喂同一系列。



#### 更新频率与渲染压力的权衡

**频率权衡**：是更新通道的到达频率与图表渲染能力之间的匹配问题，超配的表现是掉帧与发热，欠配的表现是数据滞后。

- 渲染耗时决定了每秒能承受的更新次数，先测单次 setOption 的耗时再定节拍，定位方法见本主题第 18 篇。
- 数据到达频率高于可渲染频率时，节拍批量刷（见本篇推送接入），不要逐条刷。
- 更新动画时长必须小于更新间隔，间隔三百毫秒的轮询配五百毫秒的过渡动画会让图形永远在追。
- 后台标签页里 setInterval 被节流到低频，推送与轮询都应配合 visibilitychange 暂停与恢复。
- 长时间运行后变慢优先排查三条：实例未销毁的累积、监听未解除的累积、数据数组只增不减的累积。

```js
// 更新间隔与动画时长匹配的基准配置
const UPDATE_INTERVAL = 1000;

chart.setOption({
  animationDurationUpdate: 150,
  series: [{ type: 'line', data: initialData }]
});

setInterval(() => {
  chart.setOption({ series: [{ data: fetchLatest() }] });
}, UPDATE_INTERVAL);
```

> [!TIP]
> **建议内容**：给实时图表定一个「更新频率上限」并写进封装的默认值，业务侧需要更高频率时必须显式放开；无上限的高频更新是可视化页面耗电与掉帧的第一大来源。

**速记**：先测单次耗时再定节拍，动画时长必须小于间隔，后台暂停、可见恢复，变慢先查三类累积。
