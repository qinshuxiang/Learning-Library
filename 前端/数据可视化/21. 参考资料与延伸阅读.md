## 参考资料与延伸阅读

### 官方文档

#### 图形底座：SVG、Canvas 与 WebGL

**图形底座文档**：是描述绘图语言与绘图接口本身行为的一手资料，出现渲染异常时先回到这里确认是用法问题还是实现差异。

- MDN Web Docs：覆盖 SVG 元素与属性、Canvas 上下文方法、WebGL 接口与浏览器兼容性的日常查询入口。
- W3C SVG 工作组站点：维护 SVG 规范的草案与修订，是确认某属性是否为标准成员的依据。
- WHATWG HTML 标准：canvas 元素与二维上下文的正式定义，绘制方法的参数语义以它为准（详见本主题第 6 篇 Canvas 2D 绘图基础）。
- Khronos Group 规范页：WebGL 1.0 与 WebGL 2.0 的接口定义与扩展列表，着色器与缓冲区的行为以此为准（详见本主题第 9 篇 WebGL 与 GPU 渲染基础）。
- Three.js 官方文档与示例集：以 r 编号发布、npm 包名为 three，版本递进较快，示例与文档对应同一版本（详见本主题第 10 篇 Three.js 三维可视化入门）。

> 图形底座的规范更新缓慢而实现更新较快，遇到能力差异时应以「规范是否定义」与「目标浏览器是否实现」两问分开判断。

**速记**：SVG、Canvas、WebGL 与 Three.js 的用法以官方文档为准，规范与实现要分开判断。



#### 图表库：D3、ECharts 与 AntV

**图表库文档**：是图表配置项、数据接入方式与扩展机制的权威出处，示例通常可直接复制运行。

- D3 官方文档：按模块组织，当前主版本为 7，以纯 ES 模块发布，选择集、比例尺与形状生成器各有独立说明页（详见本主题第 12、13 篇）。
- Apache ECharts 文档：含配置手册、示例集与升级指南，当前主版本为 6.x 系列，6.0 于 2025 年 7 月发布并引入新默认主题与动态主题切换（详见本主题第 14、15 篇）。
- AntV 站点：G2 与 G6 均已发布 5.x 版本，G2 提供函数式与对象式两套声明方式，G6 重构了图配置范式并支持多种渲染器（详见本主题第 16 篇 AntV 与其它图表方案）。
- 轻量与商业方案文档：Chart.js 等轻量库适合简单图表，Highcharts 等商业方案在导出与技术支持上有额外能力。
- 版本注意事项：图表库的大版本会调整配置字段与默认值，跨版本迁移前先读官方升级指南，不要按旧教程改配置。

> [!NOTE]
> **提醒内容**：图表库的官网示例默认跟随最新版本。项目若停留在旧大版本，示例中的字段可能已经改名或改变默认值，核对文档时要确认页面标注的版本与项目一致。

**速记**：D3、ECharts 与 AntV 的配置以各自官方文档为准，跨大版本迁移先读升级指南。



#### 三维与地理方向

**三维与地理文档**：描述三维对象模型、地理数据格式与地图投影的行为，用于处理空间数据与三维场景。

- Three.js 文档：覆盖几何体、材质、光照、相机与渲染器，另有大量示例展示数据驱动的三维形态。
- Turf.js 文档：提供面向地理数据的前端空间计算函数，用于缓冲、相交与度量。
- MapLibre GL JS 与 Mapbox GL JS 文档：矢量瓦片地图的渲染与样式规范，其中样式规范已形成独立标准。
- deck.gl 与 Cesium 文档：分别面向大规模数据图层与三维地球场景，适合数据量与空间尺度更大的场合。
- 地理数据格式说明：GeoJSON 与 TopoJSON 的字段定义与坐标顺序，是空间数据接入前的必读内容（详见本主题第 17 篇 地理与空间数据可视化）。

**速记**：三维与地理方向先读 Three.js 与地图渲染库文档，再确认 GeoJSON 与 TopoJSON 的字段约定。



### 规范与标准

#### 图形与渲染规范

**图形与渲染规范**：定义绘图语言、绘制接口与坐标变换的精确语义，是判断某写法能否稳定跨浏览器复现的最终依据。

- SVG 1.1 Second Edition：W3C 推荐标准，是当前实现覆盖最完整的一版 SVG。
- SVG 2：处于 W3C 候选推荐阶段，SVG 工作组近年以维护与互操作测试为主，是否可用取决于目标浏览器实现。
- HTML 标准中的 canvas 章节：规定二维上下文的绘制状态、路径与合成行为，是画布应用的基础契约。
- WebGL 1.0 与 WebGL 2.0：由 Khronos Group 制定，2.0 在着色器语言与缓冲区能力上扩展了 1.0。
- WebGPU 规范：由 W3C 的 GPU for the Web 工作组制定，提供更贴近现代图形接口的抽象，浏览器支持范围仍在扩展。
- CSS Color 模块：定义现代色彩空间与色彩函数，是生成配色与做色彩插值时的依据（详见本主题第 3 篇 色彩与图表设计原则）。

> 规范行文严谨但冗长，正确用法是带着具体问题定点查条目，而不是从头通读。

**速记**：图形规范以 SVG、Canvas、WebGL 与 WebGPU 的正式文本为准，可用范围取决于浏览器实现。



#### 无障碍与语义标准

**无障碍标准**：规定内容对辅助技术可达的验收准则，是图表替代文本、对比度与键盘支持的判定依据。

- WCAG 2.2：2023 年 10 月成为 W3C 推荐标准，与 2.0、2.1 向后兼容，成功准则按 A、AA、AAA 分级。
- WCAG 2.1 与 2.0：仍为现行标准，分别发布于 2018 年与 2008 年，法规引用常指向较早版本。
- WAI-ARIA 规范：定义角色、状态与属性，是把图形元素标记为可读对象的基础。
- WAI-ARIA 图形模块：为图形文档类内容定义专用角色，成熟度以 W3C 最新发布状态为准。
- 对比度计算依据：正常文本与背景的对比度不低于 4.5 比 1，大字号与图形元素不低于 3 比 1（详见本主题第 20 篇 可视化可访问性与工程化）。

> 无障碍标准的验收对象是内容整体，图表只是其中一项；把图形标记做好但页面结构与文案有缺陷，同样无法通过验收。

**速记**：无障碍验收以 WCAG 的 A、AA、AAA 分级为准，语义标记以 WAI-ARIA 及其图形模块为参照。



#### 地理信息与地图合规

**地图合规要求**：规定公开传播的地图在国界绘制、数据来源与送审流程上的约束，是任何涉及中国地图的可视化必须遵守的前置条件。

- 标准地图服务：中国国界与行政区域应使用自然资源部发布的标准地图或经审核的地图数据，不得自行绘制国界线。
- 完整性要求：中国全图必须完整表示台湾、藏南、南海诸岛及钓鱼岛、赤尾屿等，不得漏绘、错绘。
- 称谓规范：涉及香港、澳门、台湾时表述为中国香港、中国澳门、中国台湾。
- 地理数据格式：GeoJSON 的坐标顺序与要素结构在公开标准中有明确定义，接入第三方数据前应核对坐标系与来源。

> [!IMPORTANT]
> **重要内容**：对外展示的地图属于受审图制度约束的内容。使用非标准地图数据、改动国界线或漏绘岛屿，属于必须避免的严重错误，交付前应逐项核对并留存数据来源记录。

**速记**：中国地图必须用标准地图或经审核数据，国界完整、称谓规范，漏绘错绘属于严重错误。



### 经典文章与书籍

#### 图形语法与可视化理论

**图形语法与可视化理论**：把图表从具体图形抽象为数据到视觉属性的映射规则，是理解各类图表库配置结构的共同基础。

- 《The Grammar of Graphics》：系统提出把图形分解为数据、变换、标度、几何对象、分面等要素，是 G2 与同类图形语法方案的思想来源。
- 《Semiology of Graphics》：较早提出视觉变量概念，讨论位置、大小、形状、方向等通道的表达能力与限制。
- 《Information Visualization: Perception for Design》：从视知觉研究出发解释各视觉通道的感知精度差异，为通道选择提供依据（详见本主题第 2 篇 数据与视觉编码原理）。
- 《The Elements of Graphing Data》：以实证方式讨论图形设计选择，强调用实验数据而非个人偏好指导设计。
- 图形语法在库中的落地：G2 的标记与编码、Vega-Lite 的声明式规格，都可视为图形语法的不同实现形态。

**速记**：图形语法把图表抽象为数据到视觉属性的映射，视觉变量理论解释各通道的表达能力。



#### 感知与设计经典

**感知与设计经典**：面向图表外观与数据诚实，讨论如何在不夸大数据的前提下提高可读性。

- 《The Visual Display of Quantitative Information》：提出数据墨水比与图表垃圾等概念，主张删去与数据无关的装饰。
- 《The Truthful Art》：讨论数据可视化中的真实性与不确定性表达，明确反对用截断坐标轴与夸张面积误导读者。
- 《How Charts Lie》：以实例说明双轴、面积错觉与选择性范围如何造成误读。
- 《Storytelling with Data》：以案例讲解结论先行、标注引导与减少非必要元素的表达顺序。
- 双轴与截断轴：这两类做法会改变读者对比例关系的判断，除非有明确说明，否则应视为错误做法（详见本主题第 2 篇 数据与视觉编码原理）。

**速记**：感知与设计经典的核心是数据诚实，双轴与截断轴等改变比例判断的做法属于错误示范。



#### 经典可视化案例

**经典案例**：是被反复引用的可视化作品或数据集，用于说明「一张图说清一件事」的判断标准。

- 约翰·斯诺 1854 年霍乱地图：以点标记病例位置并与水源位置对照，是空间分布揭示成因的早期范例。
- 拿破仑东征图：在一张图上同时表达军队数量、行军方向、地理位置与气温，被广泛引用为多变量叠加的经典。
- 安斯库姆四重奏：四组统计量几乎相同的数据集，散点图却呈现完全不同的形态，用于说明图表与统计量不可互相替代。
- 密西西比河与铁路运输图：以线宽表达运量，是比例编码的早期实例。
- 案例的用法：这些案例的价值在于说明设计判断，而不是提供可以直接照搬的样式。

> 经典案例的年代与工具都与当下不同，其结论依赖当时的印刷条件与数据规模，引用时应说明适用前提。

**速记**：斯诺霍乱地图、拿破仑东征图与安斯库姆四重奏说明空间、多变量与分布信息无法由统计量替代。



### 工具与在线平台

#### 在线示例与协作环境

**在线示例环境**：是可直接编辑并即时看到结果的网页环境，适合验证某个配置字段的确切行为。

- D3 画廊：按图表类型组织的可运行示例，是学习选择集、比例尺与形状生成器配合方式的主要来源。
- Observable：以笔记本形式组织代码与说明，D3 与 Observable Plot 的多数示例发布在这里。
- Apache ECharts 示例集：覆盖各图表类型与交互配置，可直接在线调整配置项并导出代码。
- AntV 示例站点：G2 与 G6 提供在线编辑器与示例集合，便于比对两个大版本之间的配置差异。
- 通用在线环境：CodePen、CodeSandbox 与 StackBlitz 适合搭建最小复现，用于验证是库的行为还是自身代码问题。

**速记**：在线示例环境用于验证配置与搭建最小复现，是排查用法问题的第一站。



#### 配色与无障碍检查工具

**配色与无障碍工具**：用于生成可区分的色板并校验对比度，把配色选择从主观判断变成可核对的数值。

- ColorBrewer：提供分类、顺序与发散三类色板，并标注色觉障碍与打印条件下的可用性（详见本主题第 3 篇 色彩与图表设计原则）。
- d3-scale-chromatic：把 ColorBrewer 等色板实现为可直接调用的方案集合，D3 项目中常与比例尺搭配。
- 色彩空间与色板编辑工具：支持在现代色彩空间中拖拽生成色板，并给出对比度与色觉模拟结果。
- 对比度检查：浏览器开发者工具的对比度提示与独立的无障碍审计工具，可直接定位不达标的文本与图形。
- 色觉模拟：用滤镜模拟常见色觉障碍下的观感，用于验证颜色之外是否还有区分线索。

**速记**：配色用 ColorBrewer 一类经过检验的色板，并用对比度检查与色觉模拟验证可用性。



#### 导出、快照与视觉回归工具

**导出与验证工具**：把图表转换为可交付的文件，或在改动时发现意料之外的视觉变化。

- SVG 压缩与清理工具：去除编辑器产生的冗余节点与属性，减小导出体积并便于人工审阅。
- 视觉回归平台：把界面截图与基线对比并给出差异图，接入持续集成后可在合并前发现样式回归（详见本主题第 20 篇 可视化可访问性与工程化）。
- 端到端测试工具：在真实浏览器中打开页面并截图，可固定视口、设备像素比与动画状态。
- 服务端截图方案：在无浏览器环境下渲染图表需要额外的画布实现或服务端渲染支持，选型前先确认对图表类型的覆盖范围。

> 导出与截图工具只能保证产物一致，无法判断图形是否被误读，视觉验收仍需人工确认。

**速记**：导出用清理工具减小体积，视觉回归用截图比对发现意外变化，误读问题仍需人工判断。



### 进阶方向

#### 声明式可视化与图形语法

**声明式可视化**：是用数据与映射规则组成的规格描述图表、由渲染层决定具体绘制的做法，与逐条调用绘图接口的命令式写法相对。

- 规格驱动：图表以一份结构化规格描述，便于存储、比较与程序生成。
- Vega 与 Vega-Lite：把图形语法实现为声明式规格语言，Vega-Lite 在其上提供更高层的简写。
- 库内形态：G2 的对象式声明与 ECharts 的配置对象都带有声明式特征，理解图形语法有助于看清它们的字段组织。
- 适用边界：规格难以覆盖高度定制的图形，需要与自定义渲染结合使用。
- 学习路径：先掌握标记与编码这两个概念，再理解比例尺与坐标系变换的作用。

**速记**：声明式可视化用规格描述图表，先理解标记与编码，再理解比例尺与坐标系。



#### 高性能渲染与新的图形接口

**高性能渲染方向**：是在数据量增长到常规绘制方式无法承受时，转向 GPU 与并行计算的路径。

- 批量绘制：用实例化与批量几何减少绘制调用次数，是三维与大规模二维场景的共同手段。
- GPU 计算：WebGPU 提供计算着色器与更显式的资源管理，适合需要并行计算的可视化场景。
- 后台渲染：把布局计算与数据处理移入工作线程，避免阻塞主线程的绘制与交互（详见本主题第 18 篇 大数据量与渲染性能优化）。
- 服务端渲染：在服务端生成静态图形用于报表与归档，可避免客户端性能差异带来的不一致。
- 选型前提：先确认数据规模与交互要求，再决定是否引入 GPU 路径，过早引入会显著增加维护成本。

**速记**：高性能方向靠批量绘制、GPU 计算与后台线程，引入前先确认数据规模是否真的需要。



#### 数据叙事与交互设计

**数据叙事**：是把图表组织成有顺序、有重点的阅读过程，使读者按设计者的意图获得结论。

- 滚动叙事：页面滚动与图表状态联动，按顺序展示背景、证据与结论。
- 交互下钻：从汇总视图进入明细视图，交互路径本身构成叙事结构。
- 动画的分寸：动画用于提示变化与引导视线，过度动画会干扰对数据的判读（详见本主题第 5 篇与第 8 篇的动画部分）。
- 国际与本地化：数字格式、日期格式与文字方向随语言变化，图表需按语言调整标注与排版。
- 评估方法：用可读性测试与任务完成率验证叙事效果，而不是只依据设计者的主观判断。

**速记**：数据叙事用顺序与交互组织阅读过程，动画服务于提示变化，效果要靠任务测试验证。
