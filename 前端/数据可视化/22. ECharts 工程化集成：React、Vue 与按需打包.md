## ECharts 工程化集成：React、Vue 与按需打包

第 14 篇的引入与初始化面向原生页面，真实项目里图表跑在框架组件、构建器与路由之中，初始化时机、更新策略与释放顺序都会被工程环境改写。本篇只讲工程化集成：引入与 init 参数的基础说明见第 14 篇，setOption 各参数的完整语义见第 26 篇，此处先给框架封装的标准写法，再处理按需打包的体积问题，最后清点工程环境下最常见的生命周期陷阱。

### 框架封装图表组件

图表在框架中的正确形态是一个受控组件：容器由框架渲染，实例在挂载后创建，属性变化后同步到 setOption，卸载时销毁实例。本节分别给出 React 与 Vue 的封装骨架，并说明属性到配置的更新策略。



#### React 中的封装与生命周期

**受控封装**：是把 init、setOption、resize、dispose 四件事分别挂到 useRef、useEffect 与组件卸载上的做法，让图表实例的生命周期严格跟随组件生命周期。

- 容器引用用 useRef 保存，实例也用 useRef 保存，二者都不进 state，避免触发多余渲染。
- 初始化 useEffect 的依赖数组置空，保证实例只创建一次；数据变化交给另一个 useEffect 处理。
- StrictMode 下组件会挂载两次，清理函数必须真实 dispose，否则第二次挂载拿到的是废实例。
- resize 监听在初始化 effect 内绑定，清理函数内解除，遵循谁绑定谁解除。

```jsx
import { useEffect, useRef } from 'react';
import * as echarts from 'echarts';

export function Chart({ option }) {
  const domRef = useRef(null);
  const chartRef = useRef(null);

  useEffect(() => {
    chartRef.current = echarts.init(domRef.current);
    const observer = new ResizeObserver(() => chartRef.current?.resize());
    observer.observe(domRef.current);
    return () => {
      observer.disconnect();
      chartRef.current?.dispose();
      chartRef.current = null;
    };
  }, []);

  useEffect(() => {
    chartRef.current?.setOption(option);
  }, [option]);

  return <div ref={domRef} style={{ width: '100%', height: 320 }} />;
}
```

> [!WARNING]
> **警告内容**：React 18 及以上版本的 StrictMode 开发模式会故意执行两次挂载，用来暴露副作用问题；清理函数里没有 dispose 的图表会出现实例残留与控制台警告，必须在编写封装时同步写好清理逻辑。

**速记**：实例放 useRef 不进 state，初始化 effect 只跑一次，清理函数负责解除监听并 dispose。



#### Vue3 中的封装与生命周期

**组合式封装**：是用 ref 拿容器、onMounted 创建实例、onBeforeUnmount 销毁实例、watch 同步数据更新的做法，与 React 版本职责相同。

- 容器用 template ref 绑定，实例变量不用 ref 包装，ECharts 实例没有必要做成响应式。
- onMounted 时容器已插入文档，可以直接 init；组件被 v-if 控制时会重复走挂载与卸载，dispose 必须写。
- option 变化用 watch 监听并调用 setOption，deep 选项按需开启，深层数据量大时 deep watch 有额外开销。
- keep-alive 缓存的组件触发 activated 与 deactivated，恢复时补一次 resize，因为缓存期间容器尺寸可能已变化。

```vue
<script setup>
import { ref, watch, onMounted, onBeforeUnmount, onActivated } from 'vue';
import * as echarts from 'echarts';

const props = defineProps({ option: { type: Object, required: true } });
const domRef = ref(null);
let chart = null;
let observer = null;

onMounted(() => {
  chart = echarts.init(domRef.value);
  chart.setOption(props.option);
  observer = new ResizeObserver(() => chart?.resize());
  observer.observe(domRef.value);
});

watch(() => props.option, (next) => chart?.setOption(next), { deep: true });

onActivated(() => chart?.resize());

onBeforeUnmount(() => {
  observer?.disconnect();
  chart?.dispose();
  chart = null;
});
</script>

<template>
  <div ref="domRef" style="width: 100%; height: 320px"></div>
</template>
```

**速记**：onMounted 建、onBeforeUnmount 拆，watch 同步 option，keep-alive 场景在 activated 里补 resize。



#### 属性到配置的更新策略

**更新策略**：是决定组件属性变化后如何作用到实例的规则，核心选择是整体替换还是增量合并，以及什么时候用 notMerge。

- 常规更新走默认合并：只传本次变化的字段，实例保留其余配置，重绘开销最小。
- 系列数量会变化的图表（如动态列的报表）适合 replaceMerge，见第 26 篇的合并语义详解。
- 切换图表类型的场景用 notMerge 为 true 整体替换，避免旧系列的残留字段干扰新类型。
- 组件对外只暴露 option 一个对象属性时，内部更新逻辑保持一致；暴露多个零散属性再自行拼装会引入两套更新路径。
- 事件绑定建议在封装内统一 on 后于卸载前 off，业务侧只传回调属性，避免在业务组件里直接持有实例。

```js
// 封装内部的更新分支
function applyOption(chart, option, mode) {
  if (mode === 'replace') {
    chart.setOption(option, { notMerge: true });
  } else if (mode === 'replaceSeries') {
    chart.setOption(option, { replaceMerge: ['series'] });
  } else {
    chart.setOption(option);
  }
}
```

**速记**：常规走合并、动态系列走 replaceMerge、切换类型走 notMerge，一个组件只保留一条更新路径。



### 按需引入与打包体积

ECharts 全量包体积在数百 KB 量级，对首屏敏感的项目必须按需引入。第 14 篇给过按需注册的最小示例，本节从构建角度把这件事讲完整：注册清单、tree-shaking 生效条件与体积验证方法。



#### 注册清单与模块来源

**注册清单**：是项目实际用到的图表类型、组件与渲染器的集合，按需引入的本质是让构建器只打包这份清单涉及的模块。

- 图表类型从 echarts/charts 引入，每个系列类型一个导出，如 BarChart、LineChart、PieChart。
- 组件从 echarts/components 引入，用过哪个配哪个，常见的有 GridComponent、TooltipComponent、LegendComponent、TitleComponent。
- 渲染器从 echarts/renderers 引入，CanvasRenderer 与 SVGRenderer 至少注册一个。
- echarts/core 上的方法覆盖 init、use、registerTheme 等核心能力，业务代码一律从 core 取。
- 注册代码收敛到单一模块（如 src/charts/setup.js）统一执行，页面只从该模块间接使用，防止漏注册。

```js
// src/charts/setup.js：全项目唯一的注册入口
import * as echarts from 'echarts/core';
import { BarChart, LineChart, PieChart } from 'echarts/charts';
import {
  GridComponent,
  TooltipComponent,
  LegendComponent,
  TitleComponent,
  DataZoomComponent
} from 'echarts/components';
import { CanvasRenderer } from 'echarts/renderers';

echarts.use([
  BarChart, LineChart, PieChart,
  GridComponent, TooltipComponent, LegendComponent,
  TitleComponent, DataZoomComponent,
  CanvasRenderer
]);

export default echarts;
```

> 漏注册的症状是图表区域空白且无报错或仅有开发者警告，先核对注册清单再排查其它原因。

**速记**：图表、组件、渲染器三类模块分开取，echarts.use 统一注册，注册入口全项目只留一个。



#### tree-shaking 的生效条件

**tree-shaking**：是构建器剔除未被引用模块的优化，按需引入能减掉体积的前提是这条链路真正生效。

- 引入路径必须是 echarts/core、echarts/charts 等子路径，写成 import * as echarts from 'echarts' 会把全量包拉进来。
- 构建器需启用生产模式构建，开发模式下看到的包体积不代表线上结果。
- 使用副作用明显的写法（如把 echarts 整体挂到 window）会阻止剔除，保持模块化引用。
- 动态注册第三方扩展时，扩展依赖的模块会被连带打进包，评估体积时把它们算进去。
- 升级 ECharts 大版本后体积构成会变化，重新跑一次体积分析再下结论。

```bash
npm run build
# 用构建器自带的体积分析产物核对 echarts 相关模块的实际占比
# Vite：rollup-plugin-visualizer
# webpack：webpack-bundle-analyzer
```

**速记**：子路径引入是前提，生产构建后用体积分析工具验证，整体挂载与动态扩展都会破坏剔除效果。



#### CDN 引入与本地构建的取舍

**CDN 引用**：是通过脚本标签加载官方构建产物、使用全局变量 echarts 的做法，与本地构建各有适用场合。

- 内部系统与快速原型可用 CDN，省去构建配置；对外产品不建议，第三方源可用性不受自己控制。
- CDN 产物是全量包，按需引入的体积优势在 CDN 模式下不存在。
- 二者混用时注意实例创建入口一致，init 既在全局对象上也在 core 模块上，避免两套代码各引各的。
- 有离线或内网部署要求时，把构建产物下载到本地静态目录随应用一起发布。
- 版本要显式锁定，跟随最新版可能在不通知的情况下引入破坏性变更。

```html
<!-- 锁定版本的 CDN 引入，产线慎用 -->
<script src="https://cdn.example.com/echarts/5.6.0/echarts.min.js"></script>
<script>
  const chart = echarts.init(document.getElementById('box'));
</script>
```

> [!NOTE]
> **提醒内容**：CDN 地址锁定的大版本要与本地开发依赖一致，两边版本漂移时，开发环境验证过的配置可能在线上表现不同。

**速记**：CDN 适合内网与原型且是全量包，产线用本地构建并锁定版本，两边版本必须一致。



### 工程环境下的生命周期陷阱

框架与布局系统会改变容器的存在时机与尺寸，初始化与销毁的顺序一旦错位，症状是白屏、尺寸错乱或内存上涨。本节清点四类高频陷阱与对应解法。



#### 重复初始化与实例残留

**实例残留**：是同一容器上存在多个实例或已销毁实例仍被引用的状态，来源几乎都是重复 init 与漏 dispose。

- 封装组件里初始化前先用 getInstanceByDom 检查，已有实例直接复用或先销毁。
- 路由切换不卸载组件时实例会长期存活，这是正常的；组件卸载而不 dispose 才是问题。
- 热更新（HMR）会重新执行模块与组件，开发环境频繁出现残留属于正常现象，验证内存问题要基于生产构建。
- 全局缓存实例对象时，销毁后要把引用置空，防止后续代码对废实例调用 setOption 报错。

```js
import * as echarts from 'echarts';

function ensureChart(dom) {
  const existing = echarts.getInstanceByDom(dom);
  if (existing && !existing.isDisposed()) {
    return existing;
  }
  return echarts.init(dom);
}
```

**速记**：init 前查 getInstanceByDom，dispose 后引用置空，内存问题以生产构建为准验证。



#### 容器尺寸与初始化时机

**初始化时机问题**：是容器在 init 时不可见或尺寸未确定，导致图表按 0 尺寸或错误尺寸创建的现象，典型场景有标签页、弹窗与折叠面板。

- 容器处于 display: none 状态时宽高为 0，此时 init 得到空白图表；等容器可见后调用 resize 即可恢复。
- 弹窗与抽屉内的图表应在打开动画结束后 init 或 resize，挂在动画期间仍拿不到最终尺寸。
- 用 v-show 切换的标签页内图表，在切换为可见的回调里统一 resize 一遍。
- 图片与字体加载会改变容器高度时，等布局稳定再初始化，或初始化后监听容器尺寸自动纠正。
- ResizeObserver 能自动纠正大部分尺寸错位，但不适用于 display: none 期间的 0 尺寸，因为隐藏状态下不触发回调。

```js
// 标签页切换后纠正尺寸
tabBar.addEventListener('click', (event) => {
  switchTab(event.target.dataset.tab);
  requestAnimationFrame(() => {
    chartsInTab(event.target.dataset.tab).forEach((c) => c.resize());
  });
});
```

> [!WARNING]
> **警告内容**：在 display: none 的容器上初始化是白屏问题的首要来源，图表实例创建成功但画布尺寸为 0，页面上除了一块空白什么都没有，必须在容器可见后 resize 或改为可见后再初始化。

**速记**：隐藏容器不 init 或可见后 resize，动画结束后再取尺寸，ResizeObserver 只能救可见状态的变化。



#### 内存泄漏的三个来源

**工程环境泄漏**：是图表实例、事件监听与定时器在组件卸载后仍存活的现象，长时间运行的单页应用最容易中招。

- 实例泄漏：卸载未 dispose，画布与内部缓存全部滞留，见本篇重复初始化小节的解法。
- 监听泄漏：chart.on 绑定的回调未 off，实例销毁后回调若还引用外部大对象，对象无法回收。
- 定时器泄漏：为轮询创建的 setInterval 在卸载时未 clearInterval，回调持续调用已销毁实例。
- 三类泄漏常叠加出现：轮询回调持有 chart 引用，chart 持有 DOM，整条引用链都断不掉。
- 排查手段：开发者工具的内存面板拍堆快照，搜索 ECharts 实例对象数量随切换页面的增长趋势。

```js
// 卸载时三件事一次做完
function teardown() {
  clearInterval(timer);          // 定时器
  chart.off('click', onClick);   // 监听
  chart.dispose();               // 实例
  chart = null;
}
```

**速记**：泄漏三源是实例、监听与定时器，卸载时按定时器、监听、实例的顺序逐一释放。



#### 路由与多页签下的实例管理

**实例管理**：是在单页应用多视图场景下，决定实例随组件创建销毁还是集中缓存复用的策略。

- 默认策略随组件走：进入页面创建、离开销毁，代码简单且无泄漏，适合大多数后台页面。
- 高频切换的页面（如监控大屏的多页签）可以集中缓存实例，返回时复用并 setOption 刷新数据。
- 缓存复用要处理尺寸失效：视图隐藏期间容器尺寸变化，恢复时必须 resize。
- 缓存要有上限或淘汰策略，视图数量多时全量缓存等于把所有图表常驻内存。
- keep-alive、display: none、v-show 三种隐藏方式的恢复时机不同，封装层要为每种方式提供可见后的 resize 钩子。

```js
// 带淘汰的实例缓存
const cache = new Map();
const MAX = 8;

function getChart(dom, key) {
  if (cache.has(key)) {
    return cache.get(key);
  }
  const chart = echarts.init(dom);
  cache.set(key, chart);
  if (cache.size > MAX) {
    const oldest = cache.keys().next().value;
    cache.get(oldest).dispose();
    cache.delete(oldest);
  }
  return chart;
}
```

**速记**：默认随组件生死，高频页面才做缓存复用，缓存要带上限、淘汰与恢复时 resize。
