## Canvas 进阶：变换、像素与离屏渲染

### 变换与矩阵操作

直接用绝对坐标绘制，会让旋转、缩放与整体平移的推导变得繁琐。变换把坐标系的调整交给矩阵，本节讲基本变换、矩阵语义与重置方式。

#### 平移、旋转与缩放

**变换方法**：是修改当前变换矩阵从而改变后续绘制坐标含义的接口，translate(x, y) 平移坐标原点，rotate(angle) 旋转坐标系，scale(x, y) 缩放坐标单位。

- translate：把原点沿 x 与 y 方向各移动一段距离，之后绘制的坐标都相对新原点。
- rotate：角度以弧度为单位，正值表示顺时针方向，旋转中心是当前原点。
- scale：大于 1 放大、小于 1 缩小，负值产生镜像，缩放会同时影响线宽与字体。
- 组合顺序：变换按调用顺序依次作用于坐标系，先平移再旋转与先旋转再平移的结果不同。

```js
ctx.save();
ctx.translate(160, 160);
ctx.rotate(-Math.PI / 6);
ctx.fillStyle = "#6366f1";
ctx.fillRect(-40, -20, 80, 40);
ctx.restore();
// 在画布中心放一个逆时针倾斜 30° 的矩形
```

> 变换改变的是坐标系而不是图形本身：矩形仍按 80×40 绘制，只是其坐标含义随坐标系一起旋转。

**速记**：translate 移原点、rotate 转方向、scale 改比例，三者按调用顺序叠加作用于坐标系。



#### setTransform 与矩阵语义

**变换矩阵**：是一个描述坐标映射的 3×3 矩阵，2D 上下文中以六个分量 a、b、c、d、e、f 存储，点 (x, y) 映射为 (a·x + c·y + e, b·x + d·y + f)；setTransform(a, b, c, d, e, f) 用给定矩阵替换当前矩阵，transform(a, b, c, d, e, f) 则把给定矩阵乘到当前矩阵上。

- 单位矩阵：a 与 d 为 1、其余为 0 时表示不做任何变换。
- setTransform 语义：先重置为单位矩阵再应用给定矩阵，等价于 resetTransform() 后接一次 transform。
- transform 语义：在现有变换基础上继续叠加，适合在已变换的坐标系里追加局部变换。
- 用途：封装或还原一个确定的坐标系时用 setTransform，做增量调整时用 transform。

```js
// 把坐标系整体缩放 2 倍并平移 40 像素
ctx.setTransform(2, 0, 0, 2, 40, 40);
ctx.fillRect(0, 0, 50, 50);
// 实际落笔为 (40, 40) 起、100×100 的方块

ctx.resetTransform();
console.log(ctx.getTransform().a); // 1
```

**速记**：矩阵六个分量 a、b、c、d、e、f 决定坐标映射，setTransform 替换、transform 叠加。



#### 变换栈与重置

**变换栈**：是随绘制状态一起保存与恢复的矩阵序列，save() 记录当前矩阵，restore() 还原到记录值；resetTransform() 直接把当前矩阵恢复为单位矩阵。

- 嵌套绘制：进入子坐标系前 save()、退出后 restore()，是局部变换的标准写法。
- 重置时机：给画布 width 或 height 赋值会重置矩阵，之后若要按 DPR 缩放必须重新设置。
- 常见错误：连续多次 translate 而未恢复，坐标原点会不断偏移，越画越离谱。

```js
function drawMarker(ctx, x, y, angle) {
  ctx.save();
  ctx.translate(x, y);
  ctx.rotate(angle);
  ctx.beginPath();
  ctx.moveTo(0, 0);
  ctx.lineTo(12, 0);
  ctx.strokeStyle = "#ef4444";
  ctx.stroke();
  ctx.restore();
}
// 每画一个标记都自动回到原坐标系
```

> [!IMPORTANT]
> **重要内容**：变换与裁剪、样式一样属于绘制状态，必须在成对的 save 与 restore 之间使用，否则会持续影响后续所有绘制。

**速记**：变换随状态栈保存与恢复，resetTransform 直接归位，局部变换务必成对包裹。



### 合成模式与裁剪

多个图元叠加时，默认按覆盖顺序混色；有时需要求交集、做擦除或整体限幅。本节讲合成模式与裁剪区域两类控制手段。

#### globalCompositeOperation 的常用取值

**合成模式**：是决定新绘制内容与已有像素如何混合的 globalCompositeOperation 属性，默认值为 "source-over"，即新内容画在旧内容之上。

- "source-over"：新内容覆盖旧内容，是默认行为。
- "destination-over"：新内容画在旧内容之下，适合先画前景再补背景。
- "destination-out"：用新内容的形状擦除旧像素，常用于挖洞与橡皮擦效果。
- "source-atop"：只在旧内容不透明的区域绘制新内容，适合给图形上色而不越界。
- "lighter"：把新旧颜色相加，适合高亮叠加与光效。
- 可混合模式：还提供 "multiply"、"screen"、"overlay" 等取自 CSS 混合模式的值，用于色调融合。

```js
ctx.fillStyle = "#3b82f6";
ctx.fillRect(40, 40, 160, 120);

ctx.globalCompositeOperation = "destination-out";
ctx.beginPath();
ctx.arc(120, 100, 40, 0, Math.PI * 2);
ctx.fill();
// 矩形被挖出一个圆形透明洞
```

**速记**：globalCompositeOperation 决定新旧像素如何混合，destination-out 挖洞、source-atop 限幅、lighter 相加。



#### clip 裁剪区域

**裁剪区域**：是限定后续绘制生效范围的区域，clip(fillRule) 用当前路径与填充规则设置裁剪区域，clip(path, fillRule) 直接用给定路径设置。

- 作用方式：裁剪之后的所有绘制只在区域内可见，区域外即使绘制也不产生像素。
- 状态归属：裁剪区域属于绘制状态，save 与 restore 能保存与还原它。
- 只能收窄：再次调用 clip 只会与已有区域求交集，无法扩大，扩大必须先 restore。
- 与命中检测配合：裁剪区域不影响 isPointInPath 的几何判断，只影响像素输出。

```js
ctx.save();
ctx.beginPath();
ctx.arc(160, 120, 90, 0, Math.PI * 2);
ctx.clip();
ctx.fillStyle = "#f59e0b";
ctx.fillRect(0, 0, 320, 240);
ctx.restore();
// 整块矩形被裁成圆形
```

> [!TIP]
> **建议内容**：裁剪区域只能收窄，做多层遮罩时按从大到小的顺序嵌套 clip，并逐层用 save 与 restore 配对。

**速记**：clip 用路径限定绘制范围，区域只减不增，属于状态并能被 restore 还原。



### 像素级操作

对像素直接读写，是 Canvas 区别于 SVG 的能力之一，可用于滤镜、热力图与取色。本节讲像素数据的读写与注意点。

#### getImageData 与 putImageData

**像素数据**：是画布某块区域的原始 RGBA 副本，getImageData(sx, sy, sw, sh) 读出该区域的 ImageData 对象，putImageData(imageData, dx, dy) 把它写回画布。

- 坐标系：源矩形以画布位图坐标为原点，写回的 dx 与 dy 也是位图坐标，不受当前变换影响。
- 数据结构：ImageData 含 width、height 与 data 三个字段，data 是长度为宽度乘高度乘 4 的 Uint8ClampedArray。
- 通道顺序：每四个连续元素依次是红、绿、蓝与透明度，取值 0 到 255。
- 额外写入参数：putImageData 还可传 dirtyX、dirtyY、dirtyWidth、dirtyHeight 只回写子矩形。

```js
const region = ctx.getImageData(0, 0, 2, 1);
console.log(region.width, region.height); // 2 1
console.log(region.data.length); // 8，即 2×1×4
console.log(region.data[0], region.data[3]); // 第一个像素的红与透明度
```

> 读取与写入都作用于位图坐标，即使当前设了缩放或旋转，getImageData 取到的仍是物理像素。

**速记**：getImageData 读出区域副本、putImageData 写回位图，数据按 RGBA 四通道排列。



#### 像素数据的读写方式

**逐像素处理**：是按通道修改 ImageData.data 后写回的模式，典型流程为读出、遍历数组、改写通道、写回；createImageData(width, height) 或 createImageData(imageData) 用于新建一张空白的像素数据。

- 灰度化：把同一像素的红绿蓝按权重加权求和后写回三个通道。
- 阈值与调色：按条件改写通道值，可做二值化与单色映射。
- 新图像数据：createImageData 生成的 data 全为 0，即全透明黑。
- 性能量级：遍历成本与像素数成正比，百万像素级操作应放在离屏画布或后台线程中执行。

```js
function toGrayscale(ctx, x, y, width, height) {
  const image = ctx.getImageData(x, y, width, height);
  const data = image.data;
  for (let i = 0; i < data.length; i += 4) {
    const gray = data[i] * 0.299 + data[i + 1] * 0.587 + data[i + 2] * 0.114;
    data[i] = gray;
    data[i + 1] = gray;
    data[i + 2] = gray;
  }
  ctx.putImageData(image, x, y);
}
// 调用后该区域变为灰度
```

> [!CAUTION]
> **注意内容**：像素遍历在主线程执行会阻塞渲染，整屏级处理应改用离屏画布配合 Worker，避免掉帧。

**速记**：像素处理按读出、遍历改写、写回三步走，createImageData 用于新建空白像素数据。



### 线条与阴影细节

线宽为奇数时的模糊、拐角的尖刺与阴影的额外开销，都是实际绘制中容易忽视的细节。本节讲对齐、尖角控制与阴影属性。

#### 线条端点、拐角与虚线

**线端点与拐角**：是描边在端点与转折处的收尾方式，lineCap 控制端点，lineJoin 控制拐角，miterLimit 限制尖角的延伸长度。

- 端点取值：lineCap 取 "butt"、"round" 与 "square"，后两者会分别向外延伸半个线宽。
- 拐角取值：lineJoin 取 "miter"、"round" 与 "bevel"，锐角配 "miter" 会产生长尖刺。
- miterLimit：默认 10，尖角长度与线宽之比超过该值时自动退化为 "bevel"。
- 虚线回顾：setLineDash 与 lineDashOffset 描述实虚交替与相位，属于绘制状态。

```js
ctx.lineJoin = "miter";
ctx.miterLimit = 4;
ctx.lineWidth = 10;
ctx.beginPath();
ctx.moveTo(60, 200);
ctx.lineTo(60, 60);
ctx.lineTo(200, 60);
ctx.stroke();
// 拐角被限制为平角，不会拖出长尖刺
```

**速记**：lineCap 定端点、lineJoin 定拐角、miterLimit 限制尖角。



#### 阴影属性

**阴影**：是由 shadowColor、shadowBlur、shadowOffsetX 与 shadowOffsetY 四个属性控制的投影效果，对填充、描边、文本与图像都生效。

- shadowColor：阴影颜色，默认全透明，即不显示阴影。
- shadowOffsetX 与 shadowOffsetY：阴影相对图形的偏移量，正值分别向右与向下。
- shadowBlur：模糊程度，取非负值，值越大越模糊，不表示模糊半径的一半。
- 作用时机：阴影在绘制图元时生成，会随变换一起进入坐标系计算。

```js
ctx.save();
ctx.shadowColor = "rgba(15, 23, 42, 0.25)";
ctx.shadowBlur = 12;
ctx.shadowOffsetX = 0;
ctx.shadowOffsetY = 6;
ctx.fillStyle = "#ffffff";
ctx.fillRect(60, 60, 200, 80);
ctx.restore();
// 白色矩形下方出现一层柔和投影
```

> 阴影的模糊计算开销明显高于普通绘制，大面积图元或逐帧动画中应谨慎开启，必要时改用预渲染的位图阴影。

**速记**：阴影由颜色、模糊与两个偏移量组成，默认透明不可见，开启后随坐标系一起变换。



#### 抗锯齿与像素对齐

**抗锯齿**：是浏览器对斜线与曲线边缘做平滑采样的过程，2D 上下文默认开启，无法直接关闭；**像素对齐**：是把坐标落在能让描边边界与像素网格重合的位置，从而获得锐利直线。

- 水平与垂直直线：线宽为奇数时坐标取半像素，线宽为偶数时坐标取整数。
- 网格线：用 0.5 偏移配合 1 像素线宽，可避免网格发虚。
- 斜线与曲线：抗锯齿使其边缘带半透明过渡，无法完全消除，属于正常表现。
- 矩形填充：填充不受半像素影响，只有描边需要对齐。

```js
ctx.lineWidth = 1;
for (let y = 0; y <= 240; y += 40) {
  ctx.beginPath();
  ctx.moveTo(0, y + 0.5);
  ctx.lineTo(320, y + 0.5);
  ctx.stroke();
}
// 每条横线都清晰锐利，没有两层灰边
```

**速记**：抗锯齿默认开启无法关闭，描边锐利靠把坐标对齐到半像素或整数像素。



### 离屏与分层渲染

整帧重绘全部图元代价高昂，把不常变化的部分预先画好再合成，是最常用的提速手段。本节讲离屏画布的创建、分层缓存与尺寸注意点。

#### 离屏画布的作用

**离屏画布**：是不挂在文档树上的画布，用 document.createElement("canvas") 创建，或按环境使用 OffscreenCanvas 构造，先在内存中完成绘制，再通过 drawImage 一次性合成到主画布。

- 创建方式：常规用法是创建 canvas 元素并设置 width 与 height，取 2D 上下文后即可绘制。
- 合成方式：drawImage(offscreenCanvas, dx, dy) 把整张离屏画布画到主画布的目标位置。
- 主要收益：把复杂图元的重复绘制转化为一次位图拷贝，显著降低每帧开销。
- 适用场景：静态背景、网格、渐变底与固定水印，都适合预渲染到离屏画布。

```js
function createLayer(width, height) {
  const layer = document.createElement("canvas");
  layer.width = width;
  layer.height = height;
  return layer;
}

const gridLayer = createLayer(640, 400);
const gridCtx = gridLayer.getContext("2d");
drawGrid(gridCtx, 640, 400);
// 网格只画一次，后续用 drawImage 复用

function drawGrid(ctx, width, height) {
  ctx.strokeStyle = "#e2e8f0";
  ctx.lineWidth = 1;
  for (let x = 0; x <= width; x += 40) {
    ctx.beginPath();
    ctx.moveTo(x + 0.5, 0);
    ctx.lineTo(x + 0.5, height);
    ctx.stroke();
  }
}
```

**速记**：离屏画布在内存中预渲染，再用 drawImage 合成，把重复绘制换成一次位图拷贝。



#### 分层渲染与缓存

**分层渲染**：是按变化频率把画面拆成若干层的策略，静态层缓存为离屏画布，动态层每次重绘，最终按顺序叠加。

- 分层原则：背景与网格归静态层，数据点与游标归动态层，提示框等浮层可再分一层。
- 重绘策略：数据变化只重画动态层，再清空主画布并依次合成各层。
- 缓存失效：尺寸变化、主题切换或数据整体重算时，静态层需要重新生成。
- 内存取舍：每层都占用一张位图内存，层数不是越多越好，按变化频率划分即可。

```js
function renderFrame(ctx, width, height) {
  ctx.clearRect(0, 0, width, height);
  ctx.drawImage(gridLayer, 0, 0);      // 静态层
  ctx.drawImage(seriesLayer, 0, 0);    // 数据层
  drawTooltip(ctx, pointer);           // 浮层
}
// 每帧只做三次合成，不重复绘制网格与曲线
```

> 离屏画布同样受设备像素比影响：按 CSS 尺寸创建会让高分屏下的缓存变模糊，创建时应传入已乘 DPR 的位图尺寸。

**速记**：按变化频率分层，静态层缓存、动态层每帧重绘，合成顺序决定遮挡关系。



### 图像导出

把画布内容保存为图片，是数据可视化交付与分享的常见需求。本节讲两种导出接口、背景处理与失败原因。

#### toDataURL 与 toBlob

**导出接口**：是把画布位图编码为图片的方法，toDataURL(type, quality) 同步返回图片的数据地址字符串，toBlob(callback, type, quality) 异步回调一个 Blob 对象。

- 参数语义：type 指定图片类型，默认 image/png；quality 只对有损格式如 image/jpeg 有效，取 0 到 1。
- 同步与异步：toDataURL 直接返回字符串，适合小图与即时预览；toBlob 不占用主线程做编码，适合大图与下载。
- Blob 用法：拿到 Blob 后用 URL.createObjectURL 生成地址，再交给下载或上传逻辑。
- 调用时机：必须在绘制完成之后调用，否则导出的是尚未绘制内容之前的画面。

```js
function exportCanvas(canvas) {
  canvas.toBlob((blob) => {
    if (!blob) return;
    const url = URL.createObjectURL(blob);
    const link = document.createElement("a");
    link.href = url;
    link.download = "chart.png";
    link.click();
    URL.revokeObjectURL(url);
  }, "image/png");
}
// 点击后浏览器下载当前画布内容
```

**速记**：toDataURL 同步返回数据地址，toBlob 异步回调二进制对象，导出须在绘制完成后进行。



#### 导出时的背景与尺寸

**导出尺寸**：是导出图片的像素行列数，等于画布的位图尺寸，而不是它当前的 CSS 显示尺寸；**导出背景**：是导出图在透明区域填充的颜色。

- 尺寸关系：位图为 800×400 时导出即为 800×400，与 CSS 是否缩放无关。
- 透明背景：PNG 支持透明，画布上未被绘制的区域会以透明导出。
- 有损格式：JPEG 不支持透明，透明区域会被填成黑色，导出前需要先铺一层底色。
- 高清导出：想要更高分辨率，应临时把画布位图尺寸放大、重绘后再导出，再恢复原尺寸。

```js
function exportWithBackground(canvas, backgroundColor) {
  const ctx = canvas.getContext("2d");
  ctx.save();
  ctx.globalCompositeOperation = "destination-over";
  ctx.fillStyle = backgroundColor;
  ctx.fillRect(0, 0, canvas.width, canvas.height);
  ctx.restore();
  return canvas.toDataURL("image/jpeg", 0.92);
}
// 先补白底再编码，避免透明区域变黑
```

> [!WARNING]
> **警告内容**：导出 JPEG 前必须在画布最底层补上不透明底色，否则原本透明的区域会被编码为黑色，成品出现大片黑块。

**速记**：导出尺寸取位图尺寸，PNG 保留透明、JPEG 需先铺底色，高清导出要临时放大位图重绘。



#### 跨域污染与导出失败

**画布污染**：是画布在绘制了来源不可信的跨域图像后进入的保护状态，此时调用 getImageData、toDataURL 或 toBlob 会抛出安全错误，而不是返回错图。

- 触发条件：drawImage 绘制了未声明跨域许可的图片，画布即被标记为受污染。
- 连带影响：污染后像素读取同样被禁止，getImageData 也会抛出安全错误。
- 规避方式：让图片来源携带允许跨域的响应头，并在图片元素上声明匿名跨域请求属性。
- 排查方式：捕获导出调用的异常，区分「未绘制完成」与「画布被污染」两类原因。

```js
const img = new Image();
img.crossOrigin = "anonymous";
img.src = "https://cdn.example.com/tile.png";
img.onload = () => {
  ctx.drawImage(img, 0, 0, 320, 240);
  // 服务端返回允许跨域响应头时，这里才能安全导出
};
```

> [!NOTE]
> **提醒内容**：同源图片不会污染画布；跨域图片要么由服务端配合返回跨域响应头，要么只能用于展示而不能导出。

**速记**：跨域图片会污染画布并禁止读像素与导出，靠服务端跨域响应头与匿名请求规避。
