## 按钮变体与组合模式

按钮是这套代码里最简单的组件，也是变体系统的样本：它用一条变体函数定义了全部外观分支，用一个渲染替换属性解决了「长得像按钮但不是按钮」的问题。把按钮与徽标放在同一篇，是因为两者共用同一套变体思路，一个是多轴变体，一个是单轴变体。单色方案下按钮层级的取舍见本篇末节，令牌取值依据见第 13 篇。

### 变体系统的写法

组件的全部外观分支写在一个变体函数里。理解这个函数，等于理解了所有组件的样式结构。

#### 变体函数与轴定义

**变体函数**：是把若干「轴」映射到具体类名的函数，调用时传入轴取值并返回一条完整类名字符串。

- 轴的定义：每个轴是一组互斥的外观分支，如强调程度、尺寸、形状。
- 基础类：所有分支共享的类名单独写一份，作为每个取值的公共前缀。
- 默认值：每个轴都要给默认取值，组件内不传时按默认取用。
- 组合校验：轴与轴之间若不希望任意组合，需要在函数里收窄取值类型或做条件过滤。
- 返回值：函数的返回值本身也可导出，供非按钮元素借用外观。

```ts
import { cva, type VariantProps } from "class-variance-authority"

const buttonVariants = cva(
  "inline-flex items-center justify-center gap-2 whitespace-nowrap rounded-md text-sm font-medium transition-colors disabled:pointer-events-none disabled:opacity-50",
  {
    variants: {
      variant: {
        default: "bg-primary text-primary-foreground hover:bg-primary/90",
        outline: "border border-input bg-background hover:bg-accent hover:text-accent-foreground",
        secondary: "bg-secondary text-secondary-foreground hover:bg-secondary/80",
        ghost: "hover:bg-accent hover:text-accent-foreground",
        destructive: "bg-destructive text-destructive-foreground hover:bg-destructive/90",
        link: "text-primary underline-offset-4 hover:underline",
      },
      size: {
        default: "h-9 px-4 py-2",
        sm: "h-8 rounded-md px-3 text-xs",
        lg: "h-10 rounded-md px-6",
        icon: "size-9",
      },
    },
    defaultVariants: { variant: "default", size: "default" },
  }
)
```

> 轴的价值在于把「外观选择」与「组件实现」分开：新增一个外观档次只改变体函数，不碰组件结构。

**速记**：变体函数把互斥外观收成若干轴与默认值，基础类共享，返回值可导出给非按钮元素。



#### 强调程度的六个档位

**强调程度**：是按钮在视觉层级中的位置，由填充、边框与文字三层手段的组合决定，共六档。

- 实心默认：深色填充配浅色文字，用于一屏内唯一的主操作。
- 描边：透明填充加边框，用于与主操作并列的次操作。
- 次级实心：浅色填充加文字，用于工具栏一类中等强调的批量操作。
- 幽灵：无填充无边框，仅悬停时有底色，用于表格行内与卡片角上的轻量操作。
- 危险：状态色填充，用于不可撤销的破坏性操作。
- 链接：无填充无边框且带下划线，用于文案内跳转而非操作。

```tsx
import { Button } from "@/components/ui/button"

export function ActionBar() {
  return (
    <div className="flex items-center gap-2">
      <Button>保存</Button>
      <Button variant="outline">另存为</Button>
      <Button variant="secondary">批量导出</Button>
      <Button variant="ghost">取消</Button>
      <Button variant="destructive">删除</Button>
      <Button variant="link">查看变更记录</Button>
    </div>
  )
}
```

> [!IMPORTANT]
> **重要内容**：单色方案里六档强调靠的全是明度与边框，因此一屏内必须限定各档的出现次数。同一视区内出现两个实心默认按钮时，主操作就不再是主操作，用户会停下来判断该点哪个。

**速记**：六档强调由填充、边框、文字三层组合而成，单色下靠明度区分，一屏只允许一个实心主按钮。



#### 尺寸档位与图标间距

**尺寸档位**：是按钮在高度、内边距与字号三处的成套取值，图标专用档位则是等宽等高的方形变体。

- 常规档位：从特小到大共四档，高度与内边距同步变化，字号在最小档降一级。
- 图标档位：方形按钮，尺寸档位与常规档位一一对应，用于工具栏与表格行。
- 图标间距：按钮内的图标必须带上标注位置的属性，间距才由组件统一控制。
- 图标与文字：图标在前用于动作，图标在后用于展开，方向要与语义一致。
- 触达下限：后台系统以鼠标为主，但图标按钮仍不宜小于行高减去两倍内边距。

```tsx
import { ArrowUpIcon, PlusIcon } from "lucide-react"
import { Button } from "@/components/ui/button"

export function Sizes() {
  return (
    <div className="flex items-center gap-2">
      <Button size="xs">特小</Button>
      <Button size="sm">小</Button>
      <Button>默认</Button>
      <Button size="lg">大</Button>
      <Button size="icon" variant="ghost" aria-label="新增">
        <PlusIcon data-icon="inline-start" />
      </Button>
      <Button>
        导出
        <ArrowUpIcon data-icon="inline-end" />
      </Button>
    </div>
  )
}
```

> [!CAUTION]
> **注意内容**：图标不写位置属性时按钮不会报错，只是间距由图标自身外边距决定，表现为同一排按钮里的图标左右留白不一致。这类不一致在评审时难以描述，靠统一加属性根治。

**速记**：常规档位四档加图标方形档位，按钮内图标必须标注位置属性，图标在前表示动作、在后表示展开。



#### 加载态与禁用态

**加载态**：是把按钮内容替换为进度指示并阻止重复提交的状态，与禁用态不是同一件事。

- 加载表现：按钮内渲染进度指示组件，并同样标注图标位置属性。
- 阻止重复：加载中必须同时禁止点击，仅换图标不阻止重入等于没做。
- 宽度稳定：固定宽度按钮在加载时应保持原宽度，避免内容变化引起布局跳动。
- 禁用语义：禁用适用于条件不满足，加载适用于操作进行中，两者不要混用。
- 反馈闭环：操作完成后必须给出结果反馈，只收起加载态会让用户怀疑是否成功。

```tsx
import { Button } from "@/components/ui/button"
import { Spinner } from "@/components/ui/spinner"

export function SubmitButton({ pending }: { pending: boolean }) {
  return (
    <Button disabled={pending} className="w-24">
      {pending ? <Spinner data-icon="inline-start" /> : null}
      {pending ? "提交中" : "提交"}
    </Button>
  )
}
```

> 加载态解决的是「用户不知道要不要再点一次」这个问题。只换图标而不禁用，等于把这个疑问留在原地。

**速记**：加载态换进度指示并禁止点击，靠固定宽度防跳动，禁用用于条件不足、加载用于操作进行中。



### 组装而非继承

按钮变体的第二处设计是渲染替换：外观与语义分离，语义由使用者决定。

#### 渲染元素替换

**渲染替换**：是把组件渲染成另一个元素或第三方组件的机制，用属性声明目标元素，而不是把它包在组件外面。

- 用途一：把按钮渲染成链接，同时保留按钮外观。
- 用途二：把触发器渲染成已有组件，避免多包一层元素影响无障碍语义与定位。
- 写法差异：Radix 实现的底层用 asChild 布尔属性，Base UI 实现的底层用 render 属性并传元素。
- 合并规则：属性会合并到目标元素上，冲突时以目标元素自身声明的为准。
- 适用边界：外观类组件适合替换；本身带角色语义的组件不替换成同行语义的元素。

```tsx
// Radix 实现的底层：用 asChild 把样式下放给唯一的子元素
<Button asChild>
  <a href="/reports">查看报表</a>
</Button>
```

```tsx
// Base UI 实现的底层：用 render 属性声明要渲染的元素
<Button render={<a href="/reports" />}>查看报表</Button>
```

> [!WARNING]
> **警告内容**：把按钮替换成链接时要确认最后渲染出来的元素到底带的是什么角色。依赖底层实现自行推断时，可能出现链接被赋予按钮角色的情况，屏幕阅读器会读成「按钮」而用户按回车的行为却是导航，两者预期不一致。

**速记**：渲染替换把外观与语义分离，Radix 用 asChild、Base UI 用 render，替换前确认最终角色语义。



#### 借外观而不借语义

**外观导出**：是把组件的变体函数单独导出，供普通元素取用外观的做法，用于必须保持原生语义的场景。

- 使用场景：链接、表格行操作、自定义触发器等需要原生语义的位置。
- 写法：把变体函数作为类名工具调用，写在原生元素的类名上。
- 相对优势：不改变元素角色，无障碍语义与浏览器默认行为都保持原样。
- 适用条件：目标元素本身可聚焦且行为明确时才用，否则应重新考虑交互设计。
- 代价：需要自己补齐禁用态与焦点可见的样式。

```tsx
import { buttonVariants } from "@/components/ui/button"

export function BackLink() {
  return (
    <a href="/list" className={buttonVariants({ variant: "outline", size: "sm" })}>
      返回列表
    </a>
  )
}
```

> 外观与语义是可以拆开的：想要按钮的样子又必须保持链接的语义时，借用外观比替换元素更安全。

**速记**：需要原生语义时借变体函数拿外观，不改变元素角色，但要自行补齐禁用与焦点样式。



#### 组合式接口的层级

**组合式接口**：是把一个复杂组件拆成若干语义化子组件、由使用方显式拼装的接口形态。

- 拆解方式：容器、头、体、尾、标题、说明各成一个子组件。
- 显式拼装：使用方按需组合，不用的部分不渲染，避免隐藏的默认结构。
- 统一前缀：子组件共享同一前缀，导入时一眼看出归属。
- 样式透传：每个子组件都接受外部类名，最后参与合并。
- 与配置式接口对比：配置式接口改动需要动组件，组合式接口改动发生在使用方。

```tsx
import {
  Card,
  CardAction,
  CardContent,
  CardDescription,
  CardFooter,
  CardHeader,
  CardTitle,
} from "@/components/ui/card"

export function OrderCard() {
  return (
    <Card>
      <CardHeader>
        <CardTitle>订单概览</CardTitle>
        <CardDescription>最近 24 小时</CardDescription>
        <CardAction>{/* 右上角操作 */}</CardAction>
      </CardHeader>
      <CardContent>{/* 内容 */}</CardContent>
      <CardFooter>{/* 底部操作 */}</CardFooter>
    </Card>
  )
}
```

> 组合式接口的代价是使用方要写更多标签，收益是任何一个局部都能被替换或省略而不影响其余部分。

**速记**：复杂组件拆成语义化子组件由使用方拼装，不用即不渲染，改动发生在使用方而非组件内。



### 自定义变体与扩展

组件不可能预先覆盖全部外观需求，扩展方式要统一，否则很快会退化成逐处覆盖。

#### 新增变体轴的判断

**新增变体轴**：是在变体函数里增加一个互斥外观维度，与「就地传类名」是两条不同的扩展路径。

- 判定条件一：同一组取值在三个以上位置重复出现。
- 判定条件二：这组取值有独立语义，且未来会一起变化。
- 就地覆盖：只在一处使用的外观差异，用类名覆盖即可，不进变体函数。
- 收窄类型：新增轴时同步收窄取值类型，让错误取值在编译期就被发现。
- 文档同步：新增轴必须同步写入团队规范文档，否则他人无从知晓。

```ts
const badgeVariants = cva("inline-flex items-center rounded-md border px-2 py-0.5 text-xs font-medium", {
  variants: {
    variant: {
      default: "border-transparent bg-primary text-primary-foreground",
      secondary: "border-transparent bg-secondary text-secondary-foreground",
      destructive: "border-transparent bg-destructive text-destructive-foreground",
      outline: "text-foreground",
      ghost: "border-transparent hover:bg-accent hover:text-accent-foreground",
    },
    tone: {
      solid: "border-transparent",
      soft: "border-border bg-muted text-muted-foreground",
    },
  },
  defaultVariants: { variant: "default" },
})
```

> 变体函数是公共接口，改动它等于改动全部调用点。动手前先确认这组取值真的会被复用，别把一次性的外观需求固化进公共接口。

**速记**：同一组取值重复三处以上且有独立语义才新增轴，一次性外观差异用类名覆盖，新增轴须收窄类型并同步文档。



#### 徽标的变体与用法

**徽标**：是承载短状态标签的小型元素，用于在列表与详情页里标注记录的状态、类别或计数。

- 变体档位：实心默认、次级、危险、描边、幽灵五档，选择依据与按钮一致。
- 尺寸：徽标不做多档尺寸，统一为一种小尺寸，避免贴到表格里高度不齐。
- 内容长度：只放一个词或一个数字，超过三个词改用普通文字。
- 计数场景：数字类徽标放在图标右上或侧栏菜单项尾部，不在正文里使用。
- 状态映射：状态到变体的映射写在一处常量表里，不在各页面重复判断。

```tsx
import { Badge } from "@/components/ui/badge"

const STATUS_TONE = {
  pending: "secondary",
  processing: "outline",
  success: "secondary",
  failed: "destructive",
} as const

export function StatusBadge({ status, label }: { status: keyof typeof STATUS_TONE; label: string }) {
  return <Badge variant={STATUS_TONE[status]}>{label}</Badge>
}
```

> [!NOTE]
> **提醒内容**：状态到变体的映射散落在页面里时，新增一个状态就要全库搜索补漏。集中成一张常量表后，遗漏会变成编译错误，这是唯一能在长期维护中不出错的写法。

**速记**：徽标五档变体、单一尺寸、内容不超过三个词，状态映射集中成常量表避免逐页判断。



### 单色方案下的按钮层级

把前面几节的选择收拢成可在评审时直接引用的规则。

- 一屏一主：每个视区只允许一个实心默认按钮，其余操作降档。
- 层级递减：主操作实心、次操作描边、工具栏次级实心、行内幽灵，顺序固定。
- 危险隔离：危险按钮不与主按钮相邻，中间用间距或分隔隔开。
- 图标一致：同一区域的按钮是否带图标必须统一，避免视觉重量不齐。
- 文字动作：介词类动作（取消、返回、关闭）一律降为幽灵档或文字按钮。

```tsx
// 单色方案下的标准操作区：一主一描边，危险操作右对齐且拉开间距
<div className="flex items-center justify-between">
  <div className="flex items-center gap-2">
    <Button>保存</Button>
    <Button variant="outline">预览</Button>
    <Button variant="ghost">取消</Button>
  </div>
  <Button variant="destructive">删除记录</Button>
</div>
```

> [!TIP]
> **建议内容**：把「一屏一主」写进代码评审清单。它没有类型系统可以强制，但是单色后台界面里最容易被逐步侵蚀的一条规则，通常表现为每次加需求时多出一个实心按钮。

**速记**：一屏一主、层级递减、危险隔离、图标一致、介词动作降档，五条构成单色方案的操作区规则。
