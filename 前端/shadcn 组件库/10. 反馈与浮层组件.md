## 反馈与浮层组件

这一类组件在页面之上临时出现，解决「这一步的结果是什么」与「要不要继续」两类问题。它们的共同难点不在外观，而在焦点、层叠与滚动这三处工程细节。浮层内的表单写法见第 6 篇，表格行操作菜单见第 8 篇，焦点检查清单见第 14 篇。

### 浮层的种类与选择

浮层按「遮不遮住页面」与「打扰程度」两个维度分成四类，选错类型比样式做错更难纠正。

#### 居中对话框

**对话框**：是遮住页面并要求用户先处理完才继续的居中浮层，用于必须打断当前流程的场景。

- 适用场景：填写一张独立表单、展示需要专注阅读的详情。
- 打断程度：最高，同时只允许打开一个。
- 关闭方式：提供显式关闭按钮，遮罩点击是否关闭要按场景决定并保持一致。
- 尺寸约束：宽度取固定档位，高度超过视口时内容区单独滚动，标题与底部操作固定。
- 标题必需：对话框必须有标题，供辅助技术播报，视觉上可隐藏但语义上不能省。

```tsx
import {
  Dialog,
  DialogContent,
  DialogDescription,
  DialogFooter,
  DialogHeader,
  DialogTitle,
} from "@/components/ui/dialog"

export function EditDialog({ open, onOpenChange }: { open: boolean; onOpenChange: (open: boolean) => void }) {
  return (
    <Dialog open={open} onOpenChange={onOpenChange}>
      <DialogContent className="max-h-[80vh] sm:max-w-lg">
        <DialogHeader>
          <DialogTitle>编辑记录</DialogTitle>
          <DialogDescription>修改后立即生效，可在变更记录中查看。</DialogDescription>
        </DialogHeader>
        <div className="overflow-y-auto">{/* 表单 */}</div>
        <DialogFooter>{/* 取消与保存 */}</DialogFooter>
      </DialogContent>
    </Dialog>
  )
}
```

> [!IMPORTANT]
> **重要内容**：视口高度不足时必须只让内容区滚动。整块浮层一起滚动时，标题与底部按钮会滑出视口，用户既不知道该填什么，也找不到提交按钮。

**速记**：对话框用于必须打断的场景，同屏只开一个，必须有标题，超高时只让内容区滚动。



#### 侧边抽屉

**抽屉**：是从视口边缘滑出的浮层，宽度窄于对话框，用于需要与主内容对照的场景。

- 适用场景：从列表点开一条记录的详情，需要一边看列表一边看详情。
- 方向选择：详情与筛选从右侧滑出，导航类从左侧滑出。
- 宽度档位：固定几档宽度，窄屏下占满宽度。
- 与对话框的分工：需要对照主内容用抽屉，需要独占注意力用对话框。
- 内部滚动：抽屉内容区独立滚动，头部与底部操作固定。

```tsx
import { Sheet, SheetContent, SheetDescription, SheetHeader, SheetTitle } from "@/components/ui/sheet"

export function DetailSheet({ open, onOpenChange }: { open: boolean; onOpenChange: (open: boolean) => void }) {
  return (
    <Sheet open={open} onOpenChange={onOpenChange}>
      <SheetContent side="right" className="w-full sm:max-w-xl">
        <SheetHeader>
          <SheetTitle>记录详情</SheetTitle>
          <SheetDescription>编号 2026-0914-0031</SheetDescription>
        </SheetHeader>
        <div className="overflow-y-auto">{/* 详情内容 */}</div>
      </SheetContent>
    </Sheet>
  )
}
```

> [!TIP]
> **建议内容**：列表加详情的后台界面建议统一用抽屉而不是对话框。用户在核对一条记录时往往要回头对照另一条，抽屉不遮挡列表，这一步对照就不需要来回开关浮层。

**速记**：抽屉从边缘滑出用于与主内容对照，详情与筛选用右侧、导航用左侧，内容区独立滚动。



#### 气泡与下拉

**气泡**：是以触发元素为锚点、不遮住页面的小型浮层，用于补充说明与轻量选择。

- 气泡适用：一段补充说明、一次字段级的时间选择。
- 下拉适用：一组动作或一组取值，需要列表结构时使用。
- 悬停卡片：鼠标悬停即出现、可交互的浮层，只用于展示不可用于操作。
- 提示条：悬停出现、不接收交互的极简浮层，只放一句名词解释。
- 锚点对齐：浮层需按触发元素对齐，并在空间不足时自动翻转方向。

```tsx
import { Tooltip, TooltipContent, TooltipTrigger } from "@/components/ui/tooltip"

export function FieldHint() {
  return (
    <Tooltip>
      <TooltipTrigger>
        <InfoIcon className="size-4 text-muted-foreground" />
      </TooltipTrigger>
      <TooltipContent>该编号由系统生成，不可修改。</TooltipContent>
    </Tooltip>
  )
}
```

> [!WARNING]
> **警告内容**：悬停类浮层里的内容在触屏设备上无法触发，而键盘用户也常常拿不到。凡是写进悬停浮层的信息，都必须另有可达的呈现方式，不能只存在于悬停态。

**速记**：气泡锚定触发元素并在空间不足时翻转，悬停浮层只放说明不放操作，其内容必须另有可达途径。



### 提示与状态反馈

反馈类组件解决的是「事情做了之后，用户怎么知道结果」。

#### 轻提示

**轻提示**：是自动消失、不打断操作的短消息，用于操作结果的即时回执。

- 四种类型：成功、信息、警告与错误，配对应图标并只让图标着色。
- 出现位置：固定在一个角落，同一位置堆叠，最新的在后。
- 停留时长：按内容长度给时长，带操作按钮的提示必须停留更久或不自动消失。
- 数量控制：同一时刻最多三条，超出时合并同类而不是无限堆叠。
- 不放关键信息：轻提示会消失，任何需要回看的信息都不能只放在这里。

```tsx
import { toast } from "@/components/ui/toast"

export function useSaveFeedback() {
  return async function save(values: unknown) {
    const id = toast.add({ title: "正在保存", type: "loading" })
    try {
      await persist(values)
      toast.add({ title: "保存成功", description: "变更已写入变更记录。", type: "success" })
    } catch {
      toast.add({ title: "保存失败", description: "请检查网络后重试。", type: "error" })
    } finally {
      toast.close(id)
    }
  }
}
```

> [!NOTE]
> **提醒内容**：轻提示组件在版本演进中换过底层实现，早期版本的调用形态是按状态分开的方法，当前版本的调用形态是统一的添加方法加类型字段。升级时这一处必须逐调用点核对，它不会报错，只会悄悄不显示。

**速记**：轻提示自动消失、最多三条、带操作时延长停留，关键信息不得只放在轻提示里。



#### 提示条与横幅

**提示条**：是嵌在页面内容里、不自动消失的说明区块，用于需要持续可见的提示。

- 适用内容：表单校验失败的汇总、权限不足的说明、功能下线公告。
- 两档语义：默认档用于一般信息，危险档用于失败与阻断类信息。
- 构成顺序：图标、标题、说明、操作，四者按此顺序排列。
- 位置：页面级提示条置于内容区顶部，区块级提示条置于该区块内部。
- 关闭控制：可关闭的提示条要持久化关闭状态，否则每次进入都重新出现。

```tsx
import { Alert, AlertAction, AlertDescription, AlertTitle } from "@/components/ui/alert"
import { AlertCircleIcon } from "lucide-react"

export function PermissionNotice() {
  return (
    <Alert variant="destructive">
      <AlertCircleIcon />
      <AlertTitle>权限不足</AlertTitle>
      <AlertDescription>当前账号只能查看本部门数据，如需扩大范围请提交申请。</AlertDescription>
      <AlertAction>
        <Button variant="outline" size="sm">提交申请</Button>
      </AlertAction>
    </Alert>
  )
}
```

> 轻提示用于「刚才那件事成功了」，提示条用于「从现在起你要知道这件事」。两者的生命周期不同，不能互相替代。

**速记**：提示条嵌在内容里不自动消失，分默认与危险两档，四段内容按图标标题说明操作排列。



#### 确认对话框

**确认对话框**：是只为一次确认而存在的对话框，用一段文字与两个按钮构成最短的决策闭环。

- 适用场景：不可撤销的操作、影响多条数据的操作、需要二次确认的提交。
- 标题写法：用动词加对象，直接说清楚要做什么。
- 说明写法：写清楚影响范围与不可撤销性，不写「确定要执行此操作吗」这类空话。
- 按钮措辞：确认按钮用具体动词，不使用「确定」与「取消」这类无法区分的措辞。
- 破坏性呈现：破坏性操作使用危险档按钮，并把焦点默认落在取消按钮上。

```tsx
import {
  AlertDialog,
  AlertDialogAction,
  AlertDialogCancel,
  AlertDialogContent,
  AlertDialogDescription,
  AlertDialogFooter,
  AlertDialogHeader,
  AlertDialogTitle,
} from "@/components/ui/alert-dialog"

export function ConfirmDelete({ open, onOpenChange, count, onConfirm }: { open: boolean; onOpenChange: (open: boolean) => void; count: number; onConfirm: () => void }) {
  return (
    <AlertDialog open={open} onOpenChange={onOpenChange}>
      <AlertDialogContent>
        <AlertDialogHeader>
          <AlertDialogTitle>删除 {count} 条记录</AlertDialogTitle>
          <AlertDialogDescription>删除后无法恢复，关联的附件也会一并移除。</AlertDialogDescription>
        </AlertDialogHeader>
        <AlertDialogFooter>
          <AlertDialogCancel>保留记录</AlertDialogCancel>
          <AlertDialogAction onClick={onConfirm}>确认删除</AlertDialogAction>
        </AlertDialogFooter>
      </AlertDialogContent>
    </AlertDialog>
  )
}
```

> 确认对话框的价值来自措辞而不是样式。按钮上写「确定」，用户唯一能做的事就是重新读一遍上面的说明——那说明这段话没有说清。

**速记**：确认对话框标题写动作加对象、说明写影响范围、按钮用具体动词、破坏性操作默认聚焦取消。



### 浮层的工程细节

外观做对只完成了一半，浮层真正的缺陷都藏在这三处。

#### 焦点管理

**焦点管理**：是控制打开与关闭浮层时键盘焦点落在哪里、关闭后回到哪里的机制。

- 打开时：焦点移入浮层内第一个可交互元素，或落在浮层容器本身。
- 循环约束：焦点在浮层内循环，不能 Tab 到背后的页面上去。
- 关闭后：焦点回到触发元素，而不是回到页面开头。
- 关闭时机：焦点移出浮层不自动关闭，避免误关；需要显式关闭或按退出键。
- 多层浮层：浮层内再开浮层时，关闭内层后焦点回到外层内的触发位置。

```tsx
// 关闭后把焦点还给触发元素，键盘用户才不会丢失位置
const triggerRef = React.useRef<HTMLButtonElement>(null)

function close() {
  setOpen(false)
  triggerRef.current?.focus()
}
```

> [!CAUTION]
> **注意内容**：关闭浮层后焦点回到页面开头，会让键盘用户每关一个浮层就要重新 Tab 一遍整页。这一条在鼠标用户身上完全观察不到，却会显著拖慢键盘操作速度。

**速记**：打开时焦点入浮层、浮层内循环、关闭后回到触发元素、焦点移出不自动关闭。



#### 层叠与滚动锁定

**滚动锁定**：是浮层打开时禁止背后页面滚动的处理；**层叠顺序**：是多个浮层同时出现时的前后关系。

- 锁定范围：打开对话框与抽屉时锁定页面滚动，打开气泡与下拉时不锁。
- 锁定副作用：锁定会改变滚动条宽度，需要在根元素上补等宽的占位，避免页面横向跳动。
- 层叠规则：按打开顺序递增，后开的在上层。
- 遮罩层级：遮罩与浮层之间要保持稳定的固定关系，避免遮罩盖住自己的浮层。
- 冲突处理：不同库各自管理层叠时容易出现顺序错乱，全站应统一用同一种浮层实现。

```css
/* 锁定滚动并补等宽占位，避免页面横向跳动 */
body[data-scroll-locked] {
  overflow: hidden;
  padding-right: var(--scrollbar-width, 0);
}
```

> [!WARNING]
> **警告内容**：不做滚动锁定，浮层打开时滚动滚轮会滚动背后的页面，用户关闭浮层后发现自己已经不在原来的位置。混合使用两套浮层实现时，这个问题几乎必然出现。

**速记**：对话框与抽屉锁滚动并补等宽占位、气泡与下拉不锁，层叠按打开顺序递增且全站统一实现。



#### 浮层内的表单

**浮层表单**：是放在浮层里的表单，比页面内表单多出三处必须处理的状态。

- 未保存拦截：关闭浮层时若有未保存改动，必须拦截并询问。
- 提交后行为：提交成功后关闭浮层并把结果以轻提示告知，失败时保留浮层并把错误落到字段。
- 校验焦点：校验不通过时焦点移到第一个出错字段，见第 6 篇。
- 高度处理：字段多时内容区滚动，底部操作固定，按钮始终可见。
- 状态重置：下次打开时表单必须回到初始取值，不残留上一次的输入。

```tsx
function handleOpenChange(next: boolean) {
  if (!next && formRef.current?.isDirty()) {
    setConfirmDiscard(true)
    return
  }
  if (next) formRef.current?.reset()
  setOpen(next)
}
```

> 浮层表单容易只做「提交成功关闭」这一条路径。真正影响使用的是另外两条：失败时留在原地，以及关掉时提醒有未保存内容。

**速记**：浮层表单要拦截未保存关闭、失败时保留浮层并落错误、内容区滚动、每次打开重置取值。



### 单色方案下的浮层层级

单色方案里，浮层与页面之间只能用阴影与遮罩拉开，没有颜色可用。

- 阴影唯一：只有浮层允许使用阴影，页面内的容器一律用边框，见第 7 篇。
- 遮罩强度：遮罩用极低不透明度的黑或白，深浅主题各取一套，保证背后的内容仍可辨认。
- 面差异：浮层面与页面面在深色主题下必须差一档明度，否则浮层看起来只是贴了一张边框。
- 危险色节制：同一浮层内最多一处危险色，出现在确认按钮或标题上，不同时出现。
- 焦点环可见：浮层内的焦点环必须清晰，这是键盘用户在浮层里唯一的定位依据。

```css
:root {
  --popover: oklch(1 0 0);
  --popover-foreground: oklch(0.145 0 0);
  --overlay: oklch(0 0 0 / 45%);
}

.dark {
  --popover: oklch(0.205 0 0);
  --popover-foreground: oklch(0.985 0 0);
  --overlay: oklch(0 0 0 / 65%);
}
```

> 浮层在单色方案里靠「比其他所有面都亮或都暗一档」来成立。当它和页面同档时，用户需要读完内容才知道这是一层浮层。
