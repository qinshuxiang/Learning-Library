## 黑白主题设计规范

本篇是本主题的规范篇：给出单色后台界面全部令牌的取值、对比度门槛与实测结果，以及可直接勾选的核对清单。取值不是审美结论，每一条都能用脚本复算。令牌的机制见第 4 篇，样式映射见第 3 篇，图表编码见第 11 篇，可访问性检查见第 14 篇。

### 令牌的取值依据

单色方案的取值只有一个维度可调，因此每一档都必须有明确理由，不能凭手感补中间档。

#### 明度阶梯的构造规则

**明度阶梯**：是把全部中性令牌按 OKLCH 亮度排成一条单调序列的取值集合，色度与色相通道一律为零。

- 通道约定：三元组写作亮度、色度、色相，单色方案要求后两个参数恒为零。
- 单调性：从页面底色到主文字的亮度必须单调递减，中间不允许出现回折。
- 档位来源：每一档都应能对应一个用途，不设「备用」档位。
- 取值个数：浅色主题有效的面档位控制在六个以内，再多就会出现无法区分的相邻面。
- 修改方式：改动某一档必须同时重算它上下相邻两档之间的对比度。

```css
/* 单色阶梯：色度与色相恒为零，只调第一个参数 */
:root {
  --background: oklch(1 0 0);        /* 1.000 页面底 */
  --sidebar: oklch(0.985 0 0);       /* 0.985 侧栏面 */
  --muted: oklch(0.97 0 0);          /* 0.970 弱面 */
  --border: oklch(0.922 0 0);        /* 0.922 边线 */
  --ring: oklch(0.64 0 0);           /* 0.640 焦点环 */
  --muted-foreground: oklch(0.54 0 0); /* 0.540 次要文字 */
  --primary: oklch(0.205 0 0);       /* 0.205 主色面 */
  --foreground: oklch(0.145 0 0);    /* 0.145 主文字 */
}
```

> 单色方案没有别的可调维度，所以「感觉这一档浅了一点」不构成改动的理由。要么算出来不达标，要么不动。

**速记**：单色阶梯色度色相恒为零、亮度单调递减、每档对应一个用途，改动需重算相邻对比度。



#### 浅色主题的完整令牌

**浅色令牌**：是单色方案在浅色外观下的全部取值，下表所列即为本规范的基准值。

- 基准色：使用完全无彩的基准色，任何带色相倾向的基准色都不适用。
- 两处修正：次要文字与焦点环两档取的是修正值，原因见下一节实测。
- 状态色：危险色是全套令牌里唯一保留色度的取值。
- 图表色：三级灰阶单独定义，见第 11 篇。
- 过渡色：主色悬停态用主色加九成不透明度近似得到，不单独定义令牌。

**速记**：浅色基准色必须完全无彩，次要文字取 0.54、焦点环取 0.64 是规范要求的修正值。



#### 深色主题的完整令牌

**深色令牌**：是单色方案在深色外观下的全部取值，与浅色令牌一一对应，数量必须严格相等。

- 对应要求：浅色有多少个令牌，深色就有多少个，不许多也不许少。
- 底面上移：深色下页面底取 0.145，卡片与浮层取 0.205，明度越高越靠前。
- 主色反转：深色下主色面取接近白的 0.922，主色前景取 0.205。
- 边线策略：边线默认用半透明白，属于装饰用途，见下一节的门槛界定。
- 焦点环：深色下焦点环取 0.556，在深底上达到门槛。

**速记**：深色令牌与浅色一一对应，页面底 0.145、卡片面 0.205、主色反转、边线用半透明白。



### 对比度门槛与实测

门槛是判定令牌是否合格唯一的客观依据。这一节给出门槛口径与全部实测结果。

#### 门槛取值与适用范围

**对比度**：是两个颜色的相对亮度之比，按国际通行的无障碍准则取值；**非文本对比**：是界面元素与相邻颜色之间需要达到的比值门槛。

- 正文文字：比值需达到 4.5 比 1，适用于十六像素以下的一般文字。
- 大字文字：比值需达到 3 比 1，适用于十八像素以上或十四像素以上加粗的文字。
- 非文本元素：比值需达到 3 比 1，适用于焦点环、图标、图形边界这类承载信息的元素。
- 装饰元素：纯装饰的分隔线与底色不适用上述门槛，但不得是识别控件边界的唯一手段。
- 计算口径：相对亮度必须在线性空间计算，拿到伽马编码值必须先解码，否则结果全错。

```js
// 相对亮度只吃线性通道；把伽马编码值直接代入，算出的比值会整体偏小
function luminance(linearRgb) {
  const [r, g, b] = linearRgb.map((c) => Math.min(1, Math.max(0, c)));
  return 0.2126 * r + 0.7152 * g + 0.0722 * b;
}

function contrast(fgLinear, bgLinear) {
  const a = luminance(fgLinear);
  const b = luminance(bgLinear);
  return (Math.max(a, b) + 0.05) / (Math.min(a, b) + 0.05);
}
```

> [!WARNING]
> **警告内容**：把伽马编码后的通道值直接当作线性值算相对亮度，是这一类脚本最常见的错误，它不会报错，只会把所有比值压低到失真，进而让人误判一批本来合格的取值。写脚本时先用纯白与纯黑验证：两者比值必须是 21 比 1。

**速记**：正文 4.5 比 1、大字与非文本元素 3 比 1、装饰元素不适用，相对亮度必须在线性空间计算。



#### 实测结果与三处修正

**实测表**：是用可复算脚本对每一对令牌取出的比值，是本规范唯一认可的判定方式。

- 合格项：主文字、主色前景、次色前景、侧栏文字、危险色与深色全部文字项均有余量。
- 修正一：次要文字在弱面上不达标，需要把亮度从 0.556 降到 0.54。
- 修正二：浅色焦点环在页面底上不达标，需要把亮度从 0.708 降到 0.64。
- 修正三：深色边线用半透明白时只有 1.25，只能作装饰；需要满足非文本门槛时改用实色。

#### 半透明令牌的合成口径

**半透明令牌**：是带透明度通道的颜色令牌，用于在任意底色上取到稳定的相对明暗，而不是固定色值。

- 合成顺序：先在半透明色与底色之间按透明度合成，再计算对比度。
- 合成空间：CSS 默认在伽马编码空间合成，脚本必须按同一规则实现才与浏览器一致。
- 深色优势：深底上叠白可以看到明暗随底色变化，浅底上叠黑同理。
- 达标限制：透明度越低，合成结果越接近底色，因此低透明度令牌几乎必然不达门槛。
- 使用边界：半透明令牌只用于分隔线与装饰底色，不用于焦点环与控件边界。

```css
/* 半透明令牌的适用边界 */
:root {
  --border: oklch(0.922 0 0);         /* 浅色：实色边线 */
  --divider: oklch(0 0 0 / 6%);        /* 装饰分隔线，可用半透明 */
}

.dark {
  --border: oklch(1 0 0 / 10%);        /* 深色：默认边线为装饰，需达标时改实色 */
  --border-strong: oklch(0.54 0 0);    /* 需满足 3 比 1 时的实色替代 */
}
```

> [!NOTE]
> **提醒内容**：深色主题下边线只有 1.25 比 1，看上去「明显不够」，但它是装饰而非识别依据：卡片之间还有底色差与留白。真正需要警惕的是把输入框边界也只交给这样一条线，那时它就成了唯一的识别手段，必须换成实色。

**速记**：半透明令牌按 CSS 规则在伽马空间合成，只用于分隔与装饰，控件边界需达标时换实色。



### 面、边线与状态的规则

把令牌的取值组织成可执行的界面规则，评审时才有可对照的标准。

#### 三层面的划分与顺序

**面的层次**：是界面中不同明度平面的数量与前后关系，单色方案要求面的层数尽可能少。

- 浅色顺序：页面底最浅，侧栏面次之，弱面再次之，边线最深。
- 深色顺序：页面底最深，卡片与浮层面次之，侧栏面再次之，弱面最浅。
- 层数上限：同屏出现三个以上的面时，改用边线或留白切分。
- 浮层例外：临时浮层可以取比页面更亮或更暗一档，并额外使用阴影。
- 顺序一致：同一层级在不同页面必须取同一个面，不允许按页面调整。

```css
:root {
  --background: oklch(1 0 0);      /* 页面底 */
  --sidebar: oklch(0.985 0 0);     /* 侧栏面 */
  --muted: oklch(0.97 0 0);        /* 弱面 */
  --border: oklch(0.922 0 0);      /* 边线 */
}
```

> 面的数量是单色界面的秩序来源。每多一层底色，就少一次被留白区分的机会。

**速记**：单色界面同屏面不超过三层，浅色由浅到深、深色由深到浅，同层级面在不同页面取值一致。



#### 边线与分隔的用法

**边线**：是划分边界的线条；**分隔**：是同一容器内部的区段线，二者宽度与颜色可以不同。

- 边线宽度：全站统一一个宽度，不按重要性调整。
- 分隔颜色：比边线更浅一档，且不使用虚线。
- 使用位置：容器外轮廓用边线，容器内部区段之间用分隔。
- 禁止重复：容器已有边线时，内部不再重复画外层边框。
- 与留白取舍：能用留白区分时优先留白，边线只用在留白不足以表达边界的地方。

```tsx
<section className="rounded-lg border border-border">
  <div className="border-b border-border/60 px-4 py-3 text-sm font-medium">筛选条件</div>
  <div className="p-4">{/* 内容 */}</div>
</section>
```

> [!WARNING]
> **警告内容**：稀疏排列的项目里，边线会渐渐被当成「强调」使用，最终每个区块都框起来。到这一步，边框已经不再表示边界，界面只能靠读取文字来理解结构。单色方案尤其要守住这一条。

**速记**：边线宽度全站统一、分隔比边线更浅且不用虚线，容器有边线时内部不重画，能留白就留白。



#### 状态色的使用边界

**状态色**：是单色方案里唯一保留色度的令牌组，用于表达需要被立刻识别的异常与破坏性操作。

- 允许位置：徽标、提示条、字段错误提示、破坏性按钮、图表中的异常点。
- 禁止位置：常规按钮、选中态、图标底色、卡片背景、页面标题。
- 同屏上限：同一视区内带状态色的元素不超过三个。
- 深浅取值：深色下的状态色需要单独取值，浅色取值放到深底上普遍过暗。
- 冗余标注：状态不能只靠颜色表达，必须同时给出文字说明。

```tsx
// 状态色只落在徽标与提示条上，并同时给出文字
<Badge variant="destructive">校验未通过</Badge>
```

```css
:root {
  --destructive: oklch(0.577 0.245 27.325);
}

.dark {
  --destructive: oklch(0.704 0.191 22.216);
}
```

> [!IMPORTANT]
> **重要内容**：状态色必须同时有文字说明。红绿色觉障碍人群看这两类颜色没有区别，只靠颜色表达的状态对他们等于不存在，而这条不需要额外成本，只是不要省掉那一行字。

**速记**：状态色只出现在徽标、提示条、字段错误与破坏性按钮，同屏不超过三处，且必须有文字冗余。



### 交付前的核对清单

提交主题改动前逐项确认，任何一项不通过都不进入主线。

- 通道检查：全部中性令牌的色度与色相是否为 0。
- 阶梯检查：亮度是否单调，是否存在无用途的备用档位。
- 数量检查：浅色与深色的令牌数量是否严格相等。
- 文字对比：正文项是否达到 4.5 比 1，且在弱面上也达到。
- 元素对比：焦点环在页面底与弱面上是否都达到 3 比 1。
- 边线界定：边线是否仅为装饰，凡作为唯一识别手段的边界是否已改实色。
- 状态节制：状态色是否只出现在允许位置，同屏是否不超过三处。
- 图表档位：灰阶阶梯的相邻对比度是否达到 3 比 1，系列数是否不超过三。
- 复算留痕：改动后的实测表是否已更新并随主题入库。

```bash
# 提交前的三步：重跑实测表、转灰度看图、核对深浅令牌数量
node tools/contrast-check.mjs
grep -c -- "^  --" src/styles/light.css src/styles/dark.css
```

> 清单的价值在于可重复执行。凭印象判断「看起来还行」是这类改动最容易出错的地方，因为对比度失效在单色方案里的表现只是「有点淡」，而不会显得明显异常。
