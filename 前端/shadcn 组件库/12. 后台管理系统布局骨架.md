## 后台管理系统布局骨架

骨架决定了页面的第一层结构：哪一块固定、哪一块滚动、内容在多宽的范围内排布。它一旦定错，后面所有页面的间距与滚动都会跟着别扭。本篇说明三段结构的划分、内容区的组织与密度档位的取舍。侧栏零件的用法见第 9 篇，卡片与面板见第 7 篇，间距取值见第 13 篇。

### 骨架的三段结构

后台骨架由侧栏、顶栏与内容区三部分组成，三者的高度与滚动关系是唯一的硬约束。

#### 侧栏、顶栏与内容区

**应用骨架**：是把导航、上下文与内容三块按固定关系摆放的最外层容器，决定全局的滚动行为。

- 侧栏：常驻在侧边，自身不参与页面滚动。
- 顶栏：横跨内容区宽度，可吸附在内容区顶部，不随内容滚走。
- 内容区：唯一的滚动容器，页面内的所有滚动都发生在它内部。
- 层级关系：三者与视口等高，任何一块超出视口高度都意味着滚动分配出了问题。
- 状态来源：侧栏折叠状态由提供者统一管理，见第 9 篇。

```tsx
import { SidebarInset, SidebarProvider, SidebarTrigger } from "@/components/ui/sidebar"

export function AppShell({ sidebar, header, children }: { sidebar: React.ReactNode; header: React.ReactNode; children: React.ReactNode }) {
  return (
    <SidebarProvider>
      {sidebar}
      <SidebarInset>
        {header}
        <main className="flex-1 overflow-y-auto p-4 md:p-6">{children}</main>
      </SidebarInset>
    </SidebarProvider>
  )
}
```

> 判断骨架是否正确的方法很简单：把页面滚到底，再看侧栏与顶栏是否还在原位。任一者被滚走，说明滚动容器挂错了层级。

**速记**：侧栏与顶栏不滚动，内容区是唯一滚动容器，三块与视口等高。



#### 高度与滚动的分配

**滚动分配**：是决定哪一层承担滚动条的策略，后台系统应把滚动限制在内容区一层。

- 高度基准：外层容器取视口高度的小视口单位，避免移动端地址栏收起时高度跳变。
- 单层滚动：只有内容区出现滚动条，侧栏与顶栏各自内部需要滚动时单独处理。
- 吸附定位：顶栏在内容区外层时天然固定；在内容区内部时需用吸附定位并声明层级。
- 滚动条占位：内容区出现或消失滚动条会引起宽度变化，需用等宽占位或稳定滚动条设置。
- 回到顶部：内容区滚动远超一屏时提供回到顶部入口，位置固定在内容区右下角。

```tsx
<div className="flex h-svh w-full overflow-hidden">
  <aside className="shrink-0">{/* 侧栏，内部独立滚动 */}</aside>
  <div className="flex min-w-0 flex-1 flex-col">
    <header className="h-14 shrink-0 border-b border-border">{/* 顶栏 */}</header>
    <main className="min-h-0 flex-1 overflow-y-auto">{/* 唯一滚动区 */}</main>
  </div>
</div>
```

> [!IMPORTANT]
> **重要内容**：内容区必须带上允许收缩的最小高度声明。缺少它时内容区被内容撑高，整页出现滚动条，侧栏随之被滚走，表现为「布局是好的，但只是滚一下就散了」。

**速记**：外层取视口高度、只有内容区滚动、侧栏与顶栏各管各的内部滚动，滚动条需等宽占位。



#### 变体选择与切换成本

**布局变体**：是侧栏与内容之间的贴合方式，分为紧贴、悬浮与内嵌三种观感。

- 紧贴变体：侧栏与内容区共用边界，视觉上是一整块，适合信息密集的系统。
- 悬浮变体：侧栏从边界向内缩进，自身带边框与圆角，适合内容较轻的系统。
- 内嵌变体：内容区整体嵌入侧栏留出的内框中，主内容需放进内嵌容器。
- 切换成本：变体改变的是外层留白与圆角，组件内部逻辑不变，可以随时更换。
- 选择建议：后台系统以信息密度为先，紧贴或内嵌变体比悬浮变体更实用。

```tsx
<SidebarProvider>
  <Sidebar variant="inset" collapsible="icon" />
  <SidebarInset>{/* 内嵌变体下，主内容必须放进内嵌容器 */}</SidebarInset>
</SidebarProvider>
```

> [!CAUTION]
> **注意内容**：使用内嵌变体时忘记把主内容放进内嵌容器，内容会直接铺满视口并穿过侧栏留下的内框，表现为内容区盖住了侧栏边缘。这一处不报错，只是看起来「哪里不对」。

**速记**：变体分紧贴、悬浮、内嵌三种，改动只涉及外层留白与圆角，内嵌变体必须配内嵌容器。



### 内容区的组织

内容区的结构在各类页面间是高度重复的，把它固化成模板能省下大量重复决策。

#### 页头与操作区

**页头**：是内容区顶部的固定区块，由标题、说明、主操作与面包屑组成，位置与顺序全站统一。

- 标题：页面名，与侧栏当前项一致。
- 说明：一句话交代页面用途或数据口径，只在需要时出现。
- 主操作：每页最多一个实心按钮，位置固定在页头右侧。
- 次操作：其余操作收进描边按钮或浮层菜单，见第 5 篇。
- 返回入口：详情页在页头左侧提供返回，与面包屑二选一不重复。

```tsx
export function PageHeader({ title, description, actions }: { title: string; description?: string; actions?: React.ReactNode }) {
  return (
    <div className="flex items-start justify-between gap-4 pb-4">
      <div className="min-w-0">
        <h1 className="truncate text-lg font-semibold">{title}</h1>
        {description ? (
          <p className="mt-1 text-sm text-muted-foreground">{description}</p>
        ) : null}
      </div>
      <div className="flex shrink-0 items-center gap-2">{actions}</div>
    </div>
  )
}
```

> 页头是全站重复次数最多的区块。它每处都重新设计一次，用户就要在每个页面重新找一次主操作在哪里。

**速记**：页头含标题、说明、主操作与面包屑，顺序全站固定，主操作每页最多一个且固定右置。



#### 页内分栏与主次关系

**页内分栏**：是把内容区再切成若干列的组织方式，按主次关系决定列宽比例。

- 主次分栏：主内容占主要宽度，辅助信息栏固定在右侧，比例取三比一。
- 辅助栏行为：辅助栏在窄屏下折到主内容下方，内容顺序不变。
- 两侧分栏：列表加详情的组合用两侧分栏，左列表右详情，比例取二比三。
- 分栏上限：同一层不超过两列，三列以上在 1280 宽度下会让每列过窄。
- 独立滚动：两侧分栏各自独立滚动，不共享滚动位置。

```tsx
<div className="grid gap-6 lg:grid-cols-[minmax(0,3fr)_minmax(0,1fr)]">
  <div className="min-w-0">{/* 主内容 */}</div>
  <aside className="min-w-0">{/* 辅助信息 */}</aside>
</div>
```

> [!TIP]
> **建议内容**：栅格列宽写成分数加最小宽度零的形式。不写最小宽度零时，表格与长文本会把列撑破，表现为横向滚动条出现在整页而不是表格内部。

**速记**：主次分栏三比一、两侧分栏二比三，同层不超过两列，窄屏下辅助栏折到主内容下方。



#### 列表页与详情页的骨架

**列表页骨架**：是「筛选加表格」的固定结构；**详情页骨架**：是「概要加分节」的固定结构，两者覆盖了后台系统绝大多数页面。

- 列表页顺序：页头、筛选区、批量操作条、表格、分页，从上到下。
- 筛选区行为：筛选条件超过四项时收进可折叠面板，默认收起。
- 批量条位置：表格上方，有选中项时出现，不占固定高度。
- 详情页顺序：页头、概要卡、分节内容、关联记录，从上到下。
- 分节折叠：分节超过四段时启用折叠，默认展开第一段。

```tsx
export function ListPage() {
  return (
    <div className="space-y-4">
      <PageHeader title="案件管理" actions={<Button>新建案件</Button>} />
      <FilterBar />
      <BulkBar />
      <DataTable />
      <TablePagination />
    </div>
  )
}
```

> 把这两套骨架固化下来之后，新页面的设计工作就只剩下「有哪些筛选条件、有哪些列」这两件事。

**速记**：列表页按页头、筛选、批量条、表格、分页排列，详情页按页头、概要、分节、关联记录排列。



### 密度与栅格

密度是后台系统最容易被忽略、也最影响长期使用体验的一个维度。

#### 间距的取值节奏

**间距节奏**：是把所有间距收敛到一条固定刻度上的做法，用少量取值覆盖全部场景。

- 刻度来源：间距由基准单位按倍数派生，见第 3 篇。
- 三级取值：区块之间用最大档，区块内部用中档，紧密元素之间用最小档。
- 数量约束：全站间距取值不超过六个，超出的取值说明刻度没被贯彻。
- 成对关系：内边距通常等于相邻两个元素之间间距的两倍，视觉上才平衡。
- 禁止硬编码：不写任意像素值，所有间距都从刻度上取。

```tsx
// 三级间距：区块之间 24，区块内部 16，元素之间 8
<div className="space-y-6">
  <section className="space-y-4">{/* 区块内部 */}</section>
  <section className="space-y-4" />
  <div className="flex gap-2">{/* 元素之间 */}</div>
</div>
```

> 间距是单色界面唯一还能用的层次手段。取值越多，界面越难显得整齐，而这一点无法用配色补救。

**速记**：间距收敛到一条刻度、全站取值不超过六个、区块间用最大档且内边距约为相邻间距两倍。



#### 内容宽度与留白分配

**内容宽度**：是内容区在一行内允许占据的最大宽度，用于控制长文本的行长。

- 行长控制：纯文本段落限制行长，超过后阅读时容易串行。
- 表格例外：表格类页面不限制宽度，允许占满并横向滚动。
- 表单例外：单列表单限制宽度，避免输入框被拉得过长。
- 大屏行为：超宽屏下不无限拉伸内容，改用居中并限制最大宽度。
- 两侧留白：限制宽度时留白留在两侧，不在单侧堆积。

```tsx
// 表单页限制宽度并居中；表格页不限制
<main className="min-h-0 flex-1 overflow-y-auto p-6">
  <div className="mx-auto w-full max-w-3xl">{/* 表单 */}</div>
</main>
```

> [!NOTE]
> **提醒内容**：表格页与表单页对宽度的诉求是相反的，因此宽度限制不能写在外层骨架里，只能按页面类型在页面层声明，否则总有一类页面要被牺牲。

**速记**：文本与表单限制最大宽度并居中，表格页允许占满，宽度约束写在页面层而非骨架层。



#### 密度档位与批量操作

**密度档位**：是同一种页面在行高与间距上的松紧切换，用于适配只读浏览与高频录入两种工作方式。

- 宽松档：行高更大、留白更多，用于核对与浏览。
- 紧凑档：行高与内边距同比例减小，用于高频录入与逐条处理。
- 切换位置：密度切换入口放在表格工具栏，与其他表格设置放在一起。
- 持久化：密度偏好按用户持久化，与列显隐偏好一并存储。
- 档位上限：同一系统内不超过两档，命名不用「大中小」而用「宽松紧凑」。

```tsx
const densityClass = density === "compact" ? "[&_td]:py-1.5 [&_th]:py-1.5" : "[&_td]:py-3 [&_th]:py-3"

<div className={densityClass}>{/* 表格 */}</div>
```

> [!WARNING]
> **警告内容**：把紧凑档做成默认会让新用户觉得界面拥挤，把宽松档做成默认会让熟练用户觉得一屏看不到几行。密度必须可切换且被记住，用一个默认值同时满足两种人是做不到的。

**速记**：密度分宽松与紧凑两档、按用户持久化、入口在表格工具栏，同系统不超过两档。



### 单色方案下的布局层级

黑白方案没有颜色可以划分区域，划分职责全部落在面、边线与留白三样东西上。

- 面不超过三层：页面底色、侧栏面、卡片面，超过三层时改用边线切分。
- 边线一处：同一容器只画一条边框，内部细分改用分隔线或加大留白。
- 留白承担分块：区块之间用最大档间距分隔，比加边框更不容易显得杂乱。
- 圆角一致：同层级容器取同一圆角档位，从派生刻度上取值。
- 顶栏与侧栏同档：两者同为最外层，用同一个边线宽度与同一个面。

```css
:root {
  --background: oklch(1 0 0);
  --sidebar: oklch(0.985 0 0);
  --card: oklch(1 0 0);
  --border: oklch(0.922 0 0);
}
```

> 单色界面的整洁来自「面少、边线少、留白稳定」，而不是来自更多的分组框。每多加一层底色，就多一次需要用边框去补救的混乱。
