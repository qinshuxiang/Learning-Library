## Tailwind 与 CSS 变量体系

组件的外观全部建立在样式变量之上：工具类负责把变量接进元素，变量本身承载主题。本篇说清这条链路的两端——样式入口与主题指令如何把变量变成可用的工具类，以及类名冲突如何收敛。变量取什么值属于主题决策，见第 4 篇；取值多少才达标，见第 13 篇。

### 样式底座的工作方式

样式的输入是一份含有主题变量的全局样式文件，输出是元素上的工具类。理解底座先要看清这两层各自负责什么。

#### 工具类与语义令牌的分工

**工具类**：是直接描述某条样式声明的原子类，一个类只承担一项；**语义令牌**：是按用途命名的样式变量，取值来自主题，与具体外观解耦。

- 工具类职责：定位、间距、排版、层叠与状态，写在元素上，随元素一起读改。
- 令牌职责：颜色、圆角、字体这类需要跨组件统一且随主题改变的取值。
- 组合方式：工具类引用令牌，元素只写语义类，不写具体色值。
- 硬编码禁令：元素上出现十六进制色值或绝对灰度时，主题切换立即失效。
- 判断标准：改一处令牌能全站生效的写法正确，需要逐处改元素的写法已经跑偏。

```tsx
// 语义类引用令牌，换主题时无需改动组件
<div className="bg-background text-foreground border-border rounded-lg border" />

// 硬编码色值：主题切换时这一块不会跟着变
<div className="bg-white text-black border-[#e5e5e5] rounded-lg border" />
```

> 判断一个组件是否接入主题，只需看它有没有出现具体色值。出现色值的地方就是主题的破口。

**速记**：工具类管布局与状态，令牌管取值与主题，元素上只写语义类，不写具体色值。



#### 样式入口与主题指令

**样式入口**：是全局样式文件里引入样式框架的那一行，它一次性装载默认主题、基础重置与工具类三部分。

- 装载内容：默认主题变量、元素基础重置、全部工具类三个层次一次到位。
- 主题指令：用于声明主题变量，位置必须在顶层，不能写进选择器或媒体查询内部。
- 覆盖与扩展：同名变量即覆盖默认值，新名字即新增一项工具类能力。
- 命名空间重置：把某命名空间的变量整体置为初始化值，可清空该组默认工具类。
- 常规变量：不需要生成工具类的变量仍可写在根选择器里，二者分工明确。

```css
@import "tailwindcss";

@theme {
  /* 新增一项颜色工具类：此后可写 bg-mint-500 */
  --color-mint-500: oklch(0.72 0.11 178);
}

@theme {
  /* 覆盖默认断点：sm 前缀的触发宽度随之改变 */
  --breakpoint-sm: 30rem;
}
```

> [!IMPORTANT]
> **重要内容**：主题指令必须写在全局样式的顶层。写进选择器或媒体查询内部不会报错，但该变量会被静默忽略，对应的工具类也不生成，排查起来要绕一大圈。

**速记**：样式入口一次装载默认主题、基础重置与工具类，主题指令必须在顶层声明。



#### 主题变量的取值时机

**取值时机**：指工具类里出现的是变量的引用还是变量的值，由是否使用内联修饰决定，这一差别直接决定嵌套场景下取到哪个值。

- 默认行为：工具类引用主题变量，变量在被引用的选择器上解析。
- 内联修饰：工具类直接使用主题变量的值，把解析提前到定义处。
- 嵌套差异：变量在父级被定义、在子级被覆盖时，默认行为取父级的值，内联修饰取定义处的值。
- 使用场合：主题变量引用另一个变量时用内联修饰，避免出现上述错位。
- 实践结果：组件库的令牌映射一律用内联修饰，这是接入语义令牌的标准写法。

```css
@theme inline {
  --color-background: var(--background);
  --color-foreground: var(--foreground);
}

:root {
  --background: oklch(1 0 0);
  --foreground: oklch(0.145 0 0);
}

.dark {
  --background: oklch(0.145 0 0);
  --foreground: oklch(0.985 0 0);
}
```

> [!CAUTION]
> **注意内容**：把这一段的内联修饰去掉，深色主题仍会生效，但嵌套在自定义变量作用域内的少数元素会取到浅色值，表现为局部「漏白」。这类缺陷只在特定嵌套结构下出现，靠肉眼抽查极难发现。

**速记**：令牌映射用内联修饰，让工具类直接取到变量值，避免嵌套作用域下取错父级取值。



### 令牌的命名空间与映射

主题变量的名字不是自由的：前缀决定它能生成哪一类工具类。掌握命名空间就等于掌握了可用的词汇表。

#### 颜色命名空间与工具类

**颜色命名空间**：是颜色类变量的固定前缀，命名空间内的每一项都会派生出背景、文字、边框、填充等一系列工具类。

- 派生规则：命名空间内定义一项，前景、背景、边框、填充等工具类同时可用。
- 现状取值：语义令牌通过内联修饰映射进该命名空间，组件只使用语义工具类。
- 原始色板：默认色板仍可用，但后台系统内禁止在元素上直接使用原始色阶。
- 状态色：危险色等状态色仍走语义令牌，不直接引用原始色阶，以便深浅主题分别取值。
- 图表色：图表用色同样以令牌形式存在，深浅主题各取一套，见第 11 篇。

```css
@theme inline {
  --color-background: var(--background);
  --color-foreground: var(--foreground);
  --color-muted: var(--muted);
  --color-muted-foreground: var(--muted-foreground);
  --color-border: var(--border);
  --color-ring: var(--ring);
  --color-destructive: var(--destructive);
}
```

> 原始色阶在后台系统里是禁用词。它的取值不随主题切换，一旦写进组件，深浅两套外观立刻分叉。

**速记**：颜色命名空间内定义一项即派生全套工具类，组件只用语义令牌，禁用原始色阶。



#### 圆角与间距的派生

**派生令牌**：是由一个基准值按固定比例计算出来的同类令牌，改基准值即改整条刻度。

- 圆角基准：一个基准圆角变量，派生出一整套从小到大按比例缩放的圆角。
- 中档等同基准：中间那一档直接等于基准值，是「基准」这个词的实际含义。
- 间距基准：间距由一个基准单位按倍数派生，所有内边距与外边距都落在同一条刻度上。
- 定制范围：组件允许在派生尺度之外单独指定取值，用于个别需要精确对位的场景。
- 规范要求：后台系统内圆角只允许取派生刻度上的值，不写任意数值。

```css
@theme inline {
  --radius-sm: calc(var(--radius) * 0.6);
  --radius-md: calc(var(--radius) * 0.8);
  --radius-lg: var(--radius);
  --radius-xl: calc(var(--radius) * 1.4);
}

:root {
  --radius: 0.625rem;
}
```

> 圆角不做派生而是逐处指定时，界面上会同时出现四五个近似的圆角，观感上表现为「不整齐」而不是「有变化」。

**速记**：圆角与间距都由一个基准值派生，中间档等于基准，容器内只取刻度上的值。



#### 自定义变体与数据属性

**自定义变体**：是给工具类追加可复用的条件前缀，让状态样式能用数据属性而非类名切换。

- 声明方式：在全局样式里声明变体名与它的选择器条件。
- 数据属性条件：以元素上的数据属性取值作为条件，适合由组件内部自行维护的状态。
- 深色变体：深色模式以根元素上的类名为条件声明，是必装的一个自定义变体。
- 组合能力：自定义变体可继续叠加其它变体，形成状态与断点的组合。
- 自定义工具类：需要一组固定声明的样式时，用工具指令声明，比反复写多个类名更省。

```css
@import "tailwindcss";

/* 深色变体：以根元素上的类名为条件 */
@custom-variant dark (&:is(.dark *));

/* 数据属性变体：由组件内部维护的展开状态 */
@custom-variant data-open {
  &:where([data-state="open"]),
  &:where([data-open]:not([data-open="false"])) {
    @slot;
  }
}

/* 自定义工具类：隐藏滚动条 */
@utility no-scrollbar {
  -ms-overflow-style: none;
  scrollbar-width: none;

  &::-webkit-scrollbar {
    display: none;
  }
}
```

> 用数据属性表达状态比用附加类名可靠：状态由组件自己维护时，不会因为外部忘记加类而丢样式。

**速记**：自定义变体给工具类加条件前缀，深色与展开态都用数据属性表达，成组样式用工具指令声明。



### 从工具类到语义类

组件文件里同时出现语义类与条件类名，两者如何拼接、冲突如何收敛，是样式层最后一段链路。

#### 语义类的生成链路

**生成链路**：是从令牌取值到元素样式的完整路径，任何一环断开都会表现为样式不生效。

- 第一环：根选择器与深色选择器里定义原始变量取值。
- 第二环：主题指令把原始变量映射进颜色命名空间。
- 第三环：命名空间派生出一整套语义工具类。
- 第四环：组件用变体函数把语义类与条件类组装成最终类名。
- 断环表现：样式完全不生效说明入口没引入；样式部分生效说明落在第二环或第三环。

```tsx
// 完整链路在组件里的样子
export function StatusDot({ tone = "idle" }: { tone?: "idle" | "active" | "failed" }) {
  return (
    <span
      className={cn(
        "inline-block size-2 rounded-full",
        tone === "active" && "bg-primary",
        tone === "idle" && "bg-muted-foreground",
        tone === "failed" && "bg-destructive"
      )}
    />
  )
}
```

> 样式不生效时按链路逐环排查，比在元素上反复试类名快得多：先确认入口引入，再确认映射，最后才看组件。

**速记**：取值、映射、派生、组装四环相扣，样式完全不生效优先查样式入口是否引入。



#### 类名冲突与合并

**类名冲突**：是同一元素上出现两条作用在同一属性上的工具类，实际生效的取决于样式表中的先后而非书写顺序。

- 冲突成因：条件分支各自带一组默认类时，后写的不一定覆盖先写的。
- 传统解法：靠层级与优先级堆叠，改动一处容易牵动别处。
- 本库解法：拼接后由合并函数按属性去重，保留最后一条同类声明。
- 覆盖方式：外部调用方传入的类名总是排在最后，因此能稳定覆盖组件默认类。
- 边界：合并函数只处理它认识的类名形态；自定义工具类需要单独登记才参与合并。

```tsx
// 合并函数让外部传入的类名稳定覆盖组件默认值
function Panel({ className, ...props }: React.ComponentProps<"div">) {
  return <div className={cn("rounded-lg border border-border p-4", className)} {...props} />
}

// 传入 p-6 时，合并后只保留 p-6
<Panel className="p-6" />
```

> [!WARNING]
> **警告内容**：在组件上叠加条件类名时，如果两条类名分别来自不同分支且都带内边距，书写顺序不决定胜负，必须依赖合并函数去重。手动调整类名顺序来「修」覆盖问题，会在构建配置变化后再次失效。

**速记**：冲突靠合并函数按属性去重解决，外部类名总在最后因此能稳定覆盖，手调顺序不可靠。



#### 类名辅助函数的职责

**类名辅助函数**：是把条件类名、数组与对象展开成一条类名字符串并去重的工具，项目内统一从同一个模块导入。

- 第一职责：展开条件表达式，把为假的项丢掉。
- 第二职责：展平数组与嵌套结构，允许按组书写类名。
- 第三职责：按属性合并冲突的工具类，保留最后一条。
- 存放位置：默认位于工具目录下，别名在配置文件的 utils 一项中声明。
- 使用纪律：组件内部拼接类名一律走它，不手写字符串相加。

```ts
import { clsx, type ClassValue } from "clsx"
import { twMerge } from "tailwind-merge"

export function cn(...inputs: ClassValue[]) {
  return twMerge(clsx(inputs))
}
```

> [!NOTE]
> **提醒内容**：辅助函数的三个职责里，只有第三个与本库绑定。外层未引入去重合入时，函数仍然可用，但类名冲突会重新回到「靠顺序碰运气」的状态，表现为偶发的样式失效。

**速记**：辅助函数展开条件、展平数组、按属性去重，组件内拼接类名一律走它。



#### 光标与基础层约定

**基础层约定**：是写在样式末尾的一组元素级默认声明，用于统一边框色、焦点轮廓与页面底色。

- 边框默认色：全元素默认边框色取自边框令牌，避免出现浏览器默认灰。
- 页面底色：页面根元素的背景与文字色直接绑定语义令牌。
- 焦点轮廓：默认轮廓色取自焦点环令牌，并按半透明处理，真正的可见焦点环仍由组件显式声明。
- 光标形态：样式框架改用默认光标后，按钮不再显示手形，需要手形得在基础层补一条声明。
- 书写位置：这组声明放在基础层末尾，位于令牌定义之后。

```css
@layer base {
  * {
    @apply border-border outline-ring/50;
  }

  body {
    @apply bg-background text-foreground;
  }

  button:not(:disabled),
  [role="button"]:not(:disabled) {
    cursor: pointer;
  }
}
```

> [!TIP]
> **建议内容**：后台系统的按钮数量大、误点代价高，建议在基础层统一恢复手形光标。逐组件补写既容易漏，也会让「光标是不是手形」变成无法统一评审的细节。

**速记**：基础层统一边框色、页面底色、焦点轮廓与光标形态，默认轮廓为半透明，可见焦点环由组件声明。
