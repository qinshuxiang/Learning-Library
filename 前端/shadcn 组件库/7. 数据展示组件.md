## 数据展示组件

这一类组件不改变数据，只负责把数据摆到该在的位置：把内容装进面、把身份压成头像、把状态收成徽标、把等待画成骨架。它们在后台系统里出现的最频繁，也最容易因为层级混乱而互相抵消。本篇按容器、标识、加载三组说明。表格与图表另立专题，见第 8 篇与第 11 篇。

### 容器与层级

面的数量决定页面的层次感。单色方案下，面的区分手段只有边框、底色与圆角三种。

#### 卡片的组成与部件

**卡片**：是承载一组相关信息的面容器，由头部、内容与脚部三段组成，头部又可细分为标题、说明与右上角操作。

- 头部三段：标题承担一句话结论，说明承担口径与时间范围，右上角操作承载本卡片级的动作。
- 内容段：只放一种主体内容，表格与图表不要混装在同一张卡里。
- 脚部段：放卡片级的次要操作或统计补充，内容为空时整段不渲染。
- 间距归属：内边距由卡片各段自行给出，使用方不额外包裹内边距容器。
- 嵌套限制：卡片内不再套卡片，需要分组时改用卡内小节与分隔。

```tsx
import {
  Card,
  CardAction,
  CardContent,
  CardDescription,
  CardFooter,
  CardHeader,
  CardTitle,
} from "@/components/ui/card"
import { Button } from "@/components/ui/button"

export function SummaryCard({ children }: { children: React.ReactNode }) {
  return (
    <Card>
      <CardHeader>
        <CardTitle>今日办理情况</CardTitle>
        <CardDescription>口径：受理件数，截至当日 18 时</CardDescription>
        <CardAction>
          <Button variant="ghost" size="sm">查看明细</Button>
        </CardAction>
      </CardHeader>
      <CardContent>{children}</CardContent>
      <CardFooter className="text-xs text-muted-foreground">数据每十分钟同步一次</CardFooter>
    </Card>
  )
}
```

> 卡片是「一组信息」的边界，不是「好看一点」的手段。把三张卡的内容塞进一张卡，只是把边界取消了，并没有让界面更整齐。

**速记**：卡片分头部、内容、脚部三段，一卡一种主体内容，卡内不套卡，间距由各段自持。



#### 抬升层级与边框的使用

**抬升**：是用阴影或底色让元素在视觉上浮起的做法；**边框**：是用线条划出边界而不改变底色的做法。

- 单色首选：黑白方案优先用边框而不是阴影表达层级，阴影在无彩色下容易发灰变脏。
- 阴影例外：只有真正浮在页面之上的临时元素（下拉、气泡、抽屉）使用阴影。
- 底色区分：卡片与页面同色时靠边框区分，卡片略浅或略深时靠底色区分，两者不叠加使用。
- 边框位置：边框只画一层，卡片上画了边框，内部小节就改用分隔线。
- 圆角一致：同一层级的容器使用同一个圆角档位，见第 3 篇的派生刻度。

```tsx
// 页面级容器用边框划分；内部小节用分隔线，不再重复画边框
<section className="rounded-lg border border-border bg-card">
  <div className="border-b border-border px-4 py-3 text-sm font-medium">筛选条件</div>
  <div className="p-4">{/* 表单 */}</div>
</section>
```

> [!IMPORTANT]
> **重要内容**：边框、底色、阴影三者同时叠加是最常见的层级失控方式，表现为块与块挤在一起、边界反而看不清。同一处只允许一种区分手段，这一条没有例外。

**速记**：单色优先用边框而非阴影，只有临时浮层用阴影，边框与底色不叠加，一层只画一条边。



#### 面板内的小节划分

**小节**：是面板内部按语义切出的区段，用于把一个长面板拆成若干可读的块。

- 划分依据：按阅读目的划分，不按数据来源划分。
- 标题层级：小节标题只在字段数量多且需要跳读时出现，字段少时不加标题。
- 分隔手段：小节之间用一条分隔线或加大留白，二者选一。
- 折叠：小节数超过四段时启用折叠，默认展开第一段。
- 顺序：按用户处理事务的顺序排列，不按系统内部的数据结构排列。

```tsx
import { Separator } from "@/components/ui/separator"

export function DetailPanel() {
  return (
    <div className="space-y-6">
      <section>{/* 基本信息 */}</section>
      <Separator />
      <section>{/* 关联记录 */}</section>
    </div>
  )
}
```

> [!TIP]
> **建议内容**：长详情面板的分节应当与用户查找信息的习惯一致。判断方法很简单：让使用者说出他会先看哪一块，如果当场说得出顺序，就按那个顺序排。

**速记**：小节按阅读目的划分，分隔线或大留白二选一，超过四段启用折叠并按事务顺序排列。



### 标识类元素

这一类元素把长度不定的内容压成固定尺寸，是维持列表对齐的关键。

#### 头像与身份标识

**头像**：是以固定尺寸呈现个人或组织身份的图形元素，图像缺失时回退为文字缩写。

- 回退内容：图像加载失败或未提供时，用姓名首字或首字母作为回退。
- 尺寸档位：列表用最小档，卡片头部用中档，详情页头部用最大档，档位不宜超过三档。
- 形状：同一系统内形状统一，要么全圆要么全方，不按场景切换。
- 状态点：在线状态一类标记用角标叠加，颜色只允许取状态令牌。
- 文字并置：头像旁必须给出可读的名字，头像本身不承担识别职责。

```tsx
import { Avatar, AvatarFallback, AvatarImage } from "@/components/ui/avatar"

export function OwnerCell({ name, src }: { name: string; src?: string }) {
  return (
    <div className="flex items-center gap-2">
      <Avatar className="size-6">
        <AvatarImage src={src} alt="" />
        <AvatarFallback className="text-[10px]">{name.slice(0, 1)}</AvatarFallback>
      </Avatar>
      <span className="truncate text-sm">{name}</span>
    </div>
  )
}
```

> 头像在无彩色方案里几乎没有信息量，它只是让列表行有了一个可对齐的锚点。把识别职责交给它，等于把信息藏起来。

**速记**：头像必须有文字回退，尺寸不超过三档、形状全局统一，旁边必须给出可读名字。



#### 徽章与计数标记

**计数标记**：是把数量或状态压成短标签的元素，用于列表与侧栏里标注需要关注的条目。

- 状态徽章：一个词表达状态，取值来源固定，不使用自由文本。
- 计数标记：纯数字，放在菜单项尾部或图标角上，超过两位数用加号缩写。
- 上限提示：同一行内徽章数量不超过两个，超过即说明这一行的信息没被组织好。
- 描边优先：单色方案下优先用描边档，实心档留给必须被立刻看到的条目。
- 一致性：同一列表内徽章的出现规则要统一，不要只给部分行加状态。

```tsx
import { Badge } from "@/components/ui/badge"
import { SidebarMenuBadge } from "@/components/ui/sidebar"

export function PendingRow({ count, status }: { count: number; status: string }) {
  return (
    <div className="flex items-center justify-between">
      <span className="text-sm">待办事项</span>
      <div className="flex items-center gap-2">
        <Badge variant="outline">{status}</Badge>
        <span className="text-xs text-muted-foreground tabular-nums">{count}</span>
      </div>
    </div>
  )
}
```

> 徽章的价值来自稀缺。当每一行都带一个徽章时，它从标记退化成了装饰，用户会直接跳过这一列。

**速记**：徽章承载固定取值集的状态词，计数超过两位用加号缩写，每行不超过两个，单色优先描边档。



#### 空状态与占位

**空状态**：是数据为空时替代内容区出现的说明性区块，承担「为什么空、接下来做什么」两件事。

- 三种成因：未创建任何数据、筛选后无结果、加载失败，三者的文案与操作各不相同。
- 构成要素：一句说明、一句补充、一个主要操作，最多再加一张极简图示。
- 筛选空态：必须给出清除筛选的入口，否则用户会以为系统坏了。
- 失败空态：必须给出重试入口，并说明是网络问题还是服务问题。
- 尺寸约束：空状态区块高度不小于内容区的最小高度，避免页面剧烈伸缩。

```tsx
export function EmptyResult({ onClear }: { onClear: () => void }) {
  return (
    <div className="flex min-h-64 flex-col items-center justify-center gap-3 text-center">
      <p className="text-sm font-medium">没有符合条件的记录</p>
      <p className="text-xs text-muted-foreground">当前筛选条件过窄，可放宽后重试。</p>
      <Button variant="outline" size="sm" onClick={onClear}>清除筛选</Button>
    </div>
  )
}
```

> [!CAUTION]
> **注意内容**：把「暂无数据」用于全部空场景，会让用户无法判断是自己筛得太窄、系统出了问题，还是本来就该是空的。三种成因必须给出三套不同的文案与操作。

**速记**：空状态分未创建、筛选无结果、加载失败三类，各配不同文案与操作，筛选空态必须给清除入口。



### 加载与过渡

等待是数据界面不可避免的状态。这一组组件解决的是「等待期间界面长什么样」。

#### 骨架屏的形态对应

**骨架屏**：是用占位块预先画出内容大致形态的加载表现，目的是让内容到达时的布局变化最小。

- 形态对应：骨架块的尺寸与位置应贴近真实内容的尺寸与位置。
- 数量匹配：骨架块数量取默认页大小，不要固定写死一个数字。
- 结构覆盖：只覆盖会变化的数据区，页头与侧栏不重绘。
- 时长阈值：请求可能在一瞬间返回时不要显示骨架，避免闪烁。
- 避免旋转：骨架块保持静止，不做扫光动画，减少长时间停留时的干扰。

```tsx
import { Skeleton } from "@/components/ui/skeleton"

export function DetailSkeleton() {
  return (
    <div className="space-y-3">
      <Skeleton className="h-5 w-40" />
      <Skeleton className="h-4 w-full" />
      <Skeleton className="h-4 w-4/5" />
    </div>
  )
}
```

> [!WARNING]
> **警告内容**：骨架屏的形状与真实内容差得远时，内容到达的瞬间会发生整块跳动，用户会认为页面「卡了一下」。骨架屏的前提是与真实布局对齐，做不到对齐时，宁可只放一个居中的进度指示。

**速记**：骨架块尺寸与位置贴近真实内容、数量按页大小、结构只覆盖数据区、短请求不显示骨架。



#### 进度指示的选用

**进度指示**：是在操作进行期间表示「正在处理但尚未完成」的元素，分为不确定时长与已知进度两类。

- 不确定进度：用旋转指示，适用于时长不可预估的请求。
- 已知进度：用进度条，并给出当前百分比，适用于批量导入一类可计量的操作。
- 定位方式：全局操作用页面级指示，局部操作用按钮内或卡片内的指示。
- 文字配合：超过三秒仍未完成时补一句当前阶段的文字说明。
- 可中断：长任务应提供取消入口，取消后必须把界面恢复到可操作状态。

```tsx
import { Progress } from "@/components/ui/progress"
import { Spinner } from "@/components/ui/spinner"

export function ImportProgress({ percent }: { percent: number | null }) {
  if (percent === null) return <Spinner className="size-4" />
  return (
    <div className="space-y-2">
      <Progress value={percent} />
      <p className="text-xs text-muted-foreground tabular-nums">已处理 {percent}%</p>
    </div>
  )
}
```

> 进度指示的作用是消除「还要不要等」这个疑问。只转圈不给阶段说明，用户在三秒后就会开始怀疑。

**速记**：时长不可预估用旋转指示、可计量用进度条加百分比，超三秒补阶段说明，长任务提供取消。



#### 局部刷新与高度稳定

**局部刷新**：是只更新页面某一块数据的加载方式，与整页刷新相对，需要显式处理另两种视觉状态。

- 刷新中的三种表现：首次加载显示骨架、再次加载在顶部显示细进度条、保留旧数据。
- 旧数据策略：翻页与筛选时保留上一批数据并降低不透明度，比清空重画更不打断。
- 高度锁定：表格与列表容器应锁定最小高度，避免数据条数变化时页面推挤。
- 滚动保持：刷新后保持滚动位置，不自动回到顶部，除非是筛选条件发生变化。
- 状态提示：刷新失败时保留旧数据并给出一条可关闭的提示，不要清空内容。

```tsx
export function DataRegion({
  loading,
  stale,
  children,
}: {
  loading: boolean
  stale: boolean
  children: React.ReactNode
}) {
  return (
    <div className="min-h-80">
      {loading && stale ? <div className="h-0.5 w-full animate-pulse bg-muted" /> : null}
      <div className={stale ? "opacity-60 transition-opacity" : "transition-opacity"}>{children}</div>
    </div>
  )
}
```

> [!NOTE]
> **提醒内容**：清空重画是最省事也最打扰人的做法。后台系统里翻页与筛选极其频繁，一次清空就意味着一次整屏空白，长期使用下会显著降低操作速度。

**速记**：局部刷新区分首次与再次加载，翻页筛选保留旧数据并降不透明度，容器锁最小高度并保持滚动位置。



### 单色方案下的层级表达

把容器、标识、加载三组的取舍收拢成可直接照做的规则。

- 两层面：页面底色一层、卡片面一层，第三层靠边框与留白切出，不新增底色。
- 边框一处：同一容器上只出现一条边框，内部细分用分隔线。
- 同层同角：同一层级的容器取同一圆角档位。
- 中性优先：状态的表达优先用文字与边框，徽章与角标是例外而非默认。
- 数据等宽：所有数值列使用等宽数字，避免刷新时宽度抖动。

```css
:root {
  --background: oklch(1 0 0);
  --card: oklch(1 0 0);
  --muted: oklch(0.97 0 0);
  --border: oklch(0.922 0 0);
}
```

```tsx
// 数值列统一等宽数字，刷新时列宽不抖动
<td className="px-4 py-2 text-right tabular-nums">{amount}</td>
```

> 单色界面的层次感来自「面少而边界清楚」，而不是「面多」。每多引入一层底色，就多一层需要用边框去挽救的混乱。
