## 环境初始化与 CLI 工作流

命令行工具是这套代码唯一的入口：组件写入、差异比对、迁移与注册表检索都通过它完成。本篇给出初始化前的环境前提、初始化时会被写死的三项选择、以及日常工作中真正高频的四组命令。组件写入之后的样式底座见第 3 篇，主题令牌的取值见第 4 篇与第 13 篇。

### 环境前提与选型

初始化之前先确认运行时、包管理器与框架三者都落在支持范围内，否则命令行工具会在写入阶段才报错。

#### 运行时与框架要求

**支持矩阵**：是命令行工具认可的框架与构建工具组合，落在矩阵内可直接初始化，落在矩阵外需按手动步骤接入。

- 官方模板：Next.js、Vite、TanStack Start、React Router、Astro 五类可直接脚手架。
- 特殊前置：Laravel 需先用其自带命令建好应用，再执行初始化。
- 运行前提：React 项目需使用函数组件与 Hooks 写法，类组件不走这套组合接口。
- 样式前提：必须使用 Tailwind CSS v4 作为样式层，命令行工具依赖其主题变量机制。
- 手动路径：其它框架按官方手动接入章节逐项配置，配置项与自动初始化结果一致。

```bash
# 落在模板矩阵内：一条命令完成脚手架与初始化
pnpm dlx shadcn@latest init -t vite

# 已在使用的项目：先确认 Tailwind v4 已接入，再初始化
pnpm dlx shadcn@latest init
```

> 判断能不能用这套代码，先看样式层是不是 Tailwind v4；组件的外观完全建立在主题变量之上，缺少这一层时组件能写入但不会正常显示。

**速记**：支持五类框架模板，前提是函数组件与 Tailwind v4，其余框架走手动接入。



#### 包管理器与项目脚手架

**脚手架**：是命令行工具把项目骨架、依赖与初始化配置一次性落地的过程，可用参数跳过全部交互。

- 执行方式：以临时执行方式调用最新版命令行工具，不把它装进项目依赖。
- 默认配置：默认参数会锁定官方默认模板与预设，适合想快速看到结果时使用。
- 命名与目录：可在指定目录下建项目并同时指定项目名。
- 静默模式：自动化脚本里用静默参数关掉交互输出，避免日志被交互提示打断。
- 目标目录：在已有项目里执行时用工作目录参数指定根目录，适合多包仓库。

```bash
# 非交互地新建一个项目：默认模板、默认预设、指定名字
pnpm dlx shadcn@latest init -t next -n admin-console -y

# 在已有项目里初始化，并指定工作目录
pnpm dlx shadcn@latest init -c packages/admin

# 自动化脚本里静默执行
pnpm dlx shadcn@latest init -t vite -n admin-console -y -s
```

> [!TIP]
> **建议内容**：后台管理系统建议固定用同一个模板初始化，让团队内所有项目共享同一条升级路径；混用模板会让组件之外的部分（构建配置、入口结构）产生分叉，抵消掉统一组件带来的收益。

**速记**：用临时执行方式调用工具，非交互参数适合自动化，已有项目用工作目录参数指定根目录。



#### 初始化方式的三条路径

**初始化路径**：是把这套代码接入项目的方式，分为可视化预设、命令行脚手架与手动配置三类。

- 可视化预设：在官方创建页配色、圆角、字体与图标，导出预设码或直接生成命令。
- 命令行脚手架：在终端里按提示逐项选择，适合已有明确技术栈的项目。
- 手动配置：逐项配置依赖、样式入口与路径别名，用于框架不在模板矩阵内的情形。
- 预设复用：预设码可在其它项目上套用，也可以只套用主题或字体两个部分。
- 结果一致性：三条路径的最终产物一致，差别只在于人工参与的多少。

```bash
# 把某套预设应用到已有项目，也可以只套用主题或字体
pnpm dlx shadcn@latest apply a2r6bw
pnpm dlx shadcn@latest apply a2r6bw --only theme
pnpm dlx shadcn@latest apply a2r6bw --only font

# 查看预设对应的信息与创建链接
pnpm dlx shadcn@latest preset decode a2r6bw
pnpm dlx shadcn@latest preset resolve
```

> [!IMPORTANT]
> **重要内容**：预设会把主题令牌整体覆盖。团队项目在套用预设前必须先提交当前的工作区改动，否则自定义过的令牌会被静默替换，且无法与业务改动分开回退。

**速记**：可视化预设、命令行脚手架、手动配置三条路径产物一致，预设可只套用主题或字体。



### 初始化参数详解

初始化时会写死三项不可回改的选择，必须在这一步就按后台系统的实际需求定下来。

#### 模板、底层实现与预设

**模板参数**：决定脚手架生成的框架骨架；**底层实现参数**：决定组件属性的透传写法；**预设参数**：决定初始的主题令牌与字体。

- 模板取值：next、vite、start、react-router、astro 五类，与框架一一对应。
- 实现取值：base、radix、aria 三类，对应三套无障碍底层，选定后组合写法随之固定。
- 默认配置：默认参数会一次性锁定默认模板与默认预设，追求最快见效时使用。
- 强制覆盖：已有配置需要重建时用强制参数，会覆盖既有配置与样式入口。
- 重置代价：底层实现与样式方案不在可回改之列，选错只能删掉组件重新安装。

```bash
# 指定模板、底层实现与预设
pnpm dlx shadcn@latest init -t vite -b radix -p nova

# 一键采用默认配置
pnpm dlx shadcn@latest init -d

# 覆盖既有配置重新初始化
pnpm dlx shadcn@latest init -f
```

> 初始化阶段真正需要认真决策的只有两件事：哪一套无障碍底层，以及用不用样式变量。其余参数都能事后调整。

**速记**：模板、底层实现与预设决定初始形态，底层实现与样式方案不可回改，选错要重装组件。



#### components.json 字段

**components.json**：是命令行工具读取的项目配置文件，描述样式方案、路径归属与组件来源，仅在用命令行工具时需要。

- style：组件样式方案，初始化后不可更改，历史值 new-york 与新版预设名并存。
- tailwind.config：Tailwind 配置路径，使用 v4 时留空。
- tailwind.css：引入 Tailwind 的全局样式文件路径，主题令牌就写在这个文件里。
- tailwind.baseColor：初始令牌所用的基准色，决定中性灰的色相倾向。
- tailwind.cssVariables：是否使用样式变量生成语义令牌，初始化后不可更改。
- tailwind.prefix：工具类前缀，用于避免与既有样式冲突。
- rsc：是否支持服务端组件，开启后自动为客户端组件补上指令。
- tsx：组件以 TypeScript 还是 JavaScript 写入。
- aliases：components、ui、lib、hooks、utils 五个导入根，决定文件落在哪里。
- iconLibrary：图标库，决定新增组件时引用哪一套图标。
- registries：多注册表配置，支持私有源与鉴权头。

```json
{
  "$schema": "https://ui.shadcn.com/schema.json",
  "style": "new-york",
  "rsc": false,
  "tsx": true,
  "tailwind": {
    "config": "",
    "css": "src/index.css",
    "baseColor": "neutral",
    "cssVariables": true
  },
  "aliases": {
    "components": "@/components",
    "ui": "@/components/ui",
    "lib": "@/lib",
    "hooks": "@/hooks",
    "utils": "@/lib/utils"
  },
  "iconLibrary": "lucide"
}
```

> [!CAUTION]
> **注意内容**：baseColor 决定的是中性灰带不带色相倾向。黑白单色后台必须选 neutral，选成 stone 或 zinc 会让整套灰阶带上暖调或冷调，单色规范随之失效，且初始化后无法通过改配置回退。

**速记**：components.json 描述样式方案、路径归属与组件来源，其中样式方案、基准色与是否用变量三项不可回改。



#### 基准色与色相倾向

**基准色（base color）**：是初始化时生成整套中性令牌所依据的色相方案，决定灰阶偏暖、偏冷还是完全无彩。

- neutral：色度为零的纯灰，是黑白单色方案的唯一正确选择。
- stone：偏暖的灰，带少量黄红色相，观感偏纸感。
- zinc：偏冷的灰，带少量蓝色相，是很多界面框架的默认观感。
- mauve、olive、mist、taupe：带更明显色彩倾向的中性色，用于有调性诉求的场景。
- 迁移手段：已选错基准色时用迁移命令改写主题变量，但组件内已手改过的取值会被跳过并上报。

```bash
# 把项目主题迁移到另一个基准色；已自定义过的令牌会被跳过并列出
pnpm dlx shadcn@latest migrate base-color --to neutral --yes
pnpm dlx shadcn@latest migrate base-color --from zinc --to neutral
```

> 单色方案的判定标准是色度通道为零。只要灰阶带上一丝色相，「无彩色」这个前提就不成立，第 13 篇的对比度取值也不再适用。

**速记**：黑白单色必须选 neutral，其余六个基准色都带色相倾向，选错用迁移命令改写主题变量。



#### 路径别名的两种解析方式

**路径别名**：是把导入说明符映射到实际目录的机制，命令行工具依据它决定组件写到哪、导入语句怎么写。

- 配置位置一：写在 TypeScript 或 JavaScript 配置的路径字段里，配合基础路径使用。
- 配置位置二：写在包的导入字段里，配合打包器解析与包导入解析开关使用。
- 扩展名差异：映射目标不带扩展名时生成不带扩展名的导入，带扩展名时保留扩展名。
- 别名必需：无论用哪种解析方式，components.json 里的五个别名都必须填写。
- 多包仓库：本地包用包导入字段解析，跨包导入由目标包的导出字段解析。

```json
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": { "@/*": ["./src/*"] }
  }
}
```

```json
{
  "imports": {
    "#components/*": "./src/components/*.tsx",
    "#lib/*": "./src/lib/*.ts"
  },
  "aliases": {
    "components": "#components",
    "ui": "#components/ui",
    "utils": "#lib/utils"
  }
}
```

> 别名写错时命令行工具不会失败，而是把组件写到推导出来的错误位置，或在导入语句里留下解析不了的路径。初始化后先加一个组件确认落点，再开始写业务。

**速记**：别名可用 TypeScript 路径或包导入字段解析，两种方式都必须同步填写 components.json 的五个别名。



### 命令族与日常工作流

日常工作真正用到的是四组命令，其余属于一次性或排障用途。

#### 添加、预览与试运行

**添加命令**：是把注册表里的组件写入项目并补齐依赖的命令，支持试运行与批量添加。

- 批量添加：可一次给出多个组件名，也可用全量参数写入全部组件。
- 指定路径：可用路径参数改变本次写入目录，用于临时验证。
- 试运行：只打印将要发生的改动而不落盘，适合评估影响范围。
- 覆盖写入：目标文件已存在时默认跳过，需覆盖须显式声明。
- 静默执行：自动化脚本里关闭交互输出，避免等待输入。

```bash
# 常用组合：一次写入一组成套组件
pnpm dlx shadcn@latest add button card badge table input select

# 先看会改什么，再决定落盘
pnpm dlx shadcn@latest add sidebar --dry-run

# 覆盖已有文件
pnpm dlx shadcn@latest add button -o
```

> [!WARNING]
> **警告内容**：覆盖写入会直接丢掉该文件上已有的自定义改动，且没有二次确认以外的保护。组件文件一旦开始按本规范定制，就不要再对同一文件使用覆盖参数，改用差异命令逐处合并。

**速记**：添加命令支持批量、指定路径、试运行与覆盖，覆盖会丢掉已有自定义改动。



#### 差异比对与版本升级

**差异比对**：是把本地组件文件与上游同版本对照，找出本项目相对上游的全部偏离。

- 比对范围：单文件比对适合排错，整目录比对适合升级前的整体评估。
- 内容预览：内容命令直接打印上游文件原文，用于确认上游写法。
- 升级判定：只合并缺陷修复与无障碍修正，纯外观差异一律按本规范取舍。
- 依赖核对：同步确认底层依赖的主版本变化，避免只改组件不改依赖。
- 落地方式：升级以独立提交完成，与业务改动分开，便于整体回退。

```bash
# 排错时看单文件差异
pnpm dlx shadcn@latest add button --diff

# 升级前看整目录相对上游的偏离
pnpm dlx shadcn@latest add --all --diff
```

> 差异比对的产物是「本项目改了什么」，不是「上游改了什么」。把它当作自定义清单来维护，升级才有据可依。

**速记**：差异比对单文件排错、整目录评估升级，只合并缺陷修复，升级做成独立提交。



#### 注册表检索与私有源

**检索命令**：是在一个或多个注册表里按名称或关键字查找可用组件的命令。

- 注册表指定：可一次给出多个注册表，用命名空间加以区分。
- 关键字过滤：用查询参数过滤结果，并按数量与偏移分页。
- 内容查看：查看命令在安装前打印候选组件的完整内容，用于比对实现。
- 组件文档：文档命令拉取指定组件的用法与接口参考。
- 项目信息：信息命令输出当前项目的配置与依赖概况，排障时先跑它。

```bash
# 在官方注册表里按关键字找组件
pnpm dlx shadcn@latest search @shadcn -q "table" -l 20

# 安装前查看候选实现，避免引错同名组件
pnpm dlx shadcn@latest view @shadcn data-table

# 排障第一步：确认工具读到的项目配置
pnpm dlx shadcn@latest info
```

> [!NOTE]
> **提醒内容**：私有注册表可以用环境变量占位符承载凭据，这些占位符在运行时展开。把凭据直接写进 components.json 会随仓库一起提交，属于必须避免的写法。

**速记**：检索支持多注册表与关键字分页，查看命令用于安装前比对实现，排障先跑项目信息命令。



#### 迁移与依赖还原

**迁移命令**：是把既有组件批量改写以适配新方案的命令，覆盖图标库、基准色、工具函数与书写方向四类。

- 工具函数迁移：把类名合并工具收敛到统一的辅助函数。
- 图标迁移：重写图标导入与用法并更新配置，无对应图标者跳过并列出。
- 基准色迁移：改写主题令牌并更新配置，已自定义的令牌跳过并列出。
- 书写方向迁移：把物理方向属性改为逻辑方向属性，并补充方向变体。
- 依赖还原：把共享样式从依赖中内联进全局样式并移除该依赖，属不可逆操作。

```bash
# 图标库迁移：从一套图标换到另一套
pnpm dlx shadcn@latest migrate icons --from lucide --to tabler --yes

# 把共享样式内联进全局样式，并移除该依赖；此操作不可逆
pnpm dlx shadcn@latest eject
```

> [!CAUTION]
> **注意内容**：依赖还原操作不可逆，执行后上游对共享样式的更新不再自动生效。只有在需要彻底脱离该依赖或必须锁死全部样式时才使用，常规项目不要执行。

**速记**：迁移覆盖图标、基准色、工具函数与书写方向，依赖还原不可逆且会切断上游样式更新。



### 与既有项目的衔接要点

接入已有项目时，容易出问题的不是组件本身，而是构建配置与样式入口这两处。

- 别名对齐：先确认构建配置里的别名与 components.json 一致，再写第一个组件。
- 样式入口：全局样式文件必须真正被应用入口引入，否则主题令牌不会生效。
- 样式层顺序：主题变量声明应位于样式导入之后，避免被默认主题覆盖。
- 字体变量：自定义字体以变量形式声明，再由主题映射到字体工具类上。
- 提交边界：初始化的产物（配置、样式入口、工具函数）与首个业务组件分开提交。

```css
@import "tailwindcss";

@custom-variant dark (&:is(.dark *));

@theme inline {
  --color-background: var(--background);
  --color-foreground: var(--foreground);
}

:root {
  --background: oklch(1 0 0);
  --foreground: oklch(0.145 0 0);
}
```

> 初始化后先跑一次构建并打开页面，确认背景与文字色来自令牌而不是浏览器的默认白底黑字；这是判断接入是否成功最快的办法。

**速记**：接入要点是别名对齐、样式入口被真正引入、主题声明位于导入之后，产物与业务组件分开提交。
