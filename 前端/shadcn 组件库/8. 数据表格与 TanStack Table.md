## 数据表格与 TanStack Table

表格是后台系统的主界面：列表页、审核页、对账页的主体都是一个按列组织的数据区。本篇先区分两种表格形态，再说明数据表格的实例化与交互能力。列里出现的状态徽标见第 7 篇，翻页与筛选的加载表现见第 7 篇末节。表格的外观取值见第 13 篇。

### 表格的两种形态

表格组件只提供结构与样式，不提供数据逻辑。先分清「够不够用」再谈引入表格引擎。

#### 静态表格与数据表格

**静态表格**：是把已经排好序的数据按行渲染出来的表格，不含排序、筛选与分页；**数据表格**：是在静态表格之上接入表格引擎，由引擎计算行与列的行为。

- 静态适用：固定行数、不需要排序筛选的小型列表，如详情页里的关联记录。
- 数据适用：行数不受控、需要排序、筛选、分页、列显隐或行选择的列表页。
- 引擎角色：表格引擎只负责计算，不负责渲染，渲染仍由表格原语完成。
- 引入代价：数据表格需要维护列定义与状态，行数少时属于过度设计。
- 判断标准：列表页出现任意一个交互列头或页码时，就应该上数据表格。

```tsx
// 静态表格：数据已排好序，直接渲染
import {
  Table,
  TableBody,
  TableCell,
  TableHead,
  TableHeader,
  TableRow,
} from "@/components/ui/table"

export function SimpleTable() {
  return (
    <Table>
      <TableHeader>
        <TableRow>
          <TableHead>名称</TableHead>
          <TableHead className="text-right">数量</TableHead>
        </TableRow>
      </TableHeader>
      <TableBody>
        <TableRow>
          <TableCell>受理件</TableCell>
          <TableCell className="text-right tabular-nums">128</TableCell>
        </TableRow>
      </TableBody>
    </Table>
  )
}
```

> 表格引擎不会让静态表格变得更好看。它的全部价值在于把排序与筛选的计算从业务代码里拿走。

**速记**：静态表格只渲染、数据表格接引擎算行为，出现交互列头或页码时才引入引擎。



#### 表格原语的职责划分

**表格原语**：是表格组件的六个组成件，各对应一个表格语义元素，共同构成一张可样式化的表格。

- 容器件：包裹整张表格，负责横向溢出与边框。
- 表头件：包裹表头行，负责表头区的底色与文字层级。
- 行件：一行，负责悬停与选中态。
- 表头单元件：一个表头格，承载列名或排序按钮。
- 数据单元件：一个数据格，承载单元格内容。
- 表体件：包裹全部数据行。
- 单元格对齐：对齐方式由使用方在单元件上声明，组件不自作判断。

```tsx
<Table>
  <TableHeader>
    <TableRow>
      <TableHead className="w-24">编号</TableHead>
      <TableHead>名称</TableHead>
      <TableHead className="text-right">数量</TableHead>
      <TableHead className="w-16" />
    </TableRow>
  </TableHeader>
  <TableBody>{/* 数据行 */}</TableBody>
</Table>
```

> [!IMPORTANT]
> **重要内容**：表格原语不含任何数据逻辑，接引擎与不接引擎用的是同一套原语。因此引入引擎属于纯逻辑增量，不会带来样式返工，可以等到确实需要时再上。

**速记**：六个原语一一对应表格语义元素，对齐由使用方声明，接引擎与否共用同一套原语。



#### 数字、日期与状态列的对齐

**列对齐**：是按列内取值的类型确定横向对齐方式，目的是让同列数字的位数可以竖直比对。

- 文本列：左对齐，长文本单行截断并在悬停时显示完整内容。
- 数值列：右对齐，使用等宽数字，千分位与小数位数全列统一。
- 日期列：统一格式并左对齐，同列不混用两种日期写法。
- 状态列：左对齐并用徽标承载，宽度固定，避免长短状态词把列撑开。
- 操作列：贴右边缘，固定列宽，不随窗口缩放变化。

```tsx
<TableCell className="text-right tabular-nums">{formatNumber(row.amount)}</TableCell>
<TableCell className="truncate" title={row.title}>{row.title}</TableCell>
<TableCell>
  <Badge variant="outline">{row.statusLabel}</Badge>
</TableCell>
```

> 数值右对齐加等宽数字，是表格里成本最低、收益最直接的一条规则。缺了它，比较金额这件事只能靠眼睛逐位对齐。

**速记**：文本左对齐、数值右对齐加等宽数字、日期统一格式、状态用徽标、操作列固定贴右。



### 数据表格的实现

接入表格引擎要写三样东西：特性声明、列定义与实例化。三者分工明确。

#### 实例化与特性声明

**特性声明**：是显式声明本次表格用到哪些能力对象，未声明的能力会被打包器裁掉，从而减小体积。

- 实例接口：新版本用统一的表格钩子，把特性对象与数据一起传入。
- 核心行模型：始终内置，不需要手工注册。
- 可选行模型：分页、排序、筛选等能力各由对应的行模型工厂创建并注册到特性对象上。
- 旧版差异：早期版本用另一套钩子，并通过若干取行模型的选项逐一开启能力，这些选项在新版中已不再存在。
- 迁移成本：两套写法的差别集中在实例化与列定义两处，渲染部分不变。

```ts
// 声明本次表格用到的能力，未声明的会被裁掉
import {
  columnFilteringFeature,
  columnVisibilityFeature,
  createFilteredRowModel,
  createPaginatedRowModel,
  createSortedRowModel,
  filterFn_includesString,
  rowPaginationFeature,
  rowSelectionFeature,
  rowSortingFeature,
  sortFn_alphanumeric,
  sortFn_text,
  tableFeatures,
} from "@tanstack/react-table"

export const features = tableFeatures({
  columnFilteringFeature,
  columnVisibilityFeature,
  rowPaginationFeature,
  rowSelectionFeature,
  rowSortingFeature,
  filteredRowModel: createFilteredRowModel(),
  paginatedRowModel: createPaginatedRowModel(),
  sortedRowModel: createSortedRowModel(),
  filterFns: { includesString: filterFn_includesString },
  sortFns: { alphanumeric: sortFn_alphanumeric, text: sortFn_text },
})

export type DataTableFeatures = typeof features
```

```tsx
const table = useTable({ features, data, columns })
```

> [!CAUTION]
> **注意内容**：早期版本的写法在网上存量极大，直接照抄会出现「传了取行模型的选项却毫无反应」的现象，因为新版本已经不再读取这些选项。接入前先确认依赖的主版本，再决定用哪一套写法。

**速记**：特性声明显式列出用到的能力，核心行模型内置，可选行模型由工厂创建，早期版本的取行模型选项已废弃。



#### 列定义与访问器

**列定义**：是描述每一列取值来源、表头内容与单元格渲染方式的声明，与数据分离。

- 访问器列：取值直接来自数据对象的某个字段，是最常见的一类。
- 展示列：没有对应字段，只负责渲染内容，用于操作列与序号列。
- 表头函数：表头内容需要用到列状态（如当前排序方向）时写成函数。
- 单元格函数：需要格式化或嵌入组件时写成函数，接收行对象。
- 类型参数：列定义需要知晓特性对象的类型，才能在单元格里用上对应能力。

```tsx
import { createColumnHelper } from "@tanstack/react-table"
import type { DataTableFeatures } from "./data-table-features"

export type Record = {
  id: string
  name: string
  amount: number
  status: "pending" | "done" | "failed"
}

const columnHelper = createColumnHelper<DataTableFeatures, Record>()

export const columns = columnHelper.columns([
  columnHelper.accessor("name", { header: "名称" }),
  columnHelper.accessor("amount", {
    header: () => <div className="text-right">金额</div>,
    cell: ({ row }) => (
      <div className="text-right tabular-nums">{row.getValue<number>("amount").toFixed(2)}</div>
    ),
  }),
  columnHelper.display({
    id: "actions",
    cell: ({ row }) => <RowActions record={row.original} />,
  }),
])
```

> 列定义与数据分离后，同一套列可以复用在导出、打印与移动端卡片视图上。把格式化逻辑写在渲染循环里就失去了这份复用。

**速记**：列定义分访问器列与展示列，表头与单元格可写成函数，列定义需带上特性对象的类型参数。



#### 状态托管与受控

**状态托管**：指排序、筛选、分页等状态由组件自己保存还是由外部传入，二者决定了数据从哪来。

- 自托管：状态在组件内部，引擎直接在传入的完整数据上完成排序与分页，适合一次性取全量数据。
- 受控：状态由外部持有并传给引擎，数据由服务端按当前条件返回，适合大表与需分享链接的场景。
- 受控写法：每个状态配一个变化回调，把新状态写回外部状态。
- 服务端分页：需要把当前页与页大小一并传给接口，并把总行数回传给引擎。
- 选择策略：单次返回行数少于千级时用自托管，超过或需深链时改为受控。

```tsx
const [sorting, setSorting] = React.useState<SortingState>([])
const [columnFilters, setColumnFilters] = React.useState<ColumnFiltersState>([])
const [rowSelection, setRowSelection] = React.useState({})

const table = useTable({
  features,
  data,
  columns,
  state: { sorting, columnFilters, rowSelection },
  onSortingChange: setSorting,
  onColumnFiltersChange: setColumnFilters,
  onRowSelectionChange: setRowSelection,
})
```

> [!WARNING]
> **警告内容**：在受控模式下仍然把全量数据传给引擎，是后台列表页最常见的性能事故：接口只返回一页，表格却按全量计算排序与筛选，用户看到的排序结果与预期不一致，而页面上没有任何报错。

**速记**：小数据自托管让引擎算，大数据受控由外部持有状态并走服务端，受控时不要再用全量数据。



### 交互能力

表格的可用性取决于四类交互是否齐全，缺任何一项都会把用户推回浏览器的复制粘贴。

#### 排序与筛选

**排序**：是按某一列取值重排行序；**筛选**：是按列条件过滤出符合条件的行，两者都应有可见的状态回显。

- 排序入口：可排序列的表头渲染为按钮，点击在升序、降序、取消三态间循环。
- 排序标记：当前排序列必须显示方向箭头，且同一时刻只允许一列参与排序，除非明确需要多列。
- 筛选位置：列筛选放在列头内的浮层里，全局搜索放在表格上方的工具栏。
- 筛选项回显：已生效的筛选条件必须以可关闭的标签形式显示在表格上方。
- 条件组合：多个筛选条件之间的关系要在界面上说明，不能默认按交集处理而不告知。

```tsx
columnHelper.accessor("name", {
  header: ({ column }) => (
    <Button
      variant="ghost"
      size="sm"
      onClick={() => column.toggleSorting(column.getIsSorted() === "asc")}
    >
      名称
      <ArrowUpDownIcon data-icon="inline-end" />
    </Button>
  ),
})
```

> 排序与筛选不出现在界面上时，用户唯一的选择就是把全部数据导出到表格软件里处理。后台系统的价值有一大半就损失在这里。

**速记**：可排序列表头做按钮并显示方向，列筛选入列头、全局搜索入工具栏，生效条件必须以标签回显。



#### 分页与页大小

**分页**：是把结果集切成若干页的控制，需要同时给出页码、总条数与页大小三处信息。

- 信息齐全：只给页码不给总条数，用户无法判断还要翻多久。
- 页大小：提供几个固定档位，默认值取列表实际可读行数，不要写死为十。
- 边界态：首页禁用上一页、末页禁用下一页，而不是隐藏按钮。
- 跳转：页码较多时提供直接输入页码的入口。
- 计数口径：总条数应与当前筛选条件对应，不要把全表条数当作筛选后的总数。

```tsx
<div className="flex items-center justify-between">
  <p className="text-xs text-muted-foreground tabular-nums">
    共 {total} 条，第 {page} / {pageCount} 页
  </p>
  <div className="flex items-center gap-2">
    <Button variant="outline" size="sm" disabled={page <= 1} onClick={() => setPage(page - 1)}>
      上一页
    </Button>
    <Button
      variant="outline"
      size="sm"
      disabled={page >= pageCount}
      onClick={() => setPage(page + 1)}
    >
      下一页
    </Button>
  </div>
</div>
```

> 分页控件是唯一能告诉用户「数据有多少」的地方。把它简化成一个下一页按钮，用户就失去了对数据规模的判断。

**速记**：分页同时给出页码、总数与页大小，边界态禁用而非隐藏，总数按筛选后的结果统计。



#### 行选择与批量操作

**行选择**：是在每行前提供勾选以对多行施加同一操作，需要明确选择范围与状态保持规则。

- 表头勾选：表头勾选框选中当前页，并明确标注是「选中本页」还是「选中全部结果」。
- 跨页保持：勾选状态跨页保持，并在工具栏显示已选条数。
- 批量工具条：有选中项时在表格上方出现批量操作条，无选中项时隐藏或置灰。
- 破坏性操作：批量删除一类操作必须二次确认，并在确认框里写明影响条数。
- 清除入口：必须提供一键清除全部选择，避免用户逐行取消。

```tsx
{selectedCount > 0 ? (
  <div className="flex items-center justify-between rounded-md border border-border px-3 py-2">
    <span className="text-sm tabular-nums">已选 {selectedCount} 条</span>
    <div className="flex items-center gap-2">
      <Button variant="outline" size="sm" onClick={clearSelection}>清除选择</Button>
      <Button variant="destructive" size="sm" onClick={confirmDelete}>批量删除</Button>
    </div>
  </div>
) : null}
```

> [!NOTE]
> **提醒内容**：跨页保持选中是易被忽略的一条。翻页时清空选择会让批量操作在大表上无法使用，用户只能一页一页重复操作；而这一点在只有十几条测试数据的开发环境里永远暴露不出来。

**速记**：表头勾选需标明范围，跨页保持选中并回显条数，批量条按需出现，破坏性操作二次确认并写明条数。



#### 行操作与列显隐

**行操作**：是挂在单行末尾的一组动作，通常收进浮层菜单以控制表格宽度。

- 收起方式：超过两个动作时收进浮层菜单，常用动作可外露一个。
- 动作顺序：按使用频率降序，破坏性动作永远排在末位并用分隔线隔开。
- 列显隐：列数较多时提供列显隐控制，并把该偏好持久化。
- 列宽：为关键列设定固定宽度，其余列自适应，避免窗口变化时列宽乱跳。
- 键盘：行操作应可用键盘触发，浮层菜单需支持方向键移动与回车选中。

```tsx
<DropdownMenu>
  <DropdownMenuTrigger asChild>
    <Button variant="ghost" size="icon" aria-label="更多操作">
      <MoreHorizontalIcon />
    </Button>
  </DropdownMenuTrigger>
  <DropdownMenuContent align="end">
    <DropdownMenuItem>查看详情</DropdownMenuItem>
    <DropdownMenuItem>复制编号</DropdownMenuItem>
    <DropdownMenuSeparator />
    <DropdownMenuItem variant="destructive">删除</DropdownMenuItem>
  </DropdownMenuContent>
</DropdownMenu>
```

> [!TIP]
> **建议内容**：列显隐偏好建议按用户维度持久化，而不是按浏览器会话。后台人员通常有稳定的查看习惯，每次打开都要重新勾选列会持续消耗耐心。

**速记**：行操作超过两个收进浮层并让破坏性动作置末，列显隐偏好持久化，关键列设固定宽度。



### 单色方案下的表格密度

表格是黑白方案里最考验间距的地方：没有颜色帮忙，行与行之间只能靠线与留白区分。

- 行高两档：宽松档用于行内操作较多的表，紧凑档用于只读明细，同一系统内不超过两档。
- 分隔优先：行之间用极浅的分隔线或极弱的斑马纹，二者只取其一。
- 表头处理：表头用弱色面加中等字重，不用深色填充，避免整块压过数据。
- 悬停与选中：悬停用强调交互面，选中用略深一档的同色，两者不能都靠边框表达。
- 焦点可见：整行可点击时行本身也要有可见焦点，键盘用户才找得到当前行。

```tsx
<TableRow className="hover:bg-accent/60 data-[state=selected]:bg-accent">
  <TableCell className="py-2 text-sm">{row.name}</TableCell>
  <TableCell className="py-2 text-right text-sm tabular-nums">{row.amount}</TableCell>
</TableRow>
```

> 表格的可读性几乎全部来自「对齐、等宽、行高一致」三件事，配色能提供的信息量非常有限；黑白方案不过是把这一点提前暴露出来。
