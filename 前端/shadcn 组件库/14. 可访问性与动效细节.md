## 可访问性与动效细节

可访问性不是附加项，而是这套组件体系的既定前提：组件底层的键盘交互与语义由无障碍库提供，使用方要做的只是不去破坏它。本篇说明使用方真正需要负责的三块——键盘与焦点、语义与播报、动效与偏好。对比度门槛与实测见第 13 篇，浮层的焦点管理见第 10 篇。

### 键盘与焦点

键盘可用性是后台系统里收益最直接的一项：高频录入的用户几乎全程不碰鼠标。

#### 可达顺序与跳转链接

**可达顺序**：是按下制表键时焦点在页面上的移动次序，默认与文档结构顺序一致。

- 结构对齐：把结构按阅读顺序排列，可达顺序就自动正确，不要用正的次序值去修正。
- 顺序值：次序值只允许出现零与负一，正数会把焦点顺序从结构中剥离。
- 跳转链接：页面第一个可聚焦元素应是跳到主内容的链接，仅在聚焦时可见。
- 地标划分：页面用主内容、导航、补充内容三个地标元素划开，让跳转可落在区域级。
- 折叠区处理：收起的内容不应留在可达顺序里，隐藏要同时移出焦点。

```tsx
// 跳到主内容：常态隐藏，聚焦时可见
<a
  href="#main"
  className="sr-only focus:not-sr-only focus:absolute focus:left-4 focus:top-4 focus:z-50 focus:rounded-md focus:border focus:border-border focus:bg-background focus:px-3 focus:py-2"
>
  跳到主内容
</a>
```

> [!IMPORTANT]
> **重要内容**：用正的次序值调整焦点顺序，会造成焦点在页面上跳跃、跳过中间元素，且结构稍有改动就全部失序。让结构顺序本身正确是唯一可持续的做法。

**速记**：可达顺序由结构决定，次序值只用零与负一，首个可聚焦元素是跳到主内容链接，并用地标划分区域。



#### 可见焦点的判定

**可见焦点**：是键盘用户判断「当前在哪个元素上」的唯一依据，必须有确定的样式且达到对比门槛。

- 判定条件：焦点环必须在键盘聚焦时出现，在鼠标点击时可以不出现。
- 选择器：用仅键盘聚焦的选择器，避免鼠标点击后也留下焦点环。
- 对比要求：焦点环与相邻颜色的对比度需达到 3 比 1，见第 13 篇。
- 覆盖范围：被裁切、溢出隐藏或处于滚动容器内的元素，焦点环不能被切掉。
- 禁止清零：移除默认轮廓时必须提供替代样式，不能只写轮廓为无。

```css
/* 键盘聚焦时显示焦点环，鼠标点击不显示 */
:focus-visible {
  outline: 2px solid var(--ring);
  outline-offset: 2px;
}
```

> [!WARNING]
> **警告内容**：把默认轮廓去掉而不提供替代样式，会让键盘用户彻底失去位置感，这是所有无障碍缺陷里后果最严重、修复成本最低的一条。任何一次去掉轮廓的改动都必须在同一次提交里补上替代样式。

**速记**：焦点环用仅键盘聚焦选择器触发、对比度达 3 比 1、不被裁切，禁止只去掉轮廓不给替代。



#### 快捷键的分配与冲突

**快捷键**：是不经过界面元素直接触发功能的按键组合，需要一套全局分配规则以免互相覆盖。

- 修饰键约定：全局快捷键使用功能键或控制键组合，避免覆盖浏览器与系统的既有组合。
- 冲突检查：新增快捷键前先检索既有分配，同组合不允许承载两个功能。
- 可视提示：快捷键必须在界面上有可发现的入口，不能只写在文档里。
- 作用域：页面级快捷键在输入框聚焦时必须让位，避免输入字母触发动作。
- 列表导航：列表内的上下移动用方向键，配合回车确认，符合用户既有预期。

```tsx
function useHotkey(combo: string, handler: () => void) {
  React.useEffect(() => {
    function onKeyDown(event: KeyboardEvent) {
      const target = event.target as HTMLElement
      if (target.closest("input, textarea, [contenteditable]")) return
      if (combo === "mod+k" && (event.metaKey || event.ctrlKey) && event.key === "k") {
        event.preventDefault()
        handler()
      }
    }
    window.addEventListener("keydown", onKeyDown)
    return () => window.removeEventListener("keydown", onKeyDown)
  }, [combo, handler])
}
```

> [!CAUTION]
> **注意内容**：单字母快捷键在录入类后台系统里几乎必然出错：用户在搜索框外的任意位置按下该字母，都会触发一次意外跳转。字母类快捷键必须带修饰键，或限定在明确的非输入区域内生效。

**速记**：全局快捷键用功能键组合、分配前查重、界面上要有入口、输入框聚焦时让位。



### 语义与播报

辅助技术读到的内容决定了非视觉用户能否完整使用系统。

#### 名称与标签

**可访问名称**：是控件被辅助技术播报时读出的名字，来源可以是可见文字、关联标签或显式标注。

- 可见优先：能用可见文字时就用可见文字，眼睛与播报读到的是同一份信息。
- 图标按钮：只有图标的按钮必须显式标注名称，标注内容对视觉用户隐藏。
- 表单关联：标签与控件必须建立关联，见第 6 篇的字段族。
- 名称一致：可见文字与标注名称应保持一致，不一致时语音控制的用户无法用可见文字操作。
- 装饰元素：纯装饰的图标与图形需要从辅助技术中隐藏。

```tsx
<Button variant="ghost" size="icon" aria-label="关闭">
  <XIcon aria-hidden="true" />
</Button>
```

> 图标按钮的可访问名称是这类界面最高频的遗漏。一个全是图标按钮的工具栏，对屏幕阅读器用户来说就是一片「按钮、按钮、按钮」。

**速记**：可访问名称优先取自可见文字，图标按钮必须显式标注，标注名与可见文字保持一致。



#### 状态变化与即时播报

**即时播报**：是通过播报区域把不改变焦点的事件结果读给辅助技术，用于提交结果、校验错误与计数变化。

- 播报区域：页面内设置一个持久的播报容器，内容变化时自动读出。
- 语气档位：一般信息用礼貌档，错误与阻断类信息用强势档，二者不可互换。
- 轻提示：轻提示必须挂上播报语气，否则屏幕阅读器用户收不到操作回执。
- 表单错误：字段级错误应在出现时播报，见第 6 篇的错误落点。
- 计数变化：批量选择条数这类实时数字变化需要播报，但应做节流，避免每勾一项读一次。

```tsx
<div aria-live="polite" aria-atomic="true" className="sr-only">
  {status}
</div>
```

> [!NOTE]
> **提醒内容**：视觉用户与屏幕阅读器用户收到反馈的路径完全不同：前者靠看见，后者靠播报。任何只做了视觉反馈的交互，对后者等于没有反馈，而这一点在开发过程中几乎不会被发现。

**速记**：设置持久播报容器，信息用礼貌档、错误用强势档，轻提示与表单错误都必须挂播报。



#### 结构与表格语义

**表格语义**：是表格元素及其内部行、列、标题的对应关系；**结构语义**：是页面分节使用的标题层级与地标元素。

- 表格关联：表头单元格需声明其作用范围，数据单元格才能被正确播报。
- 标题层级：页面内标题层级连续，不跳级，标题文本本身可读。
- 单标题一：每页只有一个最高级标题，与页面名对应。
- 地标元素：导航、主内容、补充内容用语义标签划分，不用普通容器加标注模拟。
- 描述表格：数据表格必须有一段文字说明它的口径与排序规则，与表格关联。

```tsx
<Table>
  <TableHeader>
    <TableRow>
      <TableHead scope="col">编号</TableHead>
      <TableHead scope="col" aria-sort="ascending">受理时间</TableHead>
    </TableRow>
  </TableHeader>
</Table>
```

> 用普通容器加标注模拟语义，能得到播报但得不到浏览器的原生行为。语义元素能做的事，不要用标注去补。

**速记**：表头声明作用范围、标题层级连续不跳级、每页一个最高级标题、地标用语义标签划分。



### 动效

动效在这类系统里只服务两件事：说明层级变化与提示状态切换，不做装饰。

#### 时长与缓动

**过渡时长**：是状态变化从开始到结束的时间；**缓动**：是这段变化的速度曲线。

- 时长分档：悬停与聚焦在极短时间内完成，浮层进出用中档，页面级过渡用较长档。
- 档位数量：全站时长取值不超过三档，与间距一样收敛到固定刻度。
- 缓动选择：进入用减速曲线，退出用加速曲线，位移与缩放用同一条曲线。
- 变色与位移：变色只改颜色属性，不要触发重排；位移只用变换与透明度。
- 禁止动画属性：不对宽高与位置做动画，它们会触发布局重算。

```css
:root {
  --duration-fast: 100ms;
  --duration-base: 180ms;
  --duration-slow: 260ms;
  --ease-out: cubic-bezier(0.16, 1, 0.3, 1);
  --ease-in: cubic-bezier(0.7, 0, 0.84, 0);
}
```

> [!TIP]
> **建议内容**：把时长收敛成三个变量，比逐组件调时长省事得多，也让「这个过渡有点慢」这类反馈变成一次可执行的改动而不是各说各话。

**速记**：时长不超过三档，进入用减速、退出用加速，只对颜色与变换做动画，不动宽高与位置。



#### 减少动效偏好的尊重

**减少动效偏好**：是用户在系统层面表达的对动画敏感或不适的设定，页面必须响应它。

- 响应范围：位移、缩放、旋转、视差与自动播放一律在偏好开启时取消。
- 保留范围：纯颜色与透明度的短过渡可以保留，它们是层次提示而非运动。
- 实现方式：用媒体查询声明，把动画与过渡置为近乎瞬时。
- 例外标注：个别必须保留的动效用小范围覆盖，不做全局例外。
- 验证方式：在系统设置里开启该偏好，逐个走查浮层、列表与图表。

```css
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

> [!CAUTION]
> **注意内容**：全局把过渡时长压到接近零时，颜色过渡也会一起消失，浮层的进出会显得生硬。若这不可接受，应只对位移动画取消，保留颜色与透明度过渡，而不是整体一刀切。

**速记**：减少动效偏好开启时取消位移缩放旋转与自动播放，可保留颜色与透明度过渡，并逐处走查验证。



#### 加载与跳转的视觉衔接

**视觉衔接**：是页面或区块在加载、跳转与刷新之间保持视觉连续的做法，避免出现整屏空白。

- 骨架对齐：骨架屏的形状与真实内容对齐，见第 7 篇。
- 高度稳定：切换筛选与翻页时锁定容器最小高度，避免内容区高度跳变。
- 滚动处理：跳转到新页面时回到顶部，更新当前页数据时保持滚动位置。
- 焦点落点：路由跳转后把焦点移到主内容标题，键盘用户才知道页面换了。
- 图表例外：图表在首帧测量前留出占位高度，避免布局因图表出现而整体下移。

```tsx
// 路由跳转后把焦点移到主内容标题
React.useEffect(() => {
  document.getElementById("page-title")?.focus()
}, [routeKey])
```

> [!WARNING]
> **警告内容**：单页应用的路由跳转不会触发浏览器的焦点重置，键盘用户跳页后焦点仍停在侧栏菜单里，需要重新 Tab 一整页。把焦点移到主内容标题只有几行代码，漏掉的代价却是每个页面都要多操作一次。

**速记**：骨架与真实内容对齐、翻页锁最小高度、跳页回顶且更新时保持滚动、跳转后焦点移到主内容标题。



### 可访问性检查清单

提交前逐项走查，键盘相关项必须实测，不能靠阅读代码判断。

- 键盘全程：不用鼠标可否完成页面的全部操作。
- 焦点可见：每个可聚焦元素在键盘聚焦时都有清晰焦点环。
- 焦点循环：浮层内焦点循环，关闭后回到触发元素。
- 跳转链接：页面第一个可聚焦元素是跳到主内容。
- 顺序自然：没有正的次序值，可达顺序与阅读顺序一致。
- 名称齐全：图标按钮与图形控件都有可访问名称。
- 状态播报：提交结果、校验错误与计数变化均被播报。
- 标题层级：页面只有一个最高级标题，层级不跳级。
- 动效响应：开启减少动效偏好后，位移与缩放动画消失。
- 对比达标：文字与界面元素按第 13 篇的实测表核对。

```bash
# 走查顺序：只用键盘过一遍，再开减少动效偏好过一遍
# 制表键走完全部可交互元素 -> 记录焦点丢失与顺序异常的位置
# 打开系统减少动效偏好 -> 逐个打开浮层与图表 -> 记录仍在动的元素
```

> 清单里最容易被跳过的是「只用键盘过一遍」这一项。它不需要任何工具，却能一次性发现绝大多数可访问性缺陷，成本远低于逐条读代码推断。
