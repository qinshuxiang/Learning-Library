## 图表与数据可视化

后台系统里的图表只有两个用途：让趋势被看见，让异常被找到。黑白方案把这两件事的难度抬高了——系列之间不能再靠色相区分，只能靠明度与图案。本篇说明图表的构成方式、单色方案的编码规则与常用图形的取舍。配色的通用原则见数据可视化主题，令牌的对比度依据见第 13 篇。

### 图表的构成方式

图表组件不封装图表库，只提供容器、配置对象与两个可选的浮层组件，图形本身仍由图表库组件搭建。

#### 容器与配置对象

**图表配置**：是把系列的显示名、图标与颜色集中声明的一份对象，与数据分离，可跨图复用。

- 容器职责：提供尺寸上下文与颜色变量作用域，是图表的必备外层。
- 配置键：以数据中的字段名为键，值为该系列的显示名、图标与颜色。
- 颜色取值：颜色可以是色值，也可以引用主题令牌，单色方案必须引用令牌。
- 键与数据对应：配置的键必须与数据字段名一致，否则该系列取不到颜色。
- 尺寸要求：容器必须给出高度或宽高比，否则首次渲染时无法测量。

```tsx
import { type ChartConfig, ChartContainer } from "@/components/ui/chart"
import { Bar, BarChart } from "recharts"

const chartConfig = {
  received: { label: "受理", color: "var(--chart-2)" },
  closed: { label: "办结", color: "var(--chart-3)" },
} satisfies ChartConfig

export function CaseChart({ data }: { data: { month: string; received: number; closed: number }[] }) {
  return (
    <ChartContainer config={chartConfig} className="h-64 w-full">
      <BarChart accessibilityLayer data={data}>
        <Bar dataKey="received" fill="var(--color-received)" radius={2} />
        <Bar dataKey="closed" fill="var(--color-closed)" radius={2} />
      </BarChart>
    </ChartContainer>
  )
}
```

> [!IMPORTANT]
> **重要内容**：配置对象与数据分离，是为了让同一套系列颜色在多张图之间保持一致。把颜色写在图里，同一指标在两张图上取了不同灰阶，用户会以为它们是两个指标。

**速记**：配置对象以字段名为键声明显示名与颜色，与数据分离并跨图复用，容器必须给出高度或宽高比。



#### 提示与图例

**提示浮层**：是悬停某一点时显示该点详细信息的小浮层；**图例**：是把颜色映射回系列名称的元素。

- 提示内容：系列名、数值与单位三样齐全，数值按该列的格式统一。
- 提示与图例的选择：四类图表容器都提供自己的提示与图例组件，需显式引入才生效。
- 图例位置：置于图形上方或下方，不遮挡数据。
- 直接标注优先：系列不超过三个时优先直接把系列名写在图形上，省掉来回检索。
- 单位落点：单位写在坐标轴标题或数值后缀上，两处只取其一。

```tsx
import { ChartContainer, ChartLegend, ChartLegendContent, ChartTooltip, ChartTooltipContent } from "@/components/ui/chart"

export function ChartWithLayers({ data }: { data: unknown[] }) {
  return (
    <ChartContainer config={chartConfig} className="h-64 w-full">
      <BarChart accessibilityLayer data={data}>
        <ChartTooltip content={<ChartTooltipContent />} />
        <ChartLegend content={<ChartLegendContent />} />
        <Bar dataKey="received" fill="var(--color-received)" />
      </BarChart>
    </ChartContainer>
  )
}
```

> 提示浮层里给裸数字而不给单位，是后台图表最常见的低级缺陷：用户在核对时必须在脑内补一次量纲。

**速记**：提示浮层必须给系列名、数值与单位，图例置上或下不遮数据，三系列以内优先直接标注。



#### 响应式与首帧测量

**首帧测量**：是图表在第一次渲染时读取容器尺寸以确定绘图区大小的过程，缺尺寸时图形会空白或高度为零。

- 尺寸来源：容器必须有确定的高度或宽高比，不能只写宽度。
- 自适应宽度：宽度撑满父容器，图表库自行测量，使用方不写固定像素宽。
- 尺寸变化：侧栏折叠会改变内容区宽度，图表需能跟随重排。
- 首帧宽度：宽度为百分比且高度为固定值是最稳的组合。
- 常见空白：只给宽度不给高度时，绘图区高度为零，表现为图表完全不显示。

```tsx
<ChartContainer config={chartConfig} className="h-64 w-full">
  {/* 高度由容器给出，宽度撑满；侧栏折叠后自动重排 */}
  <BarChart accessibilityLayer data={data}>{/* 图形 */}</BarChart>
</ChartContainer>
```

> [!CAUTION]
> **注意内容**：图表高度为百分比时，在父容器未定高的情况下高度会一路传到零，图表区域直接消失且不报错。给图表容器一个固定的高度类是最省事的解决办法。

**速记**：容器必须给出确定高度或宽高比，宽度撑满父容器，侧栏折叠后图表需能跟随重排。



### 单色方案下的系列编码

去掉色相之后，系列之间的区分只剩明度一个维度，而这个维度的容量非常有限。

#### 灰阶阶梯与对比门槛

**灰阶阶梯**：是单色方案里各系列使用的明度序列，按相邻系列之间的对比度是否达到门槛来定级。

- 实测结论：三级阶梯取亮度 0.92、0.60、0.30 时，相邻对比度分别为 3.12 与 3.45，均达到非文本对比门槛。
- 容量上限：五级阶梯即便按等步长取到 0.95 至 0.24，相邻对比度最低只有 1.73，低于门槛，人眼在图上无法稳定区分。
- 取值规则：单色方案下可靠区分的系列数上限为三，第四、第五类不再新增灰阶。
- 深浅两套：同一组阶梯在深浅主题下分别取值，浅主题用浅端，深主题用深端。
- 校验要求：新增或调整档位后必须重新计算相邻对比度，不凭观感判断。

```css
:root {
  /* 三级灰阶：相邻对比度 3.12 与 3.45，达到非文本门槛 */
  --chart-1: oklch(0.92 0 0);
  --chart-2: oklch(0.6 0 0);
  --chart-3: oklch(0.3 0 0);
}

.dark {
  /* 深色主题用同一组阶梯，直方图底色变深时浅端仍可辨 */
  --chart-1: oklch(0.9 0 0);
  --chart-2: oklch(0.66 0 0);
  --chart-3: oklch(0.42 0 0);
}
```

> [!WARNING]
> **警告内容**：把五个系列都压进灰阶是黑白方案里最常见的越界。相邻两档在图上只差一点点亮度，读者会把它们读成同一个系列的深浅变化，进而得出错误结论。超过三类时必须改用图案，而不是继续加密灰阶。

**速记**：单色可靠区分的系列上限为三，三级阶梯相邻对比度需达 3 比 1，超过三类的改用图案编码。



#### 图案与形状叠加

**图案编码**：是在填充色之外叠加线型、纹理或形状，使系列在没有颜色信息时仍然可区分。

- 适用场合：系列数超过三类，或图表会被黑白打印与截图。
- 折线：用实线、虚线、点线区分，线宽保持一致。
- 柱形与面积：用纯色、斜纹、点阵三种填充区分。
- 散点：用圆、方、三角三种标记区分。
- 灰度校验：把图表转为灰度后仍能区分，是图案是否合格的唯一检验方法。
- 成本：图案会降低填充的视觉纯度，类别数越多画面越花，因此不解决容量问题。

```tsx
// 折线用线型区分，不再新增灰阶
<Line dataKey="received" stroke="var(--color-received)" strokeWidth={2} />
<Line dataKey="closed" stroke="var(--color-closed)" strokeDasharray="4 3" strokeWidth={2} />
<Line dataKey="pending" stroke="var(--color-pending)" strokeDasharray="1 3" strokeWidth={2} />
```

> 图案解决的是「能不能区分」，不解决「能区分几类」。超过五类时应当拆分图表或改为分面，而不是继续加图案。

**速记**：超过三类时用线型、填充纹理与标记形状区分，并以灰度检查作为合格判据。



#### 强调与非强调系列

**强调系列**：是被单独提亮或压暗以突出的一组数据，与其余系列拉开一个档位。

- 实现方式：把被强调的系列取阶梯两端之一，其余系列取中间档并降低不透明度。
- 数量约束：同一张图里被强调的系列不超过一个。
- 交互联动：图例点击可切换系列显隐，隐藏后其余系列的灰阶不重新分配。
- 阈值线：关键阈值用一条细虚线标注，不占用系列的灰阶档位。
- 直接标注：被强调的系列直接在曲线末端标注名称与数值。

```tsx
<Line dataKey="received" stroke="var(--color-received)" strokeWidth={2} />
<Line dataKey="closed" stroke="var(--color-closed)" strokeWidth={2} opacity={0.45} />
<ReferenceLine y={120} stroke="var(--border)" strokeDasharray="4 3" />
```

> 强调的做法是让其余部分后退，不是让目标部分变大变色。后者在单色方案里做不出来，也会破坏整体的灰阶秩序。

**速记**：强调系列取阶梯端点、其余降不透明度，同图只强调一个，阈值另用虚线不占灰阶档位。



### 后台常用图表的取舍

图形类型的选择由「要回答什么问题」决定，不由数据长什么样决定。

#### 趋势图与对比图

**趋势图**：是横轴为时间、回答「怎么变化」的图形；**对比图**：是分类轴、回答「谁多谁少」的图形。

- 折线使用：时间点密集且关注连续变化时用折线。
- 柱形使用：时间点稀疏或只有几个分类时用柱形，比折线更容易读出绝对量。
- 面积慎用：堆叠面积图只有在各系列之和有意义时才使用。
- 双轴禁令：不使用双纵轴，两个量纲不同就拆成两张图上下对齐。
- 纵轴起点：柱形图的纵轴必须从零开始，折线图可以放大但需明确标注。

```tsx
<div className="grid gap-4 lg:grid-cols-2">
  {/* 量纲不同就拆图，不用双纵轴 */}
  <ChartContainer config={volumeConfig} className="h-60 w-full">{/* 件数趋势 */}</ChartContainer>
  <ChartContainer config={durationConfig} className="h-60 w-full">{/* 平均时长趋势 */}</ChartContainer>
</div>
```

> [!WARNING]
> **警告内容**：双纵轴能让两条曲线在图上看起来高度相关，但这个相关性是坐标缩放造出来的。后台报表一旦被用于决策，双纵轴就会变成一条有说服力的错误结论。

**速记**：时间密集用折线、分类稀疏用柱形，纵轴柱形从零、折线放大需标注，两个量纲拆成两张图。



#### 占比图与分布图

**占比图**：是回答「各占多少」的图形；**分布图**：是回答「集中在哪里」的图形，两者对分类数的容忍度都很低。

- 饼图上限：分类不超过五项，且必须有一项明显占优才使用。
- 环形替代：需要同时显示总量时用环形并在中心写总数。
- 条形替代：分类较多或名称较长时改用横向条形图，比饼图更易读。
- 直方图：用于看取值的集中趋势，组距要统一并标注。
- 排名列表：分类超过十项时用带进度条的排名列表，不用任何图形。

```tsx
// 分类较多时用横向条形加数值，不用饼图
<div className="space-y-2">
  {rows.map((row) => (
    <div key={row.label} className="flex items-center gap-3">
      <span className="w-24 shrink-0 truncate text-sm">{row.label}</span>
      <div className="h-2 flex-1 rounded-sm bg-muted">
        <div className="h-2 rounded-sm bg-chart-2" style={{ width: `${row.percent}%` }} />
      </div>
      <span className="w-12 text-right text-xs tabular-nums">{row.percent}%</span>
    </div>
  ))}
</div>
```

> 饼图在分类超过五项后迅速失效：相邻扇区的角度差小于人眼的比较精度，读者只能回到图例里逐个对照。

**速记**：饼图分类不超过五项且需一项明显占优，分类多改用横向条形或排名列表，直方图组距统一。



#### 图表与表格的取舍

**图形与表格的分工**：图形回答趋势与异常，表格回答精确取值，同一份数据常常两者都要。

- 图形优先：需要判断趋势、比较量级、发现离群点时用图形。
- 表格优先：需要读精确数值、逐条核对、导出处理时用表格。
- 组合方式：图形在上、可折叠的明细表在下，共用同一份筛选条件。
- 数值标注：图形上只标注关键点，其余数值交给提示浮层与表格。
- 切换入口：提供图形与表格的切换按钮，让用户按当前任务选择。

```tsx
<div className="space-y-4">
  <ChartContainer config={chartConfig} className="h-64 w-full">{/* 趋势图 */}</ChartContainer>
  <Collapsible defaultOpen={false}>
    <CollapsibleTrigger>查看明细数据</CollapsibleTrigger>
    <CollapsibleContent>{/* 与图共用筛选条件的表格 */}</CollapsibleContent>
  </Collapsible>
</div>
```

> [!TIP]
> **建议内容**：后台报表建议默认给图形、按需给明细。图形负责让异常被注意到，明细负责让异常被核对，两者缺一都会把用户推回导出到表格软件的老路。

**速记**：趋势与异常用图形、精确取值用表格，两者共用筛选条件并带切换入口，明细默认折叠。



### 单色方案下的图表规范

收拢前几节的结论，形成可逐条核对的图表规则。

- 系列上限：单色方案下可靠区分的系列不超过三，超出必须叠加图案编码。
- 阶梯取值：三级灰阶取 0.92、0.60、0.30，相邻对比度 3.12 与 3.45，改动后需重新计算。
- 令牌来源：颜色一律引用图表令牌，不写具体色值，也不引用原始色阶。
- 网格与轴线：网格用极浅的中性色并弱于数据线，轴线只保留一条基准。
- 数值格式：坐标轴与提示浮层使用同一套数值格式与单位，等宽数字对齐。
- 灰度检查：交付前把图表转成灰度看一遍，这一步是唯一能发现编码失效的方法。

```css
/* 网格与轴线取中性色，且必须弱于数据本身 */
:root {
  --chart-grid: oklch(0.922 0 0);
  --chart-axis: oklch(0.8 0 0);
}
```

> 单色图表的准确性完全落在明度差与图案上。任何一次凭手感调整档位，都必须重新跑一遍相邻对比度计算，否则下一张图就会退回到「看起来差不多」的状态。
