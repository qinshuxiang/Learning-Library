## 表单与字段组件

表单是后台系统里出现频率最高的界面，也是缺陷最集中的地方：标签与控件的关联、错误的落点、校验状态的表达，任一处做错都会让整张表单难以使用。本篇按「字段如何组装、控件如何选择、状态如何衔接」三层说明。单色方案下的错误态处理见末节，控件的对比度取值见第 13 篇。

### 字段的组装方式

字段族把「一个控件加上它的标签、说明与错误」抽象成一组语义化子组件，写表单变成了按固定顺序摆零件。

#### 字段族的分层结构

**字段族**：是一组配合使用的语义化子组件，分为单字段、字段组与字段集三层，逐层负责不同的组织职责。

- 单字段层：一个控件连同它的标签、辅助说明与错误提示，是最小的完整单元。
- 字段组层：把相关字段纵向排列，并在需要时用分隔插入区块边界。
- 字段集层：以语义化的分组容器与图例，把一组字段标成一个有名字的区块。
- 内容列：当标签位于控件旁侧时，用内容列把标签与说明归到一列，避免说明跑到控件下方。
- 布局职责：间距由字段组统一给出，单个字段不自行设置外边距。

```tsx
import {
  Field,
  FieldDescription,
  FieldGroup,
  FieldLabel,
  FieldLegend,
  FieldSet,
} from "@/components/ui/field"
import { Input } from "@/components/ui/input"

export function AccountForm() {
  return (
    <FieldSet>
      <FieldLegend>账号信息</FieldLegend>
      <FieldDescription>用于登录与接收通知。</FieldDescription>
      <FieldGroup>
        <Field>
          <FieldLabel htmlFor="username">账号</FieldLabel>
          <Input id="username" autoComplete="off" />
          <FieldDescription>六到二十位字母或数字。</FieldDescription>
        </Field>
        <Field>
          <FieldLabel htmlFor="nickname">显示名</FieldLabel>
          <Input id="nickname" autoComplete="off" />
        </Field>
      </FieldGroup>
    </FieldSet>
  )
}
```

> [!IMPORTANT]
> **重要内容**：字段族的价值在于把标签与控件的关联交给组件完成。绕过它手写标签与控件时，最容易漏掉的就是关联属性，表现为点击标签无法聚焦到输入框、屏幕阅读器读不出字段名，而这两种缺陷在视觉上完全看不出来。

**速记**：字段族分单字段、字段组、字段集三层，间距由字段组统一给出，关联属性由组件负责。



#### 标签、说明与错误的顺序

**字段顺序**：是字段内部各零件的固定排列，顺序决定了阅读动线与错误出现的位置。

- 标准顺序：标签、控件、辅助说明、错误提示，自上而下。
- 说明与错误互斥：同一条信息不要既是说明又是错误，两者语义不同。
- 错误落点：错误提示紧跟在控件之后，不要放到整张表单的顶部或底部汇总。
- 横向布局：标签在左时用内容列包裹标签与说明，让说明与标签左对齐。
- 布局方向：字段支持纵向、横向与自适应三种方向，缺省为纵向。

```tsx
<Field>
  <FieldLabel htmlFor="email">邮箱</FieldLabel>
  <Input id="email" type="email" aria-invalid />
  <FieldError>请输入有效的邮箱地址。</FieldError>
</Field>
```

> 错误提示贴着出错的控件，用户才不需要在表单两端来回找。把错误统一收到顶部是常见的省事实践，代价是每次出错都要重新定位。

**速记**：字段内部固定为标签、控件、说明、错误四段，错误紧跟控件，横向布局用内容列归位。



#### 校验状态的两种表达

**校验状态**：是字段对合法性的自我描述，需要同时传达给样式层与辅助技术两层。

- 样式层标记：在字段容器上添加非法态标记，整块字段切换到错误外观。
- 语义层标记：在控件自身添加非法属性，供辅助技术读取。
- 两处缺一：只加样式层则读屏软件不知道出错，只加语义层则视觉上没有任何提示。
- 三处着色：错误态只让边框、文字与图标着色，不填充整块背景。
- 恢复时机：用户开始修改时即可清除非法标记，不必等重新校验完成。

```tsx
<Field data-invalid>
  <FieldLabel htmlFor="phone">手机号</FieldLabel>
  <Input id="phone" aria-invalid />
  <FieldError>手机号格式不正确。</FieldError>
</Field>
```

> [!CAUTION]
> **注意内容**：错误态用整块红色背景是最省事的做法，也是最容易失控的做法。表单里同时出现三处错误时，页面会变成一片红，真正的错误落点反而更难找；单色方案更应把错误限制在边框、文字与图标三处。

**速记**：非法态要同时打在字段容器与控件上，只让边框、文字、图标着色，用户开始修改即清除标记。



### 输入控件的选择

控件类型的选择由「取值空间是否已知」和「取值数量多少」两个问题决定。

#### 文本类输入

**文本控件**：是取值不受枚举限制的输入，按单行与多行分为输入框与文本域两种。

- 单行输入：适用于账号、名称、编号一类短文本，宽度按预期内容长度设定。
- 多行文本域：适用于备注、说明、驳回事由一类长文本，需给出可见行数。
- 字数约束：有长度限制时必须在界面上给出当前长度与上限，不靠提交后报错。
- 自动完成：能对应到浏览器自动填充语义的字段应声明，减少后台人员的重复输入。
- 前缀后缀：单位、货币符号一类固定文案用输入组承载，不写进占位文字。

```tsx
import { Field, FieldDescription, FieldLabel } from "@/components/ui/field"
import { InputGroup, InputGroupAddon, InputGroupInput } from "@/components/ui/input-group"
import { Textarea } from "@/components/ui/textarea"

export function TextFields() {
  return (
    <>
      <Field>
        <FieldLabel htmlFor="amount">金额</FieldLabel>
        <InputGroup>
          <InputGroupAddon align="inline-start">¥</InputGroupAddon>
          <InputGroupInput id="amount" inputMode="decimal" className="tabular-nums" />
          <InputGroupAddon align="inline-end">元</InputGroupAddon>
        </InputGroup>
      </Field>
      <Field>
        <FieldLabel htmlFor="reason">办理说明</FieldLabel>
        <Textarea id="reason" rows={4} />
        <FieldDescription>不超过 200 字。</FieldDescription>
      </Field>
    </>
  )
}
```

> 占位文字不是标签，也不是单位说明。它一旦承载信息，用户开始输入的那一刻信息就消失了。

**速记**：文本控件按单行与多行分工，长度上限要实时回显，单位与符号用输入组承载而非占位文字。



#### 选择类输入

**选择控件**：是从已知取值集合中取一个或多个的输入，按可选项数量与是否需要搜索来选型。

- 少量枚举：可选项在三到七个之间时用单选组，全部摊开便于一次比对。
- 大量枚举：可选项较多时用下拉选择，避免占满表单高度。
- 需要搜索：选项超过一屏或需要按关键字定位时用可搜索下拉。
- 多选：多选场景用复选框组，选中项数量有上限时在说明里写明。
- 原生选择：表单需要浏览器原生行为（如移动端原生弹层）时使用原生选择控件。

```tsx
import { Field, FieldLabel } from "@/components/ui/field"
import { RadioGroup, RadioGroupItem } from "@/components/ui/radio-group"
import { Select, SelectContent, SelectItem, SelectTrigger, SelectValue } from "@/components/ui/select"

export function ChoiceFields() {
  return (
    <>
      <Field>
        <FieldLabel htmlFor="department">所属部门</FieldLabel>
        <Select>
          <SelectTrigger id="department">
            <SelectValue placeholder="请选择" />
          </SelectTrigger>
          <SelectContent>
            <SelectItem value="net">网安</SelectItem>
            <SelectItem value="ops">运维</SelectItem>
          </SelectContent>
        </Select>
      </Field>
      <Field>
        <FieldLabel>优先级</FieldLabel>
        <RadioGroup defaultValue="normal">
          <RadioGroupItem value="low">低</RadioGroupItem>
          <RadioGroupItem value="normal">中</RadioGroupItem>
          <RadioGroupItem value="high">高</RadioGroupItem>
        </RadioGroup>
      </Field>
    </>
  )
}
```

> 单选组与下拉的取舍标准是可选项能否一眼扫完：扫得完就摊开，扫不完就收进下拉，不要按界面美观决定。

**速记**：少量枚举摊成单选组、大量枚举收进下拉、需检索用可搜索下拉、多选用复选框组。



#### 开关与数值类输入

**开关与数值控件**：是布尔量与区间量的专用输入，前者表达立即生效的状态，后者表达有序或定量的取值。

- 开关用法：用于修改后立即生效的设置项，不用于需要提交按钮才生效的表单字段。
- 复选框用法：用于随表单一起提交的布尔字段，语义与开关不同不可互换。
- 滑块用法：用于取值连续且不需要精确输入的场景，如阈值与预算区间。
- 数值精度：滑块旁必须显示当前取值，且允许直接输入精确数字。
- 步进器：需要按固定步长增减时用带按钮的输入组，不靠滑块微调。

```tsx
import { Field, FieldDescription, FieldLabel } from "@/components/ui/field"
import { Checkbox } from "@/components/ui/checkbox"
import { Slider } from "@/components/ui/slider"
import { Switch } from "@/components/ui/switch"

export function ToggleFields() {
  return (
    <>
      <Field orientation="horizontal">
        <Switch id="audit" />
        <FieldLabel htmlFor="audit">开启操作审计</FieldLabel>
      </Field>
      <Field orientation="horizontal">
        <Checkbox id="agree" />
        <FieldLabel htmlFor="agree">随表单一起提交该项确认</FieldLabel>
      </Field>
      <Field>
        <FieldLabel htmlFor="threshold">告警阈值</FieldLabel>
        <Slider id="threshold" defaultValue={[60]} max={100} step={5} />
        <FieldDescription>当前取值 60，可拖动或直接输入。</FieldDescription>
      </Field>
    </>
  )
}
```

> [!WARNING]
> **警告内容**：把随表单提交的布尔字段做成开关，用户会以为改动已经生效而直接离开页面，实际并未提交。判断依据是「改动是否需要提交」：立即生效用开关，随表单提交用复选框。

**速记**：开关用于即时生效的设置项，复选框用于随表单提交的布尔字段，滑块必须回显取值并允许精确输入。



### 表单状态与校验

字段族只负责呈现，状态与校验由表单库提供，两者通过错误数组衔接。

#### 校验规则的组织

**校验规则**：是对各字段取值约束的声明，用模式校验库集中描述，字段族只消费校验产出的错误。

- 集中声明：一条规则写在一个模式对象里，字段与规则一一对应。
- 类型推导：由模式推导出表单取值类型，避免类型与规则两处维护。
- 复用边界：同一模式可在前端与服务端共用，保证两侧判定一致。
- 自定义消息：每条规则都应给出面向人的中文提示，不直接抛库默认文案。
- 跨字段规则：字段间依赖的规则写在对象层级，不写在单个字段上。

```ts
import { z } from "zod"

export const accountSchema = z.object({
  username: z.string().min(6, "账号至少六位").max(20, "账号最多二十位"),
  email: z.string().email("请输入有效的邮箱地址"),
  threshold: z.number().min(30, "阈值不得低于 30").max(100, "阈值不得超过 100"),
})

export type AccountValues = z.infer<typeof accountSchema>
```

> 校验规则是契约而不是提示文本的容器。把它写成可复用的模式，服务端校验与前端提示才有同一个来源。

**速记**：校验规则集中成模式对象并推导取值类型，每条规则给出中文提示，前后端共用同一份判定。



#### 错误信息的组织

**错误数组**：是字段族接收校验结果的接口，可以直接接收表单库的错误对象，也可以接收标准校验规范的错误列表。

- 单条消息：直接给出一个错误提示子组件，内部承载消息文本。
- 多条消息：传入错误数组时组件自动渲染为列表，不需要手工拼装。
- 跨库兼容：符合标准校验规范的结果可直接传入，不必转换成特定库的格式。
- 字段映射：错误数组必须填入对应字段的错误，不要整表共用一份错误。
- 展示上限：同一字段的错误超过两条时只展示最靠前的一条，其余并入说明。

```tsx
<Field data-invalid={Boolean(errors.username)}>
  <FieldLabel htmlFor="username">账号</FieldLabel>
  <Input id="username" aria-invalid={Boolean(errors.username)} />
  <FieldError errors={errors.username} />
</Field>
```

> [!NOTE]
> **提醒内容**：错误数组按字段传递，是让错误落在正确位置的前提。把全表错误统一传给每个字段，会在所有字段下方同时显示同样的提示，看起来像整张表单都出了问题。

**速记**：错误数组按字段传递，多条自动渲染为列表，符合标准校验规范的结果可直接传入。



#### 提交与重置

**提交**：是把校验通过的取值交给业务逻辑的动作；**重置**：是把表单恢复到初始取值的动作。

- 提交时机：校验不通过时阻止提交并把焦点移到第一个出错字段。
- 提交锁定：提交过程中锁定提交按钮，避免重复创建记录。
- 结果反馈：提交成功与失败都要给出明确反馈，前者可用轻提示，后者必须落在字段或表单级提示条上。
- 重置范围：重置应恢复到初始取值而不是清空，多用于编辑场景。
- 离开保护：有未保存改动时拦截离开，避免误关标签页丢失填写内容。

```tsx
async function onSubmit(values: AccountValues) {
  const result = await saveAccount(values)
  if (!result.ok) {
    setFormError(result.message)
    return
  }
  toast.success("保存成功")
}
```

> [!TIP]
> **建议内容**：后台表单建议统一采用「校验不通过先把焦点移到第一个出错字段」这一行为。它把「哪里错了」从一次视觉搜索变成一次自动定位，在字段数量超过二十的长表单上收益最明显。

**速记**：提交时先校验并把焦点移到首个出错字段、提交中锁定按钮、重置回到初始值、有改动时拦截离开。



### 单色方案下的表单密度

单色后台的表单外观高度依赖间距与对齐，配色能帮的忙很有限。

- 纵向节奏：字段之间的间距取一个固定值，字段内部的间距取它的三分之一左右。
- 标签对齐：纵向布局下标签左对齐并与控件同宽，横向布局下标签宽度统一。
- 必填标记：必填字段用标记标出而非把选填都写一遍，标记位置固定在标签后。
- 错误占位：字段下方预留错误提示的位置，避免出错时整列高度跳变。
- 三列上限：单行最多三个字段，超过后改用两列或整行，避免输入框过窄。

```tsx
// 标准表单骨架：固定间距节奏，错误出现时列高不跳变
<FieldGroup className="gap-6">
  <Field>
    <FieldLabel htmlFor="name">名称</FieldLabel>
    <Input id="name" />
    <FieldError />
  </Field>
</FieldGroup>
```

> 单色方案里，表单的「整齐」几乎完全由间距与对齐决定。配色越克制，间距的不一致就越显眼。

**速记**：字段间固定间距、标签对齐一致、必填集中标记、预留错误位、单行最多三列。
