## 导航与侧栏组件

导航决定用户在系统里「知不知道自己在哪、能不能快速换地方」，是后台系统里唯一需要全局一致性的组件组。本篇按侧栏、页内、顶部与小屏三组说明。侧栏使用的独立令牌见第 4 篇，切页时的加载表现见第 7 篇，整体骨架的搭建见第 12 篇。

### 侧栏的组成

侧栏是这套组件里结构最复杂的一个：它由十几个语义化子组件按固定层级拼装而成。

#### 侧栏的层级结构

**侧栏**：是把全站一级与二级导航收在页面侧边、可折叠的常驻区域，分为提供者、容器、内容区与菜单四层。

- 提供者层：统一管理折叠状态并向内部组件提供上下文，必须包裹整个应用。
- 容器层：侧栏面板本体，分为页头、内容区、页脚与拖拽边四个部分。
- 内容层：由若干分组组成，分组带可选的组标题与组操作。
- 菜单层：分组内的菜单项，每项可带图标、徽标、行内动作与子菜单。
- 语义归属：每一层的职责固定，不要跳过内容层直接在容器里放菜单。

```tsx
import {
  Sidebar,
  SidebarContent,
  SidebarFooter,
  SidebarGroup,
  SidebarGroupContent,
  SidebarGroupLabel,
  SidebarHeader,
  SidebarMenu,
  SidebarMenuButton,
  SidebarMenuItem,
  SidebarProvider,
  SidebarTrigger,
} from "@/components/ui/sidebar"

export function Shell({ children }: { children: React.ReactNode }) {
  return (
    <SidebarProvider>
      <Sidebar>
        <SidebarHeader />
        <SidebarContent>
          <SidebarGroup>
            <SidebarGroupLabel>业务办理</SidebarGroupLabel>
            <SidebarGroupContent>
              <SidebarMenu>
                <SidebarMenuItem>
                  <SidebarMenuButton>受理登记</SidebarMenuButton>
                </SidebarMenuItem>
              </SidebarMenu>
            </SidebarGroupContent>
          </SidebarGroup>
        </SidebarContent>
        <SidebarFooter />
      </Sidebar>
      <main>
        <SidebarTrigger />
        {children}
      </main>
    </SidebarProvider>
  )
}
```

> [!IMPORTANT]
> **重要内容**：提供者必须包在整个应用外层。只包在当前页面时，侧栏状态会在路由切换后重置，表现为每次跳页侧栏都自己展开一次，而这类缺陷在只有一个页面的示例里无法复现。

**速记**：侧栏分提供者、容器、内容、菜单四层，提供者包在应用外层，层级不可跳。



#### 折叠形态与宽度

**折叠形态**：是侧栏收起时所保留的最小形态，分为整块滑出、收成图标条与不可折叠三种。

- 整块滑出：收起后完全移出可视区，腾出最大宽度，适合以内容为主的页面。
- 收成图标条：收起后保留一列图标，鼠标悬停可见名称，适合导航频繁切换的场景。
- 不可折叠：始终展开，仅用于导航项很少且宽度充裕的系统。
- 宽度定义：展开宽度与移动端宽度各有一个基准值，也可由使用方按需覆盖。
- 变体搭配：面板另有默认、悬浮与内嵌三种变体，内嵌变体需把主内容放进内嵌容器。

```tsx
// 图标条折叠形态；内嵌变体需把主内容放进内嵌容器
<SidebarProvider
  style={{ "--sidebar-width": "15rem", "--sidebar-width-mobile": "18rem" } as React.CSSProperties}
>
  <Sidebar collapsible="icon" variant="inset" />
  <SidebarInset>
    <main>{/* 主内容 */}</main>
  </SidebarInset>
</SidebarProvider>
```

> [!CAUTION]
> **注意内容**：选择收成图标条时，每一项都必须有能一眼认出的图标。图标语义模糊时，收起状态的侧栏会变成一排需要逐个悬停才敢点的方块，可用性不如整块滑出。

**速记**：折叠形态分滑出、图标条、不可折叠三种，宽度有展开与移动端两个基准，内嵌变体需配内嵌容器。



#### 菜单项状态与高亮

**当前项**：是侧栏里标记用户所处位置的菜单项，由路由匹配结果决定，不由点击事件决定。

- 判定来源：以当前路由与菜单项的路径匹配结果为准，保证刷新与直达链接后仍然正确。
- 匹配精度：使用精确或前缀匹配要给出明确规则，避免父项与子项同时高亮。
- 子菜单：有子菜单的项在展开时保留父项的高亮，展开状态本身也要持久化。
- 图标呈现：当前项可用图标容器的底色变化表达，不必改变文字色。
- 徽标保留：当前项上的计数徽标不因高亮而隐藏。

```tsx
<SidebarMenuItem>
  <SidebarMenuButton render={<a href="/cases" />} isActive={pathname === "/cases"}>
    <FolderIcon />
    <span>案件管理</span>
  </SidebarMenuButton>
  <SidebarMenuBadge>12</SidebarMenuBadge>
</SidebarMenuItem>
```

> 用点击事件驱动高亮，是这类侧栏最常见的实现错误：刷新页面、从消息链接直达、或浏览器前进后退时，高亮都会与实际位置脱节。

**速记**：当前项由路由匹配决定而非点击事件，父子项不重复高亮，展开状态持久化，徽标不因高亮隐藏。



### 页内导航

侧栏解决「换模块」，页内导航解决「在一个模块里换位置」。

#### 面包屑与位置回显

**面包屑**：是沿层级路径回溯的导航条，用一行文字表达「当前在哪、上一级是什么」。

- 层级内容：从模块名到当前页，最多三段，更深的层级折叠成一个省略项。
- 末项处理：最后一段是当前页，不可点击，与前面的可点击项在样式上区分。
- 首项固定：首项固定为首页或系统名，作为最短的回退路径。
- 窄屏处理：宽度不足时只保留首项与末项，中间折叠。
- 与标题重复：面包屑与页面标题表达同一位置时，二者并列而不互相替代。

```tsx
import {
  Breadcrumb,
  BreadcrumbItem,
  BreadcrumbLink,
  BreadcrumbList,
  BreadcrumbPage,
  BreadcrumbSeparator,
} from "@/components/ui/breadcrumb"

export function PageCrumb() {
  return (
    <Breadcrumb>
      <BreadcrumbList>
        <BreadcrumbItem>
          <BreadcrumbLink href="/">工作台</BreadcrumbLink>
        </BreadcrumbItem>
        <BreadcrumbSeparator />
        <BreadcrumbItem>
          <BreadcrumbPage>案件管理</BreadcrumbPage>
        </BreadcrumbItem>
      </BreadcrumbList>
    </Breadcrumb>
  )
}
```

> 面包屑是深链场景下唯一的定位手段。用户从消息里点进来时没有经过侧栏，面包屑就是他判断自己身处何处的全部依据。

**速记**：面包屑最多三段、末项不可点、首项固定到首页，窄屏只留首末，与标题并列而非替代。



#### 标签页与分节切换

**分节切换**：是在同一路由内切换若干并列视图的控制，用于把同一个对象的不同侧面分开呈现。

- 适用场景：同一实体的不同侧面，如详情、变更记录、附件。
- 状态入地址：当前分节要写进地址栏，保证可分享与可回退。
- 数量约束：分节数量不超过七个，超过改为纵向导航。
- 载荷策略：切换分节时按需加载该分节内容，不预先拉取全部。
- 移动端：窄屏下分节可横向滚动，但必须保留可滚动提示。

```tsx
import { Tabs, TabsContent, TabsList, TabsTrigger } from "@/components/ui/tabs"

export function DetailTabs() {
  return (
    <Tabs defaultValue="overview">
      <TabsList>
        <TabsTrigger value="overview">概览</TabsTrigger>
        <TabsTrigger value="history">变更记录</TabsTrigger>
        <TabsTrigger value="files">附件</TabsTrigger>
      </TabsList>
      <TabsContent value="overview">{/* 概览 */}</TabsContent>
      <TabsContent value="history">{/* 变更记录 */}</TabsContent>
      <TabsContent value="files">{/* 附件 */}</TabsContent>
    </Tabs>
  )
}
```

> [!TIP]
> **建议内容**：把当前分节写进地址栏几乎是零成本的，收益却很大：用户可以把「案件详情的第一条变更记录」直接发给同事，而不必口头描述点哪几下。

**速记**：分节切换用于同一实体的不同侧面，当前分节写入地址栏，不超过七项，内容按需加载。



#### 命令面板与快速跳转

**命令面板**：是用一个浮层同时承担搜索与跳转的控制台，让熟练用户不离开键盘就能完成导航。

- 触发方式：绑定一个全局快捷键，并在界面某处给出入口与快捷键提示。
- 数据来源：导航项、最近访问记录与常用动作三类合并成一张可检索列表。
- 分组呈现：按类别分组，每组给出小标题，跨组结果按匹配度排序。
- 空结果：无匹配时给出建议动作，而不是只显示「无结果」。
- 关闭行为：选中后关闭面板并执行动作，执行后焦点回到触发前的位置。

```tsx
import {
  CommandDialog,
  CommandEmpty,
  CommandGroup,
  CommandInput,
  CommandItem,
  CommandList,
} from "@/components/ui/command"

export function Palette({ open, onOpenChange, routes }: { open: boolean; onOpenChange: (open: boolean) => void; routes: { value: string; label: string }[] }) {
  return (
    <CommandDialog open={open} onOpenChange={onOpenChange}>
      <CommandInput placeholder="搜索页面或动作" />
      <CommandList>
        <CommandEmpty>没有匹配项，可尝试更短的关键词。</CommandEmpty>
        <CommandGroup heading="导航">
          {routes.map((route) => (
            <CommandItem key={route.value} value={route.value}>
              {route.label}
            </CommandItem>
          ))}
        </CommandGroup>
      </CommandList>
    </CommandDialog>
  )
}
```

> [!NOTE]
> **提醒内容**：命令面板是熟练用户的加速器，不是新用户的入口。它必须与侧栏并存，且侧栏始终可见，否则新用户会在一个只有快捷键的系统里彻底迷失。

**速记**：命令面板合并导航、最近访问与常用动作，按组呈现并在空结果时给建议，与侧栏并存。



### 顶部与移动端

顶栏与小屏适配决定了同一套导航能否在两种使用环境下都成立。

#### 顶栏要素与顺序

**顶栏**：是页面顶部的常驻横条，承载全局操作与当前上下文，要素的顺序在全站必须一致。

- 左端：侧栏折叠开关、面包屑或模块名。
- 中段：全局搜索或命令面板入口。
- 右端：帮助入口、主题切换与账号菜单，顺序固定不变。
- 高度：固定高度并参与页面高度计算，内容区高度按剩余空间计算，不写死像素。
- 层级：顶栏与侧栏同属最外层，内容区滚动不影响二者。

```tsx
<header className="sticky top-0 z-20 flex h-14 items-center gap-2 border-b border-border bg-background px-4">
  <SidebarTrigger />
  <Breadcrumb>{/* 面包屑 */}</Breadcrumb>
  <div className="ml-auto flex items-center gap-2">{/* 搜索、帮助、主题、账号 */}</div>
</header>
```

> 顶栏要素顺序固定，用户才能凭肌肉记忆操作。把主题切换从一个位置挪到另一个位置，看起来只是小事，实际会持续引发误点。

**速记**：顶栏左端放折叠开关与面包屑、右端固定放帮助与账号，高度固定且内容区按剩余空间计算。



#### 小屏下的形态切换

**小屏适配**：是把常驻侧栏降级为临时浮层的处理方式，避免在小屏上挤压主内容。

- 断点行为：进入小屏后侧栏改为浮层，由触发器打开，带遮罩且点击遮罩关闭。
- 记忆保持：在宽屏下收起侧栏的状态应被记住，切回宽屏时不自动展开。
- 快捷键：折叠快捷键在桌面端有效，按住功能键加字母触发。
- 主内容：侧栏变浮层后主内容占满宽度，不做留白占位。
- 表格降级：小屏下表格可改为卡片列表，见第 8 篇的列定义复用。

```tsx
// 侧栏状态由上下文统一读出，宽屏与小屏各用一套开关
const { state, isMobile, toggleSidebar } = useSidebar()
```

> [!WARNING]
> **警告内容**：小屏下仍然保留常驻侧栏，会让主内容宽度被压缩到不可用，同时表格出现双重横向滚动。判断依据很简单：只要小屏上需要同时滚动页面和表格，侧栏就必须降级为浮层。

**速记**：小屏侧栏降级为带遮罩的浮层，宽屏折叠状态单独记忆，主内容占满宽度，表格可改卡片。



#### 键盘与焦点可达

**键盘可达**：是指导航的全部功能不依赖鼠标即可完成，包括切换折叠、进出子菜单与跳转当前项。

- 折叠开关：提供可聚焦的折叠按钮，并绑定全局快捷键。
- 子菜单：子菜单展开与收起支持方向键，焦点在父子项之间可预期地移动。
- 表格与侧栏联动：从侧栏跳转后焦点应落到主内容标题，便于屏幕阅读器用户确认已切换。
- 可见焦点：侧栏内所有可聚焦元素都要有可见焦点环，且不被裁切。
- 跳转链接：提供跳到主内容的跳转链接，作为键盘用户的第一个可聚焦元素。

```tsx
// 跳到主内容：键盘用户的第一个可聚焦元素
<a
  href="#main"
  className="sr-only focus:not-sr-only focus:absolute focus:left-4 focus:top-4 focus:z-50 focus:rounded-md focus:border focus:border-border focus:bg-background focus:px-3 focus:py-2"
>
  跳到主内容
</a>
```

> [!CAUTION]
> **注意内容**：侧栏收起为图标条时，子菜单若没有键盘出口，键盘用户就再也进不去二级页面。修正成本很低，但只在用键盘时才暴露，因此常年无人报告。

**速记**：折叠开关可聚焦并有快捷键、子菜单支持方向键、跳转后焦点落到主内容、提供跳到主内容链接。



### 单色方案下的导航层级

侧栏有一套独立令牌，正是为了让导航与页面可以在同一套单色阶梯里各占一档。

- 面分两档：浅色主题下侧栏面比页面底色略深一档；深色主题下侧栏面比页面底色略浅一档。
- 当前项：用强调交互面表达，不改变文字色，避免出现一处深字一处浅字。
- 分组标题：用弱色文字加较小字号，字号与颜色只动其一即可，二者同时动会失衡。
- 图标：图标与文字同色，尺寸统一，不为主线图标单独着色。
- 分隔：分组之间靠留白区分，只有跨语义边界时才加分隔线。

```css
:root {
  --sidebar: oklch(0.985 0 0);
  --sidebar-foreground: oklch(0.145 0 0);
  --sidebar-accent: oklch(0.97 0 0);
  --sidebar-accent-foreground: oklch(0.205 0 0);
  --sidebar-border: oklch(0.922 0 0);
}

.dark {
  --sidebar: oklch(0.205 0 0);
  --sidebar-foreground: oklch(0.985 0 0);
  --sidebar-accent: oklch(0.269 0 0);
  --sidebar-accent-foreground: oklch(0.985 0 0);
  --sidebar-border: oklch(1 0 0 / 10%);
}
```

> 侧栏与页面各占一档明度，是单色方案里划分导航与内容最稳的做法。靠边框区分导航区，在窄屏下会因为高度压缩而失去效果。
