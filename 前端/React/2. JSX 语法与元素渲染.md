## JSX 语法与元素渲染

### JSX 是什么

这一节说明 JSX 的定义、它与 HTML 的表面差异，以及它在现代构建链路中的编译方式。

#### JSX 的定义与编译产物

**JSX（JavaScript XML）**：是一种在 JavaScript 中书写元素结构的语法扩展，编译后转换成创建元素的函数调用，本身不引入新的运行时语义。

- 语法位置：出现在 JavaScript 表达式可以出现的地方，如赋值、函数返回、函数实参。
- 编译结果：被转换为对 JSX 运行时函数的调用，返回元素（element）对象。
- 依赖条件：需要编译器支持，浏览器与 Node.js 都不识别 JSX 原文。
- 等价关系：一段 JSX 与它编译后的函数调用完全等价，没有额外魔法。

```jsx
// 源码：JSX 写法
const heading = <h1 className="title">Hello, React</h1>;
```

```js
// 编译后（自动运行时）：转换为运行时函数调用，返回元素对象
import { jsx as _jsx } from "react/jsx-runtime";

const heading = _jsx("h1", { className: "title", children: "Hello, React" });
```

> JSX 不是模板语言：模板有自己的指令与作用域规则，JSX 只是 JavaScript 表达式的一种写法，规则由 JavaScript 决定。

**速记**：JSX 是 JavaScript 的语法扩展，编译后变成创建元素对象的函数调用。



#### JSX 与 HTML 的差异

**JSX 与 HTML 的差异**：是属性命名与书写规则上的差异，JSX 采用 DOM 属性名与 JavaScript 标识符习惯，而不是 HTML 的宽松写法。

- 属性改名：class 写作 className，for 写作 htmlFor，因为二者在 JavaScript 中是保留字。
- 驼峰命名：多词属性写作小驼峰，如 tabindex 写作 tabIndex，onclick 写作 onClick。
- 必须闭合：空元素必须自闭合，img、input、br 都要写成斜杠结尾的自闭合形式。
- 样式与注释：样式通过对象传值，注释写在花括号包裹的块注释中。

```html
<!-- HTML 写法：属性小写，空元素可以不加斜杠 -->
<label for="name" class="field">姓名</label>
<img src="avatar.png" alt="头像">
```

```jsx
// JSX 写法：属性驼峰，空元素必须自闭合
<label htmlFor="name" className="field">姓名</label>
<img src="avatar.png" alt="头像" />

// 注释必须写在花括号里，否则会被当作文本渲染
const hint = (
  <p>
    {/* 花括号里的块注释不会渲染到界面上 */}
    提示文本
  </p>
);
```

> 这些差异全部来自 JavaScript 语法限制与 DOM 属性命名，编译器只做文本转换，元素在浏览器中的解析结果与 HTML 一致。

**速记**：JSX 属性用驼峰与 DOM 命名，空元素必须自闭合，注释写在花括号里。



#### 自动运行时与不必手写 import React

**自动运行时（automatic runtime）**：是 JSX 编译的默认模式，编译器自动从 react/jsx-runtime 导入所需的创建函数，源码中不必再写 import React。

- 旧模式：classic 运行时把 JSX 编译为 React.createElement，因此文件顶部必须导入 React，否则报 React 未定义。
- 新模式：automatic 运行时直接导入 jsx 或 jsxs 函数，不再依赖 React 标识符是否存在。
- 启用条件：由构建工具或 Babel 配置决定，现代工具链默认启用。
- 文件写法：组件文件即使没有显式使用 React，也不需要引入它。

```jsx
// 现代写法：不需要 import React，编译器自动补齐运行时导入
function Badge({ label }) {
  return <span className="badge">{label}</span>;
}

export default Badge;
```

> [!NOTE]
> **提醒内容**：只有使用 Fragment 长语法或需要显式调用 React 提供的 API 时，才从 react 包按需导入对应成员。

**速记**：自动运行时由编译器补齐 JSX 运行时导入，组件文件不必手写 import React。



### 表达式嵌入与属性传递

这一节讲数据如何进入元素结构：花括号嵌入表达式、属性传值的两种写法、批量传递 props 与 children 的位置。

#### 花括号嵌入表达式

**花括号嵌入**：是把 JavaScript 表达式的结果插入元素结构的写法，一对花括号内只能写一个表达式。

- 取值：变量、属性访问、函数调用、模板字符串都可以直接嵌入。
- 计算：算术、比较、逻辑运算可以在花括号内完成。
- 渲染规则：字符串与数字直接显示，null、undefined、布尔值不渲染任何内容。

```jsx
function UserSummary({ user, score }) {
  return (
    <p>
      {user.name} 的得分是 {score + 10}，等级 {(score + 10) >= 90 ? "A" : "B"}
    </p>
  );
}

// user 为 { name: "Ada" }、score 为 85 时渲染：「Ada 的得分是 95，等级 A」
```

> [!CAUTION]
> **注意内容**：把普通对象直接放进花括号会触发「Objects are not valid as a React child」错误，展示对象时应先显式序列化为字符串。

**速记**：一对花括号插入一个表达式，字符串与数字显示，null 与布尔值不渲染。



#### 属性传值的写法

**属性传值**：是为元素或组件设置 props 的写法，字符串字面量用双引号，其它类型的值用花括号中的表达式。

- 字符串：写成属性名等于双引号字符串，内容按字面量处理。
- 表达式：写成属性名等于花括号，可以传数字、布尔、对象、数组、函数与元素。
- 混用：同一个标签上两种写法可以并存，按属性逐个选择。
- 命名：属性名用小驼峰，传给自定义组件时属性名即 props 的键名。

```jsx
function ProfileCard({ name, age, isVerified }) {
  return (
    <div className="card">
      <span>{name}</span>
      <span>{age}</span>
      {isVerified ? <em>已认证</em> : null}
    </div>
  );
}

// 字符串用引号，数字与布尔用花括号
// <ProfileCard name="Ada" age={36} isVerified={true} />
```

> 引号里写花括号不会求值，会原样变成文本；需要求值时必须去掉引号并改用花括号。

**速记**：字符串属性用引号，非字符串属性用花括号，属性名即 props 的键名。



#### 布尔属性与展开运算符传递 props

**布尔属性**：是取值为 true 或 false 的属性，写成花括号表达式，只写属性名等价于传入 true。**展开运算符**：是把对象的键值逐个展开为属性的写法，用于把 props 成批透传。

- 简写规则：只写属性名等于传入 true，与显式写成花括号 true 等价，但显式写法更易读。
- 展开传递：在标签内写展开对象，对象的每个键值对都会成为一条属性。
- 覆盖顺序：后写的属性覆盖先写的同名属性，展开的位置决定优先级。
- 剩余属性：配合对象剩余语法收集未解构的属性，再整体展开到子元素上。

```jsx
function IconButton({ label, ...restProps }) {
  // 收集剩余属性并展开到 button 上，实现属性透传
  return (
    <button type="button" {...restProps}>
      {label}
    </button>
  );
}

// onClick 与 disabled 会被透传到 button 元素上
// <IconButton label="保存" onClick={handleSave} disabled={true} />
```

> 展开对象中的非标准属性会原样落到 DOM 节点上并触发警告，透传前应明确允许的属性范围。

**速记**：布尔属性只写属性名等于传 true，展开运算符用于成批透传 props。



#### children 的位置

**children**：是夹在开始标签与结束标签之间的内容，被收集为名为 children 的特殊 prop 传给组件。

- 位置：children 由标签之间的内容决定，不在属性列表中书写。
- 类型：可以是文本、表达式、元素，也可以是多段内容的组合。
- 显式传入：也可以在属性位置写 children 传值，效果与夹在标签之间一致。
- 空白处理：标签之间的换行与缩进会被裁剪，行首行尾的空白不参与渲染。

```jsx
function Panel({ title, children }) {
  return (
    <section>
      <h3>{title}</h3>
      <div>{children}</div>
    </section>
  );
}

// 标签之间的内容成为 children
// <Panel title="统计"><p>共 12 条记录</p></Panel>
```

> children 的组合模式与进阶用法详见本主题第 13 篇组件组合。

**速记**：children 是标签之间的内容，作为特殊 prop 传入，换行与缩进会被裁剪。



### 条件与列表的表达

条件与列表在 JSX 中没有专用指令，全部由 JavaScript 表达式与数组方法表达。

#### 三元与逻辑与的写法

**三元表达式**：是在花括号内用条件运算符在两种结果间二选一的写法。**逻辑与**：是在花括号内用逻辑与运算符在条件成立时输出内容、不成立时输出条件本身的写法。

- 三元形式：条件、问号、成立分支、冒号、不成立分支，两个分支都必须是表达式。
- 二选一空值：不渲染的分支写 null，渲染规则见前文「花括号嵌入表达式」一节。
- 逻辑与形式：左侧为真时返回右侧值，为假时返回左侧值，适合有则显示的场合。
- 选择依据：需要两种输出用三元，只需要一种输出用逻辑与。

```jsx
function Notice({ isLoading, message, count }) {
  return (
    <div>
      {isLoading ? <p>加载中</p> : <p>{message}</p>}
      {count > 0 && <p>未读 {count} 条</p>}
    </div>
  );
}
```

> [!CAUTION]
> **注意内容**：逻辑与左侧为数字 0 时会把 0 渲染到界面上，应先把左侧转成布尔值或改用三元表达式。

**速记**：三元用于二选一，逻辑与用于有则显示，须留意左侧为 0 时的渲染结果。



#### 只能写表达式不能写语句

**只能写表达式不能写语句**：指花括号内不接受 if、for、switch 这类语句，只接受有返回值的表达式。

- 原因：花括号会被当作表达式嵌入编译，语句没有返回值，无法放进元素结构。
- 替代写法：分支改用三元或逻辑运算，循环改用数组的 map 方法。
- 语句外提：确实需要语句时，把语句写在 return 之前，用变量保存结果再嵌入。
- 函数体自由：组件函数体内可以写任意语句，限制只在 JSX 的花括号内。

```jsx
function ScoreList({ scores }) {
  // 语句写在 return 之前
  const total = scores.reduce((sum, score) => sum + score, 0);

  return (
    <ul>
      {scores.map((score) => (
        <li key={score.id}>{score.value}</li>
      ))}
      <li>合计 {total}</li>
    </ul>
  );
}

// 花括号内不能写 if 语句或 for 语句，它们没有返回值
```

> 这条限制来自 JavaScript 语法本身：凡是以表达式为构成单位的写法都不接受语句。

**速记**：花括号内只放表达式，分支用三元、循环用 map，语句写在 return 之前。



#### map 渲染列表的语法形态

**map 渲染列表**：是用数组的 map 方法把数据数组转换为元素数组并嵌入结构的写法，方法签名为 map(callback, thisArg)，callback 接收 (element, index, array) 并返回新元素。

- 回调要求：回调必须返回一个元素，返回 null 或 false 时该位置不渲染内容。
- key 语法：返回的顶层元素需要带 key 属性，取值须在同级列表中唯一。
- 嵌套列表：每层列表各自维护 key 的唯一性，不与其它层级比较。
- 返回值形态：map 得到的是元素数组，可以直接放进花括号参与渲染。

```jsx
function TodoList({ todos }) {
  return (
    <ul>
      {todos.map((todo) => (
        <li key={todo.id}>{todo.title}</li>
      ))}
    </ul>
  );
}

// todos 为 [{ id: 1, title: "写文档" }, { id: 2, title: "审阅" }] 时渲染两个列表项
```

> key 的取值策略、列表的状态保持与空列表处理详见本主题第 5 篇条件渲染与列表渲染，本篇只讲语法形态。

**速记**：用 map 把数据数组转成元素数组，回调返回带 key 的元素。



### 片段与多根节点

组件必须返回单个根节点，Fragment 提供了在不增加额外 DOM 层级的前提下返回多段内容的手段。

#### Fragment 的作用

**Fragment**：是 React 提供的特殊组件，用于把多个元素归为一组返回，而不在真实 DOM 中产生对应的包裹节点。

- 结构作用：让组件返回多段平级内容，满足单一根节点的返回要求。
- 无额外节点：与用 div 包裹不同，Fragment 不会在页面上生成多余的容器。
- 布局影响：包一层无意义的 div 可能破坏弹性布局或选择器结构，Fragment 避免该问题。
- 导入方式：使用具名导入从 react 包取得 Fragment。

```jsx
import { Fragment } from "react";

function UserMeta({ user }) {
  return (
    <Fragment>
      <dt>{user.name}</dt>
      <dd>{user.email}</dd>
    </Fragment>
  );
}
```

> 组件返回多段内容也可以写成数组，但数组形式需要显式 key，可读性不如 Fragment。

**速记**：Fragment 把多段元素归为一组返回，且不产生额外的 DOM 节点。



#### 短语法与带 key 的长语法

**短语法**：是 Fragment 的空标签简写形式，省略组件名与属性，适用于不需要 key 的场景。**长语法**：是显式写 Fragment 组件名的形式，支持传入 key，适用于遍历生成的片段。

- 短语法：写成一对空尖括号，不能携带任何属性，因此不能传 key。
- 长语法：写成 Fragment 标签，可以传 key 与其它允许的属性。
- 选择依据：遍历产生的片段需要 key 时只能用长语法。
- 编译结果：短语法与不带属性的长语法编译后等价。

```jsx
// 短语法：不需要 key 时使用
const header = (
  <>
    <h1>标题</h1>
    <p>副标题</p>
  </>
);

// 长语法：遍历生成片段时需要 key
const rows = items.map((item) => (
  <Fragment key={item.id}>
    <dt>{item.term}</dt>
    <dd>{item.definition}</dd>
  </Fragment>
));
```

> [!TIP]
> **建议内容**：优先使用短语法，只有遍历生成且必须携带 key 时才改写为 Fragment 长语法。

**速记**：短语法不能带属性，长语法可传 key，遍历生成片段时用长语法。



#### 多根节点的返回

**多根节点的返回**：是组件一次返回多段平级内容的写法，通过 Fragment 或元素数组满足单根返回约束。

- 返回要求：组件函数必须有返回值，且返回值是单个元素、Fragment 或 null。
- 不返回内容：组件不渲染内容时返回 null，不能省略返回值。多段内容的组织方式见前文 Fragment 两节。

```jsx
function OrderSummary({ order }) {
  // 错误：并排返回两个顶层标签会被当作语法错误
  // return <p>{order.total}</p><p>{order.status}</p>;

  return (
    <>
      <p>{order.total}</p>
      <p>{order.status}</p>
    </>
  );
}
```

> null、false 与 undefined 不渲染的完整规则见前文「花括号嵌入表达式」一节。

**速记**：组件必须返回单个元素、Fragment 或 null。



### 元素、组件与实例之别

三者常被混为一谈：元素是描述对象，组件是函数，实例由框架在渲染过程中创建与管理。

#### 元素是不可变描述对象

**元素（element）**：是描述界面上应该出现什么的普通 JavaScript 对象，创建后不再修改，只描述某一时刻的界面。

- 结构：包含 type、props、key 等字段，type 为字符串时表示宿主元素，为函数时表示组件。
- 不可变：元素对象一旦创建就不再修改，重新渲染会生成新的元素对象。
- 轻量：创建元素不涉及 DOM，也不执行组件，只是构造一个对象。
- 描述性：元素描述的是结果，不包含任何更新步骤。

```jsx
// JSX 编译后返回的即为元素对象，近似结构如下
const element = {
  type: "h1",
  props: { className: "title", children: "Hello" },
  key: null,
};
```

> 元素不等于 DOM 节点：元素是描述，DOM 节点是描述经过协调后落到页面上的真实结果。

**速记**：元素是不可变的描述对象，包含 type 与 props，创建它不涉及 DOM。



#### 组件是函数

**组件（component）**：是接收 props 并返回元素的函数，其函数名即元素的 type，由框架在渲染时调用。

- 调用时机：渲染过程中由框架调用，组件自身不调用其它组件。
- 输入输出：输入是 props 对象，输出是元素、Fragment 或 null。
- 纯函数要求：同样的 props 应得到同样的输出，不在渲染阶段修改外部状态。
- 命名要求：组件名用大驼峰，首字母大写用于与宿主标签名区分。

```jsx
function Welcome({ name }) {
  // 组件是被框架调用的函数，返回元素的描述
  return <p>欢迎，{name}</p>;
}

// 写成元素后由框架在渲染时调用
// <Welcome name="Ada" />
```

> [!IMPORTANT]
> **重要内容**：组件名必须以大写字母开头，写成小写会被当作宿主标签名处理，从而渲染出未知标签。

**速记**：组件是接收 props 并返回元素的函数，由框架调用，命名用大驼峰。



#### 实例由框架管理

**实例（instance）**：是框架在渲染过程中为组件建立并维护的内部载体，开发者不直接创建也不直接持有它。

- 创建时机：组件首次被渲染时，框架为其建立对应的工作单元并保存 state。
- 状态存放：state 与副作用登记都挂在这个内部载体上，随组件在树中的位置绑定。
- 不暴露：函数组件没有 this，无法从外部取得实例引用。
- 生命周期：挂载时创建，卸载时销毁，中间可能经历多次重新渲染而实例保持不变。

```jsx
function Toggle({ on, onToggle }) {
  // 每次渲染都读到最新的 props，状态本身存放在框架维护的实例上
  return <button onClick={onToggle}>{on ? "开" : "关"}</button>;
}
```

> 函数组件里谈不到 this：实例的概念用于理解状态的存放位置，不用于编写代码。

**速记**：实例由框架创建与销毁，函数组件无法从外部拿到它。



#### 三者关系与常见误解

**三者关系**：组件是被调用的函数，元素是它返回的描述对象，实例是框架依据元素与位置维护的内部载体。

- 关系链：框架调用组件得到元素，再依据元素与既有的实例状态完成协调与提交。
- 误解一：把元素当作组件，认为创建元素就会渲染界面，实际上创建元素只是构造对象。
- 误解二：以为重新渲染会重建实例，实际上实例按位置保留，这也是 state 得以保持的原因。
- 误解三：用函数调用的方式直接调用组件函数，这会绕过框架，组件内部若有 Hook 将报错。

```jsx
function Item({ label }) {
  return <li>{label}</li>;
}

// 正确：把组件写成元素交给框架渲染
const list = <ul><Item label="第一项" /></ul>;

// 错误：直接调用组件函数会绕过框架，组件内部若有 Hook 将报错
// const wrong = Item({ label: "第一项" });
```

> 三者的区分是理解渲染流程的起点，Fiber 节点与协调过程详见本主题第 17 篇渲染原理：Fiber 与协调。

**速记**：组件产出元素，元素与位置共同决定实例，直接调用组件函数会绕过框架。
