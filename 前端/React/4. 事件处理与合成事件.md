## 事件处理与合成事件

### 事件绑定与处理函数

事件把用户操作接入组件逻辑，本节说明 JSX 事件属性、处理函数的传法与组织方式。

#### JSX 中事件属性的驼峰命名

**事件属性**：是 JSX 标签上以 on 开头的驼峰命名属性，用于把处理函数绑定到对应事件。

- 命名：原生 onclick 在 JSX 中写作 onClick，onchange 写作 onChange，一律小驼峰。
- 取值：值必须是函数，不能是字符串。
- 事件名：去掉 on 后的大驼峰部分是事件类型，如 Click、Change、Submit。
- 覆盖范围：鼠标、键盘、表单、焦点、滚轮等常用原生事件都有对应的合成事件属性。

```jsx
function ActionButton() {
  function handleClick() {
    console.log("已点击");
  }

  return <button onClick={handleClick}>确定</button>;
}
```

> 原生属性可以写 onclick 加代码字符串，JSX 的 onClick 只接收函数，二者的取值形式不同。

**速记**：JSX 事件属性用 on 加驼峰命名，值必须是函数。



#### 传函数引用与传调用结果的差别

**函数引用**：是函数本身，写作 handleClick；**调用结果**：是函数执行后的返回值，写作 handleClick()。两者在事件属性中含义完全不同。

- 传引用：onClick={handleClick}，事件触发时才调用。
- 传结果：onClick={handleClick()}，渲染时就执行，返回值被当作处理函数（通常为 undefined）。
- 典型症状：点击没有反应，控制台在渲染阶段就打出日志。
- 需要传参：用箭头函数包一层，而不是在引用后直接加括号。

```jsx
function CounterButton() {
  function handleIncrement() {
    console.log("+1");
  }

  return (
    <div>
      <button onClick={handleIncrement}>正确：传引用</button>
      {/* <button onClick={handleIncrement()}>错误：渲染时立即执行</button> */}
    </div>
  );
}
```

**速记**：事件属性传函数引用，写成调用形式会在渲染期立即执行。



#### 内联箭头函数的取舍

**内联箭头函数**：是直接写在事件属性里的箭头函数，形如 onClick={() => handleRemove(id)}。

- 优点：可以就地传参、访问当前作用域的变量，写法紧凑。
- 代价：每次渲染都创建新的函数对象，作为 props 传给子组件时可能引起额外的重新渲染。
- 优化手段：需要稳定引用或参与依赖比较时提取为具名函数，或使用 useCallback（详见本主题第 11 篇 useMemo 与 useCallback）。
- 取舍：需要传参的场景优先内联，其余场景用具名函数更清晰。

**速记**：内联箭头便于传参，代价是每次渲染都新建函数。



#### 一个组件内多个处理函数

**多处理函数**：是同一组件内按动作拆成多个具名函数，各自负责一类交互。

- 命名：用 handle 加动作的小驼峰名，如 handleSubmit、handleInputChange、handleRemove。
- 可读性：每个函数只做一件事，事件属性按名引用即可。
- 复用：多个元素可共享同一个处理函数，需要区分来源时读事件对象。
- 拆分时机：处理函数超过两三件事，或内部出现明显分支时，按动作再拆。

**速记**：多个交互拆成多个 handleXxx 具名函数，事件属性按名引用。



### 合成事件与事件委托

React 不直接把处理函数绑到元素上，本节说明合成事件模型与事件委托机制。

#### SyntheticEvent 是什么

**合成事件（SyntheticEvent）**：是 React 对浏览器原生事件的跨浏览器包装对象，提供与原生事件一致的接口并抹平浏览器差异。

- 接口一致：事件对象提供 preventDefault、stopPropagation 等方法与 target、type 等属性。
- 统一模型：不同浏览器上拿到的事件对象接口相同，业务代码不必分支判断。
- 类型名：处理函数参数的类型写作 React.MouseEvent、React.ChangeEvent 等。
- 底层事件：通过 event.nativeEvent 可以取到底层的浏览器原生事件对象。

```jsx
function ClickLogger() {
  function handleClick(event) {
    console.log(event.type);        // "click"
    console.log(event.target.tagName);   // 触发事件的元素标签名
  }

  return <button onClick={handleClick}>记录</button>;
}
```

**速记**：SyntheticEvent 是 React 包装过的原生事件，接口统一且可回溯到原生事件。



#### React 挂在根容器上统一委托

**事件委托（event delegation）**：是把子元素的事件监听统一挂在共同祖先上，由祖先接收事件后按目标分发。

- 挂载点：React 17 起把监听器挂在应用挂载的根容器（root container）上，而不是 document。
- 分发：事件冒泡到根容器后，React 依据事件目标在组件树中找到对应处理函数并调用。
- 好处：增删元素不需要逐个绑定与解绑，监听器数量与元素数量无关。
- 边界：在根容器之外以原生方式阻止传播，React 无法感知。

```jsx
function RowList({ rows, onPick }) {
  return (
    <ul>
      {rows.map((row) => (
        <li key={row.id} onClick={() => onPick(row.id)}>{row.text}</li>
      ))}
    </ul>
  );
}
// 每个 li 都没有真实监听器，绑定与分发由 React 在根容器统一完成
```

**速记**：React 把监听器挂在根容器上，用事件委托统一分发。



#### 与原生事件的差别

**合成事件与原生事件的差别**：体现在事件名、绑定位置与事件对象三处。

- 事件名：原生 addEventListener 用 "click" 字符串，JSX 用 onClick 属性。
- 绑定位置：原生直接绑在元素上，合成事件由 React 在根容器统一代理。
- 事件对象：原生是浏览器提供的 Event 实例，合成事件是 SyntheticEvent 包装对象。
- 阻止默认：原生在部分内联场景可写 return false，合成事件必须调用 preventDefault。

**速记**：合成事件是包装层，原生事件对象通过 nativeEvent 取到。



#### 原生事件与合成事件的混用顺序

**混用顺序**：指同一个交互同时触发原生监听与合成事件时，两条链路的执行先后。

- 原生监听：直接绑在元素上的 addEventListener 在目标阶段先收到事件。
- 合成事件：事件冒泡到根容器后，React 才开始按组件树分发处理函数。
- 结论：元素自身的原生监听通常先于对应的合成事件处理函数执行。
- 边界情况：在根容器层面阻止传播，会同时影响合成事件的分发结果。

**速记**：元素上的原生监听先执行，冒泡到根容器后合成事件再分发。



### 事件对象与阻止默认行为

处理函数通过事件对象了解本次交互，本节说明常用属性与阻止默认行为的方式。

#### 事件对象属性

**事件对象**：是处理函数收到的第一个参数，描述本次事件的类型、来源元素与附加数据。

- type：事件名，如 "click"、"change"、"submit"。
- target：实际触发事件的最内层元素。
- currentTarget：注册该处理函数的元素，即事件属性所在的元素。
- key：键盘事件的按键值，如 "Enter"、"Escape"。
- value：表单元素的当前值，通过 event.target.value 读取。

```jsx
function SearchInput({ onSearch }) {
  function handleKeyDown(event) {
    if (event.key === "Enter") {
      onSearch(event.currentTarget.value);
    }
  }

  return <input onKeyDown={handleKeyDown} />;
}
```

> target 与 currentTarget 容易混淆：处理函数绑在父元素而事件由子元素触发时，二者指向不同节点。

**速记**：事件对象提供 type、target、currentTarget、key 等信息。



#### preventDefault 的用法

**preventDefault**：是事件对象上的方法，用于取消浏览器的默认行为，如表单提交导致的页面刷新与链接跳转。

- 签名：event.preventDefault()，无参数、无返回值。
- 表单：在 onSubmit 中调用可阻止页面刷新与地址栏变化。
- 链接：在 onClick 中调用可阻止跳转，改由脚本接管导航。
- 前提：事件必须是可取消的，且要在处理函数的同步阶段调用。

```jsx
function LoginForm() {
  function handleSubmit(event) {
    event.preventDefault();     // 阻止表单默认提交导致的页面刷新
    console.log("改为脚本处理提交");
  }

  return (
    <form onSubmit={handleSubmit}>
      <button type="submit">登录</button>
    </form>
  );
}
```

**速记**：preventDefault 取消浏览器默认行为，表单与链接场景最常用。



#### 不返回 false 的写法

**返回 false 无效**：指 React 的事件处理函数返回 false 不会阻止默认行为，必须显式调用 preventDefault。

- 内联属性差异：HTML 内联的 onclick 属性写 return false 可以阻止默认行为，那是内联脚本的语义。
- JSX 语义：事件属性接收的是函数，返回值被忽略，return false 不起作用。
- 正确写法：在函数体内调用 event.preventDefault()。
- 常见症状：写了 return false 之后表单仍然刷新页面。

```jsx
function LinkButton() {
  function handleClick(event) {
    // return false;                // 无效：合成事件忽略返回值
    event.preventDefault();        // 正确：显式阻止默认行为
    console.log("已阻止跳转");
  }

  return <a href="/docs" onClick={handleClick}>文档</a>;
}
```

**速记**：合成事件忽略返回值，阻止默认行为只能调用 preventDefault。



#### 事件对象的复用与异步访问注意

**异步访问事件对象**：指在处理函数返回之后继续读取事件对象。React 17 起事件对象不再复用，异步读取属性是安全的，但属性指向的 DOM 可能已经变化。

- 陈旧风险：event.target 指向真实 DOM 节点，节点卸载后其值不再代表当时的界面。
- 建议做法：同步阶段先把需要的值复制到普通变量，再交给异步逻辑使用。
- 类型收益：显式复制字段也便于给后续逻辑标注类型。

```jsx
function AsyncReader() {
  function handleChange(event) {
    const value = event.target.value;   // 同步取出
    setTimeout(() => {
      console.log(value);               // 安全：读取的是已保存的副本
    }, 1000);
  }

  return <input onChange={handleChange} />;
}
```

> 事件对象引用的是真实 DOM 节点，节点被卸载后其值可能已经过期。

**速记**：事件对象可异步访问，但应在同步阶段先取出需要的值。



### 传参与闭包陷阱

把参数与标识传进处理函数是常见需求，本节说明两种传参写法与闭包带来的状态问题。

#### 两种传参写法

**传参写法**：是给事件处理函数附加额外数据的两种常见方式，一是箭头函数包裹，二是读取元素上的数据属性。

- 箭头函数包裹：onClick={() => handleRemove(item.id)}，直观且类型清晰。
- 数据属性：在元素上写 data-id={item.id}，处理函数内读 event.currentTarget.dataset.id。
- 取舍：需要传对象或数组时用箭头函数；希望元素与处理函数解耦时用数据属性。
- 代价：两种写法都会为每个元素生成处理逻辑，列表很长时需要评估。

```jsx
function TaskRow({ task, onToggle }) {
  function handleToggle() {
    onToggle(task.id);
  }

  function handleDataToggle(event) {
    onToggle(Number(event.currentTarget.dataset.id));
  }

  return (
    <li>
      {task.text}
      <button onClick={handleToggle}>切换</button>
      <button data-id={task.id} onClick={handleDataToggle}>数据属性切换</button>
    </li>
  );
}
```

**速记**：传参用箭头函数包裹或读 data 属性，前者直观后者解耦。



#### 循环中绑定参数

**循环中绑定参数**：是在列表渲染时为每个元素绑定携带自身标识的处理函数，标识必须进入闭包或写进数据属性（两种写法见前文「两种传参写法」一节）。

- 错误做法：在循环外把 id 存进一个可变变量，所有处理函数都会读到循环结束后的值。
- 前提：列表元素需要稳定的 key（详见本主题第 5 篇 条件渲染与列表渲染）。

```jsx
function NumberList({ numbers, onPick }) {
  return (
    <ul>
      {numbers.map((number) => (
        <li key={number}>
          <button onClick={() => onPick(number)}>{number}</button>
        </li>
      ))}
    </ul>
  );
}
```

**速记**：循环中让每个元素把自己的标识捕获进闭包或写进 data 属性。



#### 闭包捕获旧 state 的现象与原因

**闭包捕获旧 state**：指处理函数读取到的 state 是它被创建那一次渲染的快照，连续快速调用时后一次仍读到旧值。

- 快照机制：每次渲染都会生成一组新的 state 常量，本次渲染中的处理函数只能看到本次的值。
- 典型现象：在同一帧内多次调用 setCount(count + 1)，实际只增加 1。
- 原因：count 是当次渲染的常量，多次相加用的都是同一个旧值。
- 机制细节：快照的形成原理详见本主题第 16 篇 Hook 规则与运行机制。

```jsx
function StepCounter() {
  const [count, setCount] = useState(0);

  function handleTripleClick() {
    setCount(count + 1);   // 三次都基于同一个 count 值
    setCount(count + 1);
    setCount(count + 1);
    // 结果只加 1
  }

  return <button onClick={handleTripleClick}>{count}</button>;
}
```

> [!CAUTION]
> **注意内容**：连续多次基于旧 state 计算并更新，只有最后一次的结果会保留，其余更新被覆盖而丢失。

**速记**：处理函数读到的是所属渲染的快照，多次基于旧 state 计算只生效一次。



#### 用函数式更新规避

**函数式更新**：是给状态更新函数传入回调的写法 setState(prev => next)，回调接收上一次的最新值并返回新值。

- 签名：setState(updater)，其中 updater 为 (prevState) => nextState 的函数。
- 效果：多次连续更新会依次作用，不会因闭包快照丢失更新。
- 适用：新值依赖旧值的场景，如计数累加、数组追加、布尔取反。
- 归属：完整用法归本主题第 7 篇 State 与 useState，此处只用它规避闭包问题。

```jsx
function StepCounter() {
  const [count, setCount] = useState(0);

  function handleTripleClick() {
    setCount((prev) => prev + 1);
    setCount((prev) => prev + 1);
    setCount((prev) => prev + 1);
    // 结果加 3
  }

  return <button onClick={handleTripleClick}>{count}</button>;
}
```

> [!TIP]
> **建议内容**：只要新值依赖旧值，就改用函数式更新 setState(prev => next)，回调参数始终是最新值。

**速记**：新值依赖旧值时用函数式更新，回调参数始终是最新值。



### 受控与非受控的边界

事件模型决定了表单元素有两种管理方式，本节只界定判据，具体写法归第 6 篇。

#### 事件驱动值变化的一般模型

**事件驱动模型**：是界面值的变化由用户交互触发事件、事件处理函数再改变数据的模型。

- 链路：用户操作触发事件，处理函数更新数据，数据变化引起重新渲染。
- 数据位置：值保存在哪里，决定组件是受控还是非受控。
- 单一来源：值若保存在 state，state 就是唯一数据源，界面显示由它决定。
- 补充：不经过用户事件、由代码直接赋值的场景同样遵循这条链路。

```jsx
function NameField() {
  const [name, setName] = useState("");

  function handleChange(event) {
    setName(event.target.value);
  }

  return <input value={name} onChange={handleChange} />;
}
```

**速记**：交互触发事件、事件改数据、数据决定显示，这是两种模式的共同基础。



#### 受控的判据

**受控组件（controlled component）**：是值由 React 的 state 决定、并由事件处理函数更新 state 的表单元素。

- 判据：元素上写了 value（或 checked），并配有 onChange 把新值写回 state。
- 数据来源：显示值完全来自 state，DOM 不保留自己的当前值。
- 收益：校验、格式化、联动可以在每次输入时进行。
- 代价：每个字段都要写一套 value 与 onChange。

```jsx
function EmailField() {
  const [email, setEmail] = useState("");

  return (
    <input
      value={email}
      onChange={(event) => setEmail(event.target.value)}
      placeholder="邮箱"
    />
  );
}
```

**速记**：受控组件用 value 加 onChange 把值交给 state 保管。



#### 非受控的判据

**非受控组件（uncontrolled component）**：是值由 DOM 自身保存、需要时再通过 ref 读取的表单元素。

- 判据：元素上不写 value 与 onChange，缺省值用 defaultValue 或 defaultChecked。
- 数据来源：DOM 持有当前值，React 不参与每次输入。
- 收益：写法更少，适合一次性读取或接入非 React 的第三方控件。
- 代价：无法在输入过程中做实时校验与联动。

```jsx
function QuickSearch() {
  const inputRef = useRef(null);

  function handleSubmit(event) {
    event.preventDefault();
    console.log(inputRef.current.value);   // 提交时再读取
  }

  return (
    <form onSubmit={handleSubmit}>
      <input ref={inputRef} defaultValue="" />
      <button type="submit">搜索</button>
    </form>
  );
}
// ref 的完整用法详见本主题第 10 篇 useRef 与 DOM 交互
```

**速记**：非受控组件把值交给 DOM，提交时再用 ref 读取。
