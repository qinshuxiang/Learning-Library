## State 与 useState

### State 是什么

**State（状态）** 是组件在多次渲染之间需要记住的数据，由 React 代为保存，改动后自动触发重新渲染。本篇只讲 state 的概念与 useState 这个 Hook；状态应当放在哪一层、如何提升与派生，归下一篇。

#### 组件内部状态的定义

**组件内部状态**：是组件自己持有、在组件生命周期内可以变化、并且变化后会触发重新渲染的一份数据。

- 归属：state 属于声明它的那个组件，父组件不能直接读写子组件的 state。
- 可写：与只读的 props（父组件传入的输入）不同，state 只能通过它对应的状态更新函数改写。
- 驱动界面：state 的值变化后，React 会重新调用该组件函数，用新值生成新的元素树。

```jsx
function CounterPanel() {
  const [count, setCount] = useState(0);

  return (
    <button onClick={() => setCount(count + 1)}>
      已点击 {count} 次
    </button>
  );
}
```

> props 是外部传入的输入，state 是组件自己的记忆，两者共同决定一次渲染的输出。

**速记**：state 是组件自持、可变化、变化即触发重新渲染的数据。



#### state 与普通变量的差别

**state 与普通变量的差别**：普通变量在函数每次执行时被重新创建并丢失，state 由 React 在多次渲染之间保留下来。

- 普通变量：每次渲染都重新初始化，给它赋新值不会让界面更新。
- state：React 记住上一次的值，调用状态更新函数会安排一次新的渲染并读到新值。
- 选择：需要跨渲染保存并驱动界面的数据用 state，只在单次渲染内使用的中间结果用普通变量。

> 判断标准是「这个值是否需要被记住并影响下一次渲染」，需要就用 state，否则保持为普通变量。

**速记**：普通变量随渲染重建，state 由 React 跨渲染保存。



#### state 是渲染快照

**state 是渲染快照（snapshot）**：指某一次渲染中读到的 state，在该次渲染全过程内固定不变，不会因为随后调用状态更新函数而改变。

- 固定性：渲染函数执行期间，state 变量始终是本次渲染开始时的那个值。
- 事件处理函数：处理函数捕获的是定义它的那次渲染的 state，不是调用时刻的最新值。
- 成因：快照来自闭包与 Hooks 的存储模型，运行机制归第 16 篇。

在上面的事件处理函数中，调用状态更新函数之后再读取 state，console.log 打印的仍是本次渲染的快照值。

> 快照语义解释了一个常见困惑：调用状态更新函数后立刻读取 state，读到的仍是旧值。

**速记**：一次渲染读到的 state 是固定快照，本次渲染内读不到更新后的值。



### useState 的签名与用法

**useState** 是声明一份 state 的 Hook。理解它的关键在于把签名、返回值与命名约定一次记全，后面的更新规则都建立在这三者之上。

#### useState 的完整签名

**useState**：是 React 提供的 Hook，签名是 useState(initialState)，返回一个由当前 state 与状态更新函数组成的二元数组，即 [state, setState]。

- 参数 initialState：首次渲染时使用的初始值，可以是任意类型的值，也可以是一个无参并返回初始值的函数。
- 返回值第一项 state：本次渲染中该状态的值。
- 返回值第二项 状态更新函数：接受新值或更新函数，调用后安排一次重新渲染。

```jsx
const [count, setCount] = useState(0);
const [todos, setTodos] = useState([]);
const [profile, setProfile] = useState({ name: "Ada Lovelace", age: 36 });
```

> 状态更新函数的名称由使用方决定，React 不做限制，社区约定为 set 加状态名。

**速记**：useState(initialState) 返回 [state, 状态更新函数] 二元数组。



#### 解构命名约定

**解构命名约定**：指用数组解构取出返回值中的两项，state 用名词，状态更新函数用 set 加首字母大写的同一个名词。

- 名词：count、todos、isOpen，含义直接对应所存数据。
- 更新函数：setCount、setTodos、setIsOpen，与 state 一一对应。
- 多份状态：命名必须彼此可区分，避免 setState 这类无信息量的名字。

```jsx
function SearchBox() {
  const [keyword, setKeyword] = useState("");
  const [isFocused, setIsFocused] = useState(false);

  return (
    <input
      value={keyword}
      onFocus={() => setIsFocused(true)}
      onBlur={() => setIsFocused(false)}
      onChange={(event) => setKeyword(event.target.value)}
      placeholder={isFocused ? "输入关键词" : "等待聚焦"}
    />
  );
}
```

**速记**：值用名词，更新函数用 set 加同名名词，成对命名。



#### 多次调用与多份 state

**多次调用与多份 state**：指在同一组件中调用 useState 多次，会得到彼此独立的若干份 state，更新其中一份不影响其余各份。

- 独立更新：调用某一份的更新函数，只会改变那一份的值。
- 组织建议：把关系松散的数据拆成多份 state，比塞进一个大对象更易读写。
- 顺序稳定：多次调用必须保证在每次渲染中顺序一致，这是 Hook 规则的要求，机制见第 16 篇。

```jsx
function EditorPanel() {
  const [title, setTitle] = useState("");
  const [content, setContent] = useState("");
  const [isPreview, setIsPreview] = useState(false);

  return (
    <div>
      <input value={title} onChange={(event) => setTitle(event.target.value)} />
      <textarea value={content} onChange={(event) => setContent(event.target.value)} />
      <button type="button" onClick={() => setIsPreview(!isPreview)}>
        {isPreview ? "编辑" : "预览"}
      </button>
    </div>
  );
}
```

> 拆成多份 state 不会增加渲染次数：同一事件中的多次更新会被批量处理，下文详述。

**速记**：多次调用得到多份互相独立的 state，更新只作用于目标那一份。



### 状态更新与不可变更新

更新 state 只有一条正路：产生一个新值交给状态更新函数。理解不可变更新，是理解 React 为何能识别变化的前提。

#### 更新函数接受新值或更新函数

**状态更新函数**：是 useState 返回的第二项，接受一个参数，该参数可以是新的 state 值，也可以是一个接收上一次 state 并返回新 state 的函数。

- 传新值：setCount(count + 1)，用本次渲染的快照值算出结果。
- 传更新函数：setCount((previous) => previous + 1)，React 会把上一次的值交给这个函数。
- 选择：新值不依赖旧值时传值，依赖旧值时传更新函数。

```jsx
setCount(5);                          // 直接设为 5
setCount((previous) => previous + 1); // 在上一次的值上加 1
setCount(() => 0);                    // 忽略上一次的值，重置为 0
```

> 更新函数应当是纯函数：只依据入参计算并返回新值，不修改入参本身。

**速记**：更新函数可传新值，也可传「上一次的值到新值」的映射函数。



#### 为什么不能直接改对象与数组

**不能直接修改对象与数组**：指对 state 中的对象或数组就地改写时引用不变，React 因此判定该 state 没有变化。

- 比较方式：React 用 Object.is 比较新旧 state，引用相同即视为未变化。
- 后果：push 数组或改写对象字段之后引用未变，界面不会更新。
- 正解：产生新对象或新数组，让引用发生变化。

```jsx
const [todos, setTodos] = useState(["读书"]);

// 错误：就地修改，引用未变，界面不更新
// todos.push("跑步");
// setTodos(todos);

setTodos([...todos, "跑步"]); // 正确：返回新数组
```

> [!WARNING]
> **警告内容**：就地修改 state 中的对象或数组会绕过变化检测，表现为数据已变而界面未变，且难以排查。

**速记**：变化判断靠引用比较，就地修改后引用不变等于没变。



#### 对象与数组的不可变写法

**不可变写法（immutable update）**：指用展开运算符、map、filter、slice、toSpliced 等返回新集合的方式表达增、删、改。

- 新增：setTodos([...todos, newTodo])。
- 改写某一项：setTodos(todos.map((todo) => todo.id === id ? { ...todo, done: true } : todo))。
- 删除某一项：setTodos(todos.filter((todo) => todo.id !== id))。
- 指定位置替换：setTodos(todos.toSpliced(index, 1, newTodo))，返回新数组且不改原数组。
- 改写对象字段：setProfile({ ...profile, name: "Grace Hopper" })。

```jsx
function TodoList() {
  const [todos, setTodos] = useState([
    { id: 1, text: "读书", done: false },
    { id: 2, text: "跑步", done: true },
  ]);

  function toggleTodo(id) {
    setTodos(todos.map((todo) =>
      todo.id === id ? { ...todo, done: !todo.done } : todo
    ));
  }

  function removeTodo(id) {
    setTodos(todos.filter((todo) => todo.id !== id));
  }

  return (
    <ul>
      {todos.map((todo) => (
        <li key={todo.id}>
          <button onClick={() => toggleTodo(todo.id)}>
            {todo.text} {todo.done ? "已完成" : "未完成"}
          </button>
          <button onClick={() => removeTodo(todo.id)}>删除</button>
        </li>
      ))}
    </ul>
  );
}
```

> toSpliced、with、toReversed 是 ES2023 的不可变数组方法，旧运行环境可用 slice 与展开运算符代替。

**速记**：展开、map、filter、toSpliced 返回新集合，是 state 更新的标准写法。



#### 嵌套对象的更新

**嵌套对象的更新**：指修改深层字段时，需要沿路径逐层复制所有祖先对象，未变化的分支保持原引用。

- 逐层展开：每一层都要写一次展开运算符，漏掉一层就会改到原对象。
- 代价：层级越深样板越多，可把深层数据抽成独立 state，或改用 useReducer，用法见第 12 篇。
- 原则：只重建变化的分支，其余分支复用原引用，便于后续比较。

```jsx
const [user, setUser] = useState({
  id: 1,
  name: "Ada Lovelace",
  address: { city: "London", street: "Baker Street" },
});

function changeCity(city) {
  setUser({
    ...user,
    address: { ...user.address, city },
  });
}
```

**速记**：嵌套更新要逐层复制祖先对象，未改动的分支保持原引用。



### 批量更新与异步特性

状态更新不是对变量的即时赋值，而是向 React 提交一次变更请求。这一节说明请求何时生效、如何合并，以及连续更新时该用什么写法。

#### 更新是异步可见的

**更新异步可见**：指调用状态更新函数不会立刻改变本次渲染中的 state 变量，React 会在当前事件处理结束后统一安排重新渲染。

- 不立即改：同一段处理逻辑里，state 仍是本次渲染的快照。
- 记入队列：更新请求先被登记，等处理逻辑结束再执行渲染。
- 读取时机：需要新值时应先在局部变量中算出，或留到下一次渲染读取。

> 更新不是「立刻改内存再刷新界面」，而是「登记一次状态变更，随后重新渲染」。

**速记**：调用更新函数只登记变更，新值要到下一次渲染才可见。



#### 一次事件中的多次更新会被批量处理

**批量处理（batching）**：指同一个事件处理函数中触发的多次状态更新会被合并，只引起一次重新渲染。

- 范围：React 18 起自动批量处理覆盖事件处理、Promise 回调、定时器回调等场景。
- 收益：多次更新只渲染一次，减少重复计算与重复提交。
- 观察：一次点击里更新多份 state，组件函数只执行一次。

```jsx
function BatchDemo() {
  const [first, setFirst] = useState(0);
  const [second, setSecond] = useState(0);

  console.log("渲染一次"); // 每次点击只输出一次

  function handleClick() {
    setFirst(first + 1);
    setSecond(second + 1);
  }

  return <button onClick={handleClick}>{first} / {second}</button>;
}
```

**速记**：同一事件中的多次更新被合并为一次重新渲染。



#### 连续更新的正确写法

**连续更新的正确写法**：指多次更新都依赖上一次的值时，必须传更新函数，不能使用本次渲染的快照值。

- 错误写法：setCount(count + 1) 连写三次，三次都用同一个快照值，结果只加 1。
- 正确写法：setCount((previous) => previous + 1) 连写三次，每次都取到上一步的结果，结果加 3。
- 原理：React 依次以队列中累积的最新值调用更新函数。

```jsx
function TripleCounter() {
  const [count, setCount] = useState(0);

  function handleWrong() {
    setCount(count + 1);
    setCount(count + 1);
    setCount(count + 1); // 结果只加 1
  }

  function handleRight() {
    setCount((previous) => previous + 1);
    setCount((previous) => previous + 1);
    setCount((previous) => previous + 1); // 结果加 3
  }

  return (
    <div>
      <span>{count}</span>
      <button onClick={handleWrong}>错误 +3</button>
      <button onClick={handleRight}>正确 +3</button>
    </div>
  );
}
```

> [!IMPORTANT]
> **重要内容**：只要新值由旧值推导，就必须写成更新函数形式，否则批量处理会把多次更新压成只生效一次。

**速记**：依赖旧值的连续更新一律写成「上一次的值到新值」的函数。



#### 渲染后才读到新值

**渲染后才读到新值**：指更新后需要使用新值时，不能在调用处读取 state，而应先在局部变量中算出，或把逻辑留到下一次渲染。

- 局部变量：先算出目标值，用它更新 state，并同时用于后续逻辑。
- 下一次渲染：把依赖新值的动作放到渲染阶段或副作用中执行，用法见第 9 篇。
- 常见错误：更新后立刻读取 state 继续计算，结果始终落后一步。

```jsx
function SearchForm() {
  const [keyword, setKeyword] = useState("");

  function handleSubmit(event) {
    event.preventDefault();
    const trimmed = keyword.trim(); // 先在局部变量中算出要用的值
    setKeyword(trimmed);
    console.log(trimmed);           // 用的是局部变量，不是 state
  }

  return (
    <form onSubmit={handleSubmit}>
      <input
        value={keyword}
        onChange={(event) => setKeyword(event.target.value)}
      />
    </form>
  );
}
```

> [!CAUTION]
> **注意内容**：在调用状态更新函数之后立刻读取 state 会读到旧值，据此继续计算会让逻辑慢一拍。

**速记**：更新后要用新值就先在局部变量里算，读取 state 要等到下一次渲染。



### 状态初始化的时机

初始值只在组件第一次挂载时使用一次，这决定了初始化写法、惰性求值的取舍，以及用 props 初始化时容易踩的坑。

#### 直接传值与传函数两种写法

**初始值写法**：useState 的入参可以是初始值本身，也可以是一个无参并返回初始值的函数。

- 传值：useState(0)、useState("")，字面量或简单表达式直接给出。
- 传函数：useState(() => createInitialRows())，函数只在首次渲染时被调用。
- 等价性：初始值可由常量直接表达时，两种写法的结果相同。

```jsx
const [count, setCount] = useState(0);              // 写法一：直接传值
const [rows, setRows] = useState(() => createInitialRows()); // 写法二：传函数

function createInitialRows() {
  return Array.from({ length: 3 }, (element, index) => index + 1); // [1, 2, 3]
}
```

**速记**：初始值可传值，也可传一个无参并返回初始值的函数。



#### 惰性初始化的适用场景

**惰性初始化（lazy initialization）**：指把初始值的计算放进函数，React 只在首次渲染时调用一次，避免每次渲染重复计算。

- 适用：读取 localStorage、解析大段 JSON、生成随机数或唯一标识等开销较大的初始化。
- 不适用：初始值只是字面量或简单表达式，包成函数只增加噪音。
- 写法：把 useState 的入参从表达式改成函数，其余不变。

```jsx
function ThemeProvider() {
  // 每次渲染都会执行 readTheme()，重复承担开销
  // const [theme, setTheme] = useState(readTheme());

  const [theme, setTheme] = useState(() => readTheme()); // 只在首次渲染执行

  return <span>当前主题：{theme}</span>;
}

function readTheme() {
  return localStorage.getItem("theme") ?? "light";
}
```

> [!TIP]
> **建议内容**：初始值需要读取存储、遍历集合或生成随机数据时使用惰性初始化，把入参写成函数形式。

**速记**：初始值计算有成本时传函数，只算一次而不是每次渲染都算。



#### 初始值只在首次挂载使用

**初始值只在首次挂载使用**：指 useState 的入参仅在该组件第一次渲染时生效，后续渲染会忽略它并沿用当前 state。

- 忽略后续：重新渲染时传入的初始值不会覆盖已有 state。
- 重新挂载才重置：组件卸载后再次挂载，才会重新取一次初始值。
- 常见误区：父组件传入新的 prop 触发渲染，子组件的 state 不会因此回到初始值。

```jsx
function Greeting({ defaultName }) {
  // 第一次渲染用 defaultName 初始化，之后传入的新值被忽略
  const [name, setName] = useState(defaultName);

  return (
    <input value={name} onChange={(event) => setName(event.target.value)} />
  );
}

// 父组件把 defaultName 从 "Ada" 改成 "Grace"，Greeting 中的 name 仍保持原值
```

> 需要状态跟随 prop 变化时，应当取消这份 state 并直接用 prop 计算，见下一篇的派生状态。

**速记**：初始值只在首次挂载时读取一次，后续渲染一律沿用当前 state。



#### 不要用 props 直接初始化后不管更新

**用 props 初始化 state 的风险**：指以 props 作为初始值之后，props 的后续变化不会同步到 state，界面会出现两份不一致的数据。

- 症状：父组件传入新值，子组件仍显示旧值，刷新页面后才恢复一致。
- 诊断：先问这份数据是否需要独立于 props 演化，不需要就不该另存为 state。
- 替代：能由 props 算出的值直接计算，见下一篇；确实需要跟随变化时可让父组件持有该状态，或改变 key 强制重新挂载。

```jsx
function UserCard({ user }) {
  const [name] = useState(user.name); // 反例：之后 user 变化不会同步

  return <span>{name}</span>;
}

function UserCardFixed({ user }) {
  return <span>{user.name}</span>; // 正解：直接使用 props，不另存一份
}
```

> [!NOTE]
> **提醒内容**：state 是组件的私有记忆，props 是外部输入，一旦用 props 初始化，就要承担两者不同步的后果。

**速记**：用 props 初始化 state 后不同步更新，多半说明这份数据不该存成 state。
