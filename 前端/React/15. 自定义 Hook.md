## 自定义 Hook

**自定义 Hook（custom Hook）**：是以 use 开头的函数，函数内部调用其他 Hook，用于在组件之间复用状态逻辑。

本章只讲自定义 Hook 的写法与设计。逻辑复用优先用自定义 Hook，界面复用才用组合模式（本主题第 13 篇 组件组合：children、render props 与 HOC）；调用顺序、链表存储与闭包快照等内部机制统一归本主题第 16 篇 Hook 规则与运行机制。

### 自定义 Hook 是什么

**自定义 Hook 解决的问题**：是组件之间的状态逻辑复用，把一段带状态、带副作用的逻辑从组件里搬出来供多处调用。

#### 自定义 Hook 的定义

**自定义 Hook**：是一个以 use 开头的函数，函数体内调用至少一个内置 Hook（如 useState(initialState)、useEffect(setup, dependencies)、useContext(SomeContext)），并可选地返回任意值。

- 命名前提：函数名必须以 use 开头，这是标识它需要在组件顶层调用的约定。
- 调用范围：只能从函数组件或另一个自定义 Hook 中调用，不能从普通函数调用。
- 返回值：可以返回任何类型，包括 state、状态更新函数、派生值，或由它们组成的数组与对象。
- 不返回 JSX：自定义 Hook 不描述界面，它只封装逻辑，界面由调用它的组件负责。

```jsx
import { useState } from "react";

function useCounter(initialCount = 0) {
  const [count, setCount] = useState(initialCount);
  const increment = () => setCount((current) => current + 1);
  return [count, increment];
}

function CounterPanel() {
  const [count, increment] = useCounter(10);
  return <button onClick={increment}>count: {count}</button>;
}
```

> 自定义 Hook 只是一次函数调用，React 不会为它单独创建组件实例；它读写的 state 归属于调用它的那个组件。

**速记**：自定义 Hook 是以 use 开头、内部调用 Hook、能返回任意值的函数。



#### 复用状态逻辑而非状态本身

**复用状态逻辑**：指被复用的是一段「怎么读写状态、什么时候同步状态」的算法，而不是某个具体的 state 值，每个调用处各自持有独立的状态。

- 逻辑共享：同一个 useCounter 被两个组件调用，两处共用同一份实现代码。
- 状态独立：两处的 count 是两份互不影响的值，各自的更新函数只影响自己那一份。
- 数据隔离：需要跨调用处共享的数据要提升到父组件（详见本主题第 8 篇 状态提升与单向数据流）。
- 实例计数：一次调用产生一份状态，调用几次就有几份。

```jsx
const [firstCount, incrementFirst] = useCounter(0);    // 独立状态 1
const [secondCount, incrementSecond] = useCounter(5);  // 独立状态 2
// 点击 first 后：firstCount 变 1，secondCount 仍为 5
```

> 模块级变量在所有调用处共享同一份值；自定义 Hook 的状态天然按调用处隔离。

**速记**：自定义 Hook 复用逻辑，state 按调用处各存一份。



#### 与普通工具函数的差别

**与普通工具函数的差别**：普通工具函数是不含 Hook 的纯函数，自定义 Hook 允许调用 Hook，因而能参与组件的渲染与状态更新。

- 能否调用 Hook：普通函数调用 useState 会报错，自定义 Hook 可以。
- 是否依赖渲染：工具函数与渲染无关，同样输入得到同样输出；自定义 Hook 的状态来自组件渲染过程。
- 命名约定：工具函数用动词短语（如 formatCount、getUserById），自定义 Hook 必须 use 开头。
- 适用判断：只做数据变换用工具函数；需要状态、副作用或 Context 才写自定义 Hook。

```jsx
// 工具函数：纯变换，不调用 Hook
function formatCount(count) {
  return count.toLocaleString("en-US");
}

// 自定义 Hook：封装状态，内部调用 Hook
function useToggle(initialValue = false) {
  const [value, setValue] = useState(initialValue);
  return [value, () => setValue((current) => !current)];
}
```

**速记**：能调用 Hook 的是自定义 Hook，纯变换逻辑用工具函数。



#### 与组件的关系

**与组件的关系**：自定义 Hook 依附于组件运行，它读写的 state 属于调用它的组件实例，卸载该组件会同时丢弃这份 state。

- 归属：state 存放在调用它的组件里，不在 Hook 函数自身里。
- 生命周期：组件挂载时建立 state，卸载时连同 Hook 内注册的副作用一起清理。
- 更新触发：Hook 内调用状态更新函数，重新渲染的是调用它的组件。
- 职责分离：Hook 管逻辑，组件管渲染，一个组件可以调用多个自定义 Hook。

> 多个组件调用同一个自定义 Hook 时，各自拥有独立的 state 与独立的副作用，互不干扰。

**速记**：自定义 Hook 的 state 归属于调用它的组件，随组件挂载与卸载。



### 命名与规则

**命名与规则** 决定自定义 Hook 能否被工具识别、能否被安全复用；违反其中任何一条，行为都会退化为难以排查的错误。

#### 必须以 use 开头

**use 前缀**：是自定义 Hook 的强制命名约定，用于向人和工具标明「这个函数内部调用了 Hook」。

- 语言层含义：函数名以 use 开头，规则检查才会把它当作 Hook 处理。
- 工具识别：静态检查按名字前缀判断调用位置是否合法，普通函数名不会进入这项检查。
- 首字母形式：写 useOnlineStatus，不写 UseOnlineStatus 或 useonlinestatus。
- 后果：不以 use 开头却调用 Hook，会被判定为在普通函数里调用 Hook。

```jsx
// 合法：use 开头，被当作自定义 Hook
function useOnlineStatus() {
  const [isOnline, setIsOnline] = useState(true);
  return isOnline;
}

// 不合法：名字没有 use 前缀，内部调用 Hook 会被规则检查拦下
function readOnlineStatus() {
  // const [isOnline] = useState(true); // 报错：普通函数里不能调用 Hook
  return true;
}
```

> use 前缀是规则检查的识别依据，也是 React 区分 Hook 与普通函数的方式。

**速记**：自定义 Hook 必须以 use 开头，供规则检查识别。



#### 内部必须遵守 Hook 规则

**内部遵守 Hook 规则**：指自定义 Hook 内部同样只能在其函数体顶层调用其他 Hook，不能放进条件、循环或嵌套函数。

- 规则一致：自定义 Hook 是 Hook 规则的载体而非例外，它也必须按固定顺序调用 Hook。
- 原因衔接：为什么顺序如此关键，详见本主题第 16 篇 Hook 规则与运行机制。
- 常见错误：在 if 分支里调用 useContext，会让两次渲染的 Hook 调用顺序不一致。
- 自检方式：把全部 Hook 调用集中写在函数体顶部，其后才是条件判断与计算。

```jsx
function useUserRole(userId) {
  const [role, setRole] = useState("guest");

  useEffect(() => {
    setRole(userId ? "member" : "guest");
  }, [userId]);

  return role;
}
```

> [!WARNING]
> **警告内容**：把 Hook 写在条件分支里，会让不同渲染之间的调用顺序发生偏移，取值将落到错误的节点上。

**速记**：自定义 Hook 内部同样只在顶层调用 Hook，顺序固定。



#### 一个 Hook 只做一件事

**单一职责**：指一个自定义 Hook 只封装一类逻辑，命名与返回值都围绕这一件事展开。

- 可读性：职责单一的函数名能直接表达用途，调用处不必读实现就能使用。
- 可组合：小块 Hook 可以互相调用，组合出更复杂的 Hook，如 useUserProfile 内部调用 useFetch 与 useLocalStorage。
- 易测试：职责越小，输入输出越清晰，越容易单独验证。
- 反例：把表单状态、校验、提交、缓存塞进一个 Hook，任何一处改动都会波及其他场景。

> 拆分的信号：当一个 Hook 的返回值出现两组互不相关的字段时，通常说明它可以拆成两个 Hook。

**速记**：一个自定义 Hook 只封装一类逻辑，便于组合与测试。



#### 命名要描述能力与返回值

**命名描述能力**：指函数名应表达它提供的能力或它返回的值，而不是它的内部实现手段。

- 能力型：useOnlineStatus 说明返回是否在线，useLocalStorage 说明提供本地存储读写。
- 结果型：useDebouncedValue 说明返回值是防抖后的值，名字直接对应返回内容。
- 避免实现型：不写 useAddEventListener、useSetInterval，那描述的是内部动作而非对外能力。
- 参数提示：必要时用参数名补充语义，如 useLocalStorage(key, initialValue) 标明需要键名与初值。

```jsx
function useDebouncedValue(value, delay = 300) {
  const [debounced, setDebounced] = useState(value);
  useEffect(() => {
    const timer = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(timer);
  }, [value, delay]);
  return debounced;
}
```

> 命名是自定义 Hook 的公开契约，读者只看名字就应知道返回值的形状与含义。

**速记**：命名描述能力与返回值，不描述内部实现。



### 抽取复用逻辑的步骤

抽取是渐进式重构：先找出重复，再搬运状态与副作用，最后用参数与返回值收口。

#### 识别重复并把逻辑搬进函数

**识别与搬运**：指先在多个组件中发现成组出现、形状一致的 state 与 Effect，再把它们原样移入以 use 开头的函数体，先不改行为。

- 信号一：两处都有同样的 useState(0) 与同样的自增函数。
- 信号二：两处都订阅同一个浏览器事件，写法只差组件内部的处理逻辑。
- 信号三：两处都以相同方式读写 localStorage 的同一个键。
- 搬运要求：保持 Hook 调用顺序不变，Effect 引用的变量随 state 一起搬入。

```jsx
// 抽取前：状态与副作用散落在组件里
function ProfilePage() {
  const [isOnline, setIsOnline] = useState(navigator.onLine);
  // 订阅 online 与 offline，卸载时移除监听
  return <p>{isOnline ? "online" : "offline"}</p>;
}

// 抽取后：同一段逻辑进入以 use 开头的函数，组件只剩一行调用
function useOnlineStatus() {
  const [isOnline, setIsOnline] = useState(navigator.onLine);
  // 原样的订阅与清理逻辑
  return isOnline;
}
```

> 搬运完成后组件里只剩一行调用，逻辑与原来完全等价，可先确认行为不变再继续参数化。

**速记**：先找出重复的 state 与 Effect，再原样搬进以 use 开头的函数。



#### 把变化的量变成参数

**参数化**：指把原先写死在逻辑里的值改成函数参数，并给出默认值，让同一段逻辑适配更多场景。

- 找出差异：不同调用处数值不同的量，通常是延迟毫秒数、初始值、存储键名。
- 设默认值：delay = 300、initialValue = false 这类默认值让常用场景少传参数。
- 同步依赖：参数若被 Effect 使用，必须加入依赖数组，否则会读到旧值（详见本主题第 9 篇 useEffect 与副作用）。
- 避免过载：参数过多说明这个 Hook 承担的职责过多，应考虑拆分。

**速记**：把变化的值提为参数并设默认值，同时同步依赖数组。



#### 把需要外部使用的值作为返回值

**返回值收口**：指只把组件真正需要的值暴露出去，其余中间变量留在 Hook 内部。

- 最小暴露：组件只需要读值时，不要连内部临时 state 一起返回。
- 成对返回：读写配套时返回 [value, setValue] 形式，便于调用处按需改名。
- 派生值：可以在 Hook 内算好派生状态再返回，避免每个调用处重复计算。
- 稳定引用：返回的函数若在 Effect 中被依赖，应保证引用稳定（详见本主题第 11 篇 useMemo 与 useCallback）。

```jsx
function useLocalStorage(key, initialValue = "") {
  const [storedValue, setStoredValue] = useState(
    () => window.localStorage.getItem(key) ?? initialValue
  );
  useEffect(() => {
    window.localStorage.setItem(key, storedValue);
  }, [key, storedValue]);
  return [storedValue, setStoredValue];
}
```

> 返回值就是自定义 Hook 的接口，形状一旦定下，后续所有调用处都会依赖它。

**速记**：只返回组件需要的值，读写成对并保持函数引用稳定。



#### 把组件改写成调用处

**改写调用处**：指删除组件内已搬运的状态与副作用，替换为一行自定义 Hook 调用，并让渲染使用返回的值。

- 删除原代码：去掉搬空的 useState 与 useEffect，避免重复订阅。
- 按需解构：用数组解构或对象解构取出需要的字段，并改成语义化名字。
- 校验行为：逐项对比重构前后的界面与网络请求，确认没有回归。
- 复用扩散：把其他重复的组件依次改为调用同一个 Hook。

```jsx
function StatusBadge() {
  const isOnline = useOnlineStatus();
  const [lastSeen, setLastSeen] = useLocalStorage("last-seen", "");

  useEffect(() => {
    if (!isOnline) setLastSeen(new Date().toISOString());
  }, [isOnline, setLastSeen]);

  return <span>{isOnline ? "online" : "offline since " + lastSeen}</span>;
}
```

**速记**：组件删除原实现，改为一行调用并按需解构返回值。



### 返回值设计

**返回值设计** 决定调用处的书写体验：形状选得合适，改名与扩展都轻松；选得不合适，每次调用都要额外包装。

#### 返回数组还是对象

**返回数组**：适合位置固定、数量少的返回值，调用处可以自由改名。**返回对象**：适合字段较多或需要按名取用的返回值，调用处按需解构且与顺序无关。

- 数组：解构按位置对应，改名方便，约束是调用处必须记住顺序。
- 对象：解构按字段名对应，顺序无关，新增字段不破坏已有调用处。
- 选择依据：两个以内且每一项都要用时选数组，超过两个或调用处只用其中一部分时选对象。
- 一致性：同一个 Hook 的返回形状在项目内应保持一致，不在两种形状之间来回切换。

```jsx
const [count, setCount] = useCounter(0);                 // 数组：按位置解构并改名
const { isOnline, lastChangedAt } = useNetworkStatus();  // 对象：按名取用
```

> 数组的解构位置与返回顺序绑定，一旦调整返回顺序就是破坏性变更。

**速记**：两个以内按位置解构用数组，字段较多用对象。



#### 数组适合两个以内且需改名的值

**数组返回**：指返回 [value, setValue] 这类位置固定的二元数组，调用处解构时可以随意命名。

- 改名能力：同一个 useLocalStorage 在两个组件里可分别解构为 [token, setToken] 与 [theme, setTheme]。
- 顺序即契约：数组的长度与顺序是 Hook 的公开接口，不能随意增删。
- 常见形态：useState 本身就返回二元数组，生态内大量 Hook 沿用该形状。
- 上限建议：超过两项后位置记忆成本上升，改用对象更清晰。

**速记**：二元数组让调用处自由改名，是 useState 延用的形状。



#### 对象便于扩展与忽略部分字段

**对象返回**：指返回由命名字段组成的对象，调用处按需解构，不需要的字段可以不写。

- 按名取用：写作 const { data, isLoading } = useFetch(url)，不关心 error 时可以不接。
- 向后兼容：新增字段不会改变已有解构的含义。
- 可读性：调用处一眼能看出每个值的来源与用途。
- 代价：每次渲染都会创建新对象，若该对象进入依赖数组会产生无谓更新（详见本主题第 11 篇 useMemo 与 useCallback）。

> [!NOTE]
> **提醒内容**：返回对象会被依赖数组按引用比较，把整个返回对象写进依赖数组会因每次渲染都是新引用而反复触发。

**速记**：对象返回按名解构、易于扩展，新增字段不影响旧调用。



#### 把更新函数与稳定引用一起返回

**稳定引用**：指返回的函数在多次渲染之间保持同一引用，使调用处可以安全地把它放进依赖数组。

- 问题来源：Hook 内部每次渲染都新建的箭头函数，引用每次都变。
- 处理方式：用 useCallback(fn, dependencies) 包裹更新函数，依赖数组写清它读取的值。
- 收益：调用处把该函数作为 Effect 依赖或传给子组件时不会反复触发。
- 取舍：函数只在事件回调里使用时，不必为稳定而额外包裹。

```jsx
function useCounter(initialCount = 0) {
  const [count, setCount] = useState(initialCount);
  const increment = useCallback(() => setCount((current) => current + 1), []);
  const reset = useCallback(() => setCount(initialCount), [initialCount]);
  return { count, increment, reset };
}
```

> 把更新函数返回出去时，读者会默认它可以安全依赖，保持引用稳定是对调用处的承诺。

**速记**：返回的更新函数用 useCallback 稳定引用，可安全进入依赖数组。



### 常见自定义 Hook 示例

以下四个示例覆盖订阅、持久化、防抖与请求四类常见诉求，可作为项目内的起步写法。

#### useOnlineStatus

**useOnlineStatus**：是监听浏览器在线状态并返回布尔值的自定义 Hook，初值取自 navigator.onLine。

- 输入：无参数。
- 输出：布尔值，表示当前是否在线。
- 依赖：监听 window 的 online 与 offline 事件，卸载时移除监听。
- 边界：navigator.onLine 只反映网络接口状态，不等于目标服务可达。

```jsx
function useOnlineStatus() {
  const [isOnline, setIsOnline] = useState(navigator.onLine);

  useEffect(() => {
    const updateStatus = () => setIsOnline(navigator.onLine);
    window.addEventListener("online", updateStatus);
    window.addEventListener("offline", updateStatus);
    return () => {
      window.removeEventListener("online", updateStatus);
      window.removeEventListener("offline", updateStatus);
    };
  }, []);

  return isOnline;
}
```

> 依赖数组留空是正确写法，因为订阅只建立一次，回调只调用状态更新函数，不读取会变化的 props 或 state。

**速记**：useOnlineStatus 订阅 online 与 offline 事件，返回是否在线的布尔值。



#### useLocalStorage

**useLocalStorage(key, initialValue)**：是读写 localStorage 并返回二元数组的自定义 Hook，state 初值优先取已存值。

- 参数：key 是存储键名，initialValue 是键不存在时的初值。
- 返回：二元数组，元素依次为当前值与状态更新函数。
- 写入：值变化时同步写回 localStorage，依赖数组包含 key 与 storedValue。
- 兼容：写法与 useState 一致，调用处可把本地存储当作有持久化能力的 state。

```jsx
function useLocalStorage(key, initialValue = "") {
  const [storedValue, setStoredValue] = useState(
    () => window.localStorage.getItem(key) ?? initialValue
  );

  useEffect(() => {
    window.localStorage.setItem(key, storedValue);
  }, [key, storedValue]);

  return [storedValue, setStoredValue];
}
```

> 初值用函数形式传入，读取 localStorage 只在首次渲染时发生一次，避免每次渲染都做无谓的读取。

**速记**：useLocalStorage 以键名与初值为参数，返回持久化的值与更新函数。



#### useDebouncedValue

**useDebouncedValue(value, delay)**：是返回延迟更新后的值的自定义 Hook，用于抑制高频变化引发的重复计算。

- 参数：value 是待防抖的源值，delay 是毫秒延迟，常用 300。
- 返回：防抖后的值，源值稳定超过 delay 毫秒后才更新。
- 清理：每次源值或 delay 变化都清除上一次的定时器。
- 场景：搜索框输入、窗口尺寸监听、滚动位置等高频来源。

```jsx
function useDebouncedValue(value, delay = 300) {
  const [debounced, setDebounced] = useState(value);

  useEffect(() => {
    const timer = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(timer);
  }, [value, delay]);

  return debounced;
}
```

> 调用处把 keyword 传入，得到 debouncedKeyword，在它稳定后再发起搜索；清理函数保证旧定时器不会误触发。

**速记**：useDebouncedValue 用定时器与清理函数把高频值降为稳定值。



#### useFetch 的简化形态与注意事项

**useFetch(url)**：是把请求、加载中与错误三种状态打包返回的自定义 Hook 的简化写法。

- 返回：对象包含 data、isLoading、error 三个字段。
- 时机：url 进入依赖数组，url 变化时重新发起请求。
- 竞态：用 cancelled 标志忽略过期结果，防止慢响应覆盖新结果。
- 边界：这是教学用的最简形态，生产项目应交给成熟的数据请求方案（数据请求的副作用写法详见本主题第 9 篇 useEffect 与副作用）。

```jsx
function useFetch(url) {
  const [state, setState] = useState({ data: null, isLoading: true, error: null });

  useEffect(() => {
    let cancelled = false;
    setState({ data: null, isLoading: true, error: null });

    fetch(url)
      .then((response) => response.json())
      .then((data) => {
        if (!cancelled) setState({ data, isLoading: false, error: null });
      })
      .catch((error) => {
        if (!cancelled) setState({ data: null, isLoading: false, error });
      });

    return () => {
      cancelled = true;
    };
  }, [url]);

  return state;
}
```

> 自定义 Hook 只封装逻辑，不决定界面：加载态与错误态怎么显示由调用它的组件决定。

> [!IMPORTANT]
> **重要内容**：示例中的 useFetch 用于说明封装方式，真实项目中的数据获取与缓存应交由专门的服务端状态方案处理。

**速记**：useFetch 打包请求三态并处理竞态，仅作最简示例。
