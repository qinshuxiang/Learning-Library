## useRef 与 DOM 交互

state 记录参与渲染的数据，而有一类值需要在多次渲染之间保留却不影响输出，还有一类需求要求直接操作真实 DOM 节点，这两类场景都由 ref 承担。本篇讲清 ref 与 state 的分工、useRef 的签名与读写规则、通过 ref 访问 DOM 的时机，以及 ref 的转发与受控暴露。

### ref 是什么

本节先给出 ref 的定义，再划清它与 state 的界线。

#### ref 的定义

**ref（reference）**：是组件在多次渲染之间持久保留的可变引用对象，值存放在 current 属性上，读写它不会触发重新渲染。

- 数据结构：一个普通对象，形如 { current: 值 }，引用在组件存活期内保持不变。
- 生存周期：从首次渲染创建，到组件卸载才被丢弃。
- 关键性质：修改 current 不会通知 React，也不会引起重新渲染。

```jsx
function IdBadge() {
  const idRef = useRef("u-1024"); // { current: "u-1024" }
  return <span>{idRef.current}</span>;
}
```

**速记**：ref 是跨渲染保留的可变引用对象，值在 current 上，改动不触发重新渲染。



#### ref 与 state 的差别

**ref 与 state 的差别**：在于改动是否驱动界面更新，以及值是否参与渲染计算。

- 触发渲染：改 state 会调度重新渲染，改 ref.current 不会。
- 可读时机：ref.current 的写入立即可读，state 更新是异步的。
- 分工：state 描述界面呈现的数据，ref 保存不影响输出的数据。
- 渲染纯度：渲染中可读 state 与 props，但不应在渲染中读写 ref.current。

```jsx
function ClickCounter() {
  const [count, setCount] = useState(0);
  const clicksRef = useRef(0);
  const handleClick = () => {
    clicksRef.current += 1; // 不触发渲染
    setCount(count + 1);    // 触发渲染
    console.log(clicksRef.current, count + 1);
  };
  return <button onClick={handleClick}>{count}</button>;
}
```

> 选择标准：值的变化需要反映到界面上就用 state；只是记录信息供后续逻辑读取就用 ref。

**速记**：state 改动驱动界面，ref 改动不触发渲染，需要上屏的数据用 state。



#### ref 的两种用途

**ref 的两种用途**：一是获取 DOM 节点，二是保存与渲染无关的可变值。

- DOM 用途：把 ref 对象挂到 JSX 元素上，React 在提交阶段把节点写入 current。
- 可变值用途：保存定时器标识、上一轮的值、请求序号等在渲染之间延续的数据。
- 共同点：两类用途都依赖同一份跨渲染持久的可变引用。
- 边界：ref 不参与渲染计算，不用它保存需要在界面上显示的数据。

```jsx
function AutoFocusInput() {
  const inputRef = useRef(null);
  useEffect(() => {
    inputRef.current.focus(); // DOM 用途
  }, []);
  return <input ref={inputRef} />;
}
```

**速记**：ref 一用于获取 DOM 节点，二用于保存与渲染无关的可变值。



### useRef 的签名与用途

useRef 是创建 ref 对象的 Hook，本节给出完整签名与两条使用规则。

#### useRef 的完整签名

**useRef**：是接收一个初始值并返回跨渲染持久的可变对象的 Hook，签名为 useRef(initialValue)，返回形如 { current: initialValue } 的对象。

- initialValue：初始值，可为任意类型，包括 null，只在首次渲染时使用。
- 返回值：一个可变对象，具有可读写的 current 属性。
- 类型标注：通常写成 useRef(null)，并由类型参数描述 current 的元素类型。
- 与 useState 的差别：返回对象本身不是响应式的，改写 current 不会调度渲染。

```jsx
const inputRef = useRef(null); // { current: null }
const timerRef = useRef(0);    // { current: 0 }
```

> useRef 返回的对象在整个组件存活期内保持同一引用，重新渲染拿到的是同一个对象。

**速记**：useRef(initialValue) 返回带 current 属性的同一对象，跨渲染保持引用不变。



#### current 的读写

**current 的读写**：是直接访问 ref 对象的 current 属性，读与写都不经过 React。

- 读：ref.current 取出当前值，写入之后立刻能读到新值。
- 写：ref.current 等于新值，是一条普通赋值语句，不触发渲染。
- 可写性：current 是普通可写属性，没有只读限制。
- 清空：可以重新赋值为 null，表示不再引用原对象。

```jsx
function RunOnce() {
  const runsRef = useRef(0);

  const handleRun = () => {
    runsRef.current = runsRef.current + 1;
    console.log(runsRef.current); // 1，2，3……
  };

  return <button onClick={handleRun}>运行</button>;
}
```

> 把 current 的读写集中在事件处理函数与副作用中，便于确认它没有参与渲染计算。

**速记**：current 可读可写，写入是普通赋值，立即生效且不触发渲染。



#### 初始值只在首次生效

**初始值的生效范围**：是 initialValue 只在首次渲染创建对象时使用，后续渲染传入的值被忽略。

- 只建一次：首次渲染创建 ref 对象，此后每次渲染都返回同一对象。
- 忽略实参：重新渲染时传入的 initialValue 不参与任何计算。
- 常见误用：用某个 state 或 props 作为初始值，期望 ref 跟随它变化，实际不会。
- 正确做法：需要随渲染更新的值用 state，需要同步的值在副作用中显式赋值。

```jsx
function Greeting({ name }) {
  const nameRef = useRef(name); // 只在首次渲染使用 name
  console.log(nameRef.current); // 始终是首次渲染时的 name
  return <span>{name}</span>;
}
```

> [!IMPORTANT]
> **重要内容**：useRef 的初始值只在首次渲染生效，需要 ref 跟随 props 或 state 变化时，必须在副作用中显式同步。

**速记**：initialValue 只用于首次创建对象，后续渲染传入的值一律被忽略。



### 访问 DOM 节点

把 ref 挂到元素上即可在提交之后拿到真实节点，本节说明时机与常见操作。

#### 把 ref 挂到 JSX 元素上

**挂载 ref**：是把 useRef 创建的对象作为元素的 ref 属性传入，由 React 负责把节点写入该对象。

- 写法：在元素上写 ref 属性，值为 ref 对象。
- 支持范围：内置元素如 div、input、button 都接受 ref 属性。
- 与受控的关系：ref 只提供节点访问，不参与元素的值管理，与受控组件不冲突。
- 多节点：需要访问多个节点时分别创建多个 ref 对象。

```jsx
function SearchForm() {
  const inputRef = useRef(null);
  return (
    <form>
      <input ref={inputRef} />
      <button>搜索</button>
    </form>
  );
}
```

> 元素是否受控由值是否来自 state 决定，能否拿到节点由 ref 决定，两件事互不影响。

**速记**：把 ref 对象作为元素的 ref 属性，React 在提交时把对应节点写入 current。



#### current 在挂载后才有值

**current 的就绪时机**：是元素完成提交后 React 才把节点写入 ref.current，在此之前其值为 null。

- 首次渲染：渲染阶段 current 仍是 null，此时无法访问节点属性。
- 提交之后：节点写入 current，可在副作用与事件处理函数中安全使用。
- 卸载之后：节点被移除时 React 把 current 重新置为 null。
- 条件渲染：元素未出现在树中时，对应 ref 的 current 保持 null。

```jsx
function AutoFocusInput() {
  const inputRef = useRef(null);
  useEffect(() => {
    console.log(inputRef.current);              // 提交后：input 元素
    return () => console.log(inputRef.current); // 卸载时：null
  }, []);
  return <input ref={inputRef} />;
}
```

> [!WARNING]
> **警告内容**：在渲染期间读取 ref.current 会得到 null 或上一轮的节点，访问其属性可能直接抛出异常，务必只在提交之后访问。

**速记**：current 在提交后写入节点、卸载时置回 null，渲染期读取不可靠。



#### 读取与聚焦与滚动

**常见 DOM 操作**：是借助 ref.current 调用元素自身的命令式方法，完成聚焦、滚动、播放与测量。

- 聚焦：inputRef.current.focus() 把焦点移到输入框。
- 滚动：listRef.current.scrollIntoView() 把元素滚动到可视区域。
- 播放：mediaRef.current.play() 开始播放音频或视频。
- 测量：getBoundingClientRect 等方法读取元素的尺寸与位置。

```jsx
function SearchBox() {
  const inputRef = useRef(null);
  const focusInput = () => {
    inputRef.current.focus(); // 点击按钮后聚焦输入框
  };
  return (
    <div>
      <input ref={inputRef} />
      <button onClick={focusInput}>聚焦</button>
    </div>
  );
}
```

> 命令式方法只应在事件处理函数或副作用中调用，写在渲染体中会在每次渲染时产生副作用。

**速记**：聚焦、滚动、播放、测量都通过 current 调用元素方法，调用点放在事件或副作用中。



#### 在副作用中访问的时机原因

**在副作用中访问**：是把需要节点的逻辑放进 useEffect，等提交完成后再操作。

- 原因：渲染阶段节点尚未写入 current，副作用在提交之后运行，能保证节点可用。
- 依赖：只在挂载后执行的动作使用空依赖数组。
- 清理：副作用建立的监听要配清理，节点引用本身由 React 管理。
- 只读渲染：渲染只输出 JSX，不读取节点属性来做条件判断。

```jsx
function ScrollToBottom({ messages }) {
  const endRef = useRef(null);
  useEffect(() => {
    endRef.current.scrollIntoView({ behavior: "smooth" }); // 消息变化后滚动到底部
  }, [messages]);
  return <div ref={endRef} />;
}
```

> 需要同步读取布局并立刻写入 DOM 时改用 useLayoutEffect，可避免绘制之后再跳动。

**速记**：节点在提交后才可用，因此读写节点放在副作用中，挂载类动作用空依赖。



### 存储可变值

ref 的另一半用途是保存不影响渲染的可变数据，本节给出四类典型场景。

#### 保存定时器标识

**保存定时器标识**：是把 setInterval 或 setTimeout 的返回值放进 ref.current，供清理函数使用。

- 必要性：setup 与清理函数处于不同调用栈，需要共享同一个标识。
- 写法：setup 中把标识写入 ref.current，清理函数中读取并清除。
- 收益：避免把标识放进 state，从而省掉无意义的重新渲染。
- 收尾：清理后把 current 置回 null，表示计时器已停止。

```jsx
function PollingPanel() {
  const timerRef = useRef(null);
  useEffect(() => {
    timerRef.current = setInterval(() => console.log("poll"), 2000);
    return () => {
      clearInterval(timerRef.current); // 先停止计时器
      timerRef.current = null;         // 再从记账中移除
    };
  }, []);
  return <span>polling</span>;
}
```

> 定时器标识属于纯粹的记账数据，放进 state 只会带来多余渲染，放进 ref 更贴切。

**速记**：定时器标识写入 ref.current，清理函数读取后清除并置回 null。



#### 保存上一轮的值

**保存上一轮的值**：是在副作用中把本轮值写入 ref，供下一轮渲染与上一轮比较。

- 顺序：先读取 ref.current 得到上一轮值，再写入本轮值。
- 用途：趋势判断、跳过首次执行、计算相邻两次的差值。
- 时机：写入必须放在副作用中，避免在渲染期修改 ref。
- 取舍：只用于比较而不上屏用 ref，需要上屏用 state。

```jsx
function PriceTrend({ price }) {
  const previousRef = useRef(null);
  const trend = previousRef.current === null
    ? "无"
    : price >= previousRef.current ? "涨" : "跌";

  useEffect(() => {
    previousRef.current = price; // 渲染完成后记为上一轮
  }, [price]);

  return <span>{trend}</span>;
}
```

> [!NOTE]
> **提醒内容**：在副作用中写入 ref 会使当前渲染读到的仍是上一轮的值，这正是比较类逻辑需要的时序。

**速记**：副作用中先读后写 ref.current，即可在下一轮拿到并比较上一轮的值。



#### 保存不触发渲染的数据

**不触发渲染的数据**：是只在逻辑内部使用、不参与界面输出的值。

- 计数与去重：请求序号、自增实例编号、已处理的标识集合。
- 开关与标记：是否已初始化、是否已上报、上一次的滚动位置。
- 缓存：不参与渲染的临时计算结果。
- 反例：需要在界面上显示的任何数据都应放进 state。

```jsx
function RequestLog() {
  const sequenceRef = useRef(0);

  const logRequest = () => {
    sequenceRef.current += 1;
    console.log("请求序号：" + sequenceRef.current); // 序号只用于日志
  };

  return <button onClick={logRequest}>记录</button>;
}
```

> 判断标准：把该值删掉后界面是否仍然正确；若正确用 ref，若不正确用 state。

**速记**：只服务内部逻辑、删掉后界面不受影响的数据存 ref，需要上屏的存 state。



#### 不在渲染期读写 current

**渲染期隔离**：是要求渲染函数只根据 state 与 props 计算输出，不读取也不写入 ref.current。

- 读取问题：渲染期读到的可能是上一轮的值或 null，输出因此不可预测。
- 写入问题：并发渲染下渲染可能重复或作废，写入会被执行多次。
- 允许的例外：首次渲染时创建 ref 对象本身是允许的，因为它不读取外部状态。
- 后果：渲染期读写会让组件行为依赖渲染次数，破坏可预测性。

```jsx
function BrokenBadge() {
  const countRef = useRef(0);
  // countRef.current += 1; // 渲染期写入：并发渲染下会重复执行
  return <span>{countRef.current}</span>; // 渲染期读取：可能显示过期值
}
```

> [!IMPORTANT]
> **重要内容**：渲染期读写 ref.current 会引入不可预测行为，所有读写都应放在事件处理函数或副作用中。

**速记**：ref.current 的读写只放在事件与副作用中，渲染期一律不碰。



#### 与闭包配合的用法

**与闭包配合**：是用 ref 保存跨渲染共享的值，弥补闭包只捕获当次渲染快照的限制。

- 快照问题：事件处理函数与副作用闭包各自捕获当次渲染的 state 与 props。
- ref 补位：把需要读取最新值的变量放进 ref，闭包通过 current 读到当前值。
- 典型场景：定时器回调读取最新输入、事件监听读取最新参数。
- 取舍：能用依赖数组解决时优先用依赖，ref 只用于确实需要绕过快照的场景。

```jsx
function SearchBox({ keyword }) {
  const keywordRef = useRef(keyword);

  useEffect(() => {
    keywordRef.current = keyword; // 每次渲染后同步最新值
  }, [keyword]);

  useEffect(() => {
    const id = setInterval(() => console.log(keywordRef.current), 1000);
    return () => clearInterval(id); // 回调始终读到最新 keyword
  }, []);

  return <span>{keyword}</span>;
}
```

> 闭包只捕获当次渲染快照的原理详见本主题第 16 篇 Hook 规则与运行机制。

**速记**：闭包只捕获当次快照，用 ref.current 读到最新值，能改依赖时优先改依赖。



### ref 的转发与受控访问

自定义组件默认拿不到内部的 DOM 节点，本节说明转发与受控暴露的写法。

#### 把 ref 传给自定义组件需要转发

**ref 转发的必要性**：是函数组件没有实例，直接把 ref 属性传给自定义组件不会指向任何节点。

- 默认行为：函数组件不接收 ref 属性，未转发时 React 会给出告警。
- 结果：父组件无法直接访问子组件内部的 DOM 节点。
- 解决办法：用 forwardRef 把 ref 转交到内部的具体元素上。
- 替代思路：优先通过 props 传递回调或状态，只在必要时暴露节点。

```jsx
function TextInput() {
  return <input />; // 内部节点没有暴露出口
}
// <TextInput ref={inputRef} /> 报错：函数组件不能接收 ref
```

**速记**：函数组件之间传递 ref 必须转发，否则 ref 不会指向任何节点。



#### forwardRef 的写法与 ref 作为 props 的现状

**forwardRef**：是接收渲染函数并返回可接收 ref 的组件的 API，签名为 forwardRef(render)，render 的第二个参数即 ref。

- 写法：把组件包进 forwardRef，在 render 中把 ref 交给内部元素。
- 现状：React 19 起 ref 可以直接作为普通 props 传递，不必再包 forwardRef。
- 返回值：forwardRef 返回新组件，其 ref 属性指向 render 中被赋值的元素。
- 命名：返回的组件应保持原有名称，便于在调试工具中显示。

```jsx
// React 19：ref 作为普通 props 传递
function TextInput({ ref, ...props }) {
  return <input ref={ref} {...props} />;
}

// 兼容旧写法：用 forwardRef(render)
const LegacyInput = forwardRef(function LegacyInput(props, ref) {
  return <input ref={ref} {...props} />;
});
```

> 两种写法都把 ref 交给内部元素，差别只在于接收 ref 的位置是 props 还是 render 的第二个参数。

**速记**：forwardRef 把 render 的第二个参数 ref 转交内部元素，React 19 起 ref 可直接作为 props。



#### useImperativeHandle 暴露受控方法

**useImperativeHandle**：是配合 ref 暴露自定义命令式方法的 Hook，签名为 useImperativeHandle(ref, createHandle, dependencies?)。

- ref：由父组件传入的 ref 对象。
- createHandle：返回一个对象，其成员即暴露给父组件的方法。
- dependencies：可选依赖数组，依赖变化时重新创建暴露对象。
- 效果：父组件通过 ref.current 调用这些方法，而不是拿到内部节点。

```jsx
const FancyInput = forwardRef(function FancyInput(props, ref) {
  const inputRef = useRef(null);
  useImperativeHandle(ref, () => ({
    focus: () => inputRef.current.focus(), // 只暴露聚焦能力
  }), []);
  return <input ref={inputRef} />;
});
```

> 暴露的是经过挑选的方法而不是整个 DOM 节点，因此可以限制父组件能做的事。

**速记**：useImperativeHandle(ref, createHandle, dependencies?) 用自定义方法替代裸节点暴露。



#### 不要滥用命令式接口

**命令式接口**：是通过 ref 直接调用方法改变界面，与由 props 驱动界面的声明式方式相对。

- 优先声明式：能用 props 与 state 表达的行为不要用 ref 方法。
- 适用场景：聚焦、滚动、播放、测量等浏览器只提供命令式 API 的操作。
- 代价：命令式接口让数据流难以追踪，父子组件耦合更紧。
- 原则：能通过状态传递的信息用 props，节点级动作用 ref。

```jsx
function SearchBox() {
  const inputRef = useRef(null);
  const [keyword, setKeyword] = useState("");
  return (
    <div>
      <input ref={inputRef} value={keyword}
        onChange={(event) => setKeyword(event.target.value)} />
      <button onClick={() => inputRef.current.focus()}>聚焦</button>
    </div>
  );
}
```

> [!WARNING]
> **警告内容**：把本该用 props 表达的交互改写成 ref 方法，会让组件的输入与输出无法从签名看出，破坏单向数据流。

**速记**：能声明式表达的一律用 props 与 state，ref 只留给浏览器强制要求命令式的操作。
