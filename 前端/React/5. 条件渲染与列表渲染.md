## 条件渲染与列表渲染

条件渲染决定哪些内容出现，列表渲染决定同样的内容出现几次，key 决定相邻两次渲染之间哪些列表项是同一个。本篇讲三者的策略与取舍，JSX 中条件表达式与数组 map 的语法形态归第 2 篇（详见本主题第 2 篇 JSX 语法与元素渲染），此处不复述语法。

### 条件渲染的写法

同一个条件分支可以用多种写法表达，选择依据是分支数量、分支是否影响组件后续的全部输出、以及嵌套深度。以下逐个给出判定标准。

#### 早返回与守卫分支

**早返回（early return）**：是在函数组件主体内先判断不成立的分支并直接 return，使后续代码只处理正常路径的写法。

- 适用场景：前置条件不成立时组件整体不渲染，例如加载中、加载失败、无权限。
- 收益：正常路径的缩进层级不增加，后续代码不必重复判断前置条件。
- 边界：return 的值必须是可渲染内容或 null，返回 undefined 会在运行时报错。

```jsx
function UserPanel({ user, isLoading }) {
  if (isLoading) {
    return <p>加载中</p>;
  }
  if (!user) {
    return null; // 无数据时不渲染任何内容
  }
  return <p>{user.displayName}</p>; // 正常路径不再判断前置条件
}
```

> 守卫分支与早返回是同一件事：把前置条件挡在前面，主逻辑留在最后。

**速记**：早返回先挡掉不成立的分支，正常路径不增加缩进。



#### 三元与逻辑与的选择依据

**三元表达式与逻辑与的选择依据**：是分支属「二选一」还是「有或无」——两个分支都有内容用三元，只决定某块内容是否出现用逻辑与。

- 二选一：登录态与未登录态各自渲染一个组件，两个分支都不能缺。
- 有或无：存在错误才渲染错误条，不存在时不渲染任何内容。
- 逻辑与的陷阱：左侧为数字 0 或空字符串时会把该值直接渲染出来，应先把左侧转成布尔值。
- 可读性：条件过长时抽成布尔变量（如 isDisabled），再用于三元的判断位置。

```jsx
function OrderSummary({ count, isPaying }) {
  return (
    <div>
      {count > 0 && <p>共 {count} 件</p>}
      {/* count 为 0 时上面不会渲染出 0 */}
      {isPaying ? <p>支付中</p> : <button>去支付</button>}
    </div>
  );
}
```

> 逻辑与返回的是左侧的值而不是布尔值，React 只跳过 null、undefined、false、true，数字 0 会被当作合法文本渲染。

**速记**：二选一用三元，有或无用逻辑与，注意 0 与空字符串会被渲染。



#### 返回 null 与不渲染的差别

**返回 null 与不渲染的差别**：是组件是否被挂载——返回 null 的组件仍然挂载并保留自身 state，由父级不包含该元素则组件不创建，state 一并丢弃。

- 返回 null：组件仍在，state 保留，副作用仍按依赖数组执行，只是没有输出 DOM。
- 不渲染：父级条件为假导致元素根本不出现在返回结果中，再次出现时是全新挂载。
- 判定：需要在隐藏期间保留输入内容与滚动位置，用返回 null；希望重置则用不渲染。

```jsx
function TogglePanel({ isOpen, children }) {
  // 返回 null：面板的 state 与副作用在隐藏期间保留
  return isOpen ? children : null;
}
```

> 这一差别直接影响状态保持，与本篇最后一个模块「列表中的状态保持」是同一套挂载规则。

**速记**：返回 null 保留挂载与 state，不渲染等同于卸载。



#### 避免深层嵌套的写法

**避免深层嵌套的写法**：是用若干个浅判断替代层层嵌套的三元与逻辑与，使条件在代码里是平的。

- 抽成变量：把组合条件写成 isReady、hasPermission 这样的布尔变量。
- 拆成子组件：把内层分支移入独立组件，各组件只处理一个条件。
- 早返回替代 else：先处理边界情况，主路径不再缩进。
- 映射表：多个互斥分支用对象映射到一个返回元素或组件的函数。

```jsx
function StatusView({ status }) {
  if (status === "loading") return <p>加载中</p>;
  if (status === "error") return <p>加载失败</p>;
  if (status === "empty") return <p>暂无数据</p>;
  return <p>共 {status.length} 条</p>; // 主路径留在最后
}
```

> 嵌套层级是条件写法的可读性上限：超过两层就该考虑拆组件或改用早返回。

**速记**：浅判断加早返回替代深层嵌套，复杂组合先抽成布尔变量。



### 列表渲染与 key

列表渲染把数组的每一项映射成一个元素，key 则告诉 React 相邻两次渲染之间元素与元素如何对应。语法层面的 map 用法归第 2 篇，本节讨论写法要点与 key 的来源。

#### map 返回元素的写法要点

**map 返回元素的写法要点**：是每次迭代都返回一个带 key 的元素，且返回的数组可直接作为 JSX 的子内容。

- 必带 key：列表项元素需要一个写在元素上的 key，缺失时开发环境会给出警告。
- 链式处理：先 filter 过滤，再 map 渲染，两步都返回新数组，不修改原数组。
- 返回值：map 的回调必须返回内容，写成隐式返回的箭头函数最简洁。
- 序号问题：需要显示序号时才用 map 的第二个参数 index，且不要把它当 key。

```jsx
function TodoList({ todos }) {
  return (
    <ul>
      {todos
        .filter((todo) => !todo.done)
        .map((todo) => (
          <li key={todo.id}>{todo.title}</li>
        ))}
    </ul>
  );
}
```

> map 的回调收到 value、index、array 三个参数，列表中只有需要显示序号时才用到 index。

**速记**：列表用 filter 加 map 链式生成，每个元素带 key。



#### key 是什么、由谁使用

**key**：是 React 在协调（reconciliation）阶段用来匹配新旧列表项的特殊 prop，它不传进组件，组件内部读不到它。

- 消费者：key 由 React 自身读取，用于判断某项是移动、保留还是删除。
- 不可读：组件内部拿不到 key，需要用值时应在数据上另设字段并作为普通 prop 传入。
- 兄弟范围：key 只需在同一父元素的直接子元素之间唯一，不同列表之间互不影响。
- 仅列表需要：单个元素不需要 key，只有数组生成的多个兄弟元素需要。

```jsx
function TagList({ tags }) {
  // 组件内部读不到 key，需要的值要用普通 prop 传
  return (
    <ul>
      {tags.map((tag) => (
        <Tag key={tag.id} label={tag.label} />
      ))}
    </ul>
  );
}
```

> key 是渲染元信息而不是业务数据，把它当普通 prop 使用会拿到 undefined。

**速记**：key 只由 React 读取，用于协调时匹配列表项，组件内部无法访问。



#### 找 key 的依据

**找 key 的依据**：是稳定性、可预测性与唯一性三条同时满足——同一项在多次渲染中 key 不变，且与数据一一对应。

- 稳定：不随时间或渲染次数变化，重新渲染后仍是同一个值。
- 可预测：由数据自身决定，相同数据得到相同 key。
- 唯一：在同一组兄弟元素中不重复。
- 优先业务主键：数据库 id、用户名这类天然唯一值最优先。

```jsx
const fruitItems = [
  { id: "apple", name: "苹果" },
  { id: "banana", name: "香蕉" },
];
// 用业务 id 作为 key，插入与排序都不会改变已有项的 key
```

> 三者冲突时以稳定与唯一为先：可预测性主要用来避免同一份数据渲染出不同 key。

**速记**：key 要稳定、唯一、由数据决定，业务主键优先。



### key 的作用与选择

key 的选择直接决定列表项的状态归属与 DOM 复用方式，以下四类取值分别对应不同的后果。

#### 用下标当 key 的后果

**用下标当 key 的后果**：是列表项的位置与身份被绑定，插入、删除、排序都会让原有项拿到下标对应的不同数据，导致状态错位。

- 前置插入：新项占据下标 0，旧项整体后移，React 认为内容变了但组件还在，输入框里残留上一项的内容。
- 排序变化：排序后同一位置的组件被复用，勾选、焦点、动画状态跟着错位。
- 可接受场景：列表只增删结尾、不排序、项内部不携带 state 的静态渲染。
- 判定：只要列表会插入或排序，下标就不合格。

```jsx
// 反例：前置插入后，输入内容会错位到相邻项
{todos.map((todo, index) => (
  <TodoItem key={index} todo={todo} />
))}
// 正例：用业务 id 绑定身份
{todos.map((todo) => (
  <TodoItem key={todo.id} todo={todo} />
))}
```

> [!WARNING]
> **警告内容**：用下标当 key 配合可编辑列表，会让输入内容与勾选状态错位到相邻项，这类缺陷在测试中很难复现。

**速记**：下标当 key 把身份绑到位置，插入与排序必然状态错位。



#### 用随机数当 key 的后果

**用随机数当 key 的后果**：是每次渲染都生成新 key，React 认为所有项都是全新的，从而卸载并重建整段列表。

- 每次都重建：随机数、时间戳在每次渲染中取值不同，旧节点全部卸载。
- 直接后果：列表项内的 state 被清空，输入框失焦，DOM 被反复销毁与创建。
- 性能后果：重建成本高于复用，长列表会明显卡顿。
- 相似错误：在渲染函数里现场创建对象或函数并作为 key 或依赖，也属于同一类问题。

```jsx
// 反例：每次渲染都换 key，输入框会不停失焦
{todos.map((todo) => (
  <TodoItem key={Math.random()} todo={todo} />
))}
```

> [!CAUTION]
> **注意内容**：随机 key 带来的不只是性能损失，用户正在输入的字符也会随卸载而丢失。

**速记**：随机数当 key 等于每次重建，state 清空且频繁卸载。



#### 用业务唯一值

**用业务唯一值**：是取数据中天然唯一且稳定的字段作为 key，这是绝大多数列表的正确做法。

- 来源：服务端 id、slug、用户名、订单号等能唯一标识一项的字段。
- 组合键：单项没有唯一字段时，把两个稳定字段拼成组合键，例如用户 id 与角色 id 拼接。
- 避免重复：拼接结果要保证在同一列表内不重复，否则退化为 React 无法区分。
- 避免可变：不要用会被编辑的字段（如邮箱）当 key，改名会让该项被当作新项。

```jsx
function MemberList({ members }) {
  return (
    <ul>
      {members.map((member) => (
        <li key={`${member.userId}-${member.roleId}`}>
          {member.displayName}
        </li>
      ))}
    </ul>
  );
}
```

> 组合键是数组渲染中最常见的兜底方案，前提是两个字段都稳定且合起来唯一。

**速记**：key 优先取业务主键，无单一主键时用稳定字段组合。



#### 必要时生成稳定标识

**必要时生成稳定标识**：是当数据本身没有唯一字段时，在数据进入 state 之前一次性生成并保存 id，而不是在渲染过程中生成。

- 生成时机：新增项时生成，随数据一起存入 state，后续渲染复用同一个值。
- 生成方式：使用 crypto.randomUUID 或自增计数器，二者都只调用一次。
- 不可放渲染内：写在渲染函数里等同于随机 key，每次都变。
- 数据建模：把 id 视为数据的一部分，与 title 等业务字段同等对待。

```jsx
function createTask(title) {
  return { id: crypto.randomUUID(), title, done: false }; // 只在创建时生成一次
}

function addTask(tasks, title) {
  return [...tasks, createTask(title)]; // id 随数据一起保存
}
```

> 生成稳定标识的关键是时机：在数据产生处生成，在渲染处只读取。

**速记**：没有主键时在数据创建处生成一次 id 存入 state，渲染中只读。



### 列表中的状态保持

React 决定保留还是重建一个组件，依据是它在新旧渲染树中的位置与 key，理解这条规则才能解释列表与条件渲染中 state 的去留。

#### React 按位置与 key 匹配组件

**按位置与 key 匹配**：是 React 在同一父元素的子元素序列中，以「位置加 key」为身份判断新旧元素是否是同一个组件。

- 无 key 时按位置：同一位置、同一类型的元素被视为同一个组件，state 保留。
- 有 key 时按 key：key 相同即视为同一个，位置移动不影响 state 保留。
- key 变化：key 不同即视为不同组件，旧组件卸载、新组件挂载，state 重建。
- 类型变化：同一位置类型不同也视为不同组件，见下一个考点。

```jsx
function CounterPair({ showFirst }) {
  // 两个位置上的元素类型相同，React 按位置区分
  return (
    <div>
      {showFirst && <Counter key="first" />}
      <Counter key="second" />
    </div>
  );
}
```

> 位置加 key 这套身份规则是协调的基础，第 17 篇渲染原理会从 Fiber 节点的角度展开。

**速记**：React 用位置加 key 判断组件身份，身份相同才保留 state。



#### 同一位置不同类型会卸载重建

**同一位置不同类型会卸载重建**：是同一位置上的元素类型从一种换成另一种时，React 不会复用节点，而是卸载旧组件并挂载新组件。

- 类型判定：普通容器元素之间互换、自定义组件之间互换，都算类型不同。
- 后果：该位置以下整棵子树的 state 全部丢弃，副作用按卸载流程清理。
- 常见触发：三元表达式两个分支返回不同组件类型时，切换分支即重建。
- 保留办法：两个分支返回同一组件、靠 props 区分布局，或给同一组件不同 key 明确区分。

```jsx
function Profile({ isEditing }) {
  // 两个分支类型不同，切换时输入内容不会保留
  return isEditing ? <EditForm /> : <ReadonlyView />;
}

function ProfileKeepState({ isEditing }) {
  // 类型相同，仅 props 变化，组件与 state 保留
  return <ProfileForm readOnly={!isEditing} />;
}
```

> [!NOTE]
> **提醒内容**：希望切换时重置 state，把两个分支写成不同类型或给出不同 key 是最直接的手段。

**速记**：同位置换类型即卸载重建，想保留就让类型相同。



#### 条件渲染中的状态丢失与保留

**条件渲染中的状态丢失与保留**：是条件表达式在渲染与不渲染之间切换时，被移除的组件连同 state 一起消失。

- 移除即丢失：条件由真转假，元素从树中移除，state 与 DOM 一并销毁。
- 位置变化也丢失：条件为假时后续兄弟元素位置前移，会被当作新位置上的组件。
- 保留手段：稳定 key 能让兄弟元素跨位置保持身份，从而保留 state。
- 占位换位：需要保留时给每个兄弟元素显式 key，使位置变化不影响身份。

```jsx
function FormRow({ showNote }) {
  return (
    <div>
      <input name="title" />
      {showNote && <input name="note" />}
      {/* 隐藏 note 后，它后面的兄弟元素位置前移 */}
    </div>
  );
}
```

> 条件渲染与列表渲染共用同一套身份规则：判断身份的是位置与 key，不是视觉上的顺序。

**速记**：条件切换会随元素移除丢掉 state，稳定 key 用于跨位置保留。



### 空列表与占位

数据为空、加载中、请求失败是三种不同的界面状态，占位方案决定用户在等待时看到什么。

#### 空态渲染的判断位置

**空态渲染的判断位置**：是在数据相关的渲染逻辑之外统一判断，而不是把判断塞进 map 的回调里。

- 判断依据：数组长度为 0 且已完成加载，才是真正的空态。
- 位置：在列表组件内、生成列表之前用一个早返回处理空态。
- 文案与操作：空态应说明原因并给出下一步操作，例如提示暂无待办并指向新建入口。
- 不可用 map 兜底：map 空数组本身什么都不渲染，会让界面出现无解释的空白。

```jsx
function TodoList({ todos }) {
  if (todos.length === 0) {
    return <p>暂无待办，点击上方按钮新建</p>; // 空态单独渲染
  }
  return (
    <ul>
      {todos.map((todo) => (
        <li key={todo.id}>{todo.title}</li>
      ))}
    </ul>
  );
}
```

> 空数组与加载未完成都会让列表为空，判断空态前必须先确认数据已经返回。

**速记**：空态在列表生成之前统一判断，并给出明确的下一步操作。



#### 加载态与空态与错误态三分

**加载态、空态、错误态三分**：是把正在取数、取到空数据、取数失败当作三种互斥的界面状态，各自渲染各自的内容。

- 加载态：请求进行中，渲染加载提示或骨架占位。
- 空态：请求成功但结果为空，渲染空态说明。
- 错误态：请求失败，渲染错误提示并提供重试入口。
- 互斥判定：三者用同一个状态字段区分，避免同时为真；数据请求的写法详见本主题第 9 篇 useEffect 与副作用。

```jsx
function RemoteList({ state, items }) {
  if (state === "loading") return <p>加载中</p>;
  if (state === "error") return <p>加载失败，请重试</p>;
  if (items.length === 0) return <p>暂无数据</p>;
  return (
    <ul>
      {items.map((item) => (
        <li key={item.id}>{item.name}</li>
      ))}
    </ul>
  );
}
```

> [!IMPORTANT]
> **重要内容**：空态与错误态必须分开，把请求失败渲染成暂无数据会掩盖真实故障。

**速记**：加载、空、错误三态互斥渲染，错误态不能伪装成空态。



#### 占位骨架屏的简单写法

**占位骨架屏**：是在数据返回之前用与真实内容结构相近的占位元素填充页面，减少加载时的布局跳动。

- 结构相近：占位块的数量与尺寸接近真实内容，加载完成后布局不跳。
- 数量固定：用固定长度的数组生成占位块，长度取常见数据量。
- 样式隔离：占位元素用独立的 class 控制灰底与动画，不与真实内容混用样式。
- 兜底：数据量很少或接口很快时，简单的加载文字即可，不必上骨架屏。

```jsx
function TodoSkeleton() {
  const placeholders = [1, 2, 3];
  return (
    <ul>
      {placeholders.map((slot) => (
        <li key={slot} className="skeleton-row" />
      ))}
    </ul>
  );
}
```

> 占位块不携带任何 state，槽位编号作 key 是安全的，因为数量固定、不会插入或排序。

**速记**：骨架屏用固定数量的占位块贴近真实结构，减少布局跳动。
