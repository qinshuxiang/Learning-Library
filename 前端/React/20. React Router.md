## React Router

React Router 是 React 生态中使用最广的客户端路由方案。本篇回答四个问题：路由是什么、怎么装与怎么配、嵌套与布局怎么组织、参数与跳转怎么用，最后给出导航与权限判断的常见写法。

### 客户端路由是什么

客户端路由是单页应用的基本设施，它让地址变化与界面切换不再依赖服务器的整页响应。

#### 单页应用与前端路由

**单页应用（SPA，single page application）**：是只加载一份 HTML 文档、由 JavaScript 接管后续界面切换的应用形态。**前端路由**：是在浏览器端依据当前地址决定渲染哪个页面的机制。

- 一次加载：首次进入时下载应用代码，之后切换页面不再请求整份文档。
- 前端接管：地址变化后由路由匹配到对应组件，在内容区替换渲染结果。
- 状态保留：应用实例不被销毁，全局状态、登录态与滚动位置得以延续。

**速记**：单页应用只加载一份文档，前端路由按地址决定渲染哪个页面。



#### 路由解决 URL 与 UI 的映射

**路由（route）**：是一条路径到渲染内容的映射规则；路由表由若干条路由组成，决定不同地址分别渲染什么界面。

- 输入：浏览器地址栏中的路径与查询字符串。
- 匹配：从路由表中找到与当前路径最匹配的一条。
- 输出：渲染该条路由对应的元素，并把动态段解析成参数。
- 可回溯：地址本身可复制、可分享，刷新后仍能定位到同一界面。

```jsx
import { createBrowserRouter } from "react-router-dom";

const router = createBrowserRouter([
  { path: "/", element: <HomePage /> },
  { path: "/users", element: <UserListPage /> },
  { path: "/users/:userId", element: <UserDetailPage /> },
]);
```

> 路由把界面状态写进地址，因此「当前页面」可以被链接、前进后退与刷新还原，这是纯组件状态做不到的。

**速记**：路由是路径到界面的映射规则，地址因此可分享、可刷新还原。



#### history 模式与 hash 模式的差别

**history 模式**：是使用浏览器 History API 的地址形式，路径形如 /users/1，需要服务器把未命中的路径回退到入口文档。**hash 模式**：是把路由信息放在井号之后的地址形式，形如 /index.html#/users/1，井号后的内容不参与服务端请求。

- 外观：history 模式路径干净；hash 模式地址中始终带一个井号。
- 部署：history 模式需要服务端回退配置；hash 模式无需服务端配合即可用于静态托管。
- 语义：history 模式更贴近常规地址，利于统计与分享；hash 模式规避了刷新 404。

```jsx
import { createBrowserRouter, createHashRouter } from "react-router-dom";

// history 模式：路径干净，依赖服务端的回退配置
const browserRouter = createBrowserRouter(routes);

// hash 模式：无需服务端配合，地址中带井号
const hashRouter = createHashRouter(routes);
```

> [!NOTE]
> **提醒内容**：history 模式部署到静态托管时，未配置回退会出现刷新即 404 的现象；hash 模式不存在这个问题。

**速记**：history 模式路径干净但需服务端回退，hash 模式带井号却不依赖服务端。



#### 为什么不用原生跳转

**原生跳转**：是通过 a 标签或直接给 location 赋值让浏览器重新请求整份文档的行为。

- 整页刷新：重新下载文档、脚本与样式，应用内状态全部丢失。
- 空窗等待：刷新期间页面空白，交互被硬性打断。
- 路由方案：用 Link 等组件接管点击，只更新地址与内容区，不发生整页请求。
- 例外：指向外部站点或确实需要整页重载时，仍应使用原生跳转。

```jsx
import { Link } from "react-router-dom";

// 原生写法：点击后整页刷新，应用状态丢失
// <a href="/users">用户列表</a>

// 路由写法：只更新地址与内容区，应用状态保留
<Link to="/users">用户列表</Link>
```

**速记**：原生跳转整页刷新会丢状态，路由跳转只替换内容区。



### 路由安装与基本配置

安装与配置决定路由如何接入应用：装一个包、定义一张路由表、在入口挂载一次。

#### 安装与依赖包

**安装命令**：是在项目根目录执行 npm install react-router-dom，浏览器端组件与 Hook 均从该包导入。

- 依赖包：浏览器端路由的包名为 react-router-dom，核心能力由 react-router 提供。
- 前提：项目已具备 React 运行环境，可参考本主题第 1 篇 React 简介与编写方式。
- 验证：安装后能从包中导入 createBrowserRouter 与 RouterProvider 即接入成功。

```bash
npm install react-router-dom
```

> 包的拆分方式随版本演进而调整，导入路径以所装版本的官方文档为准，不要照搬旧版本的写法。

**速记**：安装 react-router-dom，组件与 Hook 从该包导入。



#### 用 createBrowserRouter 定义路由表

**createBrowserRouter**：是接收路由配置数组并返回路由实例的函数，签名 createBrowserRouter(routes, options?)，routes 中每一项描述一条路由。

- path：路径字符串，冒号开头的片段表示动态段。
- element：匹配成功后渲染的元素。
- children：嵌套的子路由数组，需要父级提供占位位置。
- errorElement：该路由出错时渲染的元素，承担路由层的错误兜底。

```jsx
import { createBrowserRouter } from "react-router-dom";

const router = createBrowserRouter([
  {
    path: "/",
    element: <AppLayout />,
    errorElement: <PageError />,
    children: [
      { index: true, element: <HomePage /> },
      { path: "users", element: <UserListPage /> },
      { path: "users/:userId", element: <UserDetailPage /> },
    ],
  },
]);
```

> errorElement 负责路由层的错误渲染，与组件层的错误边界互补（详见本主题第 19 篇 错误边界、Suspense 与并发特性）。

**速记**：createBrowserRouter 接收路由配置数组，返回可挂载的路由实例。



#### RouterProvider 与入口衔接

**RouterProvider**：是把路由实例接入 React 树的组件，props 包含 router 与可选的 fallbackElement。挂载点是应用入口文件。

- 挂载：在入口的 createRoot 渲染中把 RouterProvider 作为根元素。
- 数据路由：配合 createBrowserRouter 时，加载与错误处理由路由层统一调度。
- 位置：全局只挂一个 RouterProvider，放在应用最外层。

```jsx
import { createRoot } from "react-dom/client";
import { RouterProvider } from "react-router-dom";
import { router } from "./router";

const root = createRoot(document.getElementById("root"));
root.render(<RouterProvider router={router} />);
```

> [!TIP]
> **建议内容**：把路由表单独放在 router 模块里导出，入口只负责挂载，便于测试与复用同一份配置。

**速记**：RouterProvider 挂在入口最外层，把路由实例接入组件树。



### 嵌套路由与布局

嵌套路由把「外壳」与「内容」拆成父子两级，让共享布局只写一次、子页面各管一段路径。

#### 父路由与子路由的嵌套

**嵌套路由**：是在父路由的 children 中再定义子路由，子路由匹配时渲染在父路由指定的占位处。

- 匹配：子路由路径相对父路由书写，两级路径拼接成完整地址。
- 渲染：父路由元素先渲染，子路由元素渲染在父级的占位位置。
- 用途：把框架与内容分离，避免每个页面重复写导航与容器。

```jsx
const router = createBrowserRouter([
  {
    path: "/users",
    element: <UsersLayout />,
    children: [
      { index: true, element: <UserListPage /> },
      { path: ":userId", element: <UserDetailPage /> }, // 完整路径 /users/:userId
    ],
  },
]);
```

**速记**：子路由写在父路由的 children 中，路径相对父级拼接。



#### Outlet 作为子路由占位

**Outlet**：是嵌套路由中标记子路由渲染位置的组件，无必需 props，匹配到的子路由元素会渲染在它所在处。

- 作用：父路由元素中放入 Outlet，子路由内容便出现在该位置。
- 缺省：父路由未放 Outlet 时，子路由即使匹配成功也不会显示。
- 层级：多级嵌套时，每一层父组件各放一个 Outlet 承接下一层。

```jsx
import { Outlet } from "react-router-dom";

export function UsersLayout() {
  return (
    <section>
      <nav>用户中心</nav>
      <Outlet />   {/* 子路由 UserListPage 或 UserDetailPage 渲染在这里 */}
    </section>
  );
}
```

> 父级忘记放 Outlet 是嵌套路由最常见的空白页原因：匹配成功却无处渲染。

**速记**：Outlet 标记子路由的渲染位置，父级不放它子路由就不显示。



#### 共享布局与导航区

**共享布局**：是把多个页面共用的外壳，如导航、侧边栏与页脚，放在父路由元素中，只定义一次。

- 复用：外壳在父级渲染，切换子页面时导航区不重新挂载。
- 高亮：导航链接用 NavLink，可依据当前路径显示激活态。
- 解耦：布局不关心页面内容，页面只负责自身区域。

```jsx
import { NavLink, Outlet } from "react-router-dom";

export function AppLayout() {
  return (
    <div>
      <nav>
        <NavLink to="/">首页</NavLink>
        <NavLink to="/users">用户</NavLink>
      </nav>
      <main>
        <Outlet />
      </main>
    </div>
  );
}
```

**速记**：共享外壳写在父路由元素里，一次定义、多页复用。



#### 索引路由与路径不匹配

**索引路由（index route）**：是 children 中把 index 设为 true 的特殊子路由，用于匹配父路径本身而不追加路径片段。**路径不匹配**：是地址与任何路由都不相符的情形，通常用通配路径兜底。

- 索引路由：写法为 index 为 true，不写 path，匹配父路径本身。
- 通配兜底：path 写为星号，匹配所有未命中的地址，渲染 404 页面。
- 顺序：匹配按最具体优先，通配路由放在最后一条。

```jsx
const router = createBrowserRouter([
  {
    path: "/",
    element: <AppLayout />,
    children: [
      { index: true, element: <HomePage /> },     // 匹配 "/"
      { path: "users", element: <UserListPage /> },
      { path: "*", element: <NotFoundPage /> },   // 兜底
    ],
  },
]);
```

**速记**：索引路由匹配父路径本身，星号路径兜住所有未命中地址。



### 参数与查询字符串

动态段与查询字符串是地址携带数据的两种方式，前者表达资源标识，后者表达可选条件。

#### 动态段与 useParams

**动态段**：是路径中以冒号开头的片段，如 users/:userId，匹配到的实际值由 useParams 读取。**useParams**：是无参数的 Hook，返回一个以动态段名为键、匹配到的路径片段为值的对象。

- 声明：在 path 中写冒号加参数名。
- 读取：useParams() 返回形如 userId 对应字符串值的对象。
- 类型：取到的值是字符串或 undefined，参与计算前要显式转换与判空。

```jsx
import { useParams } from "react-router-dom";

export function UserDetailPage() {
  const { userId } = useParams();
  if (!userId) return <p>缺少用户标识</p>;

  const numericId = Number(userId);
  return <UserProfile userId={numericId} />;
}
```

> [!NOTE]
> **提醒内容**：useParams 返回的值始终是字符串，直接做数值比较或运算会得到意外结果，必须先转换。

**速记**：动态段用冒号声明，useParams 无参返回参数名到字符串值的映射。



#### 查询字符串与 useSearchParams

**查询字符串（query string）**：是地址问号之后的键值对部分。**useSearchParams**：是无参数 Hook，返回 URLSearchParams 实例与设置函数组成的数组，用法与 useState 类似。

- 读取：searchParams.get 传入键名取得对应值，不存在时返回 null。
- 写入：setSearchParams 传入对象或 URLSearchParams，更新地址并触发重新渲染。
- 函数式：也可传入回调，基于上一份查询项计算新值。

```jsx
import { useSearchParams } from "react-router-dom";

export function UserListPage() {
  const [searchParams, setSearchParams] = useSearchParams();
  const keyword = searchParams.get("keyword") ?? "";

  return (
    <div>
      <input
        value={keyword}
        onChange={(event) => setSearchParams({ keyword: event.target.value })}
      />
      <p>当前关键词：{keyword}</p>
    </div>
  );
}
```

> 查询字符串适合表达筛选、分页、排序这类可选条件；资源标识应放进动态段，两者不要混用。

**速记**：useSearchParams 无参返回查询项读写数组，读用 get、写用 set。



#### 编程式导航与 useNavigate

**useNavigate**：是无参数 Hook，返回一个导航函数，用于在代码逻辑中跳转。返回的 navigate 签名为 navigate(to, options?)，to 是目标地址，options 可含 replace 与 state。

- to：目标路径字符串，也可传数字表示前进或后退的步数。
- replace：为 true 时替换当前历史记录，返回上一页不会回到跳转前的地址。
- state：随跳转携带的状态，可由目标路由读取。

```jsx
import { useNavigate } from "react-router-dom";

export function LoginPage() {
  const navigate = useNavigate();

  async function handleSubmit(event) {
    event.preventDefault();
    await signIn(event.target);
    navigate("/dashboard", { replace: true }); // 登录后替换历史，避免回退到登录页
  }

  return (
    <form onSubmit={handleSubmit}>
      <button type="submit">登录</button>
    </form>
  );
}
```

> 视图上可点击的跳转优先用 Link，表单提交或异步完成后的跳转再用 useNavigate。

**速记**：useNavigate 无参返回导航函数，navigate 接收目标地址与可选配置。



### 导航与守卫

导航组件负责日常跳转，守卫决定哪些地址可以进入，两者都建立在路由匹配信息之上。

#### Link 与 NavLink 的差别

**Link**：是渲染为锚点元素、点击后由路由接管跳转的组件，props 含 to 与 replace。**NavLink**：是在 Link 基础上增加激活态能力的组件，props 额外含 className 与 style 的回调形式，可依据匹配状态返回不同的类名或样式。

- 跳转：两者都不触发整页刷新。
- 激活态：NavLink 能得知当前路径是否与自身匹配，Link 不能。
- 取舍：普通跳转用 Link，导航菜单用 NavLink。

```jsx
import { Link, NavLink } from "react-router-dom";

<Link to="/help" replace>帮助</Link>
<NavLink to="/users">用户</NavLink>
```

> [!TIP]
> **建议内容**：导航菜单统一使用 NavLink，普通内容跳转使用 Link，避免为不需要激活态的链接引入样式逻辑。

**速记**：Link 只负责跳转，NavLink 额外提供当前路径的激活态。



#### NavLink 的激活态样式

**激活态样式**：是 NavLink 依据自身与当前地址是否匹配而附加的类名或内联样式。

- 回调形式：className 可写成函数，接收含 isActive 与 isPending 的对象，返回类名字符串。
- 内联样式：style 同样支持函数形式，按匹配结果返回样式对象。
- 用途：把高亮逻辑集中在导航组件，无需在外部比对当前路径。

```jsx
import { NavLink } from "react-router-dom";

<NavLink
  to="/users"
  className={({ isActive }) => (isActive ? "nav-item active" : "nav-item")}
>
  用户
</NavLink>
```

> className 与 style 的回调参数只是普通对象，不提供状态更新能力，不要按 Hook 的用法理解它。

**速记**：NavLink 的 className 与 style 支持函数形式，按 isActive 返回激活样式。



#### 重定向与路径跳转

**重定向**：是在渲染阶段把当前地址替换为另一个地址的行为，用于登录后跳首页、旧路径迁移等场景。

- 组件形式：Navigate 组件接收 to 与 replace，渲染即触发跳转。
- 加载器形式：路由的 loader 中返回 redirect 结果，在渲染前完成跳转。
- 条件限定：组件式重定向必须放在条件分支中，否则会持续跳转。

```jsx
import { Navigate } from "react-router-dom";

export function LegacyUsersPage() {
  // 渲染即重定向到新地址
  return <Navigate to="/users" replace />;
}
```

**速记**：Navigate 组件渲染即跳转，按条件放在分支里完成重定向。



#### 路由级权限判断

**路由级权限判断**：是在进入受保护路由前检查是否具备访问条件，不具备时跳转到登录页或提示无权访问。

- loader 方式：在路由的 loader 中判断登录态，未通过时返回重定向，跳转发生在渲染之前。
- 组件内方式：在页面组件中读取登录态，未通过时渲染 Navigate 完成跳转。
- 对比：loader 方式不会渲染受保护内容，更贴近访问控制；组件内方式实现简单，适合少量页面。

```jsx
import { redirect } from "react-router-dom";

function requireAuth() {
  const user = readCurrentUser();
  if (!user) return redirect("/login");
  return null;
}

const router = createBrowserRouter([
  { path: "/dashboard", element: <DashboardPage />, loader: requireAuth },
]);
```

> [!WARNING]
> **警告内容**：前端路由守卫只是界面层的跳转控制，服务端仍需对每个受保护接口逐一鉴权，不能把权限判断全部交给前端。

**速记**：loader 在渲染前判断权限，组件内则渲染 Navigate，二者都不能替代服务端鉴权。
