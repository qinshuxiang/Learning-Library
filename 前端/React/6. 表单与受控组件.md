## 表单与受控组件

表单把用户输入变成组件可以读取与校验的数据。React 提供两条路径：受控组件把输入值交给 state 管理，非受控组件把输入值留在 DOM 里按需读取。本篇讲两条路径的原理、绑定写法、校验与提交，事件的绑定与传参归第 4 篇（详见本主题第 4 篇 事件处理与合成事件）。

### 受控组件的原理

受控是 React 处理表单的默认思路：表单元素的显示值由 state 决定，用户操作通过事件回写 state。

#### 受控组件的定义

**受控组件（controlled component）**：是其显示值来自 state、用户输入通过事件处理函数回写 state 的表单元素。

- 值的来源：元素的 value 或 checked 由 state 提供，DOM 只负责显示。
- 变更的通道：用户每次输入都触发 onChange，处理函数把新值写回 state。
- 单向链路：state 到视图由 React 负责，视图到 state 由开发者负责，两侧都要写。

```jsx
function NameField() {
  const [name, setName] = useState("");
  return (
    <input value={name} onChange={(event) => setName(event.target.value)} />
  );
}
```

> 受控的关键不是用了 onChange，而是显示值必须来自 state：写了 onChange 却没写 value 仍是普通输入框。

**速记**：受控组件的值来自 state、变更走事件，两侧链路缺一不可。



#### 值与变更回调的闭环

**值与变更回调的闭环**：是 value 决定显示、onChange 决定状态，二者构成一个完整回路，缺任一侧输入框都会异常。

- 只写 value 不写 onChange：输入框只读，用户敲键盘没有反应，控制台给出警告。
- 只写 onChange 不写 value：输入框实际是非受控，state 与显示可能不同步。
- 事件对象：必须同步读取 event.target.value，异步回调中事件对象可能已被回收。

**速记**：value 与 onChange 成对出现才成立，事件值要同步读取。



#### 单一数据源

**单一数据源（single source of truth）**：是同一份输入值只保存在 state 一处，DOM 与派生显示都从 state 推导。

- 唯一存储：输入值不再同时存在于 DOM 与 state 两处，避免不一致。
- 派生显示：字数统计、按钮禁用、错误提示都由 state 计算，不额外存布尔量。
- 便于重置：把 state 置为初始值即完成重置，不需要逐个操作 DOM 节点。

```jsx
function BioField() {
  const [bio, setBio] = useState("");
  const isTooLong = bio.length > 200; // 派生值，不另存状态
  return (
    <textarea value={bio} onChange={(event) => setBio(event.target.value)} />
  );
}
```

> [!TIP]
> **建议内容**：能从已有 state 计算出的值不要另设 state，字数、选中数量、是否禁用都属于派生值。

**速记**：输入值只存 state 一处，其余显示与校验都从它派生。



### 表单元素绑定

不同表单元素的取值方式不同：文本类读 value，勾选类读 checked，列表类可能需要数组。

#### input 的文本与数值

**文本与数值输入**：是 type 为 text、password、email 等元素统一读 event.target.value，type 为 number 时同样读 value 但需要自行转成数字。

- 统一写法：value 与 onChange 由 state 提供，不因 type 不同而改。
- 数字转换：event.target.value 总是字符串，需要数字时用 Number 或 parseFloat 转换。
- 空值处理：数字输入被清空时 value 是空字符串，转数字会得到 NaN，需要单独判断。

> [!NOTE]
> **提醒内容**：数字输入清空时 event.target.value 是空字符串而不是 0，直接转换会得到 NaN 并让输入框显示空白。

**速记**：文本与数值都读 value，数值要自己转换并处理空字符串。



#### checkbox 与 radio

**checkbox 与 radio**：是勾选类元素用 checked 表示选中状态，用 event.target.checked 回写布尔值。

- 单个复选框：state 为布尔值，绑定 checked 与 event.target.checked。
- 单选按钮组：多个 radio 绑定同一个 state，选中项由 checked 是否等于本项 value 决定。
- 常见错误：给复选框绑 value 会让勾选状态永远为真，因为 value 是字符串而非布尔。

```jsx
function NotifySettings() {
  const [subscribe, setSubscribe] = useState(false);
  const [plan, setPlan] = useState("monthly");
  return (
    <form>
      <input type="checkbox" checked={subscribe}
        onChange={(event) => setSubscribe(event.target.checked)} />
      <input type="radio" value="monthly" checked={plan === "monthly"}
        onChange={(event) => setPlan(event.target.value)} />
    </form>
  );
}
```

**速记**：勾选类用 checked 与 checked 事件值，单选组由值比较决定选中。



#### textarea 与 select 的写法差异

**textarea 与 select 的受控写法差异**：是二者都用 value 绑定，但 select 的选中项由 value 属性表示，而不是在选项上写 selected。

- textarea：直接用 value 与 onChange，不再用子节点文本作为初始值。
- select：value 写在 select 上，等于某个 option 的 value 即选中该项。
- 多选 select：value 是字符串数组，配合 multiple 属性使用。
- 默认选项：受控 select 用 value 指定初始项，不需要在 option 上写 selected。

> 在 option 上写 selected 属于非受控写法，与 select 的 value 同时出现时以 value 为准。

**速记**：textarea 与 select 都用 value 绑定，select 不在 option 上写 selected。



#### 多选与数组值

**多选与数组值**：是允许多选的 select 或复选框组的 state 为数组，切换某项时增删该值。

- select multiple：event.target.selectedOptions 是所有选中项，需要映射成 value 数组。
- 复选框组：每个 checkbox 的 checked 由 state 数组是否包含本项值决定。
- 增删写法：用 includes 判断后 filter 或展开追加，不做原地修改。

```jsx
function SkillPicker() {
  const [skills, setSkills] = useState([]);
  const toggleSkill = (skill) => {
    setSkills((prev) =>
      prev.includes(skill) ? prev.filter((item) => item !== skill) : [...prev, skill]
    );
  };
  return ["js", "ts"].map((skill) => (
    <label key={skill}>
      <input type="checkbox" checked={skills.includes(skill)}
        onChange={() => toggleSkill(skill)} />
      {skill}
    </label>
  ));
}
```

> 数组型 state 的更新必须返回新数组，用修改原数组的写法不会触发重新渲染。

**速记**：多选的 state 是数组，勾选即增删，更新时必须返回新数组。



### 多字段与动态表单

字段一多，逐个 useState 会迅速膨胀，改用对象承载并把变更逻辑统一起来。

#### 用一个对象 state 承载多字段

**用对象 state 承载多字段**：是把整张表单的值放进一个对象，对象的一个键对应一个字段。

- 结构对应：state 的键与字段 name 一一对应，读值与回写路径清晰。
- 初始值集中：初始对象集中定义，重置时直接回到该对象。
- 更新方式：必须返回新对象并展开旧值，不能修改原对象。

```jsx
function SignUpForm() {
  const [formValues, setFormValues] = useState({ email: "", nickname: "" });
  const updateField = (name, value) => {
    setFormValues((prev) => ({ ...prev, [name]: value })); // 返回新对象
  };
  return (
    <input name="email" value={formValues.email}
      onChange={(event) => updateField(event.target.name, event.target.value)} />
  );
}
```

**速记**：多字段用一个对象 state，更新时展开旧对象再覆盖目标键。



#### 统一的 handleChange 写法

**统一的 handleChange**：是用一个事件处理函数处理全部字段，靠元素的 name 属性决定更新哪个键。

- 依赖 name：每个字段写 name，处理函数从 event.target 读出 name 与 value。
- 计算键名：用方括号把 name 作为动态键写入新对象。
- 勾选兼容：需要同时支持文本与复选框时，按 type 决定取 value 还是 checked。

```jsx
function ProfileForm() {
  const [formValues, setFormValues] = useState({ name: "", bio: "" });
  const handleChange = (event) => {
    const { name, value, type, checked } = event.target;
    const nextValue = type === "checkbox" ? checked : value;
    setFormValues((prev) => ({ ...prev, [name]: nextValue }));
  };
  return (
    <form>
      <input name="name" value={formValues.name} onChange={handleChange} />
      <textarea name="bio" value={formValues.bio} onChange={handleChange} />
    </form>
  );
}
```

> 依赖 name 的写法要求 name 与 state 的键严格一致，否则会静默多出一个无效字段。

**速记**：一个 handleChange 靠 name 定位字段，键名与字段名必须一致。



#### 字段的动态增删

**字段的动态增删**：是把可重复的字段组做成数组 state，用唯一 id 标识每一项，按 id 增删与更新。

- 增：用展开运算在末尾追加一个带新 id 的对象。
- 删：用 filter 按 id 过滤，删除时不要用下标。
- 改：用 map 匹配 id 后返回替换后的新对象。
- key 要求：渲染时数组元素的自有 id 正好是稳定 key。

```jsx
function ContactList() {
  const [contacts, setContacts] = useState([{ id: "c1", phone: "" }]);
  const addContact = () =>
    setContacts((prev) => [...prev, { id: crypto.randomUUID(), phone: "" }]);
  const removeContact = (id) =>
    setContacts((prev) => prev.filter((item) => item.id !== id));
  const updatePhone = (id, phone) =>
    setContacts((prev) =>
      prev.map((item) => (item.id === id ? { ...item, phone } : item))
    );
  return contacts.map((contact) => (
    <div key={contact.id}>
      <input value={contact.phone}
        onChange={(event) => updatePhone(contact.id, event.target.value)} />
      <button type="button" onClick={() => removeContact(contact.id)}>删除</button>
      <button type="button" onClick={() => addContact()}>新增</button>
    </div>
  ));
}
```

> [!WARNING]
> **警告内容**：动态字段的增删必须按 id 而非下标，按下标删除会让后面的字段内容整体前移错位。

**速记**：动态字段用带 id 的数组 state，增删改都按 id 定位。



#### 复用字段组件

**复用字段组件**：是把一组成对的 label、控件与错误提示封装成受控组件，通过 value 与 onChange 与父级通信。

- 单向契约：字段组件只负责显示与上抛变更，值仍由父级 state 持有。
- 参数设计：value、onChange、label、error 是常见的一组 props。
- 不放内部 state：字段组件内部不镜像一份值，避免两份值不同步。

```jsx
function TextField({ label, value, onChange, error }) {
  return (
    <label>
      {label}
      <input value={value} onChange={onChange} />
      {error && <span>{error}</span>}
    </label>
  );
}
```

> 值由父级持有、变更通过回调上抛，是受控组件跨层复用的唯一必要契约。

**速记**：字段组件只显示与上抛，值留在父级，用 value 与 onChange 通信。



### 非受控组件与 ref

非受控把输入值留在 DOM，由 DOM 自己管理，需要时再读取。

#### defaultValue 与 defaultChecked

**defaultValue 与 defaultChecked**：是给非受控元素设定初始值的属性，只在挂载时生效，之后不受 state 影响。

- defaultValue：对应文本类元素的初始值，挂载后用户可自由修改。
- defaultChecked：对应勾选类元素的初始勾选状态。
- 与受控互斥：同一元素同时用 value 与 defaultValue 会以 value 为准并给出警告。

> [!CAUTION]
> **注意内容**：defaultValue 只在挂载时读取，之后修改它不会改变输入框内容，需要动态控制就用受控写法。

**速记**：defaultValue 与 defaultChecked 只设置初始值，之后由 DOM 自己管理。



#### 用 ref 读取当前值

**用 ref 读取当前值**：是在提交或需要时通过 ref 拿到 DOM 节点，再从节点上读取 value。

- 创建：调用 useRef(null) 得到 ref 对象，把它绑到元素的 ref 属性上。
- 读取：在事件或效果中访问 ref.current.value 取得当前输入值。
- 时机：挂载完成前 ref.current 为 null，读取需要判空。

```jsx
function QuickSearch() {
  const keywordRef = useRef(null);
  const handleSubmit = (event) => {
    event.preventDefault();
    console.log(keywordRef.current?.value); // 提交时才读取
  };
  return (
    <form onSubmit={handleSubmit}>
      <input ref={keywordRef} defaultValue="" />
    </form>
  );
}
```

> ref 的完整签名与转发方式详见本主题第 10 篇 useRef 与 DOM 交互。

**速记**：非受控值通过 ref.current.value 读取，注意挂载前为 null。



#### 文件输入的必选非受控

**文件输入的非受控性**：是 type 为 file 的输入框只能是非受控的，其 value 由安全规则限定为只读，不能由程序写入。

- 不能受控：给文件输入绑 value 会被浏览器拒绝，React 也明确不支持。
- 读取方式：通过 ref 拿 files 列表，或在 onChange 里读 event.target.files。
- files 对象：FileList 是类数组对象，需要遍历或用扩展运算转成真数组。
- 清空方式：把 ref.current.value 置为空字符串，或切换 key 重建元素。

```jsx
function AvatarUpload() {
  const fileRef = useRef(null);
  const handleChange = (event) => {
    const [file] = event.target.files; // FileList 可解构
    console.log(file?.name);
  };
  const resetFile = () => {
    fileRef.current.value = ""; // 清空文件输入的唯一方式
  };
  return (
    <div>
      <input type="file" ref={fileRef} onChange={handleChange} />
      <button type="button" onClick={resetFile}>清除</button>
    </div>
  );
}
```

> 文件输入是受控写法唯一的例外，不能把文件内容放进 state 绑定回 value。

**速记**：文件输入只能非受控，用 ref 或 files 读取，置空 value 清空。



#### 受控与非受控的取舍

**受控与非受控的取舍**：是按是否需要实时读取、校验与联动来决定——需要这些能力用受控，只做一次性取值用非受控。

- 选受控：需要即时校验、字段联动、字数统计、按值禁用按钮、程序化重置。
- 选非受控：字段很多且极少变化、只在提交时取值、迁移遗留代码。
- 混合：同一表单里多数字段受控、少数只读字段用 ref 读取是允许的。

> 非受控不是更快的默认选择，绝大多数业务表单需要校验与联动，受控才是常规做法。

**速记**：要实时校验与联动就用受控，只在提交取值才用非受控。



### 表单校验与提交

校验回答什么时候检查与错误显示在哪，提交回答如何阻止默认跳转并处理数据。

#### 提交事件与阻止默认行为

**表单提交处理**：是监听 form 的 submit 事件并在处理函数中调用 preventDefault，阻止浏览器默认的整页提交与跳转。

- 绑定位置：submit 事件绑在 form 元素上，不是绑在提交按钮上。
- 阻止默认：处理函数第一行调用 event.preventDefault()。
- 按钮类型：表单内的按钮要写 type，默认的 submit 会在点击时触发提交。

```jsx
function LoginForm() {
  const [email, setEmail] = useState("");
  const handleSubmit = (event) => {
    event.preventDefault(); // 阻止整页刷新
    console.log("提交邮箱", email);
  };
  return (
    <form onSubmit={handleSubmit}>
      <input value={email} onChange={(event) => setEmail(event.target.value)} />
      <button type="submit">登录</button>
    </form>
  );
}
```

**速记**：submit 绑在 form 上，第一行 preventDefault，按钮要写 type。



#### 提交前校验与错误提示位置

**提交前校验**：是在提交处理函数内先检查全部字段，发现错误则中止提交并把错误写入 state。

- 校验时机：提交时至少校验一次，全部通过才发送请求。
- 错误状态：把错误放进一个以字段名为键的对象，便于与字段一一对应。
- 显示位置：错误提示紧邻对应字段渲染，而不是统一堆在表单顶部。

```jsx
function validateEmail(email) {
  return /^[^@\s]+@[^@\s]+\.[^@\s]+$/.test(email) ? "" : "邮箱格式不正确";
}

function EmailForm() {
  const [email, setEmail] = useState("");
  const [errors, setErrors] = useState({});
  const handleSubmit = (event) => {
    event.preventDefault();
    const emailError = validateEmail(email);
    if (emailError) {
      setErrors({ email: emailError });
      return; // 校验不通过，中止提交
    }
    console.log("提交", email);
  };
  return (
    <form onSubmit={handleSubmit}>
      <input value={email} onChange={(event) => setEmail(event.target.value)} />
      {errors.email && <p>{errors.email}</p>}
    </form>
  );
}
```

> 错误对象以字段名为键，字段增删时校验与显示两处同步修改，不会把错误挂到错误的字段上。

**速记**：提交时先校验，错误按字段名存入对象并紧邻字段显示。



#### 即时校验与失焦校验

**即时校验与失焦校验**：是两种不同于只在提交时校验的时机——即时校验在每次输入后校验，失焦校验在字段失去焦点时校验。

- 即时校验：值一变就校验，反馈最快，但输入未完成时容易出现刺眼报错。
- 失焦校验：在 onBlur 时校验，用户在输入过程中不被干扰，适合格式类字段。
- 混合策略：首次失焦后开启即时校验，兼顾不打扰与及时纠错。

```jsx
function EmailField() {
  const [email, setEmail] = useState("");
  const [touched, setTouched] = useState(false);
  const emailError = validateEmail(email);
  return (
    <div>
      <input value={email} onChange={(event) => setEmail(event.target.value)}
        onBlur={() => setTouched(true)} />
      {touched && emailError && <p>{emailError}</p>}
    </div>
  );
}
```

> 用户在首次输入途中就报错体验较差，用失焦后才显示错误可以在不牺牲校验的前提下减少打扰。

**速记**：即时校验反馈快但易打扰，失焦校验更温和，二者可组合。



#### 提交后重置与状态清理

**提交后重置**：是把表单 state 恢复为初始对象并清空错误与提交状态，使表单回到可再次填写的样子。

- 重置方式：受控表单把 state 设回初始对象即可，不需要操作 DOM。
- 错误清理：重置时同时清空错误对象，避免旧错误留在界面上。
- 提交状态：请求进行中禁用提交按钮并显示加载态，成功后关闭或清空。

```jsx
function FeedbackForm() {
  const initialValues = { email: "" };
  const [formValues, setFormValues] = useState(initialValues);
  const [errors, setErrors] = useState({});
  const [isSubmitting, setIsSubmitting] = useState(false);
  const handleSubmit = async (event) => {
    event.preventDefault();
    setIsSubmitting(true);
    await submitFeedback(formValues); // 请求发送
    setFormValues(initialValues); // 回到初始值
    setErrors({}); // 清空错误
    setIsSubmitting(false);
  };
  return (
    <form onSubmit={handleSubmit}>
      <input value={formValues.email}
        onChange={(event) => setFormValues({ email: event.target.value })} />
      <button type="submit" disabled={isSubmitting}>提交</button>
    </form>
  );
}
```

> [!IMPORTANT]
> **重要内容**：重置必须同时清空错误与提交状态，只重置字段值会留下过期错误提示。

**速记**：受控表单重置即把 state 设回初始对象，并一并清空错误与提交状态。
