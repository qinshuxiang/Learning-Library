## 组件基础与 props

### 函数组件是什么

函数组件是 React 应用最小的复用单元，本节确认它的定义、命名规则与调用方式，为随后的 props 与组合打底。

#### 函数组件的定义与返回值

**函数组件（function component）**：是接收 props 作为第一个参数、返回 JSX 元素的普通函数，在 React 19 中是定义组件的唯一推荐方式。

- 参数：第一个参数是 props 对象，不需要接收数据时可以省略。
- 返回值：返回 JSX 元素（element），描述该位置应渲染成什么界面。
- 调用方：组件由 React 在渲染流程中调用，业务代码只书写 JSX 标签。

```jsx
function Greeting() {
  return <h1>Hello, React!</h1>;
}

// 使用：<Greeting />
// React 在渲染时调用 Greeting()，把返回值交给协调流程
```

**速记**：函数组件是返回 JSX 元素的函数，由 React 调用而非业务代码调用。



#### 组件名必须大驼峰的原因

**大驼峰命名（PascalCase）**：是首字母大写的命名形式，React 依靠首字母的大小写区分 JSX 标签是组件还是宿主元素。

- 大写开头：被解析为组件引用，指向当前作用域里的函数或变量。
- 小写开头：被解析为宿主元素（host element），如 div、span，原样交给 DOM。
- 后果：组件名若小写，React 会按同名 DOM 元素处理，函数不会被调用。

```jsx
function UserCard() {
  return <div>Ada Lovelace</div>;
}

const card = <UserCard />;    // 正确：识别为组件
// const bad = <userCard />;  // 报错：userCard 被当作宿主元素，函数未被调用
```

> 组件名与组件文件名约定为大驼峰；普通工具函数仍用小驼峰，两者的识别规则不同。

**速记**：首字母大写是组件在 JSX 中的识别标记，小写会被当成宿主元素。



#### 组件与普通函数的差别

**组件与普通函数的差别**：在于调用者是框架而非业务代码，并且组件能够持有状态与副作用。

- 调用者：普通函数由代码显式调用，组件由 React 在渲染时调用。
- 返回值：普通函数返回任意值，组件返回可参与协调（reconciliation）的元素。
- 附加能力：组件内可以使用 Hook 保存 state、注册副作用，普通函数不适用 Hook 规则。
- 复用方式：普通函数靠调用复用，组件靠 JSX 标签复用并进入渲染树。

```jsx
function formatUserName(firstName, lastName) {
  return firstName + " " + lastName;
}

function UserCard({ firstName, lastName }) {
  return <p>{formatUserName(firstName, lastName)}</p>;
}

// 普通函数可直接调用：formatUserName("Ada", "Lovelace") → "Ada Lovelace"
// 组件只能写成标签：<UserCard firstName="Ada" lastName="Lovelace" />
```

> Hook 只能在组件或自定义 Hook 中调用，这条规则来自 React 的运行机制，详见本主题第 16 篇 Hook 规则与运行机制。

**速记**：组件由 React 调用并可使用 Hook，普通函数只做计算、由代码调用。



#### 渲染一次即一次函数调用

**渲染一次即一次函数调用**：指 React 每次需要生成或更新界面时都会重新执行组件函数，函数体内的语句随之重跑。

- 局部变量重建：函数体内声明的普通变量在每次渲染中重新创建。
- 不跨渲染保存：需要跨渲染保留的值必须放进 state 或 ref，普通变量会重置。
- 输出由输入决定：同一份 props 与 state 对应同一份界面描述，这是纯函数要求的前提。

```jsx
function BrokenCounter() {
  let count = 0;           // 每次渲染都重新初始化为 0
  count += 1;
  return <p>{count}</p>;   // 永远渲染 1
}

// 需要跨渲染保留计数时必须使用 state，详见本主题第 7 篇 State 与 useState
```

**速记**：每次渲染都会重新执行组件函数，局部变量不跨渲染保留。



### props 的传递与只读性

props 是父子组件之间的数据通道，本节说明它的形态、传递写法以及只读约束。

#### props 是参数对象

**props**：是父组件传给子组件的数据集合，以单个对象作为函数组件的第一个参数传入，可理解为「属性参数」。

- 形态：一个普通对象，键来自父组件在 JSX 标签上书写的属性名。
- 来源：由父组件提供，子组件只负责读取，不负责创建。
- 完整签名：function UserCard(props) { return ... }，props 是对象，返回值是 JSX 元素。
- 空组件：不接收数据时参数可省略，函数签名写作 function Badge() { ... }。

```jsx
function UserCard(props) {
  return <p>{props.name} 今年 {props.age} 岁</p>;
}

// 父组件传入 { name: "Ada Lovelace", age: 36 }
// 输出：Ada Lovelace 今年 36 岁
```

**速记**：props 是子组件函数的第一个参数，形态为对象。



#### 父传子的写法与解构

**父传子**：是在父组件的 JSX 中把值写成子组件的属性，子组件通过参数接收的过程。

- 静态值：写成字符串字面量，如 name="Ada"。
- 动态值：用花括号包裹任意表达式，如 age={user.age}、items={todos}。
- 解构：在参数位置写 { name, age }，等价于在函数体内逐次读取 props.name。
- 展开：用展开运算符把整个对象铺成属性，见本篇默认值与类型约定一节。

```jsx
function UserCard({ name, age }) {
  return <p>{name} 今年 {age} 岁</p>;
}

function ProfilePanel() {
  const user = { name: "Ada Lovelace", age: 36 };
  return <UserCard name={user.name} age={user.age} />;
}
```

**速记**：父传子靠 JSX 属性，子组件用解构或逐属性读取。



#### props 只读的原因

**props 只读**：指子组件不得改动接收到的 props，因为 props 承载的是父组件持有的数据。

- 单向数据流：数据从父流向子；子组件要改数据只能通知父组件改（状态提升详见本主题第 8 篇 状态提升与单向数据流）。
- 引用共享：同一份数据可能同时传给多个子组件，任一处改动会波及其他位置。
- 可预测性：只读保证界面完全由数据推断，调试时可以从数据反推界面。
- 排查成本：一旦 props 被就地改写，问题会出现在距离改动点很远的组件里。

```jsx
function PriceTag(props) {
  // props.amount = props.amount * 2;   // 错误：改动了父组件持有的数据
  return <span>{props.amount}</span>;
}
```

> 只读是约定而非语言限制：JavaScript 不会阻止给对象属性赋值，React 依赖开发者遵守这条约定。

**速记**：props 只读，因为它承载父组件的数据，改动会破坏单向数据流。



#### 不要直接修改 props

**不要直接修改 props**：指对 props 本身及其嵌套的对象、数组一律不做赋值与原地变更，需要变换时先复制。

- 直接赋值：给 props 的属性赋值会污染父组件持有的同一个对象。
- 原地变更：对 props 里的数组调用 push、sort、reverse 同样会改到原数组。
- 复制后再改：用展开运算符、filter、map 生成新对象或新数组再使用。
- 深层结构：嵌套较深时逐层复制，或借助不可变更新写法（详见本主题第 7 篇 State 与 useState）。

```jsx
function TodoList(props) {
  // props.items.push("新任务");        // 错误：改动了父组件的数组
  const visibleItems = props.items.filter((item) => !item.done);
  return (
    <ul>
      {visibleItems.map((item) => <li key={item.id}>{item.text}</li>)}
    </ul>
  );
}
```

> [!WARNING]
> **警告内容**：直接修改 props 中的对象或数组，会让父组件与子组件看到同一份被改动的数据，界面更新时机变得不可预测。

**速记**：需要变换 props 时先复制再改，绝不原地修改。



### 组件的拆分与组合

界面由组件拼装而成，本节给出拆分的判断标准、职责划分与两种常见组合方式。

#### 拆分的判断标准

**拆分标准**：是一条界面边界是否值得独立成组件的判断依据，通常看重复、复杂度与独立变化三方面。

- 重复出现：同一段 JSX 在多个位置出现，抽取成组件并参数化。
- 复杂度：单个组件文件过长、JSX 层级过深时，按视觉区块切开。
- 独立变化：某块内容的数据来源或更新频率与其他部分不同，拆开可缩小重新渲染范围。
- 过度拆分：为拆而拆会增加 props 传递层级，反而降低可读性。

```jsx
function UserCard({ name, avatarUrl }) {
  return (
    <div>
      <img src={avatarUrl} alt={name} />
      <p>{name}</p>
    </div>
  );
}
```

**速记**：重复、复杂、独立变化三处出现时才拆，避免为拆而拆。



#### 按职责与复用拆分

**按职责拆分**：是把只负责渲染的展示组件与负责组织数据的容器组件分开，前者可被多处复用。

- 展示组件：只接收 props 并渲染，不关心数据从哪来、如何取。
- 容器组件：持有数组与取数、过滤等编排逻辑，把数据分发给展示组件。
- 命名对应：展示组件名描述界面，如 UserCard、TodoItem；容器组件名描述数据范围，如 UserList、TeamPanel。
- 复用收益：同一个展示组件换一组 props 就能渲染出不同内容。

```jsx
function UserCard({ name, role }) {
  return <p>{name} · {role}</p>;
}

function TeamPanel({ members }) {
  return (
    <section>
      {members.map((member) => (
        <UserCard key={member.id} name={member.name} role={member.role} />
      ))}
    </section>
  );
}
```

**速记**：展示组件只渲染，容器组件管数据，复用价值集中在展示组件。



#### children 插槽式组合

**children 插槽**：是 props 中名为 children 的特殊属性，值为标签开始与结束标记之间的内容，用于把父组件的界面片段放进子组件的固定位置。

- 写法：子组件在需要的位置输出 {children} 或 {props.children}。
- 传入：父组件把内容写在子组件标签的开始与结束标记之间。
- 组合优于继承：用 children 组合比继承更灵活，完整模式详见本主题第 13 篇 组件组合：children、render props 与 HOC。
- 适用：布局容器、卡片、弹窗等外壳固定、内容多变的组件。

```jsx
function Card({ title, children }) {
  return (
    <div className="card">
      <h3>{title}</h3>
      {children}
    </div>
  );
}

function Profile() {
  return (
    <Card title="个人资料">
      <p>Ada Lovelace</p>
    </Card>
  );
}
```

**速记**：children 是标签之间的内容，用于插槽式组合，完整模式见本主题第 13 篇。



#### 列表项组件与容器组件

**列表项组件**：是渲染单个条目的组件；**容器组件**：是遍历数据并组织多个列表项的组件。二者一起构成列表的拆分方式。

- 列表项：只认单条数据的字段，如 TodoItem 接收一个 todo 对象。
- 容器：持有数组与遍历逻辑，负责给每个列表项加上稳定的 key。
- 职责边界：列表项不做过滤与排序，容器不做视觉样式。
- key 规则：由容器在遍历时提供，取值方式详见本主题第 5 篇 条件渲染与列表渲染。

```jsx
function TodoItem({ todo }) {
  return <li>{todo.done ? "已完成" : "待办"}：{todo.text}</li>;
}

function TodoList({ todos }) {
  return (
    <ul>
      {todos.map((todo) => (
        <TodoItem key={todo.id} todo={todo} />
      ))}
    </ul>
  );
}
```

**速记**：列表项管单条渲染，容器管遍历与 key，两者职责不交叉。



### 默认值与类型约定

组件需要在不传属性时也正确工作，本节说明默认值、展开传递与 props 的类型约定。

#### defaultProps 与默认参数

**默认值**：是属性未传入时组件采用的兜底取值，函数组件通过参数默认值实现。

- 写法：在解构参数处写 { size = "medium" }，属性没传时取该值。
- 生效条件：仅当属性为 undefined 时生效，传 null 不会触发默认值。
- defaultProps：是 React 早期用于设置默认 props 的静态属性，React 19 已移除对函数组件的支持，新代码统一用参数默认值。
- 多属性：每个属性各自写默认值，互不影响。

```jsx
function Button({ label = "提交", variant = "primary" }) {
  return <button className={variant}>{label}</button>;
}

// <Button />                → 提交
// <Button label="保存" />   → 保存
```

> [!NOTE]
> **提醒内容**：参数默认值只在属性值为 undefined 时生效；父组件显式传入 null 时，子组件拿到的是 null，不会回退到默认值。

**速记**：函数组件用参数默认值兜底，defaultProps 已从函数组件中移除。



#### props 的对象形态与展开传递

**展开传递**：是用展开运算符把对象铺开成多个 JSX 属性，或用剩余运算符把多余属性收集成一个对象。

- 展开传入：写 {...user} 等价于逐个书写 name={user.name}、age={user.age}。
- 剩余收集：子组件用 { id, ...rest } 收集未显式列出的属性，便于整体透传。
- 适用场景：包装原生元素、向下透传配置、构造底层通用组件。
- 风险：展开会连不相关的字段一起传下去，可能覆盖目标组件的同名属性。

```jsx
function Avatar({ src, alt, ...rest }) {
  return <img src={src} alt={alt} {...rest} />;
}

const user = { name: "Ada", avatarUrl: "/ada.png" };

function ProfileCard() {
  return <Avatar src={user.avatarUrl} alt={user.name} width={64} />;
}
// width 经 ...rest 透传到 img 上
```

**速记**：展开运算符把对象铺成属性，剩余运算符把多余属性收进 rest。



#### 用类型系统描述 props

**用类型系统描述 props**：是通过类型声明为 props 建立契约，让编辑器与编译器校验属性名与值类型。

- 位置：在参数解构处直接标注对象类型，或先声明 interface 再引用。
- 收益：漏传必填属性、字段拼写错误、类型不匹配都会在编译期报错。
- 可选属性：用问号标记，表示该属性可以缺省或为 undefined。
- 完整语法：类型与接口的完整写法归 前端/TypeScript 主题，本篇只给最小示例。

```jsx
interface UserCardProps {
  name: string;
  age?: number;
}

function UserCard({ name, age }: UserCardProps) {
  return <p>{name}{age ? " · " + age + " 岁" : ""}</p>;
}
```

> 类型只做开发期的结构校验，不校验运行时传入的真实数据，外部数据仍需另行校验。

**速记**：用 interface 描述 props 的形状，属性错误在编译期即可发现。



#### PropTypes 的历史与现状

**PropTypes**：是 React 早期提供的运行时 props 校验工具，通过给组件挂载 propTypes 静态属性声明每个字段的类型。

- 写法：UserCard.propTypes = { name: PropTypes.string.isRequired }。
- 时机：属性传入后、渲染前检查一次，只在控制台打印警告，不中断执行。
- 现状：由独立的 prop-types 包维护，新项目优先使用 TypeScript 类型，运行时校验只在必要时保留。
- 局限：运行时才生效，无法提供编辑器补全与提前报错。

```jsx
import PropTypes from "prop-types";

function PriceTag({ amount, currency }) {
  return <span>{amount} {currency}</span>;
}

PriceTag.propTypes = {
  amount: PropTypes.number.isRequired,
  currency: PropTypes.string
};
```

**速记**：PropTypes 是运行时校验手段，新项目优先用类型系统替代。



### 组件的纯函数要求

React 依赖组件的确定性来推断界面，本节说明纯函数的定义以及渲染期的行为约束。

#### 纯函数的定义

**纯函数（pure function）**：是只依赖入参、不修改外部状态、相同输入必得相同输出的函数。

- 只读入参：不修改参数本身，也不修改参数引用的对象。
- 无副作用：不写存储、不发请求、不改全局变量、不操作 DOM。
- 组件的要求：React 要求组件在渲染阶段表现为纯函数，界面才是数据的确定函数。
- 副作用位置：需要副作用时放进事件处理函数或 useEffect（详见本主题第 9 篇 useEffect 与副作用）。

```jsx
function double(value) {
  return value * 2;      // 只依赖入参，无副作用
}

console.log(double(3));  // 6
```

**速记**：纯函数只依赖入参、无副作用、相同输入得到相同输出。



#### 相同输入相同输出

**相同输入相同输出**：指给定同一份 props 与 state 时，组件必须渲染出同一份界面描述。

- 可预测：相同数据得到相同界面，便于测试与复现问题。
- 禁止随机：渲染期使用 Math.random、Date.now 会让输出随调用变化。
- 固定来源：随机数与时间应放进 state 初始化或缓存，而不是每次渲染重新计算。
- 外部变量：读取渲染期会变化的外部变量同样会破坏确定性。

```jsx
function RandomBadge() {
  const [id] = useState(() => Math.random());   // 只初始化一次，渲染结果稳定
  return <span>{id}</span>;
}
```

> [!CAUTION]
> **注意内容**：在渲染期直接调用 Math.random 或 Date.now，会让界面在每次重新渲染时变化，导致相同数据渲染出不同结果。

**速记**：相同 props 与 state 必须得到相同界面，随机与时间来源要固定。



#### 渲染期不得产生副作用

**渲染期副作用**：指在组件函数体内修改外部状态、发起请求、操作 DOM 等行为，这些行为必须移到事件处理函数或 useEffect 中。

- 禁止项：修改外部变量、写 localStorage、发起网络请求、直接操作 DOM。
- 正确位置：用户交互触发的逻辑放事件处理函数，随渲染发生的放 useEffect。
- 根本原因：React 可能重复执行或中断渲染，渲染期副作用会被执行多次或被丢弃。
- 表现：重复请求、计数翻倍、状态错乱通常都源于渲染期副作用。

```jsx
function SearchBox({ keyword, onKeywordChange }) {
  // localStorage.setItem("keyword", keyword);   // 错误：渲染期写存储
  useEffect(() => {
    localStorage.setItem("keyword", keyword);     // 正确：放进 useEffect
  }, [keyword]);

  return <input value={keyword} onChange={onKeywordChange} />;
}
```

**速记**：渲染期只做计算，请求、存储、DOM 操作放到事件处理函数或 useEffect。



#### 严格模式下双调用暴露不纯写法

**严格模式双调用**：指开发环境下 React 的严格模式会故意把组件函数执行两次，用来暴露不纯的渲染代码。

- 机制：开发期重复调用一次组件函数并比较结果，意在提示渲染期副作用。
- 表现：渲染期写日志、累加外部计数、修改外部对象的代码会看到翻倍或错乱的结果。
- 生效范围：只在开发环境生效，生产构建不会双调用。
- 机制细节：双调用的实现原理详见本主题第 16 篇 Hook 规则与运行机制。

```jsx
let renderCount = 0;

function Badge({ text }) {
  renderCount += 1;          // 严格模式下会被执行两次
  return <span>{text}（{renderCount}）</span>;
}
```

> [!IMPORTANT]
> **重要内容**：严格模式的双调用是开发期的检查手段，它不是在制造缺陷，而是把渲染期副作用导致的错误提前暴露出来。

**速记**：严格模式在开发期双调用组件函数，用来暴露渲染期的不纯写法。
