## 参考资料与延伸阅读

### 官方文档

React 的官方资料集中在少数几个站点，按先建立全貌、再逐项查证的顺序使用，即可覆盖日常开发中的绝大多数问题。以下条目按使用频率排列。

#### React 官方文档

**React 官方文档**：是 React 团队维护的第一手资料，站点分为学习板块与 API 参考板块，前者回答怎么做，后者回答签名是什么。

- 学习板块按由浅入深的章节组织，从描述界面到处理交互与状态，最后讲特殊情况，与本系列前十九篇的推进顺序大致对应，适合当线性教材通读。
- API 参考板块逐个列出组件、Hook 与接口的签名、参数、返回值与使用限制，写法存疑时以该板块为准。
- 站点内搜索与侧边导航可直接定位到具体条目，比在搜索引擎结果中逐条筛选可靠。
- 页面内的示例可即时编辑运行，改动一处即可观察结果，适合验证边界细节。

**速记**：学习路线看学习板块，签名与限制查 API 参考板块，两者是同一站点的两个部分。



#### React 中文文档的使用边界

**React 中文文档**：是官方站点提供的简体中文版本，与英文版同源、术语与示例逐句对应，适合以中文快速建立整体认知。

- 中文版覆盖主干章节，阅读时没有语言转换成本，适合首轮通读与检索。
- 译文更新通常滞后于英文原文，新发布的 API 页面或新特性说明可能暂时缺译。
- 涉及版本行为、破坏性变更与边界结论时，回到英文原文页面核对更稳妥。
- 中文版作为通读入口，不作为唯一依据，与英文版对照使用。

**速记**：中文版用于通读，时效与边界的结论回英文原文确认。



#### React Router 官方文档

**React Router 官方文档**：是官方客户端路由方案的文档，覆盖声明式路由与数据路由两类用法，回答路由如何配置、数据如何加载、导航如何拦截。

- 讲清嵌套路由与布局路由的组织方式，与本系列第 20 篇的对应章节配合阅读。
- 数据路由部分说明 loader 与 action 的职责：前者在渲染前取数，后者处理提交，两者都在路由层集中管理，组件只负责消费结果。
- 导航拦截与重定向的写法随版本演进而有调整，落地配置前先确认当前稳定写法。

**速记**：路由的权威依据是官方路由文档，配置前先核对当前稳定写法。



#### React DevTools 与调试相关文档

**React 官方调试文档**：是 React 文档中讲解组件检查与性能分析的章节，配合浏览器扩展使用，回答组件树长什么样、一次交互触发了哪些重新渲染。

- 官方文档的调试章节讲清 DevTools 面板各栏含义与使用入口，是排查渲染问题的起点。
- 扩展自身的说明页面给出安装方式与各面板的操作细节，遇到面板功能更新时以它为准。
- 断点、调用栈与网络面板属于浏览器开发者工具的通用能力，不在 React 文档的范围内，查 MDN 更合适。

**速记**：先读官方调试章节，再进 DevTools 面板核对每一栏的含义。



#### 版本发布说明与升级指引

**版本发布说明**：是 React 官方博客按版本发布的新特性、行为变更与升级步骤说明，是判断某个写法在目标版本能否使用的第一手依据。

- 发布文逐条列出新增能力、行为调整与需要注意的不兼容点，按时间倒序排列。
- 升级指引把破坏性变更与迁移步骤集中成清单，并说明自动迁移工具的使用方式与覆盖范围。
- 升级前按清单逐条核对，避免把旧写法直接带进新版本；跨越多个大版本时逐版核对更稳。

> [!NOTE]
> **提醒内容**：官方文档与发布说明持续更新，页面标注的适用版本决定该写法能否在当前项目使用；脱离版本读文档，容易把实验阶段的写法当成稳定接口。

**速记**：升级先读发布说明与升级指引，逐条核对后再动代码。



### 规范与提案

React 的行为归根到底由语言规范与 Web 平台规范决定，本节列出理解这些底层依据时应查证的资源，用于解释框架为什么这样表现。

#### JSX 的语法基础

**JSX**：是 JavaScript 的语法扩展，允许在代码中书写类似标签的表达式，最终由编译器转换为普通的函数调用，本身不是浏览器能识别的语法。

- JSX 的语法与转换规则在 React 官方文档中有专章说明，是本系列第 2 篇的原始依据。
- 具体转换由编译器实现，Babel 与 TypeScript 的文档给出各自的转换行为与可配置项。
- 遇到编译产物与预期不符时，查对应编译器的实现说明，而不是 React 文档。

**速记**：JSX 是语法扩展，转换规则查 React 文档，转换行为查编译器文档。



#### TC39 提案与相关语言特性

**TC39 提案**：是 JavaScript 语言演进的标准流程，提案按 Stage 0 到 Stage 4 分阶段推进，进入最终阶段后随规范定稿，再由运行环境逐步实现。

- TC39 官网与提案仓库按阶段跟踪每一项语法的进展，可据此判断某语法是否已经可用。
- 可选链、空值合并、对象分组等特性先在提案中定义，再逐步进入运行环境，React 代码能用到的时间取决于目标环境。
- 新语法能否写进项目，受目标运行环境与编译目标共同约束，写之前先确认目标环境是否支持。

**速记**：新语法是否可查 TC39 的阶段，能否落地看目标运行环境。



#### 前端可访问性规范与 React 的关系

**WCAG**：是由 W3C 发布的 Web 内容可访问性指南，按 A、AA、AAA 三级给出可检验的成功标准，是 React 应用可访问性的判定依据。

- React 官方文档设有可访问性专章，讲语义化标签、焦点管理与 ARIA 属性的用法，是本主题相关结论的出处。
- 原生标签能满足的语义优先用原生标签，语义不足时才补 ARIA，自定义组件需要自行补齐键盘交互。
- 审计工具只能发现部分问题，最终判定仍以 WCAG 的条目为准，工具结果作为线索而非结论。

**速记**：可访问性的判定依据是 WCAG，React 侧写法查官方可访问性专章。



#### Web 平台能力

**Web 平台能力**：指 DOM、事件模型与 Web Components 等浏览器原生接口，React 建立在其之上，理解原生行为有助于判断框架行为。

- MDN 是查询 DOM 接口、事件模型与浏览器 API 的权威参考，属性、方法与兼容性说明最全。
- 合成事件建立在原生事件流之上，理解捕获与冒泡的执行次序，有助于判断事件处理函数的调用顺序。
- Web Components 与 React 的互操作有既定边界，跨技术栈集成前先查官方说明，避免按经验推断。

**速记**：框架行为的下层是 Web 平台，查接口与事件模型用 MDN。



#### 浏览器兼容与特性查询资源

**浏览器兼容性查询**：是判断某项特性在目标浏览器与版本上是否可用的资料，决定能否直接使用而不加降级方案。

- 兼容性汇总站点给出特性在各浏览器与版本上的支持矩阵，按目标用户范围判断即可得出结论。
- MDN 每个 API 页面的底部附有兼容性表，与接口说明同页，查一处即可。
- 新特性上线前先确认目标浏览器范围，必要时交由构建工具做降级处理。

> 兼容性判断依据的是目标用户实际使用的浏览器范围，而不是最新浏览器是否支持；先把范围定下来，再决定用不用新特性。

**速记**：能不能用某特性，看目标浏览器范围与兼容性表的交集。



### 经典文章与书籍

本节列出理解 React 设计动机与工程实践的延伸读物，用于在会用之后回答为什么这样设计，以及遇到取舍时该参考什么。

#### React 官方博客中的设计决策类文章

**React 官方博客的设计决策类文章**：是核心团队解释某个特性为何这样设计的公开说明，回答的是动机与取舍，而不是用法。

- 这类文章讲清特性的设计目标、被否决的替代方案与适用边界，读后对接口的容忍度更高。
- 涉及并发渲染、服务端组件等方向时，先读设计文再读 API 文档，理解成本更低。
- 博客内容按发布时间排列，读旧文时注意其结论是否已被后续文章更新。

**速记**：设计文回答为什么，API 文档回答怎么用，两者配合读。



#### 关于声明式与组件化的经典论述

**声明式与组件化的经典论述**：是围绕用描述状态代替操作步骤、用组件组合代替继承展开的公开讲解，是 React 心智模型的基础读物。

- React 官方文档中的思维章节讲组件拆分与自上而下的构建思路，与本系列第 1 篇对应。
- 声明式与命令式的对比论述解释为何不直接操作 DOM，而是描述界面应有的样子，由框架负责同步。
- 这类论述适合在初学阶段读一遍，在遇到状态组织与组件拆分问题时再回来读一遍。

**速记**：声明式关注结果状态，组件化关注拆分与组合，是 React 的两块基石。



#### Fiber 与协调机制的公开解读文章

**Fiber 与协调机制的解读文章**：是讲解 React 渲染如何被拆分为可中断工作单元的公开材料，回答重新渲染为什么可以被打断与恢复。

- React 官方博客中关于 Fiber 架构的介绍文章是这一方向的源头材料，讲清双缓存与工作循环。
- 官方文档对渲染阶段与提交阶段的划分说明，可与本系列第 17 篇对照阅读。
- 社区的源码解读文章质量参差，结论应以官方材料与源码为准，读到结论后回源码验证。

**速记**：Fiber 把渲染拆成可中断单元，先读官方架构文章再看源码。



#### 状态管理与数据流的讨论文章

**状态管理与数据流的讨论文章**：是讨论状态放在哪里、如何在组件间流动的公开材料，回答局部状态何时该提升为全局状态。

- React 官方文档讲状态放置位置与单向数据流，是本系列第 8 篇的原始依据。
- Redux Toolkit 与 Zustand 的官方文档分别解释各自的设计取舍，选型时可对照阅读。
- 服务端数据的缓存与失效属于另一类问题，先看本系列第 9 篇的数据请求写法，再决定是否引入专门库。

**速记**：状态讨论先分清客户端状态与服务端状态，再谈放在哪一层。



#### 可查阅的书籍方向

**延伸书籍**：指在接口用法之外补充架构、语言与可访问性知识的读物方向，用于补足框架文档不覆盖的部分。

- 前端架构方向：讲大型应用的模块划分、状态组织与构建策略，与架构主题互补，适合有项目经验后阅读。
- 语言精进方向：讲 JavaScript 的运行机制与异步模型，是本系列多处原理描述的底层依据，可对照 前端/JavaScript 主题阅读。
- 可访问性方向：讲 WCAG 落地与辅助技术适配，与可访问性规范条目配合使用。
- 书籍更新慢于框架，具体接口用法仍以官方文档为准，书籍的价值在体系而不在时效。

> 书籍用来建立体系与判断力，官方文档用来确认当下可用的写法；合理的顺序是先读一本体系书，再把文档当手册长期查阅。

**速记**：体系靠书、时效靠文档，两者分工不同，不可互相替代。



### 工具与在线调试

本节列出日常开发与排查问题时会用到的工具入口，具体配置分散在相邻主题中，此处只给查阅方向与适用场景。

#### Vite 等脚手架与构建工具

**Vite**：是当下主流的构建工具，基于原生 ES 模块提供服务，开发期按需编译、生产期打包输出静态资源。

- Vite 官方文档给出创建 React 项目的模板命令与 React 插件的启用方式，是新建项目的入口。
- 脚手架生成的项目结构即官方推荐的起点，新项目不必手工搭建骨架。
- 路径别名、环境变量与构建配置的整体写法详见 前端/构建工具 主题，本篇不展开。

**速记**：运行与构建查 Vite 文档，工程配置深入看 前端/构建工具 主题。



#### React DevTools Profiler 的用法入口

**Profiler**：是 React DevTools 中的性能分析面板，录制一次交互后给出各次提交的耗时与发生重新渲染的组件，用于定位性能问题。

- React 官方性能章节说明何时该录制、如何读火焰图与组件排名视图。
- 分析结果指向的是重新渲染成本高的组件，判断具体原因仍需结合本系列第 11 篇与第 18 篇。
- 生产环境分析需使用对应的生产构建配置，开发模式下的耗时不能直接当作线上结论。

**速记**：先用 Profiler 定位到组件，再回到代码判断重新渲染的原因。



#### 在线 Playground 与代码沙盒

**在线 Playground**：是无需本地环境即可运行 React 代码的网页工具，用于验证语法、复现问题与分享最小示例。

- React 官方文档的示例本身即可编辑运行，验证某个接口的行为最快。
- 代码沙盒类站点可创建完整项目，支持多文件与依赖安装，适合复现依赖多个包才能出现的问题。
- 提问或提交问题时附上最小可复现链接，比粘贴大段代码更有效。

> 复现问题时先把无关代码删到最少，能触发问题的最小示例往往已经暴露了原因所在。

**速记**：验证语法与接口用官方示例，复现依赖问题用代码沙盒。



#### 测试相关工具

**React 测试工具**：指官方测试章节与 React Testing Library 等以用户行为为中心的测试库，回答如何断言组件的渲染结果与交互结果。

- React 官方文档的测试章节给出推荐做法与查询方式的选择原则，与本系列第 22 篇对应。
- React Testing Library 的文档讲清各类查询方法的适用场景，以及何时该改用用户事件模拟。
- 测试运行器、断言库与覆盖率配置属于测试体系，详见 前端/测试 主题。

**速记**：组件测试的写法看官方章节与 Testing Library，体系配置看 前端/测试 主题。



#### 类型检查与 ESLint 相关插件

**类型检查与静态检查工具**：是给 React 代码提供类型校验与规则校验的工具，回答 props 类型是否匹配、Hook 调用是否违反规则。

- TypeScript 官方手册与配置参考是类型设置的依据，语言基础详见 前端/TypeScript 主题。
- typescript-eslint 提供让 ESLint 理解 TypeScript 语法的解析器与规则集，是类型感知规则的载体。
- Hook 规则相关插件能在编码阶段拦下违反 Hook 规则的写法，是运行期报错之前的提前防线，与本系列第 16 篇对应。

**速记**：类型问题查 TypeScript 文档，Hook 规则问题交给 ESLint 插件。



### 进阶方向

本节按方向列出继续深入时可查阅的资料，每一方向都指向可验证的公开来源，不涉及具体版本细节。

#### 渲染原理与并发特性的深入阅读

**渲染原理与并发特性**：是 React 在渲染流程与调度层面的机制，回答更新为什么可以被打断、优先级如何影响渲染次序。

- React 官方文档关于渲染阶段与提交阶段、过渡更新与延迟值的章节是机制说明的主干。
- React 官方博客中关于并发特性的介绍文章给出设计动机与适用场景。
- 进一步深入需读协调器相关源码模块，读之前先读本系列第 17 篇建立整体流程，否则容易迷失在细节里。

**速记**：机制先读官方文档与博客，再进源码，顺序不宜颠倒。



#### 服务端渲染与 React 服务端组件

**服务端渲染**：是在服务器上把组件渲染为 HTML 再发送给浏览器的方案，服务端组件则进一步允许部分组件只在服务端运行，不把代码发往客户端。

- React 官方文档的服务端渲染章节讲清渲染流程、注水与数据准备的配合方式。
- 服务端组件的说明文档给出组件边界的划分规则与使用限制，边界划分是落地时的主要难点。
- 工程落地通常由框架承担，Next.js 等框架的官方文档给出具体配置与目录约定。

> 服务端渲染解决的是首屏与搜索收录问题，代价是服务端复杂度上升；先确认需求再决定是否引入，不宜默认开启。

**速记**：服务端渲染看官方章节与框架文档，先确认需求再落地。



#### React Native 与跨端方案

**React Native**：是用 React 的组件与状态模型编写原生移动应用的方案，组件最终映射为平台的原生控件。

- React Native 官方文档给出环境搭建、组件与接口索引，是这一方向的权威入口。
- 与 Web 版 React 共享组件模型与状态逻辑，但渲染目标与可用组件不同，不能直接复用全部代码。
- 跨端方案的取舍需结合目标平台与团队技术栈判断，不宜只看一致性宣传。

**速记**：React Native 复用模型不复用渲染，落地前先查官方文档确认可用组件。



#### 编译器与自动优化方向的公开进展

**编译器方向**：是 React 团队在自动优化上的公开探索，目标是在不改写业务代码的前提下减少手工记忆化。

- React 官方博客中关于编译器进展的文章是这一方向的权威来源，讲清适用边界与已知限制。
- 相关话题的公开演讲与讨论可作为补充，但结论以官方材料为准，不采信二手转述。
- 自动优化尚未覆盖的场景中，手工记忆化仍是必要手段，详见本系列第 18 篇。

**速记**：编译器方向看官方博客，未覆盖的场景仍按手工优化处理。



#### 性能与可观测性的工程化方向

**性能与可观测性的工程化**：是把性能指标持续采集、上报与分析的一整套实践，回答线上体验是否在退化、退化发生在哪一步。

- Web 核心指标的官方说明给出加载、交互响应与视觉稳定三类指标的定义与测量方式。
- React 官方文档的性能章节给出组件层面的优化清单，与本系列第 18 篇对应。
- 采集数据需同时覆盖真实用户监控与实验室测量两类手段，单一数据源容易得出片面结论。

**速记**：性能从组件优化走向持续观测，指标定义查核心指标的官方说明。
