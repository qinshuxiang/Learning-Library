## JS 设计模式

### 模块与单例

#### 闭包私有状态

**闭包私有状态**：是利用函数作用域对外不可见的特性，把变量封在闭包内部、只通过暴露的方法读写的封装手段。「闭包」一篇讲过原理，这里看它在模式层面的价值。

- **封闭性**：外部拿不到内部变量本身，只能通过返回的方法间接访问。
- **持久性**：闭包让内部变量在多次调用之间保持，效果类似实例字段。
- **适用性**：适合审计计数、日志缓冲、限流配额等只需少量内部状态的小模块。

```js
function createAuditCounter() {
  let count = 0;
  return {
    record(event) {
      count++;
      return `${count}: ${event}`;
    },
    get count() {
      return count;
    }
  };
}

const counter = createAuditCounter();
console.log(counter.record("登录成功"));
console.log(counter.record("访问敏感目录"));
console.log(counter.count);
counter.count = 999; // 只有 getter, 赋值静默无效
console.log(counter.count);
```

```text
1: 登录成功
2: 访问敏感目录
2
2
```

> 闭包私有状态的要点是「外部只能走暴露的入口」。审计计数这类值一旦能被外部直接改写，日志就失去可信度，只读 getter 正是防线。



#### 模块模式

**模块模式（Module Pattern）**：是用立即执行函数（IIFE）包裹私有实现、只把公开 API 挂在返回对象上的组织方式。

- **私有区**：IIFE 内部的变量与函数对外不可见，充当模块的内部实现。
- **公开区**：返回对象上的方法是对外的唯一接口，可以调用私有实现。
- **立即执行**：IIFE 只在加载时运行一次，初始化成本一次性支付。

```js
const securityAudit = (function () {
  const logs = [];
  return {
    log(message) {
      const time = new Date("2026-09-23T10:00:00Z");
      logs.push(`[${time.toISOString()}] ${message}`);
    },
    dump() {
      return logs.slice();
    }
  };
})();

securityAudit.log("检测到暴力破解尝试");
securityAudit.log("已封禁来源 IP");
console.log(securityAudit.dump());
console.log(typeof securityAudit.format);
```

```text
[
  '[2026-09-23T10:00:00.000Z] 检测到暴力破解尝试',
  '[2026-09-23T10:00:00.000Z] 已封禁来源 IP'
]
undefined
```

> 模块模式用「一层 IIFE 加一个返回对象」划出公私边界。ES Module 普及后，文件本身就是模块，顶层不导出的声明天然私有，二者思路一致。



#### 单例与 WeakMap 写法

**单例（Singleton）**：是保证一个构造结果只存在一份、重复获取都返回同一实例的创建型模式。

- **WeakMap 键控**：以 WeakMap 做实例缓存，按 key 维度各保留一份实例，key 被回收后实例随之回收。
- **与模块单例的关系**：ES Module 顶层导出的对象本身就是天然单例，多数场景无需再手写。

```js
const instances = new WeakMap();

function getCenter(regionConfig) {
  if (instances.has(regionConfig)) return instances.get(regionConfig);
  const center = {
    name: regionConfig.name,
    alerts: 0,
    report() {
      this.alerts++;
      return `${this.name} 告警数: ${this.alerts}`;
    }
  };
  instances.set(regionConfig, center);
  return center;
}

const east = { name: "华东" };
const south = { name: "华南" };
const a = getCenter(east);
const b = getCenter(east);
const c = getCenter(south);
console.log(a === b, a === c);
console.log(a.report());
console.log(b.report());
console.log(c.report());
```

```text
true false
华东 告警数: 1
华东 告警数: 2
华南 告警数: 1
```

> 单例的第一问是「真的需要单例吗」。全局唯一适合配置中心、连接池；WeakMap 键控版本按 key 各留一份实例，更贴近多区域告警中心这类需求，且不阻碍垃圾回收。



### 工厂与构造

#### 工厂函数

**工厂函数（Factory Function）**：是返回新对象的普通函数，用「函数产出对象」替代「new 加构造函数」的创建方式。

- **无 new**：调用即得到对象，不涉及 this 与原型链绑定。
- **可定制**：参数决定产出的形态，同一函数可以造出多种检测器。
- **可组合**：返回对象里可以自由混入方法，也便于叠加闭包状态。

```js
function createDetector(type, threshold) {
  return {
    type,
    threshold,
    check(value) {
      return value >= this.threshold;
    }
  };
}

const bruteForce = createDetector("暴力破解", 10);
const sqlInjection = createDetector("SQL 注入", 3);
console.log(bruteForce.check(12), sqlInjection.check(1));
console.log(bruteForce.type, sqlInjection.type);
```

```text
true false
暴力破解 SQL 注入
```

> 工厂函数的优势是「轻」。原型与继承已在「原型与原型链」「继承与 ES6 class」两篇展开，这里只强调：对象之间没有继承需求、只是形态不同的数据载体时，工厂函数比类更直接。



#### class 静态工厂

**静态工厂方法**：是定义在类上的 static 方法，把「从什么来源构造实例」封装成语义化入口。

- **fromLog(line)**：从一行原始日志解析并构造实例，解析细节不外泄。
- **highRisk(message)**：为高频场景提供默认值，调用方不必逐个填参数。
- **与构造函数的分工**：构造函数只管字段装配，静态工厂管「从哪来、默认是什么」。

```js
class SecurityEvent {
  constructor(level, message, time) {
    Object.assign(this, { level, message, time });
  }
  static fromLog(line) {
    const [level, time, ...rest] = line.split(" | ");
    return new SecurityEvent(level, rest.join(" | "), new Date(time));
  }
  static highRisk(message) {
    return new SecurityEvent("HIGH", message, new Date("2026-09-23T11:00:00Z"));
  }
  describe() {
    return `[${this.level}] ${this.time.toISOString()} ${this.message}`;
  }
}

const evt = SecurityEvent.fromLog("HIGH | 2026-09-23T08:00:00Z | 异地登录");
console.log(evt.describe());
const evt2 = SecurityEvent.highRisk("勒索软件特征命中");
console.log(evt2.level, evt2.message);
```

```text
[HIGH] 2026-09-23T08:00:00.000Z 异地登录
HIGH 勒索软件特征命中
```

> 静态工厂让创建语义显式化：SecurityEvent.fromLog 读起来就是「从日志来」。依赖当前时间的 new Date() 会让结果不可复现，稳定测试里应显式传入时间或注入时钟。



#### 对象池

**对象池（Object Pool）**：是预先创建一批可复用对象、用完归还而不是销毁重建的资源管理模式，这里做机制简述。

- **acquire()**：从空闲区取出对象，取不到返回 null，由调用方决定等待或放弃。
- **release(conn)**：归还对象，内部通常用 Set 记录在用状态，防止同一对象被归还两次。
- **适用场景**：日志上报连接、Worker 线程、大缓冲区等「创建贵、复用稳」的重资源；普通对象不值得入池。

> 对象池解决的是「创建成本」而非「逻辑复杂度」。归还前必须重置内部状态，否则上一个任务的残留数据会泄漏给下一个使用者，日志连接尤其如此。



### 观察者与发布订阅

#### 手写 EventEmitter

一个 EventEmitter 的本质是「事件名到监听函数数组」的 Map，其余 API 都是对这个 Map 的增删与遍历触发。「事件处理」一篇的 addEventListener 与 removeEventListener 就是同一模式的浏览器内置实现：目标元素是被观察者，监听函数是观察者。

- **on(event, listener)**：注册监听函数，事件名不存在时先初始化空数组。
- **off(event, listener)**：按引用移除监听函数，所以匿名函数无法被移除。
- **emit(event, ...args)**：拷贝一份监听数组后逐个调用，避免监听函数在触发途中增删影响本次遍历。

```js
class EventEmitter {
  constructor() {
    this.events = new Map();
  }
  on(event, listener) {
    if (!this.events.has(event)) this.events.set(event, []);
    this.events.get(event).push(listener);
    return this;
  }
  off(event, listener) {
    const listeners = this.events.get(event) || [];
    const index = listeners.indexOf(listener);
    if (index !== -1) listeners.splice(index, 1);
    return this;
  }
  emit(event, ...args) {
    const listeners = this.events.get(event) || [];
    listeners.slice().forEach(listener => listener(...args));
    return this;
  }
}

const bus = new EventEmitter();
const onIntrusion = source => console.log(`告警: 发现来自 ${source} 的入侵尝试`);
bus.on("intrusion", onIntrusion);
bus.emit("intrusion", "203.0.113.7");
bus.off("intrusion", onIntrusion);
bus.emit("intrusion", "203.0.113.8"); // 已解绑, 无输出
console.log("解绑后不再有输出");
```

```text
告警: 发现来自 203.0.113.7 的入侵尝试
解绑后不再有输出
```

> 两个易错点：off 只能移除持有引用的函数，传入匿名函数等于没移除；emit 里先 slice 再遍历，防止遍历中修改数组。只触发一次的 once，可以在 on 的基础上包一层「先自移除再执行」的包装函数实现。



#### 发布订阅与事件总线

**发布订阅（Publish-Subscribe）**：是在发布者与订阅者之间加入主题调度中心、双方互不知晓对方存在的解耦模式。

- **与观察者的差别**：观察者是「目标直接通知观察者」，发布订阅中间多了一层按主题分发的总线，总线可以是上文 EventEmitter 加一层主题约定。
- **主题约定**：主题名用字符串约定，建议收敛成常量表，避免拼写漂移。
- **网安场景**：告警产生方只管 publish 一条「安全告警」主题，短信、入库、大屏各自订阅，新增消费方不动存量代码。

> 发布订阅的代价是「控制流不可见」：读代码时看不出谁在消费某主题，排查要靠全局搜索主题名。主题收敛到常量模块，并在总线上保留调试日志，能明显缓解这类问题。



### 策略与命令

#### 策略模式与表单校验

**策略模式（Strategy）**：是把一族可互换的算法各自封装、运行时按名选用，解耦「用算法的人」和「算法本身」。

- **策略表**：strategies 对象以校验名为键，新增校验只加一行，不改 validate 函数。
- **统一签名**：每个策略接收 value 与附加参数，返回空串表示通过，返回文案表示失败。
- **流程数据化**：rules 用「名称加参数」的数组描述，校验流程成为数据，甚至可以由服务端下发。

```js
const strategies = {
  required(value) {
    return value.trim() === "" ? "内容不能为空" : "";
  },
  minLength(value, length) {
    return value.length < length ? `长度不能少于 ${length} 位` : "";
  },
  strongPassword(value) {
    return /^(?=.*[a-z])(?=.*[A-Z])(?=.*\d).+$/.test(value)
      ? ""
      : "需同时包含大小写字母与数字";
  }
};

function validate(value, rules) {
  const errors = [];
  for (const [name, ...args] of rules) {
    const message = strategies[name](value, ...args);
    if (message) errors.push(message);
  }
  return errors;
}

console.log(validate("abc123", [["required"], ["minLength", 8], ["strongPassword"]]));
console.log(validate("Admin2026", [["required"], ["minLength", 8], ["strongPassword"]]));
```

```text
[ '长度不能少于 8 位', '需同时包含大小写字母与数字' ]
[]
```

> 策略模式消灭的是成片的 if-else。口令强度这类被合规要求反复调整的规则，正适合做成策略表：调整策略不需要动校验流程，流程永远只负责「逐个跑、收集失败文案」。



#### 命令模式与命令队列

**命令模式（Command）**：是把一次操作封装成带 execute 与 undo 的对象，从而可以排队、记录与撤销的模式。

- **execute()**：执行封禁动作，命令对象持有对防火墙集合的引用。
- **undo()**：执行逆操作。审计类系统要求动作可回溯，撤销能力常是硬需求。
- **CommandQueue**：run() 顺序执行并归档已完成的命令，undoLast() 弹出最近一条执行逆操作。

```js
class CommandQueue {
  constructor() {
    this.queue = [];
    this.done = [];
  }
  add(command) {
    this.queue.push(command);
    return this;
  }
  run() {
    while (this.queue.length) {
      const command = this.queue.shift();
      command.execute();
      this.done.push(command);
    }
  }
  undoLast() {
    const command = this.done.pop();
    if (command) command.undo();
  }
}

class BlockIpCommand {
  constructor(firewall, ip) {
    this.firewall = firewall;
    this.ip = ip;
  }
  execute() {
    this.firewall.add(this.ip);
    console.log(`已封禁 ${this.ip}`);
  }
  undo() {
    this.firewall.delete(this.ip);
    console.log(`已解封 ${this.ip}`);
  }
}

const firewall = new Set();
const queue = new CommandQueue();
queue.add(new BlockIpCommand(firewall, "203.0.113.7"));
queue.add(new BlockIpCommand(firewall, "198.51.100.9"));
queue.run();
console.log([...firewall]);
queue.undoLast();
console.log([...firewall]);
```

```text
已封禁 203.0.113.7
已封禁 198.51.100.9
[ '203.0.113.7', '198.51.100.9' ]
已解封 198.51.100.9
[ '203.0.113.7' ]
```

> 命令模式的本质是「把动作变成数据」。动作一旦成为数据，就获得了排队、持久化、重放、撤销的能力；代价是每个操作都要多写一个类，简单一次性操作不值得。



### 代理与装饰

#### Proxy 前置校验与缓存

**代理模式（Proxy）**：是给目标对象包一层同接口的替身，在访问前后插入校验、缓存、日志等附加行为的结构型模式。「Proxy、Reflect 与响应式」一篇已讲 Proxy 与 Reflect 的完整语义，这里聚焦两个最常用的切面。

- **缓存切面**：get 拦截器命中缓存直接返回，未命中调用源方法并回填。
- **前置校验**：访问不存在的接口名时抛出明确错误，把「拼错方法名」提前暴露。
- **拦截范围**：typeof prop !== "string" 的判断过滤了 Symbol 类型的内部键，避免误伤。

```js
function createCachedApi(target) {
  const cache = new Map();
  return new Proxy(target, {
    get(obj, prop) {
      if (typeof prop !== "string") return undefined;
      if (cache.has(prop)) {
        console.log(`[缓存命中] ${prop}`);
        return cache.get(prop);
      }
      if (!(prop in obj)) {
        throw new TypeError(`接口 ${prop} 不存在`);
      }
      const value = obj[prop]();
      cache.set(prop, value);
      return value;
    }
  });
}

const api = createCachedApi({
  threatLevel() {
    console.log("[源调用] threatLevel");
    return "中危";
  }
});

console.log(api.threatLevel);
console.log(api.threatLevel);
try {
  console.log(api.blockList);
} catch (error) {
  console.log(error.message);
}
```

```text
[源调用] threatLevel
中危
[缓存命中] threatLevel
中危
接口 blockList 不存在
```

> 代理适合「对所有成员一视同仁」的横切逻辑；一旦逻辑开始关心某个成员的业务含义，就应回到普通函数。切面写多了，调用栈里全是陷阱，排障成本会反噬收益。



#### 装饰器思想与组合函数

**装饰器模式（Decorator）**：是不改动原函数、用高阶函数把它包上一层附加行为的模式，与代理的区别在于包装的是函数能力而非对象访问。

- **withAuditLog(fn)**：打印入参与返回值，网安场景里等价于给业务函数加审计埋点。
- **withRetry(fn, times)**：捕获异常重试至多 times 次，全部失败后抛出最后一次的错误。
- **组合顺序**：withAuditLog(withRetry(fetchThreatFeed, 3)) 表示重试整体被审计，一次审计对应一次最终结果。

```js
function withAuditLog(fn) {
  return function (...args) {
    console.log(`[审计] 调用 ${fn.name}, 参数: ${JSON.stringify(args)}`);
    const result = fn.apply(this, args);
    console.log(`[审计] ${fn.name} 返回: ${JSON.stringify(result)}`);
    return result;
  };
}

function withRetry(fn, times) {
  return function retryWrapped(...args) {
    let lastError;
    for (let i = 0; i < times; i++) {
      try { return fn.apply(this, args); }
      catch (error) { lastError = error; }
    }
    throw lastError;
  };
}

let attempts = 0;
function fetchThreatFeed() {
  attempts++;
  if (attempts < 3) throw new Error("feed 暂时不可用");
  return ["malware", "phishing"];
}

const safeFetch = withAuditLog(withRetry(fetchThreatFeed, 3));
console.log(safeFetch());
```

```text
[审计] 调用 retryWrapped, 参数: []
[审计] retryWrapped 返回: ["malware","phishing"]
[ 'malware', 'phishing' ]
```

> 组合函数是装饰器思想在 JS 里成本最低的落地。嵌套顺序即执行语义：外层管记录，内层管重试，想换成「先重试后记录」只需交换位置，原函数一行不动。



### 选型收束

#### 模式滥用与选型决策

设计模式解决的是「变化」，没有变化的地方套模式，得到的只有间接层；选型先问意图，再对号入座。

- **为模式而模式**：只有一个实现的策略表、只有一个监听者的总线，都是提前抽象。
- **上帝事件总线**：所有模块都往一个总线收发，数据流失去边界，出了问题无从追责。
- **装饰器叠罗汉**：五层高阶函数嵌套之后，报错栈与业务逻辑完全对不上。
- **控制创建**：需要唯一实例选单例，需要多形态选工厂，资源昂贵选对象池。
- **控制通知**：一对一回调选观察者，多对多解耦选发布订阅。
- **控制行为切换**：分支随配置变化选策略，需要撤销与重放选命令。
- **控制访问**：拦截属性读写选 Proxy，包装函数行为选组合函数。

> 判断标准只有一条：当前是否存在真实的第二形态或复用需求。回答不上来就写最直白的版本，等变化真的出现再重构——重构一个直白实现，远比拆掉一个错误的模式便宜。模式名是沟通词汇而非目标，写代码时从最小实现起步，模式是长出来的，不是塞进去的。
