## 自定义函数

本篇是本库自定义函数的合集。每个三级模块收一组用途相同的函数，先给共用约定与工具函数，再给可直接复制的实现与实测输出。第一个模块解决的是把对象数组导出成 CSV、PRN、TXT 三种表格文本，第二个模块解决的是把 Excel 读到的二维数组转成对象数组，第三个模块在第二个模块的结果上按户主分组整理，第四个模块提供手机号、身份证与姓名的文本脱敏。

- 收录标准：能独立复用、输入输出明确、边界条件写清楚的函数；只服务于一次具体业务、换个场景就作废的临时片段不入本篇。
- 组织方式：导出组的公共约定与工具函数集中在该组之前，其后按用途分组，函数名直述用途。
- 扩展方式：**后续新增的自定义函数继续以新的三级模块追加进本篇**，不另起篇，保证查找入口唯一。

### 导出组的编写约定

#### 公共工具先行

**同一组函数共用的转换与判断逻辑先抽成工具函数**，避免在每个函数里各写一遍，也避免两处实现悄悄分叉。

- 导出组的公共工具有三个：把任意值转成单元格文本的 stringifyCell、收集表头键名的 collectHeaders、按显示宽度计量的 displayWidth。
- 命名直述用途、动词开头，同一篇内不重名；被多处调用才抽出来，只在一处用过的逻辑留在原函数里更好读。
- 工具函数只做一件事，输出完全由输入决定，不读写外部状态，因此可以单独喂数据验证。
- 工具函数不抛异常、不打印日志，出错时返回一个中性值（如空字符串），把判断交回调用方。



#### 输入输出只认基本形态

**导出组三个函数的输入统一为对象数组、输出统一为字符串**，中间不引入类与自定义类型，换任何环境都能直接搬用。

- 数组的每个元素代表一行，对象的键名充当表头，键值充当单元格内容。
- 三个函数各自独立，分别产出 CSV、PRN、TXT 三种字符串，互不依赖、可单独取用。
- 输出都是能整段写盘的纯文本字符串，存成对应扩展名后即可交给 WPS 导入。
- 不做流式处理与增量拼接：数千行量级用数组拼接一次 join 即可，先求正确、再谈性能；真遇到十万行以上再改成逐行写入。
- 不返回对象包装的「成功与否」，出错情形在参数层面排除（空数组返回空字符串），调用方只需判断结果是否为空。



#### 空值与行尾的统一口径

**null 与 undefined 一律输出为空字符串**，而数字 0、空字符串与布尔 false 不在此列，它们照常输出为 0 与 false。

- 判断要写成分别与 null、undefined 严格相等再取或，不能写成取反判断，否则 0 与 false 会被一并吞成空值。
- 非字符串的值统一交给 String 转换：数字按十进制字面量输出，布尔输出 true 或 false。
- 普通对象经 String 转换只会得到方括号包住的 object Object 字样，嵌套对象应先展平成一层字段再传入。
- 行尾统一用 CRLF（回车加换行），最后一行之后也补一个；在 JavaScript 字符串里写作反斜杠 r 反斜杠 n 两个转义字符，不要只写反斜杠 n。
- 空数组直接返回空字符串，不产出只有表头的文件。

```js
function stringifyCell(value) {
  if (value === null || value === undefined) return "";
  return String(value);
}
```

> RFC 4180 的记录定义是各条记录之间用 CRLF 分隔，并允许文件末尾出现一个 CRLF（file = [header CRLF] record *(CRLF record) [CRLF]）。CRLF 在 Windows 记事本、Excel、WPS 中都能正确断行；只有 LF 的文件在旧版记事本里会被挤成一整行。



#### 表头取全部键名的并集

**表头来源是对象数组的键名，取全部行的并集、按键名首次出现的顺序排列**，而不是只取第一行的键。

- 只取第一行：后面的行若多出字段，多出的整列会被静默丢弃。
- 取并集：某行缺少某个键时，该格按空值处理，各行列数仍然整齐。
- 键名的出现顺序决定列顺序；需要固定列序时，在数据源侧把键名的书写顺序统一。
- 用 Set 记录已出现过的键名做去重，Set 的插入顺序与遍历顺序一致，因此首现顺序天然保留。

```js
function collectHeaders(rows) {
  const headers = [];
  const seen = new Set();
  for (const row of rows) {
    for (const key of Object.keys(row)) {
      if (!seen.has(key)) {
        seen.add(key);
        headers.push(key);
      }
    }
  }
  return headers;
}
```

> 表头与数据行取同一份表头数组，两者列的对应关系由数组下标保证；不要在数据行里再用 Object.keys 重新取一遍键，否则某行缺字段时列会整体左移。



### 生成 CSV 字符串

#### 转义规则

**字段内出现逗号、双引号或换行时，必须整段用双引号包住**；双引号又恰好出现在这层包裹内部时，每个双引号写成两个连续双引号。

- RFC 4180 第 6 条：含换行、双引号、逗号的字段应用双引号包裹。
- RFC 4180 第 7 条：已被双引号包裹的字段中，内部的每个双引号须在它前面再加一个双引号。
- 含逗号不包裹，导入时被拆成两列；含换行不包裹，导入时被拆成两条记录。
- 字段内双引号不翻倍，解析方会提前结束该字段，其后的内容变成游离文本。
- 不含这三类字符的字段不加引号，文件更短也更易读。

> 还有两条容易被忽略的规定：字段内的空格属于字段本身，不应被忽略，所以首尾空格不必额外处理；最后一条记录的最后一个字段之后不能再多写一个逗号，拼接时用 join 而不是在末尾追补逗号，天然满足这条。



#### 转义与拼接的实现

```js
function escapeCsvField(text) {
  if (/[",\r\n]/.test(text)) return '"' + text.replace(/"/g, '""') + '"';
  return text;
}

function toCsv(rows) {
  if (rows.length === 0) return "";
  const headers = collectHeaders(rows);
  const lines = [headers.map(escapeCsvField).join(",")];
  for (const row of rows) {
    lines.push(headers.map((h) => escapeCsvField(stringifyCell(row[h]))).join(","));
  }
  return lines.join("\r\n") + "\r\n";
}
```

- 字符组里列出逗号、双引号、CR、LF 四种字符，一次判断取代四次包含判断。
- 替换里的正则带全局标志，才能把字段内每个双引号都翻倍，漏掉标志只会翻倍第一个。
- 表头同样过一遍转义函数：键名里也可能带逗号，不转义会直接把表头行撑出多余列。
- 先得出各行字符串数组再统一 join 行尾，避免在循环里反复拼接长字符串。

#### 中文与 BOM

**含中文的 CSV 要在写盘时于文件开头加一个字节序标记（BOM，对应字符 U+FEFF）**，否则双击打开容易变成乱码。

- 有 BOM 时 WPS 与 Excel 会按 UTF-8 解释文件，中文正常显示。
- 没有 BOM 时改用「从文本或 CSV」导入并手动选 65001 编码，也能正常显示，只是不能图省事去双击。
- BOM 是文件首字节层面的东西，不是 toCsv 返回值的组成部分；把 BOM 交给写盘函数处理，toCsv 保持只产纯数据，便于单独测试或转发。

> [!CAUTION]
> **注意内容**：CSV 出问题最多的两步都在 WPS 这一侧——无 BOM 的直接双击会乱码，超长的身份证号被按数值解释会变成科学计数法并丢掉 15 位之后的精度。导入路径与分列设置见「资源格式」主题第 2 篇 CSV，本篇只负责把文件生成对。



### 生成 PRN 字符串

#### 按显示宽度补空格

**PRN 的列对齐靠补空格实现，而补空的计量单位是显示宽度而不是字符个数**：一个汉字或全角标点在等宽字体下占两格，半角字符占一格。

- 按字符个数补空，只要某列出现过中文，该列之后的所有列都会整体左移，PRN 的对齐就名存实亡。
- 判断依据是字符码位落在哪个区间：中文、全角标点、全角英数、韩文与常用表情等区间按 2 计，其余按 1 计。

```js
function displayWidth(text) {
  let width = 0;
  for (const ch of text) {
    const code = ch.codePointAt(0);
    const wide =
      (code >= 0x1100 && code <= 0x115f) ||
      (code >= 0x2e80 && code <= 0xa4cf) ||
      (code >= 0xac00 && code <= 0xd7a3) ||
      (code >= 0xf900 && code <= 0xfaff) ||
      (code >= 0xfe30 && code <= 0xfe6f) ||
      (code >= 0xff00 && code <= 0xff60) ||
      (code >= 0xffe0 && code <= 0xffe6) ||
      (code >= 0x1f300 && code <= 0x1faff) ||
      (code >= 0x20000 && code <= 0x3fffd);
    width += wide ? 2 : 1;
  }
  return width;
}
```

用逐字符遍历而不是按下标遍历，遇到需要两个码元表示的生僻字与表情符号时才能整体算作一个字符，不会把代理对拆成两个半格。

在 Node 22 里的实测结果：

- 中文 → 4
- abc → 3
- 张三abc → 7
- 全角括号包住的（一） → 6
- 码位 U+1F600 的表情符号 → 2
- 空字符串 → 0

> 这是按常用区间做的近似，不是完整的 Unicode East_Asian_Width 表。带音标的组合字符、零宽字符按 1 计，少数歧义宽度的符号也按 1 计。名册类数据（姓名、单位、证件号、手机号）不涉及这些字符，够用。



#### 列宽与对齐的实现

**先算出每列的最大显示宽度作为列宽，再把每格补足到列宽，列与列之间加一个空格。**

- 文本左对齐：内容在前，空格补在后面。
- 数值右对齐：空格补在前面，内容贴右。这是 Excel 另存 PRN 的既有行为，照此实现才能与 WPS 另存的文件长相一致。
- 单元格为空时补满整列宽度的空格，保证它右边的列不错位。
- 每行末尾的空格整段删掉，避免行尾空白被导入方当成额外一列。

```js
function isNumericCell(text) {
  return text !== "" && !Number.isNaN(Number(text));
}

function toPrn(rows) {
  if (rows.length === 0) return "";
  const headers = collectHeaders(rows);
  const matrix = [headers.slice()];
  for (const row of rows) {
    matrix.push(headers.map((h) => stringifyCell(row[h])));
  }
  const widths = headers.map((_, i) =>
    Math.max(...matrix.map((line) => displayWidth(line[i])))
  );
  return matrix
    .map((line) =>
      line
        .map((cell, i) => {
          const gap = " ".repeat(Math.max(widths[i] - displayWidth(cell), 0));
          return isNumericCell(cell) ? gap + cell : cell + gap;
        })
        .join(" ")
        .replace(/\s+$/, "")
    )
    .join("\r\n") + "\r\n";
}
```

- 表头行与数据行合入同一个矩阵，表头的宽度也参与列宽计算，列宽因此不会小于表头本身。
- 空值先变成空字符串再参与计算，显示宽度为 0，补空格即补满整列。
- 判断数值只看内容能否被 Number 转换成功，不改变原本的文本；因此带前导零的编号 001 会右对齐但内容仍是 001，前导零不会被抹掉。
- 列宽有余时才补空格，取零与差值中的较大者，内容超出列宽时不截断，靠列宽向后扩张容纳。



#### 调用示例与对齐效果

```js
console.log(toPrn(rows));
```

```text
姓名   单位     手机号      备注
张三   法制大队 13800138000
李四   治安大队 13900139000 协办
王小明 网安大队 13700137000
```

姓名列宽由王小明三个字撑到 6，第一列的汉字占两格，补空后各列的起始位置一致；手机号列按数值右对齐；末尾两行的备注列为空，该列被整段删除，所以看不到尾部空白。



#### PRN 的先天缺陷

**PRN 没有任何转义机制，字段内容会直接破坏行与列的结构**，因此它只适合「字段内不含空格与换行、且没有空单元格」的规整数据。

- 字段内含空格：空格被当成列分隔符，一个含空格的单位名会被切成两列。
- 字段内含换行：该条记录断成两行，其后所有行的列对应关系整体错位。
- 空单元格：补出的整段空格与相邻的分隔空格连成一片，导入方若勾选将连续分隔符视为单个处理，这一列会被吞掉。
- 含逗号的字段在 PRN 里反而安全，逗号只是普通字符，这点与 CSV 正好相反。

> [!WARNING]
> **警告内容**：PRN 保存的是打印外观而不是数据事实。列宽不足时内容直接截断且不可逆，字段内的空格与换行无法还原，空单元格会导致列错位。正式的数据交换一律走 CSV，PRN 只用于打印留档与人眼速览，导入路径见「资源格式」主题第 4 篇 PRN。



### 生成 TXT 字符串

#### 制表符分隔的实现

**TXT 用制表符（字符 U+0009）分隔字段**，实现上就是把拼接的分隔符换成制表符，其余与 CSV 的思路一致。

- 制表符只有一种含义，只要字段内不含制表符与换行，导入方按制表符分列的结果一定正确。
- 与 CSV 的关键差别是**没有转义机制**：字段里出现制表符就多切一列，出现换行就多切一行。
- 空值仍然输出为空，两个制表符紧挨着就表示中间那一格为空。
- 这也是 Excel 另存为「文本文件（制表符分隔）」的格式，属于单层的纯文本表格。

```js
function toTxt(rows) {
  if (rows.length === 0) return "";
  const headers = collectHeaders(rows);
  const lines = [headers.slice()];
  for (const row of rows) {
    lines.push(headers.map((h) => stringifyCell(row[h])));
  }
  return lines.map((line) => line.join("\t")).join("\r\n") + "\r\n";
}
```



#### 调用示例与制表符输出

```js
console.log(toTxt(rows).replace(/\t/g, "[TAB]"));
```

```text
姓名[TAB]单位[TAB]手机号[TAB]备注
张三[TAB]法制大队[TAB]13800138000[TAB]
李四[TAB]治安大队[TAB]13900139000[TAB]协办
王小明[TAB]网安大队[TAB]13700137000[TAB]
```

上面用替换把制表符显式打印出来；直接打印时，制表符在编辑器里表现为一段宽度不定的对齐空隙，看起来像多个空格，实际只是一个字符。



#### 字段内含制表符或换行时的处理

**先把字段内的制表符与换行替换成空格再输出**，这是 TXT 唯一可行的补救方式；这些字符必须原样保留时，改用 CSV 的引号转义。

```js
const cleanRows = rows.map((row) =>
  Object.fromEntries(
    Object.entries(row).map(([key, value]) => [key, stringifyCell(value).replace(/[\t\r\n]+/g, " ")])
  )
);

console.log(toTxt(cleanRows));
```

> [!CAUTION]
> **注意内容**：TXT 与 PRN 一样没有转义机制，两者都不该用来传递字段含特殊字符的数据。需要区分「一个格式没有转义机制」与「转义写错了」——前者换格式，后者改代码。判断依据很简单：字段里有没有可能出现分隔符与换行，有就用 CSV。



### 保存为文件

#### 写盘封装

**写盘用 node:fs 的 writeFileSync，编码固定 utf8**，需要 BOM 的格式在写入前给字符串补上 U+FEFF。

```js
import { writeFileSync } from "node:fs";

function saveTextFile(filePath, text, withBom = false) {
  writeFileSync(filePath, withBom ? "\uFEFF" + text : text, "utf8");
}

const rows = [
  { 姓名: "张三", 单位: "法制大队", 手机号: "13800138000", 备注: null },
  { 姓名: "李四", 单位: "治安大队", 手机号: "13900139000", 备注: "协办" },
  { 姓名: "王小明", 单位: "网安大队", 手机号: "13700137000", 备注: undefined },
];

saveTextFile("名册.csv", toCsv(rows), true);
saveTextFile("名册.prn", toPrn(rows));
saveTextFile("名册.txt", toTxt(rows), true);
```

BOM 用转义序列写成字符 U+FEFF，比在源码里直接敲一个不可见字符可靠——后者在编辑器与复制粘贴中极易丢失。



#### 实测的落盘结果

三个文件在 Node 22 下写盘后用 file 与 xxd 查看：

```text
名册.csv  UTF-8 (with BOM), CRLF 行结束符
  00000000: efbb bfe5 a793 e590 8d2c ...   efbbbf 即文件开头的 BOM
名册.txt  UTF-8 (with BOM), CRLF 行结束符
  00000000: efbb bfe5 a793 e590 8d09 ...   09 即字段之间的制表符
名册.prn  UTF-8 无 BOM, CRLF 行结束符
  00000000: e5a7 93e5 908d 20e5 8d95 ...   20 即补位与分隔用的空格
```

三个文件都是可以双击查看、也可以直接导入的纯文本文件，且都带 CRLF 行结束符。



#### 在 WPS 中导入

- **CSV**：走数据选项卡的从文本或 CSV，编码选 65001，分隔符选逗号。
- **TXT**：同一入口，分隔符改选制表符；字段内不含制表符时结果必然正确。
- **PRN**：分隔符选空格并勾选将连续分隔符视为单个处理，或改用固定宽度分列。
- 三者的共同一步：把身份证号、手机号、案号这几列在导入时声明为**文本**，防止科学计数法与精度丢失。

> [!TIP]
> **建议内容**：导出与导入是同一套规则的两端。写导出函数时把「资源格式」主题第 2 篇 CSV 与第 4 篇 PRN 的转义规则、编码与列宽清单放在手边对照，比导入出错后再回头查要省事得多。



### 三个函数的选用

- **要交给系统或别人**：用 CSV。它有引号转义，任何工具都能解析，是数据交换的标准答案。
- **字段全是普通文本、不含制表符**：用 TXT。导入时按制表符分列不会误判，体积也最小。
- **只给人看或打印留档**：用 PRN。空格对齐便于速览，但不要用它传递数据。
- 三者的边界都指向同一件事：**有转义机制就能表达任意内容，没有转义机制就只能承载规整数据**。

> 这组函数的分工也是后续自定义函数的取舍标准：**能被别人拿去用的，输入输出就要足够简单；只服务于一次具体场景的，就不要为通用性增加参数**。下一组函数继续按这个标准追加进本篇。



### 二维数组转对象数组

#### 完整函数

**输入是数组的数组、第一行是表头，输出是对象数组**；只有一个函数，整段复制即可用，没有依赖。

```js
function toObjectRows(rawData) {
  if (!Array.isArray(rawData) || rawData.length < 2) return [];
  const headers = rawData[0];
  const rows = [];
  for (let i = 1; i < rawData.length; i++) {
    const row = {};
    for (let j = 0; j < headers.length; j++) {
      const cell = rawData[i][j];
      row[headers[j]] = cell === undefined ? null : cell;
    }
    rows.push(row);
  }
  return rows;
}
```

- toObjectRows：第一行取作键名，其余行按列位置装配成对象；某行比表头短，缺的列补 null。

> 判缺失写成与 undefined 严格相等，不写取反。写成取反会把 0 与空字符串一起当成缺失，数字列里的 0 会被抹成 null。

- 表头清洗、重名退让、整行判空的处理都不放进这个函数。一条表一次转换，键名错了回原表改比在代码里兜底快；只有在同一个函数要长期兼顾多种表头形态时，才值得为它增加参数。
- 转换完对两个数字：rows.length 对预期数据行数、Object.keys(rows[0]).length 对预期列数，两个都对得上再交给下游。
- 不要走「把每行拼成字符串再按分隔符拆」的路线：拼拆会把值全变成字符串，数字列变文本、日期列变序列号，后续比较与统计还要再转一次。

> [!CAUTION]
> **注意内容**：本节只做与业务无关的结构转换，产出的对象数组可以直接交给导出组的 toCsv、toPrn、toTxt，也可以喂给下一节的按户切分。判据只有一条——换一张表还成立的留在本节，只有户籍名册才成立的放下一节。



### 从 Excel 二维数组整理户主分组

#### 完整函数

**在上一节的对象数组上按户主行切分，每户落成 head 与 members 两个属性**；下列三个函数整段复制即可用，输入输出都是对象数组。

```js
function isEmptyRow(item) {
  return !item["姓名"] && !item["与户主关系"];
}

function groupByHousehold(rows) {
  const households = [];
  let current = null;
  for (const item of rows) {
    if (isEmptyRow(item)) continue;
    if (item["与户主关系"] === "户主") {
      current = { head: item, members: [item] };
      households.push(current);
    } else if (current) {
      current.members.push(item);
    }
  }
  return households;
}

function fillAddress(households) {
  for (const h of households) {
    const address = h.head["标准地址"];
    for (const member of h.members) {
      if (member["标准地址"] === null || member["标准地址"] === "") {
        member["标准地址"] = address;
      }
    }
  }
  return households;
}
```

- isEmptyRow：姓名与与户主关系两列都为空的行归不进任何一户，先剔除。判空只在这一步做，整行全空的幽灵行与表格下方的批注、合计残行都被它拦下。
- groupByHousehold：遇到与户主关系等于「户主」的行开启新户，其余行追加到当前户；户主行放在 members 首位，户数人数都直接取 members.length。
- fillAddress：把户主那一行的标准地址回填给同户中地址为空的成员，成员自带的地址不覆盖。

> 开启新户时就立即把这一户放进结果，而不是等遇到下一个户主再回头补上一户——后者会让最后一户永远漏掉，这是这段逻辑最容易写错的一行。head 与 members 的第一项是同一个对象引用，改 head 上的字段会连带改到成员列表里的那一条。

#### 异常情况

**切分依赖「户主行在前、成员行紧随」的顺序，顺序一旦被破坏就丢数据或错分户，且不报错。**

- 成员行出现在首个户主之前：当前户还不存在，这些行无处可去，被直接跳过。
- 整表没有任何一行的与户主关系是「户主」：结果为空数组，全部数据丢失。
- 同一户里出现两行「户主」：后一行开启新户，原来的一户被从中间劈成两户，人数统计跟着错。
- 关系列写成户主的同义写法（户主本人、本人、户主（女））：整户切不出来，落回前两种情形。

> 除此之外还有一种半空行：姓名有值、与户主关系为空。它会被 isEmptyRow 放行，再被切分逻辑静默丢掉——这类行通常出自登记时漏填关系，属于数据质量问题，应在原始表格里补齐，而不是在代码里兜底猜测。



#### 注意情况

- 地址回填必须在分组之后做。在分组前对整表逐行向下填充，一旦某个成员行带了自己的地址（人户分离就是这种情形），这份地址会被当成本户地址继续往下传，其后成员全部串户。
- 不用 Object.groupBy 代替分组。它按回调返回的键值把元素分桶，而这里的分组依据是一条记录在数组里的位置，并且需要额外保留户主那一行本身，见本主题第 26 篇 ES2022 到 ES2026 新特性。
- 正式使用前对三个数字：原始表的数据行数、切出的户数、各户人数之和，两两对得上再往下走。

> [!WARNING]
> **警告内容**：这组函数不做数据质量校验，靠顺序切分换来的简洁是有代价的——成员先于户主、整表无户主、一户两个户主、关系列写成同义写法，四种输入都会静默丢数据或错分户。各户人数之和应当等于有效数据行数，对不上就回原始表格查。

> 整理结果可直接交给导出组：写盘时把 households 用 flatMap 摊平成成员行，再依次传给 toCsv 与 saveTextFile，文件名给「一标三实名册.csv」。



### 文本脱敏

#### 共用的定长打星

**同一组函数共用的逻辑先抽成工具函数 maskKeepEnds，放在完整函数之前单独成节**，三个脱敏函数各自只决定保留几位。

- maskKeepEnds(value, head, tail)：把字符串保留前 head 个与后 tail 个字符，中间按实际字符数补足星号。
- 判断按码点进行：用 Array.from 拆串，少数民族姓名里的间隔号、扩展区字符都按一个字符计。
- 长度不超过保留位数之和时原样返回，不打星也不截断。

```js
function maskKeepEnds(value, head, tail) {
  const chars = Array.from(String(value));
  if (chars.length <= head + tail) return String(value);
  const headPart = chars.slice(0, head).join("");
  const tailPart = chars.slice(-tail).join("");
  return headPart + "*".repeat(chars.length - head - tail) + tailPart;
}
```

> 打星位数取实际字符数而不是固定写死，短输入与长输入都能保持结果长度与原串一致，便于肉眼对位核对。



#### 完整函数

```js
function maskKeepEnds(value, head, tail) {
  const chars = Array.from(String(value));
  if (chars.length <= head + tail) return String(value);
  const headPart = chars.slice(0, head).join("");
  const tailPart = chars.slice(-tail).join("");
  return headPart + "*".repeat(chars.length - head - tail) + tailPart;
}

function maskPhone(value) {
  return maskKeepEnds(value, 3, 4);
}

function maskIdCard(value) {
  return maskKeepEnds(value, 6, 4);
}

function maskName(value) {
  const chars = Array.from(String(value));
  if (chars.length <= 1) return String(value);
  return chars[0] + "*".repeat(chars.length - 1);
}
```

- maskPhone：11 位手机号保留前 3 后 4，中间打星。
- maskIdCard：18 位身份证保留前 6 后 4，中间打星，前 6 位即地址码。
- maskName：姓名保留首字，其余按字数打星。

#### 异常情况

**两类输入会给出意外结果且不报错：过短的原样返回，tail 传 0 会把整串都拼回尾部。**

- 位数不足：maskPhone("12345") 只有 5 位，不超过 3 加 4，原样返回 12345；maskIdCard("") 返回空串。
- tail 传 0：chars.slice(-0) 等价于 slice(0)，尾部拿到整串，结果变成头部加星号加整串，如下例。

```js
console.log(maskPhone("12345"));
console.log(maskIdCard(""));
console.log(maskKeepEnds("abcdefgh", 2, 0));
```

```text

```



#### 注意情况

- 本组只做展示层脱敏，输入串的合法性不在职责内：位数不对的号码、拼错的身份证都会被原样返回，调用前先校验格式。
- 姓名 maskName 只保留首字，与「保留姓氏末字」的口径不同，对外发文时按发文单位的脱敏要求选口径。
- tail 为 0 的陷阱是既有实现有意不修的：三个包装函数分别传 3 加 4、6 加 4、走姓名分支，都不会触发；若将来新增保留 0 位的函数，须先改 maskKeepEnds 的尾部取法。

> 脱敏结果直接进导出组即可复用：把成员数组的姓名与证件字段先过 maskName 与 maskIdCard，再传 toCsv，导出的名册即自带脱敏。
