## Symbol 与元编程进阶

### Symbol 基础速览

#### Symbol 的唯一性

**Symbol**：是一种原始类型，每次调用 Symbol() 都返回互不相等、适合做唯一标识的值。「ES6 新特性」一篇讲过基础，这里从元编程视角重新聚焦。

- **描述仅用于调试**：String(s1) 显示 Symbol(audit)，描述不参与相等性比较。
- **typeof 结果**：typeof 返回 "symbol"，可以在运行时识别。
- **不参与隐式转换**：Symbol 值不能与字符串拼接、不能参与算术运算，转字符串要显式调用 String()。

```js
const s1 = Symbol("audit");
const s2 = Symbol("audit");
console.log(s1 === s2);
console.log(typeof s1);
console.log(String(s1));
```

```text
false
symbol
Symbol(audit)
```

> 唯一性带来的心智模型是：Symbol 不是「更隐蔽的字符串」，而是「永不撞车的标识符」，它的全部价值从唯一性开始。



#### Symbol.for 与 Symbol.keyFor 注册表

**Symbol.for(key)**：是在全局注册表里按 key 查找或注册 Symbol 的方法，同名必同值；**Symbol.keyFor(sym)** 反查注册 key，未注册返回 undefined。

- **跨作用域共享**：注册表全局有效，不同模块用同一 key 取到同一个 Symbol。
- **与 Symbol() 的区别**：Symbol() 每次新建，Symbol.for 复用已有，相当于给 Symbol 加了字符串命名空间。
- **keyFor 只认注册表**：对 Symbol() 创建的值调用，返回 undefined。

```js
const a1 = Symbol.for("role.admin");
const a2 = Symbol.for("role.admin");
console.log(a1 === a2);
console.log(Symbol.keyFor(a1));
const local = Symbol("local");
console.log(Symbol.keyFor(local));
```

```text
true
role.admin
undefined
```

> Symbol.for 把唯一性升级为「按名共享」。跨模块约定协议常量时，key 建议带上命名空间前缀，例如 role.admin，降低与第三方库撞名的概率。



#### 作对象键与私有常量

用 Symbol 作属性键的属性不出现在 Object.keys、JSON.stringify 与 for-in 之中，天然成为「半私有」字段。

- **枚举隔离**：Object.keys 与 JSON.stringify 均跳过 Symbol 键，序列化不会带出内部字段。
- **仍可被反射枚举**：Reflect.ownKeys 与 Object.getOwnPropertySymbols 能列出 Symbol 键，所以它不是真正的私有，只是「默认不可见」。
- **模块内常量**：Symbol 常量配合导出，使用方拿不到引用就访问不到对应字段。

```js
const READ = Symbol("read");
const WRITE = Symbol("write");

const permission = {
  [READ]: true,
  [WRITE]: false
};

console.log(permission[READ], permission[WRITE]);
console.log(Object.keys(permission));
console.log(JSON.stringify(permission));
console.log(Reflect.ownKeys(permission).length);

const external = Symbol("read");
console.log(permission[external]);
```

```text
true false
[]
{}
2
false
```

> Symbol 键提供的是「不被意外触碰」，而非「不可触碰」。真有保密要求时，应配合闭包或 WeakMap 保管数据，而不是指望 Symbol 键本身防住访问。



### well-known Symbol 实战

#### Symbol.iterator 与分页迭代

**Symbol.iterator**：是约定「如何迭代自身」的键，实现后对象即可被 for-of 与展开语法消费。「迭代器与生成器」一篇讲过协议本身，这里看一个贴合日志分析的分页用法。

- **返回迭代器**：方法返回带 next() 的对象，next() 每次吐出一页日志。
- **惰性切片**：index 随调用推进，不必一次组装出所有页。
- **与展开语法协同**：[...logs] 会重新触发一次完整迭代。

```js
class LogPages {
  constructor(lines, size) {
    this.lines = lines;
    this.size = size;
  }
  [Symbol.iterator]() {
    let index = 0;
    const { lines, size } = this;
    return {
      next() {
        if (index >= lines.length) return { value: undefined, done: true };
        const page = lines.slice(index, index + size);
        index += size;
        return { value: page, done: false };
      }
    };
  }
}

const logs = new LogPages(["a.log", "b.log", "c.log", "d.log", "e.log"], 2);
for (const page of logs) console.log(page);
console.log([...logs]);
```

```text
[ 'a.log', 'b.log' ]
[ 'c.log', 'd.log' ]
[ 'e.log' ]
[ [ 'a.log', 'b.log' ], [ 'c.log', 'd.log' ], [ 'e.log' ] ]
```

> well-known Symbol 是引擎与代码之间的「官方协议位」：不用猜方法名，引擎只认这个键。给日志文件、缓冲区实现分页迭代后，for-of 与展开语法全部自动生效。



#### Symbol.toPrimitive 与类型转换控制

**Symbol.toPrimitive(hint)**：是对象参与类型转换时的优先拦截点，hint 为 "number"、"string" 或 "default"，返回值即为转换结果。

- **hint 判定**：算术与比较倾向 number，模板串与字符串拼接倾向 string，加号无明确倾向时是 default。
- **返回约束**：必须返回原始值，返回对象会抛出 TypeError。
- **与 valueOf、toString 的关系**：本方法优先级最高，定义后两者退居备用。

```js
class RiskScore {
  constructor(value) {
    this.value = value;
  }
  [Symbol.toPrimitive](hint) {
    if (hint === "number") return this.value;
    if (hint === "string") return `${this.value} 分`;
    return this.value;
  }
}

const score = new RiskScore(87);
console.log(score * 1);
console.log(`风险评分: ${score}`);
console.log(score + 0);
```

```text
87
风险评分: 87 分
87
```

> 风险评分这类业务对象若放任默认转换，日志里会出现 [object Object]。实现 Symbol.toPrimitive 让「对象被打印成什么样」由业务决定，是元编程里性价比最高的一处投资。



#### Symbol.toStringTag 与类型标签

**Symbol.toStringTag**：决定 Object.prototype.toString.call(value) 输出方括号里的标签，是跨环境识别类型的可靠手段。

- **自定义标签**：以 getter 形式定义，返回的字符串即成为 [object 标签]。
- **内置标签**：数组、Map、Promise 都内置了它，所以 toString.call 能准确区分它们。
- **比 typeof 强的地方**：typeof 无法区分数组与普通对象，toStringTag 可以。

```js
class ThreatReport {
  get [Symbol.toStringTag]() {
    return "ThreatReport";
  }
}

console.log(Object.prototype.toString.call(new ThreatReport()));
console.log(Object.prototype.toString.call([]));
console.log(Object.prototype.toString.call(new Map()));
```

```text
[object ThreatReport]
[object Array]
[object Map]
```

> 序列化、埋点、日志管道里判断「这是不是数组」时，Object.prototype.toString.call 比 instanceof 更能跨 iframe 环境。Symbol.toStringTag 让自定义类也享受同样的可靠识别。



#### Symbol.hasInstance 与 instanceof 定制

**Symbol.hasInstance**：是 instanceof 运算符背后的查找键，右侧对象定义了它，instanceof 就按它的返回值下结论。

- **定义在静态侧**：必须写成 static [Symbol.hasInstance](value)，value 是左侧操作数。
- **语义自定**：类型检查、范围检查都可以，甚至与类自身结构无关。
- **不发生隐式转换**：字符串 "6" 不满足 typeof === "number"，判为 false。

```js
class EvenNumber {
  static [Symbol.hasInstance](value) {
    return typeof value === "number" && value % 2 === 0;
  }
}

console.log(4 instanceof EvenNumber);
console.log(7 instanceof EvenNumber);
console.log("6" instanceof EvenNumber);
```

```text
true
false
false
```

> 定制 instanceof 是把判断逻辑挂到类型系统上，注意可读性代价：使用者默认 instanceof 表示「是这个类的实例」，让它表达「是偶数」需要团队约定，否则宁可写成普通谓词函数。



#### Symbol.species 与派生构造器

**Symbol.species**：是内置方法返回新实例时使用的构造器键，默认指向类本身，改写后可以让派生操作「降级」为基类。

- **默认行为**：子类实例调用 slice 这类方法，产物仍是子类实例。
- **改写效果**：静态 getter 返回 Array 后，slice 的产物退回普通数组。
- **动机**：子类往往只为附加 summarize 这类工具方法，链式产物不需要继承整套子类行为。

```js
class LogCollection extends Array {
  static get [Symbol.species]() {
    return Array;
  }
  summarize() {
    return `共 ${this.length} 条日志`;
  }
}

const logs = new LogCollection("a", "b", "c");
console.log(logs.summarize());
const sliced = logs.slice(0, 2);
console.log(sliced instanceof LogCollection, sliced instanceof Array);
console.log(sliced.summarize === undefined);
```

```text
共 3 条日志
false true
true
```

> Symbol.species 回答的问题是「方法的返回值应该是谁」。日志集合这类扩展工具类推荐降级派生，避免每次 slice、map、filter 都背着一个不必要的子类实例。



### 标签模板

#### 标签模板函数签名

**标签模板（Tagged Template）**：是把模板字符串交给函数处理的语法，在模板前挂一个标签函数，函数收到片段数组与插值序列。

- **strings**：第一个参数是按插值位置切开的字符串片段数组，元素个数永远比插值多一个。
- **strings.raw**：同一数组的原始形态，转义序列保持源码写法，\n 是两个字符。
- **values**：剩余参数收集所有插值，顺序与源码一致。

```js
function inspect(strings, ...values) {
  console.log(JSON.stringify(strings));
  console.log(JSON.stringify(strings.raw));
  console.log(values);
}

inspect`访问 ${"敏感目录"} 共 ${3} 次\n`;
```

```text
["访问 "," 共 "," 次\n"]
["访问 "," 共 "," 次\\n"]
[ '敏感目录', 3 ]
```

> 记住结构「strings 与 values 交错拼回原文」即可，strings.length === values.length + 1。所有标签模板——防注入、国际化、样式库——都是在这两个参数上做文章。



#### 防注入的 HTML 转义标签

标签模板最贴合网安的用法是自动转义：插值一律按纯文本处理，从语法层面堵住拼接型 XSS。

- **escape 顺序**：先转 &，再转 <、>、"，顺序颠倒会产生双重转义。
- **默认不信任**：所有插值无差别转义，想插入可信 HTML 需要显式设计豁免通道。
- **与手工拼接的对比**：模板拼接靠开发者记得调用 escape，标签模板把转义变成语法默认。

```js
function safeHtml(strings, ...values) {
  const escape = value =>
    String(value)
      .replace(/&/g, "&amp;")
      .replace(/</g, "&lt;")
      .replace(/>/g, "&gt;")
      .replace(/"/g, "&quot;");
  return strings.reduce((result, str, i) =>
    result + str + (i < values.length ? escape(values[i]) : ""), "");
}

const userInput = '<img src=x onerror="alert(1)">';
const page = safeHtml`<div class="comment">${userInput}</div>`;
console.log(page);
console.log(page.includes("<img"));
```

```text
<div class="comment">&lt;img src=x onerror=&quot;alert(1)&quot;&gt;</div>
false
```

> 把用户输入原样拼进 innerHTML 是存储型 XSS 的经典入口。标签模板的价值在于「默认安全」：写模板的人想犯错的唯一途径是刻意绕过，而绕过动作在代码评审里一目了然。



#### 国际化翻译标签

标签模板也可以做「以源码为 key」的翻译层：模板内容即词条，插值即占位参数。

- **词条表**：dict 按语言存放翻译模板，%s 为占位符。
- **替换策略**：values.reduce 逐个替换占位符，避免手写可变下标。
- **降级策略**：查不到词条时回退源码 key，缺翻译不至于渲染失败。

```js
const dict = {
  "zh-CN": { host: "主机 %s", scan: "完成扫描, 目标 %s" },
  "en-US": { host: "Host %s", scan: "Scan finished, target %s" }
};
let locale = "zh-CN";

function t(strings, ...values) {
  const key = strings.join("").trim();
  const template = dict[locale][key] ?? key;
  return values.reduce((result, value) => result.replace("%s", value), template);
}

console.log(t`host ${"203.0.113.7"}`);
console.log(t`scan ${"10.0.0.0/8"}`);
locale = "en-US";
console.log(t`scan ${"10.0.0.0/8"}`);
```

```text
主机 203.0.113.7
完成扫描, 目标 10.0.0.0/8
Scan finished, target 10.0.0.0/8
```

> 相比传递字符串 key 的传统方案，标签模板让源码即词条：阅读处即使用处，重命名可以被工具追踪。真正的 i18n 框架还会处理复数、时区与转义，这里只是核心机制的极简版。



### Reflect 元编程

#### Reflect.defineProperty 与属性控制

**Reflect**：是一个把对象底层操作收敛成函数的内置对象，方法与 Proxy 的拦截器一一对应。「Proxy、Reflect 与响应式」一篇讲过它在响应式里的角色，这里看操作式写法本身。

- **Reflect.defineProperty(target, propertyKey, attributes)**：等价于 Object.defineProperty，但以布尔值报告成败，而不是抛错或静默失败。
- **返回值即结果**：对不可写属性 Reflect.set 返回 false，失败原因不用 try-catch 去捞。
- **enumerable 为 false 的效果**：Object.keys 看不到它，但 Reflect.ownKeys 列得出。

```js
const rule = {};

Reflect.defineProperty(rule, "maxRetry", {
  value: 5,
  writable: false,
  enumerable: false
});

console.log(rule.maxRetry);
console.log(Reflect.ownKeys(rule));
console.log(Object.keys(rule));

const flipped = Reflect.set(rule, "maxRetry", 10);
console.log(flipped, rule.maxRetry);
```

```text
5
[ 'maxRetry' ]
[]
false 5
```

> Reflect 的价值是「把语句变成表达式」：失败返回 false，可以判断、可以聚合、可以进日志。它与 Proxy 的拦截方法一一对应，需要转发默认行为时，Reflect 保证语义原样还原。



#### Reflect.get、has、ownKeys 与 Reflect.construct

Reflect 覆盖读、判、列、建四类日常操作，每个都以函数形式给出完整签名与返回值。

- **Reflect.get(target, propertyKey[, receiver])**：读属性，receiver 决定 getter 里的 this。
- **Reflect.has(target, propertyKey)**：等价于 in 运算符，包含原型链上的键。
- **Reflect.ownKeys(target)**：合并可枚举、不可枚举与 Symbol 键，返回全部自有键。
- **Reflect.construct(target, argumentsList)**：以函数式语法完成 new，配合 new.target 可控制构造行为。

```js
const audit = { level: "HIGH", count: 3 };

console.log(Reflect.get(audit, "level"));
console.log(Reflect.has(audit, "count"));
console.log(Reflect.has(audit, "ip"));
console.log(Reflect.ownKeys(audit));

class ThreatCenter {}
const center = Reflect.construct(ThreatCenter, []);
console.log(center instanceof ThreatCenter);

Reflect.deleteProperty(audit, "count");
console.log(Reflect.has(audit, "count"));
```

```text
HIGH
true
false
[ 'level', 'count' ]
true
false
```

> 单独使用 Reflect 只是换了种写法，它真正的舞台是与 Proxy 搭配：在拦截器里用 Reflect 转发默认行为，再叠加自己的逻辑。这正是响应式系统「拦截而不破坏」的实现底座。



### 元编程边界与风险

#### 可维护性代价

元编程把「代码的行为」变成「运行时才确定的逻辑」，代价首先落在可读性与调试上。

- **静态分析失效**：动态属性、Proxy 拦截让 IDE 跳转与全局搜索找不到真实调用点。
- **调试链变深**：一次属性读取可能穿过多层 get 拦截，报错栈与源码的对应关系被拉长。
- **隐式行为传染**：Symbol.toPrimitive、Symbol.hasInstance 这类钩子改变运算符语义，阅读者若不知情会得出错误结论。
- **边界共识**：元编程能力保留给框架与基础库，业务代码默认走直白写法，这是多数团队的边界。

> 一个朴素的检验法：一段元编程若需要超过三行注释才能解释「为什么要拦截」，通常说明业务语义应该显式写成函数。让魔法留在框架里，让业务保持可搜索。



#### 性能与安全提示

Proxy 与 Reflect 的运行时开销和攻击面，是生产环境必须正视的两个工程问题。

- **性能开销**：Proxy 的每次属性访问都要经过拦截分发，热路径上高频读写的字段应避免包代理，必要时先取到局部变量再操作。
- **身份一致性**：代理对象与目标不是同一个引用，instanceof、WeakMap 键、Object.prototype.toString 的结果都可能出乎意料。
- **攻击面**：能拦截 get、set 的层，也能被用来藏恶意逻辑；对第三方深度代理传来的对象，关键路径上要做白名单校验。
- **审计友好性**：元编程层应输出可观测日志，否则「谁改了这个字段」在生产环境将无法回答。

> 元编程是高杠杆工具：杠杆一端是响应式框架、防注入模板这类基础设施，另一端是难以排查的性能与安全问题。使用前先问「这一层拦截将来能否被监控与下线」，答案决定它该不该上线。
