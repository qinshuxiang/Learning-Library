## 函数式编程

### 纯函数

#### 纯函数的作用与重要性

**纯函数（Pure Function）**：是满足两个条件的函数——**相同输入总是得到相同输出**，且**不产生副作用**。它是函数式编程的基石。

纯函数的两个条件：

- **确定性**：同样的参数，永远返回同样的结果（不依赖外部可变状态）。
- **无副作用**：不修改外部变量、不写文件、不发请求、不改 DOM。

```js
// 纯函数：只依赖参数，不碰外部
function add(a, b) {
  return a + b;
}

// 非纯函数：依赖并修改了外部变量
let count = 0;
function increment() {
  count++; // 副作用：修改了外部变量
}
```

> 纯函数的重要性在于**可预测、可测试、可缓存**：相同输入必得相同输出，没有隐藏依赖，测试只需"输入→断言输出"，无需 mock 环境。这也是 React 的"纯组件"、Redux 的"reducer 必须是纯函数"背后的原因。



#### 纯函数的案例与优势

通过案例体会纯函数的优势。

```js
// 非纯函数：结果受外部变量影响
let taxRate = 0.1;
function calcPrice(price) {
  return price * (1 + taxRate); // 依赖外部 taxRate
}
taxRate = 0.2;
console.log(calcPrice(100)); // 120（同样输入，结果变了）

// 纯函数：把依赖作为参数传入
function calcPricePure(price, tax) {
  return price * (1 + tax);
}
console.log(calcPricePure(100, 0.1)); // 110（稳定）
console.log(calcPricePure(100, 0.2)); // 120
```

纯函数的优势：

- **可预测**：输出只由输入决定。
- **易测试**：无需准备环境。
- **可缓存**：结果可记忆化（memoize）。
- **可组合**：纯函数间可自由组合。

> 对比可见：非纯函数 calcPrice 的结果**偷偷依赖** taxRate，改了就变；纯函数把依赖**显式传参**，结果稳定可控。让函数尽量纯，是提升代码质量最直接的手段之一。



#### 声明式与命令式的对比（实跑）

**声明式与命令式**：是两种组织代码的思路——命令式一步步描述「怎么做」，声明式直接描述「要什么」，函数式编程整体站在声明式一边。

```js
const nums = [1, 2, 3, 4, 5, 6];

// 命令式：手写循环、临时变量、判断与收集
const result1 = [];
for (let i = 0; i < nums.length; i++) {
  if (nums[i] % 2 === 0) {
    result1.push(nums[i] * 10);
  }
}
console.log(result1);

// 声明式：filter 描述筛选意图，map 描述转换意图
const result2 = nums.filter((n) => n % 2 === 0).map((n) => n * 10);
console.log(result2);
```

```text
[ 20, 40, 60 ]
[ 20, 40, 60 ]
```

- **命令式的负担**：循环变量、临时数组、下标判断都是「怎么做」的细节，读者需要逐行模拟执行。
- **声明式的优势**：filter 与 map 把意图摆在明面上，逻辑一眼可读，且不引入可变的中间状态。
- **结果一致**：两种写法输出完全相同，声明式只是把过程细节交给了高阶函数。

> [!TIP]
> **建议内容**：能用数组方法表达清楚的遍历，优先用声明式写法；只有需要提前退出（some、find 已能覆盖）、短路控制或性能敏感的大集合流式处理时，才退回命令式循环。



### 柯里化

#### 柯里化的过程与代码结构

**柯里化（Currying）**：是把**接收多个参数的函数**，转换成**一系列只接收一个参数的函数**的过程。

```js
// 普通函数：一次接收多个参数
function add(a, b, c) {
  return a + b + c;
}

// 柯里化后：逐个参数接收
function curriedAdd(a) {
  return function (b) {
    return function (c) {
      return a + b + c;
    };
  };
}

console.log(add(1, 2, 3));          // 6
console.log(curriedAdd(1)(2)(3));   // 6
```

> 柯里化的本质是"**把多参函数变成单参函数的链**"：add(1,2,3) 变成 curriedAdd(1)(2)(3)。它利用闭包让每一层函数"记住"前面的参数，层层累积，直到参数齐了才真正计算。



#### 柯里化的应用案例

柯里化的价值在于**参数的复用与延迟计算**，看一个日志案例。

```js
// 柯里化的日志函数
function log(level) {
  return function (message) {
    return `[${level}] ${message}`;
  };
}

const logInfo = log("INFO");
const logError = log("ERROR");

console.log(logInfo("用户登录"));   // "[INFO] 用户登录"
console.log(logError("连接失败"));   // "[ERROR] 连接失败"
```

> 柯里化让 log 的"级别"参数被**提前固定**，logInfo、logError 都是"配置好级别"的专用函数。这种"**先传部分参数、复用已固定的配置**"是柯里化最典型的应用。



#### 柯里化的优势

柯里化带来几个显著优势。

- **参数复用**：固定部分参数，生成专用函数。
- **延迟执行**：参数没凑齐前不计算。
- **函数组合**：单参函数更容易组合（与组合函数配合）。
- **语义清晰**：每个函数职责单一。

```js
// 延迟执行：参数齐了才真正计算
function multiply(a) {
  return function (b) {
    return a * b;
  };
}

const double = multiply(2); // 此时还没计算，只是"准备好"
console.log(double(5));     // 10（此时才计算）
```

> 柯里化的核心价值是**"复用"与"延迟"**：multiply(2) 先"配置"了乘数，返回的函数可反复用于不同被乘数。这让函数像"配置项"一样被灵活组装。



#### 自动柯里化函数的实现

手写一个**自动柯里化**函数，能把任意多参函数转成可柯里化调用。

```js
function curry(fn) {
  return function curried(...args) {
    // 参数够了就执行，不够就返回收集参数的函数
    if (args.length >= fn.length) {
      return fn.apply(this, args);
    }
    return function (...nextArgs) {
      return curried.apply(this, [...args, ...nextArgs]);
    };
  };
}

function add(a, b, c) {
  return a + b + c;
}

const curriedAdd = curry(add);
console.log(curriedAdd(1)(2)(3));   // 6
console.log(curriedAdd(1, 2)(3));   // 6
console.log(curriedAdd(1)(2, 3));   // 6
```

> 自动柯里化的判断依据是 **fn.length（形参个数）**：收集到的参数 >= 形参个数就执行，否则继续返回收集参数的函数。这样既支持 (1)(2)(3) 也支持 (1,2)(3) 等混合调用。



#### Vue3 中柯里化的应用

柯里化在真实框架（如 Vue3）中有实际应用。

- Vue3 的 **h 函数**（创建虚拟 DOM）经过柯里化，可预置 type 等参数。
- 柯里化让 h('div') 能生成"专门创建 div"的函数，提升渲染性能。

```js
// 柯里化思想：先固定部分参数，返回更专用的函数
function createH(type) {
  return function (props, children) {
    return { type, props, children };
  };
}

const createDiv = createH("div");
const vnode = createDiv({ id: "app" }, "hello");
console.log(vnode.type); // "div"
```

> Vue3 的响应式与渲染层大量运用柯里化来**预置参数、减少运行时判断**。理解柯里化，有助于读懂框架源码中的"高阶函数工厂"模式，也更能体会函数式编程在真实工程中的价值。



#### 柯里化进阶：无限参数的累加

**无限柯里化**：是柯里化的变体——不预先约定参数个数，参数没给够就永远返回「还能继续收参」的函数，直到出现求值时机（如参与运算）才汇总结果。

```js
function infiniteAdd(a) {
  function inner(b) {
    return infiniteAdd(a + b); // 每收到一个参数就累加一次，继续返回函数
  }
  inner.valueOf = function () {
    return a; // 隐式转数字时返回累计值
  };
  return inner;
}

console.log(infiniteAdd(1)(2)(3) + 0);       // 6
console.log(infiniteAdd(1)(2)(3)(4)(5) + 0); // 15
console.log(infiniteAdd(10)(20) + 0);        // 30
```

```text
6
15
30
```

- **累积方式**：每一层调用都把新参数加进 a，再返回携带新累计值的函数，靠闭包层层传递状态。
- **求值时机**：+ 0 这类运算触发隐式类型转换，进而调用重写的 valueOf，把累计值以数字形式交出。
- **与固定柯里化的区别**：curry 版按 fn.length 判断「参数够了没有」，无限版没有终点，何时求值由使用方决定。

> [!NOTE]
> **提醒内容**：无限柯里化依赖 valueOf 重写与隐式转换，可读性代价不小，适合作为理解闭包累积状态的练习；生产代码中推荐显式的 curry，或直接收集参数数组后再计算。



### 组合函数

#### 组合函数的理解与基本使用

**组合函数（Compose）**：是把**多个函数组合成一个函数**，让数据**依次经过**这些函数处理，实现"流水线"式的数据处理。

```js
// 几个简单函数
const double = (x) => x * 2;
const square = (x) => x * x;

// 手动组合：先 double 再 square
function composed(x) {
  return square(double(x));
}

console.log(composed(3)); // 36（(3*2)^2）
```

> 组合的思想是"**把复杂逻辑拆成小函数，再拼装起来**"：double、square 各自简单，组合后完成"先翻倍再平方"。相比写一个大函数，组合更**灵活、可复用、易测试**。



#### 通用组合函数的实现

手写一个通用的 compose，把任意多个函数从右到左组合。

```js
function compose(...fns) {
  // 从右到左依次执行
  return function (value) {
    return fns.reduceRight((result, fn) => fn(result), value);
  };
}

const double = (x) => x * 2;
const square = (x) => x * x;
const addOne = (x) => x + 1;

const pipeline = compose(addOne, square, double);
// 从右到左：double → square → addOne
console.log(pipeline(3)); // (3*2)^2 + 1 = 37
```

> compose 的**执行顺序是从右到左**（最右边的函数最先执行），这与数学里的函数复合 f(g(x)) 一致。reduceRight 从右往左归约，天然契合这一顺序。理解组合，是理解 Redux 中间件、函数式工具库（如 lodash 的 flow）的基础。



#### pipe 与柯里化 / 偏应用的辨析

**pipe（管道）** 是 compose 的**方向反转版**：从左到右依次执行函数，数据像在管道里"从左流到右"，更贴近"先处理后处理"的直觉。

```js
// pipe：从左到右，reduce 而非 reduceRight
function pipe(...fns) {
  return function (value) {
    return fns.reduce((result, fn) => fn(result), value);
  };
}

const double = (x) => x * 2;
const square = (x) => x * x;

const p = pipe(double, square); // 先 double 再 square
console.log(p(3)); // 36（与 compose(square, double)(3) 结果相同）
```

> 记忆要点：**compose 从右到左（数学复合习惯），pipe 从左到右（阅读顺序）**。二者只是方向相反，实现的组合逻辑完全一致，实际工程里 pipe 因其"顺着读"更常用（lodash 的 flow 就是 pipe）。

另一组高频易混概念是**柯里化（Currying）** 与**偏应用（Partial Application）**：

- **柯里化**：把一个 f(a, b, c) 严格拆成 f(a)(b)(c)——每步**只接收一个参数**，返回下一个单参函数。
- **偏应用**：一次性**固定一部分参数**，生成一个**仍可接收剩余参数**的新函数，如 f(1, 2)(3) 或 f(1, 2, 3) 式的 bind 预置。

```js
// 偏应用：固定前两个参数，第三个参数调用时再给
function sum(a, b, c) {
  return a + b + c;
}
const addTenAndTwenty = sum.bind(null, 10, 20);
console.log(addTenAndTwenty(30)); // 60

// 区别：柯里化要求"一参一函数"；偏应用可一次固定多个，也可经 bind 预置
```

> 对比结论：**柯里化强调"一元化"（每次一个参数），偏应用强调"预置部分参数"（可多个）**。广义上常把两者混用称呼，但严格区分时，bind 预置属偏应用，curriedAdd(1)(2)(3) 属柯里化。两者都能实现"参数复用 + 延迟求值"，只是约束强弱不同。



#### compose 与 pipe 的实跑对比

**compose 与 pipe 的实跑对比**：两者的差别只在执行方向，把同一组函数分别交给它们跑一遍，方向差异与结果是否一致，node 输出一目了然。

```js
function compose(...fns) {
  return (value) => fns.reduceRight((result, fn) => fn(result), value);
}
function pipe(...fns) {
  return (value) => fns.reduce((result, fn) => fn(result), value);
}

const trim = (s) => s.trim();
const toUpper = (s) => s.toUpperCase();
const wrap = (s) => `[${s}]`;

// compose 按从右到左的执行顺序倒着书写：trim → toUpper → wrap
const viaCompose = compose(wrap, toUpper, trim);
// pipe 按从左到右的执行顺序顺着书写：trim → toUpper → wrap
const viaPipe = pipe(trim, toUpper, wrap);
console.log(viaCompose("  hello  "));
console.log(viaPipe("  hello  "));
```

```text
[HELLO]
[HELLO]
```

- **结果一致**：同样的处理链，两种方向各写一遍，输出完全相同。
- **书写差异**：compose 要把执行顺序倒着写，pipe 顺着写，后者与阅读顺序一致。
- **选用倾向**：pipe 免去了「倒着写」的心智负担，无既定约定时出错率更低。

> [!IMPORTANT]
> **重要内容**：方向之争没有对错，本质是同一个 reduce 或 reduceRight 归约——选一个方向在项目里统一即可，混用才会带来维护成本。



#### 函子：让 map 链保持纯净

**函子（Functor）**：可以理解为「一个实现了 map 方法的容器」——把值装进容器，通过 map 传入纯函数来变换值，同时保持容器形态，从而支持链式调用。

```js
class Functor {
  constructor(value) {
    this.value = value;
  }
  static of(value) {
    return new Functor(value);
  }
  map(fn) {
    return Functor.of(fn(this.value)); // 每次返回新容器
  }
}

const result = Functor.of(3)
  .map((x) => x * 2)
  .map((x) => x + 1);
console.log(result.value);
```

```text
7
```

- **装与拆**：of 负责把普通值装进容器，map 负责在容器内对值施加函数，全程不直接裸操作值。
- **链的来源**：map 每次返回一个新函子，因此可以像数组那样连续点调。
- **与数组的关系**：数组的 map 本身就是函子行为的体现，理解函子就是理解「数组为何能链式 map」的抽象版。

> 函子属于函数式编程的进阶概念，此处只需抓住「容器 + map + 返回新容器」三点即可；更多变体（如处理空值的 MayBe、处理错误的 Either）在需要时按同样思路扩展即可。
