## 浏览器观察者 API

### 观察者模式与回调本质

#### 观察者模式

**观察者模式**：被观察对象维护一份观察者名单，状态变化时逐个通知，观察者无需轮询被观察者。

- 角色分工：被观察者只负责广播，观察者各自决定如何响应，二者解耦。
- 订阅与退订：订阅把回调加入名单，退订把回调移出，退订失败会造成无效通知与内存滞留。
- 与事件监听的关系：addEventListener 本身就是观察者模式，观察者 API 是浏览器为特定监控场景做的专用封装。

```js
class Subject {
  constructor() {
    this.observers = new Set();
  }

  subscribe(fn) {
    this.observers.add(fn);
    return () => this.observers.delete(fn);
  }

  notify(data) {
    this.observers.forEach((fn) => fn(data));
  }
}

const subject = new Subject();

const unsubscribe = subject.subscribe((data) => console.log("观察者A:", data));
subject.subscribe((data) => console.log("观察者B:", data));

subject.notify("日志上线");
unsubscribe();
subject.notify("第二次广播");
```

```text
观察者A: 日志上线
观察者B: 日志上线
观察者B: 第二次广播
```

> 手写观察者只用于理解模型：Set 天然去重保证同一回调不重复通知，返回退订函数是把清理责任交还给调用方的惯用法。



#### 异步回调机制

**观察者回调不抢占主流程**：浏览器的观察者 API 全部是异步的，变化发生在当下，回调被排入任务队列延后执行。

- 变化与回调分离：DOM 改动、尺寸变化、交叉状态在同步代码里就已确定，回调在之后的任务或渲染间隙批量执行。
- 批量合并：一次同步操作引发的多处变化合并成一批记录，回调只触发一次，避免风暴。
- 渲染前时机：多数观察者回调安排在渲染流程前后，回调里读到的布局是本帧的最终状态。
- 回调内勿再触发同类变化：回调中修改被观察目标会再次排队，需设终止条件防循环。

> 异步是特性不是缺陷：它保证了多次变化合并为一次处理。需要精确到每次变化的场景，应改为在回调外逐条入队日志再统一上报。



### MutationObserver

#### observe 与配置项

**MutationObserver**：监听 DOM 树变更的观察者，能感知子节点增删、属性修改与文本变化。

- 构造签名：new MutationObserver(callback)，callback 收到 records 数组与 observer 自身两个参数。
- 观察签名：observer.observe(target, options)，target 是要观察的节点，options 必传且至少指定一类变化，否则抛出错误。
- 核心配置：childList 观察子节点增删，attributes 观察属性变化，characterData 观察文本节点内容。
- 范围配置：subtree 为 true 时观察扩展到全部后代节点，attributeFilter 数组只观察列出的属性名，attributeOldValue 与 characterDataOldValue 为 true 时记录旧值。

```js
const observer = new MutationObserver((records, obs) => {
  records.forEach((record) => {
    // record.type 为 "childList"、"attributes" 或 "characterData"
    console.log(record.type, record.target.nodeName);
  });
});

observer.observe(document.body, {
  childList: true,      // 子节点增删
  attributes: true,     // 属性变化
  subtree: true,        // 含全部后代
  attributeOldValue: true, // 记录属性旧值
});
```

> options 是增量条件不是覆盖项：重复调用 observe 会以新 options 整体替换旧配置，想同时观察多种变化要在一次调用里把开关都打开。



#### 变更记录与回调批次

**MutationRecord**：每条记录对应一次原子变化，回调收到的是一批记录的数组，回调本身一次批量触发。

- 记录字段：type 是变化类型，target 是受影响节点，addedNodes 与 removedNodes 是增删的节点列表。
- 属性类字段：attributeName 是变化的属性名，oldValue 是旧值（需开启对应 old 开关才有值），previousSibling 与 nextSibling 标记插入位置。
- 批次语义：同一微任务里的一串 DOM 操作合并为数组一次回调，records 顺序即变化发生顺序。
- 回调时机：MutationObserver 回调在微任务里执行，早于渲染，晚于同步代码。

```js
const log = document.getElementById("log");
const observer = new MutationObserver((records) => {
  console.log("本批记录数:", records.length);

  records.forEach((record) => {
    if (record.type === "childList") {
      record.addedNodes.forEach((node) => {
        // 审计新插入的日志行
        console.log("新增:", node.textContent);
      });
    }
  });
});

observer.observe(log, { childList: true });

const item = document.createElement("p");

item.textContent = "可疑登录 203.0.113.9";
log.appendChild(item);
log.appendChild(document.createElement("p"));
// 微任务中回调一次，输出: 本批记录数: 2
// 输出: 新增: 可疑登录 203.0.113.9
```

> records 里的节点可能已从文档移除：回调执行时 DOM 是最新状态，记录只是快照。做审计时先落自己的数据结构，不要依赖记录里的节点仍有效。



#### 停止观察与即时取回

**disconnect 与 takeRecords**：前者停止观察并清空未派发的记录，后者不停止观察、立即取走待处理记录。

- disconnect 签名：observer.disconnect()，无参数，调用后不再收到任何回调，但观察者对象可复用，再次 observe 即恢复。
- takeRecords 签名：observer.takeRecords()，返回并清空尚未触发回调的记录数组，之后回调不再因这批记录触发。
- 派发中不受影响：回调正在执行时 disconnect 不会中断本次回调，只影响后续。
- 典型组合：组件卸载时 disconnect；要「探针式」抓一次当前变化后自行决定处理时用 takeRecords。

```js
const observer = new MutationObserver((records) => {
  console.log("回调触发, 记录数:", records.length);
});

observer.observe(document.body, { childList: true, subtree: true });

const pending = observer.takeRecords();

console.log("即时取走:", pending.length);
// 这批记录不会再触发回调

observer.disconnect();
// 此后 DOM 任何变化都不再观察
```

> disconnect 不会删除已入队未执行的回调任务：如果想「停观察且本批也不处理」，先 takeRecords 再 disconnect，顺序不能反。



### IntersectionObserver

#### 交叉比与阈值

**IntersectionObserver**：异步检测目标元素与视口（或指定根元素）交叉状态的观察者，交叉比越过阈值时触发回调。

- 构造签名：new IntersectionObserver(callback, options)，callback 收到 entries 数组与 observer 自身。
- 观察签名：observer.observe(target)、observer.unobserve(target)、observer.disconnect()，一次可观察多个目标，目标与根必须同文档。
- 根与边界：options 的 root 指定参照容器（缺省为视口），rootMargin 以类似 CSS margin 的语法外扩或收缩判定边界。
- 交叉比：intersectionRatio 是交集面积占目标面积的比例，threshold 接受数字或数组，如 0、0.5、1 表示「一露头、过半、全露出」各触发一次。
- 触发模型：回调只在跨越阈值时触发，不是每帧触发，静止的交叉状态不会反复通知。

```js
const observer = new IntersectionObserver(
  (entries, obs) => {
    entries.forEach((entry) => {
      // entry.isIntersecting 为 true 表示进入可视区
      console.log(entry.target.dataset.src, entry.intersectionRatio);
      obs.unobserve(entry.target); // 只处理一次
    });
  },
  { threshold: 0.25, rootMargin: "100px" }, // 四周外扩 100px 提前触发
);

document.querySelectorAll("img[data-src]").forEach((img) => {
  observer.observe(img);
});
```

> threshold 是数组不是开关集合：传 0.25 只有一个触发点，要「进入与离开都感知」需传 0 与 1 两个值。rootMargin 在 root 为跨文档 iframe 时无效。



#### entries 与回调细节

**IntersectionObserverEntry**：回调收到的每条记录描述一个目标当下与根的交叉快照，初始观察时每个目标必然先触发一次回调。

- 关键字段：isIntersecting 是布尔值判断是否在判定区内，intersectionRatio 是交叉比，intersectionRect 与 boundingClientRect 给出具体几何。
- time 字段：记录相对页面加载的时间戳，可用来计算元素在可视区停留的时长。
- 首次必触发：observe 之后无论是否可见都会先回调一次，用它做初始化判断，不要等第二次。
- 目标只读：entry 不能反向操作元素，处理完配合 unobserve 或 disconnect 管理观察寿命。

```js
const observer = new IntersectionObserver((entries) => {
  entries.forEach((entry) => {
    if (entry.isIntersecting) {
      console.log("进入视口:", entry.target.id);
    } else {
      console.log("离开视口:", entry.target.id);
    }
  });
}, { threshold: [0, 1] });

const section = document.getElementById("report");

observer.observe(section);
// observe 后立即回调一次，无论 section 当前是否可见
```

> isIntersecting 为 false 不代表元素不可见：可能是 rootMargin 收缩或元素被遮挡之外的几何判定。做曝光统计要记录进入时间戳、离开时间戳，成对求差。



#### 懒加载图片实战

**懒加载实战**：把 data-src 换成 src 的经典场景，用 IntersectionObserver 替代 scroll 监听与布局计算。

```js
const lazyObserver = new IntersectionObserver(
  (entries, obs) => {
    entries.forEach((entry) => {
      if (!entry.isIntersecting) return;

      const img = entry.target;

      img.src = img.dataset.src; // 进入判定区才发起图片请求
      img.removeAttribute("data-src");
      obs.unobserve(img); // 加载即退订，避免重复处理
    });
  },
  { rootMargin: "200px" }, // 提前 200px 预加载，抵消网络延迟
);

document.querySelectorAll("img[data-src]").forEach((img) => {
  lazyObserver.observe(img);
});
```

```html
<!-- 页面初始只写占位与 data-src，不写 src 即不请求 -->
<img data-src="/evidence/a.jpg" alt="证据截图" />
<img data-src="/evidence/b.jpg" alt="日志截图" />
```

> rootMargin 的提前量要匹配网速与滚动速度：太小会看到图片加载过程，太大退化成全量加载。动态插入的图片要在插入后逐个 observe，Observer 不会自动追踪新节点。



### ResizeObserver

#### 元素尺寸监听

**ResizeObserver**：监听单个元素内容区或边框区尺寸变化的观察者，补齐了 window.resize 只能感知视口变化的缺口。

- 构造签名：new ResizeObserver(callback)，callback 收到 entries 数组与 observer 自身。
- 观察签名：observer.observe(target, options)、observer.unobserve(target)、observer.disconnect()，options 可传 box 指定以哪种盒模型度量。
- 触发时机：尺寸变化在渲染流程中处理，回调执行于布局之后、绘制之前，回调里改样式不会引发二次布局闪烁。
- 触发范围：元素从 display none 到显示、被插入文档、盒模型变化都会触发，回调首帧对每个目标必然触发一次。

```js
const chart = document.querySelector(".chart");
const observer = new ResizeObserver((entries, obs) => {
  entries.forEach((entry) => {
    // contentRect 是内容区快照，也可用 entry.contentBoxSize 读详细规格
    console.log("新宽度:", entry.contentRect.width);
    entry.target.redraw?.(entry.contentRect.width); // 按新尺寸重绘
  });
});

observer.observe(chart);
```

> 回调里改被观察元素自身尺寸会再次触发本回调：ResizeObserver 对此有防循环保护，一帧内最多回调两次，但依赖该保护的代码不可靠，尺寸回写要用条件判断守卫。



#### contentBox 与 borderBox

**contentBox 与 borderBox**：ResizeObserver 的两种度量口径，contentBox 是内容区，borderBox 含边框与内边距，默认前者。

- 语义差异：box 为 content-box 时 contentRect 对应 CSS 的内容区，为 border-box 时对应含边框的整体外框。
- 场景选择：做 Canvas 自适应用 contentBox 即可；比较「组件实际占据多大空间」时用 borderBox。
- 字段形态：entry.contentBoxSize 与 borderBoxSize 是数组形态（内联块方向各一项），contentRect 是兼容旧版的矩形快照。
- 取值时机：entry 的快照是变化后的尺寸，回调里无需再读 getBoundingClientRect。

```js
const observer = new ResizeObserver((entries) => {
  entries.forEach((entry) => {
    console.log("内容区:", entry.contentRect.width, entry.contentRect.height);
    console.log("外框区:", entry.borderBoxSize[0].inlineSize);
  });
});

observer.observe(document.querySelector(".log-panel"), { box: "border-box" });
```

> contentRect 在 box 为 border-box 时仍返回内容区矩形，两者口径不联动，混用必然出错。一个观察者只认构造时不确定、observe 时传入的 box 口径，全组统一。



### PerformanceObserver

#### 性能条目类型

**PerformanceObserver**：订阅性能时间线条目的观察者，长任务、资源加载、绘制指标等以条目形式推送。

- 常用条目类型：longtask 捕获超过 50 毫秒的阻塞任务，resource 记录每次网络请求耗时，paint 记录首次绘制，largest-contentful-paint 记录最大内容渲染。
- 构造与观察签名：new PerformanceObserver(callback) 创建，observer.observe(options) 的 options 里 entryTypes 数组指定订阅类型，type 与 buffered 单类型订阅可回放历史条目。
- 回调形态：callback 收到 PerformanceObserverEntryList 包装对象，getEntries、getEntriesByType、getEntriesByName 取出条目。
- 前置校验：PerformanceObserver.supportedEntryTypes 可查询当前浏览器支持的类型，避免订阅无效类型抛错。

```js
const observer = new PerformanceObserver((list) => {
  list.getEntries().forEach((entry) => {
    // entry.name 是任务标识，entry.duration 是阻塞时长
    console.log("长任务:", entry.duration, "ms");
  });
});

observer.observe({ entryTypes: ["longtask", "resource"] });
```

> 性能条目是采样不是日志：浏览器只暴露白名单内的类型与字段，且部分指标有采样率限制。监控方案要按 supportedEntryTypes 降级，不要假设全类型可用。



#### 性能观察实战

**条目回放与上报取舍**：观察者只推送订阅之后的新条目，开启 buffered 可回放页面已发生的历史条目，监控初始化因此不怕晚。

```js
const observer = new PerformanceObserver((list) => {
  const records = list.getEntries().map((entry) => ({
    type: entry.entryType,
    name: entry.name,
    duration: Math.round(entry.duration),
  }));

  // 打包成日志批量上报到采集端
  console.log("性能条目:", records.length, "条");
});

observer.observe({ type: "resource", buffered: true });
// buffered: true 会先把订阅前已发生的资源条目一次性回调出来
```

> entryTypes 与 type 两种写法不能混用：entryTypes 是批量订阅、不支持回放，type 是单类型、支持 buffered。埋点脚本应尽量用 type 加 buffered，否则会漏掉初始化前的关键指标。



### 实战组合

#### 无限滚动列表

**无限滚动实战**：IntersectionObserver 监听哨兵元素，进入视口即加载下一页，替代 scroll 事件节流的老方案。

```html
<ul id="log-list"></ul>
<div id="sentinel"></div>
```

```js
const list = document.getElementById("log-list");
const sentinel = document.getElementById("sentinel");
let page = 0;

const pager = new IntersectionObserver(async (entries) => {
  if (!entries[0].isIntersecting) return;

  page += 1;
  sentinel.textContent = "加载中…";

  const res = await fetch(`/api/logs?page=${page}`);
  const items = await res.json();

  items.forEach((text) => {
    const li = document.createElement("li");

    li.textContent = text;
    list.appendChild(li);
  });

  if (items.length === 0) {
    pager.disconnect(); // 无更多数据，停止观察
    sentinel.textContent = "没有更多了";
  }
});

pager.observe(sentinel);
```

> 加载在途时要防重复请求：回调可能因滚动抖动连续触发，配合 inFlight 标志位或在请求期间 unobserve、完成后再 observe。数据耗尽可能 disconnect，让哨兵不再触发。



#### 埋点与日志上报

**埋点组合实战**：用 MutationObserver 监听审计日志区的新增行，用 IntersectionObserver 统计曝光，二者把采集与渲染彻底解耦。

```js
// 采集侧：监听日志容器新增行，无需侵入渲染代码
const auditObserver = new MutationObserver((records) => {
  const lines = [];

  records.forEach((record) => {
    record.addedNodes.forEach((node) => {
      if (node.nodeType === Node.ELEMENT_NODE) {
        lines.push({ text: node.textContent, at: performance.now() });
      }
    });
  });

  if (lines.length > 0) {
    // 批量入队，由上报模块统一压缩发送
    console.log("待上报日志:", lines.length, "条");
  }
});

auditObserver.observe(document.getElementById("audit"), { childList: true });

// 曝光侧：日志卡片进入视口即记一次曝光
const exposureObserver = new IntersectionObserver(
  (entries, obs) => {
    entries.forEach((entry) => {
      if (entry.isIntersecting) {
        console.log("曝光:", entry.target.dataset.id);
        obs.unobserve(entry.target);
      }
    });
  },
  { threshold: 0.5 }, // 露出一半才算有效曝光
);
```

> 采集与渲染解耦是这套组合的核心价值：渲染层只管往容器里塞节点，采集层以旁观者身份拿到全部变化。但旁路采集要考虑 disconnect 时机与上报去重，否则页面一关就是数据黑洞。
