## 浏览器脚本与扩展开发

### userscript 油猴脚本

#### 脚本管理器与元数据块

**userscript（用户脚本）**：是由脚本管理器托管、按匹配规则注入网页的小型 JS 程序，用于在不改动站点本身的前提下个性化改造页面。

- 脚本管理器：浏览器扩展形态的运行环境，常见的有 Tampermonkey、Violentmonkey、Greasemonkey，脚本以 .user.js 后缀分发，安装后常驻生效。
- 元数据块：脚本头部的注释区，以 ==UserScript== 起头、==/UserScript== 收尾，管理器解析其中的指令来决定注入时机、匹配范围与所需权限。
- @match：声明脚本注入的 URL 匹配模式，如 @match https://example.com/docs/*；@include 语义更宽，支持整串通配，优先用 @match 控制边界。
- @grant：声明脚本使用的特权 API，写 none 时脚本运行在页面普通环境，写成 GM_addStyle 等具体名字时逐项获得对应能力。
- @run-at：控制注入时机，document-start 早于页面脚本执行、document-end 在 DOM 就绪后、document-idle 为默认值。
- @connect：配合 GM_xmlhttpRequest 声明允许跨域请求的目标域，避免每次请求都弹确认。

```js
// ==UserScript==
// @name         站点目录折叠器
// @namespace    learning-library
// @version      1.0
// @description  在目标站点折叠长目录
// @match        https://example.com/docs/*
// @grant        GM_addStyle
// @run-at       document-end
// ==/UserScript==

GM_addStyle(".toc.collapsed { display: none; }"); // 注入一条全局样式
```

> [!NOTE]
> **提醒内容**：@match 是脚本的授权边界，写成宽泛模式等于让脚本进入所有站点。执法取证视角下，检查一个可疑用户脚本先看 @match 与 @grant 两行，就能快速判断它能去哪里、能做什么。



#### 常用 GM API 概况

**GM API**：脚本管理器注入到脚本沙箱的特权函数集合，让用户脚本具备普通页面脚本没有的持久存储、跨域请求与剪贴板等能力。

- **GM_setValue 与 GM_getValue**：跨页面、跨会话的持久键值存储，签名 GM_setValue(key, value) 与 GM_getValue(key, defaultValue)。
- **GM_xmlhttpRequest**：绕过同源策略发起跨域请求，签名 GM_xmlhttpRequest(options)，通过 onload、onerror 回调取结果。
- **GM_addStyle(css)**：向页面插入一段样式表，返回注入的 style 节点。
- **GM_registerMenuCommand(caption, onClick)**：在脚本管理器菜单里注册一个命令入口，点击时执行回调。
- **GM_setClipboard(text)**：把文本写入系统剪贴板。
- **GM_openInTab(url)**：新开一个标签页并加载指定地址，可配 active 参数控制是否前台打开。
- 沙箱差异：@grant 不为 none 时脚本运行在隔离沙箱，window 是代理对象；确需触碰页面真实环境时用 unsafeWindow 访问，此时要警惕站点的检测与反注入逻辑。

> GM API 的可用集因管理器而异，Tampermonkey 兼容面最广。脚本用到的每个 GM 函数都必须在 @grant 里逐一声明，漏声明是「脚本能装上但不工作」的第一常见原因。



#### 页面改造脚本示例

一条完整的改造脚本通常按「匹配、清理、增强、存档」四步组织：元数据限定作用域，启动时移除干扰节点，再挂上增强功能，用 GM 存储记住用户偏好。

```js
// ==UserScript==
// @name         阅读页净化器
// @namespace    learning-library
// @version      1.0
// @match        https://example.com/article/*
// @grant        GM_setValue
// @grant        GM_getValue
// @grant        GM_registerMenuCommand
// @run-at       document-end
// ==/UserScript==

(function () {
  // 第一步：启动时移除干扰节点
  document.querySelectorAll(".ad-banner, .popup-mask").forEach((node) => node.remove());

  // 第二步：读取用户偏好，恢复上次的字号档位
  const size = GM_getValue("fontSize", 16);
  document.body.style.fontSize = size + "px";

  // 第三步：菜单注册字号切换命令，把选择写回存储
  GM_registerMenuCommand("切换大字号", () => {
    GM_setValue("fontSize", 20);
    document.body.style.fontSize = "20px"; // 页面立即生效，下次打开自动恢复
  });
})();
```

> 改造类脚本的常见错误是在 document-start 阶段就查询 DOM，此时目标节点尚未渲染。要么把 @run-at 改为 document-end，要么用 MutationObserver 等节点出现后再动手，两种方案按改动力度取舍。



### MV3 扩展基础

#### manifest.json 结构

**manifest.json**：是浏览器扩展的清单文件，放在扩展根目录，声明名称、版本、权限与每个组成部分的入口。

- manifest_version：固定写 3，表示采用 MV3 规范；MV2 清单在新版 Chrome 已无法上架与加载。
- name 与 version：扩展的显示名与版本号，version 必须是点分整数，如 1.0.0。
- action：定义工具栏图标与点击行为，default_popup 指向点击后弹出的页面。
- permissions：申请扩展级 API 权限，如 storage、tabs、alarms、scripting。
- host_permissions：声明可访问的站点范围，MV3 里宽范围宿主权限按需授予。
- background：指向 service worker 入口文件，是 MV3 扩展的后台。
- content_scripts：声明静态注入的页面脚本与样式及其匹配规则。
- options_page 或 options_ui：指向扩展的设置页入口。

```js
{
  "manifest_version": 3,
  "name": "页面标记助手",
  "version": "1.0.0",
  "permissions": ["storage", "alarms"],
  "host_permissions": ["https://example.com/*"],
  "action": { "default_popup": "popup.html" },
  "background": { "service_worker": "background.js" },
  "content_scripts": [
    { "matches": ["https://example.com/*"], "js": ["content.js"] }
  ]
}
```

> [!IMPORTANT]
> **重要内容**：清单是扩展审计的第一现场。manifest_version 必须为 3；permissions 与 host_permissions 要逐项核对是否超出功能所需，这是判断一个扩展是否良性的最快速手段。



#### content script 注入页面 DOM

**content script**：注入目标页面、与页面共享同一份 DOM 却运行在隔离 JS 上下文里的扩展脚本。

- 共享 DOM：能直接增删改查页面节点与样式，这是扩展做页面改造与内容采集的基础。
- 隔离上下文：运行在 isolated world，页面脚本与 content script 各有一套 JS 全局对象，互相看不到对方的变量与函数。
- 通信受限：与扩展其他部分交换数据只能走 chrome.runtime 消息通道或共享的 chrome.storage。
- 注入方式：静态注入由清单 content_scripts 声明，随匹配页面自动加载；动态注入用 chrome.scripting.executeScript 在运行时打进去，需申请 scripting 权限。

```js
// content.js —— 与页面共享 DOM，运行在隔离上下文
const banner = document.querySelector(".ad-banner");
if (banner) banner.remove(); // 直接移除页面节点

console.log("注入完成:", location.host); // 页面环境信息可正常读取

// 页面脚本自己的全局变量在这里不可见
console.log(typeof window.pageVariable); // undefined，上下文隔离所致
```

> content script 摸得到 DOM 却摸不到页面的 JS 变量，这个「共享视图、隔离执行」的设计同样是排查恶意扩展的抓手：恶意脚本改版面必留 DOM 痕迹，而它的变量不会出现在页面全局里，固定证据时两边都要看。



#### background service worker

**service worker（MV3 的 background）**：扩展的事件驱动后台，有事件时被唤醒执行，空闲数十秒后休眠，休眠期间不保留任何内存状态。

- 事件常驻写法：所有监听器必须在顶层同步注册，worker 每次被唤醒都会先重放顶层代码，再分发触发它的事件。
- 休眠代价：内存变量随休眠丢失，需要跨唤醒保存的状态必须落到 chrome.storage。
- 唤醒来源：消息、闹钟、标签页事件、网络请求监听等都会把休眠的 worker 拉起来。
- 适合承担：跨标签页的统一调度，如定时任务、请求监听、消息路由与批量状态维护。

```js
// background.js —— service worker，所有监听必须写在顶层
chrome.runtime.onInstalled.addListener((details) => {
  if (details.reason === "install") {
    chrome.storage.local.set({ auditCount: 0 }); // 安装时初始化持久状态
  }
});

chrome.alarms.create("heartbeat", { periodInMinutes: 30 }); // 注册周期任务

chrome.alarms.onAlarm.addListener((alarm) => {
  if (alarm.name === "heartbeat") {
    chrome.storage.local.get("auditCount", (data) => {
      chrome.storage.local.set({ auditCount: (data.auditCount || 0) + 1 });
    });
  }
});
```

> [!WARNING]
> **警告内容**：把 addListener 写进 setTimeout 或任何异步回调里是 MV3 的头号错误——worker 休眠醒来后只重放顶层代码，异步注册的监听器根本不存在，事件静默丢失且不报错。



#### 消息通信

**chrome.runtime.sendMessage**：扩展各上下文之间发送单向消息的 API，接收方在 onMessage 里处理并可选择应答。

- 发送签名：chrome.runtime.sendMessage(message, callback)，message 是可结构化克隆的普通对象。
- 接收签名：chrome.runtime.onMessage.addListener((message, sender, sendResponse) => {...})，sender 携带来源标签页与框架信息。
- 异步应答：监听器返回 true 表示稍后调用 sendResponse，通道保持开启；不返回 true 或不调用，发送方 callback 收到 undefined。
- 定向投递：content script 发给扩展页面走 chrome.runtime.sendMessage；反向从 background 发给指定标签页用 chrome.tabs.sendMessage 并带 tabId。

```js
// content.js —— 发送方：向后台要一份数据
chrome.runtime.sendMessage({ type: "getPageInfo" }, (reply) => {
  console.log("后台应答:", reply.count); // 预期输出形如：后台应答: 5
});

// background.js —— 接收方：查存储后异步应答
chrome.runtime.onMessage.addListener((message, sender, sendResponse) => {
  if (message.type === "getPageInfo") {
    chrome.storage.local.get("auditCount", (data) => {
      sendResponse({ count: data.auditCount || 0 }); // 查完再应答
    });
    return true; // 声明将异步应答，保持通道开启
  }
});
```

> return true 是异步应答的开关：不写它，监听器一返回 sendResponse 立即失效，发送方永远收到 undefined。两个 content script 之间没有直接通信通道，必须经 background 中转或共享 storage 协调。



### 权限与安全

#### permissions 声明最小化

**权限最小化**：清单只申请功能必需的权限项，把扩展的能力面压到最小，是安全要求与商店审核要求的重合点。

- 按需申请：用 storage 就不申请 tabs；只在点按钮时才需要的逻辑放 popup，不搬进后台。
- 危险权限：全站点范围的 host_permissions 等价于交出用户全部浏览记录与页面内容，是审查时的重点怀疑对象。
- 收敛工具：activeTab 权限把站点访问压缩到「用户主动点击的当前标签页」且一次性生效，多数工具类扩展用它即可替代常驻 host 权限。
- 代价权衡：权限越宽，商店审核越严、用户安装告警越醒目，出事时的影响面也越大。

> [!TIP]
> **建议内容**：设计扩展时先列功能清单再逐项配权限，能靠 activeTab 与按需授权解决的就不要申请常驻宿主权限。每多一项宽权限，供应链出事时的爆炸半径就大一分。



#### host_permissions 与用户授权

**host_permissions**：声明扩展可访问的站点范围，MV3 起宽范围宿主权限不再安装即生效，而是交给用户按需授予与随时收回。

- 安装期授权：窄而具体的匹配模式在安装时静默授予，扩展立即可用。
- 运行期授权：宽范围宿主权限在首次使用时向用户弹出授权框，用户也可在扩展详情页随时收回。
- 查询与申请：chrome.permissions.contains(pattern, callback) 查询是否已有授权，chrome.permissions.request(pattern, callback) 发起申请，request 只能由用户手势触发。
- 降级路径：未获授权时 content script 不注入、跨域请求被拒，扩展必须设计无权限时的可用降级体验。

```js
// background.js —— 按需申请单个站点的宿主权限
const pattern = { origins: ["https://example.com/*"] };

chrome.permissions.contains(pattern, (granted) => {
  if (granted) {
    console.log("已有授权，直接进入工作流程");
  } else {
    chrome.permissions.request(pattern, (ok) => {
      console.log("用户授权结果:", ok); // 用户允许为 true，拒绝或关闭弹窗为 false
    });
  }
});
```

> 授权状态随时可能被用户收回，扩展不能假设宿主权限长期有效。取证视角下，扩展详情页的权限列表本身就是证据的一部分：一个天气插件申请读取全部网站数据，这个组合的动机需要解释。



#### 扩展供应链风险

**扩展供应链风险**：恶意或被入侵的扩展借安装与更新通道把恶意代码送进用户浏览器，是浏览器侧最隐蔽的攻击面之一。

- 典型恶意行为：窃取表单输入与 Cookie、注入挖矿脚本、劫持搜索与跳转、回传浏览历史。
- 伪装手法：表面功能完全正常，恶意分支低频触发或由远程配置开关控制，静态审查难以一眼识破。
- 更新通道：MV3 已禁止远程托管 JS，但远程配置仍可让同一份代码在不同时机表现出不同行为。
- 取证视角：排查从扩展本地目录入手，核对清单权限与实际代码是否匹配；检查 content script 是否把页面数据外传、service worker 是否外联陌生域名；对扩展文件做哈希比对，确认与商店发布版一致。

> [!CAUTION]
> **注意内容**：扩展是长期驻留的可信代码，一旦被投毒，影响面覆盖其全部用户。办案与自查都应固定「谁在运行、申请了什么、把数据发到哪里」三连问，扩展的本地目录与清单文件是回答这三问的起点。



### 开发与调试

#### 加载已解压扩展

**加载已解压的扩展程序**：开发者模式下的本地调试通道，让浏览器直接运行磁盘上的扩展目录而无需打包发布。

- 前置开关：打开 chrome://extensions 页面右上角的开发者模式。
- 加载步骤：点「加载已解压的扩展程序」，选择包含 manifest.json 的目录，卡片出现即加载成功。
- 即改即测：content script 随目标页刷新重新注入，popup 与扩展页重开即生效，service worker 随扩展重载而重启。
- 更新动作：改动代码后在扩展卡片上点刷新按钮重新加载；刷新会重置扩展的存储与运行状态。
- 打包分发：点「打包扩展程序」生成 .crx 与私钥，正式分发仍需走商店上架流程。

> 调试期间改了 service worker 代码必须点卡片刷新，否则旧 worker 仍在运行、新代码不生效。刷新会清掉运行态，需要状态的任务建议先从 chrome.storage 导出备份再刷新。



#### 扩展页 DevTools

**扩展调试入口**：扩展的每个运行上下文都有独立的 DevTools，入口分散在扩展管理页与各自的界面上。

- background：在 chrome://extensions 的扩展卡片上点「service worker」链接，打开后台专属 DevTools。
- content script：注入目标页后按 F12，Sources 面板左侧的 Content scripts 分组里能看到脚本文件并直接打断点。
- popup：右键工具栏图标选「检查弹出内容」；弹窗开着时也可右键弹窗页面再检查。
- 扩展自有页面：options 页等扩展页面的 DevTools 用法与普通网页完全一致。

> [!TIP]
> **建议内容**：service worker 休眠时，DevTools 一打开就会唤醒它，观察行为本身可能改变被观察对象的生命周期。排查「后台任务时好时坏」类问题时要意识到这层干扰，必要时靠 storage 日志还原现场。



#### 常见加载错误

**加载失败排查**：扩展装不上或行为异常，多数能从管理页的红色报错与清单语法两端定位。

- 清单 JSON 错误：多余逗号、缺引号、注释混入都会导致解析失败，报错信息会标注具体位置。
- 字段拼写：background 写成 background_page、manifest_version 漏写或仍写 2，都会被新版浏览器直接拒绝。
- 路径失效：background、popup、content_scripts 引用的文件不存在，加载时报 Could not load 类错误。
- 权限被拒：申请了商店策略禁止的权限组合，本地能加载但上架审核被拒。

> 排错顺序固定三步：先看 chrome://extensions 的红色错误块，再校验 manifest.json 的 JSON 语法，最后核对清单里引用的每个文件路径是否真实存在。绝大多数加载失败都落在这三处之内。



### 实战

#### IP 识别的纯逻辑实跑

**IPv4 识别**：先用正则从任意文本提取形似 IP 的串，再用逐段数值校验过滤越界串，采集与校验分成两个独立函数让规则各自可测。

```js
function collectIpAddresses(text) {
  const pattern = /\b(?:\d{1,3}\.){3}\d{1,3}\b/g;
  return [...text.matchAll(pattern)].map((m) => m[0]);
}

function isValidIpv4(ip) {
  const parts = ip.split(".");
  return parts.length === 4 && parts.every((p) => Number(p) <= 255);
}

const sample = "来源 192.168.1.107，跳板 10.0.0.8，越界串 999.1.1.1";

const all = collectIpAddresses(sample);
console.log(all.length);
console.log(all.join(","));

const valid = all.filter(isValidIpv4);
console.log(valid.join(","));
console.log(isValidIpv4("256.1.1.1"), isValidIpv4("8.8.8.8"));
```

```text
3
192.168.1.107,10.0.0.8,999.1.1.1
192.168.1.107,10.0.0.8
false true
```

> 单靠正则限制不了每段的数值范围，999.1.1.1 会照常命中，所以采集与校验必须分成两步。取证场景还应单独标注私网段地址，避免把内网地址误记为外联证据。



#### 高亮 IP 的 content script

**实战脚本**：把上面两个纯函数装进 content script，扫描页面文本节点，给命中的 IP 加高亮标记并统计数量，全程不改原文本内容。

```js
// content.js —— 高亮页面中出现的 IPv4 地址（浏览器环境运行）
function collectIpAddresses(text) {
  const pattern = /\b(?:\d{1,3}\.){3}\d{1,3}\b/g;
  return [...text.matchAll(pattern)].map((m) => m[0]);
}

function isValidIpv4(ip) {
  const parts = ip.split(".");
  return parts.length === 4 && parts.every((p) => Number(p) <= 255);
}

// 注入高亮样式
const style = document.createElement("style");
style.textContent = ".ip-mark { background: #ffec3d; color: #000; }";
document.head.append(style);

let hitCount = 0;

// 只遍历文本节点，不触碰元素结构，避免破坏页面原有事件绑定
const walker = document.createTreeWalker(document.body, NodeFilter.SHOW_TEXT);

const targets = [];
while (walker.nextNode()) {
  const node = walker.currentNode;
  if (collectIpAddresses(node.nodeValue).some(isValidIpv4)) {
    targets.push(node); // 先收集再替换，避免遍历中改树
  }
}

for (const node of targets) {
  const frag = document.createDocumentFragment();
  for (const part of node.nodeValue.split(/(\b(?:\d{1,3}\.){3}\d{1,3}\b)/)) {
    if (isValidIpv4(part)) {
      const mark = document.createElement("span");
      mark.className = "ip-mark";
      mark.textContent = part;
      frag.append(mark);
      hitCount++;
    } else {
      frag.append(part);
    }
  }
  node.replaceWith(frag); // 用文档片段整体替换原文本节点
}

console.log("高亮 IP 数量:", hitCount); // 预期输出形如：高亮 IP 数量: 2
```

> [!NOTE]
> **提醒内容**：先收集后替换是改造 DOM 的通用安全顺序，边遍历边替换会打断 TreeWalker 并造成重复处理。脚本只加标记不动内容，页面功能不受影响，截图固定证据时原始文本仍在文档流里。
