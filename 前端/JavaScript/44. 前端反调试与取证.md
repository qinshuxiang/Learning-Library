## 前端反调试与取证

### 网站在防什么

#### 反调试的攻防双方

**反调试**：页面脚本主动检测并干扰开发者工具使用的手段；执法取证视角下，它是判断「涉案页面在保护什么」的第一线索。

- 网站动机：保护前端业务逻辑、接口签名算法，抬高爬虫与逆向成本。
- 取证视角：出现反调试本身即是重要痕迹——正常业务页面极少防御调试，防护越重说明前端藏着越值钱的逻辑。
- 处置原则：取证时优先走「看得见、留得住」的通道（网络面板、HAR 导出），确需动态调试再应对反调试。



#### 四类常见手段

**debugger 陷阱**：定时循环执行 debugger 语句，工具一开就断点挂起。**检测类**：比对执行耗时、窗口尺寸差识别工具打开。**破坏类**：篡改 console 对象让日志失效、清空控制台。**拦截类**：禁用右键菜单与 F12 按键。

> [!NOTE]
> **提醒内容**：这些手段全部是前端 JS 行为，本地生效、无法对抗离线分析——把页面资源整体保存后静态分析，反调试全部失效。取证顺序建议：先存资源再动工具。



### 陷阱与检测的原理

#### debugger 陷阱与耗时检测

**耗时检测**：在 debugger 语句或定时器前后取时间差，挂起时差值剧增，据此判断「有人在调试」。

```js
function guard() {
  const start = Date.now();
  debugger; // 开发者工具打开时在此挂起，差值剧增
  const cost = Date.now() - start;
  console.log("停留毫秒(>50 视为断点挂起):", cost >= 0);
}

guard();

const t1 = Date.now();
setTimeout(() => {
  const drift = Date.now() - t1 - 100;
  console.log("定时偏差:", drift, "毫秒（断点挂起时偏差剧增）");
}, 100);
```

> 单次耗时检测有毫秒级噪声，正常波动几毫秒、断点挂起动辄数千毫秒，阈值通常设在数十毫秒以上。这类代码的特征是 Date.now 与 debugger 成对出现，静态搜索 debugger 关键字就能定位。



#### console 篡改与原生函数检测

**console 篡改**：用普通函数覆盖 console.log 等方法，让调试输出失效；**原生检测**：用 Function.prototype.toString 判断函数是否被替换。

```js
console.log(Function.prototype.toString.call(console.log).slice(0, 40));

const fake = { log: () => {} };
console.log(Function.prototype.toString.call(fake.log));
```

```text
function () { [native code] }
() => {}
```

> 原生函数的字符串形式固定含 [native code]，被替换后变成普通函数源码——这是双向的：页面用它检测自己的 console 是否被工具接管，取证时也用它识别页面是否篡改过原生对象。在控制台手敲 console.log 出来的是 [native code] 而行为异常，说明对象被换了。



#### 自动化环境特征

**navigator.webdriver**：自动化框架（Selenium、Puppeteer）置为 true 的标准特征位，页面据此识别机器人访问。

```js
// 浏览器内执行
// console.log(navigator.webdriver); // 真人 false，自动化 true
// 另有 window.chrome 缺失、userAgent 含 HeadlessChrome 等辅助特征
```

> 无头浏览器是批量注册、刷量的常用载体，反爬页面通常先查 webdriver 再叠加上述耗时检测。取证分析自动化涉案脚本时，这段特征代码反过来就是脚本作者「想让程序冒充真人」的直接证据。



#### 按键与右键拦截

**事件拦截**：监听 contextmenu 与 keydown 事件并阻止默认行为，禁掉右键菜单和 F12 等快捷键，是最表层也最易绕过的一类防护。

```js
// 浏览器内执行
// document.addEventListener("contextmenu", (e) => e.preventDefault()); // 右键失效
// document.addEventListener("keydown", (e) => {
//   if (e.key === "F12" || (e.ctrlKey && e.shiftKey && e.key === "I")) e.preventDefault();
// });
```

- 拦截只在页面层生效：浏览器设置、地址栏菜单、本地保存后的文件全都不受影响。
- 静态搜索 preventDefault 与 contextmenu 即可定位此类代码。
- 判断意义有限：大量正版站点也禁右键防图片盗用，单凭拦截不能推出恶意。

> 拦截类防护的作用对象是普通访客，对取证者只构成小障碍。见到多层拦截叠加（按键加检测加 debugger 陷阱）才有分析价值，说明站方明确知道前端逻辑值得保护。



### 应对与还原

#### 断点停不下来的处理

**禁用断点**：DevTools 的 Sources 面板提供全局断点开关（停用断点按钮），一键放行所有 debugger 语句。

- 停用断点开关激活后，debugger 语句不再挂起，陷阱直接失效。
- 对个别语句可右键选「永不在此处暂停」，精准跳过单个陷阱。
- 条件断点写成恒假条件（如 false）等价于局部禁用，且不动全局开关。

> [!TIP]
> **建议内容**：取证机上先开停用断点再刷新页面，绝大多数 debugger 陷阱到此已解决；只有陷阱逻辑附带副作用（挂起时上报或改页面）时才需要「永不在此处暂停」逐个处理。



#### 本地替换与动态改写

**本地替换**：DevTools 的 Overrides 功能把页面脚本存到本地，改完刷新即以本地版本运行。

- 入口在 Sources 面板的 Overrides 标签，选本地目录并授权后生效。
- 用途：删掉检测代码、给关键函数加日志、把压缩脚本先格式化再改。
- 证据意识：替换只在本机生效，不动服务端原文件；取证记录里应注明做过本地替换及替换内容。



#### 混淆代码的还原路径

**混淆特征**：十六进制变量名、字符串数组加下标解密、eval 与 atob 动态解码、十六进制转义字符串是最常见的四类。

```js
const samples = [
  "var _0x3f2a=['log','hello'];",
  "eval(atob('YWxlcnQoMSk='));",
  "const a='\\x68\\x65\\x6c\\x6c\\x6f';",
];

for (const s of samples) {
  const hits = [];
  if (/_0x[0-9a-f]{4,}/i.test(s)) hits.push("十六进制变量名");
  if (/eval\s*\(\s*atob/.test(s)) hits.push("eval+atob 动态解码");
  if (/\\x[0-9a-f]{2}/i.test(s)) hits.push("十六进制转义字符串");
  console.log(hits.length ? hits.join(" + ") : "无特征");
}

console.log(atob("YWxlcnQoMSk="));
```

```text
十六进制变量名
eval+atob 动态解码
十六进制转义字符串
alert(1)
```

> 还原顺序：先格式化（DevTools 的大括号按钮），再在控制台直接求值解码函数拿到字符串数组，静态分析卡住就用条件断点与日志断点打印中间值。深度混淆走 AST 工具（Babel 类）做常量折叠与控制流还原，属专项技能，常规取证到「看懂关键函数在干什么」即可止步。



### 取证实务

#### 静态固定优先

**静态固定**：先无侵入地把页面资源与请求留档，再考虑动态分析，顺序不能反。

- 资源：浏览器「另存为完整网页」或抓包工具全量保存 HTML、JS 与资源文件。
- 请求：Network 面板右键导出 HAR 文件，含全部请求头、响应体与时间线。
- 画面：整页截图配合系统时间；关键交互录屏并保留原始文件哈希。

> HAR 里通常直接藏着接口地址、鉴权头与响应明文，多数案件到此已够用；反调试应对只发生在「前端逻辑本身即证据」（如盗版验证算法、暗扣逻辑）的场景。



#### 动态分析的留痕

**动态留痕**：动态调试会改变页面执行环境，操作过程本身要可复现。

- 记录分析日期、浏览器版本、扩展与油猴脚本清单——环境差异会让结论不可复现。
- 控制台里手工执行的每条关键命令截图或复制存档。
- 涉及绕过反调试的操作写明方法（停用断点、本地替换），引用结论时能对回原始代码位置。

> [!CAUTION]
> **注意内容**：取证机上不要登录个人账号、不要装来路不明的油猴脚本——页面脚本可以读取扩展注入的环境并伪造或污染观测结果。分析涉案页面用干净的独立浏览器实例，结论才站得住。



#### 证据文件的哈希固定

**哈希固定**：对导出的 HAR、截图与保存的资源文件逐个计算 SHA-256 并登记，保证分析过程中文件未被改动，与 Web Crypto 的摘要能力直接呼应。

```js
async function sha256Hex(file) {
  const buf = await file.arrayBuffer();
  const digest = await crypto.subtle.digest("SHA-256", buf);
  return [...new Uint8Array(digest)]
    .map((b) => b.toString(16).padStart(2, "0"))
    .join("");
}

// const list = [harFile, screenshotFile];
// for (const f of list) console.log(f.name, await sha256Hex(f));
```

- 计算时点：取证材料一落盘就算，之后每次拷贝后复核，哈希一致才算同一份。
- 登记要素：文件名、SHA-256、计算时间、计算环境，四项成对保存。
- 时间戳来源取系统时钟并注明，更严格的可信时间戳走专门服务，不在本篇展开。

> 哈希固定是所有数字取证规范的基础动作：出具分析报告时附材料哈希清单，对方质疑证据完整性时能当场复算对上。



### 常见陷阱

#### 把反调试当犯罪证据

**性质判断**：反调试与混淆是通用的技术保护手段，大量正版商业网站（尤其金融、游戏）都在用，本身不违法。

- 技术特征只能说明「页面在防逆向」，不能直接推导违法故意。
- 定性要靠内容：页面业务是否涉赌涉诈、接口是否暗扣、资金流向是否异常。
- 报告里写「该站使用商业级前端保护（如某混淆方案）」并注明同类合法站点亦常见，避免结论越界。



#### 依赖单一工具

**工具依赖**：DevTools 只是一条通道，只会在浏览器里调试会错过大量证据。

- 资源保存后用静态搜索（debugger、atob、_0x、webdriver 等关键字）全量过一遍，比手工点开每个文件快得多。
- 抓包工具与浏览器面板互相印证：面板看不到的请求可能被 Service Worker 拦截改写。
- 遇到 WebAssembly 与深度混淆，超出常规取证能力时移交专业检验机构，不做超出能力的结论。

> [!WARNING]
> **警告内容**：对涉案页面的任何动态操作都可能触发服务端风控记录，导致对方销毁云端证据。分析前先评估是否需要先行固定云端数据、由谁出具手续，不要带着「先看看」的心态碰在线涉案系统。
