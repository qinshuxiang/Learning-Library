## 严格模式与对象属性描述符

### with 语句与 eval 函数

#### with 语句产生的作用域

**with 语句**：用于**扩展作用域链**，让代码块内可以直接访问指定对象的属性（无需写对象前缀）。

```js
const obj = { name: "coderwhy", age: 18 };

with (obj) {
  console.log(name); // 直接访问 obj.name
  console.log(age);  // 直接访问 obj.age
}
```

> [!WARNING]
> **警告内容**：with 的致命问题：**作用域不可预测**——若 obj 里没有某属性，查找会**沿作用域链落到外层**，导致结果模糊、难以优化，甚至产生 bug。因此它**被严格模式禁用**、也被 lint 工具禁止，实际开发中应避免使用。



#### eval 函数的执行与缺点

**eval(string)**：把字符串**当作代码执行**，是 JavaScript 最危险的特性之一。

```js
const x = 10;
eval("console.log(x + 5)"); // 15（执行字符串代码）
eval("var y = 100");
console.log(y); // 100（eval 声明的变量泄漏到外层）
```

eval 的缺点：

- **安全风险**：执行不可信字符串等于**代码注入**（XSS 温床）。
- **性能差**：阻止引擎优化（无法预知代码内容）。
- **难维护**：动态生成代码，可读性极差。

> [!WARNING]
> **警告内容**：eval 几乎**没有必须使用的理由**：它带来注入风险、性能损耗、可维护性灾难。绝大多数"看似需要 eval"的场景（动态访问属性、计算表达式）都有更安全的替代方案（如方括号语法、Function 构造器的谨慎使用）。应**一律避免**。



### 严格模式

#### 认识严格模式

**严格模式（Strict Mode）**：是 JavaScript 的一种**更严格、更安全**的运行模式，它修正了语言早期的一些"宽松"设计缺陷。

- 通过 "use strict"; 指令开启。
- 消除了部分**静默错误**（改为抛出异常）。
- 禁用了一些**危险或不合理**的语法（如 with）。

```js
"use strict";

// 未声明变量赋值会报错（非严格模式则静默创建全局变量）
// undeclaredVar = 10; // ReferenceError
```

> 严格模式的意义是"**把隐患变成显式错误**"：早期的宽松行为（隐式全局变量、静默失败）会埋下难以排查的 bug，严格模式让它们在开发阶段就**暴露**。现代工程（ESLint、ESModule）默认启用严格模式。



#### 严格模式的开启方式

严格模式可以**作用域**地开启，两种方式。

- **整个脚本**：在文件**最顶部**写 "use strict";。
- **单个函数**：在**函数体第一行**写 "use strict";。

```js
// 方式一：整个脚本严格模式
"use strict";
function foo() {
  // 严格模式
}

// 方式二：单个函数严格模式
function bar() {
  "use strict";
  // 仅此函数是严格模式
}
```

> [!IMPORTANT]
> **重要内容**：严格模式指令必须写在**作用域最顶部**（前面不能有其它语句），否则不生效。ES6 的 class 体、ESModule 模块**默认就是严格模式**，无需手动声明。



#### 严格模式下的语法细节

严格模式带来了若干具体的行为变化。

- **禁止未声明变量赋值**：x = 1 报错（非严格则创建全局变量）。
- **禁止删除变量/函数**：delete 不能作用于变量名。
- **函数参数不能重名**。
- **this 在普通函数中为 undefined**。
- **禁用 with、八进制字面量**等。

```js
"use strict";

// 1. 未声明赋值报错
// foo = 1; // ReferenceError

// 2. 普通函数的 this 是 undefined
function showThis() {
  console.log(this); // undefined
}
showThis();

// 3. 参数不能重名
// function sum(a, a) {} // SyntaxError
```

> 严格模式最重要的几条变化：**未声明赋值报错**、**this 变 undefined**、**禁用 with**。理解这些，能解释很多"非严格模式下的诡异行为"，也是写出健壮代码的基础。



#### 严格模式与模块的关系

**严格模式与模块**：ESM 模块**默认且强制**运行在严格模式——无需写指令、也无法关闭；而经典 script 默认非严格、需手动声明。这是 script 与 type="module" 两种加载方式的重要差异，也是"显式写 'use strict'"越来越少的原因。

```js
// module.mjs —— 模块文件：自动严格，未声明赋值直接抛错
undeclaredVar = 10;
console.log("不会执行到这里");
```

```text
ReferenceError: undeclaredVar is not defined
```

> [!IMPORTANT]
> **重要内容**：同样的代码放进经典 script（或 CommonJS 文件）默认非严格，x = 1 会**静默创建全局变量**、程序继续运行；模块里则直接抛 ReferenceError。模块的严格模式是「锁死」的：不能选择性关闭、也不能在模块内放宽；class 体内同样自动严格——用模块，严格模式是默认赠品，这是优先采用 ESM 的理由之一。



### 属性描述符

#### 数据属性描述符

**属性描述符（Property Descriptor）**：是描述对象属性**特性**的对象，控制属性的行为。**数据属性**有四个特性。

- **value**：属性值。
- **writable**：是否可修改。
- **enumerable**：是否可枚举（for-in、Object.keys）。
- **configurable**：是否可删除/重新定义。

```js
const obj = { name: "why" };

// 查看属性描述符
console.log(Object.getOwnPropertyDescriptor(obj, "name"));
// { value: "why", writable: true, enumerable: true, configurable: true }

// 定义属性（带描述符）
Object.defineProperty(obj, "age", {
  value: 18,
  writable: false,    // 不可修改
  enumerable: true,
  configurable: false
});

obj.age = 20;          // 无效（writable: false）
console.log(obj.age);  // 18
```

> 属性描述符让对象属性**可控**：writable: false 冻结值、enumerable: false 隐藏属性、configurable: false 禁止删除。它是实现"只读属性""私有属性""常量"等需求的底层机制。



#### 存取属性描述符

**存取属性（Accessor Property）**：用 get/set 函数代替 value，在**读写属性时**触发自定义逻辑。

- **get**：读取属性时调用的函数。
- **set**：设置属性时调用的函数（接收新值）。
- 存取属性**没有 value 和 writable**，取而代之是 get/set。

```js
const person = {
  _age: 0,
  get age() {
    return this._age;
  },
  set age(value) {
    if (value < 0 || value > 150) {
      throw new Error("年龄不合法");
    }
    this._age = value;
  }
};

person.age = 18;
console.log(person.age); // 18
// person.age = -1; // 抛出错误（校验拦截）
```

> 存取属性的价值在于**拦截读写**：set 里可以加**校验、转换、副作用**，get 里可以**计算、懒加载**。它是 Vue2 响应式（Object.defineProperty 的 getter/setter）的底层原理。



#### 定义多个属性描述符

用 **Object.defineProperties** 一次性定义多个属性。

```js
const obj = {};

Object.defineProperties(obj, {
  name: {
    value: "coderwhy",
    writable: false,
    enumerable: true,
    configurable: true
  },
  age: {
    value: 18,
    enumerable: true
  }
});

console.log(obj.name); // "coderwhy"
```

> defineProperties 与 defineProperty 的区别：前者**批量**定义多个属性，后者**单个**。它们的核心都是"**显式指定每个属性的描述符**"，实现精细的属性控制。



#### 可枚举描述符配置的补充

enumerable 特性决定属性**是否出现在遍历中**，是容易被忽略的细节。

- enumerable: true：出现在 for-in、Object.keys 中。
- enumerable: false：被**隐藏**，但仍可用 . 访问。

```js
const obj = { a: 1 };

Object.defineProperty(obj, "secret", {
  value: "隐藏值",
  enumerable: false // 不可枚举
});

console.log(Object.keys(obj));  // ["a"]（secret 不出现）
console.log(obj.secret);        // "隐藏值"（仍可访问）
for (const key in obj) {
  console.log(key); // 只有 "a"
}
```

> enumerable: false 常用于**隐藏内部字段**：字段仍存在、可访问，但不出现在遍历与序列化（JSON.stringify）中。理解它，能解释"为什么有些属性 Object.keys 取不到"。



#### defineProperty 定义存取器

**defineProperty 定义存取器**：描述符对象里用 get/set 替代 value/writable，即可给任意对象**追加**带读写拦截的属性——当对象不是字面量、需要在运行时动态挂载存取属性时，这是唯一手段。

```js
const user = {};
let _name = "默认名";

Object.defineProperty(user, "name", {
  get() { return _name; },
  set(value) {
    if (typeof value !== "string" || value.trim() === "") throw new Error("名字不能为空");
    _name = value.trim();
  },
  enumerable: true
});

user.name = "  why  ";  // 触发 set：校验 + 裁剪
console.log(user.name); // 触发 get
const d = Object.getOwnPropertyDescriptor(user, "name");
console.log(d.value, d.writable); // 存取描述符没有 value/writable
```

```text
why
undefined undefined
```

> [!NOTE]
> **提醒内容**：存取描述符里 get/set 与 value/writable **互斥**——同一描述符里同时出现会抛 TypeError；configurable 为 false 后，get/set 与 enumerable 也不可再改。存取器与数据描述符的这套约束，是「defineProperty 一次定义即定型」的体现。



#### 属性遍历方法的边界对比

**for-in 与 Object.keys 的边界**：for-in 只走可枚举属性但**会沿原型链**；Object.keys 只取**自身**可枚举；要连不可枚举属性一起拿，得用 Object.getOwnPropertyNames——加一个 hidden 属性，四种口径的差异即可全部实跑出来。

```js
const parent = { inherited: "父对象属性" };

const obj = Object.create(parent);
obj.visible = "自身可枚举";
Object.defineProperty(obj, "hidden", { value: "自身不可枚举", enumerable: false });

for (const key in obj) console.log("for-in：", key); // 沿原型链走
console.log("Object.keys：", Object.keys(obj)); // 仅自身可枚举
console.log("getOwnPropertyNames：", Object.getOwnPropertyNames(obj)); // 自身全部
console.log("JSON.stringify：", JSON.stringify(obj)); // 仅自身可枚举
```

```text
for-in： visible
for-in： inherited
Object.keys： [ 'visible' ]
getOwnPropertyNames： [ 'visible', 'hidden' ]
JSON.stringify： {"visible":"自身可枚举"}
```

> 四种口径速记：for-in 最宽（自身 + 原型链的可枚举），Object.keys 与 JSON.stringify 只认自身可枚举，getOwnPropertyNames 连不可枚举也收（但不含 Symbol 键，需用 getOwnPropertySymbols）。隐藏内部字段时（enumerable: false），用 for-in 仍可能被原型链上的可枚举属性「污染」，这是遍历前要心里有数的边界。



### Object 对对象的限制方法

#### Object.preventExtensions()

**Object.preventExtensions(obj)**：禁止**新增**属性，但**允许修改和删除**已有属性。

```js
const obj = { a: 1 };
Object.preventExtensions(obj);

obj.b = 2;        // 无效（禁止新增）
obj.a = 100;      // 有效（可修改）
delete obj.a;     // 有效（可删除）

console.log(Object.isExtensible(obj)); // false
```

> preventExtensions 是**最宽松**的限制：只禁"加"，不禁"改"和"删"。判断是否可扩展用 Object.isExtensible()。



#### Object.seal()

**Object.seal(obj)**：**禁止新增和删除**属性，但**允许修改**已有属性（相当于 preventExtensions + 所有属性 configurable: false）。

```js
const obj = { a: 1 };
Object.seal(obj);

obj.b = 2;        // 无效（禁止新增）
delete obj.a;     // 无效（禁止删除）
obj.a = 100;      // 有效（可修改）

console.log(Object.isSealed(obj)); // true
```

> seal（密封）比 preventExtensions 更严：**不能加、不能删，只能改**。它把所有属性的 configurable 置为 false，适合"结构固定但值可变"的对象。



#### Object.freeze()

**Object.freeze(obj)**：**最严格**的限制，**禁止新增、删除、修改**任何属性（相当于 seal + 所有属性 writable: false）。

```js
const obj = { a: 1 };
Object.freeze(obj);

obj.b = 2;        // 无效（禁止新增）
delete obj.a;     // 无效（禁止删除）
obj.a = 100;      // 无效（禁止修改）

console.log(Object.isFrozen(obj)); // true
console.log(obj.a); // 1（保持不变）
```

> 三个方法限制强度递增：**preventExtensions < seal < freeze**。freeze 让对象**完全不可变**（浅冻结，嵌套对象仍需递归冻结）。它们常用于**常量配置、防止意外修改**等场景。



#### seal 与 freeze 的区别实跑

**seal 与 freeze 的分界线在「改」**：两者都禁止新增与删除，差别是 seal **允许修改**已有属性的值，freeze **连改也不许**——正好对应「结构固定但值可变」与「完全只读」两类需求。

```js
"use strict";

// 用 attempt 包一层，观察每步抛出的错误类型而不中断脚本
function attempt(label, action) {
  try {
    action();
  } catch (err) {
    console.log(label, "→", err.constructor.name);
  }
}

const sealed = Object.seal({ a: 1 });
sealed.a = 100; // seal：修改有效
attempt("seal 新增", () => { sealed.b = 2; });
attempt("seal 删除", () => { delete sealed.a; });

const frozen = Object.freeze({ a: 1 });
attempt("freeze 修改", () => { frozen.a = 100; });
console.log("seal 修改后：", sealed.a, "，freeze 后：", frozen.a);
```

```text
seal 新增 → TypeError
seal 删除 → TypeError
freeze 修改 → TypeError
seal 修改后： 100 ，freeze 后： 1
```

> [!CAUTION]
> **注意内容**：三个限制方法都是**浅层**的——freeze 只冻结第一层属性，嵌套对象照样可改（实跑中 shallow.inner.n 被改成了 999）。要真正深度只读，需递归 freeze 所有嵌套对象；另外非严格模式下这些越界操作是**静默失败**，只有严格模式才抛 TypeError，这也是优先模块化开发（自动严格）的理由之一。
