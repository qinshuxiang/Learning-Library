## 二进制数据与文件

### ArrayBuffer

#### ArrayBuffer 与视图

**ArrayBuffer**：是一块**固定长度**的、连续的**二进制内存区域**，是 JavaScript 处理二进制数据的**底层载体**。

- ArrayBuffer 本身**不能直接读写**，只能分配内存。
- 必须通过**视图（View）** 来读写它：TypedArray（类型化数组）或 DataView。

```js
// 分配 16 字节的内存
const buffer = new ArrayBuffer(16);
console.log(buffer.byteLength); // 16

// 通过视图读写
const view = new Uint8Array(buffer);
view[0] = 255;
console.log(view[0]); // 255
```

> 类比理解：ArrayBuffer 是"**一块空地**"，视图是"**测量这块地的工具**"。同一块 ArrayBuffer 可以用不同的视图（8 位、16 位、32 位等）以不同方式解读，这是处理二进制（文件、网络数据、WebGL 等）的基础。



#### ArrayBuffer 的创建与切片

ArrayBuffer 支持创建与切片操作。

- **new ArrayBuffer(length)**：分配指定字节的内存。
- **buffer.slice(start, end)**：切片出一个**新** ArrayBuffer。
- **buffer.byteLength**：字节长度。

```js
const buffer = new ArrayBuffer(8);
console.log(buffer.byteLength); // 8

const sliced = buffer.slice(0, 4);
console.log(sliced.byteLength); // 4（新缓冲区，与原缓冲区独立）
```

> slice 返回的是**新的、独立的** ArrayBuffer，修改切片不影响原缓冲区。ArrayBuffer 的大小在创建时**固定**，之后无法改变（这与普通数组可动态扩容不同）。



#### Node Buffer 的合并与裁切

**Node Buffer**：是 Node 对二进制数据的**专用封装**（底层就是 ArrayBuffer），文件与网络 I/O 默认操作它。最高频的两类操作：Buffer.concat **合并出全新** Buffer；slice/subarray **裁切出共享原内存的视图**。

```js
const buf1 = Buffer.from("Hello, ");
const buf2 = Buffer.from("world");

// concat 合并成新 Buffer
const merged = Buffer.concat([buf1, buf2]);
console.log(merged.toString(), "长度", merged.length);

// slice 裁切：注意它不是拷贝，而是共享内存的视图
const sliced = merged.slice(0, 5);
console.log(sliced.toString());

// 修改裁切片段，会直接影响原 Buffer
sliced[0] = 74; // 字母 J
console.log("改动片段后原 Buffer：", merged.toString());
console.log(merged.subarray(7, 12).toString()); // 现代 API 用 subarray
```

```text
Hello, world 长度 12
Hello
改动片段后原 Buffer： Jello, world
world
```

> [!CAUTION]
> **注意内容**：slice 与 subarray 裁出的是**视图**——修改片段会同步改到原 Buffer（实跑中把首字节改成 J 后，原串变成了 Jello）。需要独立副本时，用 Buffer.from(buf) 或 TypedArray 的 slice（它是唯一会复制的切片方法）。



### TypedArray

#### TypedArray 的种类

**TypedArray（类型化数组）**：是一组**视图**类型，用**固定类型**读写 ArrayBuffer，每个元素占固定字节数。

常见的 TypedArray 类型：

- **Uint8Array**：无符号 8 位整数（1 字节）。
- **Int8Array**：有符号 8 位整数。
- **Uint16Array** / **Int16Array**：16 位整数（2 字节）。
- **Uint32Array** / **Int32Array**：32 位整数（4 字节）。
- **Float32Array** / **Float64Array**：浮点数。

```js
const u8 = new Uint8Array([1, 2, 3]);
console.log(u8.length);   // 3
console.log(u8[0]);       // 1

const f32 = new Float32Array([1.5, 2.5]);
console.log(f32[0]);      // 1.5
```

> TypedArray 相比普通数组：**元素类型固定、内存连续、性能更高**，适合大量数值运算（图形、音频、科学计算）。命名规律是"类型 + 位数 + Array"，如 Uint8Array 是"无符号 8 位整数数组"。



#### TypedArray 的使用与字节序

TypedArray 支持数组式操作，但需理解**字节序（Endianness）**。

- 支持下标访问、length、迭代、部分数组方法（map、forEach 等）。
- **字节序**：多字节数值在内存中的存储顺序，分**大端（Big-Endian）** 与**小端（Little-Endian）**。

```js
const u8 = new Uint8Array([1, 2, 3, 4]);
console.log(u8.map((x) => x * 2)); // [2, 4, 6, 8]（有 map）

// 字节序：16 位整数 0x0102 在内存中的两种存储
const buf = new ArrayBuffer(2);
const view = new Uint16Array(buf);
view[0] = 0x0102;
// 小端（x86 常见）：低字节在前 → [0x02, 0x01]
// 大端：高字节在前 → [0x01, 0x02]
```

> 字节序是多字节数据的存储顺序问题：**小端**把低位字节放前面（x86 平台默认），**大端**把高位字节放前面。TypedArray 使用**平台默认字节序**，若需指定字节序，要用 DataView（见下一节）。



### DataView

#### DataView 的使用

**DataView**：是更灵活的视图，可以**指定字节序**地读写任意类型的数据，而不受平台字节序影响。

- **new DataView(buffer)**：在 ArrayBuffer 上创建。
- 通过 setInt8、getUint16、setFloat32 等方法读写，可指定 littleEndian。

```js
const buffer = new ArrayBuffer(8);
const view = new DataView(buffer);

view.setUint16(0, 0x0102, false); // 大端写入
console.log(view.getUint16(0, false)); // 0x0102（258）

view.setUint16(0, 0x0102, true);  // 小端写入
console.log(view.getUint16(0, true));  // 0x0102（258）
```

> DataView 与 TypedArray 的区别：TypedArray 使用**平台默认字节序**、适合**同类型连续数据**；DataView 可**显式指定字节序**、适合**混合类型的结构化二进制数据**（如解析文件头、网络协议）。



#### DataView 字节序实跑

**DataView 的字节序控制**：每个读写方法的最后一个参数 littleEndian 决定多字节数据的字节排列——传 false（默认）按**大端**存取，传 true 按**小端**存取，且**与运行平台无关**，这正是它强于 TypedArray 的地方。

```js
const buffer = new ArrayBuffer(4);
const view = new DataView(buffer);

view.setUint16(0, 0x1234, false); // 大端写入
console.log("大端存储：", Array.from(new Uint8Array(buffer)));

view.setUint16(0, 0x1234, true); // 小端写入
console.log("小端存储：", Array.from(new Uint8Array(buffer)));

// 读文件头：PNG 魔数按大端解读
const png = new Uint8Array([0x89, 0x50, 0x4e, 0x47, 0x0d, 0x0a, 0x1a, 0x0a]);
const dv = new DataView(png.buffer);
console.log("PNG 头按大端读 32 位：0x" + dv.getUint32(0, false).toString(16));
```

```text
大端存储： [ 18, 52, 0, 0 ]
小端存储： [ 52, 18, 0, 0 ]
PNG 头按大端读 32 位：0x89504e47
```

> 文件格式（如 PNG 魔数 0x89504E47）与网络协议普遍采用**大端**（网络字节序），而 x86/ARM 的内存布局是**小端**——跨平台解析时永远用 DataView 显式指定字节序，不依赖 TypedArray 的平台默认序，否则同一份二进制在不同机器上会读出不同结果。



#### 实战：解析自定义二进制协议头

**定长头 + 变长载荷**：是自定义二进制协议的通用骨架——头部按字段偏移写入魔数、版本与载荷长度，解码侧先校验魔数、再按长度字段切出载荷。DataView 的按偏移读写正好与这套流程一一对应。

协议约定：前 4 字节为魔数 MYPR（用于识别帧类型），第 5～6 字节为版本号（大端），第 7～8 字节为载荷长度（大端），其余为载荷内容。

```js
const MAGIC = [0x4d, 0x59, 0x50, 0x52]; // "MYPR" 的 ASCII

// 编码侧：魔数 + 版本 + 长度 + 载荷，多字节字段统一大端
function encode(version, payload) {
  const payloadBytes = new TextEncoder().encode(payload);
  const frame = new ArrayBuffer(8 + payloadBytes.length);
  const view = new DataView(frame);
  MAGIC.forEach((byte, i) => view.setUint8(i, byte)); // 0～3：魔数
  view.setUint16(4, version, false);                  // 4～5：版本（大端）
  view.setUint16(6, payloadBytes.length, false);      // 6～7：载荷长度（大端）
  new Uint8Array(frame, 8).set(payloadBytes);         // 8 起：载荷
  return frame;
}

// 解码侧：先校验魔数与长度，再按长度拆包
function decode(frame) {
  const view = new DataView(frame);
  const magic = Array.from(new Uint8Array(frame, 0, 4));
  if (magic.join() !== MAGIC.join()) throw new Error("魔数不匹配，不是合法帧");
  const length = view.getUint16(6, false);
  if (length > frame.byteLength - 8) throw new Error("载荷长度越界");
  const payload = new TextDecoder().decode(new Uint8Array(frame, 8, length));
  return { version: view.getUint16(4, false), length, payload };
}

const frame = encode(2, "hello 协议");
console.log("帧总长：", frame.byteLength, "字节");
console.log("原始字节：", Array.from(new Uint8Array(frame)).join(" "));
const decoded = decode(frame);
console.log("版本：", decoded.version, "载荷长度：", decoded.length);
console.log("载荷：", decoded.payload);
try {
  decode(new TextEncoder().encode("NOT-MYPR").buffer);
} catch (err) {
  console.log("异常帧：", err.message);
}
```

```text
帧总长： 20 字节
原始字节： 77 89 80 82 0 2 0 12 104 101 108 108 111 32 229 141 143 232 174 174
版本： 2 载荷长度： 12
载荷： hello 协议
异常帧： 魔数不匹配，不是合法帧
```

> [!IMPORTANT]
> **重要内容**：解码侧的**防御性校验**是协议解析的必做项——先验魔数（快速拦截非法数据）、再验长度（防止越界读取）。真实网络流中帧还可能被分片截断，需按「长度字段」做攒包与半包处理，思路一致：先读定长头，再按头里的长度取载荷。



### Blob 与 File

#### Blob 对象

**Blob（Binary Large Object）**：表示**不可变的二进制数据块**，常用于处理文件、图片、下载等。

- **new Blob(parts, options)**：创建 Blob，parts 是数据源数组。
- **blob.size**：字节大小。
- **blob.type**：MIME 类型。

```js
const blob = new Blob(["Hello, world"], { type: "text/plain" });
console.log(blob.size); // 12
console.log(blob.type); // "text/plain"
```

> Blob 是处理**原始二进制**的通用对象，File 继承自 Blob。它常用于：生成下载文件、URL.createObjectURL 预览图片、FormData 上传等场景。



#### File 与 FileList

**File**：是 Blob 的子类，代表**用户选择的文件**，额外携带文件名等信息。**FileList**：是文件集合（如 input 的 files）。

```html
<input type="file" id="fileInput" multiple>
```

```js
const input = document.querySelector("#fileInput");

input.addEventListener("change", () => {
  const files = input.files;        // FileList
  console.log(files.length);        // 文件个数

  const file = files[0];            // File
  console.log(file.name);           // 文件名
  console.log(file.size);           // 文件大小
  console.log(file.type);           // MIME 类型
});
```

> File 相比 Blob 多了 **name（文件名）、lastModified（修改时间）** 等属性。input.files 返回的 FileList 是类数组，可用 Array.from 或索引访问，常用于文件上传、图片预览。



#### FileReader

**FileReader**：用于**异步读取** Blob/File 的内容，支持多种格式。

- **readAsText(blob)**：读取为文本。
- **readAsDataURL(blob)**：读取为 base64 DataURL（常用于图片预览）。
- **readAsArrayBuffer(blob)**：读取为 ArrayBuffer。

```js
const file = input.files[0];
const reader = new FileReader();

reader.onload = function (e) {
  console.log(e.target.result); // 读取结果
};

reader.readAsDataURL(file); // 读取为 DataURL，用于预览
```

> FileReader 是**异步**的（onload 回调接收结果）。readAsDataURL 把文件转成 base64 字符串，可直接赋给 img 元素的 src 属性做**本地图片预览**，是最常用的图片预览方案。



#### Blob 的现代 Promise 读取方法

现代浏览器为 Blob/File 提供了**基于 Promise** 的读取方法，比 FileReader 的事件回调更简洁，是 FileReader 的主流替代。

- **blob.text()**：将内容解析为 **UTF-8** 文本字符串（固定 UTF-8，不可指定其他编码）。
- **blob.arrayBuffer()**：将内容读取为 ArrayBuffer，便于后续二进制处理。
- **blob.stream()**：返回 ReadableStream，适合流式读取大文件（配合 TextDecoder）。

```js
const file = input.files[0];

// 读取文本（现代方式，比 FileReader 简洁）
const text = await file.text();
console.log(text);

// 读取二进制
const buffer = await file.arrayBuffer();
console.log(buffer.byteLength);
```

> 何时仍用 FileReader？三种情况：需要**进度事件**（progress 可做进度条）、需要**非 UTF-8 编码**（readAsText(file, "ISO-8859-1")）、需要 **base64 DataURL**（readAsDataURL）。除此之外的简单文本/二进制读取，现代代码优先用 blob.text()/blob.arrayBuffer()。若用 await 读取，FileReader 也可用 Promise 包装，但 Blob 原生方法更省事。



#### Blob URL 与文件下载

**URL.createObjectURL(blob)**：为 Blob/File 创建一个**临时的 URL**，可用于预览或下载。

```js
// 图片预览
const blob = file; // File 也是 Blob
const url = URL.createObjectURL(blob);
img.src = url;

// 触发下载
function download(content, filename) {
  const blob = new Blob([content]);
  const url = URL.createObjectURL(blob);
  const a = document.createElement("a");
  a.href = url;
  a.download = filename;
  a.click();
  URL.revokeObjectURL(url); // 释放
}

download("文件内容", "example.txt");
```

> [!CAUTION]
> **注意内容**：两个要点：一是 URL.createObjectURL 创建的 URL 用完后应调用 **URL.revokeObjectURL** 释放内存；二是它生成的 URL 是 blob: 开头的临时地址，比 base64 DataURL **更省内存**，适合大文件。



#### Base64 编码与解码

**Base64**：是一种用 64 个字符表示二进制数据的**编码方式**，用于在文本中传输二进制。

- **btoa(str)**：字符串 → Base64 编码。
- **atob(str)**：Base64 → 字符串解码。

```js
const encoded = btoa("hello");
console.log(encoded); // "aGVsbG8="

const decoded = atob(encoded);
console.log(decoded); // "hello"
```

> [!CAUTION]
> **注意内容**：btoa/atob 只能处理 **ASCII 字符**，处理中文需先转码：btoa(unescape(encodeURIComponent("中文")))。Base64 比二进制**体积大 1/3**，但能在纯文本环境（URL、JSON、HTML）中安全传输二进制，是 DataURL、图片内联的基础。



#### 文本编解码：TextEncoder 与 TextDecoder

**TextEncoder** 与 **TextDecoder** 是处理**字符串与字节相互转换**的现代标准 API，是 Base64 转码中文时"手动 unescape"写法的正规替代。

- **TextEncoder**：把**字符串编码为字节**（Uint8Array）。**只支持 UTF-8** 编码，无其他编码选项。
- **TextDecoder**：把**字节解码为字符串**，可指定编码（默认 UTF-8），常与 arrayBuffer()/stream() 配合读取文件。

```js
// 字符串 → UTF-8 字节
const encoder = new TextEncoder();
const bytes = encoder.encode("中文");
console.log(bytes); // Uint8Array(6) [228, 184, 173, 230, 150, 135]

// 字节 → 字符串
const decoder = new TextDecoder(); // 默认 UTF-8
console.log(decoder.decode(bytes)); // "中文"

// 处理分段/流式数据的解码（最后一帧传 { stream: true } 表示还有后续）
const chunk1 = decoder.decode(part1, { stream: true });
const rest = decoder.decode(part2);
```

> 有了 TextEncoder/TextDecoder，Base64 处理中文可写成更清晰的形式：btoa(String.fromCharCode(...new TextEncoder().encode("中文"))) 编码，new TextDecoder().decode(Uint8Array.from(atob(encoded), (c) => c.charCodeAt(0))) 解码——语义直白、无需依赖 unescape（已废弃）。TextDecoder 的另一常见场景是读取非 UTF-8 文件（如 new TextDecoder("GBK") 解码中文 GBK 文件），这是 readAsText 之外更灵活的选择。



#### Blob 与 ArrayBuffer 的互转

**Blob 与 ArrayBuffer 的互转**：方向一，构造 Blob 时传入 ArrayBuffer 或 TypedArray，把内存数据**包成**可传输的 Blob；方向二，用 blob.arrayBuffer() 把 Blob **读回** ArrayBuffer。二者分工明确：ArrayBuffer 负责**内存中的运算**，Blob 负责**文件与传输**。

```js
const text = "二进制互转示例";

// ArrayBuffer（TypedArray）→ Blob
const bytes = new TextEncoder().encode(text);
const blob = new Blob([bytes], { type: "text/plain" });
console.log("Blob 大小：", blob.size, "类型：", blob.type);

// Blob → ArrayBuffer
const restored = await blob.arrayBuffer();
console.log("解码回文本：", new TextDecoder().decode(restored));
```

```text
Blob 大小： 21 类型： text/plain
解码回文本： 二进制互转示例
```

> 完整链路常见形态：fetch 响应得到 Blob → arrayBuffer() → TypedArray 加工 → 再包回 Blob 上传或下载，互转是这条链路的衔接点。注意 Blob 按字节计数（21 字节是每个汉字占 3 字节 UTF-8 所致）而非字符数；blob.text() 则相当于 arrayBuffer() 加 TextDecoder 的快捷方式。
