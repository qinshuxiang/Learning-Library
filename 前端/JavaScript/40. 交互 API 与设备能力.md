## 交互 API 与设备能力

### 表单约束校验

#### validity 状态族与校验机制

**表单约束校验（constraint validation）**：是浏览器根据 input 元素上的 HTML 属性自动判定输入是否合法的内置机制，判定结果集中挂在元素的 validity 属性上。

- **required 与 valueMissing**：声明必填后值为空时，validity.valueMissing 为 true。
- **type 与 typeMismatch**：email、url 等类型格式不符时，validity.typeMismatch 为 true。
- **pattern 与 patternMismatch**：pattern 属性写正则字面量，不匹配时 validity.patternMismatch 为 true。
- **min、max、step 与范围类标志**：数值越界对应 rangeUnderflow、rangeOverflow，步进不符对应 stepMismatch。
- **minlength、maxlength 与长度类标志**：长度不足对应 tooShort，超出对应 tooLong。
- **valid**：以上标志全部为 false 时，validity.valid 为 true。

pattern 属性底层就是 JS 正则：匹配逻辑可以在 node 里等价复现。

```js
// 等价复现 pattern="/^[A-Za-z]\w{5,17}$/" 的校验行为
const pattern = /^[A-Za-z]\w{5,17}$/;
console.log("abc123 ->", pattern.test("abc123"));
console.log("123abc ->", pattern.test("123abc"));
console.log("ab1 ->", pattern.test("ab1"));
console.log("aB_123 ->", pattern.test("aB_123"));
```

```text
abc123 -> true
123abc -> false
ab1 -> false
aB_123 -> true
```

> pattern 匹配时始终按整串匹配处理，正则不必也不能手写首尾锚点；状态族只描述「哪条约束没过」，不负责提示文案，提示由 reportValidity 或自定义 UI 输出。



#### checkValidity、reportValidity 与 setCustomValidity

**校验触发方法**：checkValidity 静默判定，reportValidity 判定并把错误气泡交给用户，setCustomValidity 写入自定义错误。

- **checkValidity()**：返回 boolean，只判定不弹提示，触发 invalid 事件。
- **reportValidity()**：返回 boolean，判定后在首个非法控件上显示浏览器错误气泡。
- **setCustomValidity(message: string)**：传入非空字符串即把 customError 置为 true 并让控件视为非法，传入空字符串清除自定义错误。

```js
// 浏览器环境运行，输出为预期行为
const email = document.querySelector("#email");
const agree = document.querySelector("#agree");

function validate() {
  if (!email.checkValidity()) {
    console.log("静默判定:", email.validity.typeMismatch); // true
  }
  email.setCustomValidity("邮箱必须使用公司域名");
  console.log("自定义错误后:", email.validity.customError); // true
  email.setCustomValidity("");
  console.log("清除后:", email.reportValidity()); // true，气泡消失
}

agree.addEventListener("change", () => {
  agree.setCustomValidity(agree.checked ? "" : "须先勾选协议");
  agree.reportValidity(); // 未勾选时立即弹出提示
});
```

> setCustomValidity 写入后必须记得清空：只要非空消息还在，控件会一直被判定为非法，表单永远提交不出去，这是该 API 最高频的踩坑点。



#### novalidate 与手动接管

**novalidate**：是 form 元素的属性，声明后浏览器跳过提交时的整体验证，把校验时机交给脚本。

```html
<form id="signup" novalidate>
  <input id="phone" type="tel" pattern="1\d{10}" required />
  <button type="submit">提交</button>
</form>
```

```js
// 浏览器环境运行，输出为预期行为
const form = document.querySelector("#signup");
console.log(form.noValidate); // true

form.addEventListener("submit", (event) => {
  event.preventDefault(); // 接管提交
  if (!form.reportValidity()) return; // 逐个显示浏览器气泡
  console.log("本地校验通过，自行决定是否发送请求"); // 交给业务逻辑
});
```

> novalidate 只关掉「提交时自动拦截」这一扇门，控件上的约束属性和 validity 状态族依然全部生效，因此接管后仍应以 reportValidity 或逐项检查作为统一入口。



### 剪贴板

#### 异步剪贴板读写与权限

**异步剪贴板 API**：是通过 navigator.clipboard 暴露的 Promise 风格读写接口，读操作受权限系统约束。

- **writeText(text: string): Promise&lt;void&gt;**：把文本写入系统剪贴板，写文本通常在用户手势内直接放行。
- **readText(): Promise&lt;string&gt;**：读取系统剪贴板文本，需要剪贴板读权限，页面对话框会先向用户请求授权。
- **权限查询**：navigator.permissions.query({ name: "clipboard-read" }) 返回 state 为 granted、denied 或 prompt 的权限状态对象。
- **旧式同步方案**：document.execCommand("copy") 配合临时选区实现复制，兼容老浏览器，新代码只作为回退手段。

```js
// 浏览器环境运行，输出为预期行为
async function copyEvidence(raw) {
  try {
    await navigator.clipboard.writeText(raw);
    console.log("已复制"); // 写入成功
  } catch (err) {
    console.log("写入被拒绝:", err.name); // NotAllowedError 等
  }
}

async function pasteEvidence() {
  const status = await navigator.permissions.query({ name: "clipboard-read" });
  console.log("读权限状态:", status.state); // granted / denied / prompt
  if (status.state === "granted") {
    console.log("剪贴板内容:", await navigator.clipboard.readText()); // 当前文本
  }
}
```

> 剪贴板 API 只在安全上下文（HTTPS 或 localhost）可用，readText 属于敏感能力，页面失焦或权限被拒时会直接抛异常，调用处必须接住 Promise 的失败分支。



### 拖放

#### 拖放事件链

**拖放**：是把源元素标记为可拖之后，由一组 drag 系事件串成的原生交互链，落点是否放行由事件处理者决定。

- **draggable 属性**：源元素加上 draggable="true" 才可被拖，链接与图片默认可拖。
- **dragstart**：在源元素上触发，事件对象携带 dataTransfer，是放入数据的唯一时机。
- **dragenter 与 dragover**：进入和悬停在潜在落点时触发，落点必须在 dragover 里调用 preventDefault 才允许放置。
- **drop**：在放行的落点上触发，此时才能读出 dataTransfer 里的数据。
- **dragend**：拖放结束在源元素上触发，无论成功与否都收尾。

```html
<div id="card" draggable="true">证据卡片</div>
<div id="bin">取证箱</div>
```

```js
// 浏览器环境运行，输出为预期行为
const card = document.querySelector("#card");
const bin = document.querySelector("#bin");

card.addEventListener("dragstart", (event) => {
  event.dataTransfer.setData("text/plain", event.target.id);
});

bin.addEventListener("dragover", (event) => {
  event.preventDefault(); // 不写这行，drop 永远不会触发
});

bin.addEventListener("drop", (event) => {
  event.preventDefault();
  console.log("拖入的源:", event.dataTransfer.getData("text/plain")); // card
});
```

> 拖放链最常见的事故是漏写 dragover 的 preventDefault：浏览器默认不允许在任何元素上放置，落点不显式放行，drop 事件一次都不会触发。



#### dataTransfer 数据传递

**dataTransfer**：是拖放事件的随行数据载体，在 dragstart 写入、在 drop 读出，同时控制拖放视觉反馈。

- **setData(format: string, data: string)**：按 MIME 类型写入数据，常用 text/plain 与 text/html。
- **getData(format: string): string**：按类型读出数据，仅在 drop 事件里可读，其他阶段出于安全只给空串。
- **effectAllowed 与 dropEffect**：前者在源上声明允许的效果，后者在落点上声明实际效果，取值为 copy、move、link 或 none。

```js
// 浏览器环境运行，输出为预期行为
card.addEventListener("dragstart", (event) => {
  event.dataTransfer.setData("text/plain", "纯文本摘要");
  event.dataTransfer.setData("text/html", "<b>带格式摘要</b>");
  event.dataTransfer.effectAllowed = "copy";
});

bin.addEventListener("dragover", (event) => {
  event.preventDefault();
  event.dataTransfer.dropEffect = "copy"; // 光标随效果变化
});
```

> getData 在 dragover 阶段拿不到内容是刻意的安全设计：页面不能窥探用户正在拖什么，只有在用户真正放置后数据才对落点可见，跨页拖拽同样受此约束。



### 全屏与画面捕获

#### 全屏 API 与指针锁定

**全屏 API**：是把指定元素及其子树铺满整个屏幕的接口，入口是 Element.requestFullscreen。

- **requestFullscreen(): Promise&lt;void&gt;**：请求让元素进入全屏，必须由用户手势触发，成功后 document.fullscreenElement 指向该元素。
- **exitFullscreen(): Promise&lt;void&gt;**：由 document 调用退出全屏，状态变化伴随 fullscreenchange 事件。
- **指针锁定（Pointer Lock）**：element.requestPointerLock() 隐藏光标并把指针移动量持续喂给 mousemove 事件，游戏与画板常用，一句话理解即「收编光标」。
- **画面捕获**：navigator.mediaDevices.getDisplayMedia() 让用户选择一块屏幕或窗口并返回媒体流，属于录屏能力的入口。

```js
// 浏览器环境运行，输出为预期行为
const stage = document.querySelector("#stage");

async function enterStage() {
  await stage.requestFullscreen(); // 必须在点击等手势内调用
  console.log("全屏元素:", document.fullscreenElement === stage); // true
}

document.addEventListener("fullscreenchange", () => {
  console.log("全屏状态:", Boolean(document.fullscreenElement)); // 进入为 true
});
```

> requestFullscreen 的 Promise 在被用户或权限策略拒绝时进入拒绝态，不做 catch 会在控制台留下未处理异常；全屏期间除当前页面外所有界面元素都被遮蔽，因此浏览器强制绑定用户手势。



### 通知与定位

#### 桌面通知

**Notification API**：是向操作系统级通知中心发送消息的接口，使用前必须先走一次显式授权。

- **Notification.requestPermission(): Promise&lt;NotificationPermission&gt;**：弹出授权询问，返回 granted、denied 或 default。
- **new Notification(title: string, options?: NotificationOptions)**：发出通知，options 常用 body、icon、tag。
- **tag 去重**：相同 tag 的通知会替换而不是堆叠，适合进度类消息。
- **onclick 等回调**：通知可挂点击、关闭回调，点击后通常调用 window.focus 把用户带回页面。

```js
// 浏览器环境运行，输出为预期行为
async function askNotify() {
  const permission = await Notification.requestPermission();
  console.log("授权结果:", permission); // granted / denied / default
  if (permission === "granted") {
    const n = new Notification("取证完成", {
      body: "镜像文件校验通过",
      tag: "evidence-job-1",
    });
    n.onclick = () => {
      window.focus(); // 点击通知回到页面
      n.close();
    };
  }
}
```

> 授权结果由用户掌握且难以挽回：denied 后浏览器一般不再二次询问，页面只能在 UI 上引导用户去浏览器设置手动放行，代码侧不要反复弹请求。



#### 地理位置定位

**Geolocation API**：是通过 navigator.geolocation 获取设备经纬度的接口，读取一次用 getCurrentPosition，持续跟踪用 watchPosition。

- **getCurrentPosition(success, error?, options?)**：成功回调拿到 coords（含 latitude、longitude、accuracy）与 timestamp，失败回调拿到错误码。
- **options**：enableHighAccuracy 要求高精度、timeout 设毫秒上限、maximumAge 允许多旧的缓存结果。
- **watchPosition(success, error?, options?): number**：位置变化时反复回调，返回监听 id，用 clearWatch(id) 停止跟踪。

```js
// 浏览器环境运行，输出为预期行为
navigator.geolocation.getCurrentPosition(
  (pos) => {
    console.log("纬度:", pos.coords.latitude); // 如 31.2304
    console.log("精度(米):", pos.coords.accuracy); // 如 30
  },
  (err) => {
    console.log("失败码:", err.code); // 1 拒绝授权，2 不可用，3 超时
  },
  { enableHighAccuracy: true, timeout: 5000, maximumAge: 0 }
);
```

> 地理定位同样只在安全上下文开放，且精度、可否伪造都不由页面控制：取证场景里把坐标当线索而不是证据，系统代理、虚拟定位都会污染原始值。



### 输入进阶

#### Pointer 事件统一鼠标与触摸

**Pointer 事件**：是把鼠标、触摸、笔统一成一套事件的输入模型，每种输入都携带 pointerId 与 pointerType。

- **pointerdown、pointermove、pointerup、pointercancel**：分别对应按下、移动、抬起、被系统打断，命名与鼠标事件对齐。
- **pointerType**：取值为 mouse、touch 或 pen，用于在同一套逻辑里区分设备。
- **setPointerCapture(pointerId: number)**：把后续事件重定向到当前元素，即使指针滑出元素边界也持续接收，拖拽实现的关键一环。

```js
// 浏览器环境运行，输出为预期行为
const pad = document.querySelector("#pad");

pad.addEventListener("pointerdown", (event) => {
  pad.setPointerCapture(event.pointerId); // 滑出元素也不丢事件
  console.log("输入设备:", event.pointerType); // mouse / touch / pen
});

pad.addEventListener("pointermove", (event) => {
  console.log("坐标:", event.clientX, event.clientY); // 持续输出
});

pad.addEventListener("pointerup", (event) => {
  pad.releasePointerCapture(event.pointerId); // 配对释放
});
```

> Pointer 事件没有替代掉 touch 系事件的全部场景：iOS 上的部分手势行为仍依赖 touch 事件，混用时注意同一手势不要同时挂两套监听，否则双触发。



#### passive 监听器与滚动性能

**passive 监听器**：是在注册时声明「我不会调用 preventDefault」的监听器，浏览器因此可以不等回调结束就执行滚动。

- **注册方式**：addEventListener(type, listener, { passive: true })，第三个参数用对象形式，可同时配 capture。
- **适用事件**：touchstart、touchmove、wheel 这类高频滚动相关事件收益最大。
- **默认行为**：在 window 与 document 上，浏览器已把部分触摸滚动事件的 passive 默认为 true，显式写出来是防依赖错乱。

```js
// 浏览器环境运行，输出为预期行为
function onScrollTrace(event) {
  console.log("滚动轨迹采样:", event.clientY); // 高频触发
}

// 滚动跟踪只观察不拦截，声明 passive 让滚动零延迟
window.addEventListener("touchmove", onScrollTrace, { passive: true });

// 确实要阻止滚动时，绝不能再声明 passive
document.querySelector("#dialog").addEventListener(
  "touchmove",
  (event) => event.preventDefault(), // 阻止弹层内滚动穿透
  { passive: false }
);
```

> 在 passive 监听器里调用 preventDefault 不报错但完全无效，控制台会给出警告；反过来的代价更大——把触摸滚动事件注册成非 passive 会让整页滚动等待回调执行，滚动掉帧往往就出在这里。
