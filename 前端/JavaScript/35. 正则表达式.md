## 正则表达式

### 创建正则表达式

#### 字面量与构造函数

**正则表达式**：用于描述字符串匹配规则的对象，JS 提供字面量与构造函数两种创建方式。

```js
const re1 = /\d{3}/;          // 字面量：编译期确定
const re2 = new RegExp("\\d{3}"); // 构造函数：字符串需双重转义
const re3 = new RegExp("abc", "i"); // 第二个参数传标志

console.log(re1.test("abc123")); // true
console.log(re2.test("abc123")); // true
console.log(re3.test("Hello"));  // true
```

```text
true
true
true
```

> 字面量适合模式固定不变的场景；构造函数适合模式在运行期拼出来的场景，如按用户输入动态生成。构造函数收字符串时反斜杠要写两遍，这是新手最常见的转义错误。



#### 常用元字符

**元字符**：在正则里有特殊含义的字符，直接写会按特殊语义匹配。

```js
console.log(/a.c/.test("abc"));  // true（. 匹配任意单字符）
console.log(/\d+/.test("123"));  // true（\d 数字，+ 一个及以上）
console.log(/\w+/.test("a_1"));  // true（\w 字母数字下划线）
console.log(/\s/.test("a b"));   // true（\s 空白字符）
console.log(/^h/.test("hello")); // true（^ 行首锚点）
console.log(/o$/.test("hello")); // true（$ 行尾锚点）
console.log(/a\.c/.test("a.c")); // true（\. 转义后的句点）
```

```text
true
true
true
true
true
true
true
```

> 大写与 小写互为反义：\D 是非数字，\W 是非单词字符，\S 是非空白。句点、星号、加号、问号、方括号、圆括号、反斜杠这些元字符要按字面匹配时必须加反斜杠转义。



#### 字符类与量词

**字符类**：用方括号列出一组候选字符，匹配其中任意一个；**量词**：限定前一项出现的次数。

```js
console.log(/[aeiou]/.test("cat"));        // true
console.log(/[^0-9]/.test("123a"));        // true（^ 在方括号内表示取反）
console.log(/[a-z0-9]/i.test("F8"));       // true（范围连写）
console.log(/colou?r/.test("color"));      // true（? 0 次或 1 次）
console.log(/\d{4}/.test("2026"));         // true（恰好 4 次）
console.log(/\d{2,4}/.test("12345"));      // true（2 到 4 次）
console.log(/\d{2,}/.test("123456"));      // true（2 次以上）
console.log(/go*d/.test("gd"));            // true（* 0 次及以上）
console.log(/go+d/.test("gd"));            // false（+ 至少 1 次）
```

```text
true
true
true
true
true
true
true
true
false
```

> 量词默认作用于紧邻的前一个字符或分组，不是整个表达式。匹配连续多字符时用分组包起来，如 (ab)+ 匹配 abab。



#### 贪婪与懒惰

**贪婪匹配**：量词默认尽可能多地匹配；在量词后追加问号变为**懒惰匹配**，尽可能少地匹配。

```js
console.log(/a+/.exec("aaaa")[0]);  // aaaa（贪婪：吞满）
console.log(/a+?/.exec("aaaa")[0]); // a（懒惰：拿一个就停）

const html = "<div>标题</div>";
console.log(/<.+>/.exec(html)[0]);    // <div>标题</div>
console.log(/<.+?>/.exec(html)[0]);   // <div>
```

```text
aaaa
a
<div>标题</div>
<div>
```

> 从一段 HTML 里提取单个标签时，贪婪模式会把闭合尖括号也吞进去，得到整串结果，这是解析类需求写错的高发点。提取到最近的结束符用懒惰匹配。



### 分组与断言

#### 捕获组与反向引用

**捕获组**：用圆括号包住子模式，匹配成功后可单独取出；**反向引用**：在正则内部用反斜杠加序号引用已捕获的内容。

```js
const re = /(\d{4})-(\d{2})-(\d{2})/;
const m = re.exec("今天 2026-09-23 发布");

console.log(m[0]); // 完整匹配
console.log(m[1]); // 第 1 组
console.log(m[2]); // 第 2 组
console.log(m[3]); // 第 3 组
console.log(/(\w)\1/.test("aab")); // true（\1 引用第 1 组）
```

```text
2026-09-23
2026
09
23
true
```

> 只想分组、不想捕获时，在圆括号开头写问号加冒号，即非捕获组 (?:...)。捕获组会占序号并消耗回溯资源，纯分组用途一律用非捕获组。



#### 命名捕获组

**命名捕获组**：给捕获组起名字，通过 groups 属性按名取值，序号不用数。

```js
const m = "2026-09-23".match(/(?<year>\d{4})-(?<month>\d{2})-(?<day>\d{2})/);

console.log(m.groups.year);
console.log(m.groups.month);
console.log(m.groups.day);
```

```text
2026
09
23
```

> 组名用尖括号包裹写在圆括号开头。replace 的替换串里按名引用写作 美元符号加尖括号包组名，比数序号可靠得多。组名不能重复，且必须以字母开头。



#### 先行与后行断言

**断言**：只判断位置或前后文是否成立，本身不消耗字符。四种写法：正先行 (?=...)、负先行 (?!...)、正后行 (?<=...)、负后行 (?<!...)。

```js
console.log(/\d+(?=元)/.exec("苹果5元一斤")[0]);       // 5（后面是元的数字）
console.log(/\d+(?!元)/.exec("苹果5元3斤")[0]);        // 3（后面不是元的数字）
console.log(/(?<=￥)\d+/.exec("单价￥8")[0]);           // 8（前面是￥的数字）
console.log(/(?<!￥)\d+/.exec("数量8")[0]);             // 8（前面不是￥的数字）
```

```text
5
3
8
8
```

> 断言里的内容不会出现在匹配结果里，这是它与捕获组的本质区别：捕获组取「内容」，断言只定「位置」。提取金额、校验前缀这类需求用断言能省掉后续截取。



### 标志位

#### 六个常用标志

**标志位**：写在正则字面量末尾或构造函数第二个参数里，改变整体的匹配行为。

```js
console.log(/hello/i.test("HELLO"));         // true（i 忽略大小写）
console.log("a1b2".match(/\d/g));            // ["1","2"]（g 全局）
console.log(/^b/m.test("ab\nbc"));           // true（m 每行按首尾锚定）
console.log(/foo.bar/s.test("foo\nbar"));    // true（s 让 . 匹配换行）
console.log(/\u{1F600}/u.test("\u{1F600}")); // true（u 按 Unicode 码位解析）

const sticky = /\d+/y;
sticky.lastIndex = 3;
console.log(sticky.exec("ab12cd34")[0]);     // 2（y 从 lastIndex 粘性起匹配）
```

```text
true
[ '1', '2' ]
true
true
true
2
```

> s 标志解决的是句点不匹配换行的老问题，多行文本整段匹配时几乎必加。u 标志让正则按码位处理，写四个字节的字符量词时必须加，否则大括号会被当作字面字符。



### RegExp 实例方法

#### test 与 exec

**test()**：返回布尔值，判断是否匹配；**exec()**：返回匹配详情数组或 null，是拿分组信息的基本方法。

```js
console.log(/\d+/.test("abc123"));  // true
const m = /(\d+)-(\d+)/.exec("编号 2026-09");
console.log(m[0], m[1], m[2], m.index);
console.log(/xyz/.exec("abc"));     // null
```

```text
true
2026-09 2026 09 3
null
```

> exec 返回的数组第 0 项是完整匹配，1 起是各组，index 属性记录起始位置。需要位置信息或分组信息时用 exec，只做存在性判断用 test。



#### lastIndex 与全局标志陷阱

**lastIndex**：带 g 或 y 标志的正则对象会在实例上记住下次匹配的起始位置，跨调用残留状态。

```js
const re = /a/g;
console.log(re.test("aa"), re.lastIndex); // true 1
console.log(re.test("aa"), re.lastIndex); // true 2
console.log(re.test("aa"), re.lastIndex); // false 0（到头复位）
console.log(re.test("aa"), re.lastIndex); // true 1（重新开始）
```

```text
true 1
true 2
false 0
true 1
```

> 同一个带 g 的正则反复调 test，结果会在 true 与 false 之间跳动，这是共享正则对象做循环校验时最经典的 bug。要么每次用字面量新建正则，要么匹配前手动把 lastIndex 置 0，要么干脆不用 g 标志。



### 字符串上的正则方法

#### match 与 matchAll

**match()**：带 g 标志返回全部匹配串数组，不带 g 返回与 exec 同构的详情对象；**matchAll()**：返回迭代器，每项都带分组与位置信息。

```js
const s = "aaa bbb ccc";

console.log(s.match(/b+/g));
console.log(s.match(/(b+)/)[1]); // 第 1 组

for (const m of s.matchAll(/(\w)\1/g)) {
  console.log(m[0], m[1], m.index);
}
```

```text
[ 'bbb' ]
b
aa a 0
bb b 4
cc c 8
```

> 带不带 g 的 match 返回结构完全不同，前者丢掉分组信息，这是两个易混点。需要逐项分组与位置时用 matchAll，它不依赖 lastIndex 状态，也不会残留上次调用的位置。



#### replace 与 replaceAll

**replace()**：替换第一个匹配（带 g 标志替换全部）；**replaceAll()**：字面意思替换全部，等价于带 g 的 replace。替换串里支持多个特殊序列。

```js
console.log("2026-09-23".replace(/(\d{4})-(\d{2})-(\d{2})/, "$1 年 $2 月 $3 日"));
console.log("abc123".replace(/\d+/, "[$&]")); // $& 是本次完整匹配
console.log("a.b.c".replace(/\./g, "-"));
console.log("2026-09-23".replace(/(?<y>\d{4})-(?<m>\d{2})/, "<$<m>"));
```

```text
2026 年 09 月 23 日
abc[123]
a-b-c
<09
```

> 替换串里的特殊序列有：美元符号加序号取分组、美元符加取位符 $& 取完整匹配、美元符号加反引号取匹配左侧文本、美元符号加单引号取右侧文本、美元符号加尖括号取命名组。替换串本身含美元符号时注意会被解析，必要时写成两个美元符号转义。



#### search 与 split

**search()**：返回首个匹配的索引，找不到返回 -1；**split()**：按正则切分字符串。

```js
console.log("  hello  world  ".trim().split(/\s+/));
console.log("2026-09-23".split("-"));
console.log("abc123".search(/\d/));
```

```text
[ 'hello', 'world' ]
[ '2026', '09', '23' ]
3
```

> split 按连续空白切分比按单空格切分健壮得多，处理用户粘贴的文本、日志行时先 trim 再用空白字符类切，是标准写法。



### 实战模式

#### 校验与脱敏

**校验**：用锚点把模式钉满整串，判断整串是否符合格式；**脱敏**：用捕获组保留首尾，把中间段替换为星号。

```js
const phone = "13812345678";

console.log(/^1[3-9]\d{9}$/.test(phone));
console.log(phone.replace(/^(\d{3})\d{4}(\d{4})$/, "$1****$2"));
console.log(/^[\w.%+-]+@[\w.-]+\.[a-z]{2,}$/i.test("user.name@qq.com"));
console.log("6222021234567890".replace(/^(\d{4})\d+(\d{4})$/, "$1********$2"));
```

```text
true
138****5678
true
6222********7890
```

> 校验类正则必须首尾都加锚点，否则只校验了片段。正则适合做格式校验，不适合做语义校验：格式合法的号码不一定真实存在，涉及真实性的判断要走服务端或专用接口。



#### 日志关键字提取

**日志提取**：用分组配合 matchAll 从批量文本里抽出结构化字段，是网安日志分析的基本功。

```js
const logs = [
  "2026-09-23 08:01:12 [WARN] login failed ip=10.0.0.8 user=admin",
  "2026-09-23 08:01:15 [ERROR] forbidden ip=172.16.3.44 user=root",
];

const pattern = /(?<date>\d{4}-\d{2}-\d{2}) (?<time>[\d:]+) \[(?<level>\w+)\] .*ip=(?<ip>[\d.]+)/;

for (const line of logs) {
  const { date, time, level, ip } = line.match(pattern).groups;
  console.log(level, ip, date, time);
}
```

```text
WARN 10.0.0.8 2026-09-23 08:01:12
ERROR 172.16.3.44 2026-09-23 08:01:15
```

> 固定格式日志优先用命名捕获组抽字段，可读性和可维护性都远好于数序号。字段之间用 .* 桥接时注意贪婪问题，必要处换成 [^ 界定符 ] 或懒惰量词。



### 常见陷阱

#### 元字符漏转义

**元字符漏转义**：把句点、加号这类元字符直接写进模式，导致匹配范围意外扩大。

```js
console.log("a.b.c".replace(".", "-"));    // 字符串参数：只换第一个字面句点
console.log("a.b.c".replace(/\./g, "-")); // 正则写法：全部句点都替换
console.log("价格+税".replace(/价+税/, "!")); // false 语义：+ 是量词
```

```text
a-b.c
a-b-c
```

> 用户输入要拼进正则时，元字符必须先整体转义，标准做法是用 replace(/[.*+?^${}()|[\]\\]/g, "\\$&") 处理后再 new RegExp。不转义轻则匹配错、重则抛 SyntaxError。



#### 灾难性回溯

**灾难性回溯**：嵌套量词让引擎在匹配失败时穷举大量路径，输入稍长就卡死。

```js
// 危险写法：嵌套量词 (a+)+ 遇到不匹配的结尾会指数级回溯
const dangerous = /^(a+)+$/;
const input = "a".repeat(30) + "!";

const start = Date.now();
console.log(dangerous.test(input));
console.log("耗时约", Date.now() - start, "毫秒");
```

```text
false
耗时约 773 毫秒
```

> 30 个 a 就接近一秒，字符数翻倍耗时指数级增长，攻击者可借构造输入拖垮正则所在进程（正则拒绝服务）。嵌套量词 (x+)+、(x*)* 这类结构要么改写为 [^ 界定符 ] + 量词的平铺形式，要么在服务端限制输入长度。

> [!WARNING]
> **警告内容**：把用户可控文本直接拼入正则模式或用于未加防护的服务端匹配，同时存在元字符注入与回溯拒绝服务两类风险。凡正则来源含用户输入，必须先转义元字符，服务端匹配必须限制输入长度。



#### 非法模式与运行期报错

**非法模式**：括号不配对、量词无对象等错误在字面量创建时直接抛出，构造函数形式则在运行期抛出。

```js
try {
  new RegExp("(");
} catch (e) {
  console.log(e instanceof SyntaxError, e.message);
}
```

```text
true Invalid regular expression: /(/: Unterminated group
```

> 动态拼模式前先 try-catch 包一层 new RegExp，把用户输入导致的语法错误拦在业务逻辑外。字面量形式的语法错误在脚本解析阶段就会抛出，整个文件无法执行，动态场景务必用构造函数并自行兜底。
