## Web Components

### 组件化与自定义元素

#### 为什么需要组件化

**界面重复是规模的天敌**：同一个徽章、卡片、上传框在页面里复制十份，样式一改就要改十处，行为一调就要调十遍。

- 复制粘贴的代价：结构雷同但细节漂移，回归成本随页面数量线性增长。
- 框架组件的代价：React、Vue 组件离开对应运行时无法独立存在，跨技术栈复用困难。
- 原生组件的诉求：一份结构加行为，任何页面、任何框架直接使用，浏览器原生渲染无需额外依赖。
- Web Components 的答案：自定义元素、Shadow DOM、模板与插槽三项浏览器标准，共同构成与框架无关的组件方案。

> Web Components 不是要替代框架，而是提供框架之下的底座：设计系统、嵌入式小部件、微前端隔离层都建立在它之上。



#### 自定义元素的定义

**自定义元素**：用 customElements.define 注册、以普通 HTML 标签形式使用的元素类型，标签名必须含连字符。

- 注册签名：customElements.define(name, constructor, options)，name 是含连字符的小写标签名，constructor 是元素类，options 可选，传 extends 指定所扩展的内置元素。
- 连字符约束：ip-card、log-line 合法，ipcard、ip_card 非法，避免与未来新增的原生标签冲突。
- 全局注册表：customElements.get(name) 查询已注册的类，customElements.whenDefined(name) 返回 Promise，等待元素注册完成。
- 升级机制：元素注册晚于页面解析时，文档里已存在的同名标签会在注册瞬间自动升级为元素实例。

```html
<!-- 注册前写在页面里不会报错，静默等待升级 -->
<ip-card ip="203.0.113.7"></ip-card>
```

```js
class IpCard extends HTMLElement {
  connectedCallback() {
    // 升级或插入文档时触发，这里渲染内容
    this.textContent = "IP: " + this.getAttribute("ip");
  }
}

customElements.define("ip-card", IpCard);
// 页面里所有 <ip-card ip="203.0.113.7"> 都会渲染出 IP: 203.0.113.7
```

> 名字冲突是真实风险：两个脚本注册同一个标签名，后注册者抛出 NotSupportedError。组件库惯用品牌前缀区分命名空间，例如 sl-、wc-。



#### 类继承 HTMLElement

**HTMLElement 子类**：每个自定义元素对应一个继承 HTMLElement 的类，浏览器负责实例化并在恰当时机调用其生命周期方法。

- 继承对象的选择：普通元素继承 HTMLElement；想给内置标签附加行为时继承对应接口，如 HTMLButtonElement。
- 构造函数纪律：构造函数第一行必须是 super()，且不要在其中读取属性或渲染，元素此刻可能尚未挂载。
- 状态归属：类字段与实例属性保存内部状态，attribute 保存外部配置，二者职责分明。

```js
class ScanButton extends HTMLButtonElement {
  constructor() {
    super(); // 必须首先调用
    this.count = 0; // 内部状态，外部不可配置
  }
}

customElements.define(
  "scan-button",
  ScanButton,
  { extends: "button" }, // 声明为内置元素 button 的扩展
);
// 使用时写 <button is="scan-button">发起扫描</button>
```

> 扩展内置元素（customized built-in）在 Safari 长期未实现，追求跨浏览器一致性的组件应优先使用继承 HTMLElement 的自治自定义元素。



#### 属性监听白名单

**observedAttributes**：静态 getter，返回需要监听的属性名数组，只有名单内的属性变化才会触发 attributeChangedCallback。

- 声明形式：static get observedAttributes()，返回字符串数组，白名单机制避免了任意属性变化带来的性能损耗。
- 回调签名：attributeChangedCallback(name, oldValue, newValue)，属性新增、修改、删除都会触发，删除时 newValue 为 null。
- 时序保证：元素升级瞬间，已存在于标签上的属性会先逐个触发一次回调，再触发 connectedCallback。
- 配套读取：回调内通常用 this.getAttribute(name) 或直接用 newValue 更新内部状态。

```js
class LogLine extends HTMLElement {
  static get observedAttributes() {
    return ["level", "message"];
  }

  attributeChangedCallback(name, oldValue, newValue) {
    // 页面里已有 <log-line level="warn"> 时，升级瞬间会先触发两次本回调
    console.log(name, oldValue, newValue);
  }
}

customElements.define("log-line", LogLine);

const line = document.createElement("log-line");

line.setAttribute("level", "warn");
// 输出: level null warn
line.setAttribute("level", "error");
// 输出: level warn error
```

> 白名单漏写是最常见的事故源：observedAttributes 里忘写的属性，改了也不会触发回调且不报错。属性名一律小写，HTML 解析会吞掉大小写差异。



### Shadow DOM 封装

#### attachShadow 与模式

**Shadow DOM**：附着在宿主元素内部的一棵独立渲染树，与主文档树互不干扰，是样式与结构隔离的根基。

- 开启签名：element.attachShadow(init)，init 必传 mode，可选 delegatesFocus、slotAssignment、clonable。
- 模式差异：mode 为 open 时，外部可用 element.shadowRoot 拿到影子根；为 closed 时 shadowRoot 返回 null，树内部细节对外不可见。
- 返回值：attachShadow 返回 ShadowRoot 实例，之后所有内部结构都挂在它下面。
- 单次限制：每个元素只能 attachShadow 一次，重复调用抛出 InvalidStateError。

```js
class IpBadge extends HTMLElement {
  constructor() {
    super();
    const root = this.attachShadow({ mode: "open" });
    // 外部可通过 this.shadowRoot 访问 root；若 mode 为 "closed" 则返回 null
    root.innerHTML = `
      <style>p { color: crimson; }</style>
      <p>${this.getAttribute("ip") ?? "unknown"}</p>
    `;
  }
}

customElements.define("ip-badge", IpBadge);
```

> closed 模式不是安全边界：测试工具与调试器仍有途径触达内部节点，它只防止业务代码误操作。组件库多用 open，换取可测试性与 DevTools 可见性。



#### 样式隔离

**样式隔离**：Shadow DOM 内部的选择器只命中影子树，外部样式表也打不进来，双向天然屏蔽。

- 内部样式：写在影子根里的 style 标签或构造的样式表，只作用于影子树内部节点。
- 外部屏蔽：页面的 div p 这类选择器无法命中影子树里的 p，组件不会被页面样式污染。
- 继承例外：color、font 等可继承属性仍会从宿主穿透进来，需要固定外观时在内部显式声明。
- 代价：隔离意味着组件内部不能偷用页面样式，公共样式需显式传入或用下文的穿透手段。

```html
<!-- 页面样式打不进影子树 -->
<style>
  p { color: green; } /* 只影响主文档里的 p */
</style>

<ip-badge ip="10.0.0.1"></ip-badge>
<!-- ip-badge 内部的 p 仍是组件样式定义的颜色 -->
```

> 隔离是双刃剑：省去了 BEM 前缀与选择器锦标赛，但组件因此完全自负样式。凡是依赖页面全局样式表重置的写法，在影子树内一律失效。



#### :host 与 ::slotted

**:host**：影子树内部指向宿主元素自身的伪类，是组件内外样式衔接的桥梁。

- :host 用法：在影子树样式里写 :host { display: block; }，控制组件作为标签的整体表现。
- 状态匹配：:host(.active)、:host([disabled]) 按宿主的类与属性条件匹配，实现外观切换。
- ::slotted 用法：::slotted(selector) 命中被分发到插槽里的、来自主文档的子元素，只支持一层选择器。
- 优先级规则：主文档对宿主元素的样式优先级高于影子树里的 :host 声明，外部覆盖内建默认值。

```js
class IpBadge extends HTMLElement {
  constructor() {
    super();
    this.attachShadow({ mode: "open" }).innerHTML = `
      <style>
        :host { display: inline-block; border: 1px solid #999; }
        :host(.alert) { border-color: crimson; }
        ::slotted(span) { font-weight: bold; }
      </style>
      <p><slot></slot></p>
    `;
  }
}

customElements.define("ip-badge", IpBadge);
// 页面里写 <ip-badge class="alert"><span>10.0.0.1</span></ip-badge>
// 边框变红，span 文字加粗
```

> ::slotted 的选择器只到直接分发元素这一层，::slotted(span b) 这种后代写法无效。深度定制子节点样式时，改用 CSS 自定义属性穿透。



### 模板与插槽

#### template 标签

**template 元素**：声明一段惰性 HTML 的容器，内容不会渲染、不执行脚本、不进文档树，直到被克隆使用。

- 惰性解析：template 内部内容存放于 content 文档片段，加载时不请求图片、不执行脚本、不参与布局。
- 克隆使用：template.content.cloneNode(true) 得到独立副本，appendChild 到任意位置即激活。
- 组件结合：影子根里放 template 是组织组件内部结构的惯用法，比拼接 innerHTML 字符串更可读。
- 复用语义：一个 template 可反复克隆，克隆体之间互不影响，等价于一份轻量蓝图。

```html
<template id="line-tpl">
  <p class="line"><span class="ts"></span><b class="msg"></b></p>
</template>

<script>
  const tpl = document.getElementById("line-tpl");

  function renderLine(ts, msg, host) {
    const node = tpl.content.cloneNode(true);
    node.querySelector(".ts").textContent = ts;
    node.querySelector(".msg").textContent = msg;
    host.appendChild(node); // 此刻片段才真正渲染
  }
</script>
```

> template 内容只在克隆后才运行，天然规避了字符串拼 HTML 的注入面扩大问题，但插入的外部数据仍应走 textContent 赋值，不要拼进模板字符串。



#### slot 与具名插槽

**slot 元素**：影子树中的占位符，把主文档里写在组件标签内部的子节点分发进来，是内容自定义的入口。

- 默认插槽：不带 name 的 slot 收纳一切未被指名的子节点，等价于匿名出口。
- 具名插槽：slot name="title" 对应主文档里 slot="title" 属性的子节点，实现多点分发。
- 后备内容：slot 标签内部的子节点是占位默认值，调用方未提供内容时展示。
- 回退顺序：分发内容存在则覆盖后备内容，slot 本身不出现在最终渲染树，只承担搬运职责。

```html
<ip-card ip="203.0.113.7">
  <span slot="title">境外扫描源</span>
  <span>属地：示例网络</span>
</ip-card>
```

```js
class IpCard extends HTMLElement {
  constructor() {
    super();
    this.attachShadow({ mode: "open" }).innerHTML = `
      <style>
        .head { font-weight: bold; }
      </style>
      <div class="head">
        <slot name="title">IP 查询</slot>
      </div>
      <p>${this.getAttribute("ip") ?? "unknown"}</p>
      <div><slot></slot></div>
    `;
  }
}

customElements.define("ip-card", IpCard);
// title 插槽渲染「境外扫描源」，默认插槽渲染「属地：示例网络」，
// 若调用方什么都没写则显示后备内容「IP 查询」
```

> 分发是引用不是移动：主文档节点仍在原处、事件仍在主文档作用域触发。给 slot 加 click 监听监听不到分发内容，要监听 slotchange 或在宿主上委托。



### 生命周期回调

#### connectedCallback 挂载时机

**connectedCallback**：元素每次被插入文档时调用，是读取环境、请求数据、启动监听的正确位置。

- 触发次数：同一元素反复插拔会触发多次，需要幂等处理，常配 this.isConnected 判断。
- 可用性保证：此刻元素已在文档中，可以安全读取 getBoundingClientRect、发起网络请求。
- 升级联动：元素先于注册出现在文档时，升级瞬间也会触发本回调，属性可能尚未就绪。
- 清理对偶：此处注册的全局监听、定时器、订阅，是 disconnectedCallback 的清理对象。

```js
class IpCard extends HTMLElement {
  connectedCallback() {
    // 每次插入文档触发一次
    this.timer = setInterval(() => this.refresh(), 60000);
    this.refresh();
  }

  refresh() {
    // 发起 IP 查询请求并更新视图
  }
}
```

> 不要在构造函数里做挂载期的事：构造时元素可能不在文档里，读布局全是零值。凡是依赖文档环境的初始化一律放进 connectedCallback。



#### disconnectedCallback 卸载时机

**disconnectedCallback**：元素从文档移除时调用，负责释放资源，是防止内存泄漏的最后防线。

- 触发语义：从文档树摘除即触发，包括被 innerHTML 重写冲掉、被移入文档片段暂存的情形。
- 清理清单：clearInterval、removeEventListener、断开 Observer、取消未完成的请求、释放订阅。
- 重新挂载：元素随后被插回文档时 connectedCallback 再次触发，因此清理与重建必须对称成对。
- 移动误判：appendChild 把元素移到另一位置，先触发 disconnected 再触发 connected，不要把卸载当成销毁。

```js
class IpCard extends HTMLElement {
  disconnectedCallback() {
    // 清理 connectedCallback 注册的定时器
    clearInterval(this.timer);
    this.controller?.abort(); // 取消未完成的 fetch
  }
}
```

> 最典型的泄漏是把监听挂在 document 或 window 上却只清理自身：组件节点被回收了，全局引用仍把它拽着。清理时清单要覆盖所有外部挂载点。



#### adoptedCallback 移动时机

**adoptedCallback**：元素被 adoptNode 或 appendChild 跨文档移动时调用，普通页面开发几乎遇不到。

- 触发条件：仅当元素在两个文档之间移动才触发，同一文档内的移动走的是断开再连接的路径。
- 典型场景：iframe 之间搬运节点、把元素从模板文档移入主文档、构建离线 DOM 再上线。
- 参数缺失：回调无参数，新旧文档需要靠 document 指针在移动前后自行记录。
- 处理原则：多数组件留空即可，仅当行为依赖 document 上下文（如样式表、事件目标）时才需响应。

```js
class IpCard extends HTMLElement {
  adoptedCallback() {
    // 元素被移动到另一个文档时触发
    console.log("moved to", this.ownerDocument.title);
  }
}
```

> 检查 adoptedCallback 是否为空实现即可，为它写业务逻辑前先确认真的存在跨文档搬运需求，否则是过度设计。



#### attributeChangedCallback 触发细节

**attributeChangedCallback**：白名单属性发生增删改时触发，是外部配置进入组件内部的统一通道。

- 触发顺序：升级期的完整时序（先逐个触发本回调、再触发 connectedCallback）见前文「属性监听」一节的时序保证。
- 参数语义：name 是属性名，oldValue 与 newValue 是前后值，首次设置时 oldValue 为 null，删除时 newValue 为 null。
- 幂等要求：setAttribute 写入相同值不触发，回调里做的是状态同步而非事件通知。
- 反射取舍：回调内把属性写回内部节点或 style 是常见反射，但要避免回调里再改自身白名单属性造成死循环。

```js
class LogLine extends HTMLElement {
  static get observedAttributes() {
    return ["level"];
  }

  attributeChangedCallback(name, oldValue, newValue) {
    // 升级时输出: level null warn
    // 再次设置输出: level warn error
    this.style.setProperty("--level-color", this.colorOf(newValue));
  }

  colorOf(level) {
    return { info: "#888", warn: "#c90", error: "#c33" }[level] ?? "#888";
  }
}
```

> 回调里防自触发是硬要求：attributeChangedCallback 中 setAttribute 同名属性会再次进入本回调。确需回写时先比较值是否变化，或把回写目标移出白名单。



### 样式与主题

#### CSS 自定义属性穿透

**CSS 自定义属性**：即 CSS 变量，沿继承链传递且无视 Shadow DOM 隔离，是外部主题进入组件内部的标准通道。

- 穿透原理：变量值随元素继承向下传递，影子树内 inherited 到的变量照常可用，隔离规则对继承不生效。
- 组件侧定义：内部样式写 var(--accent, #345) 并给默认值，调用方在组件标签或祖先上覆盖变量即可换肤。
- 批量主题：在页面根定义一组语义变量，组件统一消费，实现整站主题一键切换。
- 命名纪律：组件对外暴露的变量用前缀区分归属，如 ip-card-accent，避免与页面变量撞名。

```js
class IpCard extends HTMLElement {
  constructor() {
    super();
    this.attachShadow({ mode: "open" }).innerHTML = `
      <style>
        .ip { color: var(--ip-card-accent, #345); }
      </style>
      <p class="ip">${this.getAttribute("ip") ?? "unknown"}</p>
    `;
  }
}

customElements.define("ip-card", IpCard);
```

```html
<!-- 调用方覆盖变量即可换肤，无需触碰组件内部 -->
<div style="--ip-card-accent: crimson;">
  <ip-card ip="10.0.0.1"></ip-card>
</div>
```

> 自定义属性穿透仅限继承链：设置在兄弟元素或子树外的变量传不进组件。需要组件内外双向同步样式时，穿透变量优先于 ::slotted。



#### 可构造样式表

**可构造样式表**：用 CSSStyleSheet 对象在脚本里构建样式，再经 adoptedStyleSheets 共享给多个影子根，一份样式多处复用。

- 构建流程：new CSSStyleSheet() 创建实例，replaceSync(text) 或 replace(text) 写入规则，replace 支持异步与 @import。
- 挂载签名：shadowRoot.adoptedStyleSheets = [sheet]，数组赋值整体替换，可同时挂多张表。
- 共享收益：同一 sheet 实例挂到任意多个影子根，规则只解析一次，内存与解析开销共享。
- 动态能力：通过 insertRule、deleteRule 在运行时增删规则，配合 replace 做主题热更新。

```js
const sheet = new CSSStyleSheet();

sheet.replaceSync(`
  .ip { font-family: monospace; color: var(--ip-card-accent, #345); }
`);

class IpCard extends HTMLElement {
  constructor() {
    super();
    const root = this.attachShadow({ mode: "open" });
    root.adoptedStyleSheets = [sheet]; // 多个组件实例共享同一张表
    root.innerHTML = `<p class="ip">${this.getAttribute("ip") ?? "unknown"}</p>`;
  }
}

customElements.define("ip-card", IpCard);
```

> replaceSync 会整体替换原有规则，追加样式要 insertRule 而不是再次 replace。document.adoptedStyleSheets 也能挂载，用于无影子树的页面级动态样式。



### 实战小部件

#### IP 查询卡片组件

**完整组件示范**：把自定义元素、Shadow DOM、模板插槽、属性监听与穿透变量串成一个可直接使用的 IP 查询卡片。

```html
<ip-card ip="203.0.113.7" query>
  <span slot="title">境外扫描源</span>
</ip-card>
```

```js
const cardSheet = new CSSStyleSheet();

cardSheet.replaceSync(`
  :host { display: block; border: 1px solid var(--ip-card-border, #ccc); border-radius: 6px; }
  header { font-weight: bold; padding: 8px; border-bottom: 1px solid #eee; }
  main { padding: 8px; font-family: monospace; }
  .error { color: crimson; }
`);

class IpCard extends HTMLElement {
  static get observedAttributes() {
    return ["ip"];
  }

  constructor() {
    super();
    const root = this.attachShadow({ mode: "open" });
    root.adoptedStyleSheets = [cardSheet];
    root.innerHTML = `
      <header><slot name="title">IP 查询</slot></header>
      <main>等待查询…</main>
    `;
  }

  attributeChangedCallback(name, oldValue, newValue) {
    // ip 属性变化时自动重新查询
    if (name === "ip" && newValue) this.lookup(newValue);
  }

  connectedCallback() {
    const ip = this.getAttribute("ip");

    if (ip) this.lookup(ip);
  }

  async lookup(ip) {
    const main = this.shadowRoot.querySelector("main");

    try {
      const res = await fetch(`https://ipinfo.io/${ip}/json`);
      const data = await res.json();
      main.textContent = `${data.ip} · ${data.country ?? "未知属地"}`;
    } catch {
      main.textContent = "查询失败";
      main.classList.add("error");
    }
  }
}

customElements.define("ip-card", IpCard);
// 修改 document.querySelector("ip-card").setAttribute("ip", "10.0.0.1")
// 卡片自动重新发起查询并刷新内容
```

> 这一个例子覆盖了本篇主干：属性是接口、生命周期是时机、Shadow DOM 是边界、插槽与变量是缝隙。写组件前先想清楚哪些能力暴露为 attribute、哪些留给 slot 与 CSS 变量。
