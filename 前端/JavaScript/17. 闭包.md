## 闭包

### 高阶函数

#### 函数作为参数和返回值

**高阶函数（Higher-Order Function）**：是**接收函数作为参数、或返回函数**的函数。它是函数式编程的核心，也是闭包的前置概念。

- **函数作为参数**：回调函数。
- **函数作为返回值**：返回另一个函数。

```js
// 函数作为参数
function applyOperation(arr, operation) {
  return arr.map(operation);
}
console.log(applyOperation([1, 2, 3], (x) => x * 2)); // [2, 4, 6]

// 函数作为返回值
function createGreeting(greeting) {
  return function (name) {
    return `${greeting}, ${name}`;
  };
}
const sayHello = createGreeting("Hello");
console.log(sayHello("why")); // "Hello, why"
```

> 高阶函数让函数"**像数据一样传递和组合**"，是实现抽象、复用逻辑的关键。返回函数的 createGreeting 已经涉及了闭包——返回的函数记住了外层的 greeting 变量。



#### 数组中的常见高阶函数

JavaScript 数组内置了大量高阶函数，它们都是"接收函数作参数"的典型。

- **map(fn)**：映射，返回新数组。
- **filter(fn)**：筛选。
- **reduce(fn, init)**：归约。
- **forEach(fn)**：遍历。
- **some(fn) / every(fn)**：判断。

```js
const nums = [1, 2, 3, 4, 5];

const doubled = nums.map((x) => x * 2);        // [2, 4, 6, 8, 10]
const evens = nums.filter((x) => x % 2 === 0); // [2, 4]
const sum = nums.reduce((acc, x) => acc + x, 0); // 15
const hasBig = nums.some((x) => x > 4);        // true
const allSmall = nums.every((x) => x < 10);    // true
```

> 这些内置高阶函数让数组处理从"手写 for 循环"进化为"**声明式描述意图**"，代码更简洁、更易读。掌握它们，是写出地道现代 JavaScript 的必备能力。



### 闭包的理解

#### 闭包的定义

**闭包（Closure）**：是指**函数与其词法作用域的组合**，具体表现为——函数能够**访问其定义位置的外部变量**，即使该函数在别处被调用。

```js
function outer() {
  const message = "我是外部的变量";
  function inner() {
    console.log(message); // 访问外部变量
  }
  return inner;
}

const fn = outer(); // outer 已执行完，但 message 仍被 inner 引用
fn(); // "我是外部的变量"（闭包生效）
```

> 闭包的精髓：outer 执行完本该销毁其变量，但 inner 仍"记住"了 message，因此 message 得以保留。**闭包 = 函数 + 它捕获的外部变量**，是 JavaScript 作用域链机制的必然结果。



#### 高阶函数的执行过程

通过一个完整例子，追踪高阶函数执行时闭包的形成过程。

```js
function makeCounter() {
  let count = 0;
  return function () {
    count++;
    return count;
  };
}

const counter = makeCounter();
console.log(counter()); // 1
console.log(counter()); // 2
console.log(counter()); // 3
```

执行过程：

1. makeCounter() 创建 count 并返回内部函数。
2. 内部函数**捕获了 count**，形成闭包。
3. 每次调用 counter()，都操作**同一个** count。

> 这个例子的关键：count 是 makeCounter 的局部变量，本该在函数返回后销毁，但因被返回的函数引用而**存活**。且多次调用 counter() 操作的是**同一个** count（而非每次新建），这正是"计数器"能累加的原因。



#### 闭包的终极定义

综合来看，闭包可以从多个角度定义。

- **从机制**：函数 + 其词法环境的引用。
- **从现象**：函数能访问定义时外部作用域的变量，即使外部函数已执行完毕。
- **从应用**：让函数"记住"私有状态，实现数据封装。

```js
// 闭包实现"私有变量"
function createBankAccount(initialBalance) {
  let balance = initialBalance; // 私有变量，外部无法直接访问
  return {
    deposit(amount) {
      balance += amount;
    },
    getBalance() {
      return balance;
    }
  };
}

const account = createBankAccount(100);
account.deposit(50);
console.log(account.getBalance()); // 150
// console.log(balance); // 报错：balance 是私有的
```

> 终极理解：闭包让函数"**携带状态**"。balance 只能通过返回的方法访问，实现了**数据私有化**——这正是闭包最实用的价值，也是模块化、工厂函数等模式的基础。



### 闭包的内存表现

#### 内存占用的测试案例

闭包会**长期持有**外部变量，理解其内存表现有助于判断内存占用。

```js
function outer() {
  const bigData = new Array(1000000).fill("data"); // 大对象
  return function () {
    console.log(bigData.length);
  };
}

const fn = outer(); // bigData 被闭包持有，一直占内存
// 若 fn 不再使用，应释放引用以回收 bigData
```

> [!CAUTION]
> **注意内容**：闭包的代价：**被捕获的变量不会随外部函数返回而释放**，会一直占用内存直到闭包本身被回收。捕获**大对象**时要留意，用完后应解除对闭包函数的引用（如置 null），让 GC 回收。



#### 闭包引用的 AO 对象属性销毁

闭包引用的对象，其**未被引用的属性**会被正常回收，只有**被引用的部分**保留。

```js
function outer() {
  const a = { big: new Array(1000000) };
  const b = "小数据";
  return function () {
    return b; // 只引用了 b，没引用 a
  };
}

const fn = outer();
// a 未被闭包引用，会被回收；b 被引用，保留
```

> 现代引擎做了优化：闭包只**保留它实际引用的变量**，未被引用的属性/变量会被正常回收（而非"整个作用域都保留"）。因此闭包的内存占用取决于"**闭包到底用了什么**"。



#### 经典循环陷阱与闭包

**经典循环陷阱**：用 var 在 for 循环中创建闭包，所有闭包共享**同一个**循环变量，最终拿到的是循环结束后的值，而非各自的迭代值。

```js
// 陷阱：三个按钮点击都输出 3
for (var i = 0; i < 3; i++) {
  setTimeout(function () {
    console.log(i); // 3 3 3（var 无块级作用域，三个回调共享同一个 i）
  }, 0);
}
```

根因：var 只有函数作用域，循环里的 i 是**唯一一个**变量；当回调真正执行时，循环早已结束，i 已是最终值 3，所有回调都读到它。

三种正确解法：

```js
// 解法一：let 声明（ES6，最推荐）——每轮迭代创建一个新的 i 绑定
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0); // 0 1 2
}

// 解法二：IIFE 立即执行，把 i 作为参数固化进独立作用域
for (var j = 0; j < 3; j++) {
  (function (n) {
    setTimeout(() => console.log(n), 0); // 0 1 2
  })(j);
}

// 解法三：把迭代值传给封装函数
function createLogger(n) {
  return () => console.log(n);
}
for (var k = 0; k < 3; k++) {
  setTimeout(createLogger(k), 0); // 0 1 2
}
```

> 底层机制：let 在 for 循环的**每一轮迭代都新建一个块级词法环境并绑定新的 i**（详见第 17 章"块级作用域的环境创建"），因此每个闭包捕获的是**各自独立**的 i；var 全程只有一个绑定，故所有闭包共享。这个对比是理解闭包与 let 块级作用域价值的经典考题，常以 setTimeout 输出顺序的形式出现。



#### 闭包与内存泄露

闭包虽好用，但**使用不当会导致内存泄漏**，需警惕几个典型场景。

内存泄漏的常见原因：

- **闭包被全局变量长期持有**：闭包一直可达，其捕获的变量无法回收。
- **事件监听未清理**：闭包作为监听器，元素被移除但监听未解绑。
- **定时器未清除**：闭包被定时器引用，定时器不清除则闭包不释放。

```js
// 内存泄漏示例：全局持有闭包
let leak;

function createLeak() {
  const bigData = new Array(1000000);
  leak = function () {
    return bigData; // bigData 被全局 leak 间接持有，永不回收
  };
}
createLeak();
// 若不 leak = null，bigData 一直占内存
```

> [!CAUTION]
> **注意内容**：避免内存泄漏的关键：**及时解除不再需要的引用**——把全局闭包变量置 null、removeEventListener 解绑监听、clearInterval/clearTimeout 清除定时器。闭包本身不是问题，**忘记释放**才是问题。



#### 循环中的闭包：var 与 let 的实跑对比

**循环中的闭包**：循环体内创建的函数会捕获循环变量，用 var 声明时所有闭包共享同一个绑定，用 let 声明时每轮迭代生成独立绑定，node 实跑结果最直观。

```js
// 在 node 中可直接运行：var 版本
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log("var:", i), 0);
}

// let 版本
for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log("let:", j), 0);
}
```

```text
var: 3
var: 3
var: 3
let: 0
let: 1
let: 2
```

- **var 的表现**：连续三行 var: 3——回调真正执行时循环早已结束，唯一的 i 已是 3。
- **let 的表现**：依次输出 0、1、2——每轮迭代为当轮闭包提供独立的 j。
- **验证方式**：把代码存成文件用 node 执行，输出顺序固定，结论可复现。

> [!IMPORTANT]
> **重要内容**：这道题的本质是「闭包捕获的是变量绑定，而不是变量的当下值」。var 全程一个绑定，let 每轮一个绑定；理解了这一点，任何输出顺序题都能现场推导，不必死记答案。



#### 闭包与内存的关系：引用链视角

**闭包与内存的关系**：闭包保留变量并不是把整个作用域复制一份，而是形成一条「闭包函数 → 词法环境 → 被引用变量」的引用链，链上的变量存活，链外的变量照常回收。

```js
function outer() {
  const tag = "保留的变量";
  const unused = "未引用的变量";
  return function () {
    return tag;
  };
}

const getTag = outer();
// 引用链：getTag → 返回的函数对象 → 它的词法环境 → tag
// unused 不在这条链上，引擎可正常回收
console.log(getTag());
```

```text
保留的变量
```

- **链的起点**：只要外部仍持有对闭包函数的引用（如 getTag），链条就一直存在。
- **链的终点**：只有被闭包函数实际引用的变量才挂在链上，unused 不在其中。
- **断链时机**：把 getTag 置为 null，链条断裂，tag 随之恢复可回收状态。

> 理解引用链即可判断「哪些变量会留下来」：从持有闭包函数的变量出发，顺着函数对象走到词法环境，凡是还能被访问到的变量都会存活。至于引擎如何标记与清扫，属于垃圾回收的内部机制，不必在此展开。



#### IIFE 与块级作用域

**IIFE（立即调用函数表达式）**：是「定义后立刻执行」的函数写法，在块级作用域普及之前，它是制造私有作用域的经典手段。

```js
// IIFE：函数作用域把变量关在里面
(function () {
  var secret = "只在这一小段作用域里";
  console.log(secret);
})();

// ES6 之后：块级作用域 + const 达到同样效果
{
  const secret = "块级作用域内的变量";
  console.log(secret);
}
// 两种写法的 secret 在外部都访问不到
```

```text
只在这一小段作用域里
块级作用域内的变量
```

- **共同点**：都为变量划出一层独立作用域，避免污染全局。
- **IIFE 的额外能力**：可接收参数、可返回值，因此还能顺便形成闭包（如循环陷阱中的解法二）。
- **现代写法**：不需要返回值时，优先用块级作用域加 const 或 let。

> IIFE 与块级作用域不是取代关系：IIFE 至今仍用于「一次性初始化、模块封装、把值固化进闭包」等场景，而单纯的变量隔离交给块级作用域更简洁。



#### 闭包的实战应用：模块模式与防抖

**闭包的实战价值**：在真实工程里，闭包最常见的两个落点是模块模式（用闭包封装私有状态）与防抖（用闭包跨多次调用记住定时器）。

```js
// 模块模式：count 藏在闭包里，外部只能通过方法访问
const counterModule = (function () {
  let count = 0;
  return {
    increment() { return ++count; },
    getCount() { return count; }
  };
})();
console.log(counterModule.increment());
console.log(counterModule.getCount());

// 防抖：timer 被闭包持有，多次调用共享同一个定时器
function debounce(fn, delay) {
  let timer = null;
  return function (...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}
const sayHi = debounce((name) => console.log(`你好, ${name}`), 100);
sayHi("A"); // 会被下一次调用取消
sayHi("B"); // 只有这一次真正触发
```

```text
1
1
你好, B
```

- **模块模式**：count 无法从外部直接修改，只能走暴露的方法，形成受控的私有状态。
- **防抖**：timer 在多次调用之间被同一个闭包记住，前一次调用总被后一次取消，A 因此被吞掉。
- **节流同理**：把 timer 换成「上次执行时间」或「待执行标记」，闭包同样承担跨调用记状态的角色。

> [!TIP]
> **建议内容**：识别这类代码时盯住一点——返回的函数用到了外层函数的局部变量，且外层函数返回后这些变量仍需存活，这就是闭包在工程里的典型形态。防抖、节流、once 函数、缓存函数都遵循同一模式。
