## 渲染管线：布局、绘制与合成

### 渲染管线的整体阶段

**渲染管线（rendering pipeline）**：是浏览器把渲染树上的节点与计算样式逐步加工成屏幕上像素的一组有序处理步骤，每一阶段的产物即下一阶段的输入。

本篇描述管线的机制，即每个阶段做什么、输入与输出各是什么；哪些操作会让哪个阶段重做、怎样改写，留给本主题第 8 篇 渲染性能：重排、重绘与合成层优化。

#### 渲染管线是什么与它的产物

**渲染管线**：是一条把「树与样式」变成「像素」的加工线，输入是渲染树及其计算样式，输出是合成完成并写入屏幕的一帧画面。

- 输入：渲染树（render tree）由 DOM 树与 CSSOM 样式树合并而来，只保留需要显示的节点，每个节点带一组计算样式（详见本主题第 6 篇 CSS 解析、样式计算与层叠）。
- 中间产物：布局树、绘制列表、图层树与图块位图，逐阶段产生并向下传递。
- 输出：合成线程与 GPU 把各层位图叠加，得到供显示的一帧完整画面。
- 判定方式：任何一个阶段的产物失效，都会让其后继阶段重做，而前面的阶段仍可复用结果。

```html
<!-- 最小结构：浏览器要从它算出几何，再画出像素 -->
<article class="card">
  <h2 class="card-title">渲染管线</h2>
  <p class="card-text">从样式到像素的有序阶段。</p>
</article>
```

```css
.card {
  padding: 16px;
  border: 1px solid #d0d7de;
  background: #ffffff;
}
```

> 渲染树与布局树不是同一棵树：前者描述显示什么，后者描述盒在哪里、有多大。

**速记**：输入是渲染树与计算样式，输出是一帧位图，中间产物逐阶段向下传递。



#### 阶段的顺序与依赖

**阶段的顺序**：是样式计算、布局、绘制、光栅化与合成依次衔接的固定次序，前一阶段的产物是后一阶段的输入，顺序不能颠倒。

- 样式计算：为每个节点确定最终属性值，产出计算样式。
- 布局：为每个盒计算几何位置与尺寸，产出布局树。
- 绘制：把外观记录成绘制指令，产出绘制列表。
- 光栅化：把绘制指令渲染成像素，产出图块位图。
- 合成：把各层位图按顺序叠加，产出一帧画面。

```text
阶段      产物
样式计算  计算样式：每个节点一组最终属性值
布局      布局树：每个盒的几何框
绘制      绘制列表：按顺序排列的绘制指令
光栅化    图块位图：像素
合成      完整一帧：送入屏幕的画面
```

> 依赖是单向的：几何变了，绘制与光栅化必须重做；只改外观，布局可以跳过。

**速记**：五阶段单向依赖，样式到布局到绘制到光栅化到合成。



#### 阶段的跳过与重用

**阶段的跳过**：是浏览器按变更类型选择从某个阶段开始重跑、其余阶段沿用缓存结果的机制，整条管线并非每次从头执行。

- 只改外观属性：布局产物仍然有效，从绘制阶段开始重跑。
- 改几何属性：布局必须重算，绘制与光栅化随之重做。
- 只改独立层上的 transform 或 opacity：布局与绘制都可沿用，只在合成阶段重算。
- 判断依据：变更是否影响几何、是否影响绘制内容、影响是否局限在独立层内。

```js
// 计算样式随时可读，几何信息要等布局完成后才准确
const card = document.querySelector(".card");
const style = getComputedStyle(card);   // 返回只读的 CSSStyleDeclaration
console.log(style.paddingTop);          // "16px"
console.log(card.offsetWidth);          // 布局完成后可读，如 320
```

> 取值的差异划出三类操作的分野：动几何、动外观、只动合成层，代价依次降低。

**速记**：变更类型决定从哪个阶段重跑，几何一变则后继阶段全部重做。



### 布局：盒模型与几何计算

**布局（layout，旧称回流 reflow）**：是浏览器为渲染树上的每个盒计算几何信息（位置与尺寸）的阶段，产出布局树并交给绘制阶段。

#### 布局树与盒模型

**布局树（layout tree）**：是布局阶段的产物，节点为盒（box），每个盒记录自身在包含块中的位置与尺寸，并保留父子与兄弟关系。

- 节点来源：元素、文本节点与伪元素都会生成盒，不参与布局的节点不入树。
- 盒模型：每个盒由内容区、内边距、边框与外边距组成。
- 尺寸模式：box-sizing 决定宽高作用在内容区还是作用在边框盒上。
- 包含块：绝对定位元素的几何相对于最近的定位祖先计算。

```css
.card {
  width: 320px;
  padding: 16px;
  border: 1px solid #d0d7de;
  box-sizing: border-box;   /* 宽高包含内边距与边框 */
}
```

```js
const card = document.querySelector(".card");
const rect = card.getBoundingClientRect();  // 无参数，返回 top、left、right、bottom、width、height 等字段
console.log(rect.width, rect.height);       // 如 320 98
```

> getBoundingClientRect 返回的坐标相对于视口，滚动与元素变换都会影响结果。

**速记**：布局树由盒组成，每个盒按盒模型与包含块确定几何。



#### 布局的计算过程

**布局计算**：是自根节点向下遍历、再由子盒把尺寸回传父盒的双向求解过程，父级提供约束，子级决定固有尺寸。

- 自上而下：确定包含块宽度与可用空间，百分比与 auto 依赖父级结果。
- 自下而上：子盒内容决定行高与固有尺寸，再向上影响父盒高度。
- 特殊布局：绝对定位、固定定位与浮动元素脱离常规流，单独计算。
- 依赖后果：某个盒的尺寸变化可能改变祖先与兄弟的几何，布局范围往往大于改动点。

```js
// 内容撑开高度：父盒高度由子盒内容决定
const list = document.querySelector(".list");
console.log(list.scrollHeight);   // 内容总高度，含溢出部分
```

```js
// 子盒最小高度变大，父盒高度随之增长
const panel = document.querySelector(".panel");
panel.querySelector(".panel-body").style.minHeight = "120px";
console.log(panel.offsetHeight);   // 父盒高度已按新约束重算
```

> 因为存在上下双向依赖，改动一个深层节点的尺寸可能让整棵子树甚至整棵树上重算。

**速记**：布局是父子双向求解，一个盒的尺寸可能牵动祖先与兄弟。



#### 布局范围与增量布局

**布局范围**：是一次布局需要重算的盒的集合，浏览器尽量把范围限制在失效子树内，无法定位时才扩大到全文档。

- 增量布局：只重算失效的盒及其后代，多数局部改动走这条路径。
- 扩大到全文档：根元素尺寸变化、文档整体可滚动尺寸变化、视口尺寸变化等情形。
- 失效标记：样式变更在树上标记脏位，布局时只处理被标记的节点。
- 代价估计：改动越靠近根、越影响流式排布，需要重算的盒越多。

> 增量布局依赖脏位标记，标记不准确时会退化为更大范围的重算，因此失效信息本身就是布局开销的一部分。

```js
// 改变根元素字号会波及全文，属于典型的全量布局场景
document.documentElement.style.fontSize = "18px";
```

> [!WARNING]
> **警告内容**：在滚动或输入事件的回调里直接修改根容器的尺寸或字号，会让每一帧都触发大范围布局，卡顿会立即显现。

**速记**：布局按脏位做增量重算，无法定位影响范围时退化为全量。



### 绘制：绘制指令与显示列表

**绘制（paint）**：是把计算样式与几何信息转换成绘制指令的阶段，只记录在什么位置画什么，不产生像素。

#### 绘制列表的生成

**绘制列表（display list，也称绘制记录 paint records）**：是绘制阶段的产物，一串有序的绘制指令，每条指令描述一个绘制操作及其位置与样式。

- 指令种类：填充矩形、描边、绘制文本、绘制图片、绘制阴影等。
- 指令内容：样式值被展开成具体的颜色、线宽、字体等参数。
- 坐标系：指令坐标通常相对于所属合成层，而非页面原点。
- 后续用途：光栅化阶段逐条执行指令，把它转成位图。

```js
// 圆角与阴影都会转成绘制指令，属于绘制阶段的工作
const card = document.querySelector(".card");
card.style.borderRadius = "12px";
card.style.boxShadow = "0 2px 8px rgba(0, 0, 0, 0.2)";
```

> 绘制列表是中间表示：它比像素轻得多，可被缓存并交给其他线程执行。

**速记**：绘制列表是一串有序指令，描述位置与样式，不产生像素。



#### 绘制顺序与层叠

**绘制顺序**：是同层内指令的排列规则，由层叠上下文与元素类别决定，后画的覆盖先画的。

- 基本次序：背景与边框在前，其后是浮动与块级内容，最后是行内内容与轮廓。
- 层叠上下文：定位元素与 z-index 决定上下层关系。
- 独立层的影响：跨层覆盖不再由指令顺序决定，而由合成器的层顺序决定。
- 视觉结果：调整绘制顺序等价于调整覆盖关系，影响外观而不影响几何。

```css
.card {
  position: relative;
  z-index: 1;   /* 建立层叠上下文，参与同层内的绘制排序 */
}
```

> 绘制顺序出现错乱时先检查层叠上下文，不必怀疑几何计算。

**速记**：同层内按层叠顺序排列指令，后画的覆盖先画的。



#### 绘制指令的内容与代价

**绘制代价**：是生成并执行绘制指令所需的工作量，取决于绘制面积、指令数量与效果复杂度。

- 面积：被覆盖的图块越多，光栅化要处理的数据越多。
- 数量：浮层、阴影、圆角与渐变会拆出更多指令。
- 效果：滤镜、模糊与半透明叠加需要额外的逐像素运算。
- 缓存：内容不变的层可以复用已生成的位图，避免重复光栅化。

```css
.card:hover {
  /* 滤镜触发逐像素运算，绘制代价高于纯色背景 */
  filter: drop-shadow(0 4px 6px rgba(0, 0, 0, 0.2));
}
```

> 同一视觉目标可以用不同写法达成，指令数量与覆盖面积会因此不同。

**速记**：绘制代价看面积、指令数量与效果复杂度，未变的层可复用位图。



### 光栅化与合成层

**光栅化（raster）与合成（composite）**：是把绘制列表转成像素、再把各层像素组合成一帧画面的两个后继阶段，二者的执行位置已从主线程移到其他线程与 GPU。

#### 光栅化的单位与图块

**光栅化**：是按图块把绘制指令渲染成位图的过程，一个图块是固定像素尺寸的方形区域。

- 图块：页面按层切成若干图块，逐块光栅化，便于按需生成与复用。
- 视口优先：靠近当前视口、即将进入屏幕的图块优先光栅化。
- 分辨率：位图尺寸要匹配屏幕的像素密度，高密度屏需要更大的位图。
- 执行位置：光栅化可以在渲染进程的线程池完成，也可以由 GPU 进程承担。

```js
// 滚动位置决定哪些图块即将可见，也就决定优先光栅化的顺序
window.addEventListener("scroll", () => {
  console.log(window.scrollY);   // 滚动越远，新进入视口的图块越多
}, { passive: true });
```

> 光栅化的关键性质是按需：当前看不见的图块可以推迟，甚至根本不生成。

**速记**：光栅化按图块进行，视口附近优先，位图尺寸跟随屏幕密度。



#### 合成层的概念与图层树

**合成层（compositing layer）**：是可以独立光栅化并独立参与合成的绘制单位，每个层持有自己的绘制列表与位图，并拥有相对页面或相对父层的变换。

- 图层树：合成层按父子关系组成一棵树，父层的变换作用到子层。
- 独立光栅化：层内内容变化只需重新光栅化该层，不必处理其他层。
- 层参数：位图、变换、透明度与裁剪区域由合成器统一管理。
- 合成顺序：合成器按图层树顺序叠加各层位图，得到最终画面。

```css
.moving-card {
  /* 变换让元素可以拥有独立的合成层 */
  transform: translateX(0);
}
```

```js
// 脚本侧只能读到变换声明，实际层信息要借助开发者工具查看
const movingCard = document.querySelector(".moving-card");
console.log(getComputedStyle(movingCard).transform);   // "matrix(1, 0, 0, 1, 0, 0)"
```

> 合成层是性能与内存的权衡单位：层越多越灵活，占用也越大。

**速记**：合成层是独立光栅化与独立合成的单位，按图层树组合出一帧。



#### 独立层的判定条件

**独立层判定**：是浏览器依据元素的属性与用途决定是否为其建立合成层的规则，命中条件的元素会脱离父层单独光栅化。

- 三维变换：含 3D 变换或透视的元素通常获得独立层。
- 显式声明：will-change 与 translateZ 一类提示会被纳入考虑。
- 特定内容：视频与画布等由独立通道上屏的内容自带独立层。
- 动画与滚动：需要独立动画或独立滚动的元素会被提升，以避开主线程。

```css
.promoted {
  will-change: transform;   /* 提前声明，由浏览器决定是否提升 */
}
```

```html
<!-- 视频内容由独立通道上屏，天然占据独立层 -->
<video class="hero-video" src="intro.mp4" controls></video>
```

> [!CAUTION]
> **注意内容**：为大量元素声明 will-change 会建立大量合成层，位图内存与合成开销同步上升，收益可能被抵消。

**速记**：三维变换、显式声明与特定内容会被独立提升，提升数量需要克制。



### 主线程与合成线程与 GPU 的分工

**分工**：是渲染管线各阶段被分配到的执行位置，主线程负责脚本、样式、布局与绘制记录，合成线程与 GPU 负责光栅化与合帧。

#### 主线程的职责

**主线程（main thread）**：是执行 JavaScript、样式计算、布局与绘制记录的唯一线程，渲染管线的前三段在这里完成。

- 脚本：事件处理、数据更新与 DOM 操作都在这里执行。
- 样式与布局：样式重算与几何计算必须在这里同步完成。
- 绘制记录：生成绘制列表，只记录指令，不做像素运算。
- 提交：把绘制列表与图层信息打包交给合成线程，这一步称为提交（commit）。

```js
// 主线程是否空闲，直接决定这些写操作何时生效
const card = document.querySelector(".card");
card.style.transform = "translateY(-4px)";
console.log(card.style.transform);   // "translateY(-4px)"
```

> 主线程一旦被长时间占用，样式与布局就排不上队，页面整体更新随之延后。

**速记**：主线程跑脚本、样式、布局与绘制记录，并把结果提交给合成线程。



#### 合成线程与 GPU 的职责

**合成线程（compositor thread）**：是接收提交结果、组织光栅化与合帧的线程，它不执行脚本，也不做布局。

- 光栅化调度：把需要的图块派发给栅格化任务，可以并行执行。
- 合帧：按图层树顺序把各层位图叠加为完整一帧。
- 变换处理：层的位移、缩放与透明度在合成阶段应用。
- GPU 协作：把合帧指令交给 GPU 进程，由 GPU 完成最终绘制与上屏。

```text
主线程        样式 -> 布局 -> 绘制记录 -> 提交
合成线程      接收提交 -> 调度光栅化 -> 合帧
GPU 进程      执行绘制调用 -> 写入帧缓冲 -> 上屏
```

```js
// 合成线程不执行脚本，脚本里的写操作仍要等主线程
const badge = document.querySelector(".badge");
badge.classList.add("is-visible");   // 类名变化会触发样式重算
```

> 合成线程与主线程并行工作，这是主线程繁忙时动画仍能继续的结构基础。

**速记**：合成线程调度光栅化并合帧，GPU 负责执行绘制调用与上屏。



#### 不经过主线程的合成动画

**合成动画**：是只改变层变换或层透明度的动画，逐帧计算在合成线程完成，不需要主线程参与。

- 可合成属性：transform 与 opacity 是典型的两类。
- 前提条件：元素必须处在可独立处理的合成层上。
- 效果：主线程正在执行较长的脚本时，这类动画仍能维持原有帧率。
- 边界：动画一旦改动布局属性，就必须回到主线程重算，优势随之消失。

```js
// 用合成属性驱动逐帧动画，避免布局与重绘
const card = document.querySelector(".card");
let offsetX = 0;
function updateCardPosition() {
  offsetX = (offsetX + 2) % 240;
  card.style.transform = "translateX(" + offsetX + "px)";
  requestAnimationFrame(updateCardPosition);   // 逐帧调度机制见本主题第 9 篇
}
requestAnimationFrame(updateCardPosition);
```

> [!IMPORTANT]
> **重要内容**：合成动画只在动画属性不触发布局与重绘时才成立；把 transform 换成 left 或 top，动画会重新依赖主线程。

**速记**：transform 与 opacity 动画可在合成线程独立完成，改布局属性则退回主线程。
