## CSS 解析、样式计算与层叠

**样式计算（style computation）**：是浏览器把样式表中的规则与文档元素匹配、按层叠顺序选出声明并换算为具体属性值的过程，产物是每个元素的计算样式。

本篇只回答实现侧的问题：样式表如何变成规则对象、选择器如何在元素上匹配、多个来源的声明如何排序、取值要经过哪些阶段，以及文档变化后哪些元素需要重算。选择器语法、层叠写法与优先级写法属于 前端/CSS 主题，本篇从实现视角描述同一套机制如何运行；样式计算之后的布局、绘制与合成详见本主题第 7 篇 渲染管线：布局、绘制与合成。

### CSSOM 的构建

样式计算的输入是样式规则，而样式规则要先从文本变成可匹配的对象。本模块讨论样式表的来源、解析后对象的结构，以及条件规则如何影响样式表是否参与计算。

#### 样式表的来源与解析入口

**CSSOM（CSS Object Model，CSS 对象模型）**：是把样式表表示为规则树的接口集合，与 DOM 并列，通过 document.styleSheets 暴露。

- 来源：外链样式表、style 元素、脚本插入的样式表，以及元素上的行内样式声明。
- 解析时机：样式表在解析到对应标记时开始解析，不等待整个文档下载完成。
- 与解析的关系：样式表不阻塞 HTML 树构建，阻塞脚本执行与首屏渲染。
- 跨源限制：跨源样式表默认不可读取其规则，读取规则集合会抛出安全错误。

```js
console.log(document.styleSheets.length);             // 2
console.log(document.styleSheets[0].cssRules.length); // 12
```

> 行内样式不是独立样式表，它以声明列表挂在元素上，在层叠中按行内来源参与比较。

**速记**：CSSOM 由文档中的样式表解析而来，通过 document.styleSheets 访问。



#### CSSOM 的节点结构与只读性

**样式规则对象**：是样式表中一条规则的运行时表示，常见类型有样式规则与条件规则，前者包含选择器与声明集合，后者包含条件与嵌套规则。

- 结构：样式规则可读选择器文本与声明集合，单条声明可读属性名、值与重要标记。
- 嵌套：条件规则内部可以继续包含样式规则，形成与样式表书写层级对应的树。
- 修改方式：直接改写规则对象上的属性通常不生效，修改样式表要走 insertRule 与 deleteRule 方法。
- 计算依据：样式计算读取的是解析后的声明集合，不是原始样式表文本。

```js
const sheet = document.styleSheets[0];
const rule = sheet.cssRules[0];
console.log(rule.selectorText);                    // ".card"
console.log(rule.style.getPropertyValue("color")); // "red"
```

> 浏览器不保留样式表的原始文本作为计算依据：注释与格式在解析阶段被丢弃，重复声明的先后次序则在声明列表中保留。

**速记**：CSSOM 是规则树，规则对象以只读方式暴露，修改需走专用方法。



#### 媒体查询与条件样式表

**条件规则（conditional rule）**：是带条件的规则组，条件不满足时其中的声明不参与匹配，最常用的是媒体查询规则。

- 求值时机：媒体查询在样式重算时求值，视口尺寸或设备特征变化会触发重新求值。
- 不参与计算：条件不满足时组内规则不进入候选集合，匹配成本随之下降。
- 外链样式表上的条件：链接元素上的媒体属性不匹配时该样式表不参与计算，但浏览器仍可能下载它。
- 常见条件：视口宽度、分辨率、颜色偏好、输出媒介等。
- 媒介切换：输出媒介变化时条件规则整组重新求值，打印样式通常在进入打印时才参与计算。

```css
@media (min-width: 768px) {
  .card {
    display: grid;
  }
}
```

> [!NOTE]
> **提醒内容**：媒体查询的求值结果属于样式失效的触发源之一，视口连续变化会带来连续的条件求值开销。

**速记**：条件不满足时组内规则不参与匹配，视口变化会触发重新求值。



### 选择器匹配与样式计算

每个元素最终生效的声明，来自所有规则中命中它的那部分。本模块先给出样式计算的整体步骤，再讨论匹配的方向、候选集合的组织方式，以及匹配成本由哪些因素决定。

#### 样式计算的整体流程

**样式计算流程**：是浏览器对每个元素依次完成的匹配、层叠与继承、取值换算三步，前一步的输出是后一步的输入。

- 匹配：收集命中该元素的所有规则中的声明，形成候选集合。
- 层叠与继承：从候选集合中按层叠规则选出胜出声明，没有命中任何声明时按继承或初始值补位。
- 取值换算：把选出的值换算为计算值，供后续的布局阶段使用。
- 执行时机：渲染前的样式重算阶段统一执行；脚本读取计算样式时也可能触发提前结算。

```js
// 读取计算样式即触发一次结算，随后返回当前结果
const card = document.body.firstElementChild;
console.log(getComputedStyle(card).color); // "rgb(51, 65, 85)"
```

> 三步的划分用于说明取值来源；实现上匹配与层叠会合并执行，不会为同一个元素重复遍历候选规则。

**速记**：样式计算依次完成匹配、层叠与继承、取值换算，渲染前统一执行。



#### 选择器匹配的方向与匹配引擎

**选择器匹配（selector matching）**：是判断一条规则的选择器是否命中某个元素的过程，实现上从选择器最右侧的关键选择器开始，逐层向左验证祖先与兄弟关系。

- 匹配方向：先判断元素是否满足最右段，再向左检查组合器施加的约束。
- 索引组织：浏览器按最右段的 id、类名或标签名把规则分桶，把候选规则限定在可能命中的集合内。
- 快速否决：祖先约束借助布隆过滤器一类的结构快速排除，避免逐层回溯。
- 去重：同一元素命中多条规则时，命中结果按规则在样式表中的顺序合并，同一选择器不重复计算。
- 组合器代价：后代组合器需要向祖先方向逐层验证，子代与相邻兄弟组合器的验证范围更小。

```css
/* 最右段是 .title，匹配时先按类名缩小候选规则范围 */
.card .title {
  font-weight: 600;
}
```

> 从右向左匹配的效果是：最右段的区分度越高，候选集合越小，整条选择器的匹配成本越低。

**速记**：匹配从最右段开始向左验证，规则按最右段的 id、类名与标签名分桶。



#### 匹配成本与影响范围

**匹配成本**：是样式计算为每个元素查找并验证候选规则所付出的时间，与规则数量、元素数量、选择器复杂度共同相关。

- 规模效应：规则数与元素数的组合决定最坏情况下的验证次数。
- 选择器类型差异：属性选择器与伪类需要读取属性或计算状态，成本高于标签选择器与类选择器。
- 结构伪类：位置相关的伪类依赖兄弟次序，实现上通过缓存或预计算位置信息降低重复计算。
- 优化方向：收窄最右段的作用范围、减少通配符、避免过深的后代组合，都能直接降低匹配成本。

```js
const card = document.body.firstElementChild;
console.log(card.matches(".card"));        // true
console.log(card.matches(".card .title")); // false
```

> 选择器的书写技巧属于 前端/CSS 主题，本条只说明同一选择器在浏览器实现中的成本构成。

**速记**：匹配成本由规则数、元素数与最右段的区分度共同决定。



#### 匹配阶段的复用与缓存

**样式复用**：是浏览器对未受变更影响的元素直接沿用上一次计算样式、跳过重新匹配的行为。

- 复用前提：元素自身、其祖先以及所匹配的规则集合在本次变更中都没有变化。
- 共享结构：多个元素的计算样式在实现中可以共享同一份数据，避免逐元素重复存储。
- 缓存边界：涉及祖先或兄弟状态的伪类在复用判定上更保守，命中范围内的元素更容易被判为失效。
- 收益：复用把整树级别的工作缩小为局部工作，是样式重算成本可控的关键。

```js
// 未受影响的元素沿用旧结果，重算耗时集中在被标记的子树上
const items = document.querySelectorAll(".item");
items.forEach((item) => item.classList.toggle("is-active", false));
```

> 复用与失效是一对机制：浏览器先判定哪些元素需要重算，再对剩余部分沿用已有结果。

**速记**：未失效的元素沿用旧计算样式，重算只发生在被标记的子树上。



### 层叠与继承与优先级

匹配得到的是候选声明的集合，同一属性可能有多条候选。层叠负责选出唯一胜出者，继承负责在没有胜出者时提供取值来源。本模块描述这两件事在浏览器中的执行次序。

#### 层叠的排序规则

**层叠（cascade）**：是把来自不同来源、不同重要性与不同优先级的声明按固定顺序排序并选出胜出声明的过程。

- 来源顺序：从低到高依次为浏览器默认样式、用户样式、作者样式。
- 重要性反转：带 important 标记的声明优先于同来源的普通声明，且用户的重要声明高于作者的重要声明。
- 动画与过渡：动画产生的声明优先于普通作者声明，过渡产生的声明优先于其他所有来源。
- 同分处理：来源、重要性与优先级都相同时，在文档中后出现的声明胜出。
- 分层：使用层显式声明顺序时，先比较层的次序，再在层内按上述规则比较。

```css
.card { color: blue; }
.card { color: red; }
/* 两条声明优先级相同，后出现的红色胜出 */
```

> 层叠的输出只有一条声明，这个过程是确定性的：相同输入在任意实现中得到相同胜出者。

**速记**：层叠按来源、重要性、优先级、出现次序依次比较，输出唯一胜出声明。



#### 优先级的三元组

**优先级（specificity）**：是层叠中用于比较同一来源、同一重要性下不同选择器的权重，由三段计数表示，比较时从左到右逐段进行。

- 三段内容：第一段统计 id 选择器数量，第二段统计类选择器、属性选择器与伪类数量，第三段统计类型选择器与伪元素数量。
- 比较方式：逐段比较，不跨段进位，一个 id 高于任意数量的类。
- 行内声明：不属于任何选择器，在层叠中按独立层级处理，默认高于普通作者规则。
- 不贡献权重：通配符与组合器不参与计数；继承得到的声明权重低于任何直接命中的声明。

```css
/* 第二段计数为 2，第三段计数为 1 */
.card.item > p {
  line-height: 1.5;
}
```

> [!IMPORTANT]
> **重要内容**：比较顺序始终是来源、重要性、优先级，因此用户样式表中的重要声明可以覆盖作者的普通声明，这是可访问性设置生效的基础。

**速记**：优先级按 id、类与属性、类型三段逐段比较，不跨段进位。



#### 继承的传播

**继承（inheritance）**：是元素上找不到某属性的任何声明时，从父元素复制该属性计算值的机制，只有可继承属性会传播。

- 可继承属性：文本相关属性通常可继承，例如字体、颜色、行高。
- 不可继承属性：盒模型与定位相关属性通常不可继承，例如宽度、边距、定位方式。
- 显式指定：关键字 inherit 强制取父元素计算值，initial 取属性初始值，unset 在可继承属性上等同 inherit。
- 传递内容：继承传递的是计算值而不是书写值，因此子元素拿到的是换算完成的结果。

```css
/* 子元素未声明颜色，直接使用父元素的计算值 */
.parent { color: #334155; }
.child { padding: 8px; }
```

> 继承发生在层叠之后：只有层叠没有产出声明时，才轮到继承或初始值补位。

**速记**：继承在层叠之后补位，传递的是可继承属性的计算值。



### 继承值与计算值与使用值

一条声明从被写下到可用于渲染，要经过若干次取值转换。区分这些阶段，才能理解脚本读到的值为什么与样式表里写的不一致。

#### 声明值与层叠值

**声明值（declared value）**：是作者或用户为某属性写下的原始值，可能包含相对单位、百分比或关键字。

- 层叠值：层叠从多条声明值中选出一条，该结果称为层叠值（cascaded value）。
- 指定值：层叠没有产生结果时，按继承或初始值补位，得到指定值（specified value）。
- 关键字处理：inherit、initial、unset、revert 等关键字在指定值阶段被解析为具体的取值来源。
- 单位保留：em、rem、百分比等相对表示在此阶段原样保留。
- 声明来源：同一属性可能同时出现在多个来源与多条规则中，取值阶段只处理已经胜出的那一条。

```css
.card {
  width: 50%;
  font-size: 1.25rem;
  line-height: 1.5;
}
```

> 层叠与继承都属于选出指定值这一步，二者是补位关系而不是并列关系。

**速记**：声明值经层叠得到层叠值，未命中时由继承或初始值补成指定值。



#### 初始值与关键字取值

**初始值（initial value）**：是属性在规范中定义的默认取值，层叠没有产出声明且属性不可继承时使用。

- 不可继承属性的补位：没有声明时取初始值，例如 display 的初始值为 inline。
- 可继承属性的补位：没有声明时先看继承，父元素也无声明时取初始值。
- 显式关键字：initial 显式取初始值，inherit 显式取父元素计算值，unset 按属性是否可继承自动二选一，revert 回退到上一层来源的取值。
- 不可改写：初始值由属性规范定义，任何样式表都无法覆盖它。
- 与默认样式的区别：浏览器默认样式是一层可被作者样式覆盖的声明，初始值不是声明。

```js
const label = document.querySelector("span");
// 未声明 display 的 span，其计算值来自属性的初始值
console.log(getComputedStyle(label).display); // "inline"
```

> 排查「样式没生效」时先区分取值来源：命中了声明、继承了父元素还是取了初始值，三种情况对应不同的修改位置。

**速记**：初始值是不可改写的属性默认取值，在层叠与继承都未产出声明时生效。



#### 计算值与使用值

**计算值（computed value）**：是相对单位按已知上下文换算后得到的绝对值，字体相对单位在此阶段换算为像素。**使用值（used value）**：是计算值经过布局计算后得到的最终数值，例如百分比宽度换算为具体像素。

- 换算边界：依赖包含块尺寸的百分比保留到使用值阶段。
- 字体相对单位：em 与 rem 在计算值阶段换算，因为字号已经确定。
- 视口单位：视口相关单位在计算值阶段按当前视口尺寸换算。
- 实际值：使用值经设备像素取整或舍入后成为实际值（actual value）。
- 与布局的关系：使用值只在布局完成后存在，布局前读取得到的可能是上一次渲染的结果。

```js
const card = document.body.firstElementChild;
const styles = getComputedStyle(card);
console.log(styles.fontSize); // "20px"，字体相对单位已换算
console.log(styles.width);    // "480px"，百分比已按布局结果换算
```

> [!CAUTION]
> **注意内容**：读取宽度一类依赖布局的属性会强制浏览器结算样式与布局，在循环中反复读取会显著放大开销，详见本主题第 8 篇 渲染性能：重排、重绘与合成层优化。

**速记**：计算值换算已知上下文中的相对单位，使用值再经布局换算百分比。



#### 值与脚本的交互

**解析值读取**：是脚本通过 getComputedStyle 获取元素计算样式的入口，返回值反映浏览器处理后的结果，而不是样式表中的书写形式。

- 与行内声明区分：element.style 只反映元素上的行内声明，未写在元素上的属性读不到。
- 读取时机：样式尚未结算时读取会触发结算，得到的是当前时刻的结果。
- 取值形态：不同属性返回的可能是计算值或使用值，颜色通常归一化为 rgb 或 rgba 形式，宽度通常返回像素值。
- 伪元素：getComputedStyle 接收 element 与伪元素两个参数，第二个参数用于读取伪元素的样式。

```js
const card = document.body.firstElementChild;
console.log(card.style.fontSize);                       // ""，行内未声明字号
console.log(getComputedStyle(card, "::after").content); // "none"
```

> 读取计算样式的成本来自它可能触发的样式结算与布局结算，与读取频次直接相关。

**速记**：getComputedStyle 返回处理后的结果，与行内声明读取的是两套数据。



### 样式失效与重算范围

文档或样式表发生变化后，此前的计算结果可能不再成立。浏览器用失效标记圈定范围，再在渲染前完成重算，范围大小决定了变更的真实成本。

#### 样式失效的触发

**样式失效（style invalidation）**：是把受影响的元素或规则标记为需要重新计算样式的行为，触发源分为元素侧与规则侧两类。

- 元素侧：元素被插入或移除、类名或属性被修改、行内样式被改写。
- 规则侧：样式表被插入或移除、规则被增删或修改、媒体查询求值结果改变。
- 标记方式：浏览器在元素上记录需要重算的标记，在渲染前统一处理。
- 失效粒度：标记以元素或规则为单位，浏览器据此推断需要重算的最小子树。
- 批处理：同一任务内的多次变更合并为一次重算，不会逐次触发。

```js
const card = document.body.firstElementChild;
card.classList.add("is-active"); // 该元素及其子树被标记为需要重算样式
```

> 失效只是打标记，真正的重算被推迟到渲染前的批量步骤，因此同一任务内连续修改不会按次数累积成本。

**速记**：样式失效由元素变更或规则变更触发，只打标记并合并到渲染前处理。



#### 重算范围的限制

**样式重算（style recalculation）**：是浏览器为失效元素重新匹配规则并计算属性值的过程，它只处理被标记的范围，而不是整棵文档树。

- 子树效应：元素自身与其子树通常一起重算，因为继承可能影响后代取值。
- 规则扩散：被修改的规则命中元素越多，重算范围越大，选择器越通用扩散越明显。
- 子树外扩散：兄弟选择器与引用祖先或兄弟状态的选择器可能让失效越过子树边界。
- 观测方式：性能面板中的样式重算耗时反映本次变更的实际范围与规则规模。
- 控制手段：改动类名比改写行内样式更容易被限制在小范围，避免在动画回调中反复改写影响全局的规则。
- 与绘制的关系：样式重算与绘制是两回事，改动不影响外观的属性只引发重算而不引发重绘。

```js
// 同一任务内批量修改，浏览器只做一次重算
const items = document.querySelectorAll(".item");
items.forEach((item) => item.classList.add("is-active"));
```

> [!WARNING]
> **警告内容**：在动画或滚动回调中逐帧修改大量元素的类名，会让样式重算成为主线程瓶颈，应改为修改不触发重算的属性或把变更合并到单次任务。

**速记**：重算以失效子树为默认粒度，通用选择器与跨子树引用会扩大范围。



#### 重算与渲染管线的衔接

**样式重算的输出**：是每个元素的计算样式，它是布局阶段的输入，只有进入渲染的元素才会把计算样式交给后续阶段。

- 参与判定：display 取值为 none 的元素不生成布局盒，其子树不参与布局与绘制。
- 输出内容：布局读取计算样式中的尺寸、边距、定位等属性，百分比在这一步换算为使用值。
- 与脚本的关系：脚本可在任意时刻读取计算样式，读取会促使浏览器先完成当前的样式结算。
- 帧内顺序：一次渲染帧内的处理顺序是样式重算、布局、绘制、合成，样式重算的结果在本次帧内被后续阶段复用。

```js
// 计算样式是布局的输入：先隐藏再测量，可避免无意义的布局
const panel = document.body.firstElementChild;
panel.style.display = "none";
console.log(panel.offsetHeight); // 0，元素不参与布局
```

> 样式重算之后的阶段详见本主题第 7 篇 渲染管线：布局、绘制与合成。

**速记**：样式重算的输出是计算样式，供布局使用，不参与渲染的元素不进入布局。
