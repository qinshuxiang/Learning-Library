## 渲染性能：重排、重绘与合成层优化

### 触发重排与重绘的常见操作

**渲染性能问题**：是样式或几何的改动迫使渲染管线从某个阶段重跑、从而挤占单帧时间预算的现象，判断代价的依据是改动会让管线从哪里重新开始。

管线的阶段划分与产物见本主题第 7 篇 渲染管线：布局、绘制与合成；本节只回答哪些操作触发哪一阶段重做。

#### 重排与重绘的定义与代价差异

**重排（reflow）**：是指元素的几何信息发生变更时，浏览器重新计算布局树、更新相关盒的位置与尺寸的过程。**重绘（repaint）**：是指几何信息不变、只有外观发生变更时，浏览器重新生成绘制列表并重新光栅化的过程。

- 代价顺序：重排高于重绘，重绘高于只走合成层。
- 波及范围：重排可能牵动祖先与兄弟，重绘通常限于失效区域。
- 例外情况：独立层上的 transform 与 opacity 改动可以跳过前两者。
- 叠加情形：一次改动可能同时触发重排与重绘，按代价最高的一档计算。

```js
const card = document.querySelector(".card");

// 只改颜色：几何不变，从绘制阶段重跑
card.style.backgroundColor = "#f5f7fa";

// 改宽度：布局必须重算，绘制与光栅化随后重做
card.style.width = "360px";

// 改变换：独立层上只在合成阶段重新应用
card.style.transform = "translateX(24px)";
```

> 判断代价只看一个问题：这次改动是否让盒的位置或尺寸发生变化。

**速记**：重排重算几何代价最高，重绘只重做外观，合成层改动代价最低。



#### 触发重排的操作

**触发重排的操作**：是所有会改变盒几何或文档结构的样式写入与 DOM 变更，改动点越靠近根，重算范围越大。

- 几何属性：width、height、min-height、max-height、padding、margin、border-width。
- 位置与显示：display、position、top、left、right、bottom、float、overflow。
- 文本与字体：font-size、font-family、line-height、letter-spacing、white-space。
- 结构变更：插入、删除或移动节点，替换文本内容，改变表单控件的尺寸。
- 读取几何：offsetWidth、offsetHeight、offsetTop、offsetLeft、clientWidth、scrollHeight 与 getBoundingClientRect 会强制布局（详见本篇强制同步布局与布局抖动一节）。

```js
// 下面每一行都会让布局失效，改动集中发生时可合并为一次
const panel = document.querySelector(".panel");
panel.style.padding = "24px";
panel.style.lineHeight = "1.8";
panel.style.display = "grid";
console.log(panel.offsetHeight);   // 读取几何，立即触发一次布局
```

> 连续写入同一元素的多个几何属性不会逐个触发布局，浏览器把它们积攒到一次布局里统一处理。

**速记**：几何属性、显示模式、字体与结构变更都会触发重排，写入会被合并。



#### 触发重绘与只触发合成的操作

**只触发重绘的操作**：是不改变盒的位置与尺寸、只改变像素外观的样式写入。**只触发合成的操作**：是在独立合成层上修改变换或透明度、连绘制内容都不变的写入。

- 只触发重绘：color、background-color、background-image、border-color、border-radius、box-shadow、outline、visibility。
- 只触发合成：位于独立层上的 transform、opacity，以及部分滤镜效果。
- 易混辨析：visibility 隐藏后元素仍占位，只触发重绘；display 切回可见会重建布局，触发重排。
- 判定口径：改动是否改变几何，是否改变该层要画的像素。

```css
.card {
  /* 只影响像素外观，不触发重排 */
  background-color: #ffffff;
  box-shadow: 0 2px 8px rgba(0, 0, 0, 0.12);
}

.card-hidden {
  /* 保留占位、只重绘，与 display: none 的后果不同 */
  visibility: hidden;
}
```

> 重绘虽然比重排便宜，但在大面积元素上频繁触发，光栅化时间同样会突破单帧预算。

**速记**：只改颜色与阴影走重绘，独立层上的 transform 与 opacity 只走合成。



### 强制同步布局与布局抖动

**强制同步布局（forced synchronous layout）**：是主线程尚未完成布局时脚本立即读取依赖布局结果的属性、浏览器被迫中断当前任务立刻执行布局的情形。

#### 强制同步布局的定义与成因

**强制同步布局**：是读取几何属性时浏览器为返回准确数值而放弃布局批处理、当场执行一次布局的行为。

- 正常节奏：样式写入只做失效标记，布局被推迟到帧末统一执行。
- 破例条件：读取几何属性或部分计算样式必须拿到已定型的布局结果。
- 触发前提：本次任务中已经发生过会让布局失效的写入。
- 代价特征：布局次数随读取次数增加，且每次都发生在脚本执行中间。

```js
const list = document.querySelector(".list");
const items = document.querySelectorAll(".item");

// 反例：先写入，再读取，读写耦合在同一轮里
list.style.width = "640px";
console.log(list.offsetWidth);   // 强制同步布局，如 640
```

> 读取与写入本身都不昂贵，昂贵的是两者在同一任务里交替出现。

**速记**：写入后立刻读几何会打断布局批处理，当场重算一次布局。



#### 布局抖动的典型循环

**布局抖动（layout thrashing）**：是在循环或逐项处理中反复交替读写、导致单次任务里触发多次强制同步布局的现象。

- 典型形态：循环里逐项写样式，紧接着读取该项的几何，下一轮重复。
- 放大效应：项数越多布局次数越多，帧时间随列表长度线性增长。
- 常见场景：按索引计算偏移、累加高度、逐项读写尺寸做对齐。
- 测量口径：一帧耗时明显超过 16 ms 的平滑基线时，卡顿即可感知（帧与调度的关系见本主题第 9 篇）。

```js
const items = document.querySelectorAll(".item");

// 反例：每轮都读一次 offsetWidth，等于每轮触发一次布局
items.forEach((item) => {
  item.style.width = item.offsetWidth / 2 + "px";
});
```

> [!WARNING]
> **警告内容**：在长列表渲染或滚动监听中写出逐项读写循环，会在单帧内触发数十次布局，滚动会立刻出现明显掉帧。

**速记**：循环里逐项读写会把布局次数放大到与项数同阶。



#### 读写分离的改造方法

**读写分离**：是先把需要读取的几何值一次性取完并存入变量，再统一执行写入的改造方式，使布局在一帧内至多发生一次。

- 集中读取：第一轮只读，把结果存进数组或映射。
- 集中写入：第二轮只写，不再读取任何几何属性。
- 批处理封装：把两轮包成 measureAndMutate 一类的函数，避免后续代码破坏约定。
- 兜底手段：必须在读取后写入时，用 requestAnimationFrame 把写入推迟到下一帧（详见本主题第 9 篇）。

```js
function measureItemWidths(items) {
  const widths = [];
  items.forEach((item) => widths.push(item.offsetWidth));
  return widths;
}

function applyItemScales(items, widths) {
  items.forEach((item, index) => {
    item.style.width = widths[index] / 2 + "px";
  });
}

const items = document.querySelectorAll(".item");
applyItemScales(items, measureItemWidths(items));   // 读一轮、写一轮，只布局一次
```

> 改造的收益来自顺序调整而非写法技巧：同样的样式与几何，读写分离后布局次数从 N 次降到 1 次。

**速记**：先读完再统一写，把一帧内的布局次数压到一次。



### 合成层与提升与层爆炸

**合成层提升（layer promotion）**：是把元素提升为独立合成层、让它的变换与透明度变化只在合成阶段处理的手段。

#### 提升的收益与成本

**提升收益**：是动画与滚动不再触发主线程的布局与绘制，逐帧工作移到合成线程与 GPU。

- 收益方向：位移与淡入淡出动画在主线程繁忙时仍能维持稳定帧率。
- 内存成本：每个层都要保存自己的位图，占用与层面积和像素密度成正比。
- 管理成本：层数增加会带来合成顺序、裁剪与光栅化调度的额外开销。
- 权衡结论：提升只在元素确实需要独立动画或独立滚动时才划算。

```css
.animated-badge {
  /* 独立层承载变换，动画期间不触碰布局与绘制 */
  transform: translateY(0);
  transition: transform 180ms ease-out;
}

.animated-badge:hover {
  transform: translateY(-6px);
}
```

> 提升买到的是动画独立性，付出的是内存与合成管理开销，两者都需要计入预算。

**速记**：提升换来动画不打扰主线程，代价是位图内存与合成开销。



#### 层爆炸的成因与表现

**层爆炸（layer explosion）**：是页面合成层数量远超实际需要、位图内存与合成开销抵消掉提升收益的状态。

- 成因一：为大量元素声明 will-change 或 translateZ，逐项建立独立层。
- 成因二：把提升写进通用选择器，列表与重复组件全部命中。
- 成因三：层内再嵌层，父子关系使层数被放大。
- 表现：内存与显存占用持续偏高，滚动与切页变慢，低内存设备容易崩溃。

```css
/* 反例：给列表中的每一项都提升，层数随数据量增长 */
.item {
  /* will-change: transform; */
}
```

> [!CAUTION]
> **注意内容**：把 will-change 或三维变换写进通用选择器，会让列表项数量直接决定层数量，移动端内存压力最大。

**速记**：层爆炸源于批量提升与嵌套提升，表现为内存高企与滚动变慢。



#### 提升的判定与取舍

**提升判定**：是决定哪些元素值得建立独立层的取舍过程，原则是只服务于确实独立变化的元素。

- 优先提升容器：一层覆盖多个同时动画的子元素，胜过逐个提升。
- 只提升动画元素：静态内容留在原层，避免为它付出位图内存。
- 复查时机：动画结束、交互完成后回收临时提升。
- 验证手段：借助开发者工具的层视图确认实际层数与面积（工具读法见本主题第 16 篇）。

```js
// 元素进入动画状态时才提升，结束后立即释放
const banner = document.querySelector(".banner");

function startBannerAnimation() {
  banner.style.willChange = "transform";
  banner.style.transform = "translateX(40px)";
}

function stopBannerAnimation() {
  banner.style.transform = "";
  banner.style.willChange = "auto";
}

banner.addEventListener("transitionend", stopBannerAnimation);
startBannerAnimation();
```

> 提升数量应与「同时独立变化的元素数量」一致，而不是与元素总数一致。

**速记**：按独立变化的需求提升，优先提升容器，用完即回收。



### 动画性能：transform 与 opacity

**可合成属性**：是能够由合成线程直接应用、不需要主线程重算布局与绘制的属性集合，transform 与 opacity 是其中最主要的两项。

#### 为何这两类属性代价最低

**代价最低的原因**：是变换与透明度都不改变布局几何，在独立层上也不需要重新生成绘制内容，因此只在合成阶段重新计算。

- 不参与布局：变换是绘制结果的仿射变换，盒的位置与尺寸声明保持不变。
- 不重做绘制：层内位图可以沿用，只是叠加时套用新的矩阵或透明度。
- 依赖前提：元素必须处在可独立处理的合成层上，否则仍会回到重绘路径。
- 反面对照：left、top、width、height 会改写几何，必然经过布局阶段。

```css
.card {
  /* 合成阶段处理：不触碰布局，也不重做层内绘制 */
  transition: transform 200ms ease-out, opacity 200ms ease-out;
}
```

> 变换作用于绘制完成的层，这正是它与定位属性开销不同的根本原因。

**速记**：transform 与 opacity 不改几何也不重画内容，代价落在合成阶段。



#### 用合成属性替换触发布局的写法

**替换写法**：是把逐帧变化的几何属性改写成等价变换、把显示切换改写成透明度切换的一组改造手段。

- 位移：用 transform 的 translate 替代 left 与 top 的逐帧变化。
- 缩放：用 transform 的 scale 替代 width 与 height 的逐帧变化，注意会同步拉伸子元素。
- 显隐：用 opacity 配合 visibility 替代 display 的切换，保留占位可避免重排。
- 旋转与倾斜：用 rotate 与 skew 替代依靠尺寸计算的近似写法。

```css
/* 反例：逐帧改写定位属性，每帧都要重新布局 */
.moving-card-bad {
  position: relative;
  left: 0;
  transition: left 200ms ease-out;
}

/* 正解：把位移交给变换，动画期间不触发布局 */
.moving-card {
  transform: translateX(0);
  transition: transform 200ms ease-out;
}

.moving-card:hover {
  transform: translateX(24px);
}
```

> 缩放替代宽高会改变视觉质量与子元素表现，只在动画期间使用、结束后回到真实尺寸更稳妥。

**速记**：位移缩放旋转都交给 transform，显隐交给 opacity，逐帧几何改写全部替换。



#### 动画的启停与清理

**动画启停**：是把优化声明集中在动画真正运行的区间内、结束后立刻回收的做法，避免优化手段长期占用资源。

- 开始前声明：在动画将要发生时设置 will-change 或提升标记。
- 结束后清理：监听 transitionend 或 animationend，把声明恢复为默认值。
- 逐帧驱动：需要脚本逐帧更新时用 requestAnimationFrame，不用定时器（机制见本主题第 9 篇）。
- 缩减面积：动画元素面积越小、同时运行的动画越少，单帧合成压力越低。

```js
const toast = document.querySelector(".toast");

function showToast() {
  toast.style.willChange = "opacity, transform";
  toast.classList.add("is-visible");
}

function handleToastEnd(event) {
  if (event.propertyName !== "opacity") return;   // 只等目标属性结束
  toast.classList.remove("is-visible");
  toast.style.willChange = "auto";
}

toast.addEventListener("transitionend", handleToastEnd);
showToast();
```

> [!CAUTION]
> **注意内容**：动画结束后不清理 will-change，元素会一直保留独立层与预留资源，长期看与层爆炸的后果相同。

**速记**：动画前声明、结束后用 transitionend 回收，逐帧驱动交给 requestAnimationFrame。



### will-change 与 contain 的正确用法

**will-change**：是 CSS 属性，用于提前告知浏览器某个属性将要变化，使浏览器有机会提前准备优化；**contain**：是 CSS 属性，用于声明元素子树在某些方面与页面其余部分隔离，使浏览器可以跳过不必要的计算。

#### will-change 的作用与常见误用

**will-change**：是接受 auto、scroll-position、contents 与具体属性名三类取值的提示属性，取值指向未来会变化的属性本身。

- 取值含义：auto 表示不预告；scroll-position 表示滚动位置将变化；contents 表示内容将变化；属性名表示该属性将变化。
- 误用一：写进通用选择器，让所有同类元素常驻提升。
- 误用二：声明后从不移除，把临时优化变成长期开销。
- 误用三：为已经能走合成路径的属性重复声明，收益为零而内存照付。

```css
/* 反例：常驻声明，页面静止期间也在占用层资源 */
.list-item {
  /* will-change: transform; */
}

/* 正解：只在确实要动画的元素上声明，且由脚本控制启停 */
.list-item.is-animating {
  will-change: transform;
}
```

> will-change 是提示而非保证：浏览器会结合内存与设备情况决定是否采纳。

**速记**：will-change 预告未来变化，通用选择器与常驻声明是两类典型误用。



#### 开启与回收时机

**开启与回收时机**：是让 will-change 只在动画区间内生效的一对动作，开启过早会浪费，回收过晚会让开销长期存在。

- 开启时机：交互发生的前一刻，通过脚本添加样式类或设置内联属性。
- 回收时机：transitionend 或 animationend 触发后立即恢复。
- 兜底路径：动画被打断时事件可能不触发，需要在状态重置处一并清理。
- 不必声明：已经由三维变换或独立内容带来提升的元素，无需重复声明。

```js
const card = document.querySelector(".card");

card.addEventListener("pointerenter", () => {
  card.style.willChange = "transform";   // 悬停前开启，给浏览器准备时间
});

card.addEventListener("transitionend", () => {
  card.style.willChange = "auto";        // 动画结束立即回收
});
```

> 开启时机的取舍是「早到足够准备，晚到不发生浪费」，一次交互一开一收最贴近这个区间。

**速记**：交互前开启、动画结束回收，被打断时也要清理。



#### contain 的取值与收益

**contain 取值**：是 layout、paint、size、style 四类隔离声明及其组合，用于限定元素子树对外部计算的影响范围。

- layout：子树内部的布局与外部互不影响，可缩小布局重算范围。
- paint：子树绘制被裁剪在元素边框盒内，同时建立包含块与层叠上下文。
- size：元素尺寸不受子树影响，可跳过对子树的尺寸测量，需要显式给定尺寸。
- style：限制计数器与引号一类的继承影响范围；content 等价于 layout、paint 与 style 的组合，strict 在此基础上再加 size。

```css
.sidebar {
  /* 布局隔离：侧栏内部变化不必让外层重新布局 */
  contain: layout;
}

.card-list {
  /* 绘制裁剪：列表内容不会溢出到卡片之外 */
  contain: paint;
}
```

> [!IMPORTANT]
> **重要内容**：contain 的 size 取值会让元素忽略子元素尺寸，必须同时给定明确的宽高，否则元素可能塌缩为零。

**速记**：contain 用 layout 隔离布局、paint 裁剪绘制、size 跳过尺寸测量，size 需要显式尺寸兜底。
