## 内存管理与垃圾回收

**浏览器内存管理**：是 JavaScript 引擎替脚本完成「分配、跟踪、回收」三件事的整套机制，脚本只决定何时申请与何时断开引用，回收时机由引擎判定。

本篇讨论 V8 如何组织堆内存、垃圾回收（garbage collection，缩写 GC）在什么条件下触发与以什么方式停顿、内存泄漏有哪些典型成因，以及内存面板的读法与排查步骤。栈与堆的语法语义、执行上下文与闭包的作用域规则详见 前端/JavaScript 主题第 16 篇 执行上下文与内存管理；V8 的解析、优化与去优化流程详见本主题第 10 篇 V8 引擎与 JavaScript 执行优化；完整的性能测量体系详见本主题第 16 篇 性能指标与优化实战。

### 内存生命周期与堆与栈

页面中的每一份数据都从一次分配开始，到不可达为止。这一模块先建立「数据放在哪里、由谁判定失效」的基本图景，为后续的分代与回收算法铺路。

#### 内存生命周期的三个阶段

**内存生命周期（memory lifecycle）**：是一块内存从分配到回收所经过的固定阶段，分为分配（allocate）、使用（use）与释放（release）三个阶段。

- 分配：变量声明、对象字面量、数组创建、字符串拼接等操作都会向引擎申请内存。
- 使用：读写变量与对象属性，即对已分配内存的访问，这一阶段不改变内存的归属。
- 释放：当内存不再被任何可达引用指向时由 GC 回收，脚本无法指定回收的具体时刻。
- 控制点：脚本能决定的只有分配规模与引用是否存在，中间态由引擎托管。

```js
let profile = { name: "Ada", score: 0 };   // 分配：在堆上创建对象
profile.score = 10;                         // 使用：写入属性
profile = null;                             // 断开引用，对象转为不可达
// console.log(profile.score);              // 报错：引用已断开
```

> 三个阶段中脚本能直接控制的只有分配与断开引用，控制不了释放时刻。释放由可达性分析的结果决定，这是自动内存管理与手动内存管理的根本差别。

**速记**：分配由脚本发起，使用是读写，释放由 GC 按可达性决定。



#### 栈与堆的分工

**栈（stack）**：是渲染进程主线程上的一段后进先出内存区，存放函数调用帧与其中的原始值，帧随函数返回自动弹出。**堆（heap）**：是引擎管理的另一片内存区，存放入口由引擎分配、GC 回收的对象实体。

- 栈上内容：调用帧、参数、局部原始值与指向堆对象的引用值。
- 堆上内容：对象、数组、函数对象、闭包捕获的环境、长字符串等引用类型实体。
- 生命周期差别：栈帧随函数返回立即失效，堆对象要等可达性分析判定后才进入回收。
- 空间差别：栈容量小且由引擎固定，超出即抛出栈溢出错误；堆容量大且可随需增长。

```js
function buildReport(title) {
  const pages = [1, 2, 3];        // pages 引用在栈上，数组实体在堆上
  return { title, pages };        // 返回对象实体，栈帧随即弹出
}

const report = buildReport("月报");   // report 指向堆上的对象
console.log(report.pages.length);      // 3
```

> [!NOTE]
> **提醒内容**：栈帧弹出不等于堆对象回收。函数返回后若返回的引用仍被外层持有，对象继续存活；只有引用链整体不可达，对象才会进入回收队列。

**速记**：栈存调用帧与原始值、随帧弹出，堆存对象实体、按可达性回收。



#### 可达性与根对象

**可达性（reachability）**：是从一组根出发沿引用链能否走到某个对象这一判定，走得到即存活，走不到即垃圾。**根对象（root）**：是可达性分析的起点集合，包含全局对象、当前调用栈中的引用、闭包捕获的环境，以及被引擎登记的监听器与定时器回调。

- 根集合来源：全局对象上的属性、栈帧中的局部变量与参数、活跃闭包的环境记录。
- 引擎登记：事件监听器、未完成的定时器与 Promise 回调在完成前都属于可达路径的一部分。
- 判定口径：GC 不看引用计数是否为零，只看从根出发能否到达。
- 循环引用：互相引用但整体与根断开时仍判定为垃圾，引用环不构成存活的理由。

```js
let first = { tag: "a" };
let second = { tag: "b" };
first.peer = second;
second.peer = first;      // 两个对象互相引用，形成引用环

// 从根出发已无路径到达这两个对象，引用环照样被回收
first = null;
second = null;
```

> 引用计数把「引用数归零」当回收条件，无法处理循环引用；可达性分析把「从根出发无路径」当回收条件，循环引用因此不再是问题。这一点是理解现代 GC 的起点。

**速记**：可达性从根对象出发判断，环状引用只要与根断开就回收。



### V8 堆结构与分代

V8 把堆切成若干职责不同的空间，并按对象的存活时长把它们分到不同代中管理。分区的意义在于把「大部分对象朝生夕死」这一分布特征转化为可用的回收效率。

#### 堆空间的分区

**V8 堆（V8 heap）**：是 V8 向操作系统申请来、用于存放 JavaScript 对象的内存池，内部按用途划分为新生代、老生代与若干专用空间。

- 新生代（new space）：新创建的小对象先分配在这里，空间小、回收频繁。
- 老生代（old space）：经历新生代回收仍存活的对象晋升到此，空间大、回收成本高。
- 大对象空间（large object space）：体积超过新生代承载能力的对象在此分配，避开复制开销。
- 专用空间：存放编译产物、对象形状（隐藏类）等引擎自有数据的空间，与脚本数据分开管理。

```js
// 新建的小对象先落在新生代
const counters = [1, 2, 3];

// 持续被根引用的对象，会在回收若干轮后晋升到老生代
const retained = { keep: true };
globalThis.retained = retained;
console.log(retained.keep);   // true
```

> 分区不是脚本可见的 API，而是引擎内部的组织方式。脚本能观察到的只有指标表现：新生代回收发生得频繁而短暂，老生代回收发生得稀少而单次停顿更长。

**速记**：堆分新生代与老生代加专用空间，小对象进新生代，长寿对象晋升老生代。



#### 对象的分配与晋升

**分配（allocation）**：是引擎在新生代中划出一段连续空间存放新对象的过程，采用移动空闲指针的方式完成，速度接近指针加法。**晋升（promotion）**：是新对象在新生代存活若干轮回收后被迁移到老生代的过程。

- 分配路径：新生代内维护一块空闲区，分配时抬高指针，不必遍历空闲链表查找空洞。
- 存活判定：新生代回收时把判定存活的对象复制到另一块半空间，未复制的整块丢弃。
- 晋升条件：对象经历多次新生代回收仍存活，或对象体积超出新生代容量，即被迁移到老生代。
- 跨代引用：老生代指向新生代对象的引用通过记忆集（remembered set）登记，避免每次新生代回收都扫描整个老生代。

```js
function keepAlive() {
  const cached = new Array(1000).fill({ alive: true });
  return () => cached.length;   // 闭包长期持有数组，数组随之晋升
}

const readLength = keepAlive();
setInterval(readLength, 1000);   // 持续可达，数组不会在新生代被回收
```

> [!TIP]
> **建议内容**：短生命周期的大数组适合随用随弃，写成函数局部变量并及时断开引用；长期持有的大数组会被晋升到老生代，此后回收代价更高，必要时改用分批加载或弱引用缓存。

**速记**：新生代分配靠抬指针，存活若干轮或体积过大即晋升老生代。



#### 大对象与专用空间

**大对象空间（large object space）**：是存放体积超过阈值的对象的独立区域，其中的对象不参与新生代的复制过程，直接进入老生代一侧参与标记与清理。

- 分配规则：超大对象跳过新生代，直接进入老生代一侧的专用区域。
- 回收规则：大对象不随新生代回收移动，省去大块内存的复制开销。
- 内存影响：大对象空间存在碎片化风险，频繁创建等大对象会加快内存增长。
- 常见来源：长字符串、大数组、图像数据与二进制缓冲（ArrayBuffer）。

```js
// 长字符串与二进制缓冲属于大对象空间的使用者
const reportText = "x".repeat(2_000_000);
const buffer = new ArrayBuffer(8 * 1024 * 1024);

console.log(reportText.length);   // 2000000
console.log(buffer.byteLength);   // 8388608
```

> 大对象是内存增长最快的来源之一：一次创建就占用成片空间，且不像小对象那样能靠新生代回收快速清理。处理二进制数据时尽量复用缓冲区，而不是反复新建。

**速记**：大对象跳过新生代直接进专用空间，不移动但易造成碎片与内存峰值。



### 垃圾回收算法与增量与并发

GC 算法回答两个问题：哪些对象判定为垃圾，以及判定与回收在什么时机执行。前者决定正确性，后者决定页面是否卡顿。

#### 标记清除与标记整理

**标记清除（mark-and-sweep）**：是从根出发标记所有可达对象、再统一回收未标记对象的算法，回收后留下不连续的空洞。**标记整理（mark-compact）**：是在标记之后把存活对象向一端移动、使空闲区连成整块的算法。

- 标记阶段：从根集合出发遍历引用图，为可达对象打标记，遍历期间脚本执行被暂停。
- 清除阶段：扫描堆空间，把未标记对象占用的内存交回空闲列表。
- 整理阶段：把存活对象搬运到空间一端，同时更新所有指向它们的引用地址。
- 取舍：清除不移动对象、开销小但产生碎片；整理消除碎片，但搬运与改指针的开销更大。

```js
let cache = { rows: [] };
for (let index = 0; index < 1000; index++) {
  cache.rows.push({ index });   // 大量短命对象反复分配与丢弃
}
cache = null;                    // 整批对象转为不可达，等待一次回收
```

> 老生代以标记清除为主，并按碎片程度择机执行标记整理：清理能快速拿回内存，整理能维持大块连续空间，两者组合使用而不是二选一。

**速记**：标记清除回收快但留碎片，标记整理搬运存活对象换连续空间。



#### 复制算法与新生代回收

**复制算法（copying collection）**：是把新生代分成大小相等的两块半空间（semispace），回收时把存活对象复制到另一块、再整体清空原块的算法，也称 Scavenge。

- 半空间结构：任一时刻只有一块在使用，另一块留作回收时的复制目标区。
- 回收过程：标记存活对象后复制到目标区，复制完成的存活对象年龄加一。
- 无碎片：复制后存活对象在目标区连续排列，天然不产生碎片。
- 代价：可用空间只有总量的一半，且复制本身需要额外的遍历与搬移时间。

```js
function allocateTemp() {
  const point = { x: 1, y: 2 };   // 进入新生代
  return point.x + point.y;
}

for (let round = 0; round < 100000; round++) {
  allocateTemp();   // 每次分配的对象随即失去引用，回收时不必复制
}
```

> 复制算法的效率取决于存活对象比例。新生代中多数对象在回收时已经死亡，需要复制的只是少数，因此回收极快；老生代存活比例高，复制成本随之上升，所以老生代改用标记清除与整理。

**速记**：新生代一分为二、存活对象复制到另一块，回收快且无碎片。



#### 三色标记与增量标记

**三色标记法（tri-color marking）**：是把对象分为白、灰、黑三种状态以描述标记进度的算法，白色表示尚未访问，灰色表示已发现但子引用未扫描，黑色表示自身与子引用均已扫描。**增量标记（incremental marking）**：是把一次完整标记拆成多个片段、在脚本执行的间隙分段推进的做法。

- 颜色语义：白色是回收候选，灰色是待处理队列，黑色是确认存活。
- 推进方式：每轮从灰色队列取出对象，扫描其引用并把子对象标灰，自身转黑。
- 增量动机：完整标记需要暂停脚本，停顿过长会造成掉帧，拆分后单次停顿显著缩短。
- 写屏障（write barrier）：标记期间脚本修改引用时，引擎通过写屏障把被覆盖的引用重新标灰，防止存活对象被漏标。

```js
// 增量标记期间脚本仍会修改引用，写屏障负责维持三色不变式
const registry = new Map();

function registerListener(id, handler) {
  registry.set(id, handler);          // 新增引用需被重新扫描
  return () => registry.delete(id);   // 注销后引用断开，对象可被回收
}

const off = registerListener("tick", () => {});
off();
```

> 三色不变式要求黑色对象不能直接指向白色对象，写屏障的作用正是在脚本破坏该条件时把它修正回来。这是增量标记与并发标记能够安全运行的前提。

**速记**：三色标记记录进度，增量标记把一次停顿拆成多段，写屏障保证不漏标。



#### 并发与并行回收

**并行回收（parallel collection）**：是多个回收线程同时承担同一批标记或清理任务、但期间主线程仍需暂停的做法。**并发回收（concurrent collection）**：是回收线程与主线程同时运行、仅在少数关键节点短暂同步的做法。

- 并行侧重缩短总时长：任务被分摊到多个线程，暂停时间随线程数下降。
- 并发侧重减少暂停：标记与清理的大部分工作在后台线程完成，主线程只做少量同步。
- 并发清理：回收线程扫描并释放不可达对象的同时，主线程可以继续执行脚本。
- 剩余停顿：并发方案仍需要短暂同步，只是单次停顿被压缩到毫秒级。

```js
// 后台回收线程与主线程同时工作，脚本代码无需感知
function renderPath(points) {
  return points.map((point) => `${point.x},${point.y}`).join(" ");
}

const points = Array.from({ length: 5000 }, (_, index) => ({ x: index, y: index % 10 }));
console.log(renderPath(points).length > 0);   // true
```

> [!IMPORTANT]
> **重要内容**：并发与增量回收会让内存指标呈锯齿状波动，读取内存面板的数值时应关注长时间趋势，而不是单次采样的高低。

**速记**：并行是多线程分担总时长，并发是与主线程同时运行，两者都压缩单次停顿。



### 内存泄漏的典型成因

**内存泄漏（memory leak）**：是对象已经不再被业务需要，却仍能被根对象访问到，因而永远不进入回收判定。这一模块列出浏览器中最常见的四类成因与对应的修复方向。

#### 意外的全局引用

**意外的全局引用**：是变量被写入全局对象而长期存活，导致其指向的整棵对象图无法回收的情形。

- 未声明赋值：在非严格模式下给未声明变量赋值，会在全局对象上创建属性。
- 挂载到全局：调试期把对象挂在 window 或 globalThis 上，上线后忘记移除。
- this 指向错误：普通函数被独立调用时，非严格模式下 this 指向全局对象，属性随之落到全局。
- 修复方向：脚本启用严格模式或使用模块作用域，调试用的全局挂载在逻辑结束时显式删除。

```js
"use strict";

function loadSettings() {
  settingsCache = { theme: "dark" };   // 报错：未声明的变量，避免污染全局
}
// loadSettings();

const debugState = { nodes: [] };
globalThis.debugState = debugState;    // 调试期挂载
delete globalThis.debugState;          // 使用完毕立即移除
```

> 模块作用域与严格模式能在语法层面拦住大部分意外全局引用，这是现代前端工程默认配置带来的隐性收益。

**速记**：未声明赋值与调试挂载都会在全局留下长期引用，用完即删。



#### 未清理的定时器与监听器

**定时器与监听器泄漏**：是定时器回调或事件监听器在业务结束后仍被引擎登记，使回调闭包捕获的对象持续可达的情形。

- 定时器：setInterval 的回调在下一次触发前一直可达，清除需调用 clearInterval 并传入其返回的标识。
- 监听器：addEventListener 登记的监听器会持有回调，移除需用 removeEventListener 并传入相同的 type、listener 与 options。
- 结构变更：把节点从文档中移除不会自动注销挂在其上的监听器，监听器仍持有节点与闭包。
- 修复方向：组件销毁时统一注销，或使用带 signal 选项的监听器配合 AbortController 一次性解除。

```js
const controller = new AbortController();

function attachListeners(target) {
  const onScroll = () => { /* 读取滚动位置 */ };
  target.addEventListener("scroll", onScroll, { signal: controller.signal });
  return onScroll;
}

attachListeners(window);
controller.abort();   // 一次调用解除该 signal 登记的全部监听器
```

> [!WARNING]
> **警告内容**：setInterval 与 addEventListener 不会因为节点被移出文档而自动失效，忘记注销会让回调、闭包与其捕获的数据在整个页面生命周期内持续占用内存。

**速记**：定时器靠 clearInterval 清除，监听器靠 removeEventListener 或 signal 解除。



#### 游离节点与闭包滞留

**游离节点（detached DOM）**：是已从文档树移除、但仍被脚本引用所指向的 DOM 节点。**闭包滞留**：是闭包捕获了外层变量，使本该结束生命的变量因闭包本身可达而继续存活的情形。

- 游离节点成因：脚本持有了节点引用，或数组、对象属性、监听器仍在引用它。
- 内存代价：节点本身连同其子树、样式数据与绑定状态一起被保留。
- 闭包滞留成因：闭包持有大对象，而闭包又被全局缓存或长期存活的回调引用。
- 修复方向：断开对已移除节点的引用，闭包中只捕获必要字段而不是整个大对象。

```js
let detachedPanel = null;

function removePanel() {
  const panel = document.querySelector(".panel");
  detachedPanel = panel;   // 引用被保留，节点成为游离节点
  panel.remove();
}

// 释放：断开引用后节点才可回收
detachedPanel = null;
```

> 在内存面板中，游离节点会被单独归类统计。排查时依据「游离节点数量是否随操作次数单调增长」判断，比只看总内存更可靠。

**速记**：移除节点还要断开引用，闭包只捕获必要字段以避免滞留。



#### 无界缓存与弱引用

**无界缓存**：是没有容量上限与淘汰策略、随调用次数持续增长的缓存结构。**WeakMap**：是键必须为对象、键被回收时对应条目自动消失的映射类型，由 new WeakMap() 创建，常用方法 set(key, value)、get(key)、has(key)、delete(key) 均以对象键为参数。**WeakRef**：是只弱引用一个对象的包装类型，由 new WeakRef(target) 创建，用 deref() 取回目标对象或得到 undefined。**FinalizationRegistry**：是登记清理回调的机制，构造时传入 callback，再用 register(target, heldValue) 登记目标对象。

- WeakMap 的弱引用只作用于键：键不可达则整条记录消失，值不会脱离键被单独保留。
- WeakRef 的取值可能失效：deref() 返回 undefined 表示目标已被回收，调用方必须处理该分支。
- FinalizationRegistry 的回调时机不确定：只适合做统计与日志，不适合承担业务逻辑。
- 修复方向：为缓存设置容量上限与淘汰策略，或把对象的附属数据改放进以对象为键的 WeakMap。

```js
const elementState = new WeakMap();   // 键为 DOM 节点，节点移除后条目自动消失

function markVisited(element) {
  elementState.set(element, { visitedAt: Date.now() });
  return elementState.get(element).visitedAt;
}

const target = document.createElement("div");
console.log(typeof markVisited(target));   // "number"

const holder = new WeakRef(target);
console.log(holder.deref() === target);    // true
```

> [!CAUTION]
> **注意内容**：WeakMap 的键一旦只被 WeakMap 引用就会随时消失，因此不能把 WeakMap 当普通缓存使用；需要按业务条件控制存活时长的数据应使用 Map 并自行实现淘汰。

**速记**：缓存要设上限，对象键的附属数据用 WeakMap，弱引用取值必须先判空。



### 内存问题排查：手动释放与性能面板

排查分两步：先用释放手段缩小怀疑范围，再用内存面板的采样数据确认增长来自哪条引用链。这一步依赖工具读法而不是经验猜测。

#### 主动释放的手段

**主动释放**：是脚本通过断开引用或注销登记，让对象提前失去可达性的操作集合。

- 断开引用：把不再使用的对象属性置为 null，或从数组、Map 中删除对应条目。
- 注销回调：clearTimeout、clearInterval、removeEventListener 分别接收定时器标识与监听器的 type、listener、options。
- 批量解除：AbortController 的 abort 方法可一次性解除所有携带同一 signal 的监听器与进行中的请求。
- 缓存治理：为缓存设置容量上限与淘汰策略，超出上限时删除最久未访问的条目。

```js
function createLruCache(capacity) {
  const entries = new Map();

  function setEntry(key, value) {
    if (entries.has(key)) entries.delete(key);
    entries.set(key, value);
    if (entries.size > capacity) {
      const oldestKey = entries.keys().next().value;   // 最久未访问的键
      entries.delete(oldestKey);
    }
  }

  return { setEntry, getEntry: (key) => entries.get(key) };
}

const lru = createLruCache(2);
lru.setEntry("a", 1);
lru.setEntry("b", 2);
lru.setEntry("c", 3);             // 超出上限，键 a 被淘汰
console.log(lru.getEntry("a"));   // undefined
```

> 手动置空只能断开脚本持有的那一份引用。若对象还被监听器、定时器或闭包捕获，置空无效；排查时必须沿引用链找到全部持有者。

**速记**：置空、注销、abort 与限容缓存是四种主动释放手段，置空只断开单条引用。



#### 堆快照的读法

**堆快照（heap snapshot）**：是内存面板在某一时刻对堆中全部对象、引用关系与占用大小做的一次完整记录。

- Shallow Size：对象自身占用的字节数，不含它引用的其他对象。
- Retained Size：该对象被回收后能连带释放的字节数，含它独占的那部分引用图。
- Distance：从根对象出发到该对象的最短引用链长度，数值越大说明离根越远。
- Retainers：指向该对象的持有者列表，是定位泄漏源头的关键视图。
- Comparison：两次快照的差集视图，可直接看到新增对象与新增数量。

```js
// 复现步骤：连续操作后各拍一次快照，用 Comparison 视图比较
function pushPayload(store) {
  store.push({ id: store.length, payload: new Array(1000).fill("x") });
  return store.length;
}

const store = [];
for (let round = 0; round < 50; round++) pushPayload(store);
console.log(store.length);   // 50
// 保留 store 这个引用不放，快照里即可看到 50 条新增记录
```

> 读快照的顺序是先看 Comparison 视图里的增量，再看某个对象的 Retainers，最后沿引用链回溯到脚本代码；先看总量容易被正常的缓存与懒加载数据干扰。

**速记**：先看 Comparison 找增量，再看 Retainers 回溯持有者，Retained Size 判断释放收益。



#### 分配时间线与排查流程

**分配时间线（allocation instrumentation on timeline）**：是记录一段时间内每次分配的对象与发生时刻、并按时间轴展示的采样方式。**分配采样（allocation sampling）**：是按概率抽取部分分配事件、开销更低的采样方式。**performance.memory**：是部分浏览器提供的非标准内存指标对象，含 usedJSHeapSize、totalJSHeapSize、jsHeapSizeLimit 三个属性，仅适合观察趋势。

- 时间线适合定位某次交互引发的分配尖峰，能看到分配发生在哪个调用栈。
- 采样适合长时间记录，开销小，但统计不精确、可能漏掉峰值。
- performance.memory 的读数受回收时机影响呈锯齿波动，不作为精确口径使用。
- 排查流程：记录基线快照，重复触发目标操作，再拍快照比对增量，最后在 Retainers 中定位持有者并修复验证。

```js
// 手动触发一次回收后再读数，可减少锯齿干扰
function readHeapUsage() {
  if (typeof performance.memory === "undefined") return null;
  return {
    used: performance.memory.usedJSHeapSize,
    total: performance.memory.totalJSHeapSize,
  };
}

const first = readHeapUsage();
// ...执行待测操作...
const second = readHeapUsage();
console.log(first, second);   // 观察两次读数之间的趋势
```

> 若怀疑泄漏，判定标准是「多次重复同一操作后，回收后的内存基线持续抬高」。只涨不落是泄漏，涨落交替属于正常的分配与回收。

**速记**：时间线抓分配尖峰，采样适合长期记录，基线逐轮抬高才判定为泄漏。
