## V8 引擎与 JavaScript 执行优化

### V8 是什么与它的组件

**V8 引擎与它的组件** 决定了一段 JavaScript 从文本变成机器指令的过程中，各阶段由谁负责、开销落在哪里。

#### 引擎与宿主环境的分工

**JavaScript 引擎**：是执行 JavaScript 代码的程序，负责把源码翻译为可执行指令并管理运行时的对象与内存。**V8**：是 Google 开发、被 Chrome 与 Node.js 采用的 JavaScript 引擎。

- 分工边界：引擎只实现语言语义与标准库，DOM、定时器、文件系统等能力由宿主环境提供。
- 宿主映射：浏览器里的 window 与 document 来自渲染进程，并不属于引擎自身。
- 一致性：同一份引擎嵌入不同宿主，语言行为一致，平台 API 各不相同。

```js
const numbers = [3, 1, 2].sort((a, b) => a - b); // 语言与标准库由引擎提供
console.log(numbers); // 输出能力由宿主提供
// [1, 2, 3]
```

> 同一段数组排序在浏览器与 Node.js 中表现一致，而涉及 DOM 或文件系统的代码无法跨宿主直接运行。

**速记**：引擎负责语言与标准库，宿主负责平台 API，两者边界决定代码的可移植性。



#### 引擎内部的主要组件

**解析器（parser）**、**解释器（interpreter）**、**优化编译器（optimizing compiler）** 与 **运行时（runtime）** 是引擎的主要组成部分，分别承担语法树构造、字节码执行、热点代码编译与对象内存管理。

- 解析器：把源码拆成词法单元并构造抽象语法树。
- 解释器：把抽象语法树转为字节码并逐条执行，启动阶段无需整段编译。
- 优化编译器：依据运行中收集的类型反馈为热点函数生成机器码。
- 运行时：提供隐藏类、内联缓存与内存分配等支撑结构。

```js
function addNumbers(a, b) {
  return a + b;
}
// 首次调用由解释器执行，反复调用后热点代码交给优化编译器
for (let round = 0; round < 100000; round += 1) {
  addNumbers(round, round + 1);
}
// 循环次数仅示意，热点判定的内部阈值由引擎决定，不对外承诺
```

> 组件的划分与命名会随版本演进，理解职责边界比记住具体模块名更重要。

**速记**：解析、解释、优化编译与运行时四类职责共同构成引擎的执行链路。



#### 引擎与渲染进程的关系

**引擎与渲染进程的关系**：V8 运行在渲染进程的主线程或工作线程上，只负责 JavaScript 的执行，不参与 HTML 解析、样式计算与绘制。

- 线程归属：主线程上的引擎负责页面脚本，每个 Web Worker 另有独立的引擎实例。
- 堆隔离：主线程与工作线程的 JavaScript 堆相互独立，只能通过消息传递数据。
- 阻塞影响：引擎在主线程长时间执行脚本会推迟渲染管线（详见本主题第 9 篇 事件循环与渲染时机）。

```js
const computeWorker = new Worker("worker.js");
computeWorker.postMessage({ task: "compute" });
computeWorker.onmessage = (event) => console.log("结果", event.data);
// 工作线程内的引擎独立执行，不阻塞主线程的渲染
```

> 引擎与渲染管线是渲染进程内两条并行的职责线，引擎调用后者提供的 DOM 接口，但不参与其内部阶段。

**速记**：引擎运行在主线程或工作线程内，只做脚本执行，线程之间以消息而非共享堆通信。



### 解析与预解析与字节码

**解析与预解析与字节码** 描述的是源码进入执行之前的准备阶段，这一阶段的成本直接体现在页面启动速度上。

#### 解析与预解析

**解析（parsing）**：是把源码转换为抽象语法树的完整过程。**预解析（pre-parsing）**：是只检查语法合法性、跳过函数体细节的轻量过程。

- 完整解析：用于立即执行的顶层代码与确定会被调用的函数。
- 预解析：用于暂不调用的函数体，只记录其边界与语法是否合法。
- 权衡：减少启动期开销，代价是该函数首次被真正调用时需要重新完整解析。

```js
function heavyTask() {
  // 函数体暂不执行，先被预解析，不生成完整语法树
  return Array.from({ length: 1000 }, (_, index) => index * 2);
}
console.log(typeof heavyTask); // "function"
```

```js
function runImmediately() {
  // 外层函数定义后立即调用，内部函数体会一起进入完整解析
  function innerTask() {
    return Array.from({ length: 500 }, (_, index) => index + 1);
  }
  return innerTask();
}
console.log(runImmediately().length); // 500
```

> [!NOTE]
> **提醒内容**：外层函数若在定义后立即被调用，其内部函数体会一起进入完整解析，预解析带来的启动收益随之消失。

**速记**：完整解析构造语法树，预解析只验语法，惰性推迟到真正调用时才付出完整成本。



#### 字节码与惰性编译

**字节码（bytecode）**：是介于源码与机器码之间的中间指令序列，由解释器逐条执行，生成快、体积小。**惰性编译（lazy compilation）**：指函数体在首次调用前不生成字节码。

- 生成时机：函数首次执行时把抽象语法树编译为字节码。
- 反馈收集：字节码执行期间记录参数与属性的实际类型，供后续优化使用。
- 性能定位：字节码快于语法树遍历、慢于机器码，是冷代码的主要执行形式。

```js
function sumUpTo(limit) {
  let total = 0;
  for (let index = 1; index <= limit; index += 1) {
    total += index;
  }
  return total;
}
console.log(sumUpTo(10)); // 55
```

> 惰性编译让启动阶段只付出必需的编译成本，未被调用的函数直到被用到才生成字节码。

**速记**：字节码是逐条执行的中间指令，函数体按需生成，兼顾启动速度与执行速度。



#### 源码规模对启动的影响

**源码规模对启动的影响**：指脚本体积越大、顶层可执行语句越多，完整解析与字节码生成的花费越高，主线程启动阶段被占用越久。

- 顶层语句：模块顶层会立即执行的代码全部需要完整解析。
- 大函数体：体积巨大的单个函数难以拆分，首次调用即产生明显停顿。
- 收敛做法：控制单文件顶层代码量，把大函数拆小，把重计算移出启动路径。

```js
// 反例：把大量初始化逻辑堆在模块顶层，启动时必须完整解析并执行
// const lookupTable = buildLookupTable(200000);
// const sortedKeys = Object.keys(lookupTable).sort();
```

> 拆分模块与代码分割属于构建期手段（详见 前端/构建工具 主题），引擎侧能做的是让被解析的函数更小。

**速记**：启动开销随顶层代码量与函数体规模上升，拆分与延后是主要收敛方向。



### 执行与内联缓存与隐藏类

**执行与内联缓存与隐藏类** 是引擎让属性访问与函数调用变快的核心机制，理解它们才能写出对引擎友好的代码。

#### 隐藏类与对象布局

**隐藏类（hidden class）**：是引擎为对象建立的内部结构描述，记录属性名到内存偏移的映射，使属性访问可以用固定偏移取代字典查找。

- 共享机制：以相同方式创建的对象共享同一隐藏类。
- 迁移代价：新增或删除属性会触发隐藏类迁移并生成新的结构描述。
- 稳定写法：在构造函数或对象字面量中一次定义全部属性，且顺序保持一致。

```js
function makePoint(x, y) {
  return { x: x, y: y };
}
const firstPoint = makePoint(1, 2);
const secondPoint = makePoint(3, 4);
// 两个对象结构一致，共享同一隐藏类
console.log(firstPoint.x + secondPoint.y); // 5
```

```js
function makeLoosePoint() {
  const point = {};
  point.x = 1; // 空对象到含 x 的结构，第一次迁移
  point.y = 2; // 含 x 到含 x、y 的结构，第二次迁移
  return point;
}
console.log(makeLoosePoint().y); // 2
```

> 隐藏类描述的是结构而非取值：属性值不同不影响共享，属性集合与定义顺序不同才会让结构分叉。

**速记**：隐藏类把属性名映射为固定偏移，结构一致即共享，增删属性会触发迁移。



#### 内联缓存

**内联缓存（inline cache）**：是在属性访问点或调用点缓存上次遇到的隐藏类与处理方式，使相同形态的后续访问可以直接复用结果。

- 单态：访问点始终遇到同一隐藏类，缓存命中率最高。
- 多态：访问点遇到少数几种隐藏类，引擎记录多条缓存，速度略有下降。
- 超多态：形态过多时退化为通用查找，缓存不再起作用。

```js
function readX(point) {
  return point.x; // 调用点缓存 point 的隐藏类
}
console.log(readX({ x: 1, y: 2 })); // 1
console.log(readX({ x: 3, y: 4 })); // 3，同一形态，缓存命中
```

> [!CAUTION]
> **注意内容**：对热点对象使用 delete 运算符删除属性会改变其隐藏类，并使引用该对象的访问点退化为多态，性能损失在循环中会被放大。

**速记**：内联缓存按访问点的隐藏类命中，形态越单一命中越多，形态过多即失效。



#### 数组的元素种类

**元素种类（elements kinds）**：是引擎为数组元素记录的类型标签，同一种类下数组按连续内存访问，种类变化会让访问路径回退。

- 常见种类：小整数、双精度浮点数、普通对象等各有独立标签。
- 稠密与稀疏：出现空洞或被当作字典使用时，访问方式从连续下标转为查找。
- 收敛写法：一个数组只存同一种类型的元素，避免中途混入其他类型。

```js
const scores = [90, 85, 77]; // 小整数数组，按连续内存访问
const ratios = [0.5, 0.25]; // 双精度浮点数组
// 反例：mixed 混装数字与字符串，元素种类不再单一
const mixed = [1, "two", 3];
console.log(scores[0] + ratios[0]); // 90.5
```

> 越界写入与过大的预分配都会让数组转向稀疏表示，填充方式对访问速度有实际影响。

**速记**：数组元素种类单一则走连续内存访问，混装类型或稀疏化都会让访问回退。



### JIT 编译与优化与去优化

**JIT 编译与优化与去优化** 是引擎在运行中提升速度又可能推翻自身假设的过程，也是性能波动的主要来源。

#### 即时编译与优化

**即时编译（just-in-time compilation，JIT）**：是在程序运行期间把热点字节码编译为机器码的技术，用于兼顾启动速度与运行速度。

- 热点判定：引擎统计函数调用频次与循环回边次数，达到内部阈值后触发优化。
- 优化输入：以字节码执行阶段收集的类型反馈作为推测依据。
- 优化结果：属性访问按固定偏移读取，数值运算使用原生数值指令。

```js
function computeTotal(values) {
  let total = 0;
  for (let index = 0; index < values.length; index += 1) {
    total += values[index];
  }
  return total;
}
// 反复传入数字数组，函数依据数值型反馈被优化
for (let round = 0; round < 10000; round += 1) {
  computeTotal([1, 2, 3, 4]);
}
```

```js
function spinHotLoop() {
  let total = 0;
  for (let index = 0; index < 100000; index += 1) {
    total += index; // 循环回边反复执行，是优化编译器关注的热点
  }
  return total;
}
console.log(spinHotLoop() > 0); // true
```

> 优化是引擎依据运行表现的投机行为：类型稳定时收益最大，类型突变时优化会被撤销。

**速记**：JIT 以热点判定与类型反馈为前提把字节码编译为机器码，收益依赖类型稳定。



#### 去优化

**去优化（deoptimization）**：是优化代码所依赖的类型假设被推翻时，引擎丢弃已编译机器码并回到字节码执行的过程。

- 触发条件：热点函数收到与优化假设不符的参数或属性类型。
- 处理流程：回退到字节码继续执行，并可能依据新的反馈重新优化。
- 代价：反复优化与去优化带来额外开销，性能可能低于稳定的解释执行。

```js
function addNumbers(a, b) {
  return a + b;
}
for (let round = 0; round < 10000; round += 1) {
  addNumbers(round, round + 1); // 一直是数字，按数值型优化
}
addNumbers("1", "2"); // 反例：传入字符串，类型假设被推翻，触发去优化
// "12"
```

> [!IMPORTANT]
> **重要内容**：让同一函数的参数类型长期保持一致，是避免去优化最有效的手段；用同一函数兼作多种类型的处理会持续触发优化与回退。

**速记**：去优化是类型假设被推翻后的回退，稳定参数类型是最直接的规避方式。



#### 优化状态的观测

**优化状态的观测**：指借助引擎提供的诊断能力查看函数是否已被优化、优化后是否又被撤销，用于定位类型不稳定点。

- 诊断方式：引擎提供打印字节码与优化状态的命令行选项，也可通过宿主工具查看。
- 观测重点：同一函数反复出现优化与去优化记录，说明调用处的类型不稳定。
- 版本差异：诊断选项的名称与输出随版本变化，只作为本机排查手段，不作为稳定接口。

```bash
# 通过 Node.js 暴露的引擎选项查看可用的诊断开关
node --v8-options | grep -i opt
```

> 诊断输出面向引擎内部实现，不同版本可能不同，排查结论应以本机当时输出的内容为准。

**速记**：用引擎诊断选项观察优化与去优化记录，重点盯住反复波动的函数。



### 代码层面的性能写法

**代码层面的性能写法** 是把前述机制落到日常代码中的一组可执行约定，目标是让热点路径的类型与结构保持稳定。

#### 保持对象结构稳定

- 在构造函数或对象字面量中一次定义全部属性，定义顺序保持一致。
- 不在热路径上新增或删除属性，需要可选字段时预置默认值。
- 用同一构造函数创建同类对象，避免同一逻辑产出多种结构。
- 把一次性补齐的属性合并到创建语句中，而不是分多次赋值。

```js
function makeRecord(id, name) {
  // 反例：先建空对象再逐个补属性，隐藏类发生多次迁移
  // const record = {};
  // record.id = id;
  // record.name = name;
  const record = { id: id, name: name }; // 一次性定义，隐藏类稳定
  return record;
}
console.log(makeRecord(1, "Ada").name); // "Ada"
```

> 结构稳定的收益在于属性访问走固定偏移，读写接近定长结构的开销，而非哈希查找。

**速记**：属性一次定义、顺序固定、不增删，对象结构稳定则访问走固定偏移。



#### 减少热路径上的意外类型

- 参数类型保持一致，不让同一函数在不同调用处收到不同类型。
- 数值运算保持数值，避免运算中途混入字符串引发隐式转换。
- 循环体内不做与迭代无关的类型判断，把分支移到循环之外。
- 集合内元素类型统一，避免同一数组或对象在不同时刻装入不同结构。

```js
function sumPrices(prices) {
  let total = 0;
  for (let index = 0; index < prices.length; index += 1) {
    total += prices[index]; // 元素保持数字，循环体内不做类型判断
  }
  return total;
}
console.log(sumPrices([10, 20, 30])); // 60
console.log(sumPrices(["10", "20"])); // 反例："1020"，类型变化会触发去优化
```

> 类型稳定并非完全不写分支，而是让每条热路径上的类型保持单一，把多样性交给调用方处理。

**速记**：热路径上参数与元素类型保持单一，隐式转换与临时分支都会破坏优化前提。



#### 避免拖慢执行的常见写法

- 避免在热路径上使用 eval 与 with，它们会阻止作用域与变量的静态分析。
- 避免在循环里反复创建结构不同的临时对象与闭包。
- 避免对同一数组混用多种元素类型，也避免频繁改变数组长度。
- 避免在同一访问点轮流处理多种隐藏类的对象，把处理分支拆开更有利。

```js
function buildIndex(names) {
  const index = {}; // 值类型统一为数字，隐藏类与元素种类都稳定
  for (let position = 0; position < names.length; position += 1) {
    index[names[position]] = position;
  }
  return index;
}
console.log(buildIndex(["Ada", "Grace"]).Grace); // 1
```

> [!TIP]
> **建议内容**：优化前先用性能面板确认热点确实落在 JavaScript 执行上，再按上述写法调整，避免为不存在的瓶颈增加代码复杂度。

> 引擎的内存分配与垃圾回收机制详见本主题第 11 篇 内存管理与垃圾回收，本篇只讨论执行路径与代码写法。

**速记**：避开动态作用域与结构频繁变化的写法，让热路径的形态在运行期保持稳定。
