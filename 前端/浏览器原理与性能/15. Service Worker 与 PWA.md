## Service Worker 与 PWA

Service Worker 与 PWA 处理同一类需求：让网页具备接近原生应用的能力，包括离线可用、可安装到桌面，以及在页面关闭后被系统事件唤醒继续工作。前者是浏览器提供的脚本运行机制，后者是在该机制之上组合出来的一套应用形态。

一条前提贯穿全篇：Service Worker 只能在安全上下文（secure context）中注册，即页面通过 HTTPS 提供，本地开发使用的 localhost 属于例外。该条件不满足时注册直接失败，后续能力无从谈起。

### Service Worker 是什么与生命周期

Service Worker 是一段由浏览器在页面之外独立运行的脚本，充当页面与网络之间的可编程代理。它不绑定任何页面，按事件被唤醒、空闲时被终止，因此运行状态需要显式保存在缓存或数据库中，不能依赖脚本内的全局变量长期驻留。

#### 定位与运行环境

**Service Worker（服务工作线程）** 是什么：是一类运行在工作线程（worker）中的脚本，没有 DOM 访问权，不能直接操作页面，只能通过网络代理、消息传递与缓存读写间接影响页面。

- 线程独立：运行在主线程之外，脚本执行不阻塞页面渲染与交互。
- 无 DOM：脚本内不存在 document 与 window，全局对象是 self。
- 事件驱动：仅在 install、activate、fetch、push、sync 等事件到来时被唤醒，处理完毕可被浏览器回收。
- 代理网络：页面发出的请求可以被 fetch 事件接管，返回缓存的响应或改写后的响应。
- 单实例：同一个作用域内，同一时刻只有一个处于激活状态的工作线程实例。

> 与 Web Worker 的区别在于控制范围：Service Worker 代理的是页面与网络之间的请求，Web Worker 只承担页面交给它的计算任务。

**速记**：Service Worker 是工作线程中的网络代理，无 DOM、事件驱动、可被回收。



#### 安全上下文与作用域约束

**安全上下文（secure context）** 是什么：是浏览器认定页面处于可信传输环境的状态，HTTPS 页面与 localhost 属于安全上下文，普通 HTTP 页面不是。

- 注册限制：非安全上下文中调用注册方法会抛出错误，脚本不会被执行。
- 作用域（scope）：决定该工作线程能接管哪些页面请求，默认是脚本所在目录及其子目录。
- 作用域收紧：注册时可传入 scope 参数缩小范围，但只能限制在脚本所在路径之下。
- 服务端配合：通过 Service-Worker-Allowed 响应头可以放宽作用域的上限。
- 生效范围：只有作用域内的页面请求会被接管，作用域外的页面不受影响。

```js
navigator.serviceWorker
  .register('/sw.js', { scope: '/app/' })
  .then((registration) => {
    console.log(registration.scope); // https://example.com/app/
  })
  .catch((error) => {
    console.error('注册失败', error);
  });
```

> [!NOTE]
> **提醒内容**：作用域一旦放宽就很难收回，已安装该应用的浏览器仍按旧作用域受控，调整前需评估存量用户。

**速记**：注册要求安全上下文，作用域决定接管范围且默认不超过脚本所在目录。



#### 生命周期阶段

**Service Worker 的生命周期** 是什么：是从注册到生效再到被替换的一组固定阶段，由浏览器推进，脚本只能影响单个阶段的完成时机。

- installing：install 事件触发，通常在此预缓存资源，过程中出错则整次安装作废。
- installed 与等待：安装完成但旧版本仍在控制页面，新版本停在等待状态。
- activating：旧版本控制的页面全部关闭，或新版本跳过等待之后，触发 activate 事件。
- activated：正式接管 fetch、message 等事件，开始影响页面请求。
- redundant：被新版本取代或安装失败，该实例被废弃。

```js
// sw.js
self.addEventListener('install', (event) => {
  event.waitUntil(
    caches.open('app-v1').then((cache) => cache.addAll(['/', '/index.html']))
  );
});

self.addEventListener('activate', () => {
  console.log('已激活，开始接管请求');
});
```

> 阶段推进的主动权在浏览器侧，脚本不能强行跳到下一阶段，只能在当前阶段内延长或放弃。

**速记**：生命周期分安装、等待、激活、已激活与废弃，脚本只能延长当前阶段。



#### 注册与状态流转

**状态流转** 是什么：是通过注册对象上的属性与事件观察当前实例处于哪个阶段的过程，用于提示更新或排查未生效问题。

- 三个属性：registration.installing、registration.waiting、registration.active 分别指向对应阶段的实例。
- updatefound：新的工作线程开始安装时触发，可在此时读取新实例的状态。
- update：主动检查脚本是否有更新，常用于页面重新可见时。
- 重复注册：同一作用域重复注册不会重复安装，浏览器按脚本内容是否变化决定是否更新。
- 就绪等待：navigator.serviceWorker.ready 返回已激活实例的 Promise，用于依赖离线能力的初始化。

```js
navigator.serviceWorker.register('/sw.js').then((registration) => {
  registration.addEventListener('updatefound', () => {
    console.log('发现新版本', registration.installing.state); // installed 等
  });
});
```

**速记**：通过 installing、waiting、active 三个属性观察状态，updatefound 用于提示更新。



### 缓存策略与离线能力

该模块回答两个问题：响应如何被存下来，以及请求到来时如何决定返回缓存还是走网络。缓存读写使用 Cache API，决策发生在 fetch 事件内，两者共同构成离线能力的骨架。

#### Cache API 与缓存写入

**Cache API** 是什么：是一组以请求与响应为键值对的存储接口，通过 caches.open(cacheName) 打开具名缓存后读写，与 HTTP 缓存相互独立。

- caches.open(cacheName)：返回 Promise，解析为对应的 Cache 对象。
- cache.add(request) 与 cache.addAll(requests)：抓取并写入，任一请求失败则整体拒绝。
- cache.put(request, response)：直接写入一条响应，适合改写或合成后的响应。
- cache.match(request, options) 与 matchAll：按请求匹配，options 支持 ignoreSearch、ignoreMethod、ignoreVary。
- cache.keys() 与 cache.delete(request)：列出全部请求与删除单条，常用于版本清理。

```js
const cache = await caches.open('static-v1');
await cache.addAll(['/index.html', '/styles.css', '/app.js']);
const hit = await cache.match('/app.js', { ignoreSearch: true });
console.log(hit ? hit.status : 'miss'); // 200
```

> Cache API 存的是完整的响应对象而非 URL 字符串；响应体被读取过之后不能再次写入缓存。

**速记**：Cache API 以请求与响应为键值对，add、put、match、delete 是基本操作。



#### fetch 事件与请求拦截

**fetch 事件** 是什么：是页面发起受控请求时派发给工作线程的事件，脚本通过 event.respondWith 返回自定义响应，未调用则回退到默认的网络请求。

- event.request：本次请求的 Request 对象，含 url、method、mode 等属性。
- event.respondWith(responsePromise)：用返回的 Promise 决定响应的来源。
- event.waitUntil：在响应之外继续做后台工作，如把结果写入缓存。
- 接管范围：仅同源且处于作用域内的请求会被接管，跨源请求通常以不透明响应的形式出现。
- 放行：不调用 respondWith 即视为放行，浏览器按常规方式请求网络。

```js
self.addEventListener('fetch', (event) => {
  event.respondWith(
    caches.match(event.request).then((cached) => cached || fetch(event.request))
  );
});
```

> 非 GET 请求与部分特殊请求不会进入 fetch 事件，缓存策略只对可缓存的请求成立。

**速记**：fetch 事件用 event.respondWith 决定响应来源，不拦截即放行走网络。



#### 常见缓存策略

**缓存策略** 是什么：是「先查缓存还是先走网络、命中后是否更新」的固定组合，常见几类按资源特性取舍。

- 缓存优先（cache first）：先匹配缓存，未命中再请求网络并写入，适合带内容指纹的静态资源。
- 网络优先（network first）：先请求网络，失败或超时再读缓存，适合变化频繁的接口数据。
- 陈旧再验证（stale-while-revalidate）：先返回缓存，同时后台请求并更新缓存，兼顾速度与新鲜度。
- 仅网络与仅缓存：分别用于不应缓存的请求与完全离线可用的资源。
- 选择依据：资源能否版本化、能否容忍过期、请求频率高低。

```js
async function handleFetch(event) {
  const cached = await caches.match(event.request);
  const network = fetch(event.request)
    .then(async (response) => {
      const cache = await caches.open('data-v1');
      cache.put(event.request, response.clone());
      return response;
    })
    .catch(() => cached);
  return cached || network;
}

self.addEventListener('fetch', (event) => {
  event.respondWith(handleFetch(event));
});
```

> 混合策略的关键是「谁先返回」：缓存优先追求首字节速度，网络优先追求数据新鲜度，陈旧再验证在两者之间折中。

**速记**：缓存优先、网络优先与陈旧再验证是三类基本策略，按资源可版本化程度选择。



#### 离线回退与导航请求

**离线回退** 是什么：是在网络不可用时为导航请求返回兜底页面的做法，使离线状态仍能看到可用界面而非浏览器错误页。

- 判断导航：event.request.mode 为 navigate 时表示这是一次页面导航。
- 回退链：先匹配目标页面，再退到预缓存的应用外壳，最后返回离线页。
- 应用外壳（app shell）：把界面骨架与静态资源预缓存，内容区域由运行时的接口数据填充。
- 导航预加载：registration.navigationPreload 可让导航请求与工作线程启动并行发起。
- 兜底可用：兜底响应自身必须已被缓存，否则仍然白屏。

```js
self.addEventListener('fetch', (event) => {
  if (event.request.mode !== 'navigate') return;
  event.respondWith(
    fetch(event.request).catch(() =>
      caches.match('/offline.html').then((page) => page || Response.error())
    )
  );
});
```

**速记**：导航请求失败时回退到预缓存的离线页，兜底页面本身必须已被缓存。



### 缓存版本与更新与清理

该模块回答新版本上线时旧缓存如何退场。核心手段是把版本标识写进缓存名称，并在激活阶段清理不再使用的具名缓存，避免旧资源长期占据空间或与新资源混用。

#### 缓存名称与版本化

**缓存版本化** 是什么：是把版本标识写进缓存名称，使新旧版本各占一份具名缓存，互不覆盖。

- 命名约定：前缀加版本号，如 app-static-v1、app-static-v2。
- 更新做法：发布新版本时改动常量，install 事件即向新名称写入资源。
- 切换原子：等待期间旧缓存仍可用，替换在 activate 阶段一次性完成。
- 短期共存：新旧两份缓存同时存在，占用双份存储空间。
- 容量规则：Cache Storage 的配额与淘汰由浏览器统一管理，详见本主题第 12 篇 浏览器存储机制。

```js
const CACHE_NAME = 'app-static-v2';
const PRECACHE_URLS = ['/', '/index.html', '/app.js', '/styles.css'];
```

**速记**：把版本写进缓存名称，新旧资源各占一份具名缓存，切换原子但短期双份占用。



#### activate 阶段清理旧缓存

**清理旧缓存** 是什么：是在 activate 阶段遍历当前源下的全部具名缓存，删除不属于当前版本的缓存，并让新版本接管已打开的页面。

- 列出名称：caches.keys() 返回当前源下全部缓存名称。
- 过滤保留：命中当前名称的保留，其余交给 caches.delete(name)。
- 接管页面：self.clients.claim() 让尚未被控制的页面立即归入当前版本。
- 空间回收：删除后旧资源占用的空间可被回收，降低被浏览器整体淘汰的风险。
- 执行顺序：先清理再接管，避免两者之间出现短暂的缓存缺失。

```js
self.addEventListener('activate', (event) => {
  event.waitUntil(
    (async () => {
      const names = await caches.keys();
      await Promise.all(
        names.filter((name) => name !== CACHE_NAME).map((name) => caches.delete(name))
      );
      await self.clients.claim();
    })()
  );
});
```

> [!CAUTION]
> **注意内容**：清理阶段若误删仍被其他版本引用的缓存，未完成更新的浏览器会立即失去离线能力。

**速记**：activate 中对比 caches.keys() 与当前名称，删除旧缓存后再接管页面。



#### skipWaiting 与 clients.claim 的取舍

**skipWaiting** 是什么：是让处于等待中的新版本跳过等待、立即进入激活的方法；**clients.claim** 则是让已打开的页面立刻转向新版本控制。

- 立即生效：跳过等待可让修复尽快上线，适合安全类修复。
- 版本错配风险：旧页面可能仍在引用旧资源名，立即切换会引发新旧资源混用。
- 默认等待：常规功能迭代宜保持等待，由页面提示用户刷新后再激活。
- 消息通道：通过 postMessage 通知页面「新版本就绪」，页面刷新即完成切换。
- 判断依据：资源能否乱序混用、本次变更是否具有破坏性。

```js
// 由页面端在合适时机发送消息，工作线程再决定是否跳过等待
self.addEventListener('message', (event) => {
  if (event.data === 'skip-waiting') self.skipWaiting();
});
```

**速记**：skipWaiting 让新版本立即生效但可能引发版本错配，默认应等页面自行刷新。



#### 更新检测与内容比对

**更新检测** 是什么：是浏览器重新抓取工作线程脚本、并与已安装脚本比对内容是否一致的过程。

- 触发时机：导航到作用域内页面、调用注册方法时，以及显式调用 registration.update()。
- 比对方式：默认按脚本内容逐字节比对，内容完全一致即视为未更新。
- 缓存参与：updateViaCache 可取 all、imports、none，控制脚本请求是否使用 HTTP 缓存。
- 单文件限制：默认只比对工作线程脚本本身，importScripts 引入的脚本需要自行版本化。
- 调试手法：开发期在开发者工具中执行注销后重新注册，或勾选更新后刷新。

```js
// 主动检查更新，常在页面重新可见时调用
document.addEventListener('visibilitychange', () => {
  if (document.visibilityState === 'visible') {
    navigator.serviceWorker.getRegistration().then((reg) => reg && reg.update());
  }
});
```

**速记**：更新依赖脚本内容比对，改动脚本内容即可触发，引入的脚本需自行版本化。



### 推送与后台同步与通知

该模块覆盖三类脱离页面运行的能力：由服务端主动发起的推送、恢复网络后自动重试的后台同步，以及展示在系统层面的通知。三者的共同前提是用户已授权，且脚本已处于激活状态。

#### 推送链路与 Push API

**Push API** 是什么：是让服务端借助推送服务把消息投递到已订阅浏览器的接口，投递到达时以 push 事件通知工作线程。

- 订阅：registration.pushManager.subscribe(options)，options 至少包含 userVisibleOnly 为 true。
- 身份标识：options.applicationServerKey 传入服务端生成的公钥，用于标识应用身份。
- 订阅信息：订阅对象含 endpoint 与加密密钥，需要上报给应用自己的服务端。
- 到达处理：push 事件派发给工作线程，负载通过 event.data 读取。
- 前置条件：用户已授予通知权限并且当前存在有效订阅。

```js
const registration = await navigator.serviceWorker.ready;
const subscription = await registration.pushManager.getSubscription();
console.log(subscription ? subscription.endpoint : '尚未订阅');
```

> 推送通道由浏览器厂商的推送服务中转，端到端细节由浏览器与服务端约定，页面侧只需处理订阅与到达。

**速记**：Push API 由服务端投递消息，以 push 事件到达工作线程，订阅需要公钥与用户授权。



#### 通知的展示与点击处理

**通知展示** 是什么：是在工作线程内调用通知接口把消息呈现到系统层面，并处理用户的点击行为。

- 权限申请：Notification.requestPermission() 返回 Promise，结果为 granted、denied 或 default。
- 展示：self.registration.showNotification(title, options) 在工作线程中展示通知。
- 点击：notificationclick 事件触发，可在其中关闭通知并打开或聚焦页面。
- 复用窗口：clients.matchAll(options) 可找到已打开的页面，配合 focus 优先复用而非新开。
- 可见性要求：部分浏览器要求每条推送都产生用户可见的通知，否则可能撤销订阅。

```js
self.addEventListener('push', (event) => {
  const data = event.data ? event.data.json() : { title: '有新消息' };
  event.waitUntil(self.registration.showNotification(data.title, { body: data.body }));
});

self.addEventListener('notificationclick', (event) => {
  event.notification.close();
  event.waitUntil(clients.openWindow('/inbox'));
});
```

> [!TIP]
> **建议内容**：推送内容宜少而准，频繁打扰会导致用户关闭通知权限，而权限一旦被拒绝很难再申请回来。

**速记**：通知在工作线程中展示，notificationclick 处理点击，权限被拒后难以恢复。



#### 后台同步 Background Sync

**后台同步（Background Sync）** 是什么：是让浏览器在页面关闭后、网络恢复时替页面重试某个命名同步任务的机制。

- 注册：registration.sync.register(tag) 请求在恢复网络后触发名为 tag 的同步。
- 触发：网络恢复时向工作线程派发 sync 事件，事件对象带 tag 属性。
- 合并语义：同名 tag 只保证最终触发一次，与逐条排队的消息队列不同。
- 适用场景：离线提交表单、补传埋点、上传草稿等弱网下容易失败的写操作。
- 幂等要求：重试可能重复执行，服务端需按幂等键去重。

```js
self.addEventListener('sync', (event) => {
  if (event.tag === 'upload-draft') {
    event.waitUntil(uploadDraftToServer());
  }
});
```

**速记**：后台同步按标签注册，网络恢复后触发重试，写操作需保证服务端幂等。



#### 周期性同步与触发限制

**周期性后台同步（Periodic Background Sync）** 是什么：是在用户授权与浏览器调度允许的前提下，让某个同步任务按最小间隔重复触发的机制。

- 注册：registration.periodicSync.register(tag, options)，options 的 minInterval 为最小间隔。
- 查询：periodicSync.getTags() 列出已注册标签，unregister 取消注册。
- 权限查询：可通过权限接口查询周期性同步的授权状态。
- 触发不保证：浏览器依据站点参与度决定是否执行，可能长时间不触发。
- 兼容范围：实现范围有限，启用前需做能力检测，不能作为精确定时任务的替代。

```js
if ('periodicSync' in registration) {
  await registration.periodicSync.register('refresh-feed', {
    minInterval: 24 * 60 * 60 * 1000,
  });
}
```

> [!WARNING]
> **警告内容**：把周期同步当作定时器使用会导致功能在部分设备上长期不执行，时效性要求高的场景必须回落到页面内主动刷新。

**速记**：周期性同步由浏览器调度，只保证按最小间隔尝试触发，不能当作定时器。



### PWA 的组成与安装与可安装性

该模块把前述机制组合成一个可安装的应用形态。PWA 不是单一接口，而是一组能力的组合约定：安全上下文、应用清单与工作线程三者齐备，浏览器才认为它可以被安装。

#### 三要素与能力边界

**PWA（渐进式 Web 应用，Progressive Web App）** 是什么：是一类按特定条件组织的网页应用，使其可以被安装到设备、离线运行，并以独立窗口启动。

- 安全上下文：必须通过 HTTPS 提供，这是全部能力的前提。
- 应用清单：描述名称、图标、启动地址与启动方式。
- Service Worker：提供离线可用与请求控制能力。
- 渐进增强：能力缺失时降级为普通网页，而非直接不可用。
- 能力边界：仍受浏览器与操作系统限制，不能访问任意系统级接口。

> PWA 的定位是渐进增强的网页，而不是打包分发的原生应用；离线与安装是附加能力，基础功能不依赖它们。

**速记**：PWA 是安全上下文、应用清单与工作线程三者的组合，能力不足时降级为普通网页。



#### 应用清单的字段

**manifest（应用清单）** 是什么：是一个以 JSON 描述应用元信息的文件，由页面通过 link 元素以 rel 为 manifest 引用。

- 名称：name 为完整名称，short_name 用于空间不足时的显示。
- 启动：start_url 指定安装后的启动地址，scope 限定可安装与接管范围。
- 显示方式：display 可取 standalone、fullscreen、minimal-ui、browser。
- 图标：icons 数组按 sizes 提供多种尺寸，适配不同场景的展示需求。
- 配色：theme_color 影响界面主题色，background_color 用于启动画面底色。

```json
{
  "name": "示例应用",
  "short_name": "示例",
  "start_url": "/",
  "scope": "/",
  "display": "standalone",
  "background_color": "#ffffff",
  "theme_color": "#2563eb",
  "icons": [
    { "src": "/icons/icon-192.png", "sizes": "192x192", "type": "image/png" },
    { "src": "/icons/icon-512.png", "sizes": "512x512", "type": "image/png" }
  ]
}
```

```html
<link rel="manifest" href="/manifest.webmanifest" />
```

**速记**：应用清单用 JSON 描述名称、启动地址、显示方式、图标与配色，由页面引用生效。



#### 可安装性判定

**可安装性** 是什么：是浏览器判断一个站点能否被安装到设备的条件集合，由浏览器根据清单与工作线程的情况自行判定。

- 安全上下文：页面通过 HTTPS 提供。
- 清单有效：清单可被获取且包含名称、图标、启动地址与显示方式等必要字段。
- 图标尺寸：通常需要覆盖常见的多种尺寸，包括较大的方形图标。
- 离线能力：具备可离线工作的请求处理能力，通常由带 fetch 处理的工作线程承担。
- 判定可变：条件随浏览器与版本调整，实际结果以目标浏览器为准。

> [!IMPORTANT]
> **重要内容**：可安装性由浏览器判定，缺少任一必要项都可能不出现安装入口，上线前必须在目标浏览器中实测确认。

**速记**：可安装性取决于安全上下文、有效清单与离线能力，具体条件随浏览器调整。



#### 安装提示与安装后的差异

**安装提示** 是什么：是浏览器在判定站点可安装后触发的事件，允许页面在合适的时机主动唤起安装界面。

- 事件：浏览器认为可安装时在页面触发 beforeinstallprompt。
- 暂存：调用事件的 preventDefault() 可推迟默认提示，并把该事件对象暂存起来。
- 唤起：在用户手势中调用暂存对象的 prompt() 方法才会弹出安装界面。
- 结果：userChoice 返回 Promise，其 outcome 为 accepted 或 dismissed。
- 完成：appinstalled 事件在安装完成后触发，可用于清理页面上的安装引导。

```js
let deferredPrompt = null;

window.addEventListener('beforeinstallprompt', (event) => {
  event.preventDefault();
  deferredPrompt = event;
});

async function handleInstallClick() {
  if (!deferredPrompt) return;
  await deferredPrompt.prompt();
  const choice = await deferredPrompt.userChoice;
  console.log(choice.outcome); // accepted 或 dismissed
  deferredPrompt = null;
}
```

> 安装后以独立窗口运行，display 为 standalone 时没有地址栏，仍可用媒体查询 display-mode 在样式上区分运行形态。

**速记**：安装提示由 beforeinstallprompt 暂存、在用户手势中唤起，userChoice 给出用户选择。
