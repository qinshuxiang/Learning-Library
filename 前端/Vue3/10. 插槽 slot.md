## 插槽 slot

### 插槽的认识

#### 插槽是父组件向子组件投放内容的出口

**插槽（slot）**：是 Vue 组件实现**内容分发**的机制，父组件可以把一段模板内容投放到子组件指定的位置。

- 插槽的本质是**子组件模板里的出口**：子组件留好位置，父组件决定填什么。
- 投放的内容可以是文本、HTML 结构，也可以是**另一个组件**。
- 组件标签之间写的所有内容，默认都会被送进子组件的**默认插槽**。

> 插槽解决的问题是“**结构由外部决定**”：封装组件时内部逻辑固定，但某一块区域每个使用者想要的画面不同，把这块区域开成出口即可。

**速记**：子组件**留出口**，父组件**填内容**。



#### slot 元素是子组件模板中的占位符

**slot 元素**：写在子组件模板中的占位标签，父组件投放的内容最终**渲染在它的位置**。

- 子组件在模板中写一个 slot 元素作为出口，无需任何参数即可工作。
- 渲染时 slot 元素本身**不会出现在 DOM 里**，被替换为父组件投放的内容。
- 一个子组件可以有**多个 slot 出口**，配合 name 属性分发（见具名插槽）。

```html
<!-- 子组件 MyButton 的模板 -->
<button class="btn">
  <slot></slot>
</button>

<!-- 父组件使用时 -->
<MyButton>点我提交</MyButton>
```

> 渲染结果为 button 元素包裹文本“点我提交”。若父组件使用 MyButton 时标签之间什么都没写，slot 处将**渲染为空**。

**速记**：slot 是**占位出口**，渲染时被父内容替换。



#### 插槽与 props、事件并列构成组件通信的三大手段

**插槽的定位**：插槽与 props、事件并列，是组件通信的基础手段之一，专管**模板内容的注入**。

- props 传递的是**数据**，插槽传递的是**一段带结构的模板**。
- 典型场景：通用卡片、弹窗、布局组件，外壳由子组件实现，内部区块留给使用者。
- 与直接传 HTML 字符串相比，插槽内容是**真正的 Vue 模板**，可以使用指令、组件与插值表达式。

> props 回答「给你什么数据」，插槽回答「这块区域长什么样」，二者的详细选型对比见本章末尾。



### 后备内容

#### 后备内容是插槽的默认渲染

**后备内容（fallback content）**：写在 slot 元素内部的默认内容，父组件**没有投放内容时**渲染。

- 后备内容直接写在子组件模板的 slot 标签之间。
- 触发条件是父组件**未提供任何内容**，提供与否以渲染结果为准。
- 父组件一旦提供内容，后备内容整体被替换，**两者不会同时出现**。

```html
<!-- 子组件 SubmitButton 的模板 -->
<button type="submit">
  <slot>提交</slot>
</button>

<!-- 父组件一：未提供内容，渲染为 提交 -->
<SubmitButton></SubmitButton>

<!-- 父组件二：提供内容，渲染为 保存修改 -->
<SubmitButton>保存修改</SubmitButton>
```

> 后备内容让组件具备**开箱即用**的默认观感，又保留定制空间：不填有合理默认，要改随时可换。

**速记**：后备内容是**没填时的默认画面**。



#### 空白内容同样触发后备内容

**触发边界**：父组件标签之间只有空白或注释时，Vue 视为**未提供内容**，后备内容照常渲染。

- 标签之间完全为空，触发后备内容。
- 只有空格、换行等空白字符，**同样触发**后备内容。
- 渲染结果为非空白文本节点的内容（哪怕只有一个字符）会**覆盖**后备内容。

> [!NOTE]
> **提醒内容**：判断标准是“渲染产物是否为空”而非“标签里是否写了字”。仅含注释与空白的写法在视觉上像提供了内容，实际仍走后备，排查默认值不生效的样式问题时可从这一点入手。

**速记**：空白不算内容，**后备照常生效**。



#### 后备内容运行在子组件作用域

**后备内容的作用域**：后备内容写在子组件模板里，因此其中的表达式**访问子组件的数据**，与父组件无关。

- 后备内容中引用的变量在**子组件**中解析。
- 父组件投放的内容则在**父组件**中解析，二者作用域不同。
- 后备内容因此常被用来展示子组件自有的状态，例如默认文案、内置图标。

> [!TIP]
> **建议内容**：后备内容是演示“编译作用域”最直观的地方——同一段模板写在 slot 内还是写进父组件的投放区，变量的解析者完全不同，面试常拿这一点设问。

**速记**：后备内容**归子组件作用域管**。



### 具名插槽

#### name 属性给插槽命名

**具名插槽**：通过 name 属性命名的插槽出口，让一个组件拥有**多个可独立填充的位置**。

- 子组件为每个出口写 slot 元素，并用 name 属性起名，如 name="header"。
- name 是 slot 的**保留属性**，不会传给插槽内容，也不会进入 slot props。
- 出现多个出口时，Vue 按名字把父组件的各段内容**分发到对应位置**。

```html
<!-- 子组件 BaseCard 的模板 -->
<div class="card">
  <header>
    <slot name="header"></slot>
  </header>
  <main>
    <slot></slot>
  </main>
  <footer>
    <slot name="footer"></slot>
  </footer>
</div>
```

> 头部、主体、尾部三个出口构成的卡片组件，正是具名插槽最典型的落地场景：外壳与排版由组件锁定，三块内容全部交给使用者。

**速记**：name 开**多个出口**，内容按名分发。



#### v-slot:name 指定填充目标并以井号简写

**v-slot 指令**：写在 template 上的填充指令，冒号后接插槽名，指明这段内容填进哪个出口。

- 完整写法为 v-slot:header，表示填入 name 为 header 的出口。
- 井号简写：v-slot:header 可缩写为 #header，二者完全等价。
- 简写必须有参数才有意义：单独写 # 不带名字，不是合法指令。

```html
<BaseCard>
  <template v-slot:header>
    <h1>页面标题</h1>
  </template>

  <template #footer>
    <p>页脚信息</p>
  </template>
</BaseCard>
```

> [!IMPORTANT]
> **重要内容**：v-slot 的简写规则是“**有参数才有简写**”。#header 之所以成立，是因为井号本身就是参数前缀的替代；脱离参数单写一个井号没有语义，模板编译器会直接报错。

**速记**：v-slot:name 填指定出口，**井号即简写**。



#### v-slot 只能用在 template 或组件标签上

**使用位置限制**：v-slot 指令只能写在 template 元素上，默认插槽内容还可以直接写在**组件标签**上。

- 具名内容必须用 template 包裹，再在 template 上写 v-slot:名字。
- 默认插槽可省略 template，内容直接写在组件标签之间。
- 默认插槽也可显式写 template 加 v-slot:default，与省略写法等价。

```html
<BaseCard>
  <!-- 合法：template 携带具名内容 -->
  <template #header>标题区</template>

  <!-- 合法：默认插槽内容直接写在组件标签之间 -->
  <p>主体内容</p>
</BaseCard>
```

> [!WARNING]
> **警告内容**：v-slot 写在普通 HTML 元素（如 div、p）上是**编译错误**，因为普通元素不接受插槽分发。见到 v-slot can only be used on components or templates 一类报错，先检查指令是否挂在了错误的标签上。

**速记**：v-slot 只认 **template 与组件标签**。



#### 未被认领的内容全部进入默认插槽

**分发兜底规则**：父组件中不带 v-slot 的内容，无论写多少段，都进入**默认插槽**。

- 没写 template 的裸内容，全部归入 default。
- 具名出口若**无人填充**，该位置渲染其后备内容，没有后备则什么都不渲染。
- default 出口与具名出口相互独立，父组件可以只填其中一部分。

> 常见误解是“裸内容会平均分给所有空着的出口”。实际上分发只看名字：**有名字的找同名出口，没名字的一律去 default**，二者互不干扰。

**速记**：裸内容进 default，具名内容**按名认领**。



### 默认插槽与具名插槽混用

#### 不带 name 的 slot 即默认插槽

**默认插槽**：不带 name 属性的 slot 元素，是组件内容分发的主出口。

- 每个 slot 若未写 name，等价于 name="default"。
- 显式写 name="default" 与省略 name 完全一致。
- 默认插槽与具名插槽可以**并存**于同一个组件，数量不受限制。

```html
<!-- 以下两种写法完全等价 -->
<slot></slot>
<slot name="default"></slot>
```

> 「一个组件必有默认插槽」的意识并不成立——slot 写几个、叫什么，完全由组件作者决定；默认插槽只是 name 取 default 的特例。

父组件一侧的对应规则：所有不带 v-slot 的裸内容，都视为投给 **default** 这个名字的出口，等价于被包进 template 加 v-slot:default（分发兜底规则见前文）。因此「默认插槽」与「具名插槽」并非两套机制，而是**同一套 name 分发规则**下的统一处理，混用场景的所有行为都可由 name 匹配一条规则推出——裸内容找 default 出口；template 加 v-slot:名字 找同名出口；找不到同名出口的内容无处渲染，等同于丢弃；具名出口无人填充则渲染后备。

**速记**：默认插槽即 **name 为 default** 的出口，混用不乱，**一切看 name 匹配**。



#### 混用示例：一个组件同时填充三个出口

**综合示例**：默认插槽与两个具名插槽并存的完整写法与渲染对应关系。

```html
<!-- 子组件 AppLayout 的模板 -->
<div class="layout">
  <nav><slot name="navbar"></slot></nav>
  <main><slot></slot></main>
  <aside><slot name="sidebar"></slot></aside>
</div>
```

```html
<!-- 父组件使用 -->
<AppLayout>
  <template #navbar>
    <MenuList />
  </template>

  <template #sidebar>
    <UserInfo />
  </template>

  <ArticleBody />
</AppLayout>
```

- #navbar 内容渲染进 nav，#sidebar 内容渲染进 aside。
- 末尾的 ArticleBody 不带 template，作为裸内容渲染进 main。
- 三个出口的填充互不影响，渲染顺序由子组件模板中出口的位置决定。

> 渲染位置由**子组件模板中的出口位置**决定，父组件里内容书写的先后不影响布局——这是“出口在子、内容在父”机制的直接推论。

**速记**：出口定位置，父内容**按名各就各位**。



### 作用域插槽

#### 作用域插槽让子组件向插槽内容传数据

**作用域插槽（scoped slot）**：能接收**子组件传递的数据**的插槽，传递的数据统称 slot props。

- 普通插槽的内容在父组件作用域渲染，默认**拿不到子组件内部的数据**。
- 子组件在 slot 元素上绑定属性，数据即随出口一起送出。
- 父组件在 v-slot 后用等号接收一个 props 对象，从中读取这些数据。

```html
<!-- 子组件在 slot 上绑定数据 -->
<ul>
  <li v-for="(item, index) in items" :key="item.id">
    <slot :item="item" :index="index"></slot>
  </li>
</ul>
```

> [!TIP]
> **建议内容**：slot props 是普通插槽与作用域插槽的**分水岭**——slot 元素上绑了属性就是作用域插槽，一个属性都没绑就是普通插槽，二者语法完全兼容，差别只在父组件是否接收。

**速记**：子绑数据在 slot 上，父用 **v-slot 等号接**。



#### 数据在子组件作用域是作用域插槽存在的理由

**存在动机**：需要作用域插槽的根源是**数据在子组件内部**，而画面却想由父组件定制。

- 列表类组件中，items 数组由子组件请求或组装，**父组件无从插手**。
- 但每一条渲染成什么样（卡片、行、链接），恰恰是父组件想定制的部分。
- 作用域插槽把“**数据给出方**”与“**画面定制方**”解耦：子交数据，父定画面。

> 类比理解：子组件说“我手里有一批 item 和 index，至于每条画成什么样，你来画”。没有作用域插槽，父组件要么放弃定制，要么把整套列表逻辑复制回家。

**速记**：数据在子、画面在父，**slot props 架桥**。



#### slot props 以单一对象接收

**接收形态**：父组件通过 v-slot 的等号接收到的是**一个对象**，子组件绑定的每个属性都是对象上的键。

- 接收写法为 v-slot="slotProps"，slotProps 是自定义的形参名，习惯上就叫 slotProps。
- 子组件绑定 :item 与 :index 后，slotProps 中即有 slotProps.item 与 slotProps.index。
- 模板中通过 slotProps.item 访问，不需要额外的解包步骤。

```html
<!-- 父组件使用 FancyList -->
<FancyList :items="list">
  <template v-slot="slotProps">
    <span>{{ slotProps.index }} - {{ slotProps.item.name }}</span>
  </template>
</FancyList>
```

> slotProps 名字可自由更换，它的键由**子组件绑定了什么属性**决定：绑几个属性就有几个键，绑什么名字就是什么名字。

**速记**：slot props 是**一个对象**，键名即绑定的属性名。



#### slot props 支持解构与重命名

**解构写法**：v-slot 的等号后可以直接写解构模式，省去逐级访问对象的前缀。

- 写 v-slot="{ item, index }" 后，模板内可直接使用 item 与 index。
- 支持重命名与默认值：{ item: it }、{ count = 0 } 均为合法写法。
- 具名作用域插槽同样支持解构，如 #header="{ user }"。

```html
<FancyList :items="list">
  <template #default="{ item, index }">
    <span>{{ index }} - {{ item.name }}</span>
  </template>
</FancyList>
```

> [!NOTE]
> **提醒内容**：解构让代码更短，但也让**数据来源不再显眼**——模板里凭空出现的 item 需要回到 template 标签才能确认来自 slot props，团队协作时可约定统一解构或统一用 slotProps。

**速记**：等号后**直接解构**，模板内免前缀。



### 具名作用域插槽

#### v-slot:name 等号同时指定出口与接收对象

**具名作用域插槽**：具名插槽与作用域插槽的叠加，v-slot:name 后接等号即可**接收该出口的 props**。

- 语法形态为 v-slot:name="props"，简写为 #name="{ 键 }"。
- 名字与 props 互不干扰：冒号后定出口，等号后定接收对象。
- 每个具名出口的 props **彼此独立**，由子组件在对应 slot 上绑定的属性决定。

```html
<!-- 子组件 AppLayout 在不同出口绑定不同数据 -->
<div class="layout">
  <nav><slot name="navbar" :menus="menus"></slot></nav>
  <main><slot :article="article"></slot></main>
</div>
```

```html
<!-- 父组件分别接收 -->
<AppLayout>
  <template #navbar="{ menus }">
    <MenuList :menus="menus" />
  </template>

  <template #default="{ article }">
    <ArticleBody :article="article" />
  </template>
</AppLayout>
```

> 同一组标签里，#navbar="{ menus }" 与 #default="{ article }" 同时成立，说明**具名与作用域两件事写在同一条指令里**：冒号后的名字管分发，等号后的模式管收数。

**速记**：具名作用域 = **冒号定出口 + 等号收数据**。



#### 动态插槽名用方括号表达式

**动态插槽名**：插槽名可以用模板表达式动态给出，写法为冒号后接方括号包裹的表达式。

- 完整写法 v-slot:[dynamicSlotName]，简写 #[dynamicSlotName]。
- 方括号内的表达式在**父组件作用域**求值，可引用父组件的响应式数据。
- 求值结果为字符串，用于匹配子组件同名出口。

```html
<ChildComponent>
  <template #[slotName]>
    动态填充到名为 slotName 的出口
  </template>
</ChildComponent>
```

> 动态插槽名与动态指令参数共用同一套方括号语法，常见于按配置渲染布局的场景；静态名能满足需求时不必引入动态名。

**速记**：方括号包表达式，**插槽名也能动态**。



### 编译作用域

#### 父模板表达式只能访问父组件作用域

**编译作用域**：一条模板表达式**在哪里编译，就只能访问哪个组件的作用域**。

- 插槽内容写在父组件的模板里，在父组件编译，因此**只能访问父组件的数据与方法**。
- 子组件作用域内的状态，插槽内容**默认完全不可见**。
- 这是模板的词法作用域规则，与 JavaScript 的作用域思想一致，不因渲染位置改变查找范围。

```html
<!-- 子组件 Child 的模板，内部定义了 message -->
<div><slot></slot></div>

<!-- 父组件 -->
<Child>{{ message }}</Child>
```

- 上例中的 message 解析为**父组件**的 message，不是子组件内部的同名数据。
- 若父组件没有定义 message，渲染为空并触发告警，**绝不会**回落去读子组件的值。

> [!IMPORTANT]
> **重要内容**：插槽内容“渲染在子组件、却编译在父组件”是插槽体系最重要的辨析点。**内容放在哪里由子组件决定，变量在哪里解析由编译位置决定**——两件事分属两个组件，互不影响。

**速记**：插槽内容**渲染在子、解析在父**。



#### slot props 是穿透编译作用域的正规通道

**桥梁定位**：slot props 是插槽内容**获取子组件数据的正规通道**，是对编译作用域规则的定向豁开。

- 编译作用域禁止插槽内容直接读取子组件状态，但**没有封死数据通道**。
- 子组件通过 slot 上的属性把数据“推”出来，父组件通过 v-slot 等号“接”住。
- 若子组件没有绑定某属性，父组件无论写什么都拿不到它。

```html
<!-- 想在插槽内容里用子组件的 user，子组件必须主动绑定 -->
<slot :user="user"></slot>
```

> 记忆锚点：编译作用域回答“**变量从哪找**”，slot props 回答“**数据怎么给**”。前者是规则，后者是该规则下开辟的通道，二者不冲突；这与 props 单向数据流的思路一脉相承——数据是否暴露由持有方决定。

**速记**：跨组件拿数，**走 slot props 这座桥**。



### 典型用例

#### 列表组件通过作用域插槽暴露 item 与 index

**列表用例**：把“遍历逻辑”封装在子组件、把“单条渲染”交给父组件，是作用域插槽最经典的应用范式。

- 子组件持有列表数据并负责 v-for 遍历，在每一条的 slot 上绑定 item 与 index。
- 父组件接收后，自由决定每一条的 DOM 结构与样式。
- 列表的过滤、排序、分页等逻辑**全部留在子组件**，父组件无需关心。

```html
<!-- 子组件 FancyList：数据与遍历都在这里 -->
<ul>
  <li v-for="(item, index) in filteredItems" :key="item.id">
    <slot :item="item" :index="index"></slot>
  </li>
</ul>
```

```html
<!-- 父组件：只关心每条长什么样 -->
<FancyList :items="todos">
  <template #default="{ item, index }">
    <span :class="{ done: item.done }">{{ index + 1 }}. {{ item.text }}</span>
  </template>
</FancyList>
```

- filteredItems 为子组件内部对 items 过滤后的结果，父组件拿到的是**加工后**的数据。
- 同一个 FancyList，被不同页面使用时可以渲染出完全不同的条目样式。

> 该范式体现了插槽的核心价值：**复用的是逻辑与外壳，开放的是画面**。官方文档中的 FancyList 示例即为此模式的范本。

**速记**：子管**遍历与数据**，父管**每条的画面**。



#### 无渲染组件只提供数据与逻辑、不渲染画面

**无渲染组件（renderless component）**：模板里只有一个 slot 的组件，自身**不输出任何结构**，只通过作用域插槽对外提供数据与行为。

- 组件的全部模板往往就是一个包着 slot 的出口，画面完全由使用者提供。
- 数据、状态、事件监听等逻辑写在组件的 script 中，经 slot props 交付。
- 典型例子：追踪鼠标位置的组件暴露 x 与 y；倒计时组件暴露剩余时间与控制方法。

```html
<!-- 无渲染组件 MouseTracker 的全部模板 -->
<slot :x="x" :y="y"></slot>
```

```html
<!-- 使用者获得数据，画面自定 -->
<MouseTracker v-slot="{ x, y }">
  当前位置：{{ x }}，{{ y }}
</MouseTracker>
```

> [!TIP]
> **建议内容**：这类逻辑复用需求如今更推荐用**组合式函数**实现（见本系列 14. 组合式函数 composables.md）；但无渲染组件是理解作用域插槽威力的绝佳教材，阅读开源组件库源码时仍会大量遇到。

**速记**：无渲染组件**零画面、纯给数**。



#### 布局组件用多个出口锁定结构

**布局用例**：页头、页脚、侧栏等**结构固定、内容多变**的场景，是具名插槽的天然舞台。

- 子组件锁定整体骨架与各区域的排版样式。
- 每个区域开一个具名出口，父组件按名填充。
- 各出口可携带自己的 slot props，例如侧栏出口传出登录用户信息。

> 判断一个场景适不适合插槽，看一句话即可：**结构与样式想复用、内容想定制**，两者同时成立就开出口。

**速记**：布局复用开**多个具名出口**。



### 插槽与 props 的选型

#### 传数据用 props、传模板内容用插槽

**选型总则**：交给子组件的是**纯数据**用 props，是**一段由父组件定义的画面**用插槽，二者服务的对象不同。

- props 适合：字符串、数字、布尔、数组对象等**值本身**。
- 插槽适合：需要在子组件某个位置渲染的**结构化内容**，含元素、组件与排版。
- 需要父组件定制画面、且画面依赖子组件数据时，用**作用域插槽**组合两者。

> [!TIP]
> **建议内容**：选型口诀为“**给值用 props，给画面用插槽**”。当发现自己在往 props 里塞 HTML 字符串、或用组件名加 v-if 分支拼凑展示结构时，通常意味着这里该开插槽了。

**速记**：给值用 **props**，给画面用 **插槽**。



#### props 与插槽组合覆盖绝大多数封装需求

**组合场景**：真实的封装通常**同时开 props 与插槽**，各司其职、互不替代。

- 以 BaseCard 为例：标题文本、尺寸变体走 props，主体内容区开默认插槽，操作区开具名插槽。
- props 定**可枚举的配置**，插槽定**不可枚举的画面**，边界清晰。
- 再配 emit 对外发事件（见本系列 9. 组件事件与组件级 v-model.md），组件三面即告完整。

```html
<BaseCard size="large" title="账户概览">
  <template #default>
    <AccountSummary :data="summary" />
  </template>

  <template #actions>
    <button @click="refresh">刷新</button>
  </template>
</BaseCard>
```

> 组件设计三条通道对照：props 进数据、插槽进画面、事件出通知。设计新组件时先问三件事——配置有哪些、哪块画面要开放、何时通知外部。

**速记**：props 进数据、插槽进画面、**事件出通知**。



#### 与相邻知识点的关联阅读

**关联阅读**：props 的定义、单向数据流与校验细节，见本系列 8. 组件基础与 props.md。

- 本篇的插槽与 props 是并列的组件通信手段，选型时相互对照。
- 组件事件与组件级 v-model 见本系列 9. 组件事件与组件级 v-model.md。
- 跨层数据传递（绕过中间组件）见本系列 11. 依赖注入 provide 与 inject.md。

> 通信手段全景：父子之间用 props 与插槽下行、用事件上行；跨层用 provide 与 inject；全局共享用状态管理。插槽负责的“画面下行”是其中唯一不可被 props 替代的一路。

**速记**：画面下行**只有插槽一路**。
