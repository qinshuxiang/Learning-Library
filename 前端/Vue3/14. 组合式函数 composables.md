## 组合式函数 composables

### 组合式函数的认识

#### 组合式函数是复用有状态逻辑的 use 函数

**组合式函数（Composable）**：是**以 use 开头命名、用于封装与复用有状态逻辑**的函数，它把响应式状态和操作状态的逻辑捆绑成一个单元，供多个组件重复调用。

- 命名约定：函数名以 **use** 开头并采用驼峰写法，如 useMousePosition、useDebounce、useUserStore，见到 use 前缀即可预期内部含有状态与生命周期逻辑。
- 有状态是本质特征：内部通常创建 ref、computed 等响应式数据，并通过事件监听、定时器等副作用随时间维护它们。
- 与纯工具函数的分界：formatDate 这类工具函数**无状态、无副作用**，传参即算、算完即走；组合式函数**持有状态并随组件生命周期运转**。
- 调用位置：组合式函数只能在**组件 setup 的同步执行段**（或另一个组合式函数的同步调用链内）被调用，以保证生命周期钩子与作用域正确挂接。

```js
// 纯工具函数：无状态，输入确定输出
function formatDate(date) {
  return date.toISOString().slice(0, 10);
}

// 组合式函数：有状态，随时间更新且需要清理
import { ref, onUnmounted } from "vue";

export function useClock() {
  const now = ref(new Date());
  const timer = setInterval(() => (now.value = new Date()), 1000);
  onUnmounted(() => clearInterval(timer));
  return { now };
}
```

> 组合式函数可以理解为“使用组合式 API 封装可复用逻辑”的习惯用法：它没有引入新的运行时机制，本质仍是普通函数，价值在于**把状态、副作用与清理打包成一个可命名的复用单元**。

**速记**：use 前缀**复用有状态逻辑**，纯函数**无状态**。



#### 经典示例 useMousePosition 追踪鼠标位置

**useMousePosition**：是最经典的组合式函数示例，它**监听 mousemove 事件维护 x、y 两个 ref**，并在组件卸载时移除监听。

- 创建状态：x 与 y 两个 ref，初始值为 0，承载随鼠标移动而变化的位置状态。
- 挂接副作用：对 window 注册 mousemove 监听，回调中把 event.pageX、event.pageY 写入两个 ref。
- 生命周期清理：用 onUnmounted 注册卸载回调，移除监听器，防止组件销毁后监听仍然残留。
- 返回状态：以普通对象返回 x、y，调用方解构后模板中直接可用且保持响应性。

```js
// mouse.js
import { ref, onUnmounted } from "vue";

export function useMousePosition() {
  const x = ref(0);
  const y = ref(0);

  function update(event) {
    x.value = event.pageX;
    y.value = event.pageY;
  }

  window.addEventListener("mousemove", update);
  onUnmounted(() => window.removeEventListener("mousemove", update));

  return { x, y };
}
```

```js
// 组件 setup 中使用
import { useMousePosition } from "./mouse.js";

const { x, y } = useMousePosition();
// 模板中直接写 x、y，坐标随鼠标移动实时更新
```

> mousemove 属于 DOM 事件，事件对象、注册与解绑等基础内容详见 JavaScript 系列的事件处理章节；本节重点在于**把事件监听这类副作用与组件生命周期绑定**，这正是组合式函数相对手写代码的增值之处。

**速记**：**注册监听、更新 ref、卸载解绑**，三步缺一不可。



### 与 mixin 和工具函数的对比

#### 与 mixin 相比来源清晰且无命名冲突

**mixin 的三大缺陷**：来源不清晰、命名冲突、类型支持差；组合式函数逐一将其解决，是 Vue 3 中替代 mixin 的首选方案。

- 来源清晰：mixin 注入的属性与方法在组件里凭空出现，必须翻找 mixin 源文件才知道数据从哪来；组合式函数经**具名导入与显式调用**引入，x、y 一眼可知来自 useMousePosition。
- 无命名冲突：多个 mixin 声明同名属性时相互静默覆盖；组合式函数通过对象解构引入，遇到同名时**重命名变量即可化解**。
- 类型友好：mixin 与组件的合并发生在运行时，TypeScript 难以推断合成后的完整类型；组合式函数就是普通函数，**参数与返回值天然可推导、可标注**。

```js
// mixin 方式：this.mouseX 从何而来，组件内部无从知晓
export default {
  mixins: [mouseMixin],
  mounted() {
    console.log(this.mouseX); // 隐式注入，无类型提示、易冲突
  },
};

// 组合式函数方式：来源显式，重命名化解冲突
const { x: mouseX, y: mouseY } = useMousePosition();
```

> [!IMPORTANT]
> **重要内容**：Vue 官方文档明确建议**在 Vue 3 中避免使用 mixin，统一改用组合式函数**。维护旧项目时能读懂 mixin 即可，新代码一律以组合式函数组织可复用逻辑。

**速记**：mixin **隐式注入**，组合式函数**显式调用**；新代码一律后者。



#### 与纯工具函数的区别在状态与生命周期

**工具函数复用不了状态与生命周期**：格式化、校验等无状态操作用普通函数即可；一旦逻辑需要**跨调用记住的状态或生命周期钩子**，就必须交给组合式函数。

- 无状态逻辑：字符串处理、日期格式化、金额计算等，输入确定输出就确定，直接导出普通函数，**不必套 use 前缀**。
- 有状态逻辑：防抖值、计时器、拖拽位置等需要在多次交互间**记住并更新**，且随组件卸载而清理，封装成组合式函数。
- 生命周期差异：普通函数无法注册 onMounted、onUnmounted 等钩子；组合式函数在 setup 上下文中同步运行，**可以合法注册钩子并自动清理**。

```js
import { ref, watch, onUnmounted, toValue } from "vue";

// 工具函数：无状态，不需要生命周期
export function formatPrice(value) {
  return "¥" + value.toFixed(2);
}

// 组合式函数：有状态（timer），有清理（onUnmounted）
export function useDebounce(source, delay = 300) {
  const debounced = ref(toValue(source));
  let timer = null;
  watch(source, (val) => {
    clearTimeout(timer);
    timer = setTimeout(() => (debounced.value = val), delay);
  });
  onUnmounted(() => clearTimeout(timer));
  return { debounced };
}
```

> 二者是分工而非对立：**纯计算交给工具函数，状态与生命周期交给组合式函数**。把无状态逻辑硬包进 use 函数，只会徒增调用成本与理解负担。

**速记**：**无状态用工具函数，有状态有生命周期用组合式函数**。



### 组合式函数的编写约定

#### 输入约定兼容 ref getter 与普通值

**输入约定**：组合式函数的参数应**同时兼容 ref、getter 函数与普通值**三种形态，内部一律用 toValue 取值，而不是假设参数形态直接访问。

- 兼容 ref：传入 ref 时由函数内部建立依赖，外部修改源数据仍能触发更新。
- 兼容 getter：传入 () => state.count 这类函数，函数内部每次取值都会重新执行它。
- 兼容普通值：传入字面量时按静态值处理，不建立任何依赖。
- 统一取值：内部用 toValue(source) 取值；不要写 source.value（普通值没有 value 属性会出错），也不要直接调用 source（ref 不可调用）。

```js
import { ref, computed, toValue } from "vue";

export function useScaled(source, factor = 2) {
  const scaled = computed(() => toValue(source) * factor);
  return { scaled };
}

// 三种传入形态全部合法
const count = ref(5);
useScaled(count); // ref
useScaled(() => state.count); // getter 函数
useScaled(10); // 普通值
```

> [!TIP]
> **建议内容**：新代码统一用 toValue 处理入参。早期的 unref 只能处理 ref 与普通值两种形态，toValue 在其基础上多支持 getter 函数，覆盖面更全。

**速记**：**入参三种形态，toValue 统一取值**。



#### 输出约定返回 ref 组成的普通对象

**输出约定**：组合式函数应**返回一个包含若干 ref 的普通对象**，调用方解构后属性仍是响应式的 ref，既灵活又不破坏响应性。

- 普通对象加 ref：每个属性都是独立 ref，解构后模板中自动解包、脚本中经 value 访问，粒度可控。
- 慎用 reactive 返回：返回 reactive 对象后**一旦解构，属性就变成静态值**，后续更新不再反映到界面。
- 私有化变体：若不希望调用方直接改动内部状态，可只返回 readonly 包装或计算属性，把修改收敛到暴露的方法上。

```js
import { ref, reactive } from "vue";

// 推荐：返回装 ref 的普通对象
export function useMousePosition() {
  const x = ref(0);
  const y = ref(0);
  return { x, y };
}
const { x, y } = useMousePosition(); // 解构安全，x、y 仍是 ref

// 不推荐：返回 reactive，解构即断链
export function useMouseState() {
  const state = reactive({ x: 0, y: 0 });
  return state;
}
const { x, y } = useMouseState(); // x、y 是静态数字，不再随事件更新
```

> [!IMPORTANT]
> **重要内容**：返回 reactive 并非语法错误，风险在于**调用方按直觉解构后失去响应性**。若确需返回 reactive，应整体持有该对象，或用 toRef、toRefs 逐属性取出。

**速记**：**返回装 ref 的普通对象，怎么解构都不断响应**。



#### 副作用必须在卸载或作用域销毁时清理

**副作用清理约定**：组合式函数内注册的**事件监听、定时器、订阅等副作用，必须在组件卸载或所在作用域销毁时清理**，否则泄漏会随调用次数累积。

- 常见副作用：addEventListener 注册的监听器、setInterval 与 setTimeout 的句柄、WebSocket 订阅、第三方图表库实例等。
- 组件场景清理：用 onUnmounted（或 onBeforeUnmount）注册清理回调，触发时机由框架保证。
- 非组件场景清理：组合式函数也可能在任意 effect 作用域中运行，用 onScopeDispose 注册清理，它只依赖作用域、不依赖组件实例。
- 句柄先行保存：监听器回调与定时器 id 要先存入变量，清理时引用同一份才能正确解绑与清除。

```js
import { ref, onUnmounted, onScopeDispose } from "vue";

export function useTicker(interval = 1000) {
  const tick = ref(0);
  const timer = setInterval(() => tick.value++, interval);

  onUnmounted(() => clearInterval(timer)); // 组件场景
  onScopeDispose(() => clearInterval(timer)); // 任意作用域场景

  return { tick };
}
```

> [!CAUTION]
> **注意内容**：忘记清理的监听器与定时器会让组件**销毁后仍占用内存并继续执行回调**，列表页反复进出时尤为明显。注册了什么，卸载时就要清理什么。

**速记**：**注册即登记清理，onUnmounted 与 onScopeDispose 兜底**。



### 参数失响应陷阱与 toValue

#### 传入普通对象会失去响应性

**失响应陷阱**：把**普通对象（非响应式）的属性**作为参数传入组合式函数后，后续修改该属性**不会触发任何更新**，因为函数拿到的是传入那一刻的静态值。

- 根因一：对象字面量 { count: 0 } 本身不是响应式数据，Vue 的依赖收集只对 ref、reactive 等响应式代理生效。
- 根因二：传入 state.count 时发生的是一次**取值求值**，函数收到的是当刻的数字，与原对象从此无关。
- 现象：界面停在初始值，watch 与 computed 也追踪不到任何变化，且控制台通常不报错。
- 解法：传 ref 或 reactive 对象本体；若源数据必须是普通对象，则传 **getter 函数** () => state.count，让函数内部每次取值都重新执行。

```js
import { reactive } from "vue";

const plainState = { count: 0 }; // 普通对象，非响应式

useScaled(plainState.count); // 陷阱：传入的是当刻的 0，之后如何修改都无关

useScaled(() => plainState.count); // 解法一：传 getter，配合 toValue 每次重新取值

const reactiveState = reactive({ count: 0 });
useScaled(() => reactiveState.count); // 解法二：源数据改用响应式
```

> [!WARNING]
> **警告内容**：解构同样会造成断链——const { count } = reactiveState 之后，修改 reactiveState.count 与局部变量 count 已经无关。判断口诀：**传值即快照，传函数才追踪**。

**速记**：普通对象**传值即快照**，getter **传函数才响应**。



#### toValue 统一处理 ref getter 与普通值

**toValue**：是**把 ref、getter 函数或普通值归一为值**的工具函数，是编写兼容多形态入参的组合式函数的标准手段。

- 传 ref：返回其 value 值。
- 传 getter：执行函数并返回结果。
- 传普通值：原样返回。
- 依赖追踪：在 computed、watch 等响应式上下文中调用 toValue，其内部的 ref 读取与 getter 执行都会被正常收集为依赖。

```js
import { ref, computed, toValue } from "vue";

toValue(ref(10)); // 10
toValue(() => 1 + 2); // 3
toValue("hello"); // "hello"

const source = ref(5);
const doubled = computed(() => toValue(source) * 2); // 依赖正常收集，source 变化时重算
```

> toValue 于 Vue 3.3 引入，行为可概括为：是 ref 就取 value，是 getter 就执行，否则原样返回。它与 unref 的区别仅在于多支持 getter 一层，**新代码一律优先 toValue**。

**速记**：**ref 取值、getter 执行、普通值原样返回**。



### 组合式函数的嵌套与异步限制

#### 组合式函数可以嵌套调用其他组合式函数

**嵌套组合**：组合式函数内部可以**像搭积木一样调用其他组合式函数**，这是组合式架构复用能力的来源，也是“组合”二字的含义。

- 层层组合：useMouseDistance 内部调用 useMousePosition，只在其上追加一层距离计算，不重复实现监听逻辑。
- 同步前提：只要外层组合式函数从 setup **同步地**被调用，整条调用链都处于同一组件实例上下文，内层注册的生命周期钩子全部有效。
- 组合粒度：底层组合式函数只做一件事（监听鼠标、防抖、轮询），上层按业务自由拼装，复用粒度远比 mixin 灵活。

```js
import { computed } from "vue";
import { useMousePosition } from "./mouse.js";

export function useMouseDistance() {
  const { x, y } = useMousePosition(); // 嵌套调用另一个组合式函数
  const distance = computed(() => Math.sqrt(x.value ** 2 + y.value ** 2));
  return { distance };
}
```

> 嵌套没有层级上限，但**嵌套过深会让数据流难以追踪**。建议保持“一个组合式函数只做一件事”，用组合而非堆叠表达复杂度。

**速记**：**组合式函数可互相调用，搭积木式复用**。



#### 生命周期钩子必须在同步执行段注册

**注册时机限制**：onMounted、onUnmounted 等生命周期钩子**只能在 setup 的同步执行段（或同步调用的组合式函数内）注册**；放在 await 之后注册会**失效**并伴随警告。

- 原理：注册钩子依赖“当前正在初始化的组件实例”，Vue 在 setup 执行期间把实例作为隐式上下文传递；await 让出主线程后，恢复执行的代码**失去了这份上下文**。
- 现象：钩子回调永不执行，控制台出现 onMounted is called when there is no active component instance 一类的警告。
- 嵌套同理：从事件回调、定时器回调中异步调用组合式函数再注册钩子，同样因无活跃实例而失效。

```js
import { ref, onMounted } from "vue";

export async function useFetchData(url) {
  const data = ref(null);

  // 正确：钩子在 await 之前的同步段注册
  onMounted(() => console.log("mounted 正常生效"));

  const res = await fetch(url);
  data.value = await res.json();

  // 错误：await 之后实例已丢失，此钩子不会生效
  onMounted(() => console.log("永远不会打印"));

  return { data };
}
```

> [!CAUTION]
> **注意内容**：await 之后的钩子注册**不会抛错，只在控制台给出警告**，问题容易上线后才暴露。凡是 async 组合式函数，先把钩子全部注册完，再开始 await。

**速记**：**钩子只认同步段，await 之后再注册即失效**。



#### await 之后的钩子注册有三种规避方式

**规避思路**：让钩子注册发生**在实例仍可用的时刻**——或把 await 挪到注册之后，或把实例显式传给钩子，或把异步逻辑拆到钩子函数之外。

- 方式一调整顺序：同步段先注册全部钩子，再做 await 异步操作，最简单也最推荐。
- 方式二传入实例：await 之前用 getCurrentInstance() 保存当前实例，之后调用钩子时把它作为最后一个参数传入，如 onMounted(回调, instance)。
- 方式三拆分职责：把取数逻辑独立为不注册钩子的普通 async 函数，组合式函数保持同步，只负责组合状态与钩子。

```js
import { ref, onMounted, getCurrentInstance } from "vue";

export async function useFetchData(url) {
  const data = ref(null);
  const instance = getCurrentInstance(); // await 之前保存实例

  const res = await fetch(url);
  data.value = await res.json();

  onMounted(() => console.log("mounted 正常生效"), instance); // 显式传实例

  return { data };
}
```

> getCurrentInstance 属于面向高级用法与库作者的内部 API，日常开发优先用方式一；方式二适用于“必须先异步、钩子又在之后才确定”的特殊场景。

**速记**：**先注册再 await，或把实例显式传给钩子**。



### 共享状态的组合式函数

#### 模块级状态实现全局单例

**共享状态模式**：把 ref 声明在**模块顶层、组合式函数体外**，所有调用方共享同一份状态实例，相当于模块级全局单例。

- 定义位置：状态随模块加载而创建，全应用仅此一份，任何组件调用 use 函数都拿到同一个引用。
- 典型场景：登录用户信息、主题偏好、全局通知队列等跨组件共享的数据。
- 入口收敛：对外只暴露修改方法或 readonly 包装，避免任意组件绕过业务逻辑直接改全局状态。

```js
// useUserStore.js — 状态声明在函数外部：全应用共享一份
import { ref, readonly } from "vue";

const user = ref(null);

export function useUserStore() {
  function setUser(next) {
    user.value = next;
  }
  return { user: readonly(user), setUser };
}
```

> 模块级状态的生命周期与组件无关，**在单元测试或同页多实例场景中会在所有实例间共享**；需要重置时应在模块内提供 reset 函数，避免状态残留污染下一个用例。

**速记**：**状态写在函数外，处处共享一份**。



#### 状态写在函数内则每次调用各自独立

**独立状态模式**：把 ref 声明在**组合式函数体内**，每次调用都创建一套全新状态，组件之间互不影响。

- 每调用一次新建一次：组件 A 与组件 B 各自调用 useToggle，得到两个互不干扰的 isOpen。
- 适用场景：组件私有的交互状态，如每个列表项的展开标志、每个弹窗的开合。
- 与单例的抉择：需要全局一致选模块级，需要组件私有选函数级，**状态的声明位置是唯一分水岭**。

```js
import { ref } from "vue";

export function useToggle(initial = false) {
  const isOpen = ref(initial); // 函数体内：每次调用新建
  function toggle() {
    isOpen.value = !isOpen.value;
  }
  return { isOpen, toggle };
}

// 两个调用方各自得到一套独立状态
const { isOpen: isOpenA } = useToggle();
const { isOpen: isOpenB } = useToggle(true);
```

> [!CAUTION]
> **注意内容**：共享与独立两种模式**只差状态声明的一行位置**，重构时把 ref 挪进或挪出函数体，语义即发生根本变化。改造前务必确认该状态应当共享还是隔离。

**速记**：**状态在函数内各自独立、在模块顶层全局共享**。



### 生态与工程实践

#### VueUse 是社区组合式函数的集大成者

**VueUse**：是 Vue 生态最流行的**组合式函数工具库**，内置两百多个覆盖常见场景的 use 函数，也是学习组合式函数写法的最佳范本。

- 覆盖面广：useLocalStorage、useDark、useMouse、useIntersectionObserver、useDebounceFn 等横跨状态管理、浏览器 API、传感器与网络场景。
- 工程质量高：统一处理了 SSR 兼容、副作用清理与 TypeScript 类型标注，可直接用于生产。
- 学习价值：其源码是官方约定如何落地的活教材，输入兼容、清理模式、按需引入都能找到标准示范。

```js
import { useLocalStorage, useDark, useMouse } from "@vueuse/core";

// 持久化到 localStorage 的状态
const theme = useLocalStorage("theme", "light");

// 一行完成暗色模式
const isDark = useDark();

// 与手写 useMousePosition 等价
const { x, y } = useMouse();
```

> [!NOTE]
> **提醒内容**：VueUse 是**社区维护的独立库**，不是 Vue 核心的一部分，使用前需单独安装 @vueuse/core 依赖；其函数命名同样遵循 use 前缀约定。

**速记**：**常见需求先查 VueUse，造轮子前先搜一轮**。



#### 自研边界与 SSR 及测试注意事项

**自研边界**：**通用且与业务无关的能力优先引入成熟库，与业务模型强绑定的逻辑自研封装**，二者以“是否可被其他项目复用”划界。

- 适合自研：订单状态机、表单联动规则、埋点上报组合等业务特有逻辑，封装后同样能跨组件复用。
- 适合用库：剪贴板、拖拽、本地存储等与业务无关的浏览器能力封装，避免重复实现与维护负担。
- SSR 守卫：依赖 window、document 的代码在服务端不存在，应放入 onMounted 内执行，或加 typeof window 判断守卫。
- SSR 状态隔离：模块级共享状态在服务端会**跨请求串数据**，服务端渲染下的全局状态需用请求级隔离方案处理。
- 测试性：组合式函数是普通函数，不含作用域依赖的部分可在单测中直接调用；注册了钩子的部分可借助 effectScope 包裹后断言状态变化。

```js
import { ref, onMounted } from "vue";

export function useWindowWidth() {
  const width = ref(0);
  onMounted(() => {
    // 仅在客户端执行，服务端渲染不会触达 window
    width.value = window.innerWidth;
  });
  return { width };
}
```

> SSR 下的组合式函数遵循一条总原则：**副作用与浏览器 API 只在客户端生命周期内执行**，服务端只负责渲染初始快照；拿不准的 API 先查其在 SSR 环境的行为再使用。

**速记**：**业务自研、通用用库，浏览器 API 加守卫**。
