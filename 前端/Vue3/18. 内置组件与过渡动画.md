## 内置组件与过渡动画

### Transition 单元素过渡

#### Transition 是单元素或单组件的进入与离开包装

**Transition**：是 Vue 的内置**过渡包装组件**，在元素或组件**进入与离开 DOM** 的过程中自动添加过渡类名，让状态切换获得动画效果。

- Transition 自身**不渲染任何真实元素**，只作为逻辑包装存在，页面结构里看不到它的痕迹。
- 它只服务**单个元素或单个组件**：包裹的内容应只有一个根节点，多个元素的场景交给 TransitionGroup。
- 类名的添加与移除由 Vue **自动完成**：元素插入前加进入类，离开时加离开类，动画结束后统一摘除。
- 默认类名以 **v 前缀**开头，即 v-enter-from 等六个类，直接用 CSS 编写这六个类即可获得动画。

> Transition 并不是渲染动画的组件，而是在正确时机切换类名的调度者：真正的动画效果完全由开发者编写的 CSS 过渡或 CSS 动画实现。

**速记**：Transition **不渲染、只调度**，单元素切换自动挂摘类名。



#### 触发过渡的三类切换场景

**触发条件**：Transition 的过渡类名只在**进入或离开的切换时机**被触发，常见于三类场景。

- **条件渲染**：v-if 切换真与假，元素插入或移除 DOM 时触发进入与离开过渡。
- **条件显示**：v-show 切换显示与隐藏，元素始终留在 DOM 中，靠 display 切换触发。
- **动态组件**：component 标签的 is 指向的组件变化时，旧组件离开、新组件进入；此外改变元素的 key 也会触发过渡，常用于内容整体替换时强制走一遍进出流程。

```html
<transition>
  <p v-if="show">条件切换的段落</p>
</transition>

<transition>
  <component :is="activeComp"></component>
</transition>
```

> [!CAUTION]
> **注意内容**：Transition 内若塞入多个同级元素或组件，Vue 无法判断该给谁做过渡，运行时会给出警告且表现异常。多元素列表的过渡请改用 TransitionGroup。

**速记**：三类触发——**v-if 插拔、v-show 显隐、动态组件换人**。



#### 六个过渡类名的含义与生效时序

**六个过渡类名**：进入三件套 v-enter-from、v-enter-active、v-enter-to 与离开三件套 v-leave-from、v-leave-active、v-leave-to，构成过渡的全部状态锚点。

- **v-enter-from**：进入的**起始状态**，元素插入前一帧添加，插入后一帧移除。
- **v-enter-active**：进入的**全程状态**，整个进入阶段都在，通常在此定义过渡的时长、缓动与延迟。
- **v-enter-to**：进入的**结束状态**，enter-from 移除的同时添加，动画完成时摘除。
- **v-leave-from**：离开的**起始状态**，离开触发后立即添加，下一帧移除。
- **v-leave-active**：离开的**全程状态**，通常在此定义离开过渡的时长与缓动。
- **v-leave-to**：离开的**结束状态**，leave-from 移除的同时添加，动画完成后随元素移除而摘除。

```css
.v-enter-active,
.v-leave-active {
  transition: opacity 0.3s ease;
}

.v-enter-from,
.v-leave-to {
  opacity: 0;
}
```

> from 类描述**动画从哪开始**，to 类描述**动画到哪结束**，active 类承载**过渡本身的时长与曲线**。三者的添加与摘除时序完全由 Vue 控制，开发者只需编写对应的 CSS 规则。

**速记**：**from 起点、to 终点、active 全程**，进入与离开各一套。



#### 用 CSS 完成一次完整的进入与离开过渡

**最小完整示例**：一个淡入淡出过渡只需模板、逻辑、样式三段配合，即可观察六个类名的实际运转。

```html
<template>
  <button @click="show = !show">切换</button>
  <transition>
    <p v-if="show">淡入淡出的内容</p>
  </transition>
</template>
```

```js
import { ref } from "vue";

const show = ref(true);
```

```css
.v-enter-active,
.v-leave-active {
  transition: opacity 0.5s ease;
}

.v-enter-from,
.v-leave-to {
  opacity: 0;
}
```

> 运行时打开开发者工具的元素面板可观察到：点击切换的瞬间元素先后挂上 v-enter-active 与 v-enter-from，下一帧 from 换成 to，0.5 秒后类名全部摘除。理解这条时间线，一切过渡异常都能定位。

**速记**：模板包 transition，CSS 写六类，**切换即动画**。



### 过渡命名与首次渲染

#### name 属性定制类名前缀

**命名过渡**：给 Transition 传 name 属性，六个类名的前缀即从 v 变为该 name 值，便于在同一页面并存多套互不干扰的动画。

- 默认前缀是 v，与内置后缀拼成 v-enter-from 等六个类。
- 传 name="fade" 后，类名变为 fade-enter-from、fade-enter-active、fade-enter-to、fade-leave-from、fade-leave-active、fade-leave-to。
- 多个 Transition 各用不同 name，即可同时维护多套动画样式，互不冲突。
- 后文的 JavaScript 钩子名同样跟随前缀变化，例如 fade-before-enter 对应 name="fade" 的 before-enter 钩子。

```html
<transition name="fade">
  <p v-if="show">淡入淡出</p>
</transition>
```

```css
.fade-enter-active,
.fade-leave-active {
  transition: opacity 0.5s;
}

.fade-enter-from,
.fade-leave-to {
  opacity: 0;
}
```

> 规则只有一条：不写 name 用 v 前缀，写了就用 name 值替换前缀。全局通用动画可在样式表统一写 v 前缀类，局部特殊动画再用 name 区分。

**速记**：name 定**前缀**，一套 name 一套类名。



#### appear 让首次渲染也执行过渡

**appear**：是 Transition 的一个布尔属性，让元素**首次渲染进入时也播放进入过渡**，而非只有后续切换才动。

- 默认情况下，初次挂载直接出现在页面，**不触发**任何过渡类名。
- 加上 appear 后，首次渲染即按进入过渡的完整流程添加 v-enter-from 等类名并播放动画。
- 还有 appear-class、appear-to-class、appear-active-class 等属性可为首次渲染单独定制类名，但通常与普通进入过渡共用一套即可。

```html
<transition name="fade" appear>
  <p v-if="show">首屏也淡入</p>
</transition>
```

> 首屏列表配合 appear 能获得入场动画，但元素较多时会集中触发大量动画，低端设备可能出现首屏卡顿，需配合分批渲染或控制动画规模。

**速记**：appear = **初次挂载也算进入**。



### 过渡模式 mode

#### 默认过渡是新旧元素同时进行

**默认行为**：Transition 在切换两个元素时，**新元素的进入与旧元素的离开同时发生**，过渡期间两个元素同时存在于页面。

- 同时进行的常见表现是新元素立即插入、旧元素并行移除，位置重叠时出现**闪烁或跳动**。
- 原因是默认不等待：进入与离开是两条独立的动画时间线，互不干涉。
- 若新旧元素都占据正常布局位置，同时存在会让布局**瞬间撑高再回落**，观感突兀。
- 解决方式有二：用 CSS 把离开元素设为绝对定位使其脱离文档流，或使用下一考点的 mode 指定先后次序。

> [!IMPORTANT]
> **重要内容**：默认同时进行的前提是新旧元素互斥切换，典型如 v-if 与 v-else 两个分支。两个元素同时渲染且无互斥条件的场景不属于过渡范畴，应改用列表过渡或自行控制。

**速记**：默认**进离同时**，重叠靠定位或 mode 解决。



#### mode 等于 out-in 与 in-out 的两种次序

**过渡模式**：mode 属性控制新旧元素动画的**先后次序**，取值只有 out-in 与 in-out 两种。

- **mode="out-in"**：先**出后进**，旧元素完全离开后新元素才开始进入，最常用，适合选项卡切换、路由页面切换。
- **mode="in-out"**：先**进后出**，新元素先进入，完成后旧元素才离开；新元素进入时旧元素还占着位置，容易重叠，使用较少。

```html
<transition name="fade" mode="out-in">
  <component :is="activeTab"></component>
</transition>
```

> out-in 的语义是让干净后再来，页面切换不重叠，是绝大多数场景的首选；in-out 的语义是无缝衔接，只适合新旧元素可以共存的画面。记不准时优先 out-in。

**速记**：out-in **先走后进**，in-out **先进后走**。



### JavaScript 过渡钩子

#### 八个钩子函数与 done 回调

**JavaScript 钩子**：Transition 在进入与离开的各阶段暴露钩子事件，允许用 JavaScript 完全接管或补充过渡逻辑。

- 进入侧四个：@before-enter、@enter、@after-enter、@enter-cancelled。
- 离开侧四个：@before-leave、@leave、@after-leave、@leave-cancelled。
- 钩子回调的第一个参数是被过渡的**原生 DOM 元素**，可直接操作其样式。
- @enter 与 @leave 回调的第二个参数是 **done 函数**：当声明 :css="false" 时，必须调用 done 才能宣告过渡结束。

```html
<transition
  @before-enter="onBeforeEnter"
  @enter="onEnter"
  @after-enter="onAfterEnter"
>
  <p v-if="show">JS 接管的过渡</p>
</transition>
```

```js
function onBeforeEnter(el) {
  el.style.opacity = 0;
}

function onEnter(el, done) {
  el.style.transition = "opacity 0.3s";
  requestAnimationFrame(() => {
    el.style.opacity = 1;
  });
  el.addEventListener("transitionend", done, { once: true });
}

function onAfterEnter(el) {
  el.style.opacity = "";
}
```

> done 不被调用时，Vue 会一直认为过渡尚未结束，后续钩子与 DOM 移除时机都会被阻塞。配合 gsap 等第三方动画库时，通常在动画完成的回调里调用 done。

**速记**：进入离开**各四钩**，:css="false" 时 **done 定终点**。



#### 纯 JS 动画需声明 type 或显式 duration

**结束时机问题**：Vue 需要知道过渡**何时结束**才能摘除类名或移除元素，默认依据是监听根元素的 transitionend 或 animationend 事件。

- 元素上同时存在 CSS 过渡与 CSS 动画且时长不一致时，Vue 无法确定监听哪个事件，需用 **type 属性**显式声明取 transition 或 animation。
- 过渡发生在嵌套子元素上而根元素本身没有过渡时，默认监听会失效，可用 **:duration** 传毫秒数显式指定，也可传对象分别为进入与离开指定时长。
- 完全用 JavaScript 驱动动画时，须设置 **:css="false"** 让 Vue 跳过 CSS 探测，完全信任 done 回调的调用时机。

```html
<transition type="animation" :duration="{ enter: 500, leave: 800 }">
  <p v-if="show">复合动画</p>
</transition>
```

> [!WARNING]
> **警告内容**：用 JS 钩子做动画却既不写 :css="false" 也不声明 type 或 duration 时，Vue 可能依据 CSS 探测结果提前或延后收尾，出现动画被截断或元素滞留的问题。三者选其一明确交代结束时机。

**速记**：**type 选监听源、duration 定时长、:css="false" 交权 done**。



### TransitionGroup 列表过渡

#### TransitionGroup 与 move 类的 FLIP 思想

**TransitionGroup**：是面向**列表**的内置过渡组件，为列表项的进入与离开提供过渡，并在项位置变化时通过 move 类自动补间移动动画。

- 进入与离开类名与 Transition 完全相同，仍是 v-enter-from 等六个，或按 name 前缀定制。
- 额外提供 **v-move** 类：当某列表项因增删而改变位置时，Vue 对所有发生平移的项添加 move 类，实现位置变化的平滑补间。
- 其原理是 **FLIP**：First 记录变化前位置，Last 记录变化后位置，Invert 用 transform 反向偏移让元素看似未动，Play 再移除反向偏移让 transform 过渡到零，从而产生滑动动画，通常只需给 move 类加一条 transition: transform 规则。

```css
.list-move,
.list-enter-active,
.list-leave-active {
  transition: all 0.5s ease;
}

.list-enter-from,
.list-leave-to {
  opacity: 0;
  transform: translateX(30px);
}

.list-leave-active {
  position: absolute;
}
```

> [!TIP]
> **建议内容**：给列表项的 leave-active 设置 position: absolute 是 FLIP 平滑的关键——离开的项脱离文档流后，其余项的 move 补间才能立即启动，否则要等离开动画结束才开始滑动，观感割裂。

**速记**：TransitionGroup = **列表过渡 + FLIP 补间**，move 类管平移。



#### 列表子元素必须携带 key

**key 要求**：TransitionGroup 内的每个列表项**必须提供唯一 key**，否则无法追踪每一项的身份，过渡与补间都会失效。

- key 是 Vue 判断哪一项进入、哪一项离开、哪一项挪动位置的**唯一依据**。
- key 应绑定**稳定且唯一**的业务标识（如 id），不要用数组下标，下标在增删时会错位并复用错误的动画。
- 列表项由 v-for 渲染时，v-for 自带的 key 即可满足要求，无需重复绑定。

```html
<transition-group name="list" tag="ul">
  <li v-for="item in items" :key="item.id">{{ item.text }}</li>
</transition-group>
```

> 用下标当 key 时，删除中间一项会导致后续所有项的身份变化，Vue 认为是内容更新而非项离开，动画完全不触发。列表过渡场景下 key 的稳定性决定动画正确性。

**速记**：**无 key 不追踪**，key 用业务 id 不用下标。



#### TransitionGroup 不支持 mode 且默认无包裹元素

**与 Transition 的差异**：TransitionGroup 在行为上有两条与 Transition 不同的硬性规则，容易踩坑。

- **不支持 mode**：列表场景中各项的进出本就并行发生，不存在先后次序问题，因此 out-in 与 in-out 均不可用。
- **默认无包裹元素**：TransitionGroup 默认以片段形式渲染，不向页面添加任何包裹标签；需要语义标签时用 tag 属性指定为 ul、ol 等。
- 其职责是服务 v-for 列表的增删与排序，不适合再用 v-if 与 v-else 在内部切换整组内容。

```html
<transition-group name="list" tag="ul">
  <li v-for="item in items" :key="item.id">{{ item.text }}</li>
</transition-group>
```

> 记忆锚点：单元素用 Transition，列表用 TransitionGroup；前者不可指定包裹标签，后者可用 tag 指定但不支持 mode。两者类名体系完全一致，切换使用时心智负担很低。

**速记**：TransitionGroup **可带 tag、不带 mode**。



### KeepAlive 组件缓存

#### KeepAlive 缓存组件实例避免重复创建

**KeepAlive**：是内置的**缓存包装组件**，包裹动态组件时把切走的组件实例**保留在内存中**，再次切回时直接复用，而非销毁重建。

- 动态组件的默认行为是切换即销毁、回来即重建，组件内部状态（表单输入、滚动位置、已加载数据）全部丢失。
- 用 KeepAlive 包裹后，组件实例连同全部状态被**缓存**，切回时恢复原样，不重新执行 setup。
- 典型场景是页签切换、多步表单、列表页与详情页来回切换时保留筛选条件与数据。

```html
<keep-alive>
  <component :is="activeComp"></component>
</keep-alive>
```

> [!NOTE]
> **提醒内容**：KeepAlive 与 Transition 一样要求**同一时刻只有一个激活组件**，v-for 产生的多个并列子组件不适用。它常与动态组件及 router-view 搭配使用。

**速记**：KeepAlive = **切换不销毁，回来不重建**。



#### include、exclude 与 max 三个缓存控制项

**缓存控制**：KeepAlive 通过 include、exclude、max 三个属性精细控制**缓存谁、不缓存谁、最多缓存几个**。

- **include**：字符串、正则或数组，只有**名称匹配**的组件才被缓存。
- **exclude**：与 include 相反，名称匹配的组件**永不缓存**，优先级高于 include。
- **max**：数字，限制缓存实例的**最大数量**，超出时按 **LRU 策略**淘汰最久未访问的实例，防止内存无限增长。
- 匹配依据是组件的 **name 选项**：script setup 写法下组件名默认取文件名，需要显式指定时用 defineOptions 声明。

```html
<keep-alive include="Detail,Editor" :max="10">
  <component :is="activeComp"></component>
</keep-alive>
```

> [!CAUTION]
> **注意内容**：被 exclude 排除的组件每次切走都会被真正销毁，状态不会保留；把本该缓存的组件误写进 exclude 是状态莫名丢失类问题的常见根源。排错时先核对 include 与 exclude 中的组件名拼写是否与 name 一致。

**速记**：include **白名单**、exclude **黑名单**、max **LRU 上限**。



#### 激活与失活钩子 onActivated 与 onDeactivated

**专属生命周期钩子**：被 KeepAlive 缓存的组件切回与切走时，触发的不是 mounted 与 unmounted，而是专属的激活与失活钩子 onActivated 与 onDeactivated。

- **onActivated**：组件被激活时调用，即从缓存恢复到页面的那一刻，适合刷新数据或恢复轮询。
- **onDeactivated**：组件被缓存失活时调用，适合暂停定时器、取消订阅等清理工作。
- 首次挂载时 mounted 与 onActivated **都会**触发且 mounted 在前；此后每次切回只触发 onActivated。
- 组件被真正销毁（如被 exclude 排除或父级卸载）时仍会执行卸载钩子。

```js
import { onActivated, onDeactivated } from "vue";

onActivated(() => {
  console.log("回到页面，刷新数据");
});

onDeactivated(() => {
  console.log("被缓存，暂停定时器");
});
```

> 这对钩子与生命周期章节中 mounted、unmounted 的关系是：缓存组件**不再重复经历挂载与卸载**，凡每次显示都要做的逻辑写进 onActivated，凡每次离开都要清的逻辑写进 onDeactivated，二者与挂载卸载钩子互补而非替代。

**速记**：缓存组件**回来走 activated、离开走 deactivated**，全程只有一次 mounted。



### Teleport 传送组件

#### Teleport 把 DOM 传送到组件树之外

**Teleport**：是内置的**传送组件**，把其内部的 DOM 结构渲染到**指定容器**而非父组件的 DOM 位置，同时组件的逻辑层级保持不变。

- 动机：弹窗、通知、加载遮罩这类 UI 留在组件原位置时，会被父级的 overflow 裁剪或祖先的层叠上下文压制。
- Teleport 让 DOM **脱离原位置**，直接挂到 body 等容器下，视觉上不再受祖先样式约束。
- 关键在于**逻辑与物理分离**：DOM 传送走了，但 props 传递、事件通信、组件嵌套关系仍按原组件树运转，开发者工具中看到的仍是原逻辑层级。

```html
<template>
  <div class="page">
    <teleport to="body">
      <div class="modal">弹窗内容</div>
    </teleport>
  </div>
</template>
```

> 传送只改变**最终 DOM 挂载点**，不改变**组件树结构**。弹窗内依然正常使用父组件传入的数据与事件，作用域样式标识也随元素一起传送，scoped 样式依旧生效。

**速记**：Teleport **DOM 搬家、逻辑不离家**。



#### to 接收选择器或元素且目标须先存在

**to 属性**：指定传送目标，值可以是 **CSS 选择器字符串**，也可以是**真实的 DOM 元素引用**。

- 写选择器：to="body"、to="#modal-root"、to=".drawer-container" 均可。
- 写元素引用：配合模板 ref 拿到真实元素后传入，类型更严格，适合动态容器场景。
- 目标容器在**组件挂载时必须已存在**于 DOM 中，否则传送无法完成。
- 多个 Teleport 指向同一目标时，内容按**挂载顺序追加**，后传的排在后面。

> [!WARNING]
> **警告内容**：目标容器若是被 v-if 延迟渲染的元素，Teleport 挂载时找不到目标会解析失败。要么保证目标始终存在（预置常驻空容器），要么使用 3.5 新增的 defer 属性推迟解析时机。

**速记**：to 收**选择器或元素**，目标**必须先在 DOM**。



#### disabled 属性与 3.5 新增的 defer 属性

**两个控制属性**：Teleport 提供 disabled 控制是否传送，3.5 起新增 defer 控制传送的解析时机。

- **disabled**：布尔属性，为 true 时**不传送**，内容留在组件原位置正常渲染；常配合响应式变量在移动端取消传送。
- **defer**：3.5 新增的布尔属性，把传送目标的解析**推迟到应用其余部分挂载完成之后**，解决目标容器与传送内容同轮渲染、目标尚未出现的时序问题。

```html
<teleport to="#drawer-root" :disabled="isMobile" defer>
  <div class="drawer">抽屉内容</div>
</teleport>
```

> defer 的典型场景是父组件同时渲染目标容器与 Teleport：默认时机下 Teleport 先解析、容器后渲染导致找不到目标；加 defer 后统一等挂载完成再传送，无需人为调整渲染顺序。

**速记**：disabled **就地渲染**，defer **晚点再传**。



#### 解决弹窗被 overflow 或层叠上下文裁剪的问题

**核心应用场景**：Teleport 最常见的用途是修复弹窗类 UI 被**祖先 overflow 裁剪**或**层叠上下文压制**的布局顽疾。

- **overflow 裁剪**：祖先元素设置 overflow: hidden 或 overflow: auto 后，超出其边界的弹窗部分被直接剪掉，调多大的 z-index 都无效。
- **层叠上下文压制**：祖先元素因 transform、opacity、filter、z-index 等属性创建了层叠上下文，弹窗的 z-index 只在该上下文内部比较，永远压不过外部元素。
- 两类问题的共同根源是弹窗与捣乱祖先之间存在**父子 DOM 关系**；Teleport 直接斩断这条物理链路，把弹窗挂到 body 下，问题随之消失。
- 工程实践中常把弹层类基础组件统一传送到 body，再结合 CSS 系列中层叠上下文的规则理解成因，从组件库设计层面预防。

> [!IMPORTANT]
> **重要内容**：遇到 z-index 写多大都没用的弹窗问题，先检查祖先是否创建了层叠上下文或裁剪容器，再决定用 Teleport 传送还是调整层叠方案，盲目提高 z-index 治标不治本。

**速记**：弹窗被剪被压，**传送到 body 一了百了**。



### Suspense 异步边界

#### Suspense 等待异步依赖并展示 fallback

**Suspense**：是内置的**异步边界组件**，在异步依赖就绪前展示 fallback 内容，全部就绪后再整体展示真正的默认内容。

- 它协调的是**默认插槽子树中的异步依赖**：子组件存在 async setup 或顶层 await 时，Suspense 自动等待。
- **default 插槽**：放真正的内容，其中的异步组件全部就绪后才整体渲染。
- **fallback 插槽**：放等待期间显示的内容，如骨架屏与加载指示器。
- 典型写法是子组件的 script setup 中顶层 await 请求接口，Suspense 在外层兜住这段时间。

```html
<template>
  <suspense>
    <async-dashboard></async-dashboard>
    <template #fallback>
      <p>加载中...</p>
    </template>
  </suspense>
</template>
```

```js
// async-dashboard 组件内部
import { ref } from "vue";

const data = ref(null);
// 顶层 await 使该组件成为异步依赖，Suspense 会等它
data.value = await fetch("/api/dashboard").then((r) => r.json());
```

> 等待的是**整棵默认插槽子树**：只要其中任一异步依赖未就绪，整个内容都不渲染，fallback 一直显示。这种全有或全无的特性让多接口聚合页的加载状态管理变得简单。

**速记**：default 放**异步内容**，fallback 放**加载占位**，全部就绪才揭晓。



#### 实验性状态与嵌套边界的限制

**使用边界**：Suspense 至今仍是**实验性特性**，官方明确其 API 与行为在后续版本可能变化，生产使用需谨慎评估。

- 官方文档将其标注为 experimental：功能可用但不承诺稳定，与 Transition、Teleport 等稳定内置组件地位不同。
- **嵌套限制**：异步组件若不是默认插槽的直接子级而是隔了多层嵌套，**内层需要显式再包一层 Suspense**，外层才能正确感知深层异步依赖。

> [!CAUTION]
> **注意内容**：依赖 Suspense 的项目在升级大版本时需重点回归测试，实验性 API 存在行为调整的可能。若只是单组件级别的加载占位，用异步组件的 loadingComponent 往往更简单可控。

**速记**：Suspense **仍是实验性**，深层异步**补内层边界**。



### defineAsyncComponent 异步组件

#### 工厂函数配合动态 import 定义异步组件

**defineAsyncComponent**：用于定义**异步加载的组件**，接收一个返回 Promise 的工厂函数，组件代码在被真正渲染时才下载执行。

- 基本形态是传入一个函数，函数内用**动态 import** 返回组件模块的 Promise。
- 异步组件首次被渲染时才触发加载，加载完成前页面可先显示占位内容。
- 价值在于**按需拆包**：首屏用不到的重组件（图表库、富文本编辑器）拆成独立 chunk，不拖累首屏加载速度。

```js
import { defineAsyncComponent } from "vue";

const AsyncChart = defineAsyncComponent(() =>
  import("./components/HeavyChart.vue")
);
```

> 工厂函数返回的 Promise resolve 的结果就是组件本身。动态 import 是原生 ES 模块能力，构建工具据此做代码分割；这与静态 import 在构建期就打包进主 chunk 的行为完全不同。

**速记**：异步组件 = **动态 import 包一层**，用到的瞬间才加载。



#### 配置对象的五项核心配置

**配置对象形态**：defineAsyncComponent 除接收函数外，还可接收配置对象，精细控制加载过程的占位与异常表现。

- **loader**：必填，组件加载工厂函数，即基础形态中的那个函数。
- **loadingComponent**：加载过程中显示的**占位组件**。
- **errorComponent**：加载失败时显示的**错误组件**。
- **delay**：显示 loading 组件前的**延迟毫秒数**，默认 200，避免加载很快时占位内容一闪而过。
- **timeout**：超过该毫秒数仍未加载完成则**判定超时**，转而显示 errorComponent。

```js
import { defineAsyncComponent } from "vue";
import LoadingSpinner from "./LoadingSpinner.vue";
import LoadError from "./LoadError.vue";

const AsyncChart = defineAsyncComponent({
  loader: () => import("./components/HeavyChart.vue"),
  loadingComponent: LoadingSpinner,
  errorComponent: LoadError,
  delay: 200,
  timeout: 5000,
});
```

> [!TIP]
> **建议内容**：delay 默认 200 毫秒是防闪烁设计——网络快时占位组件一闪而过反而干扰视觉；需要永远显示 loading 的场景可把 delay 设为 0。

**速记**：**loader 必填，双组件占位兜错，delay 防闪，timeout 判死**。



#### 与路由懒加载的关系及 3.5 延迟水合

**边界辨析**：路由懒加载与 defineAsyncComponent 同源而不同用，二者都基于动态 import，但服务的层次不同。

- **路由懒加载**：vue-router 的路由配置中 component 直接写成 () => import 的工厂函数形式，由路由库内部处理，**无需**再包 defineAsyncComponent。
- **defineAsyncComponent**：服务于**任意位置的组件级**按需加载，可用在模板里任何用到组件的地方，且支持 loading 与 error 占位。
- 路由懒加载实现**页面级代码分割**，异步组件实现**组件级代码分割**；前者不能配置占位组件，页面内需要加载态时用后者。
- 3.5 起 defineAsyncComponent 新增**延迟水合**能力（如 hydrateOnVisible、hydrateOnIdle 等策略），服务端渲染场景下可让异步组件推迟到可见或空闲等时机再激活，进一步优化首屏。

```js
// 路由懒加载：路由配置里直接写工厂函数
const routes = [
  { path: "/about", component: () => import("./views/About.vue") },
];
```

> 判断用哪种：出现在路由表里的页面组件用路由懒加载；出现在某个页面内部的重组件用 defineAsyncComponent。两者可并存于同一项目，各管一层。

**速记**：路由表里**裸写工厂函数**，页面内部**defineAsyncComponent 包一层**。



### 动画性能

#### 优先 transform 与 opacity 走合成层

**性能原则**：编写过渡与动画时应优先只改变 **transform 与 opacity** 两个属性，让动画走**合成层**由 GPU 加速完成。

- 浏览器渲染一帧要经历样式计算、布局、绘制、合成等阶段；改 width、height、top、left 会触发**重排**，改 background、color 等会触发**重绘**。
- transform 与 opacity 的变化由**合成线程**独立处理，跳过布局与绘制，主线程再忙动画也不掉帧。
- 常见改写：位移用 transform: translateX 替代 left 与 margin，缩放用 transform: scale 替代 width 与 height，淡入淡出用 opacity 实现渐变而非 display 突变。
- 前文 TransitionGroup 的 FLIP 动画正是范例：位置移动全部用 transform 补间，因此列表再长也能保持流畅。

> [!IMPORTANT]
> **重要内容**：动画卡顿的排查顺序是先看被动画的属性是否触发重排，再考虑时长与缓动。把 left、width 类动画改写为 transform 版本，往往一行 CSS 就能消掉掉帧。

**速记**：动画只动 **transform 与 opacity**，其余属性必触发重排或重绘。



#### will-change 与合理的动画选型

**辅助手段**：will-change 可提前告知浏览器某元素即将变化，促使其**预先创建合成层**，但属于双刃剑，不可滥用。

- 对确定会频繁动画的元素加 will-change: transform，浏览器提前提升合成层，动画首帧即流畅。
- 滥用会让**大量元素各占一层**，层爆炸反而消耗更多内存与合成开销；只加给少数真正需要的热点元素，动画结束后可移除。
- 技术选型上，**CSS 过渡与动画**适合声明式的简单效果，不占主线程；**JavaScript 钩子或 Web Animations API** 适合需要逐帧控制与复杂编排的场景。
- 简单优先：能用 CSS 的不写 JS，能用 Transition 的不手写钩子，复杂度留给真正需要的地方。

> 动画工程的优先级是流畅第一、华丽第二：优先 transform 与 opacity、控制同时动画的元素数量、长列表动画配合虚拟滚动，才是可持续的方案。

**速记**：will-change **少而准**，简单动画**交给 CSS**。
