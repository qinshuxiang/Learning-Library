## 组件基础与 props

### 组件的认识

#### 组件是可复用的独立功能单元

**组件**：是**可复用、可组合的独立功能单元**，把一段界面所需的模板、逻辑与样式封装在一起，通过输入与输出和外界通信。

- 组件化把界面**按功能拆小**：一个按钮、一张卡片、一个表单都可以是组件。
- 组件的输入是 **props**，输出是**事件**，内部状态与实现细节对外封闭。
- 页面由组件**层层组合**而成，组件内再嵌组件，构成组件树。

> 组件的核心价值在**复用与隔离**：同一段标记与逻辑写一次、处处使用；组件内部实现变化不影响外部使用方式，改一处即全局生效。

**速记**：组件是**封装模板、逻辑、样式的复用单元**。



#### 单文件组件 SFC 是组件的标准组织形式

**单文件组件（SFC）**：是把一个组件的**模板、脚本与样式写在同一个 .vue 文件里**的组织形式，是 Vue 官方推荐的组件载体。

- template 块写**模板**，script setup 块写**逻辑**，style 块写**样式**，三块各司其职。
- 一个 .vue 文件**对应一个组件**，文件名即组件名，如 BaseButton.vue 导出组件 BaseButton。
- SFC 需要构建工具编译（Vite 配 @vitejs/plugin-vue 插件），**浏览器不能直接运行 .vue 文件**。

```html
<!-- BaseButton.vue -->
<template>
  <button class="base-button">
    <slot></slot>
  </button>
</template>

<script setup>
// 组件逻辑写在这里
</script>

<style scoped>
.base-button {
  padding: 6px 14px;
}
</style>
```

> style 块加 scoped 后样式**只作用于本组件**，是 SFC 实现**样式隔离**的关键手段；不加 scoped 时样式会全局生效，容易污染其他组件。

**速记**：SFC 用一个 .vue 文件装下**模板、逻辑、样式**。



#### 组件名用大驼峰并以文件名即组件名组织

**组件命名约定**：组件名使用**大驼峰（PascalCase）**，每个单词首字母大写，如 BaseButton、UserCard。

- 多单词命名可**避免与原生 HTML 元素重名**：button 与原生 button 元素冲突，BaseButton 则不会。
- 文件名与组件名保持一致：BaseButton.vue 里导出的组件就叫 BaseButton。
- 命名要**见名知意**，用完整英文单词，不加无意义的前缀或缩写。

> 官方风格指南建议组件名**至少两个单词**，既避开原生元素，也让“组件还是原生标签”一眼可辨；单词组件名（如 Item、Card）虽合法，但可读性与辨识度都欠佳。

**速记**：组件名**大驼峰、多单词、文件同名**。



### 组件的注册与使用

#### script setup 下导入即用无需显式注册

**导入即用**：在 script setup 中 import 一个组件后，**模板里即可直接使用**，无需再用 components 选项显式注册。

- script setup 会把顶层导入的组件**自动暴露给模板**，注册这一步由编译器代劳。
- 传统选项式写法要先在 components 选项里登记，setup 语法糖省去了该步骤。
- 导入后未使用的组件不会进入编译产物，依赖关系一目了然。

```html
<template>
  <BaseButton>确定</BaseButton>
</template>

<script setup>
import BaseButton from "./BaseButton.vue";
// 导入即可直接使用，无需 components 选项
</script>
```

> 导入即用只覆盖 script setup 等编译场景；若写传统选项式组件或运行时 render 函数，组件仍需通过 components 选项显式注册。

**速记**：script setup 下**导入即注册**。



#### 模板中以短横线或大驼峰标签使用组件

**标签使用约定**：组件在模板中既可写成**大驼峰标签**，也可写成 **kebab-case 短横线标签**，两种写法完全等价。

- 声明用大驼峰 BaseButton，使用写 base-button，编译器会**自动匹配**。
- kebab-case 在任何模板场景都合法；大驼峰标签只在 SFC 与字符串模板中可用，DOM 内模板不可用。
- 团队统一选一种风格即可，官方风格指南对 SFC 推荐大驼峰标签，DOM 内模板只能用短横线。

```html
<template>
  <!-- 两种写法等价，均可正常渲染 -->
  <BaseButton>提交</BaseButton>
  <base-button>提交</base-button>
</template>
```

> 组件标签的**自闭合写法**（标签不写闭合）只在 SFC 与字符串模板中有效；DOM 内模板受浏览器解析规则约束，必须写显式闭合标签。

**速记**：SFC 里两种标签等价，**DOM 内只认短横线**。



#### 局部注册是默认方式全局注册需克制

**局部注册是默认方式**：script setup 的导入即用就是局部注册，组件**只在导入它的文件里可用**；全局注册则通过 app.component 把组件挂到整个应用。

- 全局注册在入口文件写 app.component("BaseButton", BaseButton)，此后**任何组件无需导入**即可使用。
- 局部注册的好处是**依赖清晰**：看 import 就知道用了哪些组件，未导入的组件不会被打进产物。
- 全局注册的代价：组件**全部进入打包结果**，且使用来源难以追溯，官方建议优先局部注册。

```js
// main.js
import { createApp } from "vue";
import App from "./App.vue";
import BaseButton from "./components/BaseButton.vue";

const app = createApp(App);
app.component("BaseButton", BaseButton); // 全局注册
app.mount("#app");
```

> 全局注册只适合**极少数全局高频的基础组件**（如图标、基础弹层）；绝大多数组件应保持局部注册，否则包体积与依赖清晰度都会受损。

**速记**：默认**局部导入即用**，全局注册要克制。



### 用 defineProps 声明 props

#### props 是父组件传给子组件的数据通道

**props**：是父组件传给子组件的**自定义属性**，是父子通信中**父到子**方向的数据通道。

- 父组件在子组件标签上**以属性形式传值**：静态值直接写，动态表达式加冒号。
- 子组件用 defineProps **声明接收**哪些 prop，声明之后在模板与逻辑中使用。
- prop 与组件内部状态的差别：prop 的值**由父组件控制**，子组件只读不写。

```html
<template>
  <!-- 父组件：静态传字符串，动态传表达式 -->
  <UserCard name="张三" :age="18" />
</template>
```

> 组件向父通信走**事件**方向，见本系列 9. 组件事件与组件级 v-model.md；数据要跨多层传递时，改用依赖注入，见 11. 依赖注入 provide 与 inject.md。

**速记**：props 是**父到子**的数据通道，先声明后使用。



#### 数组式声明列出 prop 名即可

**数组式声明**：以字符串数组列出**要接收的 prop 名**，是最简的声明方式。

- 写法：const props = defineProps(["name", "age"])。
- 只声明名字，**不带类型与校验**，适合原型验证或极简组件。
- 声明后 script 中用 props.name 访问，模板中直接写 name。

```js
const props = defineProps(["name", "age"]);
console.log(props.name);
```

> 数组式声明无法表达**期望类型**，父组件传错类型不会有任何提示；正式组件建议改用对象式声明补上类型信息。

**速记**：数组式**只报名字，不做校验**。



#### 对象式声明可携带类型与更多配置

**对象式声明**：以对象形式声明每个 prop 的**类型、必填性与默认值**，是正式组件的标准写法。

- 键为 prop 名，值为**类型构造函数**（如 String、Number）或配置对象。
- 简写形态 name: String 等价于 name: { type: String }。
- 配置对象可写 type、required、default、validator 四个键，细目见下文校验各考点。

```js
const props = defineProps({
  name: String,
  age: {
    type: Number,
    required: true,
  },
  tags: {
    type: Array,
    default: () => [],
  },
});
```

> 对象式声明里类型写的是**构造函数本身**，不是字符串；String 是构造函数引用，带引号的 "String" 是字符串字面量，二者不是一回事。

**速记**：对象式**名配类型配配置**，正式组件首选。



### prop 的校验

#### type 用构造函数规定类型且可传数组

**type**：规定 prop 的**期望类型**，值是构造函数；类型可能不止一种时传**构造函数数组**。

- 可用类型包括 String、Number、Boolean、Array、Object、Date、Function、Symbol，以及自定义类。
- 多类型写法 type: [String, Number]，值与其中任一类型匹配即通过。
- type 只约束**值的类型**，不管取值范围，范围控制交给 validator。

```js
const props = defineProps({
  size: {
    type: [String, Number],
    // 字符串或数字都合法，如 "small" 或 14
  },
});
```

> type 是**约束声明而非强拦截**：类型不匹配只在开发环境打印警告，线上构建后不会阻止渲染；不要指望 type 承担业务数据验证。

**速记**：type 写**构造函数**，多类型用**数组**。



#### required 与 default 控制必填与默认值

**required**：标记 prop 是否**必传**；**default**：规定父组件**未传该 prop 时**使用的默认值。

- required: true 时父组件不传该 prop，开发期会收到一条警告。
- default 给**可选 prop** 兜底：原始值直接写，如 default: 0、default: "全部"。
- required 与 default 语义互斥：必填的 prop 不需要默认值，二者不应加在同一个 prop 上。

```js
const props = defineProps({
  pageSize: {
    type: Number,
    default: 10, // 未传时用 10
  },
  total: {
    type: Number,
    required: true, // 必传，不传警告
  },
});
```

> default 在父组件**显式传值为 undefined** 时同样生效；但显式传 null 不会触发 default，null 会原样传入，需要区分“没传”与“传空”时要注意这个差别。

**速记**：required 管**必传**，default 管**没传时的兜底**。



#### 对象与数组类型的默认值必须用工厂函数

**工厂函数默认值**：prop 类型为 Object 或 Array 时，default 必须写成**返回对象或数组的函数**，不能直接写字面量。

- 错误写法 default: [] 与 default: {}；正确写法 default: () => [] 与 default: () => ({ page: 1 })。
- 原因：对象与数组是**引用类型**，字面量默认值会被多个组件实例**共享同一份引用**，一处修改殃及所有实例。
- 工厂函数让每个实例**各自创建一份新值**，互不影响。

```js
const props = defineProps({
  tags: {
    type: Array,
    default: () => [], // 每个实例独立的新数组
  },
  query: {
    type: Object,
    default: () => ({ page: 1 }), // 每个实例独立的新对象
  },
});
```

> [!CAUTION]
> **注意内容**：给对象或数组类型 prop 直接写**字面量默认值不会报错**，问题静默存在——所有未传该 prop 的实例共享同一份数据，一个实例内的修改会波及其余实例，排查起来非常隐蔽。

> 箭头函数直接返回对象字面量时要**包一层圆括号**写成 () => ({ page: 1 })，否则花括号会被解析为函数体而非对象。

**速记**：引用类型默认值**必须工厂函数**，每实例一份。



#### validator 自定义校验与校验失败的后果

**validator**：是接收 prop 值、**返回布尔值**的自定义校验函数，用于表达 type 无法描述的约束。

- 返回 true 表示通过，返回 false 表示校验失败。
- 典型用途：**枚举校验**（值必须落在若干选项之中）、**范围校验**（数值不得小于某下限）。
- **校验失败的后果**：仅在开发环境向控制台输出一条警告，**组件照常渲染**，不中断运行。

```js
const props = defineProps({
  size: {
    type: String,
    validator(value) {
      // 值必须落在三个选项之内
      return ["small", "medium", "large"].includes(value);
    },
  },
});
```

> type、required、validator 组成的校验体系全部是**开发期辅助**，生产构建后整体静默；真正的业务数据校验要放在运行时逻辑里，不能依赖 prop 校验兜底。

**速记**：validator 返回**布尔**，校验失败**仅开发期警告**。



### 单向数据流

#### 数据自父向子单向流动

**单向数据流**：props 的流动方向是**自父向子**，父组件的数据变化自动流向子组件，反向则不被允许。

- 父组件更新传入的值，子组件中的 prop **响应式地同步更新**。
- 子组件**不能通过修改 prop 去影响父组件**，数据的出口与入口各司其职。
- 该约束让数据变化**可追溯**：出问题先查父组件的数据源，而不必到处找谁改了值。

> 单向数据流是 Vue 与 React 共同坚持的组件通信原则，概括为**数据向下、事件向上**。子组件要影响父组件，只能发出事件由父组件自己改，详见本系列 9. 组件事件与组件级 v-model.md。

**速记**：数据**向下流**，事件**向上发**。



#### 子组件不得直接修改 prop

**禁止直接改 prop**：子组件对 prop 重新赋值或就地变更其内容，都会**触发开发期警告**，且违反单向数据流。

- 基本类型 prop 被重新赋值（如 props.count = 5）会立刻得到警告。
- 引用类型 prop 被就地变更（如向 props.list 中 push 新项）同样破坏单向流，只是不易被察觉。
- 想改 prop 的动机通常是“让父组件同步”，正确路径是**发事件让父组件改自己的数据**。

> [!WARNING]
> **警告内容**：直接修改 prop 会**打破单向数据流**，导致数据来源混乱、变化难以追溯。Vue 只以警告提示而不阻断运行，隐患会在后续维护中集中爆发，务必从源头避免这种写法。

**速记**：prop **只读不写**，要改就**发事件回父组件**。



#### 需要改动的合法路径是本地中转与派生

**合法路径**：子组件确实需要“基于 prop 得到一个会变的值”时，有两条标准做法——**本地初始值中转**与 **computed 派生**。

- **本地中转**：把 prop 作为初始值存入本地响应式变量，之后只改本地变量，prop 仅作起点。
- **computed 派生**：prop 只是参与计算的原料，最终值由计算属性实时得出，prop 一变结果自动更新。
- 两条路径的共同点：**prop 本身始终未被修改**，单向流保持完整。

```js
import { ref, computed } from "vue";

const props = defineProps(["initialCount"]);

// 路径一：本地中转，prop 只作初始值
const count = ref(props.initialCount);

// 路径二：computed 派生，prop 变则结果变
const doubleCount = computed(() => props.initialCount * 2);
```

> 选型看**结果要不要持续跟随 prop**：要跟随就用 computed；只要初始值、后续独立变化就用本地中转。中转之后 prop 再变，本地值**不会**跟着变，这是它与 computed 的本质差异。

**速记**：改值走**本地中转或 computed 派生**，prop 本体始终不碰。



### prop 的命名

#### camelCase 声明配合 kebab-case 使用

**命名约定**：prop 在 JavaScript 里用 **camelCase（小驼峰）**声明，在模板里传值时推荐写 **kebab-case（短横线）**，两种写法自动匹配。

- 声明 maxSize，模板里写 :max-size="5" 即可，写 :maxSize="5" 同样有效，官方推荐前者。
- 短横线写法贴近 HTML 属性习惯，任何模板场景都不会出错。
- 事件名遵循类似的配套约定，配合组件级 v-model 使用，见本系列 9. 组件事件与组件级 v-model.md。

```html
<template>
  <!-- 声明为 maxSize，推荐传值写短横线 -->
  <FileList max-size="5MB" :current-size="2" />
</template>
```

> 静态传值不带冒号、动态传值必须带冒号：max-size="5MB" 传的是字符串 5MB，:current-size="2" 传的是数字 2，**冒号决定传的是字面量还是表达式**。

**速记**：声明**小驼峰**，传值**短横线**，冒号分**静态动态**。



#### DOM 内模板对大小写有严格限制

**DOM 内模板限制**：直接写在 HTML 页面里的模板要经过**浏览器的 HTML 解析**，属性名一律被**转为小写**，小驼峰的 prop 名会因此失配。

- 浏览器把 maxSize 解析成 maxsize，Vue 按小驼峰匹配不到，prop 拿不到值。
- 因此 DOM 内模板必须写 **kebab-case**：max-size 能被正确还原为 maxSize。
- SFC 与字符串模板不经过浏览器解析，**无此限制**，大小写写法都能工作。

```text
DOM 内模板（直接写在 index.html 中）：
  <user-card max-size="5MB"></user-card>   正确，还原为 maxSize
  <user-card maxSize="5MB"></user-card>    错误，被浏览器转为 maxsize，失配
```

> 同源限制还有：DOM 内模板不支持组件的自闭合写法，必须显式闭合。这些限制正是官方推荐**统一使用 SFC**、避免 DOM 内模板的原因之一。

**速记**：DOM 内模板**只认短横线**，SFC 无此顾虑。



### 响应式 props 解构

#### 3.5 起解构 props 默认保持响应性

**响应式 props 解构**：Vue 3.5 起，直接解构 defineProps 的返回值，解构出的变量**仍然是响应式的**，该能力已**默认稳定开启**。

- 写法：const { title, count } = defineProps(["title", "count"])。
- 解构变量在编译时被转换为对 props 的属性访问，因此**不丢失响应性**。
- 3.4 中该能力还是需要显式开启的实验特性，3.5 起默认启用，新项目可直接使用。

```js
import { watchEffect } from "vue";

const { count } = defineProps(["count"]);

// count 保持响应性，变化会触发重新执行
watchEffect(() => {
  console.log(`count is: ${count}`);
});
```

> 解构保持响应性是**编译期转换**的结果：源代码里像普通变量，编译产物里是对 props.count 的访问。不经编译的运行时场景中，解构会退化为普通值拷贝而失去响应性，属概念边界而非日常用法。

**速记**：3.5 起**解构即响应**，默认稳定开启。



#### 解构默认值直接写在解构式中

**解构默认值**：响应式解构支持在解构式中**用等号直接给默认值**，编译后等价于对象式声明的 default。

- 写法：const { pageSize = 10, tags = [] } = defineProps(["pageSize", "tags"])。
- 引用类型的默认值同样按工厂函数语义编译，**每个实例各得一份独立值**。
- 对象式声明与解构式默认值**二选一**即可，不必对同一个 prop 重复设置。

```js
const { pageSize = 10, tags = [] } = defineProps(["pageSize", "tags"]);
// 编译后等价于对象式的 default: 10 与 default: () => []
```

> 解构式默认值胜在**声明与默认值同在一行**，可读性好；需要 required 标记或 validator 校验时，仍要回到对象式声明，二者按需选择而非互斥。

**速记**：解构式中**等号即默认值**，编译成 default。



#### 与 toRefs 方案的历史对比

**历史方案**：3.5 之前要在解构后保留响应性，需借助 **toRefs 或 toRef** 手动包装，如今已被原生响应式解构取代。

- 旧写法先接收完整的 props，再 const { title } = toRefs(props) 逐个包装。
- toRefs 方案的负担：多一层调用，解构出的每个变量都是 ref，使用时要带着包装层的心智负担。
- 新写法直接解构，变量**表现如普通值**，响应性由编译器保证，官方文档示例已按新写法组织。

```js
import { toRefs } from "vue";

// 旧方案：先拿整体 props，再 toRefs 包装
const props = defineProps(["title"]);
const { title } = toRefs(props);
```

> 老项目中的 toRefs 写法**依然有效**，不必为迁移而迁移；但新代码应统一用 3.5 的响应式解构，避免两种风格在同一项目里混杂。

**速记**：toRefs 是**过渡方案**，新代码直接解构。



### 透传 attribute

#### 透传 attribute 是自动落到底层元素的特性

**透传 attribute（fallthrough attributes）**：父组件传给子组件、但**未被声明为 prop 或 emit** 的属性与事件，会**自动落到子组件的根元素**上。

- 典型成员：class、style、id，以及 click 等原生事件监听（Vue 3 中事件监听也属于 attribute）。
- 已被子组件声明为 prop 的属性会被**正常吸收**，不再参与透传。
- 该机制让组件无需显式声明就能正确接收外部样式与事件，与原生元素的使用习惯对齐。

```html
<template>
  <!-- 父组件：class 与 click 都未在子组件中声明为 prop 或 emit -->
  <BaseButton class="primary" @click="submit">提交</BaseButton>
</template>
```

> 事件监听、class、style 是三大高频透传成员；其余自定义属性（如 data-id、aria-label）只要没被声明为 prop，同样会透传到根元素。

**速记**：未声明为 prop 的属性**自动落到根元素**。



#### class 与 style 按合并而非覆盖处理

**合并规则**：透传的 **class 与 style 不覆盖子组件根元素已有的内容，而是合并**。

- 子组件根元素写 class="btn"，父组件再传 class="primary"，最终渲染 class="btn primary"，**两个类都生效**。
- style 同理是**叠加生效**，同名样式属性冲突时以父组件传入的值为准。
- 合并的意义：**外观基调由组件内部确定，场景差异由外部补充**，二者共存互不排挤。

```html
<template>
  <!-- 子组件根元素 -->
  <button class="btn">提交</button>
  <!-- 父组件传 class="primary" 后，最终渲染为 class="btn primary" -->
</template>
```

> 除 class 与 style 外，其余 attribute 的透传规则是**同名覆盖**：父组件传入值与根元素已有属性冲突时，以父组件传入为准。

**速记**：class 与 style**合并生效**，其余 attribute**同名覆盖**。



#### $attrs 收集全部未被声明为 prop 的属性

**$attrs**：是组件实例属性，保存着**所有未被声明为 prop、也未被 emit 声明的透传属性**组成的对象。

- 模板中直接写 $attrs 即可访问，如 $attrs.class、$attrs.onClick。
- Vue 3 中**事件监听也在 $attrs 里**（如 onClick），这与 Vue 2 把事件拆入 $listeners 的做法不同。
- script setup 中用 **useAttrs** 获取同一份数据，与模板中的 $attrs 同源。

```js
import { useAttrs } from "vue";

const attrs = useAttrs();
console.log(attrs.class); // 与模板中的 $attrs 同源
```

> $attrs 对象会随组件更新而变化，但它**不是响应式对象**，无法被侦听器追踪；需要基于它做逻辑时，按一次性快照理解，不要把它当作响应式数据源。

**速记**：$attrs 是**透传属性的总收纳**，模板直接用，脚本用 useAttrs。



#### v-bind 美元 attrs 向内层转发

**转发写法**：在子组件的**内层元素或内层组件**上写 v-bind="$attrs"，把全部透传属性**显式传递下去**，是多级封装的标准手法。

- 适用场景：根元素只是布局包装层，真正要承接事件与样式的是里面的目标元素。
- v-bind="$attrs" 一次转发**整个对象**，等价于逐个绑定其中的键值对。
- 转发到内层组件时，该组件又会按透传规则继续处理，层层接力。

```html
<template>
  <!-- 外层 div 只做布局，属性与事件应落到真正的按钮上 -->
  <div class="wrapper">
    <button v-bind="$attrs" class="btn">
      <slot></slot>
    </button>
  </div>
</template>
```

> 只需转发部分属性时，可从 useAttrs 取出对象后**解构挑选再绑定**；需要整包转发时，v-bind="$attrs" 一行即可，不必逐个手写。

**速记**：v-bind 美元 attrs **整包转发**给内层。



#### inheritAttrs 设为 false 关闭自动继承

**inheritAttrs**：是组件选项，设为 false 后**关闭透传属性对根元素的自动继承**，属性只留在 $attrs 中等待手动处置。

- script setup 中用 **defineOptions** 声明：defineOptions({ inheritAttrs: false })。
- 典型组合：关闭自动继承后，再用 v-bind="$attrs" 把属性绑到真正需要的内层元素上。
- **多根组件**不做自动继承：根元素不唯一时 Vue 无法决定属性落到谁头上，外部又传了透传属性时开发期会收到警告，必须手动用 v-bind="$attrs" 指明去向。

```html
<template>
  <div class="wrapper">
    <button v-bind="$attrs" class="btn">提交</button>
  </div>
</template>

<script setup>
defineOptions({ inheritAttrs: false });
</script>
```

> 单根组件默认的自动继承已能满足多数需求；**只有当自动继承落错了位置**（落到包装层而非目标元素）时才关闭继承并手动转发，不要为关而关。

**速记**：inheritAttrs 关自动，v-bind 美元 attrs 接手动。



### 编译宏 defineProps

#### defineProps 是编译宏无需导入

**编译宏**：defineProps 是 **script setup 专属的编译器宏**，由编译器在编译期展开，**不需要 import**。

- 宏只能写在 script setup 的**顶层**，编译后从最终代码中消失，被替换为对应的运行时实现。
- 源码中的宏调用会被编译器改写，所需的运行时导入由编译产物自动补上。
- 同族编译宏还有 defineEmits、defineExpose、defineOptions、defineModel 等，全部同样免导入。
- 宏**不允许写在条件分支或函数内部**，编译器需要在编译期静态确定组件结构。

```js
// 无需 import，直接使用
const props = defineProps({
  title: String,
});

// 同族宏同理，也无需导入
const emit = defineEmits(["change"]);
```

> defineProps 还支持**类型参数写法** defineProps<{ title: string }>，以 TypeScript 类型承担声明；类型写法与对象式声明择一使用，编译器据此生成等价的运行时 props 定义。

**速记**：defineProps 是**编译宏**，免导入、顶层用、不能进分支。
