## 条件渲染与列表渲染

### 条件渲染指令 v-if 家族

#### v-if 是惰性渲染、条件为假时真实销毁

**v-if**：是**惰性条件渲染**指令，指令表达式的值为真时才把对应块**真实挂载**到 DOM，为假时把已渲染的块**真实销毁并移除**。

- 指令值是任意可求值的表达式，求值为假值（false、0、空字符串、null、undefined）时不渲染。
- 惰性的完整含义：初始条件为假时**完全不渲染**，连 DOM 节点都不存在；条件首次变真才触发初始化渲染。
- 切换过程执行的是**真实的创建与销毁**：块内的事件监听器与子组件随之一并销毁、重建，组件内部的响应式状态不会保留。
- 适用场景：条件**很少在运行时切换**，或块的内容初始化成本高、隐藏期间无需保留内部状态的场合。

```html
<p v-if="score >= 60">成绩及格</p>
```

```js
import { ref } from 'vue'
const score = ref(85) // 为真时渲染；改为 40 时节点被真实移除
```

> 惰性渲染是双刃剑：条件切换意味着**卸载与重挂载**，涉及真实的 DOM 操作与组件生命周期流转，切换成本高于纯样式切换。判断选型前，先数一数条件在运行时会切换多少次。

**速记**：v-if 条件为假**节点不存在**，切换即**销毁重建**。



#### v-else-if 与 v-else 构成互斥条件链

**条件链**：v-else-if 与 v-else 必须**紧跟**在 v-if 或另一个 v-else-if 块之后，共同构成自上而下求值、命中即止的**互斥分支结构**。

- 求值顺序自上而下：先判 v-if，再依次判各 v-else-if，全部为假时落入 v-else。
- 任何时刻**至多渲染一个分支**；v-else 不带表达式，是兜底分支。
- 分支之间必须**紧邻**，中间不得插入其他元素，否则条件链断裂、编译报错。

```html
<p v-if="score >= 90">优秀</p>
<p v-else-if="score >= 60">及格</p>
<p v-else>不及格</p>
```

```js
import { ref } from 'vue'
const score = ref(72) // 命中第一个 v-else-if 分支，渲染「及格」
```

> 条件链是编译期配对的结构约束：v-else-if 与 v-else 依靠紧邻的上一个兄弟块找到归属。链条一旦被无关元素隔断，Vue 会在编译阶段给出错误提示，模板无法正常渲染。

**速记**：链式分支**紧邻配对**，自上而下**命中即止**。



#### template 上的 v-if 一次控制多个元素

**template 分组**：把 v-if 写在 template 元素上，可以用一个条件**同时控制多个元素**的渲染，而 template 本身**不产生任何真实 DOM 节点**。

- v-if 是指令，一次只能挂在一个元素上；要显隐一组元素，逐个重复写 v-if 既啰嗦又易漏改。
- template 是编译期才存在的**逻辑分组容器**，渲染结果里只有它包裹的子元素，没有多余外壳。
- 常与条件链连用：template v-if 与 template v-else 各包裹一组分支内容，整体替换。

```html
<template v-if="loggedIn">
  <p>欢迎回来，{{ userName }}</p>
  <button>退出登录</button>
</template>
<template v-else>
  <p>游客模式</p>
  <button>去登录</button>
</template>
```

> 辨析：template 上的条件渲染结果是**无包装的**；若改用 div 包裹，渲染树里会多出一层实际参与布局的节点，可能干扰 flex、grid 等布局上下文。

**速记**：多元素同进退，用 **template 包裹**，**不留外壳节点**。



### v-show 与两种方案的选型

#### v-show 只切换 display、元素始终留在 DOM

**v-show**：是**始终渲染**的条件显示指令，不论条件真假都会把元素渲染进 DOM，仅靠切换 CSS 的 display 属性控制可见性。

- 条件为真时正常显示；条件为假时给元素加上 display: none，元素仍留在 DOM 树中。
- 切换只发生在**样式层面**，不涉及组件销毁与生命周期流转，开销极小。
- 元素初始就会渲染，因此**初始条件为假也要付出首次渲染成本**。

```html
<p v-show="showTip">这是一段提示文字</p>
```

> [!NOTE]
> **提醒内容**：v-show **不支持** template 元素，也没有 v-else 分支语法——它只作用于单个真实元素，这与 v-if 家族有本质区别。

**速记**：v-show **先渲染再藏匿**，开关只是 **display**。



#### v-if 与 v-show 的选型看切换频率与初始成本

**选型结论**：高频切换用 **v-show**，低频条件用 **v-if**；判断依据是二者把成本放在了不同阶段。

- **v-if**：初始成本低（条件为假时零渲染），切换成本高（真实销毁重建，含组件生命周期）。
- **v-show**：初始成本高（无论真假都渲染），切换成本低（仅切换 display 样式）。
- 运行时**频繁切换**的场景（折叠面板、选项卡显隐）选 v-show，避免反复重建。
- 条件**几乎不变**的场景（权限控制、整块功能开关）选 v-if，为假时彻底不渲染、不占 DOM。
- 需要条件为假时**连节点都不存在**（不参与 DOM 查询、不占布局位置）的场景，只能选 v-if。

> [!TIP]
> **建议内容**：拿不准时优先用 **v-if** 保持 DOM 干净；只有确认切换频繁、且元素初始状态常显时再改用 v-show。二者的性能差异在子组件体积大时会被急剧放大——重建一个重组件远比切换样式昂贵。

**速记**：**高频显隐 v-show，低频惰性 v-if**；成本一个在切换、一个在初始。



### v-if 与 v-for 同元素时的优先级

#### Vue3 中 v-if 优先于 v-for 求值

**优先级反转**：同一元素同时写 v-if 与 v-for 时，Vue3 中 **v-if 先于 v-for 求值**，因此 v-if 的表达式**访问不到 v-for 的别名变量**。

- Vue3 的模板编译把 v-if 处理为外层判断，求值时 v-for 的 item、index 尚未进入作用域。
- Vue2 恰好相反：v-for 优先级更高，v-if 可以访问 item，这是两版之间最容易踩的差异。
- 在 Vue3 中于 v-if 里引用 item，渲染时会因变量未定义而抛错，问题在运行期即可暴露。

```html
<!-- Vue3 中渲染报错：v-if 求值时 item 尚不存在 -->
<li v-for="item in items" v-if="item.isActive">
  {{ item.name }}
</li>
```

> [!WARNING]
> **警告内容**：从 Vue2 迁移到 Vue3 时，依靠旧版 v-for 高优先级写出的同元素混用模板会**报错或静默失效**，必须逐处改写；不要凭旧版本的优先级直觉书写模板。

**速记**：Vue3 同元素 **v-if 先跑**，**摸不到 v-for 变量**；与 Vue2 相反。



#### 官方建议不在同一元素混用 v-if 与 v-for

**官方口径**：Vue 官方风格指南明确**不建议**在同一元素上同时使用 v-if 与 v-for，应按真实意图二选一改写。

- 意图是**过滤列表**：把过滤逻辑移入 computed，v-for 只负责遍历派生数组（详见本章末节）。
- 意图是**按条件渲染列表项内容**：v-for 在外层遍历，内层用 template v-if 控制条件块，二者分层。

```html
<!-- 按条件渲染列表项内容：v-for 在外、条件判断在内层 -->
<li v-for="item in items" :key="item.id">
  <template v-if="item.isActive">{{ item.name }}</template>
  <span v-else>已停用</span>
</li>
```

> [!IMPORTANT]
> **重要内容**：分层改写不只是风格问题——同元素混用会让条件的求值时机随版本漂移，代码可移植性差；v-for 外置、v-if 内置的写法在 Vue2 与 Vue3 中语义一致。

**速记**：过滤进 **computed**，条件进**内层 template**，**不混写同一元素**。



### 列表渲染 v-for 的遍历形态

#### v-for 遍历数组时提供 item 与 index

**数组遍历**：v-for 遍历数组的完整写法是 v-for=(item, index) in items，依次提供**当前项**与**当前项索引**。

- item 是当前元素的别名，index 是从 0 起的下标，二者名字可自定义，按位置对应。
- in 与 of 等价，v-for=item of items 同样合法，贴近 JavaScript 的 for...of 习惯。
- 遍历对象数组时，item 可直接以点语法访问字段，也可在别名处解构。

```html
<li v-for="(item, index) in todos">
  {{ index }} - {{ item.text }}
</li>
```

> 别名的作用域覆盖该元素及其全部子节点；不需要索引时，短形式 v-for=item in items 同样合法，索引按需引入即可。

**速记**：数组 v-for 拿 **item 与 index**，**in 与 of 等价**。



#### v-for 遍历对象时提供 value、key 与 index

**对象遍历**：v-for 遍历对象的完整写法是 v-for=(value, key, index) in object，三个参数依次为**属性值、属性名、索引**。

- 参数顺序固定：第一个永远是 value，第二个才是 key，与直觉中先 key 后 value 相反，是高频错误点。
- index 是属性在枚举序列中的序号，从 0 起。
- 对象的键序遵循 JavaScript 引擎规则：整数类键按数值升序排在前面，其余按键的插入顺序排列。

```html
<li v-for="(value, key, index) in profile">
  {{ index }}. {{ key }}: {{ value }}
</li>
```

> 想按固定顺序展示对象属性，不要依赖枚举序，应先把对象整理成数组（如用 Object.entries 转换）再遍历。

**速记**：对象 v-for 三参 **value 在前、key 居中、index 收尾**。



#### v-for 遍历数字与字符串生成固定序列

**数字遍历**：v-for 的源可以是数字 n，此时 item 从 **1 计到 n**，用于生成固定次数的重复结构；源为字符串时按**字符**迭代。

- v-for=n in 5 中 n 依次取 1、2、3、4、5，注意**起始是 1 而非 0**，与数组索引从 0 起不同。
- 字符串源 v-for=(ch, index) in word 依次给出每个字符及其下标，行为类似按字符拆分。
- 典型用途：分页页码、评分星级、占位骨架等固定长度结构。

```html
<span v-for="n in 5" :key="n">{{ n }}</span>
<!-- 渲染出 1 2 3 4 5 -->
<i v-for="(ch, index) in 'Vue'" :key="index">{{ ch }}</i>
```

> 数字遍历从 1 开始是文档明确的行为，写分页时若误以为从 0 起，会多出一个页码或整体错位一格。

**速记**：数字源**从 1 计到 n**，字符串源**逐字符迭代**。



#### v-for 别名的作用域与嵌套时的变量遮蔽

**作用域规则**：v-for 的别名变量是**模板局部变量**，内层作用域可以访问父作用域的变量（包括外层 v-for 的别名），反向则不可见；嵌套时**同名变量内层遮蔽外层**。

- 外层 v-for 的别名在内层 v-for 中可直接使用，这是渲染表格行列等二维结构的基础。
- v-for 的别名只在自身元素范围内可见，出了该元素就访问不到；前文优先级一节讲过的「v-if 摸不到 item」正是这条规则的体现。
- 内层别名与外层同名时，内层访问到的是**内层自己的值**，外层别名被遮蔽，极易引发错数据。

```html
<li v-for="(row, r) in matrix" :key="r">
  <span v-for="(cell, c) in row" :key="c">{{ cell }}</span>
</li>
```

> [!CAUTION]
> **注意内容**：嵌套 v-for 的内外别名**务必取不同的名字**，同名遮蔽不会报错，只会静默产出错误渲染结果，属于最难排查的一类模板 bug。

**速记**：内层**可见外层**，外层**不可见内层**；嵌套**禁用同名别名**。



### key 与列表 diff 的身份机制

#### key 是虚拟 DOM 节点的身份标识

**key**：是给虚拟 DOM 节点贴上的**身份标识**，diff 算法据此把新旧列表中 key 相同的节点判定为同一个，做精准的复用与更新。

- 不写 key 时，Vue 默认采用**就地复用**策略：按位置逐一比对、就地打补丁，不关心节点「是谁」。
- 写了 key 则进入**基于 key 的比对**：新旧列表先按 key 配对，配上的只更新内容，配不上的才增删。
- key 主要服务于 v-for 列表，也可用在需要强制「替换而非复用」的元素或组件上。
- diff 的完整执行机制详见本系列 19. 渲染机制与 render 函数.md 一文。

```html
<li v-for="item in items" :key="item.id">
  {{ item.text }}
</li>
```

> [!NOTE]
> **提醒内容**：key 的比对发生在**同层级兄弟节点**之间，跨层级不会因 key 相同而复用；key 也不必全局唯一，只需在**同一列表内**唯一。

**速记**：key 是**节点身份证**，diff 靠它**认人**而非认位置。



#### 不写 key 的就地复用会引发状态错位

**就地复用**：不带 key 的列表更新时，Vue 按**位置索引**把旧节点就地更新为新数据，节点本体不动，只替换内容。

- 位置对齐策略本意是减少 DOM 移动，代价是**节点的私有状态跟着位置走、而不是跟着数据走**。
- 列表项内含输入框、勾选框、子组件内部状态等**脱离渲染数据的临时状态**时，删除或插入会使这些状态错位到相邻项上。
- 典型表现：删除第一条后，原第一条输入框里残留的文字出现在了新第一条上。

```html
<!-- 无 key 的列表：删除首项后输入内容会错位 -->
<ul>
  <li v-for="(name, index) in names">
    <input placeholder="输入内容会串行" />
    {{ name }}
  </li>
</ul>
```

> [!CAUTION]
> **注意内容**：就地复用只保证「数据渲染结果正确」，不保证「DOM 私有状态正确」。列表项一旦包含表单控件或带内部状态的子组件，无 key 的就地更新就会产生肉眼可见的状态串位。

**速记**：无 key 时**状态跟位置走**，删除插入**必错位**。



#### key 的取值应稳定唯一、忌用数组下标的动态场景

**取值原则**：key 必须**在同一列表内稳定且唯一**，理想来源是数据自带的业务 id；数组下标仅在列表**永不重排**时可用。

- 稳定：同一数据项在更新前后 key 不变；不能用 Math.random 或每次生成的随机值，否则 diff 判定为全新节点，复用彻底失效。
- 唯一：同一列表内不重复，重复 key 会触发警告且更新行为不可预期。
- 下标的隐患：unshift、splice 删除、sort 等操作会改变数据项与下标的对应关系，效果等同退回「状态跟位置走」的错位老路。
- 纯静态展示、无重排的文本列表，用 index 作 key 没有实际危害，不必教条。

```html
<!-- 推荐：业务 id 作 key -->
<li v-for="user in users" :key="user.id">{{ user.name }}</li>
```

> [!WARNING]
> **警告内容**：在会**插入、删除、排序**的列表上用 index 作 key，等于主动放弃 keyed diff 的身份配对，把状态错位风险重新引入；这类列表必须改用稳定 id。

**速记**：key 要**稳定且唯一**；动态列表**忌用 index**，首选**业务 id**。



### 数组与集合的变更检测

#### 数组变异方法直接触发视图更新

**变异方法**：对响应式数组调用 push、pop、shift、unshift、splice、sort、reverse 这七个会**改变原数组**的方法，视图自动同步更新。

- Vue3 基于 Proxy 代理整个数组对象，对方法的调用与属性的写入都能被拦截感知。
- 上述方法只改原数组、不换引用，依然响应——这与「必须换引用才更新」的旧直觉不同。
- 返回新数组的非变异方法（如 concat、filter、slice、map）不改动原数组，需把返回值**重新赋值**给响应式引用才会反映到视图。

```js
import { ref } from 'vue'
const todos = ref(['a', 'b'])
todos.value.push('c')          // 变异方法，直接响应
todos.value.sort()             // 变异方法，直接响应
todos.value = todos.value.filter(t => t !== 'a')  // 非变异，须接返回值
```

> [!NOTE]
> **提醒内容**：Vue2 中对响应式数组调用 filter 等非变异方法后忘记重新赋值是经典 bug；这条规则在 Vue3 中不变——**非变异方法必须接收返回值**，变异方法则直接调用即可。

**速记**：**七个变异方法直接响应**；非变异方法**必须接返回值**。



#### Vue3 中按索引赋值与改 length 同样可响应

**索引与长度**：Vue3 中直接给响应式数组按索引赋值、直接修改其 length 属性，都能**触发视图更新**；这是与 Vue2 的又一关键差异。

- Vue2 的 Object.defineProperty 无法侦测索引写入与 length 变化，须借助 Vue.set 或 splice 绕行。
- Vue3 的 Proxy 拦截对象上的一切属性读写，arr[index] = value 与 arr.length = n 都在侦测范围内。
- 因此 Vue2 时代为索引赋值打的补丁写法在 Vue3 中已无必要，官方也不再推荐。

```js
const list = ref(['x', 'y'])
list.value[0] = 'z'     // Vue3 响应；Vue2 中视图不更新
list.value.length = 1   // Vue3 响应；Vue2 中视图不更新
```

> [!TIP]
> **建议内容**：迁移 Vue2 代码时，可以放心删除 Vue.set 与 splice 改索引的绕行补丁；判断标准只有一条——操作的是不是**响应式代理对象**，绕过代理（如解构后持有原数组引用再操作）则不响应。

**速记**：Vue3 **索引赋值、改 length 都响应**，Vue2 的 set 补丁**可以退役**。



#### v-for 遍历 Set 与 Map：3.5 起支持响应式遍历

**Set 与 Map 遍历**：自 **Vue 3.5** 起，v-for 可直接遍历**响应式**的 Set 与 Map，遍历时正确建立依赖追踪，集合变更自动驱动视图更新。

- v-for=item in tagSet 依次给出 Set 的每个成员，key 直接用成员本身。
- 遍历 Map 时 item 是**键值对数组**，可写成解构形式 v-for=[key, value] in configMap。
- 3.5 之前对响应式集合做 v-for 时依赖追踪不完整，惯用做法是先用扩展运算符展开成数组再遍历；3.5 之后这一绕行不再必要。

```html
<li v-for="tag in tagSet" :key="tag">{{ tag }}</li>
<li v-for="[key, value] in configMap" :key="key">{{ key }}: {{ value }}</li>
```

```js
import { ref, reactive } from 'vue'
const tagSet = ref(new Set(['vue', 'vite']))
const configMap = reactive(new Map([['theme', 'dark']]))
tagSet.value.add('pinia')     // 3.5 起视图同步追加
configMap.set('lang', 'zh')   // 3.5 起视图同步追加
```

> [!NOTE]
> **提醒内容**：本特性依赖 **Vue 3.5** 的版本口径；维护旧项目时若发现直接遍历响应式 Set、Map 不触发更新，先确认版本，再决定是否退回「先展开为数组」的旧写法。

**速记**：**3.5 起直接遍历响应式 Set 与 Map**，Map 的项是**可解构的键值对**。



### 过滤与排序：用 computed 派生列表

#### 过滤排序应在计算属性中完成而非 v-for 内判断

**派生列表**：前文选型一节已给出结论——过滤逻辑移入 computed，v-for 只遍历派生数组；本节展开写法与原理。

- computed 只在依赖变化时重新计算并缓存结果，重复渲染零开销；模板内联的过滤表达式每次渲染都要重算。
- 过滤逻辑收拢进 computed，比散落在模板里更易测试与复用。
- 派生链可组合：先 filter 再 sort，在同一条 computed 内完成，模板保持纯展示职责。

```js
import { ref, computed } from 'vue'
const todos = ref([
  { text: '写周报', done: true },
  { text: '改 bug', done: false }
])
const activeTodos = computed(() =>
  todos.value.filter(t => !t.done)
)
const sortedActive = computed(() =>
  activeTodos.value.slice().sort((a, b) => a.text.localeCompare(b.text))
)
```

```html
<li v-for="todo in sortedActive" :key="todo.text">
  {{ todo.text }}
</li>
```

> [!IMPORTANT]
> **重要内容**：对派生数组排序前先 slice 复制一份，避免 sort 直接改动原数组的顺序；虽然原数组被改同样会触发响应，但「展示排序不应污染源数据」是更安全的默认约定。

**速记**：过滤排序进 **computed**，模板 v-for **只管展示**。
