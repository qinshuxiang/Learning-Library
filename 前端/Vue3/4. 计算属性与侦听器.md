## 计算属性与侦听器

### 计算属性 computed

#### computed 是基于依赖缓存的派生状态

**计算属性（computed）**：是基于已有响应式数据**求值并缓存结果**的派生状态，依赖不变时不会重新计算。

- 定义方式：向 computed 传入一个 **getter 函数**，返回值就是计算属性的值，返回一个 **ref**。
- 依赖追踪：getter 内部访问到的响应式数据会被**自动收集为依赖**，无需手动声明。
- 缓存生效：依赖未变化时，后续读取直接返回**上次缓存的结果**，getter 不会重复执行。
- 依赖变化时：getter 才会**重新执行**，并更新缓存，同时触发依赖该计算属性的更新。

```js
import { ref, computed } from "vue";

const firstName = ref("三");
const lastName = ref("张");

const fullName = computed(() => firstName.value + lastName.value);
console.log(fullName.value); // 张三
// 只要 firstName、lastName 不变，fullName.value 无论读多少次都直接用缓存
```

> 计算属性的本质是**派生**：它不保存原始数据，只描述"原始数据如何算出结果"。模板里应当像使用普通 ref 一样使用它，注意在脚本中要加 .value。

**速记**：computed = **依赖收集 + 结果缓存**，依赖不动不重算。



#### computed 与方法的区别

**核心区别**：计算属性**基于依赖缓存结果**，方法**每次调用都重新执行**，这是二者唯一的本质差别。

- 缓存语义：computed 的依赖不变时重复读取**不再执行 getter**；调用方法则**每次都跑一遍函数体**。
- 使用形态：computed 当**属性**用（fullName.value 或模板里的 fullName），方法当**函数**调用（getFullName()）。
- 性能代价：若某结果被模板多处使用或渲染频繁发生，方法会在**每次渲染时重复计算**；计算属性只在依赖变化时算一次。
- 语义差异：computed 表达"**这是一个由什么推导出的值**"，方法表达"这是一个可执行的操作"。

```js
// 方法版本：每次渲染都执行
function getFullName() {
  console.log("方法执行了");
  return firstName.value + lastName.value;
}

// 计算属性版本：依赖不变时不再执行
const fullName = computed(() => {
  console.log("computed 执行了");
  return firstName.value + lastName.value;
});
```

> [!IMPORTANT]
> **重要内容**：模板中若把方法名写成了 fullName，它仍会被当作函数调用从而**每次渲染重新计算**；而 computed 不加调用括号即可享受缓存。判断该用哪个的标准是：**要的是值用 computed，要的是动作用方法**。

> 例外辨析：方法并非一无是处。若计算**没有响应式依赖**（每次都该得到新结果，如返回当前时间），或**每次渲染确实需要重新执行**（如传入变化参数的格式化），方法反而更合适；此时 computed 会因依赖为空而永不更新。

**速记**：computed **缓存复用**，方法**逢调必算**。



#### 可写计算属性 getter 与 setter

**可写计算属性（Writable Computed）**：传入 getter 与 setter 双函数后，计算属性既可读也可被赋值，赋值时触发 setter。

- 读取时执行 **getter**，得到派生值；与只读计算属性一致。
- 赋值时执行 **setter**，接收新值作为参数，由开发者决定**反向修改哪些源数据**。
- 典型场景：**全名的拆与合**——读 fullName 得到拼接结果，写 fullName 时拆成姓与名分别更新。

```js
import { ref, computed } from "vue";

const firstName = ref("三");
const lastName = ref("张");

const fullName = computed({
  get() {
    return lastName.value + firstName.value;
  },
  set(newValue) {
    [lastName.value, firstName.value] = newValue;
  },
});

console.log(fullName.value); // 张三（走 getter）
fullName.value = "李四";     // 走 setter，反向拆分
console.log(lastName.value); // 李
```

> setter 里应**只修改源数据**，不要直接保存传入的新值本身——派生状态是算出来的，不是存出来的。若 setter 需要执行异步或副作用逻辑，说明该用侦听器或事件而非可写计算属性。

**速记**：可写 computed = **get 读派生，set 反写源**。



#### computed 的最佳实践

**getter 应当是纯函数**：computed 的 getter 只做**读取依赖并返回结果**，不应产生副作用。

- 不修改其他状态：getter 内**不要修改任何响应式数据**，也不要改全局变量，否则依赖追踪与更新时机会变得不可预测。
- 不发异步请求、不操作 DOM：这类副作用应交给**侦听器 watch** 或事件处理函数完成。
- 返回值应基于依赖：返回结果必须**由 getter 中访问到的响应式数据推导而来**，不要返回随时间或随机数变化的值。
- 依赖必须可追踪：基于 reactive 对象时，**保持对响应式属性的持续引用**，避免解构后丢失响应性导致依赖收集失败。

```js
// 反例：getter 内修改状态并异步请求
const count = ref(0);
const bad = computed(() => {
  count.value++; // 禁止：getter 内改状态
  fetch("/api/list"); // 禁止：getter 内做副作用
  return count.value;
});

// 正例：纯 getter，副作用交给 watch
const good = computed(() => count.value * 2);
watch(good, (val) => fetch("/api/list?count=" + val));
```

> [!WARNING]
> **警告内容**：在 getter 中修改另一个响应式状态可能造成**无限循环更新**——改状态触发重算，重算又改状态。Vue 会在 setter 之间互相读取时给出警告，最佳实践是把这类逻辑一律移入侦听器。

**速记**：getter 三不——**不改状态、不异步、不碰 DOM**。



### 侦听器 watch

#### watch 的定义与四种侦听源

**侦听器（watch）**：用于**声明式地观察一个或多个响应式数据源**，在数据变化时执行回调，适合处理异步或开销较大的副作用。

- 侦听 **ref 对象**：直接传入 ref，隐式追踪 .value 的变化，最常用。
- 侦听 **reactive 对象**：直接传入 reactive 对象会**隐式开启深度侦听**，回调在任意嵌套属性变化时触发。
- 侦听 **getter 函数**：传入一个返回值的函数（如 () => props.id），只追踪该函数**返回值涉及**的依赖，粒度最细。
- 侦听 **数组多源**：传入由上述三种源组成的数组，任一源变化都会触发同一个回调。

```js
import { ref, reactive, watch } from "vue";

const count = ref(0);
const state = reactive({ name: "张三", age: 18 });

// 源一：ref
watch(count, (val) => console.log("count 变为", val));

// 源二：reactive 对象，隐式深度侦听
watch(state, (val) => console.log("state 变了", val));

// 源三：getter 函数，只盯 age
watch(() => state.age, (val) => console.log("age 变为", val));

// 源四：数组多源
watch([count, () => state.age], ([newCount, newAge]) => {
  console.log(newCount, newAge);
});
```

> [!CAUTION]
> **注意内容**：侦听 reactive 对象时**拿不到正确的旧值**——新旧值是同一个对象引用，深处的属性已被就地修改，打印 oldValue 与 newValue 内容一致。需要旧值时，应改用 getter 返回**解构后的具体属性**或浅拷贝，见后文深度侦听的规避方案。

**速记**：四种源——**ref、reactive、getter 函数、数组**。



#### watch 回调的参数 新值与旧值

**回调签名**：watch 的回调接收**新值（newValue）、旧值（oldValue）**两个参数，多源时二者是**按源顺序排列的数组**。

- 单源侦听：回调为 (newValue, oldValue) 形态，二者类型与源本身一致（ref 侦听得到的是解包后的值）。
- 数组多源：回调为 ([newA, newB], [oldA, oldB]) 形态，位置与源数组一一对应。
- 旧值的可靠性：**只有直接侦听 ref 或 getter 返回的原始值时，旧值才可靠**；深度侦听 reactive 对象时旧值失真。
- immediate 首次触发：配置 immediate 后第一次执行的回调中，**旧值是 undefined**。

```js
const count = ref(0);
const state = reactive({ age: 18 });

watch(count, (newValue, oldValue) => {
  console.log(newValue, oldValue); // 1 0
});

watch([count, () => state.age], ([newC, newA], [oldC, oldA]) => {
  console.log(newC, newA, oldC, oldA);
});
```

> 利用旧值可以做**变化比较**：只有当新旧值确实不同（或满足业务条件）时才执行请求，可减少无意义的副作用。旧值失真的场景下，比较逻辑应迁移到 getter 层面完成。

**速记**：回调拿**新值旧值**，多源变**数组**。



#### watch 的选项 deep、immediate、once

**watch 的第三个参数**：是选项对象，常用选项有 **deep（深度）、immediate（立即）、once（仅一次）** 三个。

- deep：设为 true 时**强制深度遍历**侦听对象内部所有嵌套属性的变化；侦听 getter 返回对象时默认**不深入**，需要显式开启。
- immediate：设为 true 时**创建后立即执行一次**回调，常用于进入页面就要"取一次数据再随变化再取"的场景。
- once：设为 true 时回调**只触发一次**，触发后自动停止侦听，**Vue 3.4 起支持**。
- 组合使用：三者可同时配置，如 { deep: true, immediate: true }。

```js
import { ref, watch } from "vue";

const state = ref({ list: [1, 2] });

// 深度侦听整个对象内部变化
watch(state, () => console.log("内部变了"), { deep: true });

// 立即执行一次 + 只触发一次
watch(
  () => state.value.list,
  (val) => console.log("拿到列表", val),
  { immediate: true, once: true }
);
```

> [!NOTE]
> **提醒内容**：deep 的代价是**遍历开销**——对象层级深、数据量大时，深度遍历会拖慢触发判断。

**速记**：deep **挖到底**，immediate **先来一次**，once **用完即停**（3.4 起）。



#### 深度侦听 reactive 对象的局限与规避

**reactive 深度侦听的规避**：旧值失真的原理前文已讲——回调的新旧值是**同一个 reactive 代理对象**，这里补充另一局限并给出规避路径。

- 局限（粒度太粗）：任意嵌套属性变化都触发回调，**无法区分是哪个属性变了**，回调里往往需要再次比较。
- 规避一（getter 精确追踪）：改用 getter 返回**解构后的具体属性**（或浅拷贝对象），既能拿到可靠旧值，又能缩小触发范围。
- 规避二（shallowRef）：把整体替换式的数据放进 **shallowRef**，只在 .value 整体替换时触发，天然避免深度遍历。

```js
import { reactive, watch } from "vue";

const state = reactive({ profile: { age: 18 }, logs: [] });

// 反例：整对象侦听，旧值失真
watch(state, (newVal, oldVal) => {
  console.log(newVal === oldVal); // true
});

// 正例：getter 返回解构后的具体属性，旧值可靠
watch(
  () => ({ ...state.profile }), // 浅拷贝出新对象
  (newVal, oldVal) => {
    console.log(oldVal.age, "->", newVal.age); // 18 -> 19
  }
);

// 正例：只要某个具体字段
watch(() => state.profile.age, (val) => console.log("age:", val));
```

> [!TIP]
> **建议内容**：侦听的目标**越小越好**——优先侦听"具体的那个值"，而不是整个对象。getter 返回值唯一确定触发条件，旧值天然可靠，还能顺带减少 deep 带来的遍历开销。

**速记**：reactive 整侦**旧值失真**，规避用 **getter 拆字段或 shallowRef**。



#### flush 时机 pre、post 与 sync

**flush 选项**：控制回调**相对组件更新的执行时机**，取值有 **pre（默认）、post、sync** 三种。

- pre（默认）：回调在**组件更新之前**执行，此时 DOM 尚未更新，读到的是旧界面。
- post：回调在**组件更新之后**执行，可以**安全访问更新后的 DOM**，也是侦听器中使用模板 ref 的推荐时机。
- sync：回调**同步触发**，数据一变立刻执行，不等待 Vue 的批量更新；仅适合需要精确同步时机的极少数场景。
- post 配合模板 ref：监听"ref 指向的 DOM 变化"时，必须等 DOM 渲染完成，因此把 flush 设为 post。

```js
import { ref, watch, watchEffect } from "vue";

const boxRef = ref(null); // 模板 ref，指向某个 DOM 元素

// watch 写法：flush: "post"
watch(boxRef, (el) => el && el.focus(), { flush: "post" });

// watchEffect 写法：通过第二参数指定 flush
watchEffect(() => {
  console.log(boxRef.value); // 自动依赖追踪
}, { flush: "post" });
```

> [!NOTE]
> **提醒内容**：想在回调里拿到**更新后的 DOM**，选 post；默认 pre 的设计是为了**在渲染前完成状态修正**，避免用户看到中间状态。sync 会打破 Vue 的批处理优化，非必要不使用。

**速记**：pre **渲染前**，post **渲染后可碰 DOM**，sync **变了就跑**。



#### 副作用清理 onCleanup 与 onWatcherCleanup

**副作用清理**：watch 的回调第三个参数是清理函数 **onCleanup**，注册的清理逻辑会在**下次回调触发前**以及**侦听器停止时**执行；Vue 3.5 另提供独立的 **onWatcherCleanup**。

- 参数形态：watch 回调签名为 (newValue, oldValue, onCleanup)，直接调用 onCleanup(清理函数) 注册。
- 经典场景：**请求竞态**——上一次请求尚未返回，下一次监听又触发，需要在每次触发前取消上一次。
- 3.5 的 onWatcherCleanup：从 vue 导入后可在**回调作用域内任意位置**调用，不必依赖第三个参数，适合封装的组合式函数。
- 清理时机：下一次回调执行**之前**先跑清理；侦听器 stop 或组件卸载时也会执行。

```js
import { ref, watch, onWatcherCleanup } from "vue";

const keyword = ref("");

// 写法一：回调第三参数 onCleanup
watch(keyword, (val, oldVal, onCleanup) => {
  const controller = new AbortController();
  fetch("/api/search?kw=" + val, { signal: controller.signal })
    .then((res) => res.json())
    .then((data) => console.log(data));
  onCleanup(() => controller.abort()); // 下次触发前取消上次请求
});

// 写法二：3.5 的 onWatcherCleanup
watch(keyword, (val) => {
  const controller = new AbortController();
  fetch("/api/search?kw=" + val, { signal: controller.signal });
  onWatcherCleanup(() => controller.abort());
});
```

> [!IMPORTANT]
> **重要内容**：凡是会**过期**的副作用（请求、定时器、事件监听）都应配套清理，否则会出现**竞态**：慢的旧请求晚返回，把新请求的正确结果覆盖掉。onCleanup 与 onWatcherCleanup 是 Vue 对这一问题的官方解法。

**速记**：**下次触发前先打扫**——onCleanup 挂参数，3.5 用 onWatcherCleanup。



### watchEffect 与侦听器的停止

#### watchEffect 立即执行并自动收集依赖

**watchEffect**：是**立即执行一次回调并自动追踪其内部所有响应式依赖**的侦听器，依赖变化时回调整体重跑。

- 立即执行：创建时就**先跑一遍回调**，无需 immediate 选项，天然覆盖初始化逻辑。
- 自动收集：回调里**读到谁就依赖谁**，首次执行时完成依赖收集，之后依赖变化即重跑。
- 只有新值：回调**不区分新旧值**，拿不到 oldValue，只感知"有变化需要重跑"。
- 与 watch 的代码差异：不传源，只传回调；依赖写在回调体内而非参数里。

```js
import { ref, watchEffect } from "vue";

const keyword = ref("");
const page = ref(1);

watchEffect(() => {
  // 首次立即执行一次；keyword 或 page 任一变化都会重跑

  console.log("查询：", keyword.value, "第", page.value, "页");
});
```

> watchEffect 重跑时会先执行上一轮注册的清理（用法与 onCleanup 相同），因此它同样适合请求场景。注意回调应**对称**：读哪些依赖、用哪些依赖，避免首跑收集不到真正需要的依赖。

**速记**：watchEffect **先跑一遍、自动收依赖、变了就重跑**。



#### watch 与 watchEffect 的选型

**选型原则**：依赖**明确且需要旧值**用 watch，依赖**多个且希望自动追踪**用 watchEffect。

- 用 watch 的情形：需要拿到**新旧值**做比较；只在**特定数据**变化时触发；需要 deep、immediate、once 等精细控制；副作用较重，想精确控制触发条件。
- 用 watchEffect 的情形：回调**同时依赖多个状态**且不想逐个罗列；**立即执行一次**的初始化副作用；依赖关系就是回调逻辑本身。
- 粒度对比：watch 的触发条件**显式可控**，watchEffect 的依赖随回调体**自动增减**——改一行代码，依赖集合随之变化。
- 风险对比：watchEffect 可能把**无关的依赖**也收进来（回调里多读了一个状态就多一个触发源），需保持回调精炼。

```js
// watch：明确依赖，要旧值
watch(page, (newPage, oldPage) => {
  if (newPage > oldPage) fetchList(newPage);
});

// watchEffect：多依赖自动追踪，立即执行
watchEffect(() => {
  fetchList(page.value, pageSize.value);
});
```

> [!TIP]
> **建议内容**：默认**优先 watch**——依赖显式、可读性好、能拿旧值；当回调确实是"一揽子状态的联合副作用"时再换 watchEffect，用更少的代码换自动追踪。

**速记**：**懒执行、要旧值选 watch；多依赖、要立即选 watchEffect**。



#### 侦听器的自动停止与手动停止

**停止方式**：侦听器在**组件卸载时自动停止**，跨组件或异步创建的侦听器需要用返回的 **stop 函数手动停止**。

- 自动停止的前提：侦听器在**组件的 setup 同步上下文**中创建，组件实例会把它们登记到该实例上，卸载时统一回收。
- 手动停止：watch、watchEffect 的返回值就是**停止函数**，调用后依赖变化不再触发回调。
- 必须手动的情形：在 setTimeout、事件回调、async/await 之后等**脱离同步 setup 上下文**的代码里创建的侦听器，Vue 无法自动绑定实例，需要自行保存并停止。
- 判断标准：创建时刻是否还**同步处于 setup 中**——是则自动停，否则手动停。

```js
import { ref, watchEffect } from "vue";

const count = ref(0);

// setup 同步创建：组件卸载时自动停止
const stopAuto = watchEffect(() => console.log(count.value));

// 异步创建：必须手动停止
setTimeout(() => {
  const stopManual = watchEffect(() => console.log(count.value));
  // 业务结束时调用
  stopManual();
}, 1000);

// 也可以在需要时手动停止同步创建的侦听器
stopAuto();
```

> [!WARNING]
> **警告内容**：在异步钩子或全局模块中创建的侦听器**不会随组件卸载而停止**，会造成**内存泄漏与无效回调**。规范做法是把返回的 stop 函数交给 onUnmounted 或在合适的业务节点调用。

**速记**：**同步创建自动停，异步创建手动 stop**。



#### watchPostEffect 与 watchSyncEffect 的简写形式

**简写别名**：Vue 提供了 **watchPostEffect** 与 **watchSyncEffect** 两个函数，分别等价于 watchEffect 加上 flush 为 post 或 sync 的固定配置。

- watchPostEffect：回调延迟到**组件更新之后**执行，等价于 watchEffect(回调, { flush: "post" })，是模板 ref 场景下的常用简写。
- watchSyncEffect：回调**同步执行**，等价于 flush 为 sync，数据一变立即跑，一般只用于调试或极特殊场景。
- 用法差异：这两个函数**不接收 flush 选项**，行为在创建时就已固定；普通 watch 与 watchEffect 仍通过选项对象指定时机。

```js
import { ref, watchPostEffect } from "vue";

const boxRef = ref(null);

watchPostEffect(() => {
  console.log(boxRef.value); // 组件更新之后执行，可拿到最新 DOM
});
```

> 三个函数的依赖追踪与停止行为完全一致，差别只在**回调时机**。记不住时机时，统一用 watchEffect 加 flush 选项显式声明，可读性反而更高。

**速记**：post、sync 各有**别名函数**，其余一律 watchEffect 加 flush。
