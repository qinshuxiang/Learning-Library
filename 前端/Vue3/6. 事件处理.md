## 事件处理

### v-on 监听事件的基础写法

#### v-on 指令与 at 简写是事件绑定的统一入口

**v-on**：是 Vue 提供的**事件绑定指令**，负责把模板元素的 DOM 事件与处理逻辑连接起来，简写形式为 **@ 加事件名**。

- 完整写法 v-on:click 与简写写法 @click 完全等价，简写是社区事实上的标准写法。
- 事件名直接写在 v-on: 或 @ 之后，如 @click、@input、@keyup，与原生加 on 前缀的 HTML 属性写法不同。
- v-on 的值是一段**模板表达式**或一个**方法引用**，事件触发时由 Vue 调用，而不是渲染时就执行。

```html
<!-- 完整语法与简写语法完全等价 -->
<button v-on:click="increment">完整写法</button>
<button @click="increment">简写写法</button>
```

> [!WARNING]
> **警告内容**：模板里的事件名不带 on 前缀，写成 @onclick 会因为监听了一个永不触发的事件名而静默失效。事件名区分大小写，@Click 与 @click 是两个不同的监听，书写时保持小写惯例。

**速记**：**v-on 等于 at 简写，事件名不带 on**。



#### 内联处理器与方法处理器是两种处理器形态

**内联处理器**：v-on 的值是一段**在事件触发时执行的模板表达式**，适合一两句就能写完的简单逻辑。**方法处理器**：v-on 的值是**一个方法名引用**，事件触发时 Vue 自动调用该方法，并把原生事件对象作为参数传入。

- 内联处理器写在引号里，可以自增状态、赋值、调用方法，本质是一条模板语句。
- 方法处理器只写方法名、不带括号，Vue 自动传入事件对象，处理函数声明形参即可接收。
- 方法处理器由 Vue 自动绑定 this 指向组件实例，无需手动 bind。

```html
<button @click="count++">内联表达式，直接改状态</button>
<button @click="handleClick">方法引用，自动收到事件对象</button>
```

```js
function handleClick(event) {
  // event 是原生 DOM 事件对象，与原生监听器收到的一致
  console.log("点击来源", event.target.tagName);
}
```

> [!IMPORTANT]
> **重要内容**：方法名带括号与否决定处理器形态——@click="handleClick" 是方法处理器，事件对象自动传入；@click="handleClick()" 是内联处理器，相当于手动调用，事件对象不会自动传入，需要时必须补写 $event。简单交互用内联，超过一行的逻辑抽成方法。

**速记**：**不带括号自动给事件，带括号是内联要自己传**。



#### 内联处理器传参依靠 $event 拿到事件对象

**$event**：是模板表达式内的**特殊变量**，代表**当前触发的原生事件对象**，用于在内联处理器传参的同时把事件一并传入处理函数。

- 显式传参：@click="greet('你好')"，把字面量或状态值直接传给方法。
- 传参加事件：@click="warn('提示', $event)"，$event 固定代表事件对象，参数位置随意。
- 多参场景：@click="(event) => warn('提示', event, extraData)"，用内联箭头函数自己决定参数结构。

```html
<button @click="greet('你好')">显式传参</button>
<button @click="warn('提示', $event)">传参同时拿事件对象</button>
<button @click="(event) => warn('提示', event, extraData)">内联箭头函数</button>
```

```js
function warn(message, event) {
  console.log(message, event.target.tagName);
  if (event) {
    event.preventDefault();
  }
}
```

> $event 只在模板表达式里有效，script 代码中不存在这个变量；它与方法形参指向同一个原生事件对象。内联箭头函数的灵活性最高，但参数整理逻辑变复杂时，更推荐把整理工作移回方法内部，保持模板干净。

**速记**：**$event 就是原生事件对象，只活在模板里**。



#### 数组与对象语法一次绑定多个事件处理器

**多事件绑定**：同一个事件需要触发多个处理函数时，Vue 提供**内联逗号语句**、**数组语法**与**对象语法**三种写法，后两者写函数引用、按声明顺序依次执行。

- 内联逗号语句：@click="one($event), two($event)"，把多条调用写成一条内联表达式，任何版本可用。
- 数组语法：@click="[one, two, three]"，写方法引用不加括号，事件对象自动逐个传入。
- 对象语法：@click="{ start: handleStart, stop: handleStop }"，Vue 3.4 起支持，键为自定义名、值为处理函数。

```html
<button @click="one($event), two($event)">内联逗号语句</button>
<button @click="[one, two, three]">数组语法</button>
<button @click="{ start: handleStart, stop: handleStop }">对象语法，3.4 起支持</button>
```

```js
function one(event) {
  console.log("第一个处理器", event.type);
}

function two(event) {
  console.log("第二个处理器", event.type);
}
```

> [!TIP]
> **建议内容**：数组与对象语法里写的是**函数引用**，不要加括号，加了括号就变成内联调用、拿到的是返回值而非注册函数。多个处理器的执行顺序就是书写顺序；彼此独立的收尾逻辑（埋点、日志）适合放进第二个处理器，与主逻辑解耦。

**速记**：**逗号内联、数组引用、3.4 起对象语法**。



#### 处理函数中 this 的指向取决于 API 风格

**this 指向**：事件处理函数内部的 this 是否指向组件实例，取决于使用的 **API 风格**——选项式 API 下由 Vue 自动绑定，组合式 API 下根本不依赖 this。

- 选项式 API：methods 里的方法处理器由 Vue 自动把 this 绑定为**组件实例**，可直接读写 this.count、调用 this.otherMethod。
- 组合式 API：script setup 中定义的函数是普通闭包，直接引用顶层的响应式变量，不存在也不需要 this。
- 模板内联表达式里若写 this，指向的是组件实例，但惯例是省略不写，保持模板简洁。

```js
export default {
  data() {
    return { count: 0 };
  },
  methods: {
    // 选项式 API：this 自动指向组件实例
    increment() {
      this.count += 1;
    }
  }
};
```

```js
// 组合式 API：闭包直接引用响应式变量，无 this
import { ref } from "vue";

const count = ref(0);

function increment() {
  count.value += 1;
}
```

> 初学者最常踩的坑是把方法处理器写成内联调用 this.increment() 的变体或手动 bind，选项式下这些操作都多余——Vue 已保证 this 绑定正确。判断用哪种风格写 this：看方法定义在 methods 里还是 script setup 里，前者用 this，后者用闭包变量。

**速记**：**选项式靠 Vue 绑 this，组合式用闭包没有 this**。



### 事件修饰符

#### 六个常用事件修饰符各司其职

**事件修饰符**：是以**点号后缀**附加在事件名之后的声明式标记，把常见的 DOM 事件细节处理封装成一个词，如 @submit.prevent 中的 .prevent。

- **.stop**：等价于 event.stopPropagation()，阻止事件继续冒泡。
- **.prevent**：等价于 event.preventDefault()，阻止默认行为，如链接跳转、表单整页提交。
- **.self**：仅当 event.target 是元素自身时才触发，点击子元素不算。
- **.capture**：以捕获阶段监听，等价于原生监听选项中的 capture。
- **.once**：触发一次后自动移除监听，等价于原生监听选项中的 once。
- **.passive**：等价于原生监听选项中的 passive，向浏览器承诺不调用 preventDefault，让滚动不必等待回调立即开始。

```html
<a @click.prevent="handleLink">链接不再跳转</a>
<form @submit.prevent="handleSubmit">表单不再整页刷新</form>
<div @click.stop="handleInner">点击不再冒泡到父级</div>
<div @click.self="handleSelf">点到子元素时不触发</div>
<button @click.once="handleFirst">只有第一次点击生效</button>
```

> .capture、.once、.passive 三个修饰符与原生 addEventListener 第三个参数中的选项一一对应；.stop、.prevent、.self 则被编译进包装函数，在合适的时机代为调用事件对象的对应方法。修饰符描述的是**事件行为本身**而非业务，因此可以放心写在模板里而不污染处理函数。

**速记**：**stop 断传播、prevent 断默认、self 认自己、capture 走捕获、once 只一次、passive 不拦截**。



#### 修饰符可以链式书写且顺序影响语义

**链式修饰符**：多个修饰符可以**连续点号连接**写在一个事件名之后，按**从左到右**的顺序依次生效，顺序不同可能导致语义不同。

- @click.prevent.self：先执行 prevent 再判断 self，因此**包括子元素在内的所有点击**都被阻止了默认行为。
- @click.self.prevent：先判断 self 再执行 prevent，只有**点击元素自身**才会触发并阻止默认行为，点击子元素整个处理器不执行。
- 顺序的本质是编译后的包装函数内语句的执行顺序，先写的先执行。

```html
<!-- 所有点击（含子元素）都阻止默认行为 -->
<div @click.prevent.self>方案一</div>

<!-- 仅点击自身时阻止默认行为，点子元素完全不触发 -->
<div @click.self.prevent>方案二</div>
```

> 链式书写时按语义排列：先声明阻止默认、阻止冒泡这类全局控制，再声明由谁来触发这类过滤条件，读起来更接近自然语言。拿不准顺序时，回到包装函数从左到右执行这个本质逐步推演即可。

**速记**：**修饰符从左到右执行，prevent 在前拦得宽，self 在前拦得窄**。



#### 修饰符的设计意义与 passive 的搭配限制

**修饰符的设计意义**：把 stopPropagation、preventDefault 这类 **DOM 事件细节**从处理函数中抽离，让模板承担事件行为的描述、处理函数专注**数据逻辑**。

- 处理函数里不再出现 event.preventDefault() 之类的调用，只剩与状态有关的代码。
- 模板中一眼即可看出该事件的完整行为特征：是否阻止默认、是否冒泡、是否只触发一次。
- 团队内统一用修饰符表达事件行为，风格一致、可读性更高。

```js
// 使用修饰符之前：DOM 细节混在业务逻辑里
function handleSubmit(event) {
  event.preventDefault();
  form.isValid = true;
}

// 使用 @submit.prevent 之后：只关心数据逻辑
function handleSubmit() {
  form.isValid = true;
}
```

> [!WARNING]
> **警告内容**：不要把 .passive 与 .prevent 用在同一个监听上——.passive 向浏览器承诺了不阻止默认行为，此后再写 .prevent 会被忽略，浏览器还会在控制台给出警告。这两个修饰符表达的是互相矛盾的承诺，必须二选一：需要阻止默认行为就不用 passive，追求滚动性能就保证不调用 preventDefault。

**速记**：**模板管行为、函数管数据，passive 与 prevent 互斥**。



### 按键修饰符与系统修饰键

#### 按键修饰符用别名或 kebab-case 匹配按键

**按键修饰符**：附加在 keydown、keyup 等键盘事件之后，用于**按按键过滤触发**，仅当对应按键参与时处理函数才被调用。

- 内置别名：.enter、.tab、.delete（同时覆盖退格与删除两个键）、.esc、.space、.up、.down、.left、.right。
- 别名之外的按键直接写 KeyboardEvent.key 的键名，并转成 **kebab-case**，如 @keyup.page-down 对应 pageDown 键。
- 按键修饰符可以与其他修饰符连用，如 @keyup.ctrl.enter 表示 Ctrl 加回车的组合。
- Vue 3 依据标准化的 KeyboardEvent.key 匹配按键，不使用已废弃的 keyCode 数字。

```html
<input @keyup.enter="handleSubmit" />
<input @keyup.esc="handleClear" />
<input @keyup.page-down="handlePageDown" />
<input @keyup.ctrl.enter="handleQuickSubmit" />
```

> 内置别名只覆盖九个高频按键，其余按键直接写键名即可，如 @keyup.q 监听 q 键；键名含大写字母时必须转成 kebab-case，否则会被当作其他修饰符解析。涉及中文输入法组字的按键判断，需配合事件对象的 isComposing 属性排除选词过程，基础概念见 JavaScript 系列的 12. 事件处理.md。

**速记**：**九个别名不够用，键名 kebab-case 直接写**。



#### 系统修饰键与 exact 精确控制组合

**系统修饰键**：**.ctrl、.alt、.shift、.meta** 四个后缀，要求对应按键处于按下状态时事件才触发，用于实现组合键交互。

- meta 键在 Mac 上是 Command 键，在 Windows 上是 Windows 徽标键。
- 单写 @click.ctrl 时，Ctrl 与其他系统修饰键同时按住也会触发，判定条件是该键被按下，而非仅该键被按下。
- 追加 **.exact** 修饰符可精确控制组合：@click.ctrl.exact 表示仅在 Ctrl 单独按下时触发。
- @click.exact 单独使用时，表示**没有任何系统修饰键按下**才触发。

```html
<!-- Ctrl 与 Shift 等同时按住也会触发 -->
<button @click.ctrl="handleCtrlClick">Ctrl 点击</button>

<!-- 仅 Ctrl 单独按下时触发 -->
<button @click.ctrl.exact="handleCtrlOnlyClick">精确 Ctrl 点击</button>

<!-- 不按任何系统修饰键时才触发 -->
<button @click.exact="handlePlainClick">无修饰键点击</button>
```

> [!CAUTION]
> **注意内容**：浏览器与操作系统会优先接管部分全局组合键（如 Ctrl 加 T 打开新标签页），页面内的监听收不到这些事件，设计快捷键前先确认组合键未被系统占用。.exact 精确的是系统修饰键的组合情况，与鼠标按键无关，二者可以叠加使用。

**速记**：**ctrl alt shift meta 管按下，exact 管独占**。



#### 鼠标按键修饰符区分左中右键

**鼠标按键修饰符**：**.left、.right、.middle** 三个后缀，限定事件只由对应的鼠标按键触发，依据是 MouseEvent 的 button 属性。

- .left 对应主键（通常为左键），.right 对应右键，.middle 对应中键（按下滚轮）。
- 对标准双键鼠标而言，@click.left 与 @click 的日常行为一致，前者显式过滤了按键来源。
- 三个修饰符可与其他修饰符组合，如 @mousedown.right 表示仅右键按下时触发。

```html
<button @mousedown.left="handleDrawStart">仅左键开始绘制</button>
<button @mousedown.right="handleOpenMenu">仅右键唤起菜单</button>
<div @mousedown.middle="handleMiddleClick">中键操作</div>
```

> 右键交互更常见的做法是监听 contextmenu 事件并配合 .prevent 阻止浏览器默认菜单，再自行渲染自定义菜单。触屏设备与部分外设不会产生中键事件，依赖 .middle 的功能需要准备替代交互方式。

**速记**：**left right middle 按键过滤，右键优先想 contextmenu**。



### 事件处理的常见实践

#### 动态事件名用方括号语法绑定

**动态事件名**：事件名本身不是一个固定字符串、需要**运行时决定**时，把 @ 后的事件名换成**方括号包起来的模板表达式**，表达式求值结果就是实际监听的事件名。

- 方括号内写一个求值为字符串的表达式，通常是 data、ref 或 computed 的值。
- 事件名变化时，Vue 会自动移除旧监听、注册新监听，无需手动解绑。
- 完整写法为 v-on:[eventName]，简写写法为 @[eventName]，二者等价。

```html
<!-- eventName 为 "focus" 时等价于 @focus -->
<input @focus="handleFocus" />
<input @[eventName]="handleDynamic" />

<button @[currentEvent]="handleAction">事件名随状态切换</button>
```

```js
import { ref } from "vue";

const eventName = ref("focus");
const currentEvent = ref("click");

// 运行时切换监听的事件类型，Vue 自动完成解绑与重绑
function switchToListenMouseEnter() {
  currentEvent.value = "mouseenter";
}
```

> [!TIP]
> **建议内容**：方括号内是表达式而非字符串，不要写成 @["click"] 这种把字面量硬包一层的形式，直接写 @click 即可。动态事件名配合组件使用时监听的是自定义事件名，同样遵循方括号语法，与原生 DOM 事件的用法保持一致。

**速记**：**事件名要变化，方括号包表达式**。



#### 表单提交事件的组合写法

**表单提交场景**：监听原生 submit 事件配合 **.prevent** 修饰符，是 Vue 中接管表单提交的标准写法，输入框内回车与点击提交按钮会走同一条路径。

- form 元素上写 @submit.prevent，阻止整页刷新，处理函数里专注校验与提交数据。
- 输入框上写 @keyup.enter 触发同一提交函数，与点击按钮殊途同归，逻辑不重复。
- 提交按钮写 type="submit" 即可，不必再监听按钮的 click 事件，避免回车提交被遗漏。

```html
<form @submit.prevent="handleSubmit">
  <input @keyup.enter="handleSubmit" />
  <button type="submit">提交</button>
</form>
```

```js
import { ref } from "vue";

const keyword = ref("");

function handleSubmit() {
  // 不需要再调用 event.preventDefault()，修饰符已代劳
  console.log("提交内容", keyword.value);
}
```

> 若监听的是提交按钮的 click 事件，用户在输入框里按回车触发的原生提交就不会被接管，表单会整页刷新——这是原生事件篇强调过的坑，Vue 中用 @submit.prevent 一次性规避。校验失败时直接在处理函数里 return，不必再操作事件对象。

**速记**：**submit 配 prevent，回车和按钮走同路**。



#### 高频事件配合防抖与节流使用

**高频事件**：input、scroll、resize、mousemove 这类事件**触发频率极高**，处理函数过重会拖慢页面，Vue 中同样要用**防抖**或**节流**稀释执行频率。

- 防抖：停止触发后再延迟执行，适合搜索联想、输入校验等只关心最终一次的场景。
- 节流：固定时间间隔内至多执行一次，适合 scroll、resize 等需要持续反馈的场景。
- 包装后的函数直接作为方法处理器绑定，模板写法不变，频率控制封装在函数内部。

```js
import { ref } from "vue";

const keyword = ref("");

// 防抖：停止输入 300 毫秒后才真正执行
function debounce(func, wait) {
  let timerId = null;
  return function (...args) {
    clearTimeout(timerId);
    timerId = setTimeout(() => func.apply(this, args), wait);
  };
}

const handleSearch = debounce(function () {
  console.log("发起搜索", keyword.value);
}, 300);
```

```html
<input v-model="keyword" @input="handleSearch" />
```

> 防抖与节流的完整实现与原理辨析见 JavaScript 系列的 12. 事件处理.md，Vue 不提供内置的防抖节流修饰符，需要自行封装或使用工具库。另一个思路是把逻辑改写为侦听器：对 ref 变量配置 watch 并设置延时，效果等价于防抖，且不依赖事件对象。

**速记**：**高频事件先稀释，防抖等安静节流按频率**。



### v-on 与原生事件机制的关系

#### 模板绑定最终编译为原生事件监听

**v-on 的底层本质**：模板中的事件绑定经过编译后，最终仍是对原生 **addEventListener** 的调用，处理函数拿到的就是**原生事件对象**。

- 编译阶段把 @click 等绑定转换为渲染函数中的监听注册代码，运行时挂载到真实 DOM 元素上。
- 事件对象具备原生 Event、MouseEvent、KeyboardEvent 的全部属性与方法，target、currentTarget、stopPropagation 等照常可用。

```js
// 模板 @click.prevent="handleSubmit" 的等价原生写法（示意）
el.addEventListener("click", (event) => {
  event.preventDefault();
  handleSubmit();
});
```

> [!NOTE]
> **提醒内容**：冒泡、捕获、事件委托、stopPropagation 与 preventDefault 的分工等传播机制与原生完全一致，基础概念见 JavaScript 系列的 12. 事件处理.md。Vue 并未另造一套事件模型，只是在原生机制之上做了声明式封装，调试时在处理函数里打印 event，看到的就是熟悉的原生对象。

**速记**：**v-on 是声明式外壳，底层还是 addEventListener**。



#### 组件标签上的 v-on 监听的是自定义事件

**组件上的 v-on**：写在组件标签上时，监听的是**组件内部通过 emit 抛出的自定义事件**，语义与原生 DOM 事件不同。

- MyButton 标签上的 @click 默认监听组件 emit 抛出的 click 事件，而非原生点击。
- 组件若在 emits 选项中声明了 click，该事件就被认定为自定义事件，原生点击不再自动透传给根元素。
- 未声明时，单根组件上的原生事件监听会作为透传 attribute 落到根元素上，表现类似原生绑定。

```html
<MyButton @click="handleClick" />
```

> 组件事件的完整机制——emit 的用法、emits 声明的影响、事件透传与多根组件的行为——属于组件通信范畴，见第 9 篇 组件事件与组件级 v-model。此处只需建立辨析意识：看到组件标签上的 v-on，先判断它监听的是自定义事件还是透传的原生事件，再决定能否使用事件修饰符。

**速记**：**组件标签上的事件先问来源，emit 抛出的才是自定义事件**。
