## JavaScript 代码块：执行模型

### 代码块定位

#### 为什么需要代码块

**JS 代码块是无代码的能力天花板**：块覆盖不了的场景全在这里。

- 复杂计算与多步数据处理：表达式一层表达力不够时
- 自定义 DOM 逻辑：批量操作、事件派发、动态创建节点
- 绕开 CORS 的网络请求：内置 automaFetch 走扩展后台
- 自定义流程控制：按运行时状态决定下一个块

> 判断标准一句话：需要语句（if、循环、try、await）的地方，表达式到不了，代码块顶上。能用块解决的别写代码，代码是逃生门不是默认选项——逃生门写多了，工作流就失去了低代码的可维护性。

**速记**：**语句进代码，块是常态码是逃生门**。



#### 代码块的基本配置

**代码块有四个关键配置**：超时、上下文、每次新标签执行、预加载脚本。

- 超时：默认 20000 毫秒（20 秒），超时后工作流继续执行下一个块
- 执行上下文：website（网页内）或 background（扩展后台），决定代码在哪跑
- 每次新建标签时执行：开关打开后不再依赖活动标签，但内置函数不可用
- 预加载脚本：主代码执行前先加载的 JS 文件 URL

> 超时的默认行为是“继续而非报错”：超时的代码块结果丢失但流程不断，这是有意设计的容错。依赖代码块输出的下游块要自己判断空值，不能假设上游一定成功。

**速记**：**二十秒超时继续走，上下文选对再写码**。



### 执行上下文

#### website 与 background

**两种上下文是完全不同的运行环境**：能力与限制各自成对。

- website：代码跑在页面里，能用 document 与 window，页面里能用什么它就能用什么
- background：代码跑在扩展后台，没有 DOM，但有扩展的全部网络能力
- 访问工作流数据（变量、表格）两种上下文都通过内置函数完成
- 切换上下文只改一个参数，代码却可能完全不通用

> 选型口诀：碰页面用 website，碰网络用 background。automaFetch 专门为 background 场景而生——在网页上下文里 fetch 会被 CORS 拦，走扩展后台则畅通无阻（11 篇展开）。

**速记**：**website 有 DOM，background 有网络**。



#### 每次新标签执行模式

**每次新建标签时执行是一种特殊模式**：不需要活动标签，代价是没有内置函数。

- 开关打开后，代码在每次 Automa 创建或切换标签时自动执行
- 此模式下不需要活动标签页即可工作
- automaRefData、automaNextBlock 等内置函数在该模式不可用
- 典型用途：每个新页面注入同一段脚本（如埋点、全局样式覆盖）

> 这是唯一拿不到内置函数的模式：数据交互全部断路，代码只能依赖页面自身。把它理解为“注入脚本”而非“工作流代码块”，期望就摆正了。

**速记**：**新标签即执行，内置函数不奉陪**。



### 异步与超时

#### 代码块里的 async

**代码块支持异步 JavaScript**：等待、请求、定时都能用。

- 代码可以写 async 语法：await 链、Promise 都正常工作（本库 JavaScript 系列第 30、32 篇是语法与事件循环的完整底座）
- 长耗时操作注意与超时预算的关系：默认 20 秒覆盖不住的操作先想想必要性
- automaResetTimeout() 可重置超时计时，给长任务续期
- 错误语义分两层：被 try 或 .catch 住的异常由代码自己兜底；未捕获的异常会让块失败，走工作流的错误处理（源码经 $error 标记抛出，见 16 篇）

> 代码块的异步模型就是页面里的异步模型：await 到的、then 链的、setTimeout 的都跑，但超时预算一视同仁。与外部 API 交互时，超时和重试在代码里自己管；想让失败有出口，要么自己 try 写标记，要么放任块失败走全局容错（13 篇）。

**速记**：**await 随便写，预算自己管，异常分家：try 的自留，漏的块失败**。



#### 超时行为与重置

**超时是代码块的硬约束**：理解它才能用好长任务。

- 达到超时时间，工作流不中断，直接执行下一个块
- 被超时打断的代码不会返回数据，下游拿到的是空
- automaResetTimeout() 重置计时器，适合分阶段的长任务
- 预加载脚本的加载时间也计入执行预算

> 长任务的正确姿势是分块：把 40 秒的活拆成两个代码块，各自在预算内完成，比依赖重置更可控。重置函数是逃生门，不是设计手段。

**速记**：**超时静默继续走，长任务拆块最稳**。
