## JavaScript 代码块：内置函数

### 数据访问与写出

#### automaRefData：读工作流数据

**automaRefData 是代码块里的统一读取入口**：变量、表格、循环项都在门内。

- 签名：automaRefData(keyword, path)，keyword 是数据源，path 是取值路径
- 读变量：automaRefData('variables', 'text')
- 读表格：'table' 加路径 '0'、'$last'、'0.name'，分别取首行、末行、首行 name 列
- 读循环当前项：automaRefData('loopData', 'loopId')
- 读全局数据：automaRefData('globalData')

> 它与表达式数据源是同一张地图（6 篇的八关键字）：代码块里不用 mustache，改用函数参数指路。路径规则一致——点号下钻、$last 取末行、数字下标取数组项。

**速记**：**第一参定数据面，第二参点路径**。

```js
// 代码块内读取工作流数据的典型写法
const price = automaRefData('variables', 'price');
const lastRow = automaRefData('table', '$last');
const current = automaRefData('loopData', 'myLoop');
```



#### automaSetVariable：写变量

**automaSetVariable 让代码块给工作流留下状态**：代码算出的结果交还给流。

- 签名：automaSetVariable(name, value)，值可为任意 JSON 类型
- 字符串、数字直接存：automaSetVariable('name', 'John Doe')
- 数组与对象照存不误：automaSetVariable('profile', { firstName: 'John' })
- 写入后，后续块用 {{variables.name}} 表达式即可读到

> 这是代码块与块体系之间的回传通道：代码负责算，变量负责交。写完变量再 automaNextBlock，下游块顺理成章接住——先写后走，顺序不能乱。

**速记**：**代码算完存变量，下游表达式接着用**。



### 流程控制与数据写入

#### automaNextBlock：继续执行与写入表格

**automaNextBlock 是代码块的句号**：不带它，代码跑完工作流就停。

- 签名：automaNextBlock(data?, insert?)，告诉工作流继续执行下一个块
- data 参数把数据写入表格：对象或对象数组，键必须与表格已定义的列匹配
- insert 参数控制是否写表，默认 true
- 对象形态可指定 nextBlockId 跳到指定块、replaceTable 替换整表数据

```js
// 写入一行并继续
automaNextBlock({ title: 'Something', count: 200 });

// 写入多行
automaNextBlock([{ title: 'Foo' }, { title: 'Bar' }]);

// 跳转到指定块
automaNextBlock({ title: 'Hello' }, { nextBlockId: '4dxcxa3' });
```

> 关键记忆点：代码块结尾必须调 automaNextBlock，否则流程戛然而止；表格键名必须对上列定义，对不上的键静默丢失。条件跳转用 nextBlockId 实现，但慎用——硬编码块 ID 的工作流改一次结构就要改一处代码。源码补充一个宽容细节：引擎检查代码文本里有没有 automaNextBlock 字样，没有就自动补一行空参调用，所以漏写不会断流，但显式写清楚仍是好习惯。

**速记**：**结尾必调 nextBlock，键对列名才进表**。



#### 分支跳转的克制使用

**nextBlockId 能跳块，但跳转是低内聚的做法**：能用条件块就别用代码跳。

- 代码内 if 加 automaNextBlock 可实现任意跳转
- 跳转把控制流藏进代码，画布上的连线不再反映真实走向
- 更可维护的分工：代码块只算出结果并存变量，分支交给条件块
- 确需跳转的场景（复杂校验后的错误出口）才用 nextBlockId

> 与本库 JavaScript 系列第 4 篇的分支思想呼应：控制流要显形。画布是工作流的“代码”，藏在代码块里的 goto 是它的反模式。

**速记**：**算结果归代码，做分支归条件块**。



### 网络与超时

#### automaFetch：绕开 CORS 的请求

**automaFetch 在扩展后台发请求**：CORS 拦不住它。

- 签名：automaFetch(type, resource)，type 为响应类型（text 或 json），resource 是 fetch 配置
- 用法与原生 fetch 同构：url、method、headers、body 一应俱全（本库 JavaScript 系列第 14 篇网络请求与跨域是背景知识库）
- 返回 Promise：.then 接结果或 await 取值
- 在网页上下文里调用它，请求实际从扩展后台发出，绕过页面同源策略

```js
const result = await automaFetch('json', {
  url: 'https://api.example.com/data',
  method: 'POST',
  body: JSON.stringify({ title: 'Hello world' }),
});
```

> 它解决的是“页面里 fetch 被 CORS 拦”的痛点：跨域请求、需要自定义头的 API 调用都交给它。响应类型选对——json 自动反序列化，text 拿原始文本。

**速记**：**签名同 fetch，请求走后台，跨域畅通**。



#### automaResetTimeout 与函数全景

**automaResetTimeout 重置超时计时**：代码块函数全景的最后一员。

- 无参数调用即重置：automaResetTimeout()
- 五个内置函数各司其职：读（automaRefData）、写变量（automaSetVariable）、写表与续流（automaNextBlock）、请求（automaFetch）、续期（automaResetTimeout）
- 前缀统一的 automa 命名与表达式里的 $ 函数划清界限：前者在代码内，后者在表达式内
- 每次新标签执行模式下这五个函数全部不可用（8 篇）

> 函数全景记忆法：一读一写一交卷，一请求一续期。写代码块前默念这五个名字，数据面就通了一半。

**速记**：**automa 五将：读、写、续、请、重置**。
