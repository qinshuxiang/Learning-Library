## 交互 API：命令、菜单、通知与闹钟

交互 API 是把用户动作与时间推移转换成扩展事件的一组接口，包括键盘命令 chrome.commands、上下文菜单 chrome.contextMenus、桌面通知 chrome.notifications 与闹钟 chrome.alarms。

四者按触发源分工：命令与菜单由用户操作触发，通知把扩展状态推送给用户，闹钟把时间变成事件。监听器都必须在 Service Worker 顶层同步注册，否则 Service Worker 被回收后事件送达时找不到处理函数。

### 四类 API 的权限与清单声明

commands 不占权限位，靠清单里的 commands 对象注册快捷键；其余三类各需一项 permissions 权限。icons 中的 16 像素图标会显示在菜单项旁边。

```json
{
  "manifest_version": 3,
  "name": "interaction-demo",
  "version": "1.0.0",
  "permissions": ["contextMenus", "notifications", "alarms"],
  "icons": { "16": "icons/icon16.png", "128": "icons/icon128.png" },
  "background": { "service_worker": "service-worker.js" },
  "commands": {
    "toggle-capture": {
      "suggested_key": { "default": "Ctrl+Shift+Y", "mac": "Command+Shift+Y" },
      "description": "开始或暂停采集"
    }
  }
}
```

> [!IMPORTANT]
> **重要内容**：Service Worker 空闲 30 秒即被关闭，四类 API 的事件送达时浏览器会重新拉起它并重放顶层代码。把 addListener 放进异步回调，重放时注册语句尚未执行，事件会被静默丢弃且不报任何错误。



### 键盘命令 chrome.commands

chrome.commands 把键盘快捷键映射到扩展逻辑。commands 对象的属性键即命令名，键值为一个对象，含 suggested_key 与 description 两个属性。suggested_key 可写字符串表示全平台通用，也可写对象，按 default、windows、linux、mac、chromeos 分平台给出。

```json
{
  "commands": {
    "open-sidebar": { "suggested_key": "Ctrl+Shift+O", "description": "打开侧边栏" },
    "toggle-feature": {
      "suggested_key": { "default": "Ctrl+Shift+F", "mac": "MacCtrl+Shift+F" },
      "description": "切换功能开关"
    }
  }
}
```

一个扩展最多只能声明四个建议快捷键，其余命令由用户在 chrome://extensions/shortcuts 手动绑定；命令默认只在 Chrome 处于焦点时生效，加 global 为 true 可全局生效，代价是建议快捷键被限制在 Ctrl+Shift+0 到 Ctrl+Shift+9，且 ChromeOS 不支持全局命令。

按键名区分大小写，写错会导致安装时清单解析失败。可用键为字母 A 到 Z、数字 0 到 9、Comma 与 Period 等标准键、四个方向键与四个媒体键；修饰键为 Ctrl、Alt、Shift，macOS 专有 MacCtrl、Option、Command，ChromeOS 专有 Search。组合必须包含 Ctrl 或 Alt，且 Ctrl 与 Alt 不得同时出现，以免与 AltGr 冲突；修饰键也不能与媒体键组合。macOS 上 Ctrl 会自动转换为 Command，需要真正的 Control 键时写 MacCtrl，而 MacCtrl 出现在其它平台的组合里会直接导致安装失败。

以单个下划线开头的命令名由浏览器保留，MV3 下可用的只有 _execute_action，它把快捷键绑定到扩展的工具栏操作上，等同于点击图标。

```js
chrome.commands.onCommand.addListener((command, tab) => {
  if (command === 'toggle-capture') toggleCapture(tab?.id);
});

function toggleCapture(tabId) {
  if (typeof tabId !== 'number') return;
  chrome.action.setBadgeText({ tabId, text: 'ON' });
}
```

> [!NOTE]
> **提醒内容**：保留命令不派发 onCommand 事件。需要同时覆盖「点击图标」与「按下快捷键」两条入口时，处理函数应挂在 chrome.action.onClicked 上，而不是在 onCommand 里判断命令名。

chrome.commands.getAll() 返回 Command 数组，每项含 name、description 与 shortcut，shortcut 为空字符串表示该命令未绑定，Chrome 110 之前 getAll 也不返回 _execute_action。快捷键可能被其它扩展占用并静默失效，因此在首次安装时检查一次即可；安装之后用户可能有意解除绑定，重复检查会与用户意图冲突。



### 上下文菜单 chrome.contextMenus

chrome.contextMenus 向右键菜单追加菜单项，权限为 contextMenus。菜单项可以出现在任何文档中，包括 file 协议与 chrome 协议的页面，用 documentUrlPatterns 限定出现范围。type 取 normal、checkbox、radio 与 separator 四种，同组 radio 项通过 checked 读写选中状态；出现位置由 contexts 数组决定，默认只含 page。

```text
all             除 launcher 之外的全部上下文
page / frame / selection / link / editable
image / video / audio
launcher        应用启动器，仅应用支持
browser_action / page_action
action          MV3 扩展操作按钮
tab             标签条，Chrome 150 起，多选标签时全部传入
```

targetUrlPatterns 按元素的 src 或 href 过滤，只对 image、audio、video 与链接元素有意义，与按文档网址过滤的 documentUrlPatterns 是两套独立条件。

create(createProperties, callback) 返回新项的 id。title 在 type 不为 separator 时必填，contexts 为 selection 时可以在标题里用占位符显示选中的文本；id 必须在本扩展内唯一，重复会创建失败并把错误写入 runtime.lastError。

```js
chrome.runtime.onInstalled.addListener(async () => {
  await chrome.contextMenus.removeAll();
  chrome.contextMenus.create({
    id: 'translate-selection',
    title: '翻译选中的文本',
    contexts: ['selection'],
  });
  chrome.contextMenus.create({ id: 'mute-domain', title: '静音此站点', contexts: ['page', 'tab'] });
});
```

> [!WARNING]
> **警告内容**：onInstalled 在安装、扩展更新与 Chrome 更新三种情形下都会触发。先 removeAll 再重建是可重复执行的安全写法；省略这一步会在扩展错误面板里累积 id 冲突错误，用户看到的菜单也可能停留在旧版本的定义上。

点击菜单项触发 chrome.contextMenus.onClicked，监听器收到 OnClickData 与 tabs.Tab 两个参数。OnClickData 的常用字段有 menuItemId、parentMenuItemId、selectionText、linkUrl、srcUrl、pageUrl、frameId、frameUrl、mediaType、editable、checked 与 wasChecked；处理函数应先按 menuItemId 过滤，再读取字段并把结果交给后续逻辑。createProperties 里的 onclick 属性在 Service Worker 中不可用，只能改用 onClicked 事件。同一扩展的多个菜单项同时显示时会被折叠进一个以扩展名命名的父菜单；挂在扩展操作图标上的菜单还有上限，顶级项最多 6 条，该值由常量 ACTION_MENU_TOP_LEVEL_LIMIT 给出。Chrome 123 起 update、remove、removeAll 都返回 Promise。



### 桌面通知 chrome.notifications

chrome.notifications 用模板生成系统通知，权限为 notifications，Chrome 116 起 create、update、clear、getAll 都返回 Promise。通知 id 由调用方给出且不得超过 500 个字符，缺省或传空字符串时自动生成；与现存通知同名会先清除旧的再创建。

type 取 basic、image、list 与 progress 四种模板：basic 含图标、标题、正文与最多两个按钮；image 额外带一张图片；list 用条目数组展示多条信息，macOS 用户只能看到第一项；progress 显示 0 到 100 的进度值。必填字段固定为 iconUrl、title 与 message 三项。

```js
await chrome.notifications.create('sync-progress', {
  type: 'progress',
  iconUrl: 'icons/icon128.png',
  title: '同步中',
  message: '正在同步书签',
  contextMessage: '已完成 3 项中的 1 项',
  progress: 33,
  buttons: [{ title: '暂停' }],
  requireInteraction: true,
  silent: true,
});
```

eventTime 是与通知关联的时间戳，priority 取 -2 到 2 且默认为 0，在不支持通知中心的平台上 -2 与 -1 会直接报错。requireInteraction 自 Chrome 50 起可用，silent 自 Chrome 70 起可用；imageUrl 与 appIconMaskUrl 自 Chrome 59 起弃用，isClickable 自 Chrome 67 起被忽略。

事件有四个：onClicked 传通知 id；onButtonClicked 传 id 与从 0 开始的按钮下标；onClosed 传 id 与 byUser 布尔值，用于区分用户关闭与系统关闭；onPermissionLevelChanged 传新的权限级别，自 Chrome 47 起只有 ChromeOS 有界面可派发它。用户可以关闭扩展的通知权限，此时 getPermissionLevel 返回 denied，创建通知会静默失败，因此发通知前应先读一次权限级别，只有返回 granted 时才继续创建。onShowSettings 自 Chrome 65 起弃用。



### 定时任务 chrome.alarms

chrome.alarms 把代码安排到指定时刻或按周期执行，权限为 alarms。它是 Service Worker 里替代 setInterval 的机制：定时器依赖常驻进程，而 Service Worker 空闲 30 秒即被关闭。create(name, alarmInfo) 的 alarmInfo 是 AlarmCreateInfo 对象，初始时刻由 when 或 delayInMinutes 二选一给出，重复周期由 periodInMinutes 给出；重复闹钟只设 periodInMinutes 而不设初始时刻时，它同时充当 delayInMinutes。

```js
await chrome.alarms.create('refresh-feed', {
  delayInMinutes: 1,
  periodInMinutes: 15,
  persistAcrossSessions: true,
});

chrome.alarms.onAlarm.addListener((alarm) => {
  if (alarm.name === 'refresh-feed') refreshFeed();
});
```

Alarm 对象含 name、scheduledTime、periodInMinutes 与 persistAcrossSessions 四个字段；scheduledTime 是计划触发时刻，出于性能考虑闹钟可能被延迟任意时长。闹钟名另有长度约束：Chrome 150 起 create 对名字强制 1024 字节上限，超长会抛出 TypeError；名字缺省为空字符串，因此不传名字的闹钟只有一条。get、getAll、clear、clearAll 自 Chrome 91 起返回 Promise，create 自 Chrome 111 起返回 Promise。

> [!WARNING]
> **警告内容**：Chrome 把闹钟限制为最多每 30 秒触发一次，且可能继续延后。delayInMinutes 或 periodInMinutes 小于 0.5 不会生效并产生警告；when 设为不足 30 秒之后不产生警告，但实际仍要等满 30 秒。以未打包方式加载的扩展不受此限制，开发期观察到的触发频率不代表上架后的行为。

设备休眠期间闹钟不唤醒设备，唤醒后把错过的闹钟一并补响；重复闹钟最多补响一次，随后从唤醒时刻重新起算周期。闹钟是否跨浏览器重启保留由 persistAcrossSessions 决定，该属性自 Chrome 150 起可用，Chrome 中默认值为 true，含义是持续到扩展更新为止；设为 false 则在扩展重载、浏览器重启与每次扩展更新时清除。个人资料启动会触发 chrome.runtime.onStartup，但它不派发任何 Service Worker 事件，onStartup 本身是一次普通的事件唤醒。

```js
chrome.runtime.onStartup.addListener(ensureAlarms);
chrome.runtime.onInstalled.addListener(ensureAlarms);

async function ensureAlarms() {
  const { alarmSpecs = [] } = await chrome.storage.local.get('alarmSpecs');
  for (const spec of alarmSpecs) {
    if (!(await chrome.alarms.get(spec.name))) await chrome.alarms.create(spec.name, spec.info);
  }
}
```

> [!TIP]
> **建议内容**：即使 Chrome 的默认值为 true，也应在创建时显式写出 persistAcrossSessions，并在每次 Service Worker 启动时检查闹钟是否存在、不存在就补建。其它浏览器与 Chrome 150 之前的版本不支持该属性，行为不可预测，补建是全部环境下都可靠的兜底。



### 徽章、标题与串联实践

徽章与标题是不打断用户的轻量提示通道：徽章文字叠加在工具栏图标上，标题在悬停时显示为提示，两者都由 chrome.action 提供。徽章空间有限，建议不超过 4 个字符，传空字符串即清除；setBadgeTextColor 自 Chrome 110 起可用，不设置时浏览器自动选取与背景对比的颜色。

```js
await chrome.action.setBadgeText({ tabId, text: pending > 0 ? String(pending) : '' });
await chrome.action.setBadgeBackgroundColor({ tabId, color: '#4c8bf5' });
await chrome.action.setTitle({ tabId, title: `待处理 ${pending} 项` });
```

传入 tabId 时设置只对该标签页生效，标签页关闭后自动重置；省略 tabId 则是全局设置，标签页级设置优先于全局设置。通知用于需要用户回应的信息，徽章用于只需要被看见的计数。

四类 API 常在一次用户手势中连续使用：快捷键触发命令，命令处理函数写闹钟，闹钟到期后建通知，通知被点击时用标签页与徽章反馈结果。

```js
chrome.commands.onCommand.addListener(async (command) => {
  if (command !== 'schedule-report') return;
  await chrome.alarms.create('daily-report', { delayInMinutes: 1, persistAcrossSessions: true });
});

chrome.alarms.onAlarm.addListener(async (alarm) => {
  if (alarm.name !== 'daily-report') return;
  await chrome.notifications.create('daily-report', {
    type: 'basic',
    iconUrl: 'icons/icon128.png',
    title: '日报已生成',
    message: '点击查看统计结果',
  });
});

chrome.notifications.onClicked.addListener((notificationId) => {
  if (notificationId !== 'daily-report') return;
  chrome.tabs.create({ url: 'report.html' });
  chrome.action.setBadgeText({ text: '' });
});
```

链路上每个环节都可能在 Service Worker 休眠期间到达，因此必须全部写在顶层同步注册的监听器里；每个环节的耗时都计入单个请求 5 分钟与 fetch 响应 30 秒的终止条件，长任务要拆成多段并由闹钟续跑。
