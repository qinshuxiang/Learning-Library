## 无 DOM 环境的能力补齐：offscreen 与媒体捕获

Service Worker 是 MV3 的后台执行环境，它没有 DOM，也没有依赖 DOM 的那一整类浏览器能力。offscreen 文档用来补齐这部分缺口，标签页捕获与桌面捕获把媒体流引入扩展，画中画文档用来在不占标签页的前提下浮起扩展界面。

三者的分工是：捕获 API 负责拿到流或流 ID，offscreen 文档负责提供能消费流、能操作 DOM、能播放音频的容器，画中画文档负责承载需要长期可见的界面。

### Service Worker 的能力缺口

Service Worker 与普通网页 Worker 同源同构，缺少的正是窗口对象带来的那套 API，具体分三类。

文档解析与查询缺失：没有 document，无法用查询选择器定位节点，也无法直接解析一段 HTML 字符串。媒体与图形缺失：没有音频播放元素与画面元素，因此无法播放音频、无法把媒体流接到画面上。存储习惯缺失：Web Storage 在扩展的 Service Worker 里不可用，localStorage 与 sessionStorage 都不存在，持久化只能落到 chrome.storage 或 IndexedDB。

内容脚本看起来是另一个出口，但它受两层限制：必须注入到某个页面里，扩展没有正当理由为了后台任务去污染用户正在看的页面；宿主页面的内容安全策略也会限制它能做什么。offscreen 文档的定位正是在两条路之间：它提供真实的 DOM 与窗口对象，但运行在隐藏文档里，不新增标签页、不弹窗、不打断用户。



### offscreen 文档的创建与 reasons

offscreen API 自 Chrome 109 起可用，权限为 offscreen。一个 offscreen 文档就是一份随扩展打包的 HTML 页面，被浏览器加载到不可见的文档中。

#### 权限与 createDocument 参数

```json
{
  "manifest_version": 3,
  "name": "clipboard-writer",
  "version": "1.0.0",
  "permissions": ["offscreen"],
  "background": { "service_worker": "service-worker.js" }
}
```

chrome.offscreen.createDocument(parameters) 返回 Promise，在文档创建完成并结束首次页面加载时敲定。parameters 是 CreateParameters 对象，三个字段全部必填：url 是随扩展打包的静态 HTML 文件的相对路径；reasons 是创建原因的数组；justification 是面向用户解释原因的一段文字，浏览器在向用户展示时可能引用它。

```js
await chrome.offscreen.createDocument({
  url: 'offscreen/clipboard.html',
  reasons: ['CLIPBOARD'],
  justification: '在后台写入剪贴板，避免打断用户当前页面',
});
```

chrome.offscreen.closeDocument() 关闭当前文档；chrome.offscreen.hasDocument() 自 Chrome 150 起提供，直接返回是否存在有效文档的布尔值。



#### Reason 的合法取值全集

reasons 必须取自 Reason 枚举，取值与语义如下，它同时决定文档的生命周期。

```text
TESTING          仅用于测试目的
AUDIO_PLAYBACK   文档负责播放音频
IFRAME_SCRIPTING 需要嵌入 iframe 并以脚本修改其内容
DOM_SCRAPING     需要嵌入 iframe 并抓取其 DOM 以提取信息
BLOBS            需要与 Blob 对象交互，包括 URL.createObjectURL()
DOM_PARSER       需要使用 DOMParser 解析 HTML 文本
USER_MEDIA       需要与 getUserMedia() 得到的用户媒体流交互
DISPLAY_MEDIA    需要与 getDisplayMedia() 得到的展示媒体流交互
WEB_RTC          需要使用 WebRTC 相关接口
CLIPBOARD        需要与剪贴板接口交互
LOCAL_STORAGE    需要访问 localStorage
WORKERS          需要派生工作线程
BATTERY_STATUS   需要读取电池状态
MATCH_MEDIA      需要使用媒体查询匹配
GEOLOCATION      需要读取地理位置
```

原因不是装饰性说明，它决定浏览器是否会回收这个文档：AUDIO_PLAYBACK 会让文档在不播放音频满 30 秒后自动关闭，其余取值都不设使用期限。当次任务同时需要多种能力时可以把多个原因一起列入数组。



#### 单实例约束与存在性检查

offscreen 文档与普通扩展页面有四处明确差异：url 必须指向随扩展打包的静态 HTML 文件；文档无法被聚焦；它虽然是窗口对象的实例，但 opener 恒为 null；一个已安装的扩展同时只能打开一个 offscreen 文档。在分屏模式运行且无痕浏览个人资料处于活动状态时，常规与无痕个人资料各自可以有一个。

```js
let creatingDocument = null;

async function ensureOffscreenDocument() {
  const contexts = await chrome.runtime.getContexts({
    contextTypes: ['OFFSCREEN_DOCUMENT'],
    documentUrls: [chrome.runtime.getURL('offscreen/clipboard.html')],
  });
  if (contexts.length > 0) return;
  if (creatingDocument) return void (await creatingDocument);

  creatingDocument = chrome.offscreen.createDocument({
    url: 'offscreen/clipboard.html',
    reasons: ['CLIPBOARD'],
    justification: '在后台写入剪贴板',
  });
  await creatingDocument;
  creatingDocument = null;
}
```

上面的去重是必要的：两个事件几乎同时到达时可能各自判定文档不存在并同时发起创建，第二次创建会失败。runtime.getContexts 自 Chrome 116 起提供，Chrome 116 之前只能在文档内用 clients.matchAll 遍历并比对网址。

> [!IMPORTANT]
> **重要内容**：chrome.runtime 是 offscreen 文档唯一可用的扩展 API。文档享受到扩展的权限，但拿不到 chrome.storage、chrome.tabs 等命名空间，一切跨上下文的数据交换都必须经由 runtime 的消息传递完成。这是刻意的能力收窄：文档里往往要处理外部输入，一旦被攻破，可触及的扩展能力越少越好。



### 生命周期与消息通信

三种原因会让 offscreen 文档消失：扩展显式调用 closeDocument；AUDIO_PLAYBACK 原因下停止播放音频满 30 秒；扩展本身被停用、重载或更新。因此每次要用之前都应检查它是否还在，而不是假设它仍存在。

消息传递用 runtime.sendMessage 与 runtime.onMessage，谁先发起都可以。文档侧只需按消息里的目标标记与类型过滤后处理，异步返回结果时监听器要返回 true 以保持通道打开，处理方式与内容脚本完全一致。因为 offscreen 文档发消息也会重置 Service Worker 的 30 秒空闲计时器，长期存在的文档会顺带延长后台生命周期，这一点自 Chrome 109 起生效。

```js
// Service Worker 侧：确保文档存在后下发任务
await ensureOffscreenDocument();
const response = await chrome.runtime.sendMessage({
  target: 'offscreen',
  type: 'write-clipboard',
  text: '已复制的文本',
});
```

> [!WARNING]
> **警告内容**：不要用「常开一个 offscreen 文档」实现后台常驻。文档一旦长期存在，Service Worker 的休眠机制被绕过，内存占用与耗电问题会以难以定位的形式出现。正确做法是按需创建、用完关闭，让文档只在确实需要 DOM 的那段时间存在。



### 媒体捕获：tabCapture 与 desktopCapture

两个捕获 API 都返回一个不透明的流 ID，真正的媒体流要在调用 getUserMedia 时用它换出来。区别在于捕获对象与用户授权方式。

chrome.tabCapture 的权限为 tabCapture。它的 capture 方法只能在对扩展有过用户调用之后调用，行为与 activeTab 类似：用户点击扩展图标、按下快捷键或选择菜单项，扩展才获得这次捕获的资格。

```js
chrome.action.onClicked.addListener(async (tab) => {
  const streamId = await chrome.tabCapture.getMediaStreamId({ targetTabId: tab.id });
  chrome.runtime.sendMessage({ target: 'offscreen', type: 'start-record', streamId });
});
```

getMediaStreamId 自 Chrome 71 起提供，Chrome 116 起返回 Promise，参数是 GetMediaStreamOptions：targetTabId 指定要捕获的标签页，缺省时取当前活动标签页，且只有扩展已获得 activeTab 权限的标签页能作为目标；consumerTabId 指定稍后用 getUserMedia 消费该流的标签页。流 ID 只能使用一次，未被使用会在几秒后过期；它绑定安全来源，指定了 consumerTabId 时只能由该标签页中同源框架使用，未指定时自 Chrome 116 起可由同一渲染进程中安全来源相同的任意框架使用，这正是 Service Worker 里取得的流 ID 能交给 offscreen 文档消费的原因。

捕获一个标签页的媒体流会让该标签页的音频不再向用户播放，其效果等同于把抑制本地音频播放的标志置为真。需要用户继续听到声音时，必须把流接到音频上下文并显式输出到默认目的地。

```js
async function startRecording(streamId) {
  const stream = await navigator.mediaDevices.getUserMedia({
    audio: { mandatory: { chromeMediaSource: 'tab', chromeMediaSourceId: streamId } },
    video: { mandatory: { chromeMediaSource: 'tab', chromeMediaSourceId: streamId } },
  });

  const audioContext = new AudioContext();
  audioContext.createMediaStreamSource(stream).connect(audioContext.destination);

  const recorder = new MediaRecorder(stream);
  recorder.start();
}
```

捕获状态可以查询与监听：getCapturedTabs 返回所有已请求或正在捕获的标签页（Chrome 116 起返回 Promise），条目为 CaptureInfo 对象，含 tabId、status 与 fullscreen；onStatusChanged 在状态变化时派发同样的对象；状态取值为 pending、active、stopped 与 error，查询结果会主动排除后两种。

> [!NOTE]
> **提醒内容**：同一时刻只允许一个捕获请求成功。再次对同一标签页发起捕获会失败，扩展应先用 getCapturedTabs 判断当前是否已有捕获在进行，并据此给用户明确提示，而不是让 getUserMedia 抛出一个语义模糊的错误。

chrome.desktopCapture 的权限为 desktopCapture，捕获对象是整个屏幕、某个窗口或某个标签页，需要在弹出的选择器里由用户指定。

```js
const requestId = chrome.desktopCapture.chooseDesktopMedia(
  ['screen', 'window', 'tab'],
  (streamId, options) => {
    if (!streamId) return;
    startCapture(streamId, options.canRequestAudioTrack);
  },
);
```

chooseDesktopMedia(sources, targetTab?, callback) 的 sources 是来源类型数组，决定选择器里出现哪些分类：screen 表示整个屏幕，window 表示应用窗口，tab 表示浏览器标签页，audio 表示音频，数组顺序决定选择器里的排列顺序。回调的第二个参数自 Chrome 57 起提供，其 canRequestAudioTrack 表示用户在 sources 含 audio 时是否勾选了共享音频；用户取消选择时回调仍会被调用，只是 streamId 为空字符串。需要程序化关闭选择器时，把返回值传给 cancelChooseDesktopMedia。

> [!CAUTION]
> **注意内容**：选择器是系统级界面，必须由用户手势触发，因此桌面捕获只能在扩展页面或弹出窗口这类前台上下文中发起，Service Worker 里没有可承载选择器的界面上下文。桌面捕获出来的是整个屏幕内容，画面里可能包含聊天窗口、邮件与密码管理器，扩展在拿到流之后是否录制、是否落盘、是否外发必须在隐私说明里写清楚。



### documentPictureInPicture 的适用场景与限制

画中画文档 API 用于打开一个始终置顶、可以承载任意 HTML 内容的窗口，它是网页平台能力，扩展页面同样可以使用。

window.documentPictureInPicture.requestWindow(options) 返回 Promise，敲定为画中画窗口的窗口对象；未通过用户手势调用时 Promise 被拒绝。options 中 width 与 height 设定初始尺寸，取值过大或过小时浏览器自行收敛；disallowReturnToOpener 为 true 时隐藏「返回到标签页」按钮，Chrome 124 起可用；preferInitialWindowPlacement 为 true 时新建默认位置与尺寸，Chrome 130 起可用。

```js
async function openPlayerPanel() {
  const panel = document.querySelector('#playerPanel');
  const pipWindow = await documentPictureInPicture.requestWindow({ width: 320, height: 180 });

  for (const sheet of document.styleSheets) {
    const rules = [...sheet.cssRules].map((rule) => rule.cssText).join('');
    const style = pipWindow.document.createElement('style');
    style.textContent = rules;
    pipWindow.document.head.appendChild(style);
  }

  pipWindow.document.body.append(panel);
  pipWindow.addEventListener('pagehide', () => document.querySelector('#panelHost').append(panel));
}
```

样式不会自动继承，必须手动复制且只复制一次；早期规范的 copyStyleSheets 选项已从规范中移除，现行做法就是上面这段遍历样式表的写法。元素被搬进画中画后，要在 pagehide 里搬回原容器，否则打开者页面被关闭时元素会随之消失。

官方文档把画中画窗口描述为类似 window.open 打开的同源空白窗口，并列出四条差异：它浮在其它窗口之上；生命周期不会超过打开它的窗口；不能在画中画窗口里导航；网站无法设置它的位置。由此推出扩展里的两条实践边界：它是扩展页面的同源窗口，能力边界跟着打开它的那个页面走，不能当作新的注入入口或后台载体；一个文档同时只有一个画中画窗口，重复调用会替换而不是叠加。

尺寸调整用 resizeBy 与 resizeTo（Chrome 121 起支持调整），聚焦回打开者用窗口对象的 focus 方法（Chrome 123 起），两者都需要用户手势。另有纯 CSS 的配合方式：用显示模式为 picture-in-picture 的媒体查询编写只在画中画中生效的样式，Chrome 123 起可用。



### 能力选择的判断

三类能力有各自的入口条件。后台任务只需要 DOM 解析、剪贴板、Blob 与音频播放时用 offscreen 文档，按真实原因填写 reasons，用完即关。任务需要页面或屏幕的画面与声音时，先判断是不是只涉及单个标签页：只涉及标签页用 tabCapture，需要屏幕或窗口用 desktopCapture，两者都必须在用户手势中发起。需要把扩展界面从标签页里解放出来、浮在其它窗口之上时用画中画文档，它不引入新权限，也不改变扩展的能力边界。

三者都会延长或绕过 Service Worker 的空闲计时：offscreen 文档发消息会重置计时器，媒体捕获通过活跃流维持运行，画中画窗口的存在也改变页面可见性判断。任何一项被长期持有，都会让扩展回到「后台常驻」的老路，配置面板里应给出明确开关让用户关闭它们。
