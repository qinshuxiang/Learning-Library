## 内容脚本：注入方式与运行环境

### 内容脚本与它的三条入口

内容脚本是扩展注入到网页中运行的 JavaScript 或 CSS，它和页面共享同一棵 DOM，却运行在只属于本扩展的执行环境里。

把内容脚本放进页面有三条入口，取舍取决于触发时机由声明决定还是由代码决定：

- 静态声明：在 manifest.json 的 content_scripts 键里登记，网址匹配即自动注入，不需要扩展其它部分参与。
- 运行时注入：由 Service Worker 或扩展页面在事件回调里调用 chrome.scripting.executeScript 等方法注入，目标标签页与注入时刻全部由代码决定。
- 动态注册：同样由代码发起，但注册结果交由浏览器保存，之后按匹配规则自动注入，形式上介于前两者之间。

三条入口注入的代码能力完全一致，差别在生命周期。页面导航或刷新会销毁已经注入的脚本，静态声明与动态注册的脚本会在下一次匹配时重新注入，运行时注入的脚本必须由扩展再次发起调用。

> [!NOTE]
> **提醒内容**：内容脚本可以直接使用的扩展 API 只有 dom、i18n、storage、runtime 这几组中的少数成员，包括 runtime.connect、runtime.getManifest、runtime.getURL、runtime.id、runtime.onConnect、runtime.onMessage、runtime.sendMessage。其余 API 需要通过消息交给 Service Worker 代为调用。



### 静态声明的字段

静态内容脚本在 manifest.json 里以数组形式声明，每一项描述一批匹配规则与要注入的文件。

```json
{
  "manifest_version": 3,
  "name": "Reader Helper",
  "version": "1.0.0",
  "content_scripts": [
    {
      "matches": ["https://*.example.com/*"],
      "exclude_matches": ["*://*/*admin*"],
      "css": ["styles/reader.css"],
      "js": ["scripts/vendor.js", "scripts/reader.js"],
      "run_at": "document_idle",
      "all_frames": false,
      "world": "ISOLATED"
    }
  ]
}
```

matches 是必填项，值为匹配模式数组。exclude_matches、include_globs、exclude_globs 三个字段只在 matches 的基础上做二次筛选，不能单独使用：include_globs 在 matches 之后只保留同时命中 glob 的网址，exclude_globs 则相反。glob 语法比匹配模式宽松，星号匹配任意长度字符串，问号匹配单个字符。

js 与 css 两个数组内的文件按书写顺序依次注入。css 文件在为页面构建或显示任何 DOM 之前注入，js 文件的注入时刻由 run_at 决定。同一文档生命周期阶段内，清单中静态声明的内容脚本最先注入，排在动态注册与运行时注入之前。



### 隔离世界与页面世界

隔离世界是专属于本扩展的执行环境，网页脚本与其它扩展的内容脚本都无法访问其中的变量与函数。内容脚本默认运行在隔离世界里。

```js
// 页面侧：window.greeting 为 "hello, "，button.personName 为 "Bob"
// 内容脚本侧：两个世界各有一份 greeting，彼此不覆盖
const greeting = "hola, ";
const button = document.getElementById("mybutton");
button.personName = "Roberto";
button.addEventListener("click", () => console.log(greeting + button.personName));
```

两边共享 DOM，因此内容脚本可以读写页面元素、绑定事件；但各自世界里的全局变量、函数与原型修改互不可见。button 上的属性之所以双方都能读到，是因为它挂在 DOM 节点上，而不是挂在某个世界的全局对象上。

把 world 设为 MAIN 可让脚本进入页面自己的执行环境，此时它能看到页面的全局变量，页面也能看到它，代价是 chrome 命名空间下的扩展 API 全部不可用。

```json
{
  "content_scripts": [
    {
      "matches": ["https://*.example.com/*"],
      "js": ["scripts/bridge.js"],
      "world": "MAIN"
    }
  ]
}
```

> [!IMPORTANT]
> **重要内容**：内容脚本不具备扩展的跨源特权。它发起的 fetch 请求按注入页面的来源计算同源策略，与该扩展是否声明了目标站点的主机权限无关。需要访问其它域名的接口时交给 Service Worker 执行，再把结果通过消息回传。



### 注入时机

run_at 有三档取值，控制 js 文件相对于文档生命周期的注入时刻。

- document_start：在 css 中声明的文件注入之后、构建任何其它 DOM 或运行任何其它脚本之前注入。
- document_end：DOM 完成后立即注入，此时图片与框架等子资源尚未加载。
- document_idle：默认值，也是首选值。浏览器在 document_end 与 window.onload 之后立即注入之间自行挑选时机，具体取哪个取决于文档复杂度与加载耗时。

以 document_idle 注入的脚本保证在 DOM 完成后运行，不需要监听 window.onload。确实要等到 onload 之后才执行时，用 document.readyState 判断该事件是否已经触发。

```js
if (document.readyState === "complete") {
  startCollect();
} else {
  window.addEventListener("load", startCollect, { once: true });
}
```

运行时注入默认按 document_idle 的语义排队，页面若已加载完则立即执行。ScriptInjection 的 injectImmediately 字段（Chrome 102 起可用）要求尽快在目标中触发注入，但它并不保证早于页面加载完成，脚本到达目标时页面可能早已就绪。



### 运行时注入的字段

chrome.scripting.executeScript(injection) 接收一个 ScriptInjection 对象，返回 Promise，敲定值是 InjectionResult 数组，数组长度等于成功注入的帧数。

```js
function readPageTitle() {
  return document.title;
}

async function injectIntoActiveTab() {
  const [tab] = await chrome.tabs.query({ active: true, currentWindow: true });
  const results = await chrome.scripting.executeScript({
    target: { tabId: tab.id, allFrames: true },
    func: readPageTitle,
  });
  // 主框架的结果保证在第一个位置，其余帧的顺序不确定
  console.log(results[0].frameId, results[0].result);
}
```

ScriptInjection 的字段分两组。代码来源一组里，files 与 func 必须且只能指定一个，executeScript 不接受字符串形式的代码。目标一组放在 target 里，即 InjectionTarget 对象：

- tabId：唯一必填字段，默认只注入该标签页的主框架。
- allFrames：是否注入所有框架，默认 false。
- frameIds：只注入指定的框架，与 allFrames 不能同时指定。
- documentIds：按文档 ID 指定目标，Chrome 106 起可用，与 frameIds 不能同时指定。

func 注入的函数会先被序列化、再在目标中反序列化，函数体必须自包含，引用函数外部的变量会抛 ReferenceError。需要外部数据时通过 args 传入（Chrome 92 起可用），该数组必须可 JSON 序列化。

```js
function paintBackground(color) {
  document.body.style.backgroundColor = color;
}

function paintTab(tabId, color) {
  return chrome.scripting.executeScript({
    target: { tabId, frameIds: [0] },
    func: paintBackground,
    args: [color],
  });
}
```

InjectionResult 含 frameId（Chrome 90 起）、documentId（Chrome 106 起）与 result 三个字段。注入的函数返回 Promise 时，浏览器会等这个 Promise 敲定再收集结果。



### 帧范围与来源回退

只匹配顶层框架是默认行为。需要覆盖 iframe 时，静态声明改 all_frames，动态注册改 allFrames，运行时注入改 target 里的 allFrames 或 frameIds。每个子框架的网址都要单独通过匹配检查，不匹配的子框架不会注入。

about:blank 以及 data:、blob:、filesystem: 这些方案不在匹配模式的 scheme 白名单里，用匹配模式写不到它们。这类框架靠来源回退处理：静态声明与动态注册用 match_origin_as_fallback，运行时注入用 matchOriginAsFallback（Chrome 119 起可用）。

开启回退后，Chrome 改看框架启动器的来源来判断是否匹配，而不是看框架自身的网址。启动器是创建或导航到该框架的那个框架，通常是父框架，但不保证是。由于比较的是来源而不是完整网址，启用回退的匹配模式必须以通配符结尾的路径书写。

```json
{
  "content_scripts": [
    {
      "matches": ["https://*.example.com/*"],
      "match_origin_as_fallback": true,
      "js": ["scripts/frame-probe.js"]
    }
  ]
}
```

另有一个 match_about_blank 字段专门处理 about:blank 框架，默认 false。两个字段同时声明时，match_origin_as_fallback 优先。



### 动态注册与持久化

动态注册用 chrome.scripting.registerContentScripts(scripts)（Chrome 96 起可用）把内容脚本交给浏览器托管，适合匹配规则要到运行期才能确定的场景。

```js
async function registerSiteHelper() {
  await chrome.scripting.registerContentScripts([
    {
      id: "site-helper",
      matches: ["https://*.example.com/*"],
      excludeMatches: ["*://*/*admin*"],
      js: ["scripts/helper.js"],
      runAt: "document_start",
      persistAcrossSessions: true,
    },
  ]);
}
```

RegisteredContentScript 的 id 不得以半角下划线开头，该前缀留给浏览器生成的脚本 ID；matches 在注册时必填。persistAcrossSessions 默认为 true，设为 false 的注册在浏览器重启后消失。

配套的三个方法是 getRegisteredContentScripts(filter)、updateContentScripts(scripts)、unregisterContentScripts(filter)，均自 Chrome 96 起可用，filter 为 ContentScriptFilter 对象，其 ids 字段可把操作限定在指定 ID 上。注册与更新都是一次性判定：只要有一条脚本解析失败或文件校验不通过，整批都不会写入。



### 样式注入与失效情形

chrome.scripting.insertCSS(injection) 接收 CSSInjection 对象，是唯一接受字符串代码的注入方法，css 与 files 二选一。

```js
async function highlightActiveTab(tabId) {
  await chrome.scripting.insertCSS({
    target: { tabId },
    css: "body { outline: 2px solid #ff6600; }",
    origin: "AUTHOR",
  });
}
```

CSSInjection 的 origin 取 StyleOrigin 枚举，默认 AUTHOR，用于标明注入样式所处的来源层级。删除时要让 css、files、origin 三个字段与插入时完全一致，移除一个从未插入过的样式表是空操作。

> [!CAUTION]
> **注意内容**：取消注册动态内容脚本不会移除已经注入到页面里的脚本与样式，注册表与运行中的脚本是两件独立的事。要让改动立刻生效，需要在取消注册后重新加载受影响的标签页，否则页面里仍在运行旧版本的代码。

注入失败或注入后失效，常见来源有四处：目标标签页的网址属于 chrome://、扩展管理页等受限方案，注入被拒绝；页面已经导航或刷新，上一轮注入的脚本随旧文档一起销毁；目标框架不在匹配范围内，注入被跳过而结果数组里没有对应条目；扩展重载后页面里残留的脚本已与扩展断开，再调用扩展 API 会直接失败。

> [!NOTE]
> **提醒内容**：结果数组的长度只等于成功注入的帧数，不等于目标帧数。逐帧核对 frameId 才能区分「注入失败」与「该帧本就不该注入」，只看数组第一项会掩盖子框架的失败。
