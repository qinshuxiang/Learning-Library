## manifest.json 详解

### 清单文件的定位与必填字段

manifest.json 是扩展的唯一入口描述文件，它以 JSON 声明扩展的名称、版本、用到的能力与全部入口文件，浏览器在加载扩展之前先读这份文件。

平台层面只有三个必填字段，缺任何一个都无法加载：

- manifest_version：清单格式版本，取整数 3，写成字符串 "3" 会被判为类型错误。
- name：扩展名称，最长 75 个字符，展示在扩展管理页、安装对话框与商店页面。
- version：扩展版本号，格式规则见下一节。

面向网上应用店提交时还额外要求 description 与 icons 两个键，本地加载不写也能跑起来。清单是严格 JSON，不允许多余的尾逗号与注释。

> [!NOTE]
> **提醒内容**：清单里出现未知顶层键时 Chrome 忽略该键并告警，而不是拒绝加载。权限名拼错、键名写偏这类错误的直接表现是「功能静默失效」，排查时应先看扩展管理页的错误面板，再核对官方键名表。



### version 字段的格式规则

version 是一到四个以英文句点分隔的整数，用于标识扩展版本并驱动自动更新：

- 每个整数必须介于 0 到 65535 之间，含两端。
- 非零整数不能以 0 开头，032 无效。
- 几个整数不能全为零，0 与 0.0.0.0 无效，0.1.0.0 有效。

因此 "1"、"1.0"、"2.10.2"、"3.1.2.4567" 合法，而 "0"、"0.0.0.0"、"032"、"1.0-beta" 都不合法。版本比较从最左边的整数开始，相等则比下一位，缺位按零处理，于是 1.2.0 比 1.1.9.9999 新，1.1.9.9999 比 1.1 新又低于 1.2。

显示用的版本名另有一个可选键 version_name，它接受任意描述性字符串，例如 1.0 beta 或 build rc2，只影响展示，不参与更新比较；未声明时展示 version 的值。

> [!IMPORTANT]
> **重要内容**：更新判定完全依赖 version，发布后无法回退版本号，商店拒收低于或等于线上版本的更新。上线前就要把主版本、次版本、修订号的含义定下来，避免用 1.0.1 连发十次小改动。



### 名称、描述与图标

description 的长度上限为 132 个字符，商店列表摘要直接取它的前 132 字符；该键与 name 都支持国际化，用占位符引用语言文件中的条目。

icons 是把尺寸映射到相对路径的字典，官方建议覆盖 16、32、48、128 四个尺寸：16 像素用于扩展页面与菜单中的小图标，32 像素用于 Windows 的安装确认对话框，48 像素用于 chrome://extensions 扩展管理页，128 像素用于安装过程与商店列表且必须提供。

```json
{
  "icons": {
    "16": "images/icon-16.png",
    "32": "images/icon-32.png",
    "48": "images/icon-48.png",
    "128": "images/icon-128.png"
  }
}
```

图标应为 PNG，因为它对透明通道支持最好；BMP、GIF、ICO、JPEG 也可用，但不支持 WebP 与 SVG。只提供一个尺寸时可以把 icons 写成单个路径字符串，Chrome 会自行缩放，缩放结果明显模糊。工具栏图标与这里的扩展图标是两套配置，前者写在 action 键的 default_icon 下。



### 权限键的分离

扩展要调用的 API 与要访问的网站是两类不同性质的授权，Manifest V3 把它们拆成两组键，安装告警与审核尺度也随之不同。

#### 主机权限与 API 权限的分工

permissions 放 API 权限名，host_permissions 放网址匹配模式，声明扩展可以读写哪些网站的页面与响应。Manifest V2 把两者混在一个数组里，V3 的拆分让用户能看清扩展究竟要访问哪些站点。

```json
{
  "permissions": ["storage", "tabs", "scripting", "alarms"],
  "host_permissions": ["https://*.example.com/*"],
  "optional_permissions": ["unlimitedStorage", "bookmarks"],
  "optional_host_permissions": ["*://*/*"]
}
```

内容脚本的匹配范围不写在这里，而是写在 content_scripts 各元素的 matches 字段里。tabs 权限只决定标签页对象的网址与图标字段是否可见，不决定能否操作标签页。



#### 可选权限的声明

可选权限先写进 optional_permissions 与 optional_host_permissions，运行时再由用户手势触发 chrome.permissions.request 申请，这样安装时的告警最小，敏感能力留到用户真正用上该功能时再问。

```js
const granted = await chrome.permissions.request({
  permissions: ['bookmarks']
});
console.log('用户是否授权书签权限：', granted);
```

权限模型的设计原则、申请时机与告警影响归第 9 篇《权限模型与最小权限》展开。



### key 与固定扩展 ID

key 字段存放扩展公钥的 Base64 内容，作用是在开发期锁定扩展 ID，让 ID 不随目录路径变化。

未打包扩展的 ID 由目录绝对路径派生，换路径即换 ID；带上 key 后 ID 改由公钥派生，装在哪台机器都一致。做法是在开发者信息中心上传一次 zip（不必发布），在软件包页面点「查看公钥」，把公钥去掉换行后写入 key 字段。

固定的 ID 是若干能力的前提：externally_connectable 按 ID 放行，web_accessible_resources 的 extension_ids 按 ID 授权，共享模块靠 key 保证 ID 正确，服务端白名单与 OAuth 来源登记也都认 ID。



### 后台与界面键

这一类键声明扩展的可执行入口与界面载体，写法在 Manifest V3 中已完全定型。

```json
{
  "background": { "service_worker": "service-worker.js", "type": "module" },
  "action": {
    "default_icon": { "16": "images/icon-16.png", "32": "images/icon-32.png" },
    "default_title": "打开面板",
    "default_popup": "popup.html"
  },
  "side_panel": { "default_path": "sidepanel.html" },
  "options_ui": { "page": "options.html", "open_in_tab": false }
}
```

- background：只接受 service_worker 一个脚本入口。加 type 设为 module 后可用 import 语句拆分模块，但不支持动态 import。
- action：定义工具栏图标、悬停标题与弹出窗口，取代了 MV2 的 browser_action 与 page_action。
- side_panel：用 default_path 指定侧边栏页面，另需 sidePanel 权限，Chrome 114 起可用。
- options_page 与 options_ui：两套写法二选一。options_page 直接给路径并整页打开；options_ui 用 page 给路径，再用 open_in_tab 决定整页打开还是嵌入扩展管理页。

界面各形态的语义、参数与选择判据归第 5 篇《扩展的界面形态》。



### 脚本与资源键

这一类键决定哪些代码进入网页、哪些文件对外暴露。

```json
{
  "content_scripts": [
    {
      "matches": ["https://*.example.com/*"],
      "exclude_matches": ["*://*/*business*"],
      "js": ["content.js"],
      "css": ["content.css"],
      "run_at": "document_idle",
      "all_frames": false,
      "world": "ISOLATED",
      "match_origin_as_fallback": false
    }
  ],
  "web_accessible_resources": [
    { "resources": ["images/*"], "matches": ["https://example.com/*"], "use_dynamic_url": true }
  ]
}
```

content_scripts 是数组，每项只有 matches 必填，并且必须同时给出 js 或 css 之一；run_at 默认 document_idle，world 默认 ISOLATED。

web_accessible_resources 在 MV3 改为对象数组，每项必须带 resources 以及 matches 与 extension_ids 之一，只有匹配的站点或指定 ID 的扩展能取到该资源。默认全部资源都不可从网页访问，暴露资源会扩大指纹识别面，非必要不声明。

> [!CAUTION]
> **注意内容**：把脚本或模板放进 web_accessible_resources 等于允许匹配站点探测到本扩展已安装。若只是为了在内容脚本里引用自己的图片或样式文件，用 runtime.getURL 拼接扩展来源地址即可，不必对外开放。



### 能力与策略键

余下的键按用途可归为四组：声明式网络规则、交互入口、安全边界与依赖关系。

```json
{
  "declarative_net_request": {
    "rule_resources": [
      { "id": "ruleset_1", "enabled": true, "path": "rules_1.json" },
      { "id": "ruleset_2", "enabled": false, "path": "rules_2.json" }
    ]
  },
  "commands": {
    "run-scan": {
      "suggested_key": { "default": "Ctrl+Shift+Y", "mac": "Command+Shift+Y" },
      "description": "扫描当前页面"
    },
    "_execute_action": { "suggested_key": { "default": "Ctrl+Shift+U" } }
  },
  "omnibox": { "keyword": "scan" },
  "sandbox": { "pages": ["sandbox.html"] },
  "externally_connectable": {
    "ids": ["aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"],
    "matches": ["https://*.example.com/*"]
  },
  "incognito": "split",
  "storage": { "managed_schema": "schema.json" },
  "import": [
    { "id": "cccccccccccccccccccccccccccccccc", "minimum_version": "0.5" }
  ]
}
```

- declarative_net_request：rule_resources 每项含 id、enabled、path 三个字段。静态规则集最多声明 100 个、同时最多启用 50 个，完整配额见第 10 篇《网络请求与请求拦截》。
- commands：suggested_key 可写成字符串，或按 default、windows、mac、chromeos、linux 分平台写成对象；_execute_action 等保留命令直接绑定工具栏图标，不触发 onCommand。最多指定四个建议快捷键。
- omnibox：keyword 是地址栏关键字，一个扩展只能有一个，用户可在地址栏管理中修改。
- sandbox：把列出的页面放进独立来源，它们可以用 eval 与远程脚本，但拿不到扩展 API，只能靠消息通信；对应 CSP 写在 content_security_policy 的 sandbox 字段。
- externally_connectable：ids 与 matches 决定谁能连进来。未声明该键时所有扩展可连、任何网页不可连，因此写了它却没写 ids 通配，其他扩展会立刻连不上。
- incognito：取 spanning、split 或 not_allowed，默认 spanning；需要在无痕窗口里加载扩展页面时用 split。storage.managed_schema 指向企业策略的 JSON 架构文件，架构校验不通过时扩展不会被加载。
- import 与 export：共享模块的依赖声明，import 支持 id 与可选的 minimum_version，资源经保留路径访问。MV2 时代的 dependencies 键不再是 MV3 的写法。

> [!WARNING]
> **警告内容**：userScripts 能力不靠顶层键开启，而是声明 userScripts 权限并配 host_permissions，Chrome 120 起可用；用户还必须在扩展详情页打开「允许用户脚本」开关（Chrome 138 之前是开发者模式开关），否则 chrome.userScripts 为未定义。offscreen 同理只是权限，离屏文档由 chrome.offscreen.createDocument 在运行时创建，没有对应的清单顶层键。



### 清单校验与常见报错

清单在加载时一次性校验，报错挂在扩展管理页的「错误」按钮下。按现象分类，常见问题集中在四类：

- 加载直接失败，提示「清单文件缺失或不可读」：JSON 语法错误，多为多余的尾逗号或注释。
- 提示版本号无效：version 出现前导零、超过四段、含非数字字符，或几个整数全为零。
- 功能静默不生效：权限名拼错、键名大小写写错，或被忽略的未知键，对照官方键名表逐个核对。
- 提示匹配模式无效：scheme 只允许 http、https、星号与 file；用通配符时它必须是主机名第一个字符且后面紧跟句点或斜杠；不支持顶级域名匹配模式，应写 http://google.es/* 而不是 http://*.es/*；file:///* 需三个斜杠，并要用户手动授予文件访问权限。

minimum_chrome_version 接受现有 Chrome 版本字符串的子串，例如 126 或 126.0.6478.0。低于该版本的用户在商店里看到「不兼容」而无法安装；已安装的低版本用户会静默停止接收更新，因此提高这个值时需要另行通知存量用户。
