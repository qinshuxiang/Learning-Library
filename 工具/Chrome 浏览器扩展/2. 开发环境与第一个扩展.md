## 开发环境与第一个扩展

### 环境要求与版本基线

扩展开发不需要编译器、脚手架或额外运行时，只需要一份 Chrome 稳定版与一个能编辑文本的编辑器，浏览器本身就是开发环境与运行环境。

基线版本取本机稳定版 153.0.8010.36，在地址栏输入 chrome://version 可以核对：

```text
Google Chrome	153.0.8010.36 (正式版本)
```

版本决定可用 API 的下限：Manifest V3 自 Chrome 88 起支持，chrome.scripting 自 88 起，chrome.storage.session 自 102 起，chrome.sidePanel 自 114 起，chrome.userScripts 自 120 起。用到某个 API 时，清单里的 minimum_chrome_version 应写成所需的那个主版本号。

> [!TIP]
> **建议内容**：开发期同时保留一个 Beta 或 Dev 通道的 Chrome 用来提前验证新 API，日常加载扩展仍走稳定版。发布前把 minimum_chrome_version 对齐实际用到的最高版本要求，避免用户在低版本上装完才发现功能不可用。



### 开发者模式与加载已解压的扩展

开发者模式是未打包扩展的入口开关，打开后扩展管理页才出现加载与打包按钮。

加载步骤固定三步：

1. 地址栏输入 chrome://extensions 进入扩展管理页。
2. 打开右上角的开发者模式开关。
3. 点击「加载已解压的扩展程序」，选中扩展目录。

加载成功后，如果清单里没有声明图标，Chrome 会给一个通用拼图图标。扩展默认出现在拼图菜单里，点菜单里的图钉可以把图标固定到工具栏，方便开发期随时点击。

目录选择框只接受目录而不是单个文件，因此 manifest.json 必须位于所选目录的根部；选到子目录会报「清单文件缺失或不可读」。



### 最小可运行扩展的文件构成

三个文件即可跑通一次完整交互：清单声明入口，弹出窗口提供界面，后台脚本处理事件。

```text
hello-extension/
  manifest.json
  service-worker.js
  popup.html
```

清单声明名称、版本、后台脚本与弹出窗口：

```json
{
  "manifest_version": 3,
  "name": "Hello Extension",
  "description": "第一个可运行的扩展",
  "version": "1.0.0",
  "background": { "service_worker": "service-worker.js" },
  "action": {
    "default_title": "点击查看弹出窗口",
    "default_popup": "popup.html"
  },
  "permissions": ["storage"]
}
```

后台脚本在顶层同步注册监听器，保证 Service Worker 被唤醒时能找到它：

```js
chrome.runtime.onInstalled.addListener((details) => {
  console.log('安装或更新事件，原因：', details.reason);
});

chrome.runtime.onStartup.addListener(() => {
  console.log('个人资料启动');
});
```

弹出窗口是一份普通 HTML，脚本通过脚本标签引入，扩展页面禁止内联脚本：

```html
<!DOCTYPE html>
<html lang="zh-CN">
  <head>
    <meta charset="utf-8" />
    <title>Hello Extension</title>
  </head>
  <body>
    <h1>Hello Extensions</h1>
    <button id="mark">记录一次点击</button>
    <p id="status"></p>
    <script src="popup.js"></script>
  </body>
</html>
```

```js
const status = document.getElementById('status');

const markClicked = async () => {
  const { clickCount = 0 } = await chrome.storage.local.get('clickCount');
  const next = clickCount + 1;
  await chrome.storage.local.set({ clickCount: next });
  status.textContent = `已记录 ${next} 次点击`;
};

document.getElementById('mark').addEventListener('click', markClicked);
```

> [!CAUTION]
> **注意内容**：扩展页面的默认内容安全策略禁止 eval 与远程脚本，写在 HTML 里的内联脚本标签会直接被执行策略拦下，控制台只报拒绝执行的错误。所有脚本必须以独立文件形式通过脚本标签引入。



### 重载、错误面板与日志入口

改完代码要让浏览器重新读取，需要按改动位置决定重载范围：

- 清单、Service Worker、内容脚本改动后必须点扩展管理页的刷新按钮重载扩展。
- 弹出窗口、选项页面、其他扩展页面改动后无需重载，重新打开即可生效。
- 重载扩展会终止当前 Service Worker，全局变量随之丢失，调试中的临时状态不要放在全局变量里。

日志分三处看：

- 弹出窗口与选项页面的控制台：在页面上右键选择「检查」，打开的是该页面的 DevTools。
- Service Worker 的控制台：在扩展管理页点该扩展的「检查视图」链接，这个窗口同时就是该 Worker 的 DevTools。
- 清单与运行期错误：扩展管理页上出现「错误」按钮时点击它，逐条列出文件名、行号与原因。

代码出现语法错误后，扩展仍会加载，但最近一次 Service Worker 注册会失败，此时若没有错误按钮就说明错误发生在页面脚本而不是后台脚本。



### 扩展 ID 的派生规则

扩展 ID 是一串 32 位小写字母，它决定了扩展来源的地址，取值方式分两种情况。

未打包扩展的 ID 由目录的绝对路径派生。目录改名、换目录、换机器都会得到不同的 ID，因此开发期写死的 ID 相关配置随时可能失效。

已打包且清单中包含 key 字段的扩展，ID 由该公钥派生，与安装位置无关，始终固定。发行渠道分发的扩展天然带公钥，ID 在首次上传后就不再变化。两种情况下，扩展资源都用 chrome-extension 协议、扩展 ID 与资源相对路径拼接成完整地址取用。



### 固定扩展 ID 的意义与做法

固定 ID 不是洁癖，而是若干功能的硬前提：externally_connectable 要按 ID 放行其他扩展，web_accessible_resources 的 extension_ids 要按 ID 授权，服务端要把扩展来源加进白名单，OAuth 客户端要登记来源，本地存储与调试脚本也常按 ID 定位。

做法有两条，任选其一：

- 在开发者信息中心上传一次 zip 但不要发布，进入软件包页面点「查看公钥」，把公钥内容去掉换行后写入清单的 key 字段。
- 命令行打包时加 --pack-extension，同时产出一个 PEM 私钥文件，把私钥转成公钥后写入 key 字段。

```bash
chrome --pack-extension=/abs/path/hello-extension
```

执行后在同级目录得到 hello-extension.crx 与 hello-extension.pem 两个文件，PEM 需要自行保管，泄露等于任何人都能签发同 ID 的扩展。

> [!IMPORTANT]
> **重要内容**：开发者信息中心里的商品 ID 就是扩展 ID，它由首次上传时提交的公钥决定且不可更改。若本地加载后的 ID 与信息中心的 ID 不一致，说明清单里的 key 与已提交的公钥不匹配，必须先改正再提审，否则更新会被拒收。



### 命令行加载与自动化场景

手工点按钮适合调试，脚本化加载适合自动化测试与批量验证，靠两个启动参数完成：

```bash
chrome --load-extension=/abs/path/hello-extension \
       --disable-extensions-except=/abs/path/hello-extension \
       --user-data-dir=/tmp/chrome-ext-profile
```

三个参数各司其职：--load-extension 加载指定目录；--disable-extensions-except 把该目录以外的扩展全部停用，避免环境互相干扰；--user-data-dir 指定独立的个人资料目录，让测试不污染日常配置。

无头模式同样能加载扩展，Chrome 使用 --headless=new 时扩展会被正常注册，旧的 --headless 模式不支持扩展。Puppeteer 与 Playwright 都支持在这两种有头与无头形态下加载扩展并驱动页面。

> [!NOTE]
> **提醒内容**：命令行加载的扩展其 ID 仍由目录绝对路径派生，换路径即换 ID。若测试用例依赖固定 ID，应在清单里写死 key 字段，而不是在测试脚本里硬编码从路径算出来的 ID。



### 在弹出窗口里调用第一个扩展 API

第一个值得跑的 API 是 chrome.storage，它用于在扩展各处之间共享状态，并能跨浏览器重启保留。

Chrome 122 起异步扩展 API 普遍支持 Promise，本系列示例统一用 await 写法：

```js
// 写入：set 接受一个键值对象
await chrome.storage.local.set({ theme: 'dark', fontSize: 14 });

// 读取：get 接受键名、键名数组，或带默认值的对象
const { theme, fontSize } = await chrome.storage.local.get({
  theme: 'light',
  fontSize: 12
});

console.log(theme, fontSize);
```

需要注意的签名细节有三条：get 传入对象时对象既是要读的键也是默认值；set 只做浅合并，不会删除未提及的键；超出配额会立刻失败并拒绝 Promise，而不是静默截断。存储区域的划分与精确配额见第 8 篇《数据存储：chrome.storage》。

以下代码把弹出窗口的点击次数落到 storage，并由后台脚本读回写入徽章：

```js
// popup.js
document.getElementById('mark').addEventListener('click', async () => {
  const { clickCount = 0 } = await chrome.storage.local.get('clickCount');
  await chrome.storage.local.set({ clickCount: clickCount + 1 });
});

// service-worker.js
chrome.storage.onChanged.addListener(async (changes, areaName) => {
  if (areaName !== 'local' || !changes.clickCount) return;
  await chrome.action.setBadgeText({ text: String(changes.clickCount.newValue) });
});
```

chrome.action.setBadgeText 接收一个含 text 属性与可选 tabId 的对象，省略 tabId 时设置的是全局徽章。工具栏图标的其余能力见第 5 篇《扩展的界面形态》。
