## Unicode 与中文处理

### Unicode 属性转义

#### 属性转义的含义与常用属性

**Unicode 属性转义 \p{...}**：按 Unicode 标准的**属性**匹配字符，必须配合 u 或 v 修饰符使用。它回答的问题不是“这是哪个字符”，而是“这个字符属于哪一类”。

- **\p{Letter}**：任意语言的字母（拉丁字母、希腊字母、西里尔字母，**汉字也在其中**）。
- **\p{Number}**：任意数字类字符（半角与全角数字、罗马数字、分数符号）。
- **\p{Script=Han}**：汉字（含扩展 A 至扩展 I 区的生僻字）。
- **\p{White_Space}**：任意空白字符。
- **\p{P}（Punctuation）**：任意标点符号。
- **\p{Emoji}**：emoji 集合。
- **\p{Uppercase} / \p{Lowercase}**：大写字母、小写字母。
- 大写 **\P** 开头为对应属性的**取反**，如 \P{Letter} 表示非字母。

```js
console.log(/\p{Letter}/u.test("Ünikode"));  // true（带变音符的字母也是字母）
console.log(/\p{Number}/u.test("２"));        // true（全角数字属于 Number）
console.log(/\p{Number}/u.test("½"));         // true（分数符号也属于 Number）
console.log(/\p{White_Space}/u.test("\u3000")); // true（全角空格）
console.log(/\p{P}/u.test("，"));             // true（中文逗号是标点）
console.log(/\P{Letter}/u.test("，"));        // true（取反：不是字母）
```

> 属性转义是按**语言学的分类**匹配，比手写字符区间更准也更全。唯一的成本是必须加 u 标志，且在非常老的运行环境中不可用。



#### Script 与 General_Category 两类属性

**属性转义有两类用法**：\p{属性名} 直接写**通用类别**（Letter、Number、P 等），\p{Script=文字名} 按书写系统查询。

- **通用类别（General_Category）**：回答“这是什么性质的字符”。一级类别有 L（字母）、N（数字）、P（标点）、S（符号）、Z（分隔符）、M（标记）、C（其他）。
- **通用类别的二级细分**：L 下含 Lu（大写）、Ll（小写）、Lt（词首大写）、Lm（修饰字母）、Lo（其他字母）；N 下含 Nd（十进制数字）、Nl（字母数字）、No（其他数字）。
- **书写系统（Script）**：回答“它属于哪种文字”。Han（汉字）、Latn（拉丁）、Greek（希腊）、Arab（阿拉伯）等。
- **Script_Extensions（别名 scx）**：某些字符归属多个文字系统，用 Script 查不到时改用 scx。

```js
console.log(/\p{Lu}/u.test("A"));            // true（Lu：大写字母，通用类别缩写）
console.log(/\p{Script=Han}/u.test("张"));    // true（汉字）
console.log(/\p{Script=Latn}/u.test("A"));    // true（拉丁字母）
console.log(/\p{Letter}/u.test("中"));        // true（汉字属于字母，不是符号）
console.log(/\p{Script=Common}/u.test("ー")); // true（长音符标在通用区）
console.log(/\p{scx=Hira}/u.test("ー"));      // true（但它的扩展归属含平假名）
```

> Script 属性比字符区间**语义化**得多：[\u4e00-\u9fa5] 是“记位置”，\p{Script=Han} 是“说规则”。维护别人代码时，属性写法不需要注释也能看懂意图。



#### 中文数字不是数字：类别归属的易错点

**“数字”在 Unicode 里是个语言学概念，不是“看起来像数字”**：中文数字一二三属于**字母**，只有〇、〡、Ⅰ 这类才归入数字类。按字形直觉写校验，是中文数据校验里最常见的坑。

- **一二三四五六七八九十百千万：属于 Lo（其他字母）**，用 \p{Number} 一个都匹配不上。
- **〇（U+3007）：属于 Nl（字母数字）**，是全套中文数字里唯一算“数字”的一个。
- **〡〢〣（U+3021 起）：属于 Nl**，苏州码子一类的记数符号。
- **Ⅰ Ⅱ Ⅲ（U+2160 起）：属于 Nl**，罗马数字。
- **½ ⅓（U+00BC 起）：属于 No（其他数字）**，分数符号。
- **１（全角）与 1（半角）：都属于 Nd**，十进制数字。

```js
// 中文数字是字母，不是数字
console.log(/\p{Number}/u.test("三")); // false！三 的类别是 Lo
console.log(/\p{Letter}/u.test("三")); // true
console.log(/^\p{Number}+$/u.test("一二三")); // false（一个都不匹配）
console.log(/^\p{Letter}+$/u.test("一二三")); // true

// 只有 〇 这一类记数符号才算数字
console.log(/\p{Number}/u.test("〇")); // true
console.log(/\p{Nl}/u.test("〇"), /\p{Nl}/u.test("Ⅰ"), /\p{Nl}/u.test("〡")); // true true true
console.log(/\p{No}/u.test("½")); // true

// 全角与半角数字都属于 Nd
console.log(/\p{Nd}/u.test("１"), /\p{Nd}/u.test("1"), /\p{Nd}/u.test("٣")); // true true true
```

> [!IMPORTANT]
> **重要内容**：**做金额、数量类校验时不要用 \p{Number} 去“兼容中文数字”**——它根本匹配不到一二三。真要允许中文数字，正确做法是显式列出 [一二三四五六七八九十百千万零〇两]；反过来，识别全角数字、阿拉伯-印度数字这类**真的数字字符**，才该用 \p{Nd}。



#### 属性名的简写与别名

**同一个属性有多套写法**，简写、通用类别名、别名三者在规范里等价，选择哪套只影响可读性。

- **通用类别一级简写**：\p{L}、\p{N}、\p{P}、\p{S}、\p{Z}、\p{M}、\p{C}。
- **通用类别二级简写**：\p{Lu}、\p{Ll}、\p{Lo}、\p{Nd}、\p{Nl}、\p{No}。
- **等号写法**：\p{gc=L}、\p{General_Category=Letter}、\p{General_Category=L} 三者等价。
- **二元属性不带值**：\p{Uppercase}、\p{Lowercase}、\p{Diacritic}、\p{Emoji}、\p{Variation_Selector} 直接写属性名，不能用等号形式。
- **Script 与 scx 都可简写**：\p{Script=Han} 与 \p{sc=Han} 等价，\p{Script_Extensions=Han} 与 \p{scx=Han} 等价。

```js
console.log(/\p{L}/u.test("中"), /\p{gc=Lo}/u.test("中"), /\p{General_Category=Lo}/u.test("中"));
// true true true

console.log(/\p{Letter}/u.test("Ａ"));        // true（全角字母也是字母）
console.log(/\p{Uppercase}/u.test("A"));      // true（二元属性，不带等号）
console.log(/\p{Variation_Selector}/u.test("\uFE0F")); // true（变体选择符）
console.log(/\p{sc=Han}/u.test("汉"), /\p{scx=Han}/u.test("〆")); // true true
```

> [!NOTE]
> **提醒内容**：二元属性与通用类别**不能混用等号形式**：写 \p{Uppercase=true} 会直接报错，写 \p{gc=Uppercase} 同样报错。区分方法是记一条——**能拆成“XX_YY = 值”的用等号，其余直接写名字**。



### 汉字匹配

#### 两种写法的覆盖范围

**汉字匹配**有两种主流写法：固定区间 [\u4e00-\u9fa5] 与属性写法 /\p{Script=Han}/u，二者覆盖范围不同。

- **[\u4e00-\u9fa5]**：只覆盖**基本区**已分配的 20902 个汉字，兼容性最好，写法最短。
- **[\u4e00-\u9fff]**：覆盖整个基本区**码位块**（20992 个码位），比 9fa5 多出未分配的空位，效果与 9fa5 基本一致。
- **/\p{Script=Han}/u**：覆盖基本区与**全部扩展区**，包含 㐀、䶮、𠮷 这类生僻字与兼容区汉字。

```js
const rare = "𠮷"; // U+20BB7，扩展 B 区汉字，姓名与地名系统中真实存在

console.log(/^[\u4e00-\u9fa5]+$/.test(rare));   // false（扩展区不在基本区内）
console.log(/^\p{Script=Han}+$/u.test(rare));   // true（属性写法覆盖扩展区）
console.log(/^[\u4e00-\u9fa5]+$/.test("临县")); // true（常用字两种写法都行）
console.log(/^\p{Script=Han}+$/u.test("㐀䶮豈")); // true（扩展 A 区与兼容区都算）
```

> [!IMPORTANT]
> **重要内容**：处理**姓名、户籍地址**这类可能含生僻字的数据时，一律用 /\p{Script=Han}/u 而不是 [\u4e00-\u9fa5]。扩展区汉字在用户输入中真实存在（如 𠮷、䶮、頔），用基本区校验会把合法姓名误判为非法——这类误判在政务与警务系统中属于典型缺陷。



#### 汉字码位的分布

**汉字并非集中在一块连续区间**，而是散落在基本区、扩展区与兼容区三处，记位置不如记规则。

- **基本区（CJK Unified Ideographs）**：U+4E00 到 U+9FFF，已分配 20902 个，是日常用字的全部来源。
- **扩展 A 区**：U+3400 到 U+4DBF，位于基本区**之前**，收录较古老的汉字，如 㐀。
- **扩展 B 区及以后**：U+20000 起，全部位于**基本多文种平面之外**，必须用码点转义 \u{...} 加 u 标志才能表示。
- **兼容区（CJK Compatibility Ideographs）**：U+F900 到 U+FAFF，收录因编码历史原因重复的汉字，如 豈。
- **判定结论**：[\u4e00-\u9fa5] 只覆盖了第一条，其余三处全部漏掉。

```js
// 扩展 A 区在基本区之前，字符类顺序要注意
console.log(/^[\u3400-\u4dbf]$/.test("㐀")); // true（扩展 A 区）
console.log(/^\p{Script=Han}$/u.test("㐀")); // true（属性写法一并覆盖）

// 扩展 B 区超出 BMP，只有 \u{n} 加 u 能写
console.log(/^\u{20BB7}$/u.test("𠮷"));      // true
console.log(/^[\u4e00-\u9fff]$/u.test("𠮷")); // false（一个码点装不下）

// 兼容区汉字
console.log(/^\p{Script=Han}$/u.test("豈")); // true
console.log(/^[\u4e00-\u9fa5]$/.test("豈")); // true（兼容区里也有落在基本区间内的字）
```

> [!TIP]
> **建议内容**：需要写区间时，**区间只用于性能极敏感的短模式**；其余场合一律用 \p{Script=Han}。真要写区间又怕漏字，用扩展 A 区加基本区的合并区间 [\u3400-\u4dbf\u4e00-\u9fff]，能多覆盖一批古字，但扩展 B 区仍然漏掉——这正是属性写法的价值所在。



#### 中文姓名校验

中文姓名的校验要点是**汉字范围**与**少数民族姓名的间隔号**。

```js
const chineseNameReg = /^[\p{Script=Han}·]{2,16}$/u;

console.log(chineseNameReg.test("张三"));           // true
console.log(chineseNameReg.test("司马相如"));        // true（复姓同样是汉字）
console.log(chineseNameReg.test("阿依古丽·买买提")); // true（含间隔号）
console.log(chineseNameReg.test("𠮷水"));           // true（扩展区生僻字）
console.log(chineseNameReg.test("张 三"));          // false（含空格）
console.log(chineseNameReg.test("Zhang3"));        // false（非汉字）
```

> 拆解：\p{Script=Han} 覆盖基本区与扩展区的全部汉字，· 是间隔号（U+00B7），{2,16} 给出姓名长度的常见上限。用 [\u4e00-\u9fa5] 会把 𠮷、䶮 这类扩展区汉字误判为非法，姓名类校验不要用它。

> [!CAUTION]
> **注意内容**：姓名类字段**不要做过度校验**。复姓、少数民族译名的间隔号有 **U+00B7（·）与 U+30FB（・）两种**，部分录入还会用 U+2027（‧）；姓名中允许的字符在不同民族、不同地区差异很大。**稳妥的边界是“字符集从宽、长度从严”**：只拦掉明显不合法的字符（英文字母、数字、符号），长度与必填交给业务规则。



### 变音符与规范等价

#### 同一个字符的两种编码

**规范等价（canonical equivalence）**：Unicode 允许“看起来相同、语义相同”的字符有两种编码——**预组合字符**（单个码点，如 é 即 U+00E9）与**分解序列**（多个码点，如 e 加组合变音符 U+0301）。两者的 length 一个是 4、一个是 5，正则按码点逐个比对，默认把它们当成**不同的字符串**。

```js
const precomposed = "café";      // 尖音符号是预组合的 U+00E9
const decomposed = "cafe\u0301"; // e 加组合变音符 U+0301

console.log(precomposed === decomposed); // false！人眼看起来完全一样
console.log(precomposed.length);         // 4
console.log(decomposed.length);          // 5

console.log(/^café$/.test(decomposed));  // false（正则不做规范等价归一）

// 先规范化再比对，两种编码归一为同一形式
console.log(precomposed.normalize("NFC") === decomposed.normalize("NFC")); // true
console.log(/^café$/.test(decomposed.normalize("NFC"))); // true
```

> [!WARNING]
> **警告内容**：用户输入带变音的文本（外文姓名、外文地址）时，键盘与输入法产出的编码形式**不受程序控制**。凡是“把输入与预设值比对”的逻辑，两边都要先过 normalize("NFC") 再比，否则会出现肉眼看起来一样、程序判定不同的幽灵故障。



#### 剥离变音符与检索归一

**剥离变音符的标准流程**：先 normalize("NFD") 把预组合字符分解成“基础字母 + 组合变音符”，再用 \p{Diacritic} 属性把变音符批量删掉，用于把 Renée 归一为 Renee 这类检索场景。

```js
function stripDiacritics(text) {
  return text.normalize("NFD").replace(/\p{Diacritic}/gu, "");
}

console.log(stripDiacritics("Renée"));   // "Renee"
console.log(stripDiacritics("Ångström")); // "Angstrom"

// 归一化检索：输入带不带变音符都能命中
function fuzzyMatch(source, query) {
  return stripDiacritics(source).toLowerCase().includes(stripDiacritics(query).toLowerCase());
}

console.log(fuzzyMatch("Renée Dubois", "renee")); // true
```

> 两点边界：**汉字不受影响**——汉字没有组合变音符，normalize 对它原样返回；**剥离是有损操作**——结果只能用于检索与比对，不能存回原始字段。需要按字母排序时，直接用 localeCompare 比手剥变音符更可靠。



### 中英文混合文本

#### 匹配中文标点

**中文标点**集中在两个区间：CJK 符号标点区 \u3000-\u303F 与全角标点区 \uFF00-\uFFEF，属性写法可用 \p{P} 通吃。

```js
// 判断一句话是否以中文句号、叹号等结尾
console.log(/[\u3002\uff01\uff1f\uff1b\uff0c]$/.test("案件已办结。")); // true

// 用属性写法覆盖全部标点
console.log(/\p{P}$/u.test("案件已办结。")); // true
console.log(/\p{P}$/u.test("案件已办结"));   // false
```

> 区间写法精准但要背区间，属性写法全面但较宽（英文逗号也算 P）。表单校验“必须以中文句号结尾”这类明确需求用区间写法更严。

```js
// 常用中文标点的区间速查：用属性一次性验证
const sample = "。，、；：？！「」『』（）《》〈〉【】—…·";
console.log([...sample].every((char) => /\p{P}/u.test(char))); // true

// 全角标点与半角标点的区分：用区间精确锁定全角区
console.log(/^[\uff00-\uffef]$/u.test("，")); // true（全角逗号在 FF00-FFEF）
console.log(/^[\uff00-\uffef]$/u.test(","));  // false（半角逗号不在该区间）
```



#### 中英混合的提取与校验

**\w 不含中文**，中英混合文本的一切操作都要显式处理中文部分，区间或属性转义二选一。

```js
// 把中文文本里的英文单词抠出来
console.log("办理 WPS 培训与 PPT 制作".match(/[A-Za-z]+/g)); // ["WPS", "PPT"]

// 把连续的中文片段抠出来
console.log("案件编号 A2024-017 已受理".match(/[\p{Script=Han}]+/gu));
// ["案件编号", "已受理"]

// 判断字符串是否含有空白字符（含全角空格）
console.log(/\s/.test("姓名　张三")); // true（全角空格也属于 \s）

// 中英混合标识符：字母开头，允许字母数字与中文
const mixedIdReg = /^[A-Za-z][A-Za-z0-9\p{Script=Han}]*$/u;
console.log(mixedIdReg.test("A案件1")); // true
console.log(mixedIdReg.test("案件A1")); // false（汉字不能作首字符）
console.log(mixedIdReg.test("1案件"));  // false（数字开头）
```

> [!NOTE]
> **提醒内容**：\s 在 JavaScript 中**包含全角空格 \u3000**，因此 “姓名　张三” 这类带全角空格的输入用 trim() 与 /^\s+/ 都能处理到；但 \w 完全不含中文，中英混合的“单词”概念必须用 [\p{Script=Han}A-Za-z0-9_] 这类自定义类手工拼装。



### emoji 与组合字符序列

#### 一个“字符”可能是多个码点

**组合字符序列**：一个“用户眼中的字符”可能由**多个码点**组成——变音符、旗帜 emoji、肤色修饰符都是拼接出来的。正则处理它们要用 u 修饰符加属性转义。

```js
// 🇨🇳 由两个区域指示符码点组成
console.log("🇨🇳".length); // 4
console.log(/^\p{Regional_Indicator}{2}$/u.test("🇨🇳")); // true

// 👍🏻 是 👍（U+1F44D）加肤色修饰符（U+1F3FB）
console.log(/^\p{Extended_Pictographic}\u{1F3FB}?$/u.test("👍🏻")); // true

// 按码点切分字符串（把字符串看成码点序列）
console.log([..."🇨🇳 ab"].length); // 5（普通 split 会切坏代理对）
```

> [!CAUTION]
> **注意内容**：永远不要用 length 或 split("") 判断 emoji 字符串——它们按**码元**计数，会把 emoji 切成半个。国际码点展开 [...]、/u 或 /v 修饰符、\p{RGI_Emoji}/v（ES2024，按“推荐 emoji 序列”整字匹配）才是按“完整字符”处理的一组工具。



#### 输入长度限制与 emoji

**长度限制遇上 emoji 会出现“名义长度”与“用户感知长度”的分裂**：一个 emoji 可能占 4 个码元，按 length 限 20 字时用户贴几个 emoji 就被拒，体验与安全两头不讨好。

```js
const input = "👍🏻👍🏻"; // 用户眼中 2 个字符

console.log(input.length);          // 8（码元数）
console.log([...input].length);     // 4（码点数）
console.log(new Intl.Segmenter().segment(input)); // 迭代器，按“用户感知字符”切

// 按用户感知长度计数（国际化场景的推荐做法）
function graphemeLength(text) {
  return [...new Intl.Segmenter().segment(text)].length;
}
console.log(graphemeLength("👍🏻👍🏻")); // 2
```

> [!IMPORTANT]
> **重要内容**：校验“昵称不超过 N 个字符”这类需求时，先想清楚按**码元、码点还是用户感知字符**计数，并把口径写进需求文档。同一份输入三种口径的数值可以差一倍，口径不一致是国际化表单的经典纠纷来源。

```js
// 三种口径的完整对照
const text = "a👍🏻中";
console.log(text.length);              // 6（码元：字母与汉字各占 1，两个非 BMP 码点各占 2）
console.log([...text].length);         // 4（码点）
console.log([...new Intl.Segmenter().segment(text)].length); // 3（用户感知字符）

// 变体选择符同样会拉长码点计数
console.log("\u2764\uFE0F".length);     // 2（心形符号加变体选择符 FE0F）
console.log(/\p{Variation_Selector}/u.test("\uFE0F")); // true
```
