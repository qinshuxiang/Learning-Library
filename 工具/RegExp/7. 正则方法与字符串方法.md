## 正则方法与字符串方法

### 正则对象的方法

#### test() 方法

**regExp.test(string)**：测试字符串**是否包含**匹配项，返回布尔值，是验证场景的首选。

```js
const reg = /hello/i;
console.log(reg.test("Hello World")); // true
console.log(reg.test("world"));       // false
```

> test 的语义是“**包含**”而非“等于”：/\d{11}/.test("a13800138000b") 也是 true。做格式校验必须加 ^ 与 $ 收口。此外，带 g/y 的正则会因 lastIndex 累积导致连续调用结果交替，见系列第 2 篇《修饰符》中的“g 修饰符与 lastIndex”一节。

```js
// 非字符串参数会先被转成字符串
console.log(/\d/.test(123));    // true（"123"）
console.log(/true/.test(true)); // true（"true"）

// 同一段文本，加不加锚点结论完全相反
console.log(/\d{11}/.test("a13800138000b"));  // true（包含即可）
console.log(/^\d{11}$/.test("a13800138000b")); // false（必须整串）
```



#### exec() 方法

**regExp.exec(string)**：执行一次匹配，成功返回**结果数组**（含 index、input、groups，带 d 时还有 indices），失败返回 null。带 g/y 时会推进 lastIndex，可循环取出全部匹配。

```js
const wordReg = /(\w+)@(\w+)/g;
let match = null;

while ((match = wordReg.exec("a@x 和 b@y")) !== null) {
  console.log(match[0], match[1], match[2], match.index);
}
// "a@x" "a" "x" 0
// "b@y" "b" "y" 6
```

> [!WARNING]
> **警告内容**：exec 是唯一能**逐个取出“所有匹配 + 分组详情 + 下标”**的传统手段，代价是要手动维护 lastIndex 并警惕**零长匹配导致死循环**：/(a*)/g 这类能匹配空串的正则必须在使用后手动推进 lastIndex，否则 while 永不结束。日常更推荐 matchAll。

```js
// 零长匹配死循环的防范写法：匹配为空时手动推进
const zeroReg = /a*/g;
let m = null, guard = 0;
const input = "bbb";

while ((m = zeroReg.exec(input)) !== null) {
  if (m[0] === "") zeroReg.lastIndex += 1; // 空匹配时推进位置
  if (++guard > 100) break;                // 兜底保险
  console.log(m[0], m.index);
}
```



#### 符号协议：字符串方法如何调用正则

**字符串方法并不“认识”正则，它们只认符号方法**：replace、replaceAll、match、matchAll、search、split 在处理参数时，会去取参数的对应符号方法（Symbol.replace 等）并调用它。正则对象正是实现了这几个符号方法，才成了这些 API 的合法参数。

- **Symbol.replace**：str.replace 与 str.replaceAll 调用它，签名是 (字符串, 替换值)。
- **Symbol.match**：str.match 在参数带 g 判定的场景下调用它。
- **Symbol.matchAll**：str.matchAll 调用它，返回迭代器。
- **Symbol.search**：str.search 调用它，返回下标。
- **Symbol.split**：str.split 调用它，返回数组。

```js
// 自定义对象只要实现符号方法，就能充当“查找规则”
const ymdRule = {
  [Symbol.replace](text) {
    return text.replace(/(\d{4})-(\d{2})-(\d{2})/, "$1年$2月$3日");
  },
};

console.log("2024-01-15".replace(ymdRule)); // "2024年01月15日"

// 正则对象自身的符号方法可以取出来调用
const reg = /\d+/g;
console.log(RegExp.prototype[Symbol.replace].call(reg, "价格 128", "[$&]"));
// "价格 [128]"
```

> [!NOTE]
> **提醒内容**：理解这层协议，就能解释几个现象：**为什么字符串方法接受“看起来不像正则”的对象**、**为什么给正则覆写 Symbol.replace 会改变 replace 的结果**、**为什么 matchAll 要求正则带 g**（判定发生在调用 Symbol.matchAll 之前）。入门阶段不必深究，但读库源码时会频繁遇到。



### 字符串对象的方法

#### match() 方法

**str.match(regexp)**：返回匹配结果，其行为**随 g 标志而分裂**。

- **不带 g**：等价于一次 exec，返回第一个匹配的数组（含 index、input、groups），无匹配返回 null。
- **带 g**：返回由**所有完整匹配字符串**组成的数组，**不含**分组、index、groups；无匹配返回 null。

```js
const str = "2024-01-15";

console.log(str.match(/\d+/));   // ["2024"]（仅第一个）
console.log(str.match(/\d+/g));  // ["2024", "01", "15"]（全部完整匹配）

const first = str.match(/(\d{4})-(\d{2})/);
console.log(first[1], first[2], first.index); // "2024" "01" 0
```

> match 带 g 时只给“完整串”，分组信息**全部丢失**——这是它最大的局限，也是 matchAll 存在的原因。另外 match 会在开始前把 lastIndex 归零，所以它不像 test/exec 那样受上一次调用的影响。注意：**无匹配时返回 null 而不是空数组**，直接访问 length 属性会抛错。

```js
// 一个模式在四种调用下的返回值对照
const text = "2024-01-15";
console.log(text.match(/\d{4}-(\d{2})-(\d{2})/)[1]);  // "01"（不带 g：有分组）
console.log(text.match(/\d{4}-(\d{2})-(\d{2})/g));    // ["2024-01-15"]（带 g：无分组）
console.log(text.match(/xyz/));                        // null
console.log(text.match(/xyz/g));                       // null
```



#### matchAll() 方法

**str.matchAll(regexp)**：返回一个**迭代器**，逐项产出**所有匹配及其分组详情**，ES2020 引入。

```js
const str = "2024-01 2025-02";
const dateReg = /(\d{4})-(\d{2})/g;

for (const match of str.matchAll(dateReg)) {
  console.log(match[0], match[1], match[2], match.index);
}
// "2024-01" "2024" "01" 0
// "2025-02" "2025" "02" 8

// 需要数组时展开即可
const allMatches = [...str.matchAll(dateReg)];
console.log(allMatches.length); // 2
```

> [!IMPORTANT]
> **重要内容**：三条硬性规则：**正则必须带 g**，否则抛 TypeError；**返回的是迭代器而非数组**，要 for-of 遍历或用 [...] 展开；**内部会克隆一份正则**，因此不会污染原对象的 lastIndex。这是“全量匹配 + 分组详情”场景下的最优解。

```js
// matchAll 的典型应用：提取所有话题标签及其正文
const text = "#js #regex #es2022";
const tags = [...text.matchAll(/#(\w+)/g)].map((m) => m[1]);
console.log(tags); // ["js", "regex", "es2022"]

// 迭代器是惰性的：不取值就不计算，适合边匹配边处理大文件
const stream = "a1 b2 c3".matchAll(/([a-z])(\d)/g);
let total = 0;
for (const item of stream) {
  total += Number(item[2]);
}
console.log(total); // 6
```



#### search() 方法

**str.search(regexp)**：返回**第一个匹配的下标**，找不到返回 -1。

```js
const str = "Hello World";
console.log(str.search(/World/)); // 6
console.log(str.search(/xyz/));   // -1

// 即使正则带 g，也只找第一个
console.log(str.search(/o/g)); // 4
```

> search 与 indexOf 的区别是**接受正则**；与 match 的区别是**只返回下标、不要内容**。它会先把 lastIndex 设为 0 并在结束后还原，因此 g 标志对它**没有实际作用**——它永远从头找、永远只报第一个。



### 替换

#### replace() 方法

**str.replace(searchValue, replaceValue)**：把匹配到的内容替换掉，返回**新字符串**，原串不变。searchValue 可以是字符串或正则，replaceValue 可以是字符串或函数。

替换字符串中的特殊记号：

- **$$**：字面量 $。
- **$&**：整个匹配。
- **$ 加反引号记号**：匹配**之前**的文本。
- **$'**：匹配**之后**的文本。
- **$n**：第 n 个捕获组。
- **美元符号加尖括号组名**：命名捕获组。

```js
const str = "2024-01-15";

console.log(str.replace(/-/g, "/")); // "2024/01/15"（配合 g 才替换全部）
console.log(str.replace(/-/, "/"));  // "2024/01-15"（不带 g 只换第一个）

// 交换分组顺序
console.log(str.replace(/(\d{4})-(\d{2})/, "$2/$1")); // "01/2024-15"

// 命名分组与 $<name>
const dateReg = /(?<year>\d{4})-(?<month>\d{2})/;
console.log(str.replace(dateReg, "$<month>/$<year>")); // "01/2024-15"

// $& 引用整个匹配：给数字加方括号
console.log(str.replace(/\d+/g, "[$&]")); // "[2024]-[01]-[15]"

// 函数形式：动态生成替换内容
console.log(str.replace(/\d+/g, (matched) => String(Number(matched) * 2)));
// "4048-2-30"（"01" 转数字后是 1，乘 2 得 2）
```

> 函数形式的参数依次是 match、各捕获组、offset、string、groups，返回值即替换文本。它是 replace 最灵活的地方：大小写转换、查表映射、按需格式化都能一步完成。**replace 不修改原串**，必须接收返回值。



#### 替换串中的 $ 陷阱

**替换串里的 $ 永远会被解释**，而且“引用落空”要分两种情况看，行为完全不同——这是替换规则里最容易判断错的一处。

- **引用的组不存在**：模式里没有这个编号的组、或 $<组名> 的组名未定义时，整个记号**原样保留为字面文本**，输出里会实实在在地看到 $1、$<x> 这些字符。
- **引用的组存在但未参与匹配**：可选组缺席时，替换成**空串**，输出里看不出任何痕迹，只是平白多出一个空位。
- **想输出字面美元符号**：必须写成 $$，一个 $ 会被引擎当作记号的开头。

```js
const text = "Total: $5.00, Tax: $0.40";
const amountReg = /\$\d+\.\d{2}/g;

// 落空情形一：模式里没有捕获组，$1 无处可指，被原样输出
console.log(text.replace(amountReg, "$1 was here"));
// "Total: $1 was here, Tax: $1 was here"（多出两个字面的 $1）

// 组号超出范围、组名未定义，同样原样保留
console.log("ab".replace(/(a)/, "[$2]"));     // "[$2]b"
console.log("ab".replace(/(a)/, "[$<x>]"));   // "[$<x>]b"

// 落空情形二：组存在但缺席，替换成空串，只剩一对空方括号
console.log("Cher".replace(/^(\w+)(?:\s(\w+))?$/, "[$2]")); // "[]"

// 正确写法一：字面 $ 写成 $$
console.log("价格 128".replace(/(\d+)/, "$$$1")); // "价格 $128"

// 正确写法二：用 $& 引用整个匹配
console.log(text.replace(amountReg, "$&（含税）"));
// "Total: $5.00（含税）, Tax: $0.40（含税）"
```

> [!WARNING]
> **警告内容**：替换串测试必须看**最终输出**而不是匹配列表——匹配完全正确、替换却损坏数据，是 replace 事故的标准形态。替换串中出现美元符号时逐个检查：要字面就写 $$，要引用就确认组号或组名真实存在；“组不存在”会留下可见的 $1 残留，“组缺席”则留下不可见的空位，两种都得靠输出比对才能发现。



#### replace 的函数形式

```js
// 函数形式的完整参数：offset 是匹配在原串中的起始下标
console.log(
  "a1b2".replace(/(\d)(\d)?/, (m, p1, p2, offset, str, groups) => {
    console.log(m, p1, p2, offset, str); // "1" "1" undefined 1 "a1b2"
    return "X";
  })
); // "aXb2"

// 命名分组时，最后一个参数是 groups 对象
"2024-01".replace(/(?<y>\d{4})-(?<m>\d{2})/, (m, p1, p2, offset, str, groups) => {
  console.log(groups.y, groups.m); // "2024" "01"
  return m;
});

// 函数形式实战：手机号脱敏
const mobile = "13812345678";
console.log(mobile.replace(/^(\d{3})\d{4}(\d{4})$/, "$1****$2")); // "138****5678"
console.log(mobile.replace(/(\d{3})\d{4}(\d{4})/, (m, a, b) => a + "****" + b));
// "138****5678"（函数形式与 $ 记号等价，逻辑复杂时更清晰）

// 函数形式实战：单词首字母大写
function titleCase(text) {
  return text.replace(/\b\w/g, (char) => char.toUpperCase());
}
console.log(titleCase("hello regex world")); // "Hello Regex World"
```

> 函数形式与 $ 记号怎么选：**逻辑一行能写完用 $ 记号**（数字下标 $1、命名组用美元符号加尖括号组名），**涉及计算、查表、条件分支用函数**。函数形式还有个隐性优点——返回值不会被 $ 解释，天然规避上一节的所有陷阱。



#### replaceAll() 方法

**str.replaceAll(searchValue, replaceValue)**：替换**全部**匹配，返回新字符串，ES2021 引入。

```js
console.log("a-b-c".replaceAll("-", "/"));   // "a/b/c"（字符串直接全替换）
console.log("a-b-c".replaceAll(/-/g, "/"));  // "a/b/c"（正则必须带 g）
console.log("a-b-c".replaceAll(/-/, "/"));   // TypeError：正则缺 g 标志
console.log("2024-01".replace(/(\d+)/g, "$1年")); // "2024年-01年"
```

> replaceAll 对**字符串**参数等价于 split 加 join，对**正则**参数则强制要求 g 标志——这是刻意的保护：既然方法名写了 All，就不该因为漏写 g 而静默只换一个。它比 replace(/x/g, ...) 的意图更明确，也更不容易漏掉 g。



#### split() 方法

**str.split(separator, limit)**：按分隔符把字符串拆成数组，separator 可以是字符串或正则，limit 限制返回的最大片段数。

```js
console.log("apple,banana;orange".split(/[,;]/)); // ["apple", "banana", "orange"]
console.log("a  b\tc".split(/\s+/));              // ["a", "b", "c"]
console.log("a,b;c".split(/[,;]/, 2));            // ["a", "b"]

// 带捕获组时，分隔符本身也会进入结果
console.log("a1b2c3".split(/(\d)/)); // ["a", "1", "b", "2", "c", "3", ""]
```

> 传字符串分隔符时 split 会先把它转成正则，所以 "a.b".split(".") 中的 . 会被当作正则元字符（虽然匹配结果通常一样）。**正则含捕获组是关键差异点**：捕获到的分隔符会一并塞进结果数组，利用这一点可以在拆分的同时保留分隔符。

```js
// split 的实战场景：混合空白切分 + 保留分隔符
console.log("姓名　张三".split(/\s+/)); // ["姓名", "张三"]（全角空格也被切开）

// 保留分隔符：句子按标点切分，标点不丢
console.log("第一句。第二句！第三句？".split(/([。！？])/));
// ["第一句", "。", "第二句", "！", "第三句", "？", ""]
```



#### split() 的边界行为

**split 的输出长度、空串与 limit 的交互是三类常见困惑**，逐条实测一遍胜过反复试错。

- **首尾分隔符产出空串**：",a,b".split(",") 得到 ["", "a", "b"]，开头多一个空串；同理结尾的分隔符也会产出一个空串。
- **limit 截断而不补齐**：limit=2 返回前两项即止，不会把剩余部分合并成一项。
- **limit 为 0 或负值**：0 时返回空数组；负值会被转成一个大无符号整数，等同于**不限制**。
- **空字符串的分隔效果**：按空字符串或空正则切分，会按 UTF-16 码元逐个拆开，代理对会被拆坏。
- **切不出任何分隔符**：返回只含原串的单元素数组，原串从未匹配时不会返回空数组。

```js
console.log(",a,b".split(","));        // ["", "a", "b"]（首个空串来自开头的逗号）
console.log("a,b,".split(","));        // ["a", "b", ""]（末尾空串来自结尾的逗号）
console.log("a,b,c".split(",", 0));    // []（limit 为 0）
console.log("a,b,c".split(",", -1));   // ["a", "b", "c"]（负值等同不限制）
console.log("abc".split(""));          // ["a", "b", "c"]
console.log("𝄞".split(""));            // 两个元素（代理对被拆坏）
console.log([..."𝄞"]);                 // ["𝄞"]（展开运算符按码点切，正确做法）
```

> [!CAUTION]
> **注意内容**：“a,b,” 按逗号拆分得到的是**三项**而不是两项，末尾那个空串在许多解析逻辑里都会被当成一个有效字段，进而导致“空记录”。处理 CSV 风格的文本时，要么先 trim 掉结尾分隔符，要么在拆分后显式过滤空串。



### 方法对照与选用

#### 六种方法怎么选

- **“有没有”**：test() 返回布尔；search() 返回下标或 -1。
- **“第一个匹配 + 详情”**：exec() 与不带 g 的 match()，二者等价。
- **“全部匹配、只要完整串”**：带 g 的 match()。
- **“全部匹配 + 分组 + 下标”**：matchAll()（必须带 g）。
- **“替换”**：replace()（带 g 则全部）或 replaceAll()（正则必须带 g）。
- **“拆分”**：split()。

```js
const text = "联系方式：138-0013-8000，备用：139-0013-9000";
const phoneReg = /(\d{3})-(\d{4})-(\d{4})/g;

// 只要号码：用 match
console.log(text.match(/\d{3}-\d{4}-\d{4}/g));
// ["138-0013-8000", "139-0013-9000"]

// 要分组：用 matchAll
for (const m of text.matchAll(phoneReg)) {
  console.log(`${m[1]}****${m[3]}`); // "138****8000"、"139****9000"
}
```

> 选中方法的判断顺序是：**先看要不要“全部”，再看要不要“分组”**。只要完整串用 match，要分组用 matchAll，只要真假用 test，只要位置用 search——exec 循环是前两者都不方便时的兜底。



#### 方法层故障排查清单

**方法层的“正则不生效”**几乎都能对号入座，按现象排查：

- **test 时真时假**：带 g 或 y 的正则被复用，lastIndex 在累积；去掉 g 或重置为 0。
- **replace 只换第一处**：模式没带 g；或改用 replaceAll。
- **matchAll 抛 TypeError**：正则缺 g 标志。
- **match 返回 null 后直接取下标**：无匹配返回 null 而非空数组，先判空。
- **分组值是 undefined**：可选组没参与匹配；用 ?? 兜底。
- **替换结果多了空位或少了几元**：替换串引用的组缺席（落成空串），或引用了不存在的组号（留下 $1 这样的字面残留）。
- **多行文本校验失败**：没加 m，^ $ 只认整串首尾。
- **含换行的内容匹配不上**：. 默认不匹配换行；加 s 或改 [\s\S]。
- **替换函数里的 offset 用错**：offset 是**匹配在原串中的下标**，不是“第几次匹配”。
- **split 结果多出空串**：原串首尾有分隔符；先清理或在结果里过滤空串。

> [!TIP]
> **建议内容**：排查方法层问题的固定套路是**先打印匹配结果再看替换输出**：console.log 一次 match 或 matchAll 的返回值，多数“不生效”会在这一步现出原形——要么 null、要么缺分组、要么只匹配了一半。
