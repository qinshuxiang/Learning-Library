## 断言与锚点

### 锚点

#### 四种位置匹配

**锚点（Anchor）**：匹配的是**位置**而不是字符，不消耗任何字符。

- **^**：字符串开头；配合 m 时为行首。
- **$**：字符串结尾；配合 m 时为行尾。
- **\b**：单词边界，即 \w 与非 \w 之间的位置。
- **\B**：非单词边界。

```js
console.log(/^abc/.test("abcdef"));   // true
console.log(/abc$/.test("xyzabc"));   // true
console.log(/\bcat\b/.test("a cat"));      // true（cat 是独立单词）
console.log(/\bcat\b/.test("category"));   // false（cat 嵌在单词里）

// \b 以 \w 为准：下划线属于单词字符，字母与下划线之间不存在边界
console.log(/\buser_id\b/.test("我的 user_id 字段")); // true（两侧都是边界）
console.log(/\buser\b/.test("user_id"));              // false（user 后接下划线，不构成边界）
```

> [!WARNING]
> **警告内容**：三个高频误区：一是 ^...$ 才是**全串匹配**，只写一半会让 “13800138000abc” 通过 /\d{11}/.test()；二是 JavaScript 的 $ **不允许末尾换行前匹配**，/a$/.test("a\n") 是 false；三是 \b 依赖 \w，而 \w 只认 ASCII，/\b中文\b/.test("学中文") 是 false——中文没有单词边界可用。



#### 锚点的精确语义

**四个锚点各自描述一类“位置”**，把它们当成“字符的边界线”来理解，可以避免绝大多数误用。

- **^ 的默认含义**：匹配**输入的开头**这一个位置，全文只成立一次。
- **$ 的默认含义**：匹配**输入的末尾**这一个位置，且**不把末尾换行当作例外**——这一点与 Python、PCRE 不同。
- **\b 的定义**：一侧是 \w 字符、另一侧不是 \w 字符的位置；两侧都是 \w、或都不是 \w 时都不算边界。
- **\B 的定义**：\b 的补集，即两侧同为 \w 或同为非 \w 的位置。
- **JavaScript 没有 \A 与 \Z**：这两个来自 PCRE 的绝对首尾锚点在 JavaScript 中不存在，写了会被当成字面字母。

```js
// $ 不把末尾换行当例外
console.log(/a$/.test("a\n"));  // false
console.log(/a$/m.test("a\n")); // true（m 模式下行尾成立）

// \b 与 \B 的互补关系
console.log(/\bcat\b/.test("cat"), /\Bcat/.test("cat"));   // true false
console.log(/cat\B/.test("cats"), /\bcat\b/.test("cats")); // true false

// 中文没有单词边界
console.log(/\b中文\b/.test("学中文")); // false
console.log(/\B中文/.test("学中文"));   // true（中文两侧都不是 \w 边界）

// JavaScript 没有 \A
console.log(/\Aabc/.test("abc")); // false（\A 被当作字面字母 A）
console.log(/Aabc/.test("Aabc")); // true（证据：\A 等价于 A）
```

> [!NOTE]
> **提醒内容**：**中文文本不要用 \b 做词边界**。需要“词”的概念时，中英混排用 [\p{Script=Han}A-Za-z0-9_] 自定义类，或者干脆按标点切分；只有纯 ASCII 文本才适合用 \b。



#### 缺少锚点的校验漏洞

**验证类正则必须锚点收口**，这是正则安全里最基础也最高频的一条：漏锚点等于允许“在任意位置命中”，攻击面与数据脏污都由此进入。

```js
// 漏锚点：嵌在任意位置的 11 位数字都能通过
console.log(/\d{11}/.test("备注：伪造13800138000abc")); // true！

// 收口后：必须是整串恰好 11 位数字
console.log(/^\d{11}$/.test("备注：伪造13800138000abc")); // false
console.log(/^\d{11}$/.test("13800138000"));              // true
```

> [!IMPORTANT]
> **重要内容**：判断一条验证正则是否合格，先看有没有 **^ 与 $**。凡是被多人维护过的表单校验代码，回归测试里都应包含“正确值前后拼上杂质字符”的负样本。



### 四种断言

#### 先行断言

**先行断言 x(?=y)**：要求 x 的**后面**必须紧跟着 y，但 y 不进入匹配结果。

```js
console.log(/\d+(?=元)/.exec("价格 100元")[0]); // "100"（“元”未被消费）

// 密码强度校验：至少包含一个数字
console.log(/(?=.*\d)/.test("abc1")); // true
console.log(/(?=.*\d)/.test("abcd")); // false
```

> /(?=.*\d)/ 这种写法叫“**条件叠加**”：把若干个先行断言并列，等价于对同一个位置施加多个“与”条件。密码强度规则（同时含数字、含小写、含大写、长度 ≥ 8）就是靠它一行写完的，例如 /^(?=.*\d)(?=.*[a-z])(?=.*[A-Z]).{8,}$/。



#### 先行否定断言

**先行否定断言 x(?!y)**：要求 x 的**后面**不能是 y。

```js
console.log(/\d+(?!元)/.exec("数量 100件")[0]); // "100"

// 匹配不是 .js 结尾的文件名
console.log(/^\w+\.(?!js$)\w+$/.test("main.ts")); // true
console.log(/^\w+\.(?!js$)\w+$/.test("main.js")); // false
```

> 否定断言的括号里同样“只检查、不消费”，所以 /(?!js$)/ 检查的是“从当前位置起不是 js 且紧接着结尾”，它不会把 ts 吃掉。



#### 后行断言

**后行断言 (?<=y)x**：要求 x 的**前面**必须是 y，ES2018 引入。

```js
console.log(/(?<=￥)\d+/.exec("￥99")[0]);     // "99"
console.log(/(?<=单价：)\d+/.exec("单价：88")[0]); // "88"
```

> 后行断言与先行断言完全对称：先行 x(?=y) 看**后面**，后行 (?<=y)x 看**前面**。它常用于“提取带特定前缀的内容”，替代过去必须先捕获前缀再取 [1] 的写法。



#### 后行否定断言

**后行否定断言 (?<!y)x**：要求 x 的**前面**不能是 y。

```js
console.log(/(?<!￥)\d+/.exec("$88")[0]); // "88"

// 不匹配 "foo" 内部的数字
console.log(/(?<!foo)\d+/.exec("bar 123")[0]); // "123"
```

> 需要注意：后行断言在部分旧引擎（如老版本 Safari）中不被支持，且**后行断言内的匹配是从右往左进行的**，过复杂的模式可能影响可读性。生产环境使用前请核对兼容性基线。



#### 变长后行断言

**JavaScript 的后行断言允许变长**：(?<=...) 里面的模式可以用量词和多分支，各分支长度可以不同——这与 PCRE、Python（后行断言必须定长）不同，是 JavaScript 引擎的独特能力。

```js
// 两个分支长度不同（元是 1 个字符、美元是 2 个字符），JavaScript 合法
console.log(/(?<=元|美元)\d+/.exec("美元88")[0]); // "88"

// 量词同样可以出现在后行断言里
console.log(/(?<=:\s*)\d+/.exec("端口: 8080")[0]); // "8080"
console.log(/(?<=\d{2}年)\d{1,2}月/.exec("2024年3月")[0]); // "3月"

// 先行断言本来就支持变长，两个方向在此规则一致
console.log(/\d+(?=\s*元)/.exec("88 元")[0]); // "88"
```

> 变长后行断言降低了“提取带可变前缀内容”的写法成本：不必为凑定长把模式拆成两条。但可读性随分支复杂度下降，分支超过两三个时，捕获组加取下标反而是更好的选择。



#### 断言的共性

- **零宽（zero-width）**：断言只检查条件，**不消耗字符**，匹配结果里不会出现断言的内容。
- **不可量化**：(?=a)* 这类写法在 u/v 模式下是语法错误。
- **可组合**：多个断言可以并列，形成“与”逻辑；^、$、\b 本质上也是断言。
- **内部可捕获**：断言里写的捕获组照常计入编号，结果出现在返回数组里。

```js
// 断言不消耗字符的证据：两个断言叠在同一位置
const password = "Abc12345";
const pwdReg = /^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)[A-Za-z\d]{8,}$/;
console.log(pwdReg.test(password)); // true

// 断言里的捕获组计入编号
const overlapReg = /(?=(\d{2}))/g;
console.log([..."1234".matchAll(overlapReg)].map((m) => m[1])); // ["12", "23", "34"]

// 不可量化：非 u 模式放行，u 模式报错
console.log(new RegExp("(?=a)*").source); // "(?=a)*"（非 u 模式宽容）
// new RegExp("(?=a)*", "u");             // SyntaxError: Invalid quantifier
```

> 口诀：**“先行看后、后行看前；只查不拿、成对出现”**。四条断言的记忆方式是——括号里带 < 的看**前面**（< 像箭头指回左边），不带 < 的看**后面**；带 ! 的是**否定**，不带的是**肯定**。



### 断言的组合应用

#### 条件叠加写密码强度

**条件叠加**的每一项只断言一个“含有某类字符”的条件，主干量词再约束长度，两层职责清晰分离。

```js
// 至少 8 位，且同时包含小写字母、大写字母与数字
const pwdReg = /^(?=.*[a-z])(?=.*[A-Z])(?=.*\d).{8,}$/;

console.log(pwdReg.test("abc12345"));  // false（缺大写字母）
console.log(pwdReg.test("Abc12345"));  // true
console.log(pwdReg.test("ABCDEFG1"));  // false（缺小写字母）
console.log(pwdReg.test("Ab1"));       // false（不足 8 位）
```

> 拆解：^(?=.*[a-z]) 在开头位置断言“往后看能得到一个小写字母”，三个断言依次并列成“与”关系，最后 .{8,} 才真正开始吃字符。要再加一条“必须含特殊字符”，并列一个 (?=.*[^\w\s]) 即可，模式主干无需改动。



#### 条件叠加的更多用法

**“必须含”用正断言，“不得含”用否定断言**，两类条件可自由叠加，这是把多条业务规则压进一条正则的标准做法。

- **必须含某类字符**：(?=.*\d)，向后扫一遍找到一个数字。
- **不得含某类字符**：(?!.*[<>])，从当前位置起往后都不能出现尖括号。
- **必须以某类字符开头**：把断言放在 ^ 之后且不写 .*，如 ^(?=[A-Z])。
- **不得以某类字符开头或结尾**：^(?![._-]) 与 (?<![._-])$ 一前一后配合。

```js
// 规则一：不得包含尖括号与引号，防止注入
const safeTextReg = /^(?!.*[<>"']).+$/;
console.log(safeTextReg.test("正常文本"));   // true
console.log(safeTextReg.test("含<script>")); // false

// 规则二：首尾不得是标点，中间不限
const accountReg = /^(?![._-])[\w.-]{3,16}(?<![._-])$/;
console.log(accountReg.test("user_name"));   // true
console.log(accountReg.test("_username"));   // false（以下划线开头）
console.log(accountReg.test("username."));   // false（以点结尾）

// 规则三：禁止连续三个相同字符的强密码
const noRepeatReg = /^(?!.*(.)\1\1)(?=.*\d)(?=.*[a-zA-Z]).{8,}$/;
console.log(noRepeatReg.test("Abc12345")); // true
console.log(noRepeatReg.test("Aaaa1234")); // false（连续四个 a 里含三个相同字符）
console.log(noRepeatReg.test("Aaa12345")); // true（只有两个 a，不算连续三个）
```

> [!TIP]
> **建议内容**：**“不得含”这类否定条件要写成 (?!...) 并在括号里补 .* 前缀**，因为断言是零宽的，只检查当前位置；(?!.*[<>]) 表示“从这里往后扫，全程都没有尖括号”，而 (?!.*) 与 ([<>]) 的拆分写法经常写错。写完用一条含违规字符的负样本验证一次，是最快的自检。



#### 千分位中的断言配合

千分位插入是断言组合的经典范本：一个负断言收口、一个正断言计数。

```js
function groupByThousands(value) {
  return String(value).replace(/\B(?=(\d{3})+(?!\d))/g, ",");
}

console.log(groupByThousands(1234567)); // "1,234,567"
console.log(groupByThousands(123));     // "123"
```

> 拆解：\B 定位在非单词边界，(?=(\d{3})+(?!\d)) 断言“后面剩余数字个数正好是 3 的倍数”——内层 (?!\d) 负责收口，防止 3 的倍数再往后多吞。完整案例解析见系列第 10 篇《实战案例集》。



#### 环视替代捕获组取值

**断言让“取值”与“限定”解耦**：需要的是数字本身，前缀货币符号只是条件，用后行断言比捕获组省一步取值。

```js
// 传统写法：捕获前缀，取 [1]
const oldWay = /单价：(\d+)/.exec("单价：88")[1];

// 断言写法：直接匹配目标本身
const newWay = /(?<=单价：)\d+/.exec("单价：88")[0];

console.log(oldWay === newWay); // true（结果一致，代码更短）
```

> 断言的适用边界要记牢：条件**长度固定或有规律**时（货币符号、固定前缀）用断言最顺；条件本身结构复杂、需要多分支时，捕获组反而更直白。两种写法都能正确工作时，**选团队更熟悉的那种**。



#### 断言不消费的重叠提取

**断言“只查不拿”的性质可以反过来利用**：把断言放在模式开头，让引擎在每个位置都“看一眼但不前进”，就能在**互相重叠**的位置上连续提取——这是普通匹配做不到的。

```js
const digits = "20240115";

// 滑动窗口：每个位置起连续 4 个数字（8 个字符产出 5 个窗口）
console.log([...digits.matchAll(/(?=(\d{4}))/g)].map((m) => m[1]));
// ["2024", "0240", "2401", "4011", "0115"]

// 相邻字符对：断言内的捕获组同样记录结果
console.log([...("正则表达".matchAll(/(.)(?=(.))/gu))].map((m) => m[1] + m[2]));
// ["正则", "则表", "表达"]
```

> 拆解：(?=(\d{4})) 在每个位置断言“往后 4 个字符是数字”，同时把这 4 个字符**捕获**进组 1；断言本身不消耗字符，g 标志把位置一格一格推进，于是产出全部重叠窗口。断言里的捕获组照常计入编号并出现在结果里，这是“取每个连续 n 元组”类需求的标准解法。



#### 断言的顺序与性能

**断言是“在每个候选位置都要重跑一遍的条件”**：把最容易失败、代价最小的断言放在最前面，可以让不合规的输入尽早退出，而不是先跑完昂贵的条件再失败。

- **廉价的先放**：长度判断、首字符类别判断，都比较便宜，放最前。
- **昂贵的后放**：涉及 .* 的回溯型断言（如 (?=.*[A-Z])）要扫全串，尽量往后排。
- **用锚点收口**：^ 与 $ 让断言只在有限位置运行，避免在字符串每个位置都试。
- **避免重复叠加**：两条断言检查同一件事时只保留一条，多余的断言纯属开销。

```js
// 顺序一：把“长度不足就退出”的断言放第一位
const fastReg = /^(?=.{8,})(?=.*\d)(?=.*[A-Z]).*$/;
console.log(fastReg.test("Ab1"));       // false（第一条断言立刻退出）
console.log(fastReg.test("Abc12345"));  // true

// 顺序二：先扫全串再判长度，短输入也要把三条断言跑完
const slowReg = /^(?=.*\d)(?=.*[A-Z])(?=.{8,}).*$/;
console.log(slowReg.test("Ab1")); // false（结论相同，代价更高）
```

> 这类优化的收益在**高频校验接口**上最明显：断言顺序不影响正确性，只影响最坏与平均耗时。写完之后用一批“注定失败”的样本测一轮，观察耗时差异，比凭感觉调序更可靠。
