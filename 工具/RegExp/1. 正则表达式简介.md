## 正则表达式简介

### 什么是正则表达式

#### 定义与作用

**正则表达式（Regular Expression，简称 RegExp）**：是用于**匹配字符串中字符组合的模式**，本质是一套描述文本规则的**模式语言**——用紧凑的符号回答“要匹配什么样的文本”这个问题。

- **验证**：判断字符串是否符合某种格式（手机号、邮箱、密码强度、身份证号）。
- **搜索**：在文本中查找匹配的内容（日志检索、关键词定位）。
- **替换**：批量替换文本中的特定模式（格式转换、脱敏处理）。
- **提取**：从字符串中抽取所需的片段（解析日期、抓取链接、提取参数）。
- **分割**：按模式把字符串拆成数组（混合分隔符、多余空白）。
- **词法分析**：把长文本切成一个个记号（模板引擎、简易解析器）。

```js
const email = "user@example.com";
const emailReg = /^\w+@\w+\.\w+$/;
console.log(emailReg.test(email)); // true
```

> 正则的价值在于**用声明式的模式代替繁琐的字符串判断**：一个手机号校验，手写 if 可能几十行，用正则一行完成。它难在语法紧凑、不直观，但掌握之后处理文本的效率会成倍提升。



#### 正则既是语法也是对象

在 JavaScript 中，正则不只是语法，还是**对象**：RegExp 实例持有 source（模式文本）、flags（标志串）、lastIndex（下一次匹配的起始位置）等状态，可作为值传递、可作为字符串方法的参数。

```js
const digitReg = /\d+/g;

console.log(digitReg.source);    // "\d+"（模式文本）
console.log(digitReg.flags);     // "g"
console.log(digitReg.global);    // true（对应 g 标志的只读布尔属性）
console.log(digitReg.lastIndex); // 0（下一次从哪个位置开始匹配）
```

> 理解“正则是对象”是理解 lastIndex 陷阱的前提：**状态挂在对象上，复用同一个对象就会复用它的状态**。标志一旦确定就无法更改，g、i、m、s、u、y、d、v 只能通过重新创建正则来改变。



#### 方法主体的归属

**方法主体口诀**：test 与 exec 是**正则对象**的方法，match、matchAll、replace、replaceAll、search、split 是**字符串对象**的方法。两者写反是最常见的入门错误。

```js
// 正确：主体与方法匹配
console.log(/\d+/.test("abc123"));      // true（正则对象调 test）
console.log("abc123".match(/\d+/)[0]);  // "123"（字符串对象调 match）

// 错误示范（运行即报错）：
// "abc123".test(/\d+/)   → TypeError: str.test is not a function
// /\d+/.match("abc123")  → TypeError: reg.match is not a function
```

> [!IMPORTANT]
> **重要内容**：口诀——**正则当家 test、exec；字符串当家 match、replace、search、split**。判断某段代码能否运行，先看点号左边是什么对象，再确认方法是否属于它。



### 创建正则表达式对象

#### 字面量创建

**字面量创建**：用一对斜杠 /pattern/flags 直接书写模式，是最常用、最简洁的方式。

```js
const wordReg = /hello/i;
console.log(wordReg.test("Hello World")); // true

// 修饰符写在最后一个斜杠之后，可组合
const globalReg = /a/g;   // g：全局匹配
const multiReg = /^a/m;   // m：多行模式
const allFlags = /a/gimsy;
```

> 字面量在**脚本加载（解析）时编译**，模式固定不变，可读性与性能都最好。模式写成常量时，一律用字面量。



#### 构造函数创建

**构造函数创建**：new RegExp(pattern, flags) 的第一个参数是**字符串**，适用于模式需要**动态拼接**的场景。

```js
const reg = new RegExp("hello", "i");
console.log(reg.test("Hello World")); // true

// 动态生成模式：从变量拼接
const keyword = "abc";
const dynamicReg = new RegExp(keyword, "g");
console.log(dynamicReg.test("abcabc")); // true

// ES6 起允许传入正则并覆盖标志
const clonedReg = new RegExp(/abc/, "gi");
console.log(clonedReg.flags); // "gi"
```

> 构造函数在**运行时编译**，且 pattern 是字符串，因此正则里的反斜杠要写两遍：/\d+/ 对应的构造函数写法是 new RegExp("\\d+")。这是构造函数最容易出错的地方——字符串字面量先消费一个反斜杠，正则引擎再消费一个。双重转义少写一遍，new RegExp("\d+") 得到的实际模式只剩字符 d 与一个加号，校验目标整个变了。



#### 两种创建方式的选择

- **模式固定**：用**字面量**，编译早、无双重转义、可读性高。
- **模式动态**：用**构造函数**，可以从变量、用户输入、配置项拼出模式。
- **性能**：字面量在循环中不会被反复重新编译；而**每次求值正则字面量都会创建一个新的 RegExp 对象**（ES5 起），所以字面量不会在多次调用间共享 lastIndex。

```js
// 字面量之间的状态互不干扰：每次求值都是新对象
console.log(/a/g.test("aa"), /a/g.test("aa")); // true true

// 复用同一个对象，lastIndex 才会累积
const reusedReg = /a/g;
console.log(reusedReg.test("aa"), reusedReg.lastIndex); // true 1
console.log(reusedReg.test("aa"), reusedReg.lastIndex); // true 2
console.log(reusedReg.test("aa"), reusedReg.lastIndex); // false 0
```

> [!IMPORTANT]
> **重要内容**：两条铁律：**模式不变用字面量，模式动态用构造函数**；**需要在多次调用之间保持状态（如逐段解析）时，必须把正则存进变量**，否则每次都是新对象、状态无从谈起。



#### 编译时机与状态归属

同一个模式用两种写法各建一次，得到的是**两个完全独立的实例**：各自的 lastIndex、各自的标志，互不影响。这也是“正则字面量每次求值都是新对象”之外的第二个关键区分点。

```js
const fromLiteral = /\d+/g;
const fromCtor = new RegExp("\\d+", "g");

console.log(fromLiteral.source === fromCtor.source); // true（模式文本一样）
console.log(fromLiteral === fromCtor);               // false（是两个对象）
console.log(fromLiteral.flags === fromCtor.flags);   // true

// flags 属性会按固定顺序 d g i m s u v y 重排，与书写顺序无关
console.log(new RegExp("a", "yusmigd").flags); // "dgimsuy"
```

> flags 的规范顺序是 **d、g、i、m、s、u、v、y**。写 /a/mi 与写 /a/im 得到的是同一个含义，读出来的 flags 都标准化为 im 的顺序排列，所以**不要用 flags 做书写顺序的比对**，要比对就比对 source 与 flags 的组合。



### 正则表达式的标准演进

#### 语法与方法的引入版本

正则的能力是**逐版本叠加**的，遇到“某个写法在旧环境报错”时，先查它属于哪个版本，比反复调试更快。

- **ES3（1999）**：正则字面量、test、exec、replace、match、split 基础能力齐备。
- **ES5（2009）**：明确**字面量每次求值创建新对象**；补齐 source、global 等属性。
- **ES2015（ES6）**：新增 **u** 与 **y** 两个标志，正则获得 Unicode 码点视角与粘性匹配能力。
- **ES2018**：新增 **s** 标志、**命名捕获组**、**后行断言**、**Unicode 属性转义** 四项大特性。
- **ES2020**：新增 **matchAll**，全量匹配不再需要手写 exec 循环。
- **ES2021**：新增 **replaceAll**，替换全部匹配时不必再记得补 g。
- **ES2022**：新增 **d** 标志，匹配结果带上 indices 起止索引。
- **ES2024**：新增 **v** 标志，字符类获得集合运算与多字符字符串支持。
- **ES2025**：新增 **RegExp.escape**，安全转义用户输入成为标准能力；同时允许**不同分支使用同名捕获组**。

> [!NOTE]
> **提醒内容**：新旧差异最容易被忽略的是 ES5 前后对**字面量复用**的处理：ES3 允许引擎复用同一个 RegExp 对象，ES5 起强制每次求值新建。判断一段老代码为何“时对时错”时，这条历史差异值得回查。

```js
// ES2018 的命名捕获组 + 后行断言
const reg2018 = /(?<=订单号：)(?<no>[A-Z]\d{6})/u;
console.log(reg2018.exec("订单号：A202401")[0]); // "A202401"
console.log(reg2018.exec("订单号：A202401").groups.no); // "A202401"

// ES2025 的重复命名捕获组：不同分支可以同名（同一分支内仍不允许）
const reg2025 = /(?<type>\d+)|(?<type>[a-z]+)/;
console.log(reg2025.exec("abc").groups.type); // "abc"
```

> [!WARNING]
> **警告内容**：**重复命名捕获组是较新的特性**——它在 V8 13.6（Node 24 及以上）可用，Node 22 及更早版本会直接抛 Duplicate capture group 的 SyntaxError，且只允许出现在**不同的“或”分支**里，写在同一分支内仍然报错。上线前用目标运行环境实测一次，别拿开发机的行为当标准。



### 正则引擎与匹配策略

#### 回溯型引擎与自动机型引擎

**回溯型引擎**：逐个位置尝试、失败就退回上一个选择点重试，JavaScript 的 RegExp 属于这一类，特点是**功能强但最坏情况可能指数级变慢**。

- **回溯型（Backtracking）**：JavaScript、Python、PHP、Java 默认引擎。支持反向引用、后行断言、$ 记号等，代价是可能触发灾难性回溯。
- **自动机型（NFA/DFA，非回溯）**：Google RE2、Go 的 regexp、Rust 的 regex crate。保证线性耗时，代价是不支持反向引用与部分断言。
- **判定要点**：**模式里有没有“同一段字符可以有多种拆法”**——有就属于回溯型的高危区，需要单独评估。

```js
// 同一段字符的两种读法：a+ 与 a+ 抢字符，属于回溯型引擎的特征
console.log(/(a+)(a+)/.exec("aaa").slice(1)); // ["aa", "a"]（贪婪先多拿，再退一个）

// 非回溯引擎遇到这个模式只能给出“匹配/不匹配”，拿不到这种拆分结果
```

> 选型结论：写业务校验用 JavaScript 自带的回溯型引擎即可，重点是**别写出歧义模式**；做高吞吐的公共接口校验时，把高风险正则换成 RE2 方案的收益，比逐条调优更直接。展开见系列第 9 篇《性能与安全》。



#### 匹配的“尝试—回溯”模型

**匹配模型**：引擎从起始位置出发，按模式的书写顺序逐个原子推进；某个原子推进失败时，**退回最近的、还有剩余选项的选择点**换一种走法。整个字符串上找不到任何走法，才判定匹配失败。

- **选择点**：量词还可以“少拿一个”、或“或”还有别的分支，都构成选择点。
- **成功条件**：模式走完且没有剩余必须满足的断言。
- **失败条件**：所有选择点都试尽仍走不完。

```js
// 同一个模式在 "ab" 与 "ac" 上的两种走法
console.log(/a[bc]/.exec("ab")[0]); // "ab"（第一格就命中 b）

// /a[bc]/ 在 "ac" 上要换第二个分支才成功，这就是一次“分支尝试”
console.log(/a[bc]/.exec("ac")[0]); // "ac"
```

> 建立这个模型之后，很多“玄学现象”就有了统一解释：**为什么贪婪会吃到最后一个**（选择点是“还能不能再吃”）、**为什么惰性遇到失败还会继续加长**（选择点是“还没吃够”）、**为什么嵌套量词会爆炸**（每一层都有独立的选择点，组合数相乘）。



### 何时不用正则

#### 用内置方法替代简单判断

**能用更简单手段解决的需求，不要上正则**：正则的语法成本与出错风险都高于直观的字符串方法，能用内置 API 一步到位的场景写正则属于自找麻烦。

- **包含判断**：String.prototype.includes(substring) 替代 /(关键词)/.test()。
- **前后缀判断**：startsWith(prefix)、endsWith(suffix) 替代 /(^前缀)/、/(后缀$)/。
- **URL 解析**：new URL(value) 提取协议、主机、查询参数，远比正则可靠。
- **数字格式化**：Intl.NumberFormat 与 toLocaleString() 替代千分位正则。
- **日期解析**：Date 对象与专用库（如 date-fns）替代用正则硬解析日期串。
- **复杂结构解析**：HTML 用 DOMParser，JSON 用 JSON.parse，表单校验可用 Zod 这类 schema 库的 regex 能力。

```js
// 简单判断：内置方法一目了然
console.log("hello world".includes("world")); // true
console.log("report.pdf".endsWith(".pdf"));   // true

// URL 解析：内置 API 完胜正则
const url = new URL("https://example.com:8080/path?name=张三");
console.log(url.hostname);          // "example.com"
console.log(url.searchParams.get("name")); // "张三"
```

> [!TIP]
> **建议内容**：选型次序是**内置方法优先、正则次之、专用解析器兜底**。判断标准看三点：需求是否只是固定的字面子串（用 includes）、是否需要模糊模式（用正则）、是否是结构化文本（用专用解析器）。



#### 正则做不到的四类事

**正则只认“线性字符序列”，处理不了需要状态的嵌套结构**。下面四类需求无论怎么写都会在边界输入上失手，识别它们可以省下大量返工。

- **任意深度的嵌套结构**：HTML 标签配对、JSON 对象、括号配对。正则的“计数”能力无上限记忆，配不出“左括号与右括号数量相等”。
- **跨行与上下文相关的替换**：像“把函数体内所有变量改名”需要作用域信息，正则拿不到。
- **自然语言的语义判断**：判断一句话是不是疑问句、有没有讽刺意味，模式语言无能为力。
- **严格的编码合法性**：UTF-8 字节序列校验、Base64 严格性校验，用专门的解码器比写模式可靠。

```js
// 括号配对的“看上去能用”写法：只能容纳一层
console.log(/^\([^()]*\)$/.test("(内层)"));     // true（一层没问题）
console.log(/^\([^()]*\)$/.test("((更内层))")); // false！内层一出现括号就失手
console.log(/^\([^()]*\)$/.test("(a(b)c)"));    // false（任何嵌套都不行）

// 正确做法：用栈结构或专用解析器
function isBalanced(text) {
  let depth = 0;
  for (const char of text) {
    if (char === "(") depth += 1;
    if (char === ")") depth -= 1;
    if (depth < 0) return false;
  }
  return depth === 0;
}
console.log(isBalanced("(((x)))")); // true
console.log(isBalanced("((x))"));   // true
console.log(isBalanced("((x)"));    // false
```

> [!WARNING]
> **警告内容**：看到“用正则解析 HTML”的方案就要提高警惕——属性顺序、单引号与双引号、跨行属性、注释里的假标签、script 里的字符串，任何一项都能让它失手。**浏览器已经提供了 DOMParser**，解析 HTML 从来不是正则该干的活。



### 阅读一条陌生正则的方法

#### 分步拆解流程

**拆解顺序**：先定标志，再切分组，后看量词，最后收锚点。按固定顺序读，比“从左到右硬猜”快得多。

- **第一步看标志**：g 决定是否全量、i 决定大小写、m 决定锚点语义、u 或 v 决定字符的计数单位——标志错了，后面全错。
- **第二步按顶层括号切分**：把模式按左右括号切成若干段，先认清“哪几段是一个整体”。
- **第三步标出量词的作用对象**：每个量词只作用于紧邻它的那一个原子，标出作用范围再读。
- **第四步找锚点与断言**：^、$、\b 以及 (?=...)、(?<=...) 决定“能在什么位置命中”。
- **第五步假设输入验证**：拿一个应当命中的样本跑一遍，再拿一个长得像的负样本跑一遍。

```js
// 待拆解的模式
const idCardReg =
  /^[1-9]\d{5}(?:19|20)\d{2}(?:0[1-9]|1[0-2])(?:0[1-9]|[12]\d|3[01])\d{3}[\dXx]$/;

// 拆解结果：
// ^ 与 $        → 全串匹配，不含杂质
// [1-9]\d{5}    → 6 位行政区划码，首位不为 0
// (?:19|20)\d{2}→ 4 位出生年份，限 19xx 或 20xx
// (?:0[1-9]|1[0-2]) → 2 位月份，01 到 12
// (?:0[1-9]|[12]\d|3[01]) → 2 位日期，01 到 31
// \d{3}         → 3 位顺序码
// [\dXx]        → 校验位，数字或大小写 X
```

> 拆解时的一句经验：**先找 (?: 与 ( 的位置**。它们把模式切成"块"，块的边界一旦看清，量词与断言的归属就一目了然，长模式立刻变成若干短模式的拼接。



### 调试与学习资源概览

**调试工具与学习资源**在系列末篇《参考资料与延伸阅读》中完整介绍，日常最常用的三件是：

- **regex101.com**：在线解释器，逐 token 解释模式、展示匹配步骤与回溯步数。
- **regex-vis.com**：把正则渲染成可视化铁路图，长模式的辅助理解工具。
- **console 实测**：不确定返回值时直接在控制台跑一遍，比记忆规则可靠。

```js
const reg = /\d{3}/g;
console.log(reg.toString()); // "/\d{3}/g"
console.log(`${reg.source} | ${reg.flags}`); // "\d{3} | g"
```

> 调试正则的心法是**“缩小、二分、实测”**：把长正则拆成几段逐段验证，用具体字符串试探边界，再拼回去。正则出错往往不是“整条都错”，而是某一段多吃了或少吃了字符。
